# 📓️ Print

The semio print product: a LaTeX document stack and a grammar-of-graphics visualization library, both
driven from the repository's design tokens and both built through `📜️script.ts`.

## Layout

| Path | What lives there |
|---|---|
| `🖋️latex/` | The LaTeX packages. `semio.cls` plus `semio-core`, `semio-window`, `semio-table`, `semio-fonts`, `semio-tokens`, and the visualization bundle `semio-viz` with its kernel and namespace packages. |
| `🧬️schema/` | `🔣️.json` — the JSON Schema of a catalogue entry, the family option vocabularies (`x-semio-family-options`), the demo tables and the probe protocol — and `🟦️.ts`, its typed twin. |
| `🖼️assets/` | `📊️viz-taxonomy.md` (the human taxonomy, the single source of the sections and leaves), `🔣️viz-catalog.json` (the handcrafted chart-kind catalogue), fonts and demo images. |
| `🧾️template/` | Documents. `📋️report`, `📃️paper`, `📰️flyer`, `🏗️zukunftbau`; `📊️viz-gallery/` is generated, one document per taxonomy section; `📊️viz-api/🔓️viz-api.tex` is the hand-written API reference. |
| `🔨️modules/` | TypeScript modules: catalogue loading and generation, the probe harness, font provisioning, tectonic compilation. |
| `🎮️commands/` | The command objects `📜️script.ts` routes to. |
| `🧪️tests/` | One directory per test case: `🥒️.feature`, `🟦️.ts`, `🧫️fixtures/`. |
| `🔮️oracle/🔣️.json` | The owner oracle registry: the third-party packages the tests compare against, and the justified no-oracle decisions. |

## Commands

Everything runs through `📦️packages/🟦️typescript/📜️script.ts`; `📋️project.json` registers the same
entry points as nx targets, and `.vscode/🧩️launch.seed.jsonc` as launch configurations.

```bash
cd "🧰️framework/🛍️products/📓️print/📦️packages/🟦️typescript"
bun ./📜️script.ts generate            # design-token stylesheet
bun ./📜️script.ts generate viz        # catalogue → semio-viz-catalog[-labels].sty + the gallery documents
bun ./📜️script.ts fonts               # provision the fonts into the cache
bun ./📜️script.ts build               # every registered template, light and dark
bun ./📜️script.ts build viz api       # only 🔓️viz-api.tex, light and dark
bun ./📜️script.ts watch <template>    # rebuild on change
bun ./📜️script.ts test quick          # kernel probes against the d3 oracles
```

Generated files carry a `🤖 Generated by …` marker and are never edited by hand:
`semio-viz-catalog.sty`, `semio-viz-catalog-labels.sty`, `🖼️assets/🔣️viz-api.json` and everything
under `🧾️template/📊️viz-gallery/`. `test fundamental` fails if one of them is stale, so run
`generate viz` after changing the catalogue, the schema or the reference document.

## The visualization library

`semio-viz` is a grammar of graphics for print, not a collection of chart macros. A chart kind is a
preset in `🖼️assets/🔣️viz-catalog.json`; it names a *family*, and the family composes the grammar:

```
data → transform → scale → coordinate system → mark → guide → annotation → theme
```

Public commands are `\SemioViz…`; every option is an l3keys key with a documented type and default in
a `%region 🔖️Keys` block; all user-visible text exists in English and German and is chosen by the
document language; colours come from the theme kernel so a figure is correct in the light and the
dark theme.

**The reference is `🧾️template/📊️viz-api/🔓️viz-api.tex`** — every public command and environment
with its signature, every key with its type, default and meaning, a compiled example per grammar
element, one section per taxonomy §76 namespace with all 246 families and their options, a chapter on
adding a chart kind, a family or a test, and a chapter on the numerics and the measured limits.
Build it with `bun ./📜️script.ts build viz api`; it compiles in both themes.

`vizApiReference()` in `🔨️modules/📊️visualization-gallery/🟦️.ts` is the machine-readable twin of
that document: every package with its public commands and its documented key families, plus the
schema's bilingual family option vocabulary.

## Tests

Cases are language-neutral Gherkin plus a TypeScript adapter. The adapter's `subject` compiles a
probe document with the repository's tectonic and returns the numbers the LaTeX kernel produced; its
`oracle` computes the same numbers with a registered third-party package (`d3-scale`, `d3-shape`,
`d3-hierarchy`, `d3-force`, `d3-geo`, `d3-delaunay`, …). Levels: `fundamental` (no TeX),
`quick` (kernel probes), `long` (family probes and the gallery build), `exhaustive` (every chart kind
in both themes and both languages).

The probe protocol lives in `🖋️latex/semio-viz-probe.sty` and its TypeScript side in
`🔨️modules/🧪️viz-probe/🟦️.ts`. The full contract, including the mandatory `\SemioVizProbePage`, is
in the reference document's chapter on extending the library.
