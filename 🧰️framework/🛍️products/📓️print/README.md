# 📓️ Print

The semio print product: a LaTeX document stack and a grammar-of-graphics visualization library, both
driven from the repository's design tokens and both built through `📜️script.ts`.

## Layout

| Path | What lives there |
|---|---|
| `🖋️latex/` | The LaTeX packages. `semio.cls` plus `semio-core`, `semio-window`, `semio-table`, `semio-fonts`, `semio-tokens`, `semio-phd` (the dissertation apparatus), and the visualization bundle `semio-viz` with its kernel and namespace packages. |
| `🧬️schema/` | `🔣️.json` — the JSON Schema of an authored chart and catalogue entry, the family option vocabularies (`x-semio-family-options`), the demo tables and the probe protocol — and `🟦️.ts`, its typed twin. Chart snapshots, semantic diffs and mutation decisions live in `📸️snapshot/`, `🔀️diff/`, and `🧬️mutations/`; all visualization derivations live in `💡️inferences/`. |
| `🖼️assets/` | `📊️viz-taxonomy.md` (the human taxonomy, the single source of the sections and leaves), `🔣️viz-catalog.json` (the handcrafted chart-kind catalogue), fonts and demo images. |
| `🧾️template/` | Documents. `📋️report`, `📃️paper`, `🎓️phd`, `🎓️thesis`, `📰️flyer`, `🏗️zukunftbau`; `📊️viz-gallery/` is generated, one document per taxonomy section; `📊️viz-api/🔓️viz-api.tex` is the hand-written API reference. |
| `🔨️modules/` | TypeScript modules: catalogue loading and generation, the probe harness, font provisioning, tectonic compilation. |
| `🎮️commands/` | The command objects `📜️script.ts` routes to. |
| `🧪️tests/` | One directory per test case: `🥒️.feature`, `🟦️.ts`, `🧫️fixtures/`. |
| `🔮️oracles/🔣️.json` | The owner oracle registry: the third-party packages the tests compare against, and the justified no-oracle decisions. |

## Commands

Start `repo dashboard`, choose **New Task** (`Ctrl+B n`) and search `print`
plus the action. Each owner target routes to the product's authored scripts through the build graph.

```bash
repo run @semio-tech/print:generate
repo run @semio-tech/print:generate-viz
repo run @semio-tech/print:fonts
repo run @semio-tech/print:build
repo run @semio-tech/print:watch
repo run @semio-tech/print:test -- quick
repo run @semio-tech/print-rs:build
repo run @semio-tech/print-rs:test
repo run @semio-tech/print-rs:test-snapshot-sqlite
repo run @semio-tech/print-rs:test-logical-owner
```

`build` completes the template documents and `build-viz` the visualization documents (each requires the published PDF of every document of its collection); `watch` and `watch-viz` rebuild on source changes and
accept no arguments. The native package `@semio-tech/print-rs` has its own [README](🦀️native/README.md).

For one document, choose **Run an authored script** (`tool:workspace/run-script`),
set **Script path** to `🧰️framework/🛍️products/📓️print/🔨️modules/🖨️tectonic-template-compilation/📜️script.ts`,
**Build owner project** to `@semio-tech/print`, and **Working directory** to
`🧰️framework/🛍️products/📓️print/📦️packages/🟦️typescript`. Put `build <document id>` in
**Arguments** and choose **Start**. The document ids are the `id` values of
`🔨️modules/🖨️tectonic-template-compilation/📇️catalog/🔣️.json`: `report`, `paper`, `phd`, `thesis`, `flyer`,
`zwischenbericht`, `forschungsbericht`, `kompaktbericht`, `viz-api` and the `viz-<n>` gallery documents.
`build` takes exactly one id. Read compile progress, artifact paths and errors in the task output; its menu
offers restart and stop.

Generated files carry a `🤖 Generated by …` marker and are never edited by hand:
`semio-viz-catalog.sty`, `semio-viz-catalog-labels.sty`, `🖼️assets/🔣️viz-api.json` and everything
under `🧾️template/📊️viz-gallery/`. `test fundamental` fails if one of them is stale, so run
`repo run @semio-tech/print:generate-viz` after changing the catalogue, the schema or the reference document.


## The assignment kind

Assignments use the new `assignment` class, sharing semio fonts, tokens and page chrome in an inline-title, one-sided A4 article layout
`\documentclass[theme=light,language=en]{assignment}`.
The language is required and accepts `en` or `de`. Set the standard
`\title`, `\subtitle`, `\author` and `\date`, then call
`\makeassignmenttitle` or `\maketitle`. Optional course metadata uses
`\SemioAssignmentSetup{institution={...},course={...},duration={...},submission={...}}`;
unset fields are omitted. `AssignmentParameterTable` provides a shape column followed by
five blank writable columns, accepts any number of `\AssignmentParameterRow{...}`
entries, and supports the `row-height`, `shape-width` and `value-columns` keys.
`AssignmentParameterMatrix` places parameter names in the first column and type icons
across the header. Its `type-columns=8` and `parameter-rows=8` defaults produce
nine columns and nine rows: one header row and eight blank parameter rows. Pass the
localized first-column heading and the icon cells (separated by `&`) as its two
arguments. The `header-height=16mm`, `row-height=6mm`, `padding=2mm` and
`label-width=27mm` defaults separate the centered icon header from single-line
writing rows. `AssignmentMatrixImage{path}` fits an original vector resource inside
the padded header without changing its aspect ratio. The parametrization assignment
uses one exercise with both matrices together on one page, sharing one parameter
strategy across all sixteen types.
Wrap named matrices in `AssignmentTable` (`\begin{AssignmentTable}{...}`) so their
caption and grid use the existing integrated table silhouette, matching the report tables.

The declaration schema and safe plain-text preamble inference are exported through
`@semio-tech/print/template/assignment`. Run `repo run @semio-tech/print:test-assignment`
for shared language-neutral declaration vectors checked against AJV. Course-owned assignment
sources live under their topic; their builds use the shared Print compiler with explicit
producer identities and authored SVG resource plans.

Deutsch: `type=assignment` erstellt ein einseitiges Aufgabenblatt im A4-Format mit
Titel im Textfluss. Die Sprache muss ausdrücklich als `language=en` oder
`language=de` gewählt werden. Die Metadaten und das Parametertableau sind
anpassbar. Aufgabenblätter der Architektur liegen beim jeweiligen Kursthema;
der gemeinsame Print-Compiler erstellt ihre Veröffentlichungen.

The three running-header labels can be authored independently of the document title and section marks:
`\SemioHeaderSetup{left={Architecture and Technology},center={Finger Exercise},right={Parametrization}}`.
The left chip includes the semio emblem; all three authored zones keep their physical left/center/right order.
Deutsch: `\SemioHeaderSetup{left={Architektur und Technologie},center={Fingerübung},right={Parametrisierung}}`
setzt die drei Kopfzeilen-Chips unabhängig von Titel und Abschnitt.

## The thesis kind

`\documentclass[type=thesis,theme=light,language=en]{semio}` provides a bound,
chapter-based academic document. An explicit `language=en` or `language=de` is
required. Use `\SemioSetup{thesis-level=bachelor}`, `master`, `doctoral` or `custom`
to choose the localized thesis heading; `thesis-type={...}` overrides that heading
and `degree={...}` supplies the actual academic award.
The class option `bindingoffset=12mm` customizes the binding gutter; the defaults
are 8mm for `thesis` and 15mm for `phd`.

The worked source in `🧾️template/🎓️thesis/` includes examination metadata,
English and German abstracts, acknowledgements, dedication, abbreviations, a table
of contents, research chapters, equations, tables, figures, citations, appendices,
registers and a signed declaration. Its dataset is explicitly illustrative.
Build both light and dark editions with `repo run @semio-tech/print:build-thesis`.

```latex
\SemioSetup{thesis-level=master,degree={Master of Science},
  university={Example University},programme={Architecture},
  student-id={20260001},supervisor={Prof. Example},
  submission={2026-10-28},place={Hannover},keywords={design, research}}
\makethesistitle
\begin{Abstract} English abstract. \end{Abstract}
\begin{Kurzfassung} Deutsche Zusammenfassung. \end{Kurzfassung}
\begin{Acknowledgements} Thanks. \end{Acknowledgements}
\makededication{For my family.}
\begin{Abbreviations} \item[API] Application programming interface. \end{Abbreviations}
\tableofcontents
\makemainmatter
\chapter{Introduction}
% Research chapters follow.
\makeappendices
\appendixchapter{Supplementary Material}
\makeregisters
\makedeclaration[The declaration required by the examining institution.]
```

Unset academic fields are omitted. `declaration-text`, `declaration-title`,
`dedication-title` and `abbreviations-title` customize the institutional wording.
Use `\makebackmatter` for unnumbered closing chapters without resetting page
numbers. `\makefrontmatter` preserves Roman page progression when called after
the academic title; repeated calls do not restart numbering. Main matter restores
the configured heading-numbering depth and starts Arabic page numbering at one.
The declaration schema and plain-text metadata inference are exported
from `@semio-tech/print/template/thesis`; shared declaration vectors are validated
against AJV by `repo run @semio-tech/print:test-thesis`. Run
`repo run @semio-tech/print:test-thesis-render` for the actual compiler/PDF.js
language, theme and degree matrix plus compiler refusal cases.

Deutsch: Die Dokumentart `thesis` unterstützt Bachelor-, Master- und Doktorarbeiten
sowie frei benannte Abschlüsse. Die Sprache ist ausdrücklich anzugeben. Titelblatt,
Zusammenfassungen, Widmung, Abkürzungen und Erklärung sind anpassbar; Hauptteil,
Anhänge und Verzeichnisse verwenden die gemeinsamen Print-Komponenten.

## The dissertation kind

`\documentclass[type=phd,…]{semio}` is the chapter-sectioned report kind with a 15mm binding gutter
and the dissertation apparatus from `🖋️latex/semio-phd.sty`. The examination metadata is declarative —
`\university`, `\faculty`, `\institute`, `\degree`, `\discipline`, `\supervisor`, `\reviewers`,
`\place`, `\submissiondate`, `\defensedate`, `\orcid` — and every field left unset simply omits its
window, so the same template serves a monographic and a cumulative thesis. Every field is also a
`\SemioSetup` key under its bare name (`submission` and `defense` for the two dates).

```latex
\makedissertationtitle          % title page: faculty, title, degree, author, referees, dates
\begin{Abstract} … \end{Abstract}
\begin{Kurzfassung} … \end{Kurzfassung}
\begin{Acknowledgements} … \end{Acknowledgements}
\makedeclaration                % statutory declaration plus the archived signature line
\tableofcontents
\makemainmatter                 % roman frontmatter numbering ends here
…
\makeappendices
\makeregisters
```

The frontmatter parts are unnumbered chapters, so they never shift the numbering of the
thesis chapters; `Abstract` and `Kurzfassung` keep their own language regardless of the document
language, every other string follows `language=`. `🧾️template/🎓️phd/` is the worked example.

## The visualization library

`semio-viz` is a grammar of graphics for print, not a collection of chart macros. A chart kind is a
preset in `🖼️assets/🔣️viz-catalog.json`; it names a *family*, and the family composes the grammar:

```
data → transform → scale → coordinate system → mark → guide → annotation → theme
```

Public commands are `\SemioViz…`; every option is an l3keys key with a documented type and default in
a `%region 🔖️Keys` block; all user-visible text exists in English and German and is chosen by the
document language; colours come from the theme kernel so a figure is correct in the light and the
dark theme.

**The reference is `🧾️template/📊️viz-api/🔓️viz-api.tex`** — every public command and environment
with its signature, every key with its type, default and meaning, a compiled example per grammar
element, one section per taxonomy §76 namespace with all 246 families and their options, a chapter on
adding a chart kind, a family or a test, and a chapter on the numerics and the measured limits.
Build it with the **Run an authored script** form and the arguments `build viz-api` described above; it compiles in both themes.

`vizApiReference()` in `🔨️modules/📊️visualization-gallery/🧾️api-reference/🟦️.ts` is the machine-readable twin of
that document: every package with its public commands and its documented key families, plus the
schema's bilingual family option vocabulary.

## Tests

Cases are language-neutral Gherkin plus a TypeScript adapter. The adapter's `subject` compiles a
probe document with the repository's tectonic and returns the numbers the LaTeX kernel produced; its
`oracle` computes the same numbers with a registered third-party package (`d3-scale`, `d3-shape`,
`d3-hierarchy`, `d3-force`, `d3-geo`, `d3-delaunay`, …). Levels: `fundamental` (no TeX),
`quick` (kernel probes), `long` (family probes and the gallery build), `exhaustive` (every chart kind
in both themes and both languages).

The probe protocol lives in `🖋️latex/semio-viz-probe.sty` and its TypeScript side in
`🔨️modules/🧪️viz-probe/🟦️.ts`. The full contract, including the mandatory `\SemioVizProbePage`, is
in the reference document's chapter on extending the library.

## Authored Chart Inference

`@semio-tech/print-viz-inference` exposes chart snapshots, semantic customization mutations, reversible diffs and total read-side inference. Every chart selects `language: "en"` or `"de"` explicitly. A mutation validates authored values before producing a diff; applying and replaying those diffs recreates the chart. Await `inferVizChart(snapshot, { signal, onProgress })` to derive completed TikZ. Numerical charts also expose a plan and a 2D scene from the same resolved primitives. For catalogue presets, LaTeX computes the native geometry; the completed result includes a `print.chart.scene-unavailable` diagnostic and omits the numerical plan and scene. The owned worker keeps validation, layout and rendering off the caller's event loop; cancellation terminates it and removes its listeners. Progress starts at zero, increases monotonically, and reaches its total for a completed result. Catalogue presets use the existing LaTeX family inference and can compose with numerical layers. Invalid input and cancellation return diagnostics without partial results.

The native `semio-framework-print` artifact registers executable mutation and inference services in the OS registry. Its TikZ inference delegates numerical grammar operations to the existing LaTeX implementation. `test quick` also executes the schema, replay, D3 arithmetic and rendering checks; the native package has its own registered Nx test command.
