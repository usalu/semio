# Owned Template Cache

This module bounds retained opaque templates by entry count, member count and point count. It has no runtime dependencies. Python and TypeScript implement the same portable traces. These geometry-resource limits do not bound OS memory, live caller-owned drawings, or factory temporaries.

`CachePolicy` defaults to 8 entries, 1000000 members, 10000000 points and 64 cost-history keys. All numbers have integral values from zero through 9007199254740991; JSON `2.0` is accepted and normalized to an integer in Python. Booleans, nonintegral fractions and nonfinite numbers are invalid. Any zero retention limit disables retention. Keys are nonempty strings of at most 4096 Unicode scalar values. History contains only these strings and immutable costs, never values or callbacks. Release removes both retained values and history. Stats counters saturate at the safe-integer maximum.

`TemplateCache.resolve(key, factory, measure, clone, options)` returns an isolated clone on a cache hit. On a miss it reserves space before invoking the factory. An explicit reservation, or the exact key's bounded observed-cost history, permits retaining other entries. Unknown costs reserve the entire budget and evict every old entry before the factory. A failed validity predicate propagates without mutation; false validity invalidates both the entry and its cost history, including coverage upgrades. Keys must encode every resource-affecting configuration. Call `invalidate` when an external change invalidates a historical cost.

Actual measured cost governs retention. An oversized or disabled-retention result is returned directly without invoking clone. Otherwise conflicting entries are evicted before cloning; the new template is committed only after clone succeeds. Factories, measurement and cloning may throw; prior evictions remain, the new value is never retained, and reservations are always released. Cancellation is checked before any lookup, before factory, after factory, after measurement and after cloning; `CacheCancelled` identifies this path. Measurement must return this module's `CacheCost`. Callbacks cannot mutate/reenter the same cache; stats remain readable. An underestimated explicit/historical reservation is observable in `underestimates` and does not guarantee a factory memory bound.

Operations and ownership scopes are synchronous. TypeScript scope callbacks must not return a Promise/thenable; asynchronous work needs a separately owned lifetime. An expensive factory supplies its own internal progress/cancellation checkpoints; cache checkpoints cannot interrupt opaque factory code. Clone callbacks must preserve the canonical source and return an independent client value.

LRU keys in stats are oldest first. Configure validates the entire new policy before mutation and immediately evicts to its limits, including bounded history. `release` is idempotent and never mutates returned objects. `CacheOwner` supports an owned scope or a borrowed cache: an owned inner scope is released on every exit, while a borrowed outer cache is restored without release. Python uses `owner.scope(...)`; TypeScript uses `owner.run(callback, options)`. Neither uses a global owner registry.

Renderer integration must count unique family objects by identity and unique coordinate arrays by identity across the `points` and `world_vertices` fields; each array contributes its number of coordinate rows once, including aliases shared between those fields. Counting must not concatenate arrays or clone a drawing. These fields define the intended renderer metric; this neutral module never imports a renderer. Other metadata/native allocations are outside it. The proposed 10M point default has not been checked against a full building.

The schema and shared traces precede the implementations. Tests compare LRU retention against the installed `lru-cache` development dependency through a test-only resolver and independent member/point LRUs, with lifecycle and failure behaviour tested separately. No external type appears in the runtime API.
