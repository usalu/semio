# w1d-events-overlay — final report

Implemented all 5 pieces from the brief in `ui/wgpu/rs/lib.rs`, region claim `w1d-events-overlay` (`events` + `cursor`, plus a narrow documented `tree` exception, recorded in `region-claims.json`). Build and tests verified clean.

**Region bounds** (re-grep, file has concurrent editors): `tree` 3652-4025, `cursor` 4757-5144, `events` 12217-13872.

## 1. Overlay manager (`events` 🔖️Overlay)
One lifecycle for `OverlayKind::{SelectPopup,ContextMenu,Tooltip,Dialog,CommandPalette}`, built on the existing `NodeFlags::OVERLAY` hit-test-priority mechanism (verified unchanged). Types: `OverlayAnchor{Node|Point}`, `OverlayPlacement{BelowAnchorWithFlip|AtPointer|Centered}` with per-kind defaults, `DismissPolicy{outside_press_swallow,escape_closes,hover_out_delay_seconds}`, `OpenOverlay`, `OverlayStack` (z-ordered `Vec`, supports nesting). Pure fn `resolve_overlay_placement(tree, anchor, content_size, viewport, placement) -> (f32,f32)` (flip-if-clipped, viewport-clamped, centered). `EventRouter` API: `open_overlay`/`close_overlay`/`close_topmost_overlay`/`topmost_overlay`. Wired into `dispatch`: outside-press closes+swallows (early `return`), `Escape` closes only the topmost, `Tab` scopes to `overlays.topmost_focus_trap_root()` for Dialog/CommandPalette, Tooltip hover-out closes on `PointerMove` (immediate, not debounced — this crate has no animation-clock scaffolding anywhere, same documented gap `engine::Ui::needs_frame` already admits).

**Bug found and fixed**: `hit_test(tree, some_id, x, y)` implicitly assumes `some_id` is the true window root (treats its own `layout.x/y` as relative to origin `(0,0)`). An overlay root usually isn't. Added `hit_test_subtree(tree, subtree_root, x, y)` that resolves the subtree root's parent's absolute origin first and translates coordinates into that frame — used by the outside-press dismissal check.

## 2. Drag-and-drop (`events` 🔖️DragDrop)
`pub type DragPayload = HashMap<String,String>` — matches `framework/renderer/react/ui-interpreter.tsx`'s `handleDrop` shape and `UiTreeItemNode::drag_data` exactly (MIME-string keys, JSON string values). Confirmed concrete MIME strings via grep: `application/x-semio-panel-tree-unit`, `application/x-semio-tree-section-reorder`, `application/x-semio-catalogue-item`, `application/x-semio-forms-question`. `DragSession{source,payload,ghost,pointer_x,pointer_y,drop_target}`. New `NodeFlags::DRAG_SOURCE`/`DROP_TARGET`. Lifecycle: `set_drag_payload`/`clear_drag_payload`/`set_drop_accept(predicate)` registries, `maybe_promote_to_drag` (Press→Drag after a 4px threshold), `update_drag` (re-evaluates nearest accepting `DROP_TARGET` ancestor each move), commit/cancel on `PointerUp` → `UiCommand::DropCommitted`/`DropCancelled`.

## 3. Scroll routing (`events` 🔖️Scroll)
New `NodeFlags::SCROLLABLE`; `nearest_scrollable_ancestor` bubbles from the wheel event's hit target. `route_scroll` adds delta to `WidgetState::scroll_offset`, clamped at 0. `CaptureKind` extended with `ScrollThumb(ScrollAxis)` (`Drag` variant, previously unused anywhere, is now actually wired too). `register_scroll_thumb(thumb, scrollable, axis)` decouples thumb geometry (paint's job) from scrollable-content geometry; thumb press captures the scrollable node, not the thumb.

## 4. EditState + key routing (`tree` + `events` 🔖️EditRouting)
`tree::EditState{text, caret, anchor, composition: Option<String>, scroll_x}` — byte offsets throughout (documented why: native Rust string indexing; `prev_char_boundary`/`next_char_boundary` step safely). `tree::WidgetState` (previously a zero-field marker whose own doc comment already earmarked "M5 events") filled in as `{edit: Option<EditState>, scroll_offset: (f32,f32)}`. Confirmed by reading `reconcile` (read-only) that `diff_and_update` only ever overwrites `spec`, never `state` — so "focused buffer wins over a fresh `apply_tree`" falls out of the existing design for free once `edit` is populated. Lifecycle lives in `FocusState::set_focus` (single choke point for both pointer- and Tab-focus): blur clears `edit`, first focus of a `UiNode::Input` seeds it from the declarative `value`. Key routing (`route_edit_key`): arrows w/ Shift-selection, Home/End, Backspace/Delete, Ctrl/Cmd+C/X/V → `UiCommand::ClipboardCopy/Cut/PasteRequested`. New `UiEvent::Paste{text}` and `UiEvent::Ime(ImeEvent{Start,Update,Commit,Cancel})` route through shared `insert_at_caret`. Explicitly deferred (documented, matching the file's existing "Button was the only wired variant" precedent): firing `Input::on_change` on commit, and actual OS IME wiring.

Mid-session, the coordinator flagged a possible collision with a separate concurrent session touching `UiEvent::Paste`/`Ime*`. Re-checked before finishing: the variants present are this session's own (no duplicates anywhere in `text`/`shell`), `shell::dispatch`'s wildcard arm tolerates them.

## 5. Hover-reveal + cursor (`events` + `cursor`)
`update_hover` now tracks the full bubble chain (`hover_chain: Vec<NodeId>`) and flags `HOVERED` on every ancestor, not just the `hit_test`-returned leaf — needed because a bare `Stack`-based row (e.g. a tree item) is never itself a hit-test match (`is_plain_container` pass-through), so it could never observe hover for `revealOnHover`-style paint logic otherwise. New `cursor::resolve_semio_cursor_from_tree(tree, hovered, capture)` — the retained-tree counterpart to the untouched immediate-mode `resolve_semio_cursor`; active capture (`Drag`→Grabbing, `ScrollThumb(axis)`→resize cursor) wins over hover; otherwise derives from `NodeFlags::DRAG_SOURCE` or the `UiNode` variant. New `EventRouter::hovered()`/`capture()` getters for it to consume.
