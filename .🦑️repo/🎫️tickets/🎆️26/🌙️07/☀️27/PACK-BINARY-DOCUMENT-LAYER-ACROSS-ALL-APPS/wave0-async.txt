//#region 🔖️AsyncSource
- `AsyncPackSource` trait via `#[async_trait::async_trait]`: `fn len(&self) -> u64` +
  `async fn read_at(&self, offset: u64, len: usize) -> Result<Vec<u8>, pack_core::PackError>`,
  bound `Send + Sync`. Exact signature match to contract.
- `CancellationToken`: `Arc<AtomicBool>` wrapper, `new`/`cancel`/`is_cancelled`, cheap `Clone`,
  plus a `Default` impl (clippy `new_without_default` hygiene).
- `CancelWatch<'a>`: private hand-rolled `Future` that busy-polls the token (self-waking, with a
  200us sleep between polls to avoid pegging a core) and resolves once cancelled. Used to race
  against real work via `futures_lite::future::or`.

//#region 🔖️Scheduler
- `LoadPriority` (Critical..Background) with a private `rank()` used for ordering.
- `ReadRequest { range: ByteRange, priority: LoadPriority }`.
- `ReadScheduler<S: AsyncPackSource>`: `new(source)` (default concurrency cap 4) and an
  additional `with_capacity(source, max_concurrent_reads)` constructor (not in the contract, but
  additive — doesn't change the required `new` signature). `async fn read(request, cancel)`
  matches the contract exactly.
- Coalescing design: requests are grouped into a `Group { range, state, wakers }` behind
  `Arc<Mutex<_>>`. The first caller for a not-yet-covered range becomes the "leader": it opens a
  `Gathering` group, does one cooperative `futures_lite::future::yield_now().await`, then closes
  the group (`Dispatched`, freezing the union range), acquires a `BoundedDemand` permit, and
  performs the single physical `source.read_at`. Any concurrently-polled caller whose range
  touches (overlaps or is adjacent to) a still-`Gathering` group's range is folded into that same
  group instead of starting its own read, and parks on a `WaitForGroup` future until the leader
  finalizes the group with a shared `Arc<Vec<u8>>` (or an error) that every waiter slices its own
  sub-range out of. Identical-range requests degenerate to the same coalescing path (they
  trivially "touch"), which also satisfies the dedup requirement.
- Both the leader's dispatch and every follower's wait are raced (`futures_lite::future::or`)
  against `CancelWatch`, so a caller's own `CancellationToken` short-circuits its `read()` call
  without waiting for the physical fetch. If the *leader* itself is cancelled, the group is
  finalized as errored so any followers are not left hanging forever either.
- Cancellation surfaces as `PackError::Io("read cancelled".to_string())` — the shared
  `PackError` enum (contract-fixed, defined in pack_core) has no dedicated `Cancelled` variant,
  so `Io` was the closest existing fit for a non-parse, non-corruption failure.

//#region 🔖️Backpressure
- `BoundedDemand`: `new(capacity)`, `capacity()`, `in_flight()`, `async fn acquire(priority) ->
  DemandPermit<'_>` (priority parameter is an additive design choice — the contract only sketches
  the struct with no method signatures). Built entirely on `std::sync::Mutex` + a `BinaryHeap` of
  waiters ordered by `(rank, arrival seq)` — no tokio, no channel crate. Slots free instantly to
  the highest-priority queued waiter on `DemandPermit::drop` (direct transfer, not a
  decrement+re-poll-everyone), which is what gives the deterministic priority-under-contention
  behavior the ticket asked for.
- `AcquireFuture` is a small hand-rolled `Future` (fast path returns `Ready` immediately if a
  slot is free; otherwise registers a `DemandWaiter` with a stored `Waker` and returns `Pending`
  until `granted` flips).

Dependency choice: added `futures-lite = "2"` as a normal (non-dev) dependency — it's used both
by the runtime scheduler (`yield_now`, `or`, `zip`, `pending`) and by tests (`block_on`, `zip`).
This is the "one lightweight async executor" the ticket asked to pick; it is already used
elsewhere in the workspace (compose/client/{bin/store,lib}/rs), so it's not a novel dependency
family for the repo. No tokio feature was added — nothing in this crate's scope actually needed
a concrete runtime adapter (that's `pack_http`'s job per the contract), so the optional
`[features] tokio = [...]` was intentionally left out rather than added speculatively.

Cross-crate notes for downstream wave-0 agents (pack_http in particular, which impls
`AsyncPackSource` for `HttpPackSource` and is expected to wrap an internal `ReadScheduler` per
the contract):
- `ReadScheduler::new(source)` takes ownership of `S: AsyncPackSource` by value (matches
  contract). If you need a shared/cloneable source, wrap it in your own `Arc` before handing it
  to `ReadScheduler`.
- `ReadScheduler::read` returns `Vec<u8>` sliced exactly to `request.range.len` — callers never
  see the coalesced/union bytes, only their own requested slice.
- `PackError::Io("read cancelled".to_string())` is the cancellation error shape; match on that
  string if you need to distinguish cancellation from a genuine I/O failure (no dedicated variant
  exists in the contract-fixed `PackError` enum in pack_core).
