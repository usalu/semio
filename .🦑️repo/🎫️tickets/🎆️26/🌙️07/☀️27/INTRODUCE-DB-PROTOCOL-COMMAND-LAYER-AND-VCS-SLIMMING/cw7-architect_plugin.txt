Why nothing was changed: cross-crate type mismatch (blocking, not a false positive)
-------------------------------------------------------------------------------------
Every `CollectionOperation::Add`/`Remove`/`Patch` construction in this file is immediately
wrapped in a `ProgramOperation::<Variant>(...)` value. `ProgramOperation` is defined in
`architect/program/rs/lib.rs` (a SEPARATE crate, also on the CW7 assignment list), where
each variant is concretely typed, e.g.:

    Elements(CollectionOperation<EntityId, ProgramElement, ProgramElementPatch>),

As of this session, architect/program/rs/lib.rs still has:

    use vcs::{apply_collection_operation, invert_collection_operation, CollectionOperation,
               Operation, OperationDiff, Patchable};

i.e. architect_program's own CW7 migration has NOT landed yet — `ProgramOperation`'s fields
are still nominally `vcs::CollectionOperation<...>` (old shape: `Add { index, item }`, no
id). Because architect/plugin/rs only ever constructs a bare `CollectionOperation::Add {..}`
expression that Rust type-infers from the expected `ProgramOperation::<Variant>(...)`
argument type, the plugin crate has NO independent choice of which `CollectionOperation` it
uses — it is entirely dictated by whatever architect_program currently imports.

I verified this is a real, hard block rather than a theoretical concern: I made the full
migration (import switched to `protocol::CollectionOperation`, all 6 `Add` sites rewritten
to `Add { id, item, at }`, `protocol` added as a direct dependency in Cargo.toml) and ran
`cargo build -p architect-plugin`. Result: 96 compile errors, all `E0308 mismatched types`,
e.g.:

    expected `CollectionOperation<EntityId, ProgramElement, ...>` (defined in crate `vcs`,
    vcs/rs/lib.rs:488), found `CollectionOperation<EntityId, ProgramElement, ...>` (defined
    in crate `protocol_command`, protocol/command/rs/lib.rs:197) — "have similar names, but
    are actually distinct types"

This confirms `Remove`/`Patch` sites (which look unchanged) also broke, because ALL variants
of `ProgramOperation` — not just the ones I touched — are parameterized on architect_program's
single `CollectionOperation` type alias/import, so switching only the plugin's local import
poisons every use site in the file, including ones I didn't otherwise edit.

I reverted both files completely (`use protocol::CollectionOperation;` back to
`use vcs::CollectionOperation;`, all 6 Add sites back to `{ index, item }`, and removed the
`protocol` dependency line from Cargo.toml). `git diff --stat -- architect/plugin/rs/lib.rs
architect/plugin/rs/Cargo.toml` is empty — the crate is byte-for-byte unchanged from before
this session.
