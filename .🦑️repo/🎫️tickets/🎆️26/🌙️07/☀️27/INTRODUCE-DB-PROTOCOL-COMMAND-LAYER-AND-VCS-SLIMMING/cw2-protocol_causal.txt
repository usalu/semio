Deviations from / choices within the contract (all "your choice" seams, documented inline too)
-------------------------------------------------------------------------------------------------
1. operation_envelope_from_edit is the biggest genuine ambiguity in this crate's section. The
   contract's signature (`fn(edit: &Edit<Op>, document_id: &DocumentId) -> Vec<OperationEnvelope>`)
   is materially different from vcs's original (`fn(envelope: &DocumentVcsEnvelope<P, Operation>,
   edit: &Edit<Operation>, deps: Vec<OperationId>) -> Result<OperationEnvelope, VcsError>`, one
   envelope per whole Edit, payload = serde_json::to_value(the whole edit)): no vcs envelope, no
   `deps` parameter, and a Vec return. Resolved as: one OperationEnvelope per `edit.forwards[i]`,
   since only per-op iteration lets `Op: protocol_command::Operation<P>`'s own trait methods
   (operation_id/dependencies/author_id/timestamp) supply metadata without a base `P` in scope. Each
   envelope's fields are built with a documented fallback chain: `edit.operation_meta[i]` (the
   richer, already-computed per-op metadata a live appender fills in) first, then the `Op` trait
   method, then a structural default (`"{edit.id}#{i}"` for the id, `edit.actor` or `"unknown"` for
   the actor, `HybridLogicalTimestamp::new(0, 0)` for the timestamp) — so the function is total even
   for a bare Edit with an empty operation_meta vec. `diff.payload` = the forward op serialized raw
   (serde_json::to_value(op)); `inverse.inverse_diff` = the corresponding `edit.backwards[i]`
   serialized, or `Value::Null` if backwards is shorter (mirrors protocol_history::HistoryEdit's own
   documented note that backward op count may differ from forward). `diff.schema`/`inverse.schema`
   use `std::any::type_name::<Op>()` — the only stable per-Op-type tag available with no
   OperationDescriptor/SchemaId lookup in scope inside a fully generic bridge fn; a caller wanting a
   real SchemaId should overwrite the field after the call. All four choices are commented inline at
   the fn definition and covered by both test cases (with-meta and without-meta).
2. OpDagError has no `thiserror` derive (this crate's Cargo.toml, matching the contract's stated
   dep list, has no thiserror dependency — only protocol_core, protocol_command, serde, serde_json).
   Hand-rolled `impl Display` + `impl std::error::Error` instead, kept minimal since the contract
   only fixes the enum shape (`Duplicate`, no payload).
3. OpDag's `insert` preserves a pre-existing framework-core quirk verbatim rather than fixing it,
   per the contract's explicit "No behavior change" instruction for this port: a dependency is
   treated as "not blocking" for the *newly-inserted* envelope's own Applied/Pending classification
   once it is merely *known* to the dag (present in `envelopes`, e.g. via an earlier Pending insert),
   not only once it is actually `applied`. This can in principle let an envelope classify as Applied
   before every ancestor is genuinely applied, if envelopes are inserted in a scrambled (non-
   topological) order with certain shapes (verified this by hand-tracing a 3-node chain A<-B<-D
   inserted as [B, D, A]). It never manifests for insertions performed in true topological order,
   which is exactly what this crate's own `quick` convergence tests exercise; documented at the
   `OpDag` struct and the `insert` method, and flagged here rather than silently patched, since
   silently changing OpDag's behavior was explicitly out of scope for a verbatim port.
4. FrontierSummary/frontier_delta have no prior implementation anywhere in the repo to port from
   (grepped; only protocol_history's structurally-similar-but-distinct twin exists, in another
   agent's not-yet-implemented section) — the contract fixes the enum/struct shapes only, not the
   comparison algorithm. Implemented: identical (ordinal, head_edit_id, chain_hash) -> Equal; a
   strictly greater/lesser head_edit_ordinal alone -> Ahead/Behind (a bare summary carries no
   ancestry chain beyond its tip, so ordinal order is the only signal available at this layer);
   equal ordinal with differing head_edit_id/chain_hash -> Diverged, with common_edit_count
   conservatively reported as `min(local.head_edit_ordinal, remote.head_edit_ordinal)` since a
   summary-only comparison cannot walk history for the true common ancestor. Documented inline;
   covered by 4 tests (Equal/Ahead/Behind/Diverged) plus a serde round-trip.
5. Cargo.toml was NOT touched — the pre-existing scaffolded one (protocol_core, protocol_command,
   serde, serde_json path/version deps) already matched the contract's dependency list exactly.
