WHAT WAS IMPLEMENTED (single-file lib.rs, regions matching the contract's subcommand list)

- //#region 🔖️Frame
  A small set of frozen wire constants (HEADER_SIZE=32, the 8-byte MAGIC, the REC_* kind-byte
  table, and a hand-parsed CommitFields for a REC_COMMIT frame's 64-byte payload) mirrored locally
  from protocol_core/protocol_format's contract-frozen values. See deviation #1 below for why this
  crate carries its own copies instead of importing them.

- //#region 🔖️Args
  Hand-rolled parse_args (--flag value / --flag=value / bare positional), mirroring pack_cli's
  own parser exactly. parse_log_args/parse_repair_args strip no-value boolean flags (--reverse,
  --truncate-torn-tail, --rebuild-indexes) out before generic pairing runs, since parse_args always
  tries to consume the next token as a value and would otherwise swallow a following positional.

- //#region 🔖️Inspect
  `protocol inspect <file>` — raw header dump (magic/version/flags, read directly from the file's
  first 32 bytes), record counts by kind (walked via protocol::FrameCursor), the full commit chain
  across every generation (commit_seq/offset/prev_commit_offset/record_count/records_len/
  chain_hash), and dictionary/projection/index record tallies. Never panics on corrupt input: a
  malformed frame mid-walk just stops the scan and prints whatever was gathered so far.

- //#region 🔖️Verify
  `protocol verify <file> [--level=trusted|standard|full]` — opens via protocol::HistoryReader at
  the requested VerificationLevel and forces a full decode (`.log()`); `full` additionally
  recomputes the commit hash chain (that's protocol_history's own VerificationLevel::Full behavior,
  reached transitively). Prints OK/FAIL, exit 0/1, never panics.

- //#region 🔖️Hash
  `protocol hash <file>` — prints `<commit_seq> <chain_hash-hex>` via protocol::content_frontier.

- //#region 🔖️Log
  `protocol log <file> [--limit N] [--actor ID] [--alternative ID] [--reverse]` — one line per
  edit (ordinal, id, actor column, op count, description), annotated with `[checkpoint ...]` lane
  markers at the edit ordinal each checkpoint's reachable changes top out at, and `(amends <id>)`
  when an edit shares a coalesce_key with an earlier one already printed in range. --alternative
  restricts to edits transitively reachable via that alternative's checkpoint_ids -> change_ids ->
  edit_ids chain (same traversal shape as the facade's own content_frontier/build_alternative_head).

- //#region 🔖️Compile / 🔖️Decompile
  `protocol compile <doc.ops> [--out doc.spr]` / `protocol decompile <doc.spr> [--out doc.ops]` —
  thin wrappers over protocol::compile_ops/decompile_ops. --out writes to a file; its absence
  writes raw bytes (compile) or text (decompile) to stdout rather than requiring --out unlike
  pack_cli's from-dsl (see deviation #4).

- //#region 🔖️Diff
  `protocol diff <a.spr> <b.spr>` — decodes both via HistoryReader, computes the longest common
  edit prefix, then reports only-in-a / only-in-b by (ordinal, id) and content-mismatch lines for
  edits present (by id) on both sides past the prefix. Exit 0 identical, 1 differs, 2 usage/read/
  decode error. See deviation #2 for the "payload-hash" wording.

- //#region 🔖️Compact
  `protocol compact <file> [--out FIXED]` — calls protocol::compact (in-place, atomic rewrite).
  --out first copies the file, then compacts the copy, leaving the original untouched (compact's
  own signature only rewrites in place at a single path — see deviation #3).

- //#region 🔖️Repair
  `protocol repair <file> [--truncate-torn-tail] [--rebuild-indexes]` — runs
  protocol::recover_file and prints its RecoveryReport; --truncate-torn-tail physically truncates
  the file to the recovered prefix via std::fs::File::set_len. --rebuild-indexes is a documented
  no-op (see deviation #1 — IndexBuilder/IndexReader aren't reachable from this crate).

- //#region 🔖️Upgrade
  `protocol upgrade <file>` — v1 no-op passthrough exactly as the contract specifies: validates the
  file decodes cleanly at VerificationLevel::Full, prints a passthrough note, exit 0/1.

- //#region 🧪️Tests
  24 inline #[test] fns (no quick/long/exhaustive submodules — nothing here is slow): parse_args/
  parse_log_args/parse_repair_args/parse_level unit tests; kind_name covers every frozen kind byte;
  parse_commit_fields matches a real commit frame built via protocol::HistoryAppender and rejects a
  wrong-length payload; inspect on a built file and on a missing file; verify OK at all three
  levels on a clean file, rejects an unknown --level, and reliably FAILs on a corrupted-header file
  (see deviation #5 for why "flip one byte in the interior" is NOT a reliable FAIL trigger for this
  crate's verify path); hash prints a parseable line; log filters by actor/alternative/limit/
  reverse and rejects an unknown --alternative; compile/decompile round-trip a real ops-text file
  end-to-end through the actual CLI (byte-exact text after the round trip) and compile rejects
  malformed ops text; diff reports identical (0) and reports a real divergence (1) both when b is a
  shorter prefix of a and via two independently-built files; compact leaves a verifiable file both
  in-place and via --out; repair reports a clean file and truncates a real torn tail (built by
  chopping bytes out of a commit frame) then re-verifies clean afterward, and reports an error for
  a missing file; upgrade passes a valid file and fails a corrupted one; help/unknown-subcommand
  exit codes.

DEVIATIONS / DESIGN CHOICES (each also documented inline in lib.rs at its decision site)

1. protocol_cli's contract line is unambiguous: "Deps: protocol = { path = ... }" — no
   protocol_core/protocol_format/protocol_history path deps of its own, and Cargo.toml (already
   present before this wave, unmodified) matches that. But protocol::FrameCursor/RecordFrame ARE
   re-exported by the facade (RecordFrame::kind: u8 is public), so frame-level introspection for
   inspect/repair genuinely IS reachable — just not the named REC_* constants, HEADER_SIZE, or
   parse_commit_payload/CommitPayload, none of which the facade re-exports. Since these are all
   frozen, byte-for-byte contract values (not protocol_format implementation details — the
   contract itself spells out the 32-byte header layout, the RecordKinds byte table, and the
   commit payload's exact field offsets), this crate mirrors the handful it needs as small local
   consts/helpers (see //#region 🔖️Frame) rather than adding protocol_core/protocol_format as
   direct dependencies, which the contract's dep line does not authorize. One real capability gap
   follows from this: protocol_history::IndexBuilder/IndexReader are NOT frozen contract bytes
   (the contract explicitly says their payload layout is "this crate's own choice") and are not
   facade-re-exported either, so `inspect`'s "indexes" section is a record-count tally only (no
   entry decode), `verify --level=full`'s "index-rebuild equality" check from the contract's
   subcommand table is out of scope for this crate as built, and `repair --rebuild-indexes` is a
   documented no-op. All three are called out at their call sites in lib.rs.

2. diff's "payload-hash mismatches" (contract wording) are printed as `a_fp=`/`b_fp=`, not
   `a_hash=`/`b_hash=`. The only blake3 implementation in this family (protocol_format::
   Blake3Hasher) is not facade-re-exported (protocol::RecordHasher, the trait, is; no
   implementation is) — and protocol_cli has no other crypto dependency per the contract. The
   fingerprint fn uses std::hash::Hasher (DefaultHasher) purely to give diff's mismatch lines a
   short, deterministic content signature; it is explicitly labelled `fp=` rather than `hash=` so
   it is never mistaken for a cryptographic digest. Structural equality (HistoryEdit: PartialEq,
   already used to detect the mismatch in the first place) is the actual source of truth here —
   the fingerprint is a display convenience only.

3. compact's `[--out FIXED]` grammar is ambiguous against protocol::compact's actual signature
   (`fn compact(path: &Path, ...)` — always an in-place atomic rewrite at one path, no separate
   input/output params). Implemented as: --out present -> copy `<file>` to FIXED first, then
   compact the copy in place (original untouched); --out absent -> compact `<file>` in place
   directly. Documented inline at cmd_compact.

4. compile/decompile default to stdout (raw bytes / text respectively) when --out is omitted,
   rather than requiring --out like pack_cli's from-dsl does. The contract's grammar shows --out as
   bracketed/optional for both (`compile <doc.ops> [--out doc.spr]`, `decompile <doc.spr> [--out
   doc.ops]`), so an omitted --out needs SOME defined behavior; printing to stdout (rather than,
   say, deriving a default filename by swapping the extension) keeps the CLI composable with
   shell pipelines and avoids ever silently writing a file the invocation didn't name. Covered by
   cli_compile_and_decompile_round_trip_via_files (exercises the --out path end-to-end); stdout
   output isn't separately unit-tested since main_impl's stdout isn't easily interceptable from
   inside the same process's test harness without extra plumbing, but the underlying write call
   (std::io::stdout().write_all) is a two-line straight-line path with no branching left untested
   by the --out variant's coverage of compile_ops/decompile_ops themselves.

5. cli_verify_full_detects_tampered_chain (an initially-written test) was replaced with
   cli_verify_rejects_file_with_corrupted_header after investigation showed the original premise
   was wrong: this family's read path (HistoryReader::open -> protocol_format::recover) is
   deliberately self-healing for interior corruption. Any tampered frame's own CRC-32C fails during
   recover's forward scan, which EXCLUDES it (and everything after) from the trusted prefix rather
   than erroring — so verify reports OK on whatever shorter trusted prefix survives, regardless of
   VerificationLevel, for essentially any single-byte interior tamper (this is the append-only
   format's intended torn-tail tolerance, confirmed by reading protocol_format's own recover()
   implementation, not a gap in this CLI). The one corruption class that IS guaranteed unrecoverable
   at every level is a corrupted 32-byte header (no earlier trusted state exists at all to fall
   back to) — that's what the replacement test exercises. Flagging this for whoever next touches
   `verify`/`repair`: distinguishing "recovered but silently shorter than the file on disk" from
   "fully clean" is not currently surfaced by this CLI (verify prints edit/change/checkpoint counts
   off the trusted prefix only; `repair`'s RecoveryReport.torn_tail_bytes is the tool that actually
   answers "how much got silently dropped").

6. build_history_file's test fixture confirmed (via parse_commit_fields_matches_a_real_commit_frame)
   that HistoryAppender::begin's own REC_STR_DICT/REC_DOC pending records get folded into the FIRST
   commit generation alongside the first append_edit's own REC_STR_DICT/REC_EDIT pending records —
   i.e. a brand-new appender's first commit() after one edit covers 4 records, not 1 or 2. Worth
   knowing for anyone else hand-verifying commit record_count in a small fixture.

No changes made outside protocol/cli/rs/lib.rs. No git commands were run.

wasm32 note: `cargo build -p protocol_cli --target wasm32-unknown-unknown` fails — cmd_compact/
cmd_repair call protocol::compact/protocol::recover_file/protocol::CompactOptions/
protocol::KeepSnapshots, all of which the facade only re-exports under
`#[cfg(not(target_arch = "wasm32"))]` (protocol_io is native-only per its own contract section).
protocol_cli's own contract section states no wasm32 requirement (unlike protocol_core/
protocol_command's explicit "Must compile for wasm32-unknown-unknown"), and it is structurally a
CLI binary (std::fs, std::env, std::process::exit throughout) that makes no sense as a wasm32
target. Confirmed this isn't a regression specific to this crate: `cargo build -p pack_cli --target
wasm32-unknown-unknown` (the sibling crate this one's contract section explicitly says to mirror)
fails for the identical structural reason (pack_cli's cmd_inspect/verify/hash/from-dsl call
pack::FilePackSource/write_atomic, likewise native-only-gated in the pack facade). wasm32 target
was installed and available (rustup target list --installed showed wasm32-unknown-unknown); the
failure is a real compile error, not a missing-target skip.
