Scope: protocol/wire/rs (package protocol_wire). Cargo.toml + project.json + script.ts were

What was implemented (regions match the contract's region names exactly):
- 🔖️Lane: `Lane { Command = 0, Preview = 1 }` with private to_byte/from_byte helpers.
- 🔖️ClientFrame: `ClientFrame` enum with all 7 variants exactly as specified (Hello, Commands,
  FrontierAdvertise, PreviewPublish, Presence, CreditGrant, Bye), field-for-field per contract,
  using protocol_causal::{OperationEnvelope, FrontierSummary} and protocol_core::ActorId.
- 🔖️ServerFrame: `Bootstrap`, `ApplyOutcome`, `AckStage`, `ServerFrame` (9 variants: Welcome,
  SnapshotChunk, SnapshotDone, Commands, Ack, Preview, Presence, CreditGrant, Error) exactly as
  specified.
- 🔖️Codec: encode_client_frame/decode_client_frame/encode_server_frame/decode_server_frame.

Deviation taken (explicitly permitted by the contract's 🔖️Codec note):
  Byte layout is `lane: u8` + varint-u64 body length + serde_json bytes, NOT a fully hand-rolled
  binary encoding. Rationale documented in the module-level docstring: ClientFrame/ServerFrame
  carry deeply nested, already-schema-erased serde_json::Value payloads (inside
  protocol_causal::DocumentDiff/InverseOperation, ClientFrame::Presence, ServerFrame::Error, ...)
  plus Vec<OperationEnvelope> batches — hand-rolling a hashed field-by-field binary layout for this
  shape would just re-derive what serde_json already does for opaque JSON payloads, with no
  round-trip benefit. The frame *types* are implemented byte-for-byte/field-for-field per the
  frozen contract; only the wire encoding exercises the contract's declared "one degree of
  freedom".

  Sub-deviation: protocol_wire's Cargo.toml (per the frozen `Deps:` line) does NOT path-dep on
  pack_core, and protocol_core does not re-export pack_core::ByteWriter/ByteReader at its top
  level (only used internally inside protocol_core::scalar). So rather than adding an
  undocumented pack_core dependency, I hand-rolled two tiny private LEB128 varint helpers
  (write_varint_u64/read_varint_u64) directly in protocol_wire/lib.rs — a deliberate, documented
  duplication of pack_core's well-known varint algorithm, not a new format. This is called out in
  the module docstring.

  Errors from the codec (empty frame, unknown lane byte, truncated body, invalid JSON, overlong
  varint) all map to protocol_core::ProtocolError::Malformed { what, offset, detail } — no new
  ProtocolError variant was needed.
