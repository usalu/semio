Shape V2 Retrofit Path-Prefix Bug Audit — results log
=======================================================

Bug hunted: TEMPLATE.md §14 step 3's original (wrong) wording told retrofit agents to prefix
EVERY #[path = "…"] string in a relocated plugin-root 📦️lib.rs with ../../, including bare
"." grouping-module resets. Only LEAF paths (real on-disk segments) should get the prefix;
"." resets compose against the parent's already-resolved base and get double/triple-corrected
if also prefixed, failing to compile past one level of nesting. Corrected by 🪵️sourcing's
retrofit via a real compiler error (see master ticket 26/08/05/CRATE-CONSOLIDATION-AND-
PLUGIN-TAXONOMY-RESTRUCTURE's note dated 2026-08-06, and TEMPLATE.md's corrected lead
section point 1 + §14 step 3).

Detection method: literal grep for the wrong pattern `"../../."]"` in every plugin's
📦️packages/🦀️rust/📦️lib.rs (100% precise — this exact byte sequence can only appear from the
over-correction bug, since a correct file has bare `"."` for every grouping reset). Cross-checked
with an independent second pattern: any #[path] leaf (segment starting 🗿️/🎛️, not ".") that is
MISSING the ../../ prefix entirely — a second, inverse bug variant found in 4 plugins.
