# Fix Reasoning Wires Replace Document Op Text Ordering Bug

- **Root Cause**: `MindmapWiresOperation::ReplaceDocument { wires_fixture: DslValue, board_fixture: DslValue }` keeps fields as raw, schema-less `dsl::DslValue`. When deriving `#[derive(dsl::DslOps)]` directly, `ReplaceDocument`'s `wires_fixture` and `board_fixture` print/parse through the generic `DslValue` printer/parser. The generic printer emits object keys in canonical (alphabetical) order (`"board"`, `"identities"`, `"relationships"`, `"schema"`), whereas original fixtures created via `empty_wires_fixture()` / `empty_board_fixture()` keep keys in field-declaration order (`"schema"`, `"identities"`, `"relationships"`, `"board"`). Since `DslValue::Object` is structural `Vec<(String, DslValue)>`, key-reordering breaks structural equality in `op_text_round_trip_replace_document`.
- **Solution**: Replace direct `#[derive(dsl::DslOps)]` on `MindmapWiresOperation` with a hand-rolled `impl protocol::OpText` and `impl protocol::OpBinary` that delegates through an internal `MindmapWiresOperationDsl` mirror enum. In `MindmapWiresOperationDsl`, `ReplaceDocument` routes `wires_fixture` and `board_fixture` through `reasoning_wires::WiresFixtureDsl` and `reasoning_wires::BoardFixtureDsl` respectively, restoring exact struct-field declaration order upon `to_dsl_value` conversion while leaving all other variants untouched.
