## Change (identical shape across all 9 crates)

Since every crate's helper fn is the single source of truth for the `Contribution::FlowExtension` fields,
and each field is reused for both `app_id` variants, changed `flow_extension_contribution` to build the
topic payload from the *same* local field values used for the `Contribution` literal (rather than
duplicating hardcoded strings in a second function) and return `(Contribution, serde_json::Value)`:

```rust
fn flow_extension_contribution(app_id: &str, manifest_json: String) -> (Contribution, serde_json::Value) {
    let extension_id = "bim"; // or EXTENSION_ID const, per-crate
    let label = "Bim";        // or EXTENSION_LABEL const, per-crate
    let icon_id = "bim";
    let topic_payload = serde_json::json!({
        "appId": app_id,
        "extensionId": extension_id,
        "label": label,
        "iconId": icon_id,
        "manifestJson": &manifest_json,
    });
    (
        Contribution::FlowExtension { app_id: app_id.into(), extension_id: extension_id.into(), label: label.into(), icon_id: icon_id.into(), manifest_json },
        topic_payload,
    )
}
```

`bundle()` updated to destructure both calls and chain `.contributes_topic("flow.extension", ...)`
immediately after each corresponding `.contributes(...)`:

```rust
let (flow_contribution, flow_topic_payload) = flow_extension_contribution(FLOW_APP_ID, manifest_json.clone());
let (procedural3d_contribution, procedural3d_topic_payload) = flow_extension_contribution(PROCEDURAL3D_APP_ID, manifest_json);
ExtensionBundle::new(...)
    .extends("flow")
    .contributes(flow_contribution)
    .contributes_topic("flow.extension", flow_topic_payload)
    .contributes(procedural3d_contribution)
    .contributes_topic("flow.extension", procedural3d_topic_payload)
    .handler(...)
```

Field mapping (`app_id` -> `appId`, `extension_id` -> `extensionId`, `label` -> `label`, `icon_id` ->
`iconId`, `manifest_json` -> `manifestJson`) confirmed against the `FlowExtension` variant definition in
`🧰️framework/🔨️modules/🛂️manifest/🦀️component.rs:2730-2740` (`ts(rename = ...)` attributes). `icon_id` is
`IconName` (derives `serde::Serialize`, kebab-case per-variant rename matching `Display`/`as_str()`), so
passing the plain `&str` used to build it into the JSON payload round-trips to the same string the
`Contribution`'s `icon_id.into(): IconName` would serialize to.

Per-crate variation: `dictionary`, `logic`, `math`, `primitive`, `text`, `list` already had
`EXTENSION_ID`/`EXTENSION_LABEL` crate-level consts — reused those instead of re-hardcoding strings
(`primitive`'s extension id is `"core"`, not `"primitive"` — kept as-is, pre-existing naming, not part of
this change). `bim`, `brep`, `draw` had no such consts (extension_id/label/icon_id were inline string
literals in the struct literal) — introduced local `let extension_id = ...; let label = ...;` bindings
inside the helper fn so the `Contribution` literal and the topic payload draw from one value each,
avoiding duplicated literals.

Did not touch the `#[cfg(test)] mod tests` blocks (test-only `Contribution::FlowExtension { .. }`
constructions and `matches!` asserts) — out of scope per the "consumers/test-fixtures are out of scope"
rule.
