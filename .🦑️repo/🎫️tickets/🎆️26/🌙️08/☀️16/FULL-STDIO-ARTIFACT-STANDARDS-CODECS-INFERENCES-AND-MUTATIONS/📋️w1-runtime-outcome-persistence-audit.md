# Runtime Outcome Persistence Audit

Static read-only audit of the in-progress `MutationOutcome`/message/conflict work in SPR, VCS, store, and host. No Cargo/build command was run. Line numbers refer to the current worktree.

## Blocking and high-risk findings

1. **Quarantined Accept is not an atomic batch resolution.** `🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:4889-4937` loops over each envelope and commits each successful `ingest_remote` before a later envelope can return `accepted: false`. A Fatal in a later envelope therefore leaves earlier envelopes applied while the original conflict remains Open. The returned report is also only the last envelope's report. The frozen C6 behavior requires one LF batch replay, all-or-nothing state/history/ledger, and one aggregate report. Add a test with two quarantined envelopes (first applicable, second Fatal): assert unchanged snapshot, history, DAG, ledger, conflict Open, and aggregate report; add the successful multi-envelope counterpart.

2. **Empty-store snapshot import bypasses the merge protocol and drops/changes shared outcome data.** `🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:4942-4967` adopts the remote envelope wholesale without checking document id or schema, HLC sorting, merge-policy outcomes, or clock merge; it explicitly clears remote conflicts. It also does not rebuild `self.edit_messages` from the adopted envelope. This can accept a foreign artifact, accept Fatal/Warning history under Normal policy, erase persisted conflicts, and generate a local HLC behind remote history. Tests: mismatched id/schema must reject; out-of-order remote HLT edits must be stored/replayed chronologically; a remote conflict/message ledger must survive adoption; Normal/Fatal remote history must reject; a subsequent local HLT must be greater than the remote maximum.

3. **Remote snapshot identity comparison is too strict and error conversion is lossy.** In `🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:4981-4988`, same-id edits are compared as whole JSON, so harmless sequence/timestamp metadata differences reject an otherwise equivalent operation. Compare the stable operation identity/payload instead. In the reject path at `:5048-5053`, `mutation_envelope_from_edit(...).unwrap_or_default()` silently drops conversion failures and can persist a quarantine with incomplete envelopes. Tests: same operation id/payload with different sequence metadata converges; a conversion/encoding failure is returned and never creates an empty quarantine.

4. **Conflict mutations do not invalidate projection generation.** Quarantine append (`🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:4810-4814`), Degraded append (`:4840-4848`), and all status changes in `resolve_conflict` (`:4899-4935`) happen without `bump()`. The envelope and UI-facing conflict list change while `generation`/projection stamps remain stale. Test generation and `artifact_revision`/projection cause change for reject, Degraded accept, Quarantined discard/accept, and Degraded accept.

5. **Store reconstruction does not seed causal identity, sequence, or HLT state consistently.** `ArtifactStore::new` (`🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:3939-3970`) creates an empty `MutationDag`, starts `edit_sequence` at zero, and initializes the clock from `now_ms`; `set_state` (`:4106-4127`) seeds only top-level edit ids. Existing causal mutation ids are not seeded in `new`, and `set_state` does not seed `mutation_ids_for_edit`. New local sequence ids can collide after reload, a remote op depending on persisted history remains Pending, and a local clock can move behind a persisted future HLT. Tests: reload m1 then ingest m2 depending on m1 (must apply), reload then dispatch and assert unique/increasing sequence, reset/set_state then ingest dependent m2, and reload a future HLT then assert the next local HLT is greater.

6. **Every local apply does not tick the HLT.** `replay_mutations` (`🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:4621-4630`) calls `clock.tick` only when the operation has no explicit timestamp. Explicitly timestamped local operations leave the clock unchanged. Test two explicit-timestamp local edits followed by an implicit local edit; the resulting timestamp must be strictly after both explicit timestamps and monotone with the clock.

7. **Receipt edit ids are stale for mid-history merges.** `absorb_merge_report` (`🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:4411-4417`) records replayed/worst but not `pending_report.edit_ids`, although `dispatch` (`:4265-4284`) uses that field to override the ordinary before/after slice. Inserting a remote edit before the local tail can report the old tail instead of the actual accepted/rejected edit ids. Test a remote insertion before an existing tail and assert receipt ids exactly match the merge batch; add resolve-conflict receipt assertions.

8. **Host round trips drop first-class outcomes and conflicts.** `backbone_envelope_of` (`🧰️framework/🛍️products/💻️os/🖥️host/🦀️component.rs:365-370`) always writes empty `edit_messages`/`conflicts`; `decode_backbone_payload` and `OsWorkflowStore::new/document` (`:621-650`) carry only VCS, snapshot metadata, and applied ids. A host pack/text round trip therefore loses durable mutation messages and `os_spr::Conflict` history, while `snapshot_with_conflicts` still exposes the separate `SpaceConflict` vocabulary. Add host export/import tests preserving an edit ledger and Open/Accepted conflict; test `OsWorkflowStore::new(document()).document()` preserves them. This is also a C10 cleanup point if `SpaceConflict` is no longer allowed at the host boundary.

9. **`print_document_spr` validates only the message ledger, not conflicts.** `🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:2613-2655` does not call `validate_authoritative_history`; malformed conflict ids/statuses, wrong-document quarantine envelopes, empty/duplicate quarantined envelopes, and invalid conflict references can be serialized. Add print tests for each malformed conflict and require `ValidationFailed`; ensure valid conflict round trips preserve all fields.

10. **History message/conflict wire decoding accepts malformed values.** `🧰️framework/🛍️products/💻️os/🔨️modules/📡️spr/📜️history/🦀️component.rs:614-649` accepts any severity byte and any nonzero op-index presence byte without range/canonical validation. `decode_conflicts` (`:1319-1332`) does not require complete payload consumption; duplicate `REC_CONFLICT` records (`:1523-1526`) silently overwrite. Add codec tests for severity 4/255, op-index overflow, presence byte 2, trailing conflict payload bytes, and duplicate conflict records; every case must reject. `mutation_meta_from_history_op_meta` in store (`:2418-2433`) casts negative persisted physical HLT values to `u64`; add a malformed negative-HLT parse test and reject it.

11. **Parse can silently materialize an invalid cursor.** `parse_document_spr` (`🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:2663-2810`) builds the snapshot by skipping cursor ids not found in decoded edits; `ArtifactStore::new` rejects this only later. Parse should reject unknown applied/redo ids and duplicate cursor ids at the codec boundary. Add unknown cursor and duplicate applied/redo cursor tests.

12. **The current conflict shape diverges from the frozen contract.** `🧰️framework/🛍️products/💻️os/🔨️modules/📡️spr/⚔️conflict/🦀️component.rs:56-59` has `ConflictKind::Quarantined { envelopes }`, while C5 describes a policy-bearing quarantined kind. Policy is local-only and must not leak into shared envelope/history, so either update the contract to make policy runtime-only or define an explicit non-persisted resolution policy; do not add an accidentally serialized local policy. Add a codec round trip asserting policy is not shared and resolution always uses the documented LF rule.

## Result migration boundary for `MutationDiff::apply`

There is no isolated compile error attributable to the current infallible API from static inspection; changing it is intentionally a breaking, repo-wide migration. The clean boundary is the trait declaration at `🧰️framework/🛍️products/💻️os/🔨️modules/📡️spr/🎮️command/🦀️component.rs:15-16`: introduce the crate-owned typed `DiffApplyError`/`MutationApplyError` and change `MutationDiff::apply(&self, &P) -> Result<P, Error>` in one coordinated pass. The first semantic propagation seam is `🧰️framework/🛍️products/💻️os/🔨️modules/🌿️vcs/🦀️component.rs:391-403` (`apply_mutation` should return a typed error), followed by store replay/fold sites at `🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:1063,1132,1199,4228,4653,5426`, planner sites at `🧰️framework/🛍️products/💻️os/🔨️modules/📡️spr/🎮️command/🦀️component.rs:972,1063,1085`, and the testkit laws. `rg` finds about 261 `fn apply(&self, ...)` implementations/call sites across framework and `✏️s`; all leaf diffs and direct tests must migrate together. Avoid an infallible adapter: it would hide apply failures and violate the requested typed boundary. Add tests at the VCS seam for error propagation, store replay atomicity on apply failure, and inverse/state invariants after successful Result application.

## Additional semantic checks

- `MutationOutcome` message fields are private and equality is value-based, which is appropriate; the missing validation is at persistence boundaries, not serde derivation. Ensure ledger entries remain the authored durable messages: accepted remote rebases currently add messages only for new edits (`🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:4823-4830`), so add a test proving existing authored messages are not replaced by a replay with different diagnostics.
- `validate_authoritative_history` (`🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️component.rs:5221-5322`) checks shape/ranges but not the frozen message-code set, conflict actor/timestamp consistency, quarantine dependency uniqueness, or message-to-op ownership. Add negative validation tests for unknown codes, duplicate/empty entries, invalid targets/op indices, and conflict references.
