# Plugin Dependencies, Artifact Contributions and Composite Mutations

## Context

Three capabilities are missing from the s/OS plugin architecture and must land as one coherent, end-to-end mechanism set:

1. **Mutations must be able to call other mutations** — same artifact, other artifacts of the same plugin, and artifacts of other plugins — committed as one atomic, undoable, replayable, syncable step.
2. **Plugins can depend on other plugins** — today plugin crates already Cargo-depend on each other (`demonstrator` → cad/puzzle/…; `procedural` → flow + 8 flow extensions) but nothing at runtime knows: `PluginManifest` (`🧰️framework/🔨️modules/🛂️manifest/🦀️component.rs:2889`) has no `dependencies`, hosts load in arbitrary order, hot-reload/unload ignores dependents.
3. **Plugins can register mutations and inferences on artifacts defined by other plugins** — today this is *asserted away*: `ArtifactDeclaration::register_all` (`🔌️plugin/🦀️component.rs:2285-2329`) panics unless the declaring plugin owns the kind and unless every inference service's `owner == plugin_id`; `ArtifactDefinitionRegistry::register` rejects a second definition of the same identity; the mutation vocabulary of an artifact is a *closed* `#[derive(Mutations)]` enum (`🗣️dsl/✨️derive/🦀️component.rs:977`).

What exists and is reused (not reinvented):
- `protocol::Mutation<P>` / `MutationKind<P,Op>` / `SemanticMutation` (`📡️spr/🎮️command/🦀️component.rs:57-332`), `Edit{forwards: Vec<Op>, inverse: Vec<Op>, mutation_meta}` and `MutationMeta.group_id` (same file :389-447).
- `CompositionCoordinator::dispatch_group` two-phase validate/apply/compensate over `dyn SpaceMember` with opaque op bytes (`🏪️store/🦀️component.rs:5656-5770`) and `Emit.child_emits` (`🔌️plugin/🦀️component.rs:6289-6310`).
- Host routers that already make cross-plugin calls "one host hop": `IoRouter` and `ArtifactInferenceRouter` (`🔌️plugin/🖥️host/🦀️component.rs:141-353`); WIT world (`🔌️plugin/📦️packages/🦀️rust/📜️wit/📜️world.wit`) with `list-artifact-inferences`/`artifact-infer` per plugin.
- The two-tier extensibility the dev wants kept: **plugin** (plugin-world) and **extension** (extension-world, `ExtensionBundle`, `extends`, `🧩️extensions/*` crates with `evaluate` handlers). Both tiers get the *same* dependency + contribution machinery; the extension tier is not removed.
- Two hosts must stay in parity: Rust wasmtime host (`🔌️plugin/🖥️host/🦀️component.rs`, used by `🏃️run` + wgpu native) and the TS browser host (`🧰️framework/🔨️modules/🎠️kernel/🟦️component.ts`, `🧰️framework/🛍️products/💻️os/🟦️component.ts` `AppChannelClient` + hand-mirrored `AppCommand`/`AppFrame` codecs, jco host shim `🔌️plugin/📦️packages/🟦️typescript/🌐plugin-web-materialize.ts`).

Non-negotiables from CLAUDE.md that shape the design: schema-first, event-sourced CQRS (no CRUD/CRDT), no legacy/compat layers, no external runtime libs, taxonomy-tree files with regions, everything registered in `launch.json`, all work inside a ticket, no modifying git commands, no worktrees, heavy cargo gates run serially.

## Design decisions (settled)

| # | Decision | Rationale |
|---|---|---|
| D1 | **Host-driven, no re-entrant host import.** A guest never blocks inside a mutation calling into another plugin. Same-artifact composition expands in-guest; anything touching another artifact is returned to the host as a *plan* and the host drives a two-phase transaction across instances/plugins. | WIT imports are sync; the browser host runs one worker per plugin and cannot service a sync cross-worker call; the wasmtime host holds the caller's `Store` mutex (documented deadlock in `IoRouter::compose`). Host-driven is deterministic and works identically in both hosts. |
| D2 | **Composite = pure plan.** A composite mutation kind is a pure function `(payload, base) → plan`; its diff/inverse are *derived* by folding local steps. Same-artifact composites need no persisted expansion — replay re-plans deterministically exactly like `diff` today. | Keeps mutation laws (`absorb`, inverse) and CQRS event log unchanged. |
| D3 | **Foreign steps are excluded from the owner's diff.** `Mutation::diff` folds *local* steps only; foreign steps become member edits in the *target* artifact's own log, linked by one `group_id` (transaction id). Replay of one log never re-issues foreign steps. | Each artifact stays the single authority of its own history; sync per artifact stays unchanged. |
| D4 | **Contributed mutations are recorded in the owner's log as owner ops** with provenance `MutationOrigin::Contributed{plugin, mutation_id, payload_hash}` and the contributor's label. Replay never needs the contributor plugin. | Owner enum stays closed at the type level; openness is at the *routing* level (host `ArtifactMutationRouter`), mirroring `ArtifactInferenceRouter`. |
| D5 | **Runtime dependency ⇔ Cargo dependency** on `semio-s-plugin-<id>` (`default-features = false`) — the builder declares `.depends_on(cad::PLUGIN_ID)`, and a policy gate enforces parity with `Cargo.toml`. Contributions and foreign steps are permitted only against **directly** declared dependencies. | Typed payload/snapshot access needs the crate anyway; direct-only = maximum control. |
| D6 | **Extension tier kept, unified underneath.** `ExtensionManifest` gains `dependencies` (its `extends` plugin is always one) and `contributions`; extension-world exports the same `contributor` WIT interface as plugin-world; host registers extensions into the same routers. `invoke(capability)` handlers stay. | Dev instruction: keep two-step extensibility, unify as much as possible. |
| D7 | **Inference contributions with inference dependencies.** A contributed (or owned) inference may declare `depends_on: [inference ids]`; hosts resolve a per-artifact inference DAG and pass dependency results in the request envelope. Router conflict rule unchanged: one implementation per `(artifact_kind, inference_schema)`. | Cross-plugin inference reuse without breaking purity/determinism laws. |
| D8 | **One transaction coordinator design, two resolvers.** `CompositionCoordinator` is generalized to `TransactionCoordinator<R: MemberResolver>`; owned-child composition (`child_emits`) stays in-guest; the Rust host and TS host each implement the same protocol over `exchange`. | No second protocol; shared conformance vectors keep three implementations honest. |
| D9 | New ticket under goal `🎯aioptimizedrepo`: **Plugin Dependencies, Artifact Contributions and Composite Mutations**. All docs/logs/scratch inside the ticket folder; wave reports per lane; `📌️important.md` cleared last. | Repo rules. |

## Mechanisms

### M1 — Composite mutations (protocol spine)
File: `🧰️framework/🛍️products/💻️os/🔨️modules/📡️spr/🎮️command/🦀️component.rs` (region `🔖️Semantics`, new subregion `🔖️Composite`).

- `pub struct ForeignStep { target: ArtifactRef (io), mutation_id: SchemaId, payload: Vec<u8> /* target Op OpBinary or contributed payload */ , label: String }`.
- `pub enum PlanStep<Op> { Local(Op), Foreign(ForeignStep) }`.
- `pub struct Planner<'a, P, Op: Mutation<P>> { base: P, steps: Vec<PlanStep<Op>>, depth: u8, stack: Vec<(kind, payload_hash)> }` with `call(op) -> Result<(), PlanError>` (validate against current base, push, advance base by `op.diff(&base).apply(&base)`), `call_foreign(step)`, `base()`; `MAX_PLAN_DEPTH` + cycle detection by `(semantic kind, payload_hash)`; typed `PlanError`.
- `pub trait CompositeMutationKind<P, Op: Mutation<P>>: Clone + Serialize + DeserializeOwned { const SEMANTICS; fn plan(&self, base:&P, planner:&mut Planner<P,Op>) -> Result<(), PlanError>; fn label(&self)->String; fn target(&self)->Vec<String>; fn validate(&self,&P)->Result<(),String>{Ok(())} }`.
- Blanket `impl<P,Op,T: CompositeMutationKind<P,Op>> MutationKind<P,Op> for T` — `diff` = fold of local steps' diffs via `MutationDiff::absorb`; `inverse` = reversed concatenation of local steps' inverses (computed against the successive bases); `foreign_steps` = collected foreign steps.
- `Mutation<P>` gains `fn foreign_steps(&self, base:&P) -> Vec<ForeignStep> { Vec::new() }`; `MutationKind` gains the same defaulted method; `#[derive(Mutations)]` (`🗣️dsl/✨️derive/🦀️component.rs:1021-1069`) emits the delegating arm.
- `MutationMeta` gains `origin: MutationOrigin` (`Owner | Contributed{plugin_id, mutation_id, payload_hash} | Transaction{initiator: ArtifactRef}`) — persisted through `.spr` history (`📡️spr/📜️history` `HistoryOpMeta`).
- `MutationDescriptor` gains `contributor: Option<PluginId>` and `artifact_kind`.
- Laws (tests, shared vectors): `plan-fold == diff`; `inverse(diff(base)) == base`; composite of composites; depth/cycle rejection; foreign steps excluded from diff.
- Taxonomy: new leaf dir `🧩️plan` under `🧬️mutations/<kind>/` (add to `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🔣️taxonomy.json` next to `🦠️mutation/🔺️diff/↩️inverse`). A composite kind's folder is `{🦠️mutation, 🧩️plan}`; a leaf kind's stays `{🦠️mutation, 🔺️diff, ↩️inverse}`. Policy gate `policyMutationTriadCompletenessBreaches` (root `📜️script.ts:7450`) accepts either shape, never a mix; `policyMutationImplPresenceBreaches` (:7491) checks `impl … CompositeMutationKind` for plan-shaped kinds.

### M2 — Channel & transaction protocol
Files: `📡️spr/🧵️channel/🦀️component.rs` (Rust codec) + TS mirror in `🧰️framework/🛍️products/💻️os/🟦️component.ts` (`AppCommandValue`/`AppFrameValue`, `encodeAppCommand`… + tests) + shared golden vectors.

New `AppCommand`s: `TransactionPrepare{ seq, txn_id, kind: PrepareKind }` where `PrepareKind = OwnerMutation{ mutation_id, payload } | PreparedOps{ ops: Vec<Vec<u8>>, label, origin }`; `TransactionCommit{ seq, txn_id }`; `TransactionRollback{ seq, txn_id }`; `TransactionUndo{ seq, group_id }`; `TransactionRedo{ seq, group_id }`.
New `AppFrame`s: `TransactionProposal{ in_reply_to, proposal_id, local: PreparedLocal{ ops, description, coalesce_key }, foreign: Vec<ForeignStep> }` (emitted instead of applying when a dispatched op has foreign steps); `TransactionPrepared{ txn_id, foreign: Vec<ForeignStep>, rejection: Option<Fault> }`; `TransactionCommitted{ txn_id, edit_id }`; `TransactionRolledBack{ txn_id }`.
Guest state: `VcsArtifactApp` holds `pending: Option<PendingTransaction{ txn_id, ops, label, origin, base_generation }>`; commit applies as ONE `Edit` with `group_id = txn_id`; generation mismatch at commit ⇒ typed rejection.

Host protocol (identical in both hosts):
1. Initiator instance returns `TransactionProposal`. Host mints `txn_id`, records members `[initiator(local ops)]`.
2. For each foreign step: `InstanceDirectory.resolve(target: ArtifactRef) → (runtime, instance_id, artifact_kind)`; `ArtifactMutationRouter.route(artifact_kind, mutation_id) → Owner | Contributed{plugin}`. Owner ⇒ `TransactionPrepare{OwnerMutation}` to that instance. Contributed ⇒ host calls contributor's `artifact-mutation-plan(request)` with the target's current snapshot pack (Rust host: `SessionLanePack.pack`; TS host: last `AppFrame::Document` pack / `ReadDocument`) → `{ owner_ops, label, foreign }` ⇒ `TransactionPrepare{PreparedOps}` to the target instance.
3. Recurse over returned `foreign` (depth ≤ `MAX_TXN_DEPTH`, cycle detection on `(target, mutation_id, payload_hash)`, one instance appears at most once per txn — a second visit merges ops into that member in order).
4. Phase 1 complete when every member returned `TransactionPrepared` without rejection and every dependency/contribution gate passed; otherwise `TransactionRollback` to all prepared members and a typed rejection to the initiator.
5. Phase 2: `TransactionCommit` members in reverse discovery order (leaves first, initiator last — mirrors composition "children then parent"). On any commit failure ⇒ `TransactionUndo{group_id}` to already-committed members (compensation) then rollback the rest.
6. Group undo/redo: `TransactionUndo/Redo{group_id}` fan-out to all members with that group (host keeps `group_id → members` index; guests also index `group_id` in their envelope for redo/undo consistency).

### M3 — Plugin dependencies & contributions (manifest + SDK)
- `🛂️manifest/🦀️component.rs`: `PluginDependency{ plugin_id, version: VersionReq }` (in-repo `VersionReq` parser: `^`, `~`, `=`, `>=`, wildcard; no external crate), `PluginManifest.dependencies`, `PluginManifest.contributions: Vec<ArtifactContributionDescriptor>`; `ArtifactContributionDescriptor{ artifact_kind, mutations: Vec<ContributedMutationMetadata{ mutation_id, semantics, schema_version, algorithm_version }>, inferences: Vec<ArtifactInferenceServiceMetadata + contributor + depends_on: Vec<String>> }`. `ExtensionManifest` (guest struct in `🔌️plugin/🦀️component.rs:10499`, host struct in `🖥️host:976`, package manifest in `🧩️extension/🦀️component.rs`) gets the same two fields; `extends` must equal `dependencies[0].plugin_id`.
- `PluginBuilder` (`🔌️plugin/🏗️builder/🦀️component.rs`): `.depends_on(plugin_id, version_req)`, `.contributes(ArtifactContribution)`. `ExtensionBundle`: same two methods.
- `ArtifactContribution::builder(kind: &str)` (new region `🔖️ArtifactContribution` in `🔌️plugin/🦀️component.rs`): `.mutation::<K: CompositeMutationKind<TargetSnapshot, TargetOp> | MutationKind<…>>()` (payload type from the contributor crate; target `Snapshot`/`Op` types from the dependency crate), `.inference_service(ArtifactInferenceService)`, `.inference_depends_on(id, [ids])`, `.build()`. `register_all` keeps its owner asserts for declarations; a new `register_contributions(plugin_id, manifest)` asserts (a) `ArtifactKindId::parse(kind).plugin() ∈ dependencies`, (b) contributed mutation ids are `s.<contributor>.<artifact-owner-kind>.mutation.<slug>.vN`-namespaced (never colliding with owner kinds), (c) inference metadata `owner == contributor` and `artifact_kind == target`.
- Guest wire exports (`plugin_runtime` region): `wire_list_artifact_mutations()` (owner kinds from every document app's `SemanticMutation::kinds()` + contributed roster) and `wire_artifact_mutation_plan(request)`: decode target snapshot pack via the dependency crate's `Snapshot: ArtifactPack`, decode contributed payload, run `plan` with a `Planner<TargetSnapshot, TargetOp>`, return `{ owner_ops: Vec<TargetOp as OpBinary bytes>, label, foreign, inverse_hint: none }` with echo of `artifact_kind/mutation_id/revision/generation` (same echo-validation discipline as `validate_inference_echo`).
- Inference service signature: `infer_cold(snapshot_pack, dependencies: &[(inference_schema, bytes)])`; the inference request envelope (guest `WireArtifactInferenceRequest`, WIT `artifact-inference-request`) gains `dependencies`.

### M5 — Hosts
Rust `🔌️plugin/🖥️host/🦀️component.rs` (+ `🏃️run/🦀️component.rs` wiring): `PluginGraph` (register manifests, verify deps present + version match, Kahn toposort, reject cycles, `dependents(plugin)`; hot-reload of a plugin re-validates dependents' contributions; unload refused while dependents loaded), `ArtifactMutationRouter` (roster merge, conflict = same `(kind, mutation_id)` from two sources unless byte-identical, contribution gate = contributor's manifest lists owner plugin as dependency), `ArtifactInferenceRouter` (contributor-aware + `depends_on` DAG toposort per artifact, cycle rejection, dependency results injected), `InstanceDirectory` (`ArtifactRef ↔ (plugin_id, instance_id, artifact_kind)`, filled at `instantiate-app`/`Hello`/`LoadDocument`), `HostTransactionCoordinator` (M2 steps 1-6, typed `TransactionError`), `ExtensionRuntime` registers into the same routers.

## Waves, leases, workforce

Roles: **Fable** (this plan; not an executor). **Opus 5 coordinator** — one agent: opens the ticket, writes `📋️contract-freeze.md` + `📋️ownership-and-handoffs.md`, allocates leases, spawns workers, runs serial cargo/nx gates at barriers, reviews reports, closes the ticket (explicit path). **Sonnet 5 executors** — one per lease, write only inside their lease, report to `📓️<lane>-report.md` in the ticket folder, never close the ticket, no worktrees, no git-modifying commands. **Haiku 4.5 explorers** — read-only scouting/audits (`Explore` agent type), one per open question; audits between waves (schema parity, ownership, evidence honesty).

Shared-tree rule: other live sessions (notably ticket `26/08/16/FULL-STDIO-ARTIFACT-STANDARDS-CODECS-INFERENCES-AND-MUTATIONS`, whose W0 leases name `🔌️plugin/🦀️component.rs`, `🏪️store/🦀️component.rs`, `🚪️io/🦀️component.rs`, and the WIT) edit the same files concurrently. Every writer re-reads the target region immediately before editing, edits by region with `Edit` (never whole-file rewrites), keeps diffs minimal, and never reverts foreign changes; the coordinator records each lane's touched regions in `📋️ownership-and-handoffs.md` and reads the other ticket's `📌️important.md` at every barrier.

Barrier rule: within a wave lanes run in parallel with disjoint file leases; the coordinator runs `cargo check -p <touched crates>` / focused `cargo test` / `bun nx run …` serially at the barrier, then dispatches Haiku audits before the next wave. Repo-wide cargo failures may be another live session's churn (check git log/mtimes before attributing).
