## Domain-verb → family mapping table (all non-obvious mappings, with rationale)

| plugin | verb (kind)         | family chosen        | why |
|---|---|---|---|
| lowpoly | create-mesh        | add                  | Sets an existing object's `mesh` CHILD slot; the object must already exist (owner-absence check), but the mutation's own docstring calls it "overwrite-aware" (matching stdio's `create-mesh` convention) — so no Fatal duplicate-id, matching "add ⇒ Error owner absent" rather than "create ⇒ Fatal duplicate-id". |
| lowpoly | delete-mesh        | clear                | Clears a single optional slot (`Option<ArtifactChild>`) on an existing object, not a removal from a collection — "delete ⇒ Error absent" doesn't fit an idempotent slot-clear; mapped to "clear ⇒ Warning no-op when already empty" instead (plus Error target-missing for the owning object, since object-absence is still a real miss). |
| lowpoly | rename-object, rename-paint-layer | rename (no duplicate-id case) | `rename` family's Fatal duplicate-id sub-case only applies when the renamed field is a uniqueness key; both `name` fields here are non-unique display strings (the real key is `id`/index), so the Fatal branch is omitted and only Error/Warning apply. |
| process | move-stock, change-stock-label, replace-stock-solid, change-cursor | move / change / replace (singleton, no target) | The document has exactly one `stock`/cursor (not id-keyed), so there is no "target" that can be missing — matches the contract's explicit allowance for a message-free outcome on a document-level facet setter; Warning no-op is still added wherever a cheap equality check exists. |
| process | create-step, rename-step, delete-step, change-step-enabled, change-step-origin, replace-step-measure, reorder-steps | (all families, pre-empted by a documented no-op) | `steps` composes an unresolved `s.stdio.semio.flow` CHILD HANDLE (ticket UNIFIED-COMPOSABLE-ARTIFACT-SYSTEM wave 4) — there is no `Vec<ProcessStep>` on `Process3dSnapshot` to inspect, so none of the verb-family's Error/Fatal checks (which all require reading real content) can be implemented. Uniformly mapped to Warning `mutation.no-op`, since the diff leaf's own pre-existing behavior is "return `Process3dDiff::default()` always" — i.e. it IS a no-op by construction, and Warning `mutation.no-op` is the one frozen code that means exactly that, rather than silently succeeding with zero messages. |
| demonstrator | change-schema | change (root-scoped, single field) | Playground's whole persistent snapshot is one opaque `schema` string (`📓️derivation-rules.md`'s metadata-only-mutation allowance) — no target, so only the Warning no-op branch applies. |
