# Wave 1 fan-out — gismap facet report

Facet: `✏️s/🔌️plugins/🌍️gis/🗿️artifacts/🗺️gismap/🏅️standards/🔖️1/🪆️subsets/✳️any/🧬️schema/🧬️mutations`
Crate: `semio-s-plugin-gis`

## Source shape (before)

`GisMapSnapshot` has three id-keyed `Vec<MapFeature>` collections (`positions`/`routes`/`regions`,
each a full-opaque-payload feature: `id` + untyped `data: dsl::DslValue`). The old `GisMapMutation`
enum had four variants: `Positions`/`Routes`/`Regions(CollectionMutation<String, MapFeature,
MapFeaturePatch>)` (a foreign generic type wrapped directly in the public dispatch enum — forbidden
vocabulary) and the banned `SetSnapshot { snapshot }` (whole-document replace). The `💾️binary`
component carried a hand-rolled `GisMapOperationDsl` "DSL-mirror" enum purely to work around the
orphan-rule problem of not being able to derive `dsl::DslField`/`dsl::DslVariants` on the foreign
`CollectionMutation<K,V,P>`.

## Derivation applied

Per `derivation-rules.md` recipe §2 (per id-keyed collection), each of `positions`/`routes`/
`regions` got the same four-verb vocabulary:

- `create-<singular>` (was `CollectionMutation::Add`) — full payload + FINAL-state `index`.
- `delete-<singular>` (was `CollectionMutation::Remove`) — BASE-state `id`.
- `replace-<singular>-data` (was `CollectionMutation::Patch`) — `MapFeature::data` is deliberately
  untyped ("escape hatch" per its own docstring), so a partial `change` isn't expressible; this is a
  whole-value swap of a structured sub-payload, i.e. `replace` per the taxonomy.
- `reorder-<plural>` (was `CollectionMutation::Move`) — kept, since the pre-existing `Move`
  variant/tests/wire-grammar already treat feature order as meaningful; addressed by `id`+`to_index`
  (id-keyed collection, per the taxonomy's `reorder` canonical-args row), not a bare index pair.

`SetSnapshot` → **deleted, no replacement**, per taxonomy's banned-vocabulary rule. The one call site
that used it (`setActiveExample`, load-example/clear-map) now diffs old vs. new snapshot per
collection (reusing the app's existing `positions_operations`/`routes_operations`/
`regions_operations` engine helpers) into a batch of the new semantic operations — still fully
undoable (each generated mutation has a real per-kind inverse; `Edit.inverse: Vec<Op>` already
applies a whole batch as one undo step), just no longer a single atomic snapshot swap.

12 triads total (4 verbs × 3 collections).

## Triad leaves created

```
🆕create-position/{🦠️mutation,🔺️diff,↩️inverse}   🆕create-route/…   🆕create-region/…
🗑delete-position/{…}                              🗑delete-route/…   🗑delete-region/…
🔁replace-position-data/{…}                        🔁replace-route-data/…   🔁replace-region-data/…
🔀reorder-positions/{…}                            🔀reorder-routes/…   🔀reorder-regions/…
```

Each `🦠️mutation` payload derives `dsl::DslRecord` with `#[dsl(keyword = "<kind>")]` and implements
`protocol::MutationKind<GisMapSnapshot, GisMapMutation>` with a real `SEMANTICS` const;
`diff`/`inverse` delegate to the sibling `🔺️diff`/`↩️inverse` leaf functions (never inline). Each
`🔺️diff` leaf builds the sparse `GisMapFeaturesDelta` by constructing a `protocol::CollectionMutation`
value from the payload and calling the pre-existing, still-real `features_delta_from_collection_mutation`
helper in `🔺️diff/📝️text/component.rs` — per that framework module's own doc comment,
`CollectionMutation` and its helper fns are meant to be used exactly this way, as an INTERNAL
diff/inverse engine a triad leaf calls, never as a public mutation payload itself. Each `↩️inverse`
leaf reconstructs the undo mutation by reading `base` directly (never the diff): `create`'s inverse is
`delete` by the created item's own id; `delete`'s inverse re-`create`s at the pre-deletion index
captured from `base`; `replace`'s inverse restores `base`'s prior `data`; `reorder`'s inverse moves
the feature back to its pre-reorder index. All four guard for a missing target and return `Vec::new()`
(the taxonomy's replacement for the banned `NoMutation` sentinel) instead of panicking — deliberately
NOT delegating to `protocol::inverse_collection_mutation` for this, since that helper panics on a
missing id and the taxonomy requires `Vec::new()`.

Old `📄set-snapshot/**` (3 files) deleted entirely.

## Dispatch rewrite

`🧬️mutations/🦀️component.rs`'s `GisMapMutation` enum is now 12 single-field tuple variants
(`CreatePosition(create_position::mutation::CreatePosition)`, …), deriving `dsl::DslEnum` directly
(no more foreign `CollectionMutation` in its shape — every variant now wraps a local
`dsl::DslRecord` payload) **and** `dsl::Mutations` (`#[mutations(snapshot = GisMapSnapshot, diff =
GisMapDiff, schema = "gis.gismap")]`). Hand-written `impl Mutation<GisMapSnapshot> for
GisMapMutation` (the old `diff`/`inverse` match) deleted — generated by the derive now. Kept
`apply_gis_map_mutation`/`inverse_gis_map_mutation` and the `GisMapEnvelope`/`GisMapStore` type
aliases.

## `📝️text` / `💾️binary` companions

Since `GisMapMutation` no longer wraps a foreign type, the orphan-rule workaround is gone:
- `🧬️mutations/📝️text/🦀️component.rs` gained the handcrafted `OpText`/`OpBinary` impl for
  `GisMapMutation` directly (moved from the old local-mirror-type version in `💾️binary`), mirroring
  `🏔️gisterrain`'s sibling facet's identical post-migration shape verbatim.
- `🧬️mutations/💾️binary/🦀️component.rs` shrank to a pure `encode_op`/`decode_op` pass-through +
  tests — the `GisMapOperationDsl` mirror enum and its ~35-line `gis_map_operation_to_dsl`/
  `_from_dsl` conversion functions deleted entirely (no longer needed).
- Deleted the old pinned-byte compat test (`operation_rows_keep_their_pre_migration_bytes`) —
  greenfield repo, no back-compat requirement, and the wire shape necessarily changed (new keywords,
  new field names).

## Module wiring (`📦️packages/🦀️rust/📦️glue.rs`)

Replaced the single `#[path = "."] pub mod set_snapshot { .. }` block with 12 equivalent
`#[path = "."] pub mod <verb>_<noun> { pub mod mutation; pub mod diff; pub mod inverse; }` blocks.
**Caught the exact gotcha `🏔️gisterrain`'s report flagged**: an inline nested `pub mod X { #[path =
"..."] pub mod mutation; .. }` block needs its OWN `#[path = "."]` attribute immediately before it,
or rustc treats the mod's own name as an extra directory segment when resolving its children's
relative `#[path]`s (confirmed by a real compile error: `couldn't read
".../create_position/../../🗿️artifacts/..."` — the phantom `create_position/` segment). First attempt
generated all 12 blocks without their own `#[path = "."]`; caught via `cargo check`'s error message
naming the exact bad path, fixed by prepending `#[path = "."]` to all 12 via a small script,
re-verified every `#[path]` string in the file resolves to a real file with a Python existence check
before recompiling.
