W3 report — DocumentCommand text + binary representation (closes G3)

Landed exactly per w3-w4-design.md's D1-D3 decisions and ordered sequence, no deviations.

1. store/rs/lib.rs, new region 🔖CommandFormat (between 🔖TextFormat and 🔖History):
   - CommandHeaderLine enum, #[derive(DslOps)] (Apply/Undo/Redo/CommitCheckpoint/
     CreateAlternative/SwitchAlternative/Checkout/Amend) — keywords via to_kebab, reuses
     OpsAuthor for `by=[...]` (Author.avatar never serialized, matching the .ops law).
   - undo_policy_to_token/parse_undo_policy_token (text) + undo_policy_ordinal/
     undo_policy_from_ordinal (binary), declaration-order mapping.
   - print_command/parse_command (text, indented op lines for Apply/Amend, recursive dedented
     nested command block for UndoWithPolicy's semantic_command).
   - COMMAND_BINARY_FORMAT=1, encode_command/decode_command (format u8 | tag u8
     (DocumentCommand declaration order 0..8) | body; str = varint len + utf8; op = varint len +
     OpBinary::encode_op bytes; UndoWithPolicy nests a recursive length-prefixed encode_command).

2. UndoWithPolicy.semantic_command: Option<String> (JSON) -> Option<Box<DocumentCommand<Operation>>>.
   dispatch_inner's SemanticUndo|CompensatingAction arm simplified to `self.dispatch_inner(*command)`
   (no more serde_json::from_str).

3. DocumentStore::dispatch_json deleted; replaced with dispatch_text (Operation: OpText bound)
   and dispatch_binary (Operation: protocol::OpBinary bound), both method-level where clauses
   (impl block itself stays JSON-serde-bounded for other methods).

4. test_support::assert_command_text_binary_equivalence added beside
   assert_op_text_binary_equivalence — asserts parse_command(print_command(c)) == c ==
   decode_command(encode_command(c)), plus binary-encoding determinism.

5. store/rs/lib.rs tests: dispatch_json test replaced by dispatch_text_applies_a_command_block_...
   + dispatch_binary_applies_an_encoded_command_and_rejects_wrong_format +
   command_text_binary_equivalence_holds_for_every_document_command_variant (13 command literals
   covering every DocumentCommand variant incl. nested semantic UndoWithPolicy). Fixed the two
   pre-existing semantic_command test literals (compensating_undo_dispatches_semantic_command,
   compensating_undo_without_a_semantic_command_is_rejected) to the boxed type.
   store: 74 -> 79 tests, all green.

6. Fleet-wide dispatch_json caller flip (grep-verified complete list, 20 crates, zero remaining
   outside .repo/ archives and a stale worktree):
   - 17 uniform wasm-only wrappers mechanically flipped (dispatchJson -> dispatchText +
     new dispatchBinary): animate/present, cad, draw, fem/2d, fem/3d, flow/core,
     infinite/board/port/directed/dag, playbook, procedural/2d, procedural/3d, process/3d,
     puzzle/3d, puzzle/5d, shooting, trinity/ram, trinity/rewrite/engine, writer.
   - 2 differently-indented wasm-only wrappers (same substance): gis/plugin, raster/plugin.
   - 2 native+wasm dual surfaces: s/rs (StudioStore, native dispatch_text/dispatch_binary +
     wasm dispatchText/dispatchBinary) and framework/product/os/core (OsStore, same shape).
     Both had a test literal `dispatch_json(r#"{"kind":"undo"}"#)` flipped to
     `dispatch_text("undo")`.
   - OsOperation gap found and fixed: it had a hand-written `impl protocol::OpText for
     OsOperation` (bridging to/from the derived OsOperationDsl) but NO OpBinary impl (unlike
     every other DslOps-derived op enum, OsOperation itself doesn't derive DslOps — it's a
     manual wrapper). Added `impl protocol::OpBinary for OsOperation` mirroring the same
     to/from-dsl bridge pattern, forwarding to OsOperationDsl's derived OpBinary (free — DslOps
     already derives it since W2). This was NOT flagged in the design doc's caller list detail
     but was required for os/core's dispatch_binary to compile; worth noting for future waves
     touching hand-written OpText bridges (only OsOperation has one; every other app's op enum
     derives DslOps directly).
   - imperative/core/rs: confirmed unchanged (typed dispatch only, no dispatch_json ever
     existed there, per design doc).
   - No hand-written TS/JS callers exist anywhere (only generated wasm-bindgen glue under
     framework/product/os/dev/plugin-modules and framework/product/os/dev/renderer-modules,
     regenerated by wasm builds, nothing to hand-edit); confirmed via grep across
     ts/tsx/js/svelte/vue — the only hit was a stale reference inside a .repo/ archive file,
     not live code.
