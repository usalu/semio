# Sequence: fix destructive reload, text module parity, and rendering fallout

## Root cause analysis

Traced three reported bugs to two independent, well-defined defects:

**1. Destructive full-session reload on every edit** (`sequence/core/lib.rs`, `sequence/react/index.tsx`)

- `SequenceHost::from_fixture` (`sequence/core/lib.rs:196-211`) hardcodes `next_serial: 100` every time it runs.
- `SequenceSession::load_fixture_json` (`sequence/core/lib.rs:698-703`) fully replaces `self.state.borrow_mut().host` with a brand new `SequenceHost` — it does not just refresh the existing one.
- The React sync effect (`sequence/react/index.tsx:791-808`) calls `session.loadFixtureJson(nextFixture)` whenever `session.fixtureJson() !== nextFixture` (raw string compare).
- Rust's `serde_json` always emits explicit decimals for whole `f64` values (e.g. `"x":40.0`); JS `JSON.parse`/`JSON.stringify` normalizes them to `"x":40`. `SequencePlayController.applyFixtureJson` (`sequence/play/index.ts:447-454`) round-trips every incoming fixture through `JSON.parse` + `JSON.stringify`, so the string that comes back down as the `fixtureJson` prop essentially never byte-matches `session.fixtureJson()`.
- Net effect: every single fixture mutation triggers `loadFixtureJson`, which rebuilds a brand new `SequenceHost` with `next_serial` reset to 100. Dropping `math.add` a second time computes the exact same `step-101` id as the first drop, pushing a duplicate id into `fixture.steps`. Downstream DAG bookkeeping (id-keyed maps, `expect()`s such as `step_to_dag_node`'s `info.expect("function step must resolve operator info")`) can then panic or silently misbehave on the corrupted duplicate-id fixture, which is consistent with rendering ("labels/icons") breaking wholesale from that point on.
- For comparison, Flow does not have this destructive-replace problem: `FlowSession::load_fixture_json` calls `inner.host.replace_fixture(fixture)` (`flow/core/lib.rs:3110-3116`), which mutates the existing host in place and preserves `next_widget_serial`/`next_synapse_serial`. Sequence has no equivalent `replace_fixture`.

**2. `text` module was never upgraded to the "into" scope-write convention** (`imperative/module/text/lib.rs`, `sequence/core/lib.rs`, `imperative/core/index.ts`)

- `math`/`logic` operators write their result into a user-named scope key via a `"into"` string input (`imperative/module/math/lib.rs:24-27`, `imperative/module/logic/lib.rs:24-27`), which `Executor::run_step` merges flat into scope (`imperative/engine/lib.rs:164-167`).
- `text.concat`/`text.uppercase`/`text.length` (`imperative/module/text/lib.rs:10-48`) still use the old `channel_output("text", ...)` pattern with no `"into"` input at all. `merge_output_into_scope` (`imperative/engine/lib.rs:211-232`) then dumps the whole nested `{value: ...}` dictionary under the fixed key `"text"` — there is no way for the user to name the destination variable, so downstream steps can't reliably consume the result.
- `sequence/core/lib.rs`'s `is_function_kind` (`lib.rs:22-24`) only matches `"math."`/`"logic."`, so `text.*` steps fall through to the plain execution-step branch in `step_to_dag_node` (`lib.rs:613-628`): they get bare `prev`/`next` triangle ports and no data ports at all on canvas, unlike `math.add`.
- The TS-side catalogue duplicate `TEXT_MODULE_CATALOGUE_SECTION` (`imperative/core/index.ts:116-151`) — which is what `sequencePlayInspectorParamGroup` actually renders fields from — is also missing the `"into"` input that `MATH_MODULE_CATALOGUE_SECTION`/`LOGIC_MODULE_CATALOGUE_SECTION` have, so there's no Inspector field to even type a destination variable into.

## Fix plan

### A. Stop the destructive reload (`sequence/core/lib.rs`)
- Add a `max_serial_in_fixture(fixture: &SequenceFixture) -> u64` helper that scans `step-<N>`/`edge-<N>` suffixes and returns the max.
- Replace the hardcoded `next_serial: 100` in `SequenceHost::from_fixture` with a value derived from `max_serial_in_fixture` (still safely ahead of the default fixture's ids).
- Add `SequenceHost::replace_fixture(&mut self, fixture: SequenceFixture) -> Result<(), String>`: validate schema, bump `next_serial` to `max(self.next_serial, max_serial_in_fixture(&fixture))`, assign `self.fixture = fixture`, call the existing `self.rebuild_dag()` (already preserves selection since it mutates the same `DagHost` in place — no change needed there).
- Change the WASM `SequenceSession::load_fixture_json` binding (`lib.rs:698-703`) to parse the JSON and call `host.replace_fixture(...)` instead of constructing a whole new `SequenceHost`.
- Harden `add_step_in_slot`'s id generation (and the edge-id generation in `connect_steps`/`sync_edges_from_dag`) with a small collision-avoidance loop (increment `next_serial` until the candidate id isn't already present) as defense-in-depth against any other stale-state path.

### B. React-side: stop comparing raw Rust JSON to JS-canonicalized JSON (`sequence/react/index.tsx`)
- In the `fixtureJson` sync effect (`index.tsx:791-808`), canonicalize both sides via `parseSequenceFixtureJson`/`sequenceFixtureToJson` before the `!==` check (or compare parsed objects), so a harmless float-formatting difference no longer triggers `session.loadFixtureJson`. This is safe either way given fix A, but avoids needless full rebuilds/selection churn on every interaction.

### C. Give `text` module scope-write parity with `math`/`logic` (`imperative/module/text/lib.rs`)
- Add a `write_into(input, value) -> Result<Dictionary, EvalError>` helper (same shape as `math`'s), add a `string_channel("into")` input to `text.concat`, `text.uppercase`, `text.length`, and change each `Operation::evaluate` to call `write_into` instead of `channel_output`.
- Change each operator's `outputs` to `vec![ChannelSpec::wildcard()]` to match `math`/`logic`'s single generic output-port convention (the real value flows through the `"into"` scope key, not a named output channel).
- Update/extend the existing `text_concat_joins_strings` test (and add equivalents for uppercase/length) to assert the result lands at the caller-chosen `"into"` key.

### D. Wire `text` into Sequence's function-node classification (`sequence/core/lib.rs`)
- Extend `is_function_kind` to also match `"text."`, so `text.*` steps render with data ports + hidden flow ports like `math`/`logic`, instead of bare execution pins.
- Extend the existing `function_steps_use_data_ports_without_visible_execution_pins` test (or add a sibling) covering `text.concat`.

### E. Fix the TS-side catalogue duplicate (`imperative/core/index.ts`)
- Add `{ name: "into", code: "S" }` to each item's `inputs` in `TEXT_MODULE_CATALOGUE_SECTION` (`index.ts:116-151`), matching `MATH_MODULE_CATALOGUE_SECTION`/`LOGIC_MODULE_CATALOGUE_SECTION`, so the Inspector exposes an editable "into" field for text steps.

### F. Regression coverage + verification
- Add a Rust test in `sequence/core/lib.rs` that reproduces the reported bug end-to-end: `add_step_dropped("math.add", ...)`, round-trip the fixture json through `replace_fixture` (simulating the React JSON round trip), then `add_step_dropped("math.add", ...)` again — assert two distinct, non-colliding step ids exist.
- Add a test asserting `replace_fixture` preserves selection and does not reset `next_serial` below existing max ids.
- Rebuild the `sequence_core` (and `mathematical_graph_port_directed_dag` if touched) wasm packages via `bun nx build` for the affected crates so `sequence/react`/`sequence/play` pick up the Rust changes.
- Run `cargo test` for touched crates (`sequence/core`, `imperative/module/text`, `imperative/engine`) and `bun nx test` for touched TS packages (`sequence/core`, `sequence/react`, `sequence/play`, `imperative/core`).
- Browser-verify in the sequence playground: drop `math.add` twice (confirm two distinct nodes), drop `text.concat`, wire params via Inspector `into` field, run, confirm the effect log shows a resolvable scope value; confirm labels/icons render for all node kinds comparable to Flow at default zoom.
- Follow AGENTS.md ticket workflow: find/reopen the sequence-elevation ticket (or open a new one if none currently covers this) before starting, and close it with a summary + full file list when done.
