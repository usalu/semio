GOAL
----
Replace two unlinked axes:
  Level     = "base" | "canvas" | "window" | "panel" | "overlay" | "temporary"  (backgrounds/z)
  GlassTier = "panel" | "ribbon" | "menu" | "windowOptions"                      (blur/alpha)
with ONE formula-derived Level system:
  Level = "base" | "window" | "pane" | "panel" | "dialog" | "menu"
Every level's background darkens (light mode) / lightens (dark mode) per step, and glass
(blur+alpha) increases per step. Values are derived from base knobs (oklab color-mix), never
hand-tuned per level. No component may assign fill/glass classes manually — everything must
inherit from the level it is stamped with via CSS cascade off `[data-level]`.

OLD -> NEW MAPPING (exact, use everywhere)
-------------------------------------------
Level:      canvas -> base (mode body / floor windows float on)
            overlay -> dialog
            temporary -> menu
            window -> window (unchanged name)
            panel -> panel (unchanged name)
            base -> base (unchanged name)
            NEW: pane (floating in-window chrome: measures rail, engagement zone, search,
                 utility bar host — previously reused "panel" glass with no level of its own)

GlassTier:  "panel" tier            -> ui-glass @ whatever level the surface actually is
                                        (usually panel; introduction/tutorial/modal boxes -> dialog)
            "ribbon" tier           -> ui-glass-chrome @ window level (mode-dock/window cap chips, tab bars)
            "windowOptions" tier    -> ui-glass-chrome @ pane level (measures/engagement/search/utility rails)
            "menu" tier (fallback)  -> ui-glass @ menu level

Transients (ALWAYS menu level): tooltip, popover, select, dropdown menu, command palette,
  hover card, context menu.
Dialogs (ALWAYS dialog level): shadcn Dialog/DialogContent, UIDialog, introduction info box,
  tutorial captions/veil.

CSS MECHANISM (ui/styling/js/ui.css)
--------------------------------------
Formula, k = level index 0..5 (base=0, window=1, pane=2, panel=3, dialog=4, menu=5):
  bg(k)      = mix_oklab(base, foreground, k * shadeStep)      shadeStep = 5%
  alpha(k)   = 1 - k * glassAlphaStep                            glassAlphaStep = 0.12
  blur(k)    = k * glassBlurStep                                 glassBlurStep = 0.5rem
  element(k) = mix_oklab(gray, foreground, k * elementStep)      elementStep = 6%
  hover(k)   = mix_oklab(bg(k), foreground, hoverStep)            hoverStep = 12%
  z(k)       = k * zStep                                          zStep = 10
  chrome variant: alphaChrome(k) = alpha(k) * glassChromeAlphaFactor   factor = 0.5
  veil: veilAlpha = alpha(4) - glassAlphaStep = 0.40; veilBlur = glassBlurStep (one step)
Knobs live in ui/styling/tokens.json under a new "levels" block; ui.css and the generator both
read from the SAME knobs (CSS via custom properties, Rust/TS via generated constants — CSS
custom properties cannot be recomputed per-descendant, so each of the six [data-level="..."]
blocks redeclares the derived properties with its literal k; this is still 100% formula-derived,
just unrolled six times).

Exactly 4 generic fill utilities replace ALL bg-base/canvas/window/panel/overlay/temporary
surface fills and ALL 5 ui-glass-* classes:
  ui-surface       -> background-color: var(--surface-bg)
  ui-glass         -> color-mix(in srgb, var(--surface-bg) calc(var(--surface-alpha)*100%), transparent)
                       + backdrop-filter: blur(var(--surface-blur)) saturate(var(--glass-saturate))
  ui-glass-chrome  -> same as ui-glass but alpha * glassChromeAlphaFactor
  ui-veil          -> fullscreen scrim; alpha/blur are the dedicated veil values; host element
                       must carry data-level="dialog" for correct tint

Portaled surfaces (popover/select/tooltip/menu/dialog content) MUST stamp data-level on their
OWN content root (not rely on an ancestor), since Radix portals to document.body.

The chrome-gap backdrop-filter:none !important suppression (window-chrome-gap etc.) stays
untouched — it already beats ui-glass/ui-glass-chrome via specificity+!important.

Rule for nested same-level surfaces: exactly one ui-surface/ui-glass per level root; interior
containers stay bg-transparent (existing WindowChrome convention) to avoid double-tinting.
