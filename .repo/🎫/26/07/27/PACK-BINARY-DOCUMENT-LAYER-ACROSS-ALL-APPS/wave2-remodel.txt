WHAT COULD NOT BE COMPLETED, AND WHY
---------------------------------------
`tests::populated_scene_roundtrips_through_dsl`'s new `assert_dsl_pack_equivalence` call fails on a
genuine pack/** infra bug, entirely outside remodel/**'s allowed scope to fix:

  `pack/value/rs/lib.rs`'s `decode_table_soa` fallback arm (~line 1115, for any table column whose
  `Shape` isn't one of the fast-path scalar kinds — i.e. `Tuple`/`List`/`Record`/`Block`/`Map`/etc.)
  calls `decode_value(reader, None, ctx, depth + 1)` — it drops the column's `Shape`. Its encode
  counterpart, `encode_table`'s fallback arm (~line 1029), correctly passes `Some(&field.shape)`. A
  homogeneous-numeric `Shape::Tuple` column (e.g. `[f32; 5]`) gets encode-side packed as
  `TAG_PACKED_F64` (tag alone doesn't distinguish Tuple vs List — that's resolved from `shape` at
  decode time), so losing `shape` at decode makes it come back as `FieldValue::List` instead of
  `FieldValue::Tuple`, which then fails `[T; N]`'s strict `DslField::from_value` match.
  `CalibrationState.cameras: Vec<CameraCalibration>` is a `#[dsl(table)]` field and
  `CameraCalibration.distortion: [f32; 5]` — `populated_scene_fixture()` (the shared, pre-existing DSL
  round-trip fixture I was told to reuse rather than dodge) sets a non-default distortion, which
  reproduces this exactly:
      pack decode failed: schema error: expected a 5-item Tuple, found
      List([Float(0.00999...), Float(-0.01999...), Float(0.0), Float(0.0), Float(0.0)]) at 1:1
  `default_scene_roundtrips_through_dsl` passes (empty tables, never hits the bug).
  `store_roundtrips_through_document_text`'s new pack-law call passes (its fixture only mutates a
  scalar block field, no table/tuple column touched).

  This is a one-line fix (mirror encode_table's `Some(&field.shape)`) but requires editing
  pack/value/rs/lib.rs, which is explicitly out of this family's allowed directories. Documented in
  full (root cause, fix, blast-radius across other `#[dsl(table)]` fields in this same file:
  RigExtrinsic, GroundControlPoint, CameraPosePreview) in
  .repo/🎫/26/07/27/PACK-BINARY-DOCUMENT-LAYER-ACROSS-ALL-APPS/wave2-remodel-pack-table-tuple-bug.txt,
  and flagged via spawn_task (task_e3a52284, "Fix pack decode_table_soa dropping shape for tuple table
  columns") for a session with pack/** access to pick up. A related/possibly-overlapping task
  (task_2decfb30, "Fix pack decode_table_soa losing nested RecordSpec for Option fields") was already
  pending from another concurrent wave-2 session when I flagged mine — same function, likely the same
  root asymmetry surfacing through a different field shape; left both in place as independent repro
  evidence rather than dismissing either.
