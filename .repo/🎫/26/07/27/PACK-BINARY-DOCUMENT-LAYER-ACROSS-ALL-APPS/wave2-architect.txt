3. BLOCKED: CONFIRMED UPSTREAM `pack` CRATE BUG (NOT an architect defect)
--------------------------------------------------------------------------------
Test added: `program::tests::sample_program_dsl_pack_equivalence` in
architect/program/rs/lib.rs, marked `#[ignore = "..."]` with a full explanation inline
(also spawned as a background task — title "Fix pack decode_table_soa losing nested
RecordSpec for Option fields", task_id task_2decfb30).

Repro: `vcs::test_support::assert_dsl_pack_equivalence(&sample_program())` panics with
  "pack decode failed: schema error: missing field 'description' at 1:1"

Root cause (confirmed by reading pack/value/rs/lib.rs, not guessed):
`Program.stakeholders: Vec<Stakeholder>` is `#[dsl(table)]`. `Stakeholder.header:
EntityHeader` is a plain nested `#[derive(dsl::DslRecord)]` field (not `Option`, not
`#[dsl(table)]`). `EntityHeader.description: Option<TextField>` is `None` in the sample
fixture. `pack::value::decode_table_soa` (the `TableSoA` columnar table decoder) is
deliberately spec-free/self-describing per its own doc comment ("no RecordSpec is ever
required to reconstruct the rows"); for a non-primitive column (like the nested-Record
"header" column) its fallback branch calls `decode_value(reader, None, ctx, depth + 1)`
— passing `shape: None`. Inside `decode_value`'s `TAG_RECORD` arm this makes
`record_spec_of(shape)` resolve to `None`, so the nested `decode_record_fields(reader,
None, ..)` skips its own end-of-function "backfill every spec field not seen on the wire
as `Absent`" loop (gated on `spec` being `Some`). Meanwhile `encode_table`'s symmetric
fallback branch correctly omits the `Absent` `description` sub-field from the wire
(canonical-mode compaction, by design). Net effect: the omitted field is never
backfilled on decode, so `dsl_derive`'s generated `from_record` (`record.get(id)
.ok_or_else(missing field)`) errors out.

This will reproduce for ANY `#[dsl(table)]` field whose row type has a nested
(non-Option) record field that itself has an `Option<T>` sub-field left at `None` —
a common, idiomatic pattern, not architect-specific misuse. Full write-up with exact
line numbers and two candidate fixes is in the spawned task prompt (task_2decfb30).

I did NOT attempt a workaround inside architect/** (e.g. dropping the `Option` wrapper
on `EntityHeader.description`) since that would mask a real `pack` crate defect rather
than fix it at the root, and `pack/**`/`dsl/**` are explicitly out of my family's scope
— flagged for a separate session instead.
