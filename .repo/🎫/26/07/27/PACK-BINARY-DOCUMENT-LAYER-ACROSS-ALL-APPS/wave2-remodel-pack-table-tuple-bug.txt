BLOCKING BUG FOUND IN pack/value/rs/lib.rs — decode_table_soa loses field shape in its
fallback (ELEM_FALLBACK) column branch, breaking any fixed-size-array (`Shape::Tuple`) column
nested inside a `#[dsl(table)]` row. Confirmed via remodel_document's
`populated_scene_roundtrips_through_dsl` test (CalibrationState.cameras: Vec<CameraCalibration>
is `#[dsl(table)]`, CameraCalibration.distortion: [f32; 5]):

    thread 'tests::populated_scene_roundtrips_through_dsl' panicked at vcs/rs/lib.rs:3406:89:
    pack decode failed: schema error: expected a 5-item Tuple, found List([Float(...), ...]) at 1:1

ROOT CAUSE (both in pack/value/rs/lib.rs):
  encode_table's fallback branch (~line 1029, inside the `_ =>` arm of the `match elem_tag`
  block) correctly threads the column's real shape through:
      encode_value(ctx, Some(&field.shape), v, depth + 1, out)?;
  For a homogeneous-numeric Tuple column (e.g. `[f32; 5]`) this makes encode_seq's packed-numeric
  fast path fire and write TAG_PACKED_F64/TAG_PACKED_VARINT — a tag that is silent about
  Tuple-vs-List, deferring that distinction entirely to the shape passed at decode time (see
  decode_packed_f64_body/decode_packed_varint_body's `is_tuple: bool` param, itself derived from
  `is_tuple_shape(shape)`).

  decode_table_soa's matching fallback branch (~line 1115) does NOT thread the shape through —
  it hardcodes `None`:
      let v = decode_value(reader, None, ctx, depth + 1)?;
  So `is_tuple_shape(None)` is always false for any table column that isn't one of
  ELEM_{BOOL,INT,UINT,F64,STR,ENUM} (i.e. any Tuple/List/Record/Block/Map/Value/Wire/nested-Table
  column), and a homogeneous-numeric Tuple column round-trips back as a List instead, which then
  fails `[T; N]`'s `DslField::from_value` (dsl/rs/lib.rs's `impl<T, const N: usize> DslField for
  [T; N]`, which requires `FieldValue::Tuple` exactly).

  FIX (for whoever owns pack/**, forbidden to me — my family is remodel/** only): change
  decode_table_soa's fallback arm to pass `Some(&field.shape)` instead of `None`, mirroring
  encode_table's fallback arm exactly (`field` is already in scope in that loop). This is a
  one-line fix, same shape as the code right next to it.

  COVERAGE GAP CONFIRMING THIS IS UNCAUGHT, NOT JUST MISCONFIGURED: pack/value/rs/lib.rs's own
  test module (`mod tests`) has a `full_record()`/`full_spec()` fixture that DOES round-trip a
  top-level `Shape::Tuple` field (id 8, "tuple_field") and a `Shape::Table` field (id 15,
  "table_field") — but `table_row_spec()` (the row shape used for the Table field) only has
  Bool/UInt/Text/Float scalar columns, never a Tuple (or List/Record/Block/Map) column. So the
  `encode_table`/`decode_table_soa` ELEM_FALLBACK path — the one with this asymmetry — is never
  exercised by pack's own suite. This will affect EVERY document kind, in every wave-2 family,
  that has any fixed-size array (`[T; N]`) field as a column inside a `#[dsl(table)]` collection
  — not just remodel. remodel_document hits it via CameraCalibration.distortion: [f32; 5] and
  RigExtrinsic.{rotation_wxyz: [f32;4], translation_m: [f32;3]} inside CalibrationState's two
  `#[dsl(table)]` fields, GroundControlPoint.world_position: [f64;3] inside `#[dsl(table)] gcps`,
  and CameraPosePreview.{rotation_wxyz,translation}: [f32;4]/[f32;3] inside two other
  `#[dsl(table)]` fields (job.camera_poses_preview, results.trajectory.poses) — any one of these
  being non-default/non-identity in a pack round trip would reproduce it.
