4. SPECIAL EXTRA SCOPE (B) — StudioApp::handle_action wiring
--------------------------------------------------------------------------------
Added to s/plugin/rs/lib.rs, mod app_studio, StudioApp::handle_action, mirroring exportMedia/
importMedia/importMediaPayload's shape exactly:
  - "exportStudioPack": resolves the current studio's OsDocument via
    `super::app_home::resolve_studio_document(&runtime_studio_id(&self.runtime))`, calls
    `export_os_studio_pack`, pushes two HostEffect::DownloadMediaExport (base64 `.pack`, plain-text
    `.ops`).
  - "exportStudioDsl": same document resolution, calls `export_os_studio_dsl`, pushes one plain-text
    HostEffect::DownloadMediaExport (`.os`).
  - "importStudioPack": returns HostEffect::RequestFileOpen { accept: ".pack", read_as: Some("dataUrl"),
    import_action: "importStudioPackPayload", multiple: false }.
  - "importStudioPackPayload": strips the data-URL prefix, base64-decodes, calls
    `import_os_studio_from_pack(&bytes, "", super::app_home::catalog_port())`. Ops is passed as "" —
    a single `.pack` file carries no separate ops sidecar (unlike exportStudioPack's two-file output),
    so the import yields the document's bare initial projection with no replayed edit history, exactly
    like the pre-existing JSON `importStudio` action's semantics.

Supporting edits (same file):
  - `export_os_studio_dsl`/`export_os_studio_pack`/`import_os_studio_from_pack` are NOT in
    framework/product/os/core/rs/lib.rs's crate-root `pub use host::{...}` re-export list (that file's
    non-test code is out of this family's scope, so I could not add them there). Reached instead via
    `use semio_framework_os::host::{export_os_studio_dsl, export_os_studio_pack,
    import_os_studio_from_pack};` — `pub mod host` makes every `pub fn` inside it reachable this way
    regardless of the root re-export list. Flagging for wave 3 / os-core's owner: adding these three to
    the `pub use host::{...}` list would be the cleaner long-term fix.
  - `app_home::catalog_port()` changed from private to `pub(crate)` so `app_studio`'s
    importStudioPackPayload arm can obtain a backbone port (mirrors `resolve_studio_document`'s
    existing `pub(crate)` visibility for the same cross-module reason).
  - 4 new action-id labels added to `s_studio_action_labels` (en/de) and 4 new
    `.shell_action(...)`/`.action_with(...)` registrations added to `create_studio_app()`'s builder
    chain, alongside exportMedia/importMedia/importMediaPayload's — exportStudioPack, exportStudioDsl,
    importStudioPack, importStudioPackPayload. Left unscoped (not added to any `window_kind_actions`
    list), like openStudio/goHome — these operate on the whole studio document, not a windowed
    selection.
