5. CARGO TEST STATUS — NOT FULLY GREEN, BLOCKED ON A CONFIRMED UPSTREAM PACK BUG
--------------------------------------------------------------------------------
`cargo test -p layout_rs`: 34 passed, 2 FAILED (both newly-added-assertion failures, not pre-existing):
  - dsl::tests::dsl_round_trips_sample_fixture
  - dsl::tests::document_text_round_trips_a_store_with_applied_operations

Both fail identically:
  "pack decode failed: schema error: missing field 'character-style-id' at 1:1"

ROOT CAUSE (isolated and confirmed, not guessed): `TextStyleRun.character_style_id: Option<String>`
is `None` in the real sample fixture's one story style-run (`layout/example/sample.layout` line 85:
`[ start=0 end=120 paragraph-style-id=paragraph.body ]` — `character-style-id` simply omitted, which
is valid, working DSL-text syntax for "None"). `TextStyleRun` is not itself `#[dsl(table)]`; it only
appears as `TextStory.style_runs: Vec<TextStyleRun>`, which itself is a LIST-typed column *inside*
`TextStory`'s own `#[dsl(table)] pub stories: Vec<TextStory>` row (visible in the fixture's table
header: `stories [id:TEXT content:TEXT style-runs:LIST] { ... }`).

Isolated via a temporary diagnostic test (added, verified, then removed — not left in the tree):
setting `doc.stories[0].style_runs[0].character_style_id = Some("char.emph".into())` on the exact
same sample-fixture-derived document makes `assert_dsl_pack_equivalence` PASS. So: DSL-text round trip
of a `None` optional field nested inside a list-of-records table column works fine (pre-existing,
unaffected by wave 1/2); the PACK binary decode path does not — it fails to reconstruct a
`FieldValue::Absent` entry for that field key when decoding this specific
"list-of-record column nested inside a table row" shape, so `dsl_derive`'s generated
`record.get(#id).ok_or_else(|| missing field ...)` (dsl/derive/rs/lib.rs ~line 444) finds no map entry
at all instead of an `Absent` one.

This is a genuine bug in the shared `pack`/`dsl` stack's handling of optional fields inside nested
list-of-record table columns, not something fixable inside `layout/**` without either (a) changing
`TextStyleRun`/`TextStory`'s `#[dsl(...)]` shape (which would change the wire format and risk breaking
`layout/example/sample.layout`'s existing text, explicitly out of scope — "fixture stays as-is"), or
(b) touching `dsl/**`/`pack/**` (explicitly forbidden for this family). Left as-is, correctly reported
here for wave 3 / a follow-up ticket against `pack/rs` (or wherever `decode_document` reconstructs
`RecordValue` from binary for `FieldKind::Statements`/list-of-record shapes) rather than silently
weakened or reverted.
