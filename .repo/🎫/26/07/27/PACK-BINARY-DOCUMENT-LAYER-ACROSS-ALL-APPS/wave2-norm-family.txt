4. TWO CONFIRMED UPSTREAM `pack` BUGS HIT (OUT OF SCOPE — `pack/**` not touched)
--------------------------------------------------------------------------------
Both are the SAME root-cause class already independently discovered and documented by other wave-2
families this session (confirmed via `grep -rn "missing field"`/reading their reports before touching
anything) — `pack/value/rs/lib.rs`'s `decode_table_soa` (`Shape::Table` SoA decoder) drops the row
column's `Shape` in its fallback branch (passes `None` where `encode_table`'s matching branch passes
`Some(&field.shape)`), so any `#[dsl(table)]` column whose element type isn't a plain primitive
decodes wrong:

  a) `norm_iso_16757` — `Names.short_name: Option<String>` (a nested-`Record` field) inside several
     `#[dsl(table)]` catalogue row types (`ProductGroup`/`ProductClass`/`Product`/`Subject`, all embed
     `names: Names`) — decode can't backfill the `None` sub-field as `Absent` without the real shape:
       "pack decode failed: schema error: missing field 'short-name' at 1:1"
     Same variant `architect/program/rs/lib.rs`'s `Stakeholder.header.description: Option<TextField>`
     hit (see its `sample_program_dsl_pack_equivalence`, `#[ignore]`d there too, and
     wave2-architect.txt).

  b) `norm_vdi_3805` — `ConnectionPoint.position`/`direction: [f64; 3]` (fixed-size-array fields)
     inside `ParametricGeometry`'s `#[dsl(table)] connections: Vec<ConnectionPoint>` — decodes back as
     `FieldValue::List` instead of the required `FieldValue::Tuple`:
       "pack decode failed: schema error: expected a 3-item Tuple, found List([Float(0.0), Float(0.1),
       Float(0.05)]) at 1:1"
     Exact match to the bug root-caused (with a suggested one-line fix in `pack/value/rs/lib.rs`) by the
     `draw` wave-2 family — see `wave2-draw.txt` §4.

Not fixed here: `pack/**` is outside this family's allowed directories. Both are cleanly isolated via
`#[ignore]`'d tests with comments pointing back to `wave2-draw.txt` §4 / `wave2-architect.txt` and this
file, ready to un-ignore once the shared `pack/value/rs/lib.rs` fix lands.
