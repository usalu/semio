//#region 🔖Source
- `RetryPolicy { max_retries: u32, initial_backoff: Duration, max_backoff: Duration }` with
  `Default` (3 retries, 50ms initial, 2s cap) — additive vs. the contract sketch ("retry policy"
  was named but left unspecified in the struct comment), exposed via `with_retry_policy` so
  callers/tests can tune it.
- `HttpPackSource<T: RangeTransport>` does NOT hold the transport/url directly. Per the
  contract's explicit note "coalesces via an internal pack_async::ReadScheduler", it instead
  wraps `pack_async::ReadScheduler<InnerSource<T>>`, where `InnerSource<T>` (private) owns
  `url`/`transport`/`retry_policy` and is itself the thing that implements
  `pack_async::AsyncPackSource` and performs the retrying, etag-revalidating physical fetch in
  its `read_at`. `HttpPackSource::read_at` builds a `pack_async::ReadRequest` (priority
  `Requested`) and a throwaway `pack_async::CancellationToken`, then delegates to
  `self.scheduler.read(...)` — this is what gives `HttpPackSource` request coalescing/dedup for
  free from `pack_async`'s `ReadScheduler` rather than reimplementing it.
- Problem this raised: `pack_async::ReadScheduler` has no accessor back to its wrapped source
  (fields are private, no getter), but `AsyncPackSource::len()` must be answerable synchronously
  from `HttpPackSource` itself. Fixed with a `SharedState { last_etag: Mutex<Option<String>>,
  known_len: AtomicU64 }` behind an `Arc`, held by both `HttpPackSource` (for `len()`) and
  `InnerSource` (which is the only thing that ever writes into it, from observed
  `RangeResponse.etag`/`total_len`). `LEN_UNKNOWN = u64::MAX` sentinel since `AtomicU64` has no
  `Option`.
- Retry/backoff: `InnerSource::fetch_with_retry` treats any `PackError::Io(_)` returned by the
  transport as transient (that's the only variant a transport failure can plausibly map to in
  the contract-fixed `PackError` enum — no dedicated `Transient`/`Network` variant exists) and
  retries up to `retry_policy.max_retries` times with exponentially doubling backoff
  (`initial_backoff * 2^attempt`, capped at `max_backoff`), via a small hand-rolled
  runtime-neutral `sleep()` future (busy-poll + short thread sleep between polls, same pattern
  `pack_async`'s own `CancelWatch` uses — no tokio, no new async-runtime dependency).
- Etag revalidation: every fetch reads the last-seen etag from `SharedState` and forwards it as
  `if_range_etag` on the *next* request; every response's `etag` (if present) overwrites
  `SharedState.last_etag` for the one after that.
- `read_at` truncates/validates: if the transport returns fewer bytes than requested, returns
  `PackError::Truncated`; otherwise slices to exactly `len` bytes (defensive even though
  `RangeResponse.range_satisfied` is available for callers who want stricter Range-header
  compliance checks — that flag is threaded through untouched for now, no caller in this crate
  currently branches on it beyond what `fetch_with_retry`/`read_at` need).

//#region 🔖Cache
- `ChunkLruCache::new(capacity_bytes) / get(&ContentHash) -> Option<Vec<u8>> / put(ContentHash,
  Vec<u8>)` matching the contract signatures exactly, plus additive `size_bytes()`/`len()`/
  `is_empty()` for tests and callers who want introspection.
- Implementation: `HashMap<ContentHash, usize>` index into a `Vec<Option<LruSlot>>` arena, with
  each `LruSlot` carrying manual `prev`/`next` `usize` links (a hand-rolled intrusive doubly-
  linked list, `NONE = usize::MAX` sentinel) for O(1) recency reordering on `get`/`put` and O(1)
  LRU eviction from the tail. Vacated arena slots are recycled via a `free: Vec<usize>` stack so
  repeated churn doesn't grow the arena unbounded. No external `lru` crate, no `unsafe`. The
  whole mutable state (`LruState`) sits behind one `Mutex` so the public API can take `&self`
  (matching the contract's `get`/`put` signatures) while still supporting concurrent callers.
  Eviction on `put` loops until `size_bytes <= capacity_bytes`, but always keeps at least the
  just-inserted/updated entry (never evicts down to zero even for an entry larger than the whole
  capacity) — `put` is infallible, matching its signature.

//#region 🔖Ureq (feature `ureq`, off by default)
- `UreqRangeTransport` wraps a `ureq::Agent`, implements `RangeTransport`. `fetch_range` runs the
  blocking `ureq` call (`Range`/`If-Range` headers set from the request) on a dedicated
  `std::thread::spawn` so the `async fn` itself never blocks a caller's executor thread; parses
  `ETag` and `Content-Range: bytes start-end/total` response headers for `etag`/`total_len`,
  treats HTTP 206 as `range_satisfied: true`.
- `[features] ureq = ["dep:ureq"]`, off by default — confirmed the crate's default-feature build
  never pulls in `ureq` (grep of the default `cargo tree -p pack_http` / the earlier successful
  `cargo test -p pack_http` without `--features ureq` shows no `ureq`/`rustls`/`ring` in the
  compiled set).

Cross-crate notes for downstream agents:
- `HttpPackSource<T>` no longer exposes its `RangeTransport` or URL after construction (they're
  owned by the private `InnerSource<T>` living inside its internal `ReadScheduler`). Anything
  that needs to inspect transport-level state after construction should keep its own handle to
  the transport before handing it to `HttpPackSource::new`/`with_retry_policy` (see the
  `FakeTransport`/`inspector` pattern in the tests above).
- `ChunkLruCache` is keyed by `pack_core::ContentHash` only (not `(url, range)` as the contract's
  comment mentions as an alternative) — this matches the concrete `get`/`put` signatures the
  contract fixes (`&ContentHash` / `ContentHash`), so `(url, range)`-keying would require a
  different public API than what's specified; callers needing that keying scheme can hash
  `(url, range)` themselves into a `ContentHash`-shaped key before calling `put`/`get`.
- `PackError::Io(_)` is pack_http's convention for "the transport failure was transient, retry
  it" — any `RangeTransport` impl that wants a permanent failure to NOT be retried should return
  a different `PackError` variant (e.g. `Malformed`/`LimitExceeded`) instead of `Io`.
