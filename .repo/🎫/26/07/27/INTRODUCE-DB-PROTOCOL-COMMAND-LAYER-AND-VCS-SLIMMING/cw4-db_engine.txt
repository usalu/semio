cw4-db_engine — Database supervisor + catalog actor
=====================================================

Scope
-----
Replaced the stub /Users/ueli/Documents/semio/db/engine/rs/lib.rs with a real implementation of
the frozen Database/DocumentHandle API, composing the guaranteed-complete db_state/db_wal/
db_storage/db_document crates against db_document's real, current public API.

Implemented (all real, tested against real behaviour, no mocks in the production code path):

- Database::open(config, storage) / Database::open_at(root, profile) — the frozen zero-touch entry
  point over db_storage::FsStorage. Also added two additive (non-breaking) constructors:
  Database::open_with_authz (swap in a custom db_document::AuthzHook, e.g. SecurityAuthzHook) and
  Database::open_with_emit (swap in a custom db_core::Emit sink). Catalog root is persisted via
  db_storage::CatalogStorage::cas_root (EpochFence-fenced JSON array of documents), decoded back on
  reopen.
- Database::create_document / Database::document — mint or recover a document's real
  db_document::DocumentAuthority (a dedicated OS thread running db_document::DocumentEngine),
  registered in an in-process catalog + open-document cache guarded by plain Mutexes (see the
  in-file design-choice comment on why this crate does NOT wrap the catalog in its own
  db_actor::Actor — Database's own surface is already synchronous per the frozen contract, and
  per-document concurrency is already provided by each DocumentAuthority's own thread).
- Database::catalog / Database::health / Database::shutdown — frozen signatures. health() wraps a
  real db_observe::HealthRegistry snapshot. shutdown() gracefully joins every DocumentAuthority this
  Database still exclusively owns (Arc::try_unwrap; a document whose handle is still cloned
  elsewhere is skipped rather than yanking a live mailbox out from under a caller — documented
  extension seam, since DocumentAuthority::shutdown() has no timeout parameter to honor `deadline`
  against, and adding one is out of this crate's file ownership).
- DocumentHandle::submit -> SubmitFuture — real: bridges DocumentAuthority's blocking
  submit_blocking onto a genuine (not immediately-ready) Future via a dedicated bridge thread +
  db_actor::oneshot, the same spawn_blocking-over-a-channel pattern tokio/pack_async use for an
  identical blocking-API-under-a-future-facade problem (DocumentAuthority's only public submit
  entry point is blocking; its private Address field isn't reachable from db_engine to build a true
  non-blocking AskFuture without editing db_document, out of this wave's file ownership).
- DocumentHandle::query -> QueryStream — real for Consistency::Canonical/AtLeast/Exact (AtLeast/
  Exact read canonical then verify the resulting frontier actually satisfies the request, erroring
  Unavailable otherwise — a true wait-for-frontier primitive would need a new DocumentMessage
  variant). Historical/Speculative/PreviewAugmented return DbError::Unimplemented (documented
  below).
- DocumentHandle::frontier -> Frontier — real, direct DocumentAuthority::frontier_blocking.
- DocumentHandle::history -> HistoryView — real: replays the document's ENTIRE WAL directly via
  db_wal::replay_document (a crate db_engine already depends on) and groups WAL_COMMAND records by
  the WAL_FRONTIER record that closes their transaction. Deliberately does NOT go through the actor
  mailbox: db_document::DocumentEngine's in-memory commit_log is only populated by live submit()
  calls in the current process, NOT reconstructed by open()'s replay, so going through the actor
  would silently miss history from before the current process started.
- Database::compact_document -> db_compact::CompactionReport — real db_compact::Compactor pass
  (WAL retention below the latest snapshot floor, ref-traced payload GC, index compaction, optional
  snapshot consolidation), document-at-a-time (no background scheduler this wave).
- Database::hello -> db_sync::WelcomeResponse — real db_sync::handle_hello call, the server-side
  half of the wire-v2 handshake (frontier exchange / bootstrap-plan decision). No transport of its
  own (framework/sync + hub rebuilds are CW5/CW6's job).
- Database::checkpoint_document + the `vcs` feature's VcsVersionGraph (db_engine::vcs_integration,
  default-on, the ONLY db crate allowed to depend on `vcs` per the hard dependency rule) — real:
  drives an actual vcs::DocumentVcsStore<HashProjection, HashOperation> per document via real
  Apply/CommitCheckpoint dispatches. HashProjection/HashOperation/HashDiff are a small, genuinely
  correct, schema-erased concrete Operation<P> impl (real inverse via `backwards`, real DocumentDsl
  round-trip via hex encode/decode) built specifically to drive vcs's generic store with exactly
  what db_core::VersionGraph's own already-schema-erased seam carries (a pack_core::ContentHash,
  never document semantics) — mirrors db_document's own schema-erased-JSON convention one layer up.
  Verified against vcs's REAL content-addressed checkpoint id scheme (`ck-<hex16>`, already
  implemented in the current vcs/rs/lib.rs) via a passing test asserting two distinct commits mint
  two distinct "ck-"-prefixed ids.
- SecurityAuthzHook — a real db_document::AuthzHook built on db_security::SecurityGate/Principal/
  AuthzScope/Action (resolves the submitting actor to a Principal via an injected closure, then
  authorizes Action::Write on AuthzScope::Document). Not wired as the default (default stays
  db_document::AllowAll, matching db_document's own single-tenant default) — opt in via
  Database::open_with_authz. Tested directly (default-deny policy correctly rejects).

Deliberately deferred (documented in the module doc, NOT faked, NOT panicking — every deferred path
returns a real DbError::Unimplemented with an explanation, per the wave's "extension seam" allowance):

- DocumentHandle::subscribe / DocumentHandle::preview — both always return DbError::Unimplemented.
  Root cause: db_document::DocumentAuthority's mailbox (the DocumentMessage enum) only carries
  Submit/Query/Frontier/RunQuery/SnapshotNow/DrainOutbox variants — there is no Preview/Subscribe
  message to drive DocumentEngine's preview/live-query machinery through the actor boundary without
  adding one inside db_document itself, out of db_engine's file ownership this wave.
- DocumentHandle::snapshot_now -> SnapshotFuture — always resolves to DbError::Unimplemented.
  db_snapshot is not a direct dependency of db_engine per its Cargo.toml, and db_document's own
  DocumentState materializes purely from the WAL suffix with no full-state enumeration this crate
  can serialize into a real pack snapshot without db_document growing that capability on a stable,
  coordinated API first (see "Concurrent churn" section below for why this stayed deferred despite
  db_document briefly exposing a real snapshot_now_blocking mid-wave).
- db_cluster integration — none at all. db/cluster/rs/lib.rs is STILL the unmodified 6-line
  scaffold stub from CW1 (declares zero public items) as of this wave; nothing in db_engine can call
  into it. Every cluster-shaped concern (sharding, ownership leases, quorum durability, split-brain
  repair) is entirely absent from this crate, matching the instructions' allowance for a lighter
  cluster surface.
- Consistency::Historical / Consistency::Speculative / Consistency::PreviewAugmented query modes —
  DbError::Unimplemented (db_query/db_projection integration and the preview mailbox gap above).

Deviations from the contract / design choices made where the contract said "your choice" or left a
gap (each documented inline with a `// 🎯 Design choice` comment at its exact decision point):
- Query/QueryStream/HistoryView/HistoryEntry/LiveQuerySpec/LiveQuery/PreviewHandle/SnapshotKind/
  SnapshotReceipt/DocumentSpec/CatalogView/CatalogEntry/DbHealth shapes are this crate's own choice
  (the contract fixes Database/DocumentHandle's method SIGNATURES, not these payload types' shapes).
- SubmitFuture/SnapshotFuture are type aliases to db_actor::ReplyReceiver<Result<T, DbError>>
  (double-Result: the outer Result is the oneshot channel's own closed/ok signal, the inner is the
  actual operation's outcome) rather than a hand-rolled Future type, reusing db_actor's existing,
  already-tested oneshot machinery instead of inventing a second one.
- Database's catalog registry is a plain Mutex<HashMap<...>>, not a db_actor::Actor-driven process
  — see the in-file design-choice comment; Database's own public surface is already synchronous per
  the frozen contract.
- checkpoint_document does not thread CheckpointRequest.parent_checkpoint/change_ids/timestamp_ms
  through to vcs — vcs::DocumentVcsCommand::CommitCheckpoint always folds every edit applied since
  the store's OWN current checkpoint (the only value that could ever be consistent with the real
  vcs history it maintains internally) and stamps its own timestamp as part of what its
  content-addressed id hashes over; overriding either would require reaching into vcs's private
  state. Documented inline at the exact call site.
- document_engine_config() builds db_document::DocumentEngineConfig with its 4 originally-observed
  fields (limits/authz/version_graph/preview_ttl_ms) explicit and `..DocumentEngineConfig::default()`
  spread for the rest, so this call site stays correct across db_document's own additive field
  growth (security/emit/projections) without needing a coordinated re-edit every time.

Cargo.toml additions (genuinely missing, noted per the wave's instructions):
- pack_core = { path = "../../../pack/core/rs" } — the frozen CommandReceipt.state_hash field is
  typed pack_core::ContentHash verbatim in the contract; this crate names that path directly.
- serde = { version = "1", features = ["derive"] } — this crate's catalog root encoding and the
  vcs feature's HashProjection/HashOperation/HashDiff types need derive(Serialize, Deserialize)
  directly (serde_json alone is not enough for #[derive(...)]).
- serde_json = "1" — catalog root JSON encode/decode, and test fixtures.

Testing
-------
12 inline unit/integration tests in a trailing //#region 🧪Tests block (mod tests, plain #[test]
fns — no quick/long/exhaustive tiers needed, nothing here is crash-harness-shaped), covering the
actual laws this crate exists for, not smoke tests:
- open_at zero-touch fresh database has an empty catalog and reports Healthy.
- create_document registers in the catalog; document() finds it; double-create errs AlreadyExists;
  document() on an unknown id errs NotFound.
- full_submit_durable_query_round_trip_over_a_real_document_authority — THE flagship integration
  test requested: Database::open_at -> create_document -> submit (Fsync durability, through the
  real bridge-thread SubmitFuture) -> assert CommandReceipt shape -> query(Canonical) reads the
  committed value back -> frontier() matches -> AtLeast(frontier) succeeds -> history() reconstructs
  the same operation id from a fresh WAL replay.
- a_document_survives_a_full_database_shutdown_and_reopen_at_the_same_root — submits a durable
  command, shuts the Database down (joining the real actor thread), reopens Database::open_at at
  the SAME root, confirms the catalog root and the document's committed state both survived via
  real WAL replay (db_document::DocumentEngine::open's recovery path), not an in-memory artifact.
- exact_consistency_rejects_a_frontier_the_document_has_moved_past — Consistency::Exact correctly
  errs Unavailable once the document has advanced past the requested frontier.
- subscribe_preview_and_snapshot_now_are_documented_unimplemented_not_panics — asserts the deferred
  paths return DbError::Unimplemented, never panic.
- checkpoint_document_mints_distinct_real_vcs_content_addressed_checkpoint_ids (vcs feature, the
  default) — two real commits produce two distinct "ck-"-prefixed vcs checkpoint ids.
- compact_document_runs_a_real_compaction_pass_without_error — a real db_compact::Compactor pass
  over a committed document succeeds.
- hello_returns_a_welcome_with_a_fresh_bootstrap_for_a_brand_new_replica — a real db_sync::handle_hello
  call returns a protocol::ServerFrame::Welcome.
- security_authz_hook_rejects_a_principal_denied_by_its_policy — a real db_security::SecurityGate
  with an empty (default-deny) policy correctly rejects via SecurityAuthzHook.
(A `#[cfg(not(feature = "vcs"))]` variant of the checkpoint test also exists for the non-default
build, exercised via `cargo test -p db_engine --no-default-features` separately from the 12 above.)

majority of this wave's runtime — growing from the 1082 lines read at authoring time to 1400-1500+

ConflictRecord>`, single-field `SubmitOptions{durability}`) is verified against the ACTUAL, final
content of db/document/rs/lib.rs at close — confirmed via two independent, back-to-back full
`cargo build -p db_engine` + `cargo test -p db_engine` runs immediately before this report was
