4) bun ./script.ts policy — the 3 new CW8 policy lints + regression check
-----------------------------------------------------------------------------------------------
FINDING + FIX (real issue caught and repaired during this wave, not just observed):

First `bun ./script.ts policy` run: exit 1, 43 total breaches, including 11
`dsl-migration/completeness` breaches newly flagging DocumentApp::Operation types (PresentOperation,
ProgramOperation, FlowOperation, GisMapOperation, ImperativeOperation, MathOperation,
Procedural2dOperation, Procedural3dOperation, OsOperation, SequenceOperation, ShootingOperation)
as missing an OpText impl. Root cause: `POLICY_HAND_ROLLED_IMPL_RE` in script.ts (an UNRELATED,
older policy — the "Wave 4 V1 duplication audit" DSL-completeness rule) only recognized
`impl (vcs::)?OpText for X` — CW7's own import-path sweep rewrote every hand-rolled
`impl vcs::OpText for X` to `impl protocol::OpText for X` (OpText moved from vcs to protocol per
this campaign's own design), which the regex's `(?:vcs::)?` prefix never accounted for. Confirmed
by grepping the repo for `impl protocol::OpText for` — all 11 flagged type names' real impls came
back with the `protocol::` prefix exactly. This was a genuine regression introduced by this
campaign's own CW7 sweep against an older, unrelated lint that nobody had updated for the new
prefix (CW8's own verification log recorded "43 total breaches, unchanged" without noticing the
KIND composition had shifted — the pre-existing baseline plus this new false-positive class
happened to still sum to 43).

FIX APPLIED (script.ts, `POLICY_HAND_ROLLED_IMPL_RE`, ~line 2176): widened the optional prefix
from `(?:vcs::)?` to `(?:vcs::|protocol::)?` on both the trait-name and type-name capture groups.
`DocumentDsl` stays vcs-owned in practice (never moved to protocol per this campaign's design;
allowing the `protocol::` alternative there too is harmless since no such impl exists anywhere in
the repo — verified by grep).

Re-run after fix: exit 1 still (32 remaining breaches — see below), but 0 of the 11
`dsl-migration/completeness` false positives remain.

Per-lint results after the fix:
  - policyProtocolMigrationBreaches: 0 breaches (vcs's temporary CW3 shim stays gone; nothing
    resolves Operation/OpText/OperationDiff/etc. through `vcs::` again).

  - policyCommandEnvelopeCompletenessBreaches: 0 breaches AS A LINT RESULT, backed by a

    ALLOWLIST`, ~55 files) tracking technologies that prove the pack round-trip law but not yet

Other loose ends explicitly flagged in wave reports
-----------------------------------------------------------------------------------------------
- protocol_cli's `verify`/`repair` don't distinctly surface "recovered but silently shorter than
  the file on disk" vs. "fully clean" — worth fixing whenever those commands are next touched.
- protocol_io's `HistoryFile::open_append`/`compact` are O(file size) on every resume/compact, and
  `TailFollower::poll()` fully re-decodes the whole file on every call — both documented,
  acceptable-for-now costs, revisit if protocol_history grows a genuine incremental-resume API.
- protocol_io's resume/compact cannot preserve REC_PROJECTION/REC_INDEX/REC_SEALED/REC_EPHEMERAL
  records (tolerated: protocol_materialize already falls back to full replay when a projection is
  missing).
- db_wal's `PayloadTransform` hook (encryption) has a trait + `IdentityPayloadTransform` default
  but no real encrypting implementation — by design, deferred to whoever wires up real encryption.
- db_snapshot's `select_generation`/`materialize_chain` are O(generations) (no lightweight
  generation-index cache) — a reasonable future perf optimization, not a correctness gap.
- db_index has no per-run sparse index/bloom filter for point lookups, and its FullTextIndex has
  no ranking/relevance/stemming/stopwords (explicitly deferred to db_query's planner to layer on).
- `db_core::ResumeToken` has no public constructor from an arbitrary wire string — framework/sync's
  receive path works around this by using `Hello.frontier` instead of decoding an incoming resume
  token.
- os-hub's fanout/presence registries are a stand-in for real db-native live-query/preview
  integration (documented extension seam, not attempted this campaign).
- os-hub's studio-scoped VFS "document" nodes have no FK/back-reference to a real db document row
  — correlated only by convention (matching document_id string).
- os-hub's legacy REST document/operations routes were DELETED (not adapted) since they depended
  on the no-longer-existing whole-JSON-snapshot semantics, replaced with a small new frontier-only
  REST endpoint — a behavior change worth knowing about for any external tooling that used the old
  routes.
- compose-hub's `load_admin_persons` is empty (presence is ephemeral/in-actor-only; an admin-wide
  listing would need to poll every live actor) — deferred.
- Storybook full production build is currently broken for reasons entirely unrelated to this
  campaign (section 6 above) — already independently tracked/partially addressed by sibling ticket
  26/07/27/FIX-STORYBOOK-BUILD-BROKEN-BY-PUZZLE-DSL-FIXTURE-MIGRATION, which found two additional
