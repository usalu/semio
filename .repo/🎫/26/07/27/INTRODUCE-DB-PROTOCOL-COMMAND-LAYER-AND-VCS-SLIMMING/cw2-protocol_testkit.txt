DEVIATIONS FROM THE LITERAL "Deps:" LINE (`protocol = {...}, pack_testkit = {...}` only), all
documented inline in Cargo.toml:
- The `protocol` facade re-exports `RecoveryMode`/`RecoveryReport`/`FrameCursor`/etc. as *types*
  but not the free fn `protocol_format::recover`, `HEADER_SIZE`, or the `REC_*` record-kind
  constants — needed by `assert_zero_copy`/`assert_chain_detects_tamper`/
  `assert_recovery_truncates_to_commit`/`assert_compaction_identity`, which walk raw record
  streams and classify frame kinds directly. Added `protocol_core` and `protocol_format` as direct
  path deps.
- The facade also does not re-export `protocol_history::{encode_history, decode_history,
  parse_ops_text, print_ops_text}` (only `HistoryAppender`/`HistoryReader` and the ops-text-only
  `compile_ops`/`decompile_ops` wrappers) — but several frozen law signatures take
  `&protocol::HistoryLog` directly (`assert_history_encode_decode_identity`,
  `assert_history_canonical_stable`) or need the raw text grammar
  (`assert_ops_protocol_bidirectional`), which only the whole-batch codec/text-grammar functions
  provide. Added `protocol_history` as a direct path dep.
- `serde`/`serde_json` added: `OpDagGen`/wire-frame-law samples build `serde_json::Value` payloads
  directly, and this crate's inline test fixtures (`AddOp`/`AddDiff`/`RegisterDiff`) need
  `#[derive(serde::Serialize, serde::Deserialize)]`. `dsl_core` added as a dev-dependency only
  (never in the public API) since the `OpText` fixture's `parse_op` returns
  `Result<Self, dsl_core::TextError>`.
  Every added dependency is a sibling crate already inside this family, not an external one.
- `assert_chain_detects_tamper`'s docstring softens the contract's "Full verification must error"
  prose to "must never go unnoticed" (never silently decodes to the untampered original). Reason:
  per-frame CRC-32C is checked during `protocol_format::recover`'s own scan BEFORE
  `VerificationLevel::Full`'s chain-hash check ever runs, so a tampered byte inside an
  already-committed frame makes `recover` truncate the trusted range *before* it — an `Ok` with a
  visibly shorter/different log, not always a hard `Err`. This is `protocol_history`'s own
  documented precedent (`history_full_verification_detects_tampering` test, same file), not a bug
  in this crate; the law here is phrased against that real layering while still proving genuine
  tamper-detection.
- `assert_op_dag_convergence(envelopes, seed, permutation_count)` and `assert_wire_frame_round_trip`
  (via a `WireFrameSample::{Client, Server}` enum wrapper, since `ClientFrame`/`ServerFrame` have
  distinct encode/decode fn pairs) are this crate's own signature choices — the contract names
  these two law fns but does not pin exact signatures beyond that.
