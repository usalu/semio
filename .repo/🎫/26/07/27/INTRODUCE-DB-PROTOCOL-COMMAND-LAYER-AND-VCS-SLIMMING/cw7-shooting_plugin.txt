What changed
------------
1. Import: `use vcs::{CollectionOperation, DocumentDsl};` split into
   `use protocol::CollectionOperation;` + `use vcs::DocumentDsl;` (DocumentDsl has no protocol
   equivalent — confirmed by checking protocol/rs/lib.rs's re-export list — so it stays on vcs).

2. Three `CollectionOperation::Add { index, item }` construction sites rewritten to
   `Add { id, item, at }`:
   - "saveCamera" handler (SavedCameras collection): item was previously built inline inside the
     `Add` literal, so it was hoisted into a `let saved_camera = ShootingSavedCamera { .. }` binding
     first, then `id: saved_camera.id.clone()` supplied to `Add`, `at: fixture.saved_cameras.len()`.
   - "importAsset" handler (Assets collection): `id: id.clone()` (the same locally-generated
     `next_shooting_id("asset")` value already used for `asset.id` and later reused for
     `ShootingOperation::SetActiveAsset { asset_id: Some(id) }`), `at: fixture.assets.len()`.
   - "addShot" handler (Shots collection): `id: id.clone()` (locally-generated
     `next_shooting_id("shot")`, also reused for `SetActiveShot`), `at: fixture.shots.len()`.
   - "addAsset" handler (Assets collection): `id: id.clone()` (locally-generated
     `next_shooting_id("asset")`, also reused for `SetActiveAsset`), `at: fixture.assets.len()`.

   Id source rationale: in every site the crate already generates a fresh id via
   `next_shooting_id(prefix)` (an atomic counter) BEFORE constructing the item, and stores it on
   the item's own `id` field (`ShootingAsset.id` / `ShootingShot.id` / `ShootingSavedCamera.id`,
   all `Identified<String>` per shooting/rs). That's the same id later reused for the
   `SetActive*`/`SetActiveAsset` follow-up operation in each handler, so it was already the crate's
   single source of truth for that item's identity — just not previously threaded into the `Add`
   op itself. Supplied it verbatim (cloned where the local `id` binding is also needed afterward).

3. `CollectionOperation::Patch { .. }` sites (4: setActiveShotLabel, setActiveShotFormat/Shape,
   patchShot/patchShots, patchAsset/patchAssets) left untouched — Patch's shape is unchanged by the
   freeze.

4. Cargo.toml: added `protocol = { path = "../../../protocol/rs" }` (was genuinely missing — this
   crate had not been touched by CW3's earlier mechanical sweep). Path pattern verified against
   layout/plugin/rs's Cargo.toml (same directory depth, already has `protocol` at that path).
