CW7 integration verification (post-workflow + manual completion pass)

CW7 workflow ran 18 parallel agents against the 18 crates confirmed (by grep) to construct or
pattern-match vcs::CollectionOperation or call vcs::apply_collection_operation/
invert_collection_operation/collection_diff_from_operation. Before launching, found and fixed a
real gap: protocol/rs's facade re-exported CollectionOperation/Identified/Patchable/CollectionDiff
but NOT the three free functions (apply_collection_operation/invert_collection_operation/
collection_diff_from_operation) — added them to the re-export list.

Workflow outcome: 14/18 crates migrated cleanly. 4 reported real or apparent blockers:
  - animate_plugin: reported blocked on animate_present (sibling, same wave) — turned out to be a
    parallel-execution race; animate_present had actually finished by workflow end. No fix needed.
  - dag_plugin: same race pattern against infinite/board/port/directed/dag/rs (same wave) — also
    already resolved by workflow end. No fix needed.
  - architect_plugin: same race pattern against architect_program (same wave, 78 sites, took
    longest) — architect_program finished with 181/181 tests passing, but architect_plugin's own
    agent had already given up and reported blocked before that happened.
  - imperative_core / imperative_plugin: genuine blocker, NOT a race. Both depend on `Step` (defined
    in imperative/engine/rs, a THIRD sibling crate never in the original 18-crate assignment list),
    which only implemented vcs::Identified/vcs::Patchable, not protocol::Identified/Patchable. Since
    vcs::Patchable::apply_patch(&mut self, &TPatch) -> TPatch (single method, mutate-and-return-
    inverse) is a genuinely different shape from protocol::Patchable's split apply_patch(&mut self,
    &TPatch) / diff_patch(&self, &Self) -> Option<TPatch>, this isn't a mechanical rename, and
    Rust's orphan rule forbids adding the impl from either of the two assigned crates (neither owns
    Step nor the trait). Both agents correctly declined to force a broken workaround and reported
    the precise blocker instead.
