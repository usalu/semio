WHAT WAS IMPLEMENTED

1. Core LSM-lite sorted-run engine (region 🔖SortedRun + 🔖Merge):
   - RunEntry/RunValue{Put,Tombstone}: one well-formed run is a strictly-ascending,
     unique-by-key entry list.
   - build_run: sorts+dedups an unordered write batch, last-write-in-original-order wins.
   - encode_run/decode_run: on-disk format `MAGIC(4="DBIR") VERSION(1) KIND_TAG(1)
     entry_count(varint) entries... crc32c(4,LE)`; each entry is
     `key_len(varint) key tag(1) [value_len(varint) value]`. decode_run independently
     re-validates strict ascending order and the crc32c checksum before trusting anything,
     and cross-checks the kind tag against the caller's expected IndexKind.
   - peek_entry_count/read_run_header: header-only parse (no full entry decode) used by
     `stats()` so it stays cheap.
   - merge_runs(runs, drop_tombstones): k-way merge (oldest..newest ordering, newest wins
     on key collision); `drop_tombstones=false` for partial (LSM) merges where an even-older
     run may still exist beneath, `true` for a complete merge/compaction.

2. IndexKind namespacing (region 🔖IndexKind): the ten kinds named in the contract's
   db_index responsibility line (Command, ActorSeq, Frontier, TouchedRegion, Inverse,
   Commit, Conflict, Projection, FullText, Preview). run_id = (kind_tag:u8 << 56) |
   sequence:u56 — db_storage::IndexStorage addresses runs by one flat u64 per document, so
   this crate owns carving that space into one namespace per kind.

3. IndexHandle (region 🔖IndexHandle): the per-(document,kind) LSM-lite store —
   put/put_batch/delete/get/scan_prefix/compact/stats/verify, plus MergePolicy-driven
   auto-merge (default: merge the two oldest runs whenever live run count exceeds 4,
   preserving tombstones; compact() does a full merge across every run, dropping
   tombstones, since nothing older remains beneath a complete merge).

4. Typed convenience layer built on IndexHandle, for 7 of the 10 kinds:
   - CommandIndex / InverseIndex (share a private SeqLocationIndex helper):
     command_seq -> RecordLocation{segment,offset,len}.
   - ActorSeqIndex: (actor, actor_seq) -> command_seq, key = actor_bytes||0x00||seq(BE);
     rejects actor ids containing a NUL byte (index-key-safety, mirrors db_core's
     ResumeToken '|'-safety pattern) with DbError::InvalidArgument.
   - FrontierIndex: commit_seq -> db_core::Frontier (own binary encode/decode of the
     Frontier struct; ResumeToken's text encoding wasn't reused since this is a different
     use case — a sorted-run value, not a wire token).
   - TouchedRegionIndex: region -> sorted/deduped Vec<command_seq> (read-modify-write
     postings).
   - CommitIndex: commit_id (str) -> command_seq.
   - FullTextIndex: minimal inverted index — index_document tokenizes (lowercase,
     alphanumeric-run split) and posts doc_ref into each term's postings;
     search(term) resolves one term's postings. No ranking/stemming/stopwords.

DEVIATIONS FROM THE CONTRACT
None. Dependencies match the contract's table exactly (db_core, db_storage, pack_core).
No cdylib, no wasm-incompatible code (this crate has no storage/thread code of its own —
everything goes through the already-cfg-gated db_storage::IndexStorage trait object, so
db_index itself stays wasm32-unknown-unknown-clean, consistent with the "no cdylib
anywhere" / lower-crate wasm-clean spirit even though the contract doesn't explicitly list
db_index among the crates it calls out by name for that property).

EXTENSION SEAMS LEFT (clearly marked, not stubs)
- IndexKind::{Conflict, Projection, Preview} have no typed wrapper struct — but they are
  FULLY FUNCTIONAL via the generic `IndexHandle::new(storage, document, IndexKind::Conflict)`
  etc. (same put/get/delete/scan_prefix/compact/stats/verify API every other kind uses).
  Rationale documented in IndexKind's doc comment: their value shapes belong to crates that
  don't exist yet in this wave (db_conflict::ConflictRecord, a db_projection state pointer,
  a db_preview location) — adding typed sugar now would mean guessing at a payload shape
  owned by another crate. Nothing here panics or returns Unimplemented; the mechanism is
  real, tested (different_kinds_do_not_collide_for_the_same_document exercises the
  namespacing every kind — including these three — relies on), and ready for a future wave
  to add a thin typed wrapper once the value shape exists.
- FullTextIndex has no ranking/relevance scoring, stemming, or stopword filtering —
  documented as db_query's planner's job to layer on top of this crate's exact-term
  postings; index_document/search themselves are complete and tested.
- get()/scan_prefix() decode a run's full entry list even for a single-key point lookup
  (no per-run sparse index or bloom filter) — documented in IndexHandle::get's doc as a
  deliberate simplicity choice appropriate given MergePolicy keeps live run counts small;
  a real high-throughput deployment would want per-run key indexes, left as a future
  optimization, not a correctness gap.

WHAT I ADDED (region 🔖BlobList + 🔖ConflictIndex + 🔖ProjectionIndex + 🔖PreviewIndex, plus
5 new inline tests + updated module/IndexKind doc comments to say "all ten" instead of
"seven of the ten"):

- encode_blob_list/decode_blob_list: `count(varint) [len(varint) bytes]...` — a list of
  opaque byte blobs, the same read-modify-write accumulation shape TouchedRegionIndex/
  FullTextIndex already used for u64 postings, generalized to arbitrary-size values.
- ConflictIndex: `command_seq -> [ConflictRecord bytes]`. record_conflict appends to the
  list at that seq (read-modify-write like TouchedRegionIndex::record_touch);
  conflicts_for returns the accumulated list in recorded order.
- ProjectionIndex: `(projection_id, frontier_seq) -> opaque projection state bytes`, key =
  `projection_id_bytes || 0x00 || frontier_seq(8,BE)` — the same NUL-separated composite
  shape ActorSeqIndex already used (projection_id validated NUL-free). `at()` is an exact
  lookup; `latest_at_or_before()` is a floor query scoped to projection_id's own key range
  via the NUL separator, so a projection with nothing at or before the target seq never
  wrongly falls back to a different, lexicographically-earlier projection's entry (tested
  explicitly with a "by-color" probe that has zero entries, sorting after a populated
  "by-author").
- PreviewIndex: `(actor, preview_key) -> opaque latest preview bytes`, key =
  `actor_bytes || 0x00 || preview_key_bytes` (actor validated NUL-free; preview_key is the
  final component so it needs no such restriction). publish/withdraw are plain put/delete,
  so latest() naturally coalesces to the most-recent publish-or-withdraw per (actor,key) —
  matching the contract's preview law in plain terms. for_actor() lists every live preview
  for one actor via a prefix scan.
