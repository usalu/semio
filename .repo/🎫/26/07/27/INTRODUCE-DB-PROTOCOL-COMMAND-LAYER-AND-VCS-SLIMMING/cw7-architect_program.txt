3. SIGNIFICANT DEVIATION DISCOVERED AND HANDLED — protocol::Patchable is NOT a pure
   namespace move of vcs::Patchable, contrary to the instructions doc's step 6
   wording ("Identified/Patchable/CollectionDiff/ItemPatch... moved to protocol too
   per the same shape freeze"). Verified directly against protocol/command/rs/lib.rs:

     vcs::Patchable (old):      fn apply_patch(&mut self, patch: &TPatch) -> TPatch;
     protocol::Patchable (new): fn apply_patch(&mut self, patch: &TPatch);
                                 fn diff_patch(&self, other: &Self) -> Option<TPatch>;

   `Identified`, `ItemPatch`, and `CollectionDiff` ARE pure shape-identical moves
   (verified field-for-field) — only `Patchable` differs. This is not optional to
   ignore: `protocol::apply_collection_operation`/`invert_collection_operation`'s own
   trait bound is `TItem: Identified<TId> + Clone + Patchable<TPatch>` resolved
   against protocol_command's own traits (not vcs's, which are separate, unrelated
   trait definitions despite the identical name) — so calling the protocol:: free
   functions at all is impossible unless every item type in this crate implements
   protocol::Patchable specifically. There is no partial-migration path here.

   Given the mechanical centralization of this crate's patch logic (one `PatchRow`
   helper trait + one `impl_patchable!` macro driving all 67 register
   Patchable impls, plus 2 hand-written impls for TraceLink and ProgramMeta), the
   migration was done in full rather than left half-broken:
     - `PatchRow::patch_row(&mut self, patch: &Option<T>, inverse: &mut Option<T>)`
       split into `apply_row(&mut self, patch: &Option<T>)` (mutate only) and
       `diff_row(&self, other: &Self, out: &mut Option<T>)` (always snapshots
       `other`'s value into `out`, unconditionally — not gated on inequality).
     - `impl_patchable!` macro regenerated: `apply_patch` now calls `apply_row` per
       field (no return); new `diff_patch(&self, other) -> Option<$patch>` calls
       `diff_row` per field and always returns `Some(patch)` (a full-snapshot patch
       of every field, not a minimal diff — see correctness note below).
     - 2 manual impls (`TraceLink`/`TraceLinkPatch`, `ProgramMeta`/`ProgramMetaPatch`)
       hand-rewritten to the same apply/diff split, same full-snapshot semantics.
     - `invert_program_operation`'s 3 non-collection call sites (UpdateMeta,
       UpdateProject, UpdateGovernance) that relied on the old `apply_patch` return
       value were rewritten: capture `prior = program.X.clone()`, mutate a `probe`
       clone with `apply_patch`, then `probe.diff_patch(&prior)` for the inverse.
     - 65 register-level test round-trips (`let inverse = item.apply_patch(&patch);
       ... item.apply_patch(&inverse);`) mechanically rewritten to
       `item.apply_patch(&patch); let inverse =
       item.diff_patch(&original).expect(...); ... item.apply_patch(&inverse);` —
       safe because every one of these 65 tests already captured `let original =
       item.clone();` immediately before constructing the patch (verified via grep,
       exactly 65/65/65 matches for the three patterns before editing).

   CORRECTNESS NOTE (behavior-preserving, not a regression): `diff_row`/`diff_patch`
   use a full-snapshot strategy (always copy `other`'s field value) rather than a
   minimal inequality-gated diff. This was deliberate: for entity fields that are
   themselves `Option<T>` (patch field type also bare `Option<T>`, not
   `Option<Option<T>>`), the patch representation has no way to express "clear this
   field to None" — `apply_row`'s `Option<T>` impl only ever sets `Some(value)`,
   never `None`, whether the value came from a real diff or a full snapshot. This
   exact limitation already existed in the OLD vcs::Patchable-based
   `patch_row`/inverse-capture mechanism (traced through by hand: a field that goes
   None -> Some via a patch produces an "inverse" that is itself None, which the old
   `apply_patch`'s `if let Some(value) = patch` then silently no-ops on, i.e. undo
   already failed to restore None before this migration). The new diff_patch does
   not fix or worsen this pre-existing gap — it reproduces it faithfully. All 181
   tests (including every `*_patch_round_trips` test, which patches every field with
   a `Some(..)` value, never introducing new Nones) pass, confirming no regression
   inside this crate's own coverage.
