## Systemische Konsistenzprobleme (einmal tabellenweit lösen)

1. Platform-vs-seller physical-location rule applied inconsistently: third-party/partner physical yards are coded '—' for Restado (BB-09) but 'Standort' for useagain (BB-41), SalvoWEB (BB-47), Köppel & Klein (BB-30) and Stiftung Chance/BauTeile Zürich (BB-40). Same fact pattern (independent dealers with visitable shops listed on the platform) is coded both ways — needs one rule.
2. The three Matériuum rows for the same materiuum.ch/boutique contradict each other: Beschaffungsschritte recorded 'Reservierung' (BB-34, BB-35) vs full 'Warenkorb/Bestellung/Zahlung' (BB-36); Übergabe recorded 'Abholung' only with no delivery (BB-34) vs 'Abholung, Lieferung' (BB-35, BB-36). One shared shop must be coded identically across the three rows.
3. 'Reservierung' is used loosely for real webshops that actually run cart+order+payment: Cornermat (BB-02), Gruner ReUse (BB-32), re:store (BB-51) and Matériuum Lausanne (BB-36) were all recorded 'Reservierung' where no binding/provisional hold is documented — a genuine checkout should be coded instead.
4. Widespread 'n. p.' misuse on fully public sites: BB-08 Materialrest24 and BB-46 Material Index recorded almost every dimension as 'n. p.' while their search/procurement facts were knowable; BB-06 bauteilnetz has datenfelder/uebergabe 'n. p.' while suchfunktionen is populated (internal contradiction); BB-15 Cycle Up recorded all '—' while kanal is populated. 'n. p.' should be reserved for genuine tech/access walls.
5. '—' vs 'n. p.' reading-key errors: BB-08 physisch 'n. p.' should be '—' (absence, not restriction); BB-38 REUZI, BB-18 RAEDIFICARE and BB-06 uebergabe 'n. p.' reflect documented facts (unresolved logistics / self-pickup) and should be '—' or the positive value, not 'n. p.'
6. Karte/GIS coded under Angebotsform but omitted from Such- und Auswahlfunktionen where it is interactive spatial narrowing: Insert (BB-23), Restado (BB-09), REFAIR (BB-19). It should appear in both dimensions consistently.
7. App-only marketplaces treated unevenly: BatRecup (BB-13) asserted Angebotsübersicht/Detailseite/öffentlich as confirmed despite being app-only (should be 'n. p.'), whereas Cycle Zéro (BB-16) and ReSource (BB-24) were coded more conservatively for the same access limitation.
8. BB-20 Réempro is internally inconsistent: verdicts mark kanal/physisch/suchfunktionen 'incorrect' and datenfelder/uebergabe 'partly', but the 'verified' field only echoes the recorded value and there are no notes or keyDiscrepancies, so no corrected value can be derived — the row is under-documented and unactionable as delivered.
