# Terrain Contours

The GIS Terrain editor generates WGS84 routes at multiples of a metre interval. It intersects the terrain mesh's exact grid triangles at the saved elevations and joins segments at shared mesh vertices and edges. Closed loops stay closed, and paths end at junctions or the grid boundary. The contour elevations do not include viewport exaggeration.

The command replaces previously generated routes while preserving authored routes, positions, regions, and imported map properties. Repeating generation with identical geometry leaves history unchanged. Changed contour geometry publishes through the regular imported-feature mutation, so Undo and Redo apply to the complete generated set.

Inputs accept intervals from 0.1 to 65,535 metres. The command caps the result at 64 levels, 4,096 mesh segments, and 512 routes. The mounted retained operation publishes a bilingual progress message and checks cancellation at each contour level before publishing.

The segment and route limits bound the generated set to 4,608 coordinate pairs and under 384 KiB of compact canonical field data, including route identifiers and labels. The contour command publishes a typed mutation, so the retained tool's host-output byte limit does not size contour geometry. Store publication independently owns the canonical edit limit. A map admitted through the editor's 1 MiB map input bound and a full contour set fit within the Store's 16 MiB canonical edit envelope, including the previous map for Undo. Regeneration clones only preserved authored features, so the replacement does not temporarily duplicate previously generated routes.

The shared JSON fixtures cover a ramp, fractional elevations below sea level, a flat grid, and a closed loop whose shape depends on the mesh diagonal. The independent Matplotlib and Shapely oracle passed for all fixture scenarios. An isolated build of the Rust geometry implementation also passed on those surfaces and honored cancellation. The full editor Rust cases exercise density rejection, identifier collisions, mounted mutation history, and World3d overlay publication.

Authored terrain now drapes WGS84 overlays through the full latitude range, including a grid touching the pole. It normalizes geometry using the source's geographic bounds and evaluates the local-meter mesh triangles. Grid boundary markers remain visible and markers just outside those bounds are excluded. Tiled terrain retains Web Mercator latitude validation and half-open tile ownership. The two focused Rust Surface tests passed for authored polar terrain and existing streamed terrain. An isolated Rust check and the PROJ and GEOS oracle also passed for the shared high-latitude fixture.

The position add and move forms accept the full WGS84 latitude range. The saved elevation source determines which coordinates the editor accepts when publishing a position, route, or region edit. The shared overlay-history fixture now stages polar add, move, replace, and append actions and covers rejection beyond the pole as well as rejection of polar edits on tiled terrain. The fixture's expected geometry and feature order were checked across all 11 rows.
