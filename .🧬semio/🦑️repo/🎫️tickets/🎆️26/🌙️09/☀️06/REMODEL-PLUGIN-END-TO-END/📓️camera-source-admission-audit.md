# Camera Source Admission Audit

Source inspection only; no build, execution, or browser verification. This describes the source at inspection time and does not claim the separate decoder resize work is complete.

## Existing path and limits

- `✏️s/🔌️plugins/📸️remodel/🗿️artifacts/📸️remodeling/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🎮️commands/🎞️import-frames/🦀️.rs` requests multiple PNG/JPEG/video files as whole data URLs, with `max_file_bytes: None`. React `🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🏛️ShellHost/⚡️host-effects/📥️document-load-effects/🟦️.ts` therefore uses unbounded `requestFileOpen` before transfer tracking and dispatches each complete string. Supplying `max_file_bytes` selects bounded reads with signal and progress, but still constructs and dispatches whole data URLs; it is not streaming into durable content.
- `✏️editor/🎮️commands/🖼️import-frame-payload/🦀️.rs` decodes base64, synchronously decodes the entire still image merely to validate dimensions, base64-encodes the source again into `ImageAsset`, and emits `CreateAsset` and frame mutations. Its multi-file transaction lives in window transient state and requires explicit abort/rollback. This path has whole-file, whole-image and whole-mutation ownership before retained work admission.
- `🧬️schema/📸️snapshot/🧩️asset-handles-and-durable-content/🦀️.rs` stores 4,096-byte raw leaves encoded in `ByteBuffer`, but `durable_remodeling_asset` first materializes the complete base64 decode and refuses compressed bytes above 1,114,112; `remodeling_asset_chunk_source` separately enforces the same total and synchronously rebuilds an `Arc<Vec<u8>>` per decoded leaf. `✏️editor/🧵️reconstruction-session/🧭️run-contract/🦀️.rs` independently sets `MAX_STILL_INPUT_BYTES` to 1,114,112, and `🔑️trace-checkpoint-and-ingestion/🦀️.rs` passes it to `CompressedChunkRope`. A camera JPEG can exceed the compressed byte ceiling independently of its pixel dimensions. Raising one constant alone does not solve admission, transport, scheduler work, or memory ownership.
- `image_asset_child_handle` hashes `mime + U+001F + base64 data` through `store::content_id`: `🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🧩️composition/👥️space-member/📥️lifted/🏪️store/🔗️member-link-resolution-and-blob-store/🦀️.rs` truncates SHA-256 to 64 bits. Width and height are not part of that identity. `create-asset/🔺️diff/🦀️.rs` recomputes identity synchronously and currently truncates the prior content by child ID on overwrite; shared identical-content ownership needs explicit verification before changing identity or chunk publication. Check the exact current source when implementing.

## Narrow production direction

Preserve original compressed image bytes and metadata as the durable asset, not a resized replacement. Introduce a genuinely resumable import/source owner that receives bounded chunks with a declared total and limits, incrementally validates PNG/JPEG headers and hashes the identity, and stages 4 KiB durable leaves under actual work/allocation grants. Publish the asset handle, content and frame only after the complete validated source is owned; ensure cancellation or failure retires staged leaves and rolls back the exact multi-file transaction. The durable chunk reader must borrow or traverse snapshot-owned chunks in bounded turns rather than first copying/decoding every leaf. A decoder able to consume that source incrementally and produce a bounded preview/downsample remains necessary; the current whole-image decoder bound is a separate bottleneck.

The existing bounded browser `readSelectedFilesBoundedV1` supplies file-size refusal, cancellation and progress, but produces a complete data URL per file. Use its selection/read primitives only if the host-to-guest protocol gains a chunked original-source handoff with backpressure, generation/operation identity, wake and cancellation; a size cap plus whole-string dispatch is only a bounded small-file option, not camera-scale streaming. Maintain multi-select order, ownership checks, abort and atomic transaction semantics across chunks. The transport cap and raw-wire admission must be reconciled, rather than only increasing `MAX_STILL_INPUT_BYTES`.

`🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/📜️declaration/📥️natural-file/🦀️.rs` already owns a controlled decoder, checkpoint/progress, cancellation and paid retirement, and `👷️job/🏛️reserved/🦀️.rs` registers `FrameworkImportMediaJobFactory` with an 8,388,608-byte raw-wire envelope. The natural-file job takes already-owned `MediaPayload::Intrinsic` bytes and publishes a newly decoded snapshot through Pack/genesis. It is a useful lifecycle pattern, not a drop-in replacement for appending multiple camera frames to the current document or streaming larger files. Its synchronous fallback explicitly refuses inputs exceeding one scheduler grant; it must not be used to disguise whole-image decoding. Assess factoring a shared controlled input/source owner into the framework and supply a Remodel-specific append transaction and codec. Eight MiB is a real current transport/admission ceiling, not unlimited camera support.

## Verification required

Exercise ordinary PNG and JPEG above 1,114,112 compressed bytes and a size near the chosen explicit ceiling, with independent decoder/hash oracle and exact original byte recovery after cold reopen. Include one-byte-over-limit refusal, malformed/truncated header, duplicate content and overwrite with another live reference, original operation/generation substitution, partial chunk delivery, delayed wake, cancellation at every source/hash/decode/publication/retirement frontier, multi-file abort, and both renderer transports. Assert bounded grant/work/allocations and real progress without relying on source-only tests. No relevant tests were run in this audit.

The current renderer does send the data URL in ordered command chunks. The guest's actor staging concatenates those chunks and then selects the assembled value as the original typed command input. Remodel's retained command admits at most 65,536 raw bytes, leaving under 49 KiB of JPEG payload after base64 and envelope overhead. Transport chunking therefore preserves the whole-command limit. The framework's resumable JPEG job supports baseline and progressive encoding with a 16,777,216 source-pixel default. Its allocation stage reserves whole-frame coefficient and sample planes alongside full RGBA. Writing only downsampled output could remove the full RGBA allocation, while progressive decode would still need retained source coefficient planes. At 12 MP with 4:2:0 sampling, those planes account for about 90 MB before the roughly 48 MB full RGBA raster and compressed input. Camera-scale support needs real WASM allocation, work and retirement measurements.
