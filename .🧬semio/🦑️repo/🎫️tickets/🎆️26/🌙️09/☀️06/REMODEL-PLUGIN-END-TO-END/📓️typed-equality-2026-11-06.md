# Typed equality modernization

The old native slice cursor admitted a page by bytes but reported one work unit regardless of how many elements it inspected. The structural cursor and its derive also lacked a caller work limit or selected close-work quote. Float inline equality used bit identity, which disagreed with Rust `PartialEq` for signed zero and NaN. `Number` remains intentionally different: its own `PartialEq` uses encoded float identity. Current `Float32Buffer` is a derived-`PartialEq` enum whose inline branch contains `Vec<f32>`; its inline equality therefore needs IEEE semantics.

The first-party TypeScript slice cursor now accepts a separate work ceiling and reports inspected work. Existing Energy fixture laws require selected copy demand to fit the body, so the work schema and fixture gained zero- and one-byte body cases for a two-byte comparison. The updated ticket script `🧪️float-equality-oracle.mjs`, invoked through `repo tools exec --light bun`, first exited 1 on the zero-byte case against the old cursor. After correcting body selection in Rust and TypeScript, it exited 0: eight float vectors and nine work vectors agreed with the actual TypeScript cursor and independent SQLite results, with schemas validated by Ajv. This is not native validation.

The native slice cursor, typed tree, record/sequence/tuple cursors and derive are being updated to the same explicit work protocol. Their current source is an intermediate breaking change: not all callers have been migrated and no native pass is claimed. Focused native float request 2744 reached terminal exit 1. Its retained log contains two equality-compiler E0689 diagnostics for ambiguous work accumulator types and a later Cargo.toml source-extent admission refusal while other managed progress is interleaved. Both concrete accumulator sites now explicitly use `u64`; this is not a clean test-body RED or a native GREEN, and no retry has yet been issued.

The repository census found current equality-owner callers in the generic replication field-change/record/indexed owners and Energy retained mutation sources. Those callers already use older field-preparation signatures and lack a work axis, so they require a genuine protocol update rather than a constant-work shim. Energy's `EntityId(u32)` is an existing first-party inline implementation; it now declares its one-unit fixed work. The public inline-element trait cannot be sealed within the equality crate without relocating that domain-owned type; all actual implementations must be audited for fixed, allocation-free behavior.

The generic scalar field-change owner has an intermediate work-axis migration, and its neutral fixture and direct tests now reflect IEEE signed-zero and NaN behavior. The record adapter draft uses a named projection contract with explicit project/install work, propagates work through its owner and closure, and has fixture tests for work receipts and zero-work denial. Its public contract is re-exported through the existing facades. The indexed draft likewise uses a named bounded mapper and work receipts. Independent review identified that post-allocation capacity refusal could exceed admission, so it now uses the shared exact-layout value allocation helper. Both adapters report an actual allocation marker for their own backing births, including `Some(0)` for a failed attempt; empty and zero-sized values require no allocation. Tests using the actual RequestedAllocator refusal scope are authored but have not run. None of these changes has compiled or passed a native test. A bounded source census found the record and indexed owners' only concrete callers in their own test modules. The TypeScript slice descriptor likewise relies on implementations honoring its declared work; no claim is made that its callback is mechanically constrained.
