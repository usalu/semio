# Energy retained work migration

The current `RowFieldPreparation` contract has been changed to require separate work quotations and original retirement outcomes. It has 14 existing implementations: the root-link owner has a first-pass conversion, while the other 13 and the `RowLeafPreparation` parent still use old signatures and need real migration before Energy can compile. They cover membership, transforms, scalar and structured values, adjacency, lifecycle operations, outputs, root links, singletons and network inverses. No blanket work allowance or adapter has been added.

The root-link comparison now accepts an explicit work ceiling and reports bounded scalar and slice work. Its neutral fixture schema declares the comparison quantum; the added native fixture test is unexecuted. An Ajv and SQLite oracle independently classified all 28 existing root-link fixture outcomes, including invalid and missing cases, and exited 0; it does not execute the native cursor. The enclosing root owner now has a first-pass work-axis decision, inverse and closure conversion with typed child outcomes and retained error propagation. Its tests have been updated to use the schema-declared work ceiling, but neither source nor tests have compiled. The root-link projection trait and derive declare the actual fixed path work. The enclosing leaf and the other Energy row owners are still on older signatures.

The root diff default is structurally bounded: its model patch contains eight absent option fields and the root contains two more absent option fields. Its direct slot selection and assignment are fixed operations; there is no nested payload traversal in that default. Other Energy owners require their own actual field and child work quotes, genuine source bindings, and retained failure/closure receipts. No native compilation, semantic pass or live Remodel UI result follows from this work.

The parent `RowLeafPreparation` still predates the current semantic leaf work and retirement interface. Its `RowLeafSpec` also provides projection, diagnostic-target and inverse callbacks without declared work costs; their generated and handwritten implementations must gain bounded first-party contracts and actual quotes before the parent can honestly account for those calls. The remaining owners additionally depend on older branch, lookup and close helpers, so assigning a fixed allowance to the parent would conceal real unbounded or nested work.

On a child failure, the draft currently preserves that original failure if adding the enclosing progress overflows, but it cannot also retain the overflow cause without an owned failure-storage loan. This remains an unresolved error-path contract issue.

The enclosing root-link owner's own quote sequence also projects sources before full physical admission and may return zero work on a later denial. Zero-work, zero-item and zero-depth turns now return before those projections, but a partial physical denial can still reach them. Its schema-backed native test now instruments test-only source projections and requires reported work to cover any selections made on a denied turn; the current draft is expected to violate this law, and it has not run. The comparator-level denial change does not settle that parent-level issue. A sound pre-admission and work-quote design is still required; no blanket charge or native-pass claim has been substituted.

Independent design review recommends reserving a source-free upper bound for projection and child-quote work from the real caller, checking a coarse physical minimum, and then reporting actual inspection work even if the full physical grant is denied. The leaf only receives `maximum_work_units` and cannot mint an original loan. If its existing quote interface cannot express that sequence, it needs a genuine staged quote phase with the enclosing issued authority. This is a recommendation, not an implemented fix.

The same possible quote-before-admission issue was identified in the generic record owner and sent for independent review. Its source-level allocation-turn review does not cover that boundary.

Independent review found that a denied root-link comparison could inspect fields while reporting zero work. The draft now guards zero-work/coarse physical denial, reports bounded partial pin or field inspection work on later denial, and has schema-backed tests for those cases; these tests have not run. A bounded follow-up reread found the identified comparator path addressed and no additional concrete comparator counterexample; it did not establish a native pass. The shared-admission call checks a successful actual marker against the retained receipt before proceeding, preserving the sealed owner if they disagree. The row interface does not yet expose a failed-attempt marker to the enclosing leaf's original control. This is a concrete outstanding contract issue, not a proven complete failure path.
