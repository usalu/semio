# Context-Local Reconnect Control

The real document connection is opened by the store worker to the configured Hub's `/scopes/<encoded space/document>/document/ws`, with the session protocol and capability as subprotocols. On the provisioned pinned Chromium, the retained local two-context probe showed a real worker open and binary echo. `routeWebSocket` did not observe that worker socket; `setOffline(true)` did not close the already-open A worker socket within 10 seconds. Both observations are from the actual test in `🗑️generated/reconnect-provisioned-oracles.log`, not live Hub or successful outage evidence. The unsupported prototypes must be removed from final test discovery after a supported oracle is established.

The candidate test-only relay keeps the actual configured Hub and serve URLs and uses an isolated browser-context SOCKS proxy. It binds only loopback, admits only explicitly configured Hub/serve host and port pairs, forwards raw bytes, and marks Hub tunnels separately so only they are closed or refused during a bounded outage. Its finite accumulator, connection ceiling, half-close behavior, cancellation, active-tunnel witness and one-time teardown require actual test proof. Unresolved callbacks receive a cancellation signal and the relay restores on timeout or caller cancellation. Normal repo admission test 51870 was launched before subsequent source edits, so its result cannot alone validate current source. The candidate has not been wired into the official two-human journey and no live reconnect claim is made.
