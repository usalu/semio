# 📋️ Go Split Brief (wave 2, single executor)

Goal: dissolve `🔨️modules/💻️client/⌨️cli/🧩️component.go` (46,896 lines, package `client`) and `🔬️component_test.go` (23,901 lines) into the domain Go packages of `📋️plan.md` §2, producing a dependency DAG, with every package building and its tests passing. No behaviour changes except the DAG fixes below.

## Inputs
- Symbol graph: `📓️go-region-dependency-graph.md`, raw `🗑️generated/go-symbol-graph/{decls.jsonl,modules.json,scc-analysis.json,test-module-refs.json}`, region map `🔨️go-symbol-graph/🔣️region-modules.json`, tool `🔨️go-symbol-graph/main.go` (re-run with `GOWORK=off go run .`).
- Packages already created by wave 1 (each has `go.mod`, `📋️project.json`, `📜️script.ts`, and a `🐹️.go` with a `…Pending` region naming the symbols to move in): `🏠️workspace`, `🪪️identity`, `🧾️yaml`, `🔎️search`, `📐️model`, `🗣️languages`, `📡️events`, `🔗️graphql` (parser only), `🔌️mcp`, `🧩️providers`, `🏃️test-runner`, `📊️metrics`. Read each `…Pending` region first; they are the contract.
- Packages to create: `🗂️codebase`, `🎫️tickets`, `🎯️goals`, `🧑️contributors`, `📝️todos`, `📜️statutes`, `🌳️tree`, `🚚️move`, `🪝️hooks`, `⌨️cli` (`📦️packages/🐹️go` with the `main` for the `semio-repo` binary next to the library package: use `🐹️.go` for `package cli` and `📦️main.go` for `package main` in a sibling folder `⌨️cli/📦️packages/🐹️go/🚀️bin/`, since Go needs a directory per package).

## Method (scripted, AST-based, repeatable)
1. Extend the symbol-graph tool (copy to `🔨️go-split/main.go`, module `gosplit`) into a splitter: input = the live godfile + test file + `🔣️region-modules.json` + a `🔣️symbol-overrides.json` (symbol → module) that encodes the DAG fixes; output = one `🐹️.go` per target package (`package <name>`, header region, imports pruned to what is used, decls in original order grouped by original region), one `🧪️.go` test file per package (tests whose module set is a singleton go to that package; multi-module tests go to the topmost module they touch; tests touching `cli` plus domain modules go to `⌨️cli`), and a rewrite of every cross-package identifier reference into `pkg.Symbol` with the symbol exported (rename unexported → exported by capitalising, applying the rename everywhere including tests, string keys untouched). Cross-package method calls on types keep working because the receiver type moves with its methods; methods declared on a type from another package are illegal in Go — detect those (`decls.jsonl` kind=method whose receiver's module ≠ method's module) and convert them into functions in the method's module taking the receiver as first argument, rewriting call sites, OR move the method to the receiver's module when it only uses that module's symbols (prefer move).
2. DAG fixes (binding; from the graph report §8): (1) `type Kind` and its constants → `🪪️identity`; (2) `buildFileID`, `buildFolderID`, `buildSectionID`, `buildDefinitionID` → `🗂️codebase`, `buildBreachID` → `📜️statutes`; (3) `Breach` → `📐️model`; `Statute`, `PolicyDef`, `PolicyFunc` → `📜️statutes`; `CommandOutput`, `OutputError`, `OutputLine` → `🏠️workspace`; (4) every `*Command` factory (`locCommand`, `renameCommand`, `analyzeCommand`, `autofixCmd`, `ticketCommand`, `testCommand`, …) and `ToolResult`/`toolErrorResult` → `⌨️cli`; domain logic stays in the domain; (5) `providers` must not import `hooks`/`tickets`: declare `HookFormatter` and `IssueTracker` interfaces in `🧩️providers` (the wave-1 crate report says what shape), implement them in `🪝️hooks`/`🎫️tickets`; (6) `todos`, `tickets`, `statutes`, `events` use the `RepoContext` port interface, which moves to `📐️model` (port only; the default implementation stays in `🔗️graphql`); (7) `McpClientKind` + `ParseMcpClientKind` + `McpServerName` + `HookClientForMcpKind` → `🧩️providers` (check where the wave-1 providers crate put it and match). Re-run the graph tool on the OUTPUT tree (adapt it to read multiple files) until `scc-analysis.json` reports zero DAG violations; iterate `🔣️symbol-overrides.json` for the remaining edges (introduce small interfaces in the lower package rather than moving big types upward).
3. `go.work`: list every new module. `go build ./...` and `go vet ./...` per module. Tests: `go test ./...` per module, excluding the "Exhaustive" tests that walk the live monorepo (`TestExhaustive*` — keep them but tag them `//go:build exhaustive` and route them to the `test-exhaustive` script level). Use `GOWORK=<root>/go.work` and `-count=1`.
4. Delete the old `💻️client/⌨️cli` Go module (godfile, tests, `cmd/`, `internal/` leftovers, `go.mod`), remove it from `go.work`. Keep `💻️client/⌨️cli/📦️packages/🟦️typescript` untouched (the wiring agent moves it). Update `🔨️modules/🔌️mcp/📦️packages/🐹️go` imports from `repo/client` to the new packages (the mcp Go package must still build and pass its tests). Update root `📜️script.ts` constants `REPO_CLIENT_GO`, `REPO_CLI_ENTRY_GO`, the TypeScript `defaultCliBin()` (`📚️library/📦️packages/🟦️typescript/🟦️.ts` ~85) and `💻️client/⌨️cli/📦️packages/🟦️typescript/📜️script.ts` build/dev commands to build the Go binary from `⌨️cli/📦️packages/🐹️go/🚀️bin` to `⌨️cli/📦️packages/🐹️go/semio-repo[.exe]` (the wiring agent will introduce the Rust default; keep Go buildable).
5. Wave-1 harness Go adapters carry the marker `// 🚚️ repoint to github.com/usalu/semio/repo/<module> after split` — repoint every one of them and re-run their `subject … --implementation go` phase.
6. Keep the tool and `🔣️*.json` inputs in the ticket folder; delete generated outputs under `🗑️generated/go-split/` at the end except the final `scc-analysis.json` proving zero violations (copy it next to the report).
