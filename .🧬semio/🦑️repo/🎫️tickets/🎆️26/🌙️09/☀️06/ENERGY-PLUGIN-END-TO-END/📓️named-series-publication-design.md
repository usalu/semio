# Named Series Publication

The actual engine owner exposes `EnergyJob::live_time_series()` through the live table before results construction and the moved final table afterward. `TimeSeriesTable` stores a fixed table of original string keys and `TimeSeries` values. Each series owns exact f64 hour timestamps and values, a native unit, and admitted sample capacity. The current real publication serializes surface energy only; its ESF2 index has 76 bytes of header, two sorted surface partitions, prepared bounds, and 24 bytes per surface. The browser can now read that original paged surface source directly. No hourly numerical UI is claimed yet.

The next format should contain a bounded fixed header and section directory for the existing prepared surface index plus original named series. The directory must preserve the full original key, unit, sample count, exact f64 timestamp/value pairs, and native identity. A paid scan of one native series at a time can prepare cumulative offsets in retained pages; it must not flatten annual data or collect a whole-result vector. Fixed reads should locate directory ranges and sample indexes with bounded indexed reads. Every range remains at most 64 KiB and every serializer read at most 64 bytes. The original numerical owner stays paused until every range in the publication is delivered and acknowledged.

Validation must compare all 8,760 actual heating/cooling samples against the native table before and after the final owner moves, independently validate the wire with Buffer/SQLite, and verify the real mounted render path. UI rows must use native keys and units, explicit selected locale, actual publication completion, and bounded sample reads. No synthetic replacement, silent truncation, resampling, invented zero totals, or changed physics tolerances is permitted.
