# Native Checkpoint Export

The native exporter must select the exact `checkpoint.change_ids`, then each corresponding change's ordered edit IDs, and replay their actual original forward owners from the original genesis snapshot. It must preserve the live Store head, history cursor, checkpoint selection and generation. The existing cold `pack_at_checkpoint` demonstrates this semantic contract but is not an implementation dependency.

`checkpoint_origin` cannot select the historical snapshot: a later Repin transition reidentifies an earlier checkpoint and may occur after unrelated content. Replaying the active prefix before that Repin would export the wrong content. Unknown checkpoint, missing change and missing edit references must refuse rather than export head or a partial document.

The planned native route extends the existing media submission with explicit Head/Checkpoint source metadata, retaining the same export handle, poll, original chunks, cancellation and terminal acknowledgement. The source Store admits one retained checkpoint selection cursor against its generation/revision, scans the actual checkpoint/change/edit ledgers under caller grants, borrows original retained edit/operation sources, and uses the already installed semantic replay producer. The finished immutable projection is captured by the existing original media snapshot supplier and exported by the registered native writer. All source leases and semantic continuations must return to their original Store/decoder before source preparation can disappear.

The source selector carries borrowed request identity while the original command remains retained, avoiding duplicated checkpoint metadata. Its engine owner must explicitly close that metadata and every original ledger projection on refusal or cancellation. Host completion correlates the requested selection with the actual submitted operation handle; output is the ordinary canonical snapshot Pack only.
