# Weather Resolution Contract

The run factory captures the document's persisted `ArtifactLink` and resolves its target through the actor's actual request registry. The request is serialized native `ArtifactLink` JSON, including target dialect, role and `LinkPin`. `Head` means capture the target head once for this run; checkpoint and snapshot pins must remain literal. No unresolved bound link may fall back to synthetic weather.

The proposed host response is the target artifact's native canonical snapshot pack. The source hash over these immutable returned bytes records the actual captured weather version even when the authored link is `Head`. It must decode as the declared `stdio.epw` EnergyPlus dialect; errors are retained and localized in the run. Format conversion uses Stdio's native EPW schema and Energy's EPW extension, with bounded per-record weather projection. No duplicate embedded weather model is persisted in the Energy snapshot.

The registry-backed request receiver crosses into `Send` tool jobs without moving `Host` or forging `Send` on an actor-local `Rc`. Actual `Event::Completed` replies pass through the framework's original receiving custody before transfer. The existing tool-run port supplies a wake backed by its own atomic waiting state. Cancellation stops numerical admission, retains outstanding response custody, and releases response sources through funded closure rather than dropping live reply bytes.

## Retained implementation in progress

`ToolRunJobRequest.host` captures the existing actor-local Host for factory use only. `Host::resolve_link_retained` mints a real request from the same registry and returns a Send-safe receiver. Original `pending_instance`, prologue receiving and `resolve_original` paths recognize it; response bytes move without copying and refused slots keep their original pointers. The existing port state itself supplies the Waker without a second wake allocation. The registry and Host remain actor-local.

The simulation session now has a weather stage before model capture and numerical admission. A bound source without this capability refuses instead of using the engine's synthetic design weather. Returned source bytes are hashed incrementally, then decoded through the framework's real `OriginalSnapshotRecordReceiving`. To remain below ordinary one-MiB allocation grants, its generic-record transfer supports projecting one EPW row at a time instead of constructing a seven-MiB `Vec<EpwRecord>` in one allocation. The Stdio record schema supplies generated receiving cursors for the header and each row. Energy's existing EPW adapter projects their numerical values. Source bytes, generic fields, typed row destinations, source faults and parser owners retain explicit funded closure.

Weather selection and clearing use explicit editor commands that emit the existing native bind/unbind mutations. The simulation window shows the current target and literal pin, an address control, and a clear action. These changes still require compilation and runtime proof. They do not yet establish a native file picker, production cross-artifact LinkResolve backend, resolved location/date coverage display, or source-head invalidation after a target changes. The coordinator is tracing the real host/store resolution boundary.

New neutral fixtures and tests cover exact original reply ownership, zero grants, Send, funded physical receiver closure, two distinct real EPW sources against the independent CSV library, and full-year source decoding with unchanged per-turn grants. These tests are authored but have not passed yet: shared framework compilation has successively exposed Store lifecycle drift and now a missing generated icon contract source. No completion claim relies on these unrun tests.
