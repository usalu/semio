# ISO 16757 electronic product catalogue coverage

The trace maps current catalogue data checks to the 2015 architecture, the 2016 geometry edition, and the dictionary and interchange editions published in 2025. The first edition of Part 1 remains published while work on its replacement continues. The geometry part uses primitives from STEP and IFC and defines additional geometry for the building services domain. Independent external geometry and data dictionary round trips remain necessary. [Part 1](https://www.iso.org/standard/57613.html) · [Part 1 revision project](https://www.iso.org/standard/94406.html) · [Part 2](https://www.iso.org/standard/62080.html) · [Part 4](https://www.iso.org/standard/85070.html)

Part 5 specifies use of IFC and EN 17549-2 for exchange between catalogue providers and building services designers. The existing report has internal exchange, structure and identifier checks. Real-world conformance requires the normative catalogue view, the corresponding representation, an independent consumer and round-trip evidence. Draft publication numbering must remain separate from the released edition. [Part 5 publication](https://www.iso.org/standard/85071.html) · [Part 5 draft](https://www.iso.org/obp/ui?_escaped_fragment_=iso%3Astd%3Aiso%3A16757%3A-5%3Adis%3Aed-1%3Av1%3Aen)

## IFC4 catalogue projection

The exporter now emits an IFC4 project library, class groups, concrete proxy product types and declaration and group relationships. A declared dictionary name and optional version are exposed through a library association. The base document can be opened by an IFC4 consumer. IfcOpenShell 0.8.4.post1 independently validated the emitted STEP file against EXPRESS rules and checked three products, group membership, declaration, the dictionary link, and round-trip names containing Unicode, an apostrophe and a backslash. The Rust exporter yielded identical bytes when the input product order changed. IFC4 documentation prohibits direct IfcTypeProduct instances even though the EXPRESS schema accepts them, so this projection uses concrete proxies with an undefined predefined type. [IFC4 type restrictions](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/schema/ifckernel/lexical/ifctypeproduct.htm) · [Proxy type](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/schema/ifcsharedbldgelements/lexical/ifcbuildingelementproxytype.htm) · [Dictionary library information](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/schema/ifcexternalreferenceresource/lexical/ifclibraryinformation.htm)

The ISO 16757-5 exchange view still requires verification. The IFC proxy projection carries identities, class memberships, unitless scalar properties and available dictionary GUID references. Product variants, dimensional and structured properties, ports, geometry, the complete model-view schema and dictionary URI mappings remain open. The native crate check was queued behind the repository graph and capacity gates. [Part 5 publication](https://www.iso.org/standard/85071.html)

## Overall space and dictionary inheritance

The Part 2 report checks finite positive extents on all three axes and verifies that one declared overall envelope includes the other declared clearances. It verifies modeled product containment when the computed bounds establish it. A primitive outside the envelope fails. A complex surface whose conservative bounds extend outside still requires evidence for exact containment. The exact Rust envelope predicates and SQLite agreed on 14 fixtures, including inverted axes, nonfinite dimensions and contact with a boundary. Native confirmation of the new report remains pending. [ISO 16757-2:2016 §5.3](https://cdn.standards.iteh.ai/samples/62080/b0a642c4da6d44a6b634ee6ccc422d4c/ISO-16757-2-2016.pdf)

Dictionary cycle detection now accepts multiple valid inheritance paths to a shared ancestor. The production Rust predicate and SQLite reachability matched 11 cases, including diamonds, duplicate edges, cycles and self-links.

The published ISO 16757-5:2025 preview identifies the relevant IFC clauses for metadata, product classes and series, component relationships, properties and constraints, parametric geometry, ports, inlets and outlets, part numbers and external media. EN 17549-2 Annex A identifies the normative CODview2 schema. Its scope allows geometrical properties. The Part 5 preview does not establish the exact entity mapping or validate a live catalogue against the normative schema. [ISO 16757-5:2025 published contents](https://cdn.standards.iteh.ai/samples/iso/iso-16757-5-2025/b433235064b944158f4dfcdb816e438b/iso-16757-5-2025.pdf) [EN 17549-2:2023 scope and Annex A listing](https://webstore.ansi.org/preview-pages/BSI/preview_30414995.pdf)

## IFC4 scalar product properties

The exporter writes eligible unitless values as typed IFC single-value property records in each product type's property set. Values shared by a series are inherited until the product supplies its own value. Boolean, integer, finite decimal, text and identifier-like values use existing IFC4 value types. Applicable dictionary GUIDs are linked via library references to their single-value records. IfcOpenShell 0.8.4.post1 passed IFC4 schema and EXPRESS validation, independently recovered the shared and overridden values and verified both GUID relationships. Reversing products and input values produced identical export bytes. The CODview2 catalogue view remains unverified under ISO-09.
