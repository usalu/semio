## Direct Source Findings

Before this change DocumentBooleanJob cleared cache/local/ID/quality trees in one successful publication step, clears all ownership before preserving a failure, and invokes eager child cancellation on clear. Its cycle and requirement transitions also clear whole tree collections. Native Boolean node replacement discards nested child-reference strings when replacing old content.

Before this change TypeScript publication shallow-copied nodes and shares original groups, content arrays, paint stop/dash arrays, and the asset container with the caller. Calling owned scene retirement on such a published plan would mutate the input and any other live consumer. Publication therefore must build independent mutable containers under grants. Immutable encoded-source strings can stay shared, like native Arc source values; structural cleanup is not allocator byte credit.

## Intended Contract

Consuming transfer returns the genuine remaining input plan to the caller and only a valid completed result. Source-plan ownership is handed back explicitly: the eventual parent must adopt or retire it. Rust moves its input plan into the completed result, so that remaining input is empty at completion; TypeScript borrows the original input and will return that original plan unchanged. Private incomplete outputs and current publication nodes stay in retirement. Both implementations compose the existing PathBooleanRetirement and ScenePlanCloseJob, remove one tree/nested operand entry per cleanup unit, and retain failed state until transfer.

Successful publication drains intermediate maps under ordinary calculation grants before exposing completion. TypeScript independently copies groups, paint buffers, plain path segments, group references and asset containers under grants. Native retires replaced Boolean child-reference strings under grants. Existing geometry/SVG oracles must still pass, and tests must prove source/result independence by retiring a successful result without changing the source.
