# Retained Command Host Acceptance

The source audit confirms that retained_command::Publish transfers the sealed DownloadOutput through complete_download before the host begins normal final close. Cancellation before that publication must withhold the output; a committed host download cannot be retracted afterward. This is the existing host lifecycle, not evidence that private resources closed before output publication. Completed expensive child owners should be retained in distinct typed slots throughout work and physically released only in the later caller-funded close_step. StepContext has fuel/deadline but supplies no capacity or release currencies, so an internally self-funded cleanup adapter cannot establish caller authority for large releases.

The Work trait has moved to RetainedCloneGrant, but the surrounding ArtifactRetainedCommandJob still implements the obsolete two-currency InteractiveJob close interface and shallow retire_one drops. Its raw buffer releases claim initialized length, then zero allocation bytes; that is not physical backing authority. Generic command/snapshot/config owners now have RetireOwned bounds, but Emit, EphemeralEmit, HistoryView, context and completion need genuine facets/captured producer factories, not an unmeasured generic drop. Source jobs alone cannot provide complete native acceptance until the shared host shell is coherently migrated.

Root has accepted this integration lane after scene-plan/GPU evidence. No host migration was yet written or tested, and no compatibility alias or unlimited-grant bridge is authorized as a completion substitute. The fresh native Draw check is running to establish the actual current shared kernel boundary.
