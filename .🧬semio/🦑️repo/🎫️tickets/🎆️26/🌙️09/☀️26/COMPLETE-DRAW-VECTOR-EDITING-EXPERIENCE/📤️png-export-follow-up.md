# Current PNG Export Follow-Up

The current DrawingIntoPng serializer still projects DrawingSnapshot through drawing_document_to_semio_drawing and calls the neutral stdio drawing PNG encoder. Its declared fidelity is Lossy. The source explicitly states gradients, blend modes and fill rules have no equivalent in that projection. The serializer body synchronously performs this work inside its async entry and does not expose operation progress or cancellation. No PNG source changed in the current lasso stage.

The Draw artifact already has its own RasterSceneJob with resolved path paints, groups, affine image sources, bounded asset decoding and progress. Its resolved_scene_input bridge accepts only Group/Path/Image and explicitly refuses semantic Text together with unresolved algorithm content; semantic text must be shaped into an accepted owned raster/path representation rather than silently projected. The permanent export route must preserve those authored semantics rather than reduce them before rasterization, and combine cooperative vector resolution, scene paint/raster, bounded PNG encoding and host download completion. Existing third-party pixel/PNG/SVG oracles can validate appearance and bytes, followed by actual browser download and reopen journeys. Shaped text and native renderer parity remain required rather than inferred from fallback bounds.

## Current Export Ownership Audit

The existing neutral pixels PNG encoder already supplies PngEncodeJob with 4096 source-byte steps, progress, a private candidate and cancellation. A new synchronous encoder is unnecessary. The current Drawing exportDocument route is classified Migrated but uses DrawingWindowCommandWork to call the entire PDF/SVG handle in one step. Its extent admits on layer and asset counts only (4096 items); segment counts, text length and asset payload bytes do not enter that admission. Thus the classification alone does not establish bounded export work. The DocumentRasterJob producer resolves trace/Boolean work but still explicitly refuses semantic Text, and its cancellation clears partial children immediately instead of transferring their actual ownership into retirement. These concrete gaps must be repaired in the producer/retained export path before adding a PNG UI option. No export source was changed during component materialization.

## Existing Text Interfaces and Decode Ownership

The neutral 2D text module provides explicit CR/LF/CRLF line iteration and a documented font-independent fallback extent; it does not shape glyphs. Existing compiler_text wraps rustybuzz/ttf-parser behind owned Font/GlyphRun/SVG-path APIs, but shaping is whole-run synchronous and its current font policy is compiler-specific. The UI renderer TextSystem already wraps parley/swash/fontique behind owned font handles and glyph planes with bundled Anta/Kelly Slab/Share Tech Mono/Noto Emoji fallback fonts. That interface is the existing reuse candidate for owned shaped text, not a new public dependency on external shaper types. Draw's text document currently carries semantic content/x/y/size rather than an accepted font/glyph plan. Exact font policy, canvas/export agreement and glyph ownership require schema-first laws before changing raster admission.

The encoded image prerequisite also remains incomplete: ImageDecodeJob.cancel currently invokes BinarySourceJob.cancel and PngDecodeJob.cancel, then clears the pixel candidate. PngDecodeJob owns an actual Inflater and private palette/ranges/scanline/output buffers; its PngInflater destructor attempts four retained close steps. A future RasterScene retirement must adopt these actual decoder owners and drain them before claiming terminal-empty, alongside existing PathRaster/AffineImage/Composite retirement cursors. Merely adding a raster parent cleanup loop would leave this nested cancellation gap.
# Shared Font Ownership Boundary

The exact existing font owner is framework/🔨️modules/🖱️ui/🖌️render/🖋️text/🦀️.rs. TextSystem::shape:401 and shape_paragraph:461 synchronously build whole Parley layouts. ShapedGlyph and ShapedText expose only repository-owned FontHandle, glyph ids, positions, advances, metrics and paragraph direction; underlying font blobs and atlas ownership remain private. FontSource polls host-provided bytes without blocking, with explicit pending/ready/failed states. The owner embeds Anta, Kelly Slab, Share Tech Mono and partitioned Noto Emoji outline bytes.

This is a reuse seam for consistent canvas/export font identity, not an already cooperative Draw export implementation. A glyph plan must retain its actual font-byte owner, stable identity and complete shaping context through outline/raster work, cancellation and bounded retirement. Splitting arbitrary code units into independent shaping calls would change shaping and cannot substitute for bounded ownership. No font or export production source was changed during the utility acceptance stage; all current findings are source inspection, not exported text pixels.

The exact encoded-image child is framework/🔨️modules/🔲️pixels/🖼️image/📥️decode/🦀️.rs. ImageDecodeJob::cancel calls release, which cancels and immediately discards its real BinarySourceJob and PngDecodeJob, then frees its private pixel candidate. PngDecodeJob::release likewise discards its inflater and source; the inflater Drop currently tries four actual close_retained_step calls. Draw scene/📷️raster/🦀️.rs already retains real PathRasterRetirement, AffineImageRetirement and CompositeRetirement during successful work, but clear/cancel drops those same child owners and its image maps immediately. The framework's existing WorkRetirementCounter is already used by pixels sampling/compositing, so no new generic cleanup abstraction or runtime library is needed. A new image/export parent must adopt and advance the actual child and map owners on failure/cancellation; an extra counter after dropping them would not prove bounded cleanup.

BinarySourceJob is located at framework/🔨️modules/🚪️io/🔢️binary/📥️source/🦀️.rs:17 and currently owns one Arc<String> plus private binary/output Vec<u8> buffers. Its cancel/release clears those directly. The repair should account for actual owned buffers/child close states and one map entry per grant, rather than invent byte-by-byte retirement loops for trivial u8 elements. IO is lower-level than 2d: do not introduce an IO→2d dependency merely to reuse the pixel retirement counter. Source admission, publication, cancellation and private payload ownership need neutral fixture cases before a producer/export integration change.
