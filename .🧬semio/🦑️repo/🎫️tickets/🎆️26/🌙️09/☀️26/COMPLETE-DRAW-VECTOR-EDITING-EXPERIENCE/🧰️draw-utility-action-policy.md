# Draw Utility Action Policy Defect

The actual independently described materialized Draw editor manifest declares allowsActionsWhileActive=false for all twelve canvas utilities: marquee, lasso, direct selection, node editing, pen, rectangle, ellipse, line, polygon, Boolean, trace and pan. ShellHelpers.windowActionPaneNode reads that declared flag and disables every palette action while a utility is active. Thus explicitly arming a selection tool, or returning to selectDirect through a completed drawing gesture, blocks the action palette by its current catalog contract. This is a concrete emitted-descriptor and host-source result; an actual pointer/keyboard journey remains pending.

Drawing utility declarations should allow document actions while the persistent tool is armed. Work-in-progress exclusion/cancellation belongs to genuine operation/draft ownership and authority, not the idle selected tool. The next source change must have neutral declared-utility policy cases and an actual native app-manifest law before marking this repaired; a fresh independently described module must then declare the intended flags. The initial-tool mismatch is a separate contract repair and must not be fixed by arming a default selection utility while this false action gate persists.
