### Explicit Fit Follow-Up Design Constraints

Current-source inspection confirms no end-user Fit Drawing or Fit Selection controls; setCameraZoom is internal. Do not implement a one-shot `framed=false` reset: the renderer already consumes revision 0 once, and the 120 ms debounced camera publication can race a newer fit request. ### Native Attachment Transaction Audit — 2026-09-27

Native run_session_app_switch still creates and retires instances without document capture. The new bridge capture is ready at the API layer, but binding transfer cannot be reduced to updating ShellSyncChannel.instance_id. ShellSyncChannel stores the exact plugin/instance/binding generation and live actor event receiver; it currently does not retain the opening schema and persistence-binding descriptor needed for rollback. Hub execution-target leases are bound to the requested surface, and the document actor's opening configuration includes its actor identity. Reusing the editor's actor as a viewer without changing this authority would preserve the wrong surface contract.

prepare_document_open checkpoints the currently mounted session and detaches its backbone before resolving the next execution target. Calling it with a temporarily substituted session would checkpoint the wrong instance. open_document also seeds the guest from the hub checkpoint, which would overwrite an already-restored archive if blindly called after role restoration. The complete native integration needs a retained, cancellable handoff that checkpoints/captures the source under its original owner, preserves the opening descriptor, restores an unpublished successor, acquires the target surface's attachment authority, and rolls back both guest and host ownership on failure before publication. The existing ShellDocumentOpening detached-work pattern provides the progress/cancel mechanism and should be extended rather than holding the frame loop through long awaits. No partial native switch was wired that would silently drop a shared binding.
