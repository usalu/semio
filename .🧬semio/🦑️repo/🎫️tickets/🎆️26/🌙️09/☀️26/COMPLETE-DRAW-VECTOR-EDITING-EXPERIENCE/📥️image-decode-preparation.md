## Current-State Revalidation — Decode Continuation

Previous affine continuation was progress: authoritative schema/implementation/consumer/test/launch source changed and full/focused terminal checks passed. No preceding verification job remains live.

Further native source inspection found an existing `PngScanlineDecoder`, previously missed when restricting discovery to the PNG subtree. It streams non-interlaced inflate output through the first-party Inflater, but construction scans chunk headers/metadata and Adam7 decoding is eager; a full row is unfiltered/unpacked in one step. The existing one-shot `decode_png` still uses a separate synchronous RFC1950 implementation. No framework TypeScript inflate implementation was found; stdio TS facades are empty. A new owned full-image candidate needs strictly bounded all-pass preparation and decoding; its native color/scanline helpers should reuse the nearby existing PNG primitives. This is a different ownership contract from row streaming, not a legacy API adapter.

The decoder contract will preserve source sample RGB even when alpha is zero, scale low-bit-depth samples, and take the high byte for 16-bit-to-RGBA8 conversion as the current native PNG primitive does. Encoding/image color management remains separate from source sample reconstruction. Planned validation uses neutral complete PNG byte fixtures, test-only pngjs/Sharp and native png decoding; raw/stored, fixed/dynamic Huffman blocks, all PNG color types/depths, five filters and Adam7 must be covered. Input bytes/chunk count/output pixels and expanded scanline length are bounded before candidate publication; checksum/truncation/ordering failures are sticky. The real end-user export producer remains required after decoded candidate integration.

Primary format checks were read from [PNG chunk/filter/interlace rules](https://www.w3.org/TR/png/), [RFC1951 DEFLATE](https://www.rfc-editor.org/rfc/rfc1951.html) and [RFC1950 zlib](https://www.rfc-editor.org/rfc/rfc1950.html). PNG requires consecutive IDAT and first/last IHDR/IEND; 16-bit transparency compares full source samples before scaling. PNG decoders treat a future reserved-bit chunk name as unknown, so unknown ancillary chunks remain accepted and checksummed. The high-byte 16-bit conversion is explicitly permitted by the PNG sample-depth rules. Dynamic streams may have an empty distance tree when they contain literals only. The independent references stay test-only; no third-party runtime implementation is introduced.
