# Drawing Text Producer Plan

Current pure document raster preparation refuses text because no font-resolved path/sample producer is installed. Current picking uses drawing_text_fallback_extent (scalar count times size times 0.6), so it does not match actual glyph metrics. Both limitations must be resolved for a complete image-editing experience; PNG export cannot silently omit text or paint generic rectangles.

The existing first-party UI CPU TextSystem at framework/ui/render/text provides FontFamilyChoice, TextStyle, ShapedText and ShapedGlyph without exposing its underlying Parley/Swash/Fontique types. Its FontSource seam supports requested custom fonts. Its shape/layout and per-glyph rasterization are synchronous whole-run/whole-glyph operations, with an owned atlas and caches. The current native wgpu FontAtlas is a separate per-scalar source with authored Anta/Share Tech Mono assets and pair kerning. Neither is currently a retained document-raster job owner. Importing the entire retained UI engine into a portable document component would couple its GPU/platform dependencies unnecessarily.

The typeset module wraps Typst/usvg behind a first-party interface but explicitly provides no engine on wasm32-wasip2. It cannot serve as the cross-platform portable document text producer. The first-party 2d module currently contains shared newline laws and fallback extents only; repository search found no authored pure TTF outline parser there. Existing SFNT font resources are present under framework/assets/fonts, including Anta Latin/Latin Extended and glyph fallback families. The existing opentype.js installation and ttf-parser dependency in the workspace lock can serve as test-only independent oracles; no new external runtime dependency is required by the test approach.

The portable long-term producer should live under first-party 2d/text or an explicitly neutral font-codec module, with a schema-first FontOutline admission and a retained glyph/run job. Its input is an admitted font-byte source and authored text/style. Table-directory reading, character mapping, metrics, contour/composite decoding, kerning/shaping and path publication consume explicit work grants. Owned text, tasks, contours and rejected font bytes must use actual native retirement authority. The same producer yields real bounds for picking and outlines for vector raster/export, with identical explicit EN/DE font selection across hosts.

The test matrix must compare Latin and German compound/accented glyphs, spacing/kerning, multiline baselines, reflected/sheared transforms, malformed/cyclic font data, glyph and depth limits, tiny grants, cancellation and retained allocation return. A permissive unsupported-format fallback or a cached synchronous whole-run shaper must not be represented as bounded portable work. Real font assets and the independent oracle establish geometry; synthetic fixture polygons cannot establish text fidelity.

This is an execution design record, not a claim that text rasterization or exact text picking is implemented.

## Verified Primary Font Contracts

Microsoft’s [glyf specification](https://learn.microsoft.com/en-us/typography/opentype/spec/glyf) distinguishes direct quadratic contours and recursive component glyphs. Composite references form an acyclic graph; a parser must enforce cycle/depth limits rather than trusting advertised metadata. Glyph header bounds enclose control points and need not tightly bound the painted curve. The [loca specification](https://learn.microsoft.com/en-us/typography/opentype/spec/loca) supplies indexed glyph offsets, and the [cmap specification](https://learn.microsoft.com/en-us/typography/opentype/spec/cmap) defines character-to-glyph mapping. The [hmtx specification](https://learn.microsoft.com/en-us/typography/opentype/spec/hmtx) is the metric authority, so scalar-count sizing cannot substitute for authored advances. These primary pages were opened directly, with no web search. No font parser implementation or parity pass is claimed.

## Portable Execution Design

The new neutral producer will parse actual existing SFNT/TrueType bytes in first-party 2d/text. Directory, Unicode cmap (formats 4/12), hmtx metrics, loca/glyf contours and composite references advance through explicit work units. Quadratic outlines become real PathSegment owners; original font input, scratch points/frames and completed output remain retained until caller-funded physical close. Missing glyphs can select another admitted first-party catalog face; a missing or unsupported face is explicit failure, never a substitute rectangle.

The existing native UI font choice is Anta for sans and Share Tech Mono for mono, with actual Noto Emoji outline fallback. UI pair shaping disables liga/clig/calt and reads actual font pair positioning. The portable run must state that same policy and provide matching kerning; scalar-count fallback is insufficient. Draw's authored baseline law remains y + size and 1.2 size per newline, while glyph positioning uses actual font advances and outlines. Existing text semantics stay persisted; only the resolved geometry plan receives glyph outlines. Picking/PNG/SVG/PDF then consume one genuine geometry source.

Primary contracts re-opened without web search: [cmap](https://learn.microsoft.com/en-us/typography/opentype/spec/cmap), [glyf](https://learn.microsoft.com/en-us/typography/opentype/spec/glyf), [GPOS](https://learn.microsoft.com/en-us/typography/opentype/spec/gpos). Format 12 is preferred where supported; format 4's glyph offsets are relative to each offset word. Composite placement must retain actual parent/child points and enforce cycles/depth. Pair-position formats 1/2 and legacy kern are required for shipped face parity; no external parser is being added to runtime.

Native fonts can borrow the exact immutable assets already embedded by the UI. TypeScript callers must supply admitted actual byte sources through a first-party font-provider seam, with loading outside the bounded parser. Tests use the same actual assets and independent opentype.js/ttf-parser. Cross-platform font acquisition and mounted consumer wiring must be verified before full acceptance.
