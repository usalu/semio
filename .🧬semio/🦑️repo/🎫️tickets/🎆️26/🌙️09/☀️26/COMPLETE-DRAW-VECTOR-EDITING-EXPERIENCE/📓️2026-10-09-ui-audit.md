## Existing UI That Should Be Extended

The inspector already includes name, visible, locked, opacity, all sixteen blend modes, fill winding and enablement, stroke enablement/color/width/cap/join/dash, position, scales, rotation in degrees, shear, group isolation, text content/size, trace threshold/simplification and Boolean operation. It intersects field availability across multi-selection and displays mixed values. Numeric and color controls are labeled; controls commit on blur. Locked layers disable changes except visibility/locking.

Dedicated path controls already expose anchor and handle coordinates, split/delete/convert segments, reverse, open/close and join contours. Fill controls already expose none/solid/linear/radial paints, coordinates, alpha and gradient stops. Selection actions already expose grouping, ungrouping, duplicate/delete, stacking, alignment/distribution and shape-to-path conversion. Do not duplicate these as a new editor shell.

## Concrete Usability Gaps

1. `fields` has no `DrawingLayerNode::Shape` branch: rectangle dimensions/corner radii, ellipse radii, line endpoints and polygon geometry cannot be edited with dedicated controls. Generic transforms are not sufficient authored geometry controls.
2. `fields` has no `DrawingLayerNode::Image` branch: image source/size and image-specific options lack visible controls. Creation manifest declares image kinds, but the layer panel add rows omit image and ellipse/line/polygon/trace. The catalogue may provide these elsewhere; avoid claiming total creation absence.
3. Text only exposes content and size; inspect schema-supported font/layout fields before implementing richer typography.
4. Empty inspector only says to select a layer; artboard/document options are absent there.
5. PNG export is absent in `exportDocument`; prior acceptance identifies synchronous lossy raster serialization and faithful cooperative export as unresolved.
6. Import action invalid input is silently ignored. Use structured faults with translated user-facing labels and retain the existing mutation/event pathway.
7. Runtime acceptance remains required for keyboard labels/focus, creation, transforms, node dragging, undo/redo, downloads, alpha-aware image selection, and progress/cancellation. This source audit cannot establish their behavior.

## Ownership and Hooks

`drawing_active_utility` resolves the addressed window, then focused window, then flat active id, then selectDirect. Utilities are host-owned per concrete window. Manifest utilities are selectMarquee, selectLasso, selectDirect, editNodes, pen, shapeRect, shapeEllipse, shapeLine, shapePolygon, booleanCombine, trace and transformMove. They are assigned through window_kind_utilities and an initial selectDirect utility. Extend this arrangement for canvas-local modes; retain cross-window commands/tools for document operations.

UI bindings use `drawing_play_action`/ActionFactory, `ui_value_map`, `ui_value_text`, `ui_value_list`, `ui_value_number` and bounded framework UiValue builders. New semantic operations need command decode/dispatch, bounded proof catalog registration, public argument schema and durable mutation/diff/inverse authority integration. Do not bypass those with direct state changes. Existing artifact/window split distinguishes durable document from persisted camera config and ephemeral gesture/transient state.
