## Public Contract Risk — Ordinary `Drop` Is Outside the Explicit-Close Protocol

The public cursor protocol only bounds work when a caller drives `begin_close` and `close_step`. It does not prevent ordinary Rust destruction of a partially active cursor. For example, [`BoxCursor`](</Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🧬️retained-clone/🦀️.rs:664>) keeps its active child, copied value, and output in ordinary owned fields; the bounded retirement path starts only at [`close_step`](</Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🧬️retained-clone/🦀️.rs:754>). There is no `Drop` implementation for core or generated cursors. A direct low-level consumer can therefore abandon a deep partial cursor with `drop(cursor)`, invoking normal destruction outside any item or byte grant.

This is a low-level API contract-enforcement risk, not evidence that a production cancellation route bypasses close: the intended store/session protocol is explicit close, as for the existing retained sessions. The required integration is a job owner that retains its cursor through cancellation, error, rejection, and supersession, drives close to terminal, and proves this against a real `SnapshotRead`. No global retirement side queue or silent leak follows from this observation.
