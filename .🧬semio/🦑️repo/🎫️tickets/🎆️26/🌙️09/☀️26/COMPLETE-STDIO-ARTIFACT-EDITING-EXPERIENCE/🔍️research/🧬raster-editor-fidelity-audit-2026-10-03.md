# Raster Editor Fidelity Audit

Date: 2026-10-03  
Scope: read-only inspection of the shared raster-region planner, PNG retained adapter, BMP canonical/import/export/Details/primary routes, and existing BMP oracle. No production files changed and no native command was run. Root reported source green2 `97/97` with `479` assertions; native raster and PNG gates remain unverified by this audit.

## Decision

The shared RGBA8 region planner is a good PNG dependency for checked geometry. It must not be treated as BMP's canonical pixel owner: BMP's actual plane can be indexed, packed, masked, padded, and oriented differently from canonical RGBA8. PNG cancellation needs to hand its bounded patch to the framework's existing incremental `Vec` retirement cursor so that the mounted 16 KiB close grant can make progress without cutting the 256 KiB patch capacity.

BMP cannot honestly claim general natural editing or round-trip fidelity. The current `v3/*` decoder accepts bitfields and extended DIB headers that its snapshot cannot own, then silently serializes a different 40-byte BI_RGB/24-bit file. The next coherent cut is one schema-first, byte-authoritative BMP document model with explicit per-standard profiles before a BMP paint command or canvas UI is added.

## Findings

### P1 — Accepted BMP representations are flattened and silently rewritten

`BmpSnapshot` owns eleven BITMAPINFOHEADER fields, palette entries, and decoded RGBA8 pixels only; it has no file header, mask, raw pixel-plane, extension, gap, or trailing-byte field ([snapshot](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🧬️schema/📸️snapshot/🦀️.rs#L52-L86)). The decoder nevertheless accepts every DIB size at least 40 and `BI_BITFIELDS` 16/32, reading masks from either the post-header area or the extended header ([decode](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🚪️io/🦀️.rs#L175-L264)). Those masks only produce RGBA pixels; they never enter the snapshot.

`encode_bmp` chooses indexed output only for 1/4/8-bit snapshots with a palette. Every other snapshot, including a decoded 16/32-bit `BI_BITFIELDS` document, goes through the hard-coded 24-bit BI_RGB writer ([encode selection](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🚪️io/🦀️.rs#L387-L397), [direct writer](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🚪️io/🦀️.rs#L476-L516)). Both writers emit a DIB size of 40 and rebuild the file header with zero reserved fields and a computed offset ([indexed writer](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🚪️io/🦀️.rs#L421-L452), [direct writer](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🚪️io/🦀️.rs#L480-L500)). This loses bit masks, alpha/sample precision, extended DIB fields, `bfSize`, both reserved file-header fields, the original data offset and any gap/trailer bytes.

The bug is reachable through Details. `ChangeHeaderFieldsMutation` accepts changes to `headerSize`, `bitsPerPixel`, `compression`, and other derived wire facts without validating a supported profile ([mutation](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🧬️schema/🧬️mutations/📐️change-header-fields/🦀️.rs#L10-L65)); the writer ignores several of those values. This is a silent authority split between editable snapshot fields and emitted bytes.

**Required correction:** do not add a BMP region action to this snapshot. Route an input to a profile whose DIB-header size, compression, masks, palette form, pixel-plane encoding, and valid edit operations are declared together. Reject a file outside the selected standard/subset before constructing an editable document; do not accept it under `v3/*` and later normalize it.

### P1 — RGBA destroys indexed identity, and current pixel replacement changes formats implicitly

For indexed BMP, the decoder reads a palette index, immediately resolves it to RGB, and writes alpha `255` into `pixels` ([indexed decode](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🚪️io/🦀️.rs#L294-L303)). A file with duplicate palette entries consequently has distinguishable source indices that collapse to one RGBA value. The indexed writer builds an RGB-to-index map with first-entry-wins behavior ([re-index](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🚪️io/🦀️.rs#L408-L465)); a no-op save can remap every use of a later duplicate to the first entry.

`ReplacePixelDataMutation` further promotes an indexed document to 24-bit BI_RGB when a replacement RGB value is absent from its table ([replacement rule](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🧬️schema/🧬️mutations/🔲️replace-pixel-data/🦀️.rs#L57-L76)). Although documented, that is still an implicit storage conversion, not a reversible pixel-plane edit. It is incompatible with an editor that promises exact source ownership.

**Required correction:** own an index plane for indexed profiles and require an explicit palette index for indexed painting. An RGBA picker may resolve to an index only when exactly one palette entry matches; otherwise it must ask for the index or refuse. Any change of storage form belongs to a named, previewable `ConvertPixelStorage` event with its own inverse; region paint must never promote, quantize, or choose a duplicate index.

### P1 — Source and preview swallow serialization failures; decode also has no admission boundary

The source printer converts any `encode_bmp` error into an empty binary body with `unwrap_or_default` ([source codec](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🧬️schema/📸️snapshot/🦀️.rs#L119-L139)). The main image window repeats the same failure-to-empty-preview behavior ([main window](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/✏️editor/🎭️modes/✏️edit/🪟️windows/🪟️main/🦀️.rs#L18-L26)). This breaks the `ArtifactDsl` contract that printed text reparses to an equal snapshot ([contract](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️.rs#L6086-L6094)) whenever generic Details yields a non-encodable snapshot. A Details edit must either emit a valid profile-aware event or refuse before state changes; it cannot leave an invalid snapshot for a view to erase.

The import decoder calculates row and RGBA allocation sizes from untrusted dimensions without checked arithmetic or a byte/pixel admission limit ([row size](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🚪️io/🦀️.rs#L88-L95), [allocation and offsets](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/🚪️io/🦀️.rs#L284-L339)). A tiny hostile header can request impossible `width × height × 4` storage before the first truncated-row check. The declared region planner cannot repair this because it receives an already allocated `BmpSnapshot`.

**Required correction:** preflight all header/range/stride products with checked arithmetic against configured source, pixel-plane, decoded-view, and output limits before allocation. Make parsing/preview construction a bounded job that can report progress and close without publishing. Preserve an invalid edit as its draft plus diagnostic; never synthesize empty source or preview bytes.

### P1 — Current primary route materializes and re-encodes whole images synchronously

The BMP primary window encodes the full snapshot on every render ([main window](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/✏️editor/🎭️modes/✏️edit/🪟️windows/🪟️main/🦀️.rs#L18-L26)). It also mounts the generic Details renderer ([editor route](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🪟️bmp/🏅️standards/🔖️v3/🪆️subsets/✳️any/✏️editor/🦀️.rs#L204-L208)). `BmpSnapshot` has no path-projection implementation, so the default `ToValue::value_at_path` materializes `self.to_value()` ([default](../../../../../../../../🧰️framework/🔨️modules/🌱️value/🔁️codec/🦀️.rs#L46-L51)). `DslSnapshotDetailsProvider` calls those reads for every shape/scalar/key ([provider](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/📇️registry/🧬️contract/✏️editing/🪟️details/🦀️.rs#L997-L1012)). For a large RGBA raster, merely opening or updating Details copies the full pixel value repeatedly. This violates the editor's bounded, interaction-friendly requirement independently of fidelity.

**Required correction:** make the canonical byte owner expose a lazy `BmpDetailsProjection` for small metadata and plane dimensions only. Keep byte planes out of generic tree editing. Build/cached-preview the current canonical bytes in a cancellable worker; the primary window consumes that immutable preview result instead of synchronously re-encoding the document.

### P1 — PNG cancellation blocks forever under the mounted close grant

`PATCH_PAYLOAD_BYTES` permits each retained patch to allocate up to 262,144 bytes ([PNG command](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📷️png/🏅️standards/🔖️1.2/🪆️subsets/✳️any/✏️editor/🎭️modes/✏️edit/🎮️commands/🩹️patch-pixel-region/🦀️.rs#L19-L24)). For example, the existing cancellation law creates a `1024×512` raster. Its first planned patch is 64 full 4,096-byte rows, thus a 262,144-byte `Vec` ([planner](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/📇️registry/🧬️contract/✏️editing/🖼️raster/🦀️.rs#L49-L57), [law setup](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📷️png/🏅️standards/🔖️1.2/🪆️subsets/✳️any/✏️editor/🧪️tests/🔬️unit/🦀️.rs#L109-L131)).

On cancellation the work measures the `Vec` capacity, then returns `Blocked` unless the supplied byte grant can free that entire allocation ([close](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📷️png/🏅️standards/🔖️1.2/🪆️subsets/✳️any/✏️editor/🎭️modes/✏️edit/🎮️commands/🩹️patch-pixel-region/🦀️.rs#L177-L192)). However, mounted typed operations cap every job close turn at `JOB_PAYLOAD_PAGE_BYTES`, which is 16,384 bytes ([page constant](../../../../../../../../🧰️framework/🔨️modules/🧵️job/🦀️.rs#L405), [mounted close driver](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs#L20720-L20725)). The test bypasses that real boundary by passing `PATCH_PAYLOAD_BYTES` directly. In production, the work reaches its mutation owner and remains `Blocked` forever.

**Required correction:** on the first cancellation turn, move the LIFO `PatchPixelsMutation.pixels` out with `mem::take`, construct its existing `RetireOwned::retirement()` cursor, and retain that one `Box<dyn RetirementCursor>` in the worker. Forward each close grant to it: `Bytes(n)` reports `Pending { released_items: 0, released_bytes: n }`; `BudgetExhausted` reports `Blocked`; after terminal `Complete`, drop the cursor and pop the empty mutation on a later item turn as `Pending { released_items: 1, released_bytes: 0 }`. This is the repository's established no-drop `Vec<u8>` retirement behavior ([vector cursor](../../../../../../../../🧰️framework/🔨️modules/🌱️value/♻️retirement/🦀️.rs#L109-L145)): it truncates logical bytes to the grant and frees the now-empty owner only when the cursor is terminal. It preserves the current 256 KiB patch and 128-patch admission. Add an end-to-end mounted cancellation law using the normal 16 KiB driver, asserting terminal-empty; the present direct law is insufficient.

### P2 — Whole-row patches are bounded but not changed-only allocations

For a row that fits the patch budget, the planner copies the full source row and paints only the selected byte interval ([materialization](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/📇️registry/🧬️contract/✏️editing/🖼️raster/🦀️.rs#L66-L86)). The neutral `middle-rows` fixture therefore produces one 24-byte replacement to change two four-byte pixels ([fixture](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/📇️registry/🧬️contract/✏️editing/🖼️raster/🧫️fixtures/🔣️.json#L3-L5)). This is correct under the frozen source and non-overlap rules, but it is whole-row-preserving allocation, not changed-only allocation. It inflates retained/inverse bytes and makes a thin tall stroke hit the 128-item ceiling based on image width rather than touched pixels.

**Required correction:** decide the contract explicitly. If a contiguous `PatchPixels` event remains the representation, describe and test its whole-row preservation and preflight its real retained bytes. If the user promise is changed-only allocation, introduce a lossless sparse region event whose source payload contains only selected spans and whose inverse is derived against the frozen snapshot; it must remain one bounded, cancellable durable operation rather than one event per pixel row.

### P2 — TypeScript does not have Rust's opaque-plan boundary

Rust keeps `RasterRegionPlan` fields private and only `new` can construct a plan ([Rust planner](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/📇️registry/🧬️contract/✏️editing/🖼️raster/🦀️.rs#L30-L86)). TypeScript exports a fully structural `RasterRegionPlan` interface and `rasterRegionPatch` accepts it without a provenance check ([TypeScript planner](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/📇️registry/🧬️contract/✏️editing/🖼️raster/🟦️.ts#L2-L49)). `Object.freeze` protects a returned plan but cannot prevent a caller from passing a forged shaped object with inconsistent geometry.

**Required correction:** return a module-private branded class or a `WeakSet`-registered opaque plan and reject foreign plans. Add the same fixture-level law in both twins: a forged plan cannot produce a byte patch. Also add a mounted cancellation assertion that records the 16 KiB logical releases and reaches terminal-empty; current PNG coverage checks blocking and eventual completion but not the real driver boundary ([PNG cancellation law](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📷️png/🏅️standards/🔖️1.2/🪆️subsets/✳️any/✏️editor/🧪️tests/🔬️unit/🦀️.rs#L109-L133)).

## Shared Raster/PNG Assessment

The planner checks complete RGBA8 length before planning, bounds with checked endpoint addition, and caps patch size/count ([planner](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/📇️registry/🧬️contract/✏️editing/🖼️raster/🦀️.rs#L38-L87)). The PNG adapter builds a plan before work and emits each bounded `PatchPixels` mutation ([PNG worker](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📷️png/🏅️standards/🔖️1.2/🪆️subsets/✳️any/✏️editor/🎭️modes/✏️edit/🎮️commands/🩹️patch-pixel-region/🦀️.rs#L146-L170)). Its action is registered on the actual retained route and cannot fall through to the synchronous handler ([route](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📷️png/🏅️standards/🔖️1.2/🪆️subsets/✳️any/✏️editor/🦀️.rs#L386-L428)).

The source binding itself is sound in the mounted route. The retained payload owns an `Arc` to the admitted snapshot and the job supplies that same immutable root to every work step ([payload](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🧵️retained-command/🦀️.rs#L218-L257), [work step](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🧵️retained-command/🦀️.rs#L539-L585)). Before publication, the framework compares the complete captured revision and validates its generation ([freshness gate](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs#L24231-L24234), [publication](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs#L31577-L31593)). A same-length later raster cannot be substituted by the planner's length check. Add a mounted native law that changes the raster to an equal length while the region job is in flight, then asserts stale publication refusal and zero modification of the later root.

The neutral fixture set is useful, but it covers only four success shapes and seven refusals ([fixture](../../../../../../../../✏️s/🔌️plugins/🗄️stdio/📇️registry/🧬️contract/✏️editing/🖼️raster/🧫️fixtures/🔣️.json#L3-L17)). Keep the source result distinct from native validation: the Rust law is authored but this audit did not run Cargo.

## Retained Close API Review

Do **not** lower `PATCH_PAYLOAD_BYTES` to the 16 KiB mounted close page. That would turn a currently admitted `4096×2048` full-region paint into 2,048 retained items instead of 128, even though the current `256 KiB` plan admits it exactly at the 128-item ceiling. It would also turn the admitted `3840×2160` 4K single-pixel gesture from 128 whole-row items to 2,160. The 4K one-pixel acceptance law is not enough on its own; the replacement must preserve the maximum currently admitted 128-patch rectangle as well.

`ArtifactCommandWork` has only `close_step` and `terminal_is_empty` ([trait](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🧵️retained-command/🦀️.rs#L158-L182)); `ArtifactRetainedCommandJob` forwards the page-sized grant ([forwarder](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🧵️retained-command/🦀️.rs#L693-L706)). That makes a local `RetireOwned` cursor the least-duplicated sound bridge: it already owns the moved `Vec`, reports logical byte progress, and its `Drop` assertion ensures the backing owner is not freed before terminal-empty ([cursor contract](../../../../../../../../🧰️framework/🔨️modules/🌱️value/♻️retirement/🦀️.rs#L6-L23), [vector implementation](../../../../../../../../🧰️framework/🔨️modules/🌱️value/♻️retirement/🦀️.rs#L109-L145)). Do not duplicate the raw-input truncation loop from retained-command; delegate to this shared cursor.

`RetainedCloneClose` is the wrong bridge because it wraps `ErasedSnapshotRetirement` and adds a `Result` layer that `ArtifactCommandWork::close_step` does not consume. `RetainedJobPayload` is also unsuitable: it is writable only through `StepContext`, which `ArtifactCommandWork::step` does not receive, and its operation budget is 256 pages / 4 MiB ([limits and writer](../../../../../../../../🧰️framework/🔨️modules/🧵️job/🦀️.rs#L440-L458), [writer](../../../../../../../../🧰️framework/🔨️modules/🧵️job/🦀️.rs#L745-L874)). It would silently reduce the current possible `128 × 256 KiB = 32 MiB` retained region payload.

Required native evidence: (1) drive the existing `1024×512` cancellation case through the normal mounted 16 KiB close driver, showing successive 16 KiB releases and terminal-empty; (2) retain the `3840×2160` 4K one-pixel acceptance law; and (3) add a `4096×2048` full-region preflight/close case proving the existing 128-patch capacity remains admitted rather than silently becoming a 16 KiB-page limit.

## Next Coherent BMP Cut

1. Replace `BmpSnapshot` with a canonical `BmpDocument { bytes }` (or equivalent immutable owned byte carrier) plus an ephemeral, checked `BmpLayout` parser. The bytes are the only persisted authority. Header fields, display RGBA, palette, index plane, masks, rows, padding, pre-pixel gap, and trailer are projections from named byte ranges; no decoded vector can compete with source bytes.
2. Dispatch exact standards/profiles before editing. `v3` must accept only its declared 40-byte BITMAPINFOHEADER profiles; headers 52/56/108/124 and OS/2 headers become their own standards/subsets. Within each profile, declare BI_RGB indexed `1/4/8`, BI_RGB direct `24`, and BI_BITFIELDS `16/32` separately with their required masks and plane layout. A profile outside the current subset is refused, never coerced.
3. Model the actual storage plane. Indexed profiles retain packed indices and every palette entry, including duplicate identities and reserved octet. Masked/direct profiles retain exact samples, mask words, row order, stride padding, and channel precision. RGBA is a display projection only. Region paint adapts the shared planner only after the profile maps a requested coordinate to lossless raw-plane edits; it is not an RGBA replacement shortcut.
4. Publish only profile-specific events: `PaintIndexedRegion { index }`, `PatchDirectSamples`, `SetPaletteEntry`, `SetDeclaredHeaderField`, and explicit `ConvertPixelStorage`. Each event changes declared byte ranges, checks the expected layout revision, has a byte-exact inverse, and is previewable/cancellable. Remove generic header/pixel tree writes from the primary path.
5. Add admission-aware import/preview jobs and a lazy Details projection. The primary preview should read current canonical bytes or a cached decode result; source details display parse diagnostics and profile metadata without serializing the plane.

## Losslessness Evidence Required Before Enabling BMP Edit

Add externally authored, language-neutral byte fixtures and a native oracle matrix. Each accepted profile needs (a) a no-op parse/persist/export byte digest equal to input, (b) a one-operation changed-range manifest proving every unaddressed byte is identical, (c) undo restoring the original digest, (d) cancel leaving the original digest, and (e) independent rendered-pixel evidence.

The minimum v3 matrix is: 24-bit BI_RGB with nonzero padding and file-header reserved fields; 1/4/8-bit indexed images including duplicate palette colours with distinct indices; 16-bit 5:6:5 bitfields; 32-bit bitfields with alpha; nonzero palette reserved octets; and an allowed pre-pixel gap/trailer. Fixtures with 52/56/108/124 DIB headers must prove that `v3` rejects routing; their own declared standards later need the same matrix.
