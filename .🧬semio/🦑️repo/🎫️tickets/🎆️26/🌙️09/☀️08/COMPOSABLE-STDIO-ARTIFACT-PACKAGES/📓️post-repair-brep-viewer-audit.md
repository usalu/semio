# Post-Repair BREP and Viewer Audit

## Scope and method

Read-only post-repair audit of the BREP tolerance contract, its schema mirrors and neutral oracle, plus the shared viewer fixture helper. No source, Git, formatting, native build, or Nx task was changed or run by this audit.

The geometry-15 and Value-algebra-2 failures are treated as the already-established separate baseline defects; this audit makes no algorithm finding about either.

### P1 — `BoundedViewerFixture<V>` drops V-declared lifecycle hooks before strict close

The wrapper correctly delegates document/config owners and disposers, the constrained no-presence/no-transient disposers, selected retirement factories, snapshot/config initialization, `handle`, and `render` ([`🦀️.rs`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:6721)-[`🦀️.rs`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:6791)). It uses fallback bounded owners/disposers only when V supplies none, which is appropriate fixture-only authority.

However, the same wrapper does not forward V's mounted-job maintenance/close/terminal hooks, snapshot-read hook, window-owner registration, preparation factories, transient-root retirement factory, child projection, or the other declared viewer hooks. `new_viewer::<BoundedViewerFixture<V>>()` therefore runs `ViewerApp<BoundedViewerFixture<V>>` ([`🦀️.rs`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:6804)), whose production adapter would forward those hooks only to the wrapper ([`🦀️.rs`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:25368)-[`🦀️.rs`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:25400)). The wrapper receives the `ArtifactViewer` defaults instead of V's overrides.

This weakens the intended generic guarantee: `close_registered_fixture_app` is strict (it propagates close faults, rejects blocked/input states, and asserts terminal emptiness; [`🦀️.rs`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:6445)-[`🦀️.rs`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:6465)), but it is closing the wrapper's default job lifecycle rather than any V-declared job lifecycle. Forward the omitted lifecycle and bounded-store hooks through `BoundedViewerFixture<V>` wherever the constrained associated types agree. This retains fixture-only store authority while preserving V behavior.

The actual assertion does invoke `ViewerApp::<V>::handle` ([`🦀️.rs`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:6816)), so it is not an empty-fixture command-path trick; it also closes before inspecting the result, with no swallowed close error.
