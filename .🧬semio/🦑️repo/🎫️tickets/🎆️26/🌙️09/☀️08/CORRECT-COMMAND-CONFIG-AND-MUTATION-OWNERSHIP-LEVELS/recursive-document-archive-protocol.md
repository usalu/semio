# Recursive Document Archive Protocol

## Implemented Schema and Wire Boundary

Channel version 16 adds `LoadDocumentArchive` and `ReadDocumentArchive` commands plus the correlated `DocumentArchive` frame. `DocumentArchivePack` carries the parent pack and SPR together with at most 1,024 `OwnedDocumentMemberPackEntry` values. Every entry carries a stable ordinal, a full artifact reference, a full recursive owner reference and its full member envelope pack. The former `LoadDocument`, `ReadDocument`, `LoadChildren` and `ReadChildren` commands remain available to their existing callers; the recursive persistence API uses the archive pair.

The Rust and TypeScript direct codecs share tags 32, 33 and 26. The TypeScript persistence codec prefixes an archive body with version 1 and rejects unknown versions or trailing bytes. A draft-07 JSON schema independently fixes the archive shape, identity fields, byte values and 1,024-member maximum.

## Retained Decode and Replacement

The generic paged Rust command decoder has a route-specific `PagedDocumentArchiveDecode`. It reads one bounded field per step, reserves the declared member vector before reading any member, crosses command-page boundaries without concatenating the transport pages, rejects counts above 1,024, and retains partially decoded fields for explicit close. `DecodedAppCommandOwner` transfers a completed archive or closes the archive fields through the same owner.

`VcsArtifactApp::load_document_archive` validates ordinals, identity bounds, owner-to-child equality and non-empty member envelopes before parent admission. Store's authoritative `.pack` + `.spr` parser reconstructs the typed envelope and validates history; a dedicated persisted-envelope boundary then requires the exact app schema and dialect before transferring it into the app-owned `ArtifactStoreInitializationJob`. This binary persistence route is separate from fresh JSON-envelope ingress. The loader drives the initializer to `AwaitingMembers`, pre-admits the exact member count, builds typed `MemberOpenRequest` values under the same operation and generation, transfers each full reference and owner through `OwnedDocumentMemberIngress`, seals the roster and drives `ActiveArtifactStoreReplacement` to terminal state. Publication therefore reuses the existing parent/member/content/coordinator/pin/window generation fence and displaced-owner retirement path. Once Store has returned a complete decoded envelope, an initializer refusal is retained in `ActiveArtifactEnvelopeDecode::rejected` and closed through the app's exact envelope owner bundle; every post-admission error is routed through `retire_artifact_envelope_load_exact` before the method returns.

## Persisted Parent Parse Boundary Audit

The transport correction does not yet make the complete parent decode bounded. `parse_document_pack` calls `parse_document_spr`; that function first calls the whole-file `decode_history`, then `parse_decoded_document_spr`. `DecodeOptions::default` applies protocol limits to frame recovery, but `decode_history_from` still accumulates the dictionary, edit-id table and complete `HistoryLog` in one async call. The next function decodes every forward and inverse operation into vectors, constructs mutation metadata and durable messages, replays all forward operations once for validation, constructs the complete envelope, validates it, and replays the applied cursor a second time. None of those loops consumes a `StepContext`, checks cancellation, or transfers a partial typed owner into a fail-closed retained shell.

The exact partial-owner failures are:

- a malformed operation after a valid prefix returns while already-decoded `Mutation` values, earlier `Edit` values, the initial snapshot and the current replay projection are ordinary locals;
- missing or mismatched metadata returns after forward and inverse operation vectors have been allocated;
- conflict, history-ledger, composition or durable-history validation can return after the complete typed envelope has been assembled;
- an unknown cursor edit or a mutation failure during cursor replay returns after the envelope and current projection exist;
- input byte length, total decoded operations and replay work have no archive-route admission receipt, and cancellation cannot interrupt any of these phases.

The retained implementation must replace that call with one operation owned from raw Pack/SPR admission through initializer handoff. It can reuse `MemberOpenRequest`'s sealed paged input and close ladder, `RetainedSprVerification` for one-byte framing/commit verification, the retained dictionary index and semantic identity witness, the domain snapshot decoder, and `ArtifactStoreInitializationRuntime`. The additional phases must decode one history record or operation under explicit item/byte fuel, stage every initial snapshot/mutation/edit/envelope/current projection behind the app's supplied retirement factories, check operation/generation/expiry/cancellation before and after each handoff, enforce exact byte/record/operation/replay limits before allocation, and close malformed-after-valid-prefix owners through the same retained operation. Full-history member envelopes need the same retained replay path; the current `InitialMemberStoreOpen` deliberately accepts only initial history and therefore does not yet prove nonempty child history restoration.

There is also an outer scheduling limit. `plugin_exchange` currently handles `LoadDocumentArchive` by calling `resolve_ready(instance.app.load_document_archive(...))` inside `with_instances_mut`'s exclusive instance borrow. No later command can acquire that instance to cancel the load while this call is in progress. The production completion shape therefore needs a seq-keyed retained archive-load operation: command admission transfers raw owners and returns/parks; maintenance advances one bounded phase; explicit poll/cancel and terminal acknowledgement release the operation. Merely adding `yield_once` inside the current method would cap one loop iteration but would not make the user-visible command cancellable.

`VcsArtifactApp::document_archive` generation-fences the parent and child-content roots while it exports the live member registry's stored references, recursive owners and full envelope packs. It sorts the result deterministically and faults if either generation changes during assembly.

`plugin_exchange` maps the new commands to those typed app methods. The production renderer handle and `AppChannelClient` expose archive load/read methods; reads update the existing parent pack/SPR cache and return a detached archive copy.

## Production Persistence Boundary Audit

The production folder path now carries versioned archive bytes as its persistence aggregate. `ShellHost` reads the live closure through `readAppDocumentArchive`, encodes it with `encodeDocumentArchiveBytes`, and sends `localDocumentArchive` after document-backbone commands. The browser worker validates the archive before staging or publishing it. Its SQLite and file drivers persist the exact blob, while the existing pack/SPR hashes remain derived root projections for descriptor identity. External reads emit `documentArchiveReplaced`; `ShellHost` decodes that exact archive and loads it through `loadAppDocumentArchive` under the existing latest-replacement owner. Identity and tutorial save/restore use the same archive boundary.

The native Store actor mirrors that vocabulary with `LocalDocumentArchive` and `DocumentArchiveReplaced`. Folder event-log and text drivers persist the exact archive, root text mirrors are derived only after strict decode, and appending root SPR history replaces `parent_spr` while retaining every member envelope unchanged. Native folder divergence emits the complete archive and WGPU decodes it before issuing `LoadDocumentArchive` through `ProgramBridge`. The native actor source awaits compilation in the registered archive target; no native persistence result is claimed yet.

The native archive target includes handcrafted root-to-child-to-leaf event-log and text-folder round trips. It also sends a valid recursive archive into the concrete actor, then presents a trailing-byte candidate, an unsupported version and an over-limit candidate. The actor must retain the exact previously accepted bytes; the mailbox preflight must reject unsupported and over-limit owners before enqueue. These laws are authored but remain unverified until the registered native route runs.

Every archive codec is version 1, exact/trailing-byte rejecting and bounded to 4 MiB before actor mailbox or storage publication. The shell retains the previous archive when a replacement is refused, stale or over limit because the replacement lane does not publish its candidate until the plugin load succeeds.

Hub bootstrap remains root-only. Its current descriptor and assembler transfer a root pack/SPR pair, so both browser and native actors wrap a successful hub bootstrap in an empty-member archive. Complete recursive hub durability requires the hub descriptor and assembler to transfer the opaque archive while retaining the root schema digest used for execution-target admission. This limitation does not apply to the implemented browser/native folder archive path.
