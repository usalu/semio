# Layout, Sequence, GIS Map, and Remodel Window Ownership

## Ownership result

- Layout Blueprint and Preview instances each own `active_page_id` and `camera` in separately registered exact `WindowConfig` owners. The Preview owner's `camera` is the former app-level `preview_camera`. Blueprint instances own `drop_preview` and `engagement_input` in exact `WindowTransient` owners.
- Sequence Main instances own `camera` and `orientation` in exact `WindowConfig`; Script instances own `last_run_json` in exact `WindowTransient`.
- GIS Map instances own layer visibility, camera JSON, render mode, vector style, LOD mode, and layer stroke scales in one exact Map `WindowConfig`; the app uses `NoConfig`.
- Remodel Model instances own camera and layer visibility, Frames instances own the frame cursor, and Report instances own the selected report table. The app uses `NoConfig` and `NoPresence`.
- Every address helper verifies the concrete `window_id` against the caller's registered `window_instances` and the exact owner kind.
- View commands publish only window lanes and preserve document Pack/SPR bytes.

## Cross-language contracts

- Layout, Sequence, GIS Map, and all three Remodel window owners have Rust, JSON Schema, GraphQL, TypeScript, and Protobuf facets.
- Pack decoders check envelope id, `Pack` component, and version 1 with `SemioEnvelope::matches_identity`.
- Neutral TypeScript oracles validate JSON Schema through Ajv and compare the owner implementation with independent `fast-json-patch` projections.
