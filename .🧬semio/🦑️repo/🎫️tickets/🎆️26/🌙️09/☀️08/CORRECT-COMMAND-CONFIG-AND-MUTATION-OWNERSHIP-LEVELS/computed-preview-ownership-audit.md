# Computed Preview Ownership Follow-up

## Confirmed Active Misclassifications

| Owner | Current field | Producers | Consumer | Required owner |
| --- | --- | --- | --- | --- |
| Procedural Generation2d and Generation3d | `generation_preview_text` in editor config and `SetGeneration` config mutation | generation command helpers evaluate the selected generation and write a whole-config snapshot | generate-mode preview window | app transient result, driven by retained computation; selection remains a separate local choice |
| Block3d | `brush_preview` in editor config and `SetBrushPreview` | hover-surface, leave-surface and place-vortex commands | world scene preview overlay | concrete-window transient gesture state |

The artifact and sparse-diff copies have already been removed. Their active config copies remain and must be moved; removing document copies alone does not complete their ownership correction.

Procedural has five copied `refresh_generation_preview` and `handle_generation` helpers per dimensional implementation. The helpers explicitly describe the value as ephemeral while storing it in config. They also set a temporary `FlowEvalSession` created for each command. The generate-preview renderer reads the persisted config string. A correct move must carry the result to an actual transient projection read by the renderer, keep computation out of render, and retain progress/cancellation for evaluation. The selected generation can be consumed by multiple generate windows and therefore does not by itself prove a single preview-window owner.

Block3d preview is a pose generated by the current surface hover and cleared on surface leave or placement. Different concrete windows must not overwrite each other. The shared window-transient API supplies the proper partition and publication generation; the existing app-config preview mutation and its schema/descriptor/routes must be removed together.

## Validation Required

Use language-neutral traces that prove a preview update leaves the document and config revisions unchanged, two Block windows retain independent preview poses, and leave/placement clears only the addressed window. Procedural completion/cancellation must publish or retire transient output without persisting a preview string. Native behavior and an independent existing JSON/patch evaluator should consume the same traces.
