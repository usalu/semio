## Concrete Retained Operation Shape

The command sequence is the stable operation identity. `LoadDocumentArchive` must transfer the decoded archive owner into an admitted fixed registry and return only an admission receipt. Separate poll and cancel commands address that sequence; a terminal acknowledgement is the sole removal authority. A new load cannot collide with a live or terminal-unacknowledged residue class. App close cancels every admitted archive operation and advances the same close ladder until the raw archive, parser, replacement handle, fault and terminal outcome are empty.

Maintenance advances one transition per grant: raw-byte preflight; parent SPR verification; retained dictionary and record decode; typed initial snapshot; one forward or inverse operation; one validation replay operation; envelope validation; one cursor replay operation; initializer handoff; replacement `AwaitingMembers`; one member page; one member open; closure validation/publication; and terminal cleanup. Every transition checks sequence, document generation, child-content generation, expiry and cancellation before and after moving an owner. The 4 MiB archive cap, 1,024-member cap, 8,192-record cap and exact decoded-operation/replay counters are admission receipts checked before allocation.

The parser owner must retain the raw Pack/SPR pages, initial snapshot, current scratch projection, current edit's forward/inverse vectors, completed edits, envelope and cursor projection in distinct optional slots. Each slot carries its app-supplied retirement factory. A failure after a valid prefix moves the primary diagnostic into the terminal result, begins bounded close on all occupied slots, and exposes the fault only after cleanup is terminal-empty. Parent and member envelope decoding use this same owner; the genesis-only `InitialMemberStoreOpen` is insufficient for recursive persistence.

## Production Channel Boundary

Three new commands address that exact identity: `PollDocumentArchiveLoad { seq, operation }`, `CancelDocumentArchiveLoad { seq, operation }`, and `AcknowledgeDocumentArchiveLoad { seq, operation }`. Poll returns one `DocumentArchiveLoad` frame carrying the operation identity, state (`pending`, `running`, `ready`, `cancelled`, or `fault`), completed/total work counters, and the terminal encoded fault when present. A terminal operation remains in its residue slot until exact acknowledgement; cancellation only marks it and never removes an owner. The browser and WGPU clients submit once, poll across separate exchanges so reactor maintenance can run, request cancellation when their caller is cancelled, then acknowledge both success and failure after observing the terminal frame.

App close marks every archive operation cancelled and drives the same retirement ladder before the document Store detaches.
