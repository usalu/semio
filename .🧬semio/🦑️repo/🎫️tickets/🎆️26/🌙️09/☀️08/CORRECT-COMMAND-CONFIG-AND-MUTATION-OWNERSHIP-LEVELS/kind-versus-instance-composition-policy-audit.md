# Kind Versus Instance Composition Policy

Read-only inspection found a further abstraction violation in root `📜️script.ts::policyChildSlotKindDagBreaches`. It invents subset-qualified kind candidates from directory names, picks the first owner for each kind, then rejects cycles in that graph. Canonical Stdio metadata makes Kit→Object→Mesh references all target `s.stdio.semio`; the policy can consequently reject valid finite trees or choose the wrong subset owner based on scan order. Even a recursive same-dialect type such as a folder can own a distinct child instance without creating an ownership cycle.

The forest invariant belongs concrete document/member owner identities. The existing owned-document-closure neutral fixture already includes distinct Stdio members, duplicate-owner-edge, disconnected-cycle and self-cycle cases with independent Graphlib verification. Type declarations cannot prove those instance edges.

The static artifact-kind grammar policy has an additional stale claim that child references may legitimately add a fourth subset segment, despite canonical `ArtifactKindId` having exactly three segments. The proper static obligation is the actual kind identity grammar; standard and subset are separate coordinates. The proper dynamic obligation is acyclicity of exact member/owner identities.

Root has not changed these policy functions yet. A focused correction should remove the type-cycle inference and its obsolete fixture expectation, retain or strengthen canonical child-kind checks, and prove valid same-kind instances plus invalid actual ownership cycles through neutral fixtures and independent Ajv/Graphlib output. No runtime cycle admission or duplicate-owner validation should be weakened.
