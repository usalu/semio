# CAD World Window Migration Implementation

## Result

CAD camera, projection, sun, and Dislocate preferences now belong to the exact world-window instance that invoked the command. `CadConfig` no longer persists the four cameras, four Dislocate option records, or shared sun. A strict `CadWorldWindowConfig` owns those values, with concrete owners for Shape, Building, Energy, and Structure Classic.

Command authority comes from `ViewModel.window_id` and the matching entry in `window_instances`. Payload pane strings retain their surface meaning but cannot select a storage owner. Missing, stale, and non-world instances fail closed. Render and window measures resolve the supplied `WindowConfigSnapshot` for the exact instance. Runtime camera maps remain rendering scratch derived from that snapshot and are no longer app persistence.

The common window record has exact Rust, TypeScript, JSON Schema, GraphQL, and protobuf facets. Its production TypeScript parser rejects unknown fields, wrong scalar types, non-finite numbers, malformed camera tuples, and missing fields. The neutral fixture covers defaults, patching, parser rejection, and two same-kind ownership expectations. Its TypeScript law compares the production parser with independent Ajv validation and the production replacement with `fast-json-patch`.

The native ownership law drives six commands against one of two Shape instances, deliberately supplies conflicting pane strings, and verifies camera, projection, sun, and utility state only on the addressed instance. It also verifies unchanged document/app packs, exact concrete owner identity, same-byte document reload, window-pack close/reopen persistence, and rejection of stale or foreign instances.
