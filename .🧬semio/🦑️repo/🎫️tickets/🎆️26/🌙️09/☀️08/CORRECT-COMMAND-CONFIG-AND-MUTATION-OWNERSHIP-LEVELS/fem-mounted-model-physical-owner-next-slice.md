# FEM Mounted Model Physical Owner Next Slice

The mounted model is engine-level execution state. It belongs in the FEM engine and must not become window configuration or authored document state. Current source uses three large inline fixed arrays in `MountedAnalysisModel`; the admitted-slot counters are logical authority only. FEM3D later moves the complete model into an `Arc`, allocating the whole inline object in one operation. The assembly construction and job variants retain that Arc until their own teardown. This is a remaining physical-ownership gap, separate from the current element-string cleanup repair.

Observed consumers are the FEM3D numerical child and engine assembly tests. The native construction moves the Arc into the completed assembly job; it does not introduce another retained model Arc clone on that path. Accordingly, the current cleanup stall is not evidence of a reference cycle. The string owners must first pass their concrete cleanup regression.

The next implementation should use the existing shared `PagedList` for nodes, elements and supports, preserving the current fixed logical maxima. Admission must accept explicit physical-byte authority, retain every actual backing allocation, and publish logical admission only when the required page capacity exists. Each opportunity allocates at most one backing, initializes at most one item, or retires at most one string/item/backing. Refused item/byte grants leave all cursors and owners unchanged. Complex item strings must be empty before the page owner pops them. Tests must cover empty capacity, one page, a boundary crossing, maximum-plus-one, cancellation during admission and construction, and exact allocation/release conservation against neutral fixtures and JSON Patch.

API design: keep fixed logical maxima in the concrete engine model. Admission should return a concrete engine progress record carrying completion and actual allocation bytes, and a concrete engine fault carrying either the logical capacity violation or a retained allocation failure. Do not represent allocation failure as capacity overflow. The byte grant is explicit; if existing backing already covers the target, a later item opportunity may advance logical admission without allocating. Capture each PagedList's actual backing total so native laws can independently reconcile admission and release. String retirement remains inside each concrete node/element/support owner, followed by scalar item removal, followed by actual page release. Avoid retaining duplicate node/element/support lengths when PagedList already owns the initialized length.

The mounted path also needs an explicit decision on its unnecessary shared Arc root: current callers transfer sole ownership into assembly and later require exclusive access for cleanup. Prefer a directly moved model owner if the full caller inventory confirms no sharing requirement. Keep genuinely shared cold `AnalysisModel` ownership distinct. Do not report an inline Option or struct size as heap bytes retired: `AssemblyCsrBuild::close_step` currently reports `size_of::<AssemblyJob>()` and `size_of::<Csr>()` after clearing inline options; a separate physical-byte regression must remove that false accounting while preserving the nested owners' real release counters.

Source review only. No PagedList model migration, Arc removal or assembly-byte correction is applied by this report. Existing normal-stack, watchdog, grant and cancellation bounds remain unchanged.
