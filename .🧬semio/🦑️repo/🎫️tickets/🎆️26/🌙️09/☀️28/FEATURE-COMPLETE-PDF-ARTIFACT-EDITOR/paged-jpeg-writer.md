# Sequential PDF DCT Image Emission

`PdfDctImageView` gives a borrowed `ByteReadSource`, the admitted JPEG dimensions, the typed PDF colorspace and DCT transform, and the immutable SHA-256 graph key. The staged `AdmittedPdfJpeg::stream_view` creates it directly from the controlled paged owner. Its `reference` method uses the existing DCT identity format without reading or hashing the source again. It fits the [paged JPEG admission](paged-jpeg-resource.md) shape and introduces no new persisted format.

`PdfWriter::begin_dct_object` consumes a clear classical-xref writer and creates a continuation. It reuses the existing typed DCT filter formatter and dictionary writer for the prefix, including the source-derived `/Length`, then accepts the original stream in bounded windows. Each step takes a fresh digest-bound graph view. The job can own the graph and continuation without a long-lived borrow. A mismatched digest or source length is detected before reads or writes. The writer bound its prefix to 256 bytes and transfers at most one 4,096-byte input window per turn. For JPEG data, the sum of bytes read and accepted by the sink stays within the supplied byte grant. The physical paged sink must separately account for allocation and retirement under the originating grant. A contiguous image or output buffer is unnecessary.

The continuation advances only after actual sink acceptance, including when a sink accepts a prefix of a window. A zero-length acceptance or I/O error leaves the current output offset available for retry against the same private sink. The continuation returns the writer only after the full suffix and commits the exact xref offset at that time. Cancellation drops the continuation with its writer and must retire or discard the incomplete staged output. Existing support for encrypted or xref-stream output still needs its own sequential route.

## Verification

The focused Rust probe mounted the production classic writer, lexer formatting, typed filter serialization, byte-source contract and SHA-256 implementation. It used a file-backed fixture window and file sink to avoid loading the large source or output as a whole. Other artifact model and unrelated encryption/compression dependencies were narrow harness stand-ins. The writer rejected a duplicate object number, a reloan with a different digest, and attempts to recover the writer before object completion. The sink injected short writes, zero acceptances, `Interrupted`, and `WouldBlock`; the output was coherent after retries.

The 2,125,603-byte 1,024 × 1,024 baseline fixture transferred with maximum input windows of 4,096 bytes and accepted output chunks of 1,501 bytes. The 1,311,733-byte APP metadata fixture reached the same bounds. Grayscale with restart markers and Adobe RGB were also exercised. MuPDF 1.26.7 reopened all four emitted PDFs without repair. It verified PDF image dimensions, exact compressed-stream SHA-256, declared length, DCT filter and transform, matching crop pixels, and an indirect metadata object written after the JPEG. The graph reference agreed with the independent Pillow/Python fixture oracle for every file.

`paged-jpeg-writer-stage.py` stages the source overlays under `🗑️generated/paged-jpeg-writer`. `paged-jpeg-writer-probe.rs` replays the bounded emitter and `paged-jpeg-oracle.py verify-writer` checks the four files. The live repository lanes and package epochs were untouched.

## Save Integration

Extend the retained PDF graph with an exact native DCT resource keyed by its admitted digest, including the relevant identity, filter and stream dimensions. Publish that retained row together with the reversible typed image and paint operation. On graph reloan, resolve the native resource through the digest index and lend it as `PdfDctImageView`. The existing native graph `PdfObject::Stream` and cloning resolver still require this storage/index change.

Place the object continuation in an operation-owned raw Save cursor. Lower or reconcile ordinary objects while assigning the XObject another ordinary object number, use the current writer for bounded ordinary objects, and switch to `begin_dct_object` when the graph item has dedicated paged DCT custody. On each work turn, reborrow the same graph revision and destination sink, reserve a bounded destination page through the repository allocation effect, and pass the available copy/work grant. Commit the final download only once xref and trailer complete. The current whole-document raw serializer, contiguous `BinarySnapshot`, bounded output sink, large xref/trailer and mounted normal reopen remain integration work.
