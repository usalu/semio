# Durable DCT Install Payload

The staged codec stores a native DCT install payload using the repository's ordinary Pack manifest, symbol table, and identity chunk framing. The [declared payload layout](paged-dct-install-pack.schema.json) uses one 42-byte facts chunk followed by at most 128 identity chunks. They carry the exact JPEG octets in source order. The PDF DCT artifact reference keeps the existing filter-dependent SHA-256 identity. Pack separately verifies each chunk's CRC32C and BLAKE3. The small manifest and catalog are bounded independently of the original payload. The same install payload can retain the original once in the event store while other PDF edits refer to it by its bounded reference.

`write_dct_install_pack` takes the existing `PdfDctImageView` over an admitted original and an unpublished `PackSink`. It calls the supplied async checkpoint before each source fragment and before finalization. Each original fragment is at most 4,096 bytes. The writer rechecks the logical DCT digest before finalizing the Pack, so an inconsistent or canceled partial sink cannot yield a completed install payload. It uses 32 KiB native identity chunks. That larger on-disk extent keeps the chunk catalog small, with no corresponding whole-chunk buffer. Final Pack control data and allocation still need the introducing operation's actual grant accounting.

`NativeDctInstallPack::open` reopens from a standard Pack source. `PagedDctInstallPayload` adapts a borrowed native octet owner without copying, including the physical `PagedBytes<{isize::MAX as usize}>` used by SPR `CausalPayload`. Lookup checks the expected logical digest, metadata, chunk counts, and schema before any JPEG body is transferred. `DctInstallReader` reads at most one 4 KiB window or verifies one chunk boundary per turn. Bytes stay in private staging until the cursor reaches the verified terminal state. It verifies the complete DCT digest after all raw chunks verify.

## Verification

The focused probe was compiled against the actual repository Pack, native value, hashing and artifact-reference libraries in the existing cached native build. It wrote the 2,125,603-byte fixture to a private file without materializing a contiguous JPEG or Pack. It discarded original input custody, reopened the persisted bytes using the repository's actual paged owner, and extracted the JPEG through the native Pack reader. The fixture's persisted overhead was 3,821 bytes. The harness exercised wrong-key lookup, corruption within a stored chunk, and cancellation during the write. The canceled partial file was refused by the reader and removed. The probe exercises cancellation of the storage codec and its unpublished file, separate from a mounted retained-ledger teardown.

Independent Pillow 12.0.0 and MuPDF 1.26.7 checks matched the JPEG digest, PDF DCT reference, dimensions, and exact original crop. MuPDF also reopened an independent PDF made from the recovered bytes without repair and verified the original DCT stream.

`paged-dct-install-stage.py` prepares the exact source overlays and cached probe build arguments under `🗑️generated/paged-dct-install`. `paged-dct-install-probe.rs` exercises the native codec. `paged-jpeg-oracle.py verify-install-pack` independently checks the reopened resource.

## History Connection

The present PDF operation receiver expects its versioned PDF operation tag and a typed JSON payload, and its generic `Emit` exposes only mutation rows. The staged install Pack is an event payload codec. It does not bypass that operation receiver by presenting the Pack as a different already-supported PDF operation.

The concrete join is to register a native JPEG install event using the existing retained original operation wire owner and paged payload lane. The store must stage that install event and the existing `PendingDctPlacement` image and paint operations as one revision-checked transaction before either becomes reachable. Attach a digest-indexed lookup to the retained history or store-owned attachment lease, and reloan the install payload's pages into the staged reader. The graph and ordinary `PdfDiff` continue carrying bounded `ArtifactRef` values. A cold whole-snapshot clone therefore has no native JPEG to duplicate. Undo removes the visible image binding while the immutable install remains reachable from the historical forward event, and redo can use that same original. Retiring a history branch or closing the document must release its last original lease under the existing paid retirement path. Reopen must derive the resource lookup from the stored events or the authoritative resource index, with no process-local dependency.

The child-source route was examined as an alternative. It offers typed borrowed child reads and grouped publication, but current `ChildGenesis.initial_pack` and owned document archive member envelopes are contiguous byte vectors. Pushing normal photos through that route would first require paged child genesis and archive transport. The install Pack stage exercises the durable codec directly without a live schema or store change. The mounted PDF event registration, atomic commit, undo/redo, and paid cancellation still require the join above.
