# PDF Format-1 Archive Receiving

The archive writer and its direct-leaf codecs retain their existing bytes. The staged aggregate receiver borrows the caller’s exact source and range, advances one format, tag or canonical length octet at a time, and uses the same tag registry, JSON numeric representation and `FromValue` rules as the aggregate codec. Format, tag, length, UTF-8, JSON grammar, mutation identity and typed result are distinct frontiers. The grant backpressure path preserves the pending frontier, and close walks the unpublished output, parsed value, parser and JSON error under the caller’s retirement effect.

The existing cold `ByteReader` accepts a redundant terminal zero in a length. The new receiver refuses that alternate encoding, which the writer never emits. The fixture tests that distinction along with excessive lengths, truncated or trailing frame bytes, duplicate members, discriminator mismatch, and malformed typed data. The fixture’s valid insert-object frame is 141 bytes and starts with `010689017b226d75`. The CRC32C of bytes 0–19 is `94c0df0d` and the little-endian word at bytes 20–23 is `4f747265`, reproducing the original Pack-frontier refusal independently.

The proposed receiver still uses the existing aggregate’s `FromValue` for the final Bind turn. Its copy quote follows retained JSON bytes, and cancellation is checked immediately before Bind. `FromValue` can allocate or drop collections inside that turn, and cannot suspend mid-conversion. This draft therefore needs a native typed binding and accounting implementation before it can serve as fully bounded Original custody for large operations. PDF mutation declarations currently provide `FromValue` and `RetireOwned`. Most of the aggregate payload types do not provide native receiving implementations. The higher-level `OriginalJsonReceiving` uses a separate owned-projection authority and does not directly accept this binary span.

## Measured grant boundaries

The real framework parser decoded the 141-byte insert-object fixture into its native JSON owner after 475 paid advance steps, with 5,024 bytes retained at Bind. One-byte-short copy loans preserved every checked frontier and did zero work. The proposed Bind turn requests one item, depth one, one work unit, no capacity or release, and `5,056 + 2 * size_of::<Option<PdfMutation>>()` copy bytes on the native host. The isolated probe substitutes an allocation-free wrapper for the concrete mutation, whose Bind quote is 5,120 bytes. Concrete WASI aggregate metadata could not load from the stale cache, so the report does not substitute the wrapper’s layout for the actual enum.

The mounted interactive component policy allows 64 items, 32,768 copy bytes, 16,777,216 capacity bytes, 1,048,576 release bytes and depth 4,096 per outer turn. The native acceptance helper’s source stock permits 16,777,216 items, 134,217,728 cumulative copy bytes and 268,435,456 cumulative capacity bytes. Its separate retirement loan permits two items, 32,768 copy bytes and 262,144 capacity bytes. Constructor admission for the archive already prices the box placement, so child initialization spends one item and depth one with zero duplicate copy demand.

The neutral gray image fixture produces a format-1 `setImage` body of 8,388,811 JSON bytes for 4,194,304 samples. The grammar’s single allocation for the array backing would require exactly one item and 100,663,296 capacity bytes on WASI, whose `DslValue` is 24 bytes. On the native host `DslValue` is 32 bytes, making that allocation 134,217,728 bytes. The request exceeds the full interactive host capacity before the receiver reaches typed binding, so the draft yields for zero work at that frontier and cannot resume under that policy. If it could reach Bind, the array backing alone would exceed 32,768 copy bytes even before object, parser and handoff costs. The actual image samples occupy exactly 16,777,216 bytes as `Vec<u32>` elements.

## Native receiving route

The existing `OriginalTaggedPackValueReceiving` is the closest route for typed custody. It seeds `NativeSourceReceiving::from_original` from an admitted original value, selects local versus nested work, and calls the nested receiver through `NativeDecodeControl::source_witness()`. The existing `OpBinaryReceivingCursor::step` override keeps nested work outside the local effect. The PDF binding can use `NativeSourceReceiving<Source, PdfMutation, Origin>` and derive `NativeReceive` over the concrete mutation and its reachable field types. The discriminator and registry comparison still occur on the incoming format-1 source. Recursive variants such as `PdfColorSpace` need explicit recursive derive bounds and differential tests against `FromValue` for defaulted members, unknown members and number kinds.

A grammar source suitable for the full declared payload range needs a paged collection representation implementing the recorded `NativeValueSource` query contract, or a source that streams typed arrays directly from validated spans. The current sealed `JsonParsedValue::json_array(Vec<Self>)` forces the intermediate allocation quantified above. Replacing only Bind would improve custody for small values while leaving that large-array frontier.

`archive-receiver-stage.py` assembled six scoped candidates and verified their SHA-256 preimages and output identities. The stage has no apply mode. `archive-receiver-oracle.py` independently checked 12 refusals and both exact neutral frames through Python JSON and Google CRC32C 1.7.1. `archive-receiver-check.py` compiled and executed the staged framing, grammar, grant and retirement code with the real cached native framework and an isolated test projector. `archive-layout.py` verified the WASI intrinsic layout with pinned rustc. The staged product Rust tests exercise a nonzero source range, exact re-encoding, aggregate subtype round trips, malformed cases and paid cancellation closure. The concrete product tests and typed history digest require the native hydration gate.
