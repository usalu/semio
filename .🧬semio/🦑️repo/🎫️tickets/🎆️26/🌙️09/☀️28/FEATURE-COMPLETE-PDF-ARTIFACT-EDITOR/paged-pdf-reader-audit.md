# Paged PDF Reader Audit

This is a read-only source audit; no large-file decode, allocation measurement, archive publication, or test was run. The independently generated 9,437,877-byte PDF exceeds 8 MiB by 1,049,269 bytes, but its successful decoding and publication are not established here.

## Actual controlled path

In PDF 1.7 base import/controlled/🦀️.rs, admission lines 19–49 chooses controlled when source length exceeds work units per step and moves the existing Vec into NaturalPdfDecoder; the synchronous branch also retains a Vec. Cold construction lines 52–56 makes the same choice. The decoder owns source: Vec<u8> (lines 59–62), loans &self.source to PdfFilePreparationCursor::advance (99), and only marks consumed_input_bytes as the entire source length on transfer (111). No input pages are released while parsing. Even after successful snapshot publication, original source capacity is released in one operation only during close (262–266); retirement demands report that whole capacity (353–358). A release limit smaller than source capacity cannot retire this owner in bounded pages.

The preparation cursor in xref/retained-graph/🦀️.rs takes &[u8] (763), passes it to PdfByteGraphCursor (785), which passes it into PdfFileStructureCursor and a source.get(file.origin..) tail slice into GraphImportCursor (575–621). GraphImportCursor::advance, NormalProjectionCursor, indirect length and compressed-length traversal all consume a contiguous slice (163–190, 230–293). Its raw-stream path obtains the full span with source.get(start..end), checks maximum_stream_bytes (derived from contract.max_output_bytes), requests a single allocation equal to its whole length and reserves one Vec; only the subsequent copy is work-bounded (336–355). Stream payload in PdfObject::Stream remains a Vec. Object-stream members likewise parse a decoded Vec (70–75, 372–374). These are separate peak allocation and retirement obstacles even if the source itself becomes paged.

Preparation transfers the graph and trailer without clone (833–845, 880–887), and performs retained-text processing using exact xref positions (812–818). Controlled semantic lift passes GraphSource over those retained objects and positions (controlled 122–132), then closes positions before publication (134–154); publication moves graph.objects and trailer into snapshot (159–169). ReferenceRequired becomes an error (303–307), so a valid file with unsupported structure still cannot be claimed supported. Allocation/release requests that cannot fit unchanged grants eventually error (293–300). Cancellation and close own multiple graph/snapshot retirement paths; preserving them is required.

## Existing paged primitive and first safe change

Framework value/paged/read/🎟️.rs defines ByteReadSource with length, random byte access and bounded read_bytes, plus checked ByteReadRange for offset views. Slice and Vec implementations exist. Framework value/paged/read/🦀️.rs implements it for PagedBytes through retained_bytes().get and contiguous_at, copying across page boundaries into the caller buffer. PagedBytes uses 4,096-byte chunks (value/paged/🦀️.rs:11); its read law tests boundary crossing, empty/out-of-range reads and no allocation (paged/read/tests/🦀️.rs:5). This interface does not magically give a cross-page borrowed slice. No ByteReadSource use appeared in the inspected PDF base modules. A Rope-specific PDF reader was not established by this audit.

The smallest safe incremental refactor is to make the byte graph and downstream structure, lexer, xref, projection and length cursors accept ByteReadSource, replacing origin tail slicing with checked ByteReadRange and indexing/token scans with bounded byte access or fixed scratch buffers. First preserve the existing Vec caller and compare identical cursor events, results and cancellation/retirement to the slice implementation, then exercise the same source through deliberately boundary-split PagedBytes. Each cursor must continue accounting work for every scan/copy and use checked offsets; never coalesce an arbitrary span into a temporary Vec. This first refactor enables paged input but does not by itself make opening bounded: admission and lifecycle must transfer and retire the paged source, and raw streams, decoded object streams, snapshot representations and their consumers must separately gain bounded backing or explicit enforceable limits. In particular, do not claim a complete bounded open merely because input transport or parser reads are paged.

## Publication and evidence limits

The existing ingress audit identifies the archive write/readback ordering and whole-buffer boundary. The retained graph and stream buffers above can coexist with source and semantic snapshot before archive generation; archive encoded size is not necessarily the PDF size, so 9,437,877 bytes alone proves no archive limit or maximum memory. This audit did not establish an archive maximum, actual encoded size, or peak simultaneous allocation. Measure actual snapshot/archive bytes and live retained capacities on the genuine fixture, including readback, and trace every storage/serialization limit before asserting publication succeeds. Preserve the fresh unpublished owner and only publish after decode, durable write and identity/readback succeed. Exercise boundary-split tokens, xref/trailer and stream spans; large individual streams, cancellation and paid close under small grants; independently compare to MuPDF and verify archive failure leaves no published document.
