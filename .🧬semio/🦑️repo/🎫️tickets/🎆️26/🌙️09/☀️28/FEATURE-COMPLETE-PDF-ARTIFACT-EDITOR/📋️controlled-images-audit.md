# Controlled image import audit

## Decision

Start with indirect `/Subtype /Image` XObjects in a page resource dictionary and `/Name Do` content operators, using 8-bit `/DeviceRGB` or `/DeviceGray` samples and either unfiltered or supported Flate streams. Reject masks, soft masks, inline images, forms, named or indirect color spaces, unsupported filters and image dictionary features that cannot be preserved. Reuse `PdfImageSampleCursor`; do not invoke cold `lift_resources` or `lift_image` for large controlled imports. Keep the cursor integration in a new sibling owner of `🔨️modules/⬇️lift/🧩️lifter-and-document/🧭️document-lift/🧭️controlled`, outside the nearly 4,000-line lift closure; verify the repository's actual ownership accounting before landing. Likewise add a separate test owner rather than expanding the nearly full testkit closure.

## Evidence and constraints

`🔨️modules/⬇️lift/🪟️resources-and-fonts/🦀️.rs:67,187` enumerates XObject entries, claims IDs by reference, and records the name-to-ID mapping. `lift_x_object_claimed` dereferences the whole stream, recursively follows masks, invokes `lift_image`, records `PdfStreamRoleValue::Image { image: image.clone() }`, then appends the image. That path is synchronous and can clone substantial data. Preserve equivalent reference deduplication, page-scoped mappings and image role/provenance while preventing unmetered sample clones: a sample image role currently contains a full cloned `PdfImage`, so a controlled path must explicitly budget and incrementally construct that duplicate or change ownership representation; merely moving the sample vector into the snapshot is insufficient.

`🔨️modules/🖼️images/🦀️.rs:22` maps dimensions, color space, depth, decode, interpolation, masks, optional content and extras into `PdfImage`. For non-codec streams it synchronously unpacks into `PdfImageBody::Samples`; codec streams create `PdfImageBody::Artifact` via `NativePdfArtifactResources::admit` using `dict.to_vec()`, `data.to_vec()` and `filters.to_vec()`. No bounded transfer is established by this path: do not claim DCT support until admission and artifact storage expose a grant-aware transfer or bounded chunked copy, including its own retention and cancellation. Encoded bytes are not decoded into samples by `PdfImageSampleCursor`.

`PdfImageSampleCursor` at images line 115 accepts decoded packed bytes, validates exact geometry, grants work per sample, requests one allocation of `4 * sample_count` bytes, moves the completed vector through `take_samples`, and supports cancellation and release-granted close. Reuse it after the existing controlled Flate stage; it still requires the complete decoded packed buffer while converting. Account for that buffer, sample capacity, dictionary/name maps, final image, role copy, and any graph projection simultaneously. Explicitly reject geometry overflow, mismatched lengths, unknown `Do` names, unsupported filters/features and exhausted memory; never silently omit an image. Work, allocation and release receipts must cover every copy, retained structure and close step; cancellation must park or release partial state without publishing an incomplete image or page.

## Fixture and acceptance

Use a handcrafted PDF 1.7 page with an inherited or direct resource dictionary `/XObject << /Im0 5 0 R >>`, an indirect 2×2 8-bit DeviceRGB Flate image, and content `q 40 0 0 40 10 20 cm /Im0 Do Q`. Use four distinct RGB pixels; produce compressed bytes with an independent zlib implementation and compare decompressed samples against it. A second page may reuse object 5 under a different resource name to verify reference identity and page-specific renaming.

Assert controlled and cold semantic image metadata and samples agree, each `Do` resolves to the lifted image ID with the transform preserved, a shared object is lifted once, image stream role points to the correct source object, and a save/reopen retains image pixels and page appearance. Exercise work grants of one, zero allocation and release grants, partial sample conversion, cancellation and cleanup, malformed length and unsupported masks/codec; assert bounded receipts, stable partial progress, explicit barriers/errors, no published partial image, and no leaked retained allocations. Independently validate the generated document with an existing third-party PDF reader or renderer and compare rendered pixel colors. Native/browser checks are already running; this audit did not start builds or tests.
