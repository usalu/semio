The staged `Pdf17VtEditor` and `Pdf17VtViewer` quote and install the existing `cold_replay_document_store_owners` catalog for the shared base `PdfSnapshot` and `PdfMutation`. The editor uses its existing `snapshot_details_editor_support!` catalog argument and keeps the routed publication selected by its bounded editor macro. The viewer overrides the two owner methods in the actual read-only trait. Its existing `ViewerDocumentStoreOwnerProducer` and `ViewerApp` forward those methods to the registered initializer. The separate VT mutation and command codecs stay outside the shared base archive path.

The focused registered test starts the actual editor and viewer on their declared VT application definitions. It authors an InsertObject against the editor's real genesis, commits a checkpoint, and obtains the parent's Pack and SPR from `PluginApp::document_archive`. It uses the repository SPR decoder to find the committed forward and inverse bytes, then loads the same archive into the registered viewer under its original caller. The assertions check both hydrated mutation directions and the reconstructed object lane. The editor applies the inverse read from the loaded viewer and checks that its object lane returns to the real pre-edit state. Both applications and the original caller use their paid close paths. The app test selects an ordinary null object without stream-role modifications. The earlier archive object proof independently covers the 141-byte specimen with a removed stream role and the exact typed inverse that re-adds that role.
