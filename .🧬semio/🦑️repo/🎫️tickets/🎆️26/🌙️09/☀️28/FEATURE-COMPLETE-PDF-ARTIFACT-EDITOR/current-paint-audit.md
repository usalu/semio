# Current PDF Paint Audit

The highest-impact confirmed remaining paint substitution is ordinary standard-font text. In `✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📖️pdf/🏅️standards/7️⃣1.7/🪆️subsets/🧱️base/✏️editor/🖼️page/🗺️scene/🦀️.rs`, `paint_object` tries Type 3 and embedded TrueType outlines, then maps Courier to Share Tech Mono, Times to Kelly Slab, and every other font (including Helvetica) to Anta. This produces different glyph shapes and spacing for ordinary non-embedded PDF fonts. It also substitutes any font whose TrueType outlines cannot be decoded. The current TrueType path in `🗺️scene/🔠️truetype-text/🦀️.rs` returns false if a codec, units, encoding, or a glyph outline is unavailable, causing that fallback.

Extend the existing shared neutral fixture `✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📖️pdf/🏅️standards/7️⃣1.7/🪆️subsets/🧱️base/✏️editor/🖼️page/🧪️tests/🔬️unit/🧪️text-paint.json`: it currently explicitly expects Helvetica to paint as Anta, so it enshrines the discrepancy. Cover standard Helvetica, Times and Courier glyph shapes and advance positions (including mixed widths and spacing) and compare rendered output with an independent PDF rasterizer. Implement actual PDF standard-font outlines and metrics through the existing font codec/outline interface; assert no unrelated UI-font text fallback for supported standard fonts. Include save/reopen and mounted paint coverage when the active gates can run. Existing Type 3 and TrueType outline support means the older audit’s claim that all fonts are mapped is no longer accurate; the fallback remains demonstrably live.

This audit read current source and ticket evidence only; no build or runtime test was run. The editor also exposes a smaller inspector field set than its command roster, but the snapshot Details route is intended to cover remaining editable typed fields, so this paint discrepancy is the more concrete next item.
