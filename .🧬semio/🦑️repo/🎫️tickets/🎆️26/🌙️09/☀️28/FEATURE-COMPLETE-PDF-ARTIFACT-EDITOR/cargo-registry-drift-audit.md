It does not observe Cargo’s SQLite tracking database or unrelated package files. A selected lock change, selected crate replacement, touch or disappearance, or an earlier matching index can cause refusal. The receipt stores only the aggregate digest, so it cannot identify the changed crate or even distinguish a lock mismatch from registry mismatch after the fact. An offline network grant makes the selected Cargo acquisition offline but does not immobilize shared-home archives against another writer. Cargo SQLite writes or `CARGO_NET_OFFLINE=false` by themselves are not part of the drift discriminator. The repository fleet crate store is content-addressed and verifies lockfile checksums on publication; its restoration copies and renames into the mutable shared Cargo home, so it is not an immutable registry mount or a pin for existing readers. No sanctioned direct re-sign of a failed consumed snapshot was found. A durable fix would preserve an issued immutable selected-registry view or coordinate all relevant writers with the spanning reader, then let the standard reader and artifact publisher perform verification.
