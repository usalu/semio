# Paged Baseline JPEG Resource

The staged admission transfers one existing controlled paged byte owner into a JPEG proof and then into the next PDF transaction. It represents the same DCT identity used by PDF 1.7's controlled import. The 4 MiB input limit is the proposed owner capacity. This stage is independent of the still-pending picker contract. It admits baseline sequential 8-bit DeviceGray and DeviceRGB, with a single complete scan, up to 65,535 in each dimension and 64 Mi pixels. The language-neutral admission shape is in `paged-jpeg-resource.schema.json`.

`paged-jpg-baseline.rs` reads through the repository JPEG `JpgByteSource` contract. Each turn advances one marker, table, entropy block, or restart/EOI boundary. The parser skips opaque APP and comment segment bodies by their checked lengths. Fixed-size quantization and canonical Huffman tables support the same entropy reader used by the repository decoder. The proof checks referenced tables and components, entropy run bounds, restart order, bit padding, and terminal EOI. It exposes each admitted block's coordinates, sampling factors, coefficients and quantizers by a short borrow. It returns image dimensions and the PDF color transform after EOI. Progressive and other JPEG profiles return an unsupported refusal.

`paged-pdf-dct-resource.rs` takes an untouched `ControlledRetirement<PdfPickedJpegBytes>`, where the byte owner is `PagedBytes<4 MiB>`. It checks the JPEG over immutable reads and hashes at most 4 KiB of source bytes per turn after validation, using the existing PDF DCT filter identity. The caller supplies the original retained allocation effect and its work grant. A fault keeps the original available for controlled retirement. Successful admission returns fixed metadata and digest and transfers the same controlled owner. The editor can materialize bounded reference strings at publication. This owner belongs in the PDF document editor. Only the shared DCT hash accessors belong in the PDF inferences owner.

## Verification

The focused Rust probe mounted the staged cursor, actual repository entropy and transform functions, and actual SHA-256 state. A discontiguous test source provided independent 4 KiB input pages. The test checked one crop without retaining a full raster. Across the four valid cases, the maximum number of JPEG source octet observations in a cursor step was 179.

Pillow 12.0.0 generated the reference codestreams and supplied an 11 × 10 RGB crop. MuPDF 1.26.7 independently interpreted handcrafted PDF XObjects at their true dimensions and confirmed the exact original raw DCT streams. The 1,024 × 1,024 fixture measured 2,125,603 encoded bytes. The grayscale control uses restart markers, the straight RGB control uses Adobe APP14, and the opaque metadata control carries roughly 1.3 MiB of application markers. All four Rust resource identities matched independent Python digests. The large crop differed by at most two values per channel from Pillow and MuPDF. The other three differed by at most one. The cursor refused progressive JPEG, truncated entropy, trailing bytes, a zero quantizer and an incorrect restart marker.

`paged-jpeg-stage.py` prepares the precise sources in `🗑️generated/paged-jpeg-stage`. It includes the PDF document editor Cargo manifest dependency additions. `paged-jpeg-oracle.py` produces the neutral fixture in `🗑️generated/paged-jpeg-assets/fixture.json` and compares Rust results. `paged-jpeg-probe.rs` is the focused native harness. The probe exercised the cursor and digest path. The production PDF document editor owner, the repository's controlled retirement of the attached byte owner, and the staged manifest were not compiled by the probe.

## Remaining Integration

1. The picker must emit an ordered image session with an immutable instance, full canonical base revision, edit target and generation. The host needs to release its staged pages only after a local PDF import consumes the exact owned bytes. The JPEG admission owner accepts an already admitted byte owner and exposes a close demand and step for cancellation or refusal. Both picker adapters must drive that same contract.
2. The consuming PDF mutation transaction must bind the image role, graph resource and placement atomically against the captured revision. Persistent graph custody needs an exact referenced DCT stream over paged bytes and a borrowed encoded window keyed by its admitted digest. Current `PdfObject::Stream` has a contiguous body and `NativePdfArtifactResources::resolve` rehashes and clones while looking up resources. History must retain the original owner through undo and redo with explicit ownership and retirement accounting.
3. The Canvas2d preview can use the same block projection with a fixed output tile or bounded target raster. It can IDCT only blocks touched by that render tile or sample grid and must cache revision-bound results over bounded job turns. The existing preview first calls the cloning resolver and then allocates full decode planes. The crop harness demonstrates the coefficient sampling seam.
4. Raw PDF Save must preserve the one DCT filter and compute `/Length` from the encoded byte source. It needs a sequential object emitter through a paid output sink, with a bounded header and trailer and grant-sized original DCT windows. `PdfWriter::object` currently materializes streams and allocates a full object buffer, `serialize_document` appends it to a contiguous PDF, and the raw serializer returns a contiguous `BinarySnapshot`. The same design must extend to paged Save/download and normal reopen. Encryption additionally needs a streaming cipher and document-ID hash over paged inputs.
5. Before release, compile the owning crates and their mounted WASI/browser pathways and verify paid cancellation, stale admission, Add/Replace, undo/redo, raw Save and reopen with the large fixture. PNG alpha requires its own bounded decode and native soft-mask path.

All staged source and verification inputs remain in this ticket. The live source epoch was left untouched.
