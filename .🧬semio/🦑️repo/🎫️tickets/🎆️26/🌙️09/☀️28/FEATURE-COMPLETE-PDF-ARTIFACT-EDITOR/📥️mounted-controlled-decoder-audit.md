# Mounted controlled PDF decoder audit

The PDF 1.7 base editor currently opts into the single-turn owner and does not override `admit_natural_file_decode_owner`. The mounted `NaturalFileImportWork::step_request` calls that admission method after moving the original bytes into `pending_bytes`; the older `build_natural_file_decode_owner` alone does not wire this route. The default rejects an input whose length exceeds `contract.max_work_units_per_step`, independently of `max_raw_wire_bytes`.

A controlled implementation must admit its boxed owner against the actual retained grant before moving the original byte vector, preserve the source on refusal, and put `NaturalFileDecodeOwner::Controlled` into the receiving slot. Its advance must translate remaining fuel, retained allocation and release grants to each cursor, debit actual receipts, honor cancellation and yield, and report cumulative monotonic input, item, output-byte and work progress. The importer checks input against both source length and the raw limit, items against `max_decoded_items`, output against `max_output_bytes`, and completion requires the full input length. Random-access scans revisit bytes: summing reads is not valid consumed-input accounting. A turn with no progress while a grant is available is treated as stalled. Close must drive every owned cursor and source through grant-based retirement and witness emptiness before the box is released.

The natural composition is the bounded header probe, `StructuredXrefCursor`, generation-aware graph resolution and file-order projection, then `DocumentLiftCursor`, followed by the existing native snapshot Pack source and paged export/genesis path. The structured cursor can request compatible recovery; that synchronous recovery must not be presented as bounded work. Actual support also needs controlled repair, hybrid and incremental cross references, object streams, indirect lengths, filters and encryption rather than assuming an intact classic file.

`DocumentLiftCursor` now owns `DocumentLiftState` and binds the graph source to `Lifter` only during each advance. This removes its previous self-borrow and allows a decoder to own both graph and lift state. Its semantic grant is still a Boolean permission for whole operations: branch resources, optional content, embedded files, page projection, catalog and finalization may traverse or materialize unbounded data. A page action can join streams, parse content, decode resources and allocate a large result; `ContentTokenCursor` only bounds lexical tokens, not operator execution, inline-image handling, resource resolution or snapshot assembly. Finalization copies roles and materializes artifact objects. These are not safe to charge as one bounded unit.

The highest-value parallel stage is a retained graph coordinator that drives `XrefFileOrderCursor` and `NormalProjectionCursor`, maintains exact-generation indirect-length requests and bounded graph insertion, and integrates compressed-member and recovery cursors. Its output must retain source spans, decoded streams and all partial allocations across turns and close them under grants. Independently, turn page-content interpretation and resource lifting into resumable semantic state, including multi-stream concatenation and output construction; then apply the same treatment to catalog and finalization. Existing projection cursors are useful components, not proof that their synchronous callers or the graph materialization are bounded.

The native Pack path now provides paged publication, but the non-native reference-encoding fallback remains synchronous. Validate the real mounted route with a valid PDF larger than one turn, a multi-turn expanded stream, classic and compressed xref/object streams, real cancellation in decode and publication, unchanged document on failure, bounded retirement, and comparison with an independent PDF reader. Do not count a whole synchronous decode as progress.
