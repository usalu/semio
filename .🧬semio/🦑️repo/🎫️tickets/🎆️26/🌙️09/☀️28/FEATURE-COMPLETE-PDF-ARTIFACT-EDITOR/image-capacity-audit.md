# Image Import Capacity Audit

The current normal picker cannot soundly admit a typical photo by changing limits alone.

- PDF `✏️editor/📄️document/🖼️image-authoring/📥️admission.rs` uses `RequestFileOpen` with PNG only, 48 KiB wire contract and explicitly requires chunk 0 of 1. `🧵️decode.rs` caps files at 24,546 bytes and pixels at 4,096. It pins the entire canonical revision and the job checks it, reports decoder phases, supports cancellation and retires the decoder. Completion creates image, optional soft mask and paint as one mutation transaction.
- Framework `🧰️framework/🔨️modules/🎠️kernel/🗄️file-open-import/🟦️.ts` and `🎞️media-jobs/🦀️.rs` split picker payloads at half the guest contiguous ceiling (32 KiB); the shared `ImportStaging` accepts 128 chunks, 4 MiB total, two runs, ordered delivery, cancellation, and staged progress. However its final `pages.concat()` materializes one large contiguous String and strips the chunk envelope. It does not provide a bounded retained original-media handoff for a 1 MB action. The natural-file reserved import in `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/📜️declaration/📥️natural-file/🦀️.rs` transfers owned intrinsic bytes for the declared natural-file port; it is not itself the local picker image command.
- PDF `🧬️schema/📸️snapshot/📐️model/🖼️xobjects/🦀️.rs` models sampled bodies as `Vec<u32>`; 1024×768 RGB entails 2,359,296 elements, about 9 MiB before container overhead. `place_sampled_image` allocates and fills RGB and alpha and converts to u32 in one turn; the decoder completion requires fuel for all RGBA bytes in one turn. Raising its 4,096 pixel limit breaks bounded work and component-array admission even if transfer is fixed.
- Framework `🧰️framework/🔨️modules/🌱️value/📦️paged/🦀️.rs` already offers `PagedBytes<N>` with 4,096-byte pages and explicitly quoted/charged page admission, controlled cloning and retirement. A sound path needs an end-to-end paged or equivalent owned source from picker through resumable decode and a paged PDF image body, including schema, codecs, typed mutation/history, rendering and export. Existing foundational paged bytes can be reused, but PDF-only constant changes cannot implement this. A compressed JPEG representation may avoid expanding photo samples but still needs bounded paged transfer/storage and proper JPEG metadata, validation, rendering and PDF export; PNG alpha needs equivalent bounded sample/mask handling.

Keep the captured revision and immutable target across all pages, reject stale revisions before publication, publish the image, mask and placement atomically, and ensure cancellation/fault retires all private input and output pages without artifact or history changes. Charge each page, decoding and conversion to the originating turn; surface progress and cancellation during transfer and decode.

Fast verification: shared language-neutral fixture for multi-chunk order/gap/duplicates, limits, alpha, cancellation at each phase and stale revision; native and browser picker tests with a 1 MB file; 1024×768 RGB and transparent PNG insertion/replacement followed by undo/redo and save/reopen; compare output pixels and dimensions with an independent PNG/JPEG decoder and rendered PDF with an independent PDF renderer. Include small and limit-plus-one cases, adversarial malformed/truncated files, and assert per-turn allocation/work and publication bounds. This is an exploratory read-only audit; no build or server was started.
