# PDF Image Authoring Audit

Read-only source audit; no build or browser run. Paths below are relative to the PDF 1.7 base at `✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📖️pdf/🏅️standards/7️⃣1.7/🪆️subsets/🧱️base`. The mounted entrypoints and existing acceptance setup are documented in `📋️mounted-pdf-e2e.md` in this ticket. The controller is `s.stdio.pdf@1.7/*#editor`.

## User-facing paths and gaps

- The page window declares palette actions in `✏️editor/🖼️page/🪟️windows/🦀️.rs:52`: Insert Image accepts page, x, y, width and height only. `🎬️actions/🦀️.rs:27,112` serializes a replayable page edit; `🖱️object-edits/🦀️.rs:80-89` creates a fixed 8×8 RGB image of sample value 180 and a transformed PaintXObject. There is no file or sampled payload in this insertion action. Generated IDs use image count + 1, which can collide with existing nonsequential IDs.
- Set Image Samples is declared at windows line 56 with page, object, width, height and text. `edit_from_action` requires these; the editor's `command_from_action` maps to PageEdit and bounded native preparation emits mutations through `emit_page_edit` (`✏️editor/🦀️.rs:167-180,203-206,271-285`). The text is decimal 0–255 values separated by comma or whitespace, despite the helper parameter being named hex. It accepts exactly grayscale or RGB 8-bit sample counts; dimensions are clamped and rounded. Shared XObject replacement changes the resource for every use; inline replacement changes its containing page. No image file picker, decoder or direct inspector replacement is bound to it. It does not reset existing decode, mask, matte or intent when replacing samples, which can invalidate or change the appearance of an otherwise valid replacement.
- Canvas pick and the Object inspector expose x/y/width/height and, for a referenced snapshot image, interpolate, intent and decode (`🔎️inspector/🦀️.rs:41-52`). Fields commit on blur with revisioned draft targets through the controller (lines 155-184). Inline images have geometry but do not satisfy `snapshot.image(&object.text)`, so those attributes are absent. Resource detail also handles matte (`🎨️resource-edits/🦀️.rs:87-96`), and the separately declared Set Image Mask action accepts object, kind and mask; neither is a local-image replacement workflow.
- The Details pane is present in the default layout (`🪟️windows/🦀️.rs`) and rendered from the snapshot by the same controller (`✏️editor/🦀️.rs:210-220`). Schema edit rules address, insert and remove `/images/*` (`🧬️schema/🧬️mutations/🦀️.rs:347-393`). This provides low-level editing of representable image fields and sample arrays, subject to the generic editor's schema and validation; it is not evidence of a local-file picker, image decoding, atomic multi-field sample replacement, or a practical substitute for normal image authoring. Whether every union/array edit is mounted and usable needs a browser test; source inspection alone cannot establish it.

## Recommended implementation and verification

Use the host's existing natural local-file admission and typed foreign-resource infrastructure rather than transporting a large decimal string through a generic action. Add an explicit image import/replace intent, a bounded cancellable decode/conversion job and typed transfer of image dimensions, color model and samples to the PDF editor. Define formats and alpha handling explicitly; preserve or deliberately clear incompatible PDF image attributes, distinguish per-placement replacement from shared-resource replacement, allocate a collision-free resource ID, and publish the image resource plus page-content operation atomically with undo. Implement inline and referenced image semantics explicitly. Follow existing progress, cancellation and memory-grant contracts; do not publish partial decoded data. Keep geometry in page space distinct from pixel dimensions. Reuse the same source for insert and replace, and expose localized accessible picker controls and errors. Confirm exact existing host contracts before choosing the port; this audit did not establish a ready-made picker for secondary image files.

Add language-neutral fixture with a local 2×2 lossless image of distinct colors, a PDF containing both an image XObject and inline image, and another page sharing the XObject. Independently decode/render using existing third-party image and PDF libraries. Exercise real mounted file selection, insertion and replacement, geometry, attributes, save/download, reopen, pixel comparison, undo/redo and shared-resource policy. Include alpha/color conversion, malformed/unsupported file, oversize/overflow, cancellation with no mutation and resource-ID collision. Test the same shared sample fixture in the native action layer and browser; cover grant starvation and incremental cleanup. Verify Details scalar/union/array editing separately if it is claimed as supported. Existing `🧪️image-paint.json`, `🧪️image-move.json`, `🧪️coded-image.json` and `📜️image-oracle.py` are starting points, not evidence of local-file authoring.
