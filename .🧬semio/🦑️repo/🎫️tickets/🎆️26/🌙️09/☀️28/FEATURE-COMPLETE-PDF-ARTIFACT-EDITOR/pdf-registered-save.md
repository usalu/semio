# Registered Native PDF Save

The PDF 1.7 editor currently declares the native binary codec `s.stdio.pdf@1.7` and calls the cold `encode_pdf` path through `ArtifactEditor::encode_natural_file`. The normal shell Save first persists the attached program document and then requests `artifact:native` as one binary result. This change is staged in the ticket while the shared native and browser gates run.

## Original producer

`pdf-registered-save-producer.rs` stages the binary producer against the actual `ArtifactMediaExportJobRequest` supplied by Docs. Docs captures the current canonical revision and pinned snapshot, matches the runtime controller and `export-media:<port>` to the editor's typed factory, checks the paired `SnapshotRead` and close lease, and provides the output queue, credit and completion owners. The candidate binds the Original caller and checks the paired snapshot supplier before lending each turn to the program. It pays or settles one output page, moves exact pages into `ArtifactOutputChunks`, seals the queue through its Original method, and completes through the supplied result carrier. The producer's untransferred result and partial page retire through controlled Original retirement. The request stays owned by the outer job. It must be retired via `ArtifactMediaExportRequestRetirement` after the emitter and producer have closed, even on cancellation or refused eligibility.

`pdf-registered-save-window.rs` stages the combined physical budget. Source reads and bytes copied into the output page consume one combined Original receipt, including partial work before a writer fault. The available sink space is independently capped to the page tail. A one-byte tail can therefore still accept output from a bounded source prefix rather than deadlocking when the DCT emitter divides the combined allowance. The staged focused law checks a grant of 97, a one-byte tail, 48 source bytes, one emitted byte, `WouldBlock` on the second write, and an exact 49-byte receipt. The earlier sequential writer and real output-queue combined fixture emitted 2,126,390 bytes byte-for-byte, then MuPDF independently reopened it and confirmed the original DCT digest and rendered crop.

`pdf-registered-save-factory.rs` stages the PDF 1.7 Editor's typed HostOnly factory and Document output port, using the existing reserved-original handoff macro. At the editor macro, add optional `native_media_export_factory: $factory:ty` next to the native snapshot-pack stanza and register it with `registry.register(<$factory>::new(&controller))`; leave the existing edit and image factories in their existing registration. Supply `native_media_export_factory: native_save::PdfNativeExportFactory` in the PDF editor, delegate `io` to `native_save::app_io`, and add the actual `build_media_export_job` override beside `admit_natural_file_decode_owner`. That override must admit a paid `PdfGraphSaveJob` body, validate the exact `artifact:native` and `export-media:artifact:native` source, and then donate the complete request. Model the outer job on `NativeSnapshotPackExportJob`: paid body admission, a progress checkpoint on drained producer frontiers, complete after the result transfers, and retire producer, graph cursor and complete request before dropping the body. The outer job and registrations remain unmounted.

## Graph and host boundaries

`PdfNativeSaveProgram` is the production-shaped seam between the app-specific graph and the producer. Construct it only after a bounded planner proves that the source graph represents the exact pinned semantic snapshot. The current `reconcile` lifts the retained graph and compares the typed fields before deciding whether reuse is safe. A raw imported image, nonempty object list, or matching JPEG digest alone proves none of that. A planner must cover all moved graph lanes, preserve original object IDs, generations and trailer extras and their referenced objects, then quote ordinary objects and final xref within the admitted bounds. Existing `DocumentStream` cloning a headless snapshot omits trailer extras. The DCT writer stage covers classic clear raw DCT objects with bounded source reads. Its general object and xref helpers still materialize per-object and terminal buffers. A graph planner therefore needs either real bounded emission for those structures or explicit eligibility with quoted extents. Materializing a cold `encode_pdf` result and splitting it afterwards would bypass this work. Eligibility, the graph-to-writer program, and published large DCT custody are required before turning on the factory.

The shell's declared-media route already runs revision-bound submit, poll, cancel and chunk drain and validates the final binary descriptor. It needs the existing Export Media File shell action declaration with four string arguments `outputPort`, `filename`, `mediaType`, and `formatKind`, matched to the one out port. Use `artifact:native`, the normal generated PDF filename, `application/pdf` and `s.stdio.pdf@1.7`. For normal Save, run only after `persistAttachedProgramDocument` and retain the current archive and descriptor checks. The least-invasive host extension is an optional asynchronous callback after writing the staged sink and before the final identity recheck and sink close in `downloadDeclaredMediaFileV1`. In normal Save this callback checks `heldArchive` and compares the persisted/current archives through the existing helpers. Existing declared-media invocations omit it. Cancellation or revision change aborts the staged sink with no file commit. The segmented branch should be selected by the mounted declaration and actual port support, with a typed ineligible result for graphs outside the implemented writer coverage. No new protocol or naked decoder is needed.
