# Paged PDF publication audit

The normal mounted Open path currently cannot consume paged Pack output directly. The smallest sound route needs an explicit retained handoff from the natural-file job into the existing mounted replacement lifecycle; merely substituting the bounded encoder still leaves the synchronous LoadDocument effect and its Vec payload.

## Existing ownership and boundary

- `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/📜️declaration/📥️natural-file/🦀️.rs`, `NaturalFileImportJob::step_original` lines 233–315: controlled decode moves the snapshot into `pending_snapshot`, then Encode calls `document_reference_load_emit` synchronously; Publish calls the mounted completion consumer. The job owns snapshot, decoder and completion through close. Encoding is a separate turn but remains unbounded.
- `🔌️plugin/📜️declaration/🧩️app/🗂️natural-file-and-media-artifacts/🦀️.rs` lines 52–65: `document_reference_load_emit` calls the snapshot reference codec into a contiguous Pack and builds `Effect::LoadDocument { pack, spr }`; the empty SPR creates fresh history. `🔌️plugin/🌐host/🦀️.rs:442` likewise accepts `Vec<u8>`. Neither carries paged output.
- `🏪️store/🚪️io/💾️binary/📸️export/🦀️.rs`: `OriginalSnapshotPackExport::admit` binds the original caller, native receiving identity, source projection identity, epoch and envelope. Each `advance` reborrows the same unchanged `OriginalSnapshotPackView` and writes paid pages; `take` transfers unique `PagedBytes` only when cursor and pending bytes are fully closed. Cancellation/failure must drive `close` and release its boxed owner. The snapshot must remain at a stable projection identity and unchanged until encoding closes; no temporary projected record may replace it. PDF needs a borrowed `FieldProjectionSource` and `BorrowedRecordSpec` matching its existing reference encoding, including envelope, plus lifecycle tests against the codec's bytes.
- The existing paged ingress in `🔌️plugin/🧵️instance/📄️docs/📥️staging/🚪️ingress/🦀️.rs` lines 77–232 is for **artifact-envelope decode pages**, with preflight, page admission, seal, advance and cancel. It is not a Pack sink: it expects the owned-schema JSON envelope and would require bounded envelope construction and subsequent decoding. Treating raw Pack pages as those pages is incorrect. The same file's crate-private `begin_persisted_document_store_replacement` admits an already-decoded typed `ArtifactEnvelope` and preserves schema/dialect validation and the replacement pipeline.
- Native genesis machinery exists in `🔌️plugin/🌱️initialization/🌱️genesis/🦀️.rs`: `OriginalStoreGenesisOwner` supplies typed state, borrowed Pack source and catalog; `OriginalStoreInitialSource` retains the true producer across turns. `🏪️store/🏗️initialization/🌱️genesis/🏭️factory/🧬️schema/🦀️.rs` declares `OriginalStoreGenesisFactory`; `🏪️store/🚪️io/💾️binary/🌱️genesis/🦀️.rs` has `ArtifactGenesisPackCapture` and `AdmittedArtifactGenesis`. These are building blocks, not an existing natural-file completion API.

## Concrete route

Add a typed, retained genesis completion/transfer owned by the mounted job and consumed by the instance replacement, preserving the original publication token, generation, schema/dialect, owned-member closure and candidate guard. Feed its real decoded snapshot and paged canonical Pack into a bounded native genesis constructor; create empty history with matching identity and then use the existing replacement candidate and retirement sequence. The transfer must be explicit and unique, with returned custody on refusal, cancellation and stale generation. Do not emit a `Vec`, flatten pages, or invoke the whole-record reference codec on the interaction turn. A paged-Pack-to-JSON-envelope route is possible but adds bounded serialization, escaping, parsing and duplicate typed materialization, so is a larger change. The currently crate-private persisted-envelope route shows the consumer and validation but still needs a bounded constructor and transfer authority; it does not by itself solve publication.

Touch points: PDF 1.7 snapshot/reference codec and its native field projection; generic `NaturalFileImportJob` encode, completion and close stages; completion/effect vocabulary and mounted instance ingress; native typed genesis/envelope constructor and replacement admission; store/export and registered natural-decode lifecycle tests. Verify byte equality against the existing codec, stable source/caller/epoch rejection, multi-turn page output, cancellation during encode and replacement, returned custody and complete physical closure, unchanged document/history on rejection, and mounted Open of a large valid PDF against the independent PDF oracle. No build or tests were run for this audit.

## Borrowed PDF snapshot Pack producer

PDF 1.7 now exposes its original typed snapshot through `ArtifactStoreSnapshot::native_pack_source`. It borrows the existing canonical field tree and uses the same root field IDs, keys, optional declarations, and layout as the reference codec. Native byte fields remain intrinsic octets, including empty octet strings, while their canonical JSON view remains an array of numbers. The producer borrows retained COS streams, byte strings, embedded assets and document IDs directly from their original backing.

The native regression projects the genuine compressed-stream PDF with one work unit per turn, checks the original stream-byte address, and compares the result and Pack bytes with the reference Record producer. The native build has been queued to run it. The projection supplies the existing bounded Pack exporter. Mounted Open still requires a typed replacement handoff that retains paged genesis data and preserves cancellation, schema and generation checks.

## Verified genesis page backing

The bounded Pack exporter now hashes the exact bytes as each retained page is written. Its one-time completion carries the pages and digest together. The VCS genesis owner can admit those pages alongside the typed snapshot under a quoted allocation grant. A refusal returns the original typed snapshot and pages. A genesis borrows either physical byte source through the same byte-read interface. Its retirement lane closes the actual backing. The existing transport and whole-file export APIs assemble bytes at their explicitly requested boundaries.

The export regression checks canonical bytes, digest, refusal with an underfunded grant, reuse of the original page address after admission, and controlled retirement of the adopted owners. This shared native test remains pending. The mounted natural-file result cell and instance replacement route still need to carry the typed payload and its publication token.

## Mounted handoff at implementation resolution

The verified export now provides `OriginalSnapshotPackOutput::admit_snapshot<P>(self, snapshot: P, grant: RetainedCloneGrant) -> Result<(AdmittedArtifactGenesis<P>, RetainedCloneProgress), (ValueError, P, Self)>` in `🏪️store/🚪️io/💾️binary/📸️export/🦀️.rs`. Its refusal returns the exact two owners. Respect `verified_pack_birth_demand` and the returned progress under the real original effect/receiving scope; retain both owners on unfunded or failed admission and physically close them on cancellation. No Pack flattening, rehash or second typed decode is needed.

The compiled native route is an additional private typed completion variant carrying `AdmittedArtifactGenesis<A::Snapshot>` in `🔌️plugin/📜️declaration/👷️job/🩺️typed-operation-faults-and-raw-input/🦀️.rs`. The completion is a single-assignment shared cell; `🎯️completion-and-owned-context/🦀️.rs` lines 64–84 is the suitable model for `complete_genesis_original(&mut Option<…>, &mut bool, &mut StepContext)`: validate original source context, refuse a duplicate/occupied cell, check cancellation/yield, item/depth/copy-byte grant, move the owner only once, consume actual retained progress and fuel. Add the corresponding retirement branch and exhaustive-match handling, including routes that cannot consume this variant; never let an unexpected-value arm silently discard the genesis. The current `complete` call has no grant and is not the correct model for moving the new retained owner.

`NaturalFileImportWork::step_request` admits and retains the actual job and clones its completion; `NaturalFileImportJob::step_original` owns the decoded snapshot throughout exporter advance. Its completion must be transferred only after export and exporter closure; the producer still retires its own decoder, completion reference and empty export frame. The mounted consumer is `TypedCtx::publish_mounted_typed_operation_unit` in `🔌️plugin/🧵️instance/🧾️typed-operations/📥️staging/📬️publication/📬️typed-operation-unit/🦀️.rs`: lines 28–42 claim the cancellation publication lease and paid-move `completion.take()` into `mounted.publication`; lines 59–66 check captured revision/generation. `TypedCtx` already exclusively borrows `ingest: &mut EnvelopeJobs<A,M>`, `stores`, and `child_composition` in `📥️staging/🧺️bundle/🦀️.rs`, so it can hand off the actual typed value without an outbox, WIT, or wire change. `EnvelopeJobs::begin_persisted_document_store_replacement` is currently `pub(crate)` in the separate instance-docs crate: expose a narrow public admission method rather than assuming that this call already compiles across crates.

Before admission, construct the exact envelope with `store::os_store::document_materialize::empty_document_envelope_from_genesis_owners(schema: String, id: String, genesis: AdmittedArtifactGenesis<P>, backbone: Option<ArtifactBackboneRef>) -> ArtifactEnvelope<P, Mutation>` (`🏪️store/🧾️document/🦀️.rs`). It moves genesis into empty document history without allocation, initializes owner/dialect to None and history shape Document. Under paid bounded ownership, obtain the live store's schema/id/dialect/owner with the same semantics as `InstanceStores::stamp_load_document_identity` (`🏪️stores/📥️staging/🧵️instance-root/🦀️.rs:22`); set `owners.dialect = Some(A::DIALECT.into())` and `owners.owner` to the live owner, and use the live id, not a new ID. Metadata copying and ownership leases need explicit grant and retirement; the live owner may itself be nontrivial. Preserve the typed genesis on refusal or arrange bounded envelope retirement. The normal no-backbone empty genesis uses `None`; do not assume a clone of the old history.

The admission signature is `begin_persisted_document_store_replacement(&mut self, stores: &mut InstanceStores<A>, child_composition: &mut ChildComposition<M>, envelope: ArtifactEnvelope<A::Snapshot,A::Mutation>, cx: &mut StepContext<'_>) -> Result<ArtifactEnvelopeDecodeOperationHandle,(Fault,ArtifactEnvelope<A::Snapshot,A::Mutation>)>`. It validates schema and dialect, reserves a fixed slot, builds the app initializer using the current local actor, and binds `ActiveArtifactStoreReplacement::new` to current store generation, child-content generation and `(cx.operation(), cx.generation())`. Slot saturation/initializer refusal returns the original envelope, which needs retained retry or original retirement; caller must not drop it synchronously. Admission itself must be quoted and charged by its caller; current method does not itself settle a retained receipt.

Store the handle in the mounted owner and wait, rather than declaring success at admission. The existing maintenance lane `🔌️plugin/🪜️maintenance-ladder/🦀️.rs:412–433` drives the initializer and, at AwaitingMembers, seals an empty child roster or calls `complete_store_replacement_genesis`; it then performs closure, candidate-view preparation, guarded atomic commit and retirement. The latter child-genesis helper currently loops/builds a Vec and calls whole child encoding; a composed large-child case still needs a separate bounded audit. `poll_artifact_store_replacement` returns Ready only after Complete and committed; read `artifact_store_replacement_refusal` before `acknowledge_artifact_store_replacement`, which removes only a physically terminal owner. Mirror archive-load lines 467–484 of `📄️docs/📥️staging/🪜️maintenance-ladder/🦀️.rs`. On cancellation request `cancel_artifact_store_replacement(handle)` and keep driving/acknowledging: it cancels only before commit, while already committed ownership must finish retirement. Only then publish terminal success/fault/cancel and retire completion. Integrate the pending handle with mounted cancellation/close and prevent the generic stale-root check from rejecting the newly committed generation; update the mounted frontier from the accepted replacement, analogous to the stream-abort update at typed-operation-unit lines 55–57, without accepting unrelated intervening changes. Verify scheduling actually pumps replacement maintenance while publication is waiting and add progress/stall accounting for the new state.

The route changes native Rust ownership and completion vocabulary, not the external Pack, SPR, WIT, or UI result protocol. Test completion lock contention, undersized grants, duplicate handoff, stale identity, saturation/refusal return, cancellation before and after admission/commit, original-owner retirement and replacement acknowledgement, plus the mounted large-file success and independent oracle comparison. These are architectural findings; no compilation or tests were run.

The reserved natural-file producer now selects bounded original Pack export when its controlled decoder supplies a native Pack source. It limits the final Pack to the admitted output extent, advances the original encoder over the inactive snapshot, moves the verified result into typed genesis custody, and can retire the unfinished writer, snapshot, or completed genesis on cancellation. Its existing synchronous small-file route remains available for the registered PDF smoke. The framework-native mounted result consumer is being implemented against the typed completion port. A controlled PDF decoder still needs to drive the admitted parser and semantic snapshot stages to enable the new route for large files.
