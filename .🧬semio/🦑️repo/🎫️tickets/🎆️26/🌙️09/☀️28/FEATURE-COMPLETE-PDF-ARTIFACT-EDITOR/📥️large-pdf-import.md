# Large PDF import in mounted editors

The mounted Open route supports the explicit single-turn PDF owner for inputs at or below the current execution contract’s work limit. Inputs above it are refused by owner admission. The raw wire limit is separate. A larger file that passes the raw wire limit still needs a controlled decoder, and source size alone does not bound compressed-stream expansion.

## Decoder boundary

The mounted original request calls `NaturalFileImportWork::step_request` in the plugin declaration’s `📥️natural-file` module. It takes the owned input, then calls `ArtifactEditor::admit_natural_file_decode_owner`. The default creates the synchronous owner only for an opted-in format within its work limit. Implementing the older `build_natural_file_decode_owner` constructor alone does not affect the original request path.

PDF 1.7 base and its six profiles call the same whole-document `decode_pdf_with_password` pipeline under `🚪️io/📥️import`. The cross-reference module follows complete section chains, parses every referenced indirect body to validate offsets, and may scan the full input when recovering malformed offsets. Its resolver then sorts and materializes every object, expands object streams and logical filters in whole buffers, and normalizes retained values. The shared Flate path calls the sibling zlib artifact’s whole-output inflate routine. The typed lifter walks the page and resource graph, joins and parses complete page content streams, then lifts the catalog. A single object, compressed stream, page, or catalog section can exceed a turn’s budget, so splitting only by page or object is insufficient.

The PDF 1.4 editor uses a separate classic cross-reference reader with the shared COS lexer and stream filters. Its natural codec also re-encodes and byte-compares the entire document to admit only files its page model can preserve. That lossless admission would need bounded encoding and comparison as well.

## Publication boundary

`NaturalFileImportJob::step_original` calls `document_reference_load_emit` as soon as the controlled cursor returns `Complete { snapshot, progress }`. That helper calls the synchronous `ArtifactReferenceSnapshotCodec::encode` and builds a whole `LoadDocument` effect. For PDF 1.7, the reference encoder constructs an owned typed record, encodes a complete Pack buffer and wraps its envelope. The original importer also dropped the decoded snapshot in that turn, including on a rejected completion. The decoder cursor cannot grant or schedule that work.

The store’s existing `OriginalSnapshotPackExport` provides a bounded, cancellable encoder over `OriginalSnapshotPackView`, and retains the result as paged bytes. The PDF snapshot owner currently exposes the reference and SQLite codecs, with no native borrowed Pack source. The importer also needs a staged publication path that can transfer paged output or admit a typed genesis directly and retire the original snapshot in bounded steps.

## Required work and verification

A scalable route needs a persistent PDF decode state machine with paid transitions for xref and recovery scanning, COS tokenization and object/stream decoding, progressive resource and page lifting, and controlled retirement on cancellation or failure. The mounted owner must retain the decoded snapshot across bounded publication turns and expose completion only after the corresponding genesis is ready. Source progress, expanded bytes, decoded items, and completed work should be accounted by the operation that consumes each grant.

The mounted tests should use a valid PDF larger than the single-turn limit, with at least one stream whose expanded body spans several turns. They should observe monotonic decode and publication progress, cancel independently during each phase, assert unchanged document/history and a fully closed owner after cancellation, and compare completed PDF text, page order, and retained assets with the lopdf oracle. Separate cases should cover classic xref, xref/object streams, and the version-specific lossless admission. The repository already tests the generic cursor’s progress/cancellation with a small synthetic owner under `🏭️registered-factory-and-natural-decode`; it does not establish those properties for PDF.

This audit identified the above cross-module dependencies. The existing small-file admission stays in effect.

The classic xref reader now uses a resumable byte-budgeted cursor. The production synchronous parser consumes that same cursor. It yields each live or free entry separately, retains partial tokens and comments across turns, and stops at the trailer dictionary. The isolated Rust test read all eight live offsets in the two-page fixture with five grant sizes, including a single byte per turn. Trailer COS decoding, section-chain assembly, stream decoding, object resolution, document lifting, and mounted publication still need their own bounded paths.

The production footer reader now uses the same byte-budgeted reverse search exposed to a mounted decoder. A separate Rust test verified interrupted marker, whitespace, comment, integer, end-of-input, and invalid-offset handling across four grant sizes. MuPDF opened both pages in the shared fixture and independently resolved all eight live objects from its cross-reference table.

Literal and hexadecimal COS byte strings now decode through an allocation-free cursor into caller-provided spans. The regular parser drains that cursor. Independent Rust and MuPDF checks passed for seven cases covering nested parentheses, octal escapes, escaped line endings, odd hex lengths and empty strings.

Cross-reference streams now use a row cursor that can stop between any two field bytes. It reads directly from granted spans, treats absent fields according to PDF defaults, and detects overflow and truncation. Isolated Rust tests decoded the shared incremental fixture with all 28 input grant sizes. MuPDF read the final revision independently.

The importer now retains the decoded snapshot in the job before validating the final progress receipt. A separate checkpoint precedes reference encoding, and success, rejection and cancellation retire the retained snapshot through the normal grant-driven close path. Added registered lifecycle tests for the final phase sequence and cancellation between decoding and publication. Reference Pack generation remains a whole-record operation while the native borrowed field projector and paged publication route are outstanding. The new lifecycle tests are pending native execution.

The native lexer now frames indirect headers, typed COS values, and stream introducers separately. Stream payloads stay in their immutable input at that boundary. The classic xref parser uses the composed row-and-trailer cursor, and xref-stream parsing borrows the source span before filter decoding. A 15-test isolated Rust run exercised the production cursor code, including a one-work-unit pass over a real latest xref section with free entries, the matching typed trailer, and cancellation after a stream dictionary was assembled. The test harness omits serialization derives from the reused object model. The mounted parser still needs to connect these stages to object resolution, semantic lifting and store publication.

The structured reader and raw repair share resumable header scanning. The revision chain now uses bounded section-kind detection and typed Prev and XRefStm link lookup. The native importer tries intact absolute cross-reference offsets before retrying from the header when there is a preamble. Both conventions reopened with two pages and the updated title in MuPDF, which repaired both files. The native regression separately requires the freed Info object to stay absent.

The revision reader now emits target admission, typed rows, and a typed trailer across bounded turns. It reads a hybrid companion before committing the corresponding primary rows and follows Prev afterward. The ordinary reader drains the same cursor. Its sparse index migrates one slot per work unit, retains tombstones, and can retire both allocations after cancellation during a grow. The production-source harness passed 43 tests with the new reader and index, including a Flate revision followed by a classic revision.

The retained graph now passes its generation-aware directory into the semantic reader, so native import no longer rebuilds the directory before lifting. Supported filters read the original borrowed stream span directly. The sparse revision merge also keeps incomplete section entries provisional. The isolated retained-graph tests verified decoded content and predictor bytes, typed filter custody, and positions for every resolved object.

DocumentLiftCursor now separates paid page-tree work from explicit whole semantic actions for catalog, resources, and individual pages. The semantic action grant does not yet bound all work within a page. The mounted large-file path still needs nested semantic controls and bounded Pack or typed store publication.

The production repair path now scans once. It resumes beyond confirmed stream and COS body boundaries, borrows encoded object-stream bytes, and reads compressed-member declarations with the existing controlled header parser. It selects the latest physical candidate for each recovered object stream and preserves authoritative free entries. The production-source harness passed 53 tests. PyMuPDF 1.24.14 independently repaired the checked-in malformed PDF and reported one page, the text `Recovered`, the genuine catalog's `/Pages 2 0 R`, and Helvetica from the genuine font object. The fake catalog and font headers are inside an unused stream and a literal string. The synchronous repair drain still owns the table and staged object-stream declarations as a whole; a mounted coordinator must drive those owners under the interaction budget.

The reference Pack and DSL decoders now consume their decoded record fields, and the root snapshot and COS byte-string decoders move their inputs. This removes redundant deep clones at these three boundaries. Two native regression tests require preservation of the original document-ID and stream-byte storage. The related publication boundary remains full-record and synchronous, and the two new tests still need the real native gate.

Structured xref validation now exposes an allocation-free cursor that resumes in the sparse table and within each indirect header. It checks the object number and generation together. The retained resolver also uses exact generations for indirect stream lengths, encryption references and graph-source lookups. The isolated cursor test passed on real entries and rejected a deliberately mismatched generation under one-unit work grants. Full native integration remains queued.

The revision assembler now drives section visit admission, provisional row insertion, newest-revision merge, and physical retirement one action at a time. It yields validated primary trailers to the caller and assembles the directory without a separate visited-offset allocation. Both the ordinary structured reader and the bounded entry point use it. The production-source classic-xref harness passed 26 tests, including the real incremental fixture, cancellation after the first retained allocation, exact release accounting, the two primary trailers, and the root-preserving tombstone. The harness omitted the two compressed-section cases because the native Deflate artifact lease was unavailable. Those cases remain in the native suite.

The header probe now yields the original file origin and its validated version from a single resumable scan. A structured file xref cursor drives footer search, revision assembly, and generation-aware offset validation under one grant. The synchronous PDF reader now uses both cursors, and exhausted xref reconstruction reports a malformed file through the normal error path. The focused actual-source Rust harness passed 30 tests, including one-unit reads at the header search boundary, both primary revisions, wrong-generation rejection, and exact release on cancellation. PyMuPDF 1.24.14 opened the classic incremental fixture without repair and independently reported two pages, `/Root 1 0 R`, `/Info 9 0 R`, object 3 freed, and the title `Updated`.

Structured trailer folding visits one entry at a time and passes the latest dictionary, original inherited fields and validated object directory as one result. Older dictionaries retire under the same work and release limits, including after cancellation or a refused release grant. The classic-only harness passed 32 tests. Once a native Deflate artifact became available, the combined actual-source resolver, lexer, filter, and xref harness passed all 63 tests with no skipped tests. Retained stream dictionaries now compact within their parser-owned buffer and retire removed keys and nested parameters under per-turn grants. Existing byte order and backing are preserved for retained entries, including external-file declarations. The full isolated production-source PDF resolver harness passed 65 tests with the new dictionary projection. Small PDFs that supply the native snapshot Pack source now enter the same paged publication ladder intended for the controlled parser. Normal indirect object projection now drives framing, indirect length negotiation, filter planning and in-place dictionary compaction under the same turn grant. Bare page-program operators now borrow the original byte range, and complete COS operands transfer out of the same controlled lexical cursor used by the page and form reader. The actual-source lexer, filter, resolver and xref harness passed 71 tests. File-order projection now visits the xref table under grants and reorders object IDs with one heap level per work unit. Compressed members stay after their physical container and respect embedded order. Page content borrows single-stream backing directly and joins split streams once in authored order. The document lift now preserves its semantic state between short graph borrows. This removes the self-borrow that would otherwise prevent an owned mounted decoder.
