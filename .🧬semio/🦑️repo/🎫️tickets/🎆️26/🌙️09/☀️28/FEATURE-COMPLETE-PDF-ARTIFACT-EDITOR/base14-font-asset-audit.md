# Base 14 font asset audit

## Local evidence

- The installed node_modules/pdfjs-dist 5.7.284 contains FoxitSerif, FoxitFixed (four styles each), FoxitSymbol and FoxitDingbats, and LICENSE_FOXIT. The license permits redistribution with retained notices and disclaimer and limits endorsement. The .pfb names are misleading: inspected FoxitSerif and FoxitSymbol start 01 00 04 02, a raw CFF header. The package does not contain a Foxit sans face.
- Local LiberationSans-Regular.ttf reports version 1.07.4 and a Liberation Fonts license URL in its name table. The adjacent LICENSE_LIBERATION asserts OFL 1.1; that is inconsistent with the version metadata. Upstream PDF.js confirmed and corrected the same mismatch: https://github.com/mozilla/pdf.js/issues/21746. Determine exact version/source and obligations before redistribution; do not call this copy OFL on the basis of the adjacent notice.
- The macOS system has Helvetica, Times, Courier, Symbol and ZapfDingbats, but system-only fonts are not a zero-touch cross-platform asset solution and availability does not grant redistribution rights.
- URW Base35 upstream states AGPL-3.0 with an exception for embedding in a document; the exception does not automatically make shipping font programs permissive: https://github.com/ArtifexSoftware/urw-base35-fonts/blob/master/LICENSE.

## Implementation route and limits

The font module already has StandardFontMetrics including AFM widths, builtin Symbol and ZapfDingbats encodings, and FontCodec decode_codes, outline_units and glyph_outline. Raw CFF handling visits glyph names and builds code-to-glyph IDs. The scene TrueType outline routine already consumes the common outline segments, honors text adjustment, spacing and PDF widths. Add a deterministic standard-font program source through this interface, retaining the PDF encoding and PDF-provided/standard widths; do not replace advances with substitute-font advances. Verify actual CFF parser acceptance and each glyph mapping rather than assuming the header guarantees support. Missing glyphs must be explicit rather than silently becoming glyph zero. Preserve all variants, encoding Differences, symbol names and ToUnicode behavior.

ControlledFontResources standard_type1 currently rejects symbolic standard fonts, so Symbol and Dingbats must be admitted on that path or handled by the reference importer. Local Foxit Serif/Fixed/Symbol/Dingbats are a feasible candidate after provenance and coverage tests, not proof of exact Adobe outlines; PDF.js upstream notes incomplete Foxit coverage: https://github.com/mozilla/pdf.js/issues/14843. A correct cross-platform Helvetica source and its style variants remain unresolved from these local assets; PDFium upstream also has a generic FoxitSansMM source (https://pdfium.googlesource.com/pdfium/+/refs/heads/chromium/8163/core/fxge/cfx_standardfont.cpp), but multiple-master parsing, licensing and glyph coverage must be verified before selecting it. No runtime system font or node_modules path is a reproducible distribution solution. No assets were copied.

## Independent checks

Create small unembedded Base 14 PDFs for regular and bold/italic variants with mixed-width strings, spaces, TJ offsets, character and word spacing, and explicit encodings/Differences. Include Symbol alpha (code 97) and Dingbats glyph codes, comparing glyph identity and placement as well as widths. Compare generated scene raster to MuPDF under a pinned build/font configuration, allowing documented antialias tolerance; different valid substitute outlines can differ, so record expected source and assess geometry/ink bounds rather than claim byte-identical images. Separately compare advances and individual glyph positions against independent MuPDF extraction, including PDF width overrides. Exercise source fixture, save/reopen and mounted paint, and ensure unsupported glyphs do not silently paint unrelated UI fonts. These checks are proposed; no renderer was run in this audit.
