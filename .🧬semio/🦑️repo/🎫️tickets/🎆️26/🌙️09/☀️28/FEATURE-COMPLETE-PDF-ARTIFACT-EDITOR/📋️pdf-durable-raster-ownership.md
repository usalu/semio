# Durable PDF Raster Ownership

The registered native mutation wire can preserve a typed image's samples through the same publication, archive, and history owners as its placement. The current image model stores samples in one `Vec<u32>`, and its controlled canonical SetImage receiver caps that single allocation and cancellation return at 1 MiB. A 521 × 257 RGB image already needs 1,606,764 bytes in that representation. Widening the picker source alone cannot admit that image into durable history.

The Store composition interface declares a content-addressed `BlobStore` and can resolve a snapshot pin on demand. Its current API takes a contiguous slice, returns a contiguous vector, and does not make that storage part of the PDF document's irreversible mutation publication or archive. The Store operation-wire override borrows payload for encoding. The PDF renderer's resource resolver separately finds conventional COS stream owners. A detached blob referenced by new PDF rows would therefore miss the current reopen and Save path.

Two bounded owners remain plausible. An inline paged sample owner would retain the existing standard sampled-image meaning and publish image and placement in one Store edit. The values system already provides paid paged list reservation, retirement and canonical traversal, as well as language-neutral JSON values. The current controlled JSON sample donor, PDF import replay and native render/export sample consumers would need to work with the same page owner. The existing Pack design instead carries the compressed source or verified color/mask planes in a sealed page owner with exact original digest. It needs a mounted attachment publication that commits rows and source in one durable event and reconstitutes its read lease from the archive. An authority that retained an unmounted scratch Pack would produce rows that cannot reopen.

The existing small PNG path remains operational during this work. The staged picker must acknowledge completion only when either complete durable model can provide an unchanged resolver after close and reopen. The mounted acceptance must additionally cover release and absence after stale revision, cancellation, undo and a failed grant, and verify source geometry and pixels through an independent PDF reader.
