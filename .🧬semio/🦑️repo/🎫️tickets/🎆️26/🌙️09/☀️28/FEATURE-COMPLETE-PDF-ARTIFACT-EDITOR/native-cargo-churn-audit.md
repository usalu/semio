# Native Cargo Churn Retry Audit

The native launcher holds the pooled lane and Cargo build lease through execution, but captures the compilation graph and admits source boundaries only before the pass. Reuse runCargoPassAttemptsV1 and failedDependencyDriftV1 inside the existing admitted execution scope, before consumeExecution, retaining the same lane, capacity, broker, jobserver, storage reservation and full-image retry. Retry only a failed compilation when bounded physical reads prove a changed source checksum from a dependency of the failed compiler unit, subject to existing error-code and repeated-witness limits. Do not retry test failures, signals, cancellation, disk-full outcomes, execution errors, or an unproven compiler error.

Reobserve the Cargo graph, admit sources, and reobserve it again using admitWarmCargoRetryGraphV1; require the two observations to agree and the replacement to fit all held admission and resource constraints, or conservatively require equality to the original graph. Recheck storage and control around every probe and attempt. Preserve retryWhenFullV1 per attempt and invoke the capture consumer or generated-file publication exactly once for the final attempt.

The current native transport does not supply compiler artifact identities or error codes: streaming runOwnedCommand exposes human lines, and capture contains caller-requested output, not structured metadata. The component driver obtains these from Cargo JSON compiler-artifact and compiler-message records. A correct implementation therefore needs structured observation, not inference from human diagnostics: either a separate supported metadata channel or a carefully scoped JSON transport and parser. For JSON transport retain caller-selected message formats and raw capture semantics; only use it where a compatible translation can preserve stdout/stderr, Cargo progress, rendered diagnostics, test output, and stream timing. Never silently rewrite arbitrary explicit --message-format or arbitrary subcommand output. Suppressing failed attempts also changes streaming semantics; preserve each attempt's diagnostics or explicitly constrain retry eligibility. Test mixed stdout, stderr, JSON formats, test failures, disk-full, cancellation, bounded probes, graph drift, and one-time output publication before enabling.

Examined the native Cargo launcher, component-pass driver, and its failure-churn helper.

## Staged Review

The broker supplies compiler exits and extern artifact stems without changing Cargo output. The staged graph observations compare complete graph values and conservatively refuse a changed selection. The existing scanner accepts hashed extensionless extern stems and derives both possible dep-info names.

Two trigger blockers remain: broker records must be scoped to each individual child execution inside the full-disk retry, and the dependency diagnostic must be associated with the failed compiler unit whose dependencies are scanned. Otherwise records from a full-disk attempt or an unrelated concurrent unit can authorize a retry after an unrelated failure. Requiring a single failed compiler unit and excluding post-compilation commands is a conservative fallback. Validate with actual broker-shaped stems and mixed full-disk/compiler/runtime failures before adoption.
