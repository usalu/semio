# Large Natural PDF Ingress Audit

## Existing path and ownership

Browser Open in ShellHost document-transfer-tabs (lines 427–467) selects and routes a file by a bounded head, resolves the registered editor, then reads the complete selected Blob within the encoded MediaIn budget before creating a fresh app. openNaturalFileOwnerV1 owns that app through import and destroys it on failure; keepProgramDocument persists and verifies the document before focusing the new editor. Native WGPU open.rs (lines 25–82) owns one cancellable opening task, selects a path, reads a bounded whole file, creates a fresh instance, and guards it with NativeOpenedFile::Drop. It imports, checks the document identity, writes and reads back the archive, and only then returns the owner for publication. The in-flight native request is dropped on cancellation, allowing its kernel abandonment/closing lane to retire it. This fresh owner and persistence ordering must remain intact.

The ordinary MediaIn command is one encoded payload, with an 8 MiB assembled-command ceiling. Increasing the host read limit alone cannot work. Plugin instance media-transfer converts the binary artifact data into intrinsic Media bytes, and NaturalFileImportWork explicitly requires owned Vec bytes and hands that Vec to the decoder. Base PDF registers s.stdio.pdf@1.7 and calls build_pdf_natural_decode/admit_pdf_natural_decode; its editor currently declares SINGLE_TURN_NATURAL_DECODE. Thus transport segmentation alone does not establish bounded full import: the decoder contract itself currently consumes a contiguous Vec, and final archive encoding/storage also currently assembles bytes. Both need separate measured limits or bounded owners before claiming no unbounded allocation.

## Integration direction

Use a distinct, guest-issued **natural-open source** on the newly created, still-unpublished instance, scoped to that instance, operation/generation, declared format and selected extent. The browser must create the owner after routing and before reading the selected body; native creates it after selection and before reading. The guest issues a loan in response to an explicit natural-open preparation, rather than reusing an image picker loan or inventing a document revision before genesis. Transfer Begin, exact ordered bounded pages, and Complete/Cancel with acknowledged backpressure; validate all identity and extent fields on every turn, do not acknowledge Complete until the decoder and genesis publication finish, and retire partial input and pending work on cancellation, errors, owner destruction, or supersession. Reuse the existing original-media sender and paid page/closing machinery only after generalizing their origin and receiver contracts; preserve isolation from the selected-image loan and its revision/placement semantics. Native must stream from its selected file handle and browser from Blob slices, never materialize the whole file on the host.

The raw image route is not a drop-in natural Open: its issued intent is bound to an existing document, full revision and trusted image placement, and the actual native picker selects PNG. Original-media reactor/product reports describe an overlay and explicitly identify remaining mounted PDF format and storage work; they do not prove a production natural PDF route. Conversely, file-backed NaturalAttachment/Pack custody can be an appropriate destination for retained bytes only if its actual implementation is available in both browser WASM and native, accepts bounded ordered writes and paid retirement, and can be lent to the PDF decoder without materializing a Vec. No NaturalAttachment symbol appeared in the inspected plugin and PDF source roots; its availability and exact API were not established by this audit. Do not assume a native path or file handle can cross the WASM boundary, and do not wrap the existing Vec API with a segmented sender and call it bounded.

After complete coverage, connect the paged or random-access source to a PDF decoder owner that advances under real work/copy/memory grants, reports progress and checks cancellation, then feed its resulting snapshot through the existing NaturalFileImportJob genesis/LoadDocument and completion path. Preserve pending completion until the actual document is accepted; never publish a partially decoded document. On success retain the existing identity recheck, archive durability/readback and focus/publication sequence. Audit archive/snapshot serialization separately: its current whole-buffer behavior may still make a large Open fail even after bounded ingress, so the end-to-end claim depends on replacing or proving those allocations as well.

## Required verification

Add one shared language-neutral fixture with an ordinary valid PDF larger than 8 MiB and its expected digest, page count and content, independently checked by a third-party PDF reader. Exercise both browser and native actual picker-to-published-document paths, exact bytes and a measured maximum read/page allocation, decoder progress, cancellation during a pending read, transfer, decode and persistence, and successful retry. Cover extent over limit before reads, short/trailing reads, stale/wrong loan or generation, duplicate/out-of-order pages, terminal retry, backpressure, instance closure, decode error, and archive failure; verify no publication and full retirement on each failure. Test exact encoded-command boundary separately so the small existing MediaIn route remains correct. Measure all simultaneously retained input, decoder, snapshot and archive allocations, not merely the sender window. No heavy build or source modification was performed for this audit.
