# CAD React End-to-End (2026-09-16)

Pipeline under test: `@semio-tech/cad-plugin:component-dev` → `activate-cad-react-dev` → `serve-cad-react-dev` on `http://127.0.0.1:6020/?plugin=cad` (launch entry `🛠️dev📐️cad⚛️react`). Repo MCP was down, so bookkeeping is on disk; the serve ran under `screen -dmS semio-cad-react` ([📜️serve-cad-react.sh](./📜️serve-cad-react.sh)) and every guest change was restaged with [📜️activate-cad-react.sh](./📜️activate-cad-react.sh) (a running Vite serves new wasm bytes without a restart).

## What "working" looked like at the start

The 2026-09-15 fix ([cad-ui-surface-capacity-2026-09-15.md](./📓️cad-ui-surface-capacity-2026-09-15.md)) made the four windows publish without a fault — by replacing every solid's BREP tessellation with a built-in `box`/`cylinder` kind. Fixture-derived objects have `origin = [0,0,0]` (the authored placement lives in the solid's own vertices), so the Concrete Forest rendered as one unit cube per pane (boot-1 screenshot). Beyond that: no reference image (URL pointed at the pre-rename filename), no auto-fit, no `cad` interaction domain on the scenes (clicks dispatched the legacy `worldPick` verb the app has no handler for), the inspection panel always read `Objects: 0`, the Artifact tree listed no objects, and every config gesture (`setReferenceSelection`, `setCamera`, …) failed the store's fold contract.

## Open (not closed by this ticket)

1. **Object mutations are documented no-ops**: `addObject`/`patchObject`/`patchSelection`/`deleteObject`/`duplicateObject`/`translateSelection`/`rotateSelection`/`scaleSelection` return `Emit::default()` because object data lives in composed `s.stdio.semio.model` children. The seam now exists (`Emit.child_emits` / `ChildEmit::of::<SemioModelSnapshot, _>` with `SetSpatialNode`/`SetElement`, as `🌊️flow` uses) but re-materialising the pane's `CadWorkingScene` local owner after a child edit is the part no plugin has done yet, and a peer is mid-change in `🏪️store` composition — left alone deliberately. Dragging the gumball therefore snaps back, and the gumball sits at the world origin because fixture objects carry `origin = [0,0,0]`.
2. **Tree paging navigation**: the document tree closes an over-page section with a plain `+N` row (no `setPanelPage` command yet — that needs a `panel_pages` config field across the five schema twins plus the route/proof/fixture registrations puzzle 3d carries).
3. **Engagement HUD `N selected`**: `window_engagements` has no request context, so the count is live only on the render path; the HUD shows 0.
4. **Test-harness debt** listed above (registry-backed `new_app` migration for the wrapper tests, store harness contracts).
