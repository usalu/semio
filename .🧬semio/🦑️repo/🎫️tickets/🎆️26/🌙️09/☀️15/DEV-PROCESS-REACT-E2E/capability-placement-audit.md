# Capability Placement Audit

The positioned preview and world click both resolve the first installed capability of the selected cut, drill, or attach measure kind; if none exists they use the generic fallback. See `✏️editor/🎭️modes/✏️edit/🪟️windows/🪚️workpiece/👆️placement/🦀️.rs:8–23`, `✏️editor/🎮️commands/🌍️world/🦀️.rs:174–181`, and `🧬️schema/💡️inferences/🦀️.rs:355–373`. Default generic machines precede contributed installs (`🧬️schema/📸️snapshot/🪚️machines-and-catalogs/🦀️.rs:211–264`). Catalogue rows identify a specific machine and capability but immediately dispatch addStep rather than arming placement (`✏️editor/📌️panels/🛍️catalogue/🦀️.rs:51–60`).

A contributed capability is indirectly reachable: remove all earlier workshop machines producing its measure kind using their workshop menu, install the intended machine first among the remaining matching machines, then choose that utility and hover/click. For example, after removing Generic Saw, a first installed chopSaw resolves its chop capability for both hover and commit. This is an ordering effect, not an explicit selection of a capability. Other contributed cuts cannot be selected while an earlier matching machine remains. No live execution was performed.

A narrow reuse path is to arm a machine/capability identity in window-local ephemeral state from a catalogue action, share a resolver based on existing `find_capability`, stock validation, and `measure_for_capability` (`✏️editor/🎮️commands/🪜️step/🦀️.rs:32–56`) between preview and commit, and preserve that identity in StepOrigin. The existing hover transient already reaches `render_with_placement` (`✏️editor/🪟️editor-impl/🦀️.rs:18,411` and `✏️editor/🎭️modes/✏️edit/🪟️windows/🪚️workpiece/🦀️.rs:206–216`).

## Catalogue Action Window Address

A catalogue row may expose a secondary row-action verb against the same RowTarget arguments as its activation (`🔌️plugin/🪟️window-kits/📊️table/🦀️.rs:243–269`). Panel rendering clears its own window id while retaining valid focus (`🛂️manifest/🖼️view-model/🦀️.rs:221–234`), but host action dispatch scopes an action to a concrete window first. React resolves provenance, arguments, then focus (`🏛️ShellHost/🎯️input-ledger/🟦️.ts:62–70`) and stamps the window in the invocation (`🏛️ShellHost/📨️window-invocation/🟦️.ts:38–54`). WGPU resolves a panel alias through session view, active window, then fallback (`🐚️Shell/🎯️targets/🧊️wgpu/📥️staging/🎛️prefs/🔖️identity-and-types/🦀️.rs:35–39`; invocation at `🎛️prefs/🧩️session-and-topology/🦀️.rs:25–38`). The incoming concrete view must still name a live Workpiece; do not infer one from a kind or fabricate one.

Transient capture is keyed solely by the incoming view window id (`🔌️plugin/🪟️window/🫧️transient/🦀️.rs:520–529`) and publication rejects a different address (lines 532–540). The placement wrapper already refuses non-Workpiece or missing addressed views (`✏️editor/🫧️transient/👆️placement/🦀️.rs:42–57`). Existing two-window tests verify a forged windowId argument does not redirect the view-owned effect and sibling hover stays isolated (`🪚️workpiece/🧪️tests/🔬️unit/🦀️.rs:192–251`). WGPU alias tests cover precedence and fallback (`🐚️Shell/🧪️tests/🔀️wgpu-document-relay/🦀️.rs:187–190`). These are source-level observations; no test was run in this audit.
