Its admitted execution path does not materialize a frozen Rust source tree. The relay independently admits the source boundary and then calls `startToolV1("cargo", ..., { cwd, ... })` at `📚️library/🏃️process/🟦️.ts:76–89`. Thus admission reads Rust content for source bounds and graph facts, but is not a lock on checkout source bytes throughout Cargo/rustc execution. Cargo can compile a dependency before a replicated edit and read a consumer after it. The observed matched source edit timestamps and diagnostics are consistent with this mechanism; they do not alone prove which bytes each rustc read.

The separate generated Rust unit path records source path, digest and byte length and verifies an individual unit against its descriptor (`📚️library/⚡️caching/🦀️cargo/📦️units/📥️inputs/🟦️.ts:11–14` and `📦️units/📥️descriptor/🎯️selection/🟦️.ts:42`). It is not evidence that ordinary `repo cargo` executes rustc against a frozen workspace. The snapshot capture rechecks source after its reader completes (`📥️inputs/🎯️selected/📦️snapshot/🟦️.ts:37–40`).

The documented fresh native generation parameter applies to the Play build and root release targets (`🦑️repo/README.md:1229`); its documentation does not claim a coherent checkout snapshot.
