# Direct launch admission

The current command catalogue documents `repo run @semio-tech/framework-os-dev:dev-process3d-react-prototype --exclude-dependencies` (and the corresponding `dev-process3d-wgpu-prototype`) as a supported direct task mode. The catalogue in `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🏗️build/⚙️operations/🔣️catalog.json:826–832` says only the named owner is admitted and the task receives the issued invocation envelope, task identity, and store receipt. `🕸️graph/🚪️admission/🟦️.ts:153–156,230–232` and `🕸️graph/🧭️discovery/🟦️.ts:48–56` implement direct admission and owner-restricted inference; this is materially smaller than dependency closure. The mode is conditional on prerequisites already being built: it does not establish their freshness or build them.

Generated playground targets and their dependencies are defined in `🕸️graph/📥️inference/🎮️playground-targets/🟨️.mjs:137–169,229–260`: React dev requires activate, which requires prepare, registry session, browser support, fonts, engines and boot components. Thus using the direct dev task alone cannot establish the actual component activation. Existing successfully completed prerequisites and their authorization/freshness have not been independently verified in this audit, and generated-target discovery under this precise direct scope has not been executed. The prior raw script invocation failed because it lacked an issued parent. A direct-mode run is a supported candidate once its generated target resolves and every prerequisite is evidenced current, not an established equivalent replacement for the live canonical run. No build or cache was touched.
