# Terra Audit — Current AI Map End-to-End Integration

Date: 2026-09-04  
Scope: current working-tree, read-only source audit. No build, launch, model call, or test was run by this audit; `source-only` below is deliberately not a runtime claim.

## Verdict

**RED — there is no end-to-end AI map feature to invoke.** The repository has a bounded, deterministic local GIS inference function and a reusable plugin-host `semio.infer` cold-job mechanism. It does not have a user action for inference, an authenticated server admission route, a model/provider implementation, durable job/result persistence, or a collaborator-visible inference projection.

The present MCP outcome is intentionally honest: `inference_get` resolves declared metadata then returns retryable `PLUGIN_UNAVAILABLE` with `channel.not-wired`. It must not be reclassified as an AI result or treated as an integration failure hidden by a generic job handle.

## Exact gaps and required boundary

1. **No user-to-job action.** Add one GIS-owned request action only after the UI has an authoritative opened-document binding. It must submit a server-minted request/binding, never map bytes, a raw bearer, a role, or an actor identity. The UI needs a bounded private progress/cancel/result state machine; it must clear on revocation, document change, route close, and unmount.

2. **No server-owned inference contract or provider.** Define versioned `InferenceJobV1` command/event/result/proposal schemas. The hub alone must resolve the authenticated subject, membership/capability epoch, space/document, verified P4 pair, descriptor/package/wasm/provider identity, exact frontier, canonical input digest, budgets/deadline, request digest, and cancellation id. Introduce a narrow trusted executor/provider port; do not expose an external provider credential or the mutable `ArtifactInferenceRouter` to UI/MCP.

3. **No durable result or stale rule.** Append bounded lifecycle events (`Requested`, `Admitted`, `Queued`, `Started`, bounded `Progressed`, terminal `SucceededCurrent`/`Stale`/`Cancelled`/`Failed`) in the authoritative hub document/space lane. Persist CAS result references and a server-side idempotency record. Revalidate authorization and the exact frontier at result publication and again at read/apply; a changed frontier makes the result `Stale`, never current.

4. **No approved mutation contract.** Keep inference query-only. Define one GIS-owned proposal, explicit approval bound to `(proposal digest, input/result/executor identity, frontier)`, atomic expected-frontier apply, typed inverse/undo, and server audit event. Do not send inference bytes through generic JSON patch or auto-apply them.

5. **No collaborator projection.** Expose only authorization-filtered job/result/audit projection events. Progress is private/best-effort and bounded; a reconnect must reconstruct terminal state from persisted events. Share/public users receive neither map input nor private job/result/proposal detail unless a separately reviewed redacted policy is added.

## Smallest truthful proof after implementation

One registered non-cached integration target must use a temporary SQLite hub, two independently authenticated members, the real trusted GIS executor, and a raw protocol client separate from the UI. It must prove: member-only pair/input admission; provider/executor identity mismatch denies before execution; bounded progress; queued/running cancel; revocation during work; edit-during-work yields exactly one stale terminal result; restart/reconnect reconstructs terminal state; a collaborator cannot read private work; explicit proposal approval applies exactly once at the expected frontier; and typed undo is separately authorized/audited. Its independent oracle should decode the persisted GIS result and compare bounds to the existing `geo::BoundingRect` vector oracle; that local oracle alone is insufficient for auth, persistence, or collaboration.
