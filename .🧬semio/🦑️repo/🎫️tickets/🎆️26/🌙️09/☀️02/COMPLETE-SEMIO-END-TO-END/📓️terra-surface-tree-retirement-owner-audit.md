## RED: runtime surface retirement remains an unsafe duplicate owner

The runtime's `SurfaceTreeRetireCursor` owns `BuiltNode` data directly rather than using the now-green contract owner. It moves only ordinary `children`, never `rejected_children`, and it drops a node without retiring its nine typed fields (`key`, component, layout, style, activity, disabled, accessibility, bindings, menu). [old cursor](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:2327)

The cursor has three independent ownership bugs.

- `begin` unconditionally assigns `self.node`; it has no owner-empty assertion or retained-source return. The current private scheduling appears to serialize the reachable calls (taking `pending_root` before creating `held_node`), so this audit does **not** claim a demonstrated current double-begin trace. It remains an overwrite-permissive ownership API with no law preventing a future rejection/overflow ordering change from losing the first root. [cursor calls](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:2133) [terminal call](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:2572)
- `is_empty` ignores `overflow`; an overflow iterator would remain retained while the cursor reports terminal. With the present fixed child-page authority, the 4,097-depth overflow branch is not shown reachable by an admitted 384-page tree, so this is a latent bad branch rather than a separately demonstrated runtime loss. [empty predicate](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:2382)

The old 4,097-frame allocation is neither the contract's bounded page authority nor a correct stack for nested overflow. [overwrite](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:2356)

`TreeNode` is exactly `ui_contract::BuiltNode`, so no conversion, cloning, or new retirement format is required. [type alias](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/🎭️present.rs:77)

## Smallest safe adoption

1. Delete the bespoke `SurfaceTreeRetireCursor`; replace each runtime `retire_tree` field with a small wrapper containing `Option<ui_contract::BuiltTreeRetirement>`. The wrapper must create `BuiltTreeRetirement::new(tree.root)` only when it is empty, call `close_step(1, SURFACE_RECONCILE_PAGE_BYTES)`, and take/drop the owner only after `complete && terminal_is_empty`.
2. Reorder all producer and terminal close paths: drive a nonempty tree owner first; only then take `held_node`, `pending_root`, or `source` and begin the next owner. A busy begin must leave its `ComponentTree` in its original source field; it must never replace an owner or return a raw root that can drop.
3. Preserve the contract's strict terminal semantics. `BuiltTreeRetirement::Drop` deliberately panics for a nonterminal owner, so a `close_step` error cannot become a normal `SurfaceReconcileFault` followed by state disposal. Pending child-page contention remains retryable; an invariant error must retain the same owner in the handback state (or be treated as an invariant-fatal path), never overwrite, forget, or direct-drop it. [contract owner](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧬️contract/♻️retirement/🌲️built/🦀️.rs:27) [nonblocking child handback](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧬️contract/♻️retirement/🌲️built/📋️children/🦀️.rs:11)
4. Keep the existing reconciliation handback queue as the only abandonment path. Every state that can own a nonterminal built-tree owner must already have a valid reconciliation handback before constructing it; a dropped job/rejection/terminal then moves the same state into that queue. [job drop](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:3207) [queue transfer](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:2608)

## Review of the proposed lazy runtime cursor

The proposed private `SurfaceTreeRetireCursor { owner: Option<BuiltTreeRetirement> }` is the right direct adoption **if** it does not take a source while a prior owner exists. It removes the current eager 4,097-entry iterator allocation from every reconciler state and creates the contract's fixed 384-page stack only once an actual tree enters closure. That is both bounded by the child-page authority and materially smaller than the old resident allocation. [old eager allocation](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:2333) [fixed contract stack](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧬️contract/♻️retirement/🌲️built/🦀️.rs:32)

Do **not** make `try_begin` generic over `FnOnce(T) -> BuiltNode`. It necessarily moves `T` out of its `Option` before calling the mapper. A future mapper that panics or accidentally does more than a field move loses the source before a strict owner exists. The three known conversions are finite and infallible: a `ComponentTree` root, a raw `TreeNode`, and the node portion of the retained `(parent, TreeNode)` tuple. Use three concrete private methods (`try_begin_tree`, `try_begin_node`, and `try_begin_held`) or one private `begin_owned(BuiltNode)` called only after the corresponding explicit owner-empty check. The methods must return `false` without taking when occupied or source-empty.

The new contract box remains absent from `SurfaceReconcileUsage`, just as the old 4,097-frame box was absent; that usage currently measures materialized surface nodes/items/bytes, not close-cursor storage. [usage definition](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:582) Consequently this patch reduces and delays an existing uncharged fixed allocation, but it does not prove that every reconciliation allocation is credit-accounted. For this bounded owner patch, do not alter public usage numbers or claim a new all-resident accounting guarantee. If allocation itself must be governed by admission, reserve the contract stack's exact fixed bytes before taking the source and make construction fallible; an infallible `new` cannot truthfully recover an allocation failure while retaining the source.

The close routine must keep an `Err`ing `BuiltTreeRetirement` in the same retained state; converting it to an ordinary reconciliation fault then dropping state violates the contract's nonterminal `Drop` guard. A `Pending` result is the normal requeue path. The proposed integration needs no new queue: the current bounded `SURFACE_RECONCILE_HANDBACKS` queue already performs one close opportunity and requeues the same state. [one-turn handback](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:3397)

### Required no-handback rejection decision

There is one direct-adoption blocker that a strict tree owner makes observable. `try_new_reserved` can return a `SurfaceReconcileRejected` carrying `source: Some(tree)` with `handback: None` when handback admission fails. [rejection construction](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:3020) That public rejection currently exposes both `take_sources` and `close_step`. [methods](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:3226) If `close_step` starts a `BuiltTreeRetirement` and its caller drops the rejection, `handback_surface_reconcile` has no reservation and returns; the nonterminal contract owner then panics during state destruction. [empty handback return](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:2608)

Choose one explicit invariant before beginning the strict owner:

- Reserve/reacquire a bounded existing handback before allowing close to take the tree; or
- for a rejection with no handback, make `close_step` decline without taking and require the caller to use the existing `take_sources` recovery path.

The second is the smaller scope and retains the source exactly, but needs a native law proving the no-handback close leaves the tree extractable and cannot create a strict owner. Neither choice needs a new queue. The proposed direct adoption is RED until it makes that disposition explicit.

### Preferred admission repair and exact law

Reacquiring one existing bounded registry reservation before public rejected closure is feasible and preferable to a new extractable-only mode, but only through a **nonblocking** helper. The existing `reserve_surface_reconcile_handback` and `acquire_surface_reconcile_handback` use a blocking mutex, so calling them unchanged from `SurfaceReconcileRejected::close_step` would introduce a blocking registry acquisition into a bounded close turn. [existing reservation](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:2439)

Extract a `try_acquire_surface_reconcile_handback` counterpart which uses `try_lock`; `WouldBlock` or a full free list returns `None` without changing state, while poisoning follows the existing reservation policy. It must first attempt to move/rebind an already-owned exact-generation reservation from `current`, `candidate`, or `output_handback` in the same priority as the existing handback transfer, then try a free slot. [existing transfer priority](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:2608)

Only `SurfaceReconcileRejected::close_step` and `SurfaceReconcileTerminal::close_step` should call a `close_admitted_step` wrapper, and only when `state.source.is_some() && state.handback.is_none()`. It must acquire before clearing the fault or taking the source; on unavailable capacity it returns `false` unchanged. The registry reaper must continue calling raw `state.close_step`: while it holds a queued slot, `state.handback` is intentionally absent and re-entering that registry lock would be wrong. [public rejection close](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:3268) [reaper lock then close](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧠️runtime/📦️packages/🦀️rust/♻️reconcile.rs:3403)

The smallest native law is entirely in the existing reconciliation module: reserve every `SURFACE_RECONCILE_HANDBACK_SLOTS` slot, create `SurfaceReconcileJob::try_new` with a fresh reconciler, a nonzero generation, and a tree containing typed data plus a rejected child page. It must obtain a `Rejected` source with no handback; one public close returns `false` while a test-private observation proves the fault and root remain unchanged. Release precisely one held reservation, then drive public close to `terminal_is_empty` and verify the typed/rejected probe closed. This verifies no source take on saturation and later exact closure through the same existing slot. It needs no local mutex: the focused target is isolated; the broad raw-libtest fallback already serializes with `RUST_TEST_THREADS=1`, while nextest uses separate processes.
