# Complete Semio End to End — Plan of Record

Ticket: `26/09/02/COMPLETE-SEMIO-END-TO-END`  
Goal: `🎯r2603`  
Issue: https://github.com/usalu/semio/issues/2607

## Outcome

Ship one coherent Semio system in which:

- the OS shell starts through registered launch targets and exposes every installed plugin, app, artifact standard, viewer, editor, inference, mutation, and I/O contribution that declares itself available;
- users create, open, share, edit, checkpoint, and recover artifacts inside collaborative spaces;
- the hub persists directory and document events, scopes presence correctly, tolerates short connection loss, and exposes complete bilingual administrator workflows;
- the AI gateway discovers the live catalog, acts on the active map/artifact through typed capabilities, reports progress, supports cancellation, and preserves per-user/session authority;
- React and native shells agree on the same schema-first contracts and observable behavior;
- every acceptance statement is backed by a command log or runtime trace from the current tree.

## Coordination Contract

- Main lane: integration plan, dependency ordering, evidence review, acceptance decisions, and ticket lifecycle.
- Terra xhigh lanes: read-only exploration and post-change audits. Production files are not edited; each audit writes one report in this ticket.
- Sol xhigh lanes: bounded test-first implementation packets with focused verification and a report in this ticket.
- All four available agent slots stay occupied while independent work exists.
- Concurrent edits are expected. Every lane rereads a region immediately before editing and attributes failures to current evidence rather than reverting or overwriting peer work.

## Evidence Rules

1. A successful process exit is insufficient when the runner selected zero tests or skipped the scenario.
2. “Working” requires observed runtime behavior with a real built binary or browser/native shell where applicable.
3. Language-agnostic fixtures must be exercised by Semio and at least one independent implementation for every new feature.
4. Expensive operations must expose progress and cancellation, including tests for both.
5. No broad workspace failure is assigned blindly while the tree is concurrently changing; failures are minimized to the owning package and exact contract.
6. Generated command output belongs under this ticket's `🗑️generated` directory while needed and is removed before ticket closure. Durable conclusions belong in Markdown reports.

## Work Phases

### P0 — Trust the Control Plane

- Repair the repo MCP entrypoint so `repo://goals`, ticket tools, resources, and lifecycle negotiation work through the configured `.mcp.json` command.
- Eliminate false-green test targets: a quick/fundamental target must execute a meaningful non-zero suite or fail clearly.
- Keep generated registry and `launch.json` checks authoritative and non-mutating in check mode.

Exit: native MCP resource/tool smoke passes through the configured command; the initial quick-gate matrix has no silent zero/skip success.

### P1 — Freeze the Live Contract

- Census launch targets, plugins, apps, artifacts, standards, subsets, codecs, mutations, inferences, viewers/editors, hub backends, admin routes, and AI tools from generated/live registries.
- Reconcile open predecessor tickets and distinguish completed code from unverified or regressed runtime behavior.
- Convert audit gaps into dependency-ordered, file-bounded implementation packets.

Exit: `📓️terra-os-frontend-audit.md`, `📓️terra-hub-ai-audit.md`, and an acceptance matrix name every required runtime slice and its current evidence.

### P2 — OS, Plugins, and Artifacts

- Boot the React shell and native shell from launch targets.
- Load the complete installed plugin catalog without hardcoded plugin or artifact identities.
- Make every declared app and artifact contribution openable; viewers/editors execute real mutations, inference, I/O, undo/redo, and history.
- Close all declared-but-unimplemented/stub contribution gaps or remove invalid declarations schema-first.
- Verify accessibility, EN/DE parity without a default language, keyboard operation, themes/customization, desktop-first layout, and bounded mobile/tablet behavior.

Exit: registry census equals runtime census; representative and exhaustive generated artifact tests pass; all launchable apps survive browser/native smoke without faults.

### P3 — Hub, Spaces, Presence, and Administration

- Persist append-only directory/document events and rebuild projections for every configured database backend.
- Complete user identity, membership, invitations, roles, share tokens, admin authority, connection management, and audit/event views.
- Prove two-user collaboration inside one space: create/open/edit/presence/checkpoint/reconnect/delete/share/admin-kick/restart.
- Prove short connection loss queues/replays safely and never freezes the shell.
- Bring React and native collaboration/history behavior to parity.

Exit: all collaboration scenario steps execute and pass against the real hub; SQLite/Postgres/Neo4j configured backends compile and their shared contract suite runs; admin SPA and API are runtime-verified in EN and DE.

### P4 — AI over the Map

- Bind each MCP transport connection to a distinct authenticated session and space authority.
- Discover map/GIS/artifact capabilities from the live catalog, never fixtures or hardcoded plugins.
- Inspect the active map context, run typed inferences/mutations, drive UI focus/reveal, and use history safely.
- Verify bare, headless, and attached progressive-enhancement tiers, including policy denial, progress, cancellation, reconnect, and multi-client isolation.

Exit: a real client performs an auditable map change through `semio-os-mcp`, observes it in the shell and a second collaborator, and can undo it without crossing session/space boundaries.

### P5 — Integrated Release Gate

- Run package-focused unit/contract tests, generated language-agnostic fixtures, third-party oracles, wasm builds, native builds, and full browser/native end-to-end scenarios.
- Re-run read-only Terra audits against the finished tree and resolve every high/medium in-scope finding.
- Remove temporary generated output, update this plan with final evidence, and close the repo ticket only after all outcomes above are observed.

Exit: no skipped/zero-test acceptance gate, no declared stub contribution, no unexplained build/test failure in an in-scope package, and all user journeys have current runtime evidence.

## Initial Baseline — 2026-09-03

- Repo MCP configured command fails the Codex handshake because it routes to the legacy CLI MCP server; a direct no-argument build of the owned repo MCP can initialize and read `repo://goals`. Sol implementation lane active.
- `os-hub-admin:test-quick` exits successfully with zero selected test files.
- `os-hub-ts:test-quick` exits successfully with its only test skipped.
- `@semio-tech/framework-os-dev:test-quick` executes two files/9 tests but fails to transform in-source `📜️script.ts`: Vite injects `/@vite/client` before the Bun shebang, producing a Rollup parse error.
- `@semio-tech/plugin-registry:check` is red with a repository-wide plugin taxonomy violation set: missing required artifact/surface facets and many Rust leaves not owned by the generated `#[path]` module graph. Active normalization/deduplication tickets are modifying the same tree, so the violations require post-settle attribution before implementation.
- The current artifact-opening relay is only partially closed: space rows now carry `documentId`/`spaceId`, and `ShellHost` renders the React presence roster, but plain `os.open-artifact` omits `pluginId`/`appId` while the shell requires both. The default-opening path therefore still cannot resolve a declared app from the dialect and opening preferences.
- Share tokens are keyed by document id rather than `(space, document)`, and currently map to author authority. This permits a token for a common document id such as `index` to cross private-space boundaries and write.
- Directory WebSocket filtering covers directory events only; connection/presence frames and global `user.created` data can disclose private activity or email addresses to unrelated subscribers.
- MCP principals/scopes and the shared `sess_default` are caller/process supplied rather than bound to an authenticated hub user and transport connection. Hub workspaces cannot enumerate/read cold artifacts, and `inference_get` remains `channel.not-wired`, so AI cannot execute inference against an existing shared GIS map.
- GIS map inference has a deterministic typed implementation and schema descriptors, but its artifact declaration registers no executable `ArtifactInferenceService`; the executable-service roster is therefore empty even before MCP routing is considered. The AI path must first expose a bounded map inference service, then route it through the headless workspace.
- The default hub and MCP acceptance targets skip their real scenarios; the existing hub TypeScript E2E also asserts surface-isolated presence while the Rust hub intentionally implements document-wide presence.
- Both native and browser hub sync actors currently accept but ignore `Bootstrap::Snapshot`, `SnapshotChunk`, and `SnapshotDone`; only tail commands are applied. Cold or compacted documents therefore need an explicit snapshot-bootstrap repair before reconnect and MCP cold-read claims can be trusted.
- The snapshot audit proved the existing bootstrap bytes are database-internal `.spk` pages, not the canonical OS artifact `(pack, spr)` pair, and normal plugin operations are not semantically materialized into those DB pages. Clients must not decode `.spk`; the public contract needs a distinct descriptor-bound artifact bootstrap.
- Directory discovery currently exposes only document bookkeeping (`id`, head/commit/epoch). Artifact schema/owner/package identity, immutable pack-schema hash, bootstrap version, and snapshot identity are absent, while hub schema pinning lives only in volatile `schema_hashes`. A durable authorized `DocumentDescriptor` event/projection is therefore the first cold-path boundary.
- Hub snapshot publication and retention are dormant: the public `ArtifactHandle::snapshot_now` is unimplemented, the hub does not advance a retained floor, and lagged live broadcasts are silently discarded. Canonical artifact authority, retention, and lag-triggered rebootstrap must precede any claim of correct cold recovery.
- The shared tree contains extensive concurrent work across root manifests, taxonomy, framework crates, and plugin/artifact files. Integration decisions must be based on focused current-tree probes.
