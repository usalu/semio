# Map Durable Owned-Group Decision Codec

Status: the strict fixed parent+drawing+value codec fence, Store-owned prepared/bound/recovery aggregate, retained shared-root publication coordinator, and kernel-local retained-owner primitive are implemented. The neutral source/AJV/SHA/lifecycle oracle and all twelve registered exact native laws are green. The mounted law uses demo Stores and the fake journal sink; no real Map host slot or WAL implementation has qualified the lifecycle, so this is Store-contract evidence rather than end-to-end durable Map acceptance.

## Scope

- `DurableOwnedThreeMemberDecisionV1` is a real `DslArtifact` with a handcrafted `ArtifactDsl`/`ArtifactPack` codec. The WAL-facing body is the canonical binary pack, never raw JSON.
- The accepted record has exactly the parent, drawing, and value fields. It fixes their roles, Map/stdIO references, child owners, recovery schema ids, base and post frontiers, exact recovery-pack hashes, and unbound outcome commitments.
- `decision_sha256` covers only the acyclic unsigned projection: schema, anchor, fixed members, owners, expected base frontiers, recovery schema, and unbound outcome hashes. Bound recovery packs and hashes, post frontiers, final edit/prefix derivations, and private seals are excluded.
- The crate-private codec fence rejects noncanonical JSON and packs, forged ownership/identity, mismatched commitments, non-lowercase hashes, one-over member packs, and one-over Event bodies. Its Pack opener fixes stored, segment, raw aggregate, and total-allocation ceilings to 491,520 bytes, requires one document frame and no chunks, then applies the exact 162,000-byte/member and 4,096-byte structural ceilings.
- The decision fields and `admit_map` are not a caller API. There is no production `seal` constructor: callers cannot supply member hashes, frontiers, or recovery bytes and promote them into authority. The test-only fixture sealer replaces its explicitly hostile ASCII caller bytes with real typed bound packs before validation.
- `ArtifactStoreOneItemPrepared` now has a Store-private producer for an opaque `DurableStorePreparedOutcomeV1`. The producer requires an ungrouped authority, validates the private prepared seal, and canonically captures operation/base/applied-count, next sequence/HLC, actor, the complete group-free edit, and the exact post-snapshot pack. It derives the commitment from those owned bytes; callers cannot supply the hash used by `seal`.
- The inverse verifier checks the exact SHA-256 and a bounded one-frame/no-chunk canonical Pack, canonical-parses the HLC and edit from fidelity-preserving typed JSON bytes, decodes and re-encodes the post snapshot, reconstructs the ungrouped authority, and rechecks semantic edit authority. Immediate producer verification also proves equality with the original prepared authority, edit, and snapshot before the result can enter the decision preimage.
- `DurableOwnedThreeStorePreparedV1` consumes exactly three private prepared owners. `bind_store_owned` derives every member reference, owner, base frontier, and unbound commitment from those owners and the three live Stores; enforces parent/drawing/value order and distinct identities; derives the acyclic decision id; performs the sole `None -> decision_sha256` edit binding; recomputes edit digests and post revisions from each Store accumulator; and returns opaque bound prepared owners plus typed canonical recovery packs.
- `recover_store_owned` accepts only all-three exact base or all-three exact post frontiers. Base recovery reconstructs the three private Store seals only after decision, bound-pack, unbound-pack, identity, owner, edit-digest, snapshot, and post-revision verification. Post recovery verifies the exact current snapshot and tail edit. Mixed or foreign frontiers fail closed.
- Canonical JSON carriers are byte-bounded before parsing, depth/item bounded, re-encoded byte-identically, and all authority identities reject controls and overlong strings. Store snapshot packs and both outcome pack types use explicit full-verification allocation limits.
- HLC/edit values are embedded as canonical JSON byte fields rather than generic `Shape::Value`: the generic Pack value path sorts object keys and widens number tags to `f64`, so it cannot preserve the exact field order or signed/integer/float distinction required by this authority boundary. Native hostile cases reject reordered fields and a changed numeric tag.
- `begin_retained_commit` consumes the three bound Store owners into one bounded coordinator. It stages parent, drawing, and value beneath one `ArtifactGroupVisibility`, starts a journal operation with the exact canonical decision Pack and hash, and keeps every candidate and displaced Store root retained until the journal reports either trusted absence or a matching committed receipt. Sink construction is deliberately infallible and non-I/O; its first `advance` owns every fallible or externally visible action, so construction failure cannot be mistaken for proof that no journal write began.
- Pending and ambiguous journal results leave all ordinary readers on the old roots. A matching committed receipt flips the single shared visibility decision before bounded lease publication and physical root adoption, so the cross-Store capture sees either all-old or all-new. It rejects missing or foreign staged roots and structurally false adopted roots after the committed flip, and keeps all three adopted association roots until they can be cleared together in one synchronous turn. Typed and erased Store snapshot leases publish the selected staged generation/revision before issuance. Ordinary Store mutation entry points reject while a group root is staged. Acknowledgement is mandatory before a one-shot journal close; terminal cleanup relinquishes the receipt, decision hash, and final visibility view as well as all candidate/journal owners.
- Cancellation before journal commitment aborts the shared decision and retires the three staged roots. Cancellation after `begin_commit` is forwarded to the owned journal operation and cannot restore the old roots until that operation reports explicit `Absent`; an error is treated as uncertain and retried on the same journal owner rather than interpreted as absence. Starting the sink is blocked without moving the decision bytes unless the turn's byte grant covers their exact encoded length.
- `DurableOwnedMapCommitOperationV1` closes the request-lifetime ownership gap after binding and before the first staging turn. It owns all three live Stores, the coordinator, and the `Send` journal sink behind non-dropping shells; advances and coherent reads borrow only this mounted aggregate. Both the inner coordinator and outer operation reject premature Drop. The only release is `take_terminal_owners`, which succeeds once, after coordinator terminal emptiness, and returns all three live Stores plus the exact sink to the Map runtime. A request-visible uncertain error therefore cannot strand staged roots or discard the writer owner.

## Remaining proof

The kernel-local operation primitive mounts the coordinator, all three demo Store owners, and the fake sink before any staging turn, and its law proves that primitive retains an uncertain error until terminal handoff. The remaining integration boundary is a real fixed Map host slot that parks the operation before its first advance and drives cancellation, panic, error, acknowledgement, and close to terminal, plus the typed GIS preparation/router entry point and a storage-owned WAL sink with exclusive lifetime writer authority, append/sync receipt verification, and reopen recovery. Until those exist, nonterminal Drop remains a deliberate fail-stop with non-dropping owner shells, not a production cancellation path.
