# Retained Short Administrator HTTP Effects

## Contract

An accepted short administrator intent is owned by the Hub process rather than by the HTTP request future. The accepted audit fixes request id, canonical intent digest, operation id, principal session/generation, correlation, and target metadata. One bounded process-owned task retains the exact principal gates through the actual side effect, retries the terminal audit after the effect outcome is known, and only then offers a response to the original request. Dropping that request must not cancel the retained task.

Concurrent and later retries join the accepted/terminal audit identity and never execute the effect again. Each durable short effect commits a private `(operation_id, intent_digest)` effect receipt in the same backend transaction as the mutation. A missing receipt leaves an accepted operation uncertain; an exact receipt permits the Hub to append the factual succeeded terminal after restart. Invite/share secrets remain one-shot: only the original live response may receive the transient result after terminal persistence; effect receipts, audit/status projections, and retries never retain or replay a token.

An elapsed outer operation deadline or an ambiguous backend acknowledgement after effect admission is not a failed effect. The handler returns unavailable while retaining the accepted fact; only the exact same-transaction receipt may later establish success. Reconciliation also checks that the receipt outcome matches the accepted intent kind and reapplies the share/user binding and open-plan invalidation before persisting a revoke terminal, so a crash cannot publish success while leaving the revoked browser authority live.

Every short and long administrator operation consumes the existing bounded permit. Explicit cancellation and effect admission linearize through one atomic `PreEffect | EffectAdmitted | Cancelled` state: a winning cancellation prevents the effect, while cancellation after admission cannot claim rollback. Process shutdown rejects new work, requests cancellation for cancellable work, and drains retained tasks to the common bounded deadline before aborting any remainder without inventing a terminal result.

## Acceptance

The neutral state-machine corpus covers live and dropped share/invite requests, running/terminal duplicates, cancellation on both sides of effect admission, terminal-storage failure with and without an exact effect receipt, commit-before-acknowledgement-timeout reconciliation, restart with stale acceptance, a mismatched receipt digest, idempotent receipt retry, request digest collision, bounded capacity, and one-shot result delivery. An independent Bun SQLite model must produce the same states/counts. Production hostiles additionally reject a split cancellation check/store, public secret construction before terminal persistence, single-attempt terminal storage, removal of zeroizing public result ownership, a receipt outside the writer, receipt-free reconciliation, omitted intent digest, secret replay, and recording an ambiguous acknowledgement as failed.

## Three-way writer outcome and admitted lifetime

The Directory writer boundary now returns the closed `AdminEffectCommitV1<T>` sum: `Applied(T)`, `RejectedBeforeCommit`, or `Indeterminate`. All seven logical durable effect paths use it across SQLite, PostgreSQL, and Neo4j: directory event append (including create-space), share issue/revoke, session revoke, and invite issue/revoke. Only a successfully awaited transaction rollback maps to `RejectedBeforeCommit`; begin, lock, backend preflight, commit acknowledgement, and rollback failure remain `Indeterminate`. The same transaction owns both the mutation and exact `(operation_id, intent_digest, outcome, event range)` receipt. PostgreSQL and Neo4j remain source/query evidence rather than live backend qualification.

The retained task no longer wraps `execute_admin_intent` in a request deadline. It acquires the sorted principal/session/space/share/member authority guards, wins the atomic effect-admission transition, and then retains those guards plus the shared capacity permit through backend resolution and factual terminal append. Only the HTTP one-shot waiter has a bounded deadline. A timed-out or dropped HTTP request therefore cannot release an admitted mutation fence or cancel the writer; process shutdown remains the explicit bounded abort boundary.

Receipt-free ambiguity is not terminalized. The Accepted audit identity remains durable and eligible for later exact-receipt reconciliation. Once its in-process resolver is absent, request/status projection reports the distinct nonterminal `indeterminate` state and redacted `admin-effect-outcome-indeterminate` outcome. A later matching receipt still promotes the operation to the factual Succeeded terminal; a mismatched receipt remains invisible. Cancellation without a live resolver returns Conflict and never claims rollback.
