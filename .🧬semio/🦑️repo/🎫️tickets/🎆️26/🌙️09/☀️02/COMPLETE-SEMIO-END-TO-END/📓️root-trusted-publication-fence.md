## Platform Publication References

The pinned directory handle must remain the authority during replacement. Unix `renameat` resolves relative names against supplied directory descriptors ([Linux manual](https://man7.org/linux/man-pages/man2/rename.2.html)). Windows `FILE_RENAME_INFO.RootDirectory` can select the retained directory for a relative name ([Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info)). Windows exclusive locking can refuse immediately and is released by the OS when the handle/process closes ([Microsoft LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex)). These sources justify the implementation direction, not a completed cross-platform runtime claim. A pathname-only rename, stale-PID lock recovery, or precomparison outside the lock is not sufficient.
