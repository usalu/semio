# WAL Retained Decoder and Transaction Gate — Current Audit

Audit date: 2026-09-05. Read-only review of the current source; no build or runtime was run.

## Result

`WalRetainedRecordDecoder` is materially safer than the replaced one-shot retained decoder: an opaque or inline body keeps its `DbIoPageWriter`, source position, and frame boundary until a successful seal; an index checkpoint likewise keeps its list and advances its source cursor only after a successful `push`. `WalReplayCursor` keeps that decoder over ordinary `fuel`, cancellation, and deadline interruptions, and its close path deliberately does not consume a cancellation grant.

The raw `WalReplayCursor` still returns each `WalRecord` (`🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:1540-1714`), but the new `WalCommittedCursor` now owns a `WalTransactionGate` and yields a transaction borrow only after its matching logical commit (`:1717-1874`). It is the admission path that prevents committed-cursor body decoding before `TxCommit`; raw consumers remain outside that guarantee.

Two bounded correctness changes are required before that attachment: make transaction ids contiguous after the first retained suffix transaction, and make the gate depend on a segment that has already passed exact header/chain validation.

`WalPageReader` scalar decoding is allocation-bounded: text has a fixed 1,024-byte `DbIoText` authority (`db/🗄️storage/🦀️.rs:1765-1795`) and scalars reject a non-exact payload tail (`wal:1124-1153`). These are the right exactness checks; keep them in the retained path rather than relying on the test-only vector decoder, which does not perform the retained scalar trailing check (`:730-787`).

## Gate findings that block committed replay

1. **P0 resolved for the new committed cursor, not for raw consumers.** `WalCommittedCursor::prepare_transaction_step` validates every segment through `WalSegmentChain` before it sends frames to the gate (`wal:1752-1776`); it advances the raw source only after `push`, and `WalCommittedTransaction::decode_record_step` decodes only copied body spans after `ready` (`:1822-1845`). `TxAbort` clears spans in the gate without a body decoder. The returned transaction borrows the cursor, so it pins the source segment until every body is closed and `finish` releases the gate (`:1731-1735,1849-1869`). This is sound for this API; do not extend the claim to `WalReplayCursor` or its callers.

2. **P1 — later transaction-id gaps are accepted.** At `wal:1353-1357`, `tx_id < next_tx_id` rejects reuse but accepts `1, 9, 20`. The sole production writer assigns exactly `next_tx_id` on every submit (`wal:2185-2193`), so a verified-but-forged record sequence can jump ids and change reopen/recovery semantics. Compaction can legitimately make the *first observed* transaction an unknown higher id; it does not justify later gaps. Make `next_tx_id: Option<u64>`: accept any nonzero first retained id, then require `tx_id == expected` for every following begin and set `expected = checked_add(1)`. The same gate instance must span all retained segments.

3. **P1 — header acceptance is only safe after chain admission.** `push` accepts `WAL_SEGMENT_HEADER` based solely on kind/order (`wal:1343-1350`); it does not parse document, index, predecessor tag, or trailing bytes. `WalSegmentChain::check_segment_header` supplies those exact checks (`:1449-1467`), including the document/index/predecessor chain. Do not expose a raw-pages gate API. Construct the gate only after the per-segment chain validator completed successfully (or pass a private validated-segment token), otherwise a caller could make the gate's `header_seen` true with a forged header.

4. **P2 — the terminal policy must be explicit.** `finish_segment` permits an open transaction only on `writable_highest` (`wal:1386-1395`). In the normal `ArtifactWal::submit` path, a physical commit cannot contain only a prefix of its logical transaction because it appends Begin/body/Commit before `commit_and_flush` (`:2189-2200`); recovery also cuts the active tail to its last physical commit. The committed cursor should therefore see no pending transaction in the trusted active prefix. Treat one as corrupt unless its input is explicitly an unrecovered physical tail; do not turn it into an implicit abort just because the segment is highest. The opener, not replay, owns torn-tail removal.

5. **P2 — frames are a bounded grammar buffer, not retained bodies.** The 64 frame slots match `WalRecordBatch`'s exact maximum (`wal:447-474`), so the gate does not create an unbounded owner. Preserve that fixed array and keep every retained `WalBytes` allocation after commit. This also gives an observable hostile property: an aborted 496-KiB event consumes no second retained copy.

## Minimal native-law matrix

Place these as module-private native laws next to the retained cursor tests in `db/📝️wal/🦀️.rs`; add the grammar rows to the existing neutral WAL fixture only once the committed cursor consumes it.

1. **`retained_command_fuel_resume_keeps_frame_start_and_bytes`** — command spanning two DB pages; exhaust fuel after writer reservation and after one fragment, replenish, and assert exactly one returned record with byte-identical payload and a post-record offset. Close record/cursor and prove terminal emptiness.
2. **`retained_decoder_cancel_after_writer_admission_closes_without_replenish`** — cancel after the first retained page copy; `next_step` returns the control error, cancellation stays set, repeated `close_step` reaches terminal empty, and a fresh replay starts at the same source frame.
3. **`retained_decoder_reserve_write_seal_rejection_has_one_owner`** — deterministic page-writer reserve, fragment-write, and seal fault hooks. Each error returns no record, retires the held writer exactly once through cursor close, and restores the page budget. Do not simulate this by dropping the cursor.
4. **`retained_index_list_allocation_or_fuel_failure_retries_no_value`** — index count two; interrupt before a push and reject the backing allocation in a test hook. Replenishment only repeats the former; successful continuation yields `[first, second]` once. On allocation rejection, close retires the list and no record is released.
5. **`retained_scalar_and_inline_payload_are_exact`** — for every scalar kind append one byte; for inline payload test truncated varint, declared length short/long, invalid tag, and a CAS reference with a trailing byte. Every row is corrupt before a record is returned.
6. **`committed_gate_rejects_gaps_and_malformed_grammar`** — verified header, then body-outside-transaction, nested begin, mismatched terminal id, bad count, duplicate header, `1 -> 3` begin gap, and a zero-copy abort. Assert no body frame becomes decodable/releasable. Include a compacted-suffix first begin at `42`, followed by required `43`, to prove the intentional initial exception.

## Nonclaims

This audit does not claim a committed replay cursor, transaction-atomic consumer migration, or runtime verification. It does not alter the WAL opener/tail recovery work. The findings apply to the current private retained decoder and gate only.

`WalCommittedCursor` is an effective retained admission boundary, not just a grammar helper:

- It finishes `WalSegmentChain` before it reads a logical frame, advances `raw.offset` only after `gate.push` accepts the frame, and emits `Transaction` only when the matching commit made `ready` ([`wal:1752-1788`](</Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:1752>)).
- A transaction owns an exclusive mutable borrow of its cursor. Its decoded `WalRecord`, decoder and source pages therefore cannot be retired, swapped to another segment, or observed by a later transaction before every body has been closed and `finish` releases the gate ([`wal:1820-1874`](</Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:1820>)). `TxAbort` clears only frame spans, so it cannot release retained body bytes.

That correctly prohibits an implicit skip; `close_owner_step` subsequently drains a partly decoded record/decoder and pages without requiring a control grant ([`wal:1792-1801,1866-1874`](</Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:1792>)).

### Remaining narrow findings

1. **P1 — one-unit fuel can make the public cursor permanently non-progressing.** `prepare_transaction_step` grants before it calls `raw.open_segment` or `wal_next_page_frame`; each of those grants again, and `WalSegmentChain::step` grants a third time ([`wal:1752-1776,1272-1307,1569-1602`](</Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:1752>)). Thus `replenish(deadline, 1)` makes the initial call consume its sole grant before `open_segment`; repeating the documented replenishment never opens the segment. This contradicts `replenish`'s “one bounded ... opportunity” doc ([`wal:1558-1560`](</Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:1558>)). Pick one grant owner per externally visible cursor step: remove the outer preparatory grant and let the selected operation charge itself, or make internal helpers take an already-granted token. Add a native law with repeated `replenish(..., 1)` from unopened cursor through one committed empty transaction and terminal close; each non-error call must either advance an observable cursor state/offset or return the transaction/done.

2. **P1 — a long run of physical commits has no fairness yield.** `wal_next_page_frame` loops over every `REC_COMMIT`, charges fuel, and returns no distinguished “physical boundary consumed” result ([`wal:1272-1307`](</Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:1272>)). With the callers' normal million-unit fuel, a legal 496-KiB segment full of minimal physical commits may monopolize one `next_transaction_step` until the next logical frame/end. Persist a `pending_frame`/physical-boundary state or return a third frame result and expose `WalCommittedStep::Yield` after one skipped physical commit. The law needs many physical commits between header/body/terminal and must prove one external yield or bounded offset advance per call even with ample fuel.

3. **P1 — poison/close coverage does not exercise a live retained record.** `wal_committed_cursor_unfinished_borrow_poison_and_cancelled_close` drops after `WalCommittedRecordStep::Yield`, before the transaction owns a decoded `WalRecord` ([`wal:2708-2730`](</Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:2708>)). Add the same law after `Record(WalRecord::Command(_))`, without `close_record_step`: next transaction call must stay corrupt; repeated cancelled `close_owner_step` must retire record, decoder, pages and segment list to `terminal_is_empty()`. This is the exact branch that protects the retained `DbIoPages` lifetime under a caller mistake.

4. **P2 — fixture semantics intentionally differ for active incomplete transactions but do not state the layer.** Its direct gate oracle accepts `active-*-needs-durable-abort` and reports `recoverAbort`; its live cursor loop purposely skips every such row (`failure.is_none() && recovery_abort.is_none()`, [`wal:2588-2619`](</Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:2588>)), while current cursor calls `finish_segment(false)` and rejects the trusted prefix. That is aligned with opener-owned recovery, but the fixture calls it `accepted`. Give it an explicit expected consumer policy such as `cursor: "reject-until-opener-aborts"`, then add a cursor law that proves no body decoder runs and close is terminal on that row. It prevents a future broadening from silently turning the replay cursor into a recovery authority.
