# Browser Per-Activation WASI Foundation

## Implemented Boundary

`🌐️browser-bundle/🌐️wasi/🟦️.ts` is first-party runtime code with no external imports. It constructs fresh resource classes, ownership records, timers, waiters and exact Preview2 import objects for each activation. The admitted profile has14 literal `@0.2.0` WASI interfaces: CLI environment/exit/stdio/terminal types/getters, monotonic clock, IO errors/poll/streams. Environment and arguments are empty, cwd/terminals absent, stdin closed. It grants no filesystem, socket, HTTP or random capability.

Resource admission is capped at256, with128 poll items and pending waits. Clocks validate exact unsigned64-bit input and nondecreasing time. Long waits are segmented within browser timer limits; close cancels timers, rejects waiters, force-retires resources and is idempotent. Stdio wrappers are fresh on every getter. Writes require a permit, copy at most64KiB and share a1MiB lifetime output budget. The first-party binary sink contract requires synchronous consumption/copy before return; staging bytes are zeroed afterward. Every admitted output reserves an error-resource credit, so a failing sink still produces the declared WASI stream error at full capacity.

The closed actor builder now privately combines the selected WASI imports with its existing Semio host imports. WASI actors require an explicit `port.wasi` clock/binary-output capability; pure actors do not. Initialization failure and close drain both host owners and all admitted invocations; WASI exit closes its actor. No raw imported resource graph is exposed through the actor interface.

The build-time AST gate checks every used blocking WASI trampoline's actual `fnName`, `manuallyAsync=true` and matching `WebAssembly.Suspending` import binding. This is a trusted-JCO shape check, not arbitrary-JavaScript sandboxing. Runtime refuses missing JSPI support before compiling cores. A production descriptor/plan still needs to bind the JCO version and exact generation policy with the closed artifact bytes; no such production attestation is claimed here.
