## 1. Exact seam: app action → host effect → transport, with **zero** artifact persistence

### 1a. The precise, already-existing precedent to copy

The GIS 2D editor already has a "Shell-kind" action that proves this exact shape works today, with a test that locks in the no-mutation guarantee:

- `✏️s/🔌️plugins/🌍️gis/🗿️artifacts/🗺️gismap/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🎮️commands/🌐️shell/🦀️.rs` — `open_source::handle` (line ~20) returns `Ok(Emit::effect(Effect::OpenExternalUrl { url }))`, never a `GisMapMutation`.
- Its own test `open_source_is_a_shell_action_that_emits_no_operations` (same file, ~line 44) asserts `action.kind` is `ActionKind::Shell` (`🧰️framework/🔨️modules/🛂️manifest/🦀️.rs:86`, the `Shell` variant docstring: *"Shell-only effect (navigate, export, spawn) — recorded in the session command log... no document mutation"*) **and** that dispatching it through the real action registry (`app_with_registry`, kind-discipline enabled) yields zero mutations.
- This command is registered in the closed, macro-generated `Gis2dCommand` enum (`✏️s/🔌️plugins/🌍️gis/🗿️artifacts/🗺️gismap/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🦀️.rs:223-236`, `"openSource" as "open-source" => open_source::OpenSource`) and declared in `create_gis2d_app()` (same file, line ~909): `.action_with(ActionDefinition { category: Some("open".into()), ..ActionDefinition::bounded_catalog("openSource", ..., ActionKind::Shell) })`.

**The seam for "Propose bounds region" is the same shape**: a new `Gis2dCommand` row (e.g. `ProposeBoundsRegion`) in a new `🎮️commands/💡️inference/🦀️.rs` module, `ActionKind::Shell`, whose `handle()` returns `Emit::effect(Effect::<NewVariant>{ ... })` and **never** touches `GisMapMutation`. This is not a generic document command — it is dispatched through the same closed 14-row `Gis2dCommand::dispatch` (`✏️s/…/✏️editor/🦀️.rs:987`, `command.dispatch(doc, cfg)`) that the audit (`📓️terra-ai-map-live-journey-audit.md` §1) already treats as the authoritative closed set (currently 14 rows, asserted by `assert_eq!(ids.len(), 14, ...)` at line ~1137 in the same file's test module — this becomes 15 and the assertion must be updated in lock-step, not bypassed).

Exact wiring points, in order:
1. `🎠️kernel/🦀️.rs:359-667` (`pub enum Effect`) — add the new closed variant(s). **Do not** reuse the existing unconstructed `SpawnJob { job, kind, input, placement }` / `CancelJob { job }` variants (same file, in the "new variants" block, doc comment: "nothing constructs these yet"). Per the ticket `26/08/17/MICROKERNEL-POOLED-ACTOR-PLUGIN-RUNTIME`'s `📓️design-abi.md` §2, `spawn-job`/`cancel-job` are the *in-process, pooled-WASM-instance* job primitive that replaces `artifact-infer`/`artifact-mutation-plan` (well-known cold job kinds `semio.infer` etc., driven by `start-job`/`step-job` on a **local plugin instance**). The GIS Map inference job in the P0 packet is a **hub-authenticated HTTP job** (`POST /inference/gis-map/jobs`, not an in-process WASM computation) — a different transport and trust boundary entirely. Conflating the two would silently route a network-authenticated job through the plugin sandbox's local job runtime.
2. `✏️s/🔌️plugins/🌍️gis/🗿️artifacts/🗺️gismap/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🦀️.rs`: add the `Gis2dCommand` row (~223-236), `command_from_action` arm (~759-800), `create_gis2d_app()` `.action_with(...)`/`.action_interactive_job(...)` calls (~909-935), and the `every_command()`/count-assertion test updates (~1105-1137).
3. **Browser**: `🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🏛️ShellHost/🟦️.tsx`, `applyHostEffects` (starts line 3160) — add a new `if ("requestInferenceJob" in effect)` branch (mirroring the `"replayShellCommand" in effect` branch at line 3280, which already shows the exact pattern: resolve `identityRef.current`, get a worker/transport handle, `postMessage`/await, apply the response). ### 1b. Native transport precedent to mirror

`dispatch_directory_command` (same WGPU file, line ~4259) is the exact native analog of the browser's `replayShellCommand` → `directoryCommandFromAction` → `ensureBackboneWorker().postMessage(...)` funnel: it checks `self.identity.is_none()` (drop with a warning), falls back to `queue_pending_directory_command` when `self.directory_client` isn't attached yet (bounded FIFO, oldest-drop, `MAX_PENDING_DIRECTORY_COMMANDS = 64`), and otherwise calls `client.command(&self.directory_ctx(), &command).await` (`DirectoryClient::command`, `🧰️framework/🛍️products/💻️os/🔨️modules/📇️directory/🔌️client/🦀️.rs:847`). A GIS-map job submit/cancel/approval would need its own analogous `dispatch_inference_job_command`/queue, **not** reuse of the `DirectoryCommand` enum itself (that enum is for `os.directory.*` administrative commands over the *document socket*; the P0 packet's Slice B explicitly routes inference jobs through **authenticated HTTP, not the document socket**: `📓️terra-ai-map-proposal-approval-current-p0.md` Slice B: "Expose only authenticated HTTP endpoints (not the document socket)").

### 1c. Browser HTTP transport: the real seam is `browser-broker-fetch`, not the postMessage broker port

Two distinct authenticated-fetch primitives exist in `🧰️framework/🛍️products/💻️os/🧵️backbone-worker.ts`, and it matters which one is extended:

- **`browserBrokerFetch(...)`** (line ~347), a proof-ratcheted `fetch` wrapper already used directly, in-worker, by `requestDocumentSocketAuthority` (line ~517) to call `/_semio/hub${openPath}` and `/_semio/hub${grantPath}` (lines ~532, ~545). This is the trusted-context primitive — it runs inside the same worker that already holds the directory session, so a new `submitInferenceJob`/`pollInferenceEvents`/`cancelInferenceJob`/`approveInferenceProposal` function calling `browserBrokerFetch("/_semio/hub/inference/gis-map/jobs...", ...)` directly is the smallest, most consistent addition — parallel in shape to the existing open-plan/socket-grant calls.
- **`BrowserBrokerPortRequestV1`/`ResponseV1`** (`🧰️framework/🛍️products/💻️os/🟦️.ts:4057-4062`, handled in `attachLocalBrokerPort` at `🧵️backbone-worker.ts:392-424`) is a narrower, postMessage-mediated RPC currently hardcoded to exactly one operation (`"me"` → `GET /_semio/hub/auth/sessions/me`, line ~408). It exists for a *less-trusted* caller that cannot itself reach the worker directly. There is no evidence in the audit or the P0 packets that the inference port needs this weaker boundary — the action already flows through ShellHost (host-owned, per the packet's own framing), which already has direct worker access via `ensureBackboneWorker()`. **Recommendation: extend `BackboneWorkerRequest`/`BackboneWorkerResponse` (new `kind`s, exactly like `"directory-command"`/`"directory-command-result"` at `🟦️.ts:715`/`754`) and implement the four calls with `browserBrokerFetch` inside the worker — do not extend the postMessage broker.**
- Confirmed: **no** `inference`-named `BackboneWorkerRequest`/`Response` kind, worker case, or ShellHost effect branch exists anywhere today (`grep -rn "inference" 🧵️backbone-worker.ts 🟦️.ts ShellHost/🟦️.tsx` → zero hits outside comments already cited by the Terra audits). This RED is independently reconfirmed by this exploration, not merely inherited from the audit.

## 3. Closed DTOs needed (TS + Rust), mirroring the hub's job/cancel/approval bodies

The hub-side shapes are still only *specified*, not implemented (`📓️terra-ai-map-proposal-approval-current-p0.md` Slice B, owned by sibling lane `fable-ai-map-proposal`, whose own report did not exist at exploration time either — grep for it in the ticket folder found `📓️fable-ai-map-proposal.md` absent from the earlier `ls`, only its packet). The four routes as specified there:

```
POST /inference/gis-map/jobs                          — InferenceRequestV1 (closed client intent)
GET  /inference/gis-map/jobs/{id}/events?after=<cursor> — owner-private bounded progress page
POST /inference/gis-map/jobs/{id}/cancel
POST /inference/gis-map/jobs/{id}/approval             — InferenceApprovalRequestV1 { jobId, proposalHash }
```

DTOs the client port needs (TS `interface`/Rust `struct`, `ToValue`/`FromValue` + `serde` pair, same convention as `🖥️shell`'s `ShellCommand` — hand-written parity, not codegen, given the existing `NOT generated` convention documented at `🖥️shell/🟦️.ts:1-11`):

- **`GisMapInferenceJobRequestV1`** — `{ schema, version, documentId, spaceId, requestId (client idempotency key, distinct from server job id per the P0 packet's "scoped idempotency ... not globally unique client request_id"), frontierDigest (or equivalent base-snapshot identity so the server can reject a stale base) }`. The exact base/frontier identity field names should mirror whatever `DocumentOpenPlanV1`/`VerifiedGisMapProposalBindingV1` end up calling frontier — **not verified here**, since Slice A/B (owned by `fable-ai-map-proposal`) had not landed at exploration time.
- **`GisMapInferenceJobReceiptV1`** — `{ schema, version, jobId, acceptedAtMs }` — the P0 packet's lifecycle is `accepted → claimed(epoch) → running(progress*) → offered(proposalHash) → approval-prepared → applied(reconciled)` with terminals `cancelled | stale | failed`; a receipt is only the `accepted` ack.
- **`GisMapInferenceEventV1`** (one page item) — closed union over the lifecycle states above, each carrying only what's needed to render: `{ kind: "claimed", epoch } | { kind: "progress", cursor, completed, total } | { kind: "offered", proposalHash } | { kind: "applied" } | { kind: "cancelled" | "stale" | "failed", reason? }`. `cursor` is the pagination token for `events?after=`.
- **`GisMapInferenceCancelRequestV1`** — `{ schema, version, jobId }`.
- **`GisMapInferenceApprovalRequestV1`** — `{ schema, version, jobId, proposalHash }` (exact shape already fixed by the packet's own text, and already has a Rust-side echo at `🌎️hub/💡️inference/🧬️schema/✅️approval/🦀️.rs:7-24` per the audit — that file was **not re-read in this exploration** since it is outside this lane's assigned surface, but its existence/shape is corroborated by two independent Terra audits).
- **Proposal hash / progress cursor**: the deterministic local proposal fixture (`✏️s/🔌️plugins/🌍️gis/🧪️fixtures/💡️inference-control/🔣️.json`) shows the actual proposal shape the UI would eventually render a preview of: `proposal.CreateRegion.item` is `{ id: "inference-<32-hex>", data: { kind: "inference-bounds", ring: [[lon,lat] x5] } }`, and `proposalJobId` is a 32-hex-char id. The UI port's `proposalHash` field is **not** the same as `proposalJobId` — the P0 packet's approval DTO explicitly separates `jobId` from `proposalHash` (a canonicalized hash of the proposal bytes, computed server-side "on work success ... canonicalize and store its proposal hash server-side" — Slice C). **The client never computes this hash; it only echoes back the hash the server told it in the `offered` event.**
- **Rendered UI states**: the packet's exact list — `idle, submitting, running, offered, approving, applied, cancelled, stale, failed` — is a strict superset/relabeling of the server lifecycle (`accepted/claimed/running/offered/approval-prepared/applied/cancelled/stale/failed`); `idle` (nothing requested yet) and `submitting` (request sent, no receipt yet) are pure client-side states with no server counterpart, and `approving` corresponds to the server's `approval-prepared`. This mapping is not fixed anywhere in source yet — it is a **design decision this packet flags but does not resolve**, since Slice A-C (the server states) had not landed at exploration time.

## 4. Lease precondition check location, both shells (current + planned)

**Nothing exists to check against yet.** Per `📓️terra-browser-gis-wasm-execution-target-lease-p0.md` and `📓️terra-gis-execution-target-lease-blueprint.md`, `DocumentExecutionTargetLeaseFieldsV1`/`DocumentExecutionTargetLease` (the verified, immutable, non-serializable lease type) do not exist in source today — only the weak, forgeable precursor `InstalledDocumentExecutionTargetV1` does (`🧰️framework/🛍️products/💻️os/🟦️.ts:557`, package/artifact/dialect/surface only, no catalog generation/descriptor digest/grant/revalidation), consumed by `documentOpenPlanAuthority` (`🧵️backbone-worker.ts:486`, confirmed present at that function name in this exploration) which unconditionally rejects `plan.surface.rendererTarget !== "react"` (line ~508, confirmed: `grep` found this exact literal at line 508 in the current tree).

- **Current (weak) precondition location, browser**: `documentOpenPlanAuthority` (`🧵️backbone-worker.ts:486-516`), called from `requestDocumentSocketAuthority` (line 517) before any socket/asset exchange. Any Slice D gate written *today*, before the lease lands, could only check this same `installed: PersistenceBinding["installedTarget"]` plumbing — which the Terra packets explicitly say is not a real security boundary. **Do not ship a "lease check" against this weak type and call it done** — it would be forgeable exactly as the blueprint describes.
- **Planned (verified) precondition location, browser**: per the blueprint's own P0 slice list, step 5: "Only after both bytes verify, construct the private lease. Then permit `rendererTarget: 'wasm'` through the plan comparison **only if this lease is supplied**." This gate lives in the same `documentOpenPlanAuthority`/`requestDocumentSocketAuthority` funnel, i.e., **before** a GIS Map document (viewer or editor) is even opened — meaning by the time ShellHost.tsx's `applyHostEffects` could dispatch an inference-job effect, the lease (if the document opened wasm-rendered at all) is already a precondition of the document being open. The **Slice D-specific** check is therefore likely redundant with document-open-time gating **unless** a GIS Map document can be open in a non-wasm/renderer-unavailable state (which the blueprint explicitly plans for: "Route the verified GIS Map target to an explicit localized `renderer-unavailable` state"). In that renderer-unavailable state, the document is open (lease verified) but not rendered — Slice D's UI (the inference port) plausibly must render *inside* that `renderer-unavailable` surface, not inside a WGPU/canvas view. This is a real design question the sibling lane's report should settle; flagging it here rather than guessing.
- **Native**: `dispatch_directory_command` (`🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:4259`) checks `self.identity.is_none()` today (no lease check at all — native has no execution-target-lease concept yet per the blueprint's own "Native Implementation Packet" section, which is still speculative/unimplemented). The planned native lease lives in `ArtifactActor` per the blueprint ("Store the lease in `ArtifactActor`, not only `hub_surface`/`document_socket_surface`"), so the native precondition location would be wherever the WGPU shell's session/document-open path constructs its `ArtifactActor`, gating before `dispatch_directory_command`-equivalent job dispatch — **not yet a concrete line number since `ArtifactActor` lease storage doesn't exist.**

## 5. Test packet

1. **ShellHost unit tests** (`🐚️Shell/🟦️.tsx` reducer + `ShellHost/🟦️.tsx` effect application), all with a **fake, already-authenticated** transport (per the packet's own framing, this port assumes auth is handled upstream — do not build a real hub client in this test tier):
   - State-transition law: every legal `idle→submitting→running→offered→approving→applied` path and every terminal (`cancelled`, `stale`, `failed`) reachable from every non-terminal state per the packet's law text; illegal transitions (e.g. `approving` reached without a prior `offered` event, or an event for an unknown `jobId`) are rejected/ignored, not silently accepted.
   - Cancellation: a Cancel click while `running` sends exactly one cancel request, transitions to a `cancelling`-flavored intermediate or directly to `cancelled` only on server ack (never optimistically before ack, since the packet's law is "the second user receives exactly one ordinary committed document event only after the typed group transaction is committed" — client-side optimism here would be a lie the server could still reject).
   - No state before receipt: dispatching the action with no network response yet renders `submitting`, never a client-fabricated `running`/`offered`.
   - EN/DE: every rendered string for every one of the 9 states exists in both `en` and `de`, keyed by an explicit locale prop with no fallback default (mirroring the `host-bootstrap` `COPY` object's shape exactly, including its "no default — caller must supply `locale`" property, since `resolveLabelsForLocale`'s implicit-English-fallback pattern is explicitly the wrong one per §2 above).
   - Accessibility: progress renders `role="status" aria-live="polite"` with a real `<progress>` (value/max, not a bespoke bar), terminal/error states render `role="alert" aria-live="assertive"`, Cancel/Approve are real `<button>` elements reachable by keyboard (Tab order, Enter/Space activation — no click-only handlers), matching `BootstrapStatusNotice`'s existing shape exactly.
2. **WGPU native turn-driver law**: mirror `ShellDirectoryRunner`'s existing shape (`🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:1301-1432`) — bounded turns (`MAX_MESSAGES_PER_TURN`, `MAX_TURN_MS`), `Lane::Io` submission for the network leg, cooperative rescheduling (`schedule()`/`run_turn()`), a `cancel()` that's a hard terminal, and `drain()` returning ordered messages. A new `ShellInferenceJobRunner` (or equivalent) would need the same discipline: no blocking async in the render loop, bounded event queue, timer-armed reconnect/poll rather than a busy loop. This is a genuinely new component (no existing "job" runner in the WGPU file to extend — only the directory-stream one), so its test is a from-scratch native unit test, not a modification of an existing one.
3. **Two-user process law**: out of scope for this port alone — it depends on Slices A-C (server) and the execution-target lease landing first. The packet's own "Required test packet" item 5 (in `terra-ai-map-proposal-approval-current-p0.md`) and item 6 (browser/native UI laws "only after the execution lease P0") already say this explicitly; this exploration found nothing to add or contradict.
