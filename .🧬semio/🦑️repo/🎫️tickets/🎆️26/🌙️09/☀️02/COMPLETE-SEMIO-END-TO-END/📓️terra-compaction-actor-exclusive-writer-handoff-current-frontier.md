# Compaction’s Actor-Owned WAL Writer Frontier

Status: read-only source audit on 2026-09-05. No build or runtime execution was started.

## Current blocking topology

`ArtifactWal` now acquires exactly one `WalWriterPermit` at construction/open and retains it until its resumable close. The permit is stored at [`db/📝️wal/🦀️.rs:2300`](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:2300); `open_with_control` acquires it before `open_acquired` at [2340–2346](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:2340), and normal submit, flush, rotate and close use/release that exact owner at [2468–2555](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/📝️wal/🦀️.rs:2468).

An open document therefore already holds its document’s exclusive writer continuously inside `ArtifactEngine` ([`db/🗿️artifact/🦀️.rs:1158–1168`](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/🗿️artifact/🦀️.rs:1158)). `ArtifactRunner` removes the whole engine from its idle slot for a turn and only restores it when that turn is terminal ([`db/🗿️artifact/🦀️.rs:3734–3897`](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/🗿️artifact/🦀️.rs:3734)). Its current messages have no compaction/maintenance turn ([3499–3557](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/🗿️artifact/🦀️.rs:3499)).

In contrast, `Database::compact_document_retained` directly mounts `DatabaseCompactionFuture` over only `pool + storage + document + holder` ([`db/⚙️engine/🦀️.rs:7428–7444`](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/⚙️engine/🦀️.rs:7428)); it neither obtains the open actor from `open_artifacts` nor has its already-held writer. The retained worker computes a snapshot floor, then acquires only the compaction lease, then scans/deletes WAL segments ([`db/🗜️compact/🦀️.rs:1218–1252`](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/🗜️compact/🦀️.rs:1218), [1565–1609](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/🗜️compact/🦀️.rs:1565)). The old test-only `Compactor::run` has the identical direct-storage shape ([708–745](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/🗜️compact/🦀️.rs:708)).

This is not merely a migration signature change: `WalStorage` requires the exact permit for every mutable segment operation—including `delete_segment`—and describes acquisition as preceding inventory, recovery, and mutation ([`db/🗄️storage/🦀️.rs:4659–4702`](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/🗄️storage/🦀️.rs:4659)). Acquiring a second permit in compaction will deterministically conflict against the active actor in the ordinary case; omitting it makes current deletion stale/unauthorized.

## Smallest coherent production correction

Run the whole durable compaction pass as a new **`ArtifactMessage::Compact` actor turn**, not as a storage-only job that tries to reacquire its own document writer.

1. Add a crate-private `ArtifactEngine::compact_retained(&mut self, holder, consolidate, budget, now_ms, cancelled)` that calls a refactored `db_compact::retained_compaction_with_wal(storage, &mut self.wal, ...)`. `db_compact` receives `&mut db_wal::ArtifactWal`, never `WalWriterPermit`.
2. Keep the permit sealed inside `ArtifactWal`. Add only the narrow crate-private capabilities needed by compaction: `document()`, `active_segment_index()`, and `delete_compacted_sealed_segment(storage, index)`. The delete method must require the same document, reject the current active index, query `segment_state` and accept only `Sealed`, then call `WalStorage::delete_segment(self.writer.as_ref()?, index)`. It must not expose a cloneable/general writer or arbitrary append/seal API.
3. Add `ArtifactMessage::Compact { holder, consolidate_snapshots, budget, now_ms, cancelled, reply }`; dispatch it in the existing `ArtifactTurn::Future` path. Use `Priority::Command`, matching durable `Submit`, so an already queued submit stays ahead and later submits stay queued while the maintenance future owns the engine. Do not use `Recovery` merely to jump its queue.
4. Change the `Database` façade to first `document(id).await` (opening/reusing the actor), then ask that authority for its retained compaction operation. The existing synchronous `compact_document_retained` cannot safely manufacture the actor-held capability; replace it with an actor-backed retained operation rather than retaining the storage-only API. The CLI remains routed through `Database::compact_document` ([`db/⌨️cli/🦀️.rs:1091`](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/⌨️cli/🦀️.rs:1091)).
5. In the actor-owned compaction routine, acquire `CompactionLease` **before** loading the snapshot floor, WAL segment inventory/horizons, payload trace, or deletion selection. Keep both the lease and the actor-owned writer for the entire pass. The current floor-before-lease sequence can select from a stale snapshot generation; the current highest-horizon heuristic can race a rotation. The authoritative active index comes from the held `ArtifactWal`, not “highest observed index.”
6. On success, cancellation, fault, or panic, finish/close all retained scan owners and release the compaction lease before resolving the reply; then return the unchanged engine (including its original `ArtifactWal` and permit) to `ArtifactRunner`. Its normal turn completion already restores the engine and resumes queued messages. Do not release the writer between scan and delete, and do not leave an engine with `wal: None` in its idle slot.

This is smaller and safer than a cross-module pause/handoff object: no self-conflicting second acquisition, no borrowed `ArtifactWal` escaping into a `'static` compaction future, and no dependency on a separate return channel. The actor already provides the required `Send + 'static` ownership transition for an async turn. A reusable low-level compactor can separately be defined for a *closed* document as `acquire_writer → ArtifactWal::open_acquired → run with that owned WAL → close`; it must not be the `Database` live-document path.

## Required terminal and race laws

1. **Live actor succeeds without self-conflict.** Create/open a document, submit and flush enough data to leave a sealed old segment plus active successor, then call `Database::compact_document`. It deletes only the eligible sealed segment, retains the active segment and the permit, and a subsequent handle submit succeeds.
2. **Actor pause is queueing, not conflict.** Block compaction after horizon selection; submit another command through the same handle. It must remain pending with no WAL inventory change, then receive a normal receipt after compaction returns the engine. Cancellation/fault follows the same restoration path and the queued submit still succeeds.
3. **No stale selection.** Start a snapshot/compaction race through public actor messages. The floor, selected horizons, payload trace and delete all occur while the same actor turn and compaction lease are held; an active segment is never passed to delete even if it contains only the header.
4. **Failure owner ordering.** Inject `delete_segment` failure and cancellation during horizon/payload scans. The error is delivered only after retained cursors and lease finish; then an independent `acquire_writer(document)` still conflicts until the actor processes the next submit, which proves its original permit was not leaked or released early.
5. **Second compactor / unopened document.** Two compactions for the same document cannot both enter a maintenance turn. For a previously unopened document, `Database::document` opens the actor first and the same actor route is used—there is no direct-storage bypass.

The existing engine law [`compact_document_runs_a_real_compaction_pass_without_error`](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/⚙️engine/🦀️.rs:11531) is the natural replacement point, but currently only observes zero deletion; it must become law 1 plus at least the queue/cancel and sealed-successor cases above.

## Cluster follower ordering

`replicate_document` currently reads `follower_state` before constructing/opening the follower WAL ([`db/🌐️cluster/🦀️.rs:206–237`](../../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🛢️db/🌐️cluster/🦀️.rs:206)). The proposed `acquire_writer → ArtifactWal::open_acquired → replay/plan/apply while retaining that WAL → close` sequence is correct. It fences inventory/recovery and prevents an intervening follower append or rotation from invalidating the bootstrap decision. The leader may remain read-only; the follower must not re-run an unguarded `replay_sync_state` after opening—derive its final state through the held WAL/verified source or only after the owned writer is still retained.

## Qualification boundary

The committed-cursor compaction fixture/law remains valuable for effects semantics ([`📓️sol-wal-committed-compaction.md`](📓️sol-wal-committed-compaction.md)), but it does not prove this writer/actor coordination. No claim of native qualification is made here.
