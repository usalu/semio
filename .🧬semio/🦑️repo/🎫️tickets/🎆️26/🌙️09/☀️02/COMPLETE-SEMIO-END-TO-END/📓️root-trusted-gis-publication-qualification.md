# Trusted GIS Publication Qualification

## Source Defect and Required Boundary

The native bundle-check invokes both genuine GIS cold-map laws before its candidate Hub publishes current. Production TrustedStdioGisBootstrapScript and first-run DevScript call the same candidate publisher without that proof; process rotation also lacks the shared proof call. A source/native gate-only check is therefore not a publication invariant.

The repair will make the exact retained generation's cold-map proof mandatory inside validateAndPublishTrustedStdioGisCandidate, before staging or starting any candidate. Every caller must provide its known Hub binary and Cargo target explicitly. Validation output will be confined to a private non-linked child of the server-owned trusted-catalog root, separate from generations/current. Failure may preserve diagnostics but cannot publish or erase the retained current. Existing current admission is outside this new-publication invariant; this change does not fabricate a persisted prior qualification.

The existing closed bootstrap fixture now includes four entry points and five traces: exact proof, omitted proof, late proof, wrong-generation proof, and failed proof. The independent SQLite reference and production-source hostile checks are being added before production changes. The twenty path/trace combinations must publish only after materialization, exact-generation proof, and candidate validation. No genuine component build, Hub process, browser, or final end-to-end success is claimed by this source work.
