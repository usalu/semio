- charges actual reserved vector capacity and page slots against one reactor-wide 4 MiB/64-page budget;
- rechecks the exact Live lifetime on every page, load admission and post-await completion;
- updates Pack, SPR and aggregate SHA-256 incrementally as each single page is accepted;
- remains structurally mounted through the load await by sharing one exact owner and immutable file allocation with the load grant;
- turns revocation during load into a stale/fault result rather than Applied;
- retains capacity through Applied/Faulted/Loading and releases it only after explicit cleanup;
- wipes at most 64 KiB per `close_step`; registry teardown requires every structural byte and close owner to reach bounded terminal release.

The baseline frontier requires a nonempty active checkpoint edit identity and `last_commit_seq <= head_edit_ordinal`; it does not synthesize a best-effort genesis head. Cold ingress is the fourth exact guest-lifecycle close participant. `Event::ColdDocumentPairPage` is separated from generic WIT events and projected only into the dedicated optional poll input.

The browser worker retains a private `VerifiedColdDocumentPair` bound to the exact runtime key, config, socket, client instance, execution-target lease, checkpoint descriptor/aggregate, published Pack/SPR owners, and full baseline frontier. It opens the guest lifetime, requires the exact Captured receipt, ACKs it, then transfers one page per turn. Every intermediate receipt must be the exact page cursor and the terminal receipt must be the exact Applied lifetime, transfer generation, frontier and aggregate hash. Hub bootstrap network chunks and 64 KiB guest pages are intentionally independent counts.
