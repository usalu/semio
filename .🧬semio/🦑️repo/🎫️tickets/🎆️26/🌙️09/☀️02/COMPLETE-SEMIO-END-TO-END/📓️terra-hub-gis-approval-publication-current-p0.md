# Hub GIS Approval Publication: Current P0

Read-only source audit on 2026-09-05. No build was started and this report does not qualify any current source gate as passing.

## Decision

The highest-priority missing real use case, apart from the separately tracked closed browser bundle, is **approved GIS Map inference becoming a real three-member durable Map publication that survives Hub restart**. The HTTP job, private proposal, authorization checks, SQLite outbox, verified native binding, and approval route are all now present. Production startup nevertheless installs an explicit `UnavailableGisMapApprovalCommitterV1`; every otherwise-valid approval therefore terminates as `approval.commit-unavailable` before a Map patch, WAL transaction, checkpoint, peer update, or reopen can occur.

This is a better next slice than membership administration: membership removal already has a typed, fenced, SQLite-reopen acceptance route in current source. It is also more consequential than adding another route or browser control: all four inference routes already exist.

## One concrete next slice

Implement one **Hub-owned `GisMapApprovalPublicationCommitterV1`** and inject it instead of the unavailable committer at startup. It is a single vertical slice; do not change the public request/preview/approval routes.

The committer must own, per exact `DocumentScope`, the real opened Map aggregate, its current durable generation/fence, the exclusive group-journal sink, and the existing `HubArtifactPublication`. The Store module must provide the owner-only mount/open handoff for its fixed Map host; a Hub caller cannot and should not construct the private `mount_map` operation or fake its `DurableOwnedGroupJournalSinkV1`.

Its one `commit(request)` sequence is:

1. Decode and revalidate the already server-stamped canonical command within the inference module; require its exact scope/actor/mutation/hash and re-derive the prepared parent/drawing/value outcomes from that command and the opened Map state. Never accept a caller-selected `ArtifactStore`, outcome, child handle, or pack.
2. Retain the fixed three-store host and a journal operation. The real sink writes one transaction whose logical body includes both the exact canonical command and the canonical group decision, under the acquired document writer. The journal `Committed` receipt is necessary but not sufficient for an HTTP approval.
3. At `AwaitingAck`, obtain the actual committed-WAL witness through `InferenceWalVerifierV1` with the actor-owned durable generation fence. A local counter or a fresh test fence is not sufficient; the fence must be invalidated whenever that document actor is retired/replaced.
4. Derive the canonical post-group pair from the retained committed Map snapshot and publish it with the existing `CheckpointPublicationOrchestrator::publish_candidate`. Only after stage/readback/verified directory publication succeeds may the host be acknowledged, closed to terminal emptiness, and its owners returned to the document actor.
5. Return the verifier witness and the same durable generation. `commit_prepared_approval` then performs the existing SQLite reconciliation; its HTTP DTO is the approving user’s acknowledgement. If WAL/group commit has succeeded but checkpoint publication, close, or caller delivery fails, retain the host/outbox as `prepared` and resume the identical mutation on retry/recovery. It is too late to abort or re-run inference at that point.

This produces a truthful initial journey: author submits intent -> owner-private proposal -> explicit approval -> one durable three-member update -> verified checkpoint publication -> HTTP applied receipt -> fresh Hub/rebootstrap sees exactly that update. It deliberately does **not** claim current live socket propagation: `ServerFrame::Commands` only carries generic `MutationEnvelope`s ([`wire/🦀️.rs:519`](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/📡️replication/📡️wire/🦀️.rs:519)), and the existing fanout path derives them only from generic submit. A later typed checkpoint-notice/rebootstrap handoff can make already-open peers converge; this slice must not forge that through `ArtifactHandle::submit`.

The successful trace must use a real trusted GIS binding and an authority-verified GIS checkpoint—not the current test helper’s arbitrary `verified-pack` bytes—and assert all of the following before returning the approval response:

- the prepared outbox carries the deterministic mutation/command/proposal identities, then becomes `committed` and erases its private command;
