## Exact selected identity law

The law has two materially different ownership paths.

1. `flow_content_child_handle` derives a new scene allocation from cloned widgets, synapses, and layout. It is therefore the *sole* strong `Arc` carried by `derived`; the new `retire_child_local_owner` takes it out and drives `SceneRetirementFactory` to terminal. This closes the actual failing temporary instead of suppressing its destructor. [derived path](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🧵️retained/🗿️artifact/🦀️.rs:300) [helper](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🧵️retained/🗿️artifact/🦀️.rs:227)
2. Each `SceneHash` path clones the outer `root`, then `take()` transfers that exact reader `Arc` to a child. The child removes and drops this **non-final** Arc; it does not retire the scene. After the reader is closed, the outer `root` is the final strong owner and is driven through `SceneRetirementFactory`. This is the correct ordering: retiring the per-grant child would incorrectly consume the shared root. [transfer](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🧵️retained/🗿️artifact/🦀️.rs:316) [reader take](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🧵️retained/🗿️artifact/🦀️.rs:206) [final root retirement](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🧵️retained/🗿️artifact/🦀️.rs:331)

So the scoped test repair is sound on its normal path. One test-strengthening correction remains: `retire_child_local_owner` currently uses `if let Ok(Arc::try_unwrap(owner))`; an unexpected shared derived scene silently falls through to ordinary `Arc` drop. The helper is intentionally only for a *sole derived child*, so it should assert `Arc::try_unwrap(owner)` succeeds and then assert the bounded retirement reaches terminal. An optional `Arc::strong_count(&root) == 1` immediately before the final root retirement would pin the second path's premise. These are test-only assertions, not a new lifecycle API. ## Existing Flow-owned production boundary

The existing correct domain boundary is a `FlowSnapshot` that is consumed by Flow's `SnapshotRetirementFactory`/installed `MemberStoreOwners`: it removes the typed child owner and retires it only when `Arc::into_inner` owns the final scene; otherwise another retained Flow owner still exists. [snapshot disposal](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/♻️retirement/📸️snapshot/🦀️.rs:29) [installed owner catalog](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/♻️retirement/🦀️.rs:13) The contemporary store preparation path constructs its post-snapshot, then gives it to the store sealer with that same factory; its cancellation close path uses owned snapshot retirement. That is the production-safe path for the current artifact editor, not the test helper. ## Production RED outside this repair

The generic `ArtifactChild` cannot close a typed local materialization: its generic retirement intentionally retains only `child_id` and `target`, omitting `local_owner`. [generic retirement](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/♻️retirement/🦀️.rs:302) Its erased storage supports exact typed `take_local_owner`, but has no type-appropriate domain factory. [typed handoff](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️.rs:2723) Adding an erased disposer to `ArtifactChild` would introduce a generic runtime lifecycle interface and would still not tell the store how to retire a foreign domain type; it is not the correct repair.

There is, however, a real Flow-specific RED separate from the `89964` test repair. `diff_replace_content` creates a cached, strict `FlowContentChild` inside a serializable `FlowDiff`; `MutationDiff::apply` clones that local Arc into a snapshot, while `absorb` may directly overwrite the prior `content` (or the entire diff). A discarded/unapplied/absorbed diff can therefore be the final holder and ordinary-drop its scene. [mint](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🏅️standards/🔖️1/🪆️subsets/✳️any/🧬️schema/🔺️diff/📝️text/🦀️.rs:144) [clone into apply](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🏅️standards/🔖️1/🪆️subsets/✳️any/🧬️schema/🔺️diff/📝️text/🦀️.rs:80) [direct overwrite](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🏅️standards/🔖️1/🪆️subsets/✳️any/🧬️schema/🔺️diff/📝️text/🦀️.rs:99)

Likewise, public `flow_content_child_handle*` and `cache_flow_content` can manufacture or replace an erased local owner outside a Flow snapshot retirement context; `set_local_owner` directly replaces its prior erased `Arc`. Current schema-test callers cache after decoding a wire-only child, but this does not make the public boundary safe for a live child. [constructors](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🦀️.rs:167) [replacement](/Users/ueli/Documents/semio/✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🦀️.rs:209) [generic setter](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️.rs:2706)

The smallest honest follow-up is **Flow-domain-only**, not a generic erased disposer: keep live `FlowWorkingScene` materialization out of serializable `FlowDiff` / raw public child temporaries, or retain it in a Flow-specific operation whose cancel/absorb/discard paths are all driven by `SceneRetirementFactory`. A wire diff should contain only the child reference; a completed store/member mount is the point that may attach a local scene after typed materialization. That requires a separate source-first packet and laws for discarded, replaced, and applied-but-not-published diffs. It must not be credited by a passing selected identity law.

## Verdict

- **Scoped 89964 test cleanup:** PASS in source, pending the narrow uniqueness assertion and native rerun.
- **All production local-owner disposal:** RED. The established store/sealer path is bounded, but raw Flow child/diff construction bypasses it. No runtime claim or generic interface recommendation follows from this audit.
