# Flow Parent Pack and Hydration Audit

## Verdict

**RED — no authenticated, retained Flow-parent adoption exists today; no Flow render projection is safe to ship first.** The public generic path can parse and install a Flow parent, but it does not receive an expected D0 identity or hashes, retains no bounded decode owner, and does not hydrate the composed `content` child into the runtime scene that Flow renderers and most commands consume. Worse, the current Flow mutation model makes parent and child disagree after either kind of edit (documented below). This is source evidence only; no build or runtime run was performed for this audit.

The first Flow-owned packet must establish one stable child-member authority and atomic initial/mutation publication. Only then may a projection make that already-live `SemioFlowSnapshot` visible to editor/viewer. It must not be described as parent-pack persistence or as a substitute for the provider's retained child-open pipeline.

## Current parent path

`VcsArtifactApp::hydrate_document_lane` copies raw byte slices into `ArtifactPackFiles` and calls `load_document_pack` at `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:24533-24538`. `load_document_pack` then parses the raw whole `pack` plus `spr` and directly resets the document store at `:24705-24716`.

`store::parse_document_pack` is only a forwarder to `parse_document_spr` (`🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️.rs:11344-11353`). That parser decodes the complete SPR history and invokes the snapshot's whole-value `ArtifactPack::decode_pack` before replay (`:10982-10996`). The decoded log supplies the envelope `schema` and `doc_id` (`:11082-11085`), and `VcsArtifactApp` passes the resulting envelope to `ArtifactStore::reset` without comparing it to an expected document reference, full dialect, root ownership, or D0 receipt/hash.

Consequences:

- A syntactically valid Flow `.pack + .spr` identifies itself; the caller provides no expected document id, `flow.fixture` store schema, `s.flow.flow@1/*` dialect, root-owner requirement, or descriptor/receipt byte hashes to compare.
- Both byte arrays are complete `Vec`s before parsing. The generic retained envelope ingress is not this codec: the default `ArtifactApp::build_envelope_decode_owner_bundle` returns `None` at `🔌️plugin/🦀️.rs:11093-11097`, as does Flow, and the default retained initialization job returns its envelope as rejected at `:11153-11161`.
- `parse_decoded_document_spr` explicitly reconstructs non-document history lanes as an empty map because the HistoryLog has no lane overlay (`🏪️store/🦀️.rs:11089-11100`). A parent pack reload is therefore not presently a lossless general lane restore.

`ArtifactPackFiles.ops` is only a mirror; `pack` and `spr` are the authoritative bytes (`🏪️store/🦀️.rs:9306-9320`). It must not be used to repair or silently override a failed binary load.

## Exact Flow codec defects

The Flow parent is `FlowSnapshot { schema, camera, content }`, where `content` is a durable child reference and its local materialization is deliberately absent from wire identity (`✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🏅️standards/🔖️1/🪆️subsets/✳️any/🧬️schema/📸️snapshot/🦀️.rs:20-29`; `🏪️store/🦀️.rs:2653-2655,2780-2810`).

The parent binary pack writer correctly emits `flow.flow`, `Component::Pack`, version `1` (`📸️snapshot/🦀️.rs:101-109`). Its decoder checks **only** `envelope_id()` at `:110-118`; a `flow.flow.dsl`, `.op`, `.spr`, or a non-v1 binary envelope is accepted if its JSON body happens to decode. The generic envelope exposes public `component` and `version` fields (`🧰️framework/🛍️products/💻️os/🔨️modules/🧬️semio/🦀️.rs:77-103`), so the closed repair is an exact three-part comparison: id `flow.flow`, `Component::Pack`, and version `1` before JSON allocation/`FromValue`.

The textual parent parser has the parallel defect. It discards any parsed preamble, accepts raw JSON when preamble parsing fails, and otherwise falls through to the distinct framework `flow::FlowFixture` parser (`📸️snapshot/🦀️.rs:74-91`). Thus it cannot establish `flow.flow.dsl v1`; it accepts a missing, wrong-component, wrong-version, or framework-fixture source. `load_document_text` reaches that parser through the same raw-reset pattern (`🔌️plugin/🦀️.rs:24693-24698`). The durable Flow contract needs one strict preamble check for id `flow.flow`, `Component::Dsl`, version `1`, followed by only FlowSnapshot's JSON decoder. Raw JSON and `FlowFixture` belong in explicit test/developer fixture utilities, not the public persistence decoder.

These changes require hand-fixing committed Flow parent assets and callers in the same packet; no compatibility/fallback parser is justified.

## Why a decoded parent is not a usable Flow document

Flow's rich scene is a `FlowWorkingScene` local owner attached to `content`; it is omitted from every codec and a decoded unresolved handle reads as an empty scene (`✏️s/🔌️plugins/🌊️flow/🗿️artifacts/🌊️flow/🦀️.rs:197-224`). `FlowSnapshot::to_fixture` consumes that owner (`🧬️schema/📸️snapshot/🦀️.rs:46-52`). Therefore a freshly decoded parent has its durable child id and dialect but no widget, synapse, or layout materialization.

The framework does have the needed read capability. Each render receives an `ArtifactView` with an immutable `ChildContentView` (`🔌️plugin/🦀️.rs:8062-8071`), and `ChildContentView::typed_read` returns the exact typed child snapshot for `(slot, child_id)` (`:8628-8642`). A real retained Flow continuation already uses it for duplicate-widget and binds the captured child revision (`✏️editor/🎮️commands/📋️duplicate-widget/🦀️.rs:202-237`). Generic `open_child` captures a member snapshot into that view (`🔌️plugin/🦀️.rs:19929-19947`), but it does not invoke Flow's domain bridge.

Conversely, all normal Flow rendering currently ignores `doc.children`: the framework invokes `render_with_request_context` with that view at `🔌️plugin/🦀️.rs:24778-24790`, its default delegates to `render_with_instance_operation_owner` (`:26297-26318`), and Flow immediately renders `doc.snapshot` (`✏️editor/🦀️.rs:1772-1811`). The editor document panel then calls `to_fixture` at `📌️panels/🗿️artifact/🦀️.rs:37-48`; the viewer does the same at `👁️viewer/🎭️modes/👁️view/🪟️windows/🌊️main/🦀️.rs:77-102`. This yields an empty/default graph after parent wire decode rather than consuming the live child.

The existing lossless converter is the right domain primitive: `working_from_flow_content_snapshot` at `🌊️flow/🦀️.rs:152-162`, paired with `flow_content_child_handle_bounded` at `:171-193`. The latter produces the canonical content-addressed child id and complete `ArtifactRef`; `ArtifactChild` equality deliberately compares exactly child id plus full target and excludes only local ownership (`🏪️store/🦀️.rs:2754-2783`).

## Blocking Flow content-publication incoherence

**Current state is RED before any runtime projection is safe.** The generic composition contract makes an `ArtifactChild` coordinate the durable identity of a live child member: `ChildDispatch` targets that exact `ArtifactRef` (`🏪️store/🦀️.rs:18719-18724`), ownership is indexed by its `artifact_id` during group validation (`:19356-19370`), and a checkpoint cascade commits children without rewriting the parent reference (`🔌️plugin/🦀️.rs:20076-20100`). A child therefore normally keeps its identity while its own history/checkpoint changes. `ChildGenesis` is explicitly for a *new* member, with initial pack bytes (`🏪️store/🦀️.rs:18726-18735`); it is not a child-edit mechanism.

Flow currently creates a second, contradictory authority. `flow_content_child_handle_bounded` defines the child id as a SHA-256 of its complete scene (`🌊️flow/🦀️.rs:164-193`), and each of the nine ordinary semantic leaves routes through `diff_replace_content` to replace the parent `content` with a fresh hash/id plus a local-only `FlowWorkingScene` (`🧬️schema/🔺️diff/📝️text/🦀️.rs:138-146`; leaf roots under `🧬️mutations/{create-widget,delete-widget,reorder-widgets,replace-widget,connect-widgets,disconnect-widgets,reorder-synapses,update-synapse-endpoints,move-widgets}/🔺️diff`). The parallel retained preparation repeats this: it reads `base.content`'s local scene then remints a new handle at `✏️editor/🦀️.rs:520-652`. Neither route emits a child operation, child genesis, map registration, graph update, nor retired-old-child record.

The lone reverse mismatch is the action-bus duplicate-widget command. It reads the live `SemioFlowSnapshot` and emits two `ChildEmit` operations against the **existing** id (`🎮️commands/📋️duplicate-widget/🦀️.rs:191-199`), but emits no parent `FlowMutation` to recompute the content-addressed handle. The schema-level `DuplicateWidget` is indeed a `CompositeMutationKind`, but only by planning the two ordinary parent-only leaves (`🧬️mutations/👯️duplicate-widget/🦀️.rs:1-42`); that does not cure the action command's mismatch.

Thus a render-time cache refill would mask two invalid states rather than repair either:

- After an ordinary Flow mutation, the parent points at a new child id that is absent from the live map/graph; the old registered child remains.
- After the action-bus duplicate, the live child changes under an id whose parent reference still commits the old scene digest.

The existing fixtures expect changing ids because they encode precisely this content-addressed *local scene cache* model: `flow_parent_projection_and_child_identity_match_neutral_corpus` asserts a SHA-derived id from scene JSON (`✏️editor/🧵️retained/🗿️artifact/📸️snapshot/🦀️.rs:65-96`), and retained preparation tests inspect a local owner rather than a registered `SemioMembers::Flow` member (`📬️preparation/🦀️.rs:264-293`). They are not evidence that a member identity can safely change under a parent without co-publication.

### Required single-authority decision

The smallest coherent design is to make the composed `SemioMembers::Flow` child the sole durable owner of widgets, synapses, and layout. Its `ArtifactRef` must be stable for the lifetime of that composition slot; mutations become typed `SemioFlowMutation` operations dispatched through `ChildEmit`, while `FlowSnapshot.content` remains the same exact coordinate and carries no mutable scene cache. A content digest may be a verified checkpoint/content commitment, but must not double as the mutable child artifact id.

This requires a schema-first initial-composition seam before Flow can claim a live factory:

1. Make Flow's initial parent snapshot and its content child agree on one exact child `ArtifactRef`/owner coordinate. The current coordinator mints a normal-event genesis id from `(parent id, slot, parent-op fingerprint, ordinal)` (`🏪️store/🦀️.rs:19055-19083,19372-19406`), but the current plugin `Emit` path is post-construction gesture dispatch: it accepts only existing `ChildEmit`s (`🔌️plugin/🦀️.rs:10169-10212,20834-20902`) and hard-codes `genesis = Vec::new()` (`:20915,20923-20927`). Do **not** add a generic genesis vector to `Emit` to solve factory construction. A parent operation that itself embeds a content-addressed id cannot solve the circularity. Use a dedicated, schema-visible initial-composition constructor with one parent-visible, deterministically precomputed child coordinate; do not guess a global `flow-content` id and do not expose a raw child-id string. `VcsArtifactApp::with_registry_on_bus` knows `app.instance_id()` before it calls `A::initial_snapshot()` and uses it as the temporary parent envelope id (`🔌️plugin/🦀️.rs:19157-19167`), but for `EditorApp`/`ViewerApp` that is merely the derived surface id (`:26618-26660`), not a per-D0-document identity. It is reusable only for a single ephemeral surface default, never as the durable child identity for equal Flow documents. The durable construction request must instead receive the authenticated D0 parent `ArtifactRef` before snapshot creation.
2. At factory genesis, atomically create/register the `SemioFlowSnapshot` member, stamp its exact owner, insert the graph edge, then publish a parent whose `content` equals that returned target. The coordinator already defines the necessary phase order — child genesis, child edits, parent ops — and compensation semantics (`🏪️store/🦀️.rs:19289-19340`), but no Flow authoring path reaches it today.
3. Translate every Flow semantic leaf and action-bus command into a same-gesture typed child edit. Parent edits are reserved for true parent fields such as camera/schema. If a leaf must replace a child rather than mutate it, its `ChildGenesis`, parent pointer rewrite, map/graph retirement, undo/redo and checkpoint pins must be one explicit group; no current Flow emission has that protocol.
4. Only after (1)-(3), derive a short-lived `FlowWorkingScene` from the exact live child for rendering/commands. It is a projection cache, never an alternate source of truth or a persisted replacement. The parent wire snapshot stays unchanged during this projection.

The first neutral/native acceptance must start from the actual Flow factory (no test-only `register_content_child`), perform an ordinary CreateWidget and the duplicate action, then prove after each gesture that: one parent coordinate names one registered graph-owned child; that typed child equals the visible scene; parent/child group identities and undo/redo agree; a failed/cancelled group leaves prior parent, child, graph and map untouched; and close/reopen/checkpoint recreate the same relation. The present manual test helper is insufficient because it installs the content child only under `cfg(test)` (`✏️editor/🦀️.rs:2050-2125`).

### P0: document-scoped initial composition (exact current seams)

There is **no reusable durable parent identity in the current factory path**. `VcsArtifactApp::with_registry_on_bus` derives `app_id` from `A::instance_id`, then calls `A::initial_snapshot` and creates the parent envelope under that id (`🔌️plugin/🦀️.rs:19157-19167`). The `EditorApp` and `ViewerApp` adapters derive that id from only `(dialect, role)` (`:26618-26660`), so two Flow documents on the same editor surface receive the same provisional id. It is unsuitable as a document/root identity and must not seed child ids. The durable source must be the authenticated D0 document descriptor/open selection's document id plus exact selected Flow dialect, introduced as one immutable `ArtifactRef` before app construction; the current `LoadDocument` command supplies only bytes after construction (`🔌️plugin/🦀️.rs:31472-31478`).

`GroupReceipt` is not the initial-construction receipt. It describes an already-live event group and returns created members only after `dispatch_relation_group` has inserted graph edges (`🏪️store/🦀️.rs:18737-18758,19400-19465`); `VcsArtifactApp::absorb_created_children` then admits/publishes them one by one (`🔌️plugin/🦀️.rs:20811-20831`). Worse, a later genesis creation or group application error drops the locally accumulated `created_children` while graph insertions have already happened (`🏪️store/🦀️.rs:19394-19406,19415-19455`). That existing path therefore cannot be claimed as bounded all-or-nothing initial publication. Initial composition needs its own owned `InitialCompositionReceipt`/abort path: stage every `SemioMembers::Flow` candidate under the existing bounded child-member retirement machinery, validate all coordinates and parent snapshot references, then make one graph/map/root publication; any failure or cancellation retires every staged candidate and leaves no graph edge.

The new id must use a separate documented initial-composition domain over the authenticated full parent coordinate, declared slot, child dialect and fixed ordinal/initial semantic input. It is neither `mint_child_id`'s parent-operation fingerprint (there is no event yet) nor a content digest. The constructor may return a private receipt containing the immutable parent snapshot plus staged child targets, but it must never publish a partial receipt to an ordinary `Emit` handler. Once the relation is live, ordinary Flow edits should reuse existing `ChildEmit`/`dispatch_group` against that member only; a later true replacement must be an explicitly designed grouped operation with its own bounded candidate retirement, not an implicit parent-handle rewrite.

#### P0 target inventory and order

1. **Parent authority (new constructor input, not a new id generator).** The D0 authenticated open/creation selection must pass one validated `ArtifactRef` into `VcsArtifactApp` before `ArtifactApp::initial_snapshot`. The current framework has no document-scoped parent mint on this path: `with_registry_on_bus` takes only `app`/registry/bus and uses the surface-derived `instance_id` as the envelope id (`🔌️plugin/🦀️.rs:19144-19167`). The constructor must reject an absent, mismatched, or non-`A::DIALECT` parent coordinate before allocating an app/store. It must not reuse the surface id, a document snapshot hash, or a D0 display/descriptor string as an id.
2. **Schema-owned seed, framework-owned target.** Add a closed `InitialCompositionSeed` carrying bounded `ChildGenesis`-shaped member specifications (`slot`, complete child dialect, exact initial-pack bytes); it contains no caller-provided id. A framework helper mints `InitialChildTarget { ArtifactRef, OwnerRef }` using a distinct canonical `mint_initial_child_id(parent_ref, slot, child_dialect, ordinal)` domain. The app then receives those typed targets to construct its initial parent snapshot, so Flow can install `ArtifactChild<SemioFlowSnapshot>` with the exact returned target. This is the only point a parent snapshot gains its child ref. The existing `mint_child_id` remains correct only for a normal parent-operation group and must not be overloaded (`🏪️store/🦀️.rs:19055-19083`).
3. **Closed preflight before candidates.** Before `M::create`, compare `A::DIALECT`, each target's full coordinate, declared slot/kind/many rules and `A::child_restore_projection(snapshot)`; require `admit_complete` to account for exactly the seeded children. Reserve the fixed child root/child registry/abort capacity before any member is made. `admit_child_member` already constructs exact `ArtifactRef`, `OwnerRef`, graph admission and root generation (`🔌️plugin/🦀️.rs:19913-19927`), but its one-child commit is not a batch transaction and must not be called as a partial loop for a future multi-child seed.
4. **Owned staging and one observational commit.** Build each `SemioMembers` candidate with the exact target, set its exact owner, capture its `ChildContentView`, and retain any unsuccessful candidate in `ChildMemberRetirement` rather than allowing `Drop`; that retirement already demands `close_owned_step` and a terminal-empty witness (`🔌️plugin/🦀️.rs:8818-8865,19977-19989`). Only after every candidate/root is ready may the private construction receipt consume all graph admissions, registry admissions and replace the root/map. The constructor has exclusive `&mut self` before it returns the app, so this can be observationally atomic even though member setup is async. Cancellation or any failure before that point returns no app and drives the fixed abort registry; it never exposes a partially initialized `VcsArtifactApp`.
5. **Receipt and dispatch separation.** Name the result `InitialCompositionReceipt`, not `GroupReceipt`: there is no user event, parent operation fingerprint, `MutationMeta.group_id`, or ordinary undo row at initial construction. `GroupReceipt`/`dispatch_group` continue to serve post-live gestures only. `Emit` remains a reducer result and its `child_emits` branch continues to require already-registered members (`🔌️plugin/🦀️.rs:20735-20742,20884-20915`). This avoids treating factory construction as a normal asynchronous command and avoids extending the current `Vec::new()` genesis call into an unsafe generic feature.

The current `GroupReceipt` code is useful only as a type/ownership caution, not as an adoption implementation: it creates candidates and calls `insert_owns` immediately (`🏪️store/🦀️.rs:19394-19406`), then reports them to the caller; `absorb_created_children` subsequently updates map/root entry by entry (`🔌️plugin/🦀️.rs:20811-20831`). In particular, an error after one created member can leave an ownership graph entry before no-panic retirement has run. P0 must not call that route during factory genesis.

The smallest clean framework+Flow packet is therefore:

1. Add a document-scoped constructor request at the `VcsArtifactApp` construction boundary, e.g. a private typed `DocumentConstruction<A>` containing the exact parent `ArtifactRef`, already authenticated descriptor/selection generation, and cancellation authority. It validates `parent.dialect == A::DIALECT`, rejects an empty/oversize document id, and is the only constructor permitted for a composed Flow document. `VcsArtifactApp::<EditorApp<FlowPlayApp>, SemioMembers>` and the viewer equivalent are the actual registered fleet (`✏️s/🔌️plugins/🌊️flow/🦀️.rs:11-34`). No `surface_app_id` fallback may be reachable for Flow's composed factory.
2. Add a schema-first `InitialComposition<A, M>` hook that consumes that parent ref and returns a parent snapshot plus at-most-fixed-cap child creation specifications. It is an explicit result, not `ArtifactApp::initial_snapshot()` plus a later cache fill. Validate it *before* store publication with `A::child_restore_projection(&snapshot)` and `ChildRestoreProjection::admit_complete` (`🏪️store/🦀️.rs:2850-2904`), so every declared `ArtifactChild` coordinate, dialect, slot and cardinality equals the intended child set.
3. Introduce a separate root-genesis identity function with a domain distinct from `mint_child_id`. The existing `mint_child_id(parent, slot, parent_edit_fingerprint, ordinal)` is intentionally event-derived (`🏪️store/🦀️.rs:19055-19083`) and cannot be used to construct a parent snapshot that must already name the child; feeding a sentinel fingerprint risks collision with a later event. The root function must derive one stable child target from the exact parent `ArtifactRef`, slot, child dialect and ordinal under a dedicated initial-composition domain. It must never hash mutable Flow scene bytes.
4. Reuse `CompositionCoordinator`'s owned-child creation rules, but expose a distinct `initialize_owned_children` operation for the initial plan rather than abusing `dispatch_group` with a fake parent mutation. `dispatch_group` already states the relevant order — child genesis before parent apply — and owns `M::create`, owner stamping and graph insertion (`🏪️store/🦀️.rs:19289-19406`). The new operation must stage all `SemioMembers::Flow` candidates, validate fixed capacity and all projection rows, then commit graph, child map and *one immutable `ChildContentRoot`* only once. The current `absorb_created_children` publishes each child one-by-one (`🔌️plugin/🦀️.rs:20821-20831`) and is not a safe initializer for an all-or-nothing parent.
5. On a parse/create/owner/graph/root/cancellation failure, return the candidate members to an existing bounded child retirement path before exposing either the parent store or a child map entry. `ChildContentView` itself is fixed-slot (`🔌️plugin/🦀️.rs:8450-8525`); preserve that limit, reserve the whole root span before work (`:19841-19851`), and do not add an unbounded cleanup vector. Initial publication must have no parent VCS edit and no fabricated group id; it establishes the root state that later real groups mutate.

This packet deliberately does **not** change the provider's retained child envelope reader, D0 binary parent load, or every Flow semantic leaf. It creates the one true parent/child relation needed before either can be made correct.

#### Required P0 fixtures and gates

Use a language-neutral initial-composition corpus with: two distinct parent document ids with identical starter Semio Flow bytes (different child targets); same parent/slot/dialect replay (same target); substituted parent kind/standard/subset, slot, child dialect or initial pack (deny before publication); duplicate/missing child rows; fixed-root capacity exhaustion; `SemioMembers` factory mismatch; cancellation/failure at create, owner stamp, graph insertion and root publication; and retry after every rejected stage (one exact graph/map/root, no leaked candidate).

The focused native law must construct the actual `Plugin<FlowApps>::plugin().create_app` path with a document-scoped request, prove both editor and viewer have exactly one `content` entry in `ChildContentView`, prove the `SemioMembers::Flow` child owner is the same parent/slot/id held by `FlowSnapshot`, and bounded-close every app/candidate across small grants. A sibling law must prove the old surface-id-only creation rejects composed Flow rather than creating two equal-root children. Register the exact-one focused law through Flow's existing `📜️script.ts` and change the launch seed before regenerated launch metadata; no current registration proves this packet.

## Withdrawn runtime projection — conditional replacement only

The earlier proposed projection that recomputed a content digest, compared it with `FlowSnapshot.content`, and cloned a whole `FlowWorkingScene` per render is **withdrawn**. It embeds the obsolete content-addressed-id model, turns bounded render work into full-scene allocation, and would be contradicted by every valid stable-child checkpoint change.

Only after the single-authority packet above, add a private bounded `FlowChildView` conversion that receives the already-validated `ChildContentView` entry for the stable `content` coordinate. It may build a short-lived read-only UI model from the exact typed `SemioFlowSnapshot`, but it must neither allocate/attach a `FlowWorkingScene` to the parent nor recompute/change the parent reference. `working_from_flow_content_snapshot` is not sufficient as-is: it returns an infallible `Vec` projection and `widget_from_node` maps an unknown kind to `InputNote` (`🌊️flow/🦀️.rs:99-125,152-162`). The eventual view conversion must be strict and bounded before the UI sees it.

For an available live child, the replacement must:

1. Require `doc.children.dialect("content", snapshot.content.child_id)` to equal the snapshot's full `content.target`, then `typed_read::<SemioFlowSnapshot>("content", child_id)`.
2. Require `SemioFlowSnapshot.schema == STDIO_SEMIOFLOW_DOCUMENT_SCHEMA`; the retained stdio decoder already has its own identity/caps (`MAX_NODES=256`, `MAX_EDGES=512`) at `✏️s/🔌️plugins/🗄️stdio/…/📸️snapshot/💾️binary/🦀️.rs:10-16,49-105`, but Flow must additionally enforce its own 256-widget **and 256-synapse** cap before conversion. A valid stdio child may contain 512 edges, exceeding Flow's existing `FLOW_STORE_MAX_SCENE_ITEMS=256` (`✏️editor/🦀️.rs:323-324`).
3. Strictly validate and translate the child snapshot without re-hashing it into an artifact id. Reject an unknown/malformed stdio node, an unsupported parameter, a duplicate id, or an over-cap scene before constructing a UI model. The validation must preserve all Flow fields rather than silently mapping an unknown node to a note.
4. Return a borrowed/bounded UI-facing projection, not an owned clone of the parent and not a `FlowWorkingScene` cache. Do not mutate the `ArtifactStore` snapshot, its persisted parent reference, or a process-global cache.

For a fresh in-memory default, the factory must already have installed the stable content child through the initial-composition packet. An absent live child is an explicit `flow.content-unmaterialized` error, never `FlowWorkingScene::default()` and never a local-only fixture owner.

This packet is deliberately smaller than parent loading: it makes an already-admitted child render accurately. It cannot authorize the raw `load_document_pack` path and cannot replace the provider's request-owned retained `MemberFactory::open` work.

## Parent-adoption follow-up contract

After the provider's child open becomes retained, a separate parent ingress must accept an owned request containing: expected root `ArtifactRef`, exact Flow dialect, expected `flow.fixture` store schema, root-owner constraint, authoritative pack/SPR byte hashes from D0, cancellation/generation authority, and byte/page limits. It must verify Flow's outer pack identity before decoding the snapshot, verify the SPR envelope identity before parent publication, retain every partial owner, and make the parent unavailable to render/commands until its declared content child has materialized and passed the Flow projection above.

Do not wire Flow's JSON `ArtifactPack` into the generic `ArtifactEnvelopeFreshFieldDecoder`: that is a distinct 12-field canonical fresh-envelope format and expressly does not carry history. Do not call legacy `M::open` as proof of the retained child path; `open_child` still invokes it directly at `🔌️plugin/🦀️.rs:20003-20040`.

## Required laws and gate
