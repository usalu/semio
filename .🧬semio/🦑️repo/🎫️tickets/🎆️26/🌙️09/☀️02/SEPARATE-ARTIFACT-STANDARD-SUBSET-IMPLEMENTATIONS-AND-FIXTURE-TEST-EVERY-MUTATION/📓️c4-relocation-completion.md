## Read first: the framework code confirmed

`resolveFixtures` (`🧰️framework/🛍️products/🦑️repo/🔨️modules/🧪️test/📦️packages/🟦️typescript/🟦️.ts:962`):
`asset://` resolves against `discovered.owner` (the case's parent-of-parent directory), with a path-
escape guard (`resolve(abs).startsWith(guard + sep)`) that makes it categorically impossible for a
case to reach a file outside its own owner's subtree. `shared://` resolves against
`<owner>/🧫️fixtures`. This confirmed every "blocked" diagnosis in B6's census and is why every fix
below is either (a) give the subset its own copy of the input, or (b) point the URI at a real
generator-produced document already owned by that subset.

## One regression caught and fixed

After the 10-case semio batch, `missing-fixture` jumped **0 → 42**. Root cause: the semio feature
files carry TWO independent kinds of `asset://` self-reference — (1) `✳️any/📚️examples/<name>/…`
(the one this shard's script targeted, correctly), and (2) `✳️<own-subset>/🧬️schema/🧬️mutations/…`
— a SECOND, pre-existing absolute-from-artifact-root reference to the case's OWN mutation-catalog
fixtures, valid only while the case still lived at artifact level. Once relocated, `asset://` resolves
against the new owner (`✳️brep`, `✳️value`), so the un-stripped `🏅️standards/🔖️v1/🪆️subsets/✳️brep/`
prefix doubled onto the new owner path and 404'd. Affected exactly 2 of the 10 semio cases (`brep`,
14 fixtures; `value`, 1 fixture — the others' catalog references were already relative). Fixed by
stripping the case's-own-subset prefix the same way B6's `relocate()` script did for its 95 cases;
re-ran the gate and confirmed `missing-fixture` back to 0 before continuing.
