### Native entrypoint & plugin hosting
- `⌨️native-entrypoint/🦀️.rs` (included verbatim as the binary's `fn main`) does credential-poison checks (`protected_credential_environment_is_absent`), an optional `claim_inherited_local_hub_credential("native")`, then either a `--scale` scale-bench dispatch, a `--smoke` headless dump (`run_smoke`), or the default `run_native(plugin_filter, modules_root)`.
- `run_native` (`🧊️renderer/🦀️.rs:16132-16137`) builds a `winit::EventLoop`, constructs `WinitApp::new(proxy, plugin_filter, plugin_modules_root)` (native ctor variant, `🪟️winit-app/🦀️.rs:443-462` — no `plugins`/`canvas` fields for `not(wasm32)`), and runs the event loop; `resumed` (`…/🦀️.rs:648-698`) spawns `boot_runtime` which for native calls `load_wasm_plugins(plugin_filter, plugin_modules_root)` (`🌉️ProgramBridge/🎯️targets/🧊️wgpu/🦀️.rs:723-770`).
- `load_wasm_plugins` (native only, `#[cfg(not(target_arch = "wasm32"))]`) scans `modules_root` for plugin directories (space mode for `s`), finds each plugin's `.wasm` artifact via `run_renderer_io`/`ScanDirectory`, reads an optional build-time `🔣️.json` `PackageDescriptor` manifest if present (else an honest empty manifest — "no eager loading": no plugin wasm is instantiated at boot, only at first `create_app`, `🦀️.rs:706-717`), and constructs `ProgramBridgeEntry::from_wasm`. Space mode skips (rather than hard-fails on) one plugin with a missing/bad `.wasm` artifact so 53 good plugins aren't held hostage by one broken crate (`🦀️.rs:762-775`, ticket-referenced behavior).

## 3. Renderer parity — what "same schema-first contracts" means in code, and what tests exist

- Master plan (`📋️master-plan.md:15`): "React and native shells agree on the same schema-first contracts and observable behavior" is outcome bullet 5 of the whole ticket.
- The only executable parity harness found is **React vs WGPU-in-browser (wasm), driven by Playwright — there is no automated parity harness against the native winit shell** (a native OS window can't be screenshotted/DOM-dumped by Playwright the way a page can). This is a structural gap in "parity," not just an unrun test.
- Mechanism (`🧰️framework/🛍️products/💻️os/🔨️modules/🧑‍💻dev/📦️packages/🟦️typescript/📜️script.ts`):
  - `dumpReactStructure` (`:3482-3485`) calls a `REACT_DOM_DUMP_SCRIPT` `page.evaluate`.
  - `dumpWgpuStructure` (`:3493-3497`) calls `window.wasmBindings.dumpStructure()` — a wasm-bindgen introspection hook exported from the wgpu renderer's own `🔬️Introspection` region (`🧊️renderer/🦀️.rs`), i.e. the retained UI tree the wgpu renderer maintains internally, serialized to the same `{path, kind, text, rect}` shape as the React dump.
  - `compareParityStructural` (`:3538-3558+`) matches nodes by `path` across both dumps and diffs `text`/`rect` (with tolerances) — this **is** the concrete "same schema-first contract": both shells must produce an isomorphic path-keyed node tree (kind/text/rect), i.e. the same retained UiNode/document schema surfaced two different ways (React DOM vs wgpu-internal retained tree).
  - Pixel-region diffing (`compareParityRegion`) and a `behavioral` probe suite (`runParityProbe`, action-driven state-diff) run on top of structural comparison; results write to `parity-report-v2.{json,md}`.
  - Router: `parity {smoke|triage|probe|verify|sweep}` (`:5486-5495`), registered as an Nx `parity` target on `@semio-tech/framework-os-dev` (`🧑‍💻dev/📦️packages/🟦️typescript/📋️project.json:125-135`, `cwd` = that package, `command: bun ./📜️script.ts parity`).
  - `isParityStaleBridge` (`:4390-4392`) explicitly carves out `STALE-BRIDGE` boot results from the pass/fail verdict — i.e. the harness itself expects some playgrounds' generated bridge to be transiently out of date and doesn't fail the whole sweep for that.
- No result of a `parity verify s` / `parity sweep` run for `s` specifically was found in this ticket's reports; status is **unknown, needs a run** (the harness exists and is wired, but no `s`-scoped receipt is on record in the read reports).
