## Grounded Cause and Existing Interfaces

The storage owner captureJavascriptDependencyDescriptorInputsV1 uses one check counter for the complete aggregate oldMaterial.group. The counter is passed as the actual Generic descriptor checkpoint to withArtifactRelativeDirectoryV1, so it counts all underlying native ownership checks, not merely application-level file/chunk operations. SourceOwnerStoreProtocol currently allows 64 roots, 512 files per root, 64MiB, depth64, path256, chunks65536 and maximumWork4194304. The planner aggregates all selected existing/resumable plans before capture.

For every file the current implementation acquires each previously unseen directory prefix independently, then reacquires its complete parent through withJavascriptDependencyProducedDirectoryV1. That helper capture(parts) probes every prefix by reopening prior path owners, then opens the complete issued path again. Thus siblings repeatedly rebuild path custody despite an unchanged parent. Windows withDirectoryPath revalidates root-family issued proof lineage and descriptor facts on every opened path step. Windows internal() calls the supplied checkpoint and facts(owned); withFile calls internal() on reads/stat and the file facts too. The semantic safety checks are necessary, but the repeated parent acquisition multiplies their work.

Existing capability API already supports scoped parent reuse: ArtifactRelativeDirectoryV1.withDirectory / withDirectoryPath callbacks receive a live child capability, and the child can perform entry/withFile for multiple sibling files while custody remains open. Do not persist a capability after its callback or replace it with path strings or cached stat DATA. Existing directory identity maps are facts only, not authority. A bounded directory trie / per-parent sibling grouping can use the existing callback API and avoid independent full-parent capture for each sibling, while retaining per-file named-before / descriptor-before / EOF / descriptor-after / named-after checks, complete byte hashing, and post-capture verifyJavascriptDependencyDescriptorGroupV1. No new filesystem authority is needed.

The verifier currently also reacquires each parent for each file, so a capture-only grouping repair may still exceed its independent replay work counter on the same large group. Stage uses similar independent acquisition. Audit capture and replay together before assuming the first capacity refusal was the only bottleneck. Preserve complete verification and cancellation rather than increasing only maximumWork or removing ancestry facts.
