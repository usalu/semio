# Memory Incident, 26 November

During containment, the independent w25 Cargo was interrupted and its PID 30745 was no longer present. No automatic retry is configured. The managed capacity wrapper had refused the fallback before native execution; the fallback subsequently used the explicitly authorized pinned native Cargo route with one job. That route did not reserve the managed fleet capacity budget, so concurrent work could collectively exceed the admission forecast even though each job was individually bounded. This was a material gap in the fallback decision.

At 00:24:58 CET `repo capacity status` reported 16 GiB physical memory, 6515 MB available, 2124 MB swap in use, normal pressure, and a calm enforcing warden; its cumulative counters were 57 suspensions, 57 resumes, zero cancellations. The warden log records suspending a `native-clone25.ts` process and other repository build processes during warning pressure. One sample reported 2701 MB available and 478.65 MB/s swap activity; later resume messages say calm while the sampled pressure field still says warning. The log has no per-line timestamps, so those actions cannot be placed at an exact clock time from that file alone. The warden identifies and suspends process trees reactively; it is not a substitute for admitting a raw native Cargo process against the machine-wide forecast.

The bounded macOS unified-log window shows `memorystatus` idle-exit kills of background daemons beginning at 00:21:02 CET and continuing past 00:23:50. Idle-exit is the stated reason and does not establish that those kills were caused by this build. At 00:22:38 runningboard explicitly logged that the Codex app process was not lifecycle managed and ignored a suspend request; this is not evidence of an actual app suspension. No exact application pause time or individual causing process was established from the queried logs. The observed warning pressure, high swap activity and concurrent build activity support memory contention as a plausible cause of unresponsiveness, not a proven single-process attribution.

The safe follow-up is coordinated admission for every heavy compiler, including fallback children, accounting for fleet work and preserving enough interactive headroom; observe warning pressure and swap-rate recovery before starting or resuming heavy work. No warden policy was changed in this audit.

## Containment and fixes

The Draw coordination ran four overlapping Cargo pipelines and an isolated Wasmtime cold compiler on one 16 GiB host. The four pipelines were stopped without touching the desktop or other developers’ jobs. The compiler finished and preserved its 590,573,904-byte compiled artifact. Its measured peak physical footprint was 5.1 GiB. At the start of containment the system reported about 3.0 GiB of swap in use. A later repo capacity sample reported normal pressure, 4,841 MB available and zero swap-out. These are observations from different times, and peak values from different processes cannot be added to reconstruct the pause.

The repo's tool runner formerly treated `rustup run TOOLCHAIN rustc` as a toolchain-management request. A mounted regression reproduced the missing admission. The tool runner now charges the delegated command's registered resource class, even when the caller passes `--light`. Delegated Cargo also receives the assigned job limit, with test-program arguments preserved. All 16 tool-runner tests passed, including Windows executable spelling and direct inspection. The ticket's native component launcher now passes Cargo through repo admission. Each pipeline originally limited itself to one job, which allowed all four to consume memory at once. Further Draw component work is scheduled through a single repo invocation.

The warden now counts the actual room for macOS swap growth above its disk reserve when calculating swap occupancy. The regression covers a disk at the reserve with 3,000 MB used and 1,500 MB still free inside swap. The old implementation ignored swap occupancy in this case. The repaired TypeScript policy agreed with its Python oracle. The warden and churn suites passed all 51 tests on the final combined run. An earlier run saw two suspension notifications in a timing-sensitive mounted test. That test passed in isolation and in the full rerun.

The largest measured Draw-owned production library archive was the roughly 315 MB store-preparation library. The member wire receiver now compiles as a separate package. Locked offline resolution passed in the Draw and hub workspaces. Serial metadata compilation measured roughly 220 MB RSS for the wire package and 197 MB for the facade. A final optimized link peak remains to be measured.

The guard applies to work entering the repo admission path. An independent OS process can still put the machine under pressure. Host protection requires both measured per-package peaks and admission for simultaneous jobs. Compiler-worker controls and remaining verification are tracked below.

A second warden regression used a 16 GiB host fixture with 2,701 MB available, 7,860 MB compressed, warning pressure and 478 MB/s of swap-out. The first warning holds new work. If the host remains under warning with substantial compression and active swap-out, the warden can now release an overdue suspended build. Suspension alone retains its memory. The fixture also checks that protected processes are untouched and that cancellation stops when swap-out stops. This scenario combines measured incident indicators to test the boundary and is not a reconstruction of a single operating-system sample.

A live lightweight rustup compiler version query waited behind existing reservations, acquired the separate 512 MB inspection grant, and exited successfully. Build invocations use the compiler budget. The separation avoids reserving several gigabytes merely to print the compiler version.

The final warden run passed all 52 tests, including the continuing-warning case checked against Python. The tool runner passed all 16 tests with 126 assertions. The isolated Wasmtime cold build succeeded, but its final native image assembly still required a 5.1 GiB peak on this host. A code-generation or link peak for the newly split Draw packages has yet to be collected. The evidence establishes improved admission and a smaller compilation boundary, not an end-to-end minimum RAM requirement.

## Cold compilation and native execution

The compiler scheduler now gives a fallback Rust compilation one frontend thread when its grant is absent or zero. Previously the authored nightly flag `-Z threads=0` asked for every host core. Nightly component finals also run the LLVM backend serially when their crate type is supplied in a response file. A stable compiler invoked without a grant receives no nightly flag. The real scheduler binary passed the argument corpus against a stand-in compiler, including a response-file final, and the independent Python oracle passed (49 assertions in these two tests).

Wasmtime now serializes cold compilation across processes sharing the cache and checks available host memory before reading the complete component and again before invoking the compiler. Existing caches stay usable while cold work is deferred. An unknown or insufficient memory budget defers work. The current estimate is 256 MiB plus 48 bytes per input byte, in addition to the desktop reserve. Five native checks passed on macOS and the independent Python oracle passed all 12 cases. Linux and Windows live counter behavior is still unverified. See [native guest evidence](guest.md).

The published 137 MiB Draw component was deserialized from its native cache, instantiated under the production pool limits, and returned reactor protocol version 25 through its Wasm interface. Peak runtime RSS was 526,467,072 bytes. The small harness used trap stubs for host imports that this particular call does not use. This is a warm-cache execution measurement. The extensive interactive checks ran on the published browser component.

The managed replacement-component build subsequently encountered a changing shared DEFLATE source. Its compiler saw a literal template marker where a numeric match-chain constant was required. The current source contains a number. A fresh single repo-scheduled attempt was started after the failed run exited. No concurrent fallback pipeline was started.

During the replacement build retry, the live host reported warning pressure and a 358.5 MB/s swap-out sample during project-graph planning, before Draw compilation. The warden reported danger at that sample. I cancelled the Draw invocation. The subsequent sample reported normal pressure, 7,146 MB available and no active capacity grants. Other workspace services and the operating system's filesystem event service continued to run. This recurrence demonstrates why a package split alone cannot establish that every whole-machine pause is prevented.

## Nested compiler limit

The previous component driver log recorded five local jobs on the ten-core host. A deterministic planner regression reproduced a separate limit propagation defect: the nested planner admitted five local compile units with SEMIO_COMPILER_PARALLELISM=1. The explicit positive limit is now included in the work demand seen by the nested planner, along with any narrower task demand. The targeted mounted run passed three tests and 70 assertions, including five explicit-limit fixtures. A single replacement component invocation was admitted with a 3,072 MB reservation.

The actual component driver's descriptor-emitter Cargo build then reported one of ten local cores planned and one granted, after its planning subprocess reported CARGO_BUILD_JOBS=1. The Draw playground continued serving HTTP 200 during the build.

The live fleet status showed 13 connected workers and the scheduler's admission query returned 82 idle slots. Even remote Cargo jobs run a local wrapper for input shipment and waiting. The Cargo and component launchers now also charge those wrappers against the local reservation, preserving the host and desktop limits. The full fleet-planning suite passed all four tests and 16,329 assertions against the independent Python planner and Ajv. The native guest scenarios and release vectors also passed their descriptor, Ajv and SQLite checks after the package split.

## Optimized native package measurements

Both split libraries compiled through a single admitted compiler on macOS arm64 at optimization level 2 and a single LLVM codegen unit. Maximum RSS was 2,525,609,984 bytes for the wire reader and 658,685,952 bytes for the facade. Their archives were 274,924,448 and 13,061,032 bytes. Inspecting their Mach-O sections found 239,735,984 and 10,366,432 bytes of embedded LLVM bitcode respectively. The repository’s captured prototype Cargo invocation disables embedded bitcode. These direct measurements are for the stated codegen configuration. The host briefly entered warning pressure and recovered while the compiler ran.

A mounted exact-reservation probe exposed a second propagation gap: an explicit 384 MB reservation was classified entirely as fixed orchestration overhead, so the nested planner saw no reservation and proposed 22 remote wrappers. Exact command reservation now retains its full minimum and charges that memory to the single child job. The same live probe subsequently waited for admission, received 384 MB and proposed zero remote wrappers. The fresh, inherited and refusal regressions passed all 38 assertions.

The full capacity command suite subsequently passed all 19 tests with 184 assertions. The Draw entry point resolves both test packages directly from the declared hub workspace. Its project configuration passed Ajv validation including the guest dependency used for cache invalidation. The managed descriptor emitter rebuilt and published its 15,451,016-byte binary under its owned artifact receipt.

At the same optimization level, the second run disabled embedded bitcode and requested 16 LLVM codegen units with a serial backend. The wire reader took 215.88 seconds, reached 1,452,032,000 bytes maximum RSS and produced a 137,054,800-byte archive. The facade took 16.28 seconds, reached 636,403,712 bytes maximum RSS and produced a 6,070,928-byte archive. Both finished under one 3,072 MB reservation.
