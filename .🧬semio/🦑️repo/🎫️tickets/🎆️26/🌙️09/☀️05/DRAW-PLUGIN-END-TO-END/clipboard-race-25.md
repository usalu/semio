# Clipboard Timing Reproduction

The unchanged English browser journey through fcc8 was run with route-only clipboard timing observations. `keytrace25e` failed waiting for two layers after paste; it saw one. The copy and paste key events targeted `drawing.play.composite`. Paste was queued while copy was pending. Copy's immediate invoke/action effects were empty; the later refresh carried `clipboard-write`, two `send-message` effects and `typed-operation-terminal-seen`. Completion operation 1152 reported no requested effects and copy settled `applied` (input sequence 17); the queued paste then entered with no retained fragment. Only afterward did the host log `apply clipboard true`. Paste operation 1216 had no requested effects; the report recorded no notice, no reported errors, and empty focused element at failure. This ordering demonstrates a window where the queue can release paste before the separately delivered clipboard write is installed.

Attempts A, B and D reached paste and cut successfully; A and B used keyboard queue tracing, D used the extended effects trace. In D, copy also settled before `apply clipboard true`, but that application happened before paste read the fragment. They were intentionally stopped after cut, so their process exit 1 is not a test failure. Attempt C was cancelled while Chromium launched. Browser instrumentation can perturb scheduling; the failed run directly observes the race but is not an uninstrumented acceptance result.

Source review: Draw's clipboard job builds its fragment and pushes `Effect::ClipboardWrite` into `workspace.effects`, then `publish()` moves those effects into `Emit` and completes the request cell. Mounted typed-operation publication drains effects to the instance-wide `typed_effect_outbox` before enqueueing the operation's terminal witness. The reactor turn takes at most one global effect and one completion witness into separate output effects and frames. The effect has no operation token; concurrent operations and different drain turns do not provide reliable adjacent-frame association or same-response delivery. Producer order alone does not guarantee the host has applied the effect before it settles a separately processed completion.

After the scoped clipboard receiver change, a focused uninstrumented browser probe completed four immediate copy→paste→cut rounds in one session, exit 0, with no page/console errors. Extended journey trace G passed copy/paste/cut: copy operation 1152 applied, paste queued while copy was pending and entered with fragment present, paste operation 1217 applied, and cut operation 1280 applied. Its later browser close was an intentional fast-stop, not a full journey result. The old asynchronous `apply clipboard` trace did not fire in this run, consistent with the new scoped route but not independently proving where delivery occurred. Extended trace F failed earlier during blank-example switch with `original window authority is stale`, before copy; live HMR/source changes could confound that result.
