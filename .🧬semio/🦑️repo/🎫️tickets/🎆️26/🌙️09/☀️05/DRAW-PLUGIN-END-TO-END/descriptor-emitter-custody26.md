# Descriptor emitter custody and Cargo input replay

The normal Draw component CLI has no digest-selected emitter input. Its `component` command accepts exactly `--manifest <Cargo.toml>`, and `runRepositoryComponentDriverV1` calls `ensureFreshDescriptorEmitterV1` unless the build plan owns the emitter build or the internal caller already holds the emitter. The published product request selects the original invocation’s mode and the local platform. The prerequisite validates the published bundle against current authored inputs and Cargo configuration before reusing it. If the publisher’s workspace manifest or resolver lock differs byte-for-byte, the freshness check can compare the supported semantic projection against the retained original bytes. The fresh attestation entry point `produceFreshComponentV1` first calls the managed emitter build and then supplies `emitterHeld: true` under an actual reader.

## Input coverage and replay

The normal Cargo unit cache stores dependency paths and content digests for matching a build against actual inputs. Its holder keeps `outputs.*.sha256`, `stdout` and `stderr`. `restoreUnitV1` writes compiler outputs into the destination lane and re-anchors compiler messages. This cache supplies no source-byte ownership or full Cargo workspace tree.

The separate completed-compilation packet does retain the real bytes of every observed file row. In the installed emitter packet, all 4,052 path mappings resolve to 4,025 distinct present blobs. The index maps both the original root manifest and the admitted resolver lock bytes. Its roster also records 6,618 missing paths. The 3,457 file rows marked `current` all have evidence blobs. The flag describes validation policy and does not imply omitted bytes. The 595 `retained` file rows generally represent generated data and outputs. The in-flight `CargoSourceWitnessV1` bank can feed the completed packet’s copies if an observed checksum confirms the selected version.

The completed packet is a coherent, finite compiler-read roster. It does not contain a general filesystem snapshot. It omits intermediate compiler libraries from the byte roster and binds the origin workspace, Cargo home and build directories. The Hub provenance reader reads `current` rows through the workspace’s physical owner, with separately verified Cargo configuration handling. The generic TypeScript command closure reader and offload inputs serve their own declared execution stages. I found no registered CLI or API that remounts a packet or joins per-unit cache entries into a Cargo build-owner input tree while keeping the normal Draw attestation authority. Inspecting the observed bytes is possible in the existing workspace under reader custody. Treating those bytes as the inputs of a new authorized Cargo build would require a supported snapshot-owning build path.
