## Timestamped warden action evidence

Correction to the earlier timing limitation: the human-readable warden.log lines omit timestamps, but the existing cross-platform warden loop appends structured JSON lines to alarms.jsonl under hostWardenDirectoryV1() (host-capacity directory/warden). The platform-resolved local directory here is /Users/ueli/Library/Caches/semio/host-capacity/warden. Each schema-backed action row carries atMs (Unix epoch milliseconds), pid, kind, action, observed (false means enforce), reason, host sample and original English/German message. The stream is bounded at 1 MiB and keeps its newest half when trimmed; it is durable across warden restarts but is not indefinite history. The state file holds only the latest bounded alarms and is replaced each tick. The same loop writes these rows on macOS, Linux and Windows; host sampling and signaling remain platform-specific.

Existing rows establish that at 02:42:22.308 UTC the warden suspended slice-worker 27562 with 5996 MB measured, host swap-out 266.8 MB/s and compressed-memory trigger; it resumed at 02:42:29.639 with 5999 MB and 15.56 MB/s. The independent critical 261.67 MB/s host sample at 02:42:25.557 lies between those actions. Local-unit 40153 was suspended 02:42:09.385 and resumed 02:42:17.133; local-unit 40822 was suspended 02:42:40.347. These observations correlate events but do not establish one process caused host-wide swap. The retained stream includes action messages, not general warden start/stop lifecycle timestamps; process start time and the untimestamped source-change log bound the restart.

To inspect, resolve hostWardenDirectoryV1 from the repo warden loop, read alarms.jsonl as newline-delimited JSON, filter atMs and convert it with new Date(atMs).toISOString(). This is a read-only diagnostic; no warden code change, restart or signal was needed.
