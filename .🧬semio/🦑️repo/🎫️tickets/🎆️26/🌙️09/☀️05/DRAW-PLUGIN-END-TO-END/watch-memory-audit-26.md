# Watch and replica memory audit

Scope: bounded source inspection on 2026-11-26; no process signals or load tests. The reported host snapshot has system `fseventsd` around 2.5 GiB RSS after 12 days and the replica supervisor around 650 MiB. These observations do not establish that either is responsible for the other or identify a leak.

- Root `.gitignore` excludes `🗑️generated`, `.cache`, `node_modules`, `target*`, logs and build state; fixture exceptions and ticket plan exceptions are deliberate. The fleet README states that this file defines sharing, and `🚧️boundary/🟦️.ts:123-163` compiles the rules with ancestor checks. This is application-level filtering, not an operating-system event exclusion.
- `🔁️replica/🟦️.ts:3046-3053` registers one recursive watch on the entire worktree and applies ignores only inside the callback. Consequently ignored build/cache/ticket-output writes can still be observed by the underlying OS watcher before their callbacks are discarded. The code alone does not quantify the event volume or explain the system daemon RSS.
- The callback passes `false` as `isDirectory` to the ignore matcher. An event naming an ignored directory itself can therefore pass a directory-only pattern (e.g. `**/.nx/`); a descendant is still rejected via ancestor checks. This can unnecessarily mark the path dirty, update the hot set, and wake the loop. It does not demonstrate replication of ignored contents or an unbounded memory leak.

Recommended follow-up: reproduce the directory event with a small isolated fixture and assert that directory-only excluded paths do not wake the replica, while deletions and renames of shared paths are preserved. Change event classification or handle ambiguous names conservatively; validate on macOS, Linux and Windows. Separately sample event rates and memory over time before and after reducing actual generated writes or using a watcher with supported subtree exclusions; avoid claiming that ignore rules alone reduce `fseventsd` memory. Do not disable the volume event journal or restart system services based on this evidence.


## Directory event correction

A real temporary directory fixture first reproduced the original false result for the exact directory-only pattern. The watch callback now uses the same ignore matcher but consults lstat only for a directory-only candidate. It suppresses the event only if the current path is a real directory and no previous local or manifest entry exists at that exact path. Missing, inaccessible, symlink and ordinary file paths stay dirty; a previously tracked file replaced with an ignored directory stays dirty, as does a directory replaced by an ordinary file. Existing file/ancestor ignore behavior is unchanged. Races after lstat depend on subsequent events and the existing periodic scans; this test does not establish the OS event stream or fseventsd causation.

The isolated owner fixture passed one test with 11 assertions: actual directory/file/missing transitions, tracked replacement and shared directory, a schema validated with Ajv and independent ignore-library decisions. The pre-fix classifier failed the ignored-directory case. No watch service or OS process was signaled or restarted.

## Native subscription options

Further bounded source inspection: the reported increase from about 2.6 to 3.7 GB over 17 minutes while Draw was queued is a useful correlation, not an attribution of system-wide `fseventsd` memory to this watcher. The callback correction above does not alter its recursive OS subscription.

The existing separate `semio-repo-watch` backend (`📚️library/🏗️build/🏡️resident/🔭️watch/🦀️rust/🦀️.rs`) already accepts rooted `--exclude` and name filters. On macOS it passes the first eight rooted excludes to `FSEventStreamSetExclusionPaths` (lines 563, 670-676, 798-812), although the return value is currently not checked; it is not established from source that exclusion succeeded on this machine. Linux skips excluded directories when registering inotify recursively (lines 908-926). Windows uses recursive `ReadDirectoryChangesW` on the whole root and filters after delivery (lines 1085, 1121), so its existing filter is not an OS subscription exclusion. This watcher serves graph/journal consumers with their own protocol and exclusion policy; it is not a drop-in replacement for replica events without an adapter and validation of readiness, loss, restart and path semantics.

A narrow candidate is to integrate that backend through the existing replica watcher interface with a rooted `.cache` exclusion on macOS and Linux, retaining the root subscription for top-level changes and retaining the replica callback, hints and sweeps. Check exclusion acceptance and surface a degraded state on failure; never claim a reduction merely from requesting it. The eight-path macOS limit, exclusion path existence/recreation and changed ignore rules require explicit handling. A fixed `.cache` exclusion is valid only while its entire subtree is local under the actual compiled ignore and manifest rules; do not derive broad excludes naively from basename patterns or suppress fixture and ticket exceptions. The root `.git` is not wholly local: `🚧️boundary/🟦️.ts:238-260` explicitly shares HEAD, packed-refs, refs and objects, and the daemon also observes `.git/index` for its view. Excluding all `.git` would sacrifice prompt detection of those changes; targeted exclusion of provably private subtrees or additional subscriptions and the index hot scan require separate proof.

For Windows, achieving OS-level avoidance would need a root nonrecursive watch plus recursively watched eligible immediate children, with dynamic add/remove and catch-up after root events. The same partition is an alternative on all platforms, but introduces registration races, rename/replacement handling, missing filenames and many watch handles; subscriptions must become ready before a catch-up scan and any overflow/error must trigger a loss/full scan. The existing hot-set and periodic directory sweeps (`shared-worktree/README.md:206-217`) provide eventual independent discovery, not proof of the advertised near-one-second detection during a gap. Add real platform integration tests for top-level creates/deletes and rename into/out of excluded roots, `.git` shared exceptions and index, ignore changes, watcher loss and ignored build churn before adopting either design. No production watcher was changed in this audit.

## Daemon memory during the admission wait

While Draw was waiting for admission, six native macOS top and ps samples from 2026-11-26T03:10:28.250632+00:00 through 2026-11-26T03:11:46.829266+00:00 observed fseventsd (PID 99). top MEM ranged from 5275M to 5288M and CMPRS from 1744M to 3660M. The concurrent ps RSS ranged from 1,668,240 to 3,668,544 KiB. RSS alone missed a large compressed component and varied considerably over these samples. No Draw compiler was running. These observations establish a substantial independent consumer during recovery. They neither establish the daemon’s footprint during the original Codex interruption nor attribute its footprint to a particular FSEvents subscriber. The daemon and the system journal were left running.
