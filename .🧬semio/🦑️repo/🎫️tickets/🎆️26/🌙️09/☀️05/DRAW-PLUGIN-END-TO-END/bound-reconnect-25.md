# Bound Saved-Folder Reconnect

The first standalone copy of `journey-r39-de` was not equivalent to a same-session reconnect: attaching it in a fresh session appended 1,098 bytes for a new document identity. Its original 4,734 bytes were an exact prefix of the resulting 5,832 bytes; the original and working bootstrap databases shared SHA-256 `901e1d871b90accb570431b80e97aba662a5542a724c52863926e233b3316454`. The one-layer display in that attempt is not evidence that the original saved document failed to replay. Its long poll was cancelled after this identity difference was established.

The second probe copied `journey-canonical25-en/document` (8,307 event bytes), used the public `commitLocalFoldersConfigMutationV1` with the canonical saved document ID `01a21454-66e2-7da6-9e99-b6e3f5316b90`, Draw editor app and copied path, reloaded, and clicked the real reconnect offer. Against the served fcc8 prototype, the 20-second sample displayed one layer while document loading reported 33,397 of 33,407. At 30 seconds it displayed two layers with no visible load line, but the console reported: `a folder read-back could not be restored … typed-operation pending publication rejected a stale immutable document root`. The no-errors assertion failed, so this is not a clean pass. This was an independently seeded saved-device binding and separate browser context, not a replacement for the full same-session journey. The probe and screenshots are retained under the ticket and generated storage.

A repeat on a fresh copy of the same canonical archive instrumented only the served `replaceAttachedDocumentV1` module by wrapping its load and bind calls, with no assertion or result changes. It logged `load begin`, loading 0 of 1 at 20 seconds, `load success`, `bind begin`, `bind success`, then two layers by the 30-second sample; the event file remained 8,307 bytes and no page/console errors occurred. Exit 0. This confirms the earlier stale-root rejection is intermittent; this successful run cannot identify its failing call or stack. The probe's route wraps both callback boundaries and prints any thrown error and stack on a future reproduction.

After the host router change, a fresh navigation and reload repeated the bound canonical archive with route-only logging for `TypedOperationRouter.fault` (call label, token, current owner and stack) and load/bind boundaries. At 10–50 seconds it showed one layer and loading 237 of 238; then load and bind both succeeded, and at 60 seconds two layers appeared. The event archive stayed 8,307 bytes, the probe exited 0 with no page or console errors, and no typed fault was observed. This run cannot provide a failing token or prove absence of the earlier intermittent race. Vite served live source; no intentional source changes occurred during this probe, but its instrumentation is a browser route overlay.
