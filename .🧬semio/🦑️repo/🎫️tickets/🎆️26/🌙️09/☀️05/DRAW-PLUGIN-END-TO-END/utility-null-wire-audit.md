# Utility Null Wire Audit

The React store retains an explicit null for a cleared window. `buildActiveUtilityByWindowId` copies it; `guestActiveUtilityByWindowIdV1` filters and renames ownership without dropping it; `parseResolvedPluginViewState` validates nested null; and `windowViewContext` deliberately clears the flat utility on addressing a window. The schema admits string or null and the window-action-panel test verifies that an explicit clear survives these projections and suppresses a stale flat utility.

Rust `ViewModel.active_utility_by_window_id` is currently `OrderedMap<String>`, so the actual JSON null is incompatible. Removing null entries at the wire is not semantically equivalent: Draw `drawing_active_utility` falls from a missing addressed entry to a focused window entry, then to the flat utility. A cleared addressed window could therefore inherit another focused window’s tool. A nullable map preserving key presence, such as `OrderedMap<Option<String>>`, supports all three states; consumers must distinguish a present null from an absent key and suppress fallback for the former. An arbitrary string sentinel conflicts with the existing wire contract. Test serialization, window projection, addressed-clear versus differently focused active window, flat fallback, and spawned-window remapping.
