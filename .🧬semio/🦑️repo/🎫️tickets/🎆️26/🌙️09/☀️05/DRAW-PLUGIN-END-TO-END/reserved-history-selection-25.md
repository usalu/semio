# Reserved History Selection

The reproduced paste, undo and stale selection sequence reaches the framework reserved history route. `dispatch_framework_reserved_action` creates a reserved commit for undo and redo; `commit_framework_history_route` dispatches the document history command. Its completion path never invokes `revalidate_interaction_on_document_change`. Mounted typed publication does call that hook after its artifact publication.

`run_framework_reserved_commit_unit` resumes the commit permit's original identity receipt with its cancellation observer and work lender, advances the history unit and follows derivable children, then pauses the receipt. That is the natural original-authority location for a document-generation-sensitive revalidation. The hook may persist interaction state and returns a fault. Because the document can already have changed before that call, replaying a whole failed history unit would risk repeating undo. A robust change needs a retained revalidation frontier and pending result so the committed mutation is never redispatched, plus undo/redo and exact-grant coverage. The evidence does not justify silently clearing all selection or minting new authority.

The failing fixture does not record whether the history step deferred. A final local paste ordinarily qualifies for the synchronous exact-tail fast path, but that remains an inference until instrumented. Interior steps can instead defer: `step_reprojection_turn` adopts the document on successful completion and checks generation before queuing `BaseMoved`, without interaction revalidation. It receives an identity authority but stores only the action in `deferred_history_row`, not the original action metadata. Delayed successful adoption needs its own authority-preserving revalidation frontier; cancelled and refused replays do not commit.

The subsequent `history-real-env26.log` refusal is `native encoding ownership exceeds caller limit`, emitted by `NativeEncodeControl::charge`. The new revalidation persists a changed selection using `interaction_store.dispatch(ApplyInLane)` with the same reserved permit identity. `FrameworkReservedCommitPermit::new` sets its cumulative encoder ceiling from the reserved tool proof's `max_output_bytes`; undo and redo's declared `framework_reserved_job!` contracts each set that output maximum to 1,024 bytes. The new interaction write adds encoding to the same cumulative identity ledger. A correction must authorize the total at the original admission or issue an independently admitted interaction authoring receipt, with measured limits and test coverage; silently resetting the ledger is not authority.
