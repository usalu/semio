# Runtime Close Prior Outcome

The diagnostic Window debit run reached close poll 3119 and then reported `prior-outcome` at epoch 6563. Its last return settled ten Work units without a retained-memory delta. The probe paused the guest and therefore also affected its monotonic callback measurements.

In `⚛️reactor/🏃️runtime/📦️instances/🔁️cleanup-turns/🦀️.rs`, the close pump checks out the worker outcome and collects the retained step receipt before it can inspect either original continuation or semantic outcome. The continuation exposes the callback, context qualification, and receipt qualification as borrowed original failures. The current diagnostics select the first available primary failure. The normal fault view exposes borrowed detail pages, and the existing first-page copy is compiled only in tests. Both branches set the pump's faulted flag. The terminal branch closes and releases the session before publishing the generic `PriorOutcome` status.

`RuntimeCloseCleanupJob::advance_source` in the cleanup-pumps module propagates an original failure from result-page retirement, mounted maintenance drain, maintenance session close, surface context close, or mounted app close through `CleanupTurn::OriginalFailure`. The outcome driver turns that into a callback continuation. Explicit closure faults and worker-generated faults instead appear as semantic fault views.

An independent source path can account for a debugger-only result. `NativeWorkerAuthorityState::drive_original_caller` marks the worker terminal following four consecutive interactive overruns or an invalid callback clock. The next worker turn publishes the fixed detail `job-session.terminal-fault` as a normal fault view. Recording `callback_verdict()` and `overrun_ledger()` alongside the checked-out view would distinguish this result from an actual cleanup callback failure. The normal view and continuation must be inspected before the pump retires their original owners.

The preview2 runtime reads `SEMIO_RUNTIME_DIAGNOSTICS=1` through its WASI environment. The no-pause staged run used that switch and captured the actual callback continuation before session retirement. The continuation is a value invariant failure from the mounted authority check, with one item and four copied bytes and zero allocation or release. The worker-generated fault path was absent.

The narrow binary injection only covers a selected result branch and is insufficient as a model of the full Window source fix. These were read-only runtime investigations.
