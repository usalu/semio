# Blank Drawing switch stalls ~30-37 s (Draw journey, step after "boot"), 2026-11-26

Status: reproduced and narrowed to one guest wait; the lease holder is NOT yet identified and NO source fix was made (see "Why no fix").

## Reproduction (probe, no journey needed)
- Probe: `probe-blank-switch.mjs` (ticket folder) = the journey's setup (context, viewport, worker wrapper, boot waits, panel opens, treeitem click, `note("boot")`) up to the Blank pick, then `waitLayers(0)`; on a stall it keeps polling and records when the stall ends. Env: `PANELS=artifact,select,inspection,catalogue,artifact2` (default all), `NONOTE=1`, `PROBE_DIAG=1`. Needs `PLAYWRIGHT_BROWSERS_PATH=<repo>/.🧬semio/🦑️repo/⚡️cache/tools/ms-playwright`. Drivers: `blank-switch-matrix.sh`, `blank-switch-until-stall.sh`.
- The stall is NOT deterministic in the probe: roughly 1 run in 3 stalls. The journey fails every time because the journey does extra work (`waitPainted` screenshots, engagement toggling, `note("boot")`) that lengthens the pre-switch window.
- Pre-step matrix (3-4 runs each, `NONOTE=1`): no panels 4/4 pass (5-6 s); Artifact panel only 4/4 pass; Artifact+select 3/3 pass; Artifact+Catalogue 2/3 pass, 1 stall; full journey sequence with `note("boot")` stalls 3 of 4. So the Catalogue panel and the extra pre-switch time raise the odds, but no single pre-step is necessary.
- A stalled switch ENDS BY ITSELF after 31-37 s from the click (also 26-30 s after `RetiringCommittedStore` starts): a 60 s wait always settled to 0 layers (33.4, 32.3, 34.4, 37.2, 36.1, 35.6 s from the pick). Probe nudges (mouse over canvas, screenshot, engagement toggle, panel switches, resize) did not shorten it. The journey's 30 s `waitLayers` deadline sits right on this distribution, hence "never commits within 30 s".

## What the guest does during the stall (guest diagnostics, `u-a-1` log kept in `🗑️generated/stall-evidence/`)
- Replacement op: `Initializing` ~4.5 s (admission-zero spin, same as in passing runs), then `RetiringCommittedStore` with `store_close=ReturnedReads/started=false/active=false leases_empty=false` for 26-30 s, then `RuntimeOwners(3)` -> `Complete` within 0.2 s. So the new store is committed, the UI keeps showing the displaced Demo until the displaced store is fully retired, and the only gate is `snapshot_read_leases_await_return()` (the doc comment in `store-owners-retained-reads-and-retirements`: "Blocked is permanent for the closer ... only the holder can release").
- The SAME wait exists at boot in EVERY run, passing or not: the initial-store -> Demo replacement (`op=128`) sits in `ReturnedReads` for 34-40 s (journey log: boot step finishes only after ~40-50 s). Passing Blank switches just do not have an outstanding reader at that moment.
- Guest CPU profile during a stall (CDP Profiler on the plugin worker, 6 s): 76 % idle, remaining time spread over tiny wasm functions and jco async-task plumbing. The guest is not computing; its turns are ~300 ms `more-work` turns that cheaply re-poll the wait (`reading=` counter +18k/s).
- Host/worker traffic during the stall (message trace kept as `stall-host-worker-messages-u-d-2.json`): only periodic empty `turn`s and `wire` acks; no `startJob`/`stepJob`/`cancelJob` after the pick's own `framework.reserved.tool` jobs and the typed-operation result pages (ops 576, 768, 832 ...) are fully acknowledged (every page has its ack). So the holder is not a running host job and not an unacknowledged typed-operation page.
- Draw's mounted geometry job (`semio.draw.mounted-vector`) is NOT running at the pick in the stalled runs (the boot job stepped 2420 times at ~0.1 ms/step with ~15.6 ms gaps and ended `failed`; the second job ended `done` 3-4 s before the pick). Its snapshot read is returned only after its private plan/cleanup retires (`DocumentVectorRetirement::take_snapshot_read` requires `private_is_empty()`), which is the one in-guest holder with a lifetime of this order; but it is unproven (see below).

## Ruled out
- Playwright-only behaviour: stall also happens without `waitPainted`, without engagement toggling and without the worker `addInitScript` wrapper (probe has the wrapper only for tracing).
- Pointer hover / canvas gestures: nudging the pointer does not release it.
- Host poll cadence / host CPU: guest 76 % idle, host trace quiet.
- Local interaction live queries: no TS consumer sends `LocalInteractionQuery` (only tests do).

## Not proven (needs one rebuild with a named-holder diagnostic)
The component carries no holder naming and wasm function names are stripped (no `name` section), so the holder cannot be named from outside. Candidates still open, all consistent with a 26-40 s lifetime and a fully acknowledged host: (1) the Draw scene `State` cleanup chain (`DocumentVectorRetirement` private owners retiring element-wise before the source read returns; `🧬️schema/🎬️scene/🧵️mounted/🦀️.rs` `State::close_step`), (2) a retained app-owned operation/tool-run read (`MountedTypedCommandFullOperation.request_snapshot_read`, `ToolRunMemberFolded.read`), (3) an instance-root `original_read`. The ladder (`🪜️maintenance-ladder`) closes mounted jobs while a replacement is open (stage 15 `mounted_job_close_step`), so a plain "job not cancelled" is unlikely.

## Why no fix
The root-cause owner was not identified, and guessing a fix in the guest without the holder name would risk masking the symptom (for example, completing the replacement before the displaced store retires would change the retirement-order invariants documented in `store-owners-retained-reads-and-retirements`). The coordinator said not to rebuild the component, so the needed diagnostic could not be run.

## Suggested single rebuild (diagnostic only, ~10 lines, all `[DEBUG]`)
In `store-owners-retained-reads-and-retirements/🦀️.rs` add to the `RetiringCommittedStore` wait line (`maintenance-ladder` `document_load_diagnostic`, `roots=[...]` is already requested there) `outstanding_snapshot_read_count()` plus, per registry slot, an owner tag recorded when the lease is issued (add a `&'static str` call-site tag to `StoreOwners::snapshot_read` callers: render projections, typed-command, command-routes/actions, job completion, Draw scene `reconcile`). One stalled run then names the holder; the fix follows from that (most likely: return the source read at `transfer()`/`begin_close()` independent of the private plan retirement, or cancel the holder when a replacement commits).

## Update (follow-up): static search, candidate fix, build blocked
- Static search: no lease expiry, heartbeat or staleness exists in the snapshot-read registry (`🌱️value/📸️snapshot/👁️read`, `🏪️store/🔗️read`); a lease is released only by its holder (`return_to_registry`). The ~30 s release is therefore holder-driven, not a timer; the host trace shows no host involvement.
- Holder candidate with the code evidence: `State::close_step` in `🧬️schema/🎬️scene/🧵️mounted/🦀️.rs` returned the Demo store's source read LAST, after `DocumentVectorRetirement` had drained every private owner element by element (`take_snapshot_read` refused while `!private_is_empty()`), and the replacement's `ReturnedReads` gate waits on exactly that return. Draining the Demo plan is paced by maintenance turns (~270 ms guest turns, guest 76 % idle), which matches the 26-40 s.
- Fix applied (source, unverified at runtime): `DocumentVectorRetirement::take_snapshot_read` (`🧬️schema/🎬️scene/📋️prepare/🦀️.rs`) no longer waits for the private owners, and `State::close_step` (mounted `🦀️.rs`) now retires the taken read FIRST (new first two branches: `returned`, then early take from `cleanup`), then drains the private owners. The owners never dereference the source while draining, so returning the lease earlier is safe; the lease no longer depends on the plan size.
- Diagnostic rebuild attempted (holder dump per scene shell, stage-15 trace, `outstanding`/`returned` counts in the replacement wait line): 4 rounds x 8 attempts of `component-retry-26.sh` (now retries `Native build failed`/`Command failed: cargo`), wrapper `component-wait-26.sh`, from 22:07 to 00:55, all failed: repeated host-warden SIGTERM (exit 143, swap 5+ GiB), a peer's mid-edit `E0425`s (`JOB_PAYLOAD_PROCESS_OWNED_BYTES`, `OriginalCancelRootIdentity`), a peer resizing the persistent native image (`Exact canonical persistent Native publication required`, fixed.dmg 36 -> 32 GiB), and `deferred-source-digest-mismatch` restarts. No component was produced, so the fix is NOT proven by the probe matrix. All `[DEBUG]` tags were removed again; the loop is stopped.
- To verify after the coordinator's rebuild: `PLAYWRIGHT_BROWSERS_PATH=... sh blank-switch-matrix.sh fix "artifact,select,inspection,catalogue,artifact2" 0 8` (stall rate was ~1/3-1/2; expect 8/8 `OK blank` in ~6 s and the boot step well under 40 s).
