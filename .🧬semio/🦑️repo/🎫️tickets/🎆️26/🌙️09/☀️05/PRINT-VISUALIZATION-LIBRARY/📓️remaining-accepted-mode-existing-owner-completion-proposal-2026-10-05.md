## Explicit pair-weight alternative for overlap network

If choosing a conventional set-node overlap network rather than the lossless incidence representation above, define weight(i,j) as the sum of each intersection record's size whose membership contains both distinct sets i,j. The existing membership matrix marks included and excluded sets per record, so exact membership combination semantics must be declared. A triple A+B+C/s contributes s once to each AB/AC/BC pair; this is a stated inclusive pair projection, not three separately authored measurements. Do not simply ignore triples or count duplicate member tokens twice. D3 group/rollup can independently produce the full pair edge map from the authored records, then D3 path/node positions can verify actual PDF edges and weight-derived widths. Include a nondegenerate triple-only fixture and a mixture of pair+triple records, ensuring all3 expected edges and exact additive weights. Set IDs remain open; unknown membership IDs and repeated tokens within a membership record require diagnostics. The pair projection intentionally loses higher-order distinction; retain the underlying intersection records and do not claim hypergraph visualization. Both conventions are proposals; Root/Native selects and documents one before TDD.
