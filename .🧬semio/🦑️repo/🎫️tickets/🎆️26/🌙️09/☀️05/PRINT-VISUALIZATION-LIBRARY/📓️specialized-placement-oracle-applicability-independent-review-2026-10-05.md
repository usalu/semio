# Specialized Placement Oracle Applicability Review — 2026-10-05

Read-only source review of the placement proposal; no compiler or behavior test executed here.

The proposed explicit applicability boundaries are necessary. Biofabric order=layout should obtain a permutation from the selected actual existing layout, then keep fabric rows/columns discrete. A force coordinate change that preserves the sorted permutation legitimately preserves the fabric picture; fixture selection must prove a permutation-changing example. DataStructure tree modes can use parent-child placements, while container modes have specialized geometry. CommitGraph default lineage must retain time and merge meaning; alternate layouts need an explicit reading contract and caption/edge identity checks.

Native network.sty944–963 initializes the RNG, phyllotaxis, optionally authored initial-table x/y, then ticks. The public family call routes currently do not bind initial-table; authored SemioVizLayout does through2088. Seed randomizes zero-displacement jiggles, not the deterministic phyllotaxis start. Changing seed on an ordinary family graph need not change its coordinates. Do not inject coincident internal positions into a family test. A seed-sensitive fixture must use a documented public authored initial-position route, with the same data consumed by actual D3 force; otherwise document seed as conditional solver control and prove reproducibility rather than promise universal visible differences. A separately tested SemioVizLayout initial-position feature does not prove that Biofabric forwards that feature.

Root control is radial/BFS-specific: independent graph library traversal can produce rooted hop distances; compare normalized rings and bound IDs, and assert the selected root lies at the center. Sweeps applies to layered ordering, not layer assignment. Use a graph whose crossing order changes between sweep counts; compare the actual resulting permutation and endpoint routing. Do not require arbitrary differences on an already ordered graph.

Existing network-layered-twin adapter28–77 reuses the native adapter oracle and executes vizLayeredLayout. Its scenarios distinguish ranks-agree-with-dagre, slack-ranks-as-soon-as-possible and barycenter-ordering. Dagre's full solver coordinates are not universally the same contract as this longest-path/barycenter algorithm. For a suitably selected nondegenerate graph, independent Dagre can corroborate exact rank/permutation output after declared normalization; for other graphs compare agreed graph properties without claiming exact coordinate equivalence. A hand-written clone of the same barycenter algorithm is useful for a neutral specification but alone does not satisfy the third-party output requirement. Preserve the existing scenario-specific oracle applicability, inspect its exact graph/normalization, and extend an actual external solver comparison only where the outputs truly agree.

For all placements, a coordinate equality oracle plus actual PDF row/node/edge ownership is stronger than mode presence or a changed caption hash. Graph relations, isolated nodes and explicit ordering tie rules need independent assertions. Diagnostics for inapplicable parameters must be schema-first and match TS/Rust/native. Do not delete accepted controls simply to remove a failed-effect test.
