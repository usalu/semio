## Semantic Breadth Requirement

Nontext presence alone does not certify mathematical/chart semantics, per-kind uniqueness or customization. Record within-family normalized geometry digests and join them to the authoritative `family + options` dispatch. Unexpected identical geometry for declared geometry-changing variants is a finding requiring a schema-first semantic fixture and actual native repair. Explicitly label-only variants can legitimately share geometry; that classification requires source evidence, not a global allowlist or inference from a digest. Global uniqueness across families is not a valid assertion because different named visualizations can intentionally share primitives.

The family feature inventory must therefore bind each kind to its existing numerical/semantic adapter and the independently verified features that adapter exercises. Every declared meaningful customization requires an actual source-owned numerical/painter test, with a third-party oracle where one exists, or independently authored expected primitive semantics. The existing focused/native gates can transfer only exact unchanged source and authored contracts. Unnamed adapters and generic fallbacks cannot gain mathematical correctness solely from the new all-kind painted-presence census. Any remaining per-kind/feature gap stays explicit and blocks universal completion.
