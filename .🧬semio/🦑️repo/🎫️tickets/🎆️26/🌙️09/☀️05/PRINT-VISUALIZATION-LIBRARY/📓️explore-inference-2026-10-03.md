## Current Print Architecture

`🧰️framework/🛍️products/📓️print` presently owns a TypeScript package and LaTeX packages, without a Rust crate or registered artifact definition. Its `🧬️schema` describes the catalog, not an authored chart snapshot with mutation, diff, and inference families. No print mutation/inference family exists in the inspected source inventory.

`🔨️modules/📊️viz-kernel/🧬️schema/🟦️.ts` already declares scales, coordinate systems, layouts, marks, encodings, layers, and guides. `🔨️modules/📊️viz-kernel/🖼️render/🟦️.ts:62` resolves just bar, point, line, area, arc, text, and rule marks. The current resolver ignores layer transform and layout declarations; fill/stroke/opacity/size encodings are mostly ignored. Coordinate projection is used for the arc centre but not the usual point/line/bar data. Guide handling ignores the guide kind and treats top like bottom and right like left. Unknown guide scales silently disappear. Empty area rows dereference nonexistent endpoints. Title, localization, guide formatting and offsets, clipping, and most customization are absent. The TikZ text emitter inserts raw text and ignores text fill, and line dash is not emitted. These are concrete source findings, not runtime claims.

## Canonical Generic Mechanism

The native generic inference semantics are `Inference<P>` in `🧰️framework/🛍️products/💻️os/🔨️modules/📡️spr/🎮️command/🦀️.rs:33`. It requires a cloneable/default serializable inference, with `fn infer(snapshot: &P) -> Self`. Its explicit laws are purity, determinism, and totality: computation failures must appear as result data rather than panic or `Result`. `InferenceSpec<P>` at line 99 adds schema identity, schema version, and inferred-field read sets. This is the mechanism to implement for a chart snapshot; placing free functions in an inference-named folder alone does not provide runtime registration.

`ArtifactInferrer` in `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:1447` connects the snapshot to its inference and supplies `infer` plus asynchronous `infer_cached`. Plain whole-snapshot inference may use the default passthrough. Dependency-aware per-layer/per-table inference can implement `InferredField<P>` at `💡️inference/🦀️.rs:89` with a deterministic plan, read-set, dependency-input bytes, and pure per-entity compute. Its cache must remain observationally equal to ordinary inference.

`ArtifactInferenceServiceMetadata` at plugin line 1472 carries owner, artifact kind/schema, inference schema, versions, and optional payload input/output schema, progress-unit and document/commit bindings. `ArtifactDeclaration::inference_services` at line 3188 installs executable services; registry APIs at lines 1705–1736 validate/register/list them. Plugin builder `🏗️builder/🦀️.rs:313` also offers `routed_inference` for `semio.infer/<schema>` cold-job metadata, explicitly without creating a synchronous service facade. That routed mechanism is appropriate when expensive layout/projection tasks need cancellable jobs; the chart algorithm belongs to its owned inference, not to a new standalone rendering engine.

The worked example is `✏️s/🔌️plugins/🏛️architect/🗿️artifacts/🏛️program/🏅️standards/🔖️1/🪆️subsets/✳️any/🧬️schema/💡️inferences/🦀️.rs:43–111`: `ProgramInference` implements `Inference<ProgramSnapshot>`, `InferenceSpec`, `ArtifactInferrer`, and exposes an `ArtifactInferenceDescriptor` with Rust, TypeScript, GraphQL, JSON Schema and protobuf facet leaves. Named computations are children such as `🧭topology`. The family root assembles them; artifact mounting occurs through its `🦀️.rs` assembly, not separate engine files.

Canonical mutation semantics live in `🧰️framework/🔨️modules/📡️replication/🎮️mutation/🦀️.rs:174`: each `Mutation<P>` has descriptors, `diff(base) -> MutationOutcome<Diff>`, `inverse(base)`, conflict target and state class. `MutationDiff<P>` at line 103 applies and structurally absorbs diffs. `DiffAlgebra<P>` handles inverse/between/emptiness. `🧰️framework/🛍️products/💻️os/🔨️modules/🌿️vcs/🦀️.rs:1699` supplies generic `apply_mutation`, which gets the outcome, applies its diff and returns messages. Rejections must use mutation outcomes and no-op rejected diffs. Chart authoring should follow this vocabulary for changing options, adding/removing layers, binding tables, and changing encodings; derived scenes/TikZ remain read-side inference results.

## Ownership and Integration Constraint

Print can author schema families directly as product-owned source, but existing repo discovery will not auto-register them: `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🧬️schema/💡️inference/🔍️family-discovery/🟦️.ts:45` only walks `✏️s`. Native registration requires an artifact definition/declaration/plugin mounting seam. No reusable TypeScript equivalent of the Rust generic `Inference` runtime was found. Existing OS TypeScript mutation functions are owner-specific twins, while actual plugin mutation/inference execution routes through Rust/WASM/native protocol boundaries.

Recommended canonical path: define a print chart snapshot, diff, semantic mutations, and named scene/TikZ inferences schema-first under the same owned artifact; register inference descriptors and executable services through the existing artifact declaration. Reuse already-owned math via inference implementations rather than creating an independent engine. A TypeScript twin must use the same authored contracts and demonstrate equivalence; document explicitly if native registration is not yet implemented.
