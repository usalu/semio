# Original Bake Owner Migration

The new `RasterStackPreparationWork` implementation and neutral tests are authored under IO composite-and-media/prepare and mounted beside the existing cold source. Its allocation-free header captures original snapshot and requested slice identities. Granted DFS discovers that slice inside the current snapshot without dereferencing stored addresses; conversion then visits one node or string page per turn. Image references use the fixed resident asset census and paged key comparison. Each raw image allocation, copy page, Arc backing and vector handoff uses the actual caller grant through RetainedWorkLedger. Source revision, inherited protection, depth thirty-two, node count 1024 and resident asset count sixty-four remain explicit guards. Cancellation retains private owners until its funded close cursor empties.

The neutral test uses an actual OriginalJobFixtureCaller, denies zero grants, checks exact copied RGBA and image/layer identities, and closes every cancellation cut under the original source. The new owner is exported as RasterStackPreparationWork while live bake/export callers are being migrated. Existing RasterStackPreparation and STACK_STOCK are still present and have not been claimed as removed.

The new LayerBakeOwner and LayerBakeWork wrapper are now mounted on flatten and merge. They author these phases:

1. Bounded merge target discovery and source-range selection, then the new editable preparation owner.
2. Actual caller-granted RasterStackJob ledger turns, preserving independent CPU and physical receipts.
3. `into_retirement` raw output handoff and funded private stack retirement, never `into_result`'s fabricated close grants.
4. Funded Semio image metadata/frame ownership, RasterImagePayload birth and paged canonical decoded-image hashing. The raw pixel Vec moves unchanged; there is no PNG encode/decode roundtrip.
5. Bounded document reference census, exact existing-destination comparison, resource-capacity validation and one-event-at-a-time retained mutation construction.
6. Funded cancellation/closure for preparation, stack, raw image, payload and unpublished mutations.

The old EncodedPngImage publish/baked_layer helpers and PNG encoding phase were removed from both command modules. Flatten unit laws now drive the genuine original owner; merge laws are being migrated to the same shared fixture driver while preserving rendered pixels, source origins, surrounding siblings, asset sharing, full-capacity behavior and inverse history. The private owner performs selected-tree protection validation before image materialization, so protected descendants still refuse before publication even when an asset is unavailable.

A model identity writer now shares the existing namespace/counter and writes the unchanged three-word identity into preallocated backing. raster_id_bytes returns prefix UTF-8 bytes plus forty-nine; write_raster_id refuses occupied or insufficient backing before consuming a new identity. Its neutral fixture and actual original-caller tests check fifty-four layer-ID bytes, Unicode prefixes, stable output pointers and an independent standard hexadecimal formatter.

The cold compositor has live callers outside LayerBakeWork: ImageExportWork, app assembly, read-only viewer rendering and five serializer interfaces whose current `serialize_bytes(&Snapshot)` signature has no original caller authority. Removing STACK_STOCK from those paths requires genuine retained IO/window integration, not a synthetic source in a wrapper. These are concrete pending callers and must be resolved before broad completion.

Reserved import remains another pending owner: it currently decodes base64 and PNG synchronously and must receive a bounded codec preparation, canonical raw identity and funded payload root before publication. No new unchecked conversion has been introduced.

No compilation or runtime pass is claimed. After environment restoration, a model --tests Cargo check was started through the actual MCP repo gate as react_selection (functions cell g22:264); its exact handle remains active, and no terminal result has yet been received. Concurrent source edits mean any eventual result must be matched to its actual captured source before claiming current validation.
