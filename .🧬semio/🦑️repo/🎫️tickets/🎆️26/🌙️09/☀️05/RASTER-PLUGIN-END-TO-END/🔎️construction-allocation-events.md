# Construction Allocation Events

Shared and Arc receiving retain a typed preborn allocation in `NativeSharedAdmission<T>`. The allocation turn quotes the original event and work recipients before the physical effect; a separate allocation-free turn publishes the original input. The caller retains the birth and callback frame across refusals, with funded release for an unpublished birth. Value shared-root, intrinsic-field and persistent-list owners, DSL persistent receiving, Plugin completion birth and the view-root source retain typed admission slots. Callback resolution requires the same original construction recipient.

The original work refusal is independent in `OriginalReceivingPrimary`, the Job Rust and TypeScript projections, and the IO failure schema and codec. The Job receiving fixture and SQLite transport oracle include that independent field; its focused TypeScript suite passed 11 tests. A refused allocation quote cancels the unused work reservation. The separate SQLite event oracle passed one Bun test with four assertions, and the focused IO codec suite passed seven tests with 45 assertions. Native original-caller laws are authored but have not been run; native checks are owned by the root lane. Rustfmt parsed the construction source.

The old post-effect `record_constructed_allocation` and `receive_retained_work` definitions have meanwhile been removed in concurrent work; `admit_vec` and `admit_string` now expose before-effect backing admission. Numerous callers still invoke the removed methods and need caller-owned frames and before-effect admission at their actual allocators; fabricating a late quote would be incorrect. Their consumers include generated owned-schema receivers, Value record/list/map/field/value receivers, Pack native input and Job receiving owners. Job `OriginalNativeDecodeSource::with_control` supplies an authentic unreserved `NativeDecodeWorkRecipient` for self-metered receiving and its `receive_step` posts the observed work once; older callers and tests still need that route or another genuine loan. The separate prepared transaction exposes a narrower control without the receiving/event authorities and cannot nest another work reservation. The focused new laws supply a loan, but the larger migration and native validation remain open. No overall construction-seam completion is claimed.

Concurrent work introduced an issuer-bound work loan that can rebind the same reservation across continuation and reject a foreign issuer. The receiving frame now guards work settlement, transfers retained child work once even when allocation remains `EffectStarted`, and exposes typed admission resumption after callback resolution. An original-caller shared post-interruption law and a separate once-only work law are authored; native verification remains outstanding. The neutral SQLite oracle now checks five assertions, including total reported recovery work. Job is integrating the retained issuer and checks pending work before closing its forwarded receipt.

The typed turn also accepts its same retained `Granted` phase after an interrupted work quote is resolved, without reissuing the original grant or work quote. Six receiving owners permit this phase; a native original-caller law is authored. `NativeForwardedDecodeFrame::begin` keeps the caller receipt across normal return and unwind, captures raw cumulative state and identities without fallible detachment, and restores an existing receipt if rebinding fails. Job integrated the frame and its unwind accounting. A distinct `OriginalJobDecodeOwner` used by Plugin `with_native_receiving` still needs funded persistent work issuer admission; that migration is in the runtime lane.

Local retirement decoder continuations now rebind pending issuer-owned work and prevent recipient release for pending quotes or zero-sized reservations. One identity question remains: typed shared admission checks the original construction/work issuers and physical demand, but it does not yet authenticate replacement of same-shaped caller input/output slots during a suspended grant.

`NativeSharedSlots<T,R>` now joins input, output and admission in one movable owner and provides funded capture, take and owned close. Its schema-first relocation and replacement fixture has an Ajv/SQLite oracle (one test, eight assertions), and an original-caller native law is authored. Existing production shared receivers still use separate slots, so this new owner is not yet the canonical path. The defining `NativeReceiver::close_step` is currently migrating to `OriginalRetirementOutcome` so owned close failures can survive this integration: the shared-root receiver, intrinsic shared field and persistent-list close are migrated, but many implementations and product consumers remain. This migration is not ready for broad native checks.

Receiving now has an independent owned `retirement_failure` cause so a rich close failure can survive a receiving advance. A matching neutral fixture and native ownership law were added; the SQLite/Ajv oracle checks nine assertions. Rust struct literals were updated. Value/Job TypeScript, its schema and SQLite transport oracle now preserve `retirementFailure` together with `workRefusal`; the Job suite passed 11 tests. Rust Job borrowed projection and IO recursive codec/schema transport are being migrated by the root lane. Native default cursor close contracts and several Value implementations are also mid-migration. No completion of these seams is claimed.
