# Base64 Original Work and Effects Audit

Current source closure census for semio-framework-io-base64 is 18,718 bytes, 3 files and 330 active lines against unchanged 32,768 bytes, 4 files and 1,024 active lines. The actual reader was cross-checked with file stat sizes; this is not compiler admission. Base64 has no runtime dependencies. The companion test manifest at framework/🔨️modules/🚪️io/🔤️base64/🧪️tests/🥣️companion/📦️packages/🦀️rust/Cargo.toml declares third-party base64 0.22.1 and serde_json 1.0.140 as dev dependencies plus first-party trace and requested-allocation witness.

A minimal codec-owned meter can expose reset-per-call numeric actual work, bytes appended and newly retained output capacity, with an outcome on both success and error. Count actual visited input and padding scan work according to a documented unit; next_work_demand remains a conservative admission quote, not a receipt. Count only visited prefix if invalid padding or a quartet short-circuits; do not report unvisited suffix. Aggregate each admitted transition when step spans multiple transitions with checked arithmetic. On successful reserve, report actual Vec capacity; allocation failure reports no retained allocation. A checkpoint refusal immediately before decode allocation leaves none, while cancellation at a later decoded chunk occurs after output append and offset movement and must report those effects and work even though the result is Err. A repeated call after the stored refusal must report zero new work/effects. The original OwnedText or OwnedBytes input pointer stays unchanged through cursor and into_parts.

Output take and into_parts transfer ownership headers without their own grant or retained receipt. The original wrapper must quote each move, hold the partial output and input until admitted, and retire both through funded original close after denial or cancellation. Existing companion tests at 🧪️tests/🔬️unit/🦀️.rs already verify source pointer preservation, cancellation after 4096 input bytes with a 3072-byte prefix and full retained capacity, no allocation/release on into_parts, and differential codec outputs against base64 0.22.1. Extend those tests with per-turn numeric effects, malformed quartet positions, callbacks before and after allocation and independent work/copy/capacity denial; compare actual allocator events with the receipt. No production edits or native builds were performed.
