## Current Raster Costs

At 16 MP, the current clipped flood owner can retain these new buffers simultaneously: 64 MiB normalized source, 64 MiB result, 16 MiB new flood coverage, 16 MiB original clip coverage, 16 MiB visited flags and 64 MiB queue: 240 MiB before preserved auxiliary image content and smaller owners. These allocations and their eventual contiguous releases remain explicitly quoted. A callback with insufficient capacity/release returns private pending work; helpers do not invent a larger grant.

The generic stdio image schema has no frame-count, metadata-count or ICC-size limit. Raster source admission currently validates the first frame's extent and field-size limits; it does not yet establish a finite cumulative auxiliary budget. A valid domain policy must sum actual preserved profile, extra-frame and metadata capacities under bounded descriptor work, compare them against an explicit budget lent by the actual source, and refuse oversized work before allocating/copying it. The generic Semio image contract should remain unbounded.

All six pixel schemas now declare a bounded maximum of four inverse rows. This accepts actual zero, one, two, three or four inverse rows: `store/⚙️engine/🧱️store-components/📥️lifted/🏪️store/📬️store-owners-batch-fold-and-history/🦀️.rs:67` rejects only `inverse.len()+1 > footprint.work_items`; final commit in `store/⚙️engine/🧳️bundle/🦀️.rs:251` likewise rejects only a greater total. The adjacent exact authority checks concern actor, clock, identity and forward-row count, not equality with the inverse upper bound.
