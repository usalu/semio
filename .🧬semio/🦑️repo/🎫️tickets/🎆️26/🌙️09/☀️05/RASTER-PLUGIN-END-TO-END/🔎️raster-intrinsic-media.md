# Raster Intrinsic Media Ownership

Raster image:in is declared in editor/🔌️app-assembly/🦀️.rs:53-65 as TwoD/Raster, optional Many; it does not declare a concrete wire representation or intrinsic value schema. Framework MediaPayload is Structured { schema:String, json:String }, Binary { format_kind:String, blob_hash:String }, or Intrinsic { schema:String, value:DslValue } in framework/🔨️modules/🛂️manifest/🎞️media/🦀️.rs:331-335. DslValue in framework/🔨️modules/🌱️value/🌳️intrinsic/🦀️.rs:113-120 has String(String), Bytes, Object and other variants; as_str borrows only String.

For an explicitly defined intrinsic base64-string contract, borrow request.input as mutable, match MediaPayload::Intrinsic and DslValue::String, validate port, media type and declared schema, quote the actual fixed source/cursor header and work, then move the String with std::mem::take into base64_codec::Base64Input::OwnedText and Base64DecodeCursor. The schema remains in the original request; denied admission preserves the original string pointer. Non-string values must remain owned and be refused or handled by their genuine typed schema, not serialized to JSON. Original caller-funded cursor/output handoff and retirement are still required.

Existing shooting photos and framework vector-to-raster conversion actually emit Structured schema 2d.image with raw base64 PNG in json; see shooting editor/🧰️ui-helpers-and-io/🦀️.rs:190-193 and framework OS run/🎞️media/🦀️.rs:205-210. The port declaration alone does not prove any Intrinsic value has that shape. Tests should distinguish these payload forms, preserve pointer on denial and validate exact schema and malformed/non-string refusal. No native build or production edits were performed.
