## Mounted PNG and archive capacity

The mounted plugin turn issues 64 items, 32,768 copy bytes, 16,777,216 capacity bytes, 1,048,576 release bytes, and depth 4,096. Raster’s structured picker accepts up to 3,144,704 PNG file bytes and the shell streams base64 in 32 KiB command chunks. Those checks constrain the encoded file. A valid transparent RGBA PNG of 2,049 × 2,049 constructed independently with Python `zlib` is 16,392 file bytes and requires 16,793,604 output capacity bytes on the decoder’s first contiguous allocation. The previous branch yielded every time. The bounded output source and its close path remain resident when the decode turn now reports `OwnershipLimit` for an allocation above `StepContext::original_turn_ceiling()`. A smaller current loan still yields. The same fixed-capacity check in the export job uses the current `ImageExportWork::demands()` quote before entering the original effect.

The codec-side decode condition is `4 × width × height ≤ 16,777,216`. For export, the exact stored PNG capacity is `q + 5 × ceil(q / 4096) + 63`, where `q = (4 × width + 1) × height`. The largest square satisfying both codec conditions is 2,046 × 2,046. It yields a 16,767,018-byte PNG. A 2,047 × 2,047 source still fits decoded RGBA and quotes 16,783,411 export bytes. The 32 MiB segmented base64 queue can carry up to 25,165,824 raw bytes before any media metadata credit. Each export page is independently fueled. Current codecs reserve a complete contiguous `Vec<u8>` for decoded RGBA or stored PNG and transfer it to the next owner. The existing segmented sink follows PNG encoding, so changing its page size cannot split either reservation.

Archive capacity is a separate total. `VcsArtifactApp::document_archive` calls `print_document_pack` for the genesis pack and authoritative `.spr` history, then appends the live recursive member envelopes. `history_op_payloads` records `OpBinary` payloads for committed forward and inverse operations. Raster `AddLayerAsset` includes a compact `RasterMutationOctets(RecordBytes)` for every frame; the history carries RGBA bytes independently of the picker PNG size. `encode_document_archive_bytes` caps all framed bytes at 4,194,304. The separate cold-pair ingress also caps its combined pack and SPR bytes at 4,194,304. A `1024 × 1024` imported frame alone consumes the archive budget in RGBA before framing. A `1023 × 1023` frame leaves at most 8,188 bytes for all other history and archive data. There is no unconditional dimension limit that makes arbitrary edit history fit. Apply the existing serialized-byte limit to the complete archive when assessing a particular workflow. The 2,046 square bound describes codec feasibility for one in-bounds output, and the queue, compositing footprint, edit publication, and archive can impose tighter document-dependent bounds.
