# Original Export Custody

Export source now uses the original-granted `RasterCompositeWork`, followed by `PngEncodeWork`, bounded base64 pages, and an original queue append. The previous runtime use of cold stack preparation, `advance_stack`, compositor `into_result`, and cold `PngEncodeJob` has been removed from this route.

The new Rust PNG work follows the existing TypeScript encoder's stored-DEFLATE policy. Its constructor retains the supplied raster without allocating. Original grants admit the exact PNG candidate capacity, fixed header, bounded scanline pages, CRC and Adler bytes, output transfer and private retirement. The neutral corpus includes 2×1 raw RGBA and a 513×3 block boundary. Rust laws decode with the independent png library and exercise grant-axis denial and cancellation. They are authored, not executed.

`ArtifactOutputChunks::push_original` receives a mutable page slot and published witness. It validates the actual admitted fixed queue and byte ceiling before taking the page; all refusals keep its address unchanged. Queue custody and counters are installed before receipt settlement. `seal_original` seals under the initiating grant. Existing `original_birth_admit` supplies the queue backing. New laws use a genuine original caller for neutral denial, sealed/empty/oversized/total-capacity refusal, pointer-preserving transfer, idempotence and receipt refusal after queue custody.

`ArtifactToolCompletion::complete_download_original` similarly retains a mutable download slot until the real completion receiver can accept it. The destination owns the download before the original receipt can refuse. Export's neutral download law checks denial axes and receipt refusal with unchanged filename and queue identities.

The live export owner keeps partial PNG storage, encoded bytes, base64 pages, queue output, metadata and terminal results until funded close. Progress JSON reuses original-funded backing in a separate step. Metadata strings receive their own original capacity/copy loans, and structured media or download carriers are installed before their transfer receipt. The existing async export/history/cancellation/UI laws remain; standalone raw-RGBA and stage cancellation fixtures now use genuine original work and retirement.

The factory now implements the actual first-party `ToolJobFactory::admission_demands/admit_job` interface. The old payload-consuming create methods are no longer in that trait. The new mutable boxed transfer validates the exact typed owner's operation, wire bound and absence of checkpoint, then installs the job before receipt settlement. It uses the already authoritative typed ExportPng request and retains raw wire for physical close; there is no second cold command decode.

Download construction now retains the entire original request, including its command, snapshot_read, context, configuration and other lanes. Snapshot and completion read aliases are explicitly quoted; the request input is moved into the job's original-context wire close lane. The full request closes after local aliases. Request metadata also uses a quoted `RetainedCloneClose` rather than the old unquoted ControlledRetirement constructor. Generic private retirement helper outcomes now preserve their actual child work receipts.

Root removed the obsolete private request-wire retirement adapter and now defers actual RetainedToolWireInput owners directly. The full download request can therefore reuse that shared carrier without fabricating a context.
