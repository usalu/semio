### Persisted Mask Follow-Up Audit

No mask schema edits have been made yet. Current mask metadata has enabled/linked/invert and optional width/height only, so it cannot hold an editable mask. The planned domain representation is an optional image asset key plus a mask transform, with grayscale luminance multiplied by alpha supplying coverage. A mask with no asset represents a constant reveal/hide mask. Linked transforms follow the layer; unlinked transforms are relative to the layer's parent. This needs schema/fixtures first, then typed implementations, semantic mutations, editor controls and actual surface rendering; it must not be implemented as a painted white overlay.

The schema has JSON, TypeScript, GraphQL and protobuf representations. Rust `RasterLayerMask` lives in the artifact root. Three native fixture constructors and `RasterLayerCloneAuthority::mask` explicitly construct it. Adding an owned asset-key string also requires updating bounded retirement fields, layer bounds accounting and retained clone phases in mutations/binary, not merely adding a field or unbounded clone. `RasterRetirementAuthority::layer_fields` currently owns four strings; layer preflight phase4 accounts for pixel image_key/adjustment_kind, and layer clone phase3 copies them. Mask key accounting must be added consistently to all these paths and asset-reference validation/pruning. The existing remove-layer-asset diff only checks asset existence. No mask implementation should bypass those ownership rules.
