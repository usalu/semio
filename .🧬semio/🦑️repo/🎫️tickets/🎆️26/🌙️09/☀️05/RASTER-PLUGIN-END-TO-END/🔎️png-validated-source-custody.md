# PNG Validated Source Custody

PngDecodeJob at 🧰️framework/🔨️modules/🔲️pixels/📷️png/📥️decode/🦀️.rs publicly exposes mutable source Vec<u8> and phase &'static str, despite doc-hidden annotations. Therefore its source() slice is not a stable CRC-validated certificate: a holder can mutate or replace source after chunk validation, and can set phase to complete without decoding. Checking a completed phase while these fields remain public is insufficient.

A safe no-clone design keeps source and phase private and places the metadata cursor inside the decoder or a private wrapper owning the decoder and cursor. A metadata advance method reads the owned source through an ephemeral borrow each turn, gated on real completed validation; the cursor stores offsets and owned partial output, not a reference into its own container. This avoids self-referential lifetimes and prevents caller substitution of another completed job between turns. Controlled close must retain both cursor and decoder until their separately admitted retirement completes. The existing RetainedCloneSource provides an immutable sealed owned authority and funded projection leases when independent sharing is necessary, at the cost of its real admission and retirement; pointer-and-length alone cannot establish immutable source identity.

Pixel and Raster source inspection found production decoder consumers using methods rather than direct PNG source-field access. Its child unit module directly reads decoder.source.capacity(); child module privacy permits that after privatization. An attempted repository-wide heuristic scan was interrupted and is not a complete external API census; two additional files referenced PngDecodeJob and source or phase, which requires individual resolution before a general API change. No compiler test was run.

Controls subsequently made mutable decoder fields private.
