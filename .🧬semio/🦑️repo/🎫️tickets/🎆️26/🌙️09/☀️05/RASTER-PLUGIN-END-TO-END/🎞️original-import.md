# Original Reserved Import

The current reserved builder accepts its request by value and has no original context. Its caller creates metadata and clones the media before constructing the job. The media consumption path also creates a fresh NativeDecodeControl. These are separate gaps from the now original-granted export path.

The existing prepare_media_import phase runs before decoding and retains the actual original producer permit. It is the appropriate place to admit persistent request/body/shared-producer receiving slots. Incoming Media and MediaArtifact must remain in actual mutable source slots whenever admission is denied. No local grant loop, replacement issuer or assumed fixed-capacity constructor is an acceptable substitute.

Schema-first work has started: the reserved request now carries an OriginalToolSourceBinding and an optional input receiving slot. A shared thirteen-lane RetireOwned carrier retains request metadata, snapshots, exact snapshot_read, configuration, history, children, raw wire, input and completion; shared snapshot/config/history aliases use the existing OriginalRequestLease. The neutral corpus describes source binding, denial custody and external-alias closure.

A canonical ArtifactReservedRequestJob and ArtifactReservedWork interface have been authored. The job retains the complete request while bounded work borrows it, verifies the original source, and closes work before the request. The admission helper stores its concrete candidate before posting its original allocation/copy receipt. Runtime hooks, all lifts and concrete domain work still need migration; no working end-to-end import is claimed.

Reusable codecs already exist: BinarySourceJob and PngDecodeJob accept original grants. They previously discarded earlier same-turn allocations when a later parse step failed. Both now expose last_turn_progress and last_turn_work, reset on every call including cached refusals. PNG range/history allocation failures preserve the allocator's actual partial allocation receipt. Binary source capacity receipts use actual retained backing rather than the requested amount.

Neutral native laws have been authored against a genuine OriginalJobFixtureCaller. Independent png output is corrupted at IEND so a multi-item failing decode turn must still report its prior range allocation; actual heap observations are compared against the carried receipt. Invalid base64 fixtures are also refused by the independent base64 library, and cached failures must report no repeated work or resources. These tests have not run. Pinned Rustfmt parsed both changed codec production files and the new law source; this is syntax evidence only.

The old PNG-to-Semio import preserves original colorspace, bit depth and text_chunks metadata, with ICC absent. A raw RGBA-only replacement would change that behavior. Header projection and bounded ancillary text decoding remain necessary unless a deliberate replacement semantic policy is selected. The general BinarySourceJob data-URL header parser also has a preexisting bounded-header read accounting issue; the Raster import grammar is raw unprefixed base64 and must not route through that branch.
