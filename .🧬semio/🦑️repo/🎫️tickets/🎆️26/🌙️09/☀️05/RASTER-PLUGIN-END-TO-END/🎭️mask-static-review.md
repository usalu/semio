# Static Review of Retained Mask Work

Reviewed the parent's `MaskSelectionWork` phases against real framework traits, the raw image schema, and the authored tests. No concrete Rust type or borrow blocker was identified in the inspected version: `validate_extent` returns a pixel count, the retained `Pending` variant exists, and the progress/grant interfaces match the surrounding owners. This is static evidence only, without compilation.

The four-event full-capacity plan is coherent: detach prior mask, remove its unique child, add the new image, attach the new mask. Its reserved row capacity is four `RasterMutation` items; each row separately quotes its newly copied strings. The reverse inverse order restores the old child before reattaching its mask and never requires a 65th child. The dedicated factory advertises the correct resumable artifact route, retains the 65,536-byte input ceiling, and uses the separate 268,443,648-byte output ceiling.

Concrete correctness finding sent to the parent: destination reuse checked only whether the generated key exists. Asset IDs can be chosen independently of content, so a wrong image stored under the canonical output key would be reused and attached. Added `an_existing_destination_must_own_the_canonical_mask_content` to the mask tests: it stores an opaque image under the transparent mask's expected key and requires bounded refusal without publication. The parent owns the production fix.

Resource findings sent to the parent: target discovery and freshness checks repeatedly call recursive full-tree `require_layer_edit`/`find_layer` outside the granted walker, while the dedicated admission branch does not enforce the previous generic tree extent. Binding a granted target path would make later target checks bounded. Validation conversion/overflow errors should retain any earlier span progress in their failure receipt. The parent is separately adding failure stickiness and source-frame checks. The parent clarified that `begin` intentionally returns the owned candidate alongside its actual receipt so the wrapper retains the allocation before receipt consumption can refuse; an error-only fits guard would lose that ownership, so that initial review suggestion was withdrawn.

The layer-cap follow-up found `RASTER_MAXIMUM_NESTED_DEPTH = 32` and nested byte/item totals of 262,144 in the host retirement-bounds crate. `RasterSnapshotBoundsAuthority` enforces these when its snapshot clone authority runs. However, the current Raster store catalog installs `ColdMutationApplyFactory::default()`. The framework cold factory stores optional domain bounds, and its default has none: preflight skips domain measurement and begin checks source size only when bounds exist. The Raster snapshot's root layers and group children remain ordinary vectors. Therefore these old census constants do not establish a cap for every resident snapshot under the active catalog, and they cannot justify an ungranted full-tree target search.

No production mask owner file was edited during this review. No compiler or runtime validation was performed.
