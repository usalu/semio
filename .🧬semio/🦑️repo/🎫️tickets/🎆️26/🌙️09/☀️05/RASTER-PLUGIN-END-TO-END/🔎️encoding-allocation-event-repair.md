# Native Encoding Allocation Event Repair

Fresh source after the native failure shows `🧰️framework/🔨️modules/🌱️value/🫴️receiving/🦀️.rs:8–30` now forwards translated parent Quote, Post and Cancel events; this macro may have been changed concurrently after the compiler snapshot. Both Encode and Decode parent event types currently use `Quote(request)`, `Post { request, actual }`, and `Cancel(request)`. A post represents real observed physical allocation, not a caller quote.

`value/🛫️encode/🦀️.rs:180` still sends the bare request to Event-typed forwarded and scoped ports. It is not correct to simply emit Post there: `charge` precedes fallible reserve and cannot know whether storage was allocated or what capacity actually resulted. The actual three-phase settlement implementation is `value/🛫️encode/🛂️allocation/🦀️.rs:23–27`: it quotes both authorities, runs the original allocation with an actual extent marker, posts that actual extent or cancels, and retains independent operation/extent/port refusals. Migrate physical storage creation sites such as `allocate_vec`, `copy_text`, and `append` to genuine actual-effect settlement. A locally scoped precharge may remain only where no event receiver is bound; do not fabricate a successful post for an unperformed effect.

Existing forwarded native tests `value/🛫️encode/🛂️allocation/🧪️tests/🦀️.rs:20–46` still type closures with bare `NativeEncodeAllocation`; update them to the event protocol. The actual simultaneous post-refusal and real backing witness is in the same file at line 100. This inspection did not compile or run tests.
