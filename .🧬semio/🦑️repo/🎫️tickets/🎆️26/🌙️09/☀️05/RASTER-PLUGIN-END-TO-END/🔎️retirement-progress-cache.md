# Retirement Progress Cache Design

`🧰️framework/🔨️modules/🌱️value/🎟️control/🧬️contract/♻️failure/🦀️.rs:21–23` recursively descends to the deepest child to read or update its selected ValueError progress. Job's new `⚠️failure/🫴️projection/🦀️.rs:15,26,33` emits retainedProgress for every node, so projecting all nodes repeatedly traverses suffixes and costs O(depth²); an unbounded recursive setter is also unquoted work.

Use a per-node cached selected progress: constructors select the child's cached value when a child exists, otherwise the first present local primary, work refusal or receipt refusal, otherwise zero. The getter reads the cached value in O(1). An explicit enclosing progress update should set a local override only, leaving every child and original ValueError receipt unchanged; this deliberately changes the current recursive setter, which overwrites the deepest original receipt. Keep base selection distinct from an explicit override (for example an optional override), so adding a later work refusal cannot silently discard an already admitted enclosing span. On adding work without an override, its progress becomes selected only if there is no child or primary; it outranks a prior receipt. Define tests for empty child, independent distinct receipts at multiple depths, local override, and later work attachment.

All direct struct literals are in the defining file: constructors `from_primary`, `from_work_refusal`, `from_primary_and_work`, `from_primary_and_receipt`, `from_causes`, `from_owned_parts`, plus `OriginalFailureStorage::attach_owned_parts` (which must read child cache before moving it into the prepaid box). `attach` delegates there; `with_work_refusal` mutates selection; `into_unsettled_primary` destructuring must account for the new fields. `into_parts` and controlled retirement continue returning/retiring the four original owners; cache is scalar. `OriginalFailureStorage::birth_bytes` uses size_of and therefore changes automatically, but independent finite-capacity fixtures and work/copy accounting must be updated and tested. No native build was run.

## Implemented Checkpoint

Each failure node now caches its selected original progress and independently stores an optional enclosing override. Reads and updates are O(1), child and original error receipts are never modified by an enclosing override, and later work supersedes a receipt only when there is no primary or child. Prepaid storage attachment selects the actual child span before transferring its box. Five-part decomposition and reconstruction preserve the explicit override; physical retirement discards only that Copy scalar after extracting the four actual owners.

The native snapshot failure transport and both closed schemas now carry a nullable per-node progressOverride. The Ajv and SQLite suite passes 4 tests / 16 assertions, including independently distinct nested override values. Native owner, transport, and broader callers are authored or migrated but have not been compiled or executed.
