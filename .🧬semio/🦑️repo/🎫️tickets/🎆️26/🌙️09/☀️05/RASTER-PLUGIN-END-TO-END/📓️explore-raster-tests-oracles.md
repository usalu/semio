## 1. Oracle registration and how a raster test id is formed/executed

- `✏️s/🔌️plugins/🖨️raster/🧪️oracle/🔣️.json` — the plugin-level oracle manifest. `oracles: []`, `noOracleDecisions: []`. Its `_comment` explains why: `s.raster.raster` is a semio-NATIVE document (a layered raster carried in `.dsl.semio`/`.pack.semio`), so no third party reads/writes the envelope, and every per-subset manifest records `noOracleDecision` for that. The ONE real entry is `oracleHostPackages: [{ implementation: "rust", package: "semio-s-plugin-stdio-test-oracle", path: "✏️s/🔌️plugins/🗄️stdio/🧪️oracle/📦️packages/🦀️rust" }]` — registered only because `oracleHostPackagesFor` walks up from the case owner to an ancestor manifest, and this plugin links that native host package (PNG/GIF/BMP/TIFF/JPEG reference codecs) for its `export/import` serializer leaves, not for the layered-document mutation case itself.
- `✏️s/🔌️plugins/🗄️stdio/🧪️oracle/🖼️raster/🦀️.rs` — the actual Rust reference-oracle code raster's IO leaves link. It wraps `png` (image-png) and `gif` (image-gif) crates directly, and `image` (image-rs) for BMP/TIFF/JPEG, behind an owned `RasterSpec`/`Json` interface (no third-party type escapes the module, per CLAUDE.md's "external libs behind an interface" rule). It also hand-rolls a GIF interlace-row-order/reorder/flag-recovery trio (`gif_interlace_row_order`, `gif_reorder_rows`, `gif_image_interlace_flags`) because `gif::Decoder` always de-interlaces and reports `Frame::interlaced == false` regardless of the source flag — documented at lines ~120-200 of that file, with 4 genuine `#[test]`s for that logic (`the_four_pass_order_matches_the_specification`, `reordering_rows_is_its_own_inverse`, `a_buffer_that_does_not_match_the_geometry_is_returned_untouched`, `interlace_flags_are_recovered_per_image_block`, `a_stream_that_is_not_a_gif_is_rejected_rather_than_guessed`). **This is a codec/file-format oracle, not Pillow** — Pillow is explicitly declined everywhere in this plugin (see §1b).
- **1b. The mutation-document oracle is a hand-written Python cross-language differential, NOT a codec/library-backed oracle.** `✏️s/🔌️plugins/🖨️raster/🗿️artifacts/🖨️raster/🏅️standards/🔖️1/🪆️subsets/✳️any/🧪️tests/🖨️mutate-raster-1/🐍️.py` is a second, independent implementation (in Python) of the `s.raster.raster` layered-document tree algebra and all twelve typed mutations, written from the committed mutation schema/grammar/vectors — it imports nothing from the repo's Rust. Its own docstring explains why no third-party lib was used: `png`/`image`/`tiff` read image FILES, and this artifact is a layer TREE over an id-keyed asset pool; Pillow reads pixel payloads and has no authority over a group's `children`, blend modes, or reordering across groups — registering one would be a category error. The file also documents a real specification defect it found (`…/🧬️schema/📸️snapshot/🔣️.json` is a verbatim, wrong-`$id` copy of `s.stdio.json`'s `JsonSnapshot` schema, so `RasterLayerNode` points at nothing) and reports it rather than working around it.
- The subset-level oracle registry `…/🏅️standards/🔖️1/🪆️subsets/✳️any/🔮️oracle/🔣️.json` registers this Python file as oracle id `raster-python-independent`, `kind: "verified-native-second-implementation"` (promoted 2026-09-02 per ticket `SEPARATE-ARTIFACT-STANDARD-SUBSET-IMPLEMENTATIONS-AND-FIXTURE-TEST-EVERY-MUTATION`, see its `📓️d1-native-oracle-discharge.md`), `fixtureCoverage: {vectors: 12, capabilitiesCovered: ["raster-1-mutate"]}` — i.e. it explicitly claims 100% coverage of the 12 mutation kinds via 12 committed fixture vectors, and is flagged as a required SUPPLEMENTAL oracle under "protocol v2", not a discharge of the external-oracle requirement (a qualifying third-party reference is still formally "owed" per the manifest's own text, even though the native-second-implementation promotion already counts it as sufficient — see §7 gap list).
- **Test-id formation.** `.feature` file `🧪️tests/🖨️mutate-raster-1/🥒️.feature` defines scenario outlines tagged `@capability-raster-1-mutate @oracle-raster-python-independent @comparison-ordered-json-v1 @mutations-raster-1-any`, with three `Scenario Outline`s (`@id-mutate`, `@id-inverse`, `@id-spec-vector`) each expanding over the 12 kinds, plus one plain `Scenario` (`@id-identity-round-trip`). The runner forms the full test id as `<ownerPath>::<caseDirName>`, e.g. `✏️s/🔌️plugins/🖨️raster/🗿️artifacts/🖨️raster/🏅️standards/🔖️1/🪆️subsets/✳️any::🖨️mutate-raster-1` (seen verbatim in the cached result's `testId` field), then hashes it into the cache/result directory name `test-s-plugins-raster-artifacts-raster-standards-1-subsets-any-800d3c-🖨️mutate-raster-1-oracle-python` (the `-oracle-python` suffix names the oracle engine that ran, `800d3c` is a short hash of the owner path). Individual sub-scenario ids inside one case (`mutate-<kind>`, `inverse-<kind>`, `spec-vector-<kind>`, `identity-round-trip`) become the per-row result filenames (`<id>.oracle.projection.json` / `.oracle.raw`) inside that case's result directory — 3×12+1 = 37 rows, matching what's on disk (see §2).
- `✏️s/🔌️plugins/🖨️raster/🗿️artifacts/🖨️raster/🏅️standards/🔖️1/🪆️subsets/✳️any/🧪️tests/🖨️mutate-raster-1/🦀️.rs` is the Rust SUBJECT-only adapter (feature-gated `#[cfg(feature = "sut")]`) that registers `mutate-<kind>`, `inverse-<kind>`, `spec-vector-<kind>` and `identity-round-trip` handlers calling `semio_s_plugin_raster::artifacts::raster::standards::v1::subsets::any::schema::mutations::{apply_raster_mutation_json, round_trip_raster_dsl, undo_raster_mutation_json}` and asserting `semio_s_plugin_stdio_test_oracle::law::*` (mutation-observability / inverse-restores / divergence / carrier-fixpoint laws) — it deliberately registers NO oracle role, "keeping oracle registrations here would put this repository's answer on both sides of the comparison."
- The repo test module lives at `🧰️framework/🛍️products/🦑️repo/🔨️modules/🧪️test/` with subdirs `🏃️runner`, `📇️registry`, `📡️protocol`, `📦️packages/{🐍️python,🐹️go,🔷️dotnet,🟦️typescript,🦀️rust}`, `🖥️host`, `🧬️schema`, `🧫️fixtures`, `🧪️tests/{🖥️host-protocol-parity,🧭️contribution-directory-ownership}`. (I did not deep-dive the runner's discovery/`fileKinds` source in this pass beyond confirming the id-formation contract above from the artifacts it actually wrote to cache — a follow-up could read `🏃️runner/🦀️.rs` or its TS/py counterpart directly for the literal discovery algorithm.)
