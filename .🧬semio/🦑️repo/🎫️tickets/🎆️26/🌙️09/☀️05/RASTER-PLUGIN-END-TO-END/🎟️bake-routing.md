# Dedicated Bake Command Admission

The dedicated Flatten Layers and Merge Down factories existed, but the app's shared command-work gate still recognized only the general retained factory's twenty-eight tool IDs. Both bake IDs were therefore rejected before their LayerBakeWork branch could run. The gate and extent selector now share one predicate that recognizes the actual general and bake lists; the separate export, selection and mask routes retain their existing admission branches.

Eight neutral route cases cover both bake IDs, two general IDs, three separately routed IDs and an unknown ID. A Rust law calls the exact shared predicate. The independent ECMAScript Set/Ajv expected-output oracle passed eight cases; syntax and native execution remain separate checks. This fixes route reachability, not the existing cold tree-flattening extent census or end-user bake acceptance.

The new fixture also passes its closed JSON schema. Both modified route/app source files and the Rust law parse successfully. The editor library receives serde_json only as a development dependency for the law; no runtime library dependency was introduced. The native route law has not executed.
