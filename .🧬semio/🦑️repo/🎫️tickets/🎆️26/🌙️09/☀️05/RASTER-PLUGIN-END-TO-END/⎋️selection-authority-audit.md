# Selection Cancellation Carrier Audit

The carrier schema declares exactly actor, app instance, window, operation ID, and generation. The instance is an unsigned 32-bit integer, actor/window are nonempty, and operation/generation are sixteen lowercase hexadecimal characters. Rust scene serde, value conversion, optional scene fields, lane splitting, and the TypeScript scene type carry the same camelCase fields. The carrier stays in the small scene spine while coverage travels separately.

The native renderer checks that the retained pointer target is live before offering cancellation: document, surface generation, component generation, key, kind, host, and surface must still match, with no pending document or host retirement. It then requires exact current actor, app instance, and window equality, validates both hexadecimal strings, and dispatches the framework `cancelTypedOperation` action through the scene controller. The runtime independently checks live operation, actor, app instance, generation, lease availability, and terminal status before signalling cancellation. The framework cancellation action is deliberately broader than one window so Tasks can address owned operations; the native scene offer supplies the window restriction for Escape.

Escape first tries the active local pixel selection gesture. If none is pending, the retained keyboard focus can offer the admitted operation's exact carrier. The Raster producer selects one non-cancelling `selectPixels` operation for the originating window and omits the carrier if multiple operations would make that choice ambiguous. Hex strings preserve full 64-bit values rather than passing them through JavaScript numbers.

The initial codec review found serde/value validation drift from the schema: derived readers accepted empty actor/window and malformed operation strings, and the value derive did not reject unknown or duplicate members. This was reported to the native selection owner, who authored stricter production readers and a strict manual value decoder. Added a separate neutral invalid fixture and matching serde/value tests for missing, unknown, duplicate, empty, out-of-range, fractional, and malformed identifier cases. The existing valid fixture remains unchanged. No production carrier source was edited by this audit.

Static searches found all Rust scene literal families already carrying the optional field; TypeScript's optional field does not require changes to existing literals. No runtime or compiler pass is claimed. The added neutral fixture and tests still require execution through the repository's admitted test interface.
