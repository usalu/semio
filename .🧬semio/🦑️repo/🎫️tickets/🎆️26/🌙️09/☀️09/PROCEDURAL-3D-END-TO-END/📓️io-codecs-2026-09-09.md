# 🚪️ generation3d IO — from seven silent placeholders to real codecs (2026-09-09)

Scope: `✏️s/🔌️plugins/🌀️procedural/🗿️artifacts/🧊️generation3d/🏅️standards/🔖️1/🪆️subsets/✳️any/🚪️io/**`,
plus this subset's `🧫️fixtures/🚪️io/`, `🧪️tests/🚪️io-procedural-3d-1/`, `🔮️oracle/🔣️.json` and the
crate's `📦️packages/🦀️rust/Cargo.toml`. `✏️editor/🦀️.rs`, the stdio boolean kernel and `👁️viewer`
were NOT touched — the export path CALLS `crate::editor::generation3d::export_mesh_from_document`
exactly as it stands.

Follows `📓️feature-inventory-2026-09-09.md` §7/§8.1 (the IO finding) and
`📓️kernel-and-preview-audit-2026-09-09.md` §1 (the stdio crate family).

## 1. What was actually wrong

Seven of the nine format leaves were not stubs — they were placeholders that **could not fail**.

- **Export**, byte-identical bodies in all seven of `las`/`png`/`stl`/`dwg`/`obj`/`gltf`/`ply`:
  `Ok(<Generation3dSnapshot as store::ArtifactDsl>::print_dsl(snapshot).into_bytes())` — the
  artifact's own DSL *text*, handed back under the target format's name. "Export to STL" produced a
  file no STL reader accepts, and reported success.
- **Import**, the same seven: `let _ = bytes; Ok(Generation3dSnapshot::default())` — the file was
  discarded and an **empty document** returned. Dropping a real `.stl`/`.dwg` on the app produced a
  blank canvas with no error. This is the path the plugin root's registered mesh-import host-media
  handler rides on (`✏️s/🔌️plugins/🌀️procedural/🦀️.rs:32-37`).
- `txt` was an honest `Err("… not yet implemented")` both ways, and the export leaf additionally
  carried a stray `deserialize_bytes` that belonged to the import side.
- Only `json` was real.

## 2. Design

### 2.1 One composition point, no new grammars

`🚪️io/🦀️.rs` gained a `mesh_bridge` module (`🚪️io/🦀️.rs:11-158`). Nothing below it re-implements a
file format. Every mesh leaf is a two-step composition of code that already exists and is already
unit-tested elsewhere:

```
Generation3dSnapshot
  → editor::generation3d::export_mesh_from_document      (the app's own preview pipeline, unchanged)
  → semio_framework_plugin::MeshData                     (flat f32 triples + u32 index buffer)
  → mesh_bridge::semio_mesh_from_mesh_data               (🚪️io/🦀️.rs:76-96)
  → SemioMeshSnapshot  (s.stdio.semio@v1/mesh)
  → SemioMeshTo{Stl,Obj,Ply,Gltf,Las,Dwg}                (that subset's own tested bridges)
  → <format>Snapshot
  → the owning stdio artifact's own encoder               (encode_stl_ascii / encode_obj / encode_ply
                                                           / serialize_gltf_document / encode_las /
                                                           dwg_to_bytes — see §6 for why not encode_dwg)
```

Import is the mirror, and ends in the flow graph rather than in a mesh field, because a
generation3d document **has no mesh field**: its geometry is whatever its graph evaluates to.

```
bytes → the owning stdio decoder → <format>Snapshot → SemioMeshFrom{…} → SemioMeshSnapshot   (validation)
      → mesh_bridge::import_document(neuron_kind, payload)                                   (🚪️io/🦀️.rs:126-149)
      → FlowFixture { InputNote(payload) --text/data--> Neuron(brep.io.import*, preview:true)
                                          --geometry--> OutputPreview }
```

`InputNote` seeds a `text` channel (`🧰️framework/…/🌊️flow/🖥️host/🦀️.rs:1230-1232`) and
`brep.io.importStl`/`importObj`/`importDwg` consume a `data` channel
(`✏️s/🔌️plugins/🌊️flow/🧩️extensions/📐️brep/🦀️.rs:779-826`), so the planted fixture evaluates through
exactly the kernel the eight bundled examples use, and `preview: true` puts the result in the 3D
window (`widget_previews`, `✏️editor/🦀️.rs:1704`).

### 2.2 The three real decisions

**a. Formats without a flow operator normalize through STL.** The brep extension registers
`importStl`/`importObj`/`importDwg`/`importStep` and nothing else, so `ply` and `gltf` decode to a
`SemioMeshSnapshot` and are re-encoded as ASCII STL (`mesh_bridge::stl_ascii_bytes`,
`🚪️io/🦀️.rs:118-123`) before being planted. That is a real conversion through two already-tested
bridges, not a second grammar, and the geometry is asserted intact on both sides of it by the test
lane.

**b. A preview with no index buffer is `Points`, not a triangle soup.** `MeshData` without indices
carries no face connectivity at all (wire/point previews). `semio_mesh_from_mesh_data` types it as
`SemioTopology::Points` rather than reinterpreting consecutive positions as triangles, so the
formats that cannot represent points (`stl`/`obj`/`dwg`) refuse it *by name* instead of writing
invented geometry, while `ply`/`gltf`/`las` export it honestly.

**c. LAS is export-only, and says so.** `SemioMeshFromLas` really does decode (and
`las::mesh_from_bytes` is public and tested), but every BRep import operator consumes a *surface*
and LAS carries no connectivity. Reconstructing one — hull, polyline order, triangulation — would
invent geometry the file never stated, so `deserialize`/`deserialize_bytes` return a typed error
naming exactly that. `png` refuses in both directions for the analogous reason (raster in, BRep out)
plus the recorded generation2d ownership tie-break.

**d. Nothing returns an empty document, ever.** Every failure path in this surface is a
`store::TextError` carrying the direction, the format and the reason. That is the single behavioural
invariant the whole ticket turns on: the old code's fault was not that it was incomplete, it was
that it looked like success.

## 4. Tests

### 4.1 In-crate round trip — `[[test]] io-round-trip`

Entry point `🚪️io/🧪️tests/🔁️round-trip/🦀️.rs`; per-format cases live beside the leaves they
exercise, at `🚪️io/📤️export/🧵️serializers/🗿️artifacts/<format>/…/🧪️tests/🔁️round-trip/🦀️.rs`.

One committed geometry drives all of it: `🧫️fixtures/🚪️io/🧊️unit-cube/🔣️.json` — an axis-aligned unit
cube, 8 shared vertices, 12 triangles, bounds `[0,0,0]..[1,1,1]`, enclosed volume exactly 1.0, laid
out in the renderer's own `MeshData` wire form. Chosen because every quantity a mesh format can lose
is independently checkable on it and because 1.0 is exact in binary floating point.

Per format the lane asserts, in this order:

1. **The bytes are that format, by grammar** — container magic and the record the grammar repeats
   once per triangle (`facet normal` ×12, `f ` ×12, `element face 12`, `asset.version == "2.0"` with
   an embedded `data:` buffer, `LASF`, `AC1`), plus an explicit `!contains("semio")` guard that
   would have failed on every pre-ticket export.
2. **The geometry survives** — re-import through the real import leaf, then triangle count and
   bounding box; vertex count too where the format has a shared pool to preserve (`ply`, `gltf`: 8,
   not 36).
3. **A third-party oracle agrees** — `parry3d::mass_properties::MassProperties::from_trimesh` and
   `parry3d::bounding_volume::Aabb::from_points` recompute the enclosed volume and bounds of every
   recovered mesh. Volume is the quantity our own assertions cannot supply: a dropped face, a
   reversed winding or a collapsed axis moves it and does not necessarily move a triangle count.
   `parry3d` was already a registered test-only dependency of this crate (`🔒️dependencies.json`,
   `kinds: ["test-runner"]`, `productionReachable: false`) — this lane adds **no new dependency**.
4. **The import fixture is real** — the planted neuron kind is the right one, the note's payload
   decodes back to the source bytes (or to readable OBJ text), the neuron previews, and the graph
   has its two synapses.
5. **Refusals are typed** — garbage bytes per format, and the LAS/PNG refusals, are asserted on
   their message content, not merely on `is_err()`.

### 4.2 Cross-language differential — `🧪️tests/🚪️io-procedural-3d-1/`

`🥒️.feature` + `🐍️.py` + `🦀️.rs`, mirroring `🧪️tests/🧊️mutate-procedural-3d-1/`, registered in
`🔮️oracle/🔣️.json` under a new capability `procedural-3d-1-io`.

`🐍️.py` is an independent Python implementation of the three text mesh grammars (ASCII STL,
Wavefront OBJ, ASCII PLY) written from the format specifications. It wrote the three committed
`🧫️fixtures/🚪️io/🧊️unit-cube/*second-implementation.*` files, and the Rust lane feeds **those** files
through this artifact's real import leaves — so the two implementations meet on both sides of the
boundary, not only on a number. It is runnable standalone (`python3 🐍️.py`) as well as through the
coordinator.

Two oracle entries were registered, and the split is deliberate:

- `io-round-trip-parry3d` — `kind: third-party-library`, the **qualifying** oracle for
  `procedural-3d-1-io`.
- `procedural-3d-io-python-independent` — `kind: cross-semio-implementation`, **supplemental**.
  It is deliberately NOT registered as `verified-native-second-implementation`: STL/OBJ/PLY are not
  semio-native formats and real third-party readers exist and are already registered by their owning
  stdio subsets (`stl_io`, `tobj`, `ply-rs`), so that promotion would be an unearned claim.

Recorded ceiling, carried from the sibling mutate case: the SUBJECT half of the repo-test case does
not run this artifact's codec, because a generated test host may not link a plugin crate. It replays
the committed vector and checks container magic and per-triangle record counts; the grammar work is
the oracle's. The codec itself is exercised against the same bytes by the in-crate lane.

### What the first run actually caught

The lane earned its keep on its first execution: **9 of 34 failed**, on two real defects, neither of
which any amount of reading would have found.

1. **`DWG header mismatch: codepage 36865 != 0`** — three dwg cases. `encode_dwg` cross-checks the
   file header it just wrote against the `DwgSnapshot`'s own `maintenance_version`/`codepage`
   fields, and `SemioMeshToDwg` builds its snapshot with `..DwgSnapshot::default()`, leaving both at
   `0` while the `AC1015` writer stamps a real codepage — so **every** dwg export through that pair
   failed. Fixed by calling dwg's own `AC1015` writer (`drawing.to_native()` → `dwg_to_bytes`), the
   exact one `encode_dwg` dispatches to, rather than duplicating another artifact's writer constants
   in this leaf; `decode_dwg` reads the header triple out of the bytes and never consults the
   snapshot, so the round trip is unaffected. See that leaf's doc comment.
2. **`ordered-map root must be explicitly retired before drop`** — six cases. `OrderedMap`/
   `OrderedSet`/`Dictionary` are cold-tracked roots that panic on drop unless retired. This is NOT
   specific to the import fixture: every real document carries a non-empty `layout` (every bundled
   example's `🗣️.dsl.semio` writes a `layout={…}` block), so `parse_dsl`'s callers carry the same
   obligation — the example-geometry lane discharges it by moving the fixture into a `FlowHost`.
   Fixed on the test side with an explicit `retire_document` helper
   (`fixture.retire_cold()` + `generation.retire_cold()`), documented where it lives.

### Build conditions, for the record

The shared `target/` was used rather than a private `CARGO_TARGET_DIR`: the seed the brief assumed
(`$S/target-buildaudit/debug`) holds only `wasm32-wasip2`/`wasm-dev`, no native `debug`, and the
volume had ~10 GiB free — a cold private native tree for this dependency graph would not have fit.
Consequently `RUSTC_WRAPPER` was left at the repo's own `sccache` (overriding it changes the cargo
fingerprint and would have forced a full rebuild of a warm 68 GB tree). Wall-clock was dominated by
lock contention and by concurrent peer breakage in shared crates — `semio-framework-os-kernel`,
`semio-framework-plugin`, `semio-s-artifact-stdio-semio`'s brep subset (`Pnt3` indexing), and this
subset's own `👁️viewer/🎚️config/…/🌞️set-sun` (`textOpcode must be lowercase kebab-case`) each
blocked the crate for a while; all had cleared by the final runs above, and none of them was in

## 7. Known limits, stated rather than implied

- **Export needs the flow evaluator.** `preview_semio_mesh` is `#[cfg(feature = "component-app-assembly")]`
  because `host_from_fixture` is (`🧬️schema/🦀️.rs:332`). Without that feature the export leaves return a
  typed error naming the missing feature rather than an empty file. The `serialize_mesh_bytes`
  half is ungated, which is what makes the round-trip lane runnable without a live evaluator.
- **`gltf`/`dwg`/`las` are not adjudicated cross-language.** They are container formats a page of
  Python could only re-implement as a worse copy of the artifact's own codec (and LAS is
  export-only by design). All three are covered by the in-crate lane with the `parry3d` check.
- **The registered DWG standard label is `ac1018` while the emitted container is `AC1015` and the
  mesh bridge lives under the dwg artifact's `ac1024` module tree.** One `DwgSnapshot`/
  `DwgLogicalDrawing` type serves every dwg standard — the `ac1024` directory is only where the
  shared logical model was rehomed — and `SemioMeshToDwg` pins `DWG_CODEC_VERSION = "AC1015"`, which
  is the version the artifact's own polyface-mesh writer and reader agree on. Aligning the three
  labels is a dwg-artifact decision, not this leaf's; the bytes are self-describing and
  `decode_dwg` round-trips them, which is what the test asserts.
- **`encode_dwg` remains unusable for any `SemioMeshToDwg` output** until that bridge stamps the
  header triple its own writer emits (§6). This leaf routes around it; the underlying inconsistency
  is in `s.stdio.semio@v1/mesh`'s dwg leaf and is worth its own fix there.
- **`OPERATION_QUALITY`'s stale `MeshDerivedBRep` tags** (`📓️kernel-and-preview-audit-2026-09-09.md`
  §6) are untouched — the boolean kernel is another agent's slice.
