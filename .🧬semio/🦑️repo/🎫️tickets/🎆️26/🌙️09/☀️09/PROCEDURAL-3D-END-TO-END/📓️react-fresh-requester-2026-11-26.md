# React editor with the rebuilt requester

The privately served requester was tested via the ordinary React renderer on port 6019 with the authored Hexagonal Mushroom Column. The browser loaded the served WASM assets directly. The test harness added JS console observations and read the application’s existing draw data.

The first run passed initial typed bootstrap at 14 seconds. The Mushroom title and Edit layout appeared, and the two panes had empty contents when the short mount deadline expired at 120 seconds. At 80.735 seconds the host had reported `setContributions` pending at continuation 3 of 1680.

With a longer mount deadline, the same normal contribution registration reached 33 completed continuations at 130.303 seconds. The actual Flow graph and preview surface mounted at about 196 seconds. All seven authored node IDs were present. The initial tool command completed at 198.059 seconds, requesting `flowEvalTick`. The preview remained at 0 of 1 with no vertices as the row opened Artifact and Inspection. The height selection stayed empty during the 120-second inspector wait. The intervening `noteShellCommand` held the procedural actor lane and was still pending at continuation 52 at 216.468 seconds. This run reached neither an extension invocation nor an editable slider.

The longer run also recorded repeated HTTP 502 responses to same-origin WebSocket upgrades from the original private proxy. The proxy owner added transparent upgrade forwarding and Origin translation. An independent handshake then returned HTTP 101 and the expected accept header. The clean retry lets the unmodified app evaluate its initial graph before opening any inspector panels, to isolate the geometry path from the concurrent panel commands.

The clean run confirmed the repaired socket and held off every inspector or graph interaction. The normal `toolRunStart` returned full scope at 120.354 seconds. The Edit instance then entered `flowEvalTick` as a declared app command with the current effect owner. The arguments and the live roster both named `procedural-preview` as the instance and kind. The inactive Generate route also entered separately.

The edit preview reported 0 of 1 while its worker was active. An operating-system sample of the owned Chromium renderer observed one dedicated worker executing deep JIT frames in 377 of 379 samples, while the other dedicated workers waited. Math was first invoked for the Edit instance at 310.270 seconds. It loaded the real 96,497,636-byte browser core and returned the 87-byte progress answer at 314.306 seconds. The requester completion settled at 372.330 seconds. The edit preview advanced to 4 of 7, with cancellation available, one invocation in flight and zero vertices. At 465 seconds the second invocation had yet to appear.

The ticket probe can now arm Chromium’s DevTools Profiler on the application’s actual worker targets before the Edit tick. A local dedicated-worker check independently recovered its expected hot function from a 109-sample profile. This observer is opt-in and the active clean run was launched before it was configured.

The clean run met the no-interaction observation bound and reported its browser row failure at 737.975 seconds. The last visible preview remained at 4 of 7 with one invocation in flight and zero geometry. The page-error row passed. Baseline-first validation kept edits and inspector commands out of the measurement. After that browser exited, the profiled replay started independently on the same 6019 route.

The profiled replay captured the active real 6019 shard in two phases. In the trailing samples before the first capability crossing, the active worker repeatedly traversed WASM functions `23539`, `14924`, `14923`, `16811` and `36133`. After the actual Math completion settled at 590.991 seconds in the same replay, an independently attached DevTools target session sampled the trailing 12 seconds of a 15-second observation window. The active shard repeatedly traversed `36133`, `54886`, `19913`, `32956`, `59764`, `61355` and `61354`. The other four workers were idle among the dominant modes. The raw Chromium profile trees preserve parent stacks and module function indices in both phases.

An isolated short replay captured the exact opening call, preview surface projection and Edit command in the normal renderer. The first preview surface was `procedural-preview` with body key `procedural.play.preview`, bound to instance 1. Its live ViewModel carried the five expected roster entries, `activeModeId: edit`, English locale, native terminology, focused window `procedural-main` and targeted window `procedural-preview`. The emitted surface view Pack was 466 bytes. The actual Edit tick entered at 207.894 seconds as app command sequence 21 and a single ingress page. The raw command was 575 bytes with SHA-256 `c0b4640af7c6a914a1e5e3b0e1360fca408c07ea66f791f882363cd7a31616c5`. The same bytes were present in its captured ingress event array. The command received explicit Edit targets in its args and the trusted roster, while its outer ViewModel carried no `windowId`. The inactive Generate tick followed at 210.133 seconds.

The renderer completion port seals each request after its one submission to a captured activation. Its returned `deferredEvents` identifies events held by shard batching before crossing. The client reoffers those events through its own custody. The reactor’s general `more-work` status provides no event-specific authority to replay a crossed completion. A browser duplicate would therefore add a second donor, and the diagnostic left the original delivery untouched.

The next browser run can require the authoritative requester SHA-256 before it launches Chromium. The probe hashes the ordinary HTTP response as a stream and then records Chromium’s successful download from the exact requester URL. A deliberately mismatched digest failed the gate before launch on the old requester, whose actual browser core SHA-256 was `8024ecbb7896730814de8aa3b5f4355cf1160f0f3742ae13f7ef3d64ef929ec6`.

## Requester with retained Completed ingress

The private 6019 server returned the rebuilt 324,343,832-byte requester core with SHA-256 `c2824a5ee59995d51d080e90443344f54fc26a1a220d8d61c2bc09c8f998c60f`. Chromium downloaded the ordinary versioned core with HTTP 200. The stable replay made no inspector, picker, or graph interaction before the baseline.

The real contributions call sent 425,209 JSON characters, including the Flow, Procedural, Math and BRep providers and the five-window editor roster. The command completed at 158.171 seconds, with an empty friendly effect list and `uiScope:none`. The temporary `flow.extension-not-contributed` display cleared on the ordinary refresh. That refresh started `previewEval` at 206.319 seconds. The start returned the Edit preview tick at 208.491 seconds and the application dispatched both the correctly scoped Edit and Generate ticks. The Edit tick's first response at 210.525 seconds held no immediate UI scope, history patch, or effect.

At the 0-of-1 preview stage, a seven-second operating-system sample found one actual dedicated worker in deep JIT frames in 3,482 of 3,525 samples. The other four dedicated workers were idle. No extension time or mesh result had appeared at 468 seconds.

The first queued Generate tick returned at 528.539 seconds. The visible Edit preview invoked Math at 530.193 seconds, received its real 87-byte progress Pack at 539.593 seconds, and showed four of seven nodes with one request in flight. The rebuilt requester settled its Completed envelope at 588.167 seconds and returned a fresh Edit tick. Chromium dispatched it at 588.169 seconds. The earlier requester had settled the same 87-byte answer with an empty effect list.

The stable replay reached its 762-second baseline deadline with four of seven nodes, one request in flight and zero vertices. Its exact requester download and page-error checks passed. The row failed at the baseline, before any edit, undo or redo.

A separate CPU replay mapped the last 27.99 seconds after the initial Edit tick to the original linked Rust functions. One worker spent 24.25 seconds in Wasm self samples and 21.92 seconds inclusive in `advance_typed_operation_output_inner`. The outer Procedural, Generation3d editor, and artifact publication forwarding closures accounted for over four seconds of combined self time. The other four workers had zero Wasm self samples. The actual Math invocation returned 87 bytes again in this replay. An upstream Vite restart followed before Completed settled and forced a fresh document, after which Chromium exited with SIGKILL.

An independent ordinary React server on port 6021 now has its own Vite product cache and ticket-local application state. It returned HTTP 200 for the exact installed requester core and HTTP 101 for the same-origin WebSocket. The long retry there bypasses the previously shared Vite process and opens its worker profiler only after Math Completed.

Both isolated Chromium launches disconnected before downloading the requester and mounting the editor. The first Chromium process reported SIGKILL. The HTTP core preflight still matched in both attempts. The post-Completed worker profile and the full edit, undo and redo journey remain unverified.
