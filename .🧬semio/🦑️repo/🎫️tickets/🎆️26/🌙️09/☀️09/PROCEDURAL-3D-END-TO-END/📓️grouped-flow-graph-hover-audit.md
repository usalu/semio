## Limits and follow-up

A targeted scan found the explicit `DagGraphState` construction in `🧭️host/👆️host-pointer-impl/🦀️.rs` initializes `hover_ports`, and its owned retirement destructure includes the field. This was not a full compile of all feature combinations; a repository-wide struct-literal scan timed out, so no claim is made that every test-only literal compiles. The Flow ABI JSON and JS ledger agreement does not itself validate generated browser declarations or wasm execution; those require the registered browser-type and linked tests.

LOD matters: directed primary hover uses `allows_connection_hit_picking`; companion paint can only appear where the graph actually draws the corresponding channel/handle. Compact behavior was not established by this witness. Run the registered linked DAG/Flow and WGPU canvas regressions, then a real mounted React and WGPU journey: same primary with changing companions, a second surface taking ownership, group-to-single, local pointer takeover and leave, clear, scene/snapshot rebuild, and Detail/Normal paint. Assert all aliases without changing selection or geometry. A 1,024-channel and 64-KiB boundary test should also verify the producer/transport's behavior: WASM refuses an oversized group as one action, so caller-side handling must be assessed under an actually reachable large group rather than assumed.
