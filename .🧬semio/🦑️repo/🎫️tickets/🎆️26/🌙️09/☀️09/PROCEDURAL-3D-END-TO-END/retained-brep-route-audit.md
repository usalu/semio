# Retained BRep Route Audit

Read-only inspection of the live Flow registration and retained dispatch, 2026-11-21. This is a selected-branch audit, not a claim of exhaustive operator completeness.

- `brep.sweep.pipe` publicly declares `profile`, `path`, and `guide` (Flow `🧾️register-operators/🪡️surfaces-and-sweeps/🦀️.rs:144-154`), but `GeometryOperation::Pipe` refuses every supplied guide before dispatch (`〰️analytic-curves/🦀️.rs:452-462`). The remaining Sweep and Pipe route only accepts a one-edge open line wire and planar polygon or axial circle face (`🧰️framework/🔨️modules/🧊️3d/📐️brep/⚙️engine/🧠️native-registry/🛤️straight-sweep/🦀️.rs:14-20,34-61`); curved paths, multiple edges and oblique circular sweeps are unsupported. A tractable incremental target is a straight path with a straight guide whose direction is parallel to the path, with explicitly defined guide positioning and orientation semantics; it must validate rather than silently ignore the guide. Entry point is the Pipe branch and retained depth/demand handling, followed by the engine planner. Extend shared `🔣️original-straight-sweeps.json`, the Flow Rust consumer `🧪️tests/🔬️unit/🧊️original-solids.rs:958` and the existing Manifold oracle `🧪️tests/🔬️unit/🛤️original-straight-sweeps.test.ts`; assert geometry and rejection for nonparallel guides. This is a limited family, not a general guided pipe implementation.
- Fuse, Cut, and Intersect fall back to `plan_boolean_preparation` when operand capture or certified pairing rejects a family (`〰️analytic-curves/🦀️.rs:429-442,1227-1244`). Preparation eventually fails with `general face imprinting is not funded` (`:1217-1225`), so this is an explicit remaining general-Boolean gap, though substantially larger than a single route.
- `brep.sweep.extrude` accepts a face at registration (`🧾️register-operators/🪡️surfaces-and-sweeps/🦀️.rs:96-106`) but the retained dispatcher tries circular extrusion, rectangular extrusion and prism only, then reports that it requires a closed planar line or circular profile (`〰️analytic-curves/🦀️.rs:489-501`). This does not establish support for arbitrary spline-bounded planar faces; it is another operand-family boundary requiring deeper planner audit.

No production code or tests were changed or executed. Heal, Defeature and DWG were outside this audit.


## Guide Semantics Follow-Up

The cold kernel specifies orientation explicitly: `SweepJob::pipe` says each station frame x-axis points toward the closest guide point (`🧰️framework/🔨️modules/🧊️3d/📐️brep/🛠️operations/➡️sweep/🦀️.rs:327-330`); `🐍️frame/🦀️.rs:104-123` projects that vector perpendicular to the path tangent, normalizes it, and keeps the station origin at the path. It falls back to the rotation-minimizing x-axis if the projection degenerates. `➡️sweep/🦀️.rs:270-280` aligns the profile frame to the first guided path frame. Thus guide is an orientation rail, not a displacement or a position rail. The cold Flow `Pipe::evaluate` passes the optional guide through (`🔶️primitives-curves-surfaces-and-sweeps/🦀️.rs:293-306`). Registration provides channel names but no further geometric guide semantics; no BRep-specific Pipe WIT declaration or independent WIT geometric specification was located in the inspected source. Do not infer that WIT independently specifies this behavior.

A representable nondegenerate case: a 2 × 4 rectangle whose plane frame origin is at (0,0,0), x points +X and normal +Z; path from (0,0,0) to (0,0,3); guide from (5,0,0) to (5,0,3). The guide closest-point vector is +X at every station, so the result is the same rectangle translated from z=0 to z=3, with bounds [(0,0,0),(2,4,3)] if its corners are (0,0,0) and (2,4,0), volume 24, and six faces. Confirm the constructor frame origin and orientation in the actual fixture before adopting these exact bounds; a centered profile would have different bounds. Independent Manifold hull of both end rectangles supplies the oracle; existing `🛤️original-straight-sweeps.test.ts:10-35` already uses that construction for straight sweeps, but currently specifies no guided case. Existing cold unit `➡️sweep/🧪️tests/🔬️unit/🦀️.rs:277-285` tests a guided polyline only for positive volume, not precise orientation.

Caution: existing retained unguided straight sweep deliberately preserves profile placement and uses only path displacement (`🧊️original-solids.rs:953-954` and fixture whose path starts elsewhere). Cold guided station sweep aligns the profile frame to path origin. Consequently a new implementation cannot merely accept or ignore arbitrary parallel guides; only a certified case with compatible profile/path placement and guide direction may reuse the current retained extrusion without changing semantics. Add an offset-path and rotated-guide test before broadening that subset. The previous recommendation to reject all nonparallel guides was a bounded-scope suggestion, not the cold contract: cold supports varying orientation rails.
