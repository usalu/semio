# Spatial Preview Schema Audit

Read-only source audit, 2026-11-21. No production edits, Cargo or runtime tests. Findings reflect the live Flow extension constructors and Generation3d preview code inspected, not every possible third-party plugin.

## Registered and authored shapes

- Flow BRep `geometry_dict` emits `{$schema:"geometry",handle,kind}`; its `point_dictionary` and `vector_dictionary` emit `{$schema:"point"|"vector",x,y,z}`. Owner: `✏️s/🔨️modules/🌐️spatial-kernel/⚙️engine/🧠️semio/🌊️session/🧰️operator-registration/🦀️.rs`. BRep box, transformations and solid operations use `geometry_dict`; closest point and center of mass use typed point; bounding box returns geometry. No bare string handle was found in these registered channel constructors.
- BRep deconstruction outputs `$schema:"list"` dictionaries keyed by decimal indices containing separately typed `vertex`, `edge`, `face`, or `shell` objects with a handle; selected lists also use `edge`/`face`. Same file's `topology_list` and `deconstruct_geometry`. A strict geometry-handle allowlist must include these schemas, not just `geometry`. Surface/curve and ordinary primitives returned by the inspected BRep operators are represented by the generic geometry schema with a kind.
- Mesh output is `{$schema:"mesh",data,preview}`, emitted by `✏️s/🔌️plugins/🌊️flow/🧩️extensions/📐️brep/🥽️mesh/🧮️operator-core/🦀️.rs`; Mesh Analyze minimum/maximum and inspection outputs use the shared typed point/vector constructors. Flow math arithmetic produces typed point/vector via `✏️s/🔌️plugins/🌊️flow/🧩️extensions/🧮️math/🦀️.rs::xyz_dictionary`.
- Authored `WidgetInputValue::neural_value` in `✏️s/🔌️plugins/🌀️procedural/🗿️artifacts/🧊️generation3d/🏅️standards/🔖️1/🪆️subsets/✳️any/🧬️schema/🧬️mutations/🎛️change-widget-input/🦀️.rs` emits explicitly typed point/vector, typed plane with typed point origin and vector normal, and index-keyed typed list. The existing `🧵️preview-eval/🧪️tests/🧫️fixtures/preview-inline-overlap.json` also supplies schema-less numeric xyz for origin and normal **inside** an explicitly typed plane. Supporting that contextual plane shape is compatible with rejecting free-standing untyped xyz. It is a fixture shape; the inspected native literal producer tags both children.
- Both native JSON arrays and schema-tagged keyed lists are accepted by the walker for nested list structure. `preview-value-paths.json` deliberately contains schema-less `{handle:…}` objects as synthetic path/history examples; this is an existing fixture contract, but inspection did not find an actual registered canonical BRep producer emitting such untyped objects. If tightening, explicitly update those fixtures to realistic typed geometry and preserve path semantics; do not infer production compatibility solely from test shorthand.

## Concrete false positives

`🧵️preview-eval/🧊️preview-geometry/🦀️.rs::collect_preview_channel_items` recurses all object fields and arrays. For every non-mesh object, `preview_native_handle` accepts a matching handle-shaped string without checking its schema. Then `preview_xyz` accepts *any* numeric `x/y/z`, even `$schema:"dictionary"` or an unrelated custom schema, and treats it as a point unless its schema is `vector`. Thus a preview-enabled dictionary output such as `{$schema:"dictionary", metadata:{x:1,y:2,z:3}}` produces a point marker for metadata; a dictionary `{handle:"solid-…"}` may create a tessellation request for a non-geometry field. `✏️s/🔌️plugins/🌊️flow/🧩️extensions/📖️dictionary/🦀️.rs` registers arbitrary dictionary wrapping and nested values, making this a supported structured data category. The exact false-positive example is source-derived and was not run through a mounted graph here.

The collector feeds `preview_viewport_items_for_widget`, mesh demand/residency, and both Edit and View preview payload builders; Generate reuses the Edit payload path. An accidental point consequently reaches world instance/hover/fit calculations, and a false native handle can enter the tessellation demand. `preview_leaf_at` / `preview_history_handle` in the same file use `preview_native_handle` and `preview_xyz` too; admission and history-path recognition must be changed together, or indices and retained history can disagree.

## Scope of a safe correction

Classify spatial **leaves** by explicit schema: point/vector, plane, mesh, geometry and the four topology schemas above. Continue recursing structured records and both array and keyed-list carriers so genuinely typed spatial children remain discoverable. Read untyped xyz as structural coordinates only within an admitted plane's origin/normal; preserve finite checks and axis semantics. Tighten the handle path to supported spatial schemas and leave untyped metadata alone. Add neutral fixtures with untyped and unrelated-schema xyz/handle objects at top level and nested beside typed geometry, topology and plane; cover input/output directions, array/keyed lists, paths/history and demand, plus independent JSON oracle and Edit/Generate/View source projection. Existing fixture/test owners: `🧵️preview-eval/🧪️tests/🧫️fixtures/{preview-value-paths.json,preview-inline-overlap.json,preview-channel-directions.json}`, `🧵️preview-eval/🧪️tests/🔬️unit/🦀️.rs`, and ticket portable preview tests.

No additional registered Flow frame, quaternion, matrix or bounding-box spatial value requiring its own world marker was established in the inspected extension registrations: Flow math registers point/vector, BRep Bounding Box returns geometry, and mesh transforms consume a 16-number list rather than emitting a typed transform. Generation3d's typed plane is already handled. This is a scoped source search, not an exhaustive assertion about all dynamic plugins; any future explicit frame or custom spatial schema needs its own defined rendering contract rather than structural guessing.

Paths beginning `🧵️preview-eval` above are relative to `✏️s/🔌️plugins/🌀️procedural/🗿️artifacts/🧊️generation3d/🏅️standards/🔖️1/🪆️subsets/✳️any`.
