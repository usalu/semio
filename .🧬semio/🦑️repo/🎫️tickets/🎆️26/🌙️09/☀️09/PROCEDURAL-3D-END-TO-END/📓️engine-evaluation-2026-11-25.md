## Evaluation progress cadence

The Flow SDK previously constructed a packed intermediate reply after every retained advance, including input preparation and cleanup. Each reply causes the requester to construct and the extension to parse another invocation. The first coalescing change used a round of 16 units. A direct Chromium BREP invocation spent 137 seconds on at least 13 compact resumes in input parsing alone. Its requested 256 units were capped at 16.

The invocation now spends up to 256 retained work units by default and up to 4,096 for explicit budgets. A round may report progress earlier after two seconds on the caller's recorded clock, measured from the first evaluation advance. Expiring an individual poll's grant yields that poll and leaves the round active. Each poll uses the original fuel, memory, deadline and cancellation checks. Completion and external dependencies retain immediate replies. Terminal-only callers drive the same work without allocating intermediate progress envelopes. A language-neutral fixture covers default and explicit budgets, the upper ceiling, and the wall boundary. SQLite independently checks its cumulative work and elapsed-time results.

The first rebuilt Math actor's reply decoded to `done:false`, `cancellable:true`, `phase:"input-parse"` and 16 of 17 units completed. The browser delivered its completed event and the procedural actor emitted another `flowEvalTick` on the subsequent refresh. Both edit and generate previews appear in the editor's attached-window roster, with different instance and kind IDs. The addressed command resolves the exact instance's retained transient before it can dispatch a compact evaluation continuation.

The native mounted-app fixture had been parsing capability replies as JSON and encoding them again. It now forwards the response bytes directly, as the browser does. The test adapter's synthetic cancel acknowledgements also emit Pack. A new editor law serves actual Math and BREP replies, verifies that each compact resume names the same extension, window, operator, and node hash as one working Pack envelope, and requires the addressed window's run to finalize.
