# Graph Hover Granularity Audit

Read-only source audit, 2026-11-21, after the current delimiter changes. No production edits, graph or Cargo runs. This is source-derived, not a mounted reproduction.

## Confirmed collision

A valid authored widget ID `a@solid` can coexist with widget `a` and its output `solid`: the authoring path checks widget uniqueness, and the current `graph_port_id("a", "solid", false)` is also `a@solid`. The delimiter-safe channel codec does not namespace node IDs against handle IDs. A synapse ID is an independently stored string and may also equal a node or handle ID; generated IDs are ordinary `s…`, but the snapshot model does not impose a shared cross-kind namespace.

The interaction action receives separate targets `{granularity:"node",id:"a@solid"}` and `{granularity:"handle",id:"a@solid"}`, but they become indistinguishable in the hover store. Edit's `PreviewInteractionMarks::hover_port` gives an exact existing widget or synapse priority over parsing a port. Thus hovering the handle for `a.solid` when widget `a@solid` exists is interpreted as hovering that other node; its own output is not treated as the hovered port. View's `PreviewChannelAddress::marked` checks the same string against widget, port and instance without a granularity and can mark both widget `a@solid` and the `a.solid` port. In both modes `preview_wire_hover` checks the untyped set for each synapse ID, so a node/handle with a wire's ID can additionally highlight that wire's endpoints. Exact published marks depend on which geometry is preview-enabled and the graph topology.

## Where the type is lost

- `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🕹️interaction/🧭️topology/🦀️.rs::parse_interaction_targets` decodes a `Vec<InteractionTarget>`, preserving each target's `granularity` and `id`.
- `…/🧵️instance/🖼️render/📥️staging/🧭️interaction/🦀️.rs::apply_interaction_verb` passes these typed targets to `next_hover`.
- `🧰️framework/🔨️modules/📡️replication/📡️wire/🕹️interaction/🦀️.rs::next_hover` calls `expand_interaction_ids`, which initializes its walk with only `target.id`, deduplicates strings and returns `DomainHover { channel, ids }`. The original granularity is lost here. The `InteractionHoverState` map stores that result and `…/🔌️plugin/📜️declaration/👁️view/🔍️lane-views/🦀️.rs::InteractionView::hover` faithfully returns the untyped record; it cannot recover the discarded distinction. Hover owner metadata tracks source window, not target kind.
- Edit `✏️s/🔌️plugins/🌀️procedural/🗿️artifacts/🧊️generation3d/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🎭️modes/✏️edit/🪟️windows/👁️preview/🦀️.rs` collects `hover.ids` into a set, uses `hover_port` to infer type, and exposes `hovered_graph_target` / `graph_highlight_ids` for graph projection. The matching View file `👁️viewer/🎭️modes/👁️view/🪟️windows/👁️preview/🦀️.rs` collects the same IDs and delegates to `PreviewChannelAddress::marked`. `🧵️preview-eval/🦀️.rs::preview_wire_hover` performs string-only wire and input comparisons.

Topology itself must be considered: Edit's `✏️editor/🪟️artifact-editor-impl/🦀️.rs::interaction_topology` and View's `👁️viewer/🔭️viewer-and-interaction-topology/🦀️.rs` publish node, handle, and edge `TopologyNode` records with raw ID and granularity separately, but parent is only a string. `expand_interaction_ids` uses string-keyed membership/children/deduplication, so retaining just a single root granularity on `DomainHover` after the existing traversal would still conflate distinct transitive descendants with equal IDs. Both graph hover definitions request transitive expansion.

## Smallest correct shared change

The existing typed vocabulary is `InteractionTarget { granularity, id }`; selection already retains a `DomainSelection.granularity`, but one granularity is insufficient for a transitive hover containing nodes and handles. Extend the hover state and topology traversal to preserve a typed target for **each** root and descendant, with typed parent identity or an equivalent collision-free topology key. Reuse `InteractionTarget` (or a shared equivalent) in `DomainHover`, `next_hover`, validation and retirement/serialization, then let `InteractionView` expose it. Update the Edit and View mark producers, graph highlight/hover projection, and `preview_wire_hover` to branch on target granularity instead of interpreting string shape. Keep source-window clearing semantics. An alternative fully namespaced producer identity can work only if node, handle, edge and all topology parent references use an injective namespace consistently at every producer and consumer; changing only the port codec cannot resolve arbitrary authored node IDs.

Use a language-neutral fixture containing widgets `a` and `a@solid`, a preview-enabled `a.solid`, and an independent synapse whose ID is `a@solid`. Exercise each of node, handle and edge hover separately, plus transitive node hover, leave/clear and source-window ownership. Assert Edit, Generate, View and graph marks independently: handle hover affects only the intended port and its upstream link; node hover covers only that node's descendants; edge hover covers only its two endpoints. Include distinct granularity records with identical IDs in the framework hover reducer/topology tests and run real React and WGPU publication tests after the owned app build is available. No tests were run here.
