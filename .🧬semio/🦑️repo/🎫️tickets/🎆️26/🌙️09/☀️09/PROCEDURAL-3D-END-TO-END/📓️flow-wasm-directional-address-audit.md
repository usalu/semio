# Flow WASM Directional Address Audit

Read-only source audit, 2026-11-21. No build, browser run or production changes. This traces the active Generation3d Flow-session path, not the scene-record fallback.

## Finding

Yes: the active React canvas uses the raw authored Flow snapshot and drops input/output side on its public interaction handles. The existing directional `NodeGraphScene.nodes`/`edges` projection does not determine the WASM session's live ports. A node with input and output both named `vector` publishes `node@vector` for either, while the Generation3d semantic contract expects `node@!ivector` for input and `node@vector` for output. Hover and handle selection therefore cannot distinguish these two public addresses. The fallback directional projection tests do not establish this mounted path.

## Actual route

1. Generation3d's Flow scene supplies `host_snapshot_json`. React `🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🕸️NodeGraph/🔄️flow-session-sync/🟦️.ts::syncFlowSessionStructureFromScene` sends it to `session.synchronizeSnapshotJson`, along with operator catalogue records. Its `scene.selection` also enters the Flow session; projected scene nodes/edges are not installed as session structure on this branch. After a gesture, `🧾️flow-interaction-lane/🟦️.ts` calls the same function with `skipFixture=true`, avoiding replacement of the local gesture state.
2. Flow's `🧰️framework/🛍️products/💻️os/🔨️modules/🌊️flow/🖥️host/🌳️host-evaluation-history/📝️dag-sync-widget-properties-and-canvas-settings/🦀️.rs::raw_dag_snapshot` calls `widget_to_dag_node` in `…/🗿️artifacts/🌊️flow/🧬️schema/📸️snapshot/🗺️dag-node-conversion/🦀️.rs`. `…/🏷️widget-labels-and-io-ports/🦀️.rs` builds `IoPortSpec` from authored `ChannelSpec.name`; `variable_io_ports` gives its input and output the same raw name. Raw edges concatenate widget and raw port. The canonical directional adapter `✏️s/🔌️plugins/🌀️procedural/🗿️artifacts/🧊️generation3d/🏅️standards/🔖️1/🪆️subsets/✳️any/🧵️preview-eval/🦀️.rs::dag_host_snapshot_to_workflow` is used to prepare scene records, but is not applied to the raw Flow host's canvas model.
3. Shared DAG `🧰️framework/🛍️products/💻️os/🔨️modules/♾️infinite/🎲️board/🔌️ports/➡️directed/🕸️dag/🕸️graph/🧲️graph-state-selection-and-engine-rebuild/🦀️.rs` creates distinct native handles and assigns input `Target` / output `Source` roles. Its `handle_key_map` nevertheless stores the same public `{node}@{port}` for both. Thus layout and directional hit-testing have internal side, but public identity collapses.
4. `…/🖱️hover-rect-and-pick-targets/🦀️.rs::dag_pick_targets_at_screen_json` formats pick handle IDs using only widget and port. React `🕸️NodeGraph/🎯️flow-pick-spotlight/🟦️.ts` decodes that side-less ID with `nodeGraphPickChannel`, then calls `setHoverChannel(widget,port)`. DAG's `…/🔭️viewport-lod-grid-and-camera/🦀️.rs::set_hover_channel` resolves `handle_id_for_port`, which picks the lowest matching handle; inputs are created first. The Flow hover result *does* contain a typed `direction` in `🧰️framework/🛍️products/💻️os/🔨️modules/♾️infinite/🎲️board/🧬️schema/🧾️dag-output-sources/🦀️.rs`, but both React `🎯️flow-pick-spotlight/🟦️.ts` and `🧾️flow-interaction-lane/🟦️.ts` read only `hover.channel.port` and publish `nodeGraphHoverActionArgs` as raw `node@port`. Thus even the actual result direction is discarded; pointer focus can first be re-resolved to the opposite handle.
5. `…/🎚️graph-state-interaction-impl/🦀️.rs::selection_domains` similarly maps selected typed channels to side-less `node@port`; React publishes these handles unchanged through `nodeGraphSelectionActionArgs`. Selection restoration's `handle_id_for_port` is also side-less. In contrast, node and edge selections are not affected by this same-name side collision.
6. Native `…/📓️graph-state-journal-and-hits/🦀️.rs::journal_connect` obtains raw node and port strings from the actual source and target handle keys. React's `NodeGraph/🟦️.tsx` forwards pointer-up `nodeGraphEditRows` directly. The Generation3d command `✏️editor/🎮️commands/✏️node-graph-edit/🦀️.rs` then calls `graph_port_channel` on both raw journal port IDs. Ordinary names pass unchanged, but a legitimately authored raw port `!iX` or `!oX` is wrongly stripped to `X`. This is a separate wire commit mismatch, not proof that every wire gesture fails. The journal's `rsplit_once('@')` also has the delimiter ambiguity documented in `📓️graph-address-delimiter-audit.md`.

## WGPU

The actual native WGPU Flow branch `🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/⚙️EngineCanvas/🎯️targets/🧊️wgpu/🧩️engine-surface-attach/📎️registry-and-node-graph/🦀️.rs::sync_node_graph_engine` parses `host_snapshot_json` and calls `FlowHost::resync_host_snapshot_from_scene`, so it shares the raw native DAG port identities. Its `…/🕸️node-graph/🔗️screen-pointer-and-commit/🦀️.rs::graph_interaction_snapshot` formats hovered channel as `widget@port` and discards `direction`; the same collision is present. The generic `NodeGraphEngine::Dag` branch is separate and must not be substituted as proof of this Flow path.

## Smallest correct fix and verification

Preserve native `DagChannelDirection` through the actual pick, hover and selection publication and restoration, producing the same direction-qualified address expected by Generation3d. The pick result itself must carry side (or a collision-free encoded directional handle); changing only the final hover JSON mapper is insufficient because `setHoverChannel(widget,port)` already chooses the first same-named handle. Make the shared native pick/selection contract typed or use one common codec at the boundary, and keep Flow's internal authoring/wire channels raw. Distinguish raw WASM journal rows from any encoded fallback rows before `nodeGraphEdit` decodes; remove unconditional stripping for raw Flow rows. Reuse one codec across React, WGPU and Generation3d rather than duplicating a new convention. Include the delimiter issue when defining identities, rather than introducing another ambiguous concatenation.

Add a language-neutral fixture with a Variable or real operator having identical input/output `vector`, and two different preview values. Exercise actual Flow session synchronize, screen pick for both sides, hover, selection, restore and upstream wire, and confirm the published target matches the semantic scene and world preview for each side. Test a raw plugin channel starting `!i` and `!o` through actual connection journal and committed authored synapse. Run the same source fixture in React and WGPU, including channel-row and direct-handle LODs. These are required because the existing directional scene projection tests bypass this route. No runtime result is claimed by this audit.
