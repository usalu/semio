## Longer Backend Diagnosis

With the same served WGPU artifact, 90-second pointer-pumped runs both hit `original slot pages dropped before paid close`: Metal at 12.3 seconds and Chromium launched with SwiftShader flags at 9.0 seconds. In each stack `OriginalFixedSlotPages<EngineCanvasPacket, 16, 16>::drop` is reached from `ActiveFramePhase` drop inside `ActiveFrameBuild::step`; the worker then reports `original-turn.source-not-ready`. Chromium did not expose identifying adapter information, so the flags alone do not prove the selected WebGPU backend. Both captures remained dark.

The owning frame-job source assigned a new phase directly over `Build` on successful and superseded transactions, even though `retire_active_phase` already performs the transaction's paid close. Those paths now retain the old phase and drive its close before advancing. Supersession stays pending until retirement and then returns an empty completion, allowing the caller to retry. `wgpu-backend-audit.mjs` is a repeatable live regression probe that pumps input and asserts a nonuniform painted image and no captured faults; it requires a freshly rebuilt and staged WGPU artifact before it can validate the fix. A subsequent run while React activation was changing the live server saw aborted WGPU requests and is not a valid post-fix result.

## Rebuilt Renderer and Browser Bundle

The rebuilt renderer was bound with `wasm-bindgen --remove-name-section` and staged; its served wasm was 87 MiB instead of 124 MiB. The authored actor decoder already handles `publish-event`, but the served frame-worker bundle lacked that case. Regenerating the browser closure and all three browser artifacts restored the case in the served worker. A subsequent 123-second run using the regenerated worker logged no dropped `publish-event` and no former slot-page panic. Boot completed after approximately 58 seconds, but the screenshot remained a single color. Immediately after `setActiveExample`, a typed-operation drain refused with `original action window kind is foreign`, followed by surface faults. This run used the older staged procedural actor; a fresh actor build is required to distinguish an artifact mismatch from a remaining address defect. The native frame-job test was interrupted while waiting for the shared build lock held by the BREP build; its compilation work was preserved.

Instrumenting the existing worker response showed the concrete mismatch: a `toolRunStart` rearm addressed window instance `generation3d-generations` with kind `procedural-main`, even though the view roster declared kind `generation3d-generations`. The WGPU bridge now resolves the selected instance's kind from that roster and passes the roster to the shared rearm resolver, which also preserves an explicit preview target. Both regression cases failed before their fixes; the extension-dispatch suite passed all 23 tests afterward. Browser artifacts were regenerated.

With these fixes, a 150-second Metal run completed at 161 seconds with no captured panic, surface fault, or dropped `publish-event`. Its browser-composited screenshot contained 2,566 colors and showed the procedural shell, generation form, preview grid, and a tool run at “Evaluating nodes (1/2)”. It did not show solid geometry, so it establishes shell and grid paint but not end-to-end geometry. A 5-second worker CPU sample symbolicated with matching named bindings attributed about 1.1 seconds inclusive to `OriginalBrowserOutput::advance` and 1.0 second to frame-build polling; the worker was active rather than throwing an exception.
