## Resolution
No registration change was needed. The launch was restarted (v13) on the consistent registry.

## Open design point
The host log for 13:28Z has no `[graph-repair]` line, so the registry follow (`🧭️registry-follow/🟦️.ts`, `settleOwnerRegistryV1`) did not adopt the missing rows: the per-owner retry declared "reproduces on unchanged inputs" because the observed rows of an owner do not include `📋️build-owners.json`. If the failure recurs, the fix belongs in `observeOwnerWithRetryV1`: classify a registry-fault reason (`OwnerRegistryWorkerFailures` in `🕸️graph/🧬️schema/🔣️.json`) as a registry invalidation rather than a stable owner failure, so the load-level follow re-reads the registry.

## Fix (root cause found and closed)
- Trace: `loadBuildGraphV1` wraps every non-reuse read in `settleOwnerRegistryV1`; the generation and slice paths throw the owner failure through `withOwnerRegistryCustodyV1`, which turns it into the invalidation the follow consumes. The registry follow was reached, but it decided "registry moved" by comparing the physical registry now with the one read BEFORE the attempt (`before`). The attempt itself clears the pin and reads its own copy. When a peer regenerates `📋️build-owners.json`, the attempt can pin a transient copy without the row while `before` and `current` are both the complete file: not moved, nothing to adopt, so the read ended with the stable owner failure ("reproduces on unchanged inputs") and no `[graph-repair]` line.
- Fix (`🕸️graph/📥️load/🧭️registry-follow/🟦️.ts`, `settleOwnerRegistryV1`): the current registry is always judged by its content, independent of `before`: a pending root that the current registry owns (or a vanished root it no longer owns) counts as moved, an unreadable registry mid-write counts as moved; both retry through the existing bounded `repairRounds`, then the typed `BUILD_OWNER_REGISTRY_INCONSISTENT` refusal.
- Regression test: `🧪️tests/🕸️graph/🪤️registry-transient/🟦️.ts` (real temp tree, a Cargo path dependency, transient pinned registry, independent sqlite oracle for the unowned roots). Red on the old code with the exact stable failure text, green now.
- Green: registry-follow 8, adopt-registry 3, repair-rounds 28, pending-crates 5, owner-withheld 4, owner-isolation 22, task-level-failure 6. Unrelated peer failure: project-nodes `🚧️source-failure` (1 of 7).
- The running service host holds the old module; the change applies to the next read.
