# Dependency image lease order

The live setup process held the Dependencies fixed image exclusively while acquiring the JavaScript Source binding gate. The ordinary `withRepositoryCacheStoreV1` path already opens a checked shared borrower. In the Darwin provider, a warm open takes shared custody immediately, and an image prepared under an exclusive mount guard releases it before reacquiring and revalidating shared custody. The actual exclusive holder was the protected setup producer in `completeRepositoryDependenciesV1`.

Protected dependency production, probing, planning and selected retirement all take the image first. The binding gate now uses one genuine nonblocking SQLite-backed acquisition under exclusive image custody. A busy gate returns `{acquired:false}` after the protected image and lease infrastructure have settled, allowing bootstrap's existing cancellation-aware bounded retry to run outside the image. Actual maintenance still requires a genuine exclusive image lease throughout effects. Ordinary shared builds and readers keep their current custody and coalescing. Generation and unready-capsule pins in the protected retirement path already use nonblocking acquisitions. The global lease-order policy remains unchanged.

Moving the binding gate before the image in setup alone would invert the order against ordinary readers, which take the image shared before the gate. The nonblocking protected acquisition removes hold-and-wait from the current edge and avoids introducing that cycle. The dependent Source-binding and generation helpers still validate the exact original lease for authorized effects. A non-contention exception or cancellation continues to propagate rather than being turned into a retry.

The focused Bun suite passed seven tests, including the new protected-gate laws under enforced order, cancellation, existing setup bounded waits, and a live process holding the image shared. The independent Python SQLite query matched all three shared JSON scenarios. The original Darwin setup was left running and was not used as a replay test. The patch targets exclusive protected acquisition in Dependencies. General shared image rank diagnostics and protected Graph acquisition remain outside this change.
