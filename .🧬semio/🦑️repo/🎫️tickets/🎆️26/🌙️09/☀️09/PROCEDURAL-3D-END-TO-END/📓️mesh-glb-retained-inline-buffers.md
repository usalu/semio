# Retained GLB inline buffers

The original `brep.mesh.importGlb` scene cursor now admits a directory for all declared buffers and prepares it one record at a time. It scans an inline data URI header in bounded turns and validates one padded standard Base64 quartet per Work turn with the shared codec. It retains positions and byte extents into the original parsed URI. An accessor reads up to twelve decoded octets in fixed scratch storage, so inline validation and lookup never allocate a duplicate decoded buffer. Embedded BIN slices stay borrowed. Dense and sparse indices, values, normals, coordinates and UVs can reference different declared buffers.

The fixture exercises mixed BIN and inline addressing and a JSON-only GLB with three inline geometry buffers. It uses different supported MIME headers, canonical padding, sparse indices and values in separate buffers, and a malformed unused URI. Malformed or unresolved buffers remain unavailable, so only a reference to them fails the import. An actively used invalid Base64 buffer failed before any geometry allocation in the native harness.

Compiled production code matched the synchronous codec's arrays for both valid fixture forms. The mixed and URI-only documents posted fifteen and fifty-one one-Work quartet-validation turns, respectively, without a decoded-buffer allocation. A denied directory-capacity grant left the frontier unchanged. Cancellation after five inline quartets released the remaining 50,836 bytes and balanced the original allocation and release ledger. The large 4,100-triangle dense fixture and sparse index fixtures continued to pass. The independent GLTFLoader read both forms and the compiled native GLB. The portable mesh suite passed ten tests with 24,374 assertions. Scoped Rust syntax, whitespace and path-length checks passed.

The registered Flow suite now consumes the mixed buffer fixture and adds a cancellation case during inline Base64 validation. It remains pending the linked native build.

Very wide GLB objects still use the existing extended decoder. The ordered Pack JSON object currently uses a linear key lookup and this task keeps the existing fixed-width retained metadata contract. Wide support requires staged key lookup or a bounded indexed projection before running scene/accessor operations. This work leaves the outer transport Base64 budget and contiguous output array extent unchanged.
