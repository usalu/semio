# Offload: `#[path]` that climbs out of a module directory and back in by name (2026-11-23)

## Symptom
Hub flow component build (`repo run semio-hub-flow-component:component -c prototype --exclude-dependencies`) failed after 74 min:
`semio-framework-intrinsic-size: error: couldn't find file .../📏️intrinsic-size/📦️packages/🦀️rust/../../../📏️intrinsic-size/🦀️.rs` at `mod component;`. The earlier procedural build hit the same error and it was wrongly dismissed as transient.

## Root cause
`planOffloadV1` (`🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🏗️build/🌐️remote-execution/🚀️offload/🗺️paths/🟦️.ts`) ships a unit as: `reachedFilesV1` closure (it already follows `#[path]`, `cfg_attr(.., path)`, `include*!`, WIT/witx bindings), rooted at the common ancestor `shipped` of the manifest and every reached file. When the compile runs in the manifest directory (non-anchored), `shipped` is placed under the fixed virtual name `virtual.package`.

intrinsic-size is laid out as manifest and `[lib] path` in `📏️intrinsic-size/📦️packages/🦀️rust/`, with `#[path = "../../../📏️intrinsic-size/🦀️.rs"]`. `shipped` = `…/📏️intrinsic-size`. The closure was complete (the file WAS shipped, at `<virtual.package>/🦀️.rs`), but rustc resolves the attribute textually on the worker: three levels up from `<virtual.package>/📦️packages/🦀️rust` leaves `virtual.package`, then descends into a directory named `📏️intrinsic-size`, which does not exist because the module directory was renamed to `virtual.package`. The relocation (`<name>-<version>/` in the diagnostic is only the remap of the manifest) broke every `#[path]` that climbs above the shipped root and descends again by the root's own name. 504+ shims under `🧰️framework` use `../../../<module>/…` of this shape (about 520 files with `#[path = "../../…name/…"]`), so any of them that is offloaded unanchored fails the same way.

## Fix
- `climbAboveV1(entry, reached, shipped, manifest)` (same file): measures, per `#[path]`, `cfg_attr(.., path)`, `include*!` literal and binding path, how many directories above `shipped` the text climbs.
- `planOffloadV1` keeps that many real trailing directory names of `shipped` in the virtual root (`virtual.package/📏️intrinsic-size`); the root is used consistently for the file placement, package virtual path, source name, mapping back to the requester and the `--remap-path-prefix` names. Climb 0 (all other layouts) yields exactly the old plan, so existing plans and cache keys are unchanged.
