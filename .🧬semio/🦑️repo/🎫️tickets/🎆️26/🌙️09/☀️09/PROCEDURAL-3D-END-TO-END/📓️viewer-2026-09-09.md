# 👁️ Generation3d viewer — end to end (2026-09-09)

Packet: `👁️viewer/**` of `✏️s/🔌️plugins/🌀️procedural/🗿️artifacts/🧊️generation3d/🏅️standards/🔖️1/🪆️subsets/✳️any`,
plus two named cleanups in the sibling editor surface (`👥️set-contributions`, `🗺️reorganize`'s test).

## 0. TL;DR

Before this packet a user opening a generation3d artifact **read-only** got a single full-pane
`MeshWindowKit` scene, a hardcoded camera, no chrome, no hover, no selection, no presence, no config
and exactly one inert command (`Generation3dViewCommand::Noop`). The whole fixture was re-evaluated
from scratch on **every repaint**.

After it, the same user gets a real `World3dScene` bound to the framework's `graph` interaction
domain (live hover + selection), an orbit/pan/zoom preview camera, four shading modes, three LOD
steps and a full sun rig — **seven `InteractiveJobClassification::Migrated` actions**, each with an
exact app-owned bounded reducer, retained tool id, publication contract and en/de label — plus its
own persisted view-state config (four authored mutation leaves), shareable presence, and an
ephemeral local-only evaluation cache that replaces the per-repaint re-evaluation.

## 1. The framework blocker that had to be closed first

`InteractiveJobClassification::Migrated` is the **only** UI-dispatchable classification
(`validate_ui_dispatch_classification`, `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:11062-11068`),
and a `Migrated` verb without an **exact app-owned** reducer factory is rejected at dispatch with
`interactive-job.missing-owned-reducer` (`…/🔌️plugin/🦀️.rs:17044-17045`, `:20990-20997`).

The four hooks that supply that proof — `bounded_first_step_tool_proofs`,
`register_tool_job_factories`, `build_tool_job`, `build_instance_operation_owner` (plus
`retained_window_transient_target`) — existed on `ArtifactEditor` and were forwarded by
`EditorApp<E>`, but **`ArtifactViewer` declared none of them and `ViewerApp<V>` forwarded none**.
Verified by reading the whole `ViewerApp` `ArtifactApp` impl and by grepping every
`bounded_first_step_tool_proofs!` call site in `✏️s/**` — 30 hits, all under `✏️editor/`, none under
`👁️viewer/`. So *no viewer in this repo could have a live action at all*; the generation3d viewer's
inert `Noop` command was a symptom, not a design choice.

Closed additively, no behaviour change for any existing surface:

- `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:24975-25010` — five new defaulted
  `ArtifactViewer` methods, mirroring `ArtifactEditor`'s (`:24506-24552`) but typed against
  `ViewerApp<Self>`; each defaults to the same empty/fail-closed value the runtime already used.
- `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:25597-25614` — `ViewerApp<V>` now forwards
  all five to `V`, exactly as `EditorApp<E>` forwards to `E`.
- `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:10012-10096` — new `view_commands!` macro, the
  read-only twin of `app_commands!`: same generated surface (enum, `TOOL_JOB_IDS`, `command_id`,
  `ToolCommandCatalog`, `OpText`/`OpBinary`) but `dispatch` returns `ViewEmit<ConfigMutation>`
  instead of `Emit<Mutation, ConfigMutation>`. A viewer's typed command table is therefore
  **structurally** incapable of carrying a document or draft mutation — the read-only guarantee is a
  property of the generated type, not a convention each payload module has to remember.

`cargo check -p semio-framework-plugin` over these edits alone: **0 errors, 0 warnings**, 3m22s
(`$S/viewer-1.log`, copied to `🗑️generated/`).

## 2. Design

### 2.1 View-state config (`👁️viewer/🎚️config`) — schema-first, real leaves

`Generation3dViewConfig { lod_mode, show_mode, preview_camera, sun_json }`
(`👁️viewer/🎚️config/🦀️.rs:70-84`), the read-only subset of the editor's `Generation3dConfig`. The
editor's flow-graph `camera`, `selected_generation_id` and `preview_eval_text` are deliberately
absent: the viewer has no graph window, no generation list, and keeps its evaluation in the
ephemeral lane instead (§2.3).

Schema-first triple: `🧬️schema/🔣️.json` (draft-07, `x-semio-state: config`), `🧬️schema/🦀️.rs`
(`ArtifactSchema`, id `s.generation.3d.viewer.config`), `🧬️schema/🟦️.ts` (interface + guarded
parsers), plus `🔗️.graphql` and `🛰️.proto` so the `app-schema/facet-completeness` gate's five-format
set is complete.

The mutation aggregate is `dsl::Mutations`-derived over **four real authored leaf directories**
(`👁️viewer/🎚️config/🧬️schema/🧬️mutations/{👁️set-show-mode,🔬️set-lod-mode,📷️set-preview-camera,🌞️set-sun}`),
each with its own `🦀️.rs` (`dsl::MutationLeaf` + `protocol::MutationKind` with a real per-leaf
`inverse`), `🔣️.json` descriptor and `🧬️schema/🔣️.json` payload schema. This is the shape the
leaf-ownership contract requires (`26/09/02/PUZZLE-3D-END-TO-END/📓️blocker-stdio-mutation-leaf-ownership.md`:
`provenance.mutation_root == scope.mutation_root`, `descriptor.owner` an immediate child of the
aggregate's own mutation root, provenance derived from the leaf's **physical location**). The
editor's own config/presence aggregates are hand-written with `⚠️ PROVISIONAL` descriptors whose
`owner` paths do not exist on disk (`✏️editor/🎚️config/🦀️.rs:252-256`); the viewer's do exist, and a
unit test asserts each `DESCRIPTORS[i].owner` is a real directory carrying both JSON files
(`👁️viewer/🎚️config/🧪️tests/🔬️unit/🦀️.rs`, `every_view_config_leaf_owner_directory_exists_on_disk`).

Per-leaf `inverse` also means the viewer's config is **genuinely invertible**, where the editor's
aggregate can only return a whole-config `Snapshot`.

### 2.2 Presence (`👁️viewer/👥️presence`) — replaced `📌️.empty.md`

`Generation3dViewPresence { preview_camera, show_mode }` — the same two facets the editor's
`Generation3dPresence` shares, minus the flow-graph camera the viewer has no window for. Two
authored leaves (`📷️set-preview-camera`, `👁️set-show-mode`). Hover and selection are **not** here:
they broadcast on their own through the framework's typed `PresenceInteraction`, declared by
`create_generation3d_viewer`'s `.interaction("graph")` with `selection.broadcast = true`.

### 2.3 Transient (`👁️viewer/🫧️transient`) — replaced `📌️.empty.md`

`Generation3dViewTransient { preview_eval_text: Option<String> }`, one authored leaf
(`👁️set-preview-eval`).

**On the brief's wording ("declare the ephemeral hover/selection items the framework expects").**
The framework expects a surface to declare *no* hover/selection items of its own. Hover lives in the
ephemeral `InteractionHoverState` and selection in the persisted `protocol::InteractionState`; both
are read through `InteractionView` and the framework's own doc says so plainly
(`📓️kernel-and-preview-audit-2026-09-09.md` §4, quoting `PreviewInteractionMarks::from_interaction`:
"Reads the framework-owned domain … The app stores neither itself"). Copying them into the viewer's
transient would create a second source of truth for one fact and would go stale on every framework
prune. So the transient declares the ephemeral item the viewer genuinely **owns**: the evaluated
flow output its preview repaints from. That is what actually made the lane non-empty *and* fixed a
real defect — the old viewer re-ran `FlowHost::evaluate()` over the whole fixture on every single
render (`👁️viewer/🎭️modes/👁️view/🪟️windows/👁️preview/🦀️.rs:162-167` before this packet).

Hover/selection wiring is §2.5 instead, and it is real.

### 2.4 Commands (`👁️viewer/🎮️commands/*`) — seven live actions

| dir | payload | action id | wire key | config leaf written |
|---|---|---|---|---|
| `👁️set-show-mode` | `SetShowMode { value }` | `setShowMode` | `show-mode` | `SetShowMode` |
| `🔬️set-lod-mode` | `SetLodMode { value }` | `setLodMode` | `lod-mode` | `SetLodMode` |
| `📷️set-camera` | `SetCamera { camera }` | `setCamera` | `camera` | `SetPreviewCamera` |
| `🌞️toggle-sun` | `ToggleSun {}` | `toggleSun` | `toggle-sun` | `SetSun` |
| `🧭️set-sun-azimuth` | `SetSunAzimuth { value }` | `setSunAzimuth` | `sun-azimuth` | `SetSun` |
| `🌄️set-sun-elevation` | `SetSunElevation { value }` | `setSunElevation` | `sun-elevation` | `SetSun` |
| `🔆️set-sun-intensity` | `SetSunIntensity { value }` | `setSunIntensity` | `sun-intensity` | `SetSun` |

`setActiveExample` is editor-only and was skipped, as briefed (it replaces the document fixture —
structurally impossible from a `ViewEmit`).

Each payload module's `handle(payload, doc, cfg) -> Result<ViewEmit<Generation3dViewConfigMutation>, Fault>`
and each has a `🧪️tests/🔬️unit/🦀️.rs` that dispatches through the **real** interactive-job pipeline
and asserts the document is untouched.

The wiring mirrors the editor's exactly (`👁️viewer/🦀️.rs`):

- `:44-57` typed command enum via the new `view_commands!`.
- `:69` `GENERATION3D_VIEW_TOOL_IDS` — the retained tool-id list, a bijection with the enum rows.
- `:92-109` `generation3d_view_retained_reduce` — the one reducer, converting `ViewEmit` into the
  runtime `Emit` field-by-field so the document/draft lanes stay empty by construction.
- `:125-232` `Generation3dViewCommandWork` — a **real Work completion**, not a one-shot: it settles
  the config operation, then drives a `FlowEvalSession` to quiescence in bounded
  `ArtifactCommandWorkStep::Progress` steps (stage `generation3d-view-preview-evaluation`, en/de
  preview text), with `begin_close`/`close_step`/`terminal_is_empty` cancellation, and finishes with
  `CompleteWithEphemeral` carrying **presence** (camera + show mode, so a co-viewer follows) and
  **transient** (the fresh evaluation). This satisfies CLAUDE.md's "progress and cancellation for all
  expensive operations" for the viewer's own evaluate/tessellate path.
- `:234-299` `Generation3dViewBoundedCommandJobFactory` — `classification() == Migrated`,
  `payload_schema_id = "generation.3d.view-command.v1"`, exact `TOOL_IDS`, and per-tool
  `PUBLICATION_CONTRACTS` naming **only** `Config`/`Presence`/`Transient`. Never `Artifact`, never
  `Draft` — that table is the runtime half of the read-only guarantee, and a unit test asserts it.
- `:412-425` `bounded_first_step_tool_proofs!` with a real `factory_type:`
  (`Generation3dViewBoundedCommandJobFactory`) — the omission that memory records as making *every*
  action dead is explicitly avoided.
- `:545-559` `.action_interactive_job(<id>, Migrated)` for all seven, each with an
  `ActionDefinition::new(..., LocalizedLabel::native("<en>", "<de>"), ActionKind::View, <icon>)`.

### 2.5 Hover / selection

`create_generation3d_viewer` declares the same `graph` `InteractionDefinition` the editor does —
`node`/`edge`/`handle` granularities, `HierarchyProvider::Topology`, `hover.transitive = true`,
`selection.broadcast = true` — and binds it to the preview window with
`.window_kind_interactions(preview::WINDOW_KIND_ID, [InteractionRef::new("graph")])`
(`👁️viewer/🦀️.rs:560-583`).

Three things had to be true for a pick to land, and all three are now:

1. **The window must be a world-3d surface.** The old viewer used `MeshWindowKit`; the preview window
   now declares its own `WindowKindDefinition` with `SurfaceKind::World3d`, id `procedural-view-preview`,
   body key `procedural.view.preview` (`👁️viewer/🎭️modes/👁️view/🪟️windows/👁️preview/🦀️.rs:43-60`), and
   renders a `World3dScene` with `domain_id = "graph"` / `domain_granularity_id = "handle"` (`:402-427`).
2. **The picked ids must be declared.** `validate_state` prunes any hover/selection id absent from
   `interaction_topology`, so the viewer now declares the same topology the editor does — every
   widget a `node`, every visible port a `handle` parented to it, every synapse an `edge`, and each
   `Cluster`'s nested neurons `node`s parented to their cluster (`👁️viewer/🦀️.rs:433-465`, off the
   same `fixture_to_workflow` projection via `generation3d_view_port_ids_by_node`, `:304-308`).
3. **The instances must carry those ids.** Every emitted instance carries
   `interactionId = {widgetId}@{channel}` plus live `hovered`/`selected` flags
   (`👁️viewer/🎭️modes/👁️view/🪟️windows/👁️preview/🦀️.rs:359-370`).

`Generation3dViewMarks::from_interaction` (`…/👁️preview/🦀️.rs:115-122`) is the read-only twin of the
editor's `PreviewInteractionMarks::from_interaction`, with the identical three-level match (instance
id / channel id / bare widget id) that makes hover bidirectional. It is **duplicated, not imported**:
`policyViewerPurityBreaches` forbids any file under a `👁️viewer` dir from matching `::editor::`
(along with `.mutation(`, `Emit::mutations`, `artifact_mutations`), and the sibling file lives in
`✏️editor/🦀️.rs`, which another agent owns this ticket. The duplication is explicit and documented at
both ends, matching the file's own pre-existing "read-only twin" convention.

`render_with_request_context` resolves the marks once per render and threads them plus the ephemeral
evaluation into the body (`👁️viewer/🦀️.rs:487-499`).

### 2.6 Window measures

`ArtifactViewer::window_measures` now returns the preview window's chrome
(`👁️viewer/🦀️.rs:503-505` → `preview::preview_window_measures`, `…/👁️preview/🦀️.rs:96-99`):

- **Show** select — Shaded / Shaded + edges / Wireframe / Points → `setShowMode`.
- **Detail** select — Coarse / Medium / Fine → `setLodMode` (the editor puts LOD on its *flow* window;
  the viewer has no flow window, so it belongs on the preview).
- **Sun** group — `world3d_sun_measures` → `toggleSun` / `setSunAzimuth` / `setSunElevation` /
  `setSunIntensity`, byte-identical to the editor's group.

All addressed at `GENERATION3D_VIEW_APP_ID = "procedural3d-view"` through
`generation3d_view_action`, so the chrome dispatches into the viewer's own controller.

The shading mode is not cosmetic: `apply_show_mode_mesh` drops the triangle channels for
`wireframe` and the edge/normal channels for `points` before the payload is serialized
(`…/👁️preview/🦀️.rs:262-281`), and `preview_selection_json` sets `showEdges` accordingly (`:384-396`).
`gumballActive` is hardcoded `false` and `transformMode` empty — a transform handle is a mutation
affordance and a viewer emits no mutations.

  — a nested git repository (gitlink) left inside an unrelated 2026-08-17 ticket folder. That is
  another ticket's artefact and outside this packet's lease. The taxonomy policies this packet needs
  are pure exported functions, so `🐍️viewer-policy-check.ts` (kept in this ticket folder) calls them
  directly instead.
- `emoji-prefix / folder-name-emoji-not-unique`: adding `👁️viewer/🧪️tests/🔬️testkit` beside the
  existing `🔬️unit` adds **one** breach of a class with 1287 repo-wide instances (11 already inside
  this plugin, including the editor's own `🔬️testkit`/`🔬️test-support`/`🔬️unit` trio). The lock helper
  was folded into the testkit rather than given its own `🔬️test-support` dir specifically to keep this
  to one, and the naming mirrors the editor for consistency.
- The viewer's serialization lock (`testkit::lock()`) is its **own** mutex, not the editor's
  crate-wide `test_support::lock()`, because `policyViewerPurityBreaches` forbids a viewer file from
  naming `::editor::`. Viewer tests serialize against each other but not against editor tests that
  touch the same process-wide brep/neuron caches. The pre-existing viewer test had no lock at all, so
  this is strictly an improvement; a genuinely crate-wide lock would need the helper rehomed to the
  artifact level (`🗿️artifacts/🧊️generation3d/🦀️.rs`), which is outside this packet's lease.
- The viewer declares no `app_schema()` descriptor. `AppSchemaDescriptor` bundles config **and**
  presence facets; both five-format sets now exist on disk, so wiring it is a small follow-up rather
  than a gap in the schema files.
