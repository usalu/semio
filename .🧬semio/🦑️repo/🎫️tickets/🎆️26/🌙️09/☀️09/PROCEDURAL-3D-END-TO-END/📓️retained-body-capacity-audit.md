# Retained Body Size Audit

## Limits and concrete form defect

The schema-owned budget in 🧰️framework/🔨️modules/🖱️ui/🧬️contract/📏️budget/🧬️schema/🔣️.json sets documentNodes=128, textMaxBytes=512 and fixedListItems=32. The contract derives UI_DOCUMENT_PATCH_OPS=1153 and built-child maximum=128. The retained runtime also charges up to 4,097 items, an 8 MiB per-surface resident ceiling, a shared aggregate permit and 32 KiB reconciliation work pages; 32 KiB is a per-step bound, not the total payload size. These budgets interact; node arithmetic alone is not a guarantee of admission.

The shared plugin's 🪟️window/🦀️.rs section_text_chunks packs up to 33 UTF-8 slices into each text leaf. ASCII can fill 16,896 bytes per leaf; paged_text_carrier_nodes conservatively prices 16,797 bytes per leaf, plus a carrier root and any grouping nodes. The complete source is materialized into the mounted document. For a single ungrouped long text question, generation_form allows at most 126 field nodes, meaning its conservative calculation accepts at most 123 leaves (2,066,031 bytes); an answer beyond that fails field-budget. When the form requires multiple pages it uses 102 nodes per page, so one ungrouped question is limited to 99 leaves (1,662,903 bytes). Section headings reduce that. These are accounting thresholds, not certified admissible maxima: resident/item costs and other mounted UI can reject earlier.

A concrete undercount exists in ✏️s/🔌️plugins/🌀️procedural/🫀️foundation/🖼️semantic-ui/🦀️.rs generation_form: text/longText adds paged_text_carrier_nodes, but image falls through to a fixed 2 nodes even when image_with_source adds a root and many leaves. For example two authored ASCII data URI sources of about 1.1 MB each require roughly 66 leaves apiece, over the document limit together, while the paginator sees only four field nodes and selects one page. If each is individually admissible they could be paginated separately. Charge the same carrier estimate for nonempty >512-byte image src, include its field/image nodes, and add tests with two sizeable sources and a single oversized field. The larger single-source case needs the resource route below; fixing accounting alone cannot make it fit.

Base64 increases binary size by roughly one third: a 2 MiB image produces ~2.67 MiB of URI body and already needs ~159 ASCII leaves, excluding form and carrier nodes. A multi-megabyte authored answer likewise exceeds one form field's admission. Loading all bytes synchronously into a carrier also provides no progress or cancellation.

## Reusable route and ownership

The existing tree/form pagination API seats complete fields; it cannot page within one image or text input while the present consumers require a complete retainedTextBody before showing it. Merely increasing pages or using the existing carrier as a sparse resource is therefore not a drop-in solution.

A concrete framework-owned starting point is the existing media export lifecycle: 🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🎬️media/🚚️lifecycle/🟦️.ts defines submit/poll/cancel/take-page, authority checks on app instance, parent document, revision, operation and generation, bounded pages, terminal draining, progress and cancellation. Its browser host in 🎬️media/🌐️browser/🎛️host/🟦️.ts disposes and revokes the object URL. Generalize the underlying transport into a source-neutral framework resource contract (do not label an image as audio/video): a stable resource descriptor in the semantic Image, producer-owned revision/generation and bounded page producer, renderer-owned request and lifecycle, cancellation on replacement/unmount and stale-owner rejection. React consumes bytes into an owned Blob URL; native WGPU needs the corresponding resource receiver and raster-cache ownership. Generate's InputImage producer and ImageWindowKit both bind this same resource interface. Editable text needs a separate windowed editing/publication contract with the full text owned by the playbook and only visible segments in the retained document; the media output protocol does not provide text editing semantics.

This is an implementation direction, not a claim that existing media playback can be directly used: its current output port is playback:out and its descriptor is artifact-media-export, tied to media producers. The plugin Host BodyReader explicitly replays an already fully buffered blob and is not a streaming backend. Native image transfer is not established by this audit. New schema, both renderer routes, resource lifecycle tests and actual producer bindings are required. Verify cancellation, out-of-order/replaced revisions, exact bytes, missing resource, and large image rendering, plus edit/commit and keyboard behavior for long text.
