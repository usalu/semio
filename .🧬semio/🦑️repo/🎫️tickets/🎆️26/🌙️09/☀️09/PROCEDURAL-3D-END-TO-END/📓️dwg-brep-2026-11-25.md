# DWG, BRep and retained exchange: verified gaps and design (2026-11-25)

Scope this session: stdio dwg crates and the brep extension only. Procedural and flow changes are prepared, not applied (`dwg-procedural-prepared/`). No cargo ran (other cargo builds were active); only the TypeScript law ran.

## Verified in current source

1. **Mesh only.** The generation3d export leaf (`io/📤️export/.../🖊️dwg/🔖️ac1018`) takes a `SemioMeshSnapshot` and writes one `DwgGeometry::PolyfaceMesh`. The import leaf refuses drawings with no polyface or 3DFACE. The `brep.interchange.exportDwg` widget tessellates (`Pipeline::tessellate`) before `mesh_to_dwg_drawing`. No BRep survives.
2. **Dialect.** There is one writer: `dwg_to_bytes` -> `DwgSnapshot::from_drawing` -> AC1024 object streams. The io leaves are only labelled `ac1018` (registry slug and a stale doc comment that claimed R2004/AC1015). The widget and the leaves already call the same `v_ac1024` writer, so the bytes were never split. The real defects were: three literal `"AC1024"` spellings beside the owning `WRITTEN_VERSION` constant, and the stale label. The `ac1018` standard's own history fixture already mutates to `AC1024`.
3. **Immediate, non-retained.** `ExportDwg`/`ImportDwg` in `brep ext/📏️measure-utilities-and-io` implement `step_plan` as `OperatorPlanAdmission::immediate`, with zero demands, and decode/encode whole files inside `evaluate`. STL/OBJ/STEP have retained jobs (`GeometryOperation::{ExportStl,ExportObj,ImportStl,ImportObj,ImportStep,ExportStep}` in `〰️analytic-curves`).

## What the format layer lacks for BRep

`DwgGeometry` and `DwgEntityBody` have no 3DSOLID (38), BODY (39) or REGION (37) variant. The reader names these type codes only in a label table. Missing, in order:
- a typed modeler-geometry entity (version, SAT text or SAB blob, wire/silhouette/history parts) in the schema, proto, graphql and sqlite snapshot;
- an R2010 entity body reader and writer for it;
- an ACIS SAT/SAB emitter and parser for our BRep (the repo has STEP only; no ACIS code exists);
- an independent oracle (acadrust 0.5.5 exposure of Solid3D must be checked before choosing).
Until these exist DWG must stay a faceted exchange and say so (prepared `brep-faceted` diagnostic, English and German).

## Decision (clean long-term design)

- **One dialect owner:** `WRITTEN_VERSION` (dwg snapshot crate). Every writer, reader branch and demo stamps through it. The `ac1018` stdio standard stays a read-only input dialect; the registered leaf slug moves to the written dialect when procedural reopens.
- **One retained route per direction**, same stage shape as STL/OBJ: export = certified tessellation (existing `NativeMeshExport` stages) -> stepped DWG writer cursor -> stepped base64; import = base64 cursor -> `DwgDrawingRead` -> `DwgMeshProjection` -> `MeshImportCursor` publication. Cancel retires every owner; progress is the phase fraction. The widget already runs the import chain stepped; Flow reuses those cursors.
- **BRep carried** only through the ACIS body entity once the four format items above land; until then tessellated, with a loss diagnostic.
