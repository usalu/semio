# Coincident World Instance Hover Audit

React World3dHost `👇️hover-and-placement/🔶️active-utility/🟦️.ts:122` maps the one raycast instance id to one interaction target. `🔗️instance-selection/🟦️.ts:663` resolves its own `interactionId` and `interactionGranularityId`; a multi-target deduplicator exists at line 672. `🖱️interaction-domain-args/🟦️.ts:9` serializes zero or one target as JSON text. Thus shared mesh alone does not associate coincident input and output.

Native `♾️infinite/🌍️world/🧲️cursors/🎯️ray-and-component-pick/🦀️.rs:54,218,249` retains a single closest hit, using strict less-than; the first tied instance wins. At lines 318–365 it resolves one interaction target into one `WorldFlatAction`, and suppresses duplicate publications by one local id/granularity. Component pick targets are separately prioritized and should retain their existing behavior. The test-only oracle in `🧵️interaction/🖱️pointer-and-picking/🦀️.rs:354` likewise publishes one hit. Do not infer a group from identical mesh alone: transformed geometry and unrelated objects may reuse a mesh.

Recommend producer-authored group identity or explicit target list on the affected world instance records, assigned only when the producer knows those records represent the same physical authored geometry. Resolve that group after the winning instance is picked, deduplicate by `(granularity,id)`, and publish all targets in one pointer-channel interactionHover event; leave ordinary ray ordering, individual selection, component targets and null clear semantics intact. Group membership and comparison must use the entire resolved target set so changes within a group are not suppressed. The native retained/parsed scene representation and its incremental cursors need the same group mapping, bounded and revision-aware; merely expanding React cannot provide parity. A producer-supplied target list avoids a scan per pointer move if naturally available; if using a group key, preindex it during scene admission.

The interaction contract already transports `targets` as a JSON-encoded string, not a structured array (`♾️infinite/🌍️world/🧲️cursors/🦀️.rs:182`); React selection already sends multiple targets. Native `WorldInteractionText` uses `ACTION_STRING_BYTE_CAPACITY` and the action contract defines this as 4 KiB (`🧰️framework/🔨️modules/🖱️ui/🎬️action/🧭️intent-address-and-sequencer/🦀️.rs:13`). Native flat hover actions currently represent just one target, so expand the bounded plan/serialization explicitly and fault on overflow rather than truncating. The group limit must account for escaped JSON bytes and all action credits. Verify downstream framework hover-state capacity/semantics before assuming all targets survive; renderer event capacity alone does not prove that.

No production changes or official Cargo runs were made in this audit.
