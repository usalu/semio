The unit root is .cache/b/r/m/u, with lock claims in u/k, pooled lanes in u/l, per-lane live markers in u/l/<id>/v. Unit-cache/🧵️lane/🦀️.ts:99–106 removeLaneV1 obtains the same u/k/lane-<id> claim used by lane acquisition, then checks live markers and optionally performs retention before removal. Collector/🧹️gc/🟦️.ts:112–132 takes u/k/gc through tryClaimWithBallastV1, performs lock-aware incremental, lane and unit collection, and releases its claim. When an ENOSPC image has no ballast, neither collector claim nor lane claim creation is assured. Redirecting only recovery claims to another filesystem changes the namespace and cannot exclude existing or future ordinary lane acquirers.

The existing issued host-backed route is recoverCompactCompilerHeadroomV1 in repo library/⚡️caching/💾️storage/🔒️enforcement/🏗️compiler/📏️capacity/♻️recovery/🟦️.ts:17–20: it requires original ScriptInvocation, matching issued control, storage reservation and compiler-writer custody; it opens the declared diagnostics store through withRepositoryCacheStoreV1, makes its scoped scratch under diagnostics.root/tmp, and uses machine lease data at .cache/b/l/m/data while pruning finalized compact prototype/release compiler stores. This is a safe partner for scoped diagnostics and writer coordination, not an already implemented alternative unit-cache lane-lock namespace. The same file :23–26 calls the ordinary unit collector for lane recovery and inherits its image-lock limitation. A real host-backed lock change must migrate both normal lane/collector claim users and recovery to one issued shared coordination path with tests for old holders, startup races and cancellation; preserve the existing reservation, retention and root checks. No ready-to-use safe command for moving those locks was found.
