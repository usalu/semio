# Shared Preview Mesh Table Review

The current shared table compares exact evaluation text, `PreviewEvaluationSource`, widget order, show mode and tolerance, plus `(preview_mesh_cache_identity, preview_mesh_epoch)` and every resolved source handle. Identity is allocated for each `FlowEvalSession::new`; replacement in that session changes the residency epoch. Fallback is re-resolved before every lookup, so a changed resolved handle or epoch invalidates the table. Edit derives source revision and component pickability from each placement on every publication and suppresses grouped hover aliases in component mode. The same table owner is shared by Edit, Generate and View, but distinct session IDs prevent cross-app cache reuse. No concrete stale-result or component-pickability defect was established by source inspection.

The registered fixture exercises interleaved sessions, replacement, fallback, current policy, mode, detail and visibility. Its retained-table assertions check pointer identity; it does not directly count mesh conversions (the exported `preview_tessellation_count` counts missing resident meshes, not conversions). The table remains in one thread-local slot after a session closes until replaced or reset; this is bounded to one table but can retain its full JSON and source. No direct session-close eviction was found. This is a lifetime limitation, not an observed unbounded leak. No tests were run.
