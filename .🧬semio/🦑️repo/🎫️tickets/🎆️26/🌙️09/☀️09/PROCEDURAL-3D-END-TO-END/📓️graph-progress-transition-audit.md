# Graph Progress Transition Audit

The dry-run and dev logs show the same leader, but dev explicitly says it is **waiting** behind a separate load sharing the fact store. The leader's inventory elapsed counter reset from 3,678 to 4 seconds while outer slice elapsed continued from 3,705 to 3,707 seconds; observation counts fell and owner/memo counters disappeared. `slice-report/🟨️.mjs` maintains monotonic counts only within a single active inventory step; a new step creates a new counter. This establishes a new inventory invocation, not by itself whether it is a post-inference validation or retry.

The graph loader calls `settledInventory` initially and again after each graph inference, before comparing membership, admission and source facts and sealing (`🕸️graph/📥️load/🟦️.ts` lines 187–188, 219–243). It also retries inventory on `BUILD_MEMBERSHIP_CHANGED` inside `settledInventory`, and calls inventory after an inference exception. A successful post-inference recheck is therefore a normal progressive explanation, but the displayed line lacks phase diagnostics and is insufficient to prove that specific route or rule out membership retry. No `[graph-repair]`, `[graph-retry]`, or `[graph-seal]` line was observed in this log at inspection. The progress reset is not evidence that all previous durable memo work was lost.

The slice pool shares only requests with identical root, arguments, tool and graph policy (`🏡️resident/🏗️composition/🌐️host/👷️slice-pool/🟨️.mjs` lines 141–169). An abort terminates the worker when its last client leaves; the queued dev request is not an attached client to the leader, as its explicit queue message and differing dry-run arguments indicate. Dropping the dry-run can free the fact-store queue but cannot preserve that active worker for dev; durable published memo may survive, with no guarantee on work still in memory. Cancellation is not a demonstrated speedup.

Both requests already select the canonical single project/target; source performs its transitive owner admission, so the large observation count does not demonstrate an accidental whole-workspace invocation. No alternative target-focused, freshness-preserving path was established. No job, cache or repository state changed.
