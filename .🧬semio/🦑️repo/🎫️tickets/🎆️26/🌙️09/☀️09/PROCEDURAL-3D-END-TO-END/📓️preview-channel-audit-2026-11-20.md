# Preview channel production audit

The artifact composition `🗿️artifacts/🧊️generation3d/🦀️.rs` registers edit and generate preview window definitions at lines 186 and 189. The production editor edit preview builds its world payload in `✏️editor/🎭️modes/✏️edit/🪟️windows/👁️preview/🦀️.rs`; generate imports that same `preview_payload`, and the viewer independently builds its retained mesh table in `👁️viewer/🎭️modes/👁️view/🪟️windows/👁️preview/🦀️.rs`. Both use the shared `🧵️preview-eval/🧊️preview-geometry/🦀️.rs` channel enumeration and show-mode projection. Both enumerate all outputs of each widget for which `widget_previews` is true, with input fallback when the output object has no channels. Selection is carried as per-instance flags; it does not change which geometry is enumerated.

The collector handles only object-wrapped `handle` strings, not a bare handle string. It treats every object containing numeric x/y/z as a point unless its schema is `vector`, which can also project non-geometric records as markers. Vector geometry is one segment from the origin, without an arrowhead, so direction is not visually distinguished from its reverse by shape alone.

The enumerator supports BRep handles, `$schema: mesh` packed previews, XYZ points and vectors, arrays and numeric-key `$schema: list` dictionaries. Scalar, string and boolean values are not 3D geometry. A shared windowed semantic tree now lists primitive input and output channels beside editor, generate and viewer previews. Rows use the existing graph port target for hover and selection; both renderer implementations consume the shared tree contract. The scene and tree are placed in separate growable stacks; the tree has a vertical scroll layout. A renderer-neutral composition fixture checks the two wrappers, graph interaction domain, port granularity and hover binding. Runtime rendering, default sizing and interaction remain unverified. The initial audit found structured objects were not recursively traversed and empty output objects blocked input fallback; those gaps were addressed concurrently after this audit. Geometry behind unrecognized handle spellings is also omitted. These are static source findings; no claim is made that all registered operators use those forms.

Wireframe projection previously cleared positions and indices even for an indexed inline mesh with no edge buffer, making it disappear from all three surfaces. The shared projection now derives edge segments from triangle indices for wireframe and shaded-with-edges only when no explicit edges exist, retaining explicit topology when present. Points mode takes edge endpoints when a wire has no position buffer. `🧵️preview-eval/🧪️tests/🧫️fixtures/🪢️wireframe.json` specifies a two triangles, their expected edges, a shared edge emitted once, shaded-with-edges, and points from an edge-only mesh; the Rust fixture consumer checks the projected geometry. This is a triangle-edge fallback, so triangulation diagonals may appear when authored edge topology is unavailable.
