## 9. Procedural workspace "couldn't find file" (mio, errno, memmap2, cranelift-codegen): root cause and fix
Not the registry extraction and not a sandbox: the unit was compiled on another fleet machine (rustc offload) from an input set that lacked files the compiler reads.
- Evidence: `.cache/b/r/m/u/x/offload.jsonl` lists `offload-run` for `cranelift_codegen` (lane `pd6aa91`, 111 MB shipped, 2390 bytes returned = the diagnostic) and the unit-cache event log shows it as `failed` 21 s after it left. The workspace builds fine when the unit stays local, which is why only a loaded, queueing build (this workspace) showed it. The `xcrun ... /var/folders/mr/...` "Operation not permitted" lines are warnings replayed from another machine's cached output (that temp dir does not exist here), not a failure.
- Cause 1 (`mio` `selector/kqueue.rs`, `errno`, `memmap2` `unix.rs`): `reachedFilesV1` (`🏗️build/🌐️remote-execution/🚀️offload/🗺️paths/🟦️.ts`) finds module files with a regex and ships only those. It understood `#[path = "x.rs"]` but not `#[cfg_attr(cond, path = "x.rs")]`, which is how these crates select the platform file. The file was never uploaded, the worker could not read it, and the error text is translated back to the requester's path, so it looked like a local file that exists. rustc reports this as a code-less `couldn't find file`, which `classifyOffloadExitV1` (typed codes only, E0583 etc.) rightly or wrongly counts as a compile result, so there was no local fallback.
- Cause 2 (`cranelift-codegen` `include!(concat!(env!("ISLE_DIR"), "/isle_numerics.rs"))`): the build script sets `ISLE_DIR` to its `OUT_DIR`. Only `OUT_DIR`, `CARGO_MANIFEST_DIR` and `CARGO_MANIFEST_PATH` were rewritten to the worker's root; `ISLE_DIR` travelled as the requester's absolute path. The OUT_DIR files were uploaded, but the worker looked at a path that exists only on the requester.
- Fix: (1) the include scan also takes the `path = "..."` of a `cfg_attr(...)` (multi-line, quoted cfg arguments); over-shipping a not-selected platform file is harmless. (2) every environment value that is `OUT_DIR` or lies below it is carried as the virtual generated path (`SEMIO_ABSOLUTE`/`SEMIO_REL_<name>`), a value that merely contains the real path elsewhere is declined (`unmapped-path`, the unit compiles here); the worker command no longer lists those names twice (real value, then rooted value). Files: `🗺️paths/🟦️.ts`, `📜️action/🟦️.ts`.
- Tests (`🚀️offload/🧪️tests/🟦️.ts`): `a module file named by a cfg_attr path ...` (oracle: rustc `--emit=dep-info` on the same tree; every file rustc reads is in our list) and `an environment variable a build script points into OUT_DIR ...` (virtual path, files shipped, single rooted entry in the command, sibling-path value declined). Both fail on the old code (mutation-checked) and pass now: 32 pass; the one remaining failure there (`workspaceRootFromV1`, recorded cost test) fails before and after because the test temp dir lies inside this checkout.
- Open design question, not changed: a code-less rustc "couldn't find file/read" from a worker could be treated as `incomplete-inputs` (local retry) but that would match text, which the classifier forbids; the plan-side fix removes the known causes instead.
