## Established gap: Generate preview detail selector

The editor mounts the Flow window only in Edit and three different windows in Generate: `✏️editor/🎭️modes/✏️edit/🦀️.rs` and `✏️editor/🎭️modes/🧬️generate/🦀️.rs`. `✏️editor/🪟️artifact-editor-impl/🦀️.rs` publishes the editor's `WindowMeasure::Select` for `lod_mode` only on the Flow window. Both Edit and Generate previews receive `edit_preview::preview_window_measures`, which contains only show mode and sun. Generate consequently exposes no detail control in its mounted windows; a user must return to Edit to change it. The retained job factory reads `input.config.lod_mode` for `preview_tolerance`, so this setting affects the generation preview evaluation as well as the graph.

A feasible fix is to extract the existing `flow::window_measures` LOD select into a shared semantic helper, preserve its existing `GENERATION_3D_LOD_MODES`, localized labels and `generation3d_action("setLodMode", None)`, and add that `WindowMeasure::Select` to the preview chrome in Edit and Generate. It can remain on the Flow window if duplicate access is intentional. Viewer already has the same supported `WindowMeasure::Select` contract and its own `setLodMode` action at `👁️viewer/🎭️modes/👁️view/🪟️windows/👁️preview/🦀️.rs`; do not conflate the separate viewer configuration with editor state. Verify the selected value and action in both locales, a real mode switch, changed tessellation tolerance, and independent viewer state; exercise native WGPU and mounted React rather than only inspecting the projected node.

## Existing common controls and next verification

Generate's production form delegates to `✏️s/🔌️plugins/🌀️procedural/🫀️foundation/🖼️semantic-ui/🦀️.rs`: text and number use semantic `input`, slider uses `slider`, boolean uses `toggle`, single choice uses `select`, and point/vector uses `vector_input` with individually labelled axis commit bindings. Navigation uses semantic buttons and a separate viewport. The generation list uses shared `PanelTreeBuilder`, `tree_item_with_action`, row-target verbs and an inline semantic input. Edit and View previews use shared accessible scene surfaces and `WindowMeasure::Select` plus `world3d_sun_measures`. No second concrete ad hoc control or failure was established from the inspected current paths, so a speculative replacement is not recommended.

A useful second independent verification is an actual mounted generation-list interaction: select a generation, keyboard-focus its name editor, commit a changed name, activate the row's Remove action and verify the correct generation ID, plus test English/German accessible names and focus after removal in React and WGPU. Source evidence: `🫀️foundation/🖼️semantic-ui/🦀️.rs` sets the row activation target with the ID and makes the selected name editor a child; `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🪟️window-kits/🌳️tree/🦀️.rs` and `📊️table/🦀️.rs` define inherited row target and action contracts; the React interpreter's `🧱️elements/🗣️Interpreter/🧱️node-tree/🟦️.tsx` defaults a row containing controls open. This establishes intended wiring, not mounted behavior or WGPU parity.
