# Retained GLB sparse accessors

The original Mesh GLB scene cursor now accepts embedded sparse position, normal, texture-coordinate and triangle-index accessors. It borrows dense and sparse row ranges, checks each declared buffer view, then validates one sparse index per funded turn before allocating geometry. Each output sample uses the sparse replacement when present, the dense base when present, or a zero value otherwise. It applies normalization to that selected value. Each bounded sparse lookup comparison posts original Work before reading its index. An inadequate grant leaves the output row unchanged. The index preflight enforces the strictly increasing, in-range sequence required by [glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#sparse-accessors).

The shared fixture exercises a replacement in dense positions, base-less authored normals, base-less normalized U16 UVs, and sparse replacements in the primitive's own index stream. Three.js independently constructs the same binary fixture from the language-neutral recipe and compares the native writer's result by transformed positions, triangle indices and normal and UV samples. The registered Flow fixture also checks imported polygon topology and UV corners, and cancels the original job during sparse index validation.

The native harness compiled the actual production codec with cached framework crates. It observed four funded vertices, exact synchronous-codec parity, 232,200 cumulative allocated bytes, and no progress under an insufficient one-unit sparse lookup grant. It refused unsorted, duplicate and out-of-range sparse index variants before allocating geometry, with one original Work unit posted for each rejected index. A cancellation after four sparse-validation turns released 66,824 outstanding bytes and balanced the original receipt. The 4,100-triangle dense fixture also passed. The portable editor mesh suite passed nine tests with 24,307 assertions including native bytes and the independent GLTFLoader. The linked Flow suite remains pending disk admission.

Alternate URI buffers and unusually wide object metadata still use the existing extended decoder. The new sparse path applies to the active scene's embedded BIN buffer. Base64 inlet accounting and the contiguous output backing quantum are separate from this work.
