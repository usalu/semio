## Evaluated channel representation

The canonical Flow BRep `geometry_dict` in `✏️s/🔨️modules/🌐️spatial-kernel/⚙️engine/🧠️semio/🌊️session/🧰️operator-registration/🦀️.rs` returns a `$schema: geometry` dictionary with `handle` and `kind`; point and vector constructors likewise use explicit schemas. The inspected preview collector `…/🧵️preview-eval/🧊️preview-geometry/🦀️.rs` only extracts a handle member from an object, never a bare string atom. It accepts a handle-looking member on any non-mesh object, and treats any object with numeric `x/y/z` as point unless its schema is vector. Thus unrelated structured values can be rendered as unintended points; no evidence here establishes bare string handles as a canonical evaluated channel. Before tightening this, inventory nested extension dictionaries and the existing neutral preview fixtures so supported explicit point/vector/plane/geometry and mesh lists continue to work. This is a source finding, not proof that every plugin follows the canonical constructor.
