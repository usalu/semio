# Retained Tessellation Backpressure

The native reactor already keeps each pending extension invocation, its request id, callback address, and original payload in a retained request slot. After every poll it advances the global round-robin cursor, including when the selected invoke reports neither output nor refusal. A different in-flight tessellation therefore returns a zero-work pending step while the guest's tessellation lane is occupied. The next round continues the active owner and retries the waiting requests independently. The guest retains only the admitted original, keeping the existing one-at-a-time session admission and cancellation frontiers valid.

A cancelled waiter that has no guest cursor reports the typed cancellation immediately when the turn has authority. A cancelled owner keeps its original lane while the existing query and output retirement runs under its own context. It releases the lane and reports the typed cancellation only when its cursor is empty. Distinct requests never charge work or alter the original parser, request, query, or output. This is backpressure for bounded work, so the active caller still needs sufficient funded turns before others are admitted. It does not split a single kernel job across another caller's budget.

The language-neutral interleaving fixture gives distinct native lines, node hashes, and windows. The native test covers normal completion for both callers, a cancelled waiting caller, and an owner cancelled after its session query starts. It checks zero fuel and receipt for the waiting turns, request metadata in the returned binary payload, and no guest owner after each case. A lightweight Rust probe injected the actual guest invoke method into a counted fake source contract and passed all three scheduling cases. The production and native test sources parsed, the guest source closure measured 183 active lines (279 with tests), and the scoped whitespace check passed. The linked crate test was not run while the shared native build had priority.

## Remaining Immediate BRep Operators

The registered BRep operator implementations outside the separate mesh owner still contain 18 immediate entry points. These comprise eight solid finishing operators (the two Fillet and two Chamfer variants, the explicit edge variants of each, Draft, and Defeature), Helical Sweep, Heal, Convert To NURBS, and seven exchange operators (STEP/STL/DWG import and export plus OBJ export). This is a registration audit. It does not imply the individual synchronous operations or all source families have production-grade coverage.
