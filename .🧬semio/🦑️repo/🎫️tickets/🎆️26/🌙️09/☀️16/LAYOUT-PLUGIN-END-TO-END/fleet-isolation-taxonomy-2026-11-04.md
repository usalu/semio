## Clean Schema-First Distinction

Replace the broad withRepository name-family heuristic with a schema-owned operation taxonomy describing actual interfaces and effects: defining Source capture/provider, immutable pinned tool resolution/read, mutable store observation/measurement, opening/recovery/allocation, lease acquisition and write/publication/retirement. Store observation and measurement remain prohibited on checkout-owned live stores even if no write follows. Source capture is not a store sink; a callback is analyzed recursively for its own effects. Classify import-resolved owned symbol identity and argument role (Source root, storage root, Original, callback), not a string exception or spelling trick. Keep unknown effectful paths conservatively refused/unresolved until an owned interface declares its semantics; do not authorize arbitrary readFile on mutable store merely because named read.

Path getters should propagate distinct path facts (checkout Source, live mutable store, pinned immutable tool artifact) instead of conflating them all with checkout root and reporting any join as final effect. A pinned tool fact requires admitted tool identity and genuine original grant, exact version/content ownership and read-only consumer, not any arbitrary string below tools. Any subsequent lease/open/measure/write is a live-store finding. Retain existing path-only rule until these facts and effect sinks are concretely modeled/tested, rather than silently deleting it.

## Portable Sound Neutral Cases

- Source closure capture from checkout with genuine received Original/control, artifact-owned callback: no store finding; same callback opening checkout products/graph: finding at actual sink.
- Conditional or aliased Source provider call retains its Source argument role; conditional actual opener remains a sink. Copying a control or inventing Original fails separate authority law regardless Source classification.
- Pinned immutable toolkit path returned and consumed through admitted tool-read interface: no mutation/measurement finding; same result used by writeFile, storage open, usage measurement or acquireResourceLease: finding.
- Same toolkit relative suffix with missing/wrong identity/grant is unresolved/refused, never auto-approved; arbitrary tools subtree path is not a pinned toolkit fact.
- POSIX and Windows joins, identifier aliases, templates and case/normalization follow the same owned root boundary; .r/i is live mutable storage, .r-neighbour stays separate.
- Real child with parent-created private cwd and received projected Original uses private storage; same program launched checkout cwd raises actual sink. Supply parent launch facts, not a blanket process.cwd assumption or path exemption.
- Definition contains pure Source capture but callback contains live-store call: recursion must preserve that finding. Function definition containing checkout reference does not taint its unrelated return value.

Use neutral data corpus plus existing independent Python model for expected findings, and actual owned effect/interface tests for registry completeness. Root/native owners decide implementation scope; do not change24findings wholesale based on these two semantic cases.
