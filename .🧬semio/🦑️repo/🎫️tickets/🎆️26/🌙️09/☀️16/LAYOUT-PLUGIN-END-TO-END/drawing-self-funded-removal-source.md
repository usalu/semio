# Self-Funded Context Removal

The public SelfFundedCloseCaller and close_with_self_funded_context definitions and exports were removed. They created a fresh root/recipient and used unbounded work/deadline for every turn through an already removed StepContext constructor. No alias, placeholder, cfg-ignore or replacement context factory was added.

The four existing Job close-law functions remain under their owning integration target, with the former self-funded law now named genuine_close_context_lends_exactly_its_grant_and_returns_the_body_outcome. The exact current-view grant, value42, repeated depth11 and whole failure assertions remain. Every law uses one genuine FixtureCaller and one declared finite lifetime; work/deadline denial, original pointer, real heap/deallocation, granted error, nested receipt and terminal-drop assertions remain. Real eight/sixteen-byte owned buffers replace previously hypothetical release counters. Grant-only bodies return actual full outcomes; context-aware bodies post their own actual work.

The closed neutral schema replaces the unbounded selfFunded contract with a genuine finite caller contract. All original five-axis independent SQLite vectors remain unchanged. The original callback upper bound100000 is now an explicit aggregate test lifetime rather than a fresh per-turn allowance. No production policy changed.

The bounded framework census found remaining uses only in higher UI/OS test fixtures and allocation oracles. The exact path/line roster is generated/drawing-self-funded-consumers.json. These are required migration blockers: each needs its existing held genuine caller or one FixtureCaller retained for the whole law; a local fresh-per-call replacement would be invalid. Their bodies and cases were not removed or ignored. The Job close integration target declares testkit explicitly, and the final mandatory test invocation must select all targets with that feature.

No compiler or semantic runtime was launched. The Job-owned source-minting fallback is gone; the higher test-consumer closure is not yet complete.
