# Drawing TypeScript Funding Integration Progress

Source implementation is in progress and is not SourceReady. No semantic test, strict, build, setup or cache action has run under this release.

The new scene/work controller owns one finite original stock and CPU fuel, explicit operation/source identity, provider and wait policy, privately branded callback-only turns, independent actual-effect-before-refusal retained accounting and CPU folding, and opaque close recovery. The direct Text producer now shares the canonical neutral ledger through Unicode/catalog/run work, retains funded child/output archives, copies glyph geometry into an admitted original geometry buffer and quotes content publication. Existing numeric font close is removed. The Vector producer uses the same ledger and funded archives and requires a mandatory caller controller at the high-level vector boundary.

These changes are not ready for execution: the reached Scene/Trace/Boolean lower definitions, ScenePlan close, Raster/Paint/Placement/PNG and direct fixture callers still require their actual funded contracts. Transient missing signatures/types are expected until that coherent closure is authored. No wrapper makes those numeric-only lower owners funded. Actual typed-byte allocations require an owner that holds the real Uint8Array; a detached reservation is insufficient. The neutral primitive owner has been asked to coordinate that defining API.

Cancellation during asynchronous close can occur after successful output moves out of the producer. The controller retains that unpublished output privately; domain output-close owners are still required to discharge it instead of dropping it. No successful output may escape before close and post-close checks.

The former nine-file test-first hashes are historical now because the approved domain-neutral extraction changes TS imports/names after the test-first review. The actual behavioral RED command/log/terminal remain immutable; no claim is made that its current source inputs are unchanged.
