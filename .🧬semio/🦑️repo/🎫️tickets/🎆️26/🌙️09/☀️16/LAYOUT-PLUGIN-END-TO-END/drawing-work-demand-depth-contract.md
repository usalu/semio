# Absolute And Relative Retained-Work Demand

Root found a defining currency-unit gap while coordinating genuine nested parent/child ledger entry. Native Ledger.next_demand records slot/reserve depth with the current nesting already included. Producers cache that absolute demand. Calling require_child(cachedDemand) under a parent adds the current nesting again, even though require_child is intended to translate relative demands from a separate child-grant/ledger.

For cached absolute depth D under nesting n, the wrong precheck can advertise D+n and over-refuse an actually sufficient depth. Repeated denied turns must preserve the same actual minimum, zero receipt/source/CPU effects, and later exact-minimum authority must resume the real operation. Neither a raised depth ceiling nor caller estimation is a fix.

Rust/Cursor are coordinating schema/direct nested denial laws first, then explicit absolute own-demand registration versus relative separate-child translation. The actual persistent29PASS remains a real scoped result for its tested inputs; this newly identified behavior requires an affected native check after implementation. No diagnostic native request is released while its value-facade/kernel closure changes. No new runtime, quota/profile change or source bypass occurred for this audit.
