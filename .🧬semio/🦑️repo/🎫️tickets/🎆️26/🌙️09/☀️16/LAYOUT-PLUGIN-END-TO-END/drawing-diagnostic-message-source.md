# Funded Diagnostic Message Candidate

Authored, not executed. Boundary integration is still pending; this is not SourceReady or native acceptance.

The defining diagnostic owner now exports FaultMessageOwner. construction_demand borrows the exact source message and quotes its UTF8 bytes plus the fixed app.message code and actual FaultScope Layout. construct preflights the incoming five-axis data grant, performs fallible exact String reservations and checked Scope allocation, returns the actual candidate and receipt. Any partial allocation failure stays resident in that same candidate with a literal failure reason; it is never dropped to manufacture an error.

The candidate has an immutable Fault projection, no arbitrary Fault-adoption/mutation API, and a zero-payload-copy take under actual item/depth authority. Default message/code/scope allocations are closed one exact original backing at a time under actual release/depth authority. Typed retirement quotes its real cursor frame and retains candidate custody. No Diagnostic→Job dependency or runtime library was added.

Neutral cases and schema were authored before the body. The native law checks zero physical effects on each positive birth-axis denial, exact heap/receipt, actual canonical FaultWireCursor bytes against Serde expected wire for empty/Unicode/escaped messages, refused publication custody, exact release conservation and zero-effect terminal drop. Partial allocator-failure paths are source-reviewed only, not fault-injected runtime evidence.

The Drawing boundary will use the existing admit_original_construction port with this candidate. Child SceneError and Fault candidate must remain owned while denied; actual receipts and CPU post before any error publication. Existing Fault::from conversion is not being claimed funded.
