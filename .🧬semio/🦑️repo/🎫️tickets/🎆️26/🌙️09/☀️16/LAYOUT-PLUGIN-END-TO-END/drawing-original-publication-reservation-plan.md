# Original Failure Publication Reservation

The exact reached receivers are ExportProducer (Fault-only), GeometryJob (byte-only) and Clipboard placement (Fault-only). They cannot format the new OriginalWorkFailure without discarding primary/receipt/full-context fields. Existing admit_original_domain_failure preserves an input slot on denied quote, but allocates DomainFrame only after the error exists. A real allocation refusal then leaves the domain in its producer and yields another native refusal. Returning only that refusal while disposing the producer is not a complete cause handoff.

The clean defining candidate is an actually paid empty domain frame prepared before algorithm effects. It holds Option<E>, never a dummy E. Its complete real Box layout is quoted by the existing first-party domain owner. A failed preparation has no body cause yet and can return its complete native refusal. After body failure, the existing allocation stays resident; source ingress moves E into that frame and publication moves the same already-paid Box to OriginalDomainPrimary. Ordinary quote denial retains exact source/outputs and returns a blocked turn. No string/Fault/Vec mirror, guessed header allowance, new Original, runtime dependency or private producer hook is needed.

The existing DomainFrame currently contains ControlledRetirement<T>. Supporting an empty frame coherently would use ControlledRetirement<Option<T>>, keep its immutable projection valid only after Some(T), and reuse the same Box as the retirement cursor. Its real header size/close quote must change together. The existing private Sync guard remains justified only by immutable original reads; no new unsafe Sync implementation is proposed. Existing late-admission APIs/tests must retain exact semantics or be hand-migrated to the canonical reservation API, with no old compatibility path.

Publication needs actual item/depth/CPU even though payload copy is zero. The source already exposes original_total_retained_grant() and original_total_fuel_remaining(). A body loan can cap current quantum by lifetime remaining minus actual reserved handoff credit. It must NOT subtract one from every quantum-one turn: that would permanently deny all ordinary tests. Reserving future CPU does not spend it early; actual handoff records it only when performed. Current turn/deadline/cancellation remain independently enforced. A genuinely overrun or foreign context must keep unresolved frame/source ownership; no budget repair, renewed stock or forced release is allowed.

Required genuine law before implementation: zero-item/capacity/depth preparation denial with no body effects; paid empty birth with exact actual heap; same real source binding; quantum-one body progress; independent reserved lifetime credit; actual body error plus receipt/context causes; denied ingress/publication preserves pointer and full tree; zero-copy actual frame transfer and exact CPU; no old receipt repost; controlled empty/filled/cancelled closure and zero-effect terminal drop. This is a concrete design obstruction and proposal, not implemented API or SourceReady. Root is reviewing the new six-file inline failure candidate independently. Export/editor/Clipboard must reuse one settled defining publisher; none should invent its own adapter or erase the new envelope.

The existing lifetime getters also distinguish an independently narrowed zero-credit turn from genuinely exhausted original stock. A publisher must retain a pending owner and block for the former; it may not fabricate replenishment for the latter. Preparation occurs before algorithm admission, so an actual header allocation refusal has no missing domain body cause. Body admission must keep the reserved handoff credit in the lifetime stock while preserving quantum-one turns, and must not reuse stale per-turn semantic/CPU observations. A filled reservation blocks further algorithm calls until actual publication or paid cancellation/close, preventing repeated cached-error aliases from accumulating.
