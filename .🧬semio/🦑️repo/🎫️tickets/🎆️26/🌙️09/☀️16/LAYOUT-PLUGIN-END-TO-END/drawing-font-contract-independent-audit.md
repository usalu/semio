# Drawing Font Contract Audit

The five Native11 diagnostics are genuine stale Drawing call sites against the current funded font API. A sound repair must carry actual caller authority through the Drawing adapter, not merely add syntactically valid placeholder arguments. This audit changed no Source and executed no runtime.

## Defining Contracts

Drawing `scene/🔤️text/🦀️.rs` currently exposes `DocumentTextJob::advance(grant: usize)` and calls its Unicode admission, catalog and outline run children with item counts only. Its own work counter limits semantic steps, but does not supply the byte/capacity/release/depth grant now required by those children. Its output converts resolved run segments to actual Drawing glyph paths. Therefore `FontRunStyle.outlines` must be true here: false intentionally skips outline creation and publishes zero segment counts in the font run's phases 3, 5 and 6, which would silently erase visible glyph geometry.

The current run constructor takes text, font count, style, limits, Unicode layout/bytes, a `FontRunSpan` slice and `UnicodeBidiDirection`. Advance takes the same captured text/fonts/Unicode/spans plus item grant and mutable ledger. The cursor captures span pointer/count and rejects later mismatch for nonempty spans, just as it protects text identity. Drawing has one uniform style per semantic text node, so an empty, consistently supplied span slice is coherent; fabricating ranges or copying slices per turn is unnecessary. Auto direction is the coherent existing unforced-direction choice, retaining Unicode bidi handling rather than hardcoding left-to-right.

`font/🎟️work/🦀️.rs` defines `FontWorkLedger::new(RetainedCloneGrant)`. It tracks actual copied items/bytes, retained capacity, releases, nesting depth, pending demand and held copy authority. `enter`, `can_step`, `slot`, `contiguous`, `push`, child grant and child receipt operations enforce remaining original authority. A denied slot returns pending demand without the write; paid allocation and payload publication are distinct turns. Child advance clamps work to remaining items, stops on blocked work and propagates ledger accounting. Constructing a fresh permissive/unbounded ledger per child or discarding receipts/pending demand would defeat this physical accounting even if compilation succeeds. Test-only `font::testing::work_grant` is fixture authority, not a production grant source.

The public Drawing API currently lacks caller byte authority; Rust's plan must identify the actual owning grant/ledger seam and propagate demand, receipt and cancellation through its callers. An arbitrary constant grant derived only from `max_work`, ignored demand, synthetic progress, or a compatibility wrapper around the old item-only API is not justified by these contracts. Preserve current segment limits, retained completed children, original source ownership, cancellation refusal and paid retirement.

## Existing First-Party and Independent Coverage

The paragraph owner is an updated production example: its measurement run uses `outlines:false`, while final per-line paint uses `outlines:true`; both pass real span owners and bidi direction. This confirms that outlines is a semantic choice, not an optional compile filler. Its style copying is ledger-funded.

Font run Rust laws consume shared JSON layout/run corpora and compare shaped placement and outline pixels against rustybuzz, ttf-parser and tiny-skia, with grants 1/7/4096. The TypeScript law validates the neutral run schema with Ajv and compares glyph contours/pixels against opentype.js and sharp. Both retain completed-child close checks. Drawing text Rust/TS tests additionally cover shared glyph scenes, aggregate segment refusal before scene publication, independent contours and funded retirement. Their authored presence is not proof of actual execution in Native11; no selected tests ran. The Drawing text regression API must be updated coherently with production funding rather than bypassed, and actual mounting/execution must be established separately.
