# 🔍️ Browser Journey Selector Audit (2026-11-22)

This is a source-level audit of `browser-journey.mjs` and `browser-journey.json` against current sources. Nothing ran live.

## Mismatches

1. **Engagement toggle id (fixed).** The journey built `framework.window.<owner>.engagement.toggle` from the raw owner id. The renderer builds this id with `child_element_id("framework.window", [window_id, "engagement", "toggle"])`, and `element_id_segment` camelCases each segment (`🧰️framework/🔨️modules/🛂️manifest/🧭️address/🦀️.rs:237`). `layout-blueprint-1` therefore becomes `layoutBlueprint1`. The journey now uses `elementIdSegment(owner)`, a mirror of the Rust rule that was checked against `-ab`, `Layout.Doc_x y` and `layout-blueprint-1`.
2. **Targets are not in project.json.** `activate-layout-wgpu-prototype` and `serve-layout-wgpu-prototype` are generated by inference (`🎮️playground-targets/🟨️.mjs`), not declared. On this host they run natively through `launch-native.ts`.
3. **Archive actions are unverified.** `exportArtifactDocument` and `importArtifactDocument` appear only in `🌎️hub/🧩️compositions/📏️layout/🧩️component/🔣️.json`. Whether the Actions pane surfaces them must be checked on the live run.
4. **Owner id parsing is unverified.** `ownerWindowId` uses `split(".").slice(3)`, which breaks if a runtime window instance id contains dots.
5. **Readiness beacon is unverified.** The beacon receives `document.documentElement` only when `options.pageBindings` is set (`browser-host/🟦️.ts:281`).
