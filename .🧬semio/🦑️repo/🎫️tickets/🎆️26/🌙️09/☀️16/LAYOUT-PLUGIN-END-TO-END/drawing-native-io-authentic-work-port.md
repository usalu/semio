# Native Decode and IO Authentic Work Port

The actual five Renderer errors are in product OS DSL OriginalOperationReceiving. Its canonical lower protocol OpBinaryReceivingCursor currently erases work and restricts failures to ValueError, while the genuine owned field child now returns OriginalReceivingPrimary. Required matched signatures are step -> RetainedWorkOutcome<RetainedCloneProgress, OriginalReceivingPrimary>, take_into -> RetainedWorkOutcome<RetainedCloneProgress>, close_step -> RetainedWorkOutcome<RetainedCloneStep>. Admission of the fixed header also needs its direct Outcome<Option<(Self, Progress)>>. Replication binary protocol and actual Store command receiver must forward the same ports. Full causes move; no formatter or Result-only facade.

RetainedRecordReceiving is a separate Pack definer, still Result-only. Its selected normal parser/allocation/copy and close outcomes must expose genuine actual work before the OS parent can close this seam. The lower parser work cannot be reconstructed from copied_items or bytes.

For the Root-owned IO owner, the minimal native work interface is an independent scope attached to the actual caller CPU loan, not a numeric budget derived from the physical grant. Proposed NativeDecodeWorkRecipient::admits(observed_since_scope: u64, additional: u64) -> Result<bool, ValueError> validates the next bounded effect against that genuine loan. NativeDecodeControl::with_work_recipient borrows it for the original call; prepare_work(additional) is pre-effect and commit_work(actual) records only the defining effect, including real allocator-null/probe failure. A cumulative actual_work getter permits delta forwarding before Err. No default recipient or callback-entry work is accepted.

Root IO changes: carry the attached native work loan unchanged across nested owner scopes; make drive_cursor/receive/receive_nested producer callbacks return mandatory full outcomes, retain output/partial custody before folding, and forward actual work on success and Err once through the existing Original failure helper. Result-only copying/allocation leaves need their defining actual-work counter rather than a wrapper fee. The progress observer bool callback itself cannot imply work1; any work it performs needs an explicit defining outcome/witness. SourceHost CPU scope stays open until the real Job with_native_receiving boundary supplies the genuine work recipient and every reached defining effect is instrumented.

No NativeDecodeControl body is changed by this proposal. Root owns IOControl, this lane owns the necessary native definer portion after the matched port is settled; Rust owns Job Context with_native_receiving source/clock/return accounting.
