# Worker Real Receiver Migration Boundary

This is read-only planning after the genuine Job production Source refusal and context/clock extraction. No worker runtime, compiler or semantic test was launched.

The higher authority package still imports the removed payload private-ledger constructor and numeric context factory. WorkerJobAdmissionContext currently accepts only operation/generation, a StepBudget DTO, clock and recipient; it has no actual retained Original caller/source. It therefore cannot construct the canonical OriginalWorkerPageReservation. Keeping it as a fallback would invent authority. The actual admitting boundary must accept the genuine StepContext and retain the pending prepared payload before returning any post-effect refusal.

The canonical staged flow is caller-owned preparation -> genuine OriginalWorkerPageReservation.admit_step(cx) -> actual fixed authority backing admission -> ownership handoff into its preallocated payload field -> source/parameter handoff -> actual source-backed worker context. Source-issued lifetime stock comes from OriginalWorkerPayload.context_parts; scheduler configuration may only narrow the current turn. It may not initialize lifetime counters, replace clock/deadline, replace cancellation or allocate a decoder.

The current authority native state still duplicates an outcome slot beside the genuine origin receiver. The real returned Outcome/Continuation arm must enter that already-admitted receiver before terminal outcome publication, preserve independent callback/final/receipt causes, and keep the same held witnesses on busy/foreign/cancelled refusal. No producer-private pending-error field may substitute for returned custody.

Current grant-only initializer callbacks and their cleanup callbacks still return Result-only progress. They must return direct RetainedWorkOutcome witnesses at their actual defining operations. A wrapper must not infer CPU from receipt.items, callback entry or a default unit. Existing step/remove terminal wrappers around advance_retirement_turn also need full outcome forwarding.

The actual final authority close must receive the genuine external Original context. The payload owns a source loan; its context cannot be borrowed to destroy that same source owner. Source aliases, continuation/frame custody, canonical Builder pages and authority backing require separate paid close turns, under unchanged lifetime stock.

The two actual raw host receiver routes remain explicit consumers: mounted-session registry admission and router effect job driving. Neither receives a genuine Original source today through the old WorkerJobAdmissionControl DTO. These routes must receive/lend the actual caller source rather than manufacturing a new Source from configuration.
