# Genuine TypeScript Element Backing Proposal

Proposal only, for Root review before canonical schema/tests or body edits. The current22 remain frozen through the second font gate.

Use fixed sixteen-cell actual Array storage pages which hold the actual T elements. No parallel ordinary Array will hold the elements, and no byte/token allocation will merely stand beside an unfunded list. Capacity derives from live page bodies, rather than an admitted scalar. Page allocation, element writes and body retirement alone emit storage-effect epochs; index/count/header bookkeeping does not.

Use a bounded-radix sixteen-way directory so growth does not copy an unbounded existing element sequence. Directory bodies hold actual child-owner references. New element-page and directory-body births, reference publications and retirements are separate bounded phases. Pending newly allocated bodies stay privately owned through denial/error/cancel until either publication or funded retirement. Lookup uses bounded iterative descent; no growing scratch stack or synchronous whole-buffer copy is needed.

The proposed accounting remains explicitly logical representation cost, not V8 object sizes, allocator capacity or GC. Element rows retain their declared firstparty logical element width. Directory rows require a schema-declared logical owner-reference width; proposed eight logical bytes is a reference-row policy, not a portable pointer-size claim. Root should settle that exact policy before implementation. Every real new directory row/body is charged; existing fixed header moves/clears remain zero-copy. No grant comes from workBudget or a default authority.

Replace the mutable Array inheritance with a firstparty sealed owned sequence: bounded indexed read/length/iteration, private actual backing, and funded append/replace/pop/retire entrypoints. Ledger-only private mutation issuance protects cell storage. Remove inherited push/splice/sort/reverse/length writes rather than retaining a numeric or raw-array route. Hand-migrate reached font owners to resumable funded operations; expose firstparty owned/read views in their result types. Test-only conversion to thirdparty reference arrays remains behind the test interface.

A stable readonly backing view is minted only with an actual storage-body birth. It observes that body's actual cells and identity while live, retains no raw mutable Array, and refuses reads after funded retirement. It must not keep the retired backing alive through a captured raw Array reference. Tests verify exact input element identity through this view, across page/directory growth and denied resumes. This is genuine logical storage ownership, not an engine heap measurement.

Test-first laws: initial five-axis denial with no identity/epoch/effect; actual body identity and element visibility; cross-page/directory growth at17 and257 elements; repeated nested held-copy denial under the absolute quote API; cancellation at each allocation/publication phase with same finite stock; hostile raw Array/intrinsic mutations refused before effect; no epoch for cached/header-only actions; same-stock complete retirement and stale-view refusal. Independent SQLite reconstructs ordered elements and joins observed body births/releases to prove logical capacity conservation. Preserve all prior byte/PNG, generic primitive, numeric, font corpus and lifecycle assertions.

Body work remains held pending Root contract review and second font terminal/release. Native Vec storage and its physical heap evidence remain a separate implementation.


Implementation detail for test-first surface: keep all live actual body headers in one private intrusive list, using fixed prev/next metadata. Directory rows are lookup references inside that sole owner, so a staged new directory may reference the old root without double-owning or double-retiring it. No separate growing registry Array or Map will hide an additional storage body. Actual element/directory arrays have exactly sixteen initialized cells.

Keep defining ledger slot/push operations, with private mutation issuance into sealed storage. All admission phases perform one actual body birth or actual cell publication; pure planning is readonly and existing header state commits accompany that actual operation. No scalar-only preparation earns a storage epoch. Existing buffer retirement drains partial and published bodies from the same sole owner.

Proposed observation API for actual laws: get(index), backingFor(index) and lastStorageEffect(). A backing view is stable, readonly, identifies actual element or directory storage and reads its actual cells while live. It captures only its body header; retirement clears the header's storage reference, so an old observer cannot retain/read the retired Array. A storage effect reports actual birth/write/retire and that actual view, never a grant. Public mutable Array methods and intrinsic writes are absent/refused; owned result/borrowed sequence types and reached mutations will be hand-migrated.
