# Revised Font Plan and TypeScript Close Review

The revised plan resolves the principal CPU/receipt ambiguity: `last_turn_work` is per-call, includes actual work before error, and is charged once separately from the final per-turn retained receipt. Pure denial records zero work; nested copied items are not an extra CPU charge. Its explicit blocked-return, active structural/geometry demand and actual export/editor seam regression commitments address the earlier design gaps. These are plan commitments, not implemented or executed proof.

One concrete TypeScript closure gap remains. Current Drawing text stores `retainedChildren: WorkRetirement[]` and wraps its closure in `UnitRetirement`, whose interface is `advance(number)` with no ledger or demand. Current font children return `FontRetirementCursor`, whose interface requires `advance(number, FontWorkLedger)` and `nextDemand()`. Drawing's `intoRetirement` currently calls those children with `advance(1)` and pops faces/text with no funded receipt. Merely repairing forward advance signatures would leave cancellation, failure and completed-owner close incoherent.

The revised interface agreement must replace this affected Drawing closure path with genuine funded closure. Its public close owner and all actual vector/preparation/raster/editor/export close callers must carry the same caller ledger, expose pending close demand and propagate actual receipt on success and error. Font child release must use its actual `nextDemand`; scalar/text/font-cache archives and failed scene ownership need their own demand and paid custody transitions. Emptying a VM array or inventing release credit from the item count is not an acceptable representation model. A numeric `UnitRetirement` bridge around funded children would replenish or omit authority and must not remain. This does not require changing unrelated numeric geometry owners unless they are in the actual affected closure chain.

Existing first-party `FontRetirement` uses ledger enter/exit, remaining items, blocked demand and child-close delegation; `retireFontChildren`, `retireFontArchive` and `fontChildRetirement` demonstrate that supported composition. Reuse the first-party interface rather than an external runtime type or permissive adapter. Preserve the exact output/private-owner split: successful output moves once, cancelled/failed output remains privately retained until paid close, and terminal empty close has no residual releases.

Before SourceReady, the explicit TS caller map and schema-first laws must cover real five-axis close denials including positive release demand, zero-effect denial, partial paid close, cancellation during each stage, failure after allocation, receipt conservation and terminal emptiness. Rust's existing controlled retirement remains authoritative; no TS shortcut should be justified by Rust-only success. The full Drawing companion and Layout19 requirements remain unchanged. No Source edit or runtime was performed by this review.
