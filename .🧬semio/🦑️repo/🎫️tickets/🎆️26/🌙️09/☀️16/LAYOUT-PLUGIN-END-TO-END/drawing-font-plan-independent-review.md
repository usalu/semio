# Drawing Font Repair Plan Review

The same-ledger design is appropriate, but the current plan needs the following concrete details fixed in its schema/regression agreement before production integration. This review performed no Source edits or execution.

1. **Define CPU fuel independently from retained receipts.** Actual `StepContext::consume_retained` (job source lines248–251) records retained progress and checks the remaining grant; it does not consume CPU fuel. `consume_fuel` (lines363–365) separately increments work spent and reduces fuel. Therefore removing every fuel charge would be incorrect, while retaining an unconditional outer charge plus a second charge for the same child turn would double-charge. Specify one actual executed semantic-step count, bounded by remaining CPU fuel, and charge it once. Retained-only allocation progress and denied zero-effect turns need explicit treatment; font nesting already suppresses duplicate semantic-item accounting inside one ledger.

2. **Fold receipt before error propagation, exactly once.** The proposed result-first/receipt-first order must be explicit in both owned export and editor geometry: retain the child Result, read the ledger receipt, call `cx.consume_retained`, then propagate errors. Its implementation records effects even when the receipt exceeds authority, so never retry consuming the same receipt on that error. Preserve owner custody and actual effects when a child errors after allocation. If one ledger spans multiple calls, fold deltas or fold once at the boundary; consuming cumulative receipts repeatedly would overcount. A new ledger must be made from the context's newly remaining grant, never the original full turn grant again.

3. **Specify pending demand composition and no-spin behavior.** Forwarding `next_work_demand` only from text is insufficient while vector/raster owners perform their own funded work. The current active phase must quote its own or nested demand, including nested depth and held copy requirements, and retain it until satisfied. A blocked turn with zero progress must return to the original scheduler rather than loop within the old export `continue` branch. Paid capacity progress must remain distinguishable from zero-effect denial, without advancing the text's semantic counter on denial.

4. **Complete the five-axis denial matrix.** The plan lists item/copy/capacity/depth denial but omits release. Add release denial for phases that genuinely demand release, or explicitly prove that semantic font/text turns have zero release demand and exercise release during controlled close. Do not invent a release-demanding phase to satisfy a matrix. Geometry reservation, copied segment payload and final Text-to-Glyphs header transfer each need an actual demand and receipt before mutation. Publishing semantic content must not accidentally release its prior String or replace an owner without paid custody.

5. **Make TypeScript parity an explicit replacement scope.** The production interface list and caller map currently name Rust signatures only. Existing Drawing TypeScript text still calls modern Unicode/catalog/run jobs through item-only adapters; the first-party TypeScript FontWorkLedger and FontBuffer already represent portable funded capacity/copy behavior. Specify matching TS ledger parameters, pending demand/receipt forwarding and all vector/raster/editor/export callers, plus language-neutral grant/receipt expectations. Rust heap bytes and portable TS scalar capacity can have documented representation differences while both obey original authority. Do not preserve a permissive numeric-only TS compatibility route.

6. **Keep cancellation and real test mounts explicit.** Cancellation must refuse publication without allocating while retaining Unicode/catalog/run/geometry owners for controlled close, and every failure/partial allocation must remain reachable by that close. Verify the proposed Drawing scene companion actually executes new laws; Layout's dependency compilation does not. Current three Drawing laws and fourteen neutral glyph cases plus their existing external geometry checks must remain, with additional funded denial, error-after-progress, CPU-accounting and blocked-return regressions rather than fixture-only assertions.

The existing outlines:true, stable empty spans and Auto direction choices remain coherent. No compatibility shim, permissive fixture grant in production, profile/quota change or altered funded Layout paragraph path is justified. Root and Rust should resolve these interface details with Dep's schema-first matrix before production edits.
