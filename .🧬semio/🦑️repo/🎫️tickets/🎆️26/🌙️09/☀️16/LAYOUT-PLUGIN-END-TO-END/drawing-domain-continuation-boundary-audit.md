Neither callback entry nor receipt evidence grants additional CPU at a quantum-one exhausted return.

`🧵️job/📬️outcome/🤝️loan/🦀️.rs:21-23` semantic admission consumes one retained metadata item and zero default copy/capacity bytes, with depth one; it contains no fuel debit. `into_descriptor` (line 38) preserves admission and native payload address witnesses. `🧵️job/📬️outcome/🎟️descriptor/🦀️.rs:11,27,49-57` shows the slot owns **only** fixed descriptor metadata/admission, including addresses of producer-owned payloads; `retain` writes this descriptor into `MaybeUninit`. ## Existing Native Decode Return Recipient

`🌱️value/🛬️decode/🫴️recipient/🦀️.rs:9-22` is a genuine caller-owned reserved return mechanism. The inline recipient owns one existing `Box<dyn ErasedSnapshotRetirement>`. `with_reserved_owner` reserves before invoking operation, receives `(Result<T,E>, Option<Box<...>>)` and settles the exact returned box independently of semantic Result. It can preserve an original already boxed retirement owner with no new allocation in the settle operation. However `new`, `reserve`, `settle`, and `with_reserved_owner` have no grant/work parameters and no explicit CPU debit. The defining-module scan found no production invocation of `with_reserved_owner` outside its definition. It must not be treated as an already proven funded job-outcome receiver.

There is concrete prior recipient-birth funding in `🧵️job/⏱️context/🛬️decode/🦀️.rs:28,36-40`: `OriginalNativeDecodeSource` admits source first and then calls `metadata` before constructing its recipient; metadata consumes one actual item and one actual fuel. Its producer call receives actual current grant/fuel at lines 55-58; returned producer work is explicitly consumed at lines 64-70. That birth funding does not prove per-return reserve/settle funding or authorize a new boxed continuation allocation.

`🧵️job/🛬️receiving/🦀️.rs:5-13` also has inline decode recipient and detached receipt; `empty()` explicitly creates recipient without granting capacity. `receive` requires a real grant and forwards construction authority, but no body continuation Result arm is accepted by InteractiveJob through this route.

## Concrete Conclusion and Minimum Seam

The existing descriptor return mechanism cannot currently own the required exact body continuation: its return and receiving types admit semantic payload address witnesses only. The native error return can transport complete native failures (`🧵️job/⚠️failure/🦀️.rs`, `OriginalTurnFailure`), but no current variant represents prepaid reservation plus original body result plus independent final qualifier. A caller-owned stack Result variable can preserve a returned owner until its caller consumes it; that does not make an assignment to a producer field free.

The minimum concrete domain-neutral seam needing a decision is **the `InteractiveJob::step`/`drive_step` owned return contract and its real receiving boundary**, including both authority worker and context-owned callback routes. It must identify which admitted caller place receives the unchanged owner, and expose actual funding for any persistent receipt before body entry or defer that receipt with unchanged owned return. Existing descriptor slots have prepaid physical capacity but the wrong ownership type; existing worker `step_fault` has native-error type but no independent return qualifier/capsule and no demonstrated receiving CPU. Extending either by a private producer field would leave the core issue unresolved.

NativeDecodeRetirementRecipient is a reusable mechanism fact (reserve-before-operation, independent semantic Result and exact returned box), not evidence that a zero-allocation domain continuation already fits or that receiving it after exhausted quantum one is funded. Any use must retain its original preborn owner rather than allocate an erased envelope late, and must demonstrate funded receiving at the actual caller. This audit does not choose or implement an API. Required genuine exhausted-quantum, readonly zero-child-work, pointer identity, separate qualifier, cancellation, denied insertion and canonical paid-close laws remain unrun.
