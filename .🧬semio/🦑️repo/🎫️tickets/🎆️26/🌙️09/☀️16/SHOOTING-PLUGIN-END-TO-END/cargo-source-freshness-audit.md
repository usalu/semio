# Cargo Source Freshness Audit

`repo fleet status --lang=en` is a lightweight read-only live view. During this audit several active Cargo lanes reported completed source admission and `code older`. The view does not map the tool session IDs 73915 and 5237 to individual source files, so it cannot prove that a specific later edit was compiled. A log start time alone is also insufficient: individual Cargo units may compile at different times.

The managed Cargo path captures its compilation graph and admits each workspace unit's source inputs before executing the build (`🧰️framework/🔨️modules/🏃️process/📦️artifacts/🏗️native-build/🎟️admission/🟦️.ts:375` and `📥️source/🎟️admission/🟦️.ts:36`). Receipt retention compares actual source bytes with observed SHA-256 and can refuse concurrent changes with `Actual compilation source digest changed` (`🧾️receipt/📦️retention/📁️copy/🟦️.ts:25`). That diagnostic is useful when it appears, but does not establish that an edit after a unit compiled entered the artifact. Treat success from a lane admitted before a concurrent edit as insufficient evidence for that edit.

Once edits settle and the existing lane finishes, a fresh narrow owner check is `repo cargo --store=shared --configuration=prototype -- check -p semio-os-infinite-world-scene --lib`. Run the relevant renderer owner with the original target and features as well; a host-only check does not establish the browser-only path. A subsequent managed run admits current inputs and can reuse unchanged work, while a successful check still does not replace the browser end-to-end test. No compilation was started in this audit.
