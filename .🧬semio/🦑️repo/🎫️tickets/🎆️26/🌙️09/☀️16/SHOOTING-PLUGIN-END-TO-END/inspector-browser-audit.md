Shooting inputs currently supply no publicationRevision: React uses its direct send path rather than the local-document publication lane, and draft acknowledgement compares the next published value to the sent value. This is source-level reasoning, not proof of live delivery or correct acknowledgement under concurrent edits. The probe performs successive edits without waiting for individual persisted readbacks; final Save Download is an essential assertion, although a publication timing failure could make the probe fail before the app settles.

Shooting selection is app config: Add Shot emits config selection for the new id alongside artifact create/camera/active mutations. Undo of the document can leave that app-scoped selection naming a removed shot; inspector render deliberately resolves the selected id against current shots and falls back to active shot if missing. Thus the probe must not expect undo to restore config as part of document snapshot. The actual default and forest DSL fixtures both start with active `overview-svg`, with no saved camera, and their SVG-only drawing controls exist; the probe asserts the styled shot is the original active id and reads actual saved camera, drawing fields and complete undo snapshot. The export command names `<shot.id>.<format>`, matching its active SVG predicate.

The inspector exact labels and select option strings come from shooting terminology; controls expose aria-label via React and choices use select option roles. Source alone cannot establish whether the tree sections are expanded, accessible names unique in the live panel, publication has settled, the hidden layer is generated for the fixture geometry, or styled drawing renders. The probe currently assumes those and is authoritative only after execution. It checks Viewer canvas/mesh metadata, not decoded viewer pixels.
