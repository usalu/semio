# Renderer Kernel Retained API

The renderer decodes each actor turn with its original retained receipt. The renderer keeps its 100 ms turn ceiling as 100,000 microseconds and derives the CreateApp activation budget from the currently borrowed source. Replay’s millisecond field and the scale benchmark’s declared duration retain their original units at the boundary.

A CreateApp admission refusal retains the full typed failure. The native issuer funds bounded retirement before its Source is ready. Finite-task, frame dispatch and clipboard admission write to a loan slot that survives receipt refusal. Frame dispatch queues cleanup with no events in this case. Clipboard cleanup returns only the exact original loan and leaves its intent unpublished.

A shard transport trap records the actor failure while preserving any outstanding issued turn. It carries no fabricated guest receipt. The benchmark and kernel pool use this fault path.

The pinned Rust compiler parsed 18 edited sources and the scoped diff passed. Current native closure measurements were 13 library files and 2,943 active lines for kernel protocol, 10 and 3,196 for runtime mailbox, and 11 and 1,774 for host plumbing. The existing CreateApp and native-caller tests now call the output-slot loan API. The fairness fixture still expects a 100 ms maximum turn duration.

The managed renderer retry is the compilation verification for these changes. No additional full Cargo run was started here.
