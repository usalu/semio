# Fem 2D Transform Gumball — Research

## Context

- Fem2d model/results windows use `Canvas2dHost` with `layersJson` (no `selectionJson` lane on `Canvas2dScene`; only `toolRunTrace` is paged).
- 3D apps arm the host gumball via guest `selectionJson` (`gumballActive`, `gumballTarget`, `gumballConfig`, `transformMode`) and commit `translateSelection` / `rotateSelection` / `scaleSelection` on drag end (`World3dHost` + `UnifiedGumball`).
- Fem2d today: selection utilities (`selectDirect`, marquee, lasso), `transformMove` = **camera pan** (host-level in `Canvas2dHost.pointerDown`), no geometry transform.

## Approach

1. **Plugin**: `transform` utility; gumball config toggles (`setTransformGumballFlag`); meta layer carries gumball pivot + config; overlay layers for handles; pointer routing in `canvas-gesture`; selection transform commands emitting document mutations (`ReplaceNode` / `ReplaceRegion` batches).
2. **Framework**: `Canvas2dGumballOverlay` on `Canvas2dHost` reading meta `gumball` block — screen-space handles, dispatches same three actions on release (2D delta: `dx`/`dy` model meters, `angle` about pivot, `sx`/`sy` scale).

## Selection → geometry

- Node ids: move/rotate/scale node coordinates.
- Region ids: transform outline vertices.
- Element/support/load selections: resolve to affected nodes (element endpoints; support node; load anchor node).

Pivot: centroid of affected model points in model meters.
