## Critical correction made mid-pass
Initially converted remodel and part of note by **removing** `Serialize, Deserialize` outright (matching the parent brief's literal wording). Auditing `serde_json::` call sites outside `#[cfg(test)]` found this was unsafe: `RemodelSnapshot`/`RemodelMutation`, `NoteSnapshot`/`NoteMutation`/`NoteBlockNode`, and `EnergyModelSnapshot` are all decoded/encoded through **genuine production `serde_json` bridges**, not just test oracles:
- `🚪️io/📥️import/…/🔣️json/…/🦀️.rs` and `🚪️io/📤️export/…/🔣️json/…/🦀️.rs` deserializers/serializers (all three plugins)
- `🧬️schema/🧬️mutations/🦀️.rs`'s `apply_remodel_mutation_json`/`undo_remodel_mutation_json`/`round_trip_remodel_dsl` (remodel) and `decode_note_mutation_json`/`decode_note_snapshot_json`/`encode_note_snapshot_json` (note) — public, non-test, used by the generated cross-language test host (`semio-repo-test-host`'s `sut` feature)
- editor/viewer render paths (`👁️viewer/…/composite/🦀️.rs`, `✏️editor/🎭️modes/…/composite/🦀️.rs`) building `serde_json::Value` scene payloads

Removing `Serialize`/`Deserialize` from these types would have broken `cargo check` on the whole crate. **Corrected to the additive pattern**: keep `Serialize, Deserialize` (real, unconditional — not `#[cfg_attr(test, …)]`) and add `ToValue, FromValue` alongside; keep `#[serde(…)]` and add a paired `#[value(…)]` with identical arguments. This matches the pre-existing convention already used framework-side for `store::ArtifactLink`/`LinkPin` and by an earlier `➗️mathematical` pass. Verified via `grep -c '^#\[value('/`^#\[serde('` balance across every touched file (all matched, 0 mismatches) before kicking off `cargo check`.
