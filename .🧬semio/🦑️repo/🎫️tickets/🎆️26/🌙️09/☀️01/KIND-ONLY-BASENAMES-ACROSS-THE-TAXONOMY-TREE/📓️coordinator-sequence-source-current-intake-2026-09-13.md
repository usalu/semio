# Sequence Remaining Source Intake

This is a read-only intake for the queued Sequence source-owner work. No Sequence product file was changed and no native build, browser test or package publication was run.

The current sources beneath `✏️s/🔌️plugins/🎬️sequence/🗿️artifacts/🎬️sequence/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🌉️wasm` are `📡️protocol.rs` (716 lines), `🧩️component.rs` (466 lines), and `🌐️browser/🟨️.d.ts` (127 lines). The Rust protocol contains dependency-free domain protocol declarations, request handling, resource/queue limits and an existing native unit-test mount. Its schema include and test mount are relative to its current directory. The component mounts that protocol and implements the real Sequence domain adapter plus primitive linear-memory exports. These are authored implementations, not generated package glue.

The artifact Rust root mounts the component only under `#[cfg(target_arch = "wasm32")]`. Therefore an ordinary native host Cargo test does not compile or execute that component. Its exact mount is `editor::sequence::wasm` in the artifact `🦀️.rs`; moving the sources must update that mount, the component's protocol mount, the protocol's schema include and its `🧪️tests/🔬️protocol-unit/🦀️.rs` mount. The WIT schema documentation also names the old protocol source.

The declaration is a complete handwritten browser API surface, including cancellable tasks and document/editing/execution/viewport/input/layout/selection/preview/playback/lifetime features. Its same-stem relationship to `🌐️browser/🟨️.js` is a native TypeScript declaration lookup concern. A filename-only change to `🟦️.d.ts` must not silently remove this type binding. The artifact TypeScript root directly reexports the browser JS source; the package's public `types` and `import` selectors point to `dist/🟦️.d.ts` and `dist/🟦️.js`. A later execution slice must inspect and prove the actual declaration producer and compiler resolution before changing this authored mirror.

The existing JavaScript protocol oracle uses installed Ajv 2020 and an injected `CaptureBridge` with a real WebAssembly.Memory. It compares the encoded addStepDropped request frame and semantic reply. That is useful third-party/native-JavaScript wire evidence, but the injected instantiate callback does not compile or instantiate the real Rust/Wasm component. The plugin test router also runs schema, host, retained-action, browser-consumer and example tests. None was invoked by this intake.

Required execution closure is therefore semantic source owners, exact native mounts/includes, schema/portable vectors, public type-resolution and declaration publication, producer/cache inputs and an actual Wasm-target proof or a clearly retained pre-target failure. Native host compilation or the injected JS bridge alone cannot establish Rust/Wasm runtime acceptance. This intake supplements `📓️plugin-source-followup-packet-2026-09-12.md` and leaves all three sources queued.
