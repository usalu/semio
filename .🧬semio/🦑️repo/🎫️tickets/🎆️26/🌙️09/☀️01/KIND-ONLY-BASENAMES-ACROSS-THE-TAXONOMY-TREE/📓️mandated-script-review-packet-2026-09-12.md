## Decision Constraints

The existing closed BundleScript grammar deliberately permits one routed `run` method delegating to imported functions, while keeping the earlier seven hidden-code counterexamples rejected. Do not blanket-allow arbitrary class bodies because a file is named `📜️script.ts`, imports BundleScript, registers a router, or currently lacks a runtime import. Conversely, an argument guard plus two native compiler invocations is ordinary task orchestration; if an exact safe grammar expansion is justified, prove it with positive native AST and hostile-domain vectors. Do not add regex allowances based on whichever spelling clears the census.

Where actual implementation is present, keep the mandated executable router in the package and move reusable work to an anonymous source under its neutral domain owner. Generated rendering belongs with generator/build ownership; verification logic belongs with its existing tests/oracle owner; process and publication logic belongs with those exact domains. Reuse neutral owners and keep alternate language implementations adjacent. Do not move all unrelated behavior into one generic dumping folder or create a language folder outside `packages`. Additional executable command files remain restricted to `📜️script.ts`; imported anonymous library leaves are not independent executable scripts.

Import-meta anchors and call-site cwd must retain their distinct meanings. Existing native package identity, published imports, ordered generator inputs, freshness receipts, task targets, root scripts, launch seed and derivation must close together. Existing tests importing functions from old package scripts should consume the actual new owner directly; no compatibility facade. Validate moved source identity and new native import closure without regenerating unrelated shared output.
