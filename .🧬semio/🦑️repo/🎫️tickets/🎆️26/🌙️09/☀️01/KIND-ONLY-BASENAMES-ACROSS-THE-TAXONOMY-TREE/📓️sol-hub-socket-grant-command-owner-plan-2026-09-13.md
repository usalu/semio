# Hub Socket Grant Command Ownership Plan

## Boundary

This phase owns the current `socket-grant-check` command and the shared local-relay route selectors it exercises. It does not own the secure-local smoke command, live Hub/browser/service startup, the directory implementation, or the full Hub compiler graph. The source phase remains portable and performs no Cargo or service work. Native evidence is limited to a ticket-private Rust fixture oracle; the retained production command still offers the selected Cargo laws and final check through its existing launch.

The current command lists seventeen Hub binary test selectors, but two selectors have no declaration anywhere in the current Rust source:

- `tests::directory_socket_forced_lag_is_scope_authorized_and_closes_1013`
- `tests::document_socket_forced_lag_sends_verified_control_then_closes_1013`

The extracted native plan will retain the fifteen declared Hub binary laws and reject selectors not backed by an exact source declaration. The remaining two Hub library laws, one replication law, and final Hub binary check remain distinct stages, yielding nineteen production native stages.

- Existing production route and launch remain `socket-grant-check` and `⚖️gate🔌️socket-grant🛡️server`.
- New portable route and launch are `socket-grant-command-source-check` and `⚖️gate🔌️socket-grant📐️source`, placed immediately before the production launch.
- New named input `hubSocketGrantCommandSources` enumerates all seven owners, schema, fixture, portable test, existing directory schema/fixture, integration harness, phase-one environment owner, generic process owners, root router/project, Hub Cargo manifest/library and lock, the four current Rust law-source authorities, taxonomy, and seed/derived launch files.
