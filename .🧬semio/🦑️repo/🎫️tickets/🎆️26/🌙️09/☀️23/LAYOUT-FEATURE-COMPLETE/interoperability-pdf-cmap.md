# Canonical PDF Unicode CMap Audit

The canonical PDF lifter already reads a Type0 Encoding stream through parse_cmap and retains it as the owned PdfCMap::Embedded model. CidCodec::split considers physical widths1..4 and FontCodec decodes those admitted codes through ToUnicode. It therefore does not have lopdf's high-level extraction limitation when Encoding is a stream. No new forced two-byte fallback was added.

A concrete performance defect was found: FontCodec::new eagerly expanded every ToUnicode range, running a linear range lookup for each code and retaining per-code strings in multiple maps. The new full-Unicode editor CMap has1026 ranges; eager admission would materialize roughly1.1million codes and perform roughly1billion range comparisons. Font admission now keeps compact ranges. Decode resolves the requested code through ToUnicode before simple-font fallback; reverse encode consults compact mappings and uses the Encoding codespace for physical width. Character-only mappings may still use existing small direct dictionaries. Encoding candidate scanning examines at most4scalars rather than rescanning the complete remaining string. Checked scalar addition avoids overflow on malformed oversized ranges; inverted reverse ranges are ignored.

The neutral canonical fixture is fonts/🗺️cmap/🧪️fixtures/🔣️unicode.json with its JSON contract. It includes German/CJK text, supplementary starts/ends includingU+10FFFF and a distinct mixed1/2/3/4byte codespace case. Native FontCodec and CMap laws are mounted, but not compiled or run because the authorized repo frontend remains unavailable (native-runner.md).

The owned TypeScript CMap counterpart imports actual canonical PdfEmbeddedCMap/PdfToUnicode types. It uses no external runtime dependency. Actual test-only PDF.js5.7.284 reads a complete PDF containing the fixture's Encoding/ToUnicode streams and four-byte text codes, then a second PDF containing actual mixed1/2/3/4byte Encoding and ToUnicode streams, matching both expected Unicode strings. Native runtime behavior is not established by this independent witness. Reproducible retained input unicode-cmap-check.mjs returns {strictTargetDiagnostics:0,actualSourceFiles:216,cases:2,generatedModules:3}. The strict diagnostics apply to the implementation and law targets against their real source graph, not the entire monorepo. Generated modules self-clean under the ticket. Four current native font/CMap implementation/test files have no grammar errors; that is not native compilation.
