# WGPU Serve Lease Audit

`🗑️generated/serve-layout-wgpu-verified.log` reports that compiler host capacity (rank 3) is requested while the Infinite fonts publication is held shared (artifact rank 6), then announces the listener ready. This is a real order inversion, not a false instrumentation report. The order checker checks the current task and ancestor holds and reports an out-of-order request before waiting; observe mode warns instead of refusing. Readiness shows this particular request eventually succeeded, not that a deadlock cannot occur.

The WGPU server entry `🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🎯️targets/🧊️wgpu/🌐️server/📜️script.ts:36` calls `serveVite` with the fixed WGPU serve inputs. `🧰️framework/🛍️products/💻️os/🔨️modules/🧑‍💻dev/🏗️builder/🌐️vite/📥️artifacts/🟦️.ts:20` includes the shared fonts and renderer publications. `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/⚡️caching/🌐️vite/🟦️.ts:116` wraps the whole listener in `withViteArtifactInputsV1`; `📥️inputs/🟦️.ts:17` explicitly retains the exact publication readers until listener settlement. The same serve function requests counted capacity at line 127 for `createServer` and optimizer scan, and lines 147–153 request it again for each uncached transform. Capacity acquisition uses queued, potentially blocking host and core leases.

By contrast, `buildViteArtifact` acquires `withViteCompilerCapacityV1` before `withViteArtifactInputsV1` at line 64. Holding that capacity throughout a long-lived dev listener would fix ordering but reserve compiler slots while idle. A durable fix needs to change the serve ownership boundaries so rank 3 is acquired before any rank 6 publication held by the work requesting it, while preserving valid and stable asset reads during requests. For example, a bounded independently owned session snapshot made under publication leases could let those leases retire before the listener requests compiler capacity; the snapshot lifecycle and storage constraints need explicit design and tests. Suppressing or reclassifying the warning leaves the hold-and-wait relationship intact.
