## Receipt identity and live listener

The authoritative normal activation is `🧰️framework/🛍️products/💻️os/🔨️modules/🧑‍💻dev/♻️activation/🏃️execution/🟦️.ts` and `../🔖️identity/🟦️.ts`. For every file in a component's `artifactFiles(moduleDirectory)` map, `activationFilesDigest` sorts map keys lexically, hashes UTF-8 `JSON.stringify([name.replaceAll("\\\\", "/"), fileSize]) + "\\n"` followed immediately by that file's raw bytes, and returns lowercase hex. The support digest uses the same algorithm over the Preview 2 vendor and shard inventories with their directory-prefixed keys, plus the captured font keyed by `FONT_ASSET`. The row's `artifactSha256` is SHA-256 of the UTF-8 concatenation of the support digest hex and component digest hex, with no separator. It is not the SHA-256 of the guest Wasm or bridge alone.

`writeStagedSourceFreshness` computes `sourceContentSha256` from the catalog entry's component owner root, not the entire framework and not compiler provenance. In `🔌️plugin/🏗️build/🔍️freshness/🟦️.ts`, the bounded walk skips symlinks, directories `dist`, `target`, `node_modules`, `pkg`, `.git`, and only at owner root the generated `🔣️.json` and `🛂️.descriptor.semio`. It hashes each file's bytes, then hashes sorted forward-slash-relative path, NUL, lowercase file SHA-256 hex, NUL for each file. The walk is capped at 20,000 entries. It writes the resulting marker and stat index under the runtime's `🔖️/<first 24 hex of SHA-256(pluginId)>`. This reflects owner source at activation time; matching it alone does not prove the binary was built from those source bytes.

Receipt check: resolve `browserProductRootsV1(workspace,"prototype").runtime/wgpu/layout/activation/🔣️receipt.json` using `♻️activation/📂️paths/🟦️.ts`, parse with `readActivationReceipt`, require schema `semio.dev.activation/v1`, variant `layout`, profile `prototype`, and exactly the expected Layout row. Compare its source hash with a fresh `componentSourceContentHash` for the Layout owner and its staged marker. Independently recompute both complete file inventory digests and the combined artifact digest using the exact `artifactFiles` and captured font inputs above, then compare to the receipt. Require the owner guest run's successful publication and component/descriptor receipt/provenance as a separate compiler-to-artifact proof; neither the row nor `cold-boot-check` establishes that binding. `nextActivationReceipt` preserves `rebuiltAt` for unchanged artifact *and* source hashes, and otherwise increments it monotonically; timestamp alone is not an identity.

The stage's `channel-version check-descriptors` merely compares tracked JSON descriptor channel to the pin, not the JSON/Pack pair or component digest. The registry's `check` calls `validateDescriptors`, which validates semantic pair and, when present, the **release** component receipt against the descriptor pack and Wasm; absent release output is only a warning. The stronger `repo <registry-script> catalog-complete --build-root <absolute fresh build root>` validates its own complete fresh-build artifacts and receipts, not this prototype by assumption. The prototype guest owner `stage-layout-guest.ts` runs `components describe layout --profile prototype --facet browser`; its own describe/materialization semantic verification and published component receipt are the directly relevant evidence. A release driver separately uses `describeMode: "verify"` against the committed pair, whereas prototype uses `"local"`. Do not start a release build to verify the active prototype or treat a channel check as release verification.

WGPU differs from the React activation plugin: `📺️renderer/🧑‍🎨engine/🎯️targets/🧊️wgpu/🌐️server/🎚️config/🟦️.ts` points `reloadFile` at that WGPU receipt, and `🌐️server/🟦️.ts` `completedArtifactReload` watches its directory, compares receipt text and broadcasts a browser full reload on change. It mounts module directories live, so a receipt-only/module-byte update does not inherently require restarting the listener. However the injected `options.catalog` is captured in the server configuration and serialized by `transformIndexHtml`; the receipt watcher does not reread it. Compare the served injected catalog to the newly generated session/projection; if the catalog itself changed, its owner must restart the listener to update that captured value. An already open browser reload and a new HTTP request still need the route/actor checks above.
