# Layout IDML package admission

The native Interchange batch reported `layout.idml.missing-identity` from both fresh IDML export routes. Both writers emit valid package elements such as `<idPkg:Story>` around unqualified records such as `<Story Self="…">`. The importer selected elements by local name recursively and attempted to resolve `Self` on the enclosing packaging element. The production patch separates the namespace-bound package from its immediate semantic records, supports bare unqualified parts, and still requires every admitted story, spread, and master record to supply its identity. Spread and master members require one record. The shared test owner also has a native round trip which removes `Self` from the genuine story element after proving the untouched package succeeds.

Embedded PNG used a separate wire mismatch. Layout image data URLs and IDML Contents use RFC 4648 standard padded base64. The native IDML reader and IDML test image authors had used Pack's typed `pk:` wire. The patch uses the framework's existing strict standard decoder and encoder, preserving the byte and pixel limits. The two image fixtures now author standard payloads. The draft adds the same internal base64 dependency to Layout IO and Layout Model and updates their rows in the four consuming lockfiles so the shared owner is available for related printable and PDF fixes.

The neutral override fixture now uses the canonical `w` and `h` members already declared by Layout Bounds. The TypeScript mapping consumes the same names. The fixture continues to reject unknown production members rather than granting aliases. The TypeScript oracle ran all 12 cases against the independent XML library with zero strict diagnostics. Eight package fixtures gave matching namespace-aware record results in Saxes and Python ElementTree. Python's standard base64 codec also rejected Pack transport strings. Rustfmt parsed the draft product module and native test source without launching a compiler.
