# Drawing Segment Consumption

The Layout Drawing planner needs a fixed-state consumer that publishes one affine-projected path command at a time. The new schema and six neutral fixtures precede the implementation in scene/drawing/segments. Exact line and Bezier geometry is preserved. SVG endpoint arcs follow the normative [W3C SVG 1.1 Appendix F.6](https://www.w3.org/TR/SVG11/implnote.html#ArcImplementationNotes): equal endpoints omit an arc, zero radii become a line, negative radii use absolute values, undersized radii are corrected, and rotation is reduced modulo 360 degrees.

An arc retains only scalar center, transformed axes, endpoint, sweep and piece ordinals. Each funded step publishes at most one cubic. The unit-circle radial squared excess is bounded by a²/432, where a=4sin(span/2)-8tan(span/4)cos(span/2); multiplying the resulting radial excess by the sum of transformed axis lengths gives a conservative device-space bound. Piece counts are refined without storing source collections. The native counterpart and production export connection are still in progress.

Actual TypeScript evidence: six fixtures across grants1,7,4096 pass18 runs,18 independent Skia fill comparisons,6 cancellations and5 refusals. Exact Bezier cases produce identical Skia pixels. Arc comparisons explicitly allow0.1device-unit tight-bound difference and0.25mean alpha-byte difference across a256×160 raster because Skia has its own conic/float/tessellation representation; observed peak bounds difference was about0.064 and observed largest mean alpha difference0.201. Those raster checks do not prove the1e-7 mathematical tolerance. A separate sampled circle law verifies radial error at1e-7 across every emitted cubic. No native execution or full export integration is claimed.

The native scalar counterpart and two fixture/radial-error laws are now mounted; three native files parse without grammar errors. Strict TypeScript covered311 real sources with zero diagnostics. The owned `layout-drawing-segments` verification route is registered. Native execution remains unavailable and the production export adapter is still outstanding.
