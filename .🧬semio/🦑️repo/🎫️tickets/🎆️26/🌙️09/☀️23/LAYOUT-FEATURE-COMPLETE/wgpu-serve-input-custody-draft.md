# WGPU Serve Input Custody Draft

The existing interfaces cannot fix both rank inversions while preserving the current ownership boundary. The Vite serve scope holds the exact artifact group for the full listener lifetime. The group releases all shared leases after its body, accepted work, and final inspection settle. A live group task receives the same inherited custody. Loading Vite under rank 3 once leaves uncached transforms and warmup making the same rank 3 request while an ancestor holds rank 6.

The WGPU host can adopt an explicit captured-input configuration. A generic change to existing Vite config path strings cannot enforce this. The completed WGPU factory resolves and checks files and closes over roots during config evaluation. Those roots feed filesystem allowlists, aliases, and static file middleware. The public Play composition also closes over its generated package roots and needs its own conversion if the generic serve interface is changed.

## Ownership

1. Keep the fixed products-store reservation in the existing Vite session. Under its exclusive-created private temporary directory, allocate disjoint input and optimizer subtrees. Only the optimizer subtree may enter the optimizer cache publication.
2. Capture font and renderer roots inside an accepted artifact group task, with independent files and the exact manifest. Slot the two roots by declared request identity. In the artifact reader, bind each copy to the generation's existing expected content digest and file identity. Reuse the bounded descriptor copy implementation with cancellation, extent checks, and exclusive destination creation. Gate acceptance on the group final inspection and validate physical identities and content in the resulting private tree. Bounds cover the aggregate file, directory, byte and path extent. This checkout's prototype inputs contain 115,316,384 bytes including manifests.
3. Return the completed read-only private mapping only after the group and all rank 6 source leases settle. The outer private tree must remain owned by the original Vite store and continue detecting identity drift until service settlement. The existing repository artifact scratch helper holds an artifact-ranked lease, so retaining one of those leases around the listener carries the inversion into the new tree. The private Vite directory already has an independently scoped cleanup lifetime. Its sole writer is the capture phase. It must stay outside all stable publication and optimizer destinations.
4. For WGPU, use an admitted config factory receiving the captured input roots before it creates the config. Rebase renderer and font paths used by preflight checks, middleware, aliases and filesystem allowance. Map both the default and Specific composition. Exclude raw canonical renderer/font roots from that serve configuration. Leave browser boot, frame worker, guest modules and extension roots under their current owners since the WGPU artifact-input request does not cover them. A hook after Vite loads the config misses closures already created by the factory.
5. Run the existing startup and optimizer scan under counted compiler capacity. Cancel or release capacity at the same startup boundary. Each accepted uncached transform and warmup retains its own counted capacity through its optimizer drain. Cached responses do not request a grant. Prevent obsolete optimizer metadata from reviving paths to an earlier temporary input directory. Use the input content identity for cache validity and validate the current private paths before reuse.
6. On shutdown, close HTTP intake, drain accepted work and Vite, verify custody of the captured roots, and remove the private tree under the existing store scope. Cancellation before final source inspection must prevent readiness. A failed capture, final source check or closure must not leave a listener or a reusable partial input tree.

## Verification

`wgpu-serve-lease-order.json` compares the current listener-held ordering, released source publications before compiler operations, and the wrong approach of retaining a private artifact-ranked scratch claim. The existing TypeScript checker and independent Python oracle emitted identical results. The current listener-held publication sequence produced two violations, release before startup and transforms produced zero, and retaining a private artifact-ranked scratch lease produced one. This validates the declared ordering scenarios. The replacement service is a design draft.

The implementation gate should hold an independent lock long enough to queue a genuine startup/transform grant, then confirm the listener carries no rank 6 publication hold while waiting and releases the compiler grant once idle. Replace a canonical source publication under its writer lease while the service is running and verify the snapshot still serves the original renderer JS, WASM and font checksums. Inject mid-capture source drift, cancellation, a previously used optimizer cache, and snapshot drift. Check fail-closed readiness, request drainage, actual route aliases and root allowance, and cleanup. Keep the ordinary Vite build path and its capacity-before-input ordering under its existing tests.
