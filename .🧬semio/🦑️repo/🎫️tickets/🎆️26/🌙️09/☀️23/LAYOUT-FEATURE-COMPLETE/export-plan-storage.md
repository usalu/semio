# Original-Funded Export Planning Storage

The focused planning milestone replaces the three native plan Vec owners with retained first-party paged owners. It does not establish a native build or runtime pass.

## Contract and Behavior

- Schema: [plan contract](C:/git/semio/✏️s/🔌️plugins/📏️layout/🗿️artifacts/📏️layout/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/⚙️engine/📤️export/🗃️plan/🔣️.json). The same neutral fixture drives portable authority/cancellation and native paired-owner laws. Existing large-sheet final ordering supplies the semantic reference.
- PlanItems, PlanPages and PlanOffsets keep their original PagedList backing, reserve before production and retain an unexpected failed append's owned value. The original caller pays physical reservations and committed metadata copies. A refused reservation leaves paragraph, Drawing and frame production untouched.
- Planning borrows one original FontWorkLedger. Item and page metadata copy holds exist before a child can emit a proxy or glyph row. Paragraph work borrows that same ledger. Drawing receives its exact remaining child grant; actual child effects are folded back even on failure. Produced image ownership is retained before an overgrant refusal can be reported.
- PDF offset backing is prepared before object output or encoder state changes. Preparatory turns call OutputWork.mark_preparatory. Actual offset writes debit the same original output turn. This preserves the parent's BeginEncode/output work.
- PdfItem, PdfRaster and PdfPagePlan now have genuine controlled original retirement; fixed DrawingPaint has a first-party leaf retirement. Native close routes the same plan owners through the existing paired retirement ladder, including empty originals and spare paged capacity.
- Removed obsolete synchronous PdfItem::Glyph/Engine shaping and duplicated exported font/outline archives. Genuine retained paragraph Outline addresses remain. The native contour fixture now resolves its real selected font through the built-in catalog and compares contours/pixels with ttf_parser and tiny-skia. Its plan-only rotation assertion stops at BeginEncode.
- Portable ExportPlanList requires an explicit payload retirement function; rows and successful final owners close explicitly. A reported child authority fault retains the actual partial receipt. Native closed-state misuse is an invariant refusal boundary; normal production is stopped by reserve failure before any further producer runs.

- Fresh addressed flow regression: 6 flow cases/18 runs/6 cancellations/6 refusals; 18 addressed runs/60 requests/18 analyses/18 refusals; 12 borrowed face runs; 15 link labels/5 cancellations/15 refusals.
- Native grammar: 56 scoped files, 0 errors. Source checks find no remaining export PdfItem::Glyph, Engine font handle, old Fidelity prepare signature, old Vec plan push, or offset Vec/as_ptr path.

## Native and Scheduler Boundaries

Native laws were authored and mounted, including HeapWitness comparisons of physical allocation/release effects, refusal before source movement, nested original child receipts and all neutral cancellation cuts. They have NOT executed. The available repo frontend remains stale or fails during index persistence; no raw Cargo workaround was used. Rust type checking, native typography/export pixels and native physical allocator results remain unverified.

The job caches plan_work_demand after each original turn; pdf_offset_demand quotes the next original offset reservation. Existing export InteractiveJob exposes close demands, but this scope found no production execution-demand scheduler hook consuming these new quotes. A caller that never increases an insufficient grant may remain pending. The quotes are observation only and never mint authority. This integration boundary is explicit for the parent scheduler work.

Portable capacity tests model retained scalar bytes. They do not prove JavaScript VM headers/GC timing. Native sizeof and exact original PagedList physical quotes are architecture-specific; the native laws use those actual quotes rather than claiming the portable logical record widths are native ABI sizes.
