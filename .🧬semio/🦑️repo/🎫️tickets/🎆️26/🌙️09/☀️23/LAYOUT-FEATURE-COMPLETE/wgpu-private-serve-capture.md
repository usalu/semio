# Private WGPU Serve Capture

The candidate lives in `🗑️generated/wgpu-private-capture.patch`. It has not been applied to the workspace. A Bun module overlay used the working repository inputs and replaced only the drafted modules inside the test process. The live Layout listener and published component paths were never modified by these tests.

The draft captures the two WGPU artifact publications into the Vite store's private directory while the repository group retains and checks source custody. Captures use the existing bounded cancellable compiler-file copy with each expected digest from the authoritative inspection. Source grouping drains and performs its final identity checks before the Vite service makes a compiler-capacity request. WGPU mounts renderer and font aliases from the captured tree. Its HTTP middleware opens only admitted snapshot files, checks the real file descriptor and path identity, and streams that same descriptor. Unknown paths produce 404 and file replacement rejects the request before validators or a response body. Shutdown checks file identity after intake and streams settle and removes the private inputs with the existing Vite store scope. A non-cancelled shutdown also rehashes the snapshot. On cancellation the final metadata check still runs under live store custody.

The captured configuration uses a per-listener optimizer directory and skips reading or publishing shared optimizer snapshots. The input locations are temporary physical paths, and an optimizer snapshot may retain those exact paths. Reusing one could refer to a previous listener's deleted tree. WGPU already disables dependency discovery and prebundling. Authored React Play and other callers without a captured projection retain their existing optimizer and configuration behavior.
