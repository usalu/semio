# Time Travel Close Diagnostic Feature Contract

The isolated native focus check stopped with E0599 in `semio-plugin-instance-app` at the Time Travel close diagnostic. Its run checked `semio-plugin-time-travel` at log line 77614, reached the instance at line 95998 and emitted E0599 at line 97044. The live caller and provider were updated together at 20:46:09 UTC while the isolated run was active. The managed isolated lane was retired after the failure, so its old dep-info is unavailable.

The live source independently established a mismatch. `TimeTravelLedger<A>::original_close_diagnostic` uses `cfg(any(test, feature = "artifact-app-testing"))` in the provider crate. The consuming `PluginApp` implementation called it in ordinary builds. Both crates have empty enabled feature lists in the guest's ordinary WASI plan. A fresh compile of those pre-fix sources would still omit the provider method.

The applied caller always reports the Time Travel residue. Its explicit `artifact-app-testing` feature enables the expanded frontier diagnostics and forwards the provider's existing feature. Rust's per-crate `cfg(test)` by itself leaves the dependency without the testing API. The caller does not use that cfg to invoke it.

The root, Hub, and Layout artifact workspace locks already carry the three optional dependencies of the provider's testing feature. Layout bridge and fixture-sweep intentionally omit them for their default closure. The authored plugin façade's testing feature already enabled both features together, so its existing test closure requires no new package. The default branch introduces no test dependency. An explicit test feature in an otherwise default-only workspace would require that workspace's lock to include the testing closure.

The ticket JSON states four language-neutral scenarios. SQLite reproduced every result. The pinned Rust compiler built the actual extracted caller branches and the live provider cfg across a two-crate fixture. Ordinary use, caller unit test without dependency features, and independent provider-feature unification all returned only the residue. Explicitly enabling both through the forwarded feature also returned the frontier. The fixture used a controlled provider return for the frontier and made no Cargo request. The full native focus and guest builds remain owned by their running and coordinating agents.
