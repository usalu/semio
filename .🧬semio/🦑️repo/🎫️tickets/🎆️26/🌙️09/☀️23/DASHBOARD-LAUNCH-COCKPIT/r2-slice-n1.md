# Slice N-1: Nx Graph Integrity (F14)

## Cause (verified)

Regenerating the graph (`NX_DAEMON=false NX_PLUGIN_NO_TIMEOUTS=true NX_VERBOSE_LOGGING=true bun nx show projects --json`) failed with
"Failed to process project graph":

- `Duplicate Nx project workspace: . and 🧰️framework/🛍️products/🦑️repo/🔨️modules/🎛️dashboard/🧫️fixtures/🧭️journeys/🏗️workspace`
  thrown by the repo plugin `📚️library/🟨️.mjs:1353` (`emojiProjectJsonNodes`, plugin index 2).
- The V-1 journeys fixture `D/🧫️fixtures/🧭️journeys/🏗️workspace/📋️project.json` is a standalone workspace root (copied into temporary workspaces by the journey tests) and is
  named `workspace`, exactly like the real root project (`/📋️project.json`). Created 2026-10-08 03:30-04:23, which matches the shrink at about 04:50.
- Nx publishes partial results when a plugin's `createNodes` aggregate fails: the published `project-graph.json` had `errors: [AggregateCreateNodesError (pluginIndex 2), ProcessDependenciesError]`,
  680 projects, 5314 targets, `framework-os-dev` 0 targets, `framework-renderer-wgpu` 0 targets. The second error
  (`Generator output has no Nx producer: …wgpu/🎞️frame-worker/🤖️generated/🟨️.js`, `🟨️.mjs:1529`) is a cascade: the producer project had no targets in the partial graph. Not a separate bug.
- Not causes: A-1 generator/catalog rows, P-1 `dev` alias, C-1b root scripts, M-2 `continuous` keys, dashboard declarations (all processed fine once the fixture was excluded).

## Fix

`C:\git\semio\.nxignore` (the only file changed): `**/🧫️fixtures/**/📋️project.json`, with a comment. Fixture manifests are standalone workspace roots and never projects of this repository
(there is exactly one such manifest today). The journey tests copy the fixture to a temp workspace where it is the root, so they are unaffected.
