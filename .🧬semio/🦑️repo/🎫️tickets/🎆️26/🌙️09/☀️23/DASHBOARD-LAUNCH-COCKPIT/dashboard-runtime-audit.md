## 1. Part A - source audit

### A1. Process architecture and entry

`bun run dashboard` -> `package.json:33` (`bun nx run @semio-tech/repo-cli-rs:run --outputStyle=stream`) -> `package.json:30` script `nx` = bootstrap `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/⚡️caching/🚀️bootstrap/📜️script.ts:368-372`: `dashboardInstalled()` (record exists) && `dashboardInvocation(args)` (target is `repo-cli-rs:run|daemon|workflow|preferences`, no `--graph/--batch/…`) -> `launchDashboard()` = `spawn(installed executable, stdio inherit)` (`DASH/📦️installation/🟦️.ts:10-21,41-58`; the file was moved here from `⌨️cli` at 19:22 while auditing). No Nx graph, no cargo, no hashing on that path.

| Aspect | Finding |
| --- | --- |
| Warm start `[run]` | `bun run dashboard` -> first dashboard frame **0.11-0.13 s**; native binary alone 0.06-0.07 s (`OUT/console-results.txt` §m, `OUT/m-entry.results.json`). Two bun processes + the binary. |

Zero-touch canonical entry (proposal): keep exactly one command, `bun run dashboard`, and make the bootstrap script own the whole lifecycle without Nx: (1) not installed -> call `dashboardExecutable()` directly from the bootstrap (no graph), print progress, support Ctrl+C; (2) record a `buildId` (source tree hash of `DASH`, `⌨️cli`, `🖱️ui`) in `installed.json` and let the native binary compare it with a cheap runtime stamp; when the sources are newer show a footer notice and offer `Ctrl+B u` = rebuild + install + restart view (progress + cancel) instead of silently running stale code; (3) add `protocol` + `build_id` to `ServerMsg::Attached` and have the view warn "daemon older than view - finish or stop tasks, then `Ctrl+B Q`" (today a mismatch is silent, `daemon:411`).

### A2. Daemon

**Lifecycle `[code]`.** View connects (`terminal:475-488`, every 500 ms while disconnected, one new thread per attempt) -> `Connection::connect` -> on failure `start_detached` (`daemon:979-1003`): `spawn_detached` (`UI/🚇️pty/🦀️.rs`, process group 0, stdio null) + poll 5 s for the socket. Singleton: `WorkspaceLease` = `flock` on `⚡️cache/🎛️dashboard/daemon.lock` (`daemon:806-815`), released by the OS on crash; pid file and socket are removed on clean exit (`daemon:817-822`); stale sockets are replaced on bind (`daemon:271`). Several views starting at once spawn several daemons; the losers exit on the lease. Crash recovery: at start, sessions the journal still lists as running/stopping are rewritten to `exited, code -1` (`daemon:541-546`); their PTYs died with the old daemon.
Residue `[run]`: 13 `$TMPDIR/semio-dashboard-*` dirs (4 with a stale `daemon.sock`, 1 live) were left by earlier daemons/tests; the dir is never removed (`daemon:817-822` removes only the socket). The socket path is `temp_dir()/semio-dashboard-<DefaultHasher(root)>` (`daemon:158-165`): the std hasher is not guaranteed stable across Rust versions and `TMPDIR` differs per launcher (VS Code vs shell), so a view and a daemon built by different toolchains / started from different environments can disagree on the path `[code]`.

**IPC protocol.** Frame `u32 le len | u8 kind | payload`, `kind 1` JSON control, `kind 2` output `u16 id_len | id | bytes`, max 16 MiB (`daemon:17-19,187-257`). Rust enums vs schema `DASH/🧬️schema/🌀️daemon/🔣️.json`:

| Direction | Messages (Rust `daemon:36-61`) | In schema |
| --- | --- | --- |
| Client -> daemon (11) | `attach{client_id}`, `detach`, `spawn{session_id,command}`, `input{session_id,data:[u8]}`, `resize{cols,rows}`, `kill`, `stop`, `restart`, `list`, `shutdown`, `ping` | all 11 |
| Daemon -> client (7) | `attached{daemon_pid}`, `session_changed`, `sessions`, `replay_complete`, `error{message}`, `pong`, `shutdown` | all 7 |

No drift between enums and schema. Gaps: (1) the **binary output frame, the frame envelope and the 16 MiB bound are not in the schema** (so the TypeScript/Ajv "independent implementation" validates only the JSON half); (2) `input.data` is a JSON array of integers (3-4x size, `daemon:40`); (3) all messages are `deny_unknown_fields` (`daemon:35,52`) and the daemon **silently drops any control message it cannot decode** (`daemon:411`) - version skew between view and daemon degrades to silent no-ops; (4) no protocol/build version in `attached`; (5) no `session_removed`, `output_dropped`, `title`, `exit_notification` or `ready` message.

**Session model.** `SessionInfo{session_id, command{cmd,args,cwd,env,cols,rows}, status{running,stopping,exited,failed}, pid, code}` (`daemon:83-91`). `same_task()` = equality of cmd, args, cwd and env map (`daemon:110-113`), used by the view (`terminal:260`, with the graph-reuse env stripped) and by the daemon (`daemon:678-681`, error "task is already running"). Ids are chosen by the view: `task-<view pid>-<nanos>` (`terminal:277-278`).
PTY ownership: the daemon owns the master (`LiveSession.pty`, `daemon:510-517`); views never own processes. Environment: `Pty::spawn` inherits the **daemon's** environment, adds `command.env`, removes `NX_INVOCATION_ROOT_PID` (`daemon:692`, `UI/🚇️pty/🦀️.rs:54-110`, env at 77-79): `TERM`, `PATH`, tokens, `NX_*` set later in the developer's shell never reach tasks `[run]` (second view with `AUDIT_MARK=second-view` printed `AUDIT_MARK=first-view`, `OUT/f4-render--05-env.txt`, `OUT/f4-second-view--08-env-from-second-view.txt`); `COLORTERM` is empty in tasks.
Output retention: raw bytes, 64 KiB per session (`daemon:562`), no screen snapshot - a replay starts mid escape sequence/UTF-8 and cannot restore alt-screen, colors, title or cursor state; a restart replaces the buffer with an empty one (`daemon:695`) while an attached view keeps the old text `[run]` (`OUT/f1-lifecycle--07-ticker-restarted.txt`: tick lines 6 -> 13).
Stop / kill / restart (`daemon:736-764,659-662`): `stop` writes `0x03` to the PTY, status `stopping`, forced after 2 s (`daemon:737-740`, `tick` `daemon:784-786`); `kill` = `Pty::terminate()` = snapshot of the process table via a spawned `ps -axo pid=,ppid=,pgid=`, `SIGKILL` of descendants bottom-up and `killpg` (`UI/🚇️pty/🦀️.rs:170-205`) - **no `SIGTERM` stage, ever**, and the `ps` fork runs on the daemon's single thread. Exit code: a task killed by a signal is reported as `-1` (`try_wait` `unwrap_or(-1)`), so Ctrl+C, SIGKILL and crashes are indistinguishable and never shown as 130/signal `[run]` (`OUT/f1-lifecycle--04-…`, console §f1). A descendant that double-forks (ppid 1) is outside the snapshot walk `[code]`; in the fixture run the orphan grandchild was nevertheless gone after `Ctrl+B k` (not reproduced as a leak).
Limits: 128 retained sessions with eviction of the **first exited key in `BTreeMap` order** (`daemon:682-685`, journal replay `daemon:497-501`), i.e. lexicographic `task-<pid>-…`, not chronological `[code]`; 16 simultaneous views, the 17th gets the stream dropped (`daemon:586`) and the view's reconnect loop retries every 500 ms forever (`terminal:475-488`) `[code]`.
Events journal: `events.jsonl` append with `fsync` per event (`daemon:481-488`), whole-file replay at daemon start (`daemon:490-504`), never compacted; lifecycle only (no output, no names). Real file: 16 lines/5 848 B for 7 sessions; `dev` sessions repeat `NX_NATIVE_COMMAND_RUNNER`/`NX_TUI` twice in `env` (`tree:332` + `lib` `build_dev_env`) `[run]`.

### A3. Inventory / discovery

- Threading `[code]`: `inv:57-87` spawns one `std::thread` per job; stages: `seed()` (workspace scripts + `.vscode/launch.json` + playground catalog, `tree:69-75`) -> `Ready("quick commands")`; `cached()` (only when `refresh` is false) -> `Ready("cached commands")`; `discover_with_manifests()` (walk, graph, repo-domain) -> publish `manifests.json` -> write `commands.json` -> `Ready("commands ready")`. Cancellation is a flag checked inside the walk (`tree:127`) and the graph read (`tree:163-169,182`), **not** inside `seed`, the snapshot serialization or the manifest write; `Job::drop` only sets the flag (`inv:100`).
- **Cache is written but never read on this workspace `[run]`.** `cached()` rejects files over 16 MiB (`inv:23`); the current version-2 snapshot is **19 775 555 B (2 998 339 B over the limit)**, so the "cached commands" stage never runs and every start re-seeds and re-walks. The date "Jul 10" is the clock excursion (§0), not staleness. `ls -l ⚡️cache/🎛️dashboard/`.
- **The leftover `commands.10870-1791380110558124000.tmp` (13 401 547 B, birth 15:35:10, last write 15:36:01) is a killed write, not a failing rename `[run]`.** The atomic rename works (the 19.8 MB file was renamed 11 s after its tmp was created); the writer `serde_json::to_writer(&mut file, …)` on an **unbuffered `File`** (`inv:74-75`) issues one `write(2)` per JSON token, so writing took 11 s (19.8 MB) to 51+ s (13.4 MB at load 130+). The process was ended (view closed/terminated) while the detached thread was mid-write; the temp file is removed only on a *returned* error (`inv:79`), nothing sweeps old `commands.*.tmp` at start, and exit kills the thread without cleanup. Every real view that lives past the walk starts such a write.
- Walk cost `[run]`: `semio command-tree --dump-tree` (same `discover()`), 43 930 leaves: **5.48 s wall (1.05 user + 3.34 sys), 434 MB peak RSS** at load ~30 (`OUT/command-tree-dump.time`, `OUT/command-tree-stats.txt`). The earlier "46 s" combined walk, snapshot write and a machine at load 130-230.

- Memory/CPU `[run]`: view RSS 84 MB with the real 15.5 k-entry seed, **286-289 MB with a 44 k catalog** (synthetic launch.json, `OUT/b-launcher-44k.results.json`), idle 4-21 MB. The flat list is copied several times: `commands(&tree)` clones every leaf (`inv:93`), `Wizard.options` clones all labels once per Launcher window on **every** `refresh_views` (`terminal:120,139`), and `refresh_views` runs on every inventory update, **every `SessionChanged`** (`terminal:361`) and every `Sessions` frame (`terminal:523`) and resets the scroll offset (`terminal:135`) `[code]`. Typing latency is nevertheless fine at 44 k: first byte 14-15 ms, settled 28-30 ms per key, 13 KB per frame (`OUT/b-launcher-44k.results.json`). Seed of a 10.3 MB launch.json took 12.3 s (`strip_jsonc` char-by-char, `tree:290-309`); the real 3.3 MB file seeds in ~1 s.
- Graph reuse `[code+run]` (`inv:39-54`): reuse only if `project-graph.json` is not older than `nx.json`, `package.json` and **every** of the 566 discovered manifests; measured now: **all 566 manifests, `nx.json` and `package.json` are newer than the graph** (graph mtime is inside the clock excursion), so `NX_FORCE_REUSE_CACHED_GRAPH` is never set and every finite task pays the Nx graph construction again. Even without a clock excursion, any concurrent edit of one `project.json` by another developer/agent flips the answer; manifests created after the last completed discovery are invisible to the guard (README admits this). The check runs on the UI thread at Enter (566 stats + JSON parse, `terminal:449`).

## 4. Fix directions and first tests to add

1. **Transport (P0-1/P0-4):** make the daemon's per-client write path blocking-correct: either keep the socket non-blocking and queue unsent bytes with `POLLOUT`/kqueue, or give the writer thread its own blocking socket (a duplicated fd shares `O_NONBLOCK`, so use `socketpair`/a second accepted stream); never treat `WouldBlock` as fatal; page the `Sessions` frame; send replay as screen snapshots rather than a raw 64 KiB tail. Replace the sleep-poll loop with `poll`/`kqueue` readiness on the PTY masters and sockets. Add a real-socket test: 200 retained sessions + 1 MB replay + stalled client + second-view flap, with a throughput budget (>= 20 MB/s).
2. **Resize (P0-2):** SIGWINCH self-pipe or `TIOCGWINSZ` poll in `NativeTerminal::poll`, forward `Resize` for visible windows, re-send on tab activation. Test: pty resize sequence asserting frame width and `stty size` in a task.
3. **Passthrough (P0-3):** terminal panes forward every key; scrollback/search move behind an explicit prefix (`Ctrl+B [`); Esc/Tab/`/`/PageUp reach the PTY; forward bracketed paste; replace per-key `Input` messages by coalesced byte chunks with back-pressure instead of a 64-slot drop.
4. **Task model (P0-5/P0-6):** extend `SessionCommand`/`SessionInfo` with `label`, `verb`, `source`, `group_id`, `started_at`, `ended_at`, `ready_url`; compound = one group, one tab per member; tab strip with ellipsis, scroll and a visible active tab; status line localized.
