# 2026-10-10 plugin crate pl-c (PluginCloseStep/PluginLifecycleStep mix + close/maintenance/envelope ladders)

## Findings
- The pushed plugin lib is a merge of two states. The three ladder files (`🪜️close-ladder`, `🪜️maintenance-ladder`, `🪜️envelope-ladder`, all new in c44e964) are the newest state: every owner is walked one frontier per turn under the caller's unchanged five-axis grant and quotes its next turn on every axis first. The root `PluginApp for VcsArtifactApp` impl still carried the previous hand-rolled `else if` ladder (`close_step`, `maintenance_step`, `close_retirement_demands`, `maintenance_retirement_demands`, `maintenance_terminal_is_empty`, `drive_envelope_*`, `envelope_return_*`). Evidence that the ladder is the intended end state: the pushed `maintenance_under_pressure` already delegated to `maintenance_ladder_under_pressure`, the pushed `maintenance_step` doc comment already used the ladder wording, and the pushed TS laws (`♻️lifecycle/🏪️stores/🧪️tests/🟦️.ts`, `🧵️retained-command/🪟️mounted/♻️frontier/🧪️tests/🟦️.ts`) assert that the host `close_step` contains `self.close_ladder_step(grant)` and that the ladder contains `CloseRung::DirectIngress => ...close_direct_ingress(grant)` / `CloseRung::GrantedMounted => ...granted_mounted_retirement_step(grant)`.
- `PluginCloseStep` (`Pending { released_items, released_bytes }`) is the previous currency; `PluginLifecycleStep` (full `RetainedCloneProgress` receipt) is current. The TS laws also assert `not.toContain("PluginCloseStep")` for the owners. So the stale side was deleted, not the new one.

## Decisions
1. Root `PluginApp` lifecycle methods delegate to the ladders: `close_retirement_demands` (constructor receipt/phase first, then `close_ladder_demand`), `close_step` (constructor first, then `close_ladder_step` mapped through `PluginLifecycleStep::retained(step, close_terminal_is_empty())`), `maintenance_retirement_demands` -> `maintenance_ladder_demands`, `maintenance_step` -> `maintenance_ladder_step`, `maintenance_terminal_is_empty` -> `maintenance_ladder_terminal_is_empty` (which gained the `window_transient_store.maintenance_terminal_is_empty()` clause the old impl had).
2. `PluginCloseStep` is gone from the crate (type and re-export). Every plugin crate that still names it (`✏️s/🔌️plugins/{draw,fem 2d/3d,cad,sequence,procedural,puzzle,...}`, `🌎️hub/...flow tests`, stdio `🎬️media-export`) must move to `PluginLifecycleStep`.
3. Mounted job hooks (`ArtifactApp`/`ArtifactEditor`/`ArtifactViewer` and the blanket forwards): `mounted_job_{maintenance,close}_step(instance_id, grant: RetainedCloneGrant)` replace the `&mut MountedOwnerTurnV1` parameter (new fixture `🧪️tests/🧬️mutation-fixtures-surface` and the migrated bim plugin already use this shape); the `PluginApp::mounted_owner_{maintenance,close}_step` wrappers pass `turn.grant()` and book the receipt with `turn.record(progress, complete, A::mounted_jobs_terminal_is_empty(..))` themselves.
4. Duplicates: the root `drive_envelope_decode_jobs`, `drive_envelope_field_decoder_returns`, `drive_envelope_completed_record_returns`, `envelope_return_retirement_demands`, `envelope_return_step`, `ArtifactEnvelopeReturnFrontier` were deleted in favour of `🪜️envelope-ladder`. Also deleted as dead old-shape code: `retire_string_scalar`, old `MountedTypedCommandFullOperation::retirement_step(max_items, max_bytes)`, `close_retained_string_page`, `close_retained_bytes_page`, the `original_document_archive_*` method wrappers (the free functions stay, a registry test uses them).
5. `PeerRosterPublication`: `step(presence_store, grant)` replaces the `NativeSnapshotDecodeOwner` parameter. The publication builds its own `NativeDecodeControl::new_retained` + `NativeSnapshotDecodeOwner` per turn, `step_stage` accumulates every store/decoder receipt in that owner and `step` reports `original.progress()` (copied_items floored at one for a stage transition). A new `CommitTyped` stage takes the typed commit (`take_commit`) before `Ready` so the maintenance ladder's `Ready` hand-off needs no decode owner; `take_candidate()` and `retain_rejected_candidate(candidate)` lost their owner/fault arguments, `fail` answers `Progress(one item)`. `terminal_is_empty()` no longer counts the retained outcome fault (it is the hand-off payload: maintenance moves it with `PeerRosterFault::take`, the close ladder pays its transfer through `take_original_fault`).
6. Registry backing is closed by the close ladder: rungs `ChildMemberRetirements`, `ChildRootRetirements`, `DocumentArchive`, `WindowRetirements` now trigger on `empty_backing_byte_demand() != Some(0)` (the old terminal witness required `Some(0)`; the pushed ladder had no rung for it and would have faulted `Uncovered`). `drive_document_archive_load_retirements`/`document_archive_demands` release the empty registry backing through `close_empty_backing_step` when closing.
7. `child_{member,root}_retirement_{demands,step}` now have the ladder shape (`(body) -> RetirementDemand`, `(grant) -> RetainedCloneProgress`); the former `(…, closing)` forms stay as `…_quote`/`…_unit` with `closing = true`.
8. Ladder adaptations to current owner APIs: `InteractiveJobCloseStep::Refused { kind, .. }`, `ChildEmit::{retirement_demands, close_one}`, `PeerPresenceRootRetirement::{retirement_demands(body), close_step -> PluginLifecycleStep}`, `PeerRosterPublication::close_step -> Result<_, Fault>` (inner `close_value_step`), `StepBudget::new(fuel, deadline, grant)` + `StepContext::new(.., &mut sequence, &mut retained_progress)` for the archive hydration, `build_document_store_owners(grant)` returning `(owners, receipt)` with an `owners_admission_fault` helper, `SharedUtf8::close_original_lease` for the latest-wins command actor, `ActiveDocumentArchiveLoad::close_step -> RetainedCloneStep`.
