## Fixes (all in 5d, start 56 errors)
- `io/sqlite/snapshot`: `decode_sqlite_snapshot_native` takes `semio_framework_os_kernel::NativeSnapshotDecodeOwner<'_, '_>` (was `NativeDecodeControl`), same as 3d.
- pack_json `Value` has no `IndexMut`/`is_object`/`is_array`: board/view/3d-window/catalogue/editor node builders now insert through `as_object_mut()` + `Object::insert(key, ..)` (pass `&str` keys directly; `"k".into()` makes `impl Into<String>` ambiguous); import-snapshot `is_document` uses `as_object().is_some()` / `as_array().is_some()`; `puzzle5d_document_from_snapshot` removes/inserts `kindCatalogs` through the object.
- `Cow::into_bytes` gone: precompute fault paths use the `String` message directly (`error.message.into_owned()` where it is a `Cow`, plain `fault.message.into_bytes()` where `String`).
- RetireOwned cascade: derive added on `Puzzle5dGrip3d`, `Puzzle5dGrip`, `Puzzle5dPartAnchor`, `Puzzle5dFastener`, `Puzzle5dPart2d`, `Puzzle5dPart3d`, `Puzzle5dPart`, `Puzzle5dTargetVolume`.
- Codemod leftovers: removed stale `view_state: None` / `window_config: None` initializers from `Puzzle5dFocusSelectionWork`, `PatchPartWork`, `SetActiveExampleWork`, `RegisterBrushMeshWork` (fields no longer exist).
- `Puzzle5dBoardEventsWork`: the nested `Puzzle5dAddBrushPartWork` is no longer staged into the `RetireOwned` owner bundle (it is a command work, not an owned value). It now closes itself first: `begin_close` calls the brush's `begin_close` unless it is already closing (new `is_closing()`), `close_step` and the four `next_close_*_demand` methods delegate to the brush while it exists (converting its terminal `Complete` to `Pending` so the outer work still retires its bundle), `terminal_is_empty` additionally requires `brush.is_none()`.
