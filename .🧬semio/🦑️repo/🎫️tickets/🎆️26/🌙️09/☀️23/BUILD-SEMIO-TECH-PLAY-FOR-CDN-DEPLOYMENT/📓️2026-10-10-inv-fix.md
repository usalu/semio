# 2026-10-10 Missing Invocation At Owned Process Captures

Cause: the peer refactor made `captureOwnedProcess` require `options.invocation` and dropped its `cancelled` option. Seventeen call sites in 14 files still passed neither a complete invocation nor a working cancellation port; several also carried the removed `cancelled:` callback. No site is left (AST-free scan that strips strings and templates: every `captureOwnedProcess(` options object now names `invocation`, none names `cancelled`; the three remaining scan hits pass a prepared `options`/`capture` value that already holds one).

## Design

- Invocation is always the nearest Script owner's `this.invocation`; tests author an actor-style fixture owner (signal, `remainingMilliseconds`, `publish`, `yieldContinuation`) or open a real `withScriptProcessEnvelope`.
- Cancellation of the child is the invocation signal only. Local polled `cancelled` callbacks stay as pre/post checks in their owners but no longer reach the child.
- New neutral helper `scriptInvocationEnvironment(invocation, environment)` in `🧰️framework/🔨️modules/🏃️process/🧭️routing/📥️invocation/🏃️process/🟦️.ts` (re-exported by the TypeScript routing package): hands the caller's current original policy, capabilities and remaining deadline to an owned child via `SEMIO_SCRIPT_PROCESS_INVOCATION`. Needed because the strict preparation script child (`prepare`, via `receiveScriptProcessInvocation`) otherwise only worked when the parent happened to have the variable in `process.env`. No policy is invented; the helper refuses a cancelled or exhausted invocation.
- `FreshProcessControlV1` now carries a required `invocation: ScriptInvocation`. `BrowserActorBuildControl` is unchanged; `buildClosedBrowserActorArtifactV1/Owned` take the invocation as a required second parameter.
