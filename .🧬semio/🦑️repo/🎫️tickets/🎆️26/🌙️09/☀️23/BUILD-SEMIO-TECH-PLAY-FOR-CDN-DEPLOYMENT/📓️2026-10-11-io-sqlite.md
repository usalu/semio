## 1. R1: `io_export_sqlite_snapshot` / `io_import_sqlite_snapshot` had no retirement recipient

### Root cause (verified)

The typed helpers built `SqliteSnapshotControl::new(progress, limits)`. A control owns no `NativeDecodeRetirementRecipient` unless its caller installs one (`install_native_retirement_recipient`), and every projection/reconstruction that owns a tree (`project_owned` / `owned_workspace` -> `with_retirement_owner`) refuses without one ("SQLite snapshot has no explicit retirement recipient"). The helpers are the original caller of these operations, so the recipient and its funded close are theirs. No production site installs one either (`host_io_run`, plugin `step`, reactor jobs build bare controls; they are routed runs, see 2).

### Fix

- `SqliteSnapshotControl::run_as_original_caller(callback, limits, operation)` (`🧰️framework/🔨️modules/🚪️io/🪶️sqlite-snapshot/🦀️.rs`): creates the empty recipient, installs it, runs the operation, then closes the recipient before returning. The close grant is the allocation ceiling of the caller's own `limits` on every axis (items, copy, capacity, release; depth 4096), a refused or idle turn is retried once with the grant widened to the owner's own quote, and a recipient that still stops progressing is refused (and forgotten rather than aborting in its `Drop`). This is the same funding rule the plugin runtime uses (`widest(policy, quote)`).
- `io_export_sqlite_snapshot` / `io_import_sqlite_snapshot` (`🧰️framework/🛍️products/💻️os/🔨️modules/🚪️io/🦀️.rs`) run their whole body inside it; their signatures are unchanged, so no caller changes.
- New law in the sqlite-snapshot crate (`♻️retirement/🧪️tests/🦀️.rs`, `sqlite_original_caller_installs_funds_and_closes_its_own_recipient_across_cancellations`): cancellation at event 0, 1, 2 and completion each end with `requested == released` under the global allocation observer, so the recipient is physically closed on every path. Crate `--lib`: 54/54.

## 2. K2: "missing SQL `receiving` implementations"

### What `receiving` is

`ArtifactSqliteSnapshot::{to,from}_sqlite_database_receiving` and `validate_sqlite_snapshot_subset_{decoding,encoding}` are the receiving halves of the routed SQLite hop (`io_run` native <-> `SQLITE_SNAPSHOT`), driven by `sqlite_snapshot_retirement::{export,import}`. That hop is the user-visible .sqlite snapshot export/import of every editor (host `host_io_run`, plugin snapshot authority, hub `editor_catalog` `sqlite_snapshot_*` laws). Their defaults failed closed, so every editor but binary/csv/tsv/xml-style ones (and flow/workflow/run/collection/space/dag, which had a one-line bridge) refused the hop.

### Shared implementation (no per-editor code)

The authored relational model (`to_sqlite_database` / `from_sqlite_database` / `validate_sqlite_snapshot_subset`) already exists for every editor; the receiving defaults now run it under the original owner:

- NEW `🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/📦️codec/🪶️snapshot-capability/🪆️workspace-receiving/🦀️.rs`: `project` / `reconstruct` run the authored producer through `NativeDecodeControl::with_encoding_receiver` and `SqliteSnapshotControl::with_original_allocation`, so every allocation the producer admits is charged to the original native control (ceiling = `before + SQL allowance`, same rule as the hand-written receivers); `validate_*` check native cancellation first, then apply the authored subset policy. `staged` runs one stage with its own empty workspace recipient on the control and retires whatever the stage retained through the owner's `receive` (so a stage that retains nothing costs zero items).
- The trait defaults (`store/🦀️.rs`) delegate there. `sqlite_snapshot_retirement::{export,import}` run every stage (native decode/encode, projection, reconstruction, validation) through `staged`, so the one place that composes the hop supplies the recipient to every editor, including those with explicit receiving implementations.
- Six one-line `owner.native().checkpoint(); self.to_sqlite_database(control)` bridges (flow, workflow, run, collection, space, dag artifacts) were deleted; they ran the authored model without a recipient and now use the shared default. Binary/csv/tsv/xml/mcp keep their hand-written zero-copy receivers.
- Design traps found on the way (all in the source now): one recipient holds one owner, so each stage needs its own (a shared per-operation recipient made flow's second tree stage fail with "no available explicit retirement slot"); an inner `receive` frame per default costs ~5 items per call and exhausted tight shared grants, hence "pay only when non-empty"; `receiving::settle` assumes native-only allocation and underflows for producers that admit through `allocation_stage_native` (svg), so the default does not call it.
