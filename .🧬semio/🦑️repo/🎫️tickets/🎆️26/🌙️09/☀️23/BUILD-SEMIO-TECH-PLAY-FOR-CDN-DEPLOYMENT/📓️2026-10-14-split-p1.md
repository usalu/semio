## 2. Cut plan

### 2.1 Workspace

The engine and the epw extension are plugin modules, so the workspace root moves from `🗿️artifacts/🔋️model/Cargo.toml` to
the plugin, `✏️s/🔌️plugins/🔋️energy/Cargo.toml` (like `🗄️stdio`, `🔱️trinity`, `📕️norm`), and the repository root's
exclude row follows. `🏭️bridge` keeps its own workspace.

### 2.2 Crates

Every crate is a taxonomy folder with `📦️packages/🦀️rust/Cargo.toml` and `[lib] path = "../../🦀️.rs"`, rlib, no features.
Package names ≤ 48 characters. Consumers declare the crates they name; a crate root names a dependency with a private
`extern crate <package> as <module>;` so the existing `crate::<module>::Item` paths keep naming the owning crate.

### 2.3 Domain inversions

- **Mutation vocabulary.** The 297 flat leaves move into the framework's registered domain-operation layout
  (`mutationDomainOwners`, the same authority gltf and architect use). Each leaf implements
  `MutationKind<EnergyModelSnapshot, Op>` for every `Op: Mutation<EnergyModelSnapshot, Diff = EnergyModelDiff> + From<…>`
  and its builder returns `Op: From<Payload>`, so leaves never name the aggregate; `#[derive(dsl::Mutations)]` already emits
  the `From` impls. Fixture directories move with their leaves.
- **Fixture tests** read their committed quintet at run time instead of `include_str!` (the bytes stay the specification).
- **Facet leaves.** Each schema facet owner embeds its own five leaves; the descriptor assembles them.
- **Engine.** `ScheduleId` moves to `schedule`, `MAX_PANES` to `model`; upward test edges move to the crate that owns the
  higher module (or to the aggregator's integration tests).
- **Root composition** moves to its owners (snapshot construction to the snapshot crate, editor-only views to the editor).

