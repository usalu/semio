Hard facts the cut has to respect:

- `⚙️engine/🧪️sim/🦀️.rs` alone is 5,176 lines; `impl EnergyJobAuthority` is one 2,034-line inherent impl.
- `🧬️schema/🦀️.rs` embeds every facet leaf (artifact, snapshot, diff, mutations: 534 KB). The mutations facet alone is
  315 KB with its 109 KB aggregate; the diff facet is 202 KB.
- 2,970 committed fixture files are `include_str!`-ed by the 594 per-kind fixture tests (10 per kind); one test unit can
  hold at most 32 files.
- The aggregate `EnergyModelMutation` wraps 297 leaf payloads and every leaf names the aggregate (builder, `MutationKind`
  impl, inverse) — an enum↔leaf cycle that blocks any crate split of the vocabulary.
- Engine module cycles: `model`↔`schedule` (`ScheduleId`), `model`↔`fenestration` (`GasKind` / `MAX_PANES`). Test-only
  upward edges: `kernel`, `sizing`, `precompute` → `sim`; `sim`, `precompute` → `bestest`; `scene`, `bestest` → artifact.
- Lower artifact layers reach root items (`energy_snapshot_with_state`, the child types, the schema ids).

## 2. Cut plan

### 2.1 Workspace

The engine and the epw extension are plugin modules, so the workspace root moves from `🗿️artifacts/🔋️model/Cargo.toml` to
the plugin, `✏️s/🔌️plugins/🔋️energy/Cargo.toml` (like `🗄️stdio`, `🔱️trinity`, `📕️norm`), and the repository root's
exclude row follows. `🏭️bridge` keeps its own workspace.

### 2.2 Crates

Every crate is a taxonomy folder with `📦️packages/🦀️rust/Cargo.toml` and `[lib] path = "../../🦀️.rs"`, rlib, no features.
Package names ≤ 48 characters. Consumers declare the crates they name; a crate root names a dependency with a private
`extern crate <package> as <module>;` so the existing `crate::<module>::Item` paths keep naming the owning crate.

| Family | Crates | Package pattern |
|---|---|---|
| Engine (`🔨️modules/⚡️simulation/⚙️engine/<m>`) | one per module (52) + the `🧪️sim` facets it needs to fit | `semio-s-plugin-energy-engine-<m>` |
| EPW extension (`🧩️extensions/🌦️epw`) | 1 | `semio-s-plugin-energy-epw` |
| Snapshot (`🧬️schema/📸️snapshot`) | snapshot record, child types, structure/zone converters, snapshot construction (moved down from the root) | `…-energy-model-snapshot` |

### 2.3 Domain inversions

- **Mutation vocabulary.** The 297 flat leaves move into the framework's registered domain-operation layout
  (`mutationDomainOwners`, the same authority gltf and architect use). Each leaf implements
  `MutationKind<EnergyModelSnapshot, Op>` for every `Op: Mutation<EnergyModelSnapshot, Diff = EnergyModelDiff> + From<…>`
  and its builder returns `Op: From<Payload>`, so leaves never name the aggregate; `#[derive(dsl::Mutations)]` already emits
  the `From` impls. Fixture directories move with their leaves.
- **Fixture tests** read their committed quintet at run time instead of `include_str!` (the bytes stay the specification).
- **Facet leaves.** Each schema facet owner embeds its own five leaves; the descriptor assembles them.
- **Engine.** `ScheduleId` moves to `schedule`, `MAX_PANES` to `model`; upward test edges move to the crate that owns the
  higher module (or to the aggregator's integration tests).
- **Root composition** moves to its owners (snapshot construction to the snapshot crate, editor-only views to the editor).

### 2.4 Dependency graph (planned)

```
engine leaves (units, num, error, props, curves, calendar, geometry, …)
  → model (+ schedule, air_exchange, calendar, geometry) → solvers (fenestration, precompute, kernel, sizing, sim facets)
  → bestest, scene
epw → engine
snapshot → engine model, stdio semio value/table
diff → snapshot
mut-<domain> → snapshot, diff, engine (and sibling domains named by an inverse)
mutations → mut-<domain>*, snapshot, diff
schema → snapshot, diff, mutations
inferences → snapshot
io / import / export / sqlite → snapshot, diff, mutations, engine
session → engine, snapshot
examples → engine, snapshot
editor* → mutations, snapshot, session, examples, io
viewer → snapshot, mutations
aggregator → all layers (registration only)
mutation-fixtures (tests) → mutations, mut-<domain>*
```
