## What was wrong and the fixes

1. `launch(kind, || Ok(Pipeline...exported/finish))` in brep-feature, brep-transform, brep-topology, brep-intersect and io brep-interchange: the pushed `launch` took a closure returning `Pipeline`, but `exported`/`finish` return `Box<dyn WidgetJob>` (the "Pipeline replaces Box<dyn WidgetJob>" errors, ~20 sites). Root cause fix: all callers use the existing `guarded` (brep-curve); `launch` deleted from phased-job; `brep_curve` made `pub(crate)` so io can use `guarded`.
2. `ShapeValue` import (brep-transform); `&*work.source(0)?` for the `Arc<ShapeValue>` (brep-surface); `work.handles()` hoisted before the `&mut` kernel borrow (brep-topology).
3. `GeometryValue: PartialEq` is now manual, meshes compare by `Arc::ptr_eq` (`HalfedgeMesh` lost `PartialEq` when its attributes became `HistoryFoldIndex`; meshes are sealed shared values).
4. Mesh kernel grant API: `mesh_support::modeling_slice` (grant `{items: budget, copy: 1 MiB, others MAX}`, same funding as the kernel's own sync drivers) and `tessellation_slice` (one producer event per loop turn under the exact quote `next_normal_*_demand`, copy floor 128, as `HalfedgeMesh::tessellate` does). Used by mesh-support (`Stepper`, `FromSource`), mesh-convert, mesh-interchange. `mesh_fault` handles `MeshKernelError::Retained`.
5. `BrepError: From<KernelError>` does not exist: new `value::body_fault(&KernelError)` (the engine's own `BrepError::Operation(e.to_string())` mapping), exported in the geometry prelude.
6. io mesh bridge: `MeshData` materials/textures/attributes are `HistoryFoldIndex` (re-exported by mesh-engine): `merge_attributes` returns it; the non-`Copy`-key `entry()` replaced by `contains_key` + `insert` + `get_mut`; `import_semio_mesh` builds `HistoryFoldIndex`.
7. geometry-service: `new_contextual` gets a demands fn (`geometry_inference_demands`: default, because every call ends terminal in its own turn and keeps no child between turns, same shape as the framework's own `completed_child_demands` tests); `ArtifactInferenceExecution.retirement_progress = {copied_items: 1}`; `request.cancelled` cancels the host and returns a terminal empty step; zero item/depth grant returns a non-terminal empty step; `ToValue as _` imported for `Quality::to_value`.

## Decision deviating from the brief (needs main's review)

The brief asked to reuse the flow brep extension's retained geometry inference instead of keeping this engine. I did not: the flow extension executes one neural-engine operator request, while generation3d's engine evaluates a whole catalogue widget graph (typed `GeometryValue` cache, dependency hashes, 25 compute tables, ~36k lines of fixtures and tests). The only shareable parts (the inference service shell and the kernel calls) are tiny or kernel-API calls, not extractable code, and a replacement would drop catalogue kinds. Both sides call the same `semio_framework_3d` kernel; no kernel logic was duplicated. Note the flow extension itself still has old-signature mesh calls (`job.step(4096)` at `🥽️mesh/🦀️.rs:115,301,396,497,578`), owned by mg-misc2.
