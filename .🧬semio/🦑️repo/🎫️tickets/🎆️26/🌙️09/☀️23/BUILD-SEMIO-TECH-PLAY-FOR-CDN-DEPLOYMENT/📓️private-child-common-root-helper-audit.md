# Private Child Common Root Helper Audit

The current durable_group stage_store_member cannot be called directly as a bounded object-safe publication step. At lines534–570 it clones the entire live applied-edit ID stack twice and revision accumulator once using retained_string_stack and retained_revision_stack. Those helpers loop every source element without a grant, progress checkpoint, deadline or cancellation witness. index_applied_edit and the foreign_steps loop also process an entire prepared edit. This is valid cold preparation evidence, not a bounded interactive stage contract. Making this function public alone would reproduce those unbounded operations for each existing child history.

The helper's common-root visibility mechanism is reusable: ArtifactGroupVisibility is shared by staged history, cursor and the pending root; staging reserves12 displaced slots and one exact history position before publication. The root retains post_snapshot, generation, revision, clock and old-head tail alias. Adopt checks exact Arc visibility and committed state, transfers owned state and queues displaced cursors/stacks/revision/current/authority through retained factories. It preserves the old current alias when the new tail shares that exact Arc. Abort requires the same uncommitted visibility and retains rejected ownership through retirement. These ownership and visibility semantics should be factored behind the existing exact member publication seam.

SpaceMember already exposes begin/advance/prepare/abort_one_item_publication. Its concrete MemberStoreOneItemPublication preserves the exact read-lease identity, typed bounded ApplyBatch cursor, history reservation and12 displaced slots. prepare stops in Publishing and reserves these in separate one-item turns; advance explicitly refuses group-reserved candidates crossing the solitary publication path. The group seam must keep that typed retained owner, then perform bounded root preparation before the common visibility flip. Type erasure can downcast the sealed owner exactly as existing prepare does, without exporting domain types.

Recommended implementation: retain a staged-root preparation cursor at the same typed publication owner and copy each identity/revision entry under the caller item/copy/capacity grant before any staged visibility mutation; include cancellation/refusal cleanup for partial destination stacks. The final reserved stage operation can reuse the ownership/visibility transfer portion once preparation is complete. Reserve-only preparation must not call the current whole-history stage helper. The private new child remains outside the live registry until the common decision commits, with exact MemberFactory::Open and declaration authority retained throughout.
