## 2. Cut plan

### Decisions

- **D1 Names.** The aggregators keep `semio-s-artifact-procedural-generation3d` / `-generation2d`. Layer crates are `semio-s-artifact-procedural-3d-<layer>` / `-2d-<layer>`: the full prefix `…-procedural-generation3d-` is 41 characters and leaves 7 under L4's 48; `-3d-` leaves 16, which fits every folder-derived layer name (longest: `analysis-measure`).
- **D2 One crate per owner folder.** A crate's root is its owner folder's own `🦀️.rs` (`[lib] path = "../../🦀️.rs"`); its descendant folders belong to it unless they are crates themselves. Where the taxonomy is flat (operator facets, editor commands), the next taxonomy level is the leaf folder, so the split is per leaf folder, never a grouping crate without a folder.
- **D3 One owner per item, no facades.** Items move to their domain owner first (inside the monolith, compile-atomic with `🔀️repoint.py`); `pub use` facades (root re-exports, the geometry `prelude`) are deleted, never re-pointed; consumers name the owning crate.
- **D4 Fixture-iterating laws read fixtures at test runtime** (`std::fs::read_to_string(concat!(env!("CARGO_MANIFEST_DIR"), …))`) where compile-time embedding alone breaks the 32-file or byte ceiling (same rule as P5 D4). Per-case tests keep `include_str!` when they fit.
- **D5 Mutation kind SCC.** Every kind names the union in `MutationKind<Generation3dSnapshot, Generation3dMutation>` and every inverse facet constructs it, and the taxonomy keeps payload, `🔺️diff` and `↩️inverse` in separate leaf directories: union + 26 kinds + facets + central apply are one crate (`-3d-mutations`, ~71 files). Kind fixture tests become `[[test]]` targets of that crate, grouped ≤32 files.
- **D6 Cross-layer tests go to the aggregator** (graph editor replay, touched-region laws, document restoration, gesture leaves with codec witnesses); support helpers that several layers need go to a test crate.
- **D7 Operator facets keep their white-box unit tests.** The fixture support helpers need the full catalogue and the registry, so a facet crate's tests dev-depend on the geometry registry crate (a dev-dependency edge only; no normal-dependency cycle).
- **D8 The operator catalogue is embedded per facet.** Each facet crate embeds its own category JSON; the geometry crate assembles the full catalogue (419 KB never sits in one unit).
- **D9 Shared plugin core.** `🫀️core/🧬️generation/🪶️sqlite` and `🫀️core/🖼️semantic-ui` are mounted by both artifacts today; they become the plugin crates `semio-s-procedural-core-generation` and `semio-s-procedural-core-semantic-ui` in their own `🫀️core` workspace (as `🪐️space/🫀️core`).
