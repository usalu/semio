## 2. Cut plan

### Decisions

- **D1 Owner-rooted crates** (brief + Lane C): every crate is `<owner>/📦️packages/🦀️rust/Cargo.toml` with `path = "../../🦀️.rs"`, and the owner's `🦀️.rs` is the crate root. Module paths are relative to the owner, so `crate::standards::v1::subsets::any::schema::diff::Puzzle3dDiff` becomes `semio_s_artifact_puzzle_3d_diff::Puzzle3dDiff`. Items reach consumers only from their owning crate; the `pub use` facades (`schema::Puzzle3dMeta`, `editor::quat_*`, mutation `pub use super::<leaf>::mutation::*`) are deleted and their consumers retargeted.
- **D2 Mutation leaves are generic over the dispatch enum** (same as P5 D2): `impl<Op> MutationKind<Puzzle3dSnapshot, Op> for MoveObject where Op: Mutation<Puzzle3dSnapshot, Diff = Puzzle3dDiff> + From<MoveObject>`. The leaves sit below the union and depend on model + diff only; the union crate owns the enum, `From` impls, the central apply and the inverse delegate. Builders that returned the union return `impl Into`-free concrete payload constructors; the union crate keeps one builder per variant.
- **D3 Mutation groups are domain-operation roots** (`mutationDomainOwners`, the mechanism architect and gltf already use): leaves move to `🧬️mutations/<entity>/<leaf>/`, each entity group is one crate `-mutations-<entity>` (≤ 10 leaves = ≤ 31 files), registered in `🔣️taxonomy.json` and the regenerated `🔣️mutation-authority.json`. Descriptors keep their `semanticKind`; only `owner` changes.
- **D4 Fixture tests read fixtures at runtime** (same as P5 D4), resolved against `CARGO_MANIFEST_DIR`. Kind fixture tests become `[[test]]` targets of the union crate (one per entity group).
- **D5 Large editor files are cut along their own regions** into the taxonomy dirs that already name them (`📸️snapshot` for the scene projection, `🧵️retained` for retained works, `🎮️commands` for actions), never into a catch-all.
- **D6 Shared puzzle code is plugin-level crates** (`semio-s-plugin-puzzle-jobs`, `-retained`, `-board-scene`); no artifact mounts plugin-level source any more.
- **D7 Retained works are generic over the editor** (`impl<A: Puzzle3dEditorTypes> ArtifactCommandWork<EditorApp<A>>`), so the crate holding `impl ArtifactEditor for Puzzle3dPlayApp` and its job factory sits above them.
- **D8 `capsule-dream` cannot fit any unit.** It stays in its own example crate and is reported as the remaining over-ceiling unit until the plugin SDK (E2b) admits an asset-backed `ExampleSource` body.

Test restructuring decisions:

- **T1 Cross-crate test seams are a `testing` feature.** Each seam is gated `#[cfg(any(test, feature = "testing"))]`, the stdio contract/gltf pattern. The seams are: the model's serde oracle and precompute harness, the leaves' and union's serde oracle, the jobs/retained `testing` modules, and the brush/fill test hooks. A crate with tests enables `testing` on every family dependency that declares it.
- **T2 Mutation scene tests are seven `[[test]]` targets of the union crate**, one per group (`<group>/🧪️tests/🦀️.rs`). Their 313 fixture embeds read at runtime. The canonical-JSON check of the mutation encodes with the framework writer and compares as `serde_json::Value`, so serde_json stays the third-party oracle without a test-only derive on the union in an integration target.
- **T3 Store tests live in the host crate.** `🔨️modules/🏠️host/🧰️owned` (the store constructor/retirer, only used by tests) is its own crate, `-host`. Its `store` target runs the command-envelope law (one copy; the text and binary snapshot files each had one), granular replay, and the selection time-travel corpus.
- **T4 Editor unit tests (7 573 lines) are four editor `[[test]]` targets**: `editor-surface`, `editor-panels`, `editor-budgets` and `editor-gestures`. They share a context module `🧪️tests/🧰️context`, and four helpers moved into it. The source-inspection tests read the editor root at runtime.
- **T5 The brush and fill unit tests are `[[test]]` targets of `-editor-session`.** They name the session's scene projection and instance owner. Moving fill's tests also takes the fill test unit from 5 139 to 3 414 lines.
- **T6 The SQLite snapshot suite is an aggregator `[[test]]` (`snapshot-sqlite`)**, because it drives the play snapshot and the public app forms. The manifest-catalog law is an aggregator unit test, and the play-pack law is an `-editor-snapshot` unit test.
- **T7 Deleted example text constants are runtime reads** of the authored example DSL.

Other fixes:

- The generated graph-manifest registries now import `semio_framework_graph_manifest::Manifest`, which is what the generator emits since 10-14. They were stale against a renamed crate.
- `PUZZLE3D_INTERACTION_TOPOLOGY_BUILDS` counts unconditionally, like its sibling geometry counter.
- `retained_command_test_catalog` was dead and is removed.
- The hub `editor` facade module is deleted.
