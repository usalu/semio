# Descriptor Source Snapshot Readiness

The repository supports preparing a disposable checkout for incremental tests. The current descriptor producer can issue a valid receipt only for its own workspace, and the release consumer requires that exact workspace in the retained receipt. The incremental checkout, a machine state directory and the `codeRoot` field therefore do not provide a supported frozen-source handoff to a live release. This was a read-only source and fixture review. It did not create a checkout or run Cargo, materialization, dependency synchronization or release commands.

| Incremental checkout | `incrementalTrackedFilesV1` inventories tracked and non-ignored untracked files plus selected ignored outputs. `incrementalCloneV1` reflinks or copies the current files into a disjoint disposable root. The per-file copy can skip a path that disappears and the operation does not revalidate the complete roster. The result is writable. `prepare` invokes the copy's own repo entry to run preflight, tool setup and dependency synchronization, any of which can alter the prepared inputs. ## Smallest testable boundary

A disposable checkout with distinct machine storage could be used to exercise production descriptor issuance and consumption **inside that checkout**. A source-roster seal after preparation would still be required to establish that it consumed a complete, consistent captured revision, and there is no checked-in complete descriptor proof through this path. For the canonical release to consume the result, the missing API is an issued release source view that carries a verified revision identity and its materialized path through Cargo planning, source selection and retained artifact consumption. Keep the actual compiler origin in the receipt. The consumer would need to verify the issued source view identity as well as the storage owner. A synthetic first test can exercise original workspace, snapshot workspace and revision identity independently, demonstrate rejection of a foreign or changed revision even when the artifact directory is shared, and keep the existing receipt validation. An end-to-end release additionally needs the same revision across descriptor subprocesses, native and WASM jobs, and site assembly. [Prior release snapshot review](release-source-snapshot.md)
