## 2. Cut plan

### Decisions

- **D1 Engine is one shared crate family**, `semio-s-fem-<facet>` (role `s-module`), each crate rooted at its existing engine folder. No artifact mounts engine source any more; fem2d, fem3d, the bridge and norm name the engine crates directly. The `pub use` of element types from the engine model is deleted (one owner per type).
- **D2 Mutation kinds are generic over the dispatch enum.** `impl<Op> MutationKind<Fem2dSnapshot, Op> for CreateNode where Op: Mutation<Fem2dSnapshot, Diff = Fem2dDiff> + From<DeleteNode>`. That inverts the kind → union edge, so the kinds sit below the union and depend on the model only. The union crate owns the enum, the inverse delegate and the central apply.
- **D3 Groups over the file ceiling split along the next taxonomy level (brief rule).** The mesh mutation subset (13 kinds, 39 files) and the editor command folders (34 and 31 commands) are each one crate per leaf folder. Subsets that fit (load 30 files, boundary, material, analysis) are one crate each.
- **D4 Fixture tests read their fixtures at test runtime** (`fixture!("…")`, resolved against `CARGO_MANIFEST_DIR`) instead of `include_str!`. The fixtures stay the language-agnostic source of truth shared with the Python oracles; only the compile-time embedding goes. Otherwise the 266 fixture tests would need about 45 test binaries.
- **D5 Kind fixture tests are integration tests of the union crate** (they apply through the central apply and invert through the union): one `[[test]]` target per subset, split by kind group where a subset exceeds 32 files.
- **D6 `component-app-assembly` is deleted (L2).** The editor, viewer and app-surface code it gated lives in its own crates. Only the aggregator and the hub name those crates.
- **D7 The fem3d engine** (`✏️s/🔨️modules/🏗️fem/⚙️engine/🧊️3d`) depends on fem3d document types, so it moves into the artifact (`🧊️3d/⚙️engine/🧊️3d`), mirroring `◻️2d/⚙️engine/◻️2d`. `✏️s/🔨️modules` then never depends on `✏️s/🔌️plugins`.

## 3. Execution log

- The engine model's closed element set (`Elements`), the dense `Model` and `solve_linear_static` moved to the new `semio-s-fem-static` (`⚙️engine/⚖️static`); the element contract stays in `semio-s-fem-model`, which no longer re-exports element types. The closed enum imports the trait's exported `__semio_dispatch_Element!`. The element unit tests that solve through `Model` (unit, continuum, plate, 3d unit, shell) moved to `⚖️static/🧪️tests`; the 3d solid tests (they call `solve_multi_case`) moved to `🧮️analyses/🧪️tests/🔬️solid`.
- `🔢️sparse/🦀️.rs` (5 829 lines) was cut with `split-p5/✂️file-cut.py` + `✂️sparse-cut.json` into `semio-s-fem-sparse` (storage, RCM, the numerical job protocol and checkpoint page codec), `-sparse-ldlt` (`🔢️sparse/🔺️ldlt`), `-sparse-pcg` (`🔁️pcg`) and `-sparse-subspace` (`🎵️subspace`, incl. the modal input construction). Its 2 316-line test file was split by the crate each test reaches (`🧩️items.py` reference map). `Coo::graph_laplacian_plus_identity` replaces the test-local helper that all four test files used.
- `🧮️analyses/🦀️.rs` was cut into `-analyses-model` (`🗂️model`), `-analyses-assembly` (`🧩️assembly`) and `-analyses` (job graph, multi-case, modal, buckling, averaging).
- `semio-s-fem-mesh` became a `✏️s` workspace member (its standalone `[workspace]` is gone) and lost the derived meshes and the region surface schema to `semio-s-fem-mesh-derived` (`🕸️mesh/🧬️derived`), which is what those tests need (extrusion, tets, boundary faces).
- Engine test vectors moved from `🧪️tests/⚙️engine` (mounted into fem2d) to the dev-only crate `semio-s-fem-test-support` (`🧪️tests/🧰️support`), plus the shared close helpers (`test_operation`, `grant_of`, `tuple_of`, `checkpoint_payload`, `accounted_close`, `close_turn`).

- **Job API migration (not part of the cut, but required to compile).** Peer fleet A replaced `InteractiveJob::close_step(grant) -> InteractiveJobCloseStep` with `close_step(cx) -> Result<_, OriginalTurnFailure>` and removed `Refused` (15:47). Every fem job now keeps its grant ladder as `close_granted(grant) -> Result<_, ValueError>` and implements `close_step(cx)` through `numerical_close_original` (sparse core) over `close_original_retained_step`; `step` returns `OriginalTurnFailure`. Tool: `split-p5/🪙️close-migrate.py`. Test drivers use `close_turn(job, grant)`; contexts that are now `Drop` are dropped before the next one borrows the same slots (`🧹️context-scopes.py`); `block_on(token.cancel())` became `token.cancel_now()`.
