Goal: a static release of semio-tech play that can go on a CDN with every app pane booting; bugs are acceptable.

## Path taken

- `native-play.sh` and `native-launch.ts` live in this folder. `native-launch.ts` is the sibling's launcher, with owner `native-play`; it issues the script-process envelope and the provider designation that the graph runner would issue.

## Blockers fixed on the way

1. **Job graph refused.** The driver refused with `Finite job-only prerequisite graph required`.
   - Since the Nov 14 retention change, the driver finishes every declared job before any Cargo pass starts (`component-pass/🟦️.ts`, `nativeBuildPrerequisiteOrderV1` and the `await` over all `job:` completions). Play's `pages` job waited on `components:complete`, so it was refused, and it would have deadlocked if admitted.
   - Fix: `pages` is no longer a driver job. `runBuildScript` (`🔨️modules/📦️site/🟦️.ts`) publishes the pages through `publishPlayPageCohortV1` once `buildReleasePipelineV1` resolves.
   - Updated alongside: the laws in `🧪️tests/🧩️release-job-order` and `🧪️tests/🧪️playfreshbuild` (and its fixture), the `📜️script.ts` doc and both README tables.
2. **describe-tool argument.** describe-tool failed with `One exact actual-host build argument required`. Play's job lacked the reserved `--host-platform={hostPlatform}` token that the root `release` pipeline already carries; the job now has it.
3. **Compiler probe EACCES.** Every Cargo pass failed at the compiler probe with `EACCES` on the sealed unit-cache `📜️script.ts`.
   - Cause: two wrapper conventions met. The driver's `compilerWrapperEnvironmentV1` set `RUSTC` to the sealed script, while the lane's shim treats `RUSTC` as the real compiler.
   - The run now uses `SEMIO_UNIT_CACHE=off`. A fix pass unified the chain on the shim convention (`📓️2026-11-17-rustc-wrapper-chain.md`); no real driver pass has run through it yet.
4. **Single compile unit.** The run compiled at `-j1`, for two reasons:
   - `repo capacity run --memory=X` books X as fixed memory with 0 MB per job. The units planner (`🎟️capacity/🧮️units`) counts only the per-job memory, so it always planned 1 unit. The site step now runs under `--operation=cargo --jobs=6`, which grants 2048 MB per job.
   - Without unit history, the planner assumed the authored 2048 MB per unit, while measured units are about 300–420 MB. The authored default `megabytesPerUnit` is now 512, and `🧪️tests/🟦️.ts` pins it (14/14 pass). The admission broker still freezes when actual RSS exceeds the budget.
   - Together the driver plans `-j4`, and its grant can grow when the host frees memory.
6. **describe-tool takes about 30 minutes.** The retention snapshot re-verified the whole storage reservation three times per file, about 92 ms per file across 3,928 files. Retention now runs inside the recheck window (`📓️2026-11-17-describe-tool-slow.md`).

   - The job now runs the package's own producer, `../../🏗️build/📜️script.ts wasm` (exactly its `wasm` target), with policy `process`. The producer derives its compiler policy from the Rust family itself.
