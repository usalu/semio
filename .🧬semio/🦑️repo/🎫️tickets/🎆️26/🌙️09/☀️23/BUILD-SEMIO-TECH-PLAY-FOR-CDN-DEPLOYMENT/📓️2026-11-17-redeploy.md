## Blockers fixed on the way

1. **Job graph refused.** The driver refused with `Finite job-only prerequisite graph required`.
   - Since the Nov 14 retention change, the driver finishes every declared job before any Cargo pass starts (`component-pass/🟦️.ts`, `nativeBuildPrerequisiteOrderV1` and the `await` over all `job:` completions). Play's `pages` job waited on `components:complete`, so it was refused, and it would have deadlocked if admitted.
   - Fix: `pages` is no longer a driver job. `runBuildScript` (`🔨️modules/📦️site/🟦️.ts`) publishes the pages through `publishPlayPageCohortV1` once `buildReleasePipelineV1` resolves.
   - Updated alongside: the laws in `🧪️tests/🧩️release-job-order` and `🧪️tests/🧪️playfreshbuild` (and its fixture), the `📜️script.ts` doc and both README tables.
2. **describe-tool argument.** describe-tool failed with `One exact actual-host build argument required`. Play's job lacked the reserved `--host-platform={hostPlatform}` token that the root `release` pipeline already carries; the job now has it.
3. **Compiler probe EACCES.** Every Cargo pass failed at the compiler probe with `EACCES` on the sealed unit-cache `📜️script.ts`.
   - Cause: two wrapper conventions met. The driver's `compilerWrapperEnvironmentV1` set `RUSTC` to the sealed script, while the lane's shim treats `RUSTC` as the real compiler.
   - The run now uses `SEMIO_UNIT_CACHE=off`. A fix pass unified the chain on the shim convention (`📓️2026-11-17-rustc-wrapper-chain.md`); no real driver pass has run through it yet.
4. **Single compile unit.** The run compiled at `-j1`, for two reasons:
   - `repo capacity run --memory=X` books X as fixed memory with 0 MB per job. The units planner (`🎟️capacity/🧮️units`) counts only the per-job memory, so it always planned 1 unit. The site step now runs under `--operation=cargo --jobs=6`, which grants 2048 MB per job.
   - Without unit history, the planner assumed the authored 2048 MB per unit, while measured units are about 300–420 MB. The authored default `megabytesPerUnit` is now 512, and `🧪️tests/🟦️.ts` pins it (14/14 pass). The admission broker still freezes when actual RSS exceeds the budget.
   - Together the driver plans `-j4`, and its grant can grow when the host frees memory.
6. **describe-tool takes about 30 minutes.** The retention snapshot re-verified the whole storage reservation three times per file, about 92 ms per file across 3,928 files. Retention now runs inside the recheck window (`📓️2026-11-17-describe-tool-slow.md`).
7. **flow-wasm reads a missing `Cargo.toml`.** Play's `flow-wasm` job called the stale `./📜️script.ts` in `🎁️browser-package/📦️packages/🦀️rust` and declared `cargo` and `wasm` owner policies.
   - Both policies read `Cargo.toml` at the job root, which has none, so the job failed with ENOENT at second 0.
   - The job now runs the package's own producer, `../../🏗️build/📜️script.ts wasm` (exactly its `wasm` target), with policy `process`. The producer derives its compiler policy from the Rust family itself.
   - A preflight of `ownerEnvironmentV1` over all 12 jobs passes.
8. **The driver does not fail fast.** The flow failure at second 0 surfaced only after describe-tool finished, 30 minutes later. A fail-fast pass is in progress (`📓️2026-11-17-driver-fail-fast.md`).
9. **Wasm producers refused their parent's envelope.** Every wasm producer job (flow, surface and the rest) failed with `Nested Original process envelope must preserve its actual parent`.
   - `buildRepositoryWasmWebV1` re-enters the compiler store with `scriptInvocationEnvironment(invocation)`.
   - Under a finite deadline credited by an admission wait, that projected envelope differs from the birth envelope. The in-process nested receive (`withScriptProcessEnvelope`) compared only against the birth envelope, although every projection is recorded in `birth.projectedWires`.
   - Fix: the nested receive also accepts the parent's recorded projections. A foreign envelope is still refused.
   - Law: `🧭️routing/📥️invocation/🏃️process/🧪️tests/🪆️projected-parent`, which simulates the admission wait.
   - The launcher is now `native-build-launch.ts`, which issues the genuine deadline-free build-caller envelope for `@semio-tech/semio-tech-play:build`.
10. **Release describe refused every component.** Three bugs, all fixed in source (`📓️2026-11-17-release-components.md`):
    - the owned actor ABI signatures;
    - the channel version pair;
    - the caller clock in `describe_observed`.
11. **Component size against the shipped cap.** The shipped cap is 256 MiB. fem is 205 MB; demonstrator (519 MB) and energy (612 MB) are over it.
    - 94% of fem's data section is zeros. Sparse fixed-slot static tables carry a non-zero sentinel that keeps them out of `.bss`, and every component has the same pattern.
    - Fixed at the source: four `RefCell<[Option<T>; 1024]>` reactor tables have a non-zero `None` niche, so each put about 68 MB of active data into every component. They are now `semio_framework_async::LazySlots`. fem dropped from 205 MB to 137 MB.
    - demonstrator (about 450 MB) and energy (about 545 MB) are dominated by their code sections.
    - **Redeploy decision:** the release bound is raised to 1 GiB, the WebAssembly module size limit of V8 and SpiderMonkey, so every app ships now.
      - The descriptor emitter reads up to the larger profile bound.
      - Receipts bound `release` at 1 GiB and `prototype` at 512 MiB.
      - Tests: 34/34 pass.
    - **Follow-up:** split demonstrator and energy into smaller components, and apply the release-wasm profile levers (`-Zlocation-detail=none`, `-Zfmt-debug=none`, opt-level `z`, a single codegen unit for the composition leaf). Once both are under 256 MiB again, restore the bound.
12. **A concurrent edit ended a 70-minute run.** Another worker kept editing `⏳️async/🦀️.rs` while describe-tool read its inputs, so the job exited 75, the stale-implementation yield that the outermost command re-runs. The driver had never re-run jobs.
    - Fix: `runJob` restarts on exit 75, with the bound and backoff of `formatStampProtocolV1()` (`📓️2026-11-17-driver-fail-fast.md`).
    - `native-play.sh site` also retries the whole driver up to four times.
13. **Host starvation.** A stale `repo show targets` from this session had been rebuilding the project graph for 2 hours. It held 8.2 GB plus four exec grants, so the release build waited more than 10 minutes for admission; stopping it freed the host.
    - A starved graph service also kept every `repo run`-based test suite stuck at "Reading the project graph slice", which is why the native fallback was needed.
14. **Generated sources were missing.** `puzzle-wasm` failed with `process.source.unresolved-module`, because the generated `registry` of `puzzle/◻️2d/🛂️manifest` did not exist on this host. With the graph down, no `generate` or `graph-generate` dependency had run.
    - `native-play.sh generators` (listing by `native-generators.py`) runs all 21 workspace generators natively, `generate` before `graph-generate`, plus the catalog. All 19 that are not catalog steps pass.
    - `all` runs prereqs, catalog, generators, then site.
15. **A concurrent compile break.** `semio-ui-wgpu-light` was missing `semio-ui-draw-contract` during the shared-border consolidation. Another worker fixed it minutes later, and the next attempt picked it up.
16. **The map-tiles check was stale.** It hardcoded `vt/3/1/2.pbf`, while the default prefetch bounds now cover z3 at x=4, y=2. All 396 tiles were present, yet the job failed.
    - The check now requires every planned tile: `listMapTilesForBounds` over the default bounds and the play zoom range, for both raster and vector.
    - It reports the missing count and the first missing path.
    - A native run of `map-tiles` passes (396/396).
17. **A stalled refactor broke the tree.** At 02:18:44 the replica brought in another developer's partly applied refactor of `🌱️value`, about 27 files. It erases frame-logic generics per producer to shrink component code. It left the describe tool uncompilable, and all four driver attempts failed on it.
    - Fixed so far: a stray `)` in `drive_original_producer_bound`, and `admit_frame_slot` work changed from `u64` to `u128`. `value-retirement` checks clean.
    - The missing `drive_original_effect_bound_with` is being completed in the refactor's direction (`📓️2026-11-18-value-refactor-completion.md`).
5. **Stale `probe` stage key.** The root `release` pipeline gated a stage named `probe`, which the stage plan no longer has (`describe`, `model`, `transpile`, `optimize`, `browser`, `complete`, `discard`). It now gates `browser` after `job:support`.
