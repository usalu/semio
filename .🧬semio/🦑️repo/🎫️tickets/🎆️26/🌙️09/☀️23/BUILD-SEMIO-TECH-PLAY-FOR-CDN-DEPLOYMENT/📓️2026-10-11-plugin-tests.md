### (a) String retirement and the key corpus

- Reading `🧰️framework/🔨️modules/🌱️value/♻️retirement/🦀️.rs`: `String`/`PathBuf` retire through `Bytes`: one `Advanced` (a `truncate(0)`, copy 0, no allocator event), then one `Bytes(capacity)` release that needs the WHOLE backing under `maximum_release_bytes` and `maximum_depth >= 1`. `OrderedMap` keeps its key corpus in the map's own root and charges it as copy work. DECISION: the asymmetry is intended. Copy bytes price work the retirement really does; a flat backing is freed by one deallocation, so charging copy for it would invent work, while the map root really walks its keys. The replication fixtures + TS oracle from `fw-tests` stay as they are; no further fixture change.
- `child_complete_actual_authored_typed_source_physical8194_grant4096`: the logical-drain loop is replaced by "next work demand is 0, one `Advanced` step with zero heap events", all grants carry `maximum_depth: 1` (a retirement step without depth is `BudgetExhausted` by design). Physical-denial/whole-release assertions kept.
- `child_complete_original_semantic_metadata8194_grant4096`: a 4096-byte RELEASE grant can never retire an 8194-byte `String` any more (the old pieces are gone by design). The test now asserts exactly that for owner/slot/child_id/op_schema (64 refused steps) and proves completion under a grant that admits the whole backing; the `Complete` step's release is counted.
- `child_complete_actual_authored_paged_source8194_frame8202_physical4096` still fails: `read_from_encoding_source` runs out of its 512-byte owned-bytes window (label cells now carry the `SharedUtf8` Arc header). Not changed.
- Remaining ~55 `left == right` failures have no common cause. The largest family (`(40, 0)`, `(80, 0)`, `(744, 0)`, `(112, 0)` against `(0, 0)`, ~25 tests: mounted receipts, private child metadata, local-interaction live/query/capture, tool-run port) is ONE product pattern: after `ActorId(SharedUtf8)` the receipts build `ActorId(author.into())` at `take()` time; `SharedUtf8::from(String)` allocates an `Arc<String>` (40 B) with no receipt. The honest fix is to admit the author through `SharedUtf8::admit(String, grant)` during the funded copy turns (capacity currency `shared_retirement_allocation_bytes::<String>()`), e.g. `MountedKernelMutationReceipt::take` in `🧩️composition/📬️publication/🤝️group/🪟️mounted/🧾️receipt/🦀️.rs:353`. Owner: pl-c.

### (b) Stack overflow (43 tests at 64 MiB)

Diagnosis: NOT an unbounded recursion. The 43 tests all reach `JOBS`, `component_persistent_local! { static JOBS: RefCell<[Option<JobSlot>; 1024]> }` in `⚛️reactor/💼️jobs/🦀️.rs`. `JobSlot` was 10 648 B because `JobBody::AdmissionFailed` embedded a `RetainedExtensionFaultReply` (10 080 B: a `BorrowedProjectedPackCursor` with `frames: [Frame; 64]` + `path: [usize; 64]`), so the table is 10.9 MB; the lazy initializer builds it on the stack, and an unoptimized build copies it ~6 times (64 MiB was not enough; 100 MiB passed). `ComponentPersistentLocal::with` builds it the same way on the wasm guest whose shadow stack is 8 MiB, so this was a real crash risk, not a test artefact.
Fix (product): the rare failure reply no longer lives in the slot. `JobBody::Refused(Option<ExtensionInvocationCause>, Option<ControlledRetirement<…>>)` keeps only the typed cause (152 B); the reply is born in a boxed `AdmissionFailedJob` (a `BoundedJob`) whose birth is charged to the caller context exactly like every other boxed job (`retained_capacity_bytes = size_of`, released by the existing `close_body` accounting, an unfunded grant blocks and retries). Slot 10 648 B -> 960 B; first-touch table 983 KB. A debug build still copies that table ~7x on first touch (6.7 MB frame of the lazy TLS initializer, measured with `otool`), fine on the 64 MiB test threads and the optimized guest; a `const` thread-local initializer would remove it (not done: the macro has no const arm).
The 44th overflow was a different thing, `one_framework_reserved_route_fits_a_bounded_thread_stack`: a law that the construct-select-close lifecycle fits a 2 MiB thread. Measured (stack size bisection + `otool` prologue scan): constructing the interaction fixture needs 4 to 8 MiB and the select dispatch on top 8 to 16 MiB of DEBUG frames (async state machines of 2 to 10 MiB per test future are normal now; the biggest prologues are test poll functions, e.g. `folder_reload_route` 10 MB). The guest's real shadow stack is 8 MiB and only optimized frames run there. Decision: the 2 MiB contract is obsolete; the law keeps its meaning (fails on a runaway recursion / re-inlined generator) at `BOUNDED_THREAD_STACK_BYTES = 16 MiB` with the measurement in its docstring.

### (c) `mutation_retirement_factory` is `None`

Cause: a `VcsArtifactApp` is born constructing. The store owner catalogs (`snapshot/mutation retirement`, disposer, one-item factories) are installed by metered constructor turns (`drive_store_constructor_unit`) that the reactor exchange drives before it admits any command (`plugin_exchange`: `constructing` -> `retry_command`). Fixtures that call `begin_apply_batch`/`publish_as` directly (`ToyHistoryApp` and ~30 more) never ran that constructor, so every store lane had no owners.
Production check: every `DocumentStoreOwners` constructor takes the mutation retirement factory as a required argument (`🏪️store/🦀️.rs:2596` and the bounded one), `install_document_store_owners_exact` moves it, and the exchange refuses commands until the constructor settled. No production lane can miss it; nothing to fix there.
Fix (fixture, one place): `artifact_app_laws::settle_store_constructor(app, policy)` drives the constructor to completion while claiming and validating every phase receipt exactly like the reactor (`retain_original_ownership_receipts`). Called by `new_app`, `new_app_with_registry_and_members`, `new_registered_app_with_members` (so `paired_*`, `declared_verb_fixture_app` too) and by the 16 direct `VcsArtifactApp::with_registry*` call sites in the builder-contract, surface-view-state-routing and completion tests.

### (d) close / lifecycle buckets

Settling the constructor exposed that the settled production close path had never been exercised by this lib. Real bugs found and fixed (each blocks every instance close under a production `MountedOwnerPolicyV1`, whose close grant is 1 MiB release / 32 KiB copy):
1. `ArtifactFixedRegistry<ActiveDocumentArchiveLoad>`: 64 slots x 25 048 B = 1 603 584 B backing released in ONE step by the `DocumentArchive` close rung, which is more than the production 1 MiB release grant (and more than the guest contiguous-request ceiling). The close ladder parked there forever (`Progress(default)` + `yield_now`). Fix: `ArtifactFixedRegistry::with_slots(n)` (runtime capacity, divisor of the 64-bit mask) and `DOCUMENT_ARCHIVE_LOAD_SLOTS = 2` (50 KB). `begin_document_archive_load` already answers `document-load.busy` when the direct-mapped slot is taken, so a second concurrent load is the same refusal it always gave on a collision.
2. `TransientStoreDisposer` (the default `no_transient_store_disposer()` of every app without transient state) did not implement `terminal_frame_release_bytes`, so `original_disposal_demands` failed with "terminal disposer has no original physical frame authority" at the transient close stage. Implemented like its bounded sibling.
3. Remaining close-turn stalls were fixture clamps: `close_registered_fixture_app`, `settle_registered_typed_operation`, `close_fixture_app_to_terminal_emptiness` and two builder-contract drains clamped the copy grant to the 4096-byte page, but a settled `PresenceStoreRetirement` frame is 11 872 B and its disposer quotes that as copy (`PresenceStoreOwnedDisposer::retirement_demands`). Clamps removed (fixture drives with the caller's own policy, as the mounted runtime does) and the shared `native` fixture-caller grant raised 4096 -> 16384 copy (`🧪️tests/🔬️plugin-runtime-runtime-close-budget/🧫️fixtures/🧾️fixture-caller/🔣️.json`; the production minimum is 32 768).
4. Constructor Close receipts: `close_registered_fixture_app` compared the receipt with the page-clamped grant it no longer uses (`fixture_close_grant`); `close_reserved_app` and `close_transaction_store_roots` re-implemented the close loop without claiming receipts (-> `AwaitingInput`). They delegate to `close_registered_fixture_app` now; direct `app.close_step` loops in the composition/tool-run/builder-contract tests claim the receipt as the mounted runtime does (`take_constructor_receipt` after every turn, `PluginApp::close_step` wrapper in `🦀️.rs` ~34800).
Production check for the original "AwaitingInput while a receipt is unclaimed": the mounted close wrapper claims it right after the step (`self.take_constructor_receipt()`), and `plugin_exchange` claims `constructor_receipt` per turn. Production cannot hit it; only hand-rolled fixture loops could.

Two further product bugs found on the way (also fixed):
- Pack intrinsic projection convention. `ExtensionInvocationCause` (`🧩️extension/📨️invoke/⚠️failure/`) and `IntrinsicMediaSource` answered `Record(&[1])` at path `[]` and shifted every path by one, but `BorrowedProjectedPackCursor::advance_intrinsic` (fixture-defined in the pack crate, `declare` rejects anything but intrinsic views) treats path `[]` as the intrinsic value itself. Every invocation-failure reply failed with "intrinsic Pack source changed its declared value authority" (jobs tests, `extension_invocation_failure`, media). Both sources now follow the cursor contract (the cursor's cross-language fixtures are the authority).
- The fixture `TestAppCommandJob` (`🧪️tests/⏳️completion/`) never retired its leases: snapshot/config/history are `Arc`s the store still owns and were retired as unique owners (waits for uniqueness forever, the fw-tests #58 rule), and `residual` + `context` had no close path. Leases retire through `admit_shared_retirement(.., lease_only = true)`; residual inputs through a `RetireOwned` derive + a raw-wire lease cursor.

### (e) `subtract with overflow`

`child_member_registry_tests::original_composition_pin_retirement…` was a TEST bug: `(demand.capacity_bytes > 0).then_some(Grant { maximum_capacity_bytes: demand.capacity_bytes - 1, .. })` evaluates the subtraction eagerly. Five sites in `🧪️tests/🔬️app-child-member-registry/🦀️.rs` (every `then_some(RetainedCloneGrant{…:demand.x-1,..})`) are `then(|| …)` now. Product code was not at fault.

### (f) `ArtifactOwnedToolJobContext` dropped on the `?` path

`ArtifactOwnedContextHandle::drop` asserts "granted issuer handback" unless panicking, so any `?` between building the context and handing it to `ArtifactOwnedToolJobRequest` turned the real fault into a Drop assertion. Hoisted every fallible evaluation in front of the construction: `presence_store.local_read()?` and `admit_gesture_slot(..)?` (previously inside the builder chain, i.e. after the half-built context existed) and the request's `snapshot_read()?` / `window_config.try_duplicate()?` (previously evaluated after `owned_context` existed). Both construction sites (`dispatch_typed_command_job` and `preview_typed_command_job`). The context can no longer be dropped half built by a fallible argument. `build_tool_job(..).await?` consumes the request, as before.

### 1. `ArtifactOwnedToolJobContext::retirement()` and the mounted close chain (production)

The "~70 tests cannot retire" were four stacked production defects, each only visible once the previous one was fixed (found by driving the real close rungs and printing the zero-progress frame):

1. Context cursor (`🧵️retained-command/🧬️context/📸️fields/🦀️.rs`). The captured context now retires in four stages: typed metadata (`ControlledRetirement`), then the residual is split into leases (`ContextResidualLeases`: children / tool-run entities / payload retire as `SharedControlledRetirement::lease`, only a last owner pays the deep release) and the presence peers, which retire through the presence-peer factory as `PresencePeersRetirement::of_alias(root, factory)` (custody `BaseAlias` = lease semantics). `VcsError` is gone from the context: the draft source fault is a `String` (`draft_source_fault`), so no `RetireOwned for VcsError` is needed. Store additions: `PresenceStore::peer_retirement_factory()`, `PresencePeersRetirement::of_alias`. Implementing `RetireOwned for PresencePeersRoot<P>` itself is deliberately NOT done: the root is an alias of a root the store still owns, so a unique-owner retirement would wait forever; the alias constructor is the correct primitive.
2. Fixture residual (`🧪️tests/⏳️completion/🦀️.rs`): `TestAppCommandInputs` held `Arc<InteractionState>` / `Arc<InteractionHoverState>` as unique owners (strong count 3: store + issuer + job). Now `SharedControlledRetirement::lease`.
3. Worker session close (`🦀️.rs`, `MountedTypedCommandFullOperation`). The worker's `params.cancel` is `lease.token.child_now()`; its ancestor alias is the operation's own lease token, which can never become unique while the operation owns it, so `CancelTokenRetirement::close_step` answered `Blocked(SharedAlias)` forever (`typed operation mounted session close awaits its worker handback`, 1.6 M spins in 30 s). The witness API `return_original_cancel_alias_step` existed (the renderer uses it) but the mounted operation never called it, in production as in the fixture: every mounted worker session closing after a terminal outcome, and every close of an in-flight operation, was stuck. New `return_session_cancel_alias` (witness = `cancellation_lease.token`) is called in both `retire_worker_step` and the terminal-seen session close.
4. Cancellation lease retirement (`♻️cancellation/📦️lease/🦀️.rs`). Keyed leases hand the registry scope `token.clone()` (same node as the lease token) and the keyed document token is the parent of the lease token; `ControlledRetirement<CancelToken>` cannot retire either (`original cancellation node retains a shared alias`). Tokens now retire as `CancelTokenRetirement` with witnessed alias returns (sibling duplicate dropped at detach, ancestor alias returned against the still-owned document/app-scope/registry roots, `document_id` kept in the parts to find a registry-held witness).

Also: `PresenceStoreRetirement<P>` is now boxed inside `PresenceStoreOwnedDisposer` (funded birth and release), which removes the 11 872-byte COPY quote from the disposer frame.

Result: of the 74 tests that timed out in "typed operation did not retire within 30 s" (r12), 5 are green and 65 now get past every close rung and stop at two precise, unrelated gaps:
- 33: `mounted completion payload has no original app retirement issuer`. `ArtifactApp::completion_retirement_birth_bytes` defaults to `None`; the fixture (`test_completion_supported`) only supports vacant completions, so any fixture command that emits mutations / effects / events cannot retire its completion payload. Real apps must declare the payload facet (`EditorApp` / `ViewerApp` forward to their inner app). A generic `RetireOwned for ArtifactToolCompletionValue<A>` (bound `A::Mutation: RetireOwned`, per-lane facets for effects / events / tasks) is the clean fix; it is app-API surface, not done here.
- 32: `validation failed: batch original canonical factory is absent`: the store-side `one_item_preparation_factory` of the fixture stores (wire-src / factory owners, untouched).
- 3 FAILED + 1 timeout remain in other buckets.

NOT achieved (diagnosed): the "limits stay <= 4096" laws (`retained_window_input_recursive_*`, `a_retained_config_over_one_envelope_page_closes_after_a_render`). Boxing `PresencePeersRetirement` was measured and does not shrink the frame (1 192 B); the 11 872 B is the inline `SnapshotReadRegistryAliasRetirement::last_registry`, and the law now fails on `RetirementDemand { copy_bytes: 40, release_bytes: 37376, depth: 1 }`: a snapshot registry backing is ONE 37 376-byte allocation, released by one dealloc. A <= 4096 release law needs the registry backing paged (store redesign), not a quote change; I did not weaken the laws.

### 1. Completion payload retirement facet (derived, not declared)

Production DID hit it: `ArtifactApp::completion_retirement_birth_bytes` defaulted to `None` and `admit_completion_retirement` to a refusal, and only the two kit wrappers (`EditorApp` / `ViewerApp`) forwarded to inner defaults that were the same refusal, so ANY mounted tool-run whose completion carried a mutation, effect, event, task or download and was closed in flight (app close, cancellation, supersession) faulted `app has no original completion retirement authority`. Fix in `📬️completion/♻️retirement/🦀️.rs`: `ArtifactToolCompletionValue<A>` now implements `RetireOwned` by lowering itself into a typed payload (`CompletionPayload<M, C, D, P, T>` + `EphemeralParts`, both `#[derive(RetireOwned)]`; every lane type is already `RetireOwned` by the `ArtifactApp` associated-type bounds), and the trait defaults of `ArtifactApp`, `ArtifactEditor` and `ArtifactViewer` call `derived_completion_birth_bytes` / `derived_admit_completion_retirement` (exact `ControlledRetirement` frame, retains the original on every unfunded route). An app can neither forget nor refuse it; overriding stays possible (the wrappers still forward). The fixture's own vacant-only facet (`TestCompletionPayload`, ~110 lines) was deleted.

### 2. "batch original canonical factory is absent"

Trace: `ArtifactStore::advance_apply_batch` (phase `PreflightingCommit`) asked `self.one_item_preparation_factory` for `begin_batch_digest`; the `ArtifactApp` defaults of `build_{artifact,config,draft}_store_one_item_preparation_factory` are `None` (explicit fail-closed since corrections #38/#39), so every multi-operation commit (gesture commit, transaction, plain `dispatch_typed` with mutations) of a store without a factory failed, whatever the mutation type. Production apps override the factory (103 files), so production hits it only for an app that emits mutations but returns `None`; it is nevertheless a layering error: the aggregate-edit digest is a pure function of the mutation's canonical tree (`admit_artifact_batch_digest::<M>`), exactly like the authoring wire wire-src moved into the Store. Root fix: `ArtifactOperationWire<M>` carries the digest admission (`begin_batch_digest`), granted by `with_batch_digest()` (needs `M: RetireOwned + Send + Sync`), the bounded catalogs (`bounded_artifact_store_owners*`, `DocumentStoreOwners::with_batch_digest`) and the SDK wire install grant it, and the Store uses the factory's digest when a factory exists (domain codecs keep overriding) and the wire's digest otherwise. Wires built without it (`canonical()` / `semantic()` alone) refuse with a precise message.

Behind it sat a real product bug: `PendingArtifactStorePublication::is_closing` was true only in phase `Closing`; after the ACK closed the batch the phase moved to `Complete`, the next publish unit saw "not closing", called `advance_apply_batch` and faulted `artifact-store publication completed before result ACK`. Now `Closing | Complete`.

### 4. Legacy borrowed canonical encoder (NOT done, analysed)

The 12 tests (`local_interaction::{capture,live,query}`: `(744,0)` x6, `(0,392)` x4, `(112,0)` x2) all drive `ArtifactCanonicalEditEncoder` (`🏪️store/🧵️canonical-edit/🧵️borrowed/🦀️.rs`). Births are the boxed iterators created inside `ArtifactCanonicalJsonArray::new` / `ArtifactCanonicalJsonObject::new` when `canonical_json_borrowed_root()` or an element's `next()` yields an Array / Object (and the `Box<ArtifactCanonicalJsonCursor>` of an indexed source); releases are the same boxes dropping when an array / object frame ends (`depth -= 1`) or an indexed cursor completes. `value_release_bytes` / `frame_release_bytes` already price exactly those boxes for the close path. The honest fix reports `retained_capacity_bytes` at the birth sites and `released_bytes` at the natural frame ends in every `encode_chunk` receipt. It cannot be done without admission: a birth is only known after the iterator allocated, so every caller grant of the encoder (canonical sealer, reader, digest, local-interaction capture) needs a capacity allowance for one frame birth, and the sealers today grant capacity that never accounted for it. I did not change that shared contract blind; the right change is a per-chunk "one frame birth" allowance in the grant plus the receipt fields above, verified across the sealer / reader / digest laws.
