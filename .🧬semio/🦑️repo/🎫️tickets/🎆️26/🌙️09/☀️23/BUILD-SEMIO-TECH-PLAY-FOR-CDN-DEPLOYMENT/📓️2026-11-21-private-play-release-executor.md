# Private Play Release Executor

The installed `repo` launcher can start the native Play pipeline from a disjoint workspace with its own code, inputs, and cache images. The existing `incremental prepare` command provisions such a workspace without creating a Git worktree. The current tools do not supply a sealed private Play source revision or an export command for the verified four-page cohort. The local volume was also below the repository’s free-space floor during this review. The running release remains the sole release attempt.

Keep the default cache location inside that root. Clear any inherited machine state override, caller authority, build-service token, or Cargo paths from the live checkout. For subsequent native commands select the private workspace explicitly, set `BUN_RUNTIME_TRANSPILER_CACHE_PATH=0`, and set `SEMIO_BUILD_SERVICE=off`.

The native route needs the authored ticket launcher inputs at the same relative ticket depth inside the private root, so the shell finds the private `.🧬semio` and the TypeScript relative imports resolve the private code. ## Machine State Override Follow-up

`SEMIO_MACHINE_STATE_DIRECTORY` replaces the checkout's `.cache` with an absolute path. `machinePathV1` routes `.nx` under that directory as well. A private source root set to the live `.cache` would address the same tool, dependency, compiler, lease and product paths as the current release.

Partition operations require a live storage owner and issued invocation control. Cargo loads configuration and policy from the invocation's repository root. The Play publisher checks the invocation's repository authority and writes to a common mode-qualified destination within the products partition. An alternate checkout would address the same writable destination if it used the live product partition.

The inspected tests cover path redirection. Fleet rehearsal assigns a separate state directory, and the private bootstrap clears inherited `SEMIO_*` settings. A private release would need its own writable partition and product namespace. The current supervisor continues in the canonical workspace.
