# Flow WASM source drift

Play declares `flow-wasm` as a release job running `repo ../../🏗️build/📜️script.ts wasm` from the Flow browser package. The script calls the repository WASM provider without `threads`, so its compiler command goes through wasm-pack. The earlier `wh7gdVT` failure reproduced an unresolved Rust import across a split source epoch. The subsequent diagnostic change keeps the compiler error in the job log.

## Source admission and control

`admitCargoSelectionV1` checks the live compiler storage, captures the selected Cargo graph, and calls `admitCargoSourceBoundariesV1`. The latter records workspace units' admitted absolute paths, SHA-256 digests and byte lengths on `unit.sourceInputs`. The current public call returns `Promise<void>` and discards those graph rows. The WASM port awaits that call under its Cargo configuration and writer lifetime before invoking the compiler. It reacquires no source observation between admission and execution.

A narrowly scoped source-admission continuation can keep the existing `void` use cases and pass a frozen source roster and the admission start time to the WASM compile. Begin that time before source admission and use the live writer-provided control. Reject duplicate paths with conflicting admitted digests as concurrent edits. Open the existing bounded drift monitor only around the Cargo or wasm-pack command. A child-only issued cancellation scope can carry the monitor's typed `concurrentEditV1("input", path, detail, "build")` when a stable physical SHA-256 differs from the admitted digest. Cancel that scope alone and close the monitor before returning. The streaming adapter already projects the exact issued control into the child, owns process-tree termination, joins the streams and rethrows the original abort reason. A compiler error without an independently proven change remains an ordinary compiler error.

## Restart path

The Flow build script receives its process envelope and calls `runScriptMain`, whose router lets command failures propagate. The process birth calls the registered restart handler on escape. The format-stamp layer recognizes the typed edit, and an already nested repository command yields the same restart status, 75. The native driver joins each child and its streams before applying the per-job restart protocol. It allows the initial attempt plus six retries, with the declared delays of 250, 1,000, 4,000, 12,000, 30,000 and 30,000 ms and checks the parent signal before launching again. Each Flow job process runs source admission anew under the same parent job budget. This code path has no need for an additional local retry loop.

## Scoped monitor integration

Source admission now returns a read-only roster of the already admitted workspace paths and exact SHA-256 digests, with the admission start time. The WASM call receives it under its existing writer-issued control and starts the shared bounded monitor only around the compiler command. Threaded mode runs the monitor for Cargo and releases it before wasm-bindgen. The non-threaded path uses the same admitted arguments to build the wrapper command and keeps the monitor through the wrapper's lifetime. This guards the compiler's admitted source rows; the wrapper metadata subprocess still has the distinct arguments documented above.

The monitor uses the existing directory, roster, queue, physical-read and polling bounds. A stable digest mismatch cancels a child-only issued control with the typed concurrent-edit error. The owned stream runner drains the compiler process before the adapter rethrows. It stops and joins the monitor on success, failure or cancellation. Existing package custody and validation rules remain in force. The monitor does not prove an immutable source epoch or read the recipe's projected lock or manifest inputs.

The synthetic fixture used the production wasm-pack argument builder, a real received child capsule, and the actual restart classifier. A digest-changing edit stops and joins the synthetic compiler and yields 75. With unchanged source a compiler status 101 stays an ordinary failure, and a parent-side cancellation keeps its original reason. None of the cases aborts the original compiler control. The production job retry runner saw exits 75 and 0 across two synthetic process births, and the second attempt admitted the digest of the newly edited bytes. This proof did not start Cargo, wasm-pack, describe or a release build.

## Exact compiler proof for non-threaded Flow

The current non-threaded Flow path has no seam for deferred source-drift acceptance under the existing command and artifact custody. The paid execution port returns `Promise<void>`. Its production runner routes wrapper stdout to stderr, and the source-admission response exposes the start time and admitted input digests. The `wasm-pack` invocation remains under the original target/build lease through package collection, with a fresh target directory, a separate fresh package directory, and the existing shared Cargo build directory. See `🏃️process/📦️artifacts/🕸️wasm-build/🟦️.ts`, lines 44–48, 89–124 and 157–215.

The selected installed `wasm-pack` 0.15.0 already requests Cargo JSON. Its own `src/build/mod.rs`, lines 153–194, pipes that JSON into its parser, drops build-script events, and keeps only the last compiler artifact to select the input `.wasm` file. Capturing wrapper stdout therefore cannot recover the compiler roster. Looking up nearby `.d` files also leaves no exact association with this invocation's complete set of compiled and reused units. The shared build directory can contain prior unit variants, and a selected `.wasm`/`.d` pair alone covers one target. A matching checksum in one record leaves other consumers unresolved.

The existing Rust witness can hold admitted file bodies and match compiler checksums. The terminal native proof additionally authenticates each compiler artifact and its dep-info against its actual invocation and target source, tracks weak or unchecked observations and conflicts, and compares the resulting digest coverage with the admitted compilation graph before passing output to the consumer. Missing or changed records fail `verifySources` in `🏃️process/📦️artifacts/🏗️native-build/🟦️.ts`, lines 382–396. The WASM watcher already issues a restartable edit error and drains the owned process tree when the required proof is absent. Retain that behavior. Any future reuse needs the actual nested Cargo artifact and build-script stream under the existing paid Flow scope, plus the terminal coverage check before the WASM package is constructed and handed to its consumer.
