## 1. Release graph and pipeline (N1)

- Per-component `describe`/`materialize` targets are gone. Each of the 71 component crates has one uncached orchestrator `component` target (`native component --manifest`, builds that one component through the driver).
- `workspace:release` and `semio-tech-play:build` carry a schema-first `PipelineV1` in `metadata.semio.release` (`component-pass/🧬️schema/🔣️.json`): prerequisites, jobs `{id, root, command, after, lane?, profile, target, policies}`, `stageAfter`. `withReleasePipelinePreparation` adds only the prerequisites plus the native generators of the component crates and job roots (15 and 16 dependencies, verified against the taxonomy's generator contracts).
- `releasePipelinePlanV1` lives in `⚡️caching/🦀️cargo/🟦️.ts`, next to `componentPassPlanV1`. It must not live in `native-orchestration`: every target of a native project hashes the cargo script's import closure, and a static import of the driver there turned every Cargo `build`/`check`/`test` into a driver-closure consumer.
- Driver additions this wave: per-run warm generations (`w…`, 24 h retention), lane jobs before their lane's passes, `widen(max)` (non-blocking extra jobserver slots → `BINARYEN_CORES`), `finalizer` stages (run after their stages settle, whatever the outcome, without a token), unit-graph closures from `--unit-graph` run at t=0.

### Defects found by the run and fixed

1. Closure root attribution (above).
2. Triple reads: resource-read lengths re-read the whole file — now from `CurrentPhysicalPortV1.measure` (digest + byte length from one streamed read); compiler-resource observations and build-script resource inputs are read once for both text and digest.
3. A failed publish left `<module>.materialize-*` directories in the plugin-modules root. The new `discard` finalizer removes an unpublished assembly and the stage work directory whatever failed or was cancelled.

## 3. Stage cache

`🗃️stage-cache`: key `{stage, schemaVersion, inputs: {name: sha256}, tools}`, canonical JSON with keys in UTF-8 byte order, entries published by atomic rename. Warm store `⚡️cache/stages`, fresh store `<generation>/s`. Python oracle `wave-n1-n2/🧫️stage-cache-oracle.py` generates the fixture.

`PlayModuleCatalogV1`/`PlayModuleBindingV1` in `🧩️runtime/🧬️schema`. `pages` binds modules, browser support and fonts into the site with `🧾️catalog.json`; `verify` (Nx `release-verify`, launch `⚖️gate🏢️semio-tech🎡️play🚀️release-verify`) checks the generated catalog against a refusing render and every module page against its binding.

## 5. Test levels as arguments (N2)

- A level is a positional argument: `nx run X:test -- quick`. Measured with a probe workspace: Nx forwards it for `run`, `run-many` (`-- level` and positional) and through `dependsOn` with `params: "forward"`, and keys the cache on it.
- `withLeveledTestTargets` is removed, along with the `test-quick|long|exhaustive` policy rows and the root `test-quick|long|exhaustive|fundamental` targets. The root `test` forwards its level to every project's `test`; at `long` and above the root script also runs the Storybook suite.
- `native cargo test --manifest M [level]` strips a leading level into `SEMIO_TEST_LEVEL` instead of passing it to Cargo as a filter.
- Codemod `wave-n1-n2/🎚️level-target-census.py --apply` (span-preserving, verified per file): removed 670 explicit level targets from 229 `project.json` files. These were identical to `test` + level, or hand-reviewed as the same run. Hand-migrated:
  - repo-mcp `test` no longer passes `repo-mcp` to `go test`;
  - fixture-sweep `test quick` is the extraction check alone;
  - print and report `test` depend on `build` (their long levels read built PDFs);
  - print's `test-fundamental` removed.
- Callers moved to argument form:
  - `resolveNxInvocation`;
  - the root script's dsl gate and stdio long/exhaustive;
  - the hub script (5 calls);
  - 5 `package.json` files;
  - 46 seed and 52 launch commands;
  - the generic `⚖️test📋️` launch entry, which now asks for `testLevel`; the three level entries and their inputs are gone;
  - READMEs and the scalar retained-contract declaration.
- Test owners: one project per owner (`test-<slug>-<hash>`), `lint` = `contract --owner-root <owner>`, `test` = `cases <owner> [level] [--facet …] [--case …]` (new `CasesScript`, exact `--owner-root` selector). 632 cases → 247 owner projects.
- Count: 1029 projects, 8788 targets (inventory over the live plugin graph). The remaining mass is about 300 authored Rust package projects and about 190 manifest projects. Getting under 400 needs those collapsed, which is outside this wave.

## Follow-ups

1. **63 of 71 committed descriptor pairs still carry `hashes`.** Verify mode refuses them, so the full release fails at `describe` until `bun nx run workspace:components describe --all` (shipped bytes) or a write-mode release regenerates them. The demo regenerated 5:
   - 4 only dropped the binding;
   - stdio-media changed 40 semantic paths (current source, Lane C's split in flight).
2. In a cold release, describe is gated by the host describe tool on the critical path. Admission should prioritise its chain (wasmtime → os-kernel → plugin-host).
3. Taxonomy admission is needed for `🏃️process/📦️artifacts/🏗️native-build/🗃️stage-cache` and `🔌️plugin/🏗️build/🧩️driver-stages` (taxonomy lane).
4. 87 taxonomy `verification` strings still read `@semio-tech/print:test-quick` (taxonomy lane).
5. The demonstrator product has the same profile-directory drift that play had.
6. Every target of a native project, `serve` included, is wrapped as an owner command, because the cargo script closure is the fallback input set. `graph-revision` cannot observe policy changes there. Decide whether that is intended.
7. The contract runs wrote `graph-revision-*` probe workspaces into this ticket's `🗑️generated/nx`. They were left untouched, per the lane rules.
