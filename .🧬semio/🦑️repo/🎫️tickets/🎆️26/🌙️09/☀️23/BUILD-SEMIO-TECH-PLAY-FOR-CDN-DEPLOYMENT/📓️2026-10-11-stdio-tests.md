# stdio test targets 2026-10-11 (executor report)

Scope: make every stdio test target COMPILE against the current API (grant-based retained clone, native snapshot owners, job protocol, store apply API) and run the hub laws; then triage what still fails. Status at the end: all 37 test targets compile (35 artifact `--lib`, the contract crate, hub `semio-hub-stdio` lib + 3 integration targets); runtime results below. Nothing in this report is a claim about the release path; no release-path semantics were touched.

Run environment: private `CARGO_TARGET_DIR` (deleted at the end), `cargo test --manifest-path <artifact>/Cargo.toml -p <pkg> --lib --features component-app-assembly --no-fail-fast` through `🚦️cargo-slot.sh`, `--all-features` for semio. `RUST_MIN_STACK=268435456` is required for the ifc, step and semio debug binaries (debug frames overflow the default 2 MiB test-thread stack; ifc/step/semio were therefore also run one process per test).

## What changed (shared infrastructure)

- NEW `✏️s/🔌️plugins/🗄️stdio/📇️registry/🧬️contract/🧰️testing/🦀️.rs` = `semio_s_artifact_stdio_contract::testing` (cfg `test` or feature `testing`; every artifact enables it as a dev-dependency feature, hub too): `original_grant`, `unbounded_grant`, `mounted_policy`, `with_decoding`, `with_encoding`, `with_encoding_async`, `with_sqlite_recipient`, `io_run`, `decode_control`. These are the original-caller authorities the old tests took implicitly (a generous five-axis grant, a retirement recipient that is closed afterwards, the explicit mounted owner policy). They replace ~490 ad-hoc `SqliteSnapshotControl::new(...)` + owner constructions.
- ~126 test files across the 35 crates migrated by compiler-diagnostic-driven rewrites (`rsx.py`, bracket-matched on masked source) plus hand edits: snapshot owners on every `to/from_sqlite_database` and `export/import`, `ArtifactSqliteSnapshotCodec` `&mut Option<SqliteDatabase>` + owner, `apply_diff(&diff, &base)`, `StepContext::new` progress argument, `with_authoring_identity!`, `artifact_app_laws::*` policy+identity, `RetainedCloneSource::admit_owned` + full close instead of `from_authority`, `PackageDiff` newtype derives.
- semio (`🧿️semio`): compiles with `--all-features`; 490 call sites wrapped by `with_sqlite_recipient` (its projections require an installed native retirement recipient).

## Product/asset fixes found by the hub assembly (real bugs, fixed at the root)

1. Mutation bridge generator (`semio-hub-stdio-mutation-bridge`, E0425 `JpgBaselineMutation`): jpg's `🧩️composition/🔣️.json` declared a `JpgBaselineMutation` descriptor that no longer exists (the baseline editor uses the shared jpg mutation); descriptor removed, bridge regenerates cleanly.
2. xml and tiff `📜️artifact-definition.json` `native_factory.pack_schema_hash` was stale. Rule: xml, tiff, html, svg, step, xlsx, docx, png, pptx, txt, dwg, deflate use PROTOCOL-DIGEST codecs (`Sha256::digest(include_bytes!(📡️.protocol.semio))`), so their hash must equal the sha256 of the artifact's `📡️.protocol.semio`; every other artifact uses the type-derived `ArtifactCodec::of::<S,M>` hash that only Rust computes. I first wrongly rewrote 17 type-derived hashes, then reverted them; only xml (`f49c2064...`) and tiff (`a0333223...`) change.
3. dwg ac1018 lacked the composer runtime capability in its definition.
4. step: the `📐️step/🦀️.rs` `document_codec_bare` calls mixed mutation types; one codec per schema is the store-registry rule (compared by `fn_addr_eq`), so all calls now use `StepMutation`.
5. Regenerated by `composition prepare` (`prepareStdioComposition`): hub `📇️publication/📜️native-catalog.json` and `🔌️plugin/📇️catalog/📜️native-codec-factories.json`.

## Remaining failure clusters (owners other than this slice; none is a compile error)

- K1 (largest, ~180): testkit constructor-receipt grant mismatch ("registered fixture did not reach its exact terminal-empty witness", 75 in semio alone): the registered-fixture lifecycle owns the close ladder (store/os-kernel owners).
- K2: missing SQL `receiving` implementations: "snapshot owner has no original SQL projection receiving implementation" (`to/from_sqlite_database_receiving` defaults fail closed and only binary/csv/tsv/xml-style crates implement them; ~92 in the lib targets, 66+ in `editor_catalog`, txt/geojson in `shipped_fleet`). Owner: each artifact's snapshot codec.
- R1: the public typed-snapshot helpers `io_export_sqlite_snapshot` / `io_import_sqlite_snapshot` in `🧰️framework/🛍️products/💻️os/🔨️modules/🚪️io/🦀️.rs` build a bare `SqliteSnapshotControl` with no retirement recipient, so any snapshot whose projection owns a tree ("SQLite snapshot has no explicit retirement recipient", 41 semio tests) fails through them. Not changed here (retirement semantics belong to the io owner): the helper needs to take or create the recipient.
- K3: store initializer outcome missing (30); K4: acceptance harness finds 0 editable cases for png/bmp/jpg/tiff/gif/svg/docx (22); K5: pdf tool-proof (23); grammar conformance failures (12).
- S1: step/ifc "native cold retirement refused: typed owner has no controlled retirement authority" (24 in step) and "native encode has no available explicit retirement" (21).
- S2: unbounded recursion in the semio cancellation retire path (2 aborts).
- E1/E2 (`editor_catalog`): fixture `snapshotEdits` paths are stale for png/bmp/jpg/tiff/pdf/docx/ifc, and for txt/csv-style editors the generic `setSnapshotValue` premise no longer matches the edits they publish; fixtures must be handcrafted per editor by the editor owners.
- `encode_wire_value` is order sensitive (breaks `native_catalog_commitment...`); tsv DSL compile fixture; contract `editing::patch::tests::moved_values_resolve_the_destination_parent_after_removal` ("schema must be an object or boolean") and `editing::rules::tests::the_longest_template_governs...` are unrelated pre-existing logic failures.
