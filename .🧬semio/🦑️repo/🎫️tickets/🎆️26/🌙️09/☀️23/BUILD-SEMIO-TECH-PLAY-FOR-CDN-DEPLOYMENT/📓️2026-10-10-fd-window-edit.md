## Design
Mutation is `RetainedClone`; the edit clones the payload under the grants (value cursors do exact String/Vec accounting), takes it into custody, closes the clone cursor, reserves one inverse row, then `exchange(self, &mut post) -> Result<Self, (ValueError, Self)>` moves payload into post and returns the row restoring the displaced content. The displaced content equals the base content (post is a clone of base), so the inverse needs no second clone and the final turn is allocation-free. Deviation from the brief (`apply/inverse(base)`): that pair would clone heap leaves outside any grant.

## Perf follow-up (do not optimize now): turns per config edit
A single sealed config edit costs about 2.9k turns (2937 for the 4-node record through `config_apply_preparation_factory`; 2.8k to 3.2k for the paged `mutation_apply` cases), independent of the per-turn grant size (identical for floor/seven/large copy grants). Where the time goes: not the edit (a clone of the record plus 4 to 8 edit turns) but the canonical sealer (`🏪️store/🧵️canonical-edit`): its native source runs three full canonical-JSON traversals of the Edit (semantic authority check, identity pass, SHA-256 seal) and walks the edit one canonical byte-chunk or tree frame per turn, each turn paying alias binding, frame allocation and receipt bookkeeping (cumulative retained capacity 420912 bytes for the sealer alone, which is also why every config edit must declare about 0.5 MiB of footprint). Candidates for later: widen the per-turn chunk (`ARTIFACT_CANONICAL_JSON_CHUNK_BYTES`), batch several frames per turn under one grant, merge the semantic and identity passes, and avoid the per-turn projection alias re-binding.
