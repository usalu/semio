## Durable Release Admission

The graph target dispatches `repo ./🔨️modules/📦️site/📜️script.ts build` from Play. The native fallback dispatches the same command. The root release command also calls `buildReleasePipelineV1`. That shared release entry has the exact admitted pass set before it opens the driver and its Cargo input views. A future preparation step belongs there, before the first consumer takes those views.

The repository already has two bounded preparation verbs. `synchronize` can execute Cargo identity and dependency update. `prepare` runs the selected dependency recipe closure and publishes workspace membership. The `prepare` command takes one `--manifest` and a set of `--package` selectors. Play has 27 separate workspace passes, so submitting every pass with the existing verb would start 27 preparation invocations. Recipe deduplication lives inside one invocation. The existing fast witness is tied to synchronization inputs, lockfile and tool identity and is not a source-only batch receipt.

The manifest recipe contract in `🗂️workspaces/🦀️cargo/🟦️.ts` admits only `script` and `command`. It does not declare source-only effects or classify an executable as safe to dispatch during release admission. The `prepare` verb skips its own Cargo update and then runs each selected TypeScript command with the original control. The recursive owner-preparation guard applies to the Cargo preparation launcher and cannot establish the effect of arbitrary child code.

There is also an ordering dependency outside Cargo's declared package edges. The catalog-definition producer reads `🌎️hub/🧩️compositions/🗄️stdio/🧩️component/📦️packages/🦀️rust/Cargo.toml` and reads and embeds the Stdio artifact definitions. The Hub Stdio composition producer can write that component manifest. The separate Semio conversion recipe can write `✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🧿️semio/📜️artifact-definition.json`. The catalog-definition crate names framework, plugin and its projection as dependencies. It declares neither of the source producers as a preparation prerequisite. The existing preparation planner visits Cargo dependencies first and validates earlier observations after all recipes settle. Those checks can refuse an earlier stale read. They cannot order these unexpressed edges before the first read when workspace content is stale.

The narrow integration requires an existing or newly declared source-only preparation contract with producer ordering and batching across exact package selections. Once the contract supports those properties, a neutral fixture can assert one dispatch for shared recipes, prerequisite publication before the first consuming read, refusal and cancellation before driver admission, and preservation of the selected pass set. The read-only investigation did not change release code or launch preparation, Cargo, or a second release.
