# Native unit cache write bounds for Play retries

Keep `SEMIO_UNIT_CACHE=off` for a future Play invocation that must avoid publishing new unit-cache objects. It is already the default in the native fallback. The native scheduler still runs and records measured units through its normal broker. The compiler's warm build and target directories are a separate retention mechanism and remain available to the scheduler. Ordinary Cargo outputs, image maintenance, and managed publication still perform disk writes. ## Supported controls

| Setting | Effect |
| --- | --- |
| `SEMIO_UNIT_CACHE=off` | Leaves unit caching off for a new Play invocation. It is the only existing switch that prevents the wrapper from adding unit-cache writes. |
| `SEMIO_UNIT_CACHE=on SEMIO_UNIT_CACHE_REMOTE=off SEMIO_OFFLOAD=never` | Enables local cache lookup and publication for a new invocation, with fleet cache and remote Rust offload disabled. A host CAS refusal cannot spill that unit into the fleet upload spool. Local writes still occur and the settings provide no release-specific byte cap. |
| `SEMIO_CAS_ROOT=/absolute/path` | Selects the host CAS root for the process. A pre-existing separately capacity-limited filesystem could bound CAS objects physically. A second directory on the same host filesystem has the same space pressure. This setting also redirects other CAS users in the invocation, and it leaves cache index and compiler output writes on the Rust image. No suitable alternate filesystem was established for this host. |
| `repo cache cas status --json --lang=en` | Reports host CAS usage and partition space. It does not change the cache policy. |

The remote access mode `read-only` limits the remote endpoint, while local CAS writes remain active. `SEMIO_UNIT_CACHE_SLOTS` controls concurrency and `SEMIO_UNIT_CACHE_FOCUS` is not a publication filter. The driver uses one unit-cache setting across component and job wrapper selection. Play's structured release jobs offer no authored override by job or target. The scheduler constructs the admitted environment before entering the exit-75 retry loop and spawns every attempt with that same environment. Changing the switch requires a new top-level invocation. ## Which bounds apply

- **Host content-addressed objects.** The shared store's 32 GiB cap uses 28.8 GiB high and 24 GiB low watermarks. These trigger collection, and the synchronous unit publisher may proceed after starting collection even when the store is above the cap. Admission uses a usage hint plus process-local accounting. The projected partition space admits each new object before the temporary write. On a volume large enough for the derived policy, the critical minimum is 1.5 GiB free, background collection starts at 12 GiB free, and the target is 18 GiB free. The derived threshold applies from 36 GiB total volume size. Smaller or unmeasured volumes retain the declared policy of 90%, 80% and 97% used for high, low and critical. These checks provide no hard per-release quota or reservation against concurrent writers. - **Compiler image.** Play calls the Rust image collector before production and rechecks every 60 seconds. The image GC policy uses 87.5% and 75% used watermarks, with immediate collection below 4 GiB free. Its shares of the capacity used by the collector are 50% for retained build units, 23.4375% for lanes, 10% for incremental state and 1.5% for admission records. These are reclamation targets for the compiler image. The developer lane manager can derive its quota from the image minus a compiler workspace, but Play's pressure entry point uses the measured image capacity and targets the image directly. An explicit internal collector `--capacity` changes that collection's basis only. It does not constrain later wrapper writes to host CAS. At inspection, the host volume had 18.90 GiB available and the mounted Rust image had 17.58 GiB available. The default host CAS is on the host volume. Its free space and the image's logical free space are separate views of the storage and are not additive. A CAS cap of 32 GiB is therefore no basis for enabling publication on this host, and a cache hit does not remove the need to restore the unit into the compiler lane. No build, Cargo command, collection or policy change was performed.
