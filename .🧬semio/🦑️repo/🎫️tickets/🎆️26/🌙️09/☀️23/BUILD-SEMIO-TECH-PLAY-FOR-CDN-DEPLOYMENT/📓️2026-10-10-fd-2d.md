# 2026-10-10 fd-2d: 2d font kerning module restored

## Finding
- `kerning::FontKerningCursor` and `kerning::Index` never existed in any commit, branch, stash, remote ref, worktree or clone (`git log --all -S 'struct FontKerningCursor'` empty). The other machine pushed the consumers (`🧵️run`, `🧵️shape/*`, tests) without the module.
- Commit 5487a5cce52 had put an unrelated UI pair-adjustment reader (`BorrowedFontPair`, `fontPairKerningUnits`, its TS test and fixture) at `🔤️font/🤝️kerning/` and exposed it through `📝️text/🦀️.rs` as `pub mod font_pair`. Nothing used it; the UI crate owns `BorrowedFontPairSource` in `🖱️ui/🚪️io/🔤️font/🤝️pair-adjustment`.
- The TS side was equally missing (`FontIndexCursor`, `FontKerningJob` imported by `🧵️shape/*/🟦️.ts`, `🧵️run/🟦️.ts`, `🧪️tests/🟦️.ts`).

## Changes (all under `🧰️framework/🔨️modules/◻️2d/`)
- `📝️text/🔤️font/🤝️kerning/🦀️.rs`: rewritten. `Index` (pub(crate), Copy; coverage formats 1/2, class-def formats 1/2, one binary-search probe per `step`, `result()` is the coverage index or -1 / the class or 0) and `FontKerningCursor::{new(face,left,right,max_work),advance(bytes,grant),result()->i32,cancel}`: GPOS `kern` feature of script latn (fallback DFLT/dflt), default langsys, lookups applied in ascending order, PairPos formats 1 and 2, extension lookups (type 9), value records via XAdvance; falls back to legacy `kern` format 0 when GPOS has no Latin/DFLT script. Work-granted (1 unit per turn), sticky failure, cancel, controlled retirement via the same pattern as `FontSubstitutionCursor`.
- `📝️text/🔤️font/🤝️kerning/🟦️.ts`: same design in TS (`FontIndexCursor`, `FontKerningJob` with `advance/result/cancel/intoRetirement`).
- `📝️text/🦀️.rs`: removed `pub mod font_pair` (unused UI copy).
- Deleted `🤝️kerning/🧪️tests/🟦️.ts` and `🤝️kerning/🧫️fixtures/🔣️.json` (belonged to the removed pair reader; kerning is covered by the font module tests against rustybuzz / opentype.js).

## Command caveat
Run from the repo root, `cargo check -p semio-framework-2d --tests` resolves the root workspace where 2d is a non-member path dependency, so its dev-dependencies (`serde_json`, `ttf-parser`, `rustybuzz`, `tiny-skia`, `semio-framework-trace`, `semio-framework-pixels`) are silently not linked and 211 bogus E0433/E0432 errors appear. Add `--manifest-path "🧰️framework/🔨️modules/◻️2d/📦️packages/🦀️rust/Cargo.toml"` (the crate's own `workspace = "../../../.."`).

## Remaining 17 runtime failures: value crate, not 2d
Failing tests: booleans retirement x6, flatten x3, stroke x1, trace x1, font outline/run close x5 (`font_outline_*`, `font_run_*`). Panic: `retirement owner has no controlled physical release demand` (`🌱️value/♻️retirement/🎮️controlled/🦀️.rs:114`) and `controlled retirement abandoned before terminal-empty` (`:213`). Cause: `RetirementCursor::next_close_byte_demand` defaults to `None` (`🌱️value/♻️retirement/🦀️.rs:38`) and several cursors there do not override it: `FixedArray` and `PlainArray` (`[T;N]` owners, lines ~424-480), `UnorderedSet/Map`, `OrderedSet/Map`. Any 2d owner holding an array or such a collection (e.g. outline `Component{matrix:[f64;4]}`, path/trace jobs) trips it. Belongs to the value-core owner; not edited here.
