# WASM Package Identity Audit

`Actual WASM package identity changed` is emitted by `consumeProducedWasmPackageV1` when a generated output ceases to be a regular single-link file or its dev, inode, size, mode, mtimeNs or ctimeNs differs from the recorded stamp. It is not a Cargo package name check. Only after that check does the code hash the bytes again. The editor failure stack reached this recheck through the common repository WASM publication consumer after `stageRepositoryArtifacts`; its log does not name the file or differing field, so the actual cause cannot be distinguished from the retained evidence.

All five Play WASM jobs reach this guard: editor, graph, surface and flow through `buildAdmittedWasmWebV1`; puzzle through `buildRepositoryWasmWebV1`. Editor, graph and puzzle verify the produced token; surface runs its browser test while holding it; flow publishes its browser package. Thus they share the same class of refusal, but no sibling failure or changed identity has been established.

Metadata-only activity can trip this guard without changing file contents: chmod can change mode and ctime; setting timestamps can change mtime and ctime; extended-attribute or other metadata changes can update ctime; creating or removing a hardlink changes link count and typically ctime. Replacement by an identical-byte copy can change inode or device. These are possible classes, not observations of the failed file. The artifact source capture copies bytes using held descriptors and chmods its destination; no source write or hardlink was identified in that path. Rechecking bytes remains necessary, and these observations alone do not justify weakening identity protection. No build or source edits were made.

## Consumer call order and Darwin probe

- All three jobs run the repository WASM provider. Its generic callback publishes `package_.files` through `stageRepositoryArtifacts`, then calls `package_.recheck()`, then invokes the owner-specific `options.consume`. In failed run `wCsXqmg`, the editor stack points exactly at the post-publication recheck, so the editor callback had yet to run.
- Editor’s callback is `verifyProducedWasmPackageV1`, a read-only recheck. The surface callback passes paths to its browser test, which reads the TypeScript declarations and Wasm, imports the generated JavaScript, then initializes the Wasm in memory. Flow reads the produced files and writes its alternative wrapper, type declaration, and manifest to its own product scratch. Its second publication forwards existing native files as read-only sources. Neither sibling callback writes to the producer package tree.
- Generic publication admits regular, single-link input files by read-only descriptor and rechecks their exact inode, mode, size, link count, mtime and ctime before, during and after streaming. It exclusively creates each staged target as a separate file, copies bytes, chmods that target descriptor, and replaces or discards the staged destination tree. This path does not call clone, hardlink, or chmod on source.
- Tested fresh and identical-repeat publication with the six actual editor product members, including the hidden `.gitignore`, copied to disposable ticket fixtures. The producer-style `observePhysicalFileV1` advanced only source atime. Both publications preserved every audited source stamp field including ctime, and the staged files had distinct single-link inodes. A second trial called the paid `stageOwnedArtifactsV1` with an issued cleanup token and independently confirmed only source atime changed.
- Deliberately applying the same mode to the disposable `framework_editor.js` through chmod changed only its ctime on this host. The original guard would refuse that metadata-only change. The failed job does not identify a writer or prove this happened to its source. Both fixtures ran on ticket device `16777233`; the published product was on managed image device `16777267`, and the failed compiler scratch was already cleaned. The audit does not reproduce provider transitions or external filesystem activity on that compiler image.
