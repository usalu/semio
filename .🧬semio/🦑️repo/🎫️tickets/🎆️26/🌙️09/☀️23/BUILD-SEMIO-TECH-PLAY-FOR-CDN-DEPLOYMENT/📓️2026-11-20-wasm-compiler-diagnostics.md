# WASM compiler diagnostics in release job logs

The native Flow WASM failure in run `wh7gdVT` reported a failing crate but omitted its Rust `E0432` and source span. The WASM compilation adapter used the bounded 64 KiB capture intended for quiet commands. The exception appended the most recent output and the job never received the earlier compiler error. Subsequent warnings could displace the failure completely.

The default WASM command adapter now uses the existing owned stream runner. Both compiler streams reach the parent diagnostic stream and the driver collects them into its existing bounded per-attempt job log. The adapter adds no log files. It uses the narrowed compiler control to create the child capsule and pass that same control's deadline and cancellation signal to the runner. A cancellation propagates the original signal reason after owned child settlement. The command's terminal status is preserved in the owned failure outcome. The WASM policy limits child output to 128 MiB and 2,097,152 lines. Crossing either bound uses the existing runner's output-limit refusal and owned child cleanup.

The language-neutral fixture emits an `E0432` diagnostic and source span, then 2,400 warnings. The existing capture loses the diagnostic from its tail. The streamed adapter preserves the diagnostic, source span, every warning and the child's projected compiler budget in the parent diagnostics. The captured compiler lines match an independently collected Bun subprocess stream byte for byte. Cancellation of a waiting synthetic child preserves the original reason and joins the child. The regression fixture and all eight existing WASM owner tests passed, including Node execution without product imports. The verification did not run Cargo, wasm-pack, describe or a release build.

The WASM Source admission path uses `admitCargoSelectionV1`, which captures and admits the selected graph then returns no admitted roster or held recheck. The retained Cargo drift monitor receives a live plan's admitted rows before tracking its child. Applying it here would require keeping the WASM admission scope and exact source rows through execution, while validating that the effective Cargo arguments under `wasm-pack` are the admitted selection. This diagnostic change stays within the existing WASM execution port.
