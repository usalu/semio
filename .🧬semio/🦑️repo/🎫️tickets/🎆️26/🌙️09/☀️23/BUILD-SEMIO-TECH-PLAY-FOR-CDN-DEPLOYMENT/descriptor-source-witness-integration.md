# Descriptor Source Witness Integration

The existing same-root witness cannot be safely enabled for the descriptor emitter by removing the drift watch or passing one extra argument. The descriptor build requests `retainCompilationBytes` and publishes an executable plus an exact retained compilation receipt and inventory. Its current capture path cancels Cargo when an admitted source changes while Cargo is running (`native-build/🟦️.ts`, `captureCargoArtifacts`, around 1074), before provenance is written. It creates its retained provenance session without a source witness (around 1181).

The component-pass witness records bounded admitted workspace file bodies, associates a retained version only when rustc dep-info supplies a matching BLAKE3 and length, detects incompatible consumed versions, and rechecks selected retained blobs. Missing checksums fall back to current physical observation; a missing matching witness or inconsistent claims must still refuse. The component pass currently constructs the witness only when `retainCompilationBytes` is undefined (`component-pass/🟦️.ts`, 660–661). Those mechanisms do not independently establish that the descriptor's entire retained compilation packet remains valid.

The hard blocker is the retained compilation and plan contract. `completedCargoClosureRosterV1` marks ordinary source inputs as current custody, and `CargoCompilationSnapshotPoolV1.snapshot` copies each file from its original path and verifies its recorded digest. If a source has changed after rustc consumed it, that copy and later custody checks refuse even if the witness has the consumed version. A safe extension needs a verified witness-to-retained-copy transfer keyed by each checksum-backed receipt row, explicit bounded storage accounting and lifetime, and correct treatment of inputs without checksums and compiler/build-script resources. The retained index reader must still derive and verify the exact same closure and mapping from the receipt. Selected witness blobs must be rechecked before transfer and remain alive until all consumers settle.

The artifact plan additionally compares the completed receipt's workspace source digests with the pre-admitted planning roster and invokes live `recheck()` before consumption and again after capture (around 355–370). Allowing a consistent later consumed version therefore requires an explicit contract for which source identity is authorized; simply skipping those checks would admit a different plan. Conflicting per-unit source versions, graph/recipe drift and unverified non-Rust resources must remain refusal conditions. The current watcher, child termination and deadline/abort cleanup also require replacement by cancellation-safe attempt tracking; ordinary cancellation must continue to terminate and drain the child, release custody and clean witness storage.

The descriptor consumer verifies one exact executable against a successful non-cancelled receipt, reads the retained index, checks exact inventory and artifact digests, and rechecks custody around use (`describe/🛠️emitter/🟦️.ts`). Those checks must remain intact. There is no small deployable wiring-only fix evidenced by the current code; designing and testing the retained source transfer and plan authority is prerequisite. This was a read-only source audit; no build or runtime validation was performed.

## Current Descriptor Implementation

The descriptor source has changed since the audit above. `buildDescriptorEmitterV1` now enables `retainConsumedSources` within its existing bounded compilation reservation. `captureCargoArtifacts` records original admitted SHA-256-matching bodies in its private witness before spawn. The witness may spend up to half the retained compilation budget. Source capture refuses a missing or changed admitted file, and a file whose matching body was not retained still triggers immediate cancellation on observed drift.

The monitor emits `cargo:deferred-source-digest-mismatch` once per changed path when it owns an exact admitted body. `proof:pending` means it has yet to see a matching dep-info checksum in an artifact announcement. `proof:announced` means an announcement supplied a BLAKE3 checksum and byte length matching the admitted body. Both labels are progress telemetry. The announcement comparison does not select a retained provenance input.

A successful Cargo exit starts the separate completed receipt proof. The session resolves each unit's exact dep-info checksums, selects a retained body only when BLAKE3 and length match, and checks that every consumed view of that path is consistent. Missing checksum evidence keeps the input under current physical custody and blocks witness substitution for that path. The provenance session rehashes selected witness files. The retained snapshot copies a selected body under its receipt SHA-256, and the completed source check compares all admitted workspace source digests, including missing records, against the receipt. The full plan recheck still checks the current recipe, planning graph, source admission and overall identity. It substitutes an admitted digest only at the same roster position for a selected original witness. The consumer still verifies the completed executable, retained observation and packet around use. A changed current file can pass only if the completed evidence establishes the exact admitted version under these guards. A resumed compile and an artifact announcement are earlier milestones.

Flow's browser package enters `buildAdmittedWasmWebV1` and still calls `runWasmCargoCommandV1` with the admitted source roster. The WASM wrapper shares the file watcher but has no retained-source deferral. It publishes a proven mismatch, aborts and drains the owned command, and lets the existing retry path handle churn. This inspection neither ran the compiler nor changed any source, provenance or process state.

## Bounded Executable Dep-Info Discovery Fix

Final provenance still searches the admitted build directory, target, profile and package output roster. For a Cargo binary whose announced filename is its executable and matches the target name, discovery now tries a single additional underscore-normalized filename in each existing output directory. The `.exe` suffix remains on the executable path and is removed when deriving the `.d` path. An additional record must name the direct target in its rule, carry that target's rustc checksum and have an adjacent executable with the same SHA-256 as the Cargo announcement. The existing exact-name candidate remains first. If discovery finds no qualifying compiler record, normal dep-info selection applies. The downstream mixed-source and unchecked-input checks still enforce their original conditions.

The neutral regression reproduced the missing record before the fix. The actual provenance session then passed matching POSIX and `.exe` names, a lookalike executable with different bytes, an unrelated target checksum and a nonbinary declaration. The fixture uses literal Cargo and rustc names and the independent Noble SHA-256 and BLAKE3 implementations. The six focused Bun tests passed with 97 assertions, including existing dep-info and source-witness contracts. The scoped diff check passed. No Cargo, describe, or release process was started or restarted for this work.
