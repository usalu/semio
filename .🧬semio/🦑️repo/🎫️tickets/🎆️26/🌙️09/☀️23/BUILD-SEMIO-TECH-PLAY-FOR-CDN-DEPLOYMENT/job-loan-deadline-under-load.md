# puzzle-wasm: Original resource loan deadline exhausted under load

- Deadline: not the driver, not job-attempts (no deadline there). `wasm:build` runs under a renewable `native-child` progress window (idle 3600000 ms, `⏱️budget/🧬️schema`; SEMIO_BUILD_BUDGET_MS=0 so the max is the 6h preparation default). Admission/lease waits are credited via `admissionWaitedMillisecondsV1` (wall clock otherwise).
- Bug: `🕸️wasm-build/🟦️.ts` `invoke` passed `budgetMs: compilerAdmissionBudgetV1(control)` (snapshot of the remaining renewable window, about 3.6e6 ms) and `runWasmBuildCommandV1` re-requested it as a fixed, nonrenewable `requestedCompilerAdmissionControlV1(options.control, options.budgetMs)`. The wasm-pack child (label `puzzle/board`) therefore died exactly 3600 s after start while still compiling (last crate `semio-hub-puzzle-component`); it ended with SIGTERM "deadline" then `arm` threw ResourceLoanDeadlineExhausted (`🧭️invocation/🏃️process/🟦️.ts:318`).
- Fix: removed `budgetMs` from the run port options and call site; `runWasmBuildCommandV1` uses `requestedCompilerAdmissionControlV1(options.control, 0)` so the compile inherits the caller's renewable deadline.
- Tests: added a regression test in `🕸️wasm-build/🧪️tests/🟦️.ts` (fails on old code, passes on new); dropped the `options.budgetMs` expectations from `🏗️native-build/📥️inputs/🧪️tests/📥️consumers/🟦️.ts`. 5 other tests in the wasm test file and 2 in consumers fail identically before the change (SEMIO_TEST_ARTIFACT_DIR unset, `withProvisionedPythonV1` undefined).
- Files (identical edit in live and in /Users/ueli/.sinc/play; snapshot copies were identical to live pre-change; snapshot module loads): 🧰️framework/🔨️modules/🏃️process/📦️artifacts/🕸️wasm-build/🟦️.ts, .../🕸️wasm-build/🧪️tests/🟦️.ts, 🧰️framework/🔨️modules/🏃️process/📦️artifacts/🏗️native-build/📥️inputs/🧪️tests/📥️consumers/🟦️.ts
- Same snapshot-pattern (`runOwnedCommand(..., compilerAdmissionBudgetV1(control), ...)`) exists in other callers (e.g. native-build relay); not touched.

## Sweep: other frozen child budgets (2026-11-23)

Root cause of the class: a remaining renewable window read once (`compilerAdmissionBudgetV1`, `control.remainingMs()`, `policy.budgetMs` as a fixed requested budget) and passed as a fixed child budget. Second root cause found in `📥️capture/🟦️.ts` (`captureOwnedProcess`): even with budget 0 it armed ONE `setTimeout` from the remaining time at admission, so a renewable parent deadline was never re-read and the child died when the first idle window ended.

Call sites of `compilerAdmissionBudgetV1` (non-test) and verdicts:
- `🌊️relay/🟦️.ts` (native-build cargo relay): DEFECTIVE (fixed `policy.budgetMs` control + frozen `budgetMs` into capture). Fixed: control is `policy.budgetMs===0 ? inherit : renewable(native-child, maximum policy.budgetMs)` as in native-build/wasm-build; capture gets `budgetMs:0, deadline:control`.
- `📥️capture/🟦️.ts`: DEFECTIVE (fixed timer). Fixed: timer re-reads `remaining()` (parent, fixed phase, new optional live `deadline`) whenever believed due; fixed deadlines still met exactly; a throwing deadline is a `timeout`.
- `🐹️go-build/🟦️.ts`: fixed `policy.budgetMs` requested control; made renewable like wasm/native (same pattern).
- `🛂️descriptor-emission/🟦️.ts` (describe): froze `compilerAdmissionBudgetV1(control.compiler)` into the child; now asserts the compiler control is alive and inherits `tool.control` (`requested(..., 0)`).
- `🌐️browser-bundle/📜️script.ts` (actor codegen capture): frozen `compilerAdmissionBudgetV1(phase)`; now `budgetMs:0, deadline:phase`.
- `🏭️fresh-component/🟦️.ts` (iterate/fresh cargo + preparation captures): `Math.min(control.remainingMs(), ...)` frozen as fixed phase; now fixed phase = declared `policy.command.maximumElapsedMilliseconds` minus elapsed, plus live `deadline: control.remainingMs()`.
