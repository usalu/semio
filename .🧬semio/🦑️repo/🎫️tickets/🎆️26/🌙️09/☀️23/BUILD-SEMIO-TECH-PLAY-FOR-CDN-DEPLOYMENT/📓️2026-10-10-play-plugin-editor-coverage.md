## Method

1. Plugins and artifacts: directory listing of `✏️s/🔌️plugins/*/🗿️artifacts/*` (and `🗟️artifacts` for stdio). An artifact "has an editor" when a `✏️editor` directory exists below it.
2. Catalog: `🏢️semio-tech/🎡️play/🔨️modules/🧩️runtime/🔣️.json` (148 panes, 18 groups). Registry: `🤖️generated/🚀️playgrounds.json` (156 rows now, 155 at audit start). Row `app` values are authored in each composition `Cargo.toml` under `[[package.metadata.semio.playground]]`.
3. Lanes: `framework-os-dev:prepare-<variant>-react-release` targets are generated by the repo Nx plugin `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🟨️.mjs` (around lines 1180-1240) from each registry row. Its `prepare-*` depends on `materialize` of the closure `runtimeComponentClosure(components, [{id: pluginId, appScoped: true}])`.
4. Closure: rebuilt from the 70 `[package.metadata.semio]` component manifests under `🌎️hub/🧩️compositions` and `✏️s/🔌️plugins` (44 hub plugins plus extensions, with `depends-on`, `consumes`, `contributes`, `extends`), using the repo's `runtimeComponentClosure`. This is independent of the stale generated registry.
5. Lane-to-pane comparison: the 28 lane roots versus the 69-component pane closure.

## Gap list

B1. Generated registry blocks every play closure (blocker, coordinator-owned).
- `🤖️generated/🔌️plugins.json` and `🧩️plugins/🟦️.ts` list only `bim`, `draw`, `puzzle`.
- `🤖️generated/🩺️diagnostics.json`: 43 `stale-channel` (descriptorChannel 20, hostChannel 23) and 24 `stale-channel-dependency`. Refused pluginIds include animate, architect, block, cad, dag, demonstrator, energy, fem, flow, forms, gis, imperative, layout, lowpoly, mathematical, norm, note, playbook, process, raster, reasoning, remodel, sequence, shooting, sourcing, space, stdio (+ 9 extensions), trinity, vcs, wfc, writer, and the flow/imperative/playbook/cad/process/sourcing/procedural extensions.
- Effect: `🏢️semio-tech/🎡️play/🔨️modules/🧩️runtime/🟦️.ts:57` (`playRuntimeComponentIds`) throws `Unknown runtime component cad`. `prepare` and `activate` cannot succeed.
- Needed: find and fix the channel source (I could not locate the channel constant with grep; the strings `stale-channel`, `hostChannel`, and `descriptorChannel` do not occur in the framework sources), then regenerate the registry. Not done here (read-only).

G2. `bim` is missing from play.
- Row `bim` exists (`app = s.bim.model@1/*#editor`, from `🌎️hub/🧩️compositions/🏙️bim/📦️packages/🦀️rust/Cargo.toml`). Artifact `✏️s/🔌️plugins/🏙️bim/🗿️artifacts/🏢️model` has an editor.
- Not in `🏢️semio-tech/🎡️play/🔨️modules/🧩️runtime/🔣️.json` (no pane in the BIM group, which holds only IFC/BCF `stdio` rows). No lane in `📋️project.json`.
- Needed: add a pane `bim` (label, tagline, description, icon matching the schema pattern) to the BIM group in `🔣️.json`, and add `framework-os-dev:prepare-bim-react-release` / `-dev`, `activate-bim-react-dev` to `catalog-release`, `prepare-dev`, `activate-dev` in `📋️project.json`. Run the play catalog tests after the change.

G3. Nine stdio extension components are not reached by any lane (79 panes affected).
- Extensions: stdio-bim, stdio-binary, stdio-cad, stdio-image, stdio-media, stdio-mesh, stdio-office, stdio-pdf, stdio-semio. Each declares `depends-on = ["stdio"]`, so the closure goes from extension to host only. The `stdio` lane's closure is `{stdio}`.
- Play's `prepare` checks every component directory in the closure (`📜️script.ts` `PreparationScript`), so these nine must be materialized by some lane.
- Needed: add one lane per extension to the three `dependsOn` lists (for example `stdio-png` for stdio-image, `stdio-mp4` for stdio-media, `stdio-bcf` for stdio-bim, `stdio-dxf` for stdio-cad, `stdio-stl` for stdio-mesh, `stdio-docx` for stdio-office, `stdio-pdf-1-4` for stdio-pdf, `stdio-binary` for stdio-binary, `stdio-semio` for stdio-semio). Each such lane's bootSelected closure is {extension, stdio}.

G4. Root cause of G2 and G3: the 28 lanes are hand-listed in `📋️project.json` while the catalog has 148 panes. Fix: derive the lane list from `PLAY_RUNTIME_TARGETS` (or from the catalog), so every pane's pluginId is forced into a lane. The project.json should keep only calling the script.

G5. Semio `base` subset (verify). `🧿️semio` has editor dirs for 19 subsets plus the root. Registry rows cover 18 subsets (`stdio-semio-*`) and the wildcard `stdio-semio`. The `✉️base` subset (`🏅️standards/🔖️v1/🪆️subsets/✉️base/✏️editor`) has no dedicated row. It is only covered if the wildcard `s.stdio.semio@v1/*#editor` is intended to include it. Confirm at runtime; add a row and pane if a separate editor is expected.

G6. Ten plugins have an editor dir but their registry row has no `app` pointer: animate, architect, dag, flow, imperative, playbook, reasoning-wires, sequence, vcs, writer. These are single-artifact plugins that boot their default app, and they are in the catalog with an example. Not a coverage gap. Verify each opens an editor at runtime.

G7. Plugins with no lane of their own: cad, procedural, puzzle, gis, process, sourcing. They are in the release set only through the `demonstrator` lane's `consumes` closure (cad.computer, process.machines, sourcing.module, forms/flow topics). Risk: removing or changing those consumes edges drops them from release silently. Consider explicit lanes.

G8. Extra root editor dirs (informational): draw, stdio/zip, stdio/semio each have a root-level `✏️editor` in addition to subset editors. No separate row; covered by the wildcard row. Confirm no hidden editor is expected.

- Brand partner rows with brand prefix `entwerfen-mit-bestand-` (aggregator, aussuchen, bearbeiten, generator, koordinator, verfolgen).
