# S1 — Definitive Plugin Coverage Matrix (2026-09-18)

Read-only audit, slice S1. No files edited, no cargo/build run, no sub-agents spawned. Every fact below cites a
file/line or a raw capture already on disk; nothing is inferred without an evidence pointer. Base inventory is
`📓️audit-plugins-artifacts.md` (34 real plugins, `🗟️artifacts` excluded as a non-existent stub — see its §Q2.1).
This report adds today's (2026-09-18) findings from `📓️p2-dormant-plugin-compile.md`, `📓️b1b-dormant-plugin-boots.md`,
the uncommitted `🐍️b1a-*-boot-probe.mjs` captures, `🗑️generated/a1-catalog-skips.txt`, `📓️m1-mcp-servers-start.md`,
and a fresh read of `.vscode/launch.json` / `.claude/launch.json` / `🔌️plugins.json` / `🗺️catalog.json`.

## Method

- **Artifacts/crates**: `🗑️generated/plugins-inventory.txt` (per-plugin `Cargo.toml :: name =` lines) + audit table.
- **React recipe/port**: `.vscode/launch.json` — every plugin has a `workspace:dev -- <plugin>` React row and a
  `…wgpu wasm` row, each with a dedicated `<PLUGIN>_PLAY_PORT`/`S_OS_PORT` env var. Exact `name`/line/port for
  every one of the 34 was extracted with a small parser (see the line numbers cited per row below).
- **Probe/result**: `🗑️generated/b1a-*` and `🗑️generated/b1b-*` captures (console dumps, screenshots, `report.json`)
  from today, plus the per-plugin `*-END-TO-END`/`*-REACT-*`/`*-BOOT-*` ticket `📓️status.md` files under
  `.🧬semio/🦑️repo/🎫️tickets/🎆️26/`.
- **Unit tests**: `🗑️generated/plugins-tests.txt` (`#[test]`/`#[ignore]` counts, already computed by the prior audit).
  Every plugin-root crate's `📋️project.json` carries a `"test"` nx target (verified for all 34, e.g.
  `✏️s/🔌️plugins/🖨️raster/📦️packages/🦀️rust/📋️project.json`) — this is uniform, so it is not repeated per row unless
  a plugin is the exception.
- **Catalog/MCP**: `🗑️generated/a1-catalog-skips.txt` (raw `[mcp registry] skipping plugin …` lines from the A1
  slice's `capabilities_search` run) cross-referenced with `📓️m1-mcp-servers-start.md` §6.1.
- **Registry**: `🗺️catalog.json` (id/directoryName only, 60 rows) and the real per-plugin descriptor
  `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/📇️registry/🤖️generated/🔌️plugins.json` (`activationEvents`, `role`,
  `capabilities`, hashes) — read directly with `python3 -m json.load` today.

## Headline finding not in the prior audit: the capability catalog is down for all 34 plugins right now

`capabilities_search` returns **0 hits for every plugin** — not a subset. `🗑️generated/a1-catalog-skips.txt` shows
33 individual descriptor-decode failures (missing `artifactSchema`/`windowKindId`/`executionProtocol` fields, or
no `🔣️.json` committed at all — `block`, `stdio`, `playbook`, all 5 `imperative-extension-*`, all 4
`process-extension-*`, all 3 `sourcing-module-*`), and then the whole compile aborts anyway on
`duplicate capability id: architect.s.architect.program@1/*#editor.setAdjacencyKind`
(`📓️m1-mcp-servers-start.md:206-207`, raw line in `🗑️generated/a1-catalog-skips.txt`), which forces a
**gateway-only fallback with zero registered capabilities** for every plugin, including the 17 whose own
descriptor decoded cleanly (`architect`, `cad`, `draw`, `energy`, `fem`, `gis`, `imperative`, `layout`, `lowpoly`,
`note`, `procedural`, `process`, `puzzle`†, `raster`, `remodel`, `shooting`, `space`, `wfc`). (†`puzzle` is
actually also in the skip list — 16 clean, not 17; corrected in the table below.) So "Catalog/MCP" is **NO** for
all 34 today; the table's Catalog/MCP column records *why* each one would still fail even after the duplicate-id
bug is fixed, since most have their own descriptor drift underneath.

## Headline finding: every plugin declares a React boot recipe; almost none pass the interaction bar

`.vscode/launch.json` gives **all 34 plugins** a `workspace:dev -- <plugin>` React row and a `wgpu wasm` row with a
dedicated port (confirmed by direct parse, line numbers below) — "React recipe exists" is **YES for all 34**.
But today's probes (b1a/b1b, six plugins each) show a **systemic** blocker independent of any one plugin's code:
`validate_ui_dispatch_classification` (`🧰️framework/…/🔌️plugin/🦀️.rs:12594`) admits only
`InteractiveJobClassification::Migrated`; every other document-mutating verb is refused at dispatch
(`interactive-job.not-ui-safe`), and apps that never wrote `ArtifactApp::command_from_action` refuse every
shell action outright (`app.command.unsupported`, `🧰️framework/…/🔌️plugin/🦀️.rs:11762`). Of the 34, only a
handful (`raster`, `forms`, `note`, `fem` (2d/3d), `energy`, `layout`) have **direct, dated evidence** of a real
state-changing interaction (add/undo/select) reaching the document. The rest either have never been probed for
interaction, or were probed today and every action was refused.
