## 3. 🔴️→🟢️ A real defect this slice found: `idle_turns` is order-dependent

`cargo test -p semio-s-plugin-wfc --test idle_turns -j 4` (the default two-thread harness) fails
NON-DETERMINISTICALLY, and it fails differently each time:

```
run A: an_unacknowledged_open_retains_nothing_per_turn  → retained=4 662 331 B (9 106 B/turn)
run B: every_wfc_editor_idles_settled_and_retains_nothing → bitmap retained 66 290 B (129 B/turn),
                                                            sources {"settled": 510, "settled(contended)": 2}
run C (--test-threads=1): 2 passed
```

The lane installs `semio_framework_trace::HeapWitness` as the `#[global_allocator]`, so
`retained_heap_bytes()` counts the WHOLE PROCESS. The file's two laws are exactly the two the harness
runs in parallel, so each was measuring its sibling's allocations — and the sibling's typed-operation
contention, which is where the `settled(contended)` turns come from. The numbers it printed were
never this plugin's.

Fixed in `🧪️tests/😴️idle-turns/🦀️.rs`: a process-wide `IDLE_MEASUREMENT` mutex taken by both laws for
the whole of their boot-and-measure window (`measurement_lease()`, poison-tolerant), with the reason
in its docstring. Three consecutive default-harness runs are green afterwards, and the readings are
back to what a single measurement sees: bitmap 393 B, grid2d −15 991 B, wfc2d −15 991 B, grid3d
21 657 B, wfc3d −15 991 B over 512 turns (all 0 B/turn against the 65 536 B ceiling), unacknowledged
open 377 B. G's green reading was luck, not measurement.

## 11. One incident, disclosed

My first comment-migration codemod reused indices computed before its own edits, so in the six files
where one function held two or more comment blocks it deleted the wrong lines and re-inserted them,
mangled, as docstrings (`/// efault_value(&crate::examples::…)`). Caught immediately by reading the
output, repaired line by line against the pre-edit context dump — the interaction-definition fields in
wfc3d's `create_wfc3d_editor`, the `for (id, source, target)` loop head in its
`host_snapshot_mutations`, three builder calls in wfc2d's `create_wfc2d_editor`, the two
`render_with_transient` bindings in its preview law, the `StepOutcome::Complete` arms in both
inference jobs and grid2d's `let mut layer = json!({` — and then redone with a one-block-per-pass
version that recomputes positions after every edit. Proof that the repair is exact: all five crates
compile and their suites are at their EXACT pre-codemod counts (185 / 211 / 190 / 207 / 239, zero
failures), and the plugin's four lanes are green.

Second, smaller: `grep` in this shell is `ugrep`, and it silently returned nothing for
