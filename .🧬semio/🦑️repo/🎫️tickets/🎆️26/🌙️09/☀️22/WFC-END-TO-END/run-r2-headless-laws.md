# Headless Failure Lifecycle Laws

The new engine headless test module covers four schema-first portable cases: a fully closed rejection converts to text; a finite source admission refusal preserves the exact unadmitted job; temporarily blocked original teardown preserves a successful output value; and a callback failure keeps its actual original cause borrowable until explicit retirement.

The fixture is a real InteractiveJob driven by run_headless. A static AtomicBool controls close availability. It records the original source-parent identity and operation/generation on the real step, asserts the same identity during close, posts one actual metadata item and CPU witness when it becomes empty, and counts physical closure. The successful output has an independent Drop counter. Tests refuse early conversion, open the same close port, resume through the existing failure owner, assert paid work and bounded receipts, compare all original capacity against release, recover the original result and verify exactly one eventual output drop. The admission case asserts the reclaimed job identity and that no original close was fabricated.

The cases and schema live beside the native module under engine/💼️job/🏃️headless/🧪️tests/🧫️lifecycle. The retained ticket input headless-lifecycle-oracle.ts validates them with Ajv and an independent finite ownership model; all four cases passed. The new native source passed pinned syntax parsing. The same cfg=[test] public source preflight measured engine-job3784 active lines across21 files, explicitly nonauthoritative and not an upper bound. No native or build queue was started.

Source review while authoring the cause law found two real loss paths: automatic cleanup could retire the actual original failure before returning the failure owner, and a checked-out continuation was passed to the semantic outcome accessor without preserving its callback/qualification causes. These were sent directly to the native owner, who fixed the runtime and added the public original_continuation accessor. This agent did not edit headless runtime source. Runtime typechecking and execution of these laws remain pending with the sole native gate owner.
