# Space History Snapshot Receiving Work

The shared workspace receiving and space-history validation layers now carry native snapshot work outcomes. They measure the original SQLite control's performed-work delta, preserve the original native failure, and return authored `IoResult` separately. The typed validation frame keeps its original `ValueError` through body settlement so a simultaneous validation and settlement failure retains both causes. The lifted trait exposes the nested outcome to its callers.

The native verification lane owns the remaining snapshot, receiving, native codec and typed settlement migration. A new generic stage failure preserves a completed output or original error alongside settlement refusal. The approved lifted interface takes a caller-owned output slot and returns native work and any independent observer refusal separately. Validation places its result in the native receiving owner before handoff.

The shared workspace fallback still has a custody gap: its handwritten `to_sqlite_database` and `from_sqlite_database` hooks return an owned value locally before it is written into the frame, without a separately quoted handoff. Reserving after the return can strand that value on refusal; reserving a native work action before the call prevents the body from using its own original work. A staged authored producer or safe original-owner handoff primitive is required. The zero-allocation fixture does not establish safety for allocating bodies. The current changes are not a lossless completion and have not compiled.

The validation owner now includes a schema-first dual-failure fixture and a focused test that charges the original native control past an independently smaller SQL ceiling, then checks the authored error's original message pointer and settlement refusal. Another test sends an authored validation error through the actual native receiving owner, refuses the publication receipt with a construction recipient, and checks output identity, work, and funded retirement. A workspace fallback test invokes the real default trait on a zero-allocation model with a zero SQL ceiling, once successfully and once with an authored error and rejected publication receipt. The framework frame is funded independently before narrowing the SQL body allowance. The existing TypeScript suite validates the dual-failure fixture with Ajv and JSON. These tests have not run; shared retirement and snapshot callers are still being migrated.

It observes the partial object, vector, key and message backing in the paid frame, checks the retained owner and work, denies a zero-grant close, and compares all allocation and release receipts after funded retirement.
