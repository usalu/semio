# Native Snapshot Allocation Custody

The snapshot failure owner now retains the complete encode or decode allocation outcome independently of its other causes, including all individual allocation refusals and actual extent. Its transport schema, decoder, encoder, retirement and equality surfaces and schema-first fixture were extended. The owner tests and independent Ajv/SQLite oracle are authored but have not passed a compiler or runtime gate yet.

The original allocation primitive catches only the allocation operation. A panic in a Quote, Post or Cancel port can unwind before it records the original request and callback progress, even when backing or an earlier refusal exists. The fixture specifies original request, actual extent and started/completed states for each original port. The repair requires caller-owned state initialized before Quote and retained across callbacks. A started callback cannot be reposted as though it never ran.

The approved operation-panic path records actual extent, leaves settlement pending, resumes the original panic, and requires a later explicit settlement under the original authority. This avoids discarding an operation panic if settlement itself panics. Primitive repair and adversarial execution remain outstanding.

The lower encode and decode primitive drafts now retain original requests, raw actual extent, operation status and Quote/Post/Cancel callback boundaries in explicit caller-owned progress.
