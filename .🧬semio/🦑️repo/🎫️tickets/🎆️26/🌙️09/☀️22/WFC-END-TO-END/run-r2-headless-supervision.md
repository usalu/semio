# Supervised Headless Native Laws

The canonical framework headless test family now consumes nine schema-first supervision cases. Initial cancellation and budget stops execute no business span; a paid Yield admits one post-acknowledgement supervisor call; empty preparation callbacks do not supervise; genuine Complete, Cancelled and Fault outcomes reach the terminal finish callback first. Both a supervisor result and a terminal result are retained while an external static close port is blocked, then recovered from the same original source with exactly one final Drop.

The fixture uses the real InteractiveJob/RetainedPayloadBuilder APIs and a static32785byte nonzero source, crossing three payload pages. The actual HeadlessOutcome variant determines each observed result. Complete/Fault callbacks verify exact captured bytes, allocation-free payload_equals equality, length mismatch and a mismatch in the last byte of the third page.

A separate law prepares and drives the actual private HeadlessState to a checked-out Complete outcome. It snapshots the original caller immediately before staged capture, verifies capture-only copy and capacity receipts and fuel consumption, then narrows one acknowledgement turn to zero items on that same caller. Refused ACK must leave both the original payload header and the captured backing/data intact, with no new receipt. A later ordinary turn from the existing remaining source acknowledges once; full teardown must balance all original capacity and release. No new caller, stock, clock calibration or runtime test hook is used.

These laws exposed a concrete supervision mismatch during authoring: the driver originally grouped empty callbacks with real nonterminal outcomes. The native owner split Seen::Empty from genuine Seen::Pending, so only an acknowledged Yield/Preview/Checkpoint triggers supervision. The earlier exact callback-cause and continuation-preservation laws remain intact.
