# Ui Surface Registry Retirement

## Scope and evidence

This is a read-only source audit for the 65 sequential Dock-window lifetime law. I did not run the new native or React probes. Source anchors below were read after the law and fixture were added.

The proposed law is correctly aimed at a live capacity defect. `UiSurfaceRegistry` has 64 `Option<UiSurfaceSlot>` entries and only admits into `None`; admission increments a per-slot generation and installs `UiWindow`, but it has no removal operation. A window that has merely had its document closed still occupies a slot indefinitely.

## Identity correction: two generations, two meanings

`UiSurfaceToken { slot, generation }` is the only complete retained-slot identity. It is checked by `get_token`/`get_token_mut` ([`engine/🦀️.rs:549`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs)); a slot reuse necessarily gets a later token generation.

The close queue does **not** retain that token. It records `Ui::surface_generation`, which currently exposes `UiWindow.accessibility_generation` ([`Interpreter/🦀️.rs:291-327`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs), [`engine/🦀️.rs:2431`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs)). That number starts at zero in every new `UiWindow`; it is a document/accessibility epoch, not a registry-lifetime epoch. A same-id successor can reproduce it, so it cannot prevent an ABA close from consuming the successor.

The repair should therefore expose an exact `Ui::surface_token(window_id)` and make `UiDocumentCloseOwner` carry `{ window_id, token, document_generation }` (or name the latter `accessibility_generation`). Token comparison controls slot removal and close ownership; document generation remains the scene/pointer freshness value. Do not overload a `u64` API named `surface_generation` for both. While a token is queued as closing, publishing/admission for that identity must refuse; `render_ui_document_step` already has the host-side gate ([`Interpreter/🦀️.rs:2374`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)), but the engine must also reject direct ingress/reconcile paths.

## Required single-owner retirement ladder

Make `Ui::close_surface_one(token)` the operation called by the existing `close_ui_document_one`. It returns one of `Pending`, one `UiRetiredComponentScene`, or `Complete`; the interpreter continues to retire Map/Canvas outside the `UI_ENGINE` borrow exactly as it does today ([`Interpreter/🦀️.rs:352-356`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)). One invocation advances at most one owned scalar or one external scene retirement. A close request latches the token before Dock topology removal, which the existing `close_dock_window` ordering already does ([`Shell/🦀️.rs:16120`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs)).

1. **Latch and silently cancel router state.** Retire capture, drag, thumb, hover chain, focus, overlays, typeahead, deadlines, and node-indexed drag/drop/scroll registrations. This cannot call ordinary `clear_focus`, `finish_close`, or pointer cancellation: those emit blur, overlay, or `DropCancelled` commands ([`events/🦀️.rs:402`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs), [`:1325`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs), [`:1885`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs)). It needs a dedicated silent retirement cursor, with no `UiCommand::App`, `DropCommitted`, `DropCancelled`, or manufactured pointer-up. `drag_payloads`, `drop_accept`, and `scroll_thumbs` are unbounded `HashMap`s at their registration sites ([`events/🦀️.rs:1450`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs), [`:1460`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs), [`:1519`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs)); `retain` is only run during a later event dispatch ([`events/🦀️.rs:1758`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs)). Give that cursor a bounded membership representation or an explicit one-entry drain. A bulk `clear`/drop is not a one-unit retirement proof.
2. **Close layout while the tree root still exists.** Drive the existing `layout_rejected.close_step(1, …)`, `layout_session.begin_close/close_step`, and `layout_job.begin_close/close_one` before taking document bindings. `MountedLayoutJob::close_one` already frees one retained item per call and has an exact terminal predicate ([`mounted_layout/🦀️.rs:933-983`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/📌️mounted_layout/🦀️.rs)). `step_layouts` otherwise returns as soon as `tree.root` is absent, so it cannot finish an outstanding job after document closure.
3. **Close retained paint and hits before root removal.** `frame_step` returns `Missing` before it reaches `retiring_draw` when `tree.root` is absent ([`engine/🦀️.rs:1520-1534`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs)). A production close cursor must therefore retire `paint_frame`, transfer its candidate through `retiring_draw`, retire the active `draw`, and retire hit registrations before the tree phase. `DrawList::retire_step` is already scalar and `retirement_is_empty` checks terminal storage ([`draw/types/🦀️.rs:455`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/🖍️draw/🏷️types/🦀️.rs), [`:746`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/🖍️draw/🏷️types/🦀️.rs)); reuse it rather than dropping a `DrawList` whole. `hit_registry` currently is a `Vec`, so release needs a one-record/capacity-drain rule, not `Vec::clear` under this frame policy.
4. **Reuse the existing document and scene ledger.** `UiTree::close_document_binding_step` is already one binding at a time and applies component-scene backpressure ([`tree/🦀️.rs:833-853`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/🌳️tree/🦀️.rs)). The current ingress/retiring document portions of `close_document_step` should be this phase, with `scene_retirements` drained outside the UI borrow before more component bindings are admitted.
5. **Release scheduler references, then the slot.** `SurfaceLaneEntry` holds a token in fixed 64-entry lane rings and `layout_pressure` can retain another ([`engine/🦀️.rs:708`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs), [`:786`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs)). Stale tokens are safely ignored only when `next_layout` eventually pops them ([`engine/🦀️.rs:1435-1453`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs)); waiting for that can keep a lane full and block the 65th admission. The close ladder must purge at most one matching entry per opportunity, including `layout_pressure`, before final slot removal. Theme propagation holds snapshots of tokens and already checks liveness before mutation ([`engine/🦀️.rs:1338-1395`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs)); it needs no successor-facing mutation once token validation is retained.
6. **Remove only after terminal proof.** `UiSurfaceRegistry::remove_terminal(token)` should take the exact slot only after router, layout, paint/draw, hits, documents, scene ledger, and scheduler references are terminal. Leave `generations[slot]` in place; the next admission uses checked increment. The old token then fails `get_token`, and an old queued close cannot touch the successor. The close queue pops its exact front owner only after this operation reports complete.

This ordering is material. Reversing stages 2/3 with stage 4 strands retained layout and draw work behind the missing-root returns; removing the slot before stage 5 leaves fixed lane capacity occupied by dead work. `Ui::needs_frame` currently ignores close work ([`engine/🦀️.rs:1484`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs)), but Shell’s existing `CloseDocument` phase stays parked while the interpreter queue is nonempty. Keep that host wake as the only close-progress authority.

## Fail-first laws

1. **Sequential capacity:** retain the existing 65 distinct Dock close/mount scenario. It should observe at most one live UI surface, zero after each completed close, and no deadline actions. It must drive the actual Shell close phase to terminal, not call a registry helper directly. The loop bound must be derived from the maximum retained owners or wait for the explicit terminal status; `UI_DOCUMENT_NODES + 16` only described document cleanup and is not a valid full paint/layout retirement bound.
2. **Same-ID ABA:** mount `A`, capture its exact surface token and request closure, reach terminal removal, remount `A`, then present the delayed old close owner. The old token must be rejected; the successor must retain its document, scene target, and no cancellation/action. This is the regression the current `accessibility_generation` comparison cannot establish.
3. **Silent active unmount:** mount a surface with an actual focus/capture/drag/overlay, close it through Dock, and assert no app action, `DropCancelled`, blur-commit, or synthetic release reaches the action queue. Its React oracle should unmount the real host in the same state and assert no post-unmount action.
4. **Queued layout release:** enqueue a real dirty layout for a window, request close before its lane entry runs, reach terminal, and admit 65 sequential surfaces. This proves the old lane entry cannot consume the fixed scheduler capacity or act on a successor.
5. **External scene completion:** close a document containing Map/Canvas, require every `UiRetiredComponentScene` to be retired through the interpreter outside `UI_ENGINE`, and allow slot removal only after that ledger is empty. This preserves the current external ownership boundary.

## Confidence

High confidence in the capacity cause, generation mismatch, and stranded-root ordering: each follows directly from the cited production code. Medium confidence in the exact event-router data structure: the current unbounded maps prove a missing bounded retirement contract, while the best fixed representation should be selected with the UI document registration owner rather than introduced as a second cache. No runtime result is claimed here.

## Post-Native101 review: external ledgers remain outside the new UI close ladder

This section supersedes the pre-implementation recommendations above where the current source now provides a complete UI-engine close ladder. It is a further read-only audit. I did not run Native101; the two queued-scene/capture laws being red is reported by the task owner.

### Confirmed coverage in the current implementation

`UiDocumentCloseOwner` now carries both the registry token and the globally monotonic document generation. `request_ui_document_close` latches the token before topology removal, and `close_ui_document_one` refuses a changed token or generation before it calls `Ui::close_surface_one` ([`Interpreter/🦀️.rs:323-374`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)). `Ui::close_surface_one` now drains router, layout owners, previews, paint/draw, hit records, document/tree storage and scheduler references before `remove_terminal` ([`engine/🦀️.rs:941-1074`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs)). The registry removes a slot only in `Complete`, and the preserved per-slot token generation rejects an old close after reuse ([`engine/🦀️.rs:607-616`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs)).

The new ordering also retains each `UiRetiredComponentScene` for an outside-`UI_ENGINE` callback before the UI close can advance ([`engine/🦀️.rs:134-153`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs), [`Interpreter/🦀️.rs:345-369`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)). This is the right existing seam for per-component Canvas and Map retirement. It must remain distinct from final document-surface retirement: a normal component replacement can reuse the same owning-document surface and must preserve the successor state.

### Confirmed close-time actions: Canvas capture and catalogue hover

This is a live semantic defect, independent of UI-slot reuse.

`Shell::close_dock_window` latches the UI close, removes Dock topology, then marks every matching Canvas gesture and catalogue hover as `cancellation_requested` ([`Shell/🦀️.rs:16120-16133`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs)). The next `drive_scene_interaction_step` runs `canvas_pointer_terminal_step` first ([`Interpreter/🦀️.rs:1843-1852`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)). For a document Canvas gesture, that calls `cancel_canvas_pointer_gesture_into`, reserves an action, and publishes `canvasPointerUp` with a cancelled wire before it clears the slot ([`Scenes/🦀️.rs:1446-1507`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🎞️Scenes/🎯️targets/🧊️wgpu/🦀️.rs)). The corresponding catalogue path publishes `canvasDragLeave` ([`Scenes/🦀️.rs:1854-1883`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🎞️Scenes/🎯️targets/🧊️wgpu/🦀️.rs)). Pan happens to be local-only, but that does not make the document and hover paths safe.

The smallest coherent repair is a close-only, silent owner retirement API in `Scenes`, keyed by the `UiDocumentCloseOwner`'s `(window_id, document_generation)`. One call removes at most one matching entry from the fixed 16-slot `CANVAS_GESTURE` table or the one matching catalogue hover, and clears only the matching local state/deadline. It must not call either normal cancel function, reserve an `InputState` action, or manufacture a pointer-up/leave. `close_ui_document_one` should run that external unit before allowing the same close owner to reach UI terminal release. Normal pointer cancel remains unchanged because it is an actual browser cancellation, not an unmount.

### Confirmed scene queue and capture retention gap

`scene_pointer_target_is_live` correctly rejects any target whose `(window_id, document_generation)` is in `UI_DOCUMENT_CLOSE_QUEUE` ([`Interpreter/🦀️.rs:578-595`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)). That protects fresh hit lookup. It does not protect an already queued `SceneInteractionIntent`: `process_scene_interaction` validates only tree revision, document generation, node, kind, and surface id, then can execute while the close ladder has not yet removed the tree ([`Interpreter/🦀️.rs:1950-1982`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)).

The queue is a fixed 256-slot ring; an intent may retain an `InkInteractionJob`, whose own `close_step` is already the correct non-publication disposal operation ([`Interpreter/🦀️.rs:390-505`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)). Existing `close_scene_interaction_step` drains the entire global queue shape and has no production close-owner caller. It cannot be used for a document close because it would retire unrelated work.

The same distinction applies to the fixed 16-slot `SCENE_POINTER_OWNERS` ledger. A close makes an old capture non-live, but does not remove it. The next claim opportunistically filters it, so it is not an unbounded leak; it can nevertheless retain all 16 stale slots until another claim arrives ([`Interpreter/🦀️.rs:597-623`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)).

The close owner needs two bounded, exact operations:

1. A scene-intent close cursor that recognizes the exact window and document generation, marks or takes only that intent, and drives its existing `SceneInteractionIntent::close_step` without dispatching it. The live predicate in `process_scene_interaction` must also reject a close-pending owner defensively. The cursor must preserve FIFO order and unrelated intents; it must not call the global queue closer.
2. A pointer-owner close cursor that removes one exact matching capture per opportunity, without calling ordinary `cancel_scene_pointer` or emitting its kind-specific effects. It must be terminal before the document slot becomes reusable.

### Confirmed permanent scene-state capacity leaks

`SCENE_STATE` is an `AdmittedSurfaceMap<SceneSurfaceState>` with a fixed capacity of 256 ([`Scenes/🦀️.rs:26-68`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🎞️Scenes/🎯️targets/🧊️wgpu/🦀️.rs)). Its normal acquisition path is `get_or_insert_with`; its only generic removal primitive is `AdmittedSurfaceMap::remove` ([`Scenes/🦀️.rs:153-166`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🎞️Scenes/🎯️targets/🧊️wgpu/🦀️.rs), [`:220-235`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🎞️Scenes/🎯️targets/🧊️wgpu/🦀️.rs)). No ordinary component or document-close path uses that removal. `retire_canvas_scene_identity` only resets the Canvas owner, click, drag, and deadline; it intentionally leaves the state-map entry resident ([`Scenes/🦀️.rs:1003-1028`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🎞️Scenes/🎯️targets/🧊️wgpu/🦀️.rs)). Map retirement similarly clears only matching Map fields ([`Scenes/🦀️.rs:8040-8065`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🎞️Scenes/🎯️targets/🧊️wgpu/🦀️.rs)).

This becomes reachable after the UI 64-slot repair: a sequence of more than 256 distinct Canvas document surfaces can occupy all scene grants even though every UI window closed. It is not the cause of the prior 65th-window refusal. The `surfaceHostIdentityV1` projection defines the state key as the owning document surface, rather than the authored pane id ([`reconcile/🦀️.rs:461-466`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/🔀️reconcile/🦀️.rs)); that makes document-terminal release the correct boundary and makes component-replacement release incorrect.

The bounded repair should not call `AdmittedSurfaceMap::remove` and drop the whole `SceneSurfaceState` during an arbitrary close step. That value contains owner-bearing and collection fields including scroll offsets, selections, VFS expansion, Ink overrides, marquee values, and edit state ([`Scenes/🦀️.rs:381-413`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🎞️Scenes/🎯️targets/🧊️wgpu/🦀️.rs)). Add a targeted `AdmittedSurfaceMap` take-to-retirement operation and retain one `SceneSurfaceState` close owner. Its close cursor drains one collection/item or scalar per opportunity, then releases the exact map identity. The existing `PendingRasterAuthorityClose` is the appropriate ownership pattern: it removes one map owner, retains it separately, and proves it terminal before it releases its identity ([`Scenes/🦀️.rs:712-844`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🎞️Scenes/🎯️targets/🧊️wgpu/🦀️.rs)). The UI close state needs an external-final-retirement acknowledgement so that this scene close owner finishes before `UiSurfaceRegistry::remove_terminal`; releasing the UI slot first creates a same-id successor race.

Two related retained maps need the same document-closure ownership review:

- `TEXT_EDITOR_UI` is an unbounded `HashMap<String, TextEditorUiState>` keyed by surface id, with insertion/read sites but no removal ([`Scenes/🦀️.rs:9053-9080`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🎞️Scenes/🎯️targets/🧊️wgpu/🦀️.rs)). - `PENDING_RASTER_STATE` is another fixed 256-surface map. ### Focus and clipboard boundary

`FOCUSED_TEXT_EDITOR` stores only `(window_id, node, surface_id)`. Its key handling validates the still-present tree but does not consult the close queue or carry a document generation ([`Interpreter/🦀️.rs:1459-1505`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)). Add generation to this focus record and silently remove the exact focus at close latch; also reject close-pending focus in its live lookup.

Ink focus carries the generation, but its editor and surface lookup likewise only checks engine generation/tree, not the close queue ([`Interpreter/🦀️.rs:1512-1587`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs), [`:1611-1668`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)). `SCENE_LIST_TRANSFER` already has the desired close behavior: `cancel_scene_list_transfer_for_window` takes only the matching transfer and resets only local pointer state, without publishing an action ([`Scenes/🦀️.rs:2077-2095`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🎞️Scenes/🎯️targets/🧊️wgpu/🦀️.rs)). ### Global `Ui::pending_commands` is a separate retained leak

Every synchronous UI dispatch returns commands to the interpreter, which immediately applies them, and then also clones them into global `Ui.pending_commands` ([`Interpreter/🦀️.rs:825-830`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs), [`engine/🦀️.rs:2380-2423`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚙️engine/🦀️.rs)). The interpreter explicitly documents that nothing drains this global vector ([`Interpreter/🦀️.rs:1329-1335`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)). It is neither window-owned nor bounded, so a window close must not indiscriminately drain it: it can contain another surface's commands.

`set_tree_drag_policy` itself only contributes `DropCancelled`; the interpreter intentionally treats that command as a no-op ([`events/🦀️.rs:1245-1264`](../../../../../../../../🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs), [`Interpreter/🦀️.rs:974-1035`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs)). Therefore removing its duplicate retention does not lose a production effect. The clean fix belongs at the presented-command authority: either use returned command vectors exactly once, or retain an explicitly bounded, token-keyed asynchronous queue consumed through the same `apply_ui_commands` path. Do not make close-time clearing the command-consumption mechanism.

### Exact fail-first additions

1. **Silent Canvas unmount:** through the actual Dock close route, arm a document Canvas pointer and catalogue hover, close before release, reach terminal, and assert zero `canvasPointerUp` and `canvasDragLeave` actions, zero matching gesture/hover owners, and no action after same-id re-admission. The React oracle is real host unmount after pointer-down, with no synthetic app action.
2. **Queued intent and capture:** reuse the existing actual Ink-job fixture seam in `Interpreter/🧪️tests/🔬️wgpu-ui-command-wiring/🦀️.rs` (around its in-progress job assertion at line 548). Queue the job/capture, close through the real document queue, and assert terminal removal without action/mutation; then prove an unrelated queued scene intent survives in its original order.
3. **257 Canvas lifetimes:** extend the real Canvas camera mount/first-wheel scenario to `SCENE_SURFACE_CAPACITY + 1` distinct document surfaces. Each iteration must close to terminal before the next mount, preserve the authored first camera, and observe the scene-state resident count return to zero. This is the native counterpart to the existing 65 UI-registry law; it targets a different 256-owner limit.
4. **Focus and native clipboard:** focus TextEditor and Ink, begin a fixed-slot Ink stream or native pending read, close before the next key/completion, then reopen the same id. No key/paste/stream completion may target the old or successor surface, and all matching focus/stream slots must retire silently.
5. **Raster surface:** enqueue one real Canvas raster producer, close its document before upload, drive only its exact retained producer to terminal, and then repeat past 256 surfaces. It must not consume the global realm-close path or another surface's raster owner.

Confidence is high for the Canvas action, queued-intent predicate gap, permanent `SCENE_STATE`/`TEXT_EDITOR_UI` retention, and global command clone leak because each is directly visible in the cited production path. The raster sequence is high-confidence as a retained-map ownership gap; its exact runtime fixture should first verify that the chosen Canvas document reaches the raster admission path.

### Additional confirmed owner: EngineCanvas hosts are only retired at whole-host shutdown

The generic EngineCanvas registry is a separate fixed 256-slot owner. It holds NodeGraph, Map, Board, TextEditor, and Raster hosts and records their document generation ([`EngineCanvas/🦀️.rs:58-190`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/⚙️EngineCanvas/🎯️targets/🧊️wgpu/🦀️.rs)). The current paired coordinator is not a document-close service. `PairedEngineSurfaceClose` scans all 256 CPU/GPU slots and is owned by `OsHost` retirement ([`os-host/🦀️.rs:205-350`](../../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🎯️targets/🧊️wgpu/🏠️os-host/🦀️.rs)). Consequently a sequence of distinct NodeGraph, TiledMap, Board2d, TextEditor, or Raster document surfaces can fill `ENGINE_SURFACE_CAPACITY` even after the UI registry and Shell mirrors report every old window closed. This is a separate confirmed lifecycle gap from Canvas2d's `SCENE_STATE`: Canvas2d does not need an `EngineSurface`, whereas the listed engine kinds do.

Reuse the **per-token** CPU and GPU close operations, not the whole-host `PairedEngineSurfaceClose` scan. The needed document-close external lane is: obtain the exact EngineSurface token while the scene identity is still live; latch its paired CPU/GPU closure; advance one phase in one renderer-owned opportunity; require both `terminal_*_is_empty` witnesses; and acknowledge the `UiDocumentCloseOwner` only then. The existing `ScenePointerTarget` already gives component identity; its canonical owning-document `surface_id` is the lookup key. A production `engine_surface_token_for_id` lookup is needed because the current id-to-token helper is test-only while `engine_surface_token_at` is intentionally a shutdown scan. The lane must live at a level that owns both the runtime `StepContext`/`InputState` and `AppPresenter` GPU context, rather than attempting to invoke the GPU close from `Interpreter` while its UI borrow is open.

Add a native fail-first sequence for `ENGINE_SURFACE_CAPACITY + 1` distinct documents that rotates NodeGraph, Map, Board2d, TextEditor, and Raster where their normal host mounts are available. It must drive the real paired close acknowledgement after every Dock close, assert the 257th host mounts, and assert no closed host receives a pointer/key/queued action. This exercises every existing `EngineSurfaceRetirement` phase rather than only counting Shell mirror maps.
