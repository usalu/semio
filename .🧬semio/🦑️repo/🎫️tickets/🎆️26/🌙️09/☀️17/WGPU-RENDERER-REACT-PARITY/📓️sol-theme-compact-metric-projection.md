# Compact Theme Metric Projection

The coordinator delegated the Rust projection portion of the confirmed customization mismatch, with the media-slot peer owning canonical theme schema/assets and React CSS projection/oracles. `apply_theme_document_metrics` currently reads `metrics.chrome.uiSpacingCompactPx` as the size authority for all chrome and DOM multiples. It does not read `ThemeDocument.spacing.compact`. React sets that authored compact CSS length through its root theme variables. A compact spacing edit therefore changes React sizes while leaving native WGPU sizes at the separate numeric metric.

The Rust projection currently maps eight chrome multiples into `Theme` fields (gap, padding, navbar/footer/header/control sizes, and panel inset), seven DOM multiples (tree row/indent/toggle and panel/rail/engagement limits), one celebration duration, and three direct typography pixel values. Only the spacing base must change in this source slice; the named multipliers continue to come from the canonical document. The peer is establishing the neutral fixture, allowed compact-length grammar, and `metrics.dom.rootRemPx` authority before this packet adds its fail-first native law. No metric production changes or metric passing tests are claimed yet.

The native law `compact_theme_spacing_and_named_metrics_match_neutral_css_pixels` projects all 18 production `Theme` fields from these cases, verifies coverage against the binding contract, and checks invalid grammar plus zero/negative reference roots at import. The law is written; native fail-first execution is pending the current dock/spawned gate.
