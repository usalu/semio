## Layout: source-to-target pointer transport was absent in Layout4; current repair is neutral but needs one real ordering case

Layout4’s physical result—an armed draggable source, zero browser drag events, and only canvas pointer movement—matches Tree’s intentional pointer transport. [Tree/🟦️.tsx](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧱️elements/🌳️Tree/🟦️.tsx:3806) suppresses native drag at pointer-down, begins the encoded payload only after the 6px threshold, and uses window pointer events. Before the current patch, Canvas2d admitted only `DragEvent.dataTransfer`; it could not consume that session.

The current source provides the right renderer-neutral transport, without parsing Layout data in the renderer:

- Tree owns separate native and pointer payload boxes at [Tree/🟦️.tsx](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧱️elements/🌳️Tree/🟦️.tsx:1291), setting both only for the pointer transport and retiring both on its terminal path ([1312](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧱️elements/🌳️Tree/🟦️.tsx:1312)).
- Canvas2d reads only the pointer slot, turns inside moves into `canvasDragOver` with the generic catalogue MIME, clears preview on leave/cancel, and serializes `canvasDragLeave` before raw `canvasDrop` ([Canvas2dHost/🟦️.tsx](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/📐️Canvas2dHost/🟦️.tsx:887), [944](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/📐️Canvas2dHost/🟦️.tsx:944)). It does not inspect JSON or a Layout kind.
- [Canvas2dHost input contract](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/📐️Canvas2dHost/🧪️tests/🖱️input-contract/🟦️.tsx:198) uses the language-neutral [schema](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧬️schema/🛒️canvas-catalogue-pointer-transfer/🔣️.json:1) and covers inside release, outside release, and cancel.

One specific gap remains in that test: it calls `controller.pointerPaletteDrag.begin()` *before* the first target move. In an actual Tree gesture, Canvas’s window `pointermove` listener was registered at host mount, while Tree registers its listener later at pointer-down. The threshold-crossing first move therefore runs Canvas first, sees no pointer payload, then Tree starts it. A user who releases before another move gets `canvasDragLeave` then `canvasDrop`, but no `canvasDragOver` and no preview. Add a mounted Tree-source to Canvas-target law whose sole movement crosses 6px and whose next event is pointer-up. It should require the same terminal sequence as an inside drop: `canvasDragOver`, `canvasDragLeave`, `canvasDrop`. The narrow production alternative is for Canvas’s pointer-up handler to publish the final over before it invokes the existing leave-first drop helper. **Confidence: high**; this follows listener registration order and current code, rather than a hypothetical HTML5-drag concern.
