# Retained Control Clock Integration

The production Interpreter owns `UI_ENGINE: WorkerCell<ui_wgpu::wgpu::Ui>` and uses it for document ingress, reconciliation, layout, paint, and accepted-frame pointer/keyboard dispatch. The absence of a literal `Ui::new` call is not evidence that this engine is unused: WorkerCell initializes its default value.

Repository inspection currently finds no production caller of `Ui::advance_clock`. Its router clock drives stepper hold repeat, slider readout double-click timing, Select typeahead expiry, and tooltip dwell/dismissal. These local laws can pass while the product leaves their clock at zero. The facade also rebases presented interaction only when the tooltip result is non-idle, even though stepper repeat can mutate the tree independently.

The intended integration advances one retained surface per bounded worker opportunity, preserves presented-router authority, and publishes the next timer deadline to the host scheduler. Clock-only advancement must not invalidate every candidate frame. The wall-clock epoch returned by `app_now_ms` must not be cast to f32 seconds; the timer needs a monotonic timebase and an explicit host deadline conversion. The existing Interpreter command application boundary must receive any timer-produced commands. Investigation is in progress, with Sol owning the Ui/EventRouter seam and Astra owning Interpreter/runtime scheduling.

The worker integration now stamps the shared `semio_framework_job::default_now_us` clock before retained pointer, keyboard, and accessibility dispatch, and advances one accepted Shell-owned surface per frame boundary. The accepted input geometry carries the exact retained surface roster. The minimum deadline is published through a replaceable mailbox atomic. The existing frame completion delivers it to the host, which translates remaining microseconds to its own scheduler origin. Missing monotonic clock installation produces no invented timestamp.

`FrameScheduler` now supports generic `DeadlineKey` replacement and cancellation. A repeated publication cannot grow the timer queue, and cancelling a control does not retain its old wake. The neutral JSON/schema contract covers replacement, cancellation, independent owners, late wake, long uptime, and distinct worker/host time origins.
