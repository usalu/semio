## Checked, but not promoted as defects

- **Theme invalidation:** no current source evidence that selected, hovered, highlighted, disabled, provisional, or celebrated WGPU materials cache an old theme. `render_world_3d` reads `ctx.theme` and calls `world3d_style_paint(theme, ...)` for every instance each render (`🌍️world/🦀️.rs:12173-12204`); grid and pick-target overlays also use the current theme in that render. React refreshes its palette through `useCanvasAppearanceSync`. A dark/light runtime pixel probe covering selection, hover, CAD pick target, and grid would be useful regression coverage, but this is not an implementation packet.
- **Camera/template framing and grid:** current source includes the projection/content-frame path and an adaptive grid. No new source-only divergence was established. Test extreme perspective and orthographic bounds once comparable pixels are available; do not turn the old lighter/larger screenshot into a defect claim.
- **Glyphs:** the old broad “three hardcoded VFS kinds” conclusion no longer holds: current `vfs_glyph_icon` first honors schema `file_node_kinds[].icon`. The audit found no confirmed current NodeGraph/list glyph omission suitable for a packet.

## Evidence limits

This audit intentionally used source and current test coverage only. It did not claim visual framing, GPU color-space, or multi-app behavior without new WGPU pixels. The reference finding is an active-document lifecycle defect; it does not duplicate the parallel generation-token close/reopen retirement work.
