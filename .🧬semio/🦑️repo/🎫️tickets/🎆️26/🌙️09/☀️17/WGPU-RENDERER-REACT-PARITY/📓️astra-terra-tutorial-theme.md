# Tutorial Bridge and Theme Editor Audit

Source-only audit, 2026-09-20. This report covers the WGPU shell tutorial bridge and the theme-editor contract in `🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine`. It does not cover Chrome geometry or the driver editor. No production/test files were changed and no build, Cargo, or test command was run.

## Confirmed defects

1. **Tutorial capture drops real selection and tree state.** `🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:19417` always emits an empty `interaction_selection` and `expanded_tree_ids` (`:19440`, `:19447`). React captures the typed per-domain map and its open-tree ids in `🧱️elements/🛠️ShellHelpers/🟦️.tsx:2949-2993`; its recorder diffs both in `🧱️elements/🏛️ShellHost/🟦️.tsx:1092-1108`. WGPU does have an interaction command/output lane: `🧱️elements/🌉️ProgramBridge/🎯️targets/🧊️wgpu/🦀️.rs:137-140` describes the deferred `interactionSelect`/`clearSelection` completion, and the renderer owns `AppInteractionState { shell, input, … }` in `🎯️targets/🧊️wgpu/🧊️renderer/🦀️.rs:11502-11524`. It does not retain a renderer-neutral `DomainSelection` projection there. Its only nearby chrome state is `ShellState.collapsed_sections` (`🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:2847-2853`), where `tree.*` and `section.*` share an inverted collapsed boolean (`:12172-12185`); it is not the `expandedTreeIds` contract.

2. **The WGPU panel map serializes four group homes while React serializes all eight anchors.** WGPU loops `PanelGroup::{Workbench, Details, Display, Settings}` and stores group names at `🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:19420-19425`; apply repeats the same lossy loop at `:19464-19476`. `PanelAnchor::ALL` already defines the eight concrete slots at `:3334-3353`. React loops `ANCHORS`, writes anchor ids, and patches each specific anchor at `🛠️ShellHelpers/🟦️.tsx:2975-2987` and `:3011-3016`. The field's historical name, `activePanelTabByGroup`, therefore conceals an incompatible key vocabulary; it is not merely a missing corner case.

3. **Snapshot apply is one-way for dialogs and the command surface, and the command field is bound to different state.** WGPU clears the dialog stack only when `open_dialog_id` is absent and never restores a requested id (`🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:19477-19479`). It only calls `reveal_dock_tab(FRAMEWORK_CATEGORY_COMMAND_ID)` when `command_panel_open` is true and has no false branch (`:19480-19482`). Its capture equates the field with the bottom-middle Command dock (`:19427`). React captures `state.overlays.searchOpen`; apply restores a requested dialog through `ctx.restoreDialog` and supplies `commandPanelOpen` to the atomic shell snapshot at `🛠️ShellHelpers/🟦️.tsx:2988-3043`. A tutorial recorded in either renderer cannot reliably seek, revert, or sandbox to the other's dialog/command state.

4. **All semantic surface gesture kinds are silently unrenderable in WGPU.** `tutorial_resolve_gesture_point` supports screen, element, and window coordinates, then returns `None` for `Scene`, `Canvas`, `Entity`, `Curve`, and `Domain` at `🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:19496-19527`. The manifest explicitly defines those as live projection/pick contracts at `🔨️modules/🛂️manifest/🦀️.rs:2187-2211`. This is not lack of all projection machinery: the WGPU engine registry already has per-host functions such as graph `pick_targets_at_screen_json` and screen/world conversions, board and raster pick readers, and text `world_to_screen_json` (`🧱️elements/⚙️EngineCanvas/🎯️targets/🧊️wgpu/🦀️.rs:3189-3194`, `:3510-3515`, `:4557-4564`, `:5213-5219`, `:5971-5979`). Those are local helpers with incompatible host-specific data; no reusable surface-to-tutorial resolver is registered with the shell. The present unit test locks the omission in `🐚️Shell/🧪️tests/🔬️wgpu-tutorial/🦀️.rs:135-140`.

5. **The obsolete five-paint custom-theme format remains executable production fallback.** `ChromeColorOverrides` and `CustomChromeTheme` live at `🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:24360-24379`; `resolve_theme_for_ids` still parses and applies them for a `custom.*` id after the canonical document lookup fails (`:24597-24628`). `ThemeDocument::is_document` is used to distinguish that old format on read/import paths (`:25846-25852`, `:26137-26140`, `:26331-26343`). This accepts a WGPU-only theme that React cannot read, contrary to the single-document path. The exact obsolete test-only helpers are `begin_custom_theme_draft`, `set_draft_theme_color`, `save_draft_theme`, `discard_draft_theme`, `hex_to_rgba`, and `apply_chrome_color_overrides` (`:24503-24595`), plus `custom_theme_definition_from` and `custom_theme_definition` (`:24597-24603`). Their tests are `hex_to_rgba_parses_valid_and_falls_back_on_invalid`, `custom_theme_draft_round_trips_and_deletes`, and `discard_draft_theme_clears_in_progress_draft` in `🐚️Shell/🧪️tests/🔬️wgpu-ui-prefs-themes-i18n/🦀️.rs:199-236`.

6. **The canonical WGPU theme editor uses a different navigation model from React.** `ShellState` stores one `theme_editor_open_section` and one page (`🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:3033-3044`); toggling a section replaces the prior open id (`:9513-9520`). `theme_editor_page_rows` exposes only 16 rows and adds previous/next controls (`:26083-26087`, `:26175-26205`). React's tree model supplies independent expandable groups in `🧱️elements/📌️ChromePanels/🟦️.tsx:731-872`; the live React observation in `📓️astra-next-slices.md` found no page controls, a 643 px `overflow-y:auto` viewport, and 1,394 px of Colors content. WGPU also renders Reset enabled unconditionally at `🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:7037-7044`, while React disables it when the current theme is `semio` and no draft is dirty (`📌️ChromePanels/🟦️.tsx:832-845`). The theme document controls themselves are otherwise present: WGPU creates Theme, Name, Save, Reset, Export, Import, and custom-only Delete (`🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:7024-7111`), and its draft path calls `set_active_theme_document` before the next-frame re-tokenisation (`:26130-26173`, `:26294-26343`).

## Implementation boundary

Keep `TutorialUiSnapshot` and `TutorialUiChange` as the neutral grammar. Their core selection, tree-expansion, dialog, and command semantics already exist in `🔨️modules/🛂️manifest/🦀️.rs:2679-2765` and `:3074-3110`; do not add a WGPU-only snapshot shape or replay synthetic pointer input.

Implement one complete WGPU bridge at the `AppInteractionState`/`ShellState` boundary:

- retain the renderer-owned typed interaction projection from normal interaction completions, and restore it through that same state/publication seam; tutorial replay must not fabricate pointer coordinates;
- add a dedicated canonical tree-open map for actual tree nodes and make tree chevrons read/write it. Do not reinterpret the mixed, inverted `collapsed_sections` map;
- capture and apply all `PanelAnchor::ALL` entries by anchor id. Apply directly to the captured anchor's path after normal dock-path reconciliation, rather than globally searching `reveal_dock_tab`;
- route a requested dialog id through the same normal dialog-definition construction used by WGPU chrome, clear when absent, and set/clear the same command-search state that React calls `searchOpen`. Do not continue treating the bottom-middle dock category as this field;
- put one typed `IntroductionPoint` resolver at the engine-surface registry boundary. Each attached surface kind supplies its own live camera/geometry/pick implementation for the semantic kinds it supports; the shell only translates the resulting local pixel through the surface rect. Existing graph, board, raster, editor, and world hosts remain the owners of their projection mathematics. `None` remains valid only for an unknown/detached surface or an absent semantic target, never for an entire point variant.

For themes, delete the old five-paint structs, test-only draft field/helpers, fallback resolver branch, related tests, and all fixtures that serialize that format in the same change. Replace label lookup with a canonical `ThemeDocument` parse used by both selector and resolution. A malformed non-document custom theme is not a supported stored shape; fix owned fixtures/storage inputs directly and provide no migration or compatibility branch. Keep the present `ThemeDocument` draft/save/import/export path and its canonical serializer.

The retained-document limit is a transport constraint, not a user interaction model. Replace the page/exclusive-section state with scroll plus independent tree expansion, while publishing only the visible rows of a virtualized viewport. The scroll range and expanded ids must be stable shell state so a tutorial snapshot can restore them. Preserve React's control ids and reset-disabled predicate.

## Acceptance laws for the implementing packet

1. **Neutral tutorial fixture:** one JSON fixture contains a non-empty two-domain selection, two open tree ids, a known restorable dialog, `commandPanelOpen: false`, and open tabs at all eight anchors. Capture after apply must equal the fixture for both React and WGPU. A second apply after mutating every field proves closure as well as opening.
2. **Delta law:** feed the same fixture through `compose_tutorial_ui` with one selection clear, one tree close, one dialog change, one panel close, and a command open/close pair. React and WGPU must expose the same reconstructed snapshot; WGPU must use its normal interaction/dialog state paths rather than pointer replay.
3. **Gesture resolver matrix:** for every attached supported surface kind, fixture points for `Scene`, `Canvas`, `Entity`, `Curve`, and `Domain` either resolve to an in-rect pixel or identify an intentionally absent target. Pair those results with the React resolver for the same camera/fixture; a known target may not silently disappear.
4. **Theme format law:** save in each renderer, parse the emitted canonical document in the other, and assert the resolved selected chrome paint and one metric agree. No `CustomChromeTheme`, `ChromeColorOverrides`, or legacy draft helper may remain reachable.
5. **Theme interaction law:** at the observed 643 px viewport, expand Colors and verify all its rows are reachable by scrolling without page controls; expand a second section without collapsing Colors. Verify Name/Save, Theme select, Import, Export, Reset (including disabled baseline), Delete, and immediate draft repaint against the same React fixture.

Existing WGPU tests demonstrate partial behavior only: `🐚️Shell/🧪️tests/🔬️wgpu-tutorial/🦀️.rs:68-140` covers two group keys, absence-closing, and screen/window gesture points, while `🐚️Shell/🧪️tests/🎨️wgpu-theme-editor-and-accessibility/🦀️.rs:44-250` validates canonical rows and the current page ceiling. They do not establish the laws above.
