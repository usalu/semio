## Second round (plumbing requested): investigated, NOT implemented
No code was written for the five items below. Each one needs a new cross-crate capability that cannot be added safely without compiling, and a half-wired edit would break the build for every stream. What the read-only investigation found:

1. Live region for Paint2d announcements: the accessibility projection has no live-region concept at all (no `aria-live`/polite role or field anywhere under `🧰️framework`). It needs a new field on the accessibility node contract in `ui_render`, its propagation into the platform adapter, and then `paint2d_keyboard_announcement` (already written) as the source for a Paint2d status node. Owner: ui render accessibility tree.
2. Key repeat: the wgpu shell receives `KeyAction` (no repeat), queued by an input path that is not in the winit host (`🖱️ui/🖥️host/🪟️window` maps `KeyboardInput` to `DispatchEvent::KeyDown{key,modifiers}`, dropping `event.repeat`). Plumbing needs `repeat` added to `DispatchEvent::KeyDown`, `EventModifiers` (two definitions) or a new `KeyAction` carrier, and the browser wire; `PointerModifiers`/`EventModifiers` have ~100 struct-literal sites, so it is a mechanical but wide change. The consumer side is ready: `PixelKeyInput.repeat` and the 8-px stride are implemented and tested; only the shell route hardcodes `repeat: false`.
3. Group alpha: `DrawList`/`DrawLayer` (`🖍️draw/🏷️types`) carry no opacity; a dimmed row needs a per-layer alpha in `DrawLayer`, the UI/vector shaders and pipelines. Not a Rust-only change. The row displacement itself is done.
4. Device loss to scene hosts: `WebGpuBackend` records `LossReason` in `poll_device_lost` and exposes it only through `GraphicsBackend::status/recover`; nothing forwards it to the engine. Needs the presenter (`🎟️prepared/🛡️presentation-gate`, which already has `retain_after_device_loss`) to publish a loss epoch that the shell frame loop turns into `tiled_map_device_lost(surface_id)` for every mounted map surface. Note `semio_ui_wgpu` has no `on_uncaptured_error` hook either.
5. Unavailable notice + Retry: needs `canvasUnavailable` and `retry` labels (en/de strings are in the fixture `🩹️map-recovery`) in `SceneChromeLabels`, a draw path in the TiledMap scene render when `tiled_map_unavailable`, and a Retry hit target whose activation calls `retry_tiled_map` (a scene-local action route; Table/BlockList buttons dispatch guest actions, so a local-effect button route is new).

Run list is unchanged from above; status of all tests: not run.
