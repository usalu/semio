Items 2 and 3 have their own notes (`📓️opus55-wave4-menus-item2.md`, `📓️opus55-wave4-menus-item3.md`); the summary is at the end. Nothing was compiled (build policy); one TS law ran.

## 1. Browser natural-file open (React `openNaturalFile`: select, route, import, keep)

Pipeline now end to end: page drop or pick -> page-held `File` table -> host-io range reads / transport message -> worker -> shell Open File -> `route_picked_file` -> owner activation -> bounded read -> typed `MediaIn` import -> publish. The `refuseOsFileDrop` stopgap is gone.

- Page (`🌐️browser-host`): React's own `installNaturalFileDropV1` (`🏛️ShellHost/🛬️natural-file-drop`) is installed on the host window; each dropped `File` is held by the new `🛬️picked-files` table (token, capacity 64, range reads capped at 1 MiB) and announced with `transport.noteHostFileDrop`.
- Transport: `host-file-drop` message (`BrowserFrameHostFileDrop`, `BrowserFramePickedFile`), frame-worker `receive` -> `semioWgpuHostFileDrop` -> `note_host_file_drop_json` (window-actions lifecycle) -> `take_host_picked_files`.
- Host-io ops: `request-picked-file {accept}` (picker, answers the row or `null`), `read-picked-file {token,start,end}` (base64), `release-picked-file`.
- Shell queue: `OpeningState.dropped_files` (wasm). One deferred Open File action is armed per drain only while no open runs, so several dropped files open one after another like React's sequential loop. The Open File menu item now dispatches on wasm too (`native_file` gate).
- Route: `🧭️natural-route.rs` (both targets) builds the catalog from the mounted editors' natural-file declarations (Open and Save file actions must agree, React `naturalFileFormatV1`) and calls `route_picked_file` (`protocol::io`, already in the wasm graph via `semio-os-kernel`). Refusals use the shared `🏛️ShellHost/📂️picked-file-opening/🔣️.json` vocabulary in the shell's language under React's fault code `shell.openFile.<reason>` (`picked_file_refusal_text/_code`, shared with the native open, which now calls the same function).
- Owner: `resolve_activation_owner_app(dialect, Editor)` (install on demand) from the routed dialect coordinate, as React's `resolveArtifactOpeningWithActivation`.
- Import: bounded read in 256 KiB host-io chunks under the format's command maximum (`naturalFileMaximumBytes`, from the shared `naturalFileMediaInputV1`), `create_app`, `importNaturalFile` (new bridge verb over the new `importAppMedia` on the wgpu plugin handle, the same `MediaIn` React sends), document identity check; progress shows on the open band; cancel stops between chunks and the fresh instance is destroyed (`BrowserOpenedFile::drop`).
- Publish: `finish_browser_open` mirrors the native finish (checkpoint, detach, `install_app_session`, `finish_document_open`, restore the previous session on failure).

### Round 2 (coordinator close-out)

**Keep stage (React `keepArtifactOpeningV1`).** React keeps an imported document in the folder lane `<dataDir>/os/local-documents/<sha256(documentId)>` through the backbone worker, which in the browser is the page's folder transport (`/semio-backbone`). The wgpu browser shell already owns that same transport (`attach_host_route_backbone`: reads or writes the document's archive, binds it, rewrites it on every history change, remembers the folder). `finish_browser_open` now computes React's exact target (`local_document_folder_uri`, SHA-256 through the new host-io op `sha256-hex`, 256-char cap, `no-data-folder` refusal before anything is replaced) and attaches it with `attach_sync_backbone` after the document opens, so the imported document is persisted local-first through the existing event-history flush, and listed through the same remembered-folder config React's catalog lane maps to. A failed attach after the open returns the error (the document stays open and the unload guard protects it); React's full rollback of the attached instance is not reproduced.

**Package and revision sniffing on the browser path.** The product's catalog now reaches the Worker exactly as React's `formatCatalog` port: new boot option `formatCatalog` (`FrameworkOsWgpuBootOptions`, `WgpuBrowserHostOptions`) -> host-io `format-claims` (`wgpuFormatClaimsJson`: claims, owner dialects, every revision's content check, every package claim) -> `BrowserCatalog::from_claims_json` implementing `PickedFileCatalog` with `revisions_of` and `package_of`. The shared `route_picked_file` then runs `pick_revision` and `inspect_package` for browser files. Because the page's file reads are asynchronous and the shared sniff is synchronous, the route reads through `RangeCache` (a `PackageSource`): an unread range answers `None` and is recorded, the task reads the recorded ranges over the range door and routes again (at most 64 rounds), so only the head, tail and central directory the check asks for are read, like React's lazy range reads. Without a host catalog the shell falls back to the formats the mounted editors declare (no sniff claims).

**Text-selection menu for retained inputs.** React gets the browser's native input menu on `Input` and long-text fields; the wgpu twin: `Ui::text_input_at` (read-only query: text, longText and number fields, selection from the edit state), `EventRouter::run_text_selection_verb` (focuses the field, then answers the verb's own chord through the field's edit key route, so rows and typed chords share one body and emit the same `ClipboardCopy/Cut/PasteRequested` commands), `Ui::dispatch_text_selection_verb`, the focus crate's `text_input_selection_at` / `queue_text_input_verb_at` / `take_text_input_verbs`, applied in `drive_scene_interaction_step` through `apply_ui_commands`. The shell's `text_selection_menu_at` opens the same schema-driven menu for a field even when collapsed (Cut and Copy then disabled, Paste and Select all on), as the browser's menu does, and `claim_text_selection_action` falls back to the field when no text editor is under the press.

### Round 3 (coordinator finish)

**React's keep order and rollback (checked).** `keepArtifactOpeningV1` keeps before it publishes: identity, archive, folder-lane write verified, attach, record in the local catalog (`os.config.local-catalog`, `admitLocalDocument`), publish; on any failure it closes the attachment receipt and, once the catalog write was tried, unlists the document (`retireLocalDocument`), and the fresh instance is destroyed by the open flow. The wgpu twin now does the same inside `finish_browser_open`: attach the folder lane (`keep_browser_document`), refuse when the shell is not bound to it, then record the catalog entry; on any failure it detaches the backbone, forgets the remembered folder, unlists the catalog entry, restores the previous session and re-attaches the previous document through its remembered backbone uri (hub, folder or none), and the dropped `BrowserOpenedFile` destroys the fresh instance.

**`os.config.local-catalog`.** React writes one, so wgpu does: `HistoryState::record_local_document` / `unlist_local_document` / `local_document_listed` (`⏪️history/📎️local-folders`) fold the shared `admit_local_document` / `retire_local_document` mutations with `apply_local_catalog_config_mutation` and store the snapshot (`encode_local_catalog_json`) local-only under the shared schema key, next to the local-folders log. Entry: document id, schema, file name, `storage: folder`, the same folder target, surface (plugin, app), admission time.

**Sniffing always on.** `bootFrameworkOsDev` now forwards `formatCatalog` to `bootFrameworkOsWgpu`, and every `s` entry that booted without one (raster, process, wfc, note, shooting, puzzle, fem, draw, and the demonstrator shell) now passes `S_FORMAT_CATALOG_V1` (stdio-pdf and gis already did). Side effect, intended: React's Open file on those variants now routes with the same product catalog. The framework-level dev entry and the embedded-mount tests have no product, so they keep the mounted-editors fallback.

### Round 4 (coordinator last round)

**Local catalog on React's backbone-worker facet.** `🎯️targets/🧊️wgpu/🗂️local-catalog/🟦️.ts` (`createWgpuLocalCatalog`) opens the same `os.config.local-catalog` facet React opens: its own store worker (`🏪️store/👷️worker`), `localCatalogActorConfig` (folder lane under `<dataDir>/os`, `dataDir` from the boot descriptor's hub trio), React's `localCatalogMutationEnvelopeV1` envelopes sent as `localMutations`, and React's `awaitLocalCatalogMutationV1` verified read-back (fresh archive after a persisted status), following `documentArchiveReplaced` and other tabs' `remoteMutations`. Host-io ops `local-catalog-admit` / `local-catalog-retire`; every change is pushed to the Worker (`host-local-catalog` message, `semioWgpuHostLocalCatalog`, `note_host_local_catalog_json`). The browser keep stage and its rollback call these ops (`admit_local_catalog_document`, `retire_local_catalog_document`), so a document kept from wgpu is the same facet event a React shell reads. The prefs-snapshot catalog in `⏪️history` stays only for the native build and laws.

**Where React lists local documents, and the wgpu twin.** The only consumer is `LocalFilesV1` (`🏛️ShellHost/🗂️local-catalog/📂️files`), mounted by the canvas footer in host mode: a section "Files on this device" / "Dateien auf diesem Gerät", one button per kept document that names a surface (newest first, id as tie-break), each reopening it through `openKeptFile`, with "Opening {name}…" status and Cancel. wgpu: `HistoryState.local_files` (fed from the page's snapshot, `local_file_rows_of_json`, same ordering and surface filter), `LocalFilesBandPlan` (`🎛️prefs`, stacked above the folder offer or the history bands via `chrome_band_layout`), the new chrome phase `LocalFilesBand` and `render_local_files_band_step` (one scalar, glyph run or hit per opportunity like the reconnect band, buttons registered on the shell's sync controller as `openKeptFile {documentId}`, none under a modal dialog), the accessible section named by the title, en+de title. `open_kept_file` (wasm) is `openKeptFile`: owner program installed on demand, surface and schema checked against the catalog entry, kept archive read from its folder lane, loaded into a fresh instance whose identity must be the document's own, then published through the same keep/rollback path as an import (not admitted twice); a document already on screen stays.

**Generator for `stdio-format-claims.json` (lane E, do not skip).** Project `@semio-tech/s-dev-composition` (`✏️s/🧑‍💻dev`), target `generate-stdio-format-claims` (executor `repo:script`, cwd `✏️s/🧑‍💻dev`, command `repo ./📜️script.ts stdio-format-claims`; inputs the stdio `artifact-definition.json` files, the editor-catalog fixture and `🔌️plugins/🗄️stdio/📇️registry/🧬️contract/🧭️format-claims/📜️generate.ts`; output `✏️s/🧑‍💻dev/🚀️entry/🧭️format-catalog/🤖️generated/stdio-format-claims.json`).
