# Wave 4: "Files on this device" band equal to React's `LocalFilesV1`

Nothing was compiled (build policy). No TS changed (React is the reference); no TS law run.

## Changes (all under `🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/📥️staging` unless noted)

**Same documents, same order, no limit.** `LOCAL_FILES_BAND_LISTED` (4) is gone. `local_files_band_plan_for` (`🎛️prefs/📎️local-folders`) now lays React's `<ul>`: a title line and one button per kept document, all of them, newest admitted first, id as tie-break, only documents naming a surface (`⏪️history/📎️local-folders`, `sorted_local_file_rows` shared by both stores). Overflow: React's section simply grows; the band cannot grow past the viewport, so it shows the window of whole rows that fits between the navbar and the stacked band below, registers a `ScrollRegion` (`s-local-files.scroll`, offset in the shell's `scroll_offsets`, clamped to the last row each frame) so the wheel moves the first row, and paints a thin scroll thumb. Buttons are not registered while a document open runs (React `disabled={pending !== null}`).

**Host mode gate.** `render_local_files_band_step` and `local_files_accessibility_node` return nothing unless `plugins.host_config().is_some()` (React `hostMode = hostConfig !== undefined`, the footer's `{hostMode && <LocalFilesV1/>}`) and a surface-naming document exists.

**"Opening {name}…" with Cancel, out of the action turn.** New `KeptFileRequest` + `OpeningState::start_kept_file_open` (`📂️doc-open/🎨️.../🗂️kept-open.rs`): a detached, cancellable job on the shell's one document open (`ShellDocumentOpening.kept = true`, own `CancelToken`): read the kept archive (browser: folder door; native: `FolderEventLogStorage` source, cancel between reads), decode, `create_app`, `load_app_document_archive`, identity must be the document's own, cancel checked between every step; an instance created after a cancel is destroyed by the opened-file `Drop`. The result rides the existing pump answers (`BrowserFile` / `NativeFile`), so the open band shows React's text (new vocab key `local-files.opening`, en "Opening {name}…", de "{name} wird geöffnet…", through `document_opening_banner_text`) with the band's Cancel, "Opening cancelled" and failure reasons. `open_kept_file` (now both targets, `🔀️actions/.../📎️sync-attach-and-open`) only looks up the row, keeps an already open document, installs the owner program on demand (own cancellable install band) and starts the job; a busy open is `document.open-busy`. `BrowserOpenedFile.kept_folder` makes `finish_browser_open` publish a reopened document without admitting it again; `NativeOpenedFile` gained `name` and `kept(...)`.

**Native listing on the native local catalog.** `HistoryState.local_files` is now fed natively from the prefs-snapshot catalog (`local_file_rows_of_catalog`, `initial_local_files` at boot, refreshed by `record_local_document` / `unlist_local_document`). The native import (`finish_native_open`) now records the document in that catalog after the folder binding (React's keep step lists it), so natively kept documents appear and reopen. `finish_native_open` was generalised to publish an instance of any installed owner (app resolved from the program's manifest; previous program looked up by plugin id for the rollback re-attach and the destroy), unchanged for the same plugin and app. Moving native onto the facet's own store semantics was not feasible without the store worker, which is a browser page facility; the shared folds (`admit_local_document` / `retire_local_document`, schema key, row shape, order) are the same, and a law pins the two stores to equal listings.

## Laws (Rust, `🧪️tests/🧪️wgpu-local-folders/🦀️.rs`, mounted in `shell-tests-docs-2`)
- `both_stores_list_the_documents_react_lists_in_react_s_order`: page snapshot and native catalog list equal rows; unlist moves the listing.

## Known gaps
- Native reopen reads the archive contiguously (up to the contiguous-reopen maximum); a larger kept archive is refused instead of paged like `restore_folder_archive`.
- Rows scrolled out of the window are not in the keyboard ring or the accessibility tree until the wheel moves them; React's `aria-current` on the open document is not projected per button.
- The band still floats above the subfooter bands rather than inside the footer's layout.
