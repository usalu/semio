# Public WGPU Boot Progress And Cancellation

The public library door and scoped browser host now accept `signal: AbortSignal` and a first-party `onProgress(WgpuBootProgress)` callback. Progress belongs to the pending owned Worker only; stage length and finite 0–1 progress follow the shared lifecycle schema. Callback exceptions are isolated. Retired, aborted and ready mounts stop publishing boot progress.

Each rooted owner has an internal abort controller. A replacement withdraws its previous pending boot immediately, then waits for complete owned Worker retirement before creating another Worker. Aborting a queued replacement waits for prior retirement and allocates no replacement Worker. Pre-aborted requests leave DOM and existing ownership untouched. Aborting after readiness disposes the same owned mount. Existing transport watchdogs bound unresponsive shutdown; cancellation rejection waits for actual retirement, including the parent's descendant-worker closure.

The neutral lifecycle schema/fixture cover before-mount, pending, queued and ready cancellation plus bounded progress. Strict Ajv validates the contract; controlled Workers hold readiness and closure independently to prove rejection waits for a closure acknowledgement. React's independent root/unmount behavior supplies the empty-root oracle. Existing explicit plugin registries, scoped introspection, introduction suppression and repeated-disposal semantics remain exercised in the same suite.

The initial six-law gate genuinely failed five runtime assertions and passed schema validation (`boot-lifecycle-red.log`). After implementation all six passed uncached (`boot-lifecycle-green.log`). A seventh law injects malformed Worker progress through the actual transport, refusing empty/overlong stage and nonfinite/out-of-range values. The complete embedded mount suite then passed 26 of 26 laws uncached (`boot-lifecycle-embedded-all-green.log`), including the parent's existing registry, retirement and introspection laws. These are controlled Worker runtime tests; physical artifact publication and actual renderer acceptance belong to the parent integration gate.

This preserves truthful timing.
