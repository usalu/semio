## Item 1: IconSelect (done in code, synthesized child cells; NOT compiled or run)
Design: `UiNode::IconSelect` keeps its record/node but synthesizes four ledgered composite children in the sync pass (like Select option rows): mode `Select` (`{id}.mode`), mono `longText` `Input` (`{id}.field`), Import `Button` (`{id}.import`, the `importIconFile` shell verb and door from before), Clear `Button` (`{id}.clear`, change action with `value: ""`). Four real tab stops, per-node edit buffers, the real Select popup/keyboard/hit machinery and no stray edit when pressing the frame or preview all follow because the cells are ordinary nodes; the selector itself is no longer focusable, editable or hit-registered and paints only the frame-less preview cell (56 px icon, glyph, or dash).
- Declaration (`UI/📜️declaration/🧩️ui-graph/🎚️slider-stepper-and-control-nodes`): `IconSelectorMode::{ALL, from_id, editor_rows}` (4, or 5 for data/vector), `UiIconSelectNode::migrate_mode` (port of React `migrateIconKindToIconSelectorMode`, exported from the React `IconSelector` so the TS law runs the real function), `UiInputNode::{ICON_MODE_COMMIT, icon_mode, uses_mono_face}` (commit policy `iconMode:<mode>`; no new field, so the ~30 `UiInputNode` literals are untouched).
- Cells: `UI/🌳️retained/🌳️tree/🔀️reconcile/🔽️composite-expansion-rows` (`icon_select_cell`, `icon_select_cell_key`, `icon_select_mode_label`, `select_item_row_committing`, `select_commit_value`). `select_commit_value` is the ONE answer for what choosing a popup item commits (migrated icon for the mode select, item value otherwise); used by the row builder (sync SelectMint/SelectWrite), keyboard commit and the a11y option dispatch. Row keys stay the mode ids (unique) while several rows may commit the same string.
- Sync (`UI/🎯️targets/🧊️wgpu/🖌️paint/🔄️interactive-state-sync`): new phases IconCellScan/Mint/Write (find by key, mint ledgered child, write spec and explicit rect from `layout::icon_select_rows(bounds, rows)`); `sync_interactive_state_node_step` takes `Option<Locale>` (callers: frame-step, frame-into-step-and-frame, tests) so the mode/Import/Clear labels are en+de from `UiIconSelectorLabels`/`UiCommonLabels` (empty with no locale: no default language).
- Survival across republish: composite rows owned by an icon selector, and rows owned by one of its cells (the open mode popup), are exempt from the document reconcile's Compose retirement and re-attached after Mount (`UiTree::is_icon_select_cell_owner`), and `surviving_composite_owner` accepts a cell Select with no record (otherwise every keystroke commit would destroy the editor and its focus).
- Layout: `layout::{icon_select_rows(bounds, rows), icon_select_height(rows), icon_select_editor_height(rows)}` replace `ICON_SELECT_HEIGHT`; node height follows the mode (4.5rem editor, 5.625rem for data/vector). Mounted layout uses it.
- Mono: `RetainedGlyphCursor.mono`, `RetainedWrapProbe.mono`, `EditGeometry.mono` (from `UiInputNode::uses_mono_face`) select `TextFace::Mono` for glyph paint, wrap probe, kerning (`kerning_for`) and run measure (`measure_range_face`), so caret stops, hit mapping and paint agree.
- Removed: IconSelect arms of `is_interactive_kind`/`editable_value`/`edit_commit_action`/`pointer_commit_action`/`MirroredValue::Buffer`/`retained_hit_registration`; the old paint of mode/editor/buttons; icon-select cases of the shared `🎛️retained-control-commit` fixture, its Rust-adjacent TS twin and the `🎚️ring-press` case list.
- Laws added/updated: layout `icon_selector_cells_stack...` (4 and 5 rows) and `the_editor_grows_from_four_rows_to_five...`; shared fixture `🎴️icon-selector-mode` gained `migrate` vectors, run by Rust (`icon_selector_modes_and_encoding_match_the_shared_vectors`) and by the real React function (`🧪️tests/🎴️icon-selector-mode/🟦️.ts`); paint-unit `the_sync_pass_synthesizes_four_ledgered_cells...` (kinds, geometry, en+de labels, re-find without re-mint), `a_locked_selector_disables_every_cell_and_the_mode_rows_commit_the_migrated_icon`, `the_mono_flag_reaches_the_edit_measurement...`, `icon_selector_paints_only_its_preview...`; events-unit `an_icon_selector_has_four_tab_stops...`, `focusing_the_selector_itself_starts_no_edit...`, `the_editor_commit_encodes...and_a_popup_row_commits_the_migrated_icon`.
Honest gaps:
- The cells have no document records: the accessibility mirror still projects the selector as one record (role/label) and does not expose the four cells; React exposes four controls. Needs a11y projection of composite cells.
- React's `mixed` placeholder state, `readOnly` (we disable cells when locked, so they leave the tab order), whole-selector `opacity-60` (cells dim by their own disabled paint) and shared-border-row corner joining are approximated.
- Cell rects are explicit per mode; a textarea's content-driven `textarea_grow` does not grow the selector.
- Existing tests/fixtures that assumed the old single-node IconSelect (hit fixture prose edited; check any other golden that counts hits or glyphs for an IconSelect) may still need adjusting. `HitKind::IconSelect` is now unused.
- Source-boundary risk: the sync file, composite-expansion file and the retained-tree crate grew (about 80, 110 and 25 lines); split if the 4000 active-line check trips.
