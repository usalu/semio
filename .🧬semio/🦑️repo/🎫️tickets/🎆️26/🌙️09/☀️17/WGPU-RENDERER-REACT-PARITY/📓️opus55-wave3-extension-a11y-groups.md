# Wave 3 (opus55): extension hosts, IconSelect accessibility, nested and 3D group opacity

Status: implemented in code; compile and test status in the last section.

## 1. Extension component host bridge
React: `ExtensionView` asks `resolveExtensionHost(id)` (resolvers registered with `registerExtensionHostV1`); the host is a function of the authored props (`ExtensionHostV1`); no host means `Extension unavailable: <id>`.
- Registry (reconcile, `🎞️media-transport-and-node-from-record`): `register_extension_host(id, label, host: Fn(props_json) -> Vec<UiNode>)`, `retire_extension_host`, `extension_host_rows(id, props_json)`, `extension_row_key(id, i)` (thread-local, like React's module registry). `extension_host_status` answers the media transport's own status, else the registered label, so `host_status` stays the one schema field.
- Content route (wave 3b): a host's rows are mounted as ordinary retained children of the slot. Sync pass phases `ExtRowScan/Mint/Write` mint them as ledgered composite rows (same machinery as the IconSelect cells), explicit stacked rects from `layout::extension_row_rect`; `mounted_layout` reserves `extension_rows_height` as `HostContent`; paint skips the slot's own text when rows exist (the children paint, hit-test, focus and edit like any control). A host can therefore render buttons, inputs, selects and text.
- Accessibility: hosted slot is a `status` node named by the label; its rows are projected as virtual nodes keyed by row key (shared builder with IconSelect: combobox + listbox/options while open, textbox, button, text) and activate/edit through `accessibility_cell` in `dispatch_accessibility_event`.
- Program subtree through the lease protocol (wave 3c, closed out in 3d; ProgramBridge `🧩️extension-splice`, new module, backend-neutral): the extension program's own `renderDocument` records are joined to the parent's BEFORE the one `UiDocumentLease::try_publish`; no ingress/page/arena bypass.
  - Pure core: `extension_hosts(nodes, from)`, `shift_record_ids`, `splice_extension_records(nodes, index, child, root)` (refuses without touching the parent: not a childless extension, empty child, root absent, `UI_DOCUMENT_NODES` exceeded) and `splice_extension_documents(nodes, fetch)`, which splices level by level to `EXTENSION_SPLICE_DEPTH = 4` (nested extensions; a self-hosting extension stops at the bound and stays childless; same node ceiling at every level).
  - Registry (`register_extension_program(id, entry, instance)`, `unregister_extension_program`, `set_extension_program_enabled`): holds the program `ProgramBridgeEntry` (browser `Js` or native `Wasm` backend alike); `ProgramBridgeEntry::render_extension_records` is the one non-splicing render of an extension's records on either backend (props arrive as `view.extension_input_json`, as React's host receives `value={props}`).
  - Browser: `render_with_document_js` calls `render_browser_document` (the one `renderDocument` call) then `splice_browser_extensions` on the parsed records. Native: `render_with_document` (kernel `Wasm` backend) publishes the parent lease, then `splice_native_extensions` reads it back (`lease_records`: header + `credited_clone` records), splices, drops the old lease and republishes under the same identity through `try_publish`; a lease naming no hosted extension is returned untouched (no republish). Render effects of the extension join the parent's refresh effects on both backends.
  - Immediate re-render: install already ends in `refresh_ui(Full)`; the uninstall path now unregisters the program and retires its host BEFORE its own `refresh_ui(Full)` (it used to drop the program only afterwards, so that refresh would still have rendered it), enable/disable toggles the program and host before the existing refresh, and a failed load / store refresh drop unregisters. Recovery paths re-register through `load_extension_record`.
- Mounting (reconcile `ui_node_from_record`): an `Extension` record that carries children maps to a plain vertical `UiNode::Stack` around the spliced subtree (React mounts the host in place), so layout, paint, hit-testing, focus and the accessibility projection are the ordinary document paths; a childless one stays the `ExternalSlot` (label / unavailable line / registered row host).
- Shell (`load_extension_record`, refresh retirement, `dispatch-app-switch` uninstall): registers the extension's label as its host (so a slot whose program rendered nothing announces its label) and retires it with the program. The earlier props-to-text-rows renderer was removed.
- Native install door (wave 3e; ProgramBridge `🧰️native-extension-store`, native only; Cargo: `semio-os-extension` added to the program-bridge crate's native dependencies): the native twin of the browser's `semioWgpuHostIo` `extension-store-*` ops and `install_js_extension`. `native_extension_store_answer(request, root)` answers the same requests with the same shapes (`{extensions}`, `{extension}`, `{extensionId}`, `{cancelled}`) over the SAME on-disk layout the TypeScript store's `nativeMaterialize` writes: `<root>/<directoryName>/component.wasm` + `📥️install.json` (same record fields, `moduleUrl` spelled the same) + the `👀️extension-watch.json` marker. Install verifies/unpacks the `.sxt` with `semio_os_extension::unpack` (and its `extends == dependencies[0]` gate), refuses directory/identity collisions and symlinks, caps the package at 64 MiB; `extension-store-install-file` reads the request's `path` (none: `{cancelled:true}`, like a cancelled pick), `install-url` takes `file://` (a remote URL is refused: no package bytes over the network here). `install_native_extension(root, record)` admits the stored `component.wasm` as a bridge entry (`from_wasm`, manifest from the record, identity checked) and calls `register_extension_program`; `retire_native_extension` unregisters. The root is `native_extension_install_root(modules_root)` = beside the plugin modules root (the TS default).
  - Shell: one flow on both backends. `PluginState::extension_store` (browser `extension_store_answer` / native door), `admit_extension_program` (`install_js_extension` / `install_native_extension`); `load_extension_record`, `refresh_extension_store` (now also run at native boot), `install_extension_from_store`, `uninstall_extension` lost their wasm-only gates (native retire = `retire_native_extension`); `installExtensionFile` accepts an optional `path` arg for the native pick. Same records, same enable/disable, same host/label registration, same `push_contributions` + `refresh_ui(Full)`.
  - Native republish, generation-safe by construction: `splice_native_extensions` publishes the successor through `UiDocumentLease::try_publish` BEFORE releasing the predecessor, with the predecessor's identity (it never left the function, so the engine's monotonic ingress check sees one document of that generation and the kernel's next render stays newer); a refused successor returns the predecessor untouched (a failed splice costs the subtree, never the render).
- Live kernel activation (wave 3f; schema-first change in the kernel protocol): `KernelRequest::ActivateExtension { owner: CreateAppRequestOwner, activation: ExtensionActivation }` with the wire schema `ExtensionActivation { parent_instance, parent_plugin, extension: ExtensionRecord }` (kernel-core, re-exported by the kernel-protocol crate; `ExtensionRecord::installed(id)` builds a runtime-installed identity; `ExtensionRecord` is the registry record the startup cascade already used). The extension's wasm rides the request's own `CreateAppRequestOwner`, so it uses the same bounded, cancellable compile intake as every program. Answered as `KernelOutcome::Created(instance)`, the extension's OWN instance id.
  - Kernel (`KernelPoolState::activate_extension_live`, app-lifecycle file): resolves the live parent actor and REFUSES one that is no instance of the declared host plugin (`ActorKind::PluginApp.plugin == parent_plugin`), refuses an already-live extension id (`live_extensions`), compiles, activates as `ActorKind::Extension` on the background lane with capabilities scoped to the parent's grants, links it to the parent (closing the parent still cascades) and registers an instance id (for its close and replay route only). `destroy_app_step` forgets `live_extensions` on close and, when a parent's close cascades, drops the removed actors' instance entries. NO `InstanceOpen` is sent (see the verification below).
  - Protocol plumbing: `KernelRequest` variant, `kernel_request_interleavable` (true, like a new app), `command_credits` (0,0), the shutdown drain (same arm as `CreateApp`: the owner closes), `cancellable`, the pool runner arm, and `KernelClient::activate_extension(wasm_path, activation)`. Retirement is the ordinary `begin_destroy_app(instance)`.
  - Bridge: a native extension registers with `register_extension_program_extending(id, entry, None, Some(extends_host), capabilities)`; at its first render by an instance of the declared host the splice activates it (`ProgramBridgeEntry::activate_extension_instance`) and keeps the returned instance; a failed render re-activates (the kernel refuses while it is still live, so the stored instance and its retirement survive; after a parent re-creation it succeeds with a new id). `unregister_extension_program` begins the instance's retirement (`begin_retire_extension_instance`, handles polled to completion by later registry calls). The browser path is unchanged.
- Verification of the three assumptions against the browser/TS runtime (wave 3g) and the native alignment:
  1. Capability requests. The web `ActivationRegistry.activateExtensionsOf` honours the extension manifest's `caps` and grants only `intersectCapabilityGrants(parent caps, extension caps)` (the Rust `intersect_capabilities` twin), looking the manifest up fresh at activation. Aligned: the package manifest's `capabilities` are now kept (native store writes `🔐️capabilities.json` beside `📥️install.json`; the shared install record has no field, so a TS-written install has none), registered with the program and passed as `ExtensionRecord::installed(id, caps)` (unscoped requests), then scoped to the host's grants by the same intersection in `activate_extension_live`. Browser gap found, not changed here: the browser's DYNAMIC install door (`loadPluginModule` + request actor `${pluginId}#request`) activates with the extension's own manifest caps without intersecting the host's.
  2. `InstanceOpen`. Not sent in the browser: "an extension program declares no app, so it never gets a `createApp` instance and `Event::Request` needs none" (`createRequestActor`), and the cascade children only receive the `on-extension-request:<parent>` activation event. Aligned: the native live activation no longer sends `InstanceOpen` or runs a turn (as the native startup cascade never did).
  3. Host instance. The web registry keys extensions by their DECLARED parent (`extensionsByParent`, `dependsOn[0]` == `extends`) and activates them alongside the parent's `activate`. Aligned: `ExtensionActivation.parent_plugin` is the declared host and the kernel refuses a parent instance of any other plugin; the bridge retries at the next render by a real host instance (so "first naming" no longer decides).
  - Consequence to record plainly: the browser runtime treats a dynamic extension as a CAPABILITY HANDLER (`Effect::InvokeExtension` to `dispatchInvokeExtension(originInstance, extensionId, capability, request)`), not as a renderer of a subtree for `Component::Extension`; React's `ExtensionView` resolves only registered hosts. So the program-rendered subtree splice (waves 3c-3f) is plumbing the browser does not exercise: an extension that declares no app has no instance for `renderDocument` and the splice yields no subtree there, and natively (no `InstanceOpen`) likewise. It becomes live only for an extension program that declares an app and window kind. The registered-host route (label and rows) and the invoke path are the browser-parity behaviours.
- Remaining gaps: a native file-pick UI is still the `path` seam; the browser dynamic-install intersection gap above; native `Effect::InvokeExtension` dispatch to a live-activated extension is not wired (the browser's `dispatchInvokeExtension` has no native `ProgramBridgeEntry` twin).

## 2. IconSelect accessibility
- Projection (`♿️accessibility`): `cell_accessibility_nodes` projects the four synthesized cells (`<id>.mode` combobox, `.field` multiline textbox, `.import` and `.clear` buttons) after the selector; fields fall back to the selector's own label (React's `aria-labelledby`); rect, focus, disabled, tab stops from the arena cells.
- Open mode select (wave 3b): while the mode cell is open it also projects `<cell>::listbox` and one `<cell>::option::<mode>` `option` per mode (selected flag, value text), like React's `SelectContent`; `accessibility_cell` resolves an option key to (cell, value) only while the cell is open and the value is one of its items, and dispatch routes it to `dispatch_accessibility_select_option` (the same path that commits the migrated icon for the real popup).

## 3. Group opacity
- Nesting up to `GROUP_ALPHA_DEPTH = 4`: `DrawList.group_stack`, `GroupAlpha.depth`; a layer after an inner group carries the parent group; inner bounds are clipped by the parent. Prepared stepping: `GroupEnd(layer, count)` closes every group the next layer is not inside, innermost first. Executor: a pool of offscreen targets per level, `group_open` stack; an inner group composites onto its parent's target, the outermost onto the composite.
- 3D scene passes: scene-clear, backdrop snapshot, instance/material/textured/grid/line/point draws and postprocess render into the open group's target (new `world_encoded_view` on `PreparedGroupTarget`, `COPY_SRC` usage; the scratch copies read the group texture), so a scene faded with its group.
- No shader change; naga/shader-contract tests untouched.
- Tests: `group-alpha-tests` (nesting back to the parent, depth cap), prepared-unit (`nested_group_alpha_groups_close_innermost_first...`, existing bracket test updated for `GroupEnd(layer, n)`).
- Alpha (wave 3b): the world pipelines blend with `ALPHA_BLENDING`, which onto a transparent premultiplied target already yields premultiplied colour and coverage (`rgb*a`, `a`), so translucent draws needed no change; the one straight-alpha write was the authored scene clear colour, now premultiplied when it lands in a group target. Opaque `REPLACE` pipelines are expected to emit alpha 1 (not audited shader by shader).
- Gaps: glass inside a group still blurs the main composite snapshot; no GPU pixel test (needs an adapter).
