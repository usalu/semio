# Terra Controls Final Audit

Read-only source audit of the currently mounted Puzzle3D Settings surface, Shell General and Drivers. This report excludes the already-tracked command-palette, Tree scroll/hit-routing, and raster packets. No test, build, activation, production edit, or Git operation was run.

## P0 — Accessibility focus does not arm the retained keyboard route

The browser accessibility mirror sends `accessibility-focus` when one of its focusable projected controls receives DOM focus ([accessibility mirror:109-111](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🎯️targets/🧊️wgpu/♿️accessibility-mirror/🟦️.ts:109)). Shell converts that event and calls `dispatch_accessibility_event`, then returns only its boolean result ([Shell:13188-13195](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:13188)). The interpreter dispatcher obtains a `Vec<UiCommand>` containing the router result, applies actions, and discards that vector ([Interpreter:575-582](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🎯️targets/🧊️wgpu/🦀️.rs:575)).

`ShellChromeBuildState.content_focus` is only changed by `note_content_focus_commands` when it receives a `UiCommand::FocusChanged` ([Shell:12163-12181](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:12163)). Pointer and ordinary retained-key dispatch retain that vector and call the method ([Shell:12901-12905](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:12901), [Shell:15310-15319](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:15310)); the accessibility path does neither. Later browser keys are converted to `KeyAction` and reach `ShellState::handle_keyboard_async` ([Winit host:345-375](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🎯️targets/🧊️wgpu/🪟️winit-app/🦀️.rs:345)), whose sole retained-key route is gated on that missing `content_has_focus` entry ([Shell:15310-15321](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:15310)).

Consequently, tabbing or assistive-technology focus into a WGPU General or Driver Select can establish router focus but leaves subsequent Arrow, Enter, Escape, Tab, Space, and typeahead keys outside the retained router. This reaches the six General selects authored at [Shell:7783-7841](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:7783) and the Driver axis selects authored at [Shell:7677-7686](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:7677). React's Select trigger owns its DOM focus and routes `onKeyDown` directly ([Select:347-414](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧱️elements/🔽️Select/🟦️.tsx:347)).

**Repair boundary:** have the Shell accessibility path preserve and consume `FocusChanged` exactly as the retained pointer/key paths do, including active-window ownership where applicable. A direct `AccessibilityEvent::Focus` followed by an ArrowDown/Enter Select sequence must prove a visible General/Driver value consequence.

**Confidence: high.** The event and command paths are complete, including the missing `FocusChanged` consumption point.

## P1 — Space cannot reach a focused retained Select

Even after focus is armed through a canvas pointer path, `KeyAction::Space(_)` is dropped by the host mapper ([Shell:12189-12213](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:12189)). The browser host additionally intercepts `KeyAction::Space` before Shell routing and only stores `space_pressed` unless a context menu is open ([renderer:15450-15463](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🎯️targets/🧊️wgpu/🧊️renderer/🦀️.rs:15450)).

That conflicts with the retained Select state machine, which explicitly opens a closed Select and commits an open Select on key `" "` ([WGPU Select:335-386](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧱️elements/🔽️Select/🎯️targets/🧊️wgpu/🦀️.rs:335)). The browser wire deliberately admits Space for a focused combobox and suppresses its native default ([input wire:58-73](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🎯️targets/🧊️wgpu/🎮️input-wire/🟦️.ts:58)), so the missing route cannot be recovered by the DOM. React explicitly opens its Select on Space ([React Select:395-410](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧱️elements/🔽️Select/🟦️.tsx:395)).

**Repair boundary:** keep the context-menu hold behavior but feed a press edge as `UiEvent::KeyDown { key: " " }` when retained content owns focus. Verify closed-open and open-commit Space sequences on `framework.settings.appearance` and one Driver-axis Select.

**Confidence: high.** The key is explicitly accepted by both Select implementations and explicitly discarded by the only host route.

## P1 — Printable Select typeahead is converted into text editing, not Select keyboard input

Plain `KeyAction::Char` becomes `UiEvent::TextInput`, rather than `UiEvent::KeyDown`, in the Shell mapper ([Shell:12192-12208](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:12192)). `EventRouter` calls `route_select_key` only from the `KeyDown` arm; `TextInput` goes solely to `route_text_insert` ([Event router:2002-2038](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs:2002)). `route_select_key` otherwise contains the complete live typeahead state machine ([Event router:2111-2178](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs:2111)).

The browser input wire does not early-return for a non-editable combobox, so printable keys are sent down precisely this failing route ([input wire:58-73](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🎯️targets/🧊️wgpu/🎮️input-wire/🟦️.ts:58)). React sends a single printable `onKeyDown` to `openWith({ typeahead: event.key })` ([React Select:395-410](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧱️elements/🔽️Select/🟦️.tsx:395)). Thus typing `d` on a focused General Driver Select cannot open/highlight its matching option in WGPU even though the retained Select code implements that behavior.

**Repair boundary:** select the host event kind from the focused retained node: printable characters on `UiNode::Select` must arrive as `KeyDown`; editable Inputs remain `TextInput`. Add an end-to-end host-to-router law for a printable General/Driver option, not just the direct `select_key` unit law.

**Confidence: high.** The host mapping and router split are explicit; the event reaches no Select branch after conversion.

## P1 — Driver Save Label commits every accessibility input event despite `commit: "blur"`

The actual Driver editor declares `framework.settings.driver.saveLabel` as a text input with `commit: Some("blur")` and binds it to `setDriverSaveLabel` ([Shell:7688-7708](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:7688)). The browser accessibility mirror sends every native input edit as `accessibility-value` ([accessibility mirror:116-119](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🎯️targets/🧊️wgpu/♿️accessibility-mirror/🟦️.ts:116)). `AccessibilityUiEvent::Value` stores the draft then immediately calls `edit_commit_action`, with no `commits_on_blur` branch ([Event router:1790-1808](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs:1790)). That action updates the live Driver save label ([Shell:10045-10050](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🎯️targets/🧊️wgpu/🦀️.rs:10045)).

The ordinary retained edit path has the correct distinction: it suppresses per-keystroke commands for blur-committing inputs ([Event router:1518-1543](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs:1518)) and `FocusState::set_focus` commits the previous draft on actual blur ([Event router:361-403](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs:361)). React does the same: `onChange` only updates `draft`, while `onBlur` invokes `commitValue` ([React Interpreter:1216-1272](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🟦️.tsx:1216)).

**Repair boundary:** `AccessibilityUiEvent::Value` must stage a `commit: "blur"` Input without emitting `edit_commit_action`; focus transfer already supplies the existing commit boundary. Exercise keyboard entry through the browser accessibility input, assert no `setDriverSaveLabel` action before blur, then exactly one action containing the completed value after focus moves.

**Confidence: high.** The live control, mirror event, immediate action, and React’s different staging boundary are all direct source facts.

## P1 — Puzzle3D Settings steppers commit on release, so an aborted/outside gesture loses React’s increment

The current Puzzle3D app Settings document has four mounted `numberStepper` controls, each bound through `change`: Contact tolerance, Proximity Radius, Chunk Size, and Spacing ([Puzzle3D Settings fixture:31-99](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧪️fixtures/⚙️puzzle3d-settings-document/🔣️.json:31)). React renders these through `Stepper` with `onChange` ([React Interpreter:1339-1356](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🟦️.tsx:1339)); the plus/minus handlers run `applyDelta` during `onMouseDown`/`onTouchStart` ([React Stepper:138-160](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧱️elements/🪜️Stepper/🟦️.tsx:138), [React Stepper:195-271](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧱️elements/🪜️Stepper/🟦️.tsx:195)). Leaving the button stops the continuous gesture after that first update ([React Stepper:172-180](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🧱️elements/🪜️Stepper/🟦️.tsx:172)).

WGPU captures the press but invokes `pointer_commit` for a `NumberStepper` only on `PointerUp`, only when that release still hit the captured control ([Event router:1921-1961](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/⚡️events/🦀️.rs:1921)). A press followed by a release outside therefore sends no Settings action, while React has already changed the setting. Browser WGPU also binds and serializes only move/down/up; it has no `pointercancel` listener or wire variant ([browser boot:198-205](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🎯️targets/🧊️wgpu/🚀️browser-boot/🟦️.ts:198), [frame transport:113-140](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🎯️targets/🧊️wgpu/🚚️browser-frame-transport/🟦️.ts:113)), leaving the WGPU press capture active until a later unrelated release.

**Repair boundary:** preserve React’s first step at press for a NumberStepper segment, then send an explicit cancel/release cleanup event that drops capture and active paint without a duplicate increment. Test the live Puzzle3D Contact tolerance control with press → leave/release-outside and press → `pointercancel`; both need the same observable React-compatible action count and no retained active/capture state.

**Confidence: high.** The current Puzzle3D document identifies the live controls, and the React/WGPU trigger moments are direct code paths.
