# Spawned Document Routing

The literal `spawned` dock surface is rendered from the focused `SpawnedAppEntry`'s plugin and instance, but its retained paint currently uses the active host session's controller. Action dispatch then selects a plugin by controller while constructing the host session's app address and instance number. The command path explicitly rejects the spawned owner's plugin. The generic live-view projection also replaces the spawned window roster with the host dock roster. Together these routes prevent a rendered spawned app from receiving its own interactions.

The routing repair will retain an `ActiveSession` beside the exact spawned document, bind its controller in dock painting, select its plugin/app/instance for window-addressed actions and owner-addressed commands, preserve its live window roster, and keep spawned view mutations out of the host panel state. The media-slot owner will reuse this retained session for its independent trusted parent-document registry. No media registry fields or candidate geometry are edited by this packet.
