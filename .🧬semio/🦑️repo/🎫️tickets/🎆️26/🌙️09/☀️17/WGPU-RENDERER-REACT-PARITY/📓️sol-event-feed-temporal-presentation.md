# EventFeed Temporal Presentation

EventFeed keeps its domain timestamp as epoch milliseconds and delegates presentation to the host. The neutral `event-feed-time-format` contract carries a locale, time zone, hour cycle and monotonic `profileRevision`; its fixtures cover UTC, Europe/Berlin and America/New_York across winter, summer, DST boundaries and invalid dates. The TypeScript implementation uses the browser's installed `Date`/`Intl` behavior and strictly rejects partial, duplicate or mismatched replies. The Rust twin validates the same bounded request/reply grammar without adding a runtime dependency.

The browser host IO now accepts `format-event-feed-times`, owns the resolved profile signature and revision, and formats the batch through page Intl. WGPU EventFeed stores pending and candidate temporal generations separately from accepted labels. Only frame acknowledgement publishes a candidate; discarded frames do not advance presentation, and a reply from an older profile revision cannot replace the accepted labels. Native hosts receive the same boundary through `NativeEventFeedTimeFormatter`; no UTC fallback is presented as locale parity.

Architect's authored Trace window is now a real EventFeed producer. It projects the persisted audit trail into EventFeed scene rows and strictly converts UTC RFC3339 timestamps to epoch milliseconds. Its sample program and demo DSL contain a concrete audit event, so playground registration reaches the actual surface route without browser-state injection.
