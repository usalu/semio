# Wave 4 (opus55): dynamic-install capability scoping, native extension invoke

Status: TS change and law ran green; all Rust is uncompiled (no cargo; lane E compiles).

## 1. Security: host ∩ requested on every activation path
Finding (differs from the wave-3g note): no browser path passes the extension's manifest caps today (every `registerManifest` seeds `caps: []`), but `ActivationRegistry.activate` / `resume` handed `manifest.caps` to the shard VERBATIM, and only the startup cascade (`activateExtensionsOf`) intersected. A dynamic install (`loadPluginModule` -> request actor `<id>#request`, which is `activate(extensionId, ...)`) therefore had no host scoping the moment its manifest carried caps. Fixed at the root.
- `ActivationRegistry.grantsFor(pluginId)` (kernel `🎛️activation-registry`) is the ONE source of an actor's grants: the program's own request intersected (`intersectCapabilityGrants`) with every host it extends (new `ActivationManifestEntry.host`, or an indexed parent from `registerCatalog`/`registerExtension`), recursively; an unknown host or a cycle grants nothing (fail closed). `activate`, `resume` and the cascade child all call it (three call sites, no other `manifest.caps` read).
- Dynamic install wiring: `loadPluginModule(..., host?)` -> `acquirePluginDescriptor` registers `host`; the frame-worker's `semioWgpuInstallExtension` passes `record.extends`.
- Law (`kernel/🧪️tests/🧪️createturnoutcomebroadcast`, "law: an extension never exceeds its host's grants on any activation path"): dynamic install with declared host holds host ∩ requested; cascade, catalog-indexed direct activation and resume scope identically; unknown host / cycle grant nothing while a plain plugin keeps its own; nested extensions are capped by the whole chain.
- Ran: that file (52 pass), `🎬️wasm-plugin-install` (11 pass), `📦️package-assets` (9 pass).

## 2. Native `dispatch_invoke_extension`
Browser semantics mirrored (see `📞️extension-and-request-actors`): extension missing / not the requester's host -> `extension.invoke-unavailable` (message = code, scope plugin+instance); empty capability -> `extension.invoke-failed` ("extension.capability-required"); request > 65 536 B -> `extension.request-too-large` (scope plugin only); answer > 8 MiB -> `extension.answer-too-large`; undecodable fault -> `extension.answer-not-a-fault`; no answer -> `extension.request-unanswered`; JSON answer re-encoded as pack, the extension's own typed fault passed through; EVERY outcome completes the requester exactly once (never an `Err` for a refusal).
- Pure (ProgramBridge `🔀️extension-invoke`, both targets): `route_extension_invoke(target, requester_plugin, instance, extension_id, capability, bytes) -> Result<ExtensionRoute{Live|ActivateBeside}, Fault>`, `settle_extension_answer(answer, ...) -> Result<json, Fault>`, `ExtensionAnswer`, `extension_fault`, the two ceilings (from `semio-framework-trace`, now a normal dependency of the crate).
- Native transport: `ProgramBridgeEntry::dispatch_invoke_extension` (native twin of the wasm32 one, same signature) -> `dispatch_native`: route, activate beside the requester through `activate_extension_instance` when the extension has no live instance (retry once after a failed exchange, as the render path re-activates), `answer_extension_request` (one `Event::Request` from the requester's shell instance, the extension's inline `Effect::Respond` read out of the same exchange; the reactor answers on the same turn), settle, then `complete_extension_request` (one `Event::Completed` to the requester; answers an empty `InvocationResult` carrying that turn's effects, like `emptyInvocation`).
- Kernel (schema-first for the queue): `QueuedKernelEvent` admits two more single events through `exchange_events`: `Event::Request` from a shell endpoint and `Event::Completed` (kind `Call`, field `call: Option<(u64, QueuedCallRole)>`; capability rides `message_endpoint`, bytes `message_payload`, so the byte credits and the shutdown drain are the existing ones; the origin instance id string is the only uncredited, <=10 B).
- Registry helpers (`🧩️extension-splice`): `extension_invoke_target(id)`, `remember_extension_instance(id, instance)`.
- Law (`ProgramBridge/🧪️tests/🔀️extension-invoke`, pure, reads the shared `🔣️extension-invocation.json` for the unavailable code): unavailable for none / foreign host / hostless-instanceless; Live vs ActivateBeside; capability and ceiling refusals incl. exact boundary; settle table; typed fault unchanged.
