# Retained Window Close Review

Native96 reproduced a delayed Canvas camera publication after the actual Dock window and shell document lease had closed. Native97 is checking the initial bounded close repair. Source review of that candidate identified three additional lifecycle cases that require regression coverage before acceptance.

1. `Ui::surface_generation` is the accessibility mount generation. Publication increments it only when the retained tree has no document. Reopening the same window before a queued close takes the prior document can therefore reuse the old generation; a queue fenced only by that value can retire the new document. The test must publish the successor before draining the old close, and prove its target, camera and document survive.
2. The first candidate removed the Dock window before close-queue admission, then only logged a refused admission. A full queue must retain ownership or refuse before removing the window; it cannot report a successful close while leaving the old document unretired. Mode/layout and panel removals through `retire_documents_outside` also need the same retirement lane.
3. Advancing one close unit in the Chrome CloseDocument phase and immediately moving on paints an entire frame per retired node. The bounded close owner should advance per runnable work turn or remain in its phase until terminal, so a large document does not require thousands of complete frames to retire. Runtime wake ownership must persist until that work terminates.

Sol owns these tests and implementation. Root has not inferred a GREEN result from the new queue source.

The reviewed repair now admits close before Dock mutation after verifying membership, admits generic window/panel removal before releasing the shell lease, holds the Chrome close phase for one retirement unit per work opportunity, and blocks same-id successor ingress until the old close is terminal. Root replaced the membership check's collected/cloned window-id vector with the existing borrowed `window_kind_id` lookup; it preserves membership semantics without materializing all ids. The immediate post-close camera sweep, before any explicit refresh/drain, is included in the pending Native98 verification.

A separate repeated-window capacity concern remains: `UiSurfaceRegistry::try_admit` uses only empty optional slots, while document close leaves the `UiSurfaceSlot` allocated. The registry currently has no slot-release method. Likewise Canvas scene retirement clears camera ownership but retains its scene-state entry. More than64 sequential distinct mounted/closed window ids needs a real regression test and a bounded full-surface retirement path, including pending layout/paint owners. This source finding is not yet a runtime failure receipt and does not block collecting the next browser liveness checkpoint.

The input-presentation repair has an analogous authority requirement: a control moved in an unpublished candidate must still route from its old displayed rectangle until acceptance. Validating the old node identity and then hit-testing the candidate tree would only suppress or misroute that event. The presenter regression must include an unchanged-key moved control and a candidate overlap with the old rectangle, alongside pending/accept/abort paths.
