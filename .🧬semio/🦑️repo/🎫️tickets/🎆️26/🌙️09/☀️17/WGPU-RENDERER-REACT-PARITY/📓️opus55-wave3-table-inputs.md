## 1. Table (verified against React first)

- React's two table types:
  - `UI/🧱️elements/📊️Table` (generic `Table`, used by the OS `TableHost` and `VirtualFileSystem`): renders `ContextMenuTriggerButton` (`ui.contextMenu.more`, en "More", de "Mehr", glyph `⋯`, `size-6`, `ml-auto`) in the LAST cell of every row whenever `onRowContextMenu` is passed. `TableHost` always passes it. Click dispatches the same `contextmenu` event at `contextMenuAnchorPointV1(row box)` = `x = max(left, right - 4)`, `y = min(bottom, top + 24)`, and stops propagation (no row select).
  - The document `TableView` (`tree-windows`) has no menu trigger and no menu at all (unchanged from `📓️opus55-fix-table.md`): nothing was invented there.
- Drag activation: React has NO delay for any table. `dragDrop.pointerActivationDelayMs` is declared but no caller sets it (grep over the framework: only the declaration and the sensor). The dnd-kit `PointerSensor` default is `distance: 8`, `tolerance: 5` only when a delay is set; `TableHost` passes no `dragDrop` and uses native HTML5 row drag (`rowDragProps`), whose threshold is the browser's. So no delay or threshold was added to the wgpu surface table; the engine's existing press-drag threshold stays the single authority.
- Implemented on the OS surface table (`OS/🎞️Scenes/🎯️targets/🧊️wgpu/🧮️table-and-paint2d`):
  - Shared model (`W/📊️table-model`): `TABLE_ROW_MENU_TRIGGER_PX = 24`, `table_row_height` (rows grow to hold the 24 px trigger, as the `<tr>` does), `table_row_menu_trigger`, `table_row_menu_anchor`.
  - Paint: `⋯` in the last cell, hit target `{host}.row.{id}.menu`, last column text narrowed by the trigger width; accessibility: one button cell per visible row named `ui.contextMenu.more` (new `TableChromeLabels.row_menu`, en/de in `📖️shell-vocab`), activatable through the existing table-button activate path.
  - Press: `table_hit` answers the trigger with the framework verb `openRowContextMenu {x, y}` (anchor, surface-local) instead of the row action (React `stopPropagation`).
  - Shell: `framework_open_row_context_menu` stores `ShellInputState.pending_row_menu`; `route_retained_pointer_press` (pointer context, which owns `open_context_menu`) opens the SAME menu a right-click on that row opens, at body origin + anchor.

## 2. Input kinds

- Contract: `InputKind { Text, LongText, Number, Date, Color, File }` (`UI/🧬️contract/🧩️component/🎛️container-roles-and-row-actions`). React (`OS/🗣️Interpreter/✍️input-views`): `<input type="date|color|file">`, native pickers.
  - date: value `YYYY-MM-DD` or `""`, commits on `change` (or blur policy).
  - color: continuous kind: each change is offered on the trigger lane, the picker release commits; value `#rrggbb` lower case.
  - file: no value; `change` commits `files[0].name` (a NAME, not contents); `accept` is passed through.
- Shared models and vectors (new, `W/📅️date-picker-model`, `W/🎨️colour-picker-model`, exported as `semio_ui_wgpu_layout::{date_picker, colour_picker}`):
  - date: `CivilDate` (ISO parse/format, epoch day, weekday, day/month arithmetic), `date_locale("en"|"de")` (week start Sunday/Monday, `MM/DD/YYYY` / `DD.MM.YYYY`, month names, weekday headers; unknown locale = `None`, no default language), 42-cell `month_grid`, `date_key` (arrows, Page, Shift+Page, Home/End, Enter/Space, Escape), `date_popup_layout` (below the field, flips above, mirrors for rtl).
  - colour: `colour_value` (DOM normalisation via the contract's `parse_ui_color_hex`/`ui_color_hex`), channels, `colour_apply_field` (hex/R/G/B drafts), 16-swatch palette + `swatch_key`, `colour_popup_layout`.
  - Vectors `UI/🧪️tests/🧫️fixtures/📅️picker-models/🔣️.json` were GENERATED by the browser's own `Intl`/`Date` (en-US, de-DE) and `contextMenuAnchorPointV1`; Rust law `UI/🧪️tests/📅️picker-models/🦀️.rs` (registered in the layout companion), TS law `…/🟦️.ts` re-derives them from `Intl`/`Date`.
- Wired into the live path:
  - file: `UiInputNode::pick_file_action` (`framework.pickInputFile` wrapping the change action and `accept`); the pointer release on a `file` input fires it (events `PointerUp`); the input no longer owns an edit buffer (`editable_value` = `None`); shell `framework_pick_input_file` opens the host door (native `select_native_paths`, browser `request_file_open`, parked for the gesture lane) and answers the change action with `{value: <file name>}` via the same merge as `importIconFile`. Law: `a_file_input_wraps_its_change_action_and_answers_with_the_picked_name`.
  - date/colour commit semantics: `native_value_text` in `W/⚡️events/🧮️control-commit-rules`: a date field commits only `""` or a valid ISO date, a colour field only a normalised `#rrggbb` (never empty); anything else keeps the draft and is refused like the decimal-quad field.

### Follow-up 2 (coordinator fixes, code only)
1. Date typing restored next to the popup: a `date` field is text-editable again; `native_value_text` accepts the empty text or any text `date_picker::parse_typed` reads (ISO, `MM/DD/YYYY`, `DD.MM.YYYY`) and commits the ISO value; anything else keeps the draft (refusal). The popup and typing share the one commit rule. Colour and file stay non-editable (the DOM inputs are not).
2. Host clock: `date_picker::set_today_epoch_day` is the date picker's clock port; the shell publishes `app_now_ms() / 86_400_000` every frame from the wasm `pump_directory_events` (new dep `semio-ui-wgpu-layout` in `semio-renderer-wgpu-shell-frame-pumps`); `today_epoch_day()` answers the published day, else (native) the system clock, else `None`. 3. Accessibility: an open date popup projects `button` (previous/next, named `ui.common.previousMonth/nextMonth` en/de) and `grid` > `row` > `gridcell` (named by ISO date, the field's day `selected`, actionable); an open colour popup projects `listbox` (`ui.common.colours`) of `option` swatches (named by hex, current colour `selected`) and `textbox` fields Hex/R/G/B; the field reports `expanded`. New labels en/de in `UiCommonLabels` and the TS `common` rows.
4. Icons-only driver: a button with no icon keeps its caption (a label-only button cannot be icon-only), so the popup's day numbers, month title and weekday headers show; accessible names come from the projection above, not from paint.

### Follow-up 3 (code only)
- Focus ring (typed, no id marker): the picker cell model returns `PickerCell { node, rect, focused }` (`focused` = the day at `picker_day`, or the highlighted swatch); the sync pass stamps the new `NodeFlags::PICKER_FOCUS` on the minted cell each frame, and the button and input paints draw the ring from that flag with the theme's focus tokens (`theme.selected` border, `SharedBorderState::Focus`). `NodeFlags` widened from `u16` to `u32` for the bit.
