# Window layout unification: React/TS migration

The contract `WindowLayout` (`🖱️ui/🧬️contract/🖼️presentation/📐️layout`, import `@semio-tech/ui-layout`) is now the only TS layout model. Rust is untouched.

## Deleted
- `🖱️ui/🔨️modules/🗺️window-layout` (React row/column/`id`/`activeId`/percent shape, `createEvenWindowLayout`) and its `./modules/window-layout` export.
- `🎓️onboarding/🗺️window-layout` (declaration TS copy) and its `./window-layout` export; the `taxonomy.json` owner path.
- `Canvas/📐️corners` (`insertWindowAsTabAtCorner`, `splitWithWindow/Stack`, `splitRootWith*`, `mergeStackTabsIntoStack`, `setWindowCornerInLayout`, `extractStackFromLayout`, `applyAxisSizes`, ...) and its export.
- `Canvas/🗺️layout` logic (`collapseLayout`, `reconcileWindows`, `normalizeLayoutToStacks`, `update/readLayoutAtPath`, `mapLayoutStacks`, `removeWindowFromLayout`, `setActiveWindowInLayout`, `resolveStackPathForWindowId`, `modeCollectWindowIds`, string paths): file kept as a small Canvas view module (`modePathKey/FromKey/Equals`, `resolveModeLayout`, `collectModeWindows`, `findModeWindow`, `readModeStack`, `modeStackTabsByCorner`, `applyModeSplitPercents`).
- `Canvas/🎯️drop`: `insertWindowAtDropZone`, `ModeDropZone`, `ModeCanvasDropTarget`; `applyModeDrop`/`modeDockOutLayout` now call contract `dropWindow`/`dropStack`/`extractStack`/`removeWindow`. Zones are `WindowLayoutDropZone` (`rootSplit`, `index?`, array `stackPath`).
- `route-and-chrome`: `modeLayoutNodeToFramework`, `collectFrameworkLayoutWindowSeeds`, `convertFrameworkLayoutNodeToModeLayout`, the `extraWindowInstances` conversion map (`captureCurrentFrameworkLayout` lost that argument).
- Layout types/ops removed from `@semio-tech/framework` (framework-exports) and the ui-react source barrel; consumers import the contract directly.

## Migrated
- Canvas: `🟦️.tsx`, dock, drag/window callbacks, template drop, layout state, join-corners (fractions, `parentAxis`, key strings only at the `Resizable` boundary; percent conversion in `applyModeSplitPercents`/`modeAxisGroupLayout`), `Resizable` (`parentAxis`), template-drag.
- onboarding declaration, manifest (re-exports contract types; contract moved from devDependency to dependency; `UiWindowLayout` aliases removed), platform builders (`createDefaultLayout(axis, fractional sizes)`), config schema parser (`parseUserNamedLayout`: stack/split, `axis`, `activeWindowId`, size in (0,1], split >= 2 children). `package.json` + `bun.lock` (root, hub, teaching, `✏️s`, `🏢️semio-tech`, `♻️mit-bestand`).
- Renderer: route-and-chrome (+ package copy), Shell state/reducers/actions, ShellHost (`window-scope`, `spawned-program`, template drop, focus-window, canvas, layout hotkeys, ...), kernel `ui-dirty-scope`; geometry key now also ignores `templateId`.
- Tests/stories: ui `owned-locale-detector-retirement` suites (1, 4, 5, 6, 7, 8, 10, control-chrome-1, uidriver, veil), harness picks, `🎭️mode` story, `dock-axis-geometry`, Canvas tests, `Window` test; renderer suites `window-ids-and-layout-seed`, `maximize-resync`, `spawned-program-session`, `app-mode-layouts`, `window-scope`, `mounted-window-fetch`, `focus-window-of-kind`, `window-lifecycle-template-drag`, `saved-state`, `wgpu-accessibility-interaction` shared, `instance-title`, `preference-lane`.
- Data: 46 component JSONs (45 `🌎️hub/🧩️compositions/**` + procedural plugin), config `ui-preferences`/`set-named-layout` JSON Schemas, `schema-catalog.json`, renderer fixtures (`window-scope`, `app-mode-layouts`, `declared-instances`, `mounted-window-fetch`, `preference-lane`). Component sizes were normalized to fractions summing to 1 (old values mixed percent/fraction and were only relative weights). All 415 migrated layouts validate against the contract schema.
- Fixed in verification: corpus test registered the schema twice (Ajv `$id` clash), `shell-components-5` expected string peer paths, `window-scope` fixture bare window still had `id`.
