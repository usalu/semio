- React `formatDocument` / `lintDocument` do NOT run a formatter or linter: they only `dispatch(...)` the verb to the host/guest (`✏️TextEditor/🟦️.tsx:189-190,357`). The wgpu menu already declines both rows (`text_editor_queue_menu_action`, test `only_the_editors_own_menu_rows_are_claimed`), so the shell dispatches them. Nothing forked; the logic stays in the app/runtime contract.
- Missing: `Ctrl/Cmd+Shift+F` chord. Added `text_editor_format_document` and the chord in `text_editor_popup_key` (Scenes `✍️text-editor/🦀️.rs`), dispatching `formatDocument` with `{}` exactly as React.
- Missing: diagnostics footer (React lists up to 4 `[severity] message` rows below the editor). Added `text_editor_diagnostic_lines` + `render_text_editor_diagnostics`, painted above the explicit-draft footer. Squiggles come from the engine scene (`diagnosticsJson` is already synchronised in `📄️scene-document-and-host-sync`), unchanged.
- Tests (`Scenes/🧪️tests/🔬️wgpu-text-editor/🦀️.rs`): `accelerator_shift_f_dispatches_format_document_and_plain_f_does_not`, `diagnostics_footer_lists_four_rows_with_optional_severity`.
- Not done: no dedicated touch-selection module (audit item, separate).

## World3d / WorldTerrainLayer
- Audit false negatives: terrain brush, move-position overlay and `terrainFrame` are implemented in `♾️infinite/🌍️world/🧱️scene` (`terrain_brush`, `terrain_move_position`, `sync_terrain_camera_frame`, `take_camera_origin_elevation`), consumed by `🧊️renderer` frame-transaction and `interaction-state`. Vortex hover/select and vortex marker meshes live in the infinite world crates too. WorldTerrainLayer needs no port.
- Truly missing: `openVortexSuggestions`. Added `world3d_open_vortex_suggestions` (interaction crate, re-exported from `🌍️world/🦀️.rs`), `ShellState::world3d_alt_press_suggestions`, and the Alt + secondary press branch in the shell pointer handler (press consumed, no context menu, as React). Fixture: `World3dHost/🧪️tests/🧫️fixtures/🌪️vortex-suggestions.json`; test `vortex_suggestions_dispatch_the_hovered_marker_only`.
- Not done (precise remainder): (a) long-press (500 ms, 10 px slop) and `ContextMenu` / `Shift+F10` key routes to suggestions, plus the "no marker focused" announcement; (b) brush-armed variant (`brushMode && hovered vortex`); (c) point-cloud layer: `pointsJson` is only size-validated (`render-plan-validator`). It needs a new instanced billboard point-sprite pipeline in `🖱️ui/🎯️targets/🧊️wgpu/🖍️draw` (WGSL, pipeline in `world-geometry-pipelines`, pass encoding in `world-pass-drawing`, base64 buffer decode, size and `sizeAttenuation` uniforms, lifetime budget) because wgpu has no `gl_PointSize`. Not approximated with lines, to avoid a non-parity stand-in.

## Follow-up (coordinator round 2)
- Vortex suggestions now cover every React route except the announcement: `ShellState::world3d_suggestions_request` (shell input) serves Alt + secondary press (consumed even with no marker), the brush utility (`activeUtility == "brush"`, hovered marker required), the `ContextMenu` / `Shift+F10` chord (before the generic context menu in keyboard.rs, anchored at the focused scene) and the touch long press (`handle_touch_gesture`, before the plugin touch hook). The shell routing has no unit test; only the pure action builder does.
- Point-cloud layer NOT implemented, deliberately. Reading the draw path showed the work spans: `pointsJson` decode in the world bridge, a new instanced point-sprite WGSL pipeline, `world_line_pipeline`-style resources in `semio-ui-wgpu-pipelines`, pass encoding in `semio-ui-wgpu-draw-execution` (production path in `world-material-and-effect-encoding`, with bounded buffer budgets), a new draw type in `ui_scene::math` / `semio-ui-draw-contract`, and `render_world_3d` emission, plus the duplicate `webgpu` renderer. Boundaries have room (shaders 1046, pipelines 1549, execution 1803, bridge 2182 of 4000 active lines) so no new sub-crate is needed. Exact parity is computable without a new pipeline only by CPU billboards (attenuated world size = `size * tan(fov/2)`), but those would be lit by the standard material, unlike three's unlit `PointsMaterial`, so I did not land them. With the build gate down, ~10 blind edits across 6 shared crates would risk breaking everyone's compile.

## Follow-up (coordinator round 3)
- Long press: the two values were different gestures. `LONG_PRESS_MS = 450` (TS `👆️gesture/🟦️.ts`, Rust `🖐️touch-session`) is the shared touch session's additive press and plugin long press; React's suggestions hold is the separate `createLongPressV1({ holdMs: 500, slopPx: 10 })` in `World3dHost`. The 450 one is untouched. The suggestions hold is now its own lane: `world-touch` arms it at the first finger, disarms on drift past 10 px / second finger / lift / cancel, fires once at 500 ms (also as a wake-up deadline), then `poll_world_touch` queues it on `settle.suggestion_holds` and `open_world3d_suggestions_at` dispatches. One value: fixture `🌪️vortex-suggestions.json` `longPress {holdMs:500, slopPx:10}`, read by TS (`WORLD3D_SUGGESTIONS_LONG_PRESS_V1`, used by the tsx, test in `🧪️tests/👆️long-press-suggestions`) and checked against Rust `WORLD3D_SUGGESTIONS_HOLD_MS` / `_SLOP_PX` in the pointer-gestures test. The earlier 450 ms interception in `handle_touch_gesture` was removed.
- "No marker focused" announcement: `world3d.suggestions.noTarget` (en: "No marker is focused, so there are no suggestions.", de: "Keine Markierung ist fokussiert, daher gibt es keine Vorschläge.") in the shell vocab, shown as a polite transient notice (code `shell.world3d-suggestions.no-target`) for the chord and the long press. Alt press with no marker stays silent, as in React.
- Point cloud: still not landed. Reading the production path showed `line_draws` is woven through draw-usage measuring, retained ownership accounting/retirement, scalar encoding, and four renderers (wgpu, webgpu, metal, d3d12); a `point_draws` twin must be added to every one of them plus the pipeline and shader. That is a multi-crate change this session could not safely gate (each compile probe took 10+ minutes behind the shared build queue). Remaining plan, in order with a compile gate after each: (1) `semio-ui-scene` `PointDraw3d` in `📐️math/🎞️pass`; (2) draw-contract accounting (`📋️draw-list-and-retained-output`, `🗑️retained-retirement`, `📏️draw-usage-measuring`); (3) WGSL + pipeline (`semio-ui-render-prepared-shaders`, `semio-ui-wgpu-pipelines`); (4) pass encoding (`semio-ui-wgpu-draw-execution`); (5) `pointsJson` decode in the world bridge; (6) emission in `render_world_3d`; (7) metal/d3d12/webgpu twins.
