# Remodeling Structured Durable Content Gap

Read-only source proof of an actual semantic-cell gap, not a missing qualification claim. No runtime execution or production edit here.

`✏️s/🔌️plugins/📸️remodel/🗿️artifacts/📸️remodeling/🏅️standards/🔖️1/🪆️subsets/✳️any/🚪️io/🪶️sqlite/📸️snapshot/🗄️.sql:7` stores every durable content leaf as `remodel_durable_chunk.octets BLOB`. Actual projection at same provider `🦀️.rs:152` writes `Cell::Blob(&chunk.0)` for every content kind. These leaves include structured sparse numeric samples and structured mesh field vectors, not only image/media octets.

Actual domain root `✏️s/🔌️plugins/📸️remodel/🗿️artifacts/📸️remodeling/🦀️.rs:629` resolves `Float32Buffer::Content` from `kind == "sparse"` durable leaves and decodes each four-octet group using `f32::from_le_bytes` at637. The SQLite float-buffer projection at provider180–185 emits `remodel_float_sample` rows only for Inline values. Content numeric buffers get content_id/chunk_count metadata and a BLOB in the durable chunk table, but no scalar sample relation. A plain SQL consumer cannot inspect those numeric samples without knowing the custom four-byte layout. This is the strongest directly established gap.

Mesh durable leaves require additional custom meaning: domain root428–470 dispatches field tags into positions/normals/colors/UVs and integer indices/IDs, then decodes f32/u32 little-endian vectors. Mesh reconstruction at489–502 calls that decoder; the SQLite projector still stores the chunk's tag and structured components inside the same generic BLOB at152. The mesh result table stores child/dialect/source metadata, rather than those actual typed geometry entities. This is a second structured-content candidate backed by actual decoder and producer source; it should be assessed under the declared composed Semio mesh child scope rather than treated as ordinary image bytes.

Image compressed/raw asset content remains legitimate artifact media data and is excluded from the finding. Generic explicit Bytes variant values, byte buffers, Office embedded binary parts, audio/video samples and unknown format chunks are also not defects solely because they use BLOB. Their producer/domain meaning must be examined separately.

A narrow semantic schema correction would keep durable leaf/chunk identity and boundaries as relations, but represent sparse leaves as ordered numeric scalar rows carrying queryable value + IEEE754 bits/class and mesh leaves as explicit tagged vector/entity rows. Preserve exact original chunk boundary ownership through metadata so import can reconstruct the existing Snapshot without a hidden payload duplicate. Expose links from Float32Buffer Content and Remodeling mesh child handles to these semantic content rows. Do not merely duplicate decoded rows beside a still-authoritative packed geometry BLOB: the relational values must be authoritative and independent edits must change public IO roundtrip meaning.

A neutral language-agnostic law should author one real Content sparse buffer and a real nonempty mesh with several field kinds, exact typed rows and source chunk boundaries. Read exported physical SQLite with Bun; independently update a scalar sample/mesh coordinate and verify the complete authored imported Snapshot, then reject conflicting leaf ownership, wrong chunk boundaries and nonfinite bits/class conflicts. This proposal is source proof and test design, not a completed behavior change.
