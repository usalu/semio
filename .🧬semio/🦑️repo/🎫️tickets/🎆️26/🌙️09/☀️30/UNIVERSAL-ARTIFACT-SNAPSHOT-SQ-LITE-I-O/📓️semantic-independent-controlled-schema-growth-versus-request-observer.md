Read-only actual first-party API audit; no test, production, held or script mutation. The eighteen controlled-call proposals remain unqualified by owning runtime.

The first-party System observer `🧰️framework/🔨️modules/🚪️io/🪶️sqlite-snapshot/🧪️testing/💰️backing/🦀️.rs:48–64` records alloc and alloc_zeroed layout.size, and records the **entire new size** for realloc. Successful realloc additionally releases the old layout size. The requests metric is cumulative, not a capacity delta or net retained size.

Controlled transfer grow at `🔁️transfer/🦀️.rs:14` does not realloc the original Vec. It allocates a fresh replacement through reserve at doubled capacity, transfers entries and drops the previous backing. reserve charges capacity*sizeof(T) in full before try_reserve_exact. Consequently a growth sequence of old capacity C to 2C charges the complete 2C request, while the old C remains in the cumulative ledger. This agrees with observer aggregate requests; it is not delta accounting. Cancellation during transfer retains ordinary local ownership until drop and does not refund the cumulative ledger.

Lexer token growth at transfer line67 uses the same pattern through NativeDecodeControl::allocate_vec: fresh replacement, full capacity*sizeof(Token), append entries, old backing drop. Native helper authority is `🧰️framework/🔨️modules/🌱️value/🛬️decode/🦀️.rs:75`. Text copying charges full byte length and reserves exact backing once; escaped quoted SQL allocates its exact decoded byte Vec then String::from_utf8 consumes that backing. Encoding copy_text uses the same full-length pattern. None of these paths charges only growth delta.

Parser slots start as Vec::new/String::new or scalar Option and therefore own no initial backing. Token text is paid; parsed table name/column name is copied via paid copy_text; groups/statement vectors grow through paid grow; columns/names/identifier marks/declared type bytes reserve through paid reserve. Statement tuple movement, iterator traversal and stack arrays do not copy or allocate their contained owners. Parsed AST temporary drop releases owned Strings/Vecs directly and does not invoke typed domain retirement scaffolds on success. String::from_utf8 transfers the paid Vec allocation. Schema matches repeats these allocations, and each repeated request is charged. Allocation_stage settles native child owned_bytes into the same cumulative parent ledger, with no successful cleanup refund.

No definite residual controlled-parser successful-request mismatch was found in this bounded read-through. try_reserve_exact uses requested element capacity rather than allocator physical usable size; the observer measures Layout request size, so allocator internal over-allocation is irrelevant to this metric. The Rust allocator can grant greater Vec capacity, so exact runtime remains the required authority rather than a static claim about every platform. Allocation failures or cancellation can charge admitted work that never physically allocates; existing refusal law asks for balanced observed cleanup, not success-request equality in those branches.

The clean semantic decision is to retain full cumulative request admission and adopt the existing controlled validator in all remaining eighteen owners. Do not refund temporary metadata, warm an unmeasured cache, replace full requests with capacity deltas, or weaken the exact law. If owning replay exposes another mismatch, isolate that actual allocation route before changing helpers. No numerical prediction of the post-patch Model charge or success result is made here; returned owner retirement and source setup remain outside the success measurement.
