# Rust Relational SQLite Engine

The current engine exports and imports real SQLite 3 databases of explicit rowid tables. It replaces the superseded opaque artifact container. This engine is domain neutral; handwritten artifact providers own their entity schemas, constraints and native reconstruction.

The runtime uses Rust standard library only. Public values are NULL, signed INTEGER, REAL, UTF-8 TEXT and BLOB, with independent signed rowids and INTEGER PRIMARY KEY aliases restored to actual integers. REAL affinity restores SQLite's integer storage optimization. Quoted identifiers, inline/table integer primary keys, foreign-key clauses and CHECK constraints are retained. Unsupported index-producing UNIQUE/noninteger/composite primary keys, descending primary keys, AUTOINCREMENT, generated columns, WITHOUT ROWID, views, triggers and indexes fail explicitly.

The writer builds table/schema leaf and interior B-trees and overflow chains. The reader discovers table roots from sqlite_schema, accepts independent page sizes 512 through 65536, validates signed separator bounds, record serial types, overflow/global ownership, freeblock and fragment accounting, freelist chains, native header identity and authoritative page-count rules. It streams table records into destination rows. Before allocating a record payload it applies the remaining semantic value budget plus a bounded maximum record-header allowance, and before cloning each record value it enforces aggregate field bytes. Restored primary-key aliases count eight semantic bytes despite their physical NULL storage.

Limits are file272MiB, aggregate values256MiB, schema4MiB, rows1M, columns1024, tables4096 and pages1M. Shared control exposes phase/completed/total checkpoints, cancellation, row/value guards and a database counting guard with checkpoints every256 rows before provider output allocation.

## Explicit Native Numeric and Reconstruction Controls

The registered native physical target ran twenty tests successfully in Nextest run `aea15e78-ebbc-4b74-a056-f1776b43eb37`. This includes before-allocation ownership accounting, cancellation on a 100 KiB borrowed copy, bounded relational ordering, and native IEEE binary32/binary64 companions. The independent Bun SQLite oracle checks integrity, query storage classes, NaN query NULL versus exact signed INTEGER bits, and reserialization preserving signed zero, both infinities, quiet/signaling NaN payloads, and subnormals. The target's separate oracle binary build remains queued behind other Cargo builds; the complete target is not yet reported green.

The shared artifact helpers consume explicitly supplied fields and authored positions only. They do not traverse native objects or synthesize schemas. Binary64 bits use `u64 as i64` for signed INTEGER storage, with `i64 as u64` restoring the identical 64-bit pattern. Binary32 bits use a nonnegative INTEGER in the full unsigned 32-bit range. Query REAL values are NULL for NaN and accompanied by one of `finite`, `positiveInfinity`, `negativeInfinity`, or `nan`. Missing optional fields have NULL in all three columns. Readers reject inconsistent companions. Reconstruction byte accounting is cumulative across shared typed collection helpers and outer fields; numeric database storage is charged before expanded owned strings or blobs are copied.
