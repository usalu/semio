## Concrete TSV Differences

Use `✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📑️tsv/🏅️standards/🔖️iana/🪆️subsets/✳️any/🚪️io/🪶️sqlite/📸️snapshot` as owner root. `💰️backing/🦀️.rs` and authored SQL preserve TsvSnapshot { schema, records:Vec<Vec<String>>, trailing_newline, line_ending:Lf|Crlf }. Document has four cells, record three, field four. CSV instead has explicit has_header, CsvRecord/CsvField and per-field quoted flags. TSV has no header flag or quoted field authority: first record is ordinary content. Missing field means shorter record, empty String is a present empty field, and empty record is independently retained with zero children; do not pad/truncate rows. Preserve trailing_newline and lf/crlf independently of field text.

TSV SQL has string literals in CHECK(line_ending IN ('lf','crlf')). CSV's current ASCII token comparator must not be reused unchanged with case-insensitive literal comparison. A domain-neutral schema tokenizer must preserve literal bytes/escape semantics and exact token boundaries, with bounded interior scanning. SQLite CHECK on 'LF' does not have the same accepted values as 'lf'. Independent SQL edit laws should distinguish altered literal case, malformed tokens, unknown line ending, missing cells, gaps/duplicate ordinals, dangling owner ids and shuffled physical rows.

## Reuse Boundary

CSV's receiving ownership mechanism can be shared through domain-neutral first-party SQLite artifact helpers: direction-aware original native/body/SQL port, exact vector/text destination receipts, SQL row/table scratch ownership, and paid usize row identity/ordinal indexes. Place common implementation under framework `🚪️io/🪶️sqlite-snapshot/🧩️artifact` receiving taxonomy (or the existing domain-neutral control body helpers); neither TSV nor CSV should import the other's domain module. Keep both authored table/column names, schema, semantic flags and logical typed frames local to their respective artifact roots.

Projection can share one domain-neutral frame containing SqliteDatabase plus scratch SqliteRow and scalar accounting, parameterized by borrowed declared schema/table/cell visitors. Reconstruction should share only paid index utilities/port, while TSV frame owns the actual TsvSnapshot and indexes. It must push an empty Vec<String> into actual snapshot.records before reserving fields and push each empty String before copying into it. Do not create a CSV-shaped intermediate semantic root, generic JSON root or duplicate owned typed tree to gain reuse. Borrow source database and reconstruct directly into genuine TSV output. Actual shared helpers must leave each destination in its original frame on cancellation, and their published errors must retain accepted partial receipts.

## Existing Shared Native Record Interfaces

There are no general public RecordDecoder/RecordEncoder types with those exact names in inspected framework source (WalRetainedRecordDecoder belongs to WAL). Actual shared Store interfaces are `decode_sqlite_snapshot_record_native<T:RetireOwned>` at `🏪️store/📦️codec/🪶️snapshot-capability/🛬️native-decoding/🦀️.rs` and `encode_sqlite_snapshot_record_native` in Encode sibling. Decode accepts RecordSpecProducer and a constructor over `&mut RecordValue`, actual output Option<T>, original NativeDecodeControl and body wallet; its receiving frame owns optional schema, physical RecordValue and typed output. Encode accepts a controlled RecordValue constructor and receives optional schema, RecordValue, body payload and final payload. Neither signature proves internal parser partial custody or complete normal body accounting; Encode currently names its wallet _body.

TSV native Decode explicitly calls admission::admit then admission::bind, rather than generated constructor alone. Bind preflights typed slots/UTF8 demand, installs empty genuine TsvSnapshot in the output slot, fills actual schema/rows/cells, and records performed progress including text prefixes. This is a useful typed receiving precedent, but the shared physical Record parser/spec functions still return owned results only after completion; partial parser locals require separate actual receiving factories. Native Encode projects another owned RecordValue through __dsl_to_record_controlled, then creates body payload and wrapped candidate. A direct borrowed encoder interface (existing BorrowedRecordSpec plus native borrowed measure APIs) could avoid the redundant owned RecordValue, but needs a genuine cursor/retained source protocol, not just substituting measure for encode.
