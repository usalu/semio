# PNG and Deflate Owned Control Independent Audit

Read-only source inspection of the unmounted PNG engine/native snapshot producer, Deflate snapshot producer and first-party raw inflater/compressor. No Cargo, runtime invocation, source edit, modifying Git command or mount was performed. The report itself is the only write. No runtime success is claimed.

## Decisive Findings

1. **PNG canonical RGBA8 output can emit an invalid bKGD.** `encode_png` hardcodes IHDR `[8,6,0,0,0]`, but Bkgd emits the original Grayscale two-byte or Indexed one-byte payload. Its own decoder requires six bytes for color type 6. Thus a valid grayscale/indexed source with background produces a carrier which the same decoder refuses. An RGB background originating at 16-bit depth can also exceed the RGBA8 sample range. Normalize background through source depth/palette to a valid RGBA8 RGB background, or explicitly reject an unrepresentable carrier before writing. Add independent PNG-parser round trips for grayscale, indexed and RGB16 backgrounds. This is an external-carrier correctness issue; it does not require preserving arbitrary source headers through PNG, and full typed SQLite preservation remains the separate law.

2. **Bare zlib ignores the advertised window bound.** `decompress_zlib` accepts CINFO 0–7 but always creates/reserves 32768-byte history. `Inflater::read_back` enforces retained history length, not CMF CINFO. A stream advertising a 256-byte window with a longer-distance match can therefore be accepted. Construct the inflater/history ceiling from `1 << (CINFO + 8)` or enforce observed distance against that bound. The bare writer advertises 32 KiB, so this finding affects its consumer and the standalone decoder. Validate a syntactically correct FCHECK/Adler stream whose match exceeds its advertised window.

3. **Standalone Deflate's dictionary and window emission authority is incomplete.** Standalone decode records DICTID and skips it, without supplying/checking the dictionary. Encode sets FDICT/DICTID but invokes the dictionary-free 32-KiB compressor, and can advertise a smaller CINFO than its actual matcher window. Such a producer cannot promise valid RFC1950 for arbitrary owned headers. Bare PNG consumers correctly refuse FDICT. Standalone production should refuse unsupported dictionary authority and constrain the actual matcher window, or supply actual dictionary/window-aware physical APIs; typed SQLite can still preserve full header fields. Add dictionary-required and reduced-window external oracle cases before mounting.

4. **Valid PNG Latin-1 text is converted destructively.** `text` performs lossy UTF-8 conversion for all fields, including PNG tEXt/zTXt values and keywords, whose byte encoding is Latin-1. A valid single byte E9 becomes U+FFFD; encode writes UTF-8 bytes for those carriers. iTXt keyword is also Latin-1, although its translated keyword/value are UTF-8. This matches the old handwritten reader, but staging is a chance to correct the real carrier semantics rather than bless that inherited loss. Use field-specific Latin-1/UTF-8 conversion, reject nonrepresentable tEXt/zTXt Unicode explicitly, and validate accented Latin-1 against an independent parser. Arbitrary Unicode remains valid in the typed SQLite law.

5. **Chunk grammar is not validated despite CRC validation.** Input accepts IHDR after other chunks, duplicate IHDR/ancillary singletons, separated IDAT runs and nonempty IEND; the first header forecasts semantic rows while the last header controls raster materialization. Duplicated scalar ancillary chunks overwrite the owned value while multiple markers remain, so later emission repeats the last value. Text compression methods and iTXt flag values are ignored/nonzero-coerced. Add an explicit controlled chunk-order/uniqueness grammar and reject invalid reserved fields. For output, validate chunk_order before writing: an early IEND followed by Idat is emitted unchanged and then rejected as trailing bytes by the reader. These are validity failures, not a demand for byte-exact preservation of IDAT splitting.

## Inspected Control and Codec Boundaries

CRC iterates in 256-byte callback batches; chunk descriptors, IDAT gathering, palette/unknown/text ownership, inflated bytes, RGBA output, row/sample temporaries and emission candidates use the same cumulative native control. Packed samples, big-endian 16-bit samples, filter byte reconstruction and Adam7 placement follow the existing helpers. Filter emission chooses among all five predictors at RGBA8 bpp=4. Bare compression uses the real controlled raw producer rather than an ordinary fallback. Adler is calculated over output/input bytes with bounded u32 values and the stored checksum is big-endian. Retained inflater uses inline Huffman arrays, and its History drop performs explicit bounded retirement steps; cancellation/error paths therefore retain that cleanup guard. No PNG IEEE/floating-word carrier exists: unsigned chromaticity/gamma fields are integer words, while arbitrary typed header retention belongs to SQLite.

These inspections do not establish compile validity, differential parity, callback timing, exact ceilings, or runtime cleanup success. All producer files remain unmounted pending authentic Native RED, first-party Deflate dependency/module activation and owning runtime validation. Source8/69 is independent Source evidence and must not be promoted to Native proof.
