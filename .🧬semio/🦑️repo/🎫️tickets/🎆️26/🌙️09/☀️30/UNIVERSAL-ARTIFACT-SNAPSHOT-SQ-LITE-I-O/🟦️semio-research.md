# Semio TypeScript Semantic SQLite Plan

The nineteen native Semio implementations are the concrete domain/schema references, verified by108native laws. TypeScript mirrors will handcraft the same explicit semantic tables and relationship traversal for all eighteen concrete types and the base union. They will reuse actual typed SemioValue and DocBlock models only where native owners themselves share them. No reflective field traversal, generic domain mapper, opaque DSL/JSON/native-pack snapshot or automatic schema generation is permitted.

Existing TypeScript numeric models need explicit owned widths: binary32 audio/color fields and binary64 geometry/style fields become first-party bit-word scalars; full u64 timestamps/blob sizes/nextLabel and signed64 rational fields become bigint. Degree/count/index/raster fields keep their actual bounded integer widths. Handwritten parsers and field consumers must match these types without compatibility unions or narrowing. Some existing recursive union parsers flatten all variant fields into optional bags and are inconsistent with their declared models; domain ownership requires repairing them rather than relying on those malformed projections.

Each family consumes its existing neutral native corpus, checks SQL bytes against the adjacent native asset, independent Bun SQLite integrity/FKs/query/edited-file reconstruction, scalar/variant/optional/ordered state and resource/cancellation laws. All nineteen mirrors remain incomplete until registered runtime suites and strict typechecks succeed. Root owns composite Nx/launch registration and shared declaration build runner prerequisites.
