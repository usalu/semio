# Owned Native Schema Producer Propagation

The shared native capability now accepts `RecordSpecProducer`, whose input and output factories admit schema allocations under the same cumulative control as native values. Ordinary metadata construction remains an explicitly separate factory. This report covers interface propagation; it does not establish runtime completion of the affected artifact codecs.

## Changes

- Framework Flow `WidgetDsl` constructs controlled statement metadata through the actual controlled variant owner. `Widget` and `SynapseSpec` forward their typed controlled shape owners. `FlowHostSnapshot` exposes its generated lazy record producer and controlled shape.
- Process3d's existing mounted ordinary parser retains `RecordSpecProducer` in its statement frames and invokes the explicitly ordinary factory only in that ordinary parser. It does not add an ordinary fallback to controlled native decoding.
- Process3d's authored `tagged_variant_field!` shape binding forwards controlled statement metadata to the actual derived variant owner for `MeasureRecipe`, `WorkingSolid` and `ProcessMeasure`.
- Framework Collection `ArtifactBody` has handwritten factories for its two-field document metadata and three-field blob metadata. Both controlled factories admit vector slots, copy literal field labels and keywords through the caller's control, and publish exact field work. Controlled variants admit two pair slots and their two labels. The ordinary variant list carries the same explicit producers.
- WFC Bitmap's native helper now passes `BitmapSnapshotDsl::__dsl_spec_producer()`. ISO16757's helper already used the generated producer when this source state was reread.
