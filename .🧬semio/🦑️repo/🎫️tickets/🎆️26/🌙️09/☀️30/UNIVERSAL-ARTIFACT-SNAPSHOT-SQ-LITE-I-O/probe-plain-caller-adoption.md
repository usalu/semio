## Minimal Clean Owned API

Define a first-party owned local JSON session under the existing JSON IO module, with a direction-specific detached original receipt, that exact admitted recipient box, retained result/refusal, and explicit phase: running, auxiliary close, result ready, cancelled result close, recipient shell close, terminal. Keep physical result/refusal in the session before conversion into outward diagnostic strings. A consuming terminal extraction transfers the ready output/refusal once; a close error returns/keeps the same session and leaves the box and accounting intact. Charge session/recipient heap backing and wrapper capacity before construction; witness final shell release explicitly.

At request admission the actual host/workspace operation takes one fixed-capacity slot carrying that session and an operation identity. Slot contention refuses before parser ownership starts. Each step consumes the original caller grant, publishes progress/next physical demand, and preserves state on denial. Add that declared slot to HeadlessWorkspace only for its own admitted operations, and wire cancellation/shutdown into its retained request close driver. Guest requests should instead put the same session into their already admitted exchange frame and include it in exchange terminal emptiness. These are separately priced ownership attachments, not a shared global registry.

Modify the JSON IO module's plain entry points into consuming session creation/step/extraction; modify ProbeSnapshot and ProbeMutation IO implementations to use the owner-bearing contracts; modify Store's ArtifactDsl/ArtifactPack and erased ArtifactCodec callback boundary and replication's OpText/OpBinary to accept the actual caller receiving owner or return an owned operation session. Update Store mirror/hydration/op-log callers such as print_mirror, print_edit_lines and print_document_text to retain their codec child session within their original operation. Keep the same ownership in conversion to Pack/Text/Protocol diagnostics. Change text printer return types to an owned/fallible result: expect cannot express admitted capacity/work refusal.

Files defining these trait boundaries: Store `🏪️store/🦀️.rs:6515,12081,12362`; replication `🧰️framework/🔨️modules/📡️replication/🚪️io/📝️text/🦀️.rs` and `💾️binary/🦀️.rs`. Because this repo excludes compatibility layers, replace caller contracts together rather than adding ownerless defaults that silently allocate authority.

## Published and Retained Outcomes

Malformed UTF-8 or source-size rejection before any session allocation can publish directly if the diagnostic is itself admitted to its caller. Once a cursor/result/refusal owns backing, cancellation, malformed late syntax, capacity denial, close depth/release denial and exhausted work retain the session. Do not convert an unfinished result to a bare Err that drops its recipient. After auxiliary retirement is empty, success may transfer the result to its next declared owner while closing the empty session/recipient shells under explicit funding. Published failure transfers the owned diagnostic only after the request has adopted all pending retirement; abandonment closes the result too. A published status is not physical terminal emptiness.

## Finite Synchronous Closure Assessment

The inspected plain contracts provide no work/depth/release/capacity close grants and no owner receiver. Pack options supply format limits but Probe currently ignores them; text print/operation print accept arbitrary in-memory DslValue without source extent admission. A parse input byte ceiling alone does not prove a bound on retirement cursor/frame birth allocations, cumulative cleanup capacity, exact maximum close turns, or progress under refusal. The current arbitrary 100000 cutoff is not such a proof. Physical retirement can require additional capacity after the native ceiling has already been spent; source-size boundedness does not grant those bytes.

A mathematically finite synchronous closure could be implemented only by forecasting and pre-admitting every parse/write and close frontier, proving per-step progress and finite total cursor transitions, including all wrapper/index/error allocations and exact shell releases. No such proof was found in these traits or Probe callers. An always-accepting callback alone supplies no missing capacity. Therefore the clean next contract is owner-bearing IO with real retained request custody; retaining old Result-only/infallible signatures cannot satisfy pending-close ownership on all admitted failure paths.
