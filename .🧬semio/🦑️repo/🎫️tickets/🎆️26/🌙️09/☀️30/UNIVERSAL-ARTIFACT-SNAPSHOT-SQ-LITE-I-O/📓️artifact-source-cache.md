# Artifact Semantic Verification Cache Ownership

The shared project normalizer replaced every artifact TypeScript build/check/test input declaration with `artifactSources` and `artifactCommandSources`. The first group followed only the public definition facade, while the test routers named snapshot providers and suites dynamically. Actual PDF provider changes therefore restored a previous successful test without executing the new laws.

The owner policy now preserves explicit target inputs. Artifact check/test and their quick/long/exhaustive siblings additionally use `default` and `^default`, which cover the owner's domain implementation, tests and fixtures. Owner TypeScript source extensions explicitly include handwritten SQL assets. Builds retain their own authored production inputs and public import closure.

A language-neutral JSON fixture declares semantic provider, fixture, SQL DDL and shared-control changes. The registered `repo:test-artifact-source` route runs real third-party Nx in a separate ticket-owned workspace using the production project normalizer and Bun locked dependency identity. First execution increments an owned counter; the identical second execution must restore the cache without incrementing it. Each of four changed inputs must then increment it and print the changed domain value. The provider, fixture and SQL assets have no explicit target input entries; their ownership is automatic. The shared control is explicitly declared outside the artifact.

Before the policy repair, the actual test failed on the first provider change: expected execution 2, received 1. After the repair, both the first complete run and the final fresh rerun passed all 18 assertions, including all four invalidations and unchanged reuse. The final registered Nx run skipped the outer cache and completed in 12.8 seconds. Resolved PDF inputs confirm `default`, `^default`, both intrinsic groups and the author's exact domain/control inputs on all verification levels.
