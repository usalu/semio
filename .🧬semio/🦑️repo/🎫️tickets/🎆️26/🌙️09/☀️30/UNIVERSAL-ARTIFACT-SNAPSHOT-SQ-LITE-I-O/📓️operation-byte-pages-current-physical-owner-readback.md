# Operation Byte Pages Current Physical Owner Readback

Read-only actual Replication mutation/bytes source audit. OwnedOperationBytes installs finite caller payload and allocation ceilings without initial allocation; the isize::MAX constant bounds its generic container layout, not caller unlimited authority. Each reserve checks next full metadata/payload request, cumulative allocated bytes and current grant, retains an allocation fault if backing was actually acquired, and refuses subsequent admission. push_reserved returns the same rejected byte and performs no implicit allocation.

close_one with zero grants retains everything. Nonzero steps pop logical bytes with released_bytes0, then release one complete empty physical allocation only after its full required byte grant. next_close_byte_demand reports that true allocation when logical bytes are empty. Drop requires terminal closure; no partial physical return is claimed for a remaining page. This addresses the original contiguous8194-byte/fixed4096-grant mismatch structurally without pretending repeated grants resize an allocation.

The current OperationByteOutput implementation uses the same NativeEncodeControl, checkpoints before reserve, charges the next request, requires page request≤4096 and retains the already accepted byte prefix on refusal. Actual capacity/observer laws remain separate from static source checks. This is not proof that ChildEmit, actual OpBinary callers, Core sink or retained publication transport already use this owner. High reports a genuine one-law physical-floor receipt separately; this lane did not execute it.
