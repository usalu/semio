# Chart Numeric Companion Authored Edit And Corruption Policy

Read-only Source/current held Native policy assessment, no edits/execution. Both provider drafts use readable REAL plus native number kind and exact decimal companion. Native reconstruction preserves the original UInt/Int/Float only when parsed companion's as_f64 equals readable REAL; otherwise it returns Float(readable). Source similarly treats a changed readable value as the current numeric value. Existing independent width-only edit120→125 explicitly demands Native Float125, so rejecting every stale companion would contradict that authored reversible edit demand.

A reader cannot distinguish an authored REAL-only UPDATE from malicious/corrupt REAL-only UPDATE: identical database cells provide identical evidence. Declare a deliberate editable-payload contract rather than claiming this mismatch is both admissible edit and invalid corruption. Under that contract, require companion kind, canonical finite decimal spelling and original width validity first; unchanged readable payload preserves exact native variant/word; changed finite readable payload explicitly denotes a Float replacement. Reprojection regenerates coherent kind/exact companions, making edit→read→write→read stable. This does not preserve an original integer variant after a REAL-only edit; it is a declared replacement law.

To edit an exact integer while retaining UInt/Int, update readable REAL and kind/exact together transactionally to the desired exact word; require companion decimal to satisfy u64/i64 bounds and its REAL projection agree. Values beyond safe integer range need exact text, and multiple exact integers can share one rounded REAL: a readable REAL unchanged within that bucket cannot express an exact integer edit at all. Independent oracle should query text/kind directly or use Bun safeIntegers for genuine integer columns, never a rounded JS number.

Corruption refusals remain unambiguous for unknown kind, malformed/noncanonical decimal, outside declared width, nonfinite readable/companion values, scalar alternative payload contamination and broken relational ownership. Tests should separately pin these from the declared stale-companion replacement law. If strict companion coherence is desired instead, change the authored edit to update all three fields; do not accidentally keep REAL-only edit while silently discarding variants.

Additional held Native defect: NumericText uses a32-byte buffer with default decimal Display formatting. Extreme valid finite f64 values can require hundreds of decimal characters, so the formatter can refuse schema-valid chart numbers solely because of this internal bound. Use an explicitly bounded round-trippable scientific representation (with its closed lexical law), or admit actual complete canonical decimal storage; do not exclude valid finite chart domain numbers. This source-only finding requires a finite Native witness before provider correction.
