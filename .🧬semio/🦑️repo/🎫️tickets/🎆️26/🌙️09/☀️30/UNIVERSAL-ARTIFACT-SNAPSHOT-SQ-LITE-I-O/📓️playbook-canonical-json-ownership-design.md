# Playbook Canonical JSON Ownership Design

The actual Playbook native record preserves local steps as first-party JSON because free default/parameter objects preserve insertion order while native dynamic maps sort keys. SQL owns only the parent fields and literal child handles; local working scenes remain ephemeral. No JSON, native payload or nested SQLite carrier will be added to SQL.

Controlled parsing will construct the canonical DslValue tree directly and then use canonical FromValue under the same caller controller. A borrowed lexer owns no copied document. Strings receive a cancellable zero-allocation scan that validates escapes and determines exact decoded bytes, followed by admitted bounded materialization. Structural, whitespace and numeric scanning account for actual input spans. Collection capacities are admitted before each growth; completed and partial intrinsic children use their existing explicit retirement guards. Duplicate object keys keep the original position and replace the earlier value, matching ordinary first-party JSON behavior.

Controlled writing will obtain the canonical controlled ToValue once, preserve order, and count exact physical output without allocating a second JSON tree. After admitting the exact output reservation, a second bounded pass materializes escaped UTF-8. Recursive JSON depth uses the existing128 ceiling; scalar work and text spans publish cancellation boundaries. The physical native record and envelope remain controlled by the actual I/O owner afterward.

The existing exact float rounding algorithm must be retained. Stack limbs, fixed digit storage and fixed scalar text avoid guessed heap admission. Existing full f64 parity sweeps against serde_json are required after refactoring.
