# VCS Caller-Owned Reconstruction Plan

Read-only exact first-party API review. No new controller or grant required for logical7row/250byte specimen.

1. Validate authored database schema then `control.check_database(...ReconstructSnapshot)` as existing. Pin static canonical420/table2/max6. Require exactly one document aliasedidentity1/width6 and all tag rows positive aliasidentity/width4, parent1 and Text payload. Actual SQL allows arbitrary positive tagIDs, not necessarily1..N; retain surrogate identities, require uniqueness, and require dense ordinals0..N-1.
2. Obtain actual paid reference frontier using `artifact::ordered_row_refs(tag_table,2,control)`. It pays exactly one Vec<&SqliteRow> via original `transfer::reserve`, performs bounded heap sorting and rejects duplicate/missing/out-of-range ordinals. It does not independently reject duplicate rowids, so retain that check explicitly.
3. Avoid BTreeSet node estimates: sort the same reference Vec by rowid through public `transfer::heap_sort`, checkpoint adjacent equal IDs; then sort that same Vec back by ordinal through the same controlled helper. This adds no second heap frontier or controller. Alternatively perform identity sort/uniqueness first and ordinal validation afterward in one domain helper using exactly one reserve. Do not silently remove identity uniqueness merely because physical SQLite normally enforces PK; direct SqliteDatabase input is also public authority.
4. Reserve the actual output Vec<String> once with `transfer::reserve::<String>(count,control)`. Restore schema/title/notes/status and each tag using `artifact::reconstruct_text(control,...)`; counter is copied directly after integer role validation. Keep bounded explicit reconstruction row checkpoints and final completion. No Snapshot heap wrapper is needed; plain inline struct is not heap backing.

Original check_database records scalar bytes in the caller reconstruction ledger. For this full case scalar160 + actual restored UTF8 text90=250, so exact maxValue250 remains positive. Reconstruct_text adds text to cumulative reconstruction_bytes and uses actual controlled copy through allocation_stage: physical String bytes go to maxAllocation independently. Vec reference/output String backing goes only through admit_allocation_bytes, never speculative semantic payload. There is no BTreeSet48-pernode claim, Vec<Option<Row>> shadow, standalone NativeDecodeControl(maxValue) or maxValue grant raise.
