# Original Mutation Receiving

The actual `OpBinary` contract exposes only cold `encode_op` and `decode_op`. The controlled OS DSL operation decoder constructs local owned variant metadata, a local `RecordSpec`, a local generic record, and local typed binding guards before installing the completed typed operation in its retained encoding capsule. Cancellation cannot return those original scratch owners through the caller's original receiving frame.

The proposed required receiving contract is a separate `OpBinaryReceiving: OpBinary + RetireOwned` trait with `receive_op(bytes, original_owner) -> Result<Self, ValueError>` and no cold or unsupported default implementation. Each concrete producer must create its partial typed outputs inside the original owner and must pay physical allocation, copy, release, work, and depth independently. A synchronous receiver alone does not supply resumable per-turn mutation parsing.

The original `NativeSnapshotDecodeOwner` source is currently publicly compiled within OS `io::control`. The standalone SQLite snapshot crate includes the same source only privately under `cfg(test)`. Referencing the OS type from replication or generic DSL creates a dependency cycle. A single public common receiving floor must own that type before lower receiving traits can use the authentic original owner. OS must reexport the same identity instead of compiling a second copy.

Native execution has not been qualified yet. This record tracks actual source findings and must not be used as a passing runtime result.
