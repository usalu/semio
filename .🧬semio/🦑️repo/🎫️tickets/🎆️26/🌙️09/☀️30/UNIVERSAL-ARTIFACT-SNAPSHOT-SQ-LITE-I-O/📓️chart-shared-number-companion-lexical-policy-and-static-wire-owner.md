# Chart Shared Number Companion Lexical Policy And Static Wire Owner

Read-only policy recommendation from actual producers, not executed assertions.

Actual Chart Source numberCells at snapshot/sqlite TypeScript39 always emits kind float with String(number), except negative zero explicitly emits -0. Native NumericText76 emits UInt/Int integer Display and finite Float Display, preserving kind separately. First-party Pack JSON write_float_to at framework/pack/json Rust1193 emits -0.0/0.0, finite fixed decimals or scientific notation using its own correctly-rounded digits. That private helper is an authority for JSON spelling, not an exported Chart companion formatter. It must not be silently treated as identical to JavaScript String.

Choose closed language-neutral lexical admission rather than parse-and-reformat equality. UInt: `0|[1-9][0-9]*`. Int: `0|-?[1-9][0-9]*`, excluding -0. Float: `-?(0|[1-9][0-9]*)(\.[0-9]+)?([eE][+-]?(0|[1-9][0-9]*))?`. Require entire input match, finite parsed binary64 and the admitted exact text byte bound; then check integer width. This admits current -0 and -0.0, ordinary integer-looking Float120, finite scientific Source1e+21 and Rust1e21/1e-7, while refusing every Root malformed lexical case. Multiple valid decimal/scientific representations are deliberately admitted; unique canonical output spelling is a separate producer normalization contract.

Additional unsafe current parser forms: Source Number accepts empty string, whitespace-only, tabs/newlines, .5, 1., hexadecimal/binary/octal prefixes. Both parsers admit positive plus or redundant leading zeros in some variants. Explicit exponent forms 1e, 1e+, repeated signs and incomplete decimal must refuse. Float overflow must refuse even if readable REAL is valid. An underflowing finite decimal is rounded by binary64 parsing; if exact preservation of nonzero decimal semantics is intended, separately refuse nonzero mantissa parsed to zero instead of pretending it is an exact binary64 companion. Current producer spellings never require that underflow concession.

Validate companion first. If valid companion's parsed numeric value equals readable REAL, retain native UInt/Int/Float variant and Float sign word from companion (including -0 when REAL zero sign is not retained). Otherwise accept readable finite REAL as an authored Float replacement, then apply domain positivity/bounds. Invalid or out-of-width companions never reach that stale-edit branch. Source must continue refusing unsafe integers when the exact integer itself would be represented; it cannot invent Native integer precision.
