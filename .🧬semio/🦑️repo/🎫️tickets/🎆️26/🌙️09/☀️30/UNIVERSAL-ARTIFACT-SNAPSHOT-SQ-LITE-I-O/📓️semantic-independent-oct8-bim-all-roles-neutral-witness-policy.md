## Factual Numeric and Optional Policy

The actual neutral `.../🧬️schema/🔣️.json` has no minimum/maximum anywhere in its definitions. Positive geometry expectations and RGB0..1 docstrings are not persistence constraints. Width, depth, height, density, bulge, angle and color remain unconstrained numbers; do not refuse negative/zero solely because inference would diagnose them. The neutral schema permits unbounded integer panes/level/property.Integer, while Rust panes is u32 and level/property.Integer are i32. This is an actual cross-language representability mismatch requiring an explicit schema-first decision, not provider truncation. Preserve exact integer checks; never cast/saturate/wrap out-of-range values.

Rust all geometric scalars are f64 and have no constructor-level finite wrapper. JSON fixtures cannot spell NaN or infinity; ordinary JSON Schema numbers supply finite neutral witnesses, while Native f64 values can represent all IEEE words. Do not conclude nonfinite Native snapshots are invalid from JSON syntax alone. For a total Native provider, use exact scalar IEEE bits/class, finite REAL and nonfinite NULL, preserving signed zero via bits authority. A finite-only domain decision requires explicit defining schema/constructor agreement before narrowing. The present positive witness does not qualify nonfinite behavior.

Source ModelSnapshot maps are optional, Native defaults omitted maps to empty BTreeMaps. Project.phase_names and many nested Vec fields default empty. Choose a documented canonical empty normalization across both implementations; do not accidentally preserve optional top-level map presence only in one language. Actual nested Option fields cut_height, slope, opening sill_override/width/height and railing baluster permit omission, not explicit JSON null. Presence must distinguish absent from present zero and from present empty child collections. Do not substitute cut_height1.2 or inferred window sill during persistence.
