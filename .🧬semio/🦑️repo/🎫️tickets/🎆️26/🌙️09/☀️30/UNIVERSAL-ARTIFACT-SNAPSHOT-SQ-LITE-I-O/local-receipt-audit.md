## Evidence and Frontiers

- Value `🛬️decode/🫴️recipient/🦀️.rs` and Encode sibling use private identity fields and checked `AtomicU64::fetch_update`; identities are not reused on overflow (creation panics). There is no heap registry. Separate decode/encode counters are sound because detached receipt types and bind arguments cannot cross directions. Safe external callers cannot forge the scalar identity or clone receipts.
- Both `🫴️recipient/🔁️continuation/🦀️.rs` modules preserve the same scalar accounting and borrow the actual recipient. `bind` rejects mismatched identity with `(error,self)`, including an empty replacement, and permits the occupied original recipient. Rust lifetimes prevent use of that recipient while bound. The detached receipt owns only scalar identity: callers must explicitly retain the actual recipient until terminal-empty.
- Both hop methods take the receipt before `Control::resume(...)?`. A resume validation error therefore leaves `receipt=None`; subsequent detach/accounting observations panic. This is reachable through a public same-stage hop: begin a nonzero declared workload before pause, then call `advance` beyond that workload inside the hop without beginning a new stage. `advance` mutates completed before returning WorkLimit; `StageScope::drop` restores parent only if stage changed. The hop continuation check errors but Scope stores completed>total. The next hop takes that invalid receipt and loses it on resume refusal. Validate while the receipt remains in its slot, or use a consuming resume error that returns the original receipt. Do not describe validation/resume refusal custody as complete yet.
- Scope restores accounting after operation errors and unwinding once resume succeeds. `close_retirement_recipient` preflights depth/copy/capacity/release, checks cancellation, then charges original cumulative capacity before actual close. A denied close can preserve ownership while retaining a legitimate admitted capacity charge if a later close step errors; counters must not be rolled back arbitrarily.
- Initial `with_retirement_recipient` accepts any empty recipient because the unbound receipt carries no recipient identity. This is an initial installation mechanism, not proof that it was previously associated with that recipient. Encode `into_parts` intentionally erases the identity binding by exposing the scalar receipt; it cannot move an occupied original into a different recipient through the empty-recipient check, but it permits a new initial binding after emptiness. Claims must remain scoped to detached receipt custody.

## Native Physical Test Claim

The source checks original address, mismatched-bind refusal with intact receipt, denied zero-item close, cumulative allocation, and exact inner release `wrapper + textBytes + born`. The String is real backing and the ControlledRetirement wrapper is real, rather than a scalar mock. `serde_json` independently confirms UTF-8 payload length.

The test charges `size_of::<Recipient>()` and creates `Box<Recipient>`, but releases that outer box through plain `drop(recipient)` after merely asserting the close grant is large enough. It does not record outer recipient release in a physical close witness. The current exact equality proves inner returned owner release only. Strengthen the test with an explicit original-grant final box-release event and include those bytes in the terminal witness before asserting complete release of all charged backing. The source audit cannot claim either test passed.

## Probe JSON Caller Adoption

`🧰️framework/🛍️products/💻️os/🔨️modules/🌉️mcp/🏠️workspace/🚪️io/🔤️json/🦀️.rs:78-98` creates stack recipients in plain parse/print, runs read/write, then uses `?` for close errors and a 100000-turn cutoff. Either path can return with a nonempty stack recipient; its Drop then asserts and keeps its ManuallyDrop owner unreleased. The loop bound is not a terminal witness.

Adopt a genuine owned caller session: before any JSON receiving allocation, the existing workspace/request owner admits and allocates the recipient box, retains that same box alongside the detached consuming receipt, and separately retains the output/refusal. Each request close turn binds that exact recipient and uses the original grant/cumulative ceiling. On refusal, cancellation, or exhausted work, the session remains in that caller's already-priced lifecycle and exposes its actual next demand. Completion publishes the result only when required auxiliary retirement is terminal; final recipient-box release receives its own item/release grant and witness. Use the current read/write owner interfaces to build this session, then make plain caller sites explicitly adopt or drive it. A function returning only Result cannot export unfinished retirement custody without changing caller ownership/API or proving a finite funded terminal close for every admitted input. Fresh controls, an infinite drain, and a global unpriced owner map do not resolve this frontier.
