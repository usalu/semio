## Separate Input Ledger Revision

Fresh control source now retains separate finite cumulative input credit in CommandContext. It creates an InputClaim before reserve, rejects canceled authority before allocation, checks exact Vec capacity, initializes/reads in 4096-byte pages, and retains live credit through CommandBytes/CommandText. Vec-to-String conversion transfers backing without cloning. Regular failure unwinds bytes then claim and releases live ownership. Cumulative credit remains spent after release by design. Author reports actual direct Native law execution; this auditor did not run it.

Concrete panic gap reported to author: InputClaim is constructed before admission observer invocation. If that observer panics, its Drop invokes the same observer again during unwinding; a second panic aborts the process. A transport observer panic while the input claim lives has the same possible cleanup issue. Drop should always release ledger credit and avoid arbitrary callback invocation while already panicking, or provide a deliberate typed panic handling contract. Add a genuine observer-panic settlement law. No panic-safe claim is granted by normal success/cancellation evidence.

Stdin helper is now named enable_process_stdin_cancellation, reflecting its native process lifetime scope; blocking shutdown remains distinct from live input ownership.

Mounted panic repair readback: InputClaim Drop releases live ledger credit before checking `std::thread::panicking()`, and skips the arbitrary observer during unwind. The concrete double-panic gap above is resolved statically.
