# Controlled Value Construction

The canonical neutral Value codec now exposes `FromValue::from_value_controlled(&DslValue, &mut NativeDecodeControl) -> Result<Self, ValueError>`. Its default publishes a cancellation checkpoint and refuses a missing constructor. It never clones the input and invokes ordinary `from_value` as a fallback. Handwritten domain converters remain explicit owners.

The primitive and collection implementations admit copied UTF-8/octet buffers, vector slots, boxed storage, hash tables, tree insertion storage and borrowed-key validation indexes before allocation. One cumulative `NativeDecodeControl` survives physical parsing and typed construction. Containers preserve wire order while constructing children and publish interior work every 256 units. Collection errors identify the first wire index. Map keys use `from_object_key_controlled`; arbitrary `FromStr` conversions are refused until their owner implements this controlled key hook. HashSet builder construction similarly requires an explicit `ControlledValueHasher`; the standard `RandomState` is authored. Membership is unordered and has no stable array-index API.

The intrinsic Value copier uses an admitted iterative frontier, retaining ordered object keys (including duplicates), nested arrays, exact binary64 Number words and intrinsic Bytes. A 2,048-level neutral tree exercises success and interior cancellation. Its retirement delegates to the existing first-party `RetireOwned` cursor, pumped iteratively; it does not use recursive intrinsic drop.

Derived constructors read borrowed fields individually. External, internal and adjacent enum tags, field/variant renaming, required/default/optional fields, transparent newtypes, skipped fields, flattened payloads, custom converters and denied unknown fields retain their declared meaning. Only the selected flattened or internally-tagged payload is materialized when the existing owned intrinsic interface needs a filtered object, and that materialization uses the same cumulative control. Missing/custom defaults cannot call arbitrary ordinary allocators: `default_controlled` declares their admitted constructor. A custom converter declares `deserialize_controlled_with` and its field's `retire_with`; `with` alone does not authorize an ordinary fallback. Primitive/container zero-allocation defaults are implemented directly.

Partial children are held by `DecodedValue<T>`, with an explicit retirement function and no broad `Send`, `'static` or `RetireOwned` bound. Standard containers and derived records delegate to each child's `FromValue::retire_decoded`. Recursive generated owners require `#[value(retire_with = "...")]`; otherwise construction refuses. Generated recursion independently enforces 64 typed layers through `NativeDecodeControl::scoped_depth`, even for caller-built intrinsic values that bypass physical parsing. Iterative intrinsic construction has no such 64-layer ceiling. Real Drop owners use an explicit whole-owner retirement function, preserving their destructor policy rather than moving fields out of a Drop type.

The directory credential owners were repaired by the coordinating agent with explicit whole-owner drop retirement after inspecting their wipe implementations. The shared Drop-owner test verifies successful ownership and later-field failure execute that real destructor. The external team's HashSet neutral/retirement laws and input/schema additions were retained and reconciled with this worker's representation, attribute, depth, exact-word and allocation fixtures.
