## Concrete remaining findings

1. **HTML first-body parity divergence.** In `✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🌐️html/🏅️standards/🔖️5/🪆️subsets/✳️any/🧬️schema/📸️snapshot/🚦️native/🦀️.rs`, function `normalize`, the root-child loop assigns `body=Some((position,id))` for every matching body, selecting the last. Ordinary snapshot `🦀️.rs` function `normalize_html_root_whitespace` uses `children.iter().position`, selecting the first. Owner-parsable `<html><body>a</body><body>b</body> </html>` sends final space to first body in ordinary decoder and last body in controlled decoder. This is proven source divergence; no runtime reproduction was performed. Select first body via get_or_insert and add actual external parity edge law.

2. **Caller ledger reset in TIFF/HTML native decoding.** Both native decode entry points instantiate `NativeDecodeControl::new(limits.max_value_bytes,...)` and do not use `reconstruction_remaining_bytes()` or publish consumed ownership through `admit_reconstruction_bytes()`. Concrete admission is cumulative within one invocation, but retained native objects from repeated decode calls on the same SqliteSnapshotControl are not cumulatively counted. Other current owned modules explicitly publish this ledger. This is a definite source omission; runtime refusal/usage assertions for repeated retained inputs remain needed. Do not infer that within-call byte accounting is missing: all major native field containers and copies are paid locally.

3. **HTML native exact returned-row ceiling overcounts normalized whitespace.** Reader increments rows for parsed whitespace text nodes before normalization. Leading whitespace nodes are dropped and trailing whitespace nodes may merge into an existing body text node; `reader.rows` is not adjusted. Therefore max_rows equal to final normalized owned snapshot domain can refuse input with removed/merged whitespace. If max_rows intentionally bounds transient parsed entities instead, document that differing scope; TIFF currently promises final normalized domain rows. This is source-only logic, not an existing-law runtime failure.

4. **HTML incomplete partial SQL reconstruction retirement.** Semantic `🪶️sqlite/🦀️.rs` builds nested HtmlNode trees in plain `BTreeMap` and temporary child vectors. Cancellation/error before return recursively drops those trees; the public OwnedSqliteSnapshot guard only starts after `from_sqlite_database` succeeds. Late schema/doctype reconstruction cancellation after building a deep root has the same recursive-drop path. Native construction uses Forest guards and iterative retirement correctly, but these guards do not protect SQL reconstruction. Wrap partial SQL trees and transitional child ownership with the iterative retirement guard.

5. **HTML retirement scratch is unbounded/unadmitted.** Native module `retire_node` creates `vec![root]` and appends entire child arrays to `pending`, potentially reallocating O(width) work storage during failure cleanup. This prevents recursive deep destruction, but is not an allocation-free or explicitly admitted cleanup bound; there is no caller control available there. Normal successful public retirement also uses it. Do not claim cleanup allocation admission from parser allocation checks.
