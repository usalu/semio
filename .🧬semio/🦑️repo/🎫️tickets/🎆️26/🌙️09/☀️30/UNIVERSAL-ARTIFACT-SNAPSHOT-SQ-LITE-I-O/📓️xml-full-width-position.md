# XML Full-Width Position

The native XML snapshot currently stores doctype prolog_position as platform usize, its relational provider casts it to signed SQLite INTEGER, and the TypeScript owner permits only safe numeric positions. That loses/refuses legitimate owned values independently of ordinary XML wire constraints. Office shares this same typed document authority.

The canonical proposed domain is u64 in Rust, bigint in TypeScript, and a literal canonical decimal TEXT scalar named prolog_position_decimal in each explicitly authored XML table. JSON boundaries use the exact decimal string. This is an interpreted scalar, not opaque snapshot data. Ordinary XML validity continues to require the position to fit the actual prolog list. Wildcard logical snapshots may retain intermediate positions.

A neutral schema/fixture includes zero, the first unsafe JavaScript integer, the first unsigned value above SQLite i64, and u64::MAX, plus invalid/noncanonical decimals. The native law queries the explicit scalar independently with Bun SQLite and checks typed reconstruction. The first owning registered runtime RED is pending.
