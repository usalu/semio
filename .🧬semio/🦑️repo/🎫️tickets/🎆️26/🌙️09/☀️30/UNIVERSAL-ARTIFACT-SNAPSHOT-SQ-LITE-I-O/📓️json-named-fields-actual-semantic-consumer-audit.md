## GIS Terrain: imported map descriptor

Root `✏️s/🔌️plugins/🌍️gis/🗿️artifacts/🏔️gisterrain`. Standard1/any editor import_media at589–604 accepts `map:in` Structured JSON and clones it into ChangeImportedFeatures. Inferences `🧬️schema/💡️inferences/🦀️.rs:171–189` parses imported_features_json with serde_json, reads a positions array, and extracts each id/lon/lat/optional label/icon into TerrainPositionData. Bounds facet explicitly reads longitude/latitude pairs. Editor125 likewise parses it into importedFeatures for rendering; root content-key71 hashes its source string together with exaggeration.

Current SQL parameters table stores only imported_features_json TEXT; Rust and TS providers own the text directly, without relational positions/routes/regions. Existing Source independent plain-text edit and mutation tests prove exact source retention, including empty and literal null, not semantic map coverage. Imported structured pin positions are thus opaque serialized semantic data in the current schema.

Required handcrafted domain relations should include imported descriptor ownership, ordered position rows, id, longitude/latitude exact IEEE companions, nullable label/icon, and authored route/region relationships when their full actual accepted descriptor domain is closed. Arbitrary accepted extras require a faithful first-party flat value/member relation rather than a new serialized cell. Keep source text only as an explicitly independent original document where exact formatting, malformed source or null is actual retained state; it cannot be the sole authority for valid semantic positions. Current malformed/empty input contributes no pins, so designing an absent/invalid source state is required instead of silently canonicalizing away that state.

## Layout: named form dictionary

Editor1455–1471 describes and implements fields:in as a form.dictionary named data source, accepting Structured JSON and copying it into ChangeDataFields. Mutation tests explicitly preserve an opaque whole-field payload such as client/acme. Export engine3351–3364 applies JsonValidationCursor to that retained source; export1273–1274 embeds it as dataFieldsJson, and owner-source1035 reads the string.

This is structured dictionary ownership, even though interpolation into frames is not yet implemented. Current layout_document data_fields_json TEXT preserves optional raw source only; it exposes no dictionary entries. A faithful schema needs optional data-source owner plus ordered member/value relations with first-party scalar variants, exact integer/IEEE representation, and explicit object duplicate/member policy. Preserve absence separately from JSON null. Any source-document field must be ancillary original-source authority with clear parsing status, not substitute for dictionary relations. Current export validates general JSON, while the port advertises object semantics; that accepted-domain inconsistency must be settled by authored schema/tests before narrowing it to a map and losing currently retained arrays or malformed text.
