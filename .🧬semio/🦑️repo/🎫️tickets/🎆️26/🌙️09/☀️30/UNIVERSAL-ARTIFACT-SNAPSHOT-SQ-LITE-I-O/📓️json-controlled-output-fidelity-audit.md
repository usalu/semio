# JSON Controlled Output Fidelity Audit

Read-only inspection on 2026-10-03. No tests, compiler, runtime, Cargo, or Git operations were run by this auditor. Findings below are source observations and proposed validation, not runtime proof. Files may change concurrently.

## Actionable Findings

1. **The output owner is unmounted in the inspected source.** The JSON SQLite trait implementation defines controlled native decoding but does not override `encode_sqlite_snapshot_native`; `owned_pack` mounts only `decoding`. The store trait default returns `snapshot owner has no controlled native encoding implementation`. Mount the typed draft as the encode module and override the trait method only after the registered test reports the intended failure. This prevents the erased SQLite import callback from emitting either native format. Store `sqlite_codec` import reconstructs the semantic snapshot and calls its native output owner, so mounting a helper without the trait override is insufficient.

2. **One-slot exact reservation makes large projections vulnerable to quadratic allocator copying.** Draft `push` calls `try_reserve_exact(1)` on every enqueue and every node append. Rust provides no geometric-growth guarantee for that API: a moving allocator may copy the entire growing frontier on each iteration. Those copies occur inside a single allocator operation with no cancellation boundary and are not represented by the linear `step` count. Use a paid capacity-growth helper: calculate a bounded geometric target, charge the additional slots before reservation, and reserve that delta. Keep cumulative charges across projection and typed record conversion. Validate a broad many-node tree in addition to the deep-chain test; this is a performance and cancellation-boundary risk, not a demonstrated allocation failure.

3. **The 17th test cannot distinguish projection cancellation from physical writer cancellation.** Its cancellation filter selects `EncodeNative`, `total == schema.len()`, and an interior byte boundary. The draft copies the schema through `NativeEncodeControl::copy_text` before `__dsl_to_record_controlled` and before either physical writer. That copy publishes exactly the selected event and can satisfy both Binary and Text cancellation assertions. Keep this as projection Unicode coverage, but add a focused writer-level cancellation law if the claim is cancellation during actual pack/text output. The fixture schema includes multibyte text and NUL, so Unicode fidelity coverage itself is meaningful.

## Fidelity and Ownership Observations

- Domain authority is `JsonSnapshot { schema, value }`; numbers own arbitrary `String` lexemes, members own an ordered vector, and duplicate keys are allowed. The semantic SQLite provider owns four tables and derives nullable finite numeric query cells separately. It intentionally admits arbitrary intermediate lexemes; rejecting `NaN`, unusual numeric spelling, or duplicate keys in the output projection would lose valid typed state. Named subset validators own stricter semantic guards.
- The draft uses the same authored `Snapshot`, `Node`, `Member`, and `Kind` types as the existing pack/DSL authority. It preserves fields rather than rebuilding an independent dynamic schema. Existing decoder field identities are snapshot 0/1; node 0 through 5; member 0/1. Child references remain explicit `u64`; draft conversion checks `usize` to `u64` rather than routing indices through IEEE values.
- Breadth-first child indexing by `pending.len()` agrees with the previous `next` counter. Parents precede children; sibling order and duplicate-member order are retained. Native decode admission checks exact fields, variant payload exclusivity, strictly forward references, unique ownership, and presence of every node before reconstruction. Flat projected objects contain no recursive owned `JsonValue`, so dropping projection or its partial nodes on refusal does not recursively destroy the borrowed source tree.
- Native encoding control charges text, vector slots, schema production, typed record construction, physical bytes, and envelope output cumulatively. `begin_stage` resets work counts, not ownership. The helper passes the same controller through all these stages; neither draft projection nor its final conversion creates a fresh controller.
- The draft starts unknown-length projection work with total zero, checks row growth before child reservation, copies Unicode in bounded chunks, and publishes linear node/edge checkpoints. Row count is `1 document + N values + N-1 edges = 2N`; draft starting at two and adding twice each child agrees with semantic tables and controlled decode admission.
- The new test compares reconstructed semantic tables after both native encodings and includes typed number fixtures, duplicate members, deep topology, caller row limits, caller value limits, and multibyte/NUL schema content. It does not independently prove unsigned boundaries or writer-only cancellation. Existing handwritten topology tests cover dangling/backward references and repeated owners.
