## Reference Membership Is A Real Remaining Seam

STEP project_value requires a resolved target INTEGER and refuses dangling references, so semantic target cost is always8 for an admissible STEP snapshot. Counting8 needs no identity allocation or lookup; real SQL projection and original pretyped graph validation retain dangling/duplicate rejection.

IFC4 and IFC2x3 explicitly use INTEGER8 for a resolved reference and NULL0 for an unresolved reference. Therefore a fixed8 census is incorrect, and fixed0 under-admits. Their arbitrary authored entity arrays have no sorted invariant in the inspected projection: visit_rows explicitly constructs and sorts its own identity frontier. Binary-searching the unsorted owner arrays is invalid. No allocation-free general efficient membership API was found in the inspected backing/projection sources. A per-reference linear scan is exact but worst-case quadratic; it is not the requested performance solution. Do not claim the STEP solution automatically resolves this IFC seam.
