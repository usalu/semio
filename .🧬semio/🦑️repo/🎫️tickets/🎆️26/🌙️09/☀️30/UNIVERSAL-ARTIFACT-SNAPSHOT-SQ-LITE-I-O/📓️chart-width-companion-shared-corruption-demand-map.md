# Chart Width Companion Shared Corruption Demand Map

Read-only demand input in 📥️inputs/chart-width-companion-corruption-cases.json, nineteen SQL cases against the actual chart_document width/width_kind/width_exact triplet. Each begins from full-domain width120 UInt exact120. Width remains positive in malformed-companion cases, so refusal cannot be accidentally attributed to the domain width bound.

Four accepted cases preserve UInt120, replace readable REAL alone with Float125, or explicitly replace all three cells with UInt125/Int125. Fifteen refusal cases require validation of companion kind, canonical spelling, finite IEEE admission and integer width before the existing REAL-mismatch authored-edit branch. A stale companion remains an accepted REAL-only edit only when that original companion is itself valid. Unknown kinds, leading plus/zero/whitespace, hex, unsigned negative zero, out-of-width integers and nonfinite floats must not be repaired into Float merely because width is still120.

Canonical rejection is a new shared spelling demand: current Source Number(exact) and integer regular expression accept several malformed spellings; current Native parse accepts leading plus/zero. No runtime witness is claimed here. Exact scientific spelling cannot truthfully be pinned to a new literal while current Native default Display and Source String have no agreed cross-implementation canonical formatting recipe. The input therefore carries a precise preservation law over the producer-emitted companion, requiring same Float word and stable reprojection; the owner must choose and pin the shared scientific formatter before a fixed spelling oracle is added.
