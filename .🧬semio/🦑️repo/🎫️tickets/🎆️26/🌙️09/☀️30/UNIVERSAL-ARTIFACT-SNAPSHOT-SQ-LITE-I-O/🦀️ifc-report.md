# IFC Semantic SQLite Provider Evidence

IFC4 and IFC2x3 use independent handwritten domain schemas. IFC4 has eleven tables for its full header values, entities, complex types, positional arguments and value ownership. IFC2x3 has twelve tables for its full Part21 document, entity type pairs, exact decimal components and all sixteen optional EDM production fields. Values remain typed semantic columns; reference instance words have explicit entity foreign keys. Value containment is a single-owner acyclic forest; entity references may form cycles. Header member order, empty collections, optional EDM absence, duplicate schema entries and unsigned64 instance identity are preserved.

IFC4 binary64 values retain signed INTEGER IEEE words, numeric class and nullable numeric query columns. IFC2x3 decimals retain boolean sign, arbitrary coefficient digits including leading zeroes, exact unsigned32 scale and optional signed32 exponent. SQLite never formats these decimals. The explicitly requested native Text seam preflights predicted decimal expansion before calling Display; binary native reconstruction retains full decimal components. Native Part21 IFC4 encoding rejects nonfinite numbers before conversion while owned typed SQLite preserves every IEEE word.

CV20, SAV and COBie validators are authored in their own domain schema modules and use controlled borrowed native header/instance scans. Diagnostics preserve existing codes, severity, text, span and scope. The exact named declaration bindings and five owned typed I/O routes are being verified; they are not claimed complete yet.
