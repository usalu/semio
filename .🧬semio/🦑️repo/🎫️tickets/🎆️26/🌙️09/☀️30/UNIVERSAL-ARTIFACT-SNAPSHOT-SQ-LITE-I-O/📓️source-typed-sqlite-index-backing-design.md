Proposed Source destination is framework SQLite snapshot `🧪️tests/🗂️typed-index`; relative imports in the input target that location. ## Table Index

Replace ArtifactSqliteProjection's findIndex at artifact helper45 with an actual open-addressing Uint32Array. Compute smallest power-of-two capacity >=2*tableCount, with minimum2 for a nonempty table set; zero tables need zero slots. Check capacity, bytes=capacity*4 and entry+1 sentinel arithmetic before allocation (safe integer and Uint32 representability), and reject impossible growth before bitwise shifts wrap. Obtain exactly that Uint8Array via the supplied operation.allocateBytes; construct a Uint32Array view over it, checking alignment/offset rather than assuming a view's alignment. Never allocate a second backing with Uint32Array(count).

Slots hold schema table index+1; zero is vacant. Every lookup reads that slot and compares the complete borrowed table name before returning. FNV1a over UTF16 code units is only a hash, never authority; ASCII folding is explicit for SQLite lookup. Probe at most capacity slots, checkpoint at <=256 probes, scan long names at bounded frontiers. Preserve current projection exact-name insertion semantics: hash can fold ASCII but equality for Projection stays exact unless an independently tested API change is separately authorized. Reconstruction equality uses existing SQLite ASCII folding, preserving Ä versus ä and all nonASCII code units. No locale lowercasing or normalized Unicode. Duplicate canonical names remain validation errors. Underlying schema/table references remain borrowed; slot backing performs every actual lookup and replaces findIndex/Map, rather than accompanying them unused.

Closed authored collision case is a/i/q in8 slots: all hash to bucket4; expected indices0/1/2 and unknown absent. Slot storage is exactly32 bytes from Uint32 width, not a JS object ABI estimate. Inputs also retain literal case/Unicode/quoted names. Existing long-name/reversed-table cancellation laws remain selected and must not be shortened.

## Row Ownership and Parent/Ordinal Index

Build per-table borrowed row census with checked prefix offsets and total rows. A used-row bitmap needs ceil(totalRows/32)*4 bytes; each consume addresses the actual bit, refuses a second consume, and final scan refuses unconsumed rows. Refuse repeated same-row object identity if semantic owners require it; a positional bitmap alone cannot reproduce existing Set<SqliteRow> identity checks when the same object appears in multiple tables. Schema alias/name/rowid validation remains before domain publication.

Parent index slots hold source row position+1 pointing to a representative borrowed row; compare complete bigint parent values from borrowed cells, never narrow them to Uint32/Number. Collision probes are bounded as above. Store actual group counts/prefix offsets/cursors in checked Uint32 backing and flattened source row positions in exactly totalRows*4 backing. For an ordinal group, write each source position+1 into its group's ordinal range; reject negative/out-of-range/duplicate/gap before exposing results. Parent singleton/missing-parent/cardinality and every row-consumption law remain domain-owned. Keep unused fields/table spaces refusal and fullIEEE words unchanged. Do not impose a new native identifier resolution rule on Block unresolved references.

The held neutral rows are parent1 ordinal2/0/1 and parent9 ordinal0, with expected source positions [2,3,0] and [1]; parent17 has no group. Position backing16 bytes and used bitmap4 bytes are exact array representation sizes. Group slot/count/offset allocations must be explicitly enumerated by implementation; this report does not pretend the listed position and bitmap bytes are the complete group index debit. No guessed Map/Set/Array credits are permitted. Returned plain arrays may remain semantic API outputs, but this typed scratch proposal does not prove total JavaScript heap allocation ownership.

## Held Demands and Limits

The Source capsule contains independent Ajv closure/extra-key rejection, Map collision answers, Uint32 representation width, independent BunSQLite table queries and independently sorted parent/ordinal answers. Its two actual semantic directions call existing Projection/artifactSqliteTables, preserve full outputs, demand positive actual slot backing and observed exact/minus-one/two-call cumulative refusal. These are runtime tests to be mounted and run by Root, not receipts.

The closed fixture lists all row refusal and cancellation roles, but executable row-index integration demands are still needed once a named public firstparty row-index seam is selected. No invented API is supplied. In particular parent-collision, repeated identity, bitmap final scan, long-name/row-interior cancellation and overflow laws must reach the actual index. Existing frontier tests provide long-name/census cancellation but not all new typed row paths. This capsule is ready as the table-index test-first baseline, not a complete row-index suite. Mutable snapshot capture before async callbacks and schema parser's uncharged token/string objects remain separate ownership work; this index must not be advertised as resolving all Source physical storage.

Caller identity: create one sqliteOperation at each domain entry; pass the same operation to every schema/index/projection/reconstruction stage. Direct allocateBytes already preserves monotonic admission; child controls require the narrow existing-finally allocationStage bridge. Failure/cancellation cannot refund admitted backing. Cancellation before admission costs zero; cancellation after actual allocated index storage retains its debit. No full JS diagnostic/release equality is inferred from these laws.
