# Original Operation Fingerprint Source

The actual Store currently creates a contiguous length-prefixed fingerprint, then copies it into child/invocation payloads, then VCS copies the complete domain-prefixed hash input. The held source contract preserves these exact original octets while allowing actual borrowed `OperationSourceCollection` spans to feed controlled output or the existing first-party incremental hash directly. It never replaces the raw fingerprint by a digest, and it provides no Vec source implementation or flattening constructor.

Inputs `operation-fingerprint-source-contract-held.json`, `operation-fingerprint-source-provider-held.rs`, `operation-fingerprint-source-fixture.json` and schema are retained inside `📥️inputs/child-paged-complete-family`. No source provider or owning demand is mounted; no Native, allocator, digest, ID, actual Store staging or inverse/undo/redo credit exists. The complete production family remains held.

Fresh strict Ajv/TextEncoder/DataView/SQLite oracle validates the original padded8194 and binary4 sources, original little-endian u64 length prefixes, empty/one/two/reversed collection preimages of0/8202/8214/8214 bytes, distinct source ordering and the exact child envelope around that raw fingerprint. The new test initially miscounted the child envelope as22 bytes and failed its own premise. The corrected envelope has23 bytes: domain5 + zero1 + parent6 + zero1 + slot4 + zero1 + trailing zero1 + ordinal4. The first failure is invalid new-test arithmetic, not existing-provider evidence. Both logs are retained separately under generated; corrected oracle exits0.

The caller owns the accepted output prefix and original immutable sources on every result. Refusal must not grant a completed fingerprint/identifier. A hash output can remain stack-owned and retain no original payload; an owned byte output must retain its real partial pages for explicit retirement. Invocation additionally needs stable original child-ID byte ordering, with its actual sort metadata and semantic text lifetime retained independently. Those joins and their actual all-caller Before/After gates remain required before production activation.

A concrete held owning demand now exists in `operation-fingerprint-source-law-held.rs`. It constructs the original8194 plus binary4 directly in real paged operation owners and an actual paged outer collection; no old Vec source is created. All four neutral source orders compare every raw prefix/body octet. Original input pointers and allocation totals remain invariant across independently controlled output success/refusal. Missing ordinal, one-short output, real initial4096 and interior256 cancellation retain their actual prefix for explicit1/4096 disposal. The empty fingerprint compares against the real empty ByteSpan with zero output ownership: `OwnedOperationBytes` deliberately refuses zero payload authority, so the demand does not invent a one-byte carrier for an absent output. Neither demand nor provider is mounted; the authenticated native Before/After and actual Store joins remain pending.
