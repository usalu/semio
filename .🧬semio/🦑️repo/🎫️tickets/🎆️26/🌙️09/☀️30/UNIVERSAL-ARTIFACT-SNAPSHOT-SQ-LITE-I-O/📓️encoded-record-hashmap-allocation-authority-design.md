# EncodedRecord HashMap Allocation Authority Design

Read-only canonical source/witness inspection; no Cargo, source/API/script changes, or ABI assumptions.

Actual `🧰️framework/🔨️modules/🗣️dsl/🧬️schema/🛫️encode/🦀️.rs` EncodedRecord::new28 charges `count * (size_of::<(u16,FieldValue)>() + 128)` then creates RecordValue.fields and calls HashMap::try_reserve(count). RecordValue.fields is actual HashMap<u16,FieldValue>, not Vec. This expression is a guessed per-entry overhead allowance, not an exposed allocator request from the actual hash table. Its docstring claiming complete known frontier is stronger than its demonstrated authority. Overflow and reserve errors are already typed OwnershipLimit/AllocationFailed; the concern is paid byte amount, not kind classification.

No current request witness was found for this constructor. Cardinalities0,1,3 and large counts must be measured directly: HashMap capacity rounding, control storage/alignment and growth mean logical item count does not reveal requested allocation layout. No numerical undercharge is asserted without the actual allocator receipt. A large per-entry constant might overpay some sizes and still cannot prove all bucket transitions; count0 needs its own actual zero-request witness. Generated Flow records reach this canonical producer, so full Flow runtime success alone cannot establish truthful allocation admission.

Existing actual DSL test allocator at `🧰️framework/🔨️modules/🗣️dsl/🧬️schema/🧪️tests/🫳️borrowed-object/🦀️.rs` observes alloc/alloc_zeroed layout size and realloc full new request size on one enabled thread. Its current law tests borrowed object print bounds, not EncodedRecord. Existing first-party trace test request observer at `🧰️framework/🔨️modules/⏱️trace/🧮️memory/🧪️testing/📥️requests/🦀️.rs` provides stack-owned nested observation and unwind restoration. Reuse an existing test-only witness behind its current interface; avoid a second conflicting global allocator or new runtime dependency.

Future authored language-neutral fixture should close cardinalities `[0,1,3,4,7,8,15,16,255,256,4095]`, primitive field values that allocate no payload, distinct u16 field identifiers, exact/minus-one/zero/cumulative policies, expected canonical OwnershipLimit/AllocationFailed/Canceled, and literal logical field equality. Do not encode bucket ABI sizes as fixture constants. Independent SQLite can retain/count ordered field-id/value rows to validate logical record fidelity; it cannot serve as the hash-table byte oracle. Actual Native allocator requests are the byte authority.

Future narrow Native law: prepare fixture/callback/control/observing scope before measurement; isolate EncodedRecord::new(count) and declared primitive insertions; capture actual cumulative alloc/zeroed/realloc request sizes separately from error formatting or fixture construction. Compare the producer admission ledger with observed requests, recording both exact and conservative-bound contracts explicitly. For an exact admitted-request API, measured request ceiling must succeed; minus-one must refuse before any refused backing request; zero must permit only genuinely allocation-free count0; repeated constructions must settle cumulatively without retirement refund. For a conservative ceiling API, assert observed requests never exceed pre-admitted bytes and report the overhead honestly instead of asserting equality to logical entry count. Include all bucket-boundary sizes and complete guarded retirement on error/cancellation. A runtime denied allocator witness must prove refusal happens before actual allocation; a ledger-only assertion mirrors the implementation and is insufficient.

EncodedRecord::insert has no separate payment if callers exceed reserved unique-field count; future witness should separately cover whether actual descriptor-generated insertion count guarantees the admitted frontier. This is a design gate, not a proved current Flow input violation or permission to rewrite owner layouts. Canonical fix remains Root-authorized future work.
