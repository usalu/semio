# Rust HTML and SVG Semantic SQLite Providers

HTML's own native model has an eight-table handwritten schema: document, node, element, text, comment, raw text, attribute and child. Optional doctype, boolean versus empty-valued attributes, raw-text script/style kind, element names, ordered children and all native variants remain explicit scalar fields or foreign-key relationships. It does not use XML's AST or a generic markup fallback.

SVG's persisted native model is schema plus the shared typed XmlDocument. It owns thirteen svg_* tables and handwritten DDL, with explicit SVG root validity and preservation of every document node, ordered attribute/child, boundary, declaration quote/optional fields, doctype identifier/placement and entity field. Root approved sharing only the typed XmlDocument traversal: public `XmlSqliteTables` has thirteen named table fields; `project_xml_document` and `reconstruct_xml_document` operate directly on borrowed typed fields and exact declared SQL. XML retains its own thirteen xml_* tables. No database renaming adapter, reflection, native text/state blob or generic artifact mapping was introduced.

Both providers apply shared declared-schema and resource guards, reject missing/wrong typed components, dangling and multiply owned nodes, cycles, disconnected graphs and noncontiguous ordinals. Budgets precede output allocations; iterative traversals and controls checkpoint counting, validation, output construction and expensive copies/sorting.
