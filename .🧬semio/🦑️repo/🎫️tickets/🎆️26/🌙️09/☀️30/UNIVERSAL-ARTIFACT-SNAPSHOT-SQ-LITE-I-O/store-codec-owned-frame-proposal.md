# Store Codec Owned Frame Proposal

Read-only 2026-10-09 source audit; no builds or edits to source. Store codec export/import and synchronous OwnedSqliteSnapshot behavior are detailed in receiving-owner-inventory-next.md.

## Exact Existing Receiving API

`🧰️framework/🔨️modules/🚪️io/⏱️control/🦀️.rs:57` and `🛫️snapshot/🦀️.rs:112` expose direction-specific `receive_nested<T:RetireOwned,O:RetireOwned>(|slot:&mut Option<T>, nested:&mut NativeSnapshot{Decode,Encode}Owner| -> Result<O,ValueError>)`. The nested owner retains failed child receiving frames in its parent's actual pending slot. The underlying receive (snapshot file 115) pre-admits boxed frame bytes, one item and parent/child depth before the closure runs, adopts successful output, drains pending/intermediate owners under the original remaining grant, and only then extracts output and witnesses frame release. If cleanup/publication refuses, output remains in the same physical recipient.

Use this existing API for a codec frame; do not wrap codec operations in a new NativeControl. `NativeSnapshotReceiving` already provides ErasedSnapshotRetirement demand/close methods and retains pending children before intermediate then output. The frame's concrete fields need first-party RetireOwned.

## Retirement Contracts

No `SnapshotRetireOwned` identifier was found in current Rust source. The actual contract is `semio_framework_value::retirement::RetireOwned: Send + 'static`, including controlled_retirement_supported and genuine demand/birth accounting. The generic snapshot bound must include it (on sqlite_codec / its internal implementations, or the artifact snapshot trait itself), and receiving admission must reject unsupported owners before decode/construction. A schema's private snapshot type may derive/implement real retirement independently of its public artifact type; review all actual fields. Do not assert support just because ArtifactDsl/Pack exists.

FromValue `🌱️value/🔁️codec/🦀️.rs:88-91` exposes guard_decoded and retire_decoded, defaulting to synchronous drop. ArtifactSqliteSnapshot::retire_sqlite_snapshot likewise defaults to drop and many overrides synchronously invoke FromValue retirement. Neither is an ErasedSnapshotRetirement port with five-field grants; do not create a RetireOwned adapter whose close invokes that entire callback in one item. Replace generic codec reliance on `OwnedSqliteSnapshot::drop` with actual frame field retirement.

SqliteDatabase and IoPayload have real RetireOwned support. `🚪️io/🧬️schema/♻️retirement/🦀️.rs` implements RetireOwned for IoOutcome<T> with value and diagnostic authorities. Value `♻️retirement/⚖️result/🦀️.rs:24` implements RetireOwned for Result<T,E>. IoError currently has cause plus diagnostics but no RetireOwned implementation was found; add its first-party field retirement, preserving both exact original fields.

## Typed Frame and Error Preservation

Export frame needs original decoded P and projected SqliteDatabase and validation outcome/diagnostics slots. Import frame needs original input database, reconstructed P, encoded IoPayload and validation outcome/diagnostics slots. Adopt each successful child into its slot immediately, before the next checkpoint/check_database/subset validation. Borrow fields for subsequent steps; take only the final payload/database and matching diagnostics when all semantic work succeeds.

Choose the receiving output `O = IoResult<SqliteDatabase>` / `IoResult<IoPayload>`, not just IoOutcome. The outer closure returns `Ok(original_inner_result)` even when semantic work produced an original owned IoError. With genuine IoError retirement this preserves the complete diagnostic result while the outer receiving frame closes snapshots/indexes/input ownership. On outer cleanup/publication refusal, the original IoResult stays in the frame's output retirement, and the outer ValueError can be published as the close refusal without dropping the original result. On successful outer extraction, return its original inner IoResult unchanged. Do not rebuild an IoError by stringifying the retained cause or discard nonfatal diagnostics.

`validate_owned_sqlite_snapshot_subset` currently creates its failure cause with format! after owner validation (Store 12316-12319). Its diagnostics vector is owned locally during that work. Make validation retain its outcome/error before any subsequent fallible admission/checkpoint; pay error/cause allocation through the original native/body port. Changing the outer frame alone does not price arbitrary owned diagnostics constructed by the subset callback. Either make that callback receiving/owner-aware or require its exact result allocation be admitted by the original control and adopted immediately.

## Import Input Admission Boundary

Current erased import callback consumes SqliteDatabase by value before receiving frame admission. Capturing that database in a receive_nested closure drops it if receiving admission rejects without invoking the closure. Moving it into the frame only inside the closure is too late to protect this path.

Change the erased callback and callers to take an original caller-owned `&mut Option<SqliteDatabase>` (or an equivalent explicit consuming adoption result returning the database on refusal). Outer receiving admission runs while that slot remains owned by the caller; only after admission does the closure take it into the frame. Caller retains it if admission refuses. An output-only IoResult consuming a database cannot expose that preserved input. Do not fill this hole with synchronous drop or a new unpriced recipient.

Verify input survives pre-admission denial, original snapshot/database/payload/error identity survives later denial, cumulative capacity includes every nested frame, child recipient remains authentic, and exact terminal release witnesses include output discarded on cancellation and all receiving/recipient shells. ## Actual Import Callers and Common Signature

Production source search (excluding test paths) found one actual function-pointer import invocation: OS `🚪️io/🦀️.rs:2607`, inside run_snapshot_hop. There are two production implementations of that callback: Store generic import_snapshot_impl (12287), and MCP workspace guest_sqlite_import (3161), the latter registered in the guest ArtifactSqliteSnapshotCodec at 3226. Norm codec factory functions simply return the generic codec. Numerous direct artifact tests still call the older ownerless/by-value signature; these are test call sites, not additional productive installed routes. This count describes source call sites, not registered artifacts.

run_snapshot_hop owns imported database locally at 2599, removes metadata at 2600, validates dialect/provider/schema, calls import at 2607, then checks output size and publishes. It needs an admitted receiving frame around the whole hop, before the database import effect, retaining payload bytes, database, extracted metadata/diagnostics and reconstructed output. A callback borrowing database does not fix local drops before/after callback invocation.

The generic callback already passes &database to reconstruction/validation and never needs to mutate or consume it. Its ideal input is borrowed `&SqliteDatabase` from the hop frame. Guest callback presently consumes and mutates database: attach_sqlite_snapshot_metadata at 3171, serialize into bytes, run component import under forwarded original receiver, decode diagnostics and move native payload bytes. A shared `&SqliteDatabase` signature would require a borrowed serialization projection that adds metadata without cloning the database; otherwise Guest cannot preserve original input while attaching metadata. Cloning is a separately priced new owner, not the original custody solution.

The minimal common signature is therefore `fn(..., input:&mut Option<SqliteDatabase>, encoding, control, native_owner)->IoResult<IoPayload>`. run_snapshot_hop stores input in its receiving frame; generic callback borrows `input.as_ref()` and leaves it there to retire in the hop frame. Guest first admits a nested frame, then takes the input into that frame and mutates it for metadata serialization. If Guest nested admission rejects, input remains in the caller slot. Later rejection keeps original database plus serialized bytes/result in the guest frame, attached to the original caller pending chain. Empty input is an invariant refusal with no replacement owner. The optional transfer contract is explicit and useful across both providers; it avoids guest-specific cloning and leaves final input retirement with a declared custodian.

Guest frame must also adopt actual sqlite_wire result/rejection, encoded metadata file bytes, diagnostics bytes, decoded diagnostics and IoPayload before the next fallible operation. On String::from_utf8 failure, preserve returned FromUtf8Error.into_bytes in its frame rather than formatting then dropping original payload bytes. sqlite_wire owners require genuine first-party retirement declarations for supported fields; reactor/route/cancellation handles must remain borrowed session infrastructure rather than being placed behind fabricated retirement support. Guest export has analogous unretained SnapshotFileResult/file/database/diagnostics boundaries and requires its own export frame.
