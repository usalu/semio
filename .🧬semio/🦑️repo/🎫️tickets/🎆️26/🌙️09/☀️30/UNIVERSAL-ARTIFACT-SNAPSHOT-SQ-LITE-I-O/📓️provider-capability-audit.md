# Provider Capability Audit

Concurrent infrastructure changes split native document codecs from explicitly owner-declared relational capabilities. `ArtifactCodec::of` still requires `ArtifactSqliteSnapshot`; `ArtifactCodec::bare` reads `ArtifactPack::sqlite_snapshot_codec`, whose default is absent. The bare artifact declaration path uses this owner capability and publishes only its exact dialect coordinate. A handwritten provider trait by itself does not establish runtime registration through this bare path.

Binary, BMP, JSON, Deflate, STL, OBJ and PLY already contained explicit owner hooks when inspected. GIF87a, GIF89a and ZIP lacked their hooks and now explicitly return their own authored `sqlite_codec`. GIF's actual registered typed I/O tests were strengthened to construct the same bare codec authority used by artifact declarations. These changes do not register placeholder providers or infer schemas.

PDF's two wildcard document codec declarations do not expand to every profile. The I/O worker owns explicit profile publication and runtime laws after inspecting actual subset specs. Semio, PDF, Note, DXF and DWG workers were informed to inspect every newly authored native pack or derive declaration for an actual capability. The final catalog audit must reject any missing provider coordinate.

GIF's TypeScript package now registers both provider suites; its strengthened check passed. Deflate and ZIP similarly register their SQLite suites in their existing package routers; their strengthened checks remain pending. Each executable still runs through its existing Bun/Nx target and launch entry.

Actual PDF declaration-driven runtime tests exposed separate registry statics because framework and kernel each mounted the complete I/O module. The I/O worker canonicalized the framework public surface as a reexport of kernel-owned I/O and explicitly reexported the three thunk macros. The first corrected runtime lane passed twelve of thirteen PDF laws; the remaining negative profile test used a snapshot whose violations were only allowed soft warnings, so its input is being corrected to a genuinely forbidden JavaScript action. No full PDF success is claimed yet. WAV's new actual-declaration law exercises the same canonical registration path.

Future artifact document declarations must reject absent SQLite capabilities once the full roster is implemented. Unrelated configuration pack types may retain an absent optional hook. Trait implementations or helper registry calls alone do not prove actual artifact publication; the final coverage audit must inspect runtime declarations and every imperative registration route.

The owned subset guard now receives the exact dialect, the owned snapshot, its already-projected semantic database and transfer control. It rejects unimplemented named subsets and never calls native pack encoding; byte-payload validators remain a separate route. Root inspection confirmed ZIP and GIF89a actually publish wildcard runtime coordinates despite their `base` folder names. Both have explicit owner coordinate/domain guards; ZIP's new actual-declaration typed I/O law is pending. JPG baseline is genuinely named, so its implementation must explicitly publish and validate that coordinate.
