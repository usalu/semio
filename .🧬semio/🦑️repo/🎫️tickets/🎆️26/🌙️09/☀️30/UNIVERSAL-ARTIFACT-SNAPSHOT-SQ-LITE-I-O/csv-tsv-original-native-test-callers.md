## Clean Test Helper Specification

Define direction-specific local test helpers in the existing test files; do not add another script or runtime compatibility overload. Each helper receives caller-explicit body grant, close-turn grant, native maximum, original native observer, SQL limits, SQL observer, and operation closure taking SQL control plus the same original direction owner. Construct the appropriate original native retirement recipient before control, install it on that control, then construct NativeSnapshotDecodeOwner/EncodeOwner with the independent body grant. Capture actual `owner.progress()` and original `native.owned_bytes()` before dropping the owner; do not discard these receipts when returning the result.

The helper must close every pending intermediate/partial owner through that **same native control and recipient** using the separately supplied close-turn grant and a bounded maximumTurns. Inspect both accepted step receipts and refusal retained_progress; compare actual heap births/releases and terminal absence where the test requires them. A cancellation case must retain its original callback and partial state until its cancellation assertions are complete. If later cleanup requires resuming, use the caller's mutable cancellation flag/observer state or established detach-and-bind continuation; do not silently replace the callback, construct another control, or globally turn cancellation off. Keep body/close receipts distinct: close turns spend explicit close authority and must not be falsely recorded as additional body progress when body maximumReleaseBytes is zero.

Success outputs remain caller-owned. If the helper returns a successful snapshot or payload, assert it while owned, then retire it under ControlledRetirement with explicit close-turn grants. Native pending recipient cleanup does not imply successful returned output backing is empty. Provider import must start from a named mutable `Some(database)` caller slot and assert preservation on pre-admission refusal; a throwaway temporary Some or moved database hides the ownership guarantee.

Use neutral authored numeric grants independent of native maximum and SQL limits. CSV native-control fixture currently has no corresponding typedDestination grants. Add a separate neutral full-native/provider caller law with explicit body and close grants for these actual fixture paths, validated independently against schema, rather than deriving grant currencies from requested demands or copying unlimited defaults. Preserve one cumulative wallet across repeated operations intended to test cumulative exhaustion.

ToValue/serde comparison is an independent semantic oracle; it does not validate physical ownership or cancellation settlement.
