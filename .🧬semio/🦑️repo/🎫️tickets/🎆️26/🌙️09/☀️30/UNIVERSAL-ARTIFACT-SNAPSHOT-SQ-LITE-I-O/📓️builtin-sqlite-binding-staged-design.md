# Builtin SQLite Binding Staged Design

This design is unmounted pending the corrected isolated Space/Collection no-manual-registration law reaching its actual I/O assertion. Their previous tenth-law failure was a libtest selector prerequisite. The full module path is now retained after removing only the current crate prefix; the exactly-one-test guard remains.

The actual common ordinary construction seam is `ArtifactStore::construct` in Store. Its caller retains the candidate envelope and retires it on construction refusal. An owner registration failure must occur before any candidate fields are adopted or a current snapshot is materialized. The independent retained construction seam is `RetainedPersistedDocumentHydration::step`, `Phase::Finish`, in `store/🧾️document/📜️history/💧️hydration/🦀️.rs`. That path calls the infallible `ArtifactStore::from_initialized_runtime_with_owners` and bypasses `ArtifactStore::new`. Registration must therefore remain in the retained operation's fallible state while envelope/runtime/owner guards are still attached, before `take()` and the terminal Store handoff. A failure rejects through its existing initialization diagnostic and preserves controlled retirement.

The narrow owner declaration belongs on the existing `ArtifactPack` authority. A function-pointer registration hook can return `Option<fn() -> Result<(), crate::os_io::ArtifactAssemblyRegistryError>>` with an absent default, so unrelated generic Store roots acquire no new DSL/PartialEq bounds and Kernel gains no dependency on Space packages. Each of these three actual owners explicitly returns its existing typed registration function, which calls its authored bare factory with the exact coordinate. The current ordinary Store constructor returns VcsError: only that construction boundary maps the actual registry refusal to its declared validation diagnostic. The retained opening path similarly retains its existing Initialization diagnostic while leaving its cold owner guards attached. No ValueError/String compatibility conversion is proposed. This declares actual capability registration, rather than guessing an app dialect from a schema name.

The existing `os_io::register_native_snapshot_codec` already publishes the document codec and native snapshot binding atomically under `begin_artifact_assembly` and its registry-plan transaction. The owner hooks must reuse it. Space uses `os.space@1/*`, Collection uses `os.collection@1/*`, and History uses the newly authored `os.space.history@1/*` SQLite contract. History still retains its actual JSON/raw-value Pack native formats; no native envelope identity is invented. Store's persisted `dialect: None` remains unchanged.

The isolated owning law has three fresh-process modes: ordinary creation, persisted reload, and retained hydration. It closes the actual Store before asserting the public typed I/O result and performs no registration call. The fresh process prevents an earlier explicit-registration law from masking the production omission. The Source SQL oracles and manually registered public native law cannot certify this zero-touch binding.

The existing Host descriptor's `s.{component_kind}@1/*` placeholders do not prove these owner coordinates. They require separate real-owner catalog reconciliation and runtime evidence if the Host descriptor is changed. No placeholder alias or synthetic declaration tree is part of this design.

Current typed readback confirms that `ArtifactStore::construct` remains fallible with VcsError and `from_initialized_runtime_with_owners` remains infallible.
