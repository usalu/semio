## Staged TXT Billing Review

Proposed staged Port billing is sound against current receive internals if the successful binder performs residual reconciliation while its typed output remains in the intermediate frame, then drops Port and the RefCell SQL borrow before postBody=true and before taking that output. During body the outer scoped observer can return true without borrowing SQL; original native callback still runs first, and Port's own text/vector billing remains authoritative. Capture actual SQL text refusal in Port's inner callback or it remains native-kind message translation despite staged billing.

Actual NativeSnapshotOwner::receive sequence is operation result → install Ok(output) into frame.output → while intermediate/pending nonempty, original checkpoint and demand checks, native charge(actual close-factory capacity), original controlled close step and receipt addition → publication authority check → original native checkpoint → take_output → frame drop → recipient owner=None. Thus the postBody observer runs while completed output is still held at every retirement checkpoint and the final publication checkpoint. Newly charged retirement-factory bytes are reconciled at the next loop checkpoint, or at final publication checkpoint when intermediate becomes terminal. There is no output take before that final callback. Refusing it preserves original frame/output in the recipient.

SQL reconciliation can be idempotent using initial native_before and SQLremaining_before even though Port bills body allocations: subtract total SQL admitted from total native accepted before admitting residual. Update no independent counter that would double count. After receive Err, reconcile remaining short-circuited charge with recipient retained and attach cumulative owner.progress to whichever exact policy cause is returned. ## Exact API recommendation

Introduce one per-operation original SQL allocation ledger with immutable native_before and sql_remaining_before, checked `settle(control,current_native_owned)->Result<()>` using the above reconciliation equation; all Port allocation receipts and wrapper native-event receipts use that same idempotent reconciliation rather than separately billing raw deltas. A scoped event callback should settle the shared ledger, then control.checkpoint(phase,completed,total), capturing actual ValueError on refusal. Preserve original callback short-circuit: no manufactured SQL refusal when original native callback denies. Reconcile residual on the refused path and promote captured SQL/native cause with full cumulative owner receipt. The ledger must include receive frame and actual retirement factories, not just body allocations.

Port currently owns a mutable SQL control borrow while wrapper callback would also need it; wrapping the existing Port with an independently capturing callback causes Rust aliasing and duplicate accounting. Prefer a checked shared settlement/cause port designed into the receiving API, or an explicit staged local solution: Port owns billing during body; reconcile frame residual inside receive before returning output; after ending that body borrow switch to original event settlement for retirement/publication. The transition requires one live checked ledger, not independent guessed counters. Capture SQL text errors at the actual inner callback; a wrapper observing afterward cannot recover the original SQL cause.

Additional laws: SQL cancellation during long text checks exact borrowed SQL message and full owner receipt; original native cancellation at same offset checks native message; initial frame/retirement factory charges exhaust SQL allowance while body itself fits and retain output on refusal; repeated reconciliation is zero additional admission; forwarded controller starts with prior native ownership and prior SQL admission preserved.
