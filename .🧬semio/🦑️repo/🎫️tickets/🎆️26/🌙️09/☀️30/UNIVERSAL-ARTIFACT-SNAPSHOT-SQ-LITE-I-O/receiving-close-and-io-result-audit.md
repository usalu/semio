# Receiving Close and Original IO Result Audit

Read-only current source audit of `🧰️framework/🔨️modules/🚪️io/⏱️control/🛫️snapshot/🦀️.rs`; no builds or source edits.

`NativeSnapshotReceiving<T,O>` owns one pending child ticket plus controlled intermediate/output fields. Close chooses pending first, then intermediate, then output. It validates total frame depth and subtracts one before delegating. A terminal pending child ticket correctly demands frame depth 2, leaving depth 1 for actual final ticket Box release. `next_release_byte_demand` uses `size_of_val` of the original erased ticket, rather than pointer size. `close_factory_ticket` itself preserves the slot on denied work/copy/release and reports the actual box release as Progress. Controlled intermediate/output steps also report Progress for their final physical transitions, so delegated child completion does not falsely imply the whole parent is terminal.

Concrete frontier inconsistency: `NativeSnapshotReceiving::next_copy_byte_demand` delegates to `active()` even when the pending ticket is terminal-empty. That payload usually reports zero, while `close_factory_ticket` final ticket release requires `size_of::<Option<Box<dyn ErasedSnapshotRetirement>>>()` copied bytes for taking the original slot. Match the existing release/depth terminal-pending specialcases with that exact copy demand. A zero-copy grant currently makes no mutation and retains custody, but the advertised next frontier underreports the needed original authority. Root was informed directly.

On successful receive, output is first stored in its controlled field; pending children and intermediate owner must retire before publication. Final extraction prechecks remaining item and exact original frame release bytes, then checks cancellation before taking output. Accepted frame release is included in cumulative progress; frame drops only on success. Any cleanup refusal retains the same typed frame under the original native recipient or pending parent. The general API contract still requires callers to insert newly born fields into the slot before fallible effects; closure signatures alone cannot establish that.

Original error retirement is now present in `🚪️io/🧬️schema/♻️retirement/🦀️.rs`: IoError owns cause and diagnostic vector through typed deferred children/sequence; IoOutcome owns value and diagnostics similarly. ValueError retires owned Cow text through String and borrowed literals through a scalar leaf. Diagnostic has an explicit `artifact_retire_struct!` in `⚠️diagnostic/🧬️retirement/🦀️.rs`; its fields have their own controlled owners. This is typed field retirement, not an opaque callback that drops an unpriced tree.

`Result<T,E>` has a genuine original-variant cursor under Value `♻️retirement/⚖️result/🦀️.rs`. It retains its exact initial variant, admits transfer into a controlled child, and retires that original child before terminal release. Consequently `O = IoResult<SqliteDatabase>` is supported when the database and diagnostic fields are controlled. To retain an original IoError across canceled cleanup, the codec operation must return `Ok(original_io_result)` to the receiving frame. Returning outer `Err(ValueError)` communicates receiving failure and does not place the original diagnostic result in the controlled output field. Do not reconstruct a substitute error after dropping the original.
