# STEP SQLite Snapshot Research

The next assigned owner is `✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📐️step`, standard ap214, wildcard and six named conformance classes. All seven dialects share the actual persisted StepSnapshot declared in the base subset. This is a STEP-specific typed Part21 exchange model, not a generic artifact value fallback.

Persisted fields were read directly: schema string; complete StepHeader with fileDescription.description ordered strings and implementationLevel; fileName.name, timestamp, author, organization, preprocessorVersion, originatingSystem and authorization; fileSchema.schemas ordered strings; entities with unsigned64 id, name, ordered args and ordered complex type/name/args records. StepValue has unset, derived, signed64 integer, binary64 real, string, enum, unsigned64 reference, aggregate and typedValue(typeName, owned child). Derived Brep meshes and bounds are not persisted fields.

The planned handwritten relations separate the root document/header, four individually named ordered header lists, entities, complex records, arguments, typed primitive value nodes, ordered aggregate elements and typed wrapper relationships. The entity reference field must be explicitly queryable and related to actual entity identities. Structural value ownership is a forest; entity reference cycles are legitimate semantic graph links. All native integer widths and IEEE words must survive physical SQLite and independent query edits. No native pack, serialized Part21 source, JSON or generic property bag will be stored.

Native named class owners expose check_cc1_conformance through check_cc6_conformance directly on a borrowed StepSnapshot. Typed SQLite I/O can preserve their real diagnostic semantics without encoding native bytes. The declaration currently binds wildcard only through document_codec_bare; the explicit named class declaration route must be authored and tested. The actual StepSnapshot ArtifactPack implementation currently lacks sqlite_snapshot_codec and will need its explicit owner hook.

The existing TS StepValue declares integer/reference/id as number and real as number. Full-width and signaling NaN fidelity therefore require coherent bigint/Binary64 owned models, strict typed parsers and matching diff/mutation/inference consumers. Native wire/proto widths stay unchanged. This research is preparatory; STEP SQLite implementation and runtime proof are not claimed yet.

Schema-first TDD now has twelve individually authored STEP SQL tables, the complete neutral header/scalar/query corpus and the owned physical oracle suite. STEP Rust and TypeScript facet scripts, owned Nx targets, cache inputs and full/native/source launch entries are registered. The first actual uncached registered source gate is RED at the missing STEP SQLite provider import, before implementation. It completed in 1.6s including four successful fresh dependencies. The source corpus covers signed64 extrema, unsigned64 maximum, all eight IEEE64 boundary words, all nine value variants, complex records, cyclic entity references, ordered duplicate header entries, malformed ownership/identity and deep aggregates. Provider implementation remains pending.
