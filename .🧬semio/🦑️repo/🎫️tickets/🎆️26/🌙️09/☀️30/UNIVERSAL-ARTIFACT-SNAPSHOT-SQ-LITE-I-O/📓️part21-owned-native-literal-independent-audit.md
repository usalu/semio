Both `controlled/input::decode_value` and `decode_instance` transitively use this helper. Owned payload/name/coefficient copies use the real chunked canonical `copy_text`; that does not cover borrowed key hashing. 2. **Partial names bypass actual String retirement.** `controlled/input::decode_value` typed arm keeps copied `name` as an ordinary String while `values(...)` can fail. `decode_instance` does the same for each entity name. Their early error path drops names normally instead of through `RetireOwned::retirement`, whose canonical String cursor explicitly retires byte grants. `controlled::retire_instance` and `retire_entities` also discard names via `for (_, items)` and never send those bytes through an owner cursor. Guard the name immediately after construction and retire the whole tuple/vector/instance through the actual declared RetireOwned implementation. Current recursive children do have explicit cold guards; this finding concerns abandoned or retired name owners specifically.

The serde oracle checks logical JSON kind/payload/decimal/entity arrays and names. It does not directly oracle the controlled output in the output law (that law compares ordinary ToValue and ordinary FromValue). No Header/Document controlled roundtrip law, malformed entity-instance/decimal closed-field law, retirement grant observation, borrowed long-key cancellation law, or WorkLimit-specific Part21 law is present. The fixture declares unsigned 0 and MAX, but the shared values helper uses MAX only. IFC4 IEEE state is outside this shared decimal model/oracle. Add owner-specific and boundary laws before extending claims.
