# Component Snapshot Frame Grant Debit

Confirmed source defect after inspecting both component state and authoritative host receiver. No builds or source edits. Sent directly to Native execution.

Component source: `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🚪️io/🛂️authority/🪶️snapshot/🦀️.rs`, `with_snapshot_authority:51`.

The real SnapshotOperation Box birth is allocation-admitted: it checks nonzero original items/depth and sufficient capacity for `size_of::<SnapshotOperation>()`, reserves those frame bytes through `pure::operation_allocation`, and initializes `state.owned=frame`. This is a real physical allocation receipt. However neither branch subtracts the frame item or depth from the five-field grant. Both construct `IoRunControl::{decoding,encoding}(control,grant)` using the full unchanged original grant. A reduced native byte ceiling (`grant.maximum_capacity_bytes-frame`) covers some capacity admission, but is not a cumulative physical wallet debit.

Host source: `🌿️vcs/🚪️io/💾️binary/🪪️entity-identity/🎛️control/🦀️.rs`. `OriginalOperationReceiver::begin:84` derives remaining native allocation capacity; `allocation:88` validates byte totals and forwards `control.charge(bytes)`; `finish:90` checks equal owned bytes and cancellation. Its receipt has owned/input/output/retirement allocation counters, not the five retained-clone currencies. Therefore host admission does not compensate for the repeated frame item or missing nesting depth debit.

SnapshotOperation has no cumulative RetainedCloneProgress field. Its status reports owned bytes, pending flags, and next demands. `snapshot_close` returns each actual cleanup progress, and the host stores those grants/receipts separately in SnapshotComponentReceipt. Neither path reconstructs the missing original birth item/depth debit. Final shell close itself is accurately priced: original Box size release, actual slot-copy demand, one item/depth, and finish approval before slot.take.

Concrete source counterexample: an original grant with one item can admit the outer SnapshotOperation and then a nested receiving frame using that same one item. The nested operation can refuse publication after the second Box birth, but refusal does not undo the two admitted births. Similarly, original depth two is passed as depth two inside a root frame instead of depth one. This is an original-authority conservation error independent of whether the eventual call succeeds.

Required fix:

1. Give SnapshotOperation an immutable original grant and cumulative accepted physical progress. Admit/debit the real outer frame birth before invoking the child. Pass only remaining item/copy/capacity/release authority and depth minus the root frame into IoRunControl. Preserve all independent axes; do not derive a larger grant from measured demand or the host byte ceiling.
2. Record the child IoRunControl's accepted progress back into that same original wallet, including partial error/cancellation receipts. SQL forwarded allocations and physical wrapper capacity must be reconciled exactly once with the declared native grant, rather than relying only on the distinct host maximum.
3. Carry the actual initial component birth/body progress across the wire or expose it as a retained original scalar receipt. Existing owned_bytes alone cannot express item/copy/release conservation. Keep subsequent explicitly admitted close turns separate from the immutable original production grant, recording actual close receipts rather than rebasing the production grant.
4. Retain the real final frame-close receipt and existing same-instance ticket; do not allocate a replacement recipient or waive the original frame release.

Original input admission is also concretely ownerless: SnapshotInput owns dialect String, encoding String, and payload Vec, but `with_snapshot_authority` takes it by value before validating grant/limits, occupied slot, operation begin, reservation, and ticket authority. Any early error drops that input outside a receiving owner. SnapshotOperation does not retain an input field; its callback then consumes input by value again. Change the native API to caller-owned `&mut Option<SnapshotInput>` (or a genuinely borrowed input plus an admitted owner) and preserve the original slot on pre-admission failure. After the frame is admitted, move the exact input into a typed controlled field before any further fallible callback. Callbacks must borrow that field or transfer it through an admitted child input slot. SnapshotInput and its nested owned fields require genuine controlled retirement, not synchronous FromValue/deferred drop adaptation. Component/WASM entry wrappers must keep the decoded original input reachable while invoking this slot API.

Neutral laws should isolate items=1, depth=1/2, exact frame capacity versus frame+child, occupied recipient, canceled reservation, denied final release, and canceled callback after input adoption. Assert input pointer/bytes unchanged before admission; original input/receipt retained after adoption; each measured Box birth/release equals its accepted physical receipt. No runtime failure or passing-law qualification is claimed here.
