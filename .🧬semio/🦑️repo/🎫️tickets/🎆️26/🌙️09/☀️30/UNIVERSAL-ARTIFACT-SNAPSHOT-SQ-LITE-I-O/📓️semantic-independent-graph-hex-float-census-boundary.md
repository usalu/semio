## Proposed Streaming Classification Review

The overflow round-to-nearest midpoint2^1024−2^970 is correct; equality rounds to infinity. When adjusted scientific decimal exponent is308, compare first309 significant digits (right-pad shorter sequences with zeros) to the exact309-digit integer midpoint. Equality is already infinity, so discarded fractional tail digits cannot turn that decision finite. A lexicographically smaller309-digit prefix remains below that integer boundary even with a nonzero tail. For negative values classify absolute magnitude identically.

The short path should decode at most32 UTF8 bytes into stack storage and call the original float parser. Long decimal classification must accept optional leading sign, integer digits or leading decimal point with fractional digits, optional single point (trailing point legal when integer digits exist), e/E and optional exponent sign followed by at least one digit. Require at least one mantissa digit and complete token consumption; whitespace, underscores, Unicode digits and hexadecimal numeric notation refuse. Exponent clipping must be done while accumulating digits with checked/saturating bounds; avoid first parsing exponent into an integer that rejects otherwise valid very long exponent lexemes. Compute adjusted exponent after cancelling all leading mantissa zeros and decimal position. All-zero mantissa is finite even with huge positive exponent; underflow is finite including negative zero.

Clipping exponent at source-byte-length+400 is adequate for finite/infinite classification because mantissa/decimal displacement cannot exceed that source length. Cap that addition safely for usize overflow. If significant digit count itself is capped, preserve the separate full displacement count; using only retained309 digits changes magnitude. Count leading zeros after the decimal point in displacement.
