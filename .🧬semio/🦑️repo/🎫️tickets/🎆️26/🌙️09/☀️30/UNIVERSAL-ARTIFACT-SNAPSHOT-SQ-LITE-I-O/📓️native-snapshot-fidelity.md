# Native Snapshot Fidelity

Full SQLite snapshot transfer must project and reconstruct the owned snapshot type directly. Native pack/DSL encoders can normalize valid typed state before SQLite ever sees it: CSV can contain a zero-field record, `schema` is an unconstrained string field, BMP's native output canonicalizes its header and drops alpha in direct-color output, and PNG output canonicalizes source color depth/interlace while retaining decoded RGBA pixels. Equality of re-encoded native bytes alone cannot prove complete typed snapshot equality.

Evidence is in each existing native `ArtifactPack`/engine implementation and the snapshot schemas. BMP's `encode_bmp` indexed path and direct-color path are in its standards/v3 subset I/O source; `BmpSnapshot` models header size, row order, palette, alpha and integer metadata as owned fields. PNG's snapshot source explicitly documents canonical decoded RGBA and normalization by its native encoder. The valid owned schemas must remain unrestricted strings rather than adding a false constant to hide this issue.

The owned public `io_export_sqlite_snapshot` and `io_import_sqlite_snapshot` operations now use the exact registered snapshot type identity and its individually authored SQL schema. Wildcard endpoints avoid the native encoder altogether. Native payload routing still serves a wire-format transfer and has that format's existing representational limits; its encoded-byte laws are not counted as complete typed fidelity. Specialized subsets remain subject to exact registered conformance validation.

The actual BMP endpoint regression changes its schema string, header size to 108, bits per pixel to 32 and one pixel alpha to 17, then requires complete equality after SQLite I/O and verifies that no native encoding/decoding phase ran. Initial test compilation errors were corrected; the actual green result is recorded only after execution. Further family fixtures must exercise comparable fields instead of relying on normalized native output.
