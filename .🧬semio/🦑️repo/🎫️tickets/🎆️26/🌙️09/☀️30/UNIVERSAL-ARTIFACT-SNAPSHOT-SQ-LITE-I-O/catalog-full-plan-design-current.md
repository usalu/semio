# Catalog Full Plan Design Current

Read-only 2026-10-09; no runtime claims.

Current immutable binding requires actual native_identity and optional SQL/factory, but its constructor only accepts an actual ArtifactCodec. `bindings/🦀️.rs:71–75` rejects every proposed row without matching codec. Kernel IO commit1920–1955 validates all rows then commits under one existing assembly barrier, with Store/composer/subset/format/native/binding locks and no fallible operation after mutation. Keep this atomic commit shape and same lock order.

Authentic unlinked Guest entries exist: trusted-catalog `VerifiedNativeArtifactCodec:1052` contains codec:None plus actual GuestArtifactCodecBinding. Verification1713–1748 constructs these from original package/schema/pack-hash even when native provider binding is absent. Guest component residency is lazy; current verified entry is not a registered executable ArtifactCodec and does not establish SQL support. Do not build a synthetic ArtifactCodec solely to pass current binding validation or label native_identity with a fabricated TypeId/hash.

Smallest coherent extension:

- Add NativeCatalog/CatalogOpenTarget channels to neutral closed schema and Source twin first, with optional closed catalog descriptor retaining original contributor package tuple and separate codec-owner package tuple: plugin_id/package_id/version/component_sha256 (and existing other digests only if contract needs them). Keep component digest algorithm explicit; actual compiled.package_hash is not automatically interchangeable with catalog component_sha256.
- Keep executable bindings validated against real codec/native registry exactly as today. Add a distinct declarative catalog-owner representation for genuine verified Guest entries lacking codec, with actual package+schema+pack hash and explicit capability unknown/uninstalled. Do not overload sqlite_schema:None to assert known unsupported when capability was never queried. If the goal only requires installed executable bindings, keep declarative rows in a separate catalog declaration ledger rather than counting them as installedNative.
- CatalogOpenTarget includes exact original parent dialect, surface_id/app_id/window_kind_id/role/renderer_target, grants and optional browser-actor metadata. Canonical key includes complete target identity; apps alone cannot distinguish role/window/renderer. Contributor is host record package, codec-owner is bound package. Hosted target factory is copied only from actual owner's verified native binding; no host factory is minted.
- NativeCatalog executable rows preserve original optional factory and actual nativeidentity/SQL before filtering. A native catalog declaration without actual dialect/app retains None. Do not manufacture native registration for a dialect not authored by the provider.

Atomic interface: verify_selected should return catalog plus full plan/descriptors, then load1526 begins one actual assembly. Preflight function for full plan must perform the same cross-registry checks as commit without mutation and without nested begin; commit revalidates under existing locks. Declarative rows require a separately validated original catalog descriptor input in the plan; current propose(codecs) is deliberately insufficient for codec:None. Validate actual package provenance/canonical target uniqueness before registry mutation. Publish all descriptor and executable ledger rows together, then return catalog.

Original catalog verification knows authentic component SHA256/BLAKE3/descriptorSHA and selected open surface tuple, but may not yet know compiled runtime Guest package hash or SQL declaration. Preserve this epistemic boundary explicitly. Full offered prefilter denominator additionally requires selection status for original offered rows; selected registry publication alone establishes selected denominator only. No guessed joins/counts.
