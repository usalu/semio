# WAV Semantic Execution

The actual RIFF-PCM owned model has typed format fields, four data variants (signed PCM16, unsigned PCM8, float32 and intrinsic raw bytes), optional format-extension presence, primary chunk pad bytes, ordered auxiliary chunks with FourCC identity/content/padding, and an ordered marker relationship to primary or auxiliary chunks. A decoded-only audio buffer would lose its container state and is insufficient.

The individually handcrafted SQLite schema now declares twelve tables: document, primary format, optional extension presence and ordered octets, primary data, four distinct sample/content domains, auxiliary chunks and their octets, and chunk-marker relationships. It preserves optional empty extensions, every byte-width/u16/u32 field, explicit empty marker sequences, duplicate markers and intrinsic raw content. Derived audio duration and channel addressing can be obtained by SQL from sample ordinals and typed channel count; no native codec is needed to inspect PCM samples.

Float32 samples have explicit IEEE754 binary32 bits, numeric class and nullable query REAL, preserving signed zero, subnormals, infinities and every native NaN payload while remaining independently interpretable. Provider call sites explicitly project each owned field; there is no reflected object traversal, native pack envelope or JSON cell. Scalar default padding uses the model's declared zero value; optional extension presence remains distinct from an empty extension.

Language-neutral corpora and three tests per implementation were authored first. The source TDD run initially reached three failures against explicit unimplemented APIs; after implementation the full Bun source suite passed three tests with thirty assertions, including Ajv, independent SQLite integrity/FK checks, sample/format/octet edits, numeric class queries, ownership/order/kind failures, bounds and cancellation. Two preliminary Bun invocations crashed before test execution; their cause was not established and those crashes were not counted as implementation failures or successes. The invocation with an explicit relative test-file path executed the suite.

Native provider and exact actual artifact-declaration I/O laws passed, including custom schema strings and intermediate fields that the native RIFF serializer refuses. A fourth native law independently queries all IEEE754 sample classes through Bun SQLite, preserves signaling NaN bits on reserialization, and rejects forged class/query/bit inconsistencies. The owner explicitly publishes its SQLite capability from ArtifactPack. The full dependency-inclusive Nx WAV gate passed four native laws (Nextest run `af6083a9-a4e6-410a-8530-7d22ffa236c7`) and all three TypeScript tests with thirty assertions in 7m1s. This confirms the actual declaration's runtime I/O authority after canonical registry ownership was corrected. The first TypeScript package check found one widened JSON-discriminant type in the test, now corrected; the strengthened check also passed with its real provider suite (`suites=1`). Full and source targets are registered in the framework script, Nx project and launch.json. The catalog-wide goal remains incomplete.
