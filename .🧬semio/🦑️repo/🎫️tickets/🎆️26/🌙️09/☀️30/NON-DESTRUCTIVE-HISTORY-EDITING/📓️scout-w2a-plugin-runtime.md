### 0.1 Twelve conclusions the executor must know before typing

1. **`toolRun*` actions are NOT reserved-job routes.** They are intercepted at the head of `dispatch_action` (`P:29435`, `if is_tool_run_action_id(action) { return self.dispatch_tool_run_action(..) }`), before `dispatch_framework_reserved_action` (`P:28954`, the spawn-job route). That is the whole meaning of "host-driven, never queued": the verb runs synchronously inside one guest command turn and mutates ledger state; the work it started (job stepping) advances in `drive_tool_run_turn` (≤ 4 ms per reactor turn). There is no factory, no `Effect::SpawnJob`, no `reserved_commits` FIFO, no `framework_reserved_job!` ordinal, no proof entry. Neither React (`PluginRuntime`) nor wgpu special-cases these ids on the dispatch path (grep: only comments); the hosts only bind the Rust-built panel buttons and reveal the ToolRun panel when a run appears (`toolRunPanelReveal` in React ShellHost, `tool_run_panel_reveals` in the wgpu Shell). Copy this route for the nine session verbs; see §2.1 for the one verb (`historyEditCommit`) where a job route is arguable.
2. **The freeze is checked in two artifact-emit sites and both miss `child_emits`** (`P:27336` and `P:30860`): the tool-run freeze and the transaction freeze both test `!artifact_mutations.is_empty()` only, so a child-only emit (`Emit.child_emits`) bypasses them. The time-travel freeze must test `!artifact_mutations.is_empty() || !child_emits.is_empty()` and also cover `transaction_prepare` (`P:33634`) and the history-lane reserved verbs (undo/redo/checkout/alternatives/revert), which never reach `dispatch_emit` (§3).
3. **`HistoryPatch` cannot carry `timeTravel` alone.** `finish_recorded` (`P:31532`) attaches a patch only when `log_generation` moved, and the React host drops equal-cursor patches without upserts (`historyPatchShouldApplyV1`, `🛠️ShellHelpers/🟦️.tsx:267`). Either bump the patch cursor with a session counter or render the banner inside the Rust-built History body (design §7 already moves the panel to one Rust body; recommended, §5.2 H5).
4. **`ArtifactApp::Mutation` is not `SemanticMutation`** (`P:13446` bound is `Mutation<Snapshot> + PartialEq + Send + OpText + OpBinary`); `SemanticMutation` (`OS/📡️spr/🎮️command/🦀️.rs:261`, methods `kinds/semantics/label/target`) is "implemented only by `#[derive(Mutations)]`, never by hand". The session verbs need `payload_schema()/payload_value()/with_payload_value()` (W1-D, design §6) on `A::Mutation`. Decision needed: tighten the `ArtifactApp::Mutation` bound (breaks hand-written test mutations, e.g. `TestMutation`) or add a defaulted hook on `ArtifactApp` (`None` = not editable). Not decidable inside W2-A.
5. **Descriptors are generated, committed and read by the host.** Adding actions to `history_action_definitions` changes 44 checked-in descriptors (`✏️s/🔌️plugins/**/🔣️.json` + `🛂️.descriptor.semio`; count via `grep -rIl revertToCommand --include=🔣️.json ✏️s`). The host reads the roster from the descriptor (memory: stale descriptor = stale chrome). Regeneration per plugin: nx target `describe` (inferred per component by `📚️library/🟨️.mjs` `componentTargets`, depends on `component-dev`, outputs `🛂️.descriptor.semio` + `🔣️.json`): `bun nx run <plugin-project>:describe` (e.g. `@semio-tech/puzzle-plugin:describe`), ~33 min for puzzle under load. Coordinator-level chore; W2-A verifies with the builder laws, not the descriptors.
6. **Rendering has 4 overlay seams but 2 more committed-snapshot readers that must stay committed** (`pending_effects` `P:34308`, `context_menu` `P:34342`, and `capture_typed_command_roots`/`refresh_cache` cache). Only `render`, `window_engagements`, `window_measures`, `tool_measures` call `tool_runs.overlay_or(snapshot)`.
7. **One store constructor, one field.** `tool_runs` appears once as a field (`P:23525`) and once as an initializer (`P:24558`); every other use is a method call, so the ledger hosting is a small, mechanical change.
8. **Adding fields to `CommandView`/`HistoryView` breaks exhaustive literals outside W2-A's ownership** (`✏️s/🔌️plugins/🌀️procedural/…/🌀️generation2d/…/🧪️tests/🔬️unit/🦀️.rs:175`, `✏️s/🧑‍💻dev/🧩️composition-laws/…/🧊️generation3d-app-laws/…/✏️editor/🧪️tests/🔬️unit/🦀️.rs:256`, `✏️s/🔌️plugins/🌿️vcs/…/👁️viewer/…/📜️history/🧪️tests/🔬️unit/🦀️.rs:11`, plus `CommandView {` literals in generation3d preview-eval and vcs tests) and 8 literals inside the plugin tests. `HistoryView::empty()` and `..HistoryView::empty()` callers are safe.
9. **`MutationMeta` has ~45 exhaustive struct literals in plugin editors** (`grep -rn 'MutationMeta {' ✏️s`), all with `semantic_kind: None, label: None, group_id: None` (retained-batch preparations, e.g. `✏️s/🔌️plugins/🧩️puzzle/…/◻️2d/…/✏️editor/🦀️.rs:2415,2587`). That is W1-A's fallout; the central, one-place stamp for the retained batch path is `S` `fold_batch_item` (§4), so no app preparation needs to learn `transaction`.
10. **The finalize store call is unbounded unless W1-G supplies a bounded variant.** `ArtifactCommand::Supersede` does its own dry-run Report replay inside `store.dispatch(..).await` (design §3.4); the session has already replayed. Ask W1-G for a commit that accepts the finished `ReplayReport` (or a stepper-driven finalize), otherwise the finalize turn is O(suffix) on the interactive lane (≤ 64 edits, but ops are unbounded).

11. **The `dispatch_action` generator has ~0.25 MiB of stack headroom.** Law `one_framework_reserved_route_fits_a_bounded_thread_stack` (`🧪️tests/🔬️plugin-runtime-plugin-builder-contract/🦀️.rs:4070`, non-wasm) runs one `interactionSelect` through `dispatch_action` on a 2 MiB thread; the comment states ~1.75 MiB used today and 1.80 MiB per inline reserved await before the split. The new head arm `return self.dispatch_time_travel_action(..).await` adds one more future slot to that generator (the tool-run arm at `P:29435` is already one). Prefer `Box::pin(self.dispatch_time_travel_action(..)).await` (heap future) or a plain non-async classifier + one shared boxed call, and run that law after the change.
12. **Naming collision to keep out of the code:** the plugin already has an unrelated "transaction": the agent lane's cross-artifact two-phase commit (`PendingTransaction`, `txn_id`, `transaction_prepare/commit/rollback` `P:33634/33701/33731`, fault codes `transaction.instance-busy|commit-failed|generation-mismatch`, contract §5). `TransactionRef`/`ToolTransaction` (design) is a different thing; never reuse `PendingTransaction` or the `transaction.*` fault namespace for it (use `timeTravel.*` and `toolTransaction.*`).
