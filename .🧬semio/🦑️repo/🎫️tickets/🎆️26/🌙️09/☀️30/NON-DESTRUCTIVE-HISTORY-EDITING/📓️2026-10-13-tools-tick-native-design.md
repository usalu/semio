## Final Native Representation

The existing `ToolRunTick` is an owned ordinary struct with contiguous Vec columns. Trace pages also own a contiguous `Vec<ToolRunTraceOp>`, capped at4096 elements by the actual contract. A TraceOp includes a u64 key and large subject variants, so4096 actual elements necessarily exceed the original65536 capacity-byte callback grant. Repeated `reserve` calls do not solve this: each new contiguous allocation requests its entire new capacity, not just the added logical elements. Copying an existing large backing during growth also violates the original17 copied-byte budget. The same limitation applies to large ordinary opaque/operation byte leaves.

The first-party value module already has genuine `list::PagedList`, `paged::PagedBytes`, and paged text. Its existing cold conversion helpers do not certify an original native receiving factory. A complete receiving implementation must either build genuinely paid typed pages directly, or deliver typed records and original byte ranges while retaining the Job descriptor through every consumer. It must not build a large ordinary Vec outside the turn and then credit its transfer.

Existing `tick_source::ToolRunTickSource::admit` requires `size_of::<ToolRunTick>()` copy and a SealedShared birth. Operation/trace capture also declares whole source-handle copy. Therefore emitting a completed inline Tick and wrapping it with the old source issuer is another actual original17 boundary; a new direct final-native initializer/issuer or a genuine unchanged borrowed source session is required. No whole-Tick cold adapter is accepted.

For a direct final-native issuer, the native source frame must be allocated under the original capacity grant first, then each required field initialized in place by its registered source/typed owner. Partial initialized fields remain tracked explicitly through cancellation. The final source header and typed page pointers stay stable. Enclosing semantic publication, native alias capture, handback, receipt and final presence removal each have separate metadata turns with no invented source-copy cost. Root fields are1 identity,2 sequence,3 optional progress,4 step records,5 trace page bodies,6 operation byte bodies,7 LEu64 entity column,8 optional retract and9 opaque bytes. Progress has an identity child, scalar status/counters and step records. Trace page bodies contain an identity plus nine byte columns. Each nested page must decode from its original range with the unchanged captured RecordBody policy; no raw page gather is required. Trace scalar columns can be read one bounded fixed buffer at a time and pushed to paid final native pages. Counter/argument/entity groups can be staged in fixed buffers; their original octets are charged before typed derivation.

Actual application then needs original-policy History decoding for operation bodies, strict freshness, trace and step publication, payload custody, provisional mutation/refold and original error receiving.
