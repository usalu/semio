# Framework Fixture and Asset Separation

## Scope

This report covers `🧰️framework` except `🛍️products/🦑️repo` and every `✏️s` subtree. Narrow root, repository-library, Hub, and launch-configuration references were changed only where a framework move required an exact consumer update. The coordinator owns ticket lifecycle and the platform URI work.

The completed wave classifies each path by use: example inputs and expected outputs live under the nearest language-neutral `🧫️fixtures`; runtime-served content lives under `🖼️assets`; schema contracts live under `🧬️schema`; executable test support lives under `🧪️testkit` or a semantic `🧩️support` owner; executable assertions live at `<owner>/🧪️tests/<case>/<implementation>`.

## Outcome

- 453 distinct old paths map to 458 distinct new paths. The history includes intermediate paths that were subsequently canonicalized. Five destinations were created rather than moved: two Value test implementations, one plugin oracle implementation, and two Store-owned copies of retained ticket examples.
- Every recorded physical move compared SHA-256 immediately before and after the move. All move-time comparisons matched. Thirty-three moved destinations were subsequently edited for required relative paths, schema identifiers, or canonical test wiring; those files are included in `modifiedPaths` and detailed in `framework-move-evidence.json`.
- All 114 non-source examples found inside framework test-case folders moved to owner fixtures or schema folders. There are now zero fixture folders nested below a framework test case in scope.
- All 162 files below 120 legacy singular or old fixture roots moved to canonical `🧫️fixtures`, support, testkit, schema, or test owners according to their actual role. There are now zero files below a legacy fixture directory name in scope.
- Infinite's four PNG/JPG/PDF resources are runtime content and now live under `♾️infinite/🖼️assets`; authored routes and the generated WebGPU worker use `/infinite-assets`.
- Flow ABI JSON, OS media projection, and plugin runner/completion contracts moved to schema owners. Production dependencies remain only on schemas/assets where the data is part of runtime behavior.
- ABI, UI host, WebGPU surface, OS host codec, replication, Value, Flow retirement, neural, and plugin checks now load examples inside canonical test implementations.
- MCP's public fixture module moved to `🧪️testkit` and is mounted only for tests. Its caller supplies conformance JSON. Durable-group testkit likewise accepts fixture text from the canonical caller. The Scale crate and JCO guest package moved from fixture trees to OS testkit.
- Rust mutation modules masquerading as fixture data moved to Store, plugin, SPR, builder, and reactor testkit/support owners. Direct Rust `#[path]` links into fixture `.rs` files are gone.

## Remaining source-shaped fixture inputs and outputs

The final physical inventory covers 5259 authored framework files in scope. It finds 53 source-shaped fixture files, all classified individually in `source-shaped-fixture-classification.json`:

- 48 checked-in JCO transpilation/binding outputs used as expected test results.
- Four Cargo/Rust/WIT browser actor guest files used as a finite component input by testkit generation.
- One hostile Rust fragment used as a compile-fail parser input.

Only two `.rs` files remain under fixtures: the finite browser component guest source and the hostile compile-fail fragment. Neither is selected as workspace/package executable support, and neither is a production dependency. No production support module remains under a fixture owner.
