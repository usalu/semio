# Compiler Resource Observation Contract

The actual caller capability is `SEMIO_COMPILER_RESOURCE_ROOT`, resolved by the existing producer storage policy to `<buildDirectory>/semio-compiler-resources`. It changes observation storage only. Compiler selection, features, budgets, payload ownership and grants remain unchanged.

Each actual proc-macro entry creates an immutable unique capture directory and completes `observation.json` before returning tokens. A completed envelope is version 1, kind `compiler-resource`, producer `{manifest,source}`, caller `{manifest,crate,source}`, `builtAtMs`, `observedAtMs`, `completed:true`, and `resources`. The original producer and caller paths are absolute. Each read row is `{kind:"read",path,output,callsite:{source,line},operation:{source,line,name},snapshotOperation:{source,line,name}}`; `output` is the exact original read bytes retained in the actual observer root’s content-addressed `snapshots` pool. Each directory row is `{kind:"directory",path,entries:[{path,kind,symlinkTarget}],callsite:{source,line},operation:{source,line,name}}` with the exact complete original roster and file/directory/symlink types and original raw read_link targets (null for non-symlinks). Empty resources are explicit observations of a completed entry, never inferred from absent capture.

The standard-only helper tracks every actual original file and directory via the proc-macro owner's `proc_macro::tracked::path` callback. Files then bind to rustc consumed-byte checksums. Directory inputs become explicit typed `unit.inputs` observations rather than being discarded as non-files; directory digests use canonical sorted `[name,kind,symlinkTargetOrNull]` JSON with SHA-256. Directory metadata encounters are separate from file content reads: merely observing a fixture directory entry does not claim embedding or reading its corpus. A fixture file read remains refused.

Completed generic Cargo receipts retain `compilerResources` separately. Each record contains `path,text,sha256,observedAtMs`, original producer/caller identities from untouched envelope, `resources` with exact `input` row plus original/snapshot digests or current directory roster, and a bound actual production caller unit. Reuse must require original entry/source, producer compiled unit, caller crate/source/features/config and same observed .d inputs plus current bytes/rosters. Missing original observations force the existing registered producer; cached fresh compiler messages cannot imply that no resources were read.

Consumer refuses ambiguous caller/producer unit matches, missing source/checksum/roster, incomplete capture, stale hashes, relocated owners, or different invocation configuration. Generic producer code remains an observation-only collector behind existing relay/native-build interfaces. No package-name union or unknown-filesystem waiver is introduced.

The sibling plugin lane owns only existing relay/native-build observer root environment and capture retention. The runtime lane owns helper, exact proc-macro read callsites, genuine per-value contracts, neutral actual macro oracle, consumer validation and source graph proof. Actual host resource reads outside this capability remain unresolved.

## Exact operation graph integration

Original observation rows now carry `operation` (`source`, native line, `read` or `read_dir`) and read rows also carry `snapshotOperation`. These name the actual internal filesystem operation in the same compiled/current helper source, separately from the outer owner `callsite`. The verifier requires both producer and caller original compiler messages, matching current inputs and rustc consumed-byte checksums. It maps a verified operation only when the owned Rust parser finds exactly one corresponding reader token on the recorded source line; the graph owner contains the raw source SHA and that token's UTF-16 offset. Original directory listings become typed terminal graph nodes; enumeration does not imply consuming listed child bytes. Empty observations never manufacture empty read owners.

`runtimeMergeResourceReadOwnersV1` preserves all compatible inputs across observations for the same source hash and token offset. Contradictory source hashes, input digests/kinds or directory metadata are refused. The CLI selects frames by the same original producer/caller package and caches parsing only within that inspection; completion freshly rechecks each immutable capture and its actual input evidence.
