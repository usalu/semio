# Owned Output Ceiling Design

Read-only Source cut; no tests run. Original runOwnedCommand31–33 pipes directly to parent outputs before optional observer43–55. Therefore an onLine-only limiter cannot enforce real forwarded output or work without an observer. It also retains arbitrarily long unterminated text.

Add genuine optional owned-output domain limit object with positive integer maximumBytes/maximumLines; validate before spawn31 and use one combined stdout+stderr counter. Attach bounded handlers unconditionally for a supplied limit. Count raw Uint8Array bytes and LF byte boundaries before forwarding a chunk, before decoder/publication, and before growing pending strings. Reserve/count a nonempty unterminated line when its first byte arrives, so a giant partial line cannot evade maximumLines; a following LF closes that same line, and consecutive LF bytes each start/finish an empty line. Keep independent stream open-line state with shared totals. UTF8 bytes, not JS string length, define maximumBytes; StringDecoder stays per stream for unchanged text callbacks and final tails.

Replace direct pipe with the admitted forwarding path, preserving backpressure: pause each source when destination.write returns false and resume on drain; do not enable simultaneous direct pipe. On first over-limit event retain a stable refusal reason, suppress subsequent forwarding/publication, terminate the actual owned tree through existing terminate, continue draining/discarding until child close, await parent destination flush, then refuse. Do not throw inside data/end callbacks. Chunk rejection can conservatively refuse the whole crossing chunk; define this explicitly rather than claiming an exact maximal prefix. Preserve genuine process status on ordinary failure and existing progress-publication refusal ordering.

For stdout ignore, decide the contract as produced combined transport rather than visible output: pipe and discard stdout while still counting it if that is the authored native transport promise. Leaving stdio ignore would make that promise unobservable. Separate routing destination and production-byte accounting in the defining API.

Strong existing seams: stdout/tests uses an actual independent Node stdio oracle with Ω/😀, closed destination-domain Ajv and pre-spawn invalid destination refusal. progress/tests compares real Node output/JSON5 and awaited progress channel. Extend original owned-execution test owner with plain language-neutral ceiling cases in accompanying input, real Node split writes, and actual tree/drain witnesses. Verify exact limit success, one-over refusal with no excessive forwarded bytes, combined stdout+stderr, empty lines, final tails, no onLine, invalid policy no child marker and cancellation while backpressured. Do not create a whole-fixture schema; admit individual genuine limit records against the production domain.
