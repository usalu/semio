# One Controlled Ownership Engine

Current CJS defines the original physical seam state/list/readText; dependency-direction bootstrap supplies its own real operations and expects synchronous readBunRepositoryMembership. TypeScript direction37 also expects synchronous membership. Existing schema-first Source declaration remains the actual input authority.

Smallest clean design is one generator-based ownership computation in this defining lower CJS owner, not a second async walker. It yields a structured operation boundary before/after each state/list/readText and each bounded candidate-selection batch. Existing synchronous callers drain it through original operations; an async controlled drain checks actual signal/deadline, publishes progress and awaits genuine continuation between boundaries, then supplies operation results back. Neither runner changes ownership rules. No wrapper grants, duplicate traversal implementation, optional compatibility path or second policy language.

Generator must include document resolution and owner-guard/negative-tail checking, not just directory recursion. Reuse one invocation-local directory/document cache across discovery and all six packages/native projections so the gate does not repeatedly rebuild full subtree inventories. Keep current cache insertion only after a complete subtree; cancellation discards invocation state, never publishes a partial membership. Preserve byte/current-source epoch and physical no-symlink checks. Avoid copying whole subtree arrays repeatedly when a single flat directory/package index can serve selectors, but only after meaningful neutral behavior/scaling laws prove equivalence.

Production schema should define only genuine operation/progress/result DTOs if exposed (operation enum, normalized original path, performed-operation counter, complete membership); control ports remain first-party typed interfaces with original signal/publish/yield. Plain test examples do not acquire schemas. Independent fast-glob and installed Bun must compare sync and async complete results. Denial/cancel cases prove no later operations/no published complete result and exact unchanged original owners. Include cancellation after state before list, after list before child, during many candidate checks, and source mutation before final publication.

A single synchronous readdir/read cannot yield internally; qualify that atomic-operation bound honestly. Large entry lists/selection loops need explicit batches to avoid moving the entire expensive step between two nominal yields. Canonical command must forward its original invocation, not create finite policy. Existing synchronous Nx/bootstrap callers retain meaningful pure ownership semantics through the same engine, while expensive canonical gate gains actual controllability.
