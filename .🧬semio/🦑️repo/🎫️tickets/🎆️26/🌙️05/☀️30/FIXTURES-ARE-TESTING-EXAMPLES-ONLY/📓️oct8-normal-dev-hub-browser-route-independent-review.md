# Normal Dev Hub Browser Route Independent Review

An existing reusable registered route is Dev `hub-document-sweep`, routed through `verify hub-sweep` in the existing package project and verification owner. Its actual implementation is Dev `🧪️tests/🗂️hub-document-sweep/🟦️.ts`. It uses withDevServe and Playwright, signs in through actual shell UI, opens the Hub Space Browser as the shell base session, selects creation kinds from that actual space catalog, creates/opens documents, records execution-target/install statuses, performs edits and optional reopen/cancellation. Credentials come from OS_HUB_PROBE_EMAIL/PASSWORD or the existing development user's defaults; this is a real sign-in request, not fixture-session injection. It does mutate development documents and emits an acceptance record, so it must remain an explicitly owned execution with actual normal Dev Hub6 selection/current publication rather than an isolated catalog substitution.

The actual Store chain remains server-selected: authenticated hubSessionFetch POST of bounded DocumentOpenIntentV1 to `/spaces/{space}/documents/{document}/execution-target/{manifest|component|descriptor|browser-actor}`; request owner rejects arbitrary package/digest/generation/path selectors and intent-space/document mismatches. DocumentExecutionTargetLease checks the live grant/session, streams/bounds exact actor bytes, hashes them, transfers through the bound private child and invokes actual describe. Child independently hashes, imports the verified Blob at the exact operation and checks activation/invoke/close. Thus reusable sweep can establish real document activation and edit/reopen behavior, but its existing receipt alone does not explicitly join original Cargo/current companion provenance to protected response/child execution per selected package.

The generic physical UI journey owner is a renderer interaction oracle, not proof of all selected Hub actors. Likewise isolated GIS/stdio browser checks are focused component evidence and cannot satisfy normal Dev6 publication. The production proof should retain actual normal data root/current pointer + selected package rosters, exact authenticated target/actor/descriptor responses and child activation/describe evidence; use the existing owner route or a narrow permanent extension, not a fake session or public GET asset shortcut. No HTTP, sign-in, document mutation, browser, build or lifecycle command ran in this audit.
