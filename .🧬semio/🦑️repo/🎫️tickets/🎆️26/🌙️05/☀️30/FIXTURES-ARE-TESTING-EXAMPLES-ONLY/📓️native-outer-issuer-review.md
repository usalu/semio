# Explicit Outer Native Issuance

Read-only current cut, no execution. New peer law explicitly distinguishes receiving existing caller authority from issuing production authority: missing native must remain generic, missing/foreign selection must refuse, and original envelope/resources must stay unchanged. This is coherent with greenfield separation of issuance and receiving.

Use an explicit trusted outer bootstrap issuer before creating the original native-capable launch envelope. It receives the genuine production NativeOwnerExecutionPolicyV1 plus current canonical artifact/network environment, original user request and actual admitted selected command. It validates supplied authority unchanged when present; it issues config-owned resources only when the bootstrap itself owns the new launch. Receiving nativeNxChildEnvironmentV1 should preserve complete existing resources and exact selection, and return generic launch unchanged when no native authority exists. It must not silently upgrade that generic envelope.

For provision/watch commands bootstrap owns new child-launch capability, distinct from the user selected target. Keep original request provenance and unchanged parent policy/deadline, but issue explicit launch-context selector for the actual bootstrap-owned operation. Do not repurpose the already bound user native selection. A schema-first launch context with requested arguments, selected arguments and explicit source of issuance is preferable to a boolean allowReselect switch. Test generic passthrough, explicit native preservation, foreign-selection refusal, and separately trusted provision/watch issuance through actual launch body.

Current owned-execution gate validates output policy before spawn, shares raw byte/line totals across streams, counts open tails independently and admits before forwarding; ignored stdout is counted when a limit exists. Transform forwarding retains pipe backpressure. This is improved defining behavior, separate from its pending test proof. Native owner-command still does not pass `output:original.transport` at line62 in the observed cut, so admitted transport is not yet enforced on that actual route. This is a concrete wiring requirement, not a reason to manufacture new resources or weaken schema admission.
