# Frozen Fixture Runtime Boundary

Actual Source normalizer consumes admitted repository reference subjects, not an unconditional fixture boot catalog. Nevertheless, frozenEvidenceRecord validates a registered fixture's complete hash, JSON root and schemaVersion, then parses designated source/destination pointers into spans that suppress reference rewriting. A mismatch becomes a blocking plan violation; transaction preflight also invokes the same whole-document authority. This is stronger than opaque filesystem management.

Call chain: referenceGraph parses fixture payloads into reference edges; incomingReferenceSnapshot captures fixture subjects; planReferenceEdits calls frozenEvidenceRecord, which calls frozenCoordinateEvidenceCoordinates; isFrozenSourceCoordinateToken suppresses those parsed spans; terminal preflight calls frozenEvidenceCoordinateAuthority. Root metadata currently enrolls several actual Tests/Fixtures corpora by hash and array pointers.

The minimal clean extraction is a general domain test-fixture payload boundary using the existing testsDirName/testFixturesDirName policy fields. Inside canonical Tests/Fixtures, actual bytes remain physical inventory/hash/move inputs and host Source imports remain genuine edges, while fixture contents produce no production reference edges, ownership policy, frozen enrollment, preflight reference authority or semantic rewrites. Genuine production policy/transaction/report document coordinate authorities remain outside this boundary. Root owns removing fixture rows from metadata seals/populations; child owns the normalizer classifier and Source tests. No fixture hash refresh or asset reclassification is justified.
