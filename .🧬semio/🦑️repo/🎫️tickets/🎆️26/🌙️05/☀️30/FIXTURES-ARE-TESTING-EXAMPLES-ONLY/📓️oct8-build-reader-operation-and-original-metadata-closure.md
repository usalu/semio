# Build Reader Operation and Original Metadata Closure

The current authored build filesystem owner is WGPU `catalog_sources`. General Canvas and OS Infinite current manifests/source have no former asset builder entrypoint/read_dir; historical paths are not replaced with compatibility stubs. WGPU now invokes the owned `ResourceObservationsV1.read_dir` once, receiving the real original `DirEntry` values. The helper records the exact internal source/line and original entry kind/raw link target metadata. Its `read` wrapper records the original bytes and output snapshot at the real internal operation. Handled read failures remain normal I/O errors and emit failed rows; the runtime guard refuses them rather than inferring empty successful inputs. Copy behavior and selected Cargo/Trunk invocation remain unchanged.

The existing per-value `RuntimeBuildResourceObservationV1` schema now requires typed directory entries plus an exact operation, requires an operation for read rows, and admits explicit failed-read observations. Plain neutral examples remain schema-free collections. The generic completed Cargo collector retains original JSONL rows, typed current directory digests/entries and original/output bytes separately.

`runtimeBuildResourceReadOwnersV1` requires the same single selected host custom-build unit and OUT_DIR; it verifies current surviving producer bytes, actual source checksums and current original observations before mapping the unique reader token to its raw source SHA and UTF-16 offset. Directory nodes compare original metadata digests and terminate without reading child bytes. Enumeration alone does not establish a child-content edge. The CLI uses these exact owners for both target generated resources and host build-source graph inspection. Failed/conflicting/unbound evidence remains refusal.
