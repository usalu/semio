# Geometry Transfer and Canvas Test Review

Original Geometry engine517 PathEl is a plain enum of Point coordinates; BezPath526 owns a private-to-Geometry Vec<PathEl>. Public elements554 clones the Vec, so it cannot be an original custody transfer. retirement_step577 pops elements and retirement_backing_bytes581 exposes saturating capacity*sizeof; neither establishes a supplied physical grant. Package facade reexports engine types; Cargo dependencies are empty and Kurbo/Serde are test-only.

Smallest defining Geometry ownership port is `BezPath::into_elements(self)->Vec<PathEl>`, moving the actual Vec without cloning or reallocating. An optional borrowed slice view can provide preflight identity without calling elements(). Geometry need not acquire Value or implement external retirement traits. Canvas can define its own local PathElements owner/cursor holding that original Vec, with trivial coordinate element handling and checked capacity*sizeof(PathEl), preserving pointer/capacity/order and empty spare backing. Do not implement Value RetireOwned for Geometry PathEl from Canvas (orphan boundary), convert into a fresh Vec, or price len instead of capacity. Canvas RecordedShape can wrap only its own local owner after funded admission, preserving original BezPath on denied preflight.

Existing first-party test allocator utility is Trace memory/testing/requests: RequestedAllocator delegates HeapWitness, records inclusive original requested/released layout bytes in scoped thread-local storage, and supplies observe_backing. Current Canvas package facade has no cfg(test) global allocator binding, so the utility is available source infrastructure but not presently installed for Canvas laws; package test-only wiring and Trace test dependency must be explicit. Keep one global allocator per test binary.

Original Canvas tests include renderer-color-stroke-raster at387 and opaque-scene-retirement at1203; actual registered Canvas:test runs the package through permanent canonical Cargo policy. Geometry first-party-shape tests already compare PathEl sequences and geometric bounds with Kurbo. Extend those genuine oracles with allocation-free consuming transfer/pointer/capacity/order checks and Canvas System construction-to-terminal born==freed under fixed independent five-axis grants, denial/cancel original restoration, empty retained capacity and separate final frames. Construct Kurbo/oracle data outside allocation scopes so incidental oracle allocations cannot masquerade as owner receipts. No native or test execution is credited by this design review.
