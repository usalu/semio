# Hub Production Provenance Contract

The existing trusted-catalog bootstrap remains the producer. Its package roster, Cargo arguments, component profiles and selected data root remain unchanged. No production run is dispatched during implementation.

The immutable generation retains `producer.json` with schema `semio.hub.trusted-catalog-producer/v1`: `profileId`, `generationId`, `bundle` ({relativePath,sha256,byteLength}), `packages` ({pluginId,packageId,component,descriptor,cargoInvocations,browserActor}). Every byte claim contains generation-relative path, byte length and SHA256. Cargo invocation claims name actual completed compiler receipts retained beneath the package provenance directory; receipt contents preserve original compiler messages, exact source/.d checksums, resource observations and original/staged artifact identity.

An actor package retains `browser/producer.json`: schema `semio.os.closed-browser-actor-producer/v1`, actor/component/descriptor byte claims, `policyCanonical`/`policySha256`, actual Bun executable path/hash/length, actual compiler module retained bytes/hash/length, and `inputs` mapping the canonical policy logical source identities to physical paths/hash/length observed during the original reads. Logical policy inputs remain unchanged. The compiler module is copied from its real producer output, never synthesized after cleanup.

After the existing native publisher returns and the ordinary current pointer is reread and verified, a separate immutable publication record is retained at `trusted-catalog/provenance/<currentPointerSha256>.json`. Schema `semio.hub.trusted-catalog-publication-producer/v1` binds absolute `dataRoot`, actual current pointer path/hash/length and publication revision, generation ID/profile, bundle and immutable generation producer path/hash/length. The current pointer cannot be bound before publication without inventing authority; this separate final record binds it without mutating the generation.

The semantic module `🌎️hub/🏗️bootstrap/🧾️provenance/🟦️.ts` exports `trustedCatalogProvenancePathV1(dataRoot,currentSha256)` and `readTrustedCatalogPublicationProvenanceV1(dataRoot)`. The reader observes the actual current pointer and exact durable record; stale/missing records refuse. Root can import this owner helper for default selected actor admission, and acquire missing evidence through the existing `os-hub:trusted-catalog-bootstrap` route. It must still check selected package/callsite and all compiler/resource currentness.

Existing generations lacking producer observations remain unproven; no upgrade of historical bytes into new evidence. Identical catalog generation IDs may already exist: a newly observed record must remain a distinct completed production observation rather than overwrite a historical receipt. Exact evidence placement for this repeated-generation case will be settled with the retained generation record implementation.

## Exact Runtime Roster Correction

The real generation fence permits exactly packages/plugin-modules/trusted-catalog.json and the selected runtime file rosters. Evidence therefore lives in the durable companion `trusted-catalog/provenance/generations/<generation>/<observation-id>/producer.json`. Component/descriptor/actor runtime claims remain generation-relative. Cargo receipts, actor producer records and retained compiler bytes use `ObservationClaimV1` absolute path/hash/length, constrained beneath that generation-keyed companion owner. The immutable final pointer receipt binds this exact producer path. This preserves the current strict native/TS directory authority and allows repeated production observations without overwriting earlier receipts.
