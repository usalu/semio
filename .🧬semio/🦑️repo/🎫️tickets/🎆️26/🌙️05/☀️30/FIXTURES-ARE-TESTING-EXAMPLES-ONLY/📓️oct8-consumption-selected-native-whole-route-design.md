# Consumption-Selected Native Preparation Design

Read-only source review; no tests or producers were run. This is a proposed law set, not repair or runtime completion evidence.

The normal cargo setup operation deliberately serially processes the 231 currently admitted repository workspaces. Preserve that explicit full setup operation and its launch registration. A compiler invocation instead needs its actual physical Cargo owner and the owner/member dependency closure needed by the selected invocation. Selection belongs at the Cargo-consumption boundary, including Cargo invoked by Trunk and the descriptor emitter; it must not infer permission from a project name, special-case WGPU, expose a skip flag, or reuse an earlier preparation receipt. Generic outer `owner-command` currently synthesizes test preparation before the inner pair, so changing only the pair helper does not establish the desired whole-route behavior.

Define a language-neutral production contract for consumption intent: actual manifest and cwd, command/target/profile, exact package selectors, feature/default-feature selection, and physical owner/dependency identities. Bind these to current manifest bytes and current prepared graph. The contract should distinguish explicit repository setup from consuming an invocation, and state dependency-first preparation, fresh graph/member closure, exact current recipe coverage, update/fetch custody, cancellation, and no unrelated-owner execution. Do not make caller-supplied owner lists authoritative; derive and validate them against current physical manifests and the invocation's Cargo semantics.

Preserve the original compiler request without rewriting flags to simplify preparation. Current WGPU source emits locked/offline metadata, Trunk `build --config … --skip-version-check --offline true --color never`, and provenance expects Cargo `build --target=wasm32-unknown-unknown --manifest-path …`, optional release, `--offline --frozen --locked --message-format=json`. Its worker/web bindgen configuration and wasm-opt z remain part of the original route. Current Hub bootstrap forms requests from the selected package closure with `componentProfile: wasm-release` and `rootCdylib: true`; the six-package proof remains stdio, gis, note, writer, draw, puzzle. Stdio's component source retains `rustc`, explicit manifest/package, `--profile`, `--lib --crate-type cdylib --target wasm32-wasip2`, and separately builds `semio-framework-plugin-describe`. Preparation must cover that second actual consumer as well. This inspection has not independently inventoried every four-guest feature vector; the implementing lane must retain exact preimages of all four normal command arrays and compare their final arrays before claiming preservation.

Whole-route TDD must start at the genuine normal wrapper/inferred task boundary, not call the pair helper directly. A neutral workspace contains selected owner, local child, generated new child, child-mutated ancestor dependency, changed existing recipe, and an unrelated owner whose preparation fails if invoked. Record ordered preparation/update/fetch/compiler events. RED must reproduce repository-wide unrelated preparation or outer duplicate; GREEN must execute the selected current closure before consumption, exclude the unrelated owner, and execute each required recipe once within the consuming transaction. The independent oracle is actual Cargo locked/offline metadata with resolve edges and exact workspace members after preparation; `--no-deps` alone cannot validate transitive selection. Exercise feature/target/package selectors against that oracle, including multiple consumers and the describe tool.

Retain existing Unicode scanner, fresh re-resolution, consumed-read bytes, child-introduced ancestor dependency, final current recipe-key refusal, lock immutability, cancellation/lease cleanup laws. Add an explicit full-setup route law proving all admitted owners remain selected in the original order. Verify task inference no longer inserts global setup for ordinary consumers while tool installation and generated browser prerequisites remain selected. Preserve permanent `📜️script.ts` ownership and launch registration; independent system closure comparison and exact original compiler/package/feature vectors are required before normal production rerun credit.
