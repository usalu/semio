# Fixture Boundary Enforcement

Fixtures are testing examples. A contract facet inside an example collection is always inadmissible, including JSON, SQL, GraphQL, protobuf and TypeScript facets or a document declared inert. Ordinary schema-shaped parser inputs can remain explicitly inert example data outside any contract facet.

Repository discovery and test isolation both use exact declared collections; semantic testing support owners remain eligible for real contracts. Module-member carve-outs follow the taxonomy declaration, including a framework module whose own name equals the schema facet. Adjacent exported Fixture/Corpus/Cases wrappers are rejected when their structure declares expectations or a test corpus marker, and never enter the schema export catalog. Genuine physical fixtures, semantic case inputs and produced diagnostic reports remain eligible.

Language-neutral schema catalog examples cover semantic testing owners, all forbidden collection contract formats, retired facets, explicitly inert parser examples, adjacent corpus contracts, genuine physical fixtures/cases and actual produced SchemaFixtureReport contracts. Independent Ajv dialect validation and Rust export inventory agree. Final catalog rerun: four tests, zero failures, 142 expectations.
