# Publication Checkpoint Preparation

General IO still binds concrete Store transactions and codecs. The next lower prerequisite is an owned publication checkpoint: the transaction retains the exact admitted cancellation token and ancestry bound, checks that authority without releasing its gate, and does not invoke an observer or consume another admission attempt. No IO ownership extraction or native checkpoint implementation is claimed by this preparation.

The new closed language-neutral corpus contains eight handcrafted scenarios: live ownership, current cancellation, current parking and resumption, parent cancellation, parent parking and resumption, cancellation dominating child parking, the exact 4096-node ancestry bound, and unrelated-token cancellation. Every observation requires one admission attempt, one progress event, retention of the gate, and successful reacquisition after disposal.

The existing publication-contract command now includes the new schema/fixture law through its owned script. The first compiler run found an incorrectly resolved relative validator import; that carrier was corrected without changing any assertion or fixture. The second actual Nx run passed strict compilation and all seven tests across both files, with 493 assertions, in 1.1 seconds. The original four admission laws and original 30-row admission corpus remain intact. Owned schema admission agrees with independent Ajv, and an actual independent Node process produces the exact eight ancestry observations. These portable results do not prove native transaction behavior.

Two new native laws are prepared as a pure addition to the complete existing native publication test source. They execute every scenario in a distinct process gate, compare retained/released gate behavior to an independent parking_lot mutex, and check unchanged attempt/progress counts. Both existing Rust sources remain exactly equal to the captured before inputs until the short Record/derive validation epoch releases them. The missing checkpoint API must produce a genuine native compiler failure before production is mounted.

The canonical lifetime decision separates the observer turn from the admitted token lifetime. PublicationControl will borrow the token and observer with distinct lifetimes; PublicationTransaction will borrow only the admitted token. A transaction can therefore survive its local progress observer while it cannot outlive its token. The private non-Send guard stays private. The existing bounded ancestry walker will move to one private shared function rather than being copied into the transaction. The full original native roster, corpus, compiler-negative guard laws and external positive law must be retained and replayed.
