# Space Shared Authority Source Research 3

The shared runtime already lives physically at plugin-root `🫀️core/🦀️.rs` (758 lines), with its portable document preparation contract/schema/fixtures/tests beside `📄️documents`. Space mounts that root as `space_core` only under component app assembly. Home reexports the sibling's entire mounted core under the same app feature, so deleting Space removes Home's shared authority despite the neutral source file remaining.

Merely packaging this source is insufficient: the source imports Space-specific `SSpaceSnapshot`, `SSpaceMutation`, document schema constant and two timestamp functions. Two index-specific functions decode/fold an `s.space` index and project its rows to General collection rows. An actual full-repository Rust/TypeScript caller search found no callers of these index resolution/projection functions outside their own definitions and internal calls. The old prose describing a Home workflow caller was not source evidence and that assumption is corrected here. A new core package that retained these imports would create the same reverse edge from shared contract to concrete child.

The actual index resolution and projection therefore belong with the defining Space artifact, while the backbone byte receiving helper is shared authority and the original Space schema and its four actual mutation leaves remain owned by that artifact. Folding the actual event journal must remain part of index decoding; parsing only its initial snapshot or weakening index-first resolution would lose original behavior. Moving mutation leaves into common core would also change their physical descriptor ownership and invalidate the original two-coordinate producer scope, so that is not an acceptable shortcut.

Timestamp helpers are already used by both Home table rows and the Space artifact snapshot table and can belong to the genuinely shared neutral core implementation, with original UTC/RFC3339 vectors preserved. The portable document preparation helper independently knows caller-owned codecs and no selected artifact implementation. Common retained Store preparation is likewise generic over snapshot/mutation types but still targets the actual retiring Value/Store API, so its eventual native compilation must consume Native8's coherent closure.

The shared source still contains pre-existing global catalog/port state and explicit retained ownership blockers. This lane does not claim that moving its authority resolves those separate runtime interactions. Current source contracts and all original fixtures must remain intact through extraction. No shared authority production source or package has yet been modified.
