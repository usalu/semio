# Controlled Cargo Inventory Command

The general inventory execution module owns the selected Cargo producer lifecycle. Specific artifact entry points supply only their own manifest, binary and working directory. The command imports first-party policy validation and process execution; it contains no S, Hub, plugin or artifact identities and introduces no runtime library dependency.

The closed request schema requires absolute manifest and working-directory paths and a bounded canonical binary name. Authored collector arguments must match the operation policy exactly. Both Cargo storage environment fields must equal that policy before process or directory admission; the caller's environment is forwarded without an extra clone. Cancellation and the deadline remain active through compiler execution, controlled capture reads and backpressured CLI output. Native refusal codes are preserved.

The language-neutral corpus contains four selected-producer cases and five refusal controls. Genuine Cargo fixture execution is compared with installed Execa, and closed results are checked with installed SQLite. Request and law schemas are also validated with installed AJV. These libraries are confined to tests.

Independent inspection admitted both the actual publication and owning execution in `continuation-cargo-inventory-command-actual-publication-owning-audit.md`.

This admission covers the selected command and its owned process payload. It does not establish complete compiler heap ownership, atomic publication, artifact descriptor execution, physical artifact deletion, or whole-repository acceptance. Artifact relocation and the old specific dispatcher retirement remain held until their concrete caller and native gates are satisfied.
