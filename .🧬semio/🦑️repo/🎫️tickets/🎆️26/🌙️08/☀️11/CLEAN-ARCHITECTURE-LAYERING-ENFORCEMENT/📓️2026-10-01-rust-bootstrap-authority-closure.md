## Existing helpers: useful guarantees and limits

`📚️library/🔍️discovery/📖️source-access/🟦️.ts:33–55` policySourceAncestry resolves repoRoot and relPath before examining root plus target ancestors. It rejects normalized escapes, but loses authored `missing/../leaf` and `link/../leaf` prefixes. It does not inspect ancestors **above** repoRoot. For an empty relative locator it inspects no ancestors; directory/text wrappers separately inspect their leaf. policySourceText at 79–98 and policySourceDirectory at 58–76 reject linked leaves and interior ancestors. Convenience policyReadFileSafe maps missing to empty text (113 onwards), unsuitable for required policy/taxonomy manifests. policyReaddirSafe similarly permits missing→empty where only an explicitly optional owner warrants that behavior.

The stronger existing workspace authority is `📚️library/🔍️discovery/🟦️.ts:1226–1278`: workspaceAuthorityPath rejects raw dot/parent/NUL/drive-relative/compose segments **before** resolve; noFollowDirectoryAncestry walks from filesystem root through root; resolveWorkspaceTaxonomyAuthority requires real nx.json and 📋️project.json, reads root metadata.semio.taxonomy, validates its canonical slash locator and lstat-checks each component. Reuse this root/locator authority; do not hardcode a second taxonomy locator in the gate. Its noFollowDirectoryAncestry function itself assumes a previously lexically validated path; direct callers must preserve that precondition. Relative root strings still resolve against cwd, so the loading contract should accept a canonical absolute root with explicit provenance.

loadCatalogTaxonomy/loadTaxonomy at 1324–1342 cache global boxes and resolve from discovery __dirname, not from an arbitrary gate root. These are not a fresh root-scoped policy snapshot API. Calling them after creating a second fixture workspace can use another root's cached taxonomy. The gate must parse/validate the taxonomy bytes of its own validated authority per invocation.

## Hazard matrix

Linked policy/taxonomy/package leaves: direct reads or require follow them before any scanner check. Linked code/input ancestors: lstat leaf is insufficient; recursive policy imports also need ancestry. Linked gate root: subpath lstat follows it; inspectRustSourceInputs only checks root directly for target '.', not generally. Linked root ancestor: checking root itself still misses it. Raw missing/link prefixes followed by '..': normalize-before-check erases necessary traversal facts. Stale require cache: validating disk today then requiring a cached export from yesterday does not establish today's policy; root policy changes, recursive module changes and workspace contribution changes can all be hidden. Clearing only the top .cjs cache leaves child TS exports or cached membership objects alive. Resolving symlinks before checking caches also merges distinct authored locators into one cache key. Reading taxonomy twice independently can disagree with the executable policy's cached copy.

## Recommended clean loading contract

Prefer eliminating executable policy loading from the Rust gate. Move the actual policy rule construction into one owned pure first-party builder receiving a closed, validated policy snapshot; the CJS dependency-cruiser entry and Rust gate both call that canonical builder. Do not copy a subset of rules into the scanner. Builder inputs cover taxonomy, plugin/workspace membership and package role contributions, including the exact same strict layer rules currently selected. CJS becomes a thin caller of the same loading contract, so unsafe reads do not survive in the producer.

The loader must first establish root authority with the existing workspace helper, then use source-access operations for each required file/directory from that root, with lexical relative locators validated before join/resolve. Strengthen reusable source-access semantics or require canonical locators at its public boundary; explicitly reject dot/parent paths for bootstrap assets rather than reusing normalized traversal acceptance. Rust compile input traversal remains its separate raw-segment contract. Establish every root ancestor once per snapshot. Required text reads must require state=file; optional directories must distinguish absent from linked/unreadable/wrong-kind. Return explicit provenance records and immutable parsed snapshot values; no global cached taxonomy/CJS export is policy authority. Build cancellation/progress into the membership census and report exact failed bootstrap inputs before scanning.

If executable loading is retained temporarily, a full owned module loader must validate every nonbuiltin dependency and every observed filesystem authority read **before evaluation**, restrict imports to the closed supported graph, prohibit undeclared dynamic require/file reads, and evaluate fresh per invocation under the same validated root/snapshot. A top-file precheck plus native require is insufficient. Do not claim arbitrary TS/CJS safety from a regex require census or delete global require.cache entries during concurrent work. Node builtin module imports can be declared execution capabilities; installed packages or extra code cannot silently become trusted dependencies. The pure builder cut is the coherent long-term solution and avoids a new general-purpose TS evaluator.

The executable evaluator and its statically imported library runtime are inevitably the implementation being trusted to perform the audit; define this explicit process boundary. A root policy is an input authority and must not gain execution authority merely because it is in the checkout. If the requirement extends to verifying the evaluator's own code bytes, start a fresh process from a validated runtime artifact and record that artifact provenance; validating a module after it executed is not a proof.

Demonstrate changed plugin directories, root metadata taxonomy locator, package role and payload membership are observed on the next invocation. Two isolated roots in one process must produce their own taxonomy/rules with no global-cache cross-talk. For the actual TS policy closure use the repository's supported Bun loader or the shared pure builder, not a fabricated native Node claim. On native Windows use real junction/symlink creation where supported and report actual unsupported capability rather than silently skipping all refusal coverage.
