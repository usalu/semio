# Block Cargo Taxonomy Role Admission

The canonical direction classifier selects the first matching owner rule. Shared semio-s-plugin-block is exactly the plugin-root package and its plugin role is admitted by that first rule. Nested semio-s-plugin-block-catalog is not the plugin-root package: its first matching rule is the general plugin subtree, permitting s-module, library, tool, test and extension, but not plugin. Its current plugin role therefore produces owner-role-mismatch once inventory/metadata comparison succeeds.

The smallest taxonomy-consistent repair is to classify the nested catalog as library (a plugin-owned domain library), preserving the shared plugin-root role. Do not broaden the root-plugin selector to every descendant, which would erase the explicit artifact/extension/library distinction. Add a closed neutral role/path corpus case for root plugin, nested library and rejected nested plugin, validated independently against ordered matching. If product taxonomy instead declares catalog a distinct plugin participant, author a narrowly ordered schema-first owner rule rather than a blanket exception. This source inventory does not attribute Root Cargo3 metadata mismatch to the role gap; that earlier failure occurs before role validation. No files were changed.
