# Actor Cargo Backend Boundary — Read-Only Design Audit

This review reads current source only. No Source edits, module imports/evaluation, test probes, frontend, native process, initializer, registry mutation or capability factory was run. It does not qualify a future implementation. Process GUI2 remains prepared and held. Root and HighScope own implementation and registered verification.

## Recommended composition seam

Keep the General Actor script dependent only on General Process request/port contracts. The executable backend descriptor must be a closed first-party JSON contract supplied by the actual Repo caller composition. No default Repo path, runtime dynamic Repo import, fallback factory, fake storage object, or authority embedded in an arbitrary request is justified.

The concrete existing authoring seam is `NativeScript.run`'s `owner-command` branch in Repo native orchestration, after it validates the selected command and before it launches that selected program. That branch already authors Cargo test policy, multiple manifest policies and `SEMIO_EXACT_CARGO_PREPARATION` for the same child. It can author the neutral backend descriptor in the same place. `issueBuildTaskEnvironmentV1` is the earlier authority seam: it projects the actual inferred `nativeOwnerCommand` into the closed native capability role, appends only effective selected task arguments, retains transport/child/network/buildMode/artifact grants and hands down the original Script policy and decreasing remaining deadline.

A descriptor present only in an environment variable is a receiving address, not proof that any request is permitted. Bind the descriptor and supported operations to the selected native capability/declaration at the Repo composition boundary; the Repo endpoint must validate the received original selected Actor command and the operation's actual manifest/working-directory/package/law selection against its explicit declaration. Do not replace `capabilities.command` with the backend command: it identifies the originally selected Actor command. If a new descriptor field is capability-bearing, both relevant closed defining schemas/readers and all actual callers require the canonical field; there is no permissive legacy shape.

## Existing call chain and invariants

1. Graph inference's native target binding records exact manifest, working directory, program and arguments in `nativeOwnerCommand` and routes it through Repo `native owner-command`. `issueBuildTaskEnvironmentV1` schema-validates that descriptor and creates the native capability projection from the already-issued build caller resources.
2. Repo `owner-command` validates actual request root, resolved manifest, resolved cwd, program, effective argument count/elements and artifact directory against `NativeOwnerCapabilities`. Only then does it author child policy/descriptor environment. Preserve these comparisons and the root/manifest/source obligations; an endpoint request cannot widen them.
3. The General bridge should validate the entire operation-specific request and backend descriptor before spawning. Manifest/package/groups/target/laws/args are input selections, not storage authority. Store root, allocation, Source admission, dependency network policy, target/build/home/temp paths and new Script policy are not request-controlled fields.
4. Serialize the received original invocation with **`scriptInvocationEnvironment`**. It checks the invocation and preserves policy and capabilities while clipping the wire's absolute deadline to the current remaining time. The endpoint should use **`receiveScriptProcessInvocation`** and never an initial capability factory or `createScriptProcessEnvelope`. Receiver control is a process-local signal/clock reconstructed from the original wire; parent cancellation must remain connected through the owned child-process supervisor and process-tree termination. JavaScript object identity cannot cross the process boundary.
5. Invoke the existing Repo Cargo wrapper within that received invocation. `runRepositoryExactCargoLaws` owns mode/profile/network, the original compiler control, Store, dependency inputs, preparation and the call into General `runExactCargoLaws`. `runRepositoryCargoTestsV1` similarly owns Store/dependency/source composition. These wrappers belong in the Repo endpoint process, rather than running a General law runner first with a reconstructed reservation.
6. `withRepositoryCompilerStoreV1` recovers the existing persistent compiler charge by mode/owner/id through genuine image/storage operations, enforces declared byte counts/kind/phase and scoped directories, and closes the image in `finally`. `requireNativeStorageReservationV1` checks a private WeakMap binding between the actual reservation object and control signal. A serialized object or General facade cannot satisfy it. The endpoint should reuse this existing Store recovery; do not transfer or mint a reservation in JSON.
7. General exact-law execution must continue to receive that live endpoint-local reservation and Source boundary, plan the actual Cargo graph, admit sources, recheck storage, and hold capacity/build leases. Retain the existing profile ownership, exact listed-law/hash binding, dependencies and original paid-close behavior.

## Precise existing neutral transport choices

- `ScriptInvocation`, `scriptInvocationBudget`, `scriptCompilerAdmissionControlV1` and `requestedCompilerAdmissionControlV1` provide original policy/cancel/progress and intersected phase controls. `ScriptInvocation`'s runtime exact-key guard admits only `policy`, `control`, `capabilities`; current inspected contracts expose no extra `nativeResources` slot. The native resource grant is the closed native capability data, not a newly attached control property.
- `captureOwnedProcess` accepts the original invocation, explicit finite capture policy/output paths, bounds combined stdout/stderr bytes, waits for process close, awaits progress and cancels the owned process tree. Its current spawn has **stdin ignored**. A request-over-stdin design therefore requires a real defining capture-input contract/implementation change; it cannot merely pass an unused `input` option.
- `runOwnedCommand` already supports `input: string | Uint8Array`, finite timeout, original signal, bounded byte/line output, awaited progress and process-tree cancellation, but returns `void` and forwards output. It is appropriate for no-result execution or an explicitly designed response port; it is not a structured response capture API.
- `captureOwnedCommandV1` accepts an original lease control, checks it before/during/after the child and bounds bytes/lines when supplied. It also ignores stdin. Its stdout and stderr share the returned text; it is unsuitable for blindly `JSON.parse`-ing a mixed progress/result stream.
- An explicit bounded JSON argv/environment request can use existing capture mechanics, provided its exact transport limit, selection binding and closed response schema are defined. Keep machine response isolated from progress/error output and reject malformed/mismatched responses. Do not silently parse console tails, use a shell, or treat exit zero as a typed receipt. Large request sizes must respect actual cross-platform transport constraints; no new guessed quota is approved here.

## Required meaningful laws for the implementation

Portable schema cases should cover missing/extra descriptor/request fields, wrong operation arm, wrong caller manifest/cwd/program/argv/package/law selection, altered build mode/artifact/offline/transport/child authority, and malformed/mismatched responses. Independent schema validation should agree with production admission. A pure injected executable-port test should observe refusal before spawn, original capability equality, nonincreasing envelope deadline, retained signal in the parent supervisor, exact request bytes, and no fallback factory on absent descriptor. Actual endpoint tests still must prove same-process issued storage acceptance and fake reservation refusal, complete Source admission and original paid close, original cancellation/deadline termination, and actual selected native behavior. Those runtime outcomes are not established by this audit.
