## Actual Current Ownership

Deleting Specific while retaining this authority creates 53 mandatory absent-manifest references before selected native compilation. Setting default-members alone would not remove those declared members.

Full current source/hash/inverse frames (322 bounded files) are retained in native-workspace-deletion-boundary-inputs/full-current-before-hash-inverse.json.

The root package declares its true root workspace explicitly; its neutral members inherit package rust-version, lints and selected dependency keys. Product members also point at the root workspace. Thus narrowing only members while leaving their workspace pointers and inherited declarations unchanged does not form a coherent product build.

## Existing Mechanisms To Reuse

Existing workspace APIs already implement closed schema admission, discoverCargoWorkspaces, cargoWorkspaceMembers, cargoWorkspaceForManifest, selectedCargoArguments, publishCargoWorkspaceMembership and prepareCargoWorkspaceInvocation. They discover present physical owner authorities and select the nearest declared package workspace. There is no need for a new orchestration layer, aliases, optional missing-owner rows, bypass flags or migration scripts.

The ordinary native owner-command transport currently resides in Repo. NativeScript.owner-command supplies exact caller-owned process, Cargo, Vitest and artifact policies, runs normal preparation and retains progress/cancellation. The neutral framework package script already uses General runCargoTestsV1/readCargoTestPolicyV1, captureOwnedProcess, startNativeProgress and ScriptRouter/runScriptMain. The policy-consuming execution mechanism is neutral; its policy authority/discovery transport and Nx registration are still product-rooted. Root package scripts.nx points to Repo bootstrap; nx.json names Repo library and test plugins. Deleting Repo therefore removes mandatory transport/discovery files even after Rust membership is corrected.

prepareCargoOwners scans all dependency/dev/build/target tables of every package in the selected workspace, then prepares reachable owner scopes. With the current broad root it sees all 116 General/product members. With a General-only root it must see only General packages and must still refuse every real absent dependency. Shrinking invocation scope or skipping missing packages is not a replacement for fixing these declarations.
