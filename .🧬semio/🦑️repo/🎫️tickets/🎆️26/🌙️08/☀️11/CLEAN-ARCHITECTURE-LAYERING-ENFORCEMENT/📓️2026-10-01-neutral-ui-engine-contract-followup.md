## Engine Key Collision and Canonical Input Contract

Current `🧰️framework/🛍️products/💻️os/🔨️modules/⚙️engine/🦀️.rs:109-114` hashes `UTF8(engine_id) || 0 || input`. This encoding is not injective over unrestricted IDs and bytes: `(engine_id="a\0b", input=b"c")` and `(engine_id="a", input=b"b\0c")` both encode `61 00 62 00 63`. This is a deterministic preimage collision, independent of Blake3 cryptographic collision probability. derive `:117-122` checks entries before looking up the engine, so a colliding request can hit another engine's cached output before identity validation.

Canonical new contract already prepared in `🧰️framework/🔨️modules/◻️2d/🧮️compute/🧫️fixtures/🔣️.json`: **u64le byte length, exact UTF-8 identity bytes, u64le input length, exact input bytes**. Use one schema-first first-party implementation in Rust/TS; no NUL ban, ID normalization, compatibility hash branch, or legacy key. Integer lengths refer to bytes, not Unicode characters. No external hash type may leak: EngineKey remains owned [u8;32] or a first-party encapsulated digest wrapper; first-party hash facade owns algorithm.

Prepared corpus declares 22 key vectors, 2 distinct tuple pairs (ordinary concatenation and embedded-NUL boundary), 2 representation vectors and 10 cache operation scenarios. Unicode ID `⚙️.ä` is 9 UTF-8 bytes and fixture encodes 9 correctly. Prepared TS `🧰️framework/🔨️modules/◻️2d/🧮️compute/🟦️.ts:4-18` frames with DataView.setBigUint64 little-endian, hashes via first-party Blake3Hasher; independent Node Buffer framing and third-party Blake3 oracle exist in `🧰️framework/🔨️modules/◻️2d/🧮️compute/🧪️tests/🟦️.ts:24,43-62`. These files are preparation, not evidence of Rust behavior.

Additional cross-language boundary: Rust &str guarantees valid Unicode scalar UTF-8, but JavaScript string may contain unpaired UTF-16 surrogates; TextEncoder replaces them with U+FFFD and can collapse distinct original identities. Define engine identity as exact valid Unicode scalar text and reject lone surrogates in TS, or define canonical byte identity explicitly. Do not silently normalize valid Unicode or treat different normalization forms as equal. Add valid empty identity, zero byte input, unpaired surrogate refusal, and large boundary lengths where representable through public API without huge allocation.
