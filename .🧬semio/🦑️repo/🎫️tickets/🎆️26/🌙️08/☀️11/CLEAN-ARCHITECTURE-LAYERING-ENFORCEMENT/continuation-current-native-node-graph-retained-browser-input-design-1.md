# Current Retained Browser Input Design

The browser caller must not hand a complete scene Vec to a wasm-bindgen export and then describe its synchronous transport copy as bounded work. The actual OS NodeGraph owner will admit one source backing from scalar input length, explicit Body/Document framing, caller materialization limits, and an exact capacity grant. A finite input-copy step appends at most the caller's granted bytes. Seal then moves that exact Vec into the General SceneDecodeCursor; no second source or complete Serde tree is produced.

The actual locked system provider is `js-sys0.3.103`. Its defining typed-array source has `copy_to_uninit(&mut [MaybeUninit<u8>])`, documented to initialize the complete destination span. The Wasm boundary can therefore write a supplied finite Uint8Array span directly into the source Vec's admitted spare capacity and extend the initialized length only after the system copy returns. The native implementation uses an ordinary bounded byte slice and the same source owner. This avoids allocating or zero-initializing the entire input as uncharged work.

The receiving source, active General decoder, and refusal custody remain live until explicit terminal close. Capacity, logical copy work, physical release, item count and structural depth retain their separate actual grant categories. Constructor refusal must not discard a transferred source. The caller must finish retiring an old request before opening another; requests expose progress and refusal independently of output transfer.

JavaScript will perform actual browser task yields between finite upload/decode/retirement hops and cancel a superseded request before it can publish. Merely wrapping a synchronous collector in a Promise is insufficient. Neutral fixtures will test zero/undersized grants, exact/one-short capacity, cancelled partial uploads, actual pointer preservation, phase cancellation and exact independent physical receipts against the RequestedAllocator and independent Serde/JSON syntax oracles.

The existing DAG host construction and borrowed payload projection still allocate and rebuild synchronously. This design does not infer that operation to be controlled. Its defining construction/commit must receive a separate actual bounded port; any intermediate materialization-only result will be qualified explicitly. No production input-owner code or new API has been authored from this design yet.

The OS receiving capability now has a variable production Request/InputGrant/Progress schema. Its fixed neutral plan remains fixture data, with work0/1/3/256, source capacity offsets-1/0/1, partial cancellation0/1/3/256, explicit Body/Document, the original4MiB ceiling, depth128 and100000 items. Four Rust owner laws are authored but unmounted pending the relocated original51 host baseline. They cover allocation-free constructor/zero-work/one-short refusal, partial cancellation preserving initialized source bytes and pointer, exact source backing transfer through finite General decode, and independent logical-copy/capacity/physical-release receipts whose whole terminal sum must equal admitted births. The production receiving cursor is still absent; these laws are not claimed passing. Source contract3 never reached Bun due the separate repository preparation refusal.

InputStep separately exposes actual work units, copied bytes and admitted bytes. A source birth costs one structural work unit before any byte copy, so a grant1 can reserve backing without copying. Subsequent work accounts one unit per copied byte. Zero work performs neither action. The actual fixture-driven tests track uploaded position using copiedBytes, not the work receipt, and give cancellation cutoffs their explicit birth unit. This avoids hiding the initial reservation inside byte-copy work. Schema/source validators cover the new variable receipt; their actual run remains pending the preparation gate.

This is reviewable proposed code, not an accepted implementation or test result. Original OS51 execution and actual receiving-law red remain prerequisites for production publication.
