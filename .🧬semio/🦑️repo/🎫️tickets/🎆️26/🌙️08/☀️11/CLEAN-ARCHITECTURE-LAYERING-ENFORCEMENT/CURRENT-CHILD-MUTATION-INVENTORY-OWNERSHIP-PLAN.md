# Child Mutation Inventory Ownership

Current read-only inspection on2026-10-08 followed audit10 into the actual Repo orchestration/provider files and complete WFC bridge sources. No bridge/provider production body has been changed by Root in this slice. The active architecture goal and ticket remain unchanged; unavailable RepoMCP capabilities were revalidated.

The current Repo mutationBridgeFor first searches the selected owner and every ancestor for 🏭️bridge/📜️script.ts. Only after that implicit search does it select an explicit MutationInventoryProviderV1. Its providers parameter defaults to repository discovery. Thus a parent bridge wins over a caller-supplied child provider. A physically missing child can still cause a surviving sibling inventory command to compile the parent's other children.

The actual WFC parent bridge hardlinks all five artifacts and ten production mutation aggregates:2D,3D,Bitmap,Grid2D andGrid3D. Its coordinates cover all ten current document/config/transient requests. The bridge reads actual production DESCRIPTORS and excludes editor/viewer state lanes from document output; those semantics and every coordinate must be retained under their real child owner. Its current synchronous cargo subprocess has no progress/cancellation or declared compiler/lock custody.

The existing explicit provider mechanism is reusable. Owner-authored native package metadata declares a script and roots; discovery validates closed declaration fields, physical repository containment, script existence/size, and symlink refusal. Selection refuses ambiguous providers. However, parent ancestor fallback currently bypasses it, and declaration roots/script are not yet an independently demonstrated artifact-deletion contract.

The next implementation must make provider input required, permit a valid empty provider inventory, resolve exactly one explicitly contributed owner, and remove implicit ancestor bridge/default discovery from selection. Repository discovery belongs to the Specific CLI composition. Each concrete artifact must own its own native dispatch descriptors/coordinates, script, Cargo manifest/lock, and provider declaration. The WFC engine/plugin owner must have no dependency on those child executables. No parent compatibility proxy, optional missing Cargo path or fixed runtime fixture catalog should remain.

Schema-first portable cases must cover empty inventories, exact/nested owner scopes, outside/distinct-prefix scopes, duplicate ambiguity, a surviving sibling with another child absent, and an ancestor executable that cannot override the supplied provider. Expected outputs must be independently checked with existing schema/path/parser libraries. Before extraction, retain all ten original WFC coordinate bodies and the full production descriptor semantics. After publication, run the original complete child inventories and an actual child-absent plugin/source projection with exact byte provenance, progress and cancellation. A successful metadata-only projection is not runtime/deletion acceptance.

This plan does not claim current WFC compilation, any artifact deletion, all33 parent bridge extraction, independent topology implementation, whole Repo runtime, or native Windows/Linux acceptance.
