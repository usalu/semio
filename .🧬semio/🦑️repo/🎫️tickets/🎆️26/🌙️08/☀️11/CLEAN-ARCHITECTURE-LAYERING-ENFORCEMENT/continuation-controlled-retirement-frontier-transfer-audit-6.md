# Controlled Retirement Frontier Transfer Audit 6

Read-only refinement audit against existing Sequence, ControlledRetirement and PagedList code. Proposed RetainedFrontier was not yet present at inspection; no implementation/runtime success is claimed.

Flattening the original inline value and existing PagedList cursor frontier into a deferred Option<T> plus dedicated frontier cursor avoids the byte-only nested-step adapter. Existing PagedList.pop removes the final item without freeing backing or allocating. Yield the exact moved Box as RetirementStep Child with next_birth_bytes Some0. Parent then drains that child before asking Frontier for another, preserving original controlled-stack LIFO order. Sequence itself pops its final field first, so [deferred(value), frontier] processes frontier before original value. In current valid states value Some implies no active descendant cursor; value None permits the queued frontier. No simultaneous competing source should be invented.

Once all original cursor Boxes have transferred and drained, Frontier must release each original PagedList page with the exact next_release_allocation_bytes grant. PagedList.release_empty_page already returns physical receipt and refuses insufficient whole grants. Do not release any page containing untransferred Box payload. terminal_is_empty must require original PagedList terminal_is_empty rather than logical len0, because pop preserves all backing allocations. Frontier terminal scaffold release is exact sizeof Frontier after page backing is empty.

Root retirement constructor must admit the new Sequence Box, exact two cursor slots, Deferred<Option<T>> Box and Frontier Box. Original payload and original frontier/page/cursor allocations move without copy and are not new constructor bytes. Existing Sequence terminal release includes its Box and retained Vec slot capacity. Constructor allocation must actually use the admitted two-slot capacity; avoid push growth or a helper whose allocated capacity differs from the published formula.

Before ControlledRetirement self Drop runs, replace/take its ManuallyDrop Option and PagedList into the new owners so its own terminal witness is true. Its terminal Drop may then destroy only empty storage. A partial transfer must not drop a live frontier or recursively drop pending child Boxes. Exact constructor preadmission must occur before any ownership mutation; typed allocation failure handling must retain original owner or a complete truthful retirement owner, not unwind nonterminal Drop.

Cancellation/partial-prestep vectors0/1/2/3/8/16 should preserve original root/value/paged allocations and account only new wrappers as births. Verify original source identity/capacity and physical backing movement, zero and below exact grant nonmovement, exact1 transitions, copy3 unchanged, physical grants separate, pointer conservation through frontier pop, full terminal allocations freed once, and no heap activity dropping emptied original self or terminal new owner. Include pending nested child, empty reserved frontier, nonterminal parent cursor after descendant transfer, and fixture values/oracles unchanged.

Depth needs an explicit scope. Parent ControlledRetirement checks its own stack len against maximum_depth. An opaque Frontier still holds queued original ancestor Boxes, which are not counted in parent len. Flattening therefore restores ordinary parent traversal of each transferred child but does not automatically account total simultaneous retained ancestry. If depth limits mean total live retirement frontier frames, include original queued count plus new wrapper/parent frames and refuse over-limit transfer; if they mean per-frontier active traversal, document and retain original admission. A near-limit/deep-transfer neutral vector is needed before claiming generic depth conservation. Do not silently assign unlimited depth or raise fixture depth64.

This design is preferable to erased receipt conversion: no inner step converts copied work to physical release, no hidden internal capacity grant is minted, and child births/releases are handled by the ordinary parent authority. Certification still requires truthful T capability and exact Frontier/root/terminal constructor authority; a true flag alone does not establish these.
