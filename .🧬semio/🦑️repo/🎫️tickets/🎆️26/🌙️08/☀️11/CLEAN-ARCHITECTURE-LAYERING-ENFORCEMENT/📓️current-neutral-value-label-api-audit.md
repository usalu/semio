## Actionable Locale Cut

1. **Explicit default language remains.** `🧰️framework/🔨️modules/🖱️ui/🎚️axes/🤖️generated/🦀️.rs:8-13` derives Default and marks En default. `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:6881-6886` maps every string not beginning with `de` to English; this includes empty/unknown input and matches `depot` as German. This contradicts the no-default-language instruction. A canonical extraction must change the generator/schema owner and require explicit locale or an owned parse refusal, then update configuration consumers. Removing only the generated Default would be incomplete.
2. **Malformed label input is silently admitted.** `🧰️framework/🛍️products/💻️os/🔨️modules/🌐️locale/🏷️label/🦀️.rs:170-174,189-195` maps absent keys and wrong DslValue shapes to empty strings; even a scalar root can decode successfully. This is missing-data fallback, not a language choice, but conflicts with the documented full locale × terminology matrix. Require the same exhaustive shape in both serde and owned decoding, with pathful owned errors. Existing owners are the label module’s two mounted tests at lines 198-202 and UI localized-label round-trip tests; extend fixture rejection cases and differential serde parity there.
3. **UI still publishes product locale.** `🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/🦀️.rs:40` reexports AppLabels/Label/LabelText/Locale/LocalizedLabel/Terminology from the OS kernel. `🧰️framework/📦️packages/🦀️rust/🦀️.rs:10` exports OS Locale/LocalizedLabel/Terminology from the general framework facade. `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:6860` obtains AppLabels through the UI target. The locale owner doc explicitly preserves former UI paths. These are same-type reexports, not duplicate implementations, but they retain alternate architecture namespaces. Canonicalize consumers to the owning facet before removing these exports.
4. **Generic macro is still plugin-owned.** `app_labels!` at plugin root source lines 6917-6989 emits LabelText/AppLabels through `$crate`, four explicit cells, and an exhaustive match. The exhaustive macro itself has no implicit language fallback. Move this macro and LabelAxes/resolvers into the same generic facet as the carriers; use macro-defining-crate-owned paths, then update invocations directly. Keep plugin-specific ViewModel trait implementation at product level. Move the existing app-terminology test owner along with the macro rather than retaining a plugin forwarder.

## Smallest Coherent Extraction

Create a neutral locale/label facet owning axes schema + generated Rust/TS axes, carriers, owned codecs, macro, explicit parsing/resolution, and fixture tests. OS locale should consume this facet and keep OS-specific preference/configuration behavior. UI components should accept the neutral types directly. The current OS locale source (`🌐️locale/🦀️.rs:10-21`) mounts generated axes from UI and owns carriers, so relocating carriers alone leaves source ownership inverted. Move source/schema/generator ownership together and remove old alternate namespace exports in the same cut. Retain intentional first-party convenience methods (LabelText.fill, LocalizedLabel.from_fn/native, value edit support) after verifying their domain semantics; do not classify them as legacy merely because an earlier API had similar behavior.
