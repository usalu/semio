# General Retirement Canonical Port Audit 6

Read-only current ControlledRetirement, RetireOwned, RetirementCursor, erased Owned/Shared retirement, ErasedCursor and decoder recipient inspection. No edits or reruns. This document proposes the canonical next cut; it does not certify any new authority as implemented.

Current ControlledRetirement already separates frontier-page allocation, root constructor allocation, child constructor allocation, payload copied bytes, physical backing release and terminal scaffold release. It retains the initial value inline and refuses unsupported types via a runtime static boolean. Its step invokes next_birth_bytes before a child-producing call and refuses missing authority. Its terminal branch requires terminal_release_bytes before dropping the cursor. These exact boundaries should remain, with no inferred births or zero fallback.

Current deficiencies are interface contracts: RetireOwned defaults birth None/support false; RetirementCursor defaults birth/terminal release None and next physical demand None. ErasedSnapshotRetirement defaults next_close demand one and provides only a combined byte budget and released-byte receipt. OwnedRetirement uses a Vec frontier whose child pushes may allocate without separate allocation grants. CursorStack processed work is excluded from released receipt; ErasedCursor maps every Pending released_bytes into RetirementStep Bytes and cannot disclose the inner copied work or inner constructor capacity. SharedRetirement and decoder recipient each also own an erased Box which must be physically released after its child becomes terminal. A forwarded combined demand does not repair these distinctions.

## Finite Recursive Capability

Replace runtime recursive support evaluation in the canonical controlled lane with an explicit audited capability trait, for example ControlledRetireOwned: RetireOwned. Make exact root birth and constructor authority mandatory at that boundary. Generic Vec/Option/Box/tuple controlled implementations require their child controlled capability. Explicit implementations for recursive tagged Record families and DslValue certify an exhaustive variant constructor match; use compile-time child capability bounds within those implementations, not runtime calls to child supported functions. This avoids FieldValue→Box FieldValue→FieldValue boolean recursion. A sealed capability or a compile-time certified constructor helper can enforce this audit boundary inside the codebase. Do not mark a family supported merely because its root scaffold size is known: every emitted child must have exact birth and terminal-release authority.

The uncontrolled RetireOwned defaults must not serve as compatibility authority. The canonical controlled API should require complete methods with no legacy defaults or silently guessed zero/one. Remaining callers outside the certified scope must fail explicitly or migrate their defining owners; do not wrap them in a boolean true adapter.

## Exact Erased Port

Use one object-safe controlled retirement contract with mandatory methods for next copy-work demand, next capacity-constructor demand (using the upcoming body grants where necessary), next physical release demand, one granted transition, terminal-empty witness and terminal frame release size. Existing RetainedCloneGrant/Progress already expresses maximum_items, maximum_copy_bytes, maximum_capacity_bytes, maximum_release_bytes, maximum_depth and separate copied/retained/released receipts. Reuse those semantics or define an equivalent retirement-owned schema; do not collapse them back into the old maximum_bytes.

At erased wrapping time the existing inner Box is moved, not newly allocated. The wrapper birth is exactly sizeof ErasedCursor if that Box is newly constructed; charge it once. Inner next constructor demands must be forwarded before inner step. Inner copied/retained/released receipt columns must be forwarded without changing categories. Once inner is terminal, dropping the wrapper physically frees both its own Box allocation and the retained inner erased frame allocation, unless the inner frame has already been explicitly taken/released. Publish their exact layout sizes before that terminal transition and do not count either twice. Existing owned_retirement_birth_bytes and shared_retirement_birth_bytes expose frame sizes for concrete wrappers; dynamic inner frame size is size_of_val only when its terminal witness proves descendants and frontier storage empty. Decoder recipient uses this latter pattern already for final inner Box release, but still lacks the separate constructor/copy/release ports.

The erased root must use an admitted frontier such as current ControlledRetirement rather than allocating a hidden Vec cursor slot during old OwnedRetirement.close_step. Shared Arc handoff must similarly disclose whole Arc allocation release and nested controlled retirement frame birth separately. A blocked shared owner must return unchanged receipts and keep its ownership, rather than appear as an undergrant.

## Neutral Fixture Schema

Use immutable language-agnostic transition vectors with owner family/variant, original payload, actual retained capacity, constructor layout descriptor, exact capacity demand, copy demand, release demand, grants and expected receipt categories. Include zero-item/zero-credit and one-below exact credits, then exact credit one-transition progress. Keep payload work three bytes and assert copied_bytes<=3; independently assert constructor capacity and physical release bytes against their exact whole-allocation grants. Root/frontier/child/wrapper/inner-frame births and releases must be distinct vector rows, including empty buffers retaining nonzero capacity, nested recursive enums, queued writer child retirement, shared blocked/sole owner and canceled decoder recipient.

Validate allocation sizes with independent system Layout/size_of plus immutable shape/capacity fixture calculations, and preserve existing Serde/SQL payload equivalence oracles. Preserve turn limits, payload fixtures, existing zero-grant/cancel laws and budgets. A physical allocation larger than three cannot truthfully retain released_bytes<=3; the correct law distinguishes copied payload work from whole physical release. No larger hardcoded threshold or deadline is an acceptable substitute for the exact credit port.

Before publication, exhaustively audit actual eager vs deferred constructors: existing artifact_retirement_sequence is eager, whereas artifact_retire_struct uses deferred fields. Root births must match the chosen real constructor, including cursor vector capacity. DslValue, RecordFields IntoIter and erased cursor remaining missing authorities must be resolved before certifying Record writer.
