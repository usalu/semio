The landed graph now retains complete context JSON including mount origin, rather than deduplicating away incoming provenance. ## Concrete Remaining Authority Boundaries

1. Function attribute re-entry is a confirmed source-reading defect already being corrected by Root. `visit` at discovery/🟦️.ts:6687–6746 processes attributes, but an unclassified prefixed item eventually retries its plain `fn` token with empty attributes. A preceding `#[cfg_attr(any(), some_attribute)]` on an ordinary function can likewise lose metadata after token retry. Consume the entire item once with its original attributes and prefix classification. Add native-success/refused rows for `#[inline] fn run()`, dormant `#[cfg_attr(any(), unknown)] fn run()`, `async fn run()`, `unsafe fn run()`, `const fn run()` with an unused finite local template, and `extern "C" fn run()`. The conservative contract refuses these classifications even when Rust itself accepts them; plain free functions remain positive. Do not claim an unknown active procedural attribute compiles without supplying a real procedural provider.

2. Module mount rewriting authority is absent from the new mount fields. `inspectRustModuleGraphFacts` at discovery/🟦️.ts:8685 retains visibility/path/macroUse but accepts any other attributes as a private module mount. A real procedural module attribute can rewrite the module or add calls/exported bindings. A minimal native-success/refused case is `#[cfg_attr(any(), rewrite)] #[path="leaf.rs"] mod sealed;` with the existing finite leaf. Its inactive attribute requires no provider for the native proof, while the all-config gate must refuse unknown rewriting authority. Positive metadata should have a closed recursive classification of cfg/cfg_attr/path and explicitly inert attributes; macro_use must poison in every authored branch. A real active rewriting attribute needs a separate tiny owned proc-macro provider oracle. Recording only conditional=true does not establish inertness.

3. Out-of-line module path alternatives are flattened: `rustPathAttributes` gathers every cfg_attr path at discovery/🟦️.ts:7814, but `rustPathAttribute` at7831 selects the first, and graph construction at8610 uses one target. Native-success case: default `#[path="safe.rs"]` and dormant `#[cfg_attr(any(), path="other.rs")]`, where other.rs is include-emitted or has external macro reachability. Either refuse ambiguous authored paths before sealing, or model every alternative context. Proving only the first path is insufficient for an all-config finite scope claim. Existing physical path references retain the alternative files; that does not create their module authority contexts.

4. Execution deduplicates scope checks by definitionOffset before validating subsequent expansion rows (execution:111–118). Current scanner creates each row from the same template scope, so this is not a demonstrated source acceptance exploit. Nevertheless the public provenance contract should assert every row has the same definition/name/scope and validate each invocation/template offset against that scope. A two-invocation row must prove both offsets, plus distinct constant/dynamic templateOffset facts; count-only assertions cannot detect overwritten metadata.

## Closed Native Cases To Retain

- Same `sealed` module name under mutually exclusive cfg branches: a private file mount versus inline include of that same leaf. Compile default and enabled feature branches independently; all-config gate refuses dual origin. Different module names do not prove same-key preservation.
- Two cfg-alternative physical leaves under the same module key. Both native branches compile; graph reports ambiguity and neither leaf receives a successful module seal.
- Private leaf `pub(crate) use load as exposed;` with parent `sealed::exposed!("escape.txt")`: native success, scope refusal. Preserve grouped/renamed use syntax coverage.
- Dormant conditional macro_use metadata: native success in default configuration, scope refusal without requiring an escaped call in the active branch.
- A macro-generated inline module containing a plain function/local template. `visit` resets a module scope when descending inline `mod` even from a null opaque scope (discovery:6725). The current graph-facts parser skips the outer macro item, so absent context should refuse; explicitly assert this instead of relying on an incidental missing candidate. The ordinary inline-module positive sibling must still receive genuine graph context.

Async/unsafe/extern prefixes are currently checked by immediate preceding token checks (discovery:6708), including extern ABI string via the second preceding token. These are bounded token guards, not a complete item parser. Combined prefixes and intervening attributed items need original-item classification. Rust type errors outside the owned bounded expression grammar are not a reason to broaden scope authority.
