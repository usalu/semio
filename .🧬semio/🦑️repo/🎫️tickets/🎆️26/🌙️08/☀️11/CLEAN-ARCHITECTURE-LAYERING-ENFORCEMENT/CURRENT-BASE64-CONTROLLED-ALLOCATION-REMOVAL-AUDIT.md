# Base64 Controlled Allocation Removal Audit

Read-only current defining Rust implementation and existing laws inspected. No runtime rerun. Controlled decoder currently calls allocating decode_bytes during every validation and reconstruction chunk; result try_reserve_exact occurs only after validation. Stack-only decode_standard_quad already provides strict byte classification/canonical padding/low-bit validation and at most three returned bytes, so it is the coherent shared primitive for both passes.

Preserve existing API/observation ordering: length not divisible by four returns Codec InvalidLength before allowance/cancellation; predicted result length from terminal padding is admitted next, so OutputLimit can precede invalid internal padding/characters; Validate(0,total) precedes scanning; each at-most4096 chunk emits Validate(end,total); Decode(0,total) occurs before output reserve; reconstruction emits Decode(end,total). Empty input has Validate0 then Decode0, no nonzero chunk events and no allocation. Allocation failure remains OutputLimit. Callback denial always returns Cancelled at its current boundary. Preserve absolute InvalidByte offsets beyond chunk4096.

Current validation precheck rejects any '=' in a nonfinal4096 chunk as InvalidPadding before invoking the per-quartet decoder. This can precede an earlier invalid character in that same chunk. Removing this precheck changes error precedence for mixed invalid inputs; explicitly retain it or compare original/new refusal laws before deciding a deliberate contract change. Whole-input last quartet flag must be used when calling decode_standard_quad. Canonical trailing bits reject Zh== and Zm9=; padding rejects =m9v, Zm=v, padding in nonfinal groups, alphabet whitespace/url characters and Unicode byte input.

Existing defining IO unit roster tests RFC4648 standard/url fixtures and independent third-party base64::STANDARD/URL_SAFE_NO_PAD differential byte outputs, plus stack quartet refusal. TypeScript quartet law compares actual Buffer system base64 outputs and verifies malformed quartet preserves output storage. Controlled allowance/cancellation law is mounted under DSL schema intrinsic-bytes, consuming General Value bytes corpus: exact maxima, one-short large input, pre-cancel, validation cancel at8192 and codec invalid cases. It currently does not measure allocation requests or cancel reconstruction independently.

Allocator law design: mount existing thread-local requested allocator observer in the defining IO test crate; prepare input/corpus/oracle and callback state before observation. Use fixed callback counters or preallocated event capacity so oracle/log allocations do not contaminate decoder measurements. For valid nonempty input assert exactly one output allocation request of exact decoded length, no realloc, same bytes as third-party engine, and release on output drop. Empty input, denied allowance, pre-validation cancel, midvalidation cancel and malformed input must request zero decoder-owned allocations. Cancellation at Decode0 also zero; cancellation after one reconstruct chunk requests exactly one output allocation which must release on refusal. Observe allocations during callbacks separately or explicitly exclude callback-origin allocations, never claim decoder identity from aggregate unrelated allocations.

Neutral cases: RFC empty/f/fo/foo/foob/fooba/foobar; Unicode original UTF8 octets; invalid Unicode in encoded ASCII; exact4096 encoded boundary, two chunks and final padded quartet; max0/exact/one-short; malformed length/internal/final padding/low bits; invalid character after chunk boundary checking absolute index; mixed-invalid precedence; cancellation at Validate0/4096/8192/Decode0/4096; allocator failure injection retaining OutputLimit. Compare valid bytes using actual native third-party base64 and TypeScript Buffer oracle; Node Buffer permissive decoding is not the strict malformed-input oracle. Strict third-party decoder class agreement may differ in prose, so compare acceptance and first-party kind/index facts separately. Preserve original controlled law and add allocation-focused owner law rather than replace its semantic roster.
