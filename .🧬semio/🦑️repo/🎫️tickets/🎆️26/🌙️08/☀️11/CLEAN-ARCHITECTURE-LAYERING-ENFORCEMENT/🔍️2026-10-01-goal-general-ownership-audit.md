## Proc-Macro Generated Dependencies

DSL derive source genuinely contains generated include templates: `🗣️dsl/✨️derive/🦀️.rs:595`, `596`, `600` emit `include_str!(#taxonomy_dependency)`, `#descriptor_dependency`, `#payload_schema_dependency`; around 1821 it repeats `#dependencies`. They are validated paths discovered by `mutation_source_authority`, payload-schema containment/no-follow checks and aggregate authority. They are not arbitrary runtime includes.

Current neutral parser `🔍️discovery/🟦️.ts:6528` accepts literals, concat/env and bounded simple macro_rules bindings. It recursively visits delimiter bodies, so quote interpolation is an unsupported compile expression. Strict source executor retains these failures (`🕸️dependencies/🧭️direction/🦀️source/🏃️execution/🟦️.ts:43`, `61`) rather than silently omitting them.

Recommended extension: a first-party schema for declared generated dependency facts, produced from the existing validated authority, consumed by neutral provenance/direction/deletion inventory. Identify producer package/source span, consuming owner source, dependency kind, normalized target and authority inputs/digests. Require exact producer/span matching, finite resolved targets, workspace containment and no-follow existence; merge with normal compile references and apply identical strict direction rules. An unresolved target, omitted declaration or deleted owner input must fail closed. Keep generated consumer dependencies distinct from the framework proc-macro's own dependencies: the macro reads owner descriptor/schema as its client's input, which should be attributed to that consuming owner, while its general taxonomy rules are producer inputs. This prevents falsifying framework independence by either ignoring quote bodies or charging every client-owned input as a framework static dependency.

Portable laws should cover a neutral client, a specific client, foreign/escaping/symlink paths, omitted/repeated interpolation facts, modified authority, deleted descriptor/payload and macro-generated forbidden edges. Independent AST/token and filesystem oracle should reproduce facts. Existing compile-reference/module-context/provenance schemas are suitable foundations; no existing fully declared proc-macro generated-input mechanism was found here. Source deletion checks must consume the same admitted facts, so dynamic generation cannot hide a removed dependency.
