# Controlled Cargo Dependency Projection

The current dependency inventory has five real strict async-workspace diagnostics and parses Cargo dependencies by a second line/regex grammar. This schema-first proposal defines a variable production request containing admitted package and workspace documents; it contains no corpus cardinality or fixed case roster.

Seven neutral vectors preserve dependency section intent and add actual Cargo/TOML escaped keys, package aliases, nested declarations, target test dependencies, proc-macro classification, workspace inheritance, and distinction between workspace declarations and package inputs. The independent Iarna TOML parser validates both admitted documents. Ajv independently validates the production request.

The controlled projector requires an active first-party operation, charges work and retained outputs, yields progress, and rejects missing inheritance, cancellation, work/byte limits and retirement. The eight-law red route exercises the actual current five regex functions extracted from the captured source by TypeScript; only the temporary test control supplies the same projection interface. It is never a production compatibility export. Green uses the proposed first-party document projector. Both preserve the same vectors and control law.
