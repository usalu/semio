# Surface Typed Payload Neutral Port Audit

Fresh read-only source authority: Surface node-graph implementation/unit laws; General Value codec; General Viewport2d defining schema; General Pack intrinsic decoder. Concurrent source changes may follow this bounded audit.

GraphPortRecord, GraphNodeRecord and GraphEdgeRecord already derive first-party FromValue beside the independent Serde oracle. Their defining owner should remain Surface; do not introduce duplicate records or bridge through a foreign JSON value. NodeGraphScenePayload::from_json publicly accepts serde_json::Value, and NodeGraphError::Json publicly exposes serde_json::Error. These remain foreign public APIs. The private GraphHost scene path still decodes JSON to Serde Value and Pack through OS Store, retrying Body as Document and converting the intrinsic tree to Serde JSON. Their removal needs a direct first-party value entry and an explicit physical Pack format.

Existing semantics require field-local whole-vector fallback: absent, null, wrongly typed or any malformed nodes element defaults the complete nodes vector to empty; edges independently behave likewise. Do not silently retain good elements or make a malformed nodes/edges field refuse the entire payload. Present viewport is different: null, wrong class, missing coordinates, unknown members, wrong numeric classes, nonfinite coordinates or nonpositive zoom must refuse. Absent viewport alone yields None. The defining Viewport2d first-party FromValue checks exact fields and validates finite coordinates/positive zoom, as does its Serde visitor. Optional JSON text fields accept strings only and ignore other classes. Nonobject root currently behaves as no fields and defaults successfully after JSON syntax parsing; preserving that is a deliberate corpus law, not a schema-derived assumption.

Schema-first TDD corpus should include empty object and scalar/array/null roots; nodes/edges missing/null/scalar/object/empty array; minimal valid records; mixed valid/invalid lists proving complete-vector fallback; malformed nested ports; null optional record values; unknown record members; camelCase names/resourceKind/valueType/fullName; Unicode strings; all eight existing shared viewport pose cases plus absent/null and unknown field; each text field as string versus nonstring. Compare the resulting typed records/optional fields/refusal classes against a test-only Serde interpretation of the same corpus. Preserve existing live viewport hydration/lagging echo tests independently of decoding tests.

Use borrowed field lookup and FromValue::from_value_controlled on each selected borrowed field to avoid cloning the entire input tree. Output String/Vec ownership is necessary typed materialization, not an intrinsic-tree clone. Retain all-or-empty malformed collection semantics only for semantic InvalidValue refusal; cancellation/ownership limits must propagate, not become empty success. NativeDecodeControl and guarded decoded ownership give the existing first-party control path. Verify actual allocations/progress/cancellation with zero-budget, exact-budget and one-byte-short laws before claiming resource-safe decoding. Explicit Body and Document entry laws must prove mismatch refusal with no retry and third-party/test-only wire equivalence. No proposed corpus or entrypoint has been implemented or executed by this audit.
