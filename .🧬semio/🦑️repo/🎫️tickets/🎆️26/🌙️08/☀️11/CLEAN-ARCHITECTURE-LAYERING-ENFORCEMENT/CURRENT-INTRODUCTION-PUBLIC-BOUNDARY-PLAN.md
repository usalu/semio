# Introduction Public Boundary Plan

The Puzzle3d introduction law's title helper is a thin private composition of existing public General manifest functions: app_breadcrumb(resolve_app_breadcrumb(app, terminology)). A Specific consumer can use those defining functions directly; making the renderer helper public would preserve an unnecessary facade. The descriptor already provides an authored app, while the law presently fabricates the remaining app fields with the private command_registry_tests::test_app helper. Full AppDefinition deserialization must be actually checked before replacing that construction.

The arming policy has two current implementations. TypeScript shouldAutoStartIntroduction lives in the OS Shell and requires appId, authored introduction presence, tutorial activity, host suppression, replay policy, device seen state and a session dismissed-app set. Rust should_auto_start_introduction lives in the WGPU Shell and takes six scalar arguments; session/device persistence is handled by its surrounding state. Its private predicate is used by production and several generic renderer laws. The existing eight closed host-introduction vectors also test iframe-derived suppression, so that environment policy must stay with the host owner rather than be silently dropped during extraction.

A canonical neutral UI introduction policy should take seven explicit required scalar facts, including dismissal in the current session. Its TypeScript and Rust APIs should be owned, with a closed language-neutral corpus and independent schema evaluator for the eligibility rule. Caller state supplies the dismissal fact; the neutral policy owns no storage, app manifest, renderer, plugin or product dependency. Direct consumers should import the defining provider, and the old Shell declaration/private WGPU predicate should retire together with every actual caller update; forwarding aliases are not a successor.

This is research and an intended implementation boundary, not authored production or runtime proof. Exact enclosing existing policy bodies and current TypeScript/Rust consumer census were inspected. The concrete Puzzle introduction law and every current renderer assertion must remain selected after relocation. Existing canonical Specific conformance proposals and native compiler/OS queues continue independently.
