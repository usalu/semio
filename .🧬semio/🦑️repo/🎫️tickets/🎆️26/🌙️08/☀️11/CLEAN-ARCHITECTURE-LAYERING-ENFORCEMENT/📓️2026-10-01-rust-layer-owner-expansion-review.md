## Actual Loader Coverage Limits

Every case writes `package.json` with an empty workspace contribution: no members, owners, package identity or semantic dependency role. Thus actual loader execution is independently exercised, including live plugin directory discovery, but authored package contribution/installed alias semantics are not exercised by this corpus. Earlier workspace-deletion laws may cover those behaviors separately; this new corpus must not be described as independently proving them.

The deleted-specific-owner case starts with an absent specific owner and a neutral source. It verifies absence is accepted; it does not remove a formerly contributed owner or leave a stale authored membership declaration and then verify its disappearance. Likewise, source census hostile cases remain in their original tests, but new ownerCases do not add malformed present contributed manifests. Those distinctions matter for a complete deletion claim.

Missing optional taxonomy roots should disappear only on ENOENT. Present linked or non-directory roots, linked source/data inputs, malformed metadata and present contributed owners lacking a valid manifest must still fail. The existing root policy loader explicitly distinguishes missing owner directories from damaged present owners. A wider producer walk must preserve that distinction.

Root source manifest provenance needs explicit review: the current scanner includes only names ending `/Cargo.toml`, and its nearest-manifest fallback stops before `.`. A root `Cargo.toml` is therefore absent from the current scan, even though shared `inspectRustModuleGraph` accepts root manifests. If root-owned `CARGO_MANIFEST_DIR` input forms are supported by the new scope, census the actual root manifest and resolve its applicable provenance. The root owner case currently uses a plain literal, so it cannot independently catch this gap. An actual virtual workspace must not be treated as a package merely to obtain an environment anchor.

The later live producer edit was read after root reported its actual registered producer RED: seven passing tests, one failing test, 146 assertions, approximately 3.6 seconds. Root reports that the corrected old producer refused an S-only case because its framework census was empty. The first two failed runs were harness normalization/invalid empty Bun contribution failures, not actual producer RED. This reviewer did not execute any of those runs.

The producer now inventories every present taxonomy area, rejecting nonphysical directory roots and skipping only ENOENT. It also admits root Rust files and root Cargo manifest. Policy selection includes taxonomy strict directions, framework→implementation, root→implementation, S-module→plugin and every live per-plugin artifact/extension rule, with scalar path/pathNot patterns normalized to arrays. Duplicate rule names, missing fixed rules and non-error severity fail policy admission. Existing source physical checks and unresolved-expression records remain intact, and new all-area scope is not hidden behind test-only fixture patterns.

The earlier harness limitations are now superseded: the corpus contains eleven ids with closed enum and min/max cardinality eleven, and test uniqueness ensures every identity remains. The deletion case physically removes S while preserving that authored membership declaration, then independently checks absence before loading actual policy and producer. The root environment case contributes a real `[package]` and explicit library path, so its environment anchor has real package ownership. Original assertions and all `45_000` budgets remain. The producer's registered GREEN replay was still pending when this review was written.

Two concrete issues were reported to root immediately:

1. The root manifest admission predicate now accepts `path === "Cargo.toml"`, but the symlink rejection predicate still checks only `path.endsWith("/Cargo.toml")`. A root Cargo manifest symlink to a regular file therefore silently returns instead of rejecting a linked authored source input. Use the same root equality in linked-manifest admission and retain a hostile root-link assertion.
2. The new fallback assigns any inventoried root Cargo manifest to an otherwise unowned source, without checking whether the root manifest is a real package or a virtual workspace. The repository's actual root Cargo manifest is virtual. An orphan/root source using `CARGO_MANIFEST_DIR` can therefore acquire unproven root package provenance. A strict actual compiler context should supply this binding; a virtual workspace cannot create a package environment by itself. The new root environment case correctly uses a real package and does not exercise this hostile case. Preserve failclosed unsupported/unresolved behavior where a concrete package context cannot be established.

Neither issue is a Windows path-separator concern: paths passed to policy remain canonical slash paths, while native paths only reach filesystem operations and rustc. The issues concern root authored-input admission and proven compiler ownership. Any final producer changes addressing them should receive their own registered replay; this read-only report does not assert those repairs or a final test pass.
