Separate encode and decode controls cannot independently each spend the entire operation ceiling; define an explicit total grant split or cumulative shared operation owner and account all live bytes. Installing a decode retirement recipient before retaining values preserves bounded cleanup on cancellation/refusal; writer cursor also needs controlled retirement, including partial frames/source/output.

Wasm cannot expose a borrowed Rust callback lifetime. Use an owned resumable scene operation: begin(bytes, explicit format, finite grant) creates owned input/operation; step(work grant, cancellation state) returns first-party progress/refusal/completion; cancel requests bounded retirement; terminal commit applies typed payload only after successful complete decode. This enables browser event-loop cancellation and avoids a single synchronous callback that blocks UI. Native may use the same stepper directly with its actual cancellation/progress callbacks. Do not create an always-true hidden decode callback or unlimited usize::MAX grant at wasm entry.
