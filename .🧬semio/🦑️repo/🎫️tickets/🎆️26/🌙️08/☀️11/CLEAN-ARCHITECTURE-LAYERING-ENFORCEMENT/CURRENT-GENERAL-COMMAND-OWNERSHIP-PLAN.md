Its actual Nx project still routes 25 executable command fields through Specific Repo Cargo/TypeScript policy wrappers. This leaves an executable deletion dependency after the complete native source/resource boundary has passed. The observed Specific NativeScript owner-command branch performs semantic workspace preparation, constructs repository Cargo/Vitest/process/artifact policies and delegates the selected command. Those policy-construction and semantic-taxonomy decisions are Specific behavior and must remain outside a neutral executor.

The next implementation must author the defining General command execution contract under General Process, admitting an explicit caller-owned context and supplied exact package/workspace manifest policies. General Nx commands must invoke that defining General script, while Specific Repo commands supply their own policies through the same contract. Do not forward from General into Repo, retain an old entrypoint alias, invent a fixed package catalogue, silently infer Root Cargo ownership, or clone the whole Specific NativeScript implementation into General.

Keep all existing General routed commands and their original law selections, actual owning manifests, compiler budgets, progress, cancellation and artifact ownership. Add a language-agnostic variable command/context corpus with independent schema and actual executor observations, then genuine red all-General-router/Nx entry closure and green independent AST/esbuild deletion refusal. Permanent checks must derive the command/router/export inventory from the actual defining manifests and Nx files instead of a shortened fixed list.
