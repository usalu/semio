# IO Error Typed Cause Prerequisite

Actual IO schema Rust owns IoError { message: String, diagnostics: Vec<Diagnostic> }, derives ToValue/FromValue, and has only From<String>. The shipped IO JSON schema, TypeScript, GraphQL and Protobuf do not declare IoError. Current ValueError and ValueRefusalKind have no owned ToValue/FromValue implementations; replacing message with cause therefore requires a schema-first controlled Value refusal codec before the existing IO derives can compile. A derived codec cannot be inferred from Display or a String conversion.

Proposed settled direction follows Root: IoError { cause: ValueError, diagnostics: Vec<Diagnostic> }; no implicit From<String>. Direct SQLite ValueError must become cause unchanged. TextError producers preserve kind/message in cause and preserve original TextError span/expected semantics as an owned Diagnostic in diagnostics at the authored source boundary. Pack ValueRefusal and TextRefusal preserve their actual owned causes; remaining container variants require explicit source-owned authority before they can project to ValueError. LimitExceeded(&static str) mixes byte/work causes, and Io(String) has no machine identity; they cannot be classified by prose. These are remaining Pack owner prerequisites, not permission to assign InvalidValue universally. If original non-refusal Pack structure must remain lossless, use a separate owned cause enum at IO and admit its complete wire codec rather than claiming a ValueError projection retains the original Pack object.

Actual generic IO erasures include DSL parse error.to_string at deserialize_dsl_txt, pack decode string at serializer_entry, SQLite export/import and registry metadata String intermediates, and hop decoration rebuilding message. Typed hop decoration should retain cause.kind and existing diagnostics while adding authored hop context to cause.message. Native snapshot registry lock poison is InvariantViolated; absent declared dialect/provider is UnsupportedOwner; byte/file size ceiling OwnershipLimit; malformed connected route/schema admission InvalidValue. max_hops zero is WorkLimit at route policy. These choices must be verified at each full actual producer before mounting.

No IO/Value/Pack production was changed here.
