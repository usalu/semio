# Retained Surface Descriptor Size Diagnosis

The original Product whole3 reports a 24,488-byte Option<RetainedSurfaceSlot> against the committed 23,496-byte fixture, a 992-byte difference. The capacity remains 64 and the registry owner remains 32 bytes. This measures the slot element, not the pointer-sized registry owner. The corresponding 64-element backing differs by 63,488 bytes before allocator overhead. No fixture, budget, capacity or assertion was changed.

The exact nested source contributors are retained in the generated source-witness file. RetainedSurfaceSlot embeds generation, instance, SurfaceId and RetainedSurface by value. RetainedSurface embeds optional snapshot state, optional RetainedPatchApply, two UiFixedList<KernelUiPatch,64> descriptors, optional RetainedDocumentBuild, three document-lease descriptors, flags and an optional actor receipt. RetainedDocumentBuild embeds optional UiNodeRecord, alongside its builder, revision and cursor. RetainedPatchApply embeds its largest Applying/Ready/Rejected variant directly.

UiPatchApplyProducer embeds two optional snapshots, an optional patch, optional UiNodeRecord, limits, scalar cursors, removal/validation list descriptors, and 128 UiFixedList<UiText,128> validation-seen descriptors. Outcome and Rejected retain the same 128-descriptor validation-seen array; Rejected also embeds optional UiNodeRecord. UiFixedList itself owns a PagedList descriptor, rather than an inline N-element array. UiNodeRecord embeds Component, LayoutSpec, StyleSpec, AccessibilitySpec, a 512-byte UiText key plus length, and typed binding/menu/children descriptors. Component stores one of its concrete property variants inline. These are actual contributors to the element size; enum discriminant/niche selection and padding require compiler layout evidence.

The full UI contract frames captured in epoch2 and whole3 are identical. The captured renderer file changed, but the retained registry/slot/surface/build/patch definitions remain byte-identical; the fresh physical definitions were compared against whole3 individually. Therefore this audit finds no source delta in these captured contributor definitions between the failed predecessor whole2 and whole3. It does not identify a particular field as the source of the 992-byte difference: the committed fixture has no independently retained historical compiler layout here. Exact per-field Rust offsets, selected maximum enum variant and padding remain unmeasured, and attributing 992 bytes to a guessed field would be unsupported.

The next diagnosis should observe concrete layouts for RetainedSurfaceSlot, RetainedSurface, RetainedPatchApply variants and UiNodeRecord/Component in the same target/profile, then compare the fixture provenance. Preserve the failing original contract until the actual owner/descriptor design is resolved.

The actual Nextest binaries-metadata.json identifies the original arm64 test binary b8022fa0ea8021e7. A read-only xcrun dwarfdump --name=RetainedSurfaceSlot completed successfully and returned only the Mach-O arm64 header, with no matching type layout/debug entry. Thus the retained binary does not supply the requested per-field layout through that query; no new compilation or assertion was performed.
