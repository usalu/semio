# Actor Facade Boundary Read-Only Audit

Source inspection only; no test/compiler/bundler executed. This describes enforcement scope, not a whole repository architecture acceptance claim.

`🎭️actor/🧪️tests/📣️public-facets/🟦️.ts` checks declared package exports, parses authored wrapper export declarations with TypeScript, resolves each defining module path against the facade directory and compares it with the expected implementation/schema owner, then imports both the physical wrapper and package specifier to compare runtime rosters. This proves wrapper provenance/roster if executed. It does not scan consumers for forbidden private absolute/relative implementation imports.

`🎭️actor/🧪️tests/🏛️owner-boundary/🟦️.ts:18–25` recursively collects TS/TSX source under Actor, with fixture exclusions. Its AST string-literal sweep (29–43) rejects literal strings containing products, except the exact string `🛍️products`, deliberately used by the law itself. Imported @semio-tech string literals receive Bun.resolveSync + realpath product checks. Relative or absolute literal paths visibly containing the products segment are rejected by the literal sweep.

The AST importer detection handles import/export declarations, literal dynamic import and import-type syntax. It does not resolve require calls or computed module expressions, concatenated/template paths with substitutions, URL-derived imports, or arbitrary loader calls. A computed product path assembled from the explicitly allowed exact `🛍️products` string can evade the literal sweep. Absolute/relative filesystem aliases or symlinks whose specifier text omits products receive no general resolution/realpath check; only @semio-tech literal imports do. These are enforcement gaps, not confirmed offending current imports.

Its production Bun build uses `packages:"external"` and a product-text onResolve filter. Bare package dependency internals are outside bundler traversal; AST checks the directly referenced @semio-tech package realpath but does not walk transitive external package graphs. onLoad observations prove traversal only for loaded modules. The test's synthetic direct absolute product denial probe qualifies that particular literal filter, not computed loader behavior or external-package transitive provenance.

The source scope is Actor-owned TS/TSX, not all Product/S/Hub consumers and not Rust/JS/MJS/artifact source. Consequently this General law cannot certify that every domain uses public Actor facets or that no private file path remains externally imported. A clean boundary extension should classify actual module-reference AST sites, resolve absolute/relative literal references to physical owner roots, and separately inventory computed/unresolvable references and external-package ownership. Consumer facade use needs its own repository consumer scope and canonical public-export mapping rather than treating this General product-denial law as that proof. Reuse defining facade/type/schema owners; no second implementation or compatibility export is needed.
