# Catalog Ownership Plan

Closed publication request and language-neutral deletion/empty-roster vectors were authored before implementation. The neutral publisher receives an explicit owner, owned output root and contributed package roots. Hub authors its component contribution; S composes this contribution with its own plugins. Neutral publication has an empty roster. Concrete projected bytes, producer receiver, taxonomy authority and consuming application entry points belong to S's development catalog. Neutral process consumers receive an explicit runtime catalog path; unconfigured neutral inventory is empty. Generic story hosting receives catalog, targets and URL resolver from the application.

Current source contains native generated includes, development/build consumers, repo dashboard/catalog consumers and other application assemblies in addition to the originally identified TypeScript catalogs. These require correction together; none may retain a default reference to concrete S projections.

## Current Evidence and Scope

The actual original S receiver generated 70 deployed components and 156 playgrounds at its physical catalog owner. The actual neutral receiver generated empty component/playground/native documents. The source root was verified after rejecting an early ticket/v-root invocation: the harness now supplies the original workspace root and S publication passes its actual router root explicitly. No early zero-row run is used as S success evidence.

The current original-source Nx test lane passed 26 tests, 506 expectations across publication/deletion, optional Nx providers, specific installed consumer, exact owned launch routes, browser-host byte provenance and S rebuild composition. A separate actual S test command receiver passed 16 tests/464 expectations before the optional Nx provider and rebuild vectors were added to that command. Strict source checking passed for the neutral parser/projector and for relocated S browser receipt/staging/builder plus optional Nx provider protocol and its tests. These are scoped original-source checks; no whole root Nx graph or every native component build pass is claimed.

Actual S admission uncovered two production problems while testing the current composition: 227 catalog rows exceeded the former neutral 128-row ceiling, and the mathematical playground declared its own variant as an alias. The schema remains bounded at 512 rows, specific and generic boot callers receive those finite credits, the oversized portable specimen now has 513 rows, and the redundant authored alias was removed from the Hub Cargo source. Regeneration—not generated byte editing—updates the data.

Space/GIS browser-host fixture schema, receipt validator, source bytes and exact staging choreography now belong to S's catalog composition. The neutral Vite builder accepts a caller-provided root callback. Exact selected-byte/SHA and hostile substitution assertions were retained and run at their specific owner.

Root Nx options explicitly declare an optional S owner and source provider port. The neutral plugin skips an absent whole owner, refuses a broken present owner, selects only the contributed package roots, and gives actual generated session/dev tasks the owner's generator dependency and installed catalog environment. The real session producer emitted 156 scoped targets; removing every provider emits no application targets and does not inspect owner inputs. Source JSON inputs are declared by the caller port and observed by the general inference cache.

Native renderer/run/MCP/dashboard receiver work is delegated by the parent to General Native Boundary. Its schema-owned native document is emitted by this publisher as `🦀️catalog.json`; no generated Rust data is moved into a generic default import.
