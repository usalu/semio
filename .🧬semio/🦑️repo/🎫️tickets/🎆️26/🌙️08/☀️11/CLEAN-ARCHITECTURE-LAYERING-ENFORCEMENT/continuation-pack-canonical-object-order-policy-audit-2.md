# Pack Canonical And Ordered Object Policy Audit

The OS controlled dynamic Object sort is unconditional; its branch never reads EncodeOptions.canonical. Canonical defaults true in General replication codec’s PackEncodeOptions (line65 onward), but the encoder uses the flag for the document optional canonical marker, not a choice between ordered and sorted dynamic objects. Setting canonical false would still sort OS controlled dynamic objects and still retain General controlled dynamic occurrence order. It cannot resolve this difference.

General Value owns Object(Vec<(String,DslValue)>) and documents literal written order at value root line376. Its Pack ordinary dynamic encoding documents exact owner occurrence order, with forced-inline keys, at value root line554. Controlled General encoder likewise uses Object(items.iter()). The current neutral ordering fixture contains repeated z keys with different values, a NUL-containing key, and non-ASCII text. Current General unit law schema_map_keys_are_canonical_and_intrinsic_objects_preserve_occurrences (line944) requires equal ordinary/controlled schema-map bytes for shuffled maps, but different bytes for reordered intrinsic objects and exact literal roundtrip. This read-only inspection does not claim the Rust law was executed here.

OS unit fixture line105 instead pre-sorts both schema Map and dynamic Object so order-sensitive PartialEq passes canonical roundtrip. That fixture cannot distinguish preservation from sorting for unsorted or repeated-key intrinsic objects. OS controlled sort keeps original ordinal as its equal-key tiebreaker, preserving duplicate relative order while moving differently named occurrences.

Therefore do not silently sort General intrinsic Objects to inherit OS behavior. The domain-neutral shape boundary is already explicit: schema FieldValue::Map uses key-byte canonical ordering; intrinsic DslValue::Object preserves occurrence ordering and duplicates. An eventual consolidation requires actual original OS callers and fixtures to bind their intended shape/contract, plus closed unsorted/repeated-key laws comparing complete document and controlled paths. A canonical header flag or record-body substitution is insufficient. No implementation or retirement admission made.
