## Precise proposed member cut

Introduce schema-owned `RustProceduralCompileConsumerFactV1` with macro identity/provider binding, declaration source byte range/name/module scope, Cargo consumer context and invocation attributes. Add a neutral `inspectRustProceduralCompileConsumers(source)` returning every authored derive occurrence including private declarations, conditional cases and both MutationLeaf/Mutations; do not broaden the wrapped-leaf policy API in place or treat its rejected private declaration as no invocation. Its result is candidate syntax, not provider authority.

Expose reusable bounded route proof as `resolveRustProceduralMacroProvider(input)` over candidate fact + graph + checked manifests, parameterized by exact exported member MutationLeaf or Mutations. Require proc_macro_derive member existence and expander identity in the actual provider library source, exact aliases/reexports, and diagnostics for unsupported routes. Existing leaf metadata proof can call it and retain its stronger lower-contract/manual-impl obligations. Mutations consumer requires valid aggregate attrs and declaration shape but is not a MutationLeaf trait declaration.

Pure authority member `resolveMutationCompileInputObligationsV1(input)` should accept explicit workspace-relative consumer source/context; validated authority projection; canonical source/descriptor naming; domain and aggregate registries; raw descriptor text/value for a leaf; checked node accessor supplying exact kind/content/provenance. Return accepted typed obligations or structured refusal, never partial success. Leaf output: projection/descriptor/payload-schema target roles; aggregate output: projection role. Every obligation retains producer source/template offset, canonical provider/member, consumer source/declaration offset/context and target locator. Separate dependency facts from filesystem reads used to validate them. Reuse existing owner and schema checks but match the Rust descriptor validator's exact fields and semantic expectations from schema; a permissive parse of payloadSchema alone cannot authorize a leaf.

Move the equivalent pure authority model out of proc-macro-only code into a lower Rust first-party owner and call it from the expander; retain compiler span/root discovery and filesystem no-follow shell in the producer. TS uses the same language-neutral schema/corpus with its own implementation. These proposed members do not currently exist; the private Rust helpers and generator are extraction inputs, not already reusable public APIs.
