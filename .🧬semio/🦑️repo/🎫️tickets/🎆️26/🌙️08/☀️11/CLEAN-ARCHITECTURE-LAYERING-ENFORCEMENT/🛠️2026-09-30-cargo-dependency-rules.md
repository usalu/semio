# Strict Cargo Dependency Direction

The standalone Cargo contract compares independently read authored manifests against `cargo metadata --format-version 1 --no-deps --offline --locked`. It validates all normal, development and build declarations, platform tables, optional declarations, workspace inheritance, renamed dependencies and implicit local members. Missing or unknown semantic roles remain explicit problems; physical framework-to-implementation direction is enforced even when either role is invalid. The OS-owned kernel's declared framework role remains an explicit semantic peer. No role relabeling, skipped test edges, grandfathering or count baseline accepts an upward edge.

Every package and local declaration must match the authored inventory exactly. A missing package/member/dependency/target or changed alias, kind, optional flag, platform or role fails before a graph verdict. Registry dependencies are explicit nonlocal terminals, including names matching an authored workspace package. Public APIs use repository-owned types. Bun parses the authored TOML; fixtures also use the existing third-party TOML library and actual Cargo metadata as independent oracles.
