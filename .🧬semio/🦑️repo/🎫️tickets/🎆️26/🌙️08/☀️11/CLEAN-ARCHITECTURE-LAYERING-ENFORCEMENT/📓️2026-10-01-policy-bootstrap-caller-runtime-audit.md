## Freshness and runtime boundary

Canonical TS loader is appropriate for Bun repository routes and tests. Do not have Node-owned CJS/ESM entries directly import arbitrary TS or Bun-only APIs and call that zero-touch compatibility. Native Node type stripping/module resolution differs by version; the current CJS→direction.ts→Bun.ts→payload.ts graph already demonstrates a foreign-runtime limit, not a supported cross-runtime proof. A foreign tool can consume fresh data JSON produced by a registered Bun owner entrypoint. If maintaining directly loadable Node config entries, use a Node-executable first-party contract with the same snapshot semantics rather than a silent fallback/legacy policy copy. No runtime test was run here to establish current Node loading success.

Freshness means a loader invocation validates **current** root markers, metadata taxonomy locator, taxonomy bytes, every policy dependency/code input if evaluated, plugin/owner directories, workspace manifests/exports/dependency roles and payload membership. No global taxonomy or require/export cache supplies authority. Freeze/copy result values so another caller cannot mutate later proofs. If source code evaluation remains, capture/validate its whole closed dependency graph before executing and do not delete shared global caches while other agents/tool consumers run. TOCTOU scope should be explicit: a coherent captured source snapshot is authority, rather than separately rereading the same manifest while selecting rules and censusing owners.

## Root/platform no-follow closure

Reuse workspaceAuthorityPath + noFollowDirectoryAncestry + resolveWorkspaceTaxonomyAuthority for raw root/markers/locator. Validate before resolve/realpath so missing/linked raw prefixes cannot vanish. Source-access alone resolves relative paths and checks ancestry only from repoRoot, not above it. Root supplied by a caller must not be replaced with loader __dirname's cached root. Realpath in test setup may identify a canonical baseline directory but must not sanitize the hostile root argument before the loader receives it.

macOS system aliases such as /var or /tmp are real symlink ancestors: refusing an authored alias root is consistent with strict no-follow; accept only a caller-selected physical root and report the exact offending ancestor. Windows junction/reparse paths require native lstat coverage and explicit drive/UNC root handling; do not model Windows by replacing slashes while using POSIX dirname. Keep lexical unsafe-relative, NUL/dot/parent/drive-relative forms refused on all platforms. Native root ancestor/link/junction oracle cases establish actual semantics; unsupported creation capability must be reported rather than counted as passing coverage.

Recommended validation order: fresh root/authority snapshot law; full existing policy/owner deletion equivalence; two roots/repeated load after child manifest change; CJS/ESM stale-cache oracle and canonical fresh-load proof; repository Bun JSON→cruiser route; Node/VSCode config contract separately if changed.
