Read-only source/contract audit of the bounded document HTTP, GIS declaration, Stdio contribution selection and Energy EPW extraction. Read root, s and the three plugin AGENTS instructions. No source, Git or worktree mutation; this retained report is the only authored file. No generated files or heavy builds.

## Result

No confirmed introduced regression found in the inspected seams. This is not whole-package removability certification.

- Document client carries neutral route segments and a caller decoder. Compiled port admits owner-bound schema IDs, validates both directions and keeps transport byte/cursor bounds and cancellation. GIS wrapper and native Shell migration both retain typed receipt/page validation, including job/proposal binding and closed-ring checks after schema admission. No references to removed concrete client methods found in the source scan.
- GIS PluginBuilder publishes the declaration through the existing topic contribution. Independent Bun read-only descriptor check passed: exactly one port in each manifest and contribution projection, owner `gis`, service `s.gis.gismap.inference`, four operations, all eight schema strings byte-identical to authored sources. Console: `[DEBUG] descriptor GIS port count=1 per manifest/projection owner=gis operations=4 authored schema pairs identical`. Initial whole-tree topic-count assertion failed because the readable descriptor intentionally contains both manifest and contribution projections; corrected check examined each separately. The canonical producer build/hash proof remains executor evidence, not a build repeated by this audit.
- ContributionRegistry stores exactly its supplied roster, validates replacement before mutation and prevents removal when surviving declared dependencies become unresolved. Format callbacks are checked against owned schema; definition/assembly callbacks are checked for owner identity. Receipt assembly validates authorization, executable instantiation and global uniqueness; concrete catalog checks exact selected assembly identities and serialized factory ownership. Source scan found no stale concrete registry API calls or EpwWeather identifiers.
- General Energy site/BESTEST weather types contain no EPW references. Specific consumer owns decoding, typed record mapping and string-weather report convenience. Public EPW types belong to the first-party Stdio artifact; inspected new seams do not expose an unexported external-library type or introduce a compatibility facade.

## Residual Limits

- Neutral Stdio contract still has a concrete EPW rule at `📇️registry/🧬️contract/🦀️.rs:550`: artifact `epw` must have no MIME claims. This is retained policy coupling, outside the moved catalog imports; current working diff at that path was empty. A future complete neutralization should put this specific invariant in the owner contract. Do not describe the entire contract as domain-neutral.
- EPW converter preserves permissive numeric mapping: `saturating_sub(1)` maps hour zero to zero, u8 dates admit values outside calendar ranges and float parsing has no finite-value check. Neutral weather schema models Rust widths (month/day/hour 0..255) and generic numbers, and neither conversion entry point enforces that schema. These are admission-hardening gaps, not demonstrated extraction regressions; the execution scope explicitly preserves mapping. Additional invalid-calendar and non-finite fixtures would be needed before claiming validated physical weather input.
- General GIS schema, renderer, browser worker and MCP coupling remains. New admission resolves installed contributions but an already retained runner owns a compiled port and is not revoked when its contribution disappears, as the executor report explicitly states. Native lease filling remains a separate pre-existing limit.
- Stdio root still statically imports its concrete fleet. Receipt selection/removal proves the assembly seam only. General Energy engine still mounts through the model artifact.
