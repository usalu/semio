## Highest-Impact Refactor

The root cause is concrete composition hosted in general plugin owners. Sequence is an exact example: `✏️s/🔌️plugins/🎬️sequence/📦️packages/🦀️rust/🦀️.rs` reexports artifact editor/viewer modules and mounts `../../🦀️.rs`; that root closes `SequenceApps` over concrete editor/viewer apps plus `semio_s_artifact_stdio_semio::SemioMembers`, declares the artifact, registers typed mutation rosters and reads its activation kind. Its manifest directly links its artifact and Stdio codecs. Changing role fields or making dependencies optional cannot remove those declarations or preserve execution.

Move each concrete app fleet, artifact declaration, typed roster and artifact-specific activation into the specific artifact's component assembly. Keep the general plugin identity/capability/setup root independent of these concrete sources. Any cross-artifact converter belongs with the source/target artifact I/O contribution, not in the general owner. Package root reexports that recreate the coupling must disappear. Component loading/composition must be admitted through first-party contracts at the host boundary and tested with absent optional components. This is an architectural/runtime extraction, not only manifest cleanup.

## Existing Open Mechanisms and Their Limits

`✏️s/🔌️plugins/🗄️stdio/📇️registry/🦀️.rs` already owns `ContributionRegistry::new`, `register`, `remove`, and projections for artifact definitions, assemblies, format descriptors and codec receipts. Its adjacent `🧬️contract/🦀️.rs` contains catalog-independent `ArtifactContribution`/assembly/codec contracts. Prefer this admitted contribution mechanism to the concrete arrays in `✏️s/🔌️plugins/🗄️stdio/🔌️plugin/📇️catalog/🦀️.rs`, whose full/home catalogs hardcode dozens of artifact `contribution()` calls. Retain generic registry validation, uniqueness and bounded projection; move concrete catalog providers into the app/development composition owner. The registry constructor still receives concrete in-process values, so runtime component discovery/admission must be wired and proven rather than assumed.

The first-party SDK at `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs` has `ArtifactContribution`, `ArtifactDefinitionRegistry`, contributed mutation service registration, `ExtensionBundle`, `extension_exports!`, extension install/activation/invocation and bounded retirement. `ExtensionBundle::contributes` registers contribution mutation runtime and descriptors onto existing artifact kinds. It does not expose the plugin builder's `declare_artifact` or typed `document_app` channel. Therefore the SDK does not currently prove a direct replacement of a concrete `Plugin<ClosedApps>` component with an extension can preserve artifact creation/editor/viewer lifecycle. Define the missing schema-first artifact-definition/app-factory admission contract and verify ownership/activation/retirement before conversion. Do not smuggle `Plugin<ClosedApps>` inside an extension facade.

## Cargo Families and Exact Ownership Decisions

The retained live snapshot reports 291 plugin→artifact declarations, nine plugin→extension declarations and one spatial module→artifact declaration. These are prior measured counts; this audit verified current representative sources but did not rerun metadata or assert unchanged totals.

1. **Plugin component assembly:** Sequence and other plugin package wrappers close over artifact modules. Move concrete `Apps`, builder artifact registrations and mutation rosters under the corresponding artifact owner and update component manifests/descriptors/catalogs together. General plugins retain only general requests, extension points and discovery contracts. Keep artifact-specific tests with their artifact and multi-artifact integration under a composition owner.
2. **Stdio catalogs:** current `✏️s/🔌️plugins/🗄️stdio/📦️packages/🦀️rust/Cargo.toml` owns `full-artifact-catalog`, `home-io`, `component-app-assembly`, dozens of optional codec dependencies and dev dependencies on the nine families. Delete those concrete declarations only after full/home assembly callers accept admitted contributions from the app composition. Default-off features still count as forbidden declarations.
3. **Specific codec/converter dependencies:** Writer, Flow, Sequence and others depend on Stdio text/JSON/CSV/Semio codecs. Keep semantic conversion implementation at the artifact I/O owner; extract genuinely neutral wire/codec interfaces to the existing registry contract or a domain-neutral framework package. Do not relocate a whole document artifact merely to obtain its generic parsing helper.
4. **Nested generic services:** preserve physical selector enforcement for libraries/modules beneath plugins. Generic extraction is legitimate only when authored API/body and tests no longer reference the specific artifact. A role label of library does not make a concrete catalog generic.

## Nine Stdio Worlds

All nine direct extension package owners still declare `role = "plugin"`: `🔢️binary`, `🖼️image`, `🔺️mesh`, `🎵️media`, `💼️office`, `🧿️semio`, `🏠️bim`, `📘️pdf`, `🛠️cad`. Their root Rust sources call `Plugin::<Stdio*Apps>::builder(...)` and export `plugin_exports!`; manifests enable their plugin component entry feature. Thus physical ownership, metadata, compiled world and descriptor must be changed atomically.

If these are independent artifact family plugins, move them to truthful independent plugin owners and remove general Stdio's dev/runtime dependencies through higher composition. If they semantically extend Stdio, retain the extension owners, implement the missing open artifact-app admission, use `ExtensionBundle`/`extension_exports!`, declare `.extends("stdio")` with matching primary pinned dependency, preserve package identity/requests/execution/lifecycle, and update package manifests and descriptor tests. Merely moving existing plugin worlds into artifact folders leaves their semantic mismatch unresolved. The choice must follow the intended domain hierarchy; neither route is a compatibility adapter.

`✏️s/🔨️modules/🌐️spatial-kernel/⚙️engine/🧠️semio/🌊️session/🦀️.rs` imports `Brep`, `BrepKernel`, neutral vectors/handles/kinds, tessellation jobs and retirement types from Stdio's Semio Brep subset. Extract neutral geometry contracts, native engine algorithms, job stepping and retirement into the existing domain-neutral spatial/3D module taxonomy. Repoint the spatial session and Semio artifact to that package. Keep Semio snapshot/diff/mutation/document/child identity, editor windows and concrete STEP/mesh formats in the artifact. Preserve mesh exporter/importer interfaces and isolate formats; audit the embedded STEP implementation rather than moving format-specific logic wholesale. Move/rewrite independent geometry fixtures and third-party oracle tests with the engine. Delete old forward reexports; otherwise deletion of Stdio/Semio still breaks the general geometry module. This is the clearest independent first extraction with direct deletion-proof value.

## TypeScript Execution Partitions

The retained TS snapshot contains 79 plugin owner edges: 47 test, 16 story, 15 script and one composition build edge by inspection of its exact reported source paths. Families: Stdio24, Puzzle13, FEM12, Forms10, CAD10, Block6, Raster2, Procedural1, Flow1. The other29 edges are repo root-script imports of specific tests. * **Specific tests:** move Raster mask/pixel tests beneath its artifact's command/config owner; split FEM 2D/3D window-contract tests per artifact; move Stdio object/kernel/catalog tests into the exact subset/assembly owner; keep neutral geometry oracles with neutral engine extraction. CAD tests that exercise several optional AEC extensions belong to app composition integration, not the general CAD plugin root.
* **Stories:** move artifact renderer stories under the artifact, and cross-artifact app demonstrations under the s development composition owner. Update Storybook discovery and fixtures to load admitted present stories; deletion must not leave a hardcoded absent source import.
* **Plugin script imports:** Forms' general package script directly imports numerous question/editor tests; CAD imports specific renderer/stately/runtime sources. Put executable testing/build logic in the specific owner's `📜️script.ts`, register Nx targets and launch entries there, and leave general scripts using discovery/dispatch contracts. Moving only imported tests while keeping those static imports recreates the edge.
* **Root29:** `📜️script.ts` imports exact Trinity rewriting window/retirement/map tests and many specific document-contract probes. Move command bodies to their owners' `📜️script.ts`; root performs generic registered Nx dispatch to discovered owner targets. Existing generic `runCargo`/artifact schema inventory dispatch demonstrates how to select package IDs without importing test implementations. Avoid dynamic computed imports as a way to evade the graph; explicit execution partition and absent-owner handling must be covered by portable fixtures.
* **Composition build1:** `✏️s/🔌️plugins/🗄️stdio/🏘️composition/🏗️build/🟦️.ts` imports only `COMPOSITION_TYPESCRIPT_NAME` from `🗿️artifacts/📇️inventory/🟦️.ts`. This is infrastructure ownership inversion: the inventory file itself owns general composition package names plus artifact inventory functions. Move the composition names into the general composition owner and let artifact inventory consume those general declarations; leave artifact-specific enumeration and contract assertions at their specific owner. This is a small safe extraction without moving document runtime or weakening the rule.
