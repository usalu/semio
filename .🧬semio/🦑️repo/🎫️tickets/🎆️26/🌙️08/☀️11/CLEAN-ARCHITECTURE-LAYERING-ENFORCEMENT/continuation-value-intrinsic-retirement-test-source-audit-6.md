# Value Intrinsic Retirement Test Source Audit 6

Read-only inspection of the first new retirement unit law and neutral intrinsic JSON/schema. No test or script was executed.

The actual thirteen distinct rows cover Null, Bool, UInt, Int, Float, String, Bytes, Array, Object, and reserved-empty String/Bytes/Array/Object. Recursive array and object rows contain scalar/string/nested-array children; each run wraps DslValue in Box and therefore exercises Box child authority. Reserved buffers preserve explicit capacities128/17/5/5, with zero payload work. Fixture payload sums are manually consistent: UTF8 groß plus DNA is9; array bool1+ö2+uint8 is11; object keys a1/ö2 plus false1/DNA4/int8 is16. Other scalar and byte sums are consistent with their constructors. Both serde_json Value conversion and serialization compare to original payload before retirement.

The law observes actual allocator activity for inline ControlledRetirement construction, demand queries, default zero grants, each active one-below copy/capacity/release grant, exact steps and final owner drop. It requires construction/demand/denied heap0; exact step heap allocation/release totals must equal separate retained_capacity_bytes/released_bytes receipt columns. Payload copied bytes sum to the authored payloadBytes, grant fits enforce copy3/items1 and exact physical credits, terminal witness must occur within original100000 turns, and terminal drop frees0. This is stronger than a hardcoded physical release threshold and preserves the small work law.

Remaining source gaps: schema requires thirteen rows but permits duplicate kinds and missing kinds; it leaves value unconstrained and capacity optional even for reserved cases. The Rust law parses the corpus but does not validate it against the schema or assert the exact roster, and no current TS/Rust reference to the new schema was found by targeted scan. Strengthen the schema with per-kind shape/capacity rules and exact once-per-kind coverage, then enforce it through an owning language-agnostic validation law.

The zero/denied assertions prove zero receipts and no heap activity but do not directly assert cursor state/demand unchanged. Requery the three published demands after each denied step (or expose a neutral state identity) to detect inline movement with a false zero receipt. Exact terminal total currently checks released>=born rather than equality to original input allocation footprint plus scaffold births; per-step heap equality already provides strong evidence, but independently declared original Box/buffer allocation sizes would make full physical conservation explicit.

The law currently runs only Box-wrapped intrinsic owners, so direct DslValue admission should be included if the capability gate itself must be proven independently of Box. The expected red must remain an actual execution record; this source audit does not claim the test failed or passed.
