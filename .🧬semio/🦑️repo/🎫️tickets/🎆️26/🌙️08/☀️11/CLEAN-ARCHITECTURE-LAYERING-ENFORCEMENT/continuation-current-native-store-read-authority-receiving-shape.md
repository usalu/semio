# Store Read Authority Receiving Shape

General39 physically accepted the canonical typed ReadOwnershipRegistry. Actual Store's derived replay, preview and snapshot capabilities share its event-publication authority across erased member boundaries. Its Store struct is generic while these authority boundaries erase the concrete snapshot type. A public Arc of an opaque registry would reintroduce an uncontrolled final-owner Drop.

The receiving shape is a neutral ReadAuthority capability with an immutable publication/type view and a full FactoryAuthority owning the same original typed registry. Cloning a capability consumes one admitted logical item and no heap. Its view alias closes while the FactoryAuthority still retains the original; typed factory prebirth and payload closure then use the caller's separate capacity/release/depth grants. Each capability reaches terminal-empty before Drop. This uses genuine erased typed ownership rather than an old Snapshot-step adapter.

The registry supplies FactoryPayloadRetirement with an inline optional ControlledRetirement state; its full fixed backing and each typed root still follow the accepted registry law. Store mounts this new actual owner, creates typed reads with an explicit full grant, and uses bounded type selection for erased member reads. Existing source pointers, event authority fences, sparse maintenance order and original cancellation/copy datasets remain required. Every actual Store factory must expose the full constructor and retirement boundaries; no broad legacy Snapshot API remains a final interface.

General's new laws will observe multiple authority aliases and last-owner retirement with exact receipts before the actual Store mount is published. This is receiving design, not full OS acceptance.
