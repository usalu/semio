# Owned Process Async Stdin Port Audit

Bounded read-only source audit of General Process capture, termination and existing corpus/tests. Interface was contacted for proposed input design. At initial inspection captureOwnedProcess has no stdin option and starts stdin ignored; this report assesses requirements for the proposed port, not acceptance of an unobserved implementation. No tests were run.

Current public capture options/result are first-party structures with primitive fields and callbacks. Node child_process/fs remain private implementation choices behind that port. A neutral input port should expose Uint8Array chunks and a first-party cancellation-aware pull method, or carefully specified AsyncIterable<Uint8Array>; avoid exported Node Writable/Readable, Buffer or Bun FileSink types. The absent-input behavior must remain immediate EOF. Empty input must close stdin too. Explicitly define input-error refusal separately from process exit/spawn failure; never turn malformed chunks or producer rejection into success.

Original input bytes must be copied exactly to stdin without UTF-8 recoding or chunk-boundary semantics. Uint8Array offset/length must survive, including nonzero views and zero-length chunks. Borrowed chunk backing must remain retained until the write completion boundary; a producer reusing its buffer before consumption cannot be silently accepted without an ownership contract. Do not accumulate the full source before writing. An accepted module source payload must retain its original sourcefile/resolveDir or actual owning module URL for import resolution. Moving execution to a ticket file or eval root changes module origin even if byte hashes agree; preserve origin separately from capture storage.

Input pumping must run concurrently with stdout/stderr collection so a child writing output before reading input cannot deadlock. Respect write() false and wait for drain/write acknowledgement; charge/bound queued ownership rather than unlimited writes. Register input error/close handlers before the first write to catch early EPIPE. Call end exactly once on producer EOF. A child that exits before draining input must settle capture without awaiting an indefinitely pending next() or drain. Stop pulling immediately on cancel, timeout, output limit, spawn error or child close, release iterator resources when supported and prevent later asynchronous writes. Iterator.return() itself can hang behind a pending next(), so cleanup cannot rely on awaiting it forever. Prefer an input pull contract receiving cancellation and an explicit close boundary if arbitrary asynchronous iteration cannot meet bounded cancellation.

Existing output cap measures combined raw received stdout/stderr bytes, writes only remaining allowance, and terminates the process tree after overflow. New stdin cannot weaken that rule or replace first-cause result semantics. Evidence descriptors must stay open until stream close, and every timer/poll/input listener must release on terminal completion. Existing error callback overwrites reason with spawn-error, so a new stdin callback should not accidentally overwrite an earlier cancellation/output-limit decision. Child close, stdin error and pending writes race: expected precedence belongs in schema/corpus.

Current evidence files retain raw bytes, but result strings decode UTF-8. A cap cutting inside a multibyte scalar may turn one retained byte into a three-byte replacement character on result re-encoding. Raw evidence length/hash is authoritative for the cap and original-byte laws; do not infer raw byte identity from result strings. The existing test named strict independent schema admission currently only checks six unique case IDs; there is no capture schema file in the inspected owner. Add actual schema-first admission with an existing independent validator before expanding the corpus.

Portable neutral vectors should declare chunk bytes as integer arrays/base64, process mode, maximum input ownership, output limit, cancellation boundary and expected reason/status/evidence bytes. Cover absent/empty input EOF; binary NUL/invalid UTF-8; Unicode split at every byte boundary; nonzero view offset; multiple and empty chunks; slow reader exceeding stream high-watermark; child output-before-input; child waits for EOF before output; zero/nonzero early child exit; stdin rejection/EPIPE; producer rejection; producer stalled pull; cancel-before-spawn marker; cancel during drain/stalled pull; timeout/output overflow during input; exact output cap and multibyte cap truncation. Verify no pulls or writes after terminal, input closure and bounded completion, with deterministic readiness/acknowledgement rather than sleep-dependent byte expectations.

Independent Node built-in child_process spawn is the existing oracle infrastructure. Implement the oracle separately with ordinary Node stdin write/drain/end and raw Buffer readback; compare stdout/stderr bytes and exit/refusal semantics, while framework ownership counters/progress/cancellation receive their own laws. Existing esbuild can produce an independent Node executable preserving sourcefile and resolveDir to validate actual import origin. Existing third-party validators admit corpus structure; neither Node execution nor a shared helper alone proves all framework lifecycle semantics. Permanent script mounting/Nx and launch registration must make the new corpus executable; no unattached test-only shell script is needed.

The actual ticket draft at `cargo-inputs/📥️next-fixture-process/🧰️framework/🔨️modules/🏃️process/📥️capture/🟦️.ts` was subsequently read. It adds optional string input, pipes stdin, calls end(input) and maps stdin error to spawn-error. This draft does not yet implement finite byte-budget/backpressure ownership, and byte fidelity is limited to the string's UTF-8 encoding. Interface explicitly confirms this simple draft is not accepted, physical General source remains unchanged and it is revising the port to a finite first-party source with explicit byte budget and close/cancellation wakeups. No revised implementation or test receipt has yet been audited.

Revised actual ticket proposal was subsequently read: OwnedProcessInput is a first-party finite Uint8Array plus maximumBytes, checked before evidence creation/spawn; 4096-byte chunks are copied, drain waiters are detached/woken on stop, EPIPE/ERR_STREAM_DESTROYED stops input without overwriting the result cause, EOF end callback marks complete, and child close joins the bounded input task. Receipt queuedBytes explicitly counts enqueueing, not child consumption. The public port does not expose Node classes. Remaining lifecycle concern sent to Interface: close marks finished but clears timeout/cancellation only after awaiting inputTask; terminate lacks finished/exit ownership check, so a late timer can signal a child PID after actual exit. Clear timers before awaiting or guard termination by actual live owned child state. Interface reported actual fixture Bun green with nine vectors/schema/four independent Node raw-byte oracles, but Nx failure due a test type diagnostic; those receipts were not independently read in this follow-up and are not audited runtime acceptance.
