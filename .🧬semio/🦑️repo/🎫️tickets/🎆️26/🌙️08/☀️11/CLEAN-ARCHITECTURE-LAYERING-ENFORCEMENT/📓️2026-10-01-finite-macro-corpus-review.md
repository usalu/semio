## Blocking expected native result

`typed-closure-with-trailing-comma` is marked accepted but its single matcher ends `$derive:expr)` and the invocation ends `...b.len(),)`. Rust macro_rules does not accept an extra trailing separator unless the matcher author permits it. Remove that trailing comma from the accepted row and add a native-false rejection for this exact simple matcher, or explicitly add optional comma matcher syntax and implement/test that additional grammar. A scanner accepting optional trailing commas independently of the authored matcher grants unsupported invocation authority.

Other accepted native outcomes appear consistent by source reasoning: bare and typed closure expressions assigned to fn pointers, block closure with nested tuple, move || closure without captures, grouped tt boolean, numeric literal irrelevant to path, expr-forwarded concat, and multiple finite invocations. The current typed row uses &[u8], while actual PDF additionally uses `&PdfSnapshot`; retain both token shapes in closed grammar cases. The two-byte-input PDF macro body needs a case with **two include sites**, not just one generated byte include, so reference multiplicity/order is proved.

The thirteen refusal rows correctly distinguish policy-limited native-success forms (exported, qualified, multi-arm, repetition, shadowed names) from native-invalid invocations. Repeated matcher binding, malformed closure header, invalid ident argument, wrong arity, nonliteral fragment, nonstring include argument and const identifier include are appropriate native-false expectations. None was executed by this audit.

## Provenance and inventory gaps

Schema expansion metadata at `🧬️schema/🧱️rust-source-direction/🔣️.json:95` is closed but carries only macro/definitionLine/invocationLine. This distinguishes the current two invocations on separate lines, but cannot distinguish two identical invocations on one line, or identical include sites on one line. Add stable authored token offsets/ranges (definition/include site/invocation), not a synthetic counter depending on traversal order. Source identity may remain implicit in the per-source container only while same-file scope is rigorously enforced; cross-file support requires explicit definition and invocation source locators.

`🕸️dependencies/🧭️direction/🦀️source/🟦️.ts:68,81` JSON-deduplicates target rows, so same-line identical expansion metadata can collapse real facts. Its violation edge at 74–78 explicitly drops expansion metadata and deduplicates `(rule,from,to,kind,line)`. The new native law at 267–271 expects unique physical dependencies/edges, which is valid for compiler dep-info and physical targets but does **not** prove invocation-fact retention. Keep physical target dedup separate from expansion occurrence inventory. Preserve all invocation/template facts in reference/graph/report provenance even if one forbidden edge summarizes their shared target. Add same-line same-target and different-line same-target cases asserting occurrence count and metadata. Current all-config compile reference counter should count expansions before physical dedup and state that meaning.

All nine accepted rows put definition and invocation in the root source. They do not prove nested module binding, sibling-scope reachability, textual macro scope boundaries or source-file authority. Includes remain source-file-relative, not module-directory-relative, unless a native proof establishes a distinct expanded span origin. Test a root-defined macro called in an inline child and sibling; a child-local macro called only there; a call outside its scope; and a macro defined in a separate mounted source with a root call. For the last form reject unless real compiler span/input-origin behavior is implemented. Attribute path mounts/inline bases must not be transferred onto text/byte includes as substitute ownership.

## Missing hostile closure cases

Add closed refusals before implementation can claim complete finite authority:

- Zero local invocations; a valid invocation plus an invalid/unresolved invocation later; a valid root call plus qualified/cross-file call; invocation before definition or beyond local textual scope. One valid binding cannot authorize the rest of a template.
- Recursive self-call, helper macro forwarding the path, invocation inside another transcriber, macro-generated definition/invocation, repetition-created calls, cfg/cfg_attr/export attributes and shadowed nested same-name definitions. Reject the unsupported expansion mechanism even if a superficially literal include site is found.
- Include expression in an otherwise irrelevant argument, e.g. an expr argument containing another include macro. It is still a real compile input and must be discovered separately; ignoring irrelevant path-binding parameters must not mean ignoring their token bodies.
- Malformed **unused** expr/tt/ident arguments, empty expr, multiple ungrouped tt tokens, missing closing pipe, closure trailing tokens, illegal separator between closure parameters, extra invocation comma and unsupported typed/generic/return closure syntax. Native macro matching validates fragments even when the transcriber does not use them. Add a macro whose flag parameter is not emitted so these refusals cannot accidentally rely on Rust validating generated expressions later.
- Missing expanded file, linked leaf/prefix, raw missing-prefix/parent traversal and two includes with only one resolvable input. Successful path substitution is no authority to skip physical checks or return a partial fact list.

The native runtime law compiles, executes exact stdout, compares scanner references, checks rustc dep-info, resolves targets and performs physical census. That is a substantive oracle shape. Add an actual generated #[test] shape matching PDF or a test-count proof when claiming PDF generated law preservation; current synthetic functions prove input bytes/closures but not native test registration. Keep procedural quote consumer provenance outside this finite local grammar.

Recommendation: repair the trailing-comma expectation first; extend accepted corpus with two include sites, same-line repeated calls and nested same-file invocation. Add the valid-plus-hostile and template-generated-call refusals before implementation. Define occurrence provenance separately from deduplicated physical edges so GREEN cannot conceal incomplete template authority.
