# Owned Shell Branding And Development Composition

## Result

The React shell consumes generic `ShellBrand.windowTitle` and schema-owned localized footer data. It no longer imports demonstrator IDs or concrete footer components. The eight demonstrator brands contribute their own partner and funding credits with both languages, light/dark artwork, accessible link names, and compact-device behavior. The existing demonstrator page retains its own concrete footer components.

Development composition uses explicit `devContribution` playground metadata. A neutral JSON contract lives in `os/dev/🧩️contribution/🧬️schema`; its separate loader verifies canonical repository paths and real-file boundaries, rejecting traversal, Windows absolute paths, empty segments, and symbolic-link escapes. Branded rows require an owned contribution rather than silently degrading to an unbranded build. The contract references the shared development local-hub provider schema.

The generic Vite factory accepts an explicit catalog and browser entry. The generic browser boot function accepts an explicit catalog and surface-session factories. Demonstrator, S studio, and standalone puzzle entries provide the appropriate concrete dependencies from their owners. Serve, production build, and distribution planning select the metadata-owned configuration. Unbranded framework entry remains an explicit unbranded composition. The CAD/GIS multi-shell harness had an unused puzzle-factory contribution; removing it preserves its two unrelated pane behaviors while removing the dependency.

Three brand/introduction/concrete-footer tests moved from generic renderer tests to demonstrator ownership. Seven concrete Projektetage Reveal DOM tests moved from the generic presentation deck suite to the deck owner. Generic presentation geometry tests remain in the generic suite. Both concrete owners contribute `canonical-architecture` targets with the long test budget because their UI/deck import and runtime work exceeds the quick budget. The deck owner also has a public `test` target.

The browser closure fixture now starts at the actual neutral browser entry and requires the generic footer renderer. Its esbuild oracle models Vite worker-URL modules with a URL value and imports the underlying source as a side effect, preserving independent traversal of worker dependencies. Required live-tree and collision geometry symbols are explicitly exposed by the UI package from their existing owners/library boundary; there are no direct new renderer vendor imports.

## Schema And Fixture Evidence

- Manifest `ShellFooterItemV1` schema and a neutral JSON footer fixture cover English/German and expanded/compact credits; Ajv independently validates every concrete credit, and React DOM renders each case with accessible link names and security attributes.
- Neutral development-contribution fixtures compare the handwritten parser against Ajv for structure and canonical paths. A real directory-link escape test confirms physical ownership checks; the generated fixture is unique per run and removed afterward.
- The restored existing dev-root schema preserves its lease, catalog-header and spawn-request definitions. New contribution definitions have separate ownership. A mistaken initial replacement of that root was caught by the local-hub regression suite and fully corrected before completion.
