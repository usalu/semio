# Schema Boundary Audit

Read-only source audit on 2026-10-01. No tests or builds were run; the findings below are source observations and proposed work.

## Installation Identity

Current strict authority: `🧰️framework/🛍️products/💻️os/🔨️modules/🧩️extension/🧬️schema/🔣️.json` defines `InstallationDirectoryV1`: maximum 192 Unicode code points, explicit FE0F on every pictographic ZWJ component or keycap, non-generic emoji prefix, lowercase ASCII slug. `../🟦️.ts` additionally enforces NFC and derives the sibling identity using `Intl.Segmenter("und")`, dropping FE0F. Collision lookup normalizes siblings to NFC and drops both FE0F and FE0E. Preserve these distinct behaviors; accepting sibling files such as `🧩other.json` is deliberate, not permission to admit such a basename.

Repo authority `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/📇️catalog/🚚️deployment/🧬️schema/🔣️.json` instead allows any 1–128 character non-separator/non-control basename, including `foo`, colon, question mark, hash, percent, whitespace and decomposed Unicode. `🟨️.mjs` consumes that pattern; `🟦️.ts` reads bounded Cargo text and returns the same unchecked string. OS registry discovery uses that declaration at lines 169/303, while deployment `moduleDirectoryName` and `parseModuleDirectories` later call the strict OS extension parser. Therefore declarations can enter graph/discovery and fail only during materialization.

Precise extraction proposal: introduce one domain-neutral owner `🧰️framework/🔨️modules/🪪️identity/📁️installation/` with schema-first `🧬️schema/🔣️.json`, canonical ESM implementation `🟨️.mjs`, declaration `🟨️.d.mts`, and direct TS entry `🟦️.ts`. Export `InstallationDirectoryV1`, `parseInstallationDirectoryV1(value: unknown): InstallationDirectoryV1`, `installationDirectoryEmoji(value: unknown): string`, and `installationDirectoryCollision(name: InstallationDirectoryV1, siblings: readonly string[]): string | undefined`. Brand admitted strings in this owner; do not add former OS path forwarding exports. Move strict schema and pure segmentation implementation there, then rebind every OS installer/deployment consumer and their test dependency type imports directly. Repo deployment remains the owner of *optional Cargo metadata declaration*, imports the neutral parser directly, and returns `InstallationDirectoryV1 | undefined`. No Repo-to-OS dependency is necessary. Keep optional absence: generic compilation and describe must not imply publication.

Remove the old OS schema definition and old broad Repo basename schema; reference the neutral schema from deployment metadata schema. Update Repo graph revision hashing and `⚡️caching/🧫️fixtures/🔁️graph-revision/🔣️.json` for the neutral implementation/schema inputs; revision loader must include the shared schema so changing it cannot leave cached admission live. Update taxonomy/schema catalogue ownership through existing generation after source extraction, without compatibility schema copies.

Fixtures: move generic basename/collision vectors from `os/🔨️modules/🧩️extension/🧪️installation.json` to the neutral owner while retaining extension manifest data under OS. Expand neutral vectors with generic emojis, missing FE0F, ZWJ, keycap, FE0E, decomposed NFC, all URL metacharacters, 192/193 code-point boundaries and collisions with files, directories and normalized variants. Existing OS store test `🔌️plugin/🏪️store/🧪️tests/🧪️authored-extension-installation-identity/🟦️.ts` already uses third-party `emoji-regex` as emoji oracle. Repo deployment tests already use AJV and `@iarna/toml`; reuse these as independent schema/declaration oracles. Expand Repo declaration fixture with non-emoji/metacharacter declarations, valid strict names, absent declaration, malformed/repeated declarations, and compiled-only fixture. Test that the latter receives component and describe tasks but no materialization/publication tasks.

## Channel Authority

Current numeric authority is `🧰️framework/🛍️products/💻️os/🧫️fixtures/📡️channel/🔖️channel-version.json`, not the OS TS constant. Existing enforcement owner `os/🔨️modules/🧑‍💻dev/🔖️channel-version/🟦️.ts` exports `CHANNEL_VERSION_PIN_PATH`, `CHANNEL_VERSION_CONSUMERS`, census and generation. Rust channel and OS TS constants are registered consumers. Directory schema has three registered literals; browser describe schema has one. Registry `🔌️plugin/📇️registry/🧬️schema/🔣️.json` is currently absent from the registry because its `CatalogDescriptorV1.executionProtocol.appChannelVersion` is only integer/minimum 1 (lines 657–668). Tightening it to const 20 requires registering that path with occurrences 1. Portable hostile fixture versions must be registered using `hostileValues` or `arbitrary` as appropriate; generated Pack fixtures with changed descriptor bytes need derived registration and re-encoding.

Existing task registration: `os/🔨️modules/🧑‍💻dev/📦️packages/🟦️typescript/📜️script.ts` imports `ChannelVersionScript` and registers `channel-version`; adjacent `📋️project.json` has `channel-version-check` and `channel-version-generate`. Both `.vscode/launch.json` and `.vscode/🧩️launch.seed.jsonc` already expose them. Law file is `os/🔨️modules/🧑‍💻dev/🧪️tests/🔖️channel-version/🟦️.ts`. Avoid introducing a second protocol literal authority in Repo or the neutral installation owner. AppChannel is currently an OS-owned protocol, so domain-neutral installation extraction does not justify moving that authority.

## Source Versus Deployed Types

`🔌️plugin/📇️registry/🔎️discovery/🟦️.ts` currently uses a single `PluginRegistryEntry` with optional `directoryName` and supports both `descriptorAdmission: "source"` and `"compiled"`. Source parsing at line 295 is also used by build/host/filter operations at lines 477/509. Keep deployment metadata optional there, even when compiled descriptor admission succeeds. Use separate schema-first `ComponentSourceOwnerV1`, `CompiledComponentOwnerV1` and `DeployedRegistryEntryV1` contracts; only deployed entry requires admitted `InstallationDirectoryV1`. A conversion to deployed entry must check explicit declaration and descriptor ownership; source parsing must not synthesize compiled capabilities/contributions as authoritative descriptor facts. Declaration filtering at line 169 should use the neutral strict parser before discovery admits publication candidates. Materialization currently reads `metadata.semio["deployment-directory"]` directly in `🌐️browser-bundle/🏗️materialization/🚀️commands/🟦️.ts:51`; bind this to typed declaration admission rather than constructing an unchecked module row.

Current Repo `componentTargets` in `📚️library/🟨️.mjs:925–960` correctly branches only materialization leaves on presence of declaration. Preserve the compiled-only path. Its hard-coded OS describe/materialization tool paths remain separate infrastructure coupling; installation contract extraction alone does not remove that coupling.
