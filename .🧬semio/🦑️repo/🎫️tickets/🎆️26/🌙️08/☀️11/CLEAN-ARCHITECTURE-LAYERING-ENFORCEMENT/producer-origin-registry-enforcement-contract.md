## What Registration Can Prove And What Compiler Evidence Must Prove

Exact-source registration can prove: captured producer code/export/quote-slot identity, syntax binding relation, declared source authority inputs, current schema-reference closure, exact candidate consumer mounted context and unambiguous provider alias chain, deterministic expected emitted paths/cardinality. It cannot prove that proc-macro executes these paths for real compiler spans/configuration or that rustc dependency tracking includes them. Producer helpers currently read filesystem at compile time; source-only reconstruction cannot replace actual compiler expansion/dep-info evidence.

Required independent native proof: use fresh caller-owned build/test root, compile actual proc-macro plus actual consumer cohorts with present configurations/renamed aliases/facades, capture expansion or compiler-provided source map, parse escaped `.d` dependency paths, compare exact emitted include inputs with registry rows per consumer/slot; verify changing each registered raw input invalidates tracked compiler output. A mere successful compile is insufficient; unrelated same-input hashes or first-error scan count are insufficient. No such execution was performed here.
