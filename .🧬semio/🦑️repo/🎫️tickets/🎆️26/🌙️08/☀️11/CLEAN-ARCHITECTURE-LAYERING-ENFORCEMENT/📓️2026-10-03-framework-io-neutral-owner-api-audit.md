# Framework IO Neutral Owner API Audit

The General framework facade currently has one normal `semio-framework-os-kernel` manifest dependency and forwards OS `io`, three thunk macros and `sqlite_snapshot`. These are actual public API edges. IO schema and SQLite snapshot already have neutral standalone crates; the full IO module is still mounted as OS `os_io`, so General forwarding it does not establish neutral ownership.

Exact current owners: facade `🧰️framework/📦️packages/🦀️rust/{🦀️.rs,Cargo.toml}`; IO implementation `🧰️framework/🔨️modules/🚪️io/🦀️.rs`; neutral vocabulary `🚪️io/🧬️schema/🦀️.rs`; relational engine `🚪️io/🪶️sqlite-snapshot`; product store definitions `🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🦀️.rs`. Five exact manifest bodies were independently parsed with Bun and @iarna TOML with matching results. This is static ownership evidence, not Cargo feature-resolution proof.

The IO source has sixty textual `store::` couplings. Concrete public edges include six composer/subset-validator/format preflight and register APIs taking ArtifactAssemblyTransaction; ArtifactAssemblyRegistryPlan publicly carries OS document codecs, dialect migrations and native snapshot registrations. Its error enum exposes OS transaction/store errors. NativeSnapshotRegistration and NativeSnapshotMap retain the entire OS ArtifactCodec. ArchiveChildren publicly accepts OS DocumentArchivePack and stores OwnedDocumentMemberPackEntry. Typed serializer/deserializer/native SQLite entry constructors require OS ArtifactPack, ArtifactDsl and ArtifactSqliteSnapshot traits. Replacing the facade import alone therefore cannot close this boundary.

The OS ArtifactCodec is a product aggregate: alongside neutral snapshot conversion it carries VcsError-returning pack/SPR/edit operations and an OS MutationEnvelope callback. Moving that entire struct or OS store into General would recreate the inversion. The existing ArtifactSqliteSnapshotCodec is different: its exact schema/TypeId/export/import signatures use only IO schema payload/outcome/dialect, SQLite engine/control/encoding and neutral Value errors. Its ownership identity checks compare schema/type and actual function pointers. Transfer that capability directly into neutral IO/SQLite composition and rebind actual callers; do not make neutral snapshot registration retain an OS aggregate with unreachable placeholder callbacks.

A coherent direct-owner cut has four parts:

- Let existing neutral IO own its concrete registration machinery and shared ArtifactAssemblyTransaction barrier. Rebind OS store's registry guards to that exact neutral barrier, retaining the borrowed transaction lifetime. All consumers use the direct owner; remove OS alias definitions. General can then expose the real IO owner and neutral SQLite crate directly.
- Keep OS document codecs, dialect migrations and the full multi-registry assembly plan/error/commit composition in the OS plugin/store host. Neutral IO supplies its own lifetime-bound registry guards and typed preflight/commit operations; the OS host acquires every affected lock, performs every fallible validation, then commits without any fallible operation after the first mutation. Do not replace the current atomic operation with sequential independently publishing registrations.
- Give snapshot registration only its neutral conversion capability and actual identity fields used by current duplicate checks. OS decomposes its own declaration directly when composing registration; genuine IO fixtures instantiate the neutral provider rather than fabricate a whole OS codec. Preserve exact dialect/schema ownership and optional-capability semantics.
- Move genuine typed contracts to existing semantic owners: ArtifactDsl to DSL Record schema, artifact binary encoding/options/error/spec contracts to Pack and Pack Error, snapshot semantic/control contracts to IO SQLite/Schema. Separate the current optional snapshot coupling in ArtifactPack deliberately so the neutral dependency graph does not gain a Pack↔IO cycle. Archive child identity/byte carriers belong neutral IO Schema/Pack; OS document state/transactions stay Specific. Rebind generated and handwritten consumers directly in one reviewed composition; do not add legacy exports or wrapper aliases.

Public error semantics must be conserved. Barrier Unavailable displays exactly `artifact assembly transaction unavailable`. Assembly nested variants retain their concrete domain errors and Display delegation. Native snapshot duplicate/dialect/schema refusals retain exact coordinate and schema checks, reserved metadata exclusion, current function-pointer owner comparison and ValueRefusalKind mapping. PackError TextRefusal retains its TextError and diagnostic source, rather than flattening everything to strings. Canonical ordering, fidelity, cancellation and work/allocation accounting remain law-owned.

Actual direct-consumer candidates are captured in 35 files. They include OS plugin/store/space/MCP assembly, IO transfer laws, and concrete artifact IO/SQLite definitions in S. Text selects bounded files; lexical import/namespace and owned-span qualification must precede edits. Existing assembly lifetime schema has four preserved cases: explicit-release E0505, implicit-scope E0597, escaping-return E0515, and valid-order acceptance. IO snapshot fixture preserves exact native encodings, warning/error/fatal subset results and eleven refusal cases; allocation transfer laws retain native/physical values across both directions. Full source law bodies are captured, including helper functions; no claimed native test count or pass is inferred from text.

Physical deletion proof should run the real General IO facade and original neutral transfer/schema/codec laws with OS and Repo trees absent, then the actual Specific consumers with their direct declarations present. Preserve the four original borrow-checker lifetime laws at their proper composition owner, and Native must verify their compiler diagnostics unchanged. No existing API/compiler proof was run in this lane. ToolRun/Surface require separate direct ownership cuts; they are not necessary to identify these IO-owned spans.
