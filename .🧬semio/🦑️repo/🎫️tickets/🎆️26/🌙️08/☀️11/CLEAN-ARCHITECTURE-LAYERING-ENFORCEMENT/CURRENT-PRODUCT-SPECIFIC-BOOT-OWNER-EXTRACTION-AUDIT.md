# Product Specific Boot Owner Extraction Audit

Bounded read-only audit of Product15 failure summary, generated native host registry and current defining source. No tests rerun and no source edited. Native execution reports actual Product15: 1676 selected tests ran, 1662 passed, 14 failed, 11 skipped; this report does not claim acceptance.

The generated OS plugin registry hosts Rust source currently lists only draw/puzzle variants, only their activation kinds and an empty PLUGIN_HOST_CONFIGS. Consequently its global generation3d resolver returns the input spelling rather than procedural and has no declared app. CAD activation lookup returns None. This is direct current table evidence, not evidence that the CAD or procedural domain assets should be renamed to those unrelated providers.

Defining CAD authority survives at `✏️s/🔌️plugins/📐️cad/🗿️artifacts/📐️cad/🦀️.rs`: CAD_DIALECT uses s.cad.cad (line 32), artifact_kind_spec declares 3d.cad (line 493), and current capability identities retain s.cad.cad. Defining procedural authority survives at `✏️s/🔌️plugins/🌀️procedural/🗿️artifacts/🧊️generation3d/🦀️.rs`: typed declarations and capabilities explicitly name s.procedural.generation3d, its dialect, schema and document codec. Their plugin root native Cargo.toml/entry sources were not present at the inspected package roots; the roots currently expose dist. Surviving artifact source does not prove complete runtime plugin publication or generated discovery admission.

The OS Engine boot-selection corpus explicitly describes the original generation3d dependency-first flow/procedural boot regression. It supplies the domain programs and its own catalog, but the Rust law calls select_boot_program through the global generated registry. This couples otherwise valid owned fixture data to unrelated current discovery. Its semantic rows remain useful: target dependency ordering, requested owner absent, fallback within requested owner, app claimed under another owner, sibling role projection, absent sibling retaining anchor, refusing cross-dialect projection. Move the actual generation3d integration corpus and resolver declaration assertions to the surviving S procedural/dev composition owner, and maintain those rows there. They are domain-owned facts, not obsolete synonyms.

Product15 failures in plugin-install tests explicitly assert CAD ownership: the_host_plugin_is_not_the_owner_of_every_kind (line 30) and a_parsed_relay_kind_resolves_to_its_declared_owner (line 98). Move these exact CAD assertions to S CAD integration. OS generic activation laws should operate on an injected capability table with zero, one and multiple actual declared owners, reject duplicate claims, parse an arbitrary dialect coordinate and return precisely its declared owner, and refuse absent ownership. Never require every OS build to ship more than one plugin or CAD specifically. Existing parse-only coordinate tests do not inherently require CAD runtime admission; neutralize their fixture vocabulary for generic ownership without claiming it represents CAD.

The shell-input standalone_multi_app_variants_resolve_their_declared_app law directly demands generation3d -> procedural at lines 1138-1139 alongside puzzle declarations. Extract each original plugin declaration assertion to its defining owner, while OS exercises the generic mapping mechanism through explicit config input. Boot-without-requested-plugin fault test similarly demands procedural and its app from an unprovided global catalog; inject the intended boot target so the same missing-owner diagnostic behavior remains covered without requiring specific plugin discovery.

The panel fixture constructs a nonrunnable space guest with real home/studio app declarations and passes `space` to ShellState::new. Its palette order law requires space_mode, which currently depends on the empty host config table. This is a separate host composition dependency. OS should accept declared landing/host app capability through configuration and test order/panel/session laws with explicit injected host configuration; S Space integration should assert its actual composition. Do not reinstate a hardcoded space exception or synthesize a global registry row just to pass the palette test.

Schema-first split: retain original domain corpus under S/plugin ownership; add an OS-owned neutral configuration corpus expressing variant anchor, owner, activation kind and optional landing/host app configuration. Public neutral config behavior should preserve boot isolation, fallback, sibling projection, missing-owner faults and host chrome selection. Independent Serde interpretation can validate the shared corpus. TDD must run original extracted owner laws and generic injected laws before considering deletion-specific OS acceptance. Current failures identify architectural coupling; replacing expected cad/procedural names with draw/puzzle would hide it.

Existing executable admission routes inspected: `@semio-tech/procedural-js:test-renderer-contract` and its canonical-architecture alias call the procedural TypeScript package's permanent script `test renderer-contract`; that script explicitly mounts a rendererCases list, currently extension-evaluate-fault. Extracted procedural integration laws must be added to this list rather than left unmounted. CAD first-party TypeScript declarations are the artifact editor/viewer root modules, each defining its CAD_*_DIALECT constant. Existence of these routes was inspected; execution was not attempted by this audit.
