# Surface Embedded Scene Physical Format Audit

Bounded fresh source audit; no new runtime executed. OS TypeScript encodePackValue actually writes symbol table, one bridge field and value tag with no document shell. packValueToBase64 invokes that encoder and prefixes standard base64 with pk:. decodeScenePackField invokes packValueFromBase64, whose bytes go through the corresponding Body decoder. React parseSceneJsonField detects pk: and delegates to this path. These are code-authoritative Body producers/readers, not inferences from names.

OS Store encode_pack_value actually calls encode_document; decode_pack_value actually calls decode_document. Store pack_value_to_base64 only wraps given bytes and therefore has no physical-format authority on its own. Store scene_field_json_text and decode_scene_pack_field both unconditionally use decode_pack_value for pk: bytes. Consequently a pk: Body emitted by actual TS packValueToBase64 is structurally mismatched with these native Document-only readers. This is source-proven format mismatch; actual runtime failure for the eight fields has not been executed by this audit.

Surface expand_payload_pack_fields routes all eight optional slots through that Store helper: previewOffJson, lodJson, controlsJson, clustersJson, statusJson, computingJson, capabilitiesJson and hostSnapshotJson. EngineCanvas parse of embedded string fields is the other production scene_field_json_text caller found. Current original Surface native Pack test encodes the outer scene with Store encode_pack_value (Document) and contains ordinary node/edge/viewport values, with no embedded pk: slots. Neutral refusal corpus covers malformed JSON/viewport, interaction corpus covers wire values and tiledmap corpus covers PBF inventory; none qualifies embedded Body-vs-Document scene-field expansion.

Current inspected Flow editor/viewer window producers publish plain JSON strings (including preview-off IDs via serde_json::to_string and host snapshot JSON), forwarding other extras. They do not establish pk: runtime production. Repository production searches found no current packJsonText spelling; it must not be treated as a verified current function. TS packValueToBase64 is the verified generic Body producer. Rust media producers wrapping bytes under pk: include CAD, Draw, Lowpoly, Layout, FEM 2D/3D, GIS map/terrain, Mathematical equation, Process3D, Procedural generation2d/3d, Raster, Writer, Norm and generic OS plugin code; these are media/document slots, not proof every wrapper is a node-graph scene-field producer. Preserve caller-specific physical format, do not blanket-convert all pk: values.

General IO Base64 defining Rust owner exposes base64_standard_decode and base64_standard_decode_controlled with Base64Control {maximum_output_bytes, progress}; controlled decoder validates padding/characters before reserving result, distinguishes Codec/OutputLimit/Cancelled and checks phases in bounded 4096-byte chunks. Public decode_standard_quad also exists. No public decode_into port was found in this bounded defining source. Controlled decode still allocates temporary per-chunk vectors in validation and reconstruction, so maximum_output_bytes is result allowance, not total physical allocation evidence. Direct controlled use can remove Store's base64 authority, but cannot alone prove complete decoder ownership.

Next schema-first corpus should enumerate the eight slots with explicit physical format, plain-text passthrough, Body decoded against actual TS producer bytes, Document decoded against actual native producer bytes only at separately declared boundaries, malformed base64, wrong format refusal without retry, trailing bytes, null/scalar/array/object values, Unicode and exact number classes. Independent TS encoder/decoder plus native General Pack intrinsic decoder can establish cross-language agreement. Use explicit General Pack IntrinsicFormat and defining General IO Base64 control; do not replace the mismatch with heuristic Body-then-Document fallback. Runtime confirmation must precede claiming all eight producers/consumers work.
