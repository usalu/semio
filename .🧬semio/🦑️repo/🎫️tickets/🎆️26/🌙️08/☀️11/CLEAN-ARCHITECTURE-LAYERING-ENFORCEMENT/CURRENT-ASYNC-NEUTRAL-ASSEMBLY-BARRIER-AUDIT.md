# Async-Owned Neutral Assembly Barrier Audit

Read-only source audit. No production, Cargo or native changes. Canonical synchronization belongs under Async as a domain-neutral process publication gate, with the single static instance created there and used by both lower IO and upper Store. This adds no new crate or external runtime dependency. It does require a new explicit normal dependency from the containing Framework crate to the existing Async crate: Framework currently has only async-macros as a dev dependency, while OS Kernel already directly depends on Async. Re-export owned lower types explicitly; do not expose Semaphore, OwnedPermit, MutexGuard or any OS symbols as the gate API.

## Existing Mechanisms and Semantic Gaps

Async lines 1199–1280 implement Semaphore, OwnedPermit and AcquireOwned with private std Mutex state and Arc. Waiting acquisition is a Future, with waiter IDs removed on pending future Drop. Release broadcasts all wakers and drains the unordered HashMap; no fairness or bounded wait guarantee exists. Its critical-state locks are blocking Mutex::lock with poison recovery. OwnedPermit releases successfully during unwind and is movable between threads, unlike the original !Send assembly MutexGuard. An async wrapper around these operations does not establish bounded responsiveness under contention.

CancelToken.cancelled registers on the ancestor chain, wakes on cancellation and cleans registrations on Drop. Token state includes Park, but cancelled waits for terminal cancellation only: parked admission needs an explicit policy. select2 polls its left argument before right; cancellation-first ordering and a final cancellation check before accepting a permit are necessary when both become ready. yield_once only yields a polling turn; it cannot interrupt a blocking registry lock, user codec preflight, or lengthy synchronous validation. OperationContext provides cancellation and optional deadline but no progress observer, mandatory deadline or bounded-attempt contract.

Original Store lines 2458–2485 owns one process-global lock, rejects poison after a writer unwind, and exports a synchronous indefinitely blocking begin. Current corrected Store registry guards retain a private real borrow of the transaction. Preserve that borrow through all upper store guard operations. Maintain barrier→document→migration→composer→subset→format→native snapshot acquisition order. All validation remains before publication; no cancellation or fallible checkpoint is allowed after the first registry mutation. A semaphore substitution without sticky failure state would silently remove the original poison law. A Send transaction would silently change original cross-thread ownership semantics.

## Smallest Controlled API and Caller Cut

Start with a closed schema for the controlled finite step: mandatory cancellation, mandatory finite attempt/work bound, explicit progress observer, and outcomes Acquired, Busy, Cancelled, BoundExceeded, Unavailable. Proposed owned API: PublicationControl, PublicationProgress, PublicationError, PublicationTransaction, and publication_try_begin(&mut PublicationControl) returning one finite outcome. The transaction is private-storage, explicitly !Send, and its Drop records sticky process-wide Unavailable when std::thread::panicking; it releases admission and wakes contenders. There is no implicit default control or blocking begin overload. A Busy outcome is visible and requires an owner-driven retry; never spin or block_on inside registration.

An optional PublicationAcquire Future can be built on this canonical step plus registered wakes, with a caller-owned clock/deadline wake if elapsed-time bounds are required. Every poll checks cancellation and progress/work budget before attempting acquisition; pending Drop removes its registration. Polls must use nonblocking lock acquisition for state as well as permit contention, with retry scheduling so internal-lock contention cannot lose a wake. Existing Semaphore as written cannot prove this property. Reuse its waiter cleanup pattern, CancelToken and yield_once; do not simply wrap its blocking Mutex::lock in async. Cancellation wins if ready simultaneously with admission; a grabbed permit is released before returning Cancelled. Bound accounting limits attempts/work; a wall-clock waiting deadline additionally needs an actual timer wake supplied by the scheduler.

For registry preflight and commit, acquire all write locks with try_write in the same fixed order, drop all earlier guards on Busy, report progress, and return to the owning scheduler before retry. Do not await while registry guards are held. Once all candidates preflight and the final cancellation check pass, enter a synchronous publication phase with no await, cancellation or fallible operation after first mutation. Expensive preflight must itself be divided into bounded work before publication; merely changing acquisition does not bound arbitrary codec code.

Async existing preflight/document registration callers can await the controlled admission future, then execute a bounded synchronous transaction phase in the same poll. Sync callers must accept explicit control and return Busy/Cancelled/BoundExceeded to an existing job owner, or change their canonical signature to a Future and propagate await to their owner. This includes IO register_composer_entry_refs, register_subset_validators, register_native_snapshot_codec, register_native_document_codec, io_register; Store register_document_codecs/register_dialect_migrations; Plugin preflight_artifact_declarations/commit_artifact_declarations and builder try_build; MCP register_guest_document_codec. The actual async register_document_codec_for_app also needs control propagation. Update all callers together; leave no blocking unlimited compatibility API.

## Native and Wasm Constraints

The inspected primitives are pure std+repository types, without an OS product dependency. Async Cargo has a normal trace dependency; browser-only js-sys and wasm-bindgen are existing foreign dependencies, and public browser Promise/JsValue APIs expose them. The proposed gate API must not include browser ABI types. Generic semaphore/cancellation/select/yield are ungated and do not require browser bridges. Browser waits must be driven by browser-local futures rather than std-thread parking or entrypoint block_on. Native HostAsyncRuntime.spawn_scoped requires Send futures: keeping original !Send transaction means no await after transaction acquisition; the native future is Send only if every captured control/observer and pending state also meets Send. Existing async preflight wrappers holding the old MutexGuard across awaits cannot be treated as proof of this requirement.
