## 2. Method

* **Companion design.** Test files stay where they are, byte-identical. Each companion lib root (`#![cfg(test)]`) mounts them inside inline mirror modules with the physical test directory on the inline module, so rustc resolves the `#[path = "🦀️.rs"] mod tests;` in place; intermediate virtual directories use `#[path = "."]`. (An inline module cannot reach through a virtual directory with `..`, which is why the physical dir sits on the mirror.) The mirrors are `pub mod`, each with `pub use <crate>::<real path>::*;` plus the host module's external imports and trait names, and the root has `pub use <crate>::*;` plus the extras the tests expect (global allocator, `extern crate ... as protocol`). Test module paths therefore stay identical to the old ones, which is why the test-name multiset can be compared one to one.
* **Production hooks.** Private modules are reached through `#[cfg(feature = "testkit")] #[doc(hidden)] pub mod testkit { pub mod X { pub use super::super::X::*; } }`. os-command reuses its existing `mutation-testing` feature. Private items and members that the tests name are widened to `#[doc(hidden)] pub`; `cfg(test)` production items become `cfg(any(test, feature = "testkit"))`. No compatibility alias exists anywhere.
* **Widening is driven by the compiler, not by guesswork.** `union.py` compiles the baseline original (with tests) and the new production-plus-companion tree through the stub layer; `converge.py` and `autowiden.py` read rustc's own privacy diagnostics (E0603, E0616, E0624, E0451 and "is private"/"inaccessible" notes) and widen exactly what they name, skipping names the baseline cannot resolve either (negative controls in `negcontrol.py`). 141 ledger rows (`otcp-ledger.tsv`, regenerated by `ledger.py`): HOOK and WIDEN lines per file.
* **Embedded fixtures to run-time reads.** `fixtures.py` turned `include_str!` of fixture files that count into the closure into `static X: LazyLock<String>` reads through `CARGO_MANIFEST_DIR` (uses become `X.as_str()`); `const` contexts (os-command `WITNESSES`) kept `include_str!` because const evaluation needs it.
* **Registration.** Per companion: `Cargo.toml` and `project.json` (id `<crate-id>-tests`, project `@semio-tech/<id>-rs`), root `Cargo.toml` members (byte-sorted) or `🧰️framework/Cargo.toml` for the sqlite pair, `Cargo.lock` / `🧰️framework/Cargo.lock` entries (multi-version crates as `name version`, e.g. `syn 2.0.119`; validated by `lockdiff.py`), `📋️build-owners.json`, `.vscode/launch.json` plus `.vscode/🧩️launch.seed.jsonc` (six routes per crate after the `os-store-durable-group-tests 🧪️test 🚀️release` anchor), `🔒️dependencies.json` users lists, and taxonomy `crate-module-children` names (`🍎️companion`, `🍯️companion-1`, `🍰️companion-2`, `🧶️companion`, `🧷️companion`, `🧿️companion`, `🪤️companion`, `🌅️companion`, `🌈️companion-1`, `🌌️companion-2`, `🌆️companion`, `🧩️expand`); taxonomy unresolved names: 0. Each new folder is `<emoji>️<kebab>`, RGI, unique among its siblings.

## 7. Limitations

* Rust has no conditional visibility: widened items and members are unconditional `#[doc(hidden)] pub` (items hidden by `hide_items.py`, 65 lines); only the module-reachability hooks are `testkit`-gated. They are reachable from a downstream crate that names the path, but hidden from docs and not re-exported by any crate glue (glue lists made explicit for os-services; the remaining glob re-exports in touched files are either gated `testkit` mirrors or pre-existing, e.g. `pub use opening_config::*;` in os-config, where nothing was widened).
* The test names are identical, but the harness binary changes: each companion is its own test binary, so process-global state shared by tests of one crate now stays shared only within one companion (os-directory and os-config tests were split, which was verified only by the ordering-independent names, not by running them).
