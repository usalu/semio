# Result W4 TRACE-TESTKIT: one owner for the requested-allocation test helper

Executor: Sonnet 5.5, foreground, no sub-agents, 2026-10-15. Brief: `📓️WAVE4-BRIEF.md`. Tools live in `trace-testkit-tools/` (`units.py` finds the consumers, `edit.py` / `edit_mcp.py` / `ensure_manifests.py` apply the change, `census_all.py` + `closure.ts` measure, `oracle.py` + `sensitivity.py` are the differential), logs are `🗑️generated/trace-testkit-*.log`.
`TR` = `🧰️framework/🔨️modules/⏱️trace/🧮️memory/🧪️testing/📥️requests`.

## Status in one paragraph

`TR/🦀️.rs` (the `RequestedAllocator` / `observe` / `observed_requested_bytes` / `observe_backing` helper) is now the lib root of its own crate `semio-framework-trace-memory-testing` (Nx project `@semio-tech/trace-memory-testing-rs`), exposing the whole API as `pub`. All 36 `#[path]` mounts in 35 files (plus the one the mcp peer had just created inside `os-mcp-foundation`) are gone: every consumer got a `[dev-dependencies]` entry and the mount line became `use semio_framework_trace_memory_testing as <old module name>;` (`pub(crate) use` where the old module was `pub(crate) mod`). The `#[global_allocator]` statics stay in each test binary, unchanged, so each binary installs the allocator explicitly exactly as before. The patched differential is identical to the original for 35 of 36 test roots (the 36th has a pre-existing broken closure). **Nothing was compiled by cargo**: `bun repo cargo` refused with `Insufficient physical compiler initial headroom` (26 MB short of the 4 GiB image headroom).

## What the `pub(in crate::m_geometry)` edit was (the peer's intent)

- HEAD had `pub(crate)`; the working tree (staged, `16:56`) had `pub(in crate::m_geometry)` on `RequestedAllocator`, `observe`, `observed_requested_bytes`, `observe_backing`. No module named `m_geometry` exists anywhere in the repo (the only `m_geometry` string hits in source are substrings of `fro**m_geometry**`).
- Origin: `osflow-tools/union.py` (the `os-flow` carve's union sandbox) rewrites every `pub(crate)` of the files owned by a crate to `pub(in crate::m_<crate>)` so that crate-private items stay crate-private when the new crates are simulated as modules of one analysis crate (`mod="m_"+cid`, crate `geometry` -> `m_geometry`). The flow-geometry ownership test is the geometry crate's only mount of the helper, so the helper was swept into the geometry crate's "owned files" and the sandbox rewrite leaked into the real file. It was a differential artefact, not a design decision: intended visibility was "private to the geometry crate", which is what `pub(crate)` already meant for each mounting crate.
- Effect while it stood: every crate that mounts the helper and whose root is not `m_geometry` failed its `--test` build with E0742. With one owning crate the question disappears; the helper is `pub` and each binary decides by installing (or not installing) the allocator. `canvas-carve-tools/probe.py` and `trace-testkit-tools/oracle.py` revert the string in their sandboxes only.

## Design

```
semio-framework-trace            (zero-dependency tracing, owns HeapWitness)
  ^
semio-framework-trace-memory-testing   TR/🦀️.rs, role "test", id trace-memory-testing
  ^ dev-dependency only
36 consumer test builds (35 crates + 2 pack/os-kernel integration targets)
```

- Lib root `TR/🦀️.rs` beside the package dir `TR/📦️packages/🦀️rust` (recipe layout). Content is the former helper verbatim except: the four `pub(in crate::m_geometry)` became `pub`; the docstring explains installation; the tests mount (`🧪️tests/🦀️.rs` with the JSON fixture and the SQLite reference through `bun`) is now `#[cfg(test)]`, so the law runs **once** instead of in every one of 36 consumers.
- Only dependency: `semio-framework-trace` (path), for `HeapWitness`. Dev-dependency: `serde_json = "1"`. Boundary keys at the ceiling (4000 / 32 / 262144). `role = "test"` (owner-role table allows `test` under `^🧰️framework/`; `framework` would list a test helper in the framework catalog filter `role === "framework"`). Dependency-direction rules: no rule applies (framework module -> framework module; consumers under `🛍️products` depend on a module, not the reverse).
- Global-allocator semantics: a `#[global_allocator]` must be defined once per final binary. The crate defines none; it exports the unit struct `RequestedAllocator: GlobalAlloc`. Each consumer keeps its existing three lines (`#[cfg(test)] #[global_allocator] static X: <alias>::RequestedAllocator = <alias>::RequestedAllocator;`). Where the helper is linked into an integration target (pack `record-laws`, `record-schema-laws`, os-kernel `native-decoding/🚪️public`) the static lives in that target root as before. Because dev-dependencies are linked into a test binary once, `ACTIVE` (the thread-local scope stack) is one instance per binary, as before.
- No install macro was added: the static is three lines, a macro would only be an indirection with no second user. Keeping the old module name as the `use ... as` alias leaves all ~130 call sites (`test_allocation::observe_backing(...)`, `heap::observe_backing`, `allocation::observe`) untouched, which keeps the diff in peers' hot files to the mount line.

## Residual risks / open items

1. **Type-level checks never ran** (see 9): trait/method privacy and the helper crate's own tests are unproven. First compile: `-p semio-framework-trace-memory-testing`, then one small consumer (`io-base64`), then `--tests` for the rest.
2. **Lock files not updated.** The five `Cargo.lock` files are already stale for freshly carved crates (e.g. `os-channel` is absent from the framework lock), so hand-deriving would not make them consistent; the new package and the 34 dev-dependency edges are for the launcher's `update --workspace --offline` (checklist step 1). Also run `verify dependencies write-baseline` for the new manifest (step 2).
3. **Peers rewrote files under me**: the mcp carve replaced `os-mcp`, `os-mcp-plugin-runtime` and `os-mcp-foundation` manifests/roots at 17:26 (before my mcp edit) and the os-flow carve replaced the `os-flow-geometry` manifest at 17:34, dropping my dev-dependency line. `trace-testkit-tools/ensure_manifests.py` (idempotent, `--apply`) re-adds any missing dev-dependency line from `units.json`; `git grep -F "📥️requests/🦀️.rs" -- '*.rs'` must stay empty. If the mcp generator re-applies its old output, `edit_mcp.py --apply` redoes the foundation/mcp edit.
