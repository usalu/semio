## 2. Method per target

The TypeScript module splitter is `c4p3-tools/gsplit.cjs` (spec JSON per file in `c4p3-tools/specs/`): the parent keeps what is not picked, picked top-level statements move to children, imports are rebuilt per file from the names it uses, a private moved declaration that another file needs gets `export`, every region marker is re-opened and closed around the statements that sat inside it (so a region that spans several children is repeated, balanced, in each), and the importers are found with `git grep --untracked` and re-pointed (`importers: "auto"`; 0 manual importers in all three CAD runs). Children depend downward only: the parent depends on children, children never on the parent (checked below).

- **BIM mutations (row 2).** Six domain children by mutation family. The Rust descriptor `🧬️schema/🦀️.rs` builds the mutations TypeScript leaf with `concat!(include_str!(parent), include_str!(child) × 6)`, so the leaf text the registry carries is the same (the line multiset below).
- **Architect schema and diff (rows 3 and 4).** Register families moved into four children each; the generated `//#region 🚪️Parsers` block (guards and the per-register `parse…PatchEntry` functions) stays in the diff root, which is why that root is 1,012 lines (section 5).
- **CAD actions (row 5).** Four cohesive children (`action-contract` has no import edge, `selection-targets` imports the contract, `action-execution` the contract and the targets, `interaction-state` the contract and the execution). The parent keeps the display resolution and the parent-to-children edges.
- **CAD geometry targets (row 7).** `pick-model` and `preview-layout` have no edge; `geometry-index` uses both, `pick-styling` the pick model, `mesh-transfers` the pick model and the geometry index. The parent keeps the archived box footprints and the committed mesh layers, the top of the stack. Two statements gained `export` (`isVec3Record`, `spatialPickKindsForSelectionAccept`). Region `🔌️Adapters` (imports only) stays in the parent.
- **CAD artifact (row 8).** `interaction-catalog` (no edge) ← `interaction-model` ← `interaction-runtime`; the parent keeps the selection-operation runner and the in-source tests. Two statements gained `export` (`selectionOperationsForModelDefinitionFromActions`, `requireSpatialInteraction`).
- **CAD REPL (row 6).** `InteractionRepl` was one function with 157 body statements and 89 hooks, so no top-level cut exists. I wrote `c4p3-tools/hooks.cjs` after the precedent of the NodeGraph and ShellHost hook decompositions (`RESULT-NODEGRAPH-TSX.md` section 4): the component now does `const core = {} as ReplCoreAfter5;`, one `Object.assign(core, useX(core))` per hook in the original order, one destructure of the 107 names the JSX reads (80 locals, 27 props), then the original JSX `return` verbatim. Each hook module exports `ReplCoreAfter<k> = ReplCoreAfter<k-1> & ReturnType<typeof useX>` and takes the previous link as its parameter, so every binding keeps its inferred type (no `any`). The first hook takes the props with their original destructuring and defaults and returns the props the later hooks and the JSX read. Cut points (exclusive statement index): 87, 111, 121, 138, 157; the tool refuses a cut that creates a forward reference (0 found; the analysis table lists none).
- **BIM Python test (row 1).** `c4p3-tools/pysplit.py` (after `c4p14-tools/pysplit.py`, but by statement groups instead of regions, because this file nests regions): top-level statements are assigned to children by index (`specs/bim-ifc.json`, indices from `pynodes.py`), the region stack of each statement is re-opened around it, imports are rebuilt from the names used, and the root loads the children by path in dependency order with the `_load(alias, folder)` helper of the sibling adapters (the case folders are not packages), then `from export_bim_ifc_<key> import …`. The root keeps the header docstring, the case registry (`CASES`, `SNAPSHOTS`, …), `written_volume`, `straight`, `annotation_rows`, `measure`, `audit`, `open_case`, the handlers, `adapter()` and the `main` entry. Dependencies: `kernel` ← `classification`, `elements`, `walldepth`, `ramps`, `components`; `classification` ← `library`; the root imports all of them.

## 5. Deviations, limits and what was not run

- **The architect diff root is 1,012 lines**, 12 over the limit of about 1,000. What remains is the generated `🚪️Parsers` region (the `ProgramDiff` interface, the guard helpers and about 100 `parse…Patch` functions). Moving more of it needs the guards in a lower child and would change the shape the parser projection reads; I judged the 12 lines not worth that risk. Its four children are 138 to 859 lines.
- **Not run:** `cargo` (the launcher refuses raw cargo; the Rust tests of the BIM and architect schema crates, including the `include_str!`/`concat!` of the BIM mutations leaf, were not executed; the leaf text is shown equal by the line-multiset check). No browser or dev-server boot of the CAD REPL, no real-mount test of the hooks (the CAD suites that could mount it fail at load before and after, section 1). No ESLint run.
- **BIM oracle:** the repository Python host cannot run it here (`.venv` is Python 3.14 and IfcOpenShell 0.8.4 is built for 3.9). I ran the oracle with the system Python 3.9. Its EXPRESS-rule pass imports `_pytest`, which is not installed, so `pyharness.py` and `pycompare.py` skip that one pass (same before and after); installing pytest would have been a download, which I did not do without approval. The ramps and components audits (`ramp_problems`, `component_problems`) have no committed fixture to run on, so they are covered by compile, undefined-global and statement checks only.
- **Type-check scope:** the three plugin trees; the hook split relies on one type assertion (`{} as ReplCoreAfter5`), the same trade-off as the NodeGraph and ShellHost decompositions.
- `gsplit.cjs` got one fix this session: a region marker that sits between a statement's JSDoc and its first token (the `// #region 🔌️Adapters` of the geometry file) was not seen by the region scanner. The tool now cleans such markers out of the doc text and writes them after the doc comment; the pre-fix copy is `🗑️generated/c4p3-gsplit.before-docmarker.cjs`.
