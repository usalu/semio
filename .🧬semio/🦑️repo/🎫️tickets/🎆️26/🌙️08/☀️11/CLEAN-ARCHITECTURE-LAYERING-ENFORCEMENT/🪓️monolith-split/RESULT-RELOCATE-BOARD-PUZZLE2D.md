## Design decisions (owner by evidence)

1. **Brush and fill placement ids, fill stage labels and the stale-operation fault belong to the plugin.** Evidence: they are document ids and job progress text of the puzzle 2d domain. The only parser of a prefix, `FILL_RUN_NODE_ID_PREFIX`, is plugin code. The board behaviour itself (mint `<prefix><serial>`, run the stage machine) is generic. So the board keeps the mechanism, and a registration point supplies the vocabulary.
2. **The draw LOD table is board vocabulary, not puzzle vocabulary. It was renamed, not moved** (principle 2 of the brief: an item a framework module itself needs moves to its semantic framework owner). Evidence: the six bands are the variants of the board's own `BoardDrawLod`. The board's paint, grid snapping (`lod_visible_grid_snap_step_world`) and wheel-zoom pinning consume them through `current_draw_lod`. The rows' text is domain-free ("Whole-board silhouette…"). They are needed by every board host, including the plugin-less wgpu `BoardHost::default()`. The dag host owns its table the same way (`DAG_LODS`, `dag_lod_scale_json`), and its tests compare against these bands. Moving the table into the plugin would leave the board unable to resolve its own LOD and would make puzzle 5d depend on the puzzle 2d crate. Renamed `PUZZLE_2D_LODS` → `BOARD_LODS`, `PUZZLE_2D_LOD_SCALE` → `BOARD_LOD_SCALE`, `puzzle_2d_lod_scale_json` → `board_lod_scale_json`. The JSON output is byte-identical.
3. **Registration point shape: a static naming record installed on the host and on the fill ingress.** This follows the crate's existing plugin-installed policy pattern (`puzzle_board_host()` already installs `icon_paint_cache.themed_icon_lookup`, a plugin fn pointer). `&'static str` and a `fn` pointer keep `set_stage(&'static str)` allocation-free and keep `BoardFillJob` `Send` without new lifetimes or generics. The board ships a neutral default, because hosts exist that no domain configures (the wgpu surface, board unit tests).

### Design

- **Wire form of the naming.** A `&'static BoardNaming` cannot cross the scene wire. Only the brush prefixes are minted on a host the domain does not own: the fill job runs plugin-side only. So the board now has the owned type `BoardPlacementNaming { brush_node_prefix, brush_edge_prefix }` (B root), with JSON wire form `{"brushNodePrefix":…,"brushEdgePrefix":…}` (serde, `deny_unknown_fields`). It provides `BoardPlacementNaming::from_json` (both prefixes non-empty) and `to_json`, plus `BoardNaming::placement_naming()` for a domain to publish its static naming. The board crate is the single owner of the format: it both produces and parses it.
- **Owned variant on `BoardHost`.** A private `placement_naming: Option<BoardPlacementNaming>` overrides the installed static naming's brush prefixes. It comes with:
  - `set_placement_naming_json(Option<&str>) -> Result<(), NormalPortError>`: a refused form changes nothing, and `None` clears.
  - `brush_placement_naming()`, the effective prefixes.
  - `pub(super)` helpers `brush_node_prefix()` and `brush_edge_prefix()`, used by `brush_commit_preview` (`🎨️style`) and `plan_brush_pointer` (`🧹️scene-delete-links`).
  - `set_naming` drops an earlier wire override.
  - The owned strings are retired through the host's close ladder (`Strings` phase) and are part of `nonopaque_terminal_is_empty`.
  - New error variants `PlacementNamingJson` and `PlacementNamingEmpty`.
- **Scene contract.** New field `Board2dScene.placement_naming: Option<String>` (`#[serde(default, skip_serializing_if = "Option::is_none")]`). It is in the pack wire (`scene_pack_wire!`), `base()`, and `ToValue`/`FromValue` (`placementNaming`), with TS twin `Board2dScene.placementNaming?: string` (`🎬️scene/🟦️.ts`). Lane fixture `🚚️board2d-scene-lanes/🔣️.json`: `placementNaming` was added to `spineFields`, and a probe naming to `roundTrip.assembled` and `roundTrip.spine`, so the serde, pack and value round trip is exercised. Lane hashes are unchanged because they cover only the lane payloads. The plane unit probe sets the field. The typed retained catalog (`🧾️typed/📇️catalog.json`) is a curated subset that also omits `transformFlags`, `areaBrushSize` and `domainId`, so it was left unchanged.
- **Every host installs the scene's naming.**
  - wgpu: `sync_board_engine` (`🧩️engine-surface-attach`) calls `host.set_placement_naming_json(board.placement_naming.as_deref())` whenever `BoardSyncCache.placement_naming` (new `pub(super)` field, `🗂️engine-surface-registry`) differs.
  - React: `🖥️Board2dHost/🟦️.tsx` has a new effect that calls `session.setPlacementNamingJson?.(scene.placementNaming ?? null)` on `[sessionEpoch, scene?.placementNaming]`. `Board2dWasmSession` gained the optional `setPlacementNamingJson` (`🪪️WasmSessionLoader`), and the puzzle 2d wasm `BoardSession` gained the `setPlacementNamingJson` binding (`P/🌉️wasm`).
  - The render plan validator bounds the new payload (`check_optional_json_payload … board2d.placementNaming`).
- **Producers (plugin-owned vocabulary).**
  - Puzzle 2d `puzzle2d_board_scene` publishes `PUZZLE_2D_BOARD_NAMING.placement_naming().to_json()`.
  - Puzzle 5d's board scene publishes `puzzle5d_board_placement_naming()`, declared by the 5d plugin with the historic `puzzle2d.brush.` / `puzzle2d.brush.edge.` values. 5d's `applyBoardEvents` persists the board-minted `nodeId`/`edgeId` as part ids, and every lane minted those values before, so they stay byte-identical. 5d does not depend on the 2d crate.
  - The read-only 5d viewer board (`interactive: false`) publishes `None`.

Result: on the wgpu lane, the React lane and the plugin-side hosts, a puzzle 2d or puzzle 5d brush placement mints `puzzle2d.brush.<n>`/`puzzle2d.brush.edge.<n>` exactly as before slice D. A board with no declared naming mints the neutral `board.brush.<n>`.
