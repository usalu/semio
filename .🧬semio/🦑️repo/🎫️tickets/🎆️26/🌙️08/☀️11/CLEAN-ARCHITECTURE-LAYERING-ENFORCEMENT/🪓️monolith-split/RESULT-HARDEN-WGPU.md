# Result: Hardening of the wgpu monolith splits (full-resolution differential)

Executor: Sonnet 5.5. Scope: crate `semio-framework-os-renderer-wgpu`, five splits: renderer (`🧊️renderer`), Scenes, Shell, EngineCanvas (A) and Interpreter (B), plus the new `crate::element_contracts` module. `E/` = `🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/`. No cargo, no scratch workspace and no private target directory was used or created; only `rustc ... --emit=metadata --error-format=json -o /dev/null` (analysis only, nothing written to any store). Tools and logs: `🪓️monolith-split/🗑️generated/harden-wgpu/` (`mksb.py` sandbox builder, `orc.sh` oracle, `cmp.py` comparer, `fast2.sh`/`full2.sh` drivers, `defscan.py`/`apply.py` definition scan and applier, `r1`..`r7` logs, `plan1.json(.applied.json)`, `appendix.md`). Sandboxes lived in the session scratch dir only.

## 1. Setup

- Lib root: `E/🎯️targets/🧊️wgpu/📦️packages/🦀️rust/📚️library/🦀️.rs` (`[lib] path`). `[features] default` does not exist (only `native-bin`, which gates the `[[bin]]` only), so no feature cfgs were added.
- Command (one per configuration, from the package directory, with `OUT_DIR`, `CARGO_PKG_VERSION`, `CARGO_MANIFEST_DIR` set to the same values in both trees): `rustc +nightly-2026-07-20 --edition 2021 --crate-type lib --crate-name semio_framework_os_renderer_wgpu --emit=metadata --error-format=json --json=diagnostic-short -o /dev/null <cfg> 📚️library/🦀️.rs`.
- Configurations: native lib; `--test`; `--target wasm32-unknown-unknown`; `--test --target wasm32-unknown-unknown`; plus `--cfg test` (native, see section 3).
- Baseline sandbox: a full copy of `E/` (no `node_modules`) plus the 72 outside-the-tree directories that `#[path]`/`include!` reach (`extras.txt`, found by looping on "couldn't find file" errors), 21 stubbed missing fixtures (`stubs.txt`). The five parents are replaced by the saved originals (`renderer-A-original.rs.txt`, `scenes-original-HEAD.rs`, `shell-split-tools/shell-original.rs.txt`, `ecint/A-original.rs`, `ecint/B-original.rs`); every child folder that the current parent mounts and the original does not is removed (computed from the `#[path]` lines, 12 + 15 + 20 + 9 + 10 folders), as is `🧬️element-contracts`; the 31 recorded contract edits (`ecint/tools/edits.jsonl`) are reversed in the non-split files (`os-host`, tests); the source-text readers in 11 test files that the splits re-pointed (`crate::RENDERER_SOURCE`, `crate::shell::SHELL_SOURCE`, ...) are reverted line by line (`REVERT` table in `mksb.py`), and each original gets the same `#[cfg(test)] pub(crate) const <X>_SOURCE: &str = include_str!("🦀️.rs");` that the split parents define, so the many other readers resolve in both trees. Peer changes in non-split files are copied fresh into both trees, so only the splits differ. Current = a fresh copy of the live tree, rebuilt before every comparison.
- Sandbox patches applied identically to both trees, never to the repo: (1) every `extern crate x as y;` becomes `mod y {}` (missing crates make E0463 abort rustc; a stub module keeps the name in scope at the same place, so a child that lost access to `store`/`protocol`/`dsl`/`infinite_world` still shows a different error); (2) every glob from an external crate becomes `const _: () = ();` (a failed glob suppresses all unresolved-name errors in its scope); (3) `OUT_DIR/🧩️icons.rs` is an empty file; (4) the peer-owned test `Shell/🧪️tests/🧭️wgpu-navbar-footer-parity/🦀️.rs` has two missing semicolons (`expected ;, found caller`, both trees) that stop rustc at parse time, so `;` is inserted in both sandboxes.
- Comparison: multiset of (code, message, primary-span source text, label); file and line are dropped because the code moved. Unresolved-external-crate errors (label "use of unresolved module or unlinked crate", or `unresolved import` of a Cargo dependency) are compared as sets, because the same `use` now sits in several files.

## 3. Limits of the oracle

- Native `--test` stops after import resolution in both trees (about 1,550 errors, no E0425/E0412 at all, a seeded undefined function in every module is not reported). `--test` with the harness is blind here for reasons I did not isolate (the wasm `--test` run is not blind). `--cfg test` (cfg(test) code without the harness) is not blind and replaces it for native-only test code such as the kernel semantic-document law.
- Typeck never runs (extern crates are missing), so E0616/E0624 are invisible; the definition scan below is the only check for fields and methods.
- Names that come from missing crates are invisible by construction. The `mod store {}` stubs make "child lost access to a root-level crate alias" visible, but not "child names an item inside a missing crate".
- The sandbox's baseline and current both depend on peer state in non-split files at the moment of the copy.

## 4. Definition scan (fields, methods, tuple fields, items)

`defscan.py` builds the module graph from the lib root (`#[path]`, `include!`, plain `mod`), takes every private or narrower-than-needed item, field, tuple field and inherent-impl member in the files of the five new child trees (plus `element-contracts`), and looks for uses in other modules of the same original module family. The family is what could see the member before the split: the monolith's module subtree (the Shell/Scenes/A/B parents; the `kernel_runtime` subtree for the K1 to K4 children; the whole crate for the renderer root children, since root-private is crate-visible; `scale_bench` alone). Uses are classified per occurrence: `certain` (struct literal of the owner, `Owner::name`, `Self::` in an impl of the owner, or a receiver whose type is resolved to the owner through `self`, annotated parameters/lets and field types), `maybe` (receiver type unknown). For the crate-wide family only `certain` and `maybe` in a file that also names the owner count; elsewhere every `maybe` counts unless the name is a common std name. The narrowest module that contains every counted use gets the visibility.

Result: 170 widenings (89 fields, 62 methods, 19 items), all to `pub(super)` (visible in `kernel_runtime` and below, or the renderer root for the one root child), applied by `apply.py` after re-reading each target line (0 mismatches):

- `E/🎯️targets/🧊️wgpu/🧊️renderer/🎨️presentation-raster/🦀️.rs:632` `RuntimeMailboxInner.native_asset_http` (used by `📮️mailbox-impl`).
- `E/🎯️targets/🧊️wgpu/🧊️renderer/📦️kernel-runtime/🧮️kernel-core/🦀️.rs` 47, `.../📬️kernel-replay-client/🦀️.rs` 77, `.../🗃️kernel-retained-state/🦀️.rs` 44, `.../🏊️kernel-pool/🦀️.rs` 1 (field at the `KernelRequestQueueState` struct). The per-line list is `appendix.md` (inlined at the end of this file).
- Scenes, Shell, EngineCanvas, Interpreter and `element-contracts`: 0 members. The only candidates were 5 false positives that were skipped on purpose (`const _`, `fn tutorial_surface_geometry` whose name equals its module, the scale-bench `fn row` vs a loop variable, a second `TEXT_STREAM_CAPACITY` const in `🌐️browser-worker`, and the `WorkerCell.inner` field name that only appears in the Scenes' own unrelated `WorkerCell`).

After the edits a second scan reports exactly those 7 skipped candidates and nothing else. Seeded check: removing `pub(super)` from `RendererSequenceAuthority.reserved`, `RetainedSurface::admit_patch` and `RuntimeMailboxInner.native_asset_http` in a sandbox copy of the fixed tree makes the scan report all three (plus the 7 known skips). The `--cfg test` run after the fixes is identical to the baseline.

## 5. EngineCanvas, Interpreter and `element_contracts`

- The differential above includes both (originals restored, 9 + 10 child folders removed, contract edits reversed). Regressions attributable to them: none, in all five configurations. Their own report compared with only A/B restored; this run restores all five monoliths.
- The EngineCanvas/Interpreter author's note that `--test` stops after import resolution is reproduced (native `--test`); `--cfg test` reaches name resolution and was used instead. Their sandbox patches (globs, extern crates) were used here as well, with the stronger `mod alias {}` replacement.
- `crate::element_contracts` (159 lines): the scan finds no cross-module private member use; the contracts are `pub(crate)` with private fields `initialize`/`inner` of `WorkerCell` only touched inside the module.
- Residual structural risk recorded by their report (B and Scenes still call each other by function) is unchanged.

## 6. Residual risks

- Fields and methods rest on the name-and-receiver scan, not on typeck: a use through a receiver whose type the scan cannot infer, in a file that does not name the owner, and outside the `kernel_runtime` family, is not counted for the renderer root children (168 such candidates, `defscan-ignored.json`). Run the real `cargo check` (and `--tests`, and the wasm variants) first once the source-boundary gate admits the crate.
- The native `--test` configuration is not covered by name resolution; the K4 semantic-document law is covered only through `--cfg test`.
- Trait-method scoping (traits moved into children) is not covered by the scan; no trait definition was found moving in the five splits.
- The peer test `🧭️wgpu-navbar-footer-parity` does not parse in the repo (missing `;`), which breaks any real `--tests` build until its owner fixes it.
- Unused-import and dead-code warnings from the widened `pub(super)` surface and the `pub(crate) use child::*` re-exports are not assessed.
