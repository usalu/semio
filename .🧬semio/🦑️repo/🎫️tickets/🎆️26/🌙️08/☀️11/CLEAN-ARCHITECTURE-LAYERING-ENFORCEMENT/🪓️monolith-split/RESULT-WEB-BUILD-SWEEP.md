## 1. Method
Direct vite build, exactly the child command of `buildViteArtifact`: bun `node_modules/vite/bin/vite.js build --mode prototype --minify false --config <builder> --configLoader runner --outDir /Users/ueli/.cache/wbs/out/<name> --emptyOutDir`, cwd = the bundle root, env `SEMIO_BUILD_MODE=prototype` and `SEMIO_VITE_CACHE_DIRECTORY` (the builders' `viteCacheDirectory` insists on a path inside the products mount; a symlink `.cache/b/p/m/wbs-cache -> /Users/ueli/.cache/wbs/cache` satisfies the string check without writing into the bounded image). Tool: `wbs-tools/vb.sh`. Logs: `🗑️generated/wbs-<name>.log`. Output never inside the repo.
Wasm-gated apps additionally get a "stubbed" build (`wbs-tools/stub-build.mjs`): the repo config is loaded as is, the two wasm plugins (`semio-canonical-wasm-build`, `semio-managed-wasm-packages`) are dropped and the five engine packages plus `*.wasm` are replaced by an empty synthetic module. That proves the rest of the TS module graph (aliases, exports, `?raw`, CSS) resolves without cargo.

## 3. Findings and fixes
- F1 (fixed, owner `🧰️framework/🔨️modules/🖱️ui/🎨️styling/🏗️builder/🌐️vite/🟦️.ts`, `semioReferencedAssetsVitePlugin`): the plugin scans the written bundle for `/🖼️assets/<path>` and copies those files. A repository path literal in the bundle (`RUNTIME_ASSET_CHANNELS` in `🖼️canvas/🔌️runtime-assets`, `directory: "…/🔨️modules/🖼️assets/🔣️icons/🤖️generated/🔤️shortcodes"`) matched as `/🖼️assets/🔣️icons/…/🔤️shortcodes`, which is a directory, so `copyFileSync` threw. The reference regexp now needs a token boundary before the route (`(?<![^\s"'\`(=,:\[{>|;])`).
- F2 (fixed): `managedWasmPackagesVitePluginV1` has a closed row schema (`packageName, root, entry, files, entrypoint`). Play passed `frameworkOsEngineDeliveriesV1` rows unprojected (extra `id/sourceOwner/request`), demonstrator dropped the required `entrypoint`. Both now project the five fields exactly like the os dev builder does.
- F3 (fixed): play `base: "."` is rejected by Vite 7 ("invalid base option"); now `"./"`.
- F5 (fixed): `🗿️artifact-reference` package entry re-exported the schema JSON without `with { type: "json" }` while the module itself imports it with it; Rollup warned "already imported elsewhere with no attributes". Entry now carries the attribute.
- F4 (gated): see section 4.
- F9 (fixed, 27 files, `🏃️process` plus `📁️filesystem/🧾️observation/📁️descriptor`): JSON imports without `with{type:"json"}` in the closure of the Next coordinator's `next.config.mjs`, which Node loads natively (`ERR_IMPORT_ATTRIBUTE_MISSING`, first hit `🔒️leases/♻️retirement/🧭️continuation/🟦️.ts`). `wbs-tools/jsonattr-closure.mjs` walks the import closure (92 files) and listed 28 imports; `wbs-tools/fix-json-attr.py` plus two hand edits added the attribute (0 left). Bun, Vite and vitest accept the attribute-less form, only Node does not.
- F7 (fixed, `.storybook/main.ts`): `staticDirs` named `.cache/b/p/m/browser/prototype/modules` (the built plugin modules root); a directory that does not exist aborts `storybook build` with "Failed to load static files". The list is now filtered with `existsSync`, matching the comment that Storybook "serves whatever is already on disk".
- F8 (fixed, `🖱️ui/🎯️targets/⚛️react/🛠️build-tooling/🟦️.ts`): `hostBuildPlugins` refused `@tailwindcss/vite:generate:*` (Tailwind 4.3.3 declares `transform: { filter, handler }`). The shape check accepted an object hook only for `transformIndexHtml`; any hook may now be a `{ handler }` object.
- F6 (fixed in section 7.1; original finding): the os dev builder (`🧑‍💻dev/🏗️builder/🌐️vite/🟦️.ts`, async factory with opaque `import([...].join("/"))`) cannot load with `--configLoader runner`: Vite 7.3.6 closes the module runner after importing the config, so the first dynamic import fails with "Vite module runner has been closed". `buildViteArtifact` and `serveVite` both default to `runner`; it loads with `--configLoader native` (used by `stub-build.mjs` via `WBS_LOADER=native`). The owner of the build route has to choose between `native` for the os dev builds and static imports (the config-graph law wants the opaque form). Dated 2026-10-13 (line 54 blame), unrelated to the splits.
- F10 (fixed in section 7.2; original finding): the quiz bundle warns that `▶️run`, `🏁️results` and `🐾️pets/🎪️stage` are "dynamically imported but also statically imported": `quiz-react/🟦️.tsx` lines 161 to 163 re-export both screens from the entry, which defeats the lazy `runScreens()` import. Tests import them from the package entry, so removing the re-exports needs a test-import rewrite.
- F11 (reported, cosmetic): Vite warns "dynamic import cannot be analyzed" for `RUNTIME_WEBSOCKET_MODULE` in `🔌️vite-plugins/🔀️stream-mux-server/🟦️.ts` and for the opaque imports in the os dev builder.
