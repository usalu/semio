# Strict Schema Source Authority Execution

The new neutral owner is Framework Schema `📄️source/🔗️closure`. It receives captured raw JSON source and opaque input coordinates, indexes schema resources, and resolves every declared reference occurrence. It has no filesystem discovery, product dependencies, or network fetches. Its caller remains responsible for physical file identity, containment, link refusal, and source freshness.

The contract requires an explicit absolute base URI, declared JSON Schema dialect, supplied resource list, declared additional annotation keywords, and operation controls. All input identities, source paths, resource URIs, and static anchors must be conflict-free. Unknown keywords and dynamic reference semantics are refused. Data annotations do not create schema obligations. Pointer decoding retains empty segments and checks exact schema positions.

The language-neutral corpus and closed JSON Schema precede production implementation. The registered Bun/Nx route checks the complete corpus against AJV for supported reference semantics and uses the owned strict JSON member policy below Schema. Raw text remains authoritative; this feature does not expose parsed instance numbers or claim generic numeric round-trip fidelity.

Required controls bound total source bytes, per-source bytes, parser/schema depth, schema positions, resource identities, and reference occurrences. Chunk checkpoints yield to the event loop and observe cancellation. No failed operation returns a partial accepted closure.

The eventual Rust producer registry must consume equally strict resource closure and supply actual macro/Cargo/consumer origin authority. Creating this core does not make the whole Rust source scanner green or prove physical plugin/product deletion. The full existing cohort and source snapshots remain required.
