# Mesh Fixture Specific Deletion Boundary

The neutral Mesh Engine and generic 3D mesh tests currently read the polygon attribute corpus from the S Flow Brep extension. Deleting S therefore removes required compiler inputs for general crates. The compiler route observations in the native Core integration also retained this specific fixture as an input; that was a qualified capture gap, not a successful deletion proof.

The candidate clean owner is Mesh Engine, which defines the polygon source and attribute data consumed by 3D and Brep. Its existing polygon JSON schema is currently placed in the Brep extension despite describing the general polygon contract. Move both the corpus and schema to that defining lower owner, bind all original readers directly to that owner, and retire the specific copies without aliases. Preserve every fixture byte, original test assertion and workload; change the schema identifier to its neutral owner.

The scoped predecessor inputs and literal census are retained in `mesh-fixture-owner-inputs/full-predecessor-1.json`. This is a read-only discovery and proposed ownership cut. No source or compiler mutation has been made for this boundary. Native source publication must follow the current IO/UI/Pixels compiler fence.

Admission requires schema-first neutral fixture laws with an independent JSON/schema/geometry oracle, an actual failing predecessor ownership law, a neutral source test projection with S absent, exact original caller conservation, and the relevant unchanged whole native owner routes after publication. A source-only result will not be reported as a complete framework deletion proof.
