# Schema Single Provider Cycle Review

Read-only manifest/source review, no jobs. No direct schema→replication→schema cycle is present in inspected actual manifests: replication dependencies are value/hash/optional deflate/base64/value-derive plus external serialization/browser bindings; neither replication manifest nor value/value-derive inspected manifests declares schema or OS. Direct schema→replication would therefore not establish the suspected direct cycle. This is bounded manifest evidence, not full native/transitive graph proof. It would still pull a much wider runtime closure than pure descriptor/state vocabulary needs.

## Actual source purity and identity

Existing schema/🧩️composition/🦀️.rs has no crate::/super:: imports or external dependencies: six slot/reference/visitor traits/types plus Option/Vec implementations using visitor.step. It can compile under one dependency-free lower provider. Current OS package265 mounts it; schema component123 gets that OS trait identity; derive expansion270–278 emits ::semio_framework_schema traits/slot types. A second schema mount would define incompatible traits. Exactly one crate must compile this source, and all public paths/derive emitters/OS implementations must name that provider.

Existing schema-registry package is already dependency-free and schema lower package depends on it. It is a plausible existing canonical provider for generic descriptor registries, but composition is a separate domain facet: mount the source once through a dedicated schema-composition package, or explicitly extend the registry domain only if authored taxonomy/schema declares composition belongs there. Do not force unrelated domain under registry merely to avoid a package. A dedicated composition package has std-only closure and preserves source location.

Descriptor block replication wire328–484 is std HashMap/Mutex/OnceLock and static leaf strings; no crate-relative codec functions inside that block. Immediately adjacent protocol functions depend crate::codec, so extract exactly the descriptor domain rather than mounting whole wire into schema. Existing schema registry is the coherent generic catalogue destination, with single source descriptor types and conflict semantics; replication and OS import it directly. StateClass294–325 separately implements crate::value ToValue/FromValue and owns four lane vocabulary. Either keep StateClass in replication and depend direct on replication (broad but no shown cycle), or extract to schema state leaf with direct neutral value dependency; do not duplicate the enum.
