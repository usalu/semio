# BREP Native Cache Lock Assessment

Read-only inspection of the final owned BREP3 build found Cargo pid90935 waiting in cargo::core::compiler::prebuild_lock_exclusive -> LockManager::lock -> flock. A one-second sample was written only to this ticket's generated directory. The process had no active compiler children and had waited approximately twenty-five minutes. Other Cargo/rustc jobs remained active; no peer or own process was cancelled.

lsof showed the owned Cargo's deliverable lock at .🧬semio/🦑️repo/⚡️cache/cargo/debug/.cargo-lock, opened only by that process. The shared compiler locks reside separately under .🧬semio/🦑️repo/⚡️cache/cargo/build/debug/build/<package>/<unit-hash>/.lock; up to ten concurrent Cargo processes had the same unit lock files open. macOS lsof did not expose a distinguishing flock owner flag, so open descriptors alone do not identify the exclusive holder, and this report does not claim one. The sampled wait proves compiler-unit locking, rather than a wait on the owned deliverable target directory.

The repository's .cargo/config.toml explicitly places intermediate units in the shared build-dir and final uplifted outputs in target-dir. Its documented invariant is that private CARGO_TARGET_DIR changes only final deliverables while intermediates remain shared. The exact-law harness already honors a scoped CARGO_TARGET_DIR. Therefore a different owned target alone cannot bypass this observed compiler-unit contention and will still reuse the same compiled units and locks.

Meaningful isolation would also require a private CARGO_BUILD_BUILD_DIR. An empty private build directory forfeits the compiled intermediate cache and rebuilds dependencies. Copying a live shared build tree while peers are writing its metadata, fingerprints and outputs is not proven to yield a consistent reusable snapshot. No dedicated safe completed-unit clone operation was identified in the read caching owner. This worker therefore has not created an isolated build directory or duplicated/cancelled the queued law run. Parent coordination or completion of the existing shared builds remains the concrete safe path currently established.
