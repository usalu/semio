# Block Archive Dependency Boundary

The concrete Block2D ZIP import/export leaves import StdIo ZIP's snapshot, entry and codec types directly. StdIo ZIP's native container codec in turn calls StdIo Deflate's raw codec and operates on an artifact snapshot carrying the `s.stdio.zip` identity. Both dependency directions are current source facts, separate from the unused Block2D JSON edge.

General IO already declares transport `PayloadCodec`, artifact `ArtifactCodec`, bounded sources/sinks and host resource resolver contracts. It also retains a second registry family under `io_mechanism`; its source docstrings explicitly describe the old registry as retained. This is unfinished canonicalization, not an accepted compatibility design. Removing that registry requires the concrete current consumer closure rather than deleting a declaration in isolation.

The next archive extraction must separate the neutral ZIP container state/byte algorithm from the StdIo artifact identity, preserve every supported metadata/encoding policy and expose caller-owned progress/cancellation and real backing admission. A stored-only replacement or an always-successful injected codec would narrow behavior and would not satisfy the architecture goal. The remaining Block ZIP calls and the whole native production-descriptor gate therefore stay active work.
