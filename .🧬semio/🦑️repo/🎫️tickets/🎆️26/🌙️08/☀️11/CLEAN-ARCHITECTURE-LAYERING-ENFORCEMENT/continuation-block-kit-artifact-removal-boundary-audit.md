## Actual edges

The remaining 3D/5D runtime edge to2D is the catalog declaration, not a2D snapshot type: each editor imports KIT_CATALOG_ARTIFACT_ID and calls2D kit_catalog_artifact_kind. Both normal Cargo dependencies and test-serde dev dependencies still bind2D. Deleting2D therefore breaks3D/5D compilation even though their catalog payload projections remain locally authored.

The catalog function lives in2D root lines132–150 and explicitly describes itself as the Block plugin’s one catalog declaration. It returns kit.catalog identity, bilingual label, Kit×Type media, MeshOnly capability and dimension3d. The3d descriptor value describes mesh capability; moving ownership must preserve this existing descriptor field until a separately tested schema changes it. Dimension-neutral ownership does not justify silently dropping it.

The bridge is a separate semio-block-mutation-bridge executable, not the new shared schema crate. Its Cargo dependencies import all three artifacts; AGGREGATES monomorphizes Block2dSnapshot/Mutation, Block3dSnapshot/Mutation, Block5dSnapshot/Mutation and3D world transient mutation. COORDINATES hardcodes each removable artifact/subset owner. Deleting any artifact leaves an unconditional dependency and typed reference in this executable.

## Record and converter ownership

Keep dimension-neutral identity, author, attribute, representation, compatibility and metadata records in the canonical Block plugin schema owner. Camera2d/Camera3d records are dimensional leaf contracts already safely owned by the plugin; they should stay separate rather than be flattened into a guessed common camera. The kit.catalog identity and declaration belong beside a plugin-owned catalog contract, exposed explicitly from semio-s-plugin-block; all three artifact apps consume that owner. Framework media mechanisms remain General, while Block catalog vocabulary remains Specific.

The actual exported2D/3D/5D converters accept their own snapshot types and emit distinct shapes:2D portKinds/wireKinds/edgeKinds/nodeKinds plus polar handles and axes;3D objectKinds/vortexKinds/cableKinds/attractionKinds plus vector position/direction/radius and selected mesh;5D parts/grips/fasteners/ropes with separate2d/3d grip projections. They are not dimension-neutral converters. Their source-shape adapters stay in the artifact owners. Extract only output record schemas and common compatibility/representation operations that accept plugin-owned borrowed records, with explicit dimensional payload schemas. Do not move a function taking Block3dSnapshot into the plugin and thereby recreate an upward dependency.

3D also composes SemioKitSnapshot/Type from the removable stdio.semio kit artifact and keeps its vortex-kind overflow locally; retirement names that exact child owner. This is a separate composition/port boundary, not an implicit justification to move Semio stdio types into Block. A typed neutral catalog output port can use owner-qualified kit type identity and local dimensional overflow; importing an optional external artifact document remains an explicit adapter under the consuming artifact.
