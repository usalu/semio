## Concrete Gaps

1. `🧹️lint/🕸️dependency-boundaries/🟨️.cjs:267` approximates package identity using module/product families. The entire OS product becomes one family, so OS module-to-module implementation imports bypass the rule. Cross-family imports, forbidden implementation segments, and plugin SDK-only imports are warnings, so the verification gate does not enforce their elimination. Cross-technology rules filter to local dependencies; package-name aliases need canonical resolved-owner treatment. Bootstrap exemption matches every script.ts regardless of declared executable role. The scanner intentionally skips repo packages. `TECHNOLOGIES` includes opaque compose and omits teaching and semio-tech despite taxonomy having more precise area vocabulary.
2. `🧹️lint/📐️source-policy/🟨️.mjs` duplicates family roots by hand and uses sibling-name specifier heuristics. Its comments expressly acknowledge manual synchronization. It disables unused-variable checks and excludes broad OS/compose/hub/mit-bestand areas from state-authority checks. The transitional core StoragePort exclusion remains even though core is a banned taxonomy stem.
3. `📚️library/🟦️.ts:718` layering discovery counts textual occurrences of area paths rather than dependency edges. Bare npm imports, crate dependencies, aliased imports and generated registries can couple implementations without containing those strings. Comments increase counts; replacing one forbidden dependency with another while preserving the count passes the ratchet. Generated-banner skipping trusts a marker in the first 512 bytes. `🧅️layering.json` allows 138 root-script references and numerous framework/OS references, so passing layering means no count growth, not architectural independence.
4. `📜️script.ts:20269` no-glue-shim detection only scans plugin Rust package glue and only recognizes two comment phrases. A shim without those comments passes; framework/hub/other-language shims are outside scope. Root policy also retains explicit unmigrated-owner legacy branches around 22674. This conflicts with a completed no-legacy end-state.
5. Framework-specific React integration legitimately reexports React/Three types at `🖱️ui/🎯️targets/⚛️react/🟦️.tsx:112-119`; these are explicit reexports permitted by AGENTS, not evidence by themselves of a forbidden neutral-framework leak. Nevertheless `ThreeHostPort` at 192 uses typeof fiber/drei implementations, `iconRenderCameraPose` accepts THREE.Object3D at 399, and `buildIconCamera` returns THREE.Camera at 424. A nominal port does not make this owned neutral API. Keep such types confined to explicit target APIs; move cross-target contracts to owned schema types and implement adaptation internally.
6. `🖥️platform/🟦️.ts` exports Store, OsShellConfig, DockLayoutStore, DockUiStateStore and WindowPaneStateStore through the neutral framework root. This is direct OS domain coupling in a framework API, and the source-policy Store restriction would appear to reject these if its scoped override is reached. Resolve ownership rather than adding an exception.
