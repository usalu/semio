## Identity Defect And Replacement Contract

The current producer hashes `engineId UTF-8 || NUL || input`. Distinct tuples `(a\u0000b,c)` and `(a,b\u0000c)` therefore produce the same bytes `6100620063`. This is a genuine framing defect established from current source and exact bytes, not an accepted compatibility requirement. Existing IDs remain unrestricted by NUL or emptiness.

The new contract frames an unsigned 64-bit little-endian UTF-8 identity length, exact identity bytes, unsigned 64-bit little-endian input length, and exact input bytes. Two hostile tuple pairs must produce distinct preimages and keys. TypeScript must refuse lone surrogate identities because Rust String admits Unicode scalar UTF-8 strings and TextEncoder would silently replace invalid surrogates. The current Rust producer has not yet been changed or exercised against this new contract.
