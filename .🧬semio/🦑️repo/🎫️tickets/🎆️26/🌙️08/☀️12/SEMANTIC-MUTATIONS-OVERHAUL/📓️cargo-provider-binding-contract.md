# Cargo Provider Binding Authority Contract

## Released Packet

FND-CARGO-PROVIDER-BINDING-25 resolves one explicitly selected normal dependency from its consumer manifest to its real local package, explicit library target, and compiler extern name. It reuses the accepted TOML projection and no-follow workspace boundary. This is the binding authority needed by the following metadata source policy; it does not itself approve a derive or contract by spelling, turn on global policy, or implement another module graph.

The write set is the existing discovery component's Cargo-provider region, deliberate repository facade exports, a dedicated neutral fixture/schema, and focused library tests. Root reachability and its fixtures are released and must not be changed without a new demonstrated defect. Production Rust, leaf owners, taxonomy and other ongoing work are excluded. All temporary compiler/reference fixtures and evidence remain in this ticket. Root alone runs Cargo.

## Required Behavior

The input identifies the actual workspace base, exact consumer Cargo manifest locator, and selected dependency key. The output contains repository-owned explicit consumer/workspace/provider manifest locators, declared package identity, explicit library name/source locator/proc-macro status, selected dependency key, inherited-versus-local path authority, and the actual extern binding name. Invalid or unresolved evidence fails closed with a useful reason, never an invented provider.

Read only the selected consumer, governing workspace, and selected provider manifests and selected explicit library source. Cargo manifests on the already bounded consumer/provider ancestor chains may additionally be inspected solely to establish the nearest declared workspace; do not assume an ancestor workspace declaration is absent. Do not enumerate workspace members, dependency trees, Cargo caches, registries, or excluded roots. Never invoke Cargo metadata. Preserve unrelated conditional/external dependency facts without following those edges. Resolve workspace inheritance by exact key and declared workspace authority, not a name-only lookup. Reject ambiguous, target-conditional, dev-only, build-only, optional, registry/git/version-only or unsupported selected edges. Feature/default-feature controls may be accepted only as typed non-identity-changing settings; do not silently ignore unknown fields. Preserve and check package override presence even when the key and package name are identical.

Use the compiler observation in `🧪️cargo-extern-binding-preflight/📓️preflight.md`: without an explicit package override the bound name is the explicit library name; with an explicit package override it is the dependency key with hyphens replaced by underscores. Workspace inheritance preserves this distinction. Compare the effective declared package against the provider manifest package. Require an explicit valid library name and source, never a conventional-file fallback. Actual trusted metadata-provider approval later compares the exact canonical manifest/source identity as well as package and library names; this resolver must return enough evidence for that comparison, not hard-code a mutation provider allowlist.

Source locators and the native absolute workspace base are checked before any I/O, including NFC, controls/line separators, excluded case-folded `compose` components, drive/colon/backslash rules, and single file identity. Cargo dependency paths legitimately have leading `..` components: resolve them against the declaration's real directory with a bounded lexical stack, reject escape outside the workspace, and check every physical component without following symlinks. Do not normalize an excluded component or symlink detour away. The resulting provider manifest and library source remain inside that same physical workspace authority. Workspace declarations or explicit package-workspace locators must not silently be treated as the supplied root; narrowly extend the existing projection if needed to preserve those facts. No second TOML parser or regex approval path is allowed.

Use an injected repository-owned read/no-follow view only if required for virtual-path tests, with the same production path checks; do not expose external library types. Operations are bounded to the selected edge, and any broader iteration must expose cancellation. Keep output ordering deterministic and retain all evidence needed to distinguish a rejected declaration from a missing file.

## Schema-First Verification

Start with neutral expected vectors for direct, same-name package override, renamed hyphen/underscore, and workspace-inherited bindings. Cover package/library/key divergence, local sibling parents, wrong package identity, implicit library fallback rejection, optional/conditional/ambiguous/inherited conflicts, external selected edges, unrelated external edges, nested workspace disagreement, malformed TOML, missing files, and source/manifest/root/ancestor symlinks. All excluded/escaping/foreign-drive cases use a trapped virtual filesystem and assert no forbidden access. Do not create an actual excluded directory.

Compare parsed manifest facts with the existing independent TOML library. Reuse the observed six Cargo extern cases through fresh fixture inputs; root will run an additional selected compiler/runtime replay after review. Run focused registered library tests with an explicit ticket artifact root. Do not claim full Rust provider-alias resolution or active metadata policy from a passing dependency-binding test.
