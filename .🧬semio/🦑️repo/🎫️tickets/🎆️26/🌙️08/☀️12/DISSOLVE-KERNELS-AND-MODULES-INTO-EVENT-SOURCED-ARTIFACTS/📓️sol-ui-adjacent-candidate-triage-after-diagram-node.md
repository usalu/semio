# UI Adjacent Candidate Triage After Diagram Node

## Method

An active-source, path-excluded identifier scan was used only to prioritize the next bounded consumer audit. It excluded tickets/history, dependency/build caches, `compose`, hub, mit-bestand, and taxonomy legacy/exempt areas. Counts are number of matching files, not production-consumer counts and not semantic conclusions.

| Candidate | Matching active files |

`HoverCard` was selected for the next read-only audit because its closure is the smallest after the accepted removal of Card examples from the HoverCard story. No disposition is inferred from textual count alone. `Stepper` was separately rejected as a deletion candidate after direct production consumers were found in framework Tree, the React engagement renderer, and the protected OS renderer. `ActionGroup` was retained by its dedicated audit because framework Window directly renders it.
