# Wave 1 fan-out — gisterrain facet report

Facet: `✏️s/🔌️plugins/🌍️gis/🗿️artifacts/🏔️gisterrain/🏅️standards/🔖️1/🪆️subsets/✳️any/🧬️schema/🧬️mutations`
Crate: `semio-s-plugin-gis`

## Source shape (before)

`GisTerrainSnapshot` has exactly two persistent scalar fields (`exaggeration: f64`,
`imported_features_json: String`) — no id-keyed collections, no ordered lists, no relationships, no
hierarchy. The old `GisTerrainMutation` enum had three struct-variants: `SetExaggeration { .. }`,
`SetImportedFeatures { .. }`, and the banned `SetSnapshot { snapshot }` (whole-document replace),
plus three matching "leaf-shaped but actually generic" triad dirs (`🎛set-exaggeration`,
`🎛set-imported-features`, `📄set-snapshot`) that were thin apply/diff/inverse delegates back onto
the hand-written enum `impl Mutation` — not real `MutationKind` payloads.

## Derivation applied

Per `derivation-rules.md` recipe §1 (document-level scalars, no identity field on this root):

- `exaggeration` → `change-exaggeration` (verb `change`, entity `exaggeration`, record
  `ChangedExaggeration`)
- `imported_features_json` → `change-imported-features` (verb `change`, entity
  `imported-features`, record `ChangedImportedFeatures`)
- `SetSnapshot` → **deleted, no replacement**, per taxonomy's banned-vocabulary rule (whole-document
  replace has no in-history mutation).

## Triad leaves created

- `🎚change-exaggeration/{🦠️mutation,🔺️diff,↩️inverse}/🦀️component.rs`
- `📥change-imported-features/{🦠️mutation,🔺️diff,↩️inverse}/🦀️component.rs`

Each `🦠️mutation` payload struct derives `dsl::DslRecord` (needed for `dsl::DslEnum`'s tuple-variant
"newtype" delegation — the payload carries its own `#[dsl(keyword = "...")]` matching the variant's
own kebab form, otherwise `OpText::print_op`/`parse_op` round-trips break) and implements
`protocol::MutationKind<GisTerrainSnapshot, GisTerrainMutation>` with a real `SEMANTICS` const;
`diff`/`inverse` delegate to the sibling `🔺️diff`/`↩️inverse` leaf functions, which delegate in turn
to the pre-existing handcrafted `diff_exaggeration`/`diff_imported_features_json` sparse-diff
builders in `🔺️diff/📝️text/component.rs` (kept — still real, still used, unrelated to the banned
`SetSnapshot`/`diff_set_snapshot` path which stays for the Diff type's own whole-artifact-override
absorb test, unrelated to the Mutation enum).

Old dirs `🎛set-exaggeration`, `🎛set-imported-features`, `📄set-snapshot` deleted entirely.

## Dispatch rewrite

`🧬️mutations/🦀️component.rs`'s `GisTerrainMutation` enum is now two single-field tuple variants:
`ChangeExaggeration(change_exaggeration::mutation::ChangeExaggeration)` /
`ChangeImportedFeatures(change_imported_features::mutation::ChangeImportedFeatures)`, deriving
`dsl::DslEnum` (kept, for the facet's already-handcrafted `OpText`/`OpBinary` impls which need
`DslVariants`) **and** `dsl::Mutations` (`#[mutations(snapshot = GisTerrainSnapshot, diff =
GisTerrainDiff, schema = "gis.gisterrain")]` — used the crate's existing `dsl` alias for the derive,
not a direct `dsl_derive` dependency, since `semio-s-plugin-gis`'s `Cargo.toml` only depends on
`semio-framework-os-kernel` (aliased `dsl`/`protocol`/`pack`/`store`/`vcs`), which re-exports
`Mutations` at its root). Hand-written `impl Mutation<GisTerrainSnapshot> for GisTerrainMutation`
(the old `diff`/`inverse` match) deleted — generated by the derive now. Kept
`apply_gis_terrain_mutation`/`inverse_gis_terrain_mutation` (still used by the `🏗️builder` and
`📝️text` re-export) and the `GisTerrainEnvelope`/`GisTerrainStore` type aliases.
