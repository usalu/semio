# Wave 0 Remediation Barrier

## Purpose

Wave 1 remains blocked until a frozen combined tree satisfies every item below. A directory, source file, exported namespace, or registered name is never evidence that a standard, codec, inference, or mutation is implemented.

## Definition and identity

- [ ] Exactly 36 stdio artifact definitions exist and exactly one definition is assembled for each catalog artifact.
- [ ] Each artifact definition owns plural standards, profiles, source dialects, representations, codecs, mutations, inferences, resources, localizations, and conformance suites.
- [ ] Every public identity uses the canonical `s.stdio.<artifact>` hierarchy with singular namespace segments.
- [ ] Invalid, duplicate, aliased, or conflicting artifact, standard, profile, dialect, representation, codec, inference, mutation, MIME, and extension identities reject with typed errors.
- [ ] Identical registration is idempotent only when metadata and executable identity are equal.
- [ ] EPW has no registered MIME claim; TXT alone owns `text/plain`.

## Assembly and open/closed behavior

- [ ] Plugin assembly preflights all declarations through one deterministic registry before setup or global registration performs any side effect.
- [ ] The assembly boundary returns a typed result and does not panic, assert, clamp, overwrite, or silently retain an earlier registration.
- [ ] Adding a definition or capability leaf changes only its definition and assembly list, never a capability-kind dispatch switch.
- [ ] Stdio assembles all 36 definitions once and contains no duplicate PDF or legacy artifact-kind-only registration.
- [ ] TypeScript exports executable definition data and validation, not empty namespaces.

## Ledger honesty

- [ ] The ledger is derived from schema-owned artifact definitions rather than filesystem path or component-file discovery.
- [ ] No reported codec count includes an unregistered import/export path or IO file.
- [ ] Every ledger entry records normative source, publication date, source checksum, redistribution status, clauses/features, profiles, registered code points, read/write/lossless/canonical status, validators, mutations, inferences, and fixtures.
- [ ] Unknown, proprietary, incomplete, and future-wave support remains explicitly unimplemented or opaque; it is never counted as decoded support.
- [ ] Catalog, manifest, dependency graph, localized descriptors, Rust assembly, TypeScript assembly, and gates consume one definition authority without a second hand-maintained roster.

## Codec and resource runtime

- [ ] Decode and encode execute through host-owned finite read, work, allocation, and recursion budgets plus cancellation checks.
- [ ] Streaming and random-access operations are budgeted; resource resolution is present in both decode and encode contexts.
- [ ] Source spans validate their ranges, and lossless results retain owned anchored lexical and opaque records.
- [ ] Canonical encoding is an executable policy/result property rather than an enum without enforcement.
- [ ] IO fallback, subset validation, child-store factories, dialect migrations, document codecs, and all newly touched registries return typed conflict or availability errors.

## CQRS and projections

- [ ] Every mutation is validated before inverse construction, apply, replay, or event persistence.
- [ ] Malformed reset/checkpoint history returns a typed rejection and cannot panic.
- [ ] Empty checkpoint and prune behavior has explicit typed semantics and never reports a misleading success.
- [ ] Apply, remote ingest, replay, undo, redo, reset, checkout, policy change, external-resource change, checkpoint, and prune transitions use one projection freshness/invalidation seam.
- [ ] Stale inference results are rejected for every covered transition.

## Native and WIT inference boundary

- [ ] Requests carry artifact revision/generation, source dialect, policy, finite budgets, cancellation identity, previous inference state, and requested cache mode.
- [ ] Results carry canonical payloads, typed diagnostics, provenance, validity, quality, and actual cache behavior.
- [ ] Cold and incremental execution use the same registered service boundary.

## Evidence

- [ ] All permanent commands route through `bun` and `nx` into the relevant `📜️script.ts`; launch entries contain no embedded `bun -e` implementation.
- [ ] Runtime, fuzz, and cross-platform targets either execute their named evidence or fail explicitly as not closed.
- [ ] Current combined-tree Rust and TypeScript Nx gates compile and run; historical or partial-tree reports do not count.
- [ ] Three independent frozen-tree Luna audits report no Wave 0 P0 finding.
- [ ] Scoped diff hygiene passes without modifying unrelated user work or any `AGENTS.md`.

## Deferred artifact work

Removing the program-wide generic `Set*`, `SetSnapshot`, `NoMutation`, collection-command, aggregate-inference, and empty TypeScript debt is not misreported as Wave 0 completion. Wave 0 must make the registries and definition authority capable of representing the correct leaves. The artifact-family waves then replace every offending leaf and must pass the final zero-debt policy gate before program closure.
