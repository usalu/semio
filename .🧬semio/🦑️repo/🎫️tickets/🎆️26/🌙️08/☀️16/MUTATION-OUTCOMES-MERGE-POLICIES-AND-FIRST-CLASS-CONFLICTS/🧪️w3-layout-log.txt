DEVIATION (reorder-pages): the worker-brief's generic reorder rule ("Fatal mutation.invariant if the
order list is not a permutation") assumes an explicit order-list payload (like dag's reorder_nodes).
Layout's ReorderPages payload is `{id, to_index}` — a single-item move, not an order list — so there is
no way for it to produce a non-permutation result; the existing diff logic already clamps to_index into
range. Implemented only Error target-missing + Warning no-op (order unchanged after the move), no Fatal
branch. The required "assert_fatal_never_applies" OutcomeLaws coverage uses create-page's duplicate-id
case instead (contract explicitly allows "create-duplicate-id OR reorder-non-permutation").
