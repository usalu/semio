## resume-path design

`Command(bytes)` resumes through the ALREADY-EXISTING `PluginApp::handle_command_frame` (Elm's Msg-from-Cmd: re-decodes as `A::Command` via `OpBinary`, re-enters `ArtifactApp::handle` against CURRENT state) — no new trait method needed for this half. `Emit(Emit<M,C,D>)` resumes through the NEW `PluginApp::resume_task_emit`, which decodes the wire-encoded mutation-lane triple (produced at resolution time inside `spawn_task`'s completion wrapper, via the SAME `protocol::encode_ops_vec`/`OpBinary::encode_op` idiom `dispatch_emit`'s own `last_emit_wire` uses) and calls `dispatch_emit` directly — `effects`/`events`/`child_emits`/`tasks` on that `Emit` are intentionally NOT honored (documented on `TaskResolution::Emit`'s own doc: use `Command` if the follow-up needs those). Both paths converge on `plugin_runtime::plugin_resume_task`, which frames the `InvocationResult` as `AppFrame::Emit` (reusing `take_last_emit_wire()` — the SAME shape `AppCommand::PureCommand` already produces) and returns the same `(frames, effects, events)` shape `PluginExchangeOutput` does. `⚛️reactor::drain_task_resumes` feeds `frames` through the EXISTING `route_app_frame` — no second frame-routing implementation.

## quota + cancellation semantics

Quota: `Event::InstanceOpen.quotas` is now actually decoded (`wit_event_to_kernel`'s `InstanceOpen` arm previously hardcoded `QuotaSchema::default()` — real bug, fixed) and stored per-instance in `INSTANCE_QUOTAS`; `spawn_task` counts live `TASK_RECORDS` for that instance against `outstanding_requests.unwrap_or(16)` BEFORE key-dedupe (matches the brief's stated order — a same-key respawn exactly at quota legitimately fails rather than being special-cased). Exceeding it returns a typed `Fault` (`plugin.task.quota-exceeded`) that `dispatch_emit` propagates with `?`, failing the whole dispatch.

Key-dedupe: `spawn_task` looks up `TASK_KEYS[(instance,key)]`; if live, `EXECUTOR.cancel(old_id)` (drops the future, never polls it again) before spawning the new one.

`Event::InstanceClose`: the kernel `Event::InstanceClose` (SSOT, `🎠️kernel`, NOT owned by this packet) carries no instance id, so `poll`'s loop peeks the RAW WIT payload (`WitReactorEvent::InstanceClose(ref payload)`) before calling `wit_event_to_kernel`, avoiding any need to widen the shared kernel type. Two steps, in order: `cancel_instance_tasks(instance)` (drops every owned task's future — and with it, any parked `RequestFuture` that future held, since a `RequestFuture` is only ever created inside a task's own `TaskCtx.host`) then `REGISTRY.cancel_instance(instance)` (defense-in-depth registry sweep — should remove 0 given step one, exercised as such in the test).

## honest gaps

1. **Nothing here is compiler-verified.** Rule 4 is absolute and I respected it, but that means every claim about generic bounds, closure-return-type inference (`AsyncTask::<M,C,D>::new(label, |ctx| async move { ... Ok(TaskResolution::Done) })` — Rust needs to infer `TaskResolution::Done`'s generics from the surrounding `new::<F>` bound), and trait-object coercion (`Box::new(move |ctx| Box::pin(run(ctx)))` coercing to `Box<dyn FnOnce(..) -> Pin<Box<dyn Future<...>>>>`) is a careful manual read, not a proof. `rustfmt --check` parsing cleanly is real evidence against gross syntax breakage but says nothing about types. This is exactly the S1 spike risk the brief named; I used the direct typed `AsyncTask`/`Emit` design throughout (never fell back to `ErasedAsyncTask`) because every construction site I could find already threads `A::Mutation`/`A::ConfigMutation`/`A::DraftMutation` through comparable generic contexts (`dispatch_emit` itself, `Emit`'s existing builders) without issue — but I cannot rule out a genuine inference failure at one of the closure call sites until this builds.
2. **`drain_task_resumes`'s wasm-gated tail (`route_app_frame`, effect/event decode) is untested natively.** My tests exercise everything up to and including `plugin_resume_task`'s `PluginExchangeOutput`, decoding its `frames`/`document_ops` by hand — the actual `route_app_frame` call that turns those bytes into `UiPatch`/`Effect::SendMessage` inside a real `poll()` turn is not exercised by anything I wrote (it would need a `wasm32-wasip2` build).
3. **`TaskResolution::Emit` drops `effects`/`events`/`child_emits`/`tasks`** on that inner `Emit` — deliberate scope narrowing (documented on the type), but means a task that wants to also fire a host effect on its follow-up must use `TaskResolution::Command` instead, re-entering full `handle()`.
4. **No rollback if `spawn_task` faults after mutations already applied.** `dispatch_emit` spawns tasks AFTER the mutation lanes commit; a quota fault at that point fails the dispatch's `Result` but does NOT undo the already-applied `self.store`/`self.config_store`/`self.draft_store` mutations. Documented inline; a caller needing atomicity across "mutate AND spawn N tasks" must keep its task count under quota itself.
5. **Did not exhaustively grep all ~30 plugin crates** for a hand-enumerated `Emit { ... }` struct literal lacking `..Default::default()` (which would fail to compile against the new `tasks` field) — spot-checked every occurrence inside `🔌️plugin/🦀️component.rs` itself (all use the spread), but a plugin crate elsewhere in the fleet constructing `Emit` without the spread is a real, if low-probability (the SDK's own builder functions are the documented idiom), possibility I could not rule out given rule 4.
6. **`checkpoint_then_restore_requeues_a_restartable_tasks_command_as_a_resume`'s final assertion is a sanity check, not a full restore proof** — it dispatches the SAME command directly against a FRESH `TestApp` rather than driving a complete `checkpoint::restore` instance round-trip (that round-trip is `📸️checkpoint`'s own, separately-tested job); the test's actual subject (that `restore_now` requeues the exact restart bytes onto `TASK_RESUMES`) IS asserted directly and precisely.
7. **`AsyncTask.label` is diagnostic-only** — no telemetry or checkpoint surface reads it back yet (named in `TaskRecord`'s own doc comment, `#[allow(dead_code)]`).
