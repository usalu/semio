# H-GENERATED-REF — Generated Outputs and Reference Adapters

## Scope and safety

Read-only audit against the current shared working tree and the end-to-end taxonomy normalization plan. No production, schema, test, manifest, Git, `compose/**`, or `temp/compose/**` state was changed or traversed. No generator was executed. Counts below exclude the ticket tree, common build/cache trees, and the two opaque prefixes.

Applicable instructions read: root `AGENTS.md`, `🧰️framework/🛍️products/AGENTS.md`, `🧰️framework/🛍️products/🦑️repo/AGENTS.md`, `🧰️framework/🛍️products/💻️os/AGENTS.md`, `✏️s/AGENTS.md`, `🧰️framework/🔨️modules/🖱️ui/AGENTS.md`, and `🧰️framework/🔨️modules/🖼️assets/AGENTS.md`.

## Executive findings

1. The normalization schema already exposes `TaxonomyRegeneration` and `TaxonomyPlan.regenerations`, but `planTaxonomy` always emits an empty array. Apply can run a supplied regeneration command, yet the plan cannot express deterministic inputs, expected output bytes, stale removals, output modes, or a verification command.
2. Generated output is materially under-inventoried. The engine inventories Git-index files plus non-ignored untracked files. A focused census found 593 files under twelve ignored `🤖️generated` roots alone; these cannot participate in inventory, reference resolution, planning, or post-state verification.
3. The current reference-token implementation covers one narrow syntax per advertised adapter. Major plan-required forms—Rust `mod`, side-effect TypeScript imports, Go work/module directives, TOML arrays, solution project lines, CMake commands, raw-HTML links, CI/launch embedded command paths, and generator/template ownership—are absent.
4. Unsupported syntax normally produces no token and therefore no `unresolved` record. This is not fail-closed. A moved file can retain a stale reference without the plan knowing it exists.
5. The smallest sound extension is a schema-owned generator contract keyed to an Nx target, a deterministic regeneration record containing exact input/output preimages and expected outputs, and explicit unsupported-reference findings. Generated files must be regenerated from their source/template owner rather than edited directly.

### Failure mode

`buildReferenceEdits` emits edits only for recognized tokens that resolve to a planned move. A recognized incoming reference to a moved binary/generated-role file can become `opaque-reference-rewrite-unresolved`, but an unrecognized textual form simply does not exist in the reference graph. Consequently, Rust `mod`, side-effect imports, solution lines, CMake commands, and embedded launch commands can remain stale without any `unresolved` entry.

## Current regeneration/apply gaps

- `planTaxonomy` assigns `regenerations: []` unconditionally.
- `TaxonomyRegeneration` contains only `id`, `cwd`, `command`, and `outputs: string[]`.
- Source/affected tree digests cover moves and edits, not regeneration inputs or outputs.
- Apply backs up declared output files, runs `execFileSync(command[0], args)`, and records completion. It does not verify expected bytes/modes, enumerate new outputs, remove stale outputs, reject undeclared outputs, or run a freshness target.
- Backup accepts files/symlinks, not output directories. A generator-created undeclared file can survive rollback.
- The command is arbitrary argv rather than a schema-owned Nx target.
- Generator order/dependencies and overlapping output ownership are not represented.
- The graph generator currently scans the workspace while skipping common generated/build directories, but does not enforce the opaque-prefix exclusion. It must not be invoked by normalization until it consumes the same exclusion contract.

## Smallest deterministic contract

Add one schema-level registry; do not infer ownership from banners or directory names:

```ts
type TaxonomyGeneratorContract = {
  id: string;
  ownerPath: string;
  target: string;                 // exact Nx project:target
  checkTarget?: string;
  inputPatterns: readonly string[];
  outputRoots: readonly string[];
};
```

Contracts must have one owner per output, stable IDs/order, non-overlapping output roots, existing Nx targets, and no output/input roots crossing an excluded opaque tree. The engine derives argv as `['bun', 'nx', 'run', target]`; schema data must not contain arbitrary shell commands. Existing semantic manifests and Nx `outputs` should be normalized into this registry rather than consulted ad hoc.

Extend the planned record just enough to make bytes and rollback deterministic:

```ts
type TaxonomyRegeneration = {
  id: string;
  contractId: string;
  cwd: string;
  command: readonly ["bun", "nx", "run", string];
  inputs: readonly { path: string; expectedHash: string }[];
  outputs: readonly {
    path: string;
    preimageHash: string | null;
    expectedHash: string;
    mode: number;
  }[];
  removedOutputs: readonly { path: string; preimageHash: string }[];
  verifyCommand?: readonly ["bun", "nx", "run", string];
};
```

The output list/hashes must come from an isolated preview using the same generator target or a generator-owned deterministic manifest/dry protocol. They must not be predicted by path heuristics. Include regenerations in canonical plan bytes, `planDigest`, expected post-state digest, and actual verification digest.

Planner behavior:

1. Match every known generated output to exactly one contract; ambiguous, missing, external, or opaque-crossing ownership becomes `unresolved`.
2. When a move/edit affects a generator input, template, or generated reference, schedule the owner. Edit the source/template only; never create direct reference edits in generated outputs.
3. Preview in dependency order, capture exact produced paths/hashes/modes and stale removals, then stable-sort records and paths.
4. Add an explicit unsupported-reference finding for path-bearing syntax in affected files; lack of a parser must not mean lack of a reference.

Apply behavior:

1. Verify input and output preimages, back up the complete output-root union, and record absent paths.
2. Run the exact Bun/Nx argv without a shell, with cancellation and progress between generators.
3. Reject missing, byte-different, mode-different, stale, or unexpected outputs; run `checkTarget` when registered.
4. Include generated outputs in post-state verification.
5. On any failure/cancellation, restore modified/removed outputs and delete all newly created outputs. No undeclared path may survive rollback.

Recommended first pilots are UI styling tokens (multi-language manifest-owned outputs) and plugin registry (existing exact freshness check plus `.vscode/launch.json`). The graph generator must remain unresolved until its scan accepts and enforces the opaque-prefix contract. The ownerless UI icon duplicate, external STEP files, setup-wizard config, and root generated declarations must remain explicit unresolved items rather than guessed owners.

## Acceptance checks

- Identical input produces byte-identical canonical plans, regeneration order, output enumeration, and `planDigest` across worker counts and platforms.
- A styling token/template rename plans one source edit plus one regeneration; it does not directly edit generated CSS/TS/.NET/Rust/Python files.
- Plugin-registry source changes regenerate and verify both registry outputs and `.vscode/launch.json`.
- One extra stale output, one missing output, one wrong byte, and one wrong mode each fail verification.
- Generator failure, check-target failure, cancellation, and every apply failure stage restore prior outputs and remove newly created outputs.
- Missing owner, overlapping owners, unsupported generator target, and opaque-crossing generator each fail closed as stable `unresolved` records.
- Ignored generated outputs are included through registered output ownership without broadening normal inventory to arbitrary ignored files.
- Permanent adapter regressions cover the missing representative forms above: Rust `mod`; TS side-effect import; Cargo/pyproject TOML arrays; `go.work use`/`go.mod replace`; `.sln` project paths; CMake commands; raw-HTML links; CI/launch embedded argv paths; generator/template references.
- An unsupported path-bearing form affecting a move produces an unresolved diagnostic with adapter, structured location, and source token.
- No preview, generator, check, inventory, or rollback operation reads or writes an excluded opaque prefix.
- After successful apply/regenerate/check, a second inventory and plan are empty, including `regenerations` and stale-output findings.

## Conclusion

The current implementation has useful scaffolding—adapter IDs, structured edit records, regeneration records, rollback journaling, and two existing generator freshness checks—but it does not yet meet plan §6 for reference coverage or plan §5 for deterministic generated state. Schema-owned Nx generator contracts, exact planned output bytes, generator-first edits, and fail-closed unsupported-reference findings are the minimum coherent addition. Expanding regexes alone would leave ignored outputs, stale generated files, rollback, and semantic package/build resolution unsolved.
