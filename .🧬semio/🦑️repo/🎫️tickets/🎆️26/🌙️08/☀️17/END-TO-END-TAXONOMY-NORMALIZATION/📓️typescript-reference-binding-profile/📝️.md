# TypeScript Reference Binding Profile

This bounded diagnostic measures a redundant lexical lookahead on the actual TypeScript variable-reference regex identified in the earlier CPU profile. It changes no production source or exported API. The TypeScript parser locates the actual third regex inside `typescriptTokens`; the candidate keeps that entire pattern and its flags, adding only a necessary identifier/assignment/quote prefix condition. Every accepted original match necessarily has that prefix, so the experiment must preserve the complete match offsets, captures, and order rather than merely token counts.

The authored language-neutral cases include nested quoted code, dollar-bearing identifiers, Unicode case folding, comments, multiline whitespace, empty or mismatched quotes, and type annotations. Four exact live inputs are read through no-follow checks. Eleven rounds alternate original/candidate order in the same process; before/after file hashes remain observational because other tasks may edit discovery concurrently. This is a regex attribution experiment, not end-to-end performance acceptance. No production edit, Compose traversal, plan application, or repository Git mutation is performed. SIGINT cancellation is checked between bounded synchronous operations.

The first identifier-class lookahead failed the authored Unicode case before live-input timing: the actual Bun regex accepted `ſource = 'a.ts'`, while the candidate did not. Its repeat diagnostic confirmed the exact removed match at offset 6. The proposal was rejected without touching production. The revised necessary prefix condition uses only delimiter exclusions, avoiding a second character-class case-folding assumption; it still leaves the entire original pattern and flags intact.
