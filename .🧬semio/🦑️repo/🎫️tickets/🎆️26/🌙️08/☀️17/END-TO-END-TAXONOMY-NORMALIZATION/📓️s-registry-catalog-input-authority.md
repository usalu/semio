## Projected-state preview

The actual producer test first demonstrated that a source `🟦️component.ts` to canonical `🟦️.ts` move changes owner maturity and generated bytes. Pre-move physical preview alone was therefore insufficient.

The schema now declares `registry-projected-inputs-v1` with a 64 MiB input limit and 200,000-operation limit. The normalizer sends exact leaf moves, post-edit bytes, and retired leaves through stdin. A shared read-only view projects new ancestor membership and routes moved content to its physical source. All producer catalog reads and launch-seed reads use that one view. Unsupported shape, path escape, opaque paths, duplicate moves, occupied destinations, source drift, invalid base64, missing edit targets, and symlink ancestry fail closed.

Preview uses direct bounded subprocess capture with an explicit inventory-root environment, a 60-second timeout, bounded output, and cancellation checks. Stdin is read in bounded chunks. It creates no physical capture files. There is no runtime old-name fallback.

The real producer transaction fixture copies only the exact static source dependency closure into its isolated ticket workspace. Its package binding resolves to that fixture, not to production. It runs real Nx `generate` and `check-generated` targets. The fixture moves two leaves, including a Cargo manifest and owner maturity implementation, across `⚙engine` to `⚙️engine`; injects rollback after edits; retries; commits; proves the old source owner was pruned; checks generated bytes again after pruning; and obtains an empty second plan. No ghost old-owner catalog remains.
