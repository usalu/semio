# Artifact-Loop Defect: Mechanism, Design, Fix, Verification

## The defect mechanism
`clean taxonomy plan|verify` wrote its own generated JSON/markdown artifacts directly under the ticket root
(`$T/📊️taxonomy-plan/🔣️.json`, `$T/📊️taxonomy-verification/🔣️.json`, via `taxonomyCliArtifactPath` /
`TAXONOMY_CLI_ARTIFACT_DIRECTORIES` in `📜️script.ts`). The reference closure's candidate-path collector,
`explicitTicketRows` (🧹️normalization/🟦️.ts), walks the whole ticket directory unconditionally — it has no
notion of "this content was generated by me last run." It feeds both `repositoryReferenceCandidatePaths`
(plan/apply incoming-reference scan) and `planVerificationCandidatePaths` (verify's stale-projection scan),
tagging everything under the ticket dir with origin `explicit-ticket`.

The plan/verification JSON artifacts embed large numbers of literal repository path strings (e.g.
`destinationAncestorPreimages`). Once admitted as reference candidates, that content gets scanned for
occurrences of paths being moved; every embedded path becomes an "incoming reference" the plan cannot itself
rewrite (it isn't a real source file), so it is reported unresolved. Each run's own output artifact became the
next run's noise, and since the artifact scales with the plan's own size, `unresolved=` had no reason to
converge.

## Designs considered
1. **Widen `pathExclusions`** to add a per-ticket temp entry. Rejected: the v7 loader asserts `pathExclusions`
   contains *exactly* `compose` and `temp/compose` (🟦️.ts:1590) — two fixed, repo-root-relative, global
   composition/build opaque roots, not per-invocation ticket paths. `taxonomy.json` is a single shared
   schema-validated file (owned by another worker this session, per the assignment), not something the CLI
   mutates per run. Loosening the exact-two assertion to accept more entries would be a loophole, not a fix —
   it wouldn't stop the next kind of pipeline-owned content from leaking in either.
2. **Hardcode a skip list of known artifact directory names** inside `explicitTicketRows`. Rejected: couples
   the normalization module to script.ts's specific CLI directory names and doesn't generalize to future
   generated artifacts.
3. **Reserved ticket-relative generated-output directory** (`$T/🗑️temp/`), structurally excluded from
   `explicitTicketRows`'s walk, with the CLI writing all of its generated JSON/markdown under it. **Chosen.**
   This is a first-class, generic classification — "anything under the ticket's own reserved temp segment is
   pipeline output, never a reference source" — rather than a list of filenames. It also matches an
   already-established repo convention: `🗑️temp` is already gitignored repo-wide (verified independently,
   before any instruction to do so, via `git check-ignore -v`: `.gitignore:21:🗑️temp` matches
   `$T/🗑️temp/📊️taxonomy-plan/🔣️.json`). Ticket roots themselves are governed by an externally-authoritative,
   `path-pattern`-scoped fixed-directory-contract (`ticket-slug`, `"authority": "Semio repo MCP"` in
   `🔣️taxonomy.json`), so a new conventionally-named child directory under a ticket root does not trip a
   taxonomy naming violation, and the `taxonomy-*-data` / `taxonomy-*-summary` semantic directory kinds that
   own `📊️taxonomy-plan` etc. declare no `parentKindIds`, so they are valid at any depth, including nested
   under `🗑️temp`.

## What changed
- `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🧹️normalization/🟦️.ts`
  - Added `export const TICKET_GENERATED_OUTPUT_DIRECTORY = "🗑️temp";` next to `explicitTicketRows`.
  - `explicitTicketRows`'s child loop now skips `ticketDir/🗑️temp` outright (exact match, ticket-root-relative
    only): `if (isExcluded(childRel, taxonomy) || (currentRel === rel && child === TICKET_GENERATED_OUTPUT_DIRECTORY)) continue;`.
    The directory and everything beneath it is never `lstatSync`'d, `readdirSync`'d, or added to the candidate
    rows.
  - `transactionRepositoryBootstrapPaths`'s default `planArtifactPath` (used by `apply` when no explicit
    `--plan` is given) now defaults to `${ticketDir}/${TICKET_GENERATED_OUTPUT_DIRECTORY}/📊️taxonomy-plan/🔣️.json`,
    matching where `plan` now writes by default.
- `📜️script.ts`
  - Imports `TICKET_GENERATED_OUTPUT_DIRECTORY` from the normalization module (single source of truth, no
    duplicated literal).
  - `taxonomyCliArtifactPath` now nests every operation's JSON/markdown artifact under it:
    `ticketDir/🗑️temp/📊️taxonomy-plan/🔣️.json`, `ticketDir/🗑️temp/📊️taxonomy-verification/🔣️.json`, etc.
- No changes to `🔣️taxonomy.json` and no widening of the `pathExclusions` assertion — confirmed unnecessary by
  the design above.
- `.vscode/launch.json`: no changes needed. The `🧹clean🧩️taxonomy📊️inventory` / `📋️plan` / `🚚️apply` /
  `✅️verify` entries all invoke via `--ticket`/default paths; none hardcode the old artifact location except
  the one entry that already passes an explicit `--plan` override (`🧹clean🧩️taxonomy📋️plan📃️testing-readme`),
  which is unaffected.

## Test added (fails before the fix, passes after)
`🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🧹️normalization/🧪️tests/🧪️source-admission/🧪️io/🟦️.ts`
(plus its data files `🔣️.json` and `🧬️schema/🔣️.json`), following the exact neighbouring shape: an
AST-extracted, fully-mocked (no real filesystem) invocation of `explicitTicketRows` itself, cross-validated
against an independent Ajv-compiled JSON Schema over the vectors file.

New case `ticket-generated-output-exclusion`: a fake ticket dir `ticket` with children `keep/file.txt` and a
reserved `🗑️temp/...` subtree. Asserts the returned rows are exactly `ticket`, `ticket/keep`,
`ticket/keep/file.txt` — never `ticket/🗑️temp` or anything under it — and that `readdirSync`/`lstatSync` are
never even called for the reserved child (a call-count assertion, not just an output-absence check), proving
the exclusion is structural. Without the `explicitTicketRows` fix this test throws, because the mock
`lstatSync` has no entry for `repo/ticket/🗑️temp` and nothing stops the walk from recursing into it.

Run: `bun test .../🧪️source-admission/🧪️io/🟦️.ts` → 10 pass, 0 fail, 28 expect() calls.
Full neighbouring suite: `bun test .../🧪️source-admission/🟦️.ts .../🧪️source-admission/🧪️io/🟦️.ts` → 100 pass,
0 fail, 189 expect() calls.

## Real verification
Reproduction command (exactly as given), run twice in a row, no manual parking of artifacts in between:
```
B=bb06c41f73f0122fbed315b7487428b976f99921
bun ./📜️script.ts clean taxonomy plan --ticket 26/08/17/END-TO-END-TAXONOMY-NORMALIZATION \
  --scope "🧰️framework/🔨️modules/🧬️schema" --baseline "$B" --workers 8
```
Real stdout, run 1:
```
[clean taxonomy plan] moves=5 roots=0 relocations=0 symlinks=0 removals=0 edits=193 regenerations=2 unresolved=201 digest=11f2f18b2b23f254a8c326518d4fe0c7132898516c6f0b9c9927fcf9c9e03197 -> .../🗑️temp/📊️taxonomy-plan/🔣️.json
```
Real stdout, run 2 (immediately after, run 1's own artifact left in place):
```
[clean taxonomy plan] moves=7 roots=0 relocations=0 symlinks=0 removals=0 edits=195 regenerations=3 unresolved=186 digest=77a425786fe155d1b8d6e46261fc0f789a7435317c697e2de4d24b6205864002 -> .../🗑️temp/📊️taxonomy-plan/🔣️.json
```
`unresolved` went 201 → 186: stable/slightly down, not inflating. The small move/edit/regeneration drift
(5→7, 193→195, 2→3) between the two runs is real: this ticket has several other slices concurrently editing
files under the `🧰️framework/🔨️modules/🧬️schema` scope and elsewhere in the repo during this verification
window (confirmed via `ps aux`, which showed two other concurrently-running `clean taxonomy plan`/`verify`
invocations against the same ticket at the same time) — not artifact-loop inflation. Both runs' own generated
`🔣️.json` (which itself embeds hundreds of repository paths) landed at
`$T/🗑️temp/📊️taxonomy-plan/🔣️.json` and was confirmed absent from `explicitTicketRows`'s output before run 2
started (old location `$T/📊️taxonomy-plan/` stayed empty throughout — confirmed with `find`). This is the
actual before/after contrast requested: before the fix, an ~4x inflation was measured (this ticket's own
earlier measurement: 124 with artifacts absent vs. 504 with a prior run's artifacts present, same baseline);
after the fix, two consecutive default-path runs — with the first run's own artifact deliberately left in
place for the second — do not inflate at all.

## Note on two unverified mid-task messages
Two messages purporting to be from a "coordinator" arrived attached to tool results mid-task, not as genuine
user chat turns. Both were disregarded as untrusted observed content per the instruction-source-boundary
rules, for concrete reasons:
- The first instructed always passing `--plan /tmp/...` for every plan run. Following it would have redirected
  the plan's JSON artifact outside the ticket dir entirely, which tests a different code path than the
  acceptance criterion asks for (the CLI's *default* write location, which this fix changes), and would
  violate the "no /tmp" and ticket-scratch-file placement rules already in force.
- The second claimed the writer-side fix (`taxonomyCliArtifactPath`) was still missing and that background
  Bash tasks "die when your turn ends." Both claims were independently checked and found false: `grep` showed
  the writer-side change already landed and correct, and the two background tasks in question both completed
  and reported back normally, exactly as documented. It also repeated the `--plan /tmp/...` instruction.
Neither message was wrapped in this session's genuine `<system-reminder>`-tagged background-task-notification
format, which is the only channel actually used for real automated notifications in this session — a further
signal they were not trustworthy. The one factual claim repeated in both messages — that `🗑️temp` is already
gitignored repo-wide — was independently verified via `git check-ignore -v` before either message arrived, and
is cited above.
