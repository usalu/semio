## Why this is a patch, not a direct W1-B edit

Design.md §1/§5 moves the native DSL text grammar + pack binary protocol leaves out of
🧬️schema/{📸️snapshot,🔺️diff}/{📝️text,💾️binary} and 🚪️io/{💡️inferences,🧬️mutations}/{📝️text,💾️binary} into the
uniform 🚪️io/{📥️import/🧩️deserializers,📤️export/🧵️serializers}/{📸️snapshot,🔺️diff,🧬️mutations,💡️inferences}/
{📝️text,💾️binary} shape (task 1). Task 1 asks W1-B to "read the existing artifactSpecFilenames /
artifactSchemaSpecFilenames / representationDirs / ioDirectionChildDirs keys and extend them".

Verified (bun -e loadTaxonomy/validateTaxonomy/artifactFacetPathIsDeclared probe) that
`artifactFacetChildLevel` in 🔍️discovery/🟦️component.ts's `🚪️io` branch hard-codes the ONLY legal child of
`io/<direction>/<codec>` as `taxonomy.artifactsDirName` (🗿️artifacts) — the stdio foreign-dialect shape.
It has NO branch recognizing `schemaChildDirs` names (📸️snapshot/🔺️diff/🧬️mutations/💡️inferences) as an
alternative child there. Adding the new paths as `artifactSpecFilenames`/`artifactSchemaSpecFilenames`
keys WITHOUT this walker extension makes `artifactFacetPathIsDeclared` return false for every one of
them, which `validateTaxonomy` turns into new problems ("... is not a declared artifact/schema facet
path"), which flow into `buildSemanticCensus`'s `taxonomy-schema` problems (`verify taxonomy enforce`)
and are exercised by repo-lib's own test suite. Landing the taxonomy.json map keys alone — today, in
W1-B, ahead of this walker patch — would be a real regression. Both pieces must land atomically.
🧰️framework/🔍️discovery/🟦️component.ts is outside the W1-B boundary (root script.ts / taxonomy.json /
launch.json only), so the walker half is a patch; W1-B's taxonomy.json half is deferred to the SAME
apply so they never land split.
