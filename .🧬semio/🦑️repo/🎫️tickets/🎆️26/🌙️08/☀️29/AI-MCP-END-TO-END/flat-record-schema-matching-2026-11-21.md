# Flat Record Schema Matching

Derived non-tuple records without flattened fields now pass a static slice of `NativeSchemaLeaf` to `NativeRecordMatcher::new_flat`. The entries preserve the same wire names, ordinal values, and declaration order as the general descriptor table. Flattened record and union descriptors continue through the general stack constructor. Tuple and enum generation use their original paths.

The matcher starts and binds the genuine key projection through the same Source, Work, acknowledgement, and construction actions. Once bound, the flat route reads the current static descriptor under the existing metered comparison action. Each invocation inspects at most 64 name bytes, charges actual compared bytes and writes, and advances or retains its cursor only after the grant and Work checks. A first match keeps its root field index while subsequent descriptors are checked. A second match publishes ambiguity. Ordinals have the same matching and ambiguity rules without a name-byte comparison. The derive still handles unknown keys, subset mode, and duplicate incoming assignments at its existing paid output boundary. Closing the flat cursor uses the original key/projection retirement and does not acquire traversal storage.

For a full pass over `N` short leaves, the general table selects `3N+4` traversal actions before page birth and release. The flat table selects `N+1` comparison and finish actions. Additional bounded comparison chunks still cost one action per chunk in either route. The new route omits root frame admission, capture, apply, pop, and page retirement. This is a source-level action count. It does not establish live guest instruction savings.

## Verification

- The language-neutral flat fixture has an Ajv schema and a separate SQLite lookup oracle. It covers unique names and ordinals, ambiguity for both key kinds, unknown keys, and UTF-8 comparison past a 64-byte prefix. The native original-driver test additionally checks comparison counts, absence of stack selections, and funded close after a first comparison or partial long-name comparison.
- The macro expansion test checks wire rename and ordinal generation for plain records and the original path for flattened records, tuples, and enums.
- Pinned Bun passed all three lookup, UTF-8 comparison, and funded-close oracles. Pinned Rust passed both native matcher tests, including unchanged selection and zero reported Work and progress at a one-unit-short quote, followed by retry and funded retirement. The macro expansion test passed. `git diff --check` passed.
- The real `mcp_instance_open_admits_the_descriptor_grant` native test passed with the current matcher and parser on both Note and WFC vectors. It verifies the typed output against the wire fixture, full byte consumption, grant accounting, and paid retirement. Guest instruction impact still requires a build and replay of the updated Wasm component.
- The complete derive-expansion unit suite passed 12 tests, including the new table-generation test, and reported four failures in canonical octet role parsing, expected generated primary paths, closure return type, and a legacy projection token. The tracked receive generators already lack the tested `try_project_owned` token and emit `Result` for the tested close method. These checks exercise generation outside the matcher-constructor change. The unchanged baseline suite was not rebuilt.
