# Compact Owned-Core Job Input

The authenticated WFC SDK journey reached `semio_owned_admit_actor_input_v1` and exhausted the 48-million-item semantic treasury before the solve could run. The Host currently writes each application payload octet as a separate JSON number. The guest generic reader materializes those numbers before the typed Job receiver reconstructs the octets. The compact proposal applies the already authored SJS1 schema to both ends of that crossing.

## Live producers and ownership

- `GuestRelayColdController` owns the live cold Job source. Its two entry points supply either exact application bytes or a borrowed application JSON view. The byte route fills one Job donor directly. The JSON route still encodes the application schema first and then uses the same Job donor writer. The writer binds the exact operation and generation and copies bounded pages after receiving retained item, byte, depth and work authority.
- The owned interpreter calls the same allocator, ActorInput export and deallocator with the same pointer and length. The guest validates the SJS1 header, preserves the separate presence bits for input and checkpoint and fills the existing typed `ActorInput::Job`. The slot becomes ready only after its input capture settles and the same wire is marked returned. Core allocation release still follows frozen SAC3/SRE1 acknowledgment and physical handback. The existing Job registration, step, cancellation and WAL paths continue from the same typed slot.
- The other live original-unit producer is `GuestPoll` in the Host Poll module. Its generic JSON input has its own actor variant and carries the Poll limits and event data. The component WIT Job starts from its generated `JobsWire::JobSource` and has a separate export. The actor crate's older decimal wire cursor has references only in its reexports and a local serializer test. The old Host Job JSON wrapper is compiled only in tests, and the owned guest rejects an incoming JSON Job.
- Malformed headers and kind text use the existing retained input failure projection. Cleanup of an accepted refusal uses the same original capture and retires both the retained outcome and any partial typed body. Cancellation can stop between any copied pages. The unchanged guest allocation remains with its original donor until returned.
