# Prepared actor startup custody

The neutral fixture contains one real Wasm Core module implementing the current owned Semio ABI. It imports no host functions. The Wasm start writes marker 17, `semio_owned_prepare_actor_v1` changes the marker to 93 and reports readiness, and `semio_owned_channel_version_v1` returns the real channel version 25 from linear memory. The independent Bun WebAssembly engine passed all 12 Ajv and execution assertions.

The standard runtime integration target `prepared-actor-startup` opens that module through `OwnedCompiledGuest::prepare_actor` and two genuine `OwnedActorStartup` Sources. Both Sources share the same business operation, generation and logical clock binding. Each supplies exactly two measured instructions for the real channel export. Each retains marker 93, so an additional Wasm start would be observable. The first actor changes the marker to 121 through the paid Core memory write. The second still opens with 93. Its attempt to retire the first actor is rejected, and both actors close under their owning Source. The test reconciles each measured physical allocation and release against the retained receipt.

The pinned native verification rebuilt interpreter Core, interpreter host imports and interpreter runtime from source in ticket scratch, matching dependency identities from the existing host artifacts. The exact production integration test passed with the existing measured allocator. The direct route avoided Cargo and the shared compilation target. `mcp-prepared-startup-check.ts` records the invocation and `mcp-prepared-startup-fixture.py` reproduces the checked-in neutral bytes.
