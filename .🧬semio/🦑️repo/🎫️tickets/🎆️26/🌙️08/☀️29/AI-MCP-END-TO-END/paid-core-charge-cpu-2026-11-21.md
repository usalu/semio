# Paid Core Charge CPU Audit

The current scalar replay reports 1.347 billion instructions for the first Note Input in about 85 seconds without paid Core accounting. The paid gateway crossed 208 million instructions before its 150-second wall. These are different execution paths, so the counts and elapsed times establish the scale of the optimization target without isolating the relative cost of the operations below.

## Repeated accounting on one paid scalar step

- `interpreter/🏗️instance/▶️invocation/🦀️.rs:108` checks cancellation, then `deadline_exceeded()`, then `should_yield()` on every scalar loop before the machine action. When fuel remains, `should_yield()` performs another `ClockStride::read`. The subsequent `charge` at line 124 does another ordinary yield observation. These reads advance the stride and can sample different clocks at the boundary. Deduplicating them is an independent behavior change.
- `interpreter/🏗️instance/🦀️.rs:137–138` quotes the live retained grant, then runs the ordinary or retirement yield predicate, then checks one item, positive depth, copy, capacity and release. It posts the retained receipt first and consumes one fuel only on successful receipt settlement. It does not check cancellation itself. Cancellation belongs to the callers, including the scalar loop and its cleanup exception.
- Job `⏱️context/🦀️.rs:311–317,426,544–565` computes the fresh retained delta and turn, policy and lifetime limits, then reads the bound Source's `remaining()`. Fuel inside the yield predicate independently reads the same Source's `remaining()`, recomputing all retained and work stock and holds as a tuple even though it needs one member. `consume_retained` at lines 336–340 separately recomputes fresh delta for recipient admission and then recomputes the live retained quote a second time to check the identical receipt. The clock mutates the stride only; both the owned gate guard and borrowed Source forms hold exclusive ledger access over the call.
- Source `📬️outcome/🪙️budget/🦀️.rs:264–272` takes another snapshot to post retained work and another to post CPU. For a bound Source and an admitted operation, the two grant observations, the fuel observation and the two posts thus reach up to five snapshots inside one charge. The scalar loop's own `should_yield()` contributes one more. The two posting snapshots each copy the Source state and revalidate all held currencies through `advance_retained` or `advance_work_exact` and `conserved` in `📬️outcome/📦️builder/🪙️return-escrow/🦀️.rs:8–16`. This is repeated computation. One actual retained receipt and one fuel debit are still required.

## Smallest compatible implementation

Add a StepContext operation for one explicit retained action with cost one fuel, parameterized by ordinary or retirement admission. Observe the current Source once, read its remaining retained and work tuple once, and use it for both effective grants. Share the existing pure retained limit arithmetic, computing the fresh delta once. Preserve the current clock position and short circuits. A nonzero effective fuel checks the clock before deciding a retained-only shortage, except in active original retirement. Ordinary charge still checks its clock when retirement is active.

A shared internal retained-post routine can accept the precomputed admission result. Keep the physical checked add before calling Source posting. Preserve its arithmetic overflow error with the incremental receipt and no Source posting. If the recipient was already above the turn ceiling, still post the physical aggregate and try the real Source receipt before returning the existing child-receipt invariant. That invariant takes precedence over the Source error. If the recipient was admitted, propagate the Source retained error and leave fuel alone. The generic `consume_retained` and `consume_fuel` entry points must continue to support actual post-admission overrun and their current latching behavior.

Measure that StepContext change before restructuring the Source. If posting remains hot, reuse one Source posting snapshot locally for the retained-then-work transitions. Keep the physical addition and local work mutation at their original sequence points. Retained overrun may overwrite the Source failure whereas work overrun preserves a previous failure. A work-ledger failure is latched and ignored by the current `consume_fuel` call. A fused implementation needs to preserve both rules and the distinction between publicly visible origin and the pending birth origin. `is_bound()` uses `visible_origin`, while posting uses the existence of the internal origin and `snapshot()` can see a pending birth. Therefore an unbound observation alone cannot authorize skipping Source posting. Any optimized success path that proves conservation from the live net balances needs a fallback for every state for which that proof is unavailable.

Keep the observed budget inside a single synchronous action. The next action must see intervening reservations, releases, refreshed authority and actual progress. Keep the original Source and observers, the physical copy/capacity/release figures, fuel cost, VM cursor mutation and outer cancellation checks. Leave the general import-side charge alone initially because it has a different work quote and cancellation protocol. Use the original interpreter wrappers for integration after the native witness.

## Differential witness

Drive the former wrapper sequence and the new StepContext operation with the same neutral cases on separate equivalent contexts. Record verdict or exact error kind/message/attached receipt, effective retained grant and fuel, actual retained progress, raw and net Source stock, Source failure and holds, clock stride and sample count, and the external physical/work/reserved observer deltas at scope close. Where the result permits another action, compare a subsequent action too. An independent oracle can calculate the scalar stock and holds with arbitrary-width integer arithmetic and assert conservation after every success.

| Cases | Required observations |
| --- | --- |
| Fresh context, exact fit on each currency, zero copy/capacity/release, and shortage of each currency independently including zero depth | Equal verdicts, equal clock behavior, no posting on admission denial, one item and one fuel on acceptance |
| Exact one local fuel, zero local fuel, zero live net Source fuel with local fuel, and a Source hold consuming the final item/byte of a grant | Equal clock short circuits and equal live stock |
| Borrowed actual Source and owning gate reference, nonzero starting receipt, retained policy narrowing, attached reserved return observer, existing returned progress, and release or redemption of a hold between actions | Equal local and aggregate receipts, identical observed grant changes and no charge to reserved-return counters |
| Clock unknown, cached clock below/at deadline, clock changes at the next stride sample, ordinary mode under active retirement, and retirement mode with and without the original retirement loan | Equal us readings, deadline/refill boundaries and verdicts |
| Cancellation already observed and cancellation between interpreter chunks, with normal and authorized cleanup calls | Equal caller cancellation, no ordinary mutation after an observed cancellation, and preserved cleanup admission |
| Recipient above raw turn grant but saturating quote fits a zero-spend component, aggregate checked-add overflow, Source retained error, Source work error, preexisting latched failure, and pending Source birth | Equal posting order, exact invariant/Source precedence, failure latching and zero work on retained error |
| Paid Wasm sequence with scalar, memory and call instructions, one byte below a mutation quote, budget exhaustion and retry, then cleanup | Identical machine state, output and receipt totals on identical budget schedules. Validate final Wasm output with the independent Bun engine. |

For the bound Source fixture, begin with the genuine admitted Source, reserve actual holds through the owner and exercise the same retained and work observers as the paid gateway. An unbound StepContext fixture cannot establish Source behavior. A focused native performance witness can time pinned repeated scalar actions under a genuine borrowed Source and print exact conservation totals before and after. Use the same Note Wasm artifact, request, policy and interpreter/ledger optimization levels for the final gateway comparison. The objective is more progress per wall-clock interval with byte-for-byte paid totals on matching VM prefixes. No production change is needed to obtain the baseline.

The path above was checked against the current sources. No native benchmark or production edit was performed as part of this audit.

## Native fixture reuse

The existing caller fixture in `⏱️context/🧪️testing/🎟️caller/🦀️.rs` supplies an admitted authority through `OriginalJobFixtureCaller::admit`, `birth_returns`, `retain_dispatch` and `refreshed_turn`. `StepContext::testkit` exposes the real Source snapshot, inherited-loan check and pinned local turn renewal. Assert during the fixture that the candidate actually uses the inherited return budget and that a live claim changes net stock while raw stock stays constant.

For the local arithmetic-over-ceiling case, put the initial fresh copy count above the raw turn grant and quote zero additional copy bytes, while leaving item and depth available. This reaches the original retained post and child-receipt invariant. A copied-item overrun would instead zero the quote's item headroom and return `Ok(false)` before posting at all. For Source-only errors, include internal pending-origin or preexisting failure states. Conservation of a healthy visible Source plus an exact-fit retained receipt and one unit of remaining fuel rules out new Source overrun under the admitted steady-state path.
