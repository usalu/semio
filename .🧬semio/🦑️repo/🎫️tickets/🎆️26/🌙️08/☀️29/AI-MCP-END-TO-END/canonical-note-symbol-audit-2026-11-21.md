# Canonical Note Symbol Audit

The exact canonical component's main core module has 73 function imports and no core name section. The separately built `🗑️generated/m-parse` Note component has 73 function imports and a 188,560,157-byte core `name` section, but its function numbering and bodies differ substantially; indices cannot be transferred directly. A streaming BLAKE2b-128 comparison followed by byte equality gives a usable limited bridge: canonical function 57361 has a unique 200-byte canonical body equal to retained named m-parse function 560776, `_RNvMs_NtCsd5ATPcZyULN_36semio_framework_value_native_outcome9receivingNtB4_24OriginalReceivingPrimary8is_empty`. This identifies its implementation body as `semio_framework_value_native_outcome::receiving::OriginalReceivingPrimary::is_empty`; it does not prove unique source identity across optimized code folding.

The exact canonical profile reported 41,131 samples, of which 57361 had 1,574. Canonical function 58406 had 2,889 and its 389-byte body tests numerous field and sentinel values with early exits before calling 57361. This identifies it as an aggregate emptiness-style check containing the named predicate, though its source owner is unproven. Their combined 4,463 samples are 10.85% of the reported total if samples are exclusive; do not sum inclusive stack samples.

Canonical 56229 (134 bytes, 1,917 samples) performs pointer and field checks, an 8-byte alignment guard, and calls three error paths; its own body contains no loop. Canonical 136155 (263 bytes, 1,760 samples) compares fields and sentinels, invokes canonical 58825 twice, and writes distinct result records. Its owner is unproven. Canonical 121031 is an 81,055-byte body with 1,460 samples. None of these four bodies has an exact m-parse match, so no retained symbol can safely be attached to them from this comparison.

For further classification, iterate just the main core code section's length-delimited bodies, subtract the 73 imported functions, and decode operators and immediates in selected bodies with an existing `wasmparser` dependency. Resolve sampled PC coordinates against the profiler's own definition before selecting the containing instruction and enclosing structured loop; inspect direct call indices, referenced data addresses, and neighboring bodies. The 121031 function requires a focused PC window, not full disassembly. Exact body matches should be byte-verified and checked for duplicates before transferring names; partial structural or constant similarities are hypotheses only. `node_modules/.bin/wasm-dis` has no function-selection option, and full disassembly was not attempted. The retained `host-spill` object files are host runtime objects, not established canonical guest objects. No production files or builds were changed.

## Source-level receiving path and repeated selection

Canonical 58406's opcode sequence corresponds to `NativeReceivingEffect::has_no_retained_custody` in `🧰️framework/🔨️modules/🌱️value/🛬️decode/🏭️construction/📦️effect/🧳️frame/🦀️.rs:296`: its final test calls the matched 57361 predicate on `receipt_primary`. It checks every real frame owner and state before returning. Its callers include `NativeResidentSuccessAck::reusable`, binding, authority preparation, rearm and close demands, and terminal checks in the same file, plus `NativeSchemaKeyFrame::idle` at `🛬️decode/🧳️owned/🧩️record/🌳️source/🗝️key-frame.rs:19`, which is used by key/result and closing checks. Each successful bind or rearm demand tests both semantic and metadata frame custody.

One specific repeated route exists in `🛬️decode/🧳️owned/🧩️record/🔎️schema/🧭walk.rs:62` and `🎛️drive.rs:24-36,88-98`: `selection` tests `binding_needed()` by calling `bind_semantic_demand()` and probes `rearm_authority_demand()`. In one successful `advance_nested` metadata Bind or Rearm invocation, the selected predicate is calculated five times: once in the outer selection; once in the guard's `demands` selection; once in `demands`' `key_metadata_demand`; once in `advance_metadata`'s `key_metadata_demand`; and once inside `bind_semantic_into` or `rearm_authority_into`. Separate `demands`, `select_advance`, or `nested_work_demand` queries may add further selections. The exact dynamic count for this replay and contribution of this particular route to the samples remain unmeasured.

The shortest candidate is to carry the selected operation and its already checked demand through the synchronous, immutable part of `advance_nested` and its grant check into `advance_metadata`, instead of reselecting and requoting. Preserve the final `*_into` revalidation after the original Work and construction authorities are acquired; never carry a selection across a pending return or mutation. Keep exact grants, work accounting, cancellation, Post, publication and original-owner identity checks. Qualify with retained success, refusal, starvation, cancellation and replay tests, including unchanged receipt bytes and instrumented selection/predicate call counts. This removes redundant query work but has not yet been measured and cannot explain all 1.347 billion instructions by itself.

A broader independent candidate is an inline vacant/occupied representation for the private `receipt_primary` member, so a vacant frame does not scan all 16 inner members. Staging must preserve a real occupied original even on partial or refused outcomes, and normalize to vacant only after proving the entire owner empty; update field-wise initialization and all size-based paid demands. Never replace the checks with an unchecked Boolean cache: `OriginalReceivingPrimary` exposes mutable public fields. This representation change may alter accounting and requires its own lifecycle and receipt qualification.

The actual first-Input entry passes from `semio_owned_admit_actor_input_v1` (`📣️macros/⚛️wp4-reactor/🦀️.rs:269`) to `admit_input_owned`, with `OriginalActorInputReceiving` holding `OriginalJsonOutputSource<ActorInput>` and driving `receive_step` at `⚛️reactor/🎟️context/🌉️call/📥️input/🦀️.rs:44,229`. The schema matcher is a plausible typed receiving route, not yet a measured call-stack attribution for this input. The replay reports 3,220 operation-clock reads and one monotonic read in the first Input; inter-clock instruction totals do not by themselves identify which source loop consumed them.

## Common typed receiver birth

Note and WFC first Input executions measured 1,347,018,726 and 1,347,003,403 scalar instructions respectively, a difference of 15,323 (approximately 0.00114%), despite 3,221 versus 2,499 clock imports. The near equality points toward common guest work, but does not identify a loop or establish that the difference in import counts caused any particular cost.

Both enter the same framework `OriginalJsonOutputSource<ActorInput>`. `NativeReceivingOriginal::demands` (`🛬️decode/🧳️owned/🧳️original/🦀️.rs:28`) first reserves the concrete `ActorInput` receiver and then selects its template. The prior native Note fixture observed a 534,928-byte typed receiver allocation and a 534,931-byte seed quote. These are native measurements; neither establishes the canonical Wasm layout or instruction cost.

`ActorInput` is a derived payload enum (`🧬️schema/🔁️persistent-local/🦀️.rs:134`). Its generated `receiver_template(false)` is explicitly an 11-field template, not the generic by-value `initialize_seed` fallback (`✨️derive/🛬️receive/🔀️enum/🦀️.rs:43-68`). One field, `state.child`, is `Option<#selected>`, where `#selected` embeds the largest variant's receiving slot; the generated seed writes `None` in place. Large type size alone does not prove a large physical write or copy: inspect each actual Wasm field quote and generated instructions, or instrument bounded seed-part counts, before changing the representation. A compact vacant shell with separately paid selected-variant storage may reduce the fixed type extent, but it changes birth, retirement, copy and capacity quotes and requires the full original ownership and receipt lifecycle to be preserved and measured.

Canonical function 121031 is an 81,055-byte structured dispatch body containing many nested blocks and repeated branches. A raw scan finds 50 appearances apiece of five-byte direct-call encodings targeting canonical 136158, 138511 and 138521; this is only a byte-pattern clue, not a validated operator count or source attribution. It does not contain the native 534,928 or 534,931 integer encodings. No source owner or copy loop has yet been proven for this hot function. Canonical 56229's previously observed pointer and alignment checks likewise remain unattributed to a particular source operation.

## Flat record matcher opportunity

`✨️derive/🛬️receive/🦀️.rs:37,41` knows the per-field flatten attribute and emits a `Leaf` for each ordinary named field. A generated, explicitly certified flat descriptor can therefore identify a record whose entire schema consists of leaves; a single observed leaf does not prove this property for an arbitrary `NativeSchemaFields` callback. Flattened schemas and enum union alternatives must continue through the general walker unless independently proven equivalent. Descriptor names need not be unique, so flatness does not imply an unambiguous match.

For one input key against N ordinary leaves with no early ambiguity, after the original key is bound the current root walk performs N sequences of `CaptureFrame`, `ApplyFrame`, `CompareLeaf`, followed by `CaptureFrame`, `PopFrame`, `FinishPopped`, `Finish`: **3N+4 selected actions**. A matched equal-length long name may require additional comparison actions, each limited to `min(body,64)` bytes. The root `PendingSlot` reservation and adoption, key Source birth/acknowledgement, matcher closure and allocated page release are additional work. A second matching leaf terminates early as ambiguous, so this count is not an unconditional dynamic count. See `🛬️decode/🧳️owned/🧩️record/🔎️schema/🧭walk.rs:7-62`, `📦️pending.rs`, and `🗝️key.rs:62`.

Near-term design: for a certified flat table, retain a resumable original-key borrow, descriptor index, bounded byte offset and `Missing`/`Field(root)`/`Ambiguous` result. Under the actual granted effect, select one leaf and compare at most the funded prefix, recording only the real descriptor read, byte comparisons, and resident state writes. Continue scanning after the first match to detect duplicate names or ordinals, and stop at the same second match as the general walker. This can remove root page allocation, reservation, capture, apply, pop and page release from flat scans without removing the key projection's Source custody, acknowledgements or receipts. Recalculate real work and copy/capacity/release demand for the new physical operations; do not fabricate the old stack receipts. Preserve resumability and unchanged state under denied grants, original Source/effect identity, cancellation, retirement and failure handling.

Record derive currently handles `Missing` according to subset mode, rejects `Ambiguous`, and rejects duplicate non-flattened destination fields via `positions[field]` (`✨️derive/🛬️receive/🦀️.rs:116`); these rules remain in the caller. Qualify flat against general matching and an independent schema oracle for duplicate names and ordinals, unknown keys in both subset modes, duplicate incoming keys, zero and partial budgets, names across the 64-byte boundary, Source replacement, cancellation and paid closure. Include mixed/flatten/union fallback. The profile motivates eliminating repeated ceremonies but does not yet prove the sampled functions are attributable to this matcher or quantify its share of first Input.

The narrow typed interface is `NativeRecordMatcher::new_flat(&'static [NativeSchemaLeaf], NativeSchemaKeySource)`. For a named record with no flattened fields, derive emits an associated static leaf slice from the same compile-time names and ordinals as the existing descriptor, and `scan_apply` at `✨️derive/🛬️receive/🦀️.rs:95` uses `new_flat`; all other cases continue to call `new(fields,count,source)`. This certifies the table structurally without a runtime validation scan or trusting the outcome of an arbitrary callback. `NativeRecordFields::native_schema_fields` (`🛬️decode/🧳️owned/🦀️.rs:42-45`) still provides the general capability for nested records. Enum-derived `NativeRecordFields` explicitly emits a Union (`✨️derive/🛬️receive/🔀️enum/🦀️.rs:59`), while its unit/data tables may contain Skip, so this record-only selection must not mark them flat.

The flat lane still holds the genuine key backing and projection, borrowed-key pointer or ordinal, work/source binding, index, partial-name offset, match and completion state. Its close path must still retire the key backing and binding, clear any live key/partial state, and honor partial cancellation; the root `PagedList` is never created or funded in that lane. The exact 601-byte InstanceOpen replay is a Poll input. Its `PollInput` is a derived four-field named record with no flatten attributes (`🧬️schema/🔁️persistent-local/🦀️.rs:79-86`), giving a concrete candidate intersection even though the runtime call count is not yet attributed. Existing generated Wasm cannot exercise an edited source: a fresh component build and transcript are necessary. Compare semantic output, unchanged original-wire custody, paid conservation and truthful new SRE1 accounting; successful removal of physical stack work can legitimately change receipt totals, so old SRE1 bytes need not remain equal.

## Poll limit data and scalar authority

An empty Poll was measured at 525,525,103 Wasm operations. The current host freezes `PollRequestLimits` when opening its session (`🖥️host/🔁️poll/🎛️session/🦀️.rs:53`): five requested retained-policy axes, requested work fuel, root turn execution fuel, operation deadline, and the three root result-shape maxima. `GuestPollSessionInput` serializes these as immutable data within its `limits` JSON object (:68-71). The guest's `PollInput` includes that object and `poll_owned_step` later calls `poll.limits.narrow` with the then-current authenticated Poll authority (`⚛️reactor/🎟️context/🌉️call/🎭️exports/🦀️.rs:134`). `PollRequestLimits::narrow` (`🎠️kernel/🪪️identity/🦀️.rs:407-435`) takes per-axis minima for the five policy values, both fuel requests and deadline; shape maxima pass through as request data.

The Core's 19 scalar budget words identify and bound a particular loan and its epoch. They have one current fuel, not the two frozen requests, omit the three shape maxima, and may change on retries and again at Poll time. Reconstructing the original request from those words is therefore not equivalent and may change effective limits. Keep the frozen request separate from fresh loan authority and retain the existing narrowing rule. Source binding authenticates custody and issuer relationships; it does not turn the three unchanged shape values into additional loan fields.

One possible schema-first replacement is a single internal owned-Core ActorInput envelope with tag and checked extents. The Poll header carries a 76-byte fixed little-endian data record: eight `u64` values (five retained axes, work fuel, execution fuel, deadline) and three `u32` values (maximum effects, patch bytes, frames), followed by event/page payload. Decode with checked extent and platform conversions, debit actual bounded Work and state writes, and retain the same original Source and authenticated Poll-time narrowing. The host can supply that envelope at the current immutable input boundary: `🧠️interpreter/🏃️runtime/🎟️call/🧮️unit/🦀️.rs:56,68-70` allocates, copies, passes and releases one exact input allocation, validates result non-aliasing and waits for returned custody. The guest checks pointer-plus-length and linear memory extent at `🎭️exports/🦀️.rs:100`; `OriginalActorInputReceiving::new_bound` retains the whole pointer, length and Source binding. A payload suffix can be borrowed from that full envelope, but cannot replace its identity or permit early return of the original allocation.

The main implementation boundary is that `OriginalJsonOutputSource<ActorInput>` currently parses and closes the whole original wire as JSON. A binary prefix therefore requires a genuine staged envelope owner and paid fixed-record receiving, subordinate payload lifetime, cancellation and original return/retirement, plus coordinated producer, schema, fixtures and replay changes. As a smaller first slice, a fixed positional JSON array with a dedicated bounded native receiver can remove the eleven field-name matches while preserving one JSON allocation and Source lifecycle, but the generic JSON parser still creates its value tree; it is not a binary fast path. Either change can replace the internal representation in one coordinated cutover without retaining a legacy route. The existing WIT `ActorInputWire` Pack/`TurnShape` path is distinct and does not establish that the measured owned-Core JSON path already uses this layout. No measured speedup is claimed.

## Shard-to-owned Poll routing defect

`ShardLoop::execute_turn_for` (`🖥️host/🧵️shard/🎬️shard-loop-frame-turns-and-job-control/🦀️.rs:69-103`) performs the original actor admission, checks out `OriginalActorInput<Event>`, and invokes `GuestRuntime::execute_turn` with the original checked loan. The Owned adapter (`🎭️guest-runtime/🧠️owned-runtime-adapter/🦀️.rs:49`) routes that to `OwnedRuntime::execute_actor_turn` (`🧠️interpreter/🏃️runtime/🔄️owned-runtime/🦀️.rs:112`), which serializes `OwnedPollInput` and starts the old direct Poll operation with an input buffer. The current `semio_owned_poll_v1` instead requires its 19 scalar authority arguments and a separately admitted original input; a low-arity compatibility shim would not repair the custody or settlement contract.

The shortest genuine route is to integrate the existing `GuestPoll<T,R>` state machine into the shard's actual original Event and instance ownership, rather than invoke that direct turn method. Its public staged operations (`🖥️host/🔁️poll/🦀️.rs:116,140-149,321-322,394-421`) already select Boot, original Input admission, Poll, output, frozen receipt, acknowledgment and retirement with actual `StepContext`, guest subloans and execution budgets. Each guest completion and infrastructure debit must be settled back into the same checked shard Event issuer before `return_actor_turn`; keep the event and its wire pinned across pending calls, use the existing frozen escrow/journal and deliver and retire typed output under the owning Source. Preserve cancellation, failure and cleanup before releasing the actor or event. This is an integration design, not an assertion that all necessary shard adapters already exist.

`GuestPollSession::new` (`🔁️poll/🎛️session/🦀️.rs:27-30`) owns a `GuestRelayWakeDriver` and creates a `NativeHomeAdmission`; blindly constructing one for an already registered shard actor would introduce a separate treasury and native home rather than prove the existing checkout. Either extract the common session transitions to run against the shard's actual parent authority and existing instance, including genuine guest subloan and receipt journaling, or move that original ownership upstream into the existing session. Determine the operation, retirement and execution-budget bridge explicitly; neither copying numeric budgets nor self-issuing another driver proves Source identity. This crosses the shard's actor lifetime and transport settlement and is larger than a local ABI call change.

For a real-component lower-level regression, `🖥️host/🧪️tests/🔬️owned-instance-open/🦀️.rs:45-65` already loads the neutral component and constructs an InstanceOpen event, but its existing test asserts fuel exhaustion and mid-flight behavior and may stop before reaching the mismatched Poll call. Add a genuinely funded run through admitted input and current scalar Poll, validate returned original receipts and typed result, and close the actual Source. Separately exercise `ShardLoop` with a real Owned runtime and registered fixture actor through Event pump, continuation and receipt settlement; the existing shard Mock/Recording tests do not establish that production Owned dispatch works. Include denial/resume, changed wire or Source rejection, cancellation and failure closure. Neither test has been run for this audit.
