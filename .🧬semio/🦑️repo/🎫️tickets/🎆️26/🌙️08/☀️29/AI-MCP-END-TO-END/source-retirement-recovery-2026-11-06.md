# Same-Source Retirement Receiving

The actual Source now lends its original construction recipient and the same decoder construction issuer to retirement-only recovery. It exposes no raw decoder control or new semantic admission. Read-only work readiness now belongs to JobReceiving; Source retains identity, deadline and budget qualification.

## Ownership contract

`StepContext::with_native_retirement_receiving(&mut Option<OriginalNativeReceivingOutcome>, unit callback) -> Result<bool, OriginalTurnFailure>`.

- Existing destination or enclosing semantic receiving scope: refusal before entry, destination preserved.
- Source identity/issuer qualification failure: complete OriginalTurnFailure before entry.
- Insufficient two-item, exact destination-copy, depth or two-work reservation: false, no callback or output.
- True: destination contains the complete NativeDecodeCallFailure (output/operation/context/receipt_refusal) plus independent Source posting refusal. It is installed before work/Source posting. The same Source funds both destination placements before entry; that reserve is withheld from the child's grant.
- Actual nested construction progress is posted once to the Source physical ledger. Actual decoder work is consumed once. No enclosing semantic receiving receipt is created.
- The owning outcome implements controlled RetireOwned; callers retain it through paid transfer/retirement and must not overwrite an unresolved destination.

The normal already-owned retirement route remains distinct. Existing caller error projection moved to the receiving owner without changing its policy.

Normal receiving now uses the same full paid unit/preborn-outcome contract, with a distinct normal cancellation/deadline gate. Both callbacks receive the exact post-placement body RetainedCloneGrant as their second argument. The old generic-return normal callback and separate manual semantic receipt protocol were removed.
