# Paid Core Charge Verification

The ordinary and retirement Core wrappers now call `StepContext` to admit and post one retained item and one work unit. A healthy bound Source uses one live remaining-stock read for both admission decisions. The old wrapper made up to three remaining-stock reads in addition to its two Source posts. The turn-local fresh progress and the retained policy are evaluated against that single read. A nonzero effective fuel balance still checks the existing clock before returning a retained shortage. An active original retirement loan bypasses that deadline sample only in retirement mode.

The physical checked add precedes the retained Source posting, and the work debit follows successful retained settlement. An over-ceiling physical recipient still posts its incremental receipt before returning the original child-receipt invariant. Aggregate overflow returns the checked-add refusal and the attempted receipt before Source posting. Source postings use their original entry points, including for pending, externally invisible Source birth. The existing scalar loop cancellation and clock observations still run at their original call sites.

## Verification

- The focused native witness passed all three tests. It used a genuinely admitted Source, a real prepaid claim holding two items and two work units, and a child holding a borrowed reference to that same Source. The native observations matched the former sequence across all 14 neutral cases for verdict, physical delta, work, live Source stock and holds, clock stride and sample count. The test then returned the claim, confirmed that subsequent work saw zero holds, and checked the same-source borrow and closure. The owning gate case posted the expected delta to nonzero external physical and work recipients and left reserved-return observers unchanged.
- The focused overflow test verified the original refusal kind, message, attached receipt and preserved fuel for an over-ceiling recipient and for aggregate checked-add overflow. The dedicated stride test verified an accepted action at a cached below-deadline reading, followed by a real deadline sample and refusal on the next action.
- The neutral cases passed the independent SQLite calculations and Ajv schema validation in the three-test Bun native-progress suite.
- Native timing used the pinned `nightly-2026-07-20` host compiler at optimization level 3 and the warmed gateway Source ledger. In nine witness processes, 20,000 identical accepted borrowed item/work debits took a median of 6.939 ms with the former sequence and 4.691 ms with the combined read, a 32.4% reduction in this local sample. Every measured run asserted exact item and work deltas and Source conservation. This is a native accounting measurement. Gateway wall time and the Note workflow require a run of the built gateway.

The repository launcher waited in host capacity admission, and the selective Cargo path waited on the compiler host-capacity lease. The native result came from the pinned Rust fallback in `retained-charge-native.py`, linked from the warmed gateway units under `🗑️generated`. The fallback uses the test allocator belonging to the same trace crate as the warmed units. Deliberate Source-latch faults and private pending birth were reviewed through the shared unchanged posting methods. The focused witness directly forces physical refusals and healthy bound-Source admission.
