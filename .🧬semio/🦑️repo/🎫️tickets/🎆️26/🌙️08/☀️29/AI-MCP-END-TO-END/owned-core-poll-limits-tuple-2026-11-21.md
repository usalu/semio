# Owned Core Poll Limits Tuple

## Proposed wire

`{"Poll":{"events":...,"command_page":...,"cold_pair_page":...,"limits":[items,copy_bytes,capacity_bytes,release_bytes,depth,work_fuel,fuel,deadline_us,max_effects,max_patch_bytes,max_frames]}}`

[Wire schema](poll-limits-tuple.schema.json) · [Neutral cases](poll-limits-tuple.json) · [Independent oracle](poll-limits-tuple.test.ts)

The first five fields are unsigned 32-bit retained extents, the three counters are unsigned 64-bit, and the last three shape limits are unsigned 32-bit. Use a checked conversion from host `RetainedCloneGrant` extents, since the existing guest reads them as wasm32 `usize`. A host value outside wasm32 range should refuse without creating an input allocation. Counters stay integer-valued through streaming, decoding, and `narrow`, including values above JavaScript's exact numeric range. The tuple has no operation, generation, epoch, clock binding, cancellation flag, or original grant.

## Production cutover

1. Define the owned-Core-specific `OwnedCorePollLimits` typed tuple next to the existing logical `PollRequestLimits` in `kernel/identity`. Derive `Serialize`, `Deserialize`, `NativeReceive`, and `RetireOwned` on the tuple only. Use private scalar fields and a checked `TryFrom<PollRequestLimits>` boundary. Share its declared arity and bounded scalar lookup by index with streamed producers. Avoid building a per-child temporary array. Convert the tuple back to logical limits before reusing the existing `narrow` at Poll time. Preserve the original logical type and its serialization elsewhere.
2. Change `plugin/host/poll/events` so `Node::Limits` exposes an 11-item `JsonWriteNode::Array`, each scalar child as `Number::UInt`, and no object keys. The `Policy` node is only used by the old limits object and can be removed. Both `PollJsonSource` and the tagged `GuestPollSessionInput` already delegate to the same limits node. The session constructs its one tuple at open under the existing original operation request and policy.
3. Change `PollInput.limits` in `plugin/schema/persistent-local` to the shared `OwnedCorePollLimits`; no serde adapter or alternate decoder. Its actual `ActorInput::Poll` admission remains the existing borrowed JSON wire. Keep `with_poll_step` and `exports::poll_owned` on the exact retained input, with live `cx.retained_grant()`, `cx.fuel_remaining()`, and `cx.deadline_us()` used when calling `narrow`. Storage sizes are recomputed from the typed definitions by existing quote call sites. Check the small-grant, release, and exact byte-identity tests on the rebuilt code.
4. Migrate `persistent-local/actor-input.json` Poll fixtures and add rejected named-object, short/long, quoted, fractional, overflow and authority-injection cases. Update the host streaming oracle to compare against the shared typed tuple's serde output and against exact per-index fixture values. Keep the existing narrowing and exact authority assertions. Extend actual Note/WFC InstanceOpen coverage to assert tuple wire, complete byte consumption, native rejection/retirement and pointer/length stability on the existing original source.
5. Migrate the borrowed interpreter serializer to the same tagged data shape if retaining its call sites. `interpreter/runtime/snapshot-operation-and-input-records::OwnedPollInput` currently emits an untagged `budget: Budget` envelope with original identity in JSON. `encode_original_poll_input_into` and `execute_actor_turn` are its two producers. The former has only an in-module test caller. The latter's serializer must use the shared tuple and its fixture must assert the new wire. This removes a second data shape without implementing a compatibility export.

### Separate interpreter dispatch defect

The production shard child constructs `GuestRuntimes::Owned` at `host/shard/child:68`. The shard pump selects a funded `DeferredAuthority::Event` at `shard-loop-registry-and-pump:175–180`. `execute_turn_for:73–98` first admits a Pending original input, then invokes generic `execute_turn` for the dispatched event. The Owned branch forwards through `owned-runtime-adapter:48–49` to `OwnedRuntime::execute_actor_turn`. Its allocation stage passes two i32 arguments, a pointer and its length, to the same `semio_owned_poll_v1` export whose production signature takes 19 scalar arguments after separate actor-input admission. This is a static production call path. A live failure was not reproduced. Repairing that route requires migrating its dispatch and receipt custody to the admitted Core sequence. Changing limits serialization alone does not repair the dispatch.

Other WIT or native uses of `Budget` and the authenticated scalar `OriginalJobBudget` are distinct from this wire. The structured `plugin/schema/actor-input` Poll with `shape` is also a separate non-Core data schema and has no owning reference from `owned_abi::ActorInput`.

## Cost and verification

Native receiving for a derived tuple uses `sequence_len`, requires the declared width, and records source positions directly; it does not acquire schema-key projections or construct a per-key matcher. The replaced named records have seven `PollRequestLimits` fields and five nested `RetainedCloneGrant` fields. Under the current flat traversal and a full short-key comparison, the old limits subtree therefore uses (7 × (7+1) + 5 × (5+1) = 86) comparison/finish actions plus twelve key-admission lifecycles. The proposed tuple uses eleven local scan-position actions. All eleven scalar value receivers, the outer `limits` key, event payloads, and original Source accounting still execute. The derive's general state may still include an unused matcher slot in its Rust layout, so dynamic elimination does not imply a proportional allocation saving.

The compact existing large-cap Note/WFC `limits` values shrink from 278 bytes to 93 bytes. The 601- and 602-byte fixtures shrink to 416 and 417 bytes. This removes matching and lowers text parsing work. No updated component has yet been built or measured. Measure raw guest instructions against the current canonical flat Note with the equivalent canonical fixture, using the same loan, clocks, admission/return, first turn output, and close checks. No binary prefix is included.

Pinned Bun passed both neutral tests. Ajv validates shape and ordinary widths, source lexemes and `BigInt` enforce exact integer boundaries, and SQLite independently evaluates the minimum for each position using exact decimal strings. The post-cutover neutral checks passed 20 assertions, the regenerated ActorInput oracle passed 17 cases, and the scalar diagnostic confirmed live narrowing. The native Rust narrowing and original actor admission tests require the rebuilt component and host.
