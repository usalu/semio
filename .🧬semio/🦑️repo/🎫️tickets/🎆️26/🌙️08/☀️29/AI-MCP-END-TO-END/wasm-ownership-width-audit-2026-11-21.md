# Wasm Ownership Width Audit

The six-billion diagnostic can fail before the Core header: `OriginalJobBudget::scalar_arguments` serializes both `input.grant` and `retained_policy` as u64; `from_scalar_arguments` converts each of their five axes with `usize::try_from`. The wasm32 macro invokes this conversion before `admit_owned`, returning `OwnershipLimit` on any value over 4,294,967,295. This is a structural explanation consistent with the existing witness, not a new instrumented observation identifying its exact offending argument.

`RetainedTurnInput::borrow_original` reads `cx.original_total_retained_grant()`, while the independently bounded `OriginalJobBudget.retained_policy` comes from `cx.retained_grant()`. Thus a finite turn policy does not narrow the echoed total. `OriginalActorInput::checkout_guest` likewise computes and holds a bounded policy but places the entire remaining original grant in the guest input. The total is host physical stock, not evidence that the guest needs authority over that entire stock. The VM execution callback in host wake operation separately borrows the original total; trace every actual minting path, not just checkout_guest.

A candidate fix requires an explicit guest source projection minted before issuance: each extent bounded by both actually available source authority and wasm32 representability, with the host holding the full original stock and the exact projected input and bounded policy. Validate the guest's unchanged echo and actual fresh spending against that exact held projection and debit the real original source once; never rewrite a received wire value or replace host custody/stock. The guest context retains its initial grant and validates later totals against initial minus cumulative fresh spending (`OriginalActorContext::remaining_grant` and bootstrap validation), so simply re-clamping the host remaining total to u32::MAX on every call can improperly replenish the guest. Maintain a conserved guest-side projected source across epochs or explicitly implement an authenticated top-up protocol; preserve epoch, clock, deadline, receipt and escrow equality. Per-turn policy must remain within that projected remaining source and cover actual semantic, transit, and infrastructure reserves. This design needs end-to-end qualification, including cancellation and return/escrow settlement, before implementation is considered proven.

The separate retained job payload ledger is bounded to 16 KiB pages, 256 pages / 4 MiB per operation, and 64 MiB per process in `🧰️framework/🔨️modules/🧵️job/📄️payload-pages-and-ledger/🦀️.rs`; these constants fit wasm32 and do not establish a cap on total copy currency. They do not prove every other payload or value limit fits: no comprehensive payload-limit audit was completed. The configured guest memory maximum is 512 MiB per the prior canonical guest profile audit, which likewise is not a documented cap on cumulative copy authority. No authoritative requirement that the host total must fit wasm32 was found in this focused trace.

Evidence: actor retained-turn `🦀️.rs` (borrow, checkout, exact echo/receipt), `💼️job/📋️arguments/🦀️.rs` (checked target-width conversion), `💼️job/📥️source/🦀️.rs` (held job loan and exact receipt), actor `🎟️context/🦀️.rs` (cumulative source authority), plugin macro `📣️macros/⚛️wp4-reactor/🦀️.rs` (conversion before admission), and host wake `📥️operation/🦀️.rs` (execution input). Prior `source-scope-stock-2026-11-06.md` describes stable physical stock claims and custody. No source edits, tests, or builds were performed.

## Issuer and Poll Correction

The specific Boot issuer is `admit_guest_subloan_inner` in host wake policy `📥️operation/🪙️guest/🦀️.rs`, not `OriginalActorInput::checkout_guest`: it derives physical availability after host cleanup and transit reserves, intersects it with the sum of the remaining semantic and infrastructure purposes for `header_grant`, then intersects that with the selected purpose for `grant`. The guest receives this combined guest authority; it is not the raw host total. The representability projection belongs at this issue point, before Core reserve checks and the creation of `RetainedTurnInput`, descriptor, and `GuestHold`. Both the header grant and purpose grant must fit, with purpose bounded by header. The existing guest receipt checks hold that exact descriptor, including full input; boot and cleanup transitions compare the exact descriptor input. Host root `issued_input` must continue to represent its whole physical remaining stock: `issued_budget` and `begin_scope` explicitly require that equality. The guest's persistent initial-grant conservation constraint above still applies and makes independently clamping each header insufficient.

There is an independent Poll JSON request axis. `GuestPollSession` builds `PollRequestLimits.retained_policy` from the unprojected operation request; `PollJsonSource` writes its five usize fields as u64 JSON numbers. The guest must deserialize these fields as target usize before `PollRequestLimits::narrow` intersects them with scalar authority. Therefore a request extent above wasm32 remains a potential later parse failure even after fixing the scalar descriptor. Issue a representable requested policy before encoding, bounded against the authenticated projected guest authority; preserve actual source stock. `max_effects`, `max_patch_bytes`, and `max_frames` already have u32 types. No actual later failure was observed in this review.

Focused qualification should cover the wake issuer's exact hold, equality and settlement at u32 max and max+1, separate physical and purpose reserves, cumulative spending across epochs without reissuance of unspent authority, and cleanup; scalar checked conversion at the wasm32 boundary; and Poll JSON request encoding plus actual guest parsing with the oversized request. The existing wake policy guest and Poll events tests are natural narrow seams. Follow with an actual Boot, Input, Poll and CloseContext journey under oversized host stock and verify exact echoed input and ledger accounting. No tests were run here.
