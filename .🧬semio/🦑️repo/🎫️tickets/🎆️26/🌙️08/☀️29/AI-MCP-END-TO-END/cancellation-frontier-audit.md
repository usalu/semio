# Guest inference cancellation frontier

The seeded WFC run records binding and a 0.35 “running in the plugin's guest” row, then accepts cancellation, but remains running through the observation. The Pack and SPR bytes remained exact. The row is emitted immediately before the synchronous ActionAdapter call, so it does not prove guest execution or identify the blocked phase.

The job registry binds the same cancellation token before spawning the guest thread (inference/📤️submit-and-guest-jobs/🦀️.rs:29–37). Its terminal cancellation is recorded only when the guest call returns (lines 64–75). Inference routing passes that token into the actual inference operation driver (workspace/📨️plugin-artifact-channel/💡️inference-route-and-actions/🦀️.rs:75–86). However, origin registration precedes that driver and uses a persistent origin driver with an always-false cancellation supplier (lines 9–21, 81). The existing trace cannot distinguish blocked registration from inference or paid retirement.

The origin registry's resolve callback holds the process registry mutex (plugin/🖥️host/🔀️post-turn-relay/🏠️native/🗂️origin-registry.rs:24); registration and closure use try_lock. Closure must prevent new homes, wait for actual home releases, and pay for removal (lines 25–27). After closure, channel-record/🦀️.rs:63–68 synchronously loops on close_root_step without a bound. Both registry retirement and real source cleanup are therefore possible subsequent frontiers; no evidence in the recorded tool events locates the stall.

A sound repair should make registration observe the current operation's cancellation while preserving custody of any admitted origin, and drive all acquired homes and the root to real completion using their paid cleanup authority before publishing terminal cancellation. A per-call token must not be captured permanently by a reusable driver. Do not bypass release, synthesize terminal success, discard retained owners, or infer completion from the acknowledgement. Add phase-specific, bounded progress evidence and regression coverage for cancellation before origin registration, during guest work, and during real retirement; validate terminal state and unchanged durable bytes. A native stack sample or phase instrumentation is needed to identify the actual run's frontier before selecting the specific fix.
