# Dag, Reasoning and Trinity native descriptor publication

The focused catalog fixture independently checked the three committed descriptors before replacement using Ajv. All three failed because the `receiving` policy was absent from the authored layout job. The checked job IDs were `dag.dag.layoutRun`, `reasoning.wires.layoutRun` and `trinity.jack.layoutRun`. The previous [descriptor report](./mcp-tool-run-descriptors-2026-11-20.md) records the older JSON/Pack disagreement as well.

`mcp-native-descriptor.ts` builds and runs the actual composition owner with the pinned Rust toolchain and the authored Hub Cargo lock. The resulting owner invocation installs the actual plugin bundle, queries its descriptor and checks an advertised document codec. It writes the canonical Pack and the matching JSON mirror. `publish-mcp-native-descriptor.ts` applies the exact emitted bytes after the detached fixture passes. It checks component source identity, requires the separately accepted semantic digest and original pair digest, stages both files before renaming, and compares the published bytes to the emission.

The warm retry rebuilt Terrain and World Scene successfully with the current Hub lock. Both source files were already current.
