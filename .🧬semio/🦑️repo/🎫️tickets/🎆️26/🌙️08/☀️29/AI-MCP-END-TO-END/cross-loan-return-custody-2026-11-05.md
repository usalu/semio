# Cross-Loan Return Custody

The current Source-local return budget records item, copy and CPU holds, but the actor receipt transports only original input, aggregate actual retained progress and work. Host `receive_guest_subloan` requires all reported progress to fit the current descriptor's grant, records it as actual spend and clears that descriptor's hold. Consequently, it refunds an earlier call's unused reservation and cannot distinguish later Source-reserved return work from fresh later-call spend. The Source-local hold must not be treated as a cross-actor proof.

An actual fix requires a schema-owned receipt and Host ledger transition that distinguish new holds, actual spend from held stock, unused releases and fresh actual spend on every call. The hold must be bound to the actual guest producer and its Source/frame generation and claim serial, including its original semantic or infrastructure funding purpose. A later return must debit the same hold once, not the fresh later loan; host settlement must preserve the outstanding hold when returning the unused part of the current subloan. Cancellation must release only a genuinely unused claim or consume an actual captured claim, and replay must verify the complete receipt before accepting it idempotently. Aggregate held totals without claim and funding-purpose identity are insufficient when several claims or purposes coexist.

The existing 136-byte SAC3 and 144-byte TurnOutput headers have no fields for those transitions. Keeping the original loan outstanding until its return witnesses settle is an alternative only if the actual actor epoch, call progression and host loan interface support it; current per-call retry settlement does not. No compatibility alias, inferred held amount, capacity-as-copy charge, invented epoch or reservation-as-actual-copy receipt can satisfy this boundary. Native proof must include a one-item two-loan case, exact cross-purpose accounting, cancellation, foreign producer/frame/serial rejection, replay and physical copy receipts.

The ticket's `cross-loan-cases.schema.json` and `cross-loan-cases.json` define the preliminary language-neutral conservation examples. `cross-loan-oracle.ts` validates them with Ajv and SQLite, including a subsequent grant smaller than an earlier held copy extent, separate unused release and forfeiture, producer/Source/generation/purpose/loan/claim identity, and preservation of both failure causes. These model tests passed; they do not demonstrate any production receipt or ledger implementation.

One possible size-preserving wire design uses a Source-owned, preborn escrow-transition capsule referenced by pointer and length from the fixed header. The host would read and validate it while the receipt remains borrowed, settle the loan and escrow atomically, then acknowledge the borrowed header and capsule. InputAdmission would need an eight-byte extension, and TurnOutput a second pointer and length. The existing 184-byte SJH2 job frame could potentially reserve a body word for the capsule by removing duplicated operation and generation from the Step body, provided its writer checks both values against the authenticated embedded input before omitting them. This design is not selected or implemented, and all actual job paths must be audited for claim transitions before excluding any receipt kind.
