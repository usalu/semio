# Note Downstream Wiring Audit

This is a source trace of the SDK journey and the current implementation, not a successful execution. The observed native run stopped during first owned Input; it proves none of the later frontiers. No additional unconditional production wiring defect preventing the requested folder-backed Note create, mutation, undo or restart was established by this audit.

## Create and lifecycle

`mcp-native-journey.ts` invokes `driveOsMcpClientSessionV1`; its typed `artifact_create` sends Note kind without initial content. `create_plugin_artifact` opens the selected Note app and calls `channel.activate(0, scope)`. `ensure_instance_scoped` sends one InstanceOpen, then returns each real lifecycle receipt as an `InstanceLifecycleAck`, continuing until Idle with no outstanding ACK. Guest `poll_kernel_turn` retains lifecycle work in its MoreWork calculation: dispatch admits the opening, the pending native creation resumes across turns, install of the constructed app emits Captured, and an exact ACK advances Captured to Live. The finite scope, budget, exact receipt and actor identity checks can still refuse. The synthetic actor identity is below the 4096-byte runtime cap. These branches appear wired, but no matching successful lifecycle transcript exists yet.

On activation success, create sends `ReadArtifact`. The host translates it to sequenced `ReadDocument` through `CommandBatchDriver`: dedicated command page input, `command_ingress` observation and exact sequence shell reply. The guest's `ReadDocument` arm calls `plugin_document_pack` and returns Document or a typed fault. The host expects an Artifact frame, verifies the SPR's canonical owner matches Note, then uses `FolderEventLogStorage::write_if_current` before adding the in-memory binding. The `persistent_command_completion_port_ready` predicate currently tests static command page limits; it is not a missing registration gate on this path. An absent/duplicate/wrong reply, exhaustion, owner mismatch or refused genesis still fails creation explicitly. Constructor/guest economics and receipt compatibility after the first Input are unmeasured.

## Mutation, history, restart

After create the SDK exports, snapshots, prepares the pinned `addBlock`, invokes and checks a changed head and pair, then undo/redo and rollback. Routing selects the artifact and seeds its stored Pack/SPR and optional archive into the app guest, binds the document backbone, and maps prepare/commit/undo/redo to sequenced guest commands. Folder routing calls `persist_folder_guest` for commit, undo, redo or backbone egress; it reads the guest pair, compares the bound baseline, writes using `write_snapshot_if_current`, and updates the binding only on successful publication. A commit persistence failure is returned as a refused relay outcome; undo/redo persistence failure returns a fault. The test checks warnings and changed journal, so silent success is not established by the mapping alone.

Only after successful redo does the journey capture a pair, launch a fresh SDK session/server, and compare its `artifact_snapshot` Pack and SPR byte-for-byte. A fresh folder workspace can fall through `read_artifact_bytes` to folder storage without an in-memory plugin binding. This checks persistence/readback; it does not itself prove a post-restart mutation or reconstitution of undo tokens. The named commands and serialization/receipt sequences have not been exercised on this captured build; any fault, fixed-owner capacity, actual plugin factory/codec behavior, retry or timing defect may still appear. Next runtime checkpoint is Captured and its ACK followed by the first `ReadDocument` terminal ingress and matching AppFrame; record status, receipt, sequence and pair identity before asserting readiness.
