Tightening copy charges requires opcode-specific proof of every retained mutation, not skipping fuel, copying, deadline checks, or authority. Nop is the clearest narrow case but no opcode distribution demonstrates it will materially rescue this workload. Measured physical receipts and third-party oracle comparisons are required before changing any charge.

The captured guest is a `prototype` component, and the native host binary is debug. An optimized guest is a plausible high-impact experiment because this execution is guest Rust receiving machinery with deep frames, but no profile comparison here establishes an optimum or sufficient reduction. Build the same real Note under the repository release profile, regenerate its canonical descriptor/image, then compare identical Input outputs, VM fuel, physical copy receipts, and elapsed time against this exact witness. Keep existing fixed holds and budgets. A release native host can also improve wall throughput but cannot change the number of metered guest operations or the physical copy budget.

The trace does not isolate per-opcode copy shares or per-turn root selection overhead; per-op histograms and per-component receipt aggregation are the next decisive measurements. Do not adjust the 3 GB limit on inference alone.
