The gateway opens once, forwards each receipt it actually obtains as an exact `InstanceLifecycleAck` and stops at Idle with no owed receipt. The guest stages the ACK against its retained receipt, suppresses the already staged receipt from the next result, and commits `Captured` to `Live` only when the focus turn succeeds below the guest executing clock ceiling. A mere return from Poll or an ingress-level completion cannot stand in for that commit. Skipping it would allow an unacknowledged retained instance and make later commands and cleanup rely on a different authority. The 150-second gateway cutoff and the guest's 5-second lifecycle ceiling constrain different regions. A previous uninstrumented wall failure did not identify the final active frontier. ## Shared work checkpoint

`StepContext::consume_fuel` now updates its `ClockStride` in place when the debit is more than one unit. The stride's `note_work` deducts `units.saturating_sub(1)` cached reads, so zero and one have no clock-state effect. Work posting, Source conservation, the actual deadline checks and cancellation remain in their original paths. This reduces the native interpreter's scalar debit overhead for the installed WASI component, and the same helper applies to guest Source work after a component rebuild.

`source-clock-work-witness.py` builds the exact original and changed `StepContext` source with the same pinned dependencies and O3 settings. It interleaves nine repetitions of each version, each with twenty million single-unit work debits and deadline checks. The tested medians were 164.437 and 81.666 ms, respectively. A first detached run gave 165.858 and 86.308 ms. The neutral `source-clock-work.json` mixed debit tail includes zero, one, multi-unit and full stride amounts. Both Rust binaries agree with the independent SQLite work calculation and produce 20,004,110 work units, 5,890 remaining fuel, no retained progress, 4,895 actual clock reads and the same observed clock checksum 352,336. This microbenchmark suggests roughly four nanoseconds saved per matched debit. It does not establish a whole journey speedup or change managed component bytes or reported VM instruction counts.
