# Failure Pool Metadata Capture

Current implementation is not qualified: the intrusive pool head take/return, local failure-node guard return on unwind, and collision payload attachment perform typed owner writes outside an actual fixed-target Source capture. A CPU work loan cannot authorize these writes.

A genuine backend must retain exact Source-issued opaque claims for stable preborn locations, separate from CPU escrow. The callback must receive a disjoint lender that excludes the selected pool from nested child access. Qualification and preparation happen before the original node leaves its stable slot. The final no-context capture/return must be infallible under that exclusive borrow; a later funded Source observer settles actual writes exactly once and retains all refusal state. The observer may fail without discarding claims, node or causes.

The node has two different destinations at the same address: spare return writes an Option<Box> link; collision attachment writes an entire OriginalRetirementFailure. Their copy extents differ. A single fixed-extent claim cannot truthfully stand for both. The straightforward complete quote requires four distinct exact claims: pool-head Option, stable selected-node Option, node-link Option, and full node failure payload. Only the selected alternative is captured; the unused alternative is later canceled. A smaller representation requires a genuine sealed alternative-extent Source primitive with actual partial redemption, which does not exist yet. It must not report a full-payload write for a pointer-sized link write.

The return algorithm should use one mem::replace of the pool head, followed by the node-link placement and selected-slot clear. The old head.take plus head reassignment writes the same head twice. The full failure payload and parent output capture must also be audited: NativeReceivingEffect currently captures its child RetainedWorkOutcome and changes phase internally; its existing receipt does not automatically prove that a separate pool collision write was authorized.

Job's actual recipient can own persistent ReturnPlace claim state across Source-post refusal. A stack-only guard or numeric work token cannot supply that authority. A prevalidated permit may perform final primitive capture without reborrowing the active Source; subsequent Source observation remains paid and persistent. No Rust backend has been added yet; this report records the precise unresolved contract before implementation.
