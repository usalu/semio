# Seeded WFC Inference Feasibility

A separate folder-seeded MCP inference is supported by the current source and can avoid the editor `InstanceOpen`, provided it starts with a fresh workspace without a session binding. It has not been built or run; it is an independent inference proof, not a typed-create proof.

The tracked actual owner Pack/SPR constants in `✏️s/🔌️plugins/🀄️wfc/🗿️artifacts/🖼️bitmap/🔨️modules/🏠️host/💡️inferences/🧪️tests/🔬️unit/🦀️.rs` are a live-captured genesis pair and the source test decodes and solves them. They are **not** the pinned `initial-artifact.json` solve problem: genesis has a 16×16 input and 24×24 periodic output, whereas the pin specifies 1×1 input/output, seed 1, one black palette entry, pattern size 2, symmetry 1 and periodic input. Thus the genesis constants cannot substantiate the pinned expected `pixels: AA==`, `contradiction: false`, `entropy: [0]`.

For the pinned case, a native owner harness is source-supported: parse `solve` with `semio-s-artifact-wfc-bitmap-snapshot`'s `bitmap_json_decode::<BitmapSnapshot>`; use the real `BitmapMutation`, `create_document_envelope` with `ArtifactPackGenesisProducer`, and `ArtifactStore::<BitmapSnapshot, BitmapMutation>::new::<ArtifactSnapshotPublication>` as in bitmap `🧪️tests/🔬️store-fixture/🦀️.rs`; obtain `snapshot_pack()` and write its Pack/SPR through `FolderEventLogStorage::write_if_current(id, "s.wfc.bitmap", None, ...)`. Relevant packages include `semio-s-artifact-wfc-bitmap`, `semio-s-artifact-wfc-bitmap-snapshot`, `semio-os-kernel`, `semio-os-store-sync`, `pack`, and `semio-framework-async`. Verify the native snapshot decodes to the exact fixture and its SPR owner schema, and read back the identical pair. Actual public exports, build availability, completion, and limits remain to be verified. The owner test installs funded store owners for mutation; whether simple genesis snapshot needs any additional admission must be established by running the harness, not assumed.

For the shortest route, use an isolated disposable folder and artifact ID; seed it once with that owner-produced pair before launching a fresh SDK stdio gateway with the ordinary explicit policies and `inference.execute` authorization. Do **not** call `artifact_open` or create an editor session: no in-memory `PluginArtifactBinding` means `bind_artifact_document` falls directly to `read_artifact_bytes` → folder storage, and `resolve_inference_artifact_document` provides that exact pair to the command. Confirm pinned `inference_list`, then send the same `parseInferenceRunInput` request from `probeWfc` with the artifact ID, kind, schema, plugin, limits, revision 0, generation 1 and cancellation ID. Validate the actual result with `inferenceClientVerdictV1`, the published output schema and pinned values; capture progress, refusal, finite budgets and test outcome.

Source routing: `ActionAdapter::run_inference` sends `AppCommand::Infer`; routing chooses `infer.plugin_id`, explicitly skips session guest seeding for Infer, and `PluginArtifactChannel::exchange` explicitly skips `ensure_instance`. `infer_real` registers the compiled owner, uses the separate `INFERENCE_ACTOR_ORDINAL = u16::MAX`, binds Pack/SPR into declared `document`, and invokes the real `ArtifactInferenceRouter`. `inference_child_dependencies` returns empty when `session_documents` has no matching loaded instance; the pinned bitmap has no asserted children. It would execute `ReadChildHeads` when a matching session document is loaded, so avoiding editor activation is conditional on a fresh unbound state. Calling `artifact_open` first creates a folder binding; with root actions and a routable instance, the binder can call `activate_session`, reopening the expensive editor. The no-binding route's direct persisted read is still gated by `inference_run` authorization, declared service and request validation; its behavior does not require fabricating a binding.

The inference actor still has real guest registration, lifecycle/job execution, retained and wall budgets and can fail or be slow independently. No execution was performed in this audit.

## Fast first independent fixture

The two tracked source constants are `GENESIS_PACK_BASE64` at `✏️s/🔌️plugins/🀄️wfc/🗿️artifacts/🖼️bitmap/🔨️modules/🏠️host/💡️inferences/🧪️tests/🔬️unit/🦀️.rs:331` and `GENESIS_SPR_BASE64` on the following line; they are not separate Pack/SPR files. A first independent real inference can use them without generating a new model: decode the two constants, call `FolderEventLogStorage::new(folder).write_if_current(id, "s.wfc.bitmap", None, &pack, &spr).await`, assert `true`, and read back the identical pair. This writes an ordinary document event; no archive is required. The storage owner exposes `read_snapshot` with optional archive and `read_archive`; `write_snapshot_if_current` is the update API when preserving an existing archive. Do not handcraft its on-disk event layout.

The existing owner law `the_artifact_bound_genesis_document_resolves_and_solves` asserts 16×16 input, three colors, 24×24 periodic output, pattern size 3, symmetry 8, noncontradictory solution and 576 pixels. These are independent semantic invariants for the genesis fixture, supplemented by the published output schema; the law does not provide a fixed exact output byte string. A stronger comparison would run the actual native owner solver over the same pair or validate all local windows against the input. Neither proves the separate pinned 1×1 case. This larger fixture may take substantially more resources, so retain the published explicit budget and report any exhaustion honestly.
