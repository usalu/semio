# Shard-Owned Core Poll Source

The shard reaches the obsolete pointer-and-length call twice. Its first Event runs `OriginalShardIdentity::admit_actor_original`, and the Owned runtime encodes the context admission arguments as JSON and passes the allocated byte pair through `begin_owned_operation`. The Owned context close uses the same path. Once admitted, `OwnedRuntime::execute_actor_turn` sends another byte pair straight to Poll. The current guest exports each take the nineteen scalar fields of `OriginalJobBudget`. Input alone takes a byte pair followed by those nineteen fields. The shared tuple makes the Poll JSON appropriate for Input admission.

The instance path must change with dispatch. The child and the shared-thread registration API receive an already instantiated `GuestInstance`. Ordinary Owned instantiation sets `actor`, initializes the channel, and leaves `original_core` and `original_source` empty. Paid startup produces the opposite original core and source fields under the caller's actual Source. The staged input, scalar, frozen escrow and actor-failure routines require that original core. The detached job drive uses `actor`, and `begin_owned_operation` expressly refuses an instance with `original_core`. Checkpoint accesses `actor`, restore refuses original instances, and dropping the original instance asserts prior retirement. Moving only Poll to paid startup would therefore break ordinary registered actor job dispatch and checkpoint/restart.

## Existing authority and the minimum integration

1. **Register the compiled opening under the Kernel-issued actor generation.** Change the Owned shard's stored registration from an unfunded finished instance to the compiled opening and original authority held by registration. Extend both packaged dispatcher entry points, where applicable. The process child must wait for the first authorized activation grant before driving startup. Admit a resident `OriginalActorContextSlot` under the exact first `RetainedTurnInput` delivered by the Kernel. Its paid admission and `begin_pending_context` / `dispatch_pending_step` provide a genuine `StepContext` and the actual debit. Keep the compiled/artifact, resident Source and native producer stationarily owned until paid actor retirement. `OriginalCallerChildSource` can provide a child Source when a stable issuer needs a separate identity, since it borrows and returns under the real parent. Preserve the long-lived scope required by `GuestPoll::begin_next_step`. An Event-local fresh native Source cannot access the resident original Core. If existing activation stock cannot fund the Source, extend the Kernel's authored activation policy or require a new valid generation after close.
2. **Borrow the existing Poll transitions behind a Source driver.** Extract the staged driver portion of `GuestPollSession` from the concrete `GuestRelayWakeDriver` and its root bootstrap. Keep `GuestIssuedHistoryHome`, `GuestFrozenHistoryCapture`, receipt and bootstrap handback, actor failure capture, and typed `GuestPoll` in the shared path. The in-process caller continues to use its relay driver. The shard implementation borrows its resident slot and uses the exact held grant to fund each step. Use the same host reserve/transit/infrastructure/semantic partition and its paid guest ledger or extract that ledger from the existing relay driver. Hold the exact producer and guest descriptor until the header is journaled, reconciled, acknowledged, and released. Do not use actor-frame epochs as consecutive guest export epochs. A host scope can return while a guest subloan remains resident across several frame callbacks. The guest descriptor and escrow may move only through the existing issuer/history handback protocol.
3. **Fund VM credits separately from semantic work.** `ShardFrame::Grant` already carries scheduling instruction fuel next to the original retained/work loan, but `ShardOutcome::OriginalCall` carries only the raw original retained/work return and an optional one-stage fixed record. Implement a finite and checked VM execution recipient beside the retained recipient. Reserve before dispatch, narrow against the actual live callback after host charges, receive actual `OriginalGuestExecutionReceipt` exactly once even on cancellation/failure, and gate return on settlement. Carry its actual delta back to the issuing Kernel or production scheduler owner if it owns the VM currency across transport. `GuestRelayWakeDriver::execute_current_original` alone is unsuitable because the thread-local loan is tied to a concrete driver and exact callback address. Share the scoped execution helper or thread the host credit explicitly. Also author a cleanup reserve and deadline before starting semantics. Current Kernel admission clips its remaining semantic loan with each receipt and stops scheduling when it reaches zero. Unregister currently removes the grant and instance immediately. Add an explicit funded cleanup continuation and cancellation observation on the same Source.
4. **Preserve the original Event and stable input binding.** Keep the first `OriginalActorInput<Event>` on the existing deferred authority. Make its address stable after admission or expose the exact lease in the resident native home. The deferred ring presently takes and reinserts owner values. Building a fresh `EventJsonSource` at a new address for each native callback cannot prove the same source. Use the staged event/body/page extraction, reserved encoding and tagged limits tuple, and keep its original addresses through pauses and resumed admission. Let staged Boot/Input transition the Event from pending through ready. Remove old context admission for Owned at the Pending branch. A new Event is rejected while the first is in flight. A typed guest `MoreWork` retains the existing Event and sends an empty continuation input only after the previous staged round settles. A mere VM or host frontier pause sends a parent continuation receipt with no delivered output. Recheck physical and semantic minima before allocating or resuming.
5. **Receive output and settle the actual parent once.** `GuestPoll::deliver_step` offers `&T` and retires the capture afterward. Give the shard a paid output receiver in the owning Source for only the published effects, UI patches, presence, status and lifecycle. Reuse `to_actor_turn_result_in_place` where a paid transfer provides a proper owner, or add a controlled consuming delivery at the native capture. Keep the guest result's child receipt for local validation and do not substitute it for a parent return. Charge the actual host infrastructure and reconciled guest physical/work deltas to that Event once, settle `OriginalActorInput::return_actor_turn` with `IssuedShardTurn::settle_envelope`, then carry only the scheduler receipt over the outer transport. Until the failure Source is returned, a copyable diagnostic is only metadata. Do not end the Kernel continuation on early scalar refusal while guest escrow, the original Event or its native producer is live. Preserve the mesh output handback and job admission ordering, then retire the Event. On final release, retire in-flight guest output and input, run staged close of guest context, and receive retirement of the producer, history, resident Core, and parent Source before unregister completes.
6. **Cut over other calls on the same original instance.** Audit the Owned shard job, replay, checkpoint and restore entry points as part of enabling that registration kind. Route the job operations through the existing paid scalar/unit/output machinery, with general job action plans derived from the actual action shape. The headless cold controller's document workflow cannot be used as the shard's generic job dispatcher. Checkpoint/restore needs its funded original Core counterpart and consistent instance generation. A split between the old actor handle and a paid Poll handle would split actor state.

`ShardOutcome::OriginalCall` already gives the Kernel one receipt before the next `ContinueOriginalCall` envelope. Keep that sequencing for parent receipts, keep guest fixed records in shard custody, and avoid forwarding child inputs as aggregate Kernel inputs. In the current renderer, observing a fixed `Failure` record exits the loop immediately, so production fault publication must distinguish final refusal from a cleanup continuation. The direct host tests must cover both that receiving path and the packaged worker.

## Verification and remaining work

[Boundary fixture](shard-owned-core-boundary.json) and [independent Wasm runner](shard-owned-core-boundary.ts) checked five real exports. Repository-pinned Bun accepted Note digest `54f349f614c4607c6bfe046d35165336db509bd579b7740e7dbd905af4b5db02` and WFC digest `39904b6132290fd5d453fe2fccbe2b0e9d873c559292a0875007cf4d90fab58b`. Node 24.15.0 independently checked the WFC artifact. Both engines saw the old two-i32 crossing rejected before guest work, and the new arities returned scalar refusals for zero authority. This witnesses the actual guest ABI, including the early context-admission mismatch. It uses retained existing artifacts and makes no successful-lifecycle claim.

[Receipt scenarios](shard-owned-core-receipts.json) describe seven portable acceptance traces, including a guest loan that survives an intervening parent return, a cancelled frozen receipt with a paid release, and rejected donor substitution and duplicate return. The [reference transition model and SQLite oracle](shard-owned-core-receipts.ts) agreed with each expected remaining stock and rejection point. These explicitly authored traces specify the production tests still required. The independently computed SQLite totals cover conservation, and the state model checks transitions.

The production cutover needs a funded end-to-end regression through `ShardLoop::pump` with the real component. Exercise activation, paid Boot, Input denial/resume with wire identity retained, 19-scalar Poll, typed result delivery, second Event on the same resident instance, and quiescent retirement with exact Kernel receipts. Assert rejection of another operation/generation/clock, a different wire, a replayed or inflated guest receipt, and early instance removal. Repeat with cancellation before submission, during a resident input slice and at frozen output, and with a typed guest failure. Check that finite work, VM and escrow budgets have their actual independent returns and that a zero-delay denial preserves the original. Existing fixture `owned-instance-open::a_mid_flight_owned_turn_refuses_new_events_instead_of_dropping_them` only checks the old direct fuel cut, so it cannot serve as the successful boundary regression.

Production source carries no changes from this audit. The smallest authentic integration spans Kernel grant and cleanup, shard registration and dispatch, and the common staged guest producer. An interpreter-only patch would route neither the initial context correctly nor return the original actor operation safely.
