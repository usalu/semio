# Guest Input Work Audit

The 1,347,018,726 scalar instructions and 3,221 clock imports in the first 601-byte Note Input are replay observations, not a source-level profile. The following is a static audit of the current source; no rebuild, instrumentation, or source change was performed, and the exact captured component's correspondence to current source has not been verified.

## Actual path and representation

The owned export creates `OriginalActorInputReceiving` and `advance_in_turn` repeatedly invokes `advance_step` while paid work advances. The successful path calls `OriginalJsonOutputSource<ActorInput>::receive_step`, `OriginalNativeDecodeSource::receive_step`, `OriginalJsonOutputReceiving::advance`, and, in its parse phase, `JsonGrammarCursor<DslValue>::step_source`. After parsing, the same source admits a retained `DslValue` source, constructs a `NativeReceivingOriginal<DslValue, ActorInput>`, advances the typed receiver, takes the result, and closes the parser and decoder before returning the input. Thus the wire is first materialized as a generic tree and then received again as a typed tree, with admission and retirement around both.

## Amplification mechanisms

* UTF-8 validation precedes grammar and advances one Unicode scalar per work unit. `parse_work_quote` batches at most 256 validation units, bounded by one quarter of the remaining source bytes, but after validation the quote becomes one. Consequently ordinary grammar units pass through the entire native decode/retained effect machinery individually. This is independent of the 601-byte wire being small.
* Strings are walked once to measure their decoded length and again to materialize, with one output byte per turn and a separately admitted allocation. For each object key the parser tests every previously parsed key, then compares equal-length names one byte per turn. This is quadratic in member count in the worst case, with additional work for shared prefixes. `normal_step_demands` also checks frame state and computes the next physical grant on each turn. The earlier UTF-8 pass means ordinary text is traversed at least three times. The exact mix of parse versus typed receiving in the captured execution is unknown.
* Each outer `advance_step` first validates the original parent and borrowed binding, admits or settles a return place, obtains a decode grant, and sends the next frontier through `OriginalNativeDecodeSource::with_control`. That reconstructs a forwarded frame and nested allocation, work, and construction authority loans. `ActualTurn::with` gates callbacks using an atomic compare/exchange and the work context repeatedly checks source validity and yield/cancellation. Work accounting records semantic units, not a fixed upper bound on Wasm instructions for these control layers. `should_yield` may read the operation clock; the transcript independently records 3,221 imports. These mechanisms plausibly amplify many one-unit grammar and typed-receiving steps, but the profile does not identify their individual share.
* The `NumberScan::finish` float path scans up to 1,200 source bytes and calls `parse::<f64>()` as a single grammar advance; long input has bounded but still substantial normalization. This is a possible undercount for floating numbers, not an established explanation for the captured fixture without checking its exact scalar values and profile.

## Native Note Poll reconstruction

The candidate generated by `reconstruct-native-note-poll.ts` has that exact length and fingerprint. The matched candidate and the logged scalar header are in `🗑️generated/native-note-poll-exact.json` and `🗑️generated/native-note-poll-scalar.json`. A 64-bit noncryptographic fingerprint does not prove byte identity; the source-derived fields and ordering provide additional evidence, but a direct capture remains the stronger oracle. This is not the 601-byte neutral fixture used by the earlier replay.

Its work similarly subtracts all three reserves. It does not serialize the unmodified driver stock or the later scalar subloan. Remaining limits are effects 256, patch bytes 1,048,576 and frames 256.
