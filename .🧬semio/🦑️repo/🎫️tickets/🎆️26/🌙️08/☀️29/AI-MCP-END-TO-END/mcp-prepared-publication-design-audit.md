# Prepared Model Publication Audit

## Finding

The existing component model publication is the narrowest first-party custody boundary for a cross-process prepared actor image. `🔌️plugin/📦️model/🟦️.ts` lines 40–48 admit declared compiler outputs under writer custody. Lines 62–81 retain the actual descriptor emission and linked component identity, create the receipt, copy and SHA-256 check the linked bytes, and atomically stage the complete model. Add preparation there while that exact linked component remains in custody, and publish the image as part of that same owned artifact roster. There is no existing physical prepared-image writer or reader.

`🔌️plugin/📦️model/👓️reading/🟦️.ts` lines 23–27 enforces the exact four-file roster, checks component header and SHA-256 against the receipt, checks descriptor identity and semantic digest, and rechecks retained custody. Extend this contract and validation together for a prepared image. The schema and artifact request file count are in `🔌️plugin/📦️model/🧬️schema/🔣️.json` lines 4–10 and `🔌️plugin/📦️model/📋️contract/🟦️.ts` lines 13–19. The writer must derive the image from the actual bytes it owns and bind its digest to the same publication, including component digest, owner, build mode and format version. A supplied digest or matching mutable sidecar alone cannot establish that an image resulted from the constructor. The trusted provenance is the controlled producer and the retained publication, with hashes checking the actual bytes. Confirm the generic artifact custody and publication semantics before relying on it against concurrent replacement.

`🌉️mcp/📡️stdio/📦️component-models/🟦️.ts` lines 33–71 already retains all available model artifacts throughout the native child, verifies each with the model reader, and passes its root, plugin ID and crate path. `🌉️mcp/🏠️workspace/🧭️plugin-paths-and-descriptor/🦀️.rs` lines 103–145 validates mode, canonical root suffix, catalog owner and component location. Reuse that retained root and the reader-verified owner outputs rather than introducing a separate cache or arbitrary sidecar location. The native consumer must bind the image to the actual component bytes it loads, including a full component SHA-256, and to its decoded exact actor module before issuing a prepared image. The current root manifest contains no digest and does not itself authenticate contents.

## Interpreter boundary

`🔌️plugin/🧠️interpreter/🔌️owned-semio-boundary/🌱️preparation/🦀️.rs` lines 9–51 prepares the actor module, runs its explicit constructor without host imports, checks scalar readiness, supports cancellation and seals the quiescent result. `🔌️plugin/🧠️interpreter/🏗️instance/🧊️prepared/🦀️.rs` lines 15–51 validates shape, references, segment content and quiescence and binds the result to the in-process module `Arc`. Restore must reconstruct using the freshly decoded exact actor module and reseal through these checks before attachment.

`🔌️plugin/🧠️interpreter/📸️checkpoint-codec/🦀️.rs` lines 6–28 and 44–92 already serialize and restore Core resources, including an optional running machine. This is a useful codec starting point, but its 64-bit module fingerprint is insufficient as the publication content binding. Restore accepts an optional machine and its resource checks are narrower than `PreparedCoreInstance::seal`. A prepared-only reader must require no machine, apply the seal validation, impose finite read and allocation limits, and verify the full staged component/image digest under custody. The current writer accepts a `CoreInstance`, while `prepare_actor` returns a sealed `PreparedCoreInstance`, so a controlled prepared-image encoding interface is still required.

`🌉️mcp/🏠️workspace/🧊️compiled-components/🦀️.rs` lines 72–75 and 99–151 use process-local component and preparation coordination. Its `prepare_compiled_actor` runs preparation in the requesting process. This cannot supply a new process with precomputed constructor state. The isolated compile flight at lines 349–353 addresses compilation only, so it does not establish a cold actor-start deadline. No measured cold SDK deadline follows from these source paths. Test a fresh launcher and fresh native child with the real staged model, including cancellation, stale or replaced binary, corrupt image, wrong owner and mode, and independent reference validation of the image contract.

## Scope and limits

Source inspection only. No build, benchmark or cross-process timing was run. Generating and safely restoring the image are new implementation work. An image hash tied only to a mutable receipt does not prove execution provenance if an adversary can replace the whole publication. The existing model custody boundary must remain held through the native consumer, and its actual replacement guarantees need verification before selecting the final trust mechanism.
