# MCP Guest Poll Runtime Stack Audit

The fixture's stack overflow cannot be classified as cold compilation only from the available evidence. The native MCP guest poll executes synchronously on its caller's thread; some callers do not have an explicit stack budget.

- `🧰️framework/🔨️modules/⏳️async/🖥️native-pool/🦀️.rs:244,301` gives framework pool workers an explicit 64 MiB stack. MCP HTTP and workspace construct this pool (`🌉️mcp/🚚️transport/🧾️http-surface/🦀️.rs:228`, `🌉️mcp/🏠️workspace/🦀️.rs:5–7`). This applies only to work actually running on those workers.
- `🌉️mcp/💡️inference/📤️submit-and-guest-jobs/🦀️.rs:43–47,65–67` creates a separate `semio-inference-*` native thread without `stack_size`, and calls `run_guest_inference` there. `🌉️mcp/💡️inference/🏃️run-handler/🦀️.rs:82` calls `actions.run_inference`, which synchronously invokes `exchange_blocking` (`🌉️mcp/🔀️dispatch/🦀️.rs:77–80`). `exchange_blocking` drives the channel future locally with `block_on` (`🌉️mcp/🔀️dispatch/🔌️channel-port/🦀️.rs:356–357`); the pool's explicit stack does not follow this direct thread.
- Native plugin activation opens and turns the poll directly (`🌉️mcp/🏠️workspace/📨️plugin-artifact-channel/🧩️instances/🦀️.rs:43–57`). `open_poll` invokes `GuestPollSession::open_step` and `poll_turn` advances the poll inline (`🌉️mcp/🏠️workspace/📨️plugin-artifact-channel/🔁️native-poll/🦀️.rs:51–62,69–`); ordinary native turns likewise call `poll_turn` inline (:33–37). The stack therefore belongs to whichever caller drives activation or exchange; it is not intrinsically guaranteed by the session.
- Shared component compilation can run in a separate compile-worker process; `semio-compile-flight` is an observer thread (`🌉️mcp/🏠️workspace/🧊️compiled-components/🦀️.rs:440–455`). Native poll receives a compiled origin from the process cache (`instances/🦀️.rs:43`), so fixture cold-compilation stack pressure and runtime poll pressure must be measured separately.

The fixture's observed 2–3 MiB failure and 4 MiB pass establish only the fixture path and host. No production stack measurement or build was run in this audit. Verify real typed activation and inference on the actual entry threads, including a low-stack subprocess test; set an explicit appropriate stack on every native path that drives the guest if the measurement requires it.
