The public request supplies bounded DATA caps; it cannot supply internal turn authority. The host projects identity-free per-operation caps, reserves cleanup inside the same finite Source, and issues unique operation/generation plus a real clock binding at admission. Current authored caps have independent AJV/SQLite law coverage and strict TypeScript verification; native wake tests are running through the repository owner and are not yet claimed passing.

A confirmed execution gap remains in the old cold relay: every asynchronous guest crossing creates JobFunds::self_issued. The funded outer worker does not fund that inner guest call. The replacement must use one synchronous Owned original crossing per actual callback, with OriginalJobTurnLoan settling exact returned CPU/retained spend and a sealed VM receipt from the same Source. Whole physical replies and returned sources remain in retained owner custody before receipt validation.

The native Core correctly rejects resources born under a different Source. Cold stateless inference therefore births, runs, and closes a real Owned instance under the exact per-request Source; only immutable compilation/descriptor data may be cached. This does not relax Core identity checks. The job returns its paid native loan before the request closes the actual instance and finally the operation Root. Cleanup failure must retain bounded live owner custody, preserve both body and close faults, and must never be reported as success.

The synchronous body, origin return and actual native execution remain incomplete until their genuine close ports are composed and actual native tests pass. Warm gateway initialization and transpiled source tests are not native readiness evidence.
