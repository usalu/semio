# Native Enum Receiving Storage Audit

The enum derive (`🧰️framework/🔨️modules/🌱️value/✨️derive/🛬️receive/🔀️enum/🦀️.rs`) generates `Option<Selected>` inline. Each selected arm contains a `NativeReceiveSlot` and `ManuallyDrop<Option<carrier>>`, so Rust sizes the option for its largest arm. Phase 0 quotes the entire option plus flags and assigns the selected arm; closing quotes the entire option again when clearing it. The selected value is logically exclusive, but the receiver seed and assignments can carry the largest alternative’s physical layout. `NativeReceiveSlot` itself owns `NativeOwnedStorage<Receiver>` plus inline `Option<T>`; generated record receivers contain one slot and pending option per field and an inline output option. This compounds receiver size across nested shapes. These are layout-based obligations; the exact actual machine writes and largest active arms must be measured on the live build before attributing the observed burn to them.

Record partial storage (`…/🧩️record/📦️storage/🦀️.rs`) already reserves `Layout<T>` without initializing the entire record: initialization marks a boolean, and individual fields are placed under their field move quotes. Completed publication still quotes the full record and destination option, and generated enum phases 3–4 quote the carrier and output options. Thus active actual values and allocations retain real physical obligations even after inactive variant overhead is reduced.

## Narrow candidate if live replay remains excessive

Generate each selected arm as a small `NativeOwnedStorage<VariantState>` handle, with the current slot and pending carrier in the concrete variant state. Keep selection, schema metadata, wire names, original source projections, and receiver identity unchanged. Split phase 0 into selection, selected-state reservation, and seed steps. `reserve_empty` quotes the actual selected layout capacity and pointer write; seed must quote the actual selected state initialization, using a resumable template where necessary. Existing `initialize_seed` still copies the full selected state: indirection removes largest-inactive-alternative inflation, not selected-arm work. Do not charge a smaller quote for a larger actual assignment or simply box an unaccounted temporary.

All pending turns and their original work/source identities must remain resident across each phase. Normal close and cancellation need explicit paths for selected-but-unreserved, reserved-but-unseeded, partial seed, initialized child, and pending carrier. First settle child and retire any pending value using existing original-control routes. `NativeOwnedStorage::release` refuses initialized owners, so add a narrow paid in-place terminal-state teardown that proves the state empty, drops it in place, clears its initialized flag, and then releases the same allocation with its real release receipt; avoid `take_into`, which moves the entire state. Partial-template release must preserve its original work binding. A fresh capacity allocation and eventual release are real costs, so compare measured receipts and latency rather than assuming a net win.

Verify every cancellation boundary and interrupted effect, including original-birth recovery, failed allocation, partial template seed, selected-but-empty, pending value, and terminal drop. Compare actual allocation/copy/release receipts and schema-equivalent decoded values against the unchanged language-agnostic and third-party fixtures; retain the existing budget and test the real Note event. No implementation or replay was performed in this audit.
