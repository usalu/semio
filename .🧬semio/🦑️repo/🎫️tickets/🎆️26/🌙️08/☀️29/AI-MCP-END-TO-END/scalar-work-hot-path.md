# Paid Scalar Work Hot Path

The interpreter meters each executed instruction in both execution fuel and physical Source work. It also charges work for frame bookkeeping, in-memory moves, and other paid steps between instructions. The driver separately excludes the held guest work and protected cleanup work from each host checkout. A Note run can therefore exhaust a 1 billion physical-work policy before its execution receipt reaches 1 billion instructions. The wider-work Note probe reached a real 745-byte output, then refused at `ParserClose` after 920,157,956 VM instructions and 88.2 seconds. The wider run establishes the activation cost and stage reached. It does not measure the physical-work split across host and guest.

An ordinary scalar previously re-read the live Source fuel after the same loop iteration had already checked it. The scalar decoder and its operand validation execute without any callback or work debit. That branch now keeps its existing last deadline check and records one unit of physical work directly. The stack-growth branch still checks the live grant again after paying for growth. The existing cancellation check at each loop boundary remains in place. The change reduces host accounting overhead, with the same physical-work and execution-fuel totals.

The detached benchmark built both interpreter versions with identical pinned Rust compiler options at optimization level 3 and the same warmed dependencies. The baseline used a temporary generated source view that reverted only the changed scalar charge. All remaining source inputs were hardlinks. An independent Bun WebAssembly engine returned the same loop result, 1,000,000. Both paid interpreters posted exactly 7,000,006 executed instructions, 7,000,013 work units, four retained items, 192 copy bytes, 304 capacity bytes, and 96 released bytes. Seven interleaved runs gave 750.912 ms baseline median and 693.987 ms candidate median, a 7.6% elapsed-time reduction on this loop. No Note speedup is measured for the candidate.

The language-neutral metering suite passed one test and 167 assertions with the supported orphan-census opt-out for the sandbox. The production interpreter source closure is 244,863 bytes, 20 files, and 3,836 active lines on each of the macOS, Linux, and Windows target checks. The host executable was not rebuilt for the benchmark.
