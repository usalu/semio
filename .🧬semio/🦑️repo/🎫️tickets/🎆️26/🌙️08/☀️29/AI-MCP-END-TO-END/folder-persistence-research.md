## Audit Follow-up

The initial folder patch was incomplete for recursive archive replacement and post-write flush failure. The store now folds the newest document event across both representations. Reads project the newest archive root through the existing owned archive decoder; bindings retain its exact archive bytes. Expected-custody append compares that exact archive under the same mutex/file lock, updates the root pair and retains every member. Its returned publication bytes update the binding and seed baseline without a racy second read. A later pair event stops read_archive from reviving an older archive. The actual guest is seeded with the full retained carrier through the existing stepped archive load loop.

After a record-write or durability failure, append restores the previous valid tail and flushes it while still holding both writer locks. A restoration failure preserves both error descriptions and explicitly reports uncertain durability. Readers take the corresponding shared file lock, so they do not observe an in-flight unflushed append. Three private store laws inject the real post-write flush boundary, check one-shot rollback and persistent rollback failure, preserve recursive members under exact archive CAS, reject a changed member-only peer archive, and replay pair/archive order. These private native laws are authored and queued; they are not yet claimed passing.

The two independent SQLite/Ajv laws pass 26 assertions using shared JSON/CSV vectors. Registered strict TSC for the updated oracle exits 0. The MCP source target hashes the new CSV/schema inputs. Exact artifact alias reads precede plugin-only shell fallback. A real document pair no longer marks a folder binding as a hub binding: surface identity governs the hub-selection policy, and the existing two-folder-artifact regression now carries genuine document pairs.

Measured native closures: MCP root 24 files, 260,965 bytes, 3,599 active lines; native store test closure 19 files, 217,222 bytes, 3,991 active lines. Existing multiline native storage/actor narratives moved to sibling README files and redundant declaration separators were removed. No executable statement, assertion, source policy or admission guard was removed or enlarged. Actual guest commit/undo/redo persistence still requires the real note guest and native server journey; storage byte-pair laws alone do not establish that integration.
