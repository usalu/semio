# Canonical Guest Profile Audit

The configured `.mcp.json` launcher reads managed component model publications. Their Wasm is the exact linked Rust `wasm32-wasip2` component, not the browser bundle's `wasm-opt -Oz` result. The component driver's `describe` and `model` stages consume the linked component; `transpile` and `optimize` operate on browser cores independently. Model publication requires the live declared component, its privately retained descriptor emission, provenance, and writer custody. The optional prepared actor image is bound to that component digest. See `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🏗️build/🧩️driver-stages/🟦️.ts` and `../../📦️model/🟦️.ts` from that build directory.

The central Cargo profile policy derives `component` from artifact + `wasm32-wasip2` (or `wasm-component`) and selects the actual mode, not the fallback script's `dev` profile. Prototype component target settings are `opt-level=s`, debug 0, 16 codegen units, incremental false, thin LTO, assertions and overflow checks enabled, symbols stripped; host build override is O0, debug 0, 256 units, no incremental. Release Wasm is also size optimized with thin LTO; prototype package overrides do not apply in release. `.cargo/config.toml` supplies the 512 MiB memory maximum and 8 MiB stack. The ticket fallback instead uses `dev` with O1 WFC packages and optional O2 receiving packages, different flags and no thin LTO. A passing pending SDK measurement therefore shows that particular fallback works, not that adding O2 to the canonical size-optimized guest improves it. Qualify the actual canonical bytes before adopting the performance change.

If canonical measurement supports it, add the receiving package rows from `mcp-native-guest-build.ts` (`receivingProfile`) with `optLevel: "2"` under `groups.runtime.wasm` in `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🏗️build/🎚️mode/🦀️profile/📋️constraints/🔣️.json`, avoiding duplicates. Hub's registered workspace maps to `runtime`. This shared group affects all owners mapped to it and both component and browser roles; confirm that intended scope or introduce a narrower explicit policy with corresponding schema before changing it. Policy validates and snapshots the DATA, merges native then wasm constraints for prototype, sorts the overrides, renders exact `profile.prototype.package.<name>.opt-level` selectors and checks the consumed effective configuration. Check schema capacities and update language-neutral inventory counts and digests in `🧪️tests/📥️consumption/🔣️.json` and related role/selector fixture cases under the same profile owner; keep independent Ajv/TOML/SQLite checks. Do not inject unissued Cargo flags or modify the fallback as a substitute for canonical policy.

The supported fast path is a genuine describe-stage cache hit: `describeComponentStageV1` keys on exact component SHA-256, emitter SHA-256 and actor-preparation schema version, then validates the recovered JSON/Pack and identity. A changed guest or emitter misses that cache. On a miss, supported publication requires running the owned emitter against the exact new bytes with `--prepare-actor`; hashing, an old descriptor, and a direct SDK fallback do not create the publisher's live emission or prove managed publication. A model-only `components describe` facet exists, but still runs this semantic stage and publication; it is not a byte qualification shortcut. No build, network access, or publication was performed for this audit.
