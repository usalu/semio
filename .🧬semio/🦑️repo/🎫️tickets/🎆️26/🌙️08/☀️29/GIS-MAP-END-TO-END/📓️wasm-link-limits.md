# GIS WebAssembly Function Limit

The final GIS link reached core WebAssembly generation, then pinned `wasm-component-ld 0.5.26` failed when encoding the component. The validator reported the 1,000,000-function limit at offset `0x1d11`. That location identifies a validation boundary, so it does not quantify the excess or code size. The W3C browser API imposes a 1,000,000-defined-function ceiling. The wasmparser function index validation also includes imports, so measure both. Tightening the numerator while preserving feature coverage is the portable fix. ## Preserve a diagnostic baseline

- The pinned linker's help confirms `--skip-wit-component`, `--wasm-ld-path`, `--Map`, `--why-extract`, and `--reproduce`. Tagged source explains why the failed normal run left no complete output. LLD writes to a temporary directory beside the final destination, and the linker cleans that directory when component encoding fails. The failed work lane retained GIS codegen objects and all 1,078 absolute `.rlib` inputs printed in the build error. The printed line is abbreviated, including sysroot library shorthand, and enumerates 103 explicit exports. [Pinned linker source](https://github.com/bytecodealliance/wasm-component-ld/blob/v0.5.26/src/lib.rs#L560-L607)
- When collecting a baseline during the next authorized link, preserve the ordinary linker and adapters and use an isolated `--wasm-ld-path` diagnostic wrapper around the same pinned LLD. Invoke `rust-lld -flavor wasm` when the delegate is Rust's multiplexer. On successful LLD exit, copy its `-o` bytes into the ticket before passing its status back so the normal encoder can continue. Keep all export flags and input ordering. This gathers raw core bytes and the ordinary component result with one LLD execution. When only core data is needed, replay a complete recorded invocation with `--skip-wit-component` and a ticket output path. A shell replay of the abbreviated rustc diagnostic is insufficient. `--save-temps` is LLD-owned, and the component linker's temporary output still has its normal lifetime. `--reproduce` packages the link inputs and can cost markedly more disk than a map or the raw output. [Pinned linker options](https://github.com/bytecodealliance/wasm-component-ld/blob/v0.5.26/src/lib.rs#L700-L733)
- Measure the raw core with a read-only binary scan that skips bounded section payloads by unsigned LEB128 lengths. Record core version, total bytes, section 3's defined-function count, section 2's imported functions, section 10's body count and payload length, and export names with kinds from section 7. Check section 3 and 10 counts agree. Report the amount above the wasmparser limit as `max(0, defined + imported - 1_000_000)`. Check section 0 for `component-type*` metadata, and record data-section size separately. An LLD map aggregates retained symbol and code sizes by input archive, and `--why-extract` traces why archives joined the link. Summing raw archive or object functions would include dead and duplicate definitions. [Binary module format](https://webassembly.github.io/spec/core/binary/modules.html) [LLD garbage collection](https://lld.llvm.org/WebAssembly.html#garbage-collection)

## Compare targeted reductions

1. For a small measured excess, test Binaryen's existing pinned `--duplicate-function-elimination` first on the captured core. Try `--merge-similar-functions` and size passes as separate measurements. A post-link rewrite has to preserve names and kinds of core exports, component metadata, target features and canonical ABI, then componentize with the same adapter selection and validate the resulting WIT world and browser launch. Compatibility of Binaryen's reader with the oversized module and this feature set remains unverified. Post-component optimization only becomes available once the core fits the encoder.
2. For compiler changes, compare size-oriented `opt-level=s` and `z`, then explicit thin LTO in a separate measured build if needed. Keep target, feature set, exports and input semantics fixed. The current command already enables `--gc-sections` and `--strip-all`. Stripping debug and compressing relocations may reduce bytes, while the validator still counts the same functions. The pinned wasm LLD help exposes LTO controls and no identical-code-folding option. [Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html) [LLD WebAssembly documentation](https://lld.llvm.org/WebAssembly.html)
3. For a large excess or slow optimization, use the map and archive extraction evidence to identify non-GIS feature roots. Reduce reachability or split ownership behind genuine WIT boundaries while preserving real exports and dynamic dispatch. Check the resulting per-core function total, core and component size, browser publication and initialization, and GIS artifact operations. This is a larger implementation with a durable budget.
