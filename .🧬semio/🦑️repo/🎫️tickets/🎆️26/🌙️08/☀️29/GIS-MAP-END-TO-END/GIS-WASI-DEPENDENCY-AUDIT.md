# GIS WASI Dependency Audit

The GIS composition's normal Cargo dependencies include `semio-s-artifact-stdio-semio` and `semio-hub-stdio-catalog-definition` (`🌎️hub/🧩️compositions/🌍️gis/📦️packages/🦀️rust/Cargo.toml`). Its source instantiates `SemioMembers` for both map apps and requests the native catalog dependency and contribution (`🌎️hub/🧩️compositions/🌍️gis/🦀️.rs`, lines 28–29 and 38–39).

The semio artifact's normal dependencies include `semio-s-artifact-stdio-semio-brep`. Its source declares and registers B-Rep I/O and includes B-Rep in member dispatch (`✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🧿️semio/🦀️.rs`, lines 42, 85, 118 and 162). The B-Rep package normally depends on 3D B-Rep tessellation, queries, representation, surface and curve packages. This is a genuine transitive path in the current architecture; removing the edge would remove canonical B-Rep declarations or dispatch. The full stdio catalog independently includes the semio catalog and its B-Rep conversion dependencies. Avoiding the 3D compile while preserving the canonical catalog would require a broader factoring of definitions and member types from implementation, not a quick dependency deletion. No such change was made.

`withSelectedNativeSnapshotV1` is an existing finite, charged snapshot for selected Native graph inputs. `selected/🦀️rust/🟦️.ts` supplies selected Native/Nx graph input paths rather than the actual Cargo compilation source closure. Its callback rechecks the original source after the child completes, and its tests expect a concurrent edit to fail. It creates a separate source root under graph cache, so it is neither an established immutable Cargo compilation mode nor compatible with the no-shadow-repository constraint. Cargo admission instead captures the actual unit graph and source closures in the original workspace.
