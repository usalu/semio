# GIS Stdio catalog source admission

The previous prototype failed before Cargo launched at source-admission unit 424 of 1,051. Its definition-only catalog crate directly included artifact definitions from 38 owners. The admission reader exhausted its source-byte allowance at the semio definition, which was 37,154 bytes with 25,682 bytes left. The breached entry was 31 files and 273,616 bytes against the repository limits of 32 files and 262,144 bytes. The full direct roster would also exceed the file limit.

The current shared producer replaces those compiler inputs with one bounded raw-DEFLATE bundle. It still reads, observes and rechecks each original schema and resolves every native receipt from the corresponding artifact and protocol owner. The current bundle contains 38 definitions and 35 receipts, stores 28,039 bytes and expands to 372,470 bytes. The consumer's direct source boundary is two files totaling 28,842 bytes under the unchanged limits. The hub Cargo lock includes the projection's first-party deflate dependency.

The repository-managed Bun invocation of the existing producer generated the exact bundle. The updated definition-roster tests use zlib to decode it independently, compare the full order to the generated canonical Stdio composition, compare each raw JSON definition byte-for-byte to its authored owner, compare all receipts to the canonical catalog factory projection and verify codec registration bijection. They also check the exact Rust include and source boundary and reject any artifact implementation dependency. Both tests passed with 162 expectations. An independent Python zlib measurement matched the recorded sizes.

The Rust projection limits compressed input to 128 KiB and expansion to 1 MiB, validates UTF-8, rejects duplicate JSON members and unknown fields, validates each selected schema identity and native receipt correspondence, and refuses incomplete or duplicate ownership. Its consumer caches the projected contribution per process. The definition-roster Rust test compares the complete final payload against live artifact assembly and a serde_json oracle. I did not run that build or benchmark actual guest decode latency.

The bundle is an ignored output, as are the other generated Stdio composition inputs. Running the Stdio script bare failed because its Original parent is missing. The existing definition crate declares the appropriate preparation hook. Graph-free component builds need that hook invoked by their admitted preparation path when the bundle has yet to be generated. The prototype on this workspace can use the now-present output while that zero-touch integration is verified.
