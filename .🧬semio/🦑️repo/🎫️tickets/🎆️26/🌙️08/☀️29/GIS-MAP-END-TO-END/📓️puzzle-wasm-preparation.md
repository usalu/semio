# Puzzle WASM Cargo Preparation

The managed GIS2D prototype published its GIS model, module, Surface, Editor and NodeGraph artifacts. Puzzle stopped at Rust source admission with `process.source.unresolved-module` for `registry` in `semio-s-artifact-puzzle-2d-graph-manifest`. The failure is recorded at line 194480 of the warm transpiler retry log. All three Puzzle graph registries were absent when inspected.

Cargo preparation never ran on the repository WASM path. The 2D, 3D and 5D graph contracts already declared their output files, and their graph-generation commands already observed the generator inputs and outputs for Cargo custody. The Rust packages mounting those files had no preparation declaration. The browser engine compiles `semio-hub-puzzle-component`, whose composition uses all three artifact families.

The browser WASM owner now passes the selected component's manifest, profile, target and feature arguments to the existing Cargo preparation entry while the original repository compiler store is open. It awaits preparation before entering the pooled compiler lane and admitting Rust sources. The five Rust packages that directly mount generated Puzzle graph modules now declare the existing recipe. Cargo preparation deduplicates recipes pointing to the same physical script and arguments, and reuses witnessed inputs and outputs when they remain current.

The public producer targets are `repo run @semio-tech/puzzle-2d-rs:graph-generate`, `repo run @semio-tech/puzzle-3d-rs:graph-generate` and `repo run @semio-tech/puzzle-5d-rs:graph-generate`. These commands need an available managed project graph. The owned WASM preparation path selects the producer through the Cargo manifests.

Both new regressions failed before implementation. The focused WASM tests then passed with five tests and 85 assertions. The neutral fixture checks the declared owners with smol-toml and verifies the execution order with TypeScript and SQLite. The cold test obtains the exact unresolved registry error from Rust source admission and supplies the bytes returned by the existing generator in memory. The same source admission then accepts the registry and its two manifest Rust modules. Both build modes select the exact hub component for the managed preparation command. A read-only projection also produced each of the three catalog registries and the modified WASM policy imported successfully. These checks ran without launching Cargo or writing generated source. A managed browser build with the updated source remains unverified by this check.
