# Browser Engine Startup Audit

Observed 2026-11-21. This is a read-only inspection of startup and publications; no builds were started.

`serveRootPlaygroundV1` waits for boot components, then for React calls `ensureRendererEngines`. Its declared Play-facet catalog order is Surface (`@semio-tech/framework-surface-rs`), editor (`@semio-tech/framework-editor-rs`), NodeGraph (`@semio-tech/framework-os-node-graph-rs`), Puzzle (`@semio-tech/puzzle-wasm`). The loop awaits each missing producer serially. Play is selected only when the contribution's browser factories include Puzzle's exact source owner; renderer otherwise excludes Puzzle.

The products partition is `.cache/b/p/m`; the selected prototype publication namespace `.cache/b/p/m/browser/prototype/wasm-packages` did not exist at inspection. Consequently none of the four exact prototype package publications, including their `.semio-artifact.json` and four declared JS/WASM/type files, existed at that instant. This is a physical presence observation, not a freshness or provenance validation; concurrent activity can change it.

Each owner exports `WasmScript` and registers `wasm`. The first three call `buildAdmittedWasmWebV1`; Puzzle calls `buildRepositoryWasmWebV1`. Their common producer derives a Cargo build for the *component* manifest, `--locked --lib --profile prototype --target wasm32-unknown-unknown`, and passes admitted arguments through wasm-pack; it obtains compiler input custody, an exact Cargo build lease and writer, then stages the verified package via the repository artifact destination. It uses a temporary Cargo target capture and an admitted compiler build directory. Surface also runs its browser verification consumer. Merely having Cargo output is not the package publication or its provenance.

`repo cargo --store=shared --configuration=prototype -- ...` is a public Cargo ingress, but inspection did not establish that its independent admission constructs the same compiler input view, configuration, build directory and Cargo fingerprint lane as each original owner invocation. Nor does it run wasm-bindgen and stage the owned package. The script's registered `wasm` route is an owner implementation, but a graph-independent public launch with issued original invocation and required producer capabilities was not established. Therefore there is **no verified public exact prewarm workaround** to recommend from this audit. Do not call cargo, wasm-pack, or a script directly as a claimed equivalent, or fabricate publication files. Continue the managed replay or investigate an explicitly supported owner ingress.
