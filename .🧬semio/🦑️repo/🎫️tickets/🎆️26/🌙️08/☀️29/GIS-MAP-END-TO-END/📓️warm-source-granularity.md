# Warm Cargo Source Retirement

Keep immediate retirement on stable admitted-source drift for the GIS launch. Emitted compiler dep-info can establish that an artifact used an older version, but gating retirement on that evidence alone would permit a queued or running unit to consume a changed closure without source admission. The two GIS retirements show the value of investigating the cost. The current logs do not identify either edit as safe to ignore. The planar-closest retry reused completed units in its held lane.

## Follow-up

1. Have the detector close only after a caller accepts a retirement or explicitly shuts it down. Preserve the standalone caller's existing acceptance policy. Continue the rolling scan after a decline. Bound repeated checksum work by remembering declined digests with file metadata as an invalidation hint. Any eventual retirement after a deferred decision should use a fresh stable physical read.
2. For a measurement of avoidable restarts, use the existing announced dep-info iteration and associate each claim with the owning unit. Compare checksum and length against the current bytes via the same stable read, or resolve the claim to a retained SHA-256 body through the witness store. A filesystem SHA-256 mismatch alone proves only the disk changed. When a claim arrives after a file event, reconsider the bounded pending candidate immediately, then honor the existing active, unlinked, retry, and cancellation guards.
3. Gate any future allow-new-bytes policy on successful admission of the exact replacement source closure under stable graph and configuration before the affected unit can read it. That requires control over compiler unit dispatch or immutable inputs. Fresh compiler artifacts and final selectable snapshots cannot provide the same pre-execution guarantee. Until that exists, ship the decline-and-continue behavior independently if repeated or invalid candidates are observed. Use telemetry to measure early retirement cost and held-lane reuse before expanding the policy.

A focused follow-up regression should emit two distinct filesystem changes, decline the first, and accept the second. Cover a later digest of the same path, deferred evidence arriving after the file event, cancellation, and a late linked artifact. Any allow-new-bytes policy needs a real Cargo fixture covering a valid queued edit, a newly referenced module or exceeded boundary, and an emitted dependency using old bytes.

## Watcher Lifecycle Fix

The source detector keeps its existing file event and metadata scan active when the warm driver declines a mismatch. It closes after an accepted mismatch. Standalone callers still accept by returning no value. The warm driver still records one accepted witness, retires only the owned child, and uses the same retry allowance and shutdown guards. The active GIS launch continued with the code loaded at startup.

The language-neutral fixture describes an already handled path followed by an independent edit and an edit after acceptance. SQLite independently selects the first eligible match for each caller. The real file watcher regression failed on the original code when the warm attempt missed the independent edit. The full focused Bun suite passed after the patch with 37 tests, including standalone acceptance and owned-child retirement.
