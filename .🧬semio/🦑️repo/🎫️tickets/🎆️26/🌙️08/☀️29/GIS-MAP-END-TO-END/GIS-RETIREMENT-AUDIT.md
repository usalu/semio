## GIS Preparation Factory Path

A stronger concrete candidate is now verified in source: the GIS play app supplies `Gis2dOneItemPreparationFactory::default()` as its artifact Store preparation factory (`✏️editor/🧭️play-app-editor/🦀️.rs:86–87`). The typed batch clones that factory into `ArtifactTypedBatchItemAuthority` (`store-cursor-operations/🦀️.rs:304–315`). On batch-source close, `into_retirement_authorities` converts the preparation Arc into a `FactoryAuthority` (`🎮️one-item/📬️publication/🦀️.rs:571–574,785–786`); source `retirement_demands` forwards to the authority, whose `FactoryChildSlot::demands` calls `factory_ticket_demands` on its captured ticket (`🌱️value/♻️retirement/🏭️factory/🚼️construction/🦀️.rs:128`).

`Gis2dOneItemPreparationFactory` derives `FactoryPayloadRetirement` and owns `GisMapStampSlot` (`✏️editor/📬️one-item-preparation/🦀️.rs:10–14`). Both unstamped and stamped constructors use this same type (lines 17–19, 72–98). The slot's handwritten implementation declares its terminal state as `None` (lines 42–69), but does not override the trait's unsafe terminal-native-release-safety method, whose default is false (`🌱️value/♻️retirement/🏭️factory/🦀️.rs:66`). The derive ANDs each owned field's safety (`🌱️value/✨️derive/🏭️factory/🦀️.rs:165`); `FactoryTicket<T>::native_header_release` requires that resulting boolean even when terminal (`🏭️factory/🦀️.rs:184`). Thus either stamped or unstamped GIS factory ticket can become terminal and still provoke this exact refusal; this is a source-proven route and strong causal match, pending the mounted browser oracle.
