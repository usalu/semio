Design decisions made (deviating from the sketch, with reasons):
- WorkflowDiff is a hand-rolled tagged enum (matching the ALREADY-EXISTING OsDiff pattern in os-core), NOT
  #[derive(dsl::DslDiff)]'s sparse-struct-of-Options shape. Reason: dsl::DslDiff only supports structs (per
  its own doc comment, confirmed in the space crate's SpaceDiff), and WorkflowOperation has ~18 action-
  discriminated variants (not a flat "one field per possible mutation" manifest like SpaceProjection) — a
  hand-rolled enum is the direct, low-risk "lift" of the proven OsDiff code, and is what "lifted from OsOperation
  arms" most literally means. DiffCodec (print/parse/encode/decode_diff) was therefore NOT implemented for
  WorkflowDiff either (same status as the OLD OsDiff, which also never had it — W1 left DiffCodec a soft,
  policy-checked requirement, not a hard bound, specifically to allow this).
- WorkflowOperation::reconcile is NOT overridden (inherits the trait's no-op default). Reason: the original
  os-core reconcile_os_workflow pipeline has 4 ordered rules; 2 of them (contract renegotiation via
  negotiate_media_contract, parameter-binding-vs-ConfigSpec validation) genuinely need the os-core plugin/
  artifact registry, which cannot live in this kernel crate (same reasoning the file's own `validate_workflow`
  doc-comment already gives for its os-core wrapper). Splitting the 4-rule pipeline across two layers would
  change rule ORDERING versus the existing tested behavior (each rule sees the previous rule's pruned edge
  set) — too risky to guess right without the concurrent-reconcile test in hand. DECISION: keep the WHOLE
  4-rule pipeline (including the 2 pure-structural rules that COULD move down) as a single ordered function
  at the os-core layer, operating on workflow::WorkflowDocument, invoked explicitly by whatever replaces
  OsStore (not through the Operation::reconcile trait hook). This preserves exact existing semantics.
- create_default_workflow_parameter's id-minting fallback uses its own small AtomicU64 counter
  (create_workflow_parameter_id, "param-{n}") scoped to this crate, NOT os-core's shared create_os_id counter
  — the real caller (os-core) always premints via its own id and passes Some(id), so this fallback path is
  dead in practice; documented as a deliberate, safe, additive local scheme rather than plumbing os-core's
  global counter down (which would invert the dependency direction).
