# Test Layout Enforcement

The existing repository test contract discovers only cases that already contain `🧪️tests/<case>/🥒️.feature`. Its separate unmanaged-test survey recognizes a small filename set and compares area counts with `🚚️migration.json`; it does not reject every legacy file, canonical tests without Gherkin, or inline test bodies.

The permanent rule is structural: an authored executable test implementation must be the direct file `<semantic owner>/🧪️tests/<emoji-and-kebab-case case>/<canonical implementation filename>`. Canonical implementation filenames are derived from taxonomy file kinds; TypeScript therefore accepts `🟦️.ts`, `🟦️.tsx`, `🟦️.mts`, and `🟦️.cts`, while Rust, JavaScript, Go, Python, and .NET use their own declared kinds. A semantic owner cannot be below `📦️packages`, `⚡️implementations`, or `🎯️targets`.

The scan rejects legacy filename conventions even when a file contains no recognizable framework import, and finds executable declarations in canonically named or ordinary source files. Source recognition masks comments, strings, Rust character literals, and Python literals without corrupting UTF-16 offsets around emoji. Rust external test-module wiring is valid only when a test-only cfg and `#[path = "…"] mod …;` or `include!("…")` resolves to an existing canonical implementation. `cfg(not(test))` and mixed `cfg(any(test, …))` remain production gates. Inline test modules and namespaced `async_test` attributes outside canonical implementations remain violations. TypeScript and JavaScript test registrations, assertion-bearing self-test declarations, Storybook `play` interactions, and invalid `import.meta.vitest` wiring are signals; configuration-only Playwright imports and fixture extensions are allowed. Go, Python, and .NET use their standard executable declarations in addition to legacy names.

The scanner API is asynchronous, accepts an `AbortSignal`, and reports deterministic progress and sorted findings. The repository `test contract` gate invokes it, so all root test levels enforce the layout through the existing Nx dependency on `@semio-tech/repo-test-domain:test-contract`. Nx production inputs exclude the canonical `🧪️tests/**` subtree instead of relying on legacy filename suffixes.

Language-neutral JSON vectors cover valid and invalid paths and source forms. Ajv validates those vectors against the test domain protocol, Bun executes the implementation test, and the installed `minimatch` package independently checks legacy filename classification. The focused suite recorded an initial red run with two failures (the vector protocol rejected its undeclared `$schema`, and the Rust inline fixture emitted both module and test-attribute findings). After correcting the contract and expected diagnostics, `bun test ./…/📐️test-layout/🟦️.ts` passed 10 tests with 16 assertions, including Nx metadata checks for semantic-owner inputs and production exclusions.

The package-level quick suite found all three canonical files after its runner paths were corrected, then exceeded its existing 30-second quick budget while executing the large test-platform case. Direct TypeScript/Nx validation was also stopped after more than 90 seconds without diagnostics. A wider Bun build reached unrelated files being rewritten concurrently and reported malformed import syntax there, so it is not evidence against this slice. The full repository scan was cancelled after 90 seconds to release the fleet slot; final audit agents should run it after migrations settle.
