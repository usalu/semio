# Wave 7 architecture — where mutation testing lives

## The correction that shaped this wave

The first attempt put mutation oracles in a single top-level
`✏️s/🔌️plugins/🗄️stdio/🧪️oracle/🦠️mutations/<format>/` directory, one file per format. That was
wrong and was removed before any agent wrote into it.

**A mutation is not a property of a format.** It belongs to one subset of one standard of one
artifact. PDF 1.4 declares 2 mutation kinds over a single-page snapshot; PDF 1.7 declares 15 over a
full page/object/trailer model. GIF 87a has no frame delay, disposal, transparency, comments or
application extensions; GIF 89a has all of them. These are different vocabularies, not versions of
one list, and a per-format file silently flattens them into one.

Where two subsets genuinely share an implementation, they share it **through a module** — the
existing family helpers — never by copying it into both.

## The resulting layout

```
✏️s/🔌️plugins/🗄️stdio/
  🧪️oracle/                                    ← shared, reference-library helpers
    📄️document/🦀️component.rs                    project_pdf, oracle_delete_page, …
    🖼️raster/🦀️component.rs                       project_image (jpg → luma histogram), project_gif, …
    🎒️archive/ 🔊️audio/ 📊️tabular/ 🧊️mesh/
    📦️packages/🦀️rust/{Cargo.toml, 📦️lib.rs}     the crate; lib.rs mirrors the plugin's module tree
  🗿️artifacts/<fmt>/
    🏅️standards/🔖️<std>/🪆️subsets/✳️any/
      🧬️schema/🧬️mutations/🦀️component.rs        the vocabulary (XMutation + apply + diff + inverse)
      🧪️oracle/🦀️component.rs                    ← the subset's mutation oracle
      🧪️oracle/🔣️component.json                  ← its catalog + its own oracle registration
    🧪️tests/mutate-<fmt>-<std>/                  ← the case (artifact root, so asset:// reaches
      component.feature  🦀️component.rs             examples committed under any standard)
    🧫️fixtures/                                  ← real-world inputs too far from an examples dir
```

The oracle crate's `📦️lib.rs` mirrors the plugin's own
`artifacts::<fmt>::standards::<version>::subsets::<subset>` tree, so an oracle sits at the same
address as the implementation it is evidence for:

```rust
semio_s_plugin_stdio_test_oracle::artifacts::pdf::standards::v1_7::subsets::any::oracle_apply_mutation
```

14 mutation-owning subsets exist across the twelve artifacts whose reference library is already
linked: pdf 1.4 + 1.7, gif 87a + 89a, png 1.2, jpg jfif-1.01, bmp v3, tiff 6.0, zip 2.0, deflate
rfc1950, wav riff-pcm, csv rfc4180, obj 3.0, stl ascii. One agent owns each; no two share a file.

## Framework support added for this wave

| Change | Why |
|---|---|
| `asset://` fixture scheme | A 6.3 MB real thesis is read where the domain keeps it, instead of being duplicated into a fixtures directory. Owner-root relative, same escape guard and plan-time digest pin as the other two schemes. |
| `mutationCatalogs` + `@mutations-<id>` + `mutationCoverageBreaches` | Turns "exhaustive" into arithmetic: every declared kind needs a `mutate-<kind>` and an `inverse-<kind>` scenario. Also fails on a kind exercised but not declared, on an unknown catalog, and on a catalog no feature claims. |
| Owner declares the vocabulary, framework never parses Rust | Keeps open/closed intact — the framework must not know that PDF exists, nor that a vocabulary happens to be a Rust enum rather than a descriptor table. The owner proves its declaration honest with `KINDS` plus an adjacent test. |
| Work directories marked complete | `clean test --stale` treated every work directory as interrupted and deleted it, including one a concurrent run was writing. |
| `copyFixture` clone-on-write | Every work directory takes its own copy of each fixture; with real-world fixtures that is the difference between a constant and a linear cost. Still a copy, never a hard link — the caller is handed a mutable path. |
| `.gitignore` `!**/🧫️fixtures/**` | `*.obj` (a VisualStudio rule) silently untracked every Wavefront fixture; `*.[1-9]*`, `*.log`, `*.tmp`, `out`, `temp`, `build` hit others. A swallowed fixture fails on someone else's fresh clone, not here. |
| `.gitattributes` binary markers | `* text=auto` left pdf/glb/mp4/dwg/stl/… to git's content heuristic; a misread binary is line-ending normalized on checkout and then corrupt for every byte-exact test. |
| Nx inputs and outputs narrowed | Fixtures were matched by two input globs and content-hashed per target; outputs claimed the whole cache root, so every generated byte was archived. |

## Gotchas found the hard way

- **Adapter registration keys on the FULL expanded scenario id** (`mutate-remove-page`), not the
  outline's base id, and a missing registration is a hard error. Adapters register in a loop over
  their kinds.
- **Existing oracle entries declare the wrong capability for this wave** — `lopdf` declares
  `pdf-edit`/`pdf-parse`, `image` declares `jpg-raster`, none declare a `…-mutate` capability, and
  the contract enforces that the tagged oracle covers the tagged capability. Each subset registers
  its own oracle entry with its own id, which the repo-wide registry merge picks up with no central
  edit. This is what keeps the fleet free of a shared-file lease.
- **Lossy formats cannot compare raw samples**: comparison tolerance is per-number and absolute with
  no aggregate mode. The existing raster helpers already project a luma histogram for JPEG and
  palette-resolved counts for GIF; the mutation cases reuse those rather than inventing tolerances.
