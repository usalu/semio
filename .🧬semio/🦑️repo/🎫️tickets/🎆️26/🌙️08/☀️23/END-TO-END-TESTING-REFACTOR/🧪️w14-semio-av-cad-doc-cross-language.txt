================================================================================
NOT CONVERTED — mutate-semio-any, and why
================================================================================
`✳️any` keeps its recorded `semio-envelope-routing` no-oracle decision. Its rationale in
`…/✳️any/🧪️oracle/🔣️component.json` now records the wave-14 re-survey and the two blockers:
  1. the envelope's own committed documents declare the wrapped arm OPAQUE — the snapshot grammar is
     `document = artifact-mark subset-line REST`, the binary protocol models the wrapped pack as one
     opaque `payload` chain, and the mutations grammar is `op = "noMutation" | tag ":" REST` — so an
     envelope-level second implementation can reproduce both carriers byte for byte but can say
     nothing about whether a DELEGATED verb changed the arm, which is what 18 of the 20 kinds measure;
  2. `✳️any` exports `parse/print_semio_envelope_dsl` and `decode/encode_semio_envelope_pack` but NO
     JSON bridge for `SemioSnapshot`/`SemioMutation`, so the arm snapshots and wrapped verbs can only
     be built inside the subject crate, where a second language cannot read them.
A Python oracle restating the routing table would be a transcribed expectation, i.e. our own answer
on both sides, so it was not written.

Third finding, recorded here: the committed `✳️any` SNAPSHOT grammar's `subset-tag` production lists
thirteen tags (brep, mesh, model, value, document, cad, drawing, image, video, audio, animation,
presentation, flow) while this subset's catalog and its own sibling MUTATIONS grammar both declare
eighteen arms — `text`, `table`, `graph`, `object` and `kit` are missing from it.
