## Measured gaps against the target contract

### G1 — Discovery is currently near-empty
`bun ./…/🧪️test/📜️script.ts discover` reports **4** cases, all of them scratch copies inside
`.🧬semio/🦑️repo/🎫️tickets/🎆️26/🌙️08/☀️17/END-TO-END-TAXONOMY-NORMALIZATION/…`.
Cause: `🔣️taxonomy.json`'s `gherkin-feature` file kind renders `🥒️.feature`, while every real case on
disk still holds `component.feature` (e.g.
`✏️s/🔌️plugins/📐️cad/🗿️artifacts/📐️cad/🧪️tests/mutate-cad-1/component.feature`). A concurrent session is
mid-rename. **This is not in this ticket's scope** and is deliberately not chased; Protocol v2 reads the
filename from the taxonomy, so it inherits whichever spelling wins.

### G2 — Protocol v1 cannot express the required result bundle
`TestResult.output` is exactly `{rawHash, projectionHash, rawPath, projectionPath, projection}` — one
artifact. There is no artifact list, no media type, no probe stage, no engine family, no scale-relative
tolerance and no geometry/topology assertion vocabulary. `ComparisonProfileSpec` says only
`{arrays, ignoreKeys, tolerance, text, bytes}` — a single absolute numeric tolerance for everything.

`FixtureRef` is `{uri, scope, name, path, digest}`: no class, license, units, generator, engine, seed,
platform or reproducibility evidence.

### G3 — Mutation coverage is catalog-vs-feature, never runtime-vs-catalog
`mutationCoverageBreaches` counts `catalog.kinds` against scenario ids `mutate-<kind>` / `inverse-<kind>`.
`mutationVectorRegistryBreaches` audits physical vector bundles. Neither consults production dispatch —
the library comment states this explicitly ("Runtime mutation kinds are deliberately not consulted").
A mutation reachable through production dispatch but absent from a catalog is invisible today.

Production *does* expose an inventory: `protocol::SemanticMutation::kinds() -> &'static [SemanticDescriptor]`
(`🧰️framework/🛍️products/💻️os/🔨️modules/📡️spr/🎮️command/🦀️component.rs:245`), generated by
`#[derive(dsl::Mutations)]`, plus the richer `MutationLeafDescriptor` (14 fields, incl. `outcome_classes`)
at `🧰️framework/🔨️modules/📡️replication/🎮️mutation/🦀️component.rs:210`. Protocol v2 makes these the
authority instead of ignoring them.

### G4 — CAD ownership is a wildcard
`✏️s/🔌️plugins/📐️cad/🗿️artifacts/📐️cad/🏅️standards/🔖️1/🪆️subsets/🔣️component.json` declares exactly one
subset keyed `"*"` ("Unconstrained cad 1"), materialised as the single directory `✳️any`. All 20
`CadMutation` variants are owned by it.

### G5 — The CAD "independent" oracle is a second Semio implementation
`…/✳️any/🧪️oracle/🔣️.json` registers `cad-python-independent`, whose own rationale states it is
"A second implementation of the `s.cad.cad` document and all twenty typed mutations, in Python", and that
"the SUBJECT half does not run this subset's codec — … replays the committed vectors". Under the target
contract this is a *supplemental* oracle kind (`cross-semio-implementation`), never a qualifying one.
