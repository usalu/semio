Real framework gap found and worked around (documented in the new Cargo.toml's own comment, not fixed
upstream — out of this ticket's plugin-only scope):
  `dep = { workspace = true, package = "..." }` (TEMPLATE.md §13's suggested rename-while-inheriting
  pattern) does NOT work — Cargo resolves workspace inheritance by the LOCAL dependency key, and `package`
  does not redirect that lookup (verified empirically: "dependency.dsl was not found in
  workspace.dependencies"). The renamed internal aliases (dsl/store/protocol/mathematical_graph/
  mathematical_geometry/ui_wgpu) therefore stay plain `path`+`package` deps; only the 4 dependencies whose
  local name already equals the workspace key (semio-framework-core, semio-framework-plugin, serde,
  serde_json) use `workspace = true`.

Second real gap found and worked around entirely within this plugin's own files (no framework edit):
  `app_commands!` unconditionally derives `serde::Serialize`/`Deserialize` on the generated Command enum,
  so every payload struct — including nested types — must implement both. `dsl::Wire` (framework DSL
  kernel field type used by this plugin's `MathEdgeDsl`/`MathGraphDsl` DSL-mirror types) implements
  neither. Fixed by hand-writing `Serialize`/`Deserialize` for `MathGraphDsl` that round-trips through the
  fully serde-able `MathGraph` JSON shape via the existing `math_graph_to_dsl`/`math_graph_from_dsl`
  conversions, instead of deriving field-by-field — `MathEdgeDsl` itself needs no serde impl at all once
  `MathGraphDsl`'s is hand-rolled. Documented inline in 🗣️dsl/🦀️component.rs.

Shared-workspace churn encountered (per feedback-concurrent-cargo-workspace-churn / TEMPLATE.md's own
batch-2 concurrent-session note): the root workspace was red for most of this session's duration because
a concurrent session's 📋️forms migration had deleted forms' old crate dirs before its own registrar pass
added the new member line. Worked around via TEMPLATE.md §3's standalone-`[workspace]`-overlay trick,
applied to each old crate individually (not combined — combining siblings into one ad hoc workspace hits
Cargo's "member of the wrong workspace" check, since each sibling's own directory-walk-up still finds the
real root workspace as its home). One transient rmeta/fingerprint write error was hit and cleared on retry
(TEMPLATE.md §13.3's shared-cache test-serialization lesson).
