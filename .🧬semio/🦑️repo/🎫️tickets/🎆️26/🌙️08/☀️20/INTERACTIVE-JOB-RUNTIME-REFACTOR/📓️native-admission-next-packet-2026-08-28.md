## Immediate Source/API Packet

The next native work is the **existing shared resident contract's admission-cell and record subset**, in the sole `value/💾resident/🦀.rs` authority and its existing tests. The complete current431-line TS implementation, resident contract, admission contract and R27–R33 report were read. Native work will preserve these semantic stages rather than importing the obsolete direct-reservation API:

1. `prepare_admission` records the original consumer/partition and a strongly retained pending cell before returning. Read-only `prepared_admission` recovers that exact cell after an outer wrapper fails. A later `claim_admission` uses the same consumer and cell, not capacity equality or a numeric instance lookup.
2. `reserve_record` requires that held claimed cell and an explicit domain envelope. Its typed result is installed in the original cell before return. The concrete composition keeps the capability private and installs its original empty typed construction shell before populating fallible fields.
3. First-fault handoff retains the original Rust panic/error owner, never a replacement string. Repeated distinct faults return the second owner to the caller; no overwrite, public clear or refund is added. Quarantine blocks forward work but leaves exact typed retirement serviceable.
4. Neutral record close cannot invoke a domain callback or infer terminality from an empty slot. The concrete owner retires its actual shell and performs an exact retained handoff. Record unlink, result-alias detachment and healthy cell release remain separate granted phases. Fault-held cells remain charged and nonterminal.

The native public vocabulary will use `ResidentPartition`, `ResidentGrant`, `ResidentStep`, `ResidentLedger`, `ResidentAdmission` and typed `ResidentRecord<S>`. This is not another actor registry, lifecycle family or wire ABI. Actual native allocation/layout charges must be inventoried and preadmitted, including the original pending construction slot and reference/control metadata; TS296/264/8-byte logical prices are not Rust layout constants. The first native tests must verify the chosen backing and stable identity before any live caller receives these capabilities. There will be no synthetic permit constructor or public counter subtraction.

The shared schema's original prepare/read/claim, occupied/refused, fault-held and separate-alias vectors are reused. Native laws add actual allocation/refusal counters, original pointer survival across a mutation-then-panic callback, zero/short grants, foreign equal-capacity ledger rejection, and retention after losing the ordinary return. Intrinsic release does not claim arbitrary panic-payload destruction or final empty-facade allocation release.

## Initial Rust Backing Proposal — Superseded Below

The ledger root is one fixed shared `Arc<Mutex<LedgerState>>`; it contains only fixed counters, list heads, a pending construction slot and close cursors. That one root allocation is an explicit bootstrap exclusion, not a free descendant directory. Native layout instrumentation must report its requested allocation and header size. Every admission and typed record below it is separately preadmitted and allocated as a one-element Vec page, with actual `capacity * size_of::<Node>()` recorded even on refusal/error. The existing Kernel return entries provide the already-tested one-element-page/relink pattern, but are not imported back into resident (which would recreate a crate cycle), and do not confer allocation authority.

Record pages hold `Option<S>` inline. Allocation, node initialization, shell placement, typed descendant retirement and empty-page release are separate steps. An empty reserved page remains owned. Metadata relinking moves Vec descriptors, never a live S. A private erased page descriptor permits a heterogeneous ledger roster; its deallocator may run only after the concrete S slot and links are empty. It is not a generic payload destructor. Native tests must inspect both empty reservations and initialized pages, including actual capacity greater than requested and zero/short placement/final-release grants.

Consumer identity is the actual supplied `Arc<Mutex<C>>`, retained strongly and compared by original allocation identity after safe type erasure; C must be Send, matching the existing ArtifactApp/PluginApp Send bounds. No public integer, capacity-equality check or new consumer-token constructor supplies identity. Admission/record handles are privately issued for their original node. Stable node addresses come only from non-resized one-element pages; their pointer access, if needed by the heterogeneous roster, stays private under the exact ledger guard and is tested across parent moves. No self-referential Future is introduced.

Handles register exact outstanding references; dropping a handle performs only a fixed atomic handback, never final page or payload destruction. The ledger remains the strong page owner and releases it only in a later granted close step after registered aliases and its typed source are empty. Busy try-locks retain all roots. Poison blocks forward work; close-only access must preserve the first actual caught payload and cannot silently clear poison into a normal live state. The concrete typed parent holds the shell guard and original admission outside the unwind closure.

The first prototype must verify the actual layout and safe backing mechanics before this private pointer representation is exposed as a usable API. Rust metadata sizes will be calculated from its own Node/descriptor types; no TS logical price is copied and no allocation/placement is credited merely from payload length.

One required native fault-test boundary remains explicit: the shared contract intentionally offers no unknown-fault clear/refund. A Rust test cannot finish by cold-dropping an arbitrary Box<dyn Any + Send>, leaking the ledger, or inventing a generic terminal witness. Healthy bootstrap/record cancellation and exact constructor mutation/unwind retention can execute independently; final cleanup of an actually retained unknown fault needs the concrete Opening owner's typed fault custody/handoff. The first-fault observation must not be reported as successful composition close. This constraint will be carried into the native tests rather than hidden in teardown.

## Chosen Native Root And Final-Release Packet

The public owner is now one **inline fixed `ResidentLedgerRoot`**, retained in the original parent outside the callback. Its constructor takes an explicit checked capacity and allocates zero heap bytes. `root.ledger()` returns a borrowed façade; there is no public owning or last-Arc `LedgerState` handle. Dropping that façade or an ordinary admission/record return cannot drop the original root or its page roster. The bootstrap root's actual `size_of` is reported separately; this is an exclusion of that fixed root only, not consumer allocations, growing directories or control arrays. Root movement is tested after borrowed façades are gone, while its original page descriptors remain owned.

Consumer identity is the original `Arc<Mutex<Option<C>>>`, not `Arc<Mutex<C>>`. The ledger retains that exact allocation but may release its erased alias only after the actual C slot is empty. An empty record S slot is expressly insufficient. The `handoff_consumer_into` operation validates the original consumer, cell, empty structural target and actual move grant before moving C. Its result means **structural handoff**, not C retirement or destination admission. The typed original parent must retire C's descendants and final shell separately before its own composition can be terminal. The neutral root does not call a C terminal callback, sample `Arc::strong_count`, manufacture a terminal proof or invoke C's destructor.

The same rule applies to `ResidentRecord<S>`: `install` and `handoff_into` accept structurally retained `&mut Option<S>` slots. Source/destination occupancy and actual move bytes are preflighted. A wrapper panic after transfer leaves the exact source in the original parent destination. The private heterogeneous descriptor can release only an empty typed slot, detached links and retired exact aliases. Every one-element backing remains ledger-owned until its admitted release step; dropping a façade cannot recursively destroy linked Vec pages. Healthy root close has its own final grant after child release, not a free tail of a child step. The only final original-root destruction allowed by this packet is after that root's actual terminal state; loss of the enclosing process/activation owner is not claimed handled by a borrowed façade test.

The external consumer Arc and test probe payloads are already-owned fixture inputs, with their allocation before the measured resident operation explicit. They are **not** included in the root bootstrap exclusion or evidence of preproducer funding. The immediate Opening integration must create/fund those original consumer/construction slots under its actual outer composition before any producer; the isolated ownership tests do not grant that authority retroactively. The tests separately measure all additional admission/record backing and require no allocation on refused admission.

None of these methods may be mounted as an Opening/producer admission boundary on that basis. The next live join must bind transfers to a privately issued registered typed receiver capability from the actual composition.
