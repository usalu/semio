## Storage And Ownership Contract

The return domain will own a private one-item-page chain, with its maximum entry count supplied by the original caller budget. Each node holds an optional typed payload and one next-page descriptor. Reserving one uninitialized allocation and placing one initialized payload are separate granted operations. Repeated reservation has zero allocation delta. There is no full-capacity initialization, Vec relocation of previous payloads, payload clone or arbitrary global queue.

Build order is a head insertion. Freezing relinks one descriptor per call into a second structural root, preserving FIFO without moving the payload. The original root owns both chains and any empty reserved allocation throughout cancellation or a producer unwind; the root must stay outside the execution closure. Moving a one-page entry to an admitted empty target transfers its exact physical allocation accounting, not freed-memory credit. No payload is dropped by generic entry retirement: a domain-specific consumer must first transfer or retire its exact value, then empty-page release can account its actual capacity.

Allocation and placement budgets are separate. A typed allocation error reports the exact newly allocated byte delta and retains an over-admitted empty allocation for bounded close. Placement is forbidden after that fault. A test-only requested-capacity hook will exercise this branch using a real larger allocation; it does not alter the production reserve request or claim a host allocator naturally over-allocates. Aggregate owned allocation accounting uses u128 so adding individually addressable allocations cannot silently wrap the native usize counter. Per-operation physical deltas remain usize.

Cold source payload construction in tests is only the producer stand-in. The live producers, actual Effect/Presence descendant cursors, original page ACK and final-clock terminal handoff remain separate acceptance work.
