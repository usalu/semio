# Canonical Reader Partial-Error Progress

The shared indexed cursor and borrowed encoder can write several output bytes before a typed source returns an error. Their `Result<usize, String>` discards the initialized prefix length on that path; the retained reader then leaves `completed_bytes` behind the actual output. A caller cannot safely determine how much output must remain owned or be retired. A one-byte caller limits this defect but does not repair the shared contract.

The schema-first fixture declares indexed and borrowed failures after the UTF-8 prefix `["aä🧵",`, with eleven initialized JSON bytes and seven snapshot string bytes. Grants are0,1,7,256 and4096, preserving the production one-item/4096-byte maximum. Independent serde JSON and Node JSON/UTF-8 encoding provide the expected prefix; sentinel-filled output proves the untouched suffix. Native tests must retain failed owners, report exact partial counts, prohibit completion/root transfer, and explicitly close the actual string owner.

The intended source contract replaces the error String with a framework-owned typed error containing `written_bytes` and `reason`. Every layer propagates those bytes explicitly. No implicit conversion to String may discard progress. Reader totals must include bytes written on an error while failure prevents subsequent publication. The sealer and concrete query/hash/preparation consumers must account for the same initialized prefix before surfacing the error; no valid digest or prepared authority may emerge after failure. CAD compilation follows this coherent shared API boundary.
