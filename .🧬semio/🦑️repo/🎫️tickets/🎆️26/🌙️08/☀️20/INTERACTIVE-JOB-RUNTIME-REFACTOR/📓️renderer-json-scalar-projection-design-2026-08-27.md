# JSON Scalar Projection Design

## String Projection

The source-present `OwnedUiSceneJsonStringCursor` looks up an exact token ordinal, verifies a key/string token, and issues a byte reader over its content span excluding quotes. It retains both the captured document and that byte reader. A fixed 128-code-unit UTF-16 output page receives decoded code units one byte at a time: raw UTF-8 scalars become one or two UTF-16 units; JSON Unicode escapes preserve their individual code units, including lone surrogates; short escapes map to their exact control character. Emitting a bounded page is distinct from materializing an entire string. Closing retires lookup and span readers before the captured document. No caller-supplied token can substitute a different source root.

Its API is `advance(grant)` returning bounded `text` pages or an explicit control step, `offset`, `failure`, `beginClose`, `closeStep`, and `terminalIsEmpty`. Construction requires the actual private-branded JSON document and a safe token ordinal. It does not invoke a supplied capture callback. Output emission calls the platform UTF-16 constructor only with at most 128 units; the test's concatenation is an oracle-side operation, not production code. Pending source chunks are at most 256 bytes. Child refusals/faults and actual byte counts are propagated while their original owners remain available for close.

## Number Projection: Required Proof Before Implementation

An arbitrary complete numeric lexeme must not be passed to Number or JSON.parse during one retained step. A possible bounded solution is to retain a fixed prefix of significant decimal digits plus a sticky nonzero suffix flag and the exact decimal position, then use the platform conversion only on a fixed-size canonical scientific representation. This remains a proposal, not implemented behavior.

The proof obligation is exact rounding, not approximate decimal accumulation. Every positive binary64 rounding boundary is a dyadic midpoint. After removing powers of two, its significant decimal coefficient is an at-most-54-bit integer multiplied by at most `5^1075`; its decimal digit count is less than 800. Therefore a substantially larger fixed significant-prefix limit can distinguish any non-boundary interval; a sticky suffix must distinguish a boundary endpoint from a value just beyond it. Overflow, half-min-subnormal, signed zero and exponent cancellation must be handled explicitly. The exact derivation, bounds on exponent counters from admitted source extent, and runtime conversion guarantees require adversarial tests before this route is used.

Tests must include all adjacent boundary forms around zero/subnormal/normal/maximum-finite transitions, long zeros surrounding the decimal point, long identical prefixes with the first differing digit beyond the fixed prefix, huge positive/negative exponents, and negative mirrors. Existing independent JSON.parse plus byte-level float inspection can be the test oracle. A source-span result is not yet a converted numeric host field, and this proposal does not authorize a lossy fallback.
