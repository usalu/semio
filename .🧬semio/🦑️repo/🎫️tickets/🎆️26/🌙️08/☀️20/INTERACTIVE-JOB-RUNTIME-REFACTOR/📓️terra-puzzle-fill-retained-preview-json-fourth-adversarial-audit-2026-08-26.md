# Puzzle Fill Retained Preview JSON Fourth Adversarial Audit

## Verdict

**RED.** The current parser remediation is internally strong: it accepts the intended one-key null-ghost and full nine-key ghost records, rejects unknown keys, validates every present optional root member, validates the exact diagnostic/ghost shapes, and fences all six ghost/root values. The retained encoder, cursor lifecycle, active Puzzle3d/Puzzle5d consumers, locale fail-closed paths, and visible/ARIA label route remain statically present.

The language-neutral schema does not express the same byte/safe-integer wire bounds that the encoder and parser enforce. Thus valid-by-schema JSON can be rejected by the shared renderer; on a 64-bit native producer, the encoder can also emit a `usize` index the renderer rejects. This is a bounded contract-coherence blocker, not a regression of the prior root-admission remediation.

No production source was edited. Cargo, Nx, Bun/Vitest, Wasm, browser, cache, and runtime commands were not run.

## Bounded Defect

### RED-1 — Schema admits root/ghost values outside the encoder/parser wire domain

`preview-json.schema.json` declares both `sourceVortexIndex` fields only as `{ "type": "integer", "minimum": 0 }` (root lines 7-15; ghost lines 35-43). It therefore admits integers greater than JavaScript's exact-integer maximum, including `9007199254740992`. `parseWorldBrushPreview` instead requires `Number.isSafeInteger(value)` at `World3dHost/🟦️component.tsx:1160`, both for a present root index (`:1175`) and ghost index (`:1192`). `BrushPreviewState.source_vortex_index` is `usize` and the retained cursor formats it directly into root and ghost JSON (`fill/🦀️component.rs:258,311`); no maximum-safe-integer guard exists. Consequently a native 64-bit value above `2^53 - 1` is schema-valid and can be emitted, but is rejected by the consumer. The parser law covers this rejection, but the schema/encoder law does not prevent it.

The schema likewise uses JSON Schema `maxLength: 128` for root `color` (`preview-json.schema.json:13`). `maxLength` measures Unicode characters, whereas the producer rejects `color.len() > 128` (UTF-8 bytes) at `fill/🦀️component.rs:462-465`, the parser uses a UTF-8 byte census at `World3dHost/🟦️component.tsx:1163-1170,1179`, and the language-neutral law calls the limit `maximumColorBytes: 128`. A 128-character non-ASCII color such as 128 astral code points satisfies schema `maxLength` but exceeds the required 128 UTF-8-byte limit and is rejected by producer/parser.

Make the schema and schema-first law authoritative for the actual bounds: express/enforce `sourceVortexIndex <= 9007199254740991` at both schema locations and reject the value before native encoding; encode the 128-byte color bound in the shared schema contract (with the same validator vocabulary used by all implementations) rather than only `maxLength`. Add language-agnostic schema laws for a safe-integer maximum and maximum-plus-one, and for 128-byte multibyte color acceptance/rejection. Until then the required schema/encoder/parser/law coherence is not established.
