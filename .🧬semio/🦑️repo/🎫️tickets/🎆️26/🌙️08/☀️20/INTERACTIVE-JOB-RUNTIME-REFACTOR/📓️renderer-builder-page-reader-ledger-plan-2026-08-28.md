# Builder, Page and Reader Shared-Ledger Cutover

## Scope and Source Boundary

This is the concrete next implementation proposal, not a source release or a passing runtime claim. The coordinator independently ran the preceding payload/scope/metadata cohort:14 selected passing tests on the stable677-test snapshot. The remaining old builder/page methods still read removed local counters. They must be replaced, not given a compatibility capacity object.

The original `OwnedUiResidentPayload` owns one existing, precharged seven-field transition slot. The next cutover reuses that slot for one builder/page/reader/intrinsic admission or retirement at a time. It does not allocate another controller, scan all children, or give each operation a ledger. Live children retain their own exact records/admission cells outside the transition slot. The original composition ledger funds both the UI metadata and intrinsic bytes.

## Concrete Callables

The externally used builder entry remains `OwnedUiOperationPayloadBuilder.begin(owner,activation,lifetime,field,payload,grant):{step,builder}`. Each call performs at most one declared phase. It delegates to `payload.beginBuilder(field,grant)` after checking the actual private source and payload identities. Neither entry returns a builder as ready before the original parent has installed and observed it, source binding has been observed, and finalization has completed. A repeated ready call returns the same original builder; a busy foreign request cannot replace it.

The cross-module constructor will have a direct private-parent reservation check, not an unchecked mint or a caller-supplied record. The resident module retains the original record/cell in its private payload state. It installs the builder in that state before invoking the exact neutral `record.install`; the constructor installs its own original source/parent fields before any fallible finalizer. Constructor or outer-wrapper failure is recovered through that same already-held entry. No public API returns a neutral owner, record, admission cell or detachment capability.

`payload.beginPage(builder,length,grant):{step,page}` replaces `reservePage(length)` and the boolean owner check. It admits the exact builder, checked0..256 logical extent, one same-ledger storage owner when first needed, the page's domain wrapper record and its actual neutral256-byte backing reservation. A short final page remains a fully charged256-byte backing with a smaller logical extent. It does not write padding or allocate a whole-field buffer.

`payload.beginReader(builder,grant):{step,reader}` replaces `reserveReader` and boolean `releaseReader`. It derives the first page from the original payload's private roster; callers cannot supply an arbitrary page/source. The returned concrete resident reader implements `advance(grant)`, `beginClose()`, `closeStep(grant)` and `terminalIsEmpty()`. The builder retains that exact reader before finalization/exposure. Its sequential read admits one actual neutral reader alias at a time, closes the old alias and its admission cell before moving to the next page, and forwards child work without adding wrapper work to the same grant.

The operation reader name may be an explicit type export of this concrete resident reader, not a second runtime wrapper. The old page `capture()` and writer `byteAt()` are removed. Reading goes only through the strongly registered concrete reader and its private neutral reader. A caller lost after constructor allocation cannot leave a count-only alias; the original parent retains both the concrete reader and exact neutral admission.

## Transition Slot and Fault Ownership

The same seven slot words remain `requestOwner,cell,record,entry,phase,failure,witness`. The domain-specific union distinguishes builder/page/reader entries and intrinsic owner/page/reader results. It stores the original request before canonical bootstrap. A terminal or failed child is not forgotten when its result is pending, blocked or rejected. A known no-cell rejection has a separate observation; an unknown throwing return retains the original fault and request.

Successful admission transfers the exact original cell/record into the registered child before freeing the slot. Close takes those exact obligations back into the parent slot before the child's domain record can detach or refund. Neutral resource completion, its result-alias detachment, admission-cell completion and parent-slot observation are separate phases. The slot cannot be reused while an unresolved original fault remains.

All existing `catch { #failure = string }` paths are removed during this cutover. Builder/reader/page/source failures retain the first exact `unknown` root under the already admitted child or original parent slot before returning rejection. Same-value replay is inert; a distinct thrown root remains with its caller. Fault-held is not clean-close, and neither record nor cell is refunded while it still owns the fault. Public diagnostics may name a phase, but they do not replace the original thrown value.
