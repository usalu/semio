## Selected Storage And Access

Replace the externally mutable `Arc<Mutex<Option<C>>>` consumer with an original ledger-owned typed consumer slot. Its public capability is privately issued and non-owning: it holds the exact original root/typed page identity and an admitted alias, never ownership of the page or C. There is no public Option guard, arbitrary Arc conversion, independent consumer constructor or numeric identity constructor. The actual typed slot has a closed-forward-access phase; every forwarded write checks that phase under the same allocation-free gate. Once closing begins, the slot can only perform its exact typed retirement handoff. An alias attempting replacement after the empty observation is rejected and retains its attempted source unchanged. Page release waits for exact aliases, but closing does not need to wait for a late writer merely to revoke mutation authority.

The page allocation uses an explicit Rust `Layout` for the actual typed node and a retained uninitialized-page descriptor. Requested bytes/slots/owners and work are reserved before `alloc`; a null result retains the original pending admission and source. Allocation and initialization are separate operations. Deallocation uses the original pointer/Layout and requires the actual C slot empty, links detached, and aliases retired. No `Arc` final release invokes C, no Vec excess-capacity debit is treated as preadmission, and no C destructor is delegated to the neutral page owner. The requested Layout is the observable allocator contract, not allocator-internal heap-bin occupancy.

The one inline bootstrap root stays outside all callbacks; its public borrowed facades are not last-owner roots. The current enclosing-root loss/poison problem is not solved by changing the page container. Actual original composition lifetime must own that bootstrap root through its measured final release. No panic-only Drop, leaked ManuallyDrop or process-global orphan store is proposed.

## Registered Destination Rather Than An Option Borrow

A typed receiver must be privately issued by the actual registered parent record, tied to the exact source consumer and the original parent record generation/phase. Its target is one exact inline `Option<C>` field selected by that original typed parent inside its already-admitted backing. No public arbitrary projection callback is authorized. Address, extent and alignment checks are safety checks only: containment cannot confer field-selection or funding authority. The parent record's actual allocation must cover the inline field; a declared envelope, arbitrary borrowed Option or caller byte grant alone does not.

Transfer revalidates source identity, receiver identity, parent phase, exact field and vacancy before detaching either source. Parent/receiver aliases prevent that backing from disappearing or moving meanwhile. Actual source movement and receiver descriptor installation have separate measured grants. The field remains in the original parent after a callback throws following transfer. Neutral close cannot infer C retirement from source emptiness: the actual parent retires C's descendants and final typed shell, then closes the receiver alias and page in subsequent phases. There is no public refund or `handoff_into(&mut Option<C>)` funding proof.

This describes a canonical typed parent-field receiver, not a second scheduler or a generic terminal callback. Any concrete projection and final-shell retirement must be supplied by the actual Plugin parent below, with native pointer/drop and short-grant tests. The source has not yet implemented or tested these receivers.
