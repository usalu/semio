# Packed Scene Field Preparation

The live `parseSceneJsonField` dispatches `pk:` strings to generic pack, not ScenePack. Its current whole-field `atob` → Uint8Array → recursive generic pack decoder must not survive the retained cutover. Generic pack has a symbol table, one synthetic record field, and a separate tag set; reusing the native UI scalar/collection envelope would incorrectly restrict valid scene content.

The next schema-first step is an exact prepared-field base64 owner. It captures the immutable prepared scene, validates/counts one source byte per step, explicitly closes that reader, allocates the existing bounded page-builder metadata, then decodes one source byte / emits at most one output byte per step into 256-byte pages. It never creates a whole binary string or contiguous decoded buffer. The two scans use the same captured source root. Cancellation retires readers, partial output pages, and source root explicitly; a taken page owner remains independently live.

The neutral fixture preserves the current `atob` alphabet, optional padding, ASCII whitespace, and ignored unused low bits. Invalid syntax must fail before a result is exposed. Empty binary base64 can decode successfully at this transport layer but must be rejected by the subsequent generic-pack grammar. The 16-KiB decoded fixture remains within the native 32-KiB Surface field envelope.

After the byte owner is tested, generic-pack parsing must retain symbol/text spans and collection frames rather than producing a whole compatibility object. Typed host projections then consume those records; JSON syntax preparation alone cannot be used for `pk:` data or credited as host adoption. The current fixture is staged while the released JSON/receipt files remain stable for coordinator verification; no packed-field implementation/test success is claimed yet.

## Implemented Base64 Packet

`OwnedUiSceneBase64Cursor` now implements the two-pass design. Its source capture invokes the prepared-scene private-brand-checked method directly, never a structural callback. Pass one validates exact prefix/alphabet/padding and counts decoded bytes. Its retained reader is closed before pass two. The existing Surface byte builder performs dedicated metadata allocation, page allocation, and individual-byte writes. A pending output byte is retained across page-allocation steps; no input is consumed while that byte waits. The source is immutable and held across both scans. Taken output pages remain independently owned after cursor/source retirement.

The test bound is `5 * encodedBytes + 1024`: two byte-consuming scans, at most one output-byte write per encoded byte, at most one page-allocation retry per output byte, bounded chunk fetch/release, and the fixed three-record fixture's two lookup/retirement paths. Actual chunk operations occur twice per 256 source bytes, not once per byte. Every advance checks monotonic total source bytes read, a maximum increment of one, one item, and at most 4,096 reported bytes. The fixture does not certify worst-case wall-clock allocation latency or the maximum native field envelope.

## Next Retained Grammar Shape

The packed-field result will gain a private mint before the generic grammar accepts it, preventing arbitrary constructed byte owners or callbacks from becoming parser authority. The grammar retains original immutable binary pages, numeric-indexed symbol spans, and numeric-indexed flat token records. Text is validated bytewise and stored as a span; f64 reads use a fixed eight-byte scratch, not variable allocation. Explicit list/map frames preserve input key order and duplicate pairs. Each synthetic record field emits an exact field boundary, allowing field-1 selection without throwing away unknown value fields or creating a whole object. Index edits, replaced roots, and cancellation retire incrementally; no chained overlay or full index clone is introduced.

Only a successfully validated terminal parse can transfer the token document. Readers capture the exact token/page root and release it through explicit retirement. Typed host projection will read these records, not accept caller-supplied token objects or reconstitute a full compatibility scene. The schema cases are authored, but this grammar/root implementation has not yet been executed.
