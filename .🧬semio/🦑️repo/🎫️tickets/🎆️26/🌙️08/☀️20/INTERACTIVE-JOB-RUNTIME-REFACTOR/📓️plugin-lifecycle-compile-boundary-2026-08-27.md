## Concrete Native Construction Preconditions

Further source read found two exact pre-admission joins within that chain. `plugin_create_app_with_id` currently creates a local app and binds its ID before the second fallible runtime borrow installs it; the actual opening owner must retain construction/binding state rather than treating a later failure as a clean absent app. `plugin_begin_instance_close` currently takes the live cell before allocating `Arc<RuntimeCloseWorkerState>` and its pump. The close worker shell must be admitted/allocated and structurally retained before that detach; successful quarantine capacity checking alone does not cover shell construction. These are source findings, with no production edits during the active inventory hold. PatchTracker's existing first-use bank initialization must similarly stay in Retained's admitted-backing work; calling a lazy initializer does not create prior allocation credit.

The existing reactor descendant receipt also still needs its bounded-body adoption, not merely aggregate wiring. `FixedResumeQueue::cancel_instance_step` pops a PendingResume and implicitly destroys it when its numeric instance matches. That payload can contain three Vec byte buffers or a Fault with scoped strings and causes, up to the existing 196608-byte logical cap. The admission helper counts lengths, not physical capacities; a one-entry cancellation is not one-page retirement. `step_reactor_close` currently calls that method and later removes InstanceMetadata with a String. Thus its current exact key and in-place close state preserve the cursor, but its `complete` bit alone cannot certify bounded descendant destruction. The final native aggregate must join a structurally retained typed resume/metadata retirement cursor and its actual backing ownership. No source change or runtime claim is attached to this additional source finding.

Fault progress also remains distinct from fault-owner retention. `plugin_step_close_cleanup` currently returns an error for RUNTIME_CLOSE_FAULT on every subsequent call; `try_schedule_runtime_close` only admits READY. The outer late-clock verdict can set that fault after an inner owner has reached a terminal phase, while the pump still owns its session/outcome or exact empty-shell handoff state. Consequently retaining those roots is necessary but does not prove eventual cleanup/retry. The lifecycle aggregate must retain the fault diagnosis while admitting bounded close-only progress of those exact owners, publishing no terminal receipt until their final destruction and a successful strict clock verdict. Blindly resetting the fault to READY, ignoring the verdict, or treating the absence of the app cell as completion would be incorrect. This is a source-confirmed pending join, not a new executed fault-recovery test.

The final worker shell has a separate alias/quiescence obligation. The scheduled closure upgrades a Weak to an Arc, calls `run_runtime_close_turn`, then reads status and finally drops its Arc after that function returns. `PluginInstanceCloseLease::is_retired` checks COMPLETE and empty cell/pump but does not establish that the callback's final Arc is gone. The production sealed terminal-owner release must therefore join callback quiescence and exact final shell ownership before claiming its measured release; simply dropping the lease might leave the actual allocation destruction to the worker tail. A raw Arc count alone is not a complete scheduling proof unless future upgrades are excluded by the exact terminal scheduling authority. This source finding does not alter the existing lease or weaken its terminal tests.
