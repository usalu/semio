# Retained Group Publication: Exact Next Boundary

## What Is Already Implemented

The Store member seam owns a retained wire decoder/preparation, validates exact member identity and revision/generation, seals group id before the edit digest, reserves a real history slot plus displaced-owner credits, and supports bounded abort/close. Tests keep both direct Store snapshots and envelope history unchanged throughout all-member preparation. Child admission remains fail-closed in the active plugin publisher; no singleton dispatch fallback remains.

The VCS history ledger now additionally supports a provisional suffix stored in its existing fixed generation slots. No edit or ledger is cloned. A unique low-level publisher owns one shared decision, and each ledger reads its selected bounds for length, first/last, positional access, forward/reverse iteration, equality, and serialization. Uncommitted suffixes are invisible; a single decision switches all staged ledgers; adoption only folds already-visible bounds into their ordinary fields. The serializer captures one iterator so its length and contents use the same decision snapshot. Ordinary insertion/removal/mutable access is blocked while a suffix is staged. An aborted suffix transfers one exact entry per call, preserving ownership for its caller's retained disposer. Foreign decisions and post-commit aborts reject. The two native tests use `🌿️vcs/🧪️group-history.json` and independent serde_json output; the coordinator is running their focused gate now.

ArtifactCursor now follows the existing ArtifactEnvelope owner-root pattern. Its public data is ArtifactCursorOwners; ordinary field reads dereference the selected immutable old/prepared root. Serialization captures the same selected root. DerefMut rejects any staged root, including a committed root before adoption. Group adoption returns the old exact owner; abort returns the unpublished exact owner, both suitable for the existing one-item/4096-byte ArtifactStoreCursorRetirement. All old structliteral sites were replaced with constructors (10Store,2host); no app source changed. New tests compare cursor/history joint visibility, previously held immutable cursor/history reads across commit, wrong decision rejection, empty bases, cancelled reservations, and unique-publisher Drop. Dropping the publisher only aborts its fixed decision; it never drops staged payloads, which remain available to explicit bounded retirement.

This is still only the history/cursor read-storage portion of the atomic group contract. The low-level decision does not mint complete group admission: Store snapshot/generation/revision roots and kernel/invocation/grouped-undo logs are not yet joined to it, and Child remains disabled. The previous statement that history/cursor cannot expose provisional roots is superseded by these implementations; the other Store owners below remain the next required work. The coordinator's retained_group_ native r2 gate passed all four tests (two history and two cursor), with zero failures and864filtered; compilation took41.99seconds. This includes the expected caught panic rejecting mutable access to staged cursor owners. These four passes are not a mounted atomic-group or grouped-undo/log pass.

## Why a Child-Content Root Swap Alone Is Insufficient

ArtifactStore currently exposes independent mutable committed fields: current snapshot Arc, envelope history ledger and cursor, applied/redo vectors, revision accumulator, actor, clock, tail-undo cache, generation, and content revision. Its direct snapshot()/snapshot_root()/snapshot_read(), envelope(), generation(), content_revision(), projection, and history readers observe these owners without going through ChildContentView. Publishing each Store first and swapping ChildContentView last would expose partial state through those direct readers.

ArtifactHistoryLedger now stages an invisible suffix in its fixed slots, and ArtifactCursor now exposes a selected immutable owner root. These two storage owners are ready for a common decision, but the current one-item Publishing arm still changes the other Store owners and appends ordinary history immediately. Calling that arm for every prepared member cannot produce atomic group visibility. The existing TransactionCoordinator compensation path invokes generic undo and is not suitable for the retained pipeline.

The direct-reader audit also found two compound-read boundaries that must select the decision once. `projection_event` currently reads its projection stamp and snapshot separately; a group decision between those reads could combine an old stamp with a new snapshot. Whole-envelope serialization previously called history and cursor serializers separately; the concrete captured-envelope implementation below now fixes that boundary. A captured Store read view still must bind snapshot/stamp/lease authority before building a projection event. Previously captured snapshot leases must keep their exact old snapshot while their commit-authority witness rejects the old generation/revision after the decision.

The schema-first gate is `🏪️store/🧪️group-read.schema.json` with its four language-neutral vectors in `🧪️group-read.json`: pending, commit after capture, capture after commit, and abort. The envelope history/cursor projections are now wired to an executable implementation test. The snapshot/stamp/lease expectations in those vectors remain unimplemented and are not counted as passing evidence.

## Captured Whole-Envelope Read Unit

ArtifactEnvelopeOwners.capture_read now verifies that its cursor and all four VCS ledgers either have no staged group or share the same private visibility authority. It samples the decision once, captures the chosen history iterator bounds and cursor owner reference, and returns an immutable borrowed ArtifactEnvelopeRead. Serialization of ArtifactEnvelope, ArtifactEnvelopeOwners, and direct ArtifactVcs now uses this capture path. The read object owns no cloned edits, strings, mutations, or snapshots and cannot mutate or publish the group. Different visibility owners reject before serialized output begins.

Two native `retained_group_envelope_read_` tests are source-ready. The four language-neutral cases compare exact serialized history/cursor IDs with independent serde_json fixture values. In the commit-after-capture case, a custom initial-snapshot serializer commits the group during actual whole-envelope serialization; the captured result remains wholly old, and the next envelope observation is wholly prepared. A hostile cursor from a different group rejects. Cursor roots are explicitly retired using the existing one-item/4096-byte retirement path. Scoped diffcheck passed; neither new test has executed yet.

This unit changes no ArtifactStore fields and does not claim atomic Store snapshot/generation/revision publication. Child remains fail-closed. It is a concrete dependency for the next complete Store read-root unit, not full group publication.

## Concrete Next Implementation

1. Introduce one private group visibility authority containing exact operation/generation, fixed participant count, an immutable prepared manifest identity, and a single committed/cancelled decision. Each staged member and the parent kernel/invocation log must reference that exact authority. It cannot be forged from group-id text.
2. Stage a member's complete read-visible commit view without modifying the previously visible view. History needs an exact provisional slot that is invisible to iteration/length/tail lookup until the shared decision; cursor/applied/redo/revision need immutable versioned owners or explicit versioned views. Do not deep-clone an envelope or mutation to manufacture the next version.
3. Route every direct Store reader through the same visible version, including snapshot leases and envelope/history readers. Ordinary writes must refuse while the exact participant reservation is held. This is required before plugin Child admission can become executable.
4. Prepare the kernel and invocation log entries, grouped undo records, canonical result pages, and next ChildContentView under the same decision. All participants and all resources must be reserved before committing. Group id must already be part of each sealed mutation metadata; no post-digest stamping.
5. The active plugin executor retains the original child order and a bounded cursor over children and operations. Advance one semantic/byte unit each turn. Repeated edits of the same child prepare against that child's previous staged post-state, not its live pre-group snapshot. This must not consume a second live history reservation accidentally.
6. After an exact all-participant freshness/reservation pass, perform one non-failing shared decision publication. No await, allocation, serialization, mutation application, or participant loop may occur in that final publication turn. Each participant lazily/finally adopts its committed staged state in separate bounded turns while all readers already resolve the committed version.
7. Before decision publication, cancellation/staleness aborts staged owners and releases reservations incrementally; it never calls generic undo. After the decision, cancellation stops further effects but cannot reinterpret a committed group as uncommitted. Retain ACK ownership until every result page is acknowledged, then retire each old version and manifest owner in bounded turns.
