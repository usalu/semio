# P9i OS Errors and Command Encoding

## Outcome

The bounded OS-kernel packet no longer uses `thiserror` in VCS, Run, or DB identity errors.
Each converted enum owns its exact `Display` text, implements `std::error::Error`, preserves causal
`source` values, and retains the `From` conversions previously generated by derive attributes.
The Run and DB facade manifests no longer declare direct `thiserror` dependencies.

The Store command encoder also had a correctness defect exposed by the de-async sweep:
`write_command_str` remained `async` while every production `ArtifactCommand::encode_op` caller
invoked it without awaiting the returned future. The future was dropped, so descriptions, author
identity, branch/checkpoint/coalesce/conflict identifiers, and other string fields could be omitted
from encoded commands. The helper is now a pure synchronous writer, and its one remaining awaited
composition caller was corrected.

The framework and Run manifests also dropped unused `pretty_assertions` development dependencies;
repository source contains no use of that crate. The final OS-host declaration is delegated to the
agent already owning that manifest.

## OS Test-Target Repair and Host/Shell Errors

The OS-kernel de-async repair now covers Store fixtures, inference-cache laws, SPR materialization,
the SPR facade, pack CLI fixtures, IO, command, VCS, channel, history, and DSL test implementations.
The command binary round-trip suite continues to exercise every string-bearing command variant,
including descriptions, actor identity, coalesce keys, branch/checkpoint identifiers, and conflict
resolutions.

`ExtensionInstallError` in the OS host and `ShellError` in the Shell module now use owned
`Display`/`Error` implementations. `ExtensionInstallError::Package` retains its generated `From`
conversion and causal `source`; every message is byte-for-byte equivalent to the removed derive
attributes. Both package manifests dropped their direct `thiserror` rows.
