## Mounting the Existing Owner, Not a Parallel Family

The original runtime instance slot must become the structural home of its current `GuestLifecycleCell` and native opening/live/closing owner. Its captured request and guest serial are reserved before the real app producer enters. Do not append another eagerly allocated 1024-entry registry and leave the old instance entry as an independently droppable authority. The existing close quarantine remains the worker scheduling/handback queue, referencing the same captured owner. It is not a second owner selected later by numeric ID.

The concrete source cutover has these admission boundaries:

1. **Existing registry backing.** Separate empty registry construction from backing admission. Obtain the actual checked `size_of`/alignment and requested capacity before allocation; record actual allocated capacity even on allocator overshoot/error. Initialization is separately caller-granted and retained. A 1024-slot logical limit does not require a single monolithic allocation: a backing request above the existing physical grant must remain blocked until the existing registry is paged, not increase the grant. Uninitialized backing and occupied entries stay in the original runtime owner during cancellation. The neutral slot-byte samples are injected arithmetic inputs, not measured Rust layouts or wasm claims.
2. **Opening.** Reserve the original slot, its exact open correlation, checked guest serial and rollback/close destination before invoking the actual app producer. Keep the real app option in that slot across bind/install/capture. An API that merely stores an app after a whole constructor returns is insufficient to prove ownership of partial constructor work; the actual producer must expose its staged construction root. Repeated Open retains the same slot and Captured outbox rather than reentering construction. Captured is published only after binding the real allocation to the guest lifetime.
3. **Close admission.** While the live allocation still exists, preadmit and retain the worker shell, quarantine receiver, exact ReactorCloseState, PatchTracker, PendingPatchAuthority, command ingress, render bindings, presence, and canonical return-source destinations. Refusal keeps already reserved children and the original app live in the same owner. There must be no fallible detached-root rollback. Existing instance actor bytes are retained in the same original runtime owner until their measured release; removing its map entry is not proof.
4. **Exact descendant dispatch.** Preserve `NativeCloseKey` through the original producer/Ready/receipt and through task, request, resume, timer, metadata and presence admission. An exact close token on the outer cursor does not make a downstream numeric-instance sweep safe after reuse. Retained owns key-preserving PatchTracker slots and its matching close-reservation validation; this lane owns Pending and the reactor descendant join. The old guest call sites must supply the key from the original runtime-owned capture, never recreate it from current lookup or surface names.
5. **Typed retirement.** Retain the current PendingResume in its queue-owned retirement slot instead of popping and dropping it. Command, all three Emit vectors, ActionMeta actor bytes, Fault code/message/scope/cause fields and InstanceMetadata String storage each need explicit byte and final backing retirement. Count physical capacity separately from initialized content, including an empty reserved vector. A partially retired String cannot be exposed as valid UTF-8. Preserve exact cursors through busy/poison/error/unwind; no thread-global discard sink or `mem::forget` counts as recovery. Existing typed UI and published/source handbacks remain distinct children; page-input ACK is not their final witness.
6. **Worker quiescence and terminal release.** The exact scheduler authority must revoke future upgrades, acknowledge every queued/running callback and transfer the original shell to its retained terminal owner. A callback-owned tail cannot simply set a Boolean before dropping its final Arc and call that measured final release. Only the structural terminal owner may release the last shell under its turn grant, after all callback ownership has returned. This requires an explicit queue/callback handback, not a sampled Arc count. A final clock failure retains the exact released-shell witness and staged Retired ACK so the same ACK can retry without rebuilding or losing an owner. Fault diagnosis is preserved while bounded close-only progress continues; resetting a fault to normal work is not recovery.

The old two construction tests are the first narrow runtime gate in this chain, not a substitute for it. Pending's staged tests remain unmounted until the genuine baseline is available. No source reducer or constructor was changed in this packet.
