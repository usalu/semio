## Smallest Existing Ownership Seams

1. **Event/metrics candidate in the mounted host owner.** [EventQueue::enqueue](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🖥️host/📦️packages/🦀️rust/🦀️enqueue.rs:262) consumes input, advances its own generation before capacity checks, and may replace coalesced state; it has no reservation/commit API. Keep the incoming exact DispatchEvent or scalar metrics structurally retained, preflight discrete count/bytes plus both checked generations, and produce an unpublished enqueue candidate. Reuse the existing fixed coalesced slots/discrete backing; do not clone the queue or undo a published enqueue. [FrameScheduler::invalidate](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/🖼️render/📦️packages/🦀️rust/🦀️schedule.rs:102) is a small dirty-mask mutation, so an invalidation candidate can remain a scalar until accepted. handle_metrics must consume the typed candidate/verdict and stop on refusal/fault; changing only the helper's return type without joining its two downstream enqueues leaves the bug.

2. **Retained frame admission already exists, but completion is not unpublished.** [AppPresenter::admit_next_frame](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑️‍🎨️engine/📦️packages/🦀️rust/🎯️targets/🧊️wgpu/📦️glue.rs:14514) checks pending capacity before invoking the producer and stores AppPresentCursor in `self.pending`. Its existing packet/witness/gpu_cursor plus retirement owner are the correct domain to extend. Do not introduce a second watchdog or copy the frame. Add a held completion candidate carrying generation/cursor/fullscreen/wake and retain original pending/retirement authority until the actual outer verdict. At [Directives](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑️‍🎨️engine/📦️packages/🦀️rust/🎯️targets/🧊️wgpu/📦️glue.rs:14789), window cursor is already changed and pending is taken before Complete returns. At [winit completion](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑️‍🎨️engine/📦️packages/🦀️rust/🎯️targets/🧊️wgpu/🦀️winit_app.rs:197), cursor-wake acknowledgement, platform_fullscreen, revision allocation and snapshot publish all precede finish. These must not be represented as an already accepted result.

3. **Final GPU/platform commit is an irreducible separate boundary.** [prepared_present_step](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🖱️ui/📦️packages/🦀️rust/🎯️targets/🧊️wgpu/🦀️gpu.rs:414) submits GPU commands at 428/469/484 and calls `frame.present()` at 491; its elapsed check happens afterward. Presenter also resizes GPU at [14381](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑️‍🎨️engine/📦️packages/🦀️rust/🎯️targets/🧊️wgpu/📦️glue.rs:14381), changes fullscreen in its Fullscreen phase, and changes cursor in Directives. A late outer fault cannot undo any of these. The smallest honest split keeps preparation/candidate acceptance separate from a later exact retained commit operation, with that real operation itself measured by the existing watchdog and forbidden from issuing a success ACK on overrun. Moving submit/present/window calls after finish merely excludes them from measurement and is **not** a valid fix. Guaranteeing “no external effect if that same final platform call overruns” has no existing transactional platform API here; retain this limitation explicitly, quarantine the exact owner, and report any already executed effect rather than fake rollback.

4. **Snapshot/mailbox admission must be real.** [RenderSnapshotSink](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑️‍🎨️engine/📦️packages/🦀️rust/🎯️targets/🧊️wgpu/🦀️render_snapshot.rs:82) uses blocking mutex acquisition; publish allocates Arc and drops/replaces the old owner under that mutex. It has no preadmitted retained receiver. [RuntimeMailboxInner::enqueue](/Users/ueli/Documents/semio/🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑️‍🎨️engine/📦️packages/🦀️rust/🎯️targets/🧊️wgpu/📦️glue.rs:11824) allocates revision before a blocking completion lock, marks presentation authority, then calls a waker. `has_lossless_capacity` is a separate lock check, not a reservation. Reuse these domains with exact retained candidate/receiver authority and nonblocking refusal; simply staging a small snapshot value does not cover allocation, old-owner retirement, mailbox contention, or arbitrary waker work.
