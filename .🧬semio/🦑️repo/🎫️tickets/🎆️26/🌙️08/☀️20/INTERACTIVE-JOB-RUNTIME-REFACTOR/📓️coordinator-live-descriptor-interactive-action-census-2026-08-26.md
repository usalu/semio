## Result

The 32 metadata-discovered descriptors contain 101 app declaration contexts, 94 unique app identities, and 4,754 window-action rows. The declared `semantics.execution.interactiveJob` disposition is:

| Disposition | Rows |

This is a metadata census, not production acceptance. The live tool-job ledger at the captured checkpoint exposes 165 accepted exact command rows plus 8 accepted shared routes, so a `migrated` descriptor field alone is still insufficient and must never be treated as proof of a bounded production factory, worker dispatch, preview/progress, cancellation, commit freshness, or exact owner handback. Ninety-nine accepted command rows are Puzzle launch-only product rows and therefore do not join this descriptor ledger.

The census is now executable through the registered `bun ./📜️script.ts verify interactivity apps --actions` gate. Its base discovery path is GREEN; its action-acceptance path is RED on the exact 2,781 missing rows and prints bounded diagnostics. Each app is capped at 512 action declaration rows, with a maximum-plus-one hostile fixture.

The gate now also joins each declared migration to the exact live production command owner. At the latest checkpoint, 601 of the 1,973 migrated descriptor rows join to 165 accepted exact command rows or 8 accepted framework-reserved routes, while 1,372 migrated rows remain without an accepted owner-local command or reserved route. The 99 Puzzle commands are launch-only and do not inflate the descriptor join. Together with the 2,781 missing dispositions, the fail-closed total is 4,153 of 4,754 action rows. Its hostile laws cover a correct owner-local join, a wrong-owner rejection, and a separately proven shared route, so another plugin's same-named command cannot certify an app. Puzzle-only clipboard/import proof is intentionally owner-local and cannot certify identically named actions in other plugins.

## Required gate hardening

The final discovery-driven acceptance matrix must join each descriptor action row to:

1. one exact command identity in the tool-job ledger;
2. one truthful disposition and schema-derived capacity contract;
3. one concrete production factory registration;
4. one admitted worker-session dispatch from the real app entry;
5. native and Wasm timing, cancellation, freshness, close, replay, and exact-handback evidence;
6. equivalent English and German accessible progress/cancel/status semantics;
7. desktop and exposed mobile/tablet surface evidence.

Any missing join, duplicate ambiguous join, or descriptor-only `migrated` declaration fails closed. The 2,781 missing rows must be classified only alongside their implementation packet; bulk metadata relabeling is forbidden.

The seven repeated declaration contexts are owned explicitly by Demonstrator as well as their source descriptors. They are not silently deduplicated: production reachability runs per declaration context, while deterministic semantic output is compared per unique app identity.
