# Exact Native UI Descendant Retirement

## Source-Confirmed Defect

`UiValueArena::retire_one` currently frees a collection slot while returning its final page for ordinary Drop outside the arena lock. That page can own another List/Map handle, which is only then queued. Root-slot disappearance and the global queue result therefore do not establish exact descendant retirement. Document leases and turn-patch owners similarly drop typed child records and do not join their nested value-page ownership. This is independent of the actor wire codec and app-worker close lease.

## Selected Collection Seam

The new owner consumes one `UiValue` without copying it. A shared collection alias releases only that alias; its remaining owner still owns its payload. A final alias transfers to an exact slot-plus-epoch retirement root. The arena itself retains the traversal cursor and child-to-parent links, all inside its existing fixed collection admission slots. Each call consumes one metadata operation or at most the caller's text-byte grant. No depth scan, recursive Drop, growing traversal vector, global-empty check, or user-supplied completion callback participates.

The arena retirement queue is now an intrusive fixed-slot queue so an exact root can be advanced and removed in O(1), independently of unrelated queued roots. A cursor atomically claims and unlinks its root from the global queue, preventing unrelated global cleanup from consuming its payload bytes or progress. A nested final alias is attached to its exact parent and visited before its parent page is released. A shared nested alias is released in O(1) without claiming its externally owned payload. A root remains active until its final child and page have retired. Epoch checks prevent later slot reuse from extending or satisfying a different owner's authority.

The API is `UiValueRetirement::new(value)`, `close_step(maximum_items, maximum_bytes)` and `terminal_is_empty()`. The close result distinguishes progress from released owners and reports actual retired semantic text/key bytes. Zero item or byte grants leave ownership untouched. Text lengths are reduced bytewise only after the owner is inaccessible to readers; no partially retired UTF-8 is exposed. Fixed-size scalar and allocation metadata use item units, not fabricated byte credit. A strict terminal guard prevents accidental live-owner Drop.

The terminal guard is unconditional, including unwinding. A live List/Map dropped before its first close step transfers its existing exact handle to the intrinsic arena root queue in O(1) before the guard fires; a mid-close claimed root is unclaimed and requeued with its exact retained descendant cursor. Thus a caught guard cannot orphan a heap-backed collection. There is no synchronous draining loop and no new allocation in Drop. An intentional panic during live scalar-owner destruction is tested in a separate native process and must remain fatal, not silently waive ownership checks. Scalar text is fixed inline storage, not an untracked heap descendant.

## Exact Typed Consumers Still Owed

The native `UiValue` descendants occur in `Component::Extension.props`, `ActionBinding.args`, `MenuRef.args`, and intent args/input. `UiNodeRecord` combines these with component fields, bindings, menu and children; `UiPatchOp` can own a whole node or individual component/binding/menu fields. These owners require typed retained extraction, not dropping a whole record after removing it from a document slot. Their enclosing document/turn-patch/handback witnesses must survive until those extracted owners finish.

The full typed census additionally includes `TreeItem.row_actions[].action.args`, `Surface.bindings[].args`, `SurfaceDoc.bytes`, `Text.data_attributes`, `TreeItem.drag_data`, `Select.items`, `KeyValueList.entries`, grid row/column tracks and node children. Fixed-map keys and values are both semantic text. A whole-node or component transfer must not hide these under a final ordinary Drop. All 18 component variants and all 11 patch variants need an exhaustive typed match, with one nested owner retained until its descendants and allocation are empty; document or published-patch completion must not advance merely because its row was removed.

Before the fixed-list correction below, `UiFixedList<T, N>` owned `Box<[Option<T>]>` with initialized None entries through capacity. Even after all logical elements had been popped, ordinary Rust slice Drop could still visit capacity-sized discriminants. The corrected representation removes that structural issue; it does not certify every current UI producer or cold helper.

## Fixed-List Initialized Ownership

The private backing is now a `Vec<T>` whose initialized length is the actual logical length, with an explicit reservation of the existing `N` envelope before the first push. This preserves the fixed admitted count, ordered sequence and serde array wire without exposing a new external type or using unsafe allocation casts. Pop moves one exact payload to its typed retirement owner. A separate empty-allocation release method refuses while any payload remains; once empty it moves and drops only the vector allocation, without visiting `N` absent discriminants. No generic automatic draining Drop was added.

The API separates `try_reserve` from allocation-free `try_push_reserved`. Existing `try_push` remains an explicitly cold convenience for callers not yet holding allocation admission. `release_empty_allocation` returns an error without mutation when live elements remain, and distinguishes one actual retained backing-owner release from an already empty owner. The logical `N` envelope remains authoritative even when an allocator returns excess capacity or `T` is zero-sized. `UiPatchOps` currently admits 1,153 entries, so eliminating initialization/drop of all absent `Option<UiPatchOp>` slots is a real structural change, not a smaller-domain workaround.
