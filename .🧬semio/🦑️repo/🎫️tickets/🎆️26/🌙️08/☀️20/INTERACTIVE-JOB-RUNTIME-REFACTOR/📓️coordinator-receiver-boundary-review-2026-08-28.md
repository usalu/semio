Coordinator read the complete Demonstrator `📓️original-receiver-admission-design-2026-08-28.md`. This is design review only; no schema/API/source mount was approved.

Existing output448 funds only Slot/facade/outcome; pending controller, original worker ingress, raw external backing/cells, parser/projection and fault slots require their own original registrations before post. No new allowance or channel is authorized.

One outstanding canonical return per original worker is not yet a complete capture design. The same callback can receive ordinary replies and unsolicited frame/trap/host-effect traffic. Before implementation, the owner must census every actual producer/consumer message kind and specify original-root capture and transfer before discrimination. It must neither mistake legitimate traffic for a canonical violation nor route a malformed canonical object through an uncaptured ordinary path. Existing accepted work cannot silently be dropped or globally serialized by implication.

The original worker ingress slot and separately funded first-violation slot must outlive their individual request. Exact activation and actual dispatched transport sequence are checked only after raw capture. Wrong/current-route identities, post-then-throw, late closed custody and malformed headers retain their original roots. A first-violation containment contract does not claim arbitrary hostile-flood memory bounds.

Neutral exclusive backing transfer is storage evidence, not worker identity, delivery, native InputAck or semantic consumption. No-response release requires exact original transport retirement; source/semantic readers must detach before scrub/refund. The existing canonical binary envelope remains the sole returned-response grammar, with no object/binary compatibility union.
