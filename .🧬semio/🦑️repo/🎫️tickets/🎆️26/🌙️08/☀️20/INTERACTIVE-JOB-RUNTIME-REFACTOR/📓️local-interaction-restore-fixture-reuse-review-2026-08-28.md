## Reuse Decision

The six vectors are suitable semantic inputs for the existing Interaction owner. Keep the exact `semio:local-interaction#/$defs/restore` union and full identity; do not convert them to SetState, query ACK, Presence or a new AppChannel frame. `graph`, `private` and `aux` are fixture domain IDs, not a graph-specific command owner. Their string content, ordered selection IDs and anchors must remain untouched.

| Packet case | Retained-owner reuse | Missing live proof |
| --- | --- | --- |
| Full exact base | Construct an unexposed empty three-map candidate, then fill the union of keys from all three incoming maps | Bounded traversal, absent-domain clearing and one final all-domain publication |
| Sparse all-null removal | Existing `begin_domain_patch` removes the target entry in all three maps | Exact input admission, registry/topology validation and Store publication |
| Explicit private-domain values | Same typed patch preserves anchor and literal comma ID | A real declared `SelectionSpec.broadcast=false` domain and absence of private outbound Presence data |
| Empty sparse | Preserve the original three-map content without inventing defaults | Exact ordinary result/receipt semantics and no partial publication |
| Stale generation | Compare the complete captured identity before candidate/publication work | Actual retained operation refusal/close, original Store still authoritative |
| Stale topology | Revalidate original topology inputs, not just payload syntax | Fresh document/config/topology source capture and stale rejection at final publication |

The existing root cursor is a **one-domain** three-map update. `LocalInteractionRootUpdate` owns its candidate, domain, patch, current OrderedMap cursor and cleanup. `advance`, `take`, `begin_close` and `close_step` can be reused inside an outer retained restore owner. They do not themselves provide multi-domain atomic restore or identity validation. For full restore, an initially empty candidate naturally clears absent domains, but selection-only enumeration would incorrectly omit mode-only or granularity-only domains; the outer cursor must traverse their union. For sparse restore, start from the captured immutable original root and visit only supplied domains. Each completed domain remains private to that same outer candidate until the single final publication.

The original candidate/update/retirement owners must remain in the command's structural fields outside catch/unwind execution. `from_cold`, full serde construction, cold root conversion and whole BTreeMap iteration are not live bounded admission. Existing `ManuallyDrop` retention during an unwind is not, by itself, a recoverable enclosing command owner. No new live result is claimed by the protocol's earlier update3 tests.
