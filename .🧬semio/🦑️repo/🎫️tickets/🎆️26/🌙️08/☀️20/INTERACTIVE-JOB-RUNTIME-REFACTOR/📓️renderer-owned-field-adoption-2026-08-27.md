# Retained Node Field Ownership

The next live-adoption unit must not put the normalized decoder's borrowed records directly into the numeric index. Raw references neither capture surface-byte owners nor provide a final-entry retirement witness. Retaining each prior whole node inside the next node would also create an ever-growing ownership chain.

The chosen model gives an owned node seven direct immutable field roots: component, layout, style, accessibility, bindings, menu and children. Identity, key, activity, disabled and transition are fixed scalar metadata. Normalizing an upsert separates those field roots at their construction boundaries. Replacing one field captures the unchanged direct field owners and moves the exact new field owner. It never retains an older node as an ancestor and never reconstructs a map or copies an opaque surface payload.

The persistent numeric index owns an `OwnedUiNode` handle. A final index-entry retirement yields that exact handle to the record retirement cursor, which closes one direct field root at a time. Captured old numeric-index snapshots keep the old entry alive naturally. A temporary read used across removal or replacement must independently capture its node before the index edit, because a prior concurrently published root may already be retiring; relying on the borrowed record after its last index owner disappears would be unsound.

Node fields become part of the exact typed payload proof. No public arbitrary root projection callback, supplied digest or JSON cast can mint a field owner. A node's public read model only borrows immutable field values; a caller retains the explicit node/snapshot owner while reading them. Surface-byte views remain read-only and contain private exact handles.

Required laws: repeated field replacements retain a constant number of direct roots; unchanged field allocation identity is preserved; an old snapshot's surface bytes remain readable across a replacement and cancellation; final old-reader teardown releases those bytes; failed/stale candidate construction retires its own new fields without releasing the current root; removing a node captures its children before retiring the entry; zero grants do not release ownership. These are implementation gates, not currently credited live behavior.

The eventual per-instance close owner must wait for pending transactions, published snapshots, typed field roots, tree/hash work and notification frontiers. Starting close or deleting the actor/surface map does not witness completion. The channel executor owns that outer exact-instance close protocol; the renderer supplies its explicit retained participant.
