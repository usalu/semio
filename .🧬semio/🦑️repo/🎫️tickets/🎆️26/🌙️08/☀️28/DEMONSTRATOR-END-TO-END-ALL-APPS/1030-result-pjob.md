## Design finding
The peer's job model: callbacks run only on the genuine original caller (`drive_step(job,cx,receiver,..)`); semantic outcome/continuation live in the payload's `OriginalJobReturnReceiver`; the worker payload is prepared before the native authority exists (`OriginalWorkerJobAdmission` -> ready `OriginalWorkerJobAuthority`). Everything built on private contexts (ledger payload, pool submit, `run_staged_callback`, `try_reserve`, page initialization) is obsolete and was removed, not shimmed.

- New/changed: phase enum `{Outcome,OriginalFailure,BeginClose,Payload,Job,JobRelease,Parameters,Empty}`; `step_on_original_caller` drives `drive_step` with the payload receiver (Outcome -> `receive_outcome`, Continuation -> `receive_continuation`, treated terminal); fault published on the caller via `admit_fault` when `fault_pending`; `acknowledge_outcome(cx)->Result<bool,..>` (receiver ack or fault slot); new `continuation()`; `outcome_demands` covers receiver outcome; close ladder = outcome, failure, begin_close, `payload.close_step(cx)`, job, release, params, authority vec; `admission_demand` = native state capacity only; `.result` taken from peer `close_step/return_alias_step/remove_terminal/admit_owned_retirement`.
- Known gap: an overrun-quarantine that coincides with a terminal outcome no longer converts that outcome to a fault (receiver outcome cannot be moved out); non-terminal overruns still fault on the next step.

## PAYLOAD WRITER
`RetainedJobPayloadWriter` and `JobPayloadPageGrant` (old `✍️payload-writer-and-grant`) were replaced, not dropped, by `semio_framework_job_payload::RetainedPayloadBuilder` (`🧵️job/📬️outcome/📦️builder/🦀️.rs`; also re-exported via `semio_framework_job`). All methods are caller-funded turns returning `RetainedWorkOutcome` (result + work); post them with `semio_framework_job::receive_original_retained_work(cx, turn)?` (returns `RetainedCloneStep`; `Complete` = finished). No Result-returning one-shot exists and there is no `JobPayloadPageGrant`.

## Redesign wave (renderer, plugin session source, host-base) -- PARTIAL, only job-worker verified
New shared mechanism in job-worker (wasm --lib GREEN, pjob-19): `WorkerJobSessionAdmission<J,S>` + trait `AdmittedWorkerJobSession` (`👷️worker/🚪️session-admission/🦀️.rs`, exported). It wraps `OriginalWorkerJobAdmission`, the ready authority and the born session: `advance(&mut job,&mut params,cx) -> Result<Option<S>,OriginalTurnFailure>` does at most one real admission action per original turn (advance -> take_ready -> admit_ready -> close admission), returns the session only after the admission itself is closed; `close_step(cx)` retires born session, authority, admission in that order; Drop asserts terminal-empty. S = WorkerJobSession | MountedWorkerJobSession | BatchJobSession. Callers must not re-create the job/params while `job.is_none()` but the admission is non-empty (guards added below).
