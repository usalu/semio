# Exact Flow Retirement Custody Design

Status: proposal only. No production edits or Cargo in this window. Runtime owns editor r6 and actor laws. Based on actual retirement-red2 compiler GREEN, retained-authority retry PASS, consuming cold helper FAIL by nonterminal Drop. Prior ValueError-to-Fault mapping fixed compilation, not this custody contract.

## Decision

Keep interactive original hosts inside their already funded typed command job from birth through publication and terminal close. Do not move a refused host into a global collection or the app-wide session as a substitute for the original operation. Use the genuine operation/window address already in the job payload/context. A failed close returns the original error while the job remains the nonterminal custodian. Pure read-only UI paths must borrow projections and create no evaluation/history host to dispose. The consuming cold helper returns an explicit refusal containing its exact retirement, never ValueError alone. These changes must land together with all affected caller conversions; changing only the cold result type is not a correct partial implementation.

## Concrete API and State Batch

1. H/🏁️host-close: add must-use FlowHostCloseRefusal { original:ValueError, retirement:FlowHostRetirement }. No box, allocation, cloned host, replacement source, implicit Drop close, or error-only From conversion. Expose into_parts so caller must handle custody. FlowHost::retire_cold -> Result<(),FlowHostCloseRefusal>; any demand/step/stall failure moves the local original retirement and original error into refusal. Preserve error.retained_progress exactly; cumulative work must not be charged again on the resumed close. Add borrowed cold driver on retirement if needed to share code without another owner birth. Do not weaken Drop.

2. Replace runtime closure helpers with caller-owned scoped host work, provisionally FlowHostScope<R> { host:Option<FlowHost>, retirement:Option<FlowHostRetirement>, output:Option<R>, primary_failure:Option<ValueError>, failure_transferred:bool, phase }. The state is inline in the concrete command work; its original frame size is already quoted by the actual factory, with tests verifying the unchanged wallet can admit the new exact demand. Separate new/operate/handoff/close/output phases. Handoff returns exact original source unchanged if its preflight fails. There is no allocating Vec of failures and no guessed reserve. R must remain original and have its own declared close path when rejected; avoid a generic destructor that drops arbitrary R. In concrete code prefer existing job fields over introducing an unnecessarily universal generic.

3. On first valid close Err, retain retirement in the same job field. Keep original ValueError in primary_failure only until its one authorized transfer to the runtime failure channel; transfer it by move through existing OriginalTurnFailure conversion/debit once and record failure_transferred, with no clone or second error owner; continued physical closure belongs to the job closing protocol, one admitted step at a time. No automatic command reexecution. The host remains owned even when close reports Err. Outer job terminal_is_empty remains false until host and pending output have closed/transferred and original failure has transferred exactly once. Every next-close demand comes from the exact retained cursor; normalize Complete only against that cursor terminal predicate. Verify scheduler keeps failed closing job custody: this is a required regression gate, not an assumption.

4. Tick result generation becomes staged before consuming parked requests: job owns host and the original per-window emit/intake until commit. Construct origin leases and invocation publication in the existing job/state under actual grants; only then consume the tick outcome as delivered. If close faults after evaluation, hold exact host plus pending tick outcome in the original job, not in a local Vec that falls off an Err. Settle/abandon only that actual window through its existing latch APIs. Do not reset all session ledgers. Sibling windows and their in-flight invocation leases remain intact. Prefer borrowed pending-origin traversal so a failed close cannot orphan requests already removed by take_pending_extension_evals.

5. The UI and viewer path uses borrowed pure projection. Extract the current DAG projection from H/🌳️host-evaluation-history/📝️dag-sync-widget-properties-and-canvas-settings/🦀️.rs::build_dag_host_snapshot_v1 into shared host-read code taking &FlowHostSnapshot + actual operator-info map; preserve widget deduplication, cycle filtering, port resolution, node dimensions and DagHost layout semantics, proven against current genuine host outputs. Extract compiled_wire_literal inputs similarly. H/🌊️node-graph-extras no longer creates host only to derive status: publish the session-owned current status only when it belongs to the same snapshot revision, or, preferably for the coherent batch, derive identical status through borrowed snapshot/baseline projection; never substitute empty status. Current build_flow_status_json depends on blocked-port inference and remaining/wave state, so simply returning session.status_json is not equivalence without revision proof. Extract those calculations using the same underlying tree/seeds/cache interfaces and exact source data. Rendering cannot receive typed retirement failure and map it to PluginAssemblyError because it has no physical owner slot.

6. F viewer render currently creates live clone + new session + host and even imports editor host helper despite its purity doc. Remove these throwaway mutable owners: render graph/LOD/capabilities from pure snapshot and operator registry; optional evaluation/status only from actual viewer-owned read source. For P3 preview viewer and P2 IO that currently actively evaluate, graph-only extraction is insufficient: route real evaluation through their owning retained job/instance lifecycle and let render borrow its published result. Do not invent a fake evaluation or fall back to empty output. Offline encode/decode utility boundaries must return typed owned failure to their real importer/exporter job instead of formatting it away.

7. Cold with_host_snapshot and P2/P3 model with_host cannot remain Result<R,ValueError>. Replace them with explicit owned outcome carrying output + retirement on close failure; keep both body primary error and later close error without overwriting either. Runtime callers must be migrated to owning work or pure projection in the same batch. Tests/CLI utilities drive original returned retirement with their explicit diagnostic owner; no expect/drop of live typed refusal in failure tests. No compatibility aliases.

## Job Closing Evidence

The actual outer mounted operation close ladder at 🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🧵️instance/👷️jobs/📥️staging/🔒️close-ladder/🦀️.rs::close_latest_wins_command_step borrows its pending operation and returns pending.close_step failure without removal; it removes the operation only after command owners, metadata, cancellation lease and original cancellation cursor are empty. Thus inner job ownership fits the existing custody design. The genuine job refusal regression must still prove this path with the same real runtime rather than assuming inner struct fields alone solve terminal release. Retained receipts are debited by 🧰️framework/🔨️modules/🧵️job/♻️retirement/🎟️context/🦀️.rs, which keeps primary, receipt refusal and context refusal separately; use that path rather than consuming the original error into an uncharged message.

## Schema First and Required Bounded Regression Matrix

Author neutral close-contract schema + fixture next to existing cold-retirement fixture, with input source identity token, actual window/operation address, exact grant sequence, injected authority refusal turn/kind, expected work/receipt sequence, output transfer count, final terminal state and expected sibling latch states. This is in-process nonpersisted lifecycle; no artifact document migration or new wire compatibility version is needed. Schema fixtures describe custody and outcome events rather than Rust method strings. Use existing JSON parser plus Ajv validation and SQLite transaction/constraint state model as independent trace/custody oracle; keep exact canonical output expectations independently generated through existing Node SHA256/JSON oracle. A third-party library does not independently implement custom Flow close semantics; state that limit honestly.

1. Cold direct: same real decorated Store, AllocationFailed preserved, same retirement identity returned, no panic; retry its original cursor to terminal and observe zero leaked original physical owners. Measure each turn heap traffic against its original copy/capacity/release receipt.
2. Body+close failure: original body error and original close error both survive; no replacement by last error; exact body result/leaf custody retained until rejected/retired.
3. Typed job: inject one valid authority refusal after original host admission, run actual root runtime closing under unchanged execution contract; job slot remains until terminal, one original failure reported/debited, each physical turn grant fits and only terminal job frame releases. No hidden allocation on refusal handoff.
4. Window A/B: two genuine addressed windows with real latches; A parks extension source then close refuses, B has independent in-flight request. Assert no original source disappears, no evaluating node has missing invocation owner, A failure/outcome delivered once, B latch and callback unchanged; no whole-session cancellation.
5. Reserved capacity/depth denial: before constructing/taking source, insufficient grant leaves original in same job/source slot; after funding exact original quote it resumes without a replacement owner.
6. UI purity: editor main/compiled, Flow viewer, P2/P3 graph and P3 topology render exact existing node/edge/port/layout/status fields for neutral fixtures, but construct zero mutable evaluation/history hosts. A live session with unrelated refused job still renders its current owned published state.
7. Viewer active eval and document IO: genuine job cancellation/close refusal retains exact computed geometry/text and original host until publication or rejection closes it; no empty output success.
8. Normal native and wasm packages from prior4package check plus owning host3D/2D laws; same exact wallets and caller resource limits. Whole phase tests must pass once; no broad unrelated reruns.

## Scope Assessment and Acceptance

This is larger than changing one cold Result type because current UI functions have no owned failure recipient and several active IO helpers expose plain text results. The smallest coherent source batch is the host API plus the real job states and pure read helpers above. If root chooses a narrower first batch, it must remove runtime reachability of the remaining error-only cold helper users rather than leave a typed error that drops its owner in map_err. Baseline snapshot/Widget cold retirement APIs are separate and should not be swept into this batch. No limits raised, no compatibility layer, no global owner, no fake caller, no panic suppression and no tests claimed executed in this planning window.
