## pack-json-source (6 errors -> 0), DESIGN DECISION for runtime2
- The scoped-source control API (`new_scoped_source`, `resume_scoped_source` with observe/allocate/work callbacks) is gone since commit 728; its replacement is the recorded-Source model (job `OriginalSourceEncodingOwner`). That model admits exactly one flat byte backing (`EncodingTurnContext::allocate` refuses a second quote, `control.step()` is refused in recorded mode), but the JSON cursor allocates frames, path and output (three backings over several turns) and calls `control.step()`.
- Decision taken: each turn builds a LOCAL `NativeEncodeControl::new(grant.maximum_capacity_bytes, observe)` (observe = binding matches and not yield), the cursor still takes one structural phase per turn, and the encoder posts the cursor's own receipt (`normal_step_progress`, `last_turn_work`) to the caller turn exactly as before. No continuation is needed any more (the cursor keeps its own allocation markers), so `NativeScopedEncodeContinuation`, `PauseFault`, `failure_return` and the `pause_*` accessors/consts are removed (no external users, grepped). The close step runs the ControlledRetirement through `cx.with_original_effect` + `receive_original_retained_work` (single debit, overrun refusal).
- Lost vs the old design: per-allocation callback gating by the host while the cursor runs (now the grant + `maximum_bytes` ceiling and the checkpoint observer bound it). If runtime2 wants the recorded-Source authorities for JSON, the job encoding module must first allow several allocations per Source and a pausable control; that is a job-crate design item, not a port.
- The two in-file tests were edited to drop `failure_return`; not run.
