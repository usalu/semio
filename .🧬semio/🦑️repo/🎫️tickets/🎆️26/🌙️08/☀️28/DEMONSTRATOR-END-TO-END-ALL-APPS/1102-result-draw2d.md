### Performance root cause (funded stroke path, was ~4 s per job)
Profiled with `bun --cpu-prof` on the painted-ellipse prepare job (nested `PaintedPathPrepareJob` -> stroke union -> `BooleanJob`, one child unit per parent turn). Fixes, all in the framework, behaviour unchanged:
- `🔲️pixels/🖊️coverage` `CoverageJob`: the active list was fully re-sorted on every band (quadratic); now an incremental insertion into the sorted active list. Stage names and the Rust twin fixture are unchanged.
- `⏱️turn` `TurnLoan`: `Object.freeze` per turn cost ~25% of the stroke phase (JSC slow path); the loan keeps its state in private fields, so no freeze is needed. `assertRetainedWorkTurn` now returns the actual work, removing a duplicate read in the step constructor.
- `RetainedWorkLedger`: constructor no longer allocates a 64-slot array, spreads the grant or iterates `Object.values`; holds grow lazily to the same 64 ceiling; `remainingItems` replaces allocating `remaining` in the hot loop; the idle `nextDemand` is a shared frozen constant.
- `RetainedWorkProducerRuntime`/`Step`: lazy failure arrays, no getter indirection per step.
- `BooleanJob` and the painted stroke union cache their producer owner (closures were rebuilt on every one-unit child advance); `BooleanJob.intern` uses a numeric grid-cell key inside the 2^25 window (textual key outside it) instead of nine string concatenations per vertex.
- Test fidelity: the trace pipeline cancel test uses the original work budget 7 (was migrated as 1, which paid one timer turn per unit).
Result: painted ellipse/geometry-reuse tests dropped from 6-10 s to roughly 3.5-4.5 s CPU and pass at the 5 s default; authored-curves passes at its original 120 s budget. Under heavy fleet load (load average >15 on 10 cores) the two heaviest tests sit within ~10% of 5 s and can flake; 3/3 consecutive runs passed at load ~17.
