# Bounded Float Field Normalization

The existing child converter uses Rust f64 string grammar, including leading signs and zeroes, infinities, NaN and invalid-input defaults. JSON-only field receiving changes that grammar. The earlier whole-owned-word parse draft is not accepted as bounded merely because fuel was precharged.

A new lexical cursor will scan at most 64 original bytes per event, retain the first 768 significant decimal digits, the decimal fraction count, discarded digit count, signed exponent and sticky nonzero tail. For coefficient prefix D and adjusted exponent k, a nonzero discarded tail lies strictly inside (D,D+1)*10^k. Every adjacent binary64 rounding midpoint has a decimal numerator n*5^d with n <= 2^54-1 and d <= 1075, hence at most 768 significant decimal digits. Therefore a midpoint cannot lie strictly inside this prefix bucket. Replacing a nonzero tail with an appended 5 and decreasing k by one selects an interior value with the same rounded binary64 result. Exact prefixes retain nearest-even ties. This is a proof obligation for native midpoint, boundary and random-word tests, not a test verdict.

Rust itself uses a 768-digit decimal sequence plus a truncated-nonzero indicator: [official Rust decimal sequence source](https://doc.rust-lang.org/nightly/src/core/num/imp/dec2flt/decimal_seq.rs.html). Root independently verified the decimal length of ((2^54)-1)*5^1075 as 768 through the registered Node BigInt tool.

The explicit exponent may saturate only at original input byte length plus 4096, which dominates every possible mantissa/fraction offset. Final scientific exponents below -324 or above 308 produce definitive signed zero or infinity. The remaining normalized word is at most 776 bytes, so the standard scalar conversion has a fixed input bound. Special words preserve their sign and exact Rust acceptance through a separate at-most-nine-byte source. Invalid syntax remains a declared scalar default. Original pointer/length and operation/generation binding, zero-item refusal, cancellation at every phase, and actual deadline behavior remain required.

## Neutral Reference Result

The registered `repo tools exec --light node` run of the retained ticket input `inputs/float-bucket-proof.mjs` genuinely exited 0. V8 Number produced identical binary64 bits for original and normalized words in 10,128 exact BigInt midpoint-family/basic cases. The longest original word was 12,776 bytes; every normalized word stayed within 776 bytes. Families include exact ties, positive and negative tails, leading zeroes, signs, subnormal/normal/overflow boundaries and 2,000 deterministic random midpoint choices. This validates the mathematical normalization through an independent V8 engine. It does not execute the Rust NumberWork cursor and is not a native custody, cancellation, grammar or deadline verdict.
