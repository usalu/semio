## Hang (coordinator report, port-j-18)
- Cause (production): cold retirement loops (`retire_value_cold`, `Dictionary::from_value` input loop) re-issued a grant that funded nothing. After the port the cursor needs `copy >= next_demand(copy).copy_bytes` and a depth/capacity quoted for the same body width; the old per-currency quotes (`next_copy_byte_demand`, ...) under-quoted, so a step returned `Progress(default)` forever (no panic: steps were ignored).
- Fixes: `ValueRetirement::exact_grant(page)` builds the grant from the single selected `next_demand` (copy raised to the quote and re-quoted, depth = max of selected and frontier depth); per-currency quotes derive from `next_demand`; a cold step that moves nothing (`moving`) and a zero-progress `Dictionary::from_value` step now return a typed `WorkLimit` instead of looping; `RetainedDictionaryInput` quotes now include the page-reservation copy/depth and the shared-allocation header copy.
- Real faults found by the laws: (1) replication `HistoryFoldIndex`/`FoldIndexNode` kept the old `sequence_birth_bytes` scaffold override, so every cursor birth over a HistoryFoldIndex was refused "original cursor birth differs from its defining layout"; override removed (claimed in claims, replication `🗂️index/🦀️.rs`). (2) ordered `UpdateCursor::next_copy_byte_demand` omits the shared-allocation header copy that `advance` now requires; compensated in `RetainedDictionaryInput` (capacity + 2 words), owner should fix the quote in ordered.
- Test accounting: the old laws asserted `copied == 0` / `copied == expected` (copy bytes counted only boxed payload); header moves are now legitimate copy bytes. Replaced by `copied >= expected` for the schema/operator law and dropped for the dictionary law; released == born stays exact.
- Test runs are bounded: the built test binary is run one test at a time with a `kill -9` after 40 s (script in scratchpad); no run goes through `repo cargo test` without `--no-run` any more.
- Budgeted evaluation tests (`⏱️evaluation/🧪️tests/🦀️.rs:22,26,27`, wave tests 18/21) still have 1M-turn loops without idle guards (1107-audit-hang.md); they do not compile yet, so they cannot hang; add idle guards when they are ported.
