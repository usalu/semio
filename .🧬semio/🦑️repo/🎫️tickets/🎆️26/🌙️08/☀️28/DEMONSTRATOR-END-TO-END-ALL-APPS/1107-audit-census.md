## Method

- Reader: the gate's own `readRustSourceClosureV1` is imported from `🧰️framework/🔨️modules/🏃️process/📦️artifacts/🏗️native-build/📥️source/🟦️.ts`, not copied. It walks `mod` declarations with `#[path]`, `include!`, `include_str!`, `include_bytes!`, manifest-relative inputs (owner = manifest directory), and selects active lines with the gate's cfg rules. Generated token output is observed as in the gate (no-op owner observer).
- Count (same as admission): files = closure inputs; bytes = sum of input bytes including embedded `include_*` files; active lines = sum of the reader's `activeLines` (blank and comment lines count). The gate has no per-file limit: the read-time check is the remaining-budget `maximumBytes = max - used` plus the remaining file count, so the census also replays read order and reports the running total at the first crossing (the number the gate prints).
- Limits: global `storage.sourceBoundary` = 262,144 B / 32 files / 4,000 active lines (from `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/⚡️caching/🔣️policy.json`), per field `min`'d with the crate's `[package.metadata.semio.rust-source-boundary]`.
- Units: each crate's targets as cargo discovers them: lib (`[lib].path` or `src/lib.rs`), bin, test, example, bench, build script; explicit `[[bin]]`/`[[test]]`/... paths honored, `autoX = false` honored. A crate is refused if any unit is refused, so the crate value is the maximum over units.
- cfg: `rustc --print cfg` (rustc only, no cargo) for host and `wasm32-wasip2`, each with `opt-level=0` (debug_assertions) and `opt-level=3`, plus `--test` for test/bench units and `--crate-type=proc-macro` for proc-macro libs. Features: `default` (resolved from the crate's `[features]`, optional deps included) and `all` (every feature and optional dep). Worst case over all of these is the headline; the default-only column is shown separately.
- Population: `git ls-files -c -o --exclude-standard -- '*Cargo.toml'` (5,206 manifests), minus `.🧬semio/` (678 ticket and hub overlay copies, not repo members), leaving 4,528 manifests, of which 4,379 are crates with `[package]` and were measured. One manifest vanished during the run (`🧰️framework/🔨️modules/🌱️value/🛬️decode/🧳️owned/🔐️shared-slots`, the crate removed by the value lane).
- Raw data: `C/🗑️generated/1105b/aud-census-out.json` (per crate: limits, worst values, default and all feature maxima, first-crossing running total), `C/🗑️generated/1105b/aud-census-all.tsv` (all 4,379 rows with owner). Scripts: `C/1105b-tools/census/census.ts`, `C/1105b-tools/census/report.py`.

## Limits of this census

- Peers edit the tree during a run. Per-crate values drift by up to about 3 to 4 % between runs (job-context: 268,242 B, then 261,669 B, then 264,906 B worst). Treat NEAR entries as "close", not as stable verdicts; rerun the census before a decision.
- `all` features is a ceiling (a cfg-off branch can grow when a feature is off), not a build. The default column is the closer model of a plain build; the real gate uses the unit's resolved features, which the census approximates (no cross-workspace feature unification).
- The lane column is a path heuristic (`🔌️plugin` and `🧵️job` to runtime, `🌀️procedural` to proc, `🔋️energy` to energy, `🏗️fem` to statik, `🌊️flow` to flow, `🖥️host` to hostcheck, `🏪️store` and `🌱️value` to value, everything else `value (unowned)` per the lanes file). Verify before assigning.
- 5 reader errors are not measured: `semio-framework-job-native-decode` (`🛬️decode/🦀️.rs` line 36 has an unbalanced `})())}`), `semio-s-artifact-norm-en1991-inferences` (`🧷️wave3-rows/🦀️.rs`: unclosed delimiters at lines 26, 98, 113), `semio-plugin-original-job-ownership` (missing `original_action` module), and `semio-framework-value` and `semio-framework-value-persistent` (test units: missing `include` input `📐️.json`). These are syntax or missing-file failures in the working tree, so the compiler would reject them too.
