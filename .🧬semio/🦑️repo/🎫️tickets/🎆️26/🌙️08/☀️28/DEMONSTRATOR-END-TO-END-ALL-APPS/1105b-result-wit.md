# 1105b wit lane

## Design (decided here)
Every turn input crosses as ONE wire through `reactor.admit-actor-input(wire, budget)` into a single guest slot; `poll`, `start-job`, `restore` and all `codec` exports then take only an `actor-context-budget` and consume the slot (operation-tagged; a mismatched or empty slot is a typed refusal). Encoding = the repo's container-less pack value (`store::pack_rt::encode_wire_value`, TS twin `encodePackValue`), integers always `TAG_UINT`. Declared schema-first in `plugin/🧬️schema/🎟️actor-input/`: `🧬️schema/🔣️.json` (decoded form), `🧫️fixtures/🔣️.json` (valid/invalid cases + exact `packHex` per case), `🦀️.rs` (`ActorInputWire`, `encode/decode`, native test pinning the same bytes), `🧪️tests/🟦️.ts` (Ajv third-party oracle + first-party validator, operations in sync with the Rust enum). Poll events are the jco-lowered WIT `event` (`{tag,val}`, camelCase) so `wit_event_to_kernel` stays the single semantic mapping. `reactor.wit` poll doc fixed (no more `list<event>`).

1. Actor-failure exports (`publish/read/acknowledge-actor-failure`) are typed `unsupported-owner` refusals: no guest-side failure custody exists anywhere yet (runtime lane).
2. Host admits the input wire inside `execute_turn`/codec/job crossings with the same issued input (guest `admit_input_wit` charges bytes against the retained policy but does not chain epochs); making input admission its own kernel crossing with receipts (`OriginalActorInputAdmissionReply`, `GuestRuntime::admit_actor_input`, shard `admit_*_original`) is the runtime lane's accounting refinement.
3. `wit_bridge::poll` (WIT events) remains for the reactor test hosts only; production uses `event_from_wire`.
4. `OriginalJobStartReply.returned_source` is now reconstructed host-side on refusal.
