### Assignment 3 update (derive route, flow side): BLOCKED on a design mismatch, no code changed
`OriginalRecordMemberSnapshotOpen<S>` parses the pack into a `RecordValue` in the **DSL grammar** (`BorrowedDslRecord::RECORD`), and `S: NativeReceive<RecordValue>` must read exactly that grammar. For flow that grammar is the twin's (`FlowHostSnapshotDsl`, `🚪️io/📝️text/📸️snapshot/🧾️host`): `widgets: Vec<WidgetDsl>` where `params`/`preview` are `Option<BTreeMap<String, ValueDsl>>`, `expanded: Vec<String>`, Cluster `tree`/`flow` are an untyped JSON escape hatch, layout is a `BTreeMap`. The persisted types derive `ToValue/FromValue` for the canonical-JSON shape instead (`Widget` tag="kind", `Dictionary` = untagged object/atom, `OrderedSet`, `Tree` with `Option<Box<Tree>>`). `#[derive(NativeReceive)]` on `FlowHostSnapshot`/`Widget` would read the JSON shape, not the DSL record the opener hands it, so a derive-only fix reads the wrong grammar (and the neural `Dictionary`/`Value`/`Atom` are untagged, which the derive does not support; `Box<Tree>` has no `NativeReceive`).
Choices (need a coordinator decision): (a) make the persisted flow model DSL-native: replace `Widget`/`Dictionary`-based fields by the `WidgetDsl`-shaped owner types (params as an ordered `String -> value` map, expanded as `Vec<String>`, a typed cluster tree) and derive `DslRecord`/`NativeReceive` on `FlowHostSnapshot` itself, retiring the twin and `component_dsl` (touches flow eval, neural tree conversion, fixtures, text format); (b) a shared decode-via receiver (rejected); (c) leave flow as an unsupported-member opener until (a) lands.
