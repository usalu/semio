## 1. Design (as built, schema-first)
- Schema `💾️storage/🧬️schema/📥️install.json`: new `$defs.SingletonProtocol` (`singletonOwner: "."`, `singletonPackages: [@types/react, @types/react-dom, react, react-dom]`, binding `owner-generation-node-modules-link`, versions `identical`), plus `SingletonObservation` / `SingletonAlias` / `SingletonCase` for the planner contract. `SourceOwnerReady` (= `bindings.json`) is now version 4 with a required `singletons` array (`{name, owner, ownerGeneration}`; empty for the owner scope, exactly the four policy names bound to the owner generation for every other scope); `SourceOwnerReadyProtocol.version` 2 -> 3.
- Planner: every non-owner scope gets the owner scope as a Source-owner edge (`readJavascriptDependencySourceOwnersV1`), so the owner is installed first, is in every dependent's selection closure and `ownerReferences`, and a change of the owner generation changes every dependent generation (no stale link can be ready).
- Producer: new `publishJavascriptDependencySingletonsDescriptorV1` runs right after the borrowed-provider normalization, inside the produced output and BEFORE strict execution and ready publication, so the custody fingerprints are computed over the final tree (no post-install symlink swap). For each non-owner scope root and member slot it replaces the physical `node_modules/<name>` directory by a link to the owner generation's copy via the same descriptor kernel `publishBinding` the borrowed providers use. Pure planner `planJavascriptDependencySingletonAliasesV1` refuses divergent versions, an absent owner copy, undeclared names, duplicates and an owner linking to itself. A link left by an adopted donor generation that points at an older owner generation is replaced.
- Ready codec: `readJavascriptDependencySourceOwnerReadyV1` / `javascriptDependencySourceOwnerReadyReceiptV1` (v4) enforce the exact `singletons` rows against `ownerReferences`.

- Generation identity: `SourceOwnerProtocol.generationTag` bumped to `javascript-source-owner-generation-v2`. Without it every scope that already depended on `.` kept its old generation directory, whose `bindings.json` is v3 and unreadable by the v4 codec (first sync failed with "Exact selected dependency fields required"); with it all generations are new and the old ones are obsolete (the sync reported `obsolete-generations` and retired them).
