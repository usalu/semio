# Drawing Mounted Contract Frontier

Read-only source review found current Drawing editor methods still using earlier trait shapes. The actual ArtifactEditor declaration requires mounted_job_prepare_snapshot_read(operation, snapshot, windows, view, grant) -> MountedSnapshotReadPreparation, while DrawingPlayApp still defines the two-argument bool method at its play-app source. The same editor's pending_effects still accepts ArtifactView, while the actual declaration requires ArtifactPendingView. Its geometry_session::reconcile likewise accepts ArtifactView and optional render identity; the genuine pending view supplies total render identity and the admitted snapshot read.

This is a static type incompatibility finding, not a compiler verdict. No Draw source was changed. Repair must migrate the actual geometry preparation and original-source reconcile contracts together, rather than wrap an unfunded bool scan or build a synthetic ArtifactView. The existing prepare_source initializes the registry and scans the 256-shell pool with a nested 64-instance membership check. Any funded replacement must preserve exact current-candidate cancellation, last completed visual, original snapshot-read custody and registry retirement while quoting/advancing the actual bounded metadata work. Existing Draw and mounted geometry laws must remain attached to their rightful owner.

Relevant sources: the Drawing editor play-app/🦀️.rs and editor/🧵️geometry/🦀️.rs, compared with plugin/declaration/surface/artifact-editor-trait and declaration/view/artifact-view. This remains a demonstrator build frontier after the current lower and SDK passes; neither that frontier nor full browser panes is proven.
