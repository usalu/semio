## Wave 0 result — the demonstrator could not boot at all

`bun nx run @semio-tech/mit-bestand-demonstrator:dev` failed before Vite ever started:
`semio-framework-plugin` did not compile for the plugin target, so **every** plugin build failed.

### Root cause

Commit `f7b265d581` (2026-08-28 09:20) landed a capability-key close lifecycle
(`NativeCloseKey`), added actor lifecycle/UI-patch receipts, and moved `PendingPatchAuthority`
into `⚛️reactor/📨️pending/🦀️component.rs` — but left `wit_bridge::poll`/`poll_kernel` in
`🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/⚛️reactor/🦀️component.rs` on the old API.
20 compile errors, all in that one file.

It went unnoticed because `mod wit_bridge` is gated:

```rust
#[cfg(all(any(feature = "component-guest", feature = "component-extension-guest"), target_arch = "wasm32", target_env = "p2"))]
mod wit_bridge { … }
```

A native `cargo check` never compiles it, so the workspace looked green while every real plugin
build was broken. The breakage sat committed for ~14 hours; the reactor tree was clean against
HEAD and untouched since, so this was not another session's in-flight edit.

**Reproduce / verify:**

```
cargo check -p semio-framework-plugin --target wasm32-wasip2 --features component-guest
```

### Fix

Completed the migration in `⚛️reactor/🦀️component.rs` (241 insertions, 45 deletions, confined to
that file — the only production caller of these APIs):

- Added the missing per-instance lifetime glue: a fixed-capacity `INSTANCE_LIFETIMES` registry
  (`instance_id -> ActorInstanceLifetime`, sized by `PLUGIN_REACTOR_INSTANCE_SLOTS`) with a serial
  to mint `guest_lifetime`, plus `native_close_key()` — the first production route to a
  `NativeCloseKey` (looks up the lifetime, captures a lease via `plugin_capture_instance_close`,
  calls `NativeCloseKey::capture`). Nothing constructed one before; only test fixtures did.
- Added `IN_FLIGHT_CLOSES`, a fixed-capacity registry of `(request, close_generation, key)` that
  survives across turns — a close needs several polls to reach terminal, so completion cannot be
  driven from a turn-local list.
- Close pre-loop: pre-scans `&events` into `close_requests`/`close_instances` (restoring the six
  `close_instances.contains(&cursor.instance)` command-ingress guards), then per request captures a
  lease, `begin_close`, mints the key, and does reserve → activate on all three authorities
  (reactor, `PATCHES`, pending) before `plugin_destroy_app`. Close work stays **before** the event
  loop, as it was. `abort_reactor_close` is gone; `reserve_reactor_close` is idempotent for the same
  key, so a `plugin_destroy_app` error just propagates.
- Close completion: releases the three authorities once all report complete, clears the registries,
  and emits `lifecycle_receipt: Some(ActorInstanceLifecycleReceipt::Retired { .. })`.
- Mechanical migrations: `Event::InstanceClose(_)`; `Event::InstanceOpen { request, .. }` with
  `request.instance_id` (already `u32` — the old `instance.0.parse::<u32>().unwrap_or(0)` is gone);
  `Event::PatchAck { .., .. }` with the 4-arg `apply_published_ack`; `reserve_mounted(surface, key)`;
  `ready_patch_key()` + `take_ready_patch_into()` replacing the retired
  `take_ready_patch`/`return_ready_patch` pair; `take_one(SURFACE_RECONCILE_PAGE_BYTES)` with its
  `Result` handled; `TurnResult` gaining `lifecycle_receipt`/`ui_patch_receipt`.

Verified: `wasm32-wasip2 --features component-guest` → **0 errors**; also clean with
`--features component-extension-guest` and on the native target.

## Why the demonstrator would not boot — environment, not code

Four boot attempts died silently: only the startup banner and `plugin registry catalog refreshed` in
the log, no exception, no `wasm build failed`. Two independent causes, both environmental:

1. **A 20-minute hard budget per cargo invocation.**
   `BUILD_BUDGET_MS = 1_200_000` (`🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/📦️packages/🟦️typescript/📦️index.ts:1230`),
   applied to every `cargo` spawn via `defaultBudgetMs`. Under contention a single engine-wasm build
   exceeds it, gets SIGTERM'd (`runCmdInternal` prints `[budget] … exceeded … killed`), the build
   script throws, and the dev server never starts. Overridable with `SEMIO_BUILD_BUDGET_MS`.
   An earlier `cad` plugin build died exactly this way:
   `cargo rustc -p semio-s-plugin-cad … killed by signal SIGTERM`.

2. **Machine-level memory exhaustion.** During these runs:
   `vm.swapusage: total = 45056.00M used = 44187.62M free = 868.38M` — under 1 GB of swap left, with
   the system thrashing. Concurrent load included two peer `cargo` runs holding the shared build lock
   for 60-75 minutes at a stretch, two peer `📜️script.ts clean taxonomy plan` jobs, **nine** orphaned
   `📜️script.ts dev mcp stdio` repo-MCP servers left behind by earlier session restarts, plus this
   session's own agent cargo checks. Processes were being OOM-killed, which is why the dev server
   vanished without ever logging an error.

## ROOT CAUSE of the silent dev-server deaths — `wasm-pack` crashes on the warning flood

Captured by running the dev target with full output redirected to a file (the preview tooling discards
a server's log when the process exits, which is why five attempts produced only a banner):

```
wasm-pack had a problem and crashed.
[puzzle/board] wasm build failed
error: ./✏️s/🔌️plugins/🧩️puzzle/📦️packages/🦀️rust wasm build failed
```

`report-*.toml`:

```toml
name = "wasm-pack"
crate_version = "0.15.0"
cause = "failed printing to stderr: Resource temporarily unavailable (os error 35)"
  12: std::io::stdio::_eprint
  13: wasm_pack::build::cargo_build_wasm
```

**Mechanism:** `wasm-pack` relays cargo's output to a **non-blocking** stderr pipe. The peer session's
in-flight mutations refactor makes `stdio` and `puzzle` emit an enormous volume of warnings (thousands
of `unnecessary qualification` diagnostics). The pipe buffer fills, the write returns `EAGAIN`
(`os error 35`), and Rust's `_eprint` panics — so `wasm-pack` dies, the engine build fails, and the dev
server goes with it. The panic message itself is lost because it is written to the stream that just
failed, which is exactly why every attempt looked like a silent death.

**This was neither the build budget nor OOM.** Both earlier hypotheses were wrong:
- the `[budget]` line never appeared in the captured log;
- swap pressure was real but incidental — the crash is deterministic given enough warning output.

**Mitigation:** `RUSTFLAGS=-Awarnings` + `CARGO_TERM_QUIET=true` on the launch config, which collapses
the warning volume that overflows the pipe. Recorded in `.claude/launch.json` under
`mit-bestand-demonstrator-fast`; no repo behaviour changed.

**Proper fix for the repo (not done here):** the engine build should not depend on a non-blocking pipe
surviving unbounded diagnostics. Either drain wasm-pack's stderr to a file, pass `--quiet`, or set
`-Awarnings` for engine builds inside `buildEngineWasm` itself. Worth its own ticket, since any crate
in the closure that starts emitting warnings can kill every playground dev server this way.

## Correction — `generated_migrated` IS the rejection cause

An earlier entry in this file claimed `generated_migrated` was a diagnostic field outside the

## Static trace of the `setLocale` rejection — three hypotheses raised and discarded

1. **`TypeId` collision between two monomorphizations of `EditorApp<Puzzle3dPlayApp>`.** Withdrawn —

### Why `wasm-release` is inherently this slow
`[profile.wasm-release]` is `lto = "thin"`, `codegen-units = 1`, `incremental = false`. codegen-units=1
means no intra-crate parallelism, so a plugin crate is one long single-threaded tail — 3 h for stdio is
normal here, not a hang. RSS was observed cycling 0.3 → 4.0 GB across codegen units.

### Why serial-per-plugin cannot work
`pluginCargoArgs` emits `cargo rustc -p <pkg> … -- -C link-arg=-zstack-size=8388608`. `cargo rustc`
accepts exactly ONE package, and `SEMIO_PLUGIN_ONLY` is an exact single-id match
(`entries.filter(e => e.pluginId === only)`), so it cannot be given a list. With every plugin sharing the
one `target/` lock, 8 plugins × ~3 h serial is not viable.
