## 04:10 runtime-originated typed commands (coordinator task 2)
Status: host events IMPLEMENTED on the original typed source (compile-checked natively; runtime proof at producer level, see TESTS). `resume_task_command` still refuses (reactor protocol, below). Bare `dispatch_typed` removed and replaced by the resumable `drive_typed`.

### Design
A command the runtime itself originates is the same shape as an app-produced one: a typed `Box<A::Command>` plus its sealed OpBinary `RetainedToolWireInput`, donated together to `OriginalTypedCommandSource<A>`; no new wire shape (the wire is `OpBinary::encode_op`, as the retired `admit_command_wire` fed it; `ArtifactOriginalToolCommand::from_admitted_op_binary` binds exactly that).
- `plugin/🎮️command/🎟️typed/🏃️runtime/🦀️.rs` (owner of the typed source): private `RuntimeProducer<C: OpBinary>` implementing `ArtifactOriginalCommandProducer<C>`: phase 0 encodes the command (funded `capacity <= RUNTIME_COMMAND_WIRE_MAXIMUM` = 64 KiB), 1 births the exact `RetainedToolWireInput`, 2 copies one 4 KiB `ToolWirePage` per turn, 3 seals, 4 retires the encoding through the shared `RetainedCloneClose`; `take_into` hands command+wire over together; `close_step` returns every owner by paid retirement. `OriginalTypedCommandSource::produce_runtime(make, cx)` adopts it into the source's own `producer` slot (caller loan first, `close_producer` after handoff), so the source's existing `close_step`/ladders already own the custody; no new holder, no Drop-assert surface.
- `instance/📨️dispatch/📥️staging/🏃️runtime-command`: `DispatchCtx::drive_runtime_typed_command(source, make, tag, metadata, identity, cx)`: `admit` -> `produce_runtime` -> `admit_wire(declared catalog, A::command_id)` -> `require_complete_tool_operation_pipeline` -> the existing `dispatch_typed_command_inner` (receipt/`None` = another turn).
- `instance/📨️dispatch/📥️staging/📣️host-events`: delivery is a queue, not an inline call. `HostEvents` (history crate) gained `queue: VecDeque<HostEvent>`, `delivering`, `reply`. `queue_host_event` ends the gesture immediately (unchanged) and queues the fact when `A::host_event` answers it; `queue_utility_host_events`, `queue_host_event_to_every_window`, `queue_base_moved` (renamed from `deliver_*`, now sync; callers in time-travel preview, reprojection, archive-merge, plugin-app-impl updated). `host_event_turn(source, action, args, meta, ..)` queues the utility switches of the view and the `hostEvent` action's own fact, then drives the queue front through `drive_runtime_typed_command` using the composer's idle `original_typed_command` source; the view for the window is resolved at delivery time from the delivering action's metadata (so a `BaseMoved` queued without a view is delivered at the next action instead of being dropped, as the retired code did). Delivered operations are inserted into `host_event_operations` (never history rows). Cancellation closes the source and clears the queue.
- `command-routes/🚦️actions`: `drive_host_events` (builds a `DispatchCtx` beside the idle source) is called at the top of `dispatch_action_received` while `host_events.delivering` (before the branches that would hijack the half-finished source) and at the old `deliver_utility_host_events` position; the `hostEvent` action replies (`HostEventTurn::Reply`) after its fact was delivered.
- `instance-app` ctx-builders: `dispatch_typed` replaced by `drive_typed(source, command, meta, identity, cx)` (one funded turn; laws loop it over fixture turns). Net size change in `plugin-app-impl`: smaller.
