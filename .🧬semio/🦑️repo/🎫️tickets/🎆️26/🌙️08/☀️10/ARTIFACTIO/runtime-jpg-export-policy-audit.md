# JPG Export Policy Audit

Historical native 134/134 GREEN establishes the exercised implementation laws, not the intended semantic authority separation. Current schema explicitly describes `re_encode_quality` as the IJG Annex-K quantization scale for the native encoder, defaulting to 90. `ChangeReEncodeQuality` merely contributes the corresponding snapshot diff. It changes no decoded pixel or logical document metadata. This is export policy and must leave the semantic snapshot/diff/mutation roster; the native encoder must retain its quality capability through an explicit IO-owned options record.

The audit also found the physical encoder explicitly canonicalizes fresh DQT/DHT tables instead of the schema's retained decoded `quant_tables`/`huffman_tables`, and retains `restart_interval` without emitting DRI. These typed decoded observations are not currently authoritative native output content. SOF sampling is currently read from `frame` and must remain available to the physical encoder so baseline grayscale, 4:4:4, 4:2:2, 4:2:0, and legal asymmetric sampling support is preserved. Removing a semantic policy must not reduce those native profiles.

`other_segments` is described as uninterpreted APPn/COM payloads, and pure insert/remove/diff code operates on owned marker/body records without parsing byte layouts. The physical marker walker owns native segment interpretation. Further validation must ensure that known structural SOF/DQT/DHT/DRI markers cannot enter this opaque metadata carrier and that known APP0 JFIF information stays in its decoded semantic fields.

The concrete boundary decision is to keep decoded pixels and logical JFIF density/thumbnail/metadata in semantic ownership, with encoder quality and native layout/profile settings in IO. No compatibility field, deprecation, cached serialized result, or parser facade will be introduced. Exact contract/fixture fanout and the actual native runtime results will be recorded when implementation completes, after the lifecycle RED/fix sequence required by the parent.

Opaque metadata admission detail: the native marker walker sends only unknown APP0, APP1–APP15, and COM to `other_segments`; JFIF APP0 is parsed into owned fields under physical IO. The semantic carrier's `marker: u8` currently admits every byte, while its physical exporter writes the marker/body verbatim. That permits a directly constructed semantic record to inject structural markers through an opaque metadata field. The replacement needs a typed application/comment metadata kind with exact native binding; known JFIF APP0 admission stays physical, and pure leaves must continue treating opaque bodies as uninterpreted owned bytes. Native profile/header bytes must not become a side channel into semantic content.

## Canonical Physical Export Contract

`JpgEncodeOptions` is authored under IO binary snapshot encode-options with explicit quality and SOF component sampling. Gray, 4:4:4, 4:2:2, 4:2:0 and valid asymmetric sampling remain expressible. Quality is absent from semantic authority in the intended contract; encoder calls will receive this separate owned policy. The first implementation stage changes the physical API and preserves profiles explicitly; snapshot/diff/mutation/fixture retirement follows immediately. Native observation records remain under audit rather than being declared closed.

## Typed native observations / pure fact input design

The final native decode boundary returns decoded logical content separately from SOF/DQT/DHT/DRI observations. Baseline rules consume immutable first-party JpgBaselineFacts (frame presence/process predicate, precision, arithmetic conditioning, table counts, sampling facts); no native table bytes or encoder policy is persisted in semantic snapshots or editable through semantic mutation payloads. Native reports own exact original table/marker identity, preserving format diagnostics and all supported native sampling profiles. The new schema-first facts contract and Rust/TS carriers are authored; old baseline snapshot adapter will be removed with final caller fanout, so no completed migration or runtime result is claimed here.
