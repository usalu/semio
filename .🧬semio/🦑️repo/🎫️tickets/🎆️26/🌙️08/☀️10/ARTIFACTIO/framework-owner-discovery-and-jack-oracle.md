# Framework Owner Discovery And Jack Source Oracle

The physical-codecs source suite now invokes the existing Jack `testResumableQueryOracle` directly, with a verified relative import and a 60-second per-test timeout. This runs independent SQLite/JSON1 graph effects and UTF-8/JSON-escaping ownership laws through the repository source runner without artifact Cargo preparation. The Rust owned-result accounting source has no direct, dynamic, or aliased text/binary IO imports.

A language-neutral framework discovery corpus and regression test were added before changing discovery. The corpus covers a direct document product, a nested product, an existing artifact collection, unpaired schema/IO trees and ignored fixture/test trees. Ajv validates the contract and picomatch independently verifies exclusion classification. The source regression calls the architecture scanner with default root discovery, so paired products must be discovered by structure rather than a product name.

It completed with 18 passing tests and one failing test (232 assertions, 40.63 seconds test time). The new regression failed because default discovery missed both paired direct/nested product owners while recognizing the existing artifact collection. The Jack SQLite/JSON1 oracle passed with its actual `[DEBUG]` log; Program, Layout and the physical codec laws also passed.

After RED, generic discovery was changed to admit any framework directory with direct schema/snapshot and IO siblings, while retaining artifact collections and test/fixture/package exclusions. A set deduplicates owner roots. Traversal skips the paired schema/IO interiors after admitting that owner and continues through unrelated children to discover nested products. No product name is hardcoded.
