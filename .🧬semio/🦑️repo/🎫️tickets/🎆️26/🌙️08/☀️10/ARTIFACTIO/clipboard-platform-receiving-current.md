# Clipboard Platform Receiving

Primary sources inspected on 2026-10-10. No platform runtime acceptance is claimed.

Windows [GetClipboardData](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboarddata) returns system-controlled storage whose handle must remain valid through immediate copy and must not remain locked or be freed by the recipient. [GlobalSize](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-globalsize) allows extent validation before a caller-owned birth. A first-party bounded UTF16→UTF8 reader can hold the clipboard open, inspect the original extent, and copy only into caller-admitted storage; implicit format conversion is itself an OS effect and must be distinguished from owned recipient heap.

Apple [NSPasteboard](https://developer.apple.com/documentation/appkit/nspasteboard) and [NSString.getBytes(maxLength,...)](https://developer.apple.com/documentation/foundation/nsstring/getbytes(_:maxlength:usedlength:encoding:options:range:remaining:)) are the relevant system interfaces. The documentation pages require JavaScript and their Markdown endpoint failed in this browser pass. A bounded caller-storage copy is plausible, but original system object custody and get-string materialization require further verification; no pre-birth guarantee is inferred from this page alone.

[Xlib XGetWindowProperty](https://xorg.freedesktop.org/archive/current/doc/libX11/libX11/libX11.html) accepts a requested length and returns remaining bytes separately. It still returns allocated native library storage, so both that temporary owner and its closure must be funded before issuing the bounded request. Selection conversion and INCR need event/cancellation state rather than a blocking event wait; Wayland needs a separate receive descriptor interface. Neither path is currently implemented.

[W3C Clipboard API](https://www.w3.org/TR/clipboard-apis/) readText has no maximum-length argument and produces a complete DOMString after a system-data copy. It cannot establish a bounded owned recipient by inspecting the resulting string length. The receiving contract must keep the existing browser object as an external original source and copy bounded slices under the caller grant, or receive host-delivered paste data through a finite broker interface. Browser source-memory bounds are an unresolved external frontier, and are not silently counted as zero.

Required first-party interface: stable original source generation; bounded extent inspection; copy into an already-admitted caller buffer; progress/cancellation; independent source handle retirement; exact original invocation/recipient receipt conservation. Every refused turn retains the original source and receiver. SDK cold String/Vec materialization and post-birth rejection are excluded.

The installed Apple system SDK headers were independently inspected on the resumed turn at `/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/System/Library/Frameworks/AppKit.framework/Headers/NSPasteboard.h` and `Foundation.framework/Headers/NSString.h`. NSPasteboard exposes changeCount for a source generation witness. Its data/string methods combine representations from all applicable items; readObjectsForClasses creates receiver objects. No caller-storage or requested-content-length parameter appears on these acquisition methods. Thus get-string then measure cannot be represented as bounded prebirth acquisition.

For an already-held original NSString, the system header confirms UTF16 code-unit length and bounded getCharacters(range) into caller storage, plus getBytes with a byte limit, explicit input range and returned remaining range. These are usable bounded receiving primitives once the original immutable foreign source and its lifetime are supplied. They do not establish a bound on NSPasteboard acquisition itself. The macOS first-party implementation must distinguish that acquisition owner from the admitted bounded receiver and preserve both actual source generation and cancellation; treating the combined NSString birth as zero remains unacceptable. This read-only header verification is not platform runtime evidence.
