## Task 1 — Glue-mounting policy resolution (READ THIS FIRST — every F1-F6 agent's brief needs it)

**Resolved: the triad-dir policy is NOT enforced.** Investigated `📜️script.ts`'s `POLICY_MUTATION_TRIAD_DIRS` machinery directly:

- `policyMutationTriadCompletenessBreaches` only checks triad-KIND completeness (`🦠️mutation`/`🔺️diff`/`↩️inverse`) for mutation directories that **already exist** as subdirectories under an artifact's `🧬️mutations/`. It never requires a directory to exist per mutation *variant* — a variant living entirely inline in the top-level `🧬️mutations/🦀️component.rs` is invisible to this check.
- `policyMutationDispatchCoverageBreaches` (the function that would compare dispatch-enum variants against triad dirs) is a literal `return []` placeholder, explicitly commented "Wave 3 pilot will flesh this out" — it has never been implemented.
- Verified empirically (not from memory) on gif 89a and svg 1.1: `find … -type d -iname "*mutation*"` shows **only `📄set-snapshot`** has a triad subdirectory in either artifact. `GifMutation`'s `InsertFrame`/`RemoveFrame`/`SetFrameDelay`/`SetLoopCount`/`SetFrameDisposal` variants (and their `diff()`/`inverse()` bodies) all live directly inside the top-level `🧬️schema/🧬️mutations/🦀️component.rs` file. Same shape confirmed for svg.
- Even where `policyMutationTriadCompletenessBreaches` *would* fire (a `🧬️mutations/` facet with zero subdirectories at all), the breach priority is `"medium"`, and the actual policy-check entrypoint (`bun ./📜️script.ts policy`, see the `bun/policy`-vs-`verify` note below) only fails the run on `priority: "high"` breaches (`runPolicyExit` filters `breachs.filter(b => b.priority === "high")`). Moot here anyway since every stdio artifact already has ≥1 mutation dir (`set-snapshot`).

**The load-bearing invariant for F1-F6 fan-out agents**: *you can do all your real work — new mutation variants, new diff fields, new snapshot fields, everything — by editing files that already exist and are already mounted in glue.rs, with ZERO new files/directories and ZERO glue.rs edits.* Concretely, per artifact-standard, these three files are already `#[path]`-mounted and compile today:
- `🧬️schema/🧬️mutations/🦀️component.rs` (add new `enum XMutation` variants + `diff()`/`inverse()` arms directly here)
- `🧬️schema/🔺️diff/🦀️component.rs` (add new sparse diff fields + `MutationDiff`/`DiffAlgebra` impls directly here)
- `🧬️schema/📸️snapshot/🦀️component.rs` (add new snapshot fields directly here)

A per-variant triad dir (mirroring `📄set-snapshot`) is **optional scaffolding for consistency, never required for correctness**. If an F-wave agent wants one, creating it requires a **new directory**, which structurally requires a new `#[path]` mount in glue.rs — that is the one thing fan-out agents cannot do themselves. Per the plan's own design, such a request must be queued in the agent's report's `glue_followup` field for this wave's closer to apply.

Documented as a doc-comment at the top of glue.rs's `//#region Artifacts` (`✏️s/🔌️plugins/🗄️stdio/📦️packages/🦀️rust/📦️glue.rs`), citing this report.

**Bonus finding while reading `📜️script.ts`, relevant to every future wave touching `//#region 🔧️PolicyRule*`**: a prior agent's own comment (`POLICY_FLAGSHIP_MUTATION_ALLOWLIST`'s doc-comment) already records a real incident — `bun ./📜️script.ts verify` and `bun ./📜️script.ts policy` are two DIFFERENT commands. `verify` runs `runGate()` (dependency-cruiser + a handful of specific `nx` targets + a curated subset of breach groups — `policyOsStateAuthorityBreaches`, `policyHandcraftedSpecP3Breaches`, `policyArtifactSchemaBreaches`, `policyAppSchemaBreaches`, dissolve-core rules — then `nx run-many -t test --all`) and does **not** call the big `policy` export that aggregates every `//#region 🔧️PolicyRule*` function (including all of S2's new rules and S-7's ban). `bun ./📜️script.ts policy` is the command that actually runs them, via `dispatchPolicyArgv`/`runPolicyExit`, and only fails on `priority: "high"` breaches. I independently re-confirmed this by tracing `VerifyScript.runGate()` and `dispatchPolicyArgv` myself before finding the prior agent's warning — both readings agree. **Verification for this wave's Task 3/4 rules used `bun ./📜️script.ts policy`, not `verify`** — see the Verification section below for why, and what `verify` does today regardless (unrelated pre-existing failures).

## Task 4 — S-8: four new drift/honesty/coverage rules

All four added to `📜️script.ts` in a new `//#region 🔧️PolicyRuleSchemaOverhaulS2` (placed after `PolicyRuleSniffReality`, before `PolicyExport`), following the house conventions read from `policySniffRealityBreaches`/`POLICY_DIFF_COMPLETENESS_ALLOWLIST`/`policyMutationVocabularyBreaches` (breach objects with `id`/`summary`/`kind`/`scope`/`priority`/`reason`/`solution`; shrink-only allowlist + paired "stale" low-priority breach when an allowlisted entry is already fixed; keys built with the existing `policyNormalizeRelPath` short-form, e.g. `stdio/gif/standards#89a-subsets-any-schema-diff-component`, same as `POLICY_FLAGSHIP_MUTATION_ALLOWLIST` already uses).

Every seed was generated by actually running the exact detection logic against the real tree (generator script kept at `s2-artifacts/gen_s8_seeds.ts` in this ticket folder — copies, not imports, the relevant `policyNormalizeRelPath`/`policyStripRustCommentsAndStrings` internals so the hardcoded keys match byte-for-byte), never hand-guessed. New entries dynamically enumerate stdio standard/subset dirs via the pre-existing `policyListArtifactDialectDirs` helper (filtered to stdio) rather than a hardcoded "31" — a future new standard or subset is picked up automatically.

1. **`POLICY_FACET_MIRROR_DRIFT`** (`policyFacetMirrorDriftBreaches`): for each of the 31 stdio standards' 3 facets (snapshot/diff/mutations), extracts camelCased field names from the Rust leaf's `pub name: Type` declarations (comment/string-stripped, textual heuristic — not a parser) and checks each appears as a substring in the sibling `.ts`/`.graphql`/`.json`/`.proto` leaves. **Seeded with 93 entries** (31 standards × 3 facets = 93 checked pairs; the pdf 1.7 `✳️a-2b` conformance subset has no schema facets of its own, correctly excluded, not miscounted as a 32nd standard). **Every single checked pair drifts today** — confirms the plan's own finding that no facet mirror has been rewritten yet (gif's TS mirror is still literally zip's).
2. **`POLICY_GRAMMAR_HONESTY`** (`policyGrammarHonestyBreaches`): flags a grammar/protocol leaf (`.g4`/`.ebnf`/`.grammar.semio`/`.ksy`/`.spicy`/`.abnf`/`.protocol.semio`) whose content is still the literal scaffolded placeholder (`payload = *OCTET`, `size-eos: true`, `payload: bytes &eod;`, or the fixed `DOCUMENT: 'schema' [ ]+`/`header = 'schema', space,` templates — confirmed these exact strings by reading real files across 3 different standards before writing the check). **Scoped to stdio only** (this ticket's scope; the repo-wide `.grammar` completeness program is a separate, already-existing rule — `POLICY_GRAMMAR_FILE_ALLOWLIST`, jolly-spindle W1 — for a different file convention). **Seeded with 645 of 651** stdio grammar leaves (99.1%) — the 6 exceptions are json's `.grammar.semio`/`.protocol.semio` leaves (all 3 facets), which got real (if not yet artifact-specific) content from an earlier wave and correctly fall outside the literal-marker seed.
3. **`POLICY_DIFF_ALGEBRA`** (`policyDiffAlgebraBreaches`): flags a stdio standard's `🔺️diff/🦀️component.rs` lacking a real `impl DiffAlgebra<...> for` block, reusing the existing comment/string-aware `policyRustFileHasRealTraitImpl` helper (already used for `ArtifactBuilder`/`ArtifactDecomposer` etc.). **Seeded with all 31** (re-confirmed zero `impl.*DiffAlgebra` anywhere in stdio, matching S1's "zero implementors" claim for the trait it just added).
4. **Field-sweep-test presence** (`policyFieldSweepPresenceBreaches`): flags a stdio standard whose own directory tree has no test function matching `field_sweep` (regex `fn\s+\w*field_sweep\w*\s*\(`, matching the plan's exact law-6 name from `🧬️schema-design.md`'s Test laws section — grepped the plan file to confirm this literal name before writing the check). **Seeded with all 31** (confirmed zero `field_sweep` matches anywhere in stdio today).

All four allowlists' checks were **round-trip verified**, not just seeded and trusted: for each rule, one real seed entry was temporarily deleted, the rule was re-run via a standalone probe script (`bun run` importing `policySchemaOverhaulS2Breaches` directly), confirmed it produced exactly one new breach of the expected `kind`, then the entry was restored and re-confirmed zero breaches. This caught nothing wrong (all four passed cleanly) but is real evidence the checks aren't vacuously true.

**Wiring**: `policySchemaOverhaulS2Breaches` (aggregates all 5: the S-7 ban + 4 S-8 rules) is called from the main policy aggregator (`export const policy = defineLint(...)`, alongside the existing `policyMutationArtifactEngineBreaches(repoRoot)` call — same pattern S-7/S-8's sibling rules already use).
