# BRep End-User Edit Audit — 2026-10-03

Read-only source audit; no builds, tests, browser probes, or runtime confirmation. Only this report was written. Deconstruction and measurement changes described by the executor remain pending native validation.

## Current Evidence

Paths below are relative to the generation3d v1 any subset unless fully qualified.

- `✏️editor/🎯️selection/🦀️.rs`: component IDs are `widget@channel#index.mode.ordinal`; accepted modes are vertex/edge/face, not wire. `mesh_component_vertices` interprets face as indexed polygon position, edge as a polygon halfedge enumeration, and vertex as indexed mesh position. These are mesh ordinals, not persistent BRep labels. `component_pivot` averages unique selected mesh vertices, with f32 rounding; it is not analytic center of mass.
- The same file validates cached edits only against live `$schema: mesh` output, rejects list index other than zero, probes pending evaluation, and follows only pending `brep.mesh.*Components` operators to topology-preserving input. A cached BRep tessellation is not admitted as an indexed mesh edit source.
- `✏️editor/🎮️commands/🧭️transforms/🦀️.rs:507` admits only a noncollection port declaring `mesh`; BRep component transforms explicitly require conversion. Existing gestures already provide streamed preview, relative transform leaves, commit/abort, consumer splice rows, and one tool transaction. Preserve that machinery.
- `✏️editor/🎮️commands/🥽️edit-mesh-selection/🦀️.rs:87` similarly admits only `mesh`; it inserts `brep.mesh.*`, reconnects consumers, writes absolute input leaves, and clears component selection. This is a useful transaction pattern, not an analytic BRep component edit implementation.
- `🧵️preview-eval/🦀️.rs:340` recognizes face, edge, vertex, wire, shell, compound, curve and surface handles. Channel/list walking already exposes geometry leaves with stable channel-qualified instance IDs. Recognizing a handle does not prove its tessellator paints finite geometry.
- Preview reads the retained `FlowEvalSession.preview_mesh_pack(handle)` and existing geometry port. Pending/current display may use a converged or superseded packed handle (`:658` onwards). Such fallback keeps the viewport responsive but must never authorize mutation against a new live output.
- `🧬️schema/🔣️.json` and `🚪️io/🟦️.ts` already preserve optional face/edge/vertex `componentReferences` string arrays. Framework flow mesh-pack encode/decode retains these references and validates them. The inspected selection/edit paths do not consume those references. Exact decimal strings must remain strings; JavaScript numeric conversion would lose large labels.
- `✏️s/🔌️plugins/🌊️flow/🧩️extensions/📐️brep/🦀️.rs` exposes deconstruction, `brep.solid.filletEdges`, `brep.solid.chamferEdges`, `brep.solid.shell`, `brep.topology.label`, `brep.measure.centerOfMass`, `brep.measure.closestPoint`, curve closest parameter and surface closest UV. Selective operations take geometry-handle lists, not renderer ordinals.

## Minimum Implementation Order

1. Add schema-first analytic selection projection to the existing selection file. Resolve renderer hits through the painted pack's componentReferences into exact labels, scoped by source widget/channel/list leaf and geometry kind. Keep mesh ordinal selection semantics separate. Read live evaluated output from the existing session; require the painted geometry handle to match the live leaf before an edit. During pending evaluation, permit highlights but disable analytic edit admission. Do not introduce a selector evaluator or another cache.
2. Add neutral mapping fixtures for triangle-to-face, edge-segment-to-edge and tessellation-point-to-vertex reference lookup. Multiple triangles/segments may map to one analytic label; deduplicate labels. Synthetic point crosses and vector arrows must not masquerade as topology vertices. Missing references mean object-only selection.
3. Implement graph editing through existing mutation rows and transaction emission. Connect the selected source to deconstruction; find selected labels in its current edge/face outputs; use existing `list.get` for each current index and `list.pack` for the selected handle list. Connect source geometry and packed edges to filletEdges/chamferEdges, or packed faces to shell.openFaces. Reconnect consumers only to the modified whole shape, preserve upstream selection source for regeneration, and expose operation parameters through the existing inspector. One admission emits all splice/input rows as one transaction; undo/redo replays those rows.
4. First support selected-edge fillet/chamfer and selected-face shell openings. Do not route analytic selections into mesh extrude/bevel/delete or mesh component transforms. Existing whole-shape transform nodes can transform an extracted face/edge/vertex/wire, but that produces transformed standalone geometry; replacing a component inside its owning solid requires an explicit existing analytic reconstruction operator. No such support is established by these inspected commands.
5. Regeneration-stable edits require current label-to-index resolution before graph input changes. Literal list indices alone are only stable within the evaluated output that supplied them. The current paths do not establish persistent label preservation across topology-changing inference. If a label disappears or becomes ambiguous, reject explicitly and require reselection; never silently retarget by ordinal. Reuse graph mutations to update list.get indices after validated inference rather than adding independent evaluation authority.
6. Project analysis through existing inference nodes and graph results. Analytic bounds, closest point and center of mass must use current handles and their documented kernel semantics; preview position bounds and mesh-vertex averages are presentation data. Bounds operator availability/behavior was not established in this focused audit. Center-of-mass and closest-point registrations establish callable surfaces, not correctness for every shape kind.

## Preview and Selection Blockers

Face preview needs triangle face IDs/reference mapping, including holes and trimmed surfaces. Edge and wire preview need bounded-domain sampling into edgePositions, independent of face triangles. Vertex preview needs its actual point and persistent vertex reference, independent of marker geometry. Infinite underlying curve/surface previews need a declared finite domain or explicit diagnostic. Current handle recognition and four preview roles alone do not establish these behaviors. Wire is absent from selection grammar and componentReferences; support it as an extracted geometry object first, and add a wire contract only if actual component selection is required.

Persisted references and cached packs are not authoritative geometry: check live output identity, pending state and current label membership on edit admission and commit. On shape-changing operation completion, clear stale analytic selection or remap only labels whose identity is established. A topology-preserving mesh-transform fallback does not justify following arbitrary BRep operations.
