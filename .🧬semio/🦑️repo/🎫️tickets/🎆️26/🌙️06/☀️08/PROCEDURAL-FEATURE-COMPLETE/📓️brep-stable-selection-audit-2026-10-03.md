# Stable Analytic Component Selection — 2026-10-03

Read-only source audit. No tests, builds or runtime probes were run. This report is the only authored artifact.

## Primary Recommendation

Capture the exact decimal component label and painted source identity at the moment of the hit in the existing interaction target. Do not retain only the numeric renderer group and resolve it later against whichever pack is then live. The renderer hit already contains the mapped group: lookup is directly `componentReferences[domain][group]`, never a second lookup through EdgeIds/FaceIds.

Keep transient hit freshness separate from a persisted parametric component reference. An interaction requires the same live source/evaluation before admitting edits; a persisted graph reference follows its source endpoint and resolves exact current membership on each inference. Numeric list indices and opaque handles alone cannot safely express the latter. Existing Body labels preserve entities, but the inspected OpDelta does not describe successor correspondence across newly generated topology.

## Minimal Changes by Owner

1. Schema/interaction projection: extend the existing component target contract with painted source handle, exact label and an existing evaluation/authoring freshness witness. Treat renderer numeric group as highlight addressing only. Encode this unambiguously and update parsing, grouping, projections and both renderer hit producers together. No new selection state or label registry. A source endpoint/list leaf/domain belongs in the reference; labels are not globally meaningful across independent Bodies.
2. Selection owner: directly resolve the painted group table, refuse missing/out-of-bounds labels, deduplicate by scoped label. Probe current evaluation; refuse pending/missing output, changed source witness, changed handle, wrong kind and label absent or ambiguous in the current source topology. Do not remap the old group to a new table. Labels remain strings above 2^53. Unsupported vertex identity remains object selection until a real vertex position/reference contract exists.
3. Edit command owner: add analytic routing for selected-edge fillet/chamfer and selected-face shell. Reuse source/deconstruct/List/Get/Pack and the same transaction emission. Splice only the whole-shape operation output into previous consumers; extraction/selection branches must remain upstream and must not acquire a cycle through their newly inserted operation. Analytic source list leaves need existing List extraction first. Keep mesh destructive edits and mesh component transforms on explicit mesh sources.
4. Persisted graph resolution: literal Get indices must never be treated as permanent identity. Extend existing deconstruct/List Get inference owners schema-first to support exact reference matching against a current label list (deconstruct can emit parallel decimal labels from its same kernel call). Get resolves exactly one current matching label with wrap=false and fails on zero/multiple matches. This uses the same List owner and inference cache, without another evaluator/module/cache. Alternatively existing deconstruct can accept selected-label inputs and emit selected geometry through its existing owner; choose one contract, not competing authorities.
5. Existing naming/provenance owner: retain same-label modified entities and reject deleted labels. For an upstream recomputation that creates different labels, safely refuse until the existing operation provenance carries an explicit, unique correspondence. A generated label list alone is not that correspondence. Do not use nearest geometry, same ordinal, same vertex count or an arbitrary generated successor as replacement identity. If regeneration stability is required across reconstruction, implement correspondence within existing Body/operation inference records and transport it through the current geometry outputs; do not add a registry.
6. Existing command admission/commit: repeat freshness validation before transaction publication if inference or gesture work yielded. Expose pending/refusal via existing progress/fault surfaces; cancellation emits no persisted graph edit. Successful graph changes clear obsolete transient interaction targets. Analysis uses the same resolved current handles and existing measurement widgets.

## Neutral TDD Laws and Existing Oracle

Author language-neutral fixture cases before production changes, drive native and portable owners, then run registered bun/nx targets. These are proposed laws, not passing results.

- Group already mapped: primitive ID buffer [0,0,1] with hit group 1 resolves reference 1, even when primitive position 1 would yield group 0.
- Exact label text above 2^53; duplicate primitives deduplicate labels; out-of-range/missing tables and malformed targets refuse.
- Same endpoint/group with a different painted handle or evaluation witness refuses. Pending painted fallback and a live handle with changed same-label geometry refuse stale interaction.
- Reordered deconstruct outputs resolve the original exact label to its new ordinal; missing/deleted/ambiguous label fails; unrelated Body/entity with matching numeric label cannot satisfy source membership.
- Persisted selection follows same-label modified provenance; deleted+generated without explicit correspondence fails; one-to-many correspondence fails until reselection policy is explicit.
- Single transaction contains extraction/selection/operation/splice rows; consumers point at resulting whole shape; selection branches point upstream; undo/redo and cancellation preserve one action.
