## Actual Mutation And Inference Routes

Generation3d inference currently consists only of graph topology. `🧬️schema/💡️inferences/🦀️.rs:21–46` declares `Generation3dInference.topology`, reads `hostSnapshot`, and computes it with `compute_generation3d_topology`. `🧭topology/🦀️.rs` performs Kahn traversal and returns counts/order/depth/cycle status. It contains no geometry inference.

`set-widget-input` command at `✏️editor/🎮️commands/🎚️set-widget-input/🦀️.rs:48–68` resolves an unconnected declared scalar port, validates number/text/boolean/point/vector values, and emits one absolute `change-widget-input` mutation. Connected inputs and collection values are explicitly rejected. This route respects event history and does not alter geometry in a UI-only store.

`EditMeshSelection` at `🎮️commands/🥽️edit-mesh-selection/🦀️.rs:31–104` supports extrude/inset/subdivide/flip/deleteFaces/moveVertices/loopCut. It validates component granularity, rejects collection index other than zero, creates a `brep.mesh.<operation>` neuron with default parameters, splices it between the selected mesh output and consumers, commits graph differences as mutations, then appends absolute `change-widget-input` leaves. Component selection is cleared and graph selection moves to the inserted operation. Its ordinary `handle` calls with empty IDs; the actual interaction-aware editor routing at `✏️editor/🦀️.rs:875` and `:2355` supplies selected component IDs. Testing only the ordinary handler cannot prove real component dispatch.

Geometry execution currently lives outside the inference family. `✏️s/🔌️plugins/🌊️flow/🧩️extensions/📐️brep/🥽️mesh/🦀️.rs:239` implements `MeshOperation` and evaluates meshes; its retained `MeshOperatorJob` delegates to framework `MeshModelingJob`. Framework mesh assembly `🧰️framework/🔨️modules/🧊️3d/🥽️mesh/🦀️.rs:11–13` mounts a separate `🛠️modeling/` module. Thus if the user means literally all geometry execution must be named mutation/inference leaves, current implementation is structurally outside that requirement even though document persistence correctly uses mutations. Do not claim geometry already uses `Generation3dInference`: it does not.

A clean literal integration would name geometry/topology/measurement outputs as schema-first inference leaves, declare their input dependencies, and let existing flow extension workers execute those inference providers while retaining budgeted work in the established actor/session system. Mutation leaves persist operator inputs and graph wiring; they must not persist disposable evaluated handles. Existing pure kernel implementation can be colocated beneath its appropriate inference leaf rather than introducing a new editing store or a parallel command/module subsystem. Clarify internally whether “no separate modules” means forbidding the newly introduced modeling folder or forbidding independent mutable modeling state; these have different implications, and current code satisfies only the latter.

## Remaining Verified Source Limits

- Component edit commands intentionally require a single mesh output at index zero. Collections require extraction before editing; all-source/list editing is not currently implemented.
- The named mesh edit command covers seven operations; bevel/decimate/weld/mirror etc. may be available as catalogue operators but are not supported by this command yet. Do not infer viewport gesture parity from operator registration.
- Inspector literals cover only scalar number/text/boolean and point/vector coordinates; collections and schema-rich values need compatible connected sources. This is an explicit UI capability limit, not an unvalidated parse failure.
- The inference family only advertises DAG topology, so geometry, measured properties, validity, and selection mapping cannot currently be queried through that family.
- Source inspection establishes routes and limitations. None of the suggested acceptance tests have been executed in this audit.

## Exact Consumer And Inference Integration APIs

TypeScript scene definitions and generic lane reassembly are in `🧰️framework/🔨️modules/🖱️ui/🎬️scene/🟦️.ts` (`sceneFromLanes`:575, `NodeGraphScene`:824). React Interpreter `🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗣️Interpreter/🟦️.tsx:475` exposes `surfaceKindSceneLanes`; its `SURFACE_KIND_SCENE_LANES` has no node-graph entry. `PagedSurfaceView`:2510 invokes the generic `sceneFromLanes` using this table. Add the NodeGraph lane declaration to this table; the generic subscription/reassembly already exists. Existing `🚚️surface-scene-lanes/🟦️.tsx` tests currently explicitly treat nonpaged kinds as undefined and need updating for node-graph. Native fixture readers using SceneDoc merge automatically gain NodeGraph support after its override; direct typed scene decoders must also reassemble carriers where applicable.

The established inference APIs already support a bounded entry boundary; do not create a second geometry evaluator:

- Plugin `ArtifactInferrer` at `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs:1452` provides sync `infer` and async `infer_cached(snapshot, InferenceCache, InferenceSession)` with required observational equality.
- `InferredField<P>` in OS `🔨️modules/💡️inference/🦀️.rs:83` exposes stable field/schema ID, coarse `reads`, topological `plan`, canonical `dep_input`, and pure `compute`. Dependency input must include port parameters, source text, incoming connection identity and operator/version policy; hashing handles alone is insufficient for portable geometry derivation.
- Plugin `ArtifactInferenceServiceMetadata`:1472 carries artifact/inference/schema/algorithm/policy identities. `ArtifactInferencePayloadContract` carries input/output schema and progress unit. `ArtifactInferenceExecutionRequest`:1558 already supplies budgets, cancellation ID, previous resumable state, canonical payload and dependency payloads. `ArtifactInferenceExecution`:1569 supplies canonical output, diagnostics, validity/quality, completion/cache mode. `ArtifactInferenceService::new`:1600 registers the noncapturing bounded execution function. This is the clean existing interface for a named geometry inference whose internal execution reuses existing operator algorithms.

`FlowEvalSession` and `PreviewEvalRun` are currently evaluation orchestration, not protocol `Generation3dInference`: the latter has only topology and no geometry field. A transient session/tool run is still necessary for progress/cancellation and does not itself violate event sourcing. The violation under a literal mutation/inference-only requirement is that geometry computation/output is owned by flow operator/module APIs rather than registered named inference providers. Wrapping already computed geometry in an inference after the fact would leave that architecture unchanged. The worker must invoke the registered inference service as the computation owner, while commands emit mutation leaves and scene renderers consume inference publications. Reuse one execution graph and kernel; avoid a duplicate evaluator, mutated geometry shadow document, or second geometry cache.
