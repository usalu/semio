## Clean long-term solutions for development speed
These are ordered by impact, and extend the list in `📊️status-11-27-09-00.md` with what this stretch showed.

1. **One shared, content-addressed unit store per configuration.** Lanes become thin overlays, so N agents cost about 1× plus deltas instead of N×. Today a second agent doubles disk and RAM, which is why builds stay serialized.
2. **Capacity as one model, not a set of local rules.** Six separate bugs this session came from parts of the system disagreeing about capacity:
   - spill was unbounded;
   - lanes were sized flat;
   - commitment counted declared bytes instead of used bytes;
   - the partition was judged against a single image;
   - the CAS reserve didn't scale with the volume;
   - the lane peak was lost on retirement.

   A single schema-defined capacity model would fix this as a class. It would cover volume, machine budget, each store's share, sparse used-vs-declared, reserve and eviction order. One oracle and vector suite would cover it, and every writer (cargo, linker temp, spill, CAS) would ask it before writing.
3. **Never evict what the active build needs.** Eviction must be driven by recency and holds across all stores, never by a wrong pressure signal. A "units compiled vs reused" metric should alarm when it is above about 20% on a rerun. That would have caught the 1000-units-per-run eviction on the first rerun instead of after about 40.
4. **Fewer, larger test binaries.** Each bim test target links the whole model, which is 400–800 MB per binary across about 250 binaries. Consolidating to one integration-test binary per domain package cuts link time, disk and warden pressure by roughly an order of magnitude.
5. **Test selection instead of `test --workspace`.** `repo affected` should map edits to test binaries, so agents run what they touched. The full run belongs to the archivist or CI.
6. **Atomic multi-file peer edits.** Stage edits in an overlay and swap them in once `check` passes, so the replica never carries a half-edit. Half-edits cost about one rerun each, about five times this session.
7. **Typed infra refusals and a `repo doctor` digest.** ENOSPC by store, warden kill, broker stall and jobserver EFAULT should each be a typed refusal naming the owning module, with the fix. Agents go straight to the owner instead of mining 25 MB logs.
8. **Fleet by default for heavy builds,** with local as the fallback once the fleet workspace stage is stable. A 16 GB laptop is the wrong place to link 250 test binaries.
9. **Ticket-scoped tooling hygiene.** Only `ticket_close` deletes `🗑️generated/`, and one build lease per ticket. That would have prevented the mid-run log loss.
10. **Fast-fail capacity pre-flight.** Before a long build, estimate disk, RAM and per-unit peaks from recorded evidence (`lane.peaks`, `.peak` files) and refuse early with a plan, instead of failing after 30–90 minutes.
