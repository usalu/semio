## Clean long-term solutions for development speed
Ordered by impact on agent throughput.

1. **One shared build output per configuration, not per lane.**
   - **Problem:** narrow lanes (`crateKey` per crate set) re-build the whole dependency tree, so a second agent doubles disk and RAM.
   - **Fix:** lanes should share one content-addressed unit store, which the `sealed` shard almost is, with per-lane overlays only for the units that diverge. That turns N parallel agents from N×cost into roughly 1×cost plus deltas.
2. **Elastic, budgeted cache storage instead of fixed-size sparse images.**
   - Every shard has its own fixed capacity, so one fills up (`u/w` now, `ped16c6` before) while the host still has 47 GB free.
   - **Fix:** a single machine budget (already 60 % of the volume) governs all stores. Each store gets LRU eviction against its live share and grows on demand. Every writer, including spill, incremental and linker temporaries, goes through the budget.
3. **Lean test artifacts by schema.** Test profiles use line-table debuginfo and unpacked split-debuginfo, with no full debug info for dependencies. A 600 MB test binary should be 50–100 MB, which cuts link time, disk and warden pressure all at once.
4. **Crate-size governance in CI, not in failure.** The warden's per-unit ceiling (1536 MB) should be a lint, `repo check crate-budget`, using the recorded `.peak` files. It should flag crates heading toward the ceiling, and generic decode instantiations in test crates, before a 2-hour build dies on them. The carving script (`carve-bim.py`) generalizes into a `repo carve` operation.
5. **Fail-soft admission everywhere.** Broker, warden and admission must never fail a compile for slowness, only for real over-budget conditions; the `broker.md` fix is one instance of this. Any infra stall should degrade to a conservative forecast plus a progress message.
6. **Atomic peer edits.** Half-landed edits in shared framework crates, such as `[DEBUG]` traces and missing re-exports, cost about one rerun each. Agents should stage edits in a ticket-local overlay and land them as one atomic multi-file swap once `check` passes for the touched crates. That way the replica never carries a broken intermediate state.
7. **Incremental test selection.** `repo affected` should map changed files to test binaries, so agents run only the affected bim tests instead of `test --workspace`. The full run belongs to the archivist or CI.
8. **A working fleet as the default for heavy builds.** Linking 250 test binaries on one 16 GB laptop is the wrong place to do it. Once the fleet's workspace stage is stable, `repo cargo test` should offload by default, with local as the fallback.
9. **Agent hygiene rules, enforced by tooling.** Ticket `🗑️generated/` is deleted only by `ticket_close`. One build per ticket at a time, serialized by a ticket lease. Logs always go through `repo`'s own log channel, so a deleted folder can't make a run blind.
10. **Persistent infra evidence.** Each infra failure class (ENOSPC shard, warden kill, broker stall) should produce a typed, schema-defined refusal with its owner module, and be aggregated by `repo doctor`. Agents then jump straight to the owning module instead of rediscovering it from 25 MB logs.
