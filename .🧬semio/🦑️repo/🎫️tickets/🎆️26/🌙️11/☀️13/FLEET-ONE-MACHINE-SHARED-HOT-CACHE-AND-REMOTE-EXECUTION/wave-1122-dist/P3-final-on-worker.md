## What a build needs so that finals go remote and ordinary units stay local-first
Read from the code (not from a run, because the final was not reached):
1. The gate `offloadGateV1` (`L/🚀️offload/🚦️admission/🟦️.ts:162-175`) has no rule for linked wasm finals. Modes: `never`, `distribute`, `pin:<origin>`. In `distribute`, ANY unit that finds a free local compile slot compiles locally (`local-slot`), so a final goes remote only when every local slot is busy; with `pin` EVERY unit goes to that worker, including all ~1,000 dependencies (what I measured). There is no "pin only linked finals". To get the target behaviour a small code change is needed in the gate: `distribute` plus a rule `linked wasm cdylib (offloadPeakMegabytesV1(types,target)>0) -> offload:true, queue:true, reason:"final"` before the `localSlot` test, and its schema/enum entry. Not landed (`lock.component-jobs` is O14's, and the final path was not exercised, so I could not prove the rule correct).
2. `SEMIO_OFFLOAD=distribute` (play currently runs `SEMIO_OFFLOAD=never`), `SEMIO_UNIT_CACHE_SLOTS>0`, `SEMIO_UNIT_CACHE_LIGHT_SLOTS>0` (remote concurrency, O13) and cargo `CARGO_BUILD_JOBS = local + light slots` (O13 `cargoJobsV1`). The driver's component pass sets these only with O13's `component-pass.patch` + `jobserver.patch` + `wasm-build.patch` (driver restart).
3. Admission of the final on a worker needs O11 (family peak estimate 7,938 MB; a 16 GB worker's spare is 3 to 6 GB: without O12 (single charge) the scheduler's double count makes `idle?peak=4096` return 0 slots; live probe 23:30: `idle@0` 40 slots, `idle@2048` 2, `idle@4096` 0). So today no 16 GB Mac admits a hub final at the estimated peak: the final stays local. O12's scheduler change must be live (scheduler restart) AND the workers must have free memory (the Windows m05 shows 22.5 GB free but is another platform).
4. A working fleet content store (CAS3 507 relief live on the cache sidecar) and a worker with disk (m06 refused for disk).
5. Fleet-cache hits for the dependencies, which are zero here (finding above); otherwise the dependency closure is compiled once per local-first build.
