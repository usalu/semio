## Findings
1. No manifest in the coordinator tree spells that path. Checked three ways: every `path =` of all 4,677 tracked Cargo manifests (own dir and every ancestor base) and the four workspace tables used by the din4108 closure (0 of 320 workspace paths dangle); a transitive walk of the din4108-rs closure in the working tree and at HEAD (542 to 544 crates, 0 missing); and the real `nativeDependencyRoots` of this wave's code for all 4,677 roots with dev-dependencies at the root (4,677 ok, 0 errors, 5:52 at load 49).
2. The coordinator infers the owner fine: the owner harness (`W6/owner-one.mjs`, copy of the E42 `profile-owner.mjs` aimed at this checkout) infers `@semio-tech/norm-din4108-rs` in 98.9 s wall, 18.6 s CPU, 6 targets, no error. So the current code (W5 directory stamps, GR5 generated directories included) does not produce the error on this tree. W5/GR5 are not the cause: the projection, `settledReads`, `memoizedFileRecord` and the directory memo all verify by size/mtime/ctime/inode and none can invent a path that no manifest spells.
3. The trees differ. The sync attestations (`origins/g1-*/attest.json`) show the 11 workers agree with each other (448,932 files, manifest `f986bd7f`) and this coordinator (`g1-server`) does not (448,843 files, manifest `a4fb633c`, 26 modified/26 deleted against 45/24 on the workers). The server's replication latency is the outlier: publish p50 394 s, p95 397 s; apply p95 278 s (workers: publish p50 5 s, apply p50 0.5 s). The workers therefore hold about 89 files, and the edits of peers on other machines, that this tree does not have yet. The only candidate for the dangling spelling is therefore a peer's in-flight edit that has reached the workers and not the coordinator (a path in a crate that was moved or renamed, the same kind of edit as the 💾️binary to 📝️text family move in this tree). It cannot be read from here: neither the worker trees nor the worker service logs (`/var/folders/.../host-659f709f2f10.log`) are on this machine. Earlier in the night m01 logged "Another process edited ...din4108/📦️packages/🦀️rust/Cargo.toml while it was read" (00:39), so that crate family is under active edit.
4. Why "kept changing": the verdict is `unsettled` when consumed rows moved (hold fails) or the youngest row is within the racy window of the attempt start. On a replica that applies peer edits continuously, a closure of 544 crates always contains such rows, so a genuine missing manifest is classified as churn instead of "stable". That classification is intended (a half-applied edit looks exactly like this), but the cause text was useless: it named only the missing directory, never the declaring manifest.
