## 1. What the path hash was for (and what it did)
- `D🪪️mutation-leaf-attrs-and-schema-index/🦀️.rs:68` (`mutation_authority_workspace_token`) hashed `sha256("…/v1", canonical ABSOLUTE workspace path, workspace-relative authority locator)`. It is emitted as `MutationSourceProvenance.workspace_token` of every leaf and `MutationLeafSourceScope.workspace_token` of every aggregate (`🧰️framework/🔨️modules/📡️replication/🎮️mutation/🔎️leaf-source-scope/🦀️.rs:130`, a `const` check: "leaf token must equal the aggregate's token"). Purpose: one crate's leaves and its aggregate must have expanded against the same authority; nothing locates files by it at runtime.
- Consequence: the identity was the checkout location, so (a) the same sources built at another root or in a worker sandbox were another artifact; (b) the unit cache could not see it (a hash, not `env!(CARGO_MANIFEST_DIR)`), so a unit built at root A was shared by the fleet key with A's token while a unit built at root B (aggregate or a leaf of the same crate family) carried B's: mixed fleet/local units of one family fail that const check, and any worker output differed from the local bytes. 113 units per 45-minute play build (`incomplete-inputs` fallbacks, 7,466 s, O20 §1) hit the worker E0463 sentinel; all 113 were then compiled locally.
- Now: `sha256("semio.mutation-source-provenance/v2", locator, sha256(authority projection bytes))` (same file, `:68`). The authority content is the identity the check really needs; an edited authority is another token, a moved checkout is the same. Name `workspace_token` kept (renaming ripples through the contract crate and ~10 files; open item).

## 2. Reads, includes, sentinel
- Every read of the expansion already goes through `compiler_resources::read` (tracked path -> dep-info -> K7 manifest). The two workspace markers (`package.json`, `📋️project.json`) are deliberately NOT tracked (documented design: editing them must not recompile every derive user); I tried tracking them and reverted. They are shipped by the planner instead, content not a key input.
- `include_str!` paths of the expansion are now relative to the directory of the source file (`D🪪️…/🦀️.rs:118,121`, `D🔁️mutations-expansion/🦀️.rs:114`, new `include_path_v1` in `🧰️framework/🔨️modules/🏃️process/📦️artifacts/🏗️native-build/📥️resources/🧮️compiler/🦀️.rs`, unit-tested in two roots), so the token stream of an expansion contains no machine path at all. (Aggregate `source_path` made unconditional, `D🔖️mutation-source-authority/🦀️.rs:52,130`.)
- Sentinel removed (`D🔖️…/🦀️.rs:319`): a refusal is a plain compile error; a worker that lacks an input fails and the requester compiles again (`UC/📜️script.ts:242`, K7), never hands the error on. The `E0463` class in `🩺️failure` stays for real missing crates.
- Source budget: the expand crate is capped at 262,144 bytes (`maxSourceBytes`); the edit nets +319 bytes against 322 spare, so the helper lives in the compiler-resources crate. No room left in that crate for more derive code.

## 3. Planner (`OF🗺️paths/🟦️.ts`)
- Blanket decline removed. `workspaceDeriveFilesV1` finds the files that apply the derive; `deriveWorkspaceRootV1` replays the derive's own workspace lookup (nearest `package.json` with `workspaces` + `📋️project.json`, exact-ancestor delegation); that root joins `shipped`, so a unit whose cargo working directory is an artifact directory BELOW the workspace root (all plugin crates: `✏️s/…/🧊️3d`) ships the layout from the root down (`non-anchored` virtual root, the existing machinery) and the derive finds the same workspace-relative world in the sandbox. `deriveMarkersV1` ships the marker files on the way. Reads recorded by an earlier compile (dep-info or K7 manifest) outside the package now travel too (they used to travel only when a dep-info of this machine existed).
- Precise declines left: no workspace above the source (`not-portable`), and "no compile of this unit has recorded what the derive read" (`not-portable`, the first compile on a fleet that never built the unit; it compiles once locally, records, afterwards offloads). A unit whose text names the derive but whose earlier compile never read the authority (the derive crate's own sources quote it) plans as a plain unit.
- Removed the `--extern semio_os_kernel_dsl_derive` decline (O20 showed it never fired; its reason is gone) and its test.
- Not changed: a worker whose sandbox root lies behind a symlink (`/var -> /private/var`) would be refused by the derive's no-symlink rule; sandboxes of the live workers are not.
