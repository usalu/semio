## Design as built (replaces U1's per-machine gap records; `UC/🔏️key/🕳️gaps/` deleted)
1. **Manifest** = the files (portable text, roots as tokens) and environment names the compiler read beyond the source scan, names only. Address `sha256("semio.cargo.unit-cache.input-manifest/v1" NUL slotId)` (`manifestIdV1`, `UC/🛰️fleet/📋️manifest/🟦️.ts`): slot = compiler release, target, profile, package, crate, kinds, features (K4's slot identity; command-line flags beyond the profile are not in it, so variants of one slot share a manifest, which can only make it a superset: sound). Fleet entry = one blob `{version, retention, files, env}` named twice by the action result (`stage.json` carries the declaration the server reads, `inputs.json` marks the class) and the same JSON inline as stdout: a lookup is ONE GET. Local copy `<root>/fl/manifests/<xx>/<id>` (+ 30 s negative stamp `.none`).
2. **Lookup** (`UC/📜️script.ts` ~:129-133): local copy, else one GET to the fleet (kept locally), hash exactly the listed files and keyed names plus the scan's inputs (`unitSourcesV1(..., recorded, extraNames)`) into the key. Miss under a local copy: the fleet manifest is read again once before compiling (`refreshManifest`, :203) and the union is looked up (a machine with an old manifest hits instead of compiling).
3. **After the compile** (`completeInputsV1`, :210): dep-info vs what the key covered; if the observed set is not covered, manifest := union, key recomputed from the complete set (`rekey`, :199), claim moved, the unit is published locally and to the fleet under that key; manifest written and shared BEFORE the unit upload is queued. The old, incomplete key is never published. Only a missing dep-info or more than 512 files/64 names leaves a unit unshared (`key-incomplete` still counts those).
4. **Correctness rule** (stated in `manifestUnionV1`/tests): two units with equal keys had equal content for every input the compiler actually read: the key covers scan rows + every manifest file digest + env values; an input the manifest lacked is detected after the compile and the unit is keyed on the superset, so it is never served under a key that does not cover it. A shrunk set only costs extra misses.
5. **Server** (protected metadata class like R4's `graph`): declaration kind `input-manifest` (`B/🪢️slots`, `protectedKindV1`), shares the graph class's protected budget in the store (`B/🌐️remote-cache/💾️store/🟦️.ts` 5 sites), staleness judge keeps it while its one source (the crate entry file) exists in the tree whatever its digest says, retires it when the file is gone, never retires one without a source (registry crates), toolchain rule unchanged; provenance class `input-manifest` is superseding (newest write replaces, never a divergence). Python oracle and a fixture scenario cover the judge.
6. U1's R1/R2 point: the unit entry's declaration is built from the dep-info rows the compiler really read, so it already carries the full input set (data file included); asserted in the e2e test (`sources: crates/data/src/data.txt, …/lib.rs` on the server meta of the fleet key and in the installed local entry).
7. **Offload fallback (needed by the proof)**: a unit offloaded to a worker that fails (status != 0) because the worker lacks a hidden input (a derive's data file at an absolute path) is compiled again locally instead of failing the build (`script.ts:242`, event `incomplete`). Before, such a first compile killed the build.
8. **Spool depth**: `noteSpoolV1/readSpoolV1` (`UC/🛰️fleet/📊️counters`) write `unit-counters/spool` from every spool listing of the upload worker (throttled) into `build-counters.json`; `repo fleet status` reads the live depth of the cache root's spool (`B/🚢️fleet-status/📥️readers`, fact `OffloadFact.spool`, text line `offload.spool` EN/DE). Live now: "upload spool: 495 units waiting for the fleet cache (a compile waits beyond 36202)".

## Overhead (`K7-overhead.ts`, `K7-overhead-fleet.ts`, load 50)
Warm wrapper path (a local hit): added per unit = manifest id 0.0014 ms + memoised client 0.0007 ms + local manifest read 0.029 ms + files 0.048 ms = **under 0.1 ms** (the first `fleetClientV1` call, 0.44 ms, replaces the client `prepareFleetV1` built anyway). Cold: one GET 3.4 ms (hit or miss; a miss is then remembered 30 s), publish (blob + result) 16.6 ms and only after a compile; second lookup 0.07 ms. No extra process spawn. A "before" run of the old code was not taken (the tree holds uncommitted lanes K1-U1, git state cannot be switched): the figures are the isolated cost of every added step.

## Open items
- Fleet-wide spool depth: the machine table comes through the scheduler's closed `LoadReport` schema; a new field would be rejected (400) by the running scheduler until it restarts on new code, so only the local machine shows it. Order for a later lane: schema on the scheduler first, then the counters field (`readRemoteExecutionCountersV1`).
- The live cache server runs old code: manifests are stored undeclared (age/budget only) and a second origin's grown manifest is refused with 409 (first writer wins) until the server restarts; the client then keeps its local union and the key it published, other machines compile that unit once more.
- A derive that bakes an absolute path cannot run on a worker at all (the file is not at that path there): such units are compiled locally once per input change (new fallback), the manifest then makes them shareable.
- Manifests of registry crates have no source to retire them by (kept, ~300 B each).
- Slot id is shared by flag variants of one slot (union of their manifests); a flag-specific manifest would need the normalized command line in the address.
- Not run on windows/linux; negative stamp 30 s is a constant in the module.
