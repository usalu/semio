# O1: distribute + pin offload, declined events, SDK placement

LIB = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library`, RE = `LIB/🏗️build/🌐️remote-execution`.

## What changed
1. **Modes (G1/G2).** Schema `RE/🚀️offload/🧬️schema/🔣️.json`: `Mode = never | distribute | pin`, default `distribute`, `pinPrefix "pin:"`. `always`/`auto` are removed (any other value reads as the default). `policy/🟦️.ts`: `offloadSettingV1`, `offloadParseSettingV1`, `offloadPinV1`; `--offload=never|distribute|pin:<origin>` flag (EN+DE refusal text).
   - Gate (`🚦️admission/🟦️.ts`) returns `{offload,queue,reason}`: `pin` offers every unit and queues; `distribute` offers every unit worth a round trip (cost record ≥ 2500 ms or none) and sets `queue=true` only when this machine is saturated (door, slot queue ≥ 1500 ms, host wait, broker wait), else `headroom` (scheduler declines if nobody has room, unit compiles here). Vectors `🧪️tests/🚪️gate/🔣️.json` v2.
   - `semio-offload=queue` (new value): scheduler `🗓️scheduler/🟦️.ts` never declines it (still fails back at once when no worker could ever take it) and takes the requester from any `semio-offload` value. Client waits `queueSaturatedMilliseconds` 120 s (distribute) or `pinQueueMilliseconds` 3600 s (pin), the overall budget grows by that wait; decline memo is skipped for queued units. Cancellation, progress lines and local fallback unchanged.
   - Fan-out under pin is granted without pressure.
2. **Pin (G15/G14).** `semio-pin` placement property (`policy.property.pin`). Every worker agent (`🛰️agent/🟦️.ts`) advertises `semio-pin=<its origin>` itself (all production roles go through the agent). Requester sends `semio-pin=<origin>` + `queue`; placement matches it as an ordinary property and still excludes the requester. Under pin every runtime failure (no worker, queue timeout, infrastructure, incomplete inputs, worker policy ...) becomes reason `pin-failed` (event `offload-local-fallback`, detail `<pin>: <cause>`, EN+DE), the unit then compiles here so a build never fails.
3. **Declined events (G3).** `declineOffloadV1` (offload `🟦️.ts`) writes one `offload-declined` event (+ EN/DE progress line) and a reason counter for `source-kind` and `crate-type` (called from `UC/📜️script.ts`); `cheap` is counted without event (thousands of lines otherwise). `no-endpoint` is counter-only unless pinned. Progress lines now render the reason in each language (was English in the German line).
4. **Closure (G12).** `dependencyClosureV1` now follows the dependency names of every file of an artifact (rmeta, rlib, library), not one. New failure detail `offloadIncompleteDetailV1` (message + first source file, 240 chars) so the next `incomplete-inputs` is diagnosable. **Root cause of the 151 historic events was not reproduced**: three theories were tested and rejected (extern directory outside `-L` fails locally too; hash alignment; closure bound). The test (`closure is complete`) materialises the plan and lets `rustc` itself compile it with the transitive dependency in a second search root: passes. Live run still shows `incomplete-inputs` for `serde_core` ("file not found for module `de`" under the registry crate): a source-reach gap of `reachedFilesV1`, not an extern gap. Open.
5. **Limits (G10).** `maximumInputBytes` and `maximumUploadBytes` 4 GiB (were 512 MiB), `maximumClosureFiles` 32768 (was 4096), upload time 300 s. Only closure files travel and the content store dedups; no rlib pruning (risk of re-creating the can't-find-crate class). Observed refusals were 540-590 MB uploads (process3d) and "dependency closure" (>4096).
6. **G9.** `semioEnvironmentReadV1`: if a shipped `.rs` file reads `env!/option_env!("SEMIO_X")` and the requester has `SEMIO_X` set, the unit stays here (`not-portable`, detail names the variable) because no worker receives a `SEMIO_*` name. Fail closed, no silent divergence.
7. **SDK placement (coordinator extra).** Workers advertise `semio-sdk=<SDK directory name>` (`offloadSdkIdentityV1`: `SDKROOT` else `xcrun --sdk macosx --show-sdk-path`, via `sdkIdentityV1` of the unit key) through `detectWorkerRustcV1` properties (zero touch, macOS only). A unit linked by the host linker (`bin`, `proc-macro`, `cdylib/dylib/staticlib`, not wasm) requires the requester's identity (`offloadLinksNativelyV1`); unknown SDK on macOS keeps the unit local. Plain libraries and wasm ask for none.

## How and when workers pick up code (validator, placement, agent)
- Worker agent, validator (`🧱️actions`), rustc policy, offered properties: loaded by the supervised `agent` sidecar role (`🛰️sidecar/👷️agent`). The sidecar watches the role's code closure (30 s poll). A changed closure restarts only after a **quiet period of 300 s** with no further edit, at the latest after a **30 min deferral**, at most once per **30 min**; it first drains: no new action is accepted and running actions finish (waits up to 2 h, never aborted). So an edit reaches a worker 5 to 35 min later (plus drain), and a worker keeps validating with the old validator until then. Verified: ~1 h after the agent edit all 10 workers advertise `semio-pin` (`repo remote-execution status`).
- Placement, queue/decline decisions and `semio-offload` handling live in the **scheduler on the group server**: they apply after the server's `scheduler` role restarts by the same rule. Requester-side logic (gate, planner, wrapper) applies to the next build that starts (a running sealed build keeps its generation).
- Consequence: a requester that sends `semio-sdk`, `queue` or `semio-pin` to workers/scheduler that still run old code is declined/failed back to local (safe); a validator change (O2) is effective per worker only after that worker's restart.
