4. Pool (C): O16/O18 stub-rustc sandbox test shows grant 4 -> 3 tokens in the fifo; O18 real rustc, same pool: 1.91 cpu/wall at 4. A pool failure also reports 1, not excluded, but the formula below explains it without it.
5. Cause (by the grant formula, `worker/🧵️codegen/🟦️.ts`, inputs from `🛰️agent/🟦️.ts threads()`): on m07 at load 7.6, 10 cores, others 3, byCores = min(6, max(1, 4)) = 4. The only term left that gives 1 at normal pressure is `byMemory = 1 + floor((spare - peak)/512)`. `spare` = free memory above the 4096 MB floor with the other running units' reservations held; admission just required spare >= peak, so a worker packed by admission has spare - peak ~ 0 (coordinator sample: available 5918, floor 4096, spare 1822), and the declared peak (dag 4115, family estimate up to 7938) is a high estimate of what one thread uses (measured 2724, 1916). So every final on a busy 16 GB Mac got 1 thread. `pressure warn` workers (m01 m02 m11) also grant 1 via `pressured`. Not proven at runtime: the worker does not log which term bound.

## Fix (worker side, landed)
`remoteExecutionCodegenThreadsV1`: the fair share's threads are covered by the unit's own reservation: `byMemory = 1 + floor(max(0, spare - peak + (fairShare-1)*extra)/extra)`. A packed worker that admitted the final now grants 4 (cap, cores, others and pressure terms unchanged: pressure still grants 1, `others` still stop two finals sharing cores); spare below `peak - 1536` MB still grants 1. Bounded overcommit 1.5 GB per final; the ledger raises the declared peak after the first parallel measurement, the warden and the exit-137 path remain. Output bytes do not depend on thread count (O16: sha identical at 1/2/4/9), unit key untouched. Vectors: 4 re-derived (busy-reservation-covers-fair-share 2->4, memory-bounds 3->6, memory-exactly-peak-fair-share 1->4, no-declared-peak 3->6), 3 new (packed worker admitted tight 4, below reservation 1, pressured 1); independent Python oracle updated. `repo test-file` codegen: 3 pass / 0 fail.
No play restart needed; worker agents pick it up at their next restart.
