## (1) Diagnostic refusal, no change to which facts are compared
FO = `🧰️framework/🔨️modules/📁️filesystem/🧾️observation/`.
- Schema first: `FO📁️descriptor/🧬️schema/🔣️.json` `RelativeWindowsFactsChange` holds the compared fields in order. Those are the identity fields `dev ino mode size nlink mtimeNs ctimeNs`, then `kind volumeSerial fileId attributes security streams target`. It also holds the six refusals in EN and DE, the message and difference texts in EN and DE, the bounds (directory 300 code points with the tail kept, values 120), hex rendering for `attributes`, and `∅` for a missing value.
- `FO📁️descriptor/🟦️.ts`:
  - The closure-local `same` is now the exported pure `sameArtifactWindowsRelativeFactsV1`. Its body is byte-identical to the old one: the same `&&` chain over the same facts.
  - `artifactWindowsRelativeFactsDifferencesV1(expected, actual, role?)` returns `{field, expected, actual}` rows. It returns no rows exactly when `same` is true, which the test proves field by field.
  - `artifactWindowsRelativeFactsChangeTextsV1` renders the EN and DE texts.
  - `ArtifactWindowsRelativeFactsChangedErrorV1` is the typed error, modelled on the module's existing `ArtifactWindowsRelativeRenameRefusedErrorV1`. Its `message` is the EN text. It also carries `texts {en,de}`, `refusal` (the old sentence), `directory` and `differences`. It has no `code`/`path` pair, so churn does not classify it as a concurrent edit or as busy. The test asserts this, so it behaves like the old plain `Error`.
  - `artifactRelativeRefusalV1(error)` returns the declared sentence of a typed refusal and the message of any other error.
  - The Windows directory frame now carries a lazy `framePath` (root, then `win32.join` per child; it is computed only when a refusal is thrown). Six refusals now throw the typed error: `internal()` "Original Windows relative directory facts changed", "Windows relative entry changed while observed", "Exact Windows enumeration parent required", "Windows relative enumeration changed", "Current Windows relative path parent changed", and "Current exact Windows relative path descriptor changed". The last one names the fields as `parent.*` or `entry.*`, in the same order of evaluation as before.
  - Example of the new text: `Original Windows relative directory facts changed at C:\semio\…\🟦️typescript: ctimeNs expected 1763832720123456700, actual 1764061929456789000`.
- No retry decision changes. The dependency sync retry gate matched `^Current exact (?:Windows )?relative path descriptor changed$` and an excluded-word list (`lease`, `released`, …) against the whole message. A message that now contains a path would match differently. So `DEP💾️storage/🟦️.ts` (the sync loop, `retryableSyncFailureV1(...)`) now classifies `artifactRelativeRefusalV1(error)`. That value is the old message for every refusal, typed or not. The Windows branch of the incremental descriptor-retry test reads the refusal the same way.
- I deliberately did not register the error in `progress` `TypedRefusals`. Registering it would change how it is rendered and its exit class. It still surfaces as `Internal error: <EN text> (reference …)`. The reference digest changes because the message is longer.
