# R1: synced-tree staleness retention (2026-11-22)

Rule: the fleet cache holds only builds of the coordinator's synced tree. Mode `retention.mode` = `server.staleness.mode` in `🔣️policy.json` (schema `🏃️execution/🧬️schema/🌐️remote-cache.json`, `--staleness=off|dry-run|enforce` on `repo remote-cache serve`). Shipped default `dry-run`; nothing runs against live data until the server restarts on the new code (the live pid still runs old code).

## What changed (LIB = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/`)
1. Schema first (`🏗️build/🪢️slots/🧬️schema/🔣️.json`): `Declaration` (kind, toolchain sha, workspace `sources` path+sha256, `externs` blob digests), `Mode`, `Staleness`, `StalenessReport`, `Meta.declaration`, EN+DE texts. Unit-cache `Entry.retention`, fleet `RemoteUnit.retention`.
2. Declaration is a field `retention` of the entry manifest (`unit.json`, `stage.json`; names in policy `manifestNames`), so it travels in the blob the server already receives. `publishUnitV1` builds it from the dep-info rows the compiler really read (`workspaceRowsV1`: below workspace, not `.cache`/`target`/`.git`/`.nx`/`node_modules`, not lane tokens) plus extern file digests and toolchain sha; uploader copies it into the manifest, adopt copies it into the local entry. Stage manifests carry `declareV1(kind stage-output, externs = key.inputs digests)` (`☁️stage-fleet`). Build-script RUN entries: kind `build-script-run` is supported by schema, judge and server, but no producer publishes RUN entries to the fleet yet (K2 owns that); wire `declareV1` there when it lands.
3. Pure judge `🏗️build/🌐️remote-cache/🏷️retention/🍂️staleness/🟦️.ts`: stale = a source digest differs (`edited`) or is gone (`deleted`), toolchain not in the fleet's set, or every holder of a consumed blob is stale; a blob nobody holds that an earlier retirement took (persisted tombstones `.retention/retired.json`) counts as stale, a blob never held is ignored. Rust units without sources (registry, std) are live while a live root consumes them (transitively), else `unreached`; stage outputs and RUN entries are roots. Entries stored within the grace are never stale/unreached. Stat-memoized tree digests (size+mtime+inode, persisted `.retention/digests.jsonl`, 32 concurrent handles max).
4. Server: sweep inside `store.collect()` (maintenance loop, 300 s, plus writes over bound); report in `GET /status` field `retention` (and so `repo remote-cache status` JSON `server.retention`) and `.retention/sweeps.jsonl`. Dry-run records counts + first examples only. Publish gate in the PUT handler: a declaration that differs from the tree is re-checked after `recheckSeconds` (3) and then refused with HTTP 422 `stale-on-arrival: <reason> <path>` (enforce) or counted as `would-refuse-stale-on-arrival` (dry-run). Client maps 422 to skip reason `stale-on-arrival`, no retry.
5. Supersession removed as authority: collector drop reason `superseded` -> `stale`; slot is a dedupe hint (kept in sidecar and claim route). Entries that declared nothing keep the age rule (now also for slotted ones) and budget tier order stale/unreached < undeclared < live. `slotBudgetTierV1` deleted. Eviction record field `superseded` -> `retired`.
6. Local mirror `⚡️caching/🦀️cargo/🗃️unit-cache/🧹️gc/🪢️supersession/🟦️.ts`: `retireStaleUnitsV1` / `retireLocalStaleUnitsV1` judge local entries by `entry.retention` against the workspace tree (env `SEMIO_UNIT_CACHE_WORKSPACE_ROOT` or nearest `.git` ancestor), policy `gc.staleness.mode` = `dry-run` (log `retention.jsonl` in the cache root, interval 300 s).
7. G5: `.server.lock` is renewed every 60 s (`renewRemoteCacheLockV1`: the old six-hour rule made any server older than 6 h look dead, and a lock naming a dead pid is taken back), and a lock release no longer deletes a successor's lock. Live now: lock names pid 49378 (alive, stamp 4.3 h old: it crosses the 6 h rule about 23:20 until restarted on this code).
