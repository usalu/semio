## 1. `semio_offload_inputs_incomplete`: not a requester guess, a deliberate answer of the mutation derive
- The sentinel exists in ONE place: `🧰️framework/🛍️products/💻️os/🔨️modules/🗣️dsl/✨️derive/🔖️mutation-source-authority/🦀️.rs:320` (`mutation_authority_refusal`): when `SEMIO_OFFLOAD_INPUT_ROOT` is set (we run on a worker) every authority refusal expands to `extern crate semio_offload_inputs_incomplete;`, which rustc reports as E0463 and the client reads as `incomplete-inputs` (`🩺️failure`), then compiles locally. The requester never injects it and never knew: it uploads, the worker compiles (60-134 s with queue and input fetch), the derive fails, the unit compiles again here.
- Cause is NOT a missing `#[path]` file. The module scan already follows `#[path]`, `mod`, `include!` outside the crate directory (`reachedFilesV1`, `climbAboveV1`; the `../../x/🦀️.rs` text resolves in the virtual layout; tested). All 113 crates (stdio_dwg_mutations, fem_3d_material, fem_3d_mesh, fem_3d_analysis, gis_gismap_config, norm_results_config, stdio_html_mutations, layout frames/content ...) share one property: a reached module has `#[derive(... MutationLeaf)]` or `#[derive(Mutations)]` (`semio_os_kernel` re-exports the derive, so the planner's check for an `--extern semio_os_kernel_dsl_derive` never fired).
- Why shipping cannot fix it (checked in the derive): the expansion reads, by workspace-relative locators, the workspace markers (`package.json` with `workspaces` and `📋️project.json` at an ancestor), `🔣️mutation-authority.json`, `🗂️schema-document-index.json` (2.2 MB), each leaf's descriptor and payload schema and the schema documents they reference through the index (a transitive set only a compile reveals; `exactReadsV1`/the K7 manifest know it only after a first local compile), AND it computes `mutation_authority_workspace_token` = sha256 of the CANONICAL ABSOLUTE workspace path (`🪪️mutation-leaf-attrs-and-schema-index/🦀️.rs:68`) and bakes it into the unit as `MutationSourceProvenance` (and absolute paths into `include_bytes!` dependency lines). On a worker the workspace root is the sandbox, so even with every file shipped the unit would differ from the local one, with a path-derived token that no remap touches (a hash, so the path-dependent-output check cannot see it either).
- Decision (brief: ship, else decline before upload with a precise reason): shipping is impossible without changing the derive, so `planOffloadV1` declines BEFORE the upload: new `workspaceDeriveFileV1` (a `derive(...)` list, also inside `cfg_attr`, naming `MutationLeaf` or `Mutations`; not `proc_macro_derive(`, not `MutationLeafs`, not a `use`) over the reached sources; reason `not-portable` (an `offload-declined`, no fall-back counter), detail "the mutation derive in <file> reads the workspace authority and bakes the workspace path into the unit: it expands only in the original worktree". Measured on the live tree with the real planner over each unit's manifest: 113 of 113 crates of the `incomplete-inputs` list decline (113 derive, 0 planned, 0 other), 0.8 to 10 ms each (133 ms for the 666-file layout model, scan cost), no store call (test with a content store that throws on any call).
- Open (a derive change, not for this lane): derive the token from the authority projection's digest (or the workspace-relative identity) instead of the absolute path. Then the same unit is path-independent (also for the fleet cache: today a mutation unit compiled at checkout A and served to B carries A's token, `pathSensitiveV1` only looks at `env!(CARGO_MANIFEST_DIR)`), and shipping becomes possible with the K7 manifest + a workspace-rooted layout (workspace markers at the shipped root, the manifest's files at their workspace-relative place, component-root directories for aggregates, which are only `lstat`ed and are not in any dep-info). Until then 113 crates (7,466 s requester wall time per 45 minutes) compile locally at once.

## 2. `unmapped-path`
- `no --remap-path-prefix covers the module directory /Users/ueli/.sinc/play`: the units are inside the checkout; the module directory they need is the workspace root itself (`#[path]` into other top-level trees: shipped = common ancestor = root). `moduleRemapArgumentsV1` (the wrapper's own remap for a module directory above the manifest, K2 token: its path below the workspace) refused exactly that case (`workspace===shipped`; the name would be empty). Now it adds `--remap-path-prefix=<workspace>=.` (the same form the tests and Cargo's `trim-paths` use), placed before Cargo's remaps so those still win, in the LOCAL compile too, so local, worker and every checkout path record the same names (no machine path).
- `source outside CARGO_MANIFEST_DIR` (layout model): `reachedFilesV1` had its default cap of 512 files; the model reaches 666. Cap now `limits.maximumInputFiles` (8192) in the planner and the remap. (The layout model also applies the derive, so it is declined by §1; layout_diff, norm_inspector_forms, fem_app_surface, hub_stdio_catalog_projection plan with 105, 25, 8, 8 files.)
- Remaining difference not touched: `pathSensitiveV1` (unit-cache key) scans at most 64 files and treats more as path-embedding, so a big crate's key stays path-bound (K2 area).

## 3. The 60,000 ms deadline
`offloadDeadlineMillisecondsV1` (`📐️policy/🟦️.ts:65`) = min(cap 900 s, max(floor 60 s, 4 x recorded local cost)); no record: 240 s (`unknownMilliseconds`; linked units 2,400 s). `semio_plugin_retained_command` has a recorded cost of 3,999 ms: 4 x 3,999 = 15,996 < floor, so the floor applies. The deadline counts from the moment the action executes and includes the worker's input fetch (this unit shipped about 550 MB like its peers in the log: `worker fetch` 5 to 39 s per unit) plus any hand-over. So a 4 s compile on a loaded worker can exceed 60 s without anything being wrong. Not a no-record case: a unit with no record gets 240 s. One such event since 11:15 (60 over the whole log, 59 on 11-23 18:45-20:35). Suggestion, not changed (schema + policy): deadline = max(floor, 4 x cost) + shipped bytes / measured fetch rate, or decline units whose recorded cost is below the round trip (`worthARoundTripV1` already exists for the gate; here the unit was admitted because the overhead estimate was lower than the fetch).
