# W2 m12 closure-read TypeError

Evidence: /Users/Shared/semio-store/v1/origins/g1-m12/service-failure-7bc57af5.txt (+ ready.json tail): worker failure frame "TypeError: Cannot read properties of undefined (reading 'path')", relayed by closures/📡️session/🟦️.ts:33 ("Original closure read child refused: ..."). The worker stack is not retained; the parent only wraps the failure frame.

Root cause (code reading, not reproduced on m12): closures/🟦️.ts `pairs()` skipped every *trusted* index row (`if(row.trusted){...continue}`) and so never set `pack.index`. Trust comes from the member-index proof (resolveIncrementalRows): the .idx can be proven while its .pack is unproven (stamp differs: copied, fleet-fetched or touched pack). The untrusted pack then goes to the worker as kind "pack" without `index`; worker payload() does `bytesAt(row.index,...)` / `row.index.path` -> TypeError. Deterministic every attempt on a host whose pack stamp no longer matches its member index; other hosts have matching stamps.

Fix: (1) 🟦️.ts pairs(): a trusted index is skipped only when its pack is absent or trusted; otherwise it is read, hashed and attached as pack.index like an untrusted one, so the pack is re-proven. (2) worker 👷️closure-read-worker/🟨️.mjs request boundary: kind "pack" without index is refused with "Complete closure pack index required" (no TypeError).
Regression: new physical scenario "pack-unproven" (🧪️tests/🟦️.ts, 🧫️cases.json, 🧬️schema/🔣️.json enum): builds the pack fixture, indexes members, then changes the pack mtime so its member state is unproven while the idx stays trusted; capture + retire must succeed.
