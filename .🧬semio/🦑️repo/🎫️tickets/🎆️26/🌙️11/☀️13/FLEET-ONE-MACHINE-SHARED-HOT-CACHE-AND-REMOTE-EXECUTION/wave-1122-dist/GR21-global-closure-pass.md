## 2. Design (written before the code; schema-first: `CG🧬️schema/🔣️.json`, policy `CG🔣️.json`)
**Graph.** One module graph per tree and walk configuration. A node is what the command walk visits (`walkNodeV1`: a module or a resource at a path, with its source flag), keyed by `[workspace name, source, requiredSources, resource set, selected router words]` (stable across processes and machines: names are `{workspaceRoot}/…`). Its digest is `sha256(canonical JSON)` of exactly what a walk reads of it: kind, name, resolved edges (target name and source flag), defined provider ports, the directory's resolution configs, generated imports, router words and the provider designation. A file body edit that changes none of these moves no digest (the same cut GR12 made for owner records: validity on the answer, not on the bytes). Edges are stored as target keys without selection; a question's router selection is an edge redirect, its declared tool entries are stops (cut to a tool entry, never walked), exactly the walk's rules (`reachWalkV1`: a stop that is a root or a selected router is walked).
**Identity.** The digest of a strongly connected component = `sha256(sorted member entry digests sha256(name NUL nodeDigest), empty line, sorted distinct digests of the components and cut tools sha256(NUL tool NUL name) it imports)`, memoised per component and per family (stops + redirects; a component that reaches no redirected key shares the digest of the family without redirects). A question's closure digest = `sha256(sorted distinct component digests of its roots)`. One iterative Tarjan pass over the graph gives every component digest; after it every owner's closure digest is a lookup; an edit of a node forgets exactly the components that reach it (reverse edges) and nothing else; a node whose digest and edges did not change forgets nothing (cutoff).
**Owner record.** An owner's input identity = `sha256(owner, [target, closure digest of the target's walk question])` plus its own declared inputs; no per-owner layer list, no packing.
**Store.** Digest addressed under the machine store: nodes in `buckets` (256) chunks by key hash, `c/<sha256 of the text>.json.br`, a head `head.json` replaced atomically after every chunk is placed, chunks no head names removed afterwards. A save that stops anywhere (cancelled, killed) leaves the previous head whole; an edit rewrites only the chunk of each edited node; one chunk in memory at a time. A node's stored `extra` is the witness of its rows (`observationWitnessV1`: stamps of the paths that decide them, typed and live rows), so another process (or another machine that receives the chunks) trusts every unchanged node after one stat per distinct path, without reading or parsing it (`closureGraphWitnessedV1` + `closureGraphPassV1({trusted})`).
**Incremental.** A pass with the replica's change set as the journal dirty set (`pass.dirty`) revalidates only the walk nodes whose rows the set touches (`walkPartsHoldV1` + `rowTouchedV1`), rebuilds those, and the graph recomputes only the components above them.
**Boundary.** Unchanged from GR16: the reachable set is cut at the declared tool entries (`toolStopsV1`), the tool's own closure is its own question.
**Fleet (designed, not built here).** The fleet receives the chunks (digest addressed, shared by every owner) once and small owner records `[owner, target, closure digest]`; a record is valid while the taker's graph answers the same closure digest.

## 6. Open: exact remaining steps to make the digest the identity and remove the per-owner layers
1. Persist the graph in the machine store beside `ce/` (`<closure store>/g/`) and keep it current: every inference process loads it, calls `closureGraphWitnessedV1`, runs `closureGraphPassV1({trusted, witness:true})` over the questions it meets (with the read's journal as `cache.pass.dirty`), saves at the end; `🧹️retention` must treat `g/` as protected (R4's class) and never sweep chunks named by `g/head.json`.
2. In `boundedScriptInputsV1` record, instead of retaining the node parts of `reachWalkV1` into the capture (which makes them entry layers), one `global` row `closure-graph` `[question] -> digest` (`registerGlobalFactV1`), so `target-sources`, `native-target`, `generic-target`, `closure-of`, `tool-closure`, `script-provider` entries hold only their own rows; the resolver answers from the round's prepared graph. Because global resolvers are synchronous, `closureEntryHoldsAsyncV1`, `bundleRowsHoldV1`/`bundleHoldsV1`, `entryStampHoldsV1` and the take must first `await` the graph pass of the round for the questions of the entry (a sync caller without it judges stale, never wrong).
3. Remove what this supersedes: walk layers and their sidecar facts/members (`closureSidecarV1`, `walkFactsByDigestV1`, `walkMembersByDigestV1`, `closureLayerViewsV1` excluded-support logic in `closureApiV1.resolve/plan/adopt`), the per-entry packing of walk layers in the entry lane (`PT🟦️.ts` layer memo stays only for non-walk layers), the layer index for walk layers; the `derived` walk row of owner records becomes the `closure-graph` row (same question, the digest as fact). Laws to replace: `🧱️layer-lost`, `🧾️layer-index`, `🧬️read-verdicts` layer part, `🗃️layer-memo`, `📤️background-offer` shared-entry packing, `🪪️verification-stamps` layer part, `🗂️shared-groups` replay: each by a law over the graph row.
4. Fleet: offer the chunks of `g/` once per machine (digest addressed, deduplicated by the cache server like any blob) and the head per tree revision; a worker fetches the chunks it lacks, adopts through witnesses, and takes owner records of `[owner, target, closure digest]`; a record is taken when its digests equal the worker's.
5. Owners without a project manifest (3,262 Cargo-inferred owners) need their questions from inference (`targetClosureQuestionV1` on the inferred targets) to be measured; this probe covered the 1,607 manifest owners.
6. A resource-set question is only covered by the walk-pass law indirectly (no URL fixture); add a fixture with a URL import that a question names as resource.
