## 1. Design (as built)
**Identity of a walk.** `boundedScriptInputsV1` (every command walk: target sources, generic and native targets, closure-of, provider and tool groups) no longer retains the rows of the modules it visits into the caller's capture. It runs the graph pass and the walk detached and records ONE `global` row `["closure-graph", workspaceRoot, question]` whose fact is `{digest, answer}`: `digest` the closure digest of the question in the module graph (GR21 Merkle over strongly connected components, cut at the declared tool stops), `answer` the answer digest through the view of the recipe being derived (`👓️walk-views` `walkViewAnswerV1` of the reached roster, compiled modules, generated imports and ports, computed from the graph nodes). The question is in workspace names (`{workspaceRoot}/…`), so the row travels unchanged between machines and checkouts. The row holds while the digest is the recorded one, or (cutoff) while the answer through its view is the recorded one: an edit a view leaves out (scheduling code under a target's own closure) does not stale the owner, exactly as the derived walk facts did (the walk-views corpus of 8 mutations is reproduced verdict for verdict).
**Judging the row.** `O` gains `registerGlobalFactV1(name, holds, prepare)` and `prepareGlobalFactsV1(rows)`: every judge of record rows (`projectRowsHoldV1`, `settleClosureRowsV1`) prepares the global rows with an asynchronous preparer first. For `closure-graph` the preparer runs the graph pass for the question (stored nodes whose witness holds are used as they are, every other node is visited through the walk's own nodes) and leaves the answer for the round (or for the running turn outside a round); the synchronous resolver answers from there, else from the stored nodes of the machine graph while every reached node is witnessed (`O` `observationWitnessHoldsSyncV1`, the same verdict as the asynchronous one, one generator for both), else "does not hold" (never wrong: at worst an entry is derived again). Closure entries and fleet bundles judge their own `closure-graph` rows first, in one turn (`closureGraphRowsHoldV1`).
**What is gone from the record path.** No walk node row is a row or a layer of any closure entry or record any more: the per-entry layer lists of walks, their sidecar members, the derived walk facts (`walk:1` questions) and their re-asking, the reach-set fast path of the generation deriver, are removed (list in section 3). The layer store, stamps and packing remain only for the layers that are not walks (TypeScript programs, repository walks, other shared computations); for a command closure entry they are now its own rows plus one graph row per walk.
**Machine graph.** One graph per checkout and machine in `.cache/f/closure-graph/` (policy `directory`), shared by the read, its farm and its pool children whatever closure store they bind: loaded synchronously on first use, saved `saveDelayMilliseconds` (30 s) after a change and at the latest when the process flushes (`flushClosureOffersV1` → `flushClosureGraphsV1`), atomically (digest-addressed chunks, head replaced last); unreferenced chunks are removed only after `chunkGraceMilliseconds` (10 min) so a reader of a just replaced head still finds its chunks (several processes save into one directory). A save that is killed leaves the previous head whole (kill-resume).
**Fleet.** `CG🛰️fleet`: the stored graph is ONE fleet object: chunks as blobs, the head text as the result under `sha256([domain, "graph", sha256(head)])`, declared kind `graph` (R4's protected class) in a slot per scope; offering an object the fleet holds writes nothing. A taker fetches it (chunks it already has are copied, every blob checked against its hash, every chunk against its digest when loaded) and confirms its own tree by digests instead of walking: a module/resource node is adopted when the bytes of its file here have the SHA-256 the node recorded (`extra.sha256`), a file leaf likewise, a glob when it matches the same names here, a crate or sources node when its manifest and every leaf it names do; adopted nodes are stamped for this machine (`extra.adopted`), the rest is left out and visited by the next pass. The selection head (GR14) names the graph (`closureGraph`, schema EN+DE): the reading machine offers its graph before it publishes the head, a machine that takes the head adopts that graph before it judges the owners (`SX` `selectedGenerationV1` `graph` hooks, wired in `🔌️attempt`), and a newer graph alone republishes the head.
**Coverage.** `CG🍃️leaves`: file leaves (digest = SHA-256 of the bytes), glob nodes of non-module inputs (digest = base, pattern and matched names; edges to the leaves), stamp trust (this machine) and content trust (any machine). `CG🦀️cargo`: a Rust owner's closure = its crate node (the `graph` and `sources` projections of its manifest, GR18's validated reader `nativeDependencyRoots` for the path-dependency closure, development dependencies only at the root) → the crate nodes of its path dependencies, its sources node (the file list of the crate's static Rust reading `cargoSourceSetV1`, or every file below the crate for a crate without one) → file leaves, and the leaves of its workspace manifest and lock file. An edit of one crate's sources moves its leaves, its sources node and exactly the owners whose dependency closure contains that crate; a lock edit moves its Cargo workspace; an edit of a file no crate reads moves nothing.
