## 2. The rule (gate `offloadGateV1`, order of signals)
`never` -> `pin` -> **expensive unit** -> (unchanged O13 path: free local slot, worth test, unmeasured wait, door, slot queue, host, broker).
An expensive unit asks ONE question: does a worker have room for it at its placed peak, within `finals.waitMilliseconds` (30 s, poll 2 s)? Yes: `offload:true, queue:true, reason:final` (it queues up to the existing 120 s on the fleet if another final took the room in the meantime, then falls back to local like every offload). No: `offload:false, reason:final-wait`, it compiles here (the caller's `compile(true)` takes the local slot as for any local unit). The local slot is not taken before the question, so the machine stays free for the next unit. A cheap unit never asks (`workerFits` is not called: vectors and composition test assert it).
- "Expensive" (`offloadExpenseV1`, schema `policy.finals`): predicted local compile time >= 120 000 ms OR placed peak >= 4096 MB. Time = the recorded local compile time of the crate; for a linked wasm unit never measured here: the family estimate (p90 of the recorded compile times of the `_component` crates, same quantile and minimum 3 as O11's peak family), else the seed 900 000 ms. Memory = the placed peak (learned x1.25, else for a linked wasm unit the family peak x1.25 or the cold bound 6144), counted only for a unit with a learned peak or a linked wasm unit (the 2048 MB unknown default of an ordinary unit says nothing). So: any never-measured final is expensive by the seed; a measured small final (editor 36-91 s, 385 MB, surface) stays here; node_graph/flow (111-268 s, 1.2-1.9 GB) sit at the time threshold; puzzle/cad/every hub final are expensive.
- "Room" (`awaitFleetFitV1`): the scheduler's own idle counting at the unit's peak (`/v1/fleet/idle?origin=&peak=`, the same call the job plan uses: `fleetIdleSlotsV1`), slots > 0. `null` (offload never, no scheduler, no answer) is false at once, no waiting. With O12's single charge live a running final already reduces the count, so several finals ask against the true remainder; the race of two askers in the same second is covered by `queue:true`.
- Reads of the cost folder are shared with placement: `readUnitExpenseV1` returns the placed peak that `offloadRustcUnitV1` now uses too (one reading, replaces the duplicated peak expression in `OFF/🟦️.ts`).
- Learning: remote-only finals do not record a compile time (a remote run's time is not the local cost); they record their peak (O12). Final times are learned only from local compiles; until then the seed applies.
- Schema first: `Policy.finals` (definition + value in `OFF/🧬️schema/🔣️.json`), reason `final-wait` (enum, type, counters key, EN+DE text: "it is expensive but no other machine had the memory for it in time" / "sie ist teuer, aber keine andere Maschine hatte rechtzeitig den Speicher dafür"); gate reason `final`.

## 3. Composition with O10, O14 and the gate (checked by a test and by reading)
- O10/O14 plan = `planComponentJobsV1` (fleet slots at the final's peak, bounded by cap and coordinator memory) + `planComponentJobSlotsV1` (light = fleet jobs - 1, local = min(wanted, 3, tokens)). The fleet slots are counted once, in `light`; local memory is reserved only by the extra LOCAL jobs (`admitLocalComponentJobV1`), never by a light job.
- The gate asks the same scheduler at the same peak, so plan and gate cannot disagree about a table: with S worker slots, jobs = S-1 light + L local. All S+L finals ask; S get a worker; the L that do not wait 30 s and compile here, which is the number of extra local jobs O14 holds memory for. No final is charged twice (a remote final consumes no local reservation and a worker slot; a fallen-back final consumes the local reservation of a local job or, if a light job's final falls back, the broker's memory admission of the unit and the local grant, never more than the grant: stub test `localFinals.maximum <= size`).
- No starvation: the local jobs' cheap units keep compiling while finals are away (stub test: `remoteDuringCheap > 0`), the first job always starts (O14), every final runs (6 of 6 and 8 of 8 passes in the stub: remote + local = all).
- Honest limit: if workers vanish after the plan sized light jobs, those light jobs' finals fall back to local after the 30 s wait; their memory is then bounded by the broker's per-unit admission and the local grant (O10 statement), not by a reservation. With an old scheduler that ignores `peak` (the live one until its restart) the count is action slots only: the gate says "room", placement still gates by headroom, the final queues up to 120 s and then compiles here: a bounded loss against a 10-60 min compile.

## 7. Open items / risks
- Seed 15 min and thresholds (120 s, 4096 MB, wait 30 s) are policy values; tune on the first run from `offload-run` detail and the `final-wait` counter (`reason/final-wait`: how often no worker had room).
- A final that fell back after `final-wait` compiles locally and teaches its time (then the record, not the seed, decides). Finals that only ever ran remote keep the seed (always expensive); no local time exists to learn from.
- The old live scheduler ignores `peak`: "room" is then optimistic (see section 3); the O12 single-charge scheduler restart makes it exact.
