# R2: retention follows every dependency edge (2026-11-23)

LIB = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/`. Scratch: `/private/tmp/claude-501/-Users-ueli-Documents-semio/caf759d9-ccba-4796-9909-827125acd710/scratchpad/r2/` (`ws` copy of the proof workspace, `root` local store A+C, `root-enf` enforce copy, `A.out`, `C.out`, `ret-dry.json`, `ret-enf.json`). Nothing ran against the live fleet store, the live unit cache or any server; no server restarted; lock `lock.retention` taken and released.

## Cause (P1 finding, confirmed)

R1 declared only blob digests of plain file externs. Two edge kinds were lost: (1) `keyInput.externs` holds `unit:<id>:<svh>` (proc-macro dylib), `iface:<id>` (metadata) and `builtin` for such externs, and `declareV1` keeps only 64-hex values, so every proc-macro/host edge vanished (`serde -> serde_derive -> syn -> quote -> proc_macro2 -> unicode_ident`); (2) a build script has no extern edge at all: the lib reads its OUT_DIR, the RUN reads the build script executable, and RUN entries were roots without a consumer link. A registry/host entry reachable only through such an edge was `unreached` and would be retired under `enforce` (P1: 9 of 24 entries). Raw digests alone are also unsafe: a restored+rebased `.rmeta` or a codesigned dylib no longer has the digest of the stored blob.

## What changed

1. Schema first (`LIB/🏗️build/🪢️slots/🧬️schema/🔣️.json`, `🟦️.ts`): `Declaration` version 2 with `self` (the entry's own local key) and `units` (local keys of the entries it consumed whose bytes a digest cannot name); `DeclarationV1` type updated. Version is part of the contract: a declaration of another version is not judged.
2. Judge (`LIB/🏗️build/🌐️remote-cache/🏷️retention/🍂️staleness/🟦️.ts`): `judgeStalenessV1` indexes entries by `self`; transitive staleness follows `externs` (blob digest holders) and `units` (name holders), an edge stale when it has holders and all are stale; reachability of non-root entries follows both. Only workspace-source entries and `stage-output` are roots now; a `build-script-run` is no longer a root, it is live while a live unit declares it (OUT_DIR) and is reached from the build script executable (RUN's `units`/`externs`). Declarations of an older version are treated as undeclared (conservative). `declareV1` takes `self`/`units`, version 2.
3. Producers name themselves (`LIB/⚡️caching/🦀️cargo/🗃️unit-cache/🪪️extern/🟦️.ts`): `markProducerKeyV1`/`producerKeyV1` write and read `<lib>.semio-key` (`{version,sha256,key}`), trusted only while the file digest still equals `sha256`; written after the last byte change (after rebase on restore, after publish on a miss) for rlib, rmeta, dylib/so/dll. `📜️script.ts`: every `--extern` file contributes its raw digest and (when trusted) its producer key; the OUT_DIR run key is read from the build directory; both go into `retention` with `self = key`.
4. Build scripts (`LIB/⚡️caching/🦀️cargo/🗃️unit-cache/🏗️buildscript/…`): the executable's identity file now also records the compiling unit's key (`buildScriptKeyV1`); `runBuildScriptV1` writes `semio-run-key.json` beside OUT_DIR (hit, fleet hit and miss) (`markBuildRunKeyV1`/`buildRunKeyV1`) and publishes the run with a `build-script-run` declaration (`externs=[executable digest]`, `units=[executable's unit key]`, `self=run key`). `publishBuildRunV1`, `BuildEntryV1.retention`, `packRunV1` (wire `unit.json.retention`, so the server reads it) and `unpackRunV1` (adopt copies it) carry it. Registry/host units, proc-macro libraries, build script executables and runs are live exactly while reachable from a live workspace entry.
5. Entries without a declaration (pre-R1, 55,309 in the live fleet store, 0 declared) are never judged: verdict `undeclared`, a consumer is not stale while an undeclared entry holds its blob, only the age and the budget bounds retire them. Declarations of version 1 (published by the R1 wrapper with incomplete edges, e.g. local entries from P1's scratch) count as undeclared too, so enforce cannot wipe them for missing edges.
