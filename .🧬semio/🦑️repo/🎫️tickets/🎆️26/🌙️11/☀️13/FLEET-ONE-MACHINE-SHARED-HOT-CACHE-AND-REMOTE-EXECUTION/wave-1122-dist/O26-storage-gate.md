# O26: the storage gate charges what a pass still has to write (2026-11-24 14:30 to 15:20)

`NB` = `🧰️framework/🔨️modules/🏃️process/📦️artifacts/🏗️native-build/`, `CP` = `NB🧩️component-pass/`, `SG` = `CP💾️storage-gate/` (new member). Lock `lock.component-jobs` (released). The play clone and its processes were only read. Patch set `wave-1122-dist/O26-patched/` (combined O24 + O26, one restart).

## 1. What the gate computed (file:line in `CP🟦️.ts` before the change)

- **Prediction per pass** (`componentBatchesV1`, 218-241): for one batch (a pass, split into `<pass>-bN` when its joint unit closure exceeds the free bytes above the reserve) the sum over the UNION of the unit closures of its components of `quantile(recorded outputBytes of that unit)`, else the quantile of its kind, else the kind's bound. Shared units count once per BATCH, but again in every other batch: `release-00-b0` 25 components = 52,573 MiB, `b1` 22 components = 24,026 MiB, though the passes share one build directory per profile and the 25+22 components share most of their dependency units. The 51.3 GiB for b0 is therefore the right order of magnitude for b0 alone (33.7 GiB written after 2 h 25 min), but b1..b4 were charged their shared dependencies a second time.
- **What "free" is** (`availableBytes`, 870): `headroomBytes() - sum(predicted bytes of every inflight batch)`; `headroomBytes` is the statfs of the image (already net of what b0 wrote). So b0 charged its whole 52,573 MiB for its whole life, while the volume ALREADY showed 33.7 GiB of it: 47.7 - 51.3 = -3.6 GiB, no later pass ever fit (`runPass`, 872-882: wait while `inflight.size`, wake only when a batch SETTLES).
- Not counted either way: stage outputs (`components/stages`, after the pass), `incremental` sessions (collector's business). A fleet-placed final is charged like a local one (same unit outputs; what returns locally is its `outputBytes`, which is exactly what the prediction counts, no scratch of the worker).

## 2. The fix (schema first, member `SG`, laws pure and language-agnostic with a Python oracle)

- `storageChargeBytesV1` = `max(0, predicted - written)`; `storageGateV1` = free (`headroom - sum(charges)`) against prediction + reserve, with `shortBytes`. `written` = the output bytes of the pass's finished units (`measureOutputs`, now per pass and called at every evaluation, cached per artifact: only new units are stat-ed; a failed measure is skipped until the next poll).
- `admitPassStorageV1` (the whole admission as a function over ports, so it is testable without a build): waits while the room is short and something runs or reclaims, re-reading every `pollMilliseconds` (5 s) because a running pass lowers its own charge with every written byte (the old code only woke when a pass settled); one wait line per `progressMilliseconds` (60 s) saying needed / predicted / reserve / free / charged / running / written / short and what releases it, EN + DE; then collector (`reclaimStorage`), then the grow step, then the bilingual refusal. The slot in `inflight` is taken synchronously at the admission (`hold`), so two waiters cannot both pass on one wake. Cancellation is checked at every wake.
- **Shared-unit increment**: `componentBatchesV1(..., present)` takes the units no earlier batch of the same lane (profile + target = one shared build directory) accounted (`batchAdditionsV1`); the driver plans the batches in plan order per lane. Test: split fixture b0 450, b1 570 -> increments 450 + 170 = 620 = the whole-pass prediction.
- **Bytes already on disk** (restart): `measurePresentDepsBytesV1` sums the unit outputs of the profile in the shared build directory (classic `deps` and the per-unit `build/<pkg>/<hash>/out` layout of the clone), bounded walk (no incremental, no fingerprints); `creditPresentBytesV1` credits it against the lane's batches in order, never below zero; a line says it (EN/DE). This is what makes the restart admissible: b0 predicted 52,573 MiB, the lane holds ~30 GiB.
- **Learned growth**: every finished batch appends `{key = profile|target|sorted components, bytes = output bytes of the units it COMPILED (cache replays excluded)}` to `components/storage-growth.jsonl` (`recordStorageGrowthV1`, a failed write is not fatal); with two rows the p90 (type 7) replaces the computed footprint (`learnedBatchBytesV1`); torn lines are skipped, 16 rows per key.
- **Grow in place** (`storageGrowDecisionV1`, option `growStorage`): only when nothing runs (an attached image cannot be resized: W8 proved `diskutil image resize` and `hdiutil resize` refuse it), only when the host stays at or above its hard reserve (CAS7's 72 GiB cache-host floor, `Policy.growHostReserveBytes`) after holding the WHOLE larger envelope plus the initial extent (W8's `host-short` rule), aligned to 1 MiB. A refusal says why in both languages (`busy`, `host-reserve` with numbers, `host-unknown`, `grow failed`). **Honest limit: the production hook is not wired.** The driver holds its own shared lease on the image and the doctor's grow takes the exclusive lease (tried once, `held` otherwise), so a running driver cannot detach its own image; wiring the real `growNativeImageV1` there would detach under live compilers or never get the lease. Law, hook and message are in place and tested with a fake port; the production adapter belongs after the lease question (open item 2). While a pass runs the wait line says "the image can only grow while no pass runs".

## Open items
1. The wait-for-storage slot: a pass parked at the gate still holds its job slot (the runner's `ready` hook, O24 open item 1, not added).
2. Production grow adapter (needs the build's own lease released between runs, or an out-of-process grow before the chain starts).
3. Stage outputs (`components/stages`) are not part of any prediction; they land after a pass and show up in the free bytes only.
4. The present-bytes credit counts every unit output of the profile in the lane directory, including units no remaining pass needs (the collector removes those after each pass); a stale lane could be credited too much, the statfs headroom still bounds every later admission.
