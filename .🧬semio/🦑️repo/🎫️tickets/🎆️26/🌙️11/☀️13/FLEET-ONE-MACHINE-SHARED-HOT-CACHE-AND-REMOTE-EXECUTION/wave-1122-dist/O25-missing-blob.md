## 2. Fixes (root, then requester, then worker)
a. Scheduler (`R🗓️scheduler/🔐️input-leases/🟦️.ts` NEW, hooks in `R🗓️scheduler/🟦️.ts`): when an operation is accepted (after the cache check and the idle/candidate refusals, before the queue-bound check so the bound still holds), `OperationInputLeasesV1.hold` reads the action, walks the input root (directory blobs, 16 at a time) and takes ONE lease per blob under the operation's own name `input:op-<action>` through `content.missing(..., lease)` (the cache server writes the lease before it answers, for present blobs too). Every missing blob (files, directories whose children are therefore unknown, the action, the command) is answered at submission in one `FAILED_PRECONDITION` with the full `PreconditionFailure` list (message: `Missing blob <h>/<s> and N more`), so a loss costs seconds, not the queue wait. The lease is renewed while the operation exists: `server.inputLeaseRenewSeconds` (schema-first, 600 s, below the store lease; `🔣️policy.json` + `🏃️execution/🧬️schema/🌐️remote-execution.json`), one operation per sweep tick; a queued operation whose blob vanished despite the lease is finished with the lost blobs at the next renewal. Released at completion (`finish`), after which the blobs run only the store's 60 s grace. The sweep, the collector and the reclaim never remove a blob leased by a live operation.
b. Cache server and store (`LIB🌐️remote-cache/🖥️server/🟦️.ts`, `LIB🗄️cas/🪦️reclaim/🟦️.ts`, `LIB🗄️cas/🧹️collector/🟦️.ts`): the lease is written BEFORE the answer (HEAD) and BEFORE the put (PUT), a failing lease is a 503 (`retry-after: 1`, which the client already retries); reclaim reads the lease table (incremental reader, re-read when its stamp changes) and counts `leased`; the collector re-stamps the lease table before every removal like it already did for pins.
c. Requester (`R🚀️offload/...`): `executeOffloadV1` takes `repair`, `repairRounds` (default `limits.repairRounds` = 3, schema-first), `onRepair`. A response with `FAILED_PRECONDITION` naming blobs (`offloadMissingBlobsV1`: every `MISSING` violation, else the one blob of the message) calls `repair` and submits the SAME action again (new operation, same digest; budgets keep running, phase timer re-armed). `shipOffloadActionV1` returns `repair(named)`: refuses when a named blob is not one it ships; re-checks every blob (one existence check under the lease, which also re-leases the present ones), uploads the named ones plus whatever the store lacks, refuses above `maximumUploadBytes`, returns blobs and bytes sent. After three rounds, or when the blobs cannot be sent, the unit is declined as `incomplete-inputs` with the rounds and total bytes re-sent in the detail (so a pin shows `pin-failed: ... incomplete-inputs`, no longer `no-idle-machine`: `classifyOffloadStatusV1` reads the `Missing blob ` prefix). Event `offload-reuploaded` per round (round, named, sent, bytes; EN/DE progress line; kind added to the closed event schema). Both call sites (`offloadRustcUnitV1`, `offloadCommandV1`) pass it; `built.release()` still runs once at the end.
d. Worker (`R👷️worker/🟦️.ts`): on a missing blob it surveys the whole input root (directories level by level, files not in the local cache checked with one `missing` call) and answers ALL of them in one status (`missing[]`, message `... and N more`); an unreadable directory blob is named itself. Takes effect when each worker agent restarts.
