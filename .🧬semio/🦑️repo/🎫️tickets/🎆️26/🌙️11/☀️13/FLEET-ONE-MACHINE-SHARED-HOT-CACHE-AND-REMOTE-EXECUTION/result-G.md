## Built
- `R/🧶️nx/🚦️single-flight` (R = `🏗️build/🌐️remote-cache`): loopback front between Nx's native HTTP client and the cache server. GET miss -> `POST claim/nx/<hash>`; held -> long-poll `await` slices until the holder's upload (then GET again), lease lapse -> takeover, wait budget 600 s (`SEMIO_NX_FLIGHT_WAIT_SECONDS`), then plain miss (duplicate work, never a wrong result); server unreachable/refusing/full -> miss immediately, circuit breaker. PUT streams through with `x-semio-slot` when announced; `/cas/<sha>` is forwarded so executors need no real token. Real token never leaves the launcher; Nx gets a per-run token. Wired in `📜️script.ts` (stopped in finally, releases all claims). Switch `SEMIO_NX_FLIGHT=off`.
- `R/🧶️nx/🏁️task-finish` + executor (`📤️arguments/🟨️.mjs`): at task end the executor uploads receipt payload (below), then tells the front `POST /flight/finish {hash, slot, outcome}` (NX_TASK_HASH): releases the claim at once even for failed tasks.
- Wasm payload decision: **fleet CAS through the receipt**, not declared outputs. Reason: 123 MB would be stored twice and in every Nx archive; receipt entries already carry the directory digest, which is the SHA-256 of the manifest text, so the manifest is one more CAS blob under that digest and every file is a blob by its own digest (deduplicated, digest-verified by the server). `🧾️store-receipt/☁️fleet-content`: `publish` (producer, before the Nx upload, best effort), `restore` (hook in `withStoreReceiptsV1`, before the old "re-execute" repair; verifies every byte, builds aside and swaps, failure changes nothing). Backend hook in `🔌️backend/🟦️.ts`.
- Slots: `🧮️task-model/🪢️task-slot`: `nxTaskSlotV1` = slot("nx-task",[project,target,configuration,platform?]). Platform is included unless inputs are proven platform-free (named inputs expanded; unknown = platform). Finding: nx.json `sharedGlobals` (inside `default`) already hashes `process.platform+arch`, so almost every Nx hash is platform-bound; a neutral slot would make platforms delete each other. Native execution kinds always platform-bound.
- Registry capability `single-flight` for nx: NOT flipped (see unverified).

## Proof
- single-flight tests (14): pass-through/auth, two builds -> one computes and one receives the upload, 6 askers -> exactly 1 "compute", failed task release in <2 s, dead holder lease takeover, wait budget, unreachable server, claim-refusing server, slot header, routing, stop releases claims, guarded drop, and Nx's own native HTTP client (`HttpRemoteCache` from nx 23.2.0, child process) waiting through a held task and receiving the archive. Manual: native client waited 40 s (beyond Bun's 10 s idle default) and was served.
- fleet-content tests (9): manifest digest equals the repo's digest and Python hashlib; producer publishes (second publish uploads 0), a second workspace at another path restores byte-identical (sha256 per file), links, concurrent restores, absent/corrupt blob leaves nothing behind, unreachable store, through the front.
- Known Nx behaviour: `getBatch` awaits all root-task GETs together, so one held task delays cache decisions for the others in its batch (head-of-line, bounded by the wait budget).
