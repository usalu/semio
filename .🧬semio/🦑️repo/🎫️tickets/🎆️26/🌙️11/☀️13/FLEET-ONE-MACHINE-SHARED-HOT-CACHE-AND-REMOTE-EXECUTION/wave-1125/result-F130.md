## Design (schema first)
1. Footprint gate (`🧠️memory/🦶️footprint`): schema policy `overPercent: 100` (EN/DE description), message `overGrant` (EN/DE, names footprint, percent, grant, seconds); `footprintOverGrantV1`, `gate.overGrant()`; in `admit` the 120 s cooldown (`calmUntil`) is neither set nor honoured while over the grant, so every admit waits again (soft tiers keep the cooldown). `.d.mts` updated.
2. New `🧠️memory/🚧️wave-admission/` (schema `Policy`, `Messages`, `Decision`; `🟨️.mjs`, `🟨️.d.mts`, tests):
   - Policy numbers: hold on OS pressure `critical`, swap-out rate >= 32 MB/s, available < 1024 MB; step 1 s, progress every 15 s, over-grant max wait 300 s, host max wait 120 s, `reducedWidth` 1, sample ttl 5 s, stale 30 s.
   - Per the coordinator correction, swap USED never holds; it is only an informational field of the progress line ("information only"). Live signals only: `swapOutMegabytesPerSecond`, `pressure` and `availableMegabytes` of the host sample.
   - `createHostPressureReaderV1`: reads through the existing sampler port `readHostSampleV1` (macOS vm_stat/sysctl swapusage/memorystatus level, Linux meminfo/vmstat/PSI, Windows native memory facts), whole-host probe, ONE cached reading per ttl in flight at a time (never a spawn per look), keeps the previous reading for the rate, stale or failed = unknown (no hold).
   - `createWaveAdmissionV1`: `holds()` (sync: `overGrant` | `hostBusy` | `admit`; always `admit` in a process without a footprint gate), `between(signal)` (cancellable wait, release/settle between waves at most once per 30 s while over grant, bilingual progress every 15 s naming footprint, percent, grant, swap-out rate, pressure, available, swap used; after the bounded wait returns `reduced`), `narrow()` (true while reduced and the state still holds: one project at a time, never zero; later calls return at once, no repeated waits), `resumed` line.
3. Wiring: governor (`🧠️memory/🟨️.mjs`): new options `between` and `narrow`; `pump` now holds a new project over the grant even with none running (calls `between`, then admits), width `narrow()?1:workers`; `createGraphParentMemoryGovernorV1` defaults come from `waveAdmissionV1()` (old 85 % hold kept, OR the new tier). Wave start (`📦️project-nodes/🟨️.mjs`): `await waveAdmissionV1().between(waveSignal)` right after `useEnvironmentGateV1()`.
4. Scheduling table `📥️source/🔏️closure/🗓️scheduling/🔣️.json`: port `🧠️memory/🚧️wave-admission/🟨️.mjs` added to `memory-governor` (needed: keyed project-nodes imports it; the boundary law lists `project-nodes -> wave-admission` as a violation without it and not with it, checked in a scratch mini checkout).
