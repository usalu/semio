## 2. wasmparser rmeta (diagnosed, fixed at the root class)
Evidence `1795620718578-unit-b66aaa82c313` (m08 kept, m14 refused): strings equal, 180k scattered byte differences, +87 bytes, rlib equal because `embed-metadata = DoNotEmbed` puts the metadata only in the rmeta. Newer pair `serde_core` (m02 vs m10): same sizes, `.d` and `.rmeta.semio-deps` differ and the dep-info names `.../build/serde_core/<hash>/out/private.rs` with two different Cargo hash directories (f1784a69ed57cb5a vs 71f3b8ad10918f98). The key neutralises that hash (`outDirectoryIdentityV1`), the compile does not, so rustc records it in names, spans and svh. Dependents (wasmparser with serde) inherit the difference because metadata-only units key their externs by interface, not bytes.
Proof with rustc (synthetic crate + dependent, 2 hash dirs): crate rmeta differs and dependent rmeta differs (32 bytes); with the fix both equal. `-Z threads` (0,1,4,10) and source path with remap are NOT causes (identical md5 each).
Fix: `canonicalOutDirectoryArgumentsV1` appends `--remap-path-prefix=<OUT_DIR>=/cargo/out-dir` (last wins), key sees role `⟨cargo-out-dir⟩`; dep-info and the entry's dependency rows go through token `@@semio-gen@@` (schema `generatedToken`).
