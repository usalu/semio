## 1. What edges depend on (confirmed from the code)
`createStreamingEdgesImplementation(...).edgesOf(name, node)` (`📥️inference/🕸️dependency-edges/🟨️.mjs`) computes an owner's edges from (a) the stored `node` of its fragment (module graph facts), (b) its manifests read from disk, (c) the environment: owner table, package index, Go modules, lock. No inference facts, no source reads ("without reading a source"). So an owner whose own facts hold never needs inference when only the environment moved.

## 2. Finding: the edges-only operation already exists
The compute port already has it: `edgeRefreshOwnersV1` (`🤝️prefetch`) -> `part.edgeOnly` + `reEdge` (`partial:"edges"` owners, written in `buildOnce`), and it is already narrowed: `edgeConsumersOfPartV1` diffs the previous and present environment parts and matches each kept owner's recorded lookups (`reads` of its stub); non-consumers are `carried` (edges kept, only the environment name bumped). A change elsewhere moves no edges when the previous parts are stored (measured: new owner in a 300 owner store, 0 edges recomputed); without stored parts every kept owner is refreshed (edges only, no inference). So items 2 and 4 were in place for a moved environment. The inference storms came from the two places that did not use it:
- the plan (F126 fix 1) marked every owner with `edgesEnv !== manifest.env` dirty -> full inference;
- the heal in `buildOnce` re-queued stale owners as dirty -> full inference (1780, 4356 owners), and an unchanged environment refreshes nothing, so a stale row could only be inferred.
