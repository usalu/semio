### (1) Why the farm is declined: measured, and it is not the parent's heap
- `planGraphFarmV1` returns 0 workers when the memory bound is below the minimum of 2 (`serial (memory)`), or `reserveFarmV1` leaves < 2. In `planFarmWorkersV1` the host is lowered by the machine's AVAILABLE memory: `host = min(physical, grant/treeShare 0.4 + (available - 4096 floor)/0.4)`; probe with a 3072 MB grant: available 5000 MB -> 1 worker, 9738 MB -> 6, 15000 MB -> unbounded; with 4096 MB grant and 5000 MB available -> 2. This host has 72 MB unused and 31 GB used, `available` sits at 5-10 GB, so the width is 0-1 and the minimum of 2 turns it into 0. The parent's heap enters only as the constant `parentFootprintMegabytes` 1300, not as RSS (probe: resident 1.5 / 3 / 5 GB gives the same width). So the accounting is right in kind (a saturated host cannot carry more children) but the minimum of 2 has no basis: one child is also the worker the grant pays for and its first request is ESSENTIAL (admitted whatever the free memory says). Patch B drops the minimum to 1: all inference leaves the parent's single thread for one cancellable child (3 loops, recycled after 96 projects or on memory ratio), more workers join when the host frees memory.
- What the parent retains (new pass, first wave 18:04-18:10): heap 2.5-2.9 GB at wave 1 (managed 1.5 GB + external 1.0 GB, 9.5 M objects, 6 M strings), growing 0.1-0.4 GB per wave (old pass: 2.6 -> 4.4 GB over 5 waves, 14.7 M strings, 7 M arrays at 5.4 GB). Retained across waves in `🕰️generations/🟨️.mjs`: `carry.upserts` and `carry.append` (rows of every owner of every wave, kept in memory until the final patch although each wave is already written to the journal as `.rows` files), `carry.owners`. With patch B the inference heap (the part that grows with the owners' closures) lives in the child and is recycled; measure the parent's growth per wave after the next read starts.
