# F124 findings: two more readers/writers of mounted images without the shared lease

Found by the stronger image-lease law (`⚖️laws/👓️image-lease-readers`); both are documented as class `unrouted` in its allowlist so the law stays green, and each entry names the fix. Remove the entry when routed (a stale entry fails the law).

1. `🏗️build/🧹️cache-gc/🏃️runner/🟦️.ts` (`collectCacheV1` and its walks): measures and removes units below mounted images (`.cache/b/<partition>/m/...`) with the exclusive area lease only (`ports.exclusive`), never the shared lease of the image (26 call sites). It races the exclusive regrow, retirement and detach exactly as dedupe did. Fix: add an image reader per partition to `CacheRunnerPortsV1` (created in `runCacheLedgerV1` from the lease directory, as F124 did for dedupe) and run each walk, measurement and removal step inside it; keep steps short (bounded per directory batch).

Its only callers are the gc delegate and `retireIdle` in `🧹️cache-gc/⌨️command/🟦️.ts` (lines 215 and 257): wrap both in `withNativeImageSharedReadV1` for the partition of the area (`cacheLedgerV1().areas.find(id).partition`), as F121 did for the census and the dependency collector.
