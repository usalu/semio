## Round 3: `source-transient` fast retry in `🚦️ready`

Landed (details, hashes-free, in `T/landings.md` "Wave 1125 F1 round 3"): failure class `source-transient` (schema patterns: ENOENT lstat/stat/open under the checkout root, `Private Nx engine import missing`, `process.source.*` refusals, `Cannot find module`/`Could not resolve` of relative or checkout paths). The failure records the replica tree stamp read when the stage started (sorted names of `<store>/v1/heads`: they change on every replicated edit). The next attempt starts 15 s after a tree change (or after the stage's end if the tree changed during the run), never later than the normal back-off; with an unchanged tree or no store it is the normal back-off. The loop polls every 5 s for this class instead of 120 s. EN/DE refusal text added; a ready worker keeps Ready through such a failure (added to `refreshKeepingFailureCodes`).

Tests: new `🧱️source-transient` 4/0 (classification and retry rule equal to an independent Python implementation; decision law; EN/DE), existing ready tests 58/0, refresh 10/0, failure-log 7/0, tooling-compiler 5/0, stale-stage 15/0, stage-observers 4/0.

Design note: tree stamp = replica heads of the whole fleet, so on a busy fleet a worker can retry about every 15 s plus the run time; each run is bounded by the stage and the capacity gate.
