## 1. Diagnosis of `hdiutil resize … status 22`

- Which image: the **rust image** `.cache/b/r/fixed.dmg`, born by the creation step of the native image storage (`🧰️framework/🔨️modules/🏃️process/📦️artifacts/🏗️native-build/💾️storage/🧹️cleanup/🎛️command`): `hdiutil create` of a 64 MiB seeded image, then `hdiutil resize -size 98304m` stretches it sparse to 96 GiB. The failed birth is removed again, which is why `.cache/b/r` did not exist. Reproduced: `repo cargo --store=shared --configuration=prototype -- build -p semio-framework-pets-contract` (the flags are required; without them "explicit --store/--configuration") fails with `/usr/bin/hdiutil resize -size 98304m …/b/r/fixed.dmg exited with status 22` / `Invalid argument (22)`.
- Cause 1 (the one that bit): **`hdiutil resize` refuses any size above `free bytes of the host volume + current size`, although the file stays sparse.** By hand on a 64 MiB seeded image (script in the session): `hdiutil resize -limits` prints max 191164072 sectors = 91.15 GiB = free + 64 MiB (df showed 91 GiB free); resize to 8, 38, 80, 90, 91 GiB works, 96 GiB fails with status 22. The size comes from the policy `partitions.rust.capacityBytes = 96 GiB` and `elastic.rust` (need 96 GiB, 125 % wanted, cap 96 GiB, half of the free bytes), but `elasticCapacityV1` never goes **below the declared capacity** (`max(ceiling, minimumBytes)` with `minimumBytes` = declared 96 GiB at all three call sites). A host with less than ~96 GiB free (every 256 GB worker once the OS, Xcode, checkout, other images are on it) therefore always asks for 96 GiB.
- Cause 2: the admission before the creation (`nativeImageSparseAdmissionBytesV1`) only demanded `min(envelope, 4 GiB) + 64 MiB` free ("the backing only grows with its content"), which is wrong for the grow step, so the failure came late and opaque (status 22) after the seed image was already created.
- Not the cause (checked): stale attach (`hdiutil info` shows 4 healthy images l, o, d, t), leftover `.publication`/receipt (none in `b/r`), image format (UDRW raw, same as d), build policy quota (`maximumBytes` 192 GiB is not hit). d is 36 GiB (policy) and t 8 GiB, both fit.

## 2. Fix (code, schema, tests) and repair of this machine

- Schema `elasticPartition` gets a required `minimumBytes` (floor of a new elastic image, "the smallest image that still makes the partition useful"); policy: graph 6 GiB and products 24 GiB (= their declared capacity, behaviour unchanged), **rust 32 GiB** (declared 96 GiB stays the design target and the cap). `elasticCapacityV1`/`effectiveCapacityV1` receive `rule.minimumBytes` instead of the declared capacity at the three call sites (`📦️budget/🟦️.ts` budget + regrow check, `🔒️enforcement/🟦️.ts` strict storage). Existing images keep the size their receipt pins (unchanged law).
- Admission: `nativeImageSparseAdmissionBytesV1(max) = max + 64 MiB` (protocol field `admissionFreeBytes` removed from the schema). Not enough free space is now refused **before** any `hdiutil` call with `nativeBuild.image-host-free-insufficient` (EN/DE: "The disk of {directory} has {availableGiB} GiB free, but creating the fixed cache image needs {requiredGiB} GiB free … Free at least {missingGiB} GiB", German equivalent), code `refused`.
- Result on this host (91 GiB free): rule gives `floor(91.15 GiB x 50 %)` = 45 GiB; for 60 GiB free the floor 32 GiB; below ~33 GiB free the clear refusal.
- Tests: `🍎️image/🪶️sparse/🧪️tests` 5 pass, new: *the admission bound equals the free-space limit of the system `hdiutil resize` on a real seeded image* (independent oracle: the system tool; `resize -limits` max == free + initial extent within 1 GiB, a size 1 GiB below the limit resizes, 1 GiB above fails with `Invalid argument (22)` and our admission says no/yes accordingly) and *a host with too little free space is refused in English and German*. Budget tests 12 pass: rust rule has `minimumBytes < declared`, for every free size 34..633 GiB the elastic capacity fits (`capacity <= free - 64 MiB`) and is within [minimum, maximum] (plus two fixture rows for this host and a 60 GiB worker; agrees with the independent Python model in the test). The 3 other budget tests (`owned process probe…`, two nx-partition tests) need the `repo` invocation envelope and fail the same way before my change ("Original parent Script process invocation required").
- Repair of this machine by the code's own path only: the next `repo cargo …` call birthed the image: `.cache/b/r/fixed.dmg` 48 318 382 080 B (45 GiB, receipt `maximumPhysicalBytes 48318382080`), mounted at `.cache/b/r/m` (44 GiB free), 2.7 GB allocated after the first build.
