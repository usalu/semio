# Result H95: builds read a consistent source snapshot; broken-crates board (staged, not landed: 16:50 freeze)

Everything is staged in `T/🧰️scripts/H95/` (`B/` = new and changed files relative to the build module `B`, anchored patch scripts, `restage-and-land.sh`). Nothing live was edited. Tests ran in a scratch view of the tree (`scratchpad/H95/run`, symlinks to live except the staged files, tests copied as real files so they import the staged code).

## 1. Source snapshot (`B/📸️snapshot`, hook in the front door)
- **Capture** (`snapshotCaptureV1`): lists the source closure (roots `🧰️framework`, the Rust root `✏️s` without heavy members, root files; `target`, `node_modules`, `.cache`, `.git`, generated folders excluded), copies file by file (APFS clone / reflink via `COPYFILE_FICLONE`, else copy), atomically (hidden temp, rename), and only when the file did not move while copied (stat before/after, 3 retries). It then lists the closure again and recopies whatever moved until one listing equals the copy = one moment (`consistent: true`), at most 4 rounds; if peers never stop editing the receipt says `consistent:false` with example paths and the run still proceeds (bilingual warning). A lane's snapshot is refreshed in place (manifest `size:mtimeNs:ino` per file), so only changed files are copied and cargo's mtime-based incremental state survives. Crashed capture (manifest left `open`) is rebuilt from scratch.
- **Digest**: `sha256:` over sorted `path NUL content-sha256` (content only, not mtime; same sources = same digest on every machine); hashes memoised per file identity.
- **Root, short path, links**: lives under `landOverlayBaseV1(root)/s/<lane>` (the `~/.cache/semio/l/<6 hex>` short root of `repo land`); the workspace links of the overlay (node_modules bound to the snapshot, mirrored `.cache`, heavy members of `✏️s`, `.🧬semio`) come from `landLinkWorkspaceV1`, extracted from `landBuildOverlayV1` (staged gates patch `patch-gates.py`, land overlay behaviour unchanged, 29/29 land tests pass). Lane lock `<lane>.lock` (pid; a busy lane yields `<lane>-<pid>`, a dead owner's lock is taken over); prune after 24 h / 8 lanes.
- **Run** (round 1 text; round 2 below replaces the capture by the incremental base and makes `on` the opt-in for root mode; `snapshotRunV1`, hook `📸️snapshot/🚪️door` called first in `runBuildDoorMainV1`): for `cargo`, `test-file`, `typecheck`, `test` the same command line is started in a child with the snapshot as checkout (cwd mapped, `SEMIO_WORKSPACE_ROOT`/`REPO_ROOT` set, env `SEMIO_SOURCE_SNAPSHOT=<digest>`, `..._LIVE_ROOT`, `..._RECEIPT`), SIGINT/SIGTERM forwarded, exit code mirrored, digest printed in both languages at start and end; the child never captures again and nothing it reads moves, so there is no peer-edit retry or restart left to trigger. Result writers read the receipt with `snapshotReceiptOfV1` (field `sourceSnapshot`; wiring into the JSON results of `run/cargo/test-file` is NOT done, see unverified). A failed capture is announced and the command runs live. Opt-out `SEMIO_SOURCE_SNAPSHOT_MODE=off`.
- **`run`/`run-many`**: only with `SEMIO_SOURCE_SNAPSHOT_MODE=digest` (capture + digest, command stays in the live root). Reason: the Nx workspace stage and managed partitions are bound to the live checkout (H89 `workspaceBound` class: "Exact Original workspace required", "Source binding"), so a child with another root cannot mount them, and a capture only to print a digest costs 24 s warm. Running `run` fully on the snapshot needs the workspace Source binding to accept the snapshot root (H89 fix 2 did this for node_modules only); that is the follow-up.
- **Measured on the real tree (load 30-35, 10 cores)**: 51,644 files; cold capture 127 s and 143 s (two lanes), both 2 rounds consistent (a peer edited meanwhile; digests differ accordingly); refresh of the same lane 24 s (2 files copied, two listings of 51.6k files dominate, about 11 s each under load). `du` shows 8.5 GB logical per snapshot but `df` free space moved by about 330 MB after deleting it: clones share blocks. Cost versus the 12-13 min whole-command restarts of H61.

## 2. Broken-crates board (`B/💥️broken`, wired into `fleet status`)
- **Journal-driven**: reads the replica journal (`S/v1/origins/<origin>/segments/*.jsonl`, `hlc` = `<ms>-<n>-<origin>` gives the editor) from a persisted per-origin cursor (segment, byte offset; only complete lines, 4 MB per call); first read starts at the end of every segment (cold = whole workspace), an origin appearing later is read from its newest segment. Rust files, manifests, `Cargo.lock`/toolchain/cargo config map to crates via a manifest index (nearest `[package]`, all dependency tables) and to their transitive dependents; nothing changed = no check (journal read only).
- **Sweep** (`brokenSweepOnceV1`, resident `brokenWatchV1`, CLI `repo fleet broken sweep [--once|--watch] [--full]`): waits per crate for 20 s of quiet (forced after 180 s), captures a source snapshot (`lane broken-sweep`), runs `repo cargo --store=shared --configuration=prototype -- check --keep-going --message-format=json (--workspace | -p crate...)` in it at OS priority 19 with a 30 min limit (unit offload to the fleet is what `repo cargo` already does). A check that did not run (cancelled/timeout) keeps rows and cursor, so changes are replayed. Fault without compiler messages becomes a `(check)` row with the stderr tail.
- **Per crate**: `status` ok / broken / blocked (not reached: a dependency is broken) / unchecked; `firstError` {code, message, file, line} (primary span, paths relative to the checkout); `lastEditor` {origin, atMs, path} = newest journal entry of the failing file (6 segments look-back), else of the crate dir; `brokenSinceMs` kept while it stays broken; snapshot `digest` of what was checked; checking `origin`.
- **Publication**: atomic `S/v1/origins/<origin>/broken.json` (schema `B/💥️broken/🧬️schema`); reader `readFleetBrokenV1` merges all boards (freshest check per crate) into the fleet-status section `broken` (schema defs, facts, report, summary (first 10 broken), selection, sources, `--section=broken`, detail text en/de via `brokenFormatV1`). Subcommand `fleet broken` in the catalogue, help snapshot regenerated (only `root`, `fleet`, `fleet broken` rows change, both languages).

## Round 2 (stage only): incremental persistent snapshot, generation pin, key proof, default `digest`
Coordinator asked for commands under 30-60 s (round 1: 24 s warm, 130 s cold). Now O(changed files).

**Design** (`B/📸️snapshot/⏩️advance`, journal reader extracted to its own module `B/📜️change-journal`, used by snapshot and broken board):
- **One persistent base per machine** (`<snapshot folder>/main`, state file with generation, digest, journal cursor, last full verification, pending list; generation log `main.changelog.jsonl`). Advanced under a lock (a live holder is waited for, a dead one's lock taken over) from the replica journal (`S/v1/origins/*/segments`): only the paths the journal names since the cursor, plus the files named on the command line (verified against the live tree whatever the journal says), are looked at, copied (clone, stat before/after, never torn) or removed, in rounds until a journal read brings nothing new (cut consistent with the journal). No change = one journal read; a change = new generation, one log line, new digest.
- **Remote events that outrun the replica**: the journal entry carries the content `sha256` (checked: 145 of 145 recent entries equal the live file's hash). A put whose live file does not hash to it yet, or a delete whose file is still there, stays `pending` (persisted, 120 s) and is applied when the file arrives without a new event; the snapshot never claims the new state before the checkout has it. Receipt reports `pending` and the `lagSeconds` of the newest event.
- **Safety net**: a full listing verification runs when there is no base/state, no fleet store, after 30 minutes since the last one, or with `SEMIO_SOURCE_SNAPSHOT_FRESH=1`; it finds an edit whose journal event was lost (tested). Edits made in the last replica second may be missing from a warm snapshot unless the command names the file (test-file path arguments are always verified); this is the stated cost of not listing 51k files.
- **Generation pin per run** (`snapshotRefreshLaneV1`): each lane keeps a fixed-path run root (the compiler's path-based state survives) that is brought to a generation by cloning only the paths the log names between its generation and the wanted one; a lane that is new or fell behind the (compacted, 500 generations) log is cloned whole once. The lane root is not touched again until that lane is refreshed, so a run holds its generation while the base advances (tests: lane-a stays on x=1 while lane-b and the base are at x=7). Absolute links are stored location-independent (`link:@root/...` in the hash) and rebound per tree, so the digest is the same wherever the snapshot lives (tested with another base folder).
- **Modes** (`SEMIO_SOURCE_SNAPSHOT_MODE`): `off`; `digest` (DEFAULT): only advances the base and reports its digest, never runs in another root, never builds a missing base (no 130 s surprise; says so once per command when explicitly set); `on`: root mode for `cargo`/`test-file`/`typecheck`/`test` (child on the pinned lane root), `run`/`run-many` stay digest, builds the base when missing. `repo fleet broken sweep` doubles as the keeper: it builds and advances the base every poll.

**Measured on the real tree (load 30-40, real fleet store, scratch folder)**:
| step | wall |
|---|---|
| base build / full verification (51,644 files, listing) | 54 s (re-verification with the base present), 127-143 s cold (round 1) |
| warm acquire, idle (journal read only) | 4-27 ms |
| warm acquire with 9-10 real changed files (peers' edits, 2 journal rounds, includes loading and saving the 8 MB manifest) | 0.35-0.55 s |
| first acquire of a NEW lane (whole clone of the base + workspace links) | 60 s, once per lane (not per command) |
| later acquire of an existing lane | same as warm acquire + clone of the changed files |
So with the base present every command pays under 1 s; the first command of each lane pays 60 s once; the base is built once per machine (by `MODE=on` or the sweep).

**Unit-cache keys are path independent from a snapshot root (proof, `B/📸️snapshot/🔑️unit-key/🧪️tests`, 3/0)**: the real recorded unit of the unit cache portability test (`semio-framework-hash`, prototype profile) keyed with the checkout at the live root and at the root of a snapshot lane (real shape `<overlay base>/s/<lane>`, source bytes read from the snapshot copy and equal to live): `remoteKeyV1` equal, `localKeyV1` equal, the portable text of arguments and environment equal and free of the snapshot path, while the raw machine-bound `unitKeyV1` differs (so the portable layer is what makes it equal); source bytes, profile and a feature still move the key from the snapshot root. Declared limit (test 3): a unit whose bytes embed a real path (the `path-dependent` class, 386 declines in the 00:00 counters) is keyed on that path too, so from a snapshot root it shares only with builds at the same snapshot root, never with the live root. Not run: a real `repo cargo` under the snapshot root with unit-cache hit counters (needs a build, frozen). **Therefore `on` stays opt-in; default is `digest`. Enable by default only after one real `repo cargo -- check -p <crate>` with `MODE=on` shows the same hit count as with `MODE=off`.**

## Unverified / limits (round 1)
- `repo cargo` in a snapshot root was never run for real: unit-cache keys and offload mapping may depend on the absolute checkout path (the `unmapped-path` / `not-portable` declines). Gate before the apply: one real `repo cargo -- check -p <small crate>` with and without `SEMIO_SOURCE_SNAPSHOT_MODE=off`, compare unit-cache hit counts; if hits drop, set `commands.cargo` to `digest` in the policy (one line).
- `repo test-file` / `typecheck` in the snapshot: same path as the `repo land` gates (proven there), not run through the new hook.
- The digest is printed and passed on, but the JSON result of `run/cargo/test-file` and the MCP tools do not carry `sourceSnapshot` yet (helper exists).
- `run`/`run-many` full snapshot root needs workspace Source binding (above). Warm capture 24 s is dominated by two full listings; a journal-hint shortcut (skip listing when the journal shows nothing for the roots) is not built.
- Sweep: `wrapper` for `repo scheduler run --priority background` left empty (OS priority 19 used); `repo cargo` passes the JSON message stream through only as far as tested with plain cargo; a progress line mixed into stdout is ignored by the parser. Cold sweep on the real workspace (about 1,000 crates?) never ran; the 4 MB journal read budget and the workspace threshold (40 crates) are untuned.
- Editors reflect journal origins; a machine whose edits are not in the journal (before first replication) shows `unknown`.
- Windows not run (symlink creation, `setPriority`).
