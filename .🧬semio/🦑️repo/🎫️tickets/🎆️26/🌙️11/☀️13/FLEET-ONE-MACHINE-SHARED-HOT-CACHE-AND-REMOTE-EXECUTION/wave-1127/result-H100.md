## The contract (new member `🏗️build/🩹️cache-repair`, schema first)
`🧬️schema/🔣️.json` declares 11 record kinds, 9 typed reasons (`missing empty truncated malformed digest-mismatch seal-mismatch unsealed structure unreadable`, each with an English and a German text), the quarantine bounds (256 records, 256 MiB, 128 MiB per record, 1 MiB rotating `log.jsonl`) and the write/scan limits. `🟦️.ts`:
- `readVerifiedRecordSyncV1` / `readSealedRecordSyncV1`: read, verify, and on any fault move the record into `<root>/.quarantine/<kind>/` (bounded, oldest out), log one typed bilingual row, answer a miss. Never throws; a missing file is a plain miss without a row; links are removed, never followed; an unwritable quarantine falls back to removal. `mode:"remove"` + `machineQuarantineRootV1()` for stores with closed names (graph images).
- `sealRecordV1`/`openSealedRecordV1` (sha256 of the record without its `seal`), `verifyFileDigestSyncV1`/`verifyFileDigestV1` (digest-named files, streamed, hashed once per (size, mtime, inode) via a stamp, so a hit costs a stat), `verifyCacheRecordFileSyncV1` per kind, `classifyCacheRecordPathV1`, `verifyCachesV1` (scan with progress, cancellation, entry bound).
- `writeDurableSyncV1`/`writeDurableV1`/`writeSyncedSyncV1`: temp file beside, write, fsync, rename, directory fsync; a full disk removes the temp file and keeps the old content.
- `🌊️watermark`: `cacheWatermarkV1(total, free, need)` = the H82/H47 rule (guard floor and low-water mark of `🖼️image-guard`, same numbers: 771 MB / 1311 MB tests) as `ok|relief|floor`; `mayForceDetachV1`/`refuseForceDetachLineV1`.
- Rollout knob `seal.required` (schema, now `false`): entries written before sealing are accepted by shape; every new write is sealed. Set it to `true` one release after every worker runs the new writers (then an unsealed record is a miss).

## Per record type: before -> after
| Record | Read before | Read now | Writer now |
|---|---|---|---|
| Unit entry / build script run (`e/`, `r/`) | JSON.parse, torn = silent skip, flipped field accepted | sealed + shape + key==folder, any fault quarantined (typed) and a miss; prune quarantines instead of deleting silently | sealed, `writeDurableSyncV1` (also the spilled entry) |
| Objects replayed by an entry (host CAS) | `existsSync` only: a cut `.rlib` was copied into the build (the likely 6 h "no wasm" cause) | `intactCasObjectSyncV1(sha, bytes)`: recorded size (cut/empty) + digest once per machine; damaged object quarantined, entry is a miss, next publish heals | fsync before rename; an existing object of the wrong size is replaced (was: kept forever) |
| CAS object (sync + async store) | no check | `read`/`get`/`link` verify; damaged = miss + quarantine in `<cas>/v1/.quarantine` | `ingest` `handle.sync()`, `place` replaces a damaged target |
| Remote cache values | none | cas blob = digest once; action result = protobuf decoder (empty is a legal message); task archive = non-empty; damaged = miss, forgotten from the index, quarantined | `put` `handle.sync()`; reference and `retired.json` and sidecars `writeDurableV1` |
| Graph generation files (manifest, fragments, facts, frontiers) | already verified by name (`GENERATION_CORRUPT` = rebuild) but `ifAbsent` kept a corrupt file forever | same, and a content-addressed `ifAbsent` write that finds other bytes removes it (logged) and writes again; custody `ifAbsent` files keep their meaning | file port fsync before rename |
| Graph publication archive (`pa/`) | exists + hash mismatch = hard "changed" error (build failure) | mismatch removes + logs and rewrites | `writeDurableV1` |
| Dependency generation receipts | already sealed (`receipt-invalid` mismatch) | unchanged; `doctor --repair` classifies `*.receipt.json` and a test shows the product parser and `verifyReceiptBytesV1` reject the same damage | n/a (directory-atomic) |
| Closure records (`selected/`, `canonical`, `authority`) | custody-guarded, already refuse-by-proof (H32) | scan only (JSON object); no reader changed | untouched |
| Nx local cache (`<hash>.commit`) | Nx's own reader | scan: commit marker + folder + `code` + `terminalOutput` | Nx |
| Sidecars / retired / volatile memos (`tc-`, `sr-`, cost, elastic growth, seal log trim) | torn = wrong value | n/a | `writeDurableSyncV1` |

## Atomic-writer audit

The other 173 are a closed register `🩹️cache-repair/🧪️tests/⚖️atomic-writers/🔣️allowlist.json` with a law test: a new rename-without-fsync file fails, a file that became durable must leave the list, the list is sorted (regenerate: `T/🧰️scripts/H100/regenerate-allowlist.ts`). Not all 173 are cache records (stamps, journals, control files); triage by owner is the follow-up. Toolchain installs are directory-atomic with the receipt written last (not fsynced: power loss only; ENOSPC throws before the rename).

## Cleanup before full, never force an open image
- `RemoteCacheStoreV1.relieveVolume`: before every new write the volume is measured (`statfs`, injectable `volume`); below the low-water mark a collection that frees the shortfall runs (at most every 2 min, at once below the floor), a write still below the floor is the typed `capacity` outcome: nothing is ever written into a full disk. Already low/high-water driven and unchanged: CAS (partition fractions), unit cache gc (`gcPressureV1`), ready sidecar (H47/H82).
- `hdiutil detach -force` existed in 3 places: `incrementalDetachMountsV1` and the sandbox `detachDiskImagesUnderV1` / `sweepLeakedSandboxImagesV1`. All now detach politely, read the holders with `lsof` and force only when none holds a file open (holders unreadable = no force); the incremental runner refuses with a bilingual line naming the holders. Production image retirement already never forced (`🔁️detach`, H63/H64 guards).
