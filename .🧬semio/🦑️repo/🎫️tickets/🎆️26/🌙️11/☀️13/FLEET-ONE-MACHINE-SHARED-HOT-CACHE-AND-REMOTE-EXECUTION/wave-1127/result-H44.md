# H44 result: test offload takes load off the coordinator (load verdict, parallel dispatch, streaming, retry window)

Landed 06:00 (slot), lock test-file; kept scripts `🧰️scripts/H44/` (apply.py = the anchored patch, relayer.sh + run.sh + overlay-plugin.ts = tests against a scratch overlay before landing, proof.py, stream-probe.ts). Landings entry in `landings.md`.

## What changed
1. Load-aware gate (`🔬️checkout-test/🚦️gate`): in `auto`, when the host-capacity verdict is `admit`, the CPU load per core (1-min loadavg / cores) decides: at or above `load.perCoreAlways` 1.5 the file always leaves (reason `host-load`); below `perCoreMeasured` 0.75 it stays; in between it leaves unless a fresh (1 h) local and remote duration of that file are both known and remote >= 0.8 x local. Durations are recorded after every run (`offload-test-measure.json` in `.cache/f/offload-test`, schema `Measures`, bounded to 256 files, atomic). Numbers live in the schema policy `load`.
2. Parallel dispatch (`🔬️test-file/🏃️run`, `🌐️remote`): up to `limits.maximumParallel` (4) files out at once; a shared claim set keeps two files of one run off one machine, a file for which every Ready machine is claimed runs here at once (no retry wait); local fallbacks run while other files are out; remote results are consumed in route order, rows are sorted back to route order, so the aggregate is deterministic whatever the width. `--bail` and a width of one keep the old sequential behaviour.
3. Streaming (schema-first, existing wire = REAPI action cache): the worker writes the stderr of the running test file as pieces (`Chunk` schema: nonce, index, offset, origin, base64 data, last) under the cache key SHA-256(`checkout-test-chunk/<nonce>/<index>`) as ordinary ActionResults (`stderr_raw`); the requester follows them while the action executes, prints complete lines prefixed `[i/n origin]` and prints only the rest at the end (same decoder, no split character). Every fault (write refused, pieces used up, 3 s drain) just means the output comes at the end as before.
4. Retry window 8000/3000 (policy constants).

## Coordinator note: "Original Script deadline refused" on an offloaded units test (landed 06:26, overrun, lock test-file)
Not reproduced (all workers had no headroom, file ran here 141 s, 129/0). Cause by reading: the error comes from `🏃️process/🧭️routing/📥️invocation` (`remaining > policy.maximumElapsedMilliseconds`): inside the worker's own `repo test-file` the nested budget is stretched by the worker's load a second time and can come out smaller than the outer funded deadline when that load falls between the two reads; a loaded worker makes this likelier than the coordinator. The remote action itself already carries the caller's stretched budget (action timeout = budgets + 120 s). Fix landed in the requester: a remote row that failed with `deadline refused/exhausted` is an infrastructure refusal, not a verdict, so the file runs here (`remote-failed-local-redo`); a real failure stays a verdict. Test 11/0, typecheck passed. NOT fixed at the root (process-area: make the nested stretch never smaller than the parent's remaining deadline), a follow-up for a process slot.
