## 3. `🔁️verdict-reuse` (test result reuse by input digest)
- Key = SHA-256 of the canonical JSON of: test file digest, import closure (string-literal specifiers, relative resolved on disk, bare ones kept when they resolve into the checkout outside node_modules, else listed as externals covered by the lockfile digest, unresolved listed), **all files of the test's own member** (parent of `🧪️tests`; covers oracles/fixtures/spawned module files read at run time), declared fixtures (files or dirs), toolchain (runtime, version, `bun.lock` digest) and envelope (platform, arch, runner; other keys refused). Paths are checkout-relative, so another machine/location gets the same key (tested). Bounds (512 files, 32 MiB) make a test `ineligible` (always runs) instead of wrongly keyed.
- Store port `{read(hash),write(hash,bytes)}` = the shape H44's chunk transport already uses on the fleet action cache; address = SHA-256(`test-verdict/v1/`+key). Directory port included (hot local cache, atomic). Record carries its own checksum.
- Rules: only a passed verdict with >= 1 test and 0 failures is stored; lookup refuses failed/empty/corrupt/foreign/expired (24 h) records (reason in en/de); store down or slow (2 s) = miss, never blocks; opt-out `--no-reuse` or `SEMIO_TEST_REUSE=0|off|false|never`; key recomputed after the run, a file edited during the run is never filed under the old key; reused row says which machine and how old.
- Tests 8/0: key equals Python model (with and without fixtures), import scan equals `typescript.preProcessFile` (third-party oracle), 12 sensitivity cases (changes with test/closure/member/fixture/toolchain/envelope; unchanged for unrelated files, undeclared fixtures, other checkout location), bounds, store semantics, flow with the directory port.
