## What changed (landing in T/landings.md "Wave 1127 H21")
- New member `graph/📥️load/🗞️journal-clean` (schema `🧬️schema/🔣️.json`, test `🧪️tests`): `journalCleanRowsV1`. A row of the admission memo skips its probe when (a) the memo carries an attestation (`<scope>.verified.json`, atomic temp+rename: memo identity size:mtime:ino:rows, journal epoch, seq) that every row held at that cursor, (b) the change journal (exact, fenced, `connectChangeJournalV1`) reports no change at, above or below the row path since that cursor (a directory row of kind `m` changes only its own entries, other directory rows their subtree), (c) the path is under the root and not journal-excluded, (d) the kind is a path fact (file, exists, stat, lstat, fileExists, directoryExists, readdir, readdirNames), (e) the row equals the memo's own row. Everything else is probed as before. The cursor is taken before any probe, so a change during the probe shows in the next question; refusal, epoch change, foreign memo, timeout (5 s) or a missing journal means every row is probed (never a hang, never a wrong skip).
- Observation `observationsHold` / `observationsHoldWithinRoundV1`: optional last parameter `clean(row)`; `buildGraphSourceFactsHoldV1` forwards it. `load/🟦️.ts` `inventory`: takes the cursor at attempt start, passes `clean` to the memo-check and to the per-owner holds (so a memo that is stale in a few rows still skips the rest in the owners round), seals the attestation after a reused memo and after a published memo, prints `[graph-journal] {phase,reused,skipped,checked,changed}`.
- Resume after stall/kill/restart: memo (rows + owner facts) and `oc` checkpoint persisted per attempt as before; the new attestation persists "verified up to cursor", so the next process (new pid, after a landing restart) asks the journal what changed and probes only that.

## (2) Membership hash journal-vouched (done, measured)
- `buildGraphMembershipV1(..., reuse)`: `reuse.cached(entry)` returns the stored record of an entry the journal vouches for (no lstat), `reuse.learn` keeps probed records; the hash is computed from the same records, so the digest is identical (test: equals a fresh hash and an independent CPython sha256 over `[file,"file",mode]` records, after a reported chmod). Persisted per scope in `<scope>.membership.json` (records + cursor taken before the first probe + link state), written atomically after a successful hash; `[graph-journal] {phase:"membership-hash",reused,probed}`.
- chmod is reported by the journal as an `m` row of the file (verified live on this Mac), so a mode change is seen.
- Symbolic-link directories: a change below a link target is reported at the target, so nothing under a link is vouched for (new, also for the memo check). `linkIndexV1` probes each directory once (async, 128 parallel), persists `checked`/`linked` with the cursor, and re-probes only directories a change touched or sits above.
