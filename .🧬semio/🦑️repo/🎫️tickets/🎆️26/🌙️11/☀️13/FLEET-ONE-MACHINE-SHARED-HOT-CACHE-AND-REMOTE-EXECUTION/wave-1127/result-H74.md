## What it does
stage (`checkout`/`delete` keep base hashes) -> stale-base check (`--rebase`: 3-way merge by `git merge-file`) -> overlay (copy-on-write clone of `🧰️framework` in the machine cache, staged files applied; live tree only read) -> gates against the overlay -> slot (wait with progress, `--no-wait` queues, `--outage` ignores, 15 min overrun for a landing that began in the slot) -> area locks (alphabetical, apply only) -> atomic apply -> rollback point -> `landings.md` entry. Gates: debug lines (H75 law, scoped to the changeset's files), dangling imports (TS port of the coordinator's Python scanner, checked against it; also importers of deleted files), `repo typecheck` (written scripts + importers, incremental, overlay root), `repo cargo check -p` per touched crate, suite route law (when a suite table or project target changes), declared tests of touched members (test fixtures run the `🧪️tests/🟦️.ts` beside them), optional `--bench` (`repo bench latency --strict`). A test that fails in the overlay exactly as it fails on the live tree (same normalized signature) is reported "pre-existing" and does not refuse; anything new or different does (found live: H75's `🩺️diagnostics/🧪️tests` is in no suite and reds the route law today).

## Proofs (tests `🚉️land/🧪️tests/🟦️.ts`, 26/0 in the stage, also run inside the overlay by the gate)
- Stale base refused (changed file, new-file collision, delete of a changed file); live tree, landings and locks untouched.

## Unverified / limits
- Offload to the fleet: not done for overlay gates. The checkout-test offload runs the file from the worker's replica of the live tree, which would test the old code; it is switched off inside the overlay (`SEMIO_TEST_FILE_OFFLOAD=never`). Real offload needs a delta channel (overlay files by hash in the remote cache); gates run locally in sequence.
- The Rust gate was proven only with a fake port; the default (`repo cargo --store=shared --configuration=prototype -- check -p <crate>` in an overlay that also clones `✏️s`) was not run: it needs a cold overlay target through the unit cache. Treat the first real Rust landing as the test.
- No-half-state guarantee is per file (rename) plus the generation seqlock for readers that opt in; a reader that ignores the generation can still see old and new files together for the few ms of the rename phase (ordering guarantees only that no importer sees a missing new file). Workers' source-transient retries cover that window.
- The overlay clone is APFS/reflink only for speed; other systems copy (slower, same result). Windows was not run.
- Overlay tests run with the live `.cache` and `✏️s` linked in; a test that writes to them writes to the live ones.
- A test run once hung >2.5 min under load 55 (not reproduced, 3 later runs 3-6 s).
- The 3-way rebase needs `git` (merge-file only, no repository access).
