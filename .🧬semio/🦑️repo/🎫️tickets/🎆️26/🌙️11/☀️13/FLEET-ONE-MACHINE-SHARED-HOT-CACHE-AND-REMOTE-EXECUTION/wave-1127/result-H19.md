# H19: robustness of cargo compile admission on low-resource workers (L7-L10)

U = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/⚡️caching/🦀️cargo/🗃️unit-cache/`, A = `🧰️framework/🔨️modules/🏃️process/📦️artifacts/🏗️native-build/🎟️admission/`.

## Status of the four items (confirmed in code first)
| Item | Open in code? | Root cause | Fix |
|---|---|---|---|
| L8 ~30 wrappers hold :6094 while cargo is at 0 % | yes, three silent holders remained | (1) a wrapper kept its fleet claim (renewed every 8 s) while it queued up to 11 min for the single compile slot, so other machines waited for a unit nobody compiled; (2) `obtainFleetUnitV1` let every job of a machine long-poll a remote holder (up to 20 min each), so all cargo jobs could park on remote claims; (3) `acquireAloneV1` (`MAX_SAFE_INTEGER`) and `acquireLightSlotV1` had no deadline at all. The :6094 connections themselves are idle keep-alives (F69), the held things are claims and long polls. | see below |
| L9 broker never answered admit | partly | F71 landed heartbeat, stall, queue, estimate and growth bounds. Still silent: a RUNNING unit whose scheduler wedged kept its booking and the single `running` slot for ever; the `probe` estimate had no bound (admit had). | running-silence watchdog, bounded probe estimate |
| L10 Windows reader thread | yes | closing a named pipe does not wake a thread in a synchronous `ReadFile`, so a dropped attempt kept its broker-side request | `CancelSynchronousIo` on the reader thread, repeated until it ends |
| L7 growth for a waiter | yes | `rescueStalled` returned whenever `running.size>0`, so a waiter queued beside a long running unit never asked for growth when the driver's own memory grew | rescue now also beside running units, only for the driver-overhead part |

## What changed
- `U/⏳️admit/🟦️.ts` (new): `awaitCompileAdmissionV1` (headroom, then slot or whole host; every wait bounded, bilingual line on every timeout, `claim` outcome) and `whileClaimParkedV1` (gives the fleet claim back after `slot.parkAfterMilliseconds` of waiting, takes it again after the wait, also when the wait fails).
- `U/📜️script.ts`: `compile()` goes through it; the offload light slot is bounded (`slot.lightMaximumWaitMilliseconds`, then local compile with en/de line, fallback `light-timeout`); `hold` declared early so the compile closure sees it.
- `U/🔒️lock/🟦️.ts`: `acquireAloneV1` and `acquireLightSlotV1` take `maximumWaitMilliseconds` (throw `SlotWaitTimeoutV1`, leave no claim or ticket); new `tryAcquireRemoteWaitV1` (`await-<n>` places, never waits).
- `U/🛰️fleet/🟦️.ts`: `FleetHoldV1.park()/resume()` (release the claim, bounded; re-claim, `"lost"` when another machine took it, then the hold counts as lost so the uploader does not claim it); `obtainFleetUnitV1` takes one of `claim.maximumRemoteWaiters` (4) places before it long-polls a remote holder, else compiles at once with reason `waiters-full`.
- `U/🏗️buildscript/🟦️.ts`: build-script runs bound both slots the same way and park their claim while waiting.
- Schemas: `U/🧬️schema/🔣️.json` (`slot.aloneMaximumWaitMilliseconds` 900000, `lightMaximumWaitMilliseconds` 600000, `parkAfterMilliseconds` 3000; messages `slotTimeout aloneTimeout lightTimeout headroomTimeout claimParked claimLostAfterPark`, en+de), `U/🛰️fleet/🧬️schema/🔣️.json` (`claim.maximumRemoteWaiters` 4, `parkMaximumMilliseconds` 5000).
- `A/🟦️.ts`: running-silence watchdog on the 10 s tick (`bounds.runningSilenceMilliseconds` 20 min, en/de `waits.silent`; the scheduler reports `rss` every second); `rescueStalled` generalised (need = predicted + running + driver memory; no growth when the running units alone exceed the grant, so the grant still bounds parallelism; skipped for `serial` units so a refused growth is not asked again every tick); `estimate()` shared by admit and probe (probe is now bounded by `predictMilliseconds`, the connection is dropped and the wrapper proceeds with `"none"`).
- `A/🦀️.rs`: `Broker` keeps the reader `JoinHandle` and a stop flag; on drop (Windows) `cancel_reader` calls `CancelSynchronousIo` up to 50 x 20 ms until the thread ended (a cancel before the read started finds nothing, hence the repeat). Unix unchanged (socket shutdown).
- `A/🧬️schema/🔣️.json`: `bounds.runningSilenceMilliseconds`, `waits.silent` en/de.
- Tests changed: `U/🧪️tests/⌛️headroom-first` source-order law now reads the new member.

## Proof
- `U/🧪️tests/🪢️wedge` (new, 10 pass, run 4 times): 30 fake wrappers behind a compile slot whose live holder never releases it, fake fetch cache that stalls every long poll: after the park delay every claim is given back and no request is open (sampled while all 30 wait), all 30 end at the bound with the en/de line, tickets cleaned, claims taken again and released; free slot never parks nor needs the broker; claim stolen while parked is reported and the hold is lost; 30 wrappers against a holder that never answers: at most 4 long polls open, the others compile at once (`waiters-full`), all places given back; real TCP server that accepts and never answers: 30 units compile within 15 s; alone/light/remote-wait bounds; broker that never admits ends at its bound with en/de line; failing wait still resumes the claim; source laws (no unbounded wait left in wrapper or build script).
- `A/🧪️tests/🐕️watchdog` (new, 5 pass): silent running unit dropped and the queued unit runs (en/de log), a reporting unit stays, probe estimate bound, growth beside a running unit (ask equals the independent arithmetic), no growth when only the grant bounds the parallelism.
- Rust: `rustc --edition 2024 --test` 16 pass (2 new: `blocked_reader_is_cancelled_until_it_ends`, `dropped_connection_ends_its_reader`); non-test build no warnings; `--target x86_64-pc-windows-msvc --emit=metadata` clean for build and test cfg.
- Neighbours green: unit-cache headroom-first 5, slot-deadline 3, alone 2, fleet fallback 4, stale 1; admission deadlines 6, waits 6, growth 8, cold-class 6, parent 5, sibling 2, probe 3, cold-external 5. `repo typecheck` passed (54 / 32 / 24 files), dangling-imports 0.

## Not verified / notes
- `A/🧪️tests/♻️replay` 3 pass / 2 fail (`cached units are recorded...`, `physical charge freezes...`): the first reply is `admitted:false`; these tests start the broker without an `available` override and read the real host (coordinator swap is near full, warden holds), not code of this lane. Not rerun on a quiet host.
- The Windows `CancelSynchronousIo` path is type-checked for the MSVC target but never executed (no Windows host in this lane). The repeat loop is proven by the unit test with a fake cancel.
- No live fleet run: the claim-parking is proven with a fake fetch cache and a real hung TCP server, not against the fleet service on :6094. Parking releases the claim, so an idle machine may take the unit meanwhile; after resume a lost claim means a possible duplicate compile (first stored result wins), counted by the `claim-parked` event, not by a counter.
- The wrapper does not re-check the fleet cache after a long wait (another machine may have stored the unit meanwhile); it resumes the claim and compiles. A re-lookup after `claim:"lost"` is the obvious follow-up.
- `U/🧪️tests/🟦️.ts` (main unit-cache suite) and fleet `🧷️session`/`⚡️pipeline` were started in the foreground-turned-background run and had not finished when this was written (real cargo builds under load 50+); result below if it arrived.
- Locks: the two small follow-up edits of `⏳️admit/🟦️.ts` (park after headroom, free-slot ordering) were written moments before I took the lock again (landing without the lock for ~2 minutes, only my own new member); everything else under locks `caching-cargo` and `process`.
