## Clean long-term improvements for development speed
1. **Run agents' heavy work on the fleet, not the coordinator.** Make `repo test-file`, `repo cargo`, `repo typecheck` offload by default when the caller is an agent (done for tests; extend to typecheck and single-crate cargo). Longer term: agents themselves run on workers (one agent per idle 16 GB Mac), the coordinator only coordinates.
2. **Landing train instead of free landings.** A gate lane batches staged patches at fixed slots, runs one product verification per batch, lands atomically, and records a rollback point. This removes the half-edit and folder-move outages and the Ready dips.
3. **Separate "inference-relevant" from "code" changes in the graph environment**, so landings that don't touch inference inputs never invalidate whole reads; publish graph generations incrementally (per owner) instead of an hours-long all-or-nothing seal.
4. **Per-file, journal-vouched memos everywhere** (analysis, resolve rows with consulted dirs, membership hash, inventory) so every command costs O(changed files), not O(repo).
5. **Hermetic tests by construction**: destructive storage ops require a root capability; tests only get sandbox roots (H64); suite tables generated from the tree so no suite row/target drift.
6. **Determinism contract as a first-class schema** (H55) with a law test per toolchain bump, so cache sharing stays correct without per-incident hunts.
7. **Windowed metrics as the only source of truth** for findings and dashboards (H5): no cumulative counters in alerts; per-reason rates make regressions visible within 15 min.
8. **Remove host noise**: provisioned git per platform (guards drift), hostnames from origin ids (USER sudo step), Defender exclusion on Windows (USER), and a coordinator that doesn't also run IDEs and archivist signing.
9. **Smaller briefs, shorter lanes**: lanes above ~300k context made rule slips (locks, slots); retire at ~250k and continue in a fresh lane with a 10-line handover — it already worked better in this wave.
