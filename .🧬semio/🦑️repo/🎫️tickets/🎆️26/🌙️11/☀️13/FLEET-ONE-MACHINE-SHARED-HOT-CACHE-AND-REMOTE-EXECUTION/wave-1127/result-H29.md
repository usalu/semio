# H29 result: test files offload to an idle Ready worker

## Problem and measured motive
On the coordinator Mac (load 55-66, swap about 12 of 13 GB) test files time out ("Native lease readiness expired", "Original Script deadline refused" after 1920 s) while 5-9 workers sit Ready and idle. Remote execution offloaded compile units only. Same file, same code, measured live in this lane: `🔬️test-file/🧪️tests/🟦️.ts` (19 tests) takes 100.1 s of test time on the coordinator and 14.4 s on g1-m06; `🚪️gate/🟦️.ts` (4 tests) 8.8 s here, 0.8 to 2.2 s on g1-m01, g1-m06 and g1-m12.

## Design (schema first, one more kind of action in the existing REAPI path)
- New member `🏗️build/🌐️remote-execution/🚀️offload/🔬️checkout-test`; `🧬️schema/🔣️.json` is the contract (policy, `Request`, `Result`, bilingual texts):
  - `Request` is the one input file of the action (`checkout-test/request.json`): `nonce` (every request is its own action, so the scheduler never answers a test from its result cache), `file`, `fileSha256`, `cut` (the replica cut this machine has applied, per origin segment and bytes, from its own `attest.json`), `language`, `budgetSeconds`.
  - `Result` is the standard output of the action: `origin` (who ran it), `cut` (what it held), `result` (the structured `repo test-file --json` document). The output of the run is the standard error of the action, the exit status the exit code (0 passed, 1 a file failed, anything else is a fault).
  - program `@checkout-test:v1`; platform: the machine kind of the requester, `semio-checkout-test=1` (offered by every worker that is a fleet member and has the `repo` binary), `semio-offload=if-idle`, `semio-origin=<requester>`, `semio-pin=<origin>`.
- Requester (`🔌️client`, port `🔬️test-file/🌐️remote`): (1) host verdict of this machine through the very gate of the compile units (`offloadGateV1` with one always free slot, always worth a round trip, no slot queue, no broker: the file is offered exactly when the host-capacity verdict is `wait`, reason `host-wait`; a calm host keeps it, `local-slot`; verdict remembered 10 s per run); (2) the Ready machines of this platform from the readiness records (`readReadyWorkersV1`, liveness `ready`, never itself, in random order); (3) each tried pinned and `if-idle` one after the other, at most 4: a machine without room, not Ready, behind or without the capability answers at once and the next is tried; when all had no room they are asked again every 4 s for at most 20 s; (4) otherwise the file runs here.
- Worker (`👷️worker` branch + `🔬️checkout-test/👷️worker`): validates the bare action, reads the request and refuses (outcome `refused`, reason `not-ready`, so the scheduler places it elsewhere) when its own readiness record is not `ready`, when its replica cut does not cover the requester's cut (waits up to 8 s for the replica to catch up, never guesses) or when its copy of the file has another SHA-256. Then it runs `repo test-file --json -- <file>` in its own checkout with `SEMIO_TEST_FILE_OFFLOAD=never` and the stage environment of the machine (`readyStageEnvironmentV1`): the same hermetic sandbox, birth, budget and managed Python as locally. The command runs through the worker's `execute` (own process group, whole tree killed on cancel and on the action timeout, memory metered).
- Attribution: the row carries `ranOn` (schema `Row.ranOn`); text mode prints `passed  <file> (<suite>, <s> s, 19 pass, 0 fail, ran on g1-m06)` (de: `lief auf g1-m06`) and the notice `[test-file] <file> ran on g1-m06 (14.4 s)`; the worker's output is printed when the file ends (not live).
- Fallback (bounded): mode `never`, calm host, no fleet, no Ready peer, no room, refusal, replica behind, lost operation, deadline, unreadable or schema-violating answer, answer without the file: the file runs here with `[test-file] <file> runs here, the remote run was not used: <reason>` on stderr. A file that FAILED on the other machine is a verdict and is not run again.
- Cancellation: Ctrl-C/SIGTERM aborts the request (`run.cancelled`, exit 2), the stream closes, the scheduler cancels the executing task (linger), the worker aborts and kills the process tree.
- Mode `SEMIO_TEST_FILE_OFFLOAD=auto` (default) | `never` | `always` (offer whenever a Ready peer exists, no host verdict). Documented in the schema description of the policy; NOT in the operations catalogue (a catalogue note changes the help snapshot and the `noteCount` fixture of `⚙️operations`, left to the owner).

## NOT verified / open
- The big file did NOT run remotely under the pinned code: in every attempt after round 2 all candidates answered "No other machine has headroom" (workers restarting after my landings, then the load report `headroom` false; at most one probe in four found room), the retry window ended and the file ran here (19/0, same rows, 128 s, 92 s). Remote proof of the big file is the round-1 run above; the pinned path is proven live only with the small file and with the real-scheduler test.
- Fallback costs time: when every Ready peer is full the retry window adds up to 20 s before the local run. `wait.retryMilliseconds` 20000 / `pauseMilliseconds` 4000 in the schema are a guess; 8000/3000 is probably better (a constant in the policy schema lands in the sidecar closure, so it was not landed again: every worker would restart once more).
- `auto` was never seen to offload live: the host verdict of the coordinator was `admit` at every sample (305 ms, `fits`) in spite of load 45-66; the gate is proven by vectors and tests only. Under a real `wait` the Ready peers need headroom too.
- Output is delivered when the file ends (REAPI has no stream for the output of an action); progress is the stage lines (`waits for a machine`, `is running on another machine`).
- Windows (m05) and Linux (m04) workers: capability and `repo` binary lookup are by the ready module, nothing ran there.
- Cancellation: process kill on the worker is proven by the real-scheduler test, not observed on a real worker.
- NOT done: the suite runner (`runProcessTestSuiteV1` runs files through `runOwnedBunFilesV1` with its memory model; the port `createTestFileRemoteV1` is reusable, the hook per file is the missing piece) and parallel dispatch (the files of one `repo test-file` call still run one after the other, remotely or here).
- Fleet effects: three landings restarted the sidecars of every machine (Ready 9 to 4 to 8 around 03:00 and 04:00).
