# H38: narrow graph reads never wait for the whole read

## Custody model found
Graph generations are built under a slice custody (`🕸️graph/🕰️generations/🔐️custody`, claims in `.cache/b/g/m/generations/s/`). A claim is `structural` when its write set is unknown (the whole read: `show projects`, held for hours, progress at `s/<token>.progress.json`); a structural claim conflicts with every other claim (`claimsConflictV1`). A narrow read (`repo run --exclude-dependencies`, `repo inputs`, MCP build tools: closure/slice, policy fresh) first verifies the sealed generation under a shared reader; if its closure is clean it never enters the custody (measured: 64 s slice while the whole read held the custody). If any owner of its closure is stale it asks for a claim on those owners (`withBuilder` in `🕰️host`), conflicts with the whole read's structural claim, queues/attaches (`attachToBuilderV1`, prefetch) and waits until the whole read publishes: the ~15 min of H30. Only then it needs its ~200 s slice.

## Change (landed 04:05-04:10, lock graph, see landings.md)
A narrow, fresh, non-structural read with stale owners first asks `host.wholeBusy()` (a live structural claim exists). If yes it runs `host.withOverlay`: capacity admission, generation namespace as shared cohort (sweeps stay out), NO claim, and the engine builds with `ephemeral:true`: it plans against the sealed generation, infers only the stale owners, stores their fragments (content addressed) and returns an in-memory manifest on top of the sealed generation. No journal, no index patch, no manifest write, no pointer CAS, no `host.sealed` receipt, no wave rows. So the whole read's publication cannot lose to it (a published narrow generation would have made the whole read's merge conflict "owner"). Any failure of the overlay is reported (bilingual `overlayFailed`) and the read queues as before. Structural pending (environment stale, added/removed projects), a pin, policy current and cold generations keep the old path. When no whole read is live the read still builds under a claim and publishes.
"Share instead of hold": the whole read keeps its structural claim (a handover per waiter would throw away hours of the seal H9 chases); narrow readers just no longer depend on it. Files: `🕰️generations/🟨️.mjs` (+ new `🫧️overlay`, `📸️snapshot` because the engine file hit the 65536-byte Source bound), `🔌️load/🟨️.mjs`, `🔐️custody/🟨️.mjs`, `🤝️prefetch/🟦️.ts`, `🛑️custody/🟦️.ts`, `🕰️host/🟦️.ts`, `.d.mts`, schema texts.
