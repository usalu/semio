## 1. Stale first writer: contract version in the key
`key.outputDeterminism {version:"2", rules:[front-end-threads=1, dep-info-canonical, streams-canonical, offload-front-end-threads=1, module-remap-or-unshared, cargo-identity-keyed]}` in the unit-cache schema (schema-first). `unitKeyV1` hashes `["determinism",version]` for every compilation (not for build script runs, `sourceSha256` starting `run:`), so local key, portable key and fleet key (all derived from it) move together: a local entry from a pre-fix build is not re-offered under a new key, and a pre-fix fleet entry is never competed with. `-C metadata` (stable crate id) does NOT use `unitKeyV1`, so crate ids and symbol hashes do not flip. Cost: one miss wave per machine, old entries age out by GC.
Proof (tests): keys equal Python hashlib recomputation (key oracle, parts, components, portable, main test); key changes exactly when the version changes (`under(version+1)` differs) and a pinned hash of the rules fails the test when rules change without a version bump; run keys unchanged; two simulated machines (different dir names) compile one async-fn-in-trait unit with `-Z threads=0` rewritten: identical rmeta+rlib sha, equal keys; another Cargo identity or version gives another key.
