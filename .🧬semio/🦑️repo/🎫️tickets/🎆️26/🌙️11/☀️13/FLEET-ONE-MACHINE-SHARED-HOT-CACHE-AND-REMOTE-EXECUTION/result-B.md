# Package B: Rust unit cache fleet tier and fleet-wide single-flight (report fills in as it lands)

Unit cache root `U = 🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/⚡️caching/🦀️cargo/🗃️unit-cache/`, server module `R = …/📚️library/🏗️build/🌐️remote-cache/`.

## Contract for C (slots), fixed now

- Slot id: `slotIdV1("rust-unit", [toolchain, targetTriple, profile, packageId, crateName, crateKind, sortedFeatures, sortedCfg])` of `🏗️build/🪢️slots` exactly as package C specified. B fills the parts as follows:
  `toolchain` = sha256 hex of the exact `rustc -vV` text; `targetTriple` = `--target` or the compiler host triple; `profile` = `opt=<-C opt-level>;debug=<-C debuginfo>;da=<-C debug-assertions>;oc=<-C overflow-checks>;lto=<-C lto>;panic=<-C panic>;cgu=<-C codegen-units>;inc=<0|1>` (a missing flag is empty);
  `packageId` = `CARGO_PKG_NAME@CARGO_PKG_VERSION` (+ `#` + manifest dir relative to the unit's working directory when it is a workspace member, else empty); `crateName`; `crateKind` = sorted `--crate-type` values joined by `,` plus `/` plus sorted `--emit` kinds joined by `,`; `sortedFeatures` = every `--cfg feature="x"` value sorted, joined by `,`; `sortedCfg` = every other `--cfg` value sorted, joined by `,`.
- Carried by every stored entry in three places: request header `x-semio-slot: <slot id>` on `PUT /<ns>/ac/<sha>` (package C's wire), the optional field `slot` of the local `UnitEntryV1` (next to `key`), and inside the action result itself: `ExecutedActionMetadata.auxiliary_metadata` (field 11 of `execution_metadata`, field 9 of `ActionResult`) holds one `google.protobuf.Any` with `type_url = "type.semio.tech/semio.cargo.unit-cache.slot.v1"` and `value` = the 64 hex characters of the slot id as UTF-8. A server that wants the slot without the header reads that Any (reader: `readUnitSlotV1(actionResultBytes)` in `U/🛰️fleet/📦️wire/🟦️.ts`).
- Fleet cache key for one unit (the `/ac/<sha>` key): `remoteKey` = sha256 over `[namespace, "remote", platform, portable unit key parts]` (see Portability below). It is NOT the local unit key.
- Claim table (this package): in-memory, per `(namespace, kind, key)` with `kind` in `ac` or `nx`; the collector port is `claimed(namespace, kind, key): boolean` of `createClaimTableV1(...)` in `R/🎟️claims/🟦️.ts`.


## What was built (all landed; see landings.md)

1. Claim table (`R/🎟️claims`, schema first): `claim` -> `granted | held(by, until, expected) | stored | full`, `renew`, `release`, long-poll `await` -> `stored | lapsed | timeout`. Routes (instance prefix optional, kind `ac` = 64-hex action key, `nx` = Nx hash; write token for POST, read token for GET): `POST /<i>/claim/<kind>/<key>` body `{owner,ttlMilliseconds,expectedMilliseconds?}` (200 granted/stored, 409 held, 503 full); `POST .../renew` (200, 409 lost); `POST .../release` body `{owner}`; `GET .../await?timeoutMilliseconds=n` (max 25 s per poll). TTL clamped 1 s..300 s. A PUT of the `ac`/`nx` entry wakes all waiters with `stored` and drops the claim; release/expiry wake them with `lapsed`. `/status` carries `claims:{active,waiting,oldestSeconds}` (added to `ServerStatus` in `🏃️execution/🧬️schema/🌐️remote-cache.json`; the two red tests of package A are green). The table is in memory (a server restart forgets claims: duplicate work, never a wrong result). Package A's Nx path can use the same routes with kind `nx`; `server.claims.claimed(ns,kind,key)` is wired to package C.
2. Fleet tier in the rustc wrapper (`U/🛰️fleet`): local miss -> GET `/ac/<remoteKey>` -> manifest + blobs, every blob verified by sha256 and size (corrupt/short/missing = whole entry is a miss) -> installed as newest local variant (paths put back to this machine) -> the normal local second-level check (recorded input files and env values) still decides the hit -> `POST /v1/slots` claims the key for its slot (package C). On a miss: fleet claim, compile, publish locally, queue upload, return. Uploads are done by one detached worker per machine (`--semio-unit-cache fleet-upload`, lock file + heartbeat, exits after 15 s idle, spool bounded at 512, no inherited descriptor so Cargo never waits). A local hit of a unit never shared is offered once to the same worker (HEAD first), so a warm machine seeds the fleet.
3. Holder waits: bounded by `max(30 s, 2 x holder's expected cost)` (expected = last compile time of the slot on the holder, sent with the claim), cap 20 min; then compile locally. Heartbeat renews every 8 s (TTL 30 s); a dead holder lapses.
4. Breaker: connection fault/timeout/5xx stamps `fl/down` (15 s), 401/403 `fl/denied` (60 s), 404 on claim routes `fl/noclaims` (10 min); processes skip the tier while a stamp is fresh. Timeouts: lookup 1.5 s, claim 1.5 s, blobs 20 s + size/2 MiB/s.
5. Launcher: `unitCacheEnvironmentV1` now adds `SEMIO_REMOTE_CACHE_{ENDPOINT,INSTANCE,ACCESS,UPLOAD,TOKEN}` from package A's resolver (local copy only, no refresh, no network) and `SEMIO_UNIT_CACHE_WORKSPACE_ROOT`. The wrapper reads only those variables. `SEMIO_UNIT_CACHE_REMOTE=off` switches the tier off. Upload only when access is `read-write`.
6. Counters for package D: `<worktree>/.cache/f/unit-counters/*` (one byte per decision, lock free) and `📊️counters` `readBuildCountersV1(ws)` / `writeBuildCountersV1(ws)` giving exactly D's `Counters` shape; `build-counters.json` is rewritten when the upload worker exits (D should call `readBuildCountersV1` for a live value). Offload counts are kept from whatever E wrote.
7. Local entries carry `slot` (`UnitEntryV1.slot`, schema `Entry.slot`), event kinds `remote-hit|miss|claim|wait|publish|skip` added to the unit-cache schema.

## Portability (measured: pets-contract of the live repo with serde, serde_derive, proc-macro2, quote, syn, 4 build scripts; two checkouts at different paths, and a different CARGO_HOME for the second)

- Cargo runs registry units with cwd = the package directory in the registry and workspace members with cwd = the workspace root, source paths relative. The old local key contained `CARGO_MANIFEST_DIR` raw, so keys differed per checkout. The fleet key replaces the cwd (every spelling: realpath, `/private/var`, a link the manifest dir shows) and the launcher-stated workspace root by tokens, only where the path ends. The local key is unchanged.
- Result: machine A 12 misses and uploads; machine B at another path with another registry path: 12 remote hits, 0 rustc spawns (6.5 s -> 1.8 s wall). Uploaded blobs contain no checkout, registry or lane path (grep over the server store: 0 files; 22 files carry the token).
- Outputs across paths: rlib/rmeta/dep-info byte identical, except 16 bytes of the crate hash of a crate that `include!`s a build-script file from OUT_DIR (the lane path is in the hash): serde_core. Mach-O outputs (proc-macro dylib, build script executables, bins) are NOT byte reproducible (LC_UUID etc., 48 bytes), so two independent compiles give different extern digests and downstream keys diverge; this is why single-flight matters, and why a hit installs the first compiler's bytes everywhere. No `--remap-path-prefix` is added (it would change SVH-free bytes and diagnostics); option if byte-identity is wanted later.
- Correctness against wrong hits: the second-level check (all recorded input files by sha, all `env-dep` values exactly) is unchanged and runs after install. A unit that reads `env!("CARGO_MANIFEST_DIR")` or OUT_DIR records the absolute value, so it only hits where that value is equal (same canonical path); all others hit across paths.
- Platform in the key: os, arch, rustc host triple, sha256 of the full `rustc -vV` text, the launcher's toolchain digest, Darwin major release for kinds that link (proc-macro, bin, cdylib, dylib, staticlib), CPU model when the arguments contain `target-cpu=native`.
- Shareable: lib/rlib (host and wasm32 targets, within one platform key), proc-macro dylib and bin/cdylib/dylib/staticlib without native link args (platform + Darwin major), build script compile, test binaries (same as bins). NOT shared: build script RUN output (depends on host state the key cannot see: PATH tools, pkg-config, cc, absolute paths in `cargo:` lines; stays shared between lanes of one machine as before), focused `-p` units (compiled incrementally in the lane), bypassed command lines (queries, no artifact messages, native-link bins, unreadable inputs), units over 256 MiB, and anything across platform keys (Linux/Windows/macOS do not share, wasm units included: the compiler build is part of the key).

# 2026-11-14 (second follow-up): cause of the unpublished units, breaker fixes, real signed sidecar

**1. The 60 unpublished workspace units: cause found.** All 60 compiled in one four-minute window (minutes 43 to 46 of the cold build, 01:09 to 01:12); every one of the other 957 units published. The swallowed exception was invisible, so I made it visible: the wrapper now emits `publish-skip` with the reason (`no-outputs`, `no-dep-info`, `refused`, or `error: <message>`) and retries a throwing publish once after 250 ms. The first test run after that showed the reason on every unit: `error: refused process.disk.low-space {"partition"…}`. The host CAS guard (`🗄️cas/🚦️guard`, `criticalUsedFraction` 0.97) refuses every object write once the partition is above 97 % used; my own cold build had grown the target dirs by 18 GiB and pushed this Mac over the line for those minutes. So the cause is the disk guard working as designed, not an argv, `--emit`, `-C incremental`, size-cap, queue or exit-code difference (none of those showed up: the 60 are ordinary incremental workspace libraries like the 678 that published). It is still happening right now: the disk is at 98 % (20 GiB free), I stopped my second rebuild, removed its 18 GiB lane and my scratch dirs, and the free space did not recover (other agents' builds), which also makes every CAS-writing test red on this machine at the moment (see below). Test per cause: `a storage fault while publishing is logged with its reason and does not fail the build` (CAS root made unwritable: 7 `publish-skip` with `error…`, build exit 0).
  Not fixed (honest): with the disk over the line a unit still gets no local entry and therefore no fleet upload; uploading straight from the compiler outputs (hard-linked into the spool) would remove that dependency on local space and is the next step. The target "100 % of deterministic units published" holds whenever the disk guard admits writes (957 of 957 outside the window).

**2. Denied/down windows.** (a) The `denied` stamp now carries the credential identity (endpoint, facts generation from `SEMIO_REMOTE_CACHE_GENERATION` set by the launcher, SHA-256 prefix of the token) and only blocks while the identity is unchanged; the window is 15 s instead of 60 s. Test: first build with a wrong token is refused, second build with the right token on the same cache root uploads at once. (b) `down` needs two faults inside 15 s before the tier is skipped (one timeout under load no longer silences every process: in the second live rebuild 320 of 655 units had skipped on a single 1.5 s timeout), lookup timeout 3 s.
