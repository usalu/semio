## Round 3 (cross-origin key comparison, for E3 and the coordinator)
- Measured on samples of 5 origins (02:22-02:36): of 265 units seen on two origins with equal source, 100% differ in a key component. Pairwise: g1-m10 vs g1-m12 share 194 units and ALL differ in `args.diagnostics` only; g1-m10/m12/m11 agree on `args.metadata`; g1-m02 differs in `args.metadata` from m11 on 104 of 109 and from m12 on 41 of 44 shared units (and m06 on 2 of 4), nothing else. Cargo's `-C metadata` hash covers package id, features, profile, rustflags and the metadata of every dependency, so m02 has a machine-dependent cargo input (suspect: user-level `~/.cargo/config.toml` rustflags, `RUSTFLAGS`, or a different Cargo source id); the wasm host units (`wit_*`, `wasm_*`) also differ in `CARGO_ENCODED_RUSTFLAGS` and `-Z` flags between m06/m11/m12. This machine has a `~/.cargo/config.toml` with a `target.wasm32-unknown-unknown` rustflags block that the repository config does not have (Cargo concatenates array values of both files).
- Fixed by E4: rendering flags (`--color`, `--json` rendering words) no longer enter the key.
- For E3 / coordinator: the cargo inputs that remain machine-dependent are configuration outside the tree: make every machine use the repository's `.cargo/config.toml` only (e.g. `CARGO_HOME` without a config.toml or `--config` pinning rustflags per target), and compare `~/.cargo/config.toml` + `RUSTFLAGS` on g1-m02. Samples now carry the flag texts (`values`) of `args.unstable`, `args.codegen` and `CARGO_ENCODED_RUSTFLAGS` (paths as `<path#digest>`), shown by `repo fleet status`, once the machines run the new uploader.
