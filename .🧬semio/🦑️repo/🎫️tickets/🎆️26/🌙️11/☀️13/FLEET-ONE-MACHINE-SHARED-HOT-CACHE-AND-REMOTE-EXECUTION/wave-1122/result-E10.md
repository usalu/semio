   - Per-request timeout: `routeNxThroughFlightV1` takes it from the resolved contract (`timeoutSeconds`, default 30 s); it bounds the time to the response headers of a GET/HEAD (a body that is already streaming is only bounded by the old 120 s overall cap), a PUT gets that plus 1 s per 2 MiB.
   - One down-window breaker shared by GET, PUT, the CAS route and the claim calls: the first timeout, transport failure or 5xx (not 507) trips it for `breakerMilliseconds` (30 s); while open every task is answered locally at once (GET 404, PUT 502, claims "unavailable"). When the window ends the next request first asks `<upstream>/healthz` (1.5 s, single flight); only a 200 closes the breaker, otherwise it re-opens. A cache that merely refuses claims (read-only token) still serves GET/PUT (refusal is separate from "down").
