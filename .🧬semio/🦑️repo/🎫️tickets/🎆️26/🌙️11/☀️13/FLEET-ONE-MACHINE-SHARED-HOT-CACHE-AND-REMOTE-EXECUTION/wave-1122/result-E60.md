## Root causes and fixes
| Warn | Why the normal path did not retire it | Fix (system retires it itself) |
|---|---|---|
| `caches.dead-publication` (59, 1.0 GB, graph) | `observeDependencies` writes `inference/p-<pid>/<name>.publication.json` next to the shared copy; only the publisher of the SAME pid reads it (`producerPublication`, then archives it to `pa/<digest>.json`). Nothing ever removed it: not the producer, not the graph reclaim (`reclaimGraphOptionalV1` had no stage for it, groups are retired by LRU as a whole), and `repo cache gc` only runs on pressure or by hand. Every owner-pool child leaves one. | Three event-driven layers: (1) `retireProducerPublicationAtExitV1` (observation, new module `👁️observation/🪦️producer-publications`): the producing process removes its own folder on `exit` (real directory only, links never followed). (2) the publisher sweeps dead siblings below `selections/` after every successful receipt (`sweepDeadProducerPublicationsV1`, best effort, never fails the receipt). (3) the graph reclaim has a first stage `publications` (`graphProducerPublicationsV1`, dry-run plan line + done line, bilingual) for SIGKILLed leftovers. A live pid (EPERM counts alive), a folder quiet < 60 s, a link or anything not `p-<digits>` is never touched; each folder is re-checked right before `rm`; nothing outside `selections` (realpath boundary). |
| `caches.undeclared` `repository:tools/.DS_Store` | `ignored` matched only a single top-level segment, so an OS file inside a container (`tools/` holds the declared `ms-playwright` and `elan`) was "nobody's". | `classifyCachePathV1`: `ignored` is a listed root-relative path or a listed file name anywhere inside a container of declared homes (schema unchanged, `ignored` items are strings). |
| `native:b/image-relocation.json` | Written by the replica relocate (`📍️relocate`) and read by every image opener (`admitNativeImageRelocationV1`) to re-bind each image after a tree move; no area declared it, so the 7-day undeclared rule would have deleted a hint that all images share. | Declared in `roots.native.ignored` as the path `b/image-relocation.json`. |

The product's own doctrine (`👻️orphan`) is that a reparented process (nohup, setsid) is NOT abandoned: it ends only when its stdout PIPE breaks (self SIGTERM, grant returned); a stdout redirected to a file never breaks. 72392 is such a run: log updated every second, a child at 61 % CPU, `repo fleet status` lists it as `running`. | Doctor: `processes.orphan` only when the holder's whole process tree is idle (`treeCpu < idleCpuPercent`, the idle-holder rule); a detached run that still computes is not reported. A stalled one is still caught by `idle-holder` (>600 s, <1 % cpu) and by the orphan rule. No new reaper: the product mechanism for abandoned runs already exists (broken stdout pipe), I added none. The pid was not touched. |
