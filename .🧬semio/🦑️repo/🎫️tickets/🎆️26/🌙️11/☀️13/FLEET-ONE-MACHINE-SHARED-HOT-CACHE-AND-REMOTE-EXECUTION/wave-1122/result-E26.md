## 1. `repo test-file` (promoted from E19's `sf.sh`)
`repo test-file [--json] [--bail] [--dry-run] [--] <path>...` (also `--lang`, global). MCP: `test_file { files: [..], bail?, dry_run?, language?, agent? }` (the server always passes `--json`).

What it does per file, with no project graph read, no lease, no resident service (it is a light door command):
- Routes the file by the suite table of the area that holds it (`build`, `caching`, `process`) with the runner's own rule (`expandProcessTestSuiteV1`: explicit file, else deepest tree, name-filtered suites besides). A declared helper is refused (`file.helper`); a file no suite owns runs `plain` (bun test in the checkout, managed Python bound when the source names Python).
- Narrows the owning suite row to that file (its typecheck covers that file only) and runs it through the real `runProcessTestSuiteV1`: Original envelope with the native caller grant of the suite's own target (`@semio-tech/repo-lib:test-<suite>`, `@semio-tech/framework-process:test-<suite>` for process), genuine-birth launcher where the row declares one, checkout as working directory (root `bunfig.toml` preloads apply), managed Python for suites declaring it, hermetic artifact sandbox (`withProcessTestOutputV1`), strictness and budget of the suite. `SEMIO_SCRIPT_*` and `SEMIO_PROCESS_OWNER_CONTEXT` are stripped, and the fleet/remote-cache variables and `SEMIO_TEST_ARTIFACT_DIR` scrubbed (restored afterwards), so a run inside another test does not inherit a wrong envelope.
- A suite not declared for this host is `skipped` (never a pass). `--bail` leaves the rest `not-run`.
- Progress: one notice line per file (EN/DE) plus the envelope's own progress rows on stderr. Cancellation: SIGINT/SIGTERM through the envelope cancels the run and its children, exit 130, no result document.
- Result: text (one line per file and totals) or with `--json` one document `Result` (version, status, seconds, bail, counts, per file status passed|failed|skipped|not-run, bun's last-summary pass/fail, error and output tail for a failure); test output goes to stderr under `--json`. Exit 0 all passed, 1 a file failed, 2 refused (usage, missing file, outside checkout, not a test source, helper).
- Paths: absolute, or relative to the current directory when the file exists there, else to the checkout; links are resolved and must stay inside the checkout.

Deliberate difference from `sf.sh`: it does not call the suite learning (`testWorkerLearningV1`); a one-file run must not teach the suite-wide worker ratio. It runs files sequentially (one envelope each) for exact per-file attribution; the suite's `parallel` is not used.
