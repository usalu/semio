## A. Per-owner local claim in `📥️take` (E1 was editing the folder at 01:21 CET, so not implemented)
Problem: a follower load that runs alongside a leader (same checkout, bounded wait) infers an owner the leader has started but not yet written.
Design (schema-first): claim file `<facts>/claims/<owner-stem>.json` (stem = sha256(root)[:24], same as the record), created with `wx` before `infer`, content `{version:1,pid,startMs,origin}`; no new lease family, so no order rule. Lane order in a take pass: claim ok -> infer and publish -> delete claim; claim exists and its pid is alive and younger than `claimStaleMilliseconds` -> treat the owner as `running elsewhere` (the existing `takeMissingRowsV1` reason `running`), look again at the poll cadence (the record appears), never infer it; dead pid or stale claim -> take over by `rename` swap. Process-local `Map` in front for the same process. Follower should also walk the owner list in reverse so that two loads meet in the middle. Tests: two pools on one temp store (the existing `🤝️two-machines` harness), Python model of claim states, kill -9 of the claimant releases after the stale bound.
