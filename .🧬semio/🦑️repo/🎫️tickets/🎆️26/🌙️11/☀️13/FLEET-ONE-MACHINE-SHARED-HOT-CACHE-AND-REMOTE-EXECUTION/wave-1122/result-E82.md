# Result E82: resource-directory-admission lease and the persisted Nx engine memo

## 1. Who holds `resource-directory-admission:v1`, why (read from code, live state)
- It is not one global lease: it is the per-lease-directory admission gate (SQLite file `sha256("resource-directory-admission:v1").sqlite` in each lease directory, e.g. `.cache/b/l/m/data`, `.cache/b/c`, `.cache/b/r/m/b/isolated`). Every acquire holds it SHARED for the few ms of opening the resource database; retirement (idle sweep, claim sweep) holds it EXCLUSIVE. It does not appear in `repo leases status` (internal resource); the live registry showed 0 waiters, no gate holder, directories of 11-184 entries at 16:49, so the contention is bursty, not permanent.
- Failure path of after1 (160 s): a QUEUED acquire (`acquireQueuedResourceLease`) waits for the gate with the CALLER's remaining timeout in `queueClaimCatalog` (operation `queue-publish`); when a retirement slice or a stuck exclusive holder keeps the gate longer than that timeout the wait ends with `Resource lease timed out: resource-directory-admission:v1` and is converted into the typed refusal. Observed in the coordinator log: `native:preparation-entry remains active on resource-directory-admission:v1 (shared, 63 s)`. A 2026-10 observation (ticket BUILD-SEMIO-TECH-PLAY-FOR-CDN-DEPLOYMENT, `graph-admission-gate-observation.md`) found the exclusive owner to be a graph worker in `retireResources` scanning with `stat` for 470 s.
- Why a retirement slice can hold the gate long: `retireResources` counted only EXAMINED candidates against the slice cap (64/256); entries that are kept (recently used, live queue, not a candidate) did not count, so one slice scanned every remaining name of the directory (up to 65,536) with the gate held exclusive across the yields. Not measured live at that size here (current directories are small); established by reading and by the frontier test that scans 8,192 blockers in one turn.

## 2. Changes (landed under lock `process-leases`, `T/landings.md` "Wave 1122 E82")
- Gate wait never fails a queued waiter (`🔒️leases/🟦️.ts`): `directoryAdmission` for operation `queue-publish` with a waiting timeout waits in patience slices (policy `gate.admissionPatienceMilliseconds`) until the gate is free, publishing the usual progress each second, honouring cancellation; only a genuine `ResourceLeaseTimeoutErrorV1` of the gate is retried (an observer error with the same text is not swallowed). The deadline origin of the queued acquire and the catalog clock restart after the gate, so contention on the gate never consumes the caller's budget for the real resource; a real holder of the resource still ends in the resource timeout as before.
- `admissionRefusalV1` converts only genuine timeout errors (fixed an existing test regression: an observer's own error with the same message was rewrapped).
- Short-held exclusive gate: `retireResources` and `retireResourceQueueClaimsV1` stop a slice after `Scan.gateHoldMilliseconds` = 2000 (schema `♻️retirement/🧬️schema/🔣️.json`), the persisted cursor continues the next slice; the sweep pauses `Idle.slicePauseMilliseconds` = 25 ms between slices so shared openers get the gate.
- Not done: exclusive gate still spans the directory readdir of a slice; the fresh (try-lock) path keeps its bounded patience by design.
- Persisted engine-closure memo (`⚡️caching/🚀️bootstrap/🔌️nx-plugin/🧊️engine-references`, schema first): per checkout JSON in the per-user cache (`~/Library/Caches/semio/nx-engine-references/<root sha>.json`, override `SEMIO_NX_ENGINE_REFERENCES_DIRECTORY`), file -> stamp (`dev:ino:size:mtimeNs`) + sha256 of text, sha256 -> references. Stamp match answers without reading; stamp mismatch rereads and answers from the text digest (a replica rewrite with equal bytes does not rescan); only unseen text is scanned; atomic write, never fails the caller, broken/oversized/invalid memo = empty. `nxBuildEngineClosureV1` uses it. Measured on this host (load 28-32): cold 2.5 s, warm 0.23-0.27 s per process (was about 9 s at load 50, E63).
  Shared across the processes of the machine (not across checkouts or machines).
