The product is correct to report `verify`.
- Test fix: `hostDeliversEventsV1` (event-driven probe, no sleep) in `🧪️tests/🟦️.ts`; `native` in the service tests now also needs delivery, and the 4 laws that need an exact journal are `skipIf(!native)` with a console warning naming the reason. Same 8 s probe on a healthy host runs them.
- Real product bug found by the same run (flaky 2 of 3, not load): `watch` handler awaited `abort` on a signal that was already aborted when `runTasks` returned, so a cancel that arrived during the first run never produced the result 130 (test "protocol abuse"). Fixed (`throwIfAborted` first, listener only if not aborted). 4 of 4 green afterwards with the default 3 s wait.
- Product improvement: a watcher degraded by one missed canary stayed `verify` forever; `ensureFresh` now re-fences it (2 attempts), rate limited to once per 30 s after a failed recheck so a starved host does not pay 3 s per query. Not covered by a unit test (needs a watcher that misses then recovers); only the 4 skipped laws exercise it on a healthy host.
