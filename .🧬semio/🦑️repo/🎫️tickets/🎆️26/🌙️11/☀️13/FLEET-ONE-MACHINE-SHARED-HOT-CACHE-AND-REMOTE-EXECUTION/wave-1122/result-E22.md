# E22 result: Nx admission (single-target `repo run`)

## Verdict
The Nx tool namespace cannot be narrowed to Nx version/plugins/config without a wide redesign (the identity includes the whole library closure of the authorizer bundle, see `findings-E22.md` section 1). I landed the part that is safe and measurable: **the sha256 re-hash of the 11.6k pristine SDK files on every verification pass is replaced by a stamp memo**. Warm `repo tools setup nx` is 43 to 56 s at load 38 to 40 (it was never run before the change on an idle generation, see "not verified"), a rebuilt generation spends 16 s instead of 66 s in the four source-verification passes. A single-target `repo run` is still minutes, because the Nx generation is rebuilt on almost every run (a peer lands in the 1,823-file authorizer closure about every 8 minutes) and because of three costs outside this lane (capacity gate 31 to 450 s, dependency generation adoption, Nx daemon graph 90 s).

## What the namespace identity is keyed on (exact)
`nxToolingInstallIdentityV1` over: platform/arch/libc, `package.json`, `bun.lock`, patches, `.semio-sdk-material.json`, and the two source manifests `.semio-authorizer-source.json` (1,823 files, sha256 each) and `.semio-authorizer-compiler.json` (1,985 files). Any edit of one of ~2,000 library files = new digest = new 199 MB generation (hardlinks) = clone + compile + 4 verification passes. 21 to 25 generations were built between 01:06 and 04:40. Details, the import census (why the closure is the whole graph/seal/startup/storage stack) and the recommended split (`nx/<depsDigest>` + `authorizers/<sourceDigest>`) are in `findings-E22.md`.
Test for the key already exists and passes (`📦️sdk/🪪️identity/🧪️tests/🧮️keys`, 4/0: Python hashlib oracle, order, platform triple, boundary forging). The brief's "identity unchanged on an unrelated library edit" cannot hold today and I did not write a test for a law the product does not have.

## What changed
New member `⚡️caching/🚀️bootstrap/🛠️tools/📦️sdk/📥️source/🔗️derivative/🔏️index/🧊️stamps/` (schema first: `🧬️schema/🔣️.json`):
- `openNxSdkStampMemoV1(directory, sealedIndexDigest)` returns `{has, add, commit}`; `nxSdkStampKeyV1` = `dev:ino:size:mtimeNs:mode`. ctime and nlink are NOT in the stamp: every new generation hardlinks the base files and changes both, so they would invalidate the memo on each landing (the module already treats `dev,ino,size,mtimeNs,mode` as "same consumed bytes" in `nxSdkSourceStampHoldsV1(shared)`).
- Memo file `<machine cache base>/sdk-verified/<sha256(dir NUL index)[:32]>.json` (base = `nxAuthorizerMemoBaseV1`, `~/Library/Caches/semio-repo` on macOS, same convention as the authorizer source memo), written atomically, 600, at most 100k rows / 16 MiB; one `verifiedAt`, a memo older than 24 h is cold (so every file is fully re-hashed at least daily), a memo from the future, another sealed index, a malformed or oversized file is cold; a failed write never fails a verification. `SEMIO_NX_SDK_STAMPS_DIR=off|<absolute dir>` (honoured by processes that receive the variable).
- `🔏️index/🟦️.ts`: `verifySdkSourceIndexReadV1` (every reader) and the sealed branch of `captureNxSdkSourceIndexV1` (the derivative clone) skip the sha256 of a file whose stamp the memo holds. Everything else is unchanged: lstat of every entry, ancestor chain re-lstat, readonly/size/exec checks, namespace verification, rechecks, source-index byte comparison. A row is only added to the memo after its hash equalled the sealed digest.
- Test files of the derivative member and of `🧹️retention/📥️physical` set `SEMIO_NX_SDK_STAMPS_DIR=off` so their hash-counting laws (`failOnOpen` on a second verification) stay exact.
Landing recorded in `T/landings.md` (lock caching-bootstrap taken over at 04:24 from a 41 minute old E19 lock; E19 was editing only `📦️dependencies`/`📥️admission`; released 04:33).

## 4. The split: designed in detail, NOT implemented, and why
I stopped before the first edit. Reasons (all verified by reading the code):
1. The directory of the generation is the identity in at least 8 places that assume one directory = deps + authorizer: patched Nx (`loadSemioGraphAuthorizersV1.inspect()` in `⚡️caching/🩹️patches/nx@23.2.0.patch` walks up from the real path of the nx package to the first `.semio-nx-tooling.json`, requires `basename === marker.digest`, the authorizer receipt, `.semio-authorizer-source.json` and the bundle in that same directory), `📥️use` (`basename(toolkitRoot) === identity`, marker digest, lease `nx-tooling:<identity>`), the loader (`toolkitRoot = dirname(import.meta.url)`), `📦️sdk/📥️source/🔗️derivative/📥️reader` (recomputes the install identity from package.json, lock, patches **and the two authorizer manifests**), `🧹️retention/📥️physical` (59 KB: recomputes the identity and authorizer receipt per generation, witnesses, quiescent retirement), `🧹️retention/📦️generation` schema, `🔗️activation`, `📜️script.ts` (`toolingIdentity = basename(dirname(modulePath))`, daemon birth records, `SEMIO_NX_TOOLING_IDENTITY` feeding graph-seal keys), the testing `🌱️genuine-birth`, and about 15 fixtures with embedded digests.
2. The patch is part of the identity: editing it rebuilds every machine's generation at once, and a mistake stops Nx on all 13 machines (their supervisors restart on every replicated change) with no scratch environment to prove it (cloned worktrees poison the shared build dir; `bun test` of these suites needs the script runner, which aborts here).
3. The suites that would prove the change (derivative, retention, authorizers, activation, genuine-birth) cannot be run in this session, so I would land a 15-file security-code change blind.
**Design to execute (ordered, each step compile-atomic and live-testable with `repo tools setup nx`):**
- D = `nxToolingInstallIdentityV1` over platform triple, `package.json`, `bun.lock`, patches, `.semio-sdk-material.json` only (drop both authorizer manifests; the keys test and its Python oracle already cover arbitrary file lists, fixtures unchanged). Generation `nx/<D>`: node_modules, patches, marker `{version:1, digest:D, patches, binaries}` (no authorizers).
- A = sha256 of (D, `.semio-authorizer-source.json` bytes, `.semio-authorizer-compiler.json` bytes). Authorizer directory `nx-authorizers/<A>/` (sibling partition folder under the tools image): `semio-authorizers.mjs`, both manifests, marker `{version:1, digest:A, deps:D, authorizers:{...receipt}}`. Built in about 7 s by the existing compile step into a `.stage-*` and renamed; `nxAuthorizerReceiptHoldsV1` already verifies "a directory with these files" and is reused unchanged. The bundle imports only Node built-ins (checked: 402 `node:path`, 283 `node:fs`, ... no package specifier), so it needs no adjacent `node_modules`.
- `toolingIdentity` stays A everywhere downstream (`SEMIO_NX_TOOLING_IDENTITY`, graph-seal keys, daemon birth, use witness, `toolkitRoot` = the A directory), so state stays code-versioned exactly as today. `withNxToolingUseV1` additionally holds `nx-tooling:<D>` (D from the marker `deps`) so retention cannot retire the deps generation under a running Nx.
- Patch: `inspect()` keeps the walk-up to the deps marker (Nx patch receipt checks) and takes the authorizer directory from `SEMIO_NX_TOOLING_ROOT` (an existing variable already propagated to the daemon and task children), requiring `marker.deps === deps digest`, basename = A, the existing receipt/manifest/bundle checks, and returning `toolingIdentity: A`.
- Retention: authorizer directories are retired when no `nx-tooling:<A>` lease and not among the newest 4; deps generations by the existing writer with the identity computed without authorizer files.
- Tests (Python oracle as already in `🪪️identity`): edit an unrelated library file, D unchanged and A changed; edit `package.json`/lock/patch, D changed and A changed; edit an authorizer-closure file, A changed only.
Estimated 2 to 3 focused days for one lane that can run the repo-runner suites and a scratch machine that is not on the replica; expected effect: Nx tool admission after a landing falls from 255 s (this run) to the warm floor, about 45 s, plus the 7 s compile; the warm floor itself (3 readers x verification + namespace, storage planning, capacity gate 31 to 450 s, source admission 34 s, Nx daemon graph about 90 s) needs the other items listed in `findings-E22.md` to reach seconds.
