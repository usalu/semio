## 2. Fix (landed, lock caching-bootstrap, landings.md "Wave 1122 E72")
`📦️dependencies/♻️collection`:
- New liveness rule `readBoundDependencyGenerationsV1`: every `bindings[].sourceDirectory` of every ready generation that is a symlink resolving into `j/<key>` keeps `<key>`, independent of pointers and holds (readlink and realpath, store root and its realpath). Needs no cooperation from old binaries.
- Fail closed: a ready generation with an unreadable/ill-shaped `bindings.json` -> nothing is retired ("no readable dependency binding record"), as with no readable pointer.
- Age of a generation = newest change of the directory or any of its top-level entries (an install writes into `node_modules`/`w` long before the directory mtime moves), so a live >6 h unfinished install of an old binary is not "dead".
- Schema `Plan.bound` (required), Python oracle and JSON cases extended (new case "bound by a checkout is kept even when unreferenced and unheld"); pure planner takes `bound`.
- Current generation of each scope: pointers are per store (= per worktree) and per scope; `pointer.generation` is always in `referenced`, so it cannot be retired; a pointer read failure refuses everything. The remaining hole (link target not in any pointer) is covered by the bound rule.
Tests (repo test-file): collection 7/0 (new: m03 reproduction = bound generation survives without pointer and hold while an unbound one goes, and goes once the link is removed; unreadable binding record refuses; young unfinished install kept; oracle equality incl. bound), cache-gc 19/0, dependencies main 15/0. # Round 2 (15:51)

## Pin leases (LANDED, locks cache-gc + caching-bootstrap, landings.md "E72 round 2")
- `collectUnpinnedDependencyGenerationsV1` (collection member): plans with the sync collector (pointers, holds, bound links), then claims EVERY candidate exclusively through its pin lease `concurrentPinResourceV1(workspace, key)` (the lease any reader or producer of any binary holds shared) before removing anything. A candidate whose pin is held is kept; if the claim throws (lease registry unreadable) all pins are released and nothing is retired ("no readable dependency pin lease registry"); pins stay held during the removal and are released afterwards. The sync collector gained an `only` filter for this.
- `repo cache gc` (whole gc, `--area=dependencies`, `--idle`) now calls it with `leases.acquireResourceLease(... exclusive, timeoutMs 0)`; a lease timeout = pinned.
- Tests (repo test-file): collection 9/0 incl. a fake claim (pinned kept, unreadable registry retires nothing, pins released, dry run) and a REAL lease test (a shared pin taken with `acquireConcurrentPinsV1` blocks the exclusive claim, the generation goes after release); cache-gc 19/0; idle 4/0.
