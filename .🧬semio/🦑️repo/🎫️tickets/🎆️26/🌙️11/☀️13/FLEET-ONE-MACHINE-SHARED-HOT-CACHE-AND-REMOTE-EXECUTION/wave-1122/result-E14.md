# E14 result: doctor image repair and reclaim that never strands an image

## What changed
1. **Declared safe repair `storage-images`** (`🏗️build/🩺️doctor/🔎️probes/💾️storage/🟦️.ts`, policy entry in `🔣️policy.json`, EN/DE summary and safety text). Targets are re-derived from the live kernel inventory: a misplaced image is detached from its stray mount without force (a busy device refuses), then attached at `<directory>/m` with `diskutil image attach --nobrowse --mountOptions owners --mountPoint` (the library's own `nativeImageAttachArgumentsV1`, host mount checked with `requireNativeImageHostOwnersV1`, mount point must be an empty unmounted directory); a detached image is attached only while `node_modules` dangles. Pure plan `imageRepairPlanV1` (leases image first, damaged receipt never). Other platforms keep plain directories: the repair answers `unavailable` with a bilingual reason. Dry run only counts.
2. **Lease**: new `…/💾️storage/🔒️image-lease/🟦️.ts` takes `native-fixed-image:<directory>` exclusively with `timeoutMs:0` (one try, never queues). A held lease (a live reclaim or opener) leaves the image untouched and reports `unavailable` with the partition named. The doctor invariant test was narrowed: no other source may mention an acquisition and this file must contain exactly one `timeoutMs:0` call.
3. **Rules** `storage.image-misplaced` and `storage.image-detached-blocking` are `kind: automatic`, command `repo doctor --fix --only=storage`, repair `storage-images`; the detail texts no longer say recovery happens only once a command can start (doctor starts without `node_modules`).
4. **Root cause** (`🔨️modules/🏃️process/📦️artifacts/🏗️native-build/💾️storage/🍎️image/♻️reclaim/🟦️.ts`): the cycle parked the image at a private scratch mount `semio-reclaim-*` in the temp folder for the whole trim and settle phase, so every link into the image dangled for the full cycle and forever after any exit that runs no cleanup. Ports now take `mountPoint` and attach at the canonical mount (`mountsCanonically`); the cycle gives an image that was attached back attached, and the cleanup retries a failed or cancelled attach through the uncancelled cleanup runner. An image that was inactive stays inactive. Callers in `⚡️caching/💾️storage/🔒️enforcement/📦️budget/📥️opening/♻️reset/🟦️.ts` (both cycle sites, Rust wait wrapper gained phase `cleanup-attach`) pass the mount point. Remaining window: a killed process (SIGKILL, power loss) between detach and attach leaves the image detached, never at a foreign mount; `repo doctor --fix --only=storage` repairs that without any loader. The dangling-store message of every command now names `repo doctor --fix --only=storage` (format-stamps schema), closing the chicken-and-egg: the failing command tells the one command that starts without the store.
5. New public package entry `📦️packages/🟦️typescript/📦️artifacts/…/🍎️image/👤️owners/🟦️.ts` plus its `package.json` export `…/storage/image/owners`.

# Round 2

## 1. Cross-platform
Backing is declared in `💾️storage/🔌️backends/🧬️schema/🔣️.json`: `mounted-image` (capability `mounted-volume`, `fixed.dmg`) is darwin only; Linux and Windows use only `directory-partition` (`fixed.dir`, plain directories, no loop device or VHD for these partitions; the loop/VHDX ports in the reclaim module serve other image files, not the cache partitions the doctor reads). So the rules never fire there (partition state is `directory`), and the repair now derives this from the declared backends instead of a platform guess: result `unavailable` with reason "Not applicable on <platform>: its partitions are backed by the directory-partition backend, plain directories with no image to attach ..." (EN/DE), for dry run and real run. ## 3. Real SIGTERM
