# E71 findings
- m01's dependencies image `d` (36 GiB) sits at 0.4 to 8.8 GiB free within a single stage and its log says "dependency generation collection deferred, entries 4096": the generation store is at the 4096-entry protocol ceiling (`SelectedPlanProtocol.maximumGenerations`), so the collector defers instead of retiring. That, not remote execution, is what keeps m01 at disk-full. Lane E58/E72 (dependency collection).
- `readyDecideV1` refuses to start any stage while a restart is merely deferred (restartPending), even when no stage runs; with 40 landings a day on a 5 min quiet / 30 min max rule a worker can sit hours in `sidecar-restarting`. Consider starting the stage when the restart cannot happen within the stage's expected time, or dropping the quiet time on workers during a wave (lane E53).
- Other fixed 3 GiB style assumptions: `readyDiskShortV1` (stage needs 6144 MB free in `.cache`) is measured on the host volume; check that none of the image-resident stages charge a host reserve to an image.
