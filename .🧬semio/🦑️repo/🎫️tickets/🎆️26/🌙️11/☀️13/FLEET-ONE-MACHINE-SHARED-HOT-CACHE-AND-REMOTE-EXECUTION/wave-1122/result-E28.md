## Design (what is keyed on what)
- D = `nxToolingInstallIdentityV1` (tag `nx-tooling-install-v5`) over platform/arch/libc, `package.json` (projected), `bun.lock`, `patches/<sha>.patch`, `.semio-sdk-material.json`. The two authorizer manifests and `physicalSourceRoot` are out: D is now the same on every checkout of one platform (side effect: tooling-keyed state is no longer machine-specific).
- A = `nxAuthorizerBundleIdentityV1(D, {source manifest, compiler manifest})` (tag `nx-authorizer-bundle-v1`). Directory `.cache/b/t/m/nx-authorizers/<A>/` holds `semio-authorizers.mjs`, both manifests and the marker `.semio-nx-authorizers.json` `{version, digest:A, deps:D, authorizers:{receipt}}`. A is bound to D and to the physical source root (the compiler manifest names it).
- Where the bundle is found: the patched Nx loader (`loadSemioGraphAuthorizersV1.inspect()` in `nx@23.2.0.patch`) still walks up from the loaded Nx package to the generation marker (D, patch receipts, no `authorizers` field allowed), then requires `SEMIO_NX_AUTHORIZER_ROOT` to be an absolute real path `<tools>/nx-authorizers/<A>` beside the generation, `marker.deps === D`, and checks receipt, source manifest and bundle bytes as before. It returns the generation as `toolingIdentity`, so every consumer of the identity (witness, `nx-tooling:<D>` lease, daemon birth, retention, activation, tests that read `nx/<identity>`) is unchanged. The variable is set by `📜️script.ts`, inherited by the daemon and task children, pinned in the daemon service environment, set by the genuine-birth harness (newest holding bundle) and by the cache probe.
- Loaded use: `withNxLoadedToolingUseV1` derives D and the toolkit root from the bundle's own marker and location (`nxAuthorizerBundleToolkitV1`); `withNxToolingUseV1` additionally holds the shared lease `nx-authorizer-bundle:<A>` (script process, bundle process, daemon service). The lease name falls in the existing `nx-authorizer-` class, so the lease order law needed no change.
- Provision (`🛠️tools/🟦️.ts`): the generation path no longer compiles; after it is present or published, `ensureNxAuthorizerBundleV1` verifies or publishes the bundle (stage under `nx/.stage-*` because the compile child demands that scope, compile, write manifests and marker 0444, receipt and Node preflight on the stage, atomic rename, verify under the shared lease, mark used). Activation verifies D and the bundle and runs the Node preflight on the bundle.
- Retention: `retireNxAuthorizerBundlesV1` runs at the start of every managed retirement (so before every tools publication and in count-bound and quiescent runs): keeps the 4 most recently used bundles, every bundle used within 10 minutes, every bundle a reader holds (exclusive try-lock, no waiting); a failure is logged and never blocks a publication. Generation retirement lost its authorizer checks (identity recomputation, marker, hardlink and witness protocol are unchanged).
- Old generations: no migration code. A generation of the previous format (marker with `authorizers`, key tag v4) is unauthenticated for the new retention and stays on disk until the tools image is recycled (about 10 to 12 MB owned each, 30 on this machine); the running processes that use one keep it through their leases. The current activation of the old format passes the activation and retention checks until the new generation replaces it; the pristine-restore path now falls back to a cold install instead of throwing when the current artifact cannot be authenticated.

## Behaviour changes other lanes must know
- The Nx namespace (graph and daemon state keyed by tooling identity) no longer changes when only the authorizer closure changes; it changes with D, with the implementation identity (about 12 plugin files) and with the graph digest. A daemon born earlier keeps its birth-time bundle (the daemon environment is pinned) while newer clients use newer bundles: an edit in the authorizer closure (graph startup, seal, storage code) reaches a running daemon only after it idles out or its namespace changes. If an edit there seems to have no effect, stop the daemon of the workspace.
- `SEMIO_NX_AUTHORIZER_ROOT` is required by every process that loads the patched Nx authorizers (the loader fails closed without it); launchers other than `📜️script.ts` must set it (the probe and the genuine-birth harness do, from the newest bundle beside the generation).
- The installation key is machine independent now (no `physicalSourceRoot`): the same platform builds the same `nx/<D>` everywhere; the bundle key stays per checkout.
- Old-format generations stay until the tools image is recycled (see Design). `repo cache gc` does not retire them (they cannot be authenticated); removing `.cache/b/t/m/nx/<old digest>` by hand is safe once no process holds `nx-tooling:<digest>`.
- The capacity formula of the generation quote still charges the authorizer snapshot and program copies (`derivativeSnapshotCopies`, `derivativeProgramCopies`): conservative, pinned by `🎟️capacity` tests; the bundle publication itself runs without a quote under the default installer headroom (1.6 GiB). Narrowing the quote is a follow-up (E24/E32 own the capacity law split).
- `nxAuthorizerRetirementIntegrityHoldsV1` (receipt module) has no production caller left; kept with its tests, remove with the next receipt cleanup.
- E32 holds `caching-bootstrap`, `testing`, `caching-storage`, `process-leases` (07:09 to 07:26); the first two were taken over after 41 minutes and released; E32's files (rustup adoption, private-repository) are untouched.
