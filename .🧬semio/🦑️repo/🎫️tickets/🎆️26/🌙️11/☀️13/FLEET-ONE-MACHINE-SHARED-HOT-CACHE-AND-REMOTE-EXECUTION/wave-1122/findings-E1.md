## Round 3 notes for E2 and E3 (owner record key)
- E2 (generations/adoption): an owner record key no longer contains `projectAuthority` (generator contracts digest) nor the whole registry in an admission read. Key text = `JSON.stringify([stamp, null, [registryDigest(catalogProviders), commandRevision|null, assemblyAuthority|null, "closure-references/4", root, json, selectedTargets|null, selectedInputs]])`. Pool wave globals are `{registryDigest, commandRevision, late}`. A record is valid while its rows hold; the contracts the owner read are `global` rows (kind `global`, path `["generator-contracts", workspaceRoot, [segments]]`, fact = JSON string of the value read). A process that verifies rows of owner records must import `📦️project-nodes/🟨️.mjs` (it registers the resolver `generator-contracts` in the observation module) or the rows do not hold (conservative: the record is inferred again, never wrongly adopted). If the generation load verifies owner rows in a process without that import, import it first.
- E3 (record contents): the new rows carry no machine path (the workspace root in the row path is neutralised to the root token by the portable form; test `contract-reads` checks two checkouts give the same neutral rows) and no time or host field. Divergences between two machines for one key can now only come from rows (file stamps are already zeroed) or from the project image.
- Not removed: `commandRevision` still re-keys every native owner when any Cargo command input changes anywhere. Removing it needs the same read-recording for `cargoTargets(root, workspaceRoot, commandInputs, scripts)` (closure handle reads); not done.

## Round 6 notes for E2 (farm child session) and E8
- The farm child session can be built in-process without a session file and without custody: `🕸️graph/📥️inference/🔬️owner-harness/🟨️.mjs` `openOwnerHarnessV1({workspaceRoot})` opens `👷️service.open(session, {slot, generation})` with the registry (`readBuildOwnerRegistrySourceV1`), the generator contracts, the command inputs, `projectsByRoot` from the registry, a staging directory below `realpath(tmpdir())` (a path with a symlink is refused: "Original observation physical ancestry required") and runs `service.run(job)` for a job from `ownerJobV1`. CLI: `bun 🕸️graph/📥️inference/🔬️owner-harness/📜️cli.mjs <workspaceRoot> [--selected build] [--trim <MB>] <ownerRoot>...`.
- E2/E8, the cause of the 65 to 157 s medians: a farm child dropped ALL its memos after every job, because one warm owner leaves 255 to 275 MB of managed memory (heap plus external) and the retained budget was max(64 MB, 10 percent of 1536 MB) = 153 MB (`trimRetainedV1` in `👷️worker`). Every job then paid the cold walk (12 s of processor time on this host, 4 to 10 times that under load 40). The budget is now max(384 MB, 30 percent of the reservation). A worker whose reservation is below about 900 MB should not run the full inference at all (rss 900 MB with 275 MB managed).
- Pool children (`🌐️owner-pool/🧒️child`) recycle by `recycleMegabytes`: each recycle is a cold start of 12 s CPU; measure how often it fires on the workers before tuning it (not measured here).
