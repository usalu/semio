# Package H: downloads and dependency installs happen once per fleet

Paths: `LIB` = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/`, `FF` = `LIB/⚡️caching/🚀️bootstrap/🛰️fleet-fetch/`, `RC` = `LIB/🏗️build/🌐️remote-cache/`, `T` = this ticket folder. Scripts (landing, patches, proofs) are in `T/🧰️scripts/H/`. Landing record: `T/landings.md` ("Package H landing").

## 1. What was built

### Fetch layer (`FF`, schema `FF/🧬️schema/🔣️.json`)
One function family keyed by the sha256 of the artifact:
- `pinnedFetchV1(context, {url, sha256, bytes?}, init)` is a drop-in `fetch`. Order: group store (`<store>/v1/fleet/fetch/<aa>/<sha256>`, read in place, no second copy) -> cache server content-addressed store (`GET /<instance>/cas/<sha256>` with the fleet credential from package A's `resolveRemoteCacheV1`) -> upstream. A hit is verified (size, sha256; the proof is remembered per machine by size and mtime in `.cache/f/fetch-verified`). On a miss the body streams to the caller while it is hashed and staged; when hash and size match the pin it is renamed into the store (no copy) and PUT to the cache server (if <= 256 MiB). A non-matching body is passed on and never published. A `Range` request or non-GET passes through.
- `fleetBlobBytesV1` / `fleetBlobPublishBytesV1` / `fleetBlobOpenV1` / `fleetBlobPublishFileV1` for callers that fetch by ranges or files.
- Every fleet step has a timeout and returns "miss" on any failure; `SEMIO_FLEET_FETCH=off` disables the tiers; `SEMIO_FLEET_FETCH_LEDGER=<file>` appends one JSON line per get/put (`source` store/http/upstream, bytes, ms): this is the byte counter of the proofs.
- Pins that exist now (sha256): bun runtime (launcher registry, already), binaryen, bazel, cmake/uv/ninja (native tools registry, already), tectonic archive and the 500 TeX bundle files (print, already), **rustup-init 1.29.0 for all 8 host triples (added to the rustup schema `Protocol.bootstrapSha256`)**, **the dated Rust distribution manifest `2026-07-20` (added as `distributionManifestSha256`)**, every toolchain archive (pinned by `xz_hash` inside the pinned manifest), every crate (`Cargo.lock` checksum). A toolchain date without a manifest pin falls back to the official sidecar `.sha256` from upstream (never from a mirror), so a toolchain bump does not break provisioning; add the pin to make it fully repo-pinned.

### Wired call sites (anchored edits, all additive)
bun runtime (`🛠️tools/🟦️bun`), binaryen (`🕸️wasm`), bazel (`🏗️bazel/📜️script.ts`), native tools (cmake, uv, ninja: port `fetch(url, signal, pin?)` in both real ports), rustup-init + manifest + every toolchain archive (`🦀️rustup/📥️bootstrap`, `📥️installation`; the sidecar download for rustup-init is gone, the pin replaces it), print (tectonic archive through `fetchPrintHttpsV1`'s fetcher, each of the 500 TeX bundle files by its own sha256 before the Range request), and the Go launcher (`🚀️launcher/📦️packages/🐹️go`: new member `🛰️fleet-store`, one hook in `runtime-provision` `fetch`: the runtime archive is taken from the store when present and published after a verified download; works before any JavaScript runtime exists).

### Crates (`FF/🦀️crates`)
`Cargo.lock` pins the sha256 of every `.crate`. Before `cargo fetch` the locked crate files are placed from the fleet into the Cargo home's `registry/cache/index.crates.io-*`; after the fetch the files that came from crates.io are verified against the lock and published. Hooked in `LIB/🏃️process/🦀️cargo/📥️dependencies/🟦️.ts` (skipped for `--offline`). Decision "vendored sources vs this": a source replacement or vendoring changes the registry directory name, hence `CARGO_MANIFEST_DIR` and the rustc argv of every dependency, which would break package B's portable unit keys; placing the cache files changes nothing Cargo sees.

### Install state once per lock state (`FF/📦️install`)
- Key = sha256 of (lock projection digest from the existing adopt module, Bun version, platform, arch, producer recipe digest) = exactly the identity the adopt module already uses for local donors.
- `fleetInstallAcquireV1`: restore if a manifest is published; else take the fleet claim (`POST /<instance>/claim/nx/inst-<key>`, package B's routes, renewed every 20 s, at most 90 beats), re-check, and let the caller install; other machines `GET .../await` (25 s long polls, at most 30 min) and restore when the first one publishes. Claim route down, store missing, any error: plain local install.
- `fleetInstallPublishV1`: refuses a tree that contains an absolute or escaping symlink (so a non-relocatable tree is never shared), packs the clone roots (`node_modules`, `w/<i>/node_modules`) with the system `tar` through gzip level 1 into `<store>/v1/fleet/install/<archive sha256>.tar.gz`, then writes `<key>.json` (schema `InstallManifest`: runtime, shape from the installer's own scan, archive sha256/bytes) by rename, then PUTs the manifest as Nx entry `inst-<key>` to wake claim waiters. Keeps the newest 6 states, removes older manifests and unreferenced archives.
- `fleetInstallRestoreV1`: verifies the archive sha256 (once per machine), extracts, runs the installer's own `scan` and requires the publisher's shape (entries, directories, files, links, digest); any difference removes the placed roots and answers "not restored".
- Hooked in `📦️dependencies/💾️storage/🟦️.ts` right next to the local adopt: local donor first, then fleet restore/claim, then `bun install`; publish after `adoptSeal`; also publish (skipped when already published) in the "current generation reused" branch so a machine that already has the state seeds the fleet.

### Pass-through mirror (`RC/🪞️mirror`, in the cache server process)
`GET/HEAD /mirror/<ecosystem>/...` for `rustup` (static.rust-lang.org), `npm` (registry.npmjs.org, tarball URLs rewritten to the mirror), `go` (proxy.golang.org). Single-flight per path, immutable paths kept forever (dated dist files, `/-/*.tgz`, `@v/*.info|mod|zip`), other paths revalidated by etag after 300 s and answered stale when the upstream is down, range requests, LRU budget (64 GiB default), bodies stored verbatim (clients verify). GET is open (no token) because tools cannot send our bearer token and the content is public and client-verified. The server mounts it with `--mirror-directory <dir>` (on by default for a group server, `--no-mirror` to disable); the route prefix `mirror` is reserved.

## 2. The absolute links: what creates them, and what changed
Found. Every link of a dependency generation is published through one primitive, `publishBinding`/`publishPreserving` of `🔨️modules/📁️filesystem/🧾️observation/📁️descriptor` (FFI `symlinkat` on POSIX, NT reparse points on Windows). Its contract is "bounded absolute normalized binding target" (`captureArtifactRelativeBindingTargetV1` refuses anything else; Windows junctions cannot be relative at all). Callers, all in `📦️dependencies/💾️storage`: the repo-side `<package>/node_modules -> <store>/j/<gen>/w/<n>/node_modules` and its `.nx/installation` twin, workspace edges, borrowed providers and the singleton aliases (`react` etc. inside the generations). The links under the checkout that point at `/Users/ueli/Documents/semio/...` are **not replicated by the daemon** (`node_modules` is ignored by `.gitignore:69`, the replica honours the ignore); they are leftovers of the initial seeding of `/Users/Shared/semio` from that checkout. On a machine a sync recreates them for its own root: the binding step publishes when `expected.target !== binding.targetDirectory`, and the target is computed from that machine's store root.
Decision: I did not make the FFI binding relative (it would change a sealed contract used by receipts, junctions and 8 comparators, none of which I can execute here). Instead the path dependence is removed where it matters for sharing, in the install pack:
- `fleetInstallPublishV1` accepts absolute links that point **into the dependency store of the publishing checkout** and still refuses any other absolute or escaping link; the manifest records the publisher's `storeRoot` and a path-independent `fingerprint` (every entry with kind, size, execute bit and link target with the store prefix replaced by `<store>`).
- `fleetInstallRestoreV1` rewrites those links to the restoring checkout's store root (`rewriteFleetInstallLinksV1`), recomputes the fingerprint and requires equality, and compares the installer's own shape (counts; plus digest when the store root is equal).
- Test `absolute links into the dependency store are published and rewritten...`: a tree published with store `/stores/default` is restored with store `/elsewhere/.cache/b/d/m`, the link reads `/elsewhere/.cache/b/d/m/j/owner20/...`; a link outside the store stays refused. So a restored tree is valid at any worktree path (including the move to `~/Documents/semio`). Windows junction trees are not packed (tar does not carry them): unverified on Windows.
Open for the owner of the binding primitive: relative targets on POSIX would remove the need for any rewrite; the stale leftovers disappear at the next sync of each machine.

## 3. Mirrors wired, and why the keys do not move
Placement: the mirror is a **transport setting of the child process**, not of the recipe or the ambient observation. `fleetMirrorTransportEnvironmentV1(manager, env, ambient)` (`FF/🪞️mirror/🟦️.ts`) returns the settings; they are merged (a) into the `bun install` child environment at the spawn in the dependency storage, (b) after the sealed `environment.set` and before `overrides` in the generic manager `environment()` (so the Go manager gets `GOPROXY=<base>/mirror/go|https://proxy.golang.org,direct`, `|` = fall back on any error, the recipe literal stays untouched), (c) into `repoToolCacheEnv` for `PLAYWRIGHT_DOWNLOAD_HOST`. A user's own registry (`BUN_CONFIG_REGISTRY`, `npm_config_registry`) always wins. `base` comes from `.cache/f/mirror-state.json`, written by a 1.5 s probe of `GET <cache>/mirror/healthz` (`refreshFleetMirrorStateV1`, run at the start of each dependency generation); no healthy probe in the last 5 minutes, an old server without the mirror, `SEMIO_FLEET_MIRROR=off`: no setting at all, upstream as before.
Proof of unchanged keys (`FF/🪞️mirror/🧪️tests`, 2 pass): `observeJavascriptDependencyGenerationProducerV1` (the producer identity of a generation) returns byte-identical results with the mirror state healthy and absent while the transport environment is non-empty (`BUN_CONFIG_REGISTRY`, `GOPROXY`); the control run shows the observer does see `BUN_CONFIG_REGISTRY` when it is in the ambient environment, so the test would catch a leak. Real tools through the server mirror: proof 4 above (Go and Bun, 0 upstream bytes second time, Go falls back with the mirror stopped).
- **uv: not wired, and measured why.** Experiment with real uv 0.11.15 and a mirror index: `uv sync --locked` with `UV_DEFAULT_INDEX` pointing at the mirror fails ("The lockfile needs to be updated"); only `--frozen` accepts it, and then uses the lock's absolute `files.pythonhosted.org` URLs, bypassing the mirror. The uv manager runs `--locked` (`🐍️uv/🔣️.json:114`), so any index mirror breaks the lock check. uv's own cache is layout-keyed by index URL. A fleet mechanism would have to seed `archive-v0/<hash>` from the wheel hashes in `uv.lock`; I did not build that.
- **Playwright**: route `/mirror/playwright/...` (immutable `/builds/`), `PLAYWRIGHT_DOWNLOAD_HOST` set through `repoToolCacheEnv`. Trust caveat: Playwright publishes no hash, so this tier trusts the LAN mirror's fill (TLS to the CDN at fill time); everything else here is hash-verified by the client. Not exercised against the real CDN (a 550 MB browser download); unverified.
- **Nx package, sha512**: `pinnedFetchV1` now accepts 128-hex (sha512) pins (`pinFromIntegrityV1` converts `sha512-<base64>`); store tier only (the Bazel CAS route is sha256). Wired in `acquireNxPackageSourceV1` for the real host. Test: a sha512 pin is downloaded once, the stored file equals `shasum -a 512`, the second machine fetches 0 bytes.
