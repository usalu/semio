# Package E: Rust offload from the rustc wrapper

Module `R = 🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🏗️build/🌐️remote-execution/🚀️offload/` (new, schema first: `R/🧬️schema/🔣️.json` holds the policy, the event and manifest shapes and the EN/DE texts). Landed twice under the lock, see `landings.md` ("Package E landing", "landing 2"). Scripts: `🧰️scripts/E/` (`worker.py`, `command.py`, `wrapper.py`, `flag.py`, `acquire.sh`, `live-drill.ts`).

## Assumptions and contracts (as written early, still true)

- A: execution endpoint = `SEMIO_REMOTE_EXECUTION_ENDPOINT`, else `readFleetExecutionV1`; cache endpoint, instance, bearer token = `resolveRemoteCacheV1`. The fleet token is the gRPC bearer token too.
- D: matched properties `Arch`, `OSFamily`, `semio-target`, `semio-toolchain` (first 16 hex of sha256 of the exact `rustc -vV`); control properties `semio-offload=if-idle`, `semio-origin`; status 8 in the ExecuteResponse = "no idle machine", any other non-zero = run locally; worker seam `SEMIO_REMOTE_EXECUTION_HOST_VIEW`; counters in `.cache/f/build-counters.json` key `offload`.
- B: the offloaded result goes through the same `publishUnitV1` plus `shareFleetUnitV1` the local compile uses, under the unit key the requester computed. B landed in the middle of my work; my wrapper patch sits on its fleet hold (claim), so an offloaded unit is claimed, compiled elsewhere, published and shared exactly like a local one. Portability: B's rules were not consumed (I did not find an exported predicate); the offload has its own conservative rules below.

## What was built

1. Decision (in `📜️script.ts`, `offloadUnitV1`, only on a miss that is not bypassed or focused): mode `SEMIO_OFFLOAD=always|auto|never` (default auto; flag `--offload=…` on `repo run|run-many|affected|cargo`, parsed by `extractOffloadFlagV1`, handed over as that variable). Auto offloads only when this machine would wait: (a) `slotQueueMillisecondsV1` (all compile slots held and the oldest waiter older than 1.5 s) or (b) the host's single admission decision `evaluateHostCapacityV1` (request for one unit of 768 MB, current host sample, empty ledger) says wait (pressure, swap, load, memory, files). The verdict is shared for 2 s per machine; a fleet refusal is remembered for 3 s so a build of hundreds of units asks the fleet about once per window. Test seam: the wrapper takes `ports.admission={probe,policy}`, i.e. an injected host probe and policy, no environment backdoor.
2. Action (`📜️action`, `🗺️paths`, `🌳️inputs`): command `/bin/sh -c <script> semio-rustc <rustc args>`; the script writes the worker root into `.semio-offload/root`, exports `CARGO_MANIFEST_DIR`, `CARGO_MANIFEST_PATH`, `OUT_DIR` as `$PWD/<relative>`, sets `HOME`, adds `-Clink-arg=-Wl,-oso_prefix` on macOS and `--remap-path-prefix $PWD=/semio/root`, then execs the worker's rustc. Inputs: the package directory (bounded 8192 files / 512 MB), files named by an earlier dependency file, `OUT_DIR`, the direct externs and their transitive closure from the `-L dependency=` directory (found by the 16-hex `extra-filename` each artifact records, plus the `.rmeta` beside an `.rlib`). Every requester path in arguments and environment is replaced by a virtual one (`.semio-offload/{o,d,d1,x0,p,g}`) or made relative; `-C incremental` is dropped; unmappable units are declined with a reason (`-l`, `-L native`, `-o`, `--sysroot`, absolute linker paths, any environment value naming the checkout, inputs outside the checkout and the package). The action is path-independent: two checkouts at different absolute paths give identical arguments, environment and virtual file list (test). The toolchain is NOT shipped: the worker offers `semio-target`/`semio-toolchain` (D) plus `semio-rustc-target-<triple>` for each target of its sysroot, and a tool table (`worker` option `tools`, `SEMIO_TOOL_RUSTC=@tool` in the action) whose sysroot the macOS sandbox may read (`readable`). Outputs: the directory `.semio-offload/o` and the root marker.
3. Stored exactly once: the worker uploads only the output blobs to the CAS (content-addressed, the same bytes the requester then references); the unit entry is published by the REQUESTER after translating the dependency file, streams and paths back to its own, with its unit key, under its fleet hold. Reasons: only the requester knows its lane root and its key; the worker cannot rewrite templates; B's claim is held by the requester, so a worker-side upload would race it. The scheduler's action cache additionally answers an identical action (same sources, same inputs, even from a checkout at another path) without any worker.
4. Jobserver and locks: while the remote result is awaited the wrapper writes its implicit job token back into the build's named pool (`fifo:`; the repository launcher's pool and GNU make 4.4's) and takes one back afterwards (30 s bound); pipe, semaphore and absent pools keep the token (not served without blocking). The wrapper holds no slot while away (the offload path never takes a compile slot) and only the per-key unit claim, which exists for exactly that key either way. Cargo's own fine-grain lock of the unit is held for the duration, like a local compile; nothing else is locked.
5. Cancellation and failure: SIGINT/SIGTERM abort the Execute call, which cancels the action (the worker kills the process tree); the wrapper returns 130/143. Timeouts: cache probe 1.5 s, upload 90 s, taken by a machine 8 s, run 25 min, download 120 s, per request 20 s. Everything else is a local fallback: unreachable cache (probe, remembered), no endpoint, no credential, refusal, timeout, a lost worker (D reschedules once, then status 14), path-dependent output, an output missing, a worker error that looks like a missing input or linker (E0463, "can't find crate", "linking with `cc` failed", "Executable not found"). A real compile error comes back as the compiler's exit status and streams, translated to the requester's paths.
6. Visible: `x/offload.progress` of the unit cache root (one English and one German line per decision, e.g. "Unit c offloaded to wA (210 ms)." / "Einheit c auf wA ausgelagert (210 ms)."), `x/offload.jsonl` (schema `Event`), the unit event `miss … offloaded:<origin>`, and the counters `offload.{out,refused,fellBack}` (lock-free count files under `.cache/f/offload-counters/`, mirrored into `build-counters.json`).

## What is offloaded, and what is safe

Offloaded: rustc invocations of crate types lib, rlib, proc-macro and bin (not cdylib, dylib, staticlib; those stay local like B's bypass) on macOS and Linux, without native link flags. Build-script and proc-macro EXECUTION happen inside cargo (build scripts: on the requester, never offloaded; their compile is an ordinary bin unit and may be) and inside rustc (proc-macros: on the worker, loading the dylib it was given; same OS, arch and toolchain commit, so it loads: tested). The result is never stored when it depends on the worker: every non-text output is scanned for the worker's root path (it embeds e.g. `env!("CARGO_MANIFEST_DIR")`); then the unit compiles here (test). Windows is excluded (the action needs `/bin/sh`).

## Proof

Offload `🧪️tests/🟦️.ts`, 17 pass (150 expects): schema in two validators, mode, compiler identity against a Python sha256, dependency closure, bounded walk, path independence of the plan across two checkouts, declines, text translation, admission wait/admit through an injected probe, memo windows, slot queue estimate, token lease on a real fifo, counters (exact under 40 concurrent bumps, other fields kept), the flag, `CARGO_MANIFEST_PATH`, an unreachable cache (declined in under 5 s, then remembered, then no-endpoint).
Offload `🧪️tests/🌐️cluster/🟦️.ts`, 8 pass (about 100 s; run 6 times in the live tree, 5 green; the one red run was a test-only artifact, an orphaned compiler of the previous test matched by the cancel test, fixed by a unique crate name and a reaper): scheduler and cache in the test process, two worker PROCESSES (`🏃️entry`), real sandbox, real rustc, checkouts under different temp paths:
- local admission forced to wait (critical-pressure probe through the real `evaluateHostCapacityV1`): the crate compiles on a worker, `rustc-calls.log` of the local machine is empty, three artifacts exist, exactly one unit entry stored, progress line in both languages;
- calm host stays local in auto, `never` stays local;
- a crate with warnings and a crate with an error give stdout, stderr (JSON diagnostics) and exit status byte-identical to a local build (paths of the checkout neutralised), and the failed unit leaves no artifacts;
- a proc-macro crate links remotely and its dylib loads into a local compiler;
- a result embedding the worker's path falls back to a local compile whose rlib holds the requester's path;
- killing (SIGKILL) the worker that runs the unit mid-compile: the unit still completes (D rescheduled it on the other worker);
- SIGTERM to the wrapper: exit 143 and the remote compiler is gone;
- a second checkout at another absolute path gets the same unit without any compiler (fleet unit cache from B or the action cache), no new assignment.
Existing suites: sandbox 3 pass; unit-cache 26 pass (they run real cargo through the changed wrapper); remote-execution `command` 5 pass 2 fail and `scheduler` 1 pass 5 fail, identical before my landing (D's work in progress, not mine).
Live drill with real cargo (`🧰️scripts/E/live-drill.ts`, this machine, scratch workspace, scheduler/cache/two workers local, jobserver as a fifo, `-j3`): 8 independent crates of 2500 functions plus a top crate, `SEMIO_OFFLOAD=always`: baseline 4.8 s with 10 local rustc calls, offloaded 3.5 s with 1 local call (cargo's own probe); origins `drill-a`: unit0 unit6 unit1 unit3 top, `drill-b`: unit7 unit2 unit5 unit4; eight units of about 2.2 s each finished in 3.5 s wall, which needs more than the three at a time `-j3` allows, so the token lease works under real cargo (not measured directly). With 12 crates (more units than worker slots): 8 offloaded, 3 refused by the scheduler (`No other machine has headroom`), 2 skipped by the refusal memo, all 5 compiled locally; 7.3 s local against 6.0 s. These two workers share this machine with the requester, so the times only show that nothing is slower, not what a second machine gains.

## NOT verified (and why)

- The live run against other Macs: not possible yet. `cache-facts.json` has no `execution` endpoint, no scheduler or worker process runs on the fleet, so `GET /v1/fleet/load` has no remote rows. Reproduction once D publishes it, on any machine of the fleet:
  `repo cargo --offload=always --store=shared --configuration=prototype -- build -p <small crate>`, then `cat <unit cache root>/x/offload.progress` and `x/offload.jsonl` (origins per unit), `curl -H "Authorization: Bearer $TOKEN" http://<group server>:8981/v1/fleet/load`, compare with `--offload=never`. Without a fleet, `bun 🧰️scripts/E/live-drill.ts 8 2500` reproduces my numbers.
- `repo cargo …` itself does not run on this machine today: it stops before cargo starts at `hdiutil resize -size 98304m .cache/b/r/fixed.dmg` (exit 22), with and without my flag, for both stores. The flag is accepted (the run gets as far as the same failure); the wrapper path under real cargo is covered by the unit-cache suite and the drill.
- Linux workers (bwrap) and Windows: not run; the Linux action is the same, `readable` is a no-op there because bubblewrap binds the host read-only.
- Package B's remote key / upload of an offloaded unit was not observed end to end (B's uploader is asynchronous and was not running); the offloaded unit passes through B's `shareFleetUnitV1`.
- Large inputs (the package directory of a real workspace member with big assets) are bounded, not measured. The extern closure reads the metadata of every dependency once per offloaded unit; not optimised.
- `repo` help/catalogue does not list `--offload` (the invocation tests that would show it fail to load here for an unrelated import).

## What the other packages must know

- D: a freshly started worker reports `headroom: false` for its first seconds; an offload in that window is declined (correct, falls back). `semio-origin` is taken from `remoteExecutionOriginV1(workspace)`, so the workspace root must reach the wrapper (`SEMIO_UNIT_CACHE_WORKSPACE_ROOT` or `SEMIO_WORKSPACE_ROOT`); without it a requester is not excluded from its own offload. The worker now needs the `tools` table to run any rustc action: `workers` fills it from the rustc of its working directory, so start workers inside a checkout with the pinned toolchain.
- B: nothing to change; `publishUnitV1`/`shareFleetUnitV1` are called with the same shapes. If B adds portability predicates, `offloadRustcUnitV1` can call them in front of `planOffloadV1`.
- Both: the counters file `build-counters.json` is rewritten from count files by B's writer and by mine; both derive absolute values from monotonic files, so a lost race only shows a stale number until the next event.
