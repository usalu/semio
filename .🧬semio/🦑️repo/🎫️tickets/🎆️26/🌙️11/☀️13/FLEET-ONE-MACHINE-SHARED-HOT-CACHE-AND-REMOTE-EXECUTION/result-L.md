# Package L: security (roles, provenance, confinement, network, bounds)

Module roots: `RC` = `…/🏗️build/🌐️remote-cache`, `RE` = `…/🏗️build/🌐️remote-execution`. Scripts: `🧰️scripts/L/` (patch scripts, `republish-facts-without-secret.ts`). Owner steps: `prompts-security.md`.

## Correction of a premise
The "per-origin private key" of `machine.json` is not secret: `key` is a 32-hex home key, `machine.json` is mode 0644 and the same value is in `origins/<id>/home.json` in the store. It was NOT used. Each machine instead generates its own Ed25519 keys.

## What was built
1. Roles and per-origin identity (`RC/🛰️fleet/🪪️identity`, schema first in its `🧬️schema`). Per machine, in `.cache/f/identity/` (dir 0700, files 0600, never replicated): an origin key plus one key per role (`cache-read`, `cache-write`, `submit`, `worker`, and `admin` only for `<group>-server`), each private key in its own file. The public halves, signed by the origin key, are published to the machine's own `origins/<id>/fleet-auth.json` (zero-touch: done by `refreshFleetCacheFactsV1`, i.e. on the first build, and by the sidecars). Requests carry `Authorization: Semio-Fleet o= r= a= t= n= s=` (Ed25519 over audience, origin, role, time, nonce, method, target, body hash); no secret crosses the wire, so no TLS/CA (active man-in-the-middle on plain HTTP can still alter unsigned GET responses and `nx`/`cas` bodies: accepted, said plainly). Servers: audience-bound, ±60 s clock (client learns the offset once from `x-semio-time`), no signature from before the server started, replay cache, role per operation (read: cache-read/write/admin; write: cache-write; execution gRPC: submit; worker API: worker; load/status: any execution role), admin only from the admin origin. Registry reads the store (`origins/*/fleet-auth.json`, `retired.json`), refresh 5 s, unknown origins looked up alone at most once a second; retire revokes within seconds; the first origin key is pinned (server-private `pins.json`), a different key needs a rotation proof signed by the pinned one or a retire plus re-admit. `repo remote-cache rotate` now replaces this machine's role keys (origin key stays). Operator bearer tokens (`/etc/semio/remote-cache.env`) are accepted only from loopback when fleet identities are configured. The shared token is gone from the facts (`auth` replaces `credential`; facts mode 0644, no secret).
2. Provenance. `RC/🧾️provenance`: uploader origin and time per entry (journal), `ac` PUT by a different origin with a different set of output digests is refused 409 and recorded as a divergence with both fingerprints, the first stays; identical content is accepted; shown in `GET /status` (`divergences`, `fleet.origins`, `fleet.denied` by reason, no keys). `ac`, claim and slot bodies must carry a signed body hash (400 otherwise); `nx` bodies are hashed in flight when the client bound one. Claims are scoped to the authenticated origin (another origin cannot renew/release with the same owner string) and capped (`maximumLifetime` 30 min, 4 x expected cost, floor 2 min, 30 s cool-off; independent Python model extended and agrees on 400 random sequences). Offloaded results: the scheduler stamps the worker with its authenticated origin (registration must name the signer's origin) and the requester reads "executed by" from the scheduler's message, not from the worker's metadata.
3. Confinement. `RE/🧱️actions`: a worker runs only the declared rustc action (`/bin/sh -c <fixed script> semio-rustc` + allow-listed rustc flags, relative paths only, no `-C linker`/`link-arg`, `-Z`, `@file`, `--sysroot`, `--print`, `-o`, `.json` target, no loader/shell-startup/rustc-control environment, only the declared `SEMIO_` variables, the two virtual output paths). Policy `worker.actions` defaults to `rustc`; `any` is refused at start on a worker without a confining sandbox (test seam `SEMIO_REMOTE_EXECUTION_UNCONFINED_ANY=I-ACCEPT-THE-RISK`, used only by tests); an unconfined worker (Windows, fallback) therefore runs the closed set or nothing (on Windows `/bin/sh` does not exist: nothing). Linux bwrap no longer binds `/`: system directories read-only (links kept), declared tool directories, private `/tmp`, the action root, no network. macOS profile additionally hides `/private/etc/semio`, `/private/var/{root,lib,db,at}`, `/private/etc/ssh`, Keychains and the firmlink spellings. Plain statement: proc-macro and build-script code of the repository (shipped as inputs, loaded by rustc) runs on the worker; that is inside the trust model (whoever writes the store already changes the code every machine runs) and on macOS/Linux it runs sandboxed without network.
4. Network. Scheduler binds only the fleet interface (the address the facts publish, inside `SEMIO_FLEET_NETWORK` or the topology network; wildcard refused when fleet identities are on); cache server `--host fleet` or a wildcard is narrowed to the fleet interface; every request from outside the CIDR (loopback excepted) is refused with 403 before any credential is read, gRPC included (runtime `serve` now passes the peer address).
5. Bounds. Claim lifetime (above); action timeout cut to `maximumActionSeconds` 1800; queue 4096; workers 256; worker API body 16 MiB; table rows bounded by origins; mirror: at most 8 parallel upstream fetches, redirects only inside the registrable host or `githubusercontent.com`, https only, 3 hops, query strings no longer part of the key, the unpinned playwright mirror removed (client no longer points at it).

- `nx`/`cas` bodies and gRPC message bodies are not bound to the signature; plain-HTTP active man-in-the-middle is out of scope (no TLS decided).
- The Nx e2e test (needs `SEMIO_TEST_NX_*`) was adapted but not run. READMEs (EN/DE) still describe the old `rotate`.
- Nothing was changed on other machines; they pick the code up themselves. Machines on the previous code build locally until then.

## What the other packages must know
- Never read `resolution.token` as "authorised": use `tokenFrom !== "none"`; build every client request with `remoteCacheFetchV1(environment,{root})` (it signs only for facts-named hosts; role by method; `audience:"execution"` + `roleOf` for the scheduler).
- Worker options changed: `actions` defaults to `rustc`; tests that run arbitrary commands need `actions:"any"` plus the test seam.
- Scheduler options need `maximumActionSeconds`; server/handler `peer` is the second argument of `fetch`.
- The cache server refuses wildcard binds when fleet identities are on; `ac` PUT bodies must be bytes/strings (bound hash), not streams.
