# UI Introduction: Stored Poster Frames

## What the placeholder was
`🪟️presentation/🌐️browser/🟦️.tsx` contained `Thumbnail({symbol})`, an inline SVG pictogram (house outline with three red arrows for `air`/`heat`/`cool`, crossed circle for `physics`, three bars for `balance`, plus bim/excel/grasshopper/optimization/parametric glyphs). Every overview card at every level (course, topic, lesson, chapter) and every chapter window without a snapshot drew it. `symbol` lived in the catalog `🔣️.json`, its schema and `📚️collection.enrich`. All of it is deleted (a test guards that `Thumbnail` and `symbol` never return).

## New mechanism (final design)
- **Reference**: every card has a `poster` = a chapter scene id. Chapter card: itself. Lesson card: manifest lesson `poster.chapter`, default its first chapter. Topic and course card: first poster below. Topic without lessons (Parametrics): explicit localized empty card, no pictogram.
- **Moment**: end state of the chapter's last segment (the summary state), or manifest chapter `poster: {segment, animation}` (`animation` = stop after that Manim animation; mandatory for a partial `clauses` segment). Schema `🎬️clip/🧬️schema/🔣️.schema.json`, validated in `runtime.load_manifest`.
- **Stored asset** (checked in, not generated at overview time): `<lesson clip folder>/🖼️posters/<chapter>.png` (640x360) plus `<chapter>.json` sidecar (moment, workspace-relative source fingerprints, capture language/profile/audience, image sha256). Path rule: the folder of the lesson's manifest `script`, sub-folder `🖼️posters`; all paths < 256 chars (tested). The folder is excluded from segment source fingerprints (no circularity).
- **Overview reads only assets** (`posters.resolve`): missing or damaged asset = `FileNotFoundError` naming the chapters and the command; stale (any source changed since capture) = ONE warning line listing them, used as is, never re-rendered. The browser additionally throws `Missing poster image for ...` if a card has no image.
- **By-product capture** (`posters.prepare`, called in `compose_videos` after the chapters are assembled and before any overview/zoom frame): for every chapter of this render the poster frame is the last frame of the poster segment clip the render produced anyway (zero extra scene renders), refreshed atomically when stale. Sibling chapters not selected by `--chapter` and all other lessons use their stored assets.
- **`script.ts posters --language --profile [--audience] [--video ...] [--chapter ...] [--jobs N] [--force] [--output-root]`** (`🖼️posters/🖌️capture/🐍️.py`): per chapter, skip if not stale; else take the last frame of an up-to-date segment clip in the output root; else one single Manim frame (`--save_last_frame`, no lesson render). Progress lines, global `--jobs`, cancellation through the shared `ToolSession`/process-tree kill.
- Removed: shared-cache poster rendering, file locks, per-render poster rendering of foreign lessons.
- Browser: `render.mjs` serves `catalog.posters`, exposes `posters`/`empty_cards` DOM metadata; `🟦️.tsx` `Poster` draws 16:9 (`object-fit: contain`, max height per grid rows). Zoom still lands on the chapter's first frame as before.

## Emptiness guard, declared moments, roadmap (follow-up)
- `posters.coverage(image)`: share of non-background pixels (background = most frequent colour) inside the content area (5-95 % wide, 15-85 % high: title chip, references and caption excluded), minimum 3 % (`MINIMUM_COVERAGE`). `store` refuses an almost empty frame naming the chapter (nothing written); `resolve` also refuses almost empty stored assets. JSON cases in `🖼️posters/🧪️tests/🔣️.cases.json` (`coverage`), tests for refusal, per-case acceptance and a check that all 47 stored assets pass.
- Roadmap guard: `chapters()` raises if a poster segment is a `*Fahrplan*` scene; none of the 47 posters is a roadmap.
- All EnergyBalance segment end states are fade-outs (0 % content), so the manifest now declares moments: EB_01 seg 1/anim 24 (house with system boundary), EB_02 seg 1/anim 32 (monthly bars), EB_03 seg 2/anim 24 (load duration curve), EB_04 seg 2/anim 28 (boiler efficiency), EB_05 seg 2/anim 28 (primary energy bars), EB_06 seg 1/anim 16 (class scale), EB_07 seg 1/anim 24 (hydraulic rooms); lesson `energy_balance` uses `poster.chapter` = `EnergyBalance_05_Primaerenergie` (balance bars). Candidates were chosen from a contact sheet of per-segment/animation renders (`🗑️generated/cand-sheet2.png`).
- All 26 energy posters recaptured after the roadmap change (`script.ts posters`); contact sheet of all 47 stored posters viewed (`🗑️generated/contact-sheet.png`): every poster shows content; EB_01 (4.1 %) and Excel_02 (5 %) are the lightest but legitimate pictures.
