# Launcher store recovery after a reboot

## Root cause
After a reboot the dependency store disk image (`.cache/b/d/fixed.dmg`, mounted at `.cache/b/d/m`) is detached, so the managed link `node_modules` -> `.cache/b/d/m/j/<generation>/node_modules` dangles. The launcher hook `Host.Prepare` (`prepareWorkspacePackageLinks` -> `PrepareWorkspacePackageLinks` -> `ClassifyWorkspaceNamespace`, `workspaceCanonicalDirectory` does `os.Stat(endpoint)`) returned the raw `stat ...: no such file or directory` before the TypeScript implementation was started, and `speaker.fail` printed it as "Unexpected error". The owner of storage images (TypeScript, native-build storage and dependency publication/setup) therefore never ran. The error named no remedy.

## Fix
- `ClassifyWorkspaceNamespace`: a link whose target is missing is classified `detached` (still `authority:false`, `readiness:false`, `contentObserved:false`) when its target is exactly `<declared store>/<generation prefix>/node_modules` (absolute or relative link). `PrepareWorkspacePackageLinks` leaves it untouched, so the implementation starts and its existing owner re-attaches and re-syncs.
- Any other dangling link is refused with the bilingual registry text `namespaceDangling` (en/de) that names the link, its target and the remedy: delete the link, run `repo dependencies sync --all`. Occupied, escaping and foreign namespaces are still refused as before.
- Files (launcher module): `📦️packages/🐹️go/📦️workspace-namespace/🐹️.go`, `📦️workspaces/🐹️.go`, `🗂️runtime-registry/🐹️.go` (RequiredMessages), `🗂️registry/🔣️.json` (new text), `📦️workspaces/🧬️schema/🔣️.json` (`detached`, `DetachedCase`), `📦️workspaces/🧫️fixtures/🔌️detached.json` (new language-agnostic corpus), tests `🧪️tests/🏷️managed-workspaces/🐹️.go` and `🟦️.ts`, `🧪️tests/🗂️registry-contract/🐹️.go`, `README.md` (en/de).

## Evidence
Go tests, assembled like the install script (sources and tests flattened into one module, run in a scratch dir, temp-directory sandboxes only): `TestWorkspaceDetached` (6 corpus rows: detached absolute, detached relative, foreign store, wrong name, wrong generation, wrong depth; refusals checked bilingual with remedy; link never mutated), `TestWorkspaceDetachedHandsOverToTheImplementation` (Execute reaches hand-off with a dangling managed link), `TestWorkspaceManaged`, `TestEveryPrintableTextIsBilingual` all pass.
The full launcher suite still has 3 failures unrelated to this change, present with healthy node_modules in /Users/Shared/semio: `TestWorkspaceLinksPublishNeverReplacesAnotherTarget` (macOS rename over a symlink), `TestRegistryShapeChangesBumpTheContract` (schema digest drift), `TestRouteVectors` (fixture vs operations catalogue verbs).
Unverified: the TypeScript test (bun/ajv not runnable without node_modules in Documents); an end-to-end re-attach by the implementation from a detached store (not exercised, per scope). Installed binaries were not rebuilt or replaced; the CLI binary embeds the launcher, so it picks up the fix on the next supported `repo-mcp-go` build and install.
