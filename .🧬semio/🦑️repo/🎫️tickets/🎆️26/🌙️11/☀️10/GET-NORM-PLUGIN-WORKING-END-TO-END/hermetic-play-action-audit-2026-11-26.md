# Hermetic Play Action Audit — 2026-11-26

No existing complete fleet action for the standards browser acceptance was found in the inspected Play targets and command-offload integration. This is a source inspection, not a remote execution or a worker capability measurement.

The repo-owned `@semio-tech/semio-tech-play:test-e2e-standards` target is a local workflow in `🏢️semio-tech/🎡️play/📋️project.json`: preparation depends on five plugin activations and browser dependencies, then a continuous `serve-standards-e2e` service precedes a live Playwright test. `🔨️modules/🧪️e2e/🟦️.ts` filters boot tests to standards variants; `🧪️tests/🎭️acceptance/🟦️.ts` derives them from `🔨️modules/🧩️runtime/🔣️.json`. The current selector matches 15 catalog variants. Playwright requires a supplied base URL and the service; this target is not itself a remote action specification.

A command action facility does exist: `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🏗️build/🌐️remote-execution/🚀️offload/🟦️.ts` packages declared input files, output paths, arguments and environment for an allowlisted tool. The command policy only admits wasm-opt, node, native-transpile, descriptor-emitter and build-script, with a restricted environment and input limits; inspected production use includes build-script offload. It does not supply a Play browser/Vite action or a browser capability tag. Worker command discovery advertises installed tool digest properties, including Node where found, and scheduling matches the tool digest and host properties. Actual currently available matching worker tags were not measured.

Most decisively, command actions require a confined sandbox without network (`👷️worker/🟦️.ts`, `🧱️actions/🟦️.ts`); the macOS sandbox denies `network*`, and Linux creates a network namespace (`🔒️sandbox/🟦️.ts`). Thus the existing contract does not establish the required Playwright-to-Vite loopback service. Enabling an unrestricted remote command would not be an authorized equivalent.

The command offload API permits an explicit peak-memory request and emits `semio-peak-mb`; Node's default policy estimate is 2048 MB, not the required 6144 MiB. The inspected command action interface does not declare a four-core reservation. A safe workflow would need a supported action contract that provisions and keys all browser, Vite, fixture and activation inputs, permits only its intended local service communication, requests the required memory and CPU, and selects workers advertising those capabilities. The present implementation does not demonstrate that contract.

The local `dist/♻️activation/standards/🔣️receipt.json` records five activation hashes but that directory contains only the receipt; it is not evidence of a complete transferable browser and application bundle. No browser, compiler, remote action, collector, or pressure test was run.
