# Declared-order `nested_patch!` (2026-11-25)

## Decision

Schema order is the canonical JSON key order of every norm diff patch (schema first; the TypeScript, protobuf and GraphQL twins already follow it). The Rust serialiser followed the macro groups instead (`set`, `within`, `optional`, `rows`).

## Dependency re-check (nothing depends on the old order)

- Binary diff form: opaque JSON payload (ksy `payload size-eos`), so only the JSON text order is visible.
- Proto twin numbers fields in schema order, SQLite and pack fixtures hold no diff, DSL has no committed diff.
- A repo-wide search for the patch keys (`stirrupsDiameter`, `En1992MembersPatch`, `En1994BeamsPatch`) outside the diff schema twins and the `diff.json` vector fixtures only finds the schema catalog (derived from the schema JSON) and the mutation sources, which build patches with named fields and `..Default::default()`.
- Top level `En1992Diff`, `En1994Diff` and all 17 `scalar_patch!` structs already match the schema order (checked with `nested-patch-order.py` and an inline script).

## Change

- Only two copies of the macro existed (en1992 and en1994 diff crates), and they were not identical: en1992 had `optional` and a `within` behind an `Option` object; en1994 had a `within` into an always present object. Both also had a copy of `scalar_patch!` and an unused or inlined `missing_target`.
- New shared home next to the norm users, the compliance crate (which already hosts `impl_norm_artifact_record!` for the same crates): `✏️s/🔌️plugins/📕️norm/⚖️compliance/🩹️row-patch/🦀️.rs` with `#[macro_export]` `scalar_patch!` and `nested_patch!`, plus hidden re-exports `__kernel`, `__value`, `__value_derive`, `__dsl_record_derive` in `⚖️compliance/🦀️.rs`.
- `nested_patch!` takes one ordered entry list `kind field: Type [= extra]`; the struct, commit, absorb, inverse and is_empty are generated by tt-dispatch per kind (`leaf`, `nested`, `nested_option`, `clearable` + `clear`, `rows`). The semantics are copied unchanged from the old groups (including the clear flag handling and the missing-target refusal).
- The two diff crate roots import `semio_s_plugin_norm_compliance::{nested_patch, scalar_patch}`; the row modules of en1994 reach them through `use super::*`. Local macro copies and `missing_target` are removed.
- Reordered declaration of five patches (generator: `nested-patch-order.py`, input is the schema JSON): `En1992MembersPatch` (52 keys), `En1994BeamsPatch` (40), `En1994SlabsPatch` (13); `En1992AnchorsPatch` and `En1994ColumnsPatch` were already in schema order.
- Unit tests in the macro file: declared key order, emptiness, absorb, inverse.

## Law review (`✏️s/🧪️tests/🧪️mutation-vectors/🦀️.rs`)

`key_order` scans quote-delimited tokens and keeps those followed by `:` after optional whitespace, handling escapes; the string values `"a"` are never followed by `:`. It runs only when produced and committed are equal as values, so a mismatch is a pure order breach. Correct by reading; the unit test covers whitespace, nesting, arrays and escaped quotes. Not compiled.
