# Norm Final-Link Layout Audit — 2026-11-26

The evidenced artifact-side candidate is a further **component boundary**, not a Rust package carve. `🌎️hub/🧩️compositions/📕️norm/🧩️extensions/📙️eurocode-materials/🦀️.rs` assembles EN 1995, EN 1996 and EN 1999 into one `PluginBuilder`, one closed app enum containing all six editor/viewer implementations, and three artifact activations. Its package manifest directly depends on all three families. `🧩️component/🦀️.rs` exports that entire assembly in one `cdylib`. Independently linking family components would remove the other families from each final's required closure, while retaining shared framework runtime in each. This is a credible reduction in final link input, but the peak reduction has not been measured; shared framework and changed code generation may dominate. Ordinary leaf crate splitting alone retains all three families in the same final and does not demonstrate a lower linker peak.

There is an existing design precedent in that same assembly: its documentation says it was separated from `norm` to stay below the wasm function-count limit. A family-level split is a new architecture change, not a transparent manifest edit. It requires distinct plugin/package identities, each family's declaration, editor and viewer registration and activation, separate component manifests, receipts and publication, and updates to dependent app IDs, activation selection, catalogs and routing. Exact consumer coverage must be established before implementing. Reusing the old single identity or descriptor for three independent components would not preserve the existing assembly contract.

All components must still implement `semio:framework@1.0.0` world `actor` from `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🧬️schema/📜️.wit`: imports `pure` and `host-async`; exports `reactor`, `jobs`, `checkpoint`, `describe` and `codec`. The `plugin_exports!` expansion binds one typed runtime, bundle function and app enum. `📜️describe.wit` specifies an async `describe() -> list<u8>` returning a packed package descriptor that holds the static artifact and IO declarations. Existing signed publication binds the descriptor and component provenance to its source closure; each new component must go through the normal build, description, provenance and browser publication chain. There is no evidence that relabeling or recombining old signed files satisfies this contract.

`materials-controller-admission-2026-11-26.md` records eight prototype Materials final-link peaks of 2,162–4,786 MiB, a 4,427.82 MiB R-7 p95, and a 5,092 MiB forecast with margin, before pass/controller footprints. It also records that the scheduler already uses one frontend thread and disables the parallel backend for linked finals. Those are historical measurements, not a per-family attribution or a measured family-split forecast. `component-warm-rebuild-audit.md` records the closure/identity and publication requirements and warns that downstream Rust units must be rebuilt after a dependency body changes.

A defensible implementation would start at the Materials assembly, manifest and component paths above, preserve the per-family app and artifact declarations, then update the corresponding workspace/component registration and Play catalog. Existing `🧪️tests/🖥️app-surface`, `🧪️tests/🚦️compliance-gate`, and `🧪️tests/🔬️surface` are candidate behavioral tests; add descriptor, identity, activation-routing and complete 15-route Play acceptance checks, plus real signed cold/warm link-peak measurements before claiming this meets a smaller machine budget. This audit made no build, production edit, or runtime measurement.
