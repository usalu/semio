# EN 1995 Mutation Compiler Memory Boundary

The component build measured 2,258 MB for `semio-s-artifact-norm-en1995-mutations|wasm32-wasip2|prototype|lib`. Its 16 GB worker library budget was 1,536 MB, leaving a 722 MB gap. The saved component log provides a peak for the full unit. It contains no phase or function-level allocation attribution. The earlier EN 1995 bridges carve is a separate test-only package and does not move code from this production unit.

The mutation aggregate currently declares 206 direct payload variants and 206 payload reexports. The payload definitions already live in domain group crates. In the aggregate crate, the `Mutations` expansion generates a per-variant diff, inverse, foreign-step, payload conversion, descriptor and registration path. The same aggregate owns ordinary and controlled `FromValue`, `ToValue`, canonical JSON, retained clone, retirement, and standard derives. The expansion requires direct payload leaf types and validates their order and ownership against the aggregate's declared roster. Moving it to a new crate would move the full type and generated paths together.

The edit-rule literals form a standalone 31,790-byte candidate, following the EN 1992 and EN 1994 table pattern. Removing those literals would leave the typed `NormEditRules::resolve_with_id_removals<En1995Snapshot, En1995Mutation>` instance and all 206 registered mutation paths. The text and binary modules are 7,571 and 1,769 bytes respectively. Their protocol trait implementations must stay with the mutation type under Rust's coherence rules. The bridge helpers are thin calls into the same typed diff and inverse. The memory observation does not support expecting these source-only moves to close the 722 MB gap.

## Ownership boundary

The 206 leaves already live in 31 dependency crates, with at most 11 leaves in any one owner. Every inverse in the current source corpus has one concrete payload conversion and all 206 destinations belong to the source leaf's existing owner. No root dependency or cross-group inverse is needed. Diff math already runs in concrete leaf functions. The mutation derive calls it via `ColdMutationKind<Snapshot, En1995Mutation>` alongside the generic inverse and foreign-step paths. Moving the leaf diff source again would leave those root dispatches in place.

The earlier inference that EN 1995 emits 206 native receive carriers and 412 native receiver cases was incorrect. `FromValue` emits separate methods for ordinary decoding, controlled decoding, decoded-owner retirement and typed edits. It does not invoke the `NativeReceive` derive. The EN 1995 binary implementation selects `OriginalDecodedOperationReceiving<En1995Mutation>`, which runs its authored binary codec and JSON text decoder. The native receiver adapter therefore cannot remove work from this target. The aggregate does generate canonical JSON and retained-clone typed projections for each declared variant. Source analysis does not establish how much peak RSS they use.

## Smallest meaningful prototype

1. Give each existing owner a concrete group enum and generate its leaf dispatch from a shared ordinal-and-owner roster. This places diff, inverse, foreign-step, payload conversion and leaf JSON/retirement implementations with their existing payloads. Generate a separate validation mode for group subsets and keep full aggregate scope and provenance checks. Keep the cold root inverse admission check before dispatch and wrap the resulting group inverses at the root with typed constructors.
2. Keep a single external tag decision in the existing ordinary and controlled `FromValue` entry points. Forward the leaf payload and original decode control to the concrete group. Preserve its depth, stage and ownership accounting, typed edits and failure retirement. Keep the binary codec and its retained operation protocol on the same route.
3. Use one internal root variant per group. Forward canonical serialization to each group's original flat tag and payload. Keep external tags, descriptor order, schema references and Protobuf field numbers distinct from internal group ordering. The graph-free corpus found all 206 names in all three representations. JSON branch order matches the Protobuf oneof and field numbers 1 through 206. Rust native and descriptor declaration order differs at 126 positions. For example, `InsertDeck` is ordinal 80 in Rust and 186 in JSON, with ordinals counted from zero. Assemble root descriptors in existing Rust order and leave wire ordinals untouched. Move the flat Rust roster to a generated witness before repointing the checks that currently read the root declaration. Update Rust constructor and match call sites in the same change.
4. Prove the design first with two separate owner crates and interleaved global leaf ordinals. Exercise direct variant and authored singleton-object receiving, unknown and duplicate tags, work-limited rejection, cancellation before and after leaf selection, retained-close accounting and final owner cleanup. Compare bytes, descriptors, diff and inverse round trips against the flat reference. Apply the same corpus across the 206 EN 1995 tags, including insert/remove inverses and the deck/taper ordinal boundary. Then run the same admitted cold component compile and check the root and every participating owner against the 1,536 MB library ceiling. Accept the split only on observed per-unit and end-to-end measurements.

A cold-only override leaves the `FromValue` and canonical dispatch in the root. The existing graph-free EN 1995 mutation-aggregate test passed both selected cases and 1,461 assertions using the Ajv oracle. It verifies satisfiable schema facets and exactly-once leaf coverage. The ticket's independent `en1995-mutation-owner-oracle.py` passed across the JSON, Rust and Protobuf witnesses, froze the native descriptor order and checked all inverse destination owners.

## Concrete EN 1995 inverse extraction

Before the extraction, all 206 inverse helpers were generic in the outer operation type. They combined concrete lookup, bounds checks and payload construction with allocation of a generic zero- or one-element vector. Each successful helper constructed one concrete inverse payload. No helper returned an error. This caused each cold call to instantiate the concrete part with the aggregate type.

The existing leaf owner crates now compile those lookups and constructions as concrete functions returning `Option<InversePayload>`. The trait wrappers preserve the original `Result<Vec<Op>, ValueError>` contract and construct the output vector directly. `None` yields an empty vector and `Some` wraps the payload once, with no intermediate vector. The aggregate's existing cold admission decision, wire and descriptor witnesses, package registrations and lockfiles are untouched.

The ticket differential oracle compared all 206 helper source bodies against revision `8d17d8ba3998690932b0032ea2ca41bce5c994b6`. It normalized the outer `Result` and vector adapter and found identical branches, computations and destination payloads. Its independent JSON fixture check confirmed that `taper-1` changes from 0.1 to 1.15 and that the inverse selects 0.1 from the original snapshot. The roster oracle passed for all 206 concrete helper boundaries and forwarding wrappers, and the graph-free EN 1995 schema checks passed both cases with 1,461 assertions. These are structural and fixture checks. The representative one-worker native tapers test expanded to 676 compiler units and 55,716,440 admitted bytes, so its owned invocation was cancelled and exited 143 before obtaining a Rust test result.
