# Norm browser sweep capacity

Launch the sweep with `repo "$T/probe-norm-base-companions.ts" <scope...>`, where `T` is this ticket directory. The three active shell callers use this entry. Its optional publication wait runs before resource admission.

The sweep requests one `repo capacity run` grant using the repository's end-to-end envelope. At the time of verification that envelope reserved 6,144 MiB and four cores. The admitted worker checks the live reservation before starting each session, prepare, activation, Vite or browser command. Their process trees inherit the same grant. The browser probes use normal tool-registry execution under the inherited grant.

Each scope finishes before the next begins. A failed command stops the sweep even when Chromium or Playwright has reduced a resource cancellation to exit 1. A lost Play service aborts the current probe. An interrupt or termination cancels the owned process tree through the repository's Windows and POSIX termination helper.

The mock suite passed all three cases. A successful first child allows a second scope, exit 137 during the first child stops the sweep, and cancellation ends a waiting child without starting the second scope. SQLite independently reproduced the expected sequences from the same JSON fixture. A direct call to the admitted worker without a live grant exited 1 before launching a child. No browser, Vite or compiler was started for this verification.
