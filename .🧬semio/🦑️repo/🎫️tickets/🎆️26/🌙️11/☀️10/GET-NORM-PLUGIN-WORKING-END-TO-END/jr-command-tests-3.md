`NativeSchemaMatchSelection` (`🔎️schema/🧭walk.rs` `selection`) returns `KeySettlement` as soon as `acknowledgement_ready()`, before looking at the semantic side; `settlement_of` (`🌳️source/🗝️key-frame.rs`) then picks `Settle::Outcome`, which calls `transfer_semantic_into`/`semantic_transfer_demand`, and those refuse while the acknowledgement metadata still has a pending recovery. `advance_resident_success` only takes (clears) the metadata when `metadata.child_work().is_none()`; with a nested child (our nested record tests) it returns `Ready` and leaves the metadata recovery pending, so the next selection lands in the refusing branch. Needed: when the acknowledgement is ready but its child work is still resident, select a step that settles the metadata child work (take/claim, `close_metadata_into`/`accept_close` path) instead of the semantic outcome transfer; cheapest fix site is `settlement_of` + `selection` ordering.
