# Runtime Fixture Cache Path Audit

The fixture reader expands `env!("CARGO_MANIFEST_DIR")` in the caller and reads its path at test execution. Same-checkout test reruns see current fixture bytes even if Cargo reuses the binary. Runtime-only files are absent from compiler source and dep-info keys. The EN 1992 and EN 1993 outer test targets declare their full standards trees as inputs; this does not itself establish the cache configuration of every other target.

A bounded direct call to `pathSensitiveV1` on the EN 1992 checks source returned an empty list although its mounted test calls `fixture_text!`: the detector recognizes literal `env!` in scanned source, not an `env!` introduced by an external macro. Under remapping the unit cache constructs a portable local key and publishes locally before checking output bytes for leaked roots. A binary embedding the old manifest directory may therefore be reused across checkouts sharing that local cache. This is source-level evidence, not an observed cross-checkout failure. Fleet publication inspects output roots and uses rooted identity or refuses sharing, and remote compilation rejects worker-root leaks.

The general owner is `⚡️caching/🦀️cargo/🗃️unit-cache/📜️script.ts`: correct generic handling must check outputs before local publication and producer/extern identity, rekey to a path-scoped local identity, coordinate the preexisting neutral claim and cache entries, and make the scoped key discoverable at later lookup. Teaching the scanner fixture macro names alone would cover known calls but would not prove safety for arbitrary expansions or existing neutral entries. No implementation change was made in this audit.

The fixture-reader macros now resolve the test process's `CARGO_MANIFEST_DIR` at runtime, falling back to its current directory. This covers the fixture, repository-root and component helper macros without embedding the build checkout. The independent TypeScript test read the relocated fixture and verified the macro source contract. Its focused suite passed 5 tests and 20 assertions. The TypeScript companion consumes shared CSV vectors, and sampled Norm consumers use these helpers in Rust test code.
