Candidates left: (a) a `remove-*` leaf whose inverse re-inserts a large member, (b) a history-edit commit whose single Edit carries many rows, (c) the `semantic` wire (installed by the earlier pass) encoding the canonical tree of the whole mutation instead of the OpBinary frame.

## Correction and root cause (measured: en1997 copy run, `🗑️generated/cp-editor-en1997.log`)
Measured: `[DEBUG] payload extent exhausted: chunk 18 stored 15 maximum 28 head "changeFootingWidth"` (twice). The earlier claims in this report and in `editor-history-framework-2026-11-24.md` that one edit exceeds 262144 bytes were wrong: the output is not an edit payload at all.

- The output is the encoder of `OriginalOperationWireComparison` (`operation-wire/🧳️replacement/⚖️canonical/🦀️.rs:40`), created with `maximum_payload = wire.len()`. It re-encodes the replacement's typed mutation through the installed `ArtifactOperationWire` and requires the bytes to equal the replacement payload (`:3`, "replacement input is not the admitted canonical operation wire"). So the limit is the length of the replacement bytes, 28, by design: an encoder that writes more than the bytes it must equal is refused early. The quote is correct; it is not a sizing bug, not the receipt, not the digest.
- The replacement bytes come from `time-travel/🗄️store-state/🦀️.rs:566` (`rebuild`): `<Mu as OpBinary>::encode_op(&op)`, commented "canonically encoded". For en1997 `ChangeFootingWidth{id:"f1",newWidth:2.5}` the Norm frame is `[1, tag] + {"id":"f1","newWidth":2.5}` = 2 + 26 = 28 bytes.
- The installed wire encodes the same op differently: `ArtifactOperationWire::semantic` -> `CanonicalJson{header:b"op", body: canonical tree of the whole mutation enum}` (`one-item/publication/lifted/operation-wire/🦀️.rs:68`), whose enum-tagged JSON names the kind (`changeFootingWidth`) after a 15-byte prefix. The two encodings differ, so the comparison can never succeed.
- The framework law is therefore: `OpBinary::encode_op(op)` must equal the operation wire's canonical bytes for the lane's wire. Apps whose `OpBinary` is the canonical wire satisfy it; the Norm family's hand-written frame `[format, tag, payload JSON]` (`payload_op_binary`) does not. This is a Norm/framework contract mismatch, introduced in the open question's fix 3 (decoded receiving over the Norm frame); the earlier Pack placeholder compared Pack values instead.
- Not fixed in this pass (no builds allowed, and it needs a framework source type): the Norm wire must emit the Norm frame. `CanonicalJson{header,body}` copies `header` (up to 11 raw bytes) before the JSON body, so a Norm `source` of `header=[OP_BINARY_FORMAT, tag]` and `body=canonical tree of the leaf payload` produces exactly the frame, provided the macro-generated mutation enum can lend its leaf as an `ArtifactCanonicalJson` and a `'static` tag. The alternative, changing Norm's `OpBinary` to the wire bytes, would contradict the authored `📡️.protocol.semio` tags. Law test to add with that change: for every descriptor of a family, `OpBinary::encode_op(m)` equals the bytes `ArtifactPreparedOperationCursor` writes for `wire.source(m)` (quoted size equals written size is then implied).

## Fix implemented (not compiled)
Precedent in the framework: `with_original_ordinal_binary_receiving` already swaps the wire `source` so replacement/edit comparison re-encodes the persisted bytes. The new `with_original_encoded_binary_receiving` does the same for any `OpBinary` vocabulary:
- `one-item/publication/lifted/operation-wire/🧳️receiving/🦀️.rs`: `EncodedOperation<M>` (repr(transparent) over `M`, `ArtifactOperationText` with one `Scalar` leaf), `pub fn encoded_operation_source` (a `Text{header:b"", body}` source) and `ArtifactOperationWire::with_original_encoded_binary_receiving()` = source swap + `with_original_binary_receiving()`. The scalar leaf writes `OpBinary::encode_op(m)[offset..]` at most 64 bytes per turn, so the written bytes ARE the authored frame for every family ([format,tag,JSON], [format,varint tag,varint length,JSON], tagged text, print_op text); the extent the comparison quotes (`wire.len()`) is the length of exactly those bytes.
- Funding note: each scalar turn re-runs `encode_op`, so a turn allocates a transient `Vec` (not retained, not part of the retained ledger) and an op of n bytes costs about n/64 encodings. Acceptable for small operations; the zero-allocation framework tests do not run Norm. If a streaming Norm source is wanted later, replace the scalar body only.
- `📤️store/🧵️operation-wire/🦀️.rs` and `…/lifted/🧵️operation-wire/🦀️.rs`: re-export `encoded_operation_source`.

## Revision: encode once, funded frame, per-vector law (not compiled)
- Replaced the per-turn scalar re-encoding by a new source kind `ArtifactPreparedOperationSource::Encoded{body:&dyn ArtifactOperationEncoded}` (publication `lifted/operation-wire/🦀️.rs`; trait `encode_once()->Vec<u8>`). `ArtifactPreparedOperationCursor` (`operation-wire/🦀️.rs`) owns an `EncodedFrame{bytes,offset,paid,identity}`: turn 1 calls `encode_once` (one allocation), turn 2 reports its `capacity()` as `retained_capacity_bytes` against the quote `next_capacity_byte_demand` (now the frame capacity while unpaid), later turns copy at most 64 bytes, and `close` releases the capacity as `released_bytes` (quoted by `retirement_demands`). `with_original_encoded_binary_receiving` installs it; Norm macros unchanged from the previous step.
- Blocking protocol point (not silently worked around): `OpBinary::encode_op` returns an already allocated `Vec`, so its size cannot be quoted before the allocation and its internal temporaries are invisible to the ledger (same property the earlier `OriginalDecodedOperationReceiving` accepts for `decode_op`). The frame therefore exists for one turn before its capacity is reported. Smallest change that closes it: add `OpBinary::encoded_len(&self)->Result<usize,ProtocolError>` (and an `encode_op_into(&self,&mut Vec<u8>)` writing into caller-reserved capacity), implemented per family without temporaries; the cursor would then quote the capacity first and report it in the same step. Until then a strict "heap observed per step equals the receipt" law would see the encode turn (physical allocation, receipt 0) and the pay turn (receipt, no allocation).
- Ledger visibility: `semio_framework_trace::observe_heap_allocations_on_this_thread` equalities exist in `artifact-app-laws` (result pages, maintenance/retirement steps) and the framework wire tests; the only Norm hits are two en1990 mutation tests (`🧪️tests/🧮️physical`, `🌉️bridge-fatigue-rows/…/🛬️native`) that do not drive the wire. Retained and released capacity of the frame balance (unit law asserts `retained == released`). The history-edit comparison path charges only quoted capacity through `NativeDecodeControl`; it quotes the real frame capacity before paying it.
- Per-vector law: `✏️s/🧪️tests/🧪️mutation-vectors/🦀️.rs::wire_binary_breaches`, called for every committed bundle of every family that uses `assert_committed_vectors` (bound `M: OpBinary + Sync` added): the cursor over `encoded_operation_source(m)` writes exactly `m.encode_op()` and the frame's retained and released capacity balance. Its Cargo dependency `semio-framework-value` gained feature `testkit` for `testing::fx`. `os_store::encoded_operation_source` is re-exported in `🏪️store/🦀️.rs`. The unit law in `operation-wire/🧪️tests` stays and also asserts balance.
- Families calling `assert_committed_vectors`: only those whose editors/mutation tests invoke it; families without that call (the table showed 8 binary-mutation test files, 15 families) are covered by the unit law alone.
