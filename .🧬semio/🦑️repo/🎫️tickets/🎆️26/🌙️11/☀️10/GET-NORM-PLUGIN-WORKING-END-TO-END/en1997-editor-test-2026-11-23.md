# EN 1997 editor integration test (2026-11-23)

## Cause
The `integration` target of `semio-s-artifact-norm-en1997-editor` mounts the unit tests as an external crate (`pub use semio_s_artifact_norm_en1997_editor::*`). Five errors:
1. `store::` / `protocol::` (3 errors): the lib declares `extern crate semio_os_kernel as store/protocol`, which is not visible in the separate test crate. The sibling families (en1990/92/95) run the same test file in-crate, where the aliases resolve.
2. `En1997PlayApp::examples()`: `examples` is a `semio_plugin::ArtifactEditor` trait method and the trait was not in scope.
3. `queries overflow the depth limit` (depth +130, layout of the async test blocks): every `context::dispatch/render` test awaits the whole generic async chain `dispatch_original_fixture_command` -> `dispatch_fixture_action` -> `PluginApp::handle_action/handle_command/render` (blanket `impl<D: PluginAppDelegate> PluginApp for D` over `VcsArtifactApp<EditorApp<..>>`). Layout of an async block requires the layout of every awaited future, so query depth grows with the chain length. The same chain overflows `semio-hub-norm` (`<impl PluginApp>::handle_command`).

Why the tests stay a separate target: moving them into the lib (as en1992 does) was tried and fails source admission (33 of 32 files, the closed per-crate boundary), so the separate `integration` target is the intended layout.

## Fix
- Unit test file: `store::os_store::test_support` -> `semio_os_kernel::os_store::test_support`, `protocol::OpText/OpBinary` -> `semio_os_kernel::OpText/OpBinary` (already a dev-dependency with the needed features), `En1997PlayApp::examples()` -> `<En1997PlayApp as semio_plugin::ArtifactEditor>::examples()`; `semio_s_artifact_norm_en1997_editor::` -> `crate::` in this and the assets and inspection test files.
- Depth limit, root fix instead of `recursion_limit`: every forwarded future is boxed so the layout query stops at a pointer:
  - `dyn_enum(delegate)` blanket forwarding in `🧰️framework/🔨️modules/🔀️dispatch/🦀️.rs` (`Box::pin` around the target call, docstring explains why).
  - fixture drivers in `artifact-app-laws` (`handle_action`, `handle_command`, both `render` awaits).
  Test-only drivers pay no production cost; the delegate box is one allocation per async plugin call.
- Lib root: the mojibake region markers of the unit-test region were replaced by the proper region heading; the case-edit mount stays in the lib.

## Follow-up: runtime failures (2026-11-23, runs 12 to 16)

Result of the last full run (`🗑️generated/en1997-editor-run16.log`, lib and integration, `--no-fail-fast`): lib 18 passed, 14 failed (one pass was a temporary probe, removed since); integration 42 passed, 10 failed (one pass was the temporary regen test, removed since). Before this follow-up: lib 22/31 passed, integration 29/51 passed. Not all 82 pass yet; the rest is split below into fixed, framework-owned (with file and cause) and norm content.

### Fixed
1. **Stale assets (`soil-type` TEXT vs ENUM).** The DSL printer is right (the field is an enum), the four committed DSL assets (`🖼️assets/🎬️demo`, `🏗️compliant`, `🚨noncompliant`, `🏘️ground-showcase`) and their packs were stale. They were regenerated by the engine through a temporary env-gated test (decode, print, `encode_en1997_pack`), no hand edit; the regen test is removed. Round-trip, pack twin and DSL tests pass. The TS twins of these assets were not regenerated here.
2. **Wire hex.** `01010001000402` becomes `01000001000402` and `01010000` becomes `01000000`. Cause: the command enum lost its first variant (`Evaluate` moved to jobs), so `SetSelectedCheckIndex` is variant 0 and the second byte is the variant index; `command_ids_cover_every_row_and_are_unique` already expects the single row. The change is intended, so all 12 families that pinned it were re-pinned together: en1990, en1991, en1992, en1993, en1994, en1995, en1996, en1998, din16798, din18599, en1997, iso16757. Only en1997 was run (passes). en1990 and iso16757 list five commands with `setSelectedCheckIndex` first, so index 0 is expected there too but unverified.
3. **Close fault "captured shared original changed its Work or destination".** Backtrace (`[DEBUG] shared invalid` printed by the owner): `FactorySharedRetirement::close` at `🧰️framework/🔨️modules/🌱️value/♻️retirement/🔗️arc-custody/🏭️factory/🦀️.rs:27`, reached from `ArtifactGenesisRetirement<NoConfig>::close_into` (`os-store-read/🗑️envelope-genesis-and-displaced-snapshot-retirements:103`) via `ArcRootRetirement::close_reply`. Invariant: `OriginalWorkBindingIdentity::follow_between_actions` (`🎟️control/🧬️contract/🎟️work-action/🫴️borrow/🦀️.rs:18`) returns false when the closing effect is not pending but carries no Source turn, so the genesis retirement captured under one turn cannot be rebound under the fixture's close turn. The owner is annotating each refusal with a cause (`invalid(cause)`); their edit left `ok_or_else(invalid)` at line 33 not compiling, which I fixed (small, clearly correct). Two other small compile gaps of the same refactor were fixed: `NativeDecodeControl::new` and `resume_validated` lacked the new `settling:false` initializer. After these, run 16 shows 0 occurrences of the fault.
4. **`Window owner must declare its original disposer birth`.** The norm Results and Viewport window-config owners did not override `store_disposer_birth` (the trait default refuses). Both now call `bounded_window_config_store_disposer_birth::<Self>()`, like flow, cad and gis (`📕️norm/🪟️results/🎚️config/🦀️.rs`, `📕️norm/🪟️viewport/🎚️config/🦀️.rs`). The refusal is gone from run 16.
5. **History-edit law found 0 cases.** Two causes. (a) The law's fixtures root was `"../../🏅️standards/🔖️1/🪆️subsets/✳️any"`, which resolved below the editor directory and does not exist; the manifest dir is `✳️any/✏️editor/📦️packages/🦀️rust`, so the root is `"../../.."` (fixed in all 14 families that mount the law). (b) The law only read the nested fixture layout (`🦠️mutation/🔣️.json`), the norm families commit the flat one (`🔣️.mutation.json`, `🔣️.outcome.json`, `🔣️.before.json`). `acceptance_fixture_file` in `🧪️history-edit-acceptance/📚️acceptance-fixtures-cases-and-change-buckets/🦀️.rs` now reads either. The law now finds cases and runs (see remaining item C).
6. **Ownership orphans `gi-01.points` and `gi-01.spacing`.** For a document without exactly one footing the GI-01 checks have no owner row and must be document-level. `DOCUMENT_CHECKS` (scene kit) lacked `gi-01.spacing` and the family `OWNERS` document-level list lacked both. Added; the ownership test passes.
7. **Incremental laws (`every_unit_declares_all_it_reads`, retained session equals full evaluation).** Root cause is not a missing read: the check builder cites every NDP read logged on the thread since the last drain (`drain_ndp_reads`, thread-local `NDP_READS`), and the investigation spacing, CPT range, design-parameter and SLS reads were never drained. The next catalogue evaluation on the same thread (for example `geo-f04` of a footing) then cited `ndp.en1997.2.4.2.spacing.gc12.*` depending on what ran before it on that thread: output was nondeterministic (probe: `unit.execute` twice on the same document differed). Fix: `evaluate_standalone` drains stale reads before each top-level catalogue evaluation (used by `evaluate_case`, the entity reference verifications, lateral and geo-entity evaluations, GI-10), and SLS-04 inside the pairs check records its reads without leaking them. Both incremental laws pass in run 16. The same latent leak probably exists in the other norm families (not changed).
