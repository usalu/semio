# Slice Worker Memory and Capacity

The 04:56 local fleet status reproduced warden resume records for slice worker PID 70719 on `g1-m06` at 4,977 MiB and PID 62448 on `g1-m13` at 5,600 MiB. Both hosts report 16 GiB. The resume rows are historical and carry no parent reservation. The same status returned five reader deadlines, including workers, storage, fleet, CAS and offload. The worker reader waits for worktree comparison and a fleet journal verdict before it returns readiness rows. The status reader is being repaired separately.

Newer private slice reports documented substantial live allocations on successor PIDs, independent of the old resume records. On `g1-m06`, PID 31200 held 2,734 MiB footprint, 2,521 MiB charged to heap plus external memory, and 11.3 million JS objects during the first owner wave at 04:00:17 UTC. On `g1-m13`, PID 28170 held 3,462 MiB footprint, 4,330 MiB charged to heap plus external memory, and 20.5 million JS objects at 03:59:52 UTC. It was on inventory attempt three, with 138,925 source observations, 616 admitted owners and scoped source input discovery underway. The largest individually inventoried cache was settled reads at an estimated 188–196 MB. The telemetry establishes that graph inventory and owner inference still carry a large live set. It cannot attribute the historical warden RSS to a particular kernel or runtime object, nor pair it with a specific grant.

The resident service holds the authentic slice reservation and attaches its worker process tree for ledger observation. It does not forward the outer grant envelope to the worker. The pool previously sent the existing graph managed-memory budget override only if the current reservation was smaller than the booking. On a 16 GiB host this let a full 2,048 MiB first booking inherit the generic 4,096 MiB managed budget, while a 2,048 MiB reservation resulting from a larger booking correctly got the 1,024 MiB budget. The separate resident plan guard uses a 40% soft limit and a 60% hard ceiling on this host. Those are 6,553 and 9,830 MiB, so they do not make the two equally funded cases behave the same.

The resident pool now applies the existing 50%-of-grant managed budget on every active positive reservation. It preserves a tighter explicit configured budget and leaves the ordinary budget available when there is no reservation or capacity is disabled. The finite process-tree guard, owner-wave sizing, warden and existing policy thresholds remain as authored. The graph managed budget controls admission and collection within the graph reader. A production peak reduction has yet to be measured.

The regression first failed on four differences, including the unlearned full 2,048 MiB booking and a partial reservation that overwrote a tighter explicit operator limit. The language-independent fixture is evaluated separately by Python using SQLite. The follow-up booking, reservation, and plan-limit suites passed 17 tests with 142 assertions for full, partial and absent reservations, capacity disabled, tighter configuration, plan cuts and lease cleanup. No compiler, resident service restart, or load-generating graph run was used.
