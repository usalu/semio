# Cargo build script memory forecasts

The focused native actor-input run showed libc 0.2.190's build script waiting on a cold forecast of 5,959 MiB. The native scheduler already reports Cargo package name and version. The immediate cause was source sizing, since the original estimator counted all 133,623 Rust lines beneath the directory containing the 605-line build.rs. The cold formula reproduces 5,959 MiB from that input. Running the updated estimator against the same cached package read 605 lines and predicted 639 MiB.

Build scripts now use the existing authored Rust source closure reader. It includes mounted source files and falls back to the previous directory estimate when compiler cfg, an unresolved mount, an embedded input, or other uncertainty makes the smaller closure unprovable. This sizing change applies only to Cargo's generically named build script. The ordinary Cargo source-admission pass records exact cfg and source digests only for workspace units. The libc registry library had no such observed closure and retains its conservative directory forecast. Its earlier-pinned run also displayed the approximately 5,935 MiB cold hold for that separate library unit.

Build-script history now distinguishes package versions as well as package names, Rust targets, profiles and crate types. The warden records the canceled script's Cargo output directory before shortening diagnostic command text. The broker uses that directory to attribute the existing cancellation penalty to the matching script. A same-named script in another package or version does not inherit the penalty. Diagnostics include the qualified build-script key when reporting a hold.

Seventeen focused tests passed across the admission law, wire broker and launcher reporter. They cover distinct measured peaks for three same-named script units across two packages and two versions, exact cancellation attribution, and conservative source sizing fallback. Two warden-record checks passed, including production of a typed record when the compiler output directory appears beyond the stored command prefix. The real-file sizing comparison used no new compiler.
