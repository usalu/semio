# Materials Fleet Final Admission

Materials generation `wdiAegY` ended before its component Cargo pass. The report records zero compiled units and zero stages. The outer command acquired 2,048 MiB, but the pass runner saw a zero-MiB parent allowance. It required 6,197 MiB for the local pass. Earlier in the same log the job plan saw 70 idle fleet action slots and one slot sized for a 6,322 MiB linked final. The live component query later printed zero final slots.

The ticket's `native-exec.ts` verifies a fresh reservation before launching the component driver, then drops `SEMIO_HOST_CAPACITY_PLAN` on its self-acquired native-controller path while carrying the grant identifier. The compiler allowance reader treats an unpaired grant identifier as zero. At zero, the pass cannot even attempt fleet placement because the same live local grant must cover the driver's RSS and the fleet pass's 512 MiB local reservation. The separately reported live final count was also insufficient. The final-count diagnostic uses zero for a missing or failed fleet answer, so the historical log does not distinguish a busy compatible worker from a failed query. The ordinary idle count does not measure memory for this particular final.

There is a supported fleet pass for eligible WebAssembly targets. Cargo, source shipping and stage orchestration stay on the requesting host. Individual rustc actions use the fleet or cache. With a parent grant, the fleet pass registers a strict placement with its broker. A compiler unit that falls back to local admission is refused and the pass can only be retried in an eligible local slot. The initial fleet count is not a reservation. The live final query applies the peak-memory test and, when available, the matching linker filter. Real placement also enforces the exact toolchain and target properties.

The read-only status query during this audit showed 13 worker registrations with 130 nominal slots, no running remote actions, and WASI Preview 2 support on all 13. It reports an unsized headroom verdict. A sized final additionally requires a load report, no critical pressure or worker cooldown, and reported free memory minus committed memory at least as large as the final's requested peak. The status query does not show that free memory.

The existing command-capacity interface can supply the real inherited reservation without changing either gate. For the same owned invocation, prepend `repo capacity run --memory=2048 --cpu=1 -- repo` before the ticket driver's arguments in place of the initial `repo`. The inherited branch validates and preserves the plan. An actually free compatible final slot and adequate host headroom are still required. `SEMIO_OFFLOAD=pin:<origin>` selects a compatible worker for individual units and supplies neither final headroom nor the required local lease. There is no single-action remote component switch in the driver. No build or dispatch was performed for this audit.
