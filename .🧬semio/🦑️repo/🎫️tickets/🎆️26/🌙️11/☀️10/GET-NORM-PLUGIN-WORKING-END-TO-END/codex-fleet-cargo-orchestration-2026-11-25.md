# Local capacity for distributed Cargo

The observed one-core EN 1995 build reached local Cargo planning and the compiler broker with no running host grant. The outer command and its owned nested dispatch both entered the fleet branch. That branch returned directly into the command body without a grant. The same branch handled explicit distribution, default distribution when the local unit probe wanted to wait, pinned placement, and a queued local request that handed off after the fleet became eligible.

Both initial and queued fleet handoffs now reserve Cargo's authored fixed local allocation before entering the body. The request requires the entire allocation of 1,536 MB on this host, books one controller core, and allocates zero memory per compiler job. The ledger identifies the operation as `cargo-orchestration`. Separate operation identity keeps its restart handover distinct from an ordinary full Cargo grant. The host governor retains the controller allocation for the lifetime of the orchestration, including cancellation until its body settles. Critical pressure and active swap still block admission at the host gate. A genuinely live parent grant can fund the controller, and nested dispatch reuses it.

The compiler planner treats the fixed-only reservation as orchestration. Local compiler jobs continue through their existing capacity scope, native broker and unit-cache placement rules. Caller-specified local parallelism and fleet eligibility are preserved. The fixture on a simulated 16 GiB host has 3,800 MB available and a 2,048 MB host floor. Exactly one 1,536 MB local controller grant lets fleet dispatch start there, even though the full local compiler request cannot fit.

The focused tests reproduce the old missing grant and critical-pressure bypass before the fix. The final fixture checks implicit and explicit distribution, pinned and local routing, queue handoff, normal and fleet double entry, parent-grant reuse and refusal, insufficient memory, critical pressure, active swap, cancellation during fleet discovery, and grant retention while an already-started body drains. The compiler planner suite uses the independent Python model and the existing fixture kernel leases. No native build or remote action was started for verification.
