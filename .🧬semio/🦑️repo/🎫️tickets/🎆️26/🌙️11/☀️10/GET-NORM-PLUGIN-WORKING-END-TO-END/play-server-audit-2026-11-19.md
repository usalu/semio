# Play Server Transform Failure Audit

The handoff reports a malformed `/@fs` request and an unhandled Vite load error. The current `🗑️generated/serve-6033.log` and `play-serve-standards.log` do not retain a matching error, so neither the precise URL nor the original exception can be established from the available evidence. No request was sent to the live server.

The service wrapper at `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/⚡️caching/🌐️vite/🟦️.ts`, `serveVite`, wraps each environment's `transformRequest` and `warmupRequest` in `admitted`. Every rejected admitted task sets `accepting=false`, adds the rejection to `failures`, and calls `interrupt()`. The service then exits its wait, destroys connections in `finally`, drains and closes Vite. Thus an ordinary Vite load rejection reaching this path is treated as a service failure even if Vite's request middleware handles the rejection. This explains the reported shutdown mechanism; the missing original log prevents independently confirming the specific request's path through it.

A bounded correction should preserve request errors as request errors while retaining fatal treatment of resource-control, capacity, optimizer-drain, and lifecycle failures. Separate the operation outcome from the enclosing capacity/drain outcome rather than guessing from exception text or code. For example, capture Vite's operation result in a tagged outcome without throwing within the resource scope, complete optimizer drain and lease checks normally, then reject the caller with the captured operation error only after successful infrastructure cleanup. Infrastructure rejection remains fatal and interrupts the service. Keep pending bookkeeping and the admission bound intact. The existing drain helper preserves the first failure, so catching and classifying its final exception by identity alone could hide a simultaneous lease or cleanup failure.

Regression coverage should use an isolated Vite service, never the shared live listener: issue a malformed or missing `/@fs` module request, verify its error response, then request a valid module and verify the service still responds; separately inject a resource/drain failure and assert service shutdown. Retain optimizer and lease cleanup assertions, and exercise the existing capacity bound. No implementation or test was run in this read-only audit.
