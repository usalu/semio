# Managed Vite admission audit

Read-only observation on 21 November. The coordinator observed `/@vite/client` pending for over 300 seconds on the managed listener; the existing `🗑️generated/eurocode-camera-live-network.log` independently records that URL with `response:null`, but does not by itself establish the elapsed duration or the request's exact wait point. The managed listener log records repeated `vite:entry` waits on exclusive `semio.compiler.cpu-picker/v1` behind other compiler requests. The lease status records repeated lock-order violations requesting that rank-3 picker while the rank-6 shared `artifact:…/browser/prototype/wasm-packages/0eac234ec2c308c96333b196` lease is held. These observations and source explain a likely admission bottleneck, but no request-correlated trace proves that this particular pending URL was waiting on the picker rather than optimizer processing.

`serveVite` in `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/⚡️caching/🌐️vite/🟦️.ts` takes `withViteArtifactInputsV1` outside the entire listener lifetime, including all requests and shutdown. Initialization obtains counted compiler capacity inside those artifact leases. Every uncached `environment.transformRequest` and every `warmupRequest` independently obtains another `countedCompilerCapacityRequestV1()` under a 600,000 ms control, awaits the operation and optimizer processing, and checks the lease before release. Cached transform results bypass admission. The per-listener pending bound is 32. The policy is half of available cores preferred and half of that rounded up as minimum: on the observed 10-core host each uncached request asks for up to five compiler units and needs at least three. Separate requests may therefore compete with long-running compiler builds and each other. The optimizer drain can hold a request's grant beyond the transform itself.

The simplest structural correction to evaluate is to acquire a bounded compiler allocation before entering the lifetime artifact-input scope, retain it through Vite initialization, requests, optimizer drain and listener shutdown, and remove nested per-module compiler acquisition. A fixed one-unit allocation is a candidate, not a measured proof that one unit bounds all concurrent Vite work. The implementation must bound actual concurrent transform/optimizer work consistently with the granted allocation, preserve request errors as request errors and infrastructure errors as fatal, preserve cancellation and drain, and avoid a non-reentrant queue that deadlocks Vite's own nested transforms. The service then reserves its allocation until shutdown, and it can still wait at initial admission; it does not wait anew for compiler cores while holding artifact leases for every module. Releasing the lifetime artifact leases while Vite can read inputs would break publication custody, while acquiring capacity only after them retains the existing inversion. Long-lived artifact readers can themselves delay an exclusive component publisher, so a production change must retain exact input custody and explicitly test that lifecycle.

An isolated service test should saturate the other compiler slots, issue concurrent uncached module and optimizer requests, verify bounded progress and cancellation, verify ordered acquisition and teardown, then verify an input publisher waits until the service releases its lease. Confirm actual work and memory under the chosen allocation. The existing native Play fallback on 6034 is already the verification endpoint; no listener, browser, build or process was started or changed for this audit.
