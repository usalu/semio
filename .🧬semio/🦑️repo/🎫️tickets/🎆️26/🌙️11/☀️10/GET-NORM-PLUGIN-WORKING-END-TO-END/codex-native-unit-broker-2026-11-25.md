# EN 1999 native compiler admission

The one-core EN 1999 test was already inside a 4,916 MB host reservation when Cargo reached the libc build script. The compiler wrapper PID 99514 had a connected Unix socket. Its peer was FD 41 in the run's Bun driver PID 89615, which hosted `semio-broker-89615-7ec4a0ad1bc3.sock`. The stack sample at 20:52:45 CET shows the wrapper waiting in `Broker::verdict`. There was no rustc for that unit while it waited and no matching fleet scheduler queue entry. Cargo advanced through libc, futures-core, pin-project-lite, futures-sink and futures-channel without intervention. The run later reached tokio. The evidence confirms a wait in the run's local compiler admission broker and subsequent progress. The reason for the specific libc hold is unavailable. Its duration is consistent with the 180-second idle wait policy.

The ordinary Cargo launcher now supplies the same stderr reporter it uses for resource status to the compiler broker. Future runs report whether a unit is waiting for available memory, a warden hold or active swap. The in-progress run uses a pinned earlier implementation.

Two pre-existing broker paths could release a compiler despite a known hard stop. Warden danger was checked after the return for unreadable availability. Active swap froze concurrent starts but still allowed an idle unit to get the 180-second fallback. The broker now checks warden guard or danger and swap-out above 64 MiB/s before any start. The fallback for insufficient memory with an idle broker also requires a fresh calm warden state. Available memory that fits still admits when no hard hold is known. The authored wait remains 180 seconds, or 360 seconds for a previously cancelled unit.

Before the fixes, socket fixtures reproduced an actual admission at warden danger with unavailable memory, admission above the swap threshold after the wait, and admission after the wait with unknown warden state. Fourteen focused tests passed after the changes. They include the schema-backed vectors against a Python oracle, real local socket exchanges with simulated host inputs, and a launcher reporter wiring check. The socket cases verify release when swap subsides or when a calm warden reading returns. No live workload or admission setting was changed. No new Cargo, browser or workspace graph job was started.
