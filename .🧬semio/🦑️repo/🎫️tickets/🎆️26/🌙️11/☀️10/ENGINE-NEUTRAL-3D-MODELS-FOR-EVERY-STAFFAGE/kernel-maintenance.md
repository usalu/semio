# Kernel maintenance pass: loft frames (A2), solid provenance (A5), polygon robustness

Kernel `M` = `🧰️framework/🔨️modules/🧊️3d/🗿️model/`, ticket folder `T` = this folder. Normative inputs: `design.md` (A1-A6), `kernel-core.md`, `kernel-requests.md`.

## What changed

### 1. A2 loft sections (`M/🔺️tessellation/🧵️loft/🟦️.ts`)
- A section with `rotation` keeps today's behaviour (x, y plane of the rotation, absolute). A section without `rotation` lies perpendicular to the path tangent (central difference of the neighbouring `at`, one-sided at the ends; zero tangent falls back to the overall travel, then Z); x = node X projected perpendicular to the tangent (fallback Z), y = tangent x x. The frame comes from the exported `revolveFrame` of `🌀️revolved`, the very helper the capsule uses for `lateralScale`. Mixed lofts work.
- Schema descriptions: `M/🧬️schema/🔣️.json` regenerated by `T/generate-model-schema.ts` (LoftSolid and section descriptions); twin `M/🧬️schema/🟦️.ts` (LoftSection docstring). "Semantics" of `T/kernel-core.md` updated.
- Fixtures `M/🧫️fixtures/🧵️loft/🔣️.json` (generator `T/generate-model-fixtures.py`): new cases `along-x`, `along-y`, `diagonal`, `diagonal-circle`, `bent-path` (in the YZ plane), `mixed-twist`, `mixed-consistent` with expected per-section frames (hand formulas in Python) and analytic volumes/bounds. Test `M/🧪️tests/🧵️loft/🟦️.ts`: three `Vector3`/`Quaternion` recompute every frame and compare with the vectors; every section's ring vertices must lie in the plane and on the (super)ellipse of that frame and the ring start vertex `at + rx x` must exist; volumes against three `CylinderGeometry` (diagonal circle) and analytic `pi rx ry L`; a test that loft and capsule use the same lateral axis.

### 2. A5 solid provenance
- Schema `Primitive.solids?: { id: Slug, first: number, count: number }[]` (new `$defs` `PrimitiveSolid`) in `🔣️.json` + twin (`PrimitiveSolid` type, `Primitive.solids`).
- `tessellate` (`🔺️tessellation/🟦️.ts`) fills it for rigid and skinned primitives (index ranges in solid order, covering all indices; a solid with no triangles gets no range).
- `validateModel` (`✅️validation/🟦️.ts`): new error `bad-solids` (contiguous from 0, whole triangles/segments, covering all indices, slug ids, count >= 1).
- `featureEdges` (`📏️edges/🟦️.ts`): line primitives keep `solids` when the source primitive has them; an edge belongs to the solid of the first triangle using it (an edge shared by two solids is kept once under the earlier), solids without edges get no range; no provenance in, none out.
- GLB (`📤️export/🧊️glb/🟦️.ts`): written to primitive `extras.solids`; inconsistent ranges throw. FBX (`📤️export/🎬️fbx/🟦️.ts`): FBX geometry has no named parts, so the ranges are kept as the user property `SolidRanges` (`KString`, flag `U`, `id:firstPolygon:polygonCount;...`) of the mesh `Model`, with the new notice `solids-as-property`. Viewer: `ScenePrimitive.solids`, `Hit.solid` (null without provenance), exported `solidOf` (binary search) in `🖥️viewer/🧱️scene`, `🧬️contract`, `🎯️picking`, `🟦️.ts`.
- Fixtures regenerated: `T/gen-glb-fixtures.ts` (GLB digests changed, rig carries ranges, `minimal-triangle` none), `T/fbx-fixture-source.ts` (FBX digests changed), `T/gen-viewer-fixtures.ts` (`🧱️rig`, `🎯️picking` changed; camera, frame, raster identical). New kernel fixture/test `M/🧫️fixtures/🧬️provenance` + `M/🧪️tests/🧬️provenance`.
- Tests: kernel (ranges per node mesh/material/skinned mesh equal expectations with box index counts from three `BoxGeometry`; contiguity and solid order; schema + validator; featureEdges ranges equal expectations and three `EdgesGeometry` of each solid's own triangles; no provenance in, none out), GLB (extras, rejection of broken ranges, tessellated procedural document through validator and glTF-Transform), FBX (`SolidRanges` value and notice for the fixture and for a tessellated document), viewer (picking vectors carry the expected solid, grid of rays, null without provenance, `solidOf`).

### 3. Robustness (`M/🔺️tessellation/🔺️polygon/🟦️.ts`, `🌀️revolved`, `🏗️extrude`, `✅️validation`)
- Validation: new errors `self-intersection` (two non-adjacent edges touch or cross, adjacent edges fold back, closed ring without area) and `bad-holes` (hole touches/crosses the outline or another hole, outside the outline, inside another hole) for extrude outlines and holes and revolve profiles. A profile whose first point equals its last is a closed loop (extrude: `cleanRing`; revolve: `revolveOutline`, new, shared by tessellator and validator, so both walk the same polyline incl. the end discs); contacts at radial 0 are allowed (bicone touching the axis). Predicates exported from `🔺️polygon`: `cleanRing`, `contact`, `ringFault`, `holesFault`.
- Cap triangulation: ear clipping now keeps collinear and near-duplicate vertices as vertices. Stress harness `T/kernel-maintenance-polygon.ts` (random star polygons with collinear points, near-duplicates 1e-9..1e-6 relative, holes, three scales): the previous code failed 21 of 4000 (a collinear vertex dropped: area right, boundary edges unused, T-junctions; hand-picked 6-vertex failures are now vectors), the new one fails 0 of 4000. Extrude cleaning moved into `cleanRing` (same behaviour).
- Fixtures/tests: `M/🧫️fixtures/🔺️polygon` + `M/🧪️tests/🔺️polygon` (hand cases, three recorded float-noise failures of the old code, area against three `ShapeUtils.triangulateShape`, triangle count V + 2H - 2, boundary edges once, interior edges paired, seeded 3000-polygon stress, predicate tests), extrude fixture cases `collinear-midpoints`, `near-duplicate-points`, `closed-loop-profile`, `hole-with-collinear-points` (watertight, three `ExtrudeGeometry`), 24 new validation vectors (`extrude-*`, `revolve-*`, `solids-*`) in `M/🧫️fixtures/✅️validation`.

## Volume-check over the assets that have a volume
- No asset changed. Method: `T/kernel-maintenance-volumes.ts` froze the catalog (122 assets with `asset.volume` at the start, 151 at the end because authors kept adding) and `volume-check` (bbox, IoU, recall, precision per view) was run before and after the loft change on the frozen 122: all 122 results identical. On the frozen 151, `T/kernel-maintenance-regress.ts` compares `tessellateSolid` of the maintained kernel with a frozen copy of the old kernel for all 4846 solids (1347 loft, 1106 capsule, 873 box, 627 revolve, 525 ellipsoid, 368 extrude): positions, normals and indices are byte-identical, so every volume-check number is identical. No catalog loft has a section without `rotation` (the staffage layer fills them), which is why the A2 change moves nothing; on the frozen 151, volume-check reports 113 ok and 38 below its thresholds (authoring in progress), independent of this pass.
- Existing solids under the new validation (`T/kernel-maintenance-validate-catalog.ts`, one solid per document): one new error. `machinery/concrete-mixer-truck`, solid `drum-cone-cap` (revolve, profile `[[0,1.12],[2.55,0.5],[2.55,0.47],[0,1.09]]`): first and last point sit at the same axial coordinate a = 0, so their end discs overlap along the axis; the tessellator emits two coincident opposite faces that close the open end of the shell with a membrane. `tessellate` of a document containing it now rejects with `self-intersection` at `/solids/<i>/profile`. Fix on the author's side: close the loop (repeat the first point `[0,1.12]` at the end, A4). Volume-check itself calls `tessellateSolid` without validating and is unaffected.
- Pre-existing, unrelated to this pass: 37 solid ids in `vegetation/agave` (19) and `vegetation/hosta-clump` (18) are not kernel slugs (for example `leaf-L5`), so `tessellate` rejects them with `bad-slug`.
