# Library requests from the React target and site (react-site)

Append-only; each item says what the target saw and what it would like. Nothing here blocks the target.

- **`featureEdges` draws the outlines of invisible glyphs.** In the static state of a pose, glyph solids (breath emitters, arrows, arcs) have an alpha-0 face material in every variant but the analytic one, yet `featureEdges(resolved, angle, { material: "edge" })` adds opaque `lines` for their triangles, and every variant binds `edge` to an opaque colour. `standing-adult` in `relaxed` shows long stray loops around the figure in the interactive view and in `writeGlb`. The React pipeline strips the `lines` of glyph-tagged nodes after `featureEdges` (`withoutGlyphEdges`); the exporters (`writeGlb`, `writeModel` resolved) do not. Request: skip glyph-tagged nodes in the `featureEdges` call of `writeGlb` and `writeModel`, or bind `edge` for them per variant.
- **The release bundle of the site now contains the volume module.** `depict` with `viewpoint: "axonometric"` imports `🧊️volume` (looks, frames, thermal, structure) statically, so the 2D entry chunk carries them (the GLB, FBX and bundle encoders, the kernel viewer and the stage stay in lazy chunks; the site's `treeshake.moduleSideEffects` keeps the rest out). If the 2D-only path should not pay for the axonometric depiction, `depictAsync` could load the axonometric module with a dynamic `import()` (it is already async) and `depict` keep the planar path synchronous.
- **`depict(..., "axonometric")` is synchronous in the figure.** The React figure draws every clock frame through `sceneOf`; the axonometric depiction is the expensive one (23 to 66 ms for the sample figure here, more for machines). The figure holds the previous frame's work as a drawing but does not yet use `depictAsync` with the `JobControl` progress and cancellation; the interactive 3D model has both. Request: none; noted so the library owner knows the figure's cost.
- **`exportFilename` conventions.** The browser names 3D downloads `<asset>_<pose|clip|bundle>_model_<representation|all>_1-<denominator>.<ext>` (the word `model` where a drawing names its viewpoint), the library's `modelStem` is `<asset>-<pose|clip>-<view|all>-model-1to<scale>`. Both follow decision D14 per surface; the two surfaces already differ for drawings.

## From the axonometric depiction (library)
- `VolumeUnavailableError`, `VolumeFeature`, `isPlanarViewpoint` and `requirePlanarViewpoint` were deleted from `🔨️modules/🔗️contracts` (no library or React site refused anything any more). Code that still imports them (React `🧩️element`, `🗺️routing`, `📤️downloads`) must drop the imports; `depict(..., viewpoint: "axonometric")` returns a normal DrawingScene. The viewpoint list of the React UI may now use `VIEWPOINTS` (four) instead of `PLANAR_VIEWPOINTS`; `DepictionOptions.axonometric` (`{kind:"isometric"|"dimetric"}|{kind:"free",azimuthDeg,elevationDeg}`) picks the camera, `depictAsync(state, options, analysis, control)` is the cancellable form.
