
## From the viewer agent (🖥️viewer)

- **Solid identity in resolved primitives (picking). HANDLED (A5, see `kernel-maintenance.md`): `Primitive.solids: { id, first, count }[]` and `Hit.solid`; the field names follow design A5, not the proposal below.** `tessellate` merges solids per node and material, so the solid id is lost and a picked triangle can only be traced to node, mesh, primitive and material. Request: keep, per resolved `triangles` primitive, an ordered list of ranges `{ solid: Slug, indexStart, indexCount }` (schema field on `Primitive`, e.g. `solids`, optional, counted in indices of that primitive, ranges ascending and covering all indices). The viewer would then report `Hit.solid` without any other change (`🖥️viewer/🎯️picking`). Not blocking.
- **No other kernel change needed.** The viewer reads `poseModel`, `sampleMaterials`, `tessellate`, `CancelledError`, `silentOperation` and the schema twin only.

## From the staffage volume module (🧊️volume)

- **No blocking kernel request.** (informational items below handled in `kernel-maintenance.md`: loft default frame by A2, `lateralScale` by A3 as is) `modelOf`, `writeGlb`, `writeFbx` and `writeModel` run on `tessellate`, `featureEdges`, `poseModel`, `sampleMaterials`, `encodeGlb` and `encodeFbxDetailed` as they are; every staffage asset with a volume (sample figure and the catalog assets authored so far) tessellates, validates (Khronos: 0 errors, 0 warnings), loads in three and replays its poses and clips to `evaluate`.
- **Informational (non-blocking), loft default frame.** A `loft` section without `rotation` lies in the xy plane at its `at`, so a loft along an axis without explicit rotations degenerates to a flat sheet (the sample figure's torso). The staffage layer fills the missing rotations from the path (section Z = travel direction, X = bone-local lateral axis projected perpendicular, Y = Z x X) and keeps given rotations verbatim, so the kernel needs no change; a kernel default of "follow the path when no section has a rotation" would make the schema text and the tessellator agree.
- **Informational, `lateralScale`.** The kernel scales along the node X axis projected perpendicular to the capsule or revolve axis (Z when the axis is parallel to X); the staffage schema text says the lateral bone axis `w`. Both agree for axes along `u` (the authored case); the staffage layer passes the field through unchanged.

## From the React target and site (react-site)

- **Viewer: follow camera. HANDLED (`model-viewer.md`, "Follow camera and root motion"): `follow` (`off`, `bounds`, `{ node }`) with per-frame smoothing and `rootMotion` (`travel`, `in-place`).** A clip with root travel (`city-car` `drive-by`, `forklift` `drive-with-load`) leaves the picture because `ModelViewer.fit` frames the bounds of the pose at the time of the call and the camera never follows. The React stage plays clips in place (it replaces the horizontal travel of the root node channels by the rest position before tessellation), which loses the travel. Request: a `ModelViewer` option `follow: boolean` (or `fit("clip")`): while an animation is sought or played, keep `camera.target` on the posed bounds centre and keep distance and orientation; or `fitClip()` that unions the bounds over the clip. Non-blocking.
- **Viewer: preset event. HANDLED: `preset` event (`{ preset }`, null once the camera is set freely).** `setPreset` (keys 1 to 5 or the client) only emits `camera`; the stage recovers the preset by comparing yaw, pitch and projection with `PRESETS`. A `preset` event (or `camera.preset`) would make that exact. Non-blocking.
- **Viewer: constructable stylesheet for the custom element. HANDLED: adopted style sheet, `<style>` only where unsupported.** `defineModelViewerElement` writes its CSS into a `<style>` element; a Content-Security-Policy without `style-src 'unsafe-inline'` (the site's release policy) blocks it. Use `adoptedStyleSheets` with a `<style>` fallback (the React stage does). Non-blocking.
