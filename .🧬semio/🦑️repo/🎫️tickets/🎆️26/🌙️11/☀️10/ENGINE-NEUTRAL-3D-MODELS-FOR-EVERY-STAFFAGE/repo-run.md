## 3. Fixes (root causes)

1. `🧊️3d/🧪️tests/🎚️config/🟦️.ts`: `exclude: ["**/🧰️support/**"]` did not exclude support files because the include globs start with `../..` (tinyglobby/picomatch `**` does not match `..`); the support files were collected as tests ("No test suite found", 4 suites). Verified with tinyglobby: the pattern `../../**/🧰️support/**` excludes them. Independent of the runtime; the earlier direct runs used a config with another root, which hid it.
2. Engine-dependent last bits. The recorded vectors and digests were made under Bun (JavaScriptCore); the repo's test policy runs Vitest under Node (V8) (`repositoryVitestPolicyV1`: `runtime: "node"`). `Math.sin/cos/tan/atan2/acos/exp/hypot` differ in the last bit between the two (measured by tracing every call: hypot in 10 to 20 % of calls, sin/cos/atan2 in about 4 %), which changed baked pose quaternions, FBX bytes and one traced SVG polygon. Fix: new `🧊️3d/🗿️model/🧮️math/🎯️portable/🟦️.ts` with `sin cos tan asin acos atan atan2 exp pow hypot` in double-double arithmetic (only `+ - * /` and `sqrt`), correctly rounded in practice and identical on every engine; constants verified with 90-digit decimal arithmetic. New test `🧪️tests/🎯️portable-math/🟦️.ts` (12 tests) with language-agnostic vectors `🧫️fixtures/🎯️portable-math/🔣️.json` (1118 cases, expected values rounded from 90-digit decimal series in Python `decimal`, each cross-checked against the platform libm within 2 ulps by `repo-run-portable-vectors.py`), plus a sweep against the runtime's own `Math` (within 1 ulp, 2 for `hypot`, whose V8 implementation is less accurate). It passes identically under bun and node.
   Applied with `repo-run-portable-codemod.py` (`Math.fn(` to `portable.fn(`) in 35 files: the kernel (tessellation, edges, validation, mechanism, math, GLB, FBX) except the viewer, and the staffage pipeline modules `🧮️evaluation 🔺️polygon 🦴️rig 🧊️volume 🗂️catalog/🧊️volume 🎨️depiction/{📐️geometry 🧊️axonometric 🧩️shapes 🔭️views 🏷️annotations}`. Cost: about 1 to 2 microseconds per call against 0.01 for `Math` (measured), so it was not applied to the viewer rasteriser, the thermal and transport field code.
   Re-recorded, because the old bits were JavaScriptCore's: `📤️export/🧊️glb/🧫️fixtures/🧊️rig-wave-quarter` (one quaternion component and the sha), `📤️export/🎬️fbx/🧫️fixtures/🎞️rotation-continuity` (2 shas), staffage `🧫️fixtures/🧊️model-digests` (8 poses/clips), `🧫️fixtures/🚀️export-performance` (one SVG sha, `walker-thermal/0009.svg`). After re-recording (done under bun) the direct runs under bun and node agree on all of them (`model-digests` 10 and `export-performance` 31 tests pass under both).
3. `portable.hypot` coerces its arguments like `Math.hypot` (the validator relies on `NaN` for a malformed channel).
4. `📥️inputs/💾️storage/🧬️schema/🔣️.json`: `inventoryEntryLimit` 131 072 to 1 048 576. The graph inference store holds 146 257 entries after the full graph (and the closure maxima raised in `repo-graph-3.md`), so every `repo run` that had to refresh a project died with "Finite optional graph inventory exceeded" (the user-visible text is "The resident service met an unexpected failure (reference 692ef1ea)"). Not covered by an own test.
5. `🧍️staffage/📦️packages/🟦️typescript/📜️script.ts`: the test floor is now `long` (`resolveTestLevel(segments, "long")`). With the default `fundamental` the whole suite was killed at its 15 s budget; the staffage-react and site scripts already declare `quick`.

### 2. Bootstrap tests and the `node` command

- The four tests failed on macOS because of the test and the Python download code, not because of the `node` change (the node change is outside the functions they slice; a pre-change run is not possible without `git stash`, so "failed before" is by reading, not by measurement): (a) `Linux session persistence` and `Zig wrappers` call functions that are gated on `uname -s` = Linux and, in the Zig case, on the absence of a system `cc`, and the persistence test asserted `no /Users/` in a file that legitimately contains the checkout path; (b) the two Python download tests use a local self-signed HTTPS server and rely on `SSL_CERT_FILE`, which Apple's Python (LibreSSL 2.8) ignores.
- Fixes: `🧪️tests/🧰️toolchain/🟦️.ts` gets a `uname` shim that answers `Linux`, a PATH of only the needed utilities (no compilers) for the Zig case, and compares the persistence file without the repo path; `🐚️.sh` (bootstrap, two places) and the launcher `🚀️launcher/📥️install/🐚️.sh` now call `ssl.create_default_context(cafile=os.environ.get("SSL_CERT_FILE") or None)` (and import `os`), which makes `SSL_CERT_FILE` honoured on every Python. Result of `bun test` on that file: 32 pass, 4 skip (the Windows-only tests), 0 fail.
- Static review of `node` (not executed on Windows or Linux): the schema carries all six rows (darwin, linux, win32 times x64, arm64) with the nodejs.org URLs `node-v24.15.0-<platform>-<arch>.tar.xz` (`.zip` for win32), consistent with Node's naming and with the existing darwin-arm64 row that was verified by download; the sha256 of the other five rows were not verified (nothing else was downloaded). The shell path maps `uname` to darwin/linux and x64/arm64, refuses musl, verifies the sha256 before unpacking and links `node npm npx corepack` into `~/.local/bin`; the PowerShell path takes the `win32` row of the host architecture, verifies the sha256, moves `node-v24.15.0-win-<arch>` to `%LOCALAPPDATA%\semio\node\v24.15.0` and puts it first on the user PATH. Defect found and fixed: the tools catalog looked for Node in `~/.local/node/bin`, a directory nothing creates; it now looks in `~/.local/bin` (`🏃️process/🧰️tools/🔣️.json`). Left as is: the bootstrap edits no shell profile, so a shell without `~/.local/bin` on its PATH does not find the linked node (the same holds for the bootstrap's `uv` and `repo`).
