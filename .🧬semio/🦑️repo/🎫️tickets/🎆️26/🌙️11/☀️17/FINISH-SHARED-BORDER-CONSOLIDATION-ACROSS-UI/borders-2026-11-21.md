# Shared UI border verification

The Web compositor now keeps a permanent seam on its original centerline when a state-only edge joins it. Developer-created focus indicators remain visible on controls without compositor registration. The shared focus, introduction, and celebration strokes remain one CSS pixel, including in higher contrast and reduced motion. Hovered cards retain their full silhouette while controls inside the card can highlight their own edges. Navbar and footer use the same permanent band seam for hover and child states.

The targeted framework run passed 263 tests in 19 suites. The CSS animation scope tests passed all three cases, including comparison with PostCSS. The Rust border-presentation crate passed 14 tests through the repository’s isolated Cargo entry point. The Hub Admin, Staffage, and Presentation focused suites passed 28, 8, and 12 tests, respectively.

In the native renderer, hit testing for hover uses the same stepped polygons as paint and only applies to stacks reached by the pointer path. The cap, footer, and gap can therefore update the drawn state within one routed hit rectangle. All 192 native laws passed, and the wgpu engine compiled with both retained frame entry points.

At 375 px with a fine pointer, the Demonstrator uses a scrolling grid beneath the fixed logo footer. The probe found the moving card edge at y748 and the fixed footer edge at y784 at scroll offset zero. Scrolling 64, 256, or 517 px cleared those readings while the footer stayed fixed. Chrome at 375 px with a coarse touch pointer used the swipe layout and reported zero pairs in all four views.
