# 🔍 Audit: Remaining Per-Element Borders in UI Elements (excluding Navbar and Footer)

Scope: `🧰️framework/🔨️modules/🖱️ui/🧱️elements/*/🟦️.tsx` (non-test), `🖱️ui/🎨️styling/🖌️ui/🎨️.css`, `🖱️ui/🔨️modules/*`. Read-only; no source edited.

Method: grep of every border token (`border`, `border-[trblxyse]`, `border-*` constants such as `borderNormalBottomClass`, `borderElementClass`, `chromeControlGroupSiblingDividerClass`, `panelTabButtonDividerClass`), `data-shared-border-*` markers, `ring-*`, and directional border/pseudo-element hacks across all element TSX. Each hit was then read in context. Compositor semantics were taken from `🧱️elements/🗂️WindowChrome/shared-border.ts` (`commit`, `visibleSources`, `resolveBorderSegments`) and from the `shared-border-ownership` layer in `🎨️.css`. Key rule relied on: any `[data-shared-border-frame]` (and `data-shared-border-edges`) paints its own overlay and, through `[data-shared-border-attached] > input/textarea` and `[data-shared-border-attached~=side]`, makes its own native border on those sides transparent, so a frame's native `border` class is not a duplicate. Coincident frame edges are merged by `resolveBorderSegments`.

## Confirmed OK (managed by the shared mechanism, no action)

- **Stepper** (`🪜️Stepper/🟦️.tsx:253-275, 343`): root frame with edges, cells `data-shared-border-cell`, inner input `border-0`. Good.
- **ToggleGroup, Toggle, ButtonGroup, ActionGroup** (`🎛️ToggleGroup/🟦️.tsx:161-162,198`, `🔀️Toggle/🟦️.tsx:184,209`, `🔳️ButtonGroup/🟦️.tsx:71-72,128`, `⚡️ActionGroup/🟦️.tsx:64,107,222`): frame plus `shared-border-cell` items. The frame's `chromeControlGroupShellClass` `border` is owned via the ownership layer.
- **Input, Textarea** (`✏️Input/🟦️.tsx:489,510`, `🔤️Textarea/🟦️.tsx:111,119`): root is a frame; the inner `input`/`textarea` native border is transparent under `[data-shared-border-attached] > [data-slot=input|textarea]`. The collapsed display (`:297`, `data-slot=input`) is covered by the same rule.
- **Select** trigger and content (`🔽️Select/🟦️.tsx:422-430, 671-672`): frames. Native `border` on the trigger is owned by the compositor.
- **Popover** (`🗨️Popover/🟦️.tsx:423`), **Dialog** content (`💬️Dialog/🟦️.tsx:546-547`, CSS `border-width:0` for `dialog-content`) and footer (`:596`, `data-shared-border-group`, no border), **Ribbon** (`🎀️Ribbon/🟦️.tsx:23,35,83,91,93`, groups only): frames or groups without per-element borders.
- **Tabs** (`📑️Tabs/🟦️.tsx:155,205-212`): list has no border; only the selected trigger is a frame; unselected triggers use `border-transparent`. No doubled edge.
- **Command** input wrapper (`⌨️Command/🟦️.tsx:286`): `border-b` divider under the search row, inside a framed host whose edge it does not share. No duplicate found.
- **Tree rows** (`🌳️Tree/`): no row borders; guide lines are bg fills (`📏️row-alignment/🟦️.tsx:58`).
- **WindowPane, Window, WindowChrome, ContextMenu menu items/content**: `border-0` or silhouette-owned, or separators drawn as `h-px bg-border` (`🔗️fusion/🟦️.tsx:195`). OK.
- **Slider, Checkbox, Divider, Surface, Ports, Label, Form, Field**: no border classes in TSX. OK.
- **Chip, KeyValue, Wizard, List**: no web TSX under `🧱️elements`, only TUI/wgpu targets (`🎯️targets/`); no border or divider matches in those target files.
- **Already-marked silhouette chips and the `data-window-silhouette-chip` rule** (`🎨️.css:~1460-1520`): OK per brief.

## Notes

- Navbar and Footer are excluded per scope (their `data-shared-border-edges` is `bottom` and `top`, which the Layout finding 1 depends on).
- Confidence is based on static reading. No render or pixel check was done (read-only task, no tests run).
- Findings 1 and 3 are the most likely real double seams. Finding 1 is the only one that crosses into a compositor-managed element (navbar).
