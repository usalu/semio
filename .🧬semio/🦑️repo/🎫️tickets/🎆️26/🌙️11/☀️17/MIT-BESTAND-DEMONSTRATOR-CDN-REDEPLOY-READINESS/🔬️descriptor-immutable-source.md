# Descriptor compilation from a fixed Source generation

The real Procedural release's descriptor prerequisite in `wZeuq82` spent five snapshot retries on the same retirement-factory source path, followed by a second actual Cargo attempt. The earlier FEM/GIS run exhibited the same pattern on a different shared input. A checksum mismatch from Cargo cannot be repaired by rereading the same completed compiler result when a live input has permanently changed.

The current tool producer requests `retainConsumedSources:true`. The native compiler admission captures bodies in a bounded, read-only content store. Individual provenance facts select a captured body only when its BLAKE3 and length match the compiler's dep-info. However, Cargo itself still runs with the live workspace directory, live manifest path and live compiler resource includes. Its independent units and build scripts can read different generations. Source replay and rechecking stop that mixed result from becoming a mismatched tool receipt.

A portable fixed source mirror can keep authored bodies stable across rustc and build-script execution. An issued mirror needs four additional pieces before it can serve the real emitter:

1. Capture and recheck the exact selected workspace graph, all workspace/manifest/config topology required by Cargo, and the admitted Source bodies, with explicit original paths and digests. Persist only bounded sealed bytes behind the current compiler storage owner.
2. Route the original Cargo resolver and compiler against that private physical tree. Declaration-relative resources and build scripts must remain in the same captured generation. Compiler and script outputs, Cargo home and external package bytes retain their own actual owners.
3. Record both physical input provenance and the issued logical source path. A plain Cargo mirror changes path-based package IDs, and relocating a manifest can alter Rust's compile-time `CARGO_MANIFEST_DIR` string and build-script inputs. Rust diagnostic remapping does not substitute for a proven identity mapping.
4. Retain the exact emitter built for the active Original request until its descriptor stages complete. Later requests compare its attested logical source inventory with current declarations and can rebuild against the newer generation. A source-freshness waiver or the already-published historical emitter cannot supply that proof.

The separate small generated-workspace fixture exercises the physical semantics through the normal repository Cargo ingress. It adds no Git worktree and changes no active runtime or compiler source. The lower-level standalone Cargo tool correctly refused repository compiler access without an issued store. The canonical ingress accepted both fixture graphs. The production mirror, generalized provenance mapping and per-request tool retention have not been wired into the descriptor producer.

The small native fixture reached genuine compiler admission after accepting both mirror graphs and its captured Source list. A 512 MiB governed attempt waited for a physical compiler core for more than four minutes. I withdrew only that exact fixture to free its budget for Procedural. The fixture and its disjoint physical/source files remain available for the next normal admission. Canonical full compilation of the fixture has not yet run.

The standalone artifact producer now reuses the existing Cargo source-attempt law during real compiler-artifact events. If two different output families name incompatible consumed checksums for one admitted Source path, the attempt uses the original typed source-drift stop and retry. It skips physical snapshot retries on that terminally inconsistent compiler evidence. A single announced historical checksum still goes through the exact existing witness and snapshot validation. The focused physical dep-info regression failed before wiring and passed with eight assertions. Its expected checksums were produced independently by Noble.

The installed emitter's retained production source proof includes 2,012 repository Rust source bodies totalling 27,058,775 bytes. Ninety-eight carry textual include macros. The dependency graph contains real DSL compiler-resource tracking based on `CARGO_MANIFEST_DIR` and call-site Source, so those locations need explicit treatment in a production mirror.
