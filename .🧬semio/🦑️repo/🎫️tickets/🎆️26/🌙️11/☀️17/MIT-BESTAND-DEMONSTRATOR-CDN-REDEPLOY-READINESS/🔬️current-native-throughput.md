## Compiler-resource sidecar eligibility

The current replacement entry for the repeated flow-document key has 62 dependency rows, 11 of them `@@semio-lane@@/semio-compiler-resources/<timestamp>-82950-<n>/observation.json`; none of those exact relative paths was present in either retained lane at this snapshot. Its environment row for the resource root is lane-neutral. The 11 sidecar hashes were not present as objects in the default host CAS; the five artifact/stdout/stderr objects named by the entry were present. Thus this retained entry cannot currently pass the real lookup in those two lanes regardless of whether its unit key matches. This does not establish that the now-removed first entry caused the earlier duplicate miss.

`test-unit-cache-lane-eligibility.ts` exercises actual `writeEntryV1` and `lookupUnitV1` with a private cache and two synthetic lanes: the same key and equivalent resource bytes at a new per-invocation path miss; the exact recorded relative path with matching bytes hits; changed bytes refuse. This is an eligibility reproduction, not a real compiler build or historical attribution.

The sidecar is not disposable timing: proc-macro capture records producer and caller identity, completion and actual file reads and directory enumerations, then tracks the immutable observation file in rustc dep-info. The post-compile provenance observer records file content, directory entries including symlink targets, and absence/structure through its physical owner, and binds producer/caller against the unit stream. The completed compilation retention roster can retain these observations only after a completed invocation. The unit-cache entry's replay `provenance` holds only peak RSS, timing and rmeta offset; it does not retain a caller-bound compiler-resource witness or its bodies. There is no demonstrated prelookup mechanism for validating complete file/directory/symlink/absence observations and restoring an authenticated sidecar into a new lane without collisions and within the original resource controls. A safe design would need that explicit bounded custody and real cross-lane tests before relaxing path eligibility; dropping sidecars or trusting normalized keys alone would lose evidence.
