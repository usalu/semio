# Component Run Scratch Reclaim

The production component-run collector’s dry-run census found 20 runs, held 2, and retained 10 outside its removal plan. Its eight whole-run candidates total 2,229,075,968 estimated allocated bytes **inside the mounted Rust image**. The two Energy entries were wt48zqN (858,980,352 bytes) and wKZ8QJX (845,393,920 bytes). The former is named by the sealed Energy audit and the latter by the preserved predecessor gate. The identified abandoned Procedural run w2pN2J2 contributes 164,880,384 bytes.

The existing repo cache gc command calls the collector between incremental-session cleanup and stale compilation-unit cleanup. It receives only a byte target and live image-space observation. Its scope is the full components/runs store. Component keys come from materialized output directory names. It protects recently touched runs and the newest visible materialization by key, and repeats the activity timestamp immediately before deletion. The available route has no allowlist of module or run IDs and no provenance or verified-proof exclusion. An empty run may be retired based on any newer materialization. Treating the dry-run names as an executable allowlist would remove ownership checks from the supported route.

The accounting estimates allocated bytes by file blocks and hardlink share. It neither demonstrates unique clone extents nor establishes a host-space gain. The mount itself remains the physical boundary. At the final read-only snapshot host availability was 15,496,802,304 bytes. No supported deletion meets the requested exact selection and verified-release protection while supplying a demonstrated host gain. No files were removed. The plan is retained in the generated component-run-reclaim-dry log.


A follow-up measured direct-host ticket artifacts independently of the Rust image. Inactive construction-native Cargo outputs account for 370,081,792 bytes, with no observed kernel or process consumer. Existing verification inputs name that build tree, so any separate authorized removal would preserve its manifests, logs, standalone output witnesses, and regeneration recipes. Two inactive Procedural diagnostic core copies total 302,522,368 allocated host bytes. A read-only level-one gzip pass produced a combined 62,482,172-byte estimate and recorded each original SHA-256. Actual compression was declined. Between separate host samples, active Rust backing allocation declined from 60,335,890,432 to 56,648,830,976 bytes with no volume cycle initiated here. This was concurrent activity without an attributable selected-run effect.
