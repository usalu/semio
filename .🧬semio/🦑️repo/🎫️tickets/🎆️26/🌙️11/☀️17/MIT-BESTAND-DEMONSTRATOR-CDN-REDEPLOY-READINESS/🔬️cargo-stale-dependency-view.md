The native component driver counts Cargo `compiler-artifact` messages with `fresh: true` as reused (`🏗️native-build/🧩️component-pass/🟦️.ts:63-66`); Cargo owns fingerprint and dependency invalidation. The artifact plan hashes the admitted graph and workspace sources (`🏗️native-build/📋️plan/🟦️.ts:21-48`), rechecks around target recipe lease acquisition, then runs Cargo (`🏗️native-build/🟦️.ts:332-354`). Its completed provenance source comparison and recheck occur in the capture consumer after a successful build (`:354-362`). A compile that fails first never reaches that comparison, so a downstream compile can report apparent API errors after an earlier dependency source changes in flight. A target recipe lease protects the build lane, not the live shared source tree. Cargo freshness at invocation planning does not turn a long invocation into an atomic source snapshot.

A source-level infrastructure fix is possible: compile the admitted graph against an immutable, content-addressed snapshot of the complete compiler-visible source closure, preserving workspace layout, generated inputs, features and dep-info provenance, and publish only after the existing receipt/recheck succeeds. This is an internal build input snapshot, not another shared worktree or a copy in the ticket. Alternatively an efficient graph-scoped change monitor can cancel the current Cargo invocation immediately when any admitted source changes, classify it as a source-generation interruption, and replan under the existing cancellation and bounded retry policy. The latter limits wasted time but can starve under continuous edits and must also handle race-free watch registration and missed events via digest checks. On any failed invocation, compare admitted source digests to current bytes before reporting compiler diagnostics; this distinguishes concurrent change from a genuine unchanged-input compiler error and avoids recommending source edits based on a mixed view. It is not a substitute for snapshot isolation. Do not invalidate unrelated shared lanes or assume an unconditional retry fixes this.
