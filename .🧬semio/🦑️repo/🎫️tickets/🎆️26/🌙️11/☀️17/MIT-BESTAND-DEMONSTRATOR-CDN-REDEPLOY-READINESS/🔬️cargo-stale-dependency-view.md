A source-level infrastructure fix is possible: compile the admitted graph against an immutable, content-addressed snapshot of the complete compiler-visible source closure, preserving workspace layout, generated inputs, features and dep-info provenance, and publish only after the existing receipt/recheck succeeds. This is an internal build input snapshot, not another shared worktree or a copy in the ticket. Alternatively an efficient graph-scoped change monitor can cancel the current Cargo invocation immediately when any admitted source changes, classify it as a source-generation interruption, and replan under the existing cancellation and bounded retry policy. The latter limits wasted time but can starve under continuous edits and must also handle race-free watch registration and missed events via digest checks. On any failed invocation, compare admitted source digests to current bytes before reporting compiler diagnostics; this distinguishes concurrent change from a genuine unchanged-input compiler error and avoids recommending source edits based on a mixed view. It is not a substitute for snapshot isolation. Do not invalidate unrelated shared lanes or assume an unconditional retry fixes this.

The component driver's previous byte and timestamp check ran after it marked a failed invocation terminal. Its artifact prefetch also stored provisional source and output claims in the pass-wide provenance session as soon as Cargo announced a unit.

Warm release runs with one configured pass and one component now hold each invocation's unit messages, build-script records and diagnostics separately until it stops. The driver waits for the first child and its streams to retire. A retry requires a nonzero exit, no linked component, a Rust dependency-shaped diagnostic and no killed unit. For graph dependencies of the failing unit, it compares recorded rustc BLAKE3 source checksums with stable live reads. The evidence is joined by announced target identity, including platform and feature set, and takes at most 512 bounded reads and 10 seconds. Missing proof leaves the original failure path in force.

On proof, the driver re-admits sources and recaptures the exact locked unit graph under the held writer, storage, build-lane and deadline controls. A different unit graph takes the existing concurrent-edit route so the outer driver can recalculate its batch footprint and all graph custody. An equal graph permits exactly one rerun of the same Cargo command in the same directories. Cargo's checksum freshness can then rebuild changed dependencies and affected consumers while retaining prior valid units. Retry runs have distinct bounded logs. Only a successful settled attempt can stage this component, and the selected attempt's own messages, time and graph feed all existing publication and provenance checks. Multi-pass and multi-component runs keep their established streaming behavior.
