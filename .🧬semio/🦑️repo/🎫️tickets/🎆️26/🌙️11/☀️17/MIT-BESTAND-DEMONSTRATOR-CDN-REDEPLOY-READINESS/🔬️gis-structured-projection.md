# Bounded GIS Structured Projection

The only `StructuredMediaSource` implementations are GIS Map and GIS Terrain. The shared job's projection currently runs once inside an otherwise stepped job. The lower 2,000 µs registration bound does not constrain that callback. GIS Map clones the complete intrinsic feature tree, scans it, renders JSON, parses it again, and compares it with the original. GIS Terrain constructs complete intrinsic values for elevation and eagerly materializes a full grid mesh and its intermediate Value tree for scene output.

The existing Pack JSON `JsonWriteSource` lends ranked nodes, collection widths, keys and strings directly. `JsonBorrowedWriteCursor` advances with a supplied Work limit, exposes actual physical progress, enforces an output ceiling and supports controlled retirement. A mounted job can lend the exact snapshot anew for each turn and hold only its traversal frontier. A separate Source-bound wrapper exists, but its retirement currently assumes the same borrowed Source epoch and does not expose the lifecycle's close quote.

The Map source has three static members in authored order. Each vector element can lend its existing feature data. Port-specific validation must preserve rejection of Bytes, non-finite floats, nonnegative signed numbers, duplicate keys and unsupported depth. Duplicate-key detection requires explicit bounded state because intrinsic object members are Vec-backed and public constructors can create repeated keys. Keys themselves can exceed a turn's copy limit. The existing JSON parser compares authored keys against earlier members incrementally. The staged `gis-map-json-validation.rs` follows that approach directly on borrowed source keys in chunks of up to 64 bytes, without constructing an intermediate JSON parse tree.

The terrain elevation schema uses fixed 33 × 33 samples and WGS84 bounds. The scene can reuse the shared terrain's per-component formulas using the exact stored heights, reversed row order, local origins and f32 rounding. Elevation range for UVs can be accumulated one row per turn. A borrowed write projection can then emit the exact mesh document member order, including the required empty colors array, without allocating a temporary mesh or copying snapshot rows.

The proposed per-coordinate formulas are staged in `gis-terrain-mesh-projection.rs`. Its runner extracts the live mesh math and compares every position, normal, UV and index at the bit level for twelve fixed-resolution terrains spanning flat and varied heights, lower latitudes and polar bounds, and three exaggerations. The pinned Rust comparison passed. `gis-terrain-scalars.json` captures edge, interior, corner and triangle order laws. The Python standard-library oracle `gis-terrain-scalars.py` passes those independent values. No active release inputs were edited for this prototype.

The drafted Map view lends the existing feature values, the Elevation view borrows its schema-derived canonical tree, and the Scene view addresses exact canonical mesh columns one scalar at a time. The draft paid JSON turn limits work to one actual writer action. Remaining integration work is to retain both the draft writer and projection state in the existing `Buffers` close ladder, route source validation into the project's typed media result, and prove original-source receipt accounting and eventual publication through the mounted tool entry point.
