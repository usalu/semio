# Compiler Source Witness Transfer

Energy run `wKZ8QJX` linked and staged its component, then the compiler-provenance seal refused the physical BREP curve file with “Current physical bytes changed before transfer.” The report recorded one failure after 9,143 seconds. The failing check was the live-input recheck. The staged component's independent post-seal output check was later in the publication path.

The previous Source admission physically observed each eligible source and saved its digest/extent. The component provenance observer held current-path fingerprints, and the compiler dep-info carried BLAKE3 and length. Those records did not retain the corresponding bodies. An older generation that already discarded its original source bytes cannot resume a successful publication from those fingerprints. The stage cache and receipt verifier require completed provenance, and the inspected live source or digest rows cannot stand in for it.

Release component passes now put the actual Source-admission body into a private generation-local, SHA-256-addressed store. Warm memo rows that lack a body acquire one through the same physical reader before compilation. The store is bounded by the active compiler storage allocation, the existing cumulative compilation byte ceiling and the existing file and entry limits. The driver retires its private source store on settlement. Compiler tests requesting the existing full retained compilation export keep their separate stricter custody route.

For a workspace Source input where this driver uses the new store, the receipt can name a body only if rustc's own dep-info checksum and extent match that body. The stored SHA-256 is the value emitted into the receipt. This rule also permits a previously retained, matching path that has since vanished. If no retained version matches, real current bytes have to match the checksum and remain under live file custody. The driver continues to recheck sources lacking compiler checksum evidence, non-Source files, directory structure, invocation configuration, and compiler and stage outputs. A generation refuses inconsistent consumed versions of one source path across multiple units, including a retained version paired with a current version in either order. The final seal reads each selected private blob again and checks its full physical bytes. Final Cargo provenance receipt publication still requires the compiler seal and the existing stage outcome checks.

The real component-driver regression uses an issued storage and capacity scope and an independently scheduled stage. A genuine rustc invocation emits dep-info for the admitted source. The independent stage changes the live source after the provenance observation and before the compiler seal. With the driver source witness disabled only in the test runner, the same test fails with “Current physical bytes changed before transfer” and no final receipt. With the witness enabled, the actual receipt names the previous source and the live worktree holds the edited source. The fixture compares the compiler checksum with Noble's BLAKE3 and the receipt hash with Node SHA-256. The companion fixture proves refusal for unknown consumed bytes, altered retained blobs and mixed consumed versions in both orders. The existing pre-seal case without a compiler checksum and post-seal stage-output mutation both still refuse. All five focused cases passed. No full module builds or edits to active supervisors were made.
