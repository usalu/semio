# Remaining Pair Disk Recovery

The host's internal data volume fell from 11 GiB free to 4.3 GiB during the active release. The largest local cache allocations were the host CAS, Rust image, dependencies image, graph image and products image. A read-only mount census found the fleet NFS export with 65 GiB free and no independently usable writable local volume. The NFS export carries shared fleet data and has a different filesystem owner from the compiler's local mounted storage. Moving compiler or product staging there would require a different admitted store, and would leave the existing host allocations in place.

The host CAS had one large unit-cache holder and both collector previews selected zero reclaimable objects. The host-pressure floor and the holder’s own cap are separate policy checks. Directly discarding holder records would risk the warm units required by the remaining release. The normal dependency-generation preview also selected zero retired generations. The six 1.4–1.7 GiB JavaScript installs under `j/` are all current scope pointers, including the root and Demonstrator scopes. The host had no APFS Data snapshots. The current nightly and the approximately 451 MiB user stable Rust installation offered no suitable scoped toolchain reclaim.

The graph image initially held 9.64 GiB with 2.32 GiB available. The host ledger wanted roughly 4.25 GiB of graph reduction, while the ordinary graph collector stopped at its own 2 GiB in-image floor, found zero superseded blocks and reported 421 MiB of optional groups below its low watermark. The first focused preview briefly encountered the graph lease held by the already-running broader read-only preview. The lease registry identified the exact dry-run process, which later settled.

The `selected` directory contained 13 orphan admission records using 1,646,055,424 allocated bytes. Each lacked both its graph publication and its authority publication. It also contained twelve matched graph and authority pairs, which stayed in place. The authorized recovery used the genuine graph partition, the existing global collector lease, the canonical nonwaiting writer lease for each selected scope and the core orphan-retirement primitive. That primitive rechecks absence and the original leaf stamp under its writer before unlinking. The generic selected-headroom wrapper admits up to 2.5 GiB, so the orphan-only operation used its existing measured termination callback for the approved 3.75 GiB target.

All thirteen orphan records retired. The graph image gained 1,646,145,536 available bytes and reached 3.86 GiB free. Canonical graph compaction then acquired the idle owner and settled. Its receipt measured 9,178,664,960 → 8,799,379,456 backing bytes, an additional reduction of 379,285,504 bytes during compaction after the initial retirement. The graph image remained available. Concurrent work continued to write to disk, and the last host reading was about 9.1 GiB free. Compiler units, CAS holder records and dependency installations stayed in place.

The bounded input is `graph-orphan-headroom.ts`. The owner receipt is in `🗑️generated/graph-orphan-commit.log`. The broader graph and dependency previews are in `🗑️generated/cold-disk-gc-dry.log` and `🗑️generated/cold-disk-deps-dry.log`.
