# Native component disk admission on November 25

Demonstrator run `wWRav8W` selected compiler lane `p85070d` and measured only 1 MiB of outputs already materialized in its shared build directory. Repaired Procedural run `wruWBuc` also measured only 1 MiB at admission and then reused 836 rustc units. These values describe different points in the build and different stores.

The upfront gate credits files present in the selected `generation.build` directory. It includes both conventional `deps` and the active Cargo layout `build/<package>/<hash>/out`. Replayed CAS units still have to materialize in that directory. The restore code uses `COPYFILE_FICLONE` for binary artifacts, whose normal-copy fallback requires actual write space, and rewrites text artifacts into the lane. A numerical CAS hit count is therefore insufficient evidence to reduce a before-launch disk reservation. Giving credit for an arbitrary CAS object would also require proving the exact input key, collecting or pinning it against eviction, and proving no physical copy is required.

The roughly 10.28 GiB estimate was reproduced independently from the eight real Demonstrator growth records under the exact `release|wasm32-wasip2|semio-hub-demonstrator-component` key. Python's inclusive quantiles yield 11,034,227,956 bytes at p90, or 10.276 GiB, and the unchanged 2 GiB reserve brings admission to 12.276 GiB. The selected compiler lane was cold at that point. The capture's 7.95 GiB free accounts for its reported 4.32 GiB shortfall. The storage-gate suite passed all 12 tests, including generated grid comparisons against the independent Python model and the new-layout warm-materialization test. This incident provides no evidence of a defect in the reported warm credit, so there is no production policy change.

The next Demonstrator run `w22Imi5` passed the same hard space guard while above 12.276 GiB and built 1,047 units. It stopped at the independent native-memory admission for `semio-hub-demonstrator` (the root library), which had recently measured 12.27–12.47 GB RSS. The local unit cache reported `no-endpoint` for a larger worker. The root mounts a concrete six-surface Playground/Sourcing/Process family through a single manifest; separate memory work there is needed. Disk admission was no longer the deciding limit for this attempt.
