# FEM target-width credit audit

The FEM release run wbXjJ9G linked no component. Its compiler reported a constant multiplication in the 2D session registry. A shell’s 1,507,885,056-byte upper bound fits in a WASI pointer-sized credit. Multiplying it by all 64 shells exceeds that range. Current 2D production source validates each slot and checks accumulation before writing either the total or the slot. An existing 2D registry law checks refusal preserves the slot and that releasing an admitted slot makes an exact admission possible again.

Two 3D numerical unit fixtures inferred 36- and 40-bit shifts as usize from their retained grant fields. Both now use the shared FEM receiving testkit bank, which evaluates the amount as a u64 and caps it at the target-width inventory. The 64-bit test amounts are unchanged. These fixtures compile only under their tests and are outside the release entry.

The isolated pointer-width probe compiled the current reservation body and shared test bank for wasm32-wasip2. It executed the same body on wasm32-unknown-unknown and Darwin ARM64. Python ctypes independently calculated the representable credit, and both observed models matched it. The 32-bit registry accepted two maximum shell credits totaling 3,015,770,112 bytes and refused subsequent credits. The 64-bit registry accepted all 64 totaling 96,504,643,584 bytes. The fixtures retain 2^36 items and 2^40 copy, capacity and release bytes on 64-bit hosts, and take the representable maximum on wasm32. The language-neutral values are retained in the ticket’s FEM credit fixture.

The audit followed the production hub entry through both editor session initializers, bounded job-kind registration and the 2D and 3D fixed registries. The 3D mounted solver uses 4,096 fields in 128 pages and 32 shells, with checked claims and a process credit small enough for 32-bit arithmetic. No additional target-width startup failure is evidenced by the source audit. Actual browser boot awaits the managed release queue. No FEM module build was started for this check.
