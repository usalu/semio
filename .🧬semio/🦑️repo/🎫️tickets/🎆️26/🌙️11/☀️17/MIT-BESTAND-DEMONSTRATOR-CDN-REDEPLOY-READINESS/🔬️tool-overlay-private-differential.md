# Tool Overlay Private Differential Feasibility

The earlier private, current-bridge Koordinator probe hit the action-owned exit at `0x4959728` 94 times; its ToolOverlay path returned an empty retained step. The current source correction is at the *outer* `MaintenanceUnit::ToolOverlay` arm: it returns `PluginLifecycleStep::AwaitingInput` when an action source is pending **and** the independent original ToolFollow owner is absent. Otherwise it drives the retirement step normally. The condition and its priority are part of the correction.

The confirmed old-core exit is inside `tool_overlay_retirement_step`, whose result type is `Result<RetainedCloneStep, OriginalTurnFailure>`; that inner type represents retained progress/completion, not the outer `PluginLifecycleStep::AwaitingInput`. Editing the existing inner result therefore cannot express the new behavior. A debugger or binary edit at a later outer return would have to prove the complete Rust enum encoding, reason lifetime, and conditional relationship to the independent follower, including other paths. The observed all-ones return-buffer sentinel alone does not establish that representation or the required semantics.

No private binary was patched and no acceptance result is inferred. The existing matched-core/current-bridge probe remains diagnostic evidence of the old behavior only. A new source-matched build and normal localized browser probes are required to establish whether the correction opens Koordinator and Aussuchen or exposes another failure. No stall guard, shell state, or published asset was changed.
