# Extension completion frames

The support-complete private Chromium run served the current Flow URL and all renderer fonts. All four Generator checks failed in English and German. Both boot checks saw an empty 3D scene. Both undo/redo checks recorded a refusal decoding a completed extension request. The Math and BREP invocations were the first named failures.

The WIT completion protocol specifies Pack for faults. Both browser renderer paths passed fault Pack bodies, while the guest's bounded fault receiver fed them to a JSON parser. The native host's independent receiver already expects a Pack fault. The guest now reads both completion outcomes with its existing bounded Pack body decoder. JSON remains the format of the stored correlation request. Successful partial pages still join their final reply. Error returns retain and decode their own original payload under the existing caller and close it through the original allocation accounting.

The browser fault writer now emits integer fields according to the diagnostic schema. It preserves a guest's existing Pack counters across forwarding, mints the integer carriers for source or span positions received as JavaScript numbers, and records zero retained work for a host fault created before a guest acquired work. Opaque nested diagnostic values retain their normal Pack representation.

A neutral 671-byte fault fixture uses the production browser encoder. The TypeScript suite first reproduced the JSON decoder mismatch, then passed all 29 assertions, including independent SQLite JSON comparison, AJV validation, typed round-trip of every field, preservation of the original wire bytes, and rejection of fractional positions. The five changed TypeScript owners passed their scoped typecheck. The native regression exercises the complete fault, its original source allocation and its retirement for both a response action and a parked request. Its managed Rust invocation is running.
