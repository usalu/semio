# Headroom Alone Admission Incident

At 06:19 PST `df` reported 4.7 GiB free on both the host Data volume and the 96 GiB Rust image. `repo fleet status` reported 4.6 GiB host free, 91.3/96 GiB Rust usage, and two live component writers: Demonstrator PID 96267 and Procedural PID 3488. The live headroom rows recorded both `running` with 15,461,882,265-byte reservations. These measurements are time-specific; the caller observed Procedural admitted at about 06:18 with 6.2 GiB free while Demonstrator was still compiling.

`decideHeadroomV1` reduces a running writer’s held reservation linearly to zero by its estimated ramp, and after that ramp plus `strandedGraceMilliseconds` (120 seconds) excludes it from `active` for the `alone` escape. This applies to every row, without checking process ancestry, actual write activity, whether a parent awaits this child, or a verified pause. Once a non-busy collector returns, the `reclaimed` flag becomes true even if no bytes were recovered. A first waiter can then be admitted despite a live independent writer and a shortfall. The test explicitly exercises a running row outliving the ramp; it does not establish a nested-only condition.

A correct deadlock treatment needs explicit, verifiable ownership and wait relationship: a parent must report it has stopped issuing writes, drained in-flight work, and lent or transferred its reservation to its specific child, with revocation and a paid handback before the parent resumes. An ancestor PID or elapsed time alone does not prove the parent is parked; an unrelated live writer remains a blocker for underfunded `alone` admission until actual retirement or a separately justified reservation decision. This is a design direction, not an implemented fix. The admitted commands loaded their own earlier code, so a source edit alone would not change their current decisions.

The supported single-flight unit-cache collector uses locks to protect active lanes and processes incremental sessions, stale units, idle lanes and cache objects in bounded stages; running writer monitors and its pressure watcher already call it. Recent `u/gc.log` includes stalled watcher exits (39 collections, 2,771,644,416 bytes freed; another 27, 4,052,992,000 bytes), without attribution to this exact pressure interval. It offers no guarantee of the immediate multi-GiB host gain required while two writers continue. APFS image block reclamation requires an idle image and a non-waiting exclusive image lease, so it cannot safely detach the Rust image while live writers hold it. The installed `u/ballast` is 33,554,432 bytes; it is reserved to permit metadata claims on ENOSPC and is automatically released when needed, not a multi-GiB emergency reserve.

The immediate controllable intervention belongs to the running-work owners: stop or pause a writer through its supported lifecycle and monitor actual host availability before any coordinated reclaim. Re-run the supported lease-aware collector only in coordination with those owners; use image reclaim only after the required exclusive, idle check. No writer, file, cache or mount was changed by this audit.

## Admission correction

The original headroom design recorded in `1029-result-cachegc.md` required no running or earlier queued command before taking the underfunded `alone` path. The later change in `ccac6866cc1` and `1030-result-deps.md` added an elapsed-time heuristic for a stuck lease. It recorded no parent relationship or write handoff. The contemporaneous `1030-review-infra.md` identified the long-running active-writer failure.

The shared Cargo and component launchers use image-headroom admission for their outer lanes. The component descriptor stage consumes the already-built emitter through an artifact reader. The emitter producer has a separate product lane and does not recursively acquire the same image-headroom claim. The existing same-process nested test admits a second writer with sufficient measured room. Repository source and tests exposed no supported underfunded nested handoff to preserve, so no ancestry or idle-time exception was introduced.

The age test now applies only to the outstanding-byte forecast. An underfunded `alone` admission requires an empty running roster from the existing heartbeat/PID-filtered ledger, no earlier waiter, and completed reclamation. Fitting admissions, FIFO accounting, waiting cancellation, and dead or silent record cleanup follow the existing paths. The original production file was updated at 06:25:27 PST with SHA-256 `6579c8ad51532a01a2c295b77fd57be706890e4c719fdc9d5821422ffaf47b10`. This edit changed no active writer, mount, or reservation.

The red neutral vector admitted with reason `alone` despite one live running row. The red process replay launched a Bun child through the actual gate, let it refresh a real ledger heartbeat and grow a real file, and measured 6.2 GiB of fixture headroom. The old gate changed the other command's ledger state from waiting to running while the writer remained active. With the correction, the waiter stayed queued while both the file and heartbeat advanced. The waiter took the `alone` path only after the writer released and exited. The neutral fixture agrees with the independent Python oracle and AJV validates its schema. Scoped diff verification passed.

All 20 focused headroom tests passed. Coverage includes normal nested admission when room fits, a live idle parent holding an underfunded nested caller until release, dead and silent ledger records, FIFO and cancellation, reserve decay, unmeasured volumes, and ENOSPC recovery.
