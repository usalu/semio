The root scopes exhausted all 12 physical CPU lease indices. Existing code subdivides capacity using process-local `AsyncLocalStorage`. A spawned repository script can borrow the driver's named Cargo FIFO but does not inherit that in-process scope. Compiler operations in the spawned script request actual CPU leases under a new root scope. The diagnostics showed a shared compiler-capacity gate wait for all three Procedural producer scripts and the FEM/GIS descriptor producer with no nested compiler descendant.

Procedural held three stage tokens and had three unread tokens available in its own FIFO, measured without consuming them. Its descriptor script additionally waited for the exact product lane `q53457c` held by FEM/GIS's descriptor process 94201. After more than 14 minutes Procedural still had no unit graph or guest compiler, while its peer advanced. The general lease inventory reported zero recorded waiters and cycles because the CPU-capacity allocator was still polling within shared ownership. The child processes require capacity to complete before both outer scopes can release. Issued CPU capacity and the Cargo FIFO are distinct forms of custody.

Only the stalled Procedural orchestration owner and its retry dispatcher were cancelled gracefully. FEM/GIS's guest compilers and descriptor job retained custody.
