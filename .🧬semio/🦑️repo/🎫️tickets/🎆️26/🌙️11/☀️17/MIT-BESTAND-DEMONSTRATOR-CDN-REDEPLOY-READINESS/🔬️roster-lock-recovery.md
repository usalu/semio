# Roster Lock Recovery

The coordinator now serializes its lifetime with a stable sidecar OS advisory lock. The existing owner marker remains the retry protocol endpoint. While holding the advisory lock, a successor only replaces a complete, matching legacy marker when the recorded PID is demonstrably absent; a live PID, uncertain process query, malformed marker, or unexpected marker contents is refused. The sidecar remains after normal marker cleanup, so concurrent openers always lock the same inode. A crash before publishing a complete owner leaves ambiguous evidence and is deliberately refused.

The language-neutral case fixture covers dead, live, malformed and uncertain owners. The synthetic Python suite additionally killed a real coordinator subprocess, checked simultaneous lock refusal and acquired the abandoned lock after the child was reaped. It passed natively, including the existing scheduler and retry scenarios. The repository tool invocation was cancelled while waiting on machine capacity. No real queue was started. Windows uses the standard-library byte-range lock and process query; this run was on macOS and did not exercise the Windows OS implementation.
