# Release package and verdict audit

The current intermediate Vite tree contains 4,439 entries. Its longest actual absolute path is 203 UTF-16 code units and its longest archive-relative path is 128. A read-only scan found no Windows-invalid component names or case/Unicode-normalization collisions. The result applies to this tree and current workspace path; arbitrary future extraction roots can still exceed platform path limits. The existing manifest fixture passed its independent system SHA-256 comparison and overlength/non-BMP checks.

The eight named Playwright boot cases navigate to their own pane route, wait for that pane's mounted shell readiness, and check its actual declared windows and content. The final matrix parser requires one passing result per pane in each locale and rejects missing, skipped, expected-failure and duplicate cases. The existing synthetic matrix test passed; it is a verifier test, not an application acceptance run. The final launcher checks staged receipts, inventories its captured site before and after the matrix, and publishes an accepted manifest only after all checks pass.

An independent archive fixture reproduced a release bypass: omitting the accepted manifest previously produced a valid archive of an unaccepted site. `package-site.sh` now requires the accepted manifest and compares it with both the current inventory and archive contents; the revised fixture rejects omission and a changed site while preserving the input, and passes a valid system-tar round trip. Older handoff commands now provide the required argument.

Static verification attempts now acquire an atomic directory lock before touching the shared verdict files and clear the previous acceptance marker at the start of every attempt. A synthetic overlapping invocation was refused before any build. Simulated build failure and termination released the lock, and both scripts passed Bash syntax checks. An uncatchable process kill or machine crash can leave the lock directory; it must be removed only after confirming no verifier still owns it. These shell and fixture checks ran on macOS; native Windows execution was not available here. No full site build, release archive or real pane acceptance was run in this audit.
