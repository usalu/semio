# Acknowledgement batches carrying command pages

The fresh Energy guest reached document transfer after providing the weather input’s missing accessible name in a diagnostic browser replay. The static host then raised `actor-poll.event-batch-carried`. A command page was attached to the last event in a batch. Two preceding or final events could each produce their own UI patch page. The old shard crossed both before returning any result to the renderer, which could no longer deliver each page with its own receipt.

The shard now cuts at the first patch-producing event even when the caller supplied a command page. Its activation retains the remaining events in order. A positive deferred-event count means the last crossing did not take place, so the caller still owns the original command page. React accepts the returned patches and acknowledgements, then offers the same page again under its existing wall deadline. WGPU uses the same contract.

The neutral page-cut fixture covers two patch-producing events. The original implementation posted both before the first result was consumed. The repaired implementation produces the expected event order, deferred counts and exactly one page submission. The real React command harness independently reproduced dropping a withheld page. Its repaired sequence submits pages 0, 0, 1, 1 across a host batch cut and then guest backpressure. All 182 actor-transport tests and 141 React plugin runtime tests pass. Browser acceptance is pending. Generated evidence is in `🗑️generated/page-batch-transport-full.log` and `🗑️generated/page-batch-react-green.log`.
