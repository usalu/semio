# Image Reclaim During Release Builds

Read-only check 2026-11-20. Supported per-image entries are `repo run repo-cache-reset:cache-reclaim-rust` and `repo run repo-cache-reset:cache-reclaim-products`. Both call `reclaimImageIfQuiescentV1`: it checks the reclaim predicate, pending retirement and a non-waiting exclusive image lease; held, not-due, failed or retiring returns `skipped`. On macOS the actual cycle detaches, attaches through diskutil's UNMAP-capable stack, waits for backing allocation to settle, then detaches; next opener reattaches. It is not a live trim, and neither route should detach an image held by a build. Generic `repo cache gc` without `--area` also considers these images, but includes other collection and takes a non-waiting try; no recurring between-job scheduler is established by this audit.

The Rust-specific `repo run repo-cache-reset:cache-reclaim-wait-rust` is an operator entry with a bounded 120-second queued exclusive request, proof of exact backing and mount, and repeated pressure/eligibility checks. It can catch an idle interval, but a queued exclusive lease can delay new users, and it still requires all existing holders to release the image before detach. It is not a non-disruptive live trim. Neither waiting nor the non-waiting path overrides eligibility.

At inspection host `df` reports 14 GiB available, Rust volume 35 GiB used, backing about 65.7 GiB allocated; products volume 8.5 GiB used and backing about 12.7 GiB allocated. Rust has about 30.7 GiB slack; products about 4.2 GiB. Current `nativeImageReclaimDueV1` requires both slack above its floor (under 48 GiB host free the floor is one eighth: rust 1 GiB, products 0.75 GiB) AND allocation at least 300% of used bytes. Rust ~188% and products ~149% both fail the ratio, so even an idle supported per-image call is expected to report `skipped`; exact values can change. The separate host-pressure image-slack planner may nominate mounted images using a lower slack threshold, but its actual reclaim calls the same predicate, so nomination is not proof of reclaim. No supported mounted/live macOS trim path was found.

A coordinated gap must finish both Rust-using builds, stop new Rust-image users for the whole exclusive detach/attach/settle/detach sequence, and verify no open handles; reclaim eligibility must also be resolved through the maintained policy/owner before the supported operation will run. Product image is separate: schedule its own idle gap only if product-image users are absent and its eligibility is resolved; its smaller slack makes it lower priority. Changing policy, launching a direct remount, or retiring/recreating an image is outside this read-only assessment and would require coordination. No mount, unmount, trim, reclaim or service action was performed.

## Aligned pressure eligibility

The automatic pressure collector and routine image cleanup have different eligibility rules. The pressure collector spends a non-waiting reclaim attempt on an eligible mounted image once the exact host volume is short of its free-space target and the recoverable slack clears the shared amount and percentage floors. Routine cleanup uses each partition’s configured bloat policy. The executor previously required both policies on the pressure route.

The pressure executor now retains the non-waiting exclusive image lease, then checks the current device, backing, mount, free-space target, retirement state and safe slack margin before invoking the reclaim cycle. The routine ratio, routine commands and operator waiting route retain their original policies. A busy image still skips immediately. Lease release and cancellation remain in the original execution path.

The actual pressure planner and the production executor body passed ten language-neutral cases against an independent SQLite decision oracle. The cases cover the observed 66 GiB allocated and 35 GiB used pattern, the routine threshold, lost pressure, insufficient slack, wrong device, a detached backing, a pending retirement, a busy writer and cancellation. Physical reads, leases and effects used controlled test ports. No live image was mounted, detached or reclaimed.
