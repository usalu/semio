# Rust Unmounted Cargo Audit

The canonical Rust mount directory currently contains a loose `cargo/home` created November 21 at 04:21–04:22. Its presence is not proof that the image is mounted; an attached image would hide those host-directory entries. The exact process that created it is not established by the available read-only evidence.

A concrete unmanaged caller is the unit-plan stability test (`🧰️framework/🔨️modules/🏃️process/📦️artifacts/🏗️native-build/🕸️units/🧪️tests/⚓️plan-stability/🟦️.ts:37`), which spawns Cargo directly with `CARGO_HOME` at that path; this establishes a possible mechanism, not the actual creator. External callers can likewise inherit or supply that environment without acquiring image custody.

Managed native builds require storage ownership and check that Cargo paths lie inside the owned backing (`native-build/🟦️.ts:334`, repo process `🏃️process/🟦️.ts:78`). These checks are part of the managed entry path; they cannot protect raw Cargo or tests spawning it directly. Repository leases alone cannot prove absence of raw filesystem users.

Fast safe recovery requires coordinating the existing external tests: let them finish, prevent new loose-path users, and independently recheck both the exact Rust image lease and kernel open handles. Verify the image is detached and its original backing identity before effect. Preserve the loose directory rather than removing it; after its users have closed, move it aside under a distinct sibling name only under exclusive coordination, then use the repository's canonical image activation/attach route. Verify the mounted backing identity and read the mounted Cargo home and build lanes before resuming work. Never mount over a directory with active unregistered users: open descriptors and later pathname lookups would refer to different filesystems. A rename while users continue can also redirect their future pathname lookups, so it is not a safe shortcut. If tests cannot be coordinated, wait; no safe simultaneous cutover was established.
