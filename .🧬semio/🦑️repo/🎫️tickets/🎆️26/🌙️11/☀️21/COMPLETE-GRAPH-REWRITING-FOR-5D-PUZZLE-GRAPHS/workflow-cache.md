# Workflow cache and media contract

The space runner visits nodes in topological order. It reuses a node when its document, configuration, input fingerprints, and output selection still match and the cache provides every selected output. A cache miss recomputes the node with its resolved inputs and records fresh output fingerprints. The runner holds connected media through its last consumer, so cache eviction during the run cannot invalidate a resolved edge. Dry runs use prior fingerprints and can underpredict recomputation after eviction or a change in upstream output.

The workflow validator compares the stored target media type and conversion to the endpoint negotiation. It also requires a registered converter for the negotiated pair when conversion is required.

The three-node cache fixture evicts the intermediate cached value before a second run, then forces the replacement out of the bounded cache before the final node reads it. The test checks the two guest imports, the cache eviction, and the final node’s input fingerprint. The conversion tests cover an omitted conversion, a mismatched stored type, an unregistered converter, and a correctly negotiated converter.

The shipped Trinity Rewriting and Puzzle 5D editor declarations expose `rule:out` and `rewrite:in` with the same Computation/Value media type and `trinity.rewrite.invocation` schema. OS negotiation chooses an intrinsic wire with no conversion. The runner sends the guest port IDs and repacks the intrinsic value between nodes. The mounted endpoint tests exercise the real media implementations. The runner's port-routing test now negotiates the production media type and schema with the OS negotiator, then checks transfer between fake guests. The real native host formerly rejected all guest commands before submission. It now checks the same kernel page limits as the other command hosts, retires rejected or interrupted host batches through their retained owners, and checks cancellation before admission and between settled guest commands. Cancellation still allows polling, cancelling and acknowledging an admitted document load. The native host regression checks these admission decisions at instance resolution.

Puzzle 5D now passes the runtime editor's I/O declaration into its packaged app manifest. Its checked-in Pack and JSON descriptors expose that same input, and both Puzzle and Trinity descriptor pairs passed the catalog's strict validator. The official workspace describe command was held behind a saturated project graph. The ticket's fallback input uses the repository Pack codec and descriptor finalizer and verifies that the Puzzle 5D editor's I/O declaration is the only semantic change.

All 31 native runner library tests passed, including the production-contract port transfer and native host admission and cancellation tests. The focused native host test also passed when run directly without a stack-size environment override. The complete suite ran under the repository's Cargo stack configuration. These checks cover the packaged descriptors and the runner's host admission. They did not run a workflow with both compiled guest components.
