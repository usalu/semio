# Native Border Implementation

The draw contract records inset semantic edges with layer, lane, paint slot, state, width, color and optional animation geometry. The frame finalizer projects each edge through its scissor and silhouette clip, resolves ownership across compatible foreground and overlay scopes, and emits the winning paint in late layers using the winner's clipping context. Scene and glass indices are rebased incrementally as late layers are inserted. Generated edges with the same anchor, owner and lane share a layer. Resolution, clipping, reconstruction, insertion and cancellation use incremental cursors and expose allocation and retained-capacity accounting.

Semantic shared borders are boundary overlays: they paint after their incident content, including a scene in the anchor layer. Ordinary solid primitives retain their original paint position for pre-scene decoration. Scene and glass boundaries prevent ownership from crossing unrelated surfaces.

The native draw tests cover semantic recording, hover precedence, partial overlaps, overlay isolation, clipping, animated effect payloads, cancellation and scene/glass reindexing. Repository build and test verification is pending capacity admission.

The resolver, source registry, clipping scopes, layer list and finalizer scratch use bounded paged backing. Late-layer UI instance batches are capped at 256, but their Vec growth admission still assumes `try_reserve_exact` returns the requested capacity. Rust permits an allocator to over-allocate, so a strict portable capacity guarantee for those batches requires exact boxed backing or another explicitly bounded allocation mechanism.

The production worker permits one item, 65,536 copy bytes, 65,536 capacity bytes, 262,144 release bytes and depth 64 per step. Paged payloads are at most 4,096 bytes; a late-layer batch has at most 256 80-byte instances, with at most 20,480 bytes of new backing and 10,240 bytes relocated at its largest growth. Radix-list traversal and the bounded balanced ownership trees fit the depth limit.

`Ui::frame_into_step` now requires an explicit retained grant and returns the actual receipt. Its demand query distinguishes append, rollback and no-append steps. The production retained document consumer preflights all grant dimensions and consumes every receipt. A pending frame owns its unpublished target builder; stale or faulted frames drive token rollback before the builder can be published. The engine fixture covers grant refusal and stale rollback after a partial append.
