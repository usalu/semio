## Root cause found and fixed (framework, not 2D-specific)
`UnsupportedOwner: context projection retains no matching original Store issuer` is NOT a missing owner declaration. Every typed command captures a read of the DRAFT store (`with_source_issuers`); the draft store is an `ArtifactStore` with its own 1,024-slot snapshot-read registry. The returned-read rotation (`next_snapshot_read_return_stage` / `advance_snapshot_read_returns_one`) pumped only four stages (document, config, interaction, transient), never the draft store. Each tick leaked one lease; at request 1,024 `try_issue_original` refused ("snapshot read issuer has no admitted vacant slot"), the projection stayed unbound, and context retirement raised the `UnsupportedOwner`. Proven with `[DEBUG]` counters (doc/config/interaction returned counts stayed 0; the draft fault fired exactly at slot exhaustion). 3D shares the framework path and has no equivalent long test (no `frame_cost` test exists there), so it carries the same latent bug.

Fix (product, minimal): a fifth rotation stage for the draft store.
- `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🧵️instance/🏪️stores/📥️staging/🧱️components/🦀️.rs`: `LocalInteraction.draft_snapshot_read_returns: SnapshotReadReturnPump`.
- `.../🧵️instance/📄️docs/📥️staging/🚪️ingress/🦀️.rs`: stage `4` in demands, next-demand, step, `next_snapshot_read_return_stage` (rotation modulo 4 -> 5).
All temporary `[DEBUG]` edits (typed-command staging, owned-context `with_source_issuers`, the test) were removed.
