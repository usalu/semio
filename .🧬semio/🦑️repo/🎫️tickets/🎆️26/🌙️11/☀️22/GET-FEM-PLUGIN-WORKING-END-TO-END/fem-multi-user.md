# FEM multi-user: peer catch-up and presence roster (3D and 2D)

## Root causes
1. Presence roster fault `native decoding ownership exceeds caller limit` (any peer, any grant): `PeerRosterPublication::step` (`🔌️plugin/👥️peer/🦀️.rs`) builds its decoder with `NativeDecodeControl::new_retained` (ceiling 0, "each original retained turn must supply its grant") but never admitted the turn grant. The stage `PresencePeersPublication::take_commit` (and `adopt`) charges the Arc birth through `original.native().scoped_stage(.. charge(..))`, so it always exceeded the 0 ceiling, whatever the loan. Fix: `native.admit_turn_capacity(grant.maximum_capacity_bytes)` right after construction, the same pattern as every other retained decoder (store, cold apply, transient publication).
2. Peer catch-up dedupe conflict: each app instance mints its own document id (`time_ordered_id`), and `load_document` deliberately re-stamps a loaded pack with the live identity. The store re-derives its established envelopes under its own id, but `same_operation_identity_and_payload` also compared the origin `document_id`, so any re-delivery of another replica's edit (second catch-up, reconnect re-announcement of a replica's log) failed with `remote mutation id .. conflicts with its established payload` although mutation id, schema and payload were identical. Fix (`🏪️store/.../📒️store-log-operations/🦀️.rs`): operation identity is mutation id + schema + payload; the origin document id is replica-local naming.
3. Original test intent restored: new law `join_document` (`🧪️testing/🧪️artifact-app-laws/🎟️fixture-dispatch-steps-and-document-loading`, re-exported) joins an app to an existing document keeping the pack's own identity (no live-store stamp). The 3D test now joins the second peer to the first peer's genesis, asserts equal `document_identity()`, and re-delivers the OTHER peer's events (`from_second`) to check dedupe (snapshot unchanged, event log length unchanged, one report per envelope). The `!accepted` assertion of the original is not restorable: a duplicate is reported as an accepted no-op by the store contract (`no_op_report`); dedupe is proven by the unchanged snapshot and log instead.
4. Cross-test shared state: not reproducible after the fixes. Full `editor_app` 3D run: both tests pass in the full run (peer catch-up just slower: more than 60 s under 94 parallel tests on a loaded host vs 20 s alone). The earlier "alone ok, full fails" was the dedupe conflict plus the roster fault surfacing differently under load; no static or thread-local state shared between these tests was found (only `UI_ARENA` and `HOST_LIFETIME` thread-locals in the fixture kit, per test thread).
