## Clean Long-Term Solutions for Development Speed

1. **Shared content-addressed build cache for native tests.**
   - Today about 8 agents each compile the same about 900 crates privately. One cache keyed by source hash and profile (sccache-style, or the repo remote cache behind `repo test`) would cut a law run from 30–90 min to minutes.
   - This is the biggest win.
2. **Prebuilt per-plugin test binaries plus a test-filter service.**
   - Agents ask "run law X against tree hash H".
   - A warm daemon keeps the binaries linked and relinks only changed crates.
3. **Fast wasm publishing.**
   - Split the 230 MB FEM component into a stable framework layer and a thin plugin layer, or use dynamic component linking.
   - Make `prototype` incremental-safe.
   - Target: under 10 min from edit to browser. Today it is 45–90 min.
4. **Atomic change sets in the shared tree.**
   - Today's failures came from half-written edits by peers: a dev-dependency, a dropped API, and in-progress crates breaking unrelated test builds.
   - A per-agent overlay that lands only when it type-checks (a `repo` transaction) would remove this whole class of failure.
5. **Schema-first conformance suite instead of ad-hoc harness checks.**
   - About 70% of this round's FAILs were harness defects: fixed sleeps, text scraping, order dependence and stale expectations.
   - Promote `matrix-v3` into a maintained suite in the repo, with:
     - accessible selectors only;
     - fresh state per check, or explicit preconditions;
     - polling on semantic readiness signals that the app exposes, such as a `data-settled` attribute or a settle event, instead of timeouts;
     - one browser context per area against a warm server pool.
6. **App readiness and settle signals as a framework feature.**
   - Every window should expose "settled / working / failed" through ARIA live regions and a testable attribute.
   - Users would see clear status, and tests and agents would stop guessing with timeouts.
7. **Invariant budgets as laws, not browser discoveries.**
   - Turns and crossings per interaction, guest memory per example, slot-table occupancy after N cycles, and history-entry count per gesture.
   - The read-slot leak, the House memory overshoot and the empty undo steps would all have failed at the law level within minutes.
8. **Deterministic time in the framework.** Ban wall-clock asserts and wall-clock fault decisions in laws and runtime classifiers. Inject a clock, and decide by progress receipts. This class of flake appeared four times in this ticket.
9. **A typed trace channel instead of `[DEBUG]` console lines.** It can be switched on per run, which keeps probes readable and the console fast.
10. **A process supervisor owned by `repo`**, using Windows job objects. Long runs would be safe to start from any agent without detached-launch workarounds, and zombie or stale-PID cleanup would be automatic.
