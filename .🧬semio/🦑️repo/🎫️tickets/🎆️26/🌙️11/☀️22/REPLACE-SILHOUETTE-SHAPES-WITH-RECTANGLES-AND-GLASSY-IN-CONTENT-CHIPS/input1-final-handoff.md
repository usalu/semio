# 🧯️ shell-tests-input-1: final handoff (73/73)

Crate `semio-renderer-wgpu-shell-tests-input-1`. Start of this pass: reported 54 passed / 19 failed (the first full run never finished compiling, see "Measurement"). End: **73 passed / 0 failed**, both from the test binary run directly and from a full `repo cargo test --no-fail-fast` run.

## Root cause of the dominant cluster (`Layout.CloseSession invariantViolated`, about 15 tests): a product bug
- `Ui::begin_document`, `apply_document_page` and `finish_document` refused a document unless `cx.generation() == header.generation`.
- The engine's own rule says the opposite: `ui_document_ingress_generation` ("which ingress is this, never who produced it") and the fixture `document-tree-reconcile/🔣️.json` `ingressGeneration.rule` ("A surface's document is admitted by its ingress generation alone").
- Production cannot satisfy the turn-generation equality: every native frame caller is `Generation(1)` (`⌨️native-entrypoint/🎟️launch` `caller()`, `compiler_caller()`, and `NativeFrameEventIssuer`), while the Shell mints ingress generations `1, 2, 3, ...` per surface (`publish_surface_records` through `ui_document_ingress_generation`). Every second document of a surface would have been refused with `StaleGeneration` in the real frame loop.
- The fixtures that tried to mimic the check with one caller per generation could not close the predecessor's layout worker session (a layout session can only be driven and retired by the original caller that birthed it), hence `Layout.CloseSession invariantViolated`.
- Fix (product): the three turn-generation comparisons are removed from `⚙️engine/📄️viewport-and-document-ingress/🦀️.rs` (`begin_document`, `apply_document_page`, `finish_document`). Wrong-generation protection stays where it belongs: `UiDocumentTree::try_push_page` rejects a page whose generation differs from the ingress, `finish_document` still compares the ingress generation, `begin_document` still refuses a non-greater generation (`aba` hostile fixture unchanged).
- Law changed (justified by the rule above): `retained_document_page_with_a_live_wrong_generation_remains_a_terminal_fault` asserted that a correct page applied from a turn of another generation faults. That premise is exactly the bug. It is now `retained_document_page_of_another_generation_remains_a_terminal_fault`: a page of generation 2 applied into an ingress of generation 1 is a terminal fault (`🗣️Interpreter/🧪️tests/🔬️wgpu-ui-command-wiring/🗂️retained-document-queue-and-editor-fixtures/🦀️.rs`, `ingress_opportunity_document` takes a generation).

## Fixture changes (mirror production: one long-lived caller)
- `PointerFixtureTurns` (`🎯️targets/🧊️wgpu/🧰️fixtures/🐚️shell/🦀️.rs`) is now one lazily born wide caller at generation 1 instead of one turn per document generation. API: `serving_world_closes`, `turn()`, `retire_shell_worlds` (uses `advance_world3d_retirement_step_in`), new `pump_document_close_one()` (one `close_ui_document_one` opportunity on the mounting caller), `finish`, `finish_with`. No `OriginalJobFixtureCaller` change was needed.
- `FixtureTurnV1` (`🧪️tests/🎟️original-turn/🦀️.rs`): `wide(..)` now stretches the Source stock by `WIDE_STOCK_SCALE` (1024). Reason: one fixture caller stands for a whole scenario of native frame events, each of which is a fresh caller with its own stock; with the 1 GiB single stock `renderer_canvas_sequential_window_close_reuses_retained_surface_capacity` (257 windows) ran out of copy budget at window 208 and its close spun forever. New `cumulative_receipt()`; removed the now unused `disown_surface`. Only `wide` callers get the larger stock; `new`, `for_generation` and `with_identity` are unchanged.
