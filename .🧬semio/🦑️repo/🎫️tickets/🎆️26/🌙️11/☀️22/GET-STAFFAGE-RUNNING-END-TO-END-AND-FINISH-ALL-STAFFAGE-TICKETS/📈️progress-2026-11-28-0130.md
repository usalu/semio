## Clean long-term solutions for development speed

1. **Tests that scale with what changed, not with the catalog.**
   - Every staffage suite should take an asset set derived from the change: changed asset files, or all assets when shared code changes. Make this the default through the build graph (`repo affected` down to the asset level), with full runs only in CI or nightly.
   - Today a single shared change means 36 shards × 30–100 min.
2. **One process per asset with bounded memory, as the test contract.**
   - Make it a rule, in the framework test runner, that no test file loads the whole catalog. MEM-CARVE fixed 25 files by hand; a lint or test (`🎯️bounded-catalog-load`) generalised to all suites prevents a relapse.
   - The model-catalog suite should become a per-asset target with its own cache key (asset hash plus shared code hash). Then unchanged assets are cache hits and never rerun.
3. **Content-addressed caching of the derived assets.** GLB, FBX, JSON and the 2D drawings per asset, pose, scale and mode should be build outputs in the remote cache, keyed by input hashes. Matrix and model-catalog checks then read cached outputs, and a rerun after a shared change recomputes only what depends on it.
4. **Budget checks as fast unit oracles.** GLB size, triangle budgets and bounds can be computed from the scene description without writing files. A fast estimate gate would let modelling lanes iterate in seconds instead of 10–60 min queue round trips; today Fable lanes spend most of their time waiting.
5. **Capacity by measurement, not by guess.**
   - Every `repo capacity run` should learn its class peak (MEM-ADMIT started this) and every lane script should drop hand-written `--memory`.
   - Admission should run on observed footprints, and the warden should be the only enforcement, as it now is.
   - Add a per-agent fair share, so one coordinator's 36 shards cannot starve other agents.
6. **Fleet offload for tests, not only compile units.** The fleet already restores cached compile units, but test runs fall back locally. Offloading staffage suite shards and matrix assets to idle fleet machines would multiply throughput by the number of machines (50+), which is the largest single gain available.
7. **Stable tool code under the shared worktree.** Live edits of the repo tool cause warden restarts (119 in one day) and half-edited states for every agent. Run tools from a versioned, built snapshot (content-hashed) that updates atomically, never from the live source tree.
8. **Standard lane kit.** A tested framework tool for the recurring lane patterns would remove most per-lane tool writing:
   - write an asset with proof (gate, guard, sweep, check, matrix, model-catalog);
   - wait on a pid;
   - run a batch through the queue with resume;
   - a JSON summary of vitest reds.

   Today every lane rewrites these in `🧰️matrix/<LANE>/`.
9. **Reports as data.** Lane reports should carry a machine-readable header (status, assets, files, proofs, measured numbers) next to the markdown. The coordinator can then aggregate without reading prose, and `ticket_close` file lists come out exact.
