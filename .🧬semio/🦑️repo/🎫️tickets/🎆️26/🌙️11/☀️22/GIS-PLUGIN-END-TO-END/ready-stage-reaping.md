# Ready Stage Reaping: the lease owner of a stage must not reach the shared service

## Chain (evidence)

1. `.cache/f/ready/kills.log`: SIGTERMs of the ready stage runner (runner 80971, stage `workspace`) at 12:03:21Z and 12:30:12Z (also 12:36:53Z) with reason "it is an orphan that carries the owner token of a stopped try of this stage" (`ready:31a731c45270:workspace:1795778187130`), victims bun processes 39162/39226, 76652/76739, 89202/89313. Each is followed by `request-failed a4605e03 Error: Original Script process terminated` in the service log (`host-cab6c900d7b4.log` line 4868 and its neighbours). Separate kill rows give the reason "showed no output and no processor time for 600 second(s)" (09:25Z, 09:39Z, 11:00Z, 12:02Z, 12:29Z, 12:56Z, 13:07Z): the quiet rule.
2. The orphan rule (`readyOrphanVerdictsV1`, `🧰️framework/.../🚦️ready/🌲️process-tree/🧹️containment/🟦️.ts`) judges a lease registry entry by its `owner` field, which `registry/🟦️.ts` fills from `process.env.SEMIO_LEASE_OWNER` of the process itself. It spares only resident services (`sharedCommandPattern`, with the tree below a service pid) and a process that has no token. So any process that inherited the token of a stopped try is a victim, whichever client it works for.
3. Where the token entered the service (code reading, both routes):
   - direct spawn: `spawnHostServiceV1` copied `environment` and deleted only `CLIENT_BOUND_ENVIRONMENT_V1` (`SEMIO_SCRIPT_PROCESS_OWNER`, `SEMIO_SCRIPT_PROCESS_INVOCATION`, the capacity grant and plan variables). `SEMIO_LEASE_OWNER` was not in it.
   - launchd route: `allowedEnvironmentV1` allows every `SEMIO_*` name that does not match `SECRET_NAME_V1` (`TOKEN|SECRET|...|INVOCATION|PROCESS_OWNER`). `SEMIO_LEASE_OWNER` matches none of them, so the job property list carried it.
   - spawn of the workers: `createSlicePoolV1` `runWorker` started every slice worker with `{...process.env}` of the service, so every worker of every client carried the token of whichever stage try started that service generation. Workers are bun processes with their own lease registry entries, exactly the victims in `kills.log`.
   The launched run-many in the GIS ticket was started by the coordinator's wrapper below the stage and carried the token itself (ticket note: run-many 44998 had parent 80971 and the token). The coordinator's service generations were started by stage tries too, so the workers they served were orphans of "a stopped try" once the try was replaced.
4. Live observation that the trigger exists (`ps eww`, 14:23 local): the stage try `ready:31a731c45270:workspace:1795785822160` (pids 85106/85108, `SEMIO_LEASE_OWNER` set) started a new service generation (wrapper 85258, service 85371 and its child 85453, launchd label `tech.semio.repo.service.6a4424398572`, tag `e17ccd69400c`). The old generations that carried the token are gone; I could not read their environment after the fact, so the carriage of the older generations rests on the code path above (reproduced by the tests below: the old allow-list passed `SEMIO_LEASE_OWNER`).
   My own shell does not set `SEMIO_LEASE_OWNER` (only `SEMIO_REMOTE_CACHE_*`, `SEMIO_FLEET_*`), which is why my launches were clean and the token still reached other clients' work through the shared service.

## Fix

Root: the shared service belongs to no client, and a client's lease owner travels with the request.

- Service spawn: `🏡️resident/🏗️composition/🌐️host/🟨️.mjs` `CLIENT_BOUND_ENVIRONMENT_V1` (now exported) holds `SEMIO_LEASE_OWNER` (imported as `LEASE_OWNER_ENVIRONMENT_V1` from the lease registry, one source), `SEMIO_BUILD_INVOCATION_PID` and `SEMIO_BUILD_INVOCATION_PIDS` (the build invocation chain of the client's run, which would make the service pass as holding the client's leases) next to the owner pid and invocation that were there. `spawnHostServiceV1` deletes them for the direct child and the launchd job.
- launchd allow-list: `🍎️launchd/🟨️.mjs` `SECRET_NAME_V1` now also refuses `LEASE_OWNER` (invocation names were refused already).
- Per-request owner (schema first): `🏡️resident/🧬️schema/🔣️.json` `PlanRequest.owner` (`^[A-Za-z0-9:._-]{1,128}$`). Client `🚪️client/🛰️plan/🟨️.mjs` sends its own `SEMIO_LEASE_OWNER` as `owner`; `🏛️service/🌐️host/🟨️.mjs` passes `frame.owner` to the planner port and includes it in `jobKeyV1`; `🔌️ports/🧭️plan/🟨️.mjs` hands it to `loadSlice`; `⌨️command/🌐️host/🟦️.ts` to `slicePool.run`; the pool (`👷️slice-pool/🟨️.mjs`) puts it into `shareKeyV1` and `baseOf` (loads of different owners never share a worker, never merge, and a worker never carries the owner of a joiner) and builds the worker environment with the new pure `sliceWorkerEnvironmentV1(base, request)`: no grant, no inherited lease owner, the owner of the request when it names one. Types in the matching `.d.mts` files.
- Stage runner quiet rule (`🚦️ready/🌲️process-tree/🟦️.ts`, schema `Policy`): new `capacityWaitPatterns` (the `[capacity] waiting N` line of a command and the slice reservation pending/wait, memory headroom and previous generation lines of the graph service, English and German), `capacityWaitLookbackLines` 4, `capacityWaitFreshMilliseconds` 120000, `capacityWaitMaximumMilliseconds` 10800000. `readyCapacityWaitLiveV1`: a wait line among the last lines, a log written within the fresh window (a waiting planner says so again every few seconds, a wedged one does not) and a wait younger than the maximum count as liveness: the stall stop, the cpu-only stop and the soft-deadline idle rule do not run (it joins `liveRead` in the watch loop of `🚦️ready/🟦️.ts`). `readyWaitLineV1` (stale-waiting) now also knows the reservation lines. A gate that never answers still ends in the stall stop after 3 h.

## Tests

- `🏡️resident/🧪️tests/🪪️request-owner/` (rows `🔣️.json`, fixture `🔎️env-probe.mjs`, 12 pass): the service spawned with a stage owner, build invocation pids, script owner and grant in its environment sees none of them (real process) and keeps `SEMIO_LANGUAGE`; the launchd allow-list drops them; `sliceWorkerEnvironmentV1` rows (owner carried, none carried, request owner replaces an inherited one, an inherited one is never taken, empty is none); frame validation of `owner`; a real pool with `process.env.SEMIO_LEASE_OWNER` set serves three requests (two owners, one none) with three workers that each carry exactly their own owner and three distinct share keys.
- `🚦️ready/🌲️process-tree/🧪️tests/🚦️capacity-wait/` (rows `🔣️.json`, 13 pass): wait lines in both languages (and not the granted or taken lines), lookback, liveness law rows, and stages run by the real stage runner with a fake `repo`: a changing-number reservation wait and a `[capacity] waiting` line for 12 s with `stallStopMilliseconds` 4 s are not stopped; a repeated non-wait line, a wait past `capacityWaitMaximumMilliseconds` and a wait line followed by silence are stopped as quiet.
- Regressions (bun from the test directory): `client-kill` 3, `slice-share` 5, `slice-coalesce` 6, `launchd` 9 pass; broader suites listed below.

## Residual

- A planner whose output goes to a file outside the stage's log (the coordinator's `excl-*.log` redirect) is invisible to the stage log, so the log-based liveness cannot see its wait. Start such planners detached from the stage (no `SEMIO_LEASE_OWNER`, now enough because the service no longer lends the token) or let the stage's own command print them.
- A plan job shared by clients of the same owner (two lanes of one stage) carries that owner; clients of different owners no longer share a job or a worker (the price of the guarantee).
