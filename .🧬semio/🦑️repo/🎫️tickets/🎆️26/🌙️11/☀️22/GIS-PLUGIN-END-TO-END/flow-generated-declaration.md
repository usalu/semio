# Flow Browser Generated Declaration Blocker

## Root cause
- `walkImportsV1` (`🕸️graph/📥️inference/🧭️script-inputs/🟨️.mjs`) resolves every command import of a walked module. When `require.resolve` and the TypeScript resolver both fail and the specifier ends in `.ts`/`.js` (`DECLARED_MODULE_SUFFIX_V1`), it throws `BUILD_SOURCE_UNPARSEABLE` (slice worker exit 75).
- The only escape is `cache.generatedOutput`, which resolves ignored outputs declared as `outputRoots` of a `generatorContracts` entry in `📚️library/🔣️taxonomy.json` (or wasm `compileOutputs`).
- `…/🌐️browser/📝️declaration/🤖️generated/🟦️.d.ts` is matched by `.gitignore` `**/🤖️generated/`, declared by no contract, and written only by the ownership test, so a clean checkout can never plan the target that would write it.

## Decision
The file is already treated as an authored declaration (ownership fixture `projections` kind `authored-declaration`, docstring "tracked source declaration projection", authored `.d.ts` and JSDoc import it). A generator contract would be wrong because no build target produces it. It becomes a checked-in projection:
- `.gitignore`: negation `!/🧰️framework/…/🌐️browser/📝️declaration/🤖️generated/` after `**/🤖️generated.*`.
- Drift check already exists: `semio-framework-os-flow-browser-package:test-browser-ownership` asserts the on-disk file equals `flowBrowserDeclaration()`.
- Content generated by `write-flow-browser-declaration.ts` in this ticket (`repo tools exec --light bun`).
