# Puzzle Component and Guest I/O Verification

The existing prototype `wasm32-wasip2` build completed in 89m 18s. The output is the 203 MiB `semio_hub_puzzle_component.wasm` in the ticket builder’s `lane-wasip2` target. JCO 1.39.0 decoded the component and reported the expected reactor, jobs, checkpoint, describe and codec exports. The main core module contains 463,430 functions and has a maximum of 907 locals in one function. The WASI adapter has 45 functions and a maximum of zero locals. The separate `wasm32-unknown-unknown` artifact still has a function with 59,535 locals, above the 50,000 limit.

`repo capacity run` admitted the JCO transpile. Using the production async instantiation and import-mapping settings, JCO emitted a 777 KiB factory, a 203 MiB core and two small adapter cores. The ticket script applied the production JCO rewrites and host shim. The production descriptor probe ran under Node v24.15.0 with JSPI, instantiated the module, validated its actor exports and called its actual `describe()` method. The returned 319,306-byte pack passed canonical decoding and re-encoding. Its descriptor advertises the editor and viewer for each of Puzzle 2D, 3D and 5D. These outputs were written only to the ticket’s generated directory.

The existing component used frozen sources. Its descriptor differs from the checked-in component metadata in three asset hashes, the media type of three 5D examples, precision of the 3D default layout’s two widths, and the 5D editor’s `rewrite:in` port. The live Rust source and checked-in metadata both contain that port. Shipped component verification requires equality to the committed pair. The prototype driver permits local descriptor drift, with publication still requiring the emitted browser descriptor to match a genuine model receipt. The committed metadata was left intact.

The `@semio-tech/puzzle-plugin:test-guest-io` and Cargo MCP calls both timed out after 300 seconds. The registered CLI guest I/O and Puzzle 3D activation targets, the CLI `workspace:components` description target and the direct `repo cargo` compile-only guest I/O call all stopped in repo source admission before reaching Cargo. The concrete error was `Owned auxiliary publication failed: descriptor=3 phase=end-callback code=EPERM syscall=write` (reference `07fd2723`). Moving the cache and graph socket handling into writable locations was sufficient to reproduce the error past initialization. The guest I/O acceptance scenario and official publication have no passing result. The UI lane also reproduced an `EPERM` on a plain local network listener.

The authored guest I/O fixture passed both Semio’s JSON Schema subset validator and Ajv’s draft 2020-12 validator. Both rejected a copy that sets `progress.minimumCompleted` to `0`, which would allow progress without useful execution. This exercises the fixture contract before the scenario’s component and compiler requirements.

Reproduction inputs are [the Wasm locals scanner](guest-wasm-locals.py), [the browser assembly and descriptor probe](guest-browser-probe.ts) and [the native fallback build invocation](guest-component-current.sh). The fallback reads the live workspace with `--offline --locked`, applies the same prototype profile as the frozen build with thin LTO disabled, and uses one Cargo job. The frozen binary was retained by hardlink before the fallback started.
