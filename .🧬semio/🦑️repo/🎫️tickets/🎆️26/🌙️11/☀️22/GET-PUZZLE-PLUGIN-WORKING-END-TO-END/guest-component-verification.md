# Puzzle Component and Guest I/O Verification

The existing prototype `wasm32-wasip2` build completed in 89m 18s. The output is the 203 MiB `semio_hub_puzzle_component.wasm` in the ticket builder’s `lane-wasip2` target. JCO 1.39.0 decoded the component and reported the expected reactor, jobs, checkpoint, describe and codec exports. The main core module contains 463,430 functions and has a maximum of 907 locals in one function. The WASI adapter has 45 functions and a maximum of zero locals. The separate `wasm32-unknown-unknown` artifact still has a function with 59,535 locals, above the 50,000 limit.

`repo capacity run` admitted the JCO transpile. Using the production async instantiation and import-mapping settings, JCO emitted a 777 KiB factory, a 203 MiB core and two small adapter cores. The ticket script applied the production JCO rewrites and host shim. The production descriptor probe ran under Node v24.15.0 with JSPI, instantiated the module, validated its actor exports and called its actual `describe()` method. The returned 319,306-byte pack passed canonical decoding and re-encoding. Its descriptor advertises the editor and viewer for each of Puzzle 2D, 3D and 5D. These outputs were written only to the ticket’s generated directory.

The existing component used frozen sources. Its descriptor differs from the checked-in component metadata in three asset hashes, the media type of three 5D examples, precision of the 3D default layout’s two widths, and the 5D editor’s `rewrite:in` port. The live 5D test confirmed the Rust receiver existed while the `AppIo` declaration had lost the port. The checked-in metadata declares it at index 1, following `kit:in`. Its English and German names are “Rewrite Rule” and “Umschreibregel” in both terminologies. Its direction is `in`, media class is `computation`, media form is `value`, kind is `trinity.rewrite.invocation`, required is false and multiplicity is `one`. Shipped component verification requires equality to the committed pair. The prototype driver permits local descriptor drift, with publication still requiring the emitted browser descriptor to match a genuine model receipt. The committed metadata was left intact.

The `@semio-tech/puzzle-plugin:test-guest-io` and Cargo MCP calls both timed out after 300 seconds. The registered CLI guest I/O and Puzzle 3D activation targets, the CLI `workspace:components` description target and the direct `repo cargo` compile-only guest I/O call all stopped in repo source admission before reaching Cargo. The concrete error was `Owned auxiliary publication failed: descriptor=3 phase=end-callback code=EPERM syscall=write` (reference `07fd2723`). Moving the cache and graph socket handling into writable locations was sufficient to reproduce the error past initialization. The guest I/O acceptance scenario and official publication have no passing result. The UI lane also reproduced an `EPERM` on a plain local network listener.

The authored guest I/O fixture passed both Semio’s JSON Schema subset validator and Ajv’s draft 2020-12 validator. Both rejected a copy that sets `progress.minimumCompleted` to `0`, which would allow progress without useful execution. This exercises the fixture contract before the scenario’s component and compiler requirements.

Reproduction inputs are [the Wasm locals scanner](guest-wasm-locals.py), [the browser assembly and descriptor probe](guest-browser-probe.ts) and [the native fallback build invocation](guest-component-current.sh). The fallback reads the live workspace with `--offline --locked` and applies the same prototype profile as the frozen build with thin LTO disabled. The frozen binary was retained by hardlink before the fallback started.

The first fallback was cancelled after 420 compilation units because it had already compiled the paged text, DSL record model and Pack cursor crates before the projection repair landed. The second invocation used two Cargo jobs in the same warm lane and compiled all three fixed crates. The 5D `rewrite:in` declaration and native history changes landed before that invocation reached any 5D crate. At 548 compilation units it failed in the 3D fill precompute with error E0407. The compiled `InteractiveJob` metadata predated restoration of `checkpoint_follows_preview` in the live workspace at 21:20 CET. A third invocation started with the warm cache and restored trait.

That third invocation stopped at 178 compilation units with E0599 in tool-run operations. The compiled mutation receiver trait still predated the live addition of `ready_for_owned`, which tool-run operations now calls. The warm lane resumed again after both the trait and callers had been updated.

The fourth invocation stopped at 116 compilation units because the filesystem had three free inodes despite 48 GiB free. The official guest I/O ingress and native Cargo compile-only fallback also failed during that inode shortage. The coordinator reclaimed over 38,000 inodes from finished build outputs. The fifth invocation resumed the same WASI cache. The production guest I/O retry still failed with the descriptor-3 write permission error. The compile-only Cargo retry started and made progress in the native cache.

The production model publisher consumes the exact privately retained linked result provided by the admitted native build driver. It requires an issued repository invocation, a live compiler writer reservation, matching native provenance and a descriptor emitted inside that scope. The reader checks the resulting products-store roster, artifact identity, content digests and receipt. No supported path was found for adopting standalone Cargo Wasm into that model store. The standalone descriptor probe therefore establishes component behavior independently of model publication.

The isolated [auxiliary descriptor probe](guest-owned-fd3.mjs) reproduced the failure without the repo graph. With the same sandbox and capacity admission, Node v24.15.0 delivered text on descriptor 3 to the subprocess. Pinned Bun 1.4.2 returned `EPERM` from the first write. The launcher registry pins Bun 1.4.2, and it is the sole cached Bun runtime on this host.

The [native Bun descriptor experiment](guest-bun-fd3.mjs) found two distinct faults. A Bun-native `socket-fd` sent a small payload when wrapped in a standard Socket, but that wrapper fails with `EAGAIN` once the socket needs backpressure. Bun’s asynchronous `Bun.write` on the same caller-owned nonblocking descriptor completed the full payload. The owned command route now uses that native transport for its auxiliary descriptor on Bun POSIX, closes the descriptor after completion and joins the same child on cancellation. Its ordinary stdin, output limit and failure-settlement logic remain in the owning process command.

The [genuine worker replay](guest-bun-transport-law.ts) passed all nine cases of the authored subprocess fixture, including exact streamed and hashed output, 33,554,433 bytes of auxiliary input, 30 MiB of streamed stdout, distinct ordinary stdin, `EPIPE` on a closed reader, cancellation and deadline identity, and exit status 7. Its outer runner used native Bun stdin because the ordinary Node-compatible capture runner supplied an empty stdin under this sandbox. Eight schema, independent SQLite/oracle and error-context tests also passed. The registered Puzzle guest I/O retry no longer fails at FD3 and advanced from `source.capture` to `source.served`.

The production capture path now passes finite immutable stdin through Bun’s native subprocess input on POSIX. That preserves the ordinary channel and EOF when the immediate child passes stdin to a descendant. The registered repository runner passed every auxiliary publication, failure-context and terminal-settlement test (11, 6 and 4 tests, respectively), all four ordinary input tests and all seven strict encoding tests. The binary input cases compare exact returned bytes to SQLite and the largest case also compares a separately computed SHA-256. The text oracle uses CrossSpawn. The targeted TypeScript compile of the four production transport sources passed.

The registered Puzzle guest I/O then stopped at the resident graph’s Unix listener with reference `027db973`. A direct Node server under the same capacity-managed sandbox also returned `listen EPERM` on a short Unix socket path in the same scratch directory. The post-transport-fix MCP retry also timed out at 300 seconds. The genuine build-model receipt and native guest I/O scenario remain blocked by that listener.

The [JCO editor lifecycle probe](guest-editor-probe.ts) opens the actual guest through the production bridge using a finite kernel-issued Original. The frozen actor’s opening trapped with out-of-bounds memory access. The [stripped Wasm stack probe](guest-wasm-stack.py) found a 1,048,576-byte starting shadow stack and unbounded declared memory. The failing opcode is an `i64.store` to a stack-derived address in function 337445 at core byte offset `0x9c6260f`. The logged active caller stack frames total 1,218,208 bytes. The fallback environment’s `RUSTFLAGS` had replaced the target-specific `-zstack-size=8388608` and `--max-memory=536870912` settings. The warm fifth invocation was stopped once this was established so the next invocation can forward those flags only to the final guest crate, retaining the compiled dependencies. The two-job restart could not get its managed reservation under host pressure. The seventh invocation was admitted with one Cargo job and the same linker flags. The frozen binary remains available through its preserved ticket hardlink.

The seventh invocation reached 644 units and compiled the Puzzle 2D, 3D and 5D libraries. Rust received SIGTERM during code generation for the hub library at 02:55 CET, before final component linking. The host reported roughly 3.1 GiB available shortly before termination and roughly 9.1 GiB immediately afterwards. A new warm run was admitted with a 6,500 MB reservation and 64 code generation units for the hub library to lower the peak per unit. It applies the two authored final Wasm linker arguments. The [automated JCO verification](guest-run-current.sh) watches this run for a fresh component.

The [archive consistency probe](guest-check-archives.py) retained already-built Rust compiler inputs from the last failed invocation and asked rustc to check the hub’s metadata without code generation. Rust refused with E0460 because the kernel archive expected an older `semio_framework_value` identity. The warm Cargo run is rebuilding the affected dependency closure so the linker receives matching libraries.

The ninth invocation completed 665 Rust units, including the large PDF model and the Wasm metadata for the current board-fill transition. At 04:32 CET it met a live shared-worktree change in Flow host session. The caller used the new `RetirementQueue::admit_owned_slot_demand` method, while Cargo had already compiled the older queue before that method arrived. Rust reported E0599. The tenth invocation retries the warm Cargo graph with the same memory reservation, codegen units and linker arguments. The JCO watcher now follows that invocation.

With about 20 GiB free on the repository filesystem, the registered Puzzle guest I/O and Puzzle 3D React prototype activation were retried through the ordinary launcher. Both authentically served the source capture and then stopped at the graph’s Unix socket listener with reference `2e71dfd8`. That confirms the listener failure independently of the earlier disk-space gate. Neither invocation produced a model receipt.

The [frozen Cargo relink probe](guest-relink-frozen.py) retained 2,632 compiler artifacts from 1,342 Cargo units rooted at the old successful component fingerprint. One test-fixture fingerprint had been cleared by the live Cargo invalidation, but its original metadata and library files still predated the frozen link. The old kernel expected Rust crate hash `e87239ccb44e84b701563395eb192bb3`, and the only surviving binary at that metadata identity has hash `2445775826c69d43cb3ea1a4f2805e68`. The repository and ticket cache search found no second copy of the historical binary. No replacement archive was substituted.

The smaller frozen stack produced the earlier trap on the same 2D opening.
