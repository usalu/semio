# 3D Mounted Mutation Latency

The native mutation law uses a 64-item host grant and an eight-turn publication ceiling. The baseline used 26 publication turns for translate and 28 for delete on both the one-object Concrete Forest and the 180-object Nakagin. Translate consumed 688 Store units in each case. The worker polls are counted separately by the law.

The original width-64 mounted trace separated the three acknowledgement pages from their preparation and retirement. The 264-byte UI page alone spent eight turns encoding and another turn acknowledging. The bounded writer now measures a small immutable wire view and writes it directly into the existing original page backing under the same physical and Work grants. It uses the canonical JSON encoder and preserves the admitted byte prefix on framing refusal. The existing cursor continues to frame pages under tighter grants and larger sources. The UI completion witness receives the existing scope after the host has acknowledged the page.

`compact_ui_page_writes_the_committed_frame_as_one_paid_item` passed in the matched native graph. It uses original caller and decoder custody, compares the exact bytes to a language-neutral page admission vector, independently parses them with `serde_json`, and settles the result page and its decoder.

The unchanged registered law ran against the matched canonical 03:23 native graph in 468.10 seconds. Concrete Forest and Nakagin both used 14 publication turns for translate. Delete used 17 and 16 respectively. Both translation workloads reported exactly 75 Store units. The native law still fails its eight-turn ceiling.

In the small translation trace, 19 worker turns were excluded from the 33 total. The 14 publication turns comprised two latest-wins turns, three turns through the Artifact result, one Artifact acknowledgement and Store close turn, two turns to present UI and Terminal results, and six retirement turns. A rebuild with compact view retirement reduced the late close receipt from 41 to 17 items and retained the 14-turn total. The two full 64-item retirement turns occurred before the view close. The mounted operation still retires an unused segmented-output backing through the generic cursor for nested option vectors.

The native test builds its view from the shared JSON vector, round-trips through `serde_json`, and uses the original caller and allocator to check exact released bytes. A second live alias or a release grant one byte short retains the view. The production branch uses the existing generic cursor when the bounded plain view or its complete grant is unavailable.

The mounted fast close applies only to a uniquely held drained queue with a bounded table and enough physical and Work stock. Live chunks and wider tables retain their existing retirement cursor.
