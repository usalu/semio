# Signed Browser Actor Routing

The renderer admits signed actions for the exact current primary or spawned app and role, with the document, Space, shell instance, client, verified surface, and activation generation bound to the live actor. The action mailbox runs under the session work ledger and releases its execution lease before applying host effects. History applies to the originating program. Captured publication ownership is checked again before applying the decoded host effects and painting the focused owner.

Studio attaches its Workflow before sending its app registrations to the actor. Registrations use individually bounded commands. A deep link is acknowledged once the requested Workflow node is focused and the published child has the signed document actor. A command completion alone leaves the route eligible for retry. Actor readiness and panel focus changes trigger the route check again.

File-picker callbacks send the existing ordered import chunks through the same signed owner. The pre-existing original-media ingress needs a signed worker port. Signed staging and the ordinary archive transfer path also remain separate from the import-action callback. The segmented-download owner is tracking file export transfer.
