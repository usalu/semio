# GIS browser staging recovery

The scoped prototype run linked and staged a 138,549,789-byte GIS component. The run’s first failure was the missing native transpiler reported under the browser release tools path. Describe then lost Original process admission because the driver aborted. The surviving run directory contains the linked WASM and its artifact ownership stamp. It has no described component model or semantic component receipt.

The transpiler declares the owned `@semio-tech/os-plugin-native-transpile-rs:build` target. Its script receives the repository executor’s Original invocation and publishes the binary atomically under the selected browser build mode. The previously validated explicit invocation with the saved release owner uses the same mode and publication. Calling the receiving script path as an independent command does not establish that parent.

From the checkout root, the supported ordinary target is `SEMIO_BUILD_MODE=release repo --lang=en run @semio-tech/os-plugin-native-transpile-rs:build --output=stream`. The repository owner also started the previously validated saved envelope launcher while the full graph was unavailable.

The standard scoped Dev restart can use the published native binary by setting its documented `SEMIO_NATIVE_TRANSPILE_BIN` to `.cache/b/p/m/browser/release/tools/native-transpile/darwin/semio-native-transpile`. The tool selector validates the executable and the materializer hashes the actual binary in its stage cache key. The current graph-free Dev owner ensures its native tool before compilation. The failed prototype pass reported the release fallback and the older direct-script hint, while the currently authored selector accepts the deliverable profile and the original tool override.

The component driver opens the same warm lane. It accepts a Cargo `compiler-artifact` announcement for the selected linked WASM even when Cargo marks the unit fresh. It creates a new staged capture from that actual compiler artifact, verifies the current source and provenance, describes it, and publishes the browser module. The failed run never reached the sealed compilation capture lifecycle and the Dev entry did not request external retention. No registered stage-only entry accepts its raw failed-run WASM as an already described GIS module.

No duplicate build was started during this diagnosis. The deferred History index and Window publication changes were left untouched.
