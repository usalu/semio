This is a source-derived acceptance plan, not a verified browser journey. Start at `http://127.0.0.1:6070/` after the standard `s react prototype` launcher reports readiness. React is pinned to the `s` variant: `?plugin=gis3d` does not switch this server into Terrain. A standalone `gis3d` preview on 6083 is useful component evidence, but does not establish navigation from the s landing shell.

The registered GIS component descriptor contains a Terrain-dialect `demo` example labelled Demo. Once the Terrain editor is focused, the shell's example picker is the combobox `#playground\\.navbar\\.fixture` (accessible name Example in English); choose its Demo option. Its options are filtered by the focused app dialect and selection dispatches `setActiveExample`. This mutates the current artifact: use a newly created disposable local document, and verify persistence destination first. Assert visible Terrain content and inspect the authored grid, pins, route and region, then test an edit and Undo/Redo. The picker is hidden for the landing app and may be unavailable in a viewer, so select the example in the editor first.

Acceptance requires actual successful execution and evidence of Space-to-GIS activation, the registered editor and viewer identities, shared document identity, and example content. Treat missing catalogue choice, local workspace route, role control, picker, or activation as a blocker to investigate. No executable helper is supplied because the first navigation and isolation controls have not been observed.
