## Proposed first bounded slice

Use rectangular `width` and `height` each 2–65, with exactly width×height south-to-north rows of signed i32 **millimetres**, and existing WGS84 sample-centre bounds. The range is approximately −2,147,483.648 to +2,147,483.647 m; parse decimal metres with an explicit exact 1 mm policy (reject excess precision rather than silently round), checked i64 intermediate math, and finite bounds. Distinguish NODATA explicitly: this first slice refuses it on input, as today, rather than inventing values; holes require a separate validity mask and mesh semantics. Preserve rectangular dimensions and all samples within the bound; reject larger inputs visibly, never silently downsample. This does not solve large-area terrain tiling.

At 65×65 the raw samples are 4,225×4 = **16,900 bytes**, versus 1,089×2 = 2,178 today, excluding row/vector overhead. Source replacement plus its retained inverse can contain at least 33,800 sample bytes before diff, mutation encoding, allocator and simultaneous old/new snapshots; charge actual ownership/copies, not just raw bytes. Current normalized SQLite projection becomes **4,226 elevation rows** (one owner plus samples), versus 1,090; the existing 64-byte-per-sample proof alone becomes **270,400 bytes**, excluding other rows and database overhead. Worst signed i32 decimal sample text including a separator is at most 12 bytes each, or **50,700 bytes** plus row/header/bounds structure; this is not a proof that the current file-picker or scene payload limits admit it. Mesh has 4,225 vertices and 24,576 u32 indices; positions/normals/UVs plus indices are **233,504 bytes** in raw typed arrays, excluding temporary height, JSON, allocation, upload copies, and overlay data. Decimal mesh JSON may exceed 1 MiB; measure and enforce a conservative bound or stream it, rather than assuming `MAX_BYTES` is sufficient. A ray scan becomes 8,192 triangles. All counts use checked multiplication, maximum totals, controlled resumable work and cancellation.

The smallest complete vertical slice changes schema and canonical Store/Pack/SQL first, then import/export, typed edit actions and diffs, both shared rendering hosts, and registered Terrain editor/viewer descriptors in the same change; it includes rectangular 3×2 fractional fixtures, 65×65 limit/refusal, cross-codec round trips, independent raster oracle, exact undo/redo, mesh/pick/overlay agreement, and mounted browser/native host tests. Maintain the old 33×33 demo as authored data converted to millimetres, not a runtime legacy path. Do not claim arbitrary-resolution GIS support or UI readiness until the budgets, full screen and workflow lanes are measured.

The proposed [rectangular fractional fixture](terrain-fractional-grid.json) covers a 4 × 3 Esri grid with signed decimal elevations and expected southern-first millimetre rows. The independent GDAL AAIGrid reader through Rasterio verified every sample, all four WGS84 sample-centre bounds and the shape. The first-party codec still uses the current 33 × 33 grid. The fixture is ready for its replacement contract.

The ticket now has paired storage and renderer patches, an exact-decimal Esri codec patch, and a rectangular scene export, camera and Terrain Data patch. The storage and renderer designs share `rowsMillimetres` with dimensions derived from the row shape. The editor's numeric commands, bounded stroke continuation, and picker and export capacity still need integration before the schema can move in the live tree.

The storage patch was rebased over the new History labels, typed native receiver and schema-driven History tests. The proposed Esri reader parses each grid row independently, and the staged retained command grants each row separately before publishing one Replace Elevation Source mutation. Its picker cap is 64 KiB and the shared browser transport now preserves the unsigned chunk envelope. The staged 65 × 65 exchange still needs native compilation, an exact file round trip across multiple picker pages, cancellation between pages, segmented export and registered editor acceptance.

## Integrated rectangular source and brush precision

The rectangular-grid change is applied to 75 live source and fixture paths. Terrain now stores southern-first rows of exact signed millimetres, derives width and height from the authored rows, validates WGS84 bounds, and admits all 2–65 sample dimensions in the shared schema. The JSON, GraphQL and Protobuf elevation fields agree on millimetre units. The existing window setting stores the brush step as an integer number of millimetres while the standard Configure Terrain Brush action presents metres. Both World3d hosts receive a fractional height step through the existing typed interaction metadata.

The live first-party source probe passed exact 4×3 and 65×65 Esri input, signed-limit output, brush and smoothing arithmetic and overflow refusal. Three.js matched the live first-party mesh, dimensions, ray pick and overlay draping. Its 65×65 buffers measured 233,504 bytes. The native and browser brush decoders independently agreed with the neutral cases and the JSON Schema oracle, including a signed 31 mm step. The raster wire witness executed GraphQL and decoded Protobuf alongside the exact JSON values.

The current GIS Dev publication still precedes this source cut. The mounted browser verifiers cover the signed maximum-grid picker and segmented download and the new fractional Configure Terrain Brush action. A replacement GIS publication is required before those verifiers can establish the new end-to-end behavior. NoData imports still need explicit validity and mesh-hole semantics.
