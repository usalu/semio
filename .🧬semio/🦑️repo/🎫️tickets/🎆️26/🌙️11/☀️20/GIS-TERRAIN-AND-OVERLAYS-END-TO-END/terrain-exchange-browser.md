# Terrain File Exchange Browser Acceptance

Run [verify-terrain-exchange-browser.mjs](./verify-terrain-exchange-browser.mjs) from the workspace with `repo tools exec node -- <path-to-script>`. The script opens the standard GIS Terrain Demo at `http://127.0.0.1:6083/?example=demo` in headless Chrome via the repository’s Playwright dependency. An optional URL argument selects a different local Dev port.

The check opens the Terrain window’s Actions pane, clicks Import Elevation Grid, and selects the shared WGS84 ASCII Grid with Playwright’s file chooser. It checks that the chooser is configured for a single `.asc` file and the import adds one history entry. It then clicks Export Elevation Grid and reads the resulting browser download. The existing fixture specifies the expected 33 × 33 dimensions, centre-based bounds, signed metre checkpoints and two checksums over all 1,089 samples. The test undoes the import, redoes it, checks that the second browser download contains identical bytes, and leaves the import undone. The test deletes its own downloads.

The Terrain editor declares both labels and their public action IDs through the app builder. The window Actions pane combines the app and window action rosters and renders zero-argument actions as tree rows with DOM IDs `action.importElevationGrid` and `action.exportElevationGrid`. The enclosing `window-engagement-overlay` owns the Actions toggle and fold state. The catalog search shortcut is for command definitions. ## Verification

Node syntax checking passed, and both neutral fixture files resolved from the script. The download validator accepted an independently calculated raster from the fixture’s planar corner elevations and rejected a changed interior sample. Dev port 6083 refused connections during this check. The live Actions pane, picker, download and history sequence remain unverified.

The combined check also raises the imported terrain with one viewport click. It reads the resulting download and verifies that every sample follows the circular footprint at the tool’s declared radius and step. Undo must export the original imported bytes, and Redo must export the sculpted bytes. A signed example with a known nine-sample footprint passed the independent Node check. A changed sample outside the footprint was rejected.

After restoring the Liège terrain, the same browser check opens Import GeoJSON Overlays. The neutral survey fixture exercises a point with altitude, a line, a polygon with a hole, nested properties and the numeric feature ID `9007199254740993`. The verifier waits for the survey label, compares the downloaded FeatureCollection with the original, and checks the raw numeric token independently of JavaScript number parsing. Undo restores the Liège overlays, and Redo must download identical survey bytes. Node resolved the original file and distinguished both adjacent ID values. The live browser sequence is queued.
