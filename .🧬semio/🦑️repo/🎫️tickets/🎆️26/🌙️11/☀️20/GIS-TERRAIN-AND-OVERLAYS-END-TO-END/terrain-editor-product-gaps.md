# Terrain Editor Product Gaps

This source audit identifies two limits of the registered Terrain editor. Neither is a live-session verification.

1. **Terrain brush strokes are click-only.** The registered editor publishes Raise, Lower, and Smooth brush utilities and dispatches `editElevation` with a single row and column. The React terrain mesh invokes the edit on `onClick`; dragging does not create a continuous editable path. This makes broad hand sculpting require repeated clicks. Add a bounded, cancellable stroke gesture to the shared terrain interaction contract, sample the actual picked surface at a spacing tied to brush radius, and submit one typed artifact mutation with an ordered stroke and sparse reversible height diff. Preview remains transient; Store commits one stroke on release, with cancellation discarding it. Implement equivalent pointer capture and sampling for React and native, and test path interpolation, cancellation, and exact undo/redo on the same neutral fixtures. 2. **The authored elevation grid has fixed resolution and whole-metre precision.** The elevation schema requires exactly 33 rows and 33 columns and whole-metre samples; native validation enforces those dimensions and stores `i16` heights. The existing import therefore cannot preserve arbitrary raster detail, and small vertical edits cannot be represented. Design a bounded rectangular grid with explicit dimensions, georeferencing and fixed-point vertical precision, or bounded addressable tiles for larger sources. Make import and edits publish typed replacement or sparse tile/sample mutations with reversible diffs, preserve the source's declared resolution and NoData semantics, and provide bounded progress and cancellation. Extend the scene, sampling, codecs, and export together; validate asymmetric, fractional and large-grid fixtures against an independent GIS implementation.
