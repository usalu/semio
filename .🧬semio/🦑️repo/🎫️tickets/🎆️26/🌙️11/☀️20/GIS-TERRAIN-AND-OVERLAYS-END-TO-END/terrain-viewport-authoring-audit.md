# Terrain Viewport Authoring Audit

This audit covers the registered GIS Terrain editor and the shared React and native rendering paths. The findings come from the component descriptor and implementation.

- **Add Position** and **Move Position** accept an overlay ID and WGS84 coordinates in their action forms. Add can also take a label and an elevation. **Edit Route or Region** takes an ID, route or region, replace or append, and a JSON list of coordinate pairs. The published viewport utilities are Select, Raise Terrain, Lower Terrain and Smooth Terrain. Overlay marks and paths are rendered and labelled, with name hover and a screen-reader feature list in React. None of the overlay mutations has a viewport gesture binding. - The shared `TerrainSessionCore::pick_elevation_grid` intersects the rendered triangles and returns WGS84 coordinates, a world hit and the nearest sample. It respects holes in the elevation grid. The React and native elevation tool adapters currently retain only the sample indices. React already captures and cancels a primary-pointer brush gesture and dispatches one typed action on release. The native World3d authority owns the corresponding queued intent, terrain revision and utility generation. Both hosts have stable overlay IDs in projected tile markers. - The Terrain Data panel supplies grid dimensions, bounds, minimum and maximum elevation, mean, missing sample count where applicable, and overlay counts and IDs. ## Scoped Implementation

Add direct **Move Position** for a pin on an embedded grid. The editor's terrain window projects an opt-in move utility. Pressing a rendered pin claims its existing feature ID. A valid release sends exactly one existing `moveOverlayPosition` invocation with that ID and the ray hit's continuous `longitude` and `latitude`. Escape, capture loss, utility replacement, a missing-data hole, or an off-grid release clears the gesture without publishing a mutation. The guest's existing typed handler and history own the overlay update and inverse.

- Publish the action capability in [Terrain editor window](../../../../../../../✏️s/🔌️plugins/🌍️gis/🗿️artifacts/🏔️gisterrain/🏅️standards/🔖️1/🪆️subsets/✳️any/✏️editor/🎭️modes/👁️view/🪟️windows/🏔️terrain/🦀️.rs). - Use the marker ID and pointer capture in [React overlays](../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗺️WorldTerrainLayer/🗺️overlays/🟦️.tsx) and [React terrain pointer handling](../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/📺️renderer/🧑‍🎨engine/🧱️elements/🗺️WorldTerrainLayer/🟦️.tsx). Keep only the pending marker ID and pointer generation in the gesture owner.
