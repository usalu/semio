# Canonical Rectangular Elevation Storage

`terrain-rectangular-storage.patch` prepares the canonical model, native DSL and Pack source, TypeScript parser, normalized SQLite codecs, authored data and verification fixtures. It preserves WGS84 sample-centre bounds and geographic sample order. `rowsMillimetres` is the only JSON row field. Rust stores `rows_millimetres: Vec<Vec<i32>>` and exposes checked `dimensions()` in column/row order. Each axis admits 2–65 samples. The Draft 7 schema restricts all rows to one common width without validator extensions. First-party Rust and TypeScript validate ordered geographic bounds and exact shape.

The Pack and DSL record puts millimetre rows before bounds. Both signed integer heights share the same native scalar type, so merely widening the Rust integer would allow a former positional Pack source to read metre values as millimetres. The new record order makes the former shape fail its field type. The Rust test explicitly constructs that former shape and checks refusal. The existing replacement mutation and inverse preserve exact signed heights, bounds, dimensions, and absent-source semantics. Canonical tree child 0 is the sample matrix and child 1 is bounds. JSON property names remain independent of storage field ordinals.

SQLite keeps one source owner and one dense row per sample. The source stores only the column count needed to reconstruct the flattened rows. The reconstruction verifies dense ordinals, a supported number of complete rows, and the signed 32-bit sample interval before exposing the source. At the maximum, document, parameters, source and 4,225 samples require exactly 4,228 normalized rows. The existing per-sample native estimate charges 270,400 bytes, in addition to its base and source allowance. The copied demo keeps its 33×33 geometry with each originally authored whole metre converted exactly to 1,000 millimetres.

The 4×3 author fixture agrees with the managed offline Rasterio/GDAL AAIGrid reader on all 12 signed samples, orientation and all four bounds. The Bun suite ran the patched first-party TypeScript parser and normalized SQLite projection against Ajv and Bun SQLite from the ticket’s temporary overlay. It passed three tests and 31 assertions, including round-trip at the exact 4,228-row ceiling, a truncated normalized source, signed extrema, a former row-field refusal and ragged/oversized input validation. The read-only patch applicability check passed. Native Rust, registered media and end-to-end terrain rendering have yet to be built with these edits.

Integration points owned by the editor and renderer changes:

- The shared `TerrainElevationGrid` and scene lane must agree on `rowsMillimetres`. The `default_terrain_document` storage hunk is here. The camera function in the same file must select the centre with both actual dimensions and convert that sample from millimetres to metres.
- Use actual column and row counts in create, brush, grade, contours, panel summaries and media. Turn terrain metre inputs into checked millimetres once at ingress and use i64 intermediates. Terrain contours, height labels, mesh coordinates and camera elevation need metres at their output boundaries. Mounted scene assertions use the `rowsMillimetres` key.
- The ASCII codec must preserve the incoming rectangle and decimal millimetres. It should refuse larger and unrepresentable inputs explicitly. Its file statement and tests belong with registered import/download. Mesh media ownership needs the corresponding larger physical byte budget.
- The rectangular model amplifies the brush work bound. A conservative 64 × 65 × 65 × ten sample/neighbor work quote is 2,704,000 units, above the standard 2,000,000-unit Interactive turn. The stroke package needs bounded continuation across turns or a lower exact quote backed by a bounded spatial algorithm before enabling maximum-size strokes.
- Rebuild the GIS component and regenerate its semantic descriptor through the owned emitter after applying the storage, editor and renderer changes together.

After the combined changes land, run the focused `semio-s-artifact-gis-gisterrain-operations` tests for `authored_elevation_operation_and_snapshot_round_trip`, `terrain_validation` and `sqlite_snapshot_terrain`. Keep the renderer and editor work paired with the storage patch because the new Rust fields and scene data shape are intentionally exact. Production files remained untouched during preparation.
