# Terrain utility publication in the browser

The real s GIS Terrain editor mounted its authored Liège raster and four GIS overlay labels. The Utilities tray uses the browser shell's existing host register. The Raise Terrain press set that register and forwarded a registered action to the GIS component. The component acknowledged the press with a dirty scope of `none`. The host's leftover view supplied the active utility ID to World3d while the scene body retained its earlier data.

The shell now requests a partial guest body refresh when the utility register changes, even when the guest returns no effect. It replaces the live body stores in the same refresh. The browser test covers the actual button, the guest's typed `editElevation` binding, the terrain click and original Store history. The neutral scope law covers the action with an empty returned effect list.

Against the currently published component, the new refresh reaches the guest and traps in WebAssembly. The direct host action now surfaces dispatch or projection failures through its existing refusal path. The hosted editor can display the demo. The next browser acceptance needs the updated GIS component and a passing utility refresh, followed by the brush mutation and its inverse.
