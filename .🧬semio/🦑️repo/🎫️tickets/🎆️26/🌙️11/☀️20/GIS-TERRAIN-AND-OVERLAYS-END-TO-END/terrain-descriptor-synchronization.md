# GIS Terrain Descriptor Synchronization

The GIS component's authored JSON and canonical Pack now describe the current Terrain editor. The Liège demo retains every source sample and its original WGS84 extent, with elevation values expressed in signed millimetres. The editor advertises independent 2–65 column and row counts, millimetre precision for initial height, grading height, edits and the brush elevation step, plus the hidden bounded brush stroke argument. Fill Missing Samples appears in the Edit Elevation operation picker. Move Position appears in the editor utility list and the Terrain window.

The ASCII import action advertises the source's 64 KiB limit, dimensions and exact millimetre sample diagnostics. The removed NoData rejection matches the importer that now retains missing samples. The demo asset has no missing samples and its embedded DSL carries no missing-sample mask.

The repository catalog verifier decoded the JSON and Pack as equivalent semantic descriptors and re-encoded the Pack to its exact on-disk bytes. The Pack SHA-256 is `7a7584bed2404203a5901d0184c7f017099054cfd36791944a67cbec5b421f2c`. The ticket's Node acceptance verified the registered roles, actions, ports and all 1,089 Liège samples. SQLite JSON1 independently checked the numeric arguments, Fill Missing Samples, editor/Viewer/window utility membership and absence of the obsolete NoData rejection. The Git whitespace check passed.

The ordinary `repo run workspace:components -- describe gis` command uses the component driver in write mode and can settle drift in the authored pair after materializing the selected profile and facet. Regular shipped verification uses verify mode and rejects a difference. The checked pair was synchronized directly from the Rust declarations and elevation asset with the repository Pack codec. A fresh GIS component `describe()` result, browser Wasm/module, receipt and trusted catalog publication still need to be produced and verified by the standard component and browser staging owners.
