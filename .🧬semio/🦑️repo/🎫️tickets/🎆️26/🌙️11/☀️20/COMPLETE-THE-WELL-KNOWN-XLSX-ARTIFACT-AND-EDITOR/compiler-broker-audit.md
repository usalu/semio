# Compiler broker failure audit

All three failed managed compilation logs show the same preceding protocol rejection: `[admission] Invalid RssReportV1: /chargedBytes is not allowed`. The native original records it at line 44356, Office at 44565, and parity repeatedly from line 8063. The later `broker report failed: Broken pipe` occurs when each wrapper tries to send its final completion after rustc exits; the wrapper exits 1, so these messages do not themselves establish a Rust source diagnostic or compiler failure.

The scheduler wrapper in `🏃️process/📦️artifacts/🏗️native-build/🎟️admission/🦀️.rs` sends both `bytes` and `chargedBytes`. Its sampler ignores a failed RSS send, but its final done send propagates failure. The TypeScript admission broker validates each message against its loaded schema and destroys the socket on validation failure. Each Cargo launcher creates its own admission broker and closes it after execution, so a shared kill or lease rotation is not needed to explain the three failures; no such cause is established by these logs.

The current admission schema requires and allows `chargedBytes`, matching current Rust and TypeScript code; a schema test checks that shape. The failed broker instances necessarily used a schema that rejected it, consistent with long-lived source or sealed-implementation skew. A fresh documented `repo cargo` or existing managed target retry with matching current broker, schema and scheduler is the supported recovery, preserving existing stores. Confirm the implementation/seal chosen on retry and check that no new admission rejection occurs. Prior work documented `SEMIO_REPO_SEAL=live` as the current implementation choice when explicit promotion still selects an older seal. A cache reset, direct Cargo invocation, and disruption of other jobs are not supported by this evidence. The restarted builds remain the behavioral verification; no additional build was launched for this audit.
