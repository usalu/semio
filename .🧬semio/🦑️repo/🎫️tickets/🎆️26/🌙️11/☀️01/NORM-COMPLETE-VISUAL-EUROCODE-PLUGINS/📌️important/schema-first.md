# Schema-first twins: edit the JSON Schema, run the generator

The JSON Schema (`🔣️.json`) of a schema module is the only source of its types. The TypeScript wire twin (`🟦️.ts`: interfaces and `normWire*` readers), the protobuf (`🛰️.proto`), the GraphQL (`🔗️.graphql`) and the Rust structs (`🦀️.rs`: the payload struct of every mutation leaf and every record struct the schema annotates with `x-semio-rust.derive`: artifact, snapshot, diff and shared records) are generated from it. The output of the generator is canonical (strict gate: committed twin == generated twin, byte for byte). Never edit those structs or twins by hand; the impls, enums, macros and mounts around the generated structs of a `🦀️.rs` stay hand-written.

## The rule

1. Edit `🔣️.json` (or call a field-adder tool, which writes the JSON and calls the generator for you).
2. Run `repo ./📜️script.ts schema twins generate [--under <path>] [--only typescript,rust,protobuf,graphql]`.
3. `repo ./📜️script.ts schema twins check --strict` (CI, and the `schema sync` bun test) fails when a committed twin differs from the generated one in any byte. Without `--strict` only content differences fail (layout-only differences are reported as `style`); `--explain` prints the first differing statement; `--out <absolute dir>` writes into a scratch tree instead of the sources.
4. `repo ./📜️script.ts schema twins annotate` is the one-time harvest that moves a hand-written Rust struct into the schema: it writes the `x-semio-rust` / `x-semio-dsl` / `x-semio-state` annotations of every leaf payload and every record struct that a schema can reproduce exactly (a struct it cannot reproduce stays hand-written and untouched). Afterwards the struct is generated.
5. A new record: add the `$defs` record with its `x-semio-rust` annotations (copy `derive`, `attributes`, `artifactSchema` from a sibling record) to the JSON and run `generate`; a struct the file does not declare yet is inserted after the struct of the preceding record.

The engine is domain neutral (`🧰️framework/…/🎛️commands/🧬️schema/🧬️twin-projection/`). A family declares its dialect beside its schemas in `🧬️twin-dialect/🔣️.json` (norm: `✏️s/🔌️plugins/📕️norm/🧬️twin-dialect/🔣️.json`; `"projection": "off"` opts a family out, as done for din/iso/vdi). protobuf and GraphQL extend the framework renderers of `schema parsers` (`🪞️parser-projection/📐️type-render`). A twin with the `🤖️ Generated by` banner belongs to the `surface-schema` projection and is never touched.

## Extension keywords (all optional, all in the JSON)

| Keyword | Where | Meaning |
| --- | --- | --- |
| `x-semio-state` | property | state lane, rendered as `@state <lane>` (TS doc, proto comment) and `#[state(..)]` |
| `x-semio-rust` | record | `doc` (lines of the `///` docstring), `derive` (list; presence marks the record as generated into Rust), `attributes` (raw attribute lines before the `#[dsl]` line), `artifactSchema` (`#[artifact_schema(id = ..)]`), `name` (Rust name where it is not the key) |
| `x-semio-dsl` | record, property | `#[dsl(..)]`: record `keyword` / `id` / `layout`; property `unit` (string), `table` / `statements` / `block` (true) |
| `x-semio-rust` | property | `doc`, `attributes` (raw lines: serde/value/child/derived), `type` (Rust type text without the `Option` the schema's optionality adds), `name` |
| `x-semio-twin.emoji` / `.summary` | module root | docstring emoji and sentence of the TS twin header (default: descriptor emoji for leaves, facet table of the dialect otherwise) |
| `x-semio-twin.emoji` | property | docstring emoji of the TS field comment |
| `x-semio-twin.name` | `$defs` record | TypeScript name of the record |
| `x-semio-formats` | `$defs` record | languages that keep the record; a record without `🟦️typescript` is prefixed by the family (`En1990PermanentAction`) |

## Types the field-adder tools support

`🧰️scripts/field-adder/schema_twins.py` writes JSON and calls the generator: `f64 f32 u8 u16 u32 u64 usize i32 i64 String bool`, `{"enum": [...]}`, `{"ref": "Name"}`, `{"rows": "Row", "fields": {...}}` (id-keyed rows, record created) and `{"nullable": spec}`. `field_adder.py` calls it for the schema/TS/proto/GraphQL layers; model structs, SQLite and fixtures stay profile code.

## Reading a report

`identical` = byte equal, `style` = equal after dropping declaration/import order, unused imports, comments, whitespace and redundant parentheses, `drift` = content differs (the JSON is newer than the twin, or the twin was edited by hand). The bun test ratchets `drift` per language against `🧪️tests/🧬️schema-sync/🔣️drift-baseline.json`; the end state is zero, reached by running `generate` and committing.

## Ownership boundaries

A module whose twins carry the `🤖️ Generated by` banner or the `//#region 🚪️Parsers` region, and every module in a `🎚️config` or `👥️presence` lane, belongs to the `surface-schema` / `schema parsers` projections and is never touched. din/iso/vdi opt out in their dialect. A family can point its TypeScript twins at a relative contract file with `typescript.contractFile` in its dialect (the shared compliance schemas do).

## protobuf and GraphQL conventions of the generator

String enums become `enum` declarations (proto members `ENUM_NAME_MEMBER`, zero based); integers with a minimum of 0 are `uint32` (maximum within 32 bits) or `uint64`; records and lists of records are typed (no `string` blob); a mutation aggregate is a `oneof kind` message (GraphQL `union`) followed by the messages of its leaf payloads; properties whose names are no identifier (`$schema`) are not projected into protobuf/GraphQL.

## JSON layout (canonical, generated)

The JSON Schema document of a module is embedded verbatim in its crates (`FacetLeaves.json_schema`, `include_str!`), so its layout counts against the repo source boundary (262144 bytes, 4000 lines). The layout is therefore a pure function of the document, `serializeSchema` in `twin-projection/🧩️model`: two-space indent while the indented text has at most `SCHEMA_INDENT_LINES` (1500) lines, else compact (one line per top-level key and per definition); a file that already is compact stays compact. `schema twins generate` writes it (facet `json`, `--only json`), `schema twins check --strict` reports any other layout as `style`, and `annotate` uses the same function. Writers (field-adder, new-collection, `schema_twins.edit_schema`, hand edits) may leave any layout: the next `generate` normalises it, so no separate compaction step exists (`h_compact_json.py` is gone). The gate is not relaxed for generated files: the kernel counts `include_str!` inputs before the compiler, so excluding twins from `source-budget` would hide real build failures.

## Running `schema twins` (INFRA v7)

`schema twins check|generate` is a root command of the workspace `📜️script.ts`, not a command of any norm script. Run it from the repository root: `cd /home/deck/semio && nice -n 19 repo ./📜️script.ts schema twins check --strict < /dev/null` (about 1-2 min; `--strict` also fails on layout-only differences; exit 1 lists `[schema twins] drift <file>` lines and per-language counts). The error `Original parent Script process invocation required` from `📦️packages/🟦️typescript/📜️script.ts` (and other package scripts) is expected there: those scripts only register `test` and `wire-twins`, and a script started outside a `repo` invocation envelope refuses to run. Use `repo ./📜️script.ts ...` from the root, or `repo run <project>:<target>` for per-package commands, never `bun script.ts` from the script directory.
