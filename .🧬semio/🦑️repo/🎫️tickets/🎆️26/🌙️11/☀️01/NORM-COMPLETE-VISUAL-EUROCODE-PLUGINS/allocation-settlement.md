# Native allocation settlement investigation

The native decode and encode controls document `charge` as cumulative admission before copying or reserving. Both update the original forwarded ledger and their own `owned_bytes` before `try_reserve_exact`. An allocator failure therefore leaves a historical admitted reservation, even though no buffer was born. Other callers use `charge` for estimates before opaque BTreeMap operations, so simply treating every charge as physical allocation would silently change their semantics. Separate admitted reservations and measured physical receipts are required.

The physical construction recipient records retained objects but does not settle the separate forwarded cumulative allocation authority. Posting an actual allocation after the event must retain both the original buffer and any post refusal. The current `Result<Vec<T>, ValueError>` cannot express that combination. Copies into caller-owned slots already demonstrate an appropriate custody pattern, but they too currently charge before allocation.

`try_reserve_exact` promises at least the requested capacity, not a maximum. The settlement fixture therefore includes an allocation exceeding its quote; its owner and actual capacity remain recorded and the excess requires refusal. A real implementation must post actual capacity, including zero after allocator failure, and must not claim a quoted bound covered excess capacity. A direct exact-layout allocator could enforce an upper bound but needs a proven cross-platform implementation including zero-sized types and overflow.

The existing refusal types preserve independent primary, quote, allocation and receipt causes in different contexts; ownership and paid nested error storage must be preserved when integrating them. Allocation failures, both port refusals, and receiver refusals need independent custody and deterministic injection to test. A concurrent change introduced allocation event interfaces without updating all existing callers. Settlement bookkeeping now advances historical admission by the quoted request after a performed effect while actual capacity remains in the separate post; full caller migration and independent refusal custody remain incomplete.

## Ownership and demand map

1. A native control owns the historical cumulative admission counter and the original forwarded authority; its existing charge must continue to mean reservation or estimate. Decode and encode control, child, observer, construction, work/action, continuation and retirement loans reborrow that authority. Encode additionally holds scoped source authority and its own action/work observers. Both authorities must retain independent quote and post refusals.
2. An allocation demand describes the requested element count, checked byte extent and current receiving slot, not an assumed upper bound on the capacity returned by the allocator. The quote is admission for the requested extent. An implementation may require an explicit proven upper bound if it controls the allocator; ordinary Vec and String do not provide one. Overflow, zero-sized elements, zero demand, cancellation and already-populated slots must be handled before any physical effect.
3. Quote refusal leaves the caller slot and actual receipt unchanged. After authorization, perform one fallible allocation directly into the original caller slot, then post its measured capacity to the same original authority, even if allocation failed and measured capacity is zero. A post exceeding the quote is recorded as actual and independently refused; the owner is still in the slot. Historical reservation and physical ownership are separate ledgers.
4. A typed outcome must retain each owned primary allocation failure, quote refusal, post refusal and receipt refusal independently; a fallible receipt handoff cannot replace or drop any earlier cause. Use the already-owned refusal/storage ports and prepaid nested storage as needed; do not synthesize a receipt or silently retire a buffer on refusal.
5. Empty-slot allocation is the primitive required first: decode allocate_vec/copy_text_into/copy_bytes_into and encode allocate_vec/copy_text/append_bytes currently return or mutate Vec/String, and IO octets plus snapshot encoding allocate separately. Growth of an existing allocation additionally needs before/after capacity and any release/copy progress, because the old allocation may be replaced. Return-by-value conveniences cannot preserve a born buffer when posting fails unless their error owns that exact value.
6. Decode construction/backing and retirement perform separate actual-retained posts today; those must share the same original authority without double charging. Encode observer and action loans forward both scoped and external ports. Native forwarding reaches the host/guest plugin imports, SQLite transfer, and many plugin call sites, so a complete port migration is cross-component and must be coordinated with those owners.

The neutral fixture covers denial, failed allocation with zero actual, successful allocation, post refusal, excess capacity, and simultaneous allocator/post/receipt refusals. The SQLite oracle validates the accounting relations, but it is not an actual allocator-failure test. A Rust baseline test now uses the existing thread-local real allocator refusal and independent physical observer to establish that failed Vec reservation has zero physical birth while original and forwarded historical admission remain charged. A full implementation test must additionally observe the real receiving slot, actual post and all independent causes; the new physical post port does not exist yet.

## Verification

The current admission and physical ownership schema and SQLite settlement oracle passed under normal repository capacity (one test, nine assertions), including distinct causes and cancellation before the allocator effect. Both Rust allocator-failure tests could not run: native encoding has compiler errors during the concurrent allocation event conversion. The encode run additionally encountered concurrent Cargo.toml source extent churn.

The corpus distinguishes an authorized operation canceled before its effect from an allocator failure after the effect began. The former cancels the quote and retains prior admission; the latter posts zero and retains its historical admitted budget. The actual outcome marker must be explicitly set to zero by a failed allocator, rather than inferring that every error performed an allocation.

## Implementation status

The first-party allocation failure contract carries independently owned primary, admission, quote, post, cancellation, receipt and extent causes, with an optional complete original request and separate admission and physical progress. Its Rust schema-driven test and the prior ten-case SQLite/Ajv oracle passed. Retirement of every cause is implemented alongside the existing refusal retirement and its current test is blocked by native construction compiler errors. The vector and text slot implementations and callback phase custody remain under active integration.

Receiving marker reconciliation now preserves a missing or inconsistent physical marker alongside the child outcome. It leaves the original allocation quote pending rather than synthesizing either a cancellation or a post; an owner-supplied compatible marker can subsequently settle it. The associated neutral law and real-owner Rust test were added but have not passed a current native build. A concurrent fixture rewrite temporarily contradicted the agreed admission/physical distinction; the independent law was reconciled without deleting its unrelated cases and still requires its next verification.

## Core allocation follow-up

The event port quotes a requested reservation and reports a physical post or a pre-effect cancellation. The issuer identity must remain resident with the original callback across receipt detachment and rebind. Post records the actual physical extent independently from the historical admitted request. A performed failed allocator reports `Some(0)`; a missing marker remains a cancellation and is never synthesized from a child receipt. The ordinary and original-recipient recovery paths now retain requested admission in both directions. The current forwarded budget-only charge path remains unsupported, and callback ownership is not independently bound by the issuer type. These must be resolved before calling the migration source-ready. Decode production check session 84819 was queued under normal shared capacity at this checkpoint.

The neutral corpus and SQLite law now distinguish admission from physical extent, including a real failed allocator represented by a zero-byte post and a separately retained post refusal. The native encode and decode fault-injection slot tests were aligned to that fixture. All four settlement transition implementations reject replay of an already settled frame; native unwind tests now check this condition. The latest changes await the queued decode compiler gate and have not passed native or neutral successor tests.

A producer marker that differs from the child receipt now leaves the original quote and frame pending for either missing or conflicting markers; it cannot be silently posted. Recovery from an interrupted post now finalizes its already-resolved callback before extracting the retained outcome.

Receiving-frame allocation progress is read-only to callers; resolving an interrupted allocation callback now passes through the same frame and original construction recipient. The admitted-ledger assignments were restored after a concurrent conflicting edit; they require a fresh source read before acceptance. Session 84819 remains in the normal shared capacity queue.

The settled-frame replay invariant also has a language-neutral schema and cases, with SQLite checking settled and otherwise-eligible conditions independently. This oracle is authored but has not been rerun while native compilation remains pending.

Another uncoordinated writer again replaced all four historical-admission assignments with physical-actual accounting after the module contract documentation was added. The assignments were restored; acceptance requires a fresh read because the conflicting writer is not exposed in the active session list.

Both native directions now call a first-party `commit_admission` operation with the original request from their ordinary and recovery settlement paths. Direct effect and real fault-injection tests distinguish requested cumulative admission from posted physical bytes; older budget-only tests still need a genuine admission lifecycle.
