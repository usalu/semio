# NativeReceive Generated Error Path

Current record generator value/✨️derive/🛬️receive/🦀️.rs uses `#native::native_decoding::OriginalReceivingPrimary` in advance_one and advance; enum generator 🔀️enum/🦀️.rs uses the same nested path. The concrete type is defined by value/🛬️decode/🏭️construction/🧾️result/🛬️receiving and reexported by semio-framework-value-native-decoding::native_decoding, then by semio-framework-value-native-owned::native_decoding. The value facade reexports that native_decoding module, so both default native-owned root and explicit facade root resolve the same owned type. The native-owned crate depends on native-decoding; facade depends on native-owned. Adding a reverse native-owned→facade dependency would create a cycle and is unnecessary.

The generator selects explicit `value(native_owned=...)`, otherwise `value(crate=...)`, otherwise `::semio_framework_value_native_owned`. A normal consuming crate using the default needs direct native-owned and value dependencies plus derive; EN1990 model and bridge-fatigue leaf manifests already declare them. Crate-path overrides must expose both native_decoding::owned and nested native_decoding::OriginalReceivingPrimary. The current generator corpus tests default native-owned and explicit facade roots for record and tagged enum; it does not yet include explicit native_owned override.

The type retains primary, quote_refusal, allocation_refusal and physical progress as separate owned values. NativeReceivingBatch retains those fields on child error while accumulating prior progress and work, and the failure has controlled retirement. Repointing a generated type path must not flatten or reconstruct these causes; test actual refusal under original source/recipient and physical observer as well as syntax expansion. No build or runtime pass was claimed.
