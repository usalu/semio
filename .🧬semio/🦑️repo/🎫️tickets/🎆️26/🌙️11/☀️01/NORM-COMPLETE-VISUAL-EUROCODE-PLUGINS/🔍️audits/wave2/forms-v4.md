## 1. Annotation roles (shared forms, `projection-kit/🗂️design-case/🧊️forms/📏️dimensions/🦀️.rs`, new)
- Roles (accepted by every form via `forms::is_aux_role`, which also keeps `aux_roles(form)`): `dim_x` (from the start face along +X), `dim_xe` (from the end face), `dim_y` / `dim_ye` (from the near / far side), `dim_z` (up from the base), `dim_ze` (down from the top face), `dim_angle` (angle from the grain direction, local +X, to the load direction in the vertical plane through the middle of the top face). An optional trailing digit tells several of a kind apart (`dim_x2`).
- Each role whose input is set draws: a `Annotation::Dimension` `ROW:dim-x` (from/to on the body, offset staggered per slot, `Quantity` length; an angle is the chord between the grain ray and the load ray with an angle quantity; binding = the input leaf like the grip), an `Annotation::Label` `ROW:dim-x:label` (input name + value + unit, EN and DE, tone of the case), a marker cube `ROW:dim-x-mark` (linear) or a thin sector solid `ROW:dim-angle-arc` (angular; translucent context parts without utilisation), and a grip `ROW:dim-x`: `ScalarAlong` along the dimension axis for lengths (`Spacing` plan, `stored = value + per_metre * s`), `Angular` about -Y through the sector centre for angles (absolute degrees/radians, limits 0.01 to pi - 0.01 rad). All writes are `change-case-number` of the input leaf; an unset input draws and grips nothing.
- Joint forms (Fastener, Weld, Anchor, Opening) measure on the plates they really draw (`joints::build` half extents and top), the other forms on the declared box (member on its supports).
- Wiring: `build` = `shape` + `dimensions::attach`; `draw_with` appends `dimension_annotations` to `CaseDraw.notes`; exports `dimension_annotations`, `dimension_role`, `dimension_tag`, `input_radians`, `Stem`, `ANGLE_MIN/MAX`, `is_aux_role`.
- The cases scenes of EN 1990/1991/1992/1996/1997 destructured `CaseDraw { entities, points, label, anchor }` (a compile error since the `notes`/`legends` fields exist); they now take `notes, ..` and annotate every note (EN 1995 already did). Legends of those five scenes are still not emitted (no mode grids there).

## 2. Declarations
`🧰️scripts/forms-v4/scan.py --write` declared every number input with a length (Metre, Millimetre) or angle (Degree, Radian) unit that no role used, per entry, in `📐️geometry/🔣️.json`, then `geometry_gen.py` regenerated `🦀️.rs` (`--check` green, 30/97/174/70/40/71 rows). Stem by label: height/depth/thickness/level/cover/elevation/embed -> `dim_z`; width/edge/lateral/offset/eccentric/side/clear -> `dim_y`; other lengths -> `dim_x`; angles -> `dim_angle`. Declared (en1990 11, en1991 41, en1992 179, en1995 45, en1996 33, en1997 91) = 400 inputs: 170 `dim_x`, 105 `dim_z`, 61 `dim_y`, 64 `dim_angle`. The generator learned the roles (regex `dim_(x|xe|y|ye|z|ze|angle)\d*`, angle roles need a Degree/Radian input).
- Not declared on purpose: response and material quantities with a length unit (deflections, displacements, settlements, crack widths and spacing, sag, slip, tolerances, grain sizes: 40 inputs, listed by running `scan.py`), and the EN 1995 inputs that already have an extras grip (T-90 `h_i`/`s_i`, T-94 `s`/`h`, T-95, T-96, T-122 `bar_spacing`) to avoid a second grip on the same input.
- Examples: EN 1995 T-74 `dim_x a3t`, `dim_x2 a3c`, `dim_y a4t`, `dim_y2 a4c`, `dim_angle alpha_deg`; T-70/75/76/80 `dim_angle alpha_deg`.
- The generator geometry assignments are a heuristic of the label; the anchor face (start vs end, near vs far) of a dimension is the default of its stem. A catalogue owner who wants `dim_xe` or `dim_ye` for a specific input changes the role name in the JSON and regenerates.
