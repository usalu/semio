# Member Work Refusal Fold

Current OriginalNativeDecodeSource::receive_observed_work creates a fresh OriginalTurnFailure from a ValueError for grant/progress mismatch, excessive work, observed-work mismatch or receipt posting refusal. Its constructors initialize work_refusal=None; the function may set context_refusal and receipt_refusal but never work_refusal. This is a source-specific invariant, not a guarantee for arbitrary future failure producers. It reports actual max(reported, observed) and physical progress independently.

Member accept currently destructures a Value primary plus Value receiving refusal with `..` and reconstructs OriginalTurnFailure without work_refusal; after the newly added field this needs explicit field preservation. Native receiving failures can contain their own primary, quote_refusal and allocation_refusal, while the outer failure retains receipt_refusal, context_refusal and physical effects. Preserve the entire owning values and message spans; do not flatten or replace any error.

For one independent NativeDecodeControl commit refusal, fold after Member accept: on existing failure use with_work_refusal; on success return the commit error as a primary failure carrying actual effects, while any non-Value source fault already moved to Member fault custody remains retained for retirement. Inserting it as an ordinary receiving refusal before accept misclassifies the work error as a quote refusal. The current shared constructor proves its slot starts empty, but with_work_refusal deliberately returns Err((original_failure, second_error)) for a repeated attachment; a general owner must keep both in independently funded custody and retire them, never unwrap, panic, overwrite or drop the second. Add a real test combining native primary, quote and allocation refusals, receipt/context refusals, commit refusal and actual physical progress, comparing original message pointers and completing funded retirement.
