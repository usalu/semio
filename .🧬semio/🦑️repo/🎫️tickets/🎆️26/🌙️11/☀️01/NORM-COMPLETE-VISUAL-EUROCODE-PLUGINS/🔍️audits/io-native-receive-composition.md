* 🌱️value/🛬️decode/🧳️owned/🌳️value/🦀️.rs:10-46 implements NativeValueSource for DslValue, including indexed record_child and sequence_child. The derived record persists source binding, positions, scan/field indices, matcher, child slots, partial and retirement. Its child binding validates the original projected lease/path; no owned source conversion is necessary.
* The native-owned crate already composes Option<T> and Vec<T> when T: NativeReceive (🌱️value/🛬️decode/🧳️owned/🌳️value/🦀️.rs:107-120,142-162); NativeReceiveSlot persists child receiver backing, child output and retirement (line 54). NativeArrayReceiver uses MaybeUninit, index and live count with controlled partial closure (🌳️value/🔢️array/🦀️.rs:6-7); NativeBoxReceiver retains inner receiver, pending T, pending Box, NativeOwnedStorage and retirement with separately funded backing and close (🔄️map/📦️box/🦀️.rs:6-24). * RetainedCloneProgress and Grant have NativeReceive generated in 🌱️value/🛬️decode/🧳️owned/📦️packages/🦀️rust/🦀️.rs:15-16. The derived enum selector/child cursor is 🌱️value/✨️derive/🛬️receive/🔀️enum/🦀️.rs:31-44; the parent owns the original retained source throughout advance/take/close.

## Missing owner implementations and wire constraints

* No NativeReceive implementations were found for ValueError, ValueRefusalKind, NativeAllocationRefusal, OriginalRetirementFailure, OriginalReceivingPrimary, native encode/decode allocation/effect failures, NativeSnapshotCause/AllocationFailure/Failure, or diagnostic owners. ValueError in 🌱️value/🎟️control/🧬️contract/🦀️.rs:109-121 has Cow<'static, str> and private retained_progress, so a straightforward derive in another crate cannot construct it. NativeAllocationRefusal must receive the owned wire ValueError and produce its Owned variant with a paid move.
* OriginalRetirementFailure has private fields and a recursive Box at 🌱️value/🎟️control/🧬️contract/♻️failure/🦀️.rs:5. Its explicit owned-part constructors and original failure storage pool/birth must govern recursive reconstruction. A derived boxed tree is not evidence of equivalent recipient-owned storage lifecycle.
* 🚪️io/⏱️failure-owner/🦀️.rs:6-30 owns NativeSnapshotCause, NativeSnapshotAllocationFailure, NativeSnapshotFailure and public NativeSnapshotFailureParts, with actual Failure fields private. The wire is custom tagged and has nested private external owners (see current codec); deriving just Parts is insufficient until all child types implement correct wire receivers and retirement. Root construction can transfer Parts through into_failure at a separately paid step.
* ⚠️diagnostic/🦀️.rs:83-85,137-142,202-206,264-271,363-368 and ⚠️diagnostic/📍️span/🦀️.rs:10 own FaultCode, Severity, ExpectedSet, Diagnostic, FaultScope, TextSpan. Existing types do not derive NativeReceive; derive/mapped implementations in diagnostic must preserve actual wire rules, including optional absent/null diagnostic fields and severity string spelling. Diagnostic fields are public; RetireOwned availability and schema defaults still must be checked before composing.
* 🚪️io/🧬️schema/🦀️.rs:80-85 owns IoError and its crate already has RetireOwned at 🧬️schema/♻️retirement/🦀️.rs:9. It can implement/derive NativeReceive only after NativeSnapshotFailure and Diagnostic receiver bounds exist. Existing inherent receive_value is not that trait implementation.

## Crate and orphan boundaries

* NativeReceive is defined in semio-framework-value-native-owned (🌱️value/🛬️decode/🧳️owned/🦀️.rs; package export 📦️packages/🦀️rust/🦀️.rs:14). Rust permits its blanket/foreign-owner implementations there because the trait is local. Existing value_codec! generated RetainedCloneProgress receiver demonstrates that mechanism. Put canonical ValueError/ValueRefusalKind/retirement and native allocation owner receiver implementations in native-owned or an appropriate type-owning crate with legal dependency direction; io-control cannot implement a foreign trait for foreign NativeSnapshotFailure, which is owned by io-failure-owner.
* io-failure-owner already depends on value and native-owned (🚪️io/⏱️failure-owner/📦️packages/🦀️rust/Cargo.toml); implement NativeReceive for its own types there, using constructors/parts and custom cursors where required. io-schema already depends on io-control, native-owned and diagnostic (🚪️io/🧬️schema/📦️packages/🦀️rust/Cargo.toml), so it can implement NativeReceive for local IoError. Diagnostic already depends on value/native-owned (⚠️diagnostic/📦️packages/🦀️rust/Cargo.toml), so it can implement its local types without a new dependency edge. Do not add io dependencies to value: that would invert the actual graph.
* A genuine full composition therefore requires canonical error owner receivers plus diagnostic receivers, then failure-owner receiver and IoError receiver. Reusing Option/Vec/Box is feasible where semantics match, but adding a derive only to IoError or failure parts cannot compile or satisfy recursive retirement birth. Test each output and partial owner under bounded work/copy/capacity and funded close. No builds were run.
