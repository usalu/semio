Raw and post-filter numbers below are therefore not like-for-like with `i18n.md`. Deltas are given where the metric is comparable.

## 🔎 Checked and accepted (no action)

- `Locale::En` in `🪟️visual-windows/♿️accessibility/🗣️screen-reader` (`diagram_nodes`, `is_german`): `Lang` has only `En` and `De`, so the `else` branch is exhaustive, not a default.
- `Locale::En` in `📈️diagrams2d/📊️table-twin` (line 50) is a closure taking EN and DE arguments, and in `🏷️ids-chrome-and-labels` (line 108) it builds the intentional "EN / DE" media port label.
- Match arms `Locale::En =>` across compliance, units, design-case and diagram code are exhaustive matches, not defaults.
- Paired constructs that the detector missed: `if tank { EN } else { EN }` tuples (`en1991/🎬️scene/📈️diagrams` lines 332-333), `name(EN, DE)` in `en1992/🎬️scene/⚓️anchors` (lines 60-71), `names: (EN, DE)` tuples in `en1995` grips and `en1997` handles, `m!(EN, DE)` in `en1998` field-meta, `InputSpec::number(id, EN, DE, ..)` in `en1995` and `en1996` inputs, `FieldSpec::quantity(EN, DE, ..)` rows.
- Standard designations such as `DIN EN 1993-1-8` appear identically in both languages and are not defects.

- Snapshot leaves wrapped in shared `CaseRow` (`cases[].*` in en1990, en1995, en1996, en1997) show as extra meta keys because the scanner does not resolve the shared model; not treated as stale.
- Runtime rendering and the TypeScript UI were not reviewed; the `🟦️.ts` checks were limited to example titles.
