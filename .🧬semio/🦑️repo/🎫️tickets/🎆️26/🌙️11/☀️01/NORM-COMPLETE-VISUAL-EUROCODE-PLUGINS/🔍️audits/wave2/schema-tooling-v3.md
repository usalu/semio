## 1. `add-enum-value`
Spec `{"enumValue": {"token", "variant"?, "label": {en, de}, "after"?}}`, command `add-enum-value <artifact> <Enum> <spec> [--dry-run|--apply]`. Layers: schema documents (every `🔣️.json` below `🧬️schema/` that defines the enum: token in `enum`, label in `x-semio-ui.options`), Rust model variant (plain unit variants; positions behind `after`, default last, so no stored index moves), mechanical `match` arms in the model file and the artifact io tree (an arm of the `after` variant whose body is a mapping of its variant or token is cloned; arms carrying other data are reported), quoted token lists in Rust/TS, SQLite DDL CHECK lists (+ contract), field-meta choice lists (EN + DE), final consumer scan over the whole norm tree: every `match` over `Enum::` without wildcard arm and every variant list is printed as `MANUAL <file>:<line>`; a wildcard arm is never inserted. Twins are regenerated by the apply run. Example (en1993 `SectionKind` + `Tee`): 9 files, 5 MANUAL sites (`scene-members/handles`, `scene-members/kit`, `checks/parts`, `member-vids`; the hand-written sqlite/io arms are done by the tool).
Not covered: enums encoded by index in a binary codec (none found; the tool only appends, the proto numbering is generated), tests/oracle `.py`/`.feature`/JSON token lists (reported by the consumer scan only for Rust).

## 2. Enum leaves
`leaf.field.type = "enum"` with `enum: {name}` (existing: tokens, labels and variant names are adopted from the snapshot schema and the Rust model) or `enum: {name, values}` (new: `$defs` in snapshot and artifact schema, model enum cloned from a donor enum, only `impl` blocks whose arms are the token mapping are cloned). Codec: DDL CHECK column, Rust helper pair in the artifact's dialect (`learn_dialect` now reads all enums of the schema, not only the entity's), `use` list, TS choice const (only when the learned item form uses a const; inline lists are regenerated through `{TOK}`), TS import, admission cell, contract bytes, field-meta const (reused when an existing list equals the tokens), set-field kind (clone of an enum kind). Bugs fixed on the way: helper detection when the field and its helper share a name (`bond_condition`), inline token lists copied from a donor enum (`["a","b","c"]` in en1992 probe), `field_renamer` for single-word fields produced `probe-mode` in Rust (kebab collision).

## 4. Composite-codec entities
Changes in the learned engine (`l_codec.py`): (1) `find_list(tolerant=True)` accepts items between the field cells that only restate a field (`resolved(members,b.memberId)`, bare local such as `member`, shorthand array items such as `actions`, string items in `fields([..])`) and limits the TS `fields([..])` search to its own bracket; (2) column indices of the new cell and of the neighbours come from the DDL (`cols`), with `member_reference` -> `member_id` aliases and suffix matches, so interleaved resolved columns do not shift them; (3) `schema_fields(scalars=True)` skips object/array members and unwraps optional (`oneOf [x, null]`) members, which is what makes beams/slabs (sub-record tables), connections (bolts/welds), members (optional stirrups/punching/prestress/fire/tightness) addressable; (4) set-field kinds for id-less lanes (en1990 `effects` diff lane is `Replace` ops with the full row) and fixtures of id-less rows.
Result `matrix.py --leaf`: see "Matrices" below. Remaining: en1991 `accidentalCases` (array-only entity: its rows are written with `out.insert(table,[..],id)` without a float constant, a new signature would have to be learned).
Found and fixed in sources: en1992 `🟦️.ts` had two broken cells `v.headDiameteraw` and `v.relativeHumidityaw` (anchors and members write cells; compile errors, and the reason the old tool could not align anchors); both repaired by hand (one-token fixes).

## 5. `convert-field-to-collection`
`evolve.py convert-field-to-collection en1994 specs/en1994-studs.json`: runs the add-collection layers for the new top-level `studs[]` (row `{id, beamId, xM, diameterM, heightM, fUPa}`, 4 settable fields -> kinds `insert-stud`, `remove-stud`, `change-stud-x-m|diameter-m|height-m|f-u-pa`, binary tags from the next free numbers; `beamId` is `settable: false` because en1994 has no String donor kind), removes `studs` from `CompositeBeam` in the snapshot and artifact schema, rewrites fixtures (before the mutation layer and once more after it), and lists hand-written leftovers as `MANUAL`.
Fixture rules (spec `convert.rows`): `count = obj['totalCount']`, `id = "{parent[id]}-stud-{i}"`, `xM = obj['spacingM'] * i`, the three dimensions copied. Invariants checked per object (`verify`): row count, dimensions equal, spacing reproducible from the rows; `countPerRib` is declared `dropped` (the persisted rows replace it). Dry run result: 295 `studs` objects in 286 JSON files became 11 847 rows; `diff` fixtures with inserted beams keep index order (`index = base length + k`); the insert-beam mutation can no longer carry studs, so the object of beams inserted by the mutation under test is dropped from payload, diff and after document (2 objects + 1 payload; reported in the note). Residual references (53 hand-written files, 53 listed as `MANUAL`): model field `studs` + `HeadedStuds`, SQLite sub-table `en1994_beam_studs` and its codec cells/table indices, diff `beam-rows`, `apply-and-inverse`, 6 old `change-beam-stud-*` kinds and their edit rules, checks/scene/spec-trace. The removal of the Rust model field, the SQLite sub-table (positional table indices shift) and the old kinds is deliberately not automated: the queued en1994 work must delete those references together with the code that reads `beam.studs`.
Row rules are a restricted expression language (`ast` whitelist: arithmetic, comparisons, subscripts, `len all any abs sum min max range int float`), tested.

## 6. Contracts (separate run: `evolve.py contract`)
The `valueBytes` of a case is not a function of the DDL alone, so the command projects the committed sample fixture row by row into a python `sqlite3` database created from the committed DDL (constraints enforced by sqlite; subtype/1:1 sub-tables share the parent id, `resolved_*` ids only when the logical id is unique, enums as tokens, `ieee754` pairs from the real bits) and measures it with a port of the framework's `independentSqliteExtent` (typeof-based). Validation: for git HEAD the projection reproduces rows, `valueBytes`, `schemaBytes` and `tableWidths` of **all 16 stored cases** of en1990, en1991, en1993, en1994, en1995, en1996, en1997, en1999 exactly (test `test_extent_projection_reproduces_the_committed_contracts_of_git_head` covers five of them without relying on the working tree). The command refuses (no write) when the projected row count differs or any column could not be mapped.
Applied (before -> after): en1990 `schemaBytes` 12297 -> 12534, full 4411 -> 4401 (the TS inline literal said 4438/173, now equal to the JSON: 4401/146); en1993 54435 -> 55830, full 3239 -> 7746, empty 13; en1994 11031 -> 11990, full 2192 -> 2324, empty 74 -> 82. The SQLite tests' accepted `maxTables`/`maxColumns` were stale too and follow the contract now (en1993 37 -> 39 tables, en1994 67 -> 68 columns; the "short" limits stay below). Rust and TS tests that read `semantic.json` need no further change; nothing was executed (no bun, no cargo). Other artifacts keep their stored values (not stale at the time of the check except by concurrent edits; run `contract <artifact> --dry-run` after fixture or DDL edits).
Observation: en1991 and en1997 working-tree values differ from the projection of the working tree (concurrent edits of their DDL/fixtures); run the command for them when their owners are done.
