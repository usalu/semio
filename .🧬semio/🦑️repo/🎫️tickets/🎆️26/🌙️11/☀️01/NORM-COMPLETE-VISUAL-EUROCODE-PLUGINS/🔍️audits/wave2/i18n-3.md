# 🌐️ Wave 2 i18n Audit (i18n-3): norm plugin after tonight's additions

Read-only scan plus routing, 2026-11-03. No builds, no git writes. No source edits: every candidate found sits in a String-typed sink with no German slot, so a fix needs a typed bilingual value first. Those items are routed in `📌️important/requests.md` under "from: i18n-3".

- Scope: `✏️s/🔌️plugins/📕️norm`, Eurocode artifacts `🗿️artifacts/{⚖️en1990,🏋️en1991,🏛️en1992,🔩️en1993,🧩️en1994,🪵️en1995,🪨️en1996,🌍️en1997,🫨️en1998,🪶️en1999}` and the shared crates (registry, compliance, structural-scene, mechanics, viewport, results, bridge, oracles). - Script: `🗑️generated/i18n-3/scan.py` (run `python3 -I`), with `classify.py`. Outputs in the same folder: `raw.json`, `hard-ui.tsv`, `hard-domain.tsv`, `missing.tsv`, `ident.tsv`, `fallback.tsv`, `routed.tsv`. Tool output, deleted at ticket close.
- Method: bilingual pairs are read from `label_en/label_de`, `en:/de:`, `LocalizedCopy::new`, `FieldLabel::new`, `loc/native/copy/m!`, adjacent literal tuples, and `.into()` tuples. A literal with no pair is a candidate only if it has at least two English words and no sibling German text in its enclosing call or in the four lines around it. `if de { … } else { … }` and `bi(|de| …)` forms count as paired.

## 🔎 Checks that passed

2. EN-side strings with German words: 2, both `von Mises`, accepted.
3. Default-language fallbacks: `unwrap_or(en)`, `unwrap_or_else(|| en)`, `.unwrap_or(&self.en)`, `_ => en`, `else "en"`: 0 in artifacts and shared crates. The only default-language fallback is `enum Lang { #[default] En, De }` in `📇️registry/…/🪟️visual-windows/🧊️viewport3d/🎚️config/🦀️.rs:69`, which is routed. Other `Locale::En` and `Lang::En` uses are exhaustive match arms, or closures with EN/DE arguments, and were checked by i18n-2.
4. Example titles (`📚️examples/…/🟦️.ts`): no identical EN/DE pairs left apart from "Demo" (excluded artifacts), and no EN casing defects.
5. The `bi(|de| …)`, `if de { … } else { … }`, `loc(&format!(…), &format!(…))` and `(EN.into(), DE.into())` constructs were read in context and counted as paired (52 candidates, classed FALSE_POSITIVE_PAIRED in `routed.tsv`).

## ⚠️ Not verified in this pass

- Whether the UI renders spec-trace descriptions and clause section labels. The routed items ask the owners to confirm.
- Runtime rendering and the TypeScript UI. The `.ts` scan covered example titles and `title/label/text` keys only.
- Candidates are not spot-checked for false negatives. A bilingual construct that the enclosing-call and four-line window do not recognise would be counted as a candidate, not missed, but a single-language literal next to an unrelated German literal inside the same call would be hidden.
