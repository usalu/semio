## 2. Direct manipulation (all grips write typed kinds, one commit per drag)
Every grip writes entity fields in stored units (m, rad, counts) through existing `change-<entity>-<field>` kinds; the live drag commits one `setFields`. No new kinds were needed.

| grip | entity | writes | note |
|---|---|---|---|
| `hole_x`, `hole_z`, `hole_d` | `cutouts` (hole) | `distanceM`, `centreHeightM`, `lengthM` (diameter, radial grip, `k = 2`) | three distinct anchors around the hole, carried by the hole cylinder part |
| `h_ef` | `cutouts` (notch) | `depthM` | `h_ef = h - depth` is mirrored: `Binding.from = "h"`, scale `-1000`, `Home::stored` gives `depth = h/1000 - s`; v4 dropped this grip |
| `n`, `rows` | `fasteners` | `columns`, `lines` | count steppers (1..12, 1..6) |
| `col<i>` (i = 1..columns-1) | `fasteners` | `spacingParallelM` | fastener `i` of the first row stands at `a3 + i·a1`; write `a1 = (s - a3)/i` |
| `row<j>` (j = 1..lines-1) | `fasteners` | `spacingPerpendicularM` | write `a2 = (s - a4)/j` |
| `a3t`, `a4t` | `fasteners` | `endDistanceM`, `edgeDistanceM` | the first fastener |
| `a1`, `a2`, `d`, `t1`, `t2` | existing | unchanged | |

- Case engine (`🎬️scene/🗂️cases`): fastener patterns are always `Pattern::Points` (regular grids generate their points row by row; explicit `px<i>/py<i>` raised from 24 to 72 points). `regular(g)` guards the per-fastener grips: an explicit irregular point list has no spacing to rewrite. The fastener entity row now lists `px/py` of every fastener (`pattern_mm`, up to 12 x 6).
- Minimum-spacing feedback: `spacing_demands` computes per fastener the largest of required/provided over a1 and a2 to the nearest neighbour, the end distance a3,t and the edge distance a4,c (provided = pattern value, mirrored at the far side) with the kernel `spacing_table` (Tables 8.2, 8.4, 8.5, 8.6, same arithmetic as T-74; `facts::spacing_minima`, `facts::family_of`). Result: `ColourChannel::Fields` + `FieldSamples::Instance` (one value per instance), ramp `failure`, range 0..1.2, legend `spacing:<id>`, detail text "minimum spacing violated (demand x)" / DE. It is recomputed by every projection, so the live drag preview recolours while dragging.
- CLT layer thicknesses: **traced, not implemented**. The layup is the string `panels[].layup` (`40/40/40`); `FieldBinding` writes numbers only, so a layer grip has no typed kind to write. Decision for after the first green build: a sixth entity `panelLayers` (panel id, position, thickness) through `🧰️scripts/en1995-collections/spec.py` (schema.py, kinds.py are additive, but removing `layup` is not supported by the generators and must be hand-crafted across model, twins, sqlite and 242 fixtures), or a string-capable write in shared (request recorded).
- Per-fastener irregular positions: the model stays a regular pattern (EN 1995 Tables 8.2 to 8.5 assume rows and columns). `offsetXM/offsetYM` stay stored and editable but unused by the scene (open). Explicit irregular positions would need a `fastenerPoints` child entity (same blocker as `panelLayers`).
- Tests (written, not run): scene unit `the_hole_grips_drag_the_position_and_the_diameter_of_the_cutout_in_metres`, `the_notch_depth_grip_writes_the_depth_through_the_mirrored_effective_depth`, `the_fastener_pattern_editor_drags_rows_and_columns_and_writes_the_spacings`, `the_minimum_spacing_feedback_colours_each_fastener_live` (each grip evaluated at its own anchor returns the stored value; drag to a known value; tight a1 = 5 mm gives demand > 1 everywhere, 500 mm gives < 1; adding columns adds instances).

## 3. One-click remedies on unit-converted inputs
`⚖️timber/🧱️entities`: a `Binding` is `case = from + SI x scale` (`from` = another input of the row, scale may be negative). `rehome` converts `current` and `required` of every numeric remedy into the stored unit (`stored()`), flips `AtLeast`/`AtMost` for a mirrored field, and no longer marks converted remedies not applicable. A remedy whose input has no entity field (unbound) is `applicable = false` instead of pointing to the row. Handles and diagram markers use the same `Home::stored` / `Home::unit`. The shared `applyRemedy` writes `required` unchanged, so the value must already be in the stored unit, which it now is. Tests: `the_homes_convert_case_units_into_the_stored_units_of_the_entity_fields`, `a_remedy_on_a_unit_converted_entity_input_is_one_click_and_lands_in_the_stored_unit` (failing notch: width remedy in m, applying writes the required value).

## 4. T-94 to T-96: traced
T-94 (diaphragms and wall diaphragms, 9.2.4), T-95 (trusses and stabilising loads, 9.2.5), T-96 (bracing and restraints, 9.2.5) are catalogue entries with evaluators in `⚖️kernel/🧩️components`, are in the vocabulary, and since v4 each has a case in `catalogue_demo_document()` (the "no case in any document" gap of COVERAGE-3 is closed). They are not typed entities. Reasons: (1) the Method A/B factors, hold-down and stabilising constants of 9.2 are unverified NDP/table values and no entity should present them as design truth; (2) an entity needs spec.py rows for `diaphragms` (11 inputs incl. method, hold-down, panel count) and `bracings` (n_d, l_m, f_rd, k_br) plus a trusses decision, then schema.py, kinds.py and hand-written checks/scene/units modules, and the scene would draw a shear wall and a truss from numbers the snapshot cannot place (no position, no member list); (3) nothing in this wave can be compile-verified, and the generators produce ~60 files per entity. Next step after the first green build: run `spec.py` with the two entities.
