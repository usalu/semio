## Findings not coded (design notes, with estimated gain)

1. **`Arc<SceneEntity>` in `StructuralScene`** (schema change, about 120 consuming files). `SceneProjector::run` assembles via `merge`, which deep-clones every entity of every fragment, `SceneMemo`/`diff` compare whole scenes, and `live_scene` returns the scene by value. With `Vec<Arc<SceneEntity>>` the merge is pointer copies and `diff` gets an `Arc::ptr_eq` fast path. Estimate: 3 to 10 ms to below 0.3 ms per scene call at 1000 entities. Needs schema first, regenerate the twins, then the compiler.
2. **`Arc<CheckReport>` end to end.** `NormFamily::live_report` returns an owned report (session `report().clone()`), `NormHost.report` is owned, `LaneClock::reports` stores one and `over_lanes` clones it on every drag tick even when no evaluation is due, `SceneMemo` and `memo_diagrams` clone it per revision, `SessionEvent::Done` clones check vectors. 3 to 6 report clones per tick, each 0.3 to 1 ms at 1000 to 5000 checks. Needs `NormFamily`/`NormHost` signature changes in all editors.
3. **One value tree per document revision.** The document is converted with `to_value()` up to four times per revision: `EvaluationSession::rebuild`, scene kit `row_texts` (every fingerprint pass, and the production `LiveScene::scene` uses `ChangedSet::all`), `Rows::except` (en1990/1991/1997/1998/1994, only for the field names), and the overlay base. A revision-keyed `Arc<DslValue>` (or `Rows::except` through `value_key_at_path`, which the derive answers without converting values) saves 1 to 3 ms each.
4. **`revision_of` hashes `Debug` of the whole document and report on every scene call** (now without the string, still full formatting cost). The session revision plus the structural hash of the shared value tree (design note 3) would replace it: 3 to 10 ms at 1000 rows.
5. **Per-scope gates recomputed in every row unit.** EN 1990 `evaluate_scoped(Row)` runs input validation and the whole integrity pass for each member unit (comment in the code: "recomputed per scope"). After fix 8 it is O(n log n) per unit, still O(n^2) for a cold pass. A gate verdict memo keyed by document equality (static, one slot per family), or hoisting the gate into the global unit, brings the cold pass at 1000 members to the checks alone. The same shape is likely in the other families whose units call `*_scoped(.., Scope::Row)`; each needs its own review.
6. **Global units read `*`** (`Rows::global`/`part` with `ReadSet::new(["*"])` in every family; `global_reading`/`part_reading` are used nowhere in the artifacts). They re-run on every drag report tick. Declaring their reads (the integrity gates read the id columns and reference fields only) would skip them on pure value edits.
7. **`Job.document` clones the whole document per slow (T2) unit, under the session lock** (`EvaluationSession::fetch`). Holding `Arc<S::Document>` needs `UnitSource::Document: Sync` (today `Clone + ToValue + FromValue + Send`), which is a trait change for all families.
8. **`Layout::of` finds placements linearly per entity** (`placements.iter().find(..)`, n x P) and runs once per fragment. A map from id to placement built once in `Layout::of` makes it n + P. Nine layout files.
9. **`LiveView::new(document: F::Document)` takes the snapshot by value**, so every window clones it per paint (n windows x document). Pass `&Document` or an `Arc`.
10. **en1993 `live_entities` projects the whole scene just to list entity refs** (used when a gesture has no entity, and by placement `SetFields`); other editors may do the same. A document-level entity list (the `SceneKit::entities` function already exists) is O(entities).
11. **`SceneProjector::run`** builds `live`, `keep`, `dirty` as `BTreeSet<String>` clones, a `Vec<String>` of `hex(key)` for the global key and one `format!` per dependency per entity; `ReportIndex::stamp` formats a `String` per subject per entity; `ReportIndex::follow` allocates a `positions` vector per subject on every call even when nothing changed. All O(n) allocations per run (about 0.2 to 0.5 ms at 1000 entities); hash the parts directly.
12. **Transient lane is stored as JSON text** and decoded (`transient.lane()`) by each window and each reducer call; cache the decoded value per store version.
13. **Linear id lookups between collections** inside checks and scenes, all small collections today but quadratic when scaled: en1993 `d.members.iter().find(|m| m.id == ..)` in `units`, `built-up-checks`, `restraint-checks`, `frame-checks`, `shell-and-structure-checks`, `detail-sketches`, `scene-members/kit`; en1990 `scene/analyses` (`fatigue_spectra` per member), `diagrams` (line 547, nested `any`); en1996 `detailing` (`joints`/`chases` per wall), `conformance-and-integrity` (`cases` duplicates by `position`, O(k^2)); en1992 `section-resistance` bars per layer. Build an id index once per evaluation.
14. **`overlay_preview`** still does `from_value(preview_value.clone())` per tick (whole-document clone plus typed rebuild), see W3-REALTIME round 2; the remaining fix is a per-family typed row patch.

## Already good (checked, no change)

`ReadHashes` and `EntityGraph::closure` (hash maps, no allocation per read), `FragmentCache` (id keyed `BTreeMap` of `Arc<Fragment>`), `DependencyIndex` (reverse edges kept in step), `plan_units` (one pass, one sort), `Coalescer`/`PresencePublisher`/`EvalScheduler` (O(1) per tick), `PlacementCommit::of_writes` (linear scans over the handful of dragged ids only), duplicate-id checks (`BTreeMap` counts, O(n log n)).
