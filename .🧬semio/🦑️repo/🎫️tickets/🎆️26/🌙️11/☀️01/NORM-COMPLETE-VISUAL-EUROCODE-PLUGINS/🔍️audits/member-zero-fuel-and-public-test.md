# Member Public Cancellation And Zero-Fuel Review

The existing public-path test original_member_history_receiving_reborrows_actual_caller_retains_pages_and_pays_cancelled_custody already constructs genuine SPR bytes with SprWriter, sealed OwnedSchemaDecodePages, stable OriginalWireSourceIdentity, OriginalMemberCaller and original source loan. It runs fixture cuts, cancels through the actual caller, drains close_step, compares per-turn allocation births/releases to physical receipts, asserts source identity, and closes history, loan and pages. This covers substantially more than the inline scalar law. It does not explicitly make a zero-work close attempt before decoding or assert repeated terminal calls, and does not deliberately trigger cancellation inside the forwarded progress/allocation callback.

Potential zero-work transition: close_step sets closing=true before retirement_should_yield and before maximum_items denial. A fresh unadmitted receiver under with_original_work_loan(0, deadline, ...) therefore returns Progress(default) without a receipt or fuel debit, but a later funded step returns Fault because closing is set. The same holds for maximum_items=0. This is an observable state change; whether requesting close is intentionally an uncharged cancellation signal must be settled against the owner contract before labeling it a bug. A genuine regression, if admission must precede that state transition, can extend the existing real-pages setup: create the receiver, call close_step in a zero-work loan and assert empty receipt and unchanged heap, then invoke funded step with the same actual source/loan and assert it advances rather than Fault. Finish by caller cancellation and the existing bounded drain; do not synthesize flags or abandon custody. A separate zero-items turn should assert the same law if retained grant also gates initiating closure.

For shortest terminal scenario, use the same setup with an unadmitted receiver: zero-work close denial as above, then cancel the caller and drain close_step under one-work original loans until terminal_is_empty. Check every receipt against observed births/releases, original work deltas ≤1, and source identity. Invoke close_step again after terminal and assert Complete(default), zero work and zero heap effects; close loan and pages as in the existing test. To verify active custody rather than only metadata, execute at least one successful admission/step before cancellation, assert nonempty custody, and repeat the same drain.

The decoder.take metadata branch is entered only after the top-level fuel/depth/grant checks; it reports one unit to reconciliation after the mutation. The normal-step final receipt drop/closed mutation checks paused again after the preceding settlement. The final close receipt drop/closed mutation follows the initial retirement fuel check. Static inspection therefore found no route for those terminal owner mutations at fuel zero at their respective entry checks. A one-unit test should nevertheless measure reconciliation and effects; no runtime red has been established for this concern.
