## 0. Summary

| | S1 | S2 | S3 |
|---|---|---|---|
| EN 1990 | 1 | 10 | 9 |
| EN 1991 | 3 | 24 | 14 |

Headline items: (a) permanent actions get gamma_G,sup or gamma_G,inf by action *kind*, not by the sign of their effect, so a relieving `g_sup` action is amplified by 1.35 (unsafe); (b) after the `CORE` change, every EN 1991 catalogue `Info` outcome and the exceptional-snow info check are built as `utilization(value, 0)` and therefore come out `Fail` without remedy; (c) pitched-roof c_pe at 45 to 60 degrees halves the windward pressure by interpolating across the sign change; (d) the EN 1990 and EN 1991 catalogue `Outcome::utilization()` still returns 0 for zero capacity (the shared status is now correct, the remedy gate is not).

## 1. EN 1990 findings (ranked)

### S1

1. **Gamma_G,sup / gamma_G,inf follows the action kind, not the effect sign.** `H90:47-66` `actions_with`: `"g_sup" => (Permanent, false)`, `"g_inf" => (Permanent, true)`, effect = `influence × gk` (signed). `G90:240-244` `permanent_factor(fav)` then takes `k_fi·γG,sup` for `favourable == false` irrespective of the sign of `value`. EN 1990 6.4.3.2 / Table A1.2(B) note: gamma_G,inf applies to the part of a permanent action whose effect *relieves* the verified effect (continuous-beam hogging moment from the unloaded span, cantilever back-span, uplift, restoring moment). Example (`en1990-recompute.py`, demo A): span part +100, relieving part −40, Q +20 → code 1.35·100 + 1.35·(−40) + 1.5·20 = 111.0; correct 1.35·100 + 1.00·(−40) + 1.5·20 = 125.0 (unsafe by 12.6 %). Same defect makes EQU (`U90:70-82`) depend on how the user typed `kind`. Fix: classify per combination from `contribution` sign: for each permanent action choose γG,sup when its (signed) effect adds to the maximised effect and γG,inf when it reduces it; generate the pattern combinations (all sup, all inf, per-span alternation when the model has spans) and keep the maximum; same for the minimum envelope (finding S2-2). Spec E90.16 already requires this ("G inf/sup per spatial member is a pattern generator").

### S2

1. **Sign convention of favourable actions is inconsistent between EQU and STR.** `G90:161-169`: `total() = unfavourable + favourable` (STR/GEO/SLS, favourable must be *negative* to relieve), `net() = unfavourable − favourable` (EQU, favourable must be *positive*). `H90:47-66` feeds one list to both (`U90:49` STR, `U90:70` EQU), and `K90:484-485` prints `favourable` as a positive stabilising value. A `g_inf` action with positive influence is therefore *added* in STR (conservative but wrong) and a `g_inf` with negative influence *increases* the net destabilising effect in EQU. Fix: store favourable contributions with one convention (signed effect) and make `net()` = `unfavourable + favourable` with the stabilising sign convention documented once, or carry `destabilising`/`stabilising` per action explicitly for EQU.
2. **No minimum (opposite-direction) envelope.** `G90:226` drops every variable with `value < 0` (`H90:61` `favourable(value < 0.0)`), `G90:295` `governing` takes the maximum only, and the report compares one scalar `rd_str` (`U90:22-40`). A wind suction or imposed-load pattern that reverses the effect (uplift of a light roof, tension in a column, hogging) is never verified: demo B in the script, E_d,max = 30 while E_d,min = 1.0·30 + 1.5·(−80) = −90. Fix: generate `max` and `min` combinations (variables with negative influence are unfavourable for the minimum) and check against `rd_str` and a new negative resistance field, or against |effect| per sign.
3. **FORM non-convergence is reported but not enforced.** `R90:250-267` returns the last iterate; `K90:720-729` prints `converged = false` only in the step text and still emits `Outcome::minimum("beta-target", …)` on that iterate. Fix: when `!form.converged` return `Err("FORM did not converge in 100 iterations")` (not-applicable), or `Mode::Limit` with utilisation 1e6; also start from design-value guesses mean ∓ 0.7β·sd (starting at the mean fails for heavy Gumbel tails).
4. **`Outcome::utilization()` gate returns 0 for zero capacity** (`K90:111-116`, also `K91 catalogue/🦀️.rs:81`). The status is now computed by `CORE` `ratio` (zero capacity with nonzero demand = `UTILIZATION_CAP` = Fail), but the remedy is attached only `if failing` (`K90:199-206`), so the row is `Fail` without remedy (debug assert `CORE:382` panics in debug builds). Triggers: E90.10 with `x_k = 0`, E90.20 with `γ_Rd → ∞`, E90.24 with `span·1000/ratio = 0`. Fix: reuse the shared ratio for the gate (`failing = status == Fail`), or return `Err` for non-positive capacity.
5. **No input validation on the serviceability and design-value entries.** `K90:602-627` E90.24: `span ≤ 0` gives a zero limit, `ratio_* ≤ 0` or `drift_ratio = 0` gives an infinite limit (`inf` ≥ demand, Pass). `K90:363-378` E90.10 and `K90:420-433` E90.20 accept `γ_m ≤ 0`, `γ_Rd ≤ 0`. Fix: `pos()` guards as in `K91 catalogue/🦀️.rs:47`; reject NaN everywhere (`NaN > limit` is false, so a NaN effect passes unless the shared ratio is used: `CORE:19-21` handles it, `K90:111-116` does not).
6. **Unknown material silently gets gamma_M = 1.0.** `I90/⚖️checks/🦀️.rs:31-33` `annex_gamma_m`: `ndp_lookup(...).unwrap_or_else(|| ndp(annex, "gM.other"))`. A misspelled or unsupported material (masonry, aluminium, glass) is verified with 1.0, exactly the silent fallback the completion reports removed elsewhere. `NaDe::gamma_m`/`NaEn::gamma_m` expose this to every material crate. Fix: return `Option<f64>` (as `E90.10` already does at `K90:369`), or `NaN` that fails the registry test; add accidental values (concrete 1.2 EN / 1.3 DE [V], steel 1.0) and glulam 1.25 / LVL 1.2 for DE timber [V].
7. **ψ table gaps and an interop break with EN 1991 categories.** (a) `N90:272-284` `canonical_category` maps only single letters `A..H`; the NA-DE and EN 1991 categories `A1..A3, B1..B3, C1..C6, D1..D3, E1, T1, T2, Z` (used by `C91 part_1_1::imposed_row`) are unknown to `psi_entry_of` and fail input validation (`I90/🧮️partial-factor-sets` `push_input_validation`). Fix: map by first letter (`A*`→residential, `B*`→office, `C*`, `D*`, `E*`→storage); `T*`/`Z` follow the adjoining floor category (spec 1.5). (b) Missing rows: settlement (1.0/1.0/1.0) and other variable (0.8/0.7/0.5) of Table NA.A.1.1 [V]; rail wind Table A2.3 (0.75/0.50/0, only the road row 0.6/0.2/0 exists at `N90:258`) [V]; HSLM/real trains A2.3: code `psi(0.0, 1.0, 0.0)` at `N90:268`, EN prints ψ0 = 1.0 [V, 65 %]. (c) `N90:306-309` `psi_for_category` returns (1,1,1) for unknown categories (display only, but `annex_psi` returns `NaN`, `I90/⚖️checks/🦀️.rs:42-44`, which propagates silently).
8. **NA-DE GEO set C equals the EN recommendation.** `N90:29-31`: `gG_sup.geo.A1 = 1.00`, `gQ.geo.A1 = 1.30` for both annexes. For NA-DE the GEO-2 (STR/GEO, DA2*) partial factors of DIN 1054 are γG = 1.35, γQ = 1.50, and only GEO-3 (global stability, slopes) uses 1.00/1.30 [V, 70 %]. `K90:172` cites `ndp.en1990.e90-16.1` but the value is the EN value in the `de` column. Fix: keep `de` = EN until a human has the print, but split `geo-2` and `geo-3` rows now and make the E90.16 `set` input explicit ("B", "C-geo2", "C-geo3") so EN 1997 selects the right family.
9. **Table B2 conversion is discontinuous and non-monotonic.** `N90:353-368` returns the tabulated β at exactly T = 1 and T = 50 and `β(T)` from `p_T = 1 − (1 − p_1)^T` elsewhere. The two disagree (script: RC1 β50 from β1 = 3.21 vs table 3.3; RC3 4.42 vs 4.3), so RC1 gives β(40) = 3.27, β(50) = 3.30, β(51) = 3.20. Fix: anchor on the table (log-linear interpolation of β between T = 1 and T = 50 in ln T, extrapolate with the conversion from the nearest anchor), or document the anchors as step values.
10. **Seismic combination lacks φ.** `G90:272` uses ψ2,i for 6.12b; EN 1998-1 4.2.4 requires ψE,i = φ·ψ2,i (φ = 0.5 to 1.0 by storey occupancy). Link-only per spec, but the generator has no `psi_override` hook, so EN 1998 cannot supply it without a second implementation. Fix: `Action::psi_scale: f64` (default 1.0) multiplied into the ψ factor of 6.12b only.

## 2. EN 1991 findings (ranked)

### S1

1. **Every `Info` outcome of the catalogue and the exceptional-snow check now fail.** `K91 catalogue/🦀️.rs:167`: `Mode::Info => b.utilization(Quantity(value), Quantity(0.0)).build()` and `D91:188-190` `info_check`: `.utilization(quantity, Quantity::new(kind, 0.0))`. `CORE:18-26` `ratio(demand, 0)` is `UTILIZATION_CAP` for any non-zero demand and `CORE:266-272` sets `Fail` when the ratio exceeds 1. With the working-tree `CORE` all ~230 info rows (E11.01 total, E13.01 s, E14.05 q_p, every `E2.*`, `E3.*`, `E4.*`) become `Fail` without a remedy (debug assert `CORE:382`), and `en1991.1-3.snow-exceptional.*` fails for every roof of the North German lowland. Tests `validity_ranges_warn_and_limits_fail_with_remedies` (`all != Fail`) and `compliance-report` line 11 would fail. Fix: `Mode::Info => b.status(CheckStatus::Pass).explanation(...)` without `utilization` (as `K90:197` does), and set `computed`/`limit` through a `CheckBuilder::value(Quantity)` helper (request for `CORE`); same for `info_check`.
2. **Pitched-roof c_pe: interpolation across the sign change at 45 to 60 degrees.** `C91:514-526` `pitched_roof_cpe` interpolates the *primary* pair and the optional second (positive) pair only when both bracketing rows carry one. Row 45° has `(0.0, 0.0)` plus `Some(0.7, 0.7)` (zones F, G, H: `0.7/0.7/0.6`), row 60° has `(0.7, 0.7)` and `None`. At 52.5° the function returns the single pair (0.35, 0.35) (script); the EN table has +0.7 at 45°, 60° and +0.8 at 75°, so +0.7 (F, G) governs the windward roof and the result is half the load. Also, EN 1991-1-4 7.2.3 (7.4a note) asks for the flat-roof values for −5° < α < +5° and only same-sign interpolation; the code interpolates −2.3 → −1.7 across ±5°. Fix: store each column as positive and negative series, interpolate each only between rows where both exist, return one candidate per series (and the flat-roof table for |α| < 5°); add a test at α = 52.5° expecting 0.7.
3. **Orography enters the NA-DE profile linearly.** `C91:401` `Some(na_profile_pa(qb0, z_m, coast) * c_o)`. q_p scales with v_m² = (c_r c_o v_b)²; the EN branch (`C91:381-385` `exposure_factor`) uses (1 + 7 I_v)(c_r c_o)² and gives q_p(c_o = 1.3)/q_p(1) = 1.468 (script, cat II, z = 10 m, v_b = 25), the NA branch gives 1.300 (13 % low, unsafe). [V] I did not see the NA-DE rule; physically at least c_o² must apply to the velocity part. Fix: multiply by `c_o²` (conservative bound) until the NA text is keyed, and raise `ndp` basis `e14.na-profile`.

### S2
