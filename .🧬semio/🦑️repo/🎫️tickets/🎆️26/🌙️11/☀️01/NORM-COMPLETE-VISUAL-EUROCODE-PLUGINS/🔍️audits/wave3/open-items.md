## Method and limits

- Candidates: every `- [open]` line (590). Owner = the `→` target (or the sender when no arrow). Code = the EN code in the line's header, else `infra` when the header names build/runner/queue/memory/gate terms, else `shared`.
- `likely done: verify`: a later `[done]`, `[fixed]`, `[closed]`, `[ok]` or `[unlock]` line repeats one of the item's backtick paths or identifiers verbatim. This is a textual match only; the match can be a mention rather than a delivery. Verify in code before closing.
- `blocked on print/human value`: the line asks for a printed standard, a human check or an unverified value (the print list is `🔍️audits/wave2/printed-standards-checklist.md`, section 5, and `print-list.md`).
- `blocked on build queue`: the line waits for a rebuild, compile, bless or regenerate run (`🗑️generated/build-<code>/latest.md`). Runner `freeze.txt` was empty at triage time.
- `open`: none of the above. Items the newer wave3 reports already close are only caught when a done line repeats the path; the per-code reports (`en199x.md`, `*-corr*.md`, `*-fix.md`) were not read line by line.
- Owner tags are the raw tags used in the log (for example `en1995 compliance owner`, `A1`, `leaf-kinds`, `guard`).
