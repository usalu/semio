## 2. Span-arrangement visual (partial, data gap)
Layer `gamma-bands` (`🌈️gamma-bands`, `kit` layer table, `Out::push_fields`, legend `gamma` in `kit::finish`): per member a surface on the beam side face, one flat colour band per permanent action with an effect on the member (table order, equal width), value = the factor that action takes in the combination (gamma_G,sup where it adds, gamma_G,inf where it relieves, K_FI and overrides included). Source: new `combinations::permanent_factors` (regenerates the member's own combinations with `member_actions` and matches columns by family, equation, leading, group; unmatched columns fall back to the unit column factor). Each column has its own scalar field named `combination:<column id>`, the same ids as the combination track, so the existing stepper (view lane) recolours the pattern with no re-projection; the legend range is the min/max of the displayed values. Test `the_gamma_bands_colour_each_permanent_action_by_sup_or_inf_per_combination` (G-sup band equals the column factor, G-inf band is lower).
Gap: a Member has one span and the document has no span positions, so bands are per permanent action (A1.3.1 individual actions), not per span along a continuous beam. Showing real spans needs a new row collection through every layer (requested to shared, not done blind). `continuous_beam_envelope` is not wired into the scene for that reason.
