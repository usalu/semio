# Viewer Focus and Selection Event Flow

## Current Validation Status

Source implementation and native regression tests are complete. Static source audit found all ten Eurocode viewers wired to the shared renderer, interaction definition, topology and focus-keyed diagrams callback, and all ten editors wired to the retained view-focus hook. This audit is structural evidence only. No current native compilation or execution is claimed. A restricted-worker native request was superseded by the parent full-access worker and canceled before compilation; future actual builds belong to that worker under the authoritative machine-wide capacity gate.

## Event Source

Exact checks now have a canonical framework interaction address check/<id>, already supported by the norm topology. Both check activation and keyboard check stepping publish that address through interactionSelect. Keyboard stepping resolves its current position from the captured real interaction selection/report, preserving an exact picked check or choosing the governing check of a picked entity. A subsequent entity pick replaces the canonical check target through the normal framework selection machine. No guessed timestamp or new persisted/transient schema field is needed.

The editor retained reducer now offers an explicit view_focus_effects hook over its captured original transient and interaction roots; all ten Eurocode editor bindings use it. The viewer retained reducer uses the same production check-step helper. View-only transport/combination events do not publish check effects.

NormSelection::from_interaction gives explicit interaction picks authority. The local lane/stored check remains a fallback only without picks. Exact keyboard selections retain priority through their canonical check identity, including when a report changes row order. Stored-configuration owner filtering and compatible checks-list filtering remain available; a fresh entity pick selects that entity governing check rather than reviving an old lane check on the same owner.

## Readonly Viewers

All ten readonly Eurocode viewers now render their model, checks and diagrams through one NormViewerFrame. It shares report, lane and resolved selection. Viewport highlights use the selected scene addresses; checks carry the selected row and a compatible owner filter; diagrams use the selected document owner, or the governing owner when nothing is selected. Diagram memoization keys include focus. No viewer imports an editor module.

The missing native interaction definitions and topology overrides were also added to all ten viewers. Without these, framework validation could prune every pick. Shared viewer definitions admit all supported scene kinds plus check/load-case granularities. Readonly check rows bind check addresses through the framework interaction tree; they do not dispatch setSelectedCheckIndex or remedy edits. Viewport and diagram edit controls remain absent. The compiled component descriptor must be regenerated by the actual native build to include these manifest interactions.

## Native Regression Paths

- The language-neutral five-event sequence fixture covers pick B1, keyboard previous-check to B2, fresh pick B1, keyboard next-check to an exact non-governing B1 check, and fresh pick B2. Its native async test invokes the actual check-step effect, parses the real framework replay targets with serde_json, applies protocol::next_selection, folds the production view step and checks selection/planner output. It supplies no alternate selection implementation.
- The readonly production-IR test constructs real structural geometry, invokes the shared viewport/checks/diagrams BuiltNode renderers, projects and retires their real framework trees, and asserts selected owner/check/diagram plus absence of mutation actions.

Relevant native packages are semio-s-plugin-norm-app-surface-panels-inspection and semio-s-plugin-norm-app-surface-live-editor. The parent native worker is modularizing interaction topology to satisfy the real compilation-unit byte budget while preserving these production tests.

## Remaining Scope

This work covers the ten Eurocode editors/viewers; the five DIN/catalogue surfaces have different layouts. Clearing every pick can still expose the local check fallback. The sequence fixture establishes ordered event replay, not every overlapping in-flight user event interleaving. Native execution and final descriptor regeneration are still required before runtime completion can be claimed.
