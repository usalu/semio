## 1. Focused grip and platform preferences reach the overlays

### Platform preferences (domain-neutral, schema-first, both hosts)
- Schema: `ShellPlatformPrefs {forced_colors, prefers_contrast_more, prefers_dark, prefers_reduced_motion}` in `manifest/app-surface/shell-hooks` (`schema/🛰️.proto`, `schema/🟦️.ts`, Rust struct + serde camelCase), re-exported from `semio_framework`.
- Seam: `PluginShellHooks::platform_prefs_changed` (default no-op), `ShellHookRegistry::platform_prefs_changed`, `ShellHookDriver::note_platform(plugin, prefs) -> bool` (dedupes, first report counts, forgets on app switch).
- Shell: `plan_dock_windows` (view-chrome) feeds `host_platform_prefs()` into the driver before `observe_device_hooks`.
- Store: `host-base` `HostPlatformPrefs` region (`set_host_platform_prefs`, `host_platform_prefs`, `publish_host_platform_prefs -> changed`), thread-local like `HostAppearance`.
- winit host (Windows, macOS, Linux): new `native-platform/🎛️platform-prefs` (`detect()`; pure parsers `from_windows` via `reg query` (HighContrast Flags bit 0, AppsUseLightTheme, MinAnimate), `from_macos` via `defaults` (reduceMotion, increaseContrast, AppleInterfaceStyle), `from_linux` via `gsettings` (a11y high-contrast, color-scheme, enable-animations) plus `GTK_THEME`). No library, no unsafe. `native-winit-app` publishes at window creation, on `ThemeChanged` and on `Focused(true)` and requests a THEME-reason redraw on change.
- Browser host: `resolveWgpuHostPlatformPrefs` + `WGPU_PLATFORM_PREFS_MEDIA_QUERIES` (`forced-colors: active`, `prefers-contrast: more`, `prefers-color-scheme: dark`, `prefers-reduced-motion: reduce`) in boot-descriptor (public entry re-exports), initial value rides the boot message (`platformPrefs`), live changes use a new `host-platform-prefs` message (contract, `setHostPlatformPrefs` on the transport, worker `receive`, `bindings-types`, wasm door `semioWgpuSetHostPlatformPrefs` in the renderer, browser-host listeners with dispose).
- Norm: `NormShellHooks::platform_prefs_changed` stores `A11yPrefs`; `platform_a11y_prefs()`, `a11y_prefs_of`.

### Focused grip
- New `shell-hooks/🎯️grip-focus` (ephemeral, local, per interaction domain): `GripRef`, `GripWalk`, `GripStep`, pure `walk_grips`, registry `note_grips` (written by `publish_viewport_access`, drops a focus whose grip vanished), `focused_grip`, `set_focused_grip`, `walk_focus`.
- `NormShellHooks::handle_key`: scope becomes Handle while a grip of the window's domain is focused. Enter in the viewport starts the walk (first grip), Tab/Shift+Tab walk and hand the key back to the shell past either end, Escape cancels the open change (action) and returns the keyboard to the viewport; plain arrows stay nudges.
- `LaneOverlays::of_frame(frame, domain)` reads the focus and the platform prefs; the ten `viewport` windows use it instead of `LaneOverlays::default()` (so `focused` and `prefs` are no longer always default).

## Honest limits
- F2 is not implemented: the framework has no verb to focus a control inside a row. The cell is reached by Tab; Enter / leaving the cell commits (`commit("blur")` policy) and Escape follows the framework input (not verified to revert). Needs a framework `focusControl` verb.
- The React target (`targets/⚛️react`) does not consume the shell hook seam at all (only the Rust shell calls hooks); parity is the wgpu browser host (TS chain above) versus the native winit host.
- Repaint on focus change: the viewport body is re-rendered from state; focus lives in a registry (like `CURRENT_SHEET`), so a body memo keyed only on document/transient could show the cross one render late. The hook returns `Consumed` (shell settles); not verified.
- Marker lookup uses all diagrams (`focus: None`); a focused diagram set with ids not in that set would not commit. Windows reduced-motion uses `MinAnimate` (registry value of "animation effects"), not `SPI_GETCLIENTAREAANIMATION`; unverified on a real machine. Linux covers GNOME settings only (KDE not read).
- Compile risks to look at first: `Key` pattern `Key::Tab` in `handle_key`, `control_row`/`bind_on` reachability from visual-chrome, `bound.into()` for the input builder, `ShellPlatformPrefs` in a `const` of host-base, `semio_framework::PluginShellHooks as _` in the macro, `memo_diagrams(..).to_vec()`.
