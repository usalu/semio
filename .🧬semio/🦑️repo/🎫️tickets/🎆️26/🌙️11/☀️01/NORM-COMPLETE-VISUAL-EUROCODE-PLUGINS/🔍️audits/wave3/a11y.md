# W3-A11Y report (2026-11-03)

Static work only: no cargo/rustc, no `repo run`, `freeze.txt` absent at every edit batch. "- ready for rebuild: a11y" appended to all ten `build-en19xx/latest.md`. Nothing here is compile-verified.

## Audit: what already existed
Handles were sliders with name, value text and range; Tab walk, arrow nudges (Shift x10, Alt x0.1), digit entry, Enter commit, Escape abort existed in the drag statechart; live region had coalescing and politeness; themes resolve high contrast; playback honours reduced motion.

## Gaps found and closed (all domain-neutral, in `app-surface`)
1. **Nudge step was not the field's schema step** (snap increment / grid / 1 % of span). `direct-manipulation/snap`: new `schema_step(handle)` (quantise Round step, Int = 1, smallest gap of a Choice list, one decade fraction, divided by the slope of the affine map; none for tokens/unquantised). `nudge_step` now prefers it, then increment, grid, 1 % span. This is what makes the ~100 gauge grips step by exactly one schema step.
2. **Enter did nothing on a focused grip** (and Enter/Escape were unbound in the handle scope, so the shell ignored them). Statechart: Enter on a hovered/focused numeric grip opens the inline value field pre-filled with the shown value (`entry_field_text`, 12 significant digits), typing/Backspace edit it, a second Enter commits (one `setFields` = one undo step; an unchanged value commits nothing), Escape closes it without trace, token grips open no field. Shortcuts: `ConfirmHandle` (Enter) and `CancelHandle` (Escape) in the handle scope, action ids `norm.handle.enter.normal` / `norm.handle.escape.normal`, dispatched as handle keys, routed Local. The field is the existing inline dimension-line entry (caret), so pointer and keyboard share the one preview/commit path.
3. **Slider node** (`screen-reader::handle_node`, new `utilisation` argument): value, `aria-valuemin/max` now in the unit of the bound field (they were in handle units while the text was in field units), token grips speak the chosen token label, value text appends the live utilisation of the bound check ("50 cm, utilisation 83 %, passes" / DE), help text mentions Enter opens a value field. `viewport_nodes` passes the governing utilisation of the grip's entity. New `handle_value_text`.
4. **Polite announcements**: `live_region::announce_handle` (key = handle, so a run of nudges speaks only the latest value; always polite).
5. **Diagram markers**: `diagrams2d/marker-grips` turns a marker with a `binding` into a `Handle` (`marker:<diagram>:<marker>`, named by the marker label, limited to the domain of the axis in the field's unit), `marker_rest`, `marker_utilisation`, `marker_status`. Same keyboard path as 3D grips. `diagram_window_nodes` now also publishes one slider per bound marker (EN/DE name, value, range, live utilisation). `marker_row_commit` (entity-editing typed entry): a value typed into the marker's table-twin row (`350 cm`) goes through the same statechart and yields the same single commit as a drag (unit-aware, clamped, quantised, no write if unchanged).
6. **Overlays**: `lane_overlays::grips(handles, &GripView)`; the keyboard-focused grip gets a cross marker (focus not told by colour alone), forced colours / more contrast draw all grips in the strongest tone; `LaneOverlays` carries `focused` and `prefs` (A11yPrefs); the ten editors' viewport files forward them (`..view.lanes`). Grips have no animation in the framework, so reduced motion has nothing to switch off (unit-tested as "output identical").
7. **Node contract** (`assert_default_document_nodes`, called by every editor): checks the marker sliders (role, EN/DE name, value text, range, utilisation text); `NodeCounts.markers` added.

## Honest limits / open
- Arrow-key cycling between grips: Tab/Shift+Tab walk the grips of the selection (existing); arrows stay nudges (a conflict otherwise).
- The marker table-twin rows are still read-only tree items in the rendered window: the command path (`marker_row_commit`) and the a11y nodes are done, the editable cell widget in `diagrams2d/window` is not (needs a UI control with a commit action; not touched blind). A marker's bound coordinate is taken from the first axis in the unit of its binding (ambiguous only if both axes share a unit; `marker_grip(.., marker)` callers with the document can override the rest value).
- `rest_parameter` of non-along-axis grips is still the lower limit (pre-existing); the announced value there is the field value at that parameter, not the live document value.
- The slider name stays the field label; the unit lives in the value text (changing the name would break the node-contract equality with `accessible_name`).
- Wiring of `LaneOverlays.focused` / `prefs` from the shell (focus state, platform media queries) belongs to the host; the hooks and defaults exist, nothing populates them yet.
- Third-party validation (AGENTS rule) not added for these laws (no external a11y oracle in the Rust test setup); the WAI-ARIA 1.2 role check (existing) covers the roles.
- Compile risks to look at first: `crate::diagrams2d` re-export reaching `entity-editing/typed-entry` and `node-contract`, `base_id` from `projection_kit` in visual-chrome, `{:?}` of `World3dAnnotation` in the lane-overlays test, `FieldWrite` in scope of the typed-entry file, `ChoiceToken` import in the drag-tool test, `Lang` used with `==` in the stamped law.
