# History native continuation custody

The original Store command has no resident native-call failure slot. Its report close can produce a live boxed erased retirement owner, or a typed VcsError, while the original native continuation may independently refuse context or the Job return-budget receipt. A four-field NativeDecodeCallFailure retains output, operation error, context refusal and receipt refusal together. The output type contains Box<dyn ErasedSnapshotRetirement>, which is not covered by the generic sized Box RetireOwned implementation.

A complete migration must prequote and keep a typed slot in the original command frame before the native call, retain the entire envelope immediately, and then separately fund its original boxed ticket close, error-owner retirements, and final inline slot handoff. It must preserve the enclosing receipt and actual native work even on refusal. StepContext retirement work-recipient installation and outstanding reservation recovery are still in flight; assuming a fresh ledger, minting a local marker, or reducing any one of these owners to display text would not preserve custody. No implementation or native acceptance is claimed.
