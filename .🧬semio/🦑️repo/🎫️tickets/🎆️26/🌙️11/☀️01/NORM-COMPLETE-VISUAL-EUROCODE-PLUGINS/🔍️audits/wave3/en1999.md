## 1. Gauge versus e2 (fixed at the source, with tests)
- Problem: `bolting()` passed `b.gauge` as `e2` to `bearing_resistance` and `block_tearing`, and the check `en1999.8.5.gauge` bounded the gauge by 1.2·d0 as if it were an edge distance, while the scene draws the gauge as the spacing between bolt lines (`across = gauge·(n-1) + 2·edge_distance`, so `edgeDistance` is the distance to every plate edge).
- Table 8.2 definitions now used (`CHK/📏️parts/🧩️joints`): e1 = end distance along the load, e2 = edge distance across it, p1 = pitch along the load, p2 = spacing across it. The model has one `edgeDistance`, so e1 = e2 = `edgeDistance`; `bearing_resistance` and `block_tearing` are fed `b.edge_distance` for e2 (signatures unchanged, doc comments name the roles); `en1999.8.5.edge`/`emax` are titled "e1, e2"; `en1999.8.5.gauge` is now "Spacing p2 ≥ 2.4·d0" (new constants `MIN_END_EDGE_D0`, `MIN_PITCH_D0`, `MIN_SPACING_D0`), 0 for a single fastener per row. **The 2.4 for p2 is recalled from the printed Table 8.2 and is not verified against it** (no copy in the repo; doc comment says so) - please check it when the standard text is at hand; `pitch` (2.2·d0) is unchanged.
- Consequences handled: compliant sample `default_bolts` gauge 0.018 -> 0.036 (33.6 mm needed for M12); `gen1999.py` `calm()` gauge 0.03 -> 0.036 and the committed `calm-pass` fixture; Python compliance oracle (`SUB/🔮️oracles/⚖️compliance/🐍️.py`) switched to the same definitions; feature rows recomputed with the oracle (`🧪️tests/🚦️check-outcome-en1999-1/🥒️.feature`: fail-06 2.1, pass-87/fail-88 block, pass-89/fail-90 bolt, pass-95 0.9333, pass-104/fail-105 vt, pass-112 sls-freq; no status flips; fail-113 unchanged).
- Tests: `e2_08c_the_bolt_checks_read_e2_from_the_edge_distance_and_p2_from_the_gauge` (bolt/block/tension/vt/edge/emax independent of the gauge, gauge util = 2.4·d0/gauge, shrinking the edge distance raises block, single fastener per row -> 0) in `CHK/../🧪️tests/⚖️compliance/🔬️resistance-worked-examples`.

## 3. Shell (EN 1999-1-5) buckling mode ghost in 3D
- `eigen::shell_axial` / `shell_half_wave` / `shell_profile` (`SC/🌀️eigen-modes`): classical axisymmetric (Lorenz) pattern of the axially compressed cylinder, half-wave λ = π/k with k⁴ = 12(1-ν²)/(r·t)² (= 1.728·√(r·t); ν = E/(2G) - 1), the minimum of N(k) = D·k² + E·t/(r²·k²) whose stress E·t/(r·√(3(1-ν²))) is the 0.605·E·t/r of `sigma_x_rcr`. Repeated in whole half-waves over the governing (longest) ring bay; a bay longer than 4 half-waves shows the first four from the bay start (localised pattern, zero elsewhere).
- `tracks`: new `Mode::Shell`, layer `mode-shell` (EN/DE), `MODES` has 4 entries; `kit::LAYERS` 14. `tracks::push_shell_mode` adds `<shell>:mode-shell` (shell with a generatrix refined at the pattern nodes) with a `DeformationOverlay { surface }`, harmonic, `load_factor = σ_x,Rcr(bay)/σ_x,Ed` from `en1999.1-5.buckle.<id>`. The surface samples sit on the 48-segment mesh of the viewport (49 columns, chord-length arc coordinates), radial deltas only. The overlay index is re-assigned by `tracks::finish`, so the mode track gains a fourth keyframe whenever a shell exists.
- Tests: wave3 `the_axial_shell_pattern_has_the_lorenz_half_wave_and_the_bay_window`, `every_shell_gets_a_buckling_mode_sibling_with_a_surface_overlay_and_the_critical_load_factor`; oracle `shellModes` (scipy `minimize_scalar` of N(k) vs the Rust half-wave to 1e-6, classical stress 0.605 within 0.2 %, 1.728·√(r·t), every sample displacement recomputed).
- Limits: axisymmetric pattern only (the chessboard mode has the same classical load but no closed form of its own here); ring stiffeners are not drawn as nodal circles; the HAZ/imperfection reduction is not part of a mode shape.

## 4. N_cr,T section constants versus sectionproperties
- Finding: the 20 % was loose, not a model error. `section_geometry` takes I_t and I_w from `solid_constants` (the FE kernel `mechanics::analyse_section`, kernel test `finite_element_constants_match_sectionproperties_within_half_a_percent` for the sharp channel and I), A/I_y/I_z are the exact polygon formulas (also for the sharp channel), and `n_cr_torsional` and the scene system use the same constants, so check and ghost agree. The thin-walled idealisation (`thin_walled_idealisation`) is only used by the worked example E2-07.
- Measured on the oracle side (sectionproperties, I and channel 140×70×10×8 and 80×50×3×3, L = 6 m): J on the old mesh (area tf·tw/2) is +1.5 % (I) / +0.8 % (channel) above the converged value, N_cr,T +1.5 % / +0.8 %; tf·tw/8 gives +0.16 % / +0.04 %. Hence the oracle mesh is now tf·tw/16 (about 0.05 %).
- Oracle (`SC/🔮️oracles/🐍️.py`): the payload now carries the constants Rust used (`a, iy, iz, it, iw` per section plus the section dimensions) and also a synthetic channel built from the first I member (the document has no channel). Tolerances: A, I_y, I_z 1e-6 (exact), Euler loads 1e-5 (was 2 %), I_t and I_w 2 %, i0² 2 %, N_cr,T 2 % (was 20 %), shear centre offset 2e-3 of the section size (the kernel test's bound). **I could not run Rust, so the 2 % is the committed kernel bound (0.5 % against sectionproperties) plus the oracle mesh error, not a measurement of the compiled code**: the failure messages print both numbers, tighten to the measured agreement after the first run.
