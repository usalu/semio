## 1. `focusRowControl` (domain-neutral, schema-first, both hosts)

### Schema / names
- Rust `manifest/actions/utility-tool-and-document-actions`: `FOCUS_ROW_CONTROL_ACTION_ID = "focusRowControl"`, `FOCUS_ROW_CONTROL_ARG_ROW = "rowId"`, `FOCUS_ROW_CONTROL_KEY = "F2"`, `FOCUS_ROW_CONTROL_EDITABLE_KINDS = [text, longText, number, date]`, `RowControl {id, kind, disabled}`, and the shared rule `plan_row_control_focus` (first enabled control of an editable kind, else `None`). Re-exported from `semio_framework` (both lists in `packages/rust`).
- TS twin in `definitions-action-ids-and-shell-brand` and the manifest entry (`FOCUS_ROW_CONTROL_*`).
- Language-agnostic fixture `Shell/tests/fixtures/focus-row-control/fixture.json`: names, key, editable kinds, 7 plan rows, 3 F2 origin rows (row / cell / outside), EN+DE refusal announcements, 4 cell rows (Escape reverts text/number to the committed value and dispatches nothing; Enter commits text/number).

### Rust shell
- Retained engine (`retained-ui-engine/accessibility-dispatch-and-focus`): `retained_row_controls(row_key)` (controls of a tree row from the retained document, nested rows excluded, kind names = the fixture's), `retained_focused_row_key(window, node)` (`Some` only while the focused node is a tree row itself).
- `framework_focus_row_control` (dispatch-action/layouts): intercepts the verb in `dispatch_action` next to `focusWindow`, plans with `plan_row_control_focus`, queues `PendingRowControlFocus` (new field `ShellInputState.pending_row_control_focus`, initialised in the single snapshot initializer); a row nobody presents or without an editable cell is announced politely (`row.control.refused`, EN "This row has nothing to edit" / DE "Diese Zeile lässt sich nicht bearbeiten", code `shell.row-control-focus.refused`, Warning) and returned as Err. A success is not announced: the focused field announces itself through the accessibility tree (an extra notice would double-speak).
- `PointerCtx::apply_pending_row_control_focus(input)` sends the same accessibility `Focus` event a screen reader would (`handle_accessibility_event`), which opens the field's draft on the committed value and makes its window active; it runs after the F2 path and after a hook `ShellKeyOutcome::Verb`.
- **F2** (`PointerCtx::row_control_focus_request`, in the idle key path before the plugin hook): bare F2 while the retained keyboard focus is a tree row dispatches the verb with that row's key. It is framework-level, so every app (the diagram table twin of all ten Norm editors) gets it; nothing in Norm changed for F2.
- **Escape** needed no new code: the retained wgpu field already implements the shared text keyboard law (`revert_text_draft`: Escape on a blur-committing field drops the draft, shows the published value, dispatches nothing). The Norm hook only claims Escape in Handle scope (grip focused), so it cannot swallow the cell's Escape. The marker cell is `commit("blur")`, hence a draft field.
- Tests (written first): chrome-parity `focus-row-control/rs` (consts + plan rows against the fixture; refusal in en and de with notice text/code/severity, nothing queued; missing argument), `mirrored-number-and-text-keyboard-laws` (new `a_row_cell_reverts_to_its_committed_value_on_escape_and_commits_on_enter_like_the_language_agnostic_rows` reading the fixture through `fixture_text!`, 9 `..` from the companion crate).

## 2. React consumes `platform_prefs_changed` and the grip focus

## Honest limits
- Nothing compiled. Rust risks to look at first: `PendingRowControlFocus` referenced by name from the actions crate (declared beside `ShellInputState`, assumed to resolve like it); `record.key.as_str()` / `record.children.iter()` / `record.id.0` on the retained document records; `semio_framework::GripRef...` re-export names in both `packages/rust` lists; `fixture_text!` path depth (9 `..`).
- The Rust engine side of F2 (`retained_focused_row_key`, `retained_row_controls`) has no dedicated test (it needs a mounted retained window with a tree row); the plan rule, refusal and Escape/Enter laws are pinned. The success path (focus actually landing) is not exercised in Rust tests.
- Rust Escape keeps focus in the reverted field (shared law `revert`), the React `Input` blurs it after reverting; the value contract is identical and fixture-pinned, the focus difference is pre-existing and not in the fixture.
- A palette/menu raised `focusRowControl` (no key event) queues the pending focus but the pointer context applies it only on the next F2/hook-verb path; there is no input state in the action context. A drain from the frame pump is the follow-up.
- React row key from DOM id uses the text after the last `/`; a row key containing `/` would not round-trip.
- React viewports must state their grips as `data-grip-*` elements for the grip walk and cross to appear; the existing Norm viewport is a canvas painted by the Rust overlays, so the React cross renders only where a host states the grips. The CSS and the walk are in place; stating them from the Norm React viewport is not done.
- Not converted: the `.feature` files of shell-hooks/accessibility were not extended.
