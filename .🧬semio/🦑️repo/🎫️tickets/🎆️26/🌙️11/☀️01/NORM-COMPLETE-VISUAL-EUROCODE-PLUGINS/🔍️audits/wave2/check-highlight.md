## 🧭️ Finding
The audit proxy (literal id in scene code) overstated the gap. Almost every check already carries `subject.entity_id` = its row id (en1992 52 assess sites: members/anchors/cases; en1993 82: member/joint/... rows). Real holes are few and typed: (a) empty or collection-level subjects, (b) subjects that are rows of a collection without a scene entity (sections, materials, grades, placements), (c) document-level checks (`SubjectRef::whole`, `project_id`, `annex`, `site.*`), (d) scene modules that colour a sub-entity only by a family prefix, so a failing check of another family never reached the body. The result schema is unchanged (`SubjectRef` already has `entity_id` + `path`); the owner is a post-evaluation step.

## 🏗️ Design
1. Compliance core `✅️check-results`: `Owners { collections, document_level, filed }` with `Owners::file(&DslValue, &mut CheckReport)`. Owner of a check, in order: the subject when it is a row of an owning collection; the owning row whose id the check id embeds as a dot-segment run (longest run, then leftmost); the first owning row that names the subject row in a field (a section/material row is owned by the member that uses it); else none, which clears the subject for a documented document-level id prefix and leaves it as emitted otherwise. `Owners::ROWS` (default), `Owners::AS_EMITTED` (en1991 files its own aggregates with `report_owner`).
2. `⚡️incremental-evaluation`: `UnitSource::OWNERS` (default `ROWS`), applied in `evaluate_units`, `EvaluationSession::merge` (uses the retained `DslValue`), new `owned::<S>()`; `incremental_laws!` compares fold/session/live against `owned(full)`. So checks window, selection mirror (check -> entity and entity -> check), outliner badges and the scene all read the same owner, live.
3. Structural-scene `projection_kit::highlight`: `highlight_owners(fragment, report, part)` colours the main entity of every owner by its worst check (most severe, then highest utilisation; never softens a binding a module set; reseals the content hash) and, for `Part::All|Global`, adds one label `global-checks` ("n document-level checks, worst u" / DE) for checks filed under no entity. Also `worst_by_owner`, `global_badge`, `audit_owners`, `ownership_audit` -> `OwnershipAudit { orphans, unlit, global, badge }`.
4. Wiring (one line per artifact, `fragment()`): en1990 .. en1999 `highlight_owners(out.into_fragment(), input.report, part)`; en1992 also `build()`; en1991 `project()` now uses `scene_report(input.report)` like the live path. Live and full paths share `fragment()`, so incremental == full is kept.
5. `OWNERS` const in both `UnitSource` impls (`...Units`, `...Family`) of all ten artifacts (collections = scene `ENTITY_KINDS` collections + `cases`; en1991 `AS_EMITTED`). Documented document-level prefixes: en1990 `table-2.1.`, `a2.working-life`, `a2.traffic-groups`, `members`, `annex-b.`, `annex-c.beta`, `input.`, `integrity.`; en1992 `annex.`; en1993 `empty`; en1994/5/6 `subject.empty`; en1997 the six `*.na`, `gk.category`, `governing.`; en1998 the eight `*.na`, `cancelled`, `site.`; en1999 six `*.empty`, `ref.`; all `integrity.` (id-only integrity checks without owner).
6. Emitter fix: en1997 `6.6.tilt.*` subject "footings" (a collection name) -> first placed footing id.
7. Law test per artifact `✏️editor/🧮️incremental/🧪️tests/🧭️ownership/🦀️.rs`: for the incremental-law demo documents, files the report (`evaluate_units`), draws `live_scene_of`, and asserts `ownership_audit(...).is_clean()`: every check has a scene entity or design case as owner or is a documented global check, a failing check lights its entity (Fail binding), and global checks show the badge.
