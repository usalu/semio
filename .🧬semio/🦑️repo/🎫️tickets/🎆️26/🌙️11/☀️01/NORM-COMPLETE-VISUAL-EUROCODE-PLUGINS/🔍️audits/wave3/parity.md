## Top 10 gaps, ranked

1. **`deleteEntities` has no TS implementation.** Multi-delete is user-facing and the Rust side is complete. The shared fixture row exists, but the TS check only counts routes and never executes the delete. Fix: a TS twin of the delete reducer plus a shared row in an executable fixture, or a schema verb in JSON/TS.
2. **Grip focus is Rust only.** No TS, no fixture, no schema. Keyboard access to grips is a11y-relevant on web and in the React shell. Fix: a `grip-focus` pure-state twin plus a language-agnostic walk fixture (Tab, Shift+Tab, Ctrl+Arrow).
3. **Marker cells are Rust only.** The marker value cell (typed value, unit, commit on blur) has no TS twin, no fixture and no schema. Fix: a `marker_cell_id` and commit-rule twin plus a fixture of id and commit cases.
4. **The context-menu keyboard trigger is missing in the TS shell.** `KeyAction::ContextMenu` and Shift+F10 are only handled in Rust. The TS menu opens by pointer only. Fix: a TS key mapping for `ContextMenu` and Shift+F10, plus a row in `🚶️shell-interaction/🔣️.json`.
5. **`focusRowControl` does not exist.** Nothing in tracked code uses the name, so either the ticket names a symbol that was never implemented or it was renamed. Fix: confirm the intended symbol, then implement it on both sides with a fixture.
6. **Latency scenarios do not share a list.** TS drives six scenarios from `⏱️interaction-latency.json`. Rust `latency-bench` only measures `cold-drag` and `cold-evaluation` and never reads the JSON. Fix: one scenario fixture read by both, with the same ids and bounds.
7. **`pinch_navigation` wheel and pan units have no TS twin or fixture rows.** Only `applyPinchToOrbit` is shared. Fix: a TS `pinchNavigation` plus wheel and pan rows in `touch-session.json`.
8. **`ShellPlatformPrefs` has no shared fixture, and the React ShellHost does not consume it.** The schema twin is fine. Only the wgpu boot descriptor maps the media queries. Fix: a fixture of prefs to a11y effect, read by Rust `a11y_prefs_of` and the TS ShellHost.
9. **The `focusWindow` TS schema twin is missing.** JSON `🖥️shell/🧬️schema/🔣️.json:978` has the verb, but the TS shell schema twin does not. The TS command is hand-written in `🐚️shell/🟦️.ts:361`. This breaks the schema-first rule. Fix: regenerate the TS twin from the JSON.
10. **EN/DE copy lives in duplicate tables with no drift check.** Focus announcements exist in TS `🌐️i18n/🧭️shell-chrome/🟦️.ts` and Rust `shell-vocab/✅️check-in-and-palette-vocab/🦀️.rs`. Their content is identical today, but the placeholder syntax differs and nothing enforces equality. Delete also has two labels ("Delete" in the context menu, "Delete Entities" in the catalog). Fix: one catalog, with an equality law test on both sides.

## Notes and limits

- Static audit. I did not run `cargo`, `repo`, or any test. The "ok" verdicts mean the twin and fixture are wired in source, not that they pass.
- Rust test bodies were not all read. For item 9 the grep for `marker_cells` and `grip-focus` tests was the only test check.
- The `focus-window.json` fixture under `FW/…/🖥️shell/🧪️tests/🧫️fixtures/` has a Rust-only consumer (`🖥️shell/🧪️tests/🔬️unit/🦀️.rs:247`, by name). It has no TS twin.
