## 3. What was implemented (generic, by pattern; no per-artifact paths)
- `core.Names.rename`: word-aligned, context-aware rename (single-word names like `joints` are camel, snake and kebab at once; the form follows the context: kebab next to `-`, snake in Rust paths, quoted-name convention of the file, camel before an upper-case continuation); identifiers that are schema property or definition names are protected (`jointGapM` stays), `_id`/`Id`-style continuations rename. Fixes the dict-collision bug of the old `mapping`.
- `lex.py`: code mask (strings, comments, lifetimes), function bodies, body-level statements and comma/semicolon items for Rust, TS and SQL.
- Schema: diff JSON row groups for both naming families (`En1997LayersRows`, `En1998JointDelta`), Patch defs cloned from the reference Patch (title and node shape kept), reference chosen among collections that own a diff group (falls back to `placements` for en1994/en1996).
- Model: enum cloned from a donor enum including its `impl` blocks (arms regenerated); example literals for every struct literal that sets the reference (`vec![]` or `Vec::new()`); artifact conversions as struct fields, literal items and `use` lists, inline or line per item.
- Diff Rust: row blocks (Key/Patch/Rows/Delta, scalar_patch), `row_key!` lists, per-lane module files with `#[path]` mount and `DIFF_LEAVES` entry (en1994), lane arms (`absorb`, `apply`, `commit_onto`, `is_empty` chain item, `inverse`).
- Wiring: outline (names list and `+ snapshot.x.len()` chain, source = reference or last registered collection), units (only where a `ROW_COLLECTIONS` registry exists), duplicate-id checks (single or multi line, EN + DE singular for the 3-argument form), field-meta rows in all four spellings (`FieldSpec::`, `m(..)`, `m!(..)`, match arms) with learned choice spelling (`choice(..)` or `NormFieldChoice { .. }`, const or inline array), optional kit row.
- SQLite (`l_codec.py`): DDL learned from the reference table (column definition templates per kind, ieee754 pair grouped or interleaved, gaps per role, ids/CHECK spelling), Rust and TS codec statements cloned from the reference with field regions regenerated from item templates learned from the artifact itself (own entity first, then every other entity; the `id` cell is the String template; row variable, column index, enum helper and Binary64 constant abstracted; codec column order may differ from schema order), unique bindings, float/Ieee754 constants, enum helper functions and consts in the artifact's naming dialect, TS row types, import list, `fields([..])` lists, entities width/table index, native admission statement; flattened object properties count as cells. The en1997-style templates stay the first try (validated by `selfcheck.py`), the learned engine is the fallback.
- add-leaf: schema/diff tolerant of missing anchors and Patch defs, Patch field in `set { }`, `Patch for`, plain `struct` forms, example literals by lexing, in-place codec extension (write/read/fields/width/constants/type/admission), field-meta row behind the previous field (skipped with a note when the collection has no rows), DSL assets, idempotent when the leaf exists.
- Mutations: insert/remove kind detection through `InsertItemRule`/`RemoveItemRule`/`IdRemoval` across the whole `🧭️edit-rules` tree; clone with kind pairs for both prefixes, slug spelling of artifact-prefixed entities (`joint` for `En1998Joint`), labels applied before renaming, JSON hint; **error prose** of cloned kinds names the new entity by its singular EN label ("Probe row {key} already exists.", "... past the end of the tie beam list ..."), labels `Insert/Remove <singular en>` / `<singular de> einfuegen/entfernen` (DE with umlauts) and set-field labels `<entity de>: <field de> ändern`. Message ids carry a single English prose string in the framework (`MutationOutcome::fatal(code, message, keys)`), so DE exists for labels only.
- Set-field kinds: `l_setfield.py` clones an existing set-field kind with the same field type (f64, String, u8, u32, enum with token lists) incl. edit rule, registries, binary tag and a fixture family (before/after/diff/mutation/outcome with the sample row). Leaf-kinds drivers (`DRIVERS`, `driver_of`): en1997 keeps the profile driver `en1997.py` (can register entities); en1990..en1996, en1998, en1999 use the clone driver `l_setfield.py` (the older `en19xx_run.py` scripts hard-code their entity lists and cannot register a new entity). Donors missing: en1991 has no enum set-field kind, en1994 none for String (the probe spec for those two omits the type; the tool reports the missing donor).
- Contract (`l_codec.contract`): `schemaBytes`/`tableWidths` replayed with python `sqlite3` from the planned DDL; per-case `valueBytes` grow by `rows * 22` per new finite f64 column (REAL 8 + ieee bits 8 + class `finite` 6; rows from the `snapshot` of the committed fixture, `empty*` cases 0; String = UTF-8 length, integers 8); new empty tables change nothing. The TS test's inline `cases` list is rewritten too. Artifacts without `semantic.json` (en1992, en1998) skip with a note.
- Docstrings of the tool: 98 more got a unique leading emoji (AGENTS.md).

## 4. Tests (`python3 -I test_evolve.py`: 14 tests OK)
Lexer statements and items; context renaming incl. protected identifiers; all ten artifacts plan `add-collection` with 0 unsupported layers; python `sqlite3` executes the planned DDL of every artifact (column count = 4 + fields + 2 * reals); planned Rust and TS codecs name every new field and table; the learned DDL generator reproduces at least 50 committed tables verbatim (measured 74 of 75 tables whose column names equal the schema field names); leaf dry runs for eight artifacts; driver registration; plus the v1 tests (en1997 DDL, contract replay, labels, selfcheck of the en1997 codecs). Helpers: `matrix.py` (in-process matrix), `probe.py` (CLI dry runs), `snapshot.py` (sha1 plan digest for regression diffs).

## 5. Findings
- Stored contracts already drifted from the committed DDL before this change: en1990 `schemaBytes` 12297 vs replay 12534, en1993 54435 vs 54759, en1994 11031 vs 11990 (tableWidths agree everywhere). The first apply on those artifacts corrects `schemaBytes`; their per-case `valueBytes` can only be re-verified by running the artifact's contract test.
- en1998 and en1992 keep no `semantic.json`; en1996 and en1999 etc. do. Table names are not always entity-derived (`en1994_slab` for `CompositeSlab`, `en1991_self_weight*`), the tool resolves entity form, plural-singular form and the longest stem.
- The old per-collection regexes of `l_sqlite.py` wrote partial results before failing; the fallback now restores the plan snapshot before the learned path runs.
