## 2. What was built

- JSON repairs: `insert-traffic-group.index` nullable; `En1990Diff.trafficGroups` and `En1995Diff.decks` required; `En1995Artifact.decks` items `Deck` (records `Deck`, `LaminationProduct`, `PrestressBarProduct` added to the artifact schema); design-case `CaseEntry.geometry` is the record `CaseEntryGeometry`; 14 case-leaf payload schemas (en1990, en1997) declare their `mutation` tag; `x-semio-twin` headers for the compliance and design-case roots; `test-support` feature (+ forwarding by the aggregators) in the Cargo.toml of `mut-wall-seismic-reinforcement`, `mut-traffic-groups`, `mut-traffic-groups-rows`, because the leaf struct template is now `cfg_attr(any(test, feature = "test-support"), ..)` for all leaves (23 files changed).
- Rust root structs (`🦀️rust`): any record with `x-semio-rust.derive` is generated (docs, derive, raw attributes, `artifactSchema`, `#[dsl(keyword|id|layout|unit|table|statements|block)]` from `x-semio-dsl`, `#[state(..)]` from `x-semio-state`, field names/types/docs/attributes); a struct the file lacks is inserted. `annotate` harvests committed structs once and only keeps a record if its regenerated struct reads back equal (attribute order aside); structs it cannot reproduce stay hand-written (`NoConfig`/`NoPresence`, `SpecTrace`, `InputSpec`, `PlateElement`, `En1999Diff`, en1996 snapshot/diff and en1998 structs that were out of step).
- Other generator work: protobuf `enum`s, `uint32/uint64` by bounds, mutation aggregates as `oneof`/`union` plus leaf payload messages, `$schema` skipped for proto/GraphQL, union types (`normWireAny`), `Tagged` readers only when every payload declares its tag, import fix for property-pointer references, `typescript.contractFile` for the shared compliance twins (relative contract import kept), headers say `repo ./📜️script.ts schema twins generate`. Modules owned by another projection (`🤖️ Generated by`, `//#region 🚪️Parsers`, every `🎚️config` / `👥️presence` lane) are never touched. A record the generator cannot type is reported as a `problem` and left alone; the rest of the run completes (check and generate exit 1).
- Gate: the bun test `schema sync` is strict (`runTwins check`: 0 drift, 0 style, no problems; baseline file deleted). Checker change: protobuf enum members are read with their own enum-name prefix, non-identifier properties (`$schema`) are not required in proto/GraphQL.
- Tools converted (JSON first, then `schema twins generate`, no twin or generated struct edited by hand): `schema_twins.py` (layout-preserving `edit_schema`, `add_field` with dsl/state/doc/rust, `add_record`, `compact|indent` normaliser), `field_adder.py`, profiles `en1990`, `en1996` (wall fields and collections), `en1997`, `en1998` (`en1998_root.py`, `en1998_rows.py`), `new_collection.py` (en1991 template, self-test copies compliance and the dialect). The four `new_collection_en1998*.py` are applied one-shot scripts of earlier waves: they now refuse to run. Not run end to end (no builds; `py_compile` and the library test only).
- CRATE-BUDGET G request: every writer preserves the layout of a schema file (diff and aggregate schemas stay compact; `generate` never writes JSON; `new_collection.diff_json` writes compact); `compact-schema-json.py` is deleted; `schema_twins.py compact FILE` converts if ever needed. ## 3. Content differences against the committed twins (391 files, `classification.txt`)

The classification tags each differing file with the checker verdict on the committed unit; the checker only judges field sets, optionality, types and enum members, so many stale twins show as "not flagged". Classes:

- Committed twin stale or broken (generated agrees with the JSON, committed does not): ts imports of names the sibling twin does not export (23 files + 14 declaration lines of case leaves, plus the compiler errors above); schema optional/nullable fields the committed readers require (24); readers that default a field the schema leaves optional (8; en1997/en1990 diff patches, flagged by the checker); declarations the committed twin lacks, new types and payload messages (about 45: trafficGroups, decks, `NdpAnnexVerification`, reliability class, ...); types the schema no longer produces (about 28, e.g. `En1996Wall`, `FireOccupancy` renames); readers keeping a map or untyped value where the schema names a record or enum (5); readers without the integer bounds of the schema (19); serde derive of 23 leaf structs gated on `test` only (project standard is `any(test, feature = "test-support")`); 13 other Rust text differences (new leaf/roots of the en1990/en1995 owners).
- Convention (both pass the checker, generated is the typed rendering of the JSON): 242 proto/GraphQL files where the committed twin lowers records and lists of records to `string`/`JSON` blobs and enums to `string`, the generated twin has typed messages/enums/unions; 10 proto integer widths (`uint32/uint64` follow the bounds). These do NOT meet the "stale or broken" criterion literally; they are the canonical rendering and are listed so the coordinator can veto (the alternative is a blob-lowering switch in `🛰️protobuf`/`🔗️graphql`).
- Pure layout (import order, header text, whitespace, attribute order): 1730 files, not content.
