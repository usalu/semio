# IO Failure Node Continuation

The current IO decoder collects decoded retirement nodes and the accumulated child in FailureFrame, then allocates and attaches every parent inside one callback. Its direct OriginalFailureStorage::admit call has no resident actual marker and is intentionally not adapted with a local replacement. The canonical OriginalFailureStorageBirth and its marker live in the original NativeDecodeRetirementRecipient; its pool receives the actual node before work proof and post.

NativeSnapshotDecodeOwner::receive currently invokes its operation once and then retires inputs and publishes output. Its retained frame after failure is a cleanup owner, not a resumable semantic operation. IoError receiving invokes this same one-shot path. Therefore a Pending birth cannot safely restart the whole wire decode or be reported as a completed NativeSnapshotFailure. The IO path needs a caller-owned staged failure decode cursor, including source lifetime while partial wire parsing is active, then retained node index and owned field slots after parsing, and a separate pool-take/attach action and final publication. A post refusal must retain the pool node and all input owners while preserving both physical and work receipts.

The two direct IO fixture allocator calls now retain a caller-owned actual marker and check Some(exact birth bytes) against the actual physical receipt.
