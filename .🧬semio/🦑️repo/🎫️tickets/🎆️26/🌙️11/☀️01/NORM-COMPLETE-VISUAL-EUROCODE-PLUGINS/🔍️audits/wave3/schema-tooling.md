## 1. Nested collections (what was measured, what exists)

So the artifacts do not split into "separate" and "inline" families; they share one shape. The pair clone is therefore one mechanism for all seven, not two. Test `test_nested_shapes_are_measured_on_statements`.
- Not implemented: the SQLite pair clone (parent write statement with child loop and `let id`, child groups declaration before the parent consumption, parent read loop with child `Vec`, bound/admission per-parent counting loops, TS counterparts, admission field ids). ### Design as built (`l_nestedsql.py`, called by `l_codec.run_collection` for a spec with `nested`)
1. DDL: parent and child are flat-cloned (`ddl_generic`), the child's `document_id` reference becomes `<last word of the parent table>_id INTEGER NOT NULL REFERENCES <parent table>(id)`.
2. Rust and TS: `rust_generic`/`ts_generic` got `target`, `merge`, `capture`. The child is cloned from a flat reference in capture mode (statements returned, not inserted), the parent is cloned normally and the hook merges the child statements in: write loop (`let <id>=..insert(..)?;` + child loop over `parent.children` with fresh variables, `Cell::Integer(<id>)`), bound loop (child loop in the parent's bound loop), per-parent counting loops cloned from the donor parent's counters (`for v in &self.donors{add(v.children.len())?;}`, also `add(add(rows,a.len())?,b.len())?` reduced to the one child), reads in either dialect (`groups(entities(..),&parent_rows,c)` + `ordered(groups.remove(&p.rowid)..)`, or `siblings(&groups,p.rowid)`, TS `Groups.get(p.rowid)??[]`, fresh element variable because `for(const v of f(v))` is a temporal dead zone), the child vector as a member of the parent record, parent row type gets `probeReadings: ChildType[]`.
3. Native admission: the flat clone becomes `let v=n::record(v)?; let parent=n::entity(..)?;` + child loop, the row counter learns the parent rows (unless a `for id in a..=b` range covers them) and the child rows.
4. Diff layer: `key_and_macros` (en1997 names) is tried first; on `Unsupported` the artifact-generic `nested_family` clones the donor child's group (by entity names, else by the composite `<Parents><Children>` names of en1999, else the nested array is a `Vec` member of the parent `set`), then the donor parent's group with its `nest { lane: Delta }` retargeted, then the lane lines of the flat reference.
5. Mutations: when the donor parent edits its nested rows as a whole array (no insert/remove kinds for them) the child gets no kinds either (note in the plan).
