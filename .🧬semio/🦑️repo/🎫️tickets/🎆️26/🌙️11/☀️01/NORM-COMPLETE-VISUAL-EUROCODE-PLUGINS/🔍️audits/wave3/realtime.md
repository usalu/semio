# W3-REALTIME: live-path review and fixes (static, nothing compiled or run)

Gates: drag p95 <= 12 ms, commit to checks <= 400 ms. Rebuild requests are in `build-en1990..en1999/latest.md` and `build-mechanics/latest.md`.

## Fixed (shared)
1. **Read hashing (compliance, `incremental-evaluation/read-tracker`, `session`)**: `read_hash` allocated a `Vec` per read path and a `String` per visited key, walked every array item for a numeric segment (`members.12` scanned all members, so n row units cost O(n^2)) and re-hashed shared reads once per unit. Now `ReadHashes` walks without allocation, indexes arrays directly, and caches one hash per declared path per document revision (reset in `rebuild`). `read_hash` keeps its signature. The session no longer clones a `CheckUnit` for units whose memo is valid (`advance`, `fetch`).
2. **Scene kit fingerprints (structural-scene `scene-kit`)**: `row_texts` formatted every row of the document with `{:?}` on each full pass. Now a structural FNV over the value tree, one `u64` per row; stamps combine hashes. Same dirtiness semantics (own rows, named rows, global).
3. **Projector run (`projection/🦀️.rs`)**: `canonical_json(eval.of(id))` was recomputed for each entity, each dependency and the global key, and `eval.of` cloned an `EntityEvaluation` per entity even on cache hits. Entity keys are now computed once per run (`eval_keys`), the evaluation is cloned only on a miss, and the key text no longer clones fingerprint and context key per entity.
4. **`LiveScene::scene`** (the production path) no longer deep-clones the whole scene into `previous` (new `SceneProjector::project_untracked`); `follow` skips the evaluation roll-up and the `Evaluation` clone when the report index did not change. `preview`/`project_delta` unchanged; one law test adjusted (`the_declared_module_serves_editor_and_viewer_from_one_projector` no longer expects an empty delta right after `scene`).
5. **Diagram windows (all nine editors)**: every repaint recomputed every diagram of the document (en1997: slip circle with 168-circle grid search plus a 42-bishop centre sweep, M-phi curves, frame envelopes), and the focus fallback computed them twice. New `projection::memo_diagrams(variant, document, report, key, compute)` (shared slot per variant and focus key, 32 slots) wired into the nine `windows/diagrams` files. A drag still recomputes (document changes per tick); repaints, hover, fallback and second windows are free.
6. **Drag tick (`editor-wiring::lane_events`)**: `placements_of(document)` (clone of all placement rows) per tick, now only when the preview contains placement writes.

## Fixed (kernels)
7. **Slope slices (mechanics `slope`)**: `ground()` evaluated `tan` twice per scan step (4001 steps per circle, 168 circles per grid search). Now `Ground` (tan and run once), and the first/last inside point are found by scanning from each end until the first hit (identical x values and results, no full scan unless there is no sliding mass).
8. **EN 1993 frame**: `shapes_of` (sway eigen mode, combinations, case results, envelope) ran once per bar/node fragment, i.e. N full frame solves for one edit. Now `shared_shapes` (one slot, compared to the snapshot). `combination_results_cached` now compares the inputs in place (it built a `{:?}` string of nodes, bars, members, sections, materials, joints per call, once per member check) and is used by the frame scene and the design diagrams instead of the uncached solve.
9. **EN 1998 `RcMember::section_response`**: the fibre `characteristics` (about 2 x 100 force balances of 60 bisections each) was recomputed by the check, `effective_stiffness`, `yield_neutral_axis_depth`, `moment_curvature`, the capacity scene and the bridge view. Memoised per (member, coefficients), 32 entries, thread local.

## Findings not fixed (need an owner decision or a compiler)
- **Fibre kernel cost**: `balance` = 60 bisections x full fibre integrate; `characteristics` has an outer 60-step bisection over curvature, so about 12 000 integrates over 120 to 400 fibres, estimated 50 to 150 ms release. Fits the commit budget, not the drag budget. Replace the bisection by a safeguarded secant (Illinois) with a warm start from the previous curvature; changes results in the last digits, so the oracle tolerances (3e-5) must be rechecked.
- **Scene assembly clones**: `merge` deep-clones every `SceneEntity` of every fragment per project; `SceneMemo` clones document and report per revision and diffs the whole scene. Real fix: `Arc<SceneEntity>` in `Fragment`/`StructuralScene` (schema change), then `merge` is pointer copies.
- **Drag overlay**: `LiveView::over_lanes` does `to_value` + overlay + `from_value` of the whole document per pointer tick; the base tree could be kept per drag (clock-keyed) and only the written leaves patched.
- **`gesture_handles`** projects the committed scene (memo hit, but still `live_report` equality and report clone) every tick; cache the scene-targeted handles per (document, gesture entity, handle) for the duration of a drag.
- **Part units** (`Rows::part`) still read `*`: now hashed once per revision via the cache, but they still re-run on every edit.
- Frame `shared_shapes` is keyed on the whole snapshot, so a placement drag still re-solves the frame once per tick (not once per fragment); key it on the solver inputs once the field list is fixed (it is in `frame-envelope::same_inputs`).
- `ReportIndex::stamp` allocates a `String` per subject per entity; negligible next to the above.
- Diagrams in the viewers (`viewer/.../windows/diagrams`) are not wired to `memo_diagrams` (they do not repaint on view-state alone).

## Compile risks
Closure `eval_key` returning `&str` from captures (projection run); `Mutex::new(None)` static of `(En1993Snapshot, Arc<Option<Shapes>>)` requires `Shapes: Send` (plain data expected); `ReadSet`/`Number` imports in scene-kit (`semio_framework_value::Number`); `&Arc<Vec<Diagram2d>>` deref-coerces to `&[Diagram2d]` in the nine windows; `memo_diagrams` needs the snapshots to be `Send + 'static + PartialEq + Clone` (the retained sessions already require it).

## Round 2 (W3-REALTIME-2, static, nothing compiled)
1. **Fibre kernel** (`mechanics/section/fibre`): 60-step bisections replaced by `bracketed_root` (Illinois regula falsi inside the sign-change bracket, forced bisection every 4th step, 240-iteration cap, stop at 1e-14 relative step/bracket), used by `balance` and the curvature-at-ratio-one search. Cost per balance drops from 60 integrates to about 8 to 15. New `SectionCache` field on `FibreSection` (`cache: Default::default()` added at all 6 constructor sites incl. en1992 section-resistance, en1998 formulas, tests): `balance` memoised per (kappa, N, eps limit) bits, `characteristics` per (N, four limits); lives as long as the section (one document revision), 4096-entry cap. Tests added in `tests/fibre`: random-section property test (40 sections x 6 cases) against an 80-step reference bisection (strain 1e-9, moment 1e-9 relative, same bracket verdict) and a memo repeat test; the concreteproperties oracle tests are unchanged and use the same API.
2. **Scene assembly**: `StructuralScene.entities: Vec<SceneEntity>` is a generated schema record with about 120 consuming files / 178 sites; an `Arc<SceneEntity>` change cannot be made safely without a compiler and generator run. Done now: `merge` reserves the entity vector exactly. NOT fixed: schema change `entities: Vec<Arc<SceneEntity>>` (schema-first, regenerate twins, then `merge` and `diff` become pointer copies / `Arc::ptr_eq` fast paths). Needs an owner decision.
3. **Drag overlay** (`selection-mirror::overlay_preview`): per-drag memo (family, committed document by equality): the committed value tree is built once per drag instead of per tick; each tick patches only the writes whose value changed onto the retained preview tree (full rebuild only when the write path set changes); an unchanged write set returns the cached typed preview with no conversion. `NormFamily::Document` now requires `'static` (needed for the downcast). Remaining per tick: `from_value` of the preview tree (a typed per-field patch is not possible generically; it needs per-family row mutations).
4. **Viewer diagrams**: all nine viewer `windows/diagrams` now go through `memo_diagrams` (variant string = editor `VARIANT`, same key `"\u{0}"` / `"\u{0}|\u{0}"` for en1990), sharing slots with the editor windows.
5. **Compile risks**: the projector closure now calls `key_of<'a>(..) -> &'a str` (explicit lifetime, certain-safe). `Shapes` holds only Vec/String/f64/Option of plain solver results (the only `Rc` is the separate thread-local combination memo), so `Send` holds; `Number` import in scene-kit is valid (`semio_framework_value::Number` is exported, variants UInt/Int/Float match). No change needed there.
