## 🧭️ Method and precision

1. Bilingual pairs: every `label_en/label_de`, `en/de`, `X_en/X_de` pair, and every `FieldLabel::new`, `FieldSpec::{new,quantity,choice}`, `m(...)`, `LocalizedLabel::native`, `LocalizedCopy::new`, `copy`, `loc`, `native` call with two arguments was checked for empty, identical or one-sided text.
2. Hard-coded text: string literals with two or more English or German words that are not an argument of a bilingual pair were flagged. Heuristic, so the counts are upper bounds. Manual spot checks found roughly 1 in 3 "DE-only" hits were false positives (multi-line `loc(&format!(..), &format!(..))` and nested `choice(..)` rows). Treat the counts as a worklist, not a defect count.
3. Snapshot fields: camelCase wire names were derived from every `pub` field reachable from `EnXXXXSnapshot` (`S/🧬️schema/📸️snapshot`). They were compared with the field-meta table or lookup of each artifact. en1991 uses a leaf-segment fallback and en1997 a `lookup_norm_field_meta` table, so their coverage was simulated, not read from a plain table.
4. Not reviewed: runtime rendering, the TypeScript `🟦️.ts` UI, and `📚️examples` beyond their titles.

## 🚨 Findings with highest priority

### 1. EN text is blank in the fire-durability explanation (en1996)
- `A/🪨️en1996/S/🧬️schema/⚖️masonry/🧱️evaluate-wall/🔥️fire-durability-and-reinforcement/🦀️.rs:51` and `:73`
- `.explanation(loc(&text(""), &text(" (tabellarisch)")))`. EN is empty, DE is only a suffix. The user sees a blank EN explanation and a DE-only "(tabellarisch)" tag.
- Fix: EN "(tabular)" or full sentence, DE full sentence.

### 2. Leaf fields resolve to their parent collection label (en1991)
- Lookup: `A/🏋️en1991/S/✏️editor/🏷️field-meta/🦀️.rs:6-13` (`exact(key)` where `key = path.split('[')[0]`).
- Collection rows: same file `:67` (`floors`), `:68` (`selfWeightElements`), `:69` (`roofs`), `:70` (`windFaces`), `:71` (`accidentalCases`).
- 37 leaves are labelled with the collection name, e.g. `floors[].area` shows "Floor areas", `windFaces[].cPe10` shows "Wind faces", `accidentalCases[].impact[].vehicleMass` shows "Accidental cases". Both EN and DE are affected, so the labels are wrong in both languages, not only untranslated.
- Fix: add one row per leaf (EN and DE) and make `exact` strict like `lookup_norm_field_meta`.

### 3. DE == EN for example titles (all artifacts with examples)
- `A/<artifact>/S/📚️examples/<example>/🟦️.ts:3` (`en`/`de` identical): en1990 `high-consequence-office`, en1992 `liquid-retaining-fem-anchor`, en1993 `high-strength-connection`, en1994 `composite-bridge-girder`, en1996 `loadbearing-wall`, en1997 `demo`, en1998 `seismic-rc-frame`, en1999 `aluminium-roof-purlin`.
- These are sample titles, not UI chrome, but they are shown in the document picker. Fix with German titles.

## 🌍️ Framework-level observations

- `🧰️framework/🔨️modules/🖱️ui/🌐️locale/🏷️label/🦀️.rs:92` `LocalizedLabel` derives `Default`, which yields empty strings for every locale and terminology. Nothing forces both locales to be set. Risk: a missing translation is silent. Recommend removing `Default` on `LocalizedLabel`, or a debug-time check.
- `Locale` is an enum with `En` and `De` only. No default locale is assumed in the artifact code reviewed. The only fallbacks are the explicit `Locale::En` sites listed above.
