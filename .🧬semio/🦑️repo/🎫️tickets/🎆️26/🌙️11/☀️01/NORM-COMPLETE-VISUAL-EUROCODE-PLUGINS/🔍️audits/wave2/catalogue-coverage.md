# 🔍 Catalogue Coverage Audit (Eurocode plugins, wave 2)

Read-only audit of `📐️specs/*-target.md` catalogue ids against `✏️s/🔌️plugins/📕️norm/🗿️artifacts/<emoji>enXXXX`. Generated by `🗑️generated/catalogue-coverage/extract.py`, `scan.py`, `report.py` (tallies as ids are matched).

## Method

- **Id extraction**: catalogue ids only, taken from the catalogue section of each spec (entry headers, bold entry lines, table first cells). Visualisation ids (`V-M*`, `V-T*`, `VZ-*`), NDP tables and examples are excluded. EN 1991 ids are `E11..E17`, EN 1990 ids are `E90.xx`. The EN 1994 and EN 1999 spec sections are split at the `## 2. EN 1999` heading. EN 1997 ids are read from the `###` headings of section 2 (ranges such as `PILE-01…09` are expanded).
- **File kinds**: `test` = test, fixture, vector, `.feature` and oracle files. `cat` = non-test file containing `ENTRIES`, `Entry {` or `registry()` (catalogue registration). `doc` = non-test file under `⚖️checks/` or `📋️member-evaluation` that is not a catalogue file (snapshot/member check path). `fn` = all other non-test code (clause library, docstrings, scene, editor, mechanics).
- **Classes**: `implemented-in-document` = id literal in a catalogue file AND in a snapshot/member check file. `catalogue-only` = id literal in a catalogue file only (reachable via `evaluate_case`/`evaluate_outcomes`). `function-only` = id literal only in non-test code outside the catalogue. `function-only (clause-cited)` = no id literal, but the spec clause (first 3-part number of the entry header) is cited in a comment or a clause key in non-test code; this is weak evidence. `missing` = neither, including test-only mentions (listed separately below).
- **Limits**: a literal id match is reliable. Clause citations are noisy, and a clause shared by several ids is counted for each of them. Implementations that carry no id and no clause citation, for example a helper named after the concept, are not detected. Two-part clauses (for example `6.2`) are not used.

## Notes for the reader

- **EN 1993**: no `V-nnn` literal appears anywhere in the artifact. The code is keyed by clause (for example `en1993.6.2.6.*`), so only the clause-cited class can be detected here. The completion audit (`🔍️audits/en1993-completion.md`) lists V-001, V-020..V-027 and others as implemented as functions, and its own line 104 says the engine wiring for V-020..V-027 is still missing. This tool reports V-020, V-023..V-026 and V-001 as `missing` because neither a literal id nor a clause citation was found for them. Treat that part of the table as a lower bound.
- **EN 1994 and EN 1999**: the `function-only` class is mostly literal ids in clause or helper files. `C-02`, `C-32`, `C-46`, `C-50`, `C-51` and `A-01`, `A-03`, `A-10`, `A-13`, `A-26`, `A-30`..`A-33`, `A-40`, `A-41`, `A-50`, `A-52`, `A-60`, `A-62`, `A-70`, `A-80` have no trace in the artifact.
- **EN 1998**: `SEI-01`, `SEI-06`, `SEI-10`, `SEI-46`, `SEI-48`..`SEI-54` have no literal and no clause citation. SEI-51..SEI-54 are capacity-design and overview ids and may be covered by the scene or verifier layer without a catalogue entry.
- **EN 1997**: all 42 ids are literal catalogue entries, but no document or snapshot check reads them, so every id is `catalogue-only`. This includes `GEO-F01..F04`, `SLOPE-01..04`, `PILE-01..09` and `RW-01..10`.
- **EN 1995 and EN 1996**: 67 and 31 ids are `catalogue-only` (T-xx and M-xx entries reachable through `evaluate_case`). No timber or masonry check path reads them at document level.
- **EN 1992**: only `S-04` and `T-04` reach a member check path (`📋️member-evaluation`). The other 154 are catalogue-only.
- **Spec gaps (not artifact gaps)**: `E90.13` and `E15.06` appear only as worked-example ids (`E90-13`, `E15-06`) and not as catalogue entries.
- **EN 1991**: `E13.13` has no literal and no clause citation in the artifact.
