## Disagreements and findings (Rust not changed)
1. EN 1991-1-6 Table 3.1 return period. Spec E16.01 [N]: up to 3 days 2 yr, up to 3 months 5, up to 1 yr 10, longer 50. Rust `stage_return_period_years`: up to 90 days 2, up to 365 days 5, else 50. Showcase stage `short` (30 d, T = 2 yr): oracle requires 5 yr (utilisation 2.5, fail), Rust reports 1.0. The oracle follows the spec; no feature row asserts it. Fix: four-step table. Not applied because the spec notes a modified DE NA table ([V]).
2. EN 1991-1-5 Table 6.2: Rust applies k_sur only to steel decks (other decks 1.0). The standard has columns for the other deck types; values not reproducible from the repo text, needs the print. Oracle follows Rust here (transcription, not independent).
3. EN 1991-4 patch load: registry factor 0.2 p_hf. The standard's 5.2.4 patch pressure is not a flat 0.2 as far as recalled (contains a C_op factor); unverified, oracle uses 0.2.
4. EN 1991-2 LM1 braking uses the mean lane width of all lanes, the standard uses the width of lane 1; oracle uses lane 1. Equal when lanes have equal width (all fixtures). EN 1991-2 alpha factors (registry 1.0, "interim") are NA values to be confirmed.
5. EN 1991-1-4 Table 8.1 d_tot = d + max(parapet, traffic): the oracle copies this reading; the table combines solid parapet and traffic differently (not verifiable here).
6. EN 1991-1-3 drift mu_w floor 0.8 against gamma h / s_k: reading flag `drift-mu-w-reading` (0). Oracle uses the same reading.
7. EN 1991-1-7 Annex D: Rust takes the larger of D.1 and D.2; the text says selection rule unverified. Oracle takes the larger.
8. EN 1998 tank: Rust Housner coefficient 1.7 R/H against 0.866 D/H = 1.732 R/H (0.2 percent, inside 1e-2). Slosh coefficient 0.84 and the registry gamma_0 = 1.35 are read from the registry, not independent.
9. EN 1998-3 capacity uses the shared `building_base_shear_n` (known: no Table 5.1 q cap and no 0.8 factor); the oracle includes both, so assessments on irregular or capped buildings will differ until the shared fix; fixtures use regular, uncapped building `bldg-office`.
10. Pre-existing risk: EN 1998 rows `tie`, `slope`, `sliding`, `thrust` expect `pass` but cite NDP rows; `assemble()` turns a passing row with unverified NDPs into `unverifiedBasis`. If the first run shows that, the old rows need the status changed (not touched).
11. Status risk of new rows: info/pass rows depend on the thread-local registry-read log (reads leak to the next draining check). Modelled in `Emit.pending`; uncertain ones (crane-runway, lm3-vehicle-length) were left out of the feature.
