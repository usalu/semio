## What was built, per gap (priority order)

1. **Long-press Edit menu in the real input path.**
   - Framework (domain-neutral): `TouchSession` recognises contacts with a clock; the wgpu host feeds every touch pointer on a `world-3d` surface through it (`WGPU/🧊️renderer/🛎️frame-actions/🎮️interaction-state/🖐️world-touch`). A held finger (450 ms) is an additive press (shift), released in place it yields a `LongPress` gesture that `handle_pointer_button` hands to the new `PluginShellHooks::handle_touch` through `PointerCtx::handle_touch_gesture` (shell keyboard impl, answered like a key: action, selection or verb).
   - Norm: `touch_gesture_outcome` answers a long press in a norm viewport scope with the declared window action `norm.touch.menu-open`; `view_act_of` (command bridge macro) turns it into `viewportAct` / `viewportTouchMenu`, `LaneEvent::ViewMenu`, and the new ephemeral `ViewLane.menu`. `render_viewport_panel` of a live editor adds `render_touch_controls`: the `render_touch_menu` tree (Copy, Paste, Duplicate, Delete, Select all; disabled rows say why) plus a Close row, and calls `publish_touch_menu_access`. The three previously test-only functions now have a production caller. Entries route exactly like the chords (`host_entity_call`, framework `selectAll`). Bulk edit stays reachable through the Properties tab (bottom sheet on a phone) and the context-menu row.
2. **Mobile handle editing.**
   - `map_gesture`: a one-finger drag that starts on a handle under `TapNudge` is `FocusHandle` (never `Orbit`, never an edit).
   - `nudge_rows` (toolbar): per grip of the selection a minus and a plus row, device-gated by `DeviceProfileSpec.nudge_buttons` (mobile and tablet). A row carries the flat gesture `{handle, s, origin, phase: commit, ctrl: true}`, so one tap is one `setFields` that moves the bound field by one schema step (`nudge`, freed from snapping so a step never snaps back); a grip at its limit gets a row that says "At the limit / Am Grenzwert"; the description shows the current value; `LaneOverlays.focused` (A11Y) narrows the list. `Gesture::parse` now also reads `shift/alt/ctrl` flags at the top level (flat touch buttons cannot carry an object).
   - On tap-to-nudge devices (`touch_profile_of`: mobile) one finger orbits instead of editing; tablets keep one-finger pass-through (marquee/gumball) because handle drag stays the tablet's input.
3. **`map_gesture` wired.** The framework lane realises the table: tap = replace pick, long press = additive pick (`Select{Pick, Additive}`), long press then move = rectangle (`Rectangle, Additive`, through the authority's marquee with shift), drag/pan/pinch as camera. `map_gesture` itself stays a pure table; the host maps `TouchStep`s straight to intents, and the test `the_framework_touch_lane_realises_the_gesture_table_of_every_device_class` pins both to each other for every device class. `handle_hit_px` / marker pick radius: `touch_profile_of(...).hit_px` carries the profile minimum (44 px) to the host; `marker_hit_radius(min_target_px)` makes the diagram marker pick radius `max(8, edge / 2)` (22 px on touch, unchanged on desktop) through `LoweringOptions.min_target_px` / `device_profiles::touch_hit_px()`; a finger 15 px off a marker hits it on touch and misses on desktop (test). The nudge rows are tree rows whose height the shell theme owns (no touch density API exists), so a 44 px row height is NOT enforced; the 3D grip markers have no pick radius at all (see finding).
4. **Native wgpu 3D camera by touch, parity with the web orbit rig.**
   - `apply_pinch_to_orbit` is the Rust twin of the TypeScript `applyPinchToOrbit` (target-centred dolly or ortho zoom plus centroid pan in the camera plane), replayed on the shared fixture `GEST/🧪️tests/🧫️fixtures/🖐️touch-session.json` (`orbit` rows were produced by running the TS function under node; 7 rows, 1e-9).
   - `pinch_navigation` expresses a pinch in the units the native orbit controller already has (wheel `distance * (1 - w / 1000)` = `distance / scale`; shift-right-drag pan scaled by `2000 tan(fov/2) / H` so `OrbitController::pan` moves exactly as the web law). A Rust test emulates the native controller maths and compares to the web law. The host sends a wheel intent and a shift-right-drag pan intent, i.e. paths the authority already answers (`CameraLocal`, `noteWorldNavigation`, `setCamera` settle): no authority code changed.
   - Two fingers never start a marquee: the primary press is deferred until the finger decided (slop 8 px / long press); a second finger after a forwarded drag releases it first; the finger left down after a pinch never resumes (`GestureRecognizer` latch).
5. **List-based selection on mobile and tablet.** The outliner is a tab of both layouts (`MOBILE_ROLES` 5, `SIDE_ROLES` 4; old stored preferences are completed by `sanitised`), second in the a11y focus order; a list selection raises the properties bottom sheet on a phone. Alt+1 now focuses the real outliner window on every device, so norm's `stand_in_region` and the `fallbackWindowKindId` argument are removed from the norm hook (the framework capability and its fixture stay; W3-FOCUS-WINDOW-2 was told in requests.md).

## Honest limits

- No dedicated wake timer: the long press fires on the next contact event, in the frame Hover phase (`poll_world_touch`) or at the lift. A perfectly still finger on an idle app shows the menu at the lift. The retained-control deadline clock has another time base; I did not wire it blind.
- The Edit menu stays open until its Close row (entity commands do not close it). The entry counts come from `HostContext` published by the inspector, which can lag the viewport render by one refresh after a selection.
- The web shell has no long-press handler (not touched; open item in requests.md). Native only.
- Tablets keep one-finger pass-through, so one-finger orbit on empty space is a phone feature; tablets orbit by a camera toolbar or mouse (two fingers pan/pinch only, as in the web rig; no twist-to-orbit).
- DoubleTap = frame is recognised by the lane but not answered by the norm hook (the view action `viewportFrame` is a framework camera action, not an app tool).
- Touch context-menu parity (secondary press): the long-press Edit menu covers copy/paste/duplicate/delete/select all; "focus check" of the context menu is not in the touch menu.
- 44 px row height of nudge rows and a 3D grip pick radius are not enforceable from the app (see item 3).
