## 2026-11-03 01:15 root-cause analysis in the framework (no framework patch made, reasons below)
Where the invalidation comes from (read, not guessed):
- `🕸️graph/🟦️.ts:406` treats `📋️project.json` and `Cargo.toml` as owner configs; `🕰️generations/🟨️.mjs` `plan()` (l. 418-423) sends an added config to `added`, and an added file outside every owner root (`ownerOf` undefined) to `envStale=true` plus `added`. `build()` (l. 471) turns `envStale || added.length` into a `structural` claim, which is the "one refresh rebuilds the whole workspace" (4.6k projects, 300-373 s). The new leaf crates keep their sources outside their crate root (`[lib] path = "../../🦀️.rs"`, `schema/🟦️.ts`), so every new mutation leaf adds files in an unowned directory.
- A `Cargo.toml` is a legitimate owner: `discoverNativeBuildOwnersV1` makes a `discovery:manifest` project of every manifest (no `📋️project.json` needed; 0 of 89 en1993 mutation leaves have one). So "manifest without project.json" is not an ownership gap, the manifest is the owner declaration, and a new one genuinely changes the project set.
- The inference failure is a different, narrower race: the farm worker session snapshots `projectsByRoot` at graph start, while the facade crate `…-en1993-mutations` was edited later to depend on the newly created leaf (`withNativePreparation`, `🦀️native-manifests/🟨️.mjs:285`, code BUILD_SOURCE_AUTHORITY). The framework already recovers ("inferred in this process"), so it costs a retry, not a failure.
Why I did not patch: making additions stop invalidating needs a stable-directory-listing cutoff (the Cargo walk `walkCargoToml` records a `readdir` fact for every directory, so any added file anywhere makes the environment stale by fact, independently of the `ownerOf` branch). Removing only the `ownerOf` branch would not help and relaxing the fact would risk stale graphs. A sound design is: record the manifest walk as a derived fact (answer = sorted manifest paths), so the existing derived-result cutoff (`cutoff: N derived results asked again … unchanged`) absorbs added non-manifest files, and have the crate generator create the manifest last, after its sources and the facade edit, in one batch. That is a graph-store change in a hashed area under a running fleet and needs the framework test project (not runnable under current memory), so it is proposed here, not applied. The churn itself ends when the splits end; unchanged trees reuse the published generation.
Mitigation in place: runner gate (graph phase serialised) and retry on the daemon timeout (above).
