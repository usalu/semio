# Receiving allocation failure wire

The IO snapshot receiving cause carries the original construction primary, quote and allocation refusals, canonical twelve-channel allocation failure and its physical progress, existing native decode allocation outcome, independent receipt refusal, and construction progress. The receiving frame owns each field while its message is decoded. Null physical capacity indicates no allocation action; zero indicates an attempted allocation with no capacity. The closed IO and snapshot schemas require the same fields.

The neutral JSON fixture tests all twelve causes against Ajv and SQLite for null, zero, and positive physical capacities. Native round-trip coverage is authored but has not run. Normal-capacity test 58380 ran after the changes: the new allocation law and four other tests passed, while an existing allocation test failed because its fixture omitted the required request field. That fixture now explicitly supplies null; normal-capacity successor 85790 passed all six tests with 35 assertions. No native compilation or original-caller acceptance is claimed.

The shared allocation slot API is still being reconciled with callback identity and unwind handling by its owner. Existing octet and channel allocation consumers are not migrated or accepted.

A subsequent run exposed the invalid schema; the duplicate entries and duplicate unmetered decoder and malformed encoder were removed while preserving the metered receiving owner. Successor 27846 additionally checks the nested projection against the canonical allocation schema and is pending.

The native and neutral fixtures additionally carry the distinct existing decode-allocation outcome together with the canonical failure; no former outcome is discarded by the new receiving field. Shared slot signatures have changed to retain directional allocation progress across callback unwind and remain uncompiled upstream.
