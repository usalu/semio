# Schema codegen, wave 2

No cargo, no build, no git write, no twin rewritten. All runs under `nice -n 19 ionice -c3`, sequential.

## 1. What already existed
- `repo ./📜️script.ts schema generate` only rewrites the scope catalog. `schema parsers report|apply|check` (`🧰️framework/…/📚️library/🎛️commands/🧬️schema/🪞️parser-projection`) projects missing GraphQL types, protobuf messages, TS types and framework-style `parse<Export>` entries from `🔣️.json`; it is additive, never invents Rust, and does not know the norm `normWire*` dialect. `surface-schema` projects the editor/viewer config/presence lanes from Rust (the `🤖️ Generated by` banner); the generator skips those files.
- The one-shot `🧪️s2-norm-ts-twins.ts` (ticket NON-DESTRUCTIVE-HISTORY-EDITING, hard-coded `/Users/ueli/..`, old folder layout) was the original norm TS generator; its shape logic is the base of the new TS emitter.
- Extension chosen: new module `schema/🧬️twin-projection` next to `🪞️parser-projection`, reusing its protobuf/GraphQL renderers and `snake`, exposed as `repo ./📜️script.ts schema twins generate|check|annotate`.

## 2. What was built
`🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🎛️commands/🧬️schema/🧬️twin-projection/`: `🟦️.ts` (plans, generate/check/annotate, report), `🧩️model` (module walk, `$id` index, pointers, leaf descriptors), `🧭️dialect` (family dialect from `🧬️twin-dialect/🔣️.json`), `🟦️typescript`, `🛰️protobuf`, `🔗️graphql`, `🦀️rust`, `⚖️equivalence` (identical / style / drift). Engine is domain neutral; the norm dialect is `✏️s/🔌️plugins/📕️norm/🧬️twin-dialect/🔣️.json`; din/iso/vdi carry `"projection": "off"` (their twins use the older Default-reader era).
- TS: interfaces, aliases, `normWire*` readers, bounds, nullable, refs and sibling imports across modules by `$id`, externally and internally tagged aggregates (tag from the payload `mutation` const, else the leaf descriptor variant), field docs from `x-semio-twin.emoji` plus `x-semio-state`, header from the leaf descriptor or the dialect facet table. Contract imports sort by code point (locale independent).
- protobuf: framework message renderer plus file header (`package` from `$id`), `// @state` comments, nullable scalars kept scalar (`optional double`) instead of the `bytes` carrier. GraphQL: framework type renderer plus one `JSON` scalar.
- Rust: the payload struct of a mutation leaf (derives and attributes of the leaf template, field types from the schema) spliced into the leaf `🦀️.rs`; every other item untouched. Not covered: structs of root records (artifact, snapshot, diff rows) and the 283 split-layout leaves whose struct lives in another file.

## 3. Annotations added to the JSON (the lossless part)
`x-semio-rust` `{type, name}` written by `schema twins annotate` into 195 leaf payload schemas (record/enum paths such as `semio_s_artifact_norm_en1996_model::MasonryWall`, and 4 irregular field names such as `new_n1_60`). Vocabulary for `x-semio-twin` (emoji, summary, name) and `x-semio-state` is read by the emitters; documented in `📌️important/schema-first.md`. JSON files were re-serialised with two-space indent, which is how 1748 of 1864 leaf schemas were already laid out.
Not yet added: dsl `unit`/`table`/`keyword`/`block` attributes of root Rust records, per-field docstring emoji of the root twins (`x-semio-twin.emoji` is read but only the 10 artifact roots would need it), root-record derive lists. These belong to the Rust root structs, which are not generated yet.

## 4. Round trip, measured (`schema twins check`, norm scope, 4301 twins)
| twin | identical | style only | drift |
| --- | ---: | ---: | ---: |
| typescript | 858 | 1237 | 130 |
| protobuf | 0 | 0 | 198 |
| graphql | 112 | 0 | 86 |
| rust (leaf structs) | 2141 | 0 | 29 |

Byte identity is therefore NOT reached for all modules: TS 858/2225 identical, 2095 equal after layout normalisation. The reasons are twin history, not missing information in the JSON: three sort orders of the contract import (ascii 862, case-insensitive 665, `type` first 501 leaves) and unused leftover imports; hand layouts of the root twins (definition order, compact one-line interfaces, `(string) | null`); `Required`/`Default`/`Optional` mixtures; proto package names and blob conventions per file. Making these byte-identical would mean storing layout in the schema; the clean fix is one canonicalising `generate`, which I did not run (rule: no rewrite before byte identity).
Independent proof that the generated twins say what the JSON says: scratch overlay (`🧰️scripts/schema-codegen/roundtrip.sh`, copy of the norm tree, all languages regenerated into it, then `🐍️check.py --root overlay`): **11 mismatches** (committed tree at the same moment: 68). Remaining 11: the in-flight `trafficGroups` diff edit of another agent (rust/ts/proto/graphql, 5), `design-case` `InputVocabulary`/`InputSpec` (a `$schema` property and an untyped `example`, 4), 2 GraphQL enum-vs-string. Generated TS contributes 3 of them (all trafficGroups/design-case), generated Rust leaf structs 0 new.

## 5. Drift the generator exposes (needs a decision, real defects included)
- leaf TS twins import names the snapshot twin no longer exports (`parseEn1991FallingLoad` while the snapshot declares `FallingLoad`; en1997 `parseAnchor` vs prefixed): broken imports, fixed by `generate`.
- 23 `insert-*` payload schemas lack the nullability of `index` (`Option<u32>` in Rust, nullable in the twin); `kind`/`gk` enums of `PermanentAction` are `string` in the artifact JSON but enums in TS; some leaf enum fields are inline enums in JSON but `$ref` to the snapshot enum in TS. Each is a JSON repair to make before `generate` (the JSON must be right, it is the source).
- 51 leaf Rust structs still use `#[cfg_attr(test, derive(Serialize, Deserialize))]` (serde only in the crate's own tests) where the template and 2094 siblings say `any(test, feature = "test-support")`; 4 structs have enum fields the annotator could not match by position.
- 3 hand-written one-line interfaces (`ChangeBridgeLane { newBridgeLane: number; }`) are layout-only.

## 6. Gate, docs, tools
- `schema twins check`: exit 1 on drift (and on style with `--strict`). Wired into `🧪️tests/🧬️schema-sync/🟦️.ts` as a ratchet against `🔣️drift-baseline.json` (130/198/86/29, numbers only go down; end state 0). The existing checker test is unchanged. The bun test was not run (no bun on this host); the same code path ran under node 24 with `--experimental-transform-types` and under `repo ./📜️script.ts schema twins check --only rust` (19 s).
- `📌️important/schema-first.md` states the rule "edit 🔣️.json, run the generator" with the keyword table.
- Tools: `🧰️scripts/field-adder/schema_twins.py` writes any field type (f64 f32 u8 u16 u32 u64 usize i32 i64 String bool, enum, ref, rows with record creation, nullable) into the JSON and runs the generator; `field_adder.py` now uses it for the schema/TS/proto/GraphQL layers (its numeric default handling and model/SQLite layers are unchanged). `new_collection.py` and the artifact profiles (`en199x_profile.py`) were NOT converted; they still edit twins directly and should call `schema_twins.add_field` + `regenerate`.
