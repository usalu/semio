## Why not `evolve.py add-collection`
A dry run (`🧰️scripts/en1994-wave3b/en1994-cases.json`) plans 402 files but stops at three `UNSUPPORTED` layers for en1994: (1) diff: the tool looks for `pub struct <Entity>Key;` but en1994 declares its keys with the `row_key!` macro; (2) sqlite: nested rows (`numbers[]`, `texts[]`) are not supported outside en1997 (en1994 children are inline in the parent statement); (3) mutations: no String set-field kind to clone. More fundamentally the tool creates a per-artifact `CaseRow` entity with its own diff row groups, whereas every other code (en1991/1992/1995/1996/1997) shares `design_case::{CaseRow, CaseNumber, CaseText, CaseRowDelta}` and the seven shared mutation leaves. So the collection was ported by hand like en1996 (flat `cases` collection, shared types) with the repo's own `catalogue-bridge-v2` helpers (`twins.py`, `jsonspan.py`, `leaves.py`, `crates.py`; wrappers with current leaf names in `🧰️scripts/en1994-wave3b/`). `[lock]`/`[unlock]` lines are in `requests.md`.
