# Field-adder (`🧰️scripts/field-adder/`)

Schema-first, idempotent tool that adds one snapshot field to a record of a norm artifact through every layer. It generalises `en1991-add-tandem-x.py` (root scalar anchored on a neighbour field) to row-collection fields (`beams[].field`) of artifacts with hand-written positional SQLite codecs.

## Use
```
python3 -I 🧰️scripts/field-adder/field_adder.py 🧰️scripts/field-adder/specs/en1994-wave2.json [--dry]
```
`--dry` prints the files it would edit but chains of fields that depend on each other fail in dry mode (the second field anchors on the first, which a dry run does not write). A re-run is a no-op.

## Spec (`specs/*.json`)
`artifact` (profile key), `fields[]` with `entity` (collection), `field` (snake_case), `after` (existing neighbour field, unique in the artifact; for SQLite it must be the last data column of the table so no positional index shifts), `type` (`f64` | `u32`), `default`, `unit`, `en`, `de` (labels), optional `tests_after` (anchor for the SQLite test helpers), optional `kind` + leaf keys (`leaf_en`, `leaf_de`, `ui_unit`, `group`, `emoji`, `crate`) to register the per-leaf mutation kind in the artifact generator, `crates[]` for new leaf crates, `run_generator` to run the generator at the end.

## Layers edited (EN 1994 profile)
model struct (+ `#[dsl(unit)]`) and every struct literal of the neighbour; snapshot json (own and combined, property and `required`), ts interface and parser, graphql, proto; SQLite `🗄️.sql` (data column + IEEE pair), `🦀️.rs` (float column list, write cell, read, column count), `🟦️.ts` (type, float list, write, read, count), test helpers rs and ts, SQLite fixture (also minified); field-meta row (EN + DE, unit id); every committed snapshot fixture (text insertion, formatting kept, diff and schema directories skipped); the generator tables (leaf record, patch order). The generator (`🧰️scripts/en1994-leaf-kinds.py`, run with `REGEN=1` to only refresh the diff layer) then writes the kind, its diff patch fields with json / graphql / proto / ts twins, fixtures, harness rows, oracle catalogue, taxonomy, edit rules and workspace registration. Assets (`🖼️assets/**/🗣️.dsl.semio`) are not touched and are regenerated by the first test.

## Profiles
`PROFILES["en1994"]` lists the paths. A new artifact needs a profile with its paths and entity table (model type, table, SQLite constant, row variable, field-meta prefix). Root-level scalars (EN 1991 style) are not covered by the row handlers; use `en1991-add-tandem-x.py` as the template for those.

## Limits / unverified
Nothing built yet. Proto numbering appends at the end of the message (numbers need not follow field order). `u32` fields are written as SQLite integers with the 0..4294967295 check; no IEEE pair. The tool asserts exactly-one matches before editing and fails loudly otherwise.

## Applied to EN 1994 (wave 2)
`beams[].adjacentSpanM` (0 = equal span), `beams[].patchBearingLengthM` (default 0.1 m), `beams[].bridgeLanes` (0 = from the girder spacing), `columns[].introducedForceN` (0 = from the actions); 182+ fixtures updated; four new `change-*` kinds in the crates `🧭️beam-design` and `🔗️column-design`.

## Applied to EN 1994 (wave 2b, en1994 v2)
Spec `specs/en1994-wave2b.json`: `beams[].crackedLengthFraction` (default 0.15; 0 = uncracked analysis) and `columns[].{sectionHeightM, sectionWidthM, sectionTwM, sectionTfM, rebarCoverM}` (0 = equivalent section). The tool now accepts a `u32` as the SQLite anchor (`after: bridge_lanes`): the `CHECK(...)` column definition in the SQL, `Cell::Integer(i64::from(..))` in the Rust write, `unsigned(..)` in the Rust and TS read and `count(..)` in the TS write are matched as anchors. 190 fixtures per field; six kinds generated in `beam-design` / `column-design`.

## New collections (`🧰️scripts/field-adder/new_collection.py`, wave 2 collection-adder)
Schema-first template that adds one or several id-keyed row collections to an artifact, generalised from `🧰️scripts/en1993-entity-gen.py` (EN 1993) and the manual EN 1991 `accidentalCases` cascade. Idempotent (a second run edits nothing, the self-test proves it), path-guarded (every edited path must be shorter than 256 bytes), and measured against the crate budget (`source-boundary-scan.py`: the generated diff schema defs are written one line per def, which kept `semio-s-artifact-norm-en1991-diff` at about 3530 lines instead of 4066).

```
python3 -I 🧰️scripts/field-adder/new_collection.py 🧰️scripts/field-adder/specs/en1991-collections.json [--dry] [--root PATH] [--self-test]
```
`--self-test` copies the artifact to a scratch directory, runs the spec twice, asserts that the second run is a no-op, that every JSON parses and that the recomputed SQLite contract equals the replay of the final DDL by python `sqlite3` (the third-party implementation).

### Spec
`artifact` (profile key, today `en1991`), `collections[]` with `camel` (`bridgeLanes`), `entity` (`BridgeLane`), `table` (`bridge_lane` -> `en1991_bridge_lane`), `after` (camel name of the collection it follows; chain several by naming the previous new one), `emoji`, `doc`, `label_en/de`, `id_en/de`, `fields[]` (`name` snake_case, `ty` one of `String | f64 | u8 | u32`, `unit` one of `m m2 Pa N d a deg rad`, `en`, `de`, optional `step`, `precision`), optional `kit` (`id en de icon scene_kind`) for the outliner / insert palette row. `id: String` is implicit.

### Layers written
1. model row struct (derive block copied from the profile's flat template `WindFace`, `#[dsl(unit)]` per f64), snapshot field, `Default`.
2. five twins in both schema directories: ts interface + parser + root entry, proto (next tag, JSON string like the sibling lists), graphql (`[JSON!]!`), json schema (`snapshot.json` by text insertion because it keeps inline enums, `schema` by load/dump).
3. artifact schema struct + both conversions.
4. diff lane: local `<Entity>Key` marker + `row_patch!` + id-keyed `list_delta!` (positional with the key marker), the `En1991Diff` field, `absorb`, `commit_onto`, `is_empty`, `inverse`, ts / json / graphql / proto twins.
5. io: text and binary import lines.
6. SQLite: DDL appended last so no positional index moves (data columns + IEEE pair per f64), Rust codec (float columns, write, bound, read, column count, table count), TS codec (types, float columns, write, read, table index), admission (field ids are the 0-based struct index; lists loop widened), Rust and TS test perturbations, `tables.len()` and the accepted / refused table bounds, and the recomputed contract (`🎛️semantic.json`, ts expectation).
7. contract by the replay method: first the recorded `schemaBytes` and `tableWidths` are reproduced from the current DDL with python `sqlite3` (the tool aborts if they differ), then recomputed after the change (`sum(len(name)+len(sql))`, widths by `pragma table_info`). `rows` and `valueBytes` stay when the fixtures hold `[]`.
8. field-meta EN + DE rows (quantity rows with `UnitId`), `[]` in every fixture (298 json files for EN 1991, text insertion keeps the formatting; diff-form fixtures get an empty delta), outline fields and entry count, duplicate-id integrity check, incremental scope tag (`ROW_COLLECTIONS`), kit registry row.
9. printed at the end: the leaf kinds to announce to leaf-kinds (`insert-<plural>`, `remove-<plural>`, one `change-<row>-<field>` per field, id selectors) - never written here.

### By hand after the template (checks, scene)
The template does not guess domain code. For EN 1991 the checks module `🧬️schema/💡️inferences/🧱️collection-checks`, the units groups, the scene module `🎬️scene/🧱️collections`, handles, diagrams and the `owner_of` rows were written on top (see `🔍️audits/wave2/collection-adder.md`).

### Limits / unverified
Nothing built or run through rustc: all Rust and TS text is checked by reading and by the `--self-test` (JSON, DDL, contract). Profile `en1991` only; EN 1993 style artifacts keep `en1993-entity-gen.py`, other layouts need a profile (paths and anchors are the only artifact-specific part). The DSL text assets (`🖼️assets/**/🗣️.dsl.semio`) are untouched and regenerate with `EN1991_REGEN_ASSETS=1`. `u32` is supported in the codecs but only `u8` was exercised.
