# Wave 3 oracles: Rust-emitted check families against the check-outcome oracles

Python only, no Rust change, no git writes; scripts in `🧰️scripts/oracle-gaps/`. The heavy gate (`heavy.sh`) waited more than 15 minutes on the build lease and the en1997 oracle needs about 12 minutes per sweep, so the sweeps ran niced and directly (about 300 MB each, one at a time).

## Scanner (`🧰️scripts/oracle-gaps/scan.py`, `assess.py`, `report.py`, `rows.py`, `validate_rows.py`)
- Rust side (`assess.py`): the id argument of every `CheckResult::assess(` call of an artifact and, to a fixed point, of every function that forwards a parameter into it (`head`, `covers`, `info`, ...); `let id = |stem| format!(..)` closures resolved; `format!("enNNNN...")` literals of the files that build checks; spec-trace `Realisation::Check(&[..])` ids and suffixes (kernel-built families such as `en1995.t-18.*` appear only there). `{..}` becomes a wildcard segment; a family that is a prefix of another is dropped.
- Oracle side: the check-outcome oracle run over every document that the check-outcome feature references, every fixture of `🚦️check-outcome/` and `📄️oracle-documents/` and the showcase document (`ids-<code>`, cached in `🗑️generated/oracles`), plus the static `f"enNNNN..."` literals of all `🔮️oracles/**/*.py` of the artifact ("twin without fixture" = the twin exists but no document exercises it).
- A family is covered when an oracle id matches its pattern, or the oracle reports the family id without the entity suffix (`en1993.7.sls`), "coarse" when the oracle reports a parent family (`en1993.6.2.5.<member>` for `.my`/`.mz`).
- Classification (`report.py`): diagnostics (integrity, reference, unknown, empty, na), catalogue case ids (`m-01`, `gi-03`, ...), engineering families. Caveat: the Rust side is a static reading, ids built by runtime string concatenation in kernels are missed, and the classifier is a regex, so counts are +-10 %.
