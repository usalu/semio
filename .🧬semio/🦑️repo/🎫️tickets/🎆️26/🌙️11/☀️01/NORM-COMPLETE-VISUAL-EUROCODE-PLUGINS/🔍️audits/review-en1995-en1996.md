# 🔎 Formula Review EN 1995 / EN 1996

Scope: the uncompiled, actively edited compliance code of `🪵️en1995` (including the `⚖️timber` kernel) and `🪨️en1996` (including `⚖️masonry`) against `📐️specs/en1995-en1996-target.md`, `en1995-inventory.md`, `en1996-inventory.md`, `en1995-completion.md`, `en1996-completion.md`, `ndp-crosscheck-en1992-en1995-en1996.md` and `ndp-public-verification.md`. Nothing was built or modified. Recomputation scripts (stdlib, run with `python3 -I`): `🔍️audits/review/en1995-recompute.py` and `🔍️audits/review/en1996-recompute.py`.

- `K95` = `✏️s/🔌️plugins/📕️norm/🗿️artifacts/🪵️en1995/🏅️standards/🔖️1/🪆️subsets/✳️any/🧬️schema/⚖️timber`. Sub-folders are abbreviated by their English name: `strength-tables`, `material-and-annex-factors`, `load-combinations`, `structure-and-members`, `cross-sections`, `stability`, `varying-sections`, `serviceability`, `connections`, `components`, `fire`, `bridge-and-connections`, `catalogue`.
- `K96` = `✏️s/🔌️plugins/📕️norm/🗿️artifacts/🪨️en1996/🏅️standards/🔖️1/🪆️subsets/✳️any/🧬️schema/⚖️masonry`. Sub-folders: `normative-tables`, `factors-and-geometry`, `fire-and-design-effects`, `evaluate-wall/{load-case-checks,fire-durability-and-reinforcement,wall-geometry-and-material}`, `catalogue/{materials,vertical-load,shear-and-lateral,reinforced-special-and-ties,serviceability-simplified-and-fire,numerical-models}`.
- Severity: **S1** wrong or unsafe result on a default path, **S2** wrong for a variant, a unit or convention hazard, or an unverified normative value that drives a verdict, **S3** robustness, simplification, style. `[V]` = my reading of the printed standard from memory, not a verified quote; confidence is stated where it is below high. Where a statement is backed by `ndp-public-verification.md` the row id is given.
- Good news first: the formula layer is largely right. All 12 EN 1995 worked examples (E1-E11, E12 is oracle-only) and all 11 EN 1996 examples (X1-X11) reproduce from first principles (section 4), with three spec arithmetic slips (section 4). Johansen modes (a)-(m) with the per-family rope cap, tapered/apex factors k_m,α / k_l / k_p / k_dis / k_vol, k_crit, k_c, the notch k_v (6.62), the γ-method (Annex B and the CLT form), the 7.5-7.7 floor chain, charring/d_ef, the spacing Tables 8.2/8.4/8.5, EN 1996 Φ_i, Φ_m (Annex G, creep), ρ_n, β and the M-N section are all correct as transcribed. The `Outcome` to `CheckResult` path is safe for zero capacity: the shared `ratio()` (`⚖️compliance/✅️check-results/🦀️.rs:20`) maps a vanishing or non-finite capacity with non-zero demand to the utilisation cap, so a failing zero-capacity case fails. The remaining risk sits in the data tables, the member-level load layer (combinations and internals), and a handful of simplifications that are not flagged.

## 1. EN 1995 findings (ranked)

### S1

1. **Two-span continuous internals are wrong, and the profile then scales the wrong peak.** `K95/load-combinations/🦀️.rs:29-31`: `M = q l²/14 + F l/6`, `V = 0.6 (q l + F)`. For two equal spans loaded in both (UDL and a point load at each mid-span) the governing section is the central support: `M_B = q l²/8 + 3 F l/16`, `V_B = 5 q l/8 + 11 F/16`. The code uses the sagging coefficient 9/128 ≈ 1/14.2 as the peak, so the bending demand at the support is **low by 43 %** (UDL, `q l²/14` vs `q l²/8`), by 11 % for point loads, shear by 4 % / 13 %. The effect profile has the right weights (`📉️effect-profile/🦀️.rs:27` uses `q l²/8`, `3 F l/16`, and `:53` uses `5/8`, `11/16`) but is normalised to peak 1 and multiplied by the wrong `m_ed` (`structure-and-members:153` `scaled`), so the along-member field and the verdict repeat the error. The bridge member has the same coefficient (`bridge-and-connections:19` `1.0/14.0`). Fix: compute `M_support = q l²/8 + 3 F l/16` and `M_span = 9 q l²/128 + 13 F l/64` (sagging, separate station), `V_support = 5 q l/8 + 11 F/16`; check both stations and let `Profile` use the same constants (single source). Reproduced in script B3.
2. **No permanent-only (or duration-class) ULS combination when variable actions exist.** `K95/load-combinations/🦀️.rs:171-204`: with at least one variable action the only ULS combinations are `1.35 G + 1.5 Q_lead + 1.5 ψ0 Q_others` for each leading action, and `kmod` is taken from the shortest duration of **all** actions in that combination (`:195`). The check `1.35 G / kmod,permanent (0.6)` is never evaluated and neither is any subset by duration class (permanent + long + medium, without the short-term accompanying action). EN 1995-1-1 3.1.3(2) and the usual practice check each duration class. Example `G = 5, Q = 1` kN/m (medium): `1.35 G/0.6 = 11.25` vs the only built `(1.35 G + 1.5 Q)/0.8 = 10.31`, G-only governs by **+9 %** and is silent (script B4). The same gap in `enumerate_connection_combos` (`:334-355`). Fix: for every distinct duration class d among the actions build the combination of all actions with duration ≥ d (leading action = each variable of class ≥ d), `kmod = k_mod(d)`; keep γG,inf = 1.0 combos for uplift/hold-down (`:160` has no favourable branch at all).
3. **Strength table: EN 338:2016 and EN 14080:2013 rows are a mix of editions and the "verified" flags are wrong.** `K95/strength-tables/🦀️.rs:58-69, 78-91`. (a) C-classes: `f_t,0,k` is the 2009 value for C14, C16, C18, C20, C30-C50 and `f_c,0,k` for C30, C40, C45, C50. EN 338:2016 [V, confirmed for C16/C24/C30 by `ndp-public-verification.md` E95-04/05 via MAD, L3]: C14 7.2, C16 **8.5** (code 10, +18 %, unconservative), C18 10 (11), C20 11.5 (12), C30 19 / f_c,0 24 (18 / 23), C35 22.5, C40 26 / 27, C45 30 / 29, C50 33 / 30 (script B1). Rows C16 and C30 carry `verified: true` although their `f_t,0,k` is wrong; the pinned test (`🧪️tests/⚖️compliance/🦀️.rs:919-925`) and the Python oracle rows (`🔮️oracles/⚖️compliance/🐍️.py:30,36,45`) copy the same numbers, so they cannot detect it. (b) Glulam: the rows are EN 1194:1999 values (`f_t,0` 16.5/19.5/22.5, `f_c,90` 2.7/3.0/3.3, `f_t,90` 0.4/0.45/0.5) under the label `EN14080` (`:54`). `ndp-public-verification.md` E95-06/07/08 (verified-public, HASS, L3, CIV24/CIV32) says the earlier repo values were right except `G_mean`: GL24h 19.2 / 0.5 / 24 / 2.5 / G 650, GL28h 22.3 / 0.5 / 28 / 2.5 / 650, GL32h 25.6 / 0.5 / 32 / 2.5 / 650. Completion item 10 followed the **spec** instead and moved GL to EN 1194, a regression: `f_c,90` is now unconservative by +8 / +20 / +32 %. The combined classes GL24c/GL28c should be `f_t,0` 17.0/19.5, `f_c,0` 21.5/24 (HASS, L3), code 14.0/16.5 and 21/24. Fix: take EN 14080:2013 Table 5 values (homogeneous `f_t,0 = 0.8 f_m`, `f_c,0 = f_m`, `f_c,90 = 2.5`, `f_t,90 = 0.5`, `G = 650`), correct the C columns, set `verified` only after a print check, and correct the spec line 28 (the spec is the source of the wrong GL numbers). Update the pinned test and the oracle rows from the printed table, not from the Rust.

### S2

4. **Combined compression + bending omits k_crit (6.35) and the fire check omits stability.** `structure-and-members:273-279` (`combined`): `fm = kmod kh fm,k/γ` with no k_crit, so a slender beam-column with N and M is checked with the full bending strength although the standalone bending check (`:228`) applies `kcrit`. 6.35 is `(σ_m,d/(k_crit f_m,d))² + σ_c,d/(k_c,z f_c,0,d) ≤ 1`. `T-22` (`stability:131`) and `T-23` have it; the member path does not call them. `fire:94-95` (T-101) and `structure-and-members:414-447` check `(σ_c/(kfi fc))²` and bending only, no `k_c,fi` / `k_crit,fi` (EN 1995-1-2 4.2.2, E_0,05 · k_fi). Also the member fire check uses the full ULS moment (`:415` max over ULS), not the accidental/fire combination `η_fi · E_d`, and no shear/tension. Fix: route members through T-20..T-23 and make the fire member check use the fire combination with `kc,fi`.
5. **`action_internals` conflates the transverse line load with the axial load for columns.** `load-combinations:33-37`: for `MemberRole::Column` the same `q` gives `N = q l + f` **and** `M = q l²/8 + f l/4` (`:24-27`). A column cannot see the same line load as axial force and as a lateral load; every column with an `actions[].q` is checked for an invented moment. Fix: separate `axial` and `transverse` load inputs (schema) or reject `q` on columns.
6. **Member deflection ignores shear.** `load-combinations:378-382` `deflection_m` uses `E_0,mean I` only. E1 (GL28h 200×400, L/h 12.5): shear adds **+11.9 %** (`κ q L²/(8 G A)`, κ 1.2, G 650); the catalogue T-60 includes it (`serviceability:10-13`), the member verdict does not. The spec E1 values (1.514, 1.817 mm) are bending-only, so the oracle agrees with the error. Fix: add the shear term to `deflection_m` and `deflection_at`, and update E1 or state "bending only".
7. **γ_M for the DE annex disagrees with the public evidence.** `strength-tables:205-216`: glulam 1.25, LVL 1.2, plywood/OSB 1.2 for DE as well (completion item 8). `ndp-public-verification.md` E95-14/15/16/21 (single-source L1, and my reading of DIN EN 1995-1-1/NA Table NA.2 [V, medium]): DE uses 1.3 for "Holz, Holz- und Gipswerkstoffe" and for timber connections; the EN recommended 1.25/1.2 apply to the EN column only. The previous repo value 1.3 was the better-supported one; the spec E1 (GL28h, "DE annex", γ_M 1.25) is the source of the change. Using 1.25 raises design resistance by 4 %. Fix: DE column 1.3 for solid, glulam, LVL, plywood, OSB, particleboard, fibreboard, CLT pending a print check; E1 becomes `fm,d = 17.94`, `η = 0.257`; mark the row `verified: false` until the NA print is read.
8. **Notch k_v is 1.0 for impossible geometry; sign hazards in shear.** `varying-sections:112` `notch_kv` ends with `.min(1.0)`; Rust `f64::min` returns the non-NaN operand, so `h_ef ≤ 0`, `x < 0` or `α < 0` (`sqrt(α(1-α))` = NaN) yield `k_v = 1.0` instead of an error. `t15:208-212` can make `v` negative (`v -= vp (1 - β)`) and then τ < 0 passes. Fix: reject `0 < α ≤ 1`, `x ≥ 0`, `v ≥ 0` (Err), clamp the reduced shear at zero from above.
9. **n_ef for bolts/dowels uses sin(α), predrilled nails always n.** `connections:241`: `par + |sin α| (n - par)`; EN 8.5.1.1(?) states linear interpolation between `n_ef` (α = 0) and `n` (α = 90°), i.e. `α/90°`. At α = 45° the code gives 3.717 vs 3.517 (script B6), unconservative by 6 %. `connections:231-233`: `predrilled → n^1.0` for every a1; Table 8.1 has a predrilled column with `k_ef` 0.7/0.85/1.0/1.0 at a1 = 4d/7d/10d/14d [V, medium confidence, print check]; with a1 = 4d and n = 10 the code gives 10 vs 5.0. Fix both.
10. **Table 7.1 K_ser errors.** `connections:405-407`: staples use `ρ^1.5 d^0.8/30`, Table 7.1 [V] gives `/80` (K_ser too large ×2.67, unconservative for deflection and slip); toothed plate C1-C9 is `1.5 ρ_m^1.5 d_c/4` (code `/4` without 1.5, too soft), C10/C11 `/2`. `ρ_m` is the **mean** density; the spec E10 uses `ρ_k = 350` for C24 (`ρ_mean` 420 gives K 709 N/mm, γ 0.0377 instead of 0.02896). Fix the table and E10.
11. **Default `kmod = 1.0` in the connector entries and f_u = 400.** `connections:279, 372, 385, 395`: `c.o("kmod", 1.0)`; `kmod` 1.0 is above every permanent/long/medium value (0.6/0.7/0.8). `:127` silently assumes `f_u = 400` (a missing yield-moment input becomes a 400 N/mm² bolt). `:157` Johansen takes the single `kmod` of the first member and ignores `kmod_2` (`T-02` computes `√(k1 k2)` but nothing uses it, EN 2.3.2.2(2)); `:159` the DE `γ_M` is fixed 1.3. Fix: require `kmod` or `class` + `duration` (Err when missing), require `f_u`, apply `√(kmod,1 kmod,2)` when the members differ.
12. **Embedment of bolts in plywood uses the nail formula.** `connections:14`: `("plywood", _) → 0.11 ρ d^-0.3` for every fastener. Bolts and dowels need `0.11 (1 - 0.01 d) ρ_k` (EN 8.5.1.2, [V]); for M12 the code gives 0.47·ρ·0.11 vs 0.88·0.11·ρ, i.e. about 46 % too low (conservative but wrong). Nails in panels additionally require `d ≤ 8` and the predrilling rule for `ρ_k > 500`.
13. **Combination factors and categories.** `load-combinations:343` (connections) `psi_factors(kind, "")` forgets the category: storage (E, ψ0 1.0) accompanies with 0.7; `material-and-annex-factors:145-147` categories F/G/unknown fall to A (F: 0.7/0.7/0.6, so SLS creep ψ2 0.3 instead of 0.6, unconservative for creep deflection); `:120-128` `parse_load_duration` maps any unknown text ("short-term", "instant", "ständig") silently to Medium, and `:112-118` `parse_service_class` maps 0/4/9 silently to SC1; `structure-and-members:321` uses the ψ2 of the leading action only for the final deflection (accompanying variable actions need `ψ0,i + ψ2,i k_def`, EN 2.2.3(5)). Fix: reject unknown strings with a check failure, carry the category on connection actions.
14. **Floor vibration model defaults.** `structure-and-members:364-412`: the velocity criterion is computed only for `f1 ≥ 8 Hz` (`:400`), also for the DE annex whose `f1` limit is 6 Hz (NA branch `:373`), so a DE floor with 6 ≤ f1 < 8 Hz gets no velocity check although T-63 asks for the unit-load criterion; (EI)_b assumes a 22 mm deck and a square panel (`:368, :371`), disclosed in the note but not an input; T-64 (`serviceability:116-118`) compares the deflection under `force_n` (default 1000) with `a [mm/kN]` without normalising by `force_n/1000`. NA-DE `f1 ≥ 6 Hz`, `a = 0.5` are unverified (E95-44/45/46, still open).
15. **Default lateral buckling length.** `material-and-annex-factors:181-188`: `l_ef = restraint spacing` else `0.9 L` for every load case and load position; Table 6.1 gives 1.0 L (constant moment), 0.9 L (UDL), 0.8 L (mid point), 0.5 L (cantilever UDL), 0.8 L (cantilever point) plus +2h / −0.5h for the load position (`stability:84-98` has it). A cantilever, a beam loaded on the tension edge or a constant moment is under-estimated (kcrit too high). Fix: pass load case and load position to `effective_m_crit_nm` or default to l_ef = L.
16. **T-23 biaxial LTB interaction.** `stability:147`: `km σ_m,z/f_m,z` is linear with `k_m`; EN 1995-1-1 6.3.3 gives only the uniaxial form (6.35); the DIN NA form for My + Mz + N is `(σ_m,y/(k_crit f_m,y))² + σ_m,z/f_m,z + σ_c/(k_c,z f_c)` [V, low confidence]. Decide against the NA text; today the term is 30 % lighter than the linear form for rectangular sections.
17. **Dowel end distance.** `connections:206`: dowels use the bolt formula for `a3,c`; Table 8.5 has `a3,c` = 3d for 150° ≤ α < 210° and `a3,t |sin α|` otherwise [V, medium]. Axially loaded screws (`:205`) use `a4,CG = 3d`; Table 8.6 [V, low] has 6d; verify.
18. **Panel kmod values.** `strength-tables:145-146`: particleboard P6/P7 use the P5 values; the rows for P6/P7 in Table 3.1 follow the OSB pattern (0.40/0.50/0.70/0.90/1.10, SC2 0.30/0.40/0.55/0.70/0.90) [V, medium]; the code's own `KDEF_TABLE` gives P6/P7 the OSB values 1.5/2.25, an internal inconsistency. `plywood` is a single kmod row for EN 636-1/-2/-3 although the kdef table separates them (`:179-181`), so plywood 636-1 returns a value for SC2/SC3. No panel strength rows exist (spec T-01 lists them), so these rows are dead data today.

### S3

19. `cross-sections:143` T-12 reports `stability_required` as a ratio that is 1.0 or 0.0 against limit 1.0, so it can never fail (informational); `t10/t14/t17` accept negative `n_c`/`n_t` and report negative utilisation (a pass) instead of rejecting the sign.
20. `catalogue:96` `Outcome::utilization()` returns 0 for capacity ≈ 0 (used by the test oracle, `🧪️tests/⚖️compliance/🦀️.rs:834`); same in `K96/catalogue:196` where it gates remedy creation (`:270`). The shared `ratio()` is correct, so verdicts are right, but a zero-capacity failure gets no remedy and the oracle test reports 0. Make it return `f64::INFINITY` (or `UTILIZATION_CAP`) for demand > 0.
21. `Sec::load` (`catalogue:227`) turns a zero section into `NotApplicable` (Err), not a failure; a zero-capacity input should be a `Fail`.
22. `bridge-and-connections:11, 21-22`: bridge ULS uses a fixed `kmod` medium (0.8), only the crowd load with γ 1.5 and no permanent load; k_h from the depth only; fatigue S-N `a = 15, b = 4` unverified. `T-121..T-124` are model-grade, not code-grade.
23. `fire:132-134` `cladding_times`: `t_f = t_ch` for type F and `0.8 t_ch` otherwise is not the EN 1995-1-2 3.4.3 text [V, low]; `fire:138` calls `charring_rates` with `h_p = 20` for the cladding rate. Spec E9 applies `k_h` in fire (`26.46 kNm`), code does not (`24.44 kNm`, −7.6 %, conservative); choose one and pin it.
24. `component T-93` η values (glued 1, nailed 4, bolted 6, connectors 3) are the weakest unverified row group; check against Annex C Table C.1 before use. `T-95` bracing `q_d = k_l N/(30 l)` and `F_d = N/50, N/80` are [V].

## 2. EN 1996 findings (ranked)

### S1

25. **f_vk0 is material independent and the DE f_vlt uses one f_bt,cal for all units.** `K96/normative-tables/🦀️.rs:204-214, 217-225`. `f_vk0_mpa` returns 0.30/0.20/0.10 by mortar class for every unit and `0.30` for thin layer. EN 1996-1-1 Table 3.4 (public check EN6-34, `ndp-public-verification.md` E96-15/16/18): clay GP M10-M20 0.30, M2.5-M9 0.20, M1-M2 0.10, thin 0.30, lightweight 0.15; **calcium silicate, concrete, AAC: 0.20 / 0.15 / 0.10, thin layer calcium silicate 0.40 (AAC/concrete 0.30), lightweight 0.15**. The shear verdict for non-clay masonry is unconservative: CS M10 at σ = 0.2 MPa gives `f_vk` 0.38 vs 0.28 MPa (+36 %), M5 +22 % (script B3). The extra `groups234Cap 0.15` (`:211`) has no EN basis. DE `f_vlt` (`:221`): `f_bt,cal = 0.026 f_b` for every unit; ZAPF: 0.020 hollow, 0.026 perforated, 0.032 solid; hollow units are overestimated by 25 % (script B4). The oracle `tables.json` repeats `fvk0Mpa` and `0.026`, so it is not independent. The "fvk0 / fvlt corrections" announced in `ndp-public-verification.md` (E96-15/16/18/21) are **not applied**: only the clay `K` groups 3/4 and thin-layer clay groups 1/2 were. Fix: `f_vk0(material, mortar_type, mortar_class)` per Table 3.4, `f_bt,cal` per unit type (needs a `unit_kind` field: hollow/perforated/solid), keep `UNVERIFIED_NDP m03.*` until the print check.
26. **Thin-layer and lightweight K for non-clay units.** `normative-tables:124-143`: thin layer `_ => 0.80` for every non-clay material and group (public EN6-33: calcium silicate G1 0.80, G2 **0.65**, +23 % in `f_k`); lightweight non-clay `0.45` has no source (clay 0.30 is the only checked value). The clay values 0.75/0.70/0.50/0.35 and GP 0.55/0.45/0.35/0.35 are correct. Aerated GP `0.55` for all groups: Table 3.3 has one value (Group 1 only) [V]. Fix per material and group, add a `FkTableNaDe` for the DE annex (below).
27. **DE f_k from invented exponents.** `normative-tables:160-176`: DE uses `K f_b^0.65 f_m^0.25` with K 0.60/0.50/0.45/0.40. DIN EN 1996-1-1/NA provides tabulated `f_k` (Tables NA.5ff) per unit type, strength class and mortar group, and the spec M-02 says tabulated values override; `m02.k-de` is on the unverified list yet drives every DE compression verdict. Example: HLz 12 / NM IIa gives 3.76 N/mm² from the formula vs about 4.4 in the spec [V]. Fix: key the NA tables (completion gap), warn on the formula result with `UnverifiedBasis`.
28. **Wall-level shear never uses l_c.** `K96/evaluate-wall/load-case-checks/🦀️.rs:201-207`: `V_Rd = f_vk/γ_M · A` with the full net area and `σ_d = N/A`; EN 1996-1-1 6.2 uses the compressed length `l_c = 3(l/2 − e)` and `σ_d = N/(t l_c)`; `M-20` (`catalogue/shear-and-lateral:21-31`) does it correctly, so the catalogue and the wall check disagree. For `N = 300 kN`, overturning 275 kNm, l = 3 m, t = 0.365: wall check 226 kN vs M-20 165 kN (+37 %, unconservative, script B6). The wall model also derives the shear demand from the wall's own out-of-plane wind reaction (`fire-and-design-effects:48` `v_k = 0.5 w H L`), which is not an in-plane bracing force and has no overturning moment. Fix: take V and M_overturning from the bracing analysis (M-21) or the load case, use `l_c`, and make `v_slide` (`μ N/γ_M`) a documented friction option, not part of EN 6.2.

### S2

29. **Annex-specific NA-DE rules are applied to the EN annex.** `load-case-checks:59,68-71,74`: `phi_2_slab_span` and `eccentricity_from_slab_rotation_m` (`factors-and-geometry:119-131`, NA-DE) multiply `Φ_top`, `Φ_bot` and `Φ_m` for **both** annexes; `Φ_2` is also applied to `Φ_m` although the rule is a top/bottom restraint reduction in the NA (`m13.phi1` unverified). The EN result is conservatively wrong for slab spans > 4.2 m; spec X-examples (slab span 0) are not affected. Also `e_θ` is capped at `0.05 t` (`:124`) which makes it a minimum-eccentricity-sized term, not the NA formula [V, low]. Fix: gate on `annex == De`, apply `Φ_2` only where the NA says so.
30. **Concentrated load: no `a1`, always `γ = 1.35`.** `load-case-checks:360-361`: `concentrated_beta(0.0, ...)` caps `β ≤ 1.25` (spec X5 needs `a1 = 0.5 m`, `β = 1.3409`, 583 kN; the wall check yields 544 kN), and `f_ed = GAMMA_G_SUP · F_k` treats every concentrated force as permanent (imposed would be 1.5). The `A_b ≤ 0.45 A_ef` limit is emitted as a failing check (`:414-433`), EN only drops the enhancement (β = 1.0) above 0.45; the failure is non-normative (false fail). Fix: add `a1` and `kind` (permanent/imposed) to `ConcentratedLoad`, make the 0.45 rule a `Warn`.
31. **`rho_n` for fewer than two supported sides.** `factors-and-geometry:75-85`: `match support_sides { 2 => ρ2, 3 => ..., _ => 4-sided }`; 0 or 1 sides take the 4-sided branch with `ρ = 0.75` (h_ef = 0.75 h) instead of a free-standing wall (EN 5.5.1.2: h_ef = 2h) (script B7). `rho_2` (`:70-72`) knows only slab bearing ≥ 2t/3, not the floor type (timber floors ρ2 = 1.0, crosscheck E96-38, still `m10.rho2` unverified); `catalogue/vertical-load:21` repeats it.
32. **Flexure adds horizontal bed-joint reinforcement to the vertical-span moment.** `load-case-checks:270`: `m_reinf = A_s,h f_yd 0.9 t l_ef` added to `m_masonry` for the vertical span; bed-joint steel is perpendicular to the vertical-span bending and acts for the horizontal-span `f_xk2`. ## 3. Cross-cutting edge cases checked

- Zero or vanishing capacity with demand > 0 fails in every checked path (`ratio()` cap, `worst()` `.max(1e-9)`, wall `n_rd.max(1e-9)`). Zero demand over zero capacity passes (`ratio(0, 0) = 0`), which hides a degenerate section with no load; a zero section in the catalogue is `NotApplicable` (item 21), not `Fail`.
- NaN: `ratio()` maps non-finite to the cap, so NaN fails; the one real NaN leak is `notch_kv` (item 8).
- Units: kernel in N, mm, N/mm² (timber catalogue) and Pa, m (masonry catalogue); the conversions inspected (`Outcome::stress/force/moment/length`, `t04`, `t60`, fire minutes to seconds, `Quantity::*`) are consistent. The E11 conversion is correct (see section 4). The only unit hazard is T-64 (item 14).
- Divisions: `n_ef_value` with `d = 0`, `a1 = 0` returns NaN or inf (fails); `kc_factor` with `lambda_rel` NaN returns NaN (fails); `lambda_rel_m` returns 0 for `m_crit ≤ 0` (`material-and-annex-factors:172-178`), giving `k_crit = 1`, an unconservative fallback when the section modulus or the eigenvalue is zero (the member also has zero bending capacity so it still fails through `w_m3 = 0`).
