## 24th pass: soundness of directory-stamp vouching, and the real-index measurement

Stamp: one `readdir` with file types plus the directory's own stat, taken while the directory is older than the racy window before `observedAt`: `[mtimeMs, ino, dev, sorted names of symbolic-link children]` (file `directory-stamps.json`, version 2; a re-stat after the listing rejects a torn read). A directory "holds" when its current mtime, inode and device equal the stamp and it is not within the racy window.

Rules (while the parent stamp holds), each with its argument:
- listing rows (`readdir`, `readdirNames`) and `lstat` of a child: names and node types of a directory change only by create, unlink or rename inside it, each of which sets its mtime and ctime. An `lstat` of a symbolic link says `symlink` whatever its target does.
- (a) `exists`/`fileExists`/`directoryExists` true and `stat` of a type, for a child that is not in the symlink set: a plain entry changes kind only by unlink plus create, which moves the parent. A child in the symlink set is never vouched: its answer follows the target, which can change without touching this parent (oracle cases `remove-link-target`, `replace-link-target-with-dir`; the same set also guards absence rows, where a symlink to a file answers `directoryExists` false until its target becomes a directory).
- absence rows (`exists`, `fileExists`, `directoryExists` false): vouched by the parent stamp for a name that is no symlink; and vouched with no stamp at all while the parent directory is missing (ENOENT or ENOTDIR on `stat`), since nothing can exist below a missing directory.
- (c) a `resolve` of a relative or absolute request whose resolved file lies in the directory the request names: Node's file resolution probes only entries of that directory (name, then each extension), so it is vouched when that directory holds and no child whose name starts with the base name is a symlink. Bare specifiers and directory resolutions stay doubtful: their probe chain (node_modules walk, package.json fields) is not recorded; recording it at observation time would need a probing resolver and is not done.
- (d) analysis rows are vouched when their own source stamp equals the recorded one and every nested row is vouched (unchanged rule; it gains from the rows above).
- Racy: a directory touched within the racy window of `observedAt` (or of the pass) is never stamped, so a later change inside the same timestamp tick can never be mistaken for no change.
- Directory ancestors: a retargeted symlink ancestor resolves the stamped path to another directory, whose inode differs; the stamp records inode and device.
Not covered, by design: a plain entry replaced by an identical-timestamp change inside a directory whose clock granularity is coarser than the racy window (the window is 2 s); a file-system that does not update directory times (stamps would then be unsound; none of the supported ones does).

Oracle: `🕰️generations/🧪️tests/🛡️stamp-soundness` (Python builds the fixture, records the facts, applies each mutation and says which facts still hold; the JS doubt must flag every fact that no longer holds): add, add-candidate (new extension probe), remove, rename, replace file with dir, replace dir with file, retarget symlink, rename over, remove and replace a link target in another directory, add a missing tree, add a deep missing tree, nested add, touch, none, and touch-then-add inside the racy window. 16 tests pass. Sabotage checks: dropping the symlink guard fails `remove-link-target`; an earlier version without the absence guard failed `replace-link-target-with-dir`, which led to the guard on absence rows.

Measurement on the real index (681,097 rows; stamps published as of now, a fresh process, no journal; `🧰️scripts/integration-index-memory.ts`): doubtful rows of 674,390 verifiable: 579,687 (no stamps) -> 291,118 (directory stamps) -> 119,447 (these rules). The 119,447: 53,012 closure rows (skipped by the fact check, answered by the closure settler), 13,884 environment field rows (cheap read), 31,723 analysis and 6,697 file rows whose files changed since the index was built hours earlier (legitimate), and about 14,000 not vouchable by design (bare resolves 3,361, realpaths 2,706, typescriptText 5,230, the rest under 3,000). A freshly published index would carry far fewer changed files; the structural leftover is therefore about 14,000 rows, not a few thousand, until bare resolves and typescriptText get recorded probe chains and stamps.
