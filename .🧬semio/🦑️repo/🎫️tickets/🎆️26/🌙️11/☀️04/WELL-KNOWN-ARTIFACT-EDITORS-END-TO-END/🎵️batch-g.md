## Phase 1 findings

A real trim needs a `patch-frames` mutation (schema-first leaf: json/proto/graphql/ts/rust, oracle catalog, feature rows) modeled on wav `patch-data` (about 19 files). Not done blind.
- wav: complete table editor (`edit-audio` command: set sample, insert/append/remove frame, insert/append/remove channel, set sample rate; revision-guarded, bounded patches, fmt ext preserved, TS twin + language-agnostic fixture). No range-trim gesture (repeated remove-frame only).
- mp4: window hardcoded `Unsupported` with text "playback export not registered" although the editor registers `playback_app_io` and passes a live resource. Snapshot edits via Details (insert/remove track and sample, codec, dimensions, sync, ftyp, movie). Natural codec round-trip exact.
- avi: same window defect as mp4. Details edits: stream/chunk insert/remove, headers, idx1.
- Fixtures are valid by ffprobe: mp3 12.0 s 44.1 kHz, wav 12.0 s pcm_s16le, mp4 h264 47 frames, avi mjpeg 45 frames.
