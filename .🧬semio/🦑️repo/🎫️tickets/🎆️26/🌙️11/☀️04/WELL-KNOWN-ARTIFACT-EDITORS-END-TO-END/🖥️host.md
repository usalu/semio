# Editor Host: Architecture Map and Batch Contract (T02)

Paths below are relative to the repo root. `OS` = `🧰️framework/🛍️products/💻️os`, `ENGINE` = `OS/🔨️modules/📺️renderer/🧑‍🎨engine`, `SHELLHOST` = `ENGINE/🧱️elements/🏛️ShellHost`.

## 1. How stdio artifacts get editors (answer to task 1)

Neither a generic editor per format family nor a per-artifact `✏️editor` folder. The model is per-subset surfaces, published by hub family plugins, rendered through seven frozen window kits.

1. Surface: every subset owns `✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/<kind>/🏅️standards/<ver>/🪆️subsets/<subset>/{✏️editor,👁️viewer}` with `🎭️modes/<mode>/🪟️windows/<window>/{🦀️.rs,🟦️.ts}`. The window is a Rust view-model built by a window kit. 90 `✏️editor` and 88 `👁️viewer` surface dirs exist. The artifact-root `🎒️zip/✏️editor` is not a surface; it is pure archive text-edit logic (`ZipSetNode`, rename/comment) used by the zip surface.
2. Window kits (`OS/🔨️modules/🔌️plugin/🪟️window-kits`): `framework.window.{document,image,media,mesh,table,text,tree}`. Stdio windows use exactly these (grep of all stdio window TS twins: document 160, mesh 376, image 66, table 60, tree 43, text 36, media 21). The renderer has no per-kind code; kits emit generic `BuiltNode` trees (stack/text/button/image).
3. Publication: ten hub family components assemble surfaces into one plugin each: `🌎️hub/🧩️compositions/🗄️stdio/🧩️component` (plugin `stdio`: txt xml json csv md tsv html) and `🧩️extensions/{🖼️image,🎵️media,🛠️cad,🏠️bim,🔺️mesh,📘️pdf,💼️office,🧿️semio,🔢️binary}`. Each has `🧩️component/🔣️.json` (manifest, apps with ids `<kind>@<standard>/<subset>#<editor|viewer>`) and `🦀️.rs` (`dyn_enum_close!` app enum, `PluginBuilder::editor/viewer/host_artifact/activation(OnArtifactKind)`).
4. Catalog: `✏️s/🧑‍💻dev/🧩️catalog/🤖️generated/🔌️plugins.json` holds `activationEvents: on-artifact-kind:s.stdio.<kind>` for 37 kinds; `🚀️playgrounds.json` holds 90 `stdio-*` variants (one per editor app, react ports 6110..6399). Mount tests exist: `🌎️hub/🧩️compositions/🗄️stdio/🧪️tests/{🚢️shipped-fleet,✏️editor-catalog,🧩️component-assembly}/🦀️.rs`.
5. Resolution and mount (browser/React shell):
   - `os.open-artifact` (`OS/🎮️commands/🗿️open-artifact`) is replayed by `SHELLHOST/⚡️host-effects/🎯️replay-shell-command-effect/🟦️.ts`.
   - `SHELLHOST/📬️artifact-opening/🔶️catalog` resolves via `AppRouter`/`OpeningResolver`; a miss triggers `installActivationOwnerAndResolve` (installs the `on-artifact-kind:` owner, retries once).
   - `SHELLHOST/📬️artifact-opening/🔸️open-artifact-app` installs the owning plugin (WASM), `createAdmittedShellInstanceV1` creates the app instance, a `PreparedArtifactOpeningTarget` is published, then `openDocument` attaches the document.
   - Lazy loading: plugin WASM is installed on first open (`SHELLHOST/🚀️plugin-lifecycle`, `PluginSource` multiplexer; dev uses streamed module sources, prod bundled sources). Family plugins depend on `stdio`.
   - Stale guards (already present, do not duplicate): `isCurrentEffectOwner`/`canOpen` re-checked after every await; `SHELLHOST/🔀️surface-switch` seals instances before teardown (`createSealedInstanceLedgerV1`, bounded 64); `runArtifactCreationReadyOpeningV1` releases the prepared target on retirement; `createArtifactCreationCatalogMountV1` binds creation to a catalog generation.
   - Controls: role switch editor/viewer navbar (`surfaceRoleAppsV1`), "Open with..." (`groupOpenWithEntries`), default-app settings, mode switching, window kit actions as commands/menus/shortcuts via the manifest `ActionDefinition`s. Loading/error: `resolvePluginCanvasStatus`, `ShellFaultBoundary`, replay-refusal notices.

## 2. Host contract for batch editors A-H

A batch owner makes an artifact "work end to end" when all of the following hold. Nothing here needs host code changes per artifact; if a batch needs one, report it to T02.

C1 Surface completeness. For each artifact kind, every declared subset has an `#editor` and a `#viewer` app in its family component manifest (`🧩️component/🔣️.json`) and in the `dyn_enum_close!` enum + `PluginBuilder::editor/viewer` calls of the family `🦀️.rs`. App id grammar is frozen: `<kind>@<standard>/<subset>#<role>` (build via `surface_app_id`, never hand-written in Rust).
C2 Activation. The family plugin declares `ActivationEvent::OnArtifactKind { kind }` for the kind (host installs the owner lazily from `on-artifact-kind:`); `🔌️plugins.json` and `🚀️playgrounds.json` entries are generated, do not hand edit.
C3 Window kit only. A window must render through one of the seven kits and declare its `WINDOW_KIND_ID`/`BODY_KEY` in the TS twin. No bespoke renderer element, no host React code per artifact. Payload larger than `UI_TEXT_MAX_BYTES` (512) must go through the kit's paged carrier (see image kit), never fail assembly.
C4 Unavailable is a mounted state. A snapshot without a projection renders the kit's `render_unavailable*` (localized "Preview unavailable"/"Vorschau nicht verfügbar"), never an empty node, never an assembly error that blanks the window.
C5 Capabilities. Every user action is an `ActionDefinition` on the window kind (id, `LocalizedLabel::native(en, de)`, `ActionKind::Mutation` only on the editor). Viewers are read-only by type (`ViewEmit`); the runtime rejects mutating verbs with `viewer.read-only`. Keyboard shortcuts and menu entries come from the action's accessibility spec; every control carries `AccessibilitySpec` label/description in en and de (English first, no default locale).
C6 Commands. Mutating commands live in `✏️editor/🎮️commands/<cmd>` (or the mode's `🎮️commands`) with schema first (`🧬️schema/🔣️.json`), Rust apply, TS twin, and a test with a fixture; the stdio snapshot-edit actions (`SNAPSHOT_EDIT_ACTION_IDS`) must address their exact subset editor scope (checked by `assert_detail_routes` in `✏️editor-catalog`).
C7 Lifecycle and disposal. Editors own no JS resources: all state is in the WASM guest behind the instance. The host destroys the instance via `plugin.destroyApp(instanceId)` and `closeDocument`/`retireDocumentAttachment` on switch/close; a surface must not spawn workers, listeners, object URLs or timers of its own. If an editor genuinely needs one (media transport, 3D), it must be created through the existing hosts (`🎬️MediaTransportHost`, `🌐️World3dHost`, `🖼️IconRenderHost`) which are tied to the mounted window lifetime. Cancellation and progress for expensive work go through the plugin job/progress lanes (`🔌️plugin/👷️job`, `⏳️operation-progress`, `♻️cancellation`); do not add ad hoc async.
C8 Stale-load safety. Any async step that outlives a gesture must be admitted through the host effect owner (`isCurrentEffectOwner` / `canOpen`) before it publishes; never write to shell state from a bare promise continuation.
C9 Dead ends are visible. The open path must end in either a mounted window or a localized refusal notice (`📣️replay-refusal/🔣️.json`, en+de). See fix F1.
C10 Tests per editor (test-first): (a) Rust unit/law test in the subset's `🧪️tests` (open fixture, render window, apply each command, round trip); (b) the family `🚢️shipped-fleet` and `✏️editor-catalog` laws stay green; (c) one language-agnostic fixture JSON with an oracle produced by a third-party library (AGENTS.md); (d) host-level browser journey evidence is collected by T06 on the `stdio-<kind>` playground variant (open fixture -> window mounted -> edit -> save -> reopen -> switch away -> no console errors).
