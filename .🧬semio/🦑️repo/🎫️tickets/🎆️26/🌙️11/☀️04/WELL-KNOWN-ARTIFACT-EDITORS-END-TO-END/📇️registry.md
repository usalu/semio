# 📇️ Registry and Resolution (T01 sonnet-registry)

## Pipeline as traced

1. Definition: `🗿️artifacts/<a>/📜️artifact-definition.json` declares `representations[]` (mimes, extensions, aliases) and `runtime_capabilities[]` (category `representation` carries the same claim set).
2. Registry: `📇️registry/🧬️contract/🏗️assembly` `source_format_descriptors` publishes one `FormatDescriptor` per `representation` runtime capability (kind_id = representation id, short_id = first extension without dot, aliases, mimes, extensions). `ContributionRegistry::validate_catalog` and `validate_format_descriptors` (store lifted io) reject any extension or MIME claimed by two different artifacts, so claim ambiguity cannot exist in a published roster.
3. Global format catalog (`os-io` `format_catalog`, keyed by kind_id, short_id, alias). Before this ticket the only lookups were by key (`format_descriptor`, `normalize_format_kind`) and the picker accept filter. There was NO file name or MIME to format resolution anywhere.
4. Open: every shell open goes through `os.open-artifact` with an explicit dialect coordinate and `OpeningResolver` (plugin host routers): explicit user default pin, else owner plugin surface, else first, else `surface.unknown-dialect`. `AppRouter` is keyed by `(ArtifactDialect, AppRole)`. No MIME or extension is involved.
5. Natural-file open (`openNaturalFileOwnerV1`) is per app: the editor's Open/Save File actions carry one `extension` and `mediaType` default; the picker accept is `${extension},${mediaType}`. Aliases therefore reach the picker through the MIME type; a native picker that filters by extension only sees the canonical one.
6. Stdio ships as 10 components (stdio plus 9 family components). `every_stdio_kind_is_opened_by_exactly_one_package` pins kind to package.

## Findings

- F1 No canonical extension/MIME/alias resolution API. Fixed (below).
- F2 Registry sorted `extensions` on canonicalization, so `.jpeg < .jpg`, `.htm < .html`, `.tif < .tiff`: exports (`extensions.first()`) would have switched to the alias. Fixed: declared order is canonical.
- F3 `html` and `tsv` had NO `representation` runtime capability, therefore published no `FormatDescriptor` at all (never resolvable by key, extension or MIME). Fixed.
- F4 Aliases `.jpeg .tif .htm .markdown .stp` were not claimed. Added.
- F5 Roster: 36 identities. `idf` (definition-only, no surface) and `idml` (codec, not yet in roster) are the two pending artifacts; the contract test tolerates them being unresolved and requires correct resolution as soon as they publish. `inventory` is a TS package, not an artifact.
- F6 gltf registers two representations (`.gltf`, `.glb`), both owned by one artifact: resolution of `.glb` returns the gltf artifact.
- F7 Multi-revision artifacts (gif, pdf, dwg, ifc) publish ONE descriptor per distinct claim set (min representation id), so there is no intra-artifact conflict.
- F8 composer, grammar and inference runtime capabilities are also absent from html and tsv (only codec and schema); not mine, flagged for Batch A/B.

## Decisions (contract)

- D1 Resolution precedence (frozen, `🚪️io/🧭️format-resolution`): explicit key (kind, short id, alias; unknown explicit key is an error, never falls through) > longest registered extension suffix of the file name, case-insensitive, path separators ignored > exact MIME (parameters and case ignored) > unresolved. No implicit fallback format: raw bytes are opened by asking for `bin` explicitly. A browser MIME that disagrees with the extension (`application/zip` for `.docx`, `application/octet-stream` for `.glb`, `image/svg+xml` for `.xml`) never wins; the disagreement is reported in `mime_disagrees_with`.
- D2 `extensions` order is canonical export precedence: first entry is the export/short-id extension; later entries are import-only aliases. The registry no longer sorts. Schema-first: the definition array is the single source.
- D3 `aliases` stays for dot-less lookup keys; alias extensions go in `extensions` (and in the representation capability claims; descriptor string joins claims in order).
- D4 A1 (`native_factory.extension = semio` for avi/bcf/mp3/mp4): NOT changed, coordinator ruling contested with evidence. `pack::snapshot::ArtifactDsl::EXTENSION = "semio"` in each of those artifacts' `🚪️io/📝️text/📸️snapshot/🦀️.rs`: the native codec is the semio DSL text snapshot of a binary format, keyed by its codec extension, not the file extension. Renaming would mislabel a text snapshot as `.avi` and change DSL envelope, hashes and receipts for no resolution benefit. Contract: `native_factory.extension` is a codec key, independent of `representations[].extensions`; natural-file extension comes from the editor's `NaturalFileCodec`. The byte-level `.avi/.mp3/.mp4/.bcf` import belongs to the media and bim batches (G, F).
- D5 A2 keep `stdio.pdf.1.7` and `stdio.native.pdf17.v1`: receipts require `(artifact_kind, schema)` unique, so a second factory on one kind needs its own schema. Convention for any multi-revision artifact: first revision `stdio.<a>`/`stdio.native.<a>.v1`; each additional revision with its own native codec `stdio.<a>.<rev>`/`stdio.native.<a><rev-digits>.v1`. gif, dwg, ifc have no per-revision codec so nothing to rename.
- D6 A3 idml and idf roster wiring is generator work (heavy queue); not hand edited. idf stays definition-only per coordinator.
- D7 A4 idf `dependencies: []` kept: definition-only, no code reuses txt.
- D8 A5 fixed by correcting the note: `definitionOnly` means substituted in the light roster (ifc, semio); epw/gif/bmp/wav/binary keep runtime crates.
- D9 A6 implemented per D2/D3 for jpg `.jpeg`, tiff `.tif`, html `.htm`, md `.markdown`, step `.stp`.
- D10 A7 `.zz` for zlib kept (deflate codec key is `zz`; changing alters hashes). `.zlib` alias can be appended later with D2.

## Addendum 3: declared owner revision, resolver fixes, generation target

- Owner rule (schema-first): `representations[].owner: true` marks the most complete revision among representations sharing one claim set. The registry (`🏗️assembly` `validate`) requires exactly one owner when several share a claim set, and `source_format_descriptors` publishes the owner (then lowest id) — no more implicit "lowest id". Declared owners: pdf `1-7` (lossless COS model; 1.4 page model drops fonts, images, annotations, metadata per the T17 audit), gif `89a` (superset of 87a: GCE, comment and application extensions; its editors cover them), dwg `ac1024` (the only revision with a native codec), ifc `4`.
- ifc evidence and caveat: ifc publishes no native codec for any revision (definition-only), so fidelity cannot be decided from codecs. Chosen: `4` (current edition; IFC4 supersedes 2x3, shares the Part 21 reader, and has the base `*` editor). Each revision decoder validates its own exchange schema (`decode_ifc4_document` → `validate_ifc4_exchange`), so a `.ifc` carrying `FILE_SCHEMA(('IFC2X3'))` is refused by the owner and must be opened through Open with `s.stdio.ifc@2x3/*`. The proper fix is a content sniff of `FILE_SCHEMA` (not implemented; extension cannot discriminate).
- Fixture coverage: `ownerCoordinates` in the hub fixture and `a_multi_revision_artifact_resolves_to_its_declared_owner_revision`.
- Resolver fixes (Rust and TS, same fixture): extension is resolved first and an ambiguous MIME no longer aborts it (it is dropped from `mime_disagrees_with`; with no extension match it is still refused); lower-casing is ASCII-only in both; a `null` explicit is absent in TS. Fixture cases: `ambiguous-mime-*`, `null-explicit-is-absent`, `uppercase-name-and-mime`.
- Generation chain: the claims are produced by project targets `generate-stdio-format-claims` and `check-stdio-format-claims` in `✏️s/🧑‍💻dev/📋️project.json` (script `stdio-format-claims` in `✏️s/🧑‍💻dev/📜️script.ts`, logic `stdioFormatClaimsTextV1` in the registry's `🧭️format-claims/📜️generate.ts`; inputs: every definition, the editor-catalog fixture, the generator; output `🚀️entry/🧭️format-catalog/🤖️generated/stdio-format-claims.json`). `generate` and `typecheck` depend on it, so a fresh checkout regenerates it, and the Rust parity test catches drift. The output sits outside `🧩️catalog/🤖️generated` so the plugin-registry `check-generated` does not flag a foreign file. Not run through `repo` yet.

## Addendum 4: content sniff for shared claim sets

- Schema (definitions): `representations[].sniff = { window, contains[] }`, validated in the registry (window 1..65536, non-empty ASCII needles no longer than the window, no needle shared by two revisions of one claim set). Declared: gif `GIF87a`/`GIF89a` (window 6), dwg `AC1018`/`AC1024` (window 6), ifc `'IFC2X3'`/`'IFC4'`/`'IFC4X3` (window 4096; the closing quote keeps `'IFC4'` from matching IFC4X3). pdf declares none: 1.7 is the lossless superset and owner, so every `%PDF-1.x` goes to 1.7 (1.4's page model drops fonts, images, annotations and metadata, so routing 1.4 files there would lose data). Files no revision recognises (other dwg versions, ifc without a known schema) fall back to the declared owner.
- Resolver: Rust `pick_revision` (`🚪️io/🧭️format-resolution`) and TS `pickRevisionV1` share the fixture section `revisionSniffs` with real header bytes (GIF, IFC2X3/IFC4/IFC4X3 STEP headers, a schema beyond the window, dwg version bytes, empty head). Resolution stays name/MIME first; sniff only picks among the revisions of the matched format.
- Generated claims (`stdio-format-claims.json`) carry `revisions: [{ kindId, artifactRef, sniff }]` (owner first) for multi-revision formats; revisions without a catalog editor (ifc 4x3 today) are omitted, so an IFC4X3 file still opens in the IFC4 owner until its editor joins the catalog.
- Shell call shape (sonnet-host was not reachable by message): `S_FORMAT_CATALOG_V1.revisionsOf(ownerKindId)` plus `pickRevisionV1(ownerKindId, revisions, head)` with the first 4096 bytes of the picked file, then `artifactRefOf(pickedKindId)`. `artifactRefOf` answers every revision kind id.

## Addendum 7: label localization finding, multi-format design, follow-up

- Accessible-label localization: NOT changed, contract convention contradicts the ruling. The UI contract carries no locale by design (`🏗️builder/🧭️vector-reference-and-colour-input-builders`: "already localized by the caller — this crate carries no locale, so a plugin resolves both from its own `LocalizedLabel`s"); every `Label`, container label, placeholder and tree label is ONE already-resolved string, chosen per active locale when the plugin emits the node. The no-default-language rule is satisfied at authoring: `LocalizedLabel` (en and de both required, locale and terminology checked) is what plugins, action arguments (which name staged-form Field containers) and the shell use. The unnamed-control law needs no language: it checks the resolved string a renderer would announce. The static fixtures are test data in the same single-string form as every other fixture label; making `accessibility.label` an en/de map would change every node, every renderer and the wire for one field while all sibling labels stay single strings. Left as a decision for the coordinator; if overruled, the change touches `AccessibilitySpec.label` (Rust, generated TS union, wire, retained validators, all renderers) and the 14 fixtures. Recommended instead: add a manifest-level check that every `LocalizedLabel` an editor or window kit declares has non-blank en and de (authoring-time guard), which covers stdio Details args.
- Multi-format natural codecs, schema and design (migration waits for the coordinator's go after the first compile wave of the batch crates):
  - Types: `NaturalFileFormat { format_kind, extension, media_type, binary }`; editors declare `natural_file_formats() -> &'static [NaturalFileFormat]`, first entry canonical (default save format); `encode_natural_file(format_kind, snapshot)` and `decode_natural_file(format_kind, bytes)` replace the single-codec methods. Mounted Open offers every format's extension and MIME in its accept list; mounted Save carries a hidden `openedFormatKind` argument; "Save as <format>" is one action instance per declared format with an explicit `formatKind`.
  - Opened format is recorded as document metadata, persisted with the document: a `sourceFormatKind` field in the document's persisted envelope metadata (written by the load/genesis `Effect::LoadDocument` emission when the opened bytes decode; absent for documents created in-app, which save in the canonical format), restored by the archive reader so reopen and restart keep it. Save ignores shell session state. Needs the archive/envelope owner (persistence, T03) to add the field and its round-trip test.
  - Fixtures: extend `📄️natural-file-lifecycle/🔣️.json` rows with `formats[]`; the claims generator already carries every extension, plus per-representation extensions (gltf already has separate gltf and glb representations; stl and ply need a second representation each).
  - Dependencies: batch E supplies the GLB encode, STL and PLY binary encode; one owner migrates the 81 files in a single pass after the freeze.
