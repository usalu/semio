Independent Terra Light source review found no emulator in the new 3D/5D scenarios: they use actual DOM scene attributes, framework host pages, local archive attachment and fresh browser peers. This is source inspection, not executed browser evidence.

The initial 3D scenario selected any object, checked creation only by count, never made a separate coordinate/property edit, and compared an `orientation` property while the actual spatial scene uses `rotation`. These omissions could miss transform loss. The author has changed it to identify exactly the created object, pick that ID, move its real projected X gumball through pointer events, require a position change, compare rotation as well as position/scale, persist the edited pose, and check undo/redo between created and edited states. Its runtime correctness remains unverified.

The initial 5D scene selectors named `window:puzzle5d-2d` and `window:puzzle5d-3d`, while owned window constants use `puzzle.5d.play.2d` and `puzzle.5d.play.3d`. The author is checking actual surface construction and correcting the selectors against that source contract. A parser or source-string route check cannot validate that runtime mapping.

The 2D persistence journey now requires a newly opened peer to attach the same archive and read the exact edited position map before the original page reloads. The earlier existence-of-any-file check could have accepted a stale archive and was removed as sufficient evidence.

All three actual UI journeys remain required. Root activation and owning native laws are waiting behind the verified live shared dependency producer; no browser runtime success is claimed.
