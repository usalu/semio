## 1. Activation and Time-Travel

### Activation (`T/l4-activate.sh <2d|3d|5d>`)
- Runs `timeout ${L4_TIMEOUT:-14400} repo run @semio-tech/framework-os-dev:activate-puzzle<dim>-react-prototype --lang=en` from the repo root.
  - Log: `T/🗑️generated/l4-activate-<dim>.log`, ending in `EXIT <code>`.

### Time-travel
- Runner: `repo run @semio-tech/framework-os-dev:time-travel -- --scenario <module> [--locales en|de] [--renderer react|wgpu] [--serve <url>] [--out <dir>] [--only …]`.

  - The locale flag is `--locales`, not `--lang`.
- Without `--serve`, or when nothing answers at the scenario's default serve, the runner activates first (`ensureDevServe` → `activatePlaygroundRuntime`, line 67), so it repeats the activation build. Starting time-travel without running the activation first is therefore allowed.

## 3. Review of the Time-Travel TypeScript Changes (l33)

Files:
- `✏️s/🔌️plugins/🧩️puzzle/🧪️tests/⏪️time-travel/🌍️copy/🟦️.ts` (`flagOn`/`flagOff`)
- `…/🧮️gaps/🟦️.ts:427,433`
- `…/🌄️drag-journey/🟦️.ts:198`

The worktree matches HEAD for all three.

### Types
No problems found.
- `textOfKey` returns `Promise<string>` (`🧰️framework/🔨️modules/⏪️time-travel/🧪️testing/🧱️chrome/🟦️.ts:54`), so `copy.flagOn.test(text)` is well-typed.
- `presenceText` returns `string | null` and is guarded with `roster === null ||`.
- `COPY[currentLocale]` is the en|de union, and `flagOn`, `flagOff` and `changeLocked` exist in both branches.
- Every `copy.*` and `COPY[…].*` key used in gaps and drag-journey exists in the plugin copy or the framework copy. The framework copy has identical en and de key sets (45 each).
- The self-references `COPY.en.items(...)` inside the arrow bodies predate l33. They are safe because the arrow return types are inferred lazily.

### Logic
- **flagOn and flagOff** (`/\bYes\b/`, `/\bNo\b/`, `/\bJa\b/`, `/\bNein\b/`) match the new 2D terminology labels: `◻️2d/…/✏️editor/🗣️terminology/🦀️.rs:47-48` defines `yes` and `no` with native and reuse values en "Yes"/"No" and de "Ja"/"Nein". `flag_row` puts that text in the tree-item description (`📌️panels/🔍️inspection/🦀️.rs:136`).
  - React `innerText` gives the label plus the description. wgpu gives `label` plus `description`. Both contain the word.
  - The row labels ("Locked", "Gesperrt") do not contain these words.
- **Wasm dependency.** These assertions only pass once the engine wasm carries the l33 Rust change (see section 1). A stale `pkg/` makes step 13 fail with `locked.ok=false` and an `after` text of `true`. That is a build-freshness failure, not a test bug.
- **Roster regex** `/⏪|is editing|bearbeitet\b.*\bVerlauf\b/` matches every en and de presence note in `🛠️ShellHelpers/🧪️tests/🧫️fixtures/🧫️time-travel-peers/🔣️.json` and the wgpu labels:
  - `{name} bearbeitet [gerade] [dies|{target}|den] … Verlauf`
  - `is editing …`
  - It cannot produce false positives on the related UI strings, because they have "Verlauf" before "bearbeitet" ("Der Verlauf kann … nicht bearbeitet werden", "Bearbeiten ist pausiert, solange der Verlauf bearbeitet wird"), and `\bVerlauf\b` rejects "Verlaufsbearbeitung".
- **Minor, not a bug.** The check is negative-only, and any `⏪` in the roster's aria-label would trip it. Today the roster `s-presence-peers` carries none without a peer.

There are no blocking findings in the TypeScript. The remaining risk for time-travel is environmental: disk space, the stale engine wasm, memory and reaper kills, and concurrent graph-service requests.
