The lifecycle scenario's instance and selection fields are published on the same World3dHost element. Its instance `id` is the actual object ID, and `position`, quaternion `rotation`, and `scale` are emitted by the per-object scene record. The host's gumball hit projection supplies `moveX` and `origin` in canvas-relative pixel coordinates. These facts are source inspection, not a successful browser run.

The initial scenario selected the created object and waited for `data-gumball-hits` without activating the perspective pane's Transform utility. World3dHost publishes those hits only with `gumballActive` and a transform mode. The existing gumball laws explicitly establish that selection alone leaves `gumballActive` false, while Transform plus a selection enables it. The author corrected this to unfold the perspective utility bar and click the perspective-scoped `#transform`. The utility definition confirms that ID, and the Window tests and pane fixture confirm the unfold ID pattern. Live browser execution is still required. The grid pick is heuristic; a successful selection check avoids a false pass, but may fail when the new object is not under the sampled pixels.
