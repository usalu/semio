## Cluster 3: the three "interactive ceiling" tests (fixed in the test harness, unverified)
The failures are not ceiling overruns. No step time was ever compared.
- `accept_suggestion_...` and `set_active_example_...`: panic `context root retains its original projection or Store issuer` (`SnapshotReadProjection::drop`, store `🔗️read/🪞️projection`). `measured_tool_work` builds a bare `ArtifactOwnedToolJobContext::new(...)` with unbound `draft` and `transient` roots (no `with_source_issuers`, no Store). At the end of each cold run the context drops live, and the drop assertion fires. A root that holds a projection and no read is deliberately not retirable (`Cursor::demands` refuses `UnsupportedOwner`), so a fixture context has to surrender it explicitly.
  Fix: `SnapshotReadProjection::forfeit_unissued(&mut self) -> bool` (refuses and keeps the issuer when a read is bound) and `ArtifactOwnedToolJobContext::forfeit_unissued(self) -> bool`. The two measured tests call `assert!(context.forfeit_unissued(), ...)` right after `original.finish()`.
- `open_vortex_suggestions_...`: panic `original Puzzle work remains in close custody` (100000 close turns). The budgets copy of `measured_tool_work` built `Puzzle3dWindowCommandWork` with a plain `Box::new` (and the fallback arm too), so its typed frame was never admitted through the original fixture. The close then released a frame it never owned and did not reach terminal-empty. The geometry-cache copy already used `original.construct_boxed(...)`. Fix: both arms use `construct_boxed` in the budgets copy.
