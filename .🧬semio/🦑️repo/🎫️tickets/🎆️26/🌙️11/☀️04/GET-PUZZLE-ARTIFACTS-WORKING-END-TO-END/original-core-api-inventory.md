# Original Core API Inventory

Bounded read-only inventory of actual interpreter/Core/runtime owners. No source edits or execution. The general interpreter already exists; the missing piece is its demonstrated original paid execution path, not absence of every opcode implementation.

## Genuine paid original owner

The actual exported type is CoreInstanceOpening (interpreter root pub use), not a found CoreOriginalOwner symbol. instance/root owns private ManuallyDrop<Option<CoreInstance>> plus OriginalCallerSourceLoan. Its complete public surface is begin, validate_original_context, resources_ready, immutable resources, advance resource construction, write_original_memory_step, terminal_is_empty and close_step. invocation adds begin_function_step, advance_scalar, invocation_values and close_invocation_step. No public mutable-Core transfer/accessor or alternate general advance/import-resume method was found for this paid owner.

advance_scalar has a real explicit small opcode plan: nop/end/return, direct defined call, drop/local/global, scalar loads/stores, constants and selected i32/i64 arithmetic. Its fallback explicitly refuses instructions without an admitted original physical execution plan. begin_function_step requires a defined function; admit_defined_frame similarly does not create an imported HostCall. close_invocation_step explicitly refuses a pending_host. Its result statuses are Pending/Complete/Cancelled/Deadline, with an actual separate instruction receipt; no HostCall variant. This is real resource/instruction/cancellation custody, but is not a hidden general import-suspension engine.

Runtime original_call retains the same paid Core and source. begin_original_call_step admits bounded inline scalar arguments; advance_original_call_step delegates only to advance_scalar, captures zero/one scalar result and closes the actual machine before result handoff. It does not currently provide general host-import suspension or arbitrary encoded input/output transfer. Existing funded memory copy is available as a genuine prerequisite, not a complete operation adapter.

## Existing general interpreter semantics

CoreInstance instance-state has begin_function/begin_export, step(fuel,StepControl), pending_host_call and resume_host. step drives execute_machine, preserves a Machine frontier and returns CoreStepOutcome::HostCall with actual fuel_used. instruction-execution enter_function_on handles imported functions by creating HostCall/PendingHost and handles defined frames. The memory-and-bulk-execution owner and general instruction owner already implement the broad runtime semantics. OwnedSemioInstance delegates to this machinery and exposes host resume. Runtime operation-begin-resume-and-cancel has real HostCall dispatch via reply_owned_host and resumes that same actor. These are existing implementations to reuse semantically, not evidence that their allocations/copies/releases currently carry Original StepContext receipts.

The general public Core methods take ordinary Vec arguments, clone host payload/function result vectors and mutate/grow machine storage without a StepContext parameter. The paid opening retains its Core privately and exposes only an immutable resources borrow. Therefore simply calling the general step on that owner is not an existing public lawful paid mechanism. An original admission/mutation/host-loan execution seam still needs real per-instruction physical planning, receipt/error/source/cancel custody and paid host suspension/resumption; inventing a second instance or moving resources through an unfunded mutable bridge would bypass the demonstrated ownership contract. No alternate paid general method was found under another related owner in this bounded actual source search.

## Current contradiction and scope

Phased startup returns actor=None/original_coreSome, while current legacy context/poll/job paths begin through owned_operation_resumes, which refuses original_core. Existing general actor HostCall execution thus cannot be presented as available to this phased path today. Native owned JSON progress proof remains complementary and does not establish general actor operation readiness. Existing production OS Run startup checkout/receive remains real and must not be described as globally test-only. No claim that general opcode semantics must be recreated from scratch, nor that a compatibility bridge is acceptable.

## Canonical Instruction Semantics Follow-through

Root inspected the actual current instruction-execution owner and paid invocation owner during maintenance-2, without Source edits or execution. The ordinary execute_machine at instruction-execution:44 handles structured block/loop/if bounds, branches, direct and indirect calls, table operations, numeric primitives, memory grow, reference operations and bulk operations through their existing semantic owners. Its current mutation implementation allocates arguments/results/control type vectors and pops or truncates resource-owning frames without original physical admission. return_frame:268, branch:278, pop_arguments:333 and take_results:340 make those effects explicit. CoreInstance::resume_host at instance-state:153 consumes the actual pending call and extends results without an Original StepContext.

The paid invocation engine at instance/invocation:14 independently decodes a small opcode set and prepays each physical change; unplanned opcodes refuse at line17. Its close_invocation_step:21 explicitly refuses a pending host call. Existing paid tests cover real opening, scalar completion, nested defined calls, memory transfer/store/load, denied physical mutation and paid cancellation, using Wasmtime independently. These are valuable existing laws to retain when consolidating semantics, rather than replacing them with a permissive general step.

A clean extension therefore needs one canonical decoded instruction/validated effect plan shared by ordinary and Original execution, with Original resumable admission and close before committing each effect. This must include import payload and pending-call lifetime, structured-control type storage, frame/result movement, table/memory/bulk growth or release and all error paths. Merely reserving an estimated whole-turn vector allowance around execute_machine would not demonstrate individual paid mutation or bounded suspension. Existing real instructions and result semantics remain the reference implementation; no new VM or fallback instance is justified by this audit. This is a design constraint, not an implemented or executed general crossing.
