## Action Ingress Loan Reachability

`command-routes/📥️staging/🚦️actions/🦀️.rs` loans the original ingress source into a local `ManuallyDrop`, awaits `dispatch_action_received`, and returns that same source to its slot before returning either `Ok(None)`, a result, or an error. Directly polling and dropping the public async action future during that await can bypass the return; that is a distinct caller behavior from an actor cancellation between completed turns.

The reactor's manifest-command route wraps both `handle_action` and `handle_action_invocation` with `drive_self_waking_ready` inside the instance turn. That helper pins the future and repolls it synchronously until `Ready`, so an ordinary user cancel delivered as a later reactor operation cannot interleave with that local loan; an `Ok(None)` ends the current call only after the loan is returned. The reactor export likewise synchronously drives `poll_kernel`. The self-wake bound panics after 1,048,576 pending polls, so panic/unwind remains an exceptional way to drop the loaned future.

The WGPU shell loads wasm plugins, and its Wasmtime host awaits `store.run_concurrent` and the component `call_poll` future. This audit has not proved whether dropping that outer host future, or trapping/suspending an imported host call, can interrupt execution while the guest-local Rust future holds the source; a normal UI cancel alone does not establish that event. The browser/reactor path has the same synchronous guest driver. If that outer interruption is demonstrated to preserve a resumable instance, the sound repair is to keep the original source resident in its ingress slot while dispatch advances by bounded borrowed steps, so cancellation and close can access it even if a caller drops a pending future. Merely adding a synchronous drop guard that destroys the source would violate the paid original-return protocol. No source changes or builds were made in this audit.
