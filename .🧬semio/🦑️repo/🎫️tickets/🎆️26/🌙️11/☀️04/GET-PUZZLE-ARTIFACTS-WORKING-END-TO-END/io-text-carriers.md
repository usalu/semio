# Canonical Text Carriers

## Confirmed Source Finding

The newly registered Puzzle foreign serializers currently wrap every result in IoPayload::Binary. The import readers already accept both Binary bytes and Text UTF-8 bytes. For JSON, TXT, SVG and DXF the genuine file format is text, so Binary changes the outer job-result representation into a byte-number JSON array. This is an avoidable transport expansion, independent of the exact closed float-word file format.

The independent 1024-node recipe estimates approximately 1201173 bytes for the actual pretty JSON file, approximately 1377054 bytes for its Text carrier, and approximately 5072386 bytes for the Binary byte-number transport. These are source-derived recipe estimates, not an executed guest-job output measurement.

## Authorized Correction

The integration agent is changing only newly registered typed format bindings: JSON, TXT, SVG and DXF use the existing Text payload via owned UTF-8 reuse. DWG, PDF, PNG and ZIP retain their actual Binary payload. Standard IDs, exact file bytes, closed float words, full material comparison, reader fidelity and all caller budgets remain unchanged. No new runtime library or compatibility branch is needed.

The neutral full route census will declare expected carrier kinds and the registered export laws will assert them. Actual seven exact-format pairs and independent full word/relational comparisons remain required. Source and native verdicts must be recorded separately; no actor or physical native success is claimed here.
