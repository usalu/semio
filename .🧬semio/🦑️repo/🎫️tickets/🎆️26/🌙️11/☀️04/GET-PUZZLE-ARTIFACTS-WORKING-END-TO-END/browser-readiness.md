# Browser Preparation and Portable Launch

The actual first diagnostic used an installed system Chrome override because the default Playwright revision was absent. That established the runtime fault, but it is not the final zero-touch ingress. Root Storybook acceptance and root time-travel now prepare Chromium before expensive build, server startup or activation. The helper calls the existing supported runToolchainsSetupV1 owner directly with the real Original, an issued control and network offline authority read from that Original. It does not mint an invocation, spawn a detached process, select a substitute browser or add a broad child grant. Cancellation and tool storage custody remain with the actual owner.

The helper selects the repository-owned browser cache, matching the existing installer cache environment. The tool owner verifies the installed Playwright registry executable paths for both Chromium and Chromium headless shell through its existing bounded command port; a Chromium directory alone can no longer report ready after a partial installation. Registry paths provide the actual host-specific executable names and revision behavior. Offline callers reuse a complete ready installation; missing installations remain refused by their original network authority. Linux prerequisite installation remains owned by the existing browser dependency policy.

Storybook, parity and time-travel share one schema-owned software WebGPU launch policy. This removes the Metal/Vulkan-only time-travel launch defaults while retaining parity headed-mode control. The policy exposes only repository-owned scalar/array types.

Six language-neutral cases cover shared launch options, complete Unix/Windows installations, a missing headless shell and an old revision without current executables and missing host libraries. Bun testing drives the actual serialized registry probe through Node VM with an independent file/registry port. These tests are queued under normal tool capacity, not reported as a pass yet. All eight changed/new TypeScript entry files parse through the registered Bun transpiler.
