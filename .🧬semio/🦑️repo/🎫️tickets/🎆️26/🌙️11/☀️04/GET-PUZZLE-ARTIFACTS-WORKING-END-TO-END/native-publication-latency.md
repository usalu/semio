# Native Puzzle3D publication latency

The registered native `editor-gestures` law failed on its first size, the one-object Concrete Forest example. Translate used 934 host turns, including 20 worker observations, and 1,673 Store units. Delete used 993 host turns, including 14 worker observations, and 1,879 Store units. The law subtracts those worker observations and compares 914 and 979 turns against a ceiling of eight. The 293.96-second test run covered example setup and both operations. [Registered baseline](🗑️generated/3d-registered-publication-latency-native.log)

The fixture runs mounted maintenance and then the real typed publication entry once per host turn. That entry already has a bounded loop over the current original receiver's Store units. The loop was returning early when a successful unit paid ownership at the same checkpoint and did not leave a receipt. It also returned on receipts whose only paid progress was copy bytes, retained capacity, or release bytes. The loop now recognizes all four paid ownership counters. A settled unit can also continue after an actual operation checkpoint change. An empty pending receipt yields to its receiver. The existing loop bounds, remaining original grant, cancellation checks, Work/deadline checks, and the result page acknowledgment boundary still govern each slice. [Mounted publication pump](../../../../../../../🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🧵️instance/🧾️typed-operations/📥️staging/📬️publication/🏃️mounted-run-and-pump/🦀️.rs)

Two native predicate tests cover each ownership counter independently, a changed settled checkpoint, and unchanged or empty-receipt yield. The existing condition failed the paid-progress test. The patched condition passed both tests, using the real retained progress type from warm native metadata and an isolated test executable. Rustfmt parsed the edited module and the scoped diff passed its whitespace check. [Failing predicate check](🗑️generated/publication-progress-red.log) [Passing predicate check](🗑️generated/publication-progress-green.log)

The integrated gate is `mutation_latency::one_mutation_publishes_in_a_bounded_size_independent_number_of_host_turns`. It still needs a native executable linked with the patched pump before any end-to-end improvement can be quantified. The baseline also counts substantial Store work independent of batching, so the eight-turn ceiling remains unverified.
