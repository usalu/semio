# Scoped Storybook Engine Prerequisites

Storybook build and development resolve and prepare exact active-scope engine producers before acquiring dependency, product, or Vite compiler holds. Published managed WASM bytes are outputs, never proof that their current Source producers have run.

## Scope Contract

StoryScope and package Storybook opt-ins support typed wasmPackages. Requirements are explicitly declared by consumers, deduplicated, bounded to 32 packages, and checked against the canonical engine Source-package catalog. Common preview has no native engine requirement. Renderer consumers declare the renderer catalog’s actual package requirements. Puzzle scopes add Puzzle; framework scopes add separately owned Flow. UI and Infinite have no engine requirement. No request treats all recognized Source packages as prerequisites.

The same selection filters Storybook managed delivery candidates. Exact producer project names come from canonical Source owners’ authored project manifests, including Puzzle’s package/project distinction (@semio-tech/puzzle-wasm → @semio-tech/puzzle-plugin:wasm). Native modes remain the Original’s prototype/release selection; these Source wasm targets do not declare profile configuration suffixes.

## Original and Ownership

Build bootstrap descendant expansion reads the same active-scope requirements before fresh issuance, then expands each concrete run <project>:wasm child with existing native/backend descendant logic. Received Originals are never retrofitted. Root build/test/development commands and authored workspace Storybook targets share route mapping; help and static serving declare no engine producers. Direct root Storybook development now participates in genuine fresh Native birth.

Runtime preparation forwards the received Original and its actual compiler admission phase to runOwnedBuildChildInvocationV1, one producer at a time. Preparation precedes Storybook’s dependency/product store holds, preventing nested builds beneath Vite’s holds. Existing native producer caches, leases, progress, cancellation, and storage controls own execution.

## Cache Contract

workspace:build-storybook is truthful uncached orchestration (aggregate/orders-prerequisites), preserving its compiler state store and every native producer’s cache decision. Its old deterministic root task cache could skip producer freshness entirely. workspace:test-storybook likewise uses uncached live orchestration because its work includes current producer/build/browser lifetimes. No global graph-inference feature was added.
