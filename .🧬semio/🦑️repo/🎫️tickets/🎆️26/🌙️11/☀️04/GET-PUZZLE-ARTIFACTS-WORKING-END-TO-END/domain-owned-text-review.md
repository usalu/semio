# Domain Owned Text Review

The proposal uses a real existing borrowed writer, but requires explicit new domain/source/controller seams. Source review only during synchronization; no production change or native proof.

## Existing mechanisms

JsonWriteSource exposes ordinal node_at_path and object_key_at_path, returning borrowed String/NativeString, numeric and collection nodes without requiring an owned DslValue. JsonBorrowedWriteCursor allocates only retained traversal frames/path/output, measures then admits exact output capacity, provides normal_step_demands_with_copy/normal_step_progress/last_turn_work, reports measured_bytes and progress, and checkpoints the genuine NativeEncodeControl each actual transition. Text chunks are physically bounded to64 source UTF8 bytes; paged Utf8Text is already supported. Controlled retirement covers frames/path/output. Cancellation is supplied through the resumed NativeEncodeControl/checkpoint; the cursor is not itself an InteractiveJob and does not validate the external snapshot generation/revision.

No existing symbol ordinalJsonWriteSource was found in actual framework/extension source. Treat that name as a proposed domain ordinal adapter, not a ready API. Existing canonical tree has actual F32HexWord and transparent borrowed F32 wrappers; F64 is currently ordinary numeric spelling. The borrowed JsonWriteNode vocabulary has no F64 hex-word-string arm. A fixed16-lowerhex scalar arm is a real required seam; update both demand and measure/encode transitions plus exhaustive consumers. Scalar text must be derived from to_bits without heap DTO allocation, never ordinary F64 numeric rendering.

Raw generated FieldProjectionSource plus __dsl_spec_producer is insufficient to reconstruct the normative JSON without missing metadata. DSL plan_fields defaults key to to_kebab(ident), ignores value rename/skip attributes and carries DSL optional/block/table conventions. Opaque boundary is a separate concrete seam: DSL DslField for DslValue projects Intrinsic* variants, distinguishing native Float from IntrinsicNumber; canonical tree for DslValue instead returns the same F64 node as a typed f64. Thus blindly virtualizing every canonical F64 also converts opaque semantic/user numeric data, violating the existing selective converter. A shared borrowed JSON adapter needs an explicit field/node role or opaque-boundary metadata that survives traversal, plus selected typed binary64 role handling. Existing canonical hex_word is f32-only (including arrays/Vec/Option), not an available f64 bits-object contract.

Roles remain camera coordinates/zoom, every node position/size/scale and handle, every edge geometry, target regions, and catalog handle templates;43 is specimen leaf occurrence count, never an exhaustive fixed-index schema. Default annotations control decoding, not automatic output omission; encode uses actual presence predicates. These facts support one schema/value-generated native JSON view shared by leaf/owned output, with a narrow explicitly declared Puzzle word-role overlay and opaque preservation, rather than pretending the existing DSL producer already supplies all JSON semantics. Source/test caps and native proof remain unchanged/open.
