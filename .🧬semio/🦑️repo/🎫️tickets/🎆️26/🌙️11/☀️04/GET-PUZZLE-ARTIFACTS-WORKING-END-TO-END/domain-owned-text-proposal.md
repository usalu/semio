## Working Output Qualification During Fresh Maintenance

Read-only current interface check: OwnedSerializerJob.output has no documented promise to expose a partial buffer. The concrete existing DrawingOwnedSerializerJob returns Some only when finished, not closing/canceled/failed and its live source authority matches. Its take_output also requires completion authority. OwnedSerializerOutput itself can enumerate real pages and a contiguous tail, but that storage capability does not establish a working-preview contract.

Therefore the current existing public boundary cannot be used to demand an in-flight buffer witness without deliberately extending its semantics. Preserve the current native acceptance interface and verify actual written bytes with explicit program/paged-sink receipt laws after the real missing-factory red. Those laws must inspect the real sink pages under their existing owner, compare actual prefix bytes with the independently expected pretty stream, and equate the progress DTO to that physical written extent. Do not substitute an extra counter or claim the reported PreviewReady completedBytes is independently proven by itself.

No source/test/provider edits or executor were made for this qualification. A future decision to expose working output would need an explicit shared API/publication-authority contract and consumer review; it is not inferred from the optional output method.
