# WGPU Clipboard Audit

The shell retains `ClipboardWrite` fragments in `DocumentState.workspace_clipboard`. The action dispatcher binds that fragment into paste arguments before serializing the invocation and calling the program bridge; returned effects pass through the central host-effect queue. The keyboard activation route dispatches paste directly when a fragment is available. `ClipboardFragment` derives the value conversion traits used by this path.

The retained clipboard is local to the shell: the WGPU effect handler does not read or write the system clipboard. Its unit test injects effects and calls the argument binder directly, so it does not establish that a keyboard copy reaches the program bridge and that its returned effect is subsequently pasted through the bridge. No native execution or build was performed in this audit.

## Native 3D Fixture Publication Stall

The failed gesture run faults `setActiveExample` after 4096 unchanged publication units, before the clipboard assertions. The log does not record the publication witness, blocked reason, or available grant, so it does not establish a production defect or a specific starvation cause.

The fixture's `settle_with_items` captures `fuel_remaining()` and `retained_grant()` after dispatch and repeatedly renews turns using those values. `StepContext::retained_grant` explicitly returns the spendable remainder after current turn spending and source holds, which can be smaller than the admitted fresh turn ceiling. Its `measure_maintenance_step` ignores its item and byte arguments and instead uses the mounted policy. A focused diagnostic should compare the captured values with `original_turn_ceiling()` and record publication witness and blocked reason across turns. If the captured remainder is depleted, the fixture should renew from its admitted fresh ceiling while retaining source-stock constraints. Using the default app document avoids this unrelated setup for the clipboard law but does not verify example switching.

## Canonical Wire Fault Accounting

`tree/📨️wire/🧪️tests/🦀️.rs` defines `FaultingWire`, whose array advertises one child but whose `canonical_tree_child` deliberately refuses. Its CPU law expects selected faults to record work and checks the effect's performed work against the cursor's reported work.

The production `ArtifactCanonicalJsonTreeCursor::next_demand` delegates child phases to `NativeFrame::child_demand`, which invokes the fallible source child through `try_project` before any allocation effect is admitted. The wire cursor delegates its own demand query to that tree query. Its `advance_one` maps a demand error to `last_turn_work = 1` without calling `effect.performed(1)`. Separately, tree `advance` also propagates a failed child projection with `?` before its end-of-turn work charge. Thus a real selected source callback can fail without being charged, and the reported work can disagree with the effect. The current test also unwraps the demand query, which can encounter that deliberate fault before reaching the selected advance.

The smallest safe direction is to make the child demand quote structural without executing the fallible child callback, then charge the admitted selected traversal before invoking that callback, including its error path. The alias admission demand currently takes a projected reference, so its exact structural quote must be established before changing it. Relaxing the expected work to zero would mask the unfunded callback. No build or production edit was performed in this audit.

For a vacant alias admission, the physical quote is independent of the child value: `RetainedCloneRef::binding_demand(None)` uses the fixed `RetainedCloneBinding::alias_copy_bytes`; projection admission adds `size_of::<Option<NonNull<T>>>()`; `retained_alias_demand` adds fixed binding, pointer, projection and caller-slot sizes. Its depth is one and it allocates no capacity. `binding_work_demand` validates the live lease and uses the sealed shared alias's constant duplication work; `retained_alias_work_demand` adds one unit for publication. A projected child shares the parent lease. A type-only quote for vacant `dyn Tree` is therefore possible with separate live-parent validation and checked arithmetic.

Preflight the full alias physical grant and alias work plus the callback work before calling the getter, and charge the callback before invoking it. Otherwise a caller with insufficient alias authority could repeatedly invoke the getter without advancing. A separate work-only turn would need funded custody for the borrowed result across turns; retaining a raw borrowed reference is not sufficient. Combining the callback and alias admission is the smaller safe operation.

## Unfiltered 3D Example Failures

The two `Pending` versus `Ready` failures are independently explained by a fixture bug. `OriginalFixture::construct` in Puzzle command jobs creates an admission, calls `admit_original_tool_construction_scoped` once, and asserts `Ready`. The underlying `admit_original_construction` explicitly records an absent binding and returns `Pending` on that first call. These tests fail before `Puzzle3dSetActiveExampleWork` executes. The helper must retain the admission, output and one-shot construction closure while driving subsequent fresh turns to `Ready`, including the required admission settlement and reset; the framework's settled construction helper expresses this protocol if an appropriate scoped wrapper is available.

The thirteen publication faults are distinct: the example worker emits a multi-mutation edit, and the fault is generated only after the operation reaches the framework's `Publishing` stage and its store checkpoint fails to advance for 4096 units. The log has no checkpoint, grant or store blocked-reason detail, so it cannot identify whether the cold constructor authority issue, fixture turn renewal, or the store itself caused the stall. The cold constructor repair must be rerun before changing the stall ceiling or publication logic. If still reproducible, record the store checkpoint and admitted versus remaining grant during the unchanged streak. The same run separately reports `original work requires its original caller loan` for two aggregator operations, which supports checking authority but does not prove it caused the example stalls.

The fresh renewed run reaches the later `settle_with_items` bound with a terminal worker and no active ingress gates. A concrete candidate is the fixture renewal's pinned-return branch: `fixture_renew_turn` resets only the payload page and returns without refilling fuel or retained allowance whenever `return_source_pinned` is present. Publication returns immediately when fuel is exhausted, and its pump can return before recording an attempt, consistent with a long silent wait rather than a stall fault. The existing operation diagnostic does not expose this budget or the publication owner. Add fuel, retained grant, `should_yield`, `return_source_pinned` and `return_budget_snapshot` to the fixture's own terminal panic to test the hypothesis without rebuilding the actor; capture the first pinned and final snapshots. If pinned and exhausted, reconcile the live claim or held currency before renewal, not by minting funds. Otherwise inspect mounted publication, pending artifact publication, ownership receipt, tool stage and store checkpoint. The later host turn already advances publication and drains preparation receipts, so a missing call in the earlier dispatch loop does not explain this run.

## Native World3D Relocate Audit

The native relocate begin, preview and release all pick the horizontal plane at the object's Z. The verified React interaction uses the view-aligned plane for front and side views, preserving the perpendicular coordinate; the native plane can be edge-on in those views. Native preview retains only mesh URL and origin, so it omits the grabbed instance's rotation and scale. Each move also scans all draws and their instances to find the mesh and clones strings. Capturing the dragged instance's pose and mesh once at press would avoid that repeated scan while enabling a faithful preview; view-aligned picking needs its own shared preview and release calculation.

The registered `world_host_pointer_gestures` native target covers cancellation, and the host scene-input-residency test covers horizontal preview and final position; the interaction pointer-gestures target covers relative displacement and snapping. They do not prove front and side drag planes or rotated and scaled ghost rendering. The production authority does recompute the final gumball position before release. No build was run in this audit.

## Config Publication Stall Audit

The fresh example passes all 216 Artifact rows, then stalls with Config checkpoint cursor 0, three completed items and 124 bytes. Config is advanced by `typed-operation-unit` through `config_store.advance_apply_batch_with_turn_ceiling` and the same `store/⚙️engine/🧳️bundle` batch ladder as Artifact. The Artifact-only returned-root throttle does not apply to Config. The logged `returned_reads` is explicitly the document store's count, so zero does not establish that the Config store has no returned reads.

The checkpoint combines the staged and current item checkpoints with source census counts; it does not expose the batch phase, preparation closure, staged-root retirement or the last returned advance. Its unchanged value therefore does not identify the exact blocked loan. The log's grant decreases by 51,776 copy bytes and 320 items over each 64-turn interval despite ample fuel, proving that some paid work occurs while the witness stays unchanged; those charges alone do not prove the batch itself progressed, because host maintenance also runs. In the batch's Preparing branch, `item_closing` can drive `stage.retiring` or close the preparation and return `PreparationProgress` without necessarily changing the composite checkpoint. Another possible path is `minimum_advance_items` or a receiving-effect quote returning Blocked. A narrow diagnostic should capture the actual advance result and ownership receipt, `phase`, `source_census_finished`, `preparation.is_some()`, `item_closing`, `stage.folding` and `stage.retiring` presence, source remaining, and Config returned-read count, together with the receiving grant and minimum item demand. If an internal retirement is advancing, the stall witness must include its bounded progress rather than count those turns as unchanged; if the advance is Blocked, use the identified quote or loan gate rather than changing the watchdog limit.

## Active Example Close Audit

The final quote belongs to the document store disposer: `OwnedStores document advance=false` selects `close_document_disposer`, which forwards to `ArtifactStore::close_owned_store_step`; the window registry and actor fields in the same diagnostic describe later store lanes and do not identify the current blocker. The fixture renews a fresh caller turn and uses `fixture_mounted_policy()`, the actual `INTERACTIVE_COMPONENT` policy with 64 close items, but the shared `original_lifecycle_grant` caps the grant passed to `app.close_step` to one item. Its enclosing retained loan separately allows the phase's full 64 items, and the OwnedStores rung obtains its effect grant from that context; consequently the displayed one-item quote does not by itself prove the nested disposer has a one-item effect. The document cursor disposer also deliberately narrows an active nested retirement to one item. The narrow next diagnostic is to sample nonzero close receipts and `close_phase_witness` plus the actual inner effect grant. If those receipts and phase move, raise the fixture close bound to cover the measured full example; if they do not, repair the exact blocked nested demand or loan rather than increasing the bound. ## Native Offscreen Pixel Verification

Its native device ingress (`🧰️framework/🔨️modules/🖱️ui/🎯️targets/🧊️wgpu/🖍️draw/🎮️execution/🔌️device/📥️platform/🦀️.rs`) explicitly constructs `wgpu::Instance` with `Backends::PRIMARY`, which excludes OpenGL. Existing Puzzle tests and scene/input probes check typed scenes, draw records and state transitions; no already-authored native Puzzle-to-offscreen-pixel case was found. A credible Puzzle pixel test would need a supported actual WGPU adapter and a fixture that takes a registered Puzzle scene through prepared rendering and readback; this cannot be inferred from headless logical shell or mock draw fixtures. Enabling and validating GL as a supported production backend would be a separate implementation and portability change, not an existing runtime switch.

The repository's pinned Chromium headless-shell bundle also ships a SwiftShader Vulkan ICD.
