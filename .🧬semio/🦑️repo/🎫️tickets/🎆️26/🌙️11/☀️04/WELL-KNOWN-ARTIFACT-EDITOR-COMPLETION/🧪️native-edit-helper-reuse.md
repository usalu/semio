# Native Edit Test Helper Reuse

No exported generic helper combining persistent PagedOneItemEdit sources, decoder custody and the new real work payer was found. Existing mutation-apply unit helpers are local: OriginalSource, PostFixture, Receiver and step_edit. Their Receiver retains OriginalJobDecodeOwner but calls owner.receive directly; this does not install the new NativeDecodeWorkRecipient. They are not a correct drop-in harness for the new work ports.

The authoritative reusable public payer is semio-framework-job-testing-caller::OriginalJobFixtureCaller. Its package manifest is framework/job/context/testing/caller/packages/rust/Cargo.toml, package name semio-framework-job-testing-caller, with no feature gate. admit takes OperationId, Generation, original RetainedCloneGrant, clock function, deadline and fuel once. turn_with_decoder takes the turn grant, a persistent OriginalJobDecodeOwner and a callback receiving the genuine StepContext. The callback uses StepContext::with_native_receiving, which binds NativeCurrentWork over the actual fuel/cancel/deadline and delegates through the same decoder's receiving custody.

A shared generic test-only helper at the lower paged-edit owner could keep this caller, decoder, before and mutation RetainedCloneSources and mutable post across turns. Each advance should borrow those same source identities, pass the actual post mode, and use the original receiving control. Its actual semantic/physical receipt must be reconciled under the same original context, including error progress; the helper cannot discard receiving scope debt. It must explicitly fund edit/source/decoder/caller closure and never regenerate source clones, controls or budgets on each advance.

A per-test raw NativeDecodeControl plus ad hoc always-accept work recipient would exercise counters but not genuine caller admission. The public caller route is available without introducing that weaker fixture. No source or Cargo edit was made and no test/build launched.
