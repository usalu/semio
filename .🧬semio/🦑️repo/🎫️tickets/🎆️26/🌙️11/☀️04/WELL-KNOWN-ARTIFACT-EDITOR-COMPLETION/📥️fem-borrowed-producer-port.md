# FEM Borrowed Producer Port

The FEM2 and FEM3 native authoring, identity, record, binary receiving and Pack writing callers now lend mutable producers to `receive`, `receive_nested`, and `drive_cursor`. The authoring value stays in its original `Option` until the funded capture is admitted. Generic record constructors and fillers now implement `FnMut`, so the borrowed producer can be retained. Ten production files passed Rust AST parsing; this is syntax validation only. Shared owner signatures and semantic compilation are still in progress.

The FEM2/FEM3 SQLite native decode constructors also borrow their FnMut producer under the updated shared helper. Native SQLite encode remains unfinished until the retained text writer and shared construction custody are ready.

The separate FEM2 and FEM3 original-job test targets now include a zero-grant case requiring zero actual work, an ownership refusal, unchanged original authoring string, actual heap/receipt agreement and paid cleanup. The existing language-neutral denied cases provide the independent oracle; these native tests have only been syntax-parsed so far.

The publication contract now uses caller-owned output slots throughout FEM authoring, record, Pack and identity entry points. A new shared FEM receiving package retains generic row scratch and collection children, and each domain snapshot frame retains typed intermediate strings and vectors. Direct native/loads tests were updated to preserve or explicitly retire output slots. Seventeen Rust files pass AST parsing; neither the new package nor its integration has been semantically compiled. The pre-effect primitive action, unwind custody, new parent output settlement and complete FEM3 field coverage remain open.

The retained `📏️rust-source-measure.ts` invokes the repository Rust source closure reader with explicit Linux x86_64 cfg, or a caller-supplied exact cfg array. After the cohesive receiver carve, the FEM2 model reader reports 28 files, 252857 raw bytes and 3940 active lines; generated compiler inputs and actual Cargo admission remain separate checks.

The shared row/collection frame now retains effect progress and an unwind failure. Row publication, collection element push, collection output, empty Vec header and Vec handoff use the original quote/effect/post APIs, accounting for actual work and physical receipt; markers reset only after successful post. The vector allocation and other primitive actions remain on older pre-effect APIs. Expanded neutral Ajv/SQLite fixture: 1 test passed, 87 assertions; Rust is syntax-only.

Shared snapshot wrappers now lend their own birth effect marker and unwind slot. FEM row/list, snapshot/member/load, identity index, authoring capture and Pack writer births use these markers to quote, perform and post. String/vector/scalar field handoffs, finite checks, record/list/variant shape checks, 2D point publication and support enum item actions use retained markers as well. The identity sort/validation, vector backing allocation, variant conversion source clear, native SQL forecast and other selected phases remain unported. All are source-staged; native semantic compilation is still blocked upstream.

Each FEM original-job target now also stages a typed-record success test using the actual caller and decoder, real heap receipt comparison, caller-owned snapshot slot, and paid close of snapshot, decoder, record and authoring source. These tests are syntax-parsed only and must not be reported as native results until executed.

Authoring capture is now two actions: a fresh receiver header quotes exactly `size_of::<FemXdReceiving>()`, then the existing authoring owner moves under the shared zero-copy metadata handoff. Lower-level tests assert actual header work/bytes and separately admitted source handoff work, zero copied bytes and denied-source pointer custody. The original-job zero-grant test covers preflight denial. A genuine original-recipient post-refusal injection hook is still missing; neither native test target has run.
