# Explicit Domain Enum Tags
The Rust Reference gives a field-carrying enum with a primitive representation a union of variant structs with an explicitly represented tag as the first field. With #[repr(u8)], that tag has u8 representation and size. Default Rust enum layout does not supply this guarantee. See [Rust Reference: primitive representation of enums with fields](https://doc.rust-lang.org/stable/reference/type-layout.html#primitive-representation-of-enums-with-fields).

Decision for authored domain enums needing exact newly initialized tag accounting: use an explicit primitive representation chosen in the domain schema and type declaration, rather than subtracting field sizes from size_of<Enum> or reading padding. For the small FEM member/load variant families, u8 can represent every declared variant. The one-byte tag is then a documented initialized field; existing String/Vec owners transfer under the canonical zero-payload-copy convention, and newly copied scalar fields retain their own declared extent. This is an inference applying the documented layout to the native accounting policy; it is not a native conservation result.

No domain enum was modified by root during this research. The FEM owner must update its schema/type/neutral fixtures together, preserve actual field ownership, and verify native quote/post behavior. This is a greenfield representation decision; no compatibility mapping is needed.
