# Original Emission Authoring Receipt Seam

Actual outer CommandCtx::dispatch_action and dispatch_action_received receive &mut EntityIdentityAuthority. The host-configuration branch omits that argument from drive_original_host_configuration, drive_original_emission and DispatchCtx::dispatch_original_emission. Original typing emission also calls dispatch_original_emission without identity, through advance_original_typing_pass/before/dispatch. These signatures must be considered together; fixing only the host branch misses typing-generated transactions.

OriginalEmissionCapture currently stores retained input, original caller loan, OriginalSourceBinding, decoder identities and physical-retirement cursor. It has no authoring continuation/receipt or method to extract one from StepContext. Existing ArtifactToolCompletion::install_authoring_identity takes an already-owned NativeEncodeContinuation, and take_authoring_identity consumes that retained completion slot. It does not obtain an original receiving receipt. Existing typed-command creation starts NativeEncodeControl::new(max_output_bytes) before install; repeating that on emission would create fresh independent admission rather than transfer current receiving stock.

EntityIdentityAuthority supports Native, Forwarded and Retirement receipt variants. pause/pause_forwarded/pause_retirement consume self; none can move from the current &mut argument, and forwarded/retirement receipts carry lifetimes that cannot be silently stored as static NativeEncodeContinuation. No existing borrowed take-authority API was found.

Existing first-party resumable seam: entity_identity::control::OriginalOperationReceiver::new(&mut identity), begin(), pause()->OriginalOperationReceipt, and resume(receipt,&mut identity). The owned receipt is scalar; resume checks its cumulative ceiling/owned bytes against the provided authority through encode/checkpoint. It keeps the original receiving allocation/retirement port borrowed instead of reconstructing a fresh budget. This requires the same original authority be threaded to publication, and existing capture source-binding/decoder checks remain necessary; equal scalar budgets alone do not establish identity. Scope a retained emission receipt around this port only if root chooses that design. No currently available capture/StepContext method directly yields a safe static authoring continuation for all receiving variants.

ToolCancellationIssuer coercion is legitimate: its source explicitly implements Deref<Target=ToolCancellationHandle> and DerefMut. No issuer API defect claimed. No source edits or build executed in this audit.

## Borrowed Parent Publication Design

The existing runtime already supplies the needed authority: reactor runtime ops/typed-operations::advance_typed_operation_output_with_leftover takes &mut EntityIdentityAuthority and StepContext and resolves app.advance_typed_operation_publication(identity,cx). PluginApp trait and instance implementation already accept both. Instance implementation currently uses identity for pending task resume and extension drive, then drops it at the final typed_ctx().advance_typed_operation_publication_one(cx) call. Threading that exact existing borrow into TypedCtx is smaller and more faithful than adding a new retained scalar budget.

Other work can charge this same parent: advance_typed_operation_publication drives task resumes/extensions using identity before later typed publication turns, and interpreter owned_poll encodes its real poll input then charges input length on the parent identity before OriginalOperationReceiver resumes/advances. Therefore saving an emission-local scalar owned-total and demanding it remain unchanged across unrelated parent work would create a false refusal. Borrow the currently supplied original parent for each emission publication turn instead. The mutable authority borrow lives through the actual async future; it need not be serialized or stored in mounted.

Recommended narrow branch: when completion is absent and original_emission_caller is present, validate actual original producer/source/decoder binding and drive the existing admitted pump, follow_derivable_children and artifact interaction revalidation with supplied identity. Normal tool completion retains its existing owned authoring continuation. Never mint NativeEncodeControl::new as emission fallback. Preserve existing lease/publication cancellation checks; parent authority cancellation and mounted lease cancellation remain distinct concerns.

Concrete integration points: validate_original_producer_source in FullOp producer leaf is currently private to its crate, requiring a narrow public validation port; advance-unit revalidation currently unconditionally takes mounted.identity, so that step also needs the supplied borrowed authority for emissions; original typing self-drives advance_typed_operation_publication_one in phase7 and currently lacks an identity parameter throughout its prepare/pass functions. The normal PluginApp publication entry already has the authority and can forward directly. No production edits or builds performed.
