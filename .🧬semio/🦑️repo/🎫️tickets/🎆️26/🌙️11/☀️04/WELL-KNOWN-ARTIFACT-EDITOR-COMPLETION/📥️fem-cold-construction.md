# FEM Cold Construction

Cold reference construction must validate identity namespaces, row validity, graph references and finite loads before allocating sealed owners. PersistentListBuilder retains partial rows and pages during failure; exact-demand retirement must drain the builder and every separate partially sealed row before the primary ValueError can be returned. The ValueError boundary cannot own unfinished cleanup, so retirement must complete before returning.

Persistent list and builder now preflight exclusive page/row handles and nested payload predicates before mutation, then dismantle using exact shared handback with no retirement scaffold allocation. FEM cold row constructors issue their own strings and do not publish aliases; node candidates are dismantled if material construction refuses. Alias refusal leaves a list or builder unchanged. Native fixture includes a fail-next-allocation observer and exact row/page alias checks; this is staged pending semantic compilation and execution. Rust AST-only parsing and neutral SQLite/Ajv cases are not proof of native behavior.

The generic callback draft was replaced by a documented first-party `ColdRetire` semantic port: implementations must provide a pure exclusivity check and non-panicking, allocation-free release. The FEM node and material owners implement it directly. Exclusivity now checks both logical aliases and the physical Arc strong count before tree mutation. This is a safe Rust trait because violating the behavioral contract is not claimed to create memory unsafety. Cold dismantling is synchronous; interactive receiving retains its separate paid step/cancellation protocol. Native results are pending.
