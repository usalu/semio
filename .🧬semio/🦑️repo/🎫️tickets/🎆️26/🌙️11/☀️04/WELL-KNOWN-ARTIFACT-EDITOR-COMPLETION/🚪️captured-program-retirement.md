# Captured Program Retirement

The host now requests admission for exact captured program handles and instances before final spawned-window closure, ordinary app switches, plugin reload/uninstall, and human-session replacement. Content-preserving document surface handoffs retain their existing archive-transfer gate. All affected owners quiesce and seal before archive capture; all approve before any attachment closes or instance is destroyed. A failed save offers Keep/Discard using the accessible existing close dialog. Cancellation returns promptly even if a plugin read has not answered.

## Persistence and Recovery

The retirement persistence port uses the captured owner rather than focused Save. A runtime identity with null parent_document_id is the sole documentless proof. Unbound documents use the same verified archive/attachment/catalog transaction as natural import. Attached documents require exact current full-archive disk readback and a final native revision comparison. No natural export or focus change is needed.

An existing kept owner whose attachment was lost first drains its old lane, writes the current native full archive to its existing kept target, verifies identity/content/current catalog fields, and only then reattaches. It never restores old disk contents into the edited native instance. Cancellation or catalog replacement closes only the captured new receipt.

## Concurrency and Failure

Reservations are scoped to exact handle and instance, and remain held until asynchronous retirement and caller release finish. A window close and plugin reload cannot both retire the same owner. Release requested during a background switch retirement is deferred until the close ladder settles. Attachments close one owner at a time immediately before its drain/destroy; an early lane failure leaves later owners attached. Surviving owners unseal after a failed ladder; owners whose destruction was attempted remain sealed because their native lifetime is uncertain.

The seal ledger now requires the exact loaded handle at every write/read/drop call. This prevents fresh handles reusing native numeric IDs from inheriting old seals. Unseal removes its complete FIFO entry, fixing Keep followed by reseal at bounded capacity. Successful module disposal forgets that handle. New natural/archive/palette/spawned openings fence plugin operations and generation ownership.
