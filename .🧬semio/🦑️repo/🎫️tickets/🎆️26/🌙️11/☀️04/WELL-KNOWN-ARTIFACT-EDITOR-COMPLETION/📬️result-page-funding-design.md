# Result Page Funding and Retained Intent

Concrete current behavior: actor typed_operation_page::try_new copies bytes.to_vec without a grant; capacity is payload length, not necessarily 4096. try_serialize_cold first materializes ToValue, JSON tree/String, then that Vec. StepContext receiving settlement debits only explicit receiving scope spends; it does not turn arbitrary raw Vec/String allocations into funded construction. Cancellation reject runs before any page allocation quote. Current calls can mutate stage/outbox/receipt state before cold page creation. These are real unquoted allocation paths, not TLS-funded pages.

PendingPublicationOutcome currently retains only phase (Uncaptured/Captured/Released), Accepted/Rejected/Lenient disposition and Option<ArtifactBoundedToolFault>. It cannot preserve an accepted store LaneItemReceipt. That receipt is Copy and contains exactly generation_before/generation_after u64. Pending Window Config receipt already exists separately, but queue_window_config_receipt takes it before cold serialization. If a new page allocation merely returns pending after store commit, the next store advance yields AwaitingAck and current code errors because no retained host page exists. Effect/event outboxes, UI pending=false and interaction writes are also changed before page creation; retrying those branches would consume/commit twice.

Smallest clean state seam: retained pending result intent captures lane/token and small scalar accepted receipt/count, or a stable borrowed owner kind for UI/Download/fault, before page birth. This state must survive denied page grants and serialize before another semantic publication branch runs. Store commit is not replayed. Do not remove pending_window_config_receipt until the framed result is retained. Alternatively pre-admit page backing before irreversible semantic commit, while preserving the exact outcome intent for framing afterward. Existing 13 ACK laws prove retirement of an already-created page, not page birth or this commit-to-frame boundary.

It writes original borrowed fields through fixed scalar buffers and a fixed path array. No ToValue tree, intermediate JSON value or String is required. Its returned u64 is written bytes only; it does NOT return RetainedCloneProgress or exact copied-items. Caller must retain/debit the actual bounded encoding/copy metadata and use the existing original authority, not a replacement control. Existing scene text-splice::write_changes_json and pack borrowed-source-laws are concrete source adapters/callers. Existing no-op sink in space-history snapshot preflight measures exact byte count without retaining output. No ready-made fixed-array sink adapter was found among current callers; this callback API supports an explicit checked slice cursor.

Existing real fixed-page producer: actor/🖼️wire-turn/⚠️diagnostic/🦀️.rs::OperationDiagnosticPublication. next_demand quotes capacity4096 for Vec birth, then at most2048 copied initialization bytes per step. ArtifactCanonicalJsonTreeCursor::advance writes into &mut bytes[len..] and returns written_bytes plus ownership.progress. take_page uses TypedOperationResultPage::from_original with already-funded fixed backing, moves without payload copy, and retains exact ACK token. Its bytes and cursor remain in original close custody on cancellation. Reuse this physical page birth/handoff/close pattern, not cold constructors. For direct small receipt source adapters, the borrowed-source sink avoids tree construction; a generic incremental encoder must preserve its source/cursor rather than store references across turns.

Actual page backing can be admitted using the existing StepContext path admit_original_construction(cx, &mut pending_bytes, OriginalConstructionDemand, constructor). Constructor uses the supplied original receiving control/allocation path and returns exact RetainedCloneProgress (capacity4096, metadata/copy as performed), with RetainedWorkOutcome. Denial leaves destination None and pending semantic intent unchanged; copied bytes are initialized under their own bounded quote. Once full backing is owned, from_original preserves that allocation through projection/ACK/physical close. No fresh NativeEncodeControl or fallback ownership ceiling is needed.

Payload adapters are finite: LaneItemReceipt object(two u64), accepted tuple(string,count), UiDirtyScope object/arrays, DownloadResultPayload flat tuple(filename,mime,encoding|null,bytecount), already-framed bounded fault bytes, and terminal raw bytes. Download bytes field is a count, not the download body. UI Partial includes owned window/panel ID vectors in the original emit; borrow them until framing completes instead of cloning an unquoted tree.

Required actual regressions: denied page capacity/items/copy/depth performs no unquoted birth, retains exact pending outcome and produces no duplicate Store commit/outbox consumption; accepted resumed page matches independent serde_json wire; actual heap/returned receipt agree; cancel during pending frame retains emit/receipt and reaches physical terminal close. No implementation or heavy execution performed in this audit.

## UI Scope and Minimal Pending State

Exact UI source: framework kernel/🖼️ui/🦀️.rs::UiDirtyScope is Full, None, or Partial { window_bodies: Vec<String>, panel_bodies: Vec<String>, utilities, tools, engagements, measures, labels: bool }. Full/None Clone has no heap payload; Partial clones vectors and their strings. Typed unit UI branch clones before calling fixed outbox push, so even a saturated receiver can allocate and release a clone before returning a fault. Terminal TypedOperationCompletionWitness clones again; inline interaction also clones its scope. No controlled UiDirtyScope clone helper was found. These semantic consumer copies require their own funding or ownership redesign; borrowing for page framing alone does not pay them.

Minimal page intent: own lane/token plus Copy LaneItemReceipt or accepted count when available; use an owner-kind selector (Ui/Download/Fault) to borrow the unchanged retained mounted publication source on each bounded framing step. Do not put a Rust reference in persistent mounted state. Ui intent borrows emit.ui_scope directly, avoiding a third ToValue/tree clone while outbox/completion consumers retain their separate scope copies. Keep source and ui_pending stable until the page or explicitly funded receiver handoff commits. On denied frame admission, service that pending intent first on the next turn; never re-pop effect/event or re-apply interaction writes.

Diagnostic publication is reusable as the physical lifecycle pattern, not a drop-in generic UI encoder: OperationDiagnosticPublication owns typed Vec<Diagnostic> sources and RetainedOwnedProjection<dyn ArtifactCanonicalJsonTree>. The existing mounted Emit is not such an owned projection. JsonBorrowedWriteCursor can borrow an unchanged semantic owner per step, but owns frames/path and intermediate String output, whose allocation/retirement must be quoted; it does not automatically write into the page buffer. write_json_source_into can target an explicitly checked fixed slice with no intermediary; its traversal must be bounded by caller limits and funded as an atomic bounded frame or a deliberately retained incremental cursor. Do not claim its returned written-byte count is an exact original retained-work receipt.

The clearest extracted actor seam is generic page-backing admission/initialization/handoff/close (existing diagnostic 4096-capacity and <=2048-byte initialization law), with domain-owned pending intent and a finite borrowed wire view. This preserves the original payload until framing succeeds without introducing generic ToValue allocation. Root plans actual native physical red before changing production.
