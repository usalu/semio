# BIM Surface Performance Read-Only Audit

Scope: _Painter._skin → projected_material_regions → _regions in the BIM visual kernel, using the retained 177-facet pre-fix float capture and the previously recorded 40.766 s full-beam native/Cairo baseline as context. No production renderer, model or cache input was changed and no whole-building geometry was rerun.

The current exact region classifier checks every atom midpoint against each ring's exact Fraction bounds before expensive point classification. An in-memory instrumentation pass on the retained capture found 177 rings, 5,736 atoms, 1,015,272 possible atom/ring pairs, 96,817 x-range candidates and 59,963 full-bounds candidates. The run took 4.687 s with counters and ended at the known old Open exposed material boundary error. These numbers describe the old float-derived capture, not the corrected exact output.

An in-memory x-interval sweep prototype retained original ring order and exact Fraction comparisons. On that same old capture, baseline projected-region time was 4.25 s and candidate 3.89 s, about 8.5% faster; both ended in the same known boundary exception. Identical candidate filtering is plausible from interval inequalities, but this failed legacy input does not establish successful corrected-topology equivalence, native Cairo pixel equality, or representative full-render benefit. The ~0.36 s isolated difference is not evidence of a substantial reduction against the full-beam baseline. No production change or active-producer restart is recommended on this evidence.

A canonical runtime source_dependencies scan across all 26 manifest videos found these exact surfaces/regions modules only in the six BIM lessons: bim_information, bim_objects, bim_representations, bim_models, bim_exchange and bim_consistency. Editing either would stale those source pins, including active 117, and invalidate the unfiltered suite's frozen inputs; no accepted energy/GH/Excel lesson directly includes these exact files in that closure scan.

Retained ticket-only probes: bim-surface-microprobe.py, bim-surface-index-probe.py and bim-surface-closure.py. Temporary measurement JSON is under generated. Any future optimization needs a successful real exact-facet corpus, language-neutral/third-party topology and pixel oracles, cancellation/progress verification, and meaningful full native timing before a coordinated source freeze.
