# Parallel Grasshopper and Excel Beside Anatomy

`grasshopper_capsule`, `grasshopper_tower`, `grasshopper_casting`, `grasshopper_trees`, `excel_anatomy`, `excel_references`, `excel_program`, and `excel_energy` each contain one segment. Those segments are the first occurrence of their `(script, scene)` pair, so their source ordinals are 121–128. Anatomy writes only `s/120`. BIM writes `s/114`–`s/119`. Optimization writes `s/129`–`s/134`. `tower_axon` builds the Nakagin drawing in the scene; it does not write a shared media file.

`parallel-rest.ps1` renders those eight lessons into `cache/videos`. It does not take `videos/en/.media-lock` and it does not write `generated/render-en.log`. The live `render-en.ps1` still walks the same eight lessons after anatomy. This driver starts the lessons the serial walk reaches last. About 15 GB was free while anatomy and the six BIM lessons were resident, so the launcher was stopped after `excel_energy` and `excel_program` had started. `excel_anatomy` and `excel_references` were stopped before they allocated. `yield-rest.ps1` watches the two live lessons and stops that process tree if `render-en.log` records `[DEBUG] <id> attempt`.
