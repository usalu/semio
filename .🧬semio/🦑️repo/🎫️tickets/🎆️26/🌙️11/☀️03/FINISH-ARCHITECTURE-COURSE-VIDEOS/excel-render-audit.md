# Excel Render Audit

Read-only source audit of queued Excel scenes 125–128. No construction or timing measurement was run; hotspot is inferred from call paths.

- Program 341–353: repaint changes stamp according to the number painted. tower at 326–331 keys a full tower_axon rebuild on every changed stamp; _keyed_snapshot at 33–47 captures the rebuilt entire tower. Call sites 594 and 602 paint type A and all 140 slots over 1.6 seconds, respectively. This can rebuild the whole tower once per rendered frame during these animations, even when many slots already have the desired colour. It is a render-cost risk, not a measured failure. Snapshots avoid repeatedly drawing unchanged tower frames.
- References 602–616: the mixed-reference tower uses a discrete position-keyed snapshot; setdefault eagerly computes _tower_cell even on cache hit, but the function is invoked when the snapshot key changes. Whole tower rebuilds occur for each selected cell, reflecting changed lit capsules. This is an inferred cost, not an unused geometry dependency.
- Anatomy 333–341 and 528–529, References 345–346, and Energy 431–432, 583–584, 730–731 and 831–832 snapshot whole towers before display fades. Geometry is retained for targeted morphs or coordinates. Anatomy 342 uses a silhouette of a whole tower for the workbook morph; cost is unmeasured.
- Energy 270–275 keys live capsule construction on visual state, including changing tint/grow/vent/volume trackers and workbook identity/interpolation; faint and kind are declared but not read in the file. References 256–259 keys both views on width, row and visual state. Anatomy 145–152 includes drawing state. No unused key dependency was confirmed. Dynamic detailed capsule redraws while trackers animate are expected by these paths; cost is unmeasured.
