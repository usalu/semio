# Replica Pack Delete Index

The Git-object delete gate previously called `manifest.ids()` after the queued-object check. That call built an array over the entire live manifest, and the gate resolved each live put's path to look for pack indexes. `ReplicaBookV1` now records matching IDs alongside the virtual stage IDs when each path is interned. Checkpoint adoption rebuilds the sparse lists from the existing path pages during hash-table reconstruction. The delete gate iterates the sparse pack-index IDs in intern order and checks the current manifest operation before resolving a path.

The match uses the previous case-sensitive pack directory prefix and `.idx` suffix. The queued object-put check, local pack presence check, 600,000 ms HLC orphan expiry, and retry backoff retain their existing behavior. The checkpoint and journal keep their existing layouts. The separate pack publication authority check retains its own logic and memo. In `applyQueueWork`, the paused-only path still invokes stage application, and a normal turn invokes stage application before the Git-object delete gate.

The native Bun integration exercises the actual queue and disk removal with 1,024 unrelated put rows, a tombstone, a link, similarly named paths, and an interned-only pack index. The JSON fixture declares the expected retention after each step, and SQLite independently produces the same answers. One case leaves the queued replacement pending and then presents the matching pack bytes. The other persists and reopens a real checkpoint while the pack index has no counterpart. In the reopened case the old pack still exists below the expiry, and the exact expiry turn removes it.

The test primes the independent publication authority memo before spying on `manifest.ids()`. Before the implementation, the queue and disk assertions passed while the spy recorded one full enumeration for replacement arrival and two for checkpoint adoption and expiry. After the implementation both cases pass with zero enumerations. The final native pack-gate suite passed all seven tests, the packed-stage suite passed both tests, and the replica-book stage projection test passed. An initial full pack-gate run hit an existing Git GC scenario's `git fsck --full` failure with empty stderr. A fresh full rerun passed that scenario and the rest of the suite.
