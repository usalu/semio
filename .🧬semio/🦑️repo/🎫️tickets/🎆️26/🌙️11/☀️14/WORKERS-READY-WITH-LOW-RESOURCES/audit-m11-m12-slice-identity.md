- The m11 stage owner token identifies a checkout-derived hash, stage and original start time; the ready supervisor PID and `startedMs` can change on adoption. The slice PID and uptime identify a sampled worker only while combined with time and machine, since PIDs can be reused. The door clock is outer command liveness. A slice heartbeat repeats the last worker detail with a fresh elapsed time; progress is proved by changing counts or report phase, not the ticking clock. `completedOwners` increments after each successful owner callback, including memo-held facts; it is not a unique-project or build-completion count. A three-project build selection can have a much larger transitive admission frontier.

Current source confirms these distinctions: `build/🕸️graph/📥️load/🟦️.ts:139-175` checks the selected admission memo, enters scoped discovery if it does not hold, memo-checks or discovers each owner and then attempts publication. `build/🏡️resident/🏗️composition/🌐️host/👷️slice-pool/🟨️.mjs:57-60,75-88,98-100` creates a distinct worker, repeats its latest progress and serializes same-root requests within that pool. Queueing is evidence of concurrency and shared-root serialization, not duplicate physical inventory. `build/🌐️remote-execution/🛰️sidecar/🚦️ready/🌲️process-tree/🧹️containment/🟦️.ts:42` constructs the stage token. These are current source semantics; the worker revision at each historical event is not established by these files.

A durable diagnosis needs correlated immutable lifecycle events: machine/boot and service instance; stage owner and attempt; command/request and normalized selection; checkout identity and registry/scope digest; job/worker identity with process start; memo input identity and hit/miss reason; inventory phase start/end, result and publication identity; explicit retry, cut, cancellation or exit cause; and leader/follower linkage. Record bounded event receipts rather than only mutable last samples. Then same job with multiple worker starts and a retry cause distinguishes an internal restart; different request identities distinguish separate commands; memo outcome and publication receipts show whether prior work was reusable or lost. Root path or changed counter alone cannot prove either duplicate work or loss. This audit does not establish a defect requiring intervention.
