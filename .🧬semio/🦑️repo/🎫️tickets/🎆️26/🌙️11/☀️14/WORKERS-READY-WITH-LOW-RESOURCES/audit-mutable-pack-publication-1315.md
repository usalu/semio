Three independent descriptor samples found FD 16 reading inode 699903271 of the same 6,314,703,074-byte Git pack. Recorded offsets advanced from `0xb95c0000` to `0xbca80000` to `0xc8800000`. The file's modification timestamp also advanced during the observations while the inode and extent stayed the same. The existing last events reported this pack unstable. The descriptor is making slow read progress on a moving source rather than proving a stalled kernel read.

Ordinary publication waits for every preparation in a batch before committing any of its events. That wait is inside the main replica turn before unrelated hints can be consumed. A same-size candidate takes the older generic hashing path with no inner source identity check, signal, or progress callback. A valid stream has to reach EOF before this path even discovers that its bytes changed while the file was changing. Even a stable multi-gigabyte input can keep unrelated updates waiting behind the batch. The independent attestation timer runs during that wait, so a fresh attestation alone does not prove current journal progress.

The current replica and Rust processes were left running. The pending dependency source files and ordinary-sharing diagnostic still require exact coordinator journal proof. Source work is addressing both early identity loss during a large read and foreground publication isolation. The existing staged-object priority and Git pack dependency fences continue to govern acceptance.

## Bounded foreground publication

A private real daemon reproduces the queueing failure with a withheld source probe on a 64 MiB file. A fresh exact-path hint did not reach the journal while the old publisher waited. The daemon now prepares one large file asynchronously and submits its completed receipt through the serial journal turn. Small publications, packed-stage priority and incoming follow stay on that turn. Dependent pack companions and deletions retain their existing checks. A stopped, retired or disconnected turn invalidates its deferred preparation. After completion and before journal admission, the publisher checks the current winning register, source path and identity, and the stored blob's physical custody. A completed receipt that an authoritative scan no longer needs is retired.

Both isolated real-daemon cases passed with the revised loop. One writes an unrelated hint while the large read is withheld. The other replaces the source at the old blob publication boundary and checks that exactly one current large-file hash reaches the journal. SQLite independently checks the required journal order.
