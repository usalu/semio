## A. Why `sync-gate` is always stale (found, fixed, proven)
* Writer of the evidence: `sealJavascriptDependencyInstalledReceiptV1` writes `<sha>.installed.ndjson` then `<gen20>.<sha>.installed.json` (immutable, content addressed) during the dependencies stage, after the scan of a generation.
* Cause: `retireJavascriptDependencyGenerationFilesV1` (generation store, runs after every publish of any scope's generation receipt) swept every file matching `^[a-f0-9]{64}\.[a-z]+\.ndjson$` that the generation receipts do not reference. Installed-paths evidence is referenced by a different receipt kind, so it was deleted by the next publish of any scope (receipts of this checkout: 2026-11-16 18:54, newer generation receipts 2026-11-17 17:23). Not a path move, not R146/R123/an external sweep. The gate then answered `stale installed:<scope>` forever, because the producer re-seals the evidence only inside a full run, and the next publish removes it again.
* Cost of a stale gate per command: the producer does not return `current`; it runs the full attempt: whole-repository ownership walk (`store-ownership`, 1.4M to 2M operations in the old g1 logs, 115 to 1100 s per R162), then per scope a full installed scan (7.4k directories, 59k files) and a re-seal. Current logs (01:58 local) hold only workspace-stage lines, so no before/after seconds exist yet.
* Fix 1 (cause): the sweep only owns `frontier|execution` evidence. Fix 2 (repair): `repairJavascriptDependencyInstalledReceiptV1`; the gate re-derives the evidence once (shape digest must equal the receipt's, so a changed generation is never blessed), seals, republishes the sync receipt, prints `[DATA] Store dependency installed-paths evidence repaired`. The old receipts of THIS checkout (6, evidence missing) repair on the next gate run on this machine if their directories are unchanged.
* Laws `🧾️incremental/🧪️tests/🩹️evidence` (3): sweep keeps installed and ownership evidence and still removes orphan frontier evidence; repair seals one receipt and one evidence file and refuses a receipt that has evidence; repair refuses extra file, missing directory, extra directory. ## C. Single-flight: not built
Two gates run in parallel under shared leases each verify; making the second adopt the first's verdict is not linearizable (it arrives after the flight started). Exact options: serialize on an exclusive per-store gate lease and re-check by receipt (what the exclusive hold already does for syncs). Needs a design decision.

## D. Yielding walk: not built
