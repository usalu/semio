## How the process envelope is meant to be provided (item 3)

- A test file either declares its own birth (`declareLibraryBuildTestEnvelopeV1` / `declareBuildTestEnvelopeV1`, then bare `bun test ./file` works) or relies on the suite runner. Files that do not declare fail bare with "Original parent Script process invocation required" or "Owned test artifacts required".
- The repository's own per-file harness for the second kind is `LIB/🧪️testing/🌱️genuine-birth/📜️script.ts` (the launcher table the suite runner uses): `bun LIB/🧪️testing/🌱️genuine-birth/📜️script.ts --file=<abs test> --birth=setup|setup-sdk --root=<checkout> [--pattern=<regex>]`. It gives the real build-caller envelope, `SEMIO_TEST_ARTIFACT_DIR`, cwd = checkout, a 290 s budget and 120 s per test. A suite row with `"scratch": "checkout"` additionally puts the artifact dir under `.cache/test-sandbox` (set `SEMIO_TEST_ARTIFACT_DIR` to a dir there to mimic it). Every number below was measured through it; `land.py` uses it as its test runner.
