# Member Git Stage Retry

The apply step used a single deadline per worktree. A missing staged blob could keep a later, already available author entry queued for up to 30 seconds. The same deadline delayed an entry after its exact loose object had arrived. Quiet calls also reached the member publish step before consulting the deadline.

The member now records the base HLC, the pending author entry HLCs by path, and any exact missing object IDs returned by Git. A new or superseding author register wakes the next apply. A loose object can wake it when an exact watched filename appears or changes. The fast path checks directory metadata for at most the prefixes among the missing objects and visits individual candidates only after a directory change or on the first observation. Foreign registers and unrelated loose files leave the deadline in effect. The Git commands still validate actual availability before modifying the index. The timed retry covers pack-only arrivals and errors that cannot identify the missing object. Index lock and author retry rules keep their existing timing.

A schema-validated sequence in `🌿️git/🧪️tests/🧫️fixtures/⏱️stage-retry.json` reproduced the failure in a private Git repository with a fixed clock. The new ready entry originally left all three pending entries queued, instead of settling the ready and void entries while leaving the missing one queued. The same sequence now passes its 30 assertions. Git's `ls-files` and `rev-parse :late.txt` independently verify the resulting stage. Git Trace2 reports zero processes on unchanged queues, foreign and unrelated loose object arrivals, and calls during the index-lock deadline.

A register-free member repair waiting for an obsolete blob also blocked the next author register. A new valid author register now wakes the apply in this case. A separate incoming base fixture verified the wake when a missing descendant blob arrives. Before the fix it stayed in `objects-missing` until the deadline. With the fix it advanced to `index-busy` at the same clock value and preserved the writer’s lock. The three focused tests passed 45 assertions.

The Git module passed 65 tests and 525 assertions. Six replica integration tests passed 83 assertions, covering stage and unstage, missing objects, polling, stage priority over unrelated payload, and stage-related pack hydration. These were private fixture runs. They establish the member retry behavior and leave the explanation for peers with stale or absent attestations open.
