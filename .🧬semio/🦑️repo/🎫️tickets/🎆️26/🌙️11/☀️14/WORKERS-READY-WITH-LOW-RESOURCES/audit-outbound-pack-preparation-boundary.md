# Outbound Pack Preparation Boundary

The coordinator reported a 6.31 GB mutable pack held open for more than 15 minutes during an ordinary outbound publish. The live attestation loop continued independently while exact-path hints accumulated. The current daemon waits for the entire outbound slice's `prepare` pool inside one store turn. While that turn waits, it cannot consume later hints or run its following inbound pass. Large copy progress keeps the store guard alive. This behavior distinguishes slow useful I/O from a stalled store but gives other work no turn.

The smallest separation would apply only to daemon-owned ordinary large pack publication. Move the byte work into one bounded, independently metered slot and keep the main turn responsible for all journal effects. An uploaded candidate can return a closed receipt with the source identity, digest, byte length, operation generation and immutable CAS location. Keep discovery, pack authorization, queue decisions, HLC minting, base selection, append, cursor updates, file and manifest rows, chmod and persistence in the ordered turn. Manual, seed and other synchronous callers should retain their completion contract.

Keep one pending record for a candidate while bytes are in flight. Allow unrelated hints and inbound work to settle in later turns. When the upload settles, schedule a fresh exact-path observation. Check real ancestry, current descriptor and pathname identity, size, precise times, queue and same-path generation again. The existing streaming copy calls a size-and-mtime check stable, which alone cannot identify a replacement across asynchronous turns. A changed, replaced, ignored, newly held or retired source must withdraw its candidate and follow the current ordinary path. Do not reserve an HLC while hashing or reuse the stale base captured at enqueue.

Accept the blob immediately before append using the compactor's existing publication safety protocol with strict success and identity checks. `touchBlobV1` currently treats non-missing `utimes` failures as success, so its boolean alone is inadequate as the stronger custody proof. Reclaim first moves a blob to trash and restores it upon a new reference or a changed modification time. A prepared candidate held until it ages, moved into trash, reclaimed or replaced must defer and requalify asynchronously instead of doing heavy repair in the journal turn. A stronger explicit pin is viable only if the actual compactor recognizes it under the same race boundary. Current staging cleanup assumes long but finite lifetime and uses PID and age. Any new staging lifetime must remain compatible.

Retain the author index priority route and its independent packed-object membership proof or exact loose-materialization fallback. A deferred pack cannot satisfy the `packsHere` dependency until its own journal event commits. Companion puts, multi-pack-index and protected object retirement must continue to consult outstanding pack and current authorization state across turns. The current priority route rechecks the index signature before emitting. Running that route in the preparation slot would move an ordered Git mutation across the boundary.

Deactivate by daemon generation on sync-off, retirement, loss of store or local custody, restart and shutdown. Give the slot its own progress and abort state. Its liveness must never tick the main store guard, where it could hide a stuck journal commit. Filesystem operations already in the kernel can finish after cancellation. Their completion may clean its own staging or leave an unreferenced immutable blob for normal collection. A late result cannot authorize a new append, mutate a replica being closed, or release its slot early enough to accumulate blocked operations. Tight-latency behavior also depends on the same mount servicing small requests while the upload performs its existing chunked flushes.

A controlled stationary upload should prove an unrelated hinted put and inbound cursor can settle while the pack is held, and that pack companions, multi-pack-index and retirement remain ordered when it releases. Additional cases should race source replacement and same-path incoming mutation, remove or trash the prepared CAS blob before commit, delay the fsync in an abandoned generation, and exercise the author index path during ordinary backpressure. This audit is read-only. No replica source or live operation was changed.
