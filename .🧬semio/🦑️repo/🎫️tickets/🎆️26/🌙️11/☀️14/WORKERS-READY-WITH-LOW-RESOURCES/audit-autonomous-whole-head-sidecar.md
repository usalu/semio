# Head-Only Graph Sidecar Adoption

The existing graph role now supervises a restore-only lane on the 16 GiB class below the unchanged 24,000 MiB Wanted serving threshold. Admission requires the destination's fresh closed Ready record, local fleet identity, authenticated cache transport, positively enrolled publishing peer, normal pressure, an idle local host and graph builder, and host disk room measured against the graph partition. The lane uses the same supervised process and starts no CLI, graph build, graph catalog or remote command.

A local kernel lease serializes attempts for the worktree. The sidecar uses an exact 2 GiB host grant for the local seal and metadata. A matching whole seal returns before the remote metadata lookup. An exact compatible complete ahead candidate can use a separate 6 GiB grant before graph writer custody. Both grants observe the existing process and are released after settlement. In-flight admission rechecks yield to foreground work, pressure and restart. The candidate has a retry cooldown. The fenced publication callback rechecks readiness and stages a signed journal naming the exact planned local pointer before it can commit. Receipt publication receives only the original loader's verified restore outcome. The destination signs and persists the exact tuple locally before mirroring it. After a restart the matching local seal can recover the receipt only when its generation and manifest both match the authenticated journal. The mirror retries after the scoped turn without a new graph restore.

The language-neutral dispatcher fixture uses an independent SQLite oracle. It exercises admission, duplicate ticks, cancellation on foreground demand, exact cooldown, fresh local readiness and the typed receipt callback. The combined dispatcher, graph-stall, signed receipt and current-policy fixtures passed 22 tests and 180 assertions. After adding selected-scope refusal and cancellation after verified restoration to the neutral fixture, the adoption and receipt fixtures passed 7 tests and 77 assertions. The shared diff passed whitespace verification. No physical restore was invoked for verification. The 2 GiB and 6 GiB reservations are conservative policies and still need an observed physical 16 GiB acceptance receipt.
