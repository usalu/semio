# Exact Generation Head Pin

The remote generation exchange now returns a typed candidate from complete-only metadata lookup when the head is compatible and ahead. The candidate carries producer origin, producer generation, scope, neutral manifest digest, registry identity, platform and implementation. Lookup reads ActionResults only. The existing whole scope is `all`.

An internal restore may pass that candidate as `expectedHead` along with the receiver's independently derived implementation. The candidate implies strict complete mode. Restore derives the associated key from the exchange context, checks that it is in the enrolled key set and re-reads only that ActionResult through the normal transport. Drift in the head or qualification ends the attempt before any CAS read or pointer write. The exact metadata observation is made at that re-read. The strict restore continues to verify the immutable manifest and complete closure material and writes via the caller's original generation file port. The option is inert until an owned caller supplies it under generation writer custody.

The existing signed and sealed cache proves the transport and the returned ActionResult. The generation evidence binds the claimed producer to its enrolled origin-derived key and verifies the neutral manifest. Generic ActionResult reads do not carry cryptographic write provenance for the producer. Attribution against a hostile enrolled writer needs additional protocol work.

Its language-neutral whole and scoped samples use an independent SQLite oracle and WebCrypto to check ranking, the exact tuple and the immutable digest. An observed transport confirms no blob reads at lookup and only the expected ActionResult on drift, even with an alternate complete compatible head. The fixture covers six drift fields, unchanged existing pointer bytes, an absent new pointer, and no selected or partial promotion.
