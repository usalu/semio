# Cargo Source Coherence and Native Artifact Paths

The locked Window Config failure read Pack JSON before the Pack and Mesh sources changed, then compiled the new Mesh consumer against the old Pack interface. The elapsed markers and source mtimes support that ordering. They do not prove that all packages in the current sources compile. The framework Mesh package and the root OS packages are under different Cargo workspaces and their locked checks need separate manifest selections. ## What ordinary Cargo keeps

The ad-hoc ingress in `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🏃️process/🦀️cargo/🚪️launcher/🟦️.ts` selects a real Cargo configuration/registry view, captures the selected unit graph and admits workspace Rust source boundaries. The admission assigns source paths, digests and sizes to unit rows. The scoped physical reader validates descriptor and ancestor identity while reading, and the admission memo can recheck exact no-follow stamps on every positively and negatively probed module path. The command currently discards the admitted graph after that check and dispatches Cargo in the original working directory. The held configuration view and registry reader continue through consumption. Neither constitutes custody of Rust source files.

The isolated store isolates and retires target, build and temporary output. It does not relocate the compiler working directory or preserve source bytes. The shared lane additionally installs the repository unit cache wrapper as Cargo's compiler wrapper. On a miss, this wrapper forwards through the memory-admitting scheduler to rustc. The wrapper looks up an invocation using its entry digest, normalized arguments, dependency artifact identities and environment. Once a rustc miss returns, it reads non-entry dependencies from the emitted dep-info and hashes their paths as they stand. The same wrapper can publish local and fleet results while Cargo is still running. A compile spanning a worktree change can use an older dependency artifact inside the run. A launcher-only final check could refuse that run's result but cannot retract publications already made by the wrapper. A dep-info digest calculated after that unit compiled also does not establish that rustc read that same digest.

The existing offload route sends selected rustc unit inputs and dependency artifacts as a hermetic remote action. It can fall back to local compilation. It is scoped to individual portable units and does not pin one shared source identity across the Cargo command. The retained TypeScript build-source closure and the Cargo output snapshots protect their own distinct objects. Neither is an immutable source root for the ad-hoc Rust compile.

## Authored Native artifact routes

`repo run @semio-tech/os-plugin-describe-rs:build` is an existing owned artifact target. Its declaration is `🧰️framework/🛍️products/💻️os/🔨️modules/🔌️plugin/🖨️describe/📦️packages/🦀️rust/📋️project.json`. The target's `DescriptorBuildScript` calls `buildDescriptorEmitterV1`, which passes retained compilation custody through `buildRepositoryCargoArtifacts` and then `withCargoArtifactPlanV1`. The emitter manifest directly names Pack JSON and names the framework and OS Kernel. The framework manifest names Mesh Engine and the OS Kernel manifest names OS DSL. This is a larger artifact build through the corrected prerequisites. It does not select Window Config itself.

The Window Config and OS DSL project declarations contain tags and no authored standalone build target. The Mesh Engine and Pack JSON projects expose native test targets, which use admitted Cargo tests. They are not the retained artifact production route.

The generic source router registers the following artifact command form, under a real Native or Build Orchestration invocation that supplies caller custody:

```sh
repo './🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/⚡️caching/🦀️cargo/📜️script.ts' native cargo build --manifest '<package Cargo.toml>' --lib
```

Its `NativeScript` selects `buildRepositoryCargoArtifacts` for `build`. The usual declared graph native route dispatches this command as an authorized owner. The corresponding `check` branch has a different live command path. Direct invocation of the generic router for Window Config and any undeclared target inferred from its manifest were not executed or established in this audit. The descriptor target above is the confirmed ordinary declared artifact route for the three prerequisites.

## What Native artifact acceptance proves

`withCargoArtifactPlanV1` observes selected unit, recipe, configuration and source facts. It rechecks those facts around acquisition of the target lease and establishes exact artifact output custody before a consumer can run. It compares the admitted workspace source digests with the observed file digests in completed Cargo provenance. A missing observation or a conflicting digest rejects the planned consumer. It then recaptures selected graph and source facts and rejects plan identity changes. The retained-compilation mode adds bounded live watching which can cancel the owned Cargo child after a proved source digest mismatch. Its caps and event hints cannot establish absence of movement. The final receipt and plan check are a stronger consumption barrier, while Cargo still runs against the live working directory.

## Scope of a coherent ad-hoc check

A first isolated verification route could reuse the selected unit graph, exact configuration reader and bounded no-follow filesystem reader. It would retain a deduplicated roster of the selected input facts and required absences, including selected Cargo manifests, lock/configuration and negative module probes. It would validate those facts immediately before dispatch and again before reporting success or exposing captured/generated output. A mismatch would give a typed concurrent-edit result. It would use the isolated target/build route and exclude shared unit-cache publication until there is a separate publication seal. This scope can prove a recorded selected input moved and refuse the attempt. Ordinary pre/post checks, even with watch hints, cannot freeze file bytes used between checks or fully account for transient path appearances.

The stronger route materializes verified bytes for that selection in a budgeted private source root and runs the planned Cargo command there. The compiler must receive the selected package layout, inherited workspace manifests, configuration and lock. Generated sources need private outputs and explicit provenance. Build scripts, proc macros and external includes must use admitted physical sources or make the scope refuse. A module allowlist from the lexical reader alone cannot qualify those dynamic cases. The selected snapshot needs a compiler-input receipt before output promotion or shared cache publication. Neither route needs to reject ordinary changes to unrelated source paths.

A focused qualification can use two small crates with a dependency API change and a compiler barrier after dependency output, with an independent digest oracle for the owner, consumer and produced artifact. The test should exercise selected edits, an unrelated edit, a negative module path appearing, a generated input, nonzero child status and cancellation before shared promotion. The current direct launcher and wrapper do not expose enough transactional ownership to implement this as one safe local patch. No source edits, native builds or cache operations were launched during this audit.
