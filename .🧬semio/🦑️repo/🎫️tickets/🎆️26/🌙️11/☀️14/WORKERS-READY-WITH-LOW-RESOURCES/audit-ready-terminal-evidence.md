# Ready terminal evidence retention

The initial source and receipt review was read-only. The observations describe the authored source and existing m02 and m07 receipts. The loaded worker revisions remain unverified.

The current inflight watchdog checkpoint stores `progressAt`, a hash of the latest matched progress key, coarse phase (`reading`, `executing` or null), phase time, offset, step and holder state. It does not retain the last productive owned activity text or its structured resource and counter. The checkpoint supports adoption while the inflight record exists, but completion removes that record. Terminal timing stores outcome, times, exit/signal and physical evidence, without that phase or detailed watchdog verdict. A typed local `stop` is written before termination when a launch proof exists, but it is removed with the inflight record; both hard deadline and the post-soft-limit `stalled` deadline path call `kill("timeout")`, so even that stop value does not distinguish them.

Failure mirroring scans the full tools log for bounded structured tool-refusal lines, and filters heartbeat noise from only a bounded failure window. It can retain a real structured refusal beyond a noisy tail; it does not retain arbitrary earlier productive progress after it falls outside that window. This explains why the m02 terminal receipt can prove `stage-timeout` but not its last owned activity or exact deadline verdict. m07 has a terminal timing receipt after the last mirrored ready status; the older ready status therefore does not establish current execution. These observations establish an evidence gap, not the worker-loaded code or a functional watchdog failure.

The physical m02 tools receipt at 05:34:48.815 recorded 14,401 seconds. The m07 receipt at 04:42:58.362 recorded 11,762 seconds with an exit receipt. Both receipts carry `stage-timeout`. The current authored tools cap is 3,600 seconds times four, before speed scaling can increase it. An m07 duration of 11,762 seconds under those rules implies the soft-idle route. These historical receipts lack the recorded deadline decision and loaded policy identity needed to establish the exact cause unconditionally.

## Staged terminal evidence

The [review patch](ready-terminal-evidence.patch) adds optional closed evidence to the existing stage checkpoint and timings schema. It records the last recognized structured, running activity as a resource and work counter. The origin is the exact stage's own log and the previous checkpoint must match the stage, PID and start identity. Resources are allowlisted producer operation labels. The counter describes the producer's ordinal or work count. Generic elapsed heartbeats, queued activity, inadmissible labels, invalid integers and repeated or regressing counters of the same resource leave the last productive evidence intact. The implementation consumes the existing bounded complete-line input and the existing checkpoint cadence. At normal completion it also consumes the remaining bounded unread lines.

An exact timeout stop writes the deadline discriminator, `hard-cap` or `soft-cap-idle`, with the existing local `timeout` stop field. The checkpoint is flushed before the stop is written. A later supervisor can reconstruct the discriminator from a recorded timeout with the existing launch proof. Both ordinary and different-stage settlement can include the evidence in their physical timing receipt. Containment, public timeout/refusal codes, exit status, cancellation and retry retain their existing routes. Historical attempts retain the evidence they actually recorded.

The private fixture detaches a real child, appends 24,000 generic heartbeat lines and resumes under the same process identity. On each timeout the child reads the durable stop record before writing its normal exit receipt. The fixture checks its typed refusal, the local and mirrored timing, the observed cutoff and the last bounded activity against SQLite independently. Original-source testing reproduced missing evidence in both physical cases. The private overlay exercises the real Ready entry points and schema without a workspace source write. The two physical timeout cases ran on macOS. Windows normalization runs through the existing neutral fixture.

The initial timeout overlay passed 29 tests and 564 assertions through `repo tools exec --light bun -- test`. Three tests cover the new corpus and two physical timeouts. The other 26 cover stage completion, adopted watchdog state, failure-log retention and Windows log normalization. The review patch passed a read-only applicability check against shared source and awaits the coordinated deployment decision.

## Owned overdue step evidence

The [m12 record](audit-m12-step-overdue-0657.md) pairs an exit receipt categorized as `stalled` with a later `step-overdue` Ready reason. Before this change, the watchdog observed an elapsed step value, declared bound and exact quiet interval. The supervisor calculated the speed-adjusted limit and retained the step and rounded quiet seconds in memory for the current status. Settlement discarded those values. The m11 receipts carry only a generic stall, so its trigger remains unknown.

The staged patch stores `stepOverdue` on the exact same-flight `overdue` stop before containment and carries it into the terminal `watchdog` evidence. The closed shape holds four safe nonnegative integers. `seconds` is the step's observed elapsed seconds, `bound` its declared seconds, `limit` the computed speed-adjusted limit in seconds, and `quietMs` the actual no-progress interval at the decision in milliseconds. The receipt stores the numeric measurements only. The existing live status uses the current supervisor's step text and rounded seconds. Adoption recovers the measurements from a valid launch and recorded overdue stop, with or without a wrapper exit receipt. Normal and different-stage timing paths publish the same shape. Deadline disposition, current status wording, physical exit handling, retry and watchdog thresholds retain their existing behavior.

The neutral case and its independent SQLite calculation exercise a detached child across watcher adoption. The child captures the stop record at SIGTERM and writes an exit receipt. Ajv checks the stop and terminal records. The fixture checks the scaled limit, the quiet window against the independently observed endpoints, the exact recovery of all measurements, and equality of the local and mirrored timings. It also replays the genuine record with a different stop, a negative quiet interval and an elapsed value below the limit. Those records retain only the independently valid activity evidence. Before the extension, the fixture confirmed the real overdue stop and then failed on the missing timing measurement. The patch remains staged in this ticket.

The expanded overlay passed 51 tests and 1,027 assertions across the ticket fixture, failure-log, step-overdue, watchdog adoption, stage-completion and Windows progress suites. The detached-child cases ran on macOS. The patch passed a read-only applicability check.
