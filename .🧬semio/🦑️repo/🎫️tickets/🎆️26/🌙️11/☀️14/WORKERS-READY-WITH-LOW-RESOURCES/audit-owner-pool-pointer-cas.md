# Owner pool pointer publication

The physical whole-read log alternated between accepted and refused offers for wave 72a2521728b6. The pool status files also showed workers switching between that wave and 16352c072fd1. Those observations prompted the source review. They do not determine the reason for individual refusals.

The first reproduction used two signed origins on a real loopback cache. One publisher read an existing pointer containing a five-owner wave. Before that read returned, its competitor successfully added a nine-owner wave. The original publisher then reported success while replacing the pointer with just the five- and seven-owner waves. The lower-level head swap had reread the current digest after the caller had already merged stale content. The owner pool now publishes with the digest of the exact action-result bytes that produced its pointer. It rereads and merges again after a conflict. Lookups that fail do not supply an empty merge base.

A second reproduction held the first authenticated replacement at the cache store while another signed origin attempted to update the same prior digest. Both previously received HTTP 200. Action-result commits now serialize their comparison and publication by namespace and key. The second writer receives HTTP 409 and can safely retry. A stale result removed during a read is also compared under that serialization before deletion. Payload limits and signature validation still run before a write enters the commit queue.

The signed head suite passed four tests and 36 assertions. SQLite independently established the expected pointer order and set of concurrent outcomes from the neutral fixture. The ongoing coordinator read was already running when these changes landed. Its pinned process cannot prove that the updated publisher handled its earlier refusals.
The adjacent owner-pool, cache server and signed-head run passed 16 tests with 2,023 assertions.

The signed cache also refused another signed origin using the same wave ID when the new head carried different publisher and creation metadata. A publisher can now continue an offer after the manifest conflict only after it reads the existing manifest and independently recomputes the same wave identity from both manifests. The wave identity includes the record-code revision. A conflicting revision has a separate wave and cannot reuse the same ID. The signed head and early-wave suites passed eight tests and 93 assertions. This reproduction establishes the compatible-manifest refusal. The physical log did not preserve individual refusal codes.
