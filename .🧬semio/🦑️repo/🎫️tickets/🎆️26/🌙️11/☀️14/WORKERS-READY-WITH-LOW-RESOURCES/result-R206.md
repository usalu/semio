* Rows `within` the cargo phase (summed over workers, not part of the sum): Cargo's own `--timings` report read offline from `<target>/cargo-timings` (start delay = resolution and fingerprint checks before the first unit, front end, code generation, unsectioned seconds = build scripts and links, serial critical path in units and seconds, longest 6 units, one `slow=` line only for units above 10 % of the cargo wall) and the unit events of the task's lane (`unit:restore-local`, `unit:restore-fleet`, `unit:lookup-fleet-miss`, `unit:compile`, `unit:publish`, `unit:wait`, counts and seconds). `--timings` is added to the spawned `cargo build` only (not to the recorded invocation); `SEMIO_CARGO_TIMINGS=off` turns it off.
* Front of the run (`⚡️caching/🚀️bootstrap/📜️script.ts`): a successful Nx task prints nothing, so the front prints after the run the ledger lines of every task that wrote one since the run began plus `[phase] run total= longest-task= outside-task=` (the time before and after the tasks: graph, hashing, native-storage queue). They land in `ready-log-workspace.txt` beside `[units]`.
* Line format: `[phase] task=<id> name=<phase> seconds=<s> count=<n> [bytes=<n>] [within=cargo]`, head line `[phase] task=<id> total= phases= other=`, `[cargo-timings] task= units= wall= start= frontend= codegen= unsplit= critical-units= critical= longest=`.
