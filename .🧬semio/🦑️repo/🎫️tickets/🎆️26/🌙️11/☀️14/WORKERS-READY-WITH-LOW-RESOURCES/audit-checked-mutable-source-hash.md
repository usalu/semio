# Checked Hashes for Large Outgoing Files

The [coordinator descriptor audit](audit-mutable-pack-publication-1315.md) observed three advancing offsets on the same 6,314,703,074-byte Git pack while the file's modification time also advanced. The same-size publication path previously read to EOF before checking the source again. The coordinator could spend an entire read on a changing file before retrying it.

When the publisher rehashes a previously recorded same-size file of at least 64 MiB, it now checks the physical source before opening, after opening, every 8 MiB, and before accepting the result. A single 1 MiB buffer bounds each read. The hash yields between chunks, checks for cancellation before and after reading, and reports advancing local bytes as `publish-hash`. The name and the open descriptor must both continue to identify the same regular file, device, inode, size, modification time and change time. A missing or replaced source, a changed stamp, or premature EOF produces an unstable result without a digest. The publisher keeps that path on its existing retry path. Completed reads still supply the exact SHA-256 and byte count. The small-source and generic hash callers use the earlier path.

Four new boundary cases failed before the change. The focused boundary run then passed seven tests and 70 assertions. The neutral fixture covers exact SHA-256 and byte count, same-size and same-mtime replacement, in-place mutation with restored mtime, and cancellation after the first 1 MiB. The stable digest agrees with both Bun's independent hasher and Python `hashlib`. Replacement and mutation were refused at the first 8 MiB identity check.

A private 64 MiB publication test changed the file on the first hash progress event. The real publisher emitted instability, returned the file for retry and left its journal head byte-for-byte intact. The next stable attempt reached all 64 MiB and published one event. The scratch tree was removed afterward. These local checks do not establish fleet adoption or an end-to-end time improvement for the live coordinator.
