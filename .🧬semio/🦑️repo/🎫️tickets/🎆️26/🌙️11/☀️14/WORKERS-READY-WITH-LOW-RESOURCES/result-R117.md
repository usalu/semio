## 2. Governor choice (changed)

Rules and where they live:
1. First farm child always admitted (`essential`): the capacity request of the farm carries `essential: true` for the first ask (`requestBuildFarmCapacityV1`, farm `open()`), `decideHostCapacityV1` first decides it like any request (more jobs when the memory carries them) and, where the ordinary rules would make it wait (memory, load, queue order, swap, soft stop), admits its minimum jobs instead (reason `override`, charged in full to the ledger), unless a grant of the same label, holder and session already runs, the request is replaced or not elastic, or the host is in critical pressure. The floor applies to the additional children (the second ask is not essential). Schema `Request.essential`.
2. No inline fallback while a child could come: `prepare` of the farm waited at most `grantWaitMilliseconds` (60 s) for the host's answer and then set `hub.unavailable`, which sent every later owner of the read to the parent for good. It now waits as long as the request is pending; only a started pool that stays silent for `holdMilliseconds`, a refused or cancelled request and a farm that is off let the parent infer (the read's own no-progress watch of R106 still ends a stuck read). The old law test of "a pool that never comes" was rewritten to the new law.
3. The parent releases its caches before a child is held back: `farmHeldV1` takes a `release` function and calls it before it answers true (bytes freed are subtracted from the tree footprint); the project farm gets `releaseCaches` from the read (`releaseAfterTakeLookV1(scripts,{shrink:true})`: closure entry cache halved, script cache and shared source files cleared).
4. Sizing of the read's grant: `show` and `graph` already start with what they need now: full request learned at 14336 MB, `minimumMegabytes` 3072 (parent 1536 + one worker 1536), admitted with what is free when it covers that (`shrunk`) and grown later. The 936 s wait of pid 99197 was the host having less than 3072 MB above the floor (the previous read's parent at 17 GB), not the size of the request. A law test pins `minimumMegabytes >= 2 x worker`. No code change for this rule.

Tests (new, red before and green after unless noted): `host-capacity/🧪️tests/🥇️essential` (6: baseline waits; first worker admitted at -233 MB spare; sibling of same label/holder/session makes it ordinary; critical pressure and non-elastic keep old rules; admission is charged so a later request waits; a roomy host gives the preferred jobs through the ordinary path), `project-farm/🧪️tests/🥇️first-child` (5: first ask essential and the second not; owner waits 900 ms (3 x hold, 6 x grant wait) for a pending grant and then runs on the child; cancelled grant ends the wait; `farmHeldV1` releases before holding; graph read minimum), `memory/🧪️tests/🪶️owner-retained` (2: retained bytes per owner with shared strings under 48 KB and a third of a raw copy; flat second hundred; green before, a guard), rewritten law in `project-farm/🧪️tests/🟦️.ts`. The 257 stored vector worlds of the lend oracle decide as stored with the changed decision function (checked outside the harness because the lend test file itself fails in the baseline of this machine: 0 pass 1 fail before and after).
