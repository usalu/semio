2. **Mechanism (sampled live, ps every 2 s, `sample` of a worker and of the parent).** (a) The pool is created per inference call and closed with it: 2 calls per wave (prefetch, build), a pool lives 23 to 55 s, then every worker is gone. (b) The handshake needs the parent's event loop: a worker boots in 0.7 s CPU, sends `listening` and then waits for the parent's `init` message. The parent's main thread is 98 % busy inferring (`sample`: 2626 of 2626 samples in JS, `kevent64` in <3 %); bun serves IPC only between macrotasks, so with 8 loops that each run seconds of synchronous work the `init` is answered after 8 times that (synthetic test: 8 loops of 100 ms sync chunks delay the first message to 0.84 s, of 3 s chunks to more than 20 s). Six hosted workers of wave 142 and wave 143 sat 23 to 55 s at 0.67 to 0.71 s CPU and 97 MB footprint (`sample`: idle in `kevent64`), never initialised, never ran a project. The one worker of the process's own grant happened to get its `init` (the parent was between projects) and then worked: 44 projects in 120 s with 1:55 CPU (2.6 CPU s per project, 22 projects a minute, 1.2 to 1.8 GB). (c) Assignment is push: the parent loop takes the next project (`cursor++`), computes its key (assembly authority), calls `farm.prepare`, which queues it in the pool; jobs in flight = parent loops. (d) The parent infers a project itself when `prepare` returns false: the first `parentWhileStarting` = 2 projects always, and every project once the pool is not ready after `startWaitMilliseconds` = 20 s (flag `gaveUp`, never reset), which the starved handshake guarantees. (e) **P4's governor slot is held while a project waits for its worker**: `governor.run` wraps `inferProject` including `farm.prepare`, so at most as many projects as the budget admits (2 with 1 536 MB) are at the workers at the same time, however many workers exist. This and (b) explain "about two at a time" and the slower waves after P4.
3. **Landing 1 (interim, what it changes).** `🧠️memory`: new policy `serveHostMegabytes` 24000 and `serveHostShare` 0.25; `graphParentManagedBytesV1` gives a machine with at least 24 000 MB (the graph server's `serveTotalMegabytes`) a growth budget of a quarter of its memory (8 192 MB on 32 GB), at least the declared 1 536 MB; machines below keep P4's `parentHostShare` (16 GB: 1 024 MB). A smaller capacity grant still lowers it. Tests: `🧹️parent-budget` 10 pass (two assertions rewritten for the serving rule); memory main 4 pass, 1 red (bundler test, not touched). Originals: `T/🗑️generated/P5-interim/`. Result: waves 148 to 150 took 191, 112, 50 s per 48 projects against 310 and 498 s.
4. **Landing 2 (prepared): the farm as designed.** (i) Workers start from their environment (`SEMIO_GRAPH_WORKER_INIT`, schema `Start`; the `listening`/`init` messages are gone), so a busy parent never delays them: test proves 2 of 2 real workers opened their session during a 2.5 s block of the parent's loop, the live protocol 0 of 2 (control run). (ii) Pools belong to the session (`HUBS`, key = digest of registry, contracts, command inputs, project roots, implementation): the second construction of a read uses the running workers (`reused` line, EN and DE), a changed session retires the old pools, `closeProjectFarmsV1()` ends all, idle hubs end after 300 s, workers are unreferenced while no construction uses them (a read still ends by itself). (iii) The parent never infers while a worker can be had: no `parentWhileStarting`; a project waits at most `holdMilliseconds` 190 s for starting pools or `grantWaitMilliseconds` 60 s for the host's answer, then `unavailable` (reset when a pool is ready) lets the parent infer; a cancelled job (abort signal) is settled `aborted` and its worker retired without counting a lost process. (iv) The farm wait runs `away` from the governor slot (`createMemoryGovernorV1.run(task)` hands `{away}` to the task; `inferProject(job, away)`), so the budget bounds only what the parent itself infers; `loopsPerWorker` 3. Tests: new in the farm main file (hold, never-comes, session reuse and retire, self-start under a blocked loop with a Python-computed expected value list, abort), `🚪️away` in memory and project-nodes; existing fakes moved to the new handshake (`farm-close`, `declined`, `release`, `captured`, `retirement`).
