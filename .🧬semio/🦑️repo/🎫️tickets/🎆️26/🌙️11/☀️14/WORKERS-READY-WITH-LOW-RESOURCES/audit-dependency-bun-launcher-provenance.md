# Bun Launcher Environment and Dependency Receipts

The native `repo show projects --graph-policy=current --lang=en` reported a stale root dependency generation receipt with class `configuration-changed` and path `env:BUN_INSTALL`. The same command progressed through more than 178,816 parser source listing operations and then shared and exclusive dependency verification. Those counters establish that this invocation paid for substantial verification after rejecting its receipt. They do not isolate the cost of this environment variable on a physical worker.

A bounded native probe selected the same `~/.local/bin/repo` for the shell and Ready. With the existing, unset and alternate values of `BUN_INSTALL`, the pinned tool wrapper launched the same managed Bun binary and reported version 1.4.2, revision `744846f844374847c902b5e7fd59b4342a51ef99`, and the same complete dependency generation runtime identity. The Store-owned producer environment cleared `BUN_INSTALL` in all cases before launching that exact executable. Before the change the dependency receipt alone saw three different environment observations: a hash for the shell value, no row when unset, and a new hash for the alternate path.

The Bun descriptor now excludes the ambient launcher locator from its producer receipt key. The host executable lookup declaration still includes the locator, and verification still checks the running Bun identity and installer recipe. Registry, cache, proxy, certificate and installation configuration continue to affect the receipt where they did before. The native probe now gives identical complete producer observations across the three locator variants while a new `NPM_CONFIG_REGISTRY` or `BUN_INSTALL_CACHE_DIR` still changes provenance. A receipt sealed under the earlier producer projection can take the normal verification and publication path once before a new receipt becomes reusable across the ambient variants.

The language-neutral generation corpus reproduced the false mismatch before the policy change. The same fixture now verifies alternate, unset and mixed-case locator variants and still refuses altered registry and cache evidence. Python independently checks the environment rows and their hashes, and Ajv checks the receipt contract. All 17 runnable generation receipt tests passed. The real-journal fixture skipped because the watcher executable was unavailable. Independent Python minted the reviewed Bun descriptor and materialized schema digests.

The broader run reported 114 passed, one skipped and five failed. The registry and independent vector tests both reported the same existing UV descriptor checksum disagreement. Diffing the independent minted vector with the checked-in vector isolated that one UV row after the Bun changes. A test-only preload restored the earlier Bun policy and reproduced the other three failures: the mid-write cancellation expectation, the package-manager literal ratchet, and the graph row-path lock-name declaration. This verification issued no graph build, dependency sync, resource admission change or worker restart.
