# Stage Observer Index Writes

The current gitStateV1 uses the live index for its default writeTreeV1 call when the signature cache misses. The existing native cache-tree fixture explicitly verifies that this Git call changes the live index bytes, and then confirms the observed tree. The code checks the resulting signature and, when it moved, certifies the current index against a private snapshot before publishing the observation. Thus observation itself can write the live index; the mirrored counters do not identify which writer caused any particular index change.

In a fresh sample, stage-observe-index-changed counts were m02 43, m07 34, m08 82, m10 27, m11 29, m12 26 and server 1. m02 currently reported null; the other sampled workers and server reported the newer exact tree 0401fa055d8df31143107ba00e76bf7d787cf241. m05 separately reported one stage-index-busy event. These counts describe observation outcomes, not the identities or causes of index writers.

The existing private snapshot path clones the index, uses GIT_INDEX_FILE with splitIndex and sparse-index configuration disabled, checks the live signature and checks the HEAD/ref stamp before accepting. Trying private certification first could avoid the observation write while retaining fail-closed checks, but its write-tree may still create object files, and correct handling of split-index shared backing must be established. Existing native tests cover split-index publish and apply, not demonstrably private-first observation under all those conditions. Any implementation needs native tests for shared split indexes, sparse indexes, unmerged and missing objects, concurrent edits and unchanged live index, as well as a semantic tree oracle. This is a bounded design lead, not proof of the cause of current churn. No source, Git state or remote worker was changed.
