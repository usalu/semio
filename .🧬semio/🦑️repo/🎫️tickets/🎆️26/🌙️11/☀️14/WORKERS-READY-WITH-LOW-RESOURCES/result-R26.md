## 2. What changed (principle: observation narrowed to consumed facts, snapshot by content)
- Rows 1-3: the replay (`replayCurrentMembershipV1`, `authenticateCurrentMembershipV1`) already judged unsettled directories by projected-listing content (files, dot names, output names, testing collections are not part of it), so file churn never trips it; what tripped it were unrelated new/removed directories. Now `requireCurrentMembershipV1` loops: replay; on a move re-derive (listings are reused under stamps) and compare the fresh result with the ORIGINAL verified report and the baseline texts (original plus decision manifests adopted earlier), refusing at once on any real difference; accept when the fresh frontier replays clean; after `maximumRederivations` (schema `FrontierReplayProtocol`, 3) refuse with `Bun current ownership changed after refreshed continuation: <first moved path>; <fact>` where fact is existence, identity, listing or content digest (also the typed `reason`: vanished, appeared, identity, roster, bytes). Helpers `ownershipMoved`, `ownershipStateMoved`, `firstOwnershipDifference`; owner-local state `owner.moved` (no module global).
- Pinned fixtures: the old contract (`last-fresh-continuation-*-refuses`, `membership-change-remains-refused`, manifest cases) is KEPT and still green: those cases are real input changes (a new package, a changed decision manifest) and are still refused, now with the path in the message. R18's attempt broke two of them because it compared against the latest derivation; here the baseline is the original report, so none had to change. Only the `⏩️frontier` test bindings were extended (the extracted function now calls two helpers).
- Row 8: restart cause carried and printed on exhaustion; texts `finalcause` EN/DE, schema keys `causeEnvironment`.
- Row 10/11 already follow the import-closure rule (own source file / failing load); nothing to narrow, documented.
