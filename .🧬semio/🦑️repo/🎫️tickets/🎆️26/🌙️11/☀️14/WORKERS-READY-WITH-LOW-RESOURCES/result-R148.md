Not the cause here, measured on this checkout: every dependency generation under `.cache/b/d/m/j/*` (12) has root `typescript` 5.9.3; the repo slot (`w/124`) and the parsers slot (`w/128`) are empty, so `createRequire(library/🟨️.mjs)("typescript")` reaches the root install; in Bun 1.4.2 it returns 2244 exports with `preProcessFile` as a function, also from 12 concurrent worker threads, behind a `Bun.plugin` `onResolve` filter `/.*/`, and after a failed first load (Bun retries a throwing CJS module instead of caching half of it).

The one concrete candidate in the tree: `bun.lock` locks THREE typescripts: `typescript@5.9.3` (root), `typescript@6.0.3` (as `typescript-compiler-api`, an alias of jco) and `@bytecodealliance/jco/typescript` = **typescript@7.0.2**. The 7.x package is the native compiler: its `exports["."]` is `./lib/version.cjs`, which exports the version only, no compiler API at all. Resolution is per machine: it follows the node_modules layout that machine's `dependencies` stage built. I could not read g1-m01's layout (only its store origin folder), so this stays a hypothesis; the repo-wide fix below makes the engine path independent of it.

## 2. The fix (engine reference classification without the compiler)

New member `🏗️build/🧮️task-model/🔎️module-references/` (`🟦️.ts`, `🧬️schema/🔣️.json`, `🧪️tests/🟦️.ts`, `🧪️tests/🧫️corpus/🔣️.json`):
- `scanModuleSpecifiersV1(text)`: a port of `preProcessFile(text, true, true)` onto an own tokenizer with the lexical rules of the TypeScript scanner (strings with cooked escapes, template literals with the substitution stack, comments, shebang, merge-conflict markers, operator munching, no regular-expression tokens on purpose). Same limits as the compiler, so the rows are equal for every text, also where the compiler's own reading is wrong (a `'` inside a regex literal opens a string to the line end; corpus row `regex-quote-to-line-end`).
- `scanUrlReferencesV1(text)`: `new URL("./…", import.meta.url)` as tokens, regular-expression literals recognised by the usual previous-token rule, `import.meta.url` must be written without trivia (as `getText` required), exactly two arguments (a trailing comma allowed).
- `classifyModuleReferencesV1` = modules, then URLs, each (kind, specifier) once. Library `nxBuildEngineReferencesV1` now maps it; `createRequire` and the compiler are gone from that file. The compiler is the oracle only in tests.

Proof (compiler oracle = `ts.preProcessFile` + the former AST visitor, kept in the law):
- Law `🧪️tests/🟦️.ts` (6): corpus closed by the schema (Ajv); own scanner equals the language-agnostic corpus of 26 texts (comments, strings, template literals incl. nested and in substitutions, regex literals, dynamic import incl. optional chain and member calls, re-exports, type-only imports, `import type from`, AMD `define`, `declare module` at top and nested, unterminated strings, conflict markers, shebang, unicode identifiers, duplicates); the compiler reads the same corpus rows; own equals compiler on every non-JSON file of the live engine closure (1376 files); module pass equals the compiler on seeded truncations (12 cuts of every 40th big closure file, reaching every lexical state); no `preProcessFile` or `("typescript")` in library `🟨️.mjs`. ## 3. A deterministic resident failure must not say "try again"

Finding: R140's same-cause rule lives in the slice pool and counts DEATHS of a worker (exit with the stderr cause text, 3 in a row stops the plan, `host-slice-worker-failing`, retry never). This failure was not a death: the worker reported `{type:"error"}`, the pool rejects at once without restart (no loop there), and the service turned it into the `internal` refusal whose text says "try again" and whose retry is `later` (client exit 75, which the readiness loop retries). So the rule did NOT cover this path.

Fix (`🏡️resident`): `failureRefusalV1` takes `streak` and `sameCauseMaximum` (default `HOST_POLICY_V1.sliceRestartSameCauseMaximum` = 3). The same unexpected failure, identified by name, code and message (`failureMessageV1`, not the stack: async frames of one defect differ), 3 times in a row is the typed `internal-repeated` refusal: retry `never` (client exit 1), count in the fields, EN and DE text "deterministic, trying again does not help, the code or the install on this machine has to change first", still with reference and log, and the failure block still lands in the origin folder. The host holds the streak. The first two failures stay `internal` / `later` (a defect cannot be told from a transient failure on first sight).

Law `🏡️resident/🧪️tests/🧯️failure/🔁️same-cause/🟦️.ts` (5, red before): policy value and both texts without "try again"; unit sequence 1,2 internal later, 3,4 repeated never with count; another cause resets, another kind (disk) is not counted; no streak is as before and maximum 1 repeats at once; a running `createHostServiceV1` with a throwing planner answers 4 real client requests with retry later, later, never, never, EN `3 times`, DE `3 Mal`. Failure tests 17/17 and the host tests 36 of 37 pass.
