# Graph watchdog during an owned rebuild capacity wait

At about 10:32 UTC reader 19453 was still owned by runner 19451, and its descendant 60971 held a live 4,096 MiB plan grant. The same PID, grant ID and rebuild scope had an exact 14,336 MiB queued replacement. The canonical host capacity decision was wait for memory, with about 4,539 MiB measured headroom. The old observer ended a silently waiting read before looking for this evidence. Its diagnostic capacity lookup also looked only at the root reader PID.

The observer now asks a bounded local probe shortly before the quiet deadline. A valid wait requires the canonical fair evaluator to return a memory wait for a whole graph show-plan rebuild replacement, the matching current held grant and queue, and the exact outstanding rebuild request. The gate checks both issuer and holder births, the holder boot and admission identity, the same rebuild scope and queue arrival. The native ancestry must lead through the read PID to its detached runner. The observer rechecks the exact runner record and fresh beat before applying evidence. The probe runs outside the read loop with a 7.5-second subprocess limit, and only one probe can be outstanding. Unavailable, stale, malformed, withdrawn, differently owned and impossible requests earn no new time.

The watchdog deducts only the verified wait interval from quiet duration. A monotonically accumulated credit stays in the existing exact-reader checkpoint across detach and reattachment. The next observer rechecks the wait. A proven booking of the same request starts the existing quiet window at its booking time, so a healthy long wait can resume without immediately being stopped. The separate 12-hour maximum and elapsed-silence memory policy use their original clocks. For the exact verified descendant wait, the held plan’s reservation is available to an otherwise unattributed raw footprint sample. The queue and heartbeat are never counted as completed graph work.

The production probe returned a confirmed 4,096 MiB plan wait for the still-owned reader 19453 using the current live gate and native process lineage. It only observed the state through the usual local capacity status path. No new grant, remote action, graph command, service signal or checkpoint rewrite was issued.

The real detached runner test was red before capacity inspection. The passing fixture uses a language-neutral timeline and independent SQLite credit calculation. Native gate tests verify the actual queue and request against a changed arrival, foreign ownership and exact later booking. Device-bound handoff tests cover continuation after a healthy long wait, a lost proof, the unchanged absolute limit and raw memory overrun.
