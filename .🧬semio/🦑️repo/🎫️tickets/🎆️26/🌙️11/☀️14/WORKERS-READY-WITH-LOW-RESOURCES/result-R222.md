## 1. "Closed pinned dependency recipe required (reference ed58d12c)": not a Windows fault, a schema fault of the repository

- Throw site: `nxDependencyInstallFilesV1` in `🛠️tools/📦️sdk/📥️source/📐️projection/🟦️.ts` (called by `captureNxToolingInputsV1` in `🛠️tools/🟦️.ts` with the parsed `package.json` of the tools recipe, and by the pristine SDK comparison). It throws when the recipe does not validate against the `Recipe` definition of `📐️projection/🧬️schema/🔣️.json` (closed: `additionalProperties: false`) or when the lock is no object. The "reference" is the first 8 hex digits of sha256 over error name and message, so it is the same on every machine.
- A "closed pinned dependency recipe" is the authored `package.json` of `🧰️framework/…/⚡️caching/🚀️bootstrap/🛠️tools` (name, private, packageManager, dependencies, semio.toolPatches, exports, devDependencies), closed by that schema; its `bun.lock` is the pinned lock. R152/R166 are not involved.
- Cause, reproduced on this Mac with the real files (`validateJsonSchemaSubset(Recipe, package.json)` returns `["/type is not allowed"]`): `package.json` of the recipe was edited on 2026-11-18 11:56 UTC (it gained `"type": "module"`), the `Recipe` definition (last changed 2026-10-20) has no `type`. Every machine that reaches the capture of the tooling inputs refuses, on any platform. g1-m05 reached it in attempt B (22:03 UTC) and again at the end of attempt C (23:03 UTC, verbatim `Internal error: Closed pinned dependency recipe required (reference ed58d12c)` after `chromium 1248 already matches its pin.`, run 1880 s). No backslash, drive letter, case or CRLF is involved.
- Fix by construction: `Recipe` declares `type` (`const: "module"`). New typed refusal `NxRecipeRefusedV1` (name `NxRecipeRefused`, message unchanged, `texts` en/de naming up to 6 violations, e.g. `/type is not allowed`, or the lock text naming `bun.lock`), registered in the boundary list `TypedRefusals` (`nx-recipe`, exit 1), so the CLI never prints "Internal error" for it.
- Laws (`📐️projection/🧪️tests/🪟️live-recipe`, 5): the real `package.json` is closed (every key declared, ajv agrees), CRLF line endings project the same inputs as LF, every foreign field (`type: commonjs`, `scripts`, `version`, `bin`) is refused by ours and by ajv with a typed EN/DE text that names the field and renders through `reportBoundaryErrorV1` with exit 1 and no internal-error text, a lock that is no object gets the lock text.
