## 2. What was built (landed)

- **Gate and trace in the right process.** `useEnvironmentGateV1` (footprint module) installs the gate in any process that runs inside a granted run but holds no grant object: it reads the reserved megabytes of `SEMIO_HOST_CAPACITY_GRANT` live from the scheduler (`readLiveHostCapacityReservationV1`, cached 10 s so a grown reservation counts), called from `settleWaveMemoryV1`, `createClosureSettlerV1` and the project inference start (`📦️project-nodes`). `bindProcessGateV1` is the single place that creates gate, trace file and watcher (the old inline code of `useCapacityGrantV1` is now one call).
- **Sampler.** Every 2 s a row in the trace file `<tmp>/semio-footprint/<pid>.log` (both languages, only on growth of 256 MB, a blocked loop of 1 s or after 20 s): step label (profile phase + running graph phase resource, `noteFootprintStepV1` from `⏱️phases`), footprint, resident, managed heap, external, array buffers, objects, loop lag and the 15 most numerous object types. A blocked main thread cannot run a timer, so hot paths (`internJsonStringsV1`, observation `record`/`recordRowV1`, `yieldInferenceV1`) call `footprintPulseV1`, which after 1.5 s of loop starvation writes a `starved` row with the stack (function names, 14 frames) and the counts.

- **Cap of the runtime.** `implementationProcessEnvironmentV1` (`🏛️sealed/📥️execution`) gives the process that runs a graph-reading command `graphChildEnvironmentV1()` (`BUN_JSC_forceRAMSize` 512 MB and the allocator purge), exactly what the trampoline gives its door; before, this spawn path gave nothing. ## 1. Why the existing caches did not give "a lookup" (answer to the coordinator's question)

`environment.scripts` (`files`, `closures`, `commandDependencies`, `declared`, `walkNodes`, `reachState`) is content-checked (`walkPartsHoldV1` per pass) and shared by all owners, but `releaseOwnerStateV1(scripts,{shrink:governor.pressure()})` ran after EVERY owner and `governor.pressure()` is `headroom() < 1536 MB`, where `headroom` is the garbage-inflated managed measure. So the caches were declared "under memory pressure" permanently: `files`, `closures` and `commandDependencies` were cleared after each owner, and `reachState`/`walkNodes`/`declared`/`toolGroups` (the whole module graph) every 8 owners, 32 without pressure; the next owner rebuilt the import walk and the TypeScript module resolution from scratch (the 28.9 s stretches). Also each owner is a new pass, so the whole graph is revalidated per owner (O(nodes), not measured separately).
