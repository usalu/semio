# Package Q4: a moved build-implementation closure no longer fails the task (2026-11-14, LANDED 21:19)

T = `…/☀️13/FLEET-ONE-MACHINE-SHARED-HOT-CACHE-AND-REMOTE-EXECUTION/`, LIB = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library`, CL = `LIB/🏗️build/📥️source/🔏️closure`. No graph, build, cargo or `repo` command was run (operating rule). Everything below comes from code, bun test files and read-only runs against the live tree.

## Verdicts

1. The check is `closure.source-differs` (3 throw sites in `CL/🟦️.ts`, `sourceBytes` and the two capture loops). Its list is NOT carried by an Nx command runner envelope: it is baked into the compiled image of the process (`import.meta.semioCapturedPhysicalSources` = path and sha256 of the whole implementation closure, `semioCapturedSourceResolutions` = import map of each file, both defined by `compileNxAuthorizerSnapshotV1` when the image is compiled). The failing image is `.cache/b/t/m/nx/<tooling digest>/semio-authorizers.mjs`, the Nx-resident bundle of the patched Nx (`nx@23.2.0.patch` calls `withOriginalNxFixedCacheV1` for every cache operation of every task). That bundle is immutable and lives as long as the orchestration; every cache operation of every task captures a child image through `captureBuildSourceClosureV1` and compares the disk with the baked list. A peer edit of one file of the closure therefore fails EVERY later task of the same run. Found site of the observed fault: the closure read worker of the storage headroom (`prepareClosureReadSourceV1`, static scope, 174 files, it reaches `🗣️language/🚨️error/🟦️.ts` through the texts catalog); the native directory helper (58 files) and the Bazel scripts use the same function and had the same hole.
2. What it protects: one consistent implementation per process (the child image must be the parent's) and a cache key (snapshot digest) that names the code that ran. Neither needs a failure.
3. FIXED AND LANDED (21:19, `T/landings.md` section "Package Q4 landing"; originals for `land.py --rollback` in `T/🗑️generated/Q4-landing-211956`): the task admits the current closure for itself. `captureBuildSourceClosureV1` walks the baked list as before; when the list is outdated (`closure.source-differs`, `closure.source-not-admitted`, an import the list does not know, a vanished file) it takes ONE new consistent capture of the seeds from the disk (`captureNxAuthorizerSourcesV1`, the capture the front door uses), walks the same static or closure scope over that new selection, and hands the snapshot (new digest = new key) to a fresh child. The new selection is kept in the process: the next capture goes straight to it (47 ms instead of 1.5 s measured), and is dropped when it moves again. Only a closure that keeps moving DURING one admission (torn read, vanished file, a file that differs from the fresh list again) is retried: 5 retries after the first attempt, pauses 0.25, 0.5, 1, 2, 4 s, a line in English and German per retry that names the files, the count and the last writer, then the refusal `closure.moving`, code `unserved`, exit status 75 ("try again later"), never an internal error. Edits outside the closure never take part.
4. Parent (`Owned Nx invocation failed`): a residual `closure.source-differs` in a task output is class `moved-source-closure` (`reexec`: the outermost command starts again with the current implementation, bounded as before), `closure.moving` is class `closure-moving` (`reobserve`, layer `build`: `settleNxRunV1` runs the Nx invocation again, finished tasks are cache hits, 4 attempts, pauses 2, 8, 30 s). When a run ends in a failure that stands or in exhausted reruns, `settleNxRunReportedV1` prints in English and German per failed task the first line that says why and "another rerun is likely to help / unlikely to help" (inputs edited, outdated implementation, the task itself failed) plus the tasks that did not run.
5. Pinning: a store exists in two forms. (a) Descendants of a captured process: `adoptedCapturedBuildLaunchV1` / `runAdoptedCapturedBuildSourceV1` start a child from the snapshot text the process holds in memory (immutable, sha-checked by the loader, no disk read); used today by the graph farm. (b) The sealed implementation store (`🏛️sealed`, `SEMIO_REPO_SEAL`, opt-in, off): every `repo` command runs a promoted content-addressed snapshot, so a peer edit never reaches a running or starting command until a promotion. Neither covers the Nx-resident hooks: their image keeps only the HASHES of its admission, not the bytes (the snapshot file is deleted after the compile, `rmSync(snapshot)` in `provisionNxToolsOwnedV1`). Design and cost of the full pin in "Not done" below; the retry part is implemented.
6. Task kinds of `workspace:setup`: script targets through the owner-command wrapper, cargo owner commands and the orchestration children are separate `repo` processes; each captures its own consistent snapshot at ITS start (front door, `executeCapturedBuildSourceV1`, live mode), so they adopt the then-current closure without any change; only the second capture inside a long-lived process (the Nx hooks, 20 to 60 minutes old) used a stale list. That is the one place the fix sits, and it covers every caller of `captureBuildSourceClosureV1` (runtime entries, closure read worker, Bazel scripts).

## What a worker will see when a peer edits build code in the middle of a run

- An edit of a file in the closure of a task's child image (the case of the failed `workspace:setup`): one line per moved set and process, `The sources of the build implementation moved while this task was running (1 files, first: <path>; last writer: -). The task admits the current sources for itself and goes on.` (German twin in German), and the task runs. No `RepoError: stale build.closure.source-differs`, no failed `deps-cargo` / `deps-trunk` / `deps-tools`, no skipped `workspace:setup`, `deps-cpp`, `deps-wasm`, `prepare`.
- Edits outside the closure: nothing at all.
- A tree that keeps changing under one admission: up to five lines `…are still changing (n files, first: …; last writer: …): admission k of 6 did not hold still, trying again in s s.`, then the task ends with `closure.moving` (try again later, exit 75); Nx then runs the invocation again (finished tasks are cache hits), at most 4 attempts with 2, 8, 30 s, and if that is used up the summary below.
- A run that ends in a failure: header `Nx run failed: n task(s) did not succeed after r rerun(s) of the whole run.`, one line per task `- <task>: <first line that says why> (another rerun is likely to help: …)` or `(another rerun is unlikely to help: the task itself failed)`, `Not run because a task they depend on failed (n): …`, in English and German.

## Not done, not verified

- NOT verified on a real worker: no `repo` build command ran (operating rule); the landing rules ask for one real command through the changed path, the coordinator should run it (`repo` start of any short Nx task goes through the changed `captureBuildSourceClosureV1`). The in-flight orchestration of a worker keeps the OLD image (`semio-authorizers.mjs` is immutable and was compiled before this fix): the fix reaches a worker with the next tooling provisioning (the tooling digest moves with every authorizer source; one SDK derivative per generation as with every closure edit).
- The reproduction of the production failure is read-only against the live tree with a baked list that has a wrong sha for the error module (numbers above) and in a scratch tree with real compiled images; the failed run itself was not replayed.
- Version skew accepted: the host process (old image) goes on with its old code while the child it starts runs the current closure; both are individually consistent, a peer change that alters a protocol between the two files in different commits can still make them disagree (same class of risk as every late-loaded module in a live tree; a worker that must avoid it sets `SEMIO_REPO_SEAL`).
- Writer ("origin") in the lines is `-` today. The replica keeps the writer per version of a path in `.cache/f/state.ckp`/`state.wal` (`book`: hlc `…-<origin>`), a binary store with no query command; a read-only `replica who-wrote <path> <sha>` would fill `origin` (the hook `ReadmissionRequestV1.origin` exists and is tested with a fake).
- Pin design (item 4), not built: keep the captured authorizer snapshot (about 1 977 files, 15 to 20 MB) as `semio-authorizer-sources.json` next to `semio-authorizers.mjs` in the content-addressed tooling directory, list it in `authorizers.outputs` of the receipt and in the generation schema of `tools/🧹️retention`; the admitted route then reads its bytes from that copy and never from the tree, so a peer edit can not produce a half-new process and the keys keep naming the Nx process's own version. Cost: +15 to 20 MB per tooling generation, a receipt and retention schema change, and children that run code up to a whole orchestration old (their keys then name old code). It is the right choice when reproducibility of one run matters more than freshness; the landed design takes freshness.
- Capacity: the authorizer runtime closure is 1 977 files against `maximumFiles` 2 048 of the closure schema (this landing added 3); the closure read worker alone is 1 910 files. Whoever adds more than about 70 files to that closure breaks the image compile before this code runs.
- Pre-existing, not mine: the refusals test `every declared message exists at its declared site` and `…never through a plain Error` are red before and after (the text `Stale loaded Graph reader policy; restart required` is no longer in `🕸️graph/🟦️.ts`); the runtime `existing`, `lifecycle`, `capacity` tests and the closure `resolution`, `stream`, `cache-root-refusal`, `selection` tests are red in this checkout before the landing (artifact path or environment), so they are no regression evidence.
- `closure.moving` in a task output makes the parent run the Nx invocation again in the same process; a rerun that again meets a stale image of the Nx process is not helped by that (the fix for it is the next provisioning); only the classification and the bounded retry are proven, with a fake rerun.

## What the other packages must know

- `captureBuildSourceClosureV1` no longer throws `closure.source-differs` to its callers; a caller that depended on that refusal (none found) would see a readmitted snapshot. Tests that want the old refusal must call the guard directly (the mismatch test now asserts the readmission and keeps the text contract of the refusal).
- New refusal `closure.moving` is code `unserved` (exit 75) and class `closure-moving`; new keys `closure.readmitted`, `closure.readmit-retry`, `closure.moving` in the build catalog.
- A snapshot from a fresh selection is accepted by `requireAdmittedBuildSourceClosureV1` through a `WeakSet` of snapshots this module produced; do not build a second path that compares a snapshot with the baked list only.
- Tests that compile an image (`🏃️tasks`, `🧾️mismatch`) need the working directory to be the repository root and an artifact directory inside it that is short and has no `.cache` segment; the landing script uses `.nx/q4a` (ignored by git).
