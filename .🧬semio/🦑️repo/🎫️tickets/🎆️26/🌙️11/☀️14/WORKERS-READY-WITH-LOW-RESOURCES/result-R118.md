# R118: a directory fact describes only the source tree

## What was wrong
`directoryFactV1` (`👁️observation/🟨️.mjs`) fingerprinted the whole `readdir` result of a directory. Machine-local output beside the sources (`dist`, `📤️dist`, `node_modules`, `.cache`, `.DS_Store`) went into the digest of `readdir`, `readdirNames` and `directories` facts, so a record made on one machine was rejected on another and on the same machine after a build (census R116: 233 of 4619 owner records, 84 more with stale closure entries). Proof on real data: the recorded digest of `🧰️framework/🔨️modules/🖱️ui/🎨️styling/📦️packages/🦀️rust` (`5aff136c…`, made without `dist`) is exactly what the new code gives for the same directory with `dist` present today; the recorded digests of the playbook and stdio-txt package directories (`46ea2859…`, `834a31c0…`) are the digest of the listing WITH `node_modules` (reproduced by brute force), which is the old behaviour.

## The authority
No gitignore reader exists in the build library at run time (the `ignore` package is only used by tests). The existing declared authority for "generated, never source" is the cache policy `⚡️caching/🔣️policy.json` `generatedDirectories` (the list the seal membership, the journal and the admission already use). Nothing declared the file-level noise, so it is declared in the owning schema `👁️observation/📂️source-names/🧬️schema/🔣️.json` (`rules`): `.DS_Store`, `Thumbs.db`, `desktop.ini`, `.localized` and the suffixes `~`, `.swp`, `.swo` (each covered by the root `.gitignore`, a test proves it with the independent `ignore` library). Rule (`sourceTreeFilterV1`): a noise name never counts; a name of `generatedDirectories` does not count where the entry is a directory or a link (a file named `build` is source). No directory list of its own exists in the module (a law checks it). `rules.readers` names every fact kind that reads a directory.

## Where it is applied
- `👁️observation`: `directoryFactV1` for the kinds `readdir`, `readdirNames`, `directories`, the observed `readdirSync` fingerprint and the TypeScript host `getDirectories`; new export `directoryFactOfV1(kind, path)`.
- `🧱️project-assembly`: the module-resolution `directories` fact (recorded value and its answer).
- `🧭️script-inputs`: declared module globs (`declaredModuleGlobsV1`, its skip list `DECLARED_SKIPPED_DIRECTORIES_V1` replaced by the rule: a glob no longer matches files below `dist` or beside `.DS_Store`) and the repository walk listing (`walkValueV1`).
- Not changed on purpose: the TypeScript project include listing (`declaredTypeScriptProjectsV1` mirrors `tsc`, its listing goes through the filtered observed `readdirSync` for the fact); results of observed `readdirSync` are still returned unfiltered to scripts (only the fingerprint is); the derived-nodes kind `directory-names` has no production environment port (`environment.readdir` is only supplied by its test), so it is not a source of records.

## Existing records and the stamp
The record revision `semio.graph-record/2` is NOT bumped, deliberately: the digest of a listing without a machine-local name is byte-identical to before, so every record whose directory facts were clean (about 95 percent) stays valid and reused, which a bump would throw away (4619 owners computed again). Records whose listing held a machine-local name digest differently now and are rejected by their verification once, then recomputed (no migration, no compatibility code). A process that still runs the old module writes old digests that simply mismatch. If the coordinator prefers a clean cut, the one line is `$defs.record.const.stamp` in `👁️observation/🧬️schema/🔣️.json` (`semio.graph-record/3`), at the price of recomputing everything.

## Tests (red then green)
`👁️observation/📂️source-names/🧪️tests/🟦️.ts`, 10 tests: two machines (same sources, one with `dist`, `📤️dist`, `node_modules`, `.cache`, `🗑️generated`, `target`, `.DS_Store`, `Thumbs.db`, a `.swp`) give the same digest for all three kinds; a new source file, a new directory (for `directories`) or a file named `build` change it; a symlink named `node_modules` is ignored; a missing directory keeps `!ENOENT`; the digest equals the digest of the names an independent `.gitignore` reader (`ignore`, root `.gitignore`) keeps; every declared noise name is ignored by the root `.gitignore`; the filter keeps a file named like a generated directory; a declared module glob matches only source; two source-text laws (every `readdirSync` of the module goes through `directoryFactV1`, the declared reader kinds equal the kinds found in the module, the assembly and script-input sites use the filter, the module has no list of its own). Red before: 4 of 8 failed with the old digest (the module was missing before that).
Results: staged battery (59 files, preload of the staged files, load 30 to 46) none worse than the unchanged tree; the script-inputs main test failed once in it (corpus project directory `pkg` is a generated directory by policy) and the corpus was renamed to `pak`; `🪪️presence` is 33 pass 3 fail (baseline) alone, 24 to 28 pass when run beside others (sandbox native-image races, not related). Under the lock after landing: source-names 10, record-revision 1, reuse 12, record-header 2, lookup-holds 1, script-inputs main 4, project-assembly 2, provider-closures preflight 2, heavy-questions 10, all pass.
