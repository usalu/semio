# Physical worker placement and whole-head fetch

The slice-lab script runs the real readiness path on its current host. Its one- or two-machine option makes local profiles with private runtime, state, temporary, capacity and cache paths under the same work directory and one private fleet store. It starts local child drivers and contains their processes on shutdown. No machine option names a remote worker. The normal `repo scheduler run` and `repo capacity run` commands admit work on their current machine. `repo service host` uses a local per-user endpoint. `repo fleet status` reports telemetry. `repo remote-execution workers` makes the current host consume hermetic Bazel actions. Its platform and worker properties select those actions. The deployed agent checks readiness and its Rust tools before it offers work. It has no command for a live-checkout Native lab on a chosen peer. Graph Wanted messages are expiring project-owner requests for another eligible graph server, and ordinary capability, claim and headroom checks select which server takes one. The protocol has no recipient override or whole-head fetch instruction. A launch already on the intended physical replica can use the repository-owned `repo graph --graph-policy=current` command for a bounded whole-head fetch. For the unpinned whole scope, it first serves a matching local seal when one exists. When no matching local seal exists, it can fetch a complete compatible head reported ahead by the configured signed exchange if the local builder is idle. The loader obtains local builder custody for restoration, disables inference effects for this attempt, then verifies the resulting seal. It reports the absent seal when the fetch conditions fail. This command can prove a remote fetch only when the restore receipt or output shows it, and it cannot force a refresh of a replica that already has a local seal. The fresh policy can claim and launch a whole read. These findings came from help and source inspection. No graph command, lab, remote action or worker change ran.
