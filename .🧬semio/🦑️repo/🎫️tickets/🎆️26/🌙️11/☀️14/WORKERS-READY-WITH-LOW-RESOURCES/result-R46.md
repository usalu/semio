# R46: every machine converges to the git state of the archivist (LANDED 17:29, live code 203e01b3)

## Why the machines differed (from the code and the store)
- indexTree d4f57b99 on six machines: the archivist's commit staged seven paths of 335 to 397 characters (limit 256). The index registers (`.cache/f/index/<path>`) cannot represent such paths; old code skipped them silently ("skipped unrepresentable" in the log) and still recorded the stage as published. `git diff-tree d4f57b99 bb588932` is exactly those seven paths. So the tree could never become equal; the same seven paths made `guards.trackedRefused` 7 on the server and 0 elsewhere.
- indexTree null on m02/m07: `write-tree` failed (index absent, corrupt or far off); old code only reported it. Both recovered by themselves before the landing.
- m06: `pending` = "self-check timed out after 180000 ms", then "not adopted automatically: refused before": the self-check (dry-open of the 130 MB state is 15 s of its 16 s on the idle server) timed out on the loaded machine and old code records a timeout as a permanent refusal of that digest.
- `fleet` failing with "exact managed workspace Source binding required": after the move to /Users/ueli/Documents/semio the dependency receipts (`.cache/b/d/m/j/<gen>/bindings.json`) still named /Users/Shared/semio and `node_modules` pointed at the old generation. It worked again after `repo dependencies sync --all` (run by someone else at 16:24 to 16:27, new generations, link moved). Not a replica defect; documented in the module README (relocation section).

## What landed (module `🤝️shared-worktree`, 20 files + R34 bundle; ledger in `1113-landings.md`; originals in T/🗑️generated/R46-landing-*)
1. Archivist's stage wins: only the group server publishes; members publish nothing, entries of other origins are void, a rebase request on a member is dropped (`skipped archivist-only`). A tree the entries cannot carry is published as the base (`published reason unrepresentable`).
2. A member whose stage is absent, corrupt, unmerged, far off or edited by a person is rebuilt: temporary index file from a copy of its own index (`read-tree -m` keeps stat data of equal entries), `update-index --refresh --ignore-missing`, every object checked, written into `.git/index.lock` (exclusive create) and renamed. Old index kept once under `.cache/f/lost/index-*` (newest 3). Worktree never touched. A lock whose mtime is older than 10 minutes is removed by a member (process liveness cannot be proven on every platform; a live git rewrites the lock, so an untouched lock is dead). Missing objects: wait with backoff, `objects-missing` in the attestation (`fleet` warning kind `stage`), the git heal runs after one minute.
3. View and verdict compare carried state only (R34 plus: every path the policy refuses leaves the view in any state; Python oracle updated). Verdict already judged head and indexTree; new warning `stage` names why a machine waits.
4. Conflicts: found a real divergence: on macOS an NFD-named local file (never carried, "not-nfc") aliased the carried NFC name and kept different bytes forever (`kept newer-than-remote`). Fixed: the alias is copied to lost and the carried content is written. `.git/info/exclude` rules (m07 had 10) are emptied (kept under lost) so views stop differing.
5. Self-check that only timed out or could not start is repeated every 5 minutes with the deadline doubled (to 30 minutes) and is no longer recorded as refused.
