## Verdicts
1. **A sound early cutoff exists for exactly one class of units: library units that emit metadata and no code (Cargo `check` and `clippy` chains).** Built, tested, and shown with real Cargo: after a body-only edit of `a`, `a` is compiled once, `b` and `c` (which depend on it) are cache hits whose metadata is rewritten onto the new `a`. The live wrapper compiles all three (section 4).
2. **Code units (`build`, `test`, wasm) cannot be cut off by an interface identity with stock rustc.** Measured, not argued: an object compiled against the old library may call an instance of a standard generic over the library's own types that the old object defined and the new one does not (`RawVec<a::S>::grow_one`); the rebased program does not link, with and without `-Zshare-generics`. Law test `compiler law (why there is no code tier)`. The code tier is therefore not in the policy at all. Every dependant of a foundation crate is compiled again in a build or test chain; that cost is a property of rustc's crate-hash design (section 2), not of this repository.
3. **The larger lever is not body-only at all, it is the granularity of the Nx task key** (section 3, numbers): a dependency edge hashes the whole `production` glob of the dependency PROJECT, and `value` alone is 41 crates plus everything else under its folder. A body edit in one crate of `value` re-keys 3 855 crates' tasks (1 040 projects), an edit of any other file under the project (README, script) does the same. Narrowing to the dependency crates' own sources would drop the mean from 1 033 to 420 re-keyed crates per edited crate. Not built: it needs the compile inputs of each crate (rustc dep-info) or a conservative module-tree rule, and a graph refresh.
4. **The project graph proper does not stale on a body edit** (R29's law test: "a body edit changes 0 nodes"; I did not re-measure it). What stales is the cached-target key (the Nx hash), which names the dependency projects' files by content. Deferring to a task-level cutoff at that level is designed (section 6), not built: it needs a byte-reading API in the exact-source batch and a graph refresh.

## 1. How a Rust source edit propagates today (read in the code)
| layer | mechanism | consequence of a body-only edit of crate X |
|---|---|---|
| project graph (records, closures) | `nodes` hold file NAMES and token references; `{input:"nativeSources", projects:[deps]}` per target (`B/🕸️graph/📥️inference/🦀️native-manifests/🟨️.mjs:285-291`, `withNativePreparation`); `nativeSources = production` = `{projectRoot}/**/*` minus tests/fixtures (`nx.json`) | no node changes (R29); no refresh |
| Nx task key (build, check, lint, test) | hash of the content of every file in X's project and of the projects of all transitive path dependencies | every task of every dependent project re-keys; each re-runs `repo ./📜️script.ts <target>` |
| Cargo | `.cargo/config.toml`: `checksum-freshness = true` (source CONTENT, not mtime), `embed-metadata = "DoNotEmbed"`, per-lane target/build dir, `rustc-wrapper = "repo"`; toolchain `nightly-2026-07-20` (installed, `-Z ls` works) | dependency fingerprints change, so Cargo marks EVERY transitive dependent dirty and calls the wrapper once per dependent. Cargo has no early cutoff |
| unit cache (`UC/🔏️key`) | key = toolchain, normalised args, root source sha, extern artifact sha256 (`--extern` file bytes; dylibs by unit identity, `UC/🪪️extern`), env; entry valid only while all recorded dependency files still match | the rmeta of X changes (the crate hash SVH hashes all source), so the key of every direct dependent changes, so its rmeta changes, and so on: the whole cone is compiled |

Why bytes are not the issue: a one-token body edit changes 50 bytes of rmeta (the SVH and the source hash); a line-shifting edit changes 1 328 (spans). A dependent records the SVH of every crate it was compiled against (`-Z ls=root` lists them) and rustc refuses a mismatch (E0460). So "same output" never happens after a source edit, and the existing byte-identical cutoff (`🔁️churn` test) only helps for rebuilds of unchanged sources.

## 2. What rustc gives, verified against the pinned toolchain (`rustc 1.99.0-nightly 9f36de775`)
- No stable interface hash: `-Zhelp` has no SVH or stable-crate-hash option (`-Z ls=` prints the crate hash, the hashes of all upstream crates and item names only).
- The SVH occurs exactly once in the crate's own metadata and exactly once in the metadata of each dependent (all upstream crates, not only direct ones), in no rlib of a dependent (law test `the crate hash listed by the compiler occurs exactly once ...`). Rewriting the 16 bytes in a dependent's rmeta makes rustc accept it against the rebuilt library (micro experiment: output `23` of the new library, linked, section 4).
- Consumers of a library besides its metadata: its object code (instances, symbols, inline and generic MIR, `const fn`, `impl Trait` hidden types, layout). That list is what the masker (section 3.1) refuses to treat as body.

## 4. What was built (9 anchored edits of `UC/📜️script.ts`, 6 new files, schema first)
New member `UC/🔭️interface/` (`🧬️schema/🔣️.json` is the policy, a closed constant; `🟦️.ts` the code, strict-typed clean under `--strict --noUncheckedIndexedAccess --exactOptionalPropertyTypes`).
1. **Masker** (`maskRustSourceV1`): a Rust lexer (nested comments, raw/byte/C strings, chars vs lifetimes, raw identifiers) and an item scanner that replaces the body of a function by `{/*semio:masked*/}` only when it is a plain, non-generic, non-`const`, non-`async`, non-`extern`, non-inline function with allowed attributes only (`doc allow warn deny forbid expect must_use deprecated cfg`), no `where`, no `impl Trait` in the signature, in a module or a non-generic `impl` block (not a trait), and the body declares no item (`impl trait mod struct enum union type static extern macro_rules include async` absent), calls only known expression macros and carries no export attribute. Everything the scanner does not recognise stays in the text, so a misreading keeps bytes and cannot hide them. A file with unbalanced brackets, an unfinished literal, a `type X = impl …` or a feature gate through which a body reaches a signature (list in the policy) voids masking; one `include!` anywhere puts every `.rs` file of the set back to bytes (`interfaceDigestV1`). Other files count by bytes.
2. **Eligibility** (`interfaceEligibilityV1`): library, emits metadata and dep-info only, no `--test`, `opt-level` 0 (an optimised build may inline small functions across crates), unstable flags only from the policy list.
3. **Identity** (producer): after a miss or a hit of an eligible unit the wrapper writes `<rmeta>.semio-iface` (`{sha256, basis, svh, identity}`), `identity = sha256(["iface", portable unit key with the root source replaced by the interface digest of ALL recorded dependency files, real paths, observed env])` (`portableKeyV1` reused, so it is machine independent and recursive through the dependency's own identity). **Dependants** key such an extern by `iface:<identity>` instead of the file bytes, trusted only while the sidecar names the file's current sha256 and only for a metadata-only consumer. The identity is recomputed only when the entry's dependency list changed (`basis`).
4. **Rebase** (`rebaseRestoredUnitV1`): a dependent whose key used an identity publishes `<rmeta>.semio-deps` as one more output of its entry (the crate hash and the hashes of every crate it saw, from `rustc -Z ls=root`, asked once per miss). On every hit the wrapper replaces each recorded hash of a crate found beside it (`lib<id>.rmeta` in the `-L dependency=` and `--extern` directories) by that crate's current hash: each old hash must occur exactly once, all positions are found before any byte is written, the file is replaced by rename and its mtime renewed. Anything unprovable (no sidecar, unknown hash, not exactly once) makes the hit a miss (`incomplete: interface …`), never a wrong hit; a unit that could not publish its table is not published.
5. **Determinism (the 17 crates)**: in the check chain the bytes of a nondeterministic rmeta no longer enter any dependant's key (the key is a function of inputs, like the proc-macro identity of package T); the hash is always read from the actual local artifact, so a hash that differs between machines is absorbed by the rebase. The code chain keeps byte keys, so those crates stay as they are (T's "what remains non-deterministic").
6. **Project-graph deferral** is by construction only a unit-level one today: the graph keeps naming files (content), the wrapper decides at execution.

## 6. Designed, not built
- **Nx level for check-class targets** (the only part of the 3 892 re-keyed tasks that can be cut without the code problem): a node would name `{env:"SEMIO_RUST_INTERFACE_<key>"}` instead of `{input:"nativeSources", projects:[deps]}`; the record (content addressed, like `build-input-closures`) lists the same files as the `production` globs, so the graph level cannot under-key; the VALUE at hash time is `interfaceDigestV1` of those files. Blockers: (1) `readExactSourceFileV1` streams a sha and returns no bytes, so the batch needs a byte-reading call with the same custody; (2) a new digest kind beside `SEMIO_SOURCE_CLOSURE_`/`SEMIO_CARGO_LOCK_` in `📥️inputs/🧮️digest` and in the storage-enforcement capture schema; (3) `withNativePreparation` must know which targets are check-class (declare it on the target); (4) a stamp bump, so one full refresh. It applies to `check` and clippy `lint` targets only, never to `build`/`test`.
- **Crate-granular dependency inputs for build/test** (section 3, verdict 3): sound only with the real compile inputs of each dependency crate (dep-info, or `mod`/`include!`/`#[path]` resolution); mean 1 033 to 420.
- **Code tier**: would need a symbol-closure check on every replay (`llvm-nm -u` of the dependant against the definitions of the rebuilt libraries, the toolchain ships `llvm-tools`), plus a rule for debug-info and panic locations; untested. Not enabled and not in the policy.
