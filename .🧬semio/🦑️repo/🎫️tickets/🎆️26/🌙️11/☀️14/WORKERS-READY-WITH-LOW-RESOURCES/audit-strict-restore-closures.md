# Strict Restore Closure Qualification

A private loopback HTTP test reproduced strict restore sealing a generation whose local closure file was present at the expected path and had the expected size but contained other bytes. The cache returned 404 for the correct digest. Strict restore had treated any size from the closure port as proof of presence and did not read the local file. A separate path downloaded unknown-length closure bodies with `arrayBuffer()` before applying the 16 MiB closure limit.

Strict restore now checks every named local leaf for bounded readable bytes and the exact SHA-256. The workspace port checks the opened file and caps the allocation and read, so the advisory size check cannot permit a larger replacement file. A valid held leaf needs no remote request. Invalid or absent leaves follow the existing custody-controlled closure writer. The repair helper accepts strict verification before and after a put. A corrupt immutable leaf that the legitimate writer rejects remains unavailable. Strict publication leaves the pointer untouched if any required leaf is still unavailable.

Restore fetches unknown-size remote closure leaves in capped streams. The existing 16 MiB policy applies as bytes arrive, and overflow cancels the stream before it accumulates a larger closure body. The growing scratch buffer does not retain a chunk list. Ordinary restoration still uses its existing presence shortcut and reports missing owners for re-derivation. The ordinary restore's remote body reads now also observe the same byte cap while receiving the body.

The neutral fixture covers exact local bytes, equal-size corrupt local bytes, immutable-write refusal, successful verified recovery, a put that returns without installing anything, an incorrect remote digest and an oversized never-ending response. SQLite independently predicts retrieval, write and seal behavior. Web Crypto checks held bytes when a pointer is published. The oversized test observes remote stream cancellation before the caller signal expires.

The original test failed with `restored` where SQLite expected `incomplete`. After the fix, 14 tests and 148 assertions passed across the closure exchange, lost-leaf, bounded restore and closure repair suites. The combined runner used a 30-second per-test allowance after the adjacent bounded restore hit its default timeout during live producer load. No live cache or queue state was changed.
