## 2. Causes found, with evidence
1. Every Nx task hash carries the operating system and architecture. Root cause: a runtime input `process.platform.concat(process.arch)` sits in `sharedGlobals` (`nx.json`, `B/🔣️policy.json` line 92) and is added again to every inferred command target (`B/🕸️graph/📥️inference/🧭️script-inputs/🟨️.mjs:840` and `:295` region, `B/📥️inputs/🟨️.mjs:291,329`, `component-targets/🟨️.mjs`). A TypeScript build, lint or generator therefore had a different key on macOS, Linux and Windows although its output is the same. Measured with real Nx 23.2.0 on two emulated platforms in two checkouts (below): before, the same task ran twice.
2. Cacheability, not keys, limits the volume (not changed, not measured for lack of a graph read): `nxOutputsCacheableV1` (`LIB/🟨️.mjs:90`) makes a target `cache: false` unless every output lies in the rust or products cache partition or is a store receipt; `audit-computed-twice.md` counted 632 targets without a `cache` flag and 657 with `cache: false`. I could not count the effective cache-law states (that needs a graph read). Whoever wants more TypeScript volume shared must declare restorable outputs per target kind; the platform class below makes sure those results are shared once they exist.
3. Tool fetches had no claim: `pinnedFetchV1`, `fleetCargoRegistryAroundV1` and the uv seed port (`fleetUvPortV1`) looked up the fleet, and on a miss every machine downloaded. Measured before: nine simultaneous `pinnedFetchV1` calls on one pinned artifact hit the upstream 9 times (shared group store) and 9 times (cache server only).
4. The mirror (`B/🌐️remote-cache/🪞️mirror`) already coalesces concurrent requests per path in the one mirror server (`flights` map), which is one flight for the whole fleet because every machine goes through that server. No change needed. `📦️install` already had claims.
5. Wasm: the `wasm` target (browser wasm package) is deliberately guarded (hostname in its hash, upload dropped: `🧮️task-model/🛡️remote-guard`), the plugin `component` target is keyed by `nativeSources`, the toolchain commands and the explicit platform runtime (`component-targets/🟨️.mjs:93`), and the wasm32 rustc units are host independent in the Rust unit cache (R55's area). So the plugin component payload is shared between machines of one platform only. See "Unverified".
6. Provenance: the server counted only action-result reads (R55's `consume` in the `ac` branch); Nx task results and install states were not counted.

## 3. Fixes
- Platform class (`B/🧮️task-model/🧭️platform-class/`, schema-first: `🧬️schema/🔣️.json`). `splitNxPlatformInputsV1` is called in `projectBuildGraphForNxV1` (`LIB/🟨️.mjs`, one anchored edit plus import) after the named-input lift and before the sharing step. It removes the platform row from every named input group and target, and puts one canonical platform row back on every target that had reached it and is not independent. A target is independent only if: not native (`nativeOwnerCommand`), no `metadata.semio` of `rustBuildIntent`, `rustUnitAggregate`, `hostPlatformOutputsV1` or `componentStoreV1`, its resolved inputs (nested groups, `^` references, cross-project `{input,projects}` rows) reach no `nativeSources`, `nativeTestSources`, `cargoToolchain`, `go`, `uv`, `dotnet`, no runtime other than node/bun versions and the engine digest, no CARGO/RUST/CC/GO/DOTNET/UV/PYTHON/CMAKE environment input, its command names no cargo/rustc/go/dotnet/uv/python/cmake/wasm tool, it is not declared `metadata.semio.platform = "bound"`, and its kind is listed (`build, check, typecheck, lint, generate, generator, generator-manifests, graph-generate, graph-wire-check, check-generated, canonical-architecture`) or it declares `metadata.semio.platform = "independent"`. Everything else, including every `test`, keeps the platform exactly as before. Decision for the owner: the task listed "pure-JS tests"; I left `test` platform-keyed because a pass on macOS does not prove a pass on Windows (a wrong hit is worse than a miss). A TypeScript-only project can opt in per target with the metadata declaration, or the name can be added to `independentTargets`.
- Work claim (`FF/🎟️work-claim/`, schema-first): `claimFleetWorkV1` = claim, heartbeat (20 s, 60 s lease, at most 90 beats), ready check, long-poll await, release; outcomes `ready` (fetch it), `granted` (do it, then release), `alone` (claims unreachable, refused, full, no credential, wait exceeded 15 min: do it locally, as before). A holder that finishes without publishing wakes the waiters; after two such wakes the rest work in parallel instead of serialising. Wired into `pinnedFetchV1` (kind `blob`, identity the sha256 pin, so a tool is fetched once and the others are served from the group store or the cache's content store), `fleetCargoRegistryAroundV1` (kind `crates`, identity the sorted crate checksums) and the uv port (`fleetUvClaimV1`, kind `uv`, identity lock digest plus host class, so a Linux seed is never waited for by macOS). Platform match comes from the pin (different URL and sha per platform) and the host class.
- Provenance: `GET` of an `nx` entry (task result or install state) calls `provenance.consume(…)` in `B/🌐️remote-cache/🖥️server/🟦️.ts`, the same method, file (`fleet/consumption.json`) and shape (`producer>consumer` → `{hits,units}`, bounded to 1024 pairs) as R55's; no second schema. Not counted: blobs of the content store (they follow every action-result read and would double the numbers), tool blobs, crate files and uv seeds (no per-pair record; the claim `ready` outcome is counted nowhere yet).

## 5. Unverified, and what the others must know
- Linux and Windows cannot be run from here. Cross-platform key equality is proven only with an emulated platform command; real Linux and Windows hashes of a TypeScript task (shell, line endings of inputs, path separators in `runtime` outputs) are not shown. Windows is excluded from the e2e (`skipIf win32`).
- The effect on real fleet volume is not measured: no graph read was allowed, so the number of targets that are independent AND cacheable is unknown, and the cause 2 above (non-restorable outputs, `cache: false`) probably dominates. The next measurement is `cacheLawCountsV1` over the real graph plus the count of independent targets from `platformClassV1`.
- Wasm plugin `component` builds are still platform keyed on purpose. Sharing them needs a byte-identity proof of the component payload across host platforms (macOS vs Linux vs Windows) and removing host-specific toolchain commands (`rustc -vV` carries the host triple) from its inputs; set `metadata.semio.platform = "independent"` only after that proof, and the classifier will still refuse it while `nativeSources` or `componentStoreV1` are present, so the inference must change first. The browser `wasm` target stays guarded.
- The plugin edit changes the Nx plugin implementation identity: a running `nx` that started before the landing fails `createDependencies` with "Original private Nx dependency implementation differs" and must be restarted; every machine rebuilds its Nx project graph once after the replica delivers the edit (R53 area).
- Install states are still per host class and per runtime (by design); the claim of `📦️install` is unchanged. Tool blobs, crates and uv seeds have no per-pair consumption record.
- R55 files existed when I got to provenance (`consume`, `consumption.json`); I only added the `nx` call site.
