## 1. What `affected` does today (read from the code)
`selectBuildTasksV1` (`🧭️selection`) takes changed files from git, then `affectedBuildProjectsV1(graph,files)`: `affectedTouchesV1` = deepest owning root per file (root `.` owns the rest), plus every project whose target inputs (named inputs expanded, project ones over the declared ones, `{workspaceRoot}/...` strings and `fileset`, extended globs match everything, `nx.json` touches all) match a file; then a fixpoint over ALL edges (quadratic). It needs the whole graph: selection `all`, whole read, no generation = hours (R210). The source closure inputs of a project are a private token `{env:SEMIO_SOURCE_CLOSURE_<digest>}` in the stored node that `portableInputs` expands from a closure leaf (cross-language inputs live there).

## 2. Built
- Schema first: `🎯️affected-index/🧬️schema/🔣️.json` (policy, closed `Index`/`Owner` format, EN/DE texts).
- `🟨️.mjs` (+`.d.mts`): `affectedInputsOfNodeV1` (same rule as `affectedTouchesV1`, reads leaf tokens), `deriveAffectedIndexV1` (manifest + fragments of owners whose fragment digest changed + unknown leaves + global edges; nothing else), `openAffectedIndexV1` (file to owner by one walk up the path, literal patterns by hash, globs compiled on first use, dependents as adjacency lists, BFS), `ensureAffectedIndexV1` (stored beside the generation as `<generation root>/a/<manifest digest>.json.br`; derived from the newest older index; prune after grace), typed refusals `AFFECTED_TOO_LARGE`, `AFFECTED_LEAF_MISSING`.
- `🟦️.ts`: leaf port (same reading as `portableInputs`), seal hook, `affectedFastPlanV1`, `answerAffectedV1`: eligible = no `--all`/`--exclude`/`--projects`, literal bounded targets; git files or `--files`; index; zero projects prints `[semio] no affected tasks`; otherwise the args become a literal `run-many --projects=<list>` whose selected read loads only those owners. Anything else (no generation, changed manifest of an unknown project, bound, fault) says why (EN/DE) and falls to the old whole-graph path: never fails.
- Edits (anchored, applied by the script under the lock): engine option `afterSeal` called after a final publish (fault-isolated), host `storeOptions` supplies it, runtime hook before `runTaskGraphV1`.
- Fetched fleet generation: the index is not carried in the head (that would touch R219's `remote-exchange` file and the manifest); it is cheaply derived once from the fetched fragments and leaves (R219 restore fetches the leaves), incrementally afterwards.
