# Readiness Reuse Audit

The readiness supervisor hashes each stage independently from its name, platform and declared input hashes. The workspace and repo-mcp stages declare no inputs. Tools declares only the tool-setup catalog and package.json. Changes to other Nx bootstrap implementation or patch files therefore do not themselves invalidate workspace or tools readiness. A changed earlier stage does not invalidate a later stage: the decision selects the first mismatching digest and subsequently reuses independently matching stages.

With matching stored stages, marker and repo binary, the supervisor reports ready and remains idle. With an empty stage state but existing marker and binary it adopts all current stage digests without running them. These are explicit current semantics, not evidence that a worker executed a new physical fix. The existing readyMs is written on workspace completion or adoption; a fresh ready.json heartbeat does not itself imply fresh workspace execution. A physical verification needs current code identity plus successful workspace completion evidence on each target machine.
