# Bounded Graph Generation Restore

The original restore downloaded every neutral document before writing any expanded document. In the private 18-owner fixture, all 22 payload requests arrived before the first stage write. It then retained the neutral documents and the expanded output set together through closure qualification.

Restore now verifies the selected neutral manifest first and requires its typed referenced paths. Strict restore compares the addressed head with manifest generation, identity, implementation digest and owner count before staging. The HTTP content stream checks exact declared size and SHA-256 for each addressed document. A group holds up to eight compressed documents and 16 MiB of declared bytes. A document larger than 16 MiB runs alone under the existing 512 MiB exchange document limit. No aggregate graph byte cap was introduced.

The restore expands and stages one document at a time through the existing content-addressed file port. It retains source-to-destination digest metadata for canonical manifest rewriting. The closure scan rereads staged fragments one at a time. Strict closure failure and cancellation leave the pointer untouched. The existing graph claim fences pointer publication. Verified, immutable blobs from an interrupted restore may remain in the normal graph CAS for reuse or retirement. They are never deleted during the failed restore, because a concurrent publisher could have referenced one of them.

The regression fixture uses a language-neutral case table, Ajv validation, an independent SQLite outcome query, Web Crypto digest checks and a private loopback HTTP endpoint. It covers interleaved staging, a response larger than its declared size, a manifest whose owner count differs from its head, cancellation after a staged write and a same-endpoint retry after each refusal. The initial test failed at payload index 21 versus first stage index 22. After the change, 25 tests and 431 assertions passed across the fixture and the existing exchange, closures, cancellation, lost-leaf, slice, and authenticated head-evidence suites.

The bound concerns the active generation document set. A single decompression and transcode, manifest metadata, closure references and optional snapshot can still contribute to peak memory. This test does not measure a physical whole-generation restore or establish a 16 GiB machine fit.
