# Exact whole-head consumer wakeup audit

Read-only source review; no peer command, runtime intervention or heavyweight probe was performed. There is no existing authenticated, targeted instruction or automatic head-only wakeup established for the 16 GiB peer. The exchange offers an authenticated, bounded pull-side candidate lookup, not an instruction to run it. `look` reports completeness, ahead, owner count and origin, but not the complete head evidence tuple; `ahead` returns a boolean. Both call the signed remote-cache fetch with probe bounds and derive per-origin keys locally. Publication uploads leaves and documents before writing the origin-owned head; it does not address or wake a consumer. The narrow existing evidence route requires a command already running locally on the physically identified peer: `repo graph --graph-policy=current`, with the normal local capacity and builder custody and the peer matching platform, registry and generation implementation. Capture the producer publication and the peer restore lines: both carry `origin`, `producerGeneration`, `scope` and `manifest`; the wave-delta test explicitly compares the tuples. A successful command alone does not prove this specific restore: the loader may serve an existing matching local seal, and an absent, incompatible, incomplete or unavailable head can prevent restoration. A restore line must match the produced whole `scope=all` tuple and be associated with the independently identified physical peer; neither readiness nor host similarity suffices. No current interface forces that exact selected head over another better-ranked candidate.
