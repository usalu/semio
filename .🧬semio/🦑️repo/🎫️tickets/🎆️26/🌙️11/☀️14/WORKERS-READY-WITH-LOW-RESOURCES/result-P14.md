## Design (decision 7, honest platform limits)

- **(a) Platform independent records are shared.** Platforms form classes (`🌍️platform-class`, schema first): `posix-shared` = darwin-arm64, darwin-x64, linux-x64, linux-arm64; every other platform is its own class. The record state is keyed by the class, so the Linux worker finds what the Macs published. Records are published without the facts that name the producer's machine (`🧳️portable`): the `lstat` of directories above the checkout is dropped (it holds on every machine whose checkout exists), the one dependency generation id becomes a token, and the taker puts its own generation in (the real path of its `node_modules`); the compiler's package identity digest (`field` row) still decides that the tooling is the same. A record with several generations or a taker without one keeps rows that cannot hold: the project is inferred locally, never taken wrongly (the taker replays every row against its own tree as before).
- **(b) Platform dependent records are not shared.** A key text that names `hostPlatformOutputsV1` is keyed by the exact platform; the Linux worker infers that project itself (one light cargo owner). Inference is a pure function of files plus `process.platform` for that one declaration plus the host's path spelling on Windows; serving "for the requested platform" was therefore not built: for POSIX it is not needed, for Windows it would need the path and command rendering parameterised and is a larger change than the one declared target. **Windows is not served by any macOS or Linux machine**: its requests are counted in the heartbeat (`N of other platform classes left to others`) and said once per request, nothing is claimed. A Windows worker needs a serving Windows machine or its own inference within its grant.
- **Request and answer slots are per requester**, the cost table of the server is one slot for every platform (a cost is a property of the project).
- **Heavy is a measured property of named owners.** A project is refused only when its own recorded samples or a declared seed (the six measured owners, now including `workspace` 3 100 MB) exceed the grant. The cost of a kind and the unknown cost only order the serving machine's work. A light owner that outgrows the grant is stopped by the memory governor (P8/P12), recorded under its name and heavy from then on; the number of such names is bounded by the table (14 projects above the 16 GB grant today).
- **The admitted memory of the fleet decision is what the machine can give**: `min(half of the host memory, available now − 2 048 MB)`, never the small early booking of the asking slice (`fleetAdmittedMegabytesV1`; swap neither counted nor subtracted). On the Deck: 7 924 MB → grant 3 298 MB physical (1 649 managed) → 4 waves of 48 = 192 local, the rest from the fleet.
- **The refusal says which projects and why**: the heavy names with their cost (as before) and a new line before the refusal text, `graph: this machine is linux-x64 (class posix-shared); only machines of that class serve its request, and their graph server logs 'serving' for it` (EN and DE).
