There were zero queued or executing actions in that observation. It demonstrates that compiler discovery can admit the worker, with no physical Windows action result.
- The action producer writes the same exact `/bin/sh -c` command for Windows and POSIX. Worker validation requires that fixed command and its script. The worker resolves the executable before the sandbox or compiler gets a chance to run. The private wire fixture builds and decodes the real action, verifies the closed validator rejects substituting the worker's `rustc.exe` directly, and checks independently with Python's Windows path rules that the command resolves to a missing drive-root shell even with the compiler installed. Sidecar readiness reports the same cause, and the CLI displays it and continues load reporting without starting a worker. The visible report leaves headroom false and does not send worker registration. Local Ready and compiler discovery have independent lifecycles.
- All 11 tests in the worker reason suite and the private action-wire probe passed. The test scheduler received an absent, zero-headroom load report with the closed reason and no worker registration request.

## Native launch requirements

The fixed shell does more than locate the compiler. It writes the declared root marker, creates the private output and temporary directories, derives absolute Cargo variables and path remaps inside the detached input tree, appends an absolute source where needed, and preserves the Darwin linker behavior. Replacing its executable without performing that work would invalidate outputs and path-independence checks.

A scoped native implementation needs a versioned Windows action command alongside the existing POSIX command, a worker-owned Rust invocation plan produced only from the respective closed command, and the existing absolute compiler plus a worker-owned MSVC tool and SDK environment. The CMake compiler activation procedure currently depends on an issued build phase and CMake's retained inputs. The remote worker has no corresponding lease-backed MSVC tool environment. Long native requests need an owned Rust response file in the private scratch directory. Inbound response files remain refused.

Native materialization and release of results must enforce Windows path identity for the private tree and exact declared outputs. The current generic materializer compares directory names case-sensitively and admits symlinks without a Windows target proof, while the current admission checks environment names case-sensitively. Native worker preamble writes and environment reconstruction require those Windows contracts before launch. Preserve the exact declared marker and outputs and verify bytes, diagnostic path translation and local fallback with a real MSVC child. This task records the unsupported platform through normal admission. It leaves the POSIX command, wire digest and output validation unchanged.

At 15:35 UTC the live scheduler reported g1-m05 as `absent` with reason `action-unsupported` and false offload headroom. Its own replica attestation and workspace Ready receipt were two and five seconds old respectively in the independent sample. Native Rust offload on Windows remains unimplemented.
