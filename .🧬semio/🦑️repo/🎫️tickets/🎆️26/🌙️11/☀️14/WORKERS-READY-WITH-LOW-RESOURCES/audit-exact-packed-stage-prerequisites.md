# Exact Packed Stage Prerequisites

The helper accepts the exact changed blob IDs supplied by the author stage. It returns each distinct ID in its original order, grouped by whether a current fleet pack covers it, a verified local loose file was written, or preparation remains pending. The caller retains journal eligibility and stage authority.

The SHA-1 coverage fast path requires both current live fleet pack and index proofs from the caller and a complete regular local pair. It matches the pack header, stem, trailer and object count to the index. The index checksum and same opened-file identity are checked before membership can qualify. The helper rechecks both live file predicates after reading the index. It reads only eligible SHA-1 index files and holds one table at a time. The 64 MiB index cap is enforced after opening the file. Larger indexes, invalid pairs and SHA-256 packs use the exact object fallback.

The fallback shares the local Git batch and loose-object writer with pack rescue. It requests at most 5,000 explicit IDs per process, bounds the frame header to 128 bytes and streams each declared byte extent through canonical Git object hashing and compression. A single object's data can exceed memory without needing a whole-object buffer in the replica. The staged path verifies blob type, exact canonical SHA-1 or SHA-256 ID, and output delimiter before atomically publishing the loose file. Missing and malformed requests remain pending. A cancellation rejects with the caller's reason and cleans unplaced temporary output. Local Git remote access is disabled in this route. Reading a live pack's index does not rehash its entire pack body, which already has the caller's exact live file proof. The helper grants no authority to copy or retire a whole pack.

The native private fixture uses Git, Node's crypto and zlib, and an independent SQLite projection to verify exact coverage and loose-file bytes. It includes a mismatched index, pack-only standing, a multi-megabyte streamed object, cancellation, and a missing object. A separate SHA-256 fixture checks packed fallback, an invalid request, and a packed non-blob. Existing pack rescue, repack, garbage collection and consolidation fixtures run adjacent to the new cases. No live Git operations were issued.
