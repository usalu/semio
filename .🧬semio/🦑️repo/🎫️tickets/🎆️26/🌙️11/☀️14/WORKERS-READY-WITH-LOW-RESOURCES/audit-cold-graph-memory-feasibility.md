# Cold Graph Memory Feasibility

The current coordinator reader reached an exact fair upgrade from 4,096 MiB to 14,336 MiB after generation 260 was invalidated with reason `closure-missing`. The retained parent of that pointer has never been requalified as a current graph. Invalidation clears the current manifest and preserves only its parent digest. The normal complete-peer restore remains available if an authenticated compatible head appears during the wait.

The native generation engine chooses no explicit dirty owner array for a cold build. In `generations/🟨️.mjs`, `buildOnce` sets `ordered` to an empty array for every cold plan. The warm wave split and its journal therefore do not apply. The production host then invokes `discoverBuildGraphPartV1` with `cold:true`. That function omits `ownerRoots`, builds full primary, test and policy contributions, derives a common environment, and uses the complete project/file context for edges and metadata. Project-farm lanes govern concurrent child work and observation rows can spill to a log. Those controls leave the full result, global context and final fact-index format resident at different points. The lean `show projects` response occurs after generation refresh and does not skip cold discovery or sealing.

An isolated run used the real generation engine and the repository's synthetic ring of 103 owners with its independent Python oracle. After building the baseline, it invalidated only the private pointer with reason `closure-missing`. The replacement called compute once with `cold:true`, zero explicit owners and `more:false`; it inferred 103 owners and published once. The output matched the Python graph. The configured warm batch size was 48. This verifies control flow and semantic test baseline. It supplies no evidence of a smaller native memory peak.

## Testable implementation seam

The candidate starts at `discoverBuildGraphPartV1` and the project inference dispatcher. Split complete, authoritative roster discovery from owner materialization. A staged read must derive the same live primary names, roots, configurations, native roots, withheld owners and collision decisions. It must preserve the global projections required for dependency resolution, catalog providers, tests, and policy targets such as lint. A frozen file inventory supplies names of files only. It cannot replace those inferred authority and environment facts. Keep cold farm engagement and cancellation semantics while admitting only the owners of the chosen batch to materialization.

The caller seam is `generations/🟨️.mjs::buildOnce` and the build journal. A cold wave needs a distinct continuation that stays bound to the same invalidated pointer, identity, implementation and live membership throughout staging. Today the next-wave hint requires a usable manifest and cold initialization discards carried owners. The current journal's row encoder also expands a wave before encoding, so an owner-count limit alone does not bound that memory. Preserve exact observations, stream them under a proven byte bound, and run common-environment, tagged-owner and external-edge work with the complete projection. Recheck the input authority and graph closure inventory before the existing single fenced publication. Readers must never see an intermediate cold graph.

Qualify the candidate first with a frozen private real-inference fixture crossing multiple batches. Compare source and target owner rosters, fragment digests, global and frontier digests, fact-index rows and complete closure inventory against the ordinary cold output. Include an owner with generated native targets, a cross-wave dependency, a policy or test owner, and a withheld owner. Mutation, handover and deadline fixtures must refuse publication and release the original custody correctly. A separate native run should measure the complete parent and farm process-tree footprint across discovery, waves, journal, packing and sealing under the original capacity observer, including the largest per-owner input. A smaller reservation requires a validated lower peak and enforcement of the corresponding upper bound. There is no existing equivalent bounded mode for the queued reader. No live source, process, pointer or capacity state was changed during this audit.
