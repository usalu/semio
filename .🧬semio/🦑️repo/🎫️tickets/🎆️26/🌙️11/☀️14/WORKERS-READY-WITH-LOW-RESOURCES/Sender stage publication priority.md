# Sender stage publication priority

On POSIX, `publishOnceV1` currently reaches `publishStage` after the worktree walk, preparation and file journal writes. Modeless replicas also run it before files because `prepare` obtains the executable bit of a new path from its stage register. In the Git module, `publishIndexV1` already reads the index signature and short-circuits unchanged signatures before reading the semantic tree. Ordinary batches describe exact additions, updates and deletions. Base events describe a whole tree.

## Proposed change

- After `refreshIgnore` and `stateReady`, attempt an incremental-only stage publish for the POSIX archivist at the beginning of a full or index-hinted publication. Leave base cases and unready dependencies for the existing tail call, which also catches an index change during file publication. Keep the existing early behavior for modeless replicas. Boot state reconstruction must happen before the new priority writer so its first records do not obscure missing state.
- In `publishIndexV1`, let early publication defer genesis, forced rebase and unrepresentable paths before emitting a base. A root tree alone does not make its descendants available on the receiver. The ordinary branch can therefore prioritize its exact objects without a full object scan. An optional callback scoped to the early ordinary batch runs before `host.emit` and before recording its successful Git signature. The regular caller and receiver remain unchanged.
- Derive loose object paths from the validated OIDs of link entries with non-gitlink modes, and deduplicate within the batch. Ignore deletion events and gitlinks. Existing durable manifest puts already name their blobs in the store. For remaining regular loose objects, reuse the ordinary exact-path publication and its existing validation, cancellation, store and journal checks. The nested path set contains only full loose-object file names, so it cannot reenter stage publication. Recheck the requisite puts in the manifest before appending dependent register events. Leave absent loose files and failed exact publication to the tail path, where existing packed-object ordering and receiver missing-object handling remain available. No pack or other loose object discovery is needed.
- Retain the signature captured with the initial locally written tree. A subsequent index change during object storage is noticed by the tail call or following publish round. If any early batch has already emitted and a later one defers, discard the memoized known tree just as the existing partial emit failure path does. The tail can rebuild its known tree from durable prior writes and avoid attributing the initial delta twice.

## Verification

- Create two seeded private replicas with the same base. Stage content on the archivist, modify the worktree file again, and include a separate unstaged file in the exact publish call. Pass only the index hint and the unrelated worktree path as inputs. In the origin journal, assert the exact staged loose-object put precedes the entry register, the entry precedes the unrelated put, and an unrelated loose object is absent. The receiver's staged OID and worktree bytes should match the independently queried native Git state.
- Cover a delete, a mode-only change with a known object, an already-published object and a gitlink. Verify orders and no redundant object entries. In a failure path, retry across blocked object or journal publication without prematurely memoizing a signature or losing completed batches.
- Keep existing whole-base, unresolved conflicts and modeless executable tests. Add an explicit no-index-change case to ensure hint checks do not run expensive Git commands or write duplicate registers.
