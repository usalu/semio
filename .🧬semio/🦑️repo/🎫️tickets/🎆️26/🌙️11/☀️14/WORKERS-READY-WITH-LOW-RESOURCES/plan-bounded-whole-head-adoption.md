# Bounded Whole-Head Adoption on Ready 16 GiB Peers

Feasible through the existing supervised local graph sidecar, signed cache exchange and generation host. This requires a local restore-only path and resource policy. It does not require a service, remote dispatch, new fleet role or generation wire format. The stock restore's retained input and transformed output arrays have no sufficiently low aggregate ceiling. Keep the new path disabled on the physical peers until the bounded path has passed a measured 16 GiB acceptance run.

Paths below are relative to `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library`.

1. **Local admission.** In `🏗️build/🌐️remote-execution/🛰️sidecar/🕸️graph/🟦️.ts` add a dedicated timer for the adoption lane, separate from Wanted inference, refresh and uploader. Keep the 24,000 MiB serving threshold and its existing callbacks. On each bounded tick require the local origin's schema-valid, fresh `ready:true` receipt, no readiness foreground work or competing graph read, normal pressure, free disk, and bounded available host capacity with no foreground queue. The existing `🚦️ready/🟦️.ts` helper treats a missing status as idle, so it cannot by itself establish readiness. Use the existing sanitized fleet settings and signed cache fetch on the published authenticated transport. Cap metadata probe time, bytes, known-origin fan-out and retry. If the graph host cannot provide a current identity and loaded implementation cheaply, skip until a valid local memo exists. Do not replace the loaded digest with the checkout or replica-attestation digest.
2. **No process for a local seal.** Under a short shared local store read, validate the whole sealed pointer and its registry and implementation before even probing fleet heads. A matching local seal ends the tick without spawning a working CLI. Otherwise extend the metadata-only `look` in `🏗️build/🕸️graph/🕰️generations/🌐️remote-exchange/🟦️.ts` to yield the exact selected origin-owned ActionResult key and complete head evidence, plus registry, implementation, platform, scope and a bounded size verdict. Require `stale=0`, whole scope and ahead via the existing precedence rule. This phase performs no CAS blob reads. Release shared storage custody before waiting on capacity.
3. **One bounded local attempt.** Serialize by local origin and workspace using the existing local lease facility, with one supervised process at most, PID and start-time recovery, and a bounded attempt cooldown keyed by remote tuple and observed local pointer. Check readiness and blockers again before starting. The fixed local worker uses the ordinary issued invocation and host capacity gate, then obtains original generation writer custody through `🏗️build/🕸️graph/🕰️host/🟦️.ts`. Capacity must precede writer custody. Under custody reread the sealed pointer and refuse on a new matching seal, local builder conflict or candidate drift. Re-read exactly the elected origin's advertised head and compare it to the expected tuple. Keep the existing exact fence at pointer write. Use one deadline and abort signal through slot, downloads, validation and writes, and cancel on foreground demand, pressure or sidecar restart. Do not relaunch on the same stable rejection until the cooldown or relevant input changes.
4. **Strict restore only.** Extract an internal owned entry from `🏗️build/🕸️graph/🕰️generations/🔌️load/🟨️.mjs` `restoreRemoteGenerationV1` and `withBuilder` rather than running `loadGenerationGraphV1` through a public graph command. Use `requireComplete` under the normal generation file port. Do not enter inference, fleet Wants, graph/catalog rendering or publish a generation. Pin the exact elected ActionResult and disable cursor-distance downloads and optional cursor installation for this lane. Assert authenticated document lengths and digests, enforce cumulative wire, expanded and disk byte limits and bounded download/transform concurrency, and refuse before pointer publication if over-bound or any dependency closure is missing. The current policy bounds one document at 512 MiB and count at 32,768, and restore keeps neutral and expanded bytes concurrently. Either prove a conservative hard aggregate and expansion bound fits the existing capacity grant or stream/stage verified documents through existing owned storage before enabling this path. Use foreground-safe grants and unchanged rebuild minima.
5. **Exact evidence.** Re-read and verify the authoritative local pointer under its original fence. Bind the producer origin, producer generation, whole scope and neutral manifest SHA-256 to the destination origin, local generation and local manifest, registry, implementation, platform and completed time. Use existing `signFleetDocumentV1` and `verifyFleetDocumentV1` in `🏗️build/🌐️remote-cache/🛰️fleet/🪪️identity/🟦️.ts` with a dedicated receipt document label and the existing cache-read role. Persist under the destination's existing origin-owned store, with atomic replacement and durable local intent staged before pointer publication. Recover an interrupted attempt only when the exact committed local pointer still matches the intent. A no-op, partial restore, head replacement, interrupted pre-commit attempt or unsigned result yields no success receipt. A generation restore log or exit code alone proves neither destination nor exact adoption.

**Existing command behavior.** `🏗️build/⌨️command/⚙️runtime/🟦️.ts` lines 84–103 always serialize `repo graph --graph-policy=current`; `--file` streams the whole serialized graph to an owned report instead of stdout. `repo show projects --graph-policy=current` selects the existing lean catalog and prints project names. The whole-current path itself cannot underpin this observer because it checks local registry identity without requiring the same implementation, performs catalog/graph construction, can publish on a matching local read, and reselects the remote candidate under custody. Today the lean API is useful as a diagnostic and its existing restore line carries the verified producer tuple. A typed restore-only result before catalog assembly is the proposed internal seam.
