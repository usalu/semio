# Git Stage Intake and Attestation

A native polling worker processed Git health and recovery before following its incoming journal. A blocked or slow health probe could therefore hold a fully published stage. The regression publishes a new author stage and holds the worker's health probe before it returns. Before the change native Git read the old worker tree `624d5b1e7473240aa6f1c715c3750800262b0c8f` while the author tree was `8e5814fe4b4bcd417e28a13313663df8e4ca3431`. After the change the worker proves the same author tree and emits its apply event while the selected probe is still held. Real Git reads both private indexes and an independent SQLite query checks the expected tree and that it differs from the baseline. Worker turns receive before maintenance and do one ordinary receive per turn. Author priority remains outbound first during steady state. The 77-test Git, heal and race run passed 801 assertions.

Independently, the attester waited for the first full working-tree view before publishing the already certified Git state. A controlled held view reproduced an idle attestation and no receipt. The first receipt now contains the certified index tree immediately, with a null view while measurement is pending. The worktree view file and digest arrive through the existing attestation path once measured. The neutral fixture and SQLite model check both observations. Existing cadence checks were updated for the earlier first receipt. The whole attestation suite passed 144 tests and 2,287 assertions.

These tests establish two local blockers that could delay adoption and its proof. All nine active workers were still in the workspace readiness phase. The fixture did not determine the cause of the three physical receipt gaps or certify a current Ready result.
