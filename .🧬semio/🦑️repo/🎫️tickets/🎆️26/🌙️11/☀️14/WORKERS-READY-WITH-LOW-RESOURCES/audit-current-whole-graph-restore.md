# Whole graph current restore and lean workers

The graph sidecar uses a 24,000 MiB physical memory gate for background inference and fleet serving. The installed `repo show projects --graph-policy=current` can fetch a whole generation for an enrolled compatible worker when its local store lacks a sealed generation of the registry identity. It uses the lean catalog path and normal invocation. A matching local sealed generation answers immediately under `current`, including when the remote cache may hold a newer state.

The existing exchange probes ActionResult metadata with a five-second request timeout and one retry per known origin. The normal fleet transport signs the enrolled cache request and can seal it against the fleet server. The note's `signature` field is a portable state digest. Head comparison uses the generation format and catalog providers, platform, whole or selected scope, code implementation, declared stale owners and state age. The metadata result exposes completeness and ahead as a verdict. Its restore rereads and ranks the heads again, optionally using snapshot distance. The metadata verdict does not pin a particular head. Also, implementation calculation at the normal command entry loads the inferrer bootstrap, and current fetch uses the structural generation builder's grant upgrade, custody, and store maintenance. Those costs and resource ownership make this unsuitable as a periodic worker poll.

A lean automatic warm-up would require a bounded sidecar probe of the current loaded implementation and an exact local-head comparison, then a conditional restore tied to the selected remote head and current local pointer under existing custody. It would also require independent physical memory and storage admission based on measured restore cost and readiness-aware background cancellation. The stock exchange retains downloaded and expanded documents before publishing, so its per-document limits do not imply a low total memory requirement. The sidecar continues to use its existing refresh and serving policy.

## Whole current closure regression and repair

The shared graph assembly previously entered builder custody four times after a missing leaf before reporting `closure-missing`. A second regression kept a complete head readable from a private real HTTP cache while returning 404 from only its closure endpoint. Restore wrote the generation pointer and the ordinary repair path consumed the missing-leaf report. The attempt eventually returned `GENERATION_NONE_SEALED` after running repair.

A whole unpinned `current` read now reports a typed missing closure at assembly before any repair or inference path. Its existing empty-store fetch asks the exchange for a complete result, checking the actually selected head's implementation and zero stale owners, and matching its single downloaded manifest to the head's registry identity, implementation and owner count. Closure acquisition completes before generation files and the fenced pointer are written. The standard bounds apply to the entire absent set. An over-bound set or unavailable qualification returns the existing incomplete result, and a reported missing leaf returns the existing typed closure error. The graph read uses the established authority for already held local leaves, where the closure port checks presence and immutable store custody. Fetched leaf bytes are checked against their names. Fresh and selected policy paths retain the original repair behavior.

The schema-validated neutral current-fetch corpus compares the actual loader and cache against an independent SQLite decision. It covers a missing leaf, an unavailable closure store, cancellation during the leaf request, selection changing after look to partial or different code, a manifest count mismatch, and a normal complete fetch. The shared-path fixture verifies the original pointer bytes and tracks every custody, inference and settlement call. Existing fresh repair fixtures cover re-fetch, re-derivation and terminal refusal. The work used only private test fixtures.

The normal repository test entry ran the two loader suites and both exchange suites. All 125 tests passed with 574 assertions.

## Cross-host generation evidence

Successful publishes and restores emit a bilingual receipt that carries the origin, producer generation, scope, and full SHA-256 of the immutable neutral manifest. The normal publisher and sidecar wave uploader print the same publication receipt. A whole generation uses `scope=all`. A selected generation carries the digest of its exact scope. The existing restore summary still prints the receiver's local generation number.

The exchange takes the producer identifier from the schema-validated note and checks it against the addressed action key. The restore receipt requires a unique downloaded neutral manifest whose verified content hash and original generation agree with the note. The manifest transformation reuses its existing parse to expose that original number. The receipt adds no network request or persistent file and preserves the existing restore decision. An authenticated record with inconsistent receipt metadata can follow the original restore behavior without producing matching evidence.

The test runs two private enrolled origins against a sealed HTTP cache. It checks the actual published note, computes the manifest SHA-256 independently with WebCrypto, and reads the original producer generation from the manifest bytes. The reader restores into a distinct root and uses a different local generation number. Whole and scoped receipts match the independent evidence in English and German. The fixture also checks that authoring a mismatched origin or producer generation suppresses the receipt. No live host ran a restore as part of verification.

The normal repository test entry passed all 150 loader, cache exchange and wave uploader tests in the receipt test set with 1,382 assertions. Each of four published wave receipts matched its own restore receipt.
