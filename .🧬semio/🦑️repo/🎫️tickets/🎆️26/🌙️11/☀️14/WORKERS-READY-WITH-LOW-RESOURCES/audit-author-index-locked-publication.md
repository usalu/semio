# Author Index Publication During Writer Contention

On November 21 at 09:08:47 UTC, the author recorded `write-tree-failed` while its attestation subsequently reported current stage tree `41cfdebf5190cfa4c28e0b38b0294119d053503f`. Read-only checks found an 82,073,683-byte live index, a fresh zero-byte index lock at 09:09:37, no unmerged entries and the exact observed tree available as a Git tree object. A separate private copy of a stable author index produced that same tree in 0.896 seconds with its own write destination and the original object store as a read alternate. The original index signature was unchanged. The evidence does not identify the process that caused every failed real Git call.

At 09:14:04, author health was shared and its cursor was 176:51749. The author and two fresh workers were at that journal cursor, but the workers still reported the prior index tree. A read-only comparison with that tree found 1,947 changed staging entries and 1,932 distinct non-delete, non-gitlink object IDs. The journal window from 175:627483 through 176:51749 contained 1,875 events, including 1,833 distinct loose-object puts and zero stage registers. Of those loose object IDs, 905 were exact changed-stage prerequisites. The window does not account for earlier loose objects or eligible retained packs.

The author previously required `git write-tree` against the live index before it could prepare the objects for a changed stage. Its observer already knew how to obtain the exact tree from a signature-bound private copy under a writer lock. Native fixture Git reproduced the resulting author stall with a complete, stable index and a held lock. Neither the required object event nor its stage register reached the journal. A separate native fixture moved only the live index modification stamp during object preparation and reproduced the same publication outcome even though the independently calculated Git tree had stayed equal.

For a normal incremental author stage with an existing shared base, publication now reuses the exact certified index tree already available to observation, or privately certifies a locked stable index. That existing private copy prefers a filesystem clone where supported. Before dispatching a base or each register batch, publication checks the current index signature. When an incremental signature moves, one private re-certification may update the signature only if the semantic Git tree is identical. Changes in the tree defer publication so the prerequisite list can be recomputed. This retains the original object preparation order and the cold and forced base paths.

The worker adopts the same object while the original author index and lock stay byte-identical. The negative case with a missing object waits and retries the unchanged stage when the object returns. The stamp-change fixture accepts matching Git tree semantics and refuses changed staged bytes. No live Git mutation or worker control was issued.
