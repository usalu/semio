# Bound Graph Fleet Blob Reads

`getBlob(hash, size)` used to buffer a whole successful response before verifying its length. The overflow regression read all three chunks and left cancellation unused. The empty SHA-256 digest returned zero bytes for a positive declaration. A nonempty digest with zero size and a declaration above 32 MiB both reached Fetch.

The graph state policy now declares the existing 32 MiB packed-document part limit once for the packer and receiver. Closure leaves retain their existing 16 MiB producer limit. The client requires an integral declared size in range and admits the empty CAS digest only at size zero. A successful body stream is counted against the signed declared length, with at most one retained buffer of that size. The first excess chunk cancels the reader. Short bodies and incorrect digests report `blob-integrity`. Decoded Fetch chunks determine the count, so an HTTP gzip wire length can differ from the expected decoded length. Caller aborts retain their reason. Body failures and expiry of the request deadline report `transport`.

The four focused regressions reproduced the prior behavior. The new client suite passed 14 tests with 22 assertions using injected Fetch and generated in-memory streams. A stalled body was cancelled at the real 20-second request timeout. SQLite 3.54.0 independently checked declaration constraints and Python hashlib checked stream contents for all 11 shared JSON cases. The related lease-wait and refusal suites passed 22 tests. I also ran the two passing existing conformance tests before confirming that they use loopback. They started an ephemeral local cache and attempted a closed loopback port. No external target was contacted. The new regression and oracle use no network. Graph-state whitespace checks passed.
