## 1. Task 3: the local unit key is portable (done, law red first)

* Cause (R196 finding 5, confirmed): `script.ts` keyed the local entry with `unitKeyV1(keyInput)`; `keyInput.environment` carries `CARGO_MANIFEST_DIR` raw (and the normalized arguments the out-dir), so two views of different hashes, or two machines with different roots, never shared a local entry. The fleet tier already used `portableKeyV1` with the roots.
* Now: `localKeyV1(input, roots, sensitive)` in `U/🛰️fleet/🪪️identity/🟦️.ts` = the portable key; a unit whose bytes name a real path of the machine (`sensitive` from `pathSensitiveV1`, the same rule as the fleet key) is keyed on those paths as well and shares only with equal paths. `script.ts` calls it (`key=localKeyV1(keyInput,roots,sensitive)`); one line changed there.
* Law `U/🛰️fleet/🪪️identity/🧪️tests/🏠️local-key` (4 tests): the same crate content under `/work/views/<hash>/r` and `/home/other/checkout` is one local key while `unitKeyV1` differs (the defect); a changed source, extern or toolchain is another key; a unit with a real path stays keyed on it and differs between roots; the fleet key agrees. Red on the live code (import error, `localKeyV1` missing), green staged.
* Effect: every LOCAL unit key changes once (a cold local unit cache after the landing; the fleet tier keys are unchanged). The files edited are not in the engine-digest surface (`native-surface` lists `🔏️key/` of the unit cache, not `📜️script.ts` nor `🛰️fleet/`), so no Nx task hash moves.
* Staged battery (overlay preload, children included): identity 8/0, `🌳️rooted` 3/0 (real cargo, 49 s), `🧯️fallback` 4/0, unit-cache `🧪️tests` 26/0.

## 2. Tasks 1, 2 and 5: the runner for a task on a view (module done, executor wiring NOT done)

New member `LIB/🏞️task-view/🏃️executor` (schema `🧬️schema/🔣️.json`: policy `maximumPins` 4, `maximumReruns` 1, six bilingual texts; `🟦️.ts`; `🧪️tests` 9). `runOnTaskRootV1({workspace,directory,targetDirectory,taskClass,paths,run,...})`:
* mode from `taskRootModeV1` (`SEMIO_TASK_ROOT` first, then the class, then the default): `live` calls `run` once on the workspace with an empty environment and does nothing else (no digest, no open): the live path is unchanged.
* `view`: digest the declared input files, hash, `openTaskViewV1`; `moved` re-hashes and re-pins before any compile minute (bounded by `maximumPins`; exhausted: run live with a notice, never a failure); `refused` runs live with the refusal text in both languages; `ready` runs with `{mode:"view",root:view.root,environment:{CARGO_TARGET_DIR,SEMIO_UNIT_CACHE_WORKSPACE_ROOT=view root},hash,view}`; an output directory inside the view is refused before the task starts (typed, EN and DE); at the end `view.verify()`: a hard-link view edited in place runs again on a new view (`maximumReruns`, then live); the lease is released on success and on a thrown error; the result answers for the start hash.
* Laws (red on the live code: the module does not exist; 9 green staged): live unchanged; the probe class runs on a view root that is not the workspace and holds the start bytes while the live tree is edited and a file added; the hash is the start hash; the target dir receives the output and the view holds none; output inside the view refused; moved input pins twice and the new bytes win; never-settling input falls back live after exactly `maximumPins` digests; refusal falls back live; in-place edit of a hard-link view reruns once, a view that always changes runs live; failing task releases its lease.

NOT done (the wall, found by reading, with the map for the next step):
* The cargo path cannot take another root by a parameter. `withRepositoryCargoArtifactPlanV1` (`LIB/⚡️caching/📦️artifacts/🏗️native-build/🟦️.ts:56`) requires `resolve(root)===authority.repositoryRoot` and the authority is issued by the Nx front for the live workspace (`createNativeNxCallerCapabilitiesV1`, `workspaceRoot`/`codeRoot`); the same `root` names the state directories (`cargoDirectories(root)`, leases, store, preparation), the source (`path`, `.cargo/config.toml` as `compilerConfiguration`), the published directory and the lane crates. `P/📦️artifacts/🏗️native-build/🟦️.ts` (P = `🧰️framework/🔨️modules/🏃️process`) uses `policy.cwd` 24 times (recipe, plan, source boundary, preparation, provenance, receipts) and its source boundary (`options.sourceBoundary`) is the live root. Running the Nx invocation itself in the view is no option: the graph, the Nx cache namespace and the authority are keyed to the workspace root (a second 10 to 30 minute graph read).
* So the executor wiring is a split of `root` into a STATE root (live: authority, machine state, build directory, lease, capture/`dist`, published directory, store) and a SOURCE root (view: `path`, `policy.cwd`, `compilerConfiguration`, `admitCargoSourceBoundariesV1` boundary, preparation cwd, lane naming), threaded through `withRepositoryCargoArtifactPlanV1` -> `withCargoArtifactPlanV1` -> the 24 `policy.cwd` uses, `NativeScript` `cargo build` in `⚡️caching/📦️artifacts/📋️native-orchestration/🟦️.ts` calling `runOnTaskRootV1` with `paths` = the cargo input closure (the workspace `Cargo.toml`/`Cargo.lock`/`.cargo`/`rust-toolchain*` plus every path package directory of `cargo metadata --offline`) and `run` = the build with the source root. With the source root a view, R188 checks 1 to 5 and 7 (live re-reads of lock, manifests, plan; retry layer), 6 and 10 do not need the live tree any more and `retryOnConcurrentEditV1("build")` can be skipped on that path; the exit-75 "implementation sources moved" path is the executor surface (R181), unchanged by the view. None of this can be proven without the repo-launched native process (the `native-build` tests do not start outside it: `Cannot find module '@semio-tech/framework-filesystem/observation/current'`, R188), so it was not edited. A blind edit of the 94 KB native build file would break every worker's cargo path.
* Consequently task 2 (removing the churn checks on the view path) is not done, and the class `readiness-probe` still runs on the live tree.
