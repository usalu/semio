# m05 Author Stage and Optional Git Object Retries

At 21:06:03 UTC on November 21, g1-server attested author index tree `9c4d168ad54c06a72c8b89c1d9ea0047052c48f0` with its Git checkpoint at server cursor 187:253151. At 21:06:15 UTC, m05 attested that exact index tree and journal cursor with 5,867 incoming entries. It still had the same tree at 21:07:00 UTC, with 5,072 incoming entries and no Git checkpoint. Exact tree observation does not settle its full incoming queue or prove the Git checkpoint at that cut. Its Ready status was still waiting on dependencies. The 21:06:15 lifetime receipt counted 122,802 target `EPERM` and rename events and one ordinary incoming worktree sharing event. Those counters have no path or current-stage binding and cannot identify the remaining queue entries.

The source prerequisite is an authenticated incremental author stage with a known base and no pending replacement base. In that case the exact loose object requirements run with the stage inputs. The remaining Git object cohort stays available to explicit stage hydration, because packs or a rebuilt base may contain objects outside the loose set. The existing post-stage pass tries that cohort when the stage did not consume it. When a stage is rooted, when the base is pending or unavailable, or when the pending registers supply no authenticated incremental proof, the code has no optional object cohort. It uses the existing prerequisite ordering. Complete pack proof still fences all object deletes.

A bounded post-stage retry would be scoped to the remaining cohort with that incremental proof. An explicit hydration request would still have the entire eligible cohort under existing cancellation and cooldown, including its first-time deliveries and any pending pack halves. A post-stage cap would select only due entries with the same HLC and operation, oldest due first, without moving first-time or replaced entries into cooldown. Rooted and unproved paths and the deletion fence would keep the existing ordering. A cap introduced only at that boundary has no demonstrated way to help m05 reach the observed stage. Once its stage registers settle the proof no longer identifies optional backlog. No scheduler, source file, cache, process or lease was changed.

Three existing native Git and replica fixtures passed with 41 assertions. They cover an incremental stage ahead of unrelated pack traffic, an incremental stage requiring its advertised pack in the same follow, and cold rooted recovery with an obsolete held object, retained index lock and cancellation.
