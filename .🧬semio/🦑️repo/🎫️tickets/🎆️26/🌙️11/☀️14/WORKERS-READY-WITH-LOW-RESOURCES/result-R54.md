## 2. What was built

Role `ready` in `S/🚦️ready/` (schema first: `🧬️schema/🔣️.json` = policy numbers, stage table, refusal texts en/de, the closed `Status` schema of `ready.json`):
- **Digest** (`readyDigestsV1`): per stage sha256 over name, platform, the digest of the stage before and the content hash of its inputs (tool table, bootstrap pins and script, `global.json`, `package.json`, `bun.lock`); a changed input makes that stage and all later ones stale; machine digest = sha256 over the stage digests.
- **Stages** in the order the bootstrap needs: `native` (bootstrap with `SKIP_REPO_BOOTSTRAP=1`, PowerShell `-SkipRepoBootstrap` on Windows), `repo-mcp`, `dependencies`, `tools` (`repo tools setup all`), `workspace`. Marker written after the last. A machine with marker and binary that never ran a stage here adopts the marker (so a machine a person made ready is not set up again).
- **Decision** (`readyDecideV1`, pure): server never; current + marker + binary = idle; current without marker = write it; no binary = restart at stage 1; person running setup or foreign lease = observe; recorded failure of this digest = wait for its back-off (a changed digest retries at once); not enough free memory = wait; else run the first stale stage.
- **Bounds**: memory gate = the graph's `fleetHostReadingV1` against its 1536 MB floor; `CARGO_BUILD_JOBS`/`MAKEFLAGS` = min(cores-1, free MB / 1536), at least 1; nice 10; `repo run` stages inherit R48's cut-and-continue; each stage has a timeout (2 h native, 1 h others).
- **Retries**: 30 s doubling to 20 min, plus up to 10 % per-machine jitter; failures recorded with exit, last 20 output lines, refusal code in English and German; never a hot loop (the loop sleeps at least 250 ms and at most the wait the decision names).
- **Stages outlive the runner** (added after the first watch, see 6): a stage runs under a detached wrapper (`🏃️wrapper/🟦️.ts`) that writes an exit file; `running.json` lets a restarted `ready` child adopt the same process; aborting the runner only detaches; cancellation = file `.cache/f/ready/cancel` (ends the process group). The agent restarts for new code every few minutes on this tree and used to kill the stage with it.
- **One lease per machine** (`createReadyLeaseV1`, `.cache/f/ready/lease.json`, exclusive create, renew 10 s, stale 60 s or process gone, takeover through an exclusive directory). A person's `native-bootstrap.sh` (edited in this folder) keeps `.cache/f/ready/human.json` touched; a fresh file is observed (`human-running`), not fought.
- **`ready.json`** (`createReadyStatusV1`, validated against the schema before every write, atomic): digest, ready, state (`ready|running|waiting|backoff|observing`), stage and index, attempts, exit, refusal {code, en, de}, peak MB of the stage's process tree (sampled with `ps`; not measured on Windows), last output lines, next attempt, timestamps.
- **Wiring**: `S/👷️agent/🟦️.ts:44` starts the child unless `SEMIO_FLEET_ORIGIN == SEMIO_FLEET_GROUP + "-server"`; `S/🟦️.ts` (role list, dispatch, usage, restart deferral while busy); `runReady` itself also returns at once on the server and writes nothing. `SEMIO_READY=off` stops it. No change to the topology JSON, so no replica restart for this part.
- **Fleet table** (`W/🩺️attest/🚦️readiness/🟦️.ts` reader, `W/🔁️replica/⌨️command/🟦️.ts` `showReadiness`, texts `fleet.ready.*` en/de, README section "Self-made readiness"): `fleet` (text mode) prints one row per worker from its `ready.json` in each output language with the stored reason of that language, names workers without a status, leaves the server out; exit code and `--json` unchanged. The only replica-module edit; it restarts replica daemons once.

## 6. Failure causes found and fixed, incidents

1. **`tools` before `dependencies` (first real failure, g1-m08, exit 75).** `repo tools setup all` stops with `Cannot find package '@semio-tech/process'` and "run the command again" when the dependency scopes are not installed: it needs `repo dependencies sync --all`, which the old bootstrap runs before. Fixed: stage order is now native, repo-mcp, dependencies, tools, workspace (landed about 17:51Z; machines whose child was idle restarted at once, busy ones after their stage).
2. **A stage died with every agent restart (seen on g1-m05, `native` never finished in 40 minutes; likely also behind the long `tools` runs).** The agent restarts for new code every few minutes on this tree (drain 5 min), ends its children and with them the stage process. Fixed in the second landing: stages run under a detached wrapper with an exit file, `running.json` and adoption; the restart of the child is deferred while a stage runs and the new child adopts the process. Proven by the test "a stage outlives the runner" and live: g1-m05 finished `native` after the landing.
3. **A person's run that hangs would hold a machine for ever** (g1-m02 and g1-m03 were `observing` for 30 to 40 minutes). Third landing: a `human.json` older than 2 hours (birth time) no longer counts.
4. Not fixable from here: `tools` runs 20 to 40 minutes and several Macs show `javascript-installed-paths` activity of other commands; whether this is contention with the persons' rounds, memory queueing of `repo`, or the real download and compile time is not determinable from the store. g1-m06 and g1-m09 do not attest at all (m06 came back at 18:45Z).

Incidents and deviations (to be weighed by the coordinator):
- **Edited in place before the lock** (as R49 did): insertions and new files, each re-read before its edit, the landing record was taken afterwards (`T/landings.md`, three entries, all five test directories green each time). Because the role runs live on the workers, the first version (non-detached stages) ran on the workers for about 30 minutes: stages that were in flight when an agent restarted were killed and started again.
- **Early tests started the installed `repo` binary of this machine** (g1-server) with `tools setup all` once in the first test run and once in the first proof run, because `os.homedir()` ignores a changed `HOME` in Bun. It answered `unknown command "tools"` at once and did nothing; the runner now takes the home as an explicit option and the tests pass a fake home. Mentioned because the rule says `repo tools setup all` must not run on the group server.
- **`native-bootstrap.sh` was edited while sessions may have been running it** (bash reads a script by offset; the insertion shifted the rest by 243 bytes). A session that started it before about 17:44Z resumes in the middle of an earlier line when its bootstrap ends and may print a syntax error or run the end of the script twice; the marker is written by the `ready` role anyway. Sessions that started it later write `human.json` (observed on g1-m02 and g1-m03).
- Layering: `ready` is the third child of the agent, so a worker whose agent is not running new code has no `ready` child; there is no replica or topology change for it.
