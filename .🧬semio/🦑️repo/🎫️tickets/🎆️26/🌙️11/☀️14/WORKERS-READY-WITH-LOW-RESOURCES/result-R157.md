## What was built (all behind the lab, nothing of the real worker changed)

1. **Lab home seam.** Every lab machine gets its own account directory `<machine>/h` (`HOME`). Before, `HOME` was the live account, so `repo-mcp:install`, `native` (`~/.local/bin`, `~/.cargo`, `~/.rustup`, `~/.dotnet`, `~/.local/share/semio/*`) and `tools` (`homedir()` in the tool table and command) wrote into the live account. Now: `HOME` = lab home; every tool home variable of the live account is dropped (`CARGO_HOME RUSTUP_HOME DOTNET_ROOT GOPATH GOROOT GOCACHE GOMODCACHE BUN_INSTALL XDG_* ...`, list in the schema); no `PATH` entry below the live account; network clients are pointed at a refusing proxy (`HTTPS_PROXY=http://127.0.0.1:9`, loopback excluded) and `curl wget brew apt-get dnf pacman zypper sudo` are refusing programs first on the stage `PATH` (exit 22, EN/DE text, every call logged to `downloads.log`). So no stage can download or install host-wide without permission; the first stage that would show it as a wall with the URL in its tail.
2. **Read-only seed by copy-on-write clone** (`sliceLabCloneV1`): `clonefile(2)` through `bun:ffi` on macOS (one call per tree), `cp --reflink=auto` on Linux, plain copy otherwise. Seeds are declared in the schema with the tools that need them: always `launcher`, `repo` binary, `runtimes` (the pinned bun of the Go launcher: `~/Library/Caches/semio/runtimes`); only with their tool: `.cargo`, `.rustup` (rust tools), `.dotnet`, `.local/go`, `.local/share/uv`. Measured here at load 50 to 68: `.cargo` 0.6 s (16434 files), `.dotnet` 1.1 s (14389 files), `.rustup` 13.6 s (313980 files, about 10 GB logical, 0 bytes of extra disk), `launcher` and `repo` 0.01 s; a per-file `cp -c -R` of `.rustup` did not finish in 150 s (stopped). A write into a clone leaves the source unchanged (test).
3. **Tools of a slice from the declared kinds** (wall 34): table `kinds` in the schema (`typescript`, `go`, `rust`, `wasm`, `python`, `dotnet`, `cmake` -> tool ids; every id checked against the real tool table `TOOL_SETUP_V1.groups.all`); kinds of the slice come from the declared probe table `READY_PROBES_V1` (`repo-mcp` is `go`), `--kinds` overrides, an undeclared owner makes them unknown and the stage prepares `all` (said in the report). `repo-mcp` -> `repo tools setup bun go`: no rustup, no nightly, no cargo-nextest, no llvm-cov. The three-probe default prepares `bun node rustup rust cargo-nextest cargo-llvm-cov go`.
4. **`--stages=all`**: the real plan of a worker (`READY_STAGES_V1`: `native` bootstrap script, `repo-mcp`, `dependencies`, `tools` as declared) with only `tools` restricted to the slice's tool ids and `workspace` replaced by the slice read; stage table per machine (stage x seconds x verdict, from the driver's timings, or from the samples when the run ended first) in the report and `home.json`.
5. **Guards**: before/after listing (`sliceLabLiveSnapshotV1`: two levels of `.cargo .rustup .dotnet .local/bin .local/share/semio .local/go Library/Caches/semio/runtimes Library/LaunchAgents`, the shell profiles, `/tmp/semio-repo`, one level of the live `.cache`, `.cache/b`, `.cache/f`, `.cache/boot-recovery` without the scratch directories of peers); paths that changed during the run are printed and fail the run when they are outside the live `.cache` (peers write the live `.cache` all the time, so those are listed, not judged).

## Walls (numbered from 60)

60. **A refusing network proxy for the whole stage environment breaks the resident service** (my own regression, landed 22:33 UTC, found by R155 at 22:35, fixed 22:38): every lab read died at `build:implementation-source` with `Unable to connect`. Not loopback (`127.0.0.1`, `localhost`, `[::1]`, `0.0.0.0` and the host name tested and fine with `NO_PROXY`), the failing URL was not identified (a fetch-logging preload showed nothing: the fetch is not the global one). Fix: the proxy is opt-in (`SEMIO_SLICE_LAB_PROXY`), default off; the guard is now the refusing programs plus offline variables (`GOTOOLCHAIN=local GOPROXY=off CARGO_NET_OFFLINE RUSTUP_OFFLINE NPM_CONFIG_OFFLINE HOMEBREW_NO_AUTO_UPDATE`). Honest limit: a download by a TypeScript `fetch` inside a stage is not intercepted any more. Test: opt-in proxy and the forced variables.
61. **One real download happened in my runs**: before `GOTOOLCHAIN=local` existed, the `go` of the seeded `.local/go` switched to the toolchain `go1.26.9` and fetched it into the lab home (`h/go/pkg/mod/golang.org/toolchain@...`, read-only files, removed). One Go toolchain archive, no other. It is the case "Downloads need the user's permission"; reported here and in the answer.
62. **The real `native` stage cannot be sliced.** `setup` has no component selection but `rust|node`: it installs Node, rustup with the pinned nightly, .NET, uv, links Go and builds the launcher whatever the slice is, so a Go slice still pays Rust (this is wall 34 one stage earlier: the lab's `tools` is now slice-sized, `native` is not). The launcher build looks for the pinned Go in `<script root>/.cache/b/t/m/native/go/...` (hard-coded sh spelling of the live tools partition, read-only), in `$XDG_DATA_HOME/semio/go/v<ver>` and on PATH; in a lab with a frozen root it found none and tried to download. Seed `go-pinned` (copy of the live partition entry to `.local/share/semio/go/v<ver>`): native then got past the launcher in 18 s. Open for the build owner: a `native` argument per toolchain (`node`, `rust`, `go`, `dotnet`, `uv`), so the stage can be sized by kinds.
63. **This Mac cannot pass the real `native` stage: `~/.dotnet/dotnet` is a 10-byte stub (`#!/bin/sh`, 2026-11-14 12:14)**, so `dotnet --list-sdks` prints nothing, `ensure_dotnet` does not find SDK 8.0.421 (it is in `~/.dotnet/sdk`) and would download the installer script and the SDK. Live and lab alike; not repaired (a repair is a download or a restore from the SDK directory: the owner of the machine decides). Lab option `--skip=<stage>,...` runs the rest.
64. `native` on macOS runs `brew install pkg-config cairo pango` and `brew install --cask font-dejavu` unconditionally (host-wide state, network when anything is missing). The lab refuses them (logged in the report: downloads line).
65. **`mktemp` of the `native` script uses `/var/folders/.../T`, not `TMPDIR`** (seen in the refused curl lines): a temporary directory outside the machine's roots (small, removed by the script).
66. `repo-mcp:install` refuses an existing `~/.local/bin/repo` that is a copied file ("Native installation refuses an executable owned by another installer"): the real worker has a link to the launcher there (native links it). The lab seed is now that link; stage `repo-mcp` took 86 to 93 s here (load 45 to 60) and printed `Installed native repository command` into the lab home.
67. **Go spellings of the live state, not behind `machinePathV1` (cannot be: Go)**: the launcher locates the pinned bun in `<root>/.cache/b/t/m/bun/<sha>` first and in the user cache second (`🚀️launcher/📌️runtime-pin`, registry `cache.toolsPartition`); the fleet store reads `<root>/.cache/f/machine.json` (`📦️packages/🐹️go/🛰️fleet-store`). In the lab the frozen root has no `.cache`, so the seeded user cache (`Library/Caches/semio/runtimes`) is used; with the live root the live partition is READ. Fix needs the Go side to honour `SEMIO_MACHINE_STATE_DIRECTORY` (Go change, its TS mirror and the oracle fixture): not done.
68. **`dependencies` cannot be exercised without the network or a seeded store**: `dependencies sync --all` fills `b/d` (the live one is 13.9 GB on its own volume, 942k inodes) and reads `b/t/m/downloads` (191 MB of tarballs). A cross-volume copy of 14 GB per machine is not a seed; a clone is impossible across volumes. The lab stage was stopped at 112 s (`bun:dependency-storage`, store stage exclusive) before it fetched. Options for the owner: a lab partition mounted from a clone of the live image file `b/d/fixed.dmg` (same volume, `clonefile`, but the image carries inode and boot-session identity in `image.json`, which the image code checks), or a package mirror on loopback like the fleet cache.
69. **`tools` and `workspace` of the all-stage plan were never reached**, so item 5 (what is slow in `tools`) is not measured here; the earlier numbers stand (R149: 98 to 146 s for the tools of the lab plus 516 s for the real stage that failed on the boundary; compiler-helpers cap 1200 s). The tool selection (`bun go` for `repo-mcp`) is proven by a test, not by a run.
70. The listing guard prints peers' writes to the live `.cache/f` (daemon, sidecars, boot, state.wal: 11 to 12 paths per run) and no path of the account (`.cargo`, `.rustup`, `.dotnet`, `.local`, profiles, `/tmp/semio-repo`) in any run, which is the evidence that the home seam holds; the counting-fs law of item 1 is the decoy-run test (the real stage runner against a decoy account and checkout).
