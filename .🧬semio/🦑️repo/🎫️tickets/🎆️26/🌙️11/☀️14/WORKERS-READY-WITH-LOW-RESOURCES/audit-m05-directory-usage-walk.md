# m05 Directory-Partition Usage Walk

At 03:15:34 UTC on November 21, the m05 graph still ran as PID 43252 in owner pass 2, with 508 of 596 owners settled. Its directory-partition presence precheck had started 226 times. Timers recorded 6,402,814 cumulative milliseconds in 676 mapping-grant waits and 5,566,756 in 226 allocated-usage checks. Postchecks had recorded 182,524 milliseconds in total. Each timer aggregates its own waits and is nested inside the presence timing. The usage instrumentation counts meter calls, so those counts alone do not establish how many complete filesystem walks took place.

A held reservation rechecks its current directory-backed receiver and physical mapping, calls the directory meter, then checks its durable allocation and namespace. Beyond the meter’s existing two-second completed-observation window, a recheck requires a fresh allocated-usage walk. That walk measures filesystem entries through bounded, asynchronous metadata reads. Reservation, commit and recheck accounting carry distinct semantics. A clock-based exemption or a journal-only substitution would require an additional exact proof of current allocated bytes.

The existing directory walker gave an entire listing to a single worker. A 384-entry flat directory used just eight concurrent metadata requests when the same pool could support 128. Pending listings were the limiting factor. The walker now schedules bounded eight-entry batches from each admitted listing across its 16 existing workers. At most 16 listings can be in flight or retained. Physical byte accounting still consumes each observed file identity, counts hard links once, ignores entries that vanish after listing and uses the same no-follow path metadata checks. Cancellation and failure drain already issued metadata requests. Capacity and freshness rules and all receiver, mapping and journal checks still run as before.

The red fixture measured eight occupied metadata slots against SQLite’s expected 128. The fixed fixture used all 128 while retaining the exact SQL-accounted allocated bytes, logical bytes and entry count after a concurrent hard-link path replacement and a vanished leaf. A second fixture exercised the listing and metadata limits on a branching tree. Native fixture trees independently agreed with Python `lstat` and `du`. The usage, meter, platform and fixed-backend suites passed 61 tests and 1,100 assertions locally. There is no measured Windows wall-clock speedup from this change yet.
