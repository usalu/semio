## Findings from the code (verified)
- The long hold is three nested layers in `PUB/🟦️.ts` `completeRepositoryDependenciesV1` (~line 408): the exclusive lease `native-fixed-image:<dir>` taken by `withNativePlatformProtectedMaintenanceParentV1` (through `attemptFundingParentV1`), the protected artifact token (`captureNativePlatformProtectedArtifactMaintenanceV1`) and the input-group receipt that every `fence()` re-reads. The slow part is the per-scope loop (~line 387: `fleetInstallScopeV1` = fleet restore or `bun install`, then qualify). It writes into `j/<generation>`, which is already generation-named and invisible to readers until the ready receipt (`bindings.json`) and the `node_modules` binding swap (`publishBinding`, ~line 391).
- So the seam for snapshot semantics exists in the data (immutable generation directories, one atomic binding swap) but not in the locks: the protected token is valid only while the exclusive parent is held.
- A bounded exclusive window alone does not help while any reader holds the image shared for hours: the graph server and every `repo` command attach `native-fixed-image:` shared for their whole life (R1 point 3), and an exclusive request waits for all of them. The publish must therefore not be exclusive against readers at all: readers need generation pins, funders need mutual exclusion among themselves only.

## R25b (wire into the real funding): NOT DONE, stopped before any change to the tree

Nothing was landed, `LAND-OK` was not written, no `repo tools setup all` was run, the tree is as after R25. Reason, from reading the native core (not a guess):
- All four purposes of `completeRepositoryDependenciesV1` (`strict`, `preserve`, `rebuild`, `bootstrap`) run their whole body inside ONE `withNativePlatformProtectedMaintenanceParentV1` (non-waiting EX of `native-fixed-image:<dir>`, `native-build/.../publication/platform/🟦️.ts:32`). Inside it the code takes the journal presence, a protected artifact token (`captureNativePlatformProtectedArtifactMaintenanceV1`), the input-group receipt that every `fence()` re-reads, and `withArtifactReadV1` contexts bound to the parent; every one of those is a live-parent callback object (`requireProtectedMaintenanceScopeV1`: "Live private maintenance parent callback required") that dies when the parent ends. There is no shared-hold variant of the funded producer in this file to reuse; the consumer sync path is a different code path with different invariants.
- So "stage without the hold, exclusive only for the publish" is not a change of the funding module: the install loop (line ~387) needs a token and input-group receipt that exist only under the exclusive parent. It needs (1) a second protected-parent mode that proves exclusivity among funders only, with the image held shared, for an envelope that is already current and fully funded (no allocation change), (2) a re-derivation of the token, receipt and fence for a producer that runs across two short exclusive sessions (stage inputs, then publish ready receipts plus the binding swap) with the install between them, and (3) pins in `withRepositoryCacheStoreV1` for readers. Each of these changes invariants the physical-cleanup enrolment, the journal replay and the retirement driver rely on, and none can be exercised except by a real 15 to 30 minute `tools setup all`; a mistake there breaks `repo` on all eight replicas at once (the tree is replicated within a second) and the rollback needs `repo`-independent tooling.
- I judged landing an unproven rewrite of that core, and then running the real setup on this machine as its only test, as an unacceptable risk, and did not start it. What is ready to wire: the R25 primitives (proven), the exact seam list above, and `land.py` with rehearsal and rollback.
- Proposed way to do it safely (its own package, quiet machine, no fleet landing until proven): develop the second parent mode and the split producer in a scratch clone of the repository on one worker; prove with the R25 laws against a real funded image there (reader started before, during, after; two scopes; kill -9 during staging and publish); only then land. Estimated size: large; the unknown is (2).
- Not measured, therefore not reported: `Exclusive access ... for N ms` from a real run, per-scope restored/installed lines of a real run, retirement by pins, exit code, wall time, second-run time, restart-pass time.
