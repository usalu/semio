# Replica Sharing-Violation Retry Custody

At 09:02:40.770 UTC on November 21, the Windows m05 attestation reported 2,767 pending entries and 1,432,879 cumulative sharing violations. Its stated index tree was `2f8cec66552f5cd157bbc972c209be48af03cd6c`. The coordinator had already delivered the staged index and the observed journal cursor. The attestation does not identify every blocked lock holder.

The ordinary incoming PUT path consumed and verified the same CAS blob again whenever the target rename remained busy. In the private native follower fixture, an exact three-attempt schedule opened the same CAS content three times. The updated follower opened it once and still attempted target rename exactly when due, applied an unrelated path during the cooldown, and published the expected source bytes after release. A separate red test showed an already-delivered new HLC inheriting the old path cooldown. The corrected queue attempts that new winner in its first turn.

A replica now retains an already verified ordinary PUT after an actual busy rename in its private staging directory. It retains at most 512 files, 16 MiB combined and 1 MiB per file. A copy is eligible for 120 seconds and expires on the next queue sweep. Admitted files remain until consumed, invalidated or expired when the cohort is full. The next attempt requires the same winning PUT facts and independent current no-follow identity checks on both the CAS source and staging file. It repeats the existing target ancestry, type and conflict checks. Git internals and guarded entry scripts keep their original paths. Existing retry delays apply to the same HLC and operation.

A changed or corrupt CAS file never publishes from the retained bytes. Local staging replacement falls back to a freshly verified copy. A single active path owner prevents two overlapping queue turns from spending one staged file. Superseded and expired copies are removed, as are cleanly completed, cancelled and closed-session copies. There is no staging neighbor in the target directory. The next replica open already sweeps its private staging directory after a process crash.

The private SQLite fixture independently checks exact I/O counts and bounded retention across file count, total bytes, individual bytes and expiry. Fault-injected integration covers private replacement, CAS corruption, cancellation, session close, parallel follows, ownership replacement and unchanged output during a refusal. The cap addresses the retained hot subset of the queue. This work did not measure Windows throughput or perform live replica operations.

The final connected repo run passed 129 tests and 25,326 assertions across native replica convergence, fault-injected receiver races, Git stage and packed-stage hydration, and the retention-budget laws.
