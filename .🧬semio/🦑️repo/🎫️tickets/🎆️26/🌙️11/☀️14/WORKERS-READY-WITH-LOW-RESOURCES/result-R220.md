## 2. What was built (all by construction: less live data, no forced collection, no release step)
`🗂️workspaces/🟦️bun/🟨️.cjs` (ownership):
- `PackedObservations` replaces the per-path object graph (`paths` Map of sealed records, `order` array of frozen references, `frontier` Map of stamp objects): one `Map<path,id>` and one path string per path, kind/device/inode/mode/frontier mtime and ctime/settled in typed arrays (`Uint8Array`, `BigUint64Array`, `Uint32Array`, `BigInt64Array`), the fact order as one `Uint32Array` (`id*2+op`). Capacity limits, the closed-kind refusal, the "directory state before listing" rule, first-observation order and the "changed during verification" refusal (with `ownershipChange` diagnostic) are the same code paths as before.
- Packed listings: names interned once (`internName`, bounded table), one kind character per row; the listing cache record keeps the packed full listing and the packed projection (shared when nothing is dropped) instead of 2.3 `{name,kind}` objects per directory; the walk plan gets fresh row objects per call (young garbage, nothing retained). `exportOwnershipIndexV1` and `seedOwnershipIndexV1` keep their row format (export of `🎓️teaching`: 31,196 rows, same sha before and after; a seeded walk lists 0 directories and gives equal rows).
- `FrontierProof`: the frontier stamps of one replay are collected in flat arrays and applied only when the whole replay holds (same decision function `ownershipFrontierDecisionV1`, unchanged).
- `observed()` answers `paths` as a read-only array view (`Proxy` over `[]`: `length`, index, iteration, `map`, `filter`, `at`, `JSON.stringify` all work; rows are built on access, frozen, never retained, one-slot cache). It is a snapshot: a later re-derivation replaces the store's arrays but not the snapshot's.
- Empty directory results of the walk plan share one frozen singleton (98k fewer object pairs).
`⚡️caching/🚀️bootstrap/📦️dependencies/🧾️generation/🟦️.ts` (capture): `evidenceSinkV1` (exported) encodes each frontier and execution row to its JSON line at once, digests incrementally and keeps 4096-row chunks; no array of rows. The index of listed directories holds numbers, lists are read from the view when needed. Bytes, digest, name and counts are those of the old `evidenceOf`; the old function is removed.
Why this cannot trip the 85 % gate refusal: the walk adds no release, collection or footprint-keyed step; its footprint is the retained size, which grows monotonically while paths are observed and does not spike afterwards (live trace below: 119 to 871 MB climbing, flat through the recheck). The retained size per path fell about 2 times (98k paths: 202 to 104 MB heap) and the peak of the 491k synthetic store fell 2.4 times (2,762 to 1,130 MB), so the walk uses 13 % of the 3328 MB booked for the stage (was 22 %) and the 85 % line (2830 MB) is out of its reach; what else the stage holds is not changed here.
