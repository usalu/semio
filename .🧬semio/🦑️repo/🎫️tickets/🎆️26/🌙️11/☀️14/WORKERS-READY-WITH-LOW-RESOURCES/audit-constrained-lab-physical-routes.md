# Physical routes for the constrained cold lab

The corrected cold lab has an owned local wait before the host capacity grant. This audit measured 54,186,254,336 available bytes on the checkout and `/private/tmp` filesystem, against the unchanged 60,129,542,144-byte admission floor at the 41 GiB image size. The two directories share a filesystem for this measurement. The prior standalone attach controls and the host-only `diskutil image` timeout independently block assuming that fresh free blocks alone make the native route usable.

The existing acceptance launcher is ticket `constrained.ts`. Its preflight and execution require native Darwin, the canonical host capacity ledger, an isolated writable frozen checkout, a short case-sensitive APFS sparse-image mount, and at least 40 GiB available inside that fresh mount. Its outer host request covers four cores and 8,192 MiB through create, run and cleanup. It exports the actual machine verdict and timing receipts after settlement. There is no existing switch to substitute an external directory or host volume for the outer image. The source backend registry does expose an unprivileged Native directory partition on Darwin and Linux. That backend can replace inner cache partitions when its declared capabilities are sufficient. It neither creates the acceptance launcher’s outer APFS mount nor performs its disk admission or receipt export.

The generic `slice-lab` command in the library supports POSIX hosts and can run the five actual readiness stages on a frozen checkout under the simulated resource model. It explicitly refuses Windows. Its local launch path provisions an independent temporary work root and checks available bytes. It does not itself issue the acceptance wrapper’s outer host grant and physical backing custody. A standalone Linux run would therefore answer a portability question. The observed Linux fleet origin, m04, had a roughly 10.6-hour-old Ready mirror. Fresh Darwin origins m02, m07, m08, m10, m11 and m12 reported active Ready timestamps but no certificate of the required physical disk headroom or a healthy local StorageKit attachment path. The Windows m05 mirror was fresh. The m09 origin directory contained none of the inspected Ready, attestation or pool documents. An origin named in the store is insufficient to qualify its resources.

The currently authored repo catalogue has the harness script and local test surfaces, with no enrolled cold-lab dispatch action or authored REAPI command covering this wrapper. The existing offload action and worker default are bounded Rust execution. The replicated Ready, graph and pool surfaces publish claims or adopt enrolled artifacts within their own contracts. They provide neither a general command lane nor this lab’s launch authority. The existing local Docker socket, Docker Desktop user socket, and standard Colima socket were absent in the local probe.

The supported next attempt remains the existing ticket wrapper, run locally by the workspace operator on a Darwin machine that passes the unchanged physical preflight and can perform native sparse-image attachment. This coordinator presently has two independent blockers, physical headroom and the observed native image service timeout. A different Darwin host is conditional on local access and its own preflight; no authorized fleet action in the inspected surfaces can establish those facts and submit this run. A Linux acceptance route would need an authored physical admission and isolated backing/receipt contract before its result could stand in for the current wrapper. No lab, attach, remote command, mount or infrastructure change was issued in this audit.
