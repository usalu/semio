# Fact Index Backing Accounting

The generation index cache uses the opened fact index’s `stats().bytes` as its charge. The charge now includes the entire packed document backing and every distinct backing allocation retained by the offset tables and row-read tracking. The packed document can be a slice of a larger buffer, including the encoder’s growable buffer. Charging that allocation at its full length accounts for the storage the slice keeps alive. The packed format and logical length checks are unchanged. The materialized generation cache entry still uses its row estimate.

The typed tables occupy 16 bytes per string, 4 per kind, 4 per owner, 4 per fact, 11 per row and 8 per class. The implementation reads actual backing lengths and deduplicates by buffer identity. The values above describe the current layout and provide an independent test expectation. The total is captured when opening the view. The four lazy caches report and enforce their own budgets. Decoded owner and kind strings, proxy and cache objects, other JavaScript heap, runtime overhead and temporary decoding and encoding allocations are outside the backing total. Allocation lengths do not measure process RSS or graph-build peak memory.

Three schema-validated neutral fixtures assert 0, 76 and 200 bytes of tables. The independent Python decoder derives the six counts from the packed header and checks those totals using standard-width `struct` layouts. Each fixture opens an exact-length input and an offset slice backed by a larger allocation. The tests verify the backing charge before lazy reads, after reads and after dropping caches. The cases failed against the former implementation, which charged 10 of 24, 32 of 108 and 73 of 273 bytes at their first failing expectations.

The fact codec and transcode suites passed all 96 tests under `repo tools exec --light bun -- test --timeout 15000 --coverage`. The codec recorded 98.27% line coverage and 93.10% function coverage. The accounting lines were covered. The initial full run reported one failure at the 5-second default timeout in the existing workspace-size test. The second run passed with the longer test timeout.

A bounded independent Brotli header probe confirmed the scale on disk. The sole retained fact artifact belongs to generation 259, whose manifest bytes still hash to the current pointer's recorded parent. Its 14,011,996 compressed bytes encode 567,105 strings, 19 kinds, 12,242 view owners, 211,263 facts, 848,604 rows and 34,002 classes. The header counts imply 19,574,436 additional bytes of retained typed metadata for that view before lazy caches and JavaScript overhead. The probe read 16,384 compressed input bytes and examined only the 19-byte header. Generation 260 still has a null current manifest. This measurement makes no claim about a current whole-workspace peak or the validity of the retained parent.

## Registered Cache Lifetimes

The stats registry held each named cache strongly until its name was replaced or the 256-name FIFO removed it. That allowed the registry to retain populated lazy fact-index caches after their owning view became unreachable. The generation store’s explicit cache deletion also bypasses the `onEvict` callback, which made this lifetime independent of the view’s cache admission and eviction. Production cache owners retain their handles in module constants or owner closures. Host diagnostics, slice reports and graph memory reporting read the registry for metrics. The project-farm pressure path uses it to shrink caches whose owners are alive.

The registry now stores weak references. Stats and shrinking prune collected registrations. Registration also prunes at capacity before applying FIFO eviction to live registrations. Named replacement, ordering, the global cap, per-cache limits and callbacks for actual cache evictions are unchanged.

The Bun GC regression populated two named caches, released the owner of one and verified that both that cache and its payload were collected after major collections. The former implementation retained the cache. The test also confirmed that the registry still reported and trimmed the retained cache. The bounded-cache and lint suites passed all 9 tests with 100% line and function coverage of the bounded-cache module. The focused resident digest-cache and closure walk-cache consumer tests passed as well.
