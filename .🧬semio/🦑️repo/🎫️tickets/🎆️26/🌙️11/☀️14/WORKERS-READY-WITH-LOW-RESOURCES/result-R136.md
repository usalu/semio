## Walls (numbered, evidence, status)

11. **Re-diagnosed: source admission is not the time sink.** Host log of the first run (default 7-owner slice, empty machine, 16384 MB / 8 cores): the `build:source-admission` progress lines (125 of them) end after about 5 s with `last phase started: source.served` (the source memo answered); the next 250 log lines are `Downloading the pinned cargo-nextest 0.9.140`, `cargo-llvm-cov 0.8.7`, rustup and `nightly-2026-07-20` installs, all inside `repository:command`. The lab replaces the `tools` stage by `repo --help`, so the read command provisions the Rust toolchain itself: about 95 s on a slice without Rust owners (run 2: worker `start` begins at 96.9 s), 300 s or more on the default slice. Status: the 20 s / 60 s admission target is met by source admission itself (served from the memo in under 5 s, warm and cold); the cold cost belongs to the skipped `tools` stage. Open: a lab option that runs the real `tools` stage once and clones the result (see "not exercised").
10. **Missing module `🏗️ifc/📚️catalog/🛠️extract/🦀️render.ts` is the cause of the slice-worker restart loop, not a harmless retry.** Evidence: in the service log each `Cannot find module '…/🦀️render.ts'` is followed by a fresh `[capacity] admitted graph-plan` (4 times in 540 s) and the lab prints `the code on this machine changed under the slice worker (it ended with exit code 75)`; the worker never leaves phase `start`. Cause: the file was deleted by the sweep commit `ccac6866cc1` (2026-11-01, 713) while `📁️generate.ts` (imported by `🏭️pack-all.ts`) and the test `🧪️tests/🦀️native/🟦️.ts` still import `renderRustCatalog` from it: a deleted-but-used file, not a taxonomy drift and not a generated file. A static scan of every relative import below `🏗️ifc` (`missing-imports.py`) finds no other missing source module (the rest are bare directory specifiers and generated `dist`). Fix: restore the file from `ccac6866cc1^` (7627 bytes). Test: the existing `🦀️native` test, red before (baseline 0 pass 1 fail), landing below.
13. **The restart text blames the code.** A worker that dies on an unresolved import is reported by the host as `the code on this machine changed under the slice worker (exit code 75)` and restarted up to the restart budget; the real cause (the module path) is only in the service log. Open (file `🏡️resident/🏗️composition/🌐️host/👷️slice-pool/🟨️.mjs` line 110 renders `host-slice-owners-restarted`; the worker's own error text should travel with the restart decision).
14. **A selected read of an owner whose targets use `scriptProvider:` groups fails: `Unknown selected named source input: scriptProvider:artifact-package:scheduling`** (run 2, slice norm-din4108, norm-din16798, energy-oracle-py, after 130 s of reading; request-failed 33fcf501). Stack: `discoverBuildOwnerAdmissionFactsV1` (owner-discovery:197) → `projectWithDefaults` → `projectInputs` → `declaredSourceInputs` → `buildSourceContractGroupsV1` (admission:83). A dependent asks the provider owner (`@semio-tech/repo-script-providers`, the owner with `metadata.semio.scriptProviders`) for its provider group by name; `projectWithDefaults` adds the groups to the named inputs only after `projectInputs`, so the request is refused as unknown. The full read never asks a project for a group by name, so it never met it. Fix (landing below): compute the provider groups before `projectInputs` and hand their names in `commandGroups`, the existing way a command source group is made requestable; a name no designation states stays refused. Test `🔌️providers/🎯️requested-group` (new; red before: reproduces the identical stack; green after).
15. **`Maximum call stack size exceeded` in `settleObservedComputationV1` (`👁️observation/🟨️.mjs:955`).** Run 3 (slice norm-din4108-rs, norm-artifact-contract-rs, empty machine, load 50): after 313 s the service answered `request-failed acfd801c RangeError`. The line is `Math.max(0,...rows.map(...))` over every observed row of a failed round; a spread above roughly 500000 arguments overflows the stack (bun: 300000 passes, 1000000 fails). A failure of a wide computation must reach the caller as itself. Fix (landing): a `reduce`. Test `👁️observation/🧪️tests/📚️wide-failure` (1.2 million absent-path probes then a throw; red before with the identical stack, 26 s). Not yet known: which failure the round was hiding (it will show once the stack error is gone).
