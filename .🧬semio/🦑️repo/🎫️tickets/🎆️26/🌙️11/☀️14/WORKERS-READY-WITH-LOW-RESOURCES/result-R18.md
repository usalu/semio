## Design
- Existing mechanism, reused unchanged: signed manifest + index blob + unit blobs in `<group store>/v1/fleet/install`, restore verified (signature, lock digest, every blob digest while streaming into `tar`, fingerprint, installer scan shape), atomic: any disagreement removes the placed roots and is a miss; fleet claim so one machine installs a state while the others wait for its upload.
- New `fleetInstallScopeV1(request,{install,qualify})` (FF/📦️install): restore, else install here; the caller's own `qualify` (exports + installed-paths proof) must pass for both; a restored tree that does not qualify is removed and installed here and the fleet pack is replaced; publish only after qualify; cancellation propagates.
- New `javascriptDependencyFleetRequestV1` (BOOT/📦️dependencies/💾️storage/🟦️.ts): the one place that builds the request (inputs, Bun, recipe, host class, scan/remove/report). The synchronisation (`fleetRequestOf`) and the funding producer both use it, so a pack published by either is restored by either.
- Funding producer (`PUB/🟦️.ts:387` loop) now calls `fleetInstallScopeV1` per scope. A scope is its own key: one changed lockfile or member manifest changes one key, the other 5 restore.
- Host class (gap 2a): `fleetInstallRuntimeV1` makes the Linux architecture `x64-gnu` or `x64-musl` (macOS and Windows keep `arm64` / `x64`, so their existing keys do not move); `setupHostV1` of R11 now delegates to the same `fleetInstallHostV1`.
- Retention: `installKeepStates` 18 -> 36 (6 scopes x 2 classes x 3 generations), because pruning is by age and 18 states drop still-valid unchanged scopes after ~4 lock changes.
- Gap 2b, the three `generate` tasks: `framework-schema:generate`, `ui-styling-tokens:generate`, `framework-graph:generate` are now `cache:false`, `outputs:[]`, `metadata.semio.cache={version:1,class:"side-effecting",reason:"mutates-workspace"}` (as `plugin-registry:generate`). Reason: they write into the tracked tree from inputs outside the project root (the entity catalog, the styling projection); declaring outputs would let a hit restore OLDER bytes over newer sources, which is worse than today's no-op hit. Their read-only twins `preview-generated` stay cacheable. The setup family table says so and a test pins it (3 project files read by Python).
- Gap 2c, Playwright Chromium: no digest is recorded anywhere locally (no download was made). The pins schema got the field: `BOOT/📦️dependencies/🏗️native/🌐️system/🔣️.json` `chromium.downloads: []` with schema `Chromium`/`ChromiumDownload` (platform, architecture, revision, https url, sha256, bytes). A machine that downloads Chromium must fill it; then the download can become a blob like the other pinned tools (that wiring is not done: nothing to key it by yet).

## Transfer cost against the 30 minutes
Measured: extracting 87 of 1 035 unit blobs (38 MB packed, 134 MB extracted, extraction ratio 3.5) took 0.6 s here, so one 522 MB pack extracts in about 9 s on a loaded server SSD, plus two walks of 66 000 entries (fingerprint, scan). A worker reads its 6 packs: about 3.1 GB (darwin) or 4.2 GB (linux). Estimate, not measured on a worker: wire time 30 to 60 s on gigabit, extraction 1 to 3 min on a 16 GB machine, total 2 to 5 minutes against 26 to 31. Upload by the installing machine: gzip level 1 of 1.5 GB per scope (about 15 to 60 s) once per class and lock state. The waiting machines add at most the installer's time for the scope they wait on (pipeline, scopes are claimed one by one).

## What a worker's log must show
- Per scope in the funding (bilingual, `sayCachingV1`): `Scope <scope>: restored from the fleet (<entries> entries, host class darwin-arm64, state <key>); nothing was installed here` **or** `... installed here (...) and published to the fleet, so the next machine of this class restores it` **or** `... installed here (...); the fleet did not receive it (no fleet store, no identity, or it could not be published)`.
- Lines `[DATA] Store dependency fleet {"stage":"claim"|"wait"|"restore"|"publish"|"skip","detail":...,"scope":...}` (`skip` carries the reason: damaged pack, did not qualify, other lockfile).
- An equal second machine: 6 `restored`, no `bun install`, no `installed here`. A 16 GB worker whose log has `installed here` for a scope that another machine of its class has funded did not reach the pack (check `skip`).

## The restart addition (coordinator message, run 2 of R6): findings and what is NOT done
1. **What the read covers.** The text `Another process kept editing bun workspace ownership` is `edited()` (`🗂️workspaces/🟦️bun/🟨️.cjs:10`) with the path fallback when the message has no `": "`, reason `bytes`: only `Bun current ownership changed after refreshed continuation` (`🟨️.cjs:397`, in `requireCurrentMembershipV1`) fits both. It is thrown when, after one fresh derivation whose membership shape and manifest texts were **already proved equal** (`:393-395`), the replay of the whole decision frontier (`replayCurrentMembershipV1` `:318`, `authenticateCurrentMembershipV1` `:361`) still sees a moved path. The frontier is every directory and manifest candidate the ownership walk observed: log counters `dependencies:funded-ownership:frontier:1011428` at the first restart, `...1148906` at the second, i.e. about 500 000 observed paths, replayed twice per pass; limit `maximumObservationPaths` 524 288. A projected listing (`projectListing`, `:226`) already ignores files other than `package.json`, dot names and output names; what moves it is any new or removed non-dot, non-output DIRECTORY (and ino/mode of observed entries) anywhere under the walked roots during the minutes a pass takes. So the trigger is not a package.json/bun.lock edit: it is the size of the replay window against normal fleet directory churn.
2. **Why I did not narrow it.** The refusal after a fresh continuation is a pinned contract, not an accident: fixtures `last-fresh-continuation-*-refuses` in `🧪️tests/🧫️fixtures/🔣️.json` (SQLite oracle in `🧪️tests/♻️refresh`). I tried the obvious change (re-derive up to 4 times and refuse only on a membership or manifest change); it makes two of those contract cases accept and I reverted it. Changing the contract needs an owner decision on the fixtures; the real cure is a shorter replay window (fewer observed paths: stop observing directories under the roots that no pattern reaches; or replay by batch with the already-proved listing stamps), which is a change of the walk, not of the producer.
3. **(b) scope as the unit.** Partly done, honestly: each scope now publishes its pack to the fleet store right after it qualified, and a restart (any reason) restores a completed scope from that pack instead of running `bun install` again (about 10 to 60 s instead of about 4.5 minutes per scope). The producer still stages all scopes as ONE atomic input group (`stageNativePlatformProtectedArtifactInputGroupV1`, `PUB/🟦️.ts:~385`) and the ready receipts (`bindings.json`) are written after all scopes; I did NOT restructure that into per-scope custody (it needs a real multi-scope proof run, which `tools setup all` is the only way to get and takes 30+ minutes; I could not run it). Without a fleet store on the machine (standalone) a restart still reinstalls.
4. **(c) restart for a changed implementation.** Implementation restarts are decided by declared format stamps only (`🏗️build/🧷️format-stamps/🟨️.mjs:75-90`: a stamp is a declared schema document; `guard` runs at exclusive lease admission), plus the generic "loaded implementation was edited" class (`🔄️reexec/🟨️.mjs`, origin `edit`/`load`). The observed restart was the edit class on bun ownership (point 1), not an implementation change, so there was nothing to narrow in (c). Consequence for landing: any edit of a module the running funding loaded restarts it (that is why R18 waits for R6's run).
5. **Files I took over (funding producer):** `PUB/🟦️.ts` (producer part: `runRepositoryDependencyProducerCompletionV1` scope loop and imports), `BOOT/📦️dependencies/💾️storage/🟦️.ts` (`javascriptDependencyFleetRequestV1` and the sync's use of it), `FF/📦️install/🟦️.ts`. R6 keeps the retirement driver (`PUB/⚙️setup/♻️retirement`) and `PUB/⚙️setup/🟦️.ts`.
