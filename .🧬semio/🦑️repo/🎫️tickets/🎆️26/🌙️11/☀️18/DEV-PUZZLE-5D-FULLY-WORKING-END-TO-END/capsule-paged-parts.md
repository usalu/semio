# Capsule Dream parts storage

The normal mounted preparation, maintenance and close policy authorizes up to 1 MiB of release per turn. The native editor lays out each typed `Puzzle5dPart` in 368 bytes. The shipped Capsule Dream DSL contains 2,880 scene parts. The independent Bun SQLite oracle `capsule-part-release-oracle.ts` gives the exact minimum contiguous arena as 1,059,840 bytes, already 11,264 bytes above that authority before spare capacity. A Vec's backing must release as one allocation.

`Puzzle5dSnapshot.parts` and `Puzzle5dArtifact.parts` use the existing `PagedList` with the original list’s addressable cardinality. Each physical page follows the framework's bounded reserve and retirement protocol. The registered DSL derive still declares a parts table, and Pack and canonical JSON keep the same list shape and order. The same paged type flows through the existing row delta. `SpliceSceneRows` borrows table rows in order and preserves its own 64-row mutation payload. Paste and the world proximity utility read the existing indices without gathering a second contiguous table.

The native whole-document verification uses `set_active_example_reaches_the_capsule_dream_document`. The archive codec and row splice laws cover existing Pack, DSL, and inverse replay output. The source also retains the ordinary one-unit host turn ceilings.

The late native trace `capsule-returned-read-rung.gdb` sampled six actual return-pump calls after the Capsule publication was stationary at checkpoint cursor 42, 180 completed items, and two returned snapshots. All six quotes requested 24 copy bytes, zero capacity, 1,507,328 release bytes, and depth five. The loan contained one item, 32,768 copy bytes, 16,777,216 capacity bytes, 1,048,576 release bytes, and depth 4,096. Each step returned an empty physical receipt. The release was exactly 4,096 rows × the verified 368-byte part stride. The enlarged Vec came from existing list growth before the final authored row count.
