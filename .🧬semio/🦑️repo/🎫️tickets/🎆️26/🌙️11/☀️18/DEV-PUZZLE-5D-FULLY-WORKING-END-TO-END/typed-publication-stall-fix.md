# Selected Typed Publication Stall Witness

The publication scheduler records the selected mounted operation's stage, ownership flags and monotone store progress immediately before its Publishing unit and compares them to the same mounted operation afterward. The pump reports whether it entered a unit, including cases where the first attempt was blocked. Fuel/deadline skips, a preparation receipt still awaiting handback, and latest-wins scheduling make no contribution. Genesis with retained checkpoint custody remains exempt.

The consecutive count belongs to each mounted operation. Real store progress resets it even while the other witness fields remain equal, as in the Capsule Dream preset edit. The 4,096-turn fault check runs independently from power-of-two trace sampling. After the selected owner returns to the registry, its captured ID is used to route any fault to its existing publication fault path.

The shared JSON fixture covers alternating operations, repeated IDs across instances, 4,103 advancing bodies, uninterrupted and interrupted stalls, a skipped owner and Genesis. Both Bun conformance tests passed, including the SQLite oracle and scheduler-source ordering checks. The Rust parser accepted both changed scheduler/pump files. The native fixture test was added to the instance typed-operations crate and has not been run in this focused pass.

The adjacent original-emission Bun suite passed one of three tests. Its two failures are existing source expectations: it expects a scheduling condition without the custody guard already present at the start of this change, and requires `close_original_retained_step` in an unchanged native test that calls `close_original_retained_effect_step` instead.
