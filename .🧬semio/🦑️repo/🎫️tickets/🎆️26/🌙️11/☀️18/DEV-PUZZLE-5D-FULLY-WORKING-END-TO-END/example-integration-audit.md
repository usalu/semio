# 5D example integration audit

The small and large paths share one command and one document edit. `Puzzle5dSetActiveExampleWork` counts removal and addition rows, chooses a vector or `ArtifactMutationPages` at construction, admits each page before producing rows, and emits the selected backing. The mounted typed-operation publication hands both to `admit_apply_batch_with_pages`; the batch prepares mutations and inverses in order. Generic emit staging flattens pages, while child-group publication explicitly rejects them; the bounded page path therefore depends on the local mounted edit owner.

The page unit law `mutation_pages_keep_order_and_bound_each_backing_release` covers 133 synthetic entries, an insufficient capacity grant, ordered iteration and pop/restore, and individual page and directory release. The independent SQLite fixture covers its row order and releases, as recorded in `scope-final.md`. Neither proves actual 5D publication, undo, cancellation, or teardown. The prior native example parsing and document construction checks likewise do not dispatch the large example.

The existing non-ignored `set_active_example_switches_the_document_and_never_faults_on_capacity` dispatches empty, Concrete Forest, and Nakagin; Capsule Dream only receives an extent assertion. `set_active_example_reaches_the_capsule_dream_document` does dispatch and close Capsule Dream, but remains ignored with a historical publication-stall explanation. Run this ignored law explicitly against the synchronized current source; remove the ignore only after it passes, and update its stale rationale. Its assertion currently checks part count alone: also verify fastener count and identities, that prior document rows disappear, and that one edit has correct inverse/undo and redo across page boundaries.

Focused follow-up laws should exercise empty-to-large, small-to-large, large-to-small and large-to-large switches; exact page boundaries and a final partial page; an insufficient page grant followed by progress; cancellation while admitting and while publishing; and closing with both full and partial page backing. Verify the final typed document and original mutation order, no duplicate or missing rows, exact retirement receipts, and no leaked page or directory backing. Exercise a small vector case alongside the paged case. The historical 4,096-turn publication-stall risk must be observed rather than assumed resolved by paging. These are proposed coverage gaps, not claims of observed failures.
