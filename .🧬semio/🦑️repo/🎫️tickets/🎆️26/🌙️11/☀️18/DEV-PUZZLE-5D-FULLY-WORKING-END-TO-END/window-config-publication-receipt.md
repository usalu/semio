# Window configuration preparation receipt

The live Puzzle5D v1 regression failed while settling the mounted typed preparation for the voxel dimension command. The native debugger stopped where the fixture rejects an out-of-grant receipt. The mounted grant had 64 items, 32,768 copy bytes, 16,777,216 capacity bytes, 1,048,576 release bytes, and depth 4,096. Publication reported 47 items, 32,857 copy bytes, 21,632 capacity bytes, and 6,288 release bytes. Copy bytes exceeded the grant by 89.

The publication pump already restricted the grant passed explicitly to a store unit. Other work within the same synchronous unit read the initiating context directly, where the narrower mounted preparation ceiling had never been installed. The pump then included those effects in its preparation receipt. The pump now lends the original context the exact remaining phase grant across the synchronous step and its nested receiving receipt settlement. The store still gets its one-item unit grant and can consult the original full-turn ceiling when it distinguishes a spent remainder from a permanently impossible quote.

The debugger continued past the fixture check and found a second receipt of 34,953 copy bytes, then a stable block in the World WindowConfig snapshot clone. The concrete store received one item, 30,937 copy bytes, and 16,776,696 capacity bytes. Its owner requested one item, so increasing the item count left the block unchanged. The next clone demand was 192 copy bytes, 120 capacity bytes, and depth two. The native receiving callback reached controlled retirement of a cloned field binding. The mounted publication reported no progress for 4,096 successive units. A diagnostic widening of the copy/body argument to the original 32,768-byte ceiling advanced the old binary to a real 20,224-byte copy and a receiving grant mismatch. The recorded probe changes only the old binary in the debugger.

An unquoted native receiving scope caps every physical currency at half of the active context. Narrowing the pump to 32,768 bytes would therefore limit its receiving body to 16,384 bytes before source setup. The publication branch now reserves the existing Source setup and reply headroom, quotes the remaining bounded body, and uses the scope actually issued by the native caller when granting the store and settling its receipt. The full phase ceiling deducts the same overhead before permanently refusing an oversized store demand. The fixture test budgets are unchanged.

A debugger ring buffer captured the eight actual store turns immediately before the watchdog. Each entered the Seal phase with one item, 32,768 copy bytes, 16,777,216 capacity bytes, 1,048,576 release bytes, and depth 4,096. The intermediate clone samples were making progress. The canonical sealer drives the original Source admission under its selected Work quote. The old source supplied three Work units throughout edit and authority admission, while the child can require four at payload initialization and publication. Ready handoff received a pointer-sized copy quote while the child quotes its full output transfer. The canonical source now quotes admission, ready handoff, and authority close through their actual owners.

Three focused Bun tests passed. They verify both canonical admission callers use the selected Source Work and return quote, validate the preparation receipt against its actual scoped grant, and reconcile the receiving control and reserved-return currencies using SQLite. The wider three-file source conformance run had unrelated existing source and fixture mismatches.

The failing regression was reproduced from the native test binary. The updated publication crate successfully emitted native Rust metadata with the pinned compiler against the exact dependencies from the native V1 Cargo fingerprint. The smoke check uses `voxel-source-metadata.py` and writes its output under the ticket’s generated folder. Verification of the patched end-to-end test binary remains pending the coordinated rebuild.
