# Publication and Cleanup Audit

The component stage script accepts only `component --manifest <Cargo.toml>` and calls `buildComponentClosureV1` under an issued compiler control. That build driver builds, describes, receipts and materializes the selected browser component as one custody chain. No supported interface accepting an arbitrary local wasm as an official staged artifact was found. Ticket `native-preview.ts` transpiles a supplied file for a separate diagnostic proxy; this does not establish official component provenance or update the official activation receipt. The supported official route is `repo run semio-hub-fem-component:component`, then the fem3d React prototype prepare and activate targets.

The ticket-specific cleanup CLI is `repo ticket purge-artifacts 2026/11/18/DEV-FEM-3D-END-TO-END`; it is dry-run unless `--apply` is supplied. It selects only oversized generated files over 5 MiB and generated directories over 10 MiB, only after the ticket is closed. It protects tracked files, links, outside paths, unreadable tracking state and any ticket with a generated file modified within 600 seconds; apply checks the planned snapshot again. The close implementation also invokes the oversized policy. The internal `Generated` selection can remove all eligible generated content but no public CLI switch for it was identified, so the CLI alone does not ensure an empty generated directory. Stop all ticket writers before cleanup. No live state or production file was modified in this audit.
