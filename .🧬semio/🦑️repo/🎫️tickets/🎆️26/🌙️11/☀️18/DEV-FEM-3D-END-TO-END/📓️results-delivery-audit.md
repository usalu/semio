## Conditional liveness observations

- `reconcile` clears pending and calls `begin_execution` before `recovery.reserve` and previous-result retirement (`session-api:212–238`). On either later refusal it releases shell/credit but never rolls back the request execution. The registry rejects all further `begin_execution` while it exists, and only a matching terminal receipt clears it (`framework/🔨️modules/🌱️value/📋️registry/🎫️requests/🦀️.rs:98–100`). Since no new job was installed, that receipt cannot arrive. However, reachability is not established in a healthy registry: free-shell release asserts recovery reservation absent, the previous-shell retirement is prechecked under the same registry borrow, and scheduling a retained result clears its pointer. Fresh Demo has no previous or retained shell. Treat this as an invariant-dependent defensive weakness, not a demonstrated production failure.
- Model bounds return zero progress with no terminal diagnostic (`session-api:100–102`); request preparation errors likewise collapse to zero (`:69`). Preflight errors clear pending after recording progress (`:151–162`), potentially repeating preparation. A permanently invalid request thus looks queued rather than failed. Missing source has the same indistinguishable observable (`:115`). Treat permanent refusal as an addressed terminal error, distinct from temporary grant/capacity waits.
- `reconcile` finds the first complete pending entry using only app instance and canonical revision (`:172`), then validates base revision and generation afterwards (`:176–184`). A stale earlier slot sharing the canonical revision can block an eligible later slot. Reachability under healthy request lifecycle has not been established; a multi-request revision-transition test would determine it.

A fresh component containing the continuation change is needed to locate the observed Demo stall before attributing it to any conditional issue above. Capture the spawn trace, structured shell faults, changing stage/caption and final current-source caption in order.
