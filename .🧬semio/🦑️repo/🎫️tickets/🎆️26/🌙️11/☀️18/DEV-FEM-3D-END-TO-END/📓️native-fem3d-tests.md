## Sealed snapshot round-trip retirement (store test-support)

- Root cause (proven with a `[DEBUG]` track_caller probe, since removed): `drive_retirement` in `🧰️framework/🛍️products/💻️os/🔨️modules/🏪️store/🧰️test-support/🦀️.rs` issued a fresh `OriginalRetirementPump` turn per step, and each turn carries a new Source identity. `FactorySharedRetirement` (`🧰️framework/🔨️modules/🌱️value/♻️retirement/🔗️arc-custody/🏭️factory/🦀️.rs:27`) binds the Source of its first step and refuses a later step from another Source ("captured shared original changed its Work or destination"). A sealed `Fem3dSnapshot` (shared custody) needs several steps, so `retire_parsed_document` failed on step two.
- Fix: `drive_retirement` now funds every step through `AuthoringWallet::run_settled` (the store's own `close_owned_step_cold` mechanism, unsourced Work), so shared custody keeps one binding. Both round-trip asserts and `close_owned_unscheduled()` are restored in `fem3d_mutations_apply_through_the_store` (no `mem::forget`).

#### Design A: box `settlement`, `failure` (and `allocation`) in the marker
Change `NativeEncodeEffectState.settlement/allocation` and `NativeSnapshotEffectProgress.failure` to `Option<Box<..>>`. Marker drops from 10 720 to about 2.2 KB; a row frame to about 2.6 KB. #### Design B (recommended): rows share the parent marker
`row()` and the hand-written frames (`Member`, `LoadFields`, my `Term`) hold their own `NativeSnapshotEffectProgress` plus `Option<NativeSnapshotFailure>`. `receive_nested` already hands the closure the parent's `birth`/`birth_unwind` markers, and every use there is followed by `reset_completed()`, so they are free between actions. Make the frame `{value, scratch}` only and run `fill` and the final `move_existing` with `birth`/`birth_unwind`. A refused row then leaves its failure in the marker that `receive_nested` already retains and retires, which is the same custody as the birth failure today. Frame size per row becomes about 100 B (value plus scratch), independent of marker size, so it is O(1) and about 100x smaller than A; no framework edit is needed (changes live in `✏️s/🔌️plugins/🏗️fem/🧩️receiving/🦀️.rs` `row`, and `receive-record.rs` `member`/`load`/`term`). `collect`'s `Rows<T>` keeps one marker per list (not per row), which is already O(1) per row. Invariant to test: a failing row (non-finite number, refused text) still retires its partial value exactly once; run the fem2d/fem3d `invalid`, `cancel` and prefix tests after the change.
Choice: B first (outside `🧰️framework`, so it does not restart the running build); A only if other receivers need smaller markers.
