# Canonical WFC graph publication

The November 20 canonical Bitmap, Grid 2D, WFC 2D and WFC 3D launches sealed their graph on the first inference round. The selected graph was about 36 MB. Publication rejected four source receipts between 679,450,727 and 747,619,424 bytes against the unchanged 536,870,912-byte limit. The Grid 3D request ended with a separate `closed` error.

The selected graph loader had concatenated the admission and inference captures. Both captures can contain the same row, and a long capture can keep duplicate rows under different IDs when the bounded observation table clears. The two selected receipts still on disk quantify the duplication. The build selection of Norm DIN 4108 and Repo MCP retained 590,520 observations, of which 422,671 were distinct. Exact duplicates occupied 50,367,673 of 169,999,385 bytes (29.63%). The framework process diagnosis selection retained 226,783 observations, of which 172,175 were distinct. Its duplicates occupied 17,691,768 of 67,589,806 bytes (26.18%).

The failed WFC selections had no retained receipt or admission memo in the selected store. Bitmap, which produced the largest prior receipt, needs 210,748,512 bytes removed to fit the limit (28.19%). Applying the observed duplicate fractions to that receipt would leave between 526 and 552 MB, so the two samples cannot establish that WFC Bitmap fits.

The sealing path now unions exact observations in capture order before checking the facts and writing the receipt. The first occurrence of a row is retained and different facts for the same path and operation still reach conflict checking. The independent Python grouping oracle verified the output including repeated and conflicting facts. The loader regression also proved that a fact consumed by admission and inference is written once. All 45 tests passed across the row-table, row-pool, inventory, graph repair, seal, stale-fact, and candidate suites.

## Receipt size profile

A concurrent repository change introduced v4 authority receipts, which index nested observations and roots. The two archived receipts contain empty nested observation lists, so indexing after the exact union added 1.09 MB to the framework process diagnosis receipt and 2.85 MB to the Norm DIN 4108 and Repo MCP receipt. Neither sample measures savings in an input with shared nonempty nested lists. Another 45 focused tests passed after the format change, including the codec and the streaming receipt reader.

The larger sample's distinct rows spend 77.7 MB on path fields. This includes 25.2 MB for `lstat`, 21.4 MB for `exists` and 17.8 MB for `readdir`. A directory-prefix table with index and exact suffix estimated 17.10 MB and 53.61 MB of further savings on the two samples after paying 3.09 MB and 9.43 MB for their tables. Capping the table at 16,384 entries keeps its measured size below 3 MB and still saves 16.71 MB and 39.98 MB. The estimate allows worst-case index widths and keeps literal paths wherever a dictionary entry would cost more. This wire-format option has no implementation in this ticket. The measurements are in `🗑️generated/[DEBUG] graph-authority-format-profile.log` and `🗑️generated/[DEBUG] graph-authority-bounded-prefix-profile.log`.
