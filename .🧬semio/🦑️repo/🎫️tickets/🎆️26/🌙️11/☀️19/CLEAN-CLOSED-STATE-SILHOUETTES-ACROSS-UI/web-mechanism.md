# Web Mechanism: State Silhouettes in the Compositor

## What changed

- `📏️border-presentation/🟦️.ts`: pure `resolveBoxStates(boxes, pointer, focusVisible)`, `boxDrawnSides`, `boxSilhouetteSegments(boxes)` and exported `borderStatePriority`. Cases: `states.cases.json`, `silhouettes.cases.json` (unchanged; both schemas validated with Ajv, every case run forward and reversed, closure invariant checked by an independent lodash interval-union oracle, plus a generated grid of cells).
- `🗂️WindowChrome/shared-border.ts` (`BorderCompositor`) now works on boxes:
  - Boxes: windows, chips (`[data-window-silhouette-chip]`, painted in their window's SVG), frames, groups (`data-shared-border-cells|group`, edge-less owners) and cells (`.shared-border-cell`, `[data-shared-border-cell]`, or a framed child of a `data-shared-border-cells` owner; painted in the owner's overlay with the cell's four edges).
  - Interactive = matches button/link/tab/option/menuitem/treeitem/switch/checkbox/radio/field/`summary`/`[tabindex]` (not `-1`)/`data-shared-border-interactive`, or (frames, groups, cells without child boxes) has exactly one interactive descendant, or (chips) has any, or (window) sits in an interactive `[data-overview-card]`. Disabled = `:disabled` or under `aria-disabled="true"`.
  - Hover: innermost interactive enabled box of the pointer's box path. Focus: only `:focus-visible` (`matchesFocusVisible`), innermost interactive box. Marks (`data-active`, `data-state=on|active`, `aria-selected|pressed`, `data-celebrated|introduced`, `border-loading|waiting`, `data-shared-border-state`) apply to the box or its single interactive child. Listens to `keydown`/`pointerdown` too, so modality changes repaint.
  - Edges: `boxDrawnSides` (normal: declared minus sides flush with an undrawn parent edge; stated: all four). Same snapping, real-scroller clipping (a cell is never clipped by its own owner), junction and miter pipeline. Stated segments are painted after normal ones inside an overlay, and an overlay holding a stated segment gets `z-index: 41` (else 40).
  - Window hover no longer exists unless the window itself is interactive. Overview card focus and hover come from the card button through the compositor (a neighbour's coincident seam is resolved by priority).
  - Chips replace `chip-focus.ts`: a stated chip closes its own outline (snapped to the window's silhouette lines within 2 px); `data-focus-on-accent` is set when an active window shows a focused chip.
  - Lazy overlays (design point 7): a frame with `data-shared-border-edges=""` has no overlay, no `position: relative`, and no `data-shared-border-attached` while normal; its overlay is created when it is stated and removed again afterwards. Hosts with cells always keep theirs.
- `🔲️WindowSilhouette/shared-border.ts`: `sharedOutlineSegments(..., snap, source = owner)` so a cell's edges are named by the cell and painted by the owner.
- `🎨️.css`: removed cell divider borders, flow variable and wrap borders/margins, every `:has(+ …)` cell state rule, frame/cell hover and focus `border-color`, the overview card focus rule, the window hover rule, the introduction box hover stroke, the active `border-color` of toggle/button/action group items, and the forced-colors cell border rules. Added: unlayered hover stroke (no `!important`); forced colours map `CanvasText` (normal) and `Highlight` (hover, focus, active).

## Convention for borderless controls

```tsx
import { sharedBorderlessBoxProps } from "../🗂️WindowChrome/shared-border.ts";
<button {...sharedBorderlessBoxProps}>…</button>
```
Equivalent to `data-shared-border-frame="" data-shared-border-edges=""`. The element must be interactive (or carry `data-shared-border-interactive`) to be hovered or focused, and carries its state markers (`aria-selected`, `data-state="on"`, …) itself or on its only interactive child. Remove the element's own state border, ring, outline and box-shadow.

## Deviations and decisions

- `[tabindex="-1"]` is not interactive (programmatic focus targets such as windows must not hover as a whole).
- Hosts without a frame (`data-shared-border-group`, `data-shared-border-cells` without frame) now get an overlay when they own cells. A nested cells owner that is itself a cell therefore has its own overlay; coincident spans still resolve to one owner.
- Per-cell `data-tone="destructive"` no longer recolours its divider (only the row-level normal stroke rule remains).
- Not changed against design.md; no case expectation was altered.

## Round 2: live-probe defects

- Cell ownership (`sharedBorderCellOwner`): a cell is painted by the nearest ancestor owner that is not itself a cell (frames that are cells and plain wrappers such as the hint span are walked past; the walk stops at a window silhouette). A group that scrolls its content (computed `overflow` auto/scroll, or `scrollWidth > clientWidth`) is skipped in favour of the next owner out, so tab strips keep one overlay on the frame; if no other owner exists the scroller keeps it. Cells are clipped by every real clipping ancestor between the cell and the owner and beyond, never by the owner itself. Regression tests: "a cell inside a frame that is itself a cell…" (window controls, IconSelector shape), "a cell below a plain wrapper…" (panel tabs), PanelTabBar scroll test.
- Mode dock tabs (`[data-slot="mode-dock-tab"]`) are implicit borderless boxes (no attribute needed): hover/focus closes the tab, the chip stays normal. Test: "mode dock tabs are borderless boxes…". Panel tabs are cells of their group and close per tab.
- Chips: a chip belongs to the nearest registered window above it (not the nearest `[data-window-silhouette]`), is interactive when it holds any interactive element, and its stated segments are now also handed to windows whose outline is degenerate (the utility-bar unfold chip: the silhouette used its full `borderPath` and dropped every other segment). Tests: "a chip inside an interactive card…" (hover stays in the chip rect, never states the card) and "a chip of a window whose silhouette is a plain bar…" (degenerate outline).
- Tree stepper (bottom open over the cell's width): not reproducible in jsdom, the flush-bottom cell in an edge-`bottom` row closes fully (regression test "a stepper cell flush with the bottom edge…"). Most likely cause, unverified live: the row or group has `overflow: hidden` with a bottom border, so the browser clips the half of the 1 px stroke that lies on the clipper's border, while the cell's logical clip test passes (paint line equals the client edge). Check live with `silhouette.sweep()`; the fix would be to let a clipping ancestor's own border line be painted by the clipper's owner overlay rather than by a child's.

## Round 3: sweep follow-ups

- `data-selected="true"` is an active marker (compositor marks, `activeSelector`, CSS focus-on-accent underline rules, observer filter).
- New state `invalid`, ranked normal < focus < active < invalid < waiting < loading < introduced < celebrated < hover (`borderStatePriority`, `BorderState`, `states/silhouettes/segments` schemas, `cases.json`, `states.cases.json` case). Marked by `aria-invalid="true"` or `data-invalid` (not `="false"`) on the box or its single interactive child. Stroke `var(--destructive-border)` (`sharedBorderStroke` and CSS); forced colours map it to `Highlight`; contrast "more" triples its stroke width. The old input-frame `aria-invalid` stroke hack is deleted. The native agent mirrors this in Rust.
- The compositor's attribute observer now also watches `data-selected`, `aria-invalid`, `data-invalid`, `role`, `tabindex`, `data-shared-border-group|cell|interactive`.
- Table rows: checked in Chromium (browser pane, static page): an SVG appended by script to a `position: relative` `<tr>` is positioned at the row's origin, is not wrapped in an anonymous cell and does not change row layout (next row's top unchanged). So `<tr>` boxes keep the overlay as a direct child; test "table rows and zero-width separators are boxes". Not checked in Firefox or Safari.
- Zero-width Resizable separator: a box whose width or height is 0..2 px was skipped; now it is painted only while stated, as its centre line (paint inset is `min(1, size/2)`; `viewBox` is omitted for a zero dimension because a zero-sized viewBox disables rendering). Normal thin boxes still draw nothing.
- Dead modifier utilities `border-loading-active|element` and `border-waiting-active|element` are removed from the CSS. Their class strings still exist in `🌀️status-border-presentation/🟦️.ts` (`*BorderActiveClass`, `*BorderElementClass`) and in consumers (ActionGroup, os Interpreter, `tree-helpers-1` test); they are now plain aliases of `border-loading|waiting` and can be collapsed by their owners.
- `focus-seam.cases.json` follows the course CSS left by the products agent (the removed focus rules are asserted absent).

## Round 4: roots, clipping, chips

- A box can never exist without a compositor: `attachSharedBorderRoots(document)` runs at module load of `shared-border.ts`. It retains a compositor for the root (`.semio-scope`, else `body`) of every element that matches a frame/edges/cells/group/chip marker, whenever such an element is added or such an attribute is set, however the attributes were produced (hook, constant spread, mapped rows, plain props). The lease is released when the root leaves the document or holds no box any more. `useSharedBorderBox(ref)` is the explicit variant (returns `{ ref, ...sharedBorderlessBoxProps }`); `sharedBorderlessBoxProps` stays for constants, `.map` rows and conditional spreads where a hook is not possible, so no consumer had to change. `ShellScope` needs no separate retention: its `.semio-scope` root is retained as soon as it holds a box. Test: "a box that appears without any hook still gets a compositor…".
- Clipping: the clip of a box is widened by 0.5 px (a clip landing on the box edge by rounding never cuts the line on it). A stated box (frame, cell or chip) is never cut by a clip: a side overshooting a clip by more than 1 px moves onto the clip edge, a box entirely outside paints nothing, and its sources carry no clip. Normal boxes are clipped as before. Tests: "a stated cell stays closed and fully visible under a clipping row…" (clip equal to, 0.4 px inside, and 8 px inside the box bottom), covering the stepper, `button#workbench` and LayeredOverview Swipe shapes.
- Utility bar unfold chip: reproduced in jsdom only as a chip flush with a clip (stack and chip share the rect) and as a chip as large as its window, with plain and degenerate outlines; all paint a stated outline now. The live cause was most likely the clip coincidence above; re-run `silhouette.sweep()` to confirm.

## Round 5: product API, void elements, disabled stroke

- Public API: `sharedBorderlessBoxProps` and `useSharedBorderBox` are re-exported explicitly through `WindowChrome`, `SharedBorderRow`, the React component-exports barrel, the package source and the `@semio-tech/ui-react/chrome` entry. About 45 products sites (course, presentation, os) now spread `{...sharedBorderlessBoxProps}` instead of spelling the two attributes; the course `BORDERLESS` constant and the ink block `common` props use it too. No spelled pair remains outside `🖱️ui`. Products were not built or tested here (only vitest of `🧱️elements` and `border-presentation`).
- Void and replaced elements (`input`, `select`, `textarea`, `img`, `canvas`, `video`, `audio`, `iframe`, `object`, `embed`, `br`, `hr`, `svg`, and any non-HTML element) are boxes painted by the nearest ancestor that can hold an overlay (`holdsNoOverlay`); that ancestor gets its overlay only while the box is stated or declares edges. Test: "a void or replaced element that is a box…".
- Forced colours: a disabled box (`:disabled` or under `aria-disabled="true"`) marks its normal-state segments with `data-shared-border-disabled`, mapped to `GrayText`. Test: "a disabled box that draws normal edges…" and the CSS assertion in `segments.test.ts`.

## Round 6: keyboard focus

- Outline: `@layer shared-border-outline { [data-shared-border-root] :focus-visible { outline: none } }` (declared after the Tailwind import, so it outranks utilities without `!important`). The `[role="tabpanel"]:focus-visible` outline and its forced-colours line are deleted. Test: class 1 CSS test in `focus-boxes.test.tsx`.
- Converted to boxes: Tabs `TabsContent` (tabpanel), `Checkbox`, selectable HistoryTable rows, Icons story gallery buttons, the Layout story panel toggle, and Diagram nodes: the diagram wrapper now sets the keyboard-focused node when a `.react-flow__node` takes `:focus-visible` focus (and clears it on blur), which gives that node the existing box attributes and explicit focus state. Only the focused node is a box, because 20,000 boxes would be too expensive.
- Compositor: pointer and focus resolution never cross into a nested `.semio-scope` (its own compositor owns that content).
- Classes 2 to 5 (panel tab, navbar, treeitem, menu item, tab trigger focus; `tr` focus; Layout/Default Fullscreen and Properties; IconSelector, PresenceBar, Import file hover): focus and hover resolve through the same box path (`boxOf`), and jsdom reproductions of the shapes (panel tab strip, button group in a navbar, row under a clipping scroller narrower than the row, control at the right edge of a clipping bar, three-deep nested cells) all paint closed outlines for focus exactly as for hover, with no state on any ancestor. I could not reproduce the live defects without the browser, so these are covered by tests that pass but not proven fixed live. Most likely cause of the focus-only gaps: the browser's own `1px auto` outline on the focused control (the control inside a cell is not itself the box), which the new outline rule removes. Please send, for a failing live case, the painted paths with their owner overlays and the box ids resolved by `silhouette.sweep()`.
- Class 6: a native `input type="checkbox"` was not a box, so its group row cell (with a child cell) could not be hovered; it carries the box props now. Test: class 6.

## Round 7: priority and one paint convention

- Priority (decision): normal < active < invalid < waiting < loading < introduced < celebrated < focus < hover. `borderStatePriority`, `BorderState`, the `states`/`silhouettes`/`segments` schemas, the `states.cases.json` ranking cases (the focus-versus-active and focus-versus-invalid boxes now expect `focus`), `segments.test.ts` and the compositor tests follow it; design.md point 2 already states it. The Rust mirror must use the same order. A focused box is never opened by a neighbour's selection: test "focus outranks a neighbour's selection".
- One paint convention: before a box's rect becomes logical and paint lines, every side lying on an ancestor box's border-box edge (within that ancestor's border width plus 0.75 px; the walk stops at the first ancestor that is not flush) is moved onto that edge. A cell inside a bordered group, and a cell nested in a group shell that is itself a cell, therefore resolve to the group's own coordinates and paint one line with the group's outline, instead of a second line 1 px inside. Tests with mocked layout geometry (group 0..60 x 0..20 with a 1 px border and three cells; shell-in-group): every path lies on the owner's lines, hover and focus close on the shared coordinates.
- Diagram nodes: the outline rule now also names `.react-flow__node:focus-visible`, so a node shows no browser outline even before a compositor root exists. `DiagramSkeleton` (used by Canvas/DiagramSkeletonDefault and Skeletons/Diagram) renders its own React Flow, so each of its few nodes gets the box props through `domAttributes`; the owned Diagram boxes only the keyboard-focused node.
