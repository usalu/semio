# Staffage overview lifecycle audit

Source inspection only; no browser profile was run, so these are mechanisms and hypotheses rather than measured attribution.

- Root overview passes a desktop lifecycle budget of five to Level (staffage overview/🟦️.tsx:343). Level passes it to LayeredOverview and wraps every page render (levels/🟦️.tsx:118,155). The budget counts live panes in one overview, not figures or recursively nested levels. Root pages can mount nested overviews, each with an independent budget. The closed-state card preview bound therefore does not bound the live page tree.
- Strip mode enables the lifecycle warm queue (LayeredOverview/🔶️panes/🟦️.tsx:34); its effect boots unbooted panes until budget (🧵️pane/🟦️.tsx:88–95). Defaults are 1.5 seconds before the first warm and 35 seconds thereafter, with all time-based suspension thresholds infinite (layered-overview-geometry/🟦️.ts:379). This is a concrete source of late work and retained live trees; it does not establish the measured duration of a stall. Narrow remedy: prevent closed root or background nested levels from automatically warming full pages, and mount the requested page on reveal/open; preserve gesture and keyboard behavior. Alternatively explicitly bound warm policy at the owning level rather than changing unrelated consumers.
- PlacedFigure paint always runs synchronously in useLayoutEffect after every component render, including first mount, before driver visibility can be determined (staffage placed/🟦️.tsx:118–128). Each paint calls evaluateState, sceneOf and inlineSvg (lines 72–81). The visibility observer in clock/🏁️frames/🟦️.ts:23–28 initially marks entries visible and receives asynchronous intersection results; later ticks loop all visible animated entries (55–57). Thus it cannot prevent initial layout-effect work and viewport intersection alone does not know whether a pane is obscured by overview glass. Narrow remedy: only instantiate heavy page drawings for an opened or explicitly revealed pane, and avoid repaint on unrelated React renders by tracking actual drawing inputs. Preserve first visible paint and current-time catch-up.
- Overview category previews schedule category loads on staggered timers (overview/🟦️.tsx:128–132); resolving loaded rows can trigger more figure mounts and layout work after startup. Validate with marks around category resolution, pane warm, figure paint and clock ticks before attributing late peaks. Test cold and settled desktop, nested closed and revealed states, navigation and reduced motion; assert bounded heavy mounts and no repeated paint from unrelated rerenders.
