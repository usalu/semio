- **The relay loop** (`refreshKitV1`) is covered by tests, but the relay process on this Mac runs the code it started with: it picks the loop up at its next restart. Until then the kit follows every new digest through the daemon hook (observed), and a companion that changes without a new digest (editing only a provision script) reaches the kit at the next digest or relay restart. Not restarted by me (no kill allowed).
- The store snapshot of a new digest is published by the daemon after ten healthy minutes; a machine that provisions in that window gets the newest intact earlier snapshot (the overlay says which digest it used), and that one may lack the five companions; a missing boot program is then reported with exit code 5 by step 6a. The kit itself is always current.
- Content of a sealed file is trusted as far as the seal is (hashes protect against damage and torn copies, not against someone who can write the store).
- A joined machine that was off for days and is re-provisioned is not overlaid (by design); there the guard (code 5) is the only protection.
- Not touched: `🚀️launcher/📥️install` and `🔩️native/🥾️bootstrap` scripts (run from the checkout on a fresh machine; they are not in any seal).

## What other packages must know
Anything that changes the seal's file list reads `sealCompanionsV1`; the digest is unchanged by companions. `authoredCodeV1` now counts companions too. A new provision-time command must live in the module's sources or imports (it then is sealed and in the kit automatically); a new non-imported file it needs must be added to `sealCompanionsV1`.
