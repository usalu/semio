## Decisions
- `manifest` is taken from the replica's `files` table (what the machine holds), not from the store fold.
- Settled = cursors equal every head AND incoming queue empty (stricter than the contract: a stuck apply shows as `lagging`, not as a manifest mismatch).
- `ok` needs at least one `ok` row; `missing` (head without attestation) is not ok; sync-off rows are `off` and excluded.
- Writes: change-driven at most once per second, heartbeat every 5 s (contract wording "at most every 5 s and whenever a value changes").
- Attester calls `ensureHome` before the first write so the relay can find a worker that never published.
- Providers: Linux `Restart=always`+`RestartSec=2` and macOS `KeepAlive true` already restart after exit 0 (verified in `workerPartsV1` and asserted). Windows was the gap (see above). Windows keeps the interactive logon on purpose: the NFS/SMB drive lives only in the logon session of the worker account, so `S4U`/`SYSTEM` would not see the store; documented in the README and the `workerServiceV1` docstring. `🔵️.ps1` needed no change (it registers the XML from `worker-service`); no PowerShell test changes because the XML is generated by TS and asserted there.
- `listOriginsV1` already ignores `._*` and `.DS_Store` (pattern needs `[a-z0-9]` first and a directory); now tested. Compaction only touches segments, snapshots, blobs and tmp; tested that `attest.json` survives.
