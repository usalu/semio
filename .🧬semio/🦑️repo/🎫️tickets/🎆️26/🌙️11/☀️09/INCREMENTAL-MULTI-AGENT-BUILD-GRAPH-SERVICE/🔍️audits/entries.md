# Lane entries: durable closure entries

## Built
- `BUILD/🕸️graph/📥️inference/🧭️script-inputs/💾️entries/🟨️.mjs` (+ `.d.mts`): durable store of closure entries. One memo node per recipe id (`ce/e/<sha256 id>.json.br`: recipe, value, observed rows, digest of the observed inputs), shared row layers as content-addressed nodes (`ce/l/<sha256 layer>.json.br`) loaded once through a bounded cache. A damaged, missing or foreign record answers undefined (costs one derivation). Disk bounded by `closureStoreMaximumEntries` / `closureStoreMaximumLayers` (oldest removed first, pruned once per process).
- `script-inputs/🟨️.mjs`: `produceClosureEntryV1` loads the stored entry first and vouches with the existing row-hold check (`closureEntryHoldsV1`, per-round shared); stale or absent entries are derived and saved. New exports `closureEntryCountsV1`, `closureStoreDirectoryV1`, `bindClosureStoreV1`. The in-process cache is now charged by the entry's stored size (`closureEntryCacheBytes` 96 MiB, `closureEntryCacheEntries` 8192, layer cache 32 MiB), all in `🧬️schema/🔣️.json` (EN+DE descriptions).
- Farm workers read the parent's store read-only (`closureStore` in the farm session, bound in `createProjectInferenceEnvironmentV1`); only the parent writes.
- Doubt stamps: not used directly. The entry rows are vouched with the same row-hold check owner records use; the generations doubt module is a settler-side component and was not wired into script-inputs.
