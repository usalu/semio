## Flow now

`repo run|run-many|exec|affected|watch|inputs ...` (door, `BUILD/📜️script.ts` `RepoScript.run` -> `BUILD/🧭️invocation/🏃️run`):
1. `invocationPlanRequestV1` (`🧭️invocation/🛰️plan`) resolves the public selection exactly as the executing process does (`resolveBuildInvocationV1`, `buildInvocationGraphSelectionV1`) and decides eligibility: help, native recovery, dashboard launches, nested pinned readers (`SEMIO_BUILD_REUSE_GRAPH`) and every other command do not ask the service.
2. `requestInvocationPlanV1` -> `requestPlanV1` (auto-start under the exclusive lock, progress lines in the user's language, cancellation by the invocation's signal, retries of lost connections). The service is spawned as `repo service host run`, keyed by the sealed door digest (`hostImplementationV1`), so a promoted implementation starts its own service and the old one retires.
3. The reply (`PlanReplyV1`: revision, `manifest`/`pin` when the revision hook is wired, tasks, `slice` CasRef) is consumed: `scopedPlanOfReplyV1` turns the tasks into a `ScopedPlanV1` (projects, tasks, edges, scope targets; a dependency outside the plan is refused; validated against the scoped-plan schema); the graph slice document `{graph,generationPin}` is read from the content-addressed spill and verified by size and sha256.
4. `runScheduledInvocationV1` (`🧭️invocation/🗓️schedule`) submits the job to the host-wide scheduler (`runScheduledV1`): key `<command head>#<args hash>@<generation digest>` (equal command over equal planned content dedupes across agents; an edit changes the generation pin and so the key), agent identity and weight from the agent session, estimate `jobEstimateV1(phase:compile, floor 512, learned peak)` from the host estimate store, queue position printed in EN/DE, cancellation by signal. `watch` plans through the service but is not queued (it never ends).
5. The job's work hands the verified slice to the executing process through `SEMIO_BUILD_PLAN_REPLY` ({path,hash,size}); `runTaskGraphV1` calls `takePlannedGraphV1` (re-verifies the digest, records the generation pin, `readBuildGraphV1`) instead of spawning a planner. Nested `repo` calls of a running job (`SEMIO_SCHEDULED_JOB`, also set by `repo scheduler run` for its command) run inside the job, never queue behind it.
6. Hard limits: the executing process still runs under the machine grant of `withBuildCapacityV1`, whose body receives the job-limits `limit` equal to the reservation; `repo scheduler run` runs through `runLimitedJobV1`.

Service side (`BUILD/⌨️command/🌐️host`, `repo service host start|status|stop|run`): the only process that plans. Slice loads run one at a time through `loadBuildInvocationGraphV1` (the same loader the old planner child used, under the service's own invocation and the resident custody `withRepositoryResidentWatcherV1`), the process runs pinned for its whole life (`useProcessWideImplementationPinV1` + `withImplementationPinV1`, confirmed to integration in requests), memory-bounded by the existing host policy (drop indexes, exit 75).

Removed: `loadBuildGraphInChildV1`, `buildGraphPlanInChildV1`, `writeBuildGraphPlanV1`, plan-file constants and branch (`SEMIO_BUILD_GRAPH_MEMO_DERIVE`), the `service` branch with warm pool / executor / per-worktree runner in `⌨️command/🧰️utility`, `forwardRepoCommandV1` use in `RepoScript.run`, per-worktree subcommands of `runResidentCommandV1`, tests of the removed child plan (`🧭️invocation/🧪️tests/{🧊️isolated-plan,📝️plan-file}`, `⌨️command/🧪️tests/🌱️plan-child`), the catalogue entries `service status|start|stop|restart|issue|revoke|drop-caches|probe` and the options `--foreground --classes --for --ttl` (replaced by `service host start|status|stop|run`; `--service` stays accepted and ignored because the incremental bench passes it).
