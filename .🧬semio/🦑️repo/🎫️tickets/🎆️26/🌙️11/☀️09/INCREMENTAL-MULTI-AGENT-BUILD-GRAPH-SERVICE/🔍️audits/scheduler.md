# Lane `scheduler`: fair global build scheduler

`SCHED` = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🏗️build/🗓️scheduler`. Status: protocol, dedupe, fairness, priority, admission, cancellation, progress, file-backed host queue and CLI are implemented and tested. Daemon, job-limits and fleet-status integration are open (see requests).

## Design
- `SCHED/🧬️schema/🔣️.json`: closed JSON Schema (draft-07) for `JobRequest`, `Estimate` (structural `JobEstimateV1`), `Event` (10 kinds), `Snapshot`, `Scenario`/`Corpus`, `Policy` (`SchedulerPolicyV1`) and EN+DE `Messages`.
- `SCHED/🟦️.ts`: pure event-sourced core (CQRS): `decideSubmitV1`, `decideTickV1` produce events, `applySchedulerEventV1` is the only mutation, `schedulerSnapshotV1` and `schedulerTicketStateV1` are read models. State is JSON (no Maps) so it snapshots and replays.
- Dedupe: a job is keyed by `request.key`; a second request with a live equal key becomes a watcher ticket on the same job (queued or running), raising its priority and depth; one start, one run, one exit for all tickets. The oldest live ticket is the runner; a runner loss ends the shared job with `runner-lost`.
- Priority: bands (`background < agent < interactive`) with aging (one band per `agingMs`, so no wait beyond bands x `agingMs`), then fairness, then depth (longest chain of dependents; shared crates first), then arrival.
- Fairness: weighted round robin by start tags (virtual time per owner agent, cost = reserved MB / `referenceMb`, weight from the agent session budget). Agents within `fairnessSlack` of the least tag compete on depth. Idle agents are pruned (bounded).
- Admission, preemption-free: reserve = max(learned peak, floor); start when sum of reserves <= host budget, `availableMb` headroom holds, `maxConcurrent`, `maxPerAgent` and shared compiler lanes (`rustc`, `tsc`) allow it. A blocked head older than `agingMs` drains the host (no backfill past it); a job larger than the budget runs alone (no deadlock). Nothing is ever stopped to make room.
- Liveness: heartbeats (every poll); silent tickets are `lost` after `heartbeatTimeoutMs`; deadlines expire queued jobs; cancelled runners get `stopping` and abort their work through an `AbortSignal`.
- Bounds: `maxQueued` (busy refusal), `maxAttached`, `maxFinished` ring, `maxAgents`, log compaction every `compactEveryEvents`.
- `SCHED/💾️store`: daemon-less host-wide store (`schedulerDirectoryV1`: platform cache dir `semio/scheduler`, override `SEMIO_SCHEDULER_DIRECTORY`): atomic `mkdir` lock with stale break, snapshot + NDJSON log with sequence numbers (crash-safe compaction, torn last line ignored), lock-free snapshot reads. Behind `SchedulerStoreV1`, so the daemon can host the same core.
- `SCHED/🎟️ticket`: `runScheduledV1(store, request, work, {signal,onQueued})`, the ticket protocol client (submit, wait with heartbeat, run as runner or watch, progress, cancel).
- `SCHED/⌨️command`: `repo scheduler status [--json]`, `cancel <ticket>`, `run [--key --priority --depth --class --lane --peak-mb] -- <command...>` (generic replacement of `build-slot.sh`; agent identity, workspace and weight from the agent session).
