# Lane `journal`: watcher-journal-driven invalidation

`BUILD` = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🏗️build`, `H` = `BUILD/🏡️resident/🕰️graph-hooks`.

## What changed

- The graph generation host no longer asks a resident service. `BUILD/🕸️graph/🕰️host/🟦️.ts` builds `journalGraphSeamsV1` over `directJournalPortV1` (reads the change journal of the workspace through `connectChangeJournalV1`, which starts the detached journal service on demand) and a file cursor store in the journal directory. `residentGraphSeamsV1`, `membershipFromJournalV1`, `dirtyPathsFromJournalV1`, `createResidentHoldsV1` and the `forwardCommandV1` path are deleted.
- Membership: `advanceFrontierByDirtySetV1` (`H/🟨️.mjs`) advances the previous frontier from a `DirtySetV1` alone. A one-file edit costs 2 stat calls and no directory listing; added/removed/renamed directories are dropped and walked again; untouched entries are never read. Output equals a full walk, `diffFrontiersV1` and an independent Python walker.
- Fact checks: rows are trusted unless the dirty set names the row's workspace-relative path, the path lies outside the workspace, the journal excludes the path, or the row kind is not path addressed. Doubtful rows go to the unchanged stat checker.
- Verify epoch (no silent fallback): when there is no verified cursor for the generation (`unrecorded`), or the journal refuses (`lost`, `epoch`, `no-service`, `untrusted`, `overflow`, `disabled`, ...), or the advance cannot be explained (`outside`), exactly one announced scan runs (the unchanged stat code with its signal), with an EN/DE notice on stderr, and the cursor taken before the scan is committed afterwards so the journal is trusted again.
- Cursor persistence: `frontier-cursors.json` in the journal directory, key `generation:membershipDigest`, 32 entries, atomic rename, torn or foreign files cost one verify epoch.
- Schema: `H/🧬️schema/🔣️.json` (`JournalCursorV1`, `DirtySetV1`, `JournalQueryV1`, `JournalReplyV1`, `JournalOpenV1`, notice texts EN/DE, policy).

## Two defects of the old path, fixed

1. Fact row paths in the index are absolute (`/home/.../x.ts`, `/`, JSON keys for `resolve`, digests for `derived`), but the old seam compared them with workspace-relative dirty paths, so it trusted every row. Now paths are mapped with `relativeFactPathV1` and only path-addressed kinds (`file exists stat lstat fileExists directoryExists readdir readdirNames typescriptText analysis`) can be trusted.
2. The old seam adopted the new journal cursor at membership time, so the next fact check saw an empty dirty set and a content edit with an unchanged mode and member list was lost. The dirty set is now pinned from the last verified cursor, and the cursor moves only in `commit` (called from `sealed`) after a full-coverage load (a scoped load never moves it).

## Second round: unification, multi-root watcher, pathless rows

- One journal per host. The Nx-daemon membership journal no longer runs a watcher of its own: `CACHING/🕸️graph/🏁️startup/🚦️service/👁️workspace` `createRepositoryWorkspaceWatcherV1(root, policy, binary, control, ports)` (fence argument removed) reads the host change journal (delivery by polling the log every 200 ms, flush is a fenced `since`, loss or refusal is terminal). Sealing semantics are a consumer policy: `requireJournalCoversSourceV1` refuses when the journal never reports a region the Source policy observes (the real Source policy of this repository is tested to cover `RESIDENT_EXCLUDES_V1`; `bazel-*` symlinks are declared blind in the schema). Opaque and Source-excluded paths are filtered consumer-side. The sealing worker's own `semio-repo-watch` process, private fence directory, `createSupervisor` port and its tests are gone; the vendor-Nx patch test now drives the adapter against the real host journal (`workspace delivery follows the closed directory policy through the host journal`). Consequence: native registration is no longer pruned per consumer (the journal registers everything outside its own exclusions).
- Multi-root watcher. `semio-repo-watch serve` (Rust, `🦀️rust/🦀️.rs`, pin updated) opens and closes roots on stdin (`open <tag> <root> <latency> <exclusionVersion> <rooted> <names> <hex> <fence> <since> <uuid>` / `close <tag>`), one thread per root, every frame tagged `"r"`, overflow state and closed-state per root, a failing root answers an `error` frame and a `closed` frame and does not end the process, inotify stops and releases its watches on `close` (macOS and Windows backends stop receiving frames only: their native handles live until the process ends). `JournalOpenV1` is the contract of `open`.
- Hub: `BUILD/🏡️resident/🔭️watch/🌐️hub` gives each `createWatchSupervisorV1` a process-shaped handle (`spawnProcess: hub.spawnProcess`), restarts the single process when it dies (every supervisor then recovers by its own replay/lost path).
- Host: `BUILD/🏡️resident/📜️journal` `runChangeJournalHostV1` is the detached process for all workspaces of the user (lock, heartbeat, request files, up to 64 workspaces, quiet-period shutdown); `startChangeJournalServiceV1` writes a request and starts the host only when none is live. `runChangeJournalServiceV1` is unchanged per workspace.
- Pathless rows: `realpath*` kinds are vouched by path; `resolve` rows with an absolute workspace specifier are vouched when the dirty set misses specifier, its directory and the result; `derivedDirtySetV1` hands the dirty set to the derived DAG. Correction of the first report: `closure` rows (53k of 681k) are never checked by the host, the always-checked set is about 35k rows (`bare resolve`, `derived` 6.7k, `registry`, `stamp`, `directories`), the `derived` ones go away with the derived-dag cut-over (request filed).

## Not done, and why

- macOS and Windows backends of the multi-root watcher are edited (tag propagation into the FSEvents callback and restart, tag-aware `fail`, no per-root stdin guard) but could not be compiled or run here (only the Linux toolchain exists); the Linux backend, the protocol and the hub are tested. `repo tools setup` on those hosts compiles them; a CI run on macOS and Windows is required before relying on `close` there.
- Dead options of the old private watcher (`privateFence`, `failureMode`, `startupControl`, `opaqueBasenames` in `🔭️watch`, Rust flags, tests) are not removed: they are shared with composition and several resident tests owned by `daemon` (request filed).
- `.cache/b/t/m/repo-watch/007311fca68018b2/semio-repo-watch` was built from the pinned source with `rustc -O` into the content-addressed directory because provisioning needs a mounted output root; other checkouts use `repo tools setup`.
- Source-text tests `resident cold publication ...` and `repository resident composition ...` (`🧪️tests/🏗️provision`) fail on text of files changed by other lanes, not by this one.
- Residual risks: a symlink target outside the watched tree is invisible to the watcher; sealing now depends on the journal host being startable (a host that cannot vouch makes the Nx observation fail closed, as the old private watcher did).

## Third round: finishing items and the live regression

- Dead options removed: `privateFence`, `failureMode`, `startupControl`, `opaqueBasenames` (watch supervisor, resident service, listing, state filter, composition, `repo service` wiring), the `🎟️startup` module, Rust `--private-fence-directory` / `--exclude-hex-basename` (pin `3c3435d32d55ecac`, open line has 9 fields), and the tests that only served them. The provision text test now reads `⌨️command/🧰️utility/🟦️.ts`.
- Live regression (generation 325 re-verified on every planner): cursors were committed only at `sealed`, after the closure settle that planners did not survive, and keyed by generation plus digest. Now keyed by generation, inherited from the base generation (one hop) and by scoped loads, and a full verify epoch commits as soon as the fact phase ends (`factsVerified`, driven by the `facts` phase clock) with a carry of owed paths (membership changes and failed rows, bounded to 20000) that stays doubtful until a sealed load clears it.
- Epoch membership scan progress: phase `membership` ("Verifying workspace membership" / "Arbeitsbereich-Zugehörigkeit prüfen") added to the process progress schema, counted per stat call of the frontier scan.
- Daemon startup test: `openNxDaemonWorkspaceWatcherV1` is the extracted body of the service's `workspace()`; `🚦️service/🧪️tests/🔭️startup-journal` runs it against the real host journal (policy, pinned binary path, delivery, single watcher child, cancellation). The full service child process test (`🚦️service/🧪️tests/🟦️.ts`) needs the build-test harness and cannot run under plain `bun test`; its funding wrapper (`withRequestedIssuedResourceControlV1`) is therefore not covered by the new test.
- Bare-specifier `resolve` rows: the install fingerprint is the real path `node_modules` points to (the install root, written only by `repo dependencies sync/lock`) plus the sha256 of `bun.lock`; it is stored with the cursor. With an unchanged fingerprint, rows under `node_modules` or `.cache/b/d/m/j/`, and bare resolutions whose result lies there, are vouched; a changed or missing fingerprint, a dirty `package.json`/`tsconfig.json`/`jsconfig.json` of an ancestor of the importer or result, or a dirty workspace result makes them doubtful.
