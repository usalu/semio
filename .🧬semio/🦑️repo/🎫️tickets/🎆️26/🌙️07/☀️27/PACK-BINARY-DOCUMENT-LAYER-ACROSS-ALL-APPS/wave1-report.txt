2. FINAL `DocumentPack` TRAIT SHAPE (vcs/rs/lib.rs, `//#region 🔖️Pack`)
--------------------------------------------------------------------------------

pub trait DocumentPack: Sized {
    fn encode_pack_with(&self, options: &PackEncodeOptions) -> Result<Vec<u8>, PackError>;
    fn decode_pack_with(bytes: &[u8], options: &PackDecodeOptions) -> Result<Self, PackError>;

    fn encode_pack(&self) -> Vec<u8> {
        self.encode_pack_with(&PackEncodeOptions::default()).expect("default-options pack encode is infallible")
    }
    fn decode_pack(bytes: &[u8]) -> Result<Self, PackError> {
        Self::decode_pack_with(bytes, &PackDecodeOptions::default())
    }
}

Required methods: `encode_pack_with`/`decode_pack_with`. `encode_pack`/`decode_pack` are provided
defaults over `Pack{Encode,Decode}Options::default()`.

`PackEncodeOptions`/`PackDecodeOptions`/`PackVerificationLevel`/`PackError` are `vcs`'s renamed
re-exports of `pack::{EncodeOptions, DecodeOptions, VerificationLevel, PackError}` — always spelled
`vcs::PackEncodeOptions` etc., never the bare `pack::EncodeOptions` names, repo-wide.

`DocumentPackFiles`:
    pub struct DocumentPackFiles { pub pack: Vec<u8>, pub ops: String }

LAW (doc-commented on the trait): `P::decode_pack(&p.encode_pack())` recovers an equal `p`, AND
`decode_pack(encode_pack(p)) == parse_dsl(print_dsl(p))` — dsl and pack are two encodings of the
identical `(RecordSpec, RecordValue)` pair keyed by the same stable `u16` field ids `dsl_derive`
assigns.

IMPORTANT DEVIATION: there is NO `impl From<TextError> for PackError`. That impl is IMPOSSIBLE
(orphan-rule violation — both `TextError` and `PackError` are re-exports of foreign crates through
`vcs`, neither is local). Use the free function instead:
    pub fn text_error_to_pack_error(error: TextError) -> PackError
`dsl_derive`'s generated `decode_pack_with` calls `.map_err(::vcs::text_error_to_pack_error)`, NOT
`.map_err(::vcs::PackError::from)`. Any wave-2/wave-3 code that needs this conversion must use the
same free function.

Derive-emitted impl shape (dsl/derive/rs/lib.rs, `derive_dsl_document`) — what every
`#[derive(dsl::DslDocument)]` type automatically gets:

    impl ::vcs::DocumentPack for #name {
        fn encode_pack_with(&self, options: &::vcs::PackEncodeOptions) -> Result<Vec<u8>, ::vcs::PackError> {
            ::vcs::pack_rt::encode_document(&Self::__dsl_spec(), &self.__dsl_to_record(), options)
        }
        fn decode_pack_with(bytes: &[u8], options: &::vcs::PackDecodeOptions) -> Result<Self, ::vcs::PackError> {
            let (record, _report) = ::vcs::pack_rt::decode_document(bytes, &Self::__dsl_spec(), options)?;
            Self::__dsl_from_record(&record).map_err(::vcs::text_error_to_pack_error)
        }
    }

vcs/rs/lib.rs (`//#region 🔖️CodecRegistry`):

    #[derive(Clone)]
    pub struct DocumentCodec {
        pub schema: String,
        pub extension: &'static str,
        pub print: fn(&str) -> Result<(DocumentPackFiles, String), VcsError>,     // envelope_json -> (pack_files, dsl_mirror)
        pub parse: fn(&[u8], &str) -> Result<String, VcsError>,                    // (pack_bytes, ops) -> envelope_json
        pub parse_dsl: fn(&str, &str) -> Result<String, VcsError>,                 // (dsl_text, ops) -> envelope_json
    }

    impl DocumentCodec {
        pub fn of<P, Operation>(schema: impl Into<String>) -> Self
        where
            P: Clone + PartialEq + Serialize + DeserializeOwned + DocumentDsl + DocumentPack + Send + 'static,
            Operation: crate::Operation<P> + PartialEq + Serialize + DeserializeOwned + OpText + Send + 'static,
        { ... }
    }

    pub fn register_document_codec(codec: DocumentCodec);       // idempotent upsert by codec.schema
    pub fn document_codec(schema: &str) -> Option<DocumentCodec>; // clone out

framework/plugin/rs/lib.rs (`pub mod plugin_runtime`):

    pub fn register_document_codec_for_app<A: DocumentApp>(schema: impl Into<String>) {
        vcs::register_document_codec(vcs::DocumentCodec::of::<A::Projection, A::Operation>(schema));
    }

Wave-2 usage: one call per document kind, in the app's own native registration fn (pattern:
`register_draw_exports()`-style), e.g. `register_document_codec_for_app::<NoteApp>("note/v1")`.

Empirically confirmed (not just reasoned about): `DocumentApp::Operation`'s trait-level bound
(`::vcs::Operation<Self::Projection> + PartialEq + Send + vcs::OpText`, no `Serialize`/
`DeserializeOwned`/`'static` of its own) is nonetheless sufficient to satisfy `DocumentCodec::of`'s
stricter bounds when called generically as `A::Projection`/`A::Operation` inside
`register_document_codec_for_app` — `cargo check -p semio-framework-plugin` is clean. (Likely because
`VcsDocumentApp<A>`'s own `store: DocumentVcsStore<A::Projection, A::Operation>` field already forces
any real `A: DocumentApp` impl's concrete `Operation` type to satisfy those bounds structurally.)

5. SCOPE DEVIATIONS WAVE-2 AGENTS MUST KNOW ABOUT
--------------------------------------------------------------------------------

(a) `impl DocumentDsl for serde_json::Value` does not exist anywhere in the repo right now (confirmed
    by grep — a pre-existing gap/concurrent-churn artifact, not something I broke or fixed). My
    `impl DocumentPack for serde_json::Value` (vcs/rs/lib.rs, `🔖️Pack` region) therefore does NOT sit
    beside a `DocumentDsl` sibling. Whoever lands the missing `DocumentDsl` impl should place it beside
    this one for symmetry.

(b) `framework/product/os/core/rs/lib.rs` has NO command dispatcher of its own (no `OsCommand` enum, no
    `handle_command`/`handle_action` override anywhere in that file) and NEVER constructs
    `semio_framework_core::kernel::HostEffect` (confirmed by grep). All actual `HostEffect::
    DownloadMediaExport`/`RequestFileOpen` command wiring lives in `s/plugin/rs/lib.rs`'s
    `StudioApp`/`HomeApp::handle_action` — wave-2 "s+shome+sstudio" family territory, NOT wave 1's file
    list. Also: `PluginApp::document_pack()`/`load_document_pack()` (added in step 3) have ZERO call
    sites anywhere in the repo — os/core never holds a live `Box<dyn PluginApp>` for "the active app
    instance"; that concept doesn't exist in this crate.
    CONSEQUENCE: the brief's literal `exportDocumentPack`/`exportDocumentDsl`/`importDocumentPack`/
    `importDocumentPackPayload` "commands" were NOT added as such. Instead, os/core got three
    data-returning primitives (`export_os_studio_pack`, `export_os_studio_dsl`,
    `import_os_studio_from_pack` — signatures in §1) mirroring the established
    `export_os_app_instance_media`-style layering (os/core returns data, the app-plugin crate wraps it
    into `HostEffect`s). WAVE-2 TODO for `s/plugin/rs/lib.rs`: add three `StudioApp::handle_action` arms
    mirroring `exportMedia`/`importMedia`/`importMediaPayload` (lines ~2471-2545 there) verbatim in
    shape, calling `semio_framework_os::export_os_studio_pack`/`export_os_studio_dsl`/
    `import_os_studio_from_pack` instead, base64-encoding via the already-available `base64::Engine` +
    `base64::engine::general_purpose::STANDARD` pattern (no new dependency needed — `base64 = "0.22.1"`
    is already a dependency of both `framework/product/os/core` and `framework/renderer/wgpu`), two
    `DownloadMediaExport` effects (`.pack` base64 + `.ops` plain text) + one `RequestFileOpen` +
    `importDocumentPackPayload`-style decode arm. No new `HostEffect` variant needed.

(c) The studio hidden `<input>` in `framework/renderer/react/index.tsx` now accepts `.pack` in its file
    picker, but its `onChange` still always reads the file as text and dispatches `"importStudio"`.
    Picking a `.pack` file today is a safe no-op (text-decode garbage -> JSON parse fails -> `s/plugin`'s
    existing `importStudio` arm swallows the error), not silent corruption — but it isn't actually wired
    to import packs yet. WAVE-2 TODO: once `s/plugin` has a pack-aware import action (see (b)), extend
    this `onChange` to branch on `file.name.endsWith(".pack")` and read as a dataUrl instead of text.
