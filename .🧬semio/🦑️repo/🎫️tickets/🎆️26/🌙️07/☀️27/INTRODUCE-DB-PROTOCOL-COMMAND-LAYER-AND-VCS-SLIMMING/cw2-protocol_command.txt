Deviations from / choices within the contract (all "your choice" seams, documented inline too)
-------------------------------------------------------------------------------------------------
1. OperationDescriptor::fingerprint computation: the contract only fixes the struct's field shapes
   ("blake3 over the descriptor's canonical bytes"), not the encoding. Chose canonical-JSON
   (serde_json::to_vec over a private Canonical{id, schema_version, state_class, conflict_rule}
   struct) hashed with blake3. Added OperationDescriptor::new(...) as the one constructor that
   computes it, since the contract shows only the struct + registry fns, no constructor. Pinned
   with a golden hex test (fingerprint of SchemaId("note.append")/SchemaVersion(1)/Persistent/
   Merge(TextSequence) == 8c6c0b22512540811343d8caa8d147f48e936728105861c4360bb202f626d517).
2. OperationDescriptor derives only Clone/Debug/PartialEq (contract shows the struct with no derive
   attribute at all) — Clone is required for the registry's get().cloned() lookup pattern that
   mirrors vcs::CodecRegistry exactly.
3. Patchable<TPatch>'s diff_patch(&self, other: &Self) -> Option<TPatch> direction: chosen to mean
   "the patch that turns self into other" (consistent with Operation::diff(&self, base)'s "self
   relative to an argument" convention). invert_collection_operation composes
   after.diff_patch(&prior) to recover the same inverse-patch behavior vcs's single-method
   apply_patch used to return directly. Documented inline at the trait definition.
4. CollectionOperation/ReconcileReport/OperationMeta/Edit/etc. use exactly the derives the contract
   lists literally (no added Eq beyond what vcs's originals had for CollectionDiff/ItemPatch, which
   the contract says are "identical to vcs's today").
5. No apply_operation/absorb_diff free functions were added — the amendment's protocol_command
   block does not list them (they existed in vcs's original 🔖️Operation region but are superseded
   by direct diff()/apply() calls); omitted to avoid adding API surface the frozen contract doesn't
   specify.
6. Cargo.toml was NOT touched — the pre-existing one already matched the contract's dependency list
   (protocol_core, dsl_core, serde, serde_json, blake3) exactly.
