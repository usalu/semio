protocol_materialize — wave CW2 implementation report
=======================================================

Scope
-----
Replaced the stub `protocol/materialize/rs/lib.rs` with a full implementation of the frozen
`## protocol_materialize` contract section
(`.repo/🎫️/26/07/27/PROTOCOL-BINARY-OP-LOG-LAYER/contract.md`). The amendment section of that
contract (identifier/HLC/policy additions to protocol_core, and the new protocol_command/
protocol_causal/protocol_crdt/protocol_wire crates) does not touch protocol_materialize at all, so
no amendment-driven changes were needed here.

Implemented against the ACTUAL sibling crates already merged into the tree (protocol_core,
protocol_format, protocol_history — all written by other wave-CW2 agents), not just the contract
prose, since several of their concrete signatures (e.g. `RecordFrame::payload()`/`frame_len()`,
`IndexReader::{checkpoint_offset, latest_projection_offset_at_or_before}`,
`protocol_history::decode_edit` being `pub`) determine exactly how this crate has to be wired.

Regions implemented (matching the contract's region names exactly):
- 🔖️Projection — `ProjectionBodyKind`, `ProjectionRecord`, `encode_projection`/`decode_projection`,
  plus a private zero-copy `parse_projection` (returns header fields + a body byte-span rather than
  an owned Vec) that both `decode_projection` and `resolve_plan` share.
- 🔖️Policy — `CheckpointPolicy` + `Default` exactly as specified, plus two small helper methods
  (`should_checkpoint`, `should_embed`) since the contract defines only the struct/Default and
  leaves it otherwise inert; added to make the type actually usable by a future writer.
- 🔖️Plan — `BaseBytes`, `BaseProjection`, `MaterializePlan`, `MaterializeTarget`, `resolve_plan`.
- 🔖️Drive — `MaterializeReport`, `materialize_with`.

Deviations / design choices (all "your choice" per the contract, documented inline where decided)
----------------------------------------------------------------------------------------------
1. Cargo.toml: added `pack_core = { path = "../../../pack/core/rs" }` as a direct dependency — the
   stub Cargo.toml only listed protocol_core/protocol_format/protocol_history, but this crate needs
   `pack_core::{ByteReader, ByteWriter}` directly for its own hand-rolled `REC_PROJECTION` codec
   (the contract's `encode_projection`/`decode_projection` signatures take no `DictBuilder`/
   `DictReader` parameter, unlike protocol_history's per-kind codecs, so they can't route through
   protocol_core::scalar's dict-integrated `write_id`/`read_id` — a self-contained raw-string
   encoding for the optional checkpoint-id anchor was the only fit).
2. `MaterializePlan` carries one extra `pub(crate) skipped_corrupt: u32` field beyond the three the
   contract lists. `MaterializeReport::snapshots_skipped_corrupt` needs a value that only
   `resolve_plan`'s own corrupt-projection retry loop knows, and the frozen public field list gives
   no other way to carry it forward to `materialize_with`. Never `pub`, and no other crate names
   `MaterializePlan`'s fields by literal (the facade re-exports the type but not a public
   constructor), so this is additive rather than a violation of the frozen shape.
3. `MaterializeReport::snapshot_used`'s inner `Option<String>` (the anchor checkpoint id) is always
   `None` in this implementation — `MaterializePlan`'s frozen shape never threads the checkpoint id
   from `resolve_plan` through to `materialize_with`, so there is nowhere to source it from. Field
   shape kept exactly as specified; documented at the field with a `@emoji` doc comment.
4. `REC_STR_DICT` payload parsing (`apply_dict_record`) is a small, deliberate duplication of
   protocol_history's private `flush_dict_delta`/`apply_dict_record` wire format (format u8=1,
   base_count varint, count varint, count x (len varint + utf8)) — that function is private to
   protocol_history, and `materialize_with` must reconstruct dictionary + edit-id state for any
   REC_EDIT frames it decodes via the (public) `protocol_history::decode_edit`, both for the tail
   range and for a prescan covering everything before `tail_start_offset` (dictrefs/edit-ordinal
   references inside a tail edit can point at entries introduced anywhere earlier in the file,
   including inside the base projection's own coverage).
5. `MaterializeTarget::LatestOnActive` resolves to `target_edit_ordinal: None` (no cap — replay
   through the whole trusted tail). `HistoryLog::edits` is one flat, shared log in the actual
   protocol_history model (alternatives reference checkpoints, not forked edit sequences), so
   "latest on the active alternative" and "latest, full stop" are the same operation here.
6. `resolve_plan`'s corrupt-projection fallback tries the advisory `REC_INDEX` (via
   `IndexReader::latest_projection_offset_at_or_before`/`checkpoint_offset`) first, retrying at a
   strictly older ordinal cap on a CRC/hash/kind mismatch; if the index is absent, stale, or
   exhausted, falls back to a `ReverseFrameCursor` scan for `REC_PROJECTION` frames directly. Body
   hash (blake3 via `protocol_format::Blake3Hasher`) is always verified for embedded bodies before a
   candidate is accepted; `SidecarPack` bodies are accepted unverified here (their bytes live outside
   the `.spr` file — `protocol_io::read_sidecar` is the actual verification point, out of this
   crate's scope per the amendment's hard dependency rule: protocol_materialize doesn't depend on
   protocol_io).
7. `AtCheckpoint` ordinal resolution: index lookup first; fallback does a full
   `protocol_history::decode_history` and walks `checkpoint.change_ids -> change.edit_ids -> max
   position in log.edits` (0-based, matching `encode_history`'s own ordinal assignment via
   `.enumerate()`), since `HistoryCheckpoint` carries no direct edit-ordinal field.
8. `materialize_with` re-derives its own trusted byte range via `protocol_format::recover` using
   `ProtocolLimits::default()` (the frozen signature has no `limits` parameter) so a torn/in-progress
   live tail is silently excluded from replay rather than surfacing as an error — consistent with how
   every other reader in this crate family treats the recovery boundary.
9. Untrusted-count allocations (dict entry count, in `apply_dict_record`) never
   `Vec::with_capacity(count)` directly from an attacker/corruption-controlled varint; entries are
   pushed into a `Vec::new()` instead so a huge bogus count can't force a large allocation before the
   bounds-checked reads underneath would fail it anyway.

Tests (inline `//#region 🧪️Tests`, plain `#[test]` fns — no quick/long/exhaustive split needed, none
of these are slow or exhaustive-only)
--------------------------------------------------------------------------------------------------
- Projection round trips: embedded-with-checkpoint-anchor, embedded-dsl-with-ordinal-only-anchor,
  sidecar-without-body, and a corrupt-format rejection case.
- `resolve_plan` + `materialize_with` integration, against a hand-assembled `.spr` stream built
  directly with `protocol_format::SprWriter` + `protocol_history::encode_doc/encode_edit` (mirroring
  `encode_history`'s own dict-flush pattern) with a `REC_PROJECTION` frame embedded mid-stream:
  - picks the projection and replays only the tail past it (`LatestOnActive`);
  - falls back to `initial_pack` genesis when the target ordinal precedes every projection
    (`AtEditOrdinal(0)`);
  - replays the full tail when the target ordinal is past the last projection
    (`AtEditOrdinal(3)`);
  - `AtCheckpoint` resolution via the full-decode fallback (no `REC_INDEX` present) against a
    hand-built `HistoryLog` with a checkpoint/change/edit chain;
  - a corrupt projection (body_hash deliberately mismatched) is skipped and the plan falls back to
    `initial_pack`, with `skipped_corrupt == 1`.
- `CheckpointPolicy` default values and `should_checkpoint`/`should_embed` threshold behavior.

11 tests total, all passing.
