          ...

      }

  Move{id,to_index} — grep-confirmed at core lib.rs:338-352, 647-870, no `protocol::` import
  anywhere in that file).

Because `ImperativeOperation.collection`'s type is fixed by imperative_core to
`vcs::CollectionOperation<String, Step, Dictionary>` (the OLD shape), imperative_plugin's four
call sites are not independently migratable: rewriting them to construct
`protocol::CollectionOperation::Add { id, item, at }` etc. would not type-check against that
field — it's a different enum shape entirely (protocol's Add has a mandatory extra `id` field
that vcs's Add doesn't have room for). This isn't imperative_plugin's own generic-shape choice to
make; it inherits imperative_core's shape verbatim by using imperative_core's own operation type.
