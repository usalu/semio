### Root cause found (framework, shared with the browser stall)
Command ingress for host actions (`🧰️framework/.../🔌️plugin/🧵️instance/📥️staging/📥️command-routes/.../actions/🦀️.rs`, `drive_original_host_configuration`) only called `prepare_original_tool_dispatch` while `source.original_tool_dispatch.is_none()`. The scrub `advance` sets that decision as an out-param BEFORE the scrub dispatch shell has been taken, so the shell (`tools.original_scrub_dispatch`, terminal-empty, unfrozen) was never taken again: `prepare` only takes it on re-entry (`owner.terminal_is_empty()` branch). It lingered forever: `shared_command_source_pending()` stays true (blocks every following command / resume) and `tool_overlay_retirement_pending` keeps `maintenance_terminal_is_empty` false; the live maintenance unit reports zero demand for an action-source shell ("waits for the foreground source"), so nothing could ever retire it -> idle loop -> WorkLimit in the harness; in the browser the same stale shell holds `command-pending` (trickle of 30-60 fuel/turn) until the host's 300 s cap.
Fix 1: that condition is now `is_none() || self.tools.original_scrub_dispatch.is_some()` so the shell is taken before the producer proceeds.
Fix 2: `tools.original_emission_construction` (OriginalConstructionAdmission) kept its `binding` after the receipt handoff; only the CLOSE ladder closed it, while live maintenance reported AwaitingPublication (zero demand). New `MaintenanceTool::CloseEmissionConstruction` in `🪜️maintenance-ladder/🦀️.rs` (selection when no admission/receipt/operation is in flight, demand = `close_demand()`, stage-0 step = `close_step`).

## ARCHIVE LOAD FIXED
Root cause (confirmed natively): the record member open's `Receive` step demanded one indivisible 277,538 B copy (top-level receiver seed, struct records have no seed template) but the receiving scope only offered the automatic half-share (`div_ceil(2)`); every futile attempt still paid scope fees from the pinned Source stock until the stock was gone.
Fix (single mechanism): `StepContext::with_native_receiving_work(out, floor, op)` now takes the next indivisible demand as a floor; `covering_receiving_quote` raises the scope share to cover it, never above the whole turn; a floor the turn cannot afford is refused at no cost (`OriginalReturnScopePlan::quote`). All 10 callers updated (callers with no indivisible action pass `Default::default()`); the record step passes `receiver.demands(..)` (`store/composition/open/operation/record`). The three earlier widening attempts (ladder `covering_loan`, record-step widening, pin relaxation) and all `[DEBUG]` prints are removed.
Policy: `MountedOwnerPolicyV1::INTERACTIVE_COMPONENT` copy grant = `covering_copy_bytes(LARGEST_INDIVISIBLE_STEP_COPY_BYTES)`; the constant is the measured largest unit quote (377,696 B member open) -> 512 KiB; the whole turn must be at least that for the floor to fund these steps.
Result: `every_example_loads_through_the_member_less_archive_door` settles the first two examples (71 in 8,846 turns, 72 in 3,033). The third (large demonstrator) is progressing but only ~1 byte per maintenance call (each decoded byte posts one retained item), so it needs millions of turns and exceeds the 1,000,000-turn bound: a separate throughput defect in `OriginalRecordMemberSnapshotOpen::parse_step`/flow decoder (batch many bytes per item). Not fixed. Not done from the review list: seed template for struct derive (3), per-plugin tests hard-coding 32 KiB (they are local work parameters, unrelated to `INTERACTIVE_COMPONENT`), a record-law test for the floor.

## BYTE BATCHING DONE
All of the following is **uncompiled and untested**. No cargo or bun run happened, so the wasm build agent must compile it.
- Byte batching: `RetainedRecordReceiving::step` is now a thin wrapper over a private `act`, which is the old single action with `ValueError` errors. The new `advance(source, native, effect, units)` repeats `act` under `effect.nested_within(remaining grant, remaining units)`. It subtracts each action's copy, capacity and release from the shared grant. It stops when the record completes, when an action is unfunded (it returns default progress), when the native checkpoint refuses, or when the remaining Work drops below `ACTION_WORK_CEILING` (64). The whole batch reports one retained item. On error it carries the summed progress. The record `parse_step` now calls `advance` with the scope's offered grant and units, and passes the parser's next `demands` as the receiving floor. The same code path covers both the Body and the Document (flow) driver. Envelope bytes are still one per turn, but that is a fixed prefix.
- Struct-derive seed template: `NativeReceive::receiver_template(subset)` is now emitted for derived structs. It is a `NativeSeedTemplate::fields` plan with 19 fixed parts plus 2 per field (slot, pending) and 1 per defaulted field. `write_seed_field::<SUBSET>` seeds `subset`, so the template matches `receiver()` and `record_subset_receiver()`. A large struct receiver is therefore seeded in field-sized parts.
- Laws:
  - Record batching: `a_large_original_drawing_settles_in_turns_proportional_to_its_size_over_the_grant` builds a 64 KiB Drawing title. It requires `turns <= base turns + 8 * ceil(size / min(copy/2, min(fuel/2, 1 MiB)/16))`. It cross-checks the opened snapshot against the `serde_json` decode of the same JSON.
  - Record floor: `a_receiver_between_one_and_two_half_shares_reaches_ready_without_draining_its_pinned_stock` uses a turn copy of 1.5 * `size_of::<Receiver>()` and draws its turns from a pinned stock.
  - Context floor: `a_receiving_floor_raises_the_half_share_up_to_the_whole_turn_and_refuses_beyond_it_at_no_charge` has three fixture cases. The first refused turn may still settle the previous scope's observation; later refused turns must charge nothing.
