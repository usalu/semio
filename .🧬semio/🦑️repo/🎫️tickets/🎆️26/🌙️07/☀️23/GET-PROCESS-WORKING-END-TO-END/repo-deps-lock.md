# Repo Dependencies Lock Recovery

## Root cause
1. `ClassifyWorkspaceNamespace` (launcher Go package `workspace-namespace`) follows the root `node_modules` link into its generation image and unconditionally reads `bindings.json`. An image directory without that receipt (half-built, unready) made `os.Lstat` fail, surfaced as `Unexpected error: lstat .../bindings.json: no such file or directory`, before the TypeScript owner could run. The TS producer already discards or resumes unready generations (`discardUnreadyJavascriptDependencyGenerationV1`, resumable logic), so the launcher was the only blocker.
2. Behind that, the lease image `.cache/b/l/fixed.dmg` (63 MiB APFS) was corrupt (`diskutil verifyVolume`: zeroed-out block in the fsroot tree). Creating the single name `metadata-headroom.bin` failed with ENOENT, so every `repo` command died with `Lease store sweep failed`.
3. The dependencies charge ledger (`.cache/b/d/m/storage-events.jsonl`, `dependencies.json`) still recorded 8179941376 bytes while the image is now 29 GB (uncommitted `needBytes` edit in the budget `policy.json`), giving `Original cache charge disagrees with global policy`.

## Fix
- Launcher: a managed link whose generation image has no ready receipt is classified `detached` (unready image, left untouched, owner rebuilds) instead of failing.
- Added fixture row `unready-image` to `launcher/.../fixtures/detached.json`, extended the `DetachedCase` schema enum, extended `TestWorkspaceDetached` (real unready image directory, link kept intact).
- Installed the new launcher via the documented installer (`launcher/install/sh`) to `~/.local/share/semio/launcher/bin/repo`. `~/.local/bin/repo` is the full native command (18 MB, built from `repo-client`) and was left unchanged (restored byte-identical after a trial); it still contains the old launcher code until the native command is rebuilt (`repo run @semio-tech/repo-client:build`).
- Environment repair (derived state only): ejected the corrupt lease image, removed its `fixed.dmg`, `image.json`, `boot-recovery`; the tool recreated it. Removed the stale charge receipt and ledger of the dependencies image so the charge is re-reserved at the real size.

## Results
- `go test -overlay ... -run TestWorkspace` in the launcher package: ok (new subtest `TestWorkspaceDetached/unready-image` passes). Run with an overlay from `canonicalGoPlan` (script `plan.ts` in the generated folder) because `repo` was unusable at that time.
- `repo dependencies ensure` (new launcher): exit 0; image `307631934f0e2b89ee1f` now has `bindings.json`.
- `repo dependencies lock --all`: exit 0 (first attempt failed with `Current exact relative path descriptor changed` while peers edited files; second passed).
- Note: the package `@semio-tech/process-js` lives in the sub-workspace `✏️s`, so the lock that records `ajv` is `✏️s/bun.lock`, not the root `bun.lock`. Root `bun.lock` is byte-identical to the backup `🗑️generated/bun.lock.before2`. `git diff HEAD -- ✏️s/bun.lock` is exactly one inserted line (`"ajv": "8.20.0",` in the process-js devDependencies).
- No plain `bun install` was run.
