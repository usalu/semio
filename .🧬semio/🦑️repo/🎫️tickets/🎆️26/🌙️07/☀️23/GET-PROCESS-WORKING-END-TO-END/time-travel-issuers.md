# Time-travel issuers, replay wire and revert frontier (tests-07-2 Open items 1 and 3)

## Causes and fixes
1. Report replay "original operation has no authored conflict path issuer" (`a_blocking_mutation_without_editable_inputs...`, `an_inverse_refusal_is_one_mutations_fatal...`): not a missing product wire. Production (`ArtifactApp::persisted_operation_wire` and `persisted_document_store_owners`) already carries the wire, and the tests-06 `TestApp` goes through it. The two laws build their own `InertLabelOp` document store by hand and installed `ArtifactOperationWire::canonical()` on the document and left the canonical wire on the catalog from `cold_replay_document_store_owners` (the catalog wire overrides the installed one). Fix (test fixture): `inert_wire()` (semantic, batch digest, persisted receiving, whole-document target) installed on the document and set as `catalog.operation_wire`; `InertLabelOp` now declares `artifact_persisted_encoded_binary_operation!` (its `OpBinary` bytes are the original encoding source, same as `TestMutation`). The next fault was "operation output payload extent exhausted" (the already documented catalog-overwrite cause), gone with the same change.
2. Inverse refusal faulted the whole Report replay ("children have no inverse under a count below -1") instead of being one Fatal `mutation.inverse-refused` outcome. Product cause: the native cold edit (`store/paged-one-item/cold-apply`, `ColdReplayEdit::advance`) propagated `ColdMutation::inverse` with `?`. It now records the Fatal `mutation.inverse-refused` message on that operation (`at_op`), stages no inverse rows and completes, so the operation folds forward, the replay goes on and the report blocks finalizing.
3. A replaced finished replay reached Drop untaken ("finished replay reached Drop while untaken outputs..."): `StartReplay` only marks the previous finished replay cancelled; it is retired by `CloseOriginalSources` turns. Fixture `replayed_report` now drives those turns after `StartReplay` (the product driver already does).
4. Open item 3, "native history original publication frontier changed" while settling `revertToCommand`: `advance_native_vcs_command` demanded the pre-publication frontier for every stage below 15, but stage 14 is `OriginalReplayPublication::publish`, which moves generation and revision on its first successful decision and may need further turns; the next turn then failed its own frontier check. The publication itself already checks the frontier only while `receipt.is_none()`. New `OriginalReplayPublication::owns_frontier()` (`store/history/replay`) and the command frame demands the frontier at stage 14 only while the publisher has no receipt (`store/history/command`).
5. Behind it: `ack_native_vcs_command` returned "acknowledgement requires its delivered original result" on the second call because the first call's `action` had already set `closing` and left the resident constructing. It settles the resident first (as `take_native_vcs_result` does). `revertToCommand` now settles.
6. `TimeTravelLedger.queued` (another agent) referenced `semio_framework_time_travel::SupersededInput`, which does not exist and broke the build of `semio-plugin-time-travel`; changed to `protocol::SupersededInput` (identical type the ledger uses elsewhere).

## Second round: replacement in the draft preview, grace instance
7. Draft preview replacement ("original history replacement requires its retained semantic input issuer"). The preview had no replacement owner, so any operation with a draft or supersession refused. The Report replay's replacement machinery moved into one shared module, `store/engine/derived-replay/replacement` (`Replaced` borrow view, `select_replacement`, `begin_replacement`, `advance_replacement`, `close_replacement`, `replacement_reset_demand`, the canonical wire verification and the replacement row access). `report-replay` now calls it (target capture stays Report-only, the withdrawn phase hands back to the Report so it keeps its prepared operation); `history-preview` calls the same functions, with `ArtifactDerivedHistoryPreview` carrying `replacement: ArtifactReplacementOwner` (read crate) and its own copy of the plan's effective supersessions. Preview retirement and its quote (`derived_history_preview_retirement_demands`) close and price the replacement owners the same way. The preview history plan now also copies the live supersessions (native phase 5 for non-Report plans, which skipped them). `step_derived_history_preview` takes the turn's `maximum_work` (time-travel store state passes the receiving work; store laws pass 64). A checkpoint preview with a live supersession keeps refusing.
8. "cold replay mutation could not produce its post root" (a draft in the prefix that cannot apply, such as an invalid children value): the native cold edit faulted the whole step. It is now one Fatal message on that operation and no post state (`Refused`), as the sync Report fold always did; a Merge replay rejects on the message.
9. Host-event routing law (`an_opened_instance_acts_as_its_admitted_actor...`): product rule stands; the law mounts a `grace` instance through `artifact_app_laws::new_registered_app`, `bind_actor` and `load_document` of the reverted pack, and the undo runs on it.
10. `a_stage_change_ships...`: `verb` pumps the draft preview after an accepted verb and so drained the UI progress frame the law asserts; the law now dispatches `historyEditBegin` directly.
11. `a_stage_change_ships...` "the actual bounded return publishes its reviewing generation": not a product defect. The product publishes the Reviewing generation in a UI progress frame of the Discard's bounded return; the fixture `verb` ran `pump_until` after the accepted Discard, which drains every progress frame (`while take_typed_operation_ui_progress()`), so the law's own loop never saw it. The law now dispatches `historyEditDiscard` directly (as it does for Begin) and passes (`1 passed`).
