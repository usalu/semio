# Silhouette Compositor API

Adopted DOM contract: `[data-shared-border-frame]` opts a rectangular frame into compositor ownership of its full outline. `[data-shared-border-edges="bottom"]` or `"top"` opts only named physical sides (space-separated). Runtime scans within `.semio-scope` (document body standalone fallback), including the shell's portal layer. Windows register the true stepped silhouette, never a rectangle. `data-shared-border-state` optionally supplies core state. Hover/focus/active are detected on each frame; hover wins globally. Runtime paints resolved segments in an owned SVG child and sets `data-shared-border-attached` ONLY for the sides it now paints; restores previous attribute on cleanup. Thus partial duplicate segments do not cause arbitrary edge loss. Frame hosts must be positioned (relative/absolute/fixed). Do not stamp frame on WindowChrome: it already registers its silhouette. Popover can stamp frame and preserve ShellScope portal placement. Boundary adoption requires no imports.

Isolated external frame paint retains the existing one-pixel inset. Logical attachment coordinates use the exact zero-inset outline; shared paint uses state-independent canonical centerlines and connected junctions while preserving isolated silhouette/chip geometry. Overflow-clipped sources are excluded before ownership resolution. Registration begins when any adopted frame or WindowChrome mounts in the root; all participants retain the same refcounted compositor until the last participant unmounts. Resize, captured scroll, attribute/child changes coalesce into animation frames; cleanup restores original paint.
