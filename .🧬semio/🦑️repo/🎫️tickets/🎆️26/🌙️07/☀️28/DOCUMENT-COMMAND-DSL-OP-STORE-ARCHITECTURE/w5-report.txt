W5 report — binary causal envelopes + wire (closes G2), single-sitting wave

Landed per w5-w6-design.md's ordered sequence (W5.1-W5.10), plus W5.7's hub schema-hash
validation feature and two genuine cross-crate bugs found and fixed during verification (both
documented in section "Bugs found+fixed" below).

=== 1. protocol/core/rs/lib.rs — 🔖️WireCodec ===

New region between 🔖️StateClass and 🧪️Tests: write_varint_u64/read_varint_u64 (forwards to
pack_core), write_str/read_str, write_bytes/read_bytes, write_hash32/read_hash32,
write_bool/read_bool — the primitive codec every downstream binary format in this wave builds on.
9 new tests. protocol_core: 40 tests, all green.

=== 2. protocol/causal/rs/lib.rs — envelope binary reshape ===

- DocumentDiff/InverseOperation: `schema: String` -> `schema: SchemaId`, `payload: Value` ->
  `payload: Vec<u8>` (InverseOperation.inverse_diff renamed to payload — same field, same reason
  DocumentDiff.payload isn't called `diff`: both now hold an encoded op, not a structural diff).
- operation_envelope_from_edit: new `schema: &SchemaId` parameter (caller-supplied real schema,
  replacing the std::any::type_name placeholder), `Op: OpBinary` bound, now fallible
  (Result<Vec<OperationEnvelope>, ProtocolError> — one encode failure aborts the whole batch).
  Payloads via OpBinary::encode_op; inverse payload is empty Vec<u8> past edit.backwards' end
  (was Value::Null).
- New 🔖️EnvelopeCodec region: encode_envelope/decode_envelope (operation_id str | document_id str
  | actor str | dependencies vec<str> | diff.schema str | diff.payload bytes | inverse.schema str
  | inverse.payload bytes | hlc), encode_frontier/decode_frontier, private encode_hlc/decode_hlc.
  6 new tests. protocol_causal: 25 tests, all green.

=== 3. protocol/wire/rs/lib.rs — fully hand-rolled binary frame codec ===

Deleted the previous "permitted deviation" (lane + varint length-prefix + serde_json body) —
replaced with `lane u8 | frame tag u8 (variant declaration order) | fields` for every
ClientFrame/ServerFrame variant, built on protocol_core's WireCodec primitives plus this crate's
own option/vec combinators (🔖️Combinators) and nested-enum tag dispatch (🔖️NestedEnums, for
Bootstrap/ApplyOutcome/AckStage). ClientFrame::Presence.peer / ServerFrame::Presence.peers flip
from serde_json::Value(s) to peer_json: String / peers_json: Vec<String> (pre-serialized JSON, so
a peer blob round-trips byte-for-byte without a JSON re-encode — needed for the TS byte-identity
canary). serde/serde_json derives and dependencies dropped entirely (no longer needed — nothing
outside this crate ever called serde_json on these frame types; verified by grep before removing).
Module doc rewritten to describe the new binary layout instead of the old deviation rationale.
26 tests (was ~26, rewritten for the new codec + new unknown-tag/truncated-field reject cases).

=== 4. protocol/rs/lib.rs — facade re-exports ===

Added encode_envelope, decode_envelope, encode_frontier, decode_frontier to the protocol_causal
re-export line. ClientFrame/ServerFrame/Lane/AckStage/ApplyOutcome/Bootstrap re-exports unchanged
(same names, only their internals changed).

=== 5. db family — pathmap codec + fixture flips (closes the "db never interprets typed op
     payloads" boundary explicitly) ===

- db/document/rs/lib.rs: new DB_PATHMAP_SCHEMA = "db.pathmap.v1" + encode_pathmap/decode_pathmap
  (serde_json::to_vec/from_slice). diff_entries/inverse_entries now check
  `schema.0 == DB_PATHMAP_SCHEMA` before decoding — a foreign schema produces an empty TouchedSet
  (not an error): the envelope is still persisted/relayed, just not interpreted at this layer.
  envelope_from_operation retags DB_PATHMAP_SCHEMA (was std::any::type_name::<Op>()) since that's
  the only schema diff_entries will actually decode; command_touch's CommandKind classification
  collapses to one kind for all generically-bridged ops as a result — a deliberate simplification,
  not a regression (every op built through this generic path already shared "write JSON value at
  path" commutativity semantics regardless of Op type). undo/preview/test-fixture construction
  sites re-tagged + re-encoded to match. command_touch and the db_security::admit_command call
  site fixed for the SchemaId newtype (`.0`).
- db/sync/rs/lib.rs 🔖️Codec: encode_command_envelope/decode_command_envelope flip from
  serde_json to protocol::encode_envelope/decode_envelope (binary WAL record, byte-identical to
  the wire form — M-C's storage half). serde_json dependency dropped.
- db/rs, db/engine/rs, db/cli/rs, db/testkit/rs (+ its bench), db/preview/rs, db/projection/rs,
  db/cluster/rs, protocol/testkit/rs: every DocumentDiff/InverseOperation fixture construction
  updated for the new field names/types; fixtures that submit through a real DocumentEngine
  (db, db_engine, db_cli, db_testkit, os-hub, compose-hub) retagged DB_PATHMAP_SCHEMA so they
  still actually materialize state (a silent no-op was the alternative — caught by running real
  tests, not just cargo check).

=== 6. Hubs — compile flips + W5.7 schema-hash validation ===

- framework/product/os/hub/rs/bin.rs (os-hub, NOT a default workspace member — must be checked/
  tested explicitly with `-p os-hub`, easy to miss): ClientFrame::Presence/ServerFrame::Presence
  field renames; HubState.presence: DashMap<_, Value> -> DashMap<_, String>.
  New HubState.schema_hashes: DashMap<scope_key, [u8;32]> (W5.7): Hello's pack_schema_hash pins
  the first non-zero hash per (studio, document); a later non-zero mismatch gets
  error_frame("schema-hash-mismatch", ...) before Welcome; zero always skips validation
  (schema-agnostic client). Durable pinning is explicitly out of scope (belongs in the db catalog
  once it grows a column) — in-memory pin only, documented in the field's doc comment.
- compose/server/hub/rs/bin.rs (compose-hub, its OWN separate cargo workspace outside the root
  Cargo.toml — `cd compose/server/hub/rs && cargo test`, not reachable via `-p compose-hub` from
  the root): same Presence field rename + DB_PATHMAP_SCHEMA retagging at its two envelope
  construction sites. W5.7 schema-hash pinning NOT added here this wave (scope note: the os-hub
  mechanism is the reference implementation; mirroring it into compose-hub is a small, low-risk
  follow-up, not done here to keep this wave's diff to the frozen contract's actual scope).

=== 7. store/rs/lib.rs — DocumentCodec.pack_schema_hash (W5.7) ===

New DocumentPack::record_spec() -> Option<dsl::RecordSpec> trait method, DEFAULT None (so the ~11
hand-written DocumentPack impls across the fleet — puzzle 2d/3d/5d, trinity, imperative, flow,
sequence, procedural 2d/3d, infinite dag, shooting, store's own serde_json::Value impl — compile
unchanged, opting out of schema-hash validation rather than breaking). dsl/derive/rs/lib.rs's
#[derive(DslDocument)] codegen overrides it with `Some(Self::__dsl_spec())` in the SAME generated
impl block that already produces encode_pack_with/decode_pack_with — every derive-based app kind
(the overwhelming majority) gets a real structural fingerprint with zero manual per-app wiring.
DocumentCodec gains `pack_schema_hash: [u8; 32]`, computed in `of` as
`P::record_spec().map(|spec| pack::schema_hash(&spec)).unwrap_or([0u8; 32])`.

=== 8. Fixture regeneration BY CODE — store/sync/rs/lib.rs wire_fixtures test ===

Extended from 4 fixtures (client-hello, client-commands, server-welcome, server-ack) to the full
19-variant list per the design's fixture table: client-{hello,commands,frontier-advertise,
preview-publish,presence,credit-grant,bye}.bin, server-{welcome-tail,welcome-snapshot-inline,
snapshot-chunk,snapshot-done,commands,ack-accepted,ack-transformed,ack-rejected,preview,presence,
credit-grant,error}.bin. Old server-welcome.bin/server-ack.bin deleted (superseded by the more
specific names); client-hello.bin/client-commands.bin reused (same role). Op payloads are real
`DemoOperation::SetN{n}.encode_op()` bytes (dsl::op_rt-shaped), not placeholder JSON. Verified via
round-trip assertions inside the same test (encode -> decode -> re-encode -> byte-compare) plus
the pre-existing decode-on-load path.

=== 9. TS twin — framework/product/os/core/js/{index.ts,backbone-worker.ts} ===

- index.ts: WireOperationEnvelope.diff/inverse flip to `{schema: string, payload: readonly
  number[]}` (inverse's `inverse_diff` field renamed to `payload`); ClientFrame::Presence.peer ->
  peer_json: string; ServerFrame::Presence.peers -> peers_json: readonly string[]. Full binary
  codec rewrite: writeStr/readStr/writeBytes/readBytes/writeHash32/readHash32/writeBool/readBool
  primitives, 🔖️Combinators (opt/vec helpers), 🔖️EnvelopeCodec (encodeEnvelope/decodeEnvelope/
  encodeFrontier/decodeFrontier/encodeHlc/decodeHlc — TS twins of protocol_causal's Rust
  functions), 🔖️NestedEnums (Bootstrap/ApplyOutcome/AckStage), and full encodeClientFrame/
  decodeClientFrame/encodeServerFrame/decodeServerFrame rewrites matching protocol_wire's Rust tag
  order exactly. DocumentActorConfig gains `packSchemaHash?: readonly number[]` (W5.7).
- backbone-worker.ts: toWireEnvelope/fromWireEnvelope now JSON-encode/decode the payload to/from
  bytes at the wire boundary (new encodeJsonPayload/decodeJsonPayload helpers) — this actor's own
  local convention stays JSON underneath (unchanged design), only the wire/storage boundary is
  binary now. connectHub's Hello sends `state.config.packSchemaHash ?? zeros` instead of a
  hardcoded zero placeholder. presenceHeartbeat send / Presence frame receive updated for the
  peer_json/peers_json string convention (JSON.stringify/JSON.parse at the boundary, malformed
  peer entries dropped rather than failing the whole roster on receive).
- Tests: round-trip assertion fixed to decode bytes before comparing; the Rust-fixture-decode test
  rewritten for all 19 new fixture files and the real op-binary payload shape (asserts
  format-byte==1 + non-empty, not a specific JSON shape, since decoding a real DslVariants-typed
  op needs machinery this TS-only fallback doesn't have a twin of).
  `bun ./script.ts test` (framework/product/os/core): 4 test files, 38 tests, all green.

=== Bugs found+fixed (not in the original design doc — surfaced by running real tests, not just
     cargo check) ===

1. WAL command envelope encoding disagreement across THREE independent readers/writers of the
   same `db_wal::WalRecord::Command` bytes. db_sync's codec flip (section 5) made db_sync expect
   binary; db_document's OWN submit/replay (db/document/rs/lib.rs :662,:522-524 before the fix)
   and db_engine's separate replay_history (db/engine/rs/lib.rs :181-183) still wrote/read
   serde_json — all three must agree since they read the same physical WAL records for the same
   document (os-hub composes db_document's real engine with db_sync's replay-based hub-sync
   layer against the same storage). Fixed both to `protocol::encode_envelope`/`decode_envelope`,
   matching db_sync. Found via `cargo test -p os-hub` (reconnect_replays_missing_commands_via_
   bootstrap_tail failing with a wrong Bootstrap variant) and `cargo test -p db -p db_engine`
   (both erroring "expected value at line 1 column 1" — a JSON parser choking on binary bytes).
   This is exactly the kind of integration bug that only running real cross-crate tests (not
   cargo check, not single-crate test runs) catches — reinforced doing so was the right call.
2. store/rs/lib.rs's test_support::assert_command_envelope_round_trip (a public helper, not yet
   called by any app this wave — future W8 fan-out work) needed its own signature update
   (schema: &SchemaId param, Op: OpBinary bound, fallible, decode via OpBinary::decode_op instead
   of serde_json::from_value) to keep compiling against the new operation_envelope_from_edit.
   Its own lossy-impl regression test (command_envelope_round_trip_panics_on_a_lossy_operation)
   needed a hand-written OpBinary impl on the deliberately-lossy fixture type to keep exercising
   the same "trips law (2)" property via the binary path now that JSON is no longer in the loop.
