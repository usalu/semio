  spr)` (both JS-bridge and native-wasmtime backends); all 3 call sites (`HostEffect::LoadDocument`

  to dsl text" item, not a pack/spr binary swap. Added `protocol` as an explicit wgpu native-target
  dependency (was reached only transitively before). 281/281 wgpu tests passing.
- os/core (framework/product/os/core/rs): deleted `os_document_to_envelope_json` (its one caller,
  s/program, already had a real typed pack-export sibling — `export_os_studio_pack`,
  `store::print_document_pack` under the hood — added to the pub re-export list instead). Fixed one

  stale field name from a concurrent "plugin"->"program" struct-field rename). 52/52 tests passing

- os/run (framework/product/os/run/rs + bin.rs) — full binary ABI flip, the biggest contained piece:
  - `MediaNodeHost` trait: `load_document(node, document_json: &str)` ->
    `load_document(node, pack: &[u8], spr: &[u8])`; `read_document(node) -> Result<String, _>` ->
    `-> Result<(Vec<u8>, Vec<u8>), _>`. All 3 impls updated (`NullHost`, `WasmtimeNodeHost` — now
    calling the host's `load_app_document_pack`/`read_app_document_pack`, itself only reachable
    after the WIT flip above — and the test `FakeHost`).
  - `SpaceRunner::plan`/`run`'s `documents` map: `BTreeMap<String, String>` (per-instance document
    JSON) -> `BTreeMap<String, Vec<u8>>` (per-instance `encode_document_pack_bytes` blob); dirty-
    fingerprinting now hashes the real bytes instead of JSON text.
  - `SpaceBundle` (bin.rs's on-disk studio-bundle format): `documents/<id>.json` (one JSON blob per
    app instance) split into real `documents/<id>.pack` + `documents/<id>.spr` binary files
    (`document_pack_path`/`document_spr_path`/`read_document`/`write_document` all rewritten).
    Caught and fixed a fake-binary regression that had crept into `bin.rs`'s `run()` mid-session
    (some other automated pass had made it compile by wrapping `json.as_bytes()` in
    `encode_document_pack_bytes(json, &[])` — bytes-typed but still literally JSON content, exactly

  - Found and fixed a real self-inflicted bug while getting this green: two of the three dirty-
    checking tests used raw `Vec::new()` as their "empty document" fixture instead of the canonical

    equalled its next incoming bytes even with unchanged content — permanent-dirty false positive.
    Fixed the two test fixtures; not a bug in the runner itself.
  - 5/5 os/run tests passing (including the two that caught the bug above).

## Decision-1 invocation-wrapper binarization — ATTEMPTED, then REVERTED (see B6 report for why)

Investigated first and found the plan's literal type list was based on a stale inventory: the named
structs `ActionInvocation`/`CommandInvocation`/`ActionContext` in framework/core/rs are dead code —
zero live callers anywhere (grepped workspace-wide, only their own definitions and one historical
ticket backup reference them). The REAL live JSON-over-WIT boundary is the guest glue's ad-hoc
`{action, args}` / `{command, args}` / `{viewState, actor}` object parsing in
`plugin_handle_action`/`plugin_handle_command` (framework/program/rs) — not those named structs.
`InvocationResult` (the real, heavily-used return type) and `ViewState` are the two live pieces.
`update-window`/`refresh-ui` (window/render JSON) are explicitly OUT of scope per the plan's own
scope ruling — left untouched. `ViewState.*_json` fields themselves are B9-scoped (dsl-quality
follow-up), not touched here — only the wire envelope around `ViewState` was ever in play.

Flipped `action-invocation-json`/`command-invocation-json`/`invocation-context-json`/
`invocation-response-json` (`{ json: string }`) to `{ bytes: list<u8> }` records carrying
`pack_rt::encode_json_value` bytes, updated the guest glue (framework/program/rs `mod component`)
and host wrapper (framework/program/host/rs) to encode/decode at the boundary, and verified clean
against the real `wasm32-wasip2` target (not just native — `mod component` is invisible to a native
`cargo check`) plus `semio-framework-program-host`/`semio-framework-renderer-wgpu` (wgpu needed zero
call-site changes since the host wrapper's public signature stayed `&str`-based). **Then found, while
starting B6, that `framework/product/os/dev/script.ts`'s hand-written `pluginApiSource()` JS glue —
the code the browser dev server actually runs to drive a compiled wasm program component —
constructs these exact WIT records directly** (`program.handleAction(instanceId, { json: actionJson
}, { json: context })`), and its own generated `.d.ts` bindings are the ONLY thing that would have
caught the mismatch, but those are regenerated from `world.wit` only on the next real build (not
caught by any `cargo check`, and I hadn't grepped `os/dev/script.ts` before making the WIT edit). A
correct fix needs `os/dev/script.ts` to construct real pack-`Shape::Value` bytes too, which means
either a byte-identical JS/TS twin of `pack_core`'s spec-driven document-encoding format (far larger
than the LEB128-style codecs used elsewhere in this plan — not a simple varint/tag scheme) or a
JS-callable wasm export of `store::pack_rt::encode_json_value`/`decode_json_value` (doesn't exist
yet). Neither is safe to rush, so **fully reverted** this item (WIT records, guest glue, host
wrapper) back to the JSON-string shape — verified `cargo check --workspace --all-targets` returns to
the exact same 2 pre-existing unrelated errors as before this attempt, no regressions. Kept the one
independent, unrelated bug fix found along the way: `use exports::semio::framework::plugin::Guest`
in `mod component` referenced the WIT interface by its pre-rename name (`plugin`) after `world.wit`
had already been renamed to `interface program`/`export program;` — invisible to any native `cargo
check` (the whole module is `wasm32`+`p2`-gated), fixed to `exports::semio::framework::program::Guest`
and confirmed via the `wasm32-wasip2` target build. Re-attempt the wrapper binarization only after a
JS-callable pack-bytes codec exists; until then this stays `{ json: string }`, same as `update-window`/
`refresh-ui`.
