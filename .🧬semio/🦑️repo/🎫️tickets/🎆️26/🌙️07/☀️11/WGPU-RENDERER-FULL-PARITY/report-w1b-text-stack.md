## Architecture
- `FontAtlas` keeps its alpha-only `pixels` page (2048×2048, same bin-packer) unchanged, and gains a second RGBA `color_pixels` page (+ `color_width`/`color_height`/`take_color_dirty()`) for color-emoji glyphs, sharing one `pack_glyph` routine keyed by a new `GlyphEntry::is_color: bool` (purely additive field — verified no external code constructs `GlyphEntry` via struct literal).
- Two modes: `Bitmap` (== old deterministic 8×16 ASCII fallback, byte-identical, since `FontAtlas::builtin()` is also the retained-mode `engine::Ui::new()`'s production atlas and is used by dozens of tests in off-limits regions that can't be fixed if broken) and `Shaped` (`from_bytes` for any non-empty input, even unparseable — falls back to embedded fonts rather than the old bitmap fallback, a deliberate improvement).
- `Shaped` mode registers 4 families via `fontique::Collection` (`system_fonts: false`, fully self-contained/deterministic): Anta (sans, from caller bytes or embedded), Kelly Slab (serif), Share Tech Mono (mono), and all 12 Noto Emoji buckets merged under one forced family name (`FontInfoOverride`) wired to `GenericFamily::Emoji` — which parley's shaper (`shape.rs`) automatically appends to the fallback chain whenever it detects an emoji cluster, with zero extra code needed.
- Per-glyph-cache-miss: `shape_single_char` builds a single-codepoint `parley::Layout` to resolve font+glyph via real shaping/fallback, then `render_resolved` rasterizes via `swash::scale::Render` preferring `ColorBitmap`/`ColorOutline` over plain `Outline`, landing on whichever atlas page matches `Content::Color` vs `Content::Mask`.

## Important honest findings
- **Emoji fallback works** (test-verified: 😀️ resolves and rasterizes through Noto Emoji), but the bundled `ui/asset/font/noto-emoji/*.ttf` files are the **monochrome** "Noto Emoji" family — dumped the SFNT table directory and confirmed no `COLR`/`CPAL`/`CBDT`/`CBLC`/`sbix` table exists — so `is_color` is legitimately always `false` with these specific assets; the RGBA page mechanism is fully built and tested via a synthetic unit test but isn't exercised by real emoji glyphs today. Drop-in real color-emoji font files would activate it with zero code changes.
- **`gpu`/`shaders` were left untouched** despite being permitted, because the actual wgpu texture/bind-group ownership (`UiPipelines`, `upload_glyph_atlas`, etc.) lives entirely in the read-only `draw` region, not `gpu` — `GpuContext` is just a thin façade. Adding a working emoji texture requires editing `draw`, which is out of scope; documented the exact 5-step wiring request (new `UiPipelines` texture/bind-group/upload method in `draw`, `GpuContext` delegate in `gpu`, new WGSL binding+branch in `shaders`, new `UiInstance`/`DrawList` constructor in `draw`, and an `is_color` branch in `widgets`' `draw_text_on`) rather than leave disconnected dead code.
- **`flex` touchpoint**: read `impl TextMeasure for FontAtlas` — it already just delegates to `measure_text`/`measure_text_wrapped`, so no edit was needed or made.
- **Deliberately deferred**: true multi-glyph shaping benefits (kerning, ligatures, bidi reordering, complex-script clustering) are not realized in painted output. `measure_text`/`ensure_glyph` stay per-codepoint by design — because `draw_text_on`/`wrap_text` (the actual paint-time emitters, in off-limits `widgets`) also do per-char advance-summed positioning, and switching measurement to whole-string `parley::Layout` metrics while painting stays per-char would silently diverge (mis-sized/clipped text) whenever shaping actually mattered. This is a deliberate correctness-over-completeness tradeoff given the hard region boundary, not an oversight — unlocking full shaping requires a `widgets`-region rewrite of `draw_text_on` to consume positioned glyph runs, flagged as a follow-up wiring request.
