# w2-world3d — final report

Audited and filled gaps in `infinite/world/rs/lib.rs` (crate `infinite_world`), the wgpu 3D-world renderer, against `framework/renderer/react/components/world-3d-host.tsx` + `world-terrain-layer.tsx`.

## What was already solid (confirmed via full read + a research pass on the React reference)
Orbit camera, GLB mesh loading, marquee/lasso selection with polygon crossing-window semantics, vertex/edge/face selection+hover overlays, gumball translate/rotate/scale with correct handle picking, vortex markers, attraction lines, target-volume wireframes, reference-image planes, paint-stroke UV picking, and — critically — LOD tie-breaking and chunking hysteresis already exactly match the React reference (both live in the shared `kernel_3d_scene` crate: log-distance LOD comparison with a documented "prefer smaller/more-detailed on near-tie" rule, and chunk-enter/exit hysteresis of `chunkSize*0.5`). No changes needed there.

## Gaps found and fixed, by area

- **Terrain** (previously 100% absent — `terrain_json` was parsed into the scene struct but never read anywhere). Discovered a ready-made pure-Rust tile engine, `framework_surface_terrain` (already used by the React reference's own wasm session), and wired it in directly rather than reimplementing: added it as a path dependency, added `WorldTerrainStyle` parsing, and a new `#region Terrain` with `apply_terrain_style_if_changed`/`sync_terrain` (each split into a GPU-free `_state` core + a thin GPU wrapper, so the tile-visibility/meshing/fetch-queueing logic is unit-testable without a real `wgpu::Device`). Visible DEM tiles are computed from camera distance, missing tiles are queued into `pending_terrain_tile_urls` for byte-fetch, uploaded tiles are meshed and re-bucketed into elevation bands and flat-colored with the same hypsometric ramp stops as `getHypsometricTexture`. **Known limitation, flagged, not fixed**: `Instance3d`/GPU vertex format has no per-vertex color channel, so true smooth-gradient coloring isn't representable — approximated with `TERRAIN_COLOR_BANDS = 10` flat-colored bands rather than a continuous ramp.
- **Environment** (previously 100% absent). Added `WorldEnvironmentRecord` parsing and applied the representable subset: `background` → canvas clear color, `sun.{enabled,azimuth,elevation}` → `ScenePass3d.light_dir` (matches `sunPositionFromAzimuthElevation`'s horizontal-coordinate formula), `material.color` → neutral-instance base-color fallback. **Flagged as a wiring gap, not fixed**: `ambient.*`, `sun.{intensity,color}`, `shadow.*`, `material.{metalness,roughness,emissive,emissiveIntensity}` have no channel in `ScenePass3d`/`Instance3d` today (single light-direction vector, single flat per-instance color, no PBR params) — needs `kernel_3d_scene`/wgpu-shader changes outside this crate's boundary.
- **Right-click context menu priority** (previously no context-menu logic existed at all — right-click always just re-synced the orbit camera). Added `resolve_world_context_menu_target` reproducing React's exact `resolveWorldContextMenuTarget` priority (vortex → component-hover "object" → `"reference:"`-prefixed hover), wired into `handle_world3d_pointer_button` with a click-vs-drag distinction (new `right_press_point` field) so a right-drag-to-orbit doesn't also pop a menu, dispatching a new `contextMenuAt {kind, id}` action on a genuine right-click. Also added reference-image hover hit-testing (`pick_reference_at`), which didn't exist before — references were previously never hoverable/pickable at all.
- **Brush preview**: verified the field set is a complete 1:1 match with React's `WorldBrushPreviewRecord` (no radius/falloff field exists on either side — it's a ghost-copy preview, not a brush-radius indicator). Found and fixed one gap: the preview was gated on `mesh_url.is_some()`, so with no `meshUrl` it rendered nothing; React always shows a translucent unit-box fallback whenever `origin` is present. Restructured to gate on `origin` and fall back to a `"box"` mesh id (factored into a small testable `brush_preview_mesh_id` helper).
- **Gumball/selection overlay**: confirmed the polygon-offset-equivalent technique and handle picking are correct. Found one real discrepancy: the marquee-preview face-fill alpha (0.48) accidentally equaled the hover alpha, collapsing React's `selected(0.62) > hovered(0.48) > preview(0.36)` ordering. Fixed to 0.36.

## Honest gaps remaining for a follow-up pass
Terrain coloring is banded, not a smooth gradient (GPU vertex-color wiring gap). Environment ambient/shadow/sun-color-intensity/PBR-material fields are parsed but inert (no shader channel yet). Context-menu rendering (as opposed to target resolution) needs the renderer-side wiring above. `WorldEnvironmentRecord.shadow`/`ambient` fields are parsed for forward-compat only, matching the fact that shadows aren't wired to any renderer in the React reference either.
