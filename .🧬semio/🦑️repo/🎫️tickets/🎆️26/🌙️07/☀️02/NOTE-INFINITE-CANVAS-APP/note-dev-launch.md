# Note dev launch

The Note component already declared the editor app `s.note.note@1/*#editor` and the per-variant launch ports. Its Cargo playground row lacked an owned development contribution. The framework default Vite configuration uses an empty inventory, and the default browser entry deliberately boots an empty catalog. The Note lane therefore could not mount the Note surface through that entry.

The Note-specific contribution supplies the Specific OS build inventory and admits the current catalog before booting the selected Note variant. It uses the existing framework dev lifecycle for the editor role, preferences, runtime receipts, and disposal.

## Verification

- `repo run @semio-tech/framework-os-dev:dev-note-react-prototype` is the normal launch target. The existing React port is 6080. The editor URL is `http://127.0.0.1:6080/?plugin=note&role=editor`.
- `repo run @semio-tech/s-note-composition-tests:verify-dev-contribution` checks the Cargo lane, schema, and real owned entry paths against the JSON fixture. Direct execution of the same verification through `repo tools exec --light bun` initially failed because the declaration was absent, then passed after the change. Ajv independently validated the declaration.
- The direct Vite configuration import requires the Specific catalog generated by the launch graph's session dependency. The dry run waited on the shared project graph service and was cancelled after more than three minutes. Browser verification was tracked separately.
- The owned catalog generator produced a clean Note editor projection with the exact contribution path and both authored example IDs. A Vite smoke test against this generated inventory transformed the real Note entry, the Specific catalog, and the framework boot module. The real Vite configuration imported and reached the expected activation receipt lookup. Its native component and activation receipt were still unavailable during this probe.
## Current launch

The direct launch route uses the repository's same ServeScript, activation receipts, catalog and staged module. The ticket script invokes the same repository-owned ServeScript with a fresh repository-issued process invocation and the generated Specific catalog.
