# Note Geometry Commit Audit

The initial Chromium geometry probe observed the Canvas moving both blocks by 68 pixels horizontally and 41 pixels vertically. Its Undo assertions compared the Canvas before and after the shortcut. The Canvas applies pointer motion immediately to a local draft, so those observations did not establish that a native transaction reached history. The attempt 45 console contains no gesture or Undo diagnosis.

The current acceptance probe checks the read-only Navigator for the same positions and larger dimensions before asserting the move and resize. The attempt 45 run with that assertion reached its boot checkpoint. Its console showed `note setActiveExample` holding the Note lane for 5 seconds, with zero `inkApplyEvents` and Undo entries in the inspected log. The run passed both fixture block-count assertions and then timed out waiting for the multi-selection bounds before it attempted a drag. The command warning was transient. The run cannot determine what Undo does after committed geometry.

The settled attempt 45 probe waited for both selected borders, then observed the real group drag in both Canvas and Navigator. Both reported positions of (278, 201) and (658, 361) from (210, 160) and (590, 320). Undo then restored both original positions in the Canvas. This run confirms a nonzero native commit and functioning Undo for the same geometry that failed in the earlier optimistic-only probe.

The renderer's `InkCanvasHost/👆️ink-pointer/🔸️handle-pointer-move/🟦️.ts` computes move previews relative to fixed origins saved at pointer-down. At pointer-up it computes the final drag delta as the draft anchor minus that same origin, with any applicable snapping, and passes it to `commitGesture`. `InkCanvasHost/🎬️ink-gestures/🟦️.ts` sends that explicit `gestureJson`; drag preview block updates remain in the renderer draft. Reading the moved draft therefore preserves the nonzero displacement. The handler reads the current React render's draft, so the source has a distinct possibility of a stale final sample if pointer-up beats the draft render. The available logs do not establish that timing.

Note's `🎮️commands/🖊️ink-apply-events/🦀️.rs` turns a nonzero drag payload into a relative `drag_blocks` upsert keyed as `gesture`. It does not derive that delta from the document or from its native provisional entries. The stream and final phases share the same key. Dispatch finishes an open transaction or submits the final changes once if no tool is open. Its unit cases `a_streamed_gesture_is_one_transaction_and_one_undo_step` and `a_block_drag_commits_one_relative_drag_blocks_leaf` cover the native transaction and history laws. Neither case observes the browser's real dispatch.

A valid browser verdict needs an accepted move and resize observed through the Navigator, followed by restoration of the same Navigator coordinates or dimensions after Undo. The current move/resize acceptance case already verifies the first part. Its restoration assertions still read the editable Canvas.

## Resize publication and preview

The settled attempt's resize changed the editable Canvas from 280 × 120 to 395.375 × 182.603, while both Navigator blocks remained at 280 × 120. At 97,267 ms the browser reported `input #37 inkApplyEvents refused: dispatch-failed` with `interactive-job.publication-stalled` after 4,096 publication units and zero copied items, copied bytes, or released bytes in the fault payload. Its seven-line console contains no operation-stage witness or input phase. That leaves both the window transient stream and the final artifact publication open as possible lanes. The generic Artifact and WindowTransient lanes reserve result pages from their accepted receipt directly. The dedicated WindowConfig post-commit refresh and its recapture problem are separate.

The resize preview also compounds absolute pointer motion across render frames. Pointer-down captures original bounds and selected IDs but omits the original blocks. Each move computes the target bounds using the total displacement since pointer-down, then scales a block read from the current draft. That block may already include earlier frames' changes. A multi-frame 52 × 27 input can therefore produce much greater growth than the pointer displacement. The preview arithmetic and the captured publication failure are separate observations. A single-move probe can isolate the latter.
