# Shared Graph Construction Waits

On 2026-09-08, the repository, registry and Print consumer clients repeatedly waited for shared graph construction between otherwise bounded task executions. The shared daemon remained PID 4126. Its bounded log tails showed active source/output watcher traffic, and client progress reported repeated plugin-node construction. A sampled emoji plugin worker used roughly 16–26% CPU. These observations establish a wait, not a measured attribution of its full cost.

The installed Nx 23.2.0 `dist/src/daemon/server/project-graph-incremental-recomputation.js` contains a freshness gate: graph computations snapshot the plugin configuration and chain to a successor when it changes during computation. The request path flushes pending watcher evidence before deciding whether to recompute. Current `nx.json` contains the repository test-cases plugin. Progress messages listing different pending plugin subsets alone do not prove that nx.json is being changed; they may simply reflect plugins finishing at different times. No claim about another process editing configuration is established.

No installed Nx code was changed, no shared daemon was reset, and no other process was stopped. The existing source-reference cache stores compact parsed references keyed by content hashes, with a 16 MiB memory limit and a per-computation file snapshot map. Source bytes are still read to avoid mtime-only cache errors. Persistent cache or graph-cost changes require their own measured profile before implementation.

A machine memory snapshot during the waits reported 18,156.12 MiB of swap in use (19,456 MiB allocated) and 66,774 free 16 KiB pages. This shows substantial retained swapped memory, but one snapshot does not establish current swap traffic or attribute the graph delay to it. The existing helper-timing probe is running again against current sources; it was updated only to copy the newly extracted runtime helper into its isolated instrumented module directory.

The completed direct helper profile inferred 378 projects in 24.880s on its first pass and 12.467s on its second. Across both passes, cargoSourceInputs accounted for 23,397.7ms in 732 calls; nativeDependencyRoots accounted for 5,470.5ms in 1,784 calls. These timings overlap enclosing helper measurements and must not be summed. The probe used empty plugin options, so it excludes Bun lock graph work. Installed Nx starts another recomputation for each genuine watcher batch and may start another for requests while collected changes remain. This is a candidate for measured single-flight coalescing; no scheduling patch or regression proof has been implemented.

## Coalescing Regression and Candidate

The controlled installed-Nx scheduler harness reproduces 33 simultaneous discovery calls when 16 source batches and 16 clients arrive during one blocked node phase. Its candidate keeps one active discovery operation, queues invalidations, and starts one successor at the next freshness boundary. Six language-neutral scenarios cover request bursts, source changes during nodes/dependencies, environment invalidation, plugin changes and dotenv replay. Four additional failure cases cover synchronous nx.json read failure, plugin loading, node discovery and dependency construction. An early candidate retained a completed promise after a synchronous prologue error; scheduling the body on a microtask fixes recovery. All ten candidate scenarios now pass, while the installed baseline fails the concurrency requirement.

The independent native Nx experiment uses a private copy of the actual 23.2.0 package and its own daemon. With explicit fixture source inclusion in .nxignore, the baseline executed 15 overlapping discovery calls for eight successive source edits and seven waiting clients. Every result matched an independent daemon-disabled Nx graph at revision 9. The first fixture without explicit inclusion did not deliver the edit through the watcher and timed out; its file map did know the source, so the evidence concerns watcher delivery rather than initial source discovery. That probe daemon was stopped. The candidate native comparison is running. The installed workspace Nx remains unchanged.

The isolated candidate daemon executed exactly two sequential discovery calls (maximum concurrency one), compared with the baseline’s 15 overlapping calls. All seven waiting clients received revision 9, matching a separate daemon-disabled Nx computation. Both private daemons were stopped afterward. A fresh isolated Bun installation applied the complete authored nx@23.2.0 patch, and a frozen second installation succeeded. Its installed module passed all ten coalescing/error vectors and the existing environment, bounded diagnostic-read and log-retention regressions. The verified fresh-install module was then atomically published into the workspace node_modules; no shared dependency installation or daemon restart occurred. Existing already-loaded daemon code remains unchanged until that daemon naturally restarts. The repository contract suite now includes the coalescing harness. A native in-process-plugin run is being checked as well.

The two new Print commands were cancelled while still waiting before any task execution. Their root wrappers exited through the existing cancellation path. They were relaunched with NX_DAEMON=false to qualify caching through Nx without restarting the shared daemon or interrupting other clients. This is a verification invocation, not a change to the repository’s default daemon policy.

The candidate also passed the actual native daemon probe with plugin isolation disabled: two sequential computations, maximum concurrency one, all seven clients identical to daemon-disabled Nx at revision 9. The workspace-installed scheduler passed all ten controlled regressions. A full `repo:test` retry did not reach Nx task execution because unrelated ongoing discovery changes called an undefined `validateSchemaScopeVocabulary` during root launcher initialization. This is not a coalescing test failure; final integrated qualification remains pending. Narrow `git diff --check` passed for the patch, repository test integration and Print fixture fix.
