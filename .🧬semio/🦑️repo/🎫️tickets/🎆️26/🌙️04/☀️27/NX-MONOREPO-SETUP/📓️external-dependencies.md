# Bun Dependency Cache Identities

Inspected the installed Nx 23.2.0 Bun parser, native graph transformation and native hash planner on 2026-09-08. The workspace explicitly uses Bun's hoisted linker. Nx's JavaScript lockfile analysis was disabled, while several production targets conservatively hashed the entire Bun lockfile.

The installed parser produced 2,906 external nodes and 2,551 dependency edges from the current lockfile. Its hoisted `sharp`, `pdfjs-dist`, `@napi-rs/canvas` and `d3-force` nodes each had zero outgoing edges. A direct invocation of Nx's actual native hash planner confirmed that explicit inputs naming those four packages included only those four identities, omitting their transitive dependencies. The graph transformer did not repair or alias those edges. The diagnostic initially needed two missing task-graph fields and an empty project dependency list; those harness errors are separate from the reproduced dependency omission.

Actual Node resolution also confirmed two distinct PDF.js installations: the shared Print compiler resolves root version 5.7.284, while Print's package script directory resolves its nested version 6.2.108. Root PDF.js uses its own nested canvas 0.1.100 dependency; the root canvas installation is 1.0.3. Hashing only the consuming package manifest's declaration would therefore identify the wrong compiler dependency.

## Location-Sensitive Graph

The repository plugin now has a Bun lockfile model that preserves each resolved package location, including nested versions and distinct peer contexts. Each external node hashes its complete lock entry and applicable authored patch bytes. Edges resolve from the package's actual location toward its ancestors, including scoped package names and aliases. Optional and peer dependencies are included when present; absent required dependencies fail explicitly. Workspace references remain project dependencies. Unsupported resolution protocols and future lockfile versions fail instead of silently weakening cache inputs.

The current lockfile model produced 1,754 external nodes and 3,025 edges in approximately 36 ms in the diagnostic process. The measured closures include 30 nodes for sharp, 13 for root PDF.js, 12 for root canvas, four for D3 force, and 13 for Print's nested PDF.js. These timings measure only this model and its small closure probe, not complete monorepo graph construction.

Language-neutral vectors cover root versus nested versions, aliases, dependency cycles, nested peers, optional platform packages and patch changes. The test independently compares dependency resolution with Bun's resolver and transitive inputs with Nx's native hash planner. The initial test failed because the required model was absent; it now passes.

An isolated workspace exercised the real repository plugin through actual daemon-backed Nx runs. Producer execution counters proved cold execution, identical warm reuse, nested-package selection, deleted-output restoration, unrelated-package reuse, transitive dependency invalidation, unrelated-version reuse, nested-peer invalidation, optional-platform invalidation and patch-byte invalidation. A patch affecting one version did not invalidate the unrelated version. All eleven invocations passed. Its daemon was stopped only after the fixture completed; the shared workspace daemon was untouched.

The first shared-workspace integration attempt failed because dependency creation observed external edges before the corresponding external nodes existed. Node inference now attaches the lock model whenever analysis is enabled and the workspace lock exists, without depending on the callback's matched-file list. The retry is running; the shared graph is not yet claimed validated.

Print document and report PDF input contracts now select root PDF.js and sharp, preserving Bun linker configuration as a file input. The actor-network generator selects D3 force. Pure font staging and token generation select no external packages. Whole-lock inputs remain on unqualified test/native paths. More importer-aware graph coverage and command-input enforcement remain necessary before narrowing those paths.

Primary references: [Nx input contracts](https://nx.dev/docs/reference/inputs) describe explicit external dependency inputs and file-input behavior; [Nx native hash planner](https://raw.githubusercontent.com/nrwl/nx/23.2.0/packages/nx/src/native/tasks/hash_planner.rs) follows the external graph for those inputs. [Bun lockfile documentation](https://bun.sh/docs/pm/lockfile) describes the committed text lockfile; [Bun linker documentation](https://bun.sh/docs/pm/isolated-installs) distinguishes hoisted and isolated resolution. The implementation findings above come from local source and runtime probes, rather than assuming the documented graph is complete.
