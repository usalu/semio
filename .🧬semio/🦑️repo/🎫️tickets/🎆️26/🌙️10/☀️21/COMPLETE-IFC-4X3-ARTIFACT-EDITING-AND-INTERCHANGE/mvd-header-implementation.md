# IFC4x3 Header View Declaration Editing

The closed `mvd/header.schema.json`, neutral `header-cases.json` and `header.feature` were written before implementation. The initial Bun test failed because the authoring module did not exist. The new TypeScript helpers capture owned header input, read declared names verbatim and return the existing `setFileDescription` mutation. Explicit selection replaces complete ViewDefinition entries at their first original position, preserves comments/options and implementation level, and refuses malformed declarations before publication. Clearing declarations retains the required nonempty description list. Development/custom names remain unknown released identifiers and are never aliased to an ADD2 name.

The helper uses the existing central mutation/diff/inverse/history path. It has synchronous and cooperative asynchronous variants, including actual text-scanning checkpoints and no bulk prepend or declaration-index mapping pass. Public facade exports and package test registration are present. The new schema does not add a second command/event vocabulary.

Native equivalents retain their explicit cancellation callback while parsing and copying text, and yield the ordinary header mutation. Native neutral tests cover mutation inversion and cancellation. The IFC4x3 details profile offers small explicit EN/DE presets on each existing ViewDefinition tagged string object. Presets are attached to the object row because the native renderer renders variant actions for collections, while the ordinary string payload remains a text input. Preset values use the existing tagged string representation and header edit rule. Written native tests cover indexed/list/count parity, actual preflight, reduction, cold reference diff application and revisioned rendered action/controller data.

Executed TypeScript verification: **5 new tests, 100 assertions**, including Ajv closed selection admission, all six neutral selections, exact inverse, history no-op/undo/redo, STEP export/reimport, source-alias isolation and cancellation inside a 65,553-character declaration. The combined MVD/semantic binding/parity check passed **14 tests, 269 assertions**. `mvd-header-oracle.ts` and `mvd-header-oracle.py` independently authored all six headers through IfcOpenShell **0.9.0.post1**, compared all three header records to owned emitted STEP, and reimported seven arbitrary/malformed declaration strings without alteration: **zero mismatches**.

Rustfmt parsed the three new native leaves and edited native profile. Native compilation/execution and retained host publication are not established; the current authentic compiler ingress still refuses the unauthenticated direct Cargo route, and it has not been bypassed. The cold native test path is explicitly a reference check, not evidence of retained production execution. Focused strict TypeScript compilation passed after the concurrent central capture descriptor narrowing fix.

Sources remain the [buildingSMART header guide](https://standards.buildingsmart.org/documents/Implementation/ImplementationGuide_IFCHeaderData_Version_1.0.2.pdf) and [pinned official ADD2 release scope](https://github.com/buildingSMART/Standards-builds/tree/610ee3f95db9d0380b1eb8de4dc6e17833531518/IFC/RELEASE/IFC4_3/HTML/concepts). A declaration is intended scope metadata. This stage does not claim full MVD constraint evaluation or certification.
