# Cooperative GLB JSON Reader Plan

The old endpoint baseline is immutable before mounting reader changes: 75 parser-role cases, 57 admitted and 18 refused, with exact ordered typed snapshots and number words. See glb-reader-family-baseline.md. These are endpoint/schema-role fixtures, not all valid geometric assets.

Reuse the framework's owned lossless JSON decoder with explicit Replace member policy and finite original controls. Decode private UTF8 bytes with one fatal streaming TextDecoder in original bounded slices; never join the complete source text. Preserve one initial BOM and count all original raw bytes through source admission. Map cancellation at syntax consumption and completion to io.cancelled.

Add a syntax projection variant beside the glTF-owned wire combinators, sharing their exact declared member/default/role tables rather than writing another schema in IFC. Typed projection yields at each admitted node/member/array/ordering transition. Emulate native Object.entries canonical integer-key order with progressive ordering for map/extras; preserve duplicate last-member semantics, Number(token) conversion, binary64 words, safe-index restrictions, closed records and open extras. Existing synchronous parsers remain unchanged. A private immutable static reader table is declaration metadata, not a source-content cache.

Mount the new decoder/projector in the actual IFC GLB reader only after neutral tests and pre-change baseline capture. Test original interior/completion cancellation for decode/syntax/project phases, source mutation after capture, UTF8/BOM split points, exact defaults/numbers/keys and official Khronos interoperability. Generic source/text allocation, decoder token assembly and Number conversion are host scalar primitives; do not infer native physical funding or zero-copy from asynchronous scheduling. If numeric extent is newly enforced, record it as an explicit resource policy rather than silently broadening exact integer admission. Domain-coded malformed JSON diagnostics may replace engine-specific JSON.parse messages while all old admission/refusal decisions remain compared.
