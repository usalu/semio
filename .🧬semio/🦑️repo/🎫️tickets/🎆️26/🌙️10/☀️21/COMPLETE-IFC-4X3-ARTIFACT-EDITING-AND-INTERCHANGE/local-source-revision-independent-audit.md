# LocalSourceRevisionV1 Independent Audit

Read-only source and adjacent test review2026-10-21. No new confirmed P1/P2 within admitted identity/exact owner contract. No actual browser mount/native claim.

The cache matches exact owner object and plugin handle,not just instance/hash. begin clears prior identity/pending before abort callbacks,uses epoch reentrancy check,refuses while holds exist and mints opaque observation identity with original AbortController signal. publish requires that exact pending object and active owner,validates instance/canonicalu64 generation/three lowercase64hex hashes,and copies only scalar identity fields into frozen output. Forged/equal-shaped observations and old pending objects cannot publish. fail only clears its own pending observation.

hold allocates unique token in captured hold-set; release is idempotent and clears readiness. retire replaces the entire hold-set and clears owner/plugin before abort/listener callbacks,so stale releases cannot alter a replacement owner's state. Multiple holds prevent readiness until all original tokens are released; release does not synthesize a revision. Exact replacement owner identity avoids instance ABA. bind checks epoch after reentrant clear and owner.active before subscription. Listener notification snapshots the listener set.

Adjacent neutral/Ajv tests cover invalid identity/origin,opaque observations,old owner retirement,overlapping holds,abort reentrancy and pending/ready notifications. This audit did not rerun them. Constructor/API is not hostile external capture: owner/getters/subscription and identity are already admitted host objects. Actual host must preserve exact document lifetime and never use equal IDs or reconstructed owners as authority. Native/source transport admission remains separate.

Integration constraints: bind/retire on actual LocalDocumentOwner lifetime; begin only after all known mutation holds settle; invalidate before local/remote mutation submission; refresh from authenticated capture identity after settlement. Do not treat a valid64hex hash as proof that a new source object belongs to the old owner. Same-instance archive replacement and direct actor/extension paths need coverage per browser-source-invalidation-route-map.md. A stale response already installed into a separate store is not repaired by publish(false).

Narrow API hardening candidate,not a confirmed current-host defect: if a custom owner.subscribeRetirement synchronously retires/rebinds the cache during registration,the outer assignment can retain the returned unsubscribe from the old subscription over a newer one. Actual owner subscription behavior must remain non-reentrant during active registration,or bind should install returned disposer only after checking epoch/owner again and immediately dispose superseded registration. This affects subscription lifetime; no current authority bypass is established.
