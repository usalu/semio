## Remaining Findings

1. **P1 — Contextual derived markers are lost during complex type selection.** `🔎️details/🦀️.rs:123-145` argument_templates sees only each direct declaration. It discards any previous Derived marker at line 133 unless the declaration itself marks that attribute derived, then creates an explicit template/unset. A complex IFCNAMEDUNIT + IFCSIUNIT has a Dimensions marker on the ancestor component because the subtype redeclares it derived. Selecting the same IFCNAMEDUNIT primary type therefore replaces the marker, although context at lines 179-189 still detects the subtype's redeclaration and disables the field controls. The resulting value is wrong and cannot be repaired through that field. A component change to IFCSIUNIT likewise needs to normalize its ancestor's Dimensions marker. Apply contextual derivation across the complete resulting constituent set while building templates/reducing type changes; preserve derived markers when still contextual, and regenerate explicit values if contextual derivation disappears. Add retained same-primary-type and subtype-change tests with IFCNAMEDUNIT/IFCSIUNIT. Existing native test `complex_derived_redeclarations_remain_read_only_in_the_ancestor_component` starts with an already-correct marker and only checks controls; it does not cover this mutation.

2. **P2 — Signed-zero edits inside complex constituents remain discarded.** The root whole-entity `same_arguments`/entity_changes path now compares real values bitwise. However `details_edit_special` calls shared IFC4 `🏅️standards/4️⃣4/🪆️subsets/✳️any/🧬️schema/🧬️mutations/🧭️edit-rules/🦀️.rs:53`, which suppresses changes using `entity.complex == complex`. Derived PartialEq equates positive and negative zero. A nested scalar edit such as `/entities/0/complex/0/args/0/value/0/value` from +0 to -0 is therefore discarded before SetEntityComplex; whole constituent replacement has the same issue. Use an owned bitwise constituent comparison for this no-op decision, or remove the numeric-equality suppression and let exact mutation/diff logic publish. Add retained nested-complex and whole-constituent signed-zero/inverse tests, in addition to the existing root-entity vectors. The SetEntityComplex mutation leaf itself constructs its sparse replacement diff directly, so the loss occurs at the resolver's no-op check.

3. **P2 — Large type variants and argument edits still perform non-cancelable document-sized work.** `🔎️details/🦀️.rs:148-155` clones all complex constituents into every root type variant, and `variant:597` materializes that full DslValue for each visible type row. Thus a single large complex entity is copied repeatedly before command admission can reject an oversized payload. The live details render branch delegates to ordinary render without consuming its StepContext (IFC4x3 editor `🦀️.rs:102-133`). During reduction, existing argument/complex edit resolution materializes/replaces its argument subtree; `same_arguments:730` has a depth-sized allocation stack but still walks all nodes synchronously. Raw event byte/node admission does not bound the size of preexisting values copied by these operations. IFC-local options: use a virtual type-name event carrying only the chosen declaration, compute changed values in a retained bounded cursor with checkpoint/cancellation, and build sparse argument edits from the owning argument rather than materializing the entire document. Precompute/request-cache small catalog declaration indices and contextual derived metadata instead of recloning declarations for each control query. Add a large existing-argument cancellation/yield test and a type-row construction work bound. The current change improves stack allocation, but does not yet provide expensive-operation cancellation.

These findings were sent to the parent immediately. The physical internal/external mapping research was respected: no ordinary-to-single-chain external encoding toggle is requested as a conforming IFC feature.
