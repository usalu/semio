# Canonical Native MVD Preparation Plan

The canonical preparation and Direct/Terminal migration are now source-implemented with bounded independent-review closure; `native-mvd-preparation-implementation.md` records current evidence and open native gates. The before-state repeated admission stages0–4 in Direct and Terminal. This plan replaced that repeated owner pipeline. Body consumes the same owner rather than another full wrapper copy. Local clause semantics and public partial reports remain separate.

The private MVD root will include the existing shared source-index implementation once. Population, preparation and both Alignment domains import that actual native type/trait; no shared-index visibility expansion, second catalog, source copy or replacement decoder is needed.

`IfcMvdRequest` extends actual IfcSourceIds and RetireOwned+Sync with one bounded borrowed row validator. Real typed requests implement count/key through the existing trait and static per-row policy in their own domain module. There is no caller-supplied closure or readiness boolean. Row keys remain exact canonical positive u64 words; duplicate checking remains the existing original-funded index. The trait's metadata accessors must be cheap and immutable; request count and key/validator progression run under original grants.

`IfcMvdPreparation<R>` owns the request index, original source/request/caller/epoch state, one IfcMvdPopulationWork<R>, born snapshot/request aliases and the admitted sealed request donor. Its first accepting request turn retains one paid snapshot Arc before fallible request construction/posting, without model access. Validation precedes graph reads. The exact snapshot/request donors then move once through receive_donated. Index/metadata retire before population/source/request roots. No fresh wallet, second source Arc, graph scan or heap request copy is introduced.

Preparation exposes demands/check-resume/advance/status and higher-ranked Copy-result callbacks. A prepared callback lends the actual population view plus a private request-index view; an unavailable callback lends only the original request view plus the request-index view. Constructors check actual completed request-index identity against the same original request/epoch. The request-index view exposes lookup and an opaque root/type/epoch/row-buffer pin; it does not expose an unqualified raw index. Prepared population view construction still requires its actual completed shape and source-index proof. A private ready phase controls scheduling only.

Direct/Terminal wrappers retain local clause and tiny result/error/donation state plus the one canonical preparation owner. They verify original inputs before any debit, add only their own funded metadata, delegate preparation until ready, then delegate each local clause through the original borrowed callback. Terminal stores the exact request-index pin before mapping RelatingObject IDs to target rows, so index substitution is refused before effects and moving the wrapper remains valid. No generic public full-MVD verdict follows.

Schema-first neutral request cases cover accepted keys/layout kinds, exact maximum u64, empty/duplicate/noncanonical/overflow keys and rejected row policy. Native laws must consume those cases and prove first-turn retained source custody, exact donor moves, original denial/cancellation/error prefixes and paid close. Existing actual Direct/Terminal neutral corpora, late-unknown owner cases, original counterpart identities and new prepared/unavailable endpoint cases remain mounted. A native explicit two-clause law must share both the population and actual request-index views; type/runtime/heap/output claims stay false while authentic compiler ingress refuses.

Root owns Body's pure clause/domain files and selected TypeScript registration. This worker owns preparation, the narrow MVD source-index include/import changes and folding Direct/Terminal. Shared population APIs remain original-owned; any additional request-pin accessor is fixed metadata only. No build/enforcement/public transport/UI/capability changes occur here.
