# Private glTF And GLB Source Capture

The actual adapter source-alias defect is corrected. The independent red probe loaded the pinned Khronos Box physical GLB through readIfcGltfGlb, then changed caller node names at gltf-import and a later POSITION float at gltf-accessor. The emitted name changed and maximum X jumped from 0.5 to 123.25. After correction, the same probe preserves Name=Mesh and maximum [0.5,0.5,0.5], matching independent Three.js geometry. See gltf-source-independent-audit.md for exact red observations and the retained probe input.

New io/gltf-source.ts puts the real loaded GltfSnapshot shape behind the existing central external own-data copier. Its document, number[][] buffers, exact BigInt indices and Binary64 words become private before any semantic use by gltfToIfc4x3 or writeIfcGltfGlb. The shared policy refuses accessors/prototypes/cycles/non-data without invoking getters. Fixed record admission counts asset, document family records and nested mesh primitives; byte values/properties/depth are separately bounded by the central copier. Private buffer bytes, including unused bytes, are validated in original admitted batches before semantic work. This is source-container admission, not a claim of complete glTF document semantic validation. Invalid byte codes retain their domain classification: gltf.bytes for import, glb.bytes for writer; descriptor/shape admission uses exchange.source.

Raw GLB input has a schema-owned binary capture interface. Built-in TypedArray internal-slot getters admit genuine Uint8Array/Node Buffer, exact subarray offset/extent and attached byte storage without caller buffer/offset/length/tag getters. Proxies, signed/wider arrays and DataView refuse before caller reads. An admitted fixed view is copied to private Uint8Array storage under original cancellation and maxValues byte ceiling, before header parsing. Subsequent framing/BIN work reads only that completed private buffer. Extent loss during copy refuses. Source stability remains required during cooperative capture; completed custody does not claim an atomic function-entry or cross-thread snapshot.
