# Declaration-owned geometry query layer plan

The reusable boundary belongs under shared IFC artifact 📚️catalog (for example query/attribute, query/membership, query/primitive), not IFC4x3 MVD concepts or generic UI. Existing shared IfcCatalog/IfcTypeExpression/IfcAttributeDeclaration and bounded ifcNameSteps/ifcSubtypeSteps/ifcResolveTypeSteps already live there. Accept the actual catalog and borrowed schema-neutral entity/value interfaces; keep versioned schema ownership in the caller. The actual source capture/index/control runner remains a distinct layer. Query code must not import MVD applicability, IFC4x3 release singleton or IO progress policy.

## Existing useful implementation

IFC4x3 schema/👁️mvd/🧩️concepts/🟦️.ts already implements bounded membership scans over primary+complex parts; attribute resolution uses allAttributes only for simple records and direct attributes for every part of complex records. It returns original values/type expressions/exact source pointers and stops after two matches to expose ambiguity. Defined primitive walker follows only declared defined aliases, bounded name/depth/cycle checks, and exact wrapper names/items. These are predicate helpers, not terminal schema/publication authority. Extract them by passing catalog/source access explicitly while preserving concept wrappers and diagnostic contracts; do not move captured source custody into a static catalog cache.

A query result should distinguish missing, unique, ambiguous and unknown declaration, retaining exact owning part/slot/declaration/type/source pointer. Qualify attribute lookup by declared owner where relevant; Position exists in both ParameterizedProfileDef and SweptAreaSolid, so unqualified field text alone is not a universal role. Membership evidence must not silently ignore an unknown constituent. Geometry's exact constructor support must remain separate from general subtype membership: RoundedRectangle/HollowRectangle own shape-changing slots and cannot become filled rectangles merely because Rectangle is a supertype.

## Released catalog evidence

Pinned IFC4X3_ADD2.exp:178 IfcLengthMeasure=REAL;287 IfcPositiveLengthMeasure=IfcLengthMeasure with WR1 SELF>0. Rectangle9374 declares only XDim/YDim; inherited ParameterizedProfileDef8330 declares optional Position, ProfileDef owns ProfileType/ProfileName. SweptAreaSolid11273 declares SweptArea/optional Position and AREA predicate; ExtrudedAreaSolid6588 declares direction/positiveDepth with nonzero-Z dot predicate. CartesianPoint owns Coordinates below Point/GeometricRepresentationItem/RepresentationItem. Complex record query must consume direct slots from those owners rather than indexing each partial record using flattened allAttributes. Exact constituent chain consistency/ONEOF/WHERE validation remains separate from locating an attribute.

Primitive query should return a leaf together with original declared type/alias traversal and outstanding constraints; resolving to REAL does not discharge positive-length WHERE, finite representability, endpoint numeric policy, SELECT membership or physical encoding validity. Check actual leaf kind rather than assuming reaching REAL makes a string/Unset/Derived numeric. Do not generically unwrap arbitrary typed names to their first item. Constructor arity, declared membership, cycles and unknown names must be explicit refusals/incomplete results. Primitive STRING/REAL wrappers and ancestor alias wrappers require a deliberately frozen internal contract; no physical-admission widening is authorized by this plan.

## Independent physical oracle limitation

Executed geometry-query-oracle.py using existing IfcOpenShell0.9.0.post1 on actual corrected rectangle STEP variants. Raw numeric XDim passes full EXPRESS. Direct XDim IFCPOSITIVELENGTHMEASURE(2.), IFCLENGTHMEASURE(2.) and nested wrappers parse as wrapper objects but each fails XDim type validation; IFCLABEL('2') adds further diagnostics. This is real independent behavior, not proof that accepting wrappers in an internal schema-neutral graph/query is forbidden or that all external implementations agree.

Authored external complex profile/solid/point chains parse at file level, but IfcOpenShell drops their instance IDs, then reports missing referenced values/empty Items. That oracle does not validate complex constituent query behavior. Do not advertise those models as independently validated valid complex geometry. Exact source variants and full results are retained generated/geometry-query/*.ifc and oracle.json. No reinstall/runtime dependency/native execution.

## Physical mapping authority still required

No local primary ISO10303-21 mapping clauses were found in the inspected pinned IFC tree. The official ISO10303-21:2016 public record confirms the exchange format scope but does not expose the needed exact defined-type/SELECT/external-complex mapping rules: https://www.iso.org/standard/63141.html . NIST's actual analyzer describes checking SELECT value types, but is an implementation/service description rather than the normative clause: https://www.nist.gov/services-resources/software/step-file-analyzer-and-viewer . Search also surfaced third-party mirrors/translations and an EXPRESS-language tutorial; none is treated as authenticated normative authority here. Acquire the actual published ISO mapping clauses or official released IFC serialization conformance material before changing direct-defined-wrapper admission/refusal. Alias declarations alone do not specify Part21 parameter encoding.

## Minimal schema-first next slice

geometry-query-neutral-vectors.json separates raw numeric alias resolution, exact/wrong/arity wrapper query cases and declared-owner complex chains/duplicates/unknown/incompatible roles. Freeze query result status/source pointer/owner/type/leaf identity with same vectors in TS/native; use an independent released catalog roster for exact owner/alias declarations. Existing physical raw sources supply an independent valid geometry baseline. Complex and direct-defined-wrapper vectors must remain explicitly internal query laws with the external-oracle limitation above until authenticated mapping evidence exists. Every part/attribute/name byte/alias edge suspends; async caller retains the original private snapshot and captured control, denied/cancel returns no published geometry. No production edits.
