# EXPRESS Indeterminate Aggregate Follow-Up Audit

Read-only focused TS evaluator review beyond already-fixed containing SELECT and aggregate-kind cases. No new confirmed semantic defect or authenticated executable counterexample was established. Native/machine approval remains false; compiling all released AST nodes is not semantic conformance.

Reviewed evaluator aggregate construction/repetition, QUERY, equality matching, IN, subset comparisons, union/difference/intersection and used builtins SIZEOF/HIINDEX/LOINDEX/EXISTS. Ordered equality propagates unknown unless a definite mismatch; unordered equality/subset uses definite and possible bipartite matching, preserving multiplicity instead of greedy unknown selection. Membership returns true for definite match, unknown for only uncertain match, false otherwise. Aggregate-valued operations explicitly throw aggregate-indeterminate when output membership cannot be determined, rather than claiming a fabricated complete value. This refusal is a documented incompleteness frontier, not automatically a wrong successful result.

QUERY currently retains only true predicate results and preserves aggregate kind/lower metadata; scalar population follows permissive empty items fallback. Scalar QUERY and invalid builtin operand behavior are already documented cold/reference limitations. They are not new findings and were not promoted to valid released-program counterexamples. ARRAY QUERY result kind/lower and indeterminate output cardinality require authenticated ISO10303-11 rules before editing; no speculative rule is asserted here.

Pinned IFC4X3_ADD2.exp contains many QUERY/SIZEOF uses and uniqueness functions IfcUniqueDefinitionNames13748, IfcUniquePropertyName13784, IfcUniquePropertySetNames13800, IfcUniquePropertyTemplateNames13821 and IfcUniqueQuantityNames13836. Neutral vectors should separate unknown whole aggregate, known aggregate with unknown element, definite matching element plus unknown, definite mismatch plus unknown, duplicate multiplicity and empty aggregate; include SET/BAG/LIST/ARRAY wrappers only where the released parameter domain permits them. Assert result true/false/unknown or explicit incomplete, never just no exception.

That implementation can observe its own compiled behavior but does not independently authenticate ISO unknown cardinality semantics; plain Python list/set operators are especially insufficient as normative oracle. The previous documented external TYPEOF defect reinforces this distinction. Do not use coincident TS/Python results alone to enable machine admission.
