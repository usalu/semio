Read-only source review of renderer ShellHelpers/window-panes/staged-args/intents/TS implementation and adjacent test source, 2026-10-21. No new confirmed P1/P2 inside the stated trusted-adapter contract. No browser mount or native execution is established.

The module resolves the original resident control before reading raw input. Surface/revision/node/key/trigger/action must match; disabled/read-only controls refuse. Event args are ignored. Resident binding supplies fixed edits, exact choices and paths. Exact bigint sequence and decimal-u64 generation arithmetic avoid binary64 loss; successful edits alone advance sequence. Structural edits clear proof; preserved single text edits retain the resident layout and overlay host args while generation advances. Execute additionally requires latest exact token and ready status. Reset/revise/close invalidate old proof; closed owner cannot revive.

The adjacent authored tests cover forged origin/args, replay, u64 boundaries, rapid partial strings, structural descendants, fixed-only activation, disabled/read-only/token mismatch, reset/revision/close and independent windows. ## Required hookup obligations

1. `publish` accepts any supplied source whose status token matches. Its surface is established from that source rather than derived from token.window. Therefore the actual host adapter must validate the exact consumed auxiliary surface, actual instance/window/action/source owner and admitted current status before calling publish. Tokens must be unique across new sessions, including reopening the same action/source; restarting generation with a reused token permits an old response to match a new session.
2. The constructor retains host args by reference and owner/controller/locale by reference; request/executionArgs expose args. The explicit immutable-host-input contract is essential. Never mutate nested staged args or owner objects outside immutable reducer transitions. This is not an external input capture API.
3. The WeakMap replay boundary is source-adapter identity, not surface string. Reuse one stable adapter per actual retained surface lifetime, or independently reject replay at host ingress. Recreating adapters per request would reset its local seq watermark.
4. A source adapter whose getters are rebound to a stale publication makes current() fail, even if publish rejects that old status. It will not overwrite args, but display() becomes undefined and can fall back to older component.value. Suppress older response installation at the host before changing the adapter/store, not merely by observing publish(false). The test explicitly covers this refusal behavior; presentation preservation requires the host generation gate.
5. Structural replacement intentionally removes proof and display. Disable/pause the old subtree while replacement is pending; do not let fallback values masquerade as a newly selected current layout. Ordinary Select has no optimistic draft itself.
6. `ready` describes the token supplied by the trusted status adapter. This module does not validate the Extension shape, bound the whole args/request, or prove the producer's complete-tree generation. Those admissions belong to the actual host transport. Native caps/controlled ingress remain separate.

Integration tests should replay an old response after a newer accepted publication, reopen the same action with a fresh owner token, replace adapter objects with equal surface strings, and exercise text focus/selection through pending layout-preserve refresh. Also assert collapse/window-close SurfaceHidden sequencing described in browser-staged-draft-lifecycle-audit.md. These are open integration scenarios, not newly executed evidence.
