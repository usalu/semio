# Browser Staged Form Source Checkpoint

2026-10-21. The goal and ticket remain active. No native guided action, browser form mount, ordinary owned-control interaction or semantic capability is claimed by this checkpoint.

## Implemented and Executed

The canonical renderer `ShellHelpers/window-panes/staged-args/intents` module now owns a pure action/window/source session. It resolves the current resident control before consuming raw input. The exact surface/publication/node/key/trigger/controller/action/version must match. Disabled, read-only, mismatched input kinds, stale full tokens and replayed sequences refuse. Event args are ignored: only the resident binding supplies field paths, fixed values and exact selected payloads. Generations and intent sequences use exact u64 arithmetic, including values above binary64's safe integer boundary.

Preserved authority is restricted to exactly one text marker. Successive partial strings remain in immutable host-local staged args while a newer validation generation is pending. Execute requires a current ready status for that latest complete token. Choice/fixed structural changes, reset, revision change and close retire the old proof. The constructor takes host-owned immutable args; this is not an external source-capture API. Actual host hookup must issue unique owner tokens, keep a stable adapter per retained lifetime, suppress stale publication installation before rebinding that adapter, and disable old structural subtrees while replacement is pending.

The manifest's neutral `staging/refresh` contract now separates an auxiliary surface key, a real `contextWindowId`, declared body key and typed staged request. Its binder uses the existing real-window projection. It rejects unknown roster windows/actions, undeclared bodies, wrong locale/window tokens, noncanonical/overflow generations, duplicate real-window owners and occupied surface keys before returning any mounts. It neither adds a synthetic roster window nor embeds the request in ordinary ViewModel metadata. ActionDefinition exposes the existing native staging declaration through its frontend type; refresh request/response types have a distinct optional forms collection. No producer is newly advertised and no sender/mount/cap was changed.

Neutral closed JSON schemas, JSON cases and language-neutral feature laws precede both implementations. The first runs failed because each implementation module was absent. The session suite initially passed30tests/146assertions; the refresh suite passed13/39. An additional real red/green regression now captures owner controller/locale scalars before later caller replacement; the token was already captured. The latest focused run with current shared binding/census/request/wire tests passes **71tests / 3517assertions across five files**, zero failures. AJV independently validates the closed fixtures/contracts, and fast-json-patch independently reproduces the nested exact edit. Strict targeted TypeScript checking passes for the guard/refresh graph; the shared worker's new production Pack encoder test expands its separate strict graph into unrelated missing UI/manifest subpaths, recorded in its report. The framework's explicit test-staged-form command now selects the four neutral/wire/refresh/browser suites; the IFC producer is the fifth focused suite.

## Receiving and Renderer Frontiers

The frozen proposed native crossing carries a separate `stagedRequest: {contextWindowId, request: Uint8Array}` record-body source on SurfaceVisible. The real window context must be mounted first and its actual lifetime must remain controlled. The native worker is implementing that schema/retained receiver before any guided advertisement. Recursive ViewModel fields and wire caps remain unchanged.

The actual owned intake provides lease-backed per-node reads through useOwnedUiView/useOwnedUiNode. Existing ordinary InterpretedUiNode/Input/Select/Button views still require the concrete UiDocumentStore port. No full-tree projection or optional context alone is treated as owned proof. A narrow per-node read/intent port sharing those ordinary views remains required, together with status Extension admission, the original-intent interceptor, the presentation overlay, newest-generation publication gating and exact SurfaceHidden ordering on collapse/switch/close. Native guarded receiving and the generic ordinary-control body builder also remain open. See browser-staged-session-independent-audit.md, browser-staged-draft-lifecycle-audit.md and owned-form-renderer-port-audit.md.

Authentic native Cargo still refuses before rustc under the enforcing store/launcher. Rustfmt is syntax inspection only; no native type/runtime/funding/heap proof follows from these source changes.
