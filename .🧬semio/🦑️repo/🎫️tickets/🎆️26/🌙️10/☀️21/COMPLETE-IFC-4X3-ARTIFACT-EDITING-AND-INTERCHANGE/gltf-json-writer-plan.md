# Cooperative GLB JSON Writer Plan

The actual writer still converts the complete private typed glTF tree with recursive map/Object.entries, calls JSON.stringify and TextEncoder.encode on the full document, then copies/fills the complete JSON chunk without an interior scheduling boundary. Shared source value/property bounds do not bound a single immutable string. The native framework has retained JSON writer cursors; no production TS encoder was found. The existing TS decoder belongs to the separate reader follow-up.

Implement an IFC exchange JSON egress interface beside the adapter. A schema-aware generator converts one typed node/member at a time under the original control, preserving safe integer BigInt conversion, finite exact Binary64 numeric values, omitted undefined/empty ordinary arrays, attribute/target pair objects and extras/extensions closed JSON values. Last-wins object members and JavaScript property enumeration order remain explicit via safe own-data objects; __proto__ is data. Immutable strings remain borrowed until emission. No external runtime dependency, permissive alternate JSON model or legacy adapter is introduced.

A generic JSON fragment generator then visits the admitted native values incrementally. Escape quote/backslash/controls and lone surrogates exactly as well-formed JSON; preserve non-BMP pairs and finite Number formatting. Produce bounded UTF8 fragments, progressively enforce encoded-byte limits before storing them, and retain cancellation/progress through value visitation, string encoding and final framed JSON byte copying. Build GLB from the fragment roster and length without a complete JSON string/encoded buffer, whole bytes.set(json), or a fill spanning the entire JSON area. Only the at-most-three padding bytes use fill. Final BIN bytes also honor captured batch.

First closed neutral schema/cases/feature and actual Box writer tests cover complete parsed JSON equivalence with independent native JSON.stringify expectations, exact UTF8/escape/duplicate/extras/attributes/default behavior, source mutation stability, output ceiling and original interior/terminal cancellation with control replacement. Existing Khronos/Three official validation must run after final production changes. Separate host allocation, native Rust compilation and reader typed-projection boundaries remain explicit. No capability gate changes.
