## Supported Behavior and Boundaries

STEP retains complete ordered entity graphs and the three standard headers. Snapshot identity is `stdio.ifc`; FILE_SCHEMA is `IFC4X3_ADD2`. Positive u64 entity/reference identities, i64 integers, exact finite Binary64 real words including negative zero, unset/derived, strings, enums, references, nested aggregates, typed selects and complex instance members roundtrip. Strings support escaped apostrophes/backslashes, Unicode X2/X4, Latin X and S/page directives. Duplicate ids, unresolved references, invalid Unicode, malformed literals, nonfinite reals, unsupported header records and foreign schema identifiers are refused. Header semantics, EXPRESS rules and MVD conformance are separate from STEP syntax. The stored graph retains semantic values rather than original formatting/comments.

BINARY is canonical STEP literal content without quotes: unused high-bit count 0–3 followed by uppercase hexadecimal. Empty is `0`; bit width is `4*(length-1)-unused`. The unused bits pad the LEFT/high side, and must be zero. Parsing normalizes lowercase hexadecimal; native serialization requires canonical uppercase. Normative procedure: [ISO 10303-21:1994 §7.3.6 preview](https://www.theiteh.com/catalog/standards/iso/a4c627cb-62ad-466d-b1c5-85e84740f12f/iso-10303-21-1994); [2002 grammar preview](https://www.standards.iteh.ai/catalog/standards/iso/6c155770-dcbc-4fa9-80b3-eec5f694c0b1/iso-10303-21-2002). Independently checked against IfcOpenShell PixelTexture.

Triangle extraction supports product shape representations containing IfcTriangulatedFaceSet and CartesianPointList3D, PnIndex indirection, nested Cartesian local placements, representation-context placement and project SI/conversion-based length units. Geometry is returned in SI metres and IFC Z-up. Unsupported representation items and orphan face sets produce diagnostics. This is not all IFC geometry: extrusions, CSG, BRep, mapped items, polygonal face sets, linear/grid placements, infrastructure geometry evaluation, styling and georeferencing evaluation remain outside this evaluator.

GLTF exchange uses the existing glTF GltfSnapshot/GltfDocument types and native document parser, with the framework's Binary64 and bigint index ownership. IFC export applies Z-up to Y-up rotation and float32 storage, emits binary indexed triangles and product/source representation ids in extras, and reports dropped IFC semantics/materials/properties/normals. GLB 2.0 framing handles one embedded buffer and validates chunk boundaries. Import supports static dense float32 VEC3 positions, u8/u16/u32 indices or unindexed triangles, nested affine node transforms and reflection winding. Required extensions, animations, skins, morph targets, sparse/normalized accessors and nontriangle topology are refused. Import creates actual IFC product shape/triangulation/proxy entities, never fabricated authored BIM parameters. Materials and non-position attributes are explicitly diagnosed as omitted. Original IFC graphs remain preserved in the source IFC artifact, not in converted glTF artifacts.

BIM exchange is deliberately named **spatial projection**. Export emits actual project/site/building/storey entities, local placements and aggregate relationships. Geographic angles, elevations, building origins/rotation, true north, project metadata and authored storey level/height/cut-height are represented. The latter authored fields use `semio_BimStorey` properties because IFC elevation cannot determine authored level or height. Missing references, conflicting storey levels, differing site north directions and unavailable authored storey height are refused. Site boundary curves and all nonspatial BIM families produce omission diagnostics. Import does not invent sites or storey heights. Imported BIM identity is `s.bim.model@1`; ids are newly derived from IFC identity. General authored BIM family import/export and rigorous foreign spatial-placement equivalence are unfinished; these functions must not be advertised as full BIM fidelity.

FEM exchange emits actual structural analysis models, point connections with vertex topology, curve members with edge topology, material assignments and SI engineering properties, explicit section area/Iy/Iz/torsional constant properties, pin/rigid member semantics, restraints, load cases, global nodal force/moment and constant true-length global member UDL actions. Numerical section properties use `semio_FemSection` properties without inventing an unknown profile shape. Export declares explicit SI units. Local frame basis/roll follows native `Frame3` in `✏️s/🔨️modules/🏗️fem/⚙️engine/🧱️elements3d/🌉️bars-and-frames/🦀️.rs`. Import requires a single analysis, SI metre units and explicitly SI dimensional material/section properties; missing engineering semantics are refused. Nonzero roll is supported through the native reference basis. Continuum solids, load combinations, self-weight, area loads, nonuniform load configurations, member moments, springs, local load/support axes, nonunit load coefficients, member-local/shared placements and general foreign profile inference are unsupported. Source IFC analysis/results/identities remain preserved in the source graph. Solver/display settings are initialized for the new projected FEM artifact and explicitly diagnosed as outside IFC semantics.

## Reproduction

Run from repository root with a Python3.12 runtime and Bun. Infrastructure fallback rationale: cached `repo.exe` is MCP-only and old `semio-repo.exe` has no general script/read route, as documented in `plan.md`. Focused direct commands were therefore necessary; no infrastructure workaround was committed.

1. Install test-only `ifcopenshell==0.8.3` into `<ticket>/🗑️generated/ifc083` using `python -m pip install --target`.
2. `bun <ticket>/exchange-oracle.ts` prepares generated FEM/BIM/box/binary inputs.
3. For each official fixture and generated IFC input: `python <ticket>/ifc-oracle.py <ticket>/🗑️generated/ifc083 <input.ifc> <ticket>/🗑️generated/ifc-results`.
4. Set `SEMIO_IFC_ORACLE_OUTPUT=<ticket>/🗑️generated/ifc-results`; run `bun test <IFC4x3 any>/🚪️io/🧪️tests`.

Focused strict TypeScript checking of BIM/FEM production modules currently reaches a pre-existing missing `@semio-tech/framework-interaction` module through the real FEM snapshot's transitive imports; no error in these production modules was reported.

## Audit and Next Implementation Priorities

1. Spatial projection now admits only identity geometry-context/site frames, direct site→building→storey placement parents and storey translations agreeing with Elevation and cumulative authored heights. Twenty adversarial spatial/analytical regressions cover the independent audit's confirmed defects. Broader equivalent foreign placement chains and georeferencing still require explicit future mappings; unsupported transformations are now refused atomically.
2. Analytical projection now requires explicit selected-analysis/case/action membership, unmodified endpoint connections, compatible SI dimensions and measures, supported global actions and identity analytical contexts. Factored assignments, unassigned/duplicate actions, releases/connection conditions and unsupported placements are refused. Unit validation resolves all seven physical exponents, SI names/types, derived exponents and conversion nominal/factor/declaration dimensions. General official structural example is intentionally refused rather than manufacturing missing torsion/engineering data or interpreting imperial numbers as SI. Broader analytical mappings require future explicit implementation.
3. Expand geometry evaluators and BIM authored-family mappings behind their own interfaces. Full infrastructure linear alignment evaluation, MVD validation and EXPRESS rule evaluation are not implemented here.
4. Cooperative cancellation exists at parse-value/string/entity, extraction vertex/triangle, emission and projection checkpoints. Individual synchronous serialization/accessor/buffer copying stages can still be large and need cursor budgets for strict per-step allocation/latency guarantees; they must not be claimed as fully bounded jobs.
5. Subsequent native waves now add IFC4x3↔glTF native artifact composers, controlled IO/natural GLB export, BIM spatial routes and a narrower unloaded FEM route with root declaration/capability registration. See `native-exchange-implementation.md`, `native-exchange-fixes.md` and `native-domain-exchange-implementation.md` for exact admission and limits. Native compilation/execution, owned receiving verification and actual native-output third-party oracles remain blocked/unverified, so native correctness or complete cross-language parity is not claimed. Native FEM loaded/rolled/solid parity, broad BIM families and fully funded cursor/event publication remain outstanding.
