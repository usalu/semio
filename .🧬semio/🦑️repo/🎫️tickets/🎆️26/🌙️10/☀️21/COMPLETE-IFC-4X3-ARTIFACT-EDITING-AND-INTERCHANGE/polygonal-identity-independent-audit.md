# Polygonal Face Set Identity and Closure Independent Evidence

The eight explicit authored inputs in `polygonal-identity-cases.json` are a bounded prerequisite matrix, not yet the full geometry feature matrix. `polygonal-identity-oracle.py` constructs genuine ADD2 physical entities through a test-only oracle interface, runs IfcOpenShell 0.9.0.post1 full EXPRESS, and its normal geometry backend. Generated physical files/results are under `🗑️generated/polygonal-identity`. No production files or original assets changed.

All eight physical files parse and have zero EXPRESS diagnostics. Shared box indices, 24 distinct indices at identical coordinate triples, nonunique PnIndex aliases, and reversed coordinate-roster ordering produce the same 8-vertex/12-triangle mesh, bounds [0,0,0] to [2,1,3], signed volume 6. The PnIndex alias case genuinely has 24 index entries addressing eight coordinates. Source-index edge incidence alone would reject its closed geometry incorrectly. The raw source indices/coordinate roster remain important source-query identities; geometric topology can use an independent exact-coordinate equivalence key without rewriting the source. No tolerance welding is justified by this evidence.

The explicit closing-end repeat and consecutive repeat rows also receive zero EXPRESS diagnostics and the same normal mesh. Formal CoordIndex is a non-UNIQUE LIST, so blanket duplicate-index schema rejection is wrong. Normal mesher cleanup is not proof that every repeated loop is geometrically legitimate; an evaluator may remove exact consecutive/closing zero-length repetition from private ring work while retaining source indices and rejecting other degenerate/self-intersecting geometry. Open false and unset rows both produce ten triangles and zero EXPRESS diagnostics. Their computed oriented tetrahedron sum is 4 and must not be advertised as an enclosed-solid volume.

## Explicit Matrix Freeze and Negative Observations

`polygonal-neutral-cases.json` is the frozen 20-row explicit matrix, SHA256 `2e25b06cda74cc1848d25289571bd498b963adfb7d6ff296295bf18ac6765812`. Its closed schema is `polygonal-neutral.schema.json`, SHA256 `b56a0c989c492b1b2dd55bba3183dc3057e149ff1c054212e440237d0af4be72`. The frozen eight-row subset is `polygonal-identity-cases.json`, SHA256 `e0d4276bff55d5e1bae79fd07160f37f296e9d13a63d8cc54a38af61e33eff71`; `polygonal-identity.schema.json` has the same schema bytes/hash. Both validate with actual Ajv strict mode through `polygonal-neutral-schema.ts`. Numeric index fields intentionally permit malformed values as test inputs; this is a test-case schema, not the IFC declaration schema. Outer/hole lists, coordinates, PnIndex, nullable Closed, bounds, volume and closed damage tags are explicit. Repeated closing/consecutive vertices are now `expected: qualified`, `qualification: normal-backend-only`; they do not impose supported behavior without a separately chosen justified normalization policy. Six remaining baseline rows are supported geometric-contract inputs.

`polygonal-neutral-oracle.py` reuses the owned interface and stores fresh results under `🗑️generated/polygonal-neutral`. The authored through-hole prism has 16 vertices, 32 triangles, bounds [0,0,0] to [4,4,2], signed volume 24 and zero EXPRESS diagnostics. A declared-closed missing-face box passes formal EXPRESS and produces ten triangles; its geometric closed-shell contract is nevertheless false. Nonplanar and crossing faces also pass formal EXPRESS and the permissive normal backend returns meshes, illustrating why neither result establishes the informal geometric rules. Zero and negative indices produce an IfcPositiveInteger rule diagnostic and empty mesh; out-of-range CoordIndex and PnIndex references pass formal EXPRESS but produce empty meshes. Fractional integer construction refuses before a physical file is emitted (`Attribute not set`); no exact fractional physical input or zero-diagnostic acceptance is claimed. Three deliberately wrong-role/duplicate-reference damage rows are not externally constructed by this interface and have explicit notConstructed records. Root production tests must apply those damage tags to the genuine declaration roles, rather than infer oracle proof.

Primary informal proposition requires unique geometric faces, every edge used twice, and normals away from material for Closed true. It does not say distinct coordinate-list indices must mean different geometric points. Exact geometric alias indexing should therefore remain a private validation projection, leaving the source coordinate/index roster intact; no epsilon welding or general self-intersection cleanup is authorized. False/unset surfaces should not be subjected to closed-volume admission. Every script has exited; there are no live file mappings from this work.
