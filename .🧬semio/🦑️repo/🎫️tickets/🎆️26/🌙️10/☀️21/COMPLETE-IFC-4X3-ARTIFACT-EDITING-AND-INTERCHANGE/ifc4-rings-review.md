# IFC4 Rings Review

Read-only review 2026-10-21 of geometry/🕳️rings/{🟦️.ts,🔣️.json,🧪️tests/*}. Main reports six groups passing Three differential; this review did not rerun them. The earlier profile review is complete in ifc4-profile-review.md. No implementation changes.

## Actionable Findings

**P2: Simplified cap boundaries are not reusable as original solid boundaries.** The input.map normalization line removes all intermediate collinear points and the repeated closing endpoint, but the return value exposes triangles only. For input vertices [(0,0),(5,0),(10,0),(10,10),(0,10)] and ring [0,1,2,3,4], vertex 1 is removed; the cap contains edge 0–2. An extrusion constructing side quads from the original ring instead has edges 0–1 and 1–2. This creates a T junction and fails closed edge-incidence despite visually correct coverage. The module's own boundary checks use the already simplified ring so cannot detect this. Fix by retaining boundary vertices in cap triangulation (possibly splitting triangles after ear clipping), or return the normalized rings and require every adjoining surface to use exactly those boundaries. For IFC BRep faces, independent per-face simplification also risks differing segmentation on shared shell edges, so preserving caller boundary segmentation is the safer general contract. Add a full extrusion manifold regression with collinear outer and inner ring vertices before wiring this in.

**P2: Near-collinear geometry is silently changed rather than refused as ill-conditioned.** The same normalization removes b whenever on(a,c,b) is true; on accepts abs(cross)<=128*Number.EPSILON. Thus unit-scale [(0,0),(.5,-1e-14),(1,0),(1,1),(0,1)] loses its real middle vertex and produces a straight bottom boundary. The schema lists ill-conditioned predicate as invalid, yet this path does not refuse; it normalizes a noncollinear boundary. Preserve exact nonzero turns with robust orientation or explicitly reject uncertain nonzero tests instead of flattening them. The coverage/postchecks compare against normalized rings and therefore conceal this alteration. Add an uncertain-turn case that demands a documented refusal or preserves the vertex; do not accept only total-area agreement.

## Control Observations

Predicate/intersection/bridge/ear loops consistently tick and exceptions propagate; no swallowed cancellation was found. Several linear operations occur between ticks: normalize Map traversal, spread/slice copying, reverse, boundary Set construction, final winding map; hole sorting comparator has no tick. This is smaller than the budgeted quadratic validation work and not a correctness blocker for current bounded fixtures, but the JSON wording claiming every coverage/validation step ticks is stronger than implementation. Tick the normalized-point and boundary construction loops, and admit bounded sizes/capacity before large array allocations. Avoid presenting this synchronous routine as cooperatively resumable: callback cancellation is implemented; resumption/yield checkpointing is not.

## Coverage Gaps

The four valid vectors are all z=0. Equal-angle scale tests at 1e-120/1e120 verify uniform scale conditioning but not aspect-ratio, large translation, tilted plane, or non-axis plane behavior. Add x/y projection planes and an oblique plane, independent reverse winding per hole, holes with equal leftmost x/y, three or more holes, long/short edges and near-tangent gaps, exact adjacent collinear/backtracking invalidity, duplicate nonadjacent vertices, collinear cap/side manifold incidence, and explicit nonfinite/out-of-range indices. Cancellation-at-every-tick currently exercises only the central-square-hole case, not bridges involving multiple holes or removal normalization.

The Three differential checks independently assert each result area equals fixture area. They do not compare their filled triangle unions, preserved boundary edges, triangle count/topology, reversed output orientation, or hole exclusion edge intersections. Existing module postchecks are strong (normalized boundary edge incidence plus crossing-edge checks), but differential tests should independently test those properties so a shared implementation bug is observable. In particular source-boundary preservation is currently absent from both expected schema and oracle checks.

## Scope / Positive Evidence

The routine uses a common translated/scaled projection plane; validates each ring, cross-ring intersection, outer containment and nested holes; visibility-checks bridges against all boundaries and merged bridges; preserves requested outer winding; checks coverage, edge incidence and triangle crossings. This is materially stronger than merely clipping an unvalidated concatenated ring. No proven missed-hole or accepted overlapping-triangle case was found by static inspection. Do not widen claims beyond accepted finite well-conditioned polygonal rings.

Read-only execution probes were not run: node_repl forbids dynamic data imports and string code generation, and importing its TypeScript package entry exposed no compiler API. No source or test artifact was generated to work around that boundary.
