# Triangulation Admission Implementation Plan

The actual public consumer red run contains 79 tests: 27 pass, 52 fail, 578 assertions, exit 1. The preceding neutral32 consumer run contained 23 pass, 13 fail. Both ran before production changes. Logs are generated output in `🗑️generated`.

The implementation will read every attribute through the captured original catalog query index and verify exact current simple declaration arity. A staged evaluator preserves the actual `vertices`, `pn-indices`, and `triangles` progress boundaries and adds source, normals, and validation boundaries. Original controls, finite grants, and caller failure identity govern all stages.

All present coordinate/normal rows and PnIndex entries require their actual source carriers and domains. CoordIndex refers to the raw normal domain and optionally resolves coordinates through PnIndex. Optional unset, BOOLEAN, and present empty aggregates remain distinct. There is no invented unit-normal or total cardinality equality rule.

Output retains every source coordinate occurrence. A separate exact coordinate key is permitted only for private Closed=true geometric validation. It does not weld by epsilon or alter source identity. Open/unknown inputs receive per-triangle input checks without closed-solid or global self-intersection claims. Closed inputs use the existing shared cooperative solid validator after private normalization. Output reservation occurs before array growth.

Four unchanged official triangulations are pinned by hash, including both beams. Canonical coordinate edits, both inverse forms, STEP, actual GLB, source immutability, malformed source declarations, open crossing faces, and normal/validation observer refusals are covered. Native execution and full MVD certification remain unproven.
