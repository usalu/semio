# Owned and Cooperative TypeScript STEP Exchange

The STEP entry points now share small colocated control, source, reader, header, scalar and writer modules. Import scans trivia, raw source, Unicode groups, identifiers and binary literals at real bounded checkpoints. A sparse offset map preserves original positions when ignored control octets occur inside tokens. Print directives work between tokens and inside strings/binaries; literal doubled backslashes remain literal. Exponents require a decimal mantissa. Explicit finite value/entity/depth/numeric-token budgets are admitted before callbacks. The original signal and callback are captured, so replacing the caller's options cannot detach cancellation.

Export captures and admits a private graph through the central authority before writing. It validates mandatory header structure and all Unicode strings before the first output chunk. `writeIfc4x3StepChunks` emits at most 4096 UTF-16 code units per chunk, including a single large aggregate. Text progress uses total zero when output length is unknown. The ordinary string-returning API collects this same stream. Consumers of the chunk interface must wait for successful iterator completion before publishing output. The synchronous single-value formatter remains an explicit borrowed reference utility; it is not the active document producer. JavaScript host intrinsic/string allocation and garbage collection are not claimed as native physical grant/retirement proofs.

The neutral cases/feature and initially failing test preceded implementation. Final focused verification passed **31 tests / 209 assertions** across control, original STEP and MVD header suites, including source alias isolation after admission, five interior cancellation phases, original signal retention, depth parity and original error offsets. Strict targeted TypeScript compilation passed. Package registration and public chunk API exports are present. All **46 original official files** still pass the full corpus contract: **47 tests / 462 assertions**, including the retained original invalid-person baseline. No official source file was changed. Only the invalid handcrafted synthetic empty author/organisation lists were corrected.

The independent scripts generated twelve actual IFC property models, including 16,384-element list/Unicode/binary stress cases and an exact integer above 2^53. All twelve independently emitted IfcOpenShell **0.9.0.post1** models reimported to the exact owned graph; 137 chunks matched ordinary output. All seven lexical-result populations also matched explicit native IfcOpenShell authoring. Eleven owned outputs completed full EXPRESS validation with zero errors. Both original/owned long-list EXPRESS checks exceeded the explicit 20-second per-input bound; that population equality passed but EXPRESS completion is unestablished. An earlier unbounded long-list oracle process was stopped and replaced by bounded subprocess validation.

IfcOpenShell's raw-source interpretation agreed for eight models and differed for four: it retains C0 characters inside a string, interprets print-directive characters as binary digits, and returns zero source entities for directives inside a Unicode group or before a record. These are retained diagnostic differences, not silently changed expectations. Completed evidence comes from ten completed per-case rows before the initial source-count assertion stopped that run, followed by an explicit two-case follow-up. `step-control-evidence.py` collects these rows with current retained file hashes; the interrupted full run is not described as a passing run.

Normative interpretation follows [ISO 10303-21](https://steptools.com/stds/step/IS_final_p21e3.html), clauses 5.2/5.6, 8.1/8.2 and 13: ignored nonalphabet controls can occur within tokens, mandatory headers are ordered and typed, and print controls are permitted in strings/binaries and between tokens. This stage does not establish timestamp/string-width validity, complete physical complex mapping, full MVD conformance or native codec parity. Shared Rust lexical handling still needs the same print/control cases and all ISO 8859 pages; its current source explicitly refuses pages B–I. Native authentic compilation and host execution remain open goal work.
