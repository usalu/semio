# Natural glTF JSON Rules

[Khronos glTF 2.0 section 2.7](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#json-encoding) does not impose a JSON subset. It says clients SHOULD let later duplicate members override earlier values; integer-valued properties MAY use integral decimal or exponent spellings. BOM handling follows RFC 8259 recommendations, permitting clients to ignore a UTF8 BOM. These are natural glTF rules, distinct from the strict unique-member policy of owned native artifact Pack envelopes.

The TypeScript GLB boundary already uses JSON.parse, a fatal UTF8 TextDecoder and the existing native glTF document parser, so these semantics are retained as closed neutral cases without replacing them with guessed strict rules. Existing cold Rust glTF import uses generic JsonMemberPolicy::Reject and may not match the duplicate/BOM/integral-number cases. The High interchange worker was given the exact primary-source distinction for the new genuine original-owned natural GLB receiver; the cold generic parser is not used to certify that behavior.

The final neutral case contract has five accepted cases and three refusals: integral decimal/exponent, supported BOM, effective last duplicate value, supported/unsupported minimum version and nonintegral numeric refusal. A test first exposed the GLB reader admitting an effective `asset.version` of 1.0. A further direct-route test exposed export accepting 1.0 and geometry import ignoring an unsupported minimum version. One private supported-version predicate now admits version 2.0 with absent or 2.0 minimum across reading, writing and geometry import.

The retained `gltf-json-oracle.ts` compares all eight physical JSON cases against the official Khronos validator `2.0.0-dev.3.10`. It agrees on integral numbers, duplicate last-member interpretation, fractional refusal and incompatible versions/minimum versions. The validator reports a producer INVALID_JSON error for the BOM case, whereas the client deliberately ignores it under the allowed RFC behavior; this difference is explicit and is not called a passing producer conformance check. All eight interpretation cases and the direct-route regression pass; the complete focused glTF suites pass **49 tests / 152 assertions**, with strict TypeScript checking and closed-schema validation passing.

During integration, two prior schema tests briefly failed because a concurrent shared-domain reference callback changed from a boolean to retained generator steps. The concurrent worker updated the new4x3 callback before root's patch; root preserved that correction and reran current source successfully. No enforcement was removed or compatibility wrapper added. Native natural JSON execution remains the High interchange worker's open owned-pipeline work.
