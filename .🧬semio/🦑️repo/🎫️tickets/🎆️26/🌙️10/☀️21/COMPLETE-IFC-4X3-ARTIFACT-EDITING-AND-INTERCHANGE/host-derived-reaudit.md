## Actionable Findings

1. **P1 — Cancellation drops displaced native owners outside controlled close.** `🔎️details/🦀️.rs:170` moves the complete original argument vector into local `old` with `mem::take(args)`. Loop cancellation at line 173 returns through `?` before `garbage.extend(old):193`. The copied entity no longer owns those values, and IfcDetailsWork's garbage/source/cursors cannot retire them: normal Rust unwinding drops the potentially large original values synchronously. Fix by installing the old argument vector into work-held retirement custody before the first fallible cancellation check, then extracting reusable slots from that custodied owner. A work-held displaced argument vector/slot collection must survive both success and error.

   The analogous mutation-owner problem occurs in `owned_entity_edit`: local `mutations:220` receives moved values at lines 260-261, then later ticks can fail (for example while normalizing complex parts at lines 264-272). Those moved values are no longer in the copied entity or garbage. `work.rs:231` returns through `?`, and `self.pending = Some(mutations):233` is reached only on complete success. Install pending mutations in work custody before reduction begins and mutate that owner in place, or return an error together with every owned partial result. Cancellation tests should interrupt after at least one large argument has moved into a mutation, then verify controlled close owns/releases every displaced value under tight release/depth grants. Existing cancellation-before-clone-completion coverage does not exercise this final-reduction failure.

   The direct fallback helpers have the same local-owner shape (`normalize_complex_changes:1293` local primary vector; `entity_changes:1336` local mutation vector). Source-owned preparation should avoid entering a fallible fallback with large local owners or preserve those owners explicitly too. This is a concrete cancellation-ownership defect, separate from the report's acknowledged synchronous Vec shifts/allocation work.

2. **P2 — A generated replacement GlobalId can be omitted from retained primary mutations.** In root compact retyping, `retype_arguments` marks an existing same-position/same-domain String as unchanged, even if it is the empty GlobalId. `populate_global_ids:246` then generates a new value, but lines 255-258 skip every slot whose earlier `changed` flag is false. An imported entity with empty GlobalId therefore keeps its empty value after same-type selection, although the copied entity briefly owns a generated replacement; direct reduction and retained preparation differ. Update changed flags after GlobalId population, or generate required replacement identities before final delta classification. Add an empty-GlobalId same-primary compact request case comparing direct and retained emissions/inverse.
