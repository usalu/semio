# Arithmetic Source-Isolation Before Observation

The new28-case arithmetic corpus has a genuine first public29-test result27pass/2fail in generated/issued-arithmetic-first.txt. Both negative ScalarTimesVector cases return the expected result but mutate the semantic source context: DirectionRatios of source#4 and source#8 become negative; the latter is also observed through the shared orientations of source vectors#11/#12. The original raw IfcSnapshot was not shown mutated. This is not an output-comparator or signed-zero artifact.

No evaluator/population source has been edited. evaluator.copy currently copies aggregates but returns entity references, and local attribute/index assignment mutates those referenced objects. The original call-bound argument objects are consequently reachable from the context's source entity map. A blanket change making every entity assignment value-copy is not justified: entity-reference aliasing inside procedural scopes is distinct from persistent-domain isolation and must be preserved.

The official [ISO publication metadata](https://www.iso.org/standard/38047.html) identifies ISO10303-11:2004 but exposes no relevant normative body through that page. A third-party hosted [10-page ISO-branded sample](https://www.elecenghub.com/NewSamples/ISO/174364973/ISO-10303-11-2004-2.pdf), pages121–122, gives both executable-domain isolation in13 and reference assignment semantics in13.3.1. Its hosting authenticity has not been independently established, so it is corroborating candidate text rather than a claimed authenticated normative acquisition. The relevant contrast supports investigating per-evaluation/function ownership or overlays, without guessing a general entity-copy rule. Only this short wording is quoted: “These statements do not affect the entity instances within the domain”.

The pinned IFC ScalarTimesVector body is actually read and contains local entity V assignment followed by negative-scalar indexed DirectionRatios writes. Any correction must let local transient aliases observe valid writes, preserve entity identity and qualified attribute behavior, and prevent changes to the canonical source context. Deep cloning an entire reachable population per function would create the performance/ownership problem the current goal forbids. An original-controlled lazy local view or equivalent proper semantic scope requires design and test evidence; no such implementation is claimed yet.

Next evidence is the actual independent fresh-model helper behavior, scalar/ordered SQL arithmetic, sequential repeated-call observations and alias/identity laws. An external difference alone will not decide the normative contract. Native flags, source-publication gates and all existing owned freezes remain unchanged.
