# I-Profile Source And Unknown Parameter Research

i-profile-source-research.py retrieves the pinned released primary page and reads exact ADD2 metadata/original source through a test-only owned oracle. The normal web open failed with a cache miss; the standard-library retrieval succeeded and saved original HTML/text under generated/i-profile. No source asset, native route or runtime dependency changed. Primary URL is [IfcIShapeProfileDef](https://raw.githubusercontent.com/buildingSMART/Standards-builds/610ee3f95db9d0380b1eb8de4dc6e17833531518/IFC/RELEASE/IFC4_3/HTML/lexical/IfcIShapeProfileDef.htm), SHA2565a26bdd84ffab0b3dee34ddae1e01bbf8aabbbbc473a1b7adcd37b068ab92bbd.

The current declaration has ten explicit inherited/local slots: ProfileType, ProfileName, optional Position, OverallWidth/OverallDepth/WebThickness/FlangeThickness, optional FilletRadius/FlangeEdgeRadius/FlangeSlope. The four mandatory dimensions are positive; web is thinner than width and twice flange thickness is less than depth. A specified fillet radius is nonnegative and bounded by half the available flange width and web height. Position belongs to IfcParameterizedProfileDef, the basic name/type to IfcProfileDef, and the dimensional/radius/slope fields to IfcIShapeProfileDef. Each defined fillet applies equally to the four web/flange corners.

Crucial source semantics: an omitted radius/slope is unknown. Explicit zero denotes a sharp edge or parallel flange. Therefore treating optional fields as implicit zero would silently change a valid source's information. The unchanged official column-extruded-solid.ifc (SHA256e5ada0a5883b0fced6128c25eac53b0b4b1cd23ad2dc3a821d24442558a98ae0) has profile202: width100mm, depth200mm, web5.6mm, flange8.5mm, fillet12mm; FlangeEdgeRadius and FlangeSlope are omitted. Its ProfileName is human-readable IPE200, not an authenticated geometry lookup. Prior external normal mesh80v156t/volume.005704395594288147 is a mesher observation, not proof that unknown edge/slope values equal zero.

Any future I-profile evaluator must either require explicit geometric parameters or expose an explicit nominal visualization policy with a diagnostic/fidelity distinction. It must preserve unknown source values and canonical edits; no fixture repair, parameter inference from ProfileName, default-zero mutation or full exact-geometry claim is justified. Original-source testing should verify this distinction, with explicit fully defined authored cases separately exercising fillets and slopes. A partial step which only renders the twelve sharp I corners would also lose the original known12mm fillet and is not acceptable.

The existing captured curve policy uses explicit SI absolute/relative chord error and a segment grant, with a normal world-basis radius bound; future corner arcs should reuse that policy and reserve the complete profile/sweep output before growth. A circular arc chord certificate is distinct from transform/coordinate rounding and GLB float precision.
