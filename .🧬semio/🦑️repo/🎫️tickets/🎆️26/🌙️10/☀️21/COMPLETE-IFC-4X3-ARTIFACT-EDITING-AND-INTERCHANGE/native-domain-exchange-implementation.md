## Supported Mapping and Refusals

All controlled domain routes declare `IoFidelity::Lossy`. Unsupported necessary semantics return an error before a destination is published. An error does not carry a partly usable destination. Input snapshots are borrowed and remain unchanged; successful projections return fresh snapshots/packs.

Explicit property-unit admission is intentionally smaller than the complete schema. BIM length overrides support metre, millimetre, centimetre, decimetre and kilometre; other explicit prefixes/conversion-based units refuse. Admitted SI engineering names are metre, square metre, gram, pascal and newton; the supported derived tags are mass density, moment of inertia, linear force and torque. Engineering values require resolved scale exactly 1. Square-metre prefixes are squared. A mere matching tag does not admit wrong dimensions.

## Actual Output Owners and Receiving APIs

BIM uses `semio_s_artifact_bim_model_snapshot::standards::v1::subsets::any::schema::snapshot::ModelSnapshot` and source-owned schema `Point2`, Site/Building/Storey records. `ModelSnapshot::decode_native_snapshot`/`encode_native_snapshot` receive/publish packs with the original caller controls; normal pure composers use its actual `ArtifactPack` implementation.

FEM uses `semio_s_artifact_fem_3d_model::...::snapshot::Fem3dSnapshot` as the **host output type**, including actual persistent sealed nodes/materials. Its source-owned `Fem3dSnapshotValue` is the existing explicit canonical authoring interface, not a new parallel snapshot. `native_domains::fem_reference_pack` obtains that type's authored record/spec and writes the native envelope through repository-owned pack APIs; `receive_fem` then calls actual `Fem3dSnapshot::decode_native_snapshot` with the original decoder. Final output uses actual `Fem3dSnapshot::encode_native_snapshot` with the original encoder. Pure composer receiving uses the same native pack through `Fem3dSnapshot::decode_pack`. No private sealed constructor, invented plain-Vec native snapshot, JSON conversion or fresh caller authority was introduced.

Upstream native FEM ownership is currently inconsistent in checked-in source: `Fem3dSnapshot` contains persistent owned rows and no longer derives `DslRecord`, while its existing codec calls `__dsl_from_record_controlled`, and `Fem3dArtifact::to_snapshot` still assigns plain authoring Vec rows. Those foreign owner files were not changed. This is a concrete additional reason that native route type correctness/receiving cannot be claimed from syntax checks; the public codec boundary must be restored/validated by its owner before execution can establish it. The exchange tests intentionally use that real boundary rather than substituting a fake host snapshot.

## Registration and Capability Identity

`native_exchange::domains::entries()` supplies four normal composers: ADD2↔BIM and ADD2↔FEM3d. IFC root declaration includes them, and existing root registry discovery/register paths include them. Existing normal IFC contribution assembly registers the combined controlled IO entries, now seven total (three geometry/carrier and four domain). New exact central foreign claims are `17:s.stdio.ifc@4x3/*15:s.bim.model@1/*` and `17:s.stdio.ifc@4x3/*15:s.fem.fem3d@1/*`; reverse output uses IFC's existing owned ADD2 dialect capability.

The stdio contribution dependency roster was not given BIM/FEM plugin kinds: that roster validates only its selected stdio definitions. Runtime model crate dependencies and exact foreign route claims are explicit; a host viewing/operating the foreign target still needs that artifact plugin's normal definitions/codecs. Registration during old-root assembly still precedes the general plugin transaction, as documented in the prior native report; these entries do not gain transactional rollback merely by being registered.

## Progress, Closure and Publication Limits

All domain graph/relationship/property/unit, spatial-level, node/member and engineering loops checkpoint original caller authority. Shared relationship indexes avoid repeated whole-graph scans; ordered per-building level maps avoid quadratic storey elevation summation. Membership/engineering caches preserve canonical references. Entity/relationship/value/unit/depth bounds are explicit. Native input pure-composer domain packs have a 64 MiB source byte admission; target domain entity counts cap at 64,000. Source graph indexing caps at one million entities/two million expanded relationship memberships, and graph value validation at four million values.

The new computations are not fully owned cursor jobs: maps/vectors, reference authoring records, the FEM intermediate record/pack and existing synchronous codecs still allocate temporary ownership outside fully funded resumable receivers. Some existing owner admission methods are synchronous calls with checks before/after. Native codec receiving/publication uses original decode/encode ledgers, but that does not fund every domain temporary or prove terminal cleanup under every cancelled frontier. Ordinary Rust temporary destruction currently closes those intermediate objects. No strict per-step byte/retirement/latency proof is claimed.

These routes create a new artifact snapshot/pack. They do not produce a native edit-event/diff transaction or mutate an existing shared destination. Final host candidate/diff/event publication remains the existing host's responsibility and has not been exercised here. Source immutability and atomic return shapes do not prove host event publication, multi-user rollback or cancellation between an external successful route and its later commit.
