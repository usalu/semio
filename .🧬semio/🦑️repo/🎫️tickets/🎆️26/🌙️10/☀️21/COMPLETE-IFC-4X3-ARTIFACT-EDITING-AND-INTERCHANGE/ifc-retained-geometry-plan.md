# Retained IFC Geometry Preparation Plan

## Current failure and feasible route

The IFC4/IFC2x3 render_context wrappers currently call project_controlled from the first entity on every render, cap its total work to cx.fuel_remaining, and discard incomplete geometry. Measured full source projection uses819892 ticks for the official bath and about4.3m for official slab openings. These are algorithm work measurements, not evidence that either always fails a real host render: actual mounted render grants/deadlines still need exact source tracing. The proven gap is that any caller Limit unwinds and discards the frontier, so a subsequent render repeats the same prefix. Raising total limits or starting an unconstrained replacement StepContext is not a retained solution.

Framework infrastructure already exists: ArtifactApp/ArtifactViewer/ArtifactEditor mounted preparation, maintenance, close-demand and close-step hooks; AppRenderOperationContext pins instance/base revision/generation/canonical revision/policy; MountedOwnerTurnV1 intersects actual per-turn CPU and physical grants and checks receipts; ArtifactPendingView.take_snapshot_read owns an original immutable SnapshotRead lease. ArtifactInstanceOperationOwnerHandle provides typed instance state and controlled-retirement inference sessions. Job StepContext preserves original source parent, cancellation, clock/deadline and retained recipient. Payload publication already has RetainedPayloadBuilder/RetainedJobPublication and native borrowed JsonWriteCursor; use those, not an IFC JSON writer.

Critical integration fact from the independent runtime audit: the ordinary render view is constructed with no snapshot-read lease. Only pending-effects preparation conditionally obtains one through mounted_job_prepare_snapshot_read. The route must admit/capture work in the pending preparation path, step it in mounted maintenance, and let render observe prepared output. Rendering may not assume doc.take_snapshot_read succeeds, clone the entire current snapshot or seed an independent operation.

No reusable native stackful coroutine was found. TypeScript continuation scheduler only queues the next turn; Rust Future::poll wrappers meter the poll but do not suspend a synchronous recursive projector. Existing BRep TessellationJob uses explicit phase/cursors, but face triangulation is a coarse indivisible unit and its cold cleanup convenience is not suitable as IFC interactive execution. Therefore the IFC inner loops must retain explicit real frontiers. A cache wrapper around the present one-shot call would repeat work and fail this goal.

## Smallest end-to-end retained slice

1. Add schema-first source/revision identity, limits, progress and phase contracts under shared IFC geometry retained preparation, with neutral traces for admission, short/zero turns, cancellation, stale source, byte refusals and close. Source identity is the framework captured revision plus original immutable source lease, never content guessed from a current mutable graph. Shared graph reads reborrow the captured source on each step; persistent state stores entity ordinals/IDs, not self-referential borrowed GeometryEntity views.
2. Implement a small concrete retained cursor for source intake/index plus placed Block and rectangle extrusion, complete payload preparation and controlled close. Every point/index/label byte/allocation/frontier transition is bounded, including source labels and final JSON. This first vertical fixture must complete after many ordinary short grants without restarting and match the current independent Three output. It is a foundation, not an official-bath completion claim.
3. Generalize representation/profile frontiers while preserving one algorithm path: replace recursive dispatch with an explicit frame stack; retain profile sampling, ring triangulation/ear search, output mesh append and resource-limit frontiers. Move the existing one-shot façade to drive the same cursor under supplied finite limits rather than retain duplicate engines. No per-product whole synchronous evaluation may hide under one tick.
4. Convert the shared Boolean engine to a flat indexed BSP arena plus explicit split/build/clip/invert/collect stacks; admission validation, vertex weld/index, shell traversal/intersection checks, sorting, conforming triangulation and result conversion each retain loop frontiers. Source product/opening assembly waits for its pending Boolean owner; only complete products become eligible, and the visible whole output remains unpublished until final preparation completes. This phase is required for the official bath/slab, not optional.
5. Reuse the native borrowed JSON cursor/paged payload publication for mesh, instance and status bytes. Keep complete output privately pinned until all streams and camera validation finish; publish the exact captured revision once. Selection changes can rebind current interaction without recomputing geometry when source identity is unchanged. Stale revision closes prior work before admitting the next source; no uncaptured mutable reads.
6. Integrate both real IFC4 and IFC2x3 viewers/editors through their mounted hooks and prepared render observation. Only then remove repeated project_controlled calls from normal render. Host close/cancel and revision replacement must grant-drain every source/scratch/result/payload owner; no Drop of a large partial owner or unbounded cleanup loop.

## Original authority and memory

Each step borrows the actual original StepContext and its unspent RetainedCloneGrant. A session-wide maximum work counter remains distinct from turn fuel: Yield preserves the same frontier; terminal Limited means the declared operation cap was exhausted. No new independent context, worker-thread bypass, asyncThread or enlarged global grant. Demand is descriptive only. All allocations/copies/releases are preadmitted and report actual bytes once. Use first-party paged/retained collections and controlled retirement, not wholesale Vec/HashMap drop. Source and result byte policies are separate from per-turn copy/capacity/release grants; reject oversized captured input/result explicitly before publication. Fixed source/revision/operation identity is checked on every resume and close. The original source lease stays held until granted close of its concrete producer.

## Tests and gates

Neutral fixtures must run with one-unit/zero-unit/short grants, preserve monotone work/phase/frontier, and prove that completed prefixes are not recomputed. Each logical phase is cancelled and stale-invalidated; each byte currency is independently withheld; exact terminal-empty witnesses are asserted after granted close. Capture identity/source mutation tests prove output remains from the admitted revision. Complete retained output must byte/mesh match the same shared one-shot finite façade and independent existing Three solid geometry; authored Manifold/native gates stay honest. Official bath and slab must finish with real short turns before claiming this retained geometry task complete. Unsupported shapes remain truthful; no fake box, guessed result, completed-unchanged host or new dependency.

Native package execution is still gated by repo cache case-sensitivity access denied. Actual TS source evaluation is available and will exercise permanent tests. Native source and authored lifecycle regression syntax/type review do not substitute for native compile/runtime.

## Coordination boundary

## Concrete budget trace

The plugin runtime surface-render entry accepts a borrowed StepContext and forwards it through VcsArtifactApp.render into ArtifactApp.render_with_request_context; it mints no local render budget. The host original-root issued_budget uses policy.turn_fuel.min(initiating remaining fuel), the original absolute deadline and remaining retained policy. Therefore neither the 7500 public tool-contract value nor an algorithm tick count alone establishes actual render-default failure. Short-turn fixture grants will prove resumability independently of embedding policy. Controlled inference admission also retains an ArtifactInferenceSessionAccess across phases and pins its source/op/gen/name: recreating access locally each render would repeat admission, while reusing access under another context is refused.

The first owned preparation request schema and neutral lifecycle/cap/identity vectors are now authored under shared geometry/🧵️prepare; production algorithm and host integration remain untouched pending coordination.
