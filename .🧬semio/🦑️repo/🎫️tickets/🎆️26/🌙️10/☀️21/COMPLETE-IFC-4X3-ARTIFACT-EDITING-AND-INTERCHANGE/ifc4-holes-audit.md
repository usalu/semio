# IFC4 Holes Audit

Read-only source and primary-source research, 2026-10-21. No implementation or build files changed.

## Current Implementation

IFC4 any/🧬️schema/📐️geometry/{🟦️.ts,🦀️.rs} own the projector. TypeScript polygon(mesh, indices) computes a Newell-equivalent fan normal, drops its dominant axis, checks outer-ring planarity, and ear-clips a single index ring. Convexity and containment use fixed 1e-12 epsilon. It neither accepts inner rings nor validates cross-ring topology. A stuck ear reports non-simple-polygon, but a successful ear sequence alone does not establish a simple input polygon.

face() refuses multiple bounds with unsupported-face-with-holes. profile() supports rectangle and arbitrary closed polyline only; IFCARBITRARYPROFILEDEFWITHVOIDS is refused. faceSet() only reads ordinary IFCINDEXEDPOLYGONALFACE outer indices. Existing tests are neutral geometry vectors plus cancellation, budgets, real payload identity, wide ids and repeated-extrusion shared-vertex correctness. The new behavior must retain atomic product failure: no partial mesh after invalid hole topology, cancellation or limits.

## Correct Own Multi-Ring Slice

Use one first-party polygon triangulation routine for polygonal faces, polygonal BRep face bounds and extruded caps, taking outer ring plus inner rings of original mesh vertex ids. Keep one projection plane selected from outer normal, translating by an origin and scaling coordinates into a bounded local range before predicates. Validate every ring in this common plane, not each ring independently. Use consistent orientation predicates with scale-aware error bounds or an adaptive exact-sign fallback; fixed absolute tolerances fail tiny/huge or nearly collinear geometry.

Before triangulation, reject fewer than three distinct vertices, zero-length edges, degenerate area, nonplanarity, self intersections (including non-adjacent touching), ring intersections/tangencies, a hole outside/on the outer boundary, overlapping holes, and nested holes. Preserve a distinct diagnostic for invalid input versus unsupported curve type. Remove only harmless duplicate closing endpoints and strictly collinear intermediate vertices where topology remains unchanged. Normalize outer CCW and holes CW in projected coordinates, retaining the desired original face normal for emitted triangle orientation.

Bridge holes deterministically (leftmost hole vertex, holes ordered by x/y/id; visibility-tested bridge into current boundary), duplicating bridge endpoint nodes in a linked ring while retaining original vertex ids. A bridge must remain in filled polygon interior and intersect no boundary/previous bridge except permitted endpoint contact. Choose a visible vertex using segment/ray intersection and local-cone tests; nearest arbitrary vertex is incorrect for concave boundaries. Ear clipping the resulting weakly simple boundary needs node identity distinct from vertex id and must explicitly handle bridge duplicates: current triangle.includes(vertexId) and inclusive containment can reject valid ears or hide invalid intersections. Do not simply concatenate rings or feed duplicate bridges to the unchanged single-ring ear loop.

After triangulation, verify nondegenerate triangles, consistent winding, filled-domain containment, area equal to outer-minus-holes within a documented scale-relative bound, preserved boundary coverage and expected topology. Area equality alone cannot prove no overlapping triangles/gaps. For simple no-Steiner rings with N total original vertices and H holes, triangle count is N+2H-2; account explicitly for removed collinear vertices. All predicate, visibility, intersection, ear and postcheck loops consume tick() work budget and respond to cancellation.

Extrusion: caps use the shared multi-ring triangulator; each outer and inner boundary receives side quads, with opposite ring winding producing inward-facing void walls. Reverse cap orientation for negative extrusion direction as existing code does, then apply mapped/reflection winding handling once. Test signed volume = (outer area - sum hole areas) * normal extrusion component, plus manifold edge incidence. This slice does not implement IFCRELVOIDSELEMENT Boolean subtraction.

## Independent Existing Oracle

Root package.json already declares three (^0.182.0), polygon-clipping 0.15.7, d3-polygon 3.0.1 and manifold-3d 3.5.1 as development dependencies. Confirmed local node_modules/three/src/extras/ShapeUtils.js implements ShapeUtils.triangulateShape(contour, holes) using its bundled Earcut. No standalone node_modules/earcut exists. Use public Three ShapeUtils and Vector2 through a test-only reference interface; no new runtime dependency is needed. Compare coverage/area/winding/topology, not exact diagonal ordering. Existing test-only IfcOpenShell oracle remains appropriate for full official IFC projected area/volume. [Earcut primary documentation](https://github.com/mapbox/earcut) states its algorithm assumes valid polygon rings and does not guarantee arbitrary invalid input correctness; therefore it is a differential oracle for accepted valid cases, not the validity definition.

Neutral tests should include concave outer + 1/2/3 holes, concave holes, reversed input windings, hole bridge ray through an outer vertex, holes with equal leftmost x, retained indexed PnIndex remapping, mirrored/nonuniform placements, oblique/negative extrusion, all three projection planes, many collinear points, tiny/large coordinate scales, translated large-world coordinates, invalid outside/nested/overlapping/touching/crossing/nonplanar holes, and budget/cancel at every stage. Triangle centroid-outside-hole tests alone miss triangles crossing a hole.

## Verified Official Sources

- [IFC4 Add2 TC1 polygonal face tessellation SPF markup](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/annex/annex-e/polygonal-face-tessellation.ifc.htm) was fetched successfully and contains IFC4 FILE_SCHEMA, indexed face with one void (#21), point list #15, polygonal set #27, Body #28 and proxy #30. Exact raw SPF companion: https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/annex/annex-e/polygonal-face-tessellation.ifc (the raw endpoint was not separately downloaded in this audit). This is the best immediate unchanged official file fixture for hole triangulation.
- [IFC4.3 current official annex source](https://standards.buildingsmart.org/IFC/RELEASE/IFC4_3/HTML/annex_e/tessellated-shape/polygonal-face-tessellation.html) also exposes the sample, but declares IFC4X3_ADD2. Do not silently change its schema and label it an unchanged IFC4 fixture.
- [Official indexed face with voids semantics](https://standards.buildingsmart.org/IFC/DEV/IFC4_2/FINAL/HTML/schema/ifcgeometricmodelresource/lexical/ifcindexedpolygonalfacewithvoids.htm) confirms opposite outer/inner winding for closed face sets and that both index sets refer through PnIndex when provided. Use target-version lexical pages in permanent documentation when available.
- [IFC4 beam extrusion SPF markup](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/annex/annex-e/beam-extruded-solid.ifc.htm) was verified. It uses arbitrary closed profile over an IfcIndexedPolyCurve containing line and arc indices, not a profile with voids; it will remain unsupported by a polyline-only hole slice.
- [Official slab openings](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/annex/annex-e/slab-openings.htm) uses separate opening elements and IfcRelVoidsElement with round opening and rectangular recess. It is NOT an IfcArbitraryProfileDefWithVoids fixture. Raw companion is https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/annex/annex-e/slab-openings.ifc (403 in this audit).
- [Official Reference View semantics](https://standards.buildingsmart.org/MVD/RELEASE/IFC4/ADD2_TC1/RV1_2/HTML/schema/views/reference-view/index.htm) explicitly requires arbitrary profiles with voids and indexed polycurve outer/inner boundaries for space body swept-solid geometry. This establishes required semantics, not an executed file fixture.

No unchanged official arbitrary-profile-with-voids SPF sample was verified during this audit. Do not describe slab-openings or beam-extruded-solid as that fixture. Add handcrafted neutral polyline-with-voids fixtures with independent Three/IfcOpenShell checks now, and record the official profile SPF coverage gap accurately. The buildingSMART community converted-spec collection advertises corrected originals at https://github.com/buildingsmart-community/ifcJSON/tree/main/Samples/IFC_4.0/BuildingSMARTSpec ; its README explicitly distinguishes corrected files from unchanged official originals, so retain provenance if using that corpus later.
