# Owned Boolean Mesh Facade and Capture Policy

This refines the source-free kernel integration plan during the154-suite hold. These are proposed first-party interfaces and test contracts; no capability or completed mesh is issued by this document.

The new maxIntermediateValues default is20,000,000 reserved logical numeric slots, with explicit positive-safe-integer validation. Capture it once before tick/progress getters and before observer invocation, alongside the existing original limits. A one-slot grant admits empty backing, while0 remains an invalid policy as fixed by the existing61 red laws. Work, polygon, depth, async cadence and callback policies retain their current independent meanings. The value limit is cumulative current ownership within one session, and cannot be renewed at each child or operator.

The intended facade is SolidBooleanEvaluation.meshBuilder(vertexCount,triangleCount), returning an opaque SolidMeshBuilder with point(index,x,y,z), triangle(index,a,b,c), seal() and close(). SolidOwnedMesh exposes only readonly vertexCount and triangleCount; its actual backing is private to the original evaluation. Sealing checks that every declared row was authored exactly once and that all references/values are closed, finite and in range. It does not skip geometric admission or certify an IFC declaration. There is no raw-mesh-plus-count factory.

Builder creation reserves checked3*vertexCount+3*triangleCount once before backing birth. Every actual point/triangle row consumes that private prepaid capacity; it never grows usedValues a second time. Unfilled rows are reserved capacity, not authored semantic defaults, and seal still requires every row. A partially filled Block builder therefore retains60 reserved slots even after only three point rows have been authored. Duplicate populated setters refuse before replacement; no transient old/new row can escape accounting. Closing the partial builder releases its complete private reservation without calling observers. Original source-query checkpoint turns remain allowed while a builder is entered; they must not reuse the active-kernel refusal path. A second builder or kernel still cannot enter concurrently, and caught observer reentrancy remains a latched failure.

SolidBooleanEvaluation.booleanOwnedSteps(operation,left,right) and halfSpaceOwnedSteps(left,plane) return the existing private generator facade with a terminal SolidOwnedMesh. Only identity-owned handles from the same session are accepted. Inputs stay owned while the kernel runs, and output construction adopts their existing permissions instead of adding another reservation for the same backings. Complete success transfers/consumes inputs into the new result owner; any failure/early return preserves entered original children for cleanup. The same live handle may occupy both operands: self-subtraction/repeated-DAG input consumption and release deduplicate exact identity. Stale or already consumed adoption refuses. Empty results are explicit zero-numeric handles, bounded by original work/handle metadata.

SolidBooleanEvaluation.releaseMesh(handle) retires an idle owned mesh, including after first failure. publishMesh(handle) explicitly transfers its actual raw SolidMesh to the caller and ends kernel permission for it. Neither method creates a schema/topology certificate. Active cursor/builder ownership blocks unsafe release/publication/session close. Kernel failure cleanup retires temporaries first, leaving input ownership observable until its caller releases it. After a borrowed operation, all private permission is retired before returning its raw result, so usedValues is0. After an owned operation, usedValues includes the resulting parent-owned mesh; it reaches0 only on explicit release/publication. peakValues remains historical in both routes.

Actual backing ownership is private and registered, never inferred from public handle counts. Count coordinate triples once per backing identity; index scalars use each actual retained numeric buffer's logical high-water slots. Source/remap/ring/triangle/cell arrays and spatial-axis coordinate/index pairs remain included, while reference-only arrays and bounded plane/frame/string-key metadata are named separately. Entered arenas may strongly retain allocated split/normalization backings until a real phase exits; those explicitly retained owners explain conservative peak rather than hiding cumulative allocation as current residency. Final compact/world transfer moves the exact finished backing permissions to the result owner, with no second geometric algorithm.
