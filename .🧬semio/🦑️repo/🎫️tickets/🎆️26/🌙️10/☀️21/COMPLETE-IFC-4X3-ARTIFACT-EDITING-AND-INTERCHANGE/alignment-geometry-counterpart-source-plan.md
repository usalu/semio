## Authenticated evidence

Pinned [released geometry concept](https://raw.githubusercontent.com/buildingSMART/Standards-builds/610ee3f95db9d0380b1eb8de4dc6e17833531518/IFC/RELEASE/IFC4_3/HTML/concepts/Product_Shape/Product_Geometric_Representation/Alignment_Geometry/Alignment_Geometry_-_Horizontal,_Vertical_and_Cant/content.html), SHA256052ef264607c967a36123caf90a609a87c263e732cc44220c1f7847d115d07a7, repeats conditional zero-length counterpart obligation. Its diagram connects alignment ProductDefinitionShape/ShapeRepresentation items to composite/gradient/segmented reference curves. Horizontal composite uses FootPrint/Curve2D; cant segmented reference uses Axis/Curve3D. Curve Segments and BaseCurve links identify representation hierarchy, but the page does not impose a universal ordinal bijection between business-list elements and curve-list positions.

Pinned [IfcAlignmentHorizontalSegment](https://raw.githubusercontent.com/buildingSMART/Standards-builds/610ee3f95db9d0380b1eb8de4dc6e17833531518/IFC/RELEASE/IFC4_3/HTML/lexical/IfcAlignmentHorizontalSegment.htm), SHA2564be8687077d036adf417fa38924c6251cee89f24026fa42f90672b60a67d7d77, describes optional associated geometry and corresponding placement. It mentions StartPlacement while released IfcCurveSegment declaration uses Placement, so do not invent a new attribute. Placement coincidence alone is not identity/counterpart proof.

Pinned [IfcCurveMeasureSelect](https://raw.githubusercontent.com/buildingSMART/Standards-builds/610ee3f95db9d0380b1eb8de4dc6e17833531518/IFC/RELEASE/IFC4_3/HTML/lexical/IfcCurveMeasureSelect.htm), SHA2561e9c1abb6bcb6707c9fef1901f227462bc490b7a86524e0647a422ea99be7aac, has branches IfcLengthMeasure and IfcParameterValue. SegmentLength is measured from SegmentStart under the selected role. For a selected actual CurveSegment, either numeric zero branch is zero; raw scalar without admitted SELECT constructor cannot establish branch. General nonzero parameter-to-length conversion requires ParentCurve semantics and is unnecessary for zero equality, but malformed/nonfinite/unknown tags remain unresolved.

Pinned [IfcAlignmentSegment](https://raw.githubusercontent.com/buildingSMART/Standards-builds/610ee3f95db9d0380b1eb8de4dc6e17833531518/IFC/RELEASE/IFC4_3/HTML/lexical/IfcAlignmentSegment.htm), SHA25680744322313fd0f5c263e2ad0b4d28d976fd101ba0491dcf5ec288a9b2a5fa04, inherits Product.Representation and directly owns DesignParameters. Its released examples link to sectioned-solid-horizontal. That gives an explicit business segment→representation path rather than matching arbitrary geometries by proximity.

## Safe next executable slice and remaining ambiguity

Start with explicitly selected terminal business segment and its own authored Representation→ProductDefinitionShape.Representations→ShapeRepresentation(accepted declared role)→CurveSegment. Resolve exact source IDs/declared attributes and preserve competing representation/item ambiguity. Check zero under actual admitted measure SELECT branch. Missing geometry may be N/A only with authenticated geometry applicability; parent alignment geometry plus absent segment representation is not proof that an arbitrary same-ordinal curve is its counterpart.

Do not generalize the example into mandatory single representation, Axis/Segment on all exchanged models, exact1:1 list cardinality, or universal business/geometry ordinal match. Released evidence inspected does not fully specify how to infer correspondence when only parent-level composite/gradient/cant representation exists and terminal business segment has no direct geometric reference. Such cases must remain unresolved until a released concept rule/official implementation agreement explicitly supplies matching policy. Needed evidence: exact machine-readable released template rules for segment shape usage and any cardinality/correspondence clauses; a pinned official cant example; authenticated treatment of allowed multi-item/mapped representations.

Fixture plan: independently parse official model IDs above and confirm two direct counterparts; authored negatives change only selected geometric length, give unrelated zero curve elsewhere, duplicate/missing direct refs, competing items/representations, malformed SELECT, both zero branches and signedzero. Keep parent-curve-only and cant cases incomplete until matching evidence is pinned. Geometry check must remain separate from existing business report and full child/view verdict. Runtime uses existing original capture/index/attribute/cancel interfaces, no external dependencies.
