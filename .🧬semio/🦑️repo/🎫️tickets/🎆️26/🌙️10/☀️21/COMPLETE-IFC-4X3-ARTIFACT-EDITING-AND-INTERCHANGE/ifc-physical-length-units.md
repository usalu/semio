# IFC Physical Length Units

This slice reads the explicitly selected IfcProject UnitsInContext using the existing borrowed native GeometryGraph. It preserves all source coordinates and returns a positive finite metres-per-source-unit factor, with explicit failure for missing, ambiguous, cyclic, dimensionally invalid or unsupported units. It does not infer metres or convert unrelated quantity units. A retained cursor indexes and resolves within caller work grants, supports yield/cancellation, and holds the same immutable graph for its lifetime.

IfcSIUnit uses inherited slots Dimensions, UnitType, Prefix, Name; IfcConversionBasedUnit adds Name and ConversionFactor to the named-unit slots; its referenced IfcMeasureWithUnit carries a typed length measure and another length unit. Each conversion must declare dimensional exponents (1,0,0,0,0,0,0). Chained scale factors must stay finite and positive. A nonzero conversion offset cannot describe linear geometric length and is refused. IFC2x3 has no offset subtype.

Primary evidence: [buildingSMART conversion-based units](https://standards.buildingsmart.org/IFC/DEV/IFC4_3/HTML/lexical/IfcConversionBasedUnit.html), [project units](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/schema/templates/project-context.htm), and [official unit declaration guide](https://technical.buildingsmart.org/wp-content/uploads/2018/06/Basic-Unit-Declaration.pdf). Existing unchanged official IFC4 imperial and millimetre fixtures are being independently audited. No new external runtime dependency is introduced. Decimal.js is used only as the independent numeric test oracle.

This resolver does not replace full EXPRESS/MVD validation or per-quantity unit overrides; integration into measurement, render-origin transforms and exchange remains explicit.
