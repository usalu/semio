# Cartesian Placement Admission And Finite Normalization

The real TypeScript geometry query now checks the placement's declared arity, exact CartesianPoint location role, Direction role and matching two/three dimensions. IFC3D Axis and RefDirection must both be supplied or both unset, as required by the pinned ADD2 AxisAndRefDirProvision rule. Supplied zero or parallel directions still refuse. Defaults apply only to unset optional values. Native selected-triangle export now enforces the same paired-provision rule before interpreting coordinates.

TypeScript normalization now scales by the largest absolute component before calculating length. Valid finite ratios near the largest Binary64 magnitude or in the subnormal range no longer overflow or normalize to a nonunit frame. The existing native normalizer already used this method. No fallback was changed for an invalid negative-X/omitted-ref example: the normative helper's positive-X fallback was checked against the pinned EXPRESS and primary buildingSMART documentation before making the paired-provision fix.

The closed schema, feature and axis-cases.json define **18 neutral placement cases**. The actual graph evaluator suite passes **19 tests / 142 assertions**. It includes default and explicitly rotated 2D/3D frames, positive/negative X, extreme finite directions, one-sided provision, wrong coordinate roles/dimensions, zero axes and parallel axes. Initial execution reproduced failures before implementation; the strict AJV oneOf branch property declaration was also corrected. The suite is explicitly registered.

Independent **IfcOpenShell 0.9.0.post1** validates and agrees on the five ordinary valid frames and refuses all eleven invalid cases through full EXPRESS validation. Its NumPy-based normalizer yields nonfinite frames for the two extreme valid directions, and its EXPRESS evaluator also records a numerical failure there. These external numerical limitations are recorded, not counted as implementation agreement. Independent **mpmath 1.3.0 at 4,096-bit precision** reproduces all seven prescribed and actual valid matrices from the exact finite Binary64 inputs. Overall expected-outcome mismatches are zero. Inputs axis-export.ts and axis-oracle.py retain the independent comparison boundary.

The original native regression consumes the same neutral JSON for every three-dimensional case and drives the unchanged official triangulated model through the actual native projection, checking atomic invalid-value refusal or transformed quantized bounds. Both touched native files pass rustfmt syntax parsing. The test has not been compiled or executed: authentic native ingress still refuses before rustc. This does not establish native route, receipt, cancellation or output correctness. The preceding audit finding is resolved in source and remains pending genuine native verification.

Focused strict TypeScript checking passes for production geometry/source and the new fixture/test. These changes do not supply currently unsupported grid/linear placements, swept/mapped/BREP geometry or all-MVD conformance.
