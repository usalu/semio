# Procedural Root Read Scope Plan

The arithmetic28 public result observations agree with fresh IfcOpenShell0.8.5 and SQLite28. Both engines also modify two original source entity orientations. A repeated positive query after a negative query can therefore observe a different result from the same canonical source. Existing private snapshot conversion does not prevent this semantic-context order dependence. This is a root-query isolation defect independently of arbitrary entity assignment value-copy assumptions.

The proposed ownership boundary is one explicit procedural read scope per public root evaluation/call, shared by its nested function, query and derived evaluation scopes. Entity-reference assignment within that scope remains aliasing; aggregate assignment retains its existing value-copy semantics. A private source-to-local value memo lazily materializes only accessed entity field metadata and accessed aggregate containers, under existing evaluator ticks. It never clones an entire source population on function entry, never creates a second index or control wallet, and never restores mutations into canonical entities. Existing source identity values are retained for identity equality and inverse/USEDIN lookup.

The memo must be carried by explicit scope provenance rather than an ambient global current-frame slot, so two asynchronous public queries cannot redirect each other's local views. Identifier, attribute, index and query result access must resolve through that same memo. Nested functions inherit the existing root scope; they do not independently value-copy every entity assignment. Qualified and derived reads use local entity fields with canonical type metadata, without redirecting SELF back to the canonical entity object. Inverse/USEDIN results are remapped before subsequent procedural use.

Returned transient values must retain their actual computed local fields. No rollback can restore source fields underneath a returned entity reference. Their referenced entity identities remain identities, not invented new entity instances. The public evaluation API has historically exposed mutable ExpressValue objects; this correction must avoid claiming fully detached arbitrary externally mutable result graphs unless such a graph is actually materialized. Root-query source isolation and language-level reference aliasing are the immediate contract, with returned read-scope references evaluated through explicit provenance on later queries.

Before production: add language-neutral laws for repeated negative/positive actual issued calls, original source unchanged on success/failure/cancellation, entity local alias visibility, separate root isolation, derived local SELF consistency and retained entity identity. The actual pinned IFC function is the arithmetic counterexample. Candidate ISO sample text supports domain isolation but is not presented as authenticated normative acquisition; no general entity pass-by-value semantics are inferred. Independent SDK source mutation is retained as a shared divergence from the host source-read contract, not silently reclassified as output disagreement.

The implementation may require evaluator and population resolver changes only after these contracts are executable. Root has assigned that ownership explicitly. Native retained parity/type/runtime/receipt claims and all admission/publication flags remain false.
