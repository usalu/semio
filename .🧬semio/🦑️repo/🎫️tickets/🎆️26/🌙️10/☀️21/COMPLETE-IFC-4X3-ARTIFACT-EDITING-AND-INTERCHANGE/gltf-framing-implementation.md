# IFC GLB Framing and Transform Parity

The new shared cases initially produced four TypeScript failures: nonzero BIN padding was accepted, future chunks after BIN were rejected, and positive and negative `1e-200` scales became singular through determinant underflow. The implementation now rejects nonzero BIN padding, ignores unknown chunk types after the required JSON/BIN pair, and uses an exact represented-binary64 determinant sign. Known duplicate or misplaced JSON/BIN chunks remain invalid. The native checked reader now accepts legal trailing JSON TAB/LF text and the same future chunks. Native orientation already used exact bounded integer accumulation; both implementations now consume eleven shared determinant cases covering subnormals, overflowing products, singularity, cancellation, reflections and mixed exponents.

The registered language-neutral JSON bundle, closed JSON schema and feature contract live beside the real IFC IO tests. The original Khronos Box GLB remains unchanged. Four scale cases compare imported IFC world bounds with the real three.js GLTFLoader/Box3 result. The independent test-only `mpmath==1.3.0` LU decomposition agrees with all eleven determinant signs at 16,384-bit precision. No external runtime dependency was added.

Verification at this checkpoint: **27 Bun tests, 62 assertions pass**, including the existing real IFC/GLB roundtrip suite; focused strict TypeScript checking passes. Rustfmt accepts the changed Rust sources and native tests, which is syntax evidence only. Native compiler ingress still prevents executing native fixtures; neither native parity nor physical ownership is claimed from these checks.

The retained `gltf-validator-acquire.py` pins the official Khronos validator `2.0.0-dev.3.10`, verifies registry integrity and tarball SHA-256 `4e03dbdc3bc0d1342afd5d2d7ae341a7e3474502ccb872b02dbbaddaee0fdec6`, and keeps its test-only files under generated output. The official validator agrees on legal JSON whitespace, invalid NUL JSON text and accepted future chunks (one warning). It reports no error for nonzero BIN padding in this unused-buffer fixture: that is an oracle coverage limit, not a passing compliance result. The owned rejection follows [glTF 2.0 section 4.4.3](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#chunks), which requires zero BIN padding and ignoring unknown future chunk types.

All four public TypeScript glTF/GLB routes also capture the original controls before invoking caller code. Four additional test-first failures showed cancellation could be bypassed by replacing the caller's options during its callback; these now refuse on the original signal. The combined glTF suites now pass **31 tests and 70 assertions**. Strict TypeScript checking and closed-schema validation were repeated after these cases.

The GLB readers and writers still contain cold whole-buffer/JSON operations and are not the retained original-owned geometry pipeline required for full native completion. Those boundaries remain separate work. Native IO fidelity tests were also corrected to distinguish lossless natural STEP/TXT routes from the explicitly lossy geometry/domain projections.

The subsequent complete IFC4x3 TypeScript integration sweep passed **333 tests / 11,237 assertions across 23 files**, with nine output/environment-gated independent checks skipped and no failures (38.43 seconds). This includes current templates, official corpus, EXPRESS, diffs/history and exchange tests present during the sweep; it does not execute Rust or produce native physical-work evidence.
