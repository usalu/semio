## Priorities

### P1 — Actual FEM receiving owner remains unavailable as checked in

`native_domains.rs` deliberately returns actual `Fem3dSnapshot` and calls its public binary/native codecs. This is the correct artifact identity, but its owner is currently inconsistent: `.../fem/🗿️artifacts/🧊️3d/.../🧬️schema/📸️snapshot/🦀️.rs` defines persistent sealed node/material lists without `DslRecord` or `FromValue`; `.../🚪️io/💾️binary/📸️snapshot/🦀️.rs` still calls `Self::__dsl_spec`, `__dsl_from_record`, `__dsl_from_record_controlled`, `__dsl_to_record_controlled` and the `FromValue` retirement implementation. The explicit `Fem3dSnapshotValue` derives those authoring interfaces, but is a different type. The checked-in codec cannot be treated as evidence of an operational receiving implementation. This repeats and independently confirms the implementation report's owner blocker; it is not a newly introduced regression attributed to IFC.

Required next validation: the FEM owner restores its real receiving/encoding implementation under original authority, then authentic compiler/type checking and the actual native roundtrip/host/oracle tests execute. Do not replace the output type with the authoring reference value to hide the blocker. No native compiler execution was attempted or bypassed in this audit.

### P1 — Controlled IFC→FEM has an unfunded intermediate ownership expansion

`native_domains.rs:9–15` builds a complete `RecordValue` using `value.__dsl_to_record()`, encodes a complete binary document using `encode_document(..., Default::default())`, and wraps it into another byte vector. `receive_fem` checks the original control once before this expansion and passes that original decoder only afterward. Final encoding also uses the original encoder. Consequently preserving the final receiving decoder does not fund, cancel, or retire the intermediate record, document buffer and wrapped buffer through that authority. This is particularly observable with large material/section names and many rows: the route completes the whole synchronous expansion before it can observe another cancellation or a small caller byte grant. Ordinary Rust drop eventually frees temporary containers, but does not establish the required controlled ownership closure.

This is an acknowledged implementation boundary, independently confirmed in source. The same class of ordinary allocations is visible in graph indexes and authoring result vectors. Fix the actual controlled receiving path rather than enlarging limits or creating a fresh default caller. Once native ingress works, reproduce by cancelling after reference projection/before receiving and by running the same admitted source with a caller grant smaller than the intermediate document; assert refusal before unfunded copies and complete terminal retirement.

Concrete repair choices, ranked:

1. **Preferred owner solution:** expose a source-owned controlled authoring-value receiver that returns the actual `Fem3dSnapshot`, retaining the original decode owner. Its node/material row inputs already implement `NativeRecordSource` in `semio_s_fem_node`/`semio_s_fem_material`; actual rows implement `NativeFlatRecord`, and the existing `NativeFlatRecordReceiver` and `NativeDecodeControl::receive_construction_step[_typed]` provide the original-grant construction mechanism. Assemble actual persistent lists with their source-owned persistent builder (`constructor_demand/new`, `adopt_demand/adopt`, `finish_demand/finish`, `demand/advance`, `take_demand/take`), including original-funded close/retirement. This API belongs to FEM's snapshot owner, not IFC. Use the same owner implementation from binary/native decoding, so restoring the codec and receiving authoring data does not introduce competing semantics. A borrowed IFC-backed row source could ultimately avoid the full plain authoring value as well. Do not invent a convenience constructor for sealed fields or a Vec-to-persistent conversion that silently allocates.
2. **Smaller intermediate repair only after owner restoration:** the authoring `Fem3dSnapshotValue` derives the existing controlled record production method `__dsl_to_record_controlled`. It can be called with the original `control.encode()` rather than uncontrolled `__dsl_to_record()`. Actual `Fem3dSnapshot::__dsl_from_record_controlled(record.as_record(), control.decode()?)` would then receive the record under the original decoder **only once that actual owner implementation exists**. The currently checked-in calls to that method are not proof it exists. Keep the controlled encoded-record owner alive until receiving completes and use its supported retirement lifecycle; avoid extracting a bare record or losing its cleanup owner. This removes the two binary buffers but still materializes a record and needs budget/retirement tests across both original ledgers. It also does not fix the preceding plain authoring snapshot/vector allocations.
3. **Wire intermediate if required by public interface:** framework `pack::record::encode_document_controlled` exists; preferably use `store::encode_native_snapshot_record` with `Fem3dSnapshotValue::__dsl_spec_producer()` and a closure calling `value.__dsl_to_record_controlled(native)` under the original encoder. The latter is the existing owner codec pattern and controls envelope production too; merely substituting `encode_document_controlled` while retaining uncontrolled `wrap_binary` leaves a full additional copy. Receive that payload using the restored actual `Fem3dSnapshot::decode_native_snapshot` and original decoder, then retire every intermediate under its creating authority. This is more expensive than direct record receiving and cannot be promoted as fully controlled until all intermediate authoring/vector ownership is funded.

The existing `receive_fem_uncontrolled` may remain appropriate for a genuinely uncontrolled pure-composer interface, but must never be reused as the controlled host receiving implementation. Do not introduce `NativeDecodeControl::default`, a fresh permissive native owner, or unrestricted temporary record/pack production to make tests pass. The required closure covers failure/cancellation during source projection, row receiving, list page birth/adoption, record/wire production and final output encoding, not only a final borrowed snapshot's codec.

### P2 — Some admitted expensive scans have no cancellation checkpoint

`native_fem.rs:165` walks the entire canonical material property's aggregate and clones/inserts every property name without a checkpoint. `native_bim.rs:130` walks each aggregate relationship's child list without a checkpoint; `native_graph.rs:98` eagerly collects the entire entity index before the indexed loop's checkpoints. Global entity/value bounds make these finite, but the documented four-million-value frontier can still perform substantial work after cancellation is requested. Existing cancellation tests refuse at the first callback, so they do not cover these frontiers. Add cancellation probes at the start of these scans, with a large admitted aggregate, and check both cancellation observation and original-ledger closure.

## Ownership and Semantics Checked

- BIM output is the source owner's actual `ModelSnapshot`; controlled publication uses its native codec and the original encoder. FEM host output is the actual `Fem3dSnapshot`; the explicit authoring value is an intermediate, not the output artifact. There is no JSON/fake snapshot substitution.
- Original native decoder/encoder references reach final domain codecs. Mapping callbacks reduce all checkpoint errors to a boolean, so mapping refusal reports cancellation rather than preserving the caller's original specific refusal reason. Pure composers intentionally have only their uncontrolled trait surface; do not present those as controlled host execution.
- Root IFC assembly contributes domain composers and the combined IO registry. Root discovery/register paths include the domain composers. Registration precedes the general plugin transaction and therefore does not independently prove rollback of registrations.
- FEM explicit unit evaluation checks engineering dimensions and scales; section/material caches preserve shared identities; endpoint sets are checked against topology; specialized/loaded structural entities, changed connection conditions, local axes and nonzero roll refuse. Support identities are scoped to point-connection identities on import, avoiding shared-condition collisions. Material owner receiving validates finite positive E/G/rho and the Poisson interval; no new missing-material-validation finding is asserted.
- BIM direct placements, authored storey height/ordinal constraints and unit-aware property conversions are present. Boundary/family omissions are diagnosed. Building elevation is read from placement; independent IFC ElevationOfRefHeight/ElevationOfTerrain values are not retained. Treat that as the declared partial authored projection rather than a complete IFC spatial semantic roundtrip. IFC metadata is not a full event/diff publication transaction.
- Prior tiny-scale exact determinant and raw GLB padding fixes remain described as source/test changes with no native executable proof. Their source-geometry independent checks do not validate native output. Nothing found in this domain audit invalidates those earlier input-only results.
