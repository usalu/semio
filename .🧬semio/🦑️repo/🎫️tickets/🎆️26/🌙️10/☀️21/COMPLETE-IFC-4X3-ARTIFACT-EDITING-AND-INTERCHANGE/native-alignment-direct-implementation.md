The selected-direct-zero-counterpart native source is now mounted in the actual native MVD module. ## Contract and source

The implementation consumes the existing closed `alignment/direct-definition.json`, `direct.schema.json` and 24 language-neutral cases. Native laws were authored before production evaluation. The native request requires caller-authored canonical positive-u64 segment IDs, explicit horizontal/vertical/cant kind and boolean applicability; duplicate IDs and invalid kinds refuse before source capture. Reports retain the same pinned release commit/URL/SHA256 and explicit not-evaluated schema, view, geometry, layout-terminal and parent-curve fields.

An applicable target resolves its actual AlignmentSegment, its own DesignParameters and the exact H/V/C parameter role and declared business length. Only finite numeric zero proceeds to that same segment's Representation → ProductDefinitionShape.Representations → ShapeRepresentation.Items → CurveSegment. Each clause field uses the shared native borrowed query with its exact declaring owner: IFCALIGNMENTSEGMENT, the H/V/C parameter declaration, IFCPRODUCT, IFCPRODUCTREPRESENTATION, IFCREPRESENTATION and IFCCURVESEGMENT. Unknown, ambiguous, missing and unique-with-absent-value remain distinct until explicit incomplete diagnostics. Membership examines all source constituents even after a positive role.

Only exactly one IFCLENGTHMEASURE or IFCPARAMETERVALUE constructor establishes the geometric SELECT branch. Its one finite numeric payload must be zero; integer0 and signedzero retain the existing local numeric predicate behavior. This does not widen Part21/schema numeric admission. Unknown/malformed/nonfinite branches remain incomplete. A nonzero selected business precondition fails before geometry lookup; an unrelated zero curve cannot satisfy the selected direct path. Competing representations/items remain supported-scope incompleteness rather than a universal IFC cardinality assertion. Parent-only C149 remains incomplete.
