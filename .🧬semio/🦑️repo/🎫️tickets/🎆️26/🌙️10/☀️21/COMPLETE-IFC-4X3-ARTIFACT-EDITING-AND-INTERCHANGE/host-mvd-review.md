## Prioritized Findings

1. **P1 — Actual retained admission rejects virtual reference controls before normalization.** IFC4x3 `✏️editor/🦀️.rs:207-263` normalizes `/appendReference` and `/reference` inside `snapshot_edit_special`. However it inherits `SnapshotEditingEditor::snapshot_edit_is_admitted` from shared `📇️registry/🧬️contract/✏️editing/🧰️editor-traits-and-retained-copies/🦀️.rs:10-11`. Shared `🛠️tool-job-factories/🦀️.rs:185` requires the original SetValue path to exist in the persisted snapshot shape, and line 282 invokes that gate when determining retained command extent. These virtual fields intentionally do not exist in IfcSnapshot, so their commands cannot reach the normalization handler through the actual retained route. Written IFC4x3 tests at `✏️editor/tests.rs:260` invoke snapshot_edit_special directly and miss this gate. Override admission with bounded validation and normalization into real argument/complex paths before calling generic admission; preserve raw command byte/depth/node bounds, exact u64 checks, capacity and target admission. Add actual admission/extent or retained-tool tests for both virtual fields, including missing/invalid/over-limit input. Parent was notified immediately.

2. **P1 — Newly inserted complex constituents cannot acquire required attributes through controls.** Provider `✏️editor/details.rs:547-548` inserts `IFCREPRESENTATIONITEM` with an empty argument list. It permits editing the name at lines 518-525, but the renamed constituent keeps the empty list. `allows_collection_insert:529-541` does not handle `/entities/N/complex/M/args`, and context requires an existing argument; no constituent variant projection builds the new declaration's arguments. Renaming to IFCCARTESIANPOINT therefore leaves Coordinates absent with no field control to create it. Add declaration-aware constituent variants/templates using direct attributes, preserving matching direct attribute values, and expose required missing arguments for incomplete imported constituents. Test render -> type selection -> argument creation -> mutation/inverse. This confirms the parent's suspected gap rather than claiming full complex schema semantics.

3. **P2 — Primary complex records still exclude abstract constituent types from switching.** `✏️editor/details.rs:574-586` always filters entity variants by `!abstract_entity`, even when the existing record has complex constituents and entity_template uses direct partial attributes. Abstract EXPRESS supertypes can legally occur as partial constituents of a complex instance. Offer the appropriate partial declaration set for complex records while keeping ordinary simple-entity abstract restrictions. Additional constituents need equivalent declaration-based choices rather than unrestricted text renaming. Complete complex semantic admission remains a separate stated limitation.
