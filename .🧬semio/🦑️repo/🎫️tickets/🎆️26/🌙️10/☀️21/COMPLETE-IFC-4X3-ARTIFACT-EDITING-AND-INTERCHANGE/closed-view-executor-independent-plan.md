# Closed View Executor Independent Contract Plan

Ticket-only proposed infrastructure, not a released complete view definition or production API. `closed-view-executor-requirements.json` inventories exact current9 concept/predicate identities with original definition paths/hashes and primary source provenance. It does not copy the checked-in source files. Every row explicitly has unresolved viewRequirementBinding; completeViewRequirementSet is false.

## Precise Unit of Work

Use `(concept URI, predicate ID, target identity, clause scope)` as an obligation key, not concept URI alone. Seven Body definitions each cover their three selected released clauses. Business-terminal-zero is one child obligation for an explicitly selected H/V/C layout. Selected-direct-zero-counterpart is for the requested business segment's own geometry, not the entire layout/child/view. A shared concept URI can later acquire other clauses without marking them implicitly implemented.

The registry should borrow exact imported definitions/closed executor discriminants, not duplicate predicate code or scan all312 informative catalog concepts to fabricate mandatory obligations. The initial registry has no authenticated complete per-view requirement binding. Keep that missing authority visible. Future authoritative bindings may supply target selectors/conditions, but neither entity scope badges nor FILE_DESCRIPTION ViewDefinition are those bindings.

## Request and Authority

Start with selected-contracts execution using the actual existing typed request shape for each executor. The outer discriminant is closed; retain its token/source revision, exact captured graph, explicit target and applicability. Do not reinterpret all targets as ShapeRepresentation: Alignment terminal takes layout+kind; Direct takes its selected business/geometry target pair. The outer owner may share already captured/indexed source only through genuine compatible APIs; until that interface exists, do not invent a borrowed context certificate or duplicate shadow index.

Whole-view request is separately labeled and needs an authenticated requirement-set identity/provenance. At present return requirement-set-unresolved/incomplete instead of promoting nine selected passes to a view pass. Unknown selection/view names refuse closed admission. A header view declaration may be displayed as user intent but must not choose proof obligations implicitly.

## Report and Precedence

`closed-view-executor-report.schema.json` is a ticket prototype, deliberately small. Production should preserve structured bilingual diagnostics and exact source entity/attribute pointers from actual child reports, rather than reduce them to its prototype string array. Each obligation needs applicability(applicable/N/A/unknown), implementation(implemented/unimplemented), status and original child provenance. Unknown applicability and applicable unimplemented obligations are incomplete. Non-applicable obligations are N/A, not passed. A selected failed predicate remains failed even if another predicate is unavailable; incomplete coverage remains separately visible. Whole-view complete=false and valid=false whenever the required set itself is unresolved.

Recommended summary uses separate `hasFailure` and `complete` instead of throwing away known failures with a single precedence enum. If retaining enum, use fail when any known applicable predicate fails and otherwise incomplete when required coverage is unresolved. Complete flag still remains false for incomplete coverage. Avoid a single percent from312 informative concepts; report exact requested/required/evaluated/failed/incomplete counts with denominator authority. Empty selected requests refuse rather than vacuously pass. All-N/A selection reports N/A and validfalse; it is not proof a view has no requirements.

## First Neutral Laws

1. Each of9 typed selected contracts dispatches its actual executor and preserves the child target/pointers/diagnostics.
2. Two Body contracts on one representation remain separate obligations; one wrong RepresentationType is not hidden by another passing type.
3. Applicable supported pass; applicable supported fail; explicitly N/A; unknown applicability; applicable unimplemented.
4. Passing all9 still yields whole-view incomplete with unresolved requirement-set diagnostic and no valid claim.
5. Known failed clause plus unimplemented obligation retains failure and incomplete coverage.
6. Same concept URI with unimplemented predicate does not inherit implementation from an implemented sibling predicate.
7. Header declaration mutation does not change authentic requirement registry/proof or canonical source during execution.
8. Unknown metadata constituent after matches remains incomplete; owner-qualified child query statuses survive aggregation.
9. Original callback Error/typed error/undefined and signal mutation retain exact original authority at request/source/index/child/final-report gates.
10. Cancellation/refusal exposes no successful terminal view report and closes already admitted child/source/report owners under the existing original policy.
11. Raw malformed/duplicate obligation identity and oversize request roster reject under explicit admission bounds; output/diagnostic rosters have source-sized cooperative steps.
12. Actual independent simple traversal validates each selected predicate, not an unrelated full EXPRESS result. No third-party all-view conformance oracle is currently claimed.

A report schema alone cannot prove that all obligations were evaluated; the requirement registry and issued execution owner must supply that authority. This ticket proposal is for HighSem's plan, not a public arbitrary report/manifest admission API. Native source/type/runtime and public host ACK/transport acceptance remain separate gates.
