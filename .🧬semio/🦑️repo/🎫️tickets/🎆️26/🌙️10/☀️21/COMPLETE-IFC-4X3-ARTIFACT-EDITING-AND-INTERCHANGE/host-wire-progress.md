No source string or output buffer is allocated by that path.

## Owned Receiving And Native Value Editing

`receive.rs` now implements the shared original owned DslValue→IfcValue receiver, with explicit `Native` versus `Decimal` modes. Decimal transport uses exact canonical i64/u64 text and finite f64 bits. Tagged field sets are closed. Aggregate and typed children move through retained native frames, one source child and one destination slot at a time. String ownership moves without allocating or cloning its body. Canonical BINARY digits are inspected in 64-byte chunks. Every output, original envelope, partially built Vec and parent frame has controlled close custody. The public receiver also accepts an explicitly selected native payload shape for existing text, numeric, aggregate or typed controls; it does not guess a transport mode.

`value_edit.rs` implements an IFC-local native edit cursor over the actual IfcValue, with retained parent owners. Argument and header commands use this cursor in shared work. Nested values, typed names/items and bare aggregate payloads use the same receiver. Collection allocation quotes its actual contiguous destination extent and can be refused by the authored policy; it does not truncate the collection or restrict editable indices. Native pointers are explicitly bounded to 8192 bytes, covering all canonical numeric/native-field paths under the existing depth128 value bound.

## Captured Preimage Restriction

The borrowed inverse source represents captured snapshot preimages. Arbitrary progressive batches could otherwise read the wrong immediate inverse value after an earlier write or positional shift. A persistent preflight now checks declared row capacity and one prior/current mutation pair per metadata event before any operation wire begins. It refuses duplicate header tuples, duplicate entity names/complex fields, repeated argument writes, insert-then-edit or reused identity interactions, argument shifts at or before a later source-reading slot, and removals whose entity payload/index changed. The refusal explicitly says the batch requires progressive preimages. No partial forward/inverse bytes are emitted by the preflight.

The supported sparse path includes distinct field writes, descending argument removals followed by lower-slot writes, and distinct final entity insertions followed by a single write to an original entity. The selected-template planner was coordinated to emit final inserted resources and at most one original HasPropertySets edit, with its own guard as well. This is an explicit temporary admission boundary, not an implemented arbitrary progressive overlay. The central Store still validates the actual progressive batch and remains sole publication authority.

`preimages.json` defines13 admission/refusal cases. The native preflight test uses OriginalWorkFixture with one real fuel unit per turn, checks the expected refusal before codec birth, and asserts zero encoded bytes. Four independent IfcOpenShell scenarios demonstrate why duplicate-slot, insert-then-edit, ascending removal and duplicate-header preimages differ from captured values; the updated oracle rerun passed them. These written native tests have not executed.
