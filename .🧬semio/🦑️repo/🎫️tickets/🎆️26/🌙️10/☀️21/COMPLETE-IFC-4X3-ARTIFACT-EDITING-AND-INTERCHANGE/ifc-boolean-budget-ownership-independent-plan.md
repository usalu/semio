# Finite IFC Boolean Budget Ownership Independent Design

This ticket-only design was written while the shared Boolean producer is held for the receiver-authority correction. No held source was reread/imported, no production changed, and no native wallet or receipt claim is proposed.

## Three Distinct Ledgers

The current IFC geometry IO control has no maxWork grant. Its maxValues bounds source capture/geometry logical values; it cannot silently be reinterpreted as a Boolean CPU budget. Define a closed schema-owned Boolean execution policy under geometry control (for example booleanEvaluation:{maxWork,maxPolygons,maxDepth}), captured/validated once before the first source traversal or observer. Reuse the existing captured maxValues and remaining represented-output allowance separately. Default policy values must be explicit released implementation resource limits, adjustable by the caller, not fresh defaults per AST node. No synthetic StepContext/native original loan is involved in this TS session.

1. Boolean work is cumulative and monotonic across the entire actual admitted expression, including nested operations, input admission/copies and half-space cutter work. Returning a child result must not reset it. Cancellation/progress reports the same original total/budget. If source-expression/leaf-construction work is also promised in this budget, it must call a session checkpoint explicitly; IO batches alone do not debit it.
2. Live intermediate logical mesh values bound positions3+indices (+normal data only if genuinely retained). Reserve before each backing growth/producer allocation, retain reservations while an input/child output is live, and release on last owned use/close. This is a workspace capacity ceiling, not the monotonic work counter. It prevents a deep AST retaining unbounded child meshes even when each leaf individually fits.
3. Represented output values are the existing cumulative product/publication maxValues ledger. Debit one published mesh once; do not debit the same mesh again merely because it becomes a parent operand. Check final count before publishing and preserve earlier completed product outputs when the endpoint's existing partial-result policy permits them. Do not give each Boolean subtree a full fresh output allowance.

The workspace bound needs an explicit contract: reusing the original maxValues as its ceiling is coherent if documented as both final-output and live-intermediate limit. A separate schema-owned maxIntermediateValues may be cleaner for callers whose output is small but operands are large. Either choice must be test-first; it must not be an unreported grant multiplication. BSP polygons/split vertices also need the existing original polygon/work ceilings before growth; a mesh-only counter does not bound every temporary.

## Narrow Owned Session Contract

Use one owned execution session minted from the actual once-captured policy in the IFC request owner. Internally it holds genuinely private work/limits, failure/cancellation state and live-workspace reservations. Suggested conceptual operations are checkpoint(), reserveMeshValues(delta), releaseMeshValues(delta), booleanSteps(operation,left,right), halfSpaceSteps(left,plane) and close(). Names are illustrative, not a parallel implementation or prescribed public compatibility layer.

The existing public standalone generic Boolean operation may create its own session for that one call; the IFC adapter needs an internal/session route which lends the SAME session to every nested operation. It must not call a standalone factory repeatedly with unchanged original options, because that creates a new work grant for each node. No caller-supplied already-spent counter, public mutable control, free source certificate or public reset operation should exist. Observers are invoked unbound and never receive the session. Reentrant use while a child is active must refuse or be explicitly serialized; a callback cannot start another child on the same live session and reset its cursor/accounting.

The session owns resource policy, not IFC declaration authority. Actual operand/source/query ownership remains in the adapter cursor and canonical captured graph. Generic meshes remain borrowed under a documented stable-input contract; a source clone is not hidden in the async drain. Cancellation/failure closes child generators, then drops retained intermediate meshes/reservations and source frame references, preserving the first observed operation/caller failure. Success can only return after the original completion gate. No invented native receipts follow from JS reservation bookkeeping.

## Adapter Frames and Mesh Ownership

An explicit AST frame contains actual result/operand source IDs, operation, stage and owned optional child meshes/reservation handles. It enters only original owner-qualified operands, tracks active-path IDs for cycles and permits repeated DAG occurrences. Evaluate one child at a time in deterministic source order; completed left remains reserved while right is evaluated. After the shared kernel has fully consumed both, transfer the actual output reservation to the parent and release operands only if no retained alias requires them. Reused source operands may be reevaluated under the same work budget or explicitly share a retained immutable mesh with counted references; a global cache is not required and must not mint free work/space.

Primitive and extrusion evaluators need a preflight callback/session reservation before arrays grow. Their exact existing counts are useful: Block60, default cylinder1284, cone645. They must not be fabricated as a CsgSolid source wrapper. A parent result with dynamic topology needs incremental reservations in the shared kernel at actual candidate/output growth, not an after-the-fact maxValues comparison. Final central orientation swaps consume bounded work under original control and must not be performed twice when operands already have kernel-valid outward winding.

## Exact Test-First Frontiers

For a real Block leaf,59 refuses before its private mesh birth and60 admits that mesh; source capture allowance is explicitly unrestricted in that test. Two simultaneously retained Block operands need at least120 live logical values before kernel output/workspace, even if final DIFFERENCE is only60 or empty. Test the declared workspace policy at its measured actual total minus one and exact total, not a guessed multiplier. For a cone/cylinder use644/645 and1283/1284. Distinct products share one public output budget; repeat the valid shared-representation fixture style rather than duplicate SET item references.

Measure one genuine nested two-operation expression's total session work W, then assert W−1 refuses and W succeeds; verify both children contribute and a callback cannot replace policy/reset work. Repeat half-space cutter+Boolean under the same counter. Compare direct versus nested/identity-operation totals without assuming they must be equal. Original maxDepth applies to the explicit expression stack; kernel BSP depth is a different limit if both are exposed, and their names must distinguish those meanings.

Test cancellation/exact Error/undefined at source enter, each leaf/intermediate reservation, child completion, kernel split/output, central orientation and final publication. Test finite return cleanup releases reservations and ends child generators, while source/request snapshots remain unchanged. Genuine timer fairness must be observed under actual async execution; step parity or caller-provided immediate Promise cooperation alone is not host fairness proof.

No production API, schema or frozen data is changed by this design. A later actual adapter freeze must name its exact shared-session entry and published memory/work semantics before a source/runtime audit can close it.
