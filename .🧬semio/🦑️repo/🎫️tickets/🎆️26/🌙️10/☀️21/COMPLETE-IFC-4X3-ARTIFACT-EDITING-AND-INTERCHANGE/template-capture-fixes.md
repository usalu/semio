# Complete Own-Key Capture

The P2 in `template-authoring-review.md` is fixed at the shared TypeScript `copyIfcOwnedSteps` boundary. Capture now examines every own key, including non-enumerable and symbol keys. It rejects symbols, accessors and non-enumerable data fields. The explicit canonical policy also refuses non-enumerable fields whose names would otherwise be legal; these fields are never silently omitted. Arrays must have every canonical numeric index and their intrinsic length, with no extra own fields. Dense frozen arrays remain accepted. Getter bodies are not invoked.

`capture-cases.json` retains thirteen neutral defect kinds and publication expectations. New registered `template-capture.test.ts` exercises synchronous and asynchronous owned copy, snapshot and diff capture, applyTemplate/applyDiff application, inverse preparation and actual history publication. Each malformed command is refused without an event/revision/snapshot change or getter invocation. A separate descriptor-manifest policy is admitted by third-party Ajv JSON Schema to independently compare the declarative own-field/array policy; these are host descriptor manifests because hidden properties and symbols are not representable in ordinary JSON transport.

The test-first suite initially failed eleven of its fourteen tests against the audited source. After the centralized fix, the combined capture, template authoring and existing native shape suites pass **48 tests / 5,616 assertions**. This includes real cancellation at capture/planning/semantic frontiers, exact inverse/undo/redo and a revision changing during semantic preparation. Targeted strict TypeScript checks pass. The original retained `template-audit-shape.ts` now refuses all four reproductions. Native template implementation has not been executed.

## Host Intrinsic Cost

JavaScript has no standard cursor over all own keys, including symbols and non-enumerable keys. The implementation therefore calls `Reflect.ownKeys` once per container. That intrinsic allocates the whole key roster before control can return; it is **not** physically incremental or cancellable during the call. Typed array-length limits are checked before roster enumeration, and cooperative cancellation/descriptor validation/child copying resume per field after it returns. Arbitrary malformed objects with very many own fields can still incur that intrinsic roster cost before refusal. This is an explicit host-language limitation, not a claim of a bounded physical cursor. No additional eager descriptor tree or clone is created.

The captured view remains the existing per-container view: callers must keep inputs stable during capture if they require exact start-state capture. Newly attached properties after that container's roster was captured are not part of its captured view. No claim about detecting arbitrary live Proxy traps is introduced.
