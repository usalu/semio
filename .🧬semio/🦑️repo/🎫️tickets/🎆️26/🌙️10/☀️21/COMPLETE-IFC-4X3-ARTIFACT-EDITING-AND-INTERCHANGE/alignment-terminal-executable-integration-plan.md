## Closed request and result

Request targets use exact positive canonicalu64 layout ID and explicit applicable true/false/null; optionally require layoutKind horizontal/vertical/cant as declared request discriminator. Avoid parent alignment ID until its exact membership evidence is validated. False→not-applicable without requiring target resolution; null→incomplete. True requires unique target, authenticated layout declaration, one unambiguous ordered segment list and resolvable terminal design parameter/length. Unknown/missing/duplicate IDs or conflicting nesting→incomplete. Known wrong target layout kind→fail (or closed request mismatch refusal if kind is an asserted request constraint; choose and freeze schema first).

For one applicable layout, find actual IfcRelNests.RelatingObject referencing that layout. Its RelatedObjects order is the business order. Do not concatenate multiple competing nesting lists or sort IDs. Require list members to be resolvable IfcAlignmentSegment with appropriate DesignParameters role; expected horizontal IfcAlignmentHorizontalSegment.SegmentLength, vertical IfcAlignmentVerticalSegment.HorizontalLength, cant IfcAlignmentCantSegment.HorizontalLength. Terminal numeric zero accepts signedzero. Known finite nonzero final length→fail. Empty list, wrong parameter domain, malformed length, unresolved reference or membership→incomplete, never fabricate zero. No earlier zero can satisfy terminal requirement. If validating whole list membership as scope evidence, unresolved earlier members keep overall incomplete even when final nonzero is known.
