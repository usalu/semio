# ClosedShell Normal Primary Clarification

The pinned [IfcClosedShell page](https://raw.githubusercontent.com/buildingSMART/Standards-builds/610ee3f95db9d0380b1eb8de4dc6e17833531518/IFC/RELEASE/IFC4_3/HTML/lexical/IfcClosedShell.htm), SHA256d73b7baad9d629458ab8d9094051ead6918a61c08fea58fc557542094583ce95, defines its shell normal from the finite region toward the infinite region. It also states that each member face has a logical agreement sense and an ordinary face without an orientation attribute defaults that sense to true (HTML185–187). The closed oriented manifold requirement follows. FaceBasedSurfaceModel does not override this subtype definition.

Therefore globally inward face winding on the proposed exact IfcFace/PolyLoop source slice must not be treated as a normative positive solely because the shell is used in a surface model. Temporarily reversing negative-volume triangles to satisfy a positive-winding validator can verify underlying unoriented manifold geometry, but it does not establish that the actual original faces obey the shell's prescribed topological normal. A renderer could deliberately expose such malformed input under a separately named projection policy, but that is distinct from strict declared-shell admission. No source implementation is being called defective here; root was still deciding the policy. Generic concrete ConnectedFaceSet has only its own weaker connectivity contract and need not acquire an outward-solid rule.

This is primary-source clarification, not external full EXPRESS/mesher validation of an informal normal condition.
