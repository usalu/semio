# Native Details Capacity Facet

The shared retained-work capacity helper previously called the complete profile catalog and scanned all inherited tuples while the command factory queried its extent. It now reads an explicit profile constant. Both pinned4/43 catalogs have maximum21 inherited serialized attributes (IfcTaskTimeRecurring), so the existing formula remains45invertibleitems and90forward-plus-inverse rows. Actual malformed imported tuples are still separately checked by the existing publication guard.

The neutral `🔎️details/🧪️tests/capacity.json` precedes the source change. A permanent TypeScript test verifies its values against both complete catalogs and independently checks the item cap with AJV; fullDetails now passes16groups with zero diagnostics. Native tests validate both profile constants against the full catalogs. The shared HeaderProfile test has an intentionally panicking catalog accessor and now queries capacity without touching it. Those native tests are authored and grammar-clean, not executed; five modified native sources passed the installed grammar parser and independent static peer review.

Only this capacity query is made cold-safe. The actual factory calls admission before capacity, and reference normalization/attribute/render queries may still construct the catalog. The native catalog uses generated Rust builders with String/Vec/BTree allocation, not runtime JSON parsing. No measured timing, allocation total or universal host failure is asserted. See `ifc-native-cold-catalog-audit.md` and `ifc-cold-capacity-fix-peer-review.md`.
