# Repo structural conventions for the pets product (read-only exploration)

Scope: the rules every new file of the planned `🐾️pets` product (framework product with schema, TypeScript and Rust twins, fixtures, tests, a React target) and its domain extension under `🎓️teaching` must satisfy so that the taxonomy, package, test-contract and launch verifiers pass on the first run.

Method: read the verifier sources, the registry (`🔣️taxonomy.json`), the quiz product as the working precedent, and ran the read-only verifiers listed in section 0. No file of the repo was written (only this report and scratch files in the session scratchpad).

All paths are repo-root relative unless stated. `LIB` below means `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library`, `TEST` means `🧰️framework/🛍️products/🦑️repo/🔨️modules/🧪️test`, `TAX` means `LIB/🔣️taxonomy.json`.

## 0. Decision-relevant summary

1. Every directory name must be registered in `TAX`. An unregistered name is the error `directory-kind-unresolved` ("Directory has no registered semantic kind"). Right now the two reference scopes are not clean for exactly this reason: `bun ./📜️script.ts verify taxonomy report --scope "🧰️framework/🛍️products/❓️quiz"` reports `error directory-kind-unresolved 🧰️framework/🛍️products/❓️quiz/🧪️tests/🖼️task-icons`, and the `🎓️teaching` scope reports `🎓️teaching/🛂️proctor/🧪️tests/🏋️capacity` (both are other agents' in-flight directories, not mine).
2. Registration is flat per owner kind: new product names go to `members-of-products`, module names to `members-of-modules`, test case names to `members-of-tests`, fixture case names to `members-of-fixtures` (all in `TAX`, section 1.2). Domain subtrees such as `🎓️teaching` use contextual kinds (`parentKindIds`). A product additionally needs a member entry in `🧰️framework/🛍️products/🔣️.json`.
3. Files are named by kind only (`🟦️.ts`, `🟦️.tsx`, `🦀️.rs`, `🔣️.json`, `🎨️.css`, `🌐️.html`, `🥒️.feature`, `🐍️.py`); the semantic part of a name is a registered directory, never a file stem (`taxonomy/kind-only-basename`). Fixed names (`package.json`, `Cargo.toml`, `tsconfig.json`, `📋️project.json`, `📜️script.ts`, `README.md`, `LICENSE.md`) are exempt.
4. A render target owns its language packages, never the reverse: `🎯️targets/⚛️react/📦️packages/🟦️typescript/`, not `📦️packages/🟦️typescript/🎯️targets/…` (`taxonomy/target-inside-package-boundary`). Package roots contain only glue (re-exports, `#[path]` mounts, router scripts); anything else is `package-implementation-file` (a planned move, therefore an error).
5. Tests: no `#[test]`, no `describe/test/it` registrars and no `*SelfTests` functions outside a canonical test implementation (`inline-test-body`, `inline-self-test-declaration`). Rust unit tests are wired by `#[cfg(test)] #[path = "🧪️tests/🔬️unit/🦀️.rs"] mod tests;` inside the module.
6. Names: emoji is written as emoji + U+FE0F (`🐾️` = `1F43E FE0F`), exactly one leading emoji per path segment, unique among the siblings of one directory (files and directories share one namespace). `core, common, util, utils, helper, helpers, misc, shared, base, lib, impl` are banned name stems. A path is limited to 240 UTF-8 bytes and (Windows clone budget) 213 UTF-16 units for files / 202 for directories.
7. Registrations outside `TAX` that the new packages trigger: root `package.json` `workspaces` (generated by `bun nx run @semio-tech/repo-lib:workspaces-write`), root `Cargo.toml` `[workspace] members` plus `[workspace.dependencies]`, `bun.lock` and `Cargo.lock` refreshes, `.vscode/🧩️launch.seed.jsonc` curated rows followed by regenerating `.vscode/launch.json` (`bun nx run @semio-tech/plugin-registry:generate`), the schema catalog (`bun ./📜️script.ts schema generate`) because the product ships `🧬️schema/🔣️.json`, and the oracle registry `🔮️oracles/🔣️.json`.
8. I verified in memory (loaded `TAX`, cloned it, appended candidate names, called the repo's own `semanticDirectoryKindId` and `validateTaxonomy`) that the registration scheme in section 2.3 resolves every candidate uniquely and yields 0 taxonomy-schema problems (baseline also 0).

Rules (`LIB/🔍️discovery/🟦️.ts:699-742` `pathEmojiStatuteFindings`, emitted as `path-emoji-<kind>` by `LIB/🧹️normalization/🟦️.ts:3152` onward, and as `file|folder/name/<label>` by the root-script `policyEmojiPrefixBreaches`, `📜️script.ts:18934`):

| Finding kind | Meaning |
|---|---|
| `missing` | a non-reserved file/dir without a leading emoji |
| `generic` | one of `📁️ 📂️ 📄️` |
| `presentation` | the first code point is not Emoji_Presentation and no FE0F follows (always append FE0F and this never fires) |
| `spacing` | whitespace right after the emoji |
| `duplicate` | the same emoji (FE0F-folded) twice among the siblings of one directory; files and directories share the namespace (`🟦️.ts` and a directory `🟦️x` collide) |
| `multiple` | more than one emoji grapheme in the leading identity |
| `reserved-emoji` | `README*`, `LICENSE*`, `AGENTS.md` must stay literal and unprefixed |

A registry member name is valid only if it is NFC, contains no `/` or `\`, and its first emoji is `\p{RGI_Emoji}` or `\p{Extended_Pictographic}` + U+FE0F (`LIB/🔍️discovery/🟦️.ts:4184-4192`, `canonicalTaxonomyEmoji` at 694). The pair (owner kind, member name) must be unique across all member kinds (the `collide for owner` problem, same lines).

Caveat for tooling: my shell and the Write/Edit tools preserved FE0F in every path I touched. Do not retype emoji from memory; copy them from existing paths. `TAX` is not byte-stable under `JSON.stringify(parse(x), null, 2)` (the first difference is the hand-formatted inline array `"pathPatterns": ["✏️s/🔨️modules/*/⚙️engine/*/🌊️session"]` at `TAX:29371`; 20 characters of drift in total), so register with targeted text splices (Edit), not by rewriting the file from a parsed object. The file is two-space JSON with one array element per line and a final newline, no CRLF.

### 1.2 How a directory name is resolved, and where new names are registered

Resolution (`LIB/🧹️normalization/🟦️.ts:2269-2302` `matchDirectoryKind`, mirrored by the exported `semanticDirectoryKindId`, `LIB/🔍️discovery/🟦️.ts:2028-2062`):

1. Split the leading emoji identity from the slug.
2. Global candidates: `semanticDirectoryKinds` entries with the same emoji (FE0F-folded) whose `slugPattern` matches the slug.
3. If exactly one candidate (contextual ones, i.e. whose `parentKindIds` contain the parent kind, win over context-free ones) it is the kind.
4. Otherwise look for `semanticDirectoryMemberKinds` entries whose `memberNames` contain the exact name and whose `ownerKindIds` contain the parent kind or one of its ancestors (nearest owner wins).
5. No candidate: `directory-kind-unresolved`; several: `directory-kind-ambiguous`.

Consequence: a module named with an emoji+slug that already matches a context-free kind (for example `🧪️fixture`, kind `plugin-semantic-specimen`, `TAX:3464`) resolves to that kind instead of your member. Check with the probe in section 2.3.

`implementationLeafPolicy` (`TAX:20-48`): roles `["source"]` plus kinds `css` and `html` are "implementation leaves"; an implementation leaf must be named exactly `<kind emoji><extension>`, otherwise `taxonomy/kind-only-basename` (`LIB/🔍️discovery/🟦️.ts:1550`). One consequence: a directory holds at most one file per implementation kind and extension (`🟦️.ts` and `🟦️.tsx` may coexist), so any further code file means a further registered sub-directory. Non-implementation kinds with a semantic stem (`species.json`) are moved to `<semantic directory>/🔣️.json` and fail with `semantic-stem-unresolved` unless that directory is registered (`LIB/🧹️normalization/🟦️.ts:3182-3250`, `GENERIC_SEMANTIC_STEMS` at 875 are exempt: `asset assets component components descriptor glue test tests implementation impl index cases vectors`).

### 7.3 README requirements

`README.md` is a reserved name (any directory, no emoji prefix, not subject to kind-only naming). No folder is required to have one; the precedent is one `README.md` at the product root with a layout table, commands, domain model, validation codes (`🧰️framework/🛍️products/❓️quiz/README.md`), plus one on each `🎓️teaching/…` owner. A TypeScript package root may carry `README.md`/`LICENSE.md` (`bun-package-readme`, `bun-package-license`). `.empty.md` markers exist for intentionally empty folders (`📌️` kind); empty folders are otherwise a violation (`🔬️empty-folders` test).

### 7.4 Other rules that bite the Rust and React code

* OS exclusive state authority (`verify gate`, `📜️script.ts:17493-17660`): outside `🧰️framework/🛍️products/💻️os/`, a Rust struct whose name ends in `Store|Registry|Host|Session|Engine|Kernel|World|Scene|State|Cache` must not have a field whose type contains `HashMap<` or `BTreeMap<` (`os-state-authority/...`); also forbidden: item-scope `static mut`, `thread_local!`, `lazy_static!`, item-scope `static`/`const` of type `OnceLock|OnceCell|LazyLock|Mutex|RwLock|RefCell|Cell<…>` (`POLICY_OS_STATE_INTERIOR_TY_RE`, `📜️script.ts:17497`), `seq: u32` and `AtomicU32/AtomicU64` id minting. `#[cfg(test)]` modules are skipped. The existing quiz type `ThinkingState` (`🧰️framework/🛍️products/❓️quiz/🧬️schema/🦀️.rs:1021`, field `answers: BTreeMap<…>`) matches this pattern literally, so name pet types with map fields without those suffixes (`…Pose`, `…Crowd`, `…Rig`) or use `Vec`.
* TypeScript framework code: the ESLint rules above and the fixed core principle in the README (local state belongs to the host).
* Banned name stems apply to every file/dir name below `🧰️framework`, `✏️s`, `🌎️hub`, `♻️mit-bestand` (`policyBannedNameStemBreaches`, `📜️script.ts:18846`; `🎓️teaching` is not in that scan root list).
* Path budget: Windows clone budget fixture `LIB/🧫️fixtures/🥾️cross-platform-bootstrap/🔣️.json`: `windowsMaxPath 260`, `cloneRootMax 46` → repo-relative files at most 213 UTF-16 units, directories at most 202 (every emoji+FE0F counts 3 units); the deepest quiz path is 92. `collisionPolicy.maxPathBytes` is 240 UTF-8 bytes (7 bytes per emoji+FE0F).
