## 0. Ten things to know first

1. **Two kinds of test dirs live in `Q/🧪️tests/` (44 dirs).** A directory is a Protocol v2 *case* only if it holds `🥒️.feature` [V `TEST/🟦️.ts:287-330`, `discoverTestCases`]. There are **13 cases** (feature + `🐍️.py` + `🟦️.ts` + `🦀️.rs`); the other 31 are plain unit suites (10 TypeScript core suites `🟦️.ts`, 20 React suites `🟦️.tsx`, 1 `🎚️config`). `bun ./📜️script.ts discover` printed all 13 as `[rust,typescript,python]` [V].
2. **Numbers to preserve:** 13 cases, **36 scenarios**, parity `108/108` = 36 × 3 comparisons (oracle↔TS, oracle↔Rust, TS↔Rust). Every new scenario adds 3 to the denominator [V: scenario count by grep, 108 [R] in `TEACHING-ARCHITECTURE-DEPLOY-READY/📓️deploy-ready-report.md` and `QUIZ-PERIOD-LEADERBOARDS/📓️report.md`]. 35 scenarios are `@level-fundamental`, one (`learner-lifecycle` "The folded learner answers…", feature line 64) is `@level-quick` — so `parity fundamental` runs 35, `quick` and above 36 [V].
3. **Vectors are generated, never hand-edited, by ONE script that lives in a ticket**: `GEN` (1627 lines). It imports all 12 case `🐍️.py` modules, composes inputs, calls the oracle functions for every expected value, and writes `Q/🧫️fixtures/<case>/🔣️.json` (`write()` lines 51-69, `__main__` lines 1614-1627, `CASES` dict lines 34-48) [V]. Each feature text, each fixture's `$comment`, and the oracle registry all quote this path, so a new generator file would have to be quoted in the same places.
4. **Python references are self-contained duplicates.** They cannot import each other (the harness loads each as an isolated adapter). `🧾️learner-lifecycle/🐍️.py` (775 lines) re-implements sheet (`sheet_of` line 110), validation, scoring (`score_task` 284, `score_run` 291), badges and views; `🏆️leaderboard/🐍️.py` re-implements `evolve_learner`/`total_of`/`standing` (`score * 100` at lines 101 and 163); `🧾️learner-lifecycle` also has `total += score * 100` at line 524; `📊️crowd-view/🐍️.py` bins `score * 100` (lines 48-58) [V]. A change to the sheet, to the score, or to the points formula must be mirrored in **each** Python file that carries a copy — and in TS and Rust twins of each.
5. **Fixture URIs must be written in the feature text** (step text or data-table cell); the harness only resolves declared URIs, otherwise `KeyError: fixture … is not part of this plan — declare it in the feature file` [V `TEST/🖥️host/🐍️.py` `Context.fixture`; contract breach `missing-fixture` `TEST/🟦️.ts:1479-1483`].
6. **A case directory may contain only `🥒️.feature` and the declared adapters** (no sub-folders, no other file) — breaches `unknown-case-child`, `unknown-adapter-filename` [V `TEST/🟦️.ts:1486-1498`].
7. **Registry coupling of a case**: `@capability-X` must be in the chosen oracle's `capabilities`, `@comparison-Y` in its `comparisonProfiles`, `@oracle-Z` must exist in `Q/🔮️oracles/🔣️.json`; the oracle's language adapter (python) must exist [V `TEST/🟦️.ts:1441-1470`].
8. **Schema-conformance has two blind spots that matter for levels:** (a) `repository-quizzes` walks `🎓️teaching/**/❓️quiz/🔣️.json` and judges every real teaching quiz against the schema in Python (`jsonschema`) and in TS/Rust (`quizIssues`/`catalogIssues`/`quiz_issues`/`catalog_issues`) [V `🧬️schema-conformance/🐍️.py:74-114`, `🟦️.ts:41-52,72-84`]; (b) `learner-lifecycle` scenario `site-catalog` replays 12 plays against the **live** teaching catalog (`SITE_CATALOG = "🎓️teaching/🏛️architecture/❓️quiz/🔣️.json"`, GEN lines 942-957, `🐍️.py:722-748`) and demands perfect runs score exactly 1 and every badge is held — changing teaching content or the meaning of "score" changes these results without touching a fixture file [V].
9. **Rust unit tests do not go through the Protocol**: they replay the same fixtures through `crate::schema::tests::fixture("<case>")` (suffix match on the fixture dir name, `Q/🧬️schema/🧪️tests/🔬️unit/🦀️.rs:12-18`) from each module's `🧪️tests/🔬️unit/🦀️.rs`, wired by an inline `#[cfg(test)] #[path = "🧪️tests/🔬️unit/🦀️.rs"] mod tests;` at the bottom of the module's `🦀️.rs` [V]. TS does the same in the unit suite `🗃️shared-vectors/🟦️.ts` (one `describe` per case, 338 lines) [V]. So **a new/changed vector group needs four consumers updated**: Python oracle, TS adapter, Rust adapter, and the two unit-level replays (TS `🗃️shared-vectors`, Rust module unit test).
10. **Environment drift [V]:** `.venv/Scripts/python.exe` has numpy 2.4.3, scipy 1.17.1, jsonschema 4.26.0 (Python 3.14.4) while `Q/🔮️oracles/🔣️.json` `oracleHostPackages` and `pyproject.toml` declare numpy 2.5.0 and scipy 1.18.0. `QUIZ-PETS/📓️audit-registrations.md` finding 7 saw the same and found no version check in the harness [R]; the README says the harness builds a cache-local venv (`.🧬semio/🦑️repo/⚡️cache/tests/hosts/python-env-154c498180ce3916fc8edc3db6782c0f` exists) and installs declared packages that the base does not provide at the declared version [R `TEST/README.md` "Reaching a reference library"] — so a first parity run may touch the network [I].

## 4. Test style conventions

**Naming and layout** [V]:
- Case/suite dirs: `<emoji>️<kebab-slug>`; files by file-kind: `🥒️.feature`, `🐍️.py`, `🟦️.ts`, `🟦️.tsx`, `🦀️.rs`, fixtures `🔣️.json`.
- Rust unit tests: `🧪️tests/🔬️unit/🦀️.rs` inside the module; functions named as sentences in snake_case (`sorting_perfect_is_one_and_reversed_is_zero_exactly`), `use super::*;`, module docstring `//! 🎳️ Unit tests of the scoring: …` and `//! @see ../../🦀️.rs — the implementation under test`.

## 6. Facts for execution agents (checklist)

- Order (repo rule “schema-first, test-driven”): schema JSON → TS twin → Rust twin → `schema generate` + `docs` → Python reference + feature scenarios → generator → `contract` → `oracle` → TS subject → Rust subject → `parity` → unit suites (`🗃️shared-vectors`, Rust unit) → React/proctor/site.
- When in doubt keep the generated hosts' contract: a Rust adapter must compile with `--features sut` only; typed twin decode refuses unknown members, so extend `Q/🧬️schema/🦀️.rs` before writing vectors that carry new members.
- Keep `log10`-style or averaged floats under `quiz-score-v1`; integer points under `ordered-json-v1`. A projection that mixes ints/floats needs consistent JSON numbers across Python (`1` vs `1.0`), TS (single number type) and Rust (`parse_json` normalizes the string).
- Do not edit `AGENTS.md`; scripts only in `📜️script.ts`; a generator or probe lives in the ticket folder (`.🧬semio/🦑️repo/🎫️tickets/🎆️26/🌙️10/☀️02/QUIZ-CHALLENGE-LEVELS/`), generated output under `🗑️generated/` and removed at close.
- Third-party corroboration candidates for level policy [I]: points multiplier → `fractions.Fraction`/`decimal` exactness and numpy `float64` recomputation; timers → Python `datetime`/`time` arithmetic (as the leaderboard reference uses `datetime` against the cores' own days-from-civil code); hints → `collections.Counter` or `itertools` set counting (the crowd reference recounts with `Counter` and `numpy.mean`) — all stdlib or already-registered (numpy, scipy, jsonschema).
