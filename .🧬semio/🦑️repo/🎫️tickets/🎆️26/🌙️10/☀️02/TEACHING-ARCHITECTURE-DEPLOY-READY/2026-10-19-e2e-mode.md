# Neutral E2E Original Compiler Mode

The shared fixed-target helper classified every `test-e2e` target as prototype. Both the generic build resolver and the Nx bootstrap resolver combine fixed target intent with the original caller intent; consequently a legitimate inherited or explicit release E2E request threw `Conflicting build modes: prototype, release` before reaching the course. This also projected incorrect fixed metadata into every inferred E2E target.

Removed only `test-e2e` from the helper’s fixed prototype list. Neutral E2E tasks now inherit an explicit, authored, or original environment mode; an unspecified mode still defaults to prototype. Target configuration projection retains both prototype and release with prototype as its default and without a fixed mode. Explicitly named prototype/release preparation targets and development targets retain their existing fixed modes. No architecture-course name is used in the generic implementation.

The regression uses a closed schema and neutral `@fixture/rehearsal:test-e2e` vectors covering default and explicit prototype, inherited/explicit/authored release, target-encoded release, run-many, affected, agreement, and an actual conflicting caller request. It invokes both real resolver implementations. AJV validates the vectors, yargs-parser independently reads configuration arguments, and SQLite independently checks the selected mode or conflict. It also checks the real target mode projection and eight fixed-name control cases. Runtime debug output records each accepted resolver/case result.
