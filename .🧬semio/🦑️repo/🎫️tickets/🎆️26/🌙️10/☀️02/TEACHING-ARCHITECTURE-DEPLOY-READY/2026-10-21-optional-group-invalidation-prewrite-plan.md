# Optional Group Invalidation Prewrite Plan

Static proposal only. No additional multipart runtime edits, Native operation or cache mutation has run. The existing complete-reference closure proof still refuses unexplained partial publications.

## Authority and Scope

Use the real graph owner under genuine image kernel EX and acquire the existing nonwaiting namespace fact-writer resource for the exact canonical, selection or dataset namespace. Never infer a namespace writer from the image guard. If either owner is busy, retain it. ReuseHigh owns physical block publisher/expander revalidation; that fix is a prerequisite for this invalidation transition because process-local memoization must not recreate a dangling header after maintenance.

Invalidate only independently recomputable, completely inventoried namespaces: the np, ip and rr cache directories and independently named record-store directories admitted by the current optional path grammar. The default inference root, contexts/selections parent catalogs, producer publication/receipt namespaces and all other members stay in place. An outer eligible group includes all its nested packs, headers and shared observation blocks, so no block is removed while a retained header in that group needs it. No link may cross the chosen boundary; a detected cross-group reference retains or joins the group before any mutation. Overlapping groups are rejected rather than processed twice. Closed schema enumerates these roles; there is no public caller path or quota argument.

## Durable State and Atomic Boundary

Before mutation, authenticate every member, complete directory/ancestor epochs, current closure-reference union and all retaining publications. Publish a closed bounded content-addressed group intent in a fixed same-image retirement catalog. The intent binds version, original relative coordinate, unique fixed retirement coordinate, original directory physical identity, sorted member relative names/hashes/identities, exact closure references and whether the conservative reference mode is exact or all. Validate path length before publication. Publishing an intent does not yet invalidate live data.

Recheck the COMPLETE proof plus intent and namespace writer, then atomically rename that one independently owned namespace to its bound retirement coordinate. This is the invalidation commit: ordinary current readers see the exact missing optional directory and recompute. Do not rename the enclosing inference root or mutable scope parents. The closed intent plus original/retired exact presence observations distinguish prepared, committed and reclaimed states. Only one of original/retired may hold the bound ORIGINAL directory identity. Before commit, a replaced original or any retired coordinate refuses. After commit, an ordinary newly created original directory with a DIFFERENT identity is a separate live generation: independently authenticate it, include its references in the complete proof, and never retire it through this intent. Both coordinates holding the bound old identity, neither holding it while old members remain, changed retired identity, extra member, altered intent or an unrecognized state refuses.

A prepared state retains the original group and all its references. A committed state retains the intent's conservative references while deleting only authenticated retired survivors, with immediate nofollow descriptor/ancestor rechecks before each unlink. Recognize exact previously removed members as authenticated absence under the retained group ancestry; do not accept missing ancestors, permission failures or new names as absence. On cancellation, keep intent and remaining members. Resume only this exact authenticated state under fresh genuine EX and namespace writer. The authenticated state table explicitly allows the terminal transition where every bound member is absent and the empty retired directory has already been removed while the unchanged intent still exists; its exact absence is checked under the admitted retirement catalog. Remove empty retired directory, then intent LAST. The intent descriptor, retirement-catalog membership/epoch, original parent and every ancestor remain in the complete proof through every resume and deletion. Until that terminal deletion the reference proof retains the exact union, or ALL closure inventories when the declared known-incomplete state cannot expose a complete reference union. New production data at the original coordinate is a separate generation; it is re-enumerated in the complete proof and is never deleted by an old intent.

## Current Incomplete Publications

Unknown filenames, malformed complete indexes, invalid header/result digests, invalid Brotli blocks, changed leaves and unrecognized joins always refuse. Do not classify arbitrary partial bytes as a cache miss.

A closed current-format header with authenticated result and an exact missing named block can be admitted to invalidation only after the actual owner reader proves its exact typed nonreusable physical partial-publication refusal under stable ancestors. The pre-invalidation reader must NOT swallow that missing referenced block into recomputation. Only the genuine committed atomic namespace invalidation makes the header/group absent, after which the actual owner reader must prove ordinary missing-header recomputation. Because missing block observations are unavailable, its intent uses conservative all-inventory retention through terminal group deletion. The same rule applies to an authenticated closed index whose exact pack leaf is missing and whose real record-store reader proves a miss. A pack with no authenticated index remains unresolved by this proposal: matching its filename alone does not establish a complete current-format member join. It is retained/refused, with an honest availability limitation. Future pack publication/compaction must author its own closed prepared group intent before the first pack/index mutation if we want interruption recovery for that reverse window; this is not silently inferred by the recovery reader.

## Required Schema-First Proof

Language-neutral state vectors cover prepared/committed/reclaimed, cancellation before and after rename and every member deletion, exact restart, changed intent/member/ancestor, original-coordinate recreation, shared blocks, cross-group joins, unknown members, both/neither coordinates, missing leaf versus missing ancestor, and exact/all conservative retention. Independent SQLite recursive reachability and state tables determine expected retained closure sets; independent SHA verifies authenticated bytes.

Actual tests use the fixed owner-issued Graph fixture with genuine writer, reader and image EX. They invoke the real invalidation callback, actual openRecordStore and observation publisher/reader, prove busy custody performs zero mutation, and prove strict task closure consumers stay strict. A surviving process must physically recreate or refuse a retired observation block before publishing a fresh header. Actual statfs after descriptor close alone proves reclaimed capacity. Falsy primary failures, cancellation and cleanup must preserve the original failure and truthful partial counts.

## Review Boundary

This plan deliberately does not promise that all currently observed graph bytes are reclaimable. It adds no compatibility or arbitrary cleanup interface. Root and Light review must settle whether to include owner-authored pack publication/compaction intent in this feature or retain the explicit unresolved reverse window. No implementation of this additional protocol starts before that review.

## Committed-State Clarification

The closed manifest is {version,plan,committed}; its catalog CID authenticates the immutable plan, while every capture also retains the exact current complete manifest hash and physical identity. Publish committed=false before rename. After proving the bound retired directory and every original member complete, atomically replace the manifest with committed=true before any member unlink. A false manifest with the bound retired directory is a resumable rename window; false with neither old directory is a refusal. A true manifest with authenticated all-member and retired-directory absence is terminal. Any unknown partial publication temporary refuses. This distinction avoids inferring commit solely from absence.

## Persistence Scope

File fsync and same-image atomic rename match the existing owned publication mechanism and provide observed process-interruption continuation. No portable directory-metadata flush API is currently exposed by the Native platform contract; power-loss persistence ordering is not established. Any unrecognized post-crash state remains a refusal, not an inferred commit or eligibility claim.
