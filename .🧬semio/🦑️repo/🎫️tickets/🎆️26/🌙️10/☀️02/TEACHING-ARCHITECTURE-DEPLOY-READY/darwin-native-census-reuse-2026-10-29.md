# Darwin Native Census Reuse Audit — 2026-10-29

A concrete OS-library/neutral-FFI foundation exists, but no ready complete selected descriptor census was found in the bounded process/runtime production scan. runtime/native provides runtimeNativeSystemV1/open/read/pointer behind RuntimeNativeSystemV1; runtime/native/libc selects the Darwin system library through its declared loader interface. No external runtime library or C compiler installation is inherently required to bind an OS symbol through this existing port.

Existing process/testing/bun/orphans countOpenDescriptorsV1 already binds proc_pidinfo with i32/i32/u64/ptr/i32→i32 and PROC_PIDLISTFDS=1. It probes size, allocates Uint8Array and interprets8byte proc_fdinfo records. This is only a best-effort per-process count: unbounded kernel size allocation, no required complete second census, undefined on access/error, no FD/path/type/access/start-identity checks. Its ps parser skips malformed rows and errors return empty. Reusing either as retirement proof would weaken completeness. Existing Rust admission macOS rusage binding similarly measures memory rather than descriptor custody.

Primary Apple [libproc interface Source](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.h) supplies process enumeration, per-process/FD queries and proc_listpidspath for file/volume references; the volume-selection flag includes open references on a selected volume. The header labels these private interfaces subject to change. Apple [proc_info ABI Source](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/proc_info.h) defines8byte FD entries, vnode path/stat/access structures, process start-time fields and distinct FD, vnode/cwd, region and fileport query flavors. Thus a descriptor-table count alone is not equivalent to the existing lsof selected scope.

A genuine new OS census would need schema-first ABI layouts/constants tied to supported Darwin architectures/releases; bounded PID/FD/path/result buffers with explicit truncation/growth refusal; stable PID+start and held dev/inode/access/type checks; treatment of inaccessible processes and disappearing/reused descriptors; cancellation/progress and finite work under the same ordinary/accepted cleanup owner. It must account for nonnumeric file references such as cwd/root/mapped files wherever the existing selected custody contract refuses them, not silently scan only owned numeric FDs. proc_listpidspath volume selection is useful discovery, not an already-proven equivalent for arbitrary unmounted directory descendants.

Concrete reusable surface is the existing neutral runtime FFI and system loader, plus ABI/count precedent. Missing surface is an owned complete selected Native census/result contract and actual Darwin tests proving foreign/unknown/permission/truncation/race refusal and positive exact guards. No speculative implementation or replacement of strict lsof status/completeness is recommended from this audit alone. Linux startup remains independent priority. No FFI calls, builds, installs, process census or Source edits performed; only local Source and official Apple header reads.
