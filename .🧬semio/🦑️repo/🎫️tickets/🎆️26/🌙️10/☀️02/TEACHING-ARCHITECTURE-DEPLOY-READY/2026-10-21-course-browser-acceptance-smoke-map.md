# Course Browser Acceptance and Post-Build Smoke Map

Read-only current target/spec mapping; no browser, Source evaluation, tests or deployment run. Existing fixed21 controller remains unchanged. Its suite9 runs architecture-course:test, material runs proctor:check, browser runs ci-browser-prepare (installs browser prerequisites, not learner tests), deployment runs architecture-course:deploy-check and bundle stages the proctor artifact. The package deploy-check depends on typecheck+publish and genuinely invokes end-to-end serially for dev and release-static rehearsal topologies after image/stack checks.

| User flow | Existing actual checks | Practical post-build observation |
|---|---|---|
| Choose English/German | Playwright both-languages checks document/app lang, browser preference, explicit switch, unresolved labels and translated screens; first-visit exercises both locales | Fresh browser in each locale; switch both ways on overview, task and result without losing answers |
| Answer and complete quiz | quiz-runs plays every authored quiz to perfect score; per-task errors earn partial credit; balanced sheet rotations preserve individual answers | Complete classification/sorting/matching; verify score and feedback, no answer-by-position assumptions |
| Badges/progress | quiz-runs computes badge rules from course material and asserts earned overview/result badges; first-visit fresh-device pseudonym recalls progress | Reload completed run, return overview, sign in on fresh context with same pseudonym and compare progress/badges |
| Short interruption | connection-shortage reloads midrun and tests proctor return; proctor-away completes/saves/reloads locally, then syncs and checks another device | Temporarily stop only test proctor via existing harness; keep answering/reload, restore and verify settled progress once |
| Static release site/proctor | rehearsal serves immutable release artifact, baked cross-origin proctor; site boot, browser console/page/request/CSP monitoring; publish checks sealed HTML/assets | Open served release URL, ensure assets load, no runtime errors and correct proctor origin |
| Hardened service/persistence | deploy-check image+stack probes readiness, CORS, HTTPS redirect, headers/body cap, shared presence, graceful stop and SQLite/WAL persistence | Use accepted deploy-check evidence; verify healthy local stack and retained learner after owned restart |

Existing supported acceptance commands (not executed here): `repo run @teaching/architecture-course:test --configuration=release`, `repo run @teaching/architecture-course:ci-browser-prepare --configuration=release`, and `repo run @teaching/architecture-course:deploy-check --configuration=release -- --tag <reviewed-tag>`. Standalone existing browser target is `repo run @teaching/architecture-course:test-e2e --configuration=release -- --topology both --serial`. These describe current targets, not new prelaunch gates.

Concrete limits: ci-browser-prepare alone proves no learner flow. Controller step0 only proves that child command succeeded; detailed assertions/browser traces require owner output. Rehearsal is release static site plus production-mode proctor across origins, not the exact externally hosted CDN/certificate deployment. Proctor-away tests backend unavailability while site remains served; it is not proof of first navigation with all network disabled or indefinite offline operation. No real public deployment, DNS/TLS/operator certificate, physical mobile/tablet or alternate browser-engine pass is established by inspected Chromium topology. Published CSP/assets constrain external resources but do not replace an actual air-gapped smoke. These are post-build evidence limits, not added gates.
