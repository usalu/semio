# Authorizer Fixture Artifact Authority

The normal `repo:test-tools-authorizers` owner (42897, authoritative exit 1) executed sixteen tests: twelve passed and four failures came from two physical Source/memo fixture scopes plus their teardown emissions. The new ancestry diagnostic passed all five owning laws. This is not a UI or selected React semantic failure.

Both DATA and memo fixture bodies enter `withRepositoryTestArtifactsV1` before running Source capture. That helper opens the diagnostics Native store, which requires the captured runtime-entry provider. The ordinary raw Bun suite child has its genuine issued Original but does not have that compiled provider. The refusal is correct. Installing arbitrary provider bytes, bridging a global Original, or bypassing the store would be invalid.

The fixture bodies use temporary Source trees, memo files, physical filesystem assertions and SQLite/TypeScript oracles. Neither compiles/runs the captured authorizer nor asserts Native storage behavior. Their Native dependency is incidental to choosing a temporary directory.

The existing process test suite interface already supports authored `capabilities.artifacts`. The canonical suite runner loans its actual owned output directory through the issued child envelope; it does not grant authority from a raw environment string. A clean test-only correction is to declare that capability on the existing tools-authorizers suite and consume the exact issued artifact root in a private adjacent fixture helper. Validate the issued Original and finite resource control, require the root capability, retain callback/cleanup lifetime and cancellation, and preserve every existing Source/memo assertion. Do not fall back to environment or ambient temporary roots.
