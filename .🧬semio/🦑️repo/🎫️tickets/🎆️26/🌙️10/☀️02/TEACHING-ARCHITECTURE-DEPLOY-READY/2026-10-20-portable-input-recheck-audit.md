## Existing Bounded Window Integration

The existing API is withNativeRecheckWindowV1(asyncBody, milliseconds), implemented by AsyncLocalStorage.run (image/📡️roster/🟦️.ts:55–62). Units are integer milliseconds; schema ImageProtocol declares default500 and maximum5000; negative, fractional or above-cap input refuses. Zero requests strict behavior. Age is measured from full verification START, not completion (:72), so a slow check does not extend the freshness allowance. Every invocation still runs cheap identity/control checks before reuse (:69); expired views run full verification. Concurrent callers may join only within the age bound; a failed joined full check causes the joiner to perform its own full check (:71). This API introduces neither new control nor cancellation budget. Existing control checks, descriptor custody, per-file hashes/EOF/ancestry checks and progress/yield cadence must remain.

Existing owned roster tests (roster/🧪️tests/🟦️.ts:71–105) execute the actual gate and compare neutral timing cases with a Python oracle: expiry, zero strictness, cheap checks on every call, single-flight join, failed partner retry and context restoration. These tests were read, not run.

A narrow integration would retain the graph store, perform an explicitly strict checkpoint using withNativeRecheckWindowV1(()=>store.recheck(),0), enter only the existing per-cohort source-reading callback with the default500ms window, and perform another explicitly strict checkpoint after it returns, before graph acceptance/publication. The explicit zero is necessary if an outer caller already declared a positive window. Do not wrap image open/close/maintenance, remove per-file rechecks, or use a maximum5000ms merely to hide cost. A regression should verify reuse inside one cohort, expiry during a long cohort, cheap-check failure/cancellation, and strict final checkpoint after both success and failure; settlement remains the existing owner responsibility.
