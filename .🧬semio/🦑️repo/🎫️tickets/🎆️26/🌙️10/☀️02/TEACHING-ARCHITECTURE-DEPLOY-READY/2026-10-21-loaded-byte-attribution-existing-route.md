# Existing Route Loaded-Byte Attribution

Read-only current code inspection. No Source edits, helper/compiler/test execution, commands or attestation protocol added. Root deliberate loaded continuation is accepted as intended; this audit distinguishes concrete code paths from hypothetical same-process global mutation.

## Existing Positive Support

Actual combined.ts creates a separate owned child for each phase with process.execPath. Source phases pass `test`, the absolute actual Source file, exact escaped title selector and timeout. A child process cannot inherit the parent in-memory JS module registry or global pin counter: it starts its own runtime. Its environment is projected by scriptResourceProcessEnvironmentV1 into the issued child Original/deadline, preserving the provided environment and artifact directory. Thus parent loaded continuation is not by itself evidence that the child executes a cached parent function. Current combined code does not explicitly set BUN cache-disable variables; inherited environment values must be observed rather than invented.

Existing authorizer snapshot compiler supplies a stronger byte link for its own modules: readNxAuthorizerSnapshotV1 validates closed manifest digest, per-file base64/byte SHA and canonical resolutions; compileNxAuthorizerSnapshotV1 builds its file map from those validated bytes. onLoad reads that map, transpiles those exact bytes, injects physical Source URL and full `import.meta.semioCapturedPhysicalSources` expected-hash map, and returns generated contents. Revision reader physical capture still compares requested bytes with this expected map, even while self-check continuation is pinned; captured contexts disable settled target cache. These metadata are compiler-owned values in the actual route, not evidence supplied through arbitrary child env. This mechanism attributes compiled snapshot modules to captured manifest bytes without requiring a new protocol.

Fresh production entry creates a new empty /repo named volume/container, captures reviewed Source into it, checks received manifest, then provisionFresh verifies audited native bytes and guest received/probed native SHA/mode/ELF. Product controller independently verifies Source manifest/native and calls cp.spawn(plan.native.path, argv, {cwd:"/repo", env,...}) for each step, removing inherited Script invocation/policy so the step issues its own fresh guest Original. The guest step is a new native process, not the host already-loaded graph runtime. Native binary identity and captured guest Source are separately bound by the existing receipts.

## Specific Limits, Without Blanket Rejection

The combined runner can establish fresh child process + actual file/title invocation and pre/post physical cohort hashes. The inspected generic child environment projector adds no explicit Bun disk-cache-disable setting, and generic Bun file execution alone does not emit an independent loaded-SHA receipt. The snapshot onLoad proof covers modules actually compiled through that validated snapshot path; it must not be generalized to every arbitrary runtime import or Bun test without evidence that it used that path. A fixed compiled native binary is separately authenticated; that is a loaded implementation identity, not a claim that its embedded frontend bytes were freshly compiled from every current host Source file.

Accordingly existing routes provide useful, bounded attribution: owned fresh processes, physical expected hashes, validated captured snapshot metadata where used, and fresh guest/native separation. Deliberate loaded continuation does not erase these checks and is not grounds to block all native validation. Remaining result wording should identify actual native binary/snapshot identity and captured Source cohort, while avoiding an unsupported universal statement that every imported function was rebuilt from current disk. Async-local pin scope addresses actual concurrent-branch leakage; hypothetical ability of arbitrary evaluated code to mutate globals is a separate trust-model issue, not an observed bypass in authored capture/combined code.
