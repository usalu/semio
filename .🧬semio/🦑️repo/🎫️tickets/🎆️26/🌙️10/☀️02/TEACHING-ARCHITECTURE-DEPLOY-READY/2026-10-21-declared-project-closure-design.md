## Roles the Repair Must Preserve

`declaredTypeScriptProjectsV1` returns three OWN projections: files, packages and configs. `files` is MIXED: each declared config, every extended config, and in-workspace `program.getSourceFiles()` entries. The latter can include ordinary modules, declaration files and resolved JSON; installed package sources are represented as package names, and .cache paths are excluded. `configs` is the absolute declared-config list. Thus neither project.files nor the complete joined closure is an exact compiled COMMAND module set.

This distinction is operational: owner-discovery183 reads compiledNames from each targetScriptSources array into that target’s commandModules; line217 seeds commandModules using the COMMAND/runtime demand role. Marking every joined member compiled would promote configs/data/freshness resources and compiler-only members into command runtime roots. A cache-global modules/resources Set is not per-command authority either. Existing source-demand compiler matching and explicit source-contract entries must retain their separate compiler authority and strict guards.

For each produced file actually encountered in project.files, declaredProjectClosure currently records the produced target/output under the first declared config’s ABSOLUTE path in generatedImports at207. Merely copying the old command compiled Set fixes the missing-array error but does not select these config-indexed dependencies: the config is correctly not a command module. Promoting the config into compiledNames/moduleSets to select them would falsify its role.
