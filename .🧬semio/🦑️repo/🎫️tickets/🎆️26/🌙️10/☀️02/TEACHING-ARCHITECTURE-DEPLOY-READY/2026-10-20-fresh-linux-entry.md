# Fresh Linux Entry Preparation

The new `🌱️linux/entry.ts` owns creation, native provisioning and the receiver adapter. `📦️fresh/script.ts` owns host Source inventory and drives the direct stream. Everything here is unrun; no container, volume, Source capture, provisioning or product command occurred.

The entry schema and language-neutral cases precede implementation. `🌱️linux/verify.ts` imports 90 prepared cases: 46 controller, 14 entry admission, seven actual creation-port flows, six phase-owner cases, eleven physical PAX parser cases, one full receiver namespace-collision case and five actual finish/publication cases. These are prepared, not passed. Tests use existing Ajv, independent SQLite and Python standard tarfile. Receiver parser tests execute the actual `safe` and `members` AST definitions over byte archives, including oversized/chained metadata, forbidden GNU/global/sparse types, large regular headers, Unicode paths, bad checksum and truncation. They do not execute Docker or Source extraction. TypeScript syntax parsing alone returned zero diagnostics.

Creation reuses the actual reviewed Linux amd64 toolchain image `sha256:8f5852254c08a5941feea6ceb0610dbc5f66063702cfeb7f9a4edb76997e9a9b`, then requires new exclusive cohort, container name, source volume, run token and operation. Before effects, Root supplies the actual host engine ID and capture-plan SHA. Exact labels and a sole writable `/repo` mount bind custody. Docker data stays outside Source at `/var/lib/course-docker`; the initial `/repo` must be empty. Failures retain volumes and partial paths, and report actual transport outcome or unknown; only exact created/admitted workload custody authorizes stopping and verifying the dedicated builder. they never adopt an unrelated container or remove a volume. Actual engine readiness and tool versions must still be proved before acceptance.

The direct receiver is one stdin subprocess inside the native-issued operation, with bounded output, stdin backpressure, finite deadline, cancellation, tree termination and awaited client close. It validates each physical header before allocating metadata, creates ordinary files exclusively, emits the final manifest last, and checks the whole received roster against that manifest. Capture failure always joins the client, including zero-write failures. Only exact live container plus exact guest owner metadata permits stopping this dedicated builder; all partial Source remains retained. A client close or stopped container is never substituted for a successful receiver terminal.

The receiver admission has no future manifest or controller SHA. Sequence: Root seals CapturePlan; create actual fresh builder and identity receipt; seal receiver admission with that actual identity; stream and verify final manifest/receiver receipt; seal provisioning plan with actual manifest/capture receipt; install audited n3 and obtain actual guest native help0; then authenticate all receipt contents and seal final21-command plan. Root must compare actual receipt files and their hash/cross-bindings, not hash syntax alone. The authored `plan.json` is deliberately unsealed.

The entry binds reviewed entry/receiver/controller/provision helper inputs by hashes, then stable file identities while streaming. Final21 acceptance keeps its separate up-to12h whole/up-to2h per-command limits; only the fresh capture entry uses 15min body plus the existing maximum60s accepted cleanup reserve. No cache is forcibly invalidated.

A separate required stage supplies genuine fresh Git metadata and guest rev-parse/log/status proof. Runtime confirmed the old Git snapshot is stale and is preparing a fresh authentic capture; no old41707 verdict may serve as current proof. Source inventory correctly excludes `.git`; final Source contract now requires the separate real Git receipt hash. No host envelope may replace the guest Original.

Creation/provision use `repo exec --projects=workspace -- bun <absolute-ticket>/🌱️linux/entry.ts create|provision <generated-plan-basename> <exact-file-sha256>`; only Root may seal and execute those inputs.
