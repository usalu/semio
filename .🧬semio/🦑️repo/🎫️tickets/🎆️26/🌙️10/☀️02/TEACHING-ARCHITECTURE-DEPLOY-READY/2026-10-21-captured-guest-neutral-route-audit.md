# Captured Guest Neutral Route: Existing Capability Audit

Read-only bounded inspection of authored source capture/core/host, fresh receiver/entry/provision/controller and combined runner. No implementation, target invention, seal refresh, Source evaluation or execution. Neutral7 auditor log watch has separately handed off explicitly partial/live; Cargo alone owns TTY12857.

## Existing Pieces Fit the Layout

Fresh create/receiver already establishes an exclusive empty /repo volume and authenticates container/cohort. Source capture transfers only Source under workspace-relative paths and final .semio-private/source.json; .🧬semio is deliberately excluded by host inventory/core payload contract. Provision authenticates that manifest and installs exact audited native binary. The controller starts new native processes against /repo. These pieces can freeze peer-independent guest Source after a successful capture; host Source edits need not alter guest bytes. They do not make captured files intrinsically immutable: guest writes remain possible and existing hash/identity/receipt checks still matter.

Combined.ts assumes its authored directory remains at the existing relative Ticket path, resolves workspace by eight ancestor steps from 📦️fresh, reads Ticket files under its Ticket root and Source rows under workspace, and creates output under Ticket/🗑️generated. Placing reviewed authored Ticket files at that same relative path under /repo preserves these assumptions and keeps Source outside Ticket. The raw combined.inputs.json itself must accompany the eighty-three listed Ticket inputs (manifest is its own expected-SHA argument, rather than a self-listed row). Empty ordinary generated directory must exist; stale generated reports/logs/receipts should not be copied. Source pins must match the captured guest cohort, not a newer host snapshot.

## Missing Existing Supported Capability

The inspected entry CLI supports only create/provision; source receiver accepts one source stream into an empty /repo and validates it as captured Source. It cannot be reused after capture to append excluded Ticket data, and adding .🧬semio inputs to Source capture contradicts its payload exclusion. Provision transfers only audited native frontend bytes and fixed ownership/probe controls. Export moves authenticated artifacts out, not arbitrary Ticket inputs into the guest.

No existing authored closed interface was found for the separate eighty-three-Ticket-input plus raw manifest transfer at their fixed relative path, nor an existing neutral guest invocation plan/terminal wrapper that accepts combined argv. The generic native exec capability can run existing supported code once present, but there is no evidence that the current fixed production controller21 admits an extra combined command. Its steps/argv/schema/receipt count are exact and cannot be silently extended. Calling an internal arbitrary Docker port or writing an ad hoc receiver would be implementation/new control surface, not an already supported invocation demonstrated here.

## Proof and Order Implications

A future deliberate route can reuse source capture and native provision but must explicitly supply the missing bounded Ticket-data transfer/custody and neutral invocation interface, or identify an existing supported equivalent before action. Required ordering: reviewed stable Source capture→authenticated received manifest→reviewed separate authored Ticket package/raw manifest transfer with exact per-file hashes and exclusive ordinary paths→native provision/new owned neutral invocation→combined eighteen-phase receipt plus actual native terminal zero, joined to guest Source manifest and Ticket package identity. This is separate neutral validation, not a substitute or unannounced twenty-second production step.

The current capture plan/persistent Ticket custody remains useful: host capture implementation files are hash/identity checked before and after capture; Source required hashes are compared during streaming. The guest neutral result must identify the captured Source epoch actually used. A combined manifest whose Source rows were refreshed from host after capture would refuse or misname that epoch and must not be fabricated. This audit finds coherent reusable primitives and a concrete missing transfer/invocation capability; it does not claim existing end-to-end support or authorize new implementation.
