# 🔍️ Stdio PDF and glTF MutationKind Audit (Diff-Only Mutations)

Read-only audit against `📋️design.md` (laws L1–L5, codes V1–V4). No source file was edited, no cargo or bun build was run, and no git-modifying command was used. Scan scripts and raw outputs are in `🗑️generated/` (`audit-stdio-*`).

Repo root: `/Users/ueli/Documents/semio`. Artifact roots: `/Users/ueli/Documents/semio/✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/📖️pdf` and `/Users/ueli/Documents/semio/✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🧊️gltf`.

## Scope and method

- Inventory: 272 `impl … MutationKind<…> for …` sites (pdf 151, gltf 121), one per kind file. 0 hand-written `impl Mutation<…>` (V3-HAND-MUTATION = 0). Diff types: 2 `MutationDiff` impls for pdf (`PdfDiff` in standards 4️⃣1.4 and 7️⃣1.7), 1 for gltf (`GltfDiff`). Each has `DiffAlgebra` too.
- Scan: every kind's `fn diff` and `fn inverse` body was extracted by brace matching and pattern-classified (`.apply(`, `&mut`, `base.clone()`, `between(`, `graph_edit_diff`/`diff_graph_edit`, `DiffAlgebra::inverse`, `Restore(Box::new(…))`, `Vec::new()` early returns).
- Helpers were opened by hand for every pattern family, and a representative sample of each family was read in full (set-page-text, collapse-page-size, set-mark-info, set-info-title, insert-object, set-snapshot ×2, patch-snapshot, add-required-extension, change-node-name, change-material-alpha-mode, gltf fixture corpus).
- Tests: every kind's test files were resolved (`#[path]` plus `🧪️tests/**`) and checked for inverse-step replay with a base comparison (L3) and for `absorb` use. The gltf corpus helper `fixture_corpus_tests::assert_case` was read in full.
- Known limitation: the machine was heavily loaded (load average above 100). A transitive helper-resolving pass did not finish, so helper effects were applied from the hand-read helper bodies, not from an automated closure. Classification of the 62 clean pdf kinds rests on their bodies and the helpers they call, which were checked by reading the `diff_*` builder module (see Notes).

## Tests (L3 and L4)

- pdf: 151 kinds, 148 with some test file, 3 without (SetSnapshot 4️⃣1.4, PatchSnapshot 4️⃣1.4, SetSnapshot 7️⃣1.7). Nine kinds replay inverse steps and compare to base (L3 round trip): SetPageSize, CollapsePageSize, SetPageText, ClearPageText, ReplacePageText, ResizePage, InsertPage, MovePage, RemovePage. Another 38 kinds call `inverse()` only to compare it with a concrete expected vector (L2 check, not L3). The rest assert the forward diff only.
- pdf `absorb`: no per-kind test uses `absorb`. `absorb` is tested only on the diff types (4️⃣1.4 `🔺️diff/🧪️tests/🔬️unit/🦀️.rs` lines 58–92, 7️⃣1.7 `:59`, gltf `🔺️diff/🧪️tests/🔬️unit/🦀️.rs` lines 78–144).
- gltf: each of the 121 kinds mounts one committed corpus case through `fixture_corpus_tests::assert_case` (`✏️s/🔌️plugins/🗄️stdio/🗿️artifacts/🧊️gltf/…/🧪️tests/🧪️fixture-corpus/🦀️.rs:115`). The corpus has 122 cases, one-to-one with the mounted names: 118 applied, 4 rejected. For applied cases, `assert_inverse_restores` does the sequential L3 check: `restored = diff(mutation,before).apply(before)`, then for each inverse step `restored = diff(step, restored).apply(restored)`, and it asserts `restored == before`. That is the sequential form of L3, not the absorb-sum form. The 4 rejected cases (MoveNodeChild, MoveSceneRootNode, ReorderNodeChildren, ReorderSceneRootNodes) have no inverse path by design. No gltf kind tests `absorb(...)`.
- Strict reading of L3 (`Σ = absorb(d1..dn)` and `Σ.apply(after) == base`, plus `Σ == diff.inverse`): not tested for any of the 272 kinds.

## Notes and open points

1. L5 is not implemented. `MutationDiff::apply` is a public trait method with no `ApplyCapability` gate (no `ApplyCapability` symbol exists in `🧰️framework`). Leaves can call it today, which is why 120 gltf kinds and 2 `Restore` arms do. The textual gate `verify mutation-outcome-law` was not found under that name in the framework; `🧪️tests/🧪️outcome-law-gate/🟦️.ts` checks outcome-code vocabulary only.
2. `InsertObject` (V2-EMPTY-INVERSE, medium confidence): the diff appends an object with the given id and does not reject a duplicate. The inverse returns `Vec::new()` when that id already exists in `base`, so a state change has no inverse. Confirm with a runtime test before fixing.
3. `SetSnapshot` (both artifacts) and `PatchSnapshot` are whole-snapshot mutations. Their inverses are whole-snapshot restores (SetSnapshot), which L2 forbids. Replacing them needs a design decision about whole-snapshot replacement (no sparse diff exists for it), so per-kind edits alone will not clear them.
4. The pdf `SetInfoTitle`, `SetMarkInfo` families are V1+V3 with concrete inverses (no V2 code). `InsertObject` is V1+V3 and carries V2-EMPTY-INVERSE (see note 2). Fixing their diffs (L1) does not change the concrete inverses.
5. The 4 rejected gltf kinds (`MoveNodeChild`, `MoveSceneRootNode`, `ReorderNodeChildren`, `ReorderSceneRootNodes`) take the derived path in their diffs; rejection then makes their inverse empty, which is correct. Their L3 test is vacuous, not missing.
6. Some pdf `EmbedFontFile` and `SetAfRelationship` diffs silently return an empty diff when their target is missing (no refusal). Not in the code list; noted for the reviewer.
