## Finding that shapes the design
The renderer/host does NOT report a whole scene. `World3dHost` and the shell already speak a gesture vocabulary (surface verbs `translateSelection` / `rotateSelection` / `scaleSelection` with ids and deltas, `interactionSelect`, `patchInspector`, `createAttraction`, ...), and the plugin's tool machine (`Puzzle{3,5}dTransformWork`, the retained `*Work` jobs, `transform` tool phases `once/stream/commit/abort`, xstate oracle in `🧩️puzzle/🧪️tests/🧪️transform-gesture`) already turns those into concrete kinds. The "whole-scene report" was INTERNAL: the plugin's command arms edited a structural-twin scene (`Puzzle3dSceneSnapshot` / `Puzzle5dDocument`) and `dispatch_step` / `handle_action_impl` differenced it against the document (`puzzle3d_operations_from_host_snapshot_change`, `puzzle5d_operations_from_document_change`, `puzzle{3,5}d_snapshot_mutations`). So the host gesture protocol = the existing action verb vocabulary; no wire schema changed, no renderer/TS change was needed. What I did is complete the protocol on the plugin side: every gesture verb now yields concrete kinds from `(typed base, payload)`; the differencing path and its translators are deleted. Production routing for most mutating verbs already ran through dedicated retained Works emitting concrete kinds; the differencing arms were the residue (plus the unstaged `handle` adapter, tests, clipboard and `kit:in` import).
