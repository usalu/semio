### Semantic rulings taken (greenfield, flagged)
- **Collection ops** are expressed as `removed`+`added` rows (move/reorder re-add the moved entries at final index; node children inside moved nodes are remapped in the
  added item) plus renumbered-referrer `modified` rows — `GltfDiff::inverse`/`absorb` already handled this.
- **delete-X** keeps its cascade only where a bind kind can restore it (node mesh/camera/skin, primitive material/indices/attributes/targets, scene roots, node children,
  default scene); deleting an entry still referenced from a site no kind can rebind (skin joints/skeleton/ibm, animation channel node, bufferView→accessor/image,
  texture→material, image/sampler→texture, buffer→view) is now rejected `gltf.reference.in-use`. Exactly invertible; the independent subset fixtures only delete
  unreferenced or restorable entries.
- **create-X** gained an optional full record (`scene,node,mesh,material,texture,image,sampler,skin,animation,primitive,target,buffer,accessor,bufferView,camera`; for accessor/bufferView/camera it must agree with the still-required minimal fields, `gltf.mutation.record-mismatch`). `delete-X`'s inverse is `create-X(position, record)` + re-binds. Record references are validated (`check_*`).
- `change-primitive-topology-mode.mode` is nullable (`null` clears) so its inverse is exact; clearing morph weights is always admitted (inverse of setting them);
  `create-morph-target` also requires empty mesh weights (symmetric with delete); `change-node-transform` rejects a node holding matrix and TRS.
- `x-semio-inverse-rows`: `bounded 1025` for delete-{scene,node,mesh,accessor,material,skin,camera} and move-node-parent; `fixed 2` for unbind-primitive/morph-attribute.

Gate: file-level runner over every gltf `.rs` reports 0 breaches; the full `bun ./📜️script.ts verify mutation-outcome-law` result is at the end of this section. `rustfmt` syntax gate 533 files, 1197 json files parse.

1. **Framework list delta adopted.** Scene roots, node children and skin joints are `GltfRefsDelta`; document `extensionsUsed`/`extensionsRequired` are `GltfStringsDelta`; primitive attributes are `GltfAttributesDelta`; primitive morph targets are `GltfTargetsDelta`; animation channels and samplers are `GltfChannelsDelta` and `GltfAnimationSamplersDelta`. All six are `protocol::plain_list_delta!` invocations (`values_only`, because the rows lack `DslField`): wire `removed:[{id,index}]`, `inserted:[{index,row}]`, `moved:[{id,from,to}]`, applied with `commit_onto(base, capability)` inside the entity diff's `apply`, inverted with the delta's own `inverse(base)`, coalesced with its `absorb`. The local `GltfWeakCollectionDiff`-based list rows, `GltfAttributesDiff`, `rows_inserted/removed/moved/patched/reordered/reordered_by`, `rows_between`, `absorb_rows` and the `ItemDiff<GltfMorphTarget>` impl are deleted. No wire field is called `patched`.
2. **Keys.** `GltfRef(usize)` (transparent) is keyed by its index, strings by themselves, `GltfAttribute` by its semantic. Rows with no natural identity (morph targets, animation channels, animation samplers) are keyed by their `Debug` text, so a document holding two byte-identical rows in one such list is refused by the delta's duplicate-key check when that list is edited. A morph-target attribute edit replaces the whole target row (remove + insert at the same position), because a target's key is its content. Replacements (rewire after a delete/move/reorder of a referenced entry) remove the old row at its base position and insert the new row at its after position.
3. **Mutation leaves.** 28 leaves and `move-node-parent` build their deltas from payload plus base reads (`Delta::insertion/removal/relocation`, `Delta::rows` with `moves_to_order`/`moves_to_keys`, `target_replacement`); `rewire` uses `rewritten`, `refs_through` and `attributes_through` (read-only). New helpers `order_after_move`, `target_with_pair`, `target_without_pair`, `target_in_order` build the new value without a mutable clone of a base parameter.
4. **Position-addressed entity arrays keep their own algebra.** The 13 top-level collections and a mesh's primitives are addressed by position from elsewhere (`node.mesh`, `primitive.material`, …), so a position is their identity and they have no key for `Keyed`. `GltfCollectionDiff` (removed base position, modified base position + row diff, added final position + item) stays for them, extended with `amended` (the diff of a row this same diff adds, keyed by its final position) because an entity diff now owns list deltas that can only be committed under the capability, so `absorb` can no longer fold a later modification into an added record. This is the one place a second positional algebra remains; if the framework wants it gone, it needs a synthetic row identity for these arrays (open question for the coordinator).
5. **Apply under the capability.** `ItemDiff::apply(&self, base, capability) -> MutationApplyResult<T>` (no `merge_into`, no `validate`); `GltfCollectionDiff::apply(base, target, capability)` validates positions and refuses with `mutation.apply.*` codes; the mesh diff forwards the capability to its primitives; `GltfDiff::apply` forwards it to every collection and list delta.
6. **`between` is gone.** `DiffAlgebra::between` was deleted by the wave-5 ruling and a peer sweep removed every gltf `fn between`; I re-added them by mistake mid-wave and removed them again (`list_cut`/`cut_delta` went with them). The trait keeps `inverse` and `is_empty`.
