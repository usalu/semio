## What exists (done by the package lead; do not redo, read the files)

**Schema (generated by `T/r3-f1-gen-model.ts` from `T/r12-w2-f2-families-model.ts`)**, types are `crate::…` of the artifact:
- unit enums `FamilyCategory {Furniture,Equipment,Casework,Plumbing,Lighting,Mechanical,Electrical,Generic,Profile}`, `ParameterKind {Length,Angle,Real,Integer,Boolean,Text,Material}`, `SolidAxis {X,Y,Z}`.
- data enums `ParametricProfile {Rectangle{width,depth}, Circle{diameter}, IShape{width,depth,web,flange}, Polygon{points:Vec<ExprPoint>}}` (all dims are `String` formulas),
  `SolidShape {Extrusion{profile,base,height}, Revolution{profile,axis:SolidAxis,angle}, Sweep{profile,path:Vec<ExprPoint>}, Cuboid{x,y,z,width,depth,height}}`.
- records `ExprPoint{x,y:String}`, `ExprPoint3{x,y,z:String}`; entities (collections of `ModelSnapshot`, all `BTreeMap<String, _>`, skipped when empty):
  `families: Family{name, category}`, `family_parameters: FamilyParameter{family, name, kind, value}` keyed by `family.name` (`formula::parameter_id`), `family_solids: FamilySolid{family, name, shape, material, visible, offset:ExprPoint3}`.
  Patches `FamilyPatch`, `FamilyParameterPatch`, `FamilySolidPatch`; `ModelDiff::families/family_parameters/family_solids(id, Entry)`.
- `Profile::Family { family: String }` is a new variant of the snapshot `Profile`. Exhaustive-match arms were added (editor `profile_text`/`parse_profile`, IFC data/frames, bodies, element-solids polygon, validity, wall-geometry, sqlite refuses).
- Formulas are canonical text of `semio_framework_expression::print`. The expression crate is a dependency of the artifact crate.

**Leaves** (8, tags 23000..23007, all with fixtures, hand-written diff/inverse; shared rules in `S/🧬️schema/🧬️mutations/🔩️family-rules`): `create-family {id, family}`, `set-family {id, name?, category?}`, `delete-family {id}`
(cascades its parameters+solids, refuses while a Profile uses it), `set-family-parameter {family, name, kind?, value?}` (upsert, key `family.name`; a formula must parse, use only EXISTING parameters of the family and never close a circle),
`remove-family-parameter {family, name}` (refuses while another formula or a solid refers to it), `create-family-solid {id, solid}`, `set-family-solid {id, name?, shape?, material?, visible?, offset?}`, `delete-family-solid {id}`.
Variants in `ModelMutation`: `CreateFamily`, `SetFamily`, `DeleteFamily`, `SetFamilyParameter`, `RemoveFamilyParameter`, `CreateFamilySolid`, `SetFamilySolid`, `DeleteFamilySolid` (payload structs in the leaf `🦠️mutation` files;
the `Set*` payloads have `patch()` / `from_patch(..)`). Outcome codes: `mutation.invariant` (also for a formula that does not parse — the framework outcome vocabulary is frozen, there is no `mutation.formula-invalid`),
`mutation.target-missing`, `mutation.target-referenced`, `mutation.duplicate-id`, `mutation.no-op`. The editor canonicalises a formula (`formula::canonical`) before it emits a mutation.

**Inference core** `F` (module `semio_s_artifact_bim_model::standards::v1::subsets::any::schema::inferences::families`, re-exported names below), pure and unit-tested in `F/**/🧪️tests`:
```rust
pub fn family_of(snapshot: &ModelSnapshot, id: &str, overrides: &BTreeMap<String, String>) -> FamilyValue;   // overrides = formula texts of an instance (components, F3)
pub fn dependency(snapshot: &ModelSnapshot, id: &str) -> DslValue;                                           // what family_of reads of the snapshot (the dep_input of a Family node)
pub const READS: &[&str] = &["families", "family_parameters", "family_solids", "materials"];
pub struct FamilyValue { name: String, category: Option<FamilyCategory>, order: Vec<String>, parameters: BTreeMap<String, ResolvedParameter>,
    solids: BTreeMap<String, FamilySolidMesh>, outline: Vec<Vertex> /* crate::Vertex, CCW; non-empty only for a Profile family with a visible extrusion */, issues: Vec<FamilyIssue> } // ToValue/FromValue/Clone/PartialEq/Default
impl FamilyValue { fn value(&self, name) -> Option<&ParameterValue>; fn visible(&self) -> impl Iterator<Item=(&String,&FamilySolidMesh)>; fn volume(&self) -> f64 }
pub struct ResolvedParameter { kind: ParameterKind, formula: String /* effective canonical text */, value: Option<ParameterValue> }        // None = failed (see issues)
pub enum ParameterValue { Number{value:f64}, Length{value:f64} /*m*/, Angle{value:f64} /*rad*/, Boolean{value:bool}, Text{value:String} }
pub struct FamilySolidMesh { name, material: String /*evaluated id*/, visible: bool, positions: Vec<f64>, normals: Vec<f64>, indices: Vec<u32>, bounds: SolidBounds, volume: f64, area: f64 } // family frame, metres, flat arrays like ElementSolid
pub struct FamilyIssue { code: FamilyIssueCode, owner: IssueOwner, subject: String /*parameter name | solid id | ""*/, field: String /*value | height | profile.width | path[1].x | …*/, path: Vec<u32> /*Expr child indices*/, detail: String /*EN fallback*/, names: Vec<String> }
pub enum FamilyIssueCode { Syntax, Kind, Cycle, Unknown, DivisionByZero, Negative, Dependency, Domain, Outline }   // .slug() kebab-case, ::ALL
pub enum IssueOwner { Parameter, Solid, Family }
pub fn issues::message(issue: &FamilyIssue, locale: &str /* "en" | "de" */) -> String                          // localized text for the UI and the diagnostics
pub struct FamilyProfiles<'a>;  fn new() / with(id, &outline) / outline(id) / resolve(&Profile) -> Cow<Profile>  // Profile::Family -> Profile::Custom { outline } ; unknown -> empty outline
pub fn family_of_profile(&Profile) -> Option<&str>
// formula module: is_name, parameter_id(family,name), split_parameter_id, parse_formula, canonical(text)->Result<String,ParseError>, is_canonical, references(text)->BTreeSet<String>, solid_slots(&FamilySolid)->Vec<(field, &str)>
// parameters module: resolve(snapshot, family, overrides)->Resolution { order, parameters, env, names, issues }, kind_of(ParameterKind)->Kind, authored(snapshot, family)
```
Semantics: bare numbers are not lengths (write `0.4 m`, `400 mm`); a Rectangle/IShape/Circle profile is centred on the origin; a Revolution profile must lie right of the axis (use a Polygon); the section of a Profile family
is the profile of its first (by solid id) visible Extrusion (translated by the solid offset); a hidden or failed solid keeps its (empty) entry; a failed `visible` formula counts as visible.
The framework geometry gained `mesh::revolve_profile(profile:&[Point], sweep, tolerance)` (verified: `cargo test -p semio-framework-geometry` via `🧰️framework/Cargo.toml`).
