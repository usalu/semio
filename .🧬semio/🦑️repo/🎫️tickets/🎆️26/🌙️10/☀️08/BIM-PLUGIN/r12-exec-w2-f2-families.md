## Delivered

Schema (via `r3-f1-gen-model.ts`, model in `r12-w2-f2-families-model.ts`): collections `families`, `family_parameters` (key `family.name`), `family_solids`; enums `FamilyCategory` (9), `ParameterKind` (7), `SolidAxis`; `ParametricProfile` (Rectangle, Circle, IShape, Polygon), `SolidShape` (Extrusion, Revolution, Sweep, Cuboid); structs `ExprPoint`, `ExprPoint3`, `Family`, `FamilyParameter`, `FamilySolid`; `Profile::Family { family }`. Generated Rust/JSON/TS/GraphQL/proto. Binary tags 23000..23007. The generator's stale patch emission and artifact JSON/ts typing were fixed in `r3-f1-gen-model.ts`.

Leaves (`r12-w2-f2-families-leaves.ts`): `create-family`, `set-family`, `delete-family`, `set-family-parameter`, `remove-family-parameter`, `create-family-solid`, `set-family-solid`, `delete-family-solid`; case counts 5/8/5/15/5/11/11/2 (applied and rejected fixtures per leaf), en+de labels, x-semio-ui, cross-kind id uniqueness (`🧵️elements` `taken`), enum + KINDS + root mounts + feature rows. Shared rules in `🧬️schema/🧬️mutations/🔩️family-rules`. Refusals: `delete-family` TargetReferenced while a column type, beam type, curtain wall type, wall sweep or railing names it as `Profile::Family` (authored references only); `set-family` cannot take a profile family out of `Profile` while used; `remove-family-parameter` TargetReferenced while another formula or a solid slot refers to it (`semio_framework_expression` references on parsed authored text); `set-family-parameter` refuses unparsable text, unknown names and cycles (`plan`). Delete-family also cascades properties/classifications keyed by the family (`cascade::data_diff`/`data_rows`) and its inverse recreates parameters in dependency order.

Inference `🧬️families` (`S/🧬️schema/💡️inferences/🧬️families`): per-family graph node with no parents, honest `dependency()` (exactly the family's parameters, solids and the referenced materials), resolved parameter values, evaluated solids as meshes (framework `📐️geometry` extrude/sweep/revolve; tessellation contract chord tolerance 1e-4 shared with the oracle), `outline` for `Profile::Family`, nine diagnostic codes (syntax, kind, cycle, unknown name, negative, zero-division, ...) with en/de messages, 10 new `DiagnosticCode`s in the model diagnostics. Solid, Quantity and Diagnostics nodes of columns/beams/curtain walls/railings take family parents, and the existing solids resolve `Profile::Family` through `FamilyProfiles`. Cache-transparency, gating, dependency and dangling-reference tests are in `🕸️model-graph/🧪️tests/🧬️families` (not run).

Editor: window `bim-edit-family` (table: part, item, formula input, evaluated value, issue, actions; solids with one formula input per slot, add/remove, revolution axis turn, kind cycle) and `bim-edit-family-view` (3D preview of the visible solids); command `editFamily` (`🎮️commands/🧬️edit-family`, one pure `edit::apply` -> sparse leaf mutations); entity rows `family` (library, category picker, volume + issue count inferred) and `family-solid` (child of its family, shown under it in the outliner); create-entity container rules; accessible names and descriptions; 64 en+de labels and 14 fault notices (`r12-w2-f2-families-labels.ts`). Formulas are canonicalised before they reach a mutation.

Oracle (`S/🧪️tests/🧬️infer-bim-1-families`): `🐍️.py` evaluates parameter values with the F1 python evaluator (Pratt translator from Semio formula text), builds solid volumes with numpy/shapely (mitered sweep, revolution rings), audits closed forms, parameter-order invariance and the widening law; `🥒️.feature` has `@id-families-table` and `@id-families-frame`; committed expectations written by the oracle `write`; oracle `bim-1-numpy-expression-families` registered in `S/🔮️oracles/🔣️.json`.
