# 🔮️ BIM Oracle Pattern (r3, label `o-oracles`)

How an oracle is declared, executed and refreshed for a plugin feature in this repo, with the BIM paths. Every claim below
was read from the cited file or exercised on 2026-10-08 (commands and outputs: `r3-exec-o-oracles.md`).

`S` = `✏️s/🔌️plugins/🏙️bim/🗿️artifacts/🏢️model/🏅️standards/🔖️1/🪆️subsets/✳️any` (the subset root; the plugin root is `P` =
`✏️s/🔌️plugins/🏙️bim`). Harness module `H` = `🧰️framework/🛍️products/🦑️repo/🔨️modules/🧪️test`.

## 0. The five pieces of the platform

| Piece | Where | What it is |
|---|---|---|
| Case | `S/🧪️tests/<emoji><kebab-slug>/` | `🥒️.feature` (normative, language neutral) + one adapter per implementation: `🦀️.rs` (subject), `🐍️.py` / `🟦️.ts` (oracle). Nothing else lives in a case dir. |
| Fixtures | `S/🧫️fixtures/…` (immutable, reached by `shared://<path under 🧫️fixtures>` URIs written in feature steps) | JSON inputs and committed expectations. A case-private folder `🧪️tests/<case>/🧫️fixtures` is `local://`. |
| Oracle registration | `S/🔮️oracles/🔣️.json` (`oracles`, `noOracleDecisions`, `mutationCatalogs`, `mutationManifests`, `comparisonProfiles`, `testEvidence`) | The subset's own contribution. `$schema` = `H/🧬️schema/🔣️.json`, `schemaVersion: 2`. |
| Host packages | `P/🔮️oracles/🔣️.json` → `oracleHostPackages` | Which external distributions the adapters import. Resolved from every manifest at or above the case owner (`H/🕸️dependencies/🟨️.mjs` `packagesForOwner`), so the plugin level is always an ancestor. |
| Harness | `H/📜️script.ts` | `discover`, `contract`, `oracle <level>`, `subject <level>`, `parity <level>`, `fixture verify|audit|reproduce`, `dependency`. |

Feature tags (checked by `H/🥒️gherkin` and the contract): feature level `@capability-<id>`, exactly ONE `@oracle-<oracle-id>`
(or `@no-oracle-<decision-id>`), `@comparison-<profile-id>`, and for mutation vocabularies `@mutations-<catalog-id>`;
scenario level `@id-<id>`, exactly one `@level-fundamental|quick|long|exhaustive`, exactly one
`@mode-differential|conformance|round-trip|property|error`. A `@no-oracle-*` decision is recorded debt (it can never
cover a mutation capability: breach `no-oracle-covers-mutation`); BIM does not use it.

An oracle is a **third-party library** (`kind: third-party-library | third-party-cli | standards-reference-tool`) or a
`verified-native-second-implementation` (supplement only; gismap and shooting use this, README: "never a substitute").
Oracles are `testOnly: true`, `productionReachable: false`, `networkDuringExecution: false`, and appear in
`🔒️dependencies.json` as `test-oracle` (regenerated by `bun ./📜️script.ts dependency`; the entries `shapely` and
`ifcopenshell` there already exist and gain the new `oracleIds`).

## 3. (b) Inference oracle — python `shapely` + `ifcopenshell` from a snapshot fixture

Built and green: see section 6. Recipe:

```
S/🧫️fixtures/💡️inferences/<case>/📸️snapshot/🔣️.json                     authored snapshot (the ONLY input)
S/🧫️fixtures/💡️inferences/<case>/💡️inference/<emoji><slug>/🔣️.json      expected table per inference, WRITTEN by the oracle
S/🧪️tests/<emoji>infer-bim-1-<topic>/{🥒️.feature,🐍️.py}                   one oracle id per feature
S/🧪️tests/<same>/🦀️.rs                                                     subject adapter (crate owner), compares its ModelInference output to the same table
```

- One `@oracle-<id>` per feature, therefore **one case per oracle library** (shapely case, ifcopenshell case, networkx case…).
  Each case reads the same `shared://💡️inferences/…` URIs. The ifcopenshell case consumes the committed table (it measures
  it) so no arithmetic is duplicated across cases.
- Adapter skeleton (`🐍️.py`): pure functions at module top (importable and runnable standalone: `python 🐍️.py check|write
  <S/🧫️fixtures/💡️inferences>`), then `def adapter()` that imports `semio_repo_test` lazily and registers
  `Adapter("python").oracle("<scenario @id>", handler)` — **oracle role only** (registering as subject would be a green
  self-comparison). A handler gets `ctx` (`ctx.step_input_uris()`, `ctx.input_bytes(uri)`) and returns
  `Outcome(projection, raw=…)`; the projection is what the subject's projection is compared with under `@comparison-floating-point-v1`
  (core profile, tolerance 1e-9).
- Expected tables are produced by `python 🐍️.py write …`, never typed. A table is committed only after the audit routes
  agree (`shapely` length/footprint within 1e-9 / sampled arcs within 1e-5, `ifcopenshell` kernel z-extent + volume within
  1e-9, parametric law). Closed-form values go into the table when a third party can only approximate them (arcs); the
  library then *audits* them.
- Libraries and what they can actually adjudicate (measured, not assumed):
  - `shapely` 2.1.2 (GEOS): `LineString.length`, `buffer(t/2, cap_style="flat")` for unjoined footprint areas, `unary_union`
    of joined footprints, `Polygon.area/length/centroid`, `polygonize` for room outlines, `affinity.*`. Arcs are sampled
    (4096 chords) — no true arcs in GEOS.
  - `ifcopenshell` 0.8.4.post1: `api.project/root/spatial/aggregate/geometry` build an IFC4 model; `geom.create_shape` +
    `util.shape.get_vertices/get_volume/get_area` measure walls, slabs, columns; `api.geometry.add_wall_representation`,
    `add_slab_representation`, `add_profile_representation`; `util.element.get_psets` / `ifcopenshell.util.element` read
    Psets and quantities back; `file.from_string(model.to_string())` forces a Part-21 round trip. Trap found: keep the
    `create_shape` result alive in a variable (`shape = …; geometry = shape.geometry`), otherwise `get_vertices` returns an
    empty array. Default `assign_unit` is millimetres; the API converts, the kernel returns metres.
  - Arithmetic-only inferences (storey elevations are running sums) have no third-party owner; pin them with `math.fsum`
    (exactly rounded) vs the subject's f64 sum, the metamorphic parametric law (change one storey height → exact set of
    storeys/walls that move, by exactly delta), and kernel z-extents.
- IFC export validation (Wave X): the export adapter lives in `S/🧪️tests/🔺️differential-bim-ifc-2x3/🐍️.py`
  (model: `✏️s/🔌️plugins/🗄️stdio/…/🏗️ifc/…/🧪️tests/🔺️differential-ifc-4/🐍️.py`, tag `@oracle-ifcopenshell-…`,
  `@comparison-semantic-ifc-v1`). It opens the exported `.ifc` with `ifcopenshell.open`, asserts `by_type(...)` counts
  per IFC class vs the snapshot's collections, `ifcopenshell.util.element.get_psets(wall, qtos_only=True)` for
  `Qto_WallBaseQuantities` (`Length`, `Height`, `Width`, `GrossSideArea`, `NetSideArea`, `GrossVolume`) against the
  `🧮️quantities` table, and re-measures solids with `geom.create_shape`. Host package already declared.

Oracle manifest rows for the two Wave F cases (written, harness-green):
`bim-1-shapely-geometry` (family `geos`) and `bim-1-ifcopenshell-kernel` (family `ifcopenshell`), both capability
`bim-1-infer`, profile `floating-point-v1`, in `S/🔮️oracles/🔣️.json`.

## 5. Running, and refreshing evidence / sha256

```
# direct, no host (fast loop, works on any OS with the .venv):
.venv/Scripts/python.exe S/🧪️tests/<case>/🐍️.py check S/🧫️fixtures/💡️inferences     # exit 1 on any disagreement
.venv/Scripts/python.exe S/🧪️tests/<case>/🐍️.py write S/🧫️fixtures/💡️inferences     # regenerate expectations from the oracle

# through the platform (parses the feature, provisions the python env, runs the oracle role, writes JUnit):
cd H && SEMIO_TEST_LEVEL=quick bun ./📜️script.ts oracle quick --case <emoji><slug>       # 40-85 s incl. env build
cd H && bun ./📜️script.ts discover | grep bim                                            # case → Nx project
cd H && bun ./📜️script.ts contract --case <slug>                                         # repo-wide, ~8 min; breaches → .🧬semio/🦑️repo/⚡️cache/breaches/testing.json
cd H && bun ./📜️script.ts subject quick --case <slug> / parity quick --case <slug>       # once the Rust adapter exists
```
Nx: every case has generated targets `test`, `test-quick`, `test-long`, `test-exhaustive`, `test-contract`, `test-oracle`,
`test-subject`, `test-parity` (project name e.g. `test-s-plugins-bim-artifacts-model-standards-1-subsets-any-692e06-🪜️infer-bim-1-levels-and-wall-heights`).

`testEvidence[]` (in the subset manifest) registers *generated fixture files* for mutation vectors that came from a
third-party generator (classes `real-world | handcrafted | third-party-generated`). Entry (shape from the ifc/gltf manifests):

```json
{ "id": "export-ifc-house", "class": "third-party-generated",
  "target": { "artifact": "s.bim.model", "standard": "1", "subset": "any" },
  "units": { "length": "metre", "angle": "radian" },
  "files": [{ "role": "expected-ifc", "path": "../🧫️fixtures/🚪️ifc/🏠️house/🏠️house.ifc", "mediaType": "model/ifc",
              "sha256": "sha256:<64 hex>", "bytes": <n> }],
  "generator": { "oracle": "ifcopenshell-bim-export", "packageVersion": "0.8.4.post1", "engineFamily": "ifcopenshell",
                 "engineVersion": "0.8.4.post1", "command": "…<exact command that rewrites the file>…", "platform": "win32-x64" },
  "provenance": { "source": "generated", "license": "LGPL-3.0-or-later (ifcopenshell)", "attribution": "…", "security": "scanned-clean", "privacy": "no-personal-data" },
  "comparisonProfile": "semantic-ifc-v1", "reproducible": true, "family": "structural", "notes": "…" }
```
Refresh loop (no tool rewrites sha256 for you; `fixture reproduce` deliberately never overwrites):
1. regenerate the file with the recorded `generator.command`;
2. `sha256sum <file>` / `wc -c <file>` and edit `sha256` + `bytes` in the entry (hash is `sha256:` + hex);
3. `cd H && bun ./📜️script.ts fixture verify` (digest check), `fixture audit` (contract problems), `fixture reproduce` (re-runs
   the generator and compares to the committed bytes; failure = non-deterministic generator);
4. for `💡️inferences` tables there is no evidence entry: the loop is `python 🐍️.py write` → `check` → commit; the plan pins
   each `shared://` fixture's digest at run time.
