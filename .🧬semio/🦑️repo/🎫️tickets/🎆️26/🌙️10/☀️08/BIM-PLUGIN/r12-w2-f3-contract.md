  * `MepElement { storey, system, shape: MepShape, path: Vec<Point3> /*z above the storey elevation*/, name }` — collection `mep_elements`.

* Binary mutation tags **10000..10007** are reserved for this package.
* Terminal = a component with `system: Some(..)` (the connector sits at the instance origin carrying that system). A component's family category must NOT be `Profile`.
* Host semantics (binding): a hosted component (`host = Some(wall)`) clings to the host wall: the inference projects the authored `position` onto the wall axis, takes the face of the wall on the side where `position` lies, puts the family origin on that face and turns the family so its local +y axis (depth) points away from the wall (back plane y=0 against the face); `rotation` is added on top. Unhosted: yaw = `rotation`. Family frame = x right, y depth, z up, metres (as `FamilySolidMesh`). Mirror flips local x before the turn (reverse triangle winding). World = building-local exactly like columns (follow `Column`).
* Overrides: `family_of(snapshot, family_id, &overrides)` already takes the formula texts; the instance's `FamilyValue` is the family evaluated under its overrides.

### `w2-f3-graph` — inference, graph integration, quantities, diagnostics, plan symbols, inference oracle + feature
Publish the public inference API in `T/r12-w2-f3-api.md` AS SOON AS the type signatures are fixed (before the implementation is complete), because editor and IO agents code against it; update it when it changes.
Design (copy ramps/families patterns; read `T/r7-api-model-session.md`): new inference modules `I/🪑️components` (component placement + instance solids) and `I/🌀️mep` (MEP solids and metrics) (pick unique emoji), element-solids arms `I/🧊️element-solids/{🪑️components,🌀️mep}`, plan arms `I/🗺️plan-linework/...`.
* Graph nodes: `Component(id)` with parents Storey levels, the Family node of its family (when the component has no overrides its `FamilyValue` is SHARED from the Family node; with overrides it evaluates `family_of(snapshot, family, &overrides)` itself; the dependency declares exactly the component record, its overrides, the family reads and the storey elevation), the host wall's layout when hosted; `Mep(id)`. Never scan a whole collection per element: components of a host wall / of a storey come from index nodes (per-storey spatial index) if a node needs them. The instance value is also what the `solids`, `plan`, `quantities`, `diagnostics`, `schedules`, `effective-properties` projections read; ensure gating (a family parameter edit re-infers exactly that family's Family node and its components; an unrelated edit nothing) and cache-transparency tests for the new projections + a snapshot with each issue.
* Component solids: the visible solids of the instance family meshes transformed into the building frame (yaw/mirror/translate, winding flipped when mirrored), as `ElementSolid`s with the family-evaluated material ids, so 3D, glTF, IFC bodies and volume quantities treat them like any element. MEP solids: duct/tray = rectangle section (`width` horizontal, `height` vertical for horizontal runs, rectangle kept upright for vertical runs), pipe = circle section (tessellation contract of families `Circle`: chord tolerance 1e-4), swept along the polyline with mitred joints via framework `📐️geometry` (reuse the sweep used by families/railings); one solid per element; system colouring: a fixed palette per `MepSystem` (supply blue, return orange, exhaust brown, domestic water cyan, waste olive, gas yellow, power red, data purple, lighting amber — choose and document sRGB) used for the solid's colour in 3D/glTF and for plan strokes; terminals take the colour of their system for their connector marker.
* Quantities: component count/volume/footprint per instance; totals per family, per category and per system; MEP length, section area, volume per element, totals per system and per size (e.g. `300x200`, `Ø100`); add them to the existing quantity totals machinery and, if the schedule vocabulary allows it without breaking other packages, `ScheduleCategory::Component`/`Mep` (type = family name / system); if skipped justify it in the report.
* Diagnostics (en+de messages; new `DiagnosticCode`s in `⚠️diagnostics`): `ComponentOutsideStorey` (origin below the storey floor or above its top, or in plan far outside the walls of its storey), `ComponentInWall` (non-hosted component solid footprint overlaps a wall solid outline beyond tolerance; hosted ones only when deeper than the face), `RefComponentFamily` (family missing or `Profile`), `RefComponentHost` (host missing, no wall, other storey), `ComponentOverride` (the instance family issues caused by an override: kind mismatch, cycle, unknown, negative; message from `families::issues::message`), `MepDegenerate` (shape <= 0 or zero-length run), `MepClash` (basic: two elements of DIFFERENT systems whose swept volumes intersect: segment-segment distance < sum of half-sections, broad phase on AABBs per storey), `TerminalUnconnected` (info: a terminal with no MEP element of the same system ending within 5 cm of its connector). A clash scan is the expensive part: one per-storey node (sweep and prune), reporting each pair once; expensive work follows the existing cancellation/progress mechanism of the model session.
* Plan symbols (`🗺️plan-linework`): component = oriented outline of the instance footprint (rectangle of the visible solids' bounds in the instance frame) with a short front tick (local +y) and a connector cross for a terminal; MEP = centre line plus a band of its width (duct/tray) or diameter (pipe) in the system colour, hidden layers per storey cut like ramps; vertical drops drawn as a circle/section square.
* Projections/IO tables: `ModelInference.components: BTreeMap<String, ComponentValue>` and `mep: BTreeMap<String, MepValue>` (instance transform incl. host fit, footprint, bounds, volume, connector, issues / length, section, volume, colour, segments) plus facets in `I/{🔣️.json,🟦️.ts,🔗️.graphql,🛰️.proto}` and the `table_json` text tables like `S/🚪️io/📝️text/💡️inferences/🛝️ramp-runs`.
* Oracle + feature (language-agnostic `.feature` + third-party): new case `S/🧪️tests/<emoji>infer-bim-1-components/{🥒️.feature,🐍️.py,🦀️.rs}` + fixtures `S/🧫️fixtures/💡️inferences/<emoji>components/`: python (`.venv`: shapely, numpy) recomputes the instance placement (host fit, yaw, mirror), component volumes (closed forms), plan footprint areas (shapely), MEP lengths, section areas, volumes (mitred prisms), clash pairs (shapely/numpy segment distances) and the quantity totals from the snapshot alone; and a three.js volume check for component + MEP solids through the existing `🎲️infer-bim-1-solids-three` oracle (extend its fixture list) — run as in `T/r11-exec-r11-w09-ramps.md` section 5 (`SEMIO_TEST_LEVEL=quick bun ./📜️script.ts oracle quick --case …` from the test module dir).
