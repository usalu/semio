## Item 1: store-close deadlocks (4 tests) - fixed
Root cause: `SharedValueRetirementFactory::retire` (the default snapshot factory of every artifact plugin and of the owner's `DemoSnapshotRetirementFactory`) built a NON-lease `SharedControlledRetirement`, which yields until the Arc strong count is 1. A displaced snapshot queued in the FIFO displaced queue aliases the store's tail cache / prefix ring / current snapshot, which only retire in a LATER disposer phase, so the queue front waited for an alias that could never close (`phase Displaced`, quoted demand 0, every turn a zero receipt). The store's own `BoundedArtifactRetirementFactory` already used lease semantics (`admit_shared_retirement(.., true)`: the last alias retires the payload, every other alias only drops its count via `Arc::into_inner`).
Fix: `V/♻️retirement/🦀️.rs` `SharedValueRetirementFactory::retire` now passes `lease_only = true` (docstring added). Passing now: `structural_history_replicates_as_events_over_a_backbone`, `supersede_law_tests::{a_withdrawn_planner..., every_unit_row..., every_input_row...}`, `viewer_head_tests::two_peers_on_one_folder...`.

Member-close stalls ("member retirement did not reach its terminal-empty witness"): not a Weak problem any more. They were the same defect as item 2 (a history longer than one 64-slot ledger page needed more than the helper's 65 536 turns). Passing now: `artifact_store_one_item_single_retry_ack...`, `artifact_store_one_item_stale_saturation...` (65 edits), the three `artifact_store_stamped_publication_*`, `retained_member_publication_rejects_wrong_owner...`. ## Item 2: `hot_path_tests` - root-caused and fixed (not a livelock)
Measured with a temporary scaling probe (removed again, nothing `[DEBUG]` remains from me): turns grow linearly with edits (80 edits: 80 893 turns) but each turn cost 130-430 microseconds. Two independent defects:
1. Exponential demand quoting. `artifact_retirement_box_demands` asks the child for copy, capacity, release and depth separately, and every nesting owner (`ArtifactStoreEnvelopeRetirement` -> `ArtifactStoreVcsRetirement` -> `ArtifactStoreHistoryLedgerRetirement` -> decoded edit -> ..., factory tickets, shared/owned factory retirements, read lease/authority) re-derives its whole `demands()` inside each of the four axis methods: `4^depth` quotes per turn. 80-edit close: 10.6 s; with one-pass quoting: 0.31 s (40x), 1000 edits now close in seconds. Fix: additive provided method `ErasedSnapshotRetirement::next_demand(&self, body) -> RetirementDemand` (default = the four axis calls; `V/♻️retirement/🧬️contract/🦀️.rs`); every nesting impl that computes `self.demands(..)` overrides it with one call (store: all 20 `demands(0)` impls via one replace; value: `FactoryOwnedRetirement`, `FactorySharedRetirement`, `FactoryTicket`, `ReadAuthority`, `ErasedReadLease`); the helpers `artifact_retirement_box_demands`, `artifact_retirement_owner_demands`, `factory_ticket_demands` call `next_demand`.
2. Per-element fixed arrays. `[T; N]` retired one child cursor per element: `[u8; 32]` digests (3 per revision record, plus the fold-index keys) cost ~100 turns each. New `PlainArray` cursor retires arrays of trivial elements as bounded copy work like `Vec` already does (`V/♻️retirement/🦀️.rs`). 80-edit close: 80 893 -> 29 966 turns.
Result: `hot_path_tests::local_steps_cost_o_change_however_long_the_history` timed out (150 s, 1.7 M turns) before, passes in the k5 sweep.
