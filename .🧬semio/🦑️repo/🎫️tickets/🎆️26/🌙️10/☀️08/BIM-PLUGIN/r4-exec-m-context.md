Semantics: every set kind patches exactly the provided fields (`SitePatch`/`BuildingPatch`/`GridLinePatch`/`ProjectPatch`), an empty patch or one that restates the base values is `mutation.no-op`, the inverse is the same set kind carrying the base values of exactly the provided fields (the sum law holds because no per-field filtering happens). Order of refusals: target missing, invariants, no-op. Grid line: label unique per building (the line itself excluded on set), non-blank, finite and non-zero length; delete-grid-line has no dependants. Invariant paths: `["latitude"]`, `["longitude"]`, `["boundary"]`, `["phase_names"]`, `["grid_line","label"|"end"|"building"]`, `["label"]`, `["start"|"end"]`.

Parametric docstrings: `set-site` and `set-building` (module doc of the payload and of the diff) state that changing the site or building elevation re-infers the absolute elevation of every storey (nothing downstream is written).

Inference-level tests (hand-written, generated by the spec script into `🧪️tests/🪜️raises-the-absolute-levels/🦀️.rs`, mounted with the leaf): `set_building::tests_raises_the_absolute_levels::the_building_elevation_moves_every_absolute_storey_elevation` and the twin for `set-site`; they apply the committed `raises-the-datum` / `moves-the-site` case, run `storey_levels::compute_storey_levels` before and after, and assert absolute (top) elevations move by exactly the elevation delta while the building-relative ones stay equal.

Every payload property carries `x-semio-ui` (widget, role, en+de label, group, order); latitude/longitude also carry `minimum`/`maximum`; optional properties are not `required`. All labels en+de.
