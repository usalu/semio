# Captured WASI fallback

The unoptimized `w-component-84590` Cargo capture targeted `semio-hub-bim-component` against the original `b` target graph. Its component output directory contains dependency information and no component. The separate code generation replay produced a physical `.rlink` plus 32 component codegen objects against those older archives. The serial link ended with SIGTERM and left no WASI component. That attempt already passed one linker thread, stripping, low linker optimization and disabled data segment merging. The recorded toolchain link uses `--gc-sections` and the linked WebAssembly driver's help lists it as the default.

The old hub metadata names 916 transitive archive identities. The current gbXML change alone invalidates at least 58 BIM archives in that graph. Their old physical archives total 0.72 GiB before the 170,922,468-byte hub archive and the reactor. That is a lower bound from the six changed gbXML, editor, IO, geometry, pairing and inference crates. Other current model and framework changes may increase it. The ID-matched archive enumeration is reproducible with [inspect-wasi-capture.py](inspect-wasi-capture.py).

The optimized incremental Cargo pass has already progressed through the corresponding mutation libraries, viewer and interaction to the editor kit. Rebuilding the old reverse closure directly would duplicate that work, and the old less compact archive closure already reached a link termination. A component built directly from the retained old `.rlink` would still carry its older command implementation. The fallback route was closed before claiming a current component, and the optimized build remains the current shipment path.
