# Guest preflight

Read-only inspection compared the ticket probes with the current component bridge, actor codec boundary, ingress page builder, lifetime codec, canonical WIT and BIM committed-descriptor contract. The WIT exports the five facets tested by `guest-probe.ts`: reactor, jobs, checkpoint, describe and codec. Actor activation and lifecycle receipt names and authority fields, command page owner/generation/index/sequence fields, ReadConfig and Config codec fields, and the three codec request shapes match their current definitions. The two application IDs and the IO-hop table are already sorted as the verifier requires. The three example DSL source paths, descriptor path, native host smoke binary and describe emitter currently exist. The prototype component path does not yet exist because its build is pending; no real component bytes were tested.

A concrete preflight hazard is in `verify-hosted-bim.py`: its readiness condition is only a nonzero component file whose size is the same across a five-second interval. It does not require successful build completion, a fresh receipt, hash, or atomic/sealed publication. It can therefore accept a prior component or a stalled partially linked file. It then executes the emitter and *publishes* its emitted descriptor pair, so it is not a read-only verifier. Invoke it only after the owner confirms the exact immutable component is complete and associated with the intended build; compare digest or build receipt before publication.

The direct worker deliberately fails on effects, UI patches, presence and lifecycle receipts during ReadConfig that it cannot route. This makes it a strict isolated actor-bridge smoke rather than a physical OS shard/renderer test. It admits empty config, assets, capabilities and quota packs rather than the complete descriptor-derived host activation; the result alone cannot prove production quota, assets, effect routing or UI lifecycle. Host actor calls and exact byte-level codec behavior still require exercising the pending component. `guest-probe.ts` requires a working local native transpiler or jco fallback, and `guest-browser.ts` requires an actual JSPI-enabled browser.
