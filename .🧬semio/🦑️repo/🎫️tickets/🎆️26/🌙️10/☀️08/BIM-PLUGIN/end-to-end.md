# BIM plugin end-to-end verification

The BIM composition exposes the editor and viewer for `s.bim.model@1/*`. This run checks discovery, snapshot persistence, mutation and inference behavior, exchange fixtures and the compiled component.

The first SQLite run found that the model snapshot did not expose its existing relational codec. The snapshot crate now includes the relational implementation and registers it with the public store codec. The SQLite suites use an independent SQLite engine to check the physical tables, edits and invalid input.

The repository Cargo entry stopped during dependency preparation. The fallback uses the pinned Rust toolchain and the repository's WASI stack and memory settings. The ticket's guest probe exercises the editor and viewer via the browser component bridge.

A second check found that SQLite omitted the thermal fields of window, door and curtain-wall types. Both codec implementations now preserve the seven optional thermal values and admit U-value and G-value schedule fields. The language-neutral fixture exercises every new numeric column. SQLite independently counted 238 binary64 roles. The three SQLite and costing suites passed 21 tests after the change.

The SQLite DDL now belongs to a separate Rust schema package so the snapshot crate stays within the repository compiler's 256 KiB source limit. Dependency extraction for diagnostics now creates fresh filtered iterators for each pass over the retained maps.

The native borrowed SQLite census passed against the independent 4,036-row witness. It reported 288,188 value bytes, 128 tables and a maximum of 59 columns. Each one-short budget and pre-reconstruction cancellation was checked. The borrowed path allocated zero owned model bytes.

The macOS build warden measured the WASI snapshot compiler at 3,941 MiB against the existing 3,100 MiB unit limit. The 27 construction record definitions now compile in a separate first-party crate. The snapshot module continues to publish those exact types. The native snapshot binary passed all 39 tests before this extraction.

The mounted sheet export borrows the current rendered model revision. It writes one SVG or one PDF page per encoding turn, caches the ordered target list, and gives interrupted PDF state to the runtime retirement cursor. The mounted regression creates a sheet, renders the model and requests both downloads. The IFC producer uses one model family per turn. The CSV producer streams bounded chunks. These mounted regressions must still execute before the component is considered verified.
