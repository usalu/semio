Semantics as briefed. `create-*`: duplicate id (`mutation.duplicate-id`), unknown layer material (`mutation.target-missing` path `[<record>, layers, material]`), empty stack (`mutation.invariant` `[<record>, layers]`), non-positive or non-finite thickness (`[<record>, layers, thickness]`); materials: finite non-negative density, conductivity, specific heat (`[material, <field>]`) and colour channels in 0..1 (`[material, color]`). `delete-*`: `mutation.target-referenced` `[id]` for a material used by any wall, slab or roof type layer, column, beam, window or door type, curtain wall (panel or mullion) or railing; wall, slab and roof types by walls, slabs and roofs; inverse is the concrete `create-*` with the captured record. `set-*`: payload fields are `Option`s serialized sparsely (`skip_serializing_if`), `required` in the schema is only `mutation` and `id`; the diff is a `Patch` of exactly the provided fields (layer stack is one field and replaces the stack); a patch that changes nothing (empty or equal values) is `mutation.no-op`; the inverse is the same `set-*` with the base values of exactly the provided fields (built with `Patch::negate`). Every payload property carries `x-semio-ui` (reference / text / select / record / number / list, en + de labels). Every inverse emits one row.

## 3. Changes to shared tooling (both tiny, both needed)

1. Kit `outcome`: a rejected case matched the declared code only at `Error` or `Fatal`, but `mutation.no-op` is a `Warning` in `OutcomeCode::level`, so no declared no-op case (golden recipe section 1 welcomes them; other slices declare them too) could ever pass. Now `Severity::Warning | Error | Fatal`. Info (cascade) is still not a refusal.
2. Facet generator: array item `$ref`s (`Layer`) were missing from the generated `import type` list of `🟦️.ts`, and `optional repeated` is invalid proto. The import list now includes `items.$ref`; arrays never get `optional`. (Someone else had already added optional handling for TS, GraphQL and scalar proto fields.)
