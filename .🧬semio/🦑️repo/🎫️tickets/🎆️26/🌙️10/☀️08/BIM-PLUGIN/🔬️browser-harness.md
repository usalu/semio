# Browser Guest Harness Audit

The ticket harness originally instantiated the component on the page with `page.evaluate`, not in a physical worker, and silently discarded effects, UI patches, presence, and wake scheduling while declaring idle. It also did not check JSPI availability. It now runs its direct actor bridge in a module Web Worker, checks `WebAssembly.Suspending` and `WebAssembly.promising` in that worker, refuses any output needing OS routing rather than claiming it was settled, and requires no pending wake before idle. Lifecycle receipts are still acknowledged, and close must retire the captured lifetime.

This remains a direct bridge lifecycle smoke, not the OS shard worker or an application interaction test: it does not route effects or UI patches, execute a tool, prove quota enforcement, exercise worker lease/succession, or validate retained receipt accounting. Its empty quota bytes and finite grant come from the Draw guest contract, where the native smoke uses a default `QuotaSchema`; they do not prove descriptor-specific quota policy. The Vite/Playwright harness cannot currently be run because its generated guest bridge is absent. The production shard worker creates the actor through its own materialization/lease and routes replies; a passing direct-worker smoke should not be interpreted as OS application validation.
