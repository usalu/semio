Scope: read-only exploration for the BIM plugin (`model` artifact with plan, 3D, property panels, outliner, drawing tools). Reference implementations: the Drawing editor/viewer (2D, the template), the CAD plugin (multi-window 3D BIM-adjacent editor), the Lowpoly and Block plugins (3D windows). Repo root: `C:\git\semio`.

## 0. Summary (answers first)

- **Language.** Editors and viewers are Rust guest plugins. `DrawingPlayApp` implements the framework trait `ArtifactEditor`, and `DrawingViewer` implements `ArtifactViewer`. The drawing crate depends on `semio-framework-plugin` with `features = ["component-guest"]` (`D/📦️packages/🦀️rust/Cargo.toml`, line 44). That feature gates the `wasm32-wasip2` component path (`OS/🔌️plugin/🦀️.rs`, `cfg(all(feature = "component-guest", target_arch = "wasm32", target_env = "p2"))`), and the crate still builds and tests natively. TypeScript appears only as schema twins (`🟦️.ts`), `bun:test` cross-checks (with three.js, immer, ajv), and Storybook stories. The hosts are React (react-three-fiber/three.js, HTML canvas 2D) and a wgpu target (`FW/🖱️ui/🎯️targets/🧊️wgpu`).
- **Rendering.** Rust never draws. A command or query builds a declarative scene and wraps it with `scene_surface(id, SurfaceKind::…, &scene)`. `SurfaceKind::Canvas2d` gives a `Canvas2dScene` (2D, drawn by `📐️Canvas2dHost`). `SurfaceKind::World3d` gives a `World3dScene` (3D, drawn by `🌐️World3dHost`).
- **Commands → mutations.** A `DrawingCommand` enum (generated by `app_commands!`) dispatches to `handle(...) -> Emit<DrawingMutation, …>`. Each document change is one `DrawingMutation` that carries its own `inverse`, so undo is structural. Gestures run as retained, step-bounded `InteractiveJob`s.
- **Transient / presence / config.** Four persistence classes exist, and the framework maps them: document (persisted shared), config (persisted local, per window instance), presence (ephemeral shared, peer broadcast), transient (ephemeral local, per window instance). Each is a typed `DslRecord` + `ArtifactPack` + schema facet.
- **Terminology.** `semio_framework_ui_locale::app_labels!` declares a struct with `native_en/native_de/reuse_en/reuse_de` cells. The Rust compiler checks every field, and resolution happens via `resolve_labels::<T>(view_state)`.
- **3D.** The framework `FW/🧊️3d` is a geometry kernel (brep, half-edge mesh, collision, rigid, inertia). The 3D scene and viewport live in `FW/🖱️ui/🎬️scene/🎬️scenes` (`World3dScene`) and `FW/🖱️ui/🪟️viewport/🧊️3d` (projection/orbit schema). The CAD plugin is the best multi-window 3D reference (four `World3d` windows, one of them `aec.building`).
- **Progress/cancel.** `FW/🧵️job` (`InteractiveJob::step -> StepOutcome`, `is_cancelled()`, `should_yield()`), `FW/⏳️async` (`CancelToken`, `WorkerPool`, `Scope`), and plugin `OS/🔌️plugin/⏳️operation-progress` (`ArtifactOperationProgress`, `cancelTypedOperation`).

### 1.2 Commands and mutations (CQRS write side)

- Command enum: `DE/🦀️.rs` line ~265, `semio_framework_plugin::app_commands! { pub enum DrawingCommand for DrawingSnapshot, DrawingMutation, NoConfig, NoConfigMutation, ctx = DrawingSession { "addLayer" as "add-layer" => add_layer::AddLayer, … } }`. The comment says the row order is the binary variant ordinal (append-only).
- Action bridge: `args_bridge::command_from_action(action, args)` folds camelCase JSON into typed payloads (`DE/🦀️.rs` region `🌉️ActionBridge`).
- `ArtifactEditor::handle(command, doc, cfg, interaction, view_state, draft, engines) -> Result<Emit<DrawingMutation, NoConfigMutation, NoDraftMutation>, Fault>`. Dispatch is `command.dispatch(doc, cfg, &mut session)`.
- A typical command, `DE/🎮️commands/➕️add-layer/🦀️.rs`:

```rust
pub fn handle(payload: &AddLayer, doc: &ArtifactView<'_, DrawingSnapshot>, _cfg: &ConfigView<'_, NoConfig>, _session: &mut DrawingSession) -> Result<Emit<DrawingMutation, NoConfigMutation>, Fault> {
    let layer = build_layer(doc.snapshot, &payload.kind, doc.operation_optional())?;
    let id=crate::schema::layer_id(&layer).to_string();
    let mut emit=Emit::mutations(vec![crate::mutations::create_layer(None, Some(doc.snapshot.layers.len()), layer)]);
    emit.effects.push(crate::editor::drawing::commands::canvas_pointer_down::interaction_select_effect(&[id],"replace"));
    Ok(emit)
}
```

So a command returns (a) document mutations and (b) effects (for example, select the new layer). Layer identity is derived deterministically from document id, kind, operation id, generation and base revision (`identify_created_layer`).

- Document mutation type: `D/🧬️schema/🧬️mutations/🦀️.rs`, `pub enum DrawingMutation { SetLayerVisible(..), CreateLayer(..), DragLayers(..), … }` with `#[derive(…, dsl::Mutations)] #[mutations(snapshot = DrawingSnapshot, diff = crate::diff::DrawingDiff, schema = "drawing.drawing")]`. Each leaf is a handcrafted triad with its own descriptor. The derive generates `protocol::Mutation` and `SemanticMutation`.
- Store write: `DE/🦀️.rs` region `📬️StorePreparation`. The preparation computes the inverse and the post-state, then hands the edit to the authority:

```rust
let inverse = mutation.inverse(base.get()).map_err(semio_framework_value::ValueError::into_message)?;
let post = ::protocol::MutationDiff::apply(mutation.diff(base.get()).diff(), base.get()).map_err(|error| error.to_string())?;
let authority = self.authority.as_ref().ok_or_else(|| "drawing-artifact-authority-missing".to_string())?;
let edit = authority.next_edit(mutation, inverse);
let prepared = authority.prepare_one_item(edit, std::sync::Arc::new(post))?;
```

This is event-sourced history with inverses (undo and redo come from the stored inverse). It is not CRUD. Only the `Document` lane is accepted.

- Viewer (`DV/🦀️.rs`): `DrawingViewer` implements `ArtifactViewer` only. `handle` always returns `Err(Fault::from("drawing-viewer-retained-route-required"))`. Its only command is `setCamera` (`DrawingViewCommand::SetCamera { camera: String }`), run as a retained job. The viewer type therefore cannot emit document mutations.

### 1.3 Gesture commands (pointer, drag, draft): retained interactive jobs

Pointer and gesture commands (`canvasPointerDown`, `canvasPointerMove`, `canvasPointerUp`, `canvasEscape`, `engagementInput`, and others) are NOT run inline. `handle` rejects them with `drawing.gesture.retained-route`. They go through `DrawingGestureOperationJobFactory` (`DE/🦀️.rs` region `🧵️GestureOperationJobs`, ~line 895) as an `InteractiveJob`. Each step yields `Ok(Some((emit, transient)))` and completes with `EphemeralEmit { window_transient: vec![mutation], .. }`. The canvas tool itself is a statechart (`🔄️machine`) whose yields are `ToolTransaction`s of relative leaves (`drag-layers`, `rotate-layers`, `scale-layers`, `drag-path-points`, `create-layer`), per the module doc of `…/🪆️1-any/🎮️commands/🖱️canvas-pointer-down/🦀️.rs`.

Bounded commands (`DrawingBoundedCommandJobFactory`, `DrawingWindowCommandWork`) use the framework `ArtifactCommandWork` with a `drawing_bounded_extent` for work-item budgeting.

### 1.4 Rendering (read side)

`DE/🦀️.rs` `render_drawing_body(body_key, doc, config, preview, selection, point_selection, view_state)` dispatches on body key:

```rust
DRAWING_PLAY_BODY_COMPOSITE => geometry_session::with_visual(doc.render_operation(), |plan,revision,fresh| {
    let idle = DrawingGesturePreview::default();
    canvas_window::render(plan, revision, document, config, if fresh {preview} else {&idle}, active_utility, …) }),
DRAWING_PLAY_BODY_LAYERS => layers_panel::render(document, labels, &windows),
DRAWING_PLAY_BODY_CATALOGUE => catalogue_panel::render(document, labels, &windows),
DRAWING_PLAY_BODY_PROPERTIES => properties_panel::render(document, &[], labels, &windows),
```

The canvas window (`DE/🎭️modes/✏️edit/🪟️windows/🖼️canvas/🦀️.rs`, `render(...)`) builds `DslValue` records (`overlay_record(id, transform, segments, fill, stroke, width)`): artboard frame and dimension label, selection bounds, transform handles, node handles (edit-nodes utility), marquee, lasso, shape/draft previews. It ends with:

```rust
scene_surface(
    DRAWING_PLAY_SURFACE_ID,
    semio_framework_ui_contract::SurfaceKind::Canvas2d,
    &Canvas2dScene { framing: …, camera_x: config.viewport.x, camera_y: config.viewport.y, zoom: config.viewport.zoom, layers_json: … }
)
```

The Rust side projects geometry itself (`geometry_session` → `schema::scene_paint::scene` → `scene_view::nodes`). The host only paints. The geometry preparation is a `BoundedJob` (`semio_framework_plugin::reactor::jobs::{BoundedJob, JobBudget, JobStep}`) with hard limits (`max_nodes: 1024`, `max_segments: 65536`, `max_work: 1_000_000_000`). The `step` honours cancellation and deadlines (`deadline_ms.min(8)`).

Panels are virtualised trees. The layers panel uses `PanelTreeBuilder`, `TreeWindows::for_body(view_state, body_key)` and `tree_window_indexed_item`. Every row shares one `interactionSelect` binding for the `strokes` domain, so rows never carry per-row actions. Properties come from a `Field { key, label, value, kind: InputKind::{Text,Number,Color,LongText}, toggle, min, max }` table.

Window engagement (the status bar and single-line input) is declared by the window and computed from document counts and transient text (`DE/🧮️status/🦀️.rs`):

```rust
pub(crate) fn text(layers:usize,selected:usize,labels:&DrawingPlayLabels)->String {
    let layer=if layers==1 {labels.layer_count_one} else {labels.layer_count_many};
    format!("{} · {}",layer.as_str().replace("{count}",&layers.to_string()),labels.selection_count.as_str()…)

```

### 1.6 Terminology and i18n

`DE/🗣️terminology/🦀️.rs`:

```rust
semio_framework_ui_locale::app_labels! {
    pub struct DrawingPlayLabels {
        layer_count_one: native_en "{count} layer", native_de "{count} Ebene", reuse_en "{count} layer", reuse_de "{count} Ebene";
        layer_count_many: native_en "{count} layers", native_de "{count} Ebenen", reuse_en "{count} layers", reuse_de "{count} Ebenen";
        …
```

- One field per label. The macro compile-checks every locale cell, so a missing German string fails the build.
- Manifest labels use `LocalizedLabel::native(en, de)` inline (the manifest has no separate file).
- Runtime text uses `Label::data(...)` (genuine user data only) or named placeholder fill (`fill(&[("count", …)])`), never `format!` in labels.
- Locales come from the generated `FW/🖱️ui/🎚️axes/🤖️generated/🦀️.rs`: `pub enum Locale { #[default] En, De }` and `pub enum Terminology { #[default] Native, Reuse }`. Terminology is "native" (domain phrasing) or "reuse" (generic).
- Inconsistency to decide on: the AGENTS rule says "no default language", but both enums derive `Default` with `En` / `Native`. The TS mirror is in `FW/🖱️ui/🛂️manifest/🤖️generated/…`.

## 2. Drawing viewer (`DV`)

- `DV/🦀️.rs`: `DrawingViewer` implements `ArtifactViewer` (not `ArtifactEditor`). Its module doc says it "MUST NOT import anything from the sibling editor module". Adapter: `ViewerApp<DrawingViewer>`.
- Manifest: `Viewer::builder(DRAWING_DIALECT).…mode_def(view::definition()).default_mode_id("view").window_kind_def(canvas::definition()).default_layout(view::layout()).action_audience("setCamera", CapabilityAudience::Chrome).build_definition()`.
- Mode `DV/🎭️modes/👁️view`: one mode `view` with one full-pane Canvas window (`layout()` is a single `WindowLayoutStackNode`). Viewers need at least one real window per mode (contract §1).
- Window `DV/🎭️modes/👁️view/🪟️windows/🖼️canvas/🦀️.rs`: `WINDOW_KIND_ID = "drawing-view-canvas"`, `render_with_camera(document, config)` reuses the same `scene_surface(…, SurfaceKind::Canvas2d, &Canvas2dScene{…})`. Its own window config (`DrawingViewerCanvasWindowConfig`) and options exist. Presence is `NoPresence`.
- Viewers never emit mutations. Camera changes come back as `setCamera` through a retained job (`DrawingViewCommandJobFactory`) that writes only window config.

## 5. How the OS hosts an artifact editor or viewer

Chain, from the code:

1. Subset declaration: `D/🦀️.rs` `subset()` → `editor_surface::<editor::DrawingPlayApp, A>(editor::create_drawing_app())` and `viewer_surface::<viewer::DrawingViewer, A>(viewer::create_drawing_viewer())`. `SubsetDeclaration` also lists `examples`, `io`, `schema` and `inference_descriptors`.
2. Manifest build: `Editor::builder(dialect)` / `Viewer::builder(dialect)` (`FW/🛍️products/💻️os/🔨️modules/🔌️plugin/🦀️.rs` ~line 41222–41306) → `.build_definition()` → `AppDefinition`. Declared pieces: modes, windows, panels, actions, utilities, interactions, keybindings, default layout, `io`.
3. Runtime wrap: `editor_surface` builds `VcsArtifactApp::<EditorApp<E>, E::Members>::with_registry_on_bus(EditorApp::<E>::default(), AppActionRegistry::from_definition(def), …)`. `ViewerApp<V>` is the viewer equivalent. The type is `PluginApp`, which the shell reaches through the plugin runtime.
4. Shell: `OS/📺️renderer/🧑‍🎨engine/🧱️elements/🐚️Shell/🟦️.tsx` (window chrome, ribbon, palette, panels, `DocumentApp` in comments), `🔌️PluginRuntime/🟦️.tsx`, and `🛠️ShellHelpers`. The TypeScript comments refer to "`DocumentApp`". The Rust type is `VcsArtifactApp`/`VcsDocumentApp` (the Shell comment names `VcsDocumentApp::dispatch_action`; the struct itself was not found under that exact name).
5. Document I/O: the artifact is a pack (`encode_pack`), an envelope with an identity (`s.draw.drawing`), and a DSL text form. Export ports: `io()` with `drawing_io()`, `export_media("vector:out")` → PDF/SVG, `artifact:out` → pack.
6. Gateway / agent: each action has an `ActionDefinition` with `use_when`, arguments (`ActionArgDef::select`, `text_list`, `json_text`, `slider`) and an audience. Those become the MCP/agent catalogue.

## 7. Progress and cancellation

- `FW/🧵️job/🦀️.rs` (3721 lines), module doc: "`InteractiveJob` is a SYNCHRONOUS, explicitly-resumable `step(&mut StepContext) -> StepOutcome`". Ceiling per step: `INTERACTIVE_STEP_CEILING_US` = 8 ms.

```rust
pub trait InteractiveJob: JobThreadTransfer {
    fn step(&mut self, context: &mut StepContext<'_>) -> StepOutcome;
    fn begin_close(&mut self); fn close_step(…) -> InteractiveJobCloseStep;
}
pub enum StepOutcome { Yield, PreviewReady(RetainedJobPayload), CheckpointReady(Checkpoint), Complete(CommitCandidate), Cancelled, Fault(JobFault) }
```

- `StepContext` offers `is_cancelled()`, `should_yield()`, `fuel_remaining()`, `consume_fuel(n)`, `set_stage(label)` and `cancel_token()`. Example, from `DE/🦀️.rs`:

```rust
if context.is_cancelled() { return semio_framework_job::StepOutcome::Cancelled; }
if context.should_yield() || context.fuel_remaining() == 0 { return semio_framework_job::StepOutcome::Yield; }
```

- Operation registry: `FixedOperationRegistry<T, CAPACITY>` with `cancel`, `cancel_stale_step`, `begin_close_step`, `close_step` (bounded close). `FixedOperationOwner` is the trait for owners. Drawing's gesture owner (`DrawingGestureOperationOwner`) implements it. Its geometry preparation uses `BoundedJob` instead.
- Bounded (reactor) jobs: `semio_framework_plugin::reactor::jobs::{BoundedJob, BoundedJobFactory, JobBudget, JobStep}`. The geometry preparation (`DE/🧵️geometry/🦀️.rs`) is an example, with `JobBudget { fuel, deadline_ms }`.
- User-visible status: `OS/🔌️plugin/⏳️operation-progress/🦀️.rs`:

```rust
pub const CANCEL_TYPED_OPERATION_ACTION_ID: &str = "cancelTypedOperation";
pub struct ArtifactOperationProgress { pub operation_id: u64, pub generation: u64, pub label: LocalizedLabel, pub completed_units: u64, pub cancelling: bool }
```

- Async substrate: `FW/⏳️async` (`WorkerPool` = one process-wide work-stealing pool, `CancelToken`, `Scope`, `HostAsyncRuntime`). Doc: "No `tokio` in this crate." Use `async` only for real suspension.
- Refusals are localized: `DE/🦀️.rs` `drawing_fault_notices()` (nine `drawing.gesture.*` codes, each with en/de).

## 8. Multi-user, offline and event model (what applies to the BIM plugin)

- Event model: commands → `Emit` (document mutations with inverses, effects, ephemeral emits). Read model: `render`, `window_engagements`, `interaction_topology`, `pending_effects`. Writes go through `store::ArtifactStoreOneItemPreparation` with the lane check `HistoryLane::Document` only.
- Presence: `DrawingPresence` is the shared-live facet. Peers get selection and hover from the framework's `PresencePeer.interaction` broadcast, not from the facet. The React host overlays peers (`CanvasPresenceOverlayV1`).
- Local-first and short disconnects: gesture state is ephemeral (`EphemeralEmit`), so a dropped connection loses only transient state. Document commits are one-item prepared edits. I did not trace the sync/outbox code (`OS/🏪️store/🔄️sync`) for this report.

## 10. Implications for the BIM `model` artifact (short)

- Copy the Drawing shape: subset `any`, with `schema` (facets in five languages), `io`, `editor` (one mode `edit`), `viewer` (one mode `view`), `examples`. Use `Editor::builder` / `Viewer::builder`.
- Plan views per storey: `Canvas2d` windows with a window config holding viewport and storey selection (persisted local, per instance). Drawing's `DrawingCanvasWindowConfig` is the template.
- 3D view: `World3d` window, following the CAD building window (`World3dScene` with camera JSON, meshes, instances, selection, sun) and the Block/Lowpoly pattern (`domain_id` and `domain_granularity_id` on the scene). Camera and projection presets from `FW/🖱️ui/🪟️viewport/🧊️3d`.
- Outliner (model → site → building → storey → elements): `PanelTreeBuilder` with one interaction domain (`topology`), virtualised with `TreeWindows`. Property inspector: the `Field` table pattern in `properties` plus `InputKind`.
- Presence: a `*Presence` facet (shared-live, camera and engagement) plus framework interaction broadcast for selection.
- Expensive work (IFC import, geometry preparation, clash checks): `InteractiveJob` with `StepOutcome::Yield` and `is_cancelled()`, bounded by `JobBudget`, reported with `ArtifactOperationProgress` and cancelled with `cancelTypedOperation`.
- i18n: `app_labels!` struct with en/de cells per label, never inline strings in node code.
