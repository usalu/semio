## Current Exact Blockers

Both shared entry points in publication `🎛️owner/🟦️.ts` (`publishNativeImagePublicationV1` line79 and retained sibling line93 at this checkpoint) explicitly refuse Windows without actual nonzero `O_NOFOLLOW`. That refusal is currently necessary. Replacing it with a weaker Node open flag or deleting it alone would expose unqualified host record/root observation. No caller option may bypass it.

The current `capturePublicationPayload` line73 always supplies a POSIX witness binding. The witness already has a mandatory closed platform/context discriminator and explicitly compares it with actual runtime; on Windows that call refuses even if the earlier nofollow guard were satisfied. This is a concrete missing connection, not missing traversal implementation.

Shared scope acceptance/require/checkBacking/readRecord/candidate checks still use Node lstat/open/stat tuples. Fixed `observeNativeFixedPublicationV1` also qualifies backing/footer/root through those generic paths. Windows current metadata mutation children exist, but native mutation does not make the surrounding Node reads a physical no-reparse/ACL/128-bit identity proof. POSIX `mode` cannot be used as a Windows permission proof. Underlying-root observations/attach guards and final ordinary receipt readers must also share the authentic Windows identity contract; connecting only the payload witness is incomplete.
