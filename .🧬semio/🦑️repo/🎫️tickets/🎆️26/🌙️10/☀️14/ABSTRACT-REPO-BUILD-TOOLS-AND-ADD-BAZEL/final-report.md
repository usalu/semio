## Developer Interface

```text
bun repo run <project>:<task>[:<configuration>]
bun repo --tool=bazel run <project>:<task>[:<configuration>]
bun repo tools setup all
bun repo graph
bun repo show projects
```

The framework owns selection, run-many, affected tasks, execution, project/task inspection, watch, reset, portable flags, argument boundaries, progress and cancellation. Public packages, dashboard, agent/MCP instructions, setup, CI, devcontainer, native bootstrap, application orchestration and English/German editor controls route through this neutral interface. Nx implementation details remain inside private backend bridges. `SEMIO_BUILD_TOOL` carries explicit selection through nested orchestration; Nx remains the configured default.

Schema-owned project declarations define graph, inputs, configuration, resource grants and action recipes. Shared inference, observation, mode policy, catalog and outputs have framework ownership. Private adapters translate the same graph to Nx or Bazel. Configurations override options while target command form, dependencies, inputs, outputs, cache policy and Native ownership remain target-owned. Arguments are literal arrays with explicit separator preservation; the prior scalar defaults were handcrafted to arrays.

Bazel uses pinned8.4.2 distributions and checksums for six platform/architecture combinations. Setup seeds the shared fixed-module cache and lock; task namespaces disable downloads and uncached offline setup refuses before network access. The backend implements dependency closure, configuration, argv, source/lock/environment hashing, action products/restoration, nested tasks, uncached actions, nonparallel operations, services, cancellation and managed reset. Runtime qualification remains separate below.

Canonical graph publication is atomic and bound to observed Source and immutable digest pins. Execution requires an authenticated graph for the exact selected owner closure; complete inspection/exhaustive planning uses a separate complete graph. Native parent/child storage, accepted operations, output publication and terminal cleanup retain genuine Original/phase custody through drainage. No quota/capture/deadline widening or ledger reset is used to admit failing qualification.
