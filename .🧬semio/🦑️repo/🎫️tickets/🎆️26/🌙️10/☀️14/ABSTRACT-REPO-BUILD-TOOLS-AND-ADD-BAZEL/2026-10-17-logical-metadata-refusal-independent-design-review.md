# Logical Metadata Refusal Diagnostic: Independent Design Review

The failure-only proposal is appropriate: project only already-computed primitive current/root/path/depth/entry counters at the unchanged compound guard, with exact existing error text/order and no new IO/observer calls/work debit or limit change. First-failing reason must follow path, depth, entries precedence exactly. It cannot diagnose historical52615 retroactively; only a future actual captured cause can identify that branch.

The path field must be explicitly a truncated DATA prefix, never a materializable path or target authority. Measure UTF16 units independently from UTF8 byte size; a256-unit prefix may split a surrogate pair, so either define raw UTF16 prefix JSON escaping precisely or cut at a complete codepoint while preserving original measured units/truncation truth. A separate fixed serialized byte bound must accommodate maximal escaping rather than assuming256 characters equals256 bytes. POSIX and win32 relative path separators/normalization need deterministic formatting; lexical operations require no filesystem probe.

Use only own primitive closed fields, early Proxy rejection and descriptor capture in the reporter, with no inherited/cause accessor/JSON hooks. Sink failure is best effort and never replaces undefined/frozen/cancel or original Error identity. Portable exact-boundary/multiple-reason/Unicode fixtures should compare actual producer projection with Ajv, independent Python UTF16 and SQLite predicate results. Actual walker/refusal IO-count/cancellation regression and scoped final hold remain required. No implementation, Native attempt or limit/authority relaxation is approved by this design-only review; no material objection was found with these conditions.
