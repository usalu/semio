## Verified Primary API Basis

Microsoft documents [Directory.CreateDirectory(String, DirectorySecurity)](https://learn.microsoft.com/en-us/dotnet/api/system.io.directory.createdirectory?view=netframework-4.8.1) as applying Windows security and explicitly recommends this overload to avoid access before security is applied. This suits the captured system Windows PowerShell/.NET Framework route; existing-directory return behavior means retained slot must still be independently authenticated, never adopted solely because CreateDirectory returned.

[DirectorySecurity](https://learn.microsoft.com/en-us/dotnet/api/system.security.accesscontrol.directorysecurity?view=netframework-4.8.1) is the first-party Windows DACL model. [Get-Acl](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/get-acl?view=powershell-5.1) reads security descriptors; request access/owner only, no SACL privilege grant. [File.Replace](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace?view=netframework-4.8.1) documents same-volume requirements and a null backup path. These are design primitives, not a tested CAS/atomicity guarantee against same-user outside actors. Exact handle pinning/share/delete order and ReplaceFile attribute/security preservation must be reviewed before implementation; don't claim rename while retaining incompatible no-delete-sharing file handles.
