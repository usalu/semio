# Source Owner Exports Profile Review

The current execution observer captures package-directory identity/version/semantic manifest and compares canonical provider instances. Its inner exportsProfile nevertheless rejects every unknown condition recursively, including inactive semio-source in the authored example. A bounded pure manifest-profile codec is a sound narrow replacement. It must not claim that selected entry files physically exist, load, or export equivalent APIs. No runtime files were edited for this review.

## Primary Semantics

Node resolves conditional keys in authored insertion order. import and require are mutually exclusive; default always matches. A nested condition with no mapping continues at the parent; null blocks an export. Unknown custom conditions are ignored unless enabled. Relative export targets have package confinement rules, and a present exports field encapsulates subpaths. These semantics do not permit sorting condition keys or silently falling back to main after an unmatched exports branch. [Node package documentation](https://nodejs.org/api/packages.html#conditional-exports).

Bun also uses authored first matching condition order. Its documented built-ins include bun, node-addons, node, and the request-specific import/require plus default; --conditions adds custom activation. Absent exports has separate main/module/index fallback behavior. Therefore a profile containing only bun/node/import/require/default must explicitly exclude addon/custom/module-sync behavior or refuse an active unsupported branch; those keys cannot universally be called inactive. [Bun module resolution](https://bun.sh/docs/runtime/module-resolution).

TypeScript follows exports condition selection but additionally matches types/default, versioned types conditions, and configured customConditions. Its eventual file lookup also performs extension substitution. A types profile must name its compiler/moduleResolution/request/custom-condition policy; it is not merely runtime resolution with a globally preferred types key. [TypeScript module reference](https://www.typescriptlang.org/docs/handbook/modules/reference.html#packagejson-exports).

## Minimal Closed Seam

Keep separate named condition sets, e.g. Bun-import, Bun-require, Node-import, Node-require, plus explicit type profiles. A union may enumerate supported condition spellings for validation, but must not be treated as a single real loader with both import and require enabled. Include runtime version/condition policy in the existing fingerprint. semio-source is inactive only when actual launch/compiler policy does not enable it.

Walk own parsed JSON keys in original order. Distinguish a top-level subpath map from condition sugar; refuse mixed maps, numeric condition keys and malformed subpath syntax. Select exact dot for bare-package requests. Preserve distinct statuses target, blocked-null, unmatched and exports-absent. A nested unmatched branch may continue to the parent's later default; null must not. Only exports-absent allows a separately supported legacy-field profile. A declared package with exports but no dot can remain observed package-identity DATA, but must never become a proved runnable bare entry.

Inactive unknown branches need not have their target semantics validated or cause blanket rejection. Bound their structural cost using the already-bounded manifest and codec depth/node counters without executing hooks or interpreting foreign conditions. Active selected targets need closed relative URL/path checks: no traversal, node_modules segments, encoded separator/traversal aliases, backslash, NUL, unsupported query/fragment or wildcard interpretation. Unselected target branches do not grant paths or reads.

Arrays and patterns are real resolver features, not invalid packages. The smallest sound initial codec can explicitly refuse an ACTIVE array/pattern/subpath request outside its closed profile. It must report unsupported rather than flattening arrays to first string or expanding wildcards without the real resolver rules. This may still block complete ALL; it is a qualification frontier, not a reason to silently admit all manifests. Unsupported inactive branches can be ignored semantically.

Required countercases: authored semio-source/types/import example; reordered default; distinct import versus require; nested unmatched then parent fallback; null barrier; unknown inactive malformed target; custom condition activated; exports absent versus present with no dot; mixed/numeric keys; unsafe encoded target; active arrays/patterns; types branch ordering and version/custom unsupported. Validate pure outputs with independent Node/Bun resolution fixtures and TypeScript resolver API where applicable. Use only own Generated fixture packages; no production imports or Native effects. Provider-directory equality remains narrower than entrypoint physical qualification.

## Root Null and Array Correction From Pinned Node Source

Pinned Node24.15.0 code confirms Root actual Bun observation: packageResolve calls packageExportsResolve only when packageConfig.exports != null; CommonJS resolveExports has the same pkg.exports != null guard. Thus top-level exports:null is absent-profile behavior and can enter ordinary main fallback; this corrects any overbroad earlier statement that every present exports value encapsulates. A codec returning absent-profile DATA need not implement or claim that fallback itself. [Pinned ESM resolver](https://github.com/nodejs/node/blob/v24.15.0/lib/internal/modules/esm/resolve.js#L727-L736), [pinned CJS resolver](https://github.com/nodejs/node/blob/v24.15.0/lib/internal/modules/cjs/loader.js#L634-L654).

Inside resolvePackageTarget, null returns null. An object-selected null terminates that condition selection, but an array specifically continues past null and invalid-package-target entries, retaining the last null/error for final exhaustion. It returns the first successful resolved target; an unmatched undefined branch also continues. Missing physical files are not array fallback candidates: target resolution selects a URL before later file finalization. Thus nested null is not a universal array stop. A new array-support codec must match these distinctions with independent resolver cases, including [null, valid], [invalid-target, valid], [missing-file-valid-target, existing-file] and final null/error ordering. [Pinned target algorithm](https://github.com/nodejs/node/blob/v24.15.0/lib/internal/modules/esm/resolve.js#L458-L509).
