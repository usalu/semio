## Native API Evidence

- [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew): OPEN_EXISTING, non-inherited handles, OPEN_REPARSE_POINT for final components and BACKUP_SEMANTICS for directories. ACL checks still apply without backup privileges. Read sharing alone refuses existing/subsequent incompatible write/delete sharing; it does not promise an atomic whole-tree snapshot.
- [GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex), [FileIdInfo](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info), [FileAttributeTagInfo](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_attribute_tag_info): full volume/file identity, attributes/reparse, StandardInfo EOF/link/delete/type facts. Native identity is not a synthesized Node permission mode.
- [FILE_STREAM_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_stream_info): bounded linked records with 8-byte offsets, stream sizes and UTF16 byte lengths. Present regular files admit exactly unnamed ::$DATA. Named streams cannot be silently omitted.
- [GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew): request normalized volume-GUID paths with a bounded terminated UTF16 result; compare root/relative containment to retained actual mapping and named handles.
- [NtQueryDirectoryFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntquerydirectoryfile): directly returns NTSTATUS and exact initialized buffer length in IO_STATUS_BLOCK. NULL search means all entries. STATUS_NO_MORE_FILES is the terminal status; STATUS_SUCCESS with zero information can mean insufficient remaining buffer, so it is not EOF. Overflow/truncation refuses. Microsoft explicitly names NtQueryDirectoryFile for user-mode calls.
- [NtReadFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntreadfile): explicit byte offset and direct NTSTATUS/IO_STATUS_BLOCK avoid a second last-error call. The user-mode Nt entry is documented. An asynchronous handle requires one operation at a time and retained buffers until completion.
- [GetLastError](https://learn.microsoft.com/en-us/windows/win32/api/errhandlingapi/nf-errhandlingapi-getlasterror) is thread-local and must be captured immediately; pinned local ffi types expose no error-preservation setting. Therefore directory EOF must not be guessed from generic false or a possibly clobbered later error read.
- [CancelIoEx](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex) requests cancellation and does not prove completion. [GetOverlappedResult](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-getoverlappedresult) distinguishes pending/completed work. Buffers/events/handles remain owned until terminal evidence or explicit uncertainty quarantine.
