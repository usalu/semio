# Bounded Directory Path Handoff

The base7 checkpoint is held independently. Root released an additive path feature after this hold. No Native or protected cache operation is authorized for an agent.

The new `ArtifactRelativePathEntryV1` contains `name` and `identity: ArtifactRelativeEntryV1`. `withDirectoryPath(path, body)` accepts one through64 steps and at most16KiB of aggregate encoded names. Root itself already has direct methods, so an empty path is refused. Each identity must be the exact immutable entry object issued inside this one root-family callback. A copied/serialized/previous-command identity remains DATA and cannot provide the private Windows128-bit ID. The fixed administrative owner must freshly capture current entries and compare its command DATA separately; this API grants no Native authority.

Each issued directory-entry proof also retains the exact actual parent facts observed when it was issued. The first proof must belong to the current receiving frame. Subsequent proof-parent facts must equal the preceding issued directory facts, including the private Windows identity/security/streams record. Closed intermediate observation frames do not confer liveness or reopen themselves; their exact immutable proof DATA is used only to compare a fresh actual parent-relative open beneath the still-live receiving root. New root calls have disjoint private proof registries.

A private bounded handoff owner reserves shared custody before each actual open, records the returned handle before the next checkpoint, verifies both real parent and real child, then closes the previous intermediate handle before advancing. The original receiver stays held. At most current+next intermediate owners coexist, with no increase to the existing32 registry cap. The final existing directory-body implementation receives only the last real handle and drains all its accepted descendants before that handle closes. Open/verification/body failures close every provably owned handle exactly once; uncertain acquisitions and closes retain their existing registry custody and cannot yield a success. Arbitrary primary values and distinct close failures are retained.

The schema/corpus will precede the method. Tests will include depth33 actual own Generated POSIX traversal within256-character absolute paths, depth64 exact Windows owner Source model traversal, depth65/name-budget refusal, copied/foreign/lineage proofs, private ID substitution, accepted unawaited path descendants, mid-handoff closure failure and body-plus-close failure. Ajv and independent SQLite transition/count oracles will qualify the neutral vectors. Actual NTFS and Linux runtime remain unqualified; the unchanged ordinary-root ancestry constructor can still refuse shared-registry exhaustion independently of the new path handoff.

Owned edits: existing filesystem descriptor module (additive shared private handoff+POSIX/Windows methods), its schema (additive path definitions), existing explicit TypeScript descriptor facade (type export only), existing Core cache test suffix, and existing ticket stdio Source helper only if required by the established two-process pattern. Root base APIs/producer behavior remain semantically unchanged. No external runtime library or additional script is introduced.
