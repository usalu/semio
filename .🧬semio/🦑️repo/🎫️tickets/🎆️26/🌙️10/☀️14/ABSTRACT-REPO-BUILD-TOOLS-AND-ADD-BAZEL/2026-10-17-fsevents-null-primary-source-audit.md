# FSEvents NULL Primary Source Audit

Apple explicitly permits FSEventsCopyUUIDForDevice to return NULL when no stream UUID is available, giving read-only devices as an example. It means historical events are unavailable; a future event stream must use SinceNow. It does not prove a writable volume's service directory absent, corruption, an invalid dev_t, or a particular timing cause. [Apple API documentation](https://developer.apple.com/documentation/coreservices/1444453-fseventscopyuuidfordevice?changes=la__2_6).

The local primary SDK agrees: `/Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk/System/Library/Frameworks/CoreServices.framework/Frameworks/FSEvents.framework/Headers/FSEvents.h`, lines976–1009, declares nullable CFUUIDRef, the no-history meaning and Copy ownership. Its overview lines162–167 identifies this UUID as the per-volume FSEvents database identity, not generic volume identity. [Apple programming guide](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html) explains device IDs can change and persistent stream association relies on the UUID.

Current first-party observeNativeVolumeEventServiceV1 already returns null for an absent .fseventsd directory, but when that directory exists it requires the actual system UUID and exact same-device/no-follow UUID file association, reads the bounded file through a tracked descriptor, repeats all metadata/parent facts and calls the API again. The actual reported NULL is therefore unavailable authentication at that boundary, not authenticated service absence. No protected observations were performed here.

No cited primary contract guarantees that opening/starting a SinceNow stream initializes the database or yields a UUID. Doing so is an active service operation with callback/stop/invalidate/release lifetime, potentially altering service state; it is not a zero-touch read repair. Writing/removing .fseventsd, manufacturing its UUID or using generic volume UUID would destroy the current association proof. A short retry/delay is likewise not a documented guarantee or authority.

A clean observation contract may explicitly distinguish absent service, authenticated service and UUID-unavailable service DATA, with the existing publication witness refusing the unavailable branch until a genuinely supported qualification rule exists. If the goal requires a zero-touch producer to establish history, it needs a separately authored first-party service-initialization purpose, bounded owned lifecycle and Generated physical proof; primary docs alone do not supply that protocol. Preserve all current equality and unknown-content refusal. Root's Products31215 failure remains a failed operation; no service identity or custody closure is inferred.

Research used the local SDK and official Apple pages only. No Native calls, stream creation, protected filesystem read or production edit occurred.
