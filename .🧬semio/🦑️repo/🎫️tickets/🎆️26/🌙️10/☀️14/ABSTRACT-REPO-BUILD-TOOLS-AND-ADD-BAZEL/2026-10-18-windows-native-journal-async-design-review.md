# Windows Native Journal Async Design Review

Explicit async durable append/checkpoint is the clean internal API direction. Synchronous creator callbacks currently rely on commit-before-return; Windows work must not be hidden behind deferred promises or batched until callback return. Handcraft every first-party call site to await successful durable event before minting reservation/child authority or physical effects, including aliases/wrappers. A drained but unawaited append must not retroactively qualify an already-issued child. Existing event bytes/replay/row identity and POSIX ordering remain invariant.

Each actual transaction retains real canonical journal EX, exact image borrower/frame authority and a single pending mutation owner. Readonly snapshot/token cannot become a writer. Reserve synchronously, record exact failure including undefined, prevent concurrent mutation, drain before SQL release, and advance in-memory state/text only after durable commit. Readonly observer account is not an adequate write-work budget; derive one closed cumulative transaction work envelope from authentic journal bytes and one-byte partial IO including all readback/flush/final fences. No public provider, caller budget or account reset.

Checkpoint is the remaining material gate. Nt rename target is not expected-file-ID CAS, and Generic Windows conditional FILE is unqualified/refusing. A two-step retained-old/no-replace design has a temporary absent-name interval. Every journal consumer, including bootstrap, replay, read-only projections and accepted cleanup, must hold the same journal SH/EX semantics or it can interpret that interval as missing/new/empty journal. Prove the complete reader inventory before admitting this protocol; image SH alone does not supply journal-name serialization.

Define exact schema-owned staging/retained-old/intent roles, durable order and crash recovery before implementation. Pin named/held full128/size/rawhash and parent lineage, retain any foreign displaced entry, and never clean unknown files because their prefix resembles staging. Partial append, flush/close uncertainty, staged-new plus retained-old, missing canonical plus durable intent, and published-new plus stale recovery metadata require explicit no-success/charge-retained/current-owner recovery behavior. No weak ReplaceIfExists or legacy adoption may be called an atomic conditional swap.

Required Source tests go beyond a successful native syscall port: all durable-event-before-creator callsites, same POSIX event/IO order, one-byte/zero writes, concurrent unawaited mutation, late foreign target, reader during checkpoint gap, crash at each barrier, exact arbitrary primary and physical cleanup failure, inherited-control/cumulative-work and accepted drain. Real NTFS remains a separate frontier even after Source/Root0/SQLite/Generated FD tests. No conceptual objection to async conversion; checkpoint reader/recovery contract must be closed before code/dispatch. No Native effects or production edits performed here.
