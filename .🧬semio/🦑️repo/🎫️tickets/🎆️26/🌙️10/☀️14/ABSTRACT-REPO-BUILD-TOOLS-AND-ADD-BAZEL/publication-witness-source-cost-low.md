## Repeated Directory Scans

Generic witness/🟦.ts35 reopens and scans the entire directory to select the next64 lexicographic names, then closes before descent. A directory with N children requires ceil(N/64)+1 complete scans (the last proves exhaustion), approximately `(N+1)*(ceil(N/64)+1)` directory.read calls per census. Every scan iteration, including skipped names, is correctly charged. Two full censuses double this work. Bounded memory and complete canonical order are preserved; no all-name array is acceptable.

## Multiplied Synchronous Custody Checks

Each async read step invokes check before and after. Each check invokes the private publisher observer. Current capturePublicationPayload observer first calls requireNativeImagePublicationV1, then checkBacking, which calls requireNativeImagePublicationV1 again, then lstats mounted root. Each require loops every retained outside ancestor and additionally lstats the asset directory again even though it is already the first retained ancestor. Thus each observer performs two complete synchronous parent-chain checks plus duplicated folder CAS, backing and root stats. Directory paging amplifies these repeated physical syscalls substantially. Actual issuer, phase, EX and mapping checks must remain real.

Smallest cohesive optimization: make the private checked-backing routine return the already authenticated scope, so observer uses one complete require/checkBacking result and one mounted-root stat. Within that single synchronous require, reuse the already checked asset-directory row for its CAS rather than re-lstatting the same path without an intervening await. This removes duplicate syscalls, not validations or await boundaries. Add actual-function counterlaws for parent/root/backing replacement and cancellation at every retained boundary; do not cache a physical result across awaits.

## Additional Concrete Rechecks

Each file verifies its named path and full ancestor chain inside descriptor custody, then repeats named path and chain after descriptor close. The latter close boundary matters and must not be deleted blindly. The inner exact and subsequent chain checks are each separate async awaits, so combining them requires preserving pre/post phase/observer checks and descriptor ownership. External ancestor identity rechecks and in-payload full-content stamps have different contracts and must remain distinguished.

Progress currently publishes and yields after every file chunk and every directory page; directory scans additionally do so after256 work units. On many small files this is frequent accepted routing work. It may be coalesced only according to the existing progressWorkUnits contract while retaining cancellation/phase checks on each actual IO and a final progress flush; do not invent a larger budget or suppress accepted progress failures. Measure actual counts before choosing this change.

## Streaming Strategy Limits

The repeated sorted-window scan is intentionally memory bounded but quadratic in a wide directory. Replacing it with one pass plus an unbounded names array, relying on filesystem order, or a weak commutative digest would change completeness/digest guarantees. An eventual bounded external merge-sort or radix traversal requires an explicitly owned temporary-storage lifetime, declared byte/work/descriptor bounds and schema-first independent oracle; it is a separate design, not a quick bypass. Prioritize eliminating exact duplicate synchronous custody calls first, then obtain Source-level counts/timing spans under the existing phase before larger algorithm changes.
