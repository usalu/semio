## Risks And Platform Scope

A user-set immutable flag is a mechanism with privileges/owner/filesystem-specific behavior; do not claim it excludes same-user flag clearing or privileged mutation without kernel tests. Schema should state its precise threat/custody scope. Directory flags do not automatically prove file metadata protection. Unsupported filesystems/platforms remain explicit refusal; Linux capabilities/immutable and Windows ACL/attributes require their own enforcing implementations behind the same domain API. Native new feature must remain cross-platform/schema-first rather than silently macOS-only success.

Holding immutable current receipt may interfere with next canonical replacement or crash recovery, so token lifetime and recovery transitions are essential. A changed ctime with matching bytes cannot be excused merely because a flag operation was expected; exact boundary observations must bind that operation.
