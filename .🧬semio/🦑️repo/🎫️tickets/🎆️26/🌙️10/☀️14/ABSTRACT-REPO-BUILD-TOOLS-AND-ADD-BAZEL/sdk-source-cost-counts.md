# Source Validator Operation Counts

This investigation changes no production Source and launches no SDK setup, producer or physical-store operation. The ticket source-cost script transpiles the actual anchored tree definitions in memory and executes their control flow against synthetic immutable stat ports. This is an operation-count model, not issued filesystem/storage authority or elapsed/CPU attribution. A language-neutral seven-row namespace includes three directories, three files and one link. Independent SQLite counts entries, directories and slash-depth; its formulas exactly match extracted actual code for zero, one and two additional full rechecks. Actual terminal0 is `sdk-source-operation-counts.log`; receipt retains exact Source SHA. No checked-in Source file was copied into the ticket.

For N namespace entries and D directories, tree.parent invokes checkResourceLeaseControl three times per entry: absolute-path construction and before/after the immediate parent's awaited lstat. tree.directory adds one check per directory. The final rooted recheck visits D+1 unique directories with two checks each and a final original check. Therefore the tree layer performs exactly3N+3D+3 direct control calls for one complete successful pass. It performs1+N+(D+1) asynchronous lstat calls, plus two synchronous full native-root path validations. It does not walk every filesystem ancestor for each entry; nxSdkSourceAncestorsV1 still constructs lexical ancestor prefixes once per parent request. That lexical cardinality is the sum of slash depths, distinct from filesystem probes.

The retained actual namespace counts are N11701,D1478,F10189,L34 from the actual capture/copy log, not a new disk census. Substitution gives39,540 tree direct control calls and13,181 tree async lstat calls. Capture adds its own one control check and entry lstat per row, one extra root lstat, two genuineSH custody checks and one native-reservation assertion. Thus the explicitly counted capture/tree portion is51,244 direct control checks and24,883 asynchronous lstat calls. The native reservation assertion itself calls checkResourceLeaseControl once; each genuine shared custody assertion also calls it once. These counts exclude nested store.recheck, metadata readers, hashes, opendir, links and continuation ports. They are not a total SDK cost.

Actual issued checkResourceLeaseControl calls control.remainingMilliseconds. Its issued remaining function calls requireIssuedScriptInvocationV1, then checkScriptInvocation, then readScriptPolicy. Consequently each such direct resource check reaches one prepared policy validation of the current policy object; preparation is already module-owned and is not repeated compilation. checkScriptInvocation also checks exact keys/ports, signal, capabilities shape and current original remaining. Issued continuation publishes/yields each perform original checks before and after their awaited port; those extra checks are not included in the direct-resource count. No observation guard or original check is proposed for removal.

For each file-read chunk, hashNxSdkSourceFileV1 adds one direct resource check plus the issued yieldContinuation's two original validations. Exact chunk count C depends on the individual sizes, which this source-only read does not possess; do not infer C from168,402,658 aggregate bytes. Capture additionally periodically publishes/yields/rechecks every128th non-directory traversal position, whose exact count depends on directory order.

A sealed capture calls readNxSdkSourceIndexV1 twice: once for supplied index and once for freshly captured output. Each invokes the generic schema validator once for the whole Index and then explicitly checks each ordered entry's path, exact fields and link shape. readNativeCallerAuthorityV1 at capture entry separately invokes generic caller-schema validation. requireNativeStorageReservationV1 uses private issuance/control identity and no schema validator itself. Full requireNativeStoragePathV1 performs physical ancestor/type/device checks and no JSON schema validation. Store/image/allocation recheck subtrees have their own checks and are deliberately excluded rather than estimated.
