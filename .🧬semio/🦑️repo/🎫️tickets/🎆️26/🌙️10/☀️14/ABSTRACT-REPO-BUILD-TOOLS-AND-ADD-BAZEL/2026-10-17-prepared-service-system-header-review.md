# Prepared Service System Header Review

Before valid-device release, the installed primary SDK header was read at `/Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk/System/Library/Frameworks/CoreServices.framework/Frameworks/FSEvents.framework/Headers/FSEvents.h`. Its `FSEventStreamCreateRelativeToDevice` parameter documentation (lines826–834) explicitly specifies a single empty relative path for observing a volume root. The worker's empty CFString is therefore intentional and matches the installed contract; no slash or host absolute path substitution is needed. The signature takes `dev_t`, the callback event count is `size_t`, and the stream event identifier is64-bit. The observer's signed32 device and worker's64-bit counter/event bindings match the current64-bit Darwin ABI.

The [Apple File System Events programming guide](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html) was also reopened. It confirms the create/schedule/start/run/stop/invalidate/release lifecycle, per-volume relative paths and service UUID association semantics. This corroborates Source/ABI design; it is not a valid-device runtime result. No API purge, raw service UUID authority, stream fallback, external filesystem mutation or broad watcher was introduced.
