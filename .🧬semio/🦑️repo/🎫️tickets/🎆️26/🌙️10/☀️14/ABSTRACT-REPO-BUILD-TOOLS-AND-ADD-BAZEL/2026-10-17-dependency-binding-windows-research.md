# Windows Dependency Binding Replacement

Research only while the actual read-only Dependencies plan holds current Source stable. No production Source changed, Windows FFI ran, protected path was read, installer ran or binding changed.

The current fixed-producer design cannot infer that Node rename atomically replaces an existing directory junction. Microsoft's [FILE_RENAME_INFO contract](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info) exposes handle-based rename and a relative target directory, but that alone does not prove directory-junction replacement. Its [kernel rename contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information) says replacement may fail for a directory target; the POSIX flag explicitly addresses existing open file handles. Those statements do not establish a zero-touch junction solution. Actual supported Windows proof remains required.

A distinct candidate is bounded same-object reparse-data update under a real nofollow handle to the exact current Source-owned junction. [FSCTL_SET_REPARSE_POINT_EX](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/fsctl-set-reparse-point-ex) documents a supplied existing-tag mismatch refusal and accepts bounded reparse-data buffers. It does not establish an atomic target switch, required user privilege, absence of side effects on every failure, or actual compatibility with the desired directory junction. The ordinary [FSCTL_SET_REPARSE_POINT page](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_set_reparse_point) also lists a symbolic-link privilege requirement. Therefore this candidate is not selected as implemented or zero-touch behavior.

Any eventual first-party primitive must open only the exact declared Source parent and single basename without following the link; prove actual identity/current reparse tag/full current target under genuine ALL Source/global binding custody; admit the exact new issued target; bound every buffer and syscall; preserve caller control/lifetime/progress/cancellation; reobserve the actual result; and close genuine handles before complete owner settlement. Missing-leaf creation and existing-junction replacement are separate operations. No old target traversal/removal or generic reparse writer may be exported by a Dependencies command. No Native/store/reservation authority follows from a filesystem handle or serialized current DATA.

Required tests include exact old-target CAS, wrong reparse type, ordinary directory/file, copied/late/foreign capability, readonly/privilege refusal, failed update with truthful observed post-state, control cancellation, retained accepted handle drain, and actual Windows junction behavior without developer mode or administrator assumptions. POSIX rename remains a separate platform implementation. The interim fixed producer can refuse Windows before installer effects until this primitive is proved; such a refusal is not cross-platform completion.
