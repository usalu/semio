# Protected Artifact Retirement Design

This records the design boundary before implementation. A contained read-only custody capture/read was subsequently added and is qualified separately in `2026-10-17-protected-artifact-read-custody.md`. No Native/protected read, journal mutation or payload removal occurred in this lane. Root owns Tools retention; Interfaces owns Graph/domain admission and Repo administrative composition.

## Required Fixed Core Seam

Proposed `retireNativePlatformProtectedMaintenanceArtifactV1(parent, control, request)` is a closed fixed command in the existing explicit Native maintenance owner. It accepts the actual opaque maintenance parent and authentic refining control, never an ordinary fake image/reservation, public writer, generic retirement callback or caller success boolean.

Request DATA must pin the complete current policy, actual backing identity, raw journal SHA/bytes, full exact unique committed artifact-publication allocation with no child/namespace, and complete bounded nofollow payload CAS produced by the actual registered managed Artifact owner. Domain owner validation remains essential: a row owner string plus a supplied arbitrary tree does not link that tree to the allocation. Core must consume an authentic registered current Artifact provider/enrollment, or establish an equivalent private typed current-owner association from the actual physical domain declaration. The exact existing immutable-managed Artifact owner path is being coordinated with Root before choosing its issuer.

A sole expected artifact allocation and no persistent-state/child/namespace/other rows is the safe initial journal class. Broader unrelated-allocation preservation needs actual private payload ownership association to prevent cross-row deletion. Graph pool admission already derives exact owner, bytes and full current policy, and requires all descendant images gone before artifact terminal retirement. Tools current generation/registry/source/binary receipts must be authenticated by its actual domain owner; current directory names or an arbitrary CAS manifest cannot substitute.

## Two Distinct Outcomes

Selected Tools generation retention may remove only one known quiescent SDK subtree while retaining the complete committed artifact allocation and its conservative charge. It must not claim zero-charge settlement merely because the selected subtree disappeared. A terminal artifact-allocation command instead requires every registered payload role/reader/handle for that allocation to close and the complete payload ownership scope to be physically retired and durable before canonical retiring/retired journal events release its charge. Graph pool/fixture Graph terminal retirement uses this latter branch.

The existing Native reservation retire path appends retiring, calls its enforcing physical port, then appends retired. A readonly protected observation port cannot be handed to recoverNativeStorageReservation or wrapped in a fabricated writer. The new command must use the actual private maintenance provider and genuine journal transaction with timeout0; its typed physical Artifact owner acknowledgement must bind the same parent, allocation, current payload and operation. Pending/unknown producer work or unknown entries refuse and preserve charge.

## Ordering and Failures

Hold actual target image EX, then its relevant mapping EX, then actual journal EX nonwaiting. Recheck current complete zero-descendant association roster, policy/backing/raw journal/full allocation and registered payload CAS before the first physical effect. Tree operations must use bounded nofollow observations/descriptors with unchanged work/entry/byte/native grants, yield progress, and honor actual cancellation. Preserve exact unrelated Native control metadata and never detach the parent image or clear/rewrite the ledger wholesale.

Before physical work, cancellation/mismatch/busy leaves journal and payload unchanged. After physical work starts, conservative charge persists through every partial failure; the command reports actual residual state and never fabricates rollback. Only actual canonical physical retirement, metadata durability, descriptor/reader closure and exact terminal recheck permit retired to remove the charge. Arbitrary primary values, including undefined and frozen/aggregate objects, remain first; distinct cleanup failures append without masking them.

Source-first cases must cover copied/unregistered provider, read-purpose token, altered policy/backing/journal/row, persistent or child funding, extra payload/State, foreign device/symlink/hardlink facts, pending reader, busy journal, cancellation before/after first effect, partial deletion, failed durable sync, forged physical completion and correct retained-charge versus zero-charge outcomes. Neutral JSON/Ajv plus independent SQLite event projection must agree with actual Source owner bodies and real Generated EX/journal/descriptors before any physical release. No Source manifest cap/budget increase or new reachable Source file is required by the proposed seam; related definitions should fold into current owners.

## Concrete Current Artifact Custody Seam

Root identified the real Tools domain owner: `library/⚡️caching/🚀️bootstrap/🛠️tools/🧹️retention/📥️physical/🟦️.ts`, private `retireManagedToolingGenerationsOwnedV1`. Its actual registered RepositoryToolingStore and NativeStorageReservation cannot be structurally fabricated from a protected parent. Selected SDK deletion preserves the single repository:tooling-store allocation; it is distinct from Graph pool terminal row settlement.

Proposed first contained Core exports, folded into existing explicit Native maintenance owner and contract/schema, are:

- `captureNativePlatformProtectedArtifactMaintenanceV1(parent, control, expected)` returns a private opaque current-artifact maintenance token. `expected` is closed DATA: action retain-allocation-payload or retire-allocation; exact complete policy/backing/raw-journal SHA and bytes; full expected committed artifact-publication row without child/namespace. Initial scope must have a complete zero-descendant roster and no other admitted physical command. Admission atomically reserves the actual ancestor chain before journal await. No ordinary reservation or NativeImage is manufactured.
- `readNativePlatformProtectedArtifactMaintenanceV1(token, control)` returns detached current row/policy/backing/journal DATA after actual live parent/refinement checks and genuine nonwaiting journal EX replay. Every recheck verifies the same complete projection/raw bytes, never grants mutation methods, and refuses copied/foreign/escaped or cancelled tokens. This is the honest current readonly reservation view needed by selected Tools retention. It has no commit/retire/resize or NativeImage close method.
- A fixed Tools domain command receives the authentic token and closed selected SDK identities. Its own private current Tools custody verifies token action, exact declared Tools root/policy/owner and the real current registry/generation/shard locks, active pointer, receipts, provenance and full inventory. Shared algorithms should accept an accurate internal retirement-access interface with genuine ordinary-store and genuine protected-token implementations; neither implementation pretends to be the other. The Core token is never a generic physical callback or public writer port.
- Fixed `retireNativePlatformProtectedMaintenanceArtifactV1(token, control, exactPayload)` is separate and accepts only action retire-allocation. It must use a real private canonical Artifact payload owner/completion and durable journal transaction. Capturing the readonly token does not establish physical retirement or zero charge. Tools selected-generation mode cannot call terminal row retirement; Graph pool remains refused until its actual complete payload owner is implemented.

The initial implementation may restrict to exactly one expected committed artifact row and no other allocations; broad overlap/State safety cannot be inferred from owner strings. The action label remains detached intent DATA; the opaque token proves only the actual current parent EX and repeated exact journal observation. A future fixed owner must separately authenticate action and payload provenance, and neither label is evidence of physical completion. Parent/read lifetime, current Original, nonwaiting journal policy and existing depth/work/byte/cleanup caps remain unchanged. Source vectors must establish capture/recheck/escape/copy/read-purpose/current-row drift and payload-action versus terminal-action separation before either domain can remove actual payload. All Source/strict/global capture evidence must refresh after this new reachable Source batch; no Native action is implied.
