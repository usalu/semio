# Compositional Immutable Input Group: Design Before Implementation

This is a prospective Source contract. No group API, funded staging, installer or Native effect is accepted here. The existing single input batch retains its exact512-file,64-root,64MiB and other current limits and call behavior. The concrete domain requirement is more than1,126 projected manifest/input rows over current scopes; every authored w/index projection must remain. A new explicit group is appropriate instead of dropping manifests, raising the existing batch cap, retrying multiple independently authorized terminal commands, or giving a domain owner a writable Store facade.

## Closed Domain-Neutral DATA

Add a new schema definition in the existing Native schema: version1, purpose `stage-immutable-artifact-input-group`, batches:[existing canonical NativeProtectedArtifactInputBatchV1]. Require1..64 batches, exactly one root per batch, at most512 files per root, at most64 distinct disjoint complete roots overall, aggregate decoded bytes at most67,108,864 over the entire group, and existing canonical path/depth/encoding/hash/content rules. Every file root index is0 within its own batch. No domain scope, Bun/recipe, program, environment, budget, callback, provider, retry or caller-selected numeric limit belongs in this DTO. Sorting/mapping identity is full root path, never caller array position. Derive constants through existing canonical input policy; no duplicate independent policy.

All complete groups are detached, frozen and preflighted before effects. Decode/hash exact canonical input bytes, determine every derived directory roster and capacity, prove every target root absent, case/path disjointness and complete rooted relative lineage, authenticate actual current parent/control/full artifact policy/backing/raw journal/whole row, then synchronously reserve the entire actual ancestor chain once before scheduling. Bound root-local derived directories by the existing1024 rule, with the explicit new group aggregate at most64 times that existing local limit. Depth64, paths256,32 descriptors,64KiB contiguous writes and64MiB decoded aggregate remain. The group purpose is a new bounded composition contract; it is not a claim that the old512-total policy is unchanged for this new purpose.

## Fixed Owner and Actual Completion

Reuse the existing single-batch private materializer and exact descriptor/Fsync/roster logic through one internal fixed whole-group operation, one current whole artifact token, one Original and genuine journal/mapping custody. The old public batch entry must remain strict and cannot be used as repeated commands inside the group. No reset/renewal of Original, terminal reservation, byte counters or accepted lifetime is permitted between roots. Before first write, every root absence and all input bytes/limits are verified. Recheck current full authority at each root boundary and all existing cancellation/live/refinement/physical checks around each actual syscall. The selected index must identify an actual captured unique group root; copied/foreign/expired receipts and mixed single/group receipts refuse before IO/effects.

## Independent Design Review Adjustment

Low requires root absence to be rechecked immediately before each actual create in addition to the complete all-roots preflight. Drift after an earlier root is staged retains the partial group and refuses; it never adopts a collided root. The explicit group maximum is32,768 files overall. Directory/work/output/resident counters are group-cumulative, not reset by calling a single-batch helper repeatedly; at most65,536 derived directories follows64 times the existing1,024 local bound, subject to every existing path/depth rule and authentic Original cancellation.

The concrete schema must also derive a bounded encoded manifest/base64 and resident-memory plan before copying/decoding: decoded64MiB alone does not bound arbitrarily large object fields or repeated metadata. Input arrays/own-key counts, root/file path UTF8 units, fixed hash/encoding fields and JSON structure have independent finite bounds derived from the existing canonical input codec. Batch decode temporaries must be released before the next batch; no second complete decoded64MiB copy or unbounded parallel materializers. Keep only complete immutable manifest bytes and necessary actual per-root receipts. Public result serialization is a small closed count/root-digest receipt, never a full32,768-row source manifest; private actual receipts remain opaque. Exact prospective maximum encoded/resident formulas and tests must be authored in the existing schema before production implementation rather than inferred after allocation.
