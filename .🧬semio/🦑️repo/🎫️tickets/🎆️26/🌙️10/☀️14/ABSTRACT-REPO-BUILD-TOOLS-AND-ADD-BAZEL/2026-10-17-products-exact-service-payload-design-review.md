# Exact Service Payload Publication Design Review

A distinct explicit exact-payload mode can be sound without claiming FSEvents service authentication: treat every .fseventsd descendant as ordinary payload, charge every file/name/byte/depth/work observation, and require preserved complete selected payload across the real detach/attach sequence. No UUID-file fallback, daemon manipulation or assertion of absent history follows. The system may mutate those files on remount, so safe refusal is a likely legitimate outcome, not a reason to relax equality.

It is not implementable merely by catching UUID-unavailable and passing service null. Current witness unconditionally invokes the strict observer at entry and terminal. Current preservation compares applicationSha256, journalSha256 and service identity; ordinary POSIX frames include path/kind/mode/content and multi-link inode/link facts, but omit single-link inode, owner, mtime and ctime. Seven-field metadata checks currently protect each individual scan, not equality between scans. Thus the current walker supports exact ordinary content/topology preservation, not the proposed full before/after metadata claim.

Required boundaries: schema-first explicit authored mode in actual request/private scope and both before/after captures; no automatic exception-based fallback; closed witness mode discriminator preventing cross-mode comparison; strict service observer behavior unchanged. In exact mode all service files must enter application equality, and preservation must compare the complete selected digest (never service identity alone). If full metadata equality is promised, add a separate bounded service snapshot digest carrying exact stable same-volume inode/mode/nlink/size/mtime/ctime and ownership policy, and compare it across remount. Mount device numbers may legitimately change; use actual mounted identity checks per phase rather than blindly equating st_dev across detach. Do not claim the existing application digest already does this.

Keep complete nofollow same-device traversal, actual file descriptor/name/ancestor CAS, unsupported-entry refusal, existing logical byte/path/depth/work bounds, cancellation/progress and pending/receipt lifecycle. Exact service payload cannot acquire the privileged reserved-service exclusions or unknown-member tolerance of authenticated service mode. Snapshot any hardlink semantics consistently with ordinary payload; no private database interpretation is needed.

Minimum portable laws: unchanged ordinary service tree succeeds in exact mode; any content/name/mode or required cross-phase metadata mutation refuses; null system UUID never authenticates service; mixed mode witnesses refuse; all bytes count against the same maximum; unknown/unsafe entries and alias/drift preserve pending custody. Actual Generated then private mounted-image proofs are needed before Products runtime use. No implementation, Native/API call or protected read was performed.
