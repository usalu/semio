# Persistent State Directory Durability Platform Audit

Historical Source baseline at11:34UTC, before the metadata-capability implementation. The explicit allowlist/guard findings below describe that baseline. Subsequent Source integration and remaining physical qualification are tracked by [Windows metadata proposal](windows-state-metadata-port-proposal.md), [Root review](windows-metadata-root-review.md) and [current checklist](pending-qualification-current.md); this audit is not a current assertion that the old guard still exists.

Native Windows has a concrete implementation blocker: persistent directory durability is explicitly restricted to macOS and Linux. This is a deliberate fail-closed guard in current Source, but it does not satisfy the requested native Windows support for every task. This audit is read-only Source evidence; no physical runtime or filesystem durability test ran in this lane.

## Transaction and Test Boundary

The current writer completes expected prefix bytes, syncs the file, publishes a same-volume no-replace hard link, checks exact paired identity/content, removes the temporary name, syncs the parent directory, and verifies final identity/content again. Data directory creation syncs its parent before writing the durable allocation binding. A Windows implementation must preserve these transaction and recovery guarantees, immutable Native allocation binding, cancellation/progress and descriptor settlement; adding win32 to the allowlist is insufficient.

The [permanent State test owner](/Users/ueli/Documents/semio/🧰️framework/🔨️modules/🏃️process/💾️state/🧪️tests/🟦️.ts:19) calls its physical transaction helper on the host executing the test. It contains actual record/data transaction and independent SQLite checks, but no three-platform durability dispatcher law or Windows implementation. Its positive transaction cases cannot establish Windows support while the allowlist refuses their writer. This audit did not run those tests on any host and did not simulate host identity as OS proof.

## Required Next Owner Work

Define a first-party platform durability port with a closed system result and identity contract, implement the genuine Windows system operation behind it, retain the existing macOS/Linux descriptor path, and keep unsupported/failed operations fail closed. Add a language-neutral transaction/failure corpus for the platform dispatch and an independent system observer for file and directory identity/settlement. Actual native Windows, Linux and macOS qualification must cover creation, restart, prefix/link interruption recovery, unknown data refusal, cancellation, arbitrary primary preservation and complete descriptor/child drain before claiming all-platform task support. No external runtime type needs to escape that interface.

The missing Windows implementation is the concrete blocker established here. The audit does not prescribe an unverified Windows syscall or claim that a Source model proves crash durability.
