# Bounded Persisted Image Diagnostic

## Existing Boundary

Root's `image-reuse-review.md` was read before design. Current `observeProjectInferenceV1` can reuse a persisted image, but it is not a read-only probe: a miss falls through to computation and optional publication. Its exact production key includes project and registry authority, conditional native/assembly authority, root, augmented declaration and selection. The persisted digest also distinguishes a genuine nested parent/validation frame from an unscoped call. Substituting root alone, a receipt's digest or a hand-picked default declaration would not prove current eligibility.

No exported production port was found that prepares that exact key and checks persisted eligibility without a compute fallback. `inferenceHeaderLine` reads without a byte cap. Public `observationsHold` can check complete supplied Source facts, but it does not check the expected project key or sealed authority. These are precise limits, not negative reuse results.

## Proposed Read-Only Measurement

The diagnostic is proposed only; execution requires Root's design review. It would remain in the existing ticket qualifier, with one original 60-second operation and genuine graph-store capabilities. `withRepositoryCacheStoreV1(workspace,"graph",original,body)` supplies the existing shared image custody and original control. It would not open a FactStore, request writer maintenance, alter optional quota policy, rewrite a receipt or invoke a public build task. Normal enforcing store bookkeeping remains owned by the existing API.

Use the owned ALL9 start/completion trace to identify its 794 completed project roots. Check only their expected canonical `inference/np/<sha256(root)[0:24]>.json` leaves, under physical store path admission. No recursive cache census or Source copy is needed. Bound metadata to 794 leaves; bound full record inspection to the first 64 admitted leaves, 4 MiB per leaf and 32 MiB total. Missing, changed, foreign, oversized and uninspected rows stay distinct.

For inspected records, report header structure and the SHA-256 of the complete result body independently from availability. After the real source-analysis provider bootstrap, at most eight records containing at most 10,000 observations each may use the existing public `observationsHold` with no stable-directory shortcuts, eight workers and the original signal. Await original progress/continuation between bounded operations and preserve original deadline failure. A current-facts result remains separate from exact current-key eligibility.

The result must explicitly report exact eligibility as unknown because the expected full production key and nested frame admission are unavailable through a read-only interface. Structural availability or currently holding Source facts alone cannot justify a claim that a new ALL run will reuse the prefix. No helper, production change or new producer is authorized by this design report.

Header key-digest equality between two read-only samples is not a fresh production key match.
