## Contract and custody

`withNativePlatformChildStorageV1(parent, options, body)` requires the actual platform-registered image, then the concrete privately retained ready receiver. `withNativePlatformMaintenanceChildStorageV1(parent, custody, options, body)` additionally requires the exact live custody object registered by the real exclusive-maintenance callback and its authentic writer proof. Both callbacks receive `(actualChild, actualReturnedControl)` and settle the child before releasing the parent operation. Options and parent/custody references are captured before the first await. There is no raw parent token, caller-supplied assertion, optional compatibility path, or new public command.

The private parent frame retains exact receiver facts/owner and physical identity through child close. Normal child entry borrows the real parent operation; maintenance entry reuses its actual maintenance owner without acquiring another shared image lease. Both external ordinary child operations and accepted terminal cleanup reads restore the retained private frame. Child maintenance does likewise. `requireNativePlatformImageCloseV1(image)` provides a no-effects, exact-platform-member preflight so an enclosing Repo owner can refuse parent self-close before changing its own admission or awaiting pending work. Closing a parent from its child frame refuses synchronously; an external parent close drains the accepted child operation.

State now keeps its child metadata/data/task scopes inside the scoped factory, releasing the State admission gate before the long body. Compiler cache opens its catalogue child and workspace child in two distinct scopes. Each catalogue replacement remains individually awaited; no replacement ledger is held across workspace work. Child close remains inside the parent scope. Existing immutable charge bindings and physical guards remain in place.
