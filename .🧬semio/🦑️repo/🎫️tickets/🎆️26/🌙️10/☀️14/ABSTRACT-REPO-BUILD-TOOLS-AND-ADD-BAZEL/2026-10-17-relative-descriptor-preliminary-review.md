# Descriptor-relative POSIX preliminary Source review

Source only, before final fault cases/manifest. The implementation correctly uses retained parentFD+validated UTF8 basename, independent cursor open, errno-disambiguated bounded readdir records, nofollow identity handles, actual numeric-FD stats, shared descriptor lifetime and tracked child drainage. It does not confer Core administrative authority. No FFI or protected/Native IO was run by this auditor.

Three findings were sent Root for resolution before final hold. Directory stat currently lacks exact `this` admission while other methods require it, so detached/copied stat remains usable while the frame is live. Darwin O_SYMLINK probe can open a special/device before kind(fstat) refuses; NONBLOCK does not establish that arbitrary device open is inert, unlike Linux O_PATH. A genuine nofollow relative preopen metadata admission (or another explicitly qualified system mechanism) is required for a claim that foreign kinds refuse before opening. Finally, names enumeration can synchronously process the entire65536-name window without an await/yield or progress call; it is bounded and checkpoints cancellation, but does not provide event-loop cancellation during that whole synchronous interval.

These observations do not assert a protected fixture contains a special file or that a current caller escaped custody. Final tests should bind exact receiver refusal, special-kind before-open fault behavior and declared progress cadence, alongside all existing FD/name CAS/close/cancellation laws. Windows remains a preacquisition refusal in current Source, not a qualified rooted-handle mutation backend.
