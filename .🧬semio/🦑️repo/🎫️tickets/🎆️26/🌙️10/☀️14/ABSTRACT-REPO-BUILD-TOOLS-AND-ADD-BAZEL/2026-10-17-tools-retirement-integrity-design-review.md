# Retirement Integrity Authority Design Review

Root proposes a distinct private retirement-integrity proof after selecteddb49 reached its own invalid Source manifest. No new implementation or runtime acceptance is certified here.

Deletion integrity need not assert runnable compiler/source schema semantics. A genuine current owner can authenticate exact owned immutable bytes through current install identity, closed marker/receipt, exact opaque Source blob hash and fixed compiled output hash, plus the unchanged SDK material/binary/inventory and physical custody proofs. This is distinct from accepting an old Source format for execution. It must be schema-first purpose-closed, with its own private evidence registry and strict recheck; it cannot pass the existing runnable evidence recheck.

No failed strict parser followed by a permissive fallback is acceptable. The new reader must not inspect a version and choose legacy semantics. It must never consume opaque Source entry/path/resolution fields as filesystem paths, imports or code; read only the already fixed admitted metadata/bundle basenames under nofollow physical checks. Exact sourceSHA/outputSHA relations authenticate bytes, not safety or current interface compatibility.

Selected directory full identity/prefix/root CAS and current binding exclusion remain mandatory. Existing witness/protocol restrictions, global registry and real selected EX, private Core token/whole row/raw journal/physical parent proof, complete bounded payload census and unknown-hardlink refusal still apply. Binary-object shared references require their existing exact receipt/group provenance and selected-only object rules; no outside alias sweep or physical-savings inference.

Current schema-invalid Source bytes may therefore be retired only as authenticated owned bytes under this new intent; they must never be relabeled valid, imported, executed or activated. Any malformed current marker/receipt, hash mismatch, unknown material/content, released/copy/foreign proof, changed binding or busy reader refuses. Historical capacity receipts are DATA and cannot replace current evidence.

Required Source laws include strict runnable reader still refusing the same blob, retirement reader passing exact opaque-byte relations, mutual cross-proof rejection, arbitrary opaque malformed JSON with no parse/hooks, fixed output path enforcement, copied/late token, changed hashes/payload/current binding and partial deletion failures retaining whole charge. No protected read, Native operation or production edit performed by this reviewer.
