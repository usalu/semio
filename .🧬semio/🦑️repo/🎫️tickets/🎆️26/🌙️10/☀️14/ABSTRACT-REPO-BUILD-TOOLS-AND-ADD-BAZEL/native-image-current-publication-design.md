## Event and Fault Model

Use a closed state/event model colocated with Native cleanup: accepted → observed-mounted/inactive → payload-captured → detached → underlying-observed → publication-attempted → receipt-durable → attached → verified → settled. Every awaited command/progress/metadata action is accepted and drained by the same genuine phase/cleanup owner. Intent flags are set BEFORE potentially effective detach/publication/attach. Before detach, refusal closes the new observation descriptors and actual EX without touching payload or receipt. After detach, cleanup may reattach only the same bound backing to the exact newly observed underlying directory, using the accepted cleanup phase. Original body errors (including undefined/frozen) remain primary; independent cleanup faults are retained. An indeterminate command, backing/path change, unknown mapping, unproved descriptor close or failed durability barrier retains unresolved custody and reports it. No success receipt or EX release on uncertainty. A receipt-write failure is not proof no bytes changed. A failed attach is not repaired by rewriting the old receipt.

Process crash releases kernel locks but does not prove graceful settlement.
