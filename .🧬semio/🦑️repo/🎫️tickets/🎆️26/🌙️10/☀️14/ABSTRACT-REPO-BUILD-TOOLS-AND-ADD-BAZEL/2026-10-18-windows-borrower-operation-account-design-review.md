# Windows Borrower Operation Account Design Review

The qualified receiver-attempt account allows16 information commands for its body lifetime, at most eight complete mapped read brackets. A long-lived actual storage receiver can legitimately need more independent operations. A fresh account per genuine outer borrower operation is a reasonable explicit new contract, not unchanged receiver-lifetime policy or a free retry workaround.

Mint a private key only after actual outermost withNativeImageBorrowerOperation admission, bound to exact registered receiver, borrower, current guard, actual issued child control and original inherited lifetime. Nested borrower/observation/journal operations on the same receiver must reuse the parent operation account, even when a genuine requested child has a new control object. Baseline opening and accepted terminal cleanup remain separately cumulative. Reserve before await and share all per-command/work counters with every nested callback.

Keep receiver-level sticky failure/unresolved state. A poisoned operation cannot be abandoned in favor of a new key to retry its failed attempt; copied keys, concurrent callbacks and same-input retry after failure refuse. Only a successfully completed prior operation's actual drain, descriptor/library closure and association checks permit a new independent outer operation budget. No Original/deadline/funding/caller override is renewed.

Existing borrower implementation records scope failures and aggregates accepted descendant failures; those actual owner records should remain part of readiness/closure policy rather than silently replaced by per-key bookkeeping. Required counterlaws: success then independent new operation; nested real borrower preserving same key/count; same original input after poison; concurrent admission; guard replacement; close/finalmapping failure; accepted terminal after body failure without body revival. No public dispatcher/Native acceptance is authorized by this design review.

A canonical readonly borrower-operation identity accessor is preferable to Fixed guessing an outer boundary from its own ALS/control. The actual borrower owner must authenticate current live same-owner frame, return its outermost same-owner nominal key, expose no registration/writer authority, and expire only after actual descendant drain/settlement. Fixed still requires actual custody and exact receiver/guard/control binding; the key alone grants nothing. Already accepted descendants may reuse a key while their parent drains, but cannot admit late new work. Accessor tests must include outside/foreign owner, nested actual equality and escaped post-drain refusal.

Actual accessor TDD exposed that existing refinement allows equal-restriction ancestor/sibling controls and is not exact issuance ancestry. A separate canonical requireIssuedResourceControlDescendantV1 should walk authenticated private parent links (self permitted) under same genuine Original/live issuance, used only where nominal frame contracts require exact ancestry. Preserve old refinement behavior; test neutral ancestor/sibling rejection independently.
