# Dashboard Authority Policy Review

Bounded read-only inspection of dashboard authority schema/fixture/test, existing launch tests and root package.json. No directory walk, runtime test or edits.

Current authority test accepts scripts only when object keycount exactly equals canonical fixture4; schema additionalPropertiesfalse mirrors it. Current package has fifth test-reserved-producer-native = bun repo run @semio-tech/framework-plugin:test-reserved-producer-native, a neutral target alias. Therefore this gate rejects a legitimate declarative target launcher for incidental cardinality, not a backend-authority leak. Current fixture even marks dev='bun repo run workspace:dev' as competing.

The test titled every active source directory is free of editor and agent launch configuration recursively walks source directories and rejects every launch*.json/jsonc inside editor folders. It conflicts directly with user-required .vscode/launch.json registration and existing dashboard launch projection. It should be replaced by bounded authored ownership/command validation, not widened exclusions hiding launchfiles.

Minimal longterm schema: require exact four canonical bootstrap keys/values; admit extra aliases only as literal neutral single-command bun repo run <project>:<target> plus allowed neutral literal args. Root repo script remains the sole special direct bootstrap path; no arbitrary additional direct scripts, Nx/Bazel commands, shelloperators/pipelines/substitutions/environment assignment or multi-command chains. Extra keys do not require fixed count. Validate token grammar/normalform using existing neutral command/argv machinery, with independent schema+thirdparty literalargv tests; avoid permissive prefixregex (it would admit appended shell). Parameter arguments remain DATA, not shell interpolation.

Launchfiles are explicitly allowed and required. Bounded known .vscode launch and seed reads should validate repo-owned task configurations against canonical neutral declaration/projection. Preserve unrelated debugger/attach entries; only task launches must route through neutral repo boundary, including existing dashboard launch target and deliberate repo exec ticket-helper boundary. Do not wrongly require every debugger entry to be a task. Existing dashboard tests/launch already compare registry-derived ENDE owned configurations, peerpreservation/idempotence and parameter rawargv using Ajv+RFC6902; reuse that contract and existing command-audit/seed coverage rather than the broad recursive launchban.

Schema-first cases: exact4 and valid fifth alias accepted; missing/changed canonicalkey rejected; directnx/bazel/directextraBun script and shellsuffix rejected; harmless literal flag accepted; quoting/interpolation ambiguity rejected unless existing literalargv normalform explicitly supports it. Required launch/seed present, neutral ownedtasks valid, malformed/directbackend task rejected, unrelateddebugger preserved. This is a policy recommendation only, not implemented/passing runtime evidence.
