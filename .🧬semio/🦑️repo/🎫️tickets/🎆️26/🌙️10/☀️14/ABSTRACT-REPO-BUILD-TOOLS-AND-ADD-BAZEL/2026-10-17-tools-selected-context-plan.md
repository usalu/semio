# Selected Tools Payload Retirement Context

Source-only design after the released Graph and capture-reporting batches. No protected Tools payload, ledger, activation, inventory or Native image was read. No real generation eligibility or savings is claimed. Root owns the separate Native descriptor-census repair.

## Current Coupling Found

The existing physical owner at bootstrap/tools/retention/physical authenticates real RepositoryToolingStoreV1 storage reservation, actual canonical Tools root, original invocation/refined phase and registry EX. Its private retireManagedToolingGenerationsOwnedV1 short-circuits and stops on physical minimumAvailableBytes. Explicit selection cannot call it with an inflated minimum. Its quiescent variant additionally checks the store's private maintenance registration; a protected parent or artifact token cannot satisfy that registration.

Copied-generation inventory calls requireNativeStorageReservationV1 and binary verification with store.image.recheck. Binary verification and object retirement require the authentic ordinary store invocation, reservation and image. Derivative material verification reaches source/index and source/index/tree, whose rooted directory traversal, metadata reader and full-byte hashing carry that same concrete store type. Simply changing the outer physical function or manufacturing a structural root/recheck store would bypass or falsify these authentic guards. The genuine ordinary store registration owns a NativeImageStorageV1 plus a real original storage reservation and cannot be minted from a protected read view.

The existing reader algorithms are nevertheless reusable: full install inputs/host identity, authorizer receipts, current activation exclusion, witness nonce/root/stamp/bytes, copied full census, binary ownership/bytes/inode/link groups, derivative snapshot/index and namespace checks. They need a narrowly named read-only verification context rather than a counterfeit ordinary store.

## Exact Authority Split

The new public command belongs only to the existing explicit repository publication owner: retireSelectedRepositoryToolingGenerationsV1(invocation, control, closedCommand). It authenticates actual setup-all Original/root, derives the unchanged Tools declaration and global lease catalog, obtains the actual opaque protected parent EX, captures the real Core artifact token with action retain-allocation-payload, and verifies the exact committed repository:tooling-store row, full policy/backing/raw journal CAS and empty descendant roster. It owns every mutation privately. It never returns a writable image, reservation, generic deletion callback or authority-bearing read context.

A shared internal ToolingRetirementReadContextV1 describes only read verification: actual root, Original invocation, owner control, current operation control and a read-only recheck operation. It has no image, storage reservation, environment, delete/publish/retire method or maintenance-allowed boolean. The ordinary owner projects it only after its unchanged private store/reservation checks; the administrative owner constructs its own scoped read view only after the actual Core token has been authenticated. Both routes call the same material/authentication algorithms. A structural read view or inventory remains DATA for verification and cannot invoke the private fixed deletion path. Recheck is a read-only custody observation, not a caller-supplied privileged operation. No public function accepts an arbitrary effect callback or promotes detached DATA into authority.

The fixed administrative command keeps its authentic opaque Core token private and directly calls Core readNativePlatformProtectedArtifactMaintenanceV1 at admission, before each destructive boundary and at terminal settlement. That function reauthenticates the real live parent scope, exact token/control/refinement, row/policy/backing and raw journal through timeout0 journal EX. Thus a forged read view cannot substitute for private Native custody. The domain owner separately retains registry/generation/shard leases and its own live operation frame until all accepted read work drains. Escaped continuations, copied controls/tokens and closed frames refuse; no new Original or budget reset is introduced. If the Core read-only token cannot support this exact retained scope, implementation must stop and coordinate a fixed Core terminal command, not infer authority from returned DATA.

Shared read helpers do not gain effect methods. Existing public ordinary APIs continue authenticating the actual ordinary store and delegate only their read kernels to the internal context. Existing ordinary publisher/seal/projection APIs retain their authentic reservation/image requirements. This is an internal read-kernel refactor, not a compatibility or historical-adoption layer.

## Selected Operation and Invariants

The closed request contains mode selected-generations, an explicit unique sorted list of at most64 Nx64hex identities, exact current parent CAS and exact current artifact expectation. It contains no minimumAvailableBytes and no Rust names, broad prefix or whole-store discard. Missing/malformed/unknown selected material is reported as refusal; current activation is never selected. All declared names are parsed before opening, current activation is authenticated under registry custody before effects, and each selected generation's full material is authenticated before its deletion. A later refusal or cancellation retains the real full store charge and all uncertain remaining material; partial work must be recorded honestly rather than described as atomic cleanup.

Order: actual Tools parent EX and artifact custody; timeout0 registry EX; current activation and bounded witnesses; deterministic selected generation EX; exact install/authorizer/material proof; copied full inventory or derivative base SH/index/tree proof plus binary link proof; stable activation/witness/root/payload rechecks; unlink only stable selected witnesses; remove only that authenticated selected generation; recheck unchanged real artifact row and remaining activation; then selected released binary objects under exact timeout0 shard EX. Accepted work drains before gate/parent/infrastructure close; arbitrary primary and distinct cleanup failures remain ordered and exact.

Existing broad retireReleasedNxSdkBinaryObjectsV1 scans the whole object catalog. The explicit selected command must instead capture the bounded binary hashes from authenticated selected manifests, deduplicate them, and attempt only those released objects after their generation names are removed. An object still linked to active or unselected generations (nlink>1) remains. No unselected generation, pristine snapshot, Rustup toolchain, unrelated object or State is deleted. The existing broad opportunistic route remains separate and unchanged.

Preserve existing64candidate/1024witness/8MiBmetadata limits,200000entry/8GiB copied census,256byte paths,256objects per binary receipt/128MiBobject/64KiBchunks, derivative16MiBindex+inputs/200000entries/32inputs/128entry continuations. Progress/cancellation retain actual carried Original deadlines and cleanup reserves. Named logical and physical Tools8 contracts are unchanged. The fixed command neither resizes nor retires the full repository:tooling-store row and does not assert any inode unlink decreases that charge.
