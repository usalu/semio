## Pinned ABI Checks Still Required

Pinned Bun exposes u32 and u64/usize FFI integer forms. Use u32 for DWORD results and buffer counts; UTF-16 typed arrays stay allocated across each call. Real Windows x64 HANDLE is an opaque pointer-sized integer, not a dereferenceable JS data pointer; use lossless private BigInt representation, reject zero/INVALID_HANDLE_VALUE, close exactly once only after pending work settles. Validate the pinned generated trampoline C ABI and observed actual return before relying on this mapping. Existing jobserver `ptr` usage does not establish correctness. This is a proposed private representation, not an executed ABI receipt. [Pinned FFI forms](https://raw.githubusercontent.com/oven-sh/bun/bun-v1.3.14/src/js/bun/ffi.ts).

The no-FFI pinned process report alternative was investigated and rejected as a complete bootstrap: ANSI/truncation and unchecked module-array capacity prevent the required universal bounded Unicode proof. No env/program search or post-launch self-report is promoted to authority. Windows x64 implementation scope and the existing ARM64-host inconsistency remain separately recorded.
