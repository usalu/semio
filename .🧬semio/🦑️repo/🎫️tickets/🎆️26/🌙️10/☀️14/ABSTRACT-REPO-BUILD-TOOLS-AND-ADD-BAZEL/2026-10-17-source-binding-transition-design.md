# Root-Anchored Source Binding Transition Design

This is a Source-only implementation plan after the inactive-retirement7 checkpoint. No host Source binding, protected inventory or Native operation was performed. Bazel owns the funded producer Probe and will not change Source bindings in that command.

## Current Actual Seam

The detached `JavascriptDependencyProducerBindingsV1` observation contains the actual workspace root; one missing-or-link row per declared root/member node_modules endpoint; exact Node seven-field stamps and bounded link targets; physical ancestor dev/ino/mode facts; a complete digest; and authority:false. It deliberately refuses existing ordinary files/directories. The new writer must compare those prior observations to fresh real rooted observations after all producer scopes, staged generation receipts and complete256-path qualification succeed. It must retain genuine setup-all Original, Core retained whole-allocation custody, actual global bindings EX and ALL Bun ownership throughout. No serialized leaf or receipt grants filesystem custody.

The ALL Source observer retains directory kind/dev/ino/mode and filtered membership topology. It deliberately excludes node_modules and hidden staging names from discovery/replay lists. Thus an exact owned binding transition need not erase or rewrite unrelated ALL observations. Actual nonbinding ownership, manifests, topology and complete Node binding observations must still be replayed at the fixed command boundaries.

The current ordinary binder uses path-based symlink/rename and even has a physical-payload retention branch. That code is not a qualified replacement kernel for this new fixed producer. The new protected route must not call it or normalize unqualified physical content into a link.

## Chosen Generic Capability Surface

Extend only the existing first-party relative directory capability, with no Native import or raw provider:

- `captureBinding(name)` returns a frozen first-party binding expectation for a missing or single-link symbolic/reparse leaf. A private WeakMap binds exact object identity, name, live parent frame, current parent stamp/roster, and actual child facts. Windows additionally retains full128-bit file ID, volume, security, streams and raw reparse/tag facts.
- `publishBinding(expectation,target)` consumes that exact same-frame issued expectation synchronously before any await. It requires quiescent exclusive admission, closed bounded target DATA and a live synchronous checkpoint. No structural copy, expired frame, sibling directory proof or reused expectation is accepted. The target is not followed by the generic kernel.
- The result is fresh named DATA/expectation for the actual completed transition. It is not a Core or domain producer grant. Existing directory methods, relative64 handoff, shared32 registry, accepted-child drain and exact primary/close rules remain.

The fixed Repository owner separately pins each previously captured Node leaf and ancestor observation and verifies the actual desired directory target through its prepared funded producer result. It creates fresh private root-family expectations only while that real owner and global EX are live. Full Node facts and generic platform facts are distinct representations; Windows must not pretend Node lstat size/mode or normalized readlink text equals raw kernel reparse DATA. Compare the previous Node observation with a fresh Node observation, then bind its dev/ino/kind/target to the actual rooted kernel identity, retaining the full private Windows proof.

No generic arbitrary write callback or public Native writer port is introduced. Bazel's fixed producer keeps all capability callbacks private.

## POSIX Publication and the Atomic-CAS Boundary

Missing publication uses an exclusive parent-relative symbolic-link operation, with exact absent expectation and known parent transition. Existing symbolic links use a fresh exclusively created sibling link and platform atomic exchange: Darwin renameatx_np RENAME_SWAP, Linux renameat2 RENAME_EXCHANGE. The displaced entry remains under the owned staging name until its actual inode, type and complete link target are checked against the expected old link. Only that exact verified old link may be removed. A foreign file/directory is retained and the command fails; it is never adopted, overwritten then deleted, or recursively cleaned.

This is a conditional compare/publish/verify protocol under the actual domain EX, not a claim that POSIX provides an atomic inode-compare predicate. The documented exchange accepts unlike entry kinds. An uncooperative actor can race the final precheck; post-exchange verification must therefore retain any unexpected displaced entry and report failure, with no automatic rollback. A failure can leave the new name and a retained old/foreign staging entry. The fixed command must record exact current failure facts and cannot report completion. Unsupported atomic-exchange filesystems must refuse; do not silently substitute destructive plain rename.

Atomic exchange and absent-only flags cannot be combined. The existing-name branch must explicitly require the expected name to remain present and the missing branch must never replace a newly appeared entry. The staging name is an exclusively created runtime-owned leaf, not authority derived from a prefix. Crash/ambiguous-close remnants are retained for exact current intent; no global prefix sweep exists.

Apple's actual rename manual documents descriptor-relative rename, same-filesystem atomic swap and separate exclusive-name behavior. [Apple XNU rename manual](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/man/man2/rename.2). Linux documents atomic exchange of even unlike kinds, absent-only rename and their incompatible flag combination. [Linux renameat2](https://man7.org/linux/man-pages/man2/renameat2.2.html).

## Windows Native Branch

Open the host root and every parent through the existing ordinary no-reparse rooted handle capability. Never follow a Native mount reparse as a Source ancestor. Open the old leaf relative to its actual parent with OPEN_REPARSE_POINT and rights/sharing that prevent foreign write/delete mutation while its full proof is held.

Do not use Node.rename to replace a junction. A same-kind existing directory symbolic link or mount-point reparse can be updated through the exact held handle with FSCTL_SET_REPARSE_POINT, preserving its tag and full identity, then re-read target/tag/security/streams and require real flush/close/parent barriers. A noncompatible symbolic-link object requires a prepared new directory reparse plus an exact old-handle move to a private backup and absent-only publication by NtSetInformationFile, keeping the old object and new staging object on any unresolved intermediate transition. This branch has a controlled name gap under global EX; it must not be labelled a single atomic junction replacement.

Absent publication prepares a complete exclusively created private staging reparse before publishing it by relative NT rename with replacement=false. Parent RootDirectory and a single basename are bound in the actual FILE_RENAME_INFORMATION buffer; DLL and child handles use the shared registry. Known newly created unpublished staging objects can be cleaned only by their live private issued identity; ambiguous or foreign remnants are retained. No existing ordinary directory/file is converted into a binding.

The current docs say rename replacement fails for an existing directory, and describe relative RootDirectory plus DELETE access. They do not establish that Node rename replaces directory junctions. [Microsoft FILE_RENAME_INFORMATION](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information). Microsoft permits handle-bound modification of an existing reparse point only with matching tag; non-Microsoft tags have extra GUID conditions and remain outside this closed feature. [Reparse operations](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-point-operations), [FSCTL_SET_REPARSE_POINT driver contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/fsctl-set-reparse-point). Actual NTFS privilege, sharing, junction publication and durability remain physical qualification requirements.

Raw substitute targets and user-visible readlink targets require an explicit schema-owned codec, not accidental string equality. Libuv's actual readlink implementation handles DOS/UNC namespace prefixes before returning Node-facing text. It is an independent Source oracle, not a runtime dependency. [Libuv Windows filesystem implementation](https://raw.githubusercontent.com/libuv/libuv/v1.x/src/win/fs.c).
