## Capacity Decision Before Code

The original draft accidentally reused command stdout1MiB/32768 limits; those are not witness quotas and will not be used as such. Existing artifact census has262144 entries/64depth but does not establish an all-Tools/Products image limit. A complete streaming candidate uses deterministic lexicographic pages of64 names, each full physical path<=256 UTF16 units, a64KiB file buffer, and closed directory descriptors before recursive descent. Retained memory is bounded by the ancestor chain and64-name pages rather than total tree size. Each page re-enumerates its physical directory to select the next64 names after a cursor, then processes them in UTF8 byte order. This trades extra enumeration for bounded memory without scratch writes or an invented order-independent hash. Two complete canonical stream censuses must agree in digest/count/extent under the caller's actual whole-image EX and pre/post per-file/ancestry checks. This is not an atomic whole-tree claim against actors outside that custody.

The proposed finite work allocation derives from actual filesystem bytes: at most one admitted entry/directory-enumeration work unit per logical byte per pass, plus existing genuine deadline/cancellation/progress. This is a new witness work allocation, not a reinterpretation or widening of an existing cap. Pathological broad directories can exhaust it and refuse.
