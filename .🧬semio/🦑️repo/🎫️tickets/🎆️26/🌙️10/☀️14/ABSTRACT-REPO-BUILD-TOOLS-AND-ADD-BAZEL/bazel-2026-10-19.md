# Bazel Qualification, 2026-10-19

The existing backend already generates a selected Bazel task graph, fingerprints declared sources, and snapshots declared products. The root MODULE intentionally does not duplicate project declarations.

Initial source-contract execution stopped before tests: `@semio-tech/schema-validator-ts` cannot resolve from the workspace. The execution agent is repairing workspace dependency provisioning.

A concrete lazy-discovery gap exists in exported or Git-free workspaces: the Git inventory respects selected input prefixes, but its portable filesystem fallback scans every source tree. This can turn one selected small task into a repository-wide traversal. The planned correction shares a normalized minimal traversal-root calculation between the Git and filesystem paths, preserves ignored generated directories, checks cancellation, and validates behavior with portable JSON fixtures and an independent SQLite oracle.

No runtime Bazel success has been claimed.

## Implemented

- `bazelInputTraversalRootsV1` normalizes input prefixes, removes duplicate roots, and removes descendants already covered by another root. Git pathspecs and the portable fallback now share this selection.
- `bazelFilesystemSourceFilesV1` walks only those selected roots, handles explicit files and absent paths, preserves excluded generated directories, and checks original cancellation before each root read.
- The existing Bazel suite imports the new inventory contract. Its portable schema and fixture compare selected roots against SQLite and schema validation against AJV, without introducing a runtime dependency.

## Cache/Output Audit

- Generated Bazel rules include each task's manifest, fingerprint, captured runner and full captured implementation as declared inputs. Dependency snapshots are declared action inputs, so changed prerequisite products invalidate consumers.
- `runtime.json` intentionally carries live owner/cancellation data outside the action key. Stable cache reuse across different invocation envelopes depends on declared fingerprints; actual cache misses obtain live parent authority before action birth.
- Only the selected task dependency closure is generated. Snapshot capture includes declared output roots, flattens file payload names, and avoids copying undeclared workspace products. Snapshot restoration hashes current files and returns immediately when the declared output tree is already equal.
- Continuous actions are separately started with readiness/cancellation handling and never restore cached service state. `cache:false` receives both a fresh fingerprint nonce and Bazel `no-cache`; cached test targets use the same authored `cache` policy as build targets.
- Local disk action storage is configured under the products partition. Actions explicitly refuse remote execution/cache through `local`/`no-remote`; `skipRemoteCache` therefore has no additional effect in this backend. Shared remote-cache support is not claimed.
- `{dependentTasksOutputFiles, transitive}` selectors remain conservative: dependency snapshots enter action inputs in full. This protects correctness but may invalidate a consumer when an unselected prerequisite output changes. No narrowing was implemented without an actual runtime proof.
