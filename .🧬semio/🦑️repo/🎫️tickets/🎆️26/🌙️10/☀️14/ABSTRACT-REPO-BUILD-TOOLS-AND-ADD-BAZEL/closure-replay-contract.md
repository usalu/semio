The independent Bun SQLite oracle stores complete captured rows under receiver identifiers with a primary key of receiver, kind, path and full fact JSON. Measure validation/checkpoint/replay counts separately from parser or physical reads. The first hit must visit the full baseline observation set. A same-tuple hit can have reduced redundant work only after that first successful hit. Different-parent/same-capture/same-validation and different-capture/same-parent cases must each replay the full set. This is a count-based invariant, not a wall-clock threshold.

A source-byte edit belongs to a fresh attempt with fresh receiver/validation maps. It must invalidate the old entry or recompute through the existing observed machinery, match a wholly fresh computation and retain only current facts in that new capture. A registered provider revision change must refuse old-provider authority and use a genuinely new provider for the new computation, without rebinding an obsolete provider handle. Existing final source-authority checks remain mandatory.

For cancellation, use a genuine bounded original invocation and a narrower owned signal. Await its real publish and continuation before aborting. Test both first validation and repeated same-tuple fast paths; the original parent signal remains intact. The first failed validation must not cause a retry with the same maps to skip validation. An independent current receiver must still get complete facts after another receiver fails. No checkpoint may be replaced with an unawaited callback.

Closure outputs and mutable module/resource membership are outside this generic replay optimization and must remain unchanged. No selected owner cache sharing, singleton-composition feature or broader cache lifetime is part of this proposal.
