# Fixed Storage Birth Recovery — 2026-10-19

## Protocol

An unpublished top-level fixed image is never promoted to a published image and never deleted. Recovery runs under the original native-image exclusive lease and accepted cleanup enrollment. The ordinary shared probe reports an unpublished state and requests the writer path. The writer validates the exact finite two-entry envelope, complete fixed image allocation/footer, same-volume physical directory and empty mount, original parent/directory/backing identities, and inactive kernel association. It then retains the entire generation by an atomic same-parent rename to a deterministic identity-derived name. The retained generation remains available for inspection; a fresh generation follows the existing provisioning path.

No birth receipt is fabricated. Unknown directory entries, malformed/truncated backing, mount payload, mounted/associated images, symlinks, replaced identities, nested child generations and quarantine collisions are refused without deletion or activation. A crash before rename leaves the original unpublished generation; a crash after rename leaves the retained generation and an absent original path. This protocol does not require an authority-bearing birth receipt to be recreated after a crash.

## Native Windows Prerequisite and Honest Backend Boundary

The current NativeImageStorageV1 contract represents a finite mounted filesystem. Its image path, kernel-ex maintenance custody, physical capacity observation, child birth, borrower cleanup, canonical platform registration, retirement and cache-store wrappers all depend on that real filesystem enforcement. An ordinary host directory cannot satisfy that contract honestly. Windows VHD mount requires an appropriately privileged process/host service; the current Codex desktop token does not have it. Linux similarly requires CAP_SYS_ADMIN; macOS uses its existing native backend.

A future unprivileged cache implementation needs a schema-first capability split such as filesystem-volume versus reservation-ledger enforcement, a first-party directory owner with genuine EX/SH lease custody and exact directory identities, journal-based pre-reservation, cancellation and pre/post physical usage audits, and separate truthful maintenance/retirement contracts. It can account for cooperative writes; it cannot promise a kernel hard ceiling against arbitrary native writers. This redesign spans RepositoryCacheStoreV1, NativeStorageBackingV1, NativeImageStorageV1 and canonical platform dispatch. Substituting a directory while preserving today’s kernel-ex/image facts would manufacture authority. No such substitution, environment bypass, synthetic receipt or fake volume was introduced.

## Scope and Failure Preservation

The recovery protocol intentionally admits only a complete finite backing with an exact inactive two-entry envelope and no published receipt or unsettled publication slot. Truncated files, preallocation crashes, missing roots, unexpected entries and active mappings remain in place and are refused. No historical creator identity is inferred from a directory name. This is conservative recovery of the proven complete-but-unpublished generation observed on this host, not a claim that every possible interrupted birth shape is automatically recoverable.

Windows uses the system MoveFileExW ABI with WRITE_THROUGH and without REPLACE_EXISTING. POSIX uses same-parent rename followed by a containing-directory fsync. The preservation operation is under the genuine accepted writer, with all physical parent identities and backing timestamps checked around the inactive observation. The retained name is a schema-bounded 24-character digest of original path and directory identity; an existing destination is refused.

## Pre-effect Windows Host Admission

Added schema-first host admission before the fixed opener's first lease acquisition and before unpublished-generation retention, directory creation, allocation, activation or formatting. Admission uses the existing authenticated Windows system snapshot and native runtime interface. OpenProcessToken reads the actual current process token, LookupPrivilegeValueW resolves SeManageVolumePrivilege, and GetTokenInformation reads a bounded complete native token privilege inventory. Missing/removed assignment refuses immediately with an actionable message that mounted cache requires the host privilege. An existing disabled assignment is enabled through the normal AdjustTokenPrivileges API and re-observed as enabled before admission. This changes no account assignment, requests no UAC/elevation and fabricates no filesystem capability. All token and DLL handles close on success and refusal. The implementation uses the already required Windows x64 Bun native observer runtime; it does not introduce a Node compatibility layer or broaden that backend's existing runtime support.

The execution agent reran the normal public `bun repo dependencies sync --scope .` command. It now exits with the explicit SeManageVolumePrivilege prerequisite before effects. `.cache/b/l` was absent before and remained absent afterwards. Retained generation names and count were exactly unchanged (two). Its captured log was `🗑️generated/execution/host-admission.log`; the execution agent/parent owns removal of that generated evidence after this durable report.

The host-admission suite was red before implementation because the actual gate did not exist. It now passes 2 tests with 86 assertions: eight portable native privilege-inventory cases compared against independent SQLite results and Ajv schema validation; six actual gate/native API lifecycle cases covering enabled, disabled, absent, removed, failed enabling and failed querying; real current-host negative native query; and extracted actual fixed-opener refusal proving zero lease calls and settled receiver bookkeeping. Disabled-but-assigned admission is validated, without pretending that this unprivileged host can provide a successful positive OS token case.

No new public executable command or launch target was introduced. The host test is imported by the existing native-storage-platform suite, which already has script/launch lifecycle registration. No generated host-test files were created; the earlier storage temporary directory was empty and removed.
