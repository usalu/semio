# Publication Directory Ordering Design Audit

## Current Algorithm

Actual W `captureNativeImagePublicationWitnessV1` retains at most policy.nameWindow=64 selected names. Each page opens the directory again, consumes its entire cursor, keeps the smallest64 names greater than the previous cursor by Buffer byte comparison, checks equal total census and then recursively visits the selected children. An empty terminal page still rescans. A directory with n entries therefore performs approximately n*(ceil(n/64)+1) cursor reads per census, before the second complete census. Its insertion work also compares up to64 selected names per candidate. This explains an algorithmic risk, not measured causal attribution for Tools.

The algorithm does not possess a kernel cursor guaranteed to enumerate byte-canonical order. Simply retaining the cursor and emitting native enumeration order changes the stream. Increasing the window, retaining all names, reducing observer cadence, omitting the terminal census, weakening equal-count/mutation checks, adding a prefix/hash surrogate order or extending work/deadline caps does not preserve the stated contract.

## Actual Existing Facilities

`artifacts/📤️publication/🟦️.ts` exports `stageOwnedArtifactsV1`, requiring the actual issued control and an accepted cleanup token of kind artifact-scratch with exact resource artifact:absoluteDestination. It delegates to `withArtifactSourceCaptureV1`; this API takes a complete ReadonlyMap of existing source paths, constructs full finite inventory maps/sets and captures sealed files. It is publication of known complete inputs, not an incremental run writer or disk-capacity reservation for directory sorting. Its cleanup enrollment reserves terminal ownership/time; it does not grant arbitrary storage bytes.

`artifacts/🏗️native-build/💾️storage/🟦️.ts` exports `acquireNativeStorageV1({policy,control,port,owner,kind,bytes})` and genuine `NativeStorageReservationV1` with allocation/backing/recheck/commit/retire. The API reserves before managed writes through the enforcing port and durable journal. It requires an actual retained storage policy/port/backing and Original-issued control; a witness cannot fabricate those from a path. Existing allocation kinds include artifact-publication. `readNativeStorageReservationPolicyV1`, reservation proof/control binding and cleanup ports preserve actual ownership. None of the inspected W/P witness signature supplies a scratch reservation/port. Allocating scratch inside the observed payload would itself mutate the witness and its journal, so it cannot be smuggled into the current read-only root.

## Feasible Long-Term Algorithm With Explicit Ownership Work

Use external byte-canonical merge sort under a caller-owned bounded scratch reservation outside the observed payload. Enumerate the real directory once in guarded windows; accumulate at most64 names, sort with existing Buffer.compare semantics, write a length-framed run, then release the name array. Merge runs with a fixed descriptor fan-in and a total live-name budget of64: a two-input merge needs only two heads plus an output buffer of at most62 names. Merge passes reduce runs until a single ordered stream is available; stream its names to existing visit recursion. This removes repeated native directory scans and has O(n log n) name processing with bounded memory and O(serialized name bytes) live scratch per merge generation. Use a checked scheme retaining no more than the reserved simultaneous input/output extent; a two-generation reservation is an explicit maximum, not unlimited temporary disk.

Persisted run records must preserve the same original strings and Buffer byte ordering, reject invalid names/duplicates, bound frame length and total bytes with safe arithmetic, and validate sorted monotonic output. Existing SHA implementation may validate run identity if useful, but hashes must never replace lexical comparison or exact content. No custom cryptography or runtime external dependency is needed. All actual directory/scratch IO, await, yield and callback boundaries retain issuance, phase, writer proof/root/ancestry checks and work charging. Ordinary exact descriptor ownership handles both inputs and output; all accepted operations drain before scratch retirement. Arbitrary primary errors, undefined/frozen values, cancellation and distinct close/retirement failures remain observable.

Each original census must separately enumerate current names, build its own ordered stream and retain pre/post directory identity and existing complete-census equality. Scratch is not a cache authorizing stale name reuse between censuses. Progress/cancellation occur within existing work windows. New scratch write/read/merge work must fit the existing unchanged total work and deadline; otherwise refusal is correct. Existing descriptor limits and name window remain fixed.

## Unresolved Integration

This algorithm is feasible but is not a drop-in edit under the current W signature. A first-party schema-owned scratch writer capability must be issued by a real existing storage owner before the read-only publication starts, with explicit backing, capacity, control lineage and accepted cleanup. The inspected owned artifact publication API cannot be used as a fake reservation or incremental run store. Exact cross-platform scratch placement/funding and whether existing publication metadata allowance can legally fund the required runs are unresolved. No new Native authority, host-temp escape, grant, cap, phase renewal or implicit SQLite spill is justified by the current APIs.

Before implementation, schema-first language-neutral schedules should cover wide directories, byte/Unicode ordering, duplicate/mutated census, run framing/short writes, exact reserved extent, every merge cancellation prefix and arbitrary primary/cleanup failures. Existing Python full-stream equality, independent SQLite order/arithmetic, real descriptor custody and strict gates must cover the actual implementation. A small existing benchmark is insufficient evidence for a wide-directory fix. This audit performs bounded Source reads only; no code implementation, test, compiler, Native action or timing run occurred.
