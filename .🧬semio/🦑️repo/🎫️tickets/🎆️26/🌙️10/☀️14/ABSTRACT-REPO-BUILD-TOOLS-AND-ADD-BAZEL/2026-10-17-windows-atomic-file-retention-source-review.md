# Windows Atomic Conditional File Publication: Existing Source Boundary

The existing Generic Windows relative owner does not expose an atomic swap-with-displaced-retention primitive. Its publishBinding replacement branch stages a directory link, opens the old binding, renames old→displaced, then new→original, then applies disposition deletion to displaced. That is an explicit two-transition gap and deletes the old link after qualification. It cannot implement the proposed conditional FILE contract, which requires one atomic public-name replacement while retaining the displaced regular file and its exact proof.

The current NT mechanics expose handle-relative rename and disposition, not an exchange operation. Rename-with-replace alone would unlink/replace the target rather than preserve it under a distinct owned name; capture-before or rename-old-first does not make the pair atomic. Parent/DACL/noShareDelete/handle fences improve custody but cannot turn two namespace changes into one atomic transition. Existing capturePreservation/publishPreserving/retainPreservation methods truthfully refuse on Windows before effects.

No ReplaceFileW or equivalent atomic replacement-plus-backup owner is currently implemented in this module. A new genuine system-backed implementation would require its own documented atomic/backup/failure semantics, rooted-name/parent lifetime and full native identity/security/stream/sharing/durability checks, with actual failure-state classification and NTFS qualification. This review does not decide that OS API's guarantees; Root owns primary-document investigation. Until that distinct primitive is qualified, Windows must refuse this new atomic FILE purpose before staging/effects rather than reuse the controlled-gap binding algorithm or silently weaken the contract.

The POSIX descriptor-relative exchange/NOREPLACE route is a separate existing mechanism; generic FILE capture is DATA proof under the actual live root family, not Core or Store authority. No Native/protected read, Windows DLL call or Source mutation was performed by this audit.
