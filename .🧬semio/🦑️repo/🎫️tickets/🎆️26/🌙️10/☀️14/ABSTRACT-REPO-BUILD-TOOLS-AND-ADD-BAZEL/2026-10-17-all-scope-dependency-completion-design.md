## Existing Receipt And Completion Boundaries

The ordinary private publishJavascriptBindingReceiptV1 constructs exactly {version:1,generation,bindings}, where generation is the full64-hex identity and bindings is the complete ordered Source/target plan. The closed bindings schema caps each path256 and the binding count4096; ProjectionPolicy caps receipt bytes4MiB. The writer uses a temporary exclusive file, file fsync/close, rename and parent fsync. It requires a genuine RepositoryCacheStore from the ordinary producer. The protected command must not fabricate that Store or call this writer through a structural facade.

The ready reader holds one nofollow descriptor, compares named/opened/final physical facts and exact extent, decodes UTF8/JSON and returns a physical+bytes fingerprint. requireJavascriptDependencyBindingReceiptV1 compares the exact full generation and every ordered binding. A ready receipt records a prepared generation plan; current Source links independently prove activation. It is neither funding authority nor proof every Source endpoint already changed. Therefore a durable unbound generation can legitimately have bindings.json, while unknown/missing current links still cannot prove inactivity.

Core stageNativePlatformProtectedArtifactInputsV1 requires the actual retained whole-allocation token, quiescent maintenance scope, reserved actual chain and all selected roots absent before its first creation. Its returned empty opaque receipt is registered in a private WeakMap with the actual scope/owner, staged manifest, actual directory/file identities and input SHA. Fresh reads verify complete pre-installer rosters; input-only reads later preserve exact original input bytes/identities without claiming installed output qualification. The observation deliberately has installedQualified:false. Copied/serialized/foreign/closed receipts cannot regain that provenance. An old Probe directory is not a new staging receipt and cannot be adopted on a later invocation.

The current Probe stages all roots, qualifies fresh input rosters, installs sequentially, then performs input-only rechecks and the installed-path scanner. It produces no ready receipt and binds no Source endpoint. InstalledPaths.sha256 hashes path+kind observations; it is not a package payload-byte hash or package-edge target proof. Do not relabel it as full installed-content integrity. Current bounds cover256-unit paths, depth64, finite work/counts and physical nofollow topology; workspace export correctness remains a distinct required production step.

A prospective public entry such as produceRepositoryDependenciesV1(invocation,control,closedCurrentIntent) owns the entire all-scope operation and returns detached bounded results only. It captures exact current Source/ancestors/recipe before staging. Reuse the genuine current ownership progress helper without reducing physical checks. Internally, a private RepositoryDependencyPreparedAllScopesV1 WeakMap binds the actual Core input receipt, actual parent/token/scope, complete current all-scope roster, recipe/source/binding SHA, full generation/root mapping, each qualified result and each ready-receipt expectation. A caller cannot author that object. This is process-local phase control, not a persisted historical capability. A separate private all-ready phase is minted only after every receipt is durably verified. Neither private phase escapes through a generic callback.

Factor a single pure canonical receipt encoder from the existing ordinary receipt shape: javascriptDependencyBindingReceiptTextV1(fullGeneration,completeOrderedBindings) -> closed text/byte-count/SHA DATA. ## Is A New Core Writer API Needed?

On the qualified POSIX path, the existing generic relative withNewFile is mechanically sufficient for a fixed first-party ready writer: it performs exclusive absent-only creation, bounded contiguous64KiB writes, actual file sync/close, named recheck and parent sync under the shared32 registry. The ready suffix is fixed bindings.json within only this operation's privately proven fresh roots. No overwrite, temp-name fallback or old-ready-receipt adoption is needed. Existing generic filesystem capability alone grants no Native authority; the private fixed Repository owner supplies the authenticated purpose and retains actual parent/token/Core input completion/gates around every effect.

Use Core input/row rechecks at quiescent boundaries OUTSIDE NativeRead callbacks, because completion reads reject pending scope work. Enter a short genuine protected read callback only to retain the real physical custody checkpoint during the private fixed filesystem write; no writable port is derived from the readonly context. Close/drain that read frame before the next Core completion/full-row fence. Preserve cheap genuine control/held-gate/physical checks per IO and complete raw journal/row checks before/after each receipt, at all-scope barriers and on failures. No one-time observation becomes future authority.

Accordingly, do not add a receipt-specific Core data API merely to bypass the genuine Store requirement: it would duplicate physical ownership while Core cannot establish Dependencies readiness. If the common platform owner later requires all Native writes behind its private actual-root kernel, a byte-only continuation tied to the same live Core input receipt is the narrow alternative, not a writable callback: closed one-file-per-issued-root metadata, absent-only names, bytes/hash/combined path caps, private root identity, quiescent chain reservation, durable readback and a private physical completion. It must still report installedQualified:false and cannot decide semantic readiness. That alternative is not implemented or currently required for the qualified POSIX seam.

Windows remains a separate release gate. The generic ordinary-root constructor intentionally rejects a mapped Native reparse root; a string read.root or detached current token cannot upgrade it. A genuine canonical Native handle/root anchoring solution is required before this whole producer is cross-platform qualified. Adding a receipt API without that actual anchoring would only move the same missing proof. NT privilege/sharing/reparse/durability and Source controlled-gap reader coverage are not established by Source model success. No fallback wider sharing or fake root is proposed.

## Fixed Transaction Protocol

1. Before effects, validate the entire closed current command, actual all-scope ownership, unique full-generation/prefix mapping, every final256-path, bounded receipt encoding and every target declaration. Refuse if any root already exists, including previous Probe roots. Preserve unknown current content.
2. Acquire and retain actual parent/whole-row token/global EX/ALL custody. Capture Source inputs/leaf+ancestor CAS and exact whole receipt/raw journal; stage the complete fresh Core batch under its actual opaque completion.
3. Install each scope using the canonical shared recipe/program/environment and real granted child controls. Recheck exact immutable inputs, Source and actual funding around each child. No receipt or Source binding is published after a failed child.
4. Apply genuine current workspace-export/link fixups before readiness. The current hoisted codec must stay consistent; a prospective isolated recipe needs its own qualified complete package-edge rewrite (Bazel's research shows top-level fixup alone is insufficient). Do not change linker/config under only protected argv.
5. Qualify every complete installed scope under the existing256/depth/count/work bounds after its last output/export write. Once all scopes qualify, replay all current Source/recipe/Core input/funding guards and record the all-qualified barrier. A late scope refusal leaves Source bindings0.
6. For each exact fresh generation, mint/read the canonical ready bytes privately and create bindings.json exclusively with generic relative ownership. Fully flush/close/reopen/readback the file, validate exact generation/ordered bindings and compare bytes/SHA. Keep all paths<=256. Any collision refuses; no existing file is overwritten.
7. After every scope's receipt is durable and complete, repeat Source/Core/all-scope output qualification. Ready receipts themselves add a path, so the final installed-path scan includes them and every final binding target. Then mint the private all-ready phase. All receipts must precede the first Source transition.
8. Freshly compare every prior Source leaf/ancestor and every prepared target while the same gates remain held. Publish sequential bindings using the strict missing/link kernel, or the separately authorized ordinary-payload preservation primitive if that exact current endpoint requires it. No implicit file/directory adoption or target follow exists.
9. Re-read every ready receipt, every actual Source binding, immutable inputs/recipe, unrelated ALL Source ownership, whole receipt/current raw journal/row and final qualified roots. Update only exact privately witnessed own Source/capsule deltas; never blanket-recapture ALL state or adopt foreign changes as a fresh baseline. Only then return a detached completed result. Do not retire the whole charge or pending publication.
10. Partial failure retains every new generation/ready receipt/preserved opaque entry and any already-published binding. Save bounded current failure DATA, preserve arbitrary primary plus every distinct drain/close failure and abort the issued helper scope before Root0 drainage. No blind retry/rollback or fresh Original renewal occurs.

This is not an atomic all-Source-name transaction. The global EX serializes cooperative guarded consumers; strict readers must refuse a mixed/incomplete scope after a failed partial publication. Unleased bootstrap/test readers remain a separate reader-coverage issue; POSIX ordinary-payload preservation should use the atomic exchange proposal, while any Windows controlled gap remains unqualified until that issue is closed. Ready receipts never convert partial Source publication into a successful all-scope result.
