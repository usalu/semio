# Native Storage Event Extension Risks

Read-only current schema/projection/transaction/checkpoint review. No runtime, store, journal or receipt effects. Prefix S denotes PROCESS/📦️artifacts/🏗️native-build/💾️storage.

S/🧬️schema/🔣️.json Event currently permits reserved, committed, retiring, retired and checkpoint only. State retains version, sequence and allocations; each allocation retains id/owner/kind/bytes/phase. S/🟦️.ts:32–46 validates complete state/event, capacity, duplicate identities and transitions, then increments safe sequence exactly once. A rebudget event requires an explicit projection branch before generic phase transition; falling through would incorrectly assign event type as phase. It must enforce exact old identity/owner/kind/amount/eligible phase and old sequence/layout precondition, safe arithmetic, unchanged physical capacity and new complete-state capacity.

Critical checkpoint property:83–90 replay/checkpoint replaces history with checkpoint{state}. Current state contains no old amount or layout provenance. Event-only evidence needed for derived receipt recovery disappears on compaction. Either retain required canonical provenance in State or make recovery depend deterministically on authenticated current allocation/layout, with an explicit compaction recovery law. Do not retain unbounded event history as a workaround. Checkpoint preserves sequence, held and retiring charges and is accepted only at empty journal start.

Transactions obtain native-storage:<backing.identity> EX after backing recheck, replay bounded journal and append synchronously with fsync. Optional checkpoint runs before event append at byte threshold. One appended event is durable even if later cancellation/receipt publication fails; error return cannot imply rollback. Recovery must reobserve committed state and repair derived receipt under exact custody rather than append duplicate transition. Torn/oversize journals remain owned-recovery refusals.

HeldReservation:97–98 captures allocation.bytes and recheck requires exact amount. Whole-image EX must exclude old handles before transition; reopen fresh reservation afterward. Existing transaction finally directly releases lease; new operation must not let cleanup replace arbitrary primary or claim a failed durable append was absent. Actual control/Original checks around awaited backing/lease operations remain required.
