## Final Contract and Scope

Actual fixed Linux/Windows, temporary macOS and retained macOS ports authenticate the exact captured backing, retain their actual borrower, check actual descendant control, perform the host barrier and recheck. Native storage calls the injected port and has no new runtime import of the platform dispatcher. High owns the journal transaction and derived Products receipt integration; this lane only changed the neutral interface, ordinary refusal and forwarding wrapper in that shared owner.

The platform metadata capability is privately issued only after exact platform WeakMap authentication and a factory-registry-backed actual backing observation. The registry retains the actual factory lease directory; no synthetic lease policy field is invented. Tokens bind the returned actual phase, close births before drain, reject copied/closed tokens and controls, and permit one pending barrier per image. Overlap is a synchronous pre-admission refusal, not a queued serializer. The first failed barrier, including undefined, closes further births and remains the exact failure. Body primary wins over a concurrent secondary barrier failure. The ordinary accepted-operation ledger remains authoritative in real execution; the explicit physical Source model does not prove that ledger or Windows process behavior.

State record writes and directory preparation/completion/rechecks consume this capability as a mandatory argument. Parent intent/binding writes run within the parent metadata lifetime. Child data/body/recheck/task drain uses the child callback's returned actual phase. Child metadata scope drains before `image.close()`, preventing a self-drain cycle. Read-only decoding remains independent of metadata authority. The old platform allowlist was replaced by the declared mandatory capability/backend contract; no Windows directory FileHandle.sync equivalence was asserted.

## Windows Boundary

The exact privately retained VHD → one local nonboot/noncluster writable online disk → one partition whose AccessPaths contains the retained image root → one NTFS volume is resolved before and after Flush. Each mapping field must match the private original before Invoke-CimMethod. Numeric ReturnValue zero is required, and the bounded closed receipt must repeat the original mapping. The same actual control owns one system child and all process/stream/progress drainage. The backing, image receipt, root, filesystem size and bounded root→target physical directory dev/ino/nonsymlink/same-device chain are checked before and after that child.

Root and Low explicitly accepted root mapping plus this physical target chain as the containment proof. No `Get-Volume -FilePath(directory)` call remains: Microsoft's documentation states a file path and did not establish the directory case. No file probe is invented, and an empty newly created child root still requires its real barrier. No query uses the backing VHD file as though it belonged to its child volume. UNC paths and descendant aliases are refused.

Microsoft's [MSFT_Disk contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/storage/msft-disk) explicitly declares IsBoot, IsSystem, IsClustered, IsReadOnly and IsOffline; missing or non-false exclusion facts refuse. The method and privilege evidence is retained in [the proposal](windows-state-metadata-port-proposal.md). Actual Windows provider availability, privileges, root mountpoint/reparse and Node device semantics remain unqualified. Existing hardcoded Windows system-root and Hyper-V provisioning limitations remain separate follow-up work. No automatic elevation/service/privilege grant, runtime dependency, external API type, quota/cap increase or migration was added.
