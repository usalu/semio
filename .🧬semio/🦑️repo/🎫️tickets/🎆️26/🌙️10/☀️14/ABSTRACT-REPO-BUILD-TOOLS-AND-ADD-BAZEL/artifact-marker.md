# Framework Artifact Marker

The framework-owned publication filename is now `.semio-artifact.json`. Its version-one metadata remains `{version,owner,files}`. The publication fixture schema requires the exact filename through `markerFilename`; its positive fixture declares that filename, and the test rejects an alternative. Publishers, browser and native consumers, activation freshness checks, Vite snapshots, path exclusions, fixtures, and directly related messages use the neutral name. Genuine private Nx SDK contracts remain unchanged. There is no old-name fallback, alias, migration script, or automatic product repair.

The changed source inventory is `📥️artifact-marker-files.json`: 40 edited authored files, plus the separately coordinated marker literal in the core owner's `build/📜️script.ts`. No source was moved or removed. No new permanent executable was introduced; the existing artifact-publication suite exercises the new fixture.

The schema and regression preceded the publisher change. The red Nx-exec run failed when Python independently attempted to read the required new marker from a directory published by the old implementation. After the rename, the same retained ticket harness completed successfully through the installed Nx task runner. It ran the full artifact-publication regression, including lease contention, cancellation, replacement, rollback and byte preservation. Its Python oracle verified the actual new marker's version, owner and exact sorted file list.

The focused consumer proof then published the same portable fixture with the actual `stageArtifacts` implementation and passed its output to the actual `copyBrowserArtifacts` consumer. The consumer copied both declared files, preserved their bytes, excluded the marker from distributed payloads and refused a foreign owner. AJV admitted the produced distribution metadata and rejected the reserved marker filename as a payload path; fast-glob independently agreed with the complete copied file inventory. Console evidence recorded the new marker and both files. The red and green command outputs are temporarily retained under `🗑️generated/artifact-marker-{red,green}.txt`.

Two source audits found no remaining old marker reference in current authored files: the scoped ripgrep audit and a tracked-content Git grep with filesystem monitoring disabled. A separate tracked-filename query found no tracked actual old-marker asset. Historical ticket evidence and ignored generated products were excluded from source rewriting.

The broader ignored-output scan also encountered unrelated scratch products and was stopped; it is not presented as a complete generated-product inventory.

The explicitly authorized one-off asset repair subsequently renamed 97 individually validated mutable product markers, including all six products above, six canonical published CLI executables, 74 TypeScript artifact outputs, two font outputs, three Vite outputs, two Surface WASM outputs and four pinned tool wrappers. Every operation used the current publisher's original exclusive publication resource in `.cache/framework/leases`, with zero wait so an active holder would block mutation. Marker JSON bytes and file identity were preserved; complete payload before/after SHA256 witnesses matched. No payload was deleted or republished, and no migration script was created. Exact old/new paths, source-owner proofs, leases, marker digests and payload witnesses are retained in `artifact-marker-assets.md` and the inventory's `assetMoves`, `assetCreated` and `assetRemoved`. New absolute marker paths were admitted before rename; their maximum is 181 UTF-16 code units and 179 Unicode code points, within 256.

The bounded current-workspace scan and selected private product inspection found 400 candidates. Profile-qualified old browser owners differ from the current owner; retired native output paths do not establish current publication custody. Three old dashboard wrappers have owner `dashboard-installation` and unqualified digest paths, while current source uses `dashboard-installation:<mode>` and mode-qualified paths. Their bytes match their historical digests but their owner/path mismatch remains unadopted. Actual Nx result snapshots, compiler state, unrelated validation outputs and other chats' scratch copies were classified separately and preserved. Exact observed paths are retained in that report; the broad private-state scan was incomplete and is not claimed exhaustive. No compatibility behavior was added.

The actual Tectonic toolchain and current TeX bundle readers admitted their repaired products. The actual native pin publisher reused the repaired digest product without replacing its marker or payload. Pinned executable and current bundle/toolchain checksums still match their authored identities; marker metadata remains outside those payload identities.
