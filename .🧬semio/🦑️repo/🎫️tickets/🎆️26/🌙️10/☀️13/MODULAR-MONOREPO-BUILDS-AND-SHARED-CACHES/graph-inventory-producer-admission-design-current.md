The outer fixed image cap limits physical growth but does not make this a usable producer/consumer contract.

Add closed lock-inventory capture there. Exact serialized UTF8 JSON bytes must fit the existing metadata bound as well as raw filename bytes: quotes/backslashes/control escaping and JSON framing can exceed a raw filename sum. No budget increase or source fallback is appropriate.

Actual compactSourceInputs must capture and bound the complete deduplicated roster including hashing helper files before requesting a writer directory or publishing. cargoLockInput must capture its own exact manifest contract before those operations. The common helper, its policy, exact reader and digest/lock behavior must participate in actual compact Source helper inputs and implementationRevision authority so later helper-only edits invalidate warm graph inference and task hashes. Shared Source may change; inventory and qualify exact observed files rather than assuming an atomic edit lock.

Schema-first neutral source/lock/path/extent vectors, Ajv, independent SQLite JSON projection/UTF8 lengths and actual consumed Source ordering laws should reproduce the missing producer admission before editing production. Exercise the pure actual shared helper positively with ordinary DATA; do not fake a genuine Native writer to run a positive publisher. Existing exact real filesystem reader laws, descriptor/phase failures, quota identity and full strict roots must remain. Strict flags and private physical capacities/floors cannot be relaxed. All evidence belongs to this ticket and every Bun parent/child is born with its bytecode caches disabled.

This is a prerequisite for predictable metadata growth and later coupled retention.
