## Defining Native Boundary Now In Source

The actual NativeStoragePort requires withJournal. Storage custody invokes it around the actual journal EX transaction; all three actual backend ports implement it. Mac/Fixed backend physical parent observations retain the same real mapping SH. Funded preparation captures original child EX/proof/cleanup loan first, then actual parent mapping EX/loan, retaining it through reserve/creator effects/receipt and actual reader handoff, releasing before the consumer. A failed mapping release remains privately retained and cannot authorize journal retirement.

Mac and Linux parent observers authenticate every mounted descendant through the complete actual parent journal child request, recorded namespace, original creator sidecar/underlying m identity, exact receipt/inode/size/cap and actual kernel association. Linux no longer waits for descendant kernel SH while holding a parent journal. Descendant mapping SH brackets recursive observations instead. No synthetic provider/store or Native registration was added. The generic mapping lock token proves only its real SQLite exclusion; the actual private backend still supplies Native authority. The resource selector hashes the stable root namespace so the same context/image generation reuses metadata; exact literal root/lease directory/existing backend identity remain required inside the private held scope. A path selector does not grant Native authority.

Fixed canonical backing identity includes platform + backing inode/size + actual kernel mapping; Mac includes backing inode/size + mounted root device. A transient mismatch introduced during this edit was corrected before qualification; new neutral AST/SQLite identity laws bind all three actual acquisition consumers per backend to the defining constructor formula. No Native runtime was used to qualify this correction.

Unknown desktop peer protected-parent work stays attributed separately. Its read-only nonwaiting parent EX API is not a producer mutation port and is not called while our own parent SH is retained. Unfunded disposable APIs outside the opaque compiler-state consumer remain outside the claimed producer cohort; this cut does not claim every arbitrary Native API can overlap safely.

## Actual Enforcing Child Lifetime

Use a separate genuine persistent Native child for each full context directory. Retain that child's actual kernel EX through compiler execution and all accepted descendants. This provides exact same-context read/write/retirement exclusion while other context images have distinct kernel resources. Initial and final complete child FD censuses remain real backend operations; no whole state-image EX surrounds ordinary producer bodies. The immutable private Core tuple binds context, content, one pre-wait attempt nonce, entry revision, original Native allocation/request, current policy and actual receipt/backing. Cwd m/w, incremental m/i and output m/b/p/units/<attempt> all live inside that exact Native child.

Inside child EX: authenticate the child-local bounded binding and inner workspace reservation, capture original cwd/output identities, mark dirty before compiler effects, expose only the existing opaque Core/Rust loan, seal/join accepted compiler/Source/receipt copies, retire result scratch, validate/remove only original scratch, measure incremental and sync the child-local sealed binding. Then return from actual maintenance and child factory so real child kernel/open-lifetime closure completes. Only afterward acquire short catalogue EX and CAS this entry's exact context/content/attempt revision/native allocation binding before marking clean. Other entries/global sequence may advance. This keeps clean commit after positive actual owner closure; callback absence is never a completion proof.

A close/failure before that last commit leaves dirty/unknown custody. Complete dirty images may be discarded only through the genuine existing whole-child retirement chain, never reused. Incomplete or unknown births retain their charge and intent. No same-operation budget renewal or rollback is introduced.

## Pressure Order

Hold request context EX, but never wait for another context. Snapshot/select under short catalogue EX, release it, then try the exact victim context queue nonwaiting on its existing real resource. Busy candidates are skipped. If the candidate is the already-held request context, reuse the same actual private producer scope instead of reacquiring. Reread/CAS the exact entry after obtaining victim queue; global sequence drift alone is permitted, entry revision drift restarts bounded selection.

Persist exact retiring intent, release catalogue EX, recover the real committed Native reservation from the same actual parent journal, invoke retireNativePlatformFundedChildStorageV1, await genuine child EX/FD exclusion, private sidecar/request/physical durability, actual child kernel/reader closure and parent journal discharge. Delete/reuse the catalogue slot only after successful canonical return. A thrown result retains unknown intent even if late retired bytes may already replay retired or final retained-parent close follows discharge. The CLEAN retirement correction is preserved without claiming rollback.

Do not hold catalogue EX while acquiring child kernel EX, mapping EX, or waiting for another context. Do not hold an active current producer child during pressure. Actual order is context EX -> short catalogue EX (released) -> child kernel EX -> parent mapping EX -> parent journal when needed. Ordinary parent journal order is mapping SH -> journal EX, with no descendant kernel waits. No whole-parent image EX is requested while our own parent SH remains. Whole-image EX is limited to actual quiescent outer creation/retirement after own views close.
