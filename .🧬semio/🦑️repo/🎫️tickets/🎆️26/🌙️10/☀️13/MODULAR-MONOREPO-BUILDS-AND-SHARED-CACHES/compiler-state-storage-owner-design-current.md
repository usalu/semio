# Compiler State Storage Owner

The actual Core compiler-state materializer currently accepts arbitrary root and lease-directory DATA. Its issued effect control authenticates process authority but does not establish that the mutable state is inside an issued, bounded Native allocation. TypeScript project commands still supply unmanaged `.cache/framework` directories. This is a concrete storage-admission defect, independent of the physical Native qualification gate.

The replacement requires the actual Native reservation and its exact issuance control alongside the incoming effect control. Both controls and their inherited relation must be authenticated before reading path, environment or materialization DATA. The Native policy supplies the lease namespace; the caller cannot replace it. Root and materialized descendants are confined to that actual policy root. Compiler state retains a canonical accepted child and writer through descendant settlement; release must preserve an original thrown value including `undefined`.

The initial schema-owned admission law uses a genuinely received process Original, genuine controls, deliberately absent or forged storage, copied controls and a real narrowed invocation. Ajv and SQLite independently validate the closed case table. No forged reservation is accepted. The absence of DATA getter reads and filesystem effects is observed before assertions. This is refusal coverage, not a successful physical Native compiler-state runtime proof.

After the Core cut, actual Vite, Storybook, coordinator and distribution callers must carry their existing reservations and returned phases. A focused Repo TypeScript owner must open real dependency/product stores, derive its state root inside products and pass the actual reservation into Core. All existing project-check scripts must use this owner rather than free cache paths. No compatibility overload, storage adopter, new Original, replacement clock or new Native funding grant is introduced.

Physical cold/warm compilation, Nx hit/restore, bounded eviction, concurrent full-build throughput and native-platform qualification remain open. This report must not be read as a whole-repository size bound.
