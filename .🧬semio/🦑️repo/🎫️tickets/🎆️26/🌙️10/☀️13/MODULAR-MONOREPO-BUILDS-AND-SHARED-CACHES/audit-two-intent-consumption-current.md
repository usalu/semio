## Finding And Smallest Real Seam

`L/🏗️build/🎚️mode/🦀️profile/🟦️.ts::planCargoProfilePolicyV1` has no production importer in framework Source. It is DATA, explicitly `requiresConsumedView:true`. Its current manifest input preserves measured package rows from `dev` and `wasm-prototype`; deleting those tables first destroys its only authored constraint input. Its source digest includes the whole manifest and browser list, but does not itself cover schema bytes as a separately observed Source input. Its target/host settings are not automatically consumed by Cargo.

The narrow real integration owner is the existing repository Cargo inputs/configuration lifetime: `L/🏃️process/🦀️cargo/📥️dependencies/🟦️.ts::withRepositoryCargoInputsV1` → private `withRepositoryCargoConfigurationViewsV1` → `L/⚡️caching/💾️storage/🔒️enforcement/🏗️compiler/🚪️ingress/⚙️configuration/🟦️.ts::withRepositoryCargoConfigurationV1`. Materialize selected profile settings BEFORE its `cargo config get`, then keep that exact selected configuration through fetch, graph planning, actual compilation, receipt and consumer settlement. This is a scope, not another leaf planner or a mutable root-manifest rewrite.

The current callback returns only environment. That is insufficient: a role-specific generated TOML must enter actual `--config` arguments, and `admitRepositoryCargoStorageArgumentsV1` currently permits only the root `.cargo/config.toml` plus exact owned writer overrides. Extend the issued scoped view to carry exact arguments/configuration selector and provenance, and explicitly admit only that issued selector. Do not accept arbitrary caller `--config` paths. Existing immutable configuration code only freezes effective rustflags into encoded environment and retains the JSON observation; it does NOT freeze effective profile tables into actual Cargo input. `SEMIO_CARGO_CONFIGURATION_DIGEST` is evidence, not profile authority.

For several selections the current helper demands identical encoded rustflags and runs the callback with the first environment. Distinct role views must be separate actual invocations or have a selector per selection. A single scalar ambient profile environment cannot represent simultaneous native/browser/descriptor roles safely.
