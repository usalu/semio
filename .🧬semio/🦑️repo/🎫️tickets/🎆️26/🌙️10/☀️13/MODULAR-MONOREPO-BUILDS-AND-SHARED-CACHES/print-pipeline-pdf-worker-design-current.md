# Print Pipeline PDF Worker Design

The current pipeline Source retains actual compiler/material/Source/product custody and has no free PDF output/replay path. Its PDF.js operator/text readers and canvas rasterizer still execute in the parent test process. The already-authored gallery measurement worker does not qualify those algorithms.

Proposed finite extension: a domain-private worker receives only bounded copied PDF bytes and a closed job selector. It receives no Original, store, path, descriptor or arbitrary callback. The parent creates it inside the existing genuine Print task and funded scratch destination, holds the compiled probe or actual product reader through worker exit and termination, propagates exact carried cancellation, and joins termination before reporting failure. Worker termination does not claim to terminate OS descendants.

Inspection returns first-party readonly DATA: page geometry, finite text items and styles, and a bounded normalized operator stream sufficient for the existing carrier/paint assertions. Typed numeric arrays are normalized under a charged structured-DATA budget; unknown/accessor/cyclic/nonfinite payloads refuse. A separate fixed raster job takes a finite page list and scale, checks page and aggregate pixels before canvas allocation, caps PNG bytes and total output, destroys the PDF reader, then emits copied images. The parent writes images only to the actual funded destination and publishes the bounded evidence roster through the existing fixed products measurement slot. It does not accept output paths from the worker.

Preserve all current caption overlap, page bounds, scoped defaults, glyph, body paint, transformed D3 geometry and complete taxonomy assertions at their semantic boundaries. Pure assertions may run on actual snapshots; this is not a replacement oracle that fabricates PDF facts. Existing PDF.js/canvas types stay private to the worker. Page progress requires parent acknowledgement so expensive work cannot outrun the actual accepted parent scope.

Use the existing PDF input64MiB/pages512/text16MiB/worker256MiB guards. Additional explicit inspection-node/operator and raster-pixel/output ceilings must be authored in the same closed schema before implementation. No arbitrary worker-count option. The real store cumulative operation32 remains authoritative; a single worker per accepted call is not a global one-worker promise. Actual Bun worker resource-limit behavior and renderer/native allocations require later runtime qualification.

TDD: neutral JSON encoding/counter corpus with Ajv and SQLite, independent Node typed-array/JSON byte oracle, genuine real control with delegated event/exit/terminate interface, Error and undefined failure/cleanup precedence, cancellation, exact progress/ack, oversize/unknown data, and actual AST producer integration. No physical PDF, Worker, renderer, Native image or publication is authorized in this design step.


## Source qualification checkpoint

The authored worker is still unexecuted. Pure snapshot/raster DATA, PNG bytes/CRC/framing, affine math and delegated event-port lifecycle laws are qualified via the existing Source route. Both-mode CRC/PDF epoch totals were Core2/128, SDK6/40, Print41/558, shared120/1993 and default4/301 with expanded BOTH strict0. Subsequent intrinsic-byte and Source-alias corrections bring the latest prototype Source to Print42/564, shared121/2010; current final aggregate strict awaits unrelated moving compiler configuration callers.

Actual Node/Bun Worker behavior, PDF.js/native canvas allocation, termination latency, actual font/image semantics and complete command publication remain held. Six heavy native/family PDF consumers retain real compiled-probe custody but still execute PDF.js directly in the parent; their expensive-work isolation/cancellation is an explicit remaining caller frontier, not covered by the new pipeline worker.
