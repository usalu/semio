## Review Correction and Transaction Boundaries

Root rejected the initial proposal to mark eviction candidates producer-dirty: repeated interrupted removals would permanently occupy the eight slots. The implementation instead requires `retirement` on every slot (`null` for clean/dirty; exact `{dev,ino}` for retiring), preserves the original digest, and adds distinct pure mark/finish transitions. Retirement is preaccepted only for a clean digest-matching root or a previously durable exact tombstone. The planner schedules all retained tombstones before additional clean LRU victims. A partial tree may have changed digest/allocated bytes because removal progressed; that does not authorize a new root. Its persisted original root must still match, and the entire bounded remaining tree is censused again. No PID, age, owner-name adoption or Source-witness refresh is involved.

The slots namespace is enumerated with an explicit eight-entry limit and exact canonical numeric names; before/after parent directory identity and timestamps are checked across complete child observation. All catalog rows must have a corresponding observation. A missing row is accepted only for an already-retiring record with a completely null identity/digest/fingerprint and zero bytes. Unknown names, missing clean/dirty roots, mismatched clean digests, malformed records or replaced retirement roots refuse before mutation. All remaining material stays charged.

Allocated block totals count directories and each complete hardlink inode group once, using actual `blocks*512`; they are distinct from logical bytes and never treated as guaranteed reclaimable bytes on cloned/compressed filesystems. The final real child-volume statfs predicate must pass after completed removals. If physical free space falls short, the operation fails and does not claim a funded producer. The 1 GiB target is not a complete compiler peak bound. The fixed child remains the enforcing write envelope, and kernel ENOSPC/failed producer handling remains a required runtime gate.

The recovery function is private in the actual volume owner. It receives its control only inside the existing `maintenance` kernel-EX callback. The existing privately authenticated writer proof, whole-root FD inventory, unchanged whole-root recensus, receiver ledger and canonical accepted-work drainage remain in place. Pure plans/transitions are DATA only. There is no public deletion authority, exposed Native receiver, new registration port, or new control/Original. Per-victim fresh fingerprint/digest/allocated identity comparison precedes the existing exact numeric-path recursive removal; a tombstone is persisted before effects and removed only after actual absence. A failure at any catalog/remove boundary leaves the durable recoverable state and original charge; errors including thrown `undefined` still propagate through the unchanged private/canonical receiver ledger.
