## Automatic recovery protocol frontier

Inspection of canonical `withIssuedResourceOperationV1` and `withAcceptedPhysicalCleanupV1` confirms that an accepted rejected promise is recorded in every ancestor Original failure ledger. Catching a capacity Error after a snapshot/quote/image callback has rejected cannot create a successful retry under that same Original. No failure ledger reset, replacement Original, rebirth or deadline extension is permitted.

The clean implementation must therefore represent a pre-write physical capacity refusal as privately issued DATA, returned successfully through the active quote/reader/publisher boundaries. Its private issuance must bind the exact actual store, Original and required-byte observation. The publication job must never begin for such a result. Only after the entire tools SH and quote scopes settle can an outer pre-pin owner consume that exact refusal, run nonblocking whole-image EX retirement and make one fresh attempt under the identical Original and original deadline. Unexpected I/O, bad receipts, invalid custody, child failures and deadlines remain fatal errors.

This requires an explicit publication outcome API and coherent propagation through Nx provisioning and any prerequisite Bun/pristine publication, rather than pretending the existing generic publisher's `Promise<T>` can safely return a token as `T`. Ready reuse must bypass recovery EX. A competing active reader must preserve honest busy refusal. A genuine one-Original pressure→refusal DATA→retire→retry test must assert successful final Original settlement, not merely a resolved inner retry. This remains a design checkpoint, not implemented behavior; the actual current no-error maintenance proof above does not qualify automatic retry.
