Nx currently declares the aggregate products/play/<mode>/pages output and holds only artifact:<aggregate> for restore/put. That exact path lock conflicts with neither the Pages group nor its actual child artifact locks. A restore can replace content while a Pages reader is active, or interleave with several producer promotions and leave a tuple whose earlier receipt no longer matches. Later semantic rejection is useful but does not make the publication atomic or reader lifetime safe.

The selected correction puts one pure bounded canonical cohort contract in repository Nx output policy, consumed by both Pages and the Nx adapter. It describes the existing two mode roots, unchanged group resource, four families and final cohort member; it mints no lease, image or control. Nx derives matching cohorts from its actual declared output paths, checks actual Original mode, and acquires every group before its existing exact output custody. Cache put uses groupSH; restore uses groupEX, matching the actual producer/reader. Existing nonblocking Rust publication headroom remains after output custody, so this does not turn output-held admission into a global writer deadlock.

Nested operations retain private exact held group state. A held SH cannot upgrade to EX; a newly discovered group cannot be acquired after exact outputs are already retained. The shared contract removes duplicated group/path spellings, while generic framework Process remains unaware of Play-specific policy. Initial tests use a closed neutral corpus and independent Ajv/SQLite/Node path observations, including both intents, aggregate/member/descendant matching, unrelated output, wrong mode, canonical Windows/POSIX paths, immutability and ordering/refusal laws. Actual Native put/restore, cache payload semantic revalidation and platform namespace races remain separate acceptance work.
