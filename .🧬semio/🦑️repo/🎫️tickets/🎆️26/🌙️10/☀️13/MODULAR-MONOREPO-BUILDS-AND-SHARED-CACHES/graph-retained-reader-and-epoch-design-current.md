# Graph Retained Reader And Epoch Design

This is a Root design continuation after the bounded selected request and writer-identity reviews. It is not deletion authorization, implemented retirement, or Native qualification. Source-only tracing found these remaining dependencies; no cache/Native/compiler/network effects ran.

The fixed outer Graph image is the physical exclusion domain for mandatory input/lock inventories and their referring inference results. The funded Nx JSON/native pool is a separate nested image; its namespace lease alone does not authorize deleting outer records. The actual top-level Nx bootstrap and received main/executor wrappers retain an outer Graph store around their complete callbacks. Source/receipt adapters additionally require current private native namespace tasks. Their exact installed engine/worker/daemon completion and FD-close semantics remain runtime-unqualified.

The lower public exact Source inventory reader currently accepts a genuine issued phase without an enclosing genuine Graph store. The selected metadata reader likewise protects its descriptors and required phase, but ordinary fixture roots deliberately require no Native reader. Public reusable graph loading reads its pinned file before entering a graph fact writer. These are distinct from actual genuine SDK adapters and must not be assumed globally enrolled merely because paths or environment match.

A complete retirement must first separate ordinary Source/DATA observation from managed Graph inventory observation. The latter should require the existing privately issued store/consumer lifetime, with no new registrar, fake provider, public token adopter or authority inferred from a pathname. Existing generic store ownership/consumer ALS can authenticate and enroll exact live readers. A retained Native image must enclose every read and full hash-to-promotion interval; requested child controls alone do not supply image quiescence. Source-only positive ordinary metadata laws can remain beneath explicit ordinary DATA/descriptor interfaces, while actual managed positive Native laws remain HOLD until genuinely executed. Existing assertions must not silently disappear during that separation.

Coupled reset also needs a genuine owned finite generation record admitted by every referring cache: in-memory projectImages, disk inference headers and records, producer/publication/receipt records, canonical/selected graph authority pairs, snapshots where relevant, installed Nx graph/task-plan state and long-lived daemon state. A persisted epoch is invalidation DATA, never physical authority. Its update must happen only under actual whole-image EX after all readers and FDs settle, and the new epoch must be durably visible before any closure deletion. Interrupted cleanup then leaves old references invalidated, never an apparently valid warm result pointing at missing records. Unknown entries or incomplete ownership/protocol coverage fail closed. Native journals/bootstrap/guard identities remain outside the reset domain.

Per-key reachability is an alternative only with a complete reference index and genuine retained per-key reader ownership across the same producer/consumer set. Age, filename hash, current-looking reachability or absent OS observation alone cannot substitute. Whichever policy is implemented needs bounded inventory/parsing/work/path/physical-byte limits, progress/cancellation, original Error/undefined preservation, fresh recensus and optional-ledger reconciliation through the actual owner after deletions. It cannot start a new Original or clock to heal expired authority.

Warm reference admission must also cover both memory and disk paths: observeProjectInferenceV1 currently returns projectImages before disk observation, and observeInferenceComputationV1 can return a body whose compact tokens were not themselves part of source observations. Root's graph-inventory-producer-admission-design-current.md addresses admissible record production, not these dangling-reference or joint-retirement semantics. A required actual caller reuse predicate or fully admitted epoch can make stale results miss and recompute; cancellation/authority failures must propagate outside broad cache-corruption catches. Missing mandatory records must never become a successful empty scope.

No epoch, deletion loop, blanket reset, record removal or physical acceptance is implemented by this note. Full managed-reader coverage, current installed SDK/Native worker completion, finite reusable retirement, actual pressure/cold/warm/Nx restore/concurrency and platform behavior remain separate gates.
