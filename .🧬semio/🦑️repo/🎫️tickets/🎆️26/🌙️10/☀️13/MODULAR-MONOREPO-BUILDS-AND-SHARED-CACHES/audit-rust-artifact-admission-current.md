## Three Actionable Source Findings

1. **Persistent warm incremental is absent in the real direct compiler lifetime.** `C/🦀️cargo/📦️units/📜️script.ts:35` chooses a random funded workspace on each miss. `🏗️compiler/🦀️rustc/🟦️.ts` puts `-Cincremental` beneath its temporary directory. `🏗️compiler/🟦️.ts` refuses an already-existing funded directory and its `retire` removes both directory and temporary; the script calls `result.retire()` after publication. A cache hit can reuse the final rlib, but a Source edit cannot reuse that compiler incremental tree. Narrow next scope: implement a schema-owned persistent compiler-context identity, independent of Source content revision, and a charged managed incremental slot with exclusive per-context writer custody, compatibility checks, cancellation-safe release and physical retirement. Thread that slot through these exact compiler interfaces; keep final Nx rlib/receipt outputs separate. Do not merely move the current disposable path.

2. **Independent cold crates still share one physical writer exclusion.** The ordinary script wraps the entire compile/publication callback in `withCompilerWorkspaceWriteV1`. Its implementation at `C/💾️storage/🔒️enforcement/🏗️compiler/📏️capacity/🟦️.ts:17-33` reaches `withCompilerWriterCustodyV1`, which acquires an exclusive root-scoped writer resource and runs the body beneath it. Per-unit Nx tasks and `-Zthreads=1` do not remove this global serialization. Narrow next scope: implement actual bounded concurrent writer admission tied to original reservations and physical capacity/headroom accounting, then route direct rlib writers through it while preserving exclusive same-context/output custody. Retain the 16 GiB hard image and current global EX/4 GiB floor until that mechanism is proven; an EX-to-SH edit alone supplies no aggregate allocation authority.

3. **Full crate coverage and a unit-specific cache ceiling are not completed by the current supported path.** `C/🦀️cargo/📦️units/📥️descriptor/🕸️graph/🟦️.ts:19-24` explicitly refuses foreign Source and unsupported producer/profile/argument adapters, then propagates predecessor refusals. This correctly prevents invented full invalidation for registry/git/external-path dependencies, build scripts, proc macros and other absent adapters. Separately, `rustUnitNxProjectsV1` emits `{version,id,digest,mode,output}` cache metadata; `NxRustCacheExpectationV1` and `requireOriginalNxRustCachePromotionV1` carry no unit artifact limit and verify using the repository maximum. Direct compile capture enforces `unit.limits.maximumArtifactBytes`; current selected descriptors set that to the repository limit, so no present selected-path smaller-limit mismatch is demonstrated. Narrow next scope: first complete ordinary workspace rlib context/incremental custody from findings 1–2; preserve explicit unsupported closure refusals. If per-crate maximum managed size is required, author that budget in the schema, propagate it through descriptor limits and hashed Nx expectation, and enforce it at compile, put, incoming restore and persistent-context retention. Full unsupported producer coverage needs separate genuine compiler adapters and Source/dep-info/config/environment evidence, not a generic Cargo fallback claimed as direct rlib completion.
