## wasm-pack actual parser investigation

Repository native dependency provisioning explicitly pins wasm-pack0.15.0. Its [v0.15.0 build parser](https://raw.githubusercontent.com/rustwasm/wasm-pack/v0.15.0/src/command/build.rs) accepts a custom string via --profile; [Cargo forwarding](https://raw.githubusercontent.com/rustwasm/wasm-pack/v0.15.0/src/build/mod.rs) forwards that exact profile and trailing Cargo options. The [metadata selector](https://raw.githubusercontent.com/rustwasm/wasm-pack/v0.15.0/src/manifest/mod.rs) sends custom profiles to custom metadata. Both canonical modes therefore need --profile prototype|release at the wasm-pack boundary. Choosing --release would change editor/surface from existing custom optimizer arguments to their release metadata disabling wasm-opt. This investigation establishes tagged parser Source behavior, not installed-tool/runtime behavior. No compiler/tool probe, installation, store or image effect occurred. Historical0.13.1 lacks the custom parser; no compatibility path is being added.
