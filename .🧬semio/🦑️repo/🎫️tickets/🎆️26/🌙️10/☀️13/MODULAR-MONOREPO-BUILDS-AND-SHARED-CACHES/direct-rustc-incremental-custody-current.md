# Direct Rustc Incremental Custody

2026-10-16. Initial Source-only design checkpoint. No Rust/image/Cargo/download/SDK operation or fresh volume census has run. The completed context feature remains frozen at the hashes in `direct-rustc-context-implementation-current.md`.

## Current Actual Ownership

The actual unit Script holds `rust-unit:<output>` EX, then opens the actual compiler store and enters `withCompilerWorkspaceWriteV1`. That owner retains the existing root-wide `compiler-writer:<Rust root>` EX, exact live compiler allocation and actual4GiB initial headroom gate through accepted work. The compiler store retains its toolchain/tools and enclosing Rust image through inner private/canonical drains.

The compiler allocates a unique `b/p/units/<random>` output directory and sibling `.tmp`; the rustc port uses `.tmp/incremental` when the observed profile enables incremental. `compileRustUnitV1` result.retire removes both funded directories; the actual unit Script calls it after content-artifact publication. Therefore no incremental state survives even an ordinary successful compile. On compiler failure the current compile wrapper attempts retirement and retains its primary failure; that failure cleanup is not a new funded persistent-state settlement protocol.

The actual Rust partition maximum physical envelope is17,179,869,184B (16GiB), filesystem envelope17,178,820,608B, existing compiler allocation4,294,967,296B per mode, maximum final artifact1,073,741,824B. These are current schema-owned Source values, corroborated by earlier authorized observations; they are not a current available-space measurement. The existing initial-free4GiB test and journal charge are not a per-producer filesystem quota. Retaining a directory under them would not bound one rustc producer. Native fixed images supply the existing genuine hard filesystem primitive.

## Proposed Complete Producer Owner

Use ONE fixed Native compiler-state child volume for direct prototype rlibs, inside the actual Rust16 mount, with a finite per-context incremental directory pool and one transient producer workspace. Its hard filesystem includes incremental, out-dir, dep-info and all producer temporary output, rather than putting only the incremental path into a quota while temporary outputs can grow elsewhere. The existing global writer stays exclusive for every slot operation, compiler dispatch, validation and output handoff. The final content-addressed output/receipt/publication charge remains separate and is unchanged.

The candidate funding policy uses a distinct existing-journal4GiB compiler-state allocation, subdivided into a maximum backing file of4GiB−64MiB, a filesystem envelope one MiB below that file limit, and64MiB of parent metadata/control allowance. This is a candidate authored hard upper bound, not a measurement or a promise that every compiler fits. It preserves the existing1GiB artifact ceiling and4GiB workspace ceiling rather than introducing a tiny per-unit image cap. The full filesystem metadata and internal catalogue/warm/output/temp bytes share the one enforced child filesystem bound. Outer filesystem metadata still shares the actual16GiB hard enclosing filesystem. The extra logical allocation would fund genuinely distinct backing bytes; existing generic Cargo prototype/release charges remain intact and cannot be silently repurposed while their old outputs remain. No duplicate allocation for the child payload and its backing is permitted.

First creation requires actual outer available bytes for the entire new4GiB charge PLUS the unchanged4GiB writer floor before effects (and existing Native creation's own host safety predicate). Thus current previously observed~4.3GiB outer free does not fund creation. This design intentionally refuses until lawful headroom exists; it does not relax the floor. There is no physical operation authorized in this cut. On reuse, supported writes remain inside the already bounded child volume while the parent root-wide writer and original outer-floor policy remain held. Actual backend allocation behavior still needs a physical qualification before any claim of guaranteed frontloaded physical reservation.

Use eight schema-owned warm slots and one transient workspace, bounded catalogue entry/file/path/depth/bytes. Eight is retained-cache capacity, not concurrency or a per-key lock stripe: complete context keys bind one slot exclusively, lookups search the complete finite catalogue, and an unrelated key cannot alias a live slot. The unchanged global writer means at most one producer. Stable metadata context chooses reuse; full content digest chooses artifacts and records exactly which compilation completed. A miss may evict only a privately authenticated released slot under the complete actual owned lifecycle; unknown or ambiguous state refuses rather than adopting by name/age.

## Before/After Transaction

1. Authenticate actual Original, carried phase/refinement, genuine compiler reservation, existing live compiler owner and root-wide writer. Compute all paths from the actual backing; accept no output/cwd/environment pathname authority.
2. Recover or reserve the exact distinct durable compiler-state allocation before new physical effects. An intent binds allocation, actual parent root identity, fixed namespace and expected child geometry. Interrupted intents remain charged; they are never adopted from path appearance.
3. Open the real persistent child Native receiver while the parent image/allocation remain retained. Authenticate exact child receipt/backing inode/envelope and receive its real guard. A persistent mounted borrower never becomes creator/deactivation authority.
4. Under exact slot EX/global writer, validate the bounded catalogue and complete context binding. Retain exact slot/root inode and Native backing identity. Before compiler spawn, durably record the selected slot as dirty with the complete context and full current content digest. A clean committed slot can provide warm input; it cannot replace Source/dependency/receipt checks.
5. Dispatch only the existing real rustc under its actual CPU1 and carried control. Retain the child volume, slot writer, parent allocation/image, toolchain and dependency readers through actual child-tree/progress/drain and checksum validation. No persistent free path is returned to callers.
6. On success, hand complete outputs to the existing bounded content publication while the slot/volume remain held; validate final bounded inventory, clear only exact owned transient files, then durably commit warm-state facts. The state is not an artifact receipt and is not Nx cache identity.
7. On Error, thrown undefined, cancellation, deadline or unknown death, the preexisting dirty intent remains authoritative and charged. No canceled control is replaced. Any immediate cleanup requires a genuinely preaccepted funded cleanup scope, exact physical ownership and full accepted-child drain. Otherwise retain dirty state; the next genuine writer may retire it through the actual lifecycle. No age/PID guessing.
8. Reopen of dirty/incomplete/malformed contents cannot be a raw rm fallback. Authenticate its durable allocation/created root, exact existing Native inode and actual quiescence, then reset only that owned complete state under actual child maintenance EX, or refuse. If the binding/receipt itself is malformed or ambiguous, retain and fail closed.

## Unresolved Design Facts Before Source Effects

* Complete rustc write surface includes failure diagnostics, not only --out-dir/TMP/dep-info/incremental. Current dispatch cwd is the repository root. Moving cwd into the child changes an actual compiler input and may change debug/file semantics; keeping it requires qualified routing of every rustc side-file mechanism (including ICE output). No guessed RUSTC_ICE or remap flag is approved here. This must be resolved in the actual policy/context contract before calling the producer completely bounded. The finished context feature is not being silently changed.
* Actual independent parent allocation/child backend ownership needs a narrow first-party owner, not a public structural registration bridge. The genuine Native parent/control/image and exact reservation must be captured by the actual compiler owner; slots are opaque WeakMap-backed loans usable only under live actual operations.
* The existing Native journal kind set has no compiler-state kind. A new closed kind and its maximumWorkspaceBytes admission are needed if the separate physical owner is selected. Existing generic Cargo charges cannot be relabelled. All affected schema/type/parser/tests must migrate atomically without old-shape support.
* Actual free space has not been measured here; no reservation/funding claim is made. Pool entry counts/observed bytes alone are not hard quotas. The4GiB child and16GiB parent actual fixed backends are the proposed enforcing primitives.
* Native persistent create/open/close and interrupted preparation still require real host proof under an authorized bounded window. Linux/Windows require their actual closed backend qualification; Source interface parity alone is not a runtime claim.
