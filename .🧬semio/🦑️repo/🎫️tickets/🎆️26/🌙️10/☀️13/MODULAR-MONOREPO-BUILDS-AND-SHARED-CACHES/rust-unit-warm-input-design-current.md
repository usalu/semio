# Rust Unit Warm Input Binding Design

Root read the actual unit Script, exact Source reader and compiler receipt owner. RustUnitScript computes a bounded cfg-selected Source closure but does not consume its returned paths/digests/extents. The actual warm receipt return precedes compileRustUnitV1, whose entry is the only actual caller of verifyRustUnitInputsV1. A stale descriptor can therefore match a stored receipt even when newly observed Source differs; mere rediscovery/bounds admission is not snapshot identity. This is a Source finding, not a successfully executed Native warm hit.

The narrow correction will bind every observed cfg-selected Source/embedded path, byte extent and SHA256 to the descriptor source/generated input roster before Native partition opening. It will reject extra, missing, changed or duplicated source rows. Configuration/toolchain inputs continue through the existing exact physical descriptor verifier. Both checks repeat after the actual unit output writer wait before any warm receipt may be returned; a final exact verifier after output receipt capture protects against changes observed during output reading. No old artifact may be relabeled as a new plan and no automatic descriptor rewriting/migration is introduced. A stale descriptor refuses and must be freshly planned by its actual graph owner.

Schema-first neutral vectors cover unchanged/reordered, same-size edited, grown, added, removed, duplicate and embedded inputs. Ajv and independent SQLite incidence/digest comparison validate the same DATA. Source/AST observations must demonstrate actual Script call order and fail before the correction. Genuine ordinary filesystem tests use the existing received Original/control only; no accepted fake Native/provider/store, fresh clock or physical compiler effect is permitted. This correction does not establish atomic exclusion against arbitrary external editors or actual current Nx restore; actual input ownership and physical runtime qualification remain separate.
