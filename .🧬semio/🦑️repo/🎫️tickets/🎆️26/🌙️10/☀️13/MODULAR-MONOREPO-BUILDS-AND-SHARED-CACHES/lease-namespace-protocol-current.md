## Nested Resource Wait Refines The Protocol

Review identified a genuine design deadlock in the prior catalogSH-through-resource-acquisition proposal: A's body requests new B and needs catalogEX, while an A waiter retains catalogSH while waiting on A's resourceEX. The earlier preopened-fd proof alone did not qualify this nested case. That proposal is superseded before any canonical implementation.

Distinct active resources receive distinct slots; there is no hash striping or shared-live-key guard.
