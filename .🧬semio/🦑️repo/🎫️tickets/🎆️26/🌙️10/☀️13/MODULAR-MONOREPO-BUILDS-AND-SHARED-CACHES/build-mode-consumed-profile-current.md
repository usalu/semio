## Chosen Effect Design For Review

Use the current configuration receiver as the single owning callback for one sealed profile-plan record alongside its existing encoded flag view. It must be minted only after actual prebirth domain selection and an admitted physical read of the authoritative workspace manifest/configuration sources under the existing compiler storage/control. Retain that view, store, private toolchain, Cargo registry inputs, actual selected source boundary and all accepted child work until the final result consumer settles. Plan JSON, environment digest strings, a source path and recheck success alone confer no authority.

There are two distinct compiler effects; they must not be conflated:

1. **Supported selected direct units.** Compare every actual observed unit against the closed intent projection using real package, host/target role and declared target. Materialize an explicit complete, schema-owned profile argument record into its sealed descriptor. Direct rustc then consumes those exact private descriptor arguments and owned output paths, without reopening Cargo profile files. Check effective duplicate/conflicting `-C` flags before dispatch; profile and other rustflags must have one proved semantic order. Retain actual compiler/config/Source/receipt custody. New direct flags require narrow schema/argument/receipt changes and actual compiler parity tests, not broad allowlist relaxation. A manifest/config mutation during planning may cause an honest policy mismatch, but cannot change an already accepted explicit direct invocation during effect. Compilation of Source still uses the existing consumed-byte proof; this proposal does not replace it.
2. **Generic Cargo, including unsupported producer kinds and run/test/doc.** Cargo reopens profile-bearing manifests/configuration and computes host/target producer flags itself. An immutable profile config file plus hashing/rechecking mutable manifests is insufficient. The candidate bounded approach is a complete explicit sealed config projection plus an actual owned compiler-consumption receiver that validates the emitted flags for every accepted producer, its package/role and actual unit identity before invoking the real compiler. It must also account for build-script environment such as OPT_LEVEL/DEBUG, Cargo fingerprint identity, rustdoc, host proc-macro linkage, LTO's whole-link requirements and fresh cached artifacts that do not invoke rustc. A copied environment marker is not that receiver. Do not implement this as the current unissued default refusal script becoming an arbitrary executable wrapper, and do not override Cargo's real caller wrappers silently. If the actual receiver cannot authenticate a unit or fully account for its profile field consumption, refuse that profile integration rather than claim generic support.

The first path can qualify a coherent narrow supported subset before the second; the public two-name migration cannot be called complete while generic Cargo and wasm producers still lack their actual effect proof. This is an honest staged implementation boundary, not a compatibility API or legacy fallback.

## Why Explicit Config Alone Is Not Yet Sufficient

The pinned phase-one oracle shows only a base config opt-level overriding a base manifest opt-level. It does not show that a generic config value defeats a named-package manifest override; the same oracle positively shows named package beating build override. A sealed config must therefore explicitly represent the effective package constraints, not append one generic opt-level. Cargo package/build override tables also do not express all profile fields, notably LTO, so a fake target.profile or arbitrary per-target optimizer string is invalid.

A full all-fields config projection is a worthwhile smaller alternative only if the actual pinned Cargo oracle proves its behavior for base, wildcard, named package and build override simultaneously, across all admitted mutable input origins and both host/target roles. Even a positive precedence observation does not stop a newly read mutable named selector or plugin-specific profile field. A hostile mutation-and-restore between admission and effect must be tested against the actual consumer. Do not promise a filesystem cooperative read lease excludes foreign writers or a full Source clone is an acceptable solution.
