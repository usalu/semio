The internal `CargoGraphOperationsV1` owner enrolls each graph/input operation canonically before invoking it, using the actual transaction callback phase. The unchanged shared maximumPendingOperations policy bounds admission. It records first failure separately from its possibly undefined value, memoizes refusal and closes future births.

The actual driver wraps every unitGraphs promise with this owner. Disposal stops graph admission, terminates known direct children, joins every actual graph/input promise, then drains other tracked work, discards the session and closes timeline/broker/jobserver resources. Delayed input admission checks the stopped graph owner before spawning a new graph child; completed graph children check again before log publication. No promise-rejection observation is treated as actual settlement. Direct callback failure remains primary while every cleanup stage is attempted.

It then throws a distinct later failure, which does not replace the first failure. An attempted late callback performs zero effects. These are genuine Original/operation laws, not Native backend tests.
