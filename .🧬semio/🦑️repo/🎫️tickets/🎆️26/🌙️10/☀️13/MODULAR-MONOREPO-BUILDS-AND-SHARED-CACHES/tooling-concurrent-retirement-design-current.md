# Tooling Concurrent Retirement Design

## Decision and Scope

Retirement of an authenticated, released generation can coexist with readers of other generations. The current Source already implements a restricted version of this through registry EX plus candidate generation EX under tools image SH. The historical copied-generation branch deliberately requires whole-image EX instead: its material/inventory proof establishes ownership and physical contents, but does not establish that every historical managed reader enrolls in the current generation guard.

Do not remove that image-EX requirement merely because a copied receipt authenticates. A narrower historical path is justified only for an exact reviewed set of immutable opener implementations whose complete initial-load, child, detached-service and future-open behavior is proved against the same enforcing generation resource. Unproved versions remain eligible only for the existing quiescent path. Missing-material and unknown generations remain protected.

This document is a read-only Source design. No production file, guard, authority, test, process, lease, image, activation or cache data was changed. No publication, maintenance, Cargo command or physical census was run. The parent reported the latest capacity observation as 871,714,816 available versus 885,590,291 required, a 13,875,475-byte deficit, and a nonwaiting whole-image maintenance refusal after about 0.93 seconds. Those are supplied observations, not new measurements here.

## Does a Persistent Reader Pin All Retirement?

No. It pins **whole-image maintenance** while its actual image SH remains live. A service may keep that loan for its whole persistent lifetime; repeated nonwaiting image-EX attempts can therefore continue to refuse until the service settles through its authentic owner. An idle service, closed listening socket, absence of a process-name match, or stale witness is not permission to override that loan.

Normal retirement can still reclaim another authenticated candidate with the exact current reader-source closure and a free generation EX. However, after tooling/core Source evolves, old manifests often fail this exact comparison. The copied-format branch additionally requires quiescence, and missing material is rejected. Therefore persistent current readers can practically block the historical capacity needed for a new SDK without blocking every theoretically supported retirement path.

This is a completeness/capacity frontier, not evidence that image guards or the fixed 8 GiB envelope are defective. Increasing the image, lowering the quote, deleting witnesses or stopping another build is not the proposed remedy.

## Proposed Narrow Operation: Existing Committed Store Only

The long-term operation should own a privately issued **existing committed tooling-store** scope and retire only an exact released generation with a proved reader contract. This is a proposed domain boundary, not an API implemented or authorized by this report.

1. Receive the same actual Original/control; open the existing tools partition under its real image SH. Validate the exact same canonical root/device and enforcing image identity.
2. Recover the exact existing `repository:tooling-store` allocation from authenticated receipt and journal, require its phase to be committed and its finite bytes to match policy. Missing, reserved, retiring, ambiguous or mismatched state refuses. This operation must not create a receipt/allocation, commit a reservation, subdivide storage, allocate an image, unmount or retire the image. Do not reuse the present generic reservation helper without separating those effects.
3. Issue only private operation-local custody bound to store, workspace, image, reservation, actual control and lifetime. Public schema data supplies a request, never authority. Register accepted cleanup before the first await; close births and drain every accepted operation/failure before releasing any loan.
4. Retain actual `nx-tooling-provision` EX. Read/recheck the exact current pointer and its authenticated receipt. Preserve current unconditionally. Registry EX excludes current managed publication/activation while the decision is made.
5. For each bounded authenticated candidate, acquire the exact candidate generation EX **nonwaiting** on the same enforcing resource used by all admitted versions. A busy candidate remains charged. Other generations retain their SH normally.
6. Require a privately established, immutable-code-backed reader-contract match. Exact typed material/full-tree verification is an additional condition, not a substitute. Unknown or unproved historical reader closures refuse this narrow action and retain the existing quiescent-only classification.
7. Validate all roots, owned output roster, ordinary/symlink types, device/inode/stamps, complete consumed descriptor hashes and only authenticated binary/base hardlink groups. Retain relevant base SH through this inspection. Recheck complete rooted roster/identity and current-pointer/registry/control immediately before deletion. Preserve complete accepted-work drainage on refusal, cancellation and I/O failure.
8. Remove only exact candidate-owned entries. Then, if desired, invoke the existing separately guarded released-binary-object owner. Report actual physical free bytes after settlement. Stop once the actual required quote is funded; no public numeric minimum override or predicted reclaimed-size success.

This scope cannot repair unknown partial stages, retire pristine bases, mutate the active pointer, create a new compiler/tooling generation or authorize execution of an old implementation. Those owners remain separate.

## Immutable Old-Opener Proof Is the Prerequisite

The present `readerSources` equality is conservative but has a clear meaning. Replacing it with a small protocol number stored in a receipt would weaken the proof. A future finite classification must derive from independently authenticated actual old artifacts, not from a caller assertion or freshly written witness.

For every admitted immutable opener version, establish all of these facts:

- The exact generation identity is reconstructed from closed input bytes; marker, compiled program and authorizer output receipts hash-match. Bind the actual patch and every entry/loader implementation used by that generation. A Source manifest contains path/SHA evidence, not historical raw Source bytes; inspect actual receipt-authenticated bundle bytes or independently hash-matched version-history bytes where necessary.
- The actual lower lease implementation opens the same original enforcing resource/backend and canonical lease directory/inode protocol. Matching the string `nx-tooling:<digest>` is insufficient if an old implementation resolves another directory, uses another backend or does not retain the lock. Preserve the current canonical namespace/enrollment hold; do not rewrite old lock data.
- Before any generation executable/Native module or long-lived consumer is used, either an external parent holds exact generation SH through that initial load, or the actual entry acquires it itself. The initial byte-read boundary and fail-closed metadata exceptions must be explicit. A wrapper exported by the already loaded bundle does not prove pre-import coverage.
- Every accepted child, task executor, daemon startup, worker restart and persistent server retains either its own SH or an unbroken genuine parent loan. The parent does not release on readiness until the actual child acknowledges acquisition. On callback return, failure and cancellation, no detached consumer outlives the last loan.
- A future managed opener racing retirement must obtain that same SH before physical execution/use; while EX is held it blocks/refuses, and after deletion it fails before executable/Native use. A previously imported module must not resume later unguarded use from cached imports. Prove this with actual immutable version entry points, not a newly authored shim that merely imitates them.
- Module resolution through shared nonbinary hardlinks, optional/lazy package loads and binary-object references stays within the same lifetime. Current base/source index authentication does not automatically establish historical loader custody.

A classification can conservatively admit only reviewed content hashes while retaining all other versions. It is retirement-only evidence, not a compatibility execution API, migration or authority to modify those old artifacts. No such classification is qualified in this checkpoint.

## Lock Order and Dependency Ordering

Proposed narrower retirement order: existing image SH / committed store → registry EX → candidate generation EX (timeout zero) → required base SH → existing binary shard EX for independently eligible objects. Never wait for whole-image EX while holding image SH. Never wait for candidate EX under registry EX: an activating caller may hold registry SH and generation SH; a holder may also need publication work before terminal settlement. Skip/refuse and retain the candidate instead.

Existing ordinary loaded-use order can begin generation SH → tools image SH → base SH. This does not oppose the proposed image-SH acquisition, because SH is compatible; it does forbid a later image-EX upgrade. Current activation is registry SH → generation SH → base SH → activation EX. The retirement path must preserve registry-first exclusion and cannot acquire activation EX first and then wait for registry EX.

Deleting a derivative generation removes only its names/links. Its referenced base remains protected by exact snapshot SH; base eviction needs a separate snapshot-EX/dependent-reader protocol. Deleting an authenticated copied generation does not permit deleting sibling generations or missing-material roots. Released binary objects remain under their own shard and last-link protocol. A failed or busy candidate does not grant permission to scan arbitrary siblings more broadly.

Implementation order, if separately authorized:

1. Capture the finite actual historical entry/guard inventory and qualify old/future opener exclusion for a first reviewed set; leave absent/unknown versions quiescent-only.
2. Specify the closed committed-store request/result and private issued scope, including missing/phase refusal and complete drainage, before any production integration.
3. Qualify the narrower operation on an actual private image with real controls, independent SQLite/kernel observations and full content/roster oracles.
4. Integrate the same-Original pressure protocol so expected capacity refusal remains private DATA. Entire tools attempt/SH and accepted drains close before a genuinely different maintenance phase. Do not catch an accepted Error and erase its recorded failure or renew its deadline.
5. Run a bounded canonical preview/one maintenance only after proof and explicit coordination; report exact retired identities, protected identities, before/after free bytes and actual refusal. Then qualify fresh publication/callback/Native/ordinary behavior. None of those executions occurred here.

## Required Genuine Laws

| Law | Required observation beyond schema/corpus |
|---|---|
| Unrelated persistent reader | Real generation A service/worker remains active and serves work; candidate B retires under registry/candidate EX while image SH readers coexist. Exact A bytes/inodes and real response remain unchanged. |
| Same candidate reader | Each admitted actual old entry holds B SH; attempted B EX/retirement refuses with zero deletion. Independent Python SQLite/kernel EX attempt observes the enforcing lock, not just a public flag or file descriptor. |
| Future opener | Retain B EX, launch each real immutable old entry, prove no executable/Native/body-use marker occurs before SH. After retirement/release it fails without using removed generation bytes. Include a barrier before initial import. |
| Parent/service handoff | Pause between loader/import and own-loan acquisition; parent lifetime protects the gap. Parent callback return, worker refusal/restart, server-close-before-worker-exit and cancellation retain the actual last reader until terminal settlement. |
| Competing retirement/publication/activation | Actual registry conflict; no changed active pointer, stage mutation or two accepted retirements. Another candidate reader remains concurrent. All waits bounded by the same Original. |
| Reservation boundary | Missing receipt, unknown allocation, reserved/retiring phase, wrong root/device/control and forged/escaped scope refuse before any receipt, commit, allocation or deletion effect. Existing committed owner remains identical. |
| Content and namespace | Independent full-file digest/SQLite/Ajv corpus; wrong marker/material/program SHA, foreign hardlink, extra entry, replaced ancestor/file, symlink escape and changed roster refuse. Current/missing-material/unknown-stage/base entries remain byte/inode-identical. |
| Drain and failure | Accepted callback/cleanup returning early, ignored promise, undefined throw, cancellation, physical failure and late descendant all settle under retained actual loans; root Original still records genuine failure. Expected pre-write capacity refusal is DATA, not failure laundering. |
| Capacity result | Reclaim only authenticated eligible candidate bytes until unchanged actual target is funded; actual insufficient/busy results remain failures/refusals. No fixed-envelope increase or false success based on logical byte sums. |

These are proposed acceptance laws, not tests run in this read-only task. Existing historical generation inventory/copy tests and Source daemon fixtures do not replace the missing cross-version initial-load/future-opener laws.

## Protection Roster and Remaining Frontier

The earlier bounded format audit reported 24 generation directories: three shared-pristine, eight typed copied artifacts, thirteen with absent material. It authenticated metadata identities but did not establish all reader contracts or authorize deletion. Keep the thirteen absent-material directories, unrecognized formats/links/inodes and every unknown stage unchanged. Do not treat a crashed/stale/absent witness, process age, current inactivity or available PID as permission.

A narrower concurrent historical path is architecturally viable for proven versions and an already committed store. It is **not currently established across all historical versions**, so it cannot yet replace the existing whole-image-EX fallback. The first practical investigation is the actual authenticated outer loader/parent handoff and same-generation enforcing guard of the eight typed copies. If any member fails that proof, retain it; do not make the protocol universally permissive to recover capacity.
