# Owned Interactive Process Source Checkpoint

The existing actual Core capture owner now supports an interactive callback through an opaque private channel. There is no second launcher or public child/stream/provider constructor. A WeakMap authenticates the exact live token. Copied/retired tokens refuse before input DATA access.

The callback can enroll finite line reads and immutable text/Base64 writes. The closed policy allows32 pending operations,256 cumulative input frames and16MiB cumulative input bytes. Each frame also retains the existing canonical text/Base64 limits. Existing finite output limits remain capped at16MiB/65536lines; queued complete lines and incomplete tail stay inside the same output bound. A finite actual incoming control is required before effects. Command/cwd paths use at most256 UTF16 units, argv at most256 entries/65536 UTF8 bytes. All options/argv/input facts are copied before yielding. No replacement deadline or signal is issued.

Reads/writes enroll synchronously before effects. The first accepted failure stops new births and is retained with thrown undefined distinguished from success. Normal close stops births, completes pending reads with EOF, drains all already accepted writes/reads, then terminates/joins only its actual preaccepted process. Cancellation/error can terminate immediately while every accepted completion and actual terminal remain joined. The close capability authenticates only its existing private child scope and does not mint ordinary controls, paths, clocks or Native authority. The actual capture finally retires the token only after accepted channel work, input completion, process terminal and progress publication settle. The existing awaitOriginal helper now also drains an already started completion if its initial remaining-time check throws, before input buffers may be wiped.
