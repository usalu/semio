Scope is newly published canonical pristine bases; unknown historic patched snapshots remain outside any proposed ownership grant.

## Present frontier

`🧹️retention/📥️physical/🟦️.ts` 26–30 authenticates and retires only `nx/<generation>`, then released binary objects. It never enumerates or removes `sdk/<base>`. `📦️sdk/📥️source/🧊️pristine/🟦️.ts` 35–45 publishes canonical `sdk/<input digest>` bases, so these continue consuming physical capacity after all derived generations disappear.

The pristine receipt at 37 contains version, input digest, empty patches, and binary receipt identity. `requireNxPristineSdkV1` 31–32 checks that shape, recomputed environment/input identity, exact pinned input bytes, local dependency package versions, and actual binary links. It does not certify that every installed nonbinary byte belongs to a retirement-aware publisher or that all openers use an exclusion protocol. Empty patches and a directory name alone cannot grant destructive ownership. New bases need an explicitly published ownership/protocol receipt bound to their exact inputs/environment and live actual publisher/custody, followed by physical root/material reauthentication under retirement exclusion. Unknown bases must remain charged.

## Minimal truthful new-base contract

1. Publish the new ownership/protocol receipt only while the actual managed provision registry EX and tooling image are retained. Bind the receipt to the canonical digest, exact pinned inputs/environment, pristine disposition, binary receipt and the reader/retirement protocol implemented by its actual publisher. Recompute identities and verify bounded no-follow root/material, allowed same-device namespace and known binary hardlink groups before deletion. Receipt validation is evidence accompanying actual custody, not authority by itself. The existing generation retirement checks at `🧹️retention/📥️physical/🟦️.ts` 28–30 provide relevant conservative precedent, including unknown-reader retention and root rechecks.

2. Conservatively retain bases referenced by every retained authenticated generation's `.semio-sdk-material.json`, not only `.nx/installation`; that reference participates in generation identity (`📜️script.ts` 133–135). Active generation users hold `nx-tooling:<generation>` SH through work (`📥️use/🟦️.ts` 23–44), not base SH. A base-reference census must therefore use registry exclusion against generation publication and treat unknown/malformed generations as unresolved rather than declaring their bases unused. Generation clones contain independent files and shared binary links, so deleting a base is not automatically a running-generation byte dependency, but existing material inspection and pristine-transform paths can still read the referenced base. A conservative initial contract retaining all remaining references avoids inventing a weaker contract.

3. Acquire exact `nx-sdk-snapshot:<digest>` EX with nonblocking refusal for retirement; retain it through final authentication, root identity recheck, full unlink/cleanup, and observed storage recheck. All actual base openers must acquire matching SH before first receipt/path read and retain it through every asynchronous read/clone/child and cleanup. A returned base path alone is not a lifetime loan. Use bounded accepted-work drainage, as capacity quotation already does at `📦️sdk/🎟️capacity/📥️physical/🟦️.ts` 37–43.

4. Retire bases and then released binary objects under the same actual publication/capacity registry, before checking real available bytes and admitting the next writer. `🧹️retention/📥️physical/🟦️.ts` 36–44 already serializes and drains admitted publishers under `nx-tooling-provision` EX. Clone quotation retains source SH, authenticates physical facts, and rechecks actual statfs under registry EX at `📦️sdk/🎟️capacity/📥️physical/🟦️.ts` 27–30. Preserve this atomicity; a statfs number returned after registry release does not reserve capacity. Base logical/allocated totals are not guaranteed reclaimed bytes: shared binary links remain charged until their final real reference disappears; binary retirement independently requires exact shard EX, sealed ownership, content hash and nlink=1 (`📦️sdk/🧊️binary/📥️publication/🟦️.ts` 25–27).
