## Implemented Boundaries

The independent Core owner is framework/process/artifacts/native-build/⚙️configuration/🎟️admission. Its schema bounds raw effective JSON to 4 MiB, 128 flag sources, 4096 section entries, 16 levels, 64 KiB per source, 512 tokens and 4096 bytes per token. Every build, target, profile, build-override, package and known config-env flag source is admitted, including shadowed sources. Host configuration and target links overrides have explicit unsupported refusals. The receiver preserves authored native scheduling, wasm stack/memory/backend and Linux linker forms while refusing output, dump, emit-path, incremental-path, response-file, arbitrary linker/map and unknown options. Existing environment admission now uses this same owned predicate. The final selected direct-rustc argument allowlist is unchanged.

Core units/capture imports this receiver and calls it immediately after the actual config-get observation, before metadata, unit graph and compiler probes. Repository cargo/dependencies calls the retained view before registry fetch or lock resolution. RepositoryCargoInputsV1 and each additional selection now require a literal cwd; fetch and configuration observation receive that exact cwd. Updated actual callers include the generic launcher, runtime verifier, executable-test builder, repository Source admission, selected Rust graph, native orchestration relay, artifact producer, exact/physical fixtures and the OS plugin driver-stages batch. The plugin change adds cwd and the already canonical lease root; it does not redesign that separate build pipeline.

The repository configuration scope requires an authentic compiler-workspace reservation and Original control before any child. It runs the actual pinned Cargo config client with the existing default compiler-refusal entry armed, bounded capture and the issued private Rustup/Rust environment. A compiler probe during observation fails closed. It admits every observed flag source and obtains actual compiler cfg/host evidence, preserving explicit compiler/wrapper ordering. Exact native host target flags take precedence over build fallback. Matching target flag multiplicity, custom target paths and unsupported environment precedence are refused rather than guessed.

## Retained Consumed Flag View

The view is a SHA-256 addressed JSON record under the issued Rust backing configuration/<digest>/view.json. It is published under one fixed EX resource, has single-link no-follow bounded physical reads, and is retained under one of 64 deterministic reader shards. Original cancellation, authentic storage and record digest are rechecked before and after the result callback. An escaped view refuses recheck after settlement. Publication EX is separate from reader shards, so a batch cannot wait on its own retained reader when another view shares that shard.

Only admitted encoded rustc/rustdoc flags are projected into the child environment. Generic Cargo inputs and lock resolution retain all selected views through registry acquisition and the complete result consumer. Batch selections with different effective flags explicitly refuse; their consumers need separate compiler scopes. Initial profile/config-env flag views and CARGO_BUILD_*/CARGO_TARGET_* flag precedence also explicitly refuse until their semantics have an actual immutable consumer.

This is consumed *flag* custody, not immutable ownership of every Cargo configuration channel. Cargo still reads mutable cwd/ancestor files. The actual proof establishes that a later build.rustflags MIR mutation cannot replace the held encoded flags. Later config-env force/profile mutation and unrelated path/program/registry keys still need a dispatch boundary or complete immutable Cargo cwd/configuration execution view. No post-hash or advisory Source reader is presented as a substitute. Generic explicit wrappers, build scripts and custom programs remain outside an OS sandbox claim.
