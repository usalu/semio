# Scoped MCP Session And Wire Plan

The actual OSMCP Source owner still has six raw McpClientSession constructions in four files. The Core interactive successor is separate, frozen Source evidence in `owned-interactive-process-current.md`; no current raw consumer is qualified by it. The scoped MCP successor will remove the public raw constructor, carry the actual incoming phase, use that same private transport, bound request/notification state and stop/join accepted operations before returning from its callback. The request default inherits the actual phase (zero requested narrowing), and an explicit per-request budget only narrows it. No arbitrary timer becomes a new Original. A private derived cancellation signal can close the already accepted transport on a request failure while retaining the exact primary Error or undefined.

Schema-first immutable first-party wire DATA will be isolated from process ownership. The pinned existing MCP version remains2025-06-18; this work does not silently upgrade it. Its base rules require non-null string/integer request IDs, same response IDs, object results, exactly one of result/error and notifications without IDs. See [pinned MCP base protocol](https://modelcontextprotocol.io/specification/2025-06-18/basic). JSON-RPC identifies request/response correlation and distinguishes notifications; see [JSON-RPC2 specification](https://www.jsonrpc.org/specification). MCP stdio uses separate newline-delimited UTF8 messages and reserves stdout for messages, while stderr is diagnostic DATA; see [official stdio transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). These three references were actually opened during this Source cut; no search tool was used.

The closed selected wire model will impose4MiB/32depth/65536nodes/16384object entries, plain own-value input only, safe integer IDs, bounded method/error text and immutable snapshots. It is a bounded selected protocol surface, not a claim to implement every optional MCP extension. Schema/corpus and independent Ajv/SQLite/Node parser oracles precede implementation. No runtime third-party protocol package, fake accepted Native provider, Native binary launch or publication. Actual server/root/capability negotiation, six caller closures, generated/compiled binary custody and credential transport remain required work after the pure wire model.
