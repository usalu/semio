# Semantic Source Asset Repair

The previous actual prototype workspace graph reached registry generation and refused obsolete top-level byte bindings in committed semantic descriptor source assets. The current Rust describe producer already forbids those fields; accepting them in the reader would restore an unwanted old API. Sixty-three source JSON/pack pairs carried that binding. Localized source edits removed it, and the binary partners were encoded with the current owned pack codec while preserving integer and enum representations.

The canonical `@semio-tech/plugin-registry:test-semantic-source-pairs` gate walks declared owners, independently admits their language-neutral JSON assets with Ajv, and verifies each canonical binary partner with the semantic pair protocol. The physical initial red rejected flow-extension-bim for the forbidden hashes member. The current gate passed one test and 281 assertions in 18.76 seconds; its debug witness confirms seventy independently admitted source pairs. The actual prototype registry generation then passed, producing seventy plugin entries, 156 playground entries and ninety-six framework package entries. Nx reported 36.4 seconds including its generator-input prerequisite. This verifies current semantic source data and actual catalogue generation; it does not claim freshly compiled WASM for every plugin.

Prepublication checks caught existing Norm JSON/pack drift: the JSON held the newer north German lowland example field while the pack held its previous spelling, and their channel versions differed. Current authored examples were retained. Norm and host testing were the two JSON declarations still naming channel20; both semantic declarations now name current channel23. Component receipts and fresh describe still bind actual compiled bytes to the semantic declarations. No runtime artifact digest or freshness was fabricated.

All sixty-three final binary edits were strictly verified against JSON before publication, and source byte digests were checked again to refuse concurrent edits. No migration script or compatibility reader was added. Command evidence before generated cleanup: registry-semantic-source-red.log, registry-semantic-pack-edit3.log, registry-semantic-source-green.log, registry-generate-current-prototype.log.
