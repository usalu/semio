# Whole Cache Retirement Ownership Frontier

Read-only Root investigation of the current generic cache owner; no Native, lsof, lease, mount, image, compiler, deletion or quota mutation ran. The current production caps/floors, Native creator envelope and global publication HOLD remain unchanged. This is a design frontier, not an implemented retirement feature or a physical test approval.

## Actual Existing Ownership

The Core cache requires the actual canonical Native parent image, exact issued allocation/control/Original, complete matching parent policy, and the privately captured cache policy/context/content. It opens/rechecks a durable compiler-state parent charge, writes creation intent and immutable backing binding, holds the real child image, retains pending opaque borrowers, then closes accepted receiver operations before the actual child images. Its current inner pressure protocol retires only authenticated clean slots using a durable catalogue tombstone, recensus and actual OS descriptor exclusion. It does not retire the entire child volume, immutable parent binding or its parent allocation.

The canonical platform retirement operation already validates its exact real on-disk image receipt/identity and actual exclusive image lease; the macOS implementation detaches only the actual matching mount and removes only its validated image directory. That low-level operation alone does not establish that every inner allocation/receiver/configuration/consumer has settled or that the parent charge/binding can be removed. A path, policy DTO, receipt copy or new wrapper token cannot supply those obligations.

The corrected lsof parser explicitly binds NUL versus newline mode to actual argv, permits documented optional fields, and checks every complete file set against exact rooted guard ownership. Its 34 neutral records plus independent Python/SQLite and previous guards are documented in core-cache-descriptor-protocol-current.md. Root inspected its Source framing and optional-field behavior here; Root did not run a real lsof or claim physical descriptor completeness from the fixtures.

## Required Cohesive Successor

A genuine whole-cache retirement must be an operation of the actual existing cache owner. It must capture finite policy and exact binding/allocation/image identity before yielding, stop accepting borrowers, join all real compiler/input/write/reader work, and obtain the real exclusion needed by the child and parent owners. The existing open parent callback must not attempt to retire itself while its own reader remains live. No normal cache callback or caller-chosen directory may become deletion authority.

Retirement needs its own schema-first durable state binding the exact parent allocation, policy, child backing receipt and physical identity. Once this state is durable, later admission must finish or refuse that exact retirement before admitting a new cache; it must never treat an absent child with a live old parent charge as fresh uncharged capacity. Child workspace/capture allocations, child image teardown, parent charge retirement and binding/tombstone removal must have an explicit restart-safe order, with recensus at destructive boundaries and no unknown payload deletion. Every failure keeps an authenticated recoverable state rather than dropping accounting first.

Cleanup authority must be genuinely reserved at actual operation birth and retain the same incoming Original/phase. The current cache owner cannot merely obtain a new live control after a body Error/undefined and call low-level Native retirement; doing so would renew failed ownership. The accepted physical cleanup owner, its funded phase and its actual Native image/charge handoff therefore need a concrete canonical extension before a small ephemeral cache fixture can qualify teardown. A callback flag, copied issuer or private registrar is not a substitute. Single primary failures keep identity; combined real cleanup failures retain the exact primary as the first AggregateError member and every finite distinct secondary attempt.

The first physical consumer must use its own genuinely funded Diagnostics parent/child envelope with explicit cleanup reserve and full whole-cache retirement. It cannot shrink production four-GiB policy, lower the parent floor, reuse an unrelated image, or claim production admission from a small Source fixture. Until that owner transaction is implemented and independently reviewed, no such physical attempt is queued.
