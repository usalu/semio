# Task Qualified Catalog Admission

The owner registry schema now states the actual admission rule: a catalog provider activates for an observed existing selected task under a consumer root, an explicit provider Source input, or intentional all-owner selection. Importing a consumer's Source alone retains that owner and its actual files without activating its catalog.

The six portable vectors cover imported consumer Source, directly selected consumer task, declared consumer prerequisite, absent optional consumer task, explicit provider input, and all-owner selection. They run the actual closeBuildOwnerAdmissionV1 function and compare it with independent SQLite task/root joins and Ajv 2020 schema admission. The genuine first RED activated a provider for Source-only registry imports. The next RED exposed a missing optional task activating a provider before its owner facts were observed and the task pruned; activation now waits for the existing observed task. Native missing-owner guards remain intact.

The corrected prototype and release gates are terminal green: one test, 21 assertions each, covering all six vectors. The actual ordinary YAML build remains the required runtime successor after Root's graph optional-maintenance reader/writer lifetime repair. The narrowed YAML executable Source independently excludes the root library barrel and registry discovery while retaining finite test execution ownership (250 files by esbuild). No unrelated native editor owner was declared, no Source limit was increased, and no per-unit cache success has been asserted for unsupported compiler adapters.
