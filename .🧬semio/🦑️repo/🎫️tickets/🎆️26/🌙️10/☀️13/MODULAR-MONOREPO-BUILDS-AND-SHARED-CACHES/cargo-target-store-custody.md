The existing shared compiler/profile lease identifies only the compiler build directory. A caller can supply the same uplifted output target with another build directory, and the two admissions describe unrelated resources. Persistent exact recipes already provide target exclusion, but direct Cargo relay, component, WASM and test callers still need explicit output-store custody.

The selected design requires every compiler admission to declare its actual target directory. ## CLI Override Audit

Cargo CLI configuration values take precedence over environment variables and are merged left-to-right. Explicit target-dir arguments can also bypass a leased environment target. The ordinary .cargo/config.toml contains target/build defaults and is explicitly supplied as CLI configuration in artifact producers. Current recipe runtime tests pass because explicit CARGO_TARGET_DIR currently dominates or the actual compiler variant handles that value differently, but this does not prove hostile CLI targets cannot bypass custody. Exact compiler-target argument normalization must be tested with actual Cargo, not inferred from environment assignment. [Cargo official configuration precedence](https://doc.rust-lang.org/cargo/reference/config.html#command-line-overrides).
