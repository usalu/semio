# Bounded Artifact Group Reader Design

Source/unit implementation only; Native images, publication and real lease acquisition are not authorized in this checkpoint. CPU owns actual79-root Pages integration; group owner supplies one reader scope instead of recursive individual public readers/tasks.

Closed request DATA is an array of1–128 copied existing artifact requests, sorted by exact canonical path, distinct and nonoverlapping. Existing per-row schema/owner/bounds remain. Aggregate limits charge actual content, not the sum of permissive per-row ceilings:8GiB actual extents,131072 declared files,262144 physical entries and16MiB aggregate manifest extents before Buffer allocation. Inspection remains sequential, including descriptor reads; each retained artifact adds a genuine SH lease, whose FD capacity requires later real qualification.

One withArtifactStorageOperation enrollment authenticates actual store/base/phase for the whole acquisition/holding scope. Each accepted group task separately uses the same existing helper once, preserving actual cumulative store admission; no enrollment is repeated per member. Acquire artifact SHs in sorted order through the canonical lease API and retain them outside the inner requested-control callback/drain. Initial manifest/descriptor/SHA/identity/roster validation uses the extracted identical single-reader inspection body, with group counters. No path/receipt creates a store or control.

Issue an opaque private group only after all initial inspections. Group tasks synchronously register before callback effects, use genuine issued child phase controls, and receive immutable actual artifact views. At most31 accepted tasks over the group lifetime plus the enclosing operation is a local ceiling. Actual cumulative store32 admission may refuse earlier because of other retained operations;31 successful tasks are not promised. Close group births, join accepted work, preserve Error/undefined, then recheck every member under retained SH before releasing in reverse order. Detached task failure is terminal even if caller ignores its promise. A returned task/view cannot be reused after closure.

The single-reader public API, schema and corpus remain intact. Shared helper extraction is mechanical except optional aggregate accounting, which single-reader callers omit. New tests must include independent Ajv/SQLite layout/accounting oracles and actual TypeScript AST integration; no structural successful fake issuer/store is permitted. Full positive group custody, narrower-phase wait cancellation, busy producer/refusal, mutation/ABA limits and79/128 lease FD availability remain runtime gates after Root authorization.
