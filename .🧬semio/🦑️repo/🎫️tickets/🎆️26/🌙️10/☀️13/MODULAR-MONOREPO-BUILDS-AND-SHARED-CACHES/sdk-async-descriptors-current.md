# Asynchronous SDK Descriptors

## Scope and Preserved Contract

Root approved the measured scope in [the critical-path report](sdk-capture-critical-path-current.md). Production changes are limited to the private SDK index/hash owner: synchronous descriptor open/stat/positional-read/close became awaited actual built-in FileHandle operations. No higher parallelism, thread-pool setting, new dependency, whole-file buffer, preliminary hash, trusted-index shortcut, yield removal or deadline/cap/floor change was introduced.

The same 16-worker parent-layer owner limits active descriptor helpers. Each uses the unchanged 64 KiB buffer and performs the same full SHA-256 and extent checks. Actual base SH/EX, private Source capture/quote, per-file pre/post descriptor identity, no-follow open flags, immutable mode/link rules, all original control/continuation checkpoints and final rooted namespace recensus remain. The short synchronous enforcing-prefix directory checks remain intentionally outside this descriptor-I/O scope.

Every successful open is owned inside its accepted worker until awaited close settles. A primary Error **or undefined** survives a later close/control failure; a close failure without a primary remains fatal. Complete capture, sealed shared-source verification and cold sealing consume this same helper. No full-clone capacity/copy policy, derivative five-fence boundaries, publication visibility/rename, activation, retirement or lease namespace Source changed.

Diagnostics now state `descriptorBackend:"async-filehandle"` for capture phases, complete capture and sealed verification. Its open/stat/read/close accumulated durations may overlap and must no longer be summed as serialized main-thread blocking time. Actual backend scheduling is framework-owned; 16 active descriptors is not a claim of 16 simultaneous physical disk operations.
