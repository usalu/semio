## Closed Data Projection

The schema owns a finite one-to-three ordered environment-layer input, prototype/release intent, supported platform, derived variable names, exact removed Core wire, paid capacity names, forced cache-disable values, one MiB serialized input bound and256UTF16 output-path bound. The helper is pure data; its result never issues cache or control authority.

Layer merging preserves later options over earlier environment values, including Windows Path/PATH case variants. Windows uses the authored uppercase comparison while preserving the winning entry's spelling. POSIX independent lower-case variables remain independent. Undefined entries mean absence; semantic variables and Unicode values remain in the ordered digest.

Identity projection removes TMPDIR/TMP/TEMP and SEMIO_VITE_CACHE_DIRECTORY, because the actual child receives deterministic state-derived values. It removes the exact `SEMIO_SCRIPT_PROCESS_INVOCATION` wire both from identity and the actual child. Vite's thirdparty CLI is not a Core Original receiver. Incoming SEMIO_COMPILER_CAPACITY_HELD, SEMIO_COMPILER_PARALLELISM and GOMAXPROCS are removed before compiler capacity admission, preventing this route from treating an incoming marker as paid capacity. Runtime child construction uses only the actual compiler-state callback's environment after its real acquisition, preserving the scheduling values supplied there. It does not authenticate arbitrary capacity data or change the generic capacity owner.

Authoritative mode and the two fixed runtime cache-disable values are installed before digesting. The semantic digest enters the existing configuration identity; existing compiler-state code also binds owner/compiler/platform/architecture/mode. Child TMP is `join(actual state directory,"tmp")`, and child cache is that actual directory. Thus changing incoming temp paths or per-run Core wire cannot change the state/TMP identity, while a changed effective semantic option does.

## Actual Caller Construction

The command captures root/config/host/port/strictPort/mode and copied closed artifact-input data before any store/capacity await. Invocation and signal are retained as their exact actual objects, not cloned. The already-authorized mode is captured once and reused for state, child environment and CLI argv. No options property is reread after opening starts.

Semantic environment layers are copied from entry process.env and options.environment before stores open. The current products store environment contributes only later ambient process.env plus overwritten temp values, so consulting it after awaits would undermine this capture. The command therefore does not adopt that later ambient environment. This is an explicit CLI role contract, not a generic change to store environment behavior.

Inside the existing `withCompilerState` callback, which owns actual state EX and capacity, the command derives the child environment from compilerEnvironment and the actual state directory. It checks the Native path, rechecks its store, creates stable TMP, checks/rechecks again, then passes only the final child environment to the existing owned CLI child. Actual argv remains captured mode/config/root/host/port/strictPort. The pure path projection itself grants no write permission.

Stable tmp history remains within the existing products filesystem. This change does not promise tmp cleanup reserve, automatic retirement, or stateless compiler behavior. The existing whole-service capacity lifetime was not changed or runtime-qualified.
