# Artifact Publication Source Custody

The independent descriptor audit confirms a Source-level race, not a completed runtime probe. Repository admission currently retains paths and byte counts; actual Core copy and identical comparison reopen those paths after waiting for destination EX. A source replacement, symlink substitution or growth is therefore not tied to the original finite request. The destination image still enforces its physical ceiling. No claim is made that an escape was executed.

The proposed narrow correction is one internal scoped Source-set owner in Core publication. It captures the actual Map's primitive names and paths once with an explicit finite entry count, rejects the reserved .semio-artifact.json name and descendants, and accepts only exact issued control plus positive schema-bound file/byte ceilings. Repository callers pass their existing schema policy, rather than optimizer knobs or environment-derived limits.

Before destination EX acquisition, Source admission opens each real single-link regular file with no-follow where available, compares fstat against its captured lstat and relevant physical ancestry, and retains the exact descriptor. It captures dev/inode/mode/extent/mtime/ctime and hashes the bounded descriptor bytes. Short reads, growth probes, changed identity and excess aggregate bytes refuse. Admission work is asynchronous and bounded, with continuation and cancellation checks; every descriptor opened by a failed partial admission closes in finally. No caller fd, serialized descriptor record, structural receipt or filesystem path can manufacture the private Source-set capability.

The actual owned publisher consumes that private set. Copying and identical comparison read explicit captured extents through those retained descriptors, use bounded chunks and cancellation/progress, probe for growth and compare final descriptor/path facts before commit. Destination mode comes from captured facts. Copied bytes must match the captured Source digest. No source pathname is reopened for content or mode. The actual destination writer proof, accepted cleanup token, old destination identity and rename/rollback protections remain required and unchanged.

The Source-set lifetime must enclose accepted publication and all rollback/cleanup, including failure and undefined. A private pending registry is required if the new public scoped entry permits detached consumption; otherwise keep it an internal lexical owner used only by the existing actual stage operation. Do not add another Original issuer or structural registration bridge. Input descriptors must not be closed at callback return before accepted work settles.

The finite descriptor count is an explicit host-resource concern. Keeping up to the existing 16384 file cap open can exceed a host's fd limit; partial admission must fail closed and close all owned fds. This does not justify claiming future large-output availability on every host. An alternative immutable bounded capture would need its own actual funded scratch, writer custody and peak-byte quote before any capture writes. It cannot be introduced as an uncharged temp copy or assumed immutable pathname. The initial implementation should expose this refusal honestly rather than silently chunking away inode custody.

The first actual regression remains pending a separately cleared physical window: hold genuine artifact SH, start an actual publication and wait until the real EX waiter is observed, replace its admitted fixture Source with a symlink or new inode, release SH, then require rejection and unchanged old publication. Growth and mid-copy mutation follow under small explicitly bounded fixtures. Independent Node import/hash and Python/SQLite exclusion must observe real output and custody. An outer Original accepted failure is asserted outside its receiver, with a completed-observations marker. No physical probe or Core Source correction is claimed by this design.

## Capacity Correction: Bounded Descriptors, Complete Funded Capture

The first isolated descriptor primitive reserves an entire admitted subset against a process-wide publication descriptor budget of 32, including two auxiliary handles. This primitive is deliberately **not imported by the publisher**. Its 30-file subset ceiling must not become a publication capacity ceiling: current products retain the existing schema-owned 16384-file / 512 MiB capacity. The ordinary four-law fixture now passes after its genuine absent-owner RED; this proves only the subset primitive and small ordinary file behavior.

The proposed complete integration instead creates the *actual final stage tree* before waiting for the destination writer. The stage is in the held actual publication reservation and destination parent, so capture and eventual publication are the same charged bytes, not an extra uncharged Source clone. Peak includes the retained old publication plus one bounded new stage, as the current replacement algorithm already does. The stage keeps its own private creation intent, actual stage-resource EX lease, exclusive-create directory inode and exact cleanup enrollment. The publisher still acquires and retains the unchanged `artifact:<destination>` EX before comparison, rename or replacement. No original file is reopened after destination admission begins.

The algorithm validates the complete actual Map's primitive names, portable path lengths, file/directory conflicts, reserved manifest name, count and manifest bytes before any capture effect. It then captures one Source at a time through the admitted descriptor primitive. Each Source is no-follow opened, its exact regular single-link inode and bounded extent are checked, and the descriptor is consumed in 64 KiB chunks into an exclusively created private stage file. The copied digest must equal its admission digest; its extent and Source path/ancestry are rechecked before its descriptor closes. Aggregate actual captured bytes and files are checked against the existing whole-publication policy. Partial admission closes every handle, then removes only the exact created stage under its held actual stage EX and pre-funded cleanup token. No bare path can supply that capture authority.

The private captured-set record retains the stage inode, each exact file inode/size/mode/digest, complete names, exact control/token and non-releasing writer proof. After destination EX is acquired, unchanged comparison reads only these privately owned captured files and the old publication in bounded descriptors. Reopening *captured* files requires the live private stage record/EX, no-follow regular-file identity and digest checks; it never reopens original Source content. Before committing the captured stage, a complete captured inventory/hash check proves no unexpected path, hard link, substituted directory/file, changed extent or digest. The original stage directory inode is then renamed into the destination rather than copied again. Warm identical output cleans the exact unused capture stage. Both cases retain all accepted work and stage/destination guards until existing rollback and cleanup settle.

This is an explicit actual stage owner, not a generic serialized receipt, arbitrary writer callback, or claim that chmod creates kernel immutability. All content trusted after capture is owned under the real private stage EX and revalidated against its consumed descriptor digest. Supported cooperative peers cannot mutate it without that actual lease. A noncooperating same-user mutation must produce refusal under full identity/digest recensus; unrestricted same-user filesystem attack atomicity remains a distinct platform boundary. The root destination name, `.semio-artifact.json`, and its descendants are forbidden input files before effects.

The new stage resource key must not introduce unbounded permanent metadata cardinality. Prefer a single stable per-destination capture resource (`artifact-capture:<destination>`) retained through capture, destination wait and cleanup. This serializes captures targeting the same output, preserves the exact existing destination publication resource, and adds at most one resource per existing destination identity. A capture directory uses a short exclusive-create random suffix below the actual parent; that pathname alone never grants authority. Resource ordering is always capture EX → destination EX. Ordinary readers retain only destination SH, so they do not need the capture guard. A generic publisher lacking actual reservation/cleanup provenance cannot be silently called equivalent to this managed path.

Before production wiring, the Core stage guard and cleanup must explicitly distinguish the private capture inode from the destination inode: admission, capture failure, destination-wait cancellation, unchanged reuse, successful rename, rollback and cleanup failure each keep both private ownership records until their corresponding terminal operation. Existing destination cleanup proofs cannot simply be relabeled as a capture proof. The Source-only next law must verify actual call ordering/finite constraints and small private capture consistency without performing runtime publication in this turn. Physical wait-race/cancel proof remains separately held.

## Frozen Source Capture Checkpoint

The complete publication capacity remains 16384 input files and 536870912 input bytes. Core now captures one admitted descriptor at a time into its actual final private stage before waiting for the unchanged destination EX. The stable capture resource is `artifact-capture:<destination>`; it precedes the existing `artifact:<destination>` resource. It adds one stable metadata identity per destination, never one per random stage. Managed callers retain the same genuine reservation, exact carried control, cleanup enrollment and output binding. Neither the standalone descriptor primitive nor cleanup DATA supplies Native image authority. The existing generic Core path remains a generic filesystem frontier, not evidence of repository-image custody.

The source-set primitive is used by the real stage capture. Its entire subset reserves descriptors before opens, closes partial admissions, and preserves thrown undefined. The full publisher never passes all 16384 files to that pinned subset. Content descriptors across admission, captured reads, comparison and marker reads share a process-local limit of 32; this is not a limit on all unrelated process or SQLite descriptors. Schema-owned pending operations and per-file reads each cap at 32 before Promise/Buffer birth. Public byte reads use Uint8Array, not filesystem handles or a third-party class.

The capture owner snapshots the actual Map using its intrinsic iterator, reserves the marker name and descendants, bounds complete names/manifest/bytes, and captures Source through exact no-follow regular single-link descriptors with pre/post ancestry, inode, extent, mode and digest checks. The created stage records every admitted directory/file inode. Its reopened files require the live private capture guard, bounded descriptor slot, exact ancestry/identity and complete precommit inventory/digest recensus. The created stage itself becomes the output by rename; there is no second uncharged complete clone. A private prepared commit proves the destination writer before rename; acknowledgment records only the exact renamed stage inode and does not renew body authority.

Core's normal and rollback cleanup paths synchronously close capture admission and drain already accepted captured work before beginning the shared cleanup token. Accepted failures remain fatal and ordered; they do not prevent fixed owned cleanup from being attempted under the already funded cleanup phase. File closes preserve primary Error/undefined and retain close failure as secondary. Partial files without a successfully recorded inode or unexpected stage contents refuse cleanup rather than being adopted or deleted by appearance. Such unresolved I/O failure remains a possible bounded partial-output frontier; it is not claimed away.

The existing output manifest has one bounded exact-descriptor reader under destination EX: maximum 1048576 bytes, no-follow/single-link regular-file admission, 64 KiB reads, exact extent/probe and pre/post inode/ancestry checks, UTF-8/closed fields/name policy and descriptor-slot accounting. Initial owner and unchanged comparison share that result. No unbounded readFileSync/JSON.parse path remains in the publication algorithm.

Replacement after complete capture now has snapshot semantics: a later change of the original Source cannot substitute its new bytes into output while waiting for EX. The ordinary forty-file fixture captures 7, replaces original Source with 8, and still reads captured 7. Changes during descriptor admission/copy, or to the actual captured stage before commit, refuse. This supersedes the initial design's blanket future expectation of refusal for every change after capture; the separately held physical wait-race must distinguish these phases. It has not run.

### Cost and Qualification Limits

Correctness currently costs repeated bounded I/O. Let S be total input bytes, C be bytes compared before the first difference and M be marker bytes. Input descriptors are read approximately 3S (admission hash, consumed copy, final Source hash). A new destination additionally reads captured bytes once before callback and once at full precommit, approximately 2S+M, and writes S+M. A fully identical destination reads approximately 3S captured plus S existing output in addition to original 3S, approximately 7S total reads, and still writes/removes the bounded temporary S capture. Changed existing output adds bounded comparison reads (up to 2C) to the new-output path. There is no warm-fast claim, and the fifty-MiB/512-MiB or 16384-file deadline fit is not qualified by forty one-byte files. No additional full-array hash is performed merely to parse the existing marker.

Actual Native products backing, EX-wait interleaving, real publication/rollback/rename, large-file performance, low-space peak, platform runtime behavior and retained partial-image attribution remain unqualified and physically held. Existing rollback/destination guard and cleanup protocols were preserved in Source; they were not re-proven by invoking publication in this turn. Cooperative custody plus rechecks are the supported model; unrestricted same-user filesystem attack atomicity is not claimed.

## Reader-Compatible Inventory Refinement and Final Source Freeze

The prior 15/138 checkpoint is superseded by this defining Source snapshot. A new Core-owned schema policy caps all physical entries at 262144 and relative depth at 64. The pure inventory owner preflights unique actual input names, every unique parent directory, the stage root and the reserved manifest before any capture lease or creation. It rejects file/directory conflicts and predicts the complete final entry count. Exactly 16384 input files and 512 MiB remain supported when their actual paths also fit the existing manifest, path, entry and depth limits. There is no Root-to-Repo runtime dependency; neutral tests compare the two actual schema constants.

Actual creation permits only planned directories and input files. Complete captured recensus requires the exact planned directory/file inventory (plus the internally authored marker), depth and entry bounds. Partial cleanup remains bounded by its recorded created subset. Both full recensus and cleanup now stream directory entries through privately owned directory handles charged to the same descriptor pool; they refuse unexpected entries before accumulating arbitrary directory arrays. Every opened directory closes with primary/secondary error ordering. The existing output marker's declared names also pass this inventory policy before old-output comparison, so metadata cannot authorize a deeper/larger declared tree than the reader accepts.

The genuine absent-inventory-owner RED is retained in `🗑️generated/source-inventory-red.log` (15 pass / 1 fail). The initial implemented successor was 16 tests / 157 assertions. The final parity assertions then brought the final cohort to **16 tests / 159 assertions in both modes**, zero failures. All five separate real managed cleanup-token failure processes again passed BOTH: Error 8 assertions, undefined 8, partial admission 6, captured tamper 7, actual control cancellation 7. Expanded strict ES2022/noUnchecked again exited 0 BOTH. Final exact logs are `🗑️generated/source-inventory-final-<command>-<mode>.log`. All these commands keep their preauthored 120000 ms Original and are registered in both editor catalogs. No ordinary fixture directories remained after this final cohort. No physical image, system/native command or runtime publication ran, and all retained partial images stayed untouched.

The maximum-depth and maximum-entry boundary laws use neutral count/path data with independent Ajv and SQLite arithmetic. No huge directory tree was allocated. Exact-boundary counts include the reserved manifest and root: 16384 files + 245759 directories + one manifest equals 262144 entries; one additional directory refuses. A 64-segment input is admitted, 65 refuses, and shared parent paths count once. Returned counts are planning DATA, not writer or filesystem authority; the actual capture recomputes them from its own Map snapshot.

The previous I/O and physical qualification limits still apply. Large-output deadline fit, directory-allocation peak, actual EX-wait publication, rename/rollback interleaving and cross-platform Native behavior remain unqualified. The new independent inventory limits make those resource bounds explicit; they do not replace genuine physical capacity checks or allow any unknown baseline adoption.
