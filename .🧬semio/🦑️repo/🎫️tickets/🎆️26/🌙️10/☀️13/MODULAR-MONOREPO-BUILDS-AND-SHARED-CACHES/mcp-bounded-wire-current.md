# Bounded Immutable MCP Wire Source Checkpoint

The new schema-first first-party wire module is separate from actual process/Native ownership. It selects the existing pinned MCP2025-06-18 request, notification, successful object response or error response; IDs are safe integers or bounded nonempty strings, never null or fractions. Exactly one result/error branch is selected. Parameters/results are JSON objects. The selected closed implementation does not claim every optional extension. No runtime third-party library or generated binding was added. References and scoped process migration are recorded in `mcp-scoped-session-design-current.md`.

The complete immutable JSON snapshot is bounded at4MiB encoded bytes, depth32,65536value nodes and16384entries per object. It refuses nonfinite numbers, BigInt/undefined/functions, getters/proxies, nonplain containers, sparse arrays, cycles and unpaired surrogates without invoking caller serialization code. Aliased acyclic DATA is copied. Exact byte accounting includes structural punctuation, escaped keys and escaped values. UTF8 wire is one line; decoded escaped newlines inside JSON strings remain valid DATA.

Serialization explicitly emits tokens into a bounded parts array in UTF16 property order. Sorting insertion order followed by JSON.stringify was genuinely wrong for integer-looking keys: their JavaScript enumeration order moved2 before10. The independent fast-json-stable-stringify oracle exposed that exact difference in order-red6, which is retained. The new serializer agrees byte-for-byte on every accepted neutral row, including integer-looking and non-BMP/BMP keys. Snapshot creation and admission remain separate from process authority.
