# Published Rust Artifact Reader Design

Read-only design while the compiler Source is frozen. Storage confirmed that this ingress lane owns the shared published-artifact reader; its next lane owns retained Rustup tools provisioning.

The neutral Cargo builder publishes artifacts at the fixed compiler image root under `published/<sha256 absolute manifest prefix>/<mode>`. Its publication owner is the portable manifest path relative to the actual compiler cwd. `stageArtifacts` acquires an exclusive `artifact:<absolute publication directory>` lease and writes `.semio-artifact.json` with exact owner/files. It already copies and verifies POSIX permissions. A reader must acquire the same resource in shared mode and keep the actual fixed Rust image and compiler-store charge live for the entire callback.

The reader contract should centralize the publication-directory projection with the writer, validate the physical directory/ancestry and bounded exact publication marker, refuse undeclared files/symlinks/hardlinks, and bind selected executable bytes/mode before invoking a consumer. Callback progress/cancellation comes from the original compiler admission control. A returned bare executable path cannot release image lifetime before execution or installation.

For CLI/coordinator launch, run the published executable inside the reader callback with the original deadline and signal. For dashboard installation, acquire the existing tools store charge and copy the executable to its digest-named immutable installation directory while the Rust publication reader remains held. The installation should name that issued tools image path and verified content/mode; no runtime executable bytes should be written into an unbounded package or former Repo cache directory. Dashboard launch must retain the actual tools store through child settlement and protect the selected immutable executable from generation retirement.

Dashboard currently exposes a small installation record outside compiler output and shortcuts graph discovery in the Nx bootstrap when that record exists. Keep the record/control behavior, but its executable-path admission and image lifetime must be updated. `DashboardExecutionOptions` currently carries only mode/network/control; retaining tools via `withRepositoryToolingStoreV1` needs the original `ScriptInvocation` as a required local interface fact, propagated from the bootstrap and package owners. The bootstrap Source owner must coordinate that small propagation after the Nx pair.

Qualification must compile and publish a small genuine executable in the issued Rust image, acquire it through the new reader, execute/copy it while the image lease is held, refuse concurrent replacement until reader release, and verify that cancellation releases both publication and image custody. Installed dashboard tools must be executed while the tools image remains live. This does not grant binary per-unit reuse; it repairs the finite fallback artifact-consumer contract.
