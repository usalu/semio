## Scope and Architecture

The native process module `📦️artifacts/🏗️native-build/💾️storage` defines closed language-neutral policy, allocation, event and state schemas before the implementation. All reserved, committed and retiring bytes remain charged. A retirement event follows the original writer/reader owner’s awaited physical release. Cancellation or an abandoned frame does not infer release from age, PID state or file absence. `recoverNativeStorageReservationV1` reacquires the exact held allocation from the serialized durable journal and unchanged enforcing backing; the original cache owner must still hold its writer/reader guard before acknowledging physical retirement.

The default ordinary directory port rejects strict admission before directory creation, journal or compiler writes. Actual enforcing backing is supplied independently from the logical reservation ledger. `NativeStoragePolicyV1.leaseDirectory` must name the original short global lease directory; the journal remains inside the bounded filesystem. A long ticket-mounted SQLite queue path was genuinely refused by the 256-character materialized path contract; this was corrected at the canonical lease owner, without shortening/randomly aliasing Source paths.

The macOS provider creates a regular fixed-length UDIF read/write image, never a sparse image. The actual image inode, size, link count, allocated blocks, mounted filesystem device and filesystem block capacity are retained and rechecked. Persistent reopen additionally observes the system `hdiutil info -plist` mapping from this exact image path to this exact mount. Provision/remount uses exclusive global image custody; active invocations retain shared image custody concurrently. Releasing a persistent invocation does not detach the mount. Explicit image retirement acquires exclusive ownership after all users settle and refuses any remaining durable charged allocation.

`nativeStorageRetirementPortV1` joins the original cache writer/reader’s physical retirement action with the actual provider’s identity rechecks. This callback must represent real ownership; a no-op or guessed absence is not qualification. The private reservation issuer authenticates the actual object and original cancellation source; invented structural receipts cannot enter the Cargo adapter.

The raw `buildCargoArtifacts` adapter now requires `options.storage`, an already acquired authentic compiler workspace reservation, before any recipe, capture or compiler step. Build, capture, recipe target, selected publication/observation, provenance, Cargo home and temporary paths must descend the enforcing root. Existing symlinks and nested foreign filesystems are refused. TMPDIR/TMP/TEMP point inside the same backing. Compiler-produced file paths are checked before copying. The original caller retains reservation retirement responsibility; the adapter cannot privately reserve and discard a charged allocation. Default publication is inside the bounded root, not a duplicate source-tree build directory.

## Physical Guarantee and Remaining Limits

The observed hard substrate is the fixed image data file and its finite mounted filesystem. ENOSPC is synchronous filesystem enforcement, not an asynchronous monitor or an eviction observation. Logical reservations serialize admission but cannot, alone, constrain an arbitrary compiler’s writes. A unit writing more than its reservation can exhaust the shared volume; it cannot enlarge the fixed backing through ordinary filesystem writes. Per-unit partition/subquota isolation is not yet qualified.

This qualification does not establish a never-exceeded bound for the entire repository, APFS allocation metadata or snapshots, global lease database metadata, source/Git files, external toolchain/registry homes, previously existing caches or a malicious build script writing arbitrary external paths. Known compiler storage paths are confined; this is not an OS security sandbox. The persistent image receipt and global lease metadata have separate host allocations. Old Cargo build (154.54 GiB), target (7.08 GiB), Nx (6.36 GiB), private roots and copied public outputs remain an existing baseline; refusing new unbounded work does not retroactively bound them. Current measurements and narrowly owned fixture recoveries are recorded in [Native Storage Checkpoint and Producer Custody](native-storage-checkpoint-and-producers.md). The permanent preview selected zero deletions after concurrent external cleanup; no large retirement is attributed to this implementation.

Native Windows and Linux/devcontainer enforcing providers are currently unavailable and fail closed before provisioning/writes. A pre-provisioned quota/fixed filesystem can implement the first-party port, but no actual Linux/container/Windows quota was mounted or qualified in this run. Ordinary portable directories and Nx `maxCacheSize`/after-write pruning cannot satisfy the strict requirement. The 1 MiB durable event journal refuses further growth; owned checkpoint compaction and full crash/cancel mount recovery are still required for long-lived production use. The Source does not claim periodic pruning or a logical counter as a physical cap.
