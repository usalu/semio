# Direct Compiler Consumed Bytes

The old adapter emitted only `link`. A genuine production-adapter test demonstrated an ABA failure: after the pipeline admitted Source value 1, the real rustc adapter compiled value 2; an independent executable linked to that library printed 2. The test then restored the original Source bytes before the outer pipeline's after check. Both pathname hashes matched, and an authoritative artifact receipt was accepted. The new expected refusal failed as intended. This was real compilation under private tools8 and funded Rust16 custody, not a fabricated compiler result.

The actual pinned nightly accepts `-Zchecksum-hash-algorithm=sha256` and emits SHA-256/length dep-info comments. Its checksum matches changed bytes even after the file is restored, so the existing originally admitted SHA-256 can be compared directly. No new runtime hashing dependency is needed.

A closed native receipt schema now specifies version 1, SHA-256, exact workspace/cwd/platform, expected Source paths/checksums/lengths and a normalized observed receipt. The parser caps text at 8 MiB, files at 65,536, individual admitted Source bytes at 4 MiB and native paths at 256 units. It rejects extra/missing/duplicate Source rows, mismatched checksums or lengths, unsupported algorithms, malformed checksum lines and paths outside the owned Source root. Source rule membership must agree with every checksum and every admitted Source. Neutral POSIX and Windows cases are compared with independent noble SHA-256 and Ajv.

The direct adapter now emits link plus dep-info into its actual owned temporary directory, reads that file through the bounded physical Source reader, and checks consumed Source evidence before returning the artifact directory. The receipt publisher is therefore never reached on mismatch. Generation/sysroot identity, compiler cfg, dependency artifact readers and before/after Source checks remain in place.

The prototype successor passed 11 tests / 158 assertions in 22.78 seconds. It includes real cold/changed selected compilation, neutral parser/schema/hash cases, nightly SHA-256 probe and the production-adapter ABA law. The ABA law still observes compiled value 2 and restored original SHA, then now receives `Rust compiler consumed-byte Source checksum or membership differs`. Initial strict checking found only a TypeScript nullable-match narrowing issue; the declaration was corrected and the strict successor exited 0. The release successor passed all 11 tests / 158 assertions in 93.12 seconds. An earlier release attempt passed the consumed-byte laws but timed out waiting for the tools store before the selected producer, so it is not counted as a passing suite. Ordinary protected-adapter Nx reuse is not claimed yet.

The earlier canonical ordinary seven-phase pair passed both modes (one test / 285 assertions each) before this adapter extension. A current protected sealed-entry qualification is still required. Warm frontend/native inventory overhead remains a separate unresolved performance goal.
