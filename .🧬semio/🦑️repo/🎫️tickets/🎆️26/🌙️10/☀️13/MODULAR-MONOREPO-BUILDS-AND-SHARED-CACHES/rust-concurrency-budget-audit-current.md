# Rust Concurrency Budget Audit

This is a partial Source audit. No CPU utilization, Native producer concurrency, disk budget or successful compiler behavior was exercised or qualified.

The defining rustc/🎟️capacity implementation does not request one token unconditionally. With the default backend, an explicit codegen_units value greater than one and off/false LTO, it requests available capacity bounded by codegen_units. Other backend/LTO classes request whole-host capacity. The actual rustc adapter passes that request into withCompilerCapacityConsumptionV1, creates a jobserver with the granted facts.parallelism, acquires a slot, and supplies the jobserver environment plus SEMIO_COMPILER_PARALLELISM to actual cfg/compiler dispatch. Do not infer oversubscription simply from -Zthreads=1 or a four-unit prototype codegen profile. Do not infer actual all-core use from these Source calls either.

The Core artifact-cache policy model separately bounds its outer backing, per-producer filesystem/metadata charges, catalogue slots and minimum headroom. Existing Source corpus observations include a four-GiB charge, eight catalogue slots and one-GiB minimum available floor; the actual policy owner and provider must still be followed before deriving a realizable concurrency number. Catalogue slots, funded physical producer capacity, CPU grants and in-flight temporary artifacts are different constraints. A guessed division of the outer backing by producer sizes is not an observed maximum concurrency proof.
