# Nx Filesystem Journal Integration

This workstream extends the existing pinned Nx daemon's native workspace watcher and socket protocol. The daemon already registers its source watcher before the initial workspace census, and the installed watcher exposes forceFlushPending. The journal will share this daemon lifecycle and require a closed scope request, current watcher evidence and bounded original caller cancellation/deadline on the client. Explicit NX_DAEMON=false remains an unavailable fallback. The native Nx graph/hash/cache publisher patch hunks are owned by the Nx workstream and will be preserved.

The intended closed RPC is GET_SEMIO_FILESYSTEM_JOURNAL with version1 and scope roots/files. A witness carries version, epoch, scope-relevant sequence, global identity paths/hash, selected membership paths/hash and path/type changes; error, unknown/overflow, ignore changes or lost watcher liveness refuse reuse. The selected seal owner independently validates exact content and custody observations.

Implementation and runtime results will be recorded here after the provider interface is available.

## Protocol and native runtime gate

The pinned SDK now exposes `DaemonClient.getSemioFilesystemJournalV1(scope, control)` through a dedicated existing-daemon connection. It performs no implicit daemon startup, respects explicit `NX_DAEMON=false`, intersects the original caller deadline with a one-second optional probe, forwards original progress and continuation, and closes only its own connection. Original cancellation/deadline throw; unresponsive or mismatched services return unavailable.

The request is closed before the SDK adds its workspace envelope. The response is a closed version-one wrapper binding the actual loaded immutable SDK identity and the neutral witness. The SDK identity comes from the real loaded SDK ancestry and verifies its immutable patch receipt; an activation symlink does not authorize it. Server metadata stamps this identity before the client attempts the new request, so old live daemons do not receive an unsupported request. Optional server-side owner import or protocol refusal is caught without invoking Nx's fatal daemon-error path.

The existing Nx native watcher remains registered before the workspace context scan. Journal event observation shares this daemon-owned watcher, drains `forceFlushPending`, filters authored generated directories before updating native context, and supplies the effective `WorkspaceContext` census and exact path admission to the repository backend. Ordinary ignored source paths remain excluded while authored structural collection leaves are handled by the backend policy.

Physical green: the patched installed API and independent Ajv request fixture completed the actual Nx task in 2.0 seconds (`daemon-journal-api-green.log`). This green alone does not establish full journal reuse.

The permanent route is `repo:test-daemon-journal` with prototype/release configurations and the canonical caching script `test daemon-journal`. Its expanded handcrafted native corpus exercises watcher registration/census overlap, pending flush, selected updates versus unrelated updates, create/delete membership, global identity changes, generated and ignored sources, cancellation, no-follow refusal, and event overflow. Its owned transport child uses the real repository root with private workspace-data state, then checks actual daemon RPC and actual stalled socket bounds. The expanded run is in progress; no runtime success is claimed here yet.

Authorizer custody is still being integrated by the parent: mutable checkout imports cannot prove the previously cached Node module body. The parent is bundling backend, classifier, RPC and their neutral source/schema/policy closure into the immutable toolchain. Selected graph reuse remains disabled until that loaded-body custody and full daemon runtime gate are established.

## Journal isolation design

Use an owned Node worker thread with the actual immutable `semio-authorizers.mjs` as its entry, avoiding eval or copied checkout scripts. A canonical first-party worker `📜️script.ts` supplies the implementation exported into that bundle. Its runtime entry activates only for a closed authenticated worker-data envelope. The daemon owns its lifetime; daemon exit kills the worker, and explicit watcher retirement signals its own generation without changing any caller's control.

The worker owns a separate native WorkspaceContext cache and native Watcher with the same effective native census, static generated exclusions, no-follow admission and authoritative structural collection exceptions. It serves a dedicated bounded socket so the SDK's whole-graph JavaScript phase cannot starve request dispatch. The client connects directly to that journal endpoint after checking the actual immutable tooling receipt and service metadata; it still uses the original caller cancellation, deadline, progress and continuation. Socket close is the genuine request cancellation signal on the worker side.

The daemon's local publisher port must query the same worker, under its original graph construction control, rather than maintain another observer or fabricate caller authority. The response binds the actual worker/toolkit identity and observer epoch. Pending initial census, dead daemon/worker, mismatched receipt, watcher retirement, overflow, changed ignore policy, unknown event and uncertain custody remain unavailable/refused. The existing whole-graph proof continues as fallback. Readiness publication must not await whole-graph construction.

Required actual acceptance: original one-second probe while the daemon main thread deliberately performs an owned finite CPU block; native source changes and flush during that block; unchanged/unselected/selected/global membership behavior; mid-query cancellation; worker/daemon termination and restart epoch change; independent installed WorkspaceContext/Ajv oracles; then real monorepo cold and warm command measurements.
