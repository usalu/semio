# Nx Build Infrastructure Implementation

## Ownership and Contract

Nx targets have prototype/release configurations and a stable prototype default. Fixed release targets reject a contradictory prototype request. Configuration propagates through task dependencies before hashing. The bootstrap resolves explicit, inherited and fixed selections into a concrete configuration, rejects dev/ship mode aliases and adds host scheduler parallelism only when the caller has not specified it. Source and launch authority remain intact; arbitrary task failures are not retried. Only the precise graph authority-changed diagnostic receives bounded retries with the original control envelope.

Root build is a noncached completion gate with empty outputs and mode-only inputs. Generic OS-dev distribution and Demonstrator preparation dependencies inherit mode. Native, managed, browser, site, extension and Go products have separate canonical mode output owners. Active package/module views retain noncached leased publication. Go binaries use separate client/repo/coordinator directories. Next uses the short workspace dist/<mode>/repo-coordinator/next path. The runtime verifier depends on its same-mode producer for zero-touch launch.

## Source Ownership and Cache Custody

Exact compiler and command inventories are content addressed in Nx-private stores. The native hasher receives their current SHA-256 values in explicit per-task maps; private values are never injected into process.env or compiler children. File identity includes its repository-relative path and distinguishes missing from empty. The same pinned native input planner drives the inventory selection. Rust lock hashing projects the selected package's reachable version/source/checksum resolution rather than hashing every unrelated root lock entry. Missing standalone locks have a distinct digest; preparation establishing one changes the receipt.

Both pinned Nx cache implementations recheck selected source receipts after execution and withhold promotion under a stale source key. The real installed-Nx fixture edits source while a task is paused, observes withheld promotion, then a fresh successor and a warm third run with exactly two executions. Generated fixtures link the actual pinned installation rather than resolving an unpatched parent Nx.

Equivalent command closures share one external import scan per graph. Shared project groups and content-addressed source refs reduce repeated arrays. Manifest-only Cargo projects now use the same defaults/ownership normalization as authored projects. Debug task plans use a schema-first dictionary of unique native instructions and per-task numeric references instead of repeating strings throughout the export.

## Admission and Provisioning

Read-only Git index discovery plus fresh structural collection walks replaces a full checkout census. New untracked module owners and ignored manifest leaves are observed at their admitted structural roots. Compound collection sequences match exact module ancestry. Symlink/inode custody remains checked. Ordinary nonwatching runs use a source fallback instead of starting a daemon watcher over compiler caches. The launcher reports graph/hash progress every ten seconds. The initial scoped admission measurement was approximately 1.2 seconds over about 3,000 structural directories rather than about 58,000.

Immutable tooling validates its ready marker and each pinned package before publication; failed stages are removed. Installation keys now depend on package/lock/patch bytes and platform/architecture/libc, with an explicit semantic key version, rather than installer source bytes. Downloads use one shared Bun cache. Obsolete promoted download-only .bun-cache directories were removed with parent authorization; runtime modules and live staging directories were preserved. Nx patch changes still require a distinct immutable patched instance.
