# VS Code Artifact Custody Frontier

The actual package router still has three raw shared publication calls: watch output from caller argv, build output at Source/dist/mode/extension, and VSIX at Source/dist/mode/vsix. Compiler and watcher accept arbitrary output directories. Scratch derives from ticket/test environment or the ordinary repo cache. Its Vite builder accepts a pathname and sets write-enabled outDir; the package main is out/extension.js, while its test config scans out/test. Existing launch catalog commands invoke watch-extension and compile-extension with mode-specific project args. No extensionHost or extensionDevelopmentPath entry was found in the inspected launch catalogs; this is a bounded Source observation, not evidence that no external IDE reads the package.

Simply wrapping those raw stage calls would leave the real compiler and package/test readers outside custody. Adding another parent-output pathname to the child would not transfer the parent's opaque writer token. Replacing Vite with the generic JavaScript bundle would also change CommonJS, test stripping and target behavior unless independently characterized.

The coherent next implementation is a domain compiler data worker in the existing permanent router. It must accept a closed entry role and mode, use Vite/Rollup write:false, preserve the actual existing CommonJS/Node22/external/test transformation, and emit bounded fixed-role byte data. The parent actual diagnostic sink writes the bytes and owns publication. The existing fixed three-role stream can be used once per entry role only if its metadata is explicitly that compiler's schema; it must not pretend to be Bun package metadata. Main and test entry outputs need their actual semantic parity fixture before replacing the old worker. No additional arbitrary compiler flag or pathname API is needed.

Build and VSIX should open actual dependency bindings, products and diagnostics. They need one finite mode tree per authored role. VSIX must copy extension bytes under the real artifact SH into funded diagnostic scratch, keep dependency/tool loans through the owned vsce child, and publish only its bounded archive. The child package manifest can retain its installed out/extension.js layout without creating an ordinary Source output directory. The extension test consumer must retain the same product reader through its actual owned test process, with test config receiving fixed data rather than ambient pathname authority.

Watch needs the same fixed role data, finite accepted work and complete watcher/child drainage before sink cleanup. A synchronous byte consumer cannot perform detached async publication without private bounded registration. Any streaming-cycle design needs finite slots, exact cycle completion, Source/output identity checks and backpressure or an explicit bounded refusal; it cannot accumulate one output tree per edit. This requires an actual cancellation/rapid-rebuild fixture before calling the service qualified.

These are Source design facts only. No VS Code compiler, watcher, VSIX, product image or external IDE was launched. Existing old out/dist content is not adopted or removed.
