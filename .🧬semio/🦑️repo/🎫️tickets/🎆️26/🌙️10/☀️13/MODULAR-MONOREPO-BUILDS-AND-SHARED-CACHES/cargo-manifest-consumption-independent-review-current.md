## Smallest honest first projection

Limit the first supported projection to the already closed first-party explicit-workspace/no-foreign resolution subset. Capture one complete finite workspace manifest/lock closure and an explicit original-to-planning coordinate map inside the existing retained compiler storage, with real publication/writer exclusion and source-free immutable ready identity. Exclude unknown workspace globs, unrecognized manifest path fields or configuration shapes rather than claiming universal Cargo relocation.

Cargo must actually receive the retained projected manifest, cwd and exact lock for **all** fetch/metadata/unit-graph commands in that scope; a body accepting environment alone is insufficient. Return a narrowly owned planning selection/port containing those exact command coordinates plus immutable captured semantic facts, with no arbitrary path override. Hold its real read custody through all commands, descriptor materialization and accepted child settlement; reject mutation/replacement and new work during closing.

Do not move raw manifests unchanged. Preserve the workspace topology for members, excludes, default-members, package.workspace, inherited workspace.package/workspace.dependencies/workspace.lints, patches/replacements and profiles. Rebind every supported dependency path to the corresponding projected manifest coordinate. Target entry/build/lib/bin/test/example/bench paths and implicit target discovery need explicit semantic projection to the original Source files; otherwise a manifests-only tree loses targets. Readme/license and other recognized path-valued metadata need original-coordinate meaning too. Cargo can still stat/open these Source paths during planning, so this manifest-consumption phase does not claim their immutable content custody.

For a small explicit-target subset, a typed semantic manifest projection can materialize explicit original target/build paths and preserve workspace inheritance in the projected topology; it must prove that Cargo accepts those paths and preserves package/target identity. Do not fabricate an empty target or copy mutable Rust files as a substitute. Derive the generated compiler CARGO_MANIFEST_DIR/PATH and manifest-relative include/resource meaning from the authenticated **original** package coordinate, while separately recording the actual projected Cargo manifest consumed. Cargo package IDs/workspace_root/manifests in metadata must be translated through that closed map before existing graph/materialization admission, not normalized by broad string replacement. Build scripts or proc macros that execute during unsupported operations are not covered by a planning-only projection.

Keep configuration's existing actual admitted view, source toolchain identity, offline/network grant, registry EX/SH and command arguments bound to projection identity. Different root cwd/config discovery cannot silently change Cargo behavior. The lockfile-resolution writer at dependency owner 45–47 intentionally writes the live authored lock under EX; that separate producer is not a read-only projected planning consumer and must not be accidentally redirected as part of this first scope.

## Proofs and limits

The ready checkpoint records genuine native tiny path-dependency compilation, overlapping registry SH with independent SQLite EX exclusion, persistent manifest-change refusal, Rust leaf recompilation, closed schema/oracle laws, and finite physical storage. Those remain partial proofs. They do not prove Cargo opened immutable manifest/lock bytes, foreign registry extraction safety, arbitrary workspace relocation, or Windows/Linux native behavior. New projection qualification needs actual metadata/unit-graph equivalence, inherited workspace/path/default-target cases, unchanged original CARGO_MANIFEST_DIR semantics in compiled output, and a controlled transient mutation law showing Cargo reads only retained projected inputs. No such proof was run here.
