# Rust Plan Admission Design

This follows the ongoing retained state funding work. It creates no Native authority and cannot lift Native/compiler/default SDK/publication holds.

## Actual Remaining Data Gap

The actual descriptor reader deeply freezes planned data. `bindRustUnitDependencyArtifactsV1` currently returns a new mutable outer plan and dependency-digest array. The state loan checks the exact plan object and captured context/content strings, but pointer identity is not a proof that all nested fields remain immutable during awaited work. Direct `planRustUnitsV1` consumers also receive mutable plan data. This must be resolved before claiming a complete immutable-plan public API.

## Required Shape

Use a schema-first, bounded, closed, inert ordinary plan-data capture. Reject proxies/accessors/unknown fields and reducing-bound violations before unbounded allocation. Reuse one deterministic plan recipe for planning and capture so unit, context, dependency digest and output namespace validation cannot diverge. Preserve the exact semantic digest recipe and validate it with independent Python canonical JSON/SHA and language-neutral mutation vectors. Freeze an owned snapshot rather than mutating an arbitrary caller object.

A validated plan-data reader may issue owned immutable DATA only; it must not register/adopt Native images, providers, Stores, reservations, context volumes or state loans. State still authenticates its actual Store/Original before data effects and receives its Native facts only from the actual private Core context callback. Plan DATA alone never admits compilation.

The actual State callback must carry the owned immutable plan used by its private loan. Script/test helper/compiler port consumers must use that exact plan rather than continuing with a mutable caller wrapper. Migrate all genuine callers together without legacy callback paths or aliases. Release funding also needs immutable data under its actual retained writer; generic storage cannot become a bypass. Preserve complete compiler/cfg/profile/dependency/current-Source and receipt checks.

## Verification And Scope

Author neutral closed-schema/mutation/identity and independently hashed data cases first. Actual Native positive controls remain genuine or unqualified; no successful Native stand-in or registrar is permitted. Retain the strict root prefix and launch/script conventions, Original deadlines and default test budgets. Keep copied/retired loan and wrong workspace/policy/plan refusals before Source effects. Source checks do not prove physical cache speed, pressure, overlap, platform setup or default SDK behavior.

Ordinary Source discovery/input verification also remains a measured performance concern. A real five-second release fixture timeout was retained in the preceding regression; a separate measured collector completed the same configuration case in2457ms under its unchanged budget. Do not label contention as the established cause, drop the failed collector, weaken namespace/descriptor checks or extend test budgets. Cold-path import layering and Source I/O should be measured before selecting an optimization.
