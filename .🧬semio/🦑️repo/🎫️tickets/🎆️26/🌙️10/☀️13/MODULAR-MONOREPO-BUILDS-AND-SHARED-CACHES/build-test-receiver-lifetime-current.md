# Build Test Receiver Lifetime

## Approved Narrow Design

Keep the current `withBuildTestInvocationV1(body)` and cleanup registration API. No existing caller gains a budget override and no law receives a guessed runner timeout. Each accepted callback obtains a real private derived invocation via canonical `withScriptInvocationSignalV1`, retaining the original deadline. A private pending entry and owned AbortController are registered synchronously before callback effects. The callback promise is observed for failure without converting Error or undefined to success.

At afterAll entry close receiver births, abort every remaining owned callback signal, and join every accepted callback (including its issuer-tracked descendants) before registered physical cleanups, then finish/join the received root. Keep the first actual callback failure, including undefined, ahead of cleanup/receiver failures; never acknowledge cancellation to clear an accepted failure. Already completed callbacks retain their actual outcome. No per-law timer or global budget shrink is introduced in this checkpoint. Runner timeout triggers the existing afterAll boundary; cancellation cannot force a noncooperative callback to settle, so the unchanged whole-process deadline remains the final bound.

New actual child regressions use their declared short test timeout to prove timeout behavior, not to change existing law budgets. Negative children must really fail even when the parent inspects their status as DATA. The timeout child's owned SQLite EX gate is probed independently before cancellation, drains after the owned signal fires, releases before cleanup, and permits a final independent EX only after terminal settlement. Other rows cover Error, undefined, detached failure, late receiver birth, and normal multiple laws under the same received birth. No Core issuer, namespace, registration or production SDK behavior is changed.

Genuine RED is required against the unchanged receiver before implementation. Results and exact terminal status will be appended here.

## Exact Registrar API and Budget Contract

Implement `registerBuildTestLawV1(name, plan, body): void` in the existing test receiver. `body` receives the same canonical private signal alias as callback admission. `plan` is a closed test-role key, not numeric request data: `sdk-fence` owns runner30000/body25000/drain5000ms; `sdk-runtime` owns runner120000/body110000/drain10000ms; `receiver-proof` owns runner2000/body1000/drain1000ms for the independent tiny hostile fixture. The last is a test proof role, not a new user build mode. Schema contains all three exact tuples. No existing caller can override the tuple or create authority; actual remaining Original always caps admission.

At actual law start synchronously claim the single active-law slot and enroll the observed receiver promise before user effects. Compute the body cutoff as the smaller of the authored body budget minus elapsed runner time and current real Original remaining minus the authored drain reserve. Nonpositive remaining funding refuses before user effects. A referenced timer aborts the canonical signal at cutoff. The runner receives a callback(done) which returns void, never the owned Promise. Completion is sent only after the exact receiver promise (and its accepted descendants) settles; done callback errors become receiver failures without a detached rejected chain. A rejected undefined gets a reporting-only Error for Bun's optional error argument, while the actual receiver/root primary remains undefined. No cancellation acknowledgement is used.

Until the exact prior promise settles, a later runner callback is rejected before entering any law body. No FIFO re-admission or deadline rebirth occurs. Clear the active slot only after actual drainage. A deliberately uncooperative fixture holds a real SQLite EX beyond the runner timeout, then releases under the same accepted scope: the child must genuinely fail, show no unhandled Promise, and expose final EX only after terminal drainage. A separate cooperative cutoff law proves body cancellation before the runner deadline. The 120s SDK role remains its own unchanged runner budget, not a global30s shrink.

Initial adoption is only current SDK30s registrations and explicit test fixture rows. Full-size120s callers are not executed or silently narrowed in this checkpoint. No process-wide unhandled rejection listener or expected-error suppression is allowed.
