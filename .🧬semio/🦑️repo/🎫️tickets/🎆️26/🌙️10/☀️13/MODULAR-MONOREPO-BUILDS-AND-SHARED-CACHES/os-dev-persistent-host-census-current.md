## Actual Production Chain

`🧑‍💻dev/♻activation/🌐serve/🟦.ts` is the only found production caller of `ensureDevLocalHub`. It passes repository root, contribution provider DATA and an extra boot signal, then loses any owner scope before starting the actual Vite callback. It exports the returned data directory/profile via environment. Its required actual ScriptInvocation is already present and must be threaded rather than reconstructed.

`🧑‍💻dev/🚀local-hub/🏃execution/🟦.ts` currently derives `OS_HUB_DATA` or `.🧬semio/🌐hub/hub-dev`, reads an environment JSON provider, accepts arbitrary provider program/argv, creates an append log, launches detached/unref, and retains PID/file-based owner observations. These observations are not genuine Native allocation, private Host or live Original custody. `spawnDevLocalHubOwner` appends both URL and free directory to the provider command. The actual Hub DevLocalHubScript now rejects that directory before any effect, so this is a real Source incompatibility, not a hypothetical runtime claim.

The authored GIS contribution currently names `bun repo run os-hub:local-hub-owner --` as provider DATA. The provider schema/parser and contribution schema still accept arbitrary executable/args; the new design must remove that effect authority, not merely change one GIS string. Provider contract tests currently assert a real arbitrary `bun -e` detached process; they must migrate coherently instead of remaining as a compatibility API. Pure own/join status/locale reducers can remain neutral DATA, but world test doubles cannot issue genuine Host/process custody.

`🧑‍💻dev/🔌vite-plugins/🟦.ts` reads the environment data directory and calls `requestLocalBrokerSession` on every session HTTP request. That broker client performs unbounded synchronous `readFileSync` and unbounded HTTP `.json()` with a new default signal timer; it accepts a free path with no retained state task. Closing only the serve bootstrap would not close this actual ongoing consumer. The client and middleware therefore belong in the same migration. Browser HTTP response DATA can carry bounded session credentials; it must not carry or deserialize Host/state/private control authority.

GIS hub-edit-durability separately reads OS_MCP_HUB_DATA_DIR or `devLocalHubDataDir`, and remains assigned to Nx/Root's actual scoped MCP client closure. It must not adopt the persistent state path as authority. No other production `devLocalHubDataDir` caller was found in the bounded OS/Hub/application census; two direct old local-hub tests and the provider contract remain.

## Required Replacement and Execution Order

1. Schema-first replace executable/argv provider DATA with a closed first-party application service selection and profile identity. Capture bounded immutable DATA before awaits and author neutral own/join/session outcome vectors, Ajv and SQLite parity. The application owner remains responsible for genuine persistent state and actual published/captured executable; a schema selector cannot issue those capabilities.
2. Replace returning `ensureDevLocalHub` with a required incoming Original/phase callback lifetime surrounding the actual Vite serve. For the local persistent namespace use `withRepositoryDevelopmentStateV1`/its actual task; never derive it from environment or the old hub-dev path. Preserve distinct OS-neutral UI caller and Hub domain extension ownership. The parent must not close state/binary/child custody while Vite middleware can still request sessions.
3. Keep Hub writer and session-client roles distinct. Exactly one actual Hub service owns the domain `local-hub:data:<genuine root>` EX while all accepted runtime work drains. A joining UI only needs retained state SH/read task and a bounded current broker request. Requiring that data EX around every UI serve would block the second user indefinitely; that is not a valid implementation.
4. The service-start lifetime needs an explicit genuine owner transition. Retaining a first UI's scoped child then killing it on that UI's return would violate the current multi-user promise; detached/unref with a path/env receipt would violate current Original custody. A separate canonical application service receiver/promotion, or another concrete already issued service lifetime, must own the shared service before the launching UI releases. Inspect existing startup/service promotion contracts and Root's new owned interactive child primitive before choosing the exact API. Do not invent a registrar, free callback grant, fresh Original or sampled deadline. Until this transition is real, do not claim the helper is zero-touch multi-user complete.
5. Under the actual state task, bounded descriptor-read the broker record (exact regular file/ancestry/extent/EOF) and bound readiness/session response bytes before JSON parsing. Reuse the live carried control and private refinement for cancellation/deadline; close middleware births and drain already accepted HTTP requests before state scope exits. Remove the pathname environment field as authorization; retain only bounded browser session/endpoint DATA.
6. Migrate actual activation ServeScript, provider/contribution schema+GIS asset, broker client/middleware, old provider/local-hub tests and package test runner atomically. Preserve external explicit URL join behavior and all multi-user/own-vs-join assertions, with no fake accepted physical world. Add genuine normal-child/process lifetime tests only under the separately reviewed closed child/service owner. Native/persistent/service/browser positive runtime remains held until explicitly scheduled.

No old directories, owner/log files or records are adopted/deleted, no path alias or legacy overload is proposed. Root currently owns generic MCP scoped process transport and the canonical owned interactive stdio extension; those hunks must remain disjoint. The frozen Host hash epoch can be reviewed independently while this exact consumer plan is considered.
