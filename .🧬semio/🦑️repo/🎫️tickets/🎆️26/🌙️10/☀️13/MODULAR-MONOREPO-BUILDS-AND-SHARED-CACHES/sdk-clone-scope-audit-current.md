# SDK Clone Scope Audit

Read-only source inspection on 2026-10-15. No builds, tests, Original launches, source edits, or Git modifications were performed. Publisher integration was explicitly outside this review.

Paths below are relative to `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/⚡️caching/🚀️bootstrap/🛠️tools`.

## Findings

1. **Registry custody ends before detached admission work settles.** `🧹️retention/📥️physical/🟦️.ts:33-34` checks `live` only before its first await and releases the registry as soon as `body` settles. A body can start `admitPublication(quote)` without awaiting it and return or throw. The continuation can then enter `retireManagedToolingGenerationsOwnedV1` after registry release, including its destructive generation retirement, because that private function never validates the actual registry handle. The eventual quote admission custody check cannot undo those deletions. Track and drain admission promises before releasing the registry, invalidate new starts before draining, and pass/check genuine registry custody inside retirement.

2. **The clone scope retains its snapshot guard, but cannot retain the enclosing registry writer.** `📦️sdk/🎟️capacity/📥️physical/🟦️.ts:35-36` drains `cloneWork` before releasing its shared snapshot lease. However, `🧹️retention/📥️physical/🟦️.ts:34` does not participate in that drain. With a longer lived quote scope enclosing a provision scope, the provision body can start `quote.clone(...)` and settle; registry custody is released while the clone performs physical writes. Its post-clone custody check merely rejects after writing. Tie each admitted clone's running promise to the real registry scope and drain it there before releasing EX. Also recheck custody immediately after the awaited pre-clone recheck, before starting physical publication. Snapshot lease retention alone does not establish registry retention.

3. **Several quotes can spend the same available bytes.** `📦️sdk/🎟️capacity/📥️physical/🟦️.ts:24` admits each quote with a standalone statfs observation and remembers only the registry handle. Within one live registry callback, two genuine quotes can both be admitted before either clone starts and then clone concurrently; each independently sees enough free bytes while their aggregate exceeds it. This is possible without forgery, and single-use per quote does not prevent it. Serialize the complete admission-through-clone lifecycle under a single publication slot, or reserve and account outstanding quote bytes against current free space until writes finish.

4. **Repeated unquoted admission trusts stale headroom.** `🧹️retention/📥️physical/🟦️.ts:33` caches `admitted` as a historical maximum. A subsequent `admitPublication()` with the same floor skips both retirement and statfs entirely, even after the first cold installation consumes capacity. Quoted calls obtain a fresh statfs check in quote admission; unquoted calls do not. Make every unquoted admission confirm current available bytes, or make unquoted admission single-use with a publication lifecycle that covers the actual writer.

## Capacity Bound Limit

`📦️sdk/🎟️capacity/📋️policy.json` charges 65,536 metadata bytes per entry and caps total headroom at 2 GiB. This is a conservative policy allowance, not a demonstrated cross-platform upper bound on filesystem metadata, allocation side effects, or concurrent non-registry consumers. The quote does correctly round each copied file separately and refuses filesystem block units above its supported ceiling. Treat the allowance as a supported-environment assumption unless backed by platform qualification; do not claim a universal physical reservation. No additional hardlink forgery was established: known binary paths are verified against sealed backing-object inode identities before being excluded from copied extents, and unknown multiply linked files are refused.

## Registry Supervisor Design Follow-Up

The proposed exact-ResourceLease-plus-store supervisor addresses findings 1–4 if the following ownership details hold. This is a design review; the supervisor implementation was not yet present when this follow-up inspected the capacity file.

- **Drain errors must remain observable.** Waiting with `Promise.allSettled` preserves custody, but a provision callback that returns successfully after starting a failing detached admission/clone must not make the enclosing provision call succeed. Record first failure (or an aggregate) and reject after draining; preserve an original callback failure while still draining all work. Attach rejection observers immediately at registration so a fast detached failure does not surface as an unhandled rejection before cleanup begins.
- **Registration must encompass the operation itself.** Register a thunk or a promise whose execution begins only after synchronous registration, rather than invoking an async operation and subsequently registering its returned promise. This matters if its pre-await section calls progress/user callbacks or creates children. Closing births must happen before any awaited cleanup, and escaped admission/clone functions must consult that closed supervisor even while the registry handle is still physically live during draining.
- **One quote must also mean one publication modality.** A single allowed quote prevents two-quote double spending, but an unquoted cold installer and that quote can still both pass statfs before either writes if mixed admissions are allowed. Require a scope to choose cold publication or one clone publication, or otherwise account/serialize the full cold write lifecycle alongside clone work. Merely draining admission promises does not retain a detached raw installer. The canonical cold publisher must await its actual expensive write process inside its guarded callback.
- **Store ownership remains an explicit nesting requirement.** Draining inside the provision scope retains its registry, but cannot independently retain a tooling store whose own caller has already returned. Ensure the canonical caller awaits the complete provision/quote scope inside `withRepositoryToolingStoreV1`; do not describe the registry supervisor as retaining the underlying backing reservation unless the store scope participates in the same ownership mechanism.

### Concrete Runtime Schedules to Add

1. Start detached admission, suspend it in quote/store recheck, then return and separately throw from the provision callback. A competing registry EX must stay blocked until the admission settles; no retirement may run after registry release.
2. Start detached clone and suspend it after pre-clone recheck but before its first write; return/throw from provision callback while keeping the outer quote scope alive. Competing registry EX and snapshot EX must remain unavailable until clone settlement. Repeat with clone failure and assert the outer provision result rejects.
3. While draining that blocked clone, use an escaped admit function and an escaped quote clone function: both new births must reject even though genuine registry EX remains held.
4. Admit a second distinct genuine quote concurrently with the first (before either await resumes), then sequentially after the first clone completes. Both must reject under the one-quote-per-scope contract; repeat admission of the same quote must never create another clone.
5. After a successful unquoted admission, consume headroom and call unquoted admission again. The second call must re-observe insufficient capacity rather than reuse its previous maximum. Also attempt cold-plus-quote admission in both orders before any writes; assert exclusive modality or explicit accounting.
6. Make detached admission and detached clone fail immediately. Assert no unhandled rejection, complete draining, and a failing enclosing scope. Include callback error plus work error and cancellation during draining.
7. Assert canonical publisher awaits the guarded operation and the outer tooling store remains live until all registered writes settle. Use a controlled filesystem/progress barrier rather than starting a fresh SDK installation.

## Scoped Publisher API Pivot Review

Design reviewed: `publisher<T>(body: () => Promise<T>, quote?: IssuedQuote)` synchronously registers tasks, serializes their complete write callbacks under actual registry EX, checks current capacity when each task starts, and binds quote cloning to a private AsyncLocalStorage publication context. This supersedes bare admission and resolves the mixed publication accounting problem by sequencing complete writers. No implementation or runtime execution is claimed by this review.

### Remaining Lifetime Conditions

1. **Reject awaited reentrancy.** Calling and awaiting `publisher` from inside its currently running publication callback deadlocks a serial queue: the parent waits for its queued child, which cannot start until the parent completes. Reject same-supervisor nested calls synchronously/through an immediately rejected observed promise. Do not silently run the nested writer concurrently. Separate sequential top-level Bun, rustup, and clone publications remain valid.
2. **Close each publication context independently.** AsyncLocalStorage propagates its object to detached descendants even after `run` returns. A genuine context is insufficient on its own. Give each task a private live/closing state and close clone births as soon as its callback settles, before draining existing clones. A delayed descendant must fail even while the parent registry supervisor remains open for later publications, or while the old publication drains an existing clone.
3. **Keep pending tasks runnable after closing parent births.** Parent callback exit must reject newly submitted tasks while allowing previously registered queued tasks to start and settle. Do not use the parent's closed-to-new-births bit as a check that rejects all legitimate queue entries at execution time. A separate execution lifetime remains live until drain completes and EX is released.
4. **Validate the exact active quote at task start and clone start.** Binding only to the registry/store is insufficient: a callback for quote A must not clone through quote B, nor through an unrelated unquoted publication context. Authenticate the quote again when the queued task starts; the source quote may have closed while waiting. Its shared snapshot custody must still cover the actual clone. Reject stale/foreign contexts before any filesystem write.
5. **Drain errors and cancellation must settle honestly.** Attach failure observers on initial registration; report detached task/clone failure through the enclosing scope, and keep draining despite callback failure/cancellation. A rejected queue predecessor must not strand subsequent accepted tasks or leave their promises pending. Cancellation may reject queued tasks before writing, but the active task's actual subprocess/copy settlement must precede EX release.
6. **Full writer callbacks are a necessary contract.** The supervisor can drain registered clone promises, but cannot discover arbitrary detached subprocesses started inside an unquoted callback. Canonical Bun/rustup writers must await the real process close/settlement, including termination on cancellation and awaited cleanup. Returning an acknowledged launch is not completion. The tooling-store owner must likewise await the entire publisher supervisor scope.

### Pivot-Specific Deterministic Schedules

- Queue Bun and clone calls before awaiting either; block Bun after capacity check, observe clone has not checked/started; let Bun consume space, then verify clone checks fresh capacity before its first write.
- Submit two tasks, immediately return or throw from the parent callback, and block the first writer. Both accepted task promises must settle; EX remains held until both settle or are explicitly cancelled before starting. A third escaped submission must reject.
- In publication A schedule a delayed descendant, finish A, start B, then let the descendant call A's quote clone. It must fail before writes despite inherited AsyncLocalStorage and live parent EX. Repeat during A's existing-clone drain.
- Await a nested publisher call from a running callback; assert prompt rejection, no deadlock, and no nested write.
- Run quote-A callback and invoke quote-B clone; invoke quote clone from unquoted callback; invoke saved quote clone after its publication closes. All must reject before writes.
- Make the first queued task fail immediately and the second remain blocked; assert no unhandled rejection, no stranded second promise, full drain, and parent rejection. Repeat with a detached clone failure plus a successful callback result.
- Close a queued quote's source scope before its publication starts; assert the queued task refuses before cloning. Cancel a running fake subprocess and verify EX remains held until its close event.
