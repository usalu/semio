# Storyboard — Sampling the Design Space (`🎲️sampling`, `Beat2_GridRandomSampling`)

Phase 1 (storyboard only). Scene author: sampling. Contract: `plan.md`, `api.md`, `agent-rules.md`. Duration target: 37 narration clauses, ≈ 5.4 s each, ≈ 3:20 plus intro/outro ≈ 3:30 (limit 4:00).

## 1 Concept

One question, one room, one currency. **The design space is the south façade of the seminar room: window-to-wall ratio WWR 10–80 % (horizontal) × overhang depth d 0–1.2 m (vertical)**, orientation 180°, insulation 16 cm, all in physical units. Every point on the map is a **section thumbnail** (wall with its glass opening and its overhang slab, to scale) and the same design is always alive in the **room section** beside the map. The currency is **electricity in kWh/a**. Three rules run through the whole clip:

1. **A point is a position until it is simulated.** Ghost thumbnail (dashed outline, grey, no number) → *evaluation* (room takes the design, winter and summer sun rays fly, heating/cooling/lighting bar fills, total counts up) → thumbnail takes its ramp colour and its kWh/a, one budget pip lights.
2. **Equal budget.** Nine pips, nine runs, for grid, random and Latin hypercube. A scoreboard row per set stays on screen (marker shape, 9 pips, best kWh/a).
3. **Nothing abstract at any moment.** Axes are `Window-to-wall ratio WWR · %` and `Overhang depth d · m`. No x, f(x), 0–1 axes, no A/B/C, no invented scores. Every number is `model.samples()`, `model.surface()` or `model.evaluate()` output, formatted through `number()`/`quantity()` (en `1,250 kWh/a`, de `1.250 kWh/a`).

Coincidence worth using: the baseline design (WWR 45 %, d 0.6 m) **is the centre of the 3 × 3 grid**, so the very first simulation shown in the anatomy beats is already grid run 1 of 9.

Narration is deliberately free of model outputs (only structural numbers: nine, 3 × 3, 81, 108, 12×); all model numbers appear on screen, so nothing has to be re-recorded when the model changes. Visual claims that the narration makes qualitatively (gap upper right, cluster, LHS best beats random best, no set hits the optimum, optimum interior) are **model requirements** listed in section 5.

Palette (energy toolkit): electricity components heating `P_RED`, cooling `P_BLUE`, lighting `P_YELLOW`, total `P_WHITE`. Value ramp (kWh/a) = dark teal (low, good) → `P_WHITE`-ish (high, bad), fixed range `[surface min, surface max]` for the whole clip so every colour means the same number. Set identity is shape + outline colour, never fill: grid = square `P_CYAN`, random = diamond `P_ORANGE`, Latin hypercube = triangle `P_GREEN`; "gap/limit/warning" = `P_ORANGE` dashes, "best" = `P_GREEN` ring. Shapes duplicate the colour (accessibility).

## 4 Toolkit widgets needed beyond `api.md`

Existing (reuse as is): `room_section`, `facade`, `plan`, `energy_bars`, `study_trackers`, `set_design`, `live_marker`, `number`, `quantity`, `thumbnail`; `_art.sun_rays`, `meter`, `stacked_bar`, `lamp_glyph`, `dim_arrow`, `math_text`, `chip`, `color_ramp`, `labeled_axes`, `layout_conflicts`.

Changes to api.md widgets:

1. **`thumbnail(design, point, scale, *, fill=None, ring=None, ghost=False, kind="section"|"plan"|"wall")`** — the section glyph (wall line with glass opening of `WWR · 3 m` anchored under a roof slab, overhang slab of `d` to the same scale; head-anchored window so the overhang always sits right above it). Elevation cannot show depth, so the plot marker must be a **section**. `fill` = ramp colour (backing tile), `ghost` = dashed grey outline. `kind="plan"` = rotated mini plan with N arrow (orientation levels in growth), `kind="wall"` = wall layer of `t` cm (insulation levels).
2. **`study_trackers` gets `progress` (0–1).** `room_section`/`energy_bars` read it: 0 = geometry only (rays faint/dashed, bar empty + "not simulated" chip), 0–0.5 sun rays and patch, 0.5–1 bar fill and lamps; `energy_bars` fixed scale parameter `full=Surf.max`.
3. **Rays follow the model:** `room_section` draws N = 7 rays across the window height; `round(N · shading_*)` of them (top first) are stopped at the overhang tip, the rest land on the floor; patch size ∝ admitted solar (`solar_winter` / `solar_summer`); winter rays and summer rays at the study altitudes via a travelling sun glyph.

## 5 Requirements for the model (`samples`, `surface`, `evaluate`) — placeholders until delivered

- `samples(kind)` returns exactly 9 designs for every kind, in the drawing order of this storyboard (grid: reading order bottom-left → top-right with the centre = baseline; random: recorded order; lhs: recorded permutation order); each carries `evaluate()` fields.
- **Random** must leave the upper-right corner (≈ WWR > 55 %, d > 0.8 m) empty and contain one clearly close pair (≈ ≤ 5 pp, ≤ 0.1 m) — recorded draws chosen for that.
- **LHS**: points strictly inside their strata; **best LHS < best random** (plan); no sample coincides with the dense-grid optimum and `surface()["minimum"].electricity` < every sample's electricity (so "none reaches the optimum" is true); grid best ≠ optimum as well.
- Provide (or I compute in the scene from `samples`): `levels()` → `{"wwr":[…], "overhang":[…], "orientation":[90,180,270,360], "insulation":[…]}` (counts 3,3,4,3), `strata(n=9)` → edges per axis, `strata_index(kind)` → `(i, j)` per sample, `largest_empty_box(kind)`, `closest_pair(kind)`. Tests re-derive them with NumPy.
- `evaluate` provides `shading_winter`, `shading_summer`, `solar_winter`, `solar_summer`, `autonomy` (already in api.md) — the rays/patch/lamps depend on them.
