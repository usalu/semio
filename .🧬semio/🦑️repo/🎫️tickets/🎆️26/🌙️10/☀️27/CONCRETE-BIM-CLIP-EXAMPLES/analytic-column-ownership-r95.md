# Analytic Column Ownership and Native Exchange

Launcher identified an important unresolved distinction: `_column_partition` subtracts sampled column outline prisms, while native exchange exports original analytic circle sections. A polyhedral cut against an inscribed sample cannot prove ownership of the circular material between facets. Explicit source axes fix placement authority but do not make that subtraction analytic. Such rows must remain unresolved in the physical audit.

The required physical operation is a declared stock difference against the original analytic cylinder, with exact source axis, radius and height interval retained. Increasing facet counts, replacing the source circle by a polygon, shaving the circle, accepting a tolerance, or skipping a declared column/beam pair cannot supply that operation. A beam narrower than the source column can intersect only part of the circle, so a simple complete circular profile hole is not sufficient for all actual joints.

A clean representation path is a first-party schema for analytic constructive solid geometry: a native stock operand and explicit declared difference operands, including a vertical circular cylinder. The physical interface must retain that analytic boundary and distinguish any display tessellation from material authority. Native IFC can then serialize the original stock and exact cylindrical cutter as a Boolean difference, while retaining uncut nominal geometry in a separate Reference. The native Body must contain only the result, never both nominal and borrowed owner bodies.

The appropriate native entity is the general [IfcBooleanResult](https://standards.buildingsmart.org/IFC/DEV/IFC4_3/HTML/lexical/IfcBooleanResult.html) with DIFFERENCE. A cylindrical cutter is not the restricted half-space operation represented by [IfcBooleanClippingResult](https://standards.buildingsmart.org/IFC/DEV/IFC4_3/HTML/lexical/IfcBooleanClippingResult.html). BuildingSMART's [Boolean result definition and block-minus-cylinder example](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD1/HTML/schema/ifcgeometricmodelresource/lexical/ifcbooleanresult.htm) independently confirms that distinction. This is a proposed representation path, not a claim that current producers or SDK support has already been demonstrated.

This assessment does not certify that current first-party geometry, quantities, renderers or all-pair auditing already support such analytic differences. They do not obtain that support merely from an IFC serialization change. Source quantities require an independent analytic section or integral; the all-pair auditor must evaluate actual differences rather than apply a tag waiver; and native SDK checks must preserve typed source circle placement/dimensions and independently validate the Boolean Body. Schema-first translated/rotated partial-cylinder controls, a positive between-facet witness, source/reference conservation and independent quantities are required before acceptance.

Root owns the explicit-axis analytic support audit and Launcher owns the structural partition lane. Exchange Body currently consumes their actual owned ramp/beam parts. This lane can serialize a first-party analytic CSG contract once the physical producer and independent audit share that contract; inventing a private exchange-only cut would make native output disagree with public geometry and is not an acceptable repair. Full ramp Reference serialization is separately pending after analytic-axis controls.
