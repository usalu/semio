# Paged Edit Integration Review

Current-source static review; no Cargo/test graph. The edit records a boundary on the incoming effect and measures returned u128 Work from the same receipt. It validates owner address, expected length, index, and input/output occupancy first. Initial binding has its own copy/depth/work admission, charges one real Work unit, sets owner only after admission and returns immediately. In subsequent mutation turns it quotes child physical and Work demand, adds state-copy bytes and one Work unit, checks the combined original grant and remaining Work, charges state Work, then reborrows the same effect with state-copy bytes subtracted and the child Work bound. Reservation instead passes the original effect directly and maps the complete typed allocation/Work refusal, retaining allocated and copied progress. Denial paths do not move the list or item; a descendant Work error after the state precharge can legitimately report nonzero actual Work without a physical move.

Insert adopts the input only when a reserved slot is ready, advances expected length once, then adjacent swaps proceed backward to the requested target. Remove swaps forward and only then transfers the tail into the empty original destination; expected length decreases on that final completed transfer. Each successful child result is observed before cursor fields change. Physical copy progress adds cursor state bytes to the quoted child copy; measured outer Work includes the state charge and child effect. This is source reasoning, not execution or a proof of all malformed internal states.

Concrete defect: the reserve branch currently sets moved_items to usize::from(progress.progressed), but reservation can progress by allocating metadata or a backing page without moving any list item. It should report zero moved items while preserving full allocation progress. This was sent to the server owner.

Existing edit native test uses genuine EffectBank, authored JSON cases and allocator observation and checks initial denial axes plus final ordering. It does not assert the removed output, donor/list multiset conservation at every interruption, denial after binding and in subsequent phases, measured step.progress.work versus turn.work, actual allocator failure/retained allocation details, or a Work error after partial paid action. Add funded insert and removal with stop/restart or snapshots at every turn, compare the live list and optional item to an independent vector/multiset oracle, check exact source-bound measured Work and physical receipt, test each denial axis at each phase, and exercise real allocator failure and Work refusal without discarding retained fields. The existing old retained-clone test also has the conservation idea but is an unmigrated old-API caller; the new native law does not yet establish that coverage.

The movement primitive Source contract check was red before implementation and green after (1 Bun test, 10 assertions, Ajv plus SQLite admission comparison); it is a schema/source contract check, not Rust execution. Genuine EffectBank movement tests are authored but not compiled or run.

Root later bounded re-read of current edit/list signatures confirmed swap/pop quote failures are PagedListError, with the existing explicit Edit conversion; child movement failures are ValueError mapped to Work, and reserve keeps its typed Allocation fields. The suspected missing From<ValueError> at quote `?` sites is not a concrete error because those sites return PagedListError. Current edit derives child progress.work from actual turn.work and records cursor-state work after child success. This is another static check, not Rust compilation or proof of the post-admission refusal case. No Source edit/test execution by root.
