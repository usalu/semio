# Native Windows Temporary Drive

The temporary port now exposes `nativeTemporaryWindowsDosDeviceV1()` as a lease factory passed to `nativeTemporarySystemPortV1`. It opens a per-letter local named mutex, checks `QueryDosDeviceW` rather than filesystem existence (including dangling definitions), and defines a raw NT target only for a free letter. It holds that mutex and native library through the lease; cleanup verifies the current target and uses exact-match removal. A pre-aborted request stops before port calls. UNC targets are represented with the NT UNC prefix.

Windows references: [DefineDosDeviceW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-definedosdevicew), [QueryDosDeviceW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-querydosdevicew), [CreateMutexW](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createmutexw), [WaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject). DefineDosDeviceW pushes mappings, so the query and cooperative lock are essential; exact-match removal avoids deleting an unrelated target. A named mutex is thread-owned and abandoned if its owning thread exits.

The focused native Windows test initially ran through repo tools exec --light before the later instruction to use ordinary admission. It passed five cases and 16 assertions: asynchronous lease retention with SQLite ordering oracle, Unicode directory mapping and identity, dangling mapping refusal, pre-cancellation, and a child process observing the mapping followed by cleanup. One early run exposed an incorrect UTF-16 comparison; the test-created Z: mapping was queried and removed with an exact target check using the retained input script native-drive-test-cleanup.ts. The corrected run passed and no test mapping remains. A normal 768 MB capacity-reserved rerun was requested after replacing --light, and is pending admission at time of this report. Language-neutral drive vectors and schema were subsequently added, with a SQLite oracle.

The lock coordinates participants using this convention, not arbitrary external processes. A forced process or owning-thread death can leave a DOS-device definition behind; subsequent attempts refuse that mapping and do not remove it. A non-cooperating program may race the check or replace a mapping; ownership checks fail closed and cannot guarantee global cleanup. The mutex is held on the calling runtime thread, so the lease must be closed on that same thread. Cross-platform import does not load kernel32 outside the Windows factory call. Production provider adoption and the MSVC smoke remain owned by the publisher.

## Governed Rerun

The original session 13988 could not be recovered. Its capacity request had disappeared, which alone did not establish its exit status. A native `process.kill(19648, 0)` probe in the governed input script returned ESRCH before the final rerun, establishing that PID was absent at that point. The first replacement run failed one assertion: the child exited 0, but repo emitted a normal capacity notice to stderr. Its cleanup executed. The assertion now requires the child exit code to be zero and retains stderr for a real failure.

The final ordinary 768 MB capacity-reserved run completed with outer exit 0 and explicit inner exit 0: six tests passed, zero failed, and 22 assertions passed. This includes the schema-described neutral free and dangling vectors compared with SQLite, Unicode directory identity, actual child access while the lease is held, exact cleanup, occupied/dangling refusal, async retention and pre-cancellation. The generated state, stdout and stderr files contain both the failed intermediate run and final run; they are disposable generated output. The provider integration and full MSVC smoke are separate from this focused validation.
