# Dependency Replay Cost

Source inspection only; no timing or live-branch inference. The all-selection build gate loops sequentially through sealed sync scope rows, verifying one generation receipt and one installed ledger per row until first mismatch; six rows permit up to six of each. Generation receipt verification defaults to the complete check; a subsequent recheck mode skips provider observations. Execution-observation replay separately runs twice around a custody recheck.

The logged store-input-replay marker instead names descriptor input-group verification: it checks each input directory identity, file name and descriptor stamps, and rehashes complete file contents. Capture immediately performs this replay. For a producer attempt existing/resumable inputs form one group and fresh staged inputs form at most a second group. Each full fence replays all groups accumulated at that point, and also checks store, workspace custody and preservation Source.

Normal fresh installer path has three full fences per fresh scope, plus one per fresh ready write; optional borrowed-provider/singleton publication adds three. The Source binding loop uses a full fence every 64 bindings, with endpoint-only checks between; fixed initial, readiness and final fences also apply. Cache purge, reuse and retry branches add calls, and attempts can repeat. Thus the replay is at stage and scope boundaries and every 64 binding transitions, not inside each input-file or provider traversal. Its rough repeated work scales with the total grouped bytes multiplied by the reached fences; exact executed count and current scope are not observable from the marker alone. Existing-only build may return before group capture; publish can capture and repeatedly fence existing material.
