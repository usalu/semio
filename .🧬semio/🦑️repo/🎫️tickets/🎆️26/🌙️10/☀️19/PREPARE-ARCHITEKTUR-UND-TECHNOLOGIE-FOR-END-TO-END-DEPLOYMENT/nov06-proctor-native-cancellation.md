# Native Proctor Cancellation

The standalone launcher now retains each actual signal, aborts acquisition, and waits through the existing owned proctor `stop()` and `exited` cleanup after cancellation. A signal received during acquisition is checked before launch. Normal exit still returns the child status; cancellation preserves its original reason, and a cleanup failure is reported with the original failure first. The course stack's existing cleanup path was not changed. On Windows the existing owned stop uses the child-tree termination path; the standalone handler no longer relies on the no-op Windows `interrupt` for termination.
