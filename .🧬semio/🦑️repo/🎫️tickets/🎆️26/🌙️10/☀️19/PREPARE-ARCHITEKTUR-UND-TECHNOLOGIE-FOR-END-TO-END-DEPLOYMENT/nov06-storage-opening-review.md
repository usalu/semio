# Native Storage Opening Review

Static source review only; neither live call site nor readiness is established. No live process, cache, lease or namespace was modified, and no runtime test was performed.

## Opening path and limits

- 🧰️framework/🔨️modules/🏃️process/📦️artifacts/🏗️native-build/💾️storage/🧱️fixed/🟦️.ts:113-118,167: ordinary open retains a shared image guard before boot healing and persistent-state validation. A mounted receiver captures facts, constructs the borrower, then awaits recheck before return. Inactive, absent, unpublished or pending-publication state releases SH before acquiring EX for preparation; EX rechecks state. Receipt is bounded to 4096 bytes, validates platform and declared envelopes, single-link regular anchor identity and mounted directory; receipt stamp and backing identity are reread. Fact capture additionally preserves mapping, device, filesystem envelope, directory/root identities and allocated-byte bound. The shared-to-exclusive handoff requires original facts to match across the guard gap.
- .../🧱️fixed/🟦️.ts:102-105,187-198 and .../📁️directory/🟦️.ts:128-149: each mounted open observes mapping during persistent state, again during fact capture and again during recheck. These observations repeat bounded anchor reads and synchronous metadata operations. Directory mapping checks the anchor and identities of root/volume; the inspected mapping path itself does not traverse the mounted namespace. The recheck takes a separate queued shared mapping lease (.../🔒️mapping/🟦️.ts:20-21) and can wait there before return; control and abort are passed to acquisition. These facts do not locate the live processes.
- .../🧱️fixed/🟦️.ts:167 calls healNativeProcessBootV1 while image SH is held. .../🌐️platform/🥾️boot/🩹️recovery/🩺️heal/🟦️.ts:124-139 memoizes one recovery promise per lease directory and returns that same promise to later callers. A later caller has no independent abort race while waiting on the first caller’s promise; its signal is checked only after the await returns through the subsequent path. Conversely the first caller’s abort rejects the shared promise for other waiters. This is a cancellation coupling; use independently cancellable waiting around a shared recovery owner while preserving recovery custody. Recovery publishes stage progress, but remaining mounted-state/fact/recheck steps have no equivalent phase progress visible here.
- Mapping EX acquisition rejects upgrades from a live same-resource mapping frame (.../🔒️mapping/🟦️.ts:24); child scope checks reject closing a parent within its own child (.../🧱️fixed/🟦️.ts:79-86). No unconditional recursive acquisition or self-wait was established in the inspected open path. Cleanup drains accepted pending work (.../🔒️mapping/🟦️.ts:19-21,29-30), so a dependent operation that never settles can delay closure; this is a conditional custody dependency, not evidence of a current deadlock.

The detailed recovery implementation and callers beyond the fixed receiver were not exhaustively audited. This review does not rule out a traversal elsewhere, prove a latency cause, or identify the current instruction of either live job.
