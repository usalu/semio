# Native Extractor Ownership Follow-Up

The extractor now accumulates file and directory creation records directly through compiler and cabinet extraction, with cleanup installed before either phase and retained through manifest generation. It no longer re-enumerates the completed tree to claim ownership. Acquisition records the identity from the created file handle while it is still open. A replacement regression verifies that cleanup refuses an object whose identity differs. Native suite 40948 failed that regression when the test used an `Lstat` identity; the test was corrected to capture identity from an open file handle as production does. Native suite 85803 then passed with exit 0 and 2.006 seconds inner test time. Earlier run 6511 failed before the ownership helpers were implemented.

Cabinet output is reserved with `CREATE_NEW` and a metadata-only handle that shares reads and writes but denies deletion, and the same handle remains open across SetupAPI. A real pinned cabinet test, session 27242, passed extraction, cancellation cleanup and a rejected concurrent rename with exit 0 and 2.770 seconds inner test time. The implementation checks for extra hard links. Full pinned extraction session 6205 passed `TestPinnedCompleteExtraction` with exit 0, test duration 465.09 seconds and Go package time 480.703 seconds. It completed 494 compiler and 4,453 SDK files, then asserted the exact pinned inventory digest and removed the test stage. The runner streamed rather than saved its initial output; a partial remaining tail is in generated output, and the earlier raw log is incomplete.

These checks do not establish hostile same-user race-proof cleanup: directory creation still obtains identity after `Mkdir`, and identity-check-then-remove is not an atomic deletion. The publishing owner must enforce private stage custody, and must clean its allocated stage after a forcibly terminated child. The CAB handle protects its reserved target from rename during SetupAPI but does not itself prove custody of every parent directory.

The actual CLI acquisition ran as session 98257 into newly allocated ticket-generated directories after D: reported 958,332,424,192 free bytes. The command returned exit 0 and emitted all 47 progress completions. A separate Node/OpenSSL 3.5.9 pass verified all 47 payload sizes and SHA-256 values, totaling 394,016,409 bytes, plus the 18,343,591-byte catalog digest and exactly 48 input files. Exact child status and output were recorded in the generated directory. The retained invocation input is `nov06-live-msvc-acquire.cjs`. This proves the observed acquisition only, not publication, source-bound invocation, or provider readiness.
