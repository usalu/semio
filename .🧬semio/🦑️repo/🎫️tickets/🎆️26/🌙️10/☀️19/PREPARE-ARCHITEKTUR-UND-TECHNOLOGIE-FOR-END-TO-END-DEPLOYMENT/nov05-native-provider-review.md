# November 5 Native Compiler Provider Independent Review

Read-only source and retained report review. No package was run, no SDK tree was traversed or hashed, and no IDE, WSL, virtual machine, installer, security policy, global environment or Git change was made. The owner reports catalog/payload verification, SDK and compiler staging, and real native C and Rust smoke; those executions were not repeated here.

## Provider Readiness Blocker

The current portableMsvcSystemV1 reads a four-field JSON receipt from the computed store and portableMsvcEnvironmentV1 selects the provider when that JSON matches static values and ten named paths are regular files. Those facts do not authenticate a managed publication, the receipt's origin, full inventory or actual file content. A fabricated receipt and arbitrary files at those names satisfy the selection; lstat of the leaf does not authenticate linked ancestors. Receipt existence and a small file sample therefore cannot establish a verified provider. The durable store must bind a trusted, owned, no-follow publication to verified payloads and full output identity, reject partial/stale/raced or linked stores, and establish readiness from actual required SDK/CRT and compiler content. Tests should include forged receipt, replaced bytes, linked ancestors, missing non-sampled files and interrupted publication.

The authored explicit override list omits potentially relevant caller selections such as Cargo target linker, target-specific CC/AR, LIBPATH and WindowsSDKVersion. Determine actual registered cc/Cargo precedence and preserve explicit caller intent, including case-insensitive Windows environment names; add neutral cases for each relevant variable. The current sample checks CC and LIB only.

## Retained Extraction Evidence and Limits

The independent Bazel catalog hash anchors catalog content; the report properly separates that from Microsoft catalog signature verification and keeps differing VSIX declared sizes separate from served lengths. The five VSIX payload checks use publisher catalog SHA-256; the eight MSI and 34 CAB checks are reported as matching size and hash. The Go MSI metadata reader opens a read-only database and queries tables. The CAB extractor uses SetupIterateCabinet, not an MSI administrative action. The inspected smoke sets real staged tool paths and does not create fake vswhere or vcvars.

VSIX extraction checks member path segments, Windows reserved names, case-folded duplicate destinations, regular member type, per-member size and UTF-16 path length, and creates files exclusively. Its total count and aggregate size are checked at the end, rather than enforcing the aggregate bound before/during writes; it reads each archive for hashing then independently opens its path for ZIP extraction, leaving a substitution gap. The CAB extractor likewise hashes then reopens paths via the system API; it validates requested member IDs, counts and sizes, but reads its generated file plan without deriving it again from authenticated MSI bytes. SDK materialization compares that plan with generated MSI table JSON and staged file sizes, not file content hashes, before rename. These are limitations on durable provenance, not evidence that the reported staging or smoke failed.

Staging and extraction are in fresh ticket-generated directories and source checks include no-follow leaf checks in materialization. The inspected programs do not provide a full ancestor identity/revalidation protocol against concurrent substitution, and some failure paths leave partial output. A durable publisher needs explicit cancellation, bounded streaming, identity-preserving input verification, owned stage cleanup, safe final no-replace publication, and full content verification. Review the ASCII junction's exact-identity lifecycle separately when integrating it: the report says it was removed after the child, but this review did not execute it. No claim of race-proof extraction follows from exclusive leaf creation.

The reported native C/Rust hello demonstrates actual staged compiler execution under that controlled environment; it does not prove durable store ownership, a Cargo native build-script dependency, canonical course gates or complete SDK provenance. Full dependency-backed suites remain pending.
