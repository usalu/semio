# Preflight Phase Contract Review

The current preflight observes each required tool against the process environment before free-space, exchange, and case checks. This cannot discover a private held compiler, and means host refusal occurs only after tool observation. Windows policy explicitly requires msvc-linker and rust; neither may be removed, and existence or a publication receipt is not compiler authority.

The physical admission phase must validate the actual platform and architecture, filesystem free bytes, and applicable directory exchange and case capabilities before entering any managed toolchain environment. Preserve the Windows journaled fold-safe refusal mapping and propagate unrelated errors and cancellation. Unsupported platform, architecture, insufficient bytes, failed exchange or case probe, thrown probe, and cancellation must each leave acquisition and completion uncalled. The successful host path acquires genuine toolchain custody, probes every policy requirement within its environment using native probe authority, releases custody on every outcome, and reports completion only after successful observations. Missing tool, failed acquisition, probe error, or cancellation must not complete. Check cancellation at phase boundaries and during the tool loop; do not transform cancellation into an ordinary missing-tool diagnostic.

The closed Facts schema requires tools even before observation, and the existing combined decision matrix and Python oracle assert ordered diagnostic output for complete facts. Preserve those semantics or update schema and fixtures together with a separate physical phase model. The policy schema closes platform keys and the Facts schema restricts fold-safe to Windows. Existing matrix tests use Ajv as an independent schema validator and Python as the verdict oracle; they do not establish orchestration order or custody.

Add a language-neutral scenario corpus with an independent oracle for ordered observable traces and outcomes: host failure on each axis; cancellation before admission, before acquisition, during a probe and after acquisition; acquisition failure; absent or throwing tool; and successful tools observable only inside held environment. Assert no acquisition on every host failure; assert no tool probe before acquisition; assert held environment during each tool probe; assert release on acquired paths; assert no completion on any failure; and assert completion after successful probes. Use Ajv against the authored scenario schema and a separately implemented Python decision table as third-party and independent checks, rather than making mocked traces alone the oracle. Include the ordinary PATH fallback as well as native tools and verify tool requirements remain identical to policy on all three platforms.
