## The batch `churn` (78 edits, all behaviour-preserving)
1. New leaf `🏗️build/🧂️text-bytes/🟨️.mjs` (+ `.d.mts`): `sha256HexV1` (one call, `crypto.hash`, no Hash object, no digest buffer), `sha256FirstByteV1`, `sha256DelimitedHexV1(texts, delimiter, first?)` (= chained `update(text).update(delimiter)`, one string, ASCII delimiter only), `compareUtf8V1` (UTF-8 byte order of two texts without encoding them; falls back to `Buffer.compare` only for a pair that involves a surrogate or a unit above it), `utf8TextV1` (decode in place, no `Buffer.from(bytes)` copy). Bench (Bun 1.4.2, 20 k paths x 20): first byte of a path digest `createHash` 1394 ms vs `hash(..."hex")` 226 ms vs memo 22 ms; 15 k-path roster key 19.4 ms chained vs 9.6 ms joined.
2. Hashing: `recordKey` and `valueDigest` (`⚡️caching/🗃️records`: no `Buffer.from(string)`, all-text keys are one string), `splitInputClosureV1` (cut decision remembered per path, bounded 131,072, cleared by `releaseInputMemoryV1`), `capturedInventoryV1` key, chunk and lock closure keys, Cargo `sha`/`bytes` (`📥️inputs/🦀️resolution`), and all 22 single-expression `createHash("sha256").update(x).digest("hex")` of the observation module become `sha256HexV1(x)`.
3. Copies: the four `JSON.parse(Buffer.from(hit).toString("utf8"))` read the stored record in place; `settleRead` keeps the read buffer itself when the caller asked for an encoding (the bytes are never returned then), so the 128 MB settled-read cache holds no second copy of a text read.
4. File analyses in process: `memoizedFileRecord` remembers the JSON image of the analysis of a settled file (stamp equal, same racy rule as `settledReads`, 64 MB bound, dropped by `releaseInferenceMemoryV1`); a later asker replays the file row and parses the image: no read, copy, TOML parse, stringify, SHA-256, `Buffer.from(image)` or record-store put. `cargoSourceInputs` answers per fact table (one per project) through `memoizedObservedComputationV1` (rows replayed to every receiving scope, the caller gets its own list).
5. 16 distinct regex literals at about 30 sites (module constants instead of one RegExp object per call) in 8 modules (list in `🧪️tests/🧂️hoisted-literals/🔣️.json`), the Rust string-literal fast path (a literal without a backslash is its inner text, no `JSON.parse` + exception), and `rustInputTokens` reuses its three sticky patterns.
Not done, with reason: streaming JSON (the inference record already is a header line plus separately addressed blocks, no whole-record parse on this path; the generation loader is gram2-g's `json-stream`/`index-chunks`), interning path strings beyond the existing `graphStringInternerV1` (the strings that remain are row paths already shared through `canonicalObservationV1`, and key strings, which row-table removes), a global cache in `compileBuildInputPatternV1` (tried; two existing laws pin "compiles each reached glob once per operation", so it was removed again), an explicit GC checkpoint (see Open).
