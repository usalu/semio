  1. PRODUCT RACE (fixed). `Listener::bind` (`🌀️daemon/🚚️transport/🦀️.rs`, unix) claims `<key>.lock` with `lock_runtime_file` (open(create) then exclusive `try_lock`) and then `sweep`s every other `*.lock` in the SHARED runtime dir `/tmp/semio-dashboard-<uid>` with the same probe. A sweeper whose probe lands between a starting daemon's open and its lock holds that lock, so the starting daemon is refused with "workspace dashboard daemon is already listening" and its serve thread dies. The test harness (`Daemon::start_in`) ignored the thread and polled 90 s for a daemon that was already dead: panic `the daemon must start serving` (dtest21). Any two `repo dashboard` daemons starting together on one machine can hit this. FIX: `bind_guard`: one blocking exclusive lock on `<runtime dir>/bind.guard` (extension not `lock`, so never swept) held for the whole bind (claim + sweep + socket), never while serving. No clock, no retry.
  2. HARNESS (fixed). `Daemon::serve_in`: no 90 s wall clock; polls connect, and as soon as the serve thread has ended it panics with the daemon's own error (`the daemon ended before it served: …`).
  3. HARNESS + FORK (fixed in the harness, found while proving 1). `Daemon::restart` re-serves the same root inside the test process, and the workspace lease (`WorkspaceLease`, flock on `daemon.lock`) was still refused ("already running") whenever ANOTHER test thread was inside `Pty::spawn` (fork→exec window: the child owns a copy of every open descriptor, so of the old lease, until its exec). Reproduced in isolation (8 forking threads x 400 lease re-acquisitions: 65-349 refusals; throw-away `[DEBUG]` test, removed). Production is unaffected (a daemon restart is a new process, every descriptor is CLOEXEC); the harness retries exactly that one refusal after a predecessor (`predecessor` flag), which ends when the child has exec'd; any other early end panics.
