## The law (red on base, green with the fix, independent oracle)

`🏗️build/🧪️tests/🧬️policy-literals/🟦️.ts` + one directory `<emoji><module>/🔣️.json` per module (row schema `🧬️schema/🔣️.json`, Ajv strict): for each row (1) every policy key has EN and DE descriptions (DE differs from EN, both real sentences) and the values are closed under Ajv strict, (2) the exported frozen object equals the schema const, (3) no source of the row holds a policy value as a numeric or string literal (numbers >= `minimumNumber`, top-level strings and string lists >= `minimumText`; module specifiers excluded; the few sharing a value by accident are listed with a reason: basis-point scales, 0o400, a 32-digit digest prefix, the 512-byte block), (4) the findings equal those of the independent Python lexer `🐍️.py` (no parser library; the TypeScript parser is the third party, the lexer is checked against it on 3 tricky corpora with regex, nested templates, hex/octal/underscored numbers). Red on base: with only schema + row applied the law reported every literal still in the code (revision: `65536` x2, `8388608`, `256`, `2000`, `4096`; observation: `1024`, `64` and the rest until each was moved); green after the code edit. Adding a module is adding one directory.

Two independent oracles beyond the law: Ajv strict (third party) over every policy definition, and for the revision bounds the existing SQLite oracle of the opening-store test.
