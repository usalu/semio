2. **Test classes** (`BZ/🚦️test-classes/`, schema `🧬️schema`, table `🔣️.json`): `size` small/medium/large/enormous = Bazel `timeout` short/moderate/long/eternal (60/300/900/3600 s; a test checks that every neutral level budget 15/300/900/1,800 s fits its mapped size), `witness.from`, `default` (enormous = the former `eternal`, no shards, no retry), ordered `rules` (target and project globs, first match wins, `evidence` measured|declared with a reason), `measure` constants, EN/DE `messages`. `bazelTestPlanV1`, `bazelTestAttributesV1` (`size`, `timeout`, `shard_count`, `flaky`). The old constants `testTimeout`, `testInputLimit`, `sharding: unsupported`, `bazelTestWithinLimitV1`, `bazelTestTimeoutV1`, `kinds.json` and its schema are deleted (no legacy).
3. **Neutral test protocol** (`F/🧪️testing/🚦️protocol/`, `node:` built-ins only so the execution closure stays inside the framework): `SEMIO_TEST_SHARD=i/n` (1-based, sorted round-robin), `SEMIO_TEST_SHARD_STATUS_FILE`, `SEMIO_TEST_XML_OUTPUT_FILE`, `SEMIO_TEST_REPORT_OWNER`, `SEMIO_TEST_REPORT=0`. A tool table (data) names how `bun test` and `vitest run` take `--shard` and a JUnit file, and recognises `cargo test`, `go test`, `pytest`, `dotnet test`, `ctest` (no shard, no JUnit, reported as one synthetic case). Results from several commands and several processes merge into one `<testsuites>` file under a directory lock (first write of the owner starts a fresh file). Without an explicit file, a task named by Bazel (`SEMIO_TASK_*`) or Nx (`NX_TASK_TARGET_*`) whose target is `test` or `test-*` gets `<root>/.cache/b/o/m/tests/results/<project>-<hash>/<target>/test.xml`. Hooked into three spawn points: `runBudgetedTestCommand` (cargo, vitest, bun via the budget runner), `captureOwnedCommandV1` (the repo's own `TestScript.runBunTests`), `runRepositoryCommand` (plugin-composition style). The five names are added to the Nx plugin's `taskOnly` environment policy so they cannot change a graph identity.
4. **Bazel to protocol** (`script.ts`): the test launcher maps `TEST_SHARD_INDEX/TEST_TOTAL_SHARDS/TEST_SHARD_STATUS_FILE/XML_OUTPUT_FILE` to the protocol (`bazelTestEnvironmentV1`, closed schema, absolute paths) into the child environment, and in a `finally` `settleBazelTestV1` makes Bazel's expectations hold: a shard no command honoured still touches the status file (Bazel otherwise FAILS a sharded test: measured, "did not advertise support") and prints an EN/DE warning that the shard ran the whole task, and a test no command reported gets one fallback result with the failure text.
5. **Measurement to table** (`BZ/🚦️test-classes/📐️measure/🐍️.py`): reads Bazel build event files, takes the slowest shard per run, p95 per label, and proposes `measured` rules (smallest size covering 3x p95 from 5 runs on; shards only for task ids named `--shardable` and above 300 s). The proposal is admitted by the same schema; tested on real BEP files.

## Why the class table ships without rules

There is no measured run time of any test in the repository (the freeze forbids real task runs), and the neutral contract bounds a task by its phase deadline, not by a size: tightening a timeout without evidence would turn slow cargo tests red. So `default` keeps what every test had (`enormous` = `eternal`), a rule needs `evidence` and a reason, and `measure` produces the rows after the first real runs. Sharding likewise: the repo already splits suites into 860 distinct `test-*` targets (1,787 of the test-family tasks are `bun ./📜️script.ts test…`), cargo and go cannot take a shard, and nothing in the tree is known to be a long multi-file `bun test` target; a mis-declared shard is safe (it runs the whole task, with a warning) but wasteful. The mechanism is proven end to end below; the first rows belong to the first measured run.
