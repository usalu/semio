## Finding: why the suite was red on the live store

`optional-cache` passed `process.cwd()` as the repository to every store API, so it used the checkout's `.cache/b` graph image, its lease image and its lease queue:
1. the quota laws read the live optional store (1 GiB cap reached by peers: 1073741825 > 1073741824) and queued behind peer builds (`Original resource loan deadline exhausted`), classic non-hermetic reds;
2. the nested-maintenance law only "worked" when the live store already held at least one optional byte: it seeds a pressure file of `minimumPressureBytes - used` = 536870913 bytes on an empty store, one byte over the closure proof's `maximumFileBytes` (536870912) ("Ordinary single-link bounded closure proof leaf required"). A private empty store exposes it; the batch seeds a 1-byte optional leaf first (the implicit precondition, now explicit);
3. on a fresh private checkout (mirror) the same file already showed it: base 7 fail there.

## Open, not fixed here (classified; owner decision)
The 3 remaining reds are independent of store isolation and were masked before:
1. **nested maintenance** and **observation publication**: the pressure retirement starts closure-read workers (`prepareClosureReadSourceV1` calls `receiveScriptProcessInvocation(process.env)`), whose envelope must be an ancestor of the ambient invocation. Under the official envelope with a `ws.invoke` Original: "Nested Original process envelope must preserve its actual parent". With the runner's own Original (`withBuildTestInvocationV1`, tried and dropped): "Exact Original Graph format owner required" (the graph store format needs the native-caller Original). Bare: "Actual admitted Source resolution map required". A production decision: closure workers should receive the maintenance caller's invocation (or the format owner check accept the runner Original). Also the maintenance custody should take the workspace from the image or the writer scope, not `process.cwd()` (files: `🔧️custody/🟨️.mjs` `requireRepositoryBuildGraphMaintenanceImageV1`, `🧾️closures/🟦️.ts`, `🗂️members/🔎️scan/🟦️.ts` packet root, `👷️closure-read-worker`).
2. **writers-serialize** (parent) and its **contender** child: the contender wraps `options.control` with `requestedCompilerAdmissionControlV1` but leaves `options.signal` (lease API: "Original lease signal identity required"); with the signal replaced the child fails at `publisherObserved` (its `cache:leases-store` progress event never fires once the parent holds the lease image). The test also waits on the host-level shared lease of the `bun` runtime binary (`~/Library/Caches/semio/runtimes/bun/*`), which queues behind peers (seen: 17 s). Stale since the lease API change; needs its own lane.
3. the unrelated stale directory `optional-cache/.cache/b/{c,l}` + `boot-recovery` (10-22, a run with cwd = the test directory before `requireRepositoryWorkspaceRootV1` existed) is still in the source tree and has a mounted lease image (`mount | grep optional-cache`); not mine, not touched.
