## What it is
`repo fleet status [--json] [--limit=<n>]` is a light front-door command (no graph, no lease, no build, no write except the host sample cache `repo capacity status` writes too). It answers from the six existing status readers in parallel and prints one picture, EN and DE, as compact text or as one JSON document that is validated against a closed schema before it is printed. The MCP tool `fleet_status` returns the same document (query tool, `--json` bound).

Sections: runs (joined across the ledgers: state, operation, phase and counter, time left, age, priority, code freshness, memory admitted against really used), queues (graph custody, memory queue, every lease queue, each waiter with an estimated waiting time), memory, Bazel servers, storage against capacity and the machine budget, sealed implementation (drift, blocked promotions), graph generation (number, how built, age, owners covered by the last verification), findings (stuck/stale holders, cycles, pressure, under-reserved runs, long waits, low disk, full images, blocked promotions, failed readers), sources (a reader that fails or hangs names itself and leaves only its own section out).

Module `build/🚢️fleet-status/`: `🟦️.ts` pure aggregation + renderers, `📥️readers` the six readers, `⌨️command` the door entry, `🧬️schema` closed schema (facts, report, policy, EN+DE texts), tests. Three Bazel leaves changed: new read-only `🧵️sessions/📖️status` (server directory, slot list, server pid, slot state) imported by `🔌️port` and `💾️storage`, so the status command reads the Bazel servers without loading the build tools.
