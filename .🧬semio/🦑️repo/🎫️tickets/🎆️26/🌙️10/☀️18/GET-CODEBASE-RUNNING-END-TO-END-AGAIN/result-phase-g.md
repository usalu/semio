## Design (schema first, EN + DE)
- Phases of one admitted run: `assembly` (door capture, loader), `plan` (graph served from a current generation), `rebuild` (this run builds the graph: an excursion, bounded by the builder custody and the compute slots) and `execution` (the tool). Schema: `Phase` enum, `Grant.phase`, `Estimates.{phaseReferenceMegabytes 1024, rebuildPriorMegabytes 4096, rebuildShareBasisPoints 5000, maximumRebuildSlots 4}` (build policy + 3 fixtures + oracle policy), protocol `marksEnvironment`, `phasesSuffix`, `maximumPhaseTransitions`, message `phased` (EN `... at least {floor} MB because of its {phase} phase`, DE `... mindestens {floor} MB wegen der Phase {phase}`).
- KEY = PHASE x CLASS: execution learns under the class lineage of its task as before (ratio against the default of the request); `assembly`, `plan`, `rebuild` learn under ONE global class each (`phase:assembly|plan|rebuild`, absolute megabytes against a 1024 MB reference): a covered graph is small and a rebuilt one is large whatever the target. The execution class never sees the graph build; a run that never marks phases is recorded exactly as before (law below).
- MARKS (cross-process, no ack): any process of the run appends `<phase> <ms>` to `grants/<id>.phases` (`markHostCapacityPhaseV1`, library `markBuildCapacityPhaseV1`, lazy so a run without grant loads nothing). The holder reads the file every second in its lender tick, takes a closing reading at the boundary, tags every reading with its phase, and on release cuts the run into segments (`hostPhaseSegmentsV1`: peak, duration, time of the first reading within 5 % of the peak). A nested invocation that only INHERITS a grant gets `SEMIO_HOST_CAPACITY_PHASE_MARKS=off` and cannot move its parent's phases. Marks at: runtime before the graph load (`plan`), before the backend execute (`execution`), `show`/`graph` before their graph load (`plan`); graph build: `rebuild` at the start of `prefetch` and in `withBuilder`, `plan` after `withBuilder`.
- ESTIMATE (`estimateHostPhasesV1`): execution as before, learned global phases blended with the request's size at its minimum jobs as prior (the build against `rebuildPriorMegabytes`), reservation = the HIGHEST of the phases (they follow each other, so max, not sum), assembly/plan as a job-independent floor (`scaleHostRequestV1(..., floorMegabytes)`), ramp = that of the deciding phase (fix-g's time to peak per phase). Without learned global phases the answer equals the old estimate.
- RE-SIZING (`createHostPhaseResizerV1`, wired through the new gate port `resize`): entering a later phase the reservation falls to the highest need of the phases still to come (shrink only: no run ever waits for memory in the middle of its work) and counts in full for the time the deciding phase needs, measured from the grant start; entering `rebuild` it rises to the learned rebuild size, up to the whole memory above the floor, and falls back at the next boundary. A run served by coverage never reserves rebuild memory; the build is admitted by the builder custody + the compute slots.
- COMPUTE SLOTS (`hostRebuildSlotsV1`, `buildRebuildSlotsV1`): memory above the floor x `rebuildShareBasisPoints` / what a rebuild learned to need (prior 4096), 1..4; `slotCountV1` of the claim registry is lowered to it.
- A plan stretch that directly follows a build is NOT learned as plan (the builder still holds its memory until it exits); a run that never starts a tool is learned by its plan phase (so `show` learns instead of staying at 5120 MB forever).

## Open / honest limits
- The overshoot trade (see the simulation): with the shipped knobs (0.9 quantile, +25 %) a covered run is under-reserved in about 6 % of the runs, exactly the rate the old estimator has on a rebuild-free stream; the old estimator's lower rate on a rebuilding fleet was bought by asking 1.6x what covered runs use. Total memory used above reservations (build included) falls. The knob is `quantileBasisPoints`/`marginBasisPoints` of `estimates`; the iso-risk rows show the price.
- The closing reading of a phase is asked for when the holder sees the mark (within the 1 s lender tick), so up to one second of the next phase's growth is attributed to the previous phase (conservative for the global classes); readings between boundaries are the 15 s heartbeats, so a phase shorter than that is seen only through its boundary readings.
- Marks come from three call sites; a run that crosses none of them (cargo, dependencies) stays one unphased execution segment, exactly as before.
