## v2: what failed and how it is fixed

Cause (confirmed by reproducing the exact error in a law): the run phase (`runBazelTasksInStorageV1`) starts after `releaseBuildGraphV1` replaced the content of the graph (`projects`, `namedInputs`, ...) by throwing getters, and it also runs after a REUSED plan (`plan reused ... the planner was not started`), where no graph content was ever loaded in that process. v1 derived the declared names there with `bazelDeclaredEnvironmentOfPlanV1(graph, plan)`. The other graph uses of that function survive only because they hit memoized structures; my fresh `Object.values(graph.projects)` hit the getter. My v1 laws called the pure function with a live fixture graph and extracted only `writeBazelRuntimeV1`, so they never ran the statement in the run phase.

Fix (the run phase never touches the graph):
- `recordBazelDeclaredEnvironmentV1(workspace, graph, plan)` runs in `generateBazelWorkspaceV1`, where the graph is held (the planner child, also the only place a plan is made): it derives the names and writes `declared-environment.json` ({version:1, names:[...sorted]}) beside the workspace, atomically and only when the content changed; it returns the set for the runtime.json written at the end of generate.
- `readBazelDeclaredEnvironmentV1(workspace)` runs in `runBazelTasksInStorageV1` (`const declared=await readBazelDeclaredEnvironmentV1(workspace);`): reads and validates the record; a missing/malformed record is REFUSED in EN+DE (an empty set would silently drop a declared input). A reused plan finds the record of the planner run that made it (it is part of the recorded workspace outputs); a plan made before this build cannot be reused because the plan key holds the captured script identity, which changes with script.ts.
- No other graph read was added.

New laws (`🌿️environment/🏃️action/🧪️tests`, 8 tests):
1. "The run phase obtains the declared environment after the build graph was released": takes the REAL statements out of script.ts by AST (the argument `generateBazelWorkspaceV1` passes to `writeBazelRuntimeV1`, and `const declared=...` of `runBazelTasksInStorageV1`), executes the generate statement against a live graph (records the file), calls the real `releaseBuildGraphV1(graph)` from the graph module, proves the hazard (`bazelDeclaredEnvironmentOfPlanV1(graph, plan)` now throws `released-read`), then executes the REAL run statement against the released graph: it must return the same names. It also asserts the run function does not mention the graph-reading derivation and that a deleted record is refused in both languages.
2. Call-site law (3 `await writeBazelRuntimeV1(` sites end in `declared` or `await recordBazelDeclaredEnvironmentV1(workspace,graph,plan)`).
3. Record law: written once, same inode and mtime when unchanged, no temporary file left.
How it closes the gap: it executes the statement the run phase really runs, on the object state the run phase really sees (a graph released by the real release function), instead of the pure function on a live fixture. RED on the v1 batch: the same law (v1 script.ts + v2 module) fails with `RepoError: stale build.graph.released-read {}`, the exact g30 error; v2: 8 pass / 0 fail. v1 and v2 differ in the call-site law too (v1 3 pass/2 fail on this file).
Not covered by a unit law: the graph being released at some OTHER moment than in `releaseBuildGraphV1` (e.g. a different release mechanism) would not matter, because the run phase now reads no graph at all; and a real product run is still the final check.

## How the allowlist is derived (all from code, streamed, no repo run)

1. `actenv-tools/inventory.py` (streams, RSS guard 500 MB): every environment name the repository's own non-test code reads in the library + process trees: 254 names (141 SEMIO_, 113 others). Result is the fixture `🧪️tests/🧫️fixtures/🔣️.json` (`reads.delivered` 228 names, `reads.withheld` 26 with EN+DE reasons).
2. The task graph's own declarations: 1,108 `"env"` keys, 17 `valueEnv`, choice-value `env` maps (nx.json + project.json): SEMIO_TEST_LEVEL, SEMIO_TEST_BUDGET_MS, SEMIO_BUILD_BUDGET_MS, RUSTUP_TOOLCHAIN, RUSTFLAGS, CARGO_ENCODED_RUSTFLAGS, CARGO_BUILD_TARGET, NODE_ENV, BUN_ENV, PROCTOR_URL, PROCTOR_COURSE, STORYBOOK_SCOPE, SOURCE_DATE_EPOCH, SEMIO_BUILD_MODE, SDKROOT, MACOSX_DEPLOYMENT_TARGET, DEVELOPER_DIR, CC, CXX, CFLAGS, CXXFLAGS, LDFLAGS, CMAKE_GENERATOR, CMAKE_TOOLCHAIN_FILE, PLAYWRIGHT_BROWSERS_PATH, plus the 17 PRINT_NATIVE_*/dashboard parameters. These are NOT a static list: `bazelDeclaredEnvironmentOfPlanV1(graph, plan)` collects them from the plan at plan time (generate) (`env` rows in global/project named inputs and task inputs, `valueEnv` and `env` maps in task metadata), so a new declaration is delivered without a schema edit (derived at plan time, recorded in the workspace, read by the run phase: see v2). Needed for correctness, not only convenience: the fingerprint hashes `original[row.env]` (planner env), so an action that did not receive a declared input would run with a different value than it was keyed with.
3. Toolchain facts: Go `policy.environment` (CGO_ENABLED, GOARCH, GOEXPERIMENT, GOFLAGS, GOOS, GOTOOLCHAIN), GOROOT/PATH (go toolchain digest), RUSTUP_HOME (cargo digest), the native classes python/dotnet/cmake (🧰️toolchains), the platform profile env (darwin LANG/LC_ALL).
4. `{options.env.NAME}` interpolation in commands/outputs: only SEMIO_BUILD_MODE (42 uses). No `$VAR` in any project.json command.
5. Runtime facts: the live runtime.json names (72) classified one by one (see "Withheld on this Mac").

Classes (schema `🌿️environment/🏃️action/🧬️schema/🔣️.json`, EN+DE description and reason per class): host, temporary, locale, terminal, environment-kind (CI/DEVCONTAINER/...), repository (SEMIO_*, NX_*), rust (CARGO*, RUST*, MAKEFLAGS), native-toolchain (SDKROOT, CC/CXX/..., CPATH, LIBRARY_PATH, CMAKE*, OPENSSL_*, PKG_CONFIG*, `_LIB_DIR`/`_INCLUDE_DIR`/`_STATIC` suffixes, SSL_CERT_*), javascript (NODE_*, BUN_*, VITE_*, VITEST_*, STORYBOOK_*, PLAYWRIGHT_*), go, python-dotnet, package-manager (npm_execpath, npm_node_execpath, npm_command, npm_config_user_agent), git (8 names), directories (XDG_CACHE/CONFIG/DATA/STATE_HOME, XDG_RUNTIME_DIR; XDG_SESSION_* is not listed), graphics (WGPU_, VK_, MESA_, LIBGL_), windows (31 names + VSCMD_/VCTOOLS/WINDOWSSDK... prefixes). `denied` (3 regular expressions: TOKEN/SECRET/PASSWORD/PASSWD/PASSPHRASE/CREDENTIAL/COOKIE/AUTH/AUTHORIZATION/BEARER/SIGNATURE words, *_KEY / PRIVATE|API|ACCESS|SIGNING_KEY) withholds a credential-like name even inside an allowed class (CARGO_REGISTRY_TOKEN, BUN_AUTH_TOKEN, NX_SELF_HOSTED_REMOTE_CACHE_ACCESS_TOKEN, SEMIO_SERVICE_TOKEN, SEMIO_REMOTE_CACHE_TOKEN, SEMIO_HUB_LIVE_PASSWORD, SEMIO_REMOTE_CACHE_SERVER_TLS_KEY ...). Order: declared wins over everything (the build author's explicit, reviewable grant), then class minus denied. Names compare case-insensitively (Windows).

## Risk (honest)

1. WHAT CAN BREAK: only an action that read an ambient variable the build never declared. From code, per product:
   - course (`@teaching/architecture-course:build/:test`): PROCTOR_URL, PROCTOR_COURSE are declared `env` rows (delivered); PROCTOR_PORT/DATA and TEACHING_ARCHITECTURE_COURSE_WATCH are set by the task's own `execution.env` (continuous fixture); PROCTOR_MODE/MANIFEST/ALLOWED_ORIGINS, COURSE_MANIFEST, TEACHING_ARCHITECTURE_COURSE_E2E_* are set by the e2e harness for the child, not read from a shell. Low risk.
   - print (`@semio-tech/print-rs:test`): 49 `PRINT_NATIVE_*` names are opt-in test switches (default unset). The dashboard parameters of `test-native-grammar` declare them through `valueEnv`/`env` maps, which the declared walker delivers. A switch exported in an arbitrary shell is no longer honoured by a Bazel run unless the task declares it (that was an undeclared input of a cached task, i.e. a cache-correctness hole). Cargo build scripts: CARGO*/RUST*/CC_/CFLAGS_/BINDGEN_/OPENSSL_/PKG_CONFIG*/`*_LIB_DIR` delivered; an unusual `-sys` override with another name is not.
   - dashboard (`@semio-tech/repo-dashboard-rs:build`): cargo + linker only; JOURNEY_*, DASHBOARD_TEST_* are test-harness variables.
   - Services started by `launch`/continuous Bazel tasks that read credentials from the shell lose them: DATABASE_URL and DISCORD_WEBHOOK_URL (server worker), SEMIO_SERVICE_TOKEN, SEMIO_REMOTE_CACHE_SERVER_READ/WRITE_TOKEN/TLS_KEY, SEMIO_REMOTE_EXECUTION_WORKER_TOKEN, an authenticated SEMIO_REMOTE_CACHE_TOKEN for a NESTED Bazel (anonymous access is the documented fallback; the cache server itself fails closed for non-loopback hosts without tokens, loopback would print `serve.open-access`). Not part of the three product proofs. Fix per task: declare the variable as an `env` input row (explicit and reviewable); denied names are delivered when declared.
   - Linux/devcontainer GUI: DISPLAY, WAYLAND_DISPLAY, XDG_SESSION_*, DBUS_* are withheld on purpose (headless Chromium needs none; a headed run would). Proxies (HTTP(S)_PROXY, NO_PROXY) and SSH_AUTH_SOCK are withheld (builds are offline; proxies can embed credentials).
   - Windows: the class lists the system and Visual Studio names, case-insensitively; only fixtures cover it, no Windows run exists here.
2. WHY A PLAIN RUN PROVES NOTHING (v1 was in fact red in every run, see v2): runtime.json is outside every action key, so after landing a hot or cached run re-executes nothing and cannot reveal a withheld variable. Proof needs actions that execute: `--skip-cache` (every task gets a random fingerprint). Landing itself: the plan key changes (script.ts text) -> one replan; the narrow executor closure does not import script.ts (no ordinary action re-executes), the orchestrated parents (adapter closure holds script.ts) re-execute once, as after every earlier script.ts landing.
3. NOT DONE: the planner still spreads `process.env` into its own task environment (97 `e` rows, ignored by witness policy, envleak b1); replacing the spread by this allowlist would also shrink the plan-reuse key, but the planner reads declared inputs and toolchain names from that object and needs its own verdict. The Bazel CLIENT env (`client()`) is untouched (it needs the SEMIO_REMOTE_CACHE token for the credential helper).
