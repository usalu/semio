## Rule applied
AGENTS.md: external libraries only behind an interface; no exported API that requires an outside type; re-export explicitly. Per family: one owned boundary, direct usages moved behind it, public API of the touched crates free of the library. Where an owned replacement already existed in the repo (`pack-json`, the sync actor's reactor) it is used instead of a new wrapper.

## 1. tokio (group `tokio`, 8 files) — plugin-runtime and its gateway call site
- **Design (deviates from the report, on purpose).** The report put the reactor into `os-services`. Not done: that crate is documented as `sync`+`macros` only (no `rt`, no I/O driver), and the real document-socket reactor already lives in `os-store-sync-native` beside the websocket dial (`document_socket_io_reactor`, ticket 26/09/23 WG8). `plugin-runtime` kept a second, duplicate multi-thread runtime from the older 09-22 fix. Now one reactor: new `🌐️document-socket-reactor` module in sync-native exposes the owned `DocumentSocketReactor` (`shared()`, `enter()` -> `DocumentSocketReactorScope`, `spawn(task)`), `DocumentSocketReactorError`, and `ArtifactHost::pump_events_key(reactor, key, on_event)` (the broadcast receive loop with its `Lagged`/`Closed` handling now lives inside the crate that owns the channel). All re-exported through `store::sync`.
- `plugin-runtime`: `hub_socket_reactor()` returns `&'static DocumentSocketReactor` (was `&'static tokio::runtime::Runtime`), the two codec `enter()` sites are unchanged in shape; `gateway-backend::watch_hub_document` takes the owned reactor and the pump closure (no `tokio::sync::broadcast::error::RecvError`, no `subscribe_key`); the `tokio` dependency of `semio-framework-os-mcp-plugin-runtime` is gone.
- Behaviour note: the old pool was 2 worker threads, now the existing one `semio-document-io` thread drives I/O, timers and the event pumps (the pump handlers are non-suspending). Equivalent to what every actor already used.
- Tests (5 new in sync-native; the host method `pump_events_key` itself is covered by the mini-crate test only): one shared instance, spawn runs on `semio-document-io` without an ambient runtime, entered scope polls a timer on a plain thread, pump keeps order and ends on close, lagging receiver skips lost events.
- Residual: `subscribe`/`subscribe_key` still return `tokio::sync::broadcast::Receiver` and `OpenDocument.events` is a `Sender` in the sync crates (about 25 call sites, mostly tests, plus wgpu); design: owned `ArtifactEventStream` (`recv` -> `Lagged(n)`/`Closed`) in `os-store-sync`, callers migrate in one wave. Other `🌉️mcp` crates that declare tokio (`inference-tools`, `http-transport`, `hub-pair`, `hub-remote`, `inference-hub`, `workspace-host`, `gateway-tools`, `📦️packages`) use `tokio::sync::watch` in pub fields (`PairCompletion`) and `#[tokio::test]`; next wave (a `HostSignal` in os-services).

## 2. serde_json / serde (group `json`, 11 files)
- `plugin-runtime`: no `serde_json` left in production code. Roster, inference request and inference result travel through `pack_json` (`to_json_string` / `from_json_str`), the codec the router and the guests already speak. The wire records `ArtifactInferenceBudgetV1`, `CacheModeV1`, `RequestV1`, `ResultV1` (schema crate) gain `ToValue`/`FromValue` next to their serde and schemars derives (precedent: the report types of the same crate); `canonical_payload` of the result is `#[value(default)]`. `bind_inference_document` edits the body as a `pack_json::Value` (duplicate member = last value, as before). `serde_json` moved to `[dev-dependencies]` (the sqlite guest-input-slot test is its only user).
- `AppCommand::PureCommand.input` is still `serde_json::Value` (port crate; about 14 files across 5 modules plus tests). Not changed here: the port's value type is the MCP JSON-RPC layer's, a conversion shim would be a compatibility layer. What changed: the action-argument projection moved into the port as `action_input_arguments(&Value)`, so `plugin-runtime` never names the type. Design for the mcp JSON wave: `PureCommand.input: DslValue`, one conversion at the dispatch edge, schemars stays in the schema crate behind its own `schema` module.
- `plugin-host-imports`: `decode_json` through `FromValue` + `pack_json` (all targets derive `FromValue`: `MediaType`, `Vec<String>`, `ClipboardFragment`, `Vec<IconRenderExportItem>`); `serde`/`serde_json` removed, `pack-json` added. `guest-runtime`: the one presence decode is `PresenceUpdate::from_value`; `serde_json` -> dev-dependency. `operation`: `serde_json` -> dev-dependency (tests only).
- Not done: `plugin-host-wit` keeps `serde`/`serde_json` (`📥️ui-patch::decode_pack` and the tests deserialize `UiNode`, component, layout, style, accessibility, bindings, menu; only `UiNode` has `FromValue`, the other six UI contract types need it first).
- Tests (3 new, in `🔗️inference-artifact-binding`): duplicated body member vs the reference codec, non-object body refusal by name, and the **differential**: the owned codec writes the request and the roster and reads the result to the same documents as serde_json (`ToValue` vs `Serialize`, `FromValue` vs `Deserialize`, absent `canonicalPayload`, unknown result fields ignored).

## 3. wasmtime (group `wasm`, 16 files)
- New `wasm` port module in the engine crate (`🔧️engine/🔌️wasm-port/🦀️.rs`): the only module naming `wasmtime`/`wasmtime-wasi`; explicit re-exports of the 28 symbols the host layers use (`Engine`, `Config`, `Store`, `component::{Linker, Component, Accessor, HasSelf, StreamReader, ..., bindgen}`, `wasi::{WasiCtx, WasiCtxBuilder, WasiView, p2::add_to_linker_async, p2::pipe::MemoryOutputPipe}`), plus `generated_code_support` for `bindgen!`'s `wasmtime_crate` (hidden internals no list can enumerate; generated code only).
- `plugin-host-imports`, `guest-runtime`, `operation` and `wit-bindings` no longer declare `wasmtime`/`wasmtime-wasi`; the engine crate is the single pin (version + features comment moved there). Their sources use `wasm::...` (34 mechanical path rewrites in 7 files, each count checked against the pre-edit grep); `wit-bindings` generates through `wasm::component::bindgen!` with `wasmtime_crate: ::semio_framework_plugin_host_engine::wasm::generated_code_support`. New edges `wit-bindings -> engine` and `operation -> engine` (static graph check: engine reaches none of wit/operation/imports/guest-runtime, no cycle). Test-only users (`interpreter*`, `guest-laws`, `describe`, host facade) already declare it in `[dev-dependencies]` and are untouched.
- Public surface rule: the engine's own signatures still name the types it pins (`Engine`, `Store`, `Component`); they are now reached only through the explicit re-export list (AGENTS: "reexport explicitly if the client needs it"). A trait-level wrapper (`HostComponentEngine`, `HostStore<T>`) is not done: every host layer implements `bindgen!`-generated traits over wasmtime's `Accessor`/`StreamProducer`, so such a wrapper is a rewrite of the generated-trait impls, not a boundary move. Residual and design in the previous report remain valid.
- Tests (3 new in the engine crate): the port names the pinned crate's own types (type identity), an empty component instantiates through the port alone, a WASI context + diagnostics pipe build.
