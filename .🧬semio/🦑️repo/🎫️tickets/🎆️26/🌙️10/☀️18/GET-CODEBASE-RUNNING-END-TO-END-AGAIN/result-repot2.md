## Group 4 - poison class (one rejected issued operation closes the shared Original)

New helper `FW🏃️process/🧪️testing/📥️invocation/🟦️.ts#registerIsolatedBuildTestV1(file, name, timeoutMs, body(checkpoint), rejection?)`. It is the designed one-test-per-process model made reusable: the parent test spawns `bun test <this file> --test-name-pattern ^name$` with a child envelope (`scriptInvocationEnvironment(original, …)`, `SEMIO_ISOLATED_BUILD_TEST=name`) so the child registers only that test and has its own process birth. The parent judges the child result *outside* the issued callback (a failing child does not close the parent's Original). With `rejection` the child must end with that primary failure after its body reported settled post-conditions via `checkpoint()` (used where the law's own teardown needs the closed Original). Negative control run: a failing isolated test fails the parent.

Applied: `compiler/⏳️phase` (4 variants, 3/3→6/0), `cache/📦️artifacts` (2 rejection-mode laws; failure text now flattens the scope `AggregateError`), `retention/📥️physical` (25 Original-using tests; also the 5 tests read `<ticket>/tooling-diagnostic/📜️script.ts` through `dirname(SEMIO_TEST_ARTIFACT_DIR)`, now the owning ticket path), `sdk/📥️source/🔗️derivative` (11 laws), `build/🧭️selection/👁️watch` (the watch fixture child: fault cases had never run because `new Function` lacked `buildOptionsV1`/`buildBooleanOptionV1`; one child per fault `fault-error|undefined|overflow`, authority child exits 1 by design, fault children 0; child funding assertion restated as funded projection, consistent with the `build/caller/birth` ruling), plus `withBuildTestInvocationV1` instead of a second `receiveScriptProcessInvocation` in `replan` and `coordinator/builder/💾️storage` tests.
