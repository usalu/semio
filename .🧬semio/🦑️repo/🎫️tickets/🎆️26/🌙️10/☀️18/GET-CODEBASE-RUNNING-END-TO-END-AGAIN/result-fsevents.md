# result-fsevents

Task: every macOS APFS cache image must carry `.fseventsd/no_log` and a Spotlight marker from creation, verified (and pruned) at every attach/open; tiny-image budget must account for filesystem overhead.

## Findings (measured, not assumed)
- The old fix (`mkdirSync(.fseventsd)+writeFileSync(no_log)` inside `catch{}` after `hdiutil attach`) cannot work on a fresh image: attach passes `-owners on`, and macOS then creates `.fseventsd` as `root:staff 0700 +ACL`. A user write fails EACCES and the empty `catch{}` hid it. It only ever worked on `noowners` mounts.
- `hdiutil create -type` cannot be combined with `-srcfolder`; `-format UDRW -srcfolder <seed> -size Nm -nospotlight` yields the identical fixed image (same bytes, same `imageinfo` Format) and the seed's `.fseventsd/no_log` + `.metadata_never_index` arrive user-owned before macOS first mounts it.
- `no_log` written after a volume is already mounted does NOT stop logging until the next detach/attach: `d` went 1552 -> 37 -> 169 -> 205 logs within minutes, `l` 122 -> 135 with a (hand-made) marker present. Hence pruning at every open, not only at attach.
- `mdutil -s` is not a deterministic oracle ("unknown indexing state", "kMDConfigSearchLevelTransitioning"). `.Spotlight-V100` absence + `.metadata_never_index` is used.
- APFS capacity (measured on 15 real fixed images, 32 MiB .. 4095 MiB): usable filesystem = image - 40,960 B, and 200 MiB less when the image is larger than 2 GiB (2048 MiB: no loss, 2049 MiB: loss). Empty volume metadata 0.68 MB (32 MiB) .. 16.3 MB (4 GiB), i.e. ~1 MiB + 0.4%. So `g`/`d`/`t`/`p` have 200 MiB less than their nominal size, and the lease image (63 MiB) holds 63.14 MB usable after metadata and journals.
- Pre-existing incompatibility, not changed: publication in the non-exact witness mode and `prepared-service` need an FSEvents UUID, which a silenced volume by definition does not have. `observeNativeVolumeEventServiceV1` now returns `null` for a volume with the `no_log` marker (documented "no service domain"); `current-exact-publication` is the matching policy.
