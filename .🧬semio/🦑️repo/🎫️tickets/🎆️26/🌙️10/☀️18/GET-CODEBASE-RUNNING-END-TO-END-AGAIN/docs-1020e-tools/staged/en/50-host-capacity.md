### 🌡️ Host capacity

Nothing used to know what the machine could carry: every command started at once and each tool sized itself to the whole host, which ended in watchdog kernel panics on 2026-09-28, 2026-09-29 and 2026-10-20 under load. The host capacity governor is one admission domain per user: every heavy `repo` command (`run`, `run-many`, `affected`, `exec`, `watch`, `cargo`, `show`, `graph`, `dependencies`) is admitted before it starts, waits in a first-come-first-served queue (interactive before batch) when the host cannot carry it, and gets a grant that sets the parallelism of the selected tool. Light commands pass untouched. State: {{@capacity}}.

```bash
repo capacity status
repo capacity run --memory=6144 -- bun test ./some.test.ts
repo capacity run --operation=dependencies -- bun install
```

- **`capacity status`** prints the host sample (available memory, the floor, spare, pressure, swap, load, open files, attached images), every running grant with what it reserved and what it really holds, and every waiting request; `--json` prints JSON.
- **`capacity run`** puts any other heavy command (a test runner, an installer) through the same queue: `--memory=<megabytes>` reserves exactly that, `--operation=<name>` reserves the estimate of a catalogue operation, `--cpu=<cores>` and `--jobs=<n>` size the request. The command gets the grant in its environment and the grant is returned when it ends, even if the process dies.
- **Admission.** A request is admitted while the free memory stays above the floor (20 percent of host memory clamped to 4 to 8 GB; 6,553 MB on a 32 GB host), swap stays below 25 percent and swapping out below 64 MB/s, the load stays below 2 per core counting the cores of running grants, memory pressure is not `critical` (`warn` waits), the machine-wide open file table stays below 80 percent and fewer than 32 disk images are attached. The last three and raised pressure are soft: they are waited out and overridden after 120 s only when nothing of ours is running, because a leaked image never goes away by waiting. Memory, swap and critical pressure are never overridden. Estimates: test 1.5 GB, check 4 GB, generate 1 GB, build 2 GB, script 0.75 GB, service 2 GB; `show` and `graph` 5 GB, `dependencies` 6 GB. A request that does not fit gets fewer jobs (`reduced`); one larger than the whole budget runs alone on an idle machine.
- **Grants per tool.** Bazel receives `--local_resources=cpu=N`, `--local_resources=memory=MB` and `--jobs` (and resource sets per action mnemonic, so its scheduler books actions at their estimate), Nx receives `NX_PARALLEL` (it has no memory or core budget, so the mapping is approximate), Cargo receives `--parallelism`. Nested commands inherit the grant of their parent through the environment, so a task that calls `repo` again does not wait for itself.
- **Reading a wait.** A line such as `[capacity] waiting 42s for run: not enough free memory (need 3584 MB; 1200 MB spare above the 6553 MB floor, load 7.1; 2 running, 1 ahead)` names the reason (`memory`, `swap`, `swap-activity`, `pressure-critical`, `pressure-warn`, `files`, `attaches`, `load` or `queue-order`) and the queue position. The line is published every 5 s in English or German; Ctrl+C cancels the wait. The state lives in `~/Library/Caches/semio/host-capacity` (`$XDG_CACHE_HOME` or `~/.cache` on Linux, `%LOCALAPPDATA%` on Windows), shared by every checkout of the user; a grant whose process died or whose boot session ended is reclaimed.
- **Escape hatch.** `SEMIO_HOST_CAPACITY=off` switches the governor off and says so on every command. The governor admits, it does not kill; commands that run outside `repo` are governed only when wrapped in `repo capacity run`.
- **Fairness.** {{?capacity-ramp::::Today a reservation counts at its full estimate for as long as its grant lives, and a refused request holds every later request back (`queue-order`), so on 2026-10-20 two hour-long grants kept 10 GB subtracted although the host was 89 percent free and a waiting 10-job Cargo blocked `show projects`; `repo capacity status` shows the difference between reserved and observed memory. The staged set below changes that. }}A reservation counts as unrealized, and in the budget at its full estimate, only for the first 5 minutes of its grant (`memory.rampMilliseconds`); afterwards the memory it really holds speaks for itself. A refused request never holds back later requests that fit; it becomes a strict barrier only if finishing our own grants would admit it and it has waited 30 s or been overtaken 6 times, and foreign pressure alone never creates a barrier. A batch request older than 300 s ranks as interactive. The bound on starvation is the bypass time plus one short duration. State: {{@capacity-ramp}}.
- **Platforms.** macOS reads `vm_stat` and `sysctl`, Linux `/proc/meminfo`, pressure stall information and the cgroup limits, Windows only free physical memory and busy-CPU load (no machine-wide file table, no pressure level). Only macOS was run; the other parsers are tested from fixtures.
