- H1 (audit): every raw acquire kept the shared directory-admission gate while it waited for a busy resource. Now each attempt takes the gate shared, tries once, and gives it back; waiting happens outside the gate (poll 20 -> 250 ms, policy `gate`, switch `releaseWhileWaiting`). - H4 (audit): `withResourceLeases` was raw and unfair. ## 2. Lock order (schema) and runtime enforcement

Schema `🔒️leases/🧭️order/🧬️schema/🔣️.json` (closed: Policy, Class, Match, Allowed, Held, Violation, bilingual Messages), authored table `🧭️order/🔣️policy.json`: 7 classes with rank, scope (machine/checkout/project/crate/generation/path/session), owner, EN/DE title, match (exact or longest prefix), declared allowed nestings, and the rules. Unranked/unknown resources are rank 0 and never order-constrained.

Runtime (`🧭️order/🟦️.ts`, process-wide ledger of what each task holds; a task = the invocation behind the control, else the signal; child processes inherit via `SEMIO_LEASE_INHERITED`, optional group below):
- out-of-order: requesting a lower rank than one already held fails immediately (also when the lease would be free), unless the class pair is a declared edge. Shipped as **observe** (violation logged to the registry and one stderr line per pair), one-line flip to enforce after `leases status` shows none during the e2e battery, because the table is derived from the census, not proven against all 75 nesting sites.
- hold-and-wait: a blocking request that has waited longer than the grace period (15 s, policy) while its task holds another lease **exclusively** fails with a diagnostic that names the held lease, the blocking process, its pid and how long it holds. Shared holds, declared edges and try-locks are exempt. Shipped as **enforce**.
- self-deadlock: unbounded request that conflicts with the task's own hold of the same lease (shared then exclusive, exclusive then anything) fails immediately; requests with a timeout expire as before. **Enforce.**
- cycle: waits are published to the per-user registry; every waiter checks the wait-for graph every 500 ms; exactly one member of a cycle (the latest waiter) fails, the others proceed. Covers raw and queued waits (queue order is an edge). **Enforce.**
- Messages EN/DE (`SEMIO_LANGUAGE`/locale). `SEMIO_LEASE_ORDER=off|observe|enforce` overrides every rule; registry failures never fail a lease.

## 3. Per-resource minimal scope

The generic layer cannot narrow other owners' keys. It gives them the contract: add a class with `scope` (and `owner`) to the policy when you introduce or split a key, then `repo leases status` shows holders/waits per class and rank. Proposals routed (not edited): conc-graph: facts writer per namespace shard only for publish, readers shared on the seal; conc-deps: generation-scoped image key, exclusive only for the pointer swap; conc-nx: release `nx:graph-pool` before evicting other namespaces (H3); conc-cargo: `cargo:registry` and `cargo-preparation` per workspace/crate, maintenance per compilation unit; conc-bazel: `bazel-snapshot-restore` and `bazel-workspace-*` per snapshot/session. Inside this layer: waiters no longer block the admission gate (H1) and `withResourceLeases` no longer lets readers starve a writer (H4).

## 5. Capacity admission (item 3)

Per the coordinator's note this builds on mem-gov's staged ramp + 60 s backfill and does not replace it. Gaps I measured against the strict barrier that is live today and that mem-gov's backfill leaves open, kept as an optional, unwired, tested module in `proposals/host-capacity-fairness-delta/` (6 tests pass against the live decision): (a) after 60 s the barrier also blocks when the head is held back only by foreign pressure that draining our own grants cannot fix (starves small requests indefinitely); (b) no bound by number of overtakes; (c) batch requests can starve under a stream of interactive ones (aging). It wraps `evaluateHostCapacityV1` (drain-aware barrier, bypass count, aging) and needs two call-site swaps in `🎫️gate/🟦️.ts`; not applied because it overlaps mem-gov's lines. `leases status` now surfaces the admission queue and each waiter's reason. Not done: the compiler capacity picker (`🏗️build/🎟️capacity/🎫️lease`, audit row 15) holds the picker exclusive while polling cores, so a small `available` request waits behind an unsatisfiable `exact:N`; fix = take the picker per attempt (not for the whole poll) plus a starvation guard from the picker queue's oldest ticket age; left to conc-cargo because it touches compile admission.

## 8. Round 3 and later live fixes (fix2 to fix8, all in `C/conc-leases-tools/fix2/`, applied live, each idempotent)

- fix2 (task identity): a task is an `AsyncLocalStorage` scope (`withLeaseTaskV1`, child of the running task), else the control object, else the signal. A request sees its own and its ancestors' holds, never a concurrent sibling's. Self-deadlock moved from an instant check to the grace period (own lineage only, unbounded requests only). Phase bodies in routing and `withNxPutSlotV1` run as child tasks. conc-nx put-slots test is strict again.
- fix3: lease-store medium. Policy `media` (prefix `native-fixed-image:`): a shared hold of an image that contains the lease directory in use never takes part in ordering; conc-graph's `image to graph` edge removed.
- fix4 and fix5 (symlink ancestry): `databasePath` and the retirement `parent()` accept an ancestor symlink only if it is an OS link (root-owned and directly below the filesystem root; on Windows directly below the drive root, `isSystemLeaseLinkV1` in `🎛️control`), keeping the caller's path spelling. Default-env suites went from 0/17 to green.
- fix6 (wedge shape): a shared request of a process that already holds the lease shared, with an exclusive request queued on it, is granted at once (`fairness.reentrantShared`, default on); the wait-for graph gets the same-process edge from a shared holder to its stuck queued sibling (`leaseProcessDependenciesV1`), so the cycle through the queued-ahead writers is found and only the stuck request fails; `leases status` counts the whole leading shared run as holders.
- fix7 (admission gate timeout in `show project`, `Resource lease timed out: resource-directory-admission:v1`): cause was a try-lock (`timeoutMs:0`, a graph-facts shard publish) making the gate acquisition a single attempt that lost to a momentary exclusive gate holder, and every queued acquisition started a claims retirement sweep that takes the gate exclusively. Fix: policy `gate.admissionPatienceMilliseconds` and `gate.claimSweepIntervalMilliseconds`.
- fix8 (audit finding 3, fix7 was too broad): patience is now an explicit request option `admissionPatienceMs`, passed only by the queue protocol's own gate waits (ticket publication catalogue, claim lease, head-of-queue acquisition). A real try-lock (raw, timeout 0) is a single attempt again. `claimSweepDueV1` is pure: a caller with timeout 0 never starts the sweep and never moves its clock, others sweep at most once per interval. Both policy fields are required in the schema and the TS type (no `??0`). Corpus `🔒️leases/🚪️admission/🔣️.json` (schema next to it) holds 4 sweep-cadence rows (skipped inside the interval; timeout 0 never sweeps; interval 0; finite timeout) and 5 gate rows (raw try-lock not stalled by a gate held 1200 ms; queued try-lock waits for the gate within the patience; admission wait bounded at the patience; patience 0 single attempt); the TS test reads them and validates the corpus with Ajv. Suite `resource-lease-admission` registered in `📜️script.ts` and `📋️project.json`.
- Verification of fix8 (one process at a time, nice -n 10): admission 10, order unit 58, processes 21, fairness 11, waits 11, bounded 4, claims 4, continuation 9, put-slots 13, default env processes plus admission 31; `tsc --strict` clean except the existing `♻️reset` errors.
