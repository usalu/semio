DESIGN. The terminal crate is one `Dashboard` type whose `impl` blocks live in five files (windows, panes, sessions, controls, sources) that call each other; a crate split of those would need ports and effects per file (like `source-view`) and would not free more than the tests already freed. The binding part was the 100 KB / 1,800-line unit-test closure that shares the crate (test cfg 0.999). So the seams are: (a) `🖥️terminal/🌐️language-choice` (clean leaf: first-run screen, `pub fn run`), (b) the laws as their own crate `🖥️terminal/🧪️tests/🏛️laws` (hub pattern `🏛️laws`: `#[cfg(test)] #[path] mod tests`), reaching the terminal internals only through feature `testkit` (`dashboard_terminal::testing`, same convention as `dashboard_source_view::testing`; shipped API stays `run`, `run_with`, `help_text`); the crate-internal types the facade names (`Dashboard`, `Body`, `Kind`, `Place`, `Effect`, `LinkState`, `Link`, `Action`, `Flow`, `RowAction`, `PreferenceJob`, `stack_of`, `fit_hints`, `spec_of`, `Windows`, `with_sources`, `request_source`) went from `pub(super)`/private to `pub` inside private modules (reachable only through `testing`); the `Link` test hooks moved from `cfg(test)` to `cfg(feature = "testkit")`. No re-export shim, no compat: the one importer of the language screen (terminal `🦀️.rs`) and the CI commands were edited at the source. Further seams (daemon `Link`, footer projection, pane rows) stay open and are cheap to cut later: terminal is at 0.51 with every cap.
