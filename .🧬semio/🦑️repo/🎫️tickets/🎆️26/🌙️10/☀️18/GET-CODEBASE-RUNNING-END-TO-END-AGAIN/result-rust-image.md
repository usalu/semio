## Design (done, live in the tree)
1. **Sizing law (schema-first).** `needs` row `rust` in the cache ledger (`⚡️caching/💾️storage/🧾️ledger/🔣️policy.json`): caps of its parts (`cargo-home` 3 GiB, `nx-artifacts` 3 GiB, `unit-cache` 24 GiB, `compiler-workspaces` 8 GiB = 2 x the 4 GiB compile charge) x 1.15 headroom + a 4 GiB floor (one compile must always fit) = 47.7 GiB -> rust partition **48 GiB** (was 16). Measured on 10-22: cargo home 1.63 GiB, nx 0.06, unit cache (objects 3.0 + admission memo 0.7 + largest lane 3.8) about 7.8, build dirs 3.6. New nested areas `cargo-home`, `unit-cache`; `cargo-store` stays the remainder (18 GiB). Global cap 66 -> 98 GiB (`maximumBytes`, schema max, `strictStorage` in `⚡️caching/🔣️policy.json`, `cargo.budgetBytes` follows the ledger remainder). The law (`🧾️ledger/🧪️tests/📏️needs`): required equals a SQLite recomputation, capacity >= required and < required + 1 GiB, strict storage = partition, floor = compile charge, workspaces = 2 charges, partition sum within the global cap with < 1 GiB slack, collection shares fit the unit-cache area, high-water room >= one compile, rust area `carried` set lies inside declared nested areas, a 16 GiB rust partition is refused ("smaller than its measured need").
2. **Recreate declaration.** Ledger area `recreate: "carried"` + `carry: [cargo/home, u/o, u/e, u/a]` (schema + validation in `🧾️ledger`); everything else (lanes, build dirs, scheduler binary) is derived and refills from the carried content-addressed units.
3. **High-water collector (unit cache).** `🗃️unit-cache/🧬️schema` gc policy: `highWaterShare 0.8`, `lowWaterShare 0.6`, `collectorIntervalMilliseconds 300000`, `maintenanceIntervalMilliseconds 600000`, `outOfSpacePatterns`, `outOfSpaceRetries 1`; `GcInput.volumeBytes` (pressure is now measured on the whole image, no longer on a share of it). Pure rules in `🧹️gc/🟦️.ts`: `gcNeedBytesV1`, `gcPressureV1` (enough | maintain | launch | throttled | collect-now), `gcOutOfSpaceV1`; `applyGcYieldingV1` (progress, cancellation between items), `collectGarbageSingleFlightV1` (claim `k/gc.lock`, second collector reports `running`). `🚪️launch/🟦️.ts`: `startUnitCacheCollectorV1` (detached, `setPriority 10`, output `u/gc.log`), `relieveUnitCachePressureV1` (called by the lane before and after every shared Cargo command: nothing / quiet maintenance / background collector with an EN/DE line / inline collection when less than one compile charge is free), `collectAfterOutOfSpaceV1`, `retryWhenFullV1`. CLI: `--semio-unit-cache gc --single-flight` (progress as JSON lines on stderr, SIGINT/SIGTERM cancel).
4. **ENOSPC inside a build.** `🦀️cargo/🚪️launcher/🟦️.ts`: the compile's `execute` marks `full` (stream: `onLine` sees `(os error 28|112)` / "No space left on device"; capture: stderr/stdout), `retryWhenFullV1` collects once, prints the EN/DE `outOfSpace` line and runs the command ONE more time; a second failure prints `stillFull` (EN/DE) and returns Cargo's own status.
5. **Tests (language-agnostic).** `🧹️gc/🧪️tests` (9): schema-validated pressure and out-of-space vectors; decisions + need bytes equal a Python oracle and a SQLite oracle on 400 seeded states plus the 9 vectors; plan frees exactly down to the low-water mark; single-flight; progress + cancel; relief decisions incl. German message; REAL detached collector (starts, claims, collects, logs JSON); retry state machine. `🧾️ledger/🧪️tests/📏️needs` (6, two new). `🗃️unit-cache/🧪️tests` cleanup-plan test updated to `volumeBytes` + 3 vectors for the water marks (passes).

## Rollout (live run; the declaration is patched right after the exclusive ticket stands)
- Tool: `C/rust-image-tools/grow.py` (+ `queue-hold.ts`, `policy-patches.json`). It queues an exclusive FIFO ticket on `native-fixed-image:<rust dir>` through the repo's own queued leases (holders finish, later openers wait behind the ticket, nothing is killed), patches the declaration (rolled back on any failure before the move), detaches, moves the old directory aside (`rust/fixed.retired-<stamp>`, NOT deleted), releases; the next `bun repo` births the 48 GiB image; then it mounts the old image read-only and carries `cargo/home`, `u/o`, `u/e`, `u/a` additively (no-clobber, temp name + rename) and detaches it. Rehearsed on scratch images (carry incl. symlink/mode/no-clobber/second run all-skipped; patch forward/backward/idempotent round trip on copies).
- Run 1: `python3 C/chain-tools/detach.py C/🗑️generated/rust-image/grow1.log nice -n 5 python3 C/rust-image-tools/grow.py --yes --limit=5400`, pid 5184 (started 17:02:38; policy patched 17:02:38). It waits for every live `bun repo cargo` to finish; progress in the log.
