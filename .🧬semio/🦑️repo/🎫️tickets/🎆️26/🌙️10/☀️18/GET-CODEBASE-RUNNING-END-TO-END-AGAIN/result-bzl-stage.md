## Changes
1. Source groups (`B/📜️script.ts`): the 859 per-task file lists are replaced by shared filegroups.
   - `bazelSourceIndexV1` (sorted inventory, per-pattern results cached, binary-searched prefix ranges) and `bazelSourceKeyV1` units: one include pattern plus only the exclusions whose literal prefixes can overlap it (sound because a file matched by both has both prefixes as prefixes). `bazelTaskSourcePathsV1` is now implemented on it (identical results, 5 to 1000x faster per task).
   - `bazelSourceCoverV1`: per-directory filegroups `d_<hash>` (a project root is one group; single-child chains collapse), pattern-unit composites `k_<hash>` shared by all dependents, task composites `i_<hash>`; every file is listed once in its directory group. Names are ASCII; emoji appear only in file labels.
   - `renderBazelBuildV1` takes `groups: Map<name,{groups,files}>` and renders nested groups as `":name"` before files. `STARLARK_RULES` collects `src[DefaultInfo].files` of `ctx.attr.srcs` (no `ctx.files.srcs` flattening per task).
   - **`glob()` was tried and rejected, empirically** (scratch workspace, Bazel 8.4.2): (a) `.bazelignore` listing the `s` link (required so `//...` does not crawl the checkout and hit the infinite symlink expansion, see item 5) makes every `glob(["s/..."])` match nothing ("didn't match anything"); (b) without it, glob follows symlinked directories and fails with "Too many levels of symbolic links" on loops, includes git-ignored trees (node_modules, target) that Nx never hashes, and errors on names with `\` or control characters (and skips directories with an emoji `BUILD` file silently). An external `new_local_repository` would hide the crawl but would keep (b). Explicit labels keep exactly the `git ls-files -co --exclude-standard` semantics plus the existing file/hash classification.
2. Transitive `^` inputs: `bazelTaskInputsV1` expands `^name`, `{input, dependencies:true}` and `^{projectRoot}/...` over the transitive dependency closure (BFS, cycle safe, self excluded), with the Nx error for a closure member lacking the named input. Verified against Nx's own native `HashPlanner` (see tests).
3. Dangling `dependsOn`: `requireBazelDependencyV1` is called by the planner and throws `Unknown build task dependency: <task> depends on <dep>, but project <p> is not in the build graph` / `... defines no target <t>`. `bazelDanglingDependenciesV1(graph)` lists every dangling declaration (base targets and configurations) at once.
4. Cacheable without outputs: already fail-closed from bzl-label (`cache:true` or plugin class `deterministic` without `outputs` -> reason `unbounded`, not cached, nonce in the fingerprint). Added `bazelUncachedReportV1` (+ closed schema `UncachedReport`) and the owner report `C/bzl-stage-uncached-report.md`: **809 targets in 278 projects**, all via explicit `cache: true` (the earlier count of 808 grew with the graph, 1,466 projects now). Fix per target: real `outputs` or `outputs: []`.
5. Fixture tests for the two open items: `.bazelignore` (`linkBazelSourcesV1`, now exported: content, idempotence, stale link replaced, plus a real-Bazel oracle: `//...` succeeds with the ignore and fails with "infinite symlink expansion" without it, explicit `//:s/a.txt` still resolves) and the task Cargo directories (`bazelTaskCargoDirectoriesV1`/`bazelTaskBaseEnvironmentV1`/`issueBazelTaskEnvironmentV1`, independent Python `os.path.normpath(os.path.join())` cross-check, plus proof the caller authority refuses them as plain environment).
6. Existing test debt fixed: `📥️fingerprint` test bound `taskInputs` but the closure calls `bazelTaskInputsV1` (both tests failed at baseline); `📥️actions` tests use the new group shape; main test imports the two new dirs.
