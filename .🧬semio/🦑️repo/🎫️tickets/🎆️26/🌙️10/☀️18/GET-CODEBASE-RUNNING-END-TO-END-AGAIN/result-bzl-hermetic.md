## Problem and answer
Every non-hermetic action was a `repo_task` re-entering bun with `no-sandbox` + `no-remote-exec`, so cache correctness rested on declared inputs and 0 of 8,027 actions could run remotely. The hermetic action kind (`repo_hermetic_task`, strict runner, pinned bun toolchain) already existed but nothing declared it: it needs `metadata.semio.hermetic` per target and could only run pure commands, because every real target is `bun ./📜️script.ts <verb>`, which needs an original process envelope, a provider designation, workspace links, third-party packages and host stores.

This set makes hermeticity a property of a **target class**, declared in one schema-first table, and makes real repository scripts runnable inside the action.

## What was built
1. **Class table (schema first).** `B/🏃️execution/🧬️schema/🔒️hermetic-classes.json` (closed schema) and the authored table `H/🔣️.json`: `runtime` (entry module, shared source patterns, root markers, time bound, covered runtime commands), `environment` (closed admitted names, denied authority prefixes), `strategies` per host, `classes` (id, evidence `proven|derived|assumed`, `select{targets,projects,excludeRoots}`, `dependencies links|packages`, `packages`, framework `providers` replacements) and `exceptions` (project, target, closed reason). Selection, host-input admission and strategies are `H/🟦️.ts` (pure). Rollout is a ratchet: the table ships with `projects` narrowed to three canary projects; widening is a data edit (`widen.py`), an unfit target gets a declared exception, never a silent host read.
2. **Original authority inside the action.** `H/🚪️entry/🟦️.ts` issues, from the repository's own owners ([providers](L/🏃️process/🔌️providers/🟦️.ts) and the routing envelope), the provider designation (with class replacements) and a fresh original envelope bounded by `maximumElapsedMilliseconds`; the only capability is the isolated workspace, so scripts needing native build authority refuse loudly. `H/🔌️providers/🔷️typescript/🟦️.ts` replaces the host-authority `typescript-check` provider (no store, lease or compiler state): `tsc --noEmit` from the declared tree. This keeps the verb's own script (arguments, project selection) and swaps only the authority seam.
3. **Declared dependency tree.** `H/📦️dependencies/🟦️.ts` reads the installed bun isolated generation(s) (the checkout links `node_modules` into `.cache/b/d/m/j/<id>`; workspace links are absolute symlinks into the checkout) and selects per `node_modules` directory: workspace packages with declared inputs (transitively), the project's and class's packages and the transitive store closure. A new host-state Starlark rule (`repo_hermetic_modules`, runner `hermetic-modules.mjs`) copies exactly those store entries into one tree artifact (relative links only, verified relocatable); hermetic actions take it as an input by content. The tree label hashes store identities only, so another checkout path keys consumers identically (proved). Generations may differ per directory (the live checkout has two): handled as store indexes. Measured on the live checkout (read only): course project 408 store entries, writer-js 8, versus 1,380 for the whole generation.
4. **Runner v2** (`BZ/🏃️execution/🏭️runner/🟦️.ts`, self-contained): builds its own isolated workspace from the manifest's declared `inputs` whenever Bazel did not isolate one (sandbox symlink forest or local strategy: files are cloned/copied into a private root, so even realpath imports cannot reach undeclared siblings), writes root markers, builds the `node_modules` directories (workspace links, tree links, `.bin` shims), calls the entry, runs the commands with a strict environment plus the manifest's declared `inputEnv` values and refuses undeclared writes. Scratch is per action (parallel local actions no longer clash).
5. **Manifest / generator / adapter.** Closed manifest gains `inputs`, `class`, `entry`, `markers`, `maximumElapsedMilliseconds`, `providers`, `inputEnv`, `nodeModules`. `bazelHermeticDecisionV1` selects by explicit declaration (bare) or class; environment inputs enter as declared values (part of the action key), `bun --version` / platform runtime inputs are covered by the pinned toolchain and platform, any other host input refuses (`host-inputs`). The generator appends the runtime patterns to a member's inputs, derives its plan, **demotes** a member whose installed dependencies cannot be declared (it stays a host action; new reasons `excepted`, `dependencies`), writes tree manifests and renders `modules = ":m_<digest>"`. Selected hermetic snapshots are restored into the checkout as before.
6. **Strategies per platform** (`--strategy=RepoHermetic=<list>` from the table): darwin `remote,darwin-sandbox,local`, linux `remote,linux-sandbox,processwrapper-sandbox,local`, windows `remote,local` (`remote` only when an executor is configured). `local` is safe because the runner isolates itself, so an undeclared read fails on every host (Windows has no OS sandbox). The darwin non-ASCII output-base guard from `result-bzl-sandbox.md` is untouched (the production layout is ASCII).

## Open items
- Evidence of the five rows is `assumed` until the live probes; the canary rollout is deliberately small. Real targets have not been run hermetically yet (static reconstruction only; the real closure markers need the live graph store).
- Hermetic tests are `repo_hermetic_task` build actions (cached by action key, remote-eligible) rather than `bazel test` results; a `repo_hermetic_test` rule would restore test-log semantics.
- Dependency tree granularity is store-entry level; a project whose workspace dependency imports a third-party package without its own `node_modules` row fails loudly until `externalDependencies` names it.
- A hermetic run needs the pinned bun toolchain (`prepareBazelBunV1` downloads it once; offline first use fails with a clear error).
- Not run: Windows (junction links and clone fallback are written for it; strategies are fixture-tested), Linux, real remote executor (needs `bzl-rbe` service), classes for `activate`/`session` (store-aware restore), cargo (bzl-rust).
