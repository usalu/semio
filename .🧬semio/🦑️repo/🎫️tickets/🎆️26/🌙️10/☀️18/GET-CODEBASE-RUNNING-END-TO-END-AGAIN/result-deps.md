## Design questions for the coordinator
- Path cap: the repo rule is 256 chars for authored files; installed npm content cannot obey it (291 seen, store root already uses 63). I raised the installed-path policy to 1024. Alternative is a shorter store root (`.cache/b/d/m/j/<20hex>`) but that only saves ~10 chars. Say if you object.
- Parent stamps: the strict mtime fence cannot coexist with a live shared repo root; relaxed to identity. Say if you want a different semantic.
- Current blocker hypothesis (10): the check requires the provider resolved from the owner generation, the member generation and the prospective Source tree to be byte-identical JSON (path, dev, ino, version). For a Source package that is a member of two or more scopes, external npm providers live in different generation directories, so they can never be identical; it can only pass for workspace-linked providers or single-scope packages. Needs the debug output to confirm; if confirmed the likely right fix is to compare (name, version, manifestSha256) and the canonical path relative to the respective stage root, not absolute path/dev/ino.
- Unready generations cannot be resumed (bindings.json missing => read throws), so every retry reinstalls everything; resume support would cut iteration time from ~17 to ~3 min.
