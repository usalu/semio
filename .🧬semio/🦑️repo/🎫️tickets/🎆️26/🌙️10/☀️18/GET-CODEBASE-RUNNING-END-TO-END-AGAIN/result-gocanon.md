# Result gocanon: every package-root sibling `.go` file is now a registered member directory with one `🐹️.go` leaf

Root `M` = `🧰️framework/🛍️products/🦑️repo/🔨️modules`. 332 files moved losslessly (`mv`, bytes unchanged): 248 sources become `📦️packages/🐹️go/<member>/🐹️.go`, 84 `_test.go` files become owner-level cases `M/<module>/🧪️tests/<case>/🐹️.go`. One rename: `⌨️cli/📦️packages/🐹️go/🚀️bin/📦️main.go` -> `🐹️.go`. Tools and plans are in `C/gocanon/`, per-module move plans in `C/🗑️generated/gocanon-logs/*-convert-plan.json`.

## 1. How the canonical build treated `📦️packages/🐹️go` modules (established first, with code reading and a runtime probe)
- `canonicalGoModulePlan(root)` already maps registered member directories and `🧪️tests/<case>/🐹️.go` when `root` IS the package module (`walk(root)` only skips nested `go.mod` dirs and the opaque `📦️packages`/`🧫️fixtures` of its CHILDREN). The audit's "not walked" was true only for the parent-module walk (opaque `📦️packages`) and because nothing ever called the canonical plan for these modules.
- The real defect was the consumers. All 21 package-module `📜️script.ts` ran plain `go test ...`, and the `🧪️test` Go host (`go run .` in a generated `go.work`) and `goProductionClosure` (`go list -deps`) compiled workspace modules without overlay. Probe (kept out of the tree): a host module importing `repo/tree` fails with `undefined: CachedGitignore` (workspace members missing) without `-overlay` and runs with the merged overlay.
- Test-leaf placement. `<module>/📦️packages/🐹️go/🧪️tests/<case>` would build with zero library change (gocoord precedent) but breaks the repo's own test-layout gate: `assessTestImplementationPath` returns `test-owner-delivery-scope` (verified at runtime: "move the case to its nearest language-neutral semantic owner"). Rust already solves this with `#[path = "../../🧪️tests/🔬️unit/🦀️.rs"]`. Decision: white-box Go cases live at the language-neutral owner, `M/<module>/🧪️tests/<case>/🐹️.go` (feature-less cases are ignored by the host: `🧭️case-discovery` requires `🥒️.feature`), and the canonical plan adopts them.

## 2. Library rule (language-agnostic, schema-first vector, Go toolchain oracle)
`📚️library/🧪️testing/🐹️go-plan/🟦️.ts`:
- `CanonicalGoLayout` gains `packagesDirectory` and `languageDirectory` (from `taxonomy.packagesDirName` and `🐹️go`).
- New rule in `canonicalGoModulePlan`: a module rooted at `<owner>/<packagesDirectory>/<languageDirectory>` also maps `<owner>/🧪️tests/<case>/🐹️.go` as `_test` inputs of its root package when the leaf's package clause equals the package clause of the module's `🐹️.go` or `<package>_test`. Black-box adapters (`package adapter`/`main`, the existing `🌳️tree/🧪️tests/*/🐹️.go`) are never absorbed. Helpers `goPackageClause`, `packageModuleOwner`, `requireValidCanonicalGoLayout` (extracted validation).
- New export `writeCanonicalGoWorkspaceOverlay(file, roots)`: merged source overlay of roots plus their local replacements (collision-checked, each module visited once). Used by `🧪️test/🖥️host/🏗️materialization` (`go run -overlay=<host>/go-overlay.json .`) and `🧪️test/🔒️oracle-dependencies` `goProductionClosure` (`go list -overlay=...`).
- Test: `📚️library/🧪️tests/🐹️canonical-go-discovery/🟦️.ts` (second test) + vector `🧪️tests/🧫️fixtures/🐹️canonical-go-discovery/🔣️.json` (`packageModule`, contract bumped to `canonical-go-input-projection-v3`, layout gains the two names and `📦️packages` is opaque). It asserts plan packages/sources/tests, that the adapter case and the parent walk are excluded, and runs `go test -overlay -v` as oracle (unit + external `area_test` cases pass, adapter case never runs). `bun test ./…/🐹️canonical-go-discovery/🟦️.ts`: 2 pass, 21 expects. Mutation check: disabling the owner rule makes the new test fail (1 pass / 1 fail), restored.
- All 21 package-module `📜️script.ts` now call `runCanonicalGoTests(<module>, [...], {env})` (tickets additionally had a missing `await`/`async`). `yaml` and `durability` have no script.
