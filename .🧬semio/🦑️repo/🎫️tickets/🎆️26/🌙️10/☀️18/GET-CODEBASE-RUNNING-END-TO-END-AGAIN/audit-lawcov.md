Definitions (heuristics, see caveats):
- **Schema**: `<unit>/🧬schema/*.json` exists (schema-first).
- **Scope**: nearest unit-or-ancestor directory that has a `🧪tests` child; `own` = unit's own `🧪tests`, `ancestor` = inherited from a non-root ancestor, `root` = only the library-root `🧪tests` (not counted as unit test).
- **Tests**: code files (ts/mjs/mts/cjs/js/rs/go/py) under the scope's `🧪tests` tree.
- **Corpus**: data file (json/feature/yaml/toml/csv) under that tree, excluding schema-like names; counted as consumed when a test file names its basename or scans the directory (readdir/glob).
- **Oracle**: a `*oracle*.py` file, or a test file importing a third-party npm package (not test runner, not `@semio-tech/*`, not node built-in) or SQLite (`bun:sqlite`, `node:sqlite`).
- Classes (risk order): 1-NOTEST (no unit-scoped test), 2-NOCORPUS (tests, no consumed corpus), 3-NOORACLE (corpus, no oracle), 4-OK.

## Caveats

- Scope evidence for `ancestor` units is shared with every unit in that subtree; ancestor-based OK/NOORACLE ratings overstate per-unit coverage.
- Corpus consumption is basename-level (a test naming `🔣.json` marks every `🔣.json` in scope as consumed); oracle is import-level: presence of a third-party import is not proof that output is compared.
- Excluded from production by rule: `📜script.ts` (77), `🍎.ts` (2), `🟨.cjs` (6), `🟨.d.mts` (45) and `🔣.json` data files; library root tests (451 files, 213 fixtures) are not counted as unit tests.
- Non-TS test languages (rs/go) are counted as tests but not analyzed for oracles.
