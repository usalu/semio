### How it works
1. **Inventory** per set through the format-specific adapter (auto-detected, or `adapter` in the registry): `py-module` (walkperf, cargo-pressure, bzl-stage: imports the set's own `apply.py` and reads `TARGET`/`NEW`/`PATCHES`), `patches-json` (tsc-stage, with the `📜️script.ts` -> `🟦️.ts` retarget), `ops-json` (tax-stage), `tree-bases` (lease-fair: `bases.json` + `staged/`), `tree` (only `staged/`), `declared` (a set may ship `inventory.json`, see `schema.json#/$defs/Inventory`: the contract for sets of unknown format such as law-sweep2/env-pass2/bzl-real/exports-stage). Per target: staged file or embedded patch, base sha, anchors (first 100 chars in `plan.json`), live base state (`base`/`applied`/`drifted`/`absent`).
2. **Solo run** on a sandbox (fake repo root `bunfig.toml`+`bun.lock`, the set's tool dir cloned, only the files the set may touch copied): the set's own `apply --dry-run`, then `apply`; on refusal it retries with the set's `--rebase` flag when it has one. Detects files written outside the inventory (`undeclared`).
3. **Pairs**: every pair that shares a target path (incl. retarget siblings) is applied in both orders on a fresh sandbox; verdicts `independent`, `commute` (both orders succeed with byte-identical files), `ordered` (only one order works), `order-dependent`, `conflict`. Per conflict the incompatible files are explained statically (anchor absent from the other set's result, file deleted, both replace). Extras: anchor-region overlap in the live file, and `diff3 -m` of the two solo results versus our merged file.
4. **Order**: hard edges from `ordered` pairs, registry `after` hints only when they do not contradict; a set whose solo run is refused but which applies after another set is kept (`needs`). Conflicts exclude the lower-ranked set (registry order, or `plan --prefer a,b`), with the restage advice in `excluded[].detail`.
5. **Replay**: all included sets in plan order on one sandbox (dry-run, then apply, per set; a refusal excludes the set and replays again). Then every changed source file is scanned for relative imports (static, dynamic, `require`, `new URL(..., import.meta.url)`): `regressions` = resolved before, not after; `unresolved` = newly introduced and unresolvable.
6. **Driver** (`apply-all.sh`): per set its own `apply --dry-run`, then `apply`, stop at the first refusal (exit 3; exit 2 while the dependency sync runs); then the verification commands. `--dry-run` rehearses (a set that needs an earlier set is reported as `defer`); real application needs `--yes`. Other flags: `--ignore-sync`, `--include-provisional`, `--only a,b`, `--from id`, `--skip-verify`, `--heavy`, `--force-stale`. A stale plan (registry/staged inputs changed, or live target files changed) is refused for a real run (exit 4). Provisional sets (no `result-*.md` yet) are skipped by default.
7. Not-ready sets are skipped with a note (`directory missing`, `no apply entry point`, `nothing staged yet`, `inventory failed`); unregistered `*-tools` directories that look like staged sets are listed in `plan.json.unregistered`. Re-run `bun plan.ts plan` whenever a set finishes (30-60 s).
