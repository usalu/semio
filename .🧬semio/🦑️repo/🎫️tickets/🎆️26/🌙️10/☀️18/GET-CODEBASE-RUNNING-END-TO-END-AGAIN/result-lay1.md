## 1. Intra-plugin cycles (92 -> 0)

The tree changed under the cycle list (peers split and moved files), so I re-derived the cycles with my own SCC scanner (`lay1-tools/scan-cycles.ts`: every `import`/`export from`/`import()` literal, relative specifiers plus bare `@semio-tech/*` specifiers resolved through every workspace `package.json` `exports` map) and confirmed with the real dependency-cruiser run (section 3). Mechanical edits were done by an AST tool, not by hand: `lay1-tools/extract.ts` (TypeScript compiler API) moves named top-level declarations into a new sibling leaf, copies exactly the import bindings they need (relative specifiers re-based, import attributes such as `with {type:"text"}` preserved), imports them back into the parent only where still used, and rewrites every relative importer, `export … from` and package-entry consumer (`export *` entries get an `export * from leaf` appended instead of a compat re-export in the parent). It refuses to write on any ambiguity (mixed multi-name statements, namespace use, dynamic import near a moved name, missing top-level dependency).

Rule kept throughout: leaf = `<emoji>️<domain-slug>/🟦️.ts` (generator folders: same), explicit named imports, importers re-pointed, **no barrel and no compatibility re-export**. All 34 new leaf directories resolve to an admitted taxonomy kind (`lay1-tools/tax.ts`, live `semanticDirectoryKindId`).

### 1.1 Test dependency contract leaf (cad engine, extensions, dev/cad spatial-kernel tests)

The repo law `test-layout` (`inline-test-body`) *requires* the `import.meta.vitest` hook to dynamic-import a canonical test file, so the module -> test edge stays. The back edge is removed: `XTestDependencies` moved out of the module into `🎒️test-dependencies/🟦️.ts`, a sibling leaf owned by the module directory, built only from lower layers. `lay1-tools/tdpre.ts` rewrites each member first: module-local string constants -> `string`, `const { x } = core` destructures -> `typeof core.x`, `const __xTestRuntime = import.meta.vitest ? await import(S) : null` -> `typeof import(S') | null` (specifier re-based), local functions -> an explicit signature (`td-overrides.json`: `parseConstruct`, `runConstruct`, `runSelectionOperationInteraction`, `resolveDisplay`, `bootstrapCadModules`, stately builders) and the local types they need were extracted first (`🖼️display-model`, `🎛️machine-views`); then `extract.ts` moves the alias with type-only imports and re-points the suites. Applied to 14 modules: actions, artifact (7 suites share one type), inferences, stately, renderer (2 suites), runtime, 4 extensions, dev/cad geometry/semio/brepjs.

### 1.2 Hook inversion where the suite is an integration test (6 modules)

`runtime`, the 4 extensions (`spatial-shape`, `aec-building`, `aec-building-structure`, `aec-building-energy`), `dev/cad` `🧱️brepjs` and `spatial-kernel` `🗺️spatial` have suites that need the bootstrapped runtime / the brepjs kernel / the module under test as a value, so any back-edge-free in-source layout is impossible (an 18 file strongly connected component: runtime -> extension packages -> extension tests -> runtime package -> runtime tests -> extension packages, plus brepjs). `lay1-tools/invert.ts` removes the hook (and its `🧪️Tests` region) from the module and makes the suite self-registering: it imports `vitest`, builds the dependency object from the same sources the module used (`core.solidRef` instead of the destructured copy, module-local ids imported from `../../🟦️.ts`) and ends with `await registerTests1(vitestRuntime, dependencies, { url: new URL("../../🟦️.ts", import.meta.url).href })` (same `source.url` the in-source hook passed). Collection moved into the configs: the four extension `🧪️tests/🎚️config/🟦️.ts` list their suite in `include` (no `includeSource`); `✏️s/🧑‍💻dev/📐️cad/🧪️tests/🎚️config/🟦️.ts` got `INTEGRATION_TEST_FILES` (runtime, brepjs, spatial) in `include` and `SOURCE_TEST_FILES` for `includeSource`. Unused imports left in the brepjs facade by the removal were deleted (`unused.ts`, compared against HEAD).

## 2. Grab-bag directory renames (36 law breaches -> 0)

Rust module identifiers (`mod core;`, `crate::editor::flow::base::…`) were *not* renamed: the mount is a `#[path]` attribute, so the folder name is independent of the identifier, and a rename of identifiers cannot be proven without cargo.
