## Key finding (differential against the real Bun, 40 mutations, `C/deps-d-tools/diff-bun.py`)
Bun's frozen check is NOT "the lock's workspace rows equal the manifest tables". It refuses only when the RESOLVED set changes: a member added, dropped or renamed; a package no lock carries (new dependency in any of the four tables); an external range that resolves differently; the last user of a package removed; ANY `overrides` change. It ACCEPTS: member version bumps, workspace-dependency edits, moving a dependency between tables, adding an already locked package, `resolutions`, patches, trusted dependencies, a renamed scope root. Consequence: a strict row comparison (what `verify dependencies parity js` did, root lock only) would refuse runs Bun accepts. The law therefore reports every disagreement (audit) but marks `frozen: true` only where Bun is certain to refuse; refusals use only those, and the installer's own refusal text covers what no static law can know (a range that resolves differently, a last user removed).
