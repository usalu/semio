# Result nxpart: the Nx pool is a top-level cache partition (`n`)

Status: code, schema, live state and tests done and verified on the real host. Acceptance (`bun repo run @teaching/architecture-quiz:check` reaching task execution) is NOT demonstrated: the run aborts in the dependencies bootstrap ("Store dependency sync incomplete") before any Nx code runs (see "Acceptance"). Everything the run needs before task execution (provision pool, open pool store, create/recover/recheck/retire a namespace native image) is proven by probes and tests. No package.json/bun.lock edit, no cargo, no git-modifying command, no sub-agents.

## What changed (and why)

1. New partition `nx`, directory `.cache/b/n` (budget policy `📦️budget/🔣️policy.json`): capacity 1.5 GiB, new optional `maximumArtifactBytes` = 512 MiB (store charge), `maximumLogicalBytes` 1609564160. Schema (`📦️budget/🧬️schema`), `RepositoryCachePartitionIdV1`, `RepositoryCachePartitionV1.maximumArtifactBytes` (default = filesystem bytes for every other partition), store reservation uses it, store receipt schema accepts `repository:nx-store`. Totals: 68249714688 + 1 MiB control <= 64 GiB (headroom 468713472).
2. Nested pool code path removed from `🔌️nx/📦️graph/🟦️.ts`: `withNxGraphCacheStoreV1(workspace,invocation,phase,body)` now opens the generic partition store `nx` (no `parent`, no `nx/cache`, no parent headroom, no maintenance-EX provisioning). `prepareNxGraphCacheStorageV1` keeps only the graph snapshot headroom recovery (schema `ParentHeadroom` -> `SnapshotHeadroom`, no pool term) and provisions `nx` by opening it once. Callers updated (`🔌️nx/🟦️.ts` x2, `🕸️graph/📤️publication`), they keep their graph pin because build-graph consumers inside the Nx process need it.
3. Decisive finding beyond the brief: moving the pool top-level was necessary but not sufficient. The namespace native images (nested under the pool) hit the same wall: any unfunded mounted descendant makes every parent `recheck()` fail ("Exact original parent child allocation required"), and the failed acquisition leaves the child mounted. Reproduced on the real `n` image with `nxpart-tools/probe-ns.ts`. Fix: namespace native images are now **parent-funded children**:
   - layout `<n/m>/<tool20><key20>/native` (the funded namespace directory must be exactly one level below the parent root; graph JSON stays in `nx/graphs/<tool20>/<key20>`); `nxGraphNativeImageDirectoryV1`, `nxGraphNativeDirectoryV1`, `nxGraphNamespaceDirectoryOfNativeV1`;
   - `openNxGraphNativeChildV1` (fresh: funded birth + commit; existing: recover/commit + plain child), `retireNxGraphNativeChildV1`, exported `retireNxGraphNamespaceV1`; eviction in `room()` retires the funded child with its charge;
   - schema `NativePolicy` gained `fundingOwner` (`repository:nx-namespace`) and `fundingMetadataBytes` (131072); journal arithmetic enforces sum(allocations) <= capacity, hence the 512 MiB store charge in a 1.5 GiB image (15 children fit; pool byte limit unchanged);
   - new store/partition wrappers `withRepositoryCacheStoreFundedChildStorageV1`, `retireRepositoryCacheStoreFundedChildStorageV1` (+ partition twins in `📥️opening/🟦️.ts`).
4. Failed-birth cleanup (`native-build/💾️storage/🧹️cleanup/🎛️command`): a fresh persistent birth that fails after receiver acknowledgement but before hand-off used to settle "unresolved" with the image mounted and the directory present. `settle` now un-acknowledges a fresh receiver so the existing closed state machine deactivates (`hdiutil detach`) and then removes. Evidence: real-image law `🧹️cleanup/🧪️tests/🛑️failed-birth` (abort during birth leaves no mount, no directory), plus a temporary `[DEBUG]` fault injected at hand-off (removed): without the change `mounted=[…fixed.dmg] present=true`, with it `mounted=[] present=false`. The post-acknowledgement window cannot be hit from outside, so that part has no permanent test.
5. Consumers of the old nested topology: the current-maintenance planner (`readNxGraphCurrentMaintenanceIntentV1`: partition `nx|products`, `poolDirectory`, pool is a fixture child of Products and no longer a target on the repo host; host-level namespace descriptor reads in the three publication entry points; fixture inventory allows the pool directory), the setup-all helper `☀️14/ABSTRACT-REPO-BUILD-TOOLS-AND-ADD-BAZEL/graph-purpose` (script, schema, fixture), the protected-census tools `asset-census` and `asset-publication` (eight partitions, id `nx`), the Products-fixture test helpers, and `.vscode` launch inputs (`nativeAssetPartition*` gains `nx`, `graphMaintenancePartition*` is `nx|products`; both seed and generated file).
6. Live state: no `g/m/nx` mount or directory remains (`hdiutil info`/`mount` clean; the empty `g/m/nx` was removed). `.cache/b/n` is provisioned (APFS, owners on, fully allocated 1.5 GiB), holds only the store receipt, journal and an empty `nx/graphs`.

The first attempt died with the source-guard when I edited the store; the second queued 30 min behind the exclusive dependencies lease of `bun repo dependencies sync --all` and then aborted in the dependencies bootstrap before any Nx/graph/pool code ran: `[DATA] Store dependency sync incomplete {"purpose":"current-store-dependency-sync-failure",...}` followed by `SQLiteError: unable to open database file` (SQLITE_CANTOPEN in `🔒️leases/🟦️.ts:145`, `script "repo" exited with code 1`). So task execution was not reached, and the blocker is the dependencies sync (a new `dependencies sync --all` was already running), not the Nx pool. Re-run the acceptance once that sync is green; expect the namespace to be created on the first run and to need one retry only if two brand-new namespaces are bound in one store (limit below). The log was under `🗑️generated/nxpart/` and has been removed.

## Known limits for the next executor

- A funded operation consumes the parent borrower's single cleanup capture: within one open `nx` store only ONE fresh namespace birth or ONE retirement can run; a second one fails with "One live original Native borrower cleanup capture required". Reopening an existing namespace is capture-free. A run that binds two brand-new namespaces in one store (or evicts and then creates) fails once and succeeds on the next invocation; fixing that needs the borrower to allow several accepted cleanups or pre-provisioning namespaces in their own store.
- Transient `retireNxGraphNamespaceV1` -> false directly after releasing a lease (up to ~1 s); callers should retry, `room()` just skips busy namespaces.
- The Products fixture helpers still cannot run on this host for the reason above.
