## What exists
1. **The existing mechanism is `repo bench` + `repo incremental` + `repo concurrency`** (`🏗️build/📏️incremental/{🏎️bench,🤝️concurrent,...}`): SLO table (units, probes, objectives with goal/gate/blocking/tolerance), spawner with wall/first-output/marker times and sampled process-tree RSS, cache probe through the incremental harness, concurrency harness, report format = stored baseline, `bench compare` with tolerance, EN/DE, a CI job. It had probes only for proctor/framework-graph, no product, no phases, no peer edits, no history. I extended it; no parallel system.
2. **Interim harness** (`C/bench-g-tools/measure.py`, python, cross-platform ps/PowerShell sampler): one command → JSON record (wall, per-phase times, tree RSS peak at 250 ms, swap, load, bazel `N processes` executed/cached, nx tasks, graph re-inferred projects); scenarios `noop` (prime + N), `edit` (one-line product edit, run, restore), `peer` (edit an unrelated file, run the product). Data-driven by `phases.json` / `products.json`. Refuses to edit inside the live checkout. Streams, aborts above 500 MB.
3. **Library extension, staged and tested graph-free in the stage copy** (apply as ONE batch, announced below):
   - schema: new kind `peer`; metrics `queueMs graphMs executeMs executedActions inferredProjects`; unit `count`; source `product-budget`; policy tables `phases` (rules → ids → metrics), `observation` (graph/bazel/nx patterns), `history`; EN/DE labels; fixture sections `observations`, `history`.
   - `🟦️.ts`: `benchObserverV1` (streaming, keeps no line), `benchObservedValuesV1`, `benchHistoryNameV1/LatestV1`, `benchBudgetV1`, `renderBenchBudgetV1`, count formatting, issue rules for peer/cold-noop/memory.
   - runner: spawner feeds every line to the observer (also last line without newline); probe samples carry the new metrics; memory probes now also keep the plain metrics; `peer` probes edit an unrelated unit then run the product target.
   - command: `--history=<dir>` (run stores `<UTC start>-<hostClass>.json` and compares with the newest earlier report of the host class; `bench compare --history=<dir>` compares the two newest), `bench compare` also lists and fails on blocking objectives over budget.
   - independent oracle ops in the python oracle: `observe`, `history-name`, `history-latest`.
