## Design (ports, not workarounds)
Rule used everywhere: the lower layer owns a contract (a leaf module, a port type or an injected function), the upper layer implements or injects it; no module imports a layer above it, statically or dynamically.

1. Build library core knot (38 files: `caller/service` <-> `cli -> child`, host-capacity, graph/inference plugin):
   - `NativeBuildCallerCapabilitiesV1` moved to the leaf `🏗️build/📥️caller/📋️contract/🟦️.ts` (service, envelope and child import the contract, not the caller).
   - The service admission no longer imports the child bootstrap: `holdServiceInvocationV1` takes a `bootstrap:ServiceBootstrapPortV1` option (the door computation); the one holder (`⌨️command/⚙️runtime`) injects `createBuildBootstrapCapabilitiesV1`.
   - The native recovery frontend (`🚀️bootstrap/⌨️cli`) no longer composes its owners: `runNativeRepoRecoveryV1` takes `NativeRepoRecoveryPortSourceV1` (ports, or a provider of the ports of the selected plan); the composition root is the new `⌨️cli/🔌️ports/🟦️.ts` (`nativeRepoRecoveryPortsV1`), which the runtime passes.
   - `@semio-tech/repo-lib/build/inference` (inference plugin + argument shapes) no longer re-exports `nxBuildDependencyImplementationV1` from the plugin root (that edge closed the cycle graph -> repo-test -> inference facade -> plugin root -> graph pin -> graph); the identity has its own entry `@semio-tech/repo-lib/build/nx-plugin` (facade `📦️packages/…/🏗️build/🔌️nx-plugin/🟨️.mjs` + `.d.mts` + export key); three tests re-pointed.
2. `dependencies/storage` knot (4 files): the read-context primitives (`javascriptDependencyReadContextV1`, `observeJavascriptDependencyBindingsReadV1`, `readJavascriptDependencyBindingReceiptReadV1`, `javascriptDependencySourceOwnerRuntimeV1`, `selectObsoleteJavascriptDependencyGenerationsV1`, `javascriptDependencyGenerationDirectoryV1`, `requireJavascriptDependencyStorageV1`, the context type and its two helpers, `projectionPolicy`) moved to the leaf `📦️dependencies/💾️storage/📥️read-context/🟦️.ts`; generation and incremental glue import the leaf; the hub keeps lazily loading its stages. `JavascriptDependencyGenerationWalkV1` is now a consumer-owned shape declared in the generation glue (it read the full type of the Source-owner reader, which closed the cycle).
3. `budget/opening` knot (7 files): `openRepositoryCachePartitionAttemptV1` (opening without recovery, takes the way to open the lease image) and the enrollment `withRepositoryPartitionOperationV1` stay in the opening owner; the recovering opener `openRepositoryCachePartitionV1` moved to `♻️reset/🟦️.ts` (opening and recovery recurse through each other, one module); `recoverRepositoryCachePartition{Selected,Optional}HeadroomV1` moved to `📥️opening/🧹️headroom/🟦️.ts`; `withRepositoryDevelopmentStatePartitionV1` takes the opener as a port; the store charge (`repositoryCacheStoreReservationV1` + the shared store schema pin with its own stale guard) moved to `🏪️store/🎟️reservation/🟦️.ts`; the graph storage custody core (privately pinned consumer, schema/policy, retained async scopes, maintenance image and writer) moved to `🏗️build/📥️inputs/💾️storage/🔧️custody/🟨️.mjs` (+ `.d.mts`), which closes the `closures <-> graph storage` mutual import.
