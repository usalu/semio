# Result gofin4: client Go tests are hermetic, the process root is bound explicitly, a guard fails on any real-root resolution

Root `M` = `🧰️framework/🛍️products/🦑️repo/🔨️modules`, client = `M/💻️client/⌨️cli`, protocol module = `M/💻️client/🔌️mcp`. No cargo, no package.json/bun.lock edits. Tools in `gofin4-tools/` (`mkcopy.sh` builds the lean throwaway repo copy with its own `git init` and a read-only `node_modules` link; `run-client.sh <slug> [go test args]` syncs the client module into the copy and runs it with the canonical overlay `gocanon/plan.py`, `MOD=🔌️mcp` selects the protocol module; `compare.py` diffs per-test results). The copy and the logs are deleted. Nothing was run against the real checkout (the copy's `git status` showed changes only inside the client module).

## What was wrong
- `init()` of `🌱️root-and-repo-config` resolved the checkout the process started in, so every test binary started bound to the real repo; `TestMain` then bound the global executor to it; `setupToolTest`, `getTestExecutor`, `findTestRepoRoot`, `GetRootDir()`, cwd-relative `findRepoRoot(".")` and the global `executor` (used directly by 3 tests) all answered from it.
- `GetGitIgnoredSet` ran `git check-ignore` without `core.quotepath=false`, so emoji paths came back quoted and never matched (a real defect, hidden because the user's git config sets quotepath off).
- `workspace` (separate module) still resolves the real root in its own `init()`; the client now rebinds it on every `SetRootDir` and `boundExecutor` keeps it in step (see Open).

## Production changes
- No implicit default: `init()` removed, `rootDir` starts empty. `BindWorkingDirectory()` (new, exported) binds per invocation; called by `RunCLI`, `RunMcpServerFor` (so `RunMCP`/`RunMCPFor`), `RunHookFor` already did, and the `🔌️mcp` binary `main`. `SetRootDir` now also binds `workspace`.
- `ensureExecutor`/`sync.Once` global replaced by `boundExecutor()`: refuses with "repository root is not bound" while unbound, rebinds when the root changed, re-syncs the workspace root; the global is now private `activeExecutor` (so a test that used the old global no longer compiles). `gql()` uses it. `💪️effort` goal/ticket mutations therefore go through an executor bound to the test's own `withTempRepo` root.
- `findRepoRoot` = `resolveRepoRoot` + a `rootResolutionObserver` seam (nil in production) so the test guard sees every resolution.
- `GetGitIgnoredSet`: `-c core.quotepath=false`.
- `toolchainRoot()` in `🧫️test-runners`: the canonical Go dispatcher script and cwd come from `SEMIO_TOOLCHAIN_ROOT` when set, else the bound root. `📚️library/🧪️execution/🐹️go/🟦️.ts` (`GoTestScript`) now exports `SEMIO_TOOLCHAIN_ROOT=<repoRoot>` to the Go tests it spawns.

## Test changes (`🧪️tests`)
- `🎼️executor-harness` (renamed from `🎼️helpers` by a peer): `TestMain` runs in a sandbox (a temp git repo bound as root and cwd), records the real checkout root first, installs the observer, and after `m.Run()` fails the binary (exit 1, offending `Test*` named from the stack) if any root resolution landed inside the checkout or `rootDir`, the executor root, `testRepoRootOverride` or the workspace root still point into it. `setupToolTest` = `withExhaustiveRepo`; `getTestExecutor`/`findTestRepoRoot` deleted; new `moduleFixturePath`, `withGoalPath`, `withStatuteFixtures` (copies the statutes module's shared fixtures into a fixture repo), `requireToolchainRoot`.
- New `🛡️hermetic-root-guard` (6 tests): `TestNoTestResolvesTheRealRepoRoot`, detector self-tests (inside/outside, prefix sibling, held bindings), `TestTestSourcesDoNotLocateTheRealCheckout` (static scan of all 70 test sources for `findTestRepoRoot`, `os.Getwd(`, `runtime.Caller(`, `findRepoRoot(".")`, ...), `TestUnboundRootRefusesGraphQLQueries`, `TestBindWorkingDirectoryBindsTheExecutorToTheInvocation`. Mutation check: a temporary test calling `SetRootDir(<checkout>)` and leaking `rootDir` made the run print the violation with the test name and exit 1 (temporary test removed).
- `🔌️mcp`: new `🛡️hermetic-root-guard` (client must still be unbound; sources must not bind/resolve a root); `protocol-contract` reads its vectors from the sibling protocol module by module-relative path instead of `client.GetRootDir()`.
- Converted to fixtures: `💪️effort` (2 tests on `withTempRepo`), `🌈️` and `📋️` statute fixture tests (`withStatuteFixtures`), `🧜️` goal id (`withGoalPath`), `🪪️` goal/ticket compose ids, `TestGoalsMcpResource`, `TestExtractCheckpointSHAFromInput/empty_falls_back_to_git` (those three used to skip silently in the empty sandbox; now fixture repos and `t.Fatal`), `TestBuildBinaryArtifactsGitIgnored` (fixture `.gitignore`), `TestRenderPromptTemplateUsesRepoMetaRoot` (`t.Chdir`), `TestAllEntityEmojisProjectsTheFrameworkCatalog` (independent first-wins projection of `EntityKindCatalog`; catalog freshness stays owned by the TS `proveRepoEntityKindsOwnership`), module-fixture readers (`g1`, `glob`, `test-dispatch`, `territory`, `folder-file-policies`, `ticket-important`) via `moduleFixturePath`.
- Moved out of the Go suite (they read checked-in repo files, which is a repository law, not client behaviour) into `🧪️tests/🧱️checked-in-asset-contracts/🟦️.ts` (bun:test, reads the checkout read-only): MCP bootstrap assets (7 cases), Postgres kit schema, root ignore rules for build binaries (`git check-ignore`), real `post-commit` hook behaviour, dev MCP stdio initialize handshake. The Go micro-commit installer test now installs a stub hook.
- Deleted: `TestNativeHookEventMappingFromRealLogFiles` (read `.🧬semio/🦑️repo/📜️`, a legacy log directory that does not exist; it only ever skipped).
- `TestCanonicalGoTestDispatcher` and `...Cancellation` need the checkout's TS toolchain and a parent Script process invocation; they now skip unless `SEMIO_TOOLCHAIN_ROOT` is set (the repo's go-test runner sets it).

## Open
- `workspace` (`🏠️workspace/📦️packages/🐹️go`) still has its own `init()` that resolves the cwd checkout into `workspace.RootDir`. The client rebinds it in `SetRootDir` and the guard flags it if it points into the checkout, but other modules' tests that rely on that default are untouched.
- The dispatcher integration tests were not executed locally (they require running under `bun repo`'s Script process envelope; standalone they fail with "Original parent Script process invocation required"). The `SEMIO_TOOLCHAIN_ROOT` wiring in `GoTestScript` is unverified at runtime.
- The end-of-run check is enforced by `TestMain` (exit 1 plus a named list), not by a single named test, because Go cannot order `TestNoTestResolvesTheRealRepoRoot` last; the named test covers everything that happened before it runs.
- The TS handshake law is red until the root `📜️script.ts` import above is fixed.
