## Decisions (and why)
1. macOS image format = flat UDRW, created small and stretched (`hdiutil create -size 64m` seeded, then `hdiutil resize -size Nm`). Not UDSB (a directory: the leak sweep treats it as "backing removed" and detaches it, I saw it happen to my scratch bundle; receipts pin a file), not UDSP (`st_size` grows, receipts pin `size`), not ASIF (`diskutil image` only, macOS 26+). Same guarantees: APFS case-sensitive, RENAME_SWAP, nested attach with `-owners on`, kernel size cap (ENOSPC at N). Volume bytes == N exactly; `blocks*512` of the backing is no longer pinned (pinned allocation = declared extent `size`, neutral module `💾️storage/🪶️extent`; equal to the old value for every existing preallocated image because logical == allocated there).
2. Reclaim: nothing returns space while attached (APFS TRIM is not honoured by flat, UDSP or UDSB; `compact` needs a detached UDSP/UDSB). The footprint of a sparse image is its high-water mark; reclaim = recreate in a quiet window (cache = derived data). That is exactly what disk-g's GC + elastic recreate path expects.
3. Linux libc: loader names (`libc.so.6`, `libc.musl-<arch>.so.1`) probed once per process through the runtime FFI (`⚙️runtime/🧲️native/📚️libc`, table in a schema, EN+DE refusals); `renameat2` wrapper first, raw `syscall(316|276)` second (glibc < 2.28, old musl); unknown architecture refused by name. Node: unchanged and already tested (runtime test "refuses without a provider").
4. Windows without WSL: per-directory case sensitivity cannot be obtained without the optional feature (STATUS_NOT_SUPPORTED) and there is no other zero-touch case-sensitive store on stock Windows. Chosen: the partition is allocated FOLD-SAFE (anchor field `caseFold:"insensitive"`, read back by `nativeDirectoryCaseModeV1`) only for the two refusals `caseFeature`/`caseBuild`; every other refusal (access, not empty, unverified) still stops. Enforcement of fold-safety is the collision census `nativeDirectoryFoldCollisionsV1` (superset of NTFS/APFS folding, proven against a REAL case-insensitive APFS volume). OPEN, UNVERIFIED (no Windows host): the publication/restore layer must call the census before it writes a tree into a fold-safe partition; tool-written content (npm, cargo) cannot be intercepted, which is the accepted risk.
5. Tool paths: owners keep their single literal (`/usr/bin/hdiutil` in the hdiutil module, `/usr/bin/codesign` in sealing; the existing law enforces "named once", updated for the absolute literal); `pinNativeStorageProgramV1` proves once per process that a path is an absolute executable file (EN+DE refusal), Windows PowerShell comes from the validated SystemRoot. No bare name remains in the storage module (source law).
6. Stale attachments: the boot sweep now also detaches a workspace partition image that is attached without owners (blocks every nested attach) or never mounted (killed `attach`), but only when idle >= 15 min and its image lease is free; the detach re-proves the lease and is never forced.

## Right-sizing (coordinator addendum) - plan, nothing recreated yet
Facts: after this change the host cost of an image is its content, so a CEILING (declared capacity) is free; the budget stays the cap through disk-g's lock-aware GC. DECISION: keep the declared ceilings, change nothing in the pins; the footprint falls by recreating the images sparse. Consequences found in the code (why flat sparse UDRW and not UDSP/UDSB):
- UDSB is a directory: `healNativeLeakedImagesV1` (`🩹️recovery/📡️observe`) judges `present=isFile()` so a sparsebundle is "backing removed" and gets DETACHED by any peer's sweep. I saw it happen to my scratch bundle within a minute.
- UDSP grows its `st_size`; receipts pin `size` (and every identity check compares `size`).
- Flat sparse keeps `st_size` and the inode constant. The only thing that changes is `st_blocks`, and ~25 sites pin `blocks*512` (`allocatedBytes` of the publication/retirement/child-parent identities). For a preallocated image `blocks*512 == size`, so the pinned quantity becomes the declared extent (`size`): identical for existing images, stable for sparse ones.
