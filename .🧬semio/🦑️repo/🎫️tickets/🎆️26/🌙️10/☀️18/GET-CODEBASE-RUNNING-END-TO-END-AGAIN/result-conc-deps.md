## 1. Why one cold install blocked everybody (read from the code)
`ensureBuildEnvironmentV1` (called first by every dependency-requiring command since cli-zt) found "." unready and called `withJavascriptDependencyStorageV1`, which opened the dependencies image with **whole-image EXCLUSIVE queued maintenance** plus the **exclusive `javascript-dependency-bindings` gate for the whole operation**, then synced **all 6 scopes**, retired generations, published 309 bindings and sealed receipts under that one hold. ## 2. New protocol (schema-first: `🚦️concurrent/🧬️schema/🔣️.json`)
Generations were already content-addressed (`j/<key20>`, ready marker `bindings.json` written last); the fault was purely the lease protocol. Writers now run as phases and hold only what each phase needs:

| phase | image | leases | what it does |
|---|---|---|---|
| ensure (current) | shared | none | receipt check only (`inspect(false)`, unchanged); returns before any install |
| build | shared | `build` (EX, one builder) | pre-build collection (frees space when the image is tight), then install fresh scopes into new `j/<key>`, ready receipts, installed-paths proof; **stops before any binding**; scopes whose generation exists cost nothing |
| publish | shared | `build` + `bindings` (EX, short) | same producer over fully built generations (refuses if one is missing), binding switch, receipts, **atomic pointer replacement** per scope |
| collect | shared | `build` + per-generation `pin` (EX try) | unreferenced generations only: not a plan generation, not a binding target, not pinned, past retention; removed through a tombstone rename so a crash never leaves a half-removed generation name |
| read (consumers) | shared | `bindings` (shared) + `pin` (shared) | unchanged readers plus pins on the generations they read |
| receipt write | shared | `generation-writer` (EX, short) | parser/generation receipts, never waits for a build |

Lock order is `build -> bindings -> generation-writer`; readers take `bindings -> pin` and never `build`, so there is no cycle. Waiting is polite: a busy lease is probed every 500 ms with zero wait (plain, non-queued leases: measured that a waiting plain EX does not block new shared readers, a queued EX would), so a waiting publisher or builder never stalls a newcomer. Publication waits at most 15 min for readers to drain, then fails resumably (generations stay built; the next ensure only repeats the short publish).

- **Coalescing**: a second `ensure` that finds the build lease busy rechecks readiness (`recheck`, the existing receipt predicate) every 5 s and returns as soon as the build made it unnecessary; if it acquires the lease after the builder, `installUnlessReadyV1` rechecks again. Progress line every 10 s in EN or DE (`SEMIO_LANGUAGE`, locale), plus a `[DATA] Store dependency concurrency {...}` event.
- **Pointer**: `pointer/<sha16(scope)>.pointer.json` = `{scope, generation, epoch, publishedAtMs, retired[<=8], sha256}` replaced by temp file + fsync + rename + dir fsync; it is the publication commit record and carries retirement times for the retention rule.
- **Retention** (`retention` in the schema): unreferenced generations are kept 6 h after they were retired (not after they were built), the newest retired generation of a scope (rollback target) 24 h, both shrink to 0 while the image has < 25 % free, at most 16 per run, pinned ones never.
- **Incremental unit**: the scope (one bun lock + node_modules). A manifest edit changes only its scope's generation key (sync-incr tiers decide that cheaply), so only that scope is built, only its bindings change, every other scope is neither installed nor touched; the warm shared Bun cache plus clonefile makes that rebuild link-only. Seeding a new generation from the previous `node_modules` was evaluated and NOT staged: Bun's isolated linker may leave extraneous `.bun` entries and no independent oracle of the exact membership exists, so it would break the exact installed-paths proof.
- `ensure` stays on `{kind:"all"}`: its readiness predicate checks only the bootstrap scope, but the previous behaviour installed every scope and followers must not run tasks of another scope against a half-built set.

## 6. Open items and risks
1. **Writing into the dependencies image under shared custody is unproven live** (cargo and the shared receipt writer already do it; I could not run a real image). If the native storage layer refuses shared writers for this partition the first build fails fast at open; fallback is none by design (no compatibility layer).
2. A queued whole-image maintenance caller on `d` (pruning budget, headroom, tools) now waits for a long build and, being queued, blocks new shared opens meanwhile. Such callers should take the `build` lease politely first; not changed here.
3. The Bun cache purge after a cache-link refusal still empties the shared `bun-cache` while only the build lease is held; nothing else installs, but another tool reading that cache would see it empty.
4. Image headroom: the image was 83 % used during the Codex install; the pre-build collection (pressure rule frees every unpinned superseded generation) is what makes side-by-side fit; a scope larger than the free space still fails with ENOSPC without touching readers. A standalone `repo dependencies gc` operation is the obvious follow-up.
5. A publisher waits at most 15 min for readers that hold the gate (long-running consumers); then it fails resumably. Readers that never take the gate (processes started before the switch) see the new bindings mid-run, as before.
6. `ensure --help` still lists `--all/--scope` that ensure refuses (cli-zt open item), untouched.

## 7. Group 2 (READY2): generation-scoped maintenance and image-fullness admission
Staged on top of group 1 (18 more anchored ops in `mkops2.py`, group-2 versions of `core.ts`, `glue.ts`, `schema.json`, the test, fixture and oracle under `staged/g2/`). Apply: `python3 apply.py apply --group 2 --write` (refuses unless group 1 is applied; `--group all` applies both in order; the default stays group 1; `check`/`mirror` take the same flag).
- **Maintenance holds only the shared image.** `collectJavascriptDependencyGenerationsV1` / exported `maintainJavascriptDependencyGenerationsV1` take no build lease, no bindings gate and no whole-image hold, so a running build never blocks them. A generation goes only if it is not a pointer's current one, no live binding resolves into it (read from its ready receipt by `readlink`; an unreadable receipt counts as referenced), its EX pin is free, and the retention rule is due; removal is pin, tombstone rename, delete. The builder now pins every plan generation before it creates or resumes it (pins live in the writer frame), which is what makes lease-free collection safe for a generation under construction or built but not yet published. The post-publish collection and the old pre-build collection use the same function (the producer no longer deletes anything).
- **Admission before every fresh scope.** Expected size = the size recorded in that scope's pointer (new `bytes`, measured as free-space delta around its install), else the largest recorded, else 1 GiB; required = expected x 1.15. If the free bytes do not hold it: reclaim now (collection with the pressure grace, which also frees rollback targets), re-measure, and if it still does not fit, throw an EN/DE diagnostic (`admissionRefused`, language from `SEMIO_LANGUAGE`/locale, both texts plus numbers in `cause`, `[DATA]` event `refused`) before any install starts; published generations stay untouched and the next ensure resumes with the scopes already built.
- **Verified** in the mirror: 14 tests pass (admission table and size-aware pointer chain against the Python oracle, bilingual refusal texts, a model collector over real leases and a real tree with a build lease held: no wait (<500 ms), spares referenced / young / reader-pinned / builder-pinned / current / unreadable-receipt generations, removes the old one, leaves no tombstone, collects the builder-pinned one only after its pin ends), group 1 alone still 12 pass, tsc clean, regression rows identical to baseline (storage 27/19, reading 44/36, incremental 15/0, fence, platform, contract, bootstrap), nlink 0 offenders.
- **Limits**: whole-image maintenance that genuinely needs quiescence (reset, layout) still waits for a build; reclaiming space no longer needs it. No `repo dependencies gc` verb was added (catalogue and help snapshots are pinned by tests); the API above is ready for one.
