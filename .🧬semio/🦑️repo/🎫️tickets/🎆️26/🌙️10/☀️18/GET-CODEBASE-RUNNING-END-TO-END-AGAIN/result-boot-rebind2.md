## Root cause and decision
- boot-rebind's `apply.py` was NOT re-applied: round 6 replaced the "rewrite the receipt to the new device numbers" design by a read-only one (`N/🧹️cleanup/🎛️command`: `ImageReceipt` REQUIRES `bootSession` + `ancestry`; `inspectPersistentReceiver` binds by the ancestor inode chain `requireNativeImageAncestryBindingV1` and never rewrites). A receipt without those two fields (the Oct-18 ones) is simply a stale FORMAT: greenfield rule, no compat layer, no rebind.
- The root mechanism for "stale receipt format -> retire and rebuild" already existed but only for the `nx` partition (`O/♻️reset/`: preflight DATA observation `unsupported-receipt-shape` -> exclusive reset of the inactive capsule -> ordinary opener creates a fresh image; fixture `publications` already held the "missing bootSession / missing ancestry" cases). `openRepositoryCachePartitionV1` ran it only for `id==="nx"`, so every other partition (tools t, graph g, dependencies d, products p, diagnostics o, leases l, rust) and every cargo workspace cache root (`🧰️framework/.cache/b/{l,t}`) threw `Exact canonical persistent Native publication required` for a legacy receipt.

## Consequences to know
