# Build CLI front door

## English

The front door is the entry the `repo` launcher starts for every build command (`🚪️door/📜️script.ts`). It reads the neutral operations catalogue and answers what needs no build implementation: help of every command, refusals of unknown commands, unknown subcommands of closed sets and values outside an option's enumeration, and the light commands declared in `🔣️.json` (`leases`, `capacity`, `doctor`). It loads 11 modules (about 64 KB) for help and a refusal, the command's own closure for a light command, and the build implementation (`../📜️script.ts`) only when a command needs it.

- **Declared, not hand-listed.** Commands, subcommands, options, languages and help come from `⚙️operations/🔣️catalog.json`; the door's own data is `🔣️.json` (closed schema `🧬️schema/🔣️.json`): the light operations, which subcommand sets are closed, the target prefixes that must reach the full implementation, and the EN/DE refusal texts. There is no default language: the shared language rule decides, and a refusal is bilingual.
- **Exit codes.** A refusal prints to stderr and exits with `refusedExitCode` (2); a light command exits with its own code.
- **Law.** `🧪️tests/🚦️startup` fails when help, a refusal or a light command loads a heavy module group (graph, native build, test harness, caller, invocation, selection, resident service, tool bootstrap, store receipts, tools); the traced module list equals the static closure that esbuild computes for the door.
- **Adding a light command.** Declare it in `🔣️.json`, add one literal loader to `buildDoorLightLoadersV1` and its row to `🧪️tests/🚦️startup/🔣️.json` with the groups it may not load.
- **Restart (`🔄️restart`).** The full route loads the build implementation INSIDE the restart supervisor of the format stamp protocol, so a module a peer is moving or half editing while it loads, a raw filesystem race (`ENOENT`, `ENOTDIR`, … on a workspace path, classified by `🔁️churn/🌊️races`) and a moved format stamp all end in the declared restart instead of an uncaught failure: the outermost command waits 0.25/1/4/12/30/30 s, announces it in English and German and starts again with a new snapshot (6 restarts, the count restarts after a 10-minute run); a nested command prints its cause and yields exit 75, and only a restart that keeps failing early ends the command with exit 75.
- **The chain of one run.** A command that needs the build implementation is a short chain: `bun repo` (script runner), this door, the executor (a `bun --eval` loader that runs the captured implementation snapshot) and, only when the graph has to be planned, the planner (the second loader). The door waits for machine capacity before anything else is spawned (a waiting run is the door alone, below 100 MB, with no loader child); the planner is started by the executor directly from the snapshot it holds (`runAdoptedCapturedBuildSourceV1`): no second front door, no second source capture, no `repo` runner in between. A loader's memory does not grow with its module count (the admitted-source and import-resolution tables are one frozen global that every module reads, not a copy inside every transpiler). Law: `🧭️invocation/🧪️tests/🔗️process-chain` (corpus `🔣️.json`: planner argv and Original, loader memory against `ps`, the waiting door, the second loader of the same snapshot).

## Deutsch

Die Vordertür ist der Einstieg, den der `repo`-Starter für jeden Build-Befehl startet (`🚪️door/📜️script.ts`). Sie liest den werkzeugneutralen Operationskatalog und beantwortet, was keine Build-Implementierung braucht: die Hilfe jedes Befehls, die Ablehnung unbekannter Befehle, unbekannter Unterbefehle geschlossener Mengen und von Werten außerhalb der Aufzählung einer Option sowie die in `🔣️.json` deklarierten leichten Befehle (`leases`, `capacity`, `doctor`). Sie lädt für Hilfe und Ablehnung 8 Module, für einen leichten Befehl dessen eigene Hülle und die Build-Implementierung (`../📜️script.ts`) nur, wenn ein Befehl sie braucht.

- **Deklariert, nicht von Hand gelistet.** Befehle, Unterbefehle, Optionen, Sprachen und Hilfe stammen aus `⚙️operations/🔣️catalog.json`; die eigenen Daten der Tür sind `🔣️.json` (geschlossenes Schema `🧬️schema/🔣️.json`): die leichten Operationen, welche Unterbefehlsmengen geschlossen sind, die Ziel-Präfixe, die zur vollen Implementierung müssen, und die EN/DE-Texte der Ablehnungen. Es gibt keine Standardsprache: die gemeinsame Sprachregel entscheidet, und eine Ablehnung ist zweisprachig.
- **Exit-Codes.** Eine Ablehnung geht nach stderr und endet mit `refusedExitCode` (2); ein leichter Befehl endet mit seinem eigenen Code.
- **Gesetz.** `🧪️tests/🚦️startup` schlägt fehl, wenn Hilfe, eine Ablehnung oder ein leichter Befehl eine schwere Modulgruppe lädt (Graph, nativer Build, Testgeschirr, Aufrufer, Invocation, Selektion, residenter Dienst, Werkzeug-Bootstrap, Store-Quittungen, Werkzeuge); die verfolgte Modulliste entspricht der statischen Hülle, die esbuild für die Tür berechnet.
- **Leichten Befehl hinzufügen.** In `🔣️.json` deklarieren, einen literalen Lader zu `buildDoorLightLoadersV1` und seine Zeile zu `🧪️tests/🚦️startup/🔣️.json` mit den Gruppen, die er nicht laden darf, ergänzen.
- **Neustart (`🔄️restart`).** Die volle Route lädt die Build-Implementierung INNERHALB des Neustart-Überwachers des Formatstempel-Protokolls: ein Modul, das ein anderer Prozess beim Laden verschiebt oder halb bearbeitet, ein roher Dateisystem-Wettlauf (`ENOENT`, `ENOTDIR`, … auf einem Arbeitsbereichspfad, eingeordnet von `🔁️churn/🌊️races`) und ein gewechselter Formatstempel enden im deklarierten Neustart statt in einem unbehandelten Fehler: der äusserste Befehl wartet 0,25/1/4/12/30/30 s, meldet das auf Englisch und Deutsch und startet mit einem neuen Schnappschuss erneut (6 Neustarts, die Zählung beginnt nach einem 10-Minuten-Lauf neu); ein verschachtelter Befehl nennt seine Ursache und meldet Exit 75, und nur ein Neustart, der früh immer wieder scheitert, beendet den Befehl mit Exit 75.
- **Die Kette eines Laufs.** Ein Befehl, der die Build-Implementierung braucht, ist eine kurze Kette: `bun repo` (Skript-Starter), diese Tür, der Ausführer (ein `bun --eval`-Lader, der das erfasste Implementierungs-Image ausführt) und, nur wenn der Graph geplant werden muss, der Planer (der zweite Lader). Die Tür wartet auf Maschinenkapazität, bevor irgendetwas gestartet wird (ein wartender Lauf ist die Tür allein, unter 100 MB, ohne Lader-Kind); der Planer wird vom Ausführer direkt aus dem Image gestartet, das er hält (`runAdoptedCapturedBuildSourceV1`): keine zweite Vordertür, keine zweite Quellerfassung, kein `repo`-Starter dazwischen. Der Speicher eines Laders wächst nicht mit seiner Modulzahl (die Tabellen der zugelassenen Quellen und Importauflösungen sind ein eingefrorenes Global, das jedes Modul liest, keine Kopie in jedem Transpiler). Gesetz: `🧭️invocation/🧪️tests/🔗️process-chain` (Korpus `🔣️.json`: Planer-Argumente und Original, Laderspeicher gegen `ps`, die wartende Tür, der zweite Lader desselben Images).
