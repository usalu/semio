- `fresh`, dep-info gaps: no local build script and no `env!`/`option_env!` anywhere in the 437 Rust sources of the binary's dep-info (scanned the 452 recorded files); registry crates are pinned by `Cargo.lock` (in the digest; Cargo's binary dep-info lists only local packages, 0 paths outside the workspace in the live record); toolchain pinned by `rust-toolchain.toml` (dated nightly, in the digest); `.cargo/config.toml` (RUSTFLAGS etc.) in the digest; features/targets come from `📋️project.json`/`Cargo.toml` inside the roots; mode is keyed per record; proc-macro inputs read with `std::fs` are invisible to Cargo as well (no regression: before `fresh` the same cargo said fresh). Timing: `builtAtMs` is taken before cargo starts; edits between source capture and the nested compile are caught by the digest (inside roots) or still read by cargo (outside roots); max(mtime, ctime) catches timestamp-preserving replacements Cargo itself misses. Residual, not staged: the build tool's own code (documented), clock skew between a devcontainer and host-edited bind-mounted files (Cargo has the same exposure), a dep-info path that is a symlink retargeted to an older file (none in the tree).
- memoedit: the edit settlement re-checks with the engine's own `sourceAnalysisFactHoldsV1` (replays the analysis on the current bytes and compares the result digest and nested observations; a throwing analysis = does not hold). The Rust analysis records `mod` (incl. `#[path]`), `include*!` targets (dynamic ones throw), `cfg(test)` gating (a cfg change changes the image), and THROWS on `macro_rules!` that can mount a file and on `cfg_attr(..path..)`; the TS module parser records re-exports (`export * from`, `export {x} from`), dynamic `import()`, `require`, JSON imports (probe `audit5-tools/ts-import-probe.mjs`). So a content edit is served only when the planner's own refresh would keep the owner (same check); every relevant journal path with no named row is refused unless it is a frontier member, whose content no fact reads (members are only checked by mode, as `advanceFrontierV1` does). Cursor/race: the record's cursor is the journal position read BEFORE the checks, so a later edit is reported next time; concurrent lookups writing older cursors only cause more rechecks; restamps require the pre-check stamp, unchanged and outside the racy window. Pre-existing planner-level gaps it inherits (not memoedit's): `#[path] mod` inside a function body and mods emitted by a macro defined in another crate are not seen by the Rust analysis; `new URL("./x", import.meta.url)` is not a module import.
