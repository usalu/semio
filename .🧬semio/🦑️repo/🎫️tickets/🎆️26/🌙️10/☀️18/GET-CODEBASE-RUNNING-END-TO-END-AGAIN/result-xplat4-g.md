## 1. F3 (Windows suite rows advisory)

Method (rule is data, `🗂️suites/🖥️platforms/🔣️.json`, closed schema, EN docs in the schema): a test file counts a host-bound fact as an unconditioned cause of its suite when it uses it (a) outside a test whose header is `skipIf`/`skip`, (b) on a line that does not name the platform (for symlink, permission bits, process control), (c) in a test block that does not mention the platform (`win32`, `process.platform`, `posix`, ...). Six causes: `posix-program` (sh, ps, pgrep, kill, find, hdiutil, `/usr/bin/...`), `posix-shell-script` (shebang, `sh -c`, `execSync`), `python3-command` (a literal `python3` spawned; the pinned interpreter is not guaranteed under that name on Windows), `symlink` (`symlinkSync`), `permission-bits` (`chmodSync`, `mode & 0o...`), `posix-process-control` (`process.kill(-pid)`, SIGSTOP/SIGCONT, fcntl/flock in a Python probe, O_NOFOLLOW, getuid). Suite causes = union over its files (and the module of a function suite). Verdict: no cause => `platforms: [darwin, linux, win32]`; else `[darwin, linux]` + `platformCauses`, EXCEPT the suites the CI policy (`mustRun` all + win32) requires on Windows.

Result over the 3 tables (220 suites, 982 test files): 147 suites Windows-capable (process 54/67, caching 68/102, build 25/51), 73 POSIX-only (13/34/26). Causes of the 73: python3-command only 18, symlink only 18, symlink+permission-bits 5, python3+symlink 5, posix-program only 3, process control only 3, the rest 21 mixed. Only 5 process and 4 caching project targets had to become uncacheable/live (a skipped suite must never be replayed as a pass); all others already were.

Schema-first: `platformCauses` (enum `PlatformCause`, 6 values, closed, unique) added to the suite schema next to `platforms`; the table schema stays permissive for fixtures, the repository laws are strict.

Laws (new `🖥️platforms/🧪️tests`, 8 tests, TypeScript module vs independent Python reading, `🐍️oracle/🐍️.py` shares only the policy JSON):
1. policy is a closed document (Ajv strict + module validator, 8 malformed variants refused, causes equal the table schema enum);
2. 13 evidence vectors (skipped header, platform-naming block, line guard, no line guard for programs, literal python3, order of causes, describe-skip not inherited, German letters before a call, same-line header/marker, `test.skip`) give identical results in both readers; two mutated policies (marker dropped, line guard removed) change the verdicts, and both readers agree on the changed result;
3. verdict derivation unit test; findings (`unjudged`, `unexplained`, `overexplained`) equal in TS and Python;
4. LAW "every suite has an explicit and explained platform verdict": the three live tables have none of the three findings;
5. LAW "platforms follow evidence": for all 220 suites the module and Python find the same causes and the declared `platforms`/`platformCauses` equal the derived verdict;
6. LAW "a suite that leaves a host out is never replayed from a cache": its project target is `cache:false` class `live`;
7. LAW "mustRun suites are declared for their host".
Mutation controls run on the overlay (all caught): removing a `platforms` field fails 4 tests, declaring Windows for the `workspace` suite (uses `bash`/symlinks) fails law 5, making `javascript-storage`'s target cacheable fails law 6. Existing laws still green with the batch: process suites 7/7, ci-report 18/18, ci suites 16/16.

Workflow (staged, `.github/workflows/build-system.yml` + `🧾️ci-report/🗂️suites/🧪️tests/🔀️workflow`): `advisory` removed from all 21 rows and `continue-on-error` removed from the `suites` job, so all rows block; header comment says why. A POSIX-only suite on Windows prints `SKIPPED, not passed` (exit 0, existing runner) and the report counts it as skipped, never passed. The workflow law now requires the rows to carry no advisory flag and the job no `continue-on-error`. I staged the workflow instead of editing it live because the live workflow law (ci-g) pins the advisory rows and would go red between the edit and the landing.

FINDING (needs the first Windows run, or the owners): 8 suites that the CI policy already requires on Windows still carry unconditioned POSIX facts, so they are tagged Windows-capable and now block in the sweep rows as well as in `host`: `process/descriptor-lifetime` (posix-process-control; the line is a fake descriptor table, probably a false positive), `process/process-tree-termination` (a real `sh` holder in the taskkill grammar test), `process/build-facets` (python3 name), `process/native-storage` (all six causes, many darwin tests; most are probably inside gated tests of dense lines), `process/leases` (symlink in the sweep law), `caching/cargo-unit-cache-processes` (find, chmod, symlink, python3), `build/build-inputs-revision` (python3, shell text, symlink), `build/build-bazel-execution` (shell, chmod, symlink). Either the tests get their gates or the policy drops the suite from `mustRun`; the law (5) accepts a Windows verdict with causes only for `mustRun`.

Known limits of the evidence (static, never run on Windows): the markers cannot see path separators in expected strings, renames over open files, CRLF, the 256-char limit or a missing tool; a Windows-capable verdict means "no POSIX fact found", the first Windows run decides. Symlink-only suites (18) are held back conservatively although GitHub's Windows runners are administrators; widening is mechanical (probe-gate the symlink tests like xplat3-g's runtime tests, then the tag falls out of `tag.py`). The 18 python3-only suites would follow by calling the pinned interpreter helper instead of the literal name. No darwin-only or linux-only tags: suites keep their per-test `skipIf` granularity (laws-g decision).
