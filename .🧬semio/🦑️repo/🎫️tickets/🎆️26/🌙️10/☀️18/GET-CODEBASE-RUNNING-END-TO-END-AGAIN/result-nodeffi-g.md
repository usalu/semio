## Why a native addon is unavoidable (justification, as the brief demands)
Node 24.15 has no FFI (`node:ffi` absent). The contract is a generic FFI (`dlopen`, typed reads, buffer addresses) and its consumers bind libc calls Node built-ins cannot express: dirfd-relative `openat`/`fdopendir`/`readdir`/`fstatat|statx`/`unlinkat`/`readlinkat`/`linkat`/`symlinkat`, `flock`, `renameat2(RENAME_EXCHANGE)`/`renamex_np(RENAME_SWAP)`, the thread errno cell, Win32 `NtCreateFile`/`MoveFileExW`. `fs.rename`, `fs.statfs`, process APIs cover none of the capability-based, TOCTOU-safe forms (those modules exist exactly to avoid path-based calls); emulating them from paths would silently drop the guarantees the descriptor laws assert. A broker process cannot work either (file descriptors and `flock` ownership are per process). Minimal = seven primitives, no libffi, no npm package: `open`, `symbol`, `close`, `call` (one `extern "C"` trampoline of 8 integer-class words, valid for SysV x86-64, AAPCS64 and Win64), `addressOf`, `peek`, `view`.

## Scope and honest limits
- Integer-class symbols only (≤ 8 args): floats (`f32`/`f64`) and `JSCallback` are refused by name in EN+DE (no consumer on the Node path; callbacks exist only in the Bun-only macOS FSEvents module). Variadic callee on Apple arm64 behaves as with Bun (named args only).
- VERIFIED on this Mac (darwin arm64). Linux and Windows are NOT executed (no host; docker daemon is down). What IS proven for them: the Rust core type-checks and generates code for `x86_64`/`aarch64` Linux, `x86_64`/`aarch64` Windows MSVC and `x86_64` macOS (test "generates code for every declared target whose standard library is installed", rustup targets added locally for the check; skipped visibly elsewhere); the libc resolver/syscall branches are store-g's; cache-root/compiler-discovery/target tables per platform are unit tested with injected hosts. Windows links against `node.exe` through `raw-dylib` (UNVERIFIED), kernel32 through `raw-dylib`.
- First use on a machine needs the pinned Rust toolchain (rustup shim reads `rust-toolchain.toml`) and a C linker (`cc`; MSVC on Windows). Missing compiler = named EN/DE refusal telling `SEMIO_RUSTC` / `SEMIO_RUNTIME_NATIVE_ADDON` (prebuilt core). macOS Xcode-license refusal is retried once with `DEVELOPER_DIR=/Library/Developer/CommandLineTools`.
- The build runs synchronously (the contract is synchronous): a 600 s timeout, a stderr notice (EN+DE), Ctrl+C reaches the compiler through the process group; no async progress API yet → FOR tools-setup owner: call `ensureNodeNativeAddonV1(defaultNodeNativePortsV1())` from `repo tools setup`/`preflight` to prebuild (zero-touch in practice, nothing needs it).
