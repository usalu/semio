# result-repo-launcher: `repo` without a JavaScript runtime installed

READY (stage only, nothing applied live). `C` = this ticket, tools = `C/repo-launcher-tools/`, `M` = `🧰️framework/🛍️products/🦑️repo/🔨️modules`.

## What exists now
- **One launcher, Go.** New module `M/🚀️launcher` (stdlib only, 8 member dirs + `📦️main`): resolves the repo root (the shared workspace corpus), loads the schema-declared registry `M/🚀️launcher/🗂️registry/🔣️.json` (schema next to it, contract 1), provisions the pinned runtime, hands over (unix: `syscall.Exec`, same PID/signals/exit code; Windows: child with console, interrupt forwarding, exit code), prepends runtime dir and launcher dir to the child `PATH` (so nested `bun`/`repo` resolve the pinned ones).
- **Registry = swappable runtime adapter.** `runtimes.<name>`: version, executable names, probe, https download base, `launch.before/options/environment`, distributions (platform x arch x libc, bytes, SHA-256). `selected`, `entry.runtime`, `SEMIO_RUNTIME=<name>` choose; the code knows nothing else about bun. Single reading of the existing bun pins (parity law against `🟦️bun/🧬️schema` and `packageManager`); `bun` unused by CI/Dockerfile/bootstrap now.
- **Provisioning.** Lookup order: tools partition `.cache/b/t/m/<runtime>/<sha>` (what `tools setup` writes), then user cache (`SEMIO_RUNTIME_CACHE`, else OS cache dir `semio/runtimes`). Missing: lock file (peers wait, one download), https/loopback mirror (`SEMIO_RUNTIME_MIRROR`), size + SHA-256 before unpack, bounded extraction, version probe, atomic rename publish, progress on stderr, Ctrl+C cancels and leaves nothing. Decision: the launcher writes only the user cache (the tools partition is a DMG that only the runtime's own machinery mounts and accounts); it reads the partition first, so `tools setup`'s copy is reused.
- **Routes** (one planner, shared by launcher and full cli): `build` verbs, `workspace` (`dev mcp stdio os`), new `script` route (`repo [--watch] [--cwd <dir>] ./x.ts args`, options mapped by the registry), `mcp`/`domain` (stand-alone launcher refuses with `repo run repo-mcp:install`; the full `repo` embeds the launcher). **Build verbs are derived from the operations catalogue** (`registry.routing.catalogue`), no hand list (request of repo-mcp-build); `launcher.BindRoot` for sandboxed test binaries.
- **`repo --version`** (EN/DE): launcher version + contract, every runtime (pinned version, path when provisioned, never fetched), implementation version (`🦑️repo/package.json`). No default language: shared protocol/fixture of the build language module; unresolved language refuses in EN+DE, silent hot path needs none.
- **One command to install:** `bash M/🚀️launcher/📥️install/🐚️.sh [dir]` (macOS/Linux/devcontainer) / `powershell -File M\🚀️launcher\📥️install\🔵️.ps1 [-Destination dir]` (needs only Go; flattened build, `rm`+`mv` new inode). From a bare machine: the existing full bootstrap `🔩️native/🥾️bootstrap/🐚️.sh|🔵️.ps1 setup` now installs Node/Go/rustup/uv, builds the launcher, `repo run repo-mcp:install` (no Bun installed by hand anywhere).
- **Consolidation:** Go launcher kept (it is the shipped one and embeds the new module); `🚪️entrypoint_unix.go`/`_windows.go` and `LookPath("bun")` deleted; the Rust `BunScriptTool`/`run_native_*` deleted, Rust keeps `plan_native_entrypoint` (same vectors, catalogue-derived, script kind) and refuses to start build routes.
- **`rustc-wrapper`:** `.cargo/config.toml`, ingress `🔣️policy.json` and its schema now `"repo"` (cargo runs `repo <rustc script> args`, i.e. the script route).
