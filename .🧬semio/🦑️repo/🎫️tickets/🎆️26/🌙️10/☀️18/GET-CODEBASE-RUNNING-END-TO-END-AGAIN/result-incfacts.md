## 2. Decision: they are load authority, not project facts
- The observation layer already has the home: `inferenceAuthorityDigestV1` "names [module-load authority] by the meaning of its data facts, so project records inherit the declared policies and schemas by digest instead of by rows"; every record identity = record stamp + authority digest + key. Reads made at module load / wire time (coordinates `POLICY`/`WORKSPACE_POLICY`, source-analyses `TAXONOMY`, and `implementationRevision()` over `implementationFiles`) are authority rows.
- Generation side: `implementationFiles` (revision) rows are classified by the stamps protocol; data files no inferrer claims become `implementation.all` rows of EVERY owner + `@env`; code is named by an inferrer stamp, never by bytes (law `🔖️stamps`: no unclassified executable file).
- So: the build policy is ALREADY authority (coordinates load read) and an `all` row (sectional: `hostCapacity`/`workers`/`remote*` ignored). The per-walk re-read was redundant AND harmful: the whole-file row made a `hostCapacity` edit stale every walking owner at generation level, defeating the sectional design.
- Precision rules + schema: data → `implementationFiles` (rules added; schema was there) → `all` rows + authority. Granularity loss: none in practice — every project with a cached target consults the whole document (`selectRuleV1`), i.e. every such project already recorded the rules file.
- Precision engine: code → claimed by the `project-assembly` stamp (fragment `🏗️build/📥️inputs/🎯️precision/🟦️.ts`), listed in the revision (loader reload), dropped from generation rows by classification, excluded from the authority digest like all stamped code. An engine edit that changes outputs must bump `project-assembly` (protocol rule, same as every other inference module).
- Taxonomy kinds: `fileKinds` joins the taxonomy projection (`TAXONOMY`, an analysis fact of the load authority); `source-analyses` stamp 1 -> 2 (its projection output changes for the same input; golden renamed, digests unchanged).
- Not chosen: provider/token reference (peeredit2 style) — that is for closures consumed by SOME projects; these are consumed by all, so the environment/authority row is the cheaper exact form. Not chosen: "read unobserved" (td-observe idea) alone — record reuse keys on stamp+authority+key only, so an unobserved rules read would let a stale persisted record be reused after a rules edit; the reads stay observed at load time.
