### 🧰️ The tool registry and the direct-spawn law

No code starts an external program on its own. Every tool the repository uses (25 of them: `repo`, bun, node, bazel, nx, cargo with rustc, rustfmt, rustdoc and clippy, rustup, go, uv, python, dotnet, cmake, ninja, tsc, vite, vitest, playwright, tectonic, wasm-opt, jco, wasm-pack, hdiutil, docker, git, gh) is one row of a schema-first registry, and every start goes through one process API. State: registry {{@tool-registry}}, law {{@tool-spawn-law}}.

```bash
repo tools list
repo tools verify --only=go,uv
repo tools exec --light git -- --version
repo tools exec --cwd <directory> cargo -- --version
repo verify tool-spawns --report
```

- **A row** names the tool, its kind and capabilities, the executables it owns (one owner each), its platforms, its pin, how it is provisioned, where it is located (an environment override `SEMIO_TOOL_<ID>`, the running runtime, a content-addressed provisioned directory, a package script, the `PATH` and well-known directories, in that order), how it is probed, the one adapter module that may start it raw, the globs allowed to call it, its environment rules and whether it waits in the host capacity queue. Texts exist in English and German.
- **Pins are pointers, never copies**: Go, uv, rustup, node and the .NET installer point into the bootstrap pin rows, bun, bazel, wasm-opt and tectonic into their own release tables, nx and tsc into the tools `package.json`, vite, vitest, playwright and jco into the root `package.json`, cargo into the `rust-toolchain.toml` channel, python into `requires-python`, cmake into the preset minimum. A pin is `pinned`, `constrained`, `floating`, `system` or `internal`, and a floating tool states its gap.
- **`repo tools list [--json]`** prints each tool with its pin, where it was found and its command. **`repo tools verify [--only=<ids>]`** resolves and probes every tool and reports missing ones and differences from the pin (exit code 1); on the primary host it reported real drift: bun 1.3.14 against the pin 1.4.2, go 1.25.0 against 1.26.9, uv 0.11.15 against 0.11.6, and tectonic and wasm-opt not provisioned. **`repo tools exec [--cwd <dir>] [--light] <tool> -- <args>`** runs a tool with the registry's environment, waits in the capacity queue unless `--light`, forwards Ctrl+C and returns the tool's exit code.
- **One process API in three languages**: `runToolV1` (TypeScript), `RunTool` (Go), `run_tool` (Rust). Options carry cwd, environment, signal, timeout, capture and a declared caller; progress shows the phases admitting, running and finished; errors are typed (`unknown-tool`, `tool-missing`, `caller-refused`, `cancelled`, `failed`) with English and German text. The old funnels (`runOwnedCommand`, `captureOwnedCommandV1`, `runCmd`, Go `ExecCommand`) route a registered command name through the registry, so hundreds of existing call sites moved without being touched.
- **Sanitized environment.** IDE and debugger injections (`NODE_OPTIONS`, `VSCODE_*`, `CURSOR_*`, `ELECTRON_RUN_AS_NODE`, `JAVA_TOOL_OPTIONS`, `npm_config_*`) are always dropped; allowlist tools keep only the base and their own variables; registry values win (`GOCACHE` and `PLAYWRIGHT_BROWSERS_PATH` live under the shared cache, `UV_PYTHON_DOWNLOADS=never`, dotnet telemetry off); every run is marked `SEMIO_TOOL_RUN=<id>`. Code that deliberately passed `NODE_OPTIONS` to a bare command must pass it to `runToolV1` as an explicit value.
- **The law** `repo verify tool-spawns [--report] [--json] [--strict] [--prune [--accept-new]]` scans TypeScript, Rust, Go, Python, shell and PowerShell sources and the commands declared in manifests. A registered tool started outside its adapter is a finding (`raw-spawn`), a manifest that declares more commands for a tool than before is a finding (`declared-grew`), and a call `runToolV1("id")` from a caller the row does not allow or for an unknown id is a finding. Production has no ledger and no tolerance: raw spawns of registered tools went from 207 to 0. Test code has a ratcheted ledger with one English and German reason (589 files, 1,134 spawns) that can only shrink (`--prune`; new rows need `--prune --accept-new`).
- **Runtime guard.** `SEMIO_TOOL_GUARD=refuse|warn|off` checks the declared caller and hooks `Bun.spawn`, `Bun.spawnSync` and `Bun.$`; named imports of `node:child_process` are linked before any hook can run, so the static law covers those. `off` switches the guard, the funnel routing and the caller check off together.

**Verified** with 68 tests in an overlay (registry against Ajv and the real pin files, the scanner against the TypeScript compiler and ripgrep, funnels, cancellation within 10 s, admission order), Rust 7 tests and the Go tests; the real-repository scan read 55,579 files and reported 2 findings, both files the launcher set deletes (apply the launcher first). Not verified: the 98 migrated TypeScript files were parsed but not type-checked as a whole, no PATH-shim gate exists for foreign-language spawns, and 4,573 declared manifest commands are counted, not enforced, until the command-form wave rewrites them.
