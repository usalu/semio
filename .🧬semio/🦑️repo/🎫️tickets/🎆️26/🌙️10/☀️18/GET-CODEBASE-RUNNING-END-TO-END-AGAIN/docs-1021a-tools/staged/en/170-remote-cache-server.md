### 🗄️ The remote cache server

The shared result cache is an in-house server, not a script: one process serves Bazel's HTTP cache protocol and the Nx self-hosted cache API from one directory, one budget and one eviction. {{?remote-cache-server::::The own command below is a staged set; today `repo cache serve` and `repo cache remote status` do this job and are described in Caching model and Remote cache. }}State: {{@remote-cache-server}}.

```bash
repo remote-cache serve --port 6090
repo remote-cache serve --read-only --tls-certificate <cert> --tls-key <key>
repo remote-cache status
repo remote-cache gc --dry-run
```

- **A command of its own.** `repo remote-cache serve|status|gc` replaces `cache serve` and `cache remote status` (no alias); messages exist in English and German (`--lang`, `SEMIO_LANGUAGE`, locale; when none resolves both are printed); progress runs through `remote-cache:open|scan|ready|serving|probe|verify|remove`; Ctrl+C stops `serve` (exit 0) and `gc` (exit 130).
- **Protocols.** `/ac/<sha256>` and `/cas/<sha256>` with GET, HEAD and PUT and an optional `/<instance>` prefix; the CAS body is hashed while it streams and refused with 400 on a mismatch; the action cache is replaced atomically. Nx uses `/v1/cache/<hash>` (write-once: 409 on a second write, 411 without a length) in the same index, budget and eviction.
- **Action results are validated.** A strict decoder of `ActionResult` and `Tree` (wire types, UTF-8, lowercase digests, size consistency) runs on every PUT. With the default policy `complete` a PUT is refused with 400 unless the result is well formed and every blob it names, and every file of an output tree, is stored (Bazel uploads blobs first); a GET answers a miss and drops the entry once a blob has left the store. `structure` and `off` are selectable.
- **Atomic and concurrent.** Temporary file plus rename or link in a per-process temp directory (dead processes' directories are swept), a byte reservation, one server per directory (a lock; a second start fails with a clear text), a separate collector lock. Two real defects of the earlier store were found by the new tests and fixed: byte accounting drifted when concurrent writers replaced the same key, and when a read raced a replace.
- **Budget and eviction.** One pure plan (dangling entries first, then idle age, then least recently used down to 90 percent of the bound, deterministic ties) is used by the server and by `remote-cache gc`, which also works while a server runs. The default directory moved from `.cache/remote-cache` (outside every budget) to the ledger area `remote-cache` (repository root, 3 GiB); the server bound is 2.5 GiB; `repo cache gc` delegates the area to the same collector.
- **Access.** Bearer read and write tokens (constant-time compare, 401 as plain text, 403 for a read token that writes); `--read-only` or `SEMIO_REMOTE_CACHE_SERVER_READ_ONLY` refuses every write; `--tls-certificate` and `--tls-key` serve HTTPS; a non-loopback listener needs a token. The client side is unchanged: the contract is rendered for Bazel (`--remote_cache`, `--[no]remote_upload_local_results`, a credential helper) and for Nx (environment), and `remote-cache status` prints the contract, both renderings, one probe per protocol, the server's own `/status` and the local store. The in-house `--tool=semio` backend writes `/v1/cache/semio-<key>` with the same write-once rule.
- **Measured.** Real Bazel 8.4.2: a cold build uploads, a clean rebuild gives 2 remote hits, and a copy of the workspace in another directory with a second output base builds with remote cache hits only; anonymous access gets 401 and a read-only client pushes nothing. Real Nx 23.2.0: 0 of 2, then 2 of 2 (100 percent) after deleting the local cache; a wrong token aborts the run. Indicative throughput of one process at load 40: 4.6k PUT per second and 5.6k GET per second of 4 KiB, 23k misses per second. Three Python processes with 24 threads each wrote overlapping keys with no partial file and server accounting equal to the disk scan.
- **Not verified.** Bazel over HTTPS with a private certificate authority (the Bazel client trusts the JDK store, a public authority works), Windows and Linux, HTTP compression (unsupported in Bazel 8.4.2), a per-request log (a hook exists); the CI workflow still calls the old `cache remote status`.
