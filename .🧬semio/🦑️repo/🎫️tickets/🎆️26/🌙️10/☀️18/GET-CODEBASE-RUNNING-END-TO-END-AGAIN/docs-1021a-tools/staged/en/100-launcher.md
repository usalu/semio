### 🛫️ The native launcher and the runtime registry

`repo` is a native program, not a script that needs a JavaScript runtime installed by hand. {{?launcher::::The launcher below is a staged set; until it is applied the entry is still `bun repo`. }}It is written in Go with the standard library only, finds the checkout root, reads the runtime registry, provisions the pinned runtime when it is missing and hands over to it. State: launcher {{@launcher}}, runtime seam {{@runtime-seam}}.

```bash
repo --version
repo run <project>:<target>
repo ./some-script.ts arg1 arg2
repo --watch --cwd <directory> ./some-script.ts
```

- **Hand-over.** On macOS, Linux and the devcontainer the launcher replaces itself with the runtime process (same process id, same signals, same exit code); on Windows it starts a child with the console, forwards interrupts and returns the exit code. The directory of the runtime and the directory of the launcher lead the `PATH` of every child, so a nested `repo` or runtime call resolves the pinned one.
- **The registry is the swap point.** `🧰️framework/🛍️products/🦑️repo/🔨️modules/🚀️launcher/🗂️registry/🔣️.json` (a schema next to it, contract 1) lists runtimes: version, executable names, probe, https download base, launch options and environment, and one distribution per platform, architecture and libc with size and SHA-256. The entry names the selected runtime; `SEMIO_RUNTIME=<name>` overrides it. The launcher code knows nothing else about any runtime, and a law compares the registry with the existing pin files.
- **Provisioning.** The launcher looks first in the tools partition (`.cache/b/t/m/<runtime>/<sha>`, what `repo tools setup` writes) and then in the user cache (`SEMIO_RUNTIME_CACHE`, else the operating system's cache directory under `semio/runtimes`). When the runtime is missing it takes a lock file (peers wait, one download), downloads from the registry base or from `SEMIO_RUNTIME_MIRROR` (https or loopback http only), checks size and SHA-256 before unpacking, extracts with bounds, probes the version, publishes by atomic rename, prints progress on stderr and leaves nothing behind when you press Ctrl+C. It writes only the user cache: the tools partition is a mounted image that only the storage layer accounts for. With a warm cache a start costs 0.13 s in total.
- **Routes.** One planner, shared by the launcher and the full CLI: the build verbs are derived from the operations catalogue (no hand-written list), the workspace verbs (`dev mcp stdio os`), and the script route `repo [--watch] [--cwd <dir>] ./x.ts args`. The stand-alone launcher refuses the `mcp` and domain verbs with a hint to run `repo run repo-mcp:install`. A resident service gets the first chance at a plain `run|test|run-many` (see The resident service).
- **One command form.** Manifests, scripts and generated text say `repo ./x.ts` instead of `bun ./x.ts`, and a script's first line is `#!/usr/bin/env repo`. A generated wave rewrites 874 manifests (4,578 command strings, five left for review), 724 shebangs, the JSON process records and the help texts; two checks (`--check`) are the law that nothing names the runtime again.
- **`repo --version`** prints the launcher and contract version, every registered runtime (pinned version, and the path when it is provisioned; it never fetches), and the version of the implementation, in English and German. When no language can be resolved it prints both.
- **Install.** `bash 🧰️framework/🛍️products/🦑️repo/🔨️modules/🚀️launcher/📥️install/🐚️.sh [directory]` on macOS, Linux and in the devcontainer, `powershell -File 🧰️framework/🛍️products/🦑️repo/🔨️modules/🚀️launcher/📥️install/🔵️.ps1 [-Destination directory]` on Windows; neither needs Go or a JavaScript runtime installed: the installer finds the pinned Go (on the `PATH`, in the tools partition or in the user cache) or downloads it from the pins of the bootstrap table (https only, SHA-256 checked before it is unpacked, progress, Ctrl+C leaves nothing; `SEMIO_GO_MIRROR` names an https or loopback mirror) and builds the launcher from the checkout. On a bare machine the existing bootstrap `setup` calls it and installs Node, rustup and uv; nothing installs Bun or Go by hand.
- **rustc.** `.cargo/config.toml` and the compiler ingress policy name `repo` as the rustc wrapper (`repo <script> args`). Every rustc call therefore pays one launcher start (0.13 s with the runtime start included); the resident path is the way to make that cheaper.

**The runtime seam** ({{@runtime-seam}}). Production code reaches the runtime only through the facade `🧰️framework/🔨️modules/⚙️runtime`: files, globbing, TOML, JSONC, YAML, process spawning, serving, SQLite, semver, source transpiling, bundling, native bindings, loader hooks and the test API. Two adapters implement it: the Bun adapter and a Node adapter (bundling through esbuild behind our interface, FFI through a provider port, loader hooks through `module.registerHooks`). One thin test API runs the same file under `bun test` and `node --test`. The law finds no `Bun` global, no program word `bun`, no `bun:*` specifier and no `versions.bun` in production code outside the directories named `🍞️bun`: 138 findings and a ledger of 76 tolerated exceptions became 0 findings and no ledger. Every runtime error comes from an English and German catalogue (57 ids). Every family entry point of the facade imports in under 2 ms (it was about 8 ms); the adapter loads on the first member use. Open: Node has no sandbox-guard preload yet, FFI on Node needs a provider addon, and 272 shebangs, help strings and 22 data records that name `bun` belong to the launcher wave.

**Verified** with 27 Go tests (registry, routes, provisioning integrity, one download for four concurrent starts, cancellation, English and German texts) and the real pinned runtime from a loopback mirror (the extracted executable equals an independent `shasum`); the runtime facade with 33 tests under both runners, 50 existing suites with identical pass and fail counts before and after, and a type check without new errors. Not verified: Windows and Linux, a real download from the publisher, the whole manifest wave, PowerShell and Docker.
