## Item 3: idle capacity holders lend their grant back (tests green)
Analysis (`bun repo capacity status --json`): after the 5-min ramp the evaluator already counts the OBSERVED memory, so the 3584 MB reservation of a waiting holder is not the starving part. What an idle holder still costs: (a) the full reservation during the ramp, (b) its DECLARED cores in `ledgerCpu`/`own` (sum of declared cores above `2 x cores` refuses every later request with reason `load` although memory fits), (c) its reserved MB in the fair-share ordering and the status table, (d) the override `nothing of ours runs`. A process that only waits in a lease/slot/capacity queue holds a grant that nobody uses.
Design: the grant HOLDER (the process that owns it) declares it. New schema fields `Grant.lentSinceMs` / `Grant.resumedAtMs`, policy `wait.lendAfterMilliseconds` (30 s). The watchdog's wait registry gained `scriptProcessWaitEpisodeV1` (continuous wait episode: declared waits chained with gaps < 2 s). A 1-s timer in `withHostCapacityV1` lends the grant when the process has been inside one wait episode for >= 30 s AND has no live descendant (ps snapshot, throttled to the heartbeat); it takes it back (sets `resumedAtMs = now`, which restarts the memory ramp) the moment the episode ends or a child appears. `evaluateHostCapacityV1`: a lent grant counts neither unrealized/committed memory, nor cores, nor fair-share weight, nor as running for the override; a resumed grant ramps again from `resumedAtMs`. `repo capacity status` prints lent grants with EN/DE `grantLent` and the session table no longer counts their MB.
Files: `🏗️build/🌡️host-capacity/{📏️decision,🎫️gate,🧬️schema}`, `🔣️policy.json` (hostCapacity.wait.lendAfterMilliseconds), `🌡️host-capacity/⌨️command`, `🪪️agent-sessions/🗄️store`, watchdog `🟦️.ts` + schema (`waitEpisodeGapMilliseconds`), fixtures/tests.
