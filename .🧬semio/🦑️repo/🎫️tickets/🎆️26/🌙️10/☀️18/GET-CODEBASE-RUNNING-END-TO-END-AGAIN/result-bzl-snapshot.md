`B` = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🏗️build/🔧️tools/🏗️bazel`.

## Root cause and design
- `generateBazelWorkspaceV1` made `s` a symlink to the live checkout and every `a/<alias>` a symlink to a live directory, so Bazel staged and hashed declared inputs from the mutable tree. A file edited or removed between planning and action start broke the build ("missing input file //:a/<hash>/..") and could cache an output under a key its bytes did not match.
- New module `B/📸️snapshot` (schema `🧬️schema/🔣️.json`, code `🟦️.ts`): at planning each declarable file is captured ONCE into the generated workspace as a private regular file: `a/<alias>/<name>` for every declared file, `s/<path>` for the files hermetic actions name by repository path (cloned from the alias copy, never re-read from the live tree). Same BUILD labels as before; only what stands behind them changed.
  - copy = `copyFile(COPYFILE_FICLONE)` (copy-on-write where the filesystem has it, plain copy otherwise); never a hardlink, `nlink` must be 1 (an existing copy with another nlink is replaced), mode 0644/0755.
  - identity is checked once per capture: live stat before/after the copy (size, mtime ns, inode) and the byte count of the hashed copy; a torn capture retries (policy `attempts` = 3) and then fails naming the file. The sha256 is taken from the private copy, so manifest and bytes cannot disagree.
  - a file that vanished (or stopped being a regular file) between classification and capture is dropped from the universe and reported; its stale copies are removed.
  - `snapshot.json` (workspace root, schema `Manifest`): per file sha256, bytes, exec bit, live mtime/inode, racy flag, copy mtimes. A later plan of the same workspace reuses a row whose live stat and copy are intact (git-index rules: a file modified within 2 s of its capture is "racy" and read again), so a re-plan is stat calls, not copies; stale rows are pruned from both views, emptied directories removed.
  - cancellation/progress: `check()` per file, `progress()` every 1024 files (planner wires `checkScriptInvocation` + `advanceScriptInvocation("bazel:source-snapshot")` + `yieldContinuation`); concurrency 24.
  - legacy farm (symlinks into the live tree, or `s` link to the checkout) is detected by `lstat` and unlinked, never traversed or written through (tested: live files untouched, checkout listing unchanged).
- Adapter edits (`B/📜️script.ts`, anchored; script `C/bzl-snapshot-tools/edit-script.py`): import; `linkBazelSourcesV1` and `linkBazelSourceAliasesV1` deleted; `generateBazelWorkspaceV1` captures the classified files (`real` = files of hermetic actions) before building the universe, `sources.json` now takes its alias map from the snapshot; one planner log line (`[bazel] source snapshot: ...`) when `--verbose` or a file vanished.
- What does NOT change (by schema design `Actions.kinds.task.sandbox=false`): a host-class `task`/`test` action still runs its command in the real checkout (cwd, shared stores, cargo). Its Bazel inputs, cache key and staging are now the planned bytes and cannot go missing; making the command itself read only the planned bytes is exactly what the hermetic classes do (`repo_hermetic_task` stages from the same snapshot) and is the rollout lever (`widen.py` in bzl-hermetic-tools), not something a snapshot can retrofit onto cargo/bun scripts that read undeclared files.

## Open
- Host `task`/`test` actions still execute their command in the live checkout (schema decision `Actions.kinds`); only hermetic classes consume the snapshot end to end. A cheap follow-up is a report-only drift line after a host task (`bazelSourceSnapshotDriftV1` exists and is tested; not wired because bzl-tail owns the failure-reporting part of `executeTask`).
- New packages seed from the live tree; seeding a new package from a sibling package of the same slot (clone on the same volume) is not done.
- `sourceLink` in the platform profile (`junction` on Windows) is now unused by the adapter; left in place (platform fixtures/oracles reference it).
- Windows (long `s/<path>` copies, `copyFile` semantics) and Linux are not run; rename-over-existing and chmod are portable Node calls.
- `C/../scr` scratch files are outside the repo (`/private/tmp/claude-501/scr`).
