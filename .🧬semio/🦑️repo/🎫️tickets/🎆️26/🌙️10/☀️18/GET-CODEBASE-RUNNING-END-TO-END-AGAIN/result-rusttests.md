## Design (schema-first)
- `🧰️framework/🔨️modules/🏃️process/🧪️testing/📥️invocation/🧬️schema/🪪️envelope.json` (new): the closed schema of a declared birth: `owner`, `maximumElapsedMilliseconds`, `capabilities {artifacts?, command?, grant?}` with `grant {kind: "native-build-caller", arguments[], scratch: "sandbox"|"checkout"}`. `declareBuildTestEnvelopeV1` validates against it (replacing the hand-written key check).
- Helper `🧪️testing/📥️invocation/🟦️.ts`: `registerBuildTestGrantIssuerV1(kind, issuer)` plus `BuildTestGrantIssuerV1 {prepare, capabilities, matches}`. The process module cannot import the library, so the library registers the issuer.
  - Bare run: the issuer's environment is prepared AT DECLARATION (file scope: the sandbox registers its cleanup for the end of the file it is created in, created inside the first test it was removed after that test and the second test hit `ENOENT` on the artifact directory; this was the first bug I hit), the capabilities are the issuer's, `artifacts`/`command` as before; every environment change is restored and the created sandbox released after the birth.
  - Beneath a real parent: `artifacts`/`command` equality as before, and `issuer.matches(grant, inherited)` where `inherited` is the parent's capabilities minus `artifacts`/`command`. A declaration that differs from the parent is refused with `Inherited build test capabilities differ from the declared envelope of <owner>`.
  - Unregistered issuer: `Registered build test grant issuer required: <kind> for <owner>`. Malformed declaration: `Finite closed build test envelope required`.
- Library module `📚️library/🧪️testing/🪪️native-birth/🟦️.ts` (new): registers the `native-build-caller` issuer and exports `declareLibraryBuildTestEnvelopeV1({suite, scratch?})`. The owner is `test:<suite>`, the command `run @semio-tech/repo-lib:test-<suite>`, the scratch the suite row's.
  - Bare environment = what `runGenuineBunTestV1` / the suite runner hand a test: checkout (nearest `MODULE.bazel`) as `SEMIO_WORKSPACE_ROOT`, `SEMIO_BUILD_MODE` prototype, the repository script providers, `SEMIO_TEST_ARTIFACT_DIR` = the configured directory (validated) or a per-run sandbox (`build-contract`, checkout scratch for the Rust suite). Capabilities = `createBuildBootstrapCapabilitiesV1(root, ["run", "@semio-tech/repo-lib:test-<suite>"], env)`: tool, workspaceRoot, arguments, selection, buildMode, native, launches, and NO `artifacts` (with it the official runner's grant is refused).
  - `matches`: the parent's grant (without artifacts/command) must equal the grant re-issued from the PARENT'S OWN arguments, tool, build mode and root. The declared `arguments` only decide what a bare run is born with: the same file legitimately runs beneath `repo-lib:test-<suite>`, `repo-lib:test` and others (td-capacity measured `repo-lib:test`), so exact argument equality would refuse real parents. Anything that is not a genuine native build caller grant (an `artifacts`-only parent, a tampered `launches`, another root) is refused.
- Declarations: one line `declareLibraryBuildTestEnvelopeV1({suite:"…"[,scratch:"checkout"]})` after the imports of the 15 files below, plus the build route-table test file itself (its own genuine-grant law).
- Conversions needed (these called `receiveScriptProcessInvocation(process.env, …)` directly, so no declaration could apply): Rust lifetime (the main test; the failure CHILD keeps the direct receiver beneath its real parent), Rust source (the main test; the template-literal children are untouched), compiler `🤝️shared`: now `withBuildTestInvocationV1`. Rust assembly, phase, admission, digest, windows, reporting, command, consumption, native, declared-wait, borrowing, ledger already used `withBuildTestInvocationV1`/`registerBuildTestLawV1`.
