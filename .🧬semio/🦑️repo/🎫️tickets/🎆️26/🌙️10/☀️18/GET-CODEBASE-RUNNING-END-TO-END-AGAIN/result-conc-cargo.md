## 2. Design (schema first, tool neutral behind `bun repo cargo`, no external runtime dependency)

### 2.1 Lanes: no shared build directory between Cargo processes
- A **lane** is `m/u/l/<id>/{t,b,m,v}` (target, build, stamps, live markers): the private target/build directory of one agent. `<id>` = `SEMIO_CARGO_LANE`, else derived from the nearest agent-client ancestor process (claude, codex, cursor, windsurf, copilot, antigravity, droid, kiro; one lane per agent session), else `d`. No CLI flag was added (a flag needs help-snapshot regeneration owned by others).
- `acquireLaneV1` holds a lane **exclusively per Cargo process** (kernel-independent claim file with heartbeat, dead owners replaced after about 1 s). A busy lane overflows into `<id>1 … <id>31`, which start empty and fill from the unit cache. Hence Cargo's unit locks and `prebuild_lock_exclusive` never span two processes (F4) and the shared target-dir uplift lock never starves (memory note private-target starvation) while no 926 GB of private targets exist: all lanes live inside the issued Rust image and are bounded (2.5).
- `--store=shared` now means "lane + shared unit cache" (greenfield, no legacy mode); `--store=isolated` stays the swept per-invocation store.

### 2.2 Content-addressed compile-unit cache (our code; sccache only as test oracle)
`L/⚡️caching/🦀️cargo/🗃️unit-cache/` (`🧬️schema/🔣️.json` is the contract). Cargo runs `bun 📜️script.ts <rustc args>` (`RUSTC_WRAPPER=bun`, `RUSTC=<script>`, cross-platform); on a miss it runs the existing memory-admitting scheduler (`SEMIO_UNIT_CACHE_INNER=["<scheduler>","rustc"]`).
- **Key (two levels, like ccache's direct mode)**: toolchain identity + normalised command line (lane paths, output dir, incremental dir, `-L dependency`, extern paths removed; externs replaced by the SHA-256 of their bytes) + SHA-256 of the root source + selected `CARGO_PKG_*`-class environment. The entry then verifies the dependency file rustc wrote (`.d`): every file it read by content, every `# env-dep:` variable by value, with lane paths neutralised.
- **Hit**: outputs restored by reflink where supported (`COPYFILE_FICLONE`: APFS, btrfs, XFS; a real copy elsewhere, never a shared inode), the `.d` file rewritten for the lane, rustc's JSON messages (artifact notifications, warnings) replayed so Cargo pipelines exactly as with rustc. **Miss**: compile once, publish objects (content addressed, atomic rename) and the entry last, so readers see all or nothing.
- Cacheable: lib/rlib/proc-macro/bin/cdylib/dylib/staticlib, `--test` harnesses and metadata-only `check` units; bypassed (counted, `bypass` event): probes, stdin, `--print`, no artifact messages, units with `-l`/native `-L` (link inputs not keyed), unreadable inputs.
- **Incremental per lane**: units of the packages selected with `-p` (the focus) keep `-C incremental` in the lane's `b/…/incremental` and are never published; every other unit has the incremental flag stripped and is shared.

### 2.3 Leases per compile unit, bounded concurrency, no deadlock
- **Single-flight claim per unit key** (`🔒️lock`): the first process to miss compiles, the others wait on `k/<key>.lock` and are served the finished entry (`hit` with reason `after-wait`). Waiting is bounded (30 min, then compile anyway), a dead or silent holder is replaced atomically (rename takeover, restore if the victim was alive); correctness never depends on the claim (the store is atomic), so a claim can only cost time, never block progress.
- **Host-wide compile slots** (`SEMIO_UNIT_CACHE_SLOTS`, default the core count): numbered FIFO tickets, only the oldest live ticket may take a free slot, dead tickets and slots are reaped. Lock order is fixed: claim → slot → rustc; a waiter holds neither a slot nor a claim of another unit, a slot holder waits for nothing, so the wait graph is acyclic. The scheduler's memory admission and the mem-gov core grant (`--parallelism`) stay in force underneath.
- **Writer custody is shared** (F1): new `withCompilerSharedHeadroomV1` / `withCompilerWorkspaceSharedWriteV1` take the `repo:compiler-writer` custody SHARED (cohort), check headroom under it, and escalate to EXCLUSIVE only to recover missing headroom, then continue shared. `withCompilerWorkspaceWriteV1` and every maintenance caller keep their exclusive custody; only the launcher's compile and the dependency fetch / final-compile sites switch.
- **Registry** (F2): a fetch takes `cargo:registry-fetch:<home>:<request identity>` exclusively (identical requests coalesce: the waiter finds the receipt after acquiring), runs with shared writer custody, and publishes the receipt atomically (it already did). `cargo:registry:<home>` is no longer taken exclusively by the ready path. The fetched receipt stamps only the downloaded archives of the locked packages (one aggregate digest), so fetching or removing anything else never invalidates it; the resolution producer (`lock`/`update`) keeps its exclusive registry lease (rare, outside this set).
- **Admission** (F3): `CargoSourceAdmissionMemoV1` recalls a unit's whole admission result (source inputs, cfg, compiler environment) from a memo whose stamps (dev, ino, size, mtime, ctime, and recorded absences of probed paths) still hold; a recalled unit reads no Source, asks for no cfg and takes no durable recheck. A stamp younger than 2 s before the admission began is not remembered.

### 2.4 Zero-touch store and config (G5)
The launcher creates `m/u`, the lane and its directories itself after `requireNativeStoragePathV1`; nothing is created by hand. `.cargo/config.toml` now names `…/m/u/l/d/{t,b}` (the default lane) and its comment says so; raw cargo stays refused by the ingress script.

### 2.5 Bounded disk (no 926 GB blowups)
`planGcV1` (pure, deterministic) over the image capacity: idle lanes (24 h) go; free space below 10 % of the image removes, oldest first, incremental sets, then lanes, then cache objects; shares: objects 25 %, lanes 20 %, incremental 10 % (live lanes count against their share first and are never touched, re-checked at removal). The launcher runs it opportunistically at most every 10 minutes after a lane is released and prints an EN/DE line when something was removed. Operator commands (no CLI surface yet): `bun 📜️script.ts --semio-unit-cache stats|plan|gc --root <m/u> --capacity <bytes>`.

## 10. Scheduler token deadlock (urgent, APPLIED LIVE)
Cause: `semio-build-scheduler` wrote its jobserver token back on the first refused admission verdict and then blocked reacquiring it. Cargo's helper thread reads every freed token (to start or to park for another unit), so the hand-back lent the token to Cargo and the unit could not get one back; once the units that took the tokens were themselves refused or admitted-and-blocked, the fifo stayed empty with no rustc running (cargo-fix step 016, 20 min).
Fix (`F/📦️artifacts/🏗️native-build/🎟️admission/🦀️.rs`, group `scheduler`, applied 04:4x with `apply.py apply --write --ignore-sync --groups scheduler`; only the Rust file, the TS test below is staged as group `scheduler-test`): `await_admission` waits on the verdict and never touches the jobserver; the whole `Jobserver`/`read_token`/`jobserver_auth` code and the three Windows semaphore externs are deleted. A waiting unit therefore keeps its token; it cannot starve admission because the broker always admits its first waiter when nothing runs.
Tests: Rust `waits_through_refusals` (4 unit tests pass); deterministic driver test `🎟️admission/🧪️tests/🔓️tokens` (staged): N scheduler processes, K tokens in a real fifo jobserver, a Cargo stand-in that hoards every token it can read, a real broker admitting one unit at a time so all but the first are refused: OLD binary deadlocks for N/K = 8/2, 12/3, 6/2, 40/3 (1 unit finished in 15 s) and passes the no-hoard control; NEW binary finishes every case (8/2 in 1.7 s, 12/3 in 2.6 s, 40/3 in 8.7 s). Real cargo (26-crate wasm workspace, tight memory) never hoards that way, so the stand-in is what reproduces the field deadlock.
Live: the first `bun repo cargo` after the edit rebuilt the scheduler (`m/t/p/release/semio-build-scheduler`, no `could not be reacquired` string left), a tiny `check` through the launcher in my lane finished, and the live binary passes the 8/2/hoard-8 and 12/3/hoard-12 cases. cargo-fix was told to drop `pump.py` for runs started after the rebuild.
Also: set 1 and set 2 are live since Oct 20 22:31 (ledger in `C/conc-cargo-tools/backup/`); peers have since edited the live `🧵️lane` (Linux/Windows ancestry) and `🧪️tests` files of the unit cache; the staged copies were synced from live and `apply.py check` is clean.
