## Model (schema first, `🧬️schema/🔣️.json`, policy `🔣️.json` with EN/DE texts)
- **Unit** = language (typescript, rust, go, python, dotnet, cpp, wit, tex), kind, sources (exclusive), inputs, dependencies `{unit, use}`, externals (exact `module@version`, pinned distribution), interface `{kind}` or null, outputs, toolchain `{id, parts}`, action `{argv, env}`. `use` is `interface` (compilers, checkers), `implementation` (linkers, test runners) or `declared` (ordering/selection only, never keyed). Policy lists the interface kind per language: typescript-declarations, rust-rmeta, go-export-data (`__.PKGDEF` without its build id line), python-api, dotnet-reference-assembly, cpp-public-headers, wit-world, tex-aux.
- **Key** (spelled out in `key.text`, the python oracle implements that text): SHA-256 of canonical JSON of the unit's declared parts, file digests, and per dependency the **interface closure** (use interface) or **output closure** (use implementation). A dependent re-runs only when that closure changes: early cutoff. Closures are recomputed from the current facts on every run, hit or not (a hit unit's link inputs still move when a dependency's implementation does; a first version stored them in the receipt and a test caught the stale link input).
- **Finding (changes the TypeScript design)**: the live TS engine keys only the *direct* dependencies' declaration digests. With top -> mid -> low where mid re-exports low's type by reference, a change in low leaves mid's declarations and top's key unchanged, so top stays cached while it is checked against low's declarations through mid's view. Reproduced on the live engine with a fake compiler (`polyglot-units-tools/ts-closure-proof.ts`: pristine copy `top: hit` UNSOUND, with the edit `top: ran`). The neutral model therefore keys the transitive interface closure by default; an executor can report which interface dependencies its interface mentions (`exposes`) and only those enter the closure, which restores the narrow cone (fixture `exposes-limits-the-cone`); `direct` kinds (tex-aux) skip it. `apply.py --ts-closure` is the one-line TS engine fix (`declarations` returned by `run()` becomes the closure digest); the 21 TS engine tests pass with it.

## Planner, engine, emitters
- `🕸️graph`: laws (unique ids, language prefix, known acyclic dependencies, interface edge only to a unit with an interface, a file is a source of one unit, interface kind belongs to the language), stable order (layer, then code point; plain `<` differs for emoji paths), layers, dependents, affected units, critical path, shared Tarjan SCC + condensation.
- `🏃️engine`: `runUnitsV1` in dependency order, bounded concurrency, progress, cancellation (nothing published), cached failures, dependents of a failed unit run against its interface or are blocked, `cutoff` statistic, memory and file stores (temp + rename, corrupt files ignored, no locks). A shared stat-keyed digest memo is the host's `digest` port.
- `🏗️emit` (shared by both build tools): Nx targets whose inputs are the unit's own files plus `dependentTasksOutputFiles` `**/iface.json` / `**/out.json` of the dependencies only (the published file carries the closure, so the tool cuts off by itself), and a Bazel `repo_unit` rule plus BUILD text whose interface dependencies appear only as `iface_deps` (the `iface.json` file).
- Adapters: **Go** (`🐹️go`: own scanner of package clause, imports, `//go:build` and `+build`, `go:embed`; file-name suffix rules, tag evaluation incl. unix/android/illumos/ios aliases and release tags; go.mod/go.work parsing; packages -> library/binary/test units; stdlib covered by toolchain id, other modules by exact `module@version`; export-data digest from the `ar` archive; executor with `go build -trimpath` / `go test -count=1`), **Python** (`🐍️python`: own lexer, import extraction, structural API text, bound names, `.pyi` replaces the module for the interface, import cycles condensed to one unit, third-party pins, executor = `python -m py_compile` with checked-hash pycs via `SOURCE_DATE_EPOCH` plus an import-name check), **TypeScript** (wraps `TypeScriptUnitPlanV1` and maps a receipt, no re-derivation), **Rust** (wraps `cargo metadata`: lib/bin/test units, rmeta interface, proc-macro and build edges `implementation`, registry crates as externals, gran-keys identity hook; maps a unit-cache entry's `.rmeta` to the interface).
- Dedupe: group 2 of `apply.py` turns the TS engine's private Tarjan into a wrapper over the shared one (keeps its UTF-16 member order); TS engine suite 21 pass.

## Not done / limits (honest)
- **Go layout**: 467 of 503 Go packages of this repository live in emoji directories; `go list` refuses their import paths (`malformed import path`), so Go itself only builds them through the repo's canonical layout. The planner has an `importPath(module, directory)` hook for such a layout provider, but I did not find/implement the canonical mapping; the `go list` oracle therefore covers 36 real packages plus the fixtures. The Go export-data interface uses the transitive closure; whether Go's unified export data is self-contained enough for `direct` was not proven (default stays sound).
- Bazel rule `repo_unit` was **not run in Bazel** (no launcher binary found locally; only structural tests). The runner both emitters call (`repo units exec --unit … --out …`) is not implemented here; wiring into the `repo` command registry/Nx project inference and into the live Bazel generator (`tasks.bzl`) is the follow-up.
- Rust interface = rmeta digest: measured that a body edit and a line-count change both move it (rmeta holds spans/inlinable bodies), so Rust cutoff only happens on byte-identical metadata until an API digest (rustdoc JSON) exists. The unit-cache keeps working at rustc granularity; this graph is the crate-level view.
- Python: interface is the declared surface (`unannotatedReturns: ignore`); a checker that infers return types needs policy `body`. Lexer follows CPython <= 3.11 string rules (PEP 701 nested f-string quotes would be reported as unterminated). Imports inside `try`/`if` are not name-checked. The dotnet, cpp, wit and tex kinds exist in the schema/policy but have no adapter. Windows and Linux were not run (paths use `node:path`, tools are spawned by argv).
- Taxonomy name laws for `🕸️graph`, `🔏️key`, `🏃️engine`, `🏗️emit` and the language members were not run (emojis reused from the tree). One accident: a mistyped `cd` made a `grep -rl overlay .` run at the repository root for a moment (read-only, cut by `head`); no other repo-wide scan was made.
