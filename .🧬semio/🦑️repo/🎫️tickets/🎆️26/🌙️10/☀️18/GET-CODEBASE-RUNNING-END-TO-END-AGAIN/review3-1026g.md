## 1. MED-HIGH: the capacity upgrade of a quiet run waits while holding the builder custody

`B/🕸️graph/🟦️.ts:419-423` (`withBuilder`): `body` calls `markBuildCapacityPhaseV1("rebuild")` (line 420) and is passed to `withBuildGraphStateV1(..., generationScopeV1)` (line 422), which first acquires the exclusive builder lease (`acquireQueuedResourceLease`, `graph/🟦️.ts:139`) and only then runs the body. `B/🌡️host-capacity/🚏️marks/🟦️.ts:3-4`: entering `rebuild` first calls `upgradeBuildCapacityV1`, a wait in the machine-wide fair queue with no timer ("never given up on a timer", `P/🔼️upgrade`). So a run that was forecast quiet (preadmit-g, landed 16:00) takes the custody, then waits for its full grant under it.

The prefetch path does not have the problem (`graph/🟦️.ts:437` marks `rebuild` before any lease), but `🔌️load/🟨️.mjs:308` prefetches only `if(first.pending?.dirty.length)`. A delta without dirty owners (a new project: `added`, an environment move, `removed`) goes straight to `withBuilder`.

Failing scenario (16 GB host, 3 agents): A is forecast quiet (hot no-op history) and holds the 1.5-3.5 GB quiet grant; a peer adds a project; A finds `needsBuild` with `dirty=[]`, takes the builder custody, marks `rebuild`, needs +4 GB. B and C hold full 5.6 GB grants (11.2 GB of the ~13 GB budget) and need the same generation, so they queue for the builder custody that A holds. The upgrade of A is refused (`memory`: nothing of B/C is released before they get their graph), the `override` needs "nothing of ours running" (B, C run). Cycle: A holds custody, waits for capacity held by B and C; B and C hold capacity, wait for A's custody. It dissolves only through the graph queue yield of B/C (`yieldGraphQueueV1` after `yieldAfterMilliseconds`, exit and retry) or when a fourth run ends; until then the custody is blocked for as long as the capacity queue was (gate-g saw 46 min in this wave).

Fix (staged, `C/rev3-g-tools/staged/upgrade-before-custody`): ask for the upgrade BEFORE the custody, keep the phase mark inside. New `upgradeBuildCapacityBeforeRebuildV1` in the marks module (no-op without a grant or with `SEMIO_HOST_CAPACITY_PHASE_MARKS=off`), one `await` line before `let image` in `withBuilder`; the literal the generation-protocol law anchors on (`withBuildGraphStateV1(...generationScopeV1)`) is untouched. The later `rebuild` mark finds the upgrade settled and returns at once. Law `🕸️graph/🧪️tests/🔼️upgrade-before-custody` (3): red before (the export does not exist), green after (3 pass on a scratch overlay), source order custody-after-upgrade, the mark stays in the custody body, no grant means no ask. Same class, not fixed: the first-action upgrade of a quiet run happens inside the Bazel server join while the run holds its workspace slot and the pinned generation; there are several slots, so the cycle needs all slots, but a law "no unbounded capacity wait under a slot/custody" would catch the whole class.

## 2. MED: fact-index patch drift never compacts

`G/🟨️.mjs:182` (`patchFactIndexV1`): re-partition only `if classes > 2*owners+1024 && classes > 1.25 * index.classes.length` with `index` = the PREVIOUS generation's index. The real index is permanently above the first bound (20,657 classes for 4,020 owners), so the trigger is "one patch grows the class count by 25 %". A normal patch adds one class per upserted owner (+ the env owner), so the second condition is never met; but every upsert gives the owner its own class carrying ALL its row ids (the shared 15 k-row block is duplicated per touched owner, the shared class only loses that owner). Rows are duplicated per touched owner until every owner has its own class: the 70 M-pair expansion that gram-g removed, now reached by drift instead of at once, and `build()` loads the index eagerly (`readIndex`, `G/🟨️.mjs` build) every time.

Measured (scratch, `C/rev3-g-tools/drift2.mjs`, real `createFactIndexV1`/`patchFactIndexV1`, 600 owners, 3,000 shared blocks of 5 rows over 3 owners, 20 private rows; one random owner upserted per generation, same rows): classes 3,600 (bound 2,224) -> 3,598 / 3,560 / 3,527 / 3,244 and the sum of class row lists 27,000 -> 30,740 (gen 50) -> 37,225 (150) -> 42,520 (250) -> 47,620 (gen 400): +76 %, refine never ran. With a 15 k-row shared block per owner the same drift costs ~16 k ids per touched owner (64 M ids when all 4,020 were touched), i.e. the 0.4 -> 4 GB assembler growth of gram2-g's table.

Fix (stateless, no format change): the duplication ratio of an unrefined partition is `sum(cls.r.length) / rows.length` (1.0 right after `refineFactIndexV1`, every row sits in exactly one class). Re-partition when `classes > bound && (classes > growth*previous || ratio > P.compactionDuplication)` with `compactionDuplication` 1.5 (policy + schema + d.mts, one law: the drift scenario above must end in a refine and the consumers of all owners must stay equal). Not staged: it is a policy field (three files) plus a corpus, bigger than a small local defect; owner gram-g.

## 3. MED (win32): withheld owners are unfounded for ever on Windows

`G/🟨️.mjs:326-340` (`unfoundedWithheldOwnersV1`, repair-g): `row.path===config||row.path.endsWith("/"+config)`. `config` is a workspace-relative `/` path (`buildPath(...)`, `project-nodes/🟨️.mjs:50`), but the rows are keyed by `absolute()` = `path.resolve` (`👁️observation/🟨️.mjs:251`), i.e. `C:\ws\p\x.ts` on win32. On Windows the test never matches, every untagged `unavailable` owner is judged unfounded by every `plan()` (`G/🟨️.mjs:436`), is added to `dirty`, is inferred again and published as a delta: the plan is never `clean`, a hot no-op always rebuilds a generation. The law fixture (`🚧️unfounded-withheld/🔣️.json`) only has `/ws/...` rows and its Python oracle uses the same `/` logic, so no host-independent test sees it.

Staged fix (`C/rev3-g-tools/staged/win-withheld`): the row path is compared after mapping the host separator to `/` (`separator=sep`, optional third argument; POSIX hosts are byte-identical, a `\` in a POSIX file name is never a separator). Law `🚧️unfounded-withheld/🪟️windows` (3): red before (`root` and `founded` named unfounded), green after; the existing law (3 incl. the Python oracle) also passes with the patch on the scratch overlay.

## 4. LOW-MED: the plan-reuse witness does not look at everything the git universe lists

`B/🔧️tools/🏗️bazel/📜️script.ts:259-270` (`sourceFiles`): the listing is `git ls-files -co --exclude-standard` filtered only by the `.🧬semio/` and `.git/` prefixes. The witness side (`observeBazelSourceUniverseV1`, lines 230-257) walks every directory below the traversal roots EXCEPT names in `BAZEL_SOURCE_EXCLUDED_V1` (`.git .🧬semio .cache .nx node_modules target dist build coverage .venv __pycache__`, line 212; check at 245 and 249), and the tracked digest `g` covers `ls-files -c` only. A NEW untracked, not ignored file below a directory with one of those names is part of the universe (and of the fingerprint inputs of `{projectRoot}/**/*` tasks) but changes no observed identity: the next run reuses the old plan. The `bazelFilesystemSourceFilesV1` fallback applies the same exclusion to its results (line 207), so the two paths disagree. Today the repo has 0 such paths (`git ls-files -co --exclude-standard` outside `.🧬semio/`), so this is latent; it fires the day a project keeps an unignored `build/` or `dist/` directory.

Fix: in `sourceFiles`, after the git listing, `witness?.taint("source universe lists a path below an excluded directory")` when any returned path has a segment in `BAZEL_SOURCE_EXCLUDED_V1` (the plan then is not recorded: sound and cheap) or filter exactly like the fallback. Not staged (the Bazel adapter has live peer edits and the change needs a law with a real git checkout like noop2-g's oracle); owner noop2-g.

## 5. LOW (lane2-g retention)

- `⚡️caching/🦀️cargo/🗃️unit-cache/🧵️lane/📤️retention/🟦️.ts:106-114` (`withLaneRetentionV1`) publishes in the process that held the lane. A holder killed (SIGKILL, OOM, watchdog) between body and retention leaves its ledger in the lane; the next acquirer of that lane finishes it, but the pool trimmer treats a claim-free (dead holder) idle lane as evictable and deletes the directory with the unpublished receipts. Receipts of a killed build are not trusted anyway, so the harm is a missing receipt that a rebuild recreates; to close it let `trimPoolV1` (`🏊️pool/🟦️.ts:56`) run `retainLaneOutputsV1` before `removeLaneV1`.
- `retention/🟦️.ts:77`: the no-hard-link fallback does `existsSync(destination)` then `renameSync(temporary,destination)`; between the two a peer can publish that name with other bytes and rename replaces it on POSIX. Names are receipt ids (content addressed in practice), so a conflict needs two different receipts under one id; use `copyFile(..., COPYFILE_EXCL)` into the final name, or link-less `open(wx)`+write+fsync, so the existence check is atomic.
- Interleaving model, byte-for-byte publication and the "release only after publish" order are sound as written.

## 6. LOW (xplat2-g, not runnable here)

- `🧰️framework/🔨️modules/🏃️process/🔒️leases/📁️physical/🟦️.ts:56,65`: `GetLastError` is read by a second FFI call after `LockFileEx` failed. If the runtime makes a Win32 call in between, the code is not 33, and `tryLock` throws instead of answering "busy": under real contention of two Cargo builds on Windows that is a spurious failure, never a silent success. Make a non-33 failure retry the non-blocking attempt once or twice before it refuses (contention is the only reason a `FAIL_IMMEDIATELY` exclusive lock on a regular file fails), and keep the code in the message.
- `🕰️clock/🪟️native`: `SystemTimeOfDayInformation.BootTime` is the kernel's `KeBootTime`, which Windows adjusts when the system time is set; the PowerShell/CIM route derives from the same value, so both agree, but a clock step during a session changes `bootSession` for every later process, and the grants/leases of the earlier ones then look foreign. Pin the read once per session (user runtime directory file) or compare with the existing `bootToleranceMilliseconds`.
- Taskkill funnel, nextest lookup, preflight remedies: rules read correctly (anything but exit 0/128 still ends the root).

## 7. LOW (phase-g, gram2-g)

- `B/🕸️graph/🟦️.ts:437` marks `rebuild` at the start of `prefetch`, before the claim slots; a waiting prefetcher is booked at the learned rebuild size (up to the whole budget, `createHostPhaseResizerV1` rebuild branch, no check against the gate) for the length of its slot wait. With N prefetchers the ledger goes negative, other runs queue, and the farm request of the same run (`requestBuildFarmCapacityV1`, a fresh request in the same queue, `B/🌡️host-capacity/🟦️.ts:98`) cannot fit beside its own parent's booking until the rebuild ramp (`rampMilliseconds` of the phase) has passed, then the observed memory speaks: the farm starts late, never deadlocks (the parent does not wait for it). Mark `rebuild` after the first claim is held, or subtract the farm grant from the booking.
- `project-farm/🟨️.mjs:close()`: `for pool: await pool.farm.close(); pool.release(); rmSync(...)` stops at the first throwing `close()`, later pools keep their hosted grant until process exit. Wrap each pool in try/finally.
- `requestBuildFarmCapacityV1` listener fix (`B/🌡️host-capacity/🟦️.ts:105`): correct (removed on `cancel`, which `release` is; `once:true` kept). Other abort listeners in the build library without a removal (`🧵️workers/🟨️.mjs:85`, `🩺️doctor/🏃️runner/🟦️.ts:31`, `🏗️bazel/🎬️executor/🟦️.ts:212`) are per call or per action signals; none is on the long-lived invocation signal.

## 8. Checked, no defect

Late `resolveClosureRefsV1` failures withhold with their rows.
- derive-g. Streamed re-edge: the edges of a non-dirty owner come from the `moduleGraph` facts of its published node, the same `importTargetsFromFacts` and `createRelativeImportResolverV1` as the full path, manifests read as before; soundness rests on "a changed source makes the owner dirty first" (membership, analysis rows), and every input that moves with the environment (owners, packages, lock, taxonomy) is re-read live. `existsSync` of the tracked file is the same call as in the full path. The derived test-domain walk keeps support rows with the derived row (`unsupportedDerivedV1` throws without), the digest gate of the tagged owners is unchanged.
- hold-g follow-ups (rev2 findings 1 and 3): failed claims cover only for `failedRetryMilliseconds` and only for the same content `stamps`, done claims only for equal stamps (`🧩️claims/🟨️.mjs`, `chunkOfV1`). Correct.
- phase-g. Shrink only except `rebuild`; the highest of the phases to come decides; plan after a build is not learned; compute slots 1..4 from the learned rebuild size. preadmit-g: an upgrade decides as the same request in the world where its grant is released (only the difference has to fit, the freed unrealized part counts in both rooms), keeps its arrival, is a barrier for nobody; quiet grants are bounded (`maximumQuiet`, 4096 MB). The quiet class cannot deadlock by itself because a quiet grant counts its observed memory after the ramp.
- gram2-g (staged, not landed): `createFactIndexChunkedV1` (cut after rows whose number hashes to zero, chunks interned, rows -> chunks -> classes merged by equal owner set, classes ordered by first row) computes exactly the consumers of the old builder: a chunk is a subset of an owner's ids, an owner never holds the same chunk twice (ids are unique per owner), the union over the chunks of a row is its owner set. The bulk upsert path is the same rule on the upserted owners only. Hand-checked; the 300-corpus equality law backs it.
- nxret-g. The plan is pure (held, current, newest, young stay; oldest first); retirement is entered only after a try-lock probe of the whole-image scope just saw it idle and keeps every original guard; `held` is a snapshot but the exclusive scope makes it moot. Pid custody for `nx-tmp` checks the pid at observation and again before removal (`cachePidAliveV1`, EPERM counts as alive); the pid check is not valid across containers that share the volume (the devcontainer image does not mount the tools image from the host). Launch is single-flight by stamp (two agents can pass the stamp together; the collector's lease makes the second a no-op).

- zt-g.
