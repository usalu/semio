## 1. Design (what exists, what is new)
- Reused, not duplicated: the native std-only watcher (`🔭️watch/🦀️rust`, FSEvents / inotify / ReadDirectoryChangesW, `lost` frames), its supervisor `createWatchSupervisorV1` (restart, canary, fence), `RESIDENT_EXCLUDES_V1`/`RESIDENT_FENCE_DIRECTORY_V1`, `endpointsV1` (one private runtime directory per worktree and user). The resident build-task service and its 120 MB membership map stay as they are; the journal is the thin layer they can later read instead of keeping their own (`since(cursor)` there is the same idea).
- NEW neutral module `📁️filesystem/🧾️observation/📜️changes` (schema-first `🧬️schema/🔣️.json` with policy numbers and EN/DE refusal texts): log format (one JSON line per record: `{"s":seq,"t":ms,"r":[[kind,isDir,path]...]}` or `{"s":..,"l":[reason,scope]}`), single writer (segments `<epoch>.<first seq>.log`, rotation 1 MB, 16 kept, crash = at most an incomplete last line that readers ignore), contiguity-checked reader (`readChangeRecordsAfterV1`: gap / floor refusals), `changeAffectsV1` rule, `changedWatchedPathsV1` (which of many watched paths a set of rows can have changed, proportional to the rows), fenced client `🧭️client` (`cursor()`, `since(cursor, roots)`, on-demand start, `SEMIO_REPO_CHANGES=on|off`), consumer-side reference `🌳️tree` (`walkTreeStampsV1`, `applyChangeRowsV1`, `diffTreeStampsV1`).
- NEW lean service `🏗️build/🏡️resident/📜️journal` (`🟦️.ts` core with the watcher factory injected, `⌨️main` detached process, `🔭️world` consumer adapter): one NEW epoch per start (so a crash or restart is a gap and every old cursor is refused with `epoch`; no replay claims), lock directory with owner check, heartbeat file (1 s, stale after 5 s), idle shutdown (reader activity file, 2 h), self-exit above 50 MB, `unavailable.json` cool-down (60 s) when the watcher cannot vouch (portable backend, failed canary, watch limit), fence directory sweep, trust transitions written into the log as `lost` records. It keeps no membership and no tasks.
- Fence protocol (no RPC): a reader writes a unique file into the fence directory and polls the log for the record that names it; every change made before that call is at a sequence number <= the fence record (stream order of the native watcher; the supervisor's own tests prove it). A cursor is taken BEFORE a consumer's own walk or computation, so changes racing with it are reported (over-approximation, never a miss). Rows are "this path may have changed" (kinds advisory); a lost record whose scope meets a root refuses; exclusion regions and case/normalization-insensitive file systems are handled (folded comparison on macOS/Windows).
- Cross-platform: only `node:fs`, `spawn` of the runtime itself, the three native backends behind the existing watcher protocol; paths are workspace-relative `/` strings; the journal directory is the per-user runtime directory of `endpointsV1` (named-pipe-free, Windows `%LOCALAPPDATA%`).
