## What existed and what is new
The earlier `rcache` set (applied 10-20) already gave the neutral contract, Bazel/Nx renderings, a Bun store/server and `cache serve`/`cache remote status`. This set turns it into the requested service:

| Requirement | Result |
| --- | --- |
| Own command, EN/DE, progress, cancel | `repo remote-cache serve\|status\|gc` is its own catalogue operation (neutral, requires none); `cache serve` / `cache remote` are gone (greenfield, no alias). Messages in `R/📖️texts/🔣️.json`; language from `--lang`, `SEMIO_LANGUAGE`, locale, else both languages are printed (no default). Progress stages `remote-cache:open\|scan\|ready\|serving\|probe\|verify\|remove`; abort stops serve (exit 0), gc (exit 130) |
| Bazel HTTP protocol | `/ac/<sha256>` `/cas/<sha256>` GET/HEAD/PUT, optional `/<instance>` prefix; CAS body hashed while streaming and refused with 400 on mismatch; AC replaced atomically |
| AC result validation | new `R/🔬️action-result`: strict decoder of `ActionResult` and `Tree` (wire types, UTF-8, lowercase sha256, size/empty-blob consistency, inline contents vs digest, unknown fields skipped). Policy `server.actionResults` = `complete` (default): PUT refused with 400 unless well-formed and every named blob and every file of an output tree is stored (Bazel uploads blobs first); GET answers a miss and drops the entry once a blob left the store; `structure` / `off` selectable |
| nx through the same store | `/v1/cache/<hash>` (write-once, 409, 411, text/plain 401) share index, budget, LRU, GC and lock with the Bazel keyspaces: one directory, one bound, two protocols |
| Atomic, concurrent | temp file + rename/link in a per-process temp dir (dead processes' dirs swept), byte reservation, one server per directory (`.server.lock`, `RemoteCacheDirectoryBusyV1`), collector lock for gc |
| Budget + LRU GC, ledger | pure plan (`planRemoteCacheCollectionV1`: dangling, then idle age, then LRU to 90 % of the bound, deterministic ties) used by the server and by `remote-cache gc` (`--dry-run`, `--json`, lock, progress, cancel, works while a server runs; the server re-reads its directory every `maintenanceSeconds`). Ledger area `remote-cache` (repository root, tree, 3 GiB, owner `remote-cache`); `repo cache gc` delegates it to the same collector; store default dir moved from `.cache/remote-cache` (outside every budget) to the ledger home; server bound 2.5 GiB (law test: <= 90 % of the area budget; repository root sum 19.4 of 20 GiB) |
| Auth, read-only, TLS | bearer read/write tokens (constant-time, 401 text/plain, 403 read token); `--read-only` / `SEMIO_REMOTE_CACHE_SERVER_READ_ONLY` / policy refuses every write with 403; `--tls-certificate` + `--tls-key` (env / policy) serve HTTPS; non-loopback needs a token |
| Client wiring | unchanged and still correct: contract rendering in the Bazel adapter (`--remote_cache`, `--[no]remote_upload_local_results` from access+upload, credential helper) and nx environment; `remote-cache status` now prints the contract, both renderings, one probe per protocol, the server's own `/status` and the local store |
| Dashboard | tools `build-remote-cache-status`, `build-remote-cache-serve` (renamed), new `build-remote-cache-gc` (dry run) |

Two real concurrency defects of the previous store were found by the new tests and fixed: byte accounting drifted when concurrent writers replaced the same key (previous value read before the await) and when a read raced a replace (stale row object). The new lock takes no empty-file window (hard-link publish) after the first draft let 4 of 12 takers win.
