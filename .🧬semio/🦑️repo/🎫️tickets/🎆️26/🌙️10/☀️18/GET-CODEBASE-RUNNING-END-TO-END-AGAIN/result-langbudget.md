## Root cause and design
The stream loader (`sourceClosureLoaderV1(true)`) is the `--eval` argument of every captured command: `[execPath,"--eval",loader,"--",sha256,...args]` must stay below the 32767-character Windows command line (`executeCapturedBuildSourceV1` refuses above it; the sealed path has the same bound, `sealedPolicyV1.maximumCommandLineCharacters`). The loader inlined `JSON.stringify(closureRefusalMessagesV1)` (the whole EN+DE catalog) plus the renderer, so every catalog row cost command line: lang added 10 messages (catalog 5,379 -> 10,041 bytes) and the loader went 29,642 -> 33,407. The live loader already had only 2.9k of headroom.

New design (fits the captured-command model, no limit raised, no second channel): the loader carries NO catalog.
- After the snapshot is authenticated (`hash(encoded)===expected`, the identity every command already checks), refusal texts come from the authenticated snapshot itself: the loader finds the row for the sites schema file (`closureRefusalCatalogPathV1`, new `Policy.catalogPath` in `🧭️sites/🧬️schema`), decodes its base64 from the snapshot (lazy via the payload spans in the stream mode, the eager row in the file mode) and uses it once its declared sha256 holds (`closureRefusalCatalogTableV1`, self-contained, embedded like the renderer). The text is display-only, so nothing is trusted beyond what the snapshot digest already authenticates; `loaderSha256` still authenticates the loader bytes (`requireCapturedBuildCommandV1`, `loader-identity` test unchanged and green).
- A snapshot without the catalog row (or with altered bytes) gives the machine form `code: {fields}` (what `closureRefusalTextV1` already did for an unknown code), never a crash.
- The four refusals raised while the snapshot channel itself is read, before anything is authenticated (`digest-required`, `snapshot-bounded`, `snapshot-changed`, `snapshot-shortened`), are machine tokens in `lang` (same precedent as lang's other self-contained programs), and their 4 catalog messages are dropped (there is no text path before authentication). The three post-authentication image refusals and every later refusal keep their bilingual catalog texts, rendered from the image.
- Production snapshots carry the catalog: capture of every command kernel closure (all 6 selection kernels, 1,455-1,617 files) and of the sealed entry (1,640 files) includes it (probe on live; law below keeps it true).
- Result: the stream loader is 26,562 chars on live+`loader` and 26,377 chars with `nobaseline`+`lang` (broken state 33,407; live today 29,642), independent of the catalog size.
