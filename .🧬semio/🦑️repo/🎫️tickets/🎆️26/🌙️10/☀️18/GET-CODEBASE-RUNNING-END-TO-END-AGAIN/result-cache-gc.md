## Design (schema-first, tool-neutral, cross-platform, EN/DE)
- Ledger = `L/⚡️caching/💾️storage/🧾️ledger/`: `🧬️schema/🔣️.json` (closed), `🔣️policy.json` (generated by `gen-policy.py`, writers resolved against tracked files), `📖️texts/🔣️.json` (en/de), `🟦️.ts` (reader, door, classifier, pure planner, report formatter). Every cache byte has exactly one home: a fixed partition (8 images + control), a nested area inside one partition with its own budget (`nx-artifacts` 3 GiB bytes; `cargo-store` = remainder 12.998 GiB; `bazel-actions` = 4000 bp of products), or a budgeted area of a declared loose root (`repository` 20 GiB cap, declared areas sum 16.44 GiB; `native` 256 MiB). Anything else is `retired` (one-time rule in the ledger, removed after its quiet time, no migration code) or `undeclared` (collected after 14 days unused, native 7).
- G4 (area, not a new image): the Nx area is carved out of the rust partition, with the budget declared in the schema and enforced by Nx itself: `nx.json` gets `"maxCacheSize": "3GB"` (exactly the declared bytes; a law checks it, Nx's own grammar), and the cargo budget in `⚡️caching/🔣️policy.json` becomes the remainder (13957595136; incremental 24 GiB to 6 GiB). A separate image was rejected on purpose: `boundedNxNamespaceV1`, `withRepositoryNxStorageV1`, `withOriginalNxFixedCacheV1`, the promotion check, the headroom gate and ~10 tests all bind cache, outputs and temp to the rust root; moving them blind is not safe. Residual: cargo and Nx still share one ENOSPC domain (sum of budgets <= partition is law-enforced).
- Lock-aware GC (`L/🏗️build/🧹️cache-gc/🏃️runner`): scans units (children), re-measures each unit right before removal, never removes a unit that (a) is a SQLite lease file whose exclusive non-blocking transaction fails, (b) sits in a `*.queue` with a ticket of a living pid, (c) lies in an area whose declared exclusive lease cannot be taken without waiting (`timeoutMs: 0`), (d) was touched within the area's quiet time, or (e) changed since the scan. Recency uses file times only. Hardlinks counted once, links never followed or removed through. Removal is batched, cancellable and publishes progress. Owner-managed areas (Nx, Cargo, Bazel, dashboard) are reported; test evidence is delegated to `pruneTestEvidence` (same call as `cache-prune`).
- Law "no cache write outside declared homes": runtime door `repoCacheDirectory` refuses undeclared first segments (EN+DE message); static law `🧪️tests/⚖️law` scans every tracked source for `⚡️cache` literals (slash, join, chained join forms, dynamic segments only from listed writers; comments, lists, imports skipped), checks every listed writer exists, the Nx and Cargo/Bazel budget identities. A self-test of the scan proves it flags undeclared, retired and dynamic homes.
- CLI: `repo cache status|gc [--json] [--dry-run] [--area=id,id] [--lang=en|de]`; `status` takes no lease (statfs for mounted images, bounded walks otherwise, "at least" when the entry cap hit); `gc` applies by default, `--dry-run` previews. The old tool status is now `repo cache status --tasks` (catalog, help, error text updated). Routed in `runOwnedBuildInLeasesV1` before the dependencies store, so it works while `native-fixed-image:.cache/b/d` is held.
