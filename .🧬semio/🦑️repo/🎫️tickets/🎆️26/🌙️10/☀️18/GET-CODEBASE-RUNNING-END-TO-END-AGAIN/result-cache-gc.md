## Design (schema-first, tool-neutral, cross-platform, EN/DE)
- Ledger = `L/⚡️caching/💾️storage/🧾️ledger/`: `🧬️schema/🔣️.json` (closed), `🔣️policy.json` (generated by `gen-policy.py`, writers resolved against tracked files), `📖️texts/🔣️.json` (en/de), `🟦️.ts` (reader, door, classifier, pure planner, report formatter). Every cache byte has exactly one home: a fixed partition (8 images + control), a nested area inside one partition with its own budget (`nx-artifacts` 3 GiB bytes; `cargo-store` = remainder 12.998 GiB; `bazel-actions` = 4000 bp of products), or a budgeted area of a declared loose root (`repository` 20 GiB cap, declared areas sum 16.44 GiB; `native` 256 MiB). Anything else is `retired` (one-time rule in the ledger, removed after its quiet time, no migration code) or `undeclared` (collected after 14 days unused, native 7).
- G4 (area, not a new image): the Nx area is carved out of the rust partition, with the budget declared in the schema and enforced by Nx itself: `nx.json` gets `"maxCacheSize": "3GB"` (exactly the declared bytes; a law checks it, Nx's own grammar), and the cargo budget in `⚡️caching/🔣️policy.json` becomes the remainder (13957595136; incremental 24 GiB to 6 GiB). A separate image was rejected on purpose: `boundedNxNamespaceV1`, `withRepositoryNxStorageV1`, `withOriginalNxFixedCacheV1`, the promotion check, the headroom gate and ~10 tests all bind cache, outputs and temp to the rust root; moving them blind is not safe. Residual: cargo and Nx still share one ENOSPC domain (sum of budgets <= partition is law-enforced).
- Lock-aware GC (`L/🏗️build/🧹️cache-gc/🏃️runner`): scans units (children), re-measures each unit right before removal, never removes a unit that (a) is a SQLite lease file whose exclusive non-blocking transaction fails, (b) sits in a `*.queue` with a ticket of a living pid, (c) lies in an area whose declared exclusive lease cannot be taken without waiting (`timeoutMs: 0`), (d) was touched within the area's quiet time, or (e) changed since the scan. Recency uses file times only. Hardlinks counted once, links never followed or removed through. Removal is batched, cancellable and publishes progress. Owner-managed areas (Nx, Cargo, Bazel, dashboard) are reported; test evidence is delegated to `pruneTestEvidence` (same call as `cache-prune`).
- Law "no cache write outside declared homes": runtime door `repoCacheDirectory` refuses undeclared first segments (EN+DE message); static law `🧪️tests/⚖️law` scans every tracked source for `⚡️cache` literals (slash, join, chained join forms, dynamic segments only from listed writers; comments, lists, imports skipped), checks every listed writer exists, the Nx and Cargo/Bazel budget identities. A self-test of the scan proves it flags undeclared, retired and dynamic homes.
- CLI: `repo cache status|gc [--json] [--dry-run] [--area=id,id] [--lang=en|de]`; `status` takes no lease (statfs for mounted images, bounded walks otherwise, "at least" when the entry cap hit); `gc` applies by default, `--dry-run` previews. The old tool status is now `repo cache status --tasks` (catalog, help, error text updated). Routed in `runOwnedBuildInLeasesV1` before the dependencies store, so it works while `native-fixed-image:.cache/b/d` is held.

**Findings that decide the design (read-only, nice 10, live g, 10-21 16:00).** (1) Every closure capture aborts today, independent of corrupt records: the generation fact index `generations/x/6f6bc85c…` (9.7 MB packed) expands to 158.8 MiB, above `maximumExpandedBytes` 128 MiB, so the read child refuses (`inflation`, `maximumOutputBytes 134217728`) and the whole capture dies with `Original closure read child refused`. (2) What a capture reads besides the 104,290 group leaves: 4,001 generation fragments (57.6 MB packed) = about 112 s and 2.8 GiB expanded alone, two 79 MB publication JSONs = 7.6 s, frontier 1.1 s, manifest 0.5 s, plus 25.4k source closures (1.5 GiB, the bulk of the earlier 10.37 GiB). So indexing only the groups would not be enough; the generations and the shared namespace needed an index too.

**Design (schema `🗂️members/🧬️schema/🔣️.json`, engine `🗂️members/🟨️.mjs` + `.d.mts`).** One append-only `members.jsonl` per group, written under the writer's own custody: header line `{group,semio,version}` then one sealed row per leaf: `{n name, b bytes, h sha256 of the bytes, k kind, s "ino:size:mtimeNs", c check}`; a full row also carries `x` (expanded bytes), `g` (authority graph), `r` (closure references) and `l` (links, `m:"block"` for an inference block that may be missing). `c` is the first 16 hex of the sha256 of the row's canonical form, so a torn, merged or hand-edited line is rejected and counted, last row of a name wins, a torn tail is repaired by one newline before the next append. Groups: `selections/<id>`, `contexts/<id>`, `canonical` (everything under `inference/` outside them, index at `inference/members.jsonl`) and `generations` (index at `generations/members.jsonl`; the mutable `current.json` has none). Kinds are the closure `role` table plus the four generation kinds and `member-index` (new `role` rows; the plan-member enum gains `member-index`).
- **Write time** (`💾️storage/🟨️.mjs`): after `reservation.commit()` and before `withBuildGraphOptionalPublicationV1` returns, `recordMemberLeafV1` lstat-s the leaf, hashes its bytes once, re-checks the stamp and appends a light row; any failure leaves the leaf unindexed for the collector and never fails the publication.
- **Proof** (`🧾️closures/🟦️.ts`, new `resolveIncrementalRows` before `pairs`): per group it reads only the index (`smallBytes`, bounded by `maximumIndexBytes`), parses it and vouches each leaf by kind + size + stamp (`proveGroupV1`): hash from the row, references and links from full rows, nothing opened. Closure inventories (`source`/`lock`) are vouched by their content-addressed name, members pinned by a retirement plan by that plan, retired survivors by the plan. Anything the index cannot vouch for (no index, stale stamp, unknown leaf, oversized index) is never read inline: its group is counted unproven and `retainAll` keeps every inventory; a light row has a hash but unknown references, which has the same effect. `invalidateGroup` only plans groups whose rows are all hashed and of a plannable kind, so an unproven group can no longer abort a recovery. Per-row `references`/`links` replace the child's aggregate lists (schema `ReadResult`, `👷️read.mjs`), the pack/idx structural checks stay, the pins list the new files, and `maximumExpandedBytes` (and the two matching refusal maxima) rise from 128 to 256 MiB so the real index can be indexed once at all (child heap stays 1536 MiB).
- **Collector** (`🗂️members/🔎️scan/🟦️.ts`, wired into `🧹️cache-gc/🚰️reclaim` as an optional `index` port and bound in `⌨️command`): indexes unvouched leaves and upgrades light rows through the same read child, group by group; leaves are immutable so they are read without any lease (a replaced leaf fails the child's stamp check, a row for an old stamp can never vouch for new bytes), and the group's non-blocking writer lease (canonical lease for `canonical`/`generations`) is held only while appending and compacting (dead rows over live leaves plus 64, torn tail or rejected row; temp file + rename, a crash-left temp is removed first). A busy group is skipped and counted, a refused leaf is counted, never fatal; progress per group, cancellation between groups, files and chunks. It runs first in `repo cache gc --area=graph-inference` (not in `--dry-run`), then the shared scoped recoveries as before.
- **`repo cache verify --deep [--json] [--lang]`** (new subcommand; catalog, help, EN/DE texts, route): the only place a leaf is re-read after it was written: re-hashes every indexed leaf of every group and every `build-*-closures` inventory against its row or name, lists at most 100 differences, reports stale/unindexed/vanished counts, progress per group and every 512 files, cancellation between files and every 16 MiB (exit 1 on a difference, 130 cancelled, 0 clean).
- Also fixed in the catalog: the `cache` notes were plain strings while the schema requires localized notes; they are en/de objects now (the `leases` operation has the same defect, not mine, untouched).

**Cost.** A proof now reads index bytes and lstat-s members: measured 100,000 light rows = 17.7 MiB of index, parse + prove in 0.85 to 3.4 s depending on host load (bound 10 s); 10,000 full rows resolved through the real closure function in 190 to 240 ms, so the real 104k leaves cost about 2 to 3 s plus the directory walk, against 150 s and 10.37 GiB today. The first collector pass reads the whole cache once (about one old capture's work, lease-free); after that every capture, retirement step and window is index-sized.
