## 1. Designs

### 1.1 Mutation aggregate cycle (table, audio)

Cause: a leaf implements `MutationKind<Snapshot, Aggregate>` and its inverse builds `Aggregate::Variant(..)`; the aggregate enum names every leaf; the `OpText`/`OpBinary` codecs implement foreign traits on the aggregate and therefore must stay in the aggregate's crate (orphan rule), so moving the io codecs out (the first idea) is impossible.

Fix = the repository's own mutation-family pattern (`forms-diff`/`forms-inferences` leaves `impl<Op> MutationKind<FormsSnapshot, Op> for X where Op: Mutation<..> + From<X>`; planner `🏗️authoring/📦️crate-tree/🧬️mutation-families`, crate label `mut-family`, package in the first leaf's `📦️packages/🦀️rust`):
* new crate `<artifact>-mut-family` at `🧬️mutations/<first-leaf>/📦️packages/🦀️rust` mounts the eight leaf triads **in place** (`#[path]`, files stay where they are, so `MutationLeaf` source authority, descriptors, payload schemas and provenance are unchanged).
* **leaf-facing contract** = one trait per crate in the leaves crate, `SemioTableOp` / `SemioAudioOp`: `Mutation<Snapshot, Diff = <Diff>> + From<Leaf1> + ... + From<Leaf8>` with a blanket impl. Leaves become `impl<Op: SemioTableOp> MutationKind<Snapshot, Op> for Leaf`, `inverse<Op: SemioTableOp>(..) -> Result<Vec<Op>, _>` and build `Op::from(Leaf { .. })`; `diff` signatures name the concrete diff type.
* the aggregate crate keeps enum, derive, codecs, helpers, demo cases and unit tests; its package root re-exports the eight leaf modules at the same paths (`pub use <ident>::schema::mutations::{create_column, ..}`), so every consumer path (`schema::mutations::create_column::CreateColumn`, `::diff`, `::inverse`) is unchanged and no consumer was touched.
* proof of the generic shape, compiled with `rustc +nightly-2026-07-20` (`F/hdr4-tools/leaf-op-experiment.rs`, prints OK): trait + blanket contract trait, generic leaves, aggregate whose `DESCRIPTORS` const reads `<Leaf as MutationKind<S, Agg>>::SEMANTICS`, mutual inverses; no coherence or const-cycle error.

Result: table aggregator 6/7 files (0.188/0.219), audio 6/9 (0.188/0.281), leaves crates 25 files / 781 lines (0.781) each.

## 2. instance-app: why it stays at 0.950

`VcsArtifactApp<A, M>` has ~120 inherent methods (`staging/*` 6 files 78 KB, `plugin-app-impl` children 84 KB) and `impl PluginApp for VcsArtifactApp` (root 62 KB of impl). Inherent impls and the trait impl must be in the type's crate (orphan rule). The "type-core + extension traits" design fails on the first step: an extension trait declared in the core and implemented in a role crate is a foreign trait on a foreign type (rejected); a trait declared in the role crate cannot be called by the core's `PluginApp` impl (dependency cycle). Splitting the 120-method trait is the 264-file change `pai` rejected, and a newtype/marker-generic facade touches the 430 files that name `VcsArtifactApp`. Free-standing code in the closure is small (use lists ~9 KB, `lifted/tree` 6.5 KB; peeling both reaches ~0.92, not 0.90). Done: the self-contained store-stage law (`♻️lifecycle/🏪️stores/🧪️tests`, no reference to the crate) became its own crate `semio-framework-plugin-store-stage-laws` (its mount `original_store_stage_tests` removed from the instance root), taking the test closure from 0.988 to 0.950 = lib. Decision needed from the architects: either accept 0.950 as the permanent ceiling for this composer or schedule the marker-generic role-port redesign as its own multi-day ticket.
