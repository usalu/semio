## Design reports (not rewritten, per the brief)
**`react` in `MediaTransportHost/🟦️.tsx`.** The file sits in `renderer/🧑‍🎨engine/🧱️elements`, the element hosts of package `@semio-tech/framework-renderer-react` (`🎯️targets/⚛️react`, the only package that declares `react`; the sibling target `🧊️wgpu` has none). Behind an interface: yes at the lane level (UiNode schema + `ExtensionHost` registry in `🪢️ElementHosts`, `MediaTransportPort` and `MEDIA_TRANSPORT_EXTENSION_ID` are neutral). Not behind one: the module exports `MediaTransportOwnerContext` (a React `Context`) and a component typed `ReactElement`, consumed by `ShellHost/…/mode-windows` and the registry, i.e. exported API that requires an external type. Needed design: (1) a `react-port` module in the react target that is the only importer of `react` and explicitly re-exports the few symbols hosts use (`createContext`, hooks, `ReactElement`); (2) an `ExtensionHostV1` type in the lane interface (`(props: {value; nodeId; nodeKey}) => unknown`) so `ElementHosts` and `ShellHost` never name `ReactElement`; (3) the owner binding as a neutral `MediaTransportOwner` value + `subscribe` in `framework-os`, with the Context created once inside the react lane. Same shape applies to the other ~50 element hosts, so it is one wave, not a patch.
**Rust crates.** Facts: (a) `🔌️plugin/🖥️host/📥️imports` names `wasmtime`, `wasmtime_wasi` types in its source (8 sites) and declares `serde`/`serde_json` (2 uses); the intended wrapper `🔧️engine` ("shared Wasmtime engine") itself exposes `wasmtime::{Engine, Store}` in public signatures, and `🎭️guest-runtime` (16 sites), `🔗️wit-bindings`, `🚪️io/🎛️operation` also declare wasmtime. (b) `🌉️mcp/⚙️plugin-runtime` declares `tokio` + `serde_json`; its sources live in `🌉️mcp/🏠️workspace/*` (the crate root is a 28-line `#[path]` shim): `serde_json::` is used directly in `🧩️artifact-app-frames` and `📨️plugin-artifact-channel`, `tokio::runtime::Runtime` in `🗂️guest-document-codec` (`hub_socket_reactor`). (c) Interfaces that already exist: `semio-framework-async` (`HostAsyncRuntime` trait, "no tokio in this crate"), `semio-framework-os-services` (tokio-backed `TokioHostRuntime`), `semio-framework-pack-json` + `semio-framework-value` (JSON codec and value model; the mcp crate already depends on both). Needed design: (1) wasm: the engine crate defines `HostComponentEngine`, `HostStore<T>`, `HostLimiter`, `HostStream` traits/newtypes so no wasmtime type appears in any `pub` signature, wasmtime is pinned in that crate only, and `📥️imports`/`guest-runtime` depend on the wrapper; (2) tokio: move `hub_socket_reactor` into `os-services` as a `HostReactor` behind `HostAsyncRuntime` and delete the direct tokio dependency of `plugin-runtime`; (3) serde_json: route the roster/body encoding through `pack-json` + `value` and delete `serde_json`; derive-based `serde` in `📥️imports` becomes schema-first generated codecs. Order: tokio (smallest), serde_json, wasmtime (largest).
