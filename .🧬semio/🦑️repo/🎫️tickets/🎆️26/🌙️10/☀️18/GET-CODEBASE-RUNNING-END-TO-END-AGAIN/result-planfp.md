## Design (the planner observes structure, the publisher observes bytes)
- Witness (`🔭️witness/🟨️.mjs`, `.d.mts`): recorder API `entry(path, follow)` + exported `worldEntryKindV1` record kind rows `k` (lstat) / `K` (stat): `file|directory|link|other|!CODE`. They hold through byte, time and mode edits and never make the witness racy; `verifyWorldWitnessV1` checks them; the journal treats them as path rows (`🏡️resident/📜️journal/🔭️world` PATH_KINDS += kK; plan-reuse now imports `worldRowIsPathV1` instead of its own copy of the regex).
- Planner (`generateBazelWorkspaceV1(…, publish:"defer")`, used by `publishCapturedBazelGraphV1`): `bazelSourceClassesV1` asks kinds only (same classes, law + independent corpus check equal on base and batch); no capture: declarable = classified files, alias map from the new pure `bazelSourceSnapshotDirectoriesV1`; writes `snapshot.plan.json` (schema `Plan`) and per task `<label>.fingerprint.json` (schema `FingerprintPlan`: head = host, implementation, declared env, runtime answers, Cargo resolutions; `cached`; hashed paths). It never reads source bytes (oracle asserts: no `S` rows, no `f` rows of inputs).
- Publisher (`refreshBazelWorkspaceSourcesV1` in the parent, after a FRESH plan before the record and after a REUSED plan): incremental capture (existing stat-identity reuse; only changed files are copied) + `<label>.input` = sha(head, identities of hashed paths), random for uncached tasks (replaces the old randomising of ignored `.input`s). A planned file that vanished = `concurrentEditV1("vanished", path, …, "snapshot")` after removing the plan record (bounded churn retry replans). `publish:"capture"` (default, all direct callers/tests) runs the same refresh inline.
- Plan record: the publisher's entries (`<label>.input` of every task, `snapshot.json`, `snapshot-tmp`, views `a`/`s`; `bazelSourceSnapshotEntriesV1`) are in the reuse `ignore` set, so refreshes never invalidate the receipt.
- Names schema-first: `Actions.fingerprints {plan:".fingerprint.json", value:".input"}` (+ ActionPolicy), snapshot `Policy.plan`.
- Still replans (laws): new/removed file in a glob (git `g` + dir `d` rows), new BUILD boundary (k row), file↔link/dir kind change (k row), new dir, ignore rules, force-add, untracked input, changed input declarations (graph digest in the key; an import that changes declared inputs changes the graph).
