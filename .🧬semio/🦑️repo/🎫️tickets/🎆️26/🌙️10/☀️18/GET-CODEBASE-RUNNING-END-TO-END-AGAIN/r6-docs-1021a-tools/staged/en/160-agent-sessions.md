### 🪪️ Agent sessions

Every agent that works in the checkout has one identity that every layer reads: its Cargo lane, its preferred Bazel slot, its test sandbox root, the owner of its leases, its share of the capacity queue and its resident-service capability. {{?agent-sessions::::The following is a staged set; today lanes, slots and sandboxes derive identity separately (`SEMIO_CARGO_LANE`, `SEMIO_SESSION`, `SEMIO_AGENT_ID`, `SEMIO_SERVICE_TOKEN`). }}State: {{@agent-sessions}}.

```bash
repo session open --agent=<name> --weight=2
repo session open --export
repo session status
repo session list --all
repo session close --dead
repo session close <id> --force
```

- **What a session is.** A record per user and worktree (`<registry>/<worktree key>/<id>.json`, next to the lease registry; `SEMIO_AGENT_SESSION_DIRECTORY` overrides it): the agent (`id`, `client`, `origin`), the session `id` (`a` and 10 base-36 characters of a digest of the agent id, `d` for the default session), the derived names (`resources.cargo.lane`, `resources.bazel.preference`, `resources.nx.namespace`, `resources.tests.root`), the lease owner `<agent>/<id>`, a budget weight from 1 to 16, an optional capability and up to eight liveness anchors (process id and start time). The agent comes from an explicit name, else the client's own variable (`CLAUDE_CODE_SESSION_ID`, `CODEX_THREAD_ID`), else the MCP connection, else the nearest agent-client ancestor process, else the default agent.
- **One variable travels.** Between processes only the address `<worktree key>.<id>` in `SEMIO_AGENT_SESSION` travels. `SEMIO_AGENT_ID`, `SEMIO_SESSION`, `SEMIO_CARGO_LANE` and `SEMIO_SERVICE_TOKEN` are gone and nothing reads them (a source law in two suites fails when one reappears). Every heavy `repo` command attaches before the capacity gate and puts the address into its environment; light commands (`leases`, `capacity`, `session`) do not pay for it. A read-only home never stops a build: the session then lives in memory.
- **The ancestry rule matches the executable, not the command line.** The old rule tested the whole command line of every ancestor, including Claude Code's own shell wrapper that mentions the client in a path, which would have given every Bash call its own Cargo lane and never reused a warm one. One `claude` ancestor now names the same session across all the Bash calls of a task; the walk takes one `ps` listing (75 ms at load 25) instead of one spawn per ancestor.
- **State and cleanup.** `live` (seen within 10 minutes, or the default session), `idle` (owner alive within a day, or seen within an hour), otherwise `gone`. At most once a minute a command collects gone sessions: test sandboxes are reclaimed with their images detached first, the temp root is removed, a session whose sandbox still runs is kept and the default session is never collected. `repo session close <id>` refuses a live session unless `--force`; `close --dead` collects every gone one.
- **Where it is read.** Cargo lanes and the lane metadata; Bazel slot ranking (`preference mod slots`, so concurrent agents start on different slots) and the owner in the slot state; test sandboxes `<tmp>/st/<root>/<8 hex>`; TypeScript check units; run leases and the output cache; the lease registry (`repo leases status` shows `session <id> (<agent>)`); the capacity queue. In the capacity queue the order is priority, then reserved memory per weight, then arrival, so one agent with many requests no longer keeps the others waiting; the budget is an order, not a hard cap, and a lone agent is never throttled. `repo capacity status` prints a session block with grants, reserved megabytes, waiters, weight and share.
- **MCP.** The Go server asks `repo session open --json` once per agent (or per connection: client name, client pid, own pid), caches the answer and passes only `SEMIO_AGENT_SESSION`; four tools `session_open|status|list|close` exist. The running MCP binary needs a rebuild and a reconnect after the apply.
- **Limits.** The native launcher's resident client must read the address, the session record and its token file (it still read the old variables when this was staged); deriving the agent natively without an address needs the identity rules ported to Go. The optional Nx watcher identity per agent is a separate group because detached supervisors lose the process ancestry. Not run: Windows and Linux hosts, the taxonomy gates for the new directories, a real `repo session` through the built launcher.
