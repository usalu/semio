# Result xplat-win (2026-10-19)

Scope: audit `audit-cross-platform-1019.md` G4 (Windows refusals), G9, G13 (no change, see below), G19; WP-C. Abbreviations: `NB` = `🧰️framework/🔨️modules/🏃️process/📦️artifacts/🏗️native-build/💾️storage`, `LIB` = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library`, `STO` = `LIB/⚡️caching/💾️storage/🔒️enforcement/📦️budget/📥️opening/📤️publication/🟦️.ts`, `BST` = `LIB/⚡️caching/🚀️bootstrap`.

Nothing here ran on Windows. Every Windows code path is verified only through extracted-function tests with fake FFI/handle ports and independent Python/SQLite oracles on macOS arm64. Treat all of it as "not run on Windows".

## Findings that change the picture

1. The five refusals of G4 sit on the VHD backend (`fixed.vhd`, elevated `Mount-DiskImage`). They are all explicit ticket-driven maintenance operations (`tools setup all` purpose gate). The caller of `STO:195` (`maintainSelectedRepositoryDependencyGenerationV1`) and of `:243/:286` (`probeRepositoryDependencyProducerV1`, the completion owner) is reached only from ticket scripts (`ABSTRACT-REPO-BUILD-TOOLS-AND-ADD-BAZEL/tooling-diagnostic`) and tests. No `bun repo` CLI route calls them; `maintainRepositoryGraphCacheImageV1` (`:113`) likewise. So no normal `bun repo` command hit them on Windows.
2. There are more Windows refusals than G4 lists, and some are on normal routes (see "Open items", numbers 1 to 4). The most important one: Cargo compiler-state funded children (`withFixedNativeFundedChildStorageV1`, `NB/🧱️fixed/🟦️.ts` line 251, "Authenticated POSIX creator metadata required before funded fixed birth") refuses on Windows (macOS takes the persistent path, Linux the directory path), so `bun repo cargo` on Windows cannot work today.
3. `--symlink_prefix=/` needs no symlink privilege: the pinned Bazel 8.4.2 says so in its own `bazel help build --long` text ("If '/' is passed, then no symlinks are created and no warning is emitted. Warning: the special functionality for '/' will be deprecated soon; use --experimental_convenience_symlinks=ignore instead"). Greenfield rule "no deprecations" therefore gave the decision: replace it.

## Changes

Windows protected parent and protected maintenance providers (G4), `NB/🪟️image/🟦️.ts`
- `captureWindowsNativeProtectedParentV1` and `captureWindowsNativeProtectedMaintenanceV1`: information-only providers beneath the actual EX borrower and writer proof. One shared core (`createWindowsProtectedProviderV1`).
  - Physical facts come from the existing readonly handle mechanics (`withNativeWindowsReadMechanicsV1`, mode `ordinary-receiver`, mutable fields only `writeTime`/`changeTime`) through `captureFixedWindowsCurrentV1` (now exported as `nativeFixedWindowsCurrentV1`): host directory, `fixed.vhd`, `image.json` digest, volume root, 64 ancestors.
  - Kernel association comes from the existing fixed `information` PowerShell command (`nativeFixedWindowsReadV1`), read before and after one verification and required equal.
  - Descendants: walk of the mapped root to `childDepth` 2 (anchor = directory holding a regular file `fixed.vhd`; reparse entries and `System Volume Information` / `$RECYCLE.BIN` at depth 1 skipped). Each anchored directory is probed in a separate payload-free session (`withMounted` on its `m`); only a directory whose `m` resolves to a distinct NTFS volume root counts as attached, and that child's own `information` output must name `<dir>\fixed.vhd` and the same volume. Rows: `root`, `image`, `backingIdentity` `[dev,ino,size,allocatedBytes]`, `kernelIdentity` `[volume guid, volumeSerial, fileId]`.
  - First sample is compared with the caller's numeric request (dev, ino, mode, size, allocation, root, receipt digest); every later sample must be stable (mutable times excepted). `informationObservations` (2) is enforced; `observe`/`recheck` of the observation port re-sample handles without a new PowerShell run.
  - `captureChild` (maintenance) is async now (`NativeProtectedMaintenanceProviderV1.captureChild` returns `association | Promise<association>`, one `await` in `NB/📤️publication/🌐️platform/🟦️.ts`): it re-probes the child (host dir, backing, mount root, `image.json` digest) against the declared CAS and the baseline row.
- Request identity on Windows (documented in the contract docstring): `dev` = volume serial, `ino` = NTFS record number (low 48 bits of the file index), `mode` = file attributes, `size`/`allocatedBytes` exact. Reason: the full 64-bit index exceeds 2^53 as soon as the 16-bit sequence number reaches 32, which is common on reused MFT records; the request schema (and `lstat` Numbers) cannot carry that. The sequence number stays in the in-process facts that later samples must repeat.
- `NB/🧱️fixed/🗂️system/🟦️.ts`: `nativeWindowsProtectedIdentityV1` (the projection above, strict decimal and range checks); new handle role `withMounted` (follows the mount point, no `FILE_FLAG_OPEN_REPARSE_POINT`, root-of-volume pattern check, NTFS check only for volume roots); `readNativeWindowsLongPathsEnabledV1` (advapi32 `RegGetValueW`, flags `RRF_RT_REG_DWORD` 0x10, hive `HKEY_LOCAL_MACHINE`, absent value means disabled, library closed on every outcome). `🧬️schema.json`: `LongPathsProtocol`.
- `NB/🧱️fixed/🧬️schema/🔣️.json`: `WindowsProtectedObservation` (names, depth 2, entry bound, service directories, identity mapping).
- `NB/🧱️fixed/🟦️.ts`: one export line (`nativeFixedWindowsCurrentV1`, `nativeFixedWindowsReadV1`, `nativeFixedWindowsOrdinaryWorkV1`); the two Linux provider guards now say "Actual Linux directory protected ... provider required" instead of the stale "Windows ... not authored".
- Dispatch: `NB/🌐️platform/🟦️.ts` (protected parent) and `NB/📤️publication/🌐️platform/🟦️.ts` (protected maintenance): the two Windows throws are gone, `process.platform==="win32"` selects the Windows provider next to the darwin and fixed factories.
- `NB/📤️publication/📚️witness/🪟️windows/🔒️handles/🟦️.ts`: the restricted handle view refuses `withMounted` (interface gained the member).

Exact-payload publication and dependency retirement (G4)
- Removed the exact-payload special cases for Windows: `NB/📤️publication/🌐️platform/🟦️.ts` (leaf entry), `STO` (`maintainRepositoryGraphCacheImageV1` entry), `NB/📤️publication/🎛️owner/🟦️.ts` (two admissions, "Exact service payload publication requires POSIX"). Windows has no reserved service domain (the only reserved name is the macOS `.fseventsd`), so an exact payload equals the ordinary payload there; the purpose is now accepted and routed like any other. The leaf and the graph helper resolve the backing name with `nativeImageBackingFilenameV1()` (`fixed.vhd` on Windows); the package facade `🧰️framework/🔨️modules/🏃️process/📦️packages/🟦️typescript/📦️artifacts/🏗️native-build/💾️storage/🌐️platform/📋️contract/🟦️.ts` re-exports that name explicitly.
- `STO`: removed the three platform guards `:195` (selected dependency retirement), `:243` (funded producer probe), `:286` (completion). `readRepositoryGraphMaintenanceFileV1` no longer requires `O_NOFOLLOW` on win32 (it still pre-checks `lstat` and requires `fstat` equal `lstat`, so identity equality, not the flag, is the guard; Windows `fs.constants` has no `O_NOFOLLOW`).
- NOT removed, and why: the owner's `O_NOFOLLOW` gate "Actual Windows nofollow descriptor support required before publication effects" and the missing Windows payload witness binding (see Open items 5). Exact payload is therefore no longer a separate Windows refusal, but Windows image publication as a whole is still blocked by that gate.

Bazel (G9, G19)
- `.bazelrc`: `build --symlink_prefix=/` replaced by `build --experimental_convenience_symlinks=ignore` (same effect, no privilege, no deprecated special case, flag present in 8.4.2 help). `BLD/🔧️tools/🏗️bazel/💾️storage/🧪️tests/🟦️.ts`: the path-value exception for that line is gone and `symlink_prefix` is now forbidden.
- G9 decision: an output-root depth budget is moot. Every declared source is reached as `execroot\_main\<relative path>` and tracked relative paths reach 226 characters (rule: below 256), plus about 90 characters of Bazel prefix, so Windows without long paths fails for any output root. The effective guard is machine-wide `LongPathsEnabled`; with it set the existing 256-character storage rule keeps the output root far below 32 767. Implemented as a Bazel readiness refusal: `BST/🛠️tools/🏗️bazel/🩺️readiness/🟦️.ts` (new fact `longPaths: enabled|disabled|unprobed`, probed with `readNativeWindowsLongPathsEnabledV1`, refusal text with the elevated `New-ItemProperty` remedy), schema `BST/🛠️tools/🏗️bazel/🧬️schema/🔣️.json` (`PlatformFacts.longPaths` required), fixtures (`windows-long-paths-disabled`, existing Windows rows now `enabled`, invalid row `longPaths: maybe`).

Decided not to build (no consumer): Win32 file replace and directory exchange
- Atomic file replace with `SetFileInformationByHandle(FileRenameInfoEx, REPLACE_IF_EXISTS|POSIX_SEMANTICS)` exists already (xplat-boot `replaceWindowsDirectoryLinkV1`, class 22 bytes) and `MoveFileExW(..., 8)` (non-replacing, write-through) in `retainNativeFixedBirthDirectoryV1` is the intended semantic. The VHD backend replaces nothing else by rename; the descriptor library (`🧰️framework/🔨️modules/📁️filesystem/🧾️observation/📁️descriptor/🟦️.ts`) carries its own NT-handle rename and delete. A new unused wrapper would be dead code.
- Directory swap and NTFS case sensitivity are only needed if Windows adopts the new directory-backed partition (xplat-linux `NB/🐧️directory/`). That is a backend decision, see recommendation below. Needed pieces if chosen: a two-step exchange port (intent receipt `.exchange.json` written write-through before the first rename; `A->T`, `B->A`, `T->B` each `MoveFileExW(..., WRITE_THROUGH)`; recovery rolls forward by directory identity: after step 1 `A` absent and `T` holds first; after step 2 `T` holds first and `A` second; after step 3 done; always under the partition's exclusive lease so shared readers never observe the window, and an interrupted exchange is finished by the next exclusive opener before any state is read); case sensitivity through `NtSetInformationFile(FileCaseSensitiveInformation = 71)` with `FILE_CS_FLAG_CASE_SENSITIVE_DIR` on an empty directory (what `fsutil file setCaseSensitiveInfo` does), then the same `a`/`A` probe as the Linux code. Whether Node/Bun `CreateFileW` honours the flag cannot be settled without a Windows run; the VHD backend does not need it (publication payloads already reject case-fold collisions, `NB/🌐️platform/📋️contract/🟦️.ts` lines ~422 and ~440).
- Long paths: the repository rule keeps every path at most 256 characters, below `MAX_PATH`; no `\\?\` prefixing is added. The 34 tracked paths of 215 to 226 characters are why the readiness refusal above is mandatory for Bazel.
- G13 (`cmd.exe` code page for non-ASCII arguments): no change; PowerShell commands are built with literal quoting from ASCII-validated mount paths and `vcvarsall` is outside this scope.

## Open items (ordered by effect on the four products)

1. Funded Cargo compiler-state children on Windows: `NB/🧱️fixed/🟦️.ts` `withFixedNativeFundedChildStorageV1` (line 251) and `retireFixedNativeFundedChildV1`/`retireNativePlatformFundedChildStorageV1` ("Actual recovered committed POSIX child required", `NB/🌐️platform/🟦️.ts`), plus `NB/🌱️birth/🧾️claim` ("Native creator claim requires actual POSIX metadata backend"). Normal route for `bun repo cargo`; blocks semio-tech-play and the demonstrator on Windows. Needs either nested VHD children or the directory backend below.
2. Selected Tools generation maintenance (`STO` lines 28 and 144: "POSIX selected tooling durability backend required", unlink-while-open with `nlink` 0 assertions) and cleanup durability (`NB/🧹️cleanup/♻️retirement/💾️durability`, "POSIX cleanup metadata backend required"; `📋️contract` census). Windows needs NT delete-by-handle with POSIX disposition and `FlushFileBuffers` on a backup-semantics handle.
3. Whole-allocation artifact retirement in `NB/📤️publication/🌐️platform/🟦️.ts` (lines ~36 to 53) relies on unlink-while-open and `nlink` 0 as well; the dependency-generation path I unblocked uses the relative-directory descriptors instead and is the Windows-capable one.
4. Leaf publication compares Node `lstat` numbers (`file.ino`, `file.blocks`) with the request; on Windows the full index may exceed 2^53 and blocks are allocation/512. Use the identity projection above (bigint stat, masked record) when the owner is wired.
5. Windows image publication owner: `capturePublicationPayload` always builds `{platform:"posix"}` witness bindings (`NB/📤️publication/🎛️owner/🟦️.ts` line 74), and `withNativeWindowsPublicationObservationSessionV1` / `withNativeWindowsPublicationPayloadContextV1` have no caller outside tests; the `O_NOFOLLOW` gate on lines 80 and 94 refuses before effects because Windows `fs.constants` lacks it. Wiring needs the host session input (all of its fields exist in the owner scope), mapped evidence after `information`, underlying evidence while detached, and the same nofollow substitute.
6. First real Windows run should cover: the `information` JSON shape with children, `withMounted` on a real child mount, `captureFixedWindowsCurrentV1` under receiver mode while a writer is quiet, and `reg`-free `LongPathsEnabled` probing.

## Recommendation (decision for the coordinator)

Move Windows to the xplat-linux directory partition (anchor `fixed.dir`, `m`/`v` exchange), as Linux did. It removes the elevated VHD mount (G3 stays a refusal only until then), makes items 1 to 4 and the exact-payload witness POSIX-shaped, and lets the provider code in `NB/🧱️fixed/🟦️.ts` cover Windows. It needs: the two-step exchange port above, a case-sensitivity decision (set the NTFS flag, or relax the probe to the case-fold-collision policy macOS images already use), directory flush via `FlushFileBuffers`, a nofollow substitute for `open(...O_NOFOLLOW)`, and a Windows replacement for the `lsof +D` descriptor census. Until then the VHD providers in this change are the supported Windows route for protected maintenance.
