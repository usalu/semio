## Real defects found by the oracle tests and fixed at the source
- statutes `📐️specification-text` `backtick_pair`: an empty pair skipped its second backtick as an opener, so a doubled-backtick span and `` `` a` `` were not 'backtick-wrapped code' (the Go twin's regexp matches them). Leftmost-match semantics now.
- statutes `has_implementation_syntax`: after a `MUST(`-style first match it kept scanning and reported a later call; Go's `FindString` judges the first match only. Aligned.
- statutes `contributor_line`: `2026  <a@b>` (two spaces, no name) matches Go's `\d{4}\s+[\w\s]+<[\w.@-]+>` (the whitespace run backtracks into the filler); the loop required a non-empty filler after the whole run. Simplified to the regex run-length rule (dead backwards loop removed).
- statutes `🗜️deflate` `inflate`: a stored block's NLEN was never checked; a corrupt stored header was accepted. Refused now (`invalid stored block lengths`), like zlib.
- metrics `🕰️time` `iso_weekday`: documented `Monday = 1 … Sunday = 7`, returned `days % 7 + 4` (Monday = 8); both callers re-normalised, hiding it. Fixed, callers simplified.
- metrics `📤️render` (Rust AND Go twin): the churn layout of the markdown table wrote 6 separator cells under a 5-cell header (a broken GitHub table). Both fixed.
- metrics TS oracle `🧪️tests/🔢️numstat-parsing/🟦️.ts`: its `git commit` calls inherited the user's global `commit.gpgsign=true` and hung on the signing key; now `-c commit.gpgsign=false -c tag.gpgsign=false`.
- test-runner fixtures `🗺️planning-vectors.json` (8 rows) and `🛑️cancellation-vectors.json` (2 rows) froze the Go target as `...` while Go (`test-command`) and Rust (`plan_bundle`) both emit `./...`: every `scope-plans-match-the-frozen-argv` run failed for the Go rows. Fixtures corrected.
- test-runner `parse_outcome`: an `npm` invocation reported `runner: npx`, a `uv` one `runner: pytest` (the dialect parser's label overwrote the invoked runner). Now the invoked runner.
- test-runner `cargo_failure_body`: the body of the LAST failing test ran on into the `failures:` list and the `test result:` line (visible in real libtest output; the real-libtest probe pins it). Ends at `\nfailures:\n` or the next `----` now.
- test-runner `flat`: used `str::to_lowercase` (final-sigma context, multi-rune expansion: `ΣΑΣ` -> `σας`, `İ` -> `i̇`) where Go's `strings.ToLower` and `🪪️identity::flat` map rune by rune. Same simple mapping now.

## The open law of dtest2-d: `repo-test-domain:test-artifact-root-source` 'ended test runs are retired oldest first…'
ROOT CAUSES (both real, in the law, not in the retention code): (1) the shared fixture limit `maximumRetainedBytes: 4096` / `maximumRuns: 1` is below ONE run (8192-byte file + `run.json`, ~12 KiB allocated), which the other retention law needs, so the policy phase retired BOTH runs and the high-water phase had nothing left to judge (`removed` = both, expected the oldest only). (2) The runs' task shard and the driver's own task shard were drawn at random from 16: when they coincide the retention's exclusive `repository-test-task-shard:<n>` lease (timeout 0) collides with the driver's OWN shared lease (1/16), and with any peer test holding a shared lease on the run shard (the fleet-load flake) -> `held`, `removed: []`.
FIX (`🧰️framework/🛍️products/🦑️repo/🔨️modules/🧪️test/🧪️tests/🧾️artifact-root-source/🟦️.ts`, that law only): the law computes the allocated bytes of its two runs and passes its own generous policy (4x both, 8 runs) so only the volume-pressure phase retires; it picks driver and run scopes whose shards differ; it ages the runs INSIDE the driver (the framework's own entry retention on the real image cannot retire them first); and it retries up to 8 times with fresh scopes when the outcome reports `held` (a peer on the shard), failing loudly after that. Result: PASS twice in a row on Bazel (`l1`, `l2`).
