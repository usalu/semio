## Systemic root cause found: the `lift`/`plain-lift` codemod (tax2 / tax-stage `lift.ts`)

85 tracked scripts are lifted ("former top-level body of its `📜️script.ts`"); 57 register `defaultCommand: "run"`, 35 programs call `receiveScriptProcessInvocation(process.env, ...)` INSIDE the program, 23 of them test children. Two defects: (a) the router rejects the child's own argv (`unknown command "<arg>"`; commands recognised only by `startsWith(...)` are never registered); (b) the nested receive runs the work as a tracked operation of the outer Original, so the program's catch prints before descendants drain (`late:false`). Pre-lift behaviour = the program is the outermost wrapper. Fix applied to the three children my suites spawn: `📜️script.ts` = `import { runScriptProgram } from "./🟦️.ts"; if (import.meta.main) await runScriptProgram();`. The generator (`tax-stage-tools/lift.ts:317`, `tax2-tools/plain-lift.ts:119`, `restructure.ts:283`) must emit this form for programs that already receive their invocation, otherwise tax-stage re-creates the defect in every lifted child (list: `C/🗑️generated/...` was deleted; regenerate with `git grep -l "former top-level body of its"`). Open decision: if a law requires every `📜️script.ts` to be a router, test children need an exemption.
