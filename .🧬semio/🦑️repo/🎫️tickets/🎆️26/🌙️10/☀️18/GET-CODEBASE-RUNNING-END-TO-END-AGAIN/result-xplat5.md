## Findings (real defects, each with a law that is red on base and green with the fix)

### 1. The plan witness only knows macOS session variables (batch `witnessenv`)
`🔭️witness` policy `ambientEnvironment` = `CLAUDE*, ANTHROPIC*, __CF*, XPC_*, TERM_SESSION_ID, SECURITYSESSIONID, LaunchInstanceID`. A plan script that spreads `process.env` (script.ts does) records the whole environment (`E` row, minus authority/ignored/ambient names); on every other host the per-session identifiers are inputs: `WT_SESSION` (a new GUID per Windows Terminal tab), `SESSIONNAME`, `ConEmu*`, `SSH_AUTH_SOCK`/`SSH_CONNECTION`, `DBUS_SESSION_BUS_ADDRESS`, `XDG_SESSION_ID`, `INVOCATION_ID`, `TMUX`, and in a devcontainer `VSCODE_IPC_HOOK_CLI`, `VSCODE_GIT_IPC_HANDLE`, `REMOTE_CONTAINERS_IPC` (a new socket path per attach), `BROWSER`. Each new terminal or attach would break the witness and replan from cold (the 60 s to 20 s plan-reuse win of today would not exist outside the author's Terminal). Also names were compared case-sensitively although Windows variables are not (`Path`/`PATH`, `ConEmuPID`).
- Fix: schema policy grows to 26 names and 14 prefixes (prefix `REMOTE_CONTAINERS_` with the underscore, so the hosting-environment switch `REMOTE_CONTAINERS` stays an input; `DISPLAY`, `XDG_RUNTIME_DIR`, `SSH_ASKPASS`, `TERM_PROGRAM` stay inputs), both readers (`isAmbientEnvironmentNameV1` and the preload copy) upper-case once and compare. Names stay out of the action environment anyway (allowlist).
- Law `🔭️witness/🧪️tests/🖥️session`: (a) the rule equals an independent Python reading over 19 documented session variables and 22 build inputs, each in 3 spellings; (b) a child run with all session variables set leaves no `e` row and no `E` entry, changing or deleting every one of them keeps the witness valid, changing `SEMIO_FIXTURE_VALUE` still breaks it. Red on base: 3/3.
- Same batch, second defect: the stall watchdog's process table on Windows (`powershell.exe ... Get-CimInstance Win32_Process`, `liveChildPidsV1`) was not a declared host probe (macOS `ps -axo pid=,ppid=` is), so on Windows it taints any witness it runs under: `hostProbes` gets the exact row. Law (c) runs the real `liveChildPidsV1` with `process.platform` forced to `win32` under the preload and reads the witness taint list (red on base: `spawned spawnSync powershell.exe ...`).

### 2. The change-journal lock steals the lock of a starting service (batch `journal`)
`takeLock`: `mkdirSync(lock)` then `writeFileSync(owner.json)` is not atomic; a second starter in between reads an empty owner, did `process.kill(owner.pid ?? 0, 0)`. `kill(0)` signals the caller's own process group on POSIX (always "alive", no error), so `alive` was true, the start-timeout test used `owner.at ?? 0` (always expired) and the lock directory was removed: two services on one directory. On Windows `kill(0)` finds no process, so the two platforms disagreed on the same state.
- Fix: exported pure decision `changeLockHeldV1` (a pid is real only when a positive safe integer; an owner that is not readable holds the lock while the directory is younger than `startTimeoutMilliseconds`, age taken from the lock directory's mtime), used by `takeLock`.
- Law `📜️journal/🧪️tests/🔒️lock`: decision table of 11 vectors vs a Python oracle (pid 0, negative, fractional, text, dead, stale heartbeat, start timeout), plus the real service: a fresh lock directory without `owner.json` refuses a second start, the same directory aged past the timeout is reclaimed, pid 0 in an old lock is reclaimed. Red on base: the table (missing export) and the real service (`Received promise that resolved`).

### 3. The Python oracle of the journal directory cannot run on Windows (batch `journal`)
`🧪️tests/📍️directory/🐍️oracle/🐍️.py` imports `pwd` and calls `os.getuid()`; Windows has neither, so the law added with hotpath2 `jdir` fails at import there (and the suite is Windows-capable by the static evidence rule). Fix: optional `pwd`, `getuid` guarded, home from `expanduser("~")`. Law: the oracle run with `sys.modules["pwd"] = None` and `os.getuid` deleted gives the same 7 layouts (red on base: `ModuleNotFoundError: import of pwd halted`).

### 4. Files replaced by the staging tool are left at mode 0600; the root search can loop on Windows (tooling, `xplat5-tools/stage.template.py`)
`stage.py atomic()` writes through `tempfile.mkstemp` (0600) and `os.replace`s it over the target. 286 tracked files in the working tree are 0600 today (121 modified today; 213 outside `.🧬semio/`), where git records 644: invisible to git, but unreadable for another user or container uid on a shared bind mount, part of the witness stat identity (`mode` is a recorded field, so a later chmod re-keys plans) and a 100755 file would lose its executable bit. `root_of()` walks `os.path.dirname` until `here == "/"`, which never holds on `C:\` (infinite loop when no `--root` is given outside the repo).
- Fix in the template: keep the mode of the file it replaces (new files: 0666 minus the umask, read independently of the script), stop when `dirname(here) == here`. Law `tests/test_stage_mode.py` (stdlib `unittest`, oracle `os.stat` + umask): apply and revert keep 0644 and 0755, a new file gets 0666 & ~umask. Red with the old template (`384 != 420`), green with the new one. The Windows infinite loop is not reproducible on macOS (`/` terminates the loop); the second test only pins that the search ends.

## Reviewed and found correct (no change)
- `clonejournal`: the `fsevent` flag module is compiled only under `cfg(any(test, macos))`; Linux (`inotify`) and Windows (`ReadDirectoryChangesW`) backends are byte-identical in behaviour and both type-check for the real targets. Linux/Windows have no clone-source event (reflink/block clone do not touch the source's watched events: `IN_ACCESS`/`IN_OPEN` and last-access are not in the masks), so nothing to add there. The clone law is `skipIf(!darwin)`, correct.
- inotify backend: a new or moved-in directory is watched after its creation event without reporting its pre-existing entries (the classic inotify race), but the creating row is structural and `changedWatchedPathsV1` marks every watched path below a structural row as hot, so no stale vouch results. `ENOSPC` is `lost("watch-limit")` and pins the supervisor to `verify` for good. Unfollowed symlinks match `IN_DONT_FOLLOW`.
- RDCW backend: `SHARE_ALL` includes `DELETE`, subtree on, overflow (`ERROR_NOTIFY_ENUM_DIR` and `returned == 0`) is `lost`, the buffer persists changes between calls, `\` becomes `/` before the filter. Directory rows are always `dir = 0`, which only makes a modified directory structural (more `stat`, never a wrong vouch).
- Journal world check: symlink/junction directories (libuv reports junctions as symlinks) go to `stat`, case folding on darwin and win32, `memoRelativeV1` accepts `C:/` and `\` forms. Remote file systems: virtiofs, 9p, drvfs, fakeowner, grpcfuse, FUSE, NFS, SMB, UNC and network drives refuse the journal.
- `host-capacity`: darwin `vm_stat`/`sysctl`, Linux `/proc` + cgroup v1/v2, Windows PowerShell with a `freemem()` fallback and a once-per-process notice; gate directory `~/Library/Caches` | `%LOCALAPPDATA%` | `$XDG_CACHE_HOME`; `process.kill(pid, 0)` liveness is right on all three; lease reclaim refuses to stop anything on win32 (no start time).
- action environment allowlist: Windows class (`SYSTEMROOT`, `COMSPEC`, `PATHEXT`, `USERPROFILE`, `LOCALAPPDATA`, `PROGRAMFILES(X86)`, VS/SDK prefixes), `TMP`/`TEMP`/`TMPDIR`, `LIB`/`INCLUDE`/`LIBPATH`, case-insensitive compare. The new journal state directory never reads `TMPDIR`/`TMP`/`TEMP` and has a `%LOCALAPPDATA%` branch.
- Line endings: `.gitattributes` `* text=auto eol=lf`; no CRLF in any file changed today; the watcher pin hashes LF bytes. `Bun` and `Node` `localeCompare` are locale independent (checked under 7 `LC_ALL` values), so the `localeCompare` sorts that feed digests (`🕸️units`, cargo workspaces) differ only from code-point order, equally on every host; the committed `schema-document-index.json` uses `Buffer.compare`.

## Open, no staged fix (reasons)
- Runtime-row identity (`rowid`, landed): an executable is identified by its real file's stat. A version-manager shim (Volta, scoop, asdf, mise) keeps its own file while the active `node`/`bun` changes by project file, so `node --version` would be answered from a stale identity. Tried: real file named like the tool and at least N MiB. Refuted by this machine: Homebrew `node@24` is a 68 KB native launcher (the heuristic would have disabled the whole rowid win), and Volta/scoop shims are named `node`. A sound rule needs the version manager's own answer (not available generically). Mitigation until then: the user sets `SEMIO_REPO_PLAN_REUSE=verify` after switching a toolchain manager version.
- RDCW buffer is 64 KiB: a build burst in an excluded directory (`target`, `.cache`) overflows it (the kernel cannot exclude) and yields `lost("overflow")`, i.e. `stat` fallback on Windows during builds. A larger buffer (local volumes allow it) is a one-line change but cannot be measured here.
- The Rust scan on Windows reports no inode and no mode (finding fixed in `winframe` by treating `0` as unknown). A real NTFS file id needs `GetFileInformationByHandle` per directory (an extern is already declared in the backend); not done without a Windows host to measure the cost of ~80k handle opens on the course tree.
- `platforms` rows (xplat4-g `staged/platforms`) are still unlanded: the new laws here use only `python3` (`python` on win32), `bun`, `rustc` and `spawnSync`, so they carry no POSIX cause for `tag.py` except the `python3-command` pattern the table already treats the same way.
- Windows `node.exe` rename over a running watcher in `ensureWatcherV1` (two concurrent builds of the same pin) would fail with `EPERM` on the second `renameSync`; the pin directory is content addressed so only a race can reach it.
