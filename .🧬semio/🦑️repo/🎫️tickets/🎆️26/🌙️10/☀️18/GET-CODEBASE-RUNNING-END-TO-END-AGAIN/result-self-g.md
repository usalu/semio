## Design
1. Store `implementation/<entryKey>/{current.json, <digest>.json (the exact snapshot text, read-only), <digest>.seal.json (receipt: validation + stat fingerprint of the live closure), blocked.json, lock.sqlite}`; the digest is `buildSourceClosureIdentityV1` (what the loader checks), the pointer is replaced by rename (the commit point).
2. Run start (cheap): read `current.json`, stat-fingerprint the closure files, the observed directories and root lock files (about 100 ms, no file read): fresh -> run the stored snapshot; drifted -> promote under the SQLite exclusive lock (process death releases it, no TTL, no takeover race), re-check after the lock (a peer may have promoted), capture, wait for a quiet tree (settle rule, capture re-fingerprinted), validate (Bun.Transpiler over every code file, then a canary load of the candidate in a loader child), publish (snapshot, receipt, pointer), GC. Any failure keeps the old pointer and prints EN+DE which file blocks promotion; the same broken tree is never recaptured (the blocked record carries its fingerprint).
3. `SEMIO_REPO_IMPLEMENTATION=live` runs the live tree exactly as before (declared opt-in of the agent that edits the tool); `sealed` is the new mode; the default flips in one policy edit after the laws and the graph-free runs.
