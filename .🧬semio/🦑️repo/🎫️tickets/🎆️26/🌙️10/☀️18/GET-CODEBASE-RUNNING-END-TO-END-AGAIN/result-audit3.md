## Investigated and cleared (the argument, so nobody re-audits it)
- carry (memo serves a sealed slice across generations): the carried hit passes every check of an unmoved hit first (journal since the record's cursor, relevance, stamps, recheck of rows outside the journal's sight); carry only replaces the pointer equality by: retained `from` manifest, pin of exactly that manifest, `to` = the generation the pointer names, `env`/`global`/`identity`/`implementation` equal and every covered owner row (fragment, edgesEnv, targets, config, nativeRoot, tag, root, kind, bytes) identical. Env entries: any `@env` fact change moves the `env` digest -> `shared:env`; edges are in fragments/edgesEnv; externals/unavailable in `global`. Generation-level facts: the fact index is not compared, and nothing downstream of a pin reads it (only the generation store, the memo sidecar writer and a storage headroom worker read fact indexes; `readPinnedGenerationV1` serves fragments by row), so G2's facts never substitute for G1's verified ones. A new project joining the closure needs a membership change that the journal reports in a relevant directory (as without carry). Cursor rule: carry is lookup-only, sealing still requires a verification after the cursor (audit1). `invalidate` publishes `manifest:null` (`pointerOf` refuses), `refreshMetadata` keeps rows (carried, intended). Note (not a defect): the plan text names `admission.closure = sha256(manifest.membership, names)`, so a carried plan is not byte-equal to G2's plan when membership moved (printhot's "plan has no generation identity" is imprecise); only the Bazel plan key hashes it (`bazelGraphDigestV1`), i.e. at worst a replan.
- reseal (G37, landed 11:47): `expected` is a repetition heuristic, not a soundness gate; the sidecar still classifies the SERVED generation's facts and keeps the `verified`/`moved` rules, so sealing G2 with G2's relevance is sound.

- winframe (inode/mode 0 = unknown): on macOS/Linux the native scan returns `(meta.ino(), meta.mode())` (only `cfg(not(unix))` returns `(0,0)`), Node's `lstat` never yields ino 0 or mode 0 for a real file/directory (mode carries the type bits), and the memo stamps are taken by JS `lstat`; so `frontierFactHoldsV1` degrades nothing there. On Windows the directory check falls back to mtime + racy window (documented by xplat5).
- incremental (unit-cache misses keep Cargo's `-C incremental`): sessions live in the lane's own build directory and a lane is held by exactly one Cargo process (claim), so no session is shared. Published bytes of a workspace unit now depend on the publishing lane's session (256 CGUs vs 16, reused work products), but the store is variant-based (several entries per key, each with its own dependency digests) and downstream keys hash the extern bytes a lane actually holds, so a re-compile after GC can only cause misses, never a wrong reuse; `-C incremental` is an untracked rustc option (crate hash unchanged). Costs to watch, not defects: session disk (~3.5x outputs per workspace crate per lane, bounded by the collector's incremental share) and rustc RSS.
