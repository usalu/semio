## 1. Design (the clean form; no compatibility layer)
1. **Walks stop at script-provider port edges** (`boundedScriptInputsV1`, the old core of `relativeScriptInputs`): a module that defines ports adds the designated ports to the walk's ports (`cache.walkPorts`) instead of walking into the provider modules; the derived walk answer digests roster + compiled + generated + ports. The public `relativeScriptInputs` composes the bounded walks back into the full roster, so owner discovery, component targets, input precision and test discovery list exactly what they listed before (law: composed full closure = esbuild; provider law's TS-compiler/esbuild oracles over 4 real commands).
2. **Stable references.** A command closure read through a view names each provider by `{input:"scriptProvider:<port>:<view>", projects:["@semio-tech/repo-script-providers"]}` (target-sources, generic-target → `scheduling`; native-target, native-command → `native`), and (batch 2) each target-independent tool command by `{input:"toolClosure:<name>:native", …}`: `cargo-command` (the cargo driver, native fallback of every Rust target) and `cargo-lock-owner` (lock script + schema). The reference is the token; its value lives in one place.
3. **One providers project holds every shared closure** (NEW `📚️library/🏃️process/🔌️providers/📋️project.json`, `metadata.semio.scriptProviders: "🔣️.json"`, declared in the project schema): one named input per designated port × view (designation + schema + transitive provider walks without the view's prefixes; + external packages for `scheduling`) and per declared tool (its entry walk + the provider walks it names + resources). It holds those walk facts. Schema-first policy `🧭️script-inputs/🔌️provider-closures/🔣️.json` (EN/DE contracts: group names, views, tools with entries relative to the providers project, project recognition).
4. **Action keys** keep the provider/tool files: Bazel already expands `{input,projects}` inside groups (srcs deduplicated), the slice loader admits the referenced project, so a consuming action re-executes exactly when a file it consumes changes. Nx forbids project references in named inputs → NEW `liftNxNamedInputReferencesV1` moves them into the targets (refuses a `^group` holding them); `shareNxProjectInputsV1` never redirects a group another project references. The sealed selection scope follows Nx `projectInputs`.
5. **Closure queries** (`some`, `excludedPaths`, `workspaceKeys`) answer over the expanded closure (late mode: shared entries ensured detached, the project holds only the answer fact), so every assembly decision is unchanged. A shared closure importing a generated output is refused (EN/DE), a consumer could not depend on its producer (none does).
6. **Task 2 — key policy, declared**: exec-f excludes scheduling code from action keys; nodes now follow the same table: every `closure-of` names a role (`👓️walk-views/🔣️.json` `closures`, refused otherwise): `artifact-command` → `scheduling`; `artifact-sources` (the artifact's output content) and `test-discovery` (tests exercise scheduling code) → whole. The cargo lock owner (batch 1: role → `native`; batch 2: tool closure, `native`) and the cargo driver (`native`) leave scheduling code out and keep the native-build modules.
7. The inference implementation revision covers `👓️walk-views` and `🔌️provider-closures` (module, policy, schema), so a policy edit re-infers instead of leaving stale references.
