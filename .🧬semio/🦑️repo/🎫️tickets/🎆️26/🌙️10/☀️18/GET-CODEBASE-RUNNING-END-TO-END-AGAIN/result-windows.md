## Findings and what happened

| # | area | finding | state |
|---|---|---|---|
| W1 | process kill (launcher) | On Windows the launcher keeps running as the parent of `bun` (`RunChild`), while POSIX `exec`s. Ctrl+C and console close reach both processes, but `TerminateProcess` on the launcher leaves `bun` running and still holding its leases. That happens with Task Manager, `taskkill /PID` without `/T`, an agent or IDE that kills its child by PID, or a CI step timeout outside a job. | FIXED (`winlaunch`): `containChild` puts the runtime into a job with `KILL_ON_JOB_CLOSE` + `SILENT_BREAKAWAY_OK`. Only `bun` itself joins the job (it is libuv's own model), so the services bun detaches (resident, change journal, Bazel server) outlive the command. If the host refuses the job, the child runs without one. The struct layout is checked on darwin/arm64 (same 64-bit rules: 144 bytes, LimitFlags@16, IoCounters@64) and asserted again in the Windows law. Windows law: terminate the launcher, and the runtime dies within 5 s (red on base by behaviour). |
| W2 | worktree identity | Go (`filepath.EvalSymlinks`) and the service (`realpathSync`) can spell one checkout differently on Windows. Go upper-cases the drive letter and on-disk-cases each component. Node/Bun JS realpath keeps the spelling it was given, and `cmd` keeps `c:\dev\semio` as typed. Every id derived from the root then differs: resident pipe name, key dir, journal dir (`stateDirectoryV1`), agent sessions. The result is a silent miss of the resident fast path and a second change-journal service plus memo per spelling. The Bazel path plan already lower-cases for this reason; the worktree id does not. | FIXED (`winlaunch`): both sides ask the kernel. Go uses `GetFinalPathNameByHandleW` with libuv's prefix stripping (`FinalPathSpelling`, vector law on every OS). The service's `canonicalRootV1(root, platform)` uses `realpathSync.native` on win32, which is the single funnel for all 24 call sites. Laws: spy law (red on base) and a Windows-only Go law comparing the launcher with `bun -e realpathSync.native` for a mixed-case spelling. |
| W3 | resident pipe security | `residentTrusted` is `true` on Windows, and pipe names are machine-wide (`semio-repo--1-<id>`; uid is -1 for every account). Another local account that creates the name first receives the launcher's hello and capability token, and it can print arbitrary "output" plus an exit code into the victim's terminal or CI. In addition, `ERROR_PIPE_BUSY` failed at once, while the unix dial waits 250 ms. | FIXED (`winlaunch`): the dial keeps the pipe only when `GetNamedPipeServerProcessId` → process token user SID equals the caller's SID. Otherwise it falls back silently, as for "down". `WaitNamedPipeW` waits up to 250 ms. Windows law: the own pipe is accepted and its owner equals the caller, a busy single-instance pipe waits ≥ 200 ms and then fails. |
| W4 | resident nonce | The token id came from `/dev/urandom`, which does not exist on Windows, so the fallback used the SHA-256 of the current nanoseconds: predictable. | FIXED (`winlaunch`): `crypto/rand`. |
| W5 | provisioning publish | `os.Rename(staging, final)` runs right after `bun.exe` was extracted and probed. Defender or the indexer often holds a fresh executable for a moment (error 5 or 32), and the install then fails with `cacheUnavailable`. | FIXED (`winlaunch`): `renameRetrying` after 10…1280 ms (2.55 s), like Go's own `robustio`. Only errors 5 and 32 on Windows count as transient, never on POSIX. Laws: schedule/exhaustion/other-error on every OS, transient table on Windows. |
| W6 | installer | `Move-Item partial → repo.exe -Force` fails while any build runs, because on Windows the launcher is a live image for the whole build (see W1). Reinstalling, which the registry-contract refusal itself suggests, therefore fails exactly when a peer build runs. | FIXED (`wininstall`): moved-aside copies from earlier installs are removed first, the new file is staged, the running `repo.exe` is renamed to `repo.exe.old-<id>` (allowed for a running image), and the new file takes its name. Text law pins the order. |
| W7 | suite platforms | `build-fleet-status` has no platform verdict, so the platforms law "explicit and explained" is red on live. Its law spawned literal `python3`. | FIXED (`fleetpy`): `requireTestToolV1("python")`, with verdict `[darwin, linux, win32]` (no host fact left). |
| W8 | per-user roots | The Windows branch of `leaseRegistryRootV1`, `agentSessionRegistryRootV1` and `hostCapacityDirectoryV1` still uses `LOCALAPPDATA ?? …`. An empty or relative value gives a registry per working directory: the L1 defect that linuxdc fixed for `XDG_CACHE_HOME`. The same applies to `stateDirectoryV1` and the authorizer memo base (`\|\|` accepts a relative value). | OPEN, not staged. The right rule is "fully qualified" (`X:\` or `\\`), which is Python ≥ 3.13 `ntpath.isabs`. Node's `win32.isAbsolute` also accepts `\foo`, so the check needs one shared predicate rather than 5 copies. The endpoint computation must stay identical in Go and TS. Low likelihood: Bazel's strict action env drops `LOCALAPPDATA` entirely, and the `??` fallback is correct for that case. |
| W9 | hot path cost | `systemAncestryV1` on win32 starts `powershell.exe … Get-CimInstance Win32_Process` once per top-level command (agent session identity, lease custody, capacity handover). That typically costs 0.3–1.5 s on Windows, against today's 10 s hot no-op. The watchdog probe (every 30 s, only after 10 min idle) is harmless. | OPEN: replace it with a Toolhelp32 snapshot (`CreateToolhelp32Snapshot`/`Process32NextW` for pid/ppid/image, `GetProcessTimes` for the start) through `bun:ffi`, as the lease and directory hosts already do. Measure it on the first Windows CI run (CI item 6). |
| W10 | `.cache/b` swap vs the running runtime | The launcher prefers `bun.exe` from the tools partition (`.cache\b\t\m\bun\<sha>`). On Windows the directory backend swaps `m`/`v` by rename, and the protocol itself refuses with `windowsOpenHandle` while a handle is open inside. A launcher that runs bun out of `t\m` may therefore block detaching that partition for as long as any `repo` command runs. | OPEN, owner decision: on win32, prefer the user cache in `Locate` (a one-line change in Go). Prove it first on Windows (CI item 4). |
| W11 | Bazel cache probe | `🔁️probe` renders `ctx.actions.run_shell(command = "sh …")`, which needs MSYS bash (`BAZEL_SH`) on Windows. Every product rule already runs Bun directly (platform law green). | OPEN, diagnostic command only: render the probe with `ctx.actions.run(executable = bun, …)` like `🏃️execution`. |
| W12 | launcher Go tests in CI | `@semio-tech/repo-launcher-go:test` runs in no workflow on any OS. All launcher laws, including the new Windows ones, are therefore never run in CI. | OPEN, CI proposal below. |
| W13 | ticket paths | 3 tracked ticket files are over 256 UTF-16 units (xplat5 finding 5: xplat4 `freespace`, zt-g `overlay`, gram4 `shape-keys`). With `core.longpaths` (the README clone command) they check out. The AGENTS.md 256 rule still fails. | OPEN (other lanes' trees): flatten them to `files/NN.ext`. |
| W14 | parity | The POSIX installer warns about another `repo` that shadows the launcher on PATH; the PowerShell installer does not. Bootstrap `Install-PinnedExecutables` overwrites `node.exe`/`uv.exe` with `Move-Item -Force` (same failure as W6 while one runs). Detached services start with `cwd: root`, so the checkout folder cannot be renamed or deleted while they run (`repo service stop` first). | OPEN, minor |

## Reviewed and found correct (no change)
- Go launcher: `GOOS=windows` vet + build + test-binary compile is clean for amd64/arm64, including all test cases (`C/windows-tools/go-win.sh`). The root search ends at a drive root (`parent == directory`). `PATH`/`Path` are matched case-insensitively. Runtime rows exist for win32 x64 (baseline) and arm64. `bun.exe` is located via the registry, and the user cache is `%LOCALAPPDATA%` (`os.UserCacheDir`). The `O_EXCL` provisioning lock and its mtime stale rule work on NTFS. `syscall.SIGTERM` covers console close/logoff/shutdown.
- Rust parts of the build tool, `rustc --emit=metadata` for x86_64/aarch64-pc-windows-msvc (`C/windows-tools/rs-win.sh`): the watcher (bin + tests), `🏠️workspace` routing, `📥️resources`, `🎟️admission` (the rustc scheduler; `K32GetProcessMemoryInfo`/`GetProcessTimes` path, edition 2024) and `🧮️compiler` (with the hash crate as an extern) are clean. `🕸️graph/🦀️rust` needs `serde_json` (dashboard crate) and was not checked.
- TS laws with Windows fixtures, run in the mirror (24 files). Green: host-capacity Windows 6, boot clock 4, directory host 10, journaled swap 11, conditional retirement 7, physical `LockFileEx` 6, registry roots 2, taskkill grammar 6, process-tree 4, exchange 2, dispatch 4, watchdog 11, Bazel readiness 7, pins 4, platform 3, path plan 5, Bazel storage 8, resident protocol 23, install contract 7, runtime pin 15. Not green, none of them a Windows defect: leases Windows 4/1 (needs the runner envelope), statfs census 5/1 (5 s timeout under load 56-70), bootstrap workspace resolution (5 s timeout), the platforms evidence law (the mirror's closure lacks `⚙️runtime`/`🚪️io`/`💻️os`; same artefact linuxdc saw). Process laws must run with `--no-seal`: macOS `sandbox-exec` changes process liveness.
- Tracked paths (204,823): no case collision, no reserved device name (CON/PRN/AUX/NUL/COM/LPT incl. superscripts, CONIN$), no `<>:"|?*\` or control character, no trailing dot or space, all NFC. The longest source path is 226 units (33 units left for the checkout prefix under MAX_PATH; CI enables `LongPathsEnabled` + `core.longpaths` before checkout).
- CRLF: `* text=auto eol=lf` overrides `core.autocrlf`, fixtures are `-text`, and every `.ps1` is LF with a BOM (needed by Windows PowerShell 5.1 for the emoji literals).
- Locks/leases: whole-file `LockFileEx` (same range as Cargo) with `\\?\`/`\\?\UNC\` names and volume+file-index identity; `process.kill(pid, 0)` liveness; lease reclaim never kills on win32. Process trees: every group kill has a `taskkill /T /F` branch (termination module, contract capture, exec, remote worker, nx bootstrap).
- Change journal and `.cache/b`: as xplat5/xplat-win2 found (RDCW with `SHARE_ALL`, overflow → lost; directory partitions with journaled `MoveFileExW` swap). Per-directory case sensitivity falls back to case-fold mode when the WSL feature is absent (`foldSafeRefusals`), so no elevation is needed (zero-touch kept).
- Bazel: short output root via a junction and a lower-cased checkout digest; a readiness refusal without `LongPathsEnabled`; `--experimental_convenience_symlinks=ignore`; no shell, no genrule in product rules.

## CI job proposal (what only a real Windows host proves)
Add to `build-system.yml` (`smoke` matrix, after the `repo-launcher` action; all three OSes, so the launcher laws run at all):
```yaml
      - name: Launcher laws of this host (Windows: job object, final-path root vs Bun, pipe owner, transient rename)
        run: repo run @semio-tech/repo-launcher-go:test --output=stream
```
Then add one Windows-only job `windows-host` (windows-latest, long paths before checkout, `repo-launcher` action) with these steps:
1. `repo run @semio-tech/repo-launcher-go:test` → `🪟️windows-contract` 5 laws (W1–W5). Bun must be on PATH for the cross-runtime law; the launcher prepends its runtime directory for children. If it is not there, the law fails rather than skips.
2. Root spelling end to end: `cd` to the checkout spelled with a lower-case drive letter and upper-case components, run `repo service start`, then `repo run <cheap target>`. Expect the resident path to answer (no "normal path" banner) and one journal directory under `%LOCALAPPDATA%\semio\repo\`.
3. Installer replacement: start a long `repo tools exec --light node -- -e "setTimeout(()=>{},60000)"`, run `🔵️.ps1` meanwhile. Expect exit 0 and `repo.exe.old-*` beside the new `repo.exe`; run it again and the old copy is gone.
4. `.cache/b` tools partition: while a `repo` command runs bun from `.cache\b\t\m`, ask for that partition's detach/retirement. Record whether the result is `windowsOpenHandle` (decides W10).
5. Rename over an open file under Bun: two Bun processes, one holds a file open for reading, the other `renameSync`s over it. This decides whether Bun uses POSIX rename semantics (xplat3 F4 retry otherwise).
6. Timing: `Measure-Command { powershell -NoProfile -Command "Get-CimInstance Win32_Process | Out-Null" }` and the hot no-op wall time of `repo run <course target>` ×3 (decides W9).
7. xplat5 leftovers: RDCW overflow during a build burst (64 KiB buffer), NTFS file index above 2^53.
