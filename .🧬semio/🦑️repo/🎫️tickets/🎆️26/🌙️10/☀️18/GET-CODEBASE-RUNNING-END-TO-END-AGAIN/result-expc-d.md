## Method
1. Edges from the lint's own failure graph (`summary.violations`): baseline 09:05, r1 09:28 (died in an unrelated tooling capture fault: "Concrete captured workspace path required .cache/b/d/m/j/…/node_modules/.bun/ajv…", peers' dependency churn), r2 09:36, r3 09:48.
2. `C/expc-d-tools/ncpr.ts` (port of lay15's `ncpr2` narrow-facade logic, generalized to any package): for every `no-cross-package-relative-*` importer reuse the existing export key that exposes the imported names with the same deep origin, else create `<package dir>/<module path>/🟦️.ts` (explicit `export {…}` / `export type {…}` of exactly the imported members, `🔣️json` wrapper for JSON documents) plus one export key, else extend the facade of an existing key by the missing names (merged into the existing statement). Keys follow each package's convention (framework strips `🔨️modules/`, repo-lib uses its domain keys, process mirrors the module path). Specifiers are relative, so no dependency declaration and no lock change. Dynamic whole-module imports can be narrowed with `NCPR_NAMES`.
3. `C/expc-d-tools/scan-edges.ts` synthesizes edges for files that were moved. `C/expc-d-tools/extract.py` turns a failure graph into an edge file and prints the area table. `C/expc-d-tools/tsc.sh <tag> <process|course|print>` runs the three typecheck lanes. `C/expc-d-tools/lint-dir.sh <tag>` runs the Nx lint.
