## Method (graph-free, kernel enforced, reproducible)
1. Effective key of a cached target = `buildTaskInputsV1` expansion over the sealed generation (`measure.mjs`, generation 550-560) + the five root files the Bazel route adds (`bunfig.toml`, `bun.lock`, `package.json`, `tsconfig.json`, `rustfmt.toml`). Validated against the generated Bazel BUILD srcs of `ui-styling-tokens:generate` (`bazel-inputs.py`): identical except those root files.
2. The ACTION COMMAND of the target is run directly with the environment the executor itself issues (`mkenv.ts`: births an Original and calls `issueBazelTaskEnvironmentV1`; without it every script refuses "Original parent Script process invocation required"), under macOS Seatbelt: every workspace file outside the key fails with EPERM for the whole process tree (native code included); denied paths come from the unified log (the error text names the ones the rate limited log drops); learning rounds add them. A by-design seed is allowed and counted separately: the 31 scheduling prefixes, the 366 files of the executor-command implementation scope (the action key's implementation digest), the target's own outputs and the dependency outputs, and the modules the script imports but the router read slices away (full static import closure by bun's own Transpiler). Everything else the run reads is an undeclared read.
3. Seatbelt refuses profiles over 64 KB (one literal per file). `hybrid/cover.mjs`: per directory either literal grants or ONE subpath grant plus denials of the undeclared entries (last matching rule wins). Law `hybrid/tests/hybrid.test.ts` 5/5: random layouts and declared sets, the TypeScript grant function, an independent Python evaluator of the rendered text and the kernel (sandbox-exec + cat) all grant exactly the declared set. `fitCoverV1` relaxes (reports) entries when even that does not fit (course-react test: 462 undeclared siblings unenforced, listed in `relaxedPaths`).

## Findings
1. **LayeredOverview is not a cache gap.** `🖱️ui/🧱️elements/🥞️LayeredOverview/📋️types/🟦️.ts` is in the effective key of `course-react:test|typecheck` (10,012 files), `architecture-course:test|typecheck|build` (generation 550-560, `lists-c/*.files`); the kernel run of `course-react:test` named only module configs and nothing under ui elements (partial report, see Running). The law's false positive is route2-g's (FOR line).
2. **C1, module resolution configs (real, systemic).** Every TS action loads modules of other packages; bun reads the NEAREST `package.json` and `tsconfig.json` (+ `extends`) of each; only the root ones are keyed. Seen on every target below (5-17 files each, e.g. `🧰️framework/📦️packages/🟦️typescript/{package,tsconfig}.json`). Fix staged: batch `f1`.
3. **C3, CSS/HTML/SVG/SQL/JSX of native owner trees (real).** `ownerExtensions` of native projects is `{json,semio,wit,wgsl,glsl,h,c,cpp,ts,tsx,js,mjs,cjs}`; a TS/vite target depending on `^default` of `@semio-tech/ui-rs` is therefore NOT keyed by `🖱️ui/🧵️styles/🎨️.css` and `🖱️ui/🌐️globals/🎨️.css`, which the site build imports: an edit of the global CSS left `architecture-course:build` a stale cache hit. Fix staged: batch `f4`.
4. **C4, Tailwind scan region (real, partly staged).** The site build's tailwind scans the whole ui tree (`@source "../../"` in `🖱️ui/🎨️styling/🖌️ui/🎨️.css`) and the course tree, all extensions, tests included (1,578 + 49 files read); the key names only source extensions and the target policy removes `🧪️tests`, `*.feature`, `*.stories.*`. Class names in a scanned `.rs`/test/story file change the CSS (the word `hidden` in a comment emits `.hidden`). With the simulated fix of C1+C3+C5 the oracle still reads 1,000+ ui files that are not keyed by extension. OPEN decision for the ui owner: either declare the scan region (sound, broad: `🖱️ui/**/*` incl. tests) or narrow the scan with `@source not` for tests/features/rs/json so scan and key agree (stories decide the storybook CSS). Not staged: it changes the served CSS.
5. **C5, vite config closure (real).** The course site build loads `🏗️builder/🌐️vite/🟦️.ts` through vite, not through the script's imports, so its plugin closure (tailwind, wasm, emoji index…) was unkeyed. Fix staged: batch `course` (`closure.modules`). Simulated (declared set + closure + C1 + C3 + the scan region): course build undeclared 1,678 -> 137, all of class C6.
6. **C2, cargo-backed script targets (real, open).** `actor-typegen`, `ui-contract-rs:generate`, `framework-rs:generate`, `course:test` run cargo; cargo reads every workspace member `Cargo.toml` (146-195 files), `Cargo.lock`, `rust-toolchain.toml`, `.cargo/config.toml`; their curated inputs list a few. Typegen output depends on dependency versions, so a lock/toolchain edit is a wrong hit today. Fix = route through `nativeTestSources` (rust-g). The three typegen/generate runs are INCOMPLETE under the oracle (cargo's own reads are denied but the log does not name them; `failed to load manifest for workspace member …/📇️catalog`): their lists are lower bounds. The Landlock+strace backend (devcontainer, keys2-g) names every refused open and is the right tool for them.
7. **C6, cargo workspace preparation inside the vite action (open, owner decision).** The course build action also reads 89-95 `Cargo.toml` and 39 build-library modules (`🗂️workspaces/🦀️cargo/🛠️preparation/**`, `⚡️caching/🦀️cargo`, wasm provider) because its caller capabilities carry the `native` block; the site bytes do not depend on them. Either the preparation is not needed for a TS artifact (drop it: owner of `buildViteArtifact`/`scriptCompilerAdmissionControlV1`) or it is infrastructure like the scheduling domains (declare a domain). Not staged.
8. By design (counted, not defects): scheduling prefixes, executor scope, own outputs, router-sliced modules (14 for tokens, 191 for the course build). The router read keeps every module only other commands use out of the key although bun loads it; sound only if those modules have no output-relevant top-level effect. A law could prove it (top-level statements limited to declarations); not written.
9. Tool defects found on the way (not fixed by me, FOR owners): the live read-oracle `🪞️mirror` backend crashes with EEXIST on symlink when the declared list is large (seen on framework-rs:generate before the hybrid cover); `apply`-style anchors in staged scripts that truncate before reading (mine, fixed).
