## Defects found and fixed at the root (each pinned by the corpus)

1. `🏗️build/📤️arguments/🟨️.mjs` `conformsOwnerContractV1` (the validator behind every target cache decision and execution contract): `const`/`enum` compared with `===`/`includes` (object and array members never matched), `uniqueItems` compared `JSON.stringify` (key order made `{a,b}` and `{b,a}` distinct, so duplicate orchestration children slipped through), `minLength`/`maxLength` counted UTF-16 units instead of code points, an array rule without `items` threw a TypeError for non-empty arrays. Now compares by canonical (key-sorted) JSON, counts code points, treats a missing `items` as no constraint. Pinned by the corpus.
2. `🏭️generator-outputs/🟨️.mjs`: `resolveOutputPath` used string replacement patterns (a project root containing `$&`, `$'` or `$$` was rewritten); `generatorOutputCouplingInputs` digested the same output twice when two generate siblings (or one sibling) named it twice (the dedupe set was never extended); `generatorContractInputs` looked the discovery kind up on a plain object, so `toString`/`constructor` counted as fingerprint owners. Pinned by the corpus.
3. `🪢️revision-graph/🟨️.mjs` `readComponentRoster`: `NAME.test(entry.name)` coerces its argument, so an entry without a name, with `name: null` or `name: true` passed admission (the strings "undefined", "null", "true" match the name pattern). Now requires a string name.
4. `🦀️native-manifests/🟨️.mjs` `readToml` refusal observation: it read `cause.line/col/pos`, but Bun's parse error carries the position in `cause.position` (BuildMessage) or `cause.errors[0].position` (AggregateError, e.g. nested arrays); for an AggregateError `cause.line` is the JS line of the parser call site (observed `line: 89`, `sourceLine: ""`), column and position were always null. Now line, column and offset come from the TOML position. Findings pinned (not fixable here, Bun 1.3.14 `Bun.TOML.parse`): `\t` and `\f` escapes are swapped, `\UXXXXXXXX` is not decoded, a multi line basic string keeps its first newline and a line ending backslash does not trim, nested arrays and dates are refused, a table defined twice, a leading zero integer and a bare word value are accepted.
5. `🟦️typescript/🧩️units/🟦️.ts` and `📥️inputs/🎯️precision/🟦️.ts`: the workspace and input glob expressions were compiled without the dotAll flag, so `**` did not match a path with a line break while the parity compiler (`su`) did; both now compile with `s` like the parity one. Documented dialect: `**` crosses directories wherever it stands, `[...]` is literal, `\` is literal, only the input compiler has `{a,b}`, only parity and input have `?`; an unterminated brace group is a SyntaxError.
6. `💾️store/🟦️.ts` `removeObjectsV1` counted every well-formed digest as removed even when no such object existed (the gc report and the "removed" count were inflated by absent objects); now it counts only objects that existed. Pinned by the `objects` scenario. Reading note pinned by the build-run scenarios: when a build script declares inputs (any `rerun-if` file or variable) its package fact ignores `.rs` files (Cargo only watches the declared paths), without declarations every package file counts.

## Pinned divergences (not fixable here)
