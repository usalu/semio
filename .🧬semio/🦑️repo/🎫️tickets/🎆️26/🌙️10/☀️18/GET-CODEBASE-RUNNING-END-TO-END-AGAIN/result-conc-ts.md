## Design (schema first, tool neutral)
`L/🏗️build/🟦️typescript/🧩️units/` (L = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library`): `🧬️schema/🔣️.json` (closed document), `🔣️.json` (rules, EN/DE texts), `🟦️.ts` (engine), `🧪️tests/{🟦️.ts,🔣️.json,🐍️oracle/🐍️.py}`.
1. **Units, not tsconfigs.** A program (any family tsconfig) is cut into acyclic check units. Seeds: module roots (parent of `📦️packages`), manifest directories, `✏️s/🔌️plugins/*`, isolated `🧪️tests` per root (editing a test re-checks only the test unit), ambient `🌿️ambient/**/*.d.ts` (global, in every unit). Unit-graph cycles: SCC of at most `collapseFiles` (1500) files becomes one unit; bigger cores are refined along directories for `refineRounds` (2) rounds, remains collapsed; tiny siblings are coarsened when the graph stays acyclic. Deterministic, documented as data. The file graph is acyclic by law (lay15/16), so the finest partition always exists.
2. **Declaration boundary = TypeScript project references with our own orchestration.** Per unit a generated config (`composite`, `declaration`, `emitDeclarationOnly`, `include: []`, `files` = unit + its JSON inputs + ambient files, `references` = direct dependencies' *consumption views*). A view maps a unit's sources onto its content-addressed declaration directory `store/declarations/<key>`. Cross-unit imports (relative and bare, `.ts` extensions, JSON) resolve to the stored `.d.ts`; sources of other units are never loaded (`--listFilesOnly` proves it, test below). Third-party tool only (`tsc -p`); no TS API in the check path.
3. **Content address with early cutoff.** key = H(compiler, options digest, environment, unit files + digests, JSON inputs, ambient, **declaration digests of the dependencies**). A body edit leaves the unit's declaration digest unchanged, so dependents keep their key and are not re-checked. Receipts (diagnostics + errors + boundary findings + declaration digest) are replayed on a hit; failing results are cached too.
4. **Shared outputs, session-private state.** Store: `receipts/`, `views/`, `declarations/<key>/`, written by temp + rename (no lock, concurrent sessions at worst compute the same key twice). Incremental compiler state (`tsbuildinfo`, `out/`) lives only in `state/sessions/<session>/`, never shared, prunable (`pruneTypeScriptSessionsV1`). Incomplete incremental output is detected (expected `.d.ts` per source) and rebuilt cold.
5. Progress (`onProgress` per unit, `done/total`), cancellation (`AbortSignal` kills the child, nothing is published), bounded concurrency, EN/DE texts in the document.
6. **Oracle / test (language agnostic).** Fixture `🧪️tests/🔣️.json` (9 hand-written planner cases with expectations: markers, isolation, collapse, refinement, genuine file cycle, ambient+JSON, coarsening and its cycle refusal, glob roots). Python oracle written from the schema text answers every case identically and the 12 random programs (exact partition, acyclic units, topological order, edge set). Third-party: `tsc --listFilesOnly` crosscheck (derived import graph = tsc's workspace file list: **4,143 = 4,143, 0 missing, 0 extra** on the repo-library program), unit-wise diagnostics = monolithic `tsc -p` diagnostics on a synthetic workspace (3 = 3), per-unit program lists only own sources + stored declarations, second run = 0 compiler starts, implementation edit = 1 unit, signature edit >= 2 units, cancellation publishes nothing. `bun test`: **19 pass**, `tsc --strict` clean on engine and tests.

# Round 2 (10-20 21:30 to 23:15): source fixes (group 2), the 6 monolithic-only diagnostics, live wiring (group 3)

## Engine changes found necessary on the way (group 1 files, re-tested: 21 pass, `tsc --strict` clean)
- **Leaf units** (nobody consumes them: tests, scripts, vitest configs) are checked without declaration emit (`composite` off, `noEmit`): an unnameable inferred type in a leaf is not a finding, leaf checks are faster, and the flag is part of the key.
- **Same-stem sources** (`x.ts` + `x.tsx` write one declaration path, TS5056): the `.tsx` is split into its own unit, a cyclic core that would hold both is refined instead of collapsed, coarsening never re-merges them. New fixture case + oracle rule.
- **Package manifests are part of every unit key** (module resolution reads them; before, a `package.json` edit left stale receipts). Plan carries `manifests`.
- Import derivation finds manifests as ancestors of program files (no directory walk), takes an optional per-file memo (an edit re-derives only the files it touches), checks the cancellation signal; progress rows carry the error count.
- A non-canonical (symlinked) workspace path is refused (it silently defeats the redirect).

## The 6 monolithic-only diagnostics: cause and fix
`🏗️build/🧪️tests/🕸️graph/🎯️source-demand/🟦️.ts` lines 45/127 call `map`/`flatMap` on `row.roots`, a union of three anonymous array types from the JSON fixture. It is a cross-program inference-order effect, not the boundary (monolithic with `declaration` on keeps them). Fix (group 2 `source-demand-typed-roots`): one declared element type and four casts; after it library overlay: **monolithic 38 = unit-wise 38 diagnostics, identical, 0 only on either side, 0 boundary findings** (100 units, includes the new group-3 files).
