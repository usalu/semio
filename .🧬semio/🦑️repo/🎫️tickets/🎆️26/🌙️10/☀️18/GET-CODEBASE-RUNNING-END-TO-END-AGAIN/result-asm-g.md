## Design (sound incremental test discovery)
- A test project is stale exactly when something its own discovery read changed: its nodeRows are the facts of the shared state (command closure of the testing domain, computed once per discovery, ~19k raw rows, shared by all owners as one class of the fact index) followed by the facts of the capture of its own discovery (features/adapters existence, oracle and SUT crate manifests, cargo closure, ~1.6k rows). An owner is discovered again when the plan marks it dirty (`part.roots` holds its root), when a `.feature` member below it changed, or when it is new (a first case below a changed project). The environment digest moving (owner table, packages, workspace manifests, lock, taxonomy) discovers all owners again, because the dangling check (`withholdDanglingTestProjectsV1`) and the edges of kept owners depend on the owner table.
- Kept owners stay in the context as file owners (their roots keep their files away from the enclosing project) and, when withheld, stay withheld roots; their edges are untouched (edges only change when the environment digest moves).
- Why not one monolithic discovery with path-prefix claims (the old attribution): rows read outside the owner's root land in `@env` or in whichever project is refreshed in the same build, so a later edit of a crate manifest would not find the test project that read it.
