`C` = this ticket. `B` = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/🏗️build/🔧️tools/🏗️bazel`. Provisioned Bazel 8.4.2 (`.cache/b/t/m/bazel/bin/45e9388abf21d110/bazel`), macOS 27 arm64, machine heavily loaded by other fleets. Library frozen: no edit under `📚️library/`; fixes are staged under `C/bzl-real-tools/staged/`.

## Verdict
The production Bazel owner (workspace generation, control channel, action births, snapshot restore, tree-artifact outputs) executes real repo tasks end to end without `bun repo run`, and Bazel's own action cache and disk cache work: cold run, 100 % warm hits, minimal re-runs after a declared input changes, early cutoff for a dependent, disk-cache hits after `bazel clean`. Two adapter defects were found and fixed in the staging area; one of them (`.bazelignore`) made the adapter cache NOTHING. Undeclared inputs are a real, measured gap.

## Defects found (with staged fixes)
1. `.bazelignore: s` disables ALL caching (adapter `linkBazelSources`, added by bzl-breadth item 2).
   - Symptom: every run printed `WARNING: //:t_...: Skipping uploading outputs because of concurrent modifications with --guard_against_concurrent_changes enabled: <ob>/execroot/_main/s/<declared file> was modified during execution`, though the file's mtime/ctime were days old. The warm run re-executed (`2 processes: 1 internal, 1 local`, 32 s) and the disk cache directory held 0 entries (runs `a-cold`, `a-warm`, and the first akteursnetz run).
   - Cause: `.bazelignore` removes `s` from the execroot symlink forest (`ls ob/execroot/_main` has no `s`), so Bazel cannot stat the declared inputs after a non-sandboxed action and treats them as modified; the guard suppresses action-cache and disk-cache writes.
   - Fix (verified): stop writing `.bazelignore`, remove a stale one. Run `a-cold2`: no warning, `s` in the execroot, 8 disk entries, warm run 100 % hit (all later series). Query replacement: `bazel query //:all --output=label_kind` (all rules live in the root package) answers in 0.4 s without crawling `s`. Anything that used `//...` or `rdeps(//...)` (bzl-ops affected parity) must use `//:all`.
   - Patch: in `B/📜️script.ts` `linkBazelSources`, replace `await writeChanged(join(workspace,".bazelignore"),actions.sources.link+"\n");` by `await rm(join(workspace,".bazelignore"),{force:true});` and fix its docstring. Test to add (env-gated real binary): after one build of a task, no `Skipping uploading` in the output and `find <disk_cache> -type f` greater than 1.
2. Emoji target names crash the task runtime. 108 of 8,021 targets (all `🏭️generator*` of `fixture-generator-*`) die in `executeTask`: `error: Closed store receipt target required` (`B/../🧾️store-receipt/🟨️.mjs`, `storeReceiptOutputV1` validates `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$` before checking whether the task declares a receipt at all).
   - Fix (verified): `declaredStoreReceiptV1` returns `undefined` first when no declared output lies under `{projectRoot}/.🧾️store/`. `staged/store-receipt.mjs` is the patched copy (generated by `stage.ts`); the generators then start (they fail later for their own reasons: `cargo build --release --offline`, missing `⬅️before.json` fixture).
   - Test: `staged/store-receipt.test.ts`, 6 rows incl. emoji and 129-char names, Python `re.fullmatch` oracle: `bun test ./.🧬semio/.../bzl-real-tools/staged/store-receipt.test.ts` 6 pass.

Touching a file the action imports but that no declared pattern covers never rebuilds (Q7, Q8). Measured with `bun build --metafile` against `bazelTaskInputsV1` patterns minus the captured implementation closure (`undeclared.ts`):
| Task | modules in the entry script's import closure | not covered by declared inputs | not covered and not in the captured implementation |
|---|---|---|---|
| T1 | 111 | 106 | 4 (`routing/🟦️.ts`, `cargo/🟦️.ts`, `execution/🟦️.ts` of `framework/📦️packages/🟦️typescript/🏃️process/`, layout `rust-package-commands/🟦️.ts`) |

The ones inside the captured implementation closure are covered indirectly (the 5.9 MB `implementation.json` is an input of every action), so editing them re-keys everything. Fix direction (G5): derive inputs from the script's import closure (metafile at generation time) or declare the framework package dirs; `cache: true` targets should not be trusted until then.

## Observations
- Per invocation the harness spends 10-15 s regenerating workspace and fingerprints (about 100 s for the 3,892-input chain), versus 0.4-1.7 s Bazel time for pure hits: generation, not Bazel, dominates warm runs. A stable workspace with `writeChanged` plus memoised `sourceIdentity` is the lever.
- Tasks produce a tree artifact `*.snapshot` (`snapshot.json`, 37 bytes for no-output tasks); equal snapshots give the early cutoff seen in Q3.
- The first akteursnetz run reported 254 s critical path under load vs 120 s later: wall times are load dependent.
