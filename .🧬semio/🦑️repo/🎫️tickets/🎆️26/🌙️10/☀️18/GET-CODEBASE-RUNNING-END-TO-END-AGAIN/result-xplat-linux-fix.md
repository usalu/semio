## 2. Statfs on a directory partition (new class, found while checking the space consumers)

`statfs(<partition root>)` was a macOS-image truth: on a Linux or Windows directory partition it answers the **host disk** that merely stores the directories (and Bun's `fs.statfs` is unproven on Windows, `result-xplat-win2.md` open item 4). About 30 call sites decide headroom, retention, admission and "bytes built" from it. **g2** adds `nativeStatfsV1`/`nativeStatfsSyncV1` (`🌐️platform/📋️contract/📐️statfs`): below a partition root (`fixed.dir` beside `m`) they answer the declared envelope minus the shared measured usage, in number and bigint form, `fresh` for before-and-after deltas, a young measurement as is, an old one while one shared walk refreshes it; everywhere else the host answer, on Windows the free space of the volume without statfs. `nativeImageUsedBytesV1`/`nativeImageSpaceV1` use the same cell with the derived bound. **g11** migrates the 12 consumers that ask about partition roots (component pass headroom, compiler-state volume, compiler capacity and recovery, Nx SDK clone and derivative, tools, retention, graph inputs ledger and storage, Nx budget) and pins them with a site law; the darwin-only sites (`🍎️image`, macOS receiver) and lease directories stay raw on purpose. **g10** (cache-gc) replaces the macOS-only "mounted = device differs" test and the `fixed.dmg` constant by the native protocol (attached = anchor beside `m` and `m` holds the volume; capacity = envelope), and **g12** (conc-deps) makes `concurrentFreeBytesV1`/`FractionV1` fresh and async, because a free-space delta on the host disk of a directory partition is noise (5 call sites).
