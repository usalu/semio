## 1. Batch `rowid`: answer the `runtime` rows of the plan witness without a door
Cause: every plan-reuse check re-runs the recorded `x` rows (`ports.runtime` in `prepareBazelPlanReuseV1`), each one a full `bun exec "repo tools exec --light …"` process chain (door boot, tool registry, the tool): course hot = `bun --version`, `node -p "process.platform.concat(process.arch)"`, `node --version` = 3 children x ~60 MB RSS, 0.24-0.63 s wall in parallel (measured `rowid-bench.ts` on mirror under load 19: 635 ms wall for the 2 nx.json rows, 315-634 ms per child) and the 18-process moment behind the 1.68 GB peak of g29-hot3.
Design (schema-first `🌿️environment/🔏️identity/🧬️schema/🔣️.json`): a row whose output is a pure function of the executable (the closed list `Policy.rows`: `node --version`, `node -p "process.platform.concat(process.arch)"`, `bun --version`; `rustc -vV`/`cargo --version` are NOT listed: rustup proxies depend on `rust-toolchain.toml`) gets an IDENTITY = sha256 of {platform, arch, tool, arguments, locator source, prefix, and for the runtime that starts the child, the resolved program and every script word: resolved path, real path, size, mtimeNs, ctimeNs, ino, mode}. The planner records the identity in the witness SUBJECT (`runtime\0mode\0identity`, measured before AND after the run, equal or not recorded); the recheck compares the same identity in-process (tool registry resolution + 3 `stat`s = 0.5 ms for all rows) and answers `holds` without a child; changed identity (binary rewritten/replaced/touched/chmod'ed, other program on PATH) or a subject without identity (unlisted row, old receipt) runs the old child and compares the digest. Shell syntax outside words and double quotes in a row text => no identity (`$`, backquote, `'`, `;`, `|`, redirects), so a row is never judged by a word list it was not parsed from.
Laws (`🌿️environment/🔏️identity/🧪️tests`, 5 pass): listed/unlisted corpus incl. the repository's own nx.json rows + Python `shlex` oracle on every word list; identity changes under touch / equal-size rewrite / append / chmod / replace-by-rename / runtime touch / other program / missing program; independent Python digest (os.stat + hashlib) equals the TS digest; counting runner: unchanged identity => 0 child processes over repeated checks, changed identity => exactly 1 run, digest compared (same output true, other output false), wrong mode false without a run, subject without identity runs; identity that moves during the run is not recorded; real registry: the authored rows are identified, stable, distinct, and a `node` earlier on PATH changes the identity. Negative control: statFields reduced to `size` => 3 of 5 laws fail.

## 3. Batch `memolist`: a content edit of an unread sibling no longer makes the memo replan
Cause (hotpath finding 08:32, measured again on generation 619 with the course plan, `memolist/classstats.ts`, read-only): the relevance said "a row lying directly inside ANY directory of the relevance is relevant", because one of its facts might list that directory. The course slice has 157k such directories (216k fact rows), 79,351 of them frontier directories; so a peer that touches any file in a directory the course merely reads one file of, or merely lists, forced the 15-25 s graph replan.
Design (the planner's own proof, `stableDirectoriesV1`: "an entry appears, vanishes or changes type only by changing its parent"): the frontier of the pinned generation holds per directory the entry stamp `[mtimeMs, ino]` captured with the facts. The sidecar now keeps the three sets names / strict / stamped (`SMR3`) and a stamp table (`.lst`, 24 bytes per stamped directory: hash, mtime, inode):
  - names: every entry some fact read, every directory above it (as before), the frontier directories and the frontier members (a row naming one is relevant).
  - strict (old rule: every row directly inside is relevant, except the modification of a directory): directories a resolution or derived fact names (and their parents), directories read by a symbolic-link-following listing (`directories`), listings of directories WITHOUT a usable stamp (not in the frontier, or touched within the 2 s racy window of the capture).
  - stamped: the other frontier directories. A row that adds, removes or renames a name directly inside is relevant; a row that only says `modified` (the kind is advisory: FSEvents folds create+remove into `m`) is PENDING and settled by ONE `lstat` against the stamp (same inode, same mtime, directory). A sibling whose content was edited in place leaves the directory mtime alone => served; any create/delete/rename (also an atomic save, a lock directory) moved the mtime => `changed`.
  - fail closed: a missing/tampered stamp table, a directory without a record, a table of other folding => `generation`/`changed`.
Live generation 619, course slice (read-only, `classstats.ts`): names 174,988 (157,165 + 27,079 members - overlap), strict 51,345, stamped 77,373 of 79,351 frontier directories; stamp table 1.86 MB, relevance file 2.43 MB (was 1.26 MB). Hit cost: unpack 2.4 MB + one lstat per pending directory.
Laws (`🧠️memo/🧪️tests`, 9 pass incl. the REAL FSEvents watcher law with the built `semio-repo-watch`; slice 2/2; suites 7/7; tsc clean on the 5 files + command + slice test):
