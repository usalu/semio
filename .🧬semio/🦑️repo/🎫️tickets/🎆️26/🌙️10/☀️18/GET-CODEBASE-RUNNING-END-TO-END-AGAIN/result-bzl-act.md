## What changed (gap by gap)
- G5 tags: actions now carry `no-remote-exec` only, plus `no-sandbox` where `host_state` is set, plus `no-cache` only when `cache=False` with a mandatory `uncached_reason` (Starlark `fail`s without one). `local` and `no-remote` are gone. Cacheable by default: `cache !== false` and not continuous and not `skipCache`. Reasons (schema enum): `continuous`, `declared` (target says `cache:false`), `skipped` (invocation `--skip-nx-cache`-equivalent).
- No-sandbox, stated exactly (schema `Actions.kinds`, rendered into every rule as `host_state`): (a) task actions run the task process in the real checkout (cwd, declared source-tree and shared-store writes, loopback control socket, out-of-tree runtime channel); (b) launcher action: action birth binds exact execroot output paths and obtains authority over the control socket, which a sandbox execroot changes. Pure ordering tasks are the only hermetic kind and no longer spawn anything (see below).
- G6/G7 inputs: every cacheable task action declares its source closure as Bazel inputs: `srcs` = `filegroup` (deduplicated by file-set hash) of in-package labels `s/<path>`, where `s` is a symlink/junction from the generated package to the checkout. Selection reuses the nx-style resolved `inputs` (named inputs, `^` expansion, globs, `!` exclusions); object inputs are expanded in the Bazel path: `externalDependencies` -> `bun.lock` + `package.json` as declared files; `dependentTasksOutputFiles` -> dependency snapshot outputs as action inputs (transitive closure when `transitive:true`); `runtime`/`env` stay in the fingerprint. Paths Bazel cannot name (label-unsafe name, directory, dangling/dir symlink, under a nested BUILD package) are hashed into the fingerprint instead. Uncached tasks skip source declaration (they always rerun; fingerprint carries a nonce).
- Fingerprint (`.input`) is now only the derived non-file identity: host platform/arch/bun version/build mode, declared env + runtime commands, the hashed fallback paths, nonce for uncached. `task` JSON and per-file hashing left it (manifest and Bazel inputs carry them). Matching is precompiled per pattern with a literal-prefix prefilter and memoized per distinct input list (the old code built a `Bun.Glob` per file and pattern).
- G8 stable key: manifest = `{version, task, implementation:{version,sha256,loaderSha256}, orchestration?}` (schema `Manifest`, closed; no workspace, runtime or snapshot paths). The live data moved to `W/runtime.json` = `{version, workspace, environment}` (schema `Runtime`), located by the action at run time from its own manifest's real path. Not in any key.
- G9 outputs/restore: still one declared tree-artifact output per task (`<label>.snapshot`). Consumers take only producers' outputs: pure `noop` tasks are elided (their producers become the inputs; unselected noops are never emitted; a selected noop becomes a `repo_noop` marker rule with `ctx.actions.write`, no process). `transitive:true` consumers also get the transitive producers. Final restore into the source tree happens only for `plan.selected` task actions (intermediates are restored only inside the consuming action, which runs in the checkout). Birth grants use the same restore list and order.
- G11: `no-remote` dropped. `skipRemoteCache`/remote switches now come from bzl-cache's `bazelCacheFlagsV1` (see below).
- bzl-cache requests: removed `--batch` from the run startup (module-catalog setup still uses `--batch`, one-shot by design); cache flags and per-workspace `--output_base` from `bazelCacheFlagsV1(storage.paths, workspace, {environment, skipCache, skipRemoteCache})`; deleted the per-label launch `--output_base` and `launchBin` (launch deps use the shared `bin`; launcher grant is the single `[bin/label]` vector); added `--incompatible_strict_action_env` (PATH no longer enters the key).
- G16: satisfied by the shared per-workspace output base (continuous `bazel run` tasks now share the build's server). Not run.

## Open items / risks for the first real run (coordinator)
1. UNVERIFIED, highest risk: Bazel labels containing emoji (U+FE0F) and the runner label `📜️script.ts` (that one pre-existed). Schema `Actions.sources.label` admits `\u0080-￿`. If Bazel rejects them, change that single regex to ASCII-only: every non-ASCII path then falls back to fingerprint hashing (correct, just not natively declared). A 5-minute check: scratch workspace with `s -> a dir containing 🧰️x/📋️a.json`, a rule with `srcs=["s/🧰️x/📋️a.json"]`, `bazel build` with the pinned binary. I did not run it (host memory).
2. A nested `BUILD`/`BUILD.bazel` between `s` and a file is detected on disk and demoted to hashing; a `BUILD.bazel` at the checkout root would demote everything (none exists).
3. Targets with no `cache` key are now cacheable by default. Targets that generate files without declaring `outputs` and relied on rerunning need `cache:false` (bzl-man). Explicit `cache:false` targets (course `build`, `publish`, `test-e2e`, `typecheck`, proctor `build`) stay uncached with reason `declared`.
4. `dependentTasksOutputFiles` globs are not used to narrow action inputs (outputs are one tree artifact per task); consumers are invalidated by any output change of their producers.
5. Source-tree files that are both declared inputs and rewritten by another task in the same build can trip Bazel's concurrent-change guard (default `lite`); gitignored outputs (`dist/`, `target/`) are not enumerated, so the common case is safe.
6. Reset (`bazel/outputs` now holds live server bases) must stop servers first (bzl-cache note 6, not mine).
7. Remote cache with `no-sandbox` actions that mutate the checkout: results restore through the snapshot only; requires the key to cover everything read. Fingerprint covers host/bun/env/runtime; Windows/Linux not run.
