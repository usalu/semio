## 0. Verdict

1. **Root cause of the serialization.** Any source edit stales the single all-workspace seal; the only way back is one exclusive writer (`repository-graph-facts:<ws>`, held for the whole rebuild) that re-reads 3,656 records, assembles and writes a 431 MB monolith. Every other agent queues behind it, even for projects nobody touched.
2. **Design (schema-first, language-agnostic, tool-neutral).** The graph becomes a chain of immutable *generations*: `current.json` (pointer) -> manifest (owner table + digests) -> one content-addressed *fragment* per owner (neutral node, outgoing edges, module facts) + one *fact index* (every distinct observation row once; rows grouped into classes that share exactly the same consumers). All documents are written before the pointer flips; the pointer swap is one compare-and-swap.
   - **(1) Incremental.** Verification is O(distinct facts): the index rows are checked in chunks (bisection finds the exact stale rows), a stale row names its consumers through its class, so an edit in A dirties A (+ every owner that consumed the same fact), never the whole seal. Edges that consult it: owner edges carry `edgesEnv`; an *environment digest* (owner table, package names, Go modules, workspace manifests, lock, taxonomy) moves only when an edge of an unrelated owner may change, and then only edges are recomputed on the stored nodes. Membership is proven by a *frontier* (stamps of ~15 k directories + modes of ~33 k members, a stat pass, racy window 2 s) instead of a tree walk; a change is mapped to its owner through the manifest roots. Compute runs the real inference (`discoverBuildGraphPartV1`) only for the dirty roots (`ownerRoots` filter in project-nodes) in ONE call, so the shared import/command closure is walked once per build, not per project.
   - **(2) MVCC.** Readers take no writer and no lease: `read()` = pointer + manifest, retried if a retired manifest is raced, always one complete generation. A writer builds the next generation from the previous one plus the dirty set and publishes by CAS on the generation number. Writers coalesce: they queue on one builder custody (selection scope `sha256("semio-graph-generations-v1")`, shard lease), the holder re-plans first and returns the peer's generation if the work is done. Policy `--graph-policy=fresh|current` (see 5): `current` serves the newest sealed generation at once and never waits; `fresh` verifies, serves a verified generation without any lease and queues only when something it needs is dirty.
   - **(3) Lazy closure.** `refreshClosure(roots)` collects the closure through fragments and verifies only the classes of those owners (+ `@env`); an edit outside never waits or recomputes (law test: no `src` row of an unrelated project is checked). Assembly and `portableInputs` expansion touch only the closure (`show project <name>` uses it). Task selections (`run X`) stay with x-graph's closure admission, see 6.
   - **(4) Bounded facts hold.** The global `repository-graph-facts:<ws>` is no longer held during a build at all; it is acquired exclusively only inside `publish` (one pointer read + one rename, timeout 30 s). Lock order S(shard) -> B(build-graph-state) -> G(facts CAS), G last. Law test: a 300 ms build holds `build` >= 290 ms and `facts` < 100 ms (measured single-digit ms).
3. **Correctness laws (all executable, see 2).** An edit in A never yields a stale graph for A (every fresh read verifies the facts that A consumed; the plan is re-run under the builder; a peer's generation is adopted only after it verifies). A reader never sees a torn generation (24 concurrent readers during 14 publishes: each result equals the sequentially computed reference graph of exactly its generation, monotone per reader; also with aggressive retirement). Missing fragment/index/manifest self-heal (owner recomputed / cold start); a tampered or mismatched document fails closed.

## 8. READY3: converge while peers edit (settle, volatile files, per-project keys, fact table)

Root cause (read from the code): the all-graph `nodes` pass is one `observeInference` record wrapped in `settleObservedComputationV1`; a round is repeated while the facts of different projects contradict (a shared file read at two states) and every round re-infers every project whose image no longer holds. Independently, the command-closure walker (`script-inputs` `visit`, `targetScriptSources`) reads every closure member, JSON leaf and entry script with `readPhysicalSource`, which records a CONTENT row (`file`, sha256), so any edit of any file of the shared CLI closure stales all ~670 native records even when no import changed, and `📈️progress.json` is such a leaf through `import ... with {type:"json"}`.

1. **Snapshot-consistent publication, dirty set for the next generation (never a restart).** A partial pass (`ownerRoots`) now bypasses the outer record and the settle loop: `invokeCurrentImplementationV1` runs `observeInferenceSnapshotV1` (new, `👁️observation`), which only provides the nested project scopes. Each project is consistent with the facts of its own record; contradictions between projects are legitimate; a project that raced an edit is simply not persisted, returned with the rows it read, published in the generation, and stale in the next verification, which is exactly the dirty set of the next generation (`plan` derives it from the fact index). Law test on the real observation module: project `a` reads the shared file, the file is edited, `b` reads the new state, one pass returns `["1a","2b"]`; the next pass recomputes only `a` (counts a=2, b=1).
2. **Closure-scoped, bounded settle.** What remains of rounds is the edge pass (`observeDependencies`, limit 64, cached analyses, edges of the dirty owners only). No owner is retried by the store; the next `fresh` read refreshes only the owners whose consumed rows moved.
3. **Volatile files are not inference inputs.** Instead of a per-file skip list, the walker's three `readPhysicalSource` calls on closure members, data leaves and entry scripts became `requirePhysicalSourceV1` (real ancestors, regular file, no content row; recorded as type facts only). Code files are consumed through their `analysis` fact, which holds while the imports are unchanged, so a body edit of any closure file, a JSON/asset leaf such as `progress.json`, a label, a schema no longer stales a record; an import change still does, correctly. This is more general than graph-speed's `presentationResources` skip and byte-disjoint from it (it touches the same walker lines `visit`; graph-speed's anchor avoids the destructuring lines, apply either order and drop its one-line skip as redundant). Proven on the real observation module: a shape fact survives an edit of the bytes, a content fact does not.
4. **Per-project keys by what is consumed.** `commandRevision` is the digest of the closure's PATH list, not of its bytes (`nativeCommandInputs`), and the target token `SEMIO_SOURCE_CLOSURE_<key>` is the digest of the path list too; task-time hashing reads the bytes (`digestClosure`). With content rows gone the revision and the tokens move only when the import structure of the closure changes, which changes every native target's input list for real. Nothing else keys a native record by the shared closure.
5. **Shared fact table (absorbed from graph-speed).** Record header v2 in `👁️observation`: `{"digest","resultSha256","authorityObservations","blocks":[sha256…],"observations":[inline rows]}`. The rows of a record are cut into content-defined blocks (a cut after every row whose key hash hits a 7-bit mask once a block holds 32 rows, at most 4,096), written as brotli leaves `np/<24 hex>.json` (existing optional-path grammar) BEFORE the record that names them, verified against their digest on read, interned once per process; a block the quota refuses stays inline, a bad block is removed and the record recomputes (tested in a fresh process). Identical closure runs of thousands of projects become the same block files, so the 988 command-import + 988 command-reference rows (and the 6x analysis rows) are stored once per closure, not per project; the census (`seal`) reads blocks, the record-header test and schema follow. Header size is bounded by `blocks x 64 B` (test: header < blocks x 80 + 2 KB; 400 shared rows -> 2+ shared blocks, B reuses A's blocks). The in-memory fact index of the generation already deduplicates by row and consumer class.
6. **Concurrent-editor proof (overlay, synthetic 300-project world, 8 ms per project).** A writer rewrites the shared file every 250 ms while the cold build runs: exactly one inference pass (no restart), published generation 0 within 1.2 x the quiet time (+0.5 s slack, quiet = the slower of two quiet runs; load 20-40 made quiet runs vary 5.8-8 s), owners carry at least 3 distinct file states, then the next refresh recomputes EXACTLY the owners that read an older file, then verified clean, final graph = the Python oracle.

Verification added: closure-facts suite 19 (text laws + independent Python model + real observation primitives + blocks), generations suite 23, record-header 2, seal facts 5, observation `-t semantic` 12 of 13 in the scratch overlay (the 13th, `retain exact evaluated inference ownership`, needs real ancestry of `🛍️products/💻️os` and passes on the live tree), mutation proof 22 (4 new: content-row reads, settling partial pass, repeated rows, trusted bad block). Not verified live: the partial pass over the real inference, the block format under a real cold build (record count, header size), disk growth of `np/` blocks (expect ~ distinct blocks x 20 KB).

## 9. Implementation pinning (applied live, 2026-10-21)

A build completes with the implementation it loaded. An edit of any implementation file never aborts a running build; the next fresh load refreshes only the projects that consumed the edited module.

- **Pin** (`revision` module): `withImplementationPinV1(body)` / `implementationPinnedV1()` (process-wide, nesting, released on failure). While pinned, all 12 "Stale loaded ...; restart required" self-checks return (revision reader, inventory, exact reader, graph consumer, inference reuse, observation, rust assembly, 4 cargo readers, repository Store) and so do G's `requireCurrentGraphModuleV1` and `requireCurrentGraphReadPoliciesV1`; the inference `implementationRevision()` keeps the revision it computed first (no mid-build hot swap, no re-read of implementation files). Pinned scopes: the CLI door (`runAdmittedBuildCliV1`), `runOwnedBuildInvocationV1`, and the generation branch of `loadBuildGraphV1`. The strict path (baseline, `reuse`, selected graphs) is unchanged.
- **Stamp**: `identity` = registry only. The manifest carries `implementation` (digest of the loaded bytes of 25 graph files + 63 inference files). A manifest of another format is no generation (cold start, no migration).
- **Per-module keys**: each fragment owns `digest` facts (workspace relative path, sha256, size, mtime) of the modules it consumed, in the fact index like every other fact (rows interned once, classes of identical consumers): inert modules (ledger) are not consumed, node shaping modules (project-nodes, target-policy, playground/component targets, generator outputs) by valid projects, every other module by every project, every unavailable project and the environment. The table is `GENERATION_POLICY_V1.implementation` (schema `Policy`); narrowing it further is a one-line edit.
- **Policies**: `current` serves any generation of the registry identity (message `stale` when its stamp differs from the reader's loaded implementation, EN/DE); `fresh` verifies the rows and refreshes exactly the consumers of an edited module; a reader that loaded an older implementation than the one on disk finds the generation of the newer one verified and serves it.
- **Proof** (`🔌️load/🧪️tests`, `🕰️generations/🧪️tests`, `🧪️tests/🕰️generation-protocol`, `🔏️revision/🧪️tests`): scoping vectors against a Python model (6), shaping vector (1), scoped-refresh scenario (inert 0, nodes 10 of 12, shared 12; stale-but-usable and verified-older-reader), 300 projects (30 unavailable) built while an editor rewrites a node module every 250 ms (scaled from 60 s): one pass, published, within 1.2x quiet time + 0.5 s, stamped with the loaded digest, next fresh load refreshes exactly the 270 valid projects, the following one nothing; store stamp/format test; revision pin test on a copied reader (stale outside, finishes inside); text laws (every self-check site guarded; the host identity never contains the authority). 11 new mutations, all killed.
- **Tool**: `conc-graph-tools/pin-fix.py` (anchored, idempotent, `--root`, dry run by default). Staged copies synced; `apply.py check` still reports drift of files peers changed (invocation, help, closure-facts).
- **Hazard**: `🧪️tests/🕸️graph/📌️pinned-publication` mounts a disk image under its own directory; never run it on an overlay (a mount survives a failing run, `diskutil eject` it).
- **Still staged, not applied**: `revision-fix.py` (stale-reader recovery of `current()` on size-bound refusal).
