### 🧪️ Test sandbox

Tests of many agents run at the same time on one machine, so a test must not share anything mutable with another run. Before the sandbox, 21 sites in 12 test files used the generated folder of an old ticket as their scratch root inside the checkout, `repoTestArtifactEnvironment` defaulted to one fixed route in the real cache that every concurrent run of the same route shared, 19 tests used constant names below the temporary directory, and 10 tests probed a port, closed it and bound the number later, which races between agents. A killed run also left an attached disk image whose backing file lay inside the checkout, where nothing ever reclaimed it. State: {{@sandbox}}.

- **One API.** `createTestSandboxV1`, `withTestSandboxV1`, `testSandboxEnvironmentV1` and `testScratchRootV1` in `🧰️framework/🔨️modules/🏃️process/🧪️testing/🏖️sandbox` (re-exported by the package export `./test-execution`). A sandbox is a private root `<tmpdir>/st/<8 hex>` (mode 0700, length bounded) with `artifacts/<route>`, `tmp`, `images` and `cache`, and an `owner.json` whose heartbeat is refreshed every 30 s. The environment carries `SEMIO_TEST_SANDBOX`, `SEMIO_TEST_ARTIFACT_DIR`, `SEMIO_TEST_IMAGE_ROOT`, `SEMIO_TEST_CACHE_ROOT`, `SEMIO_TEST_CHECKOUT_ROOT`, `SEMIO_TEST_GUARD`, `SEMIO_TEST_GUARD_REPORT` and `TMPDIR`, `TMP` and `TEMP`. Nested runs adopt the parent's sandbox.
- **It is automatic.** `runBudgetedTestCommand`, the one spawn point of Bun, Node and Go test commands, runs every child inside a per-run sandbox, so `repo run <project>:test` needs nothing from you; with no configured `SEMIO_TEST_ARTIFACT_DIR` the artifact directory is the one of the run's sandbox. Cargo test commands go through the Cargo launcher and get only that store's own `TMPDIR` handling. Go tests were already hermetic (17 owners run under `sandbox.Run`, a temporary git repository as root and working directory).
- **Disposal and reclaim.** The sandbox is disposed by `dispose()`, at process exit and in Bun's `afterAll` (a `bun test` process ends without running exit handlers, so `afterAll` is the one that counts): images below the root are detached, ports are released, the directory is removed. The next sandbox creation (at most every 5 minutes) detaches the images of and removes every sandbox whose owner process is dead or whose heartbeat is older than 1 hour, and reclaims stale port leases. The root and `TMPDIR` lie below the scratch roots of the boot sweep, so an image that even this misses is detached by its 15-minute idle sweep.
- **Ports.** `reservePort()` takes an atomic lease directory per port in the range 49152 to 65000, shared by every sandbox of the machine, bind-checks it and releases it on disposal. Never listen on a literal number and never probe and rebind.
- **The law.** `🧪️testing/🏖️sandbox/🧪️tests/⚖️law` scans the test sources of every manifest-owned directory (23 rules in TypeScript, Go, Rust, Python and shell, with English and German messages): writes into the real checkout, fixed temporary names, `process.cwd()` writers, disk-image and kill commands on non-sandbox paths, fixed ports, probe-then-rebind. Its error findings must equal the ledger `🧪️testing/🏖️sandbox/🧪️tests/🧫️fixtures/📒️ledger.json` exactly: a new violator fails, and a fixed one fails until its row is removed, so the ledger only shrinks. 31 rows remain, each with its reason (scratch that must lie below the workspace, the vitest lane, Rust fixed-name tests, the mcp adapters that build into the shared binary cache). The TypeScript scanner and a separate Python reference produce the same 1,042 findings over the tree, and ripgrep marks the same lines for every line rule.
- **Runtime guard.** `SEMIO_TEST_GUARD=off|report|enforce` (default `off`) preloads a shim for `node:fs`, `node:fs/promises` and `node:child_process` imports of repository TypeScript. It refuses or records writes inside the real checkout (`.cache`, `.🧬semio`, `.git`, `node_modules` are protected; `.cache/b/o/m/tests` is allowed), `hdiutil` and `diskutil` verbs on non-sandbox paths, `pkill` and `killall`, and fixed ports that the sandbox did not lease. Rows are JSONL (schema `GuardReportRow`) and summarised when the sandbox is disposed. Run a sample with `SEMIO_TEST_GUARD=report repo run <project>:test` and read the report before turning enforcement on; the default stays `off` until the loader rewrite has run across the 2,175 suites.
- **Verified** with 16 sandbox tests (349 expectations: 12 ports across two sandboxes and three child processes all distinct, a SIGKILLed child with an attached image reclaimed by the next sweep, the guard in both modes) and the law; the five envelope-gated converted suites and the whole battery under `report` were not run, nor Windows and Linux.
