## Decisions (why nothing else was replaced this wave)
- serde / serde_json (dashboard 26/24, print 104/45): the root cause is the first-party value layer itself (`🌱️value` re-exports `serde` and `serde_json`, implements `Serialize/Deserialize/From<serde_json::Value>` for `DslValue`; 4,929 Rust files repo wide name serde_json, 2,910 name Serialize/Deserialize). Dashboard alone holds ~2,100 serde related lines in non-test sources (model 850, events 176, tree 147, registry 110, tickets 101, ...). A closure can only shed the identity when the value layer does, hence the wave order is: (1) value layer serde-free behind an optional `serde` feature, (2) `semio-framework-value` derive + `pack-json` for the 24 dashboard crates (mechanical), (3) the 45/104 print crates, each with its `:test`. Not startable safely while 10 other lanes build on the same crates.
- tokio / tokio-tungstenite / futures / ureq (print only, 6/2/2/2 OS crates): native sync transports (websocket with rustls-webpki-roots TLS, blocking HTTP). Needs a first-party websocket + TLS binding; they are already behind the transport interfaces (optional `ureq` feature; `tokio::net`+`tungstenite` only in `sync/🖥️native`).
- rustybuzz (1 crate): no in-repo OpenType shaper. libc (1): system ABI binding behind the owned terminal backend. wasm-bindgen/js-sys/web-sys/wit-bindgen/proc-macro2/quote/syn: toolchain bindings.
- react-resizable-panels (and @dnd-kit, @xyflow): candidates for the next first-party UI-element wave (`↔️Resizable` wrapper already isolates Group/Panel/Separator; the Canvas dock still imports `ResizablePrimitive.GroupImperativeHandle` directly in 4 files, which must first become an owned handle type). Not started: it rewrites live ui-react Canvas behaviour while e2e-f runs the 76-spec course matrix on it.
- sharp / @napi-rs/canvas / pdfjs-dist (print): used by the print PDF panel worker (`tectonic-template-compilation/🪟️panels`) and PDF measurement scripts at build time, plus as test oracles in ~20 test files; stay declared where the worker lives.
- tailwindcss / @tailwindcss/typography: build-time adapter in `🎨️styling/💨️tailwind`; moving them to devDependencies only relabels them (the gate classifies by manifest section) and could drop them from the Bazel/Nx input closure of course builds, so not done.
