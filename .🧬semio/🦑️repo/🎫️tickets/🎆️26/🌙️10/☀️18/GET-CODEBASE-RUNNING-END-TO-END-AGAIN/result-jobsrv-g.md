## Finding (what was and was not broken)
- Cargo hands its pool down in two styles. The repository launcher gives Cargo a first-party FIFO pool (`createJobserverV1`: fifo on POSIX, named semaphore on Windows; `MAKEFLAGS=-jN --jobserver-auth=fifo:PATH`) and Cargo passes `CARGO_MAKEFLAGS=-j --jobserver-fds=fifo:P --jobserver-auth=fifo:P` on: pure environment, so the shimmed build scripts already shared that pool. A pool made by Cargo itself or by any other parent is an anonymous PIPE (`--jobserver-auth=3,5`; descriptors, not environment): the build script stand-in (a `#!bun` script) did not hand the descriptors to the real build script, whose `cc` then found stale numbers, made a PRIVATE pool of `NUM_JOBS` and ran that many compilers per script. Measured 16 concurrent compile jobs under a grant of 4 (below). A second, silent hazard: rustc and `cc` with an unreachable pool also invent one (rustc 32 slots, `cc` `NUM_JOBS`).
- `try_acquire` is unsupported on pipe clients on macOS in the `jobserver` crate (0.1.35); `available()` (FIONREAD) is the only way to count pipe tokens there and returns 0 on a macOS fifo: the probe uses `try_acquire` and falls back to `available`.

## Design (staged; unit-cache only)
- NEW `🎰️jobserver/🟦️.ts` (light, no heavy imports: it runs on the hot path of every rustc call): `jobserverAuthV1` and `jobserverEndpointV1` classify the named pool with the grammar of the `jobserver` crate (first SET variable of CARGO_MAKEFLAGS, MAKEFLAGS, MFLAGS decides; last `--jobserver-auth=` wins over `--jobserver-fds=`; value ends at the first space) into none / pipe / fifo / semaphore (Windows: any name) / closed (malformed, disabled = GNU make negative pair, not-inherited, out-of-range above fd 63, missing-fifo). `jobserverPlanV1` decides per child: an OPEN pipe pair (proven by the sh stand-in's census, never by the runtime's own `fstat`) is handed on under the same numbers (`jobserverStdioV1`), fifo / semaphore / none need nothing (environment is inherited), a closed pool is REPLACED by an empty first-party fifo (`<cache>/bin/jobserver-empty`, `emptyPoolV1`, made once with `mkfifo`, atomic rename) plus `-j1` and `NUM_JOBS=1`, so the command runs on its own implicit slot (serial) instead of inventing parallelism, and a bilingual EN+DE notice goes to stderr. No token is ever consumed by a stand-in (the child works on the implicit slot of the job Cargo started), so a pool without tokens cannot deadlock: clients holding their implicit slot never block on `acquire`. `jobserverProbeShellV1` is the one shared sh prologue.
- `🏗️buildscript/🟦️.ts`: the build-script stand-in is now a `/bin/sh` script (marker on line 2) that runs the shared prologue BEFORE the runtime starts and then `exec`s this module as a script (`runBuildScriptMainV1`); `runReal` takes descriptors/environment from the plan. The whitespace refusal for the runtime path is gone (the path is quoted). `📜️script.ts` `run` uses the same plan (the `jobserverDescriptorsV1` export is replaced). `🚪️launch/🟦️.ts` `unitCacheShimSourceV1` uses the shared prologue (`MFLAGS` fallback and the set-ness rule added). Schema: message `jobserverClosed` (EN+DE). Windows: no stand-in for build scripts (platform list darwin/linux), the native wrapper passes the environment through, so Cargo's named semaphore and the launcher's work unchanged; the classification and plan are pure and covered for `win32` by the fixture.
