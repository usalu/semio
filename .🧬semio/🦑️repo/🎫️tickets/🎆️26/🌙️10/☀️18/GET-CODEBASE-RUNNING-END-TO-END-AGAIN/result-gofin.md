### Real defects found by those suites and fixed (each with a regression test)
- `tree/🎊️query-cache` `ensureCacheIndexed` reused a persisted search index whenever the git fingerprint matched, so an index built from a tree without sections answered later section/definition/contributor queries with nothing. The meta field `IncludeSections` existed but was never written or compared; now derived from the tree and compared (`TestSearchIndexIsNotReusedAcrossSectionChoice`; fails without the fix, verified).
- `model` `Ticket.GetDateStarted` fallback used the two-digit year (`time.Date(26, ...)`), rendering every interaction-less ticket as "opened 292 years ago" (also in the client copy `🎟️ticket-model`). `TestTicketDateStartedFallsBackToTheTicketDay`.
- `cli` `ToolTicketList` dropped status (a named string, so `.(string)` failed), goal and prompt: MCP markdown differed from the CLI. `ToolPolicyList`/`ToolPolicyTree` listed in registration order, the CLI sorts. Added `sortedRegisteredPolicies` (`TestToolPolicyListIsSortedByIdentifier`); the exhaustive parity tests now pass.
- `graphql` `node(id)` could not resolve a Bundle although `Node` is a union containing it; added a bundle lookup before the technology prefix lookup (covered by `TestExhaustiveNodeQuery`). The Rust twin is untouched (cargo not allowed): parity of `node(<bundle id>)` is open there.
