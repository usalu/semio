## Findings (what the real runs showed)

1. **`bun repo tools setup nx` is broken on every OS right now.** `T/package.json` lists `@semio-tech/framework-filesystem: workspace:*` under `dependencies` (added 11:04 for the bare import in `T/🔏️authorizers/📦️runtime/🟦️.ts`); the closed `Recipe` schema of `T/📦️sdk/📥️source/📐️projection` only admits `x.y.z` pins, so the capture throws `Closed pinned dependency recipe required` (reproduced on macOS with `C/bzl-xplat-tools/diag-recipe.ts`: `/dependencies/@semio-tech/framework-filesystem must match ^[0-9]+\.[0-9]+\.[0-9]+$`). Staged fix: `nxExternalPinsV1` drops `workspace:*` links from the installer recipe in three places (`Recipe` pattern, `nxDependencyInstallFilesV1`, `nxToolingInstallManifestV1`) and from the post-install completeness loop. Proof: the new test fails without the schema line and passes with it.
2. **`tools setup nx` needs installed workspace links (fresh-clone blocker, not fixed).** After fix 1, a checkout without `node_modules` still stops at `Cannot find module '@semio-tech/framework-filesystem/observation/journal'` (authorizer capture uses `Bun.resolve`) and then `Cannot find module '@semio-tech/nx-bootstrap-tools/use'` (`L/⚡️caching/🕸️graph/🏁️startup/🚦️service`). With `node_modules/@semio-tech/*` symlinks for every workspace package (what `bun install` creates; `C/bzl-xplat-tools/linux/links.ts`) it ran to the end: `Nx Version: Local v23.2.0`, rc 0, 2 min 33 s, on Linux arm64. `setup` runs `deps-build-tools` (`tools setup all`) and `deps-js-all` as unordered siblings, and `.github/workflows/build-system.yml` runs `tools setup all` before `dependencies sync`, so a fresh clone has no links when nx is set up. Owner decision needed: order `deps-build-tools` after the JS install, or make the nx setup closure relative / resolve workspace specifiers from the authored workspace index instead of `Bun.resolve`.
3. **Non-ASCII `--install_base` crashes Bazel on Linux too** (exit 37, `ClassNotFoundException com.google.devtools.build.lib.bazel.Bazel`), under every locale tried (unset, POSIX, C, C.UTF-8, en_US.UTF-8). A non-ASCII output base, emoji source labels, emoji outputs and emoji tree artifacts build and cache fine on Linux under all five locales. The existing fixture row "emoji install and output base on Linux" asserted the opposite (accepted); staged: Linux guard on `install` only (`HostPaths.platforms.linux.guarded`), fixture rows replaced.
4. **Locale env is darwin-only** (Linux needs none: G5 of `audit-cross-platform-1019.md` closed by experiment).
5. **Sandbox:** `linux-sandbox` is not registered in an unprivileged container (default seccomp; also not with `seccomp=unconfined`, `apparmor=unconfined`); Bazel's default `sandboxed` strategy falls back to `processwrapper-sandbox`, which ran a sandboxed action. A `--privileged` container registers `linux-sandbox` and ran one. Naming `--spawn_strategy=linux-sandbox` explicitly is refused in a container, so the adapter must never name a strategy (it does not; the existing storage test already forbids it in `.bazelrc`).
6. **`--nowindows_enable_symlinks` is a startup option**, not a command option (`Unrecognized option` as a command flag; listed by `help startup_options`; accepted as startup option on Linux). `--[no]enable_runfiles` and `--[no]build_runfile_links` are command options.
7. **`--output_user_root` was dead weight** (`--output_base` and `--install_base` are always explicit). Without it a build works on Linux and macOS, and no `~/Library/Caches/bazel` is created (checked).
8. Existing suite `BZ/🧪️tests/📥️actions` asserts the execution-log runner is `darwin|linux-sandbox`; in the unprivileged devcontainer it is `processwrapper-sandbox` (1 fail of 12). Staged one-line regex fix (`(darwin|linux|processwrapper)-sandbox`).
9. Pins: all six OS/CPU pairs are covered for Bazel (schema `Release`), Bun (schema, plus musl rows) and the Nx native packages (`bun.lock` has sha512 integrity for darwin arm64/x64, linux arm64/x64 gnu+musl, win32 arm64/x64). The pinned Bazel sha256 of all six files equals the checksum published beside the upstream release (fetched from `releases.bazel.build`, 6 small `.sha256` texts, `SEMIO_TEST_NETWORK=1`). The pinned linux/arm64 binary (62,234,197 bytes) was downloaded in the container and matched its pin.
