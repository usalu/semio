- Planner feed: `testFileRatioBasisPointsV1` prices a cohort with its biggest declared file (`max(learned, declared/default)` only when above the default, so learning that shrinks is untouched) and feeds the existing `ratioBasisPoints` of `testWorkersV1("bun-test")`; fewer workers are started under a small grant.
- Memory gate (`createTestFileGateV1`): files of a cohort start in the order they ask, only while the megabytes held by the running ones (a file that holds more than its budget raises what the gate counts) plus the budget of the next fit the share the run was admitted; a file above the share runs alone. This is what keeps a forced worker count (override) from over-committing.
- Ceiling watch (`createTestFileWatchV1`): ONE process-table read per tick for all running files (1 s; `/proc` on Linux, `ps` on macOS, PowerShell on Windows), each file's tree summed with the existing `treeMegabytesV1`; above its ceiling the tree is terminated (new hook `onSpawn(pid, kill)` in `🎛️owned-execution/📥️capture`, three small edits; the capture answers the terminal signal like any killed child, NOT a refusal: a refusal would poison the shared phase and cancel the cohort), the file is reported failed with `[tests] <file> held 308 MB and was stopped at its ceiling of 150 MB (100 MB declared in the test file budgets)` (DE `belegte ... und wurde an seiner Obergrenze von ... angehalten`) and its siblings finish. The per-suite learning around the cohort (`withTestWorkerLearningV1`) still records the observed peak, so a suite that ran hot gets fewer workers next time ("recycled" = the next plan, not a restart).
- Switch: `SEMIO_TEST_FILE_CEILING=off` lifts every ceiling (planner and gate stay) for a run that must see a file finish; the guide names it.
