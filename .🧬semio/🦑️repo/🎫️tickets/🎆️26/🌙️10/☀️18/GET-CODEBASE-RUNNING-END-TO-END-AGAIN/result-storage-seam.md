## 3. Findings you need to know

1. **The directory partition cannot run on a default macOS volume.** Default APFS is case-insensitive and `allocateNativeDirectoryV1` refuses it (`caseInsensitive`) by design. Selecting it on macOS therefore needs a case-sensitive volume; the conformance suite creates a 256 MB `Case-sensitive APFS` image in its own sandbox root for that row. Default selection on macOS stays `mounted-image` (preference `kernel-quota`), so nothing changes for `.cache/b/*`.
2. A reservation `retire()` of an ordinary workspace allocation is not a supported path (the backend ports throw "writer/reader physical retirement custody required", and with the directory port the call did not settle); a partition holding committed allocations is refused retirement by design (`Original fixed image allocations still held`). The conformance suite therefore retires a spare, never-allocated partition.
3. The ownership model is declared in the same schema (`modules` per backend). Law test: neutral modules may reach a backend-owned module only through the registry; the **remaining entanglements are pinned in `🧪️tests/⚖️laws/🧫️fixtures/🔣️.json` (22 neutral->backend edges, 2 backend->backend edges) and may only shrink**: the shared directory primitives (`flushNativeDirectoryV1` in the recovery ledger/act, metadata, durability, retirement census, virtual statfs), the macOS leak sweeper in boot heal, the witness/silence/owners/information imports of the publication owner and `📤️publication/🌐️platform`, `cleanup/🎛️command` -> `🧱️fixed` (protected maintenance physical facts) and `🍎️image` -> `🧱️fixed` (retirement state helpers).
