## Item 1: cargo-backed script targets
1. **The cargo identity is not file based, by design.** `{"env":"SEMIO_CARGO_LOCK_<sha>"}` resolves at execution time to `cargoResolutionDigestInBatchV1` = `composeCargoResolutionV1(lock slice of the crate, workspace identity of every crate it compiles with, toolchain pin = rust-toolchain.toml, cargo configuration = .cargo/config.toml minus artifact-location keys)` (🏗️build/📥️inputs/🦀️resolution + 🧮️digest `taskEnvironments`). `resolution/🔣️.json` `workspaceKeys` REFUSES a literal `Cargo.lock`, `rust-toolchain.toml`, `.cargo/config.toml`, `**/Cargo.toml` key (a task declares the meaning, not the whole workspace), except for the `cargo metadata --locked` replay and five named crate-partition tests.
2. **Measured on generation 560/561** (`lockcov.mjs`, 365 cached targets of the three products): `framework-actor-rs:typegen`, `framework-rs:generate`, `ui-contract-rs:generate` (precision rules `actor-typegen`, `framework-generate`, `ui-contract-generate`) all carry the token. The 190-195 other workspace member manifests those runs read (undeclared-g: 209/81/212 reads) are not output relevant: cargo only fails when a member manifest is broken; the manifests of the crates the exporter compiles with are in the key (48 for typegen).
3. **LAW (real files, independent oracle)** `batch/laws/cargo-resolution-token.test.ts`, 20 tests green, for the four crates `framework-actor-rs`, `framework-rs`, `ui-contract-rs`, `proctor`: a toolchain `channel` edit moves the token, a comment-only edit does not; a `.cargo/config.toml` `[env]` edit moves it, a `build.target-dir` edit does not; a version bump of a lock entry INSIDE the crate's dependency closure moves the lock part, a bump OUTSIDE does not. The closure oracle is `cargo-closure.py`, a version-aware line reader of the real `Cargo.lock` (no repository code; `tomllib` does not exist on this Python). Its first version was name level and WRONG (allocator-api2 looked inside the actor closure through another hashbrown version); the repository implementation was right, the oracle was fixed. Overlay host, never writes a file.
4. **REAL GAP fixed: `architecture-course:test`.** The oracle (undeclared-g `ac-test`) saw `rust-toolchain.toml`, `.cargo/config.toml` and 20 manifests read by the proctor cargo run; the hand list `proctorCargoManifests` named three `Cargo.lock` files but neither the toolchain pin nor the cargo configuration. Fix: `{input: cargoToolchain, projects: [@teaching/proctor]}` (project.json only, no library edit). The tool environment/commands (RUSTFLAGS, `rustc -vV`) already arrive through the proctor project's `default` behind `^default`.
5. **`course:test` is NOT a cargo run.** Its 146 `Cargo.toml` reads equal exactly the owner-route package-discovery glob (`**/📦️packages/*/Cargo.toml`: 146 of 146 match, 0 outside) and no lock, toolchain or config is read: the launcher's package scan, not cargo (profile `package-discovery`, 🎯️precision). Not keyed on purpose (every new crate would re-run every course test). Open question for the router owner: why `course:test` triggers that scan while `course-react:test` does not (not attributed to a process: the unified log names the file only).
6. **Static reach is not proof of a cargo run.** 147 of 365 targets reach the cargo drivers (`🧪️testing/🦀️cargo`, `native-build`) in their import closure without a token (print TeX builds, TS tests): the 1.9k-file router closure over-approximates. The oracle is the proof: of the recorded reports exactly typegen (3 reports), `framework-rs:generate` (3), `ui-contract-rs:generate` (2) and `architecture-course:test` show reads of the toolchain pin or cargo configuration; `architecture-course:build` reads 89-93 manifests through the cargo workspace preparation of the vite action (undeclared-g C6, owner decision, unchanged).

## Item 2: Tailwind scan narrowing (coordinator decision)
- **Mechanics, measured with Tailwind 4.3.3's own compiler and Scanner replaying what `@tailwindcss/vite` does** (`tw-scan.mjs`: vite root = the course site, `compiler.sources` = the `@source` lines): the scan is the site tree (auto `**/*`) + `🖱️ui/**` + the course react target; `@source not` lines are GLOBAL to the compile (an exclusion declared in the course stylesheet also removes ui and course-target files) and accept braces and a relative base (controlled fixture and the real tree; absolute and relative forms give the same CSS).
- **Region**: baseline 2,560 files scanned, 1,026 of them tests; after the two lines 1,375 files; no excluded file is scanned (law). Categories: dirs `🧪️tests 🧫️fixtures 🧫️examples 🧪️fixtures 🧪️examples 📖️stories 🎭️e2e` (the repository's own non-production set, `nx.json` `production`) and files `*.feature *.stories.* *.story.* *.mdx` (the stories are `🧪️.story.tsx` files and helpers in `📖️stories` dirs; `*.stories.*` alone would have removed nothing of 66 story files).
- **Served CSS of the course**: 304,604 -> 295,264 bytes, 2,739 -> 2,622 rules; ONLY removals (0 added), 117 rules (108 utilities, the rest `@layer properties` / theme variables only they used). Verification: (a) law test 4: every dropped rule has a literal occurrence in an excluded file (no unexplained drop); (b) `dropped-check.py` found no kept file containing a dropped class token as a bare class (the 10 literal hits are variants and definitions: `hover:bg-emphasized`, `@utility h-layout-story` in the stylesheet itself, `@apply p-4`). The dropped utilities are in `evidence/tailwind-dropped-rules.txt` (e.g. `h-layout-story`, `w-layout-story-md/lg`, `w-layout-floating-menu-lg`, `data-[state=on]:bg-hover-interactive-fill`, `ring-[3px]`, `z-[9999]`, `grid-cols-8`, `text-white`, `p-4`, `ml-auto`, `gap-8`, `font-bold`): each occurs only under tests, fixtures, e2e or stories. Tailwind scans `.rs` too and `🎨️styling/🎭️theme/🧩️component/🦀️.rs` holds real class strings (`text-diff-added`, `text-info`), so Rust files stay in the scan and are keyed instead (rejected: excluding `*.rs`; it would also drop `ring-primary`/`max-h-64`, words that only wgpu painter files spell).
- **Key in sync**: named input `tailwindScan` = ui tree + course react target + course site tree, minus the generated directories (policy `generatedDirectories`), minus the same exclusions; the `build` target lists it. Simulated key of `architecture-course:build` (generation 550 list, `newkey.ts`): 4,800 -> 5,244 files (-109 tests/e2e/stories that no longer re-key the site, +553 files the scan reads and no extension rule keyed: 460 `.rs`, 74 `.toml`, css, md, graphql, proto). The scan can no longer read an unkeyed file: law test 3 (scanned set within the declared set; every excluded file outside it; picomatch and the repository matcher `inputGlobRegExpV1` agree on 2,500+ files). A new `@source` outside the three roots fails the law until the key names it.
- **Risk under test**: the negations are global inside the build key; if the site build imported a file under an excluded directory the key would drop it. The oracle run `k3-ac-build` replays the build under Seatbelt with exactly the simulated key (old key + undeclared-g's simulated C1/C3/C5 fixes - negations + scan region = 5,804 files): a denial inside an excluded directory proves a defect. Result under "Sweep" below when it ends.
