## 2. Process API: `T/🏃️run`, `🔎️resolve`, `🌿️environment`, `📌️pin`
```ts
runToolV1(toolId, args, { cwd, root, env, environment, signal, timeoutMs, label, check = true, capture, stdout, input,
  onLine, onProgress({phase: admitting|running|finished, tool, elapsedMs, status}), heavy, admission, caller, trusted, registry, host }): Promise<{tool, command, arguments, status, signal, stdout, stderr, durationMs, resolution}>
runToolSyncV1(toolId, args, options)   // light tools only; heavy (capacity admit) refuse
createToolAdmissionV1(policy) / setDefaultToolAdmissionV1(port)  // machine-wide gate of the host-capacity module
```
- Cancellation: `AbortSignal` ends the process tree (`terminateOwnedChildTree`); a cancel while waiting for capacity is passed to the gate. Progress: phase events plus the owned 10 s running lines. Capacity admission: tools with `capacity.admit` (cargo, bazel, nx, go, uv, ...) or `heavy:true` wait fairly in the existing host-capacity queue and inherit its grant environment; an enclosing grant is inherited. Environment sanitization: IDE/debugger injections (`NODE_OPTIONS`, `VSCODE_*`, `CURSOR_*`, `ELECTRON_RUN_AS_NODE`, `JAVA_TOOL_OPTIONS`, `npm_config_*`, ...) are always dropped, `allowlist` tools keep base+own variables only, fixed values and cache directories (`GOCACHE`, `PLAYWRIGHT_BROWSERS_PATH` under `.🧬semio/🦑️repo/⚡️cache`) come from the registry, explicit caller values win, every run is marked `SEMIO_TOOL_RUN=<id>`. Errors are `ToolErrorV1` (code unknown-tool / tool-missing / caller-refused / sync-refused / cancelled / failed) with EN/DE messages (`SEMIO_LANGUAGE`, locale).
- Adapters inside the tools module: `🌿️git` (`gitOutputSyncV1`, `gitSyncV1`, `gitV1`), `🐙️github` (`ghV1`, `ghOutputSyncV1`), `🎭️playwright` (`playwrightV1` CLI under admission, `loadPlaywrightV1` library loader with the shared browser cache), `startToolV1` (a started process with streams), `runToolSyncV1` (to completion, Node's result shape) and `toolExitV1` are part of the one process API in `🏃️run`; there is no compat module.
- Package re-export `F/📦️packages/🟦️typescript/🧰️tools/🟦️.ts`, same pattern as the other process modules.

## 4. The law: `L/⚖️laws/🧰️direct-tool-spawn` and `repo verify tool-spawns [--report] [--json] [--strict] [--prune [--accept-new]]`
- Static scan (`T/🔍️scan`, no dependencies, registry-driven callee table): masks comments (and optionally strings), finds `spawn/spawnSync/execFile/execFileSync/fork/exec/execSync/Bun.spawn/Bun.spawnSync/Bun.$` in TypeScript, `Command::new` in Rust, `exec.Command(Context)` in Go, `subprocess.*` in Python, command lines in shell and PowerShell scripts, shell strings (`sh -c "cargo ..."`), and commands declared in `📋️project.json` / `package.json`. `bun ... repo` is classified as tool `repo`. Rules: `raw-spawn` (a registered tool started outside its adapter scope and the tools module, ratcheted against the ledger), `declared-grew` (manifest commands per tool), `caller-not-allowed` and `unknown-tool` (`runToolV1("id")` literal calls vs `allowedCallers`), `registry` (adapter / installer / pin / digests / globs / process funnels intact).
- Ledger `L/⚖️laws/🧰️direct-tool-spawn/🧾️ledger/🔣️.json` (schema next to it) is test-code only, with one EN+DE reason: 589 test files / 1,134 spawns. Production has no ledger and no tolerance: every production spawn of a registered tool outside its adapter scope is a finding (0 production spawns remain except the two files repo-launcher deletes, see below). Test rows may only shrink (`--prune`), new ones need `--prune --accept-new`, stale rows are warnings (`--strict` fails them). Commands declared in manifests (`bun ./📜️script.ts` 4,582 production) are reported by `--report`, not enforced; the repo-launcher manifest wave rewrites them.
- Runtime guard: (a) `runToolV1` checks the declared `caller` against `allowedCallers` (`SEMIO_TOOL_GUARD=refuse|warn|off`); (b) there is no runtime hook on the `Bun` global any more (round 3): the static law, the caller check of `runToolV1` and the funnel routing are the enforcement.
