1. **Holder progress on the lease, shown to waiters EN+DE.** New leaf module `L/📈️standing` (schema `🧬️schema/🔣️.json`: closed Policy, Standing, YieldRequest, Messages EN/DE, Corpus). `noteLeaseProgressV1` is fed by the root invocation's `publish` (routing `🧭️routing/📥️invocation/🏃️process/🟦️.ts`): phase + done/total (declared families `build:graph-phase:<phase>:<done>:<total>`, trailing `:N`, else the resource name), `progressAtMs`, published in the registry entry (`standing`, 5 s). ETA from the holder's own counter, else median of earlier holds of the same kind (`history.jsonl`, written when an exclusive hold ends). The queue notice `lease-queue:` carries `holderState/Phase/Done/Total/EtaMinutes`; formatter and labels in `📈️progress.json` (EN/DE), live example from the real writer test: `… behind the request of process 2893 (exclusive, queued 0 s ago) · holder: progressing, interleaving:stale-busy-format`.
2. **Implementation identity + cooperative yield.** Identity = digest of the captured format-stamp components + load time, supplied by a provider seam (`registerLeaseImplementationProviderV1`; the format-stamps module registers it with `idsOf(resource)` as the binding table). A waiter on newer code that finds the exclusive holder of a stamp-bound resource stale files a request (`<registry>/yield/<pid>-<start>.json`); the holder's watcher (5 s, started at the first exclusive admission) verifies the claim itself (addressed to it, fresh, held exclusively, older and different bound component) and calls the registered handler: format-stamps' handler aborts the root invocation with a `StaleImplementationErrorV1` (exit 75, outermost command re-executes) or exits 75 when there is no root. Healthy holders are never asked (law + test).
3. **Priority classes with aging.** `interactive` filed 60 min earlier, `agent` as arrived, `background` 60 min later: ticket arrival = real arrival minus advance, tickets served in filed order, so overtaking is bounded by `leaseOvertakeWindowV1` and nothing starves; the ticket row carries `priority` (omitted for agent), the real arrival is restored for the writer-preference clock, the upgrade path keeps the class. `SEMIO_LEASE_PRIORITY` overrides.
4. **`repo leases status`**: per exclusive holder (and any stale/stuck one) a second line: priority, code age, phase/counters, time left or "longer than usual", state (progressing / silent / STUCK / STALE / legacy), the chain of invocations that started it, an open yield request; waiters show `[priority]`; JSON validated by the status schema (`HolderStanding`, `Waiter.priority`). Live today every holder shows `legacy` (started before this code), as designed.
5. **Stuck holders.** Stuck = no progress for 20 min (graph builder custody) / 60 min (other). `SEMIO_LEASE_RECLAIM=report|request|terminate`, default `request` (ask the stuck holder to give the resource up). `terminate` stops a stuck holder that ignored the request for 2 min and did not progress since, only if the OS start time (`ps -o etime=`, timezone-free) equals the registered one (legacy holder older than 90 min: start precedes its ticket), only if signalable, never itself: SIGTERM, SIGKILL after 15 s, `reclaim.jsonl`, EN/DE notice. win32 cannot read the start time and therefore stops nothing.
