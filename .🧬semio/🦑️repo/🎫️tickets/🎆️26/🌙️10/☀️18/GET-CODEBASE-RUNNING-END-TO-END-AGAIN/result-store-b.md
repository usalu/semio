## 20:35 ROOT CAUSE of the 13 os-store-tests-02 close stalls (static, WRITTEN, awaiting the run)
`SnapshotReadLeaseRegistryOwner::terminal_is_empty` called `owner.terminal_is_empty()` on a `SnapshotReadRegistryAliasRetirement`. Until 10-19 (696) the alias had no `ErasedSnapshotRetirement` impl, so Rust's method probing went through `Deref` to the REGISTRY (`returned == 0 && every slot free`). Commit 696 added `impl ErasedSnapshotRetirement for SnapshotReadRegistryAliasRetirement` (`terminal_is_empty = closed()` = "registry custody already released"); probing now stops at the trait method on `&Alias`, so the owner answered "not terminal" until the very end of the close. The `ReturnedReads` close phase therefore never advanced (no returned lease, owner never terminal, `advance_returned_snapshot_read` -> `Complete(default)` mapped to a zero-progress `Progress`): exactly the observed "demand zero except depth, 4096 zero-progress turns"; `close_custody_step` had the same trap. Fix (value `snapshot/read/🦀️.rs`): both call sites name the two meanings explicitly, `ErasedSnapshotRetirement::terminal_is_empty(owner) || SnapshotReadLeaseRegistry::terminal_is_empty(owner)`. Regression coverage = the existing store tests (`store_close_waits_for_a_live_snapshot_read_...`, `store_close_releases_a_returned_read_...`, hot-path, ...). Stall panic message of the test store now also prints outstanding/returned read counts.
