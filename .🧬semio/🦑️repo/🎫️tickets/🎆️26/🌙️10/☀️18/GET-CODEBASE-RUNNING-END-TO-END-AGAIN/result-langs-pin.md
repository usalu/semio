## Design (schema first, one table, pins never copied)
* `L/🏗️build/🧰️tool-setup/🔣️.json` (+ strict schema `🧬️schema/🔣️.json`): 20 rows. Per row: `pin` = pointer into the file that already owns the pin (formats `json` pointer, `rows` filter+field, `regex` capture, `value` for the three cargo literals that used to hide in `prepareDependencies`; `package`+`from` resolves a file of an installed package), `probe` (version regex, or `listed` for `dotnet --list-sdks`, or a hook), `locate` (provisioned location per family native/bun/bazel/binaryen/dotnet/cargo, managed Python, PATH + directories), `setup` (native, bun, binaryen, bazel, dotnet, rust, bootstrap = only reported, `script` = the owning product's own prepare script run under the process envelope). EN/DE texts, no default language (unresolved language renders both).
* `L/🏗️build/🧰️tool-setup/🟦️.ts`: pure engine (`resolvePinV1`, `toolVersionMatchesV1` series match `3.14` ~ `3.14.4`, `locateToolV1`, `verifyToolV1/verifyToolsV1`, `setupToolsV1`: skip what matches, report bootstrap tools, provision, re-verify, fail when a provisioned tool still differs, `AbortSignal` between and inside steps; `renderToolReportV1`, `runtimeWarningV1`). All machine access is the injected `ToolContextV1`.
* `L/🏗️build/🧰️tool-setup/⌨️command/🟦️.ts`: system context + provisioners. Native archives go through the langs-conc engine (size + SHA-256 pinned, system `tar`/`unzip`, one atomic rename, receipt, concurrent provisioners safe, now with `received of total bytes (n %)` progress every 2 s and cancellation by signal), uv installs the managed interpreters (`uv python install <series>` into the tools partition, `UV_PYTHON_PREFERENCE=only-managed`), .NET SDK through the pinned `dotnet-install` script (shell or PowerShell, SHA-256 checked, `installDotnetSdkV1`), Bun/Binaryen through their existing preparers, Tectonic/WASM tools/browser through the owning scripts (`prepare`/`sync wasm|tools|browsers`), Rust through `rustup toolchain install`.
* Runtime wiring (`L/🏗️build/⌨️command/⚙️runtime/🟦️.ts`): `tools setup [nx|bazel|toolchains|all]` (toolchains + bazel + nx for `all`), `tools verify [tool...]` dispatched before the dependency store. Catalogue + regenerated help snapshots (EN/DE, new page `tools verify`), README (EN/DE), CI step `repo tools verify` after `repo tools setup all` in `.github/workflows/build-system.yml`. Fresh machines: `workspace:setup` already runs `tools setup all` (`deps-build-tools`), so bootstrap needs no new step.
* uv is now a repo-managed archive tool next to Go/CMake/Ninja (`python.tool` in `P/🏗️build/🧰️toolchains/🔣️.json`, same distribution schema, 6 hosts, sizes measured, SHA-256 equal the bootstrap pin rows AND astral's `.sha256` files); `pinnedUvEnvironmentV1` (native deps `deps-python`, styling Python builder) and `provisionedToolPathV1` (energy oracle plugin) put the pinned uv first on PATH, so a uv on the machine is never used.

## Root-cause fixes found while running it for real
1. Bounded archive reader refused every tar whose mode field carries file-type bits (`0100755`, as the pinned Tectonic 0.16.9 tarball has): Tectonic could never be prepared. `🧰️framework/🔨️modules/🏃️process/📦️artifacts/🗃️archive/🟦️.ts` now masks `& 0o7777` before the 0o777 ceiling (setuid etc. still refused; new corpus lines in its test, not runnable outside `repo test`).
2. `NativeCallerPhase.budget()` returned a fractional remaining time after the first child command, so every native dependency script with a second command (`deps-wasm`, `deps-tools`, ...) died with `Finite nonnegative safe command timeout` (`⚡️caching/📦️artifacts/📋️native-orchestration/📥️invocation/🟦️.ts`: `Math.ceil`).
3. `C/langs-conc-tools/apply.py` used `tarfile.extractall(filter=)` (Python 3.11+); the host `python3` is 3.9.6.
4. `prepareDependencies` hard-coded wasm-pack/trunk/nextest/llvm-cov versions; they now come from the table (`toolPinValueV1`) and `verify` checks them.
