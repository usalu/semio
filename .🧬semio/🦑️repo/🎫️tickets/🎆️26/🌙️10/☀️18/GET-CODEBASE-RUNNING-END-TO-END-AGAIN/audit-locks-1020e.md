## 1. Mechanism (shared by all keys)

- Every resource lease is one SQLite file per key: `<leaseDir>/<sha256(resource)>.sqlite` (`🔒️leases/🟦️.ts:29-34`, VERIFIED-READ). The leaseDir is `.cache/b/l/m/data` per checkout (`🏗️build/🔧️tools/🏗️bazel/📜️script.ts:79`, VERIFIED-READ).
- Modes: `shared` (BEGIN, deferred) and `exclusive` (BEGIN EXCLUSIVE), held as an open SQLite transaction for the whole lease (`🔒️leases/🟦️.ts:203`, VERIFIED-READ). Modes are declared in `🎛️control/🟦️.ts:4`.
- Ungated `acquireResourceLease` busy-polls with a delay capped at 40 ms (`🔒️leases/🟦️.ts:183-230`, esp. :225). It is NOT FIFO. Used by `withResourceLeases` (:434-443, sorted keys, :439), by fixed-image options with a DB byte cap (`🧱️fixed/🟦️.ts:106`), and by Nx output and namespace leases. Exclusive waiters can starve under readers (VERIFIED-READ; result-lease-fair.md:7-12 confirms observed starvation).
- Queued `acquireQueuedResourceLease` (`🔒️leases/🟦️.ts:359-377`) publishes a ticket `<arrivedAtMs>-<pid>-<owner>` under `<hash>.queue/`, takes a shared per-ticket claim lease (:375), then `awaitQueuedTurn` (:393-431) serves tickets in arrival order (:399). Readers may join only as a `sharedCohort` (:408-410). Waiters poll with geometric backoff from the wait policy (:423-424, schema `⏳️wait/🧬️schema/📜️policy.json`). Dead predecessors are reaped via a non-waiting exclusive probe on their claim (:344-349). Upgrades shared to exclusive keep arrival position (:380-391).
- Directory admission: every acquire first takes a SHARED lease on `resource-directory-admission:v1` (`🔒️leases/🟦️.ts:231`, `:237`, `:246`), and KEEPS it while it waits for the real resource (:238 → :247). The only admission mode used on the acquire path is shared (VERIFIED-READ). Exclusive admission is not taken on this path (INFERRED: only retirement/reset).

## 3. Lock-order and hold-and-wait findings

- H1 (VERIFIED-READ): ungated `acquireResourceLease` keeps the shared directory-admission gate while it waits for the target resource (`🔒️leases/🟦️.ts:238`, `:246-247`). Retirement or reset that needs exclusive admission would wait for every waiter.
- H2 (VERIFIED-READ): queued waiters hold a shared claim while they wait for their turn (`:375`, `:411-413`). This is per ticket, so harmless for other keys, but it means a stuck head holds every follower's claim.
- H3 (VERIFIED-READ): Nx pool holder takes namespace leases of other namespaces exclusively (`nx/📦️graph/🟦️.ts:144`) while holding `nx:graph-pool` (`:140`). A reader of another namespace therefore blocks the pool holder, and the pool blocks every other graph builder. This is the largest single serialization point of the graph path.
- H4 (VERIFIED-READ): `withResourceLeases` acquires its keys in sorted order (`:439`), which prevents cycles among callers of that helper, but it is not FIFO, so exclusive callers starve (see result-lease-fair.md:7-12).
- H5 (VERIFIED-READ, fixed): lock-order bug where `build/📜️script.ts` pinned the dependencies partition shared around the whole command (coord.md:14), and "Queued cache maintenance must begin outside its reader scope" (coord.md:141).
- H6 (INFERRED): cross-layer order is host capacity, then repo capacity picker/cores, then graph pool, then namespace, then native image. Holding cores while waiting for the pool holds host capacity for other checkouts.

## 4. Proposed minimal correct scopes

1. Host capacity (rank 1): admit by fit, not strict FIFO. Count per resource class (memory, cores, open files). Keep the progress line. Fix the darwin availability measure (mem-gov, already in flight).
2. Dependency store (rank 2): MVCC generations. Each run pins an immutable generation with a shared lease on `native-fixed-image:<dir>@gen<N>`. A sync builds generation N+1 with no lock and then swaps a pointer under an exclusive lease held for milliseconds. Cold installs and walks never block readers. This matches the conc-deps plan (coord.md:441).
3. Nx graph (rank 3): keep the pool lock for capacity accounting only, and drop the exclusive hold across the build. Readers use the last published generation under shared leases. Exclusive only at publish, scoped to `nx:graph-publication:<ns>` (already narrow). Stop evicting namespaces while holding the pool (H3): evict via a separate lease after the pool is released.
4. Cargo registry (rank 4): shared for reads, exclusive only for registry index writes, keyed per workspace or per crate, not one key per repo. Make compilers and sync use disjoint keys.
5. Bazel (ranks 8 to 10): per-session output base (conc-bazel plan, coord.md:439); `bazel-snapshot-restore` keyed per snapshot identity, not one key per checkout.
6. Cargo compile (rank 12): maintenance per compilation unit, not per profile (the schema already declares `compilerLockGranularity: cargo-compilation-unit`, `🏗️native-build/🔒️lease/🧬️schema/🔣️.json`).
7. Lease core (H1, H2, H4): release the admission gate before waiting on the resource; use FIFO with reader cohorts for `withResourceLeases` as well; never hold capacity cores while waiting on the pool.
