# Result gofin3: client `TestExhaustive*` suite is hermetic

Root `M` = `🧰️framework/🛍️products/🦑️repo/🔨️modules`, client = `M/💻️client/⌨️cli`. No cargo, no package.json/bun.lock edits. Tools in `gofin3-tools/` (`run-client.sh` syncs the client into the throwaway repo copy and runs it with the `gocanon/plan.py` overlay; `convert.py`, `fix-unused.py` were one-shot codemods). The copy (own `git init`, 1.4 GB) and `🗑️generated/gofin3-logs` are deleted.

## What was wrong
69 untagged `TestExhaustive*` in 22 case dirs (`client/🧪️tests/*/🐹️.go`) answered from the checkout they ran in: they walked the whole repo (`TestExhaustiveNormalizeTicketFileInput` ran 7 min in a 40k-file copy and hit the timeout), read real goals/tickets/contributors, and wrote real tickets/goals/section files (`setupToolTest`, `findTestRepoRoot`, `getTestExecutor`, `Getwd`). `TestMain` also bound the process-wide `executor` once to the real root, so every `gql(...)` MCP/CLI handler answered from it whatever the root was.

## Changes
- Fixture builder: `withExhaustiveRepo` (+ `exhaustiveModelsGo`, `withoutSelectors`) in `client/🧪️tests/🎼️helpers` = same builder as the module cli (`withMonorepoFixture` + bundles compose/{engine,antlr,desktop}, repo/{server,go,cli}, coda/notes + git history with a merge + contributors `usalu` and `ueli` + goals "Sketchpad"/"AI Optimized Repo" + one seeded ticket). It restores root, workspace root and, last, rebinds the global executor.
- All remaining real-root preambles in `TestExhaustive*` replaced by `withExhaustiveRepo(t)` / `newExecutorFor(t, withExhaustiveRepo(t))`; `testEngineFactory` falls back to `GetRootDir()` instead of walking from cwd to the real repo. 68 tests, all run against the fixture.
- Production: `ensureExecutor` (`🌱️root-and-repo-config`) now rebinds when the root changed (mutex + `executorRoot`) instead of `sync.Once`, so `gql()` can no longer answer from a repo the process left.
- Deleted (1): `TestExhaustiveMigrateAuthorFieldsToString`. Evidence: it only streamed every ticket and goal of the checkout and `SaveTicket`/`SaveGoal`-ed them back (a lossy rewrite of ~3.4k tickets / 200 goals, the 2026-10-18 incident class); it asserts no author-field conversion and the `author` object -> string migration it was named after does not exist in the code (greenfield: no migrations). Same decision as gofin for the module twin.
- Stale expectations fixed (ported from the module twins gofin fixed): `policy check` CLI command does not exist in the client (`unknown command "policy"`), the table case now runs `analyze <technology id>` (the client's `analyze` takes an entity id); `node(id)` test selects `__typename` (parser has no inline fragments); bundles `asset`, `compose/docs`, `repo/vscode` and the `repo` technology assertions no longer assume the real repo; technology sort test strips emoji; `tree --query cli` asserts the fixture nodes; two `t.Skip`s that would hide an empty fixture are `t.Fatal`.
- Real defects the hermetic run exposed in the client duplicate stack, fixed with regression tests:
  - `🎊️query-cache` `ensureCacheIndexed` reused a persisted index built without sections for later section/definition queries (`section/definition list --query` returned nothing). Now compares `IncludeSections` (`treeIncludesSections`). Test `TestSearchIndexIsNotReusedAcrossSectionChoice`; mutation check: with the comparison removed it fails, restored.
  - `🔧️tools-ticket-goal` `ToolTicketList` dropped status/goal/prompt (MCP differed from the CLI markdown); `🪅️analyze-fix-tools` `ToolPolicyList/Tree` listed in registration order (CLI sorts): `sortedRegisteredPolicies` + `TestToolPolicyListIsSortedByIdentifier`.
- Non-exhaustive neighbours touched because they hit the same pollution/staleness: `TestGoalCreateAndCleanup` (created a real goal) now runs in `withTempRepo`; `TestGraphQLFixMutationIsRemoved` (stale since gofin added `Mutation.fix`; also ran against the real root) replaced by `TestGraphQLFixMutationIsServed` on a fixture repo.
