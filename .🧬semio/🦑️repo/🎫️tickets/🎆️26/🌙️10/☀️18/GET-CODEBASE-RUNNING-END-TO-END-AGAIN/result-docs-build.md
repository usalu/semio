## Where it goes and why
The repo product documents its CLI in one document, `🧰️framework/🛍️products/🦑️repo/README.md`: the chapter `# 🏗️ Build and run` (English, `##` sections) followed by `## 🇩🇪️ Deutsch` (the same sections as `###`, German, no default language). The guide follows that shape: English `## 📘️ Build tools guide` inserted before `## 🧭️ Neutral model` (quick path first, reference after it), German `### Build-Werkzeuge im Alltag` inserted before `### Neutrales Modell`; subsections are `###` (EN) and `####` (DE). No new markdown file was created, because the taxonomy pins README files through the owner-projection policy (new READMEs would need catalogue entries and a relocation destination) and the earlier docs executors extended this README the same way. German terms are those of the help catalogue (`Task-Cache`, `Remote-Cache`, `Disk-Cache`, `Build-Aktivität`). Both languages are complete and equal in structure (12 headings, 8 tables, 5 code fences, 39 commands each, checked).

## What the guide covers (EN and DE, 11 subsections)
1. Choose the tool: `--tool=nx|bazel`, `SEMIO_BUILD_TOOL`, inheritance by nested tasks, provisioning (`tools setup`), comparison table.
2. Neutral operations: `run`, `run-many`, `affected` (rule, `rdeps`, the lockfile difference), `exec`, `--dry-run` and `--graph` (`DryRunPlan`), `show`/`graph`/`watch`, `cache status|clear|remote status|serve`, `reset`, cancellation, Bazel specifics (`bazel test`).
3. Caching model: key ingredients and consequences, the four layers with location and how each is cleared, partitions, `--skip-cache`/`--skip-remote-cache`, early cutoff, store receipts; remote cache how-to (serve, client environment in POSIX and PowerShell, `cache remote status`, access/tokens, `cache serve` options and bounds), download modes and why `minimal` is forbidden, what is shareable across machines.
4. Remote execution: the hermetic declaration and its closed reasons, what a hermetic action is, the four `SEMIO_REMOTE_EXECUTION_*` variables with defaults, routing without local fallback, executor requirements, platform limits (macOS network, Windows), optional local stack.
5. Worker pools: `--workers`, `SEMIO_BUILD_WORKERS`, `--parallel`, the kind table (patterns and bounds from the policy), the memory budget, Bazel and Nx mapping, what never uses workers, measured effect, when to switch off.
6. Task dispositions: `action|test|interactive|uncached|refused`, the 14 families, mapping under Bazel, the static census.
7. Classify a new target: a three-question flow, the class/reason table (including the four reasons that landed with `uncached-owners` and `unclassified`), the exact resolution order of the policy, two manifest examples, outputs rule and `optionalOutputs`, `bazel test` conditions, hermetic opt-in, the law.
8. Incremental builds and how to verify them: a six-command recipe with `cache clear|status` and `run`, five reading rules, what causes extra work.
9. Cross-platform notes: macOS, Linux, devcontainer, Windows (junction source link, runfiles off, tests as cached actions, hermetic remote-only, path budget, PowerShell syntax).
10. Troubleshooting: reboot recovery (boot-session receipts), lease queue lines, receipts, no cache hit checklist, remote cache status reading, workers, installed packages, Nx installation link.
11. Verified and not yet verified.

## Staged files (`C/docs-build-tools/`)
- `staged/guide-en.md`, `staged/guide-de.md`: the two fragments (source of truth for the text).
- `staged/edits.json`: 34 anchored edits generated from the current README by `make-edits.py` (every `old` text is derived from the README itself, occurs exactly once, `base` = README sha256). 30 are live now, 4 are conditional (`requires: remote-execution`).
- `apply.py`: dry run by default; `--write` applies all-or-nothing (state computed in memory, balance checks, temp file plus atomic rename, backup in `backup/`, record in `applied.json`); refuses on drift (README hash differs from the base or from our last result, or any anchor matches neither as old nor as new text); `--rebase` accepts a changed README when every anchor still matches exactly once; `--undo` restores while the README still equals our result; `--root DIR` for rehearsals. Python standard library only, so it runs on macOS, Linux, Windows and in the devcontainer.
- `check.py`: read-only verification (below). `selftest.sh`: rehearsal on a README copy. `make-edits.py`: regenerates `edits.json` after a fragment or README change (run it before `apply.py` when the README drifted).

## Where the live source overrode the reports (source won)
- Tests as `bazel test` are not emitted where the platform profile has `--noenable_runfiles` (Windows), and never for Cargo tasks (`exclusive`); `bzl-coverage` had passed `--enable_runfiles` for Windows, the integrated adapter does not.
- Workers: the live adapter assigns a worker kind to Cargo tasks too; `integrate` says they never use workers. The guide says only that Cargo tasks run one at a time and lists services, hermetic actions and `bazel test` tests as never using workers.
- The class-resolution order is read from `target-policy/🟨️.mjs`: a manifest `cache: true` alone is overridden when no declared decision, `targetClasses` row or `verify` command classifies the name (the guide says so; the earlier README claimed row 7 "anything else: yes").
- The policy file with `targetClasses` is `L/⚡️caching/🔣️policy.json`; the worker and remote cache policy is `L/🏗️build/🔣️policy.json`.
- `orphan-child` (descendant tolerance) is staged only and is not documented; boot-rebind is live and is.
