## 3. New findings (root cause, proof)

- **N1 closure sweep stalls for ever on one corrupt leaf.** `inference/contexts/81b87654.../np/81b87654691b6c0ffcdd0a40.json` is 1 byte (0x00), mtime 1970, written 10-26 11:27 by an optional-cache test (the `futimes(0)` maintenance law, run against the live store; the member index even holds a row with its sha256). The real closure read child answers `Z_BUF_ERROR: unexpected end of file`, `closurePayloadRefusal.check = inflation`; `supersedeBuildGraphClosuresV1` counts any refusal except `Authenticated observation closure block required` as unproven references and removes NOTHING (`unvouched`). Effect: `repo cache gc` on the graph never reclaims a closure inventory (707 MiB apparent now) and every run prints the two `closure-read-failure` lines. A truncated or corrupt stream never becomes readable and no reader can follow it to a closure, exactly like a leaf whose blocks are gone; `Z_MEM_ERROR`, I/O errors and size-limit refusals stay unproven (law). The leaf itself leaves with its group (oldest, LRU first).
- **N2 a future-dated mtime protects a file for ever.** `planCacheCollectionV1` blocks a unit when `now - recency < quietMs`; Bazel dates its installed files 10 years ahead (`stat`: mtime 2036-10-11, ctime 2026-10-14). The retired root `.cache/bazel` (182 MiB, retired since 10-14, listed by `status` as `repo cache gc removes them`) has therefore never been removed, and the native root is over its 256 MiB. Also the dedupe census protects such files (recent use). Fix: recency = newest of mtime/atime not beyond `futureSkewMs` (24 h) ahead of now, else the inode change time (no tool can set it). The Cargo pruner (`🧹️pruning`) has the same `max(atime, mtime)` expression; no future-dated Cargo file was found, left alone.
- **N3 `.cache/acceptance` is an undeclared native home** (G48 benchci). Moved under the repository cache root as the area `acceptance` (16 MiB, owner-quiet: `unusedAgeMs: null`, so the restore journal is never aged out), EN + DE purpose, README updated in both languages.
- **N4 the ledger law broke twice without anyone seeing it**: a regex fragment in a law JSON (`rust(/|`) and the 5 s timeout of a `git grep` over 465k files. Both red on live; fixed (`lawregex`). The other live red of the native law, `no cache root exists below a module directory`, is the true stray residue below.
- **N5 the sweep never reaches owner areas with `reclaim`** (`graph-inference`, `nx-tooling`, `bazel-workspaces`): they act on their own triggers (writer open, free-space thresholds). Not changed: the images are hard-bounded by their capacity, `graph-closures` (1.25 GiB) is advisory because referenced inventories are live data. If a periodic graph reclaim is wanted, add the `reclaim` areas to `budgetSweepAreasV1` (one line plus its law).
- Verified, not a gap: `repo cache gc --dry-run` over the whole ledger completes (74 s, 98 lines, 34 targets, exit 0); every area is either collected under a lease or reported as `Leaving <area> to <owner>`.
