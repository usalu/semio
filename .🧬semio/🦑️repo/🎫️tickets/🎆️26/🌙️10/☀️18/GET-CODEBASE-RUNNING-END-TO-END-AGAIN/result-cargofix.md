## (1) synchronize: the 42 s nested preparation child becomes an in-process receipt check
Cause: `prepareCargoWorkspaceInvocation` (`🗂️workspaces/🦀️cargo/🟦️.ts`; callers: repository cargo tests/lint, provider, wasm policy, process) and the library native-build path always spawn `<native-orchestration>/🛠️preparation/📜️script.ts synchronize`. The child boots a second `repo` script process, opens the compiler store + Rust toolchain generation, runs the owner closure, publishes membership, computes rosters, runs `cargo --version`, and only THEN compares `<key>.sync.json` (`withPreparedCargoDependencyPairV1`). Measured (read-only, live, `cargofix-tools/roster-cost.ts`): one `cargoWorkspaceMembers` of the root workspace (573 members) costs 3.3-5.3 s, and the child computes it >= 4 times per run.
Fix: the child, when its receipt holds or after it rewrites it, publishes `<key>.witness.json`: the exact object it hashed into `inputsSha256`, the stamp of every physical answer its owner/scope/roster plans consumed (state kind, presence, listed sub-directories + `Cargo.toml`, text sha256, plus the stat taken BEFORE the answer when it is older than the 2 s racy window), and the stamp of the toolchain `cargo` it identified (`store.toolchain.cargo`, sealed generation). The launcher replays it in-process (`cargoPreparationInvocationCurrentV1` → `cargoPreparationWitnessHoldsV1`) and starts the child only when anything differs. Exactness: the plans are deterministic functions of the answers they read (`operate` results seen through `isSymbolicLink/isFile/isDirectory`, names, text) and of pure path predicates; equal answers ⇒ equal owners, manifests, rosters ⇒ equal hashed object ⇒ the child's comparison would hit. No witness when a recipe ran (recipes always execute in the child), when an answer changed during the run (poisoned set) or when the caller names no tool file. Shared derivations (compiler environment rule, user Cargo config, receipt key) moved into the witness module (schema-declared), used by child and launcher.
Measured: print selection record = 30,815 answers (24,644 listings), 9.3 MB; replay 0.29-0.39 s (1.3-1.7 s without the settled-stat shortcut), vs 42 s (edit run g28p) / 23 s (10-26) for the child. Projected saving per print test action and per dashboard build: ~20-40 s.

## (2) leaseorder-c: Cargo store/custody/recipe leases before the compiler writer, artifacts after it
Cause (leaseord's group C, confirmed in the violation registry: 7 pids × store-lease ×2, build-lease ×2, target-store, custody, target-recipe, artifact-capture, artifact): `repositoryCargoCompilerInputsV1` held `repo:compiler-writer:` (image 7) SHARED around the whole consumer body, and `buildCargoArtifacts` then took `acquireCargoTargetRecipeV1` (= `acquireCargoBuildLeaseV1` store/build/target-store/custody + recipe, rank 2) and published artifacts (`artifact-capture:`/`artifact:`, rank 6) inside it. With a fair queued exclusive writer W, A (writer shared, wants custody) → B (custody, wants writer) → W → A.
Fix (two-phase, as designed by leaseord): the neutral port view gains an optional `writer` offer (`CargoCompilerWriterV1`); `withCargoCompilerInputsV1` hands every continuation `withWriter(body)` (enters the offered writer with the continuation's own control, or runs directly when none is offered) and refuses a continuation that never entered an offered writer ("Offered Cargo compiler writer custody was never entered"), so no consumer can silently compile without it. `repositoryCargoCompilerInputsV1` now OFFERS `withCompilerWorkspaceSharedWriteV1` instead of wrapping the body. `buildCargoArtifacts`: planning + source admission + recipe lease outside the writer; `captureCargoArtifacts` enters it only around `withCompilerCapacityScopeV1` (lock check, cargo spawn, streaming, copy of finals into the capture dir: "capture inside"); `stageArtifacts`, provenance and `withCompletedCargoArtifactCaptureV1` run after it ("publish outside"; the store/build leases still protect the target dir, recovery runs under the writer and only retires lease-free cargo units). `🧩️component-pass` (`withNativeBuildCargoInputsV1`) and `🕸️wasm-build` enter the writer at the start of their body: identical to today (their build leases were already hoisted before the scope). Order now: config view (1) → registry (2) → cargo store/custody/recipe (2) → writer (7) → compiler capacity (3, declared edge image → compiler-capacity); then artifact (6) with the writer released. Policy unchanged (the declared order was right).
