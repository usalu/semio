Scope: every target of `brief-wave-1026g.md` (hot no-op, one-line edit, peer edits, graph after a peer edit, builder RAM, three agents on 16 GB, disk budget) plus the product-green requirement, measured from the gate-g product records g33-g48. All g49* records are excluded (CLI broken by an overflowing loader, reverted; see coordination 23:41/23:49). Records of g1-g32 are used only as the baseline. No product build, no git modifying command, no file outside this ticket was changed.

Sources: `gate-g-tools/run/g*.json|log` (304 records, extracted to `🗑️generated/targets/runs.tsv`), `result-peerrun.md`, `result-agents16.md`, `result-diskbud.md`, `result-harness3.md`, `HANDOVER-1027b.md`, `coordination.md`, plus live-tree checks listed in section 4.

Method (so the numbers can be re-derived):
- wall = `wall_s` of product.py. product.py uses an exact monotonic clock, so 8.3 s and 10.1 s are real values (see section 5 on the HANDOVER claim of 5 s steps). wall includes `queued_s` (capacity or graph queue).
- peak = `peak_tree_mb`, the process-tree RSS sampled every 5 s. It is a lower bound and tree-wide, not per process.
- executed = Bazel summary processes that are neither `internal` nor a cache hit (same rule as `agents3-g-tools/measure_lib.py`). A no-op means executed 0 and exit 0.
- memo served = log line `graph: N projects served from the memo`; plan reused = `[bazel] plan reused`.
- "Latest" = the last valid (exit 0, not killed, not a failure) record before the g49 break.
