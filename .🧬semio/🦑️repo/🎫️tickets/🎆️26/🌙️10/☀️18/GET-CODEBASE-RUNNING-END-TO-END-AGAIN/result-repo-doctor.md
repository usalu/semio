## What `bun repo doctor` does
`repo doctor [--json] [--fix [--dry-run]] [--only=<area>,…] [--strict] [--facts] [--lang=en|de]`. One shot, many agents, one worktree. It only reads (no lease, no capacity grant, never a heavy command; the only writes of a read are the capacity gate's own `sample.json`/directories, exactly like `repo capacity status`), runs the probes with bounded parallelism (4) and a per-probe time budget (8 s, tools 30 s), prints progress on stderr, cancels on SIGINT/SIGTERM (exit 130), and answers:

| area | what it reads | findings (severity by policy thresholds) |
|---|---|---|
| `tools` | tool registry (tool-iface) against what is installed | missing essential (error), missing, pin drift |
| `storage` | all 8 partition images: receipt, backing file, mounted?, free vs capacity and vs floor (graph 1 GiB), unsettled `.publication`, host disk free | below floor / low / full, detached, damaged receipt, backing lost, publication pending, host disk low |
| `leases` | repository lease directory (holders, waiters, blockers, cycles, order violations), the machine registry (stale rows, vanished lease dirs), queue tickets of dead pids | cycle, long wait (60/300 s), long exclusive hold (900/1800 s), deep queue, violations, stale registry, dead ticket / dead holder in front of waiters |
| `capacity` + `host` | machine gate: grants, waiters with their reason, headroom vs floor; memory pressure, swap, load, open files, attached images, governor switch | wait long, idle grant (reserved but unused), pressure/low memory/swap/load/files/images, governor off |
| `sessions` | agent session store of this worktree (agent-session set) | gone, crowded (8+ live), damaged |
| `graph` | published generation (`current.json`, manifest), implementation files newer than the generation | unpublished (error when a graph lease is awaited), damaged store, implementation newer |
| `dependencies` | pointers, ready/unready/missing generations, scope inputs newer than publication, superseded generations | unpublished, generation missing, inputs newer, orphans, dead unfinished builds |
| `caches` | dead-pid `p-<pid>` publications (count, bytes), retired roots still on disk, undeclared entries | dead publications (error when the graph image is below its floor), retired, undeclared |
| `processes` | process table filtered to the repo tool chain plus everything holding/waiting plus descendants | phase per process (waiting-lease/-capacity, holding, admitted, running, orphan), orphan holders, idle holders (0 % CPU in the whole tree) |

Every finding carries `severity`, `owner` (the lease class owner, the module, …), EN+DE text, and `fix`: `command` (the exact `repo` command), `automatic` (`repo doctor --fix --only=<area>`), `wait` or `ask` (names whom to ask, with the inspecting command). A separate **wait chain** section answers "why is my agent waiting": for each waiting process who it stands behind, the root cause (following the holder chain, states running / itself waiting / gone / unknown) and for capacity waits the biggest grants. Verdict `ok | degraded | blocked`; exit 0 when no error (`--strict`: no warning either), else 1.

`--fix` runs only the three repairs declared safe in `D/🔣️policy.json` (EN/DE safety text each): `caches-dead-publications` (p-<digits> dirs in the declared graph publication folders whose pid does not exist, quiet 60 s, links never followed, realpath inside the partition, re-verified right before `rm`), `leases-registry` (rows of dead/silent pids by the registry's own rule and folders of lease directories outside the checkout that are gone with no live row; directories inside the checkout are never judged gone because their image may be detached), `agent-sessions` (delegates to `collectAgentSessionsV1` with the owner's sandbox reclaim). `--fix --dry-run` lists; a real `--fix` re-reads and reports the new state. A law test keeps policy repairs, catalogue rules with `fix.kind: automatic` and the implemented repairs identical.

## Design (schema first, tool neutral, multi implementation)
- `D/🧬️schema/🔣️.json` is the contract (Protocol, Policy, Rules, Facts per area, Finding, Wait, ProcessRow, RepairResult, Report); `D/📖️rules/🔣️.json` = 46 rules (area, owner, allowed severities, data keys, EN/DE title/detail, fix), `D/📖️texts/🔣️.json` interface texts, `D/🔣️policy.json` thresholds/patterns/repairs. No default language: `--lang`, `SEMIO_LANGUAGE`, locale, otherwise both languages are printed.
- Probes (`D/🔎️probes/<area>`) read through ports (`D/🔌️ports`: clock, liveness, process table via `ps`/CIM, command runner, optional-module loader) and return facts; `D/🧮️analysis` is a pure function facts → findings/waits/phases; `D/🖨️report`; `D/🏃️runner` (parallelism, timeouts, cancellation, `--only` with support probes, repair flow); `D/⌨️command`. Optional sets (tool registry, agent sessions) are read through a loader that answers "not installed" instead of failing, so the doctor works before, between and after the other sets are applied.
- Secret-looking options/assignments in command lines are redacted before they enter facts/reports; commands are collapsed to `repo …` for display.

## Limits and decisions (said plainly)
1. Graph "stale vs implementation digest": the digest is of the bytes a loaded module set had, so it cannot be recomputed without loading the graph; the doctor compares file times of the implementation roots (`🏗️build/🕸️graph`, `👁️observation`, tests and fixtures skipped) with the pointer time and says "judged by file times". Dependency "current?": checks the scope's own `package.json`, `bun.lock`, `bunfig.toml` against the publication time; edits of member manifests (which also move the generation key) are not statted (2.8 k files) — `repo dependencies ensure` is the exact check. Dependency pins (per-generation pin leases) are not reported separately; a running build shows as the lease holder.
2. Boot-session rebind is reported as state only (`detached` = next `repo` command attaches it, `publication pending`, damaged receipt, backing lost); the doctor does not compare `image.json.bootSession` with the boot session because the rebind is no-rewrite (boot-sweep).
3. Stale queue tickets of dead pids are reported (`dead-ticket`, `dead-holder` when they stand in front of waiters) but **not** removed: retiring a ticket needs the claim-database proof of the lease layer, which waiters already perform; the safe repair covers registry rows, not tickets.
4. Windows / Linux execution not run: the process table parser for `ps` and for `Get-CimInstance` (JSON) is tested from recorded samples, the partition probe has the directory-host branch tested with `platform: "linux"`; `ps` runs with `LC_ALL=en_US.UTF-8` (`C.UTF-8` off macOS) so emoji paths are not escaped.
5. Test code spawns `python3` (oracle) and `sleep`/`true` (pid fixtures) with `Bun.spawn*`; tool-iface's test-only ledger will list these three files as new rows (`verify tool-spawns --prune --accept-new`). Production code spawns only `ps` / `powershell` (not registered tools).
6. Taxonomy/emoji laws for the new directory names (`🩺️doctor`, `🧮️analysis`, `🖨️report`, `🔎️probes`, …) and the `📋️build-owners` entry were not run (names reuse the style of `🩺️preflight`, `🧹️cache-gc`); the next `show projects` after apply registers the module.
7. `rules.severities` is a closed per-rule list; adding a threshold level means editing the catalogue and the fixture, the law tests then force the oracle and the fixture to follow.
