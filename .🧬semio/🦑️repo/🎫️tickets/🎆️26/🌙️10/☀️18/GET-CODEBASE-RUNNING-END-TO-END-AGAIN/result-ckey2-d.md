## Mechanism (all in the Bazel adapter, schema-first)
1. `🔧️tools/🏗️bazel/🎬️scopes/{🟦️.ts,🔣️.json,🧬️schema/🔣️.json}` (adapter-only module; the executor never imports it, so editing the table cannot re-key narrow actions): table rows `{id, roots, leaves, classes:[{select:{command,workerKind,executionKind,semioKind,owner}, traced:{processes,modules,reads,physical}}]}` (a row is one proven scope, its classes are the action classes whose traces it holds); a declared table that fails its schema never stops a build (every class keeps the full closure, a warning is printed, the law fails); a scope whose declared root or leaf an edit moved away (not admitted / ENOENT at capture) keeps the full closure for its actions with a printed warning instead of failing the run; `bazelActionClassV1` names a planned action's class with exactly the four facts the executor trace records; unlisted class => full closure (fail-safe default). `SEMIO_BUILD_IMPLEMENTATION_SCOPE=closure` forces the full closure for one run; `SEMIO_BUILD_IMPLEMENTATION_SCOPES=<table.json>` swaps the declared table for a candidate (the planner child inherits it).
2. `📜️script.ts`: `bazelScopeAssignmentsV1` (action id -> scope id; orchestrated/hermetic/noop never), `publishBazelImplementationV1(…, scopeIds)` publishes `implementation.<id>.json` per needed scope next to `implementation.json`/`adapter.json` (capture scope `static` = static imports + schemas + the row's roots + leaves; the planner child re-captures every scope and refuses a forged one), per-action manifest/fingerprint/BUILD `source`+`source_identity` use the action's own scope snapshot, continuous (launch) tasks too. Planner input/result schema got an optional `scopes` map; `ImplementationScope` (ckey-d's hand lists) removed from `🧬️schema/🔣️.json`.
3. DERIVATION (3 independent sources + trace): (a) TypeScript compiler API static closure of the executor entry, (b) independent Python walk (`🎬️executor/🧪️tests/🐍️oracle`), (c) cheap dynamic edges: the 12 literal `import()/require()` edges out of the static closure, those adding <= 8 files (7 of them: leases metadata, host-capacity handover, cache-gc launch, store reset + recovery, selection, caller child) are roots of every scope so a rare path never meets an uncaptured module; the 2 heavy ones (graph 66 files, invocation 25) are only in a scope when a class trace needs them; (d) the runtime trace of the class: traced modules not reached by (a)+(c) become roots, traced reads/physical captures not covered become leaves.
