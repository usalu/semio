## What was built (live)
`L` = `🧰️framework/🔨️modules/🏃️process/🔒️leases`, `O` = `🧰️framework/🛍️products/🦑️repo/🔨️modules/📚️library/⚡️caching/💾️storage/🔒️enforcement/📦️budget/📥️opening/🟦️.ts`.
1. **Idle retirement with queues** (`L/🟦️.ts` `retireResources`): a database goes only when an exclusive transaction succeeds (no holder), its `.queue` is an empty plain directory (no waiter; a ticket of a dead requester is reaped first by the claims sweep through its free claim), and both files are older than the idle period; the empty queue dir is removed after the database; orphan empty queues are removed too. New `retireIdleResourceLeasesV1(directory, control, timeoutMs, {idleMilliseconds, nowMilliseconds, maximumCandidates, admissionPatienceMs})` (slice with persistent cursor, result `{examined,retired,allocatedBytes,queues,kept,complete}`); `retireResourceLeasesV1` keeps its old shape and immediate semantics (existing tests unchanged).
2. **Use clock**: `touchResourceLeaseUseV1` stamps the database mtime on acquire and before close on release (ordinary resources only, only when older than `useResolutionMilliseconds` 60 s, so a fresh file is never rewritten; the existing "foreign catalog stays unchanged" test still passes).
3. **Race-free recreate**: the queued acquire creates the `.queue` dir inside the shared claim catalog section (`mkdirSync` moved after `queueClaimCatalog`), which retirement holds exclusively; the directory admission gate (exclusive during a slice) already fences database opens. A waiting acquirer holds nothing, so it simply recreates what was retired.
4. **Incremental sweep** `L/♻️retirement/🧹️sweep` (`sweepResourceLeaseStoreV1`): claims (4 turns) -> resource slices (8 x 64, under pressure 8 x 256) -> nested stores; budget 3 s; progress rows `lease-sweep:<stage>` through the control, cancellation and deadline honoured between candidates (cursor persisted per slice), busy gate => postponed (returns `busy`), unknown failures are printed in EN/DE by the opener and never fail it. Pressure (free < 20 %) shortens idle to 60 s and the stamp interval to 30 s.
5. **Nested stores** `L/♻️retirement/🧱️nested`: an abandoned lease directory below the lease directory is retired when every entry is a recognized lease file (hash databases <= 16 KiB, queue dirs with canonical tickets, `claims/`, headroom file, `.retired`), nothing in it was used for 1 h, its dead tickets/claims/resources retire through the ordinary protocol, and the kernel grants BEGIN EXCLUSIVE on all its databases at once (any holder, waiter with live claim, foreign file or recent use keeps it).
6. **Trigger**: `O` `openRepositoryLeasePartitionV1` no longer needs exclusive image maintenance; when the cross-process stamp `data/.retired` is due it sweeps (EN/DE `[repo leases]` line when a pressure sweep retired something). `leaseRetirementFreshV1` got an `interval` parameter.
7. **Messages EN/DE**: `L/♻️retirement/🧬️schema/🔣️.json` `Messages` (swept, pressure, busy, cancelled, failed) + `formatResourceLeaseSweepV1/FailureV1`. README (EN and DE) section "Retirement of idle leases".
8. **Sizing from need**: ledger need `leases` in `💾️storage/🧾️ledger/🔣️policy.json` (resources 1,536 x 8 KiB, claims 2,048 x 12 KiB, headroom file 4 MiB, 3 nested stores x 4.06 MiB; +10 % headroom; floor 4 MiB = one claim turn of 256 x 12 KiB) = 61.4 MiB required <= 64 MiB declared (slack < 16 MiB); the entry bytes live in the retirement schema `Store`; area `leases` is `recreate: derived`. A larger image later = exclusive-ticket recreate (waits for every holder, nothing to carry: an idle entry is recreated on demand); the declared 64 MiB was NOT changed (an online resize of an attached image fails and a size mismatch refuses every opener).
