## 4. Findings worth knowing
* `uv` rejects `--managed-python` together with `UV_PYTHON_PREFERENCE` (clap conflict): the styling builder passes the flags, the plan-driven callers set the variable; never both.
* uv ignores a symlinked directory in `UV_PYTHON_INSTALL_DIR`; managed interpreters must be real directories.
* `go.work` 1.26.9 with `GOTOOLCHAIN=local` makes a Go older than 1.26.9 fail every Go command. This machine has Go 1.25.0 at `~/.local/go` (stale, first on PATH).
* A directory-chain check up to the filesystem root (as the binaryen preparer does) fails under `/var` and `/home` symlinks; the new preparer checks only between the tools root and the target.
* The cross-platform law runs `git` on the checkout; the process envelope tests cannot run outside `repo test`.

## 6. Incident disclosed
While verifying I exported `GIT_DIR`/`GIT_WORK_TREE` for one law run. The law's own `git init` wrote `core.worktree = /private/tmp/langs-conc/ov` into the REAL `.git/config` (and appended `core.longpaths = true`, which the repository's own setup also sets). Detected at 01:03, the single line was removed at once (`core.worktree` unset, `git rev-parse --show-toplevel` correct, no commit and no ref moved in the window: HEAD reflog ends at 15:04 yesterday; the remaining ref/FETCH_HEAD changes are the 60-second background fetch of the user's git client). The real index was refreshed by my `git status` with the wrong worktree, which costs one full stat rescan on the next status and changes no content. `core.longpaths = true` was left in place (it is the repository's intended setting). Since then the overlay owns an isolated repository whose index mirrors `git ls-files -s`; no `GIT_*` variable is ever exported again (`overlay.py` and `run-all.sh` strip them). Lesson for every verifier: never point `GIT_DIR` at the real repository for a test that runs `git init`, `git clone` or `git config`.
