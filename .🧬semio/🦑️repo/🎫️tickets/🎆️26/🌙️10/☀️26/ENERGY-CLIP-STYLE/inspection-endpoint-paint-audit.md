## Existing Clock And Settling Behavior

Browser MJS installs and pauses a virtual clock before loading the UI, waits for fonts/images, remounts canonical frames, runs the frame elapsed time, pauses DOM animations at explicit currentTime, and allows up to4additional34mssteps until silhouette geometry matches. The settled predicate checks window border/content silhouette geometry; it does not compare background paint or require consecutive screenshot identity. Therefore a successful settled check is not proof of exact fresh-process backdrop pixels. No cheap native-paint cause is conclusively isolated by the available evidence. Merely adding another arbitrary delay is not an exact endpoint guarantee.

## Clean Exact Boundary Guarantee

A persistent content-addressed canonical actual-UI raster is a justified boundary asset: key the complete catalog, locale, viewport/device scale, actual browser/UI/CSS/font/SVG dependency identity, canonical ancestor prefix and parked cursor state. Generate it through the real UI, store PNG bytes plus a checksum under an owned cache, publish atomically, validate checksum/dimensions before reuse, and ensure concurrent writers cannot expose partial bytes. Both adjacent chapter endpoints must request that same key and consume its exact stored bytes. Current source/provenance checks must still reject changed inputs; the cache is not a certificate for stale media. Restrict reuse to declared settled boundaries, leaving actual navigation animation and authored body frames untouched.

Native deterministic painting remains preferable if a focused metadata/paint test identifies a concrete fix, but the present evidence does not justify claiming that clock/geometry settling alone guarantees exact process-independent blur pixels. No production edit was made.
