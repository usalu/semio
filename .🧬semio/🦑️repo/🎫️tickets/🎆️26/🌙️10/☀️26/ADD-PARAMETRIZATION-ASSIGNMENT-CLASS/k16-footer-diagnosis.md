# Native Footer Resource Diagnosis

Three fresh native assignment builds failed before the first page shipped with `Argument of \\@tempa has an extra }`. A retained diagnostic driver, k16-header-trace.tex, set errorcontextlines to 999 and imported the original geometry and German content. Its stack isolated the failure to SemioFooterLogoChips, through the logo-height wrapper inside the footer chip. The authored header API was unrelated and remains intact.

The retained k16-logo-probe.tex separated the dark filename parser, path resolver, direct includegraphics call, and height wrapper. The dark parser correctly produced the dark sibling pathname. The resolver correctly selected the existing light PNG when the dark sibling did not exist. A raw includegraphics call using the literal canonical Unicode PNG path reproduced the same error; quoting the pathname did not fix it. This excludes a token-list expansion bug in the logo wrapper. The PNG has a valid PNG signature and dimensions 444 by 131 pixels, with 34,697 bytes.

The actual product compiler uses source-staging/🟦️.ts printCompilerName to strip the semantic emoji prefix from every path segment, and printSourceReferenceTextV1 to rewrite TeX references to those compiler names. The newly nonempty default footer path in semio-core.sty exposed the difference between that established compiler input and the raw direct CLI verification. No production logo or header source was edited. The root agent owns preparation of equivalent derived compiler inputs and ASCII resource aliases for native verification, without copying the authored checked source tree or changing resource bytes.

Retained probe inputs intentionally reproduce the raw-CLI refusal. Their logs and any rendered outputs are temporary under the ticket generated folder and are removed by the parent at completion.

Final probe passed with the derived compiler input first in Tectonic's search paths (and repeated last). Its DEBUG roster proves the projected path was consumed: assets/logo/luh/☀️logo.png. Both raw-BMP start and end markers were reached and a one-page PDF was emitted. The BMP leaf name is supported; the earlier derived full pass had selected the original semio-core because the derived search path came last. No production style change was required. The root uses a directory junction to preserve resource bytes and original file link counts.
