# Ordinary Tool Execution and Live Publication Authority

Ordinary repo tools exec does not create the native build Original that the actual compilation script requires. runBuildCliV1 handles tools exec/list before its ordinary runAdmittedBuildCliV1 Original birth. The tool registry resolves the executable, sanitizes its environment and supplies a host capacity grant when requested; it does not issue a native Script process envelope. Capacity admission and native source/storage authority are distinct.

A read-only scalar probe through repo tools exec light Bun reported hasOriginalWire=false and hasCapacityGrant=false. Under normal-budget execution the latter can become true, but the reviewed source has no native-Original issuance path. No wire contents or capabilities were printed.

The actual compilation script calls receiveScriptProcessInvocation, which requires an actual parent Script process envelope and rejects an absent wire with Original parent Script process invocation required. Its new router correctly derives the workspace from the received genuine native caller authority; this improvement does not create that authority.

Therefore a normal-budget tools exec of the actual script alone cannot establish canonical live publication outside the global planner. An already-authorized parent may project its genuine Original into an owned child using the existing API, as the private test does, but inventing a standalone capability wire or adding an ad hoc issuer is outside this task. No such mechanism was added. The canonical live CLI publication gate remains separate from successful private production-function/script integration. No heavy command was launched during this review.
