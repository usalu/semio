# Production Publication Under the Declared Test Issuer

## Authority

The existing repository library native-birth module registers the native-build-caller test issuer. Its capabilities callback calls createBuildBootstrapCapabilitiesV1 with the test envelope's exact declared command; it does not fabricate capabilities or execute the global graph. withBuildTestInvocationV1 supplies a genuine Original. Print operations then require the exact issued control associated with that Original, verify the native caller authority and checkout identity, and open only their declared storage roles. Production publication and artifact destination interfaces continue enforcing all their existing authority, lifetime, finite-path, source-recheck and physical-artifact checks.

A Print test envelope declaring the actual test-thesis-render command can therefore exercise the actual production compiler/publication APIs. The publication owner string is carried in the artifact manifest and validated by the reader; it is not required to equal the outer test command. This is the existing publication contract, not a bypass. The contract agent implements the durable declared test entry and independent issuer audit owns final birth-boundary review.

## Explicit Prerequisites

Open withPrintExecutionV1 with kind=document and the genuine Original/issued phase. Its role stores include dependencies, tools, products and diagnostics. Call preparePrintMaterialV1(execution.operation, kind, execution.phaseControl) sequentially for tectonic, tex and fonts. There is no hidden preparation in the compiler.

Tectonic preparation verifies the pinned host distribution and archive/binary SHA256 receipt. TeX preparation verifies the locked range bundle and SHA256SUM/file roster. Fonts preparation validates the tracked OpenType roster, font source bytes and metrics identities, then publishes the fixed font slot. Existing valid artifacts are read/rechecked and reused; missing or outdated tectonic/tex inputs require the native caller's authored online grant. Fonts require no network. No fresh runtime dependency or ad hoc compiler installation is needed.

## Exact Publication

Call buildRegisteredPrintTemplate(execution, id) for thesis and phd serially. It reads the existing registered catalog document and calls publishPrintArtifact with kind=document, namespace=print, exact registered sourceRoot/texPath/sources, dark=true and producer @semio-tech/print:build-ID. The same production source staging, shared LaTeX library, compiler, bibliography/intermediate processing, panel processing and dark-source derivation run. The publisher validates PDF signatures and source/material freshness and stages the actual canonical mode-dependent product slot through withRepositoryArtifactDestinationV1/stageRepositoryArtifacts.

Consumer filenames are thesis.pdf, thesis-dark.pdf, phd.pdf and phd-dark.pdf; compiler-staged source filenames do not change these canonical output names. This route produces the actual authored template artifacts, not probe substitutes.

Read each pair with withPublishedPrintDocumentV1(execution, print, id, canonicalProducer, callback). The accepted artifact exposes path/files/control/recheck, validates the manifest owner and fixed directory, and permits at most two PDFs. Read bounded bytes using readPrintMaterialFileV1 and consume them through inspectPrintPdfV1 while holding withPrintScratchV1's real destination and the artifact reader/control. Keep the reader callback open until PDF.js inspection settles and call artifact.recheck.

## Inspection Limit

The current independent Print PDF.js snapshot exposes page text, geometry, fonts and operators. It does not expose PDF Info metadata, and the pipeline openPrintPdf helper has no getMetadata method. It can validate actual authored content and both editions, but claiming verified pdftitle/pdfauthor/pdfkeywords Info values would require a deliberate schema/worker extension. No unsupported metadata reader or raw-parser substitute was introduced.

## Evidence Scope

This is a source-level feasibility proof; no heavy command was launched in this investigation. It does not itself establish compiler success. Actual material preparation, unchanged full render matrix, and retained thesis/doctoral light/dark publication must run under the declared test issuer and normal host capacity scheduling.
