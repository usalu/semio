# Plane Fragment Ordering Kernel

## Current strict-normal correction and proof

The current kernel retains the strict `Face.normal` actual-plane contract. Split planes are recovered internally from maximum-area cross products of LOCAL vertex differences and aligned to the supplied orientation, while the supplied normal is preserved verbatim in output Faces. Supplied normals must still place every actual source vertex within the original 64-ULP normalized plane-distance bound. No geometric epsilon increase or metadata angular allowance remains. The caller must supply a stable geometric normal for EACH original polygon, preserving any approximate bucket/lighting normal separately.

The actual capital preparation-only proof rejects 389 original approximate Item-bucket normals as intended. Independent NumPy local cross normals accept all **2,602/2,602 actual original polygons**, with no preparation errors and exact source/export endpoints unchanged. This proves input compatibility; it does not claim actual BSP ordering or rendering acceptance.

Current permanent suite: **7 tests pass in 7.773 s with exact endpoint hashes unchanged**. AJV accepts seven portable scenarios and rejects five malformed contracts. The exact source-index46 test first failed on its supplied normal, then now proves raw-normal rejection plus corrected local-normal acceptance and NumPy SVD agreement. The quadratic-validation test first observed 54 turn calculations before cancellation; the current inner pair check cancels before any pair turn calculation. Collapsed 3→1 and 3→2 boundaries already raised ValueError; the permanent cases preserve that behavior without claiming a speculative bug fix.

An intermediate kernel experiment allowed a separate coordinate-conditioned metadata-normal angular bound and accepted raw approximate normals. Root selected the cleaner strict actual-plane contract; that experiment and its earlier proof are superseded and are not current acceptance evidence.

## Initial implementation chronology

Portable schema/cases were authored before implementation: crossing quads, a genuine three-surface occlusion cycle, concave U with disconnected cross-section material, coplanar ties, empty input and progress/cancellation. Source and polygon IDs plus original normal survive every convex split. Runtime is Python standard library only. Only actual face planes may partition material. An iterative BSP build and far/coplanar/near traversal avoids recursion limits.

## Original API and geometry (unchanged except the strict-normal clarification above)

`Face` is a frozen project-owned dataclass with integer `source` and `polygon` IDs, tuple-of-3-tuples `vertices` and a preserved 3-tuple `normal`. `ordered_fragments(faces, towards, progress=None, cancelled=None)` returns a tuple of Faces. `FragmentCancelled` reports explicit cancellation. `source_files()` returns the implementation and schema paths. There is no NumPy, Manim, renderer, physical-model or other third-party runtime import.

Each original actual material polygon is a separate input Face. Holes and disconnected material are represented by separate actual boundaries; concatenating an Item vertex buffer is forbidden. Convex polygons stay whole until an actual source plane crosses them. Concave simple polygons are ear-clipped without inventing material; resulting triangles retain source and polygon identity. BSP nodes use only those actual face planes. Plane splitting preserves every source polygon area; traversal is far/coplanar/near according to the source plane normal dot the orthographic camera direction. Opposed normals are preserved, not discarded or silently reversed. Coplanar ties sort deterministically by source/polygon/vertices/normal.

Both build and traversal use explicit work stacks; the permanent 1,050-plane case exceeds the usual Python recursion limit. Progress is a phase-local `{phase, completed, total}` event; partition totals can change as actual fragments create nodes. Completion reports final output count. Cancellation is checked during preparation, boundary validation, ear clipping, partitioning, traversal and progress dispatch.

## Numerical policy

Normalized source-plane distances use 64 ulps at the actual coordinate scale solely to classify floating-point roundoff. Projected polygon area/turn tests use that distance bound times actual projected span. Segment intersections use actual signed plane distances and linear interpolation; no proxy planes, quantized coordinates, colour changes, material filters, forced face tiers or fragment budgets are used. Input must be finite, planar and simple with positive material area and a nonzero normal; invalid nonplanar material is rejected before BSP work. This is a floating-point geometric kernel, not exact rational arithmetic.

## Validation and red chronology

Schema/cases preceded code; initial execution failed because the module did not exist. The first three tests passed in 7.220 s after implementation. Additional nonplanar input exposed self-plane nontermination; the exact own red test process was explicitly stopped and the input validation was added. The permanent current five tests pass in 9.880 s with identical exact endpoint source maps. Strict AJV accepts all seven portable scenarios and rejects five malformed contracts.

Independent oracles are NumPy plane solves/even-odd ray membership and vector area, plus exact Pillow per-source union masks. Tests cover mixed-sign crossing quads, a three-surface projected cycle, a concave U split across both arms, separate polygons with one source identity, opposed winding/normal coplanar ties, empty input, two rotated orthographic camera bases, dense source rays, area/coverage, immutability, progress and cancellation.

## Integration responsibility and limits

GH owns renderer integration: map each Face back to its original source/polygon style and use its new fragment vertices. Original whole-polygon draw closures cannot draw a fragment. New internal split edges must not gain outline strokes. The kernel proof establishes the portable cases and geometry invariants; actual capsule/capital source exports and final Cairo/ray validation remain GH-owned integration evidence. No existing framework module, physical M source or renderer was overwritten by this kernel task.
