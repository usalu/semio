# Bounded Native Replay Workers

The portable native-pairs.json plan names all nine scene classes, both explicit languages, 12 Grasshopper contracts and 19 Excel contracts. AJV validates the plan and rejects three incomplete variants. The driver and recorder parse successfully. No native completion follows from preparation alone.

replay-native-pairs.py runs contracts in one fresh repository-owned worker, then launches one fresh worker per scene. That worker replays English and German through the existing validate-scenes.py interface, keeping the existing per-pair output directories, complete dependency maps, runtime identities and lifecycle assertions. verify-native-ledger.py still independently requires all eighteen current pairs and both contract results.

This replaces the earlier full-series in-memory batch plan after the cache review identified a concrete retention risk: _TOWERS strongly holds up to eight whole drawing trees, which per-pair garbage collection cannot release. Process boundaries release those caches after each scene; EN/DE reuse within a scene and managed disk font caching remain. No private production-cache mutation or new lifecycle API was introduced. See native-batch-cache-review.md.

Every child command is invoked through repo tools exec uv using the current teaching interpreter, the ticket-owned verify.py wrapper and an argument vector without shell composition. Complete child output is streamed and retained under the ticket generated folder. The recorder fingerprints the driver, plan, schema, acceptance registry and wrapper.

The complete all-scene contract map supplies the frozen baseline. Before and after each scene worker and each language pair, the driver checks source hashes and interpreter/package versions; each scene worker additionally checks rendering configuration. It aborts on drift rather than selectively reloading cached code. Successful pair maps must be contained in the full baseline. Temporary-directory selection is reset for each pair, scene probes remain fresh and cycles are collected.

Native replay remains on hold until current source-fragment ordering, performance and final captures pass. The earlier source-only full-series audit is historical design review; the bounded-worker source still receives final independent review before execution.
