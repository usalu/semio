# Storyboard: grasshopper_capsule (`Beat2_Capsule`, topic 💊️capsule)

Series 🦗️grasshopper, scene file `G/💊️capsule/🐍️.py`. Both languages are authored natively. The English Grasshopper component names stay in German narration (Number Slider, Center Box, Solid Difference, Orient, List Item, Plane), concepts are translated (Parameter, Abhängigkeit, Grundebene, Zielebene).

## Learning goals

1. "Parametric" means: parameters (sliders) feed dependencies (components, wires) that build geometry. Change one value and everything downstream follows.
2. One capsule is built in a fixed order: base plane, Center Box, rounded edges, circle on the front face, Solid Difference window, four bolt points on the back face.
3. Slider domains are design constraints (e.g. a transport size limit), not decoration; the capsule types are variants of one definition, only the parameter values differ.
4. A plane is an origin plus X, Y, Z axes (Rhino colours red, green, blue); Orient moves geometry from a base plane to a target plane, so rotating the target rotates the capsule.
5. List Item picks one type per plane; the index wraps around the list length, so any number of planes can be served by four types.

## Misconceptions addressed (research-grasshopper.md section 7, 1.1, 1.2)

- A wire does not create geometry: the circle needs a plane on the front face, a circle on the base plane lies on the floor (typical mistake, shown and fixed).
- A slider has a domain (lower/upper bound) and a rounding; values outside are impossible, not an error.
- Red component: the first red node upstream is the cause; the capsule disappears, and returns when the slider is back in the domain.
- Index in List Item is zero-based and wraps (modulo list length); it is not an error to ask for item 5 of 4.
- Orient moves geometry by the transformation base plane to target plane; the geometry itself is not redrawn by hand.

## Notes for implementation

- "Teaching model" is said once, in clause 14 (types), and the teaching-model note stays in the corner as in the BIM clips.
- Each clause is one visible change; the voice-over clause durations come from the `step` seconds.
- Every number (dimensions, window, bolts, domains, transport limit, type values, plane origins, facade angles) is read from the nakagin model or the engine solution; the scene never types a building value. The transport limit is a model value (`capsule` domain upper bounds); if the model has none, the domains are the limit.
- The canvas shows the real component names: Number Slider, XY Plane, Center Box, Fillet Edge, Circle, Plane, Extrude, Solid Difference, Point, Orient, List Item, Panel.
