# Audit: grasshopper_casting, Beat4_Casting (en and de)

Scope: all 21 keyframes per language (42 PNG, 1280x720) read with the Read tool. Narration (en and de) checked against `T/research-casting.md`, the scene file `🎓️teaching/🏛️architecture/🦗️grasshopper/🎬️clip/🫗️casting/🐍️.py`, the casting rules in `🎓️teaching/🏛️architecture/🦗️grasshopper/🎬️clip/🧱️model/🔣️.json` (`casting.rules`), the Nakagin model `🎓️teaching/🏛️architecture/🏢️nakagin/🔣️.json`, the storyboard `T/storyboard-grasshopper-casting.md` and the plan row `T/plan.md`. Layout findings in `🗑️generated/frames/🦗️grasshopper/Beat4_Casting/{en,de}/layout.md` were checked against the pictures.

## Verdict

Not ready to render. One blocker: the central rounding example (10.6 becomes 11; 2.5 becomes 2, 3.5 becomes 4) is presented as verified with no marker, while `research-casting.md` section 3 says non-tie rounding is unresolved, ties are not to be taught before a Rhino 8 test, and a 2012 Rutten statement (chopping off the decimals) contradicts it. The model rule `Number>Integer` is set to `verified` and that overstates the research. Several majors follow: community-level Point and Line to Plane claims (exact axis orientation unverified) are drawn without marker, the Orient `A` input is unwired on the explicit-plane canvas, the integer-to-boolean frame mixes a Number slider with an Integer title, the Text to Number success path used by the Value List fix has no marker, the German frames quote the English error message, and yellow or orange labels fail contrast on light backgrounds. The German text has about eight grammar or wording fixes.

Counts: 3 blocker rows (storeys, ties, and the matrix cell "10,6 → 11"; all one claim), 14 majors, 17 minors (frame table, about 34 rows); 10 fact rows (4 pass); 7 didactic findings.

Severity: blocker = a claim on screen contradicts or outruns the research; major = unmarked unverified claim, wrong or misleading canvas, broken quality rule; minor = polish. "en+de" = same defect in both languages.

## Didactic findings

1. Arc holds: hook, mismatch, text_number, order, storeys, ties, deliberate, point_plane, wrong_way, line_plane, explicit, domain, circle_curve, box_brep, bool_int, int_bool, fail, fix, matrix, matrix_fill, recap. Smallest examples come first (text 2.5, then 10.6, then Type A), the typical mistake (Point as Plane, wrong way) is shown and fixed (explicit), and the failure is shown and fixed (Value List).
2. The storyboard misconception "Number to Integer cuts off the decimals" is itself unproven: the 2012 Rutten statement says chopping. Teaching it as the wrong idea while the clip teaches rounding as fact is a double risk. Show the test result instead: "10.6 became 11 in our Rhino 8 test", once tested.
3. Plan row items missing or changed: "2.3" (see fact table); "integer to boolean (window on/off)" is shown with a Number slider; "casting matrix built up from what was shown" is present, but the Integer row is empty and Integer to Boolean is not a matrix cell.
4. Round and Ceiling are promised in the ties and deliberate captions but only Floor is shown. Either show one more Round or Ceiling example (one line on the canvas) or say "Floor, for example".
5. The fix frame hides the mechanism. The Value List item name ("Type A") and its expression (2.5) are different things in Grasshopper; the frame shows only the name. Show the expression, otherwise students learn "a Value List reads the label".
6. "A cast changes data silently" (recap) and "Casting is harmless" (storyboard misconception) conflict with the loud failure shown on fail. Replace with "successful casts give no message".
7. Accessibility is part of the lesson: the marker that tells students what to check is itself low contrast (see the contrast row). Fix that before relying on it.
