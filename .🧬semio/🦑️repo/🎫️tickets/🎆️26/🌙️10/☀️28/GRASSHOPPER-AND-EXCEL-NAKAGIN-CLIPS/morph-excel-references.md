## Identity chains (the thread of the video)

- **Width chain (W)**: width dimension line on the type A capsule -> value token `2.50 m` -> cell B2 (blue frame) -> `B2*B3` formula token -> D3 value -> hatched roof face -> bar. One object keeps its blue (width) and red (length) colour from the dimension line to the reference frame to the formula text.
- **Surface chain (S)**: a capsule face (floor, wall, window, back) -> its row in the sheet (C label + D area) -> F value token -> the same face lit by its U·A or loss tint. The face's tint colour is the number.
- **Type chain (T)**: a small capsule of type A..D (teal, orange, green, red from `type_color`) -> sheet tab -> sheet-name chip `'Type C'!` in the formula -> B13 value -> sum -> shard when deleted. The type colour stays on the chip.

## Rules for the implementation

- Replace the fade-swaps `FadeIn(win2)/FadeOut(win)` in relative, total, fixed, absolute, slide, repair, mixed2, mixed, sheet, stuck, pertype, threed, deleted, guard by window stays (`recalculate` / `select`) plus the object morphs above; windows may stay put and only the sheet/range changes.
- Heavy objects: `proxy()` of the tower; `silhouette()` per capsule/face; the count morphs (M12) use at most 14-22 `silhouette`s per cell.
- Take every number from the engine (`_cell`, `shown`, `evaluate`); the counts of towers A/B and per type come from the model (`_type_slots`).
- Mid-frame legibility: in M6, M9, M11 the in-flight token must still read as a number (use `morph` with the number text as `src`, not a scribble); in M12 the flying capsules keep their type colour.
- Keep tests: scene contract (narration keys, 14-24 clauses, en+de), presentation contract, `X/🧪️tests/🐍️.py`.
