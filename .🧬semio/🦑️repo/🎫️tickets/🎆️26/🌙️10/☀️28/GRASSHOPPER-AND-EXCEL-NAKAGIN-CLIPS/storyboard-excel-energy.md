# Storyboard: excel / energy (`Beat4_Energy`)

Video `excel_energy`, file `X/⚡️energy/🐍️.py`, title en "Heating Demand in the Nakagin Workbook" / de "Heizwärmebedarf in der Nakagin-Arbeitsmappe".
Series module: `📊️excel/🎬️clip`. Tool side = Excel workbook window (`xl_window`), building side = Nakagin capsule drawing (`capsule_axon`) and tower drawing (`tower_axon`).
Every number comes from the Excel engine (`evaluate(workbook)`) which is cross-checked against `🏢️nakagin.envelope/heating`; nothing is typed in the scene.

## Learning goals

1. Read a per-type sheet as a calculation chain: dimensions -> surface areas -> U-values -> U·A -> H_T -> H -> Φ -> Q.
2. Know why exposed and attached faces are treated differently (attached back face to the heated core: no loss in the teaching model) and see it on the capsule (solid tint vs diagonal hatch).
3. Use SUMPRODUCT (en) / SUMMENPRODUKT (de) for H_T = Σ U·A, defined names (θ_i, θ_e, HDD) across sheets, and sheet multiplication by type count.
4. See one input cell (window U-value) drive every dependent cell, arrow and total, with the dependency chain drawn as trace arrows.
5. Explain the specific demand kWh/(m²·a) per type through the surface-to-volume ratio: the small capsule loses through five exposed faces but offers little floor.

## Misconceptions addressed (research-excel §7, research-nakagin §4)

- Pasted values freeze a result and break the chain (research-excel 7.2): a typed total on the Energy sheet does not follow the what-if.
- Relative vs absolute vs named references: climate values are read by name, not by cell address that shifts (7.3).
- A displayed value is not the stored value: `5.00 W/(m²·K)` is 5 (7.1); units are labels in the number format, not part of the calculation (6.4).
- All six faces count as loss: the back face is bolted to the core and is no envelope loss in this model (research-nakagin 4.2 "shared-wall effect").
- Bigger demand per m² means worse insulation: it can be geometry alone (surface-to-volume ratio).
- Annual demand in kWh needs ×24 h/d and ÷1000 (Wh -> kWh): units checked, not guessed.

## Assumptions (stated once, "teaching model")

Simplified, rounded teaching model: steady state, no solar or internal gains, core side treated as heated (no loss), U-values and air change rate assumed, climate Tokyo with heating degree days (base 18 °C) and design outdoor temperature assumed, not measured. Window U-value 2.3 W/(m²·K) is the double-glazed value (Tokyo guideline 2019, sourced), the what-if starts from single glazing 5.0 W/(m²·K) (assumed) and improves to 2.3. All values carry their basis chip sourced / assumed / derived from the model JSON.

## Colour code (reused from the BIM / energy visual language)

- Inputs (constants, blue DATA) · formulas (INK) · results (GOOD green) · assumed values (WARN amber chip).
- Heat flow arrows in SERV (warm red, as in the heating energy lessons: arrow length and stroke width proportional to U·A, outward through the face); ventilation flow in a lighter cyan-grey arrow pair through the window.
- Exposed face: tinted fill in the colour of its table row; attached face: grey diagonal hatch (core side), as on the capsule drawing of the program video.
- Reference frames and trace arrows in the toolkit colours; frames share the colour of the face they compute.

## Notes for implementation

- All formulas are authored in canonical English in the model; the visible text uses `localize(formula, language)` (SUMMENPRODUKT, `;`, decimal comma) and `display(value, number_format, language)`.
- Sheet names (Type A…D) and row captions are bilingual from the model; the scene never types numbers.
- The attached/exposed flags, UA split, ventilation and shape ratio come from `🏢️nakagin.envelope/heating` through the workbook cells; the what-if uses `apply(workbook, events)` with a "set cell" event on the window U-value input; the ValueTracker ramps the displayed input while `evaluate` provides every dependent value (sampled once per frame, cached by tracker value).
- Narration length target: 3.5 to 5 minutes; clauses 13, 14 and 18 are the longest holds; each clause is one visible change.
