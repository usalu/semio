# Storyboard: grasshopper_anatomy (`Beat1_Anatomy`)

Title: en "Anatomy of a Grasshopper Script" / de "Aufbau eines Grasshopper-Skripts". Scene file: `🦗️grasshopper/🎬️clip/🦴️anatomy/🐍️.py`.

## Learning goals

1. Name the parts of a script: definition (.gh), canvas, component (name vs nickname, input and output params, grips, wires, preview), parameter (floating vs component param, type).
2. Read and set the input objects: Number Slider (domain, decimals, value), Boolean Toggle, Value List, and inspect data with a Panel.
3. Read component states: grey = fine, orange = warning, red = error, and find the first one upstream.
4. Know that a plugin (.gha) adds a ribbon tab and components, installed through the Package Manager (Food4Rhino).
5. Tell item, list, tree apart and read an address: path `{0;0;3;1}`, branch (Ast), index.

## Misconceptions addressed (research-grasshopper.md section 7)

- A wire does not create geometry; it only carries data of a type (a text "tall" is not a height).
- Orange is a warning, not a failure; red is the first thing to fix, traced upstream; grey downstream is not proof of correctness.
- A Panel shows paths, not just values; `{0}` and `{0;0}` are different structures.
- Reading a tree as one long list: the item index alone does not say which capsule; path plus index does.
- A floating parameter is not a component; a component parameter belongs to a port.

## Stage layout (every clause)

Left: Rhino viewport (Perspective) with the Nakagin capsule (`NakaginDrawing`, x about -6.6 to -0.4). Right: Grasshopper canvas (x about 0 to 6.7). The viewport and canvas share colours: every wire/slider has the colour of the dimension line or highlight it drives (width = yellow, length = cyan, height = green, window = red, tower items = orange). Teaching model note appears once in clause 1 (top-right corner, as in BIM). Component names are real Grasshopper 1 / Rhino 8 names in both languages; German keeps the English UI names.

## Didactic arc

Hook on the capsule (1–2) → smallest example: one slider into one box (3–9) → states and the error case (10–11) → Panel, params, other inputs (12–15) → plugin (16) → structure from item to list to tree (17–21) → recap legend with German equivalents (22–23) → outlook (24). Typical mistakes shown and fixed: red text-to-number (11), tree read as a list (21).

## Open dependencies

Engine canvas `anatomy` (slider, Center Box, Series, panels), toolkit widgets (`gh_slider`, `gh_component`, `gh_panel`, `gh_ribbon`, `gh_viewport`, `gh_bubble`, `gh_param_viewer`) and `NakaginDrawing` (`capsule_axon`, `tower_axon` with `lit`). Numbers in the table (2.5, 4.0, 1.3, 2.75, 9, 11, branch path) are the intended model values; the scene reads them from `🏢️nakagin` and the engine. Ladybug stays qualitative (no sun-hour numbers) because the teaching model has no solar model.
