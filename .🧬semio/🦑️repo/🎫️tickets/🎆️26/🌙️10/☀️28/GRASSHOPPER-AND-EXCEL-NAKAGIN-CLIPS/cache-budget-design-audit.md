# Independent Cache Budget Design Audit

Reviewed cache-budget-design.md, native-batch-cache-review.md and the actual renderer declaration/tower factory path. Renderer raw SHA256 remains 4d1d855d72e36263b8fa79402de86abb437f869fa61bf93f65b8cca42bc7edc2.

The design is suitable for implementation with the acceptance clarifications below. Actual source confirms a process-global strong _TOWERS root, insertion-order eight-entry eviction, coverage replacement whose old value survives the factory call, and a canonical rich template retained while its clone is materialized. Instance-owned explicit contexts remove this independent retention root. The design correctly distinguishes this causal mechanism from unproven attribution of process RSS. The observed 443 MB available memory under concurrent GH approximately 26 GB, capture approximately 7.6 GB and Excel approximately 11.4 GB is an aggregate admission failure, not a measurement of cache occupancy or cache-specific bytes.

Default limits of eight entries, 1000000 members and 10000000 points are honest resource policy, with optional public control. Two measured 759230-member templates cannot coexist retained. Actual point cost is still unmeasured. Oversized direct return without clone preserves geometry and avoids an unnecessary second rich object graph. It cannot prevent the first oversized construction or bound caller-owned drawings, temporary animation copies, native allocations or concurrent processes.

Pre-factory full-budget reservation for truly unknown costs is the correct minimal safe choice. Eviction must complete with no lingering local value references before factory invocation; coverage replacement must remove its old entry before building. Count constraints apply at reservation time too. Unknown-cost full reservation necessarily sacrifices multi-entry retention until an explicit conservative reservation or valid exact-key history exists; the design states this limitation. Previous observed cost is not a bound for changed coverage or source/configuration. History must have a fixed count cap and contain only keys and scalar cost data, with no values, owners or closures.

Acceptance clarifications: specify nested context ownership precisely so exiting an inner borrowed context restores rather than releases an outer borrowed cache; newly owned inner scopes release only their own entries. Exercise factory, cost-counter and clone exceptions as separate failure points, plus cancellation, so no failed admission leaves retained values or incorrect accounting. Clone failure may retain an already admitted canonical template only if that behavior is explicitly specified and accounted for; scene-finally cleanup must still release it. Decide and schema-document coordinate fields and unique-array identity semantics before asserting point limits. Reject boolean weights as well as negative/fractional costs in Python to maintain the JSON integer contract across languages.

Schema-first shared symbolic traces, stdlib first-party Python/TypeScript implementations and an installed lru-cache oracle are aligned with repository requirements. Dual synchronized oracle instances can validate independent resource vectors when both receive identical accesses and cross-evictions are synchronized after every operation. Include mixed vectors and zero-sized entries explicitly. Disabled zero-limit retention must remain a declared separate case when oracle constraints differ. The oracle does not independently validate ownership or pre-factory event order; weak-reference and callback traces must do that.

Proposed neutral cache root and Nakagin/Excel/Grasshopper integration paths are appropriately scoped. No common Drafting rewrite is needed. Preserve pure geometry, order/fragment recipes, visibility and fonts/text reuse. The design correctly repairs the older native review description of order recipes as integer-only: current recipes can retain coordinate tuples without retaining rich Scene drawings. New neutral implementation and contract dependencies must enter source_files and the next freeze; prior visual/profile/native proofs cannot be called current after source changes.

No production edits, running-job signals, heavy imports or duplicate tests were performed. Only this audit and the bounded gallery addendum were written. This audit owns no live OS jobs.
