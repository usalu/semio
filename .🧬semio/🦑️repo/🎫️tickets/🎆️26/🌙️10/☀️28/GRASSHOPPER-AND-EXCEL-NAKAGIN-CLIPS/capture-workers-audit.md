## Concrete Cancellation Blocker

final-capture.py repo_child enters Popen context then blocks consuming child.stdout until EOF and child.wait. There is no try/finally owned-tree termination or bounded terminate/kill escalation. Python Popen context exit waits for the child; interrupting the parent can therefore leave it waiting for an expensive live child rather than canceling it. Source checkpoints occur only before and after each child, so a silent running worker does not check source drift/cancellation mid-flight. Current tests cover child nonzero return and between-worker drift; their fake context has no real running descendant and cannot prove cancellation cleanup. Require the established repo process-tree cleanup through a tool-independent interface plus a portable controlled cancellation regression before launch.

One concrete reaped-root cleanup boundary remains: run_worker explicitly detects an exited root whose stdout is still held open after2seconds and raises Exited worker left stdout held open.
