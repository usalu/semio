# Storyboard: excel / 📋️program / `Beat3_Program`

Video `excel_program`. Tool side: the Nakagin workbook (`xl_window`, left, about 60 % of the stage). Building side: the Nakagin drawing (capsule plan or `tower_axon`, right, about 40 %). Both are on screen whenever a value is discussed. Every number (areas, volume, counts, totals, 140) comes from the workbook engine and `🏢️nakagin`, never typed in the scene. Type colours A, B, C, D are four fixed palette colours shared by the capsules, the table cells that name them, the formula references and the chart bars.

## Learning goals

1. A room program lists, per room, its fittings, areas and users; for the architect it is the bridge from brief to drawing and the check that nothing is forgotten.
2. One worksheet per capsule type turns the fittings into net floor area, volume and occupants by plain formulas (width x depth, SUM, subtraction, product).
3. A list of 140 capsules as an Excel table plus COUNTIF / COUNTIFS answers "how many of each type, in which tower".
4. XLOOKUP pulls a value from another sheet by key; SUMPRODUCT multiplies counts by areas into the total net floor area.
5. Everything is live: swapping one capsule type updates counts, totals and chart, and a sanity check against the building's 140 capsules catches input errors.

## Misconceptions addressed (from `research-excel.md`)

- Displayed value is not stored value: the cell shows `8.74 m²`, the number stored is 8.74 (section 1, 6.4).
- COUNT counts numbers; COUNTIF counts rows that meet a text criterion (section 7, item 7).
- Pasted values freeze a result; the formulas stay live and the change propagates (section 7, item 2).
- Table columns are addressed by name and the table grows with its rows; a fixed range does not (section 3.3).
- Text criteria must match exactly: a trailing space is a different type; the capsule is not counted and the sanity check shows it (typical mistake, fixed in clause 21).
- A missing key in XLOOKUP gives `#N/A`, a lookup problem and not a broken formula (section 6.1).
- German Excel: `ZÄHLENWENN`, `ZÄHLENWENNS`, `XVERWEIS`, `SUMMENPRODUKT`, `SUMME`, `WENN`, separator `;`, decimal comma (section 5). Check list: sheet names, table name and column names are localized by the workbook model, not by the scene.

## Layout

- Left: `xl_window` with `cols`/`rows` chosen per clause, tabs `Program` and one tab per capsule type (A to D), `Climate`, `Energy` are present and inactive. Right: capsule plan (`capsule_views`/`capsule_axon`) during clauses 3 to 8, `tower_axon` (types tinted, unlit = dimmed) during clauses 1 and 9 to 22. Chart (`xl_bar_chart`) sits below the table on the Program sheet from clause 15.
- Formula text is always shown in the formula bar and as `xl_formula_text` with reference tokens coloured like their frames.
- Captions at most two lines, stage between title and caption always filled.

## Notes for implementation

- Clause count: 22; target runtime 4 to 5 minutes at the usual narration pace.
- Dependencies on other API sections: the engine needs the capsule list table with structured references, COUNTIF, COUNTIFS, XLOOKUP, SUMPRODUCT, SUM, ROWS (to confirm in engine), `localize` for table and column names in German, `apply` for the type swap and typo events, `precedents`/`dependents` for the trace. The toolkit needs `xl_window`, `xl_ref_frame`, `xl_fill_handle`, `xl_trace`, `xl_formula_text`, `xl_bar_chart`. The drawing needs `capsule_views`, `capsule_axon`, `tower_axon(lit=...)` with per-capsule tint.
- If a function (e.g. ROWS) is missing in the engine, the check formula uses `COUNTA(Capsules[Type])` or `SUM` against the table row count constant; to be decided against the engine on disk.
