## Context and publication

The shared snapshot backend uses persistent OS file leases rather than age-based directory stealing. ## Freshness

Git porcelain alone cannot identify changes to an already-modified file. Both native projections now bind a lexical authored-source census digest that streams relative path identities and regular-file bytes, skips symlinks and canonical opaque directories, and supports cancellation and progress. A real Git oracle proves that identical porcelain status still produces different fingerprints when bytes change. Authored untracked members also invalidate the snapshot. Three language-neutral byte vectors are checked against Node SHA256.

## Domain projection boundary

Final review identified a separate metadata defect: persistent goal/ticket contents were represented by directory identity, while session projection also derives time-dependent liveness. Hashing raw metadata or event logs would preserve the wrong boundary. The tree schema now specifies an authored-codebase snapshot with fresh domain records per request and a combined-projection search identity.

Both implementations split codebase discovery from domain assembly. Only the authored codebase enters the snapshot. Goals, tickets, contributors, sessions, policies, and drafts are projected through their existing producers for every request. Index generations bind the exact current indexed-document stream, so domain changes invalidate search independently of authored-source identity. Domain-only changes retain the same published codebase snapshot inode.

The actual warmed goal regression failed before this change: the second request returned the first title. The repaired test tracks the goal in a real temporary Git repository, edits it twice while porcelain remains modified, and verifies both the warm tree and index return the new title while the codebase payload retains its file identity. The same language-neutral domainRefresh vectors drive canonical tree and duplicated-client tests; SQLite independently selects the current record.

Separate codebase/domain producer groups and explicit later-ticket completion correct it; generated/native-discovery-join-red.log and native-discovery-join-green.log retain both outcomes.

Snapshot metadata now rejects a second JSON object after the closed metadata document. The actual regression first returned success for appended data and then passed after an EOF check preserving cancellation identity. The snapshot byte limits govern decoding, emitted bytes, and disk extents. Go encoding/json still prepares one codebase value before the writer receives it; no independent bound on that intermediate serialization allocation or immediate cancellation within it is claimed.
