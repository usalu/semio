# Schema Pattern Whitespace Parity Audit

Current Rust ClassItem::Space delegates to char::is_whitespace. [Rust documentation](https://doc.rust-lang.org/std/primitive.char.html#method.is_whitespace) defines that predicate using Unicode White_Space. The [Unicode17property table](https://www.unicode.org/Public/17.0.0/ucd/PropList.txt) includes U+0085 and omits U+FEFF. [ECMAScript character-class semantics](https://tc39.es/ecma262/#sec-runtime-semantics-compiletocharset) define regex whitespace using language WhiteSpace and LineTerminator productions rather than that Unicode property.

Actual independent registered Node execution on current host confirms /^\\s$/u rejects U+0085 and accepts U+FEFF; /^\\S$/u gives the inverse. U+2028 and ordinary space are positive controls. These expectations, together with the Source predicate and normative definitions, identify a likely genuine first-party parity gap. The changed Rust binary has not yet executed these new cases, so no actual native causal-red claim is made. Root sent four neutral-case additions to schema owner for the next genuine normal native red/fix cycle. Root did not edit pattern Source. No new dependency or relaxed scalar guarantee is proposed.
