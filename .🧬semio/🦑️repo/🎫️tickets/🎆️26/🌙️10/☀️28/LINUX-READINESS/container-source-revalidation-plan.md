# Container Source Revalidation Plan

This is a preparation plan only. No container replacement, native rebuild, query, graph or setup run is authorized by the plan itself. Root owns the next actual full workspace run; the Go owner will send a final candidate freeze after the confirmed native search context repair.

1. Wait for the Go owner's explicit final freeze and terminal focused gates. Preserve the existing private Source-overlay container and both owned cache volumes. Do not duplicate a live verification handle.
2. Build a fresh host-side metadata manifest of all current Go sources, Go manifests/workspace files and the changed/untracked implementation/configuration inputs selected for the native installer, memory correction and launcher. Use read-only current worktree enumeration; exclude missing historical index entries by lstat. Record relative paths, size, mode and SHA-256 only. Include no copied Source payload.
3. Replace the ticket-generated metadata manifest on the host. Through the registered Docker helper, run the existing `verify-container-source.cjs` against the same manifest in the private container. It checks current bytes and modes plus the installed frontend ELF header. Preserve the exact drift count and selected coverage; do not describe a selected-input comparison as proof of every monorepo file.
4. If the container sees the exact current Source, retain its valid private dependency generations and endpoint bindings. Do not reset or redownload them for observation alone. Read-only confirm that the generated endpoints still resolve into the private container's own stores; any inherited host endpoint is a distinct custody failure requiring proof before a targeted private-view correction.
5. If actual selected Source drift is found, identify the exact upper-overlay file and compare host/container metadata. Do not copy Source into the container or ticket, alter the host file, or delete arbitrary overlay entries. Quiesce only our own work and recreate an owned private Source view with the same isolated cache volumes when necessary; let the normal installer rebuild its frontend from current Source.
6. After Root authorizes the fresh route, execute the checked-in native installer/bootstrap and full authored setup closure with configured devcontainer environment and direct streamed logs. Keep one handle until a real terminal result. A fresh installed ELF is required for final cold/warm search and MCP acceptance after the Go change; the prior ELF only proves the earlier candidate.
7. Preserve full failure output and actual sender/cancellation evidence before any retry. Kernel custody, actual reservation accounting and the irreducible-parent-memory limitation remain in force.

The browser-cache recheck is a separate read-only prerequisite probe and does not execute provisioning or a graph. The actual devcontainer DISPLAY value is not a running display owner; browser E2E must own or reuse an explicitly managed display with cleanup.
