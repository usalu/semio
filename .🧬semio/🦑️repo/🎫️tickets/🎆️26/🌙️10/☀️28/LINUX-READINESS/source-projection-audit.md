# Container Dependency Projection Architecture

Source node_modules endpoints must remain replaceable on their parent filesystem. The previous devcontainer mounted a separate named volume exactly at the root endpoint; the actual producer correctly refused that setup under a Source overlay because the ordinary endpoint and its parent were different filesystems. A mountpoint also cannot be atomically replaced like an ordinary Source entry. The preservation guard remains unchanged.

The devcontainer now mounts only its two owned cache roots. Installed package generations persist in the dependency partition under the private .cache volume; Source node_modules entries are ordinary managed projections. The obsolete endpoint volume and its onCreate chown argument were removed. A closed SourceDependencyProjection schema declares the endpoint basename, the neutral runtime-bootstrap fixture lists the two cache mounts, and runtime laws forbid mounting projection endpoints while retaining cache-volume coverage and ownership assertions. The focused new regression failed against the former mount and passed after correction. The final native/cross-platform focused run passes 14 tests and 331 assertions.

Actual verification uses Podman :O Source overlay to protect the concurrently used host checkout. [Podman documents the isolated upper layer](https://docs.podman.io/en/latest/markdown/podman-pod.unit.5.html); an actual kernel mount check and generated probe confirmed that container Source writes were absent from the host. This proves write isolation; it does not establish a coherent snapshot of arbitrary concurrent lower-layer changes. Podman advises keeping the lower source stable, and the repository's Source guards remain authoritative for observed changes.

The first shared-bind run was stopped before app-scope publication, and the replacement with an endpoint volume exposed the filesystem guard. The final verification container d9a5b2231efc has no endpoint volume, keeps the provisioned language toolchains/native command, and reuses both private cache volumes. Its fresh generated-endpoint view was established from the complete union of six scope manifests and every package member: 320 distinct node_modules endpoints. Only inherited host-generation links were unlinked inside the proven private overlay. All 320 host device, inode, mode, mtime and raw target records were unchanged afterward. No code, documentation, ordinary Source input or valid private generation link was removed.

The configured onCreate and postCreate argv and containerEnv are read directly from devcontainer.json by the retained run-container-setup.cjs test input, including the declared Playwright cache location. One bootstrap handle now runs to an actual terminal result; its outcome will be recorded in host-capabilities.md. No worktree or Source code copy was created, and no producer qualification check was weakened.
