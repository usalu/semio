Current watchOutputFiles eagerly creates a second native Watcher over workspaceRoot with useIgnore=false. Its responsibilities include output hash invalidation, ignored dotenv events, and detecting a changed daemon process marker.

The shared Source watcher already exists before setupWorkspaceContext and initial graph computation. Its dispatchWorkspaceChanges currently filters semioExcluded, optionally journals, and runs semioNativeChanges, which expands directory events through Source membership and can drop ignored/output-only paths. Raw output delivery must therefore happen at the top of dispatchWorkspaceChanges, before either filter or structural conversion. The force-flush path calls that same dispatch function, so it must not separately deliver the same raw events. Native Source errors must also reach the observer's terminal-error path.

Keep raw Source receipt synchronous or enqueue-only: dispatchWorkspaceChanges presently returns the Source callback's result and clears semioChangedFileHashes in finally. Awaiting an output callback before structural Source handling would change this lifetime and requires a deliberate async conversion throughout. The observer can serialize accepted work internally and expose an awaited drain/flush barrier.

watchOutputFiles can create the owned observer through the immutable graph authorizer's service-private factory, passing only repository-owned ports for native Watcher construction, nonrecursive node:fs.watch and actual callback/shutdown behavior. Do not expose the external Watcher class in a repository API. Its RPC handler must await the returned promise so registration failure stays inside its try/catch and returns a real request error. outputsHashesMatchBatch must await both pending Source force-flush and observer flush/drain before checking recorded hashes; its RPC handler must likewise await results if this function becomes async. Current SDK search found these two public functions consumed by their RPC handlers; client methods already return RPC promises.

Shutdown already awaits watcherInstance.stop() and outputWatcherInstance.stop(). The observer stop must be idempotent, reject future registration, close narrow/native handles and settle previously accepted callbacks. Daemon request handling reads getOutputsWatcherTerminalError; errors must retain this existing fail-closed path. Do not call handleOutputsChanges(null,[]) because its empty-event error branch attempts error.message.

## Native Registration Readiness

The pinned [Nx23.2.0 Rust implementation](https://github.com/nrwl/nx/blob/23.2.0/packages/nx/src/native/watch/watcher.rs#L463) constructs WatchPipeline synchronously inside watch_inner. Initial kernel registrations finish before the force-flush sender and background event thread are created. The constructor only stores configuration. On Linux, successful watch(callback) return is therefore the readiness barrier; initial watch-limit errors propagate before return. The macOS recursive registration call is also synchronous, but its error is logged rather than propagated, so the same failure guarantee cannot be claimed there.

Actual immutable SDK80e05b73 Linux validation completed status0 via the registered Node tool. Before and after constructor, /proc/self/fdinfo showed no inotify registrations. Immediately after watch returned, one fd held four registrations for the fixture's four directories. A subsequently created fixture file was returned by immediate forceFlushPending; no startup sleep was used. The watcher was stopped and the private fixture removed. Inputs are native-watcher-startup.cjs and generated/native-watcher-startup-proof.json. No mutation occurred inside authored outputs or vendor images.
