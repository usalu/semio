What I changed this session
----------------------------
- Added `DbConflictOracle` (`//#region 🔖Reconcile` in lib.rs): a `ConflictOracle` impl backed by
  the real `db_conflict::ConflictDetector`. `db_preview` still never sees a command's
  `CommandKind`/`ConflictRule`/claims (same "no crate below db_document interprets operation
  semantics" constraint db_conflict itself documents) — `Preview`/`LandedCommand` only carry opaque
  envelopes + `TouchedSet`s — so `DbConflictOracle::conflicts` bridges that gap by building two

  then calls the real `ConflictDetector::detect` and reports whether it returned anything. This
  exercises db_conflict's actual bloom-filter prefilter + touched-region-intersection law, not a
  reimplementation of it.

  `DbConflictOracle::default()` instead of the prior `TouchedRegionOracle`. `TouchedRegionOracle`
  (plain `TouchedSet::conflicts_with`, no bloom prefilter) is kept as a lighter-weight opt-in via
  `reconcile_with(landed, &TouchedRegionOracle)` — behavior is identical to `DbConflictOracle` for
  the read/read, write/write, and disjoint-path cases (verified by a new test); it differs only in
  the kind-matrix/constraint machinery db_conflict adds on top, which this crate doesn't populate.

  stale) "db_conflict is still a scaffold stub" text.

Scope
-----
Replaced the stub /Users/ueli/Documents/semio/db/preview/rs/lib.rs with a full implementation of
the crate's frozen responsibility: ephemeral document overlays ("previews") — identity, base
frontier, lifecycle (Active -> Superseded/Withdrawn/Committed/Rejected/Expired), coalescing
latest-per-(actor,key), TTL, rebase-or-stale reconciliation on frontier advance, and admission
budgets. Never durable, by construction (see "Never-durable law" below).

Files touched
-------------
- /Users/ueli/Documents/semio/db/preview/rs/lib.rs (full rewrite, was a scaffold stub)
- /Users/ueli/Documents/semio/db/preview/rs/Cargo.toml (added one dev-dependency, see below)

What was implemented
---------------------
- PreviewId: identity newtype, `pv-<document>-<store-local sequence>`, deterministic (no
  uuid/random dependency exists in the workspace) — reproducible in tests.
- PreviewState: Active + five terminal states exactly as named in the contract row
  (Superseded/Withdrawn/Committed/Rejected/Expired). `validate_transition` enforces the one-way
  law: only Active may transition, only into a terminal state; every terminal state is a dead end.
- PreviewBudgets: population/resource ceilings — `max_active_per_document`, `max_active_per_actor`,
  `max_touched_regions` (own choice, documented), and `default_ttl_ms`/`max_ttl_ms` derived from
  `db_core::DbLimits::max_preview_ttl_ms` (the contract-fixed TTL ceiling).
- Preview: one overlay's record — id, document/actor/key, base `Frontier`, the opaque
  `protocol::OperationEnvelope` payload (never interpreted, per the contract's "no crate below
  db_document interprets operation semantics" rule), `db_state::TouchedSet`, lifecycle state,
  publish sequence, created/expiry timestamps.
- PreviewStore (per-document, single-threaded, in-memory only):
  - `publish`: validates document identity, checks the touched-region budget via
    `db_core::check_len` (validate-before-allocate), coalesces (supersedes any existing Active
    preview under the same (actor,key)), enforces per-actor/per-document budgets by evicting the
    globally-oldest Active preview (mirrors `db_core::Priority::Preview`'s shed-previews-first
    admission law rather than erroring), then admits.
  - `withdraw`/`commit`/`reject`: explicit terminal transitions.
  - `sweep_expired(now_ms)`: TTL law, idempotent, only touches Active previews past deadline.
  - `reconcile`/`reconcile_with`: the rebase-or-stale law — for every Active preview behind a
    landed command's frontier, either it conflicts (Superseded, the "stale" half) or it doesn't
    (base advances to the landed frontier, stays Active — the "rebase" half). Conflict detection
    goes through a `ConflictOracle` extension seam (see deviation below), defaulting to
    `db_state::TouchedSet::conflicts_with`.
  - `get`/`active_for_key`/`list_active`/`len`/`active_len`: read-side queries, `list_active`
    ordered by arrival sequence (the shape `Consistency::PreviewAugmented` would layer atop
    canonical state).

Deviations from the contract / design choices made where it left things open
------------------------------------------------------------------------------
1. **db_conflict is still an empty scaffold stub** (zero exported symbols) as of this wave —
   confirmed by reading /Users/ueli/Documents/semio/db/conflict/rs/lib.rs directly before writing
   any code. Rather than block on it or invent a fictitious API against an empty crate, conflict
   detection in `reconcile` is expressed against a small `ConflictOracle` trait defined in this
   crate, with a real (not fake) default implementation `TouchedRegionOracle` built on
   `db_state::TouchedSet::conflicts_with` — the same touched-region-intersection primitive
   `db_conflict` itself is specified to build on. This is a genuine, tested mechanism today, and a
   clearly-marked extension seam: once `db_conflict` lands with its richer bloom-filter/command-
   kind-matrix/protocol-declared resolution, a `db_conflict`-backed `ConflictOracle` impl can be
   substituted via `PreviewStore::reconcile_with` with no API change to this crate. The
   `db_conflict` Cargo dependency itself was left untouched/declared-but-unused per instructions
   (do not touch Cargo.toml unless a dependency is genuinely missing) since referencing symbols
   that don't exist yet would not compile.
   [THIS SESSION: db_conflict is now complete; the anticipated follow-up landed — see "UPDATE" at
   top of this file. `DbConflictOracle` is now the default and this deviation is resolved.]
2. Added `[dev-dependencies] serde_json = "1"` to Cargo.toml — genuinely missing and needed:
   `protocol::OperationEnvelope`'s `diff`/`inverse` fields are `serde_json::Value`-typed, and the
   protocol facade does not re-export the `serde_json` crate itself, so constructing a sample
   envelope in this crate's own tests requires it directly. Kept dev-only since production code
   never constructs a `DocumentDiff`/`InverseOperation` (it only stores an envelope handed to it
   opaquely by the caller).
3. `PreviewId` generation is deterministic (document + monotonic store-local sequence), not
   randomized — no uuid/rand crate exists anywhere in the workspace `Cargo.lock`, and determinism
   makes every law in this crate exactly reproducible in a unit test without a
   `db_testkit::SimClock`.
4. `PreviewStore` takes `now_ms` as an explicit argument everywhere rather than reading a wall
   clock — same determinism rationale; the caller (`db_document`, which will own the real clock)
   supplies it.
5. Population-budget overflow evicts the oldest Active preview rather than returning
   `DbError::LimitExceeded` — a deliberate reading of the contract's "shed-previews-first
   admission" law (`db_core::Priority::Preview` doc) applied to this crate's own admission path,
   since a preview publish is itself the lowest-priority, always-sheddable class of write.
6. `max_active_per_document` (4096) and `max_active_per_actor` (64) and `max_touched_regions`
   (256) are this crate's own well-justified constants — the contract fixes the TTL ceiling
   (`DbLimits::max_preview_ttl_ms`) but not population caps.

Extension seams left (not stubs — each has a real, tested default)
--------------------------------------------------------------------
- `ConflictOracle` / `TouchedRegionOracle` (see deviation 1 above) — the seam for a future
  `db_conflict`-backed resolver. [THIS SESSION: now also has `DbConflictOracle`, the default.]
- `PreviewHandle` (the `db` facade's public API type returned by

`HashMap`-based structure. This is enforced by a dedicated test,
