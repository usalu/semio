intermediate state — Cargo.toml trimmed to depend on the `db` facade alone, but ~110 call sites in

db_snapshot::/db_conflict::/db_cluster::/db_observe::/db_document::/db_actor::/db_state:: path to
its db::-facade equivalent, with care around two places where a facade-promoted type and a

`pack` dependency db_cli's own trim had dropped (SnapshotManager::verify needs pack's own
VerificationLevel, not protocol's same-named enum - a real two-crate type collision, not a
migration artifact).

Clippy (-D warnings, --no-deps to isolate pre-existing pack_async/pack_value findings out of
scope for this ticket) went through six rounds of fix-and-reverify. Real issues found and fixed
(not blanket-suppressed):
  - db_state: PText::from_str renamed to from_text (clippy::should_implement_trait - collided with
    the std::str::FromStr trait method name); an fn body's local `use std::hash::{Hash, Hasher}`
    trimmed to just Hasher (Hash was already in scope via the function's own generic bound).
  - db_actor: run_actor_loop's receiver/emit params changed to references (verified against the
    thread::spawn closure call site - safe since the closure still owns them, only the inner call
    borrows).
  - db_observe: gated an Emit-trait import behind #[cfg(test)] (only exercised by this crate's own
    tests).
  - db_document: five needless_pass_by_value findings triaged individually rather than blanket-
    fixed - json_err stays by-value with a documented #[allow] (used as a bare `.map_err(json_err)`
    fn-pointer, which requires FnOnce(E) by contract of Result::map_err); DocumentEngine::open's
    storage param changed to &Arc<..> (verified it only ever .clone()s, never moves, across all 3
    call sites); submit/query stay by-value with documented #[allow]s (deliberate API ownership
    choice / high call-site count for no behavioral gain); publish_preview's entries changed to a
    slice (2 call sites, both in this crate). Also added a StatePageEntries type alias for
    decode_state_page's flagged complex return type.
  - db_engine: to_engine_frontier's core param changed to a reference (3 call sites, all verified
    non-reused-afterward); map_vcs_error kept by-value with a documented #[allow] (same
    map_err-fn-pointer reasoning as json_err); checkpoint_document's authors param changed to a
    slice (3 test call sites); query's consistency param KEPT by-value with a documented #[allow]
    because it is the frozen contract signature
    (DocumentHandle::query(&self, query: Query, consistency: Consistency) - contract.md's Stable
    API block) - the one place a clippy-suggested signature change was correctly refused.
  - db_storage_sqlite: sqlite_err kept by-value with a documented #[allow] (same map_err-fn-pointer
    reasoning, ~50 call sites); the private lock() helper's always-Ok Result wrapper removed and
    all ~29 `self.lock()?` call sites mechanically updated to `self.lock()`.
  - db_compact: two redundant `document: document` struct-init field names collapsed to shorthand.
  - db_cli / db_testkit / the db_testkit criterion bench (benches/db.rs, which normal
    build/test invocations don't compile by default and so needed a separate --benches pass to
    catch): ~10 mechanical `.map(f).unwrap_or(a)`-style chains rewritten to `.map_or(a, f)` per
    clippy's own exact suggested diff, one `Arc<dyn db_storage::DbStorage>` unnecessary
    qualification trimmed to `Arc<dyn DbStorage>`, and the DocumentEngine::open/publish_preview
    signature-change ripple applied to the 3 call sites the bench file has (missed by the earlier
    normal build/test passes since cargo doesn't compile bench targets by default).
  - db_cli's lib-target `fn main()` dead_code finding under `--all-targets --no-deps -D warnings`
    is NOT a bug - confirmed pack_cli and protocol_cli (the established precedent for this repo's
    single-file lib+bin CLI pattern) have the byte-for-byte identical finding under the same
    invocation. Left as-is, matching precedent; a plain `cargo build -p db_cli` (the shape the
    real repo verification gate uses) shows it only as a warning, not a hard failure.
  - Final round: only that one accepted precedent-matching item remains; every other crate is
    clean under --no-deps -D warnings.
