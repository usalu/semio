HubState / HubDirectory SHAPE
------------------------------

  struct HubState {
      db: Arc<db::Database>,                    // NOT `db::Database` verbatim — see deviation note
      directory: Arc<dyn HubDirectory>,
      admin_token: Option<String>,
      fanout: Arc<DashMap<String, broadcast::Sender<protocol::ServerFrame>>>,
      presence: Arc<DashMap<(String, String), serde_json::Value>>,
  }

Deviation from the plan's literal `HubState { db: db::Database, ... }`: `db::Database` has no
`Clone` impl (owns `Mutex`-guarded catalog/open-document state) and axum's `State<S>` extractor
requires `S: Clone`, so `db` is `Arc`-wrapped. `fanout`/`presence` are additive fields beyond the
plan's three — `db::DocumentHandle` currently has no live-subscription seam (`subscribe`/`preview`
are honest `DbError::Unimplemented` per `db_engine`'s own module doc), so relaying newly-committed
commands / preview blobs / presence updates to other sessions on the same document has to be this
crate's own, deliberately thin responsibility (never decides ordering/durability, only re-broadcasts
what `db` already committed or what a preview/presence frame carries verbatim — never durable).

  trait HubDirectory: Send + Sync + 'static {
      // Vfs: list_nodes, create_node
      // ShareTokens: create_share_token, authorized_by_token
      // Users: create_user, get_user_by_email, get_user_by_sso_subject, list_users
      // Studios: create_studio, list_studios_for_user, list_studios, upsert_membership,
      //          remove_membership, get_role
      // AuthSessions: create_auth_session, get_auth_session, revoke_auth_session
      // SyncSessions: record_sync_session_open, record_sync_session_close,
      //               list_sync_sessions_for_document
  }

Removed from the old `HubStorage` (document persistence + blobs, now `db`'s job):
  ensure_document, save_document, insert_operation, load_operations, list_documents_for_studio,
  put_blob, get_blob, has_blob.

Document id scheme: `db::Database`'s catalog is a flat namespace, so this crate applies its own
studio-scoping convention on top: `protocol::DocumentId(format!("{studio_id}:{document_id}"))`
(helper `db_document_id`/`scope_key`). Verified isolated by a dedicated test
(`studio_scoped_documents_are_isolated`).

WS WIRE-V2 INTEGRATION (the CW5->CW6 handoff)
-----------------------------------------------

`/studios/{studio_id}/documents/{id}/ws` now speaks `protocol_wire`'s binary `ClientFrame`/
`ServerFrame` directly (axum `Message::Binary`, `protocol::{encode_*,decode_*}_frame`), matching
the shape `framework/sync`'s `NativeActor`/`WasmActor` already speak since CW5 and the exact
`MockHub` fixture in `framework/sync/rs/lib.rs` used as the integration reference:

  - `ClientFrame::Hello` -> auth resolve (session or share-token) -> lazily mint the `db` document
    (get-or-create, tolerant of a create-race) -> `db::Database::hello(...)` (a REAL `db_sync`
    integration: frontier replay + `BootstrapPlan` decision + `Welcome`/follow-up frames) -> send
    `Welcome` + any `Bootstrap::Tail` `Commands` / `SnapshotChunk`+`SnapshotDone` follow-up.
  - `ClientFrame::Commands` -> `db_document::CommandBatch::new` -> `DocumentHandle::submit` with
    `DurabilityClass::Fsync` -> `ServerFrame::Ack{Received,Persisted,Applied{Accepted|Rejected}}`
    to the submitter + `ServerFrame::Commands` fanned out to every other session on the same
    document (submit failures degrade to `Rejected{reason}` with a best-effort current frontier,
    never a panic).
  - `ClientFrame::FrontierAdvertise` -> `db::sync::handle_frontier_advertise` against
    `Database::storage().wal()` -> catch-up `Commands` frame if the replica is behind.
  - `ClientFrame::PreviewPublish`/`Presence` -> ephemeral fan-out only (never durable, never
    touches `db`).
  - `ClientFrame::CreditGrant` -> accepted and ignored (matches `framework/sync`'s client, which
    also has no congestion control yet this wave).
  - `ClientFrame::Bye` -> session close; presence entry removed, `record_sync_session_close`.

Blob routes (`GET`/`HEAD`/`PUT` `/studios/{studio}/blobs/{hash}`) now call
`Database::storage().payload()` (`db_storage::PayloadStorage`, blake3 CAS) instead of a
directory-owned blob table; `Database::storage()` is the new accessor added to `db_engine` for
exactly this (see above).

Storage backend selection is independent for `db` and the directory, per the contract:
  - `OS_HUB_STORAGE_BACKEND` (db's substrate): `fs` (default, zero-touch, `FsStorage` at
    `{OS_HUB_DATA}/db`) | `sqlite` (`OS_HUB_DB_SQLITE`, default `{OS_HUB_DATA}/db.sqlite3`) |
    `postgres` (`OS_HUB_DATABASE_URL`) | `neo4j` (`OS_HUB_NEO4J_URI`/`_USER`/`_PASSWORD`).
  - `OS_HUB_DIRECTORY_BACKEND` (identity/tenancy substrate): `sqlite` (default, zero-touch,
    `{OS_HUB_DATA}/directory.db`) | `postgres` (`OS_HUB_DIRECTORY_DATABASE_URL`) | `neo4j`
    (`OS_HUB_DIRECTORY_NEO4J_URI`/`_USER`/`_PASSWORD`).
  - `OS_HUB_DATA` (default `./.semio/hub/`): root containing the `db/` subdir + `directory.db`.
  All four `db` backends (`fs`/`sqlite`/`postgres`/`neo4j`) are wired via the `db` crate's own
  `sqlite`/`postgres`/`neo4j` Cargo features (enabled on os-hub's `db` dependency) — real, not
  stubbed; `PostgresStorage::connect`/`Neo4jStorage::connect` are synchronous (each builds its own
  dedicated tokio runtime internally per `db_storage_postgres`/`_neo4j`'s own doc), so no
  `spawn_blocking` bridge was needed at the call site.

Bugs found and fixed during verification (both self-introduced this wave, not pre-existing):
  1. `auth_session_grants_role_and_bypasses_share_gate` test used a bare "studio-x" string as a
     studio id without creating the row; `hub_studio_membership.studio_id` is FK-bound to
     `hub_studio(id)` and this rusqlite/SQLite build enforces the FK (unlike what a naive reading
     of the old, structurally-identical test might suggest) — fixed by actually calling
     `directory.create_studio(...)` first.
  2. Two new WS tests (`reconnect_replays_missing_commands_via_bootstrap_tail`,
     `studio_scoped_documents_are_isolated`) were flaky under `cargo test`'s default parallel
     execution: the test `tempdir()` helper suffixed paths with `{pid}-{now_ms()}`, and multiple
     `#[tokio::test]`s in the same process can call it within the same millisecond, colliding on
     the identical `FsStorage` root and corrupting each other's catalog/WAL. Fixed by suffixing
     with `uuid::Uuid::now_v7()` instead; reran the full suite 3x afterward with zero failures.

DEVIATIONS FROM THE LITERAL PLAN TEXT
----------------------------------------

  1. `HubState.db: Arc<db::Database>` not `db::Database` (Clone requirement — see above).
  2. `HubState` carries two additional fields (`fanout`, `presence`) beyond the plan's three-field
     sketch — necessitated by `db::DocumentHandle` not yet exposing subscribe/preview (documented,
     honest `Unimplemented` upstream in `db_engine` per its own module doc, not a gap introduced by
     this wave).
  3. Legacy REST document routes (`GET .../documents/{id}` returning a whole JSON envelope, PUT
     .../envelope, POST/GET .../operations) are DELETED rather than adapted — they depended on
     whole-JSON-snapshot semantics (`semio_framework_core::{HubClientFrame,HubServerFrame,
     OperationEnvelope}`) that no longer exist anywhere in the new architecture (superseded by the
     WS wire-v2 protocol per the plan's own Part 3), and greping the repo confirmed zero other
     consumers of those routes. Replaced with a single `GET .../documents/{id}` returning
     `{document_id, head_seq, commit_seq, epoch}` (the document's frontier) — a new, small,
     genuinely useful REST surface for tooling/health checks, not a compatibility shim.
  4. Studio-scoped VFS "document" nodes (created by `seed()`/`create_node(..., "document")`) are
     now pure labels — they carry no FK/back-reference to a `db` document row (the old schema had
     none either; `hub_document`/`hub_document_operation` were the only tables that ever referenced
     a document id, and both are gone). A VFS node's `id`/`name` and a `db` document's
     `{studio}:{document}` key are correlated by the caller's convention (same document_id string),
     not enforced by either store.
