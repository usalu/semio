- //#region 🔖Sync: RecordSlice (unchanged from contract), extract_range, verify_slice,
  content_frontier. These three functions are NOT detailed byte-for-byte in the contract (only
  their signatures + RecordSlice's doc comment are given), so per the "your choice, document it"
  rule I made and documented the following design choices inline:
  * extract_range: scans the file's *trusted, recovered* prefix (protocol_format::recover with
    RecoveryMode::LastCommit) forward via FrameCursor, tracks a REC_EDIT ordinal counter, and
    returns the minimal contiguous span from the first target edit's frame offset through the end
    of the last target edit's frame. Frames strictly before the first target edit (e.g. an earlier
    dictionary base) are excluded — documented as this crate's own choice, since a slice recipient
    is assumed to already hold that earlier context. Empty/out-of-bounds ranges return
    ProtocolError::Malformed.
  * verify_slice: the contract's commit-chain algorithm is rooted in a specific prior commit's
    chain_hash, which a mid-stream RecordSlice doesn't carry, so verify_slice instead folds every
    frame's blake3(full frame bytes) digest in the slice into one blake3(digest_1 || .. ||
    digest_k) value (same shape as a commit's chain_hash, but rooted at nothing) and compares
    against the caller-supplied expected_chain. Documented as a deliberate deviation/choice in the
    function's doc comment.
  * content_frontier: full HistoryLog decode + protocol_format::recover for the commit tip.
    head_edit_ordinal/head_edit_id come from the last decoded edit (0/"" for an empty log, matching
    a fresh HistoryAppender::begin). chain_hash comes from the last REC_COMMIT frame's payload via
    protocol_format::parse_commit_payload, falling back to blake3(header) (chain_0) when there is no
    commit yet. Each AlternativeHead's checkpoint_id is the LAST id in
    HistoryAlternative::checkpoint_ids (append-only list -> most recent); its head_edit_ordinal is
    the highest edit ordinal transitively reachable through that checkpoint's
    change_ids -> HistoryChange::edit_ids. Documented as this crate's own choice in the function's
    doc comment.
