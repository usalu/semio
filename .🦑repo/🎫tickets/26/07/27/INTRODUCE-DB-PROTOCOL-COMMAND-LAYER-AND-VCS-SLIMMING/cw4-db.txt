CW4 report — db facade crate (/Users/ueli/Documents/semio/db/rs)
=================================================================

Scope
-----
Implemented the `db` facade crate per the frozen contract's "## db crate family" section and
Part 2 of the approved plan. This crate is pure re-export glue: it does not define any new
business logic. By the time this wave ran, every one of the 18 mandatory db_* dependency crates
(db_core, db_actor, db_state, db_storage, db_wal, db_snapshot, db_index, db_conflict,
db_projection, db_query, db_preview, db_security, db_document, db_compact, db_sync, db_cluster,
db_observe, db_engine) plus the 3 optional storage-backend crates (db_storage_sqlite,
db_storage_postgres, db_storage_neo4j) were already real, complete implementations (not stubs),
so this wave read each one's actual lib.rs and wired the facade against their real APIs directly.

What was implemented (db/rs/lib.rs, full rewrite of the stub)
---------------------------------------------------------------
- //#region 🔖Database: promotes the frozen Database/DocumentHandle API verbatim from db_engine
  to the facade's own crate root — Database, DocumentHandle, CommandReceipt, Frontier,
  Consistency, DurabilityClass, Query, QueryStream, HistoryEntry, HistoryView, LiveQuery,
  LiveQuerySpec, PreviewHandle, SnapshotKind, SnapshotReceipt, SnapshotFuture, SubmitFuture,
  CatalogEntry, CatalogView, DocumentSpec, DbHealth, SecurityAuthzHook, DbCapabilities, DbConfig,
  Profile, DbStorage, plus db_core::DbError re-exported at the root too (appears in virtually
  every facade-level Result). db_engine already exposes `Database::open_at(root, profile)`
  exactly as the contract specifies (FsStorage, zero-touch) — no extra convenience wrapper was
  needed (contract explicitly said to add one only if missing; checked first, confirmed present).
  Also re-exports `db_engine::vcs_integration` behind this crate's own `vcs` feature (the ONLY
  place in the whole family allowed to depend on `vcs`, per the hard dependency rule).
- //#region 🔖Family: every other db_* crate is additionally reachable through a same-named
  (minus the `db_` prefix) submodule — db::core, db::actor, db::state, db::storage, db::wal,
  db::snapshot, db::index, db::conflict, db::projection, db::query, db::preview, db::security,
  db::document, db::compact, db::sync, db::cluster, db::observe, db::engine — each a plain
  `pub use db_x::*;` glob re-export of that crate's complete public surface. No submodule needed
  a feature gate: every one of these 18 is a mandatory (non-optional) dependency in Cargo.toml.
  db::engine additionally exposes db_engine's full surface (redundant with the root promotions,
  same underlying types) for callers who prefer reaching it via the family-uniform path.
- //#region 🔖StorageBackends: db::storage_sqlite / db::storage_postgres / db::storage_neo4j,
  each gated behind this crate's matching optional Cargo feature, glob-re-exporting the
  corresponding optional backend crate.
- //#region 🧪Tests: two groups.
  1. Facade round-trip laws (`full_round_trip_reachable_purely_through_facade_reexports`,
     `database_error_type_is_reachable_at_the_facade_root`): a real Database::open_at ->
     create_document -> submit -> query -> frontier -> history -> shutdown cycle, and a
     not-found error path, driven ENTIRELY through this crate's own re-exported names (never
     reaching into db_engine/db_document directly) — the actual thing worth testing in a facade
     crate: that the re-export wiring composes into a genuinely working database, not just "does
     it compile".
  2. `every_family_submodule_reexports_its_headline_public_surface`: one representative
     construction per family submodule (db::core::DbLimits/check_len, db::actor::mailbox,
     db::state::PMap insert+len, db::storage::MemoryStorage as a DbStorage trait object,
     db::wal record-kind consts, db::snapshot::SnapshotOrigin, db::index::IndexKind::ALL,
     db::conflict::CommandKind, db::query::Value, db::preview::PreviewId, db::security::TenantId,
     db::compact::CompactionBudget, db::cluster::NodeId, db::observe::MemorySink,
     db::sync::frontier_delta) — catches a rename/dropped-reexport regression in any single
     family crate's public surface without duplicating that crate's own internal test suite.

as-is rather than papering over them.

Addendum (second pass, same wave, different session)
------------------------------------------------------
Re-read this crate fresh before writing (per ticket instructions) and found the above already
landed — a real, complete implementation, not the stub I'd been about to replace. Per "extend
rather than replace", I kept this design as-is and only added:

- lib.rs: `pub use pack::ContentHash;` at the crate root (next to `DbError`), with a doc comment.
  `CommandReceipt.state_hash: Option<pack_core::ContentHash>` is part of the frozen contract shape
  and was not otherwise nameable through the facade.
- Cargo.toml: added a `deflate` feature (`deflate = ["pack/deflate"]`) to `default` (`default =
  ["fs", "thread", "deflate", "vcs"]`) — the task's explicit feature-forwarding requirement,
  which the scaffold's `default = ["fs", "thread", "vcs"]` was missing — backed by a new genuine
  (non-dev) dependency `pack = { path = "../../pack/rs", default-features = false }` (also backs
  the ContentHash re-export above). Documented inline that this forward is currently "soft" (deflate
  is already unification-enabled workspace-wide via `db_storage`'s own unconditional default-
  features `pack` edge) but becomes load-bearing if that edge ever narrows — same reasoning
  `pack`'s/`protocol`'s own facades already document for their own `deflate` features. Also added a
  comment-only note (no functional change) on why `cluster = []` stays an empty feature: `db_cluster`
  is a mandatory `db_engine` dependency with no feature of its own to forward into, so `cluster`
  gates this facade's OWN re-export surface only — consistent with `db::cluster` already being an
  unconditional submodule in lib.rs above (unlike the three feature-gated storage-backend submodules).
