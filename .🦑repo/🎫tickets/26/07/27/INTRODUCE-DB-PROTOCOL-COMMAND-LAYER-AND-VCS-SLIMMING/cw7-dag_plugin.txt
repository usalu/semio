## What changed

1. Import switch: `use vcs::CollectionOperation;` -> `use protocol::CollectionOperation;` (the only
   `vcs::`-sourced import of this trio in the file; the one other `vcs::` reference in the file,
   `use vcs::MemoryBackbone;` inside a test, is unrelated to the CollectionOperation shape freeze
   and was left untouched). This crate has no `Operation`/`OperationDiff`/`OpText` imports of its
   own (it only consumes `DagOperation`, a type from the sibling crate) — step 7 of the instructions
   doc does not apply here.

2. `CollectionOperation::Add { index, item }` -> `Add { id, item, at: index }` at all three
   construction sites:
   - `"nodeGraphEdit"`'s `"connect"` branch (`DagOperation::Edges(...)`, was ~line 764): id source
     `edge.id.clone()` — `edge` is the `DagFixtureEdge` returned by `connect_edge(...)`, which
     already assigns a fresh `id` (`format!("e{}", ...)`) before this call.
   - `"connectMediaPorts"` action (`DagOperation::Edges(...)`, was ~line 844): same pattern, same
     id source (`edge.id.clone()`).
   - `"addNode"` action (`DagOperation::Nodes(...)`, was ~line 856): id source `node.id.clone()` —
     `node` is the `DagNodeSpec` built by `default_node_for_kind(kind, &id, x, y)` from the `id`
     local (`next_node_id(document)`, generated fresh two lines above); used `node.id.clone()`
     rather than the `id` local directly because `id` is moved into
     `self.runtime.selected_node_ids` on the line immediately before the `Add` construction, and
     `node.id` is provably the same value (constructed from `id.into()`/`id: id.into()` inside
     `default_node_for_kind`). Field-evaluation order in the struct literal (`id: node.id.clone()`
     before `item: node`) means the borrow-then-move is sound.
   No `Move` sites existed to rewrite.

3. No `Patchable`/`Identified`/`CollectionDiff`/`ItemPatch` imports existed in this file to redirect
   (this crate never implements those traits itself — `DagNodeSpec`/`DagFixtureEdge`/
   `DagNodePatch`/`DagEdgePatch` and their trait impls all live in the sibling `dag/rs` crate).
