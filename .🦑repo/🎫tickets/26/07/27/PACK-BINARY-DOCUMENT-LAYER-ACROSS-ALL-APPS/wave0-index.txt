Implemented exactly the "## pack_index" section of contract.md:

- FieldPath(pub Vec<u16>) — Clone, Debug, PartialEq, Eq, PartialOrd, Ord, Hash. Ord is derived
  lexicographic-on-Vec<u16>, which matches the contract's "sorted by path" requirement for the
  builder's serialized output and gives FieldIndexReader a binary-search-ready ordering.
- FieldIndexEntry { path: FieldPath, range: pack_core::ByteRange }.
- FieldIndexBuilder::new/record/build. build() sorts entries by path, then serializes:
  count: varint, then count x (path_len: varint, path field ids: varint*, offset: varint,
  len: varint) — same varint-based style as pack_format's chunk table (encode_chunk_table /
  decode_chunk_table in pack/format/rs/lib.rs), which I read first for consistency.
- FieldIndexReader<'a>::open/lookup/payload. open() eagerly parses the whole payload into a
  sorted Vec<FieldIndexEntry> (root-eager per contract's "small header, leaf pages lazy" note —
  v1 keeps the whole index in memory since there's no separate leaf-paging format specified).
  lookup() does a binary_search_by on FieldPath::cmp, returns Ok(None) for a non-matching path,
  never panics. Every read goes through pack_core::read_varint_u64 (bounds-checked) plus an
  explicit u16 range check on decoded field ids, so a truncated or corrupted payload always
  returns Err (PackError::Truncated / PackError::Malformed), never a panic or Ok-with-garbage.
