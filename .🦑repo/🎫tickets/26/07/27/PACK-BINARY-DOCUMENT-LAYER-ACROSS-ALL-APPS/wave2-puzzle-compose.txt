4. BLOCKER FOUND — OUT OF SCOPE, NEEDS A pack/** FIX (same root cause the draw family already found)
--------------------------------------------------------------------------------
Confirmed (not just reasoned about) that puzzle_2d/puzzle_3d/puzzle_5d's typed projections hit the
exact same pack/value/rs decode_table_soa shape-dropping bug the draw wave-2 family root-caused
(wave2-draw.txt §4): any #[dsl(table)] row with an Option column (plain scalar OR fixed-size array)
fails on decode with either "missing field 'x'" or "expected an N-item Tuple, found List(...)".
Isolated per-family with 3 probes (comment out the failing call, run just the surviving one):
  - puzzle_2d: with_content projection (Puzzle2dNode.handles rows, e.g. Puzzle2dHandle.color:
    Option<String>) -> "missing field 'color'". empty_puzzle2d_projection() alone PASSES.
  - puzzle_3d: representative projection (Puzzle3dObject.origin: [f64;3] table column) -> "expected a
    3-item Tuple, found List(...)". empty_puzzle3d_projection() alone PASSES.
  - puzzle_5d: representative projection (Puzzle5dPart.parts rows, nested part_2d/part_3d Option
    columns) -> "missing field 'width'". empty_puzzle5d_projection() alone PASSES.
pack/** is outside this family's allowed directories, so not fixed here — see wave2-draw.txt §4 for
the suggested one-line fix (decode_table_soa's fallback branch dropping the column Shape) and root
cause detail, which applies verbatim to all three of these kinds too.

5. SEPARATE PRE-EXISTING BUG FOUND AND FIXED (in-scope, DSL text layer, NOT pack — fixture staleness)
--------------------------------------------------------------------------------
Independent of §4: puzzle/3d/example/concrete-forest.puzzle3d and BOTH puzzle/5d/example/*.puzzle5d
fixtures failed to even *parse* as DSL text ("expected LBrace, found Ident 'x'"/'url'") — nothing to
do with pack. Root cause: `Puzzle3dReference.source: Puzzle3dReferenceSource` and
`Puzzle5dPart.part_2d`/`part_3d` are nested-record fields NOT marked `#[dsl(block)]`, and the current
derive/grammar requires such nested-record *table columns* to be written as `{ key=value ... }`
(distinct from a LIST's inline `key=value` cells, which stay bare) — but these three checked-in
fixture files still used the old bare-inline form (pre-existing on disk, unrelated to any change in
this session; confirmed via `git status`/mtimes that dsl/core, dsl/derive, and these fixture files had
zero pending changes before this fix). Since the fixture files themselves are inside puzzle/** (this
family's own directories, not pack/**/dsl/**), fixed them directly:
  - Verified the exact expected wrapped format via a temporary #[test] (print_dsl on an equivalent
    in-memory value), then added/removed only that temporary test — no net diff from it.
  - puzzle/3d/example/concrete-forest.puzzle3d: wrapped the 2 `references` rows' `source` cell in
    `{ url=... media-kind=... }`.
  - puzzle/5d/example/concrete-forest.puzzle5d (1 row) and
    puzzle/5d/example/nakagin-capsule-tower.puzzle5d (180 rows, mechanically transformed via a
    one-off Python script run once, output verified against the temporary-test's expected format):
    wrapped each `parts` row's `part-2d`/`part-3d` cells in `{ ... }`. Grip-list inner `grip-2d=`/
    `grip-3d=` cells (inside `[ ]`, a different code path) were untouched — verified via the same
    probe that those stay bare.
  - Both `puzzle3d_example_fixtures_parse_and_round_trip_as_dsl` and
    `puzzle5d_example_fixtures_parse_and_round_trip_as_dsl` now PASS end to end (parse + DSL round
    trip). This also un-poisoned puzzle-plugin's shared LazyLock example cache
    (CONCRETE_FOREST_EXAMPLE_JSON), fixing 75 previously-cascading test failures there (see §6).
