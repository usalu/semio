## Machine Accounting

After ownership was declared, targeted native status measured 3,580,506,112 bytes at `fleet-state`. The corresponding native-root and machine loose-store totals both reported zero. The status readers had summed only loose roots, and those roots omitted every managed control row. Machine collection independently measured only its eligible cache candidates, so it also omitted the fleet control.

Current status adds the known fleet control bytes to the native-root total and preserves the partial marker when any part is unknown. The CLI and fleet storage reader both consume that total once, and the known fleet amount cannot count as evictable. The collector adds the same known charge to its separately scanned loose usage and deducts it before splitting the existing loose quota among generic areas. The bootstrap control at `.cache/b/c` retains its independent reporting and contributes no loose bytes. Fleet state has no individual quota, and it does not acquire a generic retirement or delegate.

The connected fixture records the exact captured fleet measurement and a separate 12 MiB bootstrap control. Before the fix native status counted 8,192 generic bytes instead of 3,580,514,304 bytes. The independent SQLite oracle now agrees with native status, the JSON cache command and the fleet reader. With capacity one byte below the fleet amount, the machine plan reports one blocked byte. When capacity fits the fleet plus one of two generic units, the isolated collection preview selects exactly one generic unit for eviction. The focused suites passed 17 tests and 4776 assertions, and scoped whitespace verification passed.
